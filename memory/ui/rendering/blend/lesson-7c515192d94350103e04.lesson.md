# 迁移 blendMode 时先明确参与混合的画布范围

ID：`lesson-7c515192d94350103e04` · 版本：2

[本主题](index.md)

## 何时使用

规格提取或界面实现阶段，把源端同一画布上的 draw-content 加 blend 操作映射为目标端节点树时

## 适用情境

源效果先绘制底盘或字形，再让渐变按 Plus、Darken 等模式与已有像素混合；目标实现把字形、渐变和底盘放成独立兄弟节点，并准备在单个节点上启用离屏混合。

## 例外与边界

- 目标框架文档和当前设备实测均确认该混合节点能读取预期的兄弟背景像素

## 原因

同名 blend mode 只定义像素运算，不保证参与运算的画布范围相同；独立节点的离屏缓冲若不含兄弟内容，依赖底色的加法或变暗效果会退化为色块或错误着色。

## 做法

1. 按源绘制顺序列出字形、渐变与底盘中哪些像素参与混合。目标采用 OFFSCREEN 时，将需要共享像素上下文的节点放入能包含这些内容的组；不要把独立兄弟节点自动当成组内背景。
2. 保留源颜色运算。SRC_IN/DST_IN 是遮罩方案而不是 Plus/Darken 的通用替换；采用遮罩时还需满足颜色运算等价的条件，具体见本主题“用遮罩替代颜色混合”经验。
3. 当前 SDK 只说与下方画布混合、未界定其范围时，保留这个具体疑问，不把同名枚举直接写成已确定等价。

## 可选检查

仅在适用条件不确定、与当前输入冲突或需要验证关键假设时按需执行；优先复用已有证据和正常测试。
不因读取本条经验而额外启动验证流程；项目原有必需测试照常执行。

- 仅当当前 SDK 与已有材料无法确认目标画布范围时，在正常渲染测试中复用一个能区分底色是否参与的样本；不因读取经验重新跑全套主题截图。
