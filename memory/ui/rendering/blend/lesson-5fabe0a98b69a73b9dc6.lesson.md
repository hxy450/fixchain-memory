# 用遮罩替代颜色混合前，确认原颜色运算可被等价表达

ID：`lesson-5fabe0a98b69a73b9dc6` · 版本：2

[本主题](index.md)

## 何时使用

视觉修复或实现阶段，用 SRC_IN 等 alpha 遮罩结构替代源端 Plus、Darken 等颜色混合时

## 适用情境

准备把 Plus、Darken 等依赖已绘制颜色的运算，改为 SRC_IN 等 alpha 取形结构；字形颜色、透明度和背景合成会影响结果。

## 例外与边界

- 源效果本来只依赖 alpha 取形，或目标端仍使用经验证等价的同一颜色运算

## 原因

SRC_IN 只用源颜色乘目标 alpha，既不会自动执行加法或取最小值，也不能把半透明 tint 背后的合成色还原出来；直接换算子会保住形状却改变颜色。

## 做法

1. 先区分取形和算色：SRC_IN 保留形状并不会自动完成 Plus 的加色或 Darken 的颜色运算；把源字形颜色、alpha、背景和渐变作为当前公式的输入。
2. 当参与合成的颜色与当前渐变过程确实能由色标等价表达时，才将源运算折入色标并用不透明遮罩取形；主题分支分别推导。背景动态变化或等价条件不清时，不直接套用历史预混方案。
3. 保留当前实现中无法解释的残差，不因形状恢复就认定颜色运算也已一致。

## 可选检查

仅在适用条件不确定、与当前输入冲突或需要验证关键假设时按需执行；优先复用已有证据和正常测试。
不因读取本条经验而额外启动验证流程；项目原有必需测试照常执行。

- 仅当公式与现有结果不一致、需要判断色差来源时，复用稳定区域像素核对相关通道。历史卡仍有未裁决残差，不能把它的结果作为新工程的默认容差。
