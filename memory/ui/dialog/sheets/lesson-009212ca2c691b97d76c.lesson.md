# 弹层内再打开的二级弹窗按父面板的挂载层选承载层：父面板是 bindSheet 时用窗口级弹窗，父面板在页内时放根 Stack 顶层

ID：`lesson-009212ca2c691b97d76c` · 版本：4

[本主题](index.md)

## 何时使用

界面实现阶段，为从底部 sheet 或页内面板内部触发的二级弹窗（定时、新建输入、日历、选择器等）选择承载层时

## 适用情境

Android 在 BottomSheetDialog 内再 show 居中 DialogFragment（点外可关），或在当前页 show 的底部面板内再弹同类底部选择器；目标父面板用 bindSheet 或宿主页内叠层；二级弹窗候选有页内 Stack 条件浮层、bindSheet(CENTER)、bindContentCover 与全局自定义弹窗。

## 原因

页内 Stack 浮层的 z 序低于 bindSheet 半模态层，从 sheet 内打开会被盖住；修复时照搬本页已有浮层写法，会重新引入同一层级问题。父面板本身是页内叠层时，把二级弹层插进受 layoutWeight 约束的内容列，又会被键盘或面板挤压。

## 做法

1. 先确认触发点位于哪种父面板：父面板是 bindSheet 等窗口级半模态时，用全屏模态（bindContentCover）或全局级自定义弹窗（openCustomDialog），并在 sheet 打开状态下实测层级；只有父面板也在页内时，才把二级弹层放在根 Stack 顶层（遮罩加容器），覆盖面板与键盘，不在受 layoutWeight 约束的内容列里插入可见性切换块。
2. 要还原居中、点外可关的 DialogFragment：按 common.d.ts 声明，bindSheet(SheetType.CENTER) 点遮罩默认关闭（可在 onWillDismiss 按 DismissReason.TOUCH_OUTSIDE 拦截），但已观察到挂在零尺寸节点上的 bindSheet(CENTER) 实测不居中、点外未关闭，原因未查明；用它前在当前 SDK 实测居中与点外关闭并注明 SDK 版本，不满足时在模态内容里自绘全屏遮罩并居中卡片，遮罩 onClick 关闭，卡体消费点击。
3. 复用本页已有浮层写法前，核对触发点是否位于另一个半模态之内。
4. 源码在跳转回调里同时关闭对话框与父面板时，目标同样一并关闭。
