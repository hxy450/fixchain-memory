# 源端真弹窗（DialogFragment、AlertDialog、XPopup、BottomSheet）按源类迁成系统弹窗或半模态，不用页面叠层或路由页

ID：`lesson-368c4592e4c7075c1871` · 版本：8

[本主题](index.md)

## 何时使用

迁移实现、弹窗恢复与宿主接线阶段，为 Android 弹窗类（DialogFragment、AlertDialog/MaterialAlertDialogBuilder、XPopup Center/Attach/Bottom、BottomSheetDialog(Fragment)、上下文菜单）确定 ArkUI 承载形态时；规格把弹窗映射为路由页，或工程有“路由统一使用某框架”的约束时；为已有弹窗补触发、宿主、去掉路由时

## 适用情境

源端通过 DialogFragment、AlertDialog、XPopup CenterPopupView/AttachPopupView 等在当前 Activity 上弹出提示、升级、菜单或锚点气泡，点击遮罩或返回即关闭；目标工程里已有以 @Local visible/visibility 或 if 条件渲染的 Stack + 遮罩叠层，或派工只写“接到现有弹窗”“恢复可关闭的页面内弹层”。也包括源弹窗继承 BottomPopupView 一类底部弹窗基类，计划已写明映射到 showBindSheet/系统半模态，而现有实现是 NavDestination 路由页或由 @Param 可见性驱动、内嵌在宿主页的全屏 Stack（自绘遮罩、PanGesture 下拉关闭）。也包括 MaterialAlertDialogBuilder 或 AlertDialog（含 setView 输入、下拉、ListView 列表）在规格里与 bindSheet 并列，或因“弹窗里有输入框”被改成半模态；按钮的上下文菜单被写成锚定菜单而丢了长按入口与标题图标。也包括 BottomSheetDialogFragment 被写成标准模式的 NavDestination 路由页，在页内自绘蒙层与底板，调用方随之 pushPathByName。

## 例外与边界

- 确需保留页内浮层（项目已定）时，同时交付遮罩点击、返回键与页面离开关闭且只回调一次，显示期间给背景内容 accessibilityLevel('no-hide-descendants')（见 lesson-96eea0feeae116ef9262），并在报告中说明与源端承载的偏离

## 原因

页面叠层只在宿主页 Stack 里条件渲染，遮罩没有点击处理、宿主不拦返回键时，空白点击与返回都关不掉；把它当作现成弹窗接线，或以“宿主化、恢复关闭回调”为完成标准，同一批次里会出现部分真弹窗、部分叠层。标准路由页带来独立页面栈、伪造的遮罩和不同的关闭方式。以“带输入的模态最简单”为由改成底部 sheet，会同时改变呈现形态、关闭方式和校验时机。

## 做法

1. 按源端类定形态：居中类（DialogFragment、CenterPopupView、AlertDialog/MaterialAlertDialogBuilder，含 setView 输入、下拉与 setView(ListView) 列表）用 UIContext.getPromptAction().openCustomDialog 或项目已采用的弹窗库；锚点类（AttachPopupView）用 bindPopup 或按锚点全局坐标定位的自定义弹窗；底部类（BottomPopupView、BottomSheetDialog(Fragment)、底部 DialogFragment）才用 bindSheet/showBindSheet 等系统半模态。不因弹窗里有输入框改成半模态；规格并列两种形态时按源码择一，不以工程惯例替换。@ComponentV2 页面的载体限制见 lesson-3f3e1ff0a4d0e0299bda。
2. 上下文菜单区分两条入口并都实现：点击 openContextMenu 是无坐标的居中模态列表（带 header 标题与图标）；已 registerForContextMenu 视图的长按是触点锚定的浮动菜单。
3. 目标里已有 @Local 可见性 + Stack/遮罩的实现，若遮罩点击、返回键、离页关闭契约不完整，或项目没有决定保留页内浮层，视为待替换对象，不当作现成弹窗接线：改为真弹窗 API，按源端可取消性打开遮罩点击与返回关闭（如 autoCancel/backCancel），在 onDidDisappear 中单次清理状态，并确认页面离开时弹窗随之关闭。
4. 规划或交接弹窗批次时把“真弹窗、可关闭”写成形态契约，对清单里的每个弹窗记录承载形态；同一批次已有弹窗改用真弹窗 API 时，把其余仍是条件渲染的逐个改掉。“去掉路由、能关闭”不等于完成映射：可见性参数 + 全屏 Stack + 自绘遮罩 + 手势阈值关闭仍属待替换形态；交接与执行日志原样引用映射目标 API，不改述成泛化的“页面内弹层”。
5. 源类为 BottomSheetDialogFragment/DialogFragment、规格 page_type 为 modal_overlay 或 dialog 时，不用标准 NavDestination 加自绘蒙层模拟；确需路由承载就显式 .mode(NavDestinationMode.DIALOG)（工程有“路由统一用某框架”约束时见 lesson-7ef02de8bbc10734c3d2）。调用方接入已转换的弹层前，对照源端 show(childFragmentManager, …) 确认目标提供的是弹层入口。
6. 宿主页嵌在壳内容区时，页内浮层只能覆盖标题栏与底栏之间；源端底部面板用零尺寸锚点上的窗口级 bindSheet 或共享面板组件承载（写法见 lesson-b661a3a6a4c0a1e2a3c9），定样式前把面板子项布局一并读完。
7. AlertDialog 一类居中对话框优先用 openCustomDialog（页面级用 LevelMode.EMBEDDED，返回键与点外经 onWillDismiss 走取消回调）或 showDialog，由系统处理返回；保留页内浮层时同时交付返回键契约。

## 可选检查

- 对形态存疑时逐个弹层核对：弹层文件是否调用系统弹窗/半模态 API，宿主页是否只持有控制器，而不是可见性状态加内嵌组件。
