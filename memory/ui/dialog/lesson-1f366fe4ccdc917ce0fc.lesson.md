# 源弹窗按它实际加载的布局 XML 与函数全文逐控件还原，不以行为代码、相邻弹窗外壳或通用确认弹窗代替

ID：`lesson-1f366fe4ccdc917ce0fc` · 版本：3

[本主题](index.md)

## 何时使用

界面转换与接线阶段，为源端弹窗编写或补建 ArkUI 弹窗内容（包括解接线标记时顺带新建弹窗、补齐流程闭环时新建弹窗、考虑复用通用弹窗）时

## 适用情境

源弹窗由 ViewBinding/inflate 或工具类加载独立布局（DialogXxxBinding.inflate、R.layout.xxx），含标题、关闭图标、专用图标、说明文字、输入框、单个或多个按钮及容器级 margin；目标工程已有“标题 + 确定/取消”的通用确认弹窗或相邻弹窗写法可参照，或只拿到“展示、复制、关闭”一类功能描述。

## 原因

只读调用代码、功能描述或 toast 文案会漏掉布局里的控件：关闭图标被写成“取消”按钮、单按钮变双按钮、标题与图标缺失、hint 取自 toast；截断的 grep/head 读不到函数结尾的失败分支，会把“源端无提示”当成事实。通用确认弹窗缺任何一项都不等价，却常被注成“视觉由通用弹窗承载”后解除标记。另一应用里编排者写客服弹窗前只做了一次关键字搜索，输出被截断只见无关路径，便按功能自拟通用弹层：标题文案不同，缺专用图标、右上关闭与说明文字，多出整宽关闭按钮；工程 skill 已写明弹窗外观要取自布局抽取结果而非记忆。另一应用中，启动页隐私弹窗的实现者只读到 Activity 对 DialogHelper 的一行调用，没打开 helper 与它加载的布局，就断定源端没有拒绝路径，写成单按钮通用弹窗，缺了承诺卡片、权限图标与“不同意 → 二次确认 → 退出”；图标资源其实已迁移，只是没有引用。

## 做法

1. 从调用代码定位实际加载的布局（XxxBinding.inflate → xxx.xml、setContentView/inflate 的 R.layout 名，或弹窗工具函数里的布局名），读完该 XML 与弹窗函数全文（被截断就继续读），工程提供弹窗 probe 时用其控件清单，再写。
2. 按源布局逐控件核对：标题文案、图标、正文与说明、按钮数量与文案、关闭控件类型与位置、遮罩点击行为，hint 取 android:hint；每个容器自身的 layout_margin/padding 与子控件属性分开检查。
3. 通用弹窗缺少任一项时不作为等价实现；公共组件不在写权限内时，在页面内用条件浮层复刻，确实做不到就登记未决项并写明缺口。
