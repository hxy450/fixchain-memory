# 自绘底部弹窗改成 bindSheet 时迁移原手势门禁：含列表的面板按手势起点是否在顶部决定下拉关闭，不照搬无列表模板的无条件 dismiss

ID：`lesson-f35f4912277e0c9a1b14` · 版本：1

[本主题](index.md)

## 何时使用

弹窗改造阶段，把页面内自绘底部弹窗替换为系统 bindSheet/showBindSheet、配置 SheetOptions 与内部滚动时

## 适用情境

旧的自绘面板含可滚动 List，用 PanGesture 记录手势起点是否在列表顶部，只有在顶部才跟手下拉、达阈值关闭、否则回弹；参考的现有 Sheet 模板是无列表的固定高度选择器，onWillDismiss 无条件关闭。

## 例外与边界

- 面板内没有可滚动内容，下拉关闭不需要与列表滚动区分

## 原因

删掉 PanGesture 不等于门禁已迁移：内部 List 没有配置嵌套滚动、onWillDismiss 无条件关闭时，列表到顶后不能继续下拉关闭，快速回滑到顶会直接关掉，关闭前还会先上弹。来源中改造者读到了旧实现的顶部门禁，仍照搬选择器模板，用户依次报告了这三种现象。

## 做法

1. 改造前列出旧实现的手势门禁（起点是否在顶部、关闭阈值、未达阈值回弹），逐项映射到 Sheet：内部 List 配置 nestedScroll（如 SELF_FIRST），onWillDismiss 按本次手势起点是否在顶部决定 dismiss 或 springBack，并注册 onWillSpringBackWhenDismiss；允许关闭时直接退场。
2. 复用其他弹窗的 SheetOptions 前先比对结构：参考对象没有滚动列表时，它的无条件 dismiss 不能套到含 List 的面板。

## 可选检查

- 在设备上分别验证“列表在顶部时下拉关闭”和“列表在中部快速回滑到顶”两条路径。
