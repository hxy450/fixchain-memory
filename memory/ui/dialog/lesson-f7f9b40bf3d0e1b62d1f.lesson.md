# 弹窗确认区是可点击的复合容器（勾选或图标加多行文案）时，整体转成复合按钮，不用只收单个 label 的按钮 builder

ID：`lesson-f7f9b40bf3d0e1b62d1f` · 版本：1

[本主题](index.md)

## 何时使用

界面实现与收口阶段，转换弹窗里带点击事件、内含勾选控件或图标与多行文本的确认区，或用一个共享弹窗组件承载多个弹窗变体时

## 适用情境

源确认区是带形状背景、可点击的 LinearLayout/Shape 容器（勾选控件＋主文案＋小字号次文案）；目标准备复用只收单个文字 label 的主题按钮 builder；或一个共享弹窗组件承载普通、严格等多个变体，只有某个变体有显式勾选状态；源端还可能在勾选后延时再回调。

## 原因

只收一个 label 的按钮会丢掉勾选控件与次行文案；共享组件只给带显式勾选状态的变体画勾选控件时，其他变体同样缺件，而保留下来的延时等行为说明原结构曾被读到。

## 做法

1. 整个可点击容器转成复合结构，如 Button() { Column() { Row() { 勾选, 主文案 } 次文案 } }，点击挂在整体上；输出前逐个子节点对照控件类型、尺寸、文案、字号和颜色。
2. 共享组件承载多个变体时，每个变体分别对照自己的布局文件，不因只有某个变体有显式勾选状态就推断其他变体没有勾选控件；保留延时等行为时，同时核对它依附的视觉元素（如延时对应的勾选动画）。
