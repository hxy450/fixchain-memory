# 页内对话框的可见性状态逐一落实打开触发点：卡片整体点击与卡内关闭按钮分开实现，留给后续任务的触发点要登记

ID：`lesson-f0d5a447e645bc253019` · 版本：1

[本主题](index.md)

## 何时使用

界面转换与页内接线阶段，把源页面中可点击的卡片、按钮及其打开的页内对话框转换为 ArkUI 触发器与可见性状态时

## 适用情境

源端 Compose Card 以 Modifier.clickable 打开对话框，卡内另有关闭或忽略按钮；目标以 @Local 可见性标志加 @Builder 覆盖层实现页内对话框，部分处理器以前向占位留给后续切片；页面规格的导航关系表列出“触发 → 对话框”。

## 原因

只建可见性状态和覆盖层、不写置 true 的触发点，对话框永远不可达；把卡内关闭按钮当成卡片唯一的交互，会漏掉卡片本身的打开入口；后续接线只按占位清单闭合时，没有登记的入口也不会被补。来源中转换者读到了规格导航表、源码的 clickable 与布局 clickable=true，同一次输出为另外两个对话框写了置 true，却漏掉这张卡片的打开入口，报告仍称对话框开关已完整实现。

## 做法

1. 对每个新建的对话框可见性状态，按规格导航关系表逐行找到置 true 的触发组件并写上 onClick；处理器属于后续任务时在触发点登记前向占位，不只建状态和覆盖层。
2. 带 Modifier.clickable 的 Card 把卡片级 onClick 放在根容器上，与卡内关闭/忽略按钮分别实现。
3. 接线阶段除闭合占位清单外，也对照导航关系表检查触发器；发现没有登记的遗漏入口就补接线或回报。

## 可选检查

- 对可达性存疑时，grep 每个对话框可见性状态是否存在置 true 的赋值
