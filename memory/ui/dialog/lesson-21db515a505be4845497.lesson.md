# 按源弹层类型逐个选呈现形态：居中 CustomDialog 用居中卡片，底部面板才用 bindSheet，锚定菜单按锚点弹出；形态不同的面板不共用一个弹窗；定长密码框输满即校验

ID：`lesson-21db515a505be4845497` · 版本：2

[本主题](index.md)

## 何时使用

页面接线与界面实现阶段，为源端 DialogHelper 一类函数弹出的确认或输入弹窗选择承载形态与校验触发方式时；对齐同页多个工具面板（如阅读页的设置、更多、发弹幕）的容器、锚点与交互步骤时

## 适用情境

源端经 CustomDialog/AlertDialog 加自定义布局弹出居中卡片，卡内可能有定长格子密码框（输满即比对、失败提示），根视图点击关闭；目标公共弹窗封装只有确认/提示类，带输入的弹窗需要在页面内自建。 也包括源端同页多个工具面板容器各不相同（底部 PopupWindow 面板、锚定在标题栏右上角带箭头的弹出菜单、先编辑再在内容上拖动定位的多步弹层），目标现有实现用一个固定高度、带拖动条与关闭按钮的 bindSheet 承载全部面板。

## 原因

以“带输入的模态最简单”为由改成底部 sheet，会同时改变呈现形态、关闭方式和校验时机（多出确定按钮、失败没有提示）。 共用一个弹窗组件再改底色与文字，位置、拖动条、关闭按钮、选中样式与后续步骤仍与源端不同。另一应用的阅读页已读到逐面板差异与 Android 实拍，仍只把共用 bindSheet 改成深色并称已对齐；后一轮改发弹幕面板时也只改了字数上限，拖动定位步骤一直缺失。

## 做法

1. 居中卡片类（CustomDialog、AlertDialog）用页内条件浮层（遮罩 + 居中卡片）或 CustomDialog/ComponentContent 实现；只有源端是 BottomSheetDialog 一类时才用 bindSheet，不因弹窗里有输入框就改成半模态。
2. 复刻定长格子密码框时保留格数与尺寸，输入长度达到位数即自动比对；源端没有确定按钮就不加，失败提示取源端文案。
3. 同页多个源面板逐个列出容器类型（底部面板、锚定弹出菜单、全屏覆盖层）、锚点、宽高，以及有无标题、拖动条和关闭按钮；只有这些一致时才共用一个弹窗组件，否则拆成各自布局与打开方式（锚定菜单用 bindPopup 或按锚点定位的覆盖层）。
4. 源面板是多步交互（如编辑文字 → 在内容上拖动定位 → 确认或取消）时，每一步的状态与切换都要实现；只改字数上限、占位文案或标题不算对齐。
