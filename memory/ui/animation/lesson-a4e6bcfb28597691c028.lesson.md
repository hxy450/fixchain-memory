# Compose AnimatedVisibility 的 expand/shrink 落为 ArkUI 容器高度过渡，不以淡入或直切代替

ID：`lesson-a4e6bcfb28597691c028` · 版本：3

[本主题](index.md)

## 何时使用

规格提取与界面实现阶段，把 AnimatedVisibility(expandVertically/shrinkVertically 等) 翻译成 ArkUI 时；规格已写“animateTo 高度过渡 / expandVertically 等价”而准备换成其他转场时

## 适用情境

源端用 AnimatedVisibility(enter = expandVertically/expandIn…, exit = shrinkVertically/shrinkOut…) 展开、收起内联内容；目标用 if/else 条件渲染、TransitionEffect 与 animateTo 实现；流程允许把视觉差异登记为近似或留给后续核验。

## 原因

expand/shrink 里节点自身的出现方式只是一部分，承载容器的高度变化和下方内容的推移来自尺寸动画；只给节点挂 TransitionEffect.OPACITY 或直切时，节点会出现，但容器高度跳变、下方内容瞬移。把它当作可省的“视觉细节”且不登记，下游就无从发现。

## 做法

1. 起止尺寸、对齐与动画取自源 enter/exit 参数；源端未传参时按所用 Compose 版本的缺省值（animation 1.11.1 的 EnterExitTransition.kt：initialHeight/targetHeight 为 0、clip 为 true、expandFrom/shrinkTowards 为 Alignment.Bottom、animationSpec 为 spring(StiffnessMediumLow)）。在 animateTo 中改变承载容器的显式高度（目标值取实测内容高度）并配 clip(true)，容器内内容的对齐按 expandFrom/shrinkTowards 设置。
2. 被插入或移除的节点按源 enter/exit 另挂透明度、位移等 transition，不只挂 TransitionEffect.OPACITY。
3. 本步确实做不了时，按动画逐项登记缺口（哪种动画、源参数）交给有写权的后续步骤，不以“视觉细节”省略，也不只写透明度近似。

来源支持：1 张卡 · 1 次迁移 · 1 个应用
