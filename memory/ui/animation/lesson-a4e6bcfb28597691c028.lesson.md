# Compose 的显隐、内容切换、尺寸与条目位移动画（AnimatedVisibility expand/shrink、AnimatedContent + SizeTransform、animateContentSize、animateItem）逐项落为 ArkUI 动画，不以透明度渐变或直切代替

ID：`lesson-a4e6bcfb28597691c028` · 版本：1

[本主题](index.md)

## 何时使用

规格提取与界面实现阶段，把 Compose 显隐、内容切换、容器尺寸与列表条目的动画翻译成 ArkUI 时；规格已写“animateTo 高度过渡 / expandVertically 等价”而准备换成其他转场时

## 适用情境

源端用 AnimatedVisibility(enter = expandVertically, exit = shrinkVertically)、AnimatedContent(transitionSpec … using SizeTransform)、Modifier.animateContentSize，或 LazyColumn/LazyRow 条目上的 Modifier.animateItem()；目标用 if/else 条件渲染、TransitionEffect 与 animateTo 实现；流程允许把视觉差异登记为近似或留给后续核验。

## 例外与边界

- 决策记录以编号批准省略该动画，并写明差异验收

## 原因

这些动画里，节点自身的出现方式只是一部分，容器高度的变化、相邻内容的推移和条目位移来自尺寸与布局动画；只给节点挂 TransitionEffect.OPACITY 或直切时，节点会出现，但容器高度跳变、下方内容瞬移。写者把它们当作可省的“视觉细节”且不登记，下游就无从发现。

## 做法

1. AnimatedVisibility 的 expand/shrink：承载容器的高度要在 0 与内容高度之间过渡，可在 animateTo 中改变容器的显式高度（目标值取实测内容高度）并配 clip(true)；被插入或移除的节点按源 enter/exit 另挂透明度、位移等 transition，不只挂 TransitionEffect.OPACITY。
2. animateContentSize 与 SizeTransform：把引起内容尺寸变化的状态更新放进 animateTo，让容器尺寸从旧值过渡到新值；AnimatedContent 的新旧内容用随目标状态变化的 key（if/else 分支或键化 ForEach）承载，分别挂入场、出场转场（如上下滑入滑出），方向条件取自源 transitionSpec；SizeTransform(clip = false) 时过渡期间不裁切内容。
3. animateItem：List 的 ForEach 用稳定键，数据增删放进 animateTo，ListItem 挂插入/删除转场，其余条目的位移随之过渡；删除由持久化写入后经数据流回推触发时，先完成写入，再在 animateTo 中改变驱动显示的状态，不在动画闭包外同步置 false。
4. 本步确实做不了时，按动画逐项登记缺口（哪种动画、源参数）交给有写权的后续步骤，不以“视觉细节”省略，也不只写透明度近似。

来源支持：2 张卡 · 1 次迁移 · 1 个应用
