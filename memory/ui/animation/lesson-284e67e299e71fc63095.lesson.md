# View 动画调用（fade、startAnimation、setCustomAnimations）按行为迁移：取源动画资源与时长，动画结束才切显隐

ID：`lesson-284e67e299e71fc63095` · 版本：1

[本主题](index.md)

## 何时使用

实现与接线阶段，为源端用 View 动画完成的行显隐、列表项进入详情、Fragment 切换等状态变化选择 ArkUI 过渡时；规格提取阶段为导航与显隐验收项登记转场契约时

## 适用情境

源端在置 VISIBLE/GONE 或 replace Fragment 前后调用自有动画辅助类（淡入淡出、缩放进入详情）、View.startAnimation 或 FragmentTransaction.setCustomAnimations，动画取 res/anim 资源、config_mediumAnimTime 等平台时长或代码常量，常在动画结束回调里才切 visibility；目标用 if 条件渲染与 Navigation/NavDestination，未写 transition、animateTo 或 customTransition。

## 例外与边界

- 决策记录以编号批准省略该动画并写明差异验收

## 原因

这些调用决定用户看到的过渡与显隐时序；只翻译 setVisibility 或路由调用时，条件渲染瞬显瞬隐，Navigation 以系统默认横滑代替源端的淡入淡出或缩放，“动画结束才隐藏”的顺序也一并丢失。反过来，源端 Fragment 事务未设 setCustomAnimations/setTransition 时本身没有切换动画（FragmentTransaction 默认 TRANSIT_NONE），目标保留系统默认转场同样与源端不同。

## 做法

1. 翻译显隐或页面切换前，列出该处每个动画调用的资源、时长与插值器（res/anim、@android:integer/config_mediumAnimTime 一类平台值、代码常量），再选承接方式：行显隐用 animateTo 改透明度等属性或 transition；页面覆盖、列表项进入详情用 NavDestination.customTransition 或 Navigation.customNavContentTransition，缩放进入用缩放与位移属性动画。
2. 源端在动画结束回调里才切 GONE 的，目标在 animateTo 的 onFinish 里再改条件渲染或 visibility；入场先置可见再播放。不写“fade 等价：状态驱动可见性”一类把动画折成即时显隐的注释。
3. 源端 Fragment 事务没有设动画时，进入与返回都关闭系统默认转场（push、pop 传 animated 为 false）。
4. 规格给导航与显隐验收项附转场契约（动画资源、时长、插值器、起止状态、谁覆盖谁）；本步做不了的动画逐项登记缺口交给有写权的步骤，不静默删除。
