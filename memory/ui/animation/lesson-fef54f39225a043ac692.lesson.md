# 把 AnimatedVisibility 等条件块改成常驻折叠容器时，只把源 lambda 内的节点放进容器，lambda 外的兄弟留在容器外常驻

ID：`lesson-fef54f39225a043ac692` · 版本：1

[本主题](index.md)

## 何时使用

界面实现阶段，把源端条件显隐块（AnimatedVisibility、if 块）转写为显式宽/高 0↔内容加 clip(true) 的常驻折叠容器，决定哪些兄弟节点放进容器、展开尺寸怎样确定时

## 适用情境

源端同一行里既有常驻节点，又有只包住其中一部分兄弟的 AnimatedVisibility 或条件块；目标用常驻容器配显式宽/高 0↔内容、clip(true) 实现显隐，展开尺寸按容器内节点手算成常量。

## 原因

clip(true) 会静默裁掉多放进容器的节点：常驻节点被放进折叠容器后，关闭态随容器一起消失；展开态的尺寸常量只够原受控节点，又把真正受控的节点挤出可见区。编译与注释都看不出问题。

## 做法

1. 先按源码分出 lambda 内与 lambda 外的节点：只把 lambda 内的节点（连同其中的 Spacer）放进容器，lambda 外的兄弟写在容器外常驻，源端间距在哪一侧就跟着哪一侧。
2. 展开尺寸写成常量时，按容器里实际的子节点逐项加总核对；合计对不上，就说明节点归属写错了。

## 可选检查

- 对节点归属有疑问时，按开关的每个状态各数一遍可见控件并与源端对照；注释或报告写“仅某节点受控”时，核对受控容器里确实只有它。
