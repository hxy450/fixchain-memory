# 应用内主题切换不只依赖 setColorMode：命令式取色、系统栏与画布要随主题重解析

ID：`lesson-f1069f514c0eb98702fb` · 版本：3

[本主题](index.md)

## 何时使用

实现阶段，设计应用内深浅色切换，并为系统栏、Canvas、HTML 样式等非 $r 消费点取色时

## 适用情境

源换主题靠 Activity 重建；目标用 ApplicationContext.setColorMode 切换，同时存在 getColorSync 取色、setWindowSystemBarProperties 内容色、Canvas 画笔色与内联 CSS。

## 例外与边界

- 应用只跟随系统深浅色、不提供应用内切换：主题状态与渲染期取色见 lesson-7b19b801e0f21481d1d6

## 原因

setColorMode 会让 $r 资源重解析，但真机实测：应用内选深色而系统为浅色时，context.resourceManager.getColorSync 仍按设备配置取值（平台文档未写明 setColorMode 与 context.resourceManager 的关系，以实测为准）；画布色只在初始化取一次也不会更新；按一种模式写死的系统栏内容色在切换后可能看不清。

## 做法

1. 切换前检索 getColorSync/getColor、Canvas 取色、内联色与系统栏设置，逐类写明切换后由谁重解析。
2. 提供按当前主题覆写 colorMode 的资源管理器（resourceManager.getOverrideResourceManager，@ohos.resourceManager.d.ts，API 12 起），由主题控制器统一导出；取色点订阅主题态或 onConfigurationUpdate 后重解析并重绘。
3. 系统栏内容色按源端每个主题的浅色系统栏标志最终值确定（推导方法见 lesson-824031d5fddf81036b54），在应用内切换与 onConfigurationUpdate 时按当前主题重设；只有源端浅色主题设了浅色状态栏标志、深色主题没设时，结果才是“亮色用深色图标、暗色用白色图标”。
4. 移植构造期取色的自绘 View 时，把取色写成可重入的方法。
