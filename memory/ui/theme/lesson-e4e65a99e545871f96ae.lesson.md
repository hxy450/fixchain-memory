# 页面视觉数值分散在布局、item 布局与适配器分支时逐项取值，缺项补读，不以近似值、通用卡片或自拟分隔线代替

ID：`lesson-e4e65a99e545871f96ae` · 版本：4

[本主题](index.md)

## 何时使用

界面转换与实现阶段，确定标题栏背景、文字颜色与字号、按状态区分的样式（选中、当前项、特殊项）、item 尺寸、胶囊圆角、行高与分隔线时；把弹出菜单行、列表分组标题与批量操作底栏转成组件时

## 适用情境

页面规格只给合成的结构（无颜色与尺寸），视觉数值分散在 Fragment 布局、include 布局、item 布局与适配器 convert 分支里；转换者可能只读到部分文件，或读到了却写成近似值。也包括差异清单与规格只按功能行为描述新入口，菜单行或操作按钮由 ImageView 加 TextView 组成、标题用 drawableLeft 图标与专用颜色资源，部分图标随选中状态切换。

## 原因

视觉属性一旦凭经验补齐就会整体偏离源端：标题栏底色、按状态区分的颜色、标签形状、多出的分隔线与近似行高都会不同；读到 dp 值仍写成近似值也一样。规格只承载行为时，写者会只写出文字与行为，漏掉图标和按状态切换的图。

## 做法

1. 写样式前从源布局、item 布局与适配器分支逐项摘出清单：背景色、主要文字颜色与字号、默认态、选中态与业务状态（例：日历的周末、节日、当天）的颜色与样式、item 宽高、圆角、行高与上下间距、分隔线的有无；列表或网格沿适配器链追到实际 item 适配器，从 convert() 取各状态分支；某项在已读内容里找不到就回到对应文件补读。
2. 写完按清单逐个 dp 值与源值对照，数值照源端写，不自行增加源端没有的分隔线或卡片圆角。
3. 清单同时覆盖图标元素：ImageView、drawableLeft、item 里的角标图片（不用文字色块或自绘圆形代替）、按选中数量或模式切换的 drawable（如未选中用灰图、选中用高亮图）及对应文字颜色，按状态成组映射。差异清单或规格只描述行为时，实现者仍回到源布局补出可见元素；规格提取描述新 UI 入口时，把关键视觉要素（图标、标题颜色、“图标 + 文字”结构）写进验收项。
