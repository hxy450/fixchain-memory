# 按源端实际色值与字号在资源里找同值键：主题语义色、排版样式与渐变调色板先解析到值，不按 accent、primary、title/body 等名称选键

ID：`lesson-4e9507a2a793c5583aa8` · 版本：8

[本主题](index.md)

## 何时使用

界面实现阶段，为按钮、背景、文字与渐变色阶设置颜色资源引用，或为文本绑定字号资源令牌时；把 Compose Brush 渐变背景（Brush.horizontalGradient(调色板)）落为 ArkUI linearGradient 时

## 适用情境

源端颜色以 shapeSolidColor、background、textColor 等硬编码色值或色值资源给出；目标工程已有多组语义名相近但色值不同的颜色资源（如 color_accent 与 brand_accent）。也包括 Compose 源端以主题语义色（如 colors.textPrimary）、排版样式（如 MaterialTheme.typography.titleMedium）或调色板列表（Brush.horizontalGradient(colors.xxx)，可能配 Surface(color = Transparent)）取值，而目标 color.json/float.json 只有部分令牌、缺同值键，流程要求缺令牌时报告 design_tokens_missing；用 text_size_large 一类名称暗示大小的资源承载源端数值；同一组件中语义不同的颜色准备共用一个已有 token；Java 以 Color.GREEN、Color.RED 等框架颜色常量着色，规格映射成名称相近、色值不同的应用色。

## 原因

资源名只表达意图，名为 accent 的已有键可能是另一种颜色；按名字选键时代码看似引用了主题色，渲染出的颜色却与源端不同，编译与“无 hex 字面量”自检都发现不了。调色板名只是颜色列表的别名，不解析就只能用一个品牌色或名称相近的令牌代替，渐变变成单色块或错值色阶。

## 做法

1. 取源端控件的实际色值（shapeSolidColor、background、textColor 等），在 color.json 中按值反查同值的键，并读出所选键的值与源值逐字比对（把 #RRGGBB 与 #FFRRGGBB 等写法归一化后比较完整 RGBA，不忽略真实的透明度差异）；不相等就不复用，即使名称前缀相同、同属一个功能模块或同一色系。没有等值键就追加页面或元素专属的颜色键（被其他页面共享的令牌不改值）；为消除 hex 字面量改写已正确的字面色值时同样按值找键。
2. 源色或候选资源有 night/主题变体、状态 selector（ColorStateList）时，按该控件实际会用到的模式与状态逐一比较，不用浅色默认态的一次同值代替映射等价；源端是恒定色时，也不选在其他支持模式中会变值的目标令牌（依据：developer.android.com 深色主题与 color state list 资源文档，2026-10-15 访问）。
3. 源端用主题语义色或排版样式名时，先在 Theme/Color/Type 定义或设计令牌表中解析到具体值，再按值找键；缺同值键时按调色板或样式名新增令牌，或按流程报告 design_tokens_missing，不用名称相近或其他页面前缀的现有令牌代替。
4. 源背景是 Brush.horizontalGradient(colors.xxx) 时保留为 linearGradient({ direction: GradientDirection.Right, colors: [...] })：先在主题与 Color 定义中把调色板名解析成具体色阶顺序（例：某主题的 interactivePrimary 解析为两个色阶），逐个按值找键或新增缺失色阶；源 Surface 为 Transparent 时目标 backgroundColor 也设透明，不压成单一品牌色。
5. 选用命名资源前读其实际值，注释里写的数值与所引资源一致；同一组件中语义不同的颜色不共用一个 token，从已有组件照搬颜色前先核对源端是否同色。
6. 框架颜色常量按定义值匹配（android.graphics.Color：GREEN=#FF00FF00、RED=#FFFF0000），没有同值键就新增，不用名称相近的应用色代替。
