# 源主题以 CSS 变量加深色覆盖块提供中性色时，背景、正文、卡片、分隔线导出成对 base/dark 资源，页面不写 hex

ID：`lesson-eafa5f24acae0a19559b` · 版本：2

[本主题](index.md)

## 何时使用

规格与计划阶段划分设计令牌与深色资源职责时；页面转换阶段为页面底色、文字、卡片、分隔线等中性色取值时；拥有深色验收的切片或收口检查交付前

## 适用情境

源工程用主题 CSS 变量提供页面级中性色（--ion-background-color、--ion-text-color、--ion-card-background 等），在 body.dark、.ios body.dark 或 prefers-color-scheme 块里给出深色值；目标靠 base/dark 资源限定符与 ColorMode 切换深浅，页面转换与设计令牌任务可能并行。

## 原因

只读主题文件前段会漏掉后部的深色覆盖块；设计令牌只规划 accent 时，页面背景、正文与卡片的深色值没有任何任务负责。页面把主题变量的浅色值写成 hex 字面或字符串常量后，打开深色时页面仍是浅色；只为 accent 登记的前向引用也不会让人回来补中性色。

## 做法

1. 规格提取时完整读取主题文件（含深色覆盖块），把页面级中性令牌（背景、正文、次文字、卡片、列表项、分隔线、遮罩）与 accent 一样列出浅/深两值；只列了 accent 时不写“全量”或“浅/深两套齐全”。
2. 计划阶段验收要求页面面色随深浅切换时，指定一个任务产出这些键的 base 与 dark 资源，派工写明键清单与深色取值来源；不把令牌任务收窄成 accent 色板，也不让深色机制切片与页面转换互相假定对方负责。
3. 页面转换时，源色值来自带深色覆盖的主题变量就引用成对的 $r('app.color.*')（或随深色切换的系统语义色），不写 hex 字面或字符串常量；资源还没有时为中性色登记前向引用，写明所需的深色值。
4. 拥有深色验收的切片交付前，对比 dark 资源是否覆盖页面与共享常量引用的全部颜色键，并 grep 中性色 hex；有缺口写进 decision_gaps，不报“无差异”。
