# 主题提供的颜色（?attr 属性、DayNight 框架默认色）按各主题与深浅两态取值导出 base/dark 颜色键，并在 ArkUI 侧显式绑定

ID：`lesson-1856958fc6d369f0e2bb` · 版本：2

[本主题](index.md)

## 何时使用

资源前置、规格提取或界面实现阶段，为引用 ?attr 的图标 fillColor、工具栏主题色、自绘组件前景色或文字色新建或选择颜色 token 时；把未覆写主题的 AppCompat DayNight 应用映射为 base/dark 颜色资源与页面配色时

## 适用情境

源图标与控件颜色来自主题属性（应用自定义的图标色属性、colorControlNormal=colorOnSurface、colorOnSecondary 等），各主题取值不同；目标 SVG 只保留浅色值，color.json 可能缺对应键。也包括 AppTheme 只继承 Theme.AppCompat.DayNight、没有 values-night、没有 colorPrimary/colorAccent 覆写：窗口、对话框、ActionBar、状态栏、按钮、主次文字、提示、禁用、强调色与分隔线都来自框架默认并随深浅色变化；规格把业务调色板镜像到 dark 当作深色适配，各页转换器各自补键或按某一模式写死 white、dark_gray。

## 原因

缺键时借用语义不同的灰色、按名称猜为强调色，或 base/dark 写同一个值，会让图标在某个主题下颜色错误，并随先例扩散。DayNight 应用的外观几乎全由框架两态默认色决定；只把业务色镜像到 dark，框架色就没有成对 token，各页只能凭记忆补键或写死某一模式的颜色。

## 做法

1. 查矢量 fillColor 或工具栏主题引用的属性，分别取各主题 style 中的值，在 base/dark 各写一个键；检索时不要把目标属性名排除在外。
2. 自绘组件的 foregroundColor=?attr 先查 attrs/styles 的实际值再定默认色，各调用点按自己布局传参。
3. 图标 Image 用 fillColor 绑定该 token，不沿用未着色的先例；资源前置阶段把被引用的主题属性连同解析值导出为颜色键并在映射表注明。
4. 源为 DayNight 且无覆写时，在规格中列出框架浅、深两态的窗口、对话框、ActionBar、状态栏、按钮、主次文字、提示、禁用、强调色与分隔线取值，成对写入 base/dark；页面背景、文字与菜单颜色只引用这些成对 token，不按某一模式写死，也不把深色适配留待以后。
5. 框架默认值（如 colorAccent）按依赖的实际版本资源或源端运行截图核对后再写入共享 color.json；核不到就登记未决，不落猜测值。
