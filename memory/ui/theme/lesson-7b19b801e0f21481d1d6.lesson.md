# 深浅主题状态放在可观察对象里并由入口同步，组件在渲染期读取主题色

ID：`lesson-7b19b801e0f21481d1d6` · 版本：2

[本主题](index.md)

## 何时使用

主题层实现深浅色切换，以及组件、页面读取主题色（含对主题色做插值等数值运算）时

## 适用情境

源端 Theme(darkTheme = isSystemInDarkTheme()) 经 CompositionLocal 下发两套颜色，组件在组合期读取；目标用模块级主题函数与 $r 颜色资源实现，由入口读取系统 colorMode。也包括源端对 MaterialTheme.colorScheme 的颜色做数值插值（如按折叠比例 lerp 顶栏容器色），而 $r 资源不能直接参与运算。

## 原因

Compose 靠组合期读取随系统切换重组。目标端用普通模块变量保存深浅状态、组件在字段初始化器或 @Param 默认值里取一次色时，界面不会随切换刷新；同步函数没有调用点时深色永远不生效，编译照常通过。需要数值插值时，写者还容易因 $r 不能运算，把浅色色值复制成页面常量，深色下直接错色。

## 做法

1. 深浅状态放进 @ObservedV2 类的 @Trace 字段（或 AppStorageV2），入口 onCreate 与 onConfigurationUpdate 各调用一次同步。
2. 组件在 build() 或 get 访问器里读取主题色，不写进字段初始化器；颜色类 @Param 默认值设为 undefined，在 getter 里回落到主题色。
3. 需要对主题色做数值插值时，端点从可观察主题对象当前色板的数值色读取（如 surface、surfaceContainer 对应项），在渲染期计算。主题层还没提供数值色板时，登记有负责方的前向引用，不把某一模式的色值复制成页面常量。

## 可选检查

- 有疑问时检索主题同步函数，确认 onCreate 与 onConfigurationUpdate 各有一处调用。
