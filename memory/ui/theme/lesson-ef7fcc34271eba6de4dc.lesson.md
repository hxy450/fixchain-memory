# 对 #AARRGGBB 颜色串或 32 位 ARGB 数值做插值、混合时按 A/R/G/B 四通道拆分，不按 #RRGGBB 偏移取子串

ID：`lesson-ef7fcc34271eba6de4dc` · 版本：1

[本主题](index.md)

## 何时使用

界面实现阶段，对主题色等颜色值做插值、混合或其他按通道运算（折叠顶栏背景、状态色过渡、按压态混色）时

## 适用情境

目标代码先把颜色取成 '#AARRGGBB' 字符串（如 resourceManager.getColorSync 结果转成的 8 位串、8 位 color.json 值）或 32 位 ARGB 数值，再按比例在两个颜色之间插值或混合。

## 原因

8 位串与 ARGB 数值的第一个字节是 alpha；按 #RRGGBB 用 slice(1,3)/(3,5)/(5,7) 拆分时，alpha 被当成红色、蓝色字节丢失，不透明色整体偏红偏粉。颜色的产出格式与解析写法由不同位置各写一份时，这种错位编译与结构检查都发现不了。

## 做法

1. 先确认两个端点的实际表示，再按四通道运算：数值用 >>> 24/16/8/0 与 0xFF 拆出 A/R/G/B，分别插值后按同一种 8 位表示拼回；字符串先解析成数值再拆。
2. 工程已有 ARGB 插值或混色工具就复用；没有时写成单个共享工具并在注释写明输入输出格式，页面不各自手写拆分。

## 可选检查

- 把 fraction=0 和 1 代入插值函数，结果应分别原样等于两个端点；位数变化或首两位变成别的值，就是通道错位。
