# 把 Android 主题、Compose 宿主或依赖库隐式提供的外观写成目标控件的显式样式，取值来自实际提供方：框架主题（android:Theme.*，含 @android:style 引用）先在本机 SDK platforms/android-<api>/data/res 解析到值，查过仍缺才标待核

ID：`lesson-47785524c7f132ea7efe` · 版本：7

[本主题](index.md)

## 何时使用

规格提取阶段写控件转换决策，或页面实现阶段写出按钮等控件的修饰链时；为未写 tint/color 的 Compose Icon、Text 着色，翻译未传 textStyle 的 BasicTextField，或迁移 GlanceTheme 等依赖库主题色时；把 CheckBox、RadioButton、MaterialButton、TabLayout、EditText/Spinner、工具栏 SearchView 等 Material 控件映射为 ArkUI 组件时；为框架主题提供的窗口背景、文字色、列表分隔线、单行文字行框，以及位图或 9-patch 状态背景（ImageWell 按钮、EditText、SeekBar）确定目标取值时

## 适用情境

源布局中的 Button 等控件没有声明 background / backgroundTint / textColor / 圆角，外观来自应用主题（如 Theme.MaterialComponents 的 colorPrimary、colorOnPrimary）；目标工程已迁移同名语义色资源，而 ArkUI 对应组件不设样式时使用平台默认外观。也包括 Compose 的 Icon/Text 未写 tint/color、颜色来自宿主 Surface 的 LocalContentColor，而相邻页面或组件里有显式写 iconPrimary、brand 的图标可供照搬。也包括 foundation 的 BasicTextField 不传 textStyle（默认 TextStyle.Default，不读 Material 排版），以及颜色来自 GlanceTheme 一类依赖库主题、源码与规格里都没有具体色值。也包括 EditText/TextView 未声明 textColor、textSize，取值来自 Activity 主题（如 AppCompat Light 的 textColorPrimary）与 TextView 默认字号。也包括映射参考只给一对一或逐属性映射，而 ArkUI 组件自带的默认外观与源端 Material 默认不同：Checkbox 默认圆形、Radio 默认勾选样式、TextInput/Search/Select 默认填充底、Tabs 默认标签样式；MDC/M3 按钮另有字距与前景色 selector。 也包括应用主题父链止于 android:Theme.Holo/Material/DeviceDefault 的老工程（targetSdk 低），控件外观、窗口背景、文字色、ListView 分隔线由框架主题或 style="@android:style/*" 引用提供，应用源码与合成的 UI 快照里没有数值，本机装有 Android SDK 平台资源。

## 例外与边界

- 源控件在应用自有的 layout 或 style 中写出了具体值，此时按显式声明转换；style="@android:style/*" 或 ?android:attr 引用不算显式声明，外观仍由平台提供
- 决策记录明确要求目标端采用平台默认外观

## 原因

ArkUI 组件不会继承 Android 主题给控件的默认样式。规格只在全局写“颜色由资源系统负责”而不落到控件行，下游按控件行实现就得到平台默认外观。来源（API 24 工程）中不设样式的 ArkUI Button 呈默认蓝 #0A59F7 胶囊，与源端 Material 紫底白字小圆角按钮不符。另一应用中弹层的关闭图标与排序行首图标在源端都没写 tint（取宿主内容色，接近正文黑），写者统一套了 iconPrimary 令牌（该主题中为品牌紫）；同一文件里 Reset 文本显式写了 uiBackground 与禁用时 0.38 alpha，也被换成品牌色加 enabled()。实际提供方因组件而异：Scaffold、Surface 都可能提供 contentColor；foundation 组件不读 Material 的 LocalTextStyle；库主题色的回退值写在库资源里。凭“默认 onSurface”或另一设计体系的基线色填写，颜色和字号都会偏，还会被后续页面当先例照搬。另一应用中返修者见源 EditText 未声明 textColor，就把目标三个输入框统一硬编码为 #333333；另一处分数文字未声明 textSize，沿用了旧实现的 16；后续按主题默认主文字色与 TextView 默认 14sp 纠正。反方向同样成立：ArkUI 组件自带的默认外观（圆形复选框、勾选式单选、填充底输入框、Tabs 标签样式）不会因逐属性直译而消失。框架主题的提供方是 SDK 平台资源：windowBackground 是可能为渐变的 drawable，未声明颜色的 TextView 取 textAppearanceSmall 的次文字色，ListView 分隔线来自 listDivider，按钮与输入框背景是按状态切换的 9-patch。另一应用（Theme.Holo）中多个写者把“取不到精确值标待核”当作首选退路，凭记忆写成纯黑背景、纯白文字、透明按钮、静态下边框与改色的内置 Slider；召回提醒还把草稿里的未核值（“ImageWell 透明”、组件头注的 #ffcccccc）当作平台默认传给下一位写者，而本机 SDK 一直可查，返修正是从那里取值。

## 做法

1. 先定位提供方并解析到值：styles 父链止于 android:Theme.*，或控件用 @android:style/*、?android:attr 时，到本机 SDK（ANDROID_HOME 或 %LOCALAPPDATA%/Android/Sdk）的 platforms/android-<api>/data/res 沿 themes/styles → color selector 或 drawable → 具体值与原图解析，控件行为看 sources/android-<api>；Compose 与依赖库按下述各步找提供方。查过仍缺才标待核并写明已查路径；规格、注释与提醒里出现的具体值都注明出处，未核实的值不写成“平台默认”。
2. 规格提取时，对布局里没写样式的控件先查主题的父主题与语义色，把主题带来的背景色、字色、圆角、最小高度写进该控件自己的转换决策行，用已迁移的颜色资源名表达。
3. 框架主题的隐式外观不只是控件色，规格逐项写出：windowBackground 解析到最终 drawable（Holo 暗色经 screen_background_selector_dark 到 background_holo_dark，#000000→#272D33 自上而下渐变，铺在页面根部，与同名 @color 不是一个资源）；文字色按 textAppearance 取（Large/Medium 为主色，Small 与未声明颜色的 TextView 为次色，提示为 hint 色，Holo 暗色依次 #F3F3F3、#BEBEBE、#808080），源端显式色（如 @android:color/white）单列；ListView/ListActivity 未声明 divider 时写出主题 listDivider（含末行）；决定纵向排布的 wrap_content 单行 TextView 按源字体与 includeFontPadding 的行框定高。
4. 外观由位图或 9-patch 状态选择器决定的框架控件（Widget.ImageWell、EditText 的 editTextBackground、SeekBar 的拇指与双粗细轨道、CheckBox/RadioButton）复制平台原图，按状态切换并取 9-patch 内容内边距作为 padding；只给 ArkUI 内置组件改颜色不算显式化。
5. 实现时对照源主题语义色与目标颜色资源补齐修饰链：MaterialComponents 按钮对应 .backgroundColor($r('app.color.colorPrimary')) 与 .fontColor($r('app.color.colorOnPrimary'))，再按源按钮样式补 borderRadius 与最小高度；规格未写样式时同样补齐，并在转换报告注明依据来自主题。深浅色由 base/dark 资源自动切换。
6. Compose Icon/Text 未写 tint/color 时，沿调用链找最近的 Surface、Scaffold 或 CompositionLocalProvider，取它的 contentColor 对应的资源写进规格与实现；没核到宿主时标为待核，不写“默认 onSurface”或系统字色，也不照搬别处显式使用的 iconPrimary、brand 或其他页面的先例。源端显式写了 color 与禁用 alpha（如 uiBackground.copy(alpha = if (!enabled) 0.38f else 1f)）时，分别落实为 fontColor 与按状态的 opacity，不用品牌色加 enabled() 代替。
7. foundation BasicTextField 未传 textStyle 时按 TextStyle.Default 落实（14sp、黑色、系统字体）；bodyLarge 等 M3 排版只用于 M3 TextField/Text。
8. 依赖库主题色（如 GlanceTheme.widgetBackground）从库包的 res/values 与 values-night 取回退值（如 Gradle 缓存中的 aar）；取不到时登记待核，不用其他设计体系的基线色代替。
9. TextView/EditText 未声明 textSize/textColor 时按 TextView 默认值和 Activity 实际主题推导（如默认 14sp；AppCompat Light 主文字色 #DE000000，白底近似 #212121），不沿用旧实现、相邻组件或同组控件的硬编码值。
10. 映射 Material 控件时先列出它在源主题或库中的默认外观，逐项与 ArkUI 默认值对照并显式设置：Checkbox .shape(CheckBoxShape.ROUNDED_SQUARE)、Radio 的 indicatorType、TextInput/Select/Search 透明底与提示色、Tabs 用 SubTabBarStyle 指定 labelStyle 与指示条；源样式继承 MDC/M3 库按钮时，从合并资源解析 textAppearance 的 letterSpacing 与文字颜色 selector，不凭记忆取强调色。
