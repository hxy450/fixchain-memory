# 把主题、控件默认样式或依赖库隐式提供的外观写成目标显式样式：按“控件 style → 祖先布局 android:theme 覆盖 → Activity 主题 → 应用主题”定位提供方并解析到值（框架主题查本机 SDK 平台资源），部分属性显式时其余仍取控件默认；未写颜色的 TextView 取次文字色 textColorSecondary，EditText 才取主文字色

ID：`lesson-47785524c7f132ea7efe` · 版本：10

[本主题](index.md)

## 何时使用

规格提取阶段写控件转换决策，或页面实现阶段写出按钮、文本、工具栏等控件的修饰链时；为带 android:theme 覆盖（ThemeOverlay）的 AppBarLayout/Toolbar 定色时；为只显式写了部分属性的 Button、未写颜色的 TextView、SwitchPreference 开关、NavigationView 菜单项确定默认外观时；为未写 tint/color 的 Compose Icon、Text 着色，翻译未传 textStyle 的 BasicTextField，或迁移 GlanceTheme 等依赖库主题色时；把 CheckBox、RadioButton、MaterialButton、TabLayout、EditText/Spinner、工具栏 SearchView 等 Material 控件映射为 ArkUI 组件时；为框架主题提供的窗口背景、文字色、列表分隔线、单行文字行框，以及位图或 9-patch 状态背景（ImageWell 按钮、EditText、SeekBar）确定目标取值时

## 适用情境

源布局中的控件没有声明（或只声明了部分）background / backgroundTint / textColor / 圆角 / 字重 / 投影，外观来自应用主题、控件默认样式或祖先布局上的 android:theme 覆盖；ArkUI 对应组件不设样式时使用平台默认外观。也包括 AppBarLayout/Toolbar 以 android:theme 指定 ThemeOverlay（如 AppBarOverlay 的父样式为 ThemeOverlay.AppCompat.Light），而 Activity 主题是 DarkActionBar。也包括 Button/AppCompatButton 只写了 background、textColor、textSize，没有 style、textAllCaps、stateListAnimator、elevation，或自定义 View 继承 AppCompatButton 只换背景。也包括 TextView 未声明 textColor/textAppearance/style（缺省 textAppearanceSmall：次文字色、14sp、includeFontPadding）与 EditText 未声明 textColor（缺省主文字色）。也包括 PreferenceFragment 的 SwitchPreference 开关、未写 item 样式的 NavigationView 菜单项。也包括 Compose 的 Icon/Text 未写 tint/color、颜色来自宿主 Surface 的 LocalContentColor；foundation 的 BasicTextField 不传 textStyle；颜色来自 GlanceTheme 一类依赖库主题、源码与规格里都没有具体色值。也包括映射参考只给一对一或逐属性映射，而 ArkUI 组件自带的默认外观与源端 Material 默认不同：Checkbox 默认圆形、Radio 默认勾选样式、Toggle 胶囊开关、TextInput/Search/Select 默认填充底、Tabs 默认标签样式。也包括应用主题父链止于 android:Theme.Holo/Material/DeviceDefault 的老工程，外观由框架主题或 style="@android:style/*" 引用提供，本机装有 Android SDK 平台资源。

## 例外与边界

- 源控件在应用自有的 layout 或 style 中写出了具体值时，按显式声明转换这些属性；显式声明只覆盖被声明的几项，其余属性仍按控件默认样式补齐；style="@android:style/*" 或 ?android:attr 引用不算显式声明
- 决策记录明确要求目标端采用平台默认外观

## 原因

ArkUI 组件不会继承 Android 主题给控件的默认样式。规格只在全局写“颜色由资源系统负责”而不落到控件行，下游按控件行实现就得到平台默认外观，还会被后续页面当先例照搬。实际提供方因控件而异：祖先布局上的 android:theme 覆盖对整棵子树优先于 Activity 主题（DarkActionBar 只决定窗口装饰 ActionBar）；控件只写了部分属性时，其余仍来自控件默认样式（按钮的全大写、Medium 字重、投影与最小尺寸）；TextView 与 EditText 的缺省文字色不同。凭“Activity 是 DarkActionBar”“按钮已显式声明”“未写颜色即主文字色”推断，或凭记忆、另一设计体系的基线色、相邻页面先例填写，颜色、字号与投影都会偏；召回提醒还可能把草稿里的未核推断当作经验结论传下去。框架主题的提供方是 SDK 平台资源：windowBackground 可能是渐变 drawable，ListView 分隔线来自 listDivider，按钮与输入框背景是按状态切换的 9-patch，本机 SDK 一直可查。

## 做法

1. 先定位提供方并解析到值，顺序：控件自身 style/textAppearance → 祖先布局上的 android:theme/app:theme 覆盖（ThemeOverlay.AppCompat.Light 下标题取 textColorPrimary、导航图标取 colorControlNormal）→ Activity 主题 → 应用主题；框架主题（android:Theme.*、@android:style/*、?android:attr）到本机 SDK（ANDROID_HOME 或 %LOCALAPPDATA%/Android/Sdk）的 platforms/android-<api>/data/res 沿 themes/styles → color selector 或 drawable → 具体值解析，依赖库到其 aar 的 res 解析。Activity 主题是库主题（如 Theme.MaterialComponents.Light.Dialog）且不继承应用主题时，?attr/colorPrimary 等取该库主题的默认值（Material 库 values 的 design_default_color_*），不复用应用 color 资源中的同名 token。查过仍缺才标待核并写明已查路径；规格、注释与提醒里出现的具体值注明来自哪一层，源值已解析时不按可读性或记忆改写，未核实的值不写成“平台默认”。
2. 控件只显式声明部分属性时，先列出该控件默认样式的属性清单，再与源端显式属性做差集，差出的项照默认补齐。AppCompat/Material Button：textAllCaps 全大写与 sans-serif-medium、stateListAnimator 静止 2dp 投影/按下抬升 +4dp/禁用 0、minHeight 48dp 与 minWidth 88dp、样式内边距；自定义 shape 背景没有 pressed 态时按下不变色（ArkUI Button 设 stateEffect:false，按压用 stateStyles 只换投影）；继承 AppCompatButton 的自定义 View 只换背景时投影仍在。
3. 规格提取时，对布局里没写样式的控件先查主题的父主题与语义色，把主题与控件默认样式带来的背景色、字色、字重、圆角、最小高度、投影写进该控件自己的转换决策行，用已迁移的颜色资源名表达。
4. 框架主题的隐式外观不只是控件色，规格逐项写出：windowBackground 解析到最终 drawable（Holo 暗色经 screen_background_selector_dark 到 background_holo_dark，#000000→#272D33 自上而下渐变，铺在页面根部，与同名 @color 不是一个资源）；文字色按 textAppearance 取（Large/Medium 为主色，Small 与未声明颜色的 TextView 为次色，提示为 hint 色，Holo 暗色依次 #F3F3F3、#BEBEBE、#808080），源端显式色（如 @android:color/white）单列；ListView/ListActivity 未声明 divider 时写出主题 listDivider（含末行）；决定纵向排布的 wrap_content 单行 TextView 按源字体与 includeFontPadding 的行框定高。
5. 外观由位图或 9-patch 状态选择器决定的框架控件（Widget.ImageWell、EditText 的 editTextBackground、SeekBar 的拇指与双粗细轨道、CheckBox/RadioButton）复制平台原图，按状态切换并取 9-patch 内容内边距作为 padding；只给 ArkUI 内置组件改颜色不算显式化。
6. 实现时对照源主题语义色与目标颜色资源补齐修饰链：MaterialComponents 按钮对应 .backgroundColor($r('app.color.colorPrimary')) 与 .fontColor($r('app.color.colorOnPrimary'))，再按源按钮样式补 borderRadius 与最小高度；规格未写样式时同样补齐，并在转换报告注明依据来自主题。深浅色由 base/dark 资源自动切换。
7. Compose Icon/Text 未写 tint/color 时，沿调用链找最近的 Surface、Scaffold 或 CompositionLocalProvider，取它的 contentColor 对应的资源写进规格与实现；没核到宿主时标为待核，不写“默认 onSurface”或系统字色，也不照搬别处显式使用的 iconPrimary、brand 或其他页面的先例。源端显式写了 color 与禁用 alpha（如 uiBackground.copy(alpha = if (!enabled) 0.38f else 1f)）时，分别落实为 fontColor 与按状态的 opacity，不用品牌色加 enabled() 代替。
8. foundation BasicTextField 未传 textStyle 时按 TextStyle.Default 落实（14sp、黑色、系统字体）；bodyLarge 等 M3 排版只用于 M3 TextField/Text。
9. 依赖库主题色（如 GlanceTheme.widgetBackground）从库包的 res/values 与 values-night 取回退值（如 Gradle 缓存中的 aar）；取不到时登记待核，不用其他设计体系的基线色代替。
10. TextView/EditText 未声明 textSize/textColor 时按控件区分：TextView（含 AppCompatTextView）没有 textColor、textAppearance、style 时取 textAppearanceSmall——14sp、?android:textColorSecondary（AppCompat/Material 浅色 #8A000000、深色 #B3FFFFFF，白底约 #757575）；EditText 取 editTextColor 即主文字色（浅色 #DE000000）。给 ArkUI Text 显式写 fontColor，不留给 ArkUI 默认色（未设置时为 #e6182431，HarmonyOS 文档 ts-basic-components-text，访问于 2026-10-17），也不沿用旧实现、相邻组件或同组控件的硬编码值。TextView 默认 includeFontPadding=true，ArkUI Text 默认不加首尾行间距：目标 SDK 为 API 23 起时显式写 .includeFontPadding(true) 对齐源端（本机 SDK API 24 text.d.ts）；低于 API 23 时，顶部对齐、决定纵向排布的文字按源字体度量补纵向差，或登记待设备核对。
11. 映射 Material 控件时先列出它在源主题或库中的默认外观，逐项与 ArkUI 默认值对照并显式设置：Checkbox .shape(CheckBoxShape.ROUNDED_SQUARE)、Radio 的 indicatorType、TextInput/Select/Search 透明底与提示色、Tabs 用 SubTabBarStyle 指定 labelStyle 与指示条；SwitchPreference/Switch → Toggle 只是功能映射（框架 Material Switch 为细轨道加外凸带投影拇指，偏好行中开关本身不接收点击、由整行切换，开关设 hitTestBehavior(HitTestMode.None)），外观要一致时自绘或显式定制；未写 item 样式的 NavigationView 菜单项写出选中项通栏底色、加粗与 colorPrimary 着色，未选图标次文字色着色，组间通栏分隔与列表上下留白。源样式继承 MDC/M3 库按钮时，从合并资源解析 textAppearance 的 letterSpacing 与文字颜色 selector，不凭记忆取强调色。
