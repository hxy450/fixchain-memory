# View 控件未显式写的外观由主题、默认样式或依赖库提供时，按提供方链解析到值再写成目标显式样式；部分属性显式时其余仍取默认

ID：`lesson-47785524c7f132ea7efe` · 版本：10

[本主题](index.md)

## 何时使用

规格提取阶段写 View 控件转换决策，或页面实现阶段写按钮、工具栏、列表、输入框等控件的修饰链，而布局与应用 style 没写全外观时；控件或祖先布局带 android:theme 覆盖（ThemeOverlay），或主题父链止于 android:Theme.Holo/Material/DeviceDefault、style 引用 @android:style/* 时

## 适用情境

源布局中的控件没有声明（或只声明了部分）background / backgroundTint / textColor / 圆角 / 字重 / 投影 / 最小尺寸，外观来自应用主题、控件默认样式、祖先布局上的 android:theme 覆盖或依赖库；ArkUI 对应组件不设样式时使用平台默认外观。也包括 AppBarLayout/Toolbar 以 android:theme 指定 ThemeOverlay（如父样式为 ThemeOverlay.AppCompat.Light），而 Activity 主题是 DarkActionBar；Button/AppCompatButton 只写了 background、textColor、textSize，或自定义 View 继承 AppCompatButton 只换背景；框架主题提供的窗口背景、列表分隔线与按状态切换的位图背景（ImageWell、EditText、SeekBar）；库在 values-land、values-sw600dp 下另有取值而应用 res 没有覆盖。

## 例外与边界

- 源控件在应用自有的 layout 或 style 中写出了具体值时，按显式声明转换这些属性；显式声明只覆盖被声明的几项；style="@android:style/*" 或 ?android:attr 引用不算显式声明

## 原因

ArkUI 组件不会继承 Android 主题给控件的默认样式。规格只在全局写“颜色由资源系统负责”而不落到控件行，下游就得到平台默认外观，还会被后续页面当先例照搬。实际提供方因控件而异：祖先布局上的 android:theme 覆盖对整棵子树优先于 Activity 主题（DarkActionBar 只决定窗口装饰 ActionBar）；控件只写了部分属性时，其余仍来自默认样式；框架主题的 windowBackground 可能是渐变 drawable，ListView 分隔线来自 listDivider，按钮与输入框背景是按状态切换的 9-patch。凭记忆、目标平台 sys 色或相邻页面先例填写，颜色、字号与投影都会偏；提醒里的未核推断也会被当作经验结论传下去。

## 做法

1. 按顺序定位提供方并解析到值：控件自身 style/textAppearance → 祖先布局上的 android:theme/app:theme 覆盖（例：ThemeOverlay.AppCompat.Light 下标题取 textColorPrimary、导航图标取 colorControlNormal）→ Activity 主题 → 应用主题。框架主题（android:Theme.*、@android:style/*、?android:attr）到本机 SDK（ANDROID_HOME 或 %LOCALAPPDATA%/Android/Sdk）的 platforms/android-<api>/data/res 沿 themes/styles → color selector 或 drawable → 具体值解析；依赖库到 Gradle 缓存中对应版本 aar 的 res 解析。
2. 同时列出这些资源在 values-land、values-sw600dp、values-w480dp 等限定目录的覆盖值；应用 res 没有横屏覆盖不代表库没有，目标用 base + horizontal 等同名资源或运行期按窗口取值承载，代码只引用资源，不写成竖屏单值字面量。
3. 控件只显式声明部分属性时，先列出该控件默认样式的属性清单，再与源端显式属性做差集，差出的项照默认补齐。例：appcompat 1.7.1 的 Base.Widget.AppCompat.Button 为 minHeight 48dip、minWidth 88dip、textAppearanceButton（全大写、sans-serif-medium），values-v21 起继承框架 Widget.Material.Button，stateListAnimator 为 button_state_list_anim_material：静止 2dp 投影、按下再抬升 4dp、禁用为 0（android-36.1 dimens_material.xml 的 button_elevation_material、button_pressed_z_material）；自定义 shape 背景没有 pressed 态时按下不变色（ArkUI Button 设 stateEffect:false，按压用 stateStyles 只换投影）；继承 AppCompatButton 的自定义 View 只换背景时投影仍在。MaterialComponents/Material3 主题经 MaterialComponentsViewInflater 把 Button 换成 MaterialButton，样式取主题的 materialButtonStyle（material 1.12.0 values.xml），另行解析，不共用这组值。
4. 规格提取时，对布局里没写样式的控件查主题的父主题与语义色，把主题与默认样式带来的背景色、字色、字重、圆角、最小高度、投影写进该控件自己的转换决策行，用已迁移的颜色资源名表达；实现时据此补齐修饰链（例：MaterialComponents 按钮 .backgroundColor($r('app.color.colorPrimary')) 与 .fontColor($r('app.color.colorOnPrimary'))，再按源按钮样式补 borderRadius 与最小高度），深浅色由 base/dark 资源切换。
5. 框架主题的隐式外观不只是控件色，逐项写出：windowBackground 解析到最终 drawable（例：Theme.Holo 在硬件加速时经 screen_background_selector_dark 取 drawable/background_holo_dark，android-36.1 中为 #FF000000→#FF272D33、angle 270 的自上而下渐变，与同名 @color/background_holo_dark 不是一个资源），铺在页面根部；ListView/ListActivity 未声明 divider 时写出主题 listDivider（含末行）；外观由位图或 9-patch 状态选择器决定的控件（Widget.ImageWell、editTextBackground、SeekBar 的拇指与双粗细轨道）复制平台原图，按状态切换并取 9-patch 内容内边距作为 padding，只给 ArkUI 内置组件改颜色不算显式化；控件行为（如 SeekBar 触摸取值）读 sources/android-<api> 中对应类。
6. 规格、注释与提醒里出现的具体值注明来自哪一层与哪个资源文件；源值已解析时不按可读性或记忆改写。SDK 与依赖 aar 都查过仍缺的值，在规格或报告里列出已查路径并作为缺口交协调者，不写成“平台默认”。
