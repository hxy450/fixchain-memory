# LazyForEach 改为 Repeat.virtualScroll 时逐个列表核对：含 Stretch/layoutWeight 装饰的内容定高项先核首项

ID：`lesson-150e48577e599f64ee23` · 版本：3

[本主题](index.md)

## 何时使用

架构重构或缺陷修复阶段，把 LazyForEach 列表改写为 Repeat(...).virtualScroll() 并确定验收方式时

## 适用情境

List 的每个 ListItem 高度由内容决定（按日期分组、条数不等、可折叠），项内有依赖父约束定尺寸的装饰（alignSelf(ItemAlign.Stretch) 贯穿轴线、layoutWeight 竖线或内容列）；或列表按日期、分页整体替换数组。

## 例外与边界

- 项高度固定或由显式尺寸决定，且已在设备上核过首项 bounds

## 原因

Repeat.virtualScroll 对内容定高、含 Stretch/layoutWeight 装饰的 ListItem 可能把首项分配成接近 List 视口的高度（设备实测：只改项内布局不能恢复，ForEach + ListItem 按内容排列；装饰与 virtualScroll 各自的贡献未分离）。整体替换数据的 Repeat 列表若把 ri.item 按值传给 @Builder，非空切到非空时会保留旧条目。只看编译通过和旧符号清零发现不了这两类问题。

## 做法

1. 逐个列表看 ListItem 的高度来源；项内有 Stretch、layoutWeight、百分比高度或需测高的装饰时，不直接套统一模板，先在设备上 dump 首个 ListItem 的 bounds，确认是内容高度而不是视口高度。
2. 条数固定、按批加载或很短的列表，先评估是否需要虚拟化；出现首项被撑成视口高度时改用 ForEach + ListItem，并在重构报告中记录理由。
3. each/template 回调里拆出的 @Builder 或子组件接收完整 RepeatItem、在内部读 ri.item；整体替换数据的列表在设备上做一次“非空 → 非空”切换，确认已显示条目随新数据刷新。
4. 批量重构的验收把受影响的列表页纳入设备冒烟；页面因数据未加载看不到列表时记为未验证。

来源支持：2 张卡 · 1 次迁移 · 1 个应用
