# 批量把 LazyForEach 改为 Repeat.virtualScroll 时逐个列表核对项高度与数据切换；内容定高、含 Stretch/layoutWeight 装饰的项先真机核首项尺寸，短列表按豁免用 ForEach

ID：`lesson-150e48577e599f64ee23` · 版本：1

[本主题](index.md)

## 何时使用

架构重构或缺陷修复阶段，按规范批量改写列表渲染（LazyForEach → Repeat(...).virtualScroll()）并确定验收方式时

## 适用情境

List 的每个 ListItem 高度由内容决定（按日期分组、条数不等、可折叠），项内有依赖父约束定尺寸的装饰（alignSelf(Stretch) 贯穿轴线、layoutWeight 竖线或内容列）；或列表按日期、分页整体替换数组。重构规则要求统一改用 Repeat 并加空参 virtualScroll()，允许短列表豁免。

## 例外与边界

- 项高度固定或由显式尺寸决定，且已在设备上核过首项 bounds

## 原因

统一模板忽略了项高度来源与数据整体替换：来源中改写后首个日期项被分配成接近视口高度，只改项内布局没有恢复，改回 ForEach + ListItem 才按内容排列；另一处按日期整体替换数据的 Repeat.virtualScroll 列表（each 按值把 ri.item 传给 @Builder）在非空日期间切换时保留旧条目，改为 ForEach 后恢复，是否只需改传完整 RepeatItem 未经验证。两处验收都只看编译通过和旧符号 grep 归零，受影响页面没有进入真机冒烟。

## 做法

1. 逐个列表看 ListItem 的高度来源；项内有 Stretch、layoutWeight、百分比高度或需测高的装饰时，不直接套统一模板提交，先在真机 dump 首个 ListItem 的 bounds，确认是内容高度而不是视口高度。
2. 条数固定、按批加载或很短的列表，先按规则的短列表豁免评估是否需要虚拟化；出现首项被撑成视口高度或整体替换后旧条目残留时，改用 ForEach + ListItem，并在重构报告中记录豁免理由。
3. 批量重构的验收把受影响的列表页纳入真机冒烟，包含一次“非空 → 非空”的数据切换；页面因数据未加载看不到列表时记为未验证。
