# 源端按末项可见状态触发追加加载时，用 onScrollIndex 上升沿复刻，不用 onReachEnd

ID：`lesson-4cae87de686327ba6283` · 版本：2

[本主题](index.md)

## 何时使用

规格提取与列表实现阶段，为分页列表确定触底自动追加加载的触发机制时

## 适用情境

源列表用状态派生条件触发追加加载（如 derivedStateOf{最后可见项下标 == 总项数−1} 且不在重试态时 LaunchedEffect 执行一次），条件在首屏未铺满、数据变化或重试态变化后也会重新成立；目标平台另有 List.onReachEnd 这类滚动到底事件。

## 原因

onReachEnd 是滚动到底的事件：首屏不满一屏时不触发，追加后仍不满也不再触发，重试态清除后不会复核；把源端的状态条件换成事件，短列表就停在第一页。规格只写一个平台回调名时，实现者照抄。

## 做法

1. 规格遇到源码自定义的触发 helper，先读函数体及其判定函数，写清条件（总项数>0 且最后可见项为末项）、时机（由假变真一次，数据或重试态变化后重判）与各调用点实参。
2. 实现时用 onScrollIndex 的 end 下标与当前总项数（含头尾项）计算条件，数据或重试态变化时复核，做上升沿触发；各列表复用同一个触发控制器。
3. 逐个调用点核对实参：源码传字面 false 的重试参数，不照搬别的列表对追加失败态的抑制。

## 可选检查

- 列表只有 1–2 项、不满一屏时会立即加载下一页；追加后仍不满时继续加载
