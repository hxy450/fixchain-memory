# stickyHeader 用 ListItemGroup 头部加 List.sticky(StickyStyle.Header)，吸顶内容不移出 List

ID：`lesson-2674172eb470a443213d` · 版本：1

[本主题](index.md)

## 何时使用

界面实现与规格映射阶段，把 Compose LazyColumn 的 stickyHeader（含按开关在吸顶与普通项之间切换）落成 ArkUI 列表结构，或对吸顶写法没把握、准备改用别的结构时

## 适用情境

源端 LazyColumn 内用 stickyHeader 放吸顶内容，其余项随列表滚动，可能由 pinned 一类开关在 stickyHeader 与 item 之间切换；规格映射为 List + ListItemGroup(StickyStyle.Header)，或并列给出“Stack + offset”一类备选；转换批次禁止编译，写者记不清吸顶 API。

## 原因

吸顶头仍属于滚动容器：从头部起拖照常滚动列表，点击照常命中。把吸顶内容移到 List 外做固定兄弟，外观一样，但从吸顶区起拖不再滚动，依赖“内容是否超出视口”的判断也少算了头部高度。

## 做法

1. 写成 List { ListItemGroup({ header: this.吸顶内容() }) { 其余 ListItem } }.sticky(StickyStyle.Header)，吸顶内容留在 List 里；按开关在吸顶与普通项之间切换时，两种状态都在同一个 List 内实现（普通态把内容放进普通 ListItem）。
2. 吸顶分支里依赖“内容是否超出视口”的逻辑（如内容未满时不折叠顶栏），把头部与其余项一起测量，测量挂在 ListItemGroup 或等价容器上，不只测 ListItem 内容。
3. 对吸顶 API 没把握时，先在本机 SDK 的 list.d.ts 查 sticky/StickyStyle 与 ListItemGroup 的 header 选项；仍确认不了，就按派工对不确定 API 的处理写出规格指定的结构并登记，不改用把头部移出滚动容器的替代写法。规格给吸顶备选时只列保持“头部属于滚动容器”的写法。

## 可选检查

- 对吸顶行为有疑问时，从吸顶区起拖确认列表滚动，并点一次头部内的控件确认命中。
