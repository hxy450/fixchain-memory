# LazyForEach 整批替换或延迟填充数据时保持同一数据源实例并发 onDataReloaded 等通知，不重新赋值数据源对象

ID：`lesson-92ced15126309dd90a1a` · 版本：1

[本主题](index.md)

## 何时使用

界面实现、返修或重写阶段，为 LazyForEach 列表实现源端 setAdapter、notifyDataSetChanged 一类整批换数据、排序或延迟填充时

## 适用情境

目标列表用 LazyForEach 绑定实现 IDataSource 的数据源对象，并把该对象存在组件状态里；源端在排序、筛选、切换适配器或延迟加载后整批替换数据，写者准备用“this.数据源 = 新数据源”换数据。

## 例外与边界

- 列表改用 ForEach 或 Repeat 绑定可观察数组：数组整体重新赋值本身会触发刷新

## 原因

LazyForEach 依靠数据源上注册的 DataChangeListener 通知更新；重新赋值数据源对象后已观察到列表不随新数据刷新（排序后行不变），工程的组件构建 skill 也把“LazyForEach 不响应数据源对象重赋值”列为响应式硬规则。整批 reload 时键若与旧数据集重复，已有行节点还会被复用成旧内容。

## 做法

1. 数据源对象在组件生命周期内只创建一次，作为稳定宿主：整批替换、排序或延迟填充时在宿主内部换掉底层数组，再调用已注册监听的 onDataReloaded()；局部增删改用 onDataAdd、onDataDelete、onDataChange 等对应通知。
2. keyGenerator 生成的键在先后数据集之间保持唯一（以条目稳定 id 为主，必要时加数据集代次前缀），reload 后不复用错位的旧行。

## 可选检查

- 改写已有 LazyForEach 列表后，检索数据源字段在初始化之外是否还有重新赋值。
