# 异步分页列表新增批量异步修补时按列表代次丢弃过期结果、按 ID 修补当前列表；行内远端提交按条目维护在途集合

[本主题](index.md)

## 何时使用

列表页实现阶段，为触底分页、下拉刷新的列表新增返回后状态同步，或接入逐行远端提交按钮（加入书架、收藏）时

## 适用情境

列表由分页回调异步追加、下拉刷新整体替换；返回页面时要逐条 await 本地查询来刷新行内标记；每行还有调用远端接口的提交按钮；页面已有请求序号或 busy 锁保护了部分入口。

## 原因

在 await 前复制整张列表、结束后整体赋回，会用旧快照覆盖等待期间追加的分页或刷新后的新列表；同页已有的请求序号如果没用到新增的异步入口，保护就漏了一处。行内提交没有在途标记时可以重复发请求（来源中此项为代码核查推断，未见实测重复请求）。来源中写者读到源端加架后只修补当前条目、分页异步改写列表，仍以整表回写实现返回刷新，加架按钮也没沿用同页关注按钮的锁。

## 做法

1. 新增批量异步查询（如返回时逐条刷新加架标记）时先记录列表代次（沿用页面已有的 requestSerial），等待结束后代次已变就放弃；命中项按 ID 修补当前列表，不在 await 前复制整表再赋回。
2. 行内远端提交按条目 ID 维护在途集合：发请求前检查并加入，成功和失败都释放；在途时显示加载态、不再发请求，列表 key 包含该状态以触发重绘。页面已有请求序号或 busy 锁时，逐一核对分页回调、返回刷新、行内按钮等每个新增异步入口是否需要同类保护。
