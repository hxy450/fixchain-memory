# 每个列表的数据按源端该列表自己的路径迁移：各 Adapter 绑定各自的数据源与层级状态，本地变换和排序器取自该列表，不复用别的列表

ID：`lesson-b6146f290e871c82e61d` · 版本：4

[本主题](index.md)

## 何时使用

界面与数据实现阶段，把源端多个 RecyclerView/Adapter（热门、全量、当前层级）迁移为 ArkUI 列表或网格时；为某个列表准备数据（本地 shuffled/filter/sort）或新增列表查询、选择排序比较器时

## 适用情境

源页面有多组列表分别绑定不同数据（热门、全量分组、当前层级子列表），点击推进到下一层级并支持返回；或列表数据来自对本地集合做 shuffled()/filter/sortedWith 等纯本地变换；或源端按列表区分排序器与排序键（如某列表专用的 Comparator 与另一列表的排序键不同），目标多个列表共用同一仓库查询与比较函数。

## 例外与边界

- 数据依赖网络、跨页状态等当前确实不可得的工件时，按前向依赖登记；本条只覆盖可在本地完成的数据准备

## 原因

多个网格渲染同一数组时页面看似完整，实际丢失了分组与层级语义；同文件里现成的比较器按另一列表的规则排序，照搬后新列表顺序与源端不同；把纯本地变换当作依赖未建模块而登记占位，后续阶段常无人认领，功能一直缺失。

## 做法

1. 逐个列出源端 Adapter 与其数据源、点击推进和回退处理（各级点击回调与返回处理函数），目标每个分组绑定各自的数据，并实现逐级推进与返回上一级。
2. 数据源只是对本地集合做 shuffled/filter/sort 时，直接在目标侧复现该变换（如对副本做 Fisher-Yates 洗牌），不以“ViewModel 等价体未建”为由登记前向占位。变换的执行时机按源端持有该状态的生命周期：源端在 Activity 或 ViewModel 创建时变换一次、重建后保留的，不随组件每次重建重做；来源案例放在组件初始化处。
3. 新增列表查询前，在源端找到该列表自己的排序器与排序键、方向，按其实现独立的比较函数；源端列表读取用户排序偏好时，只把适用于该列表的配置传入。
