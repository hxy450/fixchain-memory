# 避让区写入窗口模型时按方位取矩形、底部取两类避让区的较大值，先 px2vp 再供 padding 消费

ID：`lesson-cf111aadb8804649b578` · 版本：4

[本主题](index.md)

## 何时使用

沉浸式安全区实现阶段，在 EntryAbility 或窗口服务里用 getWindowAvoidArea、windowRect 测量并写入共享窗口模型时；把页面里的测量代码收敛成全局模型时

## 适用情境

目标用 setWindowLayoutFullScreen(true) 全屏，EntryAbility 通过 getWindowAvoidArea 取状态栏、导航条高度，通过 getWindowProperties().windowRect 取窗口尺寸，写入 AppStorageV2 等共享的窗口模型；各页把这些值直接放进 .padding()/.height()，按 vp 解释；底部避让可能只用 TYPE_NAVIGATION_INDICATOR 测量，或复制 TYPE_SYSTEM 那一行只改了常量。

## 原因

避让区按方位落在不同矩形：TYPE_NAVIGATION_INDICATOR 的避让在窗口底部，值在 bottomRect，复制 TYPE_SYSTEM 那一行只改常量会读成 topRect（恒为 0）；三键导航栏的避让在 TYPE_SYSTEM 的底部，只测 TYPE_NAVIGATION_INDICATOR 时三键模式底部避让可能为 0。避让区 Rect 与 windowRect 的数值单位是 px，ArkUI 数字尺寸默认是 vp，原样写入后高密度屏上的避让量会放大数倍。这些错误收敛进全局窗口模型后，所有页面都跟着错。

## 做法

1. 顶部取 getWindowAvoidArea(TYPE_SYSTEM).topRect.height；底部取 TYPE_SYSTEM 与 TYPE_NAVIGATION_INDICATOR 两者 bottomRect.height 的较大值；订阅 avoidAreaChange（及窗口尺寸变化）在导航方式切换、旋转时重算。复制测量代码时同时核对矩形字段。
2. 写入模型前统一换算：const ui = mainWindow.getUIContext()，top = ui.px2vp(avoid.topRect.height)，底部与窗口宽高同理，模型注释标明字段为 vp。getUIContext 只在 windowStage.loadContent 成功回调之后可用；必须在此之前换算时，用 display.getDefaultDisplaySync().densityPixels 计算 vp = px / densityPixels，不把 px 值写进声明为 vp 的字段。
3. 把页面测量收敛成共享窗口模型前，对照沉浸式参考或工程内已正确的实现逐字段核语义与单位，不直接照搬现有页面片段。

## 可选检查

- 在带导航指示条的设备上确认模型中的底部避让非 0，且等于实测 px 值经 px2vp 后的结果。
