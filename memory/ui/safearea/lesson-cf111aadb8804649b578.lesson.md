# getWindowAvoidArea 与 windowRect 的数值是 px：在 windowStage.loadContent 成功回调里取 UIContext、先 px2vp 再写入供 padding 消费的窗口模型（loadContent 之前调 getUIContext 抛 1300002）

ID：`lesson-cf111aadb8804649b578` · 版本：3

[本主题](index.md)

## 何时使用

沉浸式安全区实现阶段，在 EntryAbility 或窗口服务里把避让区、窗口尺寸写进共享窗口模型时；安排 EntryAbility.onWindowStageCreate 中依赖 UIContext 的步骤相对 loadContent 的时机时

## 适用情境

目标用 setWindowLayoutFullScreen(true) 全屏，EntryAbility 通过 getWindowAvoidArea 取状态栏、导航条高度，通过 getWindowProperties().windowRect 取窗口尺寸，写入 AppStorageV2 共享的窗口模型；各页把这些值直接放进 .padding()/.height()，按 vp 解释。 也包括换算或其他依赖 UIContext 的步骤（如 setKeyboardAvoidMode）写在 onWindowStageCreate 中、位于 loadContent 调用之前或在其回调之外同步执行。

## 原因

避让区 Rect 与 windowRect 的数值单位是 px，ArkUI 数字尺寸默认是 vp；原样写入后，高密度屏上的避让量会放大数倍。来源中修复者首次写入时注释已写“这是物理像素、需换算”，读到工程内页面已用 uiContext.px2vp 的样例后，反而删去换算占位，把注释改成“按 vp 消费”，也没写窗口宽高。另一应用基线 EntryAbility 把导航避让区 84px 原样发布，页面按 vp 消费后底部留白过大，修复在发布端统一 px2vp。UIContent 只在 loadContent 成功后建立，之前调用 mainWindow.getUIContext() 会抛 1300002（Uicontent is nullptr），冷启动即闪退；d.ts 签名不写这一时序，只凭成员存在推定此刻可调用就会写错，而不运行应用的编译门发现不了。

## 做法

1. 在 windowStage.loadContent 的成功回调里（err.code 为 0 之后）取 const ui = mainWindow.getUIContext()；top = ui.px2vp(avoid.topRect.height)，bottom 与窗口宽高同理；模型注释标明字段为 vp。onWindowStageCreate 中 loadContent 之前只做不依赖 UIContent 的窗口调用。
2. 一时取不到 UIContext 时保留 px 字段并上报，不把 px 值写进声明为 vp 的字段。

## 可选检查

- 改动 EntryAbility 生命周期后静态核对：onWindowStageCreate 中位于 loadContent 之前或其回调之外同步执行的代码不调用 getUIContext、不依赖 UIContent。
