# Tab 宿主不给承载全部 Tab 的内容区统一加顶部安全区：按各 Tab 源 Fragment 的状态栏处理分别落实，背景延伸的 Tab 只让前景避让；只加在底栏的 padding 只加到 tabBar

ID：`lesson-48e9408812c28e934db8` · 版本：2

[本主题](index.md)

## 何时使用

规格与界面实现阶段，实现 MainActivity/Tab 宿主的内容区内边距、为作为 Tab 子组件的 Fragment 写安全区分工或转换其顶部布局时

## 适用情境

Android 主 Activity 以 ViewPager/Tab 承载多个 Fragment，主题 windowTranslucentStatus 或 ImmersionBar 让状态栏透明；各 Fragment 自行决定是否为状态栏让位：有的头图直接铺到状态栏下（未设 statusBarView，或用 titleBarMarginTop/fitsSystemWindows），有的在顶对父容器的背景上放一个由 statusBarView 撑成状态栏高度的占位 View（如 v_status_bar），只把前景内容约束在占位之下；MainActivity 的内边距可能只加在底栏容器上。目标用单个宿主页承载各 Tab，可能给承载全部 Tab 槽位的容器统一加顶部 windowTopPadding 和左右 padding；页面规格按 page_type（sub_component）标“无需沉浸”，或把页内占位概括成“安全区由宿主统一处理”。

## 原因

宿主对整块 Tab 内容统一加顶部 padding，会把背景和前景一起下推：头图应铺到状态栏下的 Tab 顶部出现白带，靠占位只让前景避让的 Tab 则前景相对背景错位（如欢迎语与头图内置文字重叠）；底栏专属的左右 padding 加到整个内容区会让每个 Tab 两侧留白；子页再加一次安全区就重复消费。sub_component 标记只说明子页不做窗口级沉浸设置，不等于页内“背景延伸、前景避让”的分层可以交给宿主；规格把占位概括为“宿主统一处理”、转换者据此跳过、宿主又统一内缩时，就没有任何一层按源端分层。来源的两个应用都出现过宿主对全部 Tab 统一内缩、并在转换回执里把它当作前景 inset，转换者按规格跳过沉浸且没有登记宿主交接。

## 做法

1. 宿主不在承载全部 Tab 的内容容器上统一加状态栏 top padding：逐个查各 Tab 源 Fragment 的状态栏处理（ImmersionBar 是否设 statusBarView、布局有无状态栏占位 View、是否用 titleBarMarginTop/fitsSystemWindows、头图是否铺到状态栏下），确定该 Tab 是背景从窗口顶起还是整体避让。
2. 背景延伸的 Tab：背景从可绘制区顶端开始、不加偏移；前景按源端让出状态栏高度。源端用占位 View 只压前景时，在子页前景容器消费宿主下发的顶部避让值（如 @Consumer 注入的 windowTopPadding 作 padding top），再叠加源 margin；也可由宿主按 Tab 注入偏移，但只作用于前景。状态栏图标深浅按源端设置。
3. 规格提取写 sub_component 的安全区节时按层写明：背景是否延伸到窗口顶、哪一层让出状态栏高度、避让值由谁提供、在页内哪一层消费；不要概括成“由宿主统一处理安全区”。needs_immersive_safearea=false 只跳过窗口级沉浸设置，页内状态栏占位仍按层级转换。
4. Activity 只加在底栏容器上的 padding 只加到 tabBar，内容区保持 ViewPager 的全宽。
5. 源码的沉浸信号与规格的自动判定冲突时以源码为准，在报告中列出，并把“宿主取消该 Tab 顶部 padding 或改为按 Tab 注入”写成交接项；子页写前查看宿主已处理了哪些安全区，同一边界只消费一次。

## 可选检查

- 需要核对时，用布局 dump 看子页：背景顶边应等于窗口顶边，首个前景元素顶边应等于状态栏高度加源 margin。
- 宿主去掉统一 padding 后头图仍比所在槽位起点低约一个安全区高度时，比较头图节点与槽位、嵌入页根滚动容器的 y 坐标；位移落在嵌入组件内部，就在该组件内排查，不再调整宿主。
