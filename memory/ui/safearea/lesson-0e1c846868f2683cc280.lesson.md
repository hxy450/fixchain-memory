# 全屏窗口下按边落实前景避让：贴底内容让出避让值，padding 与底色挂在实际占据该边的普通容器层

ID：`lesson-0e1c846868f2683cc280` · 版本：7

[本主题](index.md)

## 何时使用

沉浸式安全区实现阶段，为全屏页的标题栏、底部按钮行、按键区、Tab 栏或贴底弹层确定顶部与底部避让及承载它的容器层时；为已有固定高度（含内容下方留白）的底栏或底部定位元素补导航条避让时

## 适用情境

目标页面在 setWindowLayoutFullScreen(true) 下消费入口发布的顶部、底部避让值；Android 源布局的底部按钮行、底部 sheet 没有导航栏间距（源窗口不延伸到导航栏下，或 BottomSheetDialog、Material3 BottomSheet 由系统或库处理 inset）；根容器与底部内容层背景色不同；原 Tab 栏固定高度已在图标文字下方留有空白；NavDestination 页保留预设系统标题栏；壳页承载声明豁免安全区的内嵌子页。

## 例外与边界

- 目标窗口按源端保持非全屏时不做前景避让，内容本就在系统栏之间
- 宿主为 Tabs/Swiper 等由子页铺满的容器、要补状态栏实色带时，按 lesson-fe10bd2491ca4ba82cb5 用只承担避让的外层 Column 承载

## 原因

setWindowLayoutFullScreen(true) 与 expandSafeArea 只让窗口或容器背景延伸进系统栏，都不给前景留避让空间；源 XML 没有底部间距是因为源窗口不延伸到导航栏，目标全屏窗口会延伸，照 XML 写就贴屏底，bindSheet 内容贴屏底布局也不会自动避让。padding 区显示的是承载它的容器的背景，加错层就露出错误底色。原高度已含底部留白时再整额叠加，留白会翻倍。

## 做法

1. 全屏页的每条边都由一个前景层消费避让：顶部加在包住标题栏的那一层，底部加在伸到窗口底边的内容层（底部 CTA、按键区、贴底浮层与 bindSheet 内容，子组件由宿主经 @Param 注入）；入口尚未开全屏时也接上（当下值为 0），按 min(宽,高) 取边长的区域在避让之后测量。页面规格标注全屏或沉浸式安全区时直接消费已发布的避让值，不用固定小 padding 代替。
2. 放置避让 padding 前先确认该边由哪一层背景占据，把 padding 加在那一层；根容器只承担它实际占据的边。Tab 栏保持内容高度，让其背景延伸覆盖底部避让区。
3. 壳页承载声明豁免安全区、自绘工具栏的内嵌子页时，壳根容器同时补顶部与底部避让；移植 Android insets 时逐边核对四边各由谁负责，包括经 fitsSystemWindows 隐式消费的顶部。
4. 需要标题栏的全屏 NavDestination 页用 hideTitleBar(true)，自绘工具栏并给其所在容器加顶部避让；除非在根容器扩展状态下实测确认，不预设系统标题栏会自动避让。背景需要延伸到系统栏下时，才在背景节点自身加 expandSafeArea。
5. 原 Tab 栏或底栏的固定高度已含内容下方留白时，先从源布局（layout、dimen、barHeight）拆出这段留白，让避让值替代或抵扣它，不在总高度上整额叠加；三键与手势导航以当前设备 getWindowAvoidArea 实测的各模式避让值为准，用户声明正常的模式把“布局不变”列为验收；同一避让值在两种模式下视觉占用不同时，按 lesson-8bc258c2833be65f4fcd 的 TYPE_SYSTEM 底部高度区分导航方式，或请用户取舍并标明未验证的模式。
6. 已有固定底部偏移的元素先比较该偏移与实测避让高度，已足以避开时不追加，也不把用户未提出的组件并入同一改动。

## 可选检查

- 开启全屏的一方逐页检索顶部与底部避让的消费点：只处理了顶部或只处理了底部的页面不算完成；有设备时确认底部按钮与屏底之间留出避让高度，横屏下贴底内容不落进导航条区。
- 调整底部 Tab 高度后，分别在三键与手势导航模式下截图核对文字到屏底或指示条的间距。
