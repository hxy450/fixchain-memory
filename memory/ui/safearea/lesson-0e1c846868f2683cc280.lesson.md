# 仅当源窗口本身延伸到系统栏下才做全屏沉浸与底部避让：导航指示条取 bottomRect，贴底按钮、按键区、Tab 栏与 bindSheet 内容都让出避让值（原高度已含底部留白时先抵扣），并加在占据屏幕底边的那一层

ID：`lesson-0e1c846868f2683cc280` · 版本：6

[本主题](index.md)

## 何时使用

沉浸式安全区实现阶段，测量导航指示条避让区，并为底部按钮行、按键区、Tab 栏或贴底弹层确定底部间距及承载它的容器层时；为已有固定高度（含内容下方留白）的底部 Tab 栏或底部定位元素补导航条避让时；决定目标窗口是否全屏（沉浸式）、系统栏底色与是否做内容避让时

## 适用情境

目标页面在 setWindowLayoutFullScreen(true) 下用 getWindowAvoidArea 测避让值，写入页面或全局窗口模型；Android 源布局的底部按钮行、底部 sheet 没有导航栏间距（源窗口不延伸到导航栏下，BottomSheetDialog 由系统处理 inset）。或页面规格标注全屏页、需要沉浸式安全区，入口对 BOTTOM 边 expandSafeArea，根容器与底部内容层背景色不同。 也包括底部 Tab 栏原固定高度已在图标文字下方留有空白，避让值取自 TYPE_NAVIGATION_INDICATOR 的单一 px 快照、不区分三键与手势模式，用户只报告某一种导航模式被遮挡。也包括 Material3 BottomSheet 页面（库默认带 paddingBottomSystemWindowInsets）迁为 bindSheet，规格把“弹层跳过沉浸式处理”理解为自动避让。也包括规格要求手势与三键两种导航模式下内容都不被导航栏遮挡，而入口按沉浸式模板只以 TYPE_NAVIGATION_INDICATOR 测底部。 也包括源主题非全屏（Theme.Holo/Theme.Black 等，targetSdk 低，主题与代码都没有全屏或透明系统栏标志；requestWindowFeature(FEATURE_NO_TITLE) 只去标题栏），规格模板或页面元数据却按页面类型默认标注全屏页、需要沉浸式安全区。

## 例外与边界

- 源窗口不延伸到系统栏下（主题与代码都没有 windowFullscreen、windowTranslucentStatus/Navigation、透明 statusBarColor、FLAG_FULLSCREEN、SYSTEM_UI_FLAG_LAYOUT_*、setDecorFitsSystemWindows(false)/enableEdgeToEdge，targetSdk<35）：目标保持非全屏，按做法第 1 步处理，其余各步不适用

## 原因

TYPE_NAVIGATION_INDICATOR 的避让区在窗口底部，值在 bottomRect；复制 TYPE_SYSTEM 那一行只改常量会读成 topRect（恒为 0），这种写法一旦被收敛进全局窗口模型，所有页面的底部避让都变成 0。三键导航栏的避让区则在 TYPE_SYSTEM 的底部，只用 TYPE_NAVIGATION_INDICATOR 测底部时，三键模式下底部避让可能为 0，内容压在导航栏下。另一方面，源 XML 没有底部间距是因为源窗口不延伸到导航栏，目标全屏窗口会延伸，照 XML 写就贴屏底；bindSheet 内容贴屏底布局，也不会自动避让。来源中页面写者以“视频铺满、源端也没有底部避让”为由不消费底部值，sheet 写者照抄了 XML 的 paddingBottom。又一应用中两类偏差：计算器页规格已写明全屏与四层安全区方案，生成者只写 padding({ bottom: 8 })，底部按键落入指示条区域；补修账本页时把底部避让 padding 加在蓝色根容器上，而屏幕底边原本由浅灰内容层占据，避让区显示成一块蓝色——padding 区域显示的是承载它的容器的背景。另一应用中原 Tab 栏 barHeight(50 + 10) 已在内容下方留有约 10–16vp 空白，生成者把全额避让再加到 60vp 之上，并假设手势模式的避让值很小而未核实；真机上两种模式都报 84px（28vp），手势模式下留白翻倍，同批还给用户未提出的引导圆点追加了避让。最终由用户改为以避让值替代原 10vp 留白（手势模式仍余约 15vp）。反过来，源窗口本就非全屏时套用全屏模板，标题栏或内容会压进状态栏，各页再用避让去补偿，几何与底色都偏离源端；FEATURE_NO_TITLE 只去标题栏，不等于全屏。另一应用的页面类型模板把所有 Activity 默认标为需要沉浸式，经验摘要又被转述成“7 页全部全屏 + 底部避让”，Theme.Holo 源的各页随之被迁成全屏窗口并逐页补避让。

## 做法

1. 先判定源窗口是否延伸到系统栏下：查主题链的 windowFullscreen、windowTranslucentStatus/Navigation、statusBarColor 是否透明，代码中的 FLAG_FULLSCREEN、SYSTEM_UI_FLAG_LAYOUT_*、setDecorFitsSystemWindows(false)/enableEdgeToEdge，以及 targetSdk≥35 的强制 edge-to-edge。全都没有时目标保持非全屏：在 loadContent 回调里 setWindowLayoutFullScreen(false)，按源设置系统栏底色与图标色，用 setWindowSystemBarEnable(['status','navigation']) 保证横屏也显示系统栏，不建避让窗口模型、各页不加避让 padding；只有确需全屏时才执行以下各步。
2. 按避让区方位取矩形：顶部取 TYPE_SYSTEM 的 topRect.height；底部取 TYPE_SYSTEM 与 TYPE_NAVIGATION_INDICATOR 两者 bottomRect.height 的较大值（三键导航栏在 TYPE_SYSTEM 底部，手势条属 TYPE_NAVIGATION_INDICATOR），并订阅 avoidAreaChange 在导航方式切换时重算；复制测量代码时同时核对矩形字段。
3. 把页面测量收敛成共享窗口模型前，对照沉浸式参考或工程内已正确的实现逐字段核语义，不直接照搬现有页面片段。
4. 全屏页（按第 1 步判定确需全屏）的底部 CTA、按键区、贴底浮层与 bindSheet 内容都叠加底部避让值（子组件由宿主经 @Param 注入）；源窗口全屏时不因源 XML 没有底部间距就判定无需避让，源窗口非全屏时源 XML 没有底部间距正是保持非全屏的信号。页面规格标注全屏或沉浸式安全区时，生成页面即消费已发布的底部避让值，不用固定小 padding 代替。
5. 放置底部避让 padding 前先确认屏幕底边由哪一层背景占据，把 padding 加在那一层（如浅色内容层），根容器只承担顶部状态栏区；Tab 栏保持内容高度，让其背景延伸覆盖避让区。
6. 原 Tab 栏或底部栏的固定高度已包含内容下方留白时，让避让值替代或抵扣这段留白，不在总高度上整额叠加；三键与手势等导航模式以实测的各模式避让值为准，用户声明正常的模式把“布局不变”列为验收。同一避让值在不同模式下视觉占用不同时，以 TYPE_SYSTEM 底部高度是否大于 0 区分三键与手势导航，或请用户取舍，并在交付说明中标明未验证的模式。
7. 已有固定底部偏移的元素（如 position bottom: 50 的指示器）先比较该偏移与实测避让高度，已足以避开时不追加，也不把用户未提出的组件并入同一改动。

## 可选检查

- 在带导航指示条的设备上确认 bottomPadding 非 0、底部按钮与屏底之间留出指示条高度。
- 调整底部 Tab 高度后，分别在三键与手势导航模式下截图，核对文字到屏底或指示条的间距符合预期。
- 源端非全屏时对照两端截图：状态栏与导航栏区域为源端底色，内容起点在状态栏下沿、终点在导航栏上沿。
