# 系统栏图标深浅按源端浅色系统栏标志的最终值推导：未设时安卓图标为白色，不照搬模板默认，也不按主题名或底色对比度自选

ID：`lesson-824031d5fddf81036b54` · 版本：4

[本主题](index.md)

## 何时使用

沉浸式窗口配置阶段，调用 setWindowSystemBarProperties 设置 statusBarContentColor/navigationBarContentColor 或修改系统栏底色时；规格提取阶段整理主题与状态栏外观时

## 适用情境

Android 源端以主题（沿 parent 链，含 AppCompat/MDC 库主题与各 values-vNN、values-night 覆盖）或代码决定状态栏图标深浅：windowLightStatusBar=true、SYSTEM_UI_FLAG_LIGHT_STATUS_BAR、setSystemBarsAppearance(APPEARANCE_LIGHT_STATUS_BARS)、WindowInsetsControllerCompat.isAppearanceLightStatusBars=true、androidx 的 enableEdgeToEdge()（默认 SystemBarStyle.auto，非夜间配置下给深色图标）、基类沉浸式封装的 darkMode(true) 等表示深色图标；全都没有时为白色图标，即使主题是 Theme.AppCompat.Light 一类、状态栏底色偏浅。目标全屏窗口用 setWindowSystemBarProperties 设置系统栏，沉浸式 skill 示意写“透明背景 + 浅色文字”，规格可能只要求底色 parity。

## 原因

内容色决定时间、电量等系统图标的深浅。照模板写白色，源端为深色图标的浅色页面顶部会看不见图标；按“Light 主题”或“浅底配深色”的对比度自选，又会把源端的白色图标改成深色。主题名里的 Light 只决定窗口与控件配色，不会让状态栏图标变深；属性出现也不代表最终值为 true，导航栏图标由另一组标志决定。

## 做法

1. 设置内容色前解析源端最终生效的布尔值：沿主题 parent 链（含库主题：android-36.1 themes_material.xml 中框架 Theme.Material.Light 只有 LightStatusBar 变体设 windowLightStatusBar=true，appcompat 1.7.1 与 material 1.12.0 的库主题都不设）、各 values-vNN 与 values-night 覆盖，以及代码中的运行时设置（enableEdgeToEdge 见 androidx.activity 1.13.0 EdgeToEdge.kt：按 uiMode 非夜间设 isAppearanceLightStatusBars=true）；结果为 true 用深色图标，否则用白色图标（例：statusBarContentColor 分别写 '#FF000000' 与 '#FFFFFFFF'）。
2. 导航栏图标另按 windowLightNavigationBar、SYSTEM_UI_FLAG_LIGHT_NAVIGATION_BAR、APPEARANCE_LIGHT_NAVIGATION_BARS（isAppearanceLightNavigationBars）推导（android-36.1 attrs.xml、View.java、WindowInsetsController.java 中与状态栏标志分别定义），不从状态栏标志类推。
3. 源端未设任何浅色状态栏标志时结论就是白色图标，不再按底色对比度另选。修改系统栏底色时按源主题同步复核内容色，不沿用按旧底色写的注释。
4. 规格在主题与样式链中写明状态栏图标明暗（浅色标志是否存在、最终值及结论：白或深），状态栏外观验收同时列出底色与图标色。
