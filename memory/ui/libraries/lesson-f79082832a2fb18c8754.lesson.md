# UI 由三方库渲染、仓库只有调用面时，先取库工件（AAR 或版本 tag 源码）核对几何与行为再定映射；取不到登记阻塞，不按库名自研近似

ID：`lesson-f79082832a2fb18c8754` · 版本：1

[本主题](index.md)

## 何时使用

规格提取阶段，为 build.gradle 依赖的三方 UI 库（引导页、日期/时间选择器、取色器、图片查看器、提示条、FAB 菜单、清单编辑器、自定义 TextView 子类、对话框库）写转换决策与跨栈映射行时；实现阶段按“自研 / 原生组件替代 / Toast”一类映射行实现该库承载的组件，或准备以“库源不可见”登记占位时

## 适用情境

Activity 继承库基类（如 extends AppIntro2），布局或 UI 快照只剩库的自定义 View 类名（SublimePicker、holocolorpicker.ColorPicker、GalleryViewPager、FloatingActionsMenu、库 TextView 子类），或应用侧只保留库的 Style/Configuration 常量与配置调用（showCheckMarks、gatherLinksForText、Lib.makeText(...).show()）；几何、动画、手势、队列、截断与序列化算法都在库内，目标端没有同名库，规格准备写“自研 / 原生组件替代 / 默认样式即可对齐”并标 Auto 或 HARD；本机 Gradle 缓存可能尚无该 AAR。

## 例外与边界

- 当前任务或已批准决策明确只要求功能等价、接受与库行为不同：仍把与库行为的差异逐项写进决策，不标等价

## 原因

库渲染的界面真值在库制品里，仓库里的调用行、壳布局和样式常量只描述配置面。按库名或类名映射成原生组件、凭印象填尺寸与动画，会把整块几何、交互和算法换成近似：缩放与惯性手势、提示条的单队列串行、菜单展开动画与旋转角、清单的勾选移动与序列化规则、按空格回退的省略都会丢失。以“无源可查”登记的近似占位没有可对齐的真值，后续阶段无法收口。

## 做法

1. 从 build.gradle 读库坐标与版本，按序取工件：本机 ~/.gradle/caches/modules-2/files-2.1/<group>/<artifact>/<version>；没有就用 Gradle 解析该依赖下载，或按版本从 jitpack（https://jitpack.io/<group 路径>/<artifact>/<version>/）、上游仓库对应 tag 获取。
2. 解包 AAR：res/layout、values（dimens、styles、attrs 默认值）、drawable、anim/animator 给几何与时序；classes.jar 用 javap -c -p 或反编译读行为：手势、动画时长与插值器、队列与取消、文本拆分/截断/序列化算法、Builder 缺省值（如正文行距倍数）。
3. 列出库内参与该界面的全部视图类与公开行为（例：图片查看器里可缩放 ImageView 子类的双击、捏合、平移、惯性与回弹），逐项写进规格契约，每个值注明库内文件；应用侧常量类引用的库资源（入场/出场动画 xml）展开到时长与插值器，常量类本身不算完整样式锚点。
4. 据此再定目标映射：按库值复刻；改用原生组件或简化时，把与库行为的差异写成决策差异项或待用户裁定的决策，不标 Auto/HARD 等价，不写“默认样式即可对齐”。
5. 源端调用形如 Lib.makeText(...).show() 并传容器句柄、库内部由单例管理器串行排队时，目标按库语义实现全局队列加宿主组件（含 cancelAll 与“前一条退出后再显示下一条”），不做成页面自持的单条可见性组件。
6. 工件确实取不到时，在规格登记“缺库真值”阻塞，列出未核项（几何、手势、算法、序列化），并在交付报告标明；实现阶段收到这类阻塞不以“视觉对齐”作占位的解决方式，也不凭记忆或 README 描述自写近似。
