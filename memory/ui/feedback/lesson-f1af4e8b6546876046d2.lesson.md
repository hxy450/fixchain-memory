# 源端登录拦截在登录成功后续做原操作、目标登录守卫没有成功回调时，暂存待执行动作并在返回可见时消费

ID：`lesson-f1af4e8b6546876046d2` · 版本：3

[本主题](index.md)

## 何时使用

界面接线阶段，把源端“需登录才能继续”的操作（如点击付费项、添加自选）迁到目标登录拦截，决定登录成功后是否续做原操作时

## 适用情境

源端拦截带结果回调：未登录时拉起登录（如 userService.login(...).observe），登录成功后继续原操作（如 result.on(true) 应用所点选项），失败或取消才中止；目标工程现成的登录守卫只负责跳转并返回 false，没有成功回调。

## 例外与边界

- 源端拉起登录后直接中止、登录成功后不续做原操作时，按中止实现

## 原因

目标守卫只返回 false 时，照它写就只剩“跳登录并中止”，源端成功分支里的原操作被丢掉，用户登录回来还要重新操作；注释写“对齐源端回调”也看不出少了一支。

## 做法

1. 把源端拦截回调拆成“未登录拉起登录 → 登录成功后续做原操作 → 失败或取消才中止”逐项对照；源端成功分支会执行原操作时，目标不能只返回 false。
2. 目标守卫没有成功回调时，在拦截处暂存待执行动作（类型与参数），在页面重新可见（如 NavDestination.onShown）或登录态变更通知时一次性消费：已登录则刷新权限后执行，仍未登录则丢弃；先检索工程已有的登录回流实现并复用。
3. 注释或完成报告写“对齐源端”前，核对是否覆盖源端回调的全部分支；有意简化时说明省略了哪一步。
