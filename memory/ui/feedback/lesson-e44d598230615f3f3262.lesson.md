# 系统写入降级为“保存 + 引导手动设置”后，每个入口的成功反馈按降级语义实现，不沿用源端“设置成功”

ID：`lesson-e44d598230615f3f3262` · 版本：1

[本主题](index.md)

## 何时使用

功能接线阶段，把源端设置壁纸、设置铃声一类系统写入的结果回执接到目标端降级后的保存链、决定成功反馈时

## 适用情境

源端直接调用系统写入 API，并以 Toast 回执“设置成功/失败”；目标没有对应写入能力，已批准改为保存到相册或文件后引导用户手动设置；同一保存服务被多个入口复用，成功时发全局事件供入口展示引导。

## 原因

源端的成功文案在目标端已不属实；入口若照搬 Toast 而不订阅成功事件，用户保存成功却不知道下一步去哪里设置。占位登记里同时列出“引导”和“源端 Toast”时，最容易只实现后者。

## 做法

1. 每个调用入口都按降级决策的产出语义实现成功反馈：展示去相册或系统设置的引导，不用“设置成功”。
2. 解除占位前核对：成功路径出现了引导，没有与决策冲突的成功文案；服务返回“已引导”一类标志时，调用方确实展示了引导。
3. 成功事件是全局广播时，订阅方加“由本入口发起”的门槛，避免别处的保存在这里误弹引导。
4. 需要用户阅读的引导用常驻浮层（点击关闭），并核对实际停留时长，不用约 1 秒自动消失的提示。
