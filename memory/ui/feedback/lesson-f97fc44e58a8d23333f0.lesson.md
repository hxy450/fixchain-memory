# 源端以 toast 提示的校验失败，目标用全局提示；页内错误文字放在固定可见行，不追加到可变高度区末尾

[本主题](index.md)

## 何时使用

界面实现阶段，为弹层表单的确定按钮实现必填校验失败反馈时

## 适用情境

Android 弹窗确认时依次校验必填项并以 toast 提示；目标用“遮罩 + layoutWeight 中间区 + 固定高度键盘”的弹层承载，校验失败只写一个页内错误文字状态。

## 原因

中间区被分类网格等内容占满时，追加在末尾的错误行会落到键盘之下不可见，用户看到的是点击确定没有任何反应。来源中规格已要求错误文案可见，实现只写条件错误行、没有 toast，也未编译截图；用户两次报告“点击确认没反应”后才补上 showToast。

## 做法

1. 源端用 toast 一类全局瞬时提示时，目标同样用全局提示（promptAction 或 UIContext 的 showToast）；另加页内文字时放在操作栏下方或键盘上方的固定行。
2. 固定高度键盘与 layoutWeight 中间区组合时，按最多内容估算中间区高度；新增条件行前确认仍有空间，否则改为可滚动区或固定位置。

## 可选检查

- 规格写有“错误文案可见”的界面判定时，至少触发一次最常见的失败路径并截图确认提示出现。
