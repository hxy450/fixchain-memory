# 服务端下发的广播或飘屏消息由单例浮窗逐条播放时，按源端队列语义迁移：不自加去重、上限或点击清空

ID：`lesson-2cc8bcca579d597cb6a2` · 版本：3

[本主题](index.md)

## 何时使用

界面与服务实现阶段，把单例浮窗逐条播放的广播、飘屏消息迁成浮层服务，确定入队、去重、上限与点击后的队列处理时；审计或规格阶段为这类浮层写最小实现链时

## 适用情境

源端由单例窗口持有列表，逐个播放网络响应附带的广播或飘屏消息：addAll 入队、remove(0) 出队、动画结束回调里有剩余就继续，点击只跳详情、不动队列；上游审计或规格出现源码没有的“有界/去重队列”等防护性描述。

## 原因

去重会吞掉重复下发的消息，条数上限会截断大批次，点击清空会丢掉剩余消息，三者都改变用户可见的播放序列；审计或规格里没有源码出处的防护性描述，照写就把这些改变带进实现。

## 做法

1. 逐项对照源端入队、出队、点击与跨页清理分支：全部入队顺序播放，点击打开详情后保留剩余队列，解析不截断；源码没有的去重、上限、点击清空不作为默认防护加入，审计或规格写了而源码没有时以源码为准。
2. 确需目标侧资源保护时，单独标为适配策略并写明对可见结果的影响（是否会丢广播），交负责方确认后再实现。
3. 写审计或规格的“最小链”建议时，把源端已核行为与目标适配建议分开；去重、上限一类属性附源码出处，否则不写入契约。
