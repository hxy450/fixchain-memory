# ui/feedback

操作结果反馈：异步结果各分支的提示与去向，多来源页面按区块的失败隔离与缓存降级，Snackbar 一类提示的宿主与渲染，校验失败提示的承载与可见性，多入口 loading 的起链与收口，降级方案的成功引导，按失败类型分派的反馈（权限拒绝的去设置引导），只经通知或 Toast 交给用户的接口返回数据的替代去向

## 本级经验

- [同一业务链有多个入口时，每个入口都要真正调用服务并在所有终态收口 loading](lesson-a87eaa08f98ea95d04d5.lesson.md)
  - 时机：界面接线阶段，为同一业务链实现“弹窗确认”与“无弹窗直调”等多个入口，并编写忙态（loading）的起链与收口时
  - 情境：源端工具方法显示 loading 后直接下载或设置，并在各终态关闭；目标把链路拆成弹窗组件加静态入口方法，服务调用需要 UI context，而 context 只在组件按钮回调里拿得到。
- [按数据来源分区块管理页面状态：单个来源失败只影响自己的区块，缓存与静态默认内容保留，整页错误只留给不可恢复的前置条件](lesson-a82d821385bf8fb3feb0.lesson.md)
  - 时机：界面转换与数据接线阶段，为由多个数据来源（多个接口、首页缓存、本地登录态、XML 静态默认内容、可选附属请求）组成的页面设计加载、失败与降级状态时
  - 情境：源页面的多个请求各自 launch/observe、只在成功时更新自己的数据；或先用缓存填充再请求详情；或首屏含 XML 静态默认文案与本地状态；目标准备用一个结果对象或快照、CONTENT/ERROR 两态驱动整页。
  - 例外：缺少城市、参数等所有区块都依赖的前置条件，此时整页错误态是合理的
- [源端以 toast 提示的校验失败，目标用全局提示；页内错误文字放在固定可见行，不追加到可变高度区末尾](lesson-f97fc44e58a8d23333f0.lesson.md)
  - 时机：界面实现阶段，为弹层表单的确定按钮实现必填校验失败反馈时
  - 情境：Android 弹窗确认时依次校验必填项并以 toast 提示；目标用“遮罩 + layoutWeight 中间区 + 固定高度键盘”的弹层承载，校验失败只写一个页内错误文字状态。
- [源端单一 SnackbarHost 的结果反馈用一份反馈状态驱动唯一浮层；每个结果态都要有渲染分支，catch 写入的状态要有消费方](lesson-187c725b1bb9d8d1bf4d.lesson.md)
  - 时机：页面转换与功能接线阶段，把源端 Snackbar 结果反馈和规格里的操作状态落成 ArkUI 提示，并给成功与失败分支接通界面时
  - 情境：源端页面只有一个 SnackbarHost，按顺序显示操作结果；目标规格给出含 error 的操作状态，并要求失败时报错且不留成功状态；目标页用条件渲染的底部浮层实现提示。
- [源端只经通知、Toast 等平台通道交给用户的接口返回数据，推迟该能力时要为数据定义替代去向](lesson-9d54e42c44b0d3e78bb1.lesson.md)
  - 时机：规格与计划阶段决定推迟或替换通知等平台能力时；实现阶段调用返回非 void 的接口、准备丢弃返回值时
  - 情境：源端接口返回用户必需的数据（如测试环境下发的短信验证码），客户端只经本地通知或 Toast 展示；目标本轮不迁移通知能力，规格只保留接口签名与“请求成功”的验收条目。
- [系统写入降级为“保存 + 引导手动设置”后，每个入口的成功反馈按降级语义实现，不沿用源端“设置成功”](lesson-e44d598230615f3f3262.lesson.md)
  - 时机：功能接线阶段，把源端设置壁纸、设置铃声一类系统写入的结果回执接到目标端降级后的保存链、决定成功反馈时
  - 情境：源端直接调用系统写入 API，并以 Toast 回执“设置成功/失败”；目标没有对应写入能力，已批准改为保存到相册或文件后引导用户手动设置；同一保存服务被多个入口复用，成功时发全局事件供入口展示引导。
- [迁移源端异步结果回调时，按成功、失败分支（含失败类型）列出全部副作用（跳转与关页、提示、引导弹窗、标记写入），计划与代码逐项对上](lesson-ac7a2e17b8d88c3cee7b.lesson.md)
  - 时机：界面、流程实现与页面接线阶段，把源页面对异步操作结果的观察（LiveData observe 等）改成目标页面的 await 结果、try/catch 或路由枚举，并决定各分支的跳转、反馈与状态写入时；把源端控制器的多段启动流程（登录 → 权限 → 启动）接到宿主页时；修补某个结果分支的文案或常量时
  - 情境：源 Activity/Fragment 在结果观察回调里按成功/失败分支同时做几件事（写本地标记、跳页并 finish、showToast、更新计数）；目标 ViewModel 方法只更新状态，或把失败折叠成返回值，由页面决定导航和提示；页面里可能留有“登录成功跳 X”的注释或 TODO。也包括源端按失败类型给不同反馈（权限被拒弹“去设置”引导框，启动失败才 toast），目标 ViewModel 方法只返回 boolean、失败类型另存；接线任务的核查清单只列出部分弹窗调用（如 MessageDialog.show），用 AlertDialog.Builder 构造的弹窗不在清单里。也包括源端回调先按信封成功分流、成功分支内再按 data 是否含某键分流，错误码从 data 层读取并位于成功分支的 else 中，而目标把同名错误码判断放在成功分支之外。
