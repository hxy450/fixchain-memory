# 修补源端响应回调的某个分支前，先写出到达该分支的完整判别路径（信封成功、data 键、data 层错误码）再逐层对照

ID：`lesson-70a6729138334ac77ac1` · 版本：2

[本主题](index.md)

## 何时使用

修复或复核阶段，修补响应回调中某个分支的文案、常量或弹窗前；把多层判别的响应回调迁成目标分支时

## 适用情境

源端回调先按信封 isSuccess 分流，成功分支内再按 data 是否含某键分流，错误码与附带标志从 data 层读取、位于成功分支的 else 中；目标把同名错误码判断放在成功分支之外，由服务层解析函数产出 success/errorCode 字段。

## 原因

判别层级或判别键错位时，真实响应会落进别的分支（如本应弹上限提示的响应走了成功分支），只替换文案或常量修不好；只读过行号片段时，也容易把分支归错到成功或失败路径。

## 做法

1. 修补前写出源端到达该分支的完整判别路径（信封成功 → data 键是否存在 → data 层错误码）；读源码时窗口覆盖到所在方法或外层 if/else 的闭合处，只读过片段时不推断分支归属。
2. 同时打开目标服务层的解析函数，核对 success、errorCode 等字段的读取层级与缺省值，与源端逐层对照；层级或判别键不同就一并修正，不只替换字符串。
