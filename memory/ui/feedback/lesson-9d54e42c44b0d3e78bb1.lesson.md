# 源端只经通知、Toast 等平台通道交给用户的接口返回数据，推迟该能力时要为数据定义替代去向

ID：`lesson-9d54e42c44b0d3e78bb1` · 版本：1

[本主题](index.md)

## 何时使用

规格与计划阶段决定推迟或替换通知等平台能力时；实现阶段调用返回非 void 的接口、准备丢弃返回值时

## 适用情境

源端接口返回用户必需的数据（如测试环境下发的短信验证码），客户端只经本地通知或 Toast 展示；目标本轮不迁移通知能力，规格只保留接口签名与“请求成功”的验收条目。

## 原因

推迟平台能力时若只记“以后再做通知”，它承载的业务数据就没有去向；实现者调用接口后丢弃返回值，用户拿不到数据，流程无法继续。来源中规格与计划把通知整体推迟，只要求“用户可见反馈”，登录与注册页 await 发送接口后丢弃返回的验证码，用户无法登录，直到补成回填输入框。

## 做法

1. 规格与计划阶段逐个检查源端对接口返回值的消费（onData、回调）；数据只经通知、Toast 交给用户时，在验收条目写明该数据如何呈现（Toast 显示、回填输入框等），推迟平台能力时同时写明替代承接方式。
2. 实现时接口返回非 void 就确认返回值有去向；准备丢弃前回查源端回调的用途。
