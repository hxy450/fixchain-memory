# 源端 Toast 调用混用 LENGTH_SHORT 与 LENGTH_LONG 时，公共 Toast 封装把时长做成每次调用的参数并逐调用点映射

ID：`lesson-8335bc404934f58c6f31` · 版本：2

[本主题](index.md)

## 何时使用

服务层与页面实现阶段，把源端 Toast.makeText 调用翻译成目标 Toast 封装或 promptAction.showToast、确定每处显示时长时

## 适用情境

Android 源码在同一文件或同一公共方法中混用 Toast.LENGTH_SHORT 与 LENGTH_LONG；目标用毫秒 duration 的 showToast 或自建公共 Toast 桥，封装准备只收 message 或只定义一个时长常量。

## 原因

按多数调用把时长硬编码进封装，少数 SHORT 调用就全部变长；封装签名丢掉时长参数后，调用点即使按源码映射也传不进去。

## 做法

1. 公共 Toast 封装把时长作为每次调用的参数，逐个调用点按源码 LENGTH_* 映射：SHORT 2000ms、LONG 3500ms（AOSP NotificationManagerService 中 SHORT_DELAY/LONG_DELAY 的定义；本机 SDK sources 不含该系统服务，需要核对时查参照设备 Android 版本的 AOSP frameworks/base/services/core/java/com/android/server/notification/NotificationManagerService.java），两者都在 showToast 允许的 1500–10000ms 内（@ohos.promptAction.d.ts）。
2. 写页面或服务前在源文件检索 Toast.LENGTH_SHORT 与 LENGTH_LONG；源文件两种都有、输出只定义了一种时长时，回到每个调用点补齐。
