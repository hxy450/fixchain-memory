# 公共 Toast 封装把时长做成每次调用的参数，逐调用点映射源端 LENGTH_SHORT/LONG，位置按源端默认显式传 bottom；源端对文案的字符串加工在取得字符串后保留

ID：`lesson-8335bc404934f58c6f31` · 版本：3

[本主题](index.md)

## 何时使用

服务层与页面实现阶段，把源端 Toast.makeText 调用翻译成目标 Toast 封装或 showToast，确定每处时长、显示位置与文案拼接时

## 适用情境

Android 源码在同一文件或同一公共方法中混用 Toast.LENGTH_SHORT 与 LENGTH_LONG，部分文案先取资源串再做 toLowerCase 等加工；目标用毫秒 duration 的 promptAction.showToast 或自建公共 Toast 桥，资源经 getStringSync 等取成 string 后再拼接。 也包括源端文字 Toast 未调用 setGravity/setMargin、位置取平台默认，目标封装或直接调用的 showToast 不传 bottom。

## 原因

按多数调用把时长硬编码进封装，少数 SHORT 调用就全部变长；以“Resource 不能 toLowerCase”为由删掉加工，忽略了已经解析出的 string 可以照常加工。来源中引擎实现者与页面转换者都读到了逐处的 LENGTH_*，前者把封装写成只收 message、固定 3500ms，后者只定义了 LONG 常量；删除 toLowerCase 的理由在同一段代码里并不成立。 位置同样不同：Android 文字 Toast 默认底部居中、纵向偏移取平台 toast_y_offset（本机 SDK platforms/android-<api>/data/res/values/dimens.xml，android-34 为 48dp；重力 config_toastDefaultGravity），showToast 不传 bottom 时用系统默认 80vp，吐司偏高。

## 做法

1. 公共 Toast 封装把时长作为每次调用的参数（SHORT 2000ms、LONG 3500ms），逐个调用点按源码 LENGTH_* 映射；写页面或服务前在源文件 grep 两种时长，输出只定义了一种时回到每个调用点补齐。
2. 位置与时长一样显式映射：源端未调 setGravity/setMargin 时，按平台默认重力与 toast_y_offset 换算成 showToast 的 bottom（相对导航区，有参照截图时以实测为准），写成封装常量；直接调用 showToast 的地方传同一常量或改走封装；源端调了 setGravity/setMargin 的按源值。
3. 以平台限制为由删除源码的字符串加工前，先查实际采用的 API 返回类型；getStringSync 等取得 string 后保留源码加工。
