# 源端单一 SnackbarHost 的结果反馈用一份反馈状态驱动唯一浮层；每个结果态都要有渲染分支，catch 写入的状态要有消费方

ID：`lesson-187c725b1bb9d8d1bf4d` · 版本：1

[本主题](index.md)

## 何时使用

页面转换与功能接线阶段，把源端 Snackbar 结果反馈和规格里的操作状态落成 ArkUI 提示，并给成功与失败分支接通界面时

## 适用情境

源端页面只有一个 SnackbarHost，按顺序显示操作结果；目标规格给出含 error 的操作状态，并要求失败时报错且不留成功状态；目标页用条件渲染的底部浮层实现提示。

## 原因

拆成多个互不排斥的浮层会叠在一起；定义了 error 枚举却没有渲染分支，失败就没有任何提示；catch 只写状态不渲染，验收条目写了也等于没做。来源中转换者把唯一宿主拆成两个浮层，失败界面留给后续却没登记“要渲染失败提示”；接线者读到了“失败要报错”的验收条目，两个 catch 都只写状态，备份失败还写进了恢复状态。

## 做法

1. 用一份反馈状态（种类、计数、定时器句柄）驱动唯一的底部浮层，新提示替换旧提示；连续触发成功与失败，确认任何时刻最多一条提示。
2. 提示时长按源端调用换算：没有 actionLabel 的短提示自动消失，带 actionLabel 的按 Material3 默认常驻到点动作或离页；与评审口径不同时在迁移报告登记差异。
3. 状态接口列出的每个结果态都在 build 里找到渲染分支；确要留给接线阶段，在占位登记里写明“某态需渲染什么”，不只登记状态回填。每个 catch 写入的状态都要有消费它的分支，不同操作不借用同一个状态。
