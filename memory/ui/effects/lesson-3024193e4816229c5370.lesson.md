# Compose 叠在已画内容上的 blendMode 着色：参与混合的底色、字形和渐变放进同一离屏组，或把源算式预混进色标

ID：`lesson-3024193e4816229c5370` · 版本：1

[本主题](index.md)

## 何时使用

规格提取与界面实现阶段，把 drawWithContent { drawContent(); drawRect(brush, blendMode) } 这类图标渐变着色映射成 ArkUI 结构，或在修复阶段改写其混合方式时

## 适用情境

源组件先画图标内容，再用渐变矩形以 Plus、Darken 等混合模式叠加着色，可能按深浅主题切换模式；结果依赖画布上已画好的底色（底盘、按钮背景）与字形像素。目标端渐变层、图标、底盘是 Stack 里的兄弟节点，ArkUI 提供 blendMode 与 BlendApplyType。

## 例外与边界

- 源端混合只依赖自身 alpha（SRC_IN、DST_IN 一类）时，不需要纳入底色，也不需要预混

## 原因

Compose 的 drawRect(blendMode) 与同一画布上已画的全部内容混合：白底加 Plus 饱和为白，只有深色字形被染成渐变色。ArkUI 节点的混合目标只包含所在离屏层里已画的内容：给独立兄弟节点设 .blendMode(PLUS, OFFSCREEN)，混合目标是它自己的透明离屏层，结果是一块半透明色块盖住底盘。只用 SRC_IN 取字形形状又丢掉了 Plus 的加数（字形底色），遮罩色带 alpha 时渐变还会再与底色混一次；用 fillColor 取渐变首色则整块变成饱和单色。来源只截图核验了浅色分支；预混修复后一页达标，另一页仍有轻微通道偏差，成因未查明。

## 做法

1. 先在 SDK common.d.ts 查到对应的 BlendMode、BlendApplyType 枚举并读其语义说明；确认存在后不以“复杂”为由降级成单色。
2. 直接复刻源公式：用 .blendMode(SRC_OVER, OFFSCREEN) 的容器包住底色层、按原内容色绘制的图标和同尺寸渐变层，渐变层设 .blendMode(对应模式, FAST)，容器按源形状裁剪；深浅主题切换时同步切换模式。
3. 离屏组里没有底色、改用 SRC_IN 取形时，把源的逐通道算式折进色标：Plus = min(255, 字形 + stop)，Darken = min(字形, stop)；字形底色取内容色合成到背景上的结果，遮罩 fillColor 设为不透明。浅色、深色分支各核一遍（来源条件下 Darken 与 SRC_IN 取形结果相同，Plus 不同）。
4. 源码里有原作者的实现提示（如“应改用图层 + srcIn”）时，映射决策引用它并写明采纳与否的理由。

## 可选检查

- 有截图时对一枚着色图标核对：字形以外的像素应与底盘一致，不得出现盖住底盘的半透明色块；字形中心像素与按源算式核算的目标色在容差内。
