# linearGradient 遮罩条模拟边缘淡出：angle 按 CSS 语义或用 direction，终点取同色 alpha 0，不用透明黑

ID：`lesson-956f14dab0397768dc95` · 版本：1

[本主题](index.md)

## 何时使用

界面实现与共享组件实现阶段，用 ArkUI linearGradient 写滚动边缘渐隐遮罩条（模拟 fadingEdges、FadeClip），确定渐变方向、终点色以及遮罩层尺寸与命中时

## 适用情境

源端用 fadingEdges 一类修饰让横滑行或纵向滚动区的内容在边缘淡出、不着色；目标改用叠在内容上、从容器底色渐变到透明的 linearGradient 遮罩条，按左右或上下边分别放置，底色常是运行期解析出的 '#AARRGGBB' 主题色；生成期不能上机看效果。

## 原因

ArkUI linearGradient 的 angle 与 CSS 同义：0 指向上方（colors[0] 在底边）、90 左→右、180 上→下（缺省）、270 右→左；按数学坐标或 Android GradientDrawable 的习惯把 0 当成向右，横向与纵向会整体互换。'transparent' 与 Color.Transparent 是透明黑，渐变不按预乘插值，从底色到透明黑的中段会出现半透明灰带。方向与灰带的结论依据两端截图对照；本机 SDK 的 .d.ts 对 angle 只写缺省值 180，不足以单独判断方向。

## 做法

1. 轴向渐变优先用 direction: GradientDirection.Right/Left/Bottom/Top；写 angle 时按 0 向上、90 左→右、180 上→下、270 右→左，不凭记忆换算。
2. 终点色取起点同 RGB、alpha 0（'#AARRGGBB' → '#00RRGGBB'），不写 'transparent' 或 Color.Transparent；起点色是 Resource 或主题令牌时先解析成具体色值再派生透明版，主题切换时一起重算。
3. 遮罩层的尺寸、定位与命中按内容落实：包装组件尺寸等于内容尺寸，遮罩层按实测内容宽高定数值尺寸（不写 '100%'），层内用 Row/Column 加 Blank 或 position 把首尾两条分开（不靠子项 .align），每个实际有尺寸的绘制节点都设 HitTestMode.None；见 lesson-a58ebfe7a4c55b041b14 第 5 步与 lesson-4a4f8d845a204ffa244b 第 1 步。

## 可选检查

- 不能上机时，逐条列出每个遮罩条所在的边、angle/direction、colors[0] 落在哪条边、终点是否同色透明；同一文件里横向与纵向遮罩分别核对。
