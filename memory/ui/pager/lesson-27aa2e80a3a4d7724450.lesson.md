# 自绘 tab 行加分页容器要分别接通“页→tab”和“tab→页”两个方向

ID：`lesson-27aa2e80a3a4d7724450` · 版本：1

[本主题](index.md)

## 何时使用

界面实现阶段，把自定义 tab 行与 ViewPager2 转写成自绘 Row/@Builder tab 加受控 Swiper 并接线联动时

## 适用情境

源端用普通 TextView 充当 tab，点击切页写在 Fragment 代码里（可能在数据加载函数末尾），布局 XML 与 onPageSelected 只体现选中样式和滑动高亮；目标不用原生 Tabs。

## 原因

Swiper.index(state) + onChange 只完成“滑动 → 高亮”；“点击 tab → 切页”要在 tab 项上 onClick 写回受控 index。点击监听不在布局和页面回调里时，最容易被当成“index 绑定已覆盖”。来源中写者读到了点击监听，报告仍写“tab 切换已实现”；验证阶段发现后又随同页布局差异归为不阻塞，没有派修。

## 做法

1. 把联动拆成两个方向分别落实：页→tab（onChange 更新选中态）与 tab→页（tab 项 onClick 写回受控 index）。
2. 写页面前在源 Activity/Fragment 全文检索 setOnClickListener、currentItem/setCurrentItem（含 initView 以外的函数），逐条映射到目标 onClick；交付报告按源行号列出已实现的交互。
3. 验证汇总时，“点击无效、只能滑动”一类交互缺失按功能缺陷派修，不随同页布局差异一起归为不阻塞。
