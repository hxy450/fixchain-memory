# 首屏输入框按源端获焦并自动弹键盘时，先核 windowSoftInputMode 与获焦条件，再在窗口获焦后 requestFocus

ID：`lesson-9d42548ee3c075de3330` · 版本：3

[本主题](index.md)

## 何时使用

界面实现阶段，为首屏含输入框的页面落实冷启动初始焦点与软键盘时；规格提取阶段写首屏焦点与是否自动弹键盘的验收时

## 适用情境

源端没有 requestFocus/showSoftInput，首屏焦点由平台缺省给布局顺序中第一个可获焦视图（AdapterView 只在有数据时可获焦），获焦条件随数据分支变化（如列表为空时）；目标为 NavDestination 页 + TextInput，ArkUI 不会自动给输入框焦点。

## 例外与边界

- Manifest 中该 Activity 的 windowSoftInputMode 为 stateHidden/stateAlwaysHidden：只给焦点、不拉键盘

## 原因

缺省获焦不等于自动弹键盘：stateUnspecified 下，只有前进导航进入窗口、获焦视图是文本框，且窗口可 resize（adjustResize）或运行在大屏时系统才自动弹键盘，按 adjustPan 解析的手机窗口不弹（android-36.1 SoftInputShowHideReason.SHOW_AUTO_EDITOR_FORWARD_NAV）。冷启动时窗口激活晚于首屏数据查询，提前 requestFocus 只把控件置为 focused，不绑定输入法。

## 做法

1. 先核 Manifest 中该 Activity 的 windowSoftInputMode：stateVisible/stateAlwaysVisible 弹键盘，stateHidden/stateAlwaysHidden 不弹（android-36.1 WindowManager.LayoutParams 的 SOFT_INPUT_STATE_* 说明）；未声明或 stateUnspecified 时按上述条件判断（窗口按 adjustResize 或大屏才弹）；再按布局顺序与数据分支写出谁获焦。
2. 需要获焦时，首屏数据查询完成后按源条件给 TextInput 设 id 并请求焦点；请求前用 window.findWindow(窗口名).isFocused() 确认窗口已获焦，未获焦就监听 windowEvent 的 WINDOW_ACTIVE 后再请求。只要焦点、不要键盘时给 TextInput 设 enableKeyboardOnFocus(false)。

## 可选检查

- 清数据冷启动与有数据冷启动各看一次焦点与键盘是否与源端一致。
