# 首屏输入框按源端平台缺省获焦时，在窗口获焦后再 requestFocus：冷启动窗口激活晚于首屏查询，提前请求不会拉起输入法

ID：`lesson-9d42548ee3c075de3330` · 版本：1

[本主题](index.md)

## 何时使用

界面实现阶段，为首屏含输入框的页面落实冷启动初始焦点与软键盘时

## 适用情境

源端靠平台缺省给第一个可获焦的 EditText 焦点并自动弹键盘（源码没有 requestFocus/showSoftInput），获焦条件随数据分支变化（如列表为空时）；目标为 NavDestination 页 + TextInput，ArkUI 不会自动给输入框焦点。

## 原因

冷启动时窗口激活晚于首屏数据查询，提前 requestFocus 只把控件置为 focused，不触发 onFocus 与输入法；照搬“查询完就请求焦点”得到的是有焦点却没有键盘的首屏。

## 做法

1. 首屏数据查询完成后按源条件给 TextInput 设 id 并请求焦点；请求前用 window.findWindow(窗口名).isFocused() 确认窗口已获焦，未获焦就监听 windowEvent 的 WINDOW_ACTIVE 后再请求。

## 可选检查

- 清数据冷启动与有数据冷启动各看一次焦点与键盘是否与源端一致。
