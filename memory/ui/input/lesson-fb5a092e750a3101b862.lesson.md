# 源 EditText 未设光标样式时，按所在 Activity 主题解析光标资源，解析不出再以同页真机取证为准，写入 caretStyle

ID：`lesson-fb5a092e750a3101b862` · 版本：3

[本主题](index.md)

## 何时使用

界面实现与还原修复阶段，为输入框光标这类源端未显式定制、取决于页面主题的外观确定 caretStyle 时

## 适用情境

源 EditText 及其 style 没有 textCursorDrawable，光标外观取决于所在 Activity 的主题（父链到框架主题 android:Theme.* 时由其 textCursorDrawable 及着色属性提供）；同一应用其他页面可能有不同的光标配置；目标为 TextInput 的 caretStyle({ width, color })。

## 例外与边界

- 源端显式设置了 textCursorDrawable，此时打开该 drawable 取宽度与颜色

## 原因

光标的默认外观由 Activity 主题的 textCursorDrawable 与着色属性决定，同一应用不同页面可能不同；用另一页面的输入框代取样再写成“安卓实测”，后续验证也只会和这个错误基准比较。按暗像素阈值扫描还会漏掉彩色光标。

## 做法

1. 先按该 Activity 的主题（Manifest 的 android:theme → styles 父链）解析：父链到框架主题时，到本机 SDK platforms/android-<api>/data/res 的 themes_*.xml 查 textCursorDrawable 并打开对应 drawable（例：android-36.1 的 Material 主题为 drawable/text_cursor_material.xml，可见宽为其 size 的 2dp，颜色为 ?attr/colorControlActivated 着色的解析值），由此得出宽度与颜色写入 caretStyle。
2. 父链落在 AppCompat/Material 等库主题、或资源解析不出确定值时，以用户指定页面（同一 Activity、同一主题）的真机取证为准；框架资源已得出值时，取证只作核对。该页暂时到不了时请用户把安卓端切到该页，或先写入按主题资源推导的值并在报告写明未经该页真机核对；不借其他页面代取样，确需借用时先核两个 Activity 的主题与控件着色相同，并写明基准来自哪个页面。
3. 像素取证光标时不预设颜色：先用闪烁 ON/OFF 两帧差分定位光标，再取色、量宽高。
4. 光标宽度与颜色用 caretStyle({ width, color }) 设置（当前 SDK 的 TextInput 没有 caretWidth）；写前在 text_input.d.ts、text_common.d.ts 核对属性名。
