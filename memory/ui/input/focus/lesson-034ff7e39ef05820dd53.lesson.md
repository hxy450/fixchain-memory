# 常驻 NavBar 页面的 TextInput.onFocus 不能 1:1 当作用户聚焦：先判别焦点来源再写业务状态

ID：`lesson-034ff7e39ef05820dd53` · 版本：1

[本主题](index.md)

## 何时使用

界面实现阶段，把 TextInput 的焦点回调接到页面业务状态、且页面处于 Navigation NavBar / 常驻 Stack 会被 pushPath 覆盖时

## 适用情境

页面用 focused 之类业务字段决定显示分支（Suggestions vs Categories）；从子页系统返回后 ArkUI 会把焦点交还该 TextInput。

## 原因

SearchBarComponent 的 onFocus 无条件上抛 true，把框架恢复的焦点写进刚重建的 SearchState，返回后显示 Suggestions 而非 Categories；既有 clearFocus 在 push 起点执行清不掉 NavBar 焦点记忆（修复者假设，未对照实验）。修复以 touch-down 先行判别 + enableKeyboardOnFocus(false) 通过真机与 round-2/3 复验。

## 做法

1. 先判别焦点来源：TextInput 加 onTouch(Down) 置标记与 enableKeyboardOnFocus(false)，无 touch-down 先行的 onFocus 视为框架恢复 → stopEditing + clearFocus 且不写业务 focused；否则照常。
2. 写前用一次 push→Back 往返的 dump 核对 TextInput.focused。

## 检查

- Back 后 Categories/未聚焦/空 query；用户点击输入框仍进 Suggestions 并拉起键盘；Tab 切走再回复位不受影响。
