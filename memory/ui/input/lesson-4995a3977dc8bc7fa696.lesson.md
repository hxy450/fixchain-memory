# 工具栏 SearchView（actionView）按控件状态机迁移：展开、焦点、提交、收起与菜单重建分开建模，不折成查询函数

ID：`lesson-4995a3977dc8bc7fa696` · 版本：1

[本主题](index.md)

## 何时使用

规格提取与工具栏接线阶段，把源端菜单项上的 SearchView actionView 迁成目标标题栏搜索框时

## 适用情境

源端在菜单 inflate 后为搜索项设置 SearchView：expandActionView/collapseActionView、OnActionExpandListener 的展开与收起回调（收起时清查询、重载列表、invalidateOptionsMenu）、焦点监听切换其他菜单项可见性、onQueryTextSubmit 的返回值决定是否由 SearchView 投递 ACTION_SEARCH，以及即时搜索偏好。目标规格写成应用内 ViewModel“内化等价”的几个查询函数，实现用一个布尔同时表示展开与焦点、用取消图标代替收起。

## 原因

SearchView 的行为由控件生命周期回调决定：展开与焦点是两个状态，收起会触发清空与重载，菜单重建也会收起它，提交返回值决定是否再走搜索意图。只留查询函数，这些回调就没有验收与落点，菜单项显隐、收起时机、空串处理与提交后收键盘都会偏离。

## 做法

1. 规格提取时读创建 SearchView 的方法全文，每个回调写成一条验收：展开（含程序化 expandActionView 与收键盘）、收起（清查询、恢复列表、重建菜单）、焦点变化对其他菜单项的显隐、onQueryTextSubmit 返回值决定是否投递 ACTION_SEARCH、即时搜索开关、空串是否提交、提交后是否收键盘。
2. 实现时把展开、焦点、提交、收起、菜单重建分成独立状态与事件，由一个控制器承接展开/收起（含不触发监听的收起）与 setText 去重；取消或返回按源端走 collapseActionView 的同一路径。
3. 服务层查询函数只承接查询本身；派工的完成门槛写成“控件回调全集有落点”，不以服务接口覆盖规格服务层为完成标准。
