# 被子页覆盖后返回的 TextInput 先识别焦点来源；仅触摸交互域可用 touch-down 守卫，不能误拦键盘主动走焦

ID：`lesson-4c476a62732697c56c22` · 版本：2

[本主题](index.md)

## 何时使用

界面实现阶段，把 TextInput 的焦点回调接到页面业务状态，且页面常驻 NavBar 或保活容器、会被 pushPath 覆盖时

## 适用情境

页面用 focused 之类的业务字段决定显示分支（如建议列表与分类）；从子页系统返回后，框架可能把焦点交还该 TextInput。

## 原因

onFocus 无条件上抛时，框架恢复的焦点会被当作用户聚焦写进刚复位的状态，返回后显示错误分支并拉起键盘。来源中原有在 push 起点 clearFocus 的写法没有压住这次恢复（修复者判断，未做对照实验）；按触摸来源判别的写法经真机返回往返与后续复验通过。

## 做法

1. 先核源是否支持键盘 Tab/方向键或程序主动获焦。仅在已确认只处理触摸交互时，才给 TextInput 加 onTouch(Down) 标记并设 enableKeyboardOnFocus(false)，将无 touch-down 的返回获焦按框架恢复处理；不能用此条件拦截源允许的主动走焦。需抑制非期望恢复时，执行 stopEditing 与 clearFocus、不写业务 focused；有 touch-down 的照常处理，复位状态时一并清标记。

## 可选检查

- 有设备时做一次 push → 返回往返：返回后显示初始分支、未聚焦；用户点击输入框仍进入聚焦分支并拉起键盘。
