# 向带 maxLength 或 InputFilter 的输入框程序写入（粘贴、扫描回填）时，先按源过滤器截断或转换再赋值

ID：`lesson-299950a4255a40c6baf5` · 版本：2

[本主题](index.md)

## 何时使用

界面实现阶段，实现粘贴按钮、扫描回填、恢复草稿等向输入框程序写入文本的逻辑时

## 适用情境

源端用 EditText.setText 向带 android:maxLength、InputFilter（AllCaps、自定义过滤）的输入框写入文本；目标把状态变量直接赋给 TextInput 的 text，再拿该值去比较或保存。

## 例外与边界

- 源端写入的控件不挂过滤器，或源端已在写入前自行截断、转换：照源端逻辑

## 原因

Android TextView.setText 会按控件 mFilters 数组的顺序逐个过滤（TextView.java）：maxLength 对应的 LengthFilter 按 UTF-16 码元截断，且不把代理对拆开（InputFilter.java），AllCaps 转大写。ArkUI 的 maxLength 与 inputFilter 约束的是输入，程序赋给 text 的值不保证经过它们，后续比较、保存拿到的就是未截断的原文。

## 做法

1. 程序写入前按源控件过滤器数组的顺序处理，再赋值：XML 的 maxLength 在构造时装成 LengthFilter，代码再调 setFilters 会整组替换（TextView.java），以写入时实际生效的数组为准；setText 不经过 number 类 inputType 的 DigitsKeyListener。截断按 UTF-16 码元（JS 字符串 length 同单位），截断处末位是高位代理时再少保留一位。
2. 比较原文的逻辑（如复扫比对）用与源端相同的输入：源端没有 AllCaps 时保持原样大小写。
