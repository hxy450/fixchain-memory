# EditText 的 inputType 键盘与候选提示和内容约束分开映射：textCapCharacters → autoCapitalizationMode、textNoSuggestions → enablePreviewText(false)、带符号数字用含 +/- 的键盘；只有源端有 digits/InputFilter 才过滤，程序写入按 maxLength 截断

ID：`lesson-0457a04c31208e1fb916` · 版本：2

[本主题](index.md)

## 何时使用

界面实现阶段（含公共输入组件设计、页面规格的控件映射与页面转换），把 Android EditText 的 inputType、digits、InputFilter、maxLength 与粘贴回填翻译成 ArkUI TextInput/TextArea 属性时；为多个单行输入框确定键盘动作键与焦点链时

## 适用情境

源布局用 textCapCharacters、textNoSuggestions、number、numberSigned 等 inputType 标志声明键盘与输入法行为，多数未配 android:digits 或 InputFilter，内容合法性在点击计算或保存时才校验；个别控件挂了 InputFilter.AllCaps；页面另有粘贴或扫描回填写入带 maxLength 的输入框。目标 ArkUI（SDK 6.x 可用 autoCapitalizationMode、enablePreviewText、InputType.Number/PhoneNumber）；映射参考只给 number → InputType.Number 与“capitalize 无直接对应，使用文本转换”。 也包括多个单行 EditText 未写 imeOptions，源端键盘动作键靠框架缺省形成“下一项”焦点链。

## 原因

inputType 只决定键盘与输入法提示，不限制内容：翻成 inputFilter 加 toUpperCase，输入期就丢字符、改大小写（依赖原文的比较也变成大小写不敏感），校验时机从点击前移到输入；反过来以“无直接对应”跳过，又丢掉大写键盘与关闭候选。InputType.Number 不能输入负号；Android setText 经过 LengthFilter，直接赋值则不截断。来源中公共组件作者把单处 AllCaps 推广成全部 textCapCharacters 输入的默认组件，规格与多个页面照抄；另一些页面写成“无对应，下沉校验”。

## 做法

1. 键盘与候选提示：textCapCharacters → autoCapitalizationMode(AutoCapitalizationMode.ALL_CHARACTERS)（小写仍可输入，不 toUpperCase、不过滤）；textNoSuggestions → enablePreviewText(false)。
2. 内容约束只来自源端 android:digits 或 InputFilter：有才加 inputFilter；InputFilter.AllCaps 在输入时拦截转大写（如 RichEditor 的 aboutToIMEInput，粘贴同样处理），不推迟到保存或校验；源端保存、点击时的校验不前移成输入期过滤，也不把单处行为推广成公共输入组件的默认值。
3. 数值框按源 inputType 选键盘：number → InputType.Number 加 [0-9]；numberSigned（含 number|numberSigned）→ 带 +/- 的键盘（如 InputType.PhoneNumber）并只允许首位单个符号，不用 InputType.Number 承载可负值字段。
4. 粘贴、扫描回填等程序写入先按该框 maxLength 截断再赋值；比较原文的逻辑保持输入原样大小写。写前逐个 EditText 列出 inputType、digits、maxLength、InputFilter 与目标属性的对应，映射参考没有对应行时查 TextInput/TextArea API。
5. 单行 EditText 未写 imeOptions 时，键盘动作键由框架按焦点链给出：向下焦点搜索还能找到另一个输入框时为 Next、回车把焦点移过去，否则为 Done（本机 SDK android-36.1 源码 TextView.onCreateInputConnection）；目标逐框显式 enterKeyType(EnterKeyType.Next 或 Done)，并在 onSubmit 中把焦点移到源端焦点链的下一字段。
