# text 类 inputType 只映射键盘与输入法属性，内容约束只来自 digits、InputFilter 与 number 类过滤

ID：`lesson-0457a04c31208e1fb916` · 版本：2

[本主题](index.md)

## 何时使用

界面实现阶段（含公共输入组件设计、页面规格的控件映射与页面转换），把 Android EditText 的 inputType、digits、InputFilter 翻译成 ArkUI TextInput/TextArea 属性时

## 适用情境

源布局用 textCapCharacters、textNoSuggestions 等 text 类 inputType 标志声明键盘与输入法行为，多数未配 android:digits 或 InputFilter，内容合法性在点击计算或保存时才校验；个别控件挂了 InputFilter.AllCaps。映射参考只给“capitalize 无直接对应，使用文本转换”一类说法。

## 例外与边界

- inputType 是 number、numberSigned、numberDecimal 等数值类：按数值输入框的键盘与过滤规则处理

## 原因

text 类 inputType 只影响键盘与输入法，对应的 TextKeyListener 不是 InputFilter，不限制内容；number 类会装 DigitsKeyListener 作输入过滤（TextView.java），只收数字，signed 允许首位符号，decimal 允许小数点。把 text 类标志翻成 inputFilter 加 toUpperCase，输入期就丢字符、改大小写（依赖原文的比较也变成大小写不敏感），校验时机从点击前移到输入；反过来以“无直接对应”跳过，又丢掉大写键盘。

## 做法

1. 键盘与输入法提示：textCapCharacters → autoCapitalizationMode(AutoCapitalizationMode.ALL_CHARACTERS)（text_input.d.ts，API 20 起；小写仍可输入，不 toUpperCase、不过滤），目标 API 低于 20 时把大写键盘登记为差异。textNoSuggestions 在 ArkUI 没有直接对应：enablePreviewText 只控制预上屏，不能代替关闭候选，在规格中登记差异。
2. 内容约束只来自源端 android:digits、InputFilter 与 number 类 inputType 自带的数字过滤：有才加 inputFilter；InputFilter.AllCaps 在输入时拦截转大写（如 RichEditor 的 aboutToIMEInput，粘贴同样处理），不推迟到保存或校验。
3. 源端保存、点击时的校验不前移成输入期过滤，也不把单处控件的过滤推广成公共输入组件的默认值；公共组件只封装源码里真实挂在控件上的 InputFilter，并注明适用控件。
4. 写前逐个 EditText 列出 inputType、digits、maxLength、InputFilter 与目标属性的对应；映射参考没有对应行时查 text_input.d.ts、text_area.d.ts，不用过滤器或大写转换近似。
