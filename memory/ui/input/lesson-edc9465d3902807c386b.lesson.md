# 菜单 SearchView 迁成自绘搜索栏时把展开、焦点、提交、收起与菜单重建分成独立状态和事件，焦点态取自 TextInput 焦点回调

ID：`lesson-edc9465d3902807c386b` · 版本：1

[本主题](index.md)

## 何时使用

规格提取与界面实现阶段，把菜单 actionView 的 SearchView（collapseActionView）翻成自绘标题栏搜索框、决定工具栏菜单随搜索状态切换时

## 适用情境

源端菜单项以 SearchView 为 actionView 且 showAsAction 含 collapseActionView，代码注册 OnActionExpandListener、OnQueryTextFocusChangeListener 与 OnQueryTextListener（onQueryTextSubmit 返回 false 才由 SearchView 投递 ACTION_SEARCH），收起时 invalidateOptionsMenu 重建菜单，提交后只收键盘不清焦点；目标为自绘标题栏加按条件构建的 TextInput。

## 原因

SearchView 的展开态与输入焦点是两套状态：展开后可以失焦（收键盘、打开对话框），收起有独立回调与菜单重建，提交是否投递 ACTION_SEARCH 取决于 onQueryTextSubmit 的返回值。把控件折成几个查询函数，或用一个布尔同时表示展开与焦点、用取消图标代替 collapseActionView、在点击时手工翻转焦点标志，展开取焦、按焦点切换菜单、收起复位与重载就会丢失或互相串扰。

## 做法

1. 规格按控件 API 列状态机，每个回调写成验收项：展开与收起回调各自的副作用（收起清空查询、复位标签、重载列表、重建菜单）、焦点变化对应的菜单显隐、onQueryTextSubmit 返回值与 ACTION_SEARCH 投递、空串不提交、提交后收键盘；不以“应用内直调、内化等价”替代。
2. 实现前读源端创建该控件的方法全文，目标分设展开态与焦点态：展开态只由展开、收起入口改写，焦点态只在 TextInput 的 onFocus/onBlur 中写，菜单矩阵按源端监听读取对应的那一个。
3. 展开时用 FocusController.requestFocus(key) 取焦；输入框按条件构建时先置待取焦标记，在它的 onAppear 之后再请求（控件未上树时请求会失败，已观察错误码 150003）。
4. 源端提交后只收键盘、保留焦点时，把“收键盘引起的失焦”标记出来，不触发焦点变化分支，工具栏保持聚焦态菜单；收键盘接口按是否保留焦点选择。
5. 源方法里对宿主栏控件和框架对象的每个调用（展开、收起、菜单重建、前置提交）逐条落到目标或登记缺口，不以验收描述已覆盖代替。
