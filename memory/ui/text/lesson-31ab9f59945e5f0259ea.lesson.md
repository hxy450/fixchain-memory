# Tab 标签、页面标题与设置行等可见文案沿资源引用链取源端 strings 资源的逐字值，不用枚举名、路由名或自拟英文

ID：`lesson-31ab9f59945e5f0259ea` · 版本：3

[本主题](index.md)

## 何时使用

界面实现阶段，为 Tab 标签、页面/路由标题、设置入口行等可见文案取值并写入页面与路由表时；以及派发侦察或规格任务、确定导航与标题字段的形态时

## 适用情境

源端可见文案经资源键间接引用（导航目的地的 label、配置路由的标题资源、顶栏 title），常与目的地枚举名或功能名不同（例：某目的地枚举为 Map，显示文案却是带前缀的另一个词；消息目的地的页面标题另取一个名称）；目标以硬编码字符串或自建资源表承载；上游 brief、页面规格或侦察清单给出了文案或只给了枚举名。

## 原因

枚举名、路由名和自拟短语可能与源端显示文案不同，按它们填写会在各入口留下与源端不一致的文案；只含枚举名的侦察清单会把这一偏差传给下游。

## 做法

1. 写可见文案前沿源端引用链（导航目的地 label → 资源键 → 当前有效 locale 的 strings.xml）解析出逐字值，括号与标点一并保留；已读 brief 或页面规格给出逐字值时照抄，不用卡片标题、路由名或枚举名替代；实现某页前先读该页规格的标题与顶部栏行。
2. 把 P0 可见文案集中到一个常量或资源文件，逐条注明源资源键，页面与路由表只引用它。
3. 派发侦察或规格任务时，导航目的地和页面标题字段同时要求资源键与解析后的字面值，不只给枚举名。

## 可选检查

- 对文案有疑问时，用源 strings.xml 与集中文案文件逐项比对。
