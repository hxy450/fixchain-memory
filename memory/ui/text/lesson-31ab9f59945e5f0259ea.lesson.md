# Tab 标签、页面标题与设置行等可见文案沿资源引用链取源端 strings 资源的逐字值，不用枚举名、路由名或自拟英文

ID：`lesson-31ab9f59945e5f0259ea` · 版本：1

[本主题](index.md)

## 何时使用

界面实现阶段，为 Tab 标签、页面/路由标题、设置入口行等可见文案取值并写入页面与路由表时；以及派发侦察或规格任务、确定导航与标题字段的形态时

## 适用情境

源端可见文案经资源键间接引用（导航目的地的 label、配置路由的标题资源、顶栏 title），常与目的地枚举名或功能名不同（如 Map 目的地显示“Mesh Map”、Messages 目的地的页面标题为“Conversations”）；目标以硬编码字符串或自建资源表承载；上游 brief 或页面规格已给出、或可从 strings.xml 解析出逐字值。

## 原因

枚举名、路由名和自拟短语与源端显示文案经常不同，按它们填写会在每个入口留下近似改写，要求逐字一致的验收会成批失败。来源中生成者两分钟前读到的 brief 已逐字给出 User、Security、System AI 与完整的开关摘要，写页面时仍用了自建资源表里的 User Config、App Functions，并删去摘要的括号内容；另一批 Tab 与页面标题取自只含枚举名的侦察清单，已落盘的页面规格里有正确字面值却没有打开。

## 做法

1. 写可见文案前沿源端引用链（导航目的地 label → 资源键 → strings.xml）解析出逐字值；已读的 brief 或页面规格给出字面值时直接照抄，括号与标点一并保留。
2. 把 P0 可见文案集中到一个常量或资源文件，逐条注明源资源键，页面与路由表只引用它。
3. 派发侦察或规格任务时，导航目的地和页面标题字段同时要求资源键与解析后的字面值，不只给枚举名。

## 可选检查

- 对文案有疑问时，用源 strings.xml 与集中文案文件逐项比对。
