# 文本行高迁移应分别建模单行自然盒与多行行间距

ID：`lesson-4e8b8250476ba564b943` · 版本：1

[本主题](index.md)

## 何时使用

规格提取或主题实现阶段，映射文本 lineHeight、lineSpacing 并据此推导文本容器尺寸时

## 适用情境

源端文本样式同时携带字号与行高，目标端同名属性可能改变单行盒高；同一主题令牌又同时服务单行标签和多行段落，而目标框架的行距合成规则未必有文档或实测依据。

## 例外与边界

- 已用当前字体、框架版本和配置验证源端与目标端在单行盒高及多行块高上行为等价

## 原因

把同名 API 和相同数值当作等价，会把源端仅作用于行间的语义施加到单行文本；随后基于该错误行高推导的固定容器也会同步偏移。未经实测的行距合成公式还可能在修好单行后破坏多行。

## 做法

1. 分别定义字体自然行盒、额外行间距和多行总高，使用当前字体度量或源端实测取得自然行盒，不用一次历史修复的比例作为默认值。
2. 统一文本 modifier 发布前，同时选择一个单行样本和一个多行样本建立基线；容器固定高度引用可追踪的度量派生值，而不是复制含 lineHeight 假设的字面常量。
3. 目标框架的多行合成规则没有文档或样本时，把公式标为待验证假设；不能当场验证时优先保留已经正确的渲染路径。

## 检查

- 在当前字体与缩放配置下，对照源端或验收基线测量单行文本 bounds、多行块总高和相邻基线间距；三者均符合预期才认为映射成立。
