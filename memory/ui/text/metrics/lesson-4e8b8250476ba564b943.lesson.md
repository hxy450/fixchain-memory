# 文本行高迁移应分别建模单行自然盒与多行行间距

ID：`lesson-4e8b8250476ba564b943` · 版本：2

[本主题](index.md)

## 何时使用

规格提取或主题实现阶段，映射文本 lineHeight、lineSpacing 并据此推导文本容器尺寸时

## 适用情境

源端文本样式同时携带字号与行高，目标端同名属性可能改变单行盒高；同一主题令牌又同时服务单行标签和多行段落，而目标框架的行距合成规则未必有文档或实测依据。

## 例外与边界

- 已用当前字体、框架版本和配置验证源端与目标端在单行盒高及多行块高上行为等价

## 原因

把同名 API 和相同数值当作等价，会把源端仅作用于行间的语义施加到单行文本；随后基于该错误行高推导的固定容器也会同步偏移。未经实测的行距合成公式还可能在修好单行后破坏多行。

## 做法

1. 分开表达单行自然盒、额外行间距与多行总高。已有源码或度量说明单行使用自然盒时，不把 lineHeight 字面同时写成单行容器高度。
2. 改共享文本 modifier 时区分单行和多行路径。例：标签 H_single 取当前字体自然盒；段落 H_multi 取当前框架的多行合成结果，不能将二者都简化为 fontSize 或 lineHeight。
3. 只把已知语义写入映射；单行修法不自动推广到多行 lineSpacing。当前输入不足以确定多行公式时保留已有路径和该疑问，不套用历史字体比例。

## 可选检查

仅在适用条件不确定、与当前输入冲突或需要验证关键假设时按需执行；优先复用已有证据和正常测试。
不因读取本条经验而额外启动验证流程；项目原有必需测试照常执行。

- 仅当需要更改公共行高公式而现有依据无法确定其效果时，复用正常测试中的一个单行和一个多行样本，比较 bounds 或基线间距。
