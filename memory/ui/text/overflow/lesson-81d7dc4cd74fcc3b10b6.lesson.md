# 多行省略应核对末行渲染语义，而不是只匹配同名 API

ID：`lesson-81d7dc4cd74fcc3b10b6` · 版本：2

[本主题](index.md)

## 何时使用

规格提取或实现阶段，为带 maxLines 与 Ellipsis 的多行文本选择目标端折叠方案时

## 适用情境

源端按字符填充末行并紧接省略号，目标端同名 API 可能受默认 wordBreak 影响，按词丢弃后再显示带空格的省略标记。

## 例外与边界

- 产品允许目标平台的原生省略形态，或已验证当前 wordBreak、ellipsisMode 与字体配置能复现源端末行

## 原因

API 名称相同只说明功能类别一致，不保证断词、空格和省略号占位语义一致；差异集中在末行，普通结构检查和整体相似度容易漏掉。

## 做法

1. 区分末行填充、断词、空格和省略标记的语义；先采用当前框架与输入已经确认适用的 wordBreak、ellipsisMode 组合，不只凭 API 同名认定等价。
2. 明确仍有差异、且当前任务需要精确对齐时，才考虑按容器宽度度量可见前缀的折叠态方案；不是所有多行文本都需要自写截断。
3. 手动截断时保留原始资源与展开态全文，并处理首帧未取得宽度、后续宽度变化的情况。

## 可选检查

仅在适用条件不确定、与当前输入冲突或需要验证关键假设时按需执行；优先复用已有证据和正常测试。
不因读取本条经验而额外启动验证流程；项目原有必需测试照常执行。

- 仅当默认省略行为是否满足当前要求无法确定时，复用当前字体和宽度下的现有截图或正常文本用例，核对末行字符与省略号；不默认另起一轮视觉验收。
