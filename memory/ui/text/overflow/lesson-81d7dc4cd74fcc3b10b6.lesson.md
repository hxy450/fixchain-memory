# 多行省略应核对末行渲染语义，而不是只匹配同名 API

ID：`lesson-81d7dc4cd74fcc3b10b6` · 版本：1

[本主题](index.md)

## 何时使用

规格提取或实现阶段，为带 maxLines 与 Ellipsis 的多行文本选择目标端折叠方案时

## 适用情境

源端按字符填充末行并紧接省略号，目标端同名 API 可能受默认 wordBreak 影响，按词丢弃后再显示带空格的省略标记。

## 例外与边界

- 产品允许目标平台的原生省略形态，或已验证当前 wordBreak、ellipsisMode 与字体配置能复现源端末行

## 原因

API 名称相同只说明功能类别一致，不保证断词、空格和省略号占位语义一致；差异集中在末行，普通结构检查和整体相似度容易漏掉。

## 做法

1. 在规格中把断词方式、末行填充和省略标记形态列为可观察语义，并把未验证的 API 映射标为平台差异或待核项。
2. 先在当前字体和宽度下验证可用的 wordBreak 与 ellipsisMode 组合；仍不等价时，再按实际容器宽度和完整文本度量最长可见前缀，只替换折叠态文本。
3. 手动截断必须保留原始资源文本，并为首帧或宽度尚未回读时保留安全兜底。

## 检查

- 双端比较末行最后若干字符、空格、省略号和右侧留白；展开态仍显示完整原文，折叠态在尺寸变化后能重新计算。
