# 单行 ellipsize=middle/start 用 ellipsisMode(CENTER/START)，与 Span 组合不满足时才测量截断

ID：`lesson-a184209501ba02cb62e7` · 版本：3

[本主题](index.md)

## 何时使用

界面实现阶段，转换单行文本的省略位置（android:ellipsize="middle"/"start"、TextUtils.TruncateAt.MIDDLE/START）时

## 适用情境

源 TextView 用 android:ellipsize="middle"（或 start）配合 lines=1、maxLines=1 或 singleLine 显示文件名等尾部有意义的文本，可能还有关键字 Span 高亮；映射参考只给 end → TextOverflow.Ellipsis 示例。

## 例外与边界

- 项目已批准以尾部省略作为平台差异

## 原因

尾部省略会截掉文件名最有区分度的扩展名，用户可见差异真实存在。ArkUI 的 TextOverflow 只有 Ellipsis 一种省略，省略位置由 ellipsisMode 控制（text.d.ts，API 11 起）；只查 TextOverflow 枚举就判定无能力，再以 TODO 推给后续阶段，降级会一路保留到交付。

## 做法

1. 单行写 .maxLines(1).textOverflow({ overflow: TextOverflow.Ellipsis }).ellipsisMode(EllipsisMode.CENTER 或 START)；按 text.d.ts 核对 @since 与“START/CENTER 只在单行溢出时生效、需 Ellipsis 加 maxLines”的说明，并在 Text + Span 组合下实测一次省略结果。
2. 内置写法与 Span 高亮组合实测不满足时才走测量截断：onAreaChange 取可用宽度并换成 px，getUIContext().getMeasureUtils().measureText 以相同字体、字号、字重测量，二分求能放下的最长结果——middle 保留头尾（多出的字符给尾部以保留扩展名），start 只保留后缀；切点避开代理对，按（宽度, 文本）缓存（measureText 返回 px，见 @ohos.arkui.UIContext.d.ts）。
3. 有关键字 Span 高亮时先截断再高亮；被省略号切断的关键词怎样高亮，来源没有记录——在截断结果上重新匹配关键词会让被切断的关键词失去高亮，需要保留时按截断前后的索引映射裁剪源 span 区间。
