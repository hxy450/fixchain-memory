# 单行 ellipsize=middle/start 在目标 TextOverflow 没有同名成员时先用 Text 的 ellipsisMode、满足不了再实现测量式中间截断，不降级为尾部省略

ID：`lesson-a184209501ba02cb62e7` · 版本：2

[本主题](index.md)

## 何时使用

界面实现阶段，转换单行文本的省略位置（ellipsize），而目标 TextOverflow 枚举没有对应成员时

## 适用情境

源 TextView 用 android:ellipsize="middle"（或 start）配合 lines=1/maxLines=1 显示文件名等尾部有意义的文本，可能还有关键字 Span 高亮；ArkUI Text 的 TextOverflow 只有尾部 Ellipsis 等模式，映射参考只给 end → Ellipsis 示例。

## 例外与边界

- 项目已批准以尾部省略作为平台差异
- Text 里有 Span 子组件做关键字高亮时，ellipsisMode 的 START、CENTER 是否照样生效、省略号位置是否正确没有核实过：这种情形按做法第 2 步先截断纯文本再切分 Span，不单靠 ellipsisMode；源端是多行（maxLines 大于 1）时 START、CENTER 不生效，不适用本条的单行做法。

## 原因

尾部省略会截掉文件名最有区分度的扩展名，用户可见差异真实存在；只凭一个枚举的部分检索结果就判定无能力，再以 TODO 推给后续阶段，降级往往保留到交付。来源未核实 ellipsisMode 等属性在当时 SDK 及 Span 高亮组合下是否可用。

## 做法

1. 先用 Text 的 ellipsisMode：textOverflow 设为 TextOverflow.Ellipsis 且设了 maxLines 时，EllipsisMode.START / CENTER 在单行文本超长时做头部、中间省略（API 11 起；单独设 ellipsisMode 不生效）；它满足不了时（如要控制头尾各留几个字符）再在本阶段实现测量截断：onAreaChange 取可用宽度并换成 px，getUIContext().getMeasureUtils().measureText 以相同字号测量，二分求能放下的最长“头 + … + 尾”（多出的字符给尾部以保留扩展名，切点避开代理对），按（宽度, 文本）缓存，不在 build() 里测量。
2. 有关键字高亮时先截断纯文本，再在截断结果上切分 Span，与源端先 span 后省略的可见结果一致。
