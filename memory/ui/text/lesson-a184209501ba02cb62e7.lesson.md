# 单行 ellipsize=middle/start 在目标 TextOverflow 没有同名成员时实现测量式中间截断，不降级为尾部省略

ID：`lesson-a184209501ba02cb62e7` · 版本：1

[本主题](index.md)

## 何时使用

界面实现阶段，转换单行文本的省略位置（ellipsize），而目标 TextOverflow 枚举没有对应成员时

## 适用情境

源 TextView 用 android:ellipsize="middle"（或 start）配合 lines=1/maxLines=1 显示文件名等尾部有意义的文本，可能还有关键字 Span 高亮；ArkUI Text 的 TextOverflow 只有尾部 Ellipsis 等模式，映射参考只给 end → Ellipsis 示例。

## 例外与边界

- 项目已批准以尾部省略作为平台差异

## 原因

尾部省略会截掉文件名最有区分度的扩展名，用户可见差异真实存在；只凭一个枚举的部分检索结果就判定无能力，再以 TODO 推给后续阶段，降级往往保留到交付。来源未核实 ellipsisMode 等属性在当时 SDK 及 Span 高亮组合下是否可用。

## 做法

1. 先在 SDK 声明中全文检索 Text 与省略位置相关的属性；没有现成能力时在本阶段实现测量截断：onAreaChange 取可用宽度并换成 px，getUIContext().getMeasureUtils().measureText 以相同字号测量，二分求能放下的最长“头 + … + 尾”（多出的字符给尾部以保留扩展名，切点避开代理对），按（宽度, 文本）缓存，不在 build() 里测量。
2. 有关键字高亮时先截断纯文本，再在截断结果上切分 Span，与源端先 span 后省略的可见结果一致。
