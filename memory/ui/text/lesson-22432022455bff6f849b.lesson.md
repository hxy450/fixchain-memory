# 代码内取本模块字符串按数字 id 调 getStringSync($r(...).id)，不用 API 20 起弃用的 Resource 重载

ID：`lesson-22432022455bff6f849b` · 版本：3

[本主题](index.md)

## 何时使用

界面实现阶段，把安卓命令式取字符串（getResources().getString，如自绘 View 里 drawText、measureText 的文案）改写为 ArkTS 代码内取值并选择 resourceManager 接口时；后续切片扩展已有取值写法时

## 适用情境

源端在自绘 View 或代码里按当前资源配置取文案；目标需要在 ArkTS 中拿到纯字符串（Canvas 绘制、测宽、拼接），同一屏还有走声明式 $r 的组件文本；应用带多个 locale 资源目录，可能以应用偏好语言运行。

## 原因

两个重载都存在不代表行为一致：getStringSync(resource: Resource) 自 API 20 起标 @deprecated（@ohos.resourceManager.d.ts）；在 targetSdk 6.1.0(23) 工程中观察到，经 i18n.System.setAppPreferredLanguage 设置应用偏好语言后，Resource 重载回落到 base 文案，而按 .id 取值返回偏好语言文案，于是对话框已切换、画布仍是旧语言，d.ts 对这一差异没有说明。只在系统语言下核对，或只检索到 $r/getStringSync 引用就判 i18n 落地，发现不了这一差异。

## 做法

1. 本模块资源在代码内取字符串统一写 resourceManager.getStringSync($r('app.string.x').id)；把先前切片的取值写法扩展到更多调用点前，按这一规则核对。
2. 换 SDK 版本或遇到没有验证资料的重载差异时，临时用 i18n.System.setAppPreferredLanguage 切到一个有资源的 locale，打印两种取值对比后再定。

## 可选检查

- “文案随语言切换”的验收在系统语言与应用偏好语言两种配置下，分别对比代码内取值的文本与组件文本是否为同一语言。
