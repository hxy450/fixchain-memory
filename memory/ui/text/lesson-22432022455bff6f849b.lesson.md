# resourceManager 代码内取值（字符串、数组、复数、颜色）一律传 $r(...).id 数字重载，不用 Resource 对象重载

ID：`lesson-22432022455bff6f849b` · 版本：2

[本主题](index.md)

## 何时使用

界面与服务实现阶段，把安卓命令式取资源（getString、getStringArray、getQuantityString、getColor，如自绘 View 里 drawText、measureText 的文案）改写为 ArkTS 代码内取值并选择 resourceManager 接口时；新写取值辅助函数，或把已有取值写法扩展到更多调用点、其他取值方法时

## 适用情境

源端在自绘 View 或代码里按当前资源配置取文案、字符串数组、复数串或颜色；目标需要在 ArkTS 中拿到纯值（Canvas 绘制、测宽、拼接、菜单与选择器文案），同一屏还有走声明式 $r 的组件文本；应用带多个 locale 资源目录，可能以应用偏好语言运行（i18n.System.setAppPreferredLanguage）；SDK 对 getStringSync、getStringArrayValue(Sync)、getIntPluralStringValueSync、getColorSync 等同时提供 (resId: number) 与 (resource: Resource) 两种重载。

## 原因

两个重载都存在不代表行为一致：在应用偏好语言下，getStringSync($r(...)) 曾观察到回落 base 英文，而 getStringSync($r(...).id) 返回偏好语言译文；以 Resource 对象取字符串数组同样让菜单混入默认语言文案。只在系统语言下核对，或只检索到 $r/getStringSync 引用就判 i18n 落地，发现不了这一差异；把数字 id 约定只套到 getStringSync，数组、复数等其余取值方法和新写的辅助函数仍会走 Resource 重载。

## 做法

1. 代码内取值统一传数字 id：getStringSync($r('app.string.x').id)、getStringArrayValueSync($r('app.strarray.x').id)、getIntPluralStringValueSync($r('app.plural.x').id, n)、getColorSync($r('app.color.x').id)；辅助函数形参收 Resource 时在内部取 .id。新写辅助函数或把已有写法扩展到更多调用点、其他取值方法前，按这一规则核对，不只改 getStringSync。
2. 遇到没有验证资料的重载差异时，临时用 i18n.System.setAppPreferredLanguage 切到一个有资源的 locale，打印两种取值对比后再定。

## 可选检查

- “文案随语言切换”的验收在系统语言与应用偏好语言两种配置下，分别对比代码内取值的文本与组件文本是否为同一语言。
- 批量改写或交付前检索 resourceManager 取值调用中直接传 $r(...) 或 Resource 形参的写法，确认都已改为 .id 重载。
