# 代码内经 resourceManager 取字符串、数组、复数、颜色一律传 $r(...).id，与声明式 $r 同一解析路径，不用 Resource 重载

ID：`lesson-22432022455bff6f849b` · 版本：4

[本主题](index.md)

## 何时使用

界面实现阶段，把安卓命令式取字符串（getResources().getString，如自绘 View 里 drawText、measureText 的文案）改写为 ArkTS 代码内取值并选择 resourceManager 接口时；后续切片扩展已有取值写法时；为字符串数组、复数、颜色等其他取值方法写新文件或新辅助函数时

## 适用情境

源端在自绘 View 或代码里按当前资源配置取文案；目标需要在 ArkTS 中拿到纯字符串（Canvas 绘制、测宽、拼接），同一屏还有走声明式 $r 的组件文本；应用带多个 locale 资源目录，可能以应用偏好语言运行。

## 原因

两个重载都存在不代表行为一致：来源实测在应用偏好语言 fa 下，同一 resourceManager 的 getStringSync($r(...)) 回落到 base 英文，getStringSync($r(...).id) 返回波斯语，于是对话框已切换、画布仍是英文。只在系统语言下核对，或只检索到 $r/getStringSync 引用就判 i18n 落地，发现不了这一差异。 只把 .id 约定用在取字符串、数组等其他取值仍传 Resource 对象时，应用偏好语言下抽屉菜单、选择器等由这些方法取值的文案同样回落 base。

## 做法

1. 代码内经 resourceManager 取值一律传数字 id：getStringSync($r('app.string.x').id)、getStringArrayValue(Sync)($r('app.strarray.x').id)、getIntPluralStringValueSync($r('app.plural.x').id, n)、getColorSync($r('app.color.x').id)（Resource 重载自 API 20 废弃；resId 版 getStringSync/getStringArrayValueSync/getColorSync 为 API 10 起，getIntPluralStringValueSync(resId, n) 为 API 18 起，compatibleSdkVersion 低于 18 时用 getPluralStringValueSync(resId, n)（该接口自 API 18 起废弃，仅作低版本兼容分支）；本机 SDK API 24 @ohos.resourceManager.d.ts）；工程已有 resText 一类取值辅助时照它的写法，并把约定推及数组、复数、颜色等全部取值方法，不只用在 getStringSync。把先前切片的取值写法扩展到更多调用点、或新写取值辅助函数前，按这一规则核对。
2. 遇到没有验证资料的重载差异时，临时用 i18n.System.setAppPreferredLanguage 切到一个有资源的 locale，打印两种取值对比后再定。

## 可选检查

- “文案随语言切换”的验收在系统语言与应用偏好语言两种配置下，分别对比代码内取值的文本与组件文本是否为同一语言。
