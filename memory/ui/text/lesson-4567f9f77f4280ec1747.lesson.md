# 可见文案改为资源引用时值取自源端原文：目标字符串表缺键就新建专属键并连同原值移交，补值者回查源布局，不用语义相近的现成资源或按键名自拟

[本主题](index.md)

## 何时使用

页面转换、切片实现与组收口阶段，源端文案在目标 string.json 中没有对应条目，或把页面字面量改成由他人单写的资源引用、由收口者补值时

## 适用情境

源布局或源码给出页面专属文案（如空态“暂时没有常用的路线”、隐私弹窗“同意并继续/不同意”）或纯数字徽标序号（android:text="1"…"4"），目标字符串表没有对应键，共享资源文件由收口 agent 单写；工程里有语义相近的通用资源（“暂无数据”、他页“隐私政策”、“取消/确定”）可引用；交接可能只给键名不给值，显示容器可能是固定尺寸的小徽标。

## 例外与边界

- 纯数字等不需要翻译的序号可以保留字面量，不必新建资源

## 原因

缺资源只是写盘边界造成的缺口，换成近义的现成资源会把源端专属措辞与按钮语义（同意/不同意对比确定/取消）改掉，报告还能写“所有引用资源都已存在”；只交接键名时，补值者只能按键名猜，带语义的键名会被写成“第1站”一类新文案，在固定尺寸徽标里只显示一个字。来源中两处页面转换者读到源文案、检索不到对应键，就改用通用或他页资源；另一处切片 worker 把“1”～“4”改成带语义的键名引用、交接只写键名，收口者按键名写入“第N站”。

## 做法

1. 目标字符串表缺源端专属文案时，用页面专属的新键引用，并按工程通道交给负责共享资源的收尾者补充（登记资源占位或移交标记），在报告中列为待补资源；不用通用或其他页面的资源顶替。
2. 把字面量改成由他人单写的资源引用时，交接逐项写“键名=原值”，原值取自源布局、strings.xml 或被替换的字面量。
3. 收口者为新引用的键补值时，按页面锚点回查源布局的 android:text、strings.xml 与替换前的代码字面量，不从键名推断文案；找不到来源就登记缺口。

## 可选检查

- 补值后核对所引用资源的实际值与源文案逐字一致；固定宽高的徽标、角标类文字只放与源端等长的内容
