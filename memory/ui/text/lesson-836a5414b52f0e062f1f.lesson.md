# 多行省略正文含拉丁单词时两端末行截断粒度可能不同：先试 wordBreak(BREAK_ALL)，仍不一致才测量截断

ID：`lesson-836a5414b52f0e062f1f` · 版本：3

[本主题](index.md)

## 何时使用

规格提取阶段为带 maxLines(N) + TextOverflow.Ellipsis（或 android:ellipsize）的多行正文写转换决策，以及界面实现阶段落实折叠态末行时

## 适用情境

源端多行正文以 maxLines + Ellipsis 折叠，正文含拉丁单词或长英文串；目标用 .maxLines() + .textOverflow({ overflow: TextOverflow.Ellipsis })，默认 wordBreak 为 BREAK_WORD；映射参考只记 ellipsize → textOverflow 的 API 对应；项目可能要求完整复刻源端可观察行为。

## 例外与边界

- 项目允许平台差异、不要求逐字复刻末行时，直接使用内置行为，不引入运行期测量
- 正文是纯 CJK 文本：按 enums.d.ts，ArkUI 默认可在任意两个 CJK 字符间换行，不会出现整词丢弃

## 原因

观察到的源端末行按字符填满后接“…”，ArkUI 默认按词换行，末行放不下整词就整词丢弃，再接带前导空格的省略号并留白；只记 API 对应的映射让规格写成“等价”，差异留到视觉核验才暴露。整词丢弃来自对非 CJK 文本的按词换行（enums.d.ts：BREAK_WORD 尽量整词保留）；改用 BREAK_ALL 能否在当前文本上达到与源端一致的末行，尚无试验记录，用前在当前文本上核末行。

## 做法

1. 规格提取时不把 maxLines + Ellipsis 标为“等价”：写明两端末行的截断差异（可用双端截图或 measureTextSize 在当前文本上核对）；完整复刻口径下登记为平台差异项或直接给出实现方案；映射参考只给 API 对应时，把渲染语义缺口写进差异验收条目。
2. 实现时先设 .wordBreak(WordBreak.BREAK_ALL)（text.d.ts 注明它与 Ellipsis + maxLines 配合时可在字母间断行并接省略号），在当前文本上核末行。
3. 仍需字符级一致时，在 onSizeChange 得到宽度后，以与 Text 相同的字体、字号、行高和换行设置调用 measureTextSize，二分求“前缀 + …”满足目标行数的最长前缀；只改折叠态，展开态与首帧继续使用原文与内置省略兜底。

## 可选检查

- 仅当内置属性能否满足要求不明时，在正在实现的这一段文本上核对末行截断位置与省略号前是否有空格。
