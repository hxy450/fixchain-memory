# 多行 maxLines + Ellipsis 两端末行截断粒度不同：规格写明差异，确需字符级一致时才用测量截断兜底

ID：`lesson-836a5414b52f0e062f1f` · 版本：1

[本主题](index.md)

## 何时使用

规格提取阶段为带 maxLines(N) + TextOverflow.Ellipsis（或 android:ellipsize）的多行正文写转换决策，以及界面实现阶段落实折叠态末行时

## 适用情境

源端多行正文以 maxLines + Ellipsis 折叠；目标用 .maxLines() + .textOverflow({ overflow: TextOverflow.Ellipsis })，默认 wordBreak 为 BREAK_WORD；映射参考只记 ellipsize → textOverflow 的 API 对应；项目可能要求完整复刻源端可观察行为。

## 例外与边界

- 项目允许平台差异、不要求逐字复刻末行时，直接使用内置行为，不引入运行期测量

## 原因

来源观察到源端末行按字符填满后接“…”，ArkUI 默认按词换行，末行放不下整词就整词丢弃，再接带前导空格的省略号并留白；只记 API 对应的映射让规格写成“等价”，差异留到视觉核验才暴露。来源修复用运行期测量做到字符级截断，但没有排除更简单的 wordBreak/ellipsisMode 配置，也不证明所有工具链都必须这样做。

## 做法

1. 规格不写“等价”：写明两端末行形态的差异，完整复刻口径下登记为平台差异项，或直接给出实现方案；映射参考只给 API 对应时，把渲染语义缺口写进差异验收条目。
2. 实现时先试内置属性能否满足当前要求；确需字符级一致时，在 onSizeChange 得到宽度后，以与 Text 相同的字体、字号、行高和换行设置调用 measureTextSize，二分求“前缀 + …”满足目标行数的最长前缀；只改折叠态，展开态与首帧继续使用原文与内置省略兜底。

## 可选检查

- 仅当内置属性能否满足要求不明时，在正在实现的这一段文本上核对末行截断位置与省略号前是否有空格。
