# maxLines + Ellipsis 两端截断粒度不同：单行补 wordBreak(BREAK_ALL)，多行写明差异、确需字符级一致才测量截断

ID：`lesson-836a5414b52f0e062f1f` · 版本：2

[本主题](index.md)

## 何时使用

规格提取阶段为带 maxLines(N) + TextOverflow.Ellipsis（或 android:ellipsize、singleLine）的单行或多行文本写转换决策，以及界面实现阶段落实标题行与折叠态末行时

## 适用情境

源端多行正文以 maxLines + Ellipsis 折叠；目标用 .maxLines() + .textOverflow({ overflow: TextOverflow.Ellipsis })，默认 wordBreak 为 BREAK_WORD；映射参考只记 ellipsize → textOverflow 的 API 对应；项目可能要求完整复刻源端可观察行为。 也包括单行用户内容（标题、分类名、工具栏标题）：Android 的 TextUtils.ellipsize 按字符截断，ArkUI 默认先按词断行再省略；以及源控件是三方 TextView 子类（布局声明了库命名空间、未写 android:ellipsize），截断由库自身实现（例如取前 N 行、按空格回退、去尾标点再加省略号）。

## 例外与边界

- 项目允许平台差异、不要求逐字复刻末行时，直接使用内置行为，不引入运行期测量

## 原因

源端末行按字符填满后接“…”，ArkUI 默认按词换行，末行放不下整词就整词丢弃，再接带前导空格的省略号并留白；只记 API 对应的映射让规格写成“等价”，差异留到视觉核验才暴露。单行文本只有一行，改为 wordBreak(BREAK_ALL) 就得到字符级截断；多行时该属性会让前几行也在词中断开，与源端按词换行、只在末行按字符截断不同，测量截断是已观察可行的做法，不排除当前 SDK 有更简单的 ellipsisMode 等配置。源控件是三方 TextView 子类时截断由库实现决定，按属性名直译成 maxLines + Ellipsis 会丢掉库的回退与去尾规则。

## 做法

1. 规格不写“等价”：写明两端末行形态的差异，完整复刻口径下登记为平台差异项，或直接给出实现方案；映射参考只给 API 对应时，把渲染语义缺口写进差异验收条目。
2. 单行（maxLines(1) 或 singleLine）用户内容要与源端字符级截断一致时，在 maxLines(1) + textOverflow(Ellipsis) 上补 .wordBreak(WordBreak.BREAK_ALL)；多行不用它代替末行截断。
3. 实现时先试内置属性能否满足当前要求；确需字符级一致时，在 onSizeChange 得到宽度后，以与 Text 相同的字体、字号、行高和换行设置调用 measureTextSize，二分求“前缀 + …”满足目标行数的最长前缀；只改折叠态，展开态与首帧继续使用原文与内置省略兜底。
4. 源控件是三方 TextView 子类且未写 android:ellipsize 时，先取库实现核对截断策略（取前几行、回退规则、去尾标点、省略号字符），再按该规则用与 Text 相同字体与宽度的测量或 @ohos.graphics.text Paragraph 自排版实现，不直译为 maxLines + Ellipsis。

## 可选检查

- 仅当内置属性能否满足要求不明时，在正在实现的这一段文本上核对末行截断位置与省略号前是否有空格。
