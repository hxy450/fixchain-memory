# 源端文案来自框架（android.R.string.*，或偏好对话框未声明按钮文案时的默认）按框架译文落地：不借同名应用键，补齐各语言目录

ID：`lesson-ff19b09146b57d0f91a8` · 版本：2

[本主题](index.md)

## 何时使用

页面实现阶段，为源端 stringResource(android.R.string.ok)、@android:string/cancel 一类系统字符串，或由框架默认提供的对话框按钮文案选择目标文案来源并新建应用字符串键时

## 适用情境

源码或布局引用 android.R.string.ok、cancel 等框架字符串，它们不在应用 strings.xml 中，由系统按设备语言提供译文；目标工程已有多个语言限定目录（可能区分简繁）；转换者准备新增一个应用键（如 button_ok），只在 base 写英文值。也包括源端没有显式引用：ListPreference、EditTextPreference 等偏好对话框的 XML 未声明 positiveButtonText/negativeButtonText，按钮由框架默认 @android:string/ok、cancel 提供，而应用恰好也有 ok、cancel、confirm 等同名或近义键。

## 原因

框架字符串的译文来自系统资源，源应用在各种设备语言下都显示本地化文案；改成只有 base 值的应用键后，非英文界面显示英文。这与“源 locale 缺键回落 base”不同：源端并不缺译文，只是译文不在应用资源里。框架对同一语言还可能按地区给出不同译文（如简体与繁体）。应用同名键的措辞与语言覆盖都可能与框架串不同，借用它会让按钮文案在各语言下偏离源端。

## 做法

1. 遇到 android.R.string.* 或 @android:string/* 时，或源 XML 对偏好对话框按钮未声明 positiveButtonText/negativeButtonText 时，先列出工程已有的语言限定目录；新建专属应用键（如 android_ok、android_cancel）后为每个目录写入该字符串在对应 locale 的框架译文，可从 SDK android.jar 的框架资源导出；应用自有的 ok、cancel、confirm 等键不代替框架串。
2. 框架对同一语言按地区给出不同译文、而目标只有语言级目录时（如繁体中文），按框架的地区目录补对应限定目录，只放这些键。
3. 暂时取不到译文时按工程占位约定登记待译项，不以 base 英文当作已完成。
