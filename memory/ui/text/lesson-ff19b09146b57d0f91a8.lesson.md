# 源端引用 android.R.string.* 系统文案时按设备语言本地化落地：新建应用字符串就为工程已有的每个语言目录补框架译文，不只写 base 英文

ID：`lesson-ff19b09146b57d0f91a8` · 版本：3

[本主题](index.md)

## 何时使用

页面实现阶段，为源端 stringResource(android.R.string.ok)、@android:string/cancel 一类系统字符串选择目标文案来源并新建应用字符串键时

## 适用情境

源码或布局引用 android.R.string.ok、cancel 等框架字符串，它们不在应用 strings.xml 中，由系统按设备语言提供译文；目标工程已有多个语言限定目录（可能区分简繁）；转换者准备新增一个应用键（如 button_ok），只在 base 写英文值。

## 原因

框架字符串的译文来自系统资源，源应用在各种设备语言下都显示本地化文案；改成只有 base 值的应用键后，非英文界面显示英文。这与“源 locale 缺键回落 base”不同：源端并不缺译文，只是译文不在应用资源里。框架对同一语言还可能按地区给出不同译文（如简体与繁体）。

## 做法

1. 遇到 android.R.string.* 或 @android:string/* 时先列出工程已有的语言限定目录；新建应用键后为每个目录写入该字符串在对应 locale 的框架译文，从本机 SDK platforms/android-<api>/data/res/values-<locale>/strings.xml 取同名键（如 ok、cancel）。
2. 框架对同一语言按地区给出不同译文、而目标只有语言级目录时（如繁体中文），按框架的地区目录补对应限定目录，只放这些键。
3. 本机平台资源查不到某个 locale 的框架译文时，在报告中列出缺失的 locale 与已查路径，登记为待补译项，不以 base 英文当作已完成。
