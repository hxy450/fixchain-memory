# 系统文案（android.R.string.*、DialogPreference 默认按钮）建专属键补各语言框架译文，不借同名应用串

ID：`lesson-ff19b09146b57d0f91a8` · 版本：2

[本主题](index.md)

## 何时使用

页面实现阶段，为源端 stringResource(android.R.string.ok)、@android:string/cancel 一类系统字符串选择目标文案来源并新建应用字符串键时；以及源偏好对话框、AlertDialog 未显式声明按钮文案，为目标弹窗按钮选择文案来源时

## 适用情境

源码或布局引用 android.R.string.ok、cancel 等框架字符串，它们不在应用 strings.xml 中，由系统按设备语言提供译文；目标工程已有多个语言限定目录（可能区分简繁）；转换者准备新增一个应用键（如 button_ok），只在 base 写英文值。 也包括源偏好 XML 的 ListPreference、EditTextPreference 未声明 positiveButtonText/negativeButtonText，按钮文案由框架默认（@android:string/ok、cancel）提供，而应用自身恰有 ok、cancel、confirm 等同名或近义键。

## 原因

框架字符串的译文来自系统资源，源应用在各种设备语言下都显示本地化文案；改成只有 base 值的应用键后，非英文界面显示英文。这与“源 locale 缺键回落 base”不同：源端并不缺译文，只是译文不在应用资源里。框架对同一语言还可能按地区给出不同译文（如简体与繁体）。 应用里同名或近义的 ok、cancel、confirm 键是应用自己的文案，措辞与各语言译文都可能与框架串不同，借用后按钮文字与源端不一致。

## 做法

1. 先对照源 XML 或调用处是否显式声明按钮文案（positiveButtonText/negativeButtonText、setPositiveButton 等）；未声明时按钮取框架默认串，与显式引用 android.R.string.* 同样处理，不因应用恰有同名键就引用应用串。
2. 遇到 android.R.string.* 或 @android:string/* 时先列出工程已有的语言限定目录；新建应用键后为每个目录写入该字符串在对应 locale 的框架译文，可从 SDK android.jar 的框架资源导出。
3. 框架对同一语言按地区给出不同译文、而目标只有语言级目录时（如繁体中文），按框架的地区目录补对应限定目录，只放这些键。
4. 暂时取不到译文时按工程占位约定登记待译项，不以 base 英文当作已完成。
