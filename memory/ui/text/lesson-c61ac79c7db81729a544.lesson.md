# 可折叠正文按 onTextLayout 溢出结果显示展开钮时，用文本测量比较限行与不限行高度，overflow 按默认 Clip

ID：`lesson-c61ac79c7db81729a544` · 版本：3

[本主题](index.md)

## 何时使用

界面实现阶段，把 Compose 可折叠文本卡转换为 ArkUI 组件，确定是否显示展开按钮、折叠态 overflow 与文本加工时；占位复核阶段决定字符数近似是否保留时

## 适用情境

源 Text 用 onTextLayout { didOverflowHeight / hasVisualOverflow } 决定是否显示展开钮，maxLines 在折叠与展开间切换且未设 overflow（Compose 默认 Clip），正文可能经 buildAnnotatedStringWithUrls 等加工，外层 toggleable/clickable 带按压反馈；ArkUI Text 没有同名排版回调，写者可能用字符数阈值近似。

## 原因

字符数阈值不反映实际排版（字号、行宽、换行），只是近似，展开钮的出现会与源端按排版结果的判定不一致。只把最难的溢出判定登记为近似时，同一组件的链接、overflow 默认值与按压反馈会被静默丢弃；习惯性加 Ellipsis 也改变了源端的 Clip 外观。

## 做法

1. 先把源组件拆成逐项契约：溢出判定依据、文本加工与链接（写法见 lesson-57a52be767730880cbba）、overflow、交互反馈、容器色；每项给出实现或登记，不只登记最难的一项。
2. 溢出判定用 UIContext.getMeasureUtils().measureTextSize：以与 Text 相同的字号、字重、行高、字距，在实际约束宽度（如 onAreaChange 取得的宽度）下分别测不限行与 maxLines = N 的高度，前者更高即溢出（@ohos.measure.d.ts 的 MeasureOptions 含 maxLines）；本地知识库查不到不等于 API 不可用，先用最小编译或运行验证确认。字符数阈值只能作为显式标注的临时近似，登记时写明原因。
3. 源 Text 未设 overflow 时按 Compose 默认 Clip 落实，不加 TextOverflow.Ellipsis。
