# 源端返回按钮与 onBackPressed 执行同一逻辑时共用同一处理分支，按源端启动来源标志执行、不默认 pop；返回按钮直接调 super.onBackPressed()、finish() 时两路分开实现

ID：`lesson-f19632971e470d55c543` · 版本：3

[本主题](index.md)

## 何时使用

页面转换阶段，把 Activity 的返回按钮点击（含 ActionBar Up 的 android.R.id.home 分支）与 onBackPressed 翻译成 NavDestination 的返回处理时；规格提取阶段为导航表写 Up 与系统返回行时

## 适用情境

源 Activity 按启动来源标志（如 isFromSplash）改变返回行为：首启进入时返回会先执行补救动作（如添加默认城市）再进主页，其他来源才 finish；目标页用 NavPathStack 管理，返回按钮默认写成 pop()，系统返回未处理。 也包括源端返回按钮直接调 super.onBackPressed()、finish() 或跳转，绕过子类 onBackPressed 覆写里的分支（如先回跳上一项），与系统返回不是同一逻辑。

## 原因

返回按钮无条件 pop、系统返回不处理，首启来源的补救动作被跳过，用户返回后停在没有数据的状态。来源中转换者读到返回点击与 onBackPressed 在来源标志为真时执行补救并跳主页，输出却只有 pop()；接收来源标志的参数类又未导出、按 instanceof 判断，调用页推入的是另一个类，标志恒为假。 反过来，源端返回按钮绕过覆写、直接调 super.onBackPressed() 时，把两路合成同一分支会让返回按钮先走覆写里的回跳逻辑而不退出页面；NavDestination 系统标题栏的返回钮固定走 onBackPressed，同样分不开两路。

## 做法

1. 先逐个列出源 Activity 返回按钮（返回点击或 android.R.id.home 分支）、onBackPressed 与各结果回调实际调用的方法与去向（finish、跳主页、Toast）。两路执行同一逻辑（返回按钮调 this.onBackPressed() 或同一处理函数）时，在 NavDestination 中让两者调用同一个处理函数，来源标志为真时照源码执行；返回按钮直接调 super.onBackPressed()、finish() 或跳转时，两路分开实现：返回按钮照它自己的调用执行（如直接 pop），系统返回保留覆写里的分支，需要分开时用自绘标题栏的 Up 回调承接返回按钮。“不默认 pop”只针对源端返回按钮本来要执行补救或分支逻辑的情形。
2. 来源标志通过路由参数传入时，确认所有调用方推入的参数能被接收端识别（共享导出的参数类，或按字段结构读取）。

来源支持：2 张卡 · 2 次迁移 · 2 个应用
