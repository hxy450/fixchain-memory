# 底部 tab 的 popUpTo(start){saveState}、外部入口的 CLEAR_TOP，以及进程存活时从桌面图标再次拉起触发的路由跳板再分流，要拆出返回栈后果写成验收，并在 onBackPress、onNewWant 显式实现

ID：`lesson-39f137ee173e50363f79` · 版本：2

[本主题](index.md)

## 何时使用

规格提取阶段描述底部 tab 切换和外部深链入口，或把 LAUNCHER 路由跳板 Activity（启动页按条件分流）映射为入口分流时；入口装配与实现阶段核对导航壳差异、接线 EntryAbility 与入口页时

## 适用情境

源端 tab 切换用 navigate { popUpTo(startDestination){ saveState }; launchSingleTop; restoreState }，桌面卡片、通知等外部入口用带 FLAG_ACTIVITY_CLEAR_TOP/NEW_TASK 的 Intent 拉起主 Activity；目标端用单 Navigation 加下标或条件渲染切 tab，NavPathStack 承载详情页。也包括 LAUNCHER 路由跳板 Activity（未声明 launchMode 即 standard）按条件跳主页并带 CLEAR_TOP，任务根已被 TaskStackBuilder 等改写成主页：进程存活时从桌面图标再次进入，源端在任务顶新建跳板并重跑分流（首启进引导，否则清掉主页之上的页面回主页），从最近任务切回才保持原页；目标单例 UIAbility 再次拉起只回原页面栈。

## 原因

popUpTo(start) 同时决定 tab 状态保存和“非起始 tab 上按返回先回起始 tab”；CLEAR_TOP 决定热启动时清掉压在上面的页面。规格只写“状态保留”“落到某 tab”时，目标端下标切 tab 又没有 tab 返回栈，返回键直接退出、深链落在旧详情页下面。入口分流只接在冷启路径时，CLEAR_TOP 会被“冷启时根页天然唯一”消解，进程存活时从桌面图标重进停在原页。

## 做法

1. 规格把每个导航调用拆成“返回栈后果”和“状态保存”两类验收项；每个 Intent flag 写出可观察后果与对应的进入场景（CLEAR_TOP 只在目标页已在栈中才生效，对应热启动或桌面图标重进），或明确登记豁免；源码注释里描述的返回行为原样转成验收项。
2. 下标或条件渲染切 tab 时，在 @Entry 页 onBackPress 里显式处理：详情栈非空交给 Navigation 弹栈；在非起始 tab 上切回起始 tab 并返回 true；已在起始 tab 才交系统默认处理。
3. onNewWant 落 tab 前，按源端 flag 决定是否先清空 NavPathStack。
4. 入口分流按“冷启 / 进程回收后重入 / 进程存活时从桌面图标再次拉起 / 从最近任务切回”逐种写验收，结合跳板的 launchMode 与是否改写任务根判断源端重进时是否重跑跳板；需要重跑时在 EntryAbility.onNewWant 经事件通知入口页按同一条件再分流（首启压引导，否则回主页并清掉其上的页面）。

## 可选检查

- 有设备时，各非起始 tab 按一次系统返回应回到起始 tab；打开详情后从外部入口深链进来，返回不应再出现该详情页；游戏等内页中按 Home 再点桌面图标，两端都回主页，从最近任务切回则保持原页。
