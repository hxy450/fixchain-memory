# 底部 tab 的 popUpTo(start){saveState} 与外部入口的 CLEAR_TOP 要拆出返回栈后果写成验收，并在 onBackPress、onNewWant 显式实现

ID：`lesson-39f137ee173e50363f79` · 版本：1

[本主题](index.md)

## 何时使用

规格提取阶段描述底部 tab 切换和外部深链入口，以及实现阶段核对导航壳差异时

## 适用情境

源端 tab 切换用 navigate { popUpTo(startDestination){ saveState }; launchSingleTop; restoreState }，桌面卡片、通知等外部入口用带 FLAG_ACTIVITY_CLEAR_TOP/NEW_TASK 的 Intent 拉起主 Activity；目标端用单 Navigation 加下标或条件渲染切 tab，NavPathStack 承载详情页。

## 原因

popUpTo(start) 同时决定 tab 状态保存和“非起始 tab 上按返回先回起始 tab”；CLEAR_TOP 决定热启动时清掉压在上面的页面。规格只写“状态保留”“落到某 tab”时，目标端下标切 tab 又没有 tab 返回栈，返回键直接退出、深链落在旧详情页下面。

## 做法

1. 规格把每个导航调用拆成“返回栈后果”和“状态保存”两类验收项；每个 Intent flag 写出可观察后果或明确登记豁免；源码注释里描述的返回行为原样转成验收项。
2. 下标或条件渲染切 tab 时，在 @Entry 页 onBackPress 里显式处理：详情栈非空交给 Navigation 弹栈；在非起始 tab 上切回起始 tab 并返回 true；已在起始 tab 才交系统默认处理。
3. onNewWant 落 tab 前，按源端 flag 决定是否先清空 NavPathStack。

## 可选检查

- 有设备时，各非起始 tab 按一次系统返回应回到起始 tab；打开详情后从外部入口深链进来，返回不应再出现该详情页。
