# 底部 tab 以 popUpTo(起始){saveState} 切换、目标按下标切 tab 时，在 onBackPress 让非起始 tab 先回起始 tab

ID：`lesson-39f137ee173e50363f79` · 版本：3

[本主题](index.md)

## 何时使用

规格提取阶段描述底部 tab 切换的返回与状态保留时；入口装配与实现阶段核对导航壳差异、为下标或条件渲染的 tab 壳接系统返回时

## 适用情境

源端 tab 切换用 navigate(route) { popUpTo(startDestination){ saveState = true }; launchSingleTop = true; restoreState = true }；目标用单 Navigation 加下标或条件渲染切 tab，NavPathStack 只承载详情页，规格可能只把它写成“切回 tab 时状态保留”。

## 例外与边界

- 源端 tab 切换不带 popUpTo(startDestination)（各 tab 依次压栈，或另有 BackHandler 处理返回）时，按源端实际返回栈实现

## 原因

popUpTo(start) 同时决定 tab 状态保存和“非起始 tab 上按返回先回起始 tab”；规格只写“状态保留”时，目标按下标切 tab 又没有 tab 返回栈，在非起始 tab 按返回会直接退出应用。

## 做法

1. 规格把每个导航调用拆成“返回栈后果”和“状态保存”两类验收项：至少写“非起始 tab 按系统返回回到起始 tab（tab 状态不重置）、起始 tab 上按返回才退出”，另写一条切回 tab 状态保留；源码注释里描述的返回行为原样转成验收项。
2. 在 @Entry 页 onBackPress 里显式处理：详情栈非空时由 Navigation 弹栈（此时返回先交栈顶 NavDestination）；在非起始 tab 上切回起始 tab 并返回 true；已在起始 tab 才交系统默认处理；外部入口带 CLEAR_TOP 的热启动清栈另按 onNewWant 清栈的经验处理。

## 可选检查

- 有设备时，各非起始 tab 按一次系统返回应回到起始 tab，起始 tab 上再按返回才退出。
