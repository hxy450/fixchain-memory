# NavHost 起点是会重组作用域里每次求值、会话内会变的表达式时，起点一变就换图清栈并以新起点重进：目标在等价时机重算起点，不冻结首压

ID：`lesson-43459cb01320674b2864` · 版本：1

[本主题](index.md)

## 何时使用

规格提取与导航壳实现阶段，把 Compose NavHost 的 startDestination 映射成目标的首屏压栈和顶级切换回退基准，或推演会话内返回栈时

## 适用情境

源端 NavHost(startDestination = 读偏好或状态的函数) 写在会重组的壳层内容 lambda 里（抽屉、Rail、常驻抽屉），没有 remember，读到的标记在同一会话内会变（完成引导、登录）；目标用单个 Navigation + NavPathStack，首屏在空栈时压入，顶级切换以起点为 popTo 基准。

## 例外与边界

- 起点表达式被 remember 固定，或读到的状态在会话内不会变化时，一次压栈即可

## 原因

起点表达式随每次重组重新求值；值变化后，宿主下一次重组（如打开抽屉）时 NavHost 换图、清空整个返回栈，并以新起点和新实例重新进入，popUpTo(graph.findStartDestination()) 的基准也随之改变。把起点翻成“栈空时只压一次”的首屏，或把首压时的起点冻结进顶级导航器，起点变化后返回栈就与源端不同（如返回落回已完成的引导页）。这一行为依据源设备上的可观察结果，未逐行核对 navigation-compose 实现。

## 做法

1. 规格看到 NavHost(startDestination = 表达式) 写在壳层内容 lambda 里时，先判断表达式读的状态在会话内会不会变；会变就写成验收：哪些重组会触发重算（打开抽屉、配置变化、订阅的状态变化），起点变化后清空返回栈、以新起点和新实例重进，以起点为基准的顶级切换随之改变。推演返回栈时不假设图的起点在整场会话里不变。
2. 实现导航壳时把起点做成可重算的值，在源端重组的等价时机（如抽屉打开、顶级切换入口）重算；变化时 clear 返回栈后以新起点压栈，并重建以新起点为基准的顶级导航器；起点不变时什么都不做。

## 可选检查

- 对清栈时机有疑问时，在源设备上走一遍“改变起点状态 → 触发壳层重组（如打开抽屉）→ 返回”，对照两端返回栈。
