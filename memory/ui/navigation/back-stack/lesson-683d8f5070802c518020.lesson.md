# 源端对同一次成功有多条导航响应时，目标只保留一个导航出口，并按净效果定义返回栈

ID：`lesson-683d8f5070802c518020` · 版本：2

[本主题](index.md)

## 何时使用

规格提取与接线阶段，把源页面对同一业务结果的多条响应（事件订阅里 finish、成功回调里 startActivity）翻译成目标 NavPathStack 操作时

## 适用情境

源 Activity 对同一次成功既在全局事件订阅里关闭本页，又在回调里启动主页（可能带 FLAG_ACTIVITY_NEW_TASK）；全局管理器在回调前发布成功事件；目标由单一 NavPathStack 管理页面，Navigation 根内容可能是启动页。

## 原因

Android 中 finish() 只结束当前 Activity，与启动主页互不抵消；目标端两条响应操作同一个栈，效果会叠加：连续两次出栈把主页也弹掉，露出栈底的启动页。只修其中一条（如把 clear+push 改成 pop）时另一条仍在，症状不变。来源中规格把两条响应拆成两条独立验收，实现者照写。

## 做法

1. 先列出源页面对同一结果的全部响应（事件订阅、回调、结果回传），标明是否由同一次成功触发，再为目标定义唯一导航出口。
2. 写出合并后的“操作前栈 → 操作后栈”，例如 [主页, 登录页] → [主页]，并写主页不在栈中时的替换兜底；根内容是启动页时，不用 clear() 表达“回主页”。
3. 接线成功导航前，查本页与服务层是否还有全局成功事件的订阅会操作导航栈；有就只保留一个出口，并把与规格的冲突回写规格。
