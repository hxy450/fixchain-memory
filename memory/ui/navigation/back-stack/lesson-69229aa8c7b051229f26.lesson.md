# 源端用 handleDeepLink 处理外部拉起的深链时，目标清空 NavPathStack 并按导航图合成返回栈，不在当前栈上 push

ID：`lesson-69229aa8c7b051229f26` · 版本：3

[本主题](index.md)

## 何时使用

规格提取与入口接线阶段，把源端 handleDeepLink/navDeepLink 迁成 want 解析后的导航动作、决定打开深链后的返回栈时

## 适用情境

源 Activity 在 onCreate、onNewIntent 或 LaunchedEffect(intent) 中调用 navController.handleDeepLink(intent)，目的地以 navDeepLink(uriPattern) 注册；外部链接经 VIEW intent 以新任务（FLAG_ACTIVITY_NEW_TASK）拉起宿主。目标由 UIAbility 的 onCreate/onNewWant 解析 want.uri 后操作 Navigation 的 NavPathStack；规格可能写成“在当前栈上 pushPathByName、目标已在栈顶则只更新参数”。

## 例外与边界

- intent 不带 FLAG_ACTIVITY_NEW_TASK 时 handleDeepLink 不合成起始页：以 popUpTo(图根, inclusive) 只留下目标一页，返回即离开该 Activity、回到发起方（navigation-runtime 2.9.8 NavController.handleDeepLink）；目标按这一栈形另定，不套用本条的合成
- Navigation 根内容是启动页等不在源端栈中的页面时，clear() 会露出它：clear 后先 push 源端起始页再 push 目标

## 原因

handleDeepLink 处理新任务拉起的意图时，先清空当前返回栈，再按导航图从各级起始目的地导航到目标；这层语义在源码里只体现为一行调用。规格写成在当前栈上 push 时，从任意页面（如设置页）收到深链后按返回会回到拉起前停留的页面，而不是起始页。该语义属框架隐含行为，按 API 公开语义归因，未做源端设备复现。

## 做法

1. 规格写深链时同时写返回栈语义：外部拉起（带 NEW_TASK）时清栈，按导航图父链合成——各级嵌套图的起始目的地依次入栈，再入目标；目标本身就是某级起始目的地时不重复入栈。以“停在其他页时收到深链，打开后按返回回到起始页”作为验收项。
2. 实现时在消费待处理 want 的位置先 navPathStack.clear()；起始页以 NavDestination 压栈承载时先 push 起始页（及各级嵌套起始页），再 push 目标页（参数按 uriPattern 解析），合成过程关闭转场动画（如 pushPathByName 的 animated 参数传 false）；起始页是 Navigation 根内容时 clear 后不再 push 它。冷启动与热启动（onNewWant）走同一个合成函数。
