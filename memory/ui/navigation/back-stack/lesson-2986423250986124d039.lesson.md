# 源端经 TaskStackBuilder 父栈跳转时，按 Manifest 父链清栈重建返回栈，返回落到父页而非来源页

ID：`lesson-2986423250986124d039` · 版本：2

[本主题](index.md)

## 何时使用

规格提取与基座实现阶段，把基类的父栈跳转方法（抽屉导航等）翻译成 NavPathStack 操作与返回验收时

## 适用情境

源基类被多个页面继承，抽屉等跳转经 TaskStackBuilder 发起，Manifest 为目标声明 parentActivityName 或 PARENT_ACTIVITY；目标是单个 Navigation + NavPathStack，跳转可从栈底以外的任意宿主页发起；页面规格里可能有“pushPathByName（主页为根天然在栈底）”一类只在来源页是主页时成立的映射。

## 例外与边界

- 父链上某一级就是 Navigation 根内容（不在 NavPathStack 中）时，clear 后不再 push 它，只 push 其余父页与目标；根内容是启动页等不在父链中的页时，clear 会露出它，要先 push 父链根页

## 原因

startActivities 以新任务按父链重建任务，从任一页跳转后都是 [Manifest 父链…, 目标]；写成在当前栈上 push，从非根页跳转后返回会落回来源页，栈也越积越深。只在父链根页上验证时两者看不出差别。

## 做法

1. 规格按 Manifest 父链（parentActivityName 或 PARENT_ACTIVITY 逐级上溯，不预设只有主页一级）写出跳转后的完整栈与返回落点；实现映射写成 clear → 依次 pushPathByName 不由 Navigation 根内容承载的父页 → pushPathByName 目标（转场按源端设置），不写“带回栈、返回落回来源页”。
2. 把页面规格里的映射行复用到被多个宿主调用的基类方法前，核对该行成立的前提；验收用从非根页发起的样例（如从设置页经抽屉进入帮助页，返回应到父链上一级，再返回按根页的返回语义处理）。
