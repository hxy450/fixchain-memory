# 被 @Entry 页直接组合的子组件要拦截返回键时，由 @Entry 页的 onBackPress 转调子组件注册的处理函数

ID：`lesson-803ba029eea852122e77` · 版本：2

[本主题](index.md)

## 何时使用

页面转换与接线阶段，为源端非根 Composable 里的 BackHandler/PredictiveBackHandler 选择 ArkUI 返回键钩子时

## 适用情境

源端在抽屉宿主等非 Activity 根的 Composable 中按状态条件拦截返回（例如抽屉打开时先关抽屉）；目标端该组件不是 @Entry，由唯一的 @Entry 页直接组合，没有作为页面驻留在 Navigation 路由栈内。

## 例外与边界

- 组件本身就是 @Entry 页时，直接实现 onBackPress
- 组件作为 NavDestination 驻留在 Navigation 栈内时，返回由 NavDestination.onBackPressed 处理；来源实测只覆盖被直接组合、未入栈的情况

## 原因

SDK 的 onBackPress 注释写明只对 @Entry 装饰的自定义组件回调，子组件自己实现的 onBackPress 不会触发。来源工程的子组件把同一逻辑另挂到自身 NavDestination.onBackPressed，但该节点被 @Entry 页直接组合、不在 Navigation 栈内，设备实测（API 12 模拟器）也不回调，抽屉打开时按返回直接回到桌面。编译、结构审计与静态判定全部通过，只有设备上按返回键才暴露。

## 做法

1. 先确认子组件的挂载形态：被 @Entry 页直接组合，还是 NavPathStack 中的页面。
2. 直接组合时，子组件在 aboutToAppear 经回调参数（@ComponentV2 用 @Event）把 () => boolean 的裁决函数交给 @Entry 页，aboutToDisappear 交回 null；@Entry 页的 onBackPress() 有函数就返回其结果，没有就返回 false 交系统默认处理。

## 可选检查

- 能上设备时：状态打开（如抽屉展开）按 Back，状态关闭且应用留在前台；关闭态按 Back 仍按源端行为退出。
