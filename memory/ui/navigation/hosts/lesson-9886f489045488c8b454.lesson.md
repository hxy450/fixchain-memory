# Activity 切换转场按源端迁移：overridePendingTransition(0,0) 时各进入路由关闭，未调用时按主题默认窗口动画写转场

ID：`lesson-9886f489045488c8b454` · 版本：4

[本主题](index.md)

## 何时使用

规格提取阶段写页面规格与路由契约、决定页面切换动画时；实现阶段写 pushPathByName/replacePathByName 或 router.pushUrl 页的 pageTransition 时

## 适用情境

源 Activity 或所继承的基类在 onCreate 调 overridePendingTransition(0,0)；目标用 Navigation 的 push/replace 进入该页，进入路径不止一条，规格可能只把转场禁用挂在抽屉基座等某一条路径上。也包括多个 Activity 只用 startActivity/finish 切换，源码没有 overridePendingTransition、styles 也没覆盖 windowAnimationStyle，目标 @Entry 页或 NavDestination 没有转场设置。

## 例外与边界

- 目的地以复用实例进入（singleTop、CLEAR_TOP 回到已有实例，只走 onNewIntent）时不执行 onCreate，该路径不受此约束

## 原因

“进入无转场”是目的地页的属性；把它当成某个基座的横切行为时，规格只在一条路径上关闭转场，按钮跳转、引导完成、启动分流等其余进入路径仍按默认动画进入。反过来，源端没调用 overridePendingTransition 时切换仍有动画，由主题窗口动画决定；鸿蒙 router 页不写 pageTransition、Navigation 不配自定义转场时用系统默认横滑，与源端不等价。

## 做法

1. 对每个目的地 Activity 同时查它及所继承基类的 onCreate（grep overridePendingTransition 与 extends）和主题 windowAnimationStyle。调用 (0,0) 时，把“进入无转场”写进该页页面规格，并在所有进入该页的路由契约里写 animated=false（或让目的地统一关闭系统转场）。
2. 没有调用、主题也没覆盖时，结论是“平台默认 Activity 动画”，不是“无转场”：沿主题 parent 链（含 values-v11、values-v14 等限定目录）找到 windowAnimationStyle，按参照机 API 从 SDK platforms/android-<API>/data/res 的 anim/activity_{open,close}_{enter,exit}.xml 读参数（随系统版本变化，例：本机 android-30 为缩放加淡入，android-34 为横移加淡入），写成目标页在 Push/Pop × Enter/Exit 下的转场（ets/component/page_transition.d.ts 的 PageTransitionEnter/Exit，或 Navigation 自定义转场）；查不到目标值就回报规格缺口，不保留目标默认横滑。
3. 实现时与工程已有路由保持一致：规格只给两参伪代码时，不据此省略第三参数。
