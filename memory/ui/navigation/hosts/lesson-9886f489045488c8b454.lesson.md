# 源 Activity 或其基类 onCreate 调 overridePendingTransition(0,0) 时，“进入无转场”是目的地页的属性：进入该页的每条路由（按钮跳转、引导完成、启动分流、抽屉）都关闭转场；未调用时按主题默认窗口动画写目标转场，不留目标默认横滑

ID：`lesson-9886f489045488c8b454` · 版本：2

[本主题](index.md)

## 何时使用

规格提取阶段写页面规格与路由契约时；实现阶段写 pushPathByName/replacePathByName 时；规格提取阶段把 startActivity/finish 映射为路由契约、决定页面切换动画时

## 适用情境

源 Activity 或所继承的基类在 onCreate 调 overridePendingTransition(0,0)；目标用 Navigation 的 push/replace 进入该页，进入路径不止一条，规格可能只把转场禁用挂在抽屉基座等某一条路径上。 也包括源端多个 Activity 用 startActivity 线性跳转、按返回 finish，源码没有 overridePendingTransition，styles 也没覆盖 windowAnimationStyle；目标 router.pushUrl 的 @Entry 页或 Navigation 页未写转场，系统默认横向滑入滑出。

## 原因

把目的地属性当成某个基座的横切行为，其余路径按默认动画进入（来源中按钮进游戏页、教程完成进主菜单都出现滑入）。 没调用 overridePendingTransition 时，Activity 切换仍有动画，由主题 windowAnimationStyle 决定；主题没覆盖时沿 parent 链落到平台 Animation.Activity 的 activity_open_enter、open_exit、close_enter、close_exit（例：Theme.Holo 指向 Animation.Holo.Activity，本机 SDK android-30 values/themes_holo.xml），具体动画随系统版本变化。目标页不写转场时用系统默认横滑，与源端不同；把“没调用”记成“无转场”，各页就都留着目标默认值。

## 做法

1. 对每个目的地 Activity 查它及所继承基类的 onCreate（grep overridePendingTransition 与 extends），把“进入无转场”写进该页页面规格，并在所有进入该页的路由契约里写 animated=false（或让目的地统一关闭系统转场）。 同时查主题 windowAnimationStyle：没有 overridePendingTransition 时，按参照机 API 从 SDK platforms/android-<api>/data/res 沿主题 parent 链（含 values-v11/v14）读窗口动画的四段参数，写成每个目标页 Push/Pop × Enter/Exit 的转场（router 页用 pageTransition 的 PageTransitionEnter/Exit 按 RouteType 分支，见 ets/component/page_transition.d.ts）；导航图的转场字段写“平台默认（主题名）”，不写 none；查不到目标值时作为规格缺口回报，不保留目标默认横滑。
2. 实现时与工程已有路由保持一致：规格只给两参伪代码时，不据此省略第三参数。
