# 导航目的地内的 ON_STOP/ON_RESUME 观察者按返回栈条目生命周期接 onHidden/onShown，不窄化为退后台

ID：`lesson-19dd006e049c3f9d7563` · 版本：4

[本主题](index.md)

## 何时使用

规格提取阶段翻译 LifecycleEventObserver 的 ON_STOP/ON_RESUME 触发契约时；页面实现阶段把引擎或服务暴露的 onStop/onResume 一类入口接到 NavDestination 生命周期时

## 适用情境

源 Composable 用 DisposableEffect(LocalLifecycleOwner.current) 注册 LifecycleEventObserver，ON_STOP 时移交后台服务、暂停或保存，ON_RESUME 时取回；该 Composable 位于 navigation-compose 的目的地内。目标页面是 NavDestination，引擎是普通类，需由页面在 onShown/onHidden/aboutToDisappear 中显式调用入口；规格可能把触发写成“退后台/前后台切换”。

## 例外与边界

- 观察者挂在 ProcessLifecycleOwner 上：只对应应用前后台，按 Ability 前后台回调接线
- 观察者挂在 Activity 上：除应用前后台外，被其他 Activity 覆盖、配置变更重建时也会 ON_STOP（Activity.java 的 onStop 说明），按 Ability 前后台回调加页面覆盖情形接线
- 源端的存档写在 Activity 的 onPause/onSaveInstanceState 而不是 Compose 观察者里：按存档触发点逐个映射，不在 aboutToDisappear 存档

## 原因

目的地内的 LocalLifecycleOwner 是该页的 NavBackStackEntry：退后台、跳到其他目的地、返回出栈都会让它进入 ON_STOP，回到本页进入 ON_RESUME。把触发写成“退后台”，目标只接应用前后台或完全不接，导航离开时正在运行的任务会随页面销毁丢失，或在隐藏页里继续运行而不移交。navigation-compose 2.9.1 中出栈时 ON_STOP 先于观察者注销，所以出栈也会执行移交。

## 做法

1. 规格提取时先确认 owner 是谁（Activity、进程、NavBackStackEntry），把会让它进入 ON_STOP/ON_RESUME 的用户路径逐条写成触发契约与验收：退后台、返回出栈、跳到其他目的地、回到本页。本页被对话框或浮动类目的地覆盖时是否进入 ON_STOP 来源未观察：遇到时查所用 androidx.navigation 版本对浮动目的地下层条目的生命周期处理，再单独写明。
2. 实现时把 ON_STOP 映射到 NavDestination.onHidden 的各类原因（被新页覆盖、出栈转场、应用退后台），ON_RESUME 映射到 onShown；目标用 NavDestinationMode.DIALOG 承载的目的地进出栈不影响下层页生命周期（nav_destination.d.ts，API 12），按上一步核对的源端行为决定是否另补停止处理。
3. 离开路径要销毁引擎时（出栈、aboutToDisappear），只补调幂等的停止或移交入口，收掉仍在运行、尚未经 onHidden 处理的任务，再 dispose。
4. 引擎把生命周期回调暴露为公开入口时，在页面规格与派工里写明各入口的调用位；本任务接不上就登记带负责方的移交项，不只写在代码注释里。

## 可选检查

- 对接线有疑问时，检索引擎每个公开生命周期入口都有调用方，并走一遍“运行中返回上一页”“运行中进入其他页”“运行中退后台再回来”三条路径。
