# 源端只在 onPause、onSaveInstanceState 存档时，目标接 onHidden，不在 aboutToDisappear 存档或计时

ID：`lesson-33e61b21f6981abc40d2` · 版本：2

[本主题](index.md)

## 何时使用

规格提取与页面实现阶段，把源 Activity 的存档、计时、统计调用点映射到 NavDestination 回调（onHidden、onBackPressed、aboutToDisappear）时

## 适用情境

源 Activity 只在 onPause、onBackPressed、onSaveInstanceState、Up 调用存档，onDestroy 不存档；存档有非幂等副作用（按 now − startingTime 累计时长、写统计）。目标页是 Navigation 下的 NavDestination，可能在隐藏（退后台）很久之后才被清栈销毁（桌面图标重进、popToIndex、replace）。

## 例外与边界

- 源端在 onDestroy 或 finish 路径里也做同一存档：此时 aboutToDisappear 才是对应的存档钩子

## 原因

aboutToDisappear 对应组件销毁，不对应 onPause 或 onSaveInstanceState；页面隐藏后可能很久才被销毁，在 aboutToDisappear 再存一次会把隐藏期间的时间计入累计时长，或多写一条统计。“多调一次无害”只在几个回调紧接着触发时成立。

## 做法

1. 逐个映射源端存档触发点：onPause → NavDestination.onHidden（退后台、被覆盖）；onBackPressed → onBackPressed；onSaveInstanceState → 退后台的 onHidden 与配置变化回调（Ability.onConfigurationUpdate 或 EnvironmentCallback.onConfigurationUpdated）；Up → 标题栏返回。同时写出源端不存档的回调（通常是 onDestroy）。
2. 给存档、计时、计数这类非幂等方法加调用位前，先在源码找同一时机的调用，源端没有就不加；判断“多调一次无害”时，按“页面已隐藏、很久以后才被销毁”的路径推演，不只看返回出栈时几个回调连续触发的情况。
3. 已写的 aboutToDisappear 逐个对照源 Activity 的 onDestroy，源端 onDestroy 不做的副作用删掉。

## 可选检查

- 对累计时长有疑问时，走一遍“开始计时 → 退后台 → 等待 → 桌面图标重进 → 查看统计”，确认累计值与源端一致。
