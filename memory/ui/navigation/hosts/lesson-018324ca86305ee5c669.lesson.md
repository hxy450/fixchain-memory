# SideBarContainer 承接源端抽屉、源端无悬浮切换钮时显式写 showControlButton(false)：默认内置按钮会盖住左上角返回键

ID：`lesson-018324ca86305ee5c669` · 版本：1

[本主题](index.md)

## 何时使用

界面实现阶段，把源端模态抽屉（Compose ModalNavigationDrawer、DrawerLayout）映射为 ArkUI SideBarContainer 并编写其属性链时；规格提取阶段写抽屉转换决策时

## 适用情境

源端抽屉只经页内导航图标回调（openDrawer、汉堡键）或边缘手势打开，内容之上没有常驻的切换按钮；目标用 SideBarContainer（常见 Overlay 类型）包住 Navigation 等内容宿主，被包裹页面在左上角有返回键或菜单键。

## 例外与边界

- 源端确有常驻在内容之上的抽屉切换按钮时，保留内置按钮，并按源端位置与图标设置 controlButton 样式

## 原因

SideBarContainer 的 showControlButton 默认为 true（SideBarContainer 官方组件参考，修复会话 2026-09-29 查阅；来源案例在 HarmonyOS 5.1.1/API 19 模拟器上未设置该属性时渲染出内置按钮）。这个按钮浮在容器左上角、层级高于内容页，盖住同位置的返回键，点击被它接走去开合侧栏；源端没有这个按钮，编译和静态检查都看不出，只有点击才暴露。只设置 showSideBar、sideBarWidth、onChange 不会关掉它。

## 做法

1. 写 SideBarContainer 前列出源端抽屉的全部打开入口（页内导航图标回调、边缘手势、代码调用）；内容之上没有常驻切换按钮时，在属性链里显式写 .showControlButton(false)，开合交给 showSideBar 绑定的状态和页内菜单键，不依赖默认值。
2. 规格把模态抽屉映射为 SideBarContainer 时，在转换决策里写明抽屉的触发入口和是否保留内置控制按钮，让实现者直接落实。

## 可选检查

- 能上设备时，在会被抽屉包住的二级页点左上角返回键：应出栈而不是打开侧栏；布局 dump 中 SideBarContainer 的直接子节点不应有内置 Button 叠在返回键上。
