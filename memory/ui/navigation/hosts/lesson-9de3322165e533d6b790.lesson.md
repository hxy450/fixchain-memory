# NavHost 的 enter/exit/popEnter/popExit 自定义转场迁到 Navigation：用 customNavContentTransition 驱动，各 NavDestination 把位移、透明度与缩放绑定到共享转场状态

ID：`lesson-9de3322165e533d6b790` · 版本：1

[本主题](index.md)

## 何时使用

规格提取、计划派工与界面实现阶段，把 Compose NavHost（或目的地）上的 enterTransition/exitTransition/popEnterTransition/popExitTransition 落到 ArkUI Navigation 时

## 适用情境

源端 NavHost 定义四向自定义转场（scaleIn/scaleOut、slideIn/slideOut、tween 时长与延迟等）；目标为 Navigation + NavDestination，在已观察的 API 中 customNavContentTransition 回调拿到的 NavContentInfo 不提供页面的 opacity、translate 属性；规格或派工可能写“customNavContentTransition 或默认转场”二选一，验收只核转场常量是否与源相等。

## 例外与边界

- 决策记录以编号批准采用系统默认转场，并写明差异

## 原因

转场参数只有被 Navigation 回调与页面属性消费才产生效果。规格留出“默认转场近似”分支、验收只比对常量、计划又不给页面绑定的写权时，实现者会留下无人使用的常量类，页面仍是系统默认转场，所有检查照样通过。

## 做法

1. Navigation 设 customNavContentTransition，按 NavigationOperation 区分：PUSH 时 to 页走源 enter、from 页走源 exit，POP 时 to 页走 popEnter、from 页走 popExit；在返回的 NavigationAnimatedTransition 的 transition 回调里用 animateTo 改变共享转场状态，结束后调用 finishTransition。
2. 每个 NavDestination 的根节点把 translate、opacity、scale 绑定到按页面区分的共享 @ObservedV2 转场状态，时长、延迟、缩放比与位移量取源端定义。
3. 规格把各页面的绑定写成对接义务，验收检查 Navigation 已设置回调且页面消费状态，不只核常量；计划与派工把这些页面的绑定改动列入写入范围，不写“定制或默认”二选一；为对齐源端定义的转场常量必须能指出消费点。
