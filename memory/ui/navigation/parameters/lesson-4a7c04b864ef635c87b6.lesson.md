# 路由参数以接收端契约为准：接收方不读取或写死的 extra 不透传，也不在目标页新增对它的消费

ID：`lesson-4a7c04b864ef635c87b6` · 版本：3

[本主题](index.md)

## 何时使用

功能接线阶段，为跨页跳转构造目标页参数、决定哪些发起页状态要带过去时；为目标页新增入参消费或入页自动动作时

## 适用情境

源发起页用 putExtra 传一个开关（如显隐标签），但接收 Activity 不读取该 extra，或创建 Fragment 时写死该参数；目标页参数类已用默认值与注释标明该字段由接收端固定。也包括多个调用方 putExtra 一个看似有含义的开关（如“显示一键登录弹窗”），接收 Activity 从不读取；目标页准备在 onReady 读取该参数并触发自动动作。

## 原因

发起端的 putExtra 只说明“传了”，不说明“被用了”；把发起页状态照搬进参数会覆盖接收端的固定值，出现源端没有的控件。前向占位里的“携带参数”也常按发起端写。来源中接线者两次读到目标参数类“Activity 固定传 false”的注释，仍用发起页的 true 赋值。另一应用的接线者只查到调用方传参，没有核对接收方是否读取，就在登录页 onReady 按参数名新增入页自动一键登录；协议未勾选时带参进入即弹协议框、无参进入不弹，UI 测试设计又把这一行为固化为验收。

## 做法

1. 构造参数前读目标参数类每个字段的注释和默认值；字段注明由接收端固定时，发起端不赋值或写该固定值。
2. 迁移 startActivity + putExtra 时，逐个 extra 到接收 Activity 查 getXxxExtra 是否消费、是否在创建 Fragment 时被写死；只迁移被消费的 extra。
3. 占位登记里的“携带参数”当作发起端线索，接线时与接收端契约核对，冲突以接收端为准。
4. 为目标页新增入参消费或入页自动动作前，先在源端接收方确认是否读取该 extra 及读取后的行为；接收方不读的参数迁移后忽略，不按参数名推断语义。

## 可选检查

- 对同一页面分别以带参与无参入口进入，首屏一致且没有源端不存在的自动弹窗。
