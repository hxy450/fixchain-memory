# 路由参数以接收端契约为准：接收方不读取或写死的 extra 不透传，也不在目标页新增对它的消费

ID：`lesson-4a7c04b864ef635c87b6` · 版本：4

[本主题](index.md)

## 何时使用

功能接线阶段，为跨页跳转构造目标页参数、决定哪些发起页状态要带过去时；为目标页新增入参消费或入页自动动作时

## 适用情境

源发起页用 putExtra 传一个开关（如显隐标签），但接收 Activity 不读取该 extra，或创建 Fragment 时写死该参数；目标页参数类已用默认值与注释标明该字段由接收端固定。也包括多个调用方 putExtra 一个看似有含义的开关（如“显示一键登录弹窗”），接收 Activity 从不读取；目标页准备在 onReady 读取该参数并触发自动动作。

## 原因

发起端的 putExtra 只说明“传了”，不说明“被用了”；把发起页状态照搬进参数会覆盖接收端的固定值，出现源端没有的控件；按参数名推断语义新增的入页动作，会让带参与无参入口表现不同。目标参数类的注释与前向占位也是迁移产物，可能沿用了发起端的写法。

## 做法

1. 构造参数前以源接收端为准确认每个 extra 的实际消费：沿接收 Activity 及其基类、封装读取与 Fragment 转交查 getXxxExtra 是否读取、是否在创建 Fragment 时被写死；目标参数类的注释与默认值只作线索，与源码冲突时改注释。
2. 只迁移被消费的 extra；字段由接收端固定时，发起端不赋值或写该固定值。
3. 占位登记里的“携带参数”当作发起端线索，接线时与接收端契约核对，冲突以源接收端为准。
4. 为目标页新增入参消费或入页自动动作前，先在源端接收方确认是否读取该 extra 及读取后的行为；接收方不读的参数迁移后忽略，不按参数名推断语义。

## 可选检查

- 对同一页面分别以带参与无参入口进入，首屏一致且没有源端不存在的自动弹窗。
