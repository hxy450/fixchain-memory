# 经 router.pushUrl 进入的 @Entry 页在 aboutToAppear 用 router.getParams() 读取必填入参，不声明等待外部赋值的普通字段

ID：`lesson-0d7d6e7302f8c8c77c66` · 版本：2

[本主题](index.md)

## 何时使用

页面实现阶段，编写由 router.pushUrl 打开、需要入参（如详情 id）的 @Entry 页面时；给页面补 @Entry 或登记路由时

## 适用情境

源端 Fragment 经 Navigation Component 进入，nav_graph 声明必填 <argument>，Fragment 用 requireArguments()/navArgs 读取；目标页登记在 main_pages.json、以 @Entry 页面经 router.pushUrl({ url, params }) 打开。

## 例外与边界

- 目标页作为 NavDestination 经 NavPathStack 进入：从 NavPathStack 的参数取值
- 该 struct 是被父组件实例化的子组件：入参由父组件构造时传入

## 原因

@Entry 页由路由框架创建，没有调用方会给普通成员字段赋值；把 id 写成默认空串的字段并以它为加载门控，页面永远取不到 id，只显示“不存在”。来源中实现者看得到深链 {tripId} 与“从首页进入详情”，仍这样写；该页随后被登记为路由页并补 @Entry，进入路径上就只剩 router 传参。

## 做法

1. 在 aboutToAppear 读取 router.getParams()，按发送端 params 的键名（如 tripId）取值并校验必填，存在后再加载；缺失时进入错误态。
2. 给页面补 @Entry 或登记路由时同步检查入参：源端 requireArguments/navArgs 读取的每个参数在目标都有取参代码，键名与发送端 pushUrl 的 params 一致。
