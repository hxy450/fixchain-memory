# 源端跳转前写入的共享状态（如播放队列）是跳转契约的一部分，按原顺序迁移

ID：`lesson-dfcdbb19cd93d29159b2` · 版本：2

[本主题](index.md)

## 何时使用

功能接线阶段，把列表项点击 → 启动目标页的链路迁成目标导航调用时；路由核验阶段比对跳转一致性时

## 适用情境

源端点击处理在 startActivity 之前先把当前列表（过滤后）交给共享播放器或仓库（如 setPlaylist(list, position, true)），目标页只显示共享状态；目标跳转参数只带 id 一类字段。

## 原因

跳转参数不是完整契约：目标页若从共享引擎读取当前项和队列，调用方漏掉交接时，目标页显示的是上一次残留的状态（错曲、错列表）。把这一步归给“别的功能域”或假定目标页会按参数自行加载时最容易漏。

## 做法

1. 把源端 startActivity 之前的每个副作用逐条列出，在目标端 push 之前按同一顺序落地。
2. 想把某一步归给其他模块、或假定目标页按参数自行加载时，先打开目标页与共享引擎确认数据来源。
3. 路由核验比对一致性时，除目标页与参数外，还要比对跳转前的状态写入。
