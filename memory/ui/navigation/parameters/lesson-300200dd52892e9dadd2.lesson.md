# Compose 带参路由迁到 NavPathStack 时，目的地名用固定名、参数只走 param，pageMap 按固定名精确匹配

ID：`lesson-300200dd52892e9dadd2` · 版本：2

[本主题](index.md)

## 何时使用

界面转换与导航壳实现阶段，写 pushPathByName 与 navDestination 分发时

## 适用情境

源端 Compose Navigation 以带占位符的路由模式（如 detail/{id}）注册目的地，并用拼串函数生成实际路由；目标用 Navigation + NavPathStack，由 pageMap 按目的地名分发。

## 原因

把拼串照搬成目的地名，同一个 id 既进名字又进 param，名字不再是稳定标识；分发端只好用 startsWith 迁就，静态路由对账也解析不出这些目的地。来源中转换者读过导航 skill 的“固定名 + param”和验收判定组里的固定名，仍照搬源端拼串；接手者沿用并扩大到其他页和深链入口。

## 做法

1. 从路由模式里拆出 {参数}：目的地名取固定名常量，参数经 pushPathByName 的第二个参数传；目标页从 NavDestinationContext 的 pathInfo.param 取值。
2. pageMap 只按固定名精确匹配；调用方传动态名时改调用方，不写前缀分发，路由常量类也不保留拼串构造函数。
3. 写完 grep 每个 pushPathByName 的首参，出现模板字符串或字符串拼接就改成常量。
