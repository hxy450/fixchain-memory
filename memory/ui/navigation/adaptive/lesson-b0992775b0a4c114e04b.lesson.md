# 宽窗列表-详情分栏按当前目的地的 pane 角色进入：只有详情目的地进右侧 pane，同一顶层下 push 的其他页面保持全宽

ID：`lesson-b0992775b0a4c114e04b` · 版本：1

[本主题](index.md)

## 何时使用

应用壳与导航实现阶段，用 Navigation 的 Split/Stack 模式或自绘双栏模拟源端宽窗列表-详情布局，确定何时进入分栏、哪些页面进入详情 pane 时

## 适用情境

源端用 ListDetailSceneStrategy、ListDetailPaneScaffold 等列表-详情布局，各目的地带 pane 元数据（listPane、detailPane 或没有元数据）；目标在单个 Navigation 中按宽度断点切 NavigationMode.Split，列表所在顶层下还能 push 搜索、设置等非详情页。

## 原因

以所在顶层或宽度单独决定分栏，会把同一顶层下 push 的非详情页塞进详情 pane（列表仍占左侧），或在没有详情时也进入分栏；源端分栏取决于栈顶目的地的 pane 角色，而不是它从哪个顶层打开。仅有列表时源端是否在中等宽度显示“列表+占位”双栏，取决于所用 scaffold directive 的宽度规则，需按源端版本查证。

## 做法

1. 分栏条件取当前栈顶目的地的 pane 角色：源端标 detailPane（或规格路由表标为详情 pane）的目的地才进右侧详情、列表留左侧；没有 pane 元数据的目的地（搜索、设置等）按普通全宽 push，即使它从列表所在顶层打开。
2. 对某个目的地进入哪个 pane 有疑问时，先在源码检索各入口的 pane 元数据（detailPane()/listPane()/无元数据）再定条件，不凭对 scene strategy 的推测接受偏离路由表的行为。
3. 仅有列表、尚未打开详情时：源 listPane 带 detailPlaceholder 或规格要求右侧占位，则在源端会分栏的宽度下保留列表+占位；分栏宽度阈值取源端 directive 的实际规则（查所用 adaptive 库版本的 calculatePaneScaffoldDirective 或工程自定义 directive），不默认等同导航栏切侧轨的断点，查不到时按规格执行并在交接中报告。

## 可选检查

- 逐个列出能在该顶层下打开的目的地，对照路由表确认各自在宽窗下是全宽 push 还是进入详情 pane
