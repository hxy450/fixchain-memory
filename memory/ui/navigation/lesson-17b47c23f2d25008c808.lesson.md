# 把“另起 Activity”的跳转翻成同窗口 push 时补方向隔离：横屏可触发的入口先切到目标页方向，返回后恢复原方向再续做

ID：`lesson-17b47c23f2d25008c808` · 版本：1

[本主题](index.md)

## 何时使用

交互实现阶段，把 Android 启动独立 Activity 的跳转（如登录拦截）翻译成同窗口 Navigation push，且该入口在横屏界面也能触发时

## 适用情境

源端页面可在运行时切横屏（setRequestedOrientation），并在其中调用 startActivity、userService.login 等另起页面；目标用 Navigation 在同一窗口 push，方向由 window.setPreferredOrientation 在窗口级控制，目标页按竖屏设计。

## 原因

Android 的方向按 Activity 隔离，新 Activity 不继承调用页的横屏请求；鸿蒙横屏是对同一窗口的运行时覆盖，push 出来的页面仍在横屏窗口里渲染，返回后也没有恢复逻辑。来源中生成者已把横屏入口列入拦截范围，仍只保留了跳转与回调结构。来源未见 Android 登录页的方向声明，“目标页应为竖屏”依据应用默认竖屏与修复者看到的横屏渲染异常推断。

## 做法

1. 实现跳转前列出入口能在哪些方向触发；当前可能处于运行时横屏而目标页按竖屏设计时，跳转前切到目标页方向，并记录需要恢复的原方向。
2. 在返回回调（如 NavDestination.onShown）中恢复原方向；依赖横屏状态的后续动作（如应用暂存的选择），等窗口尺寸变化确认方向后再执行。

## 可选检查

- 横屏下逐个触发跳转入口，确认目标页方向正确；成功与取消两条返回路径都恢复原方向和暂存动作。
