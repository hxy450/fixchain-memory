# 把“另起 Activity”的跳转翻成同窗口 push 时补方向隔离：横屏可触发的入口先切到目标页方向，返回后恢复原方向再续做

ID：`lesson-17b47c23f2d25008c808` · 版本：3

[本主题](index.md)

## 何时使用

交互实现阶段，把 Android 启动独立 Activity 的跳转（如登录拦截）翻译成同窗口 Navigation push，且该入口在横屏界面也能触发时

## 适用情境

源端页面可在运行时切横屏（setRequestedOrientation），并在其中调用 startActivity、登录拦截等另起页面；被启动 Activity 在 AndroidManifest 有自己的 android:screenOrientation 或未声明；目标用 Navigation 在同一窗口 push，方向由 window.setPreferredOrientation 在窗口级控制。

## 原因

Android 的方向按 Activity 决定：被启动 Activity 声明了具体方向时按自己的声明显示，不受调用页横屏请求影响；未声明（unspecified）时由系统决定，可能沿用下层 Activity 选定的方向或用户偏好（platforms/android-36/data/res/values/attrs_manifest.xml 的 screenOrientation 说明）。鸿蒙横屏是对同一窗口的运行时覆盖，push 出来的页面仍在横屏窗口里渲染，返回后也没有恢复逻辑。

## 做法

1. 实现跳转前列出入口能在哪些方向触发；目标页方向按被启动 Activity 在 AndroidManifest 的 android:screenOrientation 及其 onCreate 中的 setRequestedOrientation 确定。声明了具体方向且与当前窗口不同时，跳转前切到该方向，并记录需要恢复的原方向；未声明时系统可能沿用调用页方向，不强制切换，以参照设备上的实际表现为准，无法实测时在报告写明该未知项及其对目标页布局的影响。
2. 在返回回调（如 NavDestination.onShown）中恢复原方向；依赖横屏状态的后续动作（如应用暂存的选择），等窗口尺寸变化确认方向后再执行。

## 可选检查

- 横屏下逐个触发跳转入口，确认目标页方向正确；成功与取消两条返回路径都恢复原方向和暂存动作。
