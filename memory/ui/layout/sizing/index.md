# ui/layout/sizing

宽高、比例、百分比与边距的组合（父尺寸减边距、占剩余空间，由内容定尺寸的父级里的百分比），Compose 修饰符链顺序与 Row 的测量顺序、固有高度，Material 按钮的布局占位与实绘尺寸，px 域整数布局公式与随进度收放的间距，以及随内容定尺寸的图片、背景和描边，以及非 Row/Column/Flex 父级中 layoutWeight 不生效时的显式尺寸；嵌入满高子组件时的剩余高度分配，居中的 wrap_content 子项组不被拉伸。；换容器（Tabs、Grid 槽位改自绘 Row）后子项的主轴尺寸，TableLayout 按内容测量的列宽

  - 情境：源 Compose Column 里内容区排在搜索栏、分隔线等固定高度节点之后，靠 fillMaxSize、weight 或 Lazy 列表占满剩余高度，可能有空结果、加载、结果等多个状态分支；或 Android 以 MATCH_PARENT 的 PopupWindow showAsDropDown(锚点) 弹出面板，只占锚点以下的高度；或被嵌子组件的源布局根与空态容器都是 wrap_content，在宿主 NestedScrollView 的 wrap_content 槽位里按内容取高。目标准备给内容区或组件根写 height('100%')。
  - 例外：宿主槽位本身已有确定高度（显式数值或已被外层约束定死）时，子树的 '100%' 按该高度解析，可以使用

- [Compose Row 中无 weight 的 fillMaxWidth 子项先占满剩余宽：不换成 layoutWeight(1)，后续兄弟按实得宽判断是否绘制](lesson-45f77b3088fa69398f9e.lesson.md)

  - 情境：有限宽度的 Row 中，无 weight 子项使用 fillMaxWidth()，后面还有兄弟（按钮、文字）；规格或派工可能用“近乎不可见、按源码保留”描述该兄弟，实现者准备把该子项换成 layoutWeight(1)。
  - 例外：fillMaxWidth 带比例、主轴约束无上限或子项使用 weight 时，按当前分配规则处理，不套“占满剩余宽度”。；后续子项含 requiredWidth/requiredSize、无界 wrapContent 或自定义测量/绘制时，零宽约束仍不足以判断实际是否绘制。

- [TableLayout 表格转 ArkUI 时按内容测量列宽：每列宽取该列各行单元格自然宽的最大值，不自拟 fr 比例或权重](lesson-6cb9ad45093ce2ca28af.lesson.md)
  - 时机：规格提取与页面转换阶段，把 Android TableLayout/TableRow 表格（含与滚动区外固定表头对齐的写法）翻译为 ArkUI 列宽时

  - 例外：声明了 android:stretchColumns/shrinkColumns（或 setStretchAllColumns/setShrinkAllColumns）时，自然宽之外的剩余或不足空间按这些列分配；collapseColumns 指定的列不显示；单元格带 layout_span 跨列时，该单元不计入单列自然宽

  - 时机：界面实现阶段，把 match_parent 或两侧约束 0dp 且带同轴 margin 的视图、带 margin 的等权重兄弟（0dp + layout_weight）或 RecyclerView 项偏移翻译成 ArkUI 尺寸与间距时；按要求调整左右边距时

  - 例外：元素要占满的是扣除固定高度兄弟后的剩余区域，或是被宿主嵌入的满高组件时，按宿主有界槽位的规则处理
