# 把 Tabs、Grid 槽位里的子项搬进自绘 Row/Column 时重定主轴尺寸：等分用 layoutWeight(1)，不保留旧槽位的 100% 宽

ID：`lesson-c572346f0be19acf5579` · 版本：2

[本主题](index.md)

## 何时使用

公共组件或页面实现阶段，把 Tabs 内置 tabBar、Grid 等由容器分配槽位的子项改写为自绘 Row/Column + ForEach（如自绘底部导航），确定每个子项的主轴尺寸时

## 适用情境

源端底栏是水平 LinearLayout，子项由代码以 LayoutParams(0, MATCH_PARENT) 与 weight=1 动态添加，布局 XML 里没有静态子项；目标原先用 Tabs BarMode.Fixed 承载页签、页签 builder 写 width('100%')/height('100%')，新组件把该 builder 原样搬进 Row。

## 例外与边界

- 内容 builder 移进 Refresh、Stack 等非 Row/Column/Flex 父级、原本靠 layoutWeight 填满时，按 layoutWeight 失效的规则处理

## 原因

在 Tabs、Grid 的槽位里，子项的 '100%' 按容器分给它的槽位解析；搬进 Row 后每个子项都取父容器全宽，N 项合计 N×100%，后面的项被挤出屏幕。只读容器 XML 看不到子项如何分宽，代码里的 LayoutParams 与 weight 才是依据。

## 做法

1. 换容器时重新确定子项主轴尺寸：源端等分（0dp + weight=1）写 layoutWeight(1)；需要固定宽或按内容宽时按源端 LayoutParams 写，不保留旧容器里的 '100%'。
2. 组件来源写成“XML + 代码”时，同时读代码中动态添加子项的 LayoutParams 与 weight。

## 可选检查

- 写完做算术核对：Row 内 N 个子项的主轴宽度之和不超过父宽
