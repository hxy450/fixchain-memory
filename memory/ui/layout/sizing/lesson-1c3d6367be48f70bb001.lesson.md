# 把靠 layoutWeight 填满并居中的内容移进 Refresh、Stack 等非 Row/Column/Flex 父级时，改用 height('100%') 等显式尺寸

ID：`lesson-1c3d6367be48f70bb001` · 版本：1

[本主题](index.md)

## 何时使用

界面实现阶段，把已有空态、未登录引导等内容 builder 放进下拉刷新组件或其他封装容器的 content 时，确定内容根节点的高度约束

## 适用情境

内容根节点原本在 Column 中用 layoutWeight(1) + justifyContent(Center) 占满剩余空间并居中；新父级是封装了原生 Refresh（或 Stack、Scroll 等）的组件，经 @BuilderParam 注入内容；工程里可能已有同样写法可以照搬。

## 原因

layoutWeight 只在 Row/Column/Flex 父级中参与空间分配；父级换成 Refresh 等容器后属性仍能编译，却不再生效，内容高度缩成自身高度，原本居中的空态贴到顶部。工程里的同构写法可能带着同样的问题，不能当作“能用”的证据。

## 做法

1. 移动 builder 前读封装组件的 build()，确认 content 的直接父组件；父级不是 Row/Column/Flex 时，把根节点的 layoutWeight 改成 height('100%') 等显式尺寸，居中仍交给 justifyContent(Center)。
2. 已意识到“容器要给高度”时，用组件源码或官方文档核实，不以工程内同构写法代替。

## 可选检查

- 包进刷新容器后按原样式要求核对一次：内容仍在剩余区域垂直居中，下拉区域覆盖整个空白区。
