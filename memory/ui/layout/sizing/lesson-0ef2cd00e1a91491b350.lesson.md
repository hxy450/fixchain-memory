# 源端在整数 px 上取整的布局公式：规格写明运算域，实现在 px 域取整、写入布局属性前再换回 vp

ID：`lesson-0ef2cd00e1a91491b350` · 版本：2

[本主题](index.md)

## 何时使用

规格提取阶段，把自定义 Layout、MeasureScope 里的测量与整数几何公式翻成目标契约时；界面实现阶段，用 onAreaChange、measureText 等返回值驱动这类公式时；移植自绘 View 的绘制坐标、setBounds 边界、位移与文字基线修正中的 (int) 强转时

## 适用情境

源算法在约束或测量结果（Compose constraints、placeable 宽高等整数 px）上做整数除法、.toInt() 截断或取整；目标布局属性和尺寸回调（onAreaChange）使用 vp 等逻辑单位，回调值通常不是整数，measureText 返回 px。 也包括 Canvas 绘制代码中的 (int) 强转（setBounds 边界、int 位移、文字基线修正），其中的量可能为负。

## 例外与边界

- 公式本来作用于 Dp 常量（固定间距、固定尺寸），不涉及 constraints 或 placeable 时，按原单位保留

## 原因

单位缩放与取整不可交换：保留 floor 等函数名却把输入换成 vp，每次截断的小数按 vp 丢弃，槽宽总和铺不满容器、位置偏移；把 measureText 的 px 先转 vp 再进公式也改变了运算域。规格把 vp 回调值写成“整数”或把“源端余下 W mod n 空白”按 vp 复述时，错误的等价性声明看起来成立，并传给所有照做的实现者。

## 做法

1. 规格提取：写出公式输入输出的单位、整数或浮点类型、取整位置和换算边界，以源测量代码为准；例如源公式为 Wpx/(n+1) 时，契约写成 u_px = floor(Wpx/(n+1))、供布局使用时 u_vp = px2vp(u_px)，不要写成 floor(Wvp/(n+1))。用例至少放一个非整数 vp 宽与对应 px 宽的对照行。
2. 实现：参数名带单位（如 widthPx）；onAreaChange 的 vp 宽先 vp2px，measureText 的 px 直接使用，公式在 px 域取整，结果写入 width、translate、position 前再 px2vp。规格把回调值写成“vp、整数”时，先用一个真实回调值核对。
3. Java/Kotlin 的 (int)/toInt() 向零截断，用 Math.trunc；量可能为负（反向位移、扩张时的负边界）时不能换成 Math.floor。视觉验收看不出亚像素差也原样保留，偏移被乘倍使用时误差随之放大。

## 可选检查

- 单位或取整顺序有疑问时，代入一个实测宽度比较两种顺序；能 dump 时核对行总宽是否等于容器 px 宽。
