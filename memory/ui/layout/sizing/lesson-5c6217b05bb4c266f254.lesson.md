# Compose Modifier 链里位于背景之前的内距与 inset 放外层，背景、圆角和裁剪放内层

ID：`lesson-5c6217b05bb4c266f254` · 版本：2

[本主题](index.md)

## 何时使用

规格提取与界面实现阶段，描述或翻译同一条 Compose Modifier 链中的 padding、statusBarsPadding 与 background、clip、Surface 形状时

## 适用情境

源 Modifier 链中 padding 或窗口 inset 位于 background、clip 或 Surface 包装之前；目标 ArkUI 的 padding 计入组件尺寸，backgroundColor 和 borderRadius 覆盖含 padding 的整个组件。

## 原因

Compose 修饰符按链顺序生效，背景之前的内距落在背景之外；写成同一 ArkUI 组件的并列属性后，背景涂进内距区，圆角基准也随之变大。规格把内距、底色、圆角写成并列属性时，这一顺序信息在交接中丢失。

## 做法

1. 先标出链中 background/clip/Surface 的位置：它之前的 padding、statusBarsPadding、navigationBarsPadding 放到外层容器（或改用 margin、位移），背景、圆角、clip 放到内层组件；只有位于背景之后的 padding 才能与背景写在同一组件上。 改用 margin 时，若该节点在同轴占满父级（源端 fillMaxWidth，或被占满宽的子项撑满；也包括 Button、Card 等包装组件 modifier 里的 fillMaxWidth().padding(horizontal = N.dp)），这个节点不能再写 width('100%')：百分比按父内容区计算、margin 再向外扩会溢出，改用外层容器 padding 加内层 '100%'，或把该节点宽写成 calc(100% - 两侧之和)（见 lesson-75f4743dff663f50966b）。
2. Surface 类包装组件收到的 modifier 视为作用在其背景和形状之前；圆角按内距以内的尺寸计算时，背景必须落在同尺寸的组件上。
3. 用窗口避让值替代 statusBarsPadding 时，若源链的背景在 inset 之后，不在带背景的同一组件上加顶部 padding，改为外层让位或并入位移，并把 inset 之前的 heightIn(min) 换算成内容区尺寸。
4. 规格描述带背景的组件时，按修饰符顺序写明内距或 inset 在背景之内还是之外。
