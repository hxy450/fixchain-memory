# 区分 Material 按钮的布局占位、背景实绘与触控范围：不只凭调用处 size 定背景，也不给内容撑开的容器补最小尺寸

ID：`lesson-b73a1ac8908f74856a02` · 版本：1

[本主题](index.md)

## 何时使用

规格提取或界面实现阶段，确定 Material 按钮及包装容器的尺寸与位置时

## 适用情境

源组件含 size/background 与库内部的最小交互尺寸规则（如 IconButton 在调用方 .size(x) 之内再套 minimumInteractiveComponentSize），或只是由内容撑开的 Surface/Box（如图标撑开的圆钮）；ui 快照由源码合成、bounds 为空时，调用处 size 数值最容易被当成实绘尺寸。

## 例外与边界

- 当前组件明确关闭或改写了最小交互尺寸，或强约束及修饰符顺序限制了其作用时，不套默认最小尺寸。

## 原因

minimumInteractiveComponentSize 的作用受约束和修饰符顺序影响，布局留位也不等于背景、图标或输入层的触控范围。来源两个方向都出现过：把 IconButton 调用处的小于 48dp 的 size 当成背景实绘尺寸（实测背景为 48dp、圆心不变），以及给只由内容撑开的 Surface 自加边距、放大成按钮尺寸。这些数值只说明当时的库配置，不等于“小于 48 的按钮都改成 48”。

## 做法

1. 普通 Surface/Box 没设尺寸时按内容和实际修饰符确定大小，不因里面有图标就补上 Material 按钮的最小交互尺寸或自加边距。
2. 对 IconButton，把调用处 size/background 的顺序与组件内部最小尺寸规则对应起来，分别保留布局占位、背景尺寸和图标尺寸；已有契约或测量足够时直接采用。
3. 已确定背景需要围绕原中心扩大时，保持槽位中心并按差值补偿位置（外边距各减差值的一半）；规格以中心而非左上角描述位置，记录实际尺寸来源。

## 可选检查

- 仅当当前库配置或修饰符顺序不足以确定背景尺寸时，查看该组件局部实现或复用已有布局 dump、截图；无需遍历全部按钮。
