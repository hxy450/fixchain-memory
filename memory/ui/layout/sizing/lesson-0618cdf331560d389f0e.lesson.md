# 水平 LinearLayout 里并排的无权重 wrap_content 列总宽超出时，源端按顺序测量：前列保持固有宽、后列被压缩；不写死固有 dp 宽

ID：`lesson-0618cdf331560d389f0e` · 版本：3

[本主题](index.md)

## 何时使用

界面实现阶段，把 match_parent 父行中并排的 wrap_content 图片列等子项转换为 ArkUI Row 并确定列宽时；修复“右侧顶满/被挤出屏幕”时

## 适用情境

源布局在 match_parent 的水平 LinearLayout 中并排放置无 layout_weight 的 wrap_content 子项（常为 ImageView），列宽来自 drawable 固有尺寸与左右、列间 margin；其总和与目标最窄支持窗口的可用宽度接近或超过。

## 例外与边界

- 子项带 layout_weight 时按 LinearLayout 的权重分配规则计算
- 单个图片盒在已定宽度下的高度（adjustViewBounds 按固有比例定高）按图片盒比例的规则处理

## 原因

水平 LinearLayout 对无权重子项按声明顺序测量，每个子项拿到“父宽 − padding − 已用宽 − 自身 margin”的 AT_MOST 上限（LinearLayout.java measureChildBeforeLayout、ViewGroup.getChildMeasureSpec）：前列保持固有宽，排在后面的列被压缩到剩余宽度，不会越出父宽。照抄固有 dp 写成固定 width，总和超过设备可用宽度时右列被推出屏幕；按固有宽比例分列又是另一种结果。

## 做法

1. 先把各列固有宽（drawable 像素尺寸按密度桶换算）与全部水平 margin 相加，与目标最窄窗口的可用宽度比较。
2. 忠实复刻时：前列取固有宽；最后一列写 layoutWeight(1) 加 constraintSize({ maxWidth: 固有宽 })，在剩余宽度内收缩；不在固定宽度子项之间夹 Blank().layoutWeight(1) 充当对齐。
3. 被压缩列的高度：源 ImageView 设 adjustViewBounds 时随宽按固有比例缩小（目标写 aspectRatio(像素宽/像素高)），否则盒高保持固有高、内容按 scaleType 缩放（目标按 objectFit 映射）。
4. 改成按固有宽比例分列属于有意偏离源端，需在报告中注明理由。
