# Column 中占剩余高度的内容区或被嵌入的满高组件，由宿主给有界槽位（layoutWeight(1)），子树不写 100% 高再叠固定兄弟

ID：`lesson-313f7ee22c558c2c8a15` · 版本：1

[本主题](index.md)

## 何时使用

界面实现阶段，为 Compose Column 中排在固定高度兄弟之后、占满剩余高度的内容区确定高度时；宿主页嵌入根节点为 height('100%') 的面板、弹层或由 Fragment 转成的子组件，确定根节点与各状态视图的高度约束时

## 适用情境

源 Compose Column 里内容区排在搜索栏、分隔线等固定高度节点之后，靠 fillMaxSize、weight 或 Lazy 列表占满剩余高度，可能有空结果、加载、结果等多个状态分支；或 Android 以 MATCH_PARENT 的 PopupWindow showAsDropDown(锚点) 弹出面板，只占锚点以下的高度；或被嵌子组件的源布局根与空态容器都是 wrap_content，在宿主 NestedScrollView 的 wrap_content 槽位里按内容取高。目标准备给内容区或组件根写 height('100%')。

## 例外与边界

- 宿主槽位本身已有确定高度（显式数值或已被外层约束定死）时，子树的 '100%' 按该高度解析，可以使用

## 原因

Compose 测量 Column 中的 fillMaxSize 子项时，可用高度已扣除先测的兄弟；ArkUI height('100%') 取父容器全高，再叠上固定兄弟就超出窗口，底部按钮或后续区块被挤出。被嵌组件根节点的 '100%' 在 Scroll 的无界父链里按视口高解析（设备实测），把首屏后续区块挤出；wrap_content 槽位里的 match_parent 实际按内容取高。

## 做法

1. Column 中占剩余高度的内容区写成一个 .layoutWeight(1) 容器，各状态分支都放在这一层里，分支自身不写 height('100%')；规划过这层包裹容器时，写完回看 build() 确认它确实写出。规格写“占某元素之后的剩余高度”，不写“全屏”。
2. 嵌入自带标题行与底栏、根节点为 height('100%') 的面板时，先读组件根尺寸声明，不在同一 Column 里再给它叠固定高度兄弟：给面板槽位 layoutWeight(1) 或外包有界容器，或放到外层 Stack 作覆盖层并去掉重复标题。源端 MATCH_PARENT + showAsDropDown(锚点) 对应锚点以下的剩余高度。
3. 被嵌子组件按源布局根节点与各状态容器的 layout_height 映射：wrap_content 不写 height('100%')，空态居中用内容高度或 constraintSize 最小高度；宿主向无高度槽位嵌入组件前，读被嵌组件 build() 根与各状态分支的高度修饰，有百分比高度就先改组件，或在槽位按源端尺寸给显式高度。
4. 并行拆分组件与宿主时，交接写明尺寸契约（组件满高、由宿主分配有界区域，或组件按内容取高），宿主收到组件代码后回看承载结构是否满足。

## 可选检查

- 带底部操作栏的弹层打开最长内容态，核对底栏下边界不越出可视区、按钮可点；嵌入组件后核对首屏后续区块仍可见。
