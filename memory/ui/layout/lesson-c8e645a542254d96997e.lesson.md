# 源布局有 layout-land、layout-sw600dp 等变体时逐控件对照，在承载组件内按限定词对应的窗口条件分支；运行时换背景只覆盖被调用控件

ID：`lesson-c8e645a542254d96997e` · 版本：2

[本主题](index.md)

## 何时使用

界面实现阶段，合并 layout 与 layout-land 变体，或实现替代带变体 fragment 的共享组件时；计划与派工阶段指派变体实现时；页面元数据与规格阶段登记 layout_sources 时

## 适用情境

源 res/layout-land/ 下有同名变体，控件的 background、weight、margin、textSize 或整体结构与竖屏不同；Activity 代码在运行时只对部分控件 setBackgroundResource；布局由另一任务的共享组件承载，派工只写竖屏结构，横屏要求只出现在资源任务或移交登记里。 也包括被 include 进页面的布局在 layout-sw600dp 下有变体（如按钮由纵向改为横排），页面元数据只登记 base 布局，计划里“随迁”的变体没有点名文件与承接页面。

## 原因

只按竖屏骨架实现，或把运行时覆盖推广到所有控件，横屏下结构与外观都会偏（来源中统计卡没有横屏分支，横屏主菜单的直角按钮被写成圆角）；资源任务承接不了布局变体。

## 做法

1. 开写前对每个被替代的源布局（含 <include> 引入的布局）ls res/layout-*/<name>.xml，按 android:id 逐控件 diff 各变体的属性；每个差异写成与限定词对应的窗口条件分支（land → 窗口宽 > 高；sw<N>dp → 窗口短边 ≥ N vp；w<N>dp → 可用宽 ≥ N vp），或在报告注明被哪段运行时代码覆盖。
2. 先列出运行时 setBackgroundResource/setBackground 实际作用的控件变量，只有这些改用运行时背景，其余控件在每个变体里按该变体 XML 取形状与颜色。
3. 布局由共享组件承载时，把变体路径与差异写进该组件的产出与验收，不只放进资源任务；本任务确实不做时登记带负责方、变体路径与关键值的移交，关闭移交前逐条核对横屏要求。
