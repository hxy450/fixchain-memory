# 源布局（含 include 引入的布局）有 layout-land、layout-sw<N>dp 等变体时逐控件对照，在承载组件内按配置条件分支实现

ID：`lesson-c8e645a542254d96997e` · 版本：2

[本主题](index.md)

## 何时使用

页面数据提取与规格阶段登记页面布局来源时；界面实现阶段，合并 layout 与 layout-land、layout-sw<N>dp 等变体，或实现替代带变体 fragment 的共享组件时；计划与派工阶段指派变体实现时

## 适用情境

源 res/layout-land/、layout-sw600dp/ 等目录下有同名变体（也可能是被 <include> 或 setContentView 引入的子布局），控件的 background、weight、margin、textSize、排列方向或整体结构与 base 不同；Activity 代码在运行时只对部分控件 setBackgroundResource；页面元数据的布局来源清单只列 base 文件，或计划写“变体随迁”却未点名文件与负责方；布局由另一任务的共享组件承载，派工只写竖屏结构，横屏要求只出现在资源任务或移交登记里。

## 原因

只按 base 骨架实现，或把运行时覆盖推广到所有控件，横屏或大屏下结构与外观都会偏；ArkUI 没有布局资源限定词，未进入布局来源清单或未点名负责方的变体不会被任何任务实现，资源任务也承接不了布局变体。

## 做法

1. 开写前对每个被替代的源布局及其 <include> 引入的布局 ls res/layout-*/<name>.xml，按 android:id 逐控件 diff 各变体的属性；每个差异写成配置条件分支：-land 按窗口宽 > 高，-sw<N>dp 按设备屏幕短边 min(宽,高) ≥ N vp（与方向无关，不用 mediaquery min-width），-w<N>dp 按当前窗口宽 ≥ N vp；或在报告注明被哪段运行时代码覆盖。
2. 先列出运行时 setBackgroundResource/setBackground 实际作用的控件变量，只有这些改用运行时背景，其余控件在每个变体里按该变体 XML 取形状与颜色。
3. 布局由共享组件承载时，把变体路径与差异写进该组件的产出与验收，不只放进资源任务；本任务确实不做时登记带负责方、变体路径与关键值的移交，关闭移交前逐条核对横屏要求。
4. 页面数据提取与计划阶段，把每个布局来源（含 include）的限定符变体连同判定语义记入页面元数据或规格，并点名负责的页面规格或切片；写“随迁”而未点名文件与负责方的视为未分配。
