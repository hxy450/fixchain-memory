# 源布局有 layout-land、layout-sw<N>dp 等同名变体时逐控件对照各变体，在承载组件内按对应配置条件分支（ArkUI 没有布局资源限定词）

ID：`lesson-c8e645a542254d96997e` · 版本：2

[本主题](index.md)

## 何时使用

界面实现阶段，合并 layout 与 layout-land 变体，或实现替代带变体 fragment 的共享组件时；计划与派工阶段指派变体实现时

## 适用情境

源 res/layout-land/、layout-sw600dp/ 等目录下有同名变体，控件的 background、weight、margin、textSize 或整体结构与默认布局不同；Activity 代码在运行时只对部分控件 setBackgroundResource；布局由另一任务的共享组件承载，派工只写默认结构，变体要求只出现在资源任务或移交登记里。

## 例外与边界

- 变体之间只有 values-* 中的尺寸、颜色等值不同而布局结构相同时，按资源值的限定词覆盖规则处理

## 原因

只按默认骨架实现，或把运行时覆盖推广到所有控件，变体配置下结构与外观都会偏；资源任务承接不了布局变体。layout-* 的限定词各有判据：land 看方向，sw<N>dp 看最小宽（不随旋转变），w<N>dp/h<N>dp 看当前可用宽/高，night 看深浅模式。

## 做法

1. 开写前对每个被替代的源布局列出 res/layout-*/<name>.xml，按 android:id 逐控件 diff 各变体的属性；按限定词选判据写分支：layout-land 按窗口宽 > 高，layout-sw<N>dp 按窗口最小边 ≥ N，layout-w<N>dp/h<N>dp 按当前可用宽/高，night 按深浅模式，组合限定词按 Android 资源匹配优先级处理；被运行时代码覆盖的属性在报告中注明覆盖代码。
2. 先列出运行时 setBackgroundResource/setBackground 实际作用的控件变量，只有这些改用运行时背景，其余控件在每个变体里按该变体 XML 取形状与颜色。
3. 布局由共享组件承载时，把变体路径与差异写进该组件的产出与验收，不只放进资源任务；本任务确实不做时登记带负责方、变体路径与关键值的移交，关闭移交前逐条核对变体要求。
