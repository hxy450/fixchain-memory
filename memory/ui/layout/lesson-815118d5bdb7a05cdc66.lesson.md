# 截图缺少源码中存在的入口、区块，或列数、背景、文案与源码不同时，先查运行分支与调用链，不按单张截图删改

ID：`lesson-815118d5bdb7a05cdc66` · 版本：1

[本主题](index.md)

## 何时使用

视觉校验与修复阶段，按截图删减其中没有出现的 tab、入口或区块，调整列数、背景，或按文档截图、@Preview 选定空态等文案与图标时

## 适用情境

源码布局里存在、且有点击逻辑的入口或区块在截图中缺失，或截图的列数、背景、文案与源码不一致；Fragment/Activity 可能按渠道（getChannel）、会员、开关或运行状态切换可见性与数据；截图可能只来自一种运行变体，也可能来自 docs/assets 或 @Preview 示例。

## 例外与边界

- 源码确认该入口已下线（无可达分支、无点击逻辑）时，按源码删除

## 原因

渠道、开关和运行状态决定某时刻的可见入口、列数与背景，文档截图与 @Preview 又使用示例内容；把单张截图当成全部行为，会误删源码仍定义并有点击逻辑的入口，或把示例文案写成应用文案。

## 做法

1. 截图中缺少而源码布局存在、且有点击逻辑的 tab、入口或区块，先在 Fragment/Activity 中搜索其 setVisibility、渠道、会员或开关分支，确认是运行变体还是已下线；属于变体时保留完整入口或实现同等条件开关，并请用户确认截图所属渠道。
2. 列数与区块数以 Adapter 实际绑定的数据项为准，背景以源码的状态选择逻辑为准，尺寸以源布局为准；读取出现截断就按单个文件重读后再下删改结论。
3. docs/assets 截图与 @Preview 中的示例文案、图标不是应用真值：选定字符串 key 或图标前，搜索它在应用代码中的真实引用，与页面实际调用链不一致时以调用链为准。
