# 按参考截图补元素前先把它归属到具体组件：当前组件源码没有其绘制逻辑时转查相邻组件，不在 Canvas 里自行补画

ID：`lesson-b04dfc0158b66f6544d5` · 版本：1

[本主题](index.md)

## 何时使用

界面实现或视觉修复阶段，按参考截图补齐无数据空态、提示文案等元素，决定它归属哪个组件时

## 适用情境

页面由图表 Canvas 与相邻侧栏、列表等并列组件组成；截图里出现的文案（如“暂无数据”）在正在修改的组件源码中只被赋值、没有绘制或消费逻辑；用户文字可能只列出部分要补的元素。

## 原因

截图只显示像素位置，不说明元素属于哪个组件；默认把它归入正在修改的组件，会把相邻组件的空态画进图表，而源码检索结果并不支持这种绘制。

## 做法

1. 先依据页面布局区域（各并列组件的宽度与位置）把截图中每个元素对应到具体组件，不默认归入正在修改的组件。
2. 源绘制代码中找不到该元素的绘制逻辑（只赋值、未被消费）时，转查相邻组件的空态实现（列表的 empty view、空态字符串在布局中的引用）；仍无法确认就只实现用户文字明确列出的元素，并向用户确认文案位置，在回复中写明放在哪个组件。
