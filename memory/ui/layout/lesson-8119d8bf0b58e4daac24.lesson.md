# 按截图或视觉差异单修改固定尺寸前，先按两端密度把差异折算成 vp，与源布局值、目标当前值三方对照

[本主题](index.md)

## 何时使用

视觉校验与修复阶段，根据双端截图差异撰写尺寸类工单，或决定修改页面固定高度、间距、图片尺寸时

## 适用情境

Android 基线截图与目标截图来自不同设备（密度、逻辑宽度不同），差异单写“主内容偏小/上移”一类观感结论；目标页的固定高度、margin 可能已等于源布局 dp 值，并与底栏共享有限纵向空间。

## 例外与边界

- 差异涉及自绘组件外层容器的高度、裁剪或折叠范围时，按自绘尺寸与容器同源修改的规则处理

## 原因

截图差异同时受密度、视口与运行条件影响，不直接证明源布局尺寸有误；仅凭观感放大常量会覆盖已与源端一致的值，累积高度偏差，把底部内容推到底栏下。

## 做法

1. 写尺寸工单前，按两端设备各自的密度/逻辑宽度把截图差异折算成 vp，与源布局 dp 值、目标代码当前值三方对照；目标值已等于源值时，改查视口、安全区或容器层级，不写“对齐固定高度”，源码定位不能留空。
2. 拟改值偏离源布局值时，要有源码或资源固有尺寸依据，不用放大常量补偿截图比例；放大元素前累计所有固定高度与 margin，确认底部内容仍位于底栏之上。
