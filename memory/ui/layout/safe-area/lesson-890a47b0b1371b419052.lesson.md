# 安全区应沿父子布局链只承接一次，并覆盖同一内容区的所有层

ID：`lesson-890a47b0b1371b419052` · 版本：1

[本主题](index.md)

## 何时使用

规格提取、组件派工或界面实现阶段，确定嵌套页面、Tab 内容和页内浮层由哪一层消费系统安全区时

## 适用情境

源界面通过 Scaffold、导航宿主或容器 padding 传递系统 inset，目标界面可能改为宿主避让或向子页传值；列表、顶栏、遮罩和对话框又可能作为同一 Stack 的兄弟层存在。

## 例外与边界

- 目标父容器已经消费了准确的 inset，且证据确认所有子层坐标都从该内容区起算

## 原因

只查看子页是否显式调用安全区 API，会漏掉父层通过 modifier 或 inner padding 已施加的约束；在同一内容区混用父层避让和子层自理，还会造成重复偏移，或让未接收参数的浮层压入系统栏。

## 做法

1. 沿源端宿主到子内容的布局链记录 inset 来源、每次消费位置和消费后的坐标系，再明确目标端唯一责任层。
2. 若目标端由子层消费，就把同一区域内列表、顶栏、遮罩和浮层所需的边界写入共同契约并逐层透传；若由父层消费，则子层统一使用消费后的坐标。
3. 安全区判断被纠正时，检查引用同一宿主区域的页面规格、功能规格、槽位契约和派工输入，一并更新责任决策。

## 检查

- 对照源端或当前契约检查内容起点、内容居中区、底部边界与遮罩覆盖范围，确认 inset 未遗漏也未重复，且同一 Stack 的各层采用一致坐标系。
