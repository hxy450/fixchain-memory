# 按内容与遮罩的覆盖边界分配安全区处理责任

[本主题](index.md)

## 何时使用

规格提取、组件派工或界面实现阶段，确定嵌套页面、Tab 内容和页内浮层由哪一层消费系统安全区时

## 适用情境

源界面通过 Scaffold、导航宿主或容器 padding 传递系统 inset，目标界面可能改为宿主避让或向子页传值；列表、顶栏、遮罩和对话框又可能作为同一 Stack 的兄弟层存在。

## 例外与边界

- 当前契约已分别说明各区域的边界、父层已消费的 inset 和子层剩余责任

## 原因

只看子页有无安全区 API，会漏掉 Scaffold 或宿主通过 padding 已施加的约束；重复消费同一边界又会产生偏移。内容和遮罩的覆盖目标可能不同，不能从一个层的设置推断所有层。

## 做法

1. 沿当前源端宿主到子内容的布局链追踪 padding/inset 的来源和消费位置；例如先施加 padding，再 consumeWindowInsets，会影响后代还需处理的边界。使用当前版本和配置的含义，不从子组件缺少显式调用推断没有避让。
2. 分别明确内容、顶栏和遮罩的目标覆盖区，为每个边界分配处理责任。父层已扣除的同一边界，子层不再重复扣除；预期覆盖系统栏的遮罩可以使用不同于内容的外框。
3. 将选定责任写进相关组件契约与派工输入，沿用当前工程的参数名；已有清楚契约时直接采用。

## 可选检查

仅在适用条件不确定、与当前输入冲突或需要验证关键假设时按需执行；优先复用已有证据和正常测试。
不因读取本条经验而额外启动验证流程；项目原有必需测试照常执行。

- 仅当源码与契约对某条边界有分歧时，先复用已有源端截图或 bounds 核对内容起点、遮罩覆盖范围；能裁决即可继续。
