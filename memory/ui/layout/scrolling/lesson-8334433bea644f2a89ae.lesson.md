# 源端“右列 match_parent 跟随左卡等高”在 Scroll 内用实测高度传递实现，不用估算常量

ID：`lesson-8334433bea644f2a89ae` · 版本：2

[本主题](index.md)

## 何时使用

界面实现与验证期修复阶段，为并排卡片确定跟随等高约束，而整行位于 Scroll 等纵向无界容器中时

## 适用情境

Android 水平行里右列 height=match_parent 随左侧 wrap_content 卡片等高；整行在 NestedScrollView（ArkUI Scroll）中；目标在 Scroll 内用纵向 layoutWeight 或 height('100%') 会被撑高失控。

## 原因

Scroll 内纵向百分比或权重没有上界会被撑高，修复时容易改成按字号行高估算的固定高度；左卡内容高随字体度量与内容变化，常量会与之脱钩，两卡仍不等高。

## 做法

1. 在左卡 onSizeChange((_old: SizeOptions, size: SizeOptions) => …) 中取实测高度写入状态，右卡 height 绑定该状态（首帧用估值兜底）。
2. 派修或验收时把“两卡等高”写成验收条件，不只给出“改成固定高度”这类修法。

## 可选检查

- dumpLayout 比对两卡 bounds 高度一致。
