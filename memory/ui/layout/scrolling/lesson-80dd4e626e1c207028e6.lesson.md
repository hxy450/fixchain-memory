# ScrollView 未写 overScrollMode、Compose verticalScroll/Lazy 列表未置空 overscroll 时，都按 Android 默认 IF_CONTENT_SCROLLS 映射：Scroll 写 edgeEffect(EdgeEffect.Spring, { alwaysEnabled: false })；GridView/ListView 同此，滚动条按源端默认显式设置

ID：`lesson-80dd4e626e1c207028e6` · 版本：4

[本主题](index.md)

## 何时使用

界面转换阶段，把 ScrollView/NestedScrollView（含对话框内的滚动区）转换为 ArkUI Scroll 并设置边缘效果时；把会滚动的 GridView/ListView 转成 Grid/List 并决定滚动条与越界效果时；把 Compose Modifier.verticalScroll/horizontalScroll 或 LazyColumn/LazyRow 转成 Scroll/List（含 bindSheet 半模态里的内容区）并设置边缘效果时

## 适用情境

源 ScrollView 没有声明 overScrollMode（Android 默认 IF_CONTENT_SCROLLS：内容可滚时越界回弹）；映射参考只列显式 overScrollMode，且把 ifContentScrolls 与 always 都映射为不带选项的 EdgeEffect.Spring；目标 Scroll 默认没有边缘效果。 也包括 GridView/ListView 没有改写 scrollbars、overScrollMode（AbsListView 同样默认 IF_CONTENT_SCROLLS），目标 Grid/List 没有显式设置 scrollBar 与 edgeEffect。 也包括 Compose Modifier.verticalScroll/horizontalScroll、LazyColumn/LazyRow 的默认重载带平台越界效果（Android 12+ 拉伸；foundation-android 1.12.1 的默认重载经 LocalOverscrollFactory 取平台效果，字节码已核），源工程没有经 LocalOverscrollFactory/LocalOverscrollConfiguration 或 overscrollEffect 参数置空，页面规格只写 verticalScroll、不提边缘效果。

## 原因

不写 edgeEffect 时 Scroll 没有回弹；写成不带选项的 Spring，内容不满一屏也会回弹。两者都与源端不同；映射参考没有“未声明即 IF_CONTENT_SCROLLS”的规则时，各页会分别落到这两种写法。来源中同一应用的九个滚动页里，六个没设 edgeEffect、三个写了无条件 Spring。 源端视图在窗口变为可见时先显示滚动条约 1200ms 再淡出（View.initialAwakenScrollBars 以 scrollBarDefaultDelayBeforeFade×4 唤醒，默认延迟 300ms；本机 android-36.1 源码 View.java、ViewConfiguration.java），之后滚动时再出现；ArkUI Grid 默认 BarState.Auto，进页不显示（本机 HarmonyOS 6.1.0 SDK component/grid.d.ts，早期版本默认 BarState.Off），宽度与颜色也取目标默认。ArkUI Scroll 把 scrollBar 从 BarState.On 切到 Auto（或切 Off 后不久再切 Auto）时会重新显示滚动条，按 Auto 的淡出节奏再停约 1.3–2s（HarmonyOS 6.1.0 Scroll 截屏取样：On→Auto 约 3s 才消失，只切 Off 立即消失），到时直接切 Auto 会让进页滚动条停留过久。唤醒延迟取自主题的 scrollbarDefaultDelayBeforeFade：Material 系主题若在 themes_material.xml 改写为 400，唤醒约 1600ms，参照取样未能区分 1200 与 1600ms，按源主题值取并在报告注明。

## 做法

1. 源未写 overScrollMode 或写 ifContentScrolls：.edgeEffect(EdgeEffect.Spring, { alwaysEnabled: false })；always：alwaysEnabled: true；never：EdgeEffect.None。对话框内的 Scroll 同样处理。 GridView/ListView 转 Grid/List 时同样设置（Grid 默认 EdgeEffect.None）。 Compose 的 verticalScroll/horizontalScroll、LazyColumn/LazyRow：先在源工程检索 LocalOverscrollFactory、LocalOverscrollConfiguration 与 overscrollEffect 参数，没有置空就同样写 Spring + alwaysEnabled: false；规格没写边缘效果不是保留 None 的理由。第 2 步的滚动条规则针对 View 体系的默认滚动条，Compose 源端按源码是否显式绘制滚动条决定。
2. 内容可滚动时显式设置滚动条：进页用 BarState.On 显示源端唤醒时长（约 1200ms，见原因）后切到 BarState.Off 立即收起，不直接切 Auto；在 onTouch 的 TouchType.Down 且当前为 Off 时再切 BarState.Auto，滚动时由 Auto 显示（本条只在 Scroll 实测，Grid/List 用同一切换时按同理处理）。scrollBarWidth 与 scrollBarColor 按源主题的 scrollbarSize 与对应滚动方向的 scrollbarThumbHorizontal/Vertical 取值（Holo 在 SDK values/themes_holo.xml；Material 系在 themes_material.xml，thumb drawable 再按 tint 算合成色），源主题不是示例中的主题时同样去对应 themes_*.xml 查，查不到在报告里登记缺口，不静默沿用目标默认。是否会滚动按参照机行高×行数判断。
