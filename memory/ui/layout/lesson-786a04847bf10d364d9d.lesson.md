# supportsRtl 应用保留逻辑方向：边距用 LengthMetrics 的 start/end，自动镜像图标加 matchTextDirection

ID：`lesson-786a04847bf10d364d9d` · 版本：4

[本主题](index.md)

## 何时使用

规格提取与界面实现阶段，为声明 supportsRtl=true 的源应用转换 start/end 边距与自动镜像图标时

## 适用情境

源 Manifest 声明 android:supportsRtl="true"；Compose 用 padding(start/end)、Icons.AutoMirrored.*（或 autoMirrored=true 的矢量），View 用 marginStart/End、paddingStart/End；应用含 RTL 语言资源或可能在 RTL 系统语言下运行；转换者准备写 left/right，把返回箭头等方向性图标转成普通 Image；页面规格可能没有携带 RTL 契约，资源映射可能把自动镜像图标当普通媒体。映射参考的边距示例可能是纯数字 margin({ end: 10 })，含 start/end 键的边距对象写数字会编译报 Type 'number' is not assignable to type 'LengthMetrics'。

## 例外与边界

- 源 Manifest 未声明 supportsRtl：布局恒 LTR，按显式固定 LTR 的做法处理

## 原因

start/end 与 AutoMirrored 都是随布局方向翻转的逻辑语义；写成 left/right 或普通图片后，RTL 语言下间距落在错误一侧、返回箭头指向反方向。规格没把 RTL 列为全局契约时，各页转换者容易就近改成物理方向。

## 做法

1. 规格阶段读到 supportsRtl=true 时，把“布局随语言方向镜像”写成全局契约传给各页，并在资源映射中标出需要镜像的方向性图标。
2. start/end 边距写 .padding/.margin({ end: LengthMetrics.vp(n) })，同一对象含 start/end 键时各边（包括 top/bottom）都用 LengthMetrics，并从 @kit.ArkUI 导入 LengthMetrics；源端本就是物理 left/right 的才写 left/right。映射参考示例与 SDK 声明不一致时以声明为准，并修正参考。
3. Icons.AutoMirrored.* 或 autoMirrored 矢量转成的 Image 加 .matchTextDirection(true)；图标经共享按钮组件渲染时，由组件提供镜像参数并在调用处传入。
