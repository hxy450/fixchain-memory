# 源 Box 中按内容定高、align(BottomCenter) 贴底的栏，在 Stack 中保持自身尺寸直接锚到底部，不套全屏壳

ID：`lesson-29fc0f8f62759fb1b254` · 版本：1

[本主题](index.md)

## 何时使用

界面实现与巡检修复阶段，把 Compose Box 或 FrameLayout 中叠放的顶栏、底栏迁到 ArkUI Stack，确定它们的定位方式时

## 适用情境

源页面在同一 Box(fillMaxSize) 里叠放可滚动内容、返回按钮等可点击覆盖控件，以及以 Modifier.align(Alignment.BottomCenter) 定位、按内容定高的底栏（顶栏同理只占自身高度）；目标 Stack 的 alignContent 改为 TopStart 等之后需另找贴底方式；项目映射参考可能注明 .align() 不能定位 Stack 子项。

## 例外与边界

- 栏在源端本身就是 match_parent 的全屏层：按全屏层的命中规则处理

## 原因

用 width/height('100%') 的 Column + Blank 作定位壳时，壳是后声明、默认命中模式（Default）的全屏节点，会盖住更早声明的返回按钮和下层滚动区，点击与滑动都无响应；组件的 .align() 只对齐自身内容，不能把 Stack 子项钉到顶部或底部。

## 做法

1. 逐个保留源端子项的尺寸：顶栏、底栏各自只占自身高度，用 Stack 的 alignContent、RelativeContainer 的 alignRules 或 position 的 bottom 边逐个定位，不用满屏 Column + Blank 统一摆放。
2. 确需全屏布局壳时给壳设 hitTestBehavior(HitTestMode.Transparent)，或让可点击的覆盖控件最后声明、提高 zIndex。
3. 重排叠放层后，按声明顺序检查每个可点击覆盖控件之后的同级节点：区域覆盖该控件的就调整顺序、zIndex 或命中模式，并实际点击该控件、实测下层滚动复核。

来源支持：2 张卡 · 2 次迁移 · 2 个应用
