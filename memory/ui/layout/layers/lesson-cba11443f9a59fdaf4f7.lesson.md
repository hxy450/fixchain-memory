# 在预览底部新增可选背景层时，逐层处理压在它上面的不透明内容：已选背景时上层透明或与背景合成，做不到就登记该分支的限制

ID：`lesson-cba11443f9a59fdaf4f7` · 版本：1

[本主题](index.md)

## 何时使用

组件详情或编辑页的界面实现阶段，给预览区接入用户可选的背景，并确定它与现有预览内容的叠放顺序时

## 适用情境

目标预览由静态网络预览图（Image + Contain）或铺满的白色占位层展示组件；源端选中背景后把它设为组件自身的背景 Drawable 并重绘；目标另建一个独立背景层，放在现有预览内容之下。

## 原因

背景放到最底层并不等于可见：静态预览图与白色占位都不透明，所选背景只画在它们下面，选项选了也看不出效果。源端背景是组件渲染的一部分，不是垫在成品图下面的一层。

## 做法

1. 接入前列出背景层上方的每一层（静态预览图、占位底、动态渲染等），已选背景时把不透明层改为透明，或与背景合成（例如白底静态预览用 blendMode(BlendMode.DARKEN) 叠在背景上）。
2. 某个分支无法呈现所选背景（如成品图无法重着色）时，在实现里明确采用的合成方式，或登记为结构化缺口并报告，不在回执里写一句限制就交付。

## 可选检查

- 对每个兜底分支确认：已选背景时背景层上方没有不透明底色；可断言占位层颜色随背景状态切换，或在设备上选一个纯色截图核对。
