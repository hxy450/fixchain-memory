# 为已转换页面接线时保留“全屏底层 + 按状态切换的前景层”骨架；底层 SDK 不可用也不把全屏承载改成固定高度卡片

ID：`lesson-4de4283ec625be7e976c` · 版本：5

[本主题](index.md)

## 何时使用

功能接线任务面对页面转换阶段已写出的页面、决定保留还是重写布局骨架时；巡检修复处理“缺少全屏底层承载”一类发现时

## 适用情境

Android 页面以全屏 MapView/导航视图等为底层，前景由 ViewModel 布尔状态切换两套覆盖层；导航类页面可能 FEATURE_NO_TITLE、只承载底层视图；目标端对应 SDK 暂不可用，页面转换阶段已写出带全屏占位底图与两态覆盖层的骨架。

## 例外与边界

- 已转换页面的骨架经核对与源布局不符时，按源布局修正骨架，不保留错误结构

## 原因

接线时删掉已转换页面从零重写，会丢掉已正确的层级、两态结构和字段；SDK 缺位只决定底层是占位，不是改布局的理由。把全屏承载改成固定高度的自绘卡片，或给无标题栏的页面加标题栏，界面与源端结构就不再对应。

## 做法

1. 为已转换页面接线时默认保留原骨架，只替换数据绑定与事件；确需重写，先对照源布局与 ViewModel 列出每个状态下可见的节点，写完逐项核对。
2. 底层 SDK 不可用时，承载层仍放在全屏底层（占位面或显式失败提示），前景覆盖层结构不变；源端无标题栏的页面不加标题栏。
