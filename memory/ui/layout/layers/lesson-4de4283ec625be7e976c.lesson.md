# 为已转换页面接线时保留“全屏底层 + 按状态切换的前景层”骨架；地图 SDK 不可用也不把全屏承载改成自绘小卡

ID：`lesson-4de4283ec625be7e976c` · 版本：2

[本主题](index.md)

## 何时使用

功能切片为已转换页面接入 ViewModel、Service 与跳转，决定保留还是重写布局骨架时；巡检修复处理“缺少全屏地图承载”一类发现时

## 适用情境

Android 页面以全屏 MapView/导航视图为底层，前景由 ViewModel 布尔状态（如 showRoute）切换两套覆盖层；导航页 FEATURE_NO_TITLE、只承载导航视图；目标地图/导航 SDK 暂不可用，页面转换阶段已写出带全屏占位底图与两态覆盖层的骨架。

## 原因

“UI 补充”一类切片若删掉已转换页面从零重写，已正确的层级、两态结构和字段会丢失；SDK 缺位只决定底图是占位，不是改布局的理由。把全屏承载改成固定高度的自绘卡片，或给无标题栏的导航页加标题栏，界面与源端结构就不再对应。来源中切片代理读到了两态骨架和源 ViewModel 全文，仍重写成常驻标题栏加居中卡片；巡检已指出“地图是全屏底层”，修复者却插入了 180 高的自绘地图卡。

## 做法

1. 为已转换页面接线时默认保留原骨架，只替换数据绑定与事件；确需重写，先对照源布局与 ViewModel 列出每个状态下可见的节点，写完逐项核对。
2. 驱动界面的常量与状态从源 ViewModel 一并迁移：Tab 顺序按其 tabData 与类型码映射，列表项字段按数据类与 item 布局，选中项按选中索引，距离等文本按源格式化函数；内部 id 不作用户可见标题。
3. 地图/导航 SDK 不可用时，承载层仍放在全屏底层（占位面或显式未配置提示），前景覆盖层结构不变；源端无标题栏的导航页不加标题栏。
