# 从声明式源码合成界面前应推演兄弟节点的实际测量

ID：`lesson-b5b28cbc691c44a51bbf` · 版本：2

[本主题](index.md)

## 何时使用

规格提取阶段，在缺少真机视图树时从声明式 UI 源码判断元素是否实际可见并合成页面结构时

## 适用情境

Row 或 Column 中存在未加权的填满主轴子项，其后仍声明兄弟元素；合成快照没有 bounds，却试图依据源码存在性描述后续元素的颜色、位置或交互。

## 例外与边界

- 已有覆盖目标状态的真机视图树或截图，能够直接确认该元素被测量并绘制

## 原因

声明了组件不代表它获得非零约束；前序子项可能耗尽剩余空间，使后续兄弟被零约束、裁剪或完全不绘制。把这种元素当作可见会让目标端复刻出源端不存在的 UI。

## 做法

1. 按父布局的测量顺序推演每个子项的约束、weight、剩余主轴空间和裁剪结果，把零尺寸或被裁剪元素标为声明存在但实绘缺失。
2. 没有 bounds 时，将基于颜色或可见性的判断降级为待设备核验，不把它写成确定转换决策。
3. 若必须保持布局槽位而不绘制元素，显式选择保槽位的隐藏方式，并记录测量依据。

## 可选检查

仅在适用条件不确定、与当前输入冲突或需要验证关键假设时按需执行；优先复用已有证据和正常测试。
不因读取本条经验而额外启动验证流程；项目原有必需测试照常执行。

- 仅当源码推演与规格的可见性结论冲突时，先复用目标状态的现有父子 bounds 或截图，区分未绘制、裁剪和浅色显示。
