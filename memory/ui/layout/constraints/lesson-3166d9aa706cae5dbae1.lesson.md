# 源端代码按设置与朝向重排控件时，页面按控制器产出的逐控件摆位解算渲染，不用固定百分比 position 代替

ID：`lesson-3166d9aa706cae5dbae1` · 版本：1

[本主题](index.md)

## 何时使用

界面集成阶段，把布局控制器或 ViewModel 产出的逐控件摆位（贴靠边、沿边偏移、边距、顺序）接到页面按钮层时；实现该布局控制器、为贴边控件写边距时

## 适用情境

源 Activity 在运行时按界面方位设置（如左右手布局）与系统朝向改写 RelativeLayout 规则与边距（addRule、setMargins），并给贴边控件加导航栏间隙；目标把这段逻辑移植为产出 placements 的控制器，页面按钮层负责消费；页面可能只读取其中的尺寸字段，或按默认方位写死坐标。

## 原因

摆位只在控制器里算、页面不消费时，控件位置不随设置与朝向变化，没有渲染分支的控件直接缺失；控制器漏写某类边距（如导航栏间隙）时，即使页面消费也无避让。默认方位下截图接近源端，偏差要切换设置或旋转后才暴露。

## 做法

1. 页面在实测视口（vp）中把每个 placement 的贴靠边、沿边偏移与边距解算成坐标，并按朝向变换，再用参数化的定位 @Builder 渲染；不用固定百分比 position 代替，也不只取其中的尺寸字段。
2. 以 placements 的键集合对照源布局 XML 的控件清单，每个 id 都要有渲染分支，包括条件控件在缺数据时的默认形态（如没有缩略图时的图库入口）。
3. 实现控制器时，把源端逐控件 setMargins 用到的间隙（如 navigation_gap 及其横屏、反向横屏变体）写进对应 placement 的边距；间隙值由其他切片提供时登记移交项，不静默省略。
