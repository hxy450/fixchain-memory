# 源端默认起始对齐和贴顶要显式写出：Android 与 Compose 的纵向容器默认贴起始边，ArkUI Column 交叉轴默认居中，Scroll 内不满一屏的内容默认居中

ID：`lesson-08b9064f678f1635e647` · 版本：5

[本主题](index.md)

## 何时使用

界面实现阶段，把纵向 LinearLayout、带 constraintStart/Top 的 ConstraintLayout 或 ScrollView/NestedScrollView 转成 ArkUI Column 与 Scroll 时；以及把 Compose Column 中的文本块转成 ArkUI Column 子项时

## 适用情境

源纵向 LinearLayout 没写 gravity（子项默认贴起始边），或 wrap_content 子项以 constraintStart_toStartOf=parent 靠起始边、卡片以 constraintTop_toTopOf=parent 贴顶；目标 Column 宽度撑满，子项为固定或内容宽度；滚动页内容常不满一屏。或显示卡片用 layoutWeight 分高，源端卡内内容 wrap_content 自上而下排列并带上内边距。也包括 Compose Column 未声明 horizontalAlignment（默认 Start），文本只带水平 padding 而无 fillMaxWidth，仅个别项以 fillMaxWidth + TextAlign.Center 居中。

## 原因

ArkUI Column 的交叉轴默认是 Center，把源端“没写 gravity”照搬成“不写 alignItems”，返回键、标题、列表行就会被居中；父 Stack 的 alignContent 只放置 Column 本身，不影响其子项。Scroll 对不满一屏的内容也会纵向居中，而 NestedScrollView 是顶锚。来源中写者在源端本来居中的空态上显式写了 Center，却在源端默认对齐处什么都没写。另一应用计算器显示区源端自上而下排列（上内边距 18dp），生成者写成 justifyContent(FlexAlign.End)，数值落到显示卡片底部。另一应用中，添加城市页的内容 Column 未写 alignItems(Start)，分组标题被居中，而写者写前已读到陷阱表中对齐需显式设置的条目。另一应用的 Compose 页面中，转换者读到标题、价格、正文都只带水平 padding，写进未设 alignItems 的 Column 后整体居中；给内容宽的 Text 加 textAlign(Start) 也无效，因为 textAlign 只作用于 Text 自身框内。

## 做法

1. 源端默认起始对齐时（Android 纵向 LinearLayout 未写 gravity、Compose Column 未写 horizontalAlignment），对应 Column 显式写 alignItems(HorizontalAlign.Start)，或给子项 alignSelf，或给文本 width('100%') + textAlign(TextAlign.Start)；只有源端写了 center/center_horizontal，或 fillMaxWidth + TextAlign.Center 的项才居中。内容宽的 Text 只加 textAlign 不会改变它在父容器中的位置。
2. 每写完一个撑满宽的 Column，逐个核对固定尺寸或内容宽子项的水平位置由谁决定。
3. ScrollView/NestedScrollView 转成 Scroll 时，源内容贴顶就给 Scroll 的子容器加 constraintSize({ minHeight: '100%' }) 一类约束使其顶锚，并确认超出一屏后仍能滚动。
4. 容器被 layoutWeight 撑高而源端内容贴顶时，写 justifyContent(FlexAlign.Start) 并沿用源端上内边距，不改成底对齐。
