# 源纵向容器或 Compose Row 未写交叉轴对齐时，ArkUI Column/Row 显式写起始或顶端对齐（ArkUI 默认居中）

ID：`lesson-08b9064f678f1635e647` · 版本：11

[本主题](index.md)

## 何时使用

界面实现阶段，把未写 gravity 的纵向 LinearLayout、以 constraintStart_toStartOf=parent 靠起始边的 ConstraintLayout wrap_content 子项、未传 horizontalAlignment 的 Compose Column 或未传 verticalAlignment 的 Compose Row 转成 ArkUI Column/Row 时

## 适用情境

源纵向 LinearLayout 没写 gravity（子项默认贴起始边），或 wrap_content 子项以 constraintStart_toStartOf=parent 靠起始边；Compose Column 未声明 horizontalAlignment（默认 Start），文本只带水平 padding 而无 fillMaxWidth，仅个别项以 fillMaxWidth + TextAlign.Center 居中；Compose Row 未写 verticalAlignment（默认 Top），子项高度不等。目标 Column 宽于子项（width('100%') 或约束宽），子项为固定或内容宽度。也包括容器被 layoutWeight 分到更高的高度，而源端卡内内容 wrap_content 自上而下排列。

## 例外与边界

- 源端写了 gravity=center/center_horizontal、Compose horizontalAlignment=CenterHorizontally，或子项 fillMaxWidth + TextAlign.Center：这些项按源端居中
- Stack 子项在父容器中的位置、Scroll 内不满一屏的内容位置和空态的纵向位置是另外的决策，不由 Column 的 alignItems 决定

## 原因

ArkUI Column 的交叉轴默认 HorizontalAlign.Center、Row 默认 VerticalAlign.Center（官方文档的默认值，column.d.ts/row.d.ts 未注明，设备上可直接观察）；把源端“没写 gravity”照搬成“不写 alignItems”，返回键、标题、列表行就会被居中。textAlign 只作用于 Text 自身框内，不改变内容宽的 Text 在父容器中的位置；父 Stack 的 alignContent 只放置 Column 本身，不放置其子项。

## 做法

1. 源端默认起始对齐时（纵向 LinearLayout 未写 gravity、Compose Column 未写 horizontalAlignment），对应 Column 显式写 .alignItems(HorizontalAlign.Start)，或给个别子项 alignSelf，或给文本 width('100%') + textAlign(TextAlign.Start)；只给内容宽的 Text 加 textAlign 不够。
2. Compose Row 未写 verticalAlignment 时，ArkUI Row 显式写 .alignItems(VerticalAlign.Top)。
3. 容器被 layoutWeight 撑高而源端内容 wrap_content 自上而下排列时，保持 justifyContent(FlexAlign.Start)，上内边距取当前 XML 的 paddingTop 或 Compose padding，不改成底对齐。
4. 写完逐个对照本页每个 Column()/Row() 的源端构造参数或 gravity，确认固定尺寸与内容宽子项的位置由该容器自己的 alignItems 决定；规格里的“左上角”“左对齐”也要落成 alignItems 或 alignSelf。
