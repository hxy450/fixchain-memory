# 点击处理器里的按键音与振动迁移时，复制源音频并按源音频用途选 StreamUsage，加载完成后再播，振动声明权限

ID：`lesson-3fd89449423aa8b63769` · 版本：2

[本主题](index.md)

## 何时使用

界面迁移阶段，实现按键音、点击振动这类点击副作用时

## 适用情境

源端点击处理器经 SoundPool、MediaPlayer 或封装的播放工具播放 assets、res/raw 中的音效，经 Vibrator 振动，开关常由偏好控制；目标需要等价的播放与振动。

## 例外与边界

- 振动来自框架自带触感（如 Compose combinedClickable 的长按），不在处理器代码里：按长按触感的规则补调用

## 原因

音效的音量与静音策略随播放时声明的音频用途而定：源端 SoundPool.Builder 未设属性时为 USAGE_MEDIA（SoundPool.java），MediaPlayer.create 未传属性时按 USAGE_UNKNOWN 归入 STREAM_MUSIC（MediaPlayer.java、AudioAttributes.java），显式设了 USAGE_ASSISTANCE_SONIFICATION 等用途才走其他流；目标选的用途与源端不符，音量与静音表现就不同。音频在加载完成前播放会无声；振动需要权限，实际震感还受系统触感设置影响。

## 做法

1. 从源端播放工具定位实际音频文件复制到 rawfile；读源 SoundPool/MediaPlayer 的 AudioAttributes（usage）或 streamType：未设置时走媒体流，目标用 @ohos.multimedia.audio.d.ts 的 StreamUsage.STREAM_USAGE_MUSIC；源端显式设了其他用途时，在 StreamUsage 里选用途相符的值。
2. 加载完成后才允许播放（SoundPool 的 loadComplete 回调或播放器就绪状态），偏好开关关闭时不播放、不振动。
3. 振动在 module.json5 声明 ohos.permission.VIBRATE，用 vibrator.startVibration 按源时长或效果振动；交付前在真机逐个点击确认可闻、可感。
