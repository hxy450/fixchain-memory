# Activity 级 onKeyDown 映射到页面根节点的 onKeyEvent，并让页内至少一个组件可获焦，把焦点链带进本页

ID：`lesson-80e1d2c095a3698a7156` · 版本：4

[本主题](index.md)

## 何时使用

页面实现与输入接线阶段，为源端 Activity 级硬件按键回调（onKeyDown、dispatchKeyEvent）选择 ArkUI onKeyEvent 的挂载节点时；接收“焦点获取归本任务”一类移交时

## 适用情境

安卓源在 Activity 上覆写 onKeyDown 或 dispatchKeyEvent 处理方向键、MENU、Ctrl+Z 等，不依赖某个 View 持有焦点；目标页面是 Navigation 下的 NavDestination 或 @Entry 页，交互由内部 Canvas、自绘子组件或 Image + onClick 承载。也包括页内没有 Button/TextInput 或 focusable(true) 组件，源端按键控件是缺省可获焦的 ImageButton/Button。

## 例外与边界

- 源端在输入框获焦时放行部分按键（如判当前焦点为 EditText 才处理）：放行判据按根级快捷键放行输入框的规则处理，本条只决定挂载点与焦点链

## 原因

ArkUI 按键沿焦点链派发：页内没有任何可获焦组件时，焦点链不经过本页，挂在根节点的 onKeyEvent 也收不到；子组件的 onKeyEvent 只有在焦点链上才会收到，获焦子节点未消费的事件会冒泡到根节点。源端 onKeyDown 只收子控件未消费的键，dispatchKeyEvent 则在子控件消费前截获，根节点冒泡收不到已被子组件消费的键。

## 做法

1. 源端是 Activity 的 onKeyDown 时，把 .onKeyEvent 挂在页面根节点（NavDestination 或 @Entry 根组件）上；按源端只在按下时触发的语义加 KeyType.Down 过滤，源端吞掉的键（如 MENU）同样返回 true。
2. 源端是 dispatchKeyEvent（子控件消费前拦截）时，在根节点用 onKeyEventDispatch（common.d.ts，API 15 起，自定义按键事件的处理与分发）先处理再决定是否下发，不只靠根节点冒泡；d.ts 未写明它的返回值对子组件是否还收到事件的影响，接线时用日志确认。
3. 核对页内有可获焦的叶子控件：源端 ImageButton/Button 缺省可获焦，目标对应的 Image/按钮设 focusable(true)（源端焦点态不可见时把焦点框设为透明样式），焦点进入本页后事件冒泡到根节点。
4. 确需挂在子组件上时同时写出获焦机制，并确认页面显示后的实际焦点节点就是该组件；“某容器不支持 onKeyEvent”一类判断先查 common.d.ts。收到“焦点获取归本任务”的移交时，改挂到根节点并落地可获焦组件才算完成。

## 可选检查

- 对挂载点有疑问时，在设备上注入方向键，同时看 hilog 中的当前焦点节点，并在根节点 onKeyEvent 入口打日志：入口没有日志说明事件没到达本页，有日志而 consumed 为 0 说明处理器返回了 false。
