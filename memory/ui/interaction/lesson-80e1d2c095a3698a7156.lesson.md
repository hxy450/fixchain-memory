# Activity 级 onKeyDown 映射到页面根节点（NavDestination 或 @Entry 根）的 onKeyEvent，不挂在需先获焦的子组件上

ID：`lesson-80e1d2c095a3698a7156` · 版本：1

[本主题](index.md)

## 何时使用

页面实现与输入接线阶段，为源端 Activity 级硬件按键回调（onKeyDown、dispatchKeyEvent）选择 ArkUI onKeyEvent 的挂载节点时；接收“焦点获取归本任务”一类移交时

## 适用情境

安卓源在 Activity 上覆写 onKeyDown 或 dispatchKeyEvent 处理方向键、MENU 等，不依赖某个 View 持有焦点；目标页面是 Navigation 下的 NavDestination 或 @Entry 页，交互由内部 Canvas 或自绘子组件承载。

## 原因

ArkUI 按键沿焦点链派发，子组件的 onKeyEvent 只有在焦点链上才会收到；只写 focusable(true) 不会让它获焦，页面焦点停在根节点时事件不经过子组件。来源中转换者误以为 NavDestination 不支持 onKeyEvent 而挂到 Canvas，后续切片只改了返回值与按下守卫；返修中 defaultFocus 与 onReady 时 requestFocus 都没生效，移到 NavDestination 后按键正常，获焦子节点的事件也会冒泡到这里。

## 做法

1. 源端是 Activity 级按键回调时，把 .onKeyEvent 挂在页面根节点（NavDestination 或 @Entry 根组件）上；按源端只在按下时触发的语义加 KeyType.Down 过滤，源端吞掉的键（如 MENU）同样返回 true。
2. 确需挂在子组件上时同时写出获焦机制，并确认页面显示后的实际焦点节点就是该组件；“某容器不支持 onKeyEvent”一类判断先查 SDK 声明。收到“焦点获取归本任务”的移交时，改挂到根节点或落地获焦代码才算完成。

## 可选检查

- 对挂载点有疑问时，在设备上注入方向键，查看 hilog 中的当前焦点节点与 consumed 结果。
