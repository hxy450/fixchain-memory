# 迁移带点击绑定的控件时，按源点击处理器与 ViewModel 的分支逐项迁移副作用和状态转换，不只做状态取反和换图

ID：`lesson-55e33a0621c3008ab8b3` · 版本：5

[本主题](index.md)

## 何时使用

界面迁移阶段，为布局中带 onClick 绑定、状态选图或滑动面板的控件编写 ArkUI 事件与状态逻辑时；还原由页面弹层触发的选择与写操作时

## 适用情境

源布局控件用 android:onClick、数据绑定或 setOnClickListener 声明点击，或按 ViewModel 状态选图；实际行为（按键音、振动、偏好持久化、面板展开与回填、存储写入）写在 Fragment/Activity 的统一点击处理器（when (v.id) 分支）、ViewModel 或共享弹层组件中。也包括 ViewModel 里同项再点取消、前置为空即失败、同键累加写入等状态转换由页面弹层触发。

## 原因

布局只说明控件可点和怎样换图，副作用与状态转换写在处理器和 ViewModel 里；只迁外观的控件会切换图标却没有功能，面板指示图被当成静态装饰，写操作只弹成功提示而没有写入。

## 做法

1. 对每个声明了点击或状态绑定的控件，在统一点击处理器与 ViewModel 找到对应分支，列出副作用（播放哪些音频、振动、写哪个偏好键、打开哪个面板、写哪份存储）后再写 onClick；未迁移的副作用在报告中逐项列为缺口。
2. 源码读取被截断时，按控件 id 或状态名补读被截断段；补读到的行为逐条落实，不只同步默认值或命名。
3. 滑动面板、历史列表一类组件的展开、收起与数据回填按交互迁移，与规格中的相应验收项对应实现。
4. ViewModel 与共享组件里的状态转换（同项再点取消、前置校验失败、同键累加、成功后关闭弹层）逐条列入实现清单，写完对照代码分支；交互交给共享组件时先打开其源码核对点击切换与按钮可用条件。
5. 写操作类点击先落到下游页面可读取的状态或存储，再给成功提示；本轮不实现写入时，提示与完成汇报都写明“未写入”，不输出成功提示。
