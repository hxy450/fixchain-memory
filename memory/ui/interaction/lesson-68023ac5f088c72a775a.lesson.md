# 源端 onTouch 用未掩码的 getAction 只跟随首指时，先看手指由谁接收：单个视图独占全部手指才按 touches.length 过滤；多个兄弟控件各自监听（安卓默认分指）时按控件内 pointer id 集合判首指与末指

ID：`lesson-68023ac5f088c72a775a` · 版本：2

[本主题](index.md)

## 何时使用

输入控制的规格提取与实现阶段，把 Android onTouch 的 MotionEvent 动作分支和坐标读取映射为 ArkUI onTouch 的 TouchType 分支与触点来源时

## 适用情境

源端 OnTouchListener 用未掩码的 event.getAction() 只匹配 ACTION_DOWN/MOVE/UP，以无索引的 getX()/getY()（指针索引 0）读坐标，附加手指的 POINTER_DOWN/UP 不进入任何分支；目标 ArkUI .onTouch 对每根手指都派发 TouchType.Down/Up，TouchEvent 同时提供 touches（在屏触点）与 changedTouches（本次变化的触点）。 也包括源端多个兄弟控件（方向键、旋转键等）各自 setOnTouchListener，targetSdk≥11 且未设 splitMotionEvents=false，窗口默认分指，每个控件只收落在自己身上的指针流；目标每个按钮各挂 .onTouch，而 TouchEvent.touches 列出屏幕上全部手指。

## 例外与边界

- 源端用 getActionMasked() 处理 POINTER_DOWN/UP，或按 pointerId 跟踪多指时，按源端的多指语义逐指映射

## 原因

ArkUI 回调的派发粒度比源端细，桥接处不过滤，源端忽略的事件就会进入状态机：逐一映射 Down/Up 并统一取 changedTouches[0] 时，第二指按下被当成新的 ACTION_DOWN 而重置起点，Move 跟着本次变化的手指在两指间跳动，首指抬起被当成 ACTION_UP，两指同向滑动可能触发反向手势。touches 是全屏触点：多按钮时按 touches.length 过滤，会把另一按钮上的手指当作本控件的附加手指，丢掉第二个按钮的按下与第一个按钮的抬起，按钮卡在按下态。

## 做法

1. 先确认源端由哪个视图接收手指。单个视图独占全部手指（如整屏棋盘）时：Down/Up 事件中 event.touches.length > 1 直接忽略，只让首指按下、末指抬起进入状态机，Move 取 event.touches[0]，首指 Down、末指 Up 与 Cancel 取 changedTouches[0]。多个兄弟控件各自监听时：在每个控件内按 changedTouches[0].id 维护落在本控件的指针集合，集合为空时的 Down 算按下，移除后集合为空的 Up 算抬起，Cancel 清空并抬起。
2. 规格映射动作分支时写明源端用的是 getAction() 还是 getActionMasked()、附加手指是否参与、窗口是否分指（每个控件只收自己的指针流），并写出目标端的过滤规则，不用“TouchType.Down/Move/Up 行为等价”一句带过；按键 Down/Up 双派发等同类细粒度回调，也先写明源端实际进入分支的事件子集再过滤。

## 可选检查

- 两指同时同向滑动只触发一次该方向的移动，单指四向仍各触发一次。
- 按住一个按钮再点另一个按钮，两者各自恰好产生一次按下、一次抬起，不卡按。
