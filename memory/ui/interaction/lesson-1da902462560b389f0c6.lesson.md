# 源端自写触摸状态机或用框架手势助手（ItemTouchHelper 等）时按阈值、跟手与取消逐项移植，不换成识别器手势

ID：`lesson-1da902462560b389f0c6` · 版本：1

[本主题](index.md)

## 何时使用

规格提取与界面实现阶段，为源端 onInterceptTouchEvent/onTouch 状态机、ItemTouchHelper 滑删、ScaleGestureDetector 缩放或三方查看器手势选择 ArkUI 承接方式（onClick、SwipeGesture/PanGesture/PinchGesture 或 onTouch 逐事件）时

## 适用情境

源码里有带阈值、按压时序、跟手位移、速度判定或 CANCEL 的触摸处理（DOWN 记点、MOVE 超过阈值取消点击、UP 时仍按下才算点击），或交给 ItemTouchHelper、ScaleGestureDetector、ViewPager 等框架或三方手势类；规格写「目标点击与滑动天然分离，无需迁移」，映射参考把它们列为「SwipeGesture」「PinchGesture 直接映射」。

## 例外与边界

- 源端只用识别器式回调（setOnClickListener、setOnLongClickListener），没有附加阈值或取消逻辑

## 原因

识别器一识别就回调：SwipeGesture 没有跟手位移、滑出比例阈值、甩动速度与回弹，onClick 不会在外层 Swiper/List 开始拖动时按源阈值取消，PinchGesture 没有源检测器的开始条件与焦点规则。映射参考里的对应行只是组件候选，不证明行为等价；源状态机被登记为“无需迁移”后，阈值类验收条目就没有承接代码。

## 做法

1. 按源方法体逐项列出：按下记点、跟手位移、距离与速度阈值、按压时序、取消条件、松手后的落定或回弹；框架手势类未覆写的参数取框架默认值（例：androidx recyclerview ItemTouchHelper.Callback 的 getSwipeThreshold 为 0.5 个条目宽，甩动速度取 dimen item_touch_helper_swipe_escape_velocity 120dp/s；touch slop、TAP_TIMEOUT 取本机 SDK 的 ViewConfiguration）。
2. 源端是 MotionEvent 级处理时用 onTouch 逐事件移植，并在外层 Swiper/List/Scroll 开始拖动时（如 onGestureSwipe、onScrollStart）让本次按下失效、不再触发点击；ItemTouchHelper 滑删用 PanGesture 或 onTouch 跟手位移，松手按比例阈值或甩动速度决定滑出，否则回弹；源端交给 GestureDetector/ScaleGestureDetector 的按本机 SDK 源码逐段移植检测器，不按参数清单自建。
3. 规格把这些项写成行为验收条目并与转换决策表一致；要写「目标内建、无需迁移」，先核实目标事件模型（例如 Swiper 开始拖动后子节点 onClick 是否仍触发）。三方查看器的缩放、双击、拦截不在仓库时，取库制品核对后再选手势。
