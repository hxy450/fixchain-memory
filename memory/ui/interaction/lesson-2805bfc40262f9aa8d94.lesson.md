# 源端 onTouch 交给 GestureDetector 时，按其容差、长按、双击与抛掷速度条件复刻 onFling，不改成位移阈值状态机

ID：`lesson-2805bfc40262f9aa8d94` · 版本：3

[本主题](index.md)

## 何时使用

输入控制的规格提取与实现阶段，把交给 GestureDetector 的滑动、抛掷手势映射为 ArkUI onTouch 或手势识别器时

## 适用情境

源端 OnTouchListener 只 return gestureDetector.onTouchEvent(event)（new GestureDetector、extends SimpleOnGestureListener），方向判定写在 onFling/onScroll 里；目标准备在手势区域用 .onTouch 手写 Down/Move/Up 状态机，或用 PanGesture、SwipeGesture 等识别器替代。

## 例外与边界

- 源端 onTouch 自己按 getAction 分支、不经 GestureDetector：按原始动作桥接的首指过滤处理

## 原因

GestureDetector 回调 onFling 前有一组前置条件：按下后移出触摸容差前不算滑动，长按超时后的拖动与双击的第二击不回调 fling，抬起时 VelocityTracker 估出的速度须超过最小抛掷速度并以最大速度封顶。简化成“位移超阈值且速度大于 0”，或用总位移除以总时长代替抬起前的速度，源端不触发的手势也会触发。这些阈值来自 ViewConfiguration：触摸容差可被设备资源覆盖，长按超时读取系统设置。

## 做法

1. 规格把 GestureDetector 的触发条件写进契约，不只转写 onFling 内的位移/速度矩阵。阈值按参照设备的 Android 运行版本与源端 GestureDetector 配置确定：能在参照设备上读取时，用该环境 ViewConfiguration 的有效值（getScaledTouchSlop、getScaledMinimumFlingVelocity、getScaledMaximumFlingVelocity 分别为 px 与 px/s，getLongPressTimeout、getDoubleTapTimeout 为 ms）；只有源码时，写明所查系统版本与默认值（例：android-36.1 中 config_viewConfigurationTouchSlop 为 8dp，DEFAULT_LONG_PRESS_TIMEOUT 为 400ms，DOUBLE_TAP_TIMEOUT 为 300ms，最小/最大抛掷速度为 50/8000 dp/s），并注明设备资源与系统设置可能改变这些值。targetSdk 是兼容目标，不是运行版本，只在源码里对应的兼容分支中单独考虑。
2. 实现等价检测器：移出容差前不进入滑动，长按超时后取消抛掷判定，多指时取消点击，用抬起前最近一段触点估计速度并按最小/最大抛掷速度判定 fling，满足后再调用源 onFling 的方向判定。
3. 用 .onTouch 手写时，Up 事件的 touches 仍含正在抬起的手指，末指抬起按 type === Up 且 touches.length === 1（或按 id 跟踪）判定。
