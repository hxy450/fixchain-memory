# 源端监听回调体或 Adapter 数据绑定被注释时按未启用行为迁移；审计不因“已裁定/集成点”注释放行与源端运行态相背的接线

ID：`lesson-f3e614f295aa409485fd` · 版本：3

[本主题](index.md)

## 何时使用

界面实现阶段，转换带点击监听的控件或 item 布局中由 Adapter 绑定的自定义绘制 View 时；1:1 对齐审计与修复阶段，判定目标端交互接线或数据绑定是否与安卓运行态一致，或重写组件时决定是否保留随行的 onClick 时

## 适用情境

安卓控件注册了 setOnClickListener，但回调体被整段注释（如选图调用被注释），XML 也可能写着 clickable；或 Adapter 对自定义绘制 View（曲线、进度、图表）的数据绑定整段被注释，只剩 XML 静态属性，ViewModel 仍计算着可能用于绑定的值。目标端按规格集成点把它接成可用功能，或据注释代码、ViewModel 中间值重建动态效果；代码注释可能自述源码为死码并写着“裁定/集成点”；项目要求 1:1 忠实复刻（含源码缺陷）。

## 例外与边界

- 项目决策明确要求启用该功能，且用户已知并接受与源端不同

## 原因

被注释的代码不构成运行行为：监听注册行、clickable 属性和被调方法存在都不代表点击有效果；按注释掉的绑定或 ViewModel 的中间值重建动态效果，会画出源端从未显示的内容。只凭注册行推断“可点击”，或因注释写着“已裁定”就不列差异，会把源端没有的行为一直保留到交付。反过来，回调为空只说明业务副作用未启用：CheckBox/Switch 等 CompoundButton 仍会自行切换状态，自定义 View 的默认外观也常写在构造与字段默认值里。

## 做法

1. 核点击行为时打开监听回调体全文；回调为空或调用被注释，判定该回调的业务副作用未启用，不接成功能；控件自身的默认行为（CompoundButton.java 的 performClick 先 toggle() 再回调监听，空回调也会切换勾选）与其他仍有效的监听照源迁移。
2. Adapter 中对自定义 View 的数据绑定被注释时按未启用处理：除 XML 静态属性外，一并读该 View 类的构造、字段默认值与仍在调用的 setter，按实际默认绘制结果实现，不据注释代码或 ViewModel 中间值重建动态效果。
3. 需要启用被注释的行为时，作为新需求或决策差异登记，并让用户知情。
4. 审计遇到写着“裁定/集成点/决锚”的偏差，先核该裁定下的运行行为是否与安卓一致；注释自述源码为死码而目标已接活时，列为差异或单列给用户裁决，不静默排除。
5. 重写含交互修饰的组件结构时，对随行搬运的 onClick 等接线逐个找源码依据；与文件注释、审计结论中“源码死码”的说法冲突时，先回读源码再决定保留或摘除。
