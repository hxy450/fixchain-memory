# 源端监听回调体被注释时按无响应控件迁移；审计不因“已裁定/集成点”注释放行与源端运行态相背的接线

ID：`lesson-f3e614f295aa409485fd` · 版本：1

[本主题](index.md)

## 何时使用

1:1 对齐审计与修复阶段，判定目标端交互接线是否与安卓运行态一致，或重写组件时决定是否保留随行的 onClick 时

## 适用情境

安卓控件注册了 setOnClickListener，但回调体被整段注释（如选图调用被注释），XML 也可能写着 clickable；目标端按规格集成点把它接成可用功能，代码注释自述源码为死码并写着“裁定/集成点”；项目要求 1:1 忠实复刻（含源码缺陷）。

## 例外与边界

- 项目决策明确要求启用该功能，且用户已知并接受与源端不同

## 原因

监听注册行、clickable 属性和被调方法存在都不代表点击有效果；只凭注册行推断“可点击”，或因注释写着“已裁定”就不列差异，会把源端没有的交互一直保留到用户发现。来源中只读审计读到回调体只剩被注释的调用，也承认与源端相背，仍按“已裁定偏差”不报；随后的修复轮只 grep 到注册行就判“点击可用”，重写头部卡时把 onClick 原样带入，直到用户指出安卓点头像不会弹出拍照/相册。Adapter 中被注释的数据绑定是同类机制。

## 做法

1. 核点击行为时打开监听回调体全文；回调为空或调用被注释即判定点击无响应，按无响应控件迁移，需要启用时作为新需求或决策差异登记。
2. 审计遇到写着“裁定/集成点/决锚”的偏差，先核该裁定下的运行行为是否与安卓一致；注释自述源码为死码而目标已接活时，列为差异或单列给用户裁决，不静默排除。
3. 重写含交互修饰的组件结构时，对随行搬运的 onClick 等接线逐个找源码依据；与文件注释、审计结论中“源码死码”的说法冲突时，先回读源码再决定保留或摘除。
