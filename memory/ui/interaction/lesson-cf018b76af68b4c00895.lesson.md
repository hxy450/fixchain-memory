# 弹窗防穿透的 Block 只放在无子控件的遮罩层，内容面板与根容器保持 Default；改真弹窗 API 后删掉自绘防穿透

ID：`lesson-cf018b76af68b4c00895` · 版本：2

[本主题](index.md)

## 何时使用

弹窗或浮层实现与改造阶段，为遮罩、内容面板、根容器设置 hitTestBehavior，或把页面内浮层迁到 showCustomDialog/showBindSheet、openCustomDialog 等真弹窗时

## 适用情境

弹窗或底部面板采用“根 Stack + 遮罩 + 内容面板”结构，在根或内容面板上写 hitTestBehavior(HitTestMode.Block)（含 visible ? Block : None）防止点击穿透；面板内有按钮、checkbox、列表项等要响应点击的子控件。也包括源端用全屏空 clickable 拦截层防穿透、遮罩点击关闭、居中卡片阻止冒泡，目标在包住遮罩、卡片、滑杆与滚动区的弹层根 Stack 上写 Block。

## 原因

HitTestMode.Block 让节点自身参与命中测试并阻断子节点和兄弟节点，写在内容面板或根容器上时，面板内按钮、checkbox 与整行点击都无法命中，hilog 显示 Touch test result is empty。框架弹窗已自带模态遮罩与外部点击处理，迁到真弹窗后仍保留的内容容器 Block 会变成弹窗内容根。来源中两次把页内浮层改成 harmony-dialog 时都只删了外层遮罩的 Block，保留了包住按钮或列表的内容 Column 的 Block，导致“立即升级”、checkbox 与整行点击全部无响应；生成期别的浮层已发现同类问题并定过“交互容器 Default、只留遮罩 Block”的规则，这两个弹窗没有被扫到。

## 做法

1. 防穿透只写在没有可点击子控件的遮罩层（Block，或 Default 加 onClick 关闭）；承载按钮、checkbox、列表的内容面板与根容器用 Default；需要把事件让给下层时用 Transparent 或 None。
2. 把页内浮层改为真弹窗 API 时，删掉全部自绘遮罩与 visible ? Block : None 一类写法，并对照同仓已有真弹窗内容检查目标控件的整条祖先链。
3. 在一个弹窗发现 Block 吞掉子项点击后，按 HitTestMode.Block 检索同类弹窗与浮层，逐个确认它是否包住可点击的子控件。
4. 源端已有全屏拦截层时由该层承担防穿透，弹层根容器保持 Default；对 hitTestBehavior 各值对子节点的作用拿不准时，先查交互映射参考的触摸测试表或 SDK 声明，不凭记忆定稿。

## 可选检查

- 交付前在真机点击面板内至少一个子控件，或用 uitest dumpLayout 查看目标控件祖先链的 hitTestBehavior。
