# Material 交互组件的声明尺寸、布局占位和触控区域应分开映射

ID：`lesson-b7e0ff573247b0324bef` · 版本：2

[本主题](index.md)

## 何时使用

规格提取或界面实现阶段，将 Material 交互组件的 size 映射为目标端固定尺寸时

## 适用情境

源端 IconButton 等交互组件带 size 修饰符，同时受组件库最小交互尺寸与约束影响；源码合成快照缺少实际 bounds。

## 例外与边界

- 当前版本与配置已明确关闭相关最小尺寸约束，或已有覆盖目标状态的可靠布局与视觉边界

## 原因

调用方 size 的字面值不足以确定库组件的最终布局、可见内容和触控区域；将它们当作同一个尺寸，会把推断固化进规格和目标端位置。

## 做法

1. 以 `minimumInteractiveComponentSize` 等公开机制为线索，结合当前 Material 版本、约束和配置，分开记录声明尺寸、布局占位、图标/背景实绘范围与触控区域；不默认它们相同。
2. 已有库规则或当前基线足够时据此映射；没有 bounds 且条件不明时保留具体疑问，不把某次修复的 48dp 变成所有小按钮的强制尺寸。
3. 调整布局占位时同步保留源端视觉中心和对齐关系，不机械地只改宽高而固定原左上角。

## 可选检查

仅在适用条件不确定、与当前输入冲突或需要验证关键假设时按需执行；优先复用已有证据和正常测试。
不因读取本条经验而额外启动验证流程；项目原有必需测试照常执行。

- 仅当最小交互约束是否生效会改变当前实现、且现有输入无法裁决时，优先复用已有 dump 或正常页面测试核对布局与视觉边界。
