# 源码调用项目自定义图片组件时先读组件定义（含被父级自定义 Layout 放置时）：CircleShape + Crop 译为 Cover + borderRadius(边长/2) 并确认裁剪生效，不以裸 Image + Contain 代替

ID：`lesson-9dcd69d2824702310959` · 版本：2

[本主题](index.md)

## 何时使用

页面转换与巡检修复阶段，把 Compose 页面里的自定义图片组件调用翻译为 ArkUI Image，确定形状、裁剪与填充方式时；把 Compose 自定义 Layout（measurables、Constraints.fixed、placeRelative）转写为 ArkUI Stack/position，为被放置的子组件落定形状时

## 适用情境

Compose 页面通过项目自定义组件（ui/components 下的 XxxImage 一类）渲染图片，shape = CircleShape、contentScale = Crop 写在组件定义里，调用点只传资源与 size/modifier；页面规格只写图片尺寸；目标端的共享组件可能尚未生成，或页面选择内联 Image。也包括父级自定义 Layout 以 Constraints.fixed 给共享图片组件指定尺寸和位置、容器再裁掉溢出，形状写在子组件定义里，同页另一处也调用同一组件。

## 原因

调用点看不到形状与裁剪，把自定义组件当成平台 Image 翻译就会得到矩形或方形图，ImageFit.Contain 还会留边。来源中三个页面转换者都读到了自定义图片组件的调用却没打开定义，高亮卡、购物车行、搜索分类、详情头图全部写成 Image + Contain；巡检只报了其中一处，修复也只改了那一处。父 Layout 只提供子项的尺寸与位置；逐条翻译父级测量与放置时，容易把子组件当普通 Image，而同页另一处调用却按圆形写对了。

## 做法

1. 调用的若是 import 自项目 ui/components 等位置的自定义组件，写前打开其定义，把 shape/clip 与 contentScale 一并翻译：CircleShape + Crop 对应 objectFit(ImageFit.Cover) + borderRadius(边长 / 2)，并确认圆形裁剪实际生效（来源最终同时加了 clip(true)）；目标已有对应共享组件时直接复用。
2. 巡检或返修发现某个组件调用点形状不对时，按组件名检索全部调用点逐一核对，不只修报告列出的那一处。
3. 子组件被父级自定义 Layout 放置时，照样按其定义补齐形状、裁切与内容缩放，同时保留父级对溢出的裁剪。
