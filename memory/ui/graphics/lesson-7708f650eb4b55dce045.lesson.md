# android:background 的整屏背景位图按拉伸铺满映射，不默认用 ImageFit.Cover 裁切；被铺满且未置顶的 SurfaceView 盖住时不建背景层

ID：`lesson-7708f650eb4b55dce045` · 版本：2

[本主题](index.md)

## 何时使用

界面实现阶段，把源根布局的 android:background 背景图转换为 ArkUI 背景 Image 或背景图属性时；规格提取阶段为承载自绘游戏视图的页面确定背景层与画布叠放关系时

## 适用情境

源根容器以 android:background=@drawable/xxx 铺设整屏背景位图，背景上画有需要完整显示的图文；目标用 Stack 底层 Image 或背景图属性重建。 也包括根容器内 addView 或布局了铺满的 SurfaceView/GLSurfaceView 子类（未调用 setZOrderOnTop(true)，绘制时 drawColor(Color.TRANSPARENT, PorterDuff.Mode.CLEAR) 清屏或不画底色），目标准备用 Stack 叠放背景 Image 与透明 Canvas。

## 例外与边界

- 源端是 ImageView 且显式 scaleType=centerCrop 一类裁切语义，按该 scaleType 映射
- 源容器内铺满的 SurfaceView/GLSurfaceView/VideoView 未 setZOrderOnTop(true)：该区域的父容器背景在源端不可见，不建背景层，按做法第 1 步取可见底色

## 原因

View 背景位图按视图边界拉伸铺满、不裁切；Cover 等比铺满会裁掉上下或左右，背景上的关键图文被截掉。来源中生成者读到根布局背景与资源尺寸，仍写 objectFit(ImageFit.Cover)，顶部图文被裁，修复改为 ImageFit.Fill。 背景要在源端最终渲染中可见才需要迁移：SurfaceView 的 surface 默认在其所在窗口之下合成，SurfaceView 在窗口上打洞让 surface 显示（Android SurfaceView 类文档；本机 android-36.1 源码 SurfaceView.java 类注释），铺满的 SurfaceView 区域内父容器的 android:background 被擦掉，可见的是 surface 自身内容，清成透明时为黑。ArkUI Canvas 的 clearRect 清成透明后会露出下层组件，把源容器背景放到画布下层，本该黑底的画面就显示出背景图。

## 做法

1. 源 android:background 的位图背景用 ImageFit.Fill（或等效铺满方式）映射；确需等比裁切时，先用资源宽高比与目标屏幕比例核对关键图文不会被裁。 映射前先确认该背景在源端最终可见：容器内有铺满的 SurfaceView/GLSurfaceView 子类时，打开该视图类核对父类、构造器与 SurfaceHolder 设置（grep setZOrderOnTop|setZOrderMediaOverlay|setFormat|getHolder）和清屏方式；未 setZOrderOnTop(true) 时该区域不建背景 Image 层，目标底色取 surface 的实际可见色（每帧清成透明即为黑），每帧 clearRect 照旧。规格或派工给出的背景层与这些源码事实冲突时，按源端可见结果实现，并回报规格分歧。
