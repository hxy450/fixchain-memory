# 源端可见的整屏 android:background 普通位图按拉伸铺满映射；被铺满且未置顶的 SurfaceView 遮住时不建背景层

ID：`lesson-7708f650eb4b55dce045` · 版本：5

[本主题](index.md)

## 何时使用

规格提取与界面实现阶段，把源根布局或容器的 android:background 背景图转换为 ArkUI 背景 Image 或背景图属性时

## 适用情境

源根容器以 android:background=@drawable/xxx 铺设整屏背景，该 drawable 是普通位图（png/jpg，或未设 gravity/tileMode 的 <bitmap>，BitmapDrawable.java 默认 gravity=FILL），背景上画有需要完整显示的图文，且在源端最终渲染中可见；目标用 Stack 底层 Image 或背景图属性重建。也包括容器里放了铺满的 SurfaceView 自绘视图，规格仍按布局属性给画布下加背景层。

## 例外与边界

- 容器内有铺满的 SurfaceView/GLSurfaceView/VideoView 且源码没有 setZOrderOnTop(true)：窗口在该区域打洞，父容器背景不可见，可见的是 surface 自身内容（清成透明即为黑）；不建背景层，底色取 surface 的实际可见色。ArkUI Canvas 的 clearRect 会露出下层组件，不能把源容器背景当作画布下的底层 Image
- 源端是 ImageView 且显式 scaleType=centerCrop 一类裁切语义，按该 scaleType 映射
- 背景是设了 gravity 或 tileMode 的 <bitmap>：按其定位或平铺映射（common.d.ts 的 backgroundImagePosition、backgroundImage 的 ImageRepeat）
- 背景是 .9.png：按九宫格拉伸，用 Image.resizable（image.d.ts）或 backgroundImageResizable（common.d.ts）按源 .9 的拉伸区设 slice
- 背景是 layer-list 或按产品 flavor 覆盖：按生效版本逐层落成组件

## 原因

View 背景的普通位图按视图边界拉伸铺满、不裁切；Cover 等比铺满会裁掉上下或左右，背景上的关键图文被截掉。默认 Z 序的 SurfaceView 合成在窗口之下，窗口在其区域打洞，父容器背景在该区域被擦掉（Android 框架 SurfaceView.java 的透明区域收集）；按布局属性照搬背景层，目标画布每帧清屏后会露出这张背景图。

## 做法

1. 先确认背景在源端可见：容器子节点或 Activity.onCreate 里 addView 的视图是否继承 SurfaceView/GLSurfaceView，源码有无 setZOrderOnTop（grep setZOrderOnTop|setZOrderMediaOverlay|setFormat|getHolder），绘制开头是否 drawColor(TRANSPARENT, CLEAR)。可见时再打开背景引用的 drawable 确认类型；是普通位图时用 ImageFit.Fill（或等效铺满方式）映射，不因“图文不裁切”的直觉改用 Cover；确需等比裁切时，先用资源宽高比与目标屏幕比例核对关键图文不会被裁。
