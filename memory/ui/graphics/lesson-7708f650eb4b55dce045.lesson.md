# android:background 的整屏背景是普通位图时按拉伸铺满映射，不默认用 ImageFit.Cover 裁切

ID：`lesson-7708f650eb4b55dce045` · 版本：3

[本主题](index.md)

## 何时使用

界面实现阶段，把源根布局的 android:background 背景图转换为 ArkUI 背景 Image 或背景图属性时

## 适用情境

源根容器以 android:background=@drawable/xxx 铺设整屏背景，该 drawable 是普通位图（png/jpg，或未设 gravity/tileMode 的 <bitmap>，BitmapDrawable.java 默认 gravity=FILL），背景上画有需要完整显示的图文；目标用 Stack 底层 Image 或背景图属性重建。

## 例外与边界

- 源端是 ImageView 且显式 scaleType=centerCrop 一类裁切语义，按该 scaleType 映射
- 背景是设了 gravity 或 tileMode 的 <bitmap>：按其定位或平铺映射（common.d.ts 的 backgroundImagePosition、backgroundImage 的 ImageRepeat）
- 背景是 .9.png：按九宫格拉伸，用 Image.resizable（image.d.ts）或 backgroundImageResizable（common.d.ts）按源 .9 的拉伸区设 slice
- 背景是 layer-list 或按产品 flavor 覆盖：按生效版本逐层落成组件

## 原因

View 背景的普通位图按视图边界拉伸铺满、不裁切；Cover 等比铺满会裁掉上下或左右，背景上的关键图文被截掉。

## 做法

1. 先打开背景引用的 drawable 确认类型；是普通位图时用 ImageFit.Fill（或等效铺满方式）映射，不因“图文不裁切”的直觉改用 Cover；确需等比裁切时，先用资源宽高比与目标屏幕比例核对关键图文不会被裁。
