# 修共享绘制分支里某一指标的显示差异时，按源端通用规则统一实现，不写单 key 特判；先列出落入该分支的全部指标

ID：`lesson-17d6e4c04764983be25a` · 版本：1

[本主题](index.md)

## 何时使用

界面绘制修复阶段，按用户对某一指标的视觉反馈，调整多个指标共用的 Canvas 绘制分支（线宽、描边、填充样式）时

## 适用情境

源端同类图形由通用 helper 按统一规则绘制（如 drawBars 中 STROKE/FILL_AND_STROKE 与 strokeWidth ?: 3f 像素），不区分指标 key；目标多个指标经分派落到同一绘制分支，用户只报告其中一个与源端粗细不一致。

## 原因

单 key 特判只修好被报告的指标，同一分支的其他指标仍保留来源已失效的旧值；源端参数本来不按 key 区分时，特判本身就偏离了源端，后续还会被当成“有意设计”继续沿用。

## 做法

1. 修单个指标的显示差异前，先确认源端该参数是否按指标区分；是通用 helper 的默认值时，在目标共享分支按同一规则统一实现，并用 px2vp 把源端像素值换成 vp，不写 key === '某指标' ? 新值 : 旧值。
2. 改共享分支前按分派条件列出落入该分支的指标，核对旧值注释所称的服务对象是否仍走此分支；旧值失去来源时整体回归源端规则，并请用户复测受影响的其他指标。
3. 定位用的临时诊断可以按 key 加条件，样式修复本身不与诊断条件绑定；交付前检索并清除诊断日志与残留特判。
