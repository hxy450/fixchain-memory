# 把预烘焙位图改为每帧矢量绘制前，保留位图隐含的取值时机与缩放语义：烘焙时读取的状态留快照，拉伸的全部属性按比例缩放

ID：`lesson-046c8bbb304684669060` · 版本：3

[本主题](index.md)

## 何时使用

渲染实现阶段，用每帧矢量绘制替代源端预渲染的背景位图或 tile 位图缓存，并准备声称“行为等价”时

## 适用情境

源端在 onSizeChanged 等时机把受状态字段控制的元素（如说明文案、提示层）和圆角底、文字等烘焙进 Bitmap，onDraw 只 drawBitmap，或在缩放类动画中用 setBounds((int)…) 整体拉伸位图、按 int 位移绘制；这些状态在位图生成后仍会被其他流程改写；目标改为 Canvas 每帧 roundRect、fillText 等矢量绘制。

## 例外与边界

- 只涉及每帧起始画面（是否清屏、透明区文字叠画变粗）：按画布跨帧保留与每帧清屏的规则处理

## 原因

位图把生成时刻的状态和整体缩放一起固化：生成后再改字段不影响显示，拉伸时圆角、字号、基线修正、描边随位图缩放，边界经 (int) 截断。改为每帧读实时字段、只缩放文字、保留浮点坐标后，元素集合、顺序与颜色都对，元素出现与消失的时机、动画中的形状却变了。

## 做法

1. 逐一列出缓存构建函数读到的可变状态、缓存的重建时机，以及位图生成后还有哪些写者改这些状态；在目标对应的尺寸或布局入口给它们留快照，绘制时读快照。快照依赖首次初始化写入（如异步就绪后才开始）时，布局入口加“引擎已就绪”门控，未就绪下一帧重试。
2. 源端用 setBounds 或矩阵拉伸位图时，先核目标矩形与烘焙尺寸的宽高比：等比时用 s = 绘制宽 / 烘焙宽 统一缩放烘焙内容的全部属性（圆角半径、字号、基线修正、描边）；非等比时分别用 sx、sy，或对整组绘制施加 ctx.scale(sx, sy) 等整体矩阵变换（BitmapDrawable.java 把位图画进 bounds 矩形，宽高各自拉伸）。dp 圆角先换成当前画布单位再乘比例；边界与位移按源式的 (int) 向零截断，用 Math.trunc。
3. 决策已批准离屏位图加 drawImage 时优先沿用该路线，它天然保留这些语义；改走每帧绘制时，把取值时机与缩放的处理写进交回的决策缺口。

## 可选检查

- 需要确认时，按源端流程切换状态（如首次进入 → 重新开始 → 重建视图）对照元素出现与消失；缩放动画中比例 0→1 的出现帧与比例 >1 的放大帧各取一帧，核对边界为整数、圆角等于基准圆角乘比例。
