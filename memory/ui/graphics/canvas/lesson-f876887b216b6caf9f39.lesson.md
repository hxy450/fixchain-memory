# 移植 Paint 文字度量前先按源 API 分层：getTextBounds/Rect 包围盒直接对应 actualBoundingBox*（各自 Math.ceil）；Paint.ascent/descent 字体级基线修正才实测选与 hhea 吻合的 TextMetrics 字段，不凭字段名或先例推定；源式取整原样保留

[本主题](index.md)

## 何时使用

渲染实现阶段，把源端 Canvas 文字居中或基线修正（如 (int)((descent+ascent)/2)）移植为 measureText 的 TextMetrics 计算，或决定能否关闭“需实测校正”的字段映射标记时；规格提取阶段写文字基线映射时；把 Paint.getTextBounds 取得的文字高度映射为行高或间距时

## 适用情境

源端以 Paint.ascent()/descent()（字体级上/下伸，ascent 为负）计算基线偏移，供数字、标题、说明等文字使用；目标用 CanvasRenderingContext2D.measureText 返回的 fontBoundingBox*、emHeight*、actualBoundingBox* 取等价度量，并注册了自定义字体。 也包括源端用 Paint.getTextBounds(text, start, end, Rect) 取一段具体字符的墨迹包围盒高度来定行高或间距（如 HUD 标签与数值的行距、自适应字号循环）。

## 原因

TextMetrics 各字段在目标实现中的量值不一定符合同名 W3C 语义：来源实测某注册字体时，fontBoundingBoxDescent 等于 head.yMin，emHeightAscent/Descent 才等于 hhea 上下伸；actualBoundingBox* 是墨迹级、随字符变化。按字段名推定等价会让文字整体偏上，偏移被乘倍用于标题时误差放大。getTextBounds 返回所测字符的墨迹紧包围盒（Skia roundOut 向外取整），对应 actualBoundingBox*；映射成 fontBoundingBox 行框约大 1.4 倍，行距吃掉组间留白。“不把墨迹级字段列为候选”只在源度量是字体级时成立，召回把本条套到 getTextBounds 上，规格与实现都选了 fontBoundingBox。

## 做法

1. 先按源 API 名判断度量层级：Paint.getTextBounds(…, Rect)、rect.height()，或度量参数是一段具体字符时，映射为 Math.ceil(actualBoundingBoxAscent) + Math.ceil(actualBoundingBoxDescent)，不做 hhea 实测、不列 fontBoundingBox* 为候选；只有 Paint.ascent()/descent()/getFontMetrics() 的字体级度量才按下一步实测选字段。
2. 注册目标字体后取固定字号（如 100px）打印 fontBoundingBox*、emHeight*、actualBoundingBox*，与字体 hhea ascender/descender ÷ unitsPerEm × 字号比较，选数值吻合的字段；注意符号约定：Paint.ascent 为负、TextMetrics 的 *Ascent 为正，(descent + ascent)/2 对应 (D − A)/2。
3. 源式含 (int) 等取整时原样移植（Java 向零截断用 Math.trunc），不以“视觉看不出亚像素差”为由去掉。
4. 生成期无法实测时保留“需实测”标记，写明待测字段与预期值（hhea 值），不在注释或笔记里写“数值同值”；规格写字体级基线映射时注明 Paint 度量是字体级带符号值、结果取整，不把墨迹级字段列为等价候选。规格只给“候选字段 + 待实测”时，实现者先读 d.ts 中各候选字段的注释，按源 API 语义选字段。
