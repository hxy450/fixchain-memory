# Canvas.drawText 移植为 fillText 时按每串首个强方向字符设置 ctx.direction，不让画布方向随系统语言 inherit

ID：`lesson-68717b80482f4bd12825` · 版本：1

[本主题](index.md)

## 何时使用

规格提取与渲染实现阶段，把安卓 Canvas.drawText 文字迁到 ArkUI fillText、确定文字段落方向时

## 适用情境

源端文字经 Canvas.drawText 配默认 new Paint()（未设 bidi）绘制；应用有 fa、ar 等 RTL 资源，或可能在无对应资源、回落英文的 RTL 系统语言下运行；目标 CanvasRenderingContext2D.direction 保持默认 inherit。

## 原因

安卓默认 Paint 为 BIDI_DEFAULT_LTR：每串按首个强方向字符定段落方向，无强字符时为 LTR，与系统语言无关。ArkUI 画布 direction 默认 inherit，RTL 系统语言下整串按 RTL 段落排列，英文句末标点会被挪到行首。把“安卓不镜像”推成“默认 fillText 即等价”，会漏掉这一差异。

## 做法

1. 封装一个绘制函数：按串中首个强方向字符设 ctx.direction（希伯来、阿拉伯等 RTL 区块 → 'rtl'，其他字母 → 'ltr'，无字母 → 'ltr'）后再 fillText，所有文字绘制都经它。
2. 规格把 drawText 映射到 fillText 时写出这条段落方向契约，不写“1:1 移植、不需特殊 RTL 处理”。

## 可选检查

- RTL 验收覆盖有 RTL 资源的语言与回落英文的 RTL 系统语言（如 ar），看句末标点位置；全仓检索不到 rtl/bidi 不能作为等价证据。
