# 源端绘制函数从 Paint 读回字号或对齐时，目标在组件内自记字体与对齐，不读回 ctx.font、ctx.textAlign

ID：`lesson-8b1a03e44c59e371ff57` · 版本：1

[本主题](index.md)

## 何时使用

渲染实现阶段，把依赖 Paint getter（getTextSize、getTextAlign 等）读回状态的绘制辅助函数（如带底衬的文字绘制）移植到 ArkUI Canvas 时；规格提取阶段写 Paint→Canvas 映射行时

## 适用情境

源端多个绘制调用共用一个 Paint：调用方先 setTextSize/setTextAlign/setTypeface，被调的辅助函数再用 getter 读回当前字号与对齐，计算底衬框、内边距或文字偏移；目标把 Paint 设置译成 ctx.font、ctx.textAlign 赋值，规格映射只写“Paint 属性映射 Canvas 等价属性”。

## 原因

Paint 是可读写的状态对象；CanvasRenderingContext2D 的 font、textAlign 不能当作同样的状态读回：在 HarmonyOS 6.1 模拟器（6.1.0.126）上读回为 undefined，解析字号或按对齐分支时抛 TypeError。setter 示例看不出这一点，只编译、不启动也发现不了。

## 做法

1. 用组件内的 setFont(…)/setTextAlign(…) 包装赋值，同时把当前字号、粗细与对齐记进字段（如 curFontPx、curTextAlign）；辅助函数只读这份记录，不解析 ctx.font、不读 ctx.textAlign。
2. 辅助函数需要文字高度与基线位置时，用 measureText 返回的 TextMetrics 计算，不从字体串反推。
3. 规格的 Paint→Canvas 映射行写明：上下文属性只写不读，绘制状态由组件自记。

## 可选检查

- 绘制代码只经编译、未在设备或模拟器上运行过时，启动一次含该画布的页面并让各绘制分支执行，暴露运行时 TypeError。
