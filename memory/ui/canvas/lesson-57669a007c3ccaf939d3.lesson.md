# 按帧推进的自绘动画用逐帧回调驱动，不用固定间隔定时器

ID：`lesson-57669a007c3ccaf939d3` · 版本：1

[本主题](index.md)

## 何时使用

规格提取、派工与实现阶段，为源端自绘渲染循环确定目标帧驱动方式时

## 适用情境

源端渲染线程在任务队列非空时不休眠、按合成节奏逐帧推进；各动画按帧计步（每帧位移、透明度或步数），个别任务另带毫秒节流；目标为ArkUI Canvas单UI线程绘制。

## 原因

按帧计步的动画速度随帧率变化；把渲染循环换成约30ms定时器并宣称“步长常量不变即等价”，实际帧率更低，动画整体变慢；拿某个任务的毫秒节流当帧间隔依据会掩盖这一点。

## 做法

1. 规格逐个任务标明“按帧计步”还是“按时间节流”；只要有按帧计步的任务，源端实际帧节奏（无sleep的lockCanvas循环约等于屏幕刷新率）就是行为契约。
2. 实现用displaySync等逐帧回调（期望帧率设为屏幕刷新率），队列空时停帧、入队时恢复；只能用定时器时，按实际帧间隔换算每帧步长，使总时长一致。
3. 改成逐帧绘制后注意渲染负载：每帧整盘重绘大量drawImage可能压垮渲染服务；ArkUI Canvas内容常驻，可在任务首帧整盘绘制、之后只在变化区域内clip重画。

## 可选检查

- 两端同一场景计数实际帧数，帧率差明显即未等价
