# 源端 onCreate 里 findViewById 后立即调用的 View setter，在子组件登记时回调宿主完成首次接线，不在 NavDestination.onReady 中读子组件句柄

ID：`lesson-f9be21096154da5890b5` · 版本：1

[本主题](index.md)

## 何时使用

界面实现与跨组件接线阶段，决定宿主页何时、经什么机制拿到子组件实例并完成首次接线时

## 适用情境

源 Activity.onCreate 中 findViewById 取到自定义 View 后立即调用 setter（设置状态对象、注册触摸或回调监听）；目标父页不能直接取得子 struct 实例，改由子组件在 aboutToAppear 把自身写入宿主传入的句柄，宿主的初始化链放在 NavDestination.onReady 等生命周期回调里。

## 例外与边界

- 子组件通过 @Param/@Event 等声明式参数直接接收状态与回调，宿主不需要命令式取得实例

## 原因

NavDestination.onReady 在其子组件创建之前回调（本机 SDK component/nav_destination.d.ts 的 onReady 注释），此时子组件尚未执行 aboutToAppear，句柄为空；接线写成 ?. 可选链会静默跳过，之后再无接线点，视图停在空态分支、监听未注册。凭“子组件先登记、再 onReady”的直觉推断时序而不读回调注释，缺陷会进入共享句柄约定并被其他页面复用。

## 做法

1. 让首次接线发生在登记那一刻：句柄提供登记回调（如 onAttach），子组件在 aboutToAppear 写入自身后立即回调；宿主在自己的 aboutToAppear 挂好回调，在回调里完成全部 setter。宿主初始化链执行时若句柄已登记，就调用同一个接线函数，保证不论先后都只走一条路径接通。
2. 依赖宿主回调（onReady、onShown、aboutToAppear）与子组件创建的先后前，在本机 SDK 对应 .d.ts 读该回调的注释段，不只看签名行；没有核实就按与先后无关的方式设计，不在注释里写“此时必已就绪”。
3. 只执行一次的接线不用 ?. 静默跳过：取不到实例时由登记回调补接，或记录错误；可选链只用于登记后会反复调用的命令（重绘、度量）。给共享组件加跨页句柄时，把“宿主最早何时可用”写进组件契约。

## 可选检查

- 对接线时机有疑问时，进入页面看首帧是否为实际数据而非空态分支，做一次操作后状态是否改变。
