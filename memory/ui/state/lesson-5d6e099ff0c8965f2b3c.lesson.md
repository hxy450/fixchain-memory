# 源端以引用比较判断“有未保存改动”时，先确认未改动时两侧是同一对象；ArkUI V2 中改用显式改动标志，不拿 @Local 数组与另存的原数组或新字面量做 ===

ID：`lesson-5d6e099ff0c8965f2b3c` · 版本：1

[本主题](index.md)

## 何时使用

界面实现阶段，把编辑页的未保存检测（离开前确认、canSafelyExit 一类）从 Compose 翻译到 ArkUI V2 状态时

## 适用情境

源端编辑页以 remember(x){ mutableStateOf(x) } 一类写法让编辑状态的初值就是入参对象，修改时整体替换成新列表，再用 !== / === 引用比较判断是否改动；目标用 @Local 数组承载编辑状态，另存一份初始数组，或在新增模式把两者各自初始化为 []。

## 原因

源端“未改动”时比较两侧本就是同一对象，任何修改都换成新对象，所以引用比较等价于“是否被替换过”。目标里两个独立的 [] 字面量永远不相等；按 V2 的状态代理语义，赋给 @Local 的数组与另存的原始数组也可能不相等（来源依据框架语义与复审结论，编辑模式未单独运行验证）。结果是未改动直接离开也被判为有改动、弹出未保存确认。

## 做法

1. 先确认源端比较两侧在未改动时是否为同一对象；是的话，目标用显式的“已改动/已替换”标志表达：每条修改路径（保存、删除、移动、追加）置位，载入初始数据时复位，离开判断只读这个标志。
2. 确需比较对象身份时，两侧取同一来源：用 UIUtils.getTarget 取 @Local 代理背后的原对象，再与保存的初值比较；不拿另一个 [] 字面量或另行构造的数组比较。

## 可选检查

- 对引用语义有疑问时，分别从新增、编辑两个入口进入后不做修改直接返回，确认不弹未保存确认
