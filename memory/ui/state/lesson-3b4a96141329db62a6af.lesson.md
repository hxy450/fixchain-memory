# 迁移 Compose remember 状态时按源端的求值与重建时机落实：无键 remember 只在首次组合求值，remember(key) 只在 key 变化时重算，条件挂载的子组件每次显示都是新状态，无 key 惰性项随位置重建

ID：`lesson-3b4a96141329db62a6af` · 版本：1

[本主题](index.md)

## 何时使用

界面实现或公共组件抽取阶段，把 Compose 中 remember、derivedStateOf、LaunchedEffect 持有或算出的局部状态迁到 ArkUI（写成 @Computed、getter 或缓存字段，提升为页级 @Local，放进常驻的 ListItem 或子组件，或改成选择 handler 里的直接赋值），并决定何时求值、何时复位时

## 适用情境

源端状态写在无键 remember { … } 或 remember { derivedStateOf { … } } 包住的一次性判定（如按目标值是否含小数点决定是否显示小数）、remember(k1, k2){…} 派生值、条件挂载（if (show) Dialog/卡片）子组件内的 remember 与 LaunchedEffect，或 LazyColumn 中不设 key 的 item{}/items 项里；源码没有显式重算或清空，时机依赖组合身份。目标准备写成每次渲染都重算的 @Computed、getter，或把状态放到页级 @Local、常驻组件，或在每次点击时重写派生值。

## 例外与边界

- 目标保持与源端相同的挂载结构（条件渲染的子组件自己持有状态、每次显示新建实例），重建语义已自然保留

## 原因

Compose 的 remember 值跟随所在组合节点的身份：无键时只在首次组合求值、之后沿用，带 key 时 key 变化才重算；derivedStateOf 只在它读取的 State 变化时更新，捕获的普通参数停在首次组合时的值；条件挂载的子树每次显示都是新实例（其中的 LaunchedEffect 随之重跑），不设 key 的惰性项按位置标识，位置一变旧状态就丢弃。目标端 @Computed 与 getter 每次渲染都重算，常驻组件和页级状态又不会自动重建，handler 赋值也不区分新旧 key 是否相同；结果是判定随后续参数变化而翻转、重开对话框保留上次的勾选、保存后尾部新增卡残留旧输入、重选同一类型清掉用户改过的名称。

## 做法

1. 无键 remember 或只读普通值的 derivedStateOf 按“首次组合求值一次”迁移：在组件初始化（aboutToAppear）或按条目标识首次计算后存入字段，条目切换（源端重新进入组合）时再算；不写成每次渲染都重算的 @Computed 或 getter。
2. remember(key) 派生的状态：在改变 key 的 handler 里先比较新旧值，相同即不做任何事；只有 key 真正变化才按源端初始化表达式重算（如编辑已有项时恢复原值、新增时取默认值）。
3. 条件挂载子组件里的 remember/LaunchedEffect 被提升到页级状态时，在每个打开入口先复位这些状态，再重跑源端挂载时的初始化（如打开即全选、清空已选）；不要只在集合为空时补初始化。
4. 无 key 的惰性项改由常驻组件承载时，在源端位置会变化的时机强制重建（以随位置变化的值作键，如以当前条目数为键包一层 ForEach），或在保存后显式复位。推断出“源端保存后仍保留旧输入”这类反常行为时，先查该项有无 key、位置是否变化，不以“源就是这样”收束。
