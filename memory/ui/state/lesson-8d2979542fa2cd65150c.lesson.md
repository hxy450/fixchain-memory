# 随状态变化的控件参数不作 @Builder 位置值参，改为内联读取、@ComponentV2 子组件 @Param 或按引用传参

ID：`lesson-8d2979542fa2cd65150c` · 版本：8

[本主题](index.md)

## 何时使用

界面实现阶段（页面转换与公共组件抽取），以及返修或按源端几何重写已有页面时，为源端带状态参数的子控件、多个同构开关行或数据文字选择 ArkUI 复用写法时；把 LazyForEach 改写为 Repeat、拆出条目 @Builder 时

## 适用情境

源端 Compose 子 Composable 以当前状态算出的值作参数（如 enabled = count > 1、颜色随选中态变化），或 Android 页面有多个同构的开关行、各自持有状态；目标准备把子控件或开关行抽成共享的 @Builder 方法，并把 this.<状态>、异步重新赋值的数组或对象（搜索结果、定位卡）、随布局或旋转变化的尺寸作为位置值参传入。也包括把 LazyForEach 改为 Repeat 时 each 回调写成 this.Row(ri.item)；以及为子页面嵌入点写只含前向引用的空 @Builder 槽位，参数表成为后续填充者的接口。

## 例外与边界

- 传入 @Builder 的只有文案、尺寸等在该组件生命周期内不随状态变化的值

## 原因

Compose 每次重组都按当前状态重算实参；ArkUI @Builder 按值传入的参数是调用时刻的快照，状态变化后不会刷新 @Builder 内的 UI，异步重新赋值的数组或对象同样停在旧值。Repeat 复用节点时只更新 RepeatItem.item，按值传入的 ri.item 是旧对象，不会重绘。

## 做法

1. 状态派生的 enabled、selected、颜色、开关值、显示文字与尺寸等参数，用内联属性链直接读 this 上的状态，或抽成 @ComponentV2 子组件用 @Param 接收，或让 @Builder 只接收一个对象字面量参数（按引用传递，状态变化会刷新 @Builder 内 UI；API 20 起也可用 UIUtils.makeBinding 传只读绑定，见 @ohos.arkui.StateManagement.d.ts）；@Builder 多个位置值参只放不随状态变化的值。
2. 多个开关行共用外观时，每行在 build 中直接写复用组件并绑定自己的状态（如 isOn: this.<该开关状态>），不经共享 @Builder 转发状态值。
3. 写完 grep `@Builder` 签名与调用处，实参含 `this.<状态>` 表达式的即为风险点，改写后再落盘；返修重写已有片段时同样执行，不因原片段能刷新就省略。
4. 异步结果写回 @Local 前，grep 它在 build 中的全部消费点，确认没有经 @Builder 值参快照；“先切分支、后 await 赋值”的流程尤其要查。
5. Repeat 的 each/template 回调里拆出的 @Builder 或子组件接收完整 RepeatItem，在内部读取 ri.item；出现 this.Xxx(repeatItem.item) 写法先改正再提交。
6. 即使槽体只是前向引用占位，也按这条规则定签名：空槽的参数表会成为后续填充者沿用的接口契约；后续填充槽体时先确认槽内数据在异步更新后能否刷新，不默认沿用占位签名。

## 可选检查

- 改动涉及按状态显示的文字或尺寸时，验收至少包含一次改变数据或尺寸的操作（切换选项、重置、旋转），确认显示随之更新。
