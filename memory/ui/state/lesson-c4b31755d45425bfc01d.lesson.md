# 定时器或帧回调里同步遍历 V2 可观察数组时，用 UIUtils.getTarget 取原始数组计算，提交时再整体赋给可观察字段

ID：`lesson-c4b31755d45425bfc01d` · 版本：1

[本主题](index.md)

## 何时使用

功能实现阶段，为 @ObservedV2 模型或 V2 组件编写由定时器、帧回调驱动、在 UI 线程同步执行的逐格或逐元素计算，并读取 @Trace、@Local 数组时

## 适用情境

源端在 delay 循环或帧回调里对普通 List/数组逐元素计算（同步耗时可忽略，周期约等于设定间隔）；目标把数据放在 @Trace、@Local 等 V2 可观察字段上（含二维数组，嵌套的每一行也是代理），在 setTimeout、setInterval 或帧回调中同步计算后提交。

## 原因

V2 可观察数组经代理读取，每次元素访问都有额外开销，嵌套数组的每一行也是代理。逐格读邻居这类密集访问全部走代理时，单次同步计算会从几毫秒涨到十几、几十毫秒，叠加到定时周期上，迭代速率明显低于源端；V2 的 ArrayProxy 通常只被当作刷新机制理解，这部分开销不易察觉。

## 做法

1. 循环开头用 UIUtils.getTarget(this.字段)（@kit.ArkUI）取原始数组，计算、比较、计数与结束判定都在原始数组上做；提交结果时仍整体赋值给可观察字段来触发刷新，不在原始对象上原位修改、指望界面刷新。

## 可选检查

- 对迭代速率有疑问时，用 Date.now 或 hilog 打点量一次单次 tick 的同步耗时（连同回调里取色、动画等其他工作），确认它相对最短间隔档可以忽略。
