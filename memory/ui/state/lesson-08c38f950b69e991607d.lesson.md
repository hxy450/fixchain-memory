# 页面直接读共享 @ObservedV2 模型的 @Trace 字段，不复制成 @Local 快照再手动同步

ID：`lesson-08c38f950b69e991607d` · 版本：2

[本主题](index.md)

## 何时使用

功能接线与页面实现阶段，把页面显示状态接到 @ObservedV2 模型或共享 store，且模型会被其他页面、异步加载或服务回调改写时

## 适用情境

目标端用 @ObservedV2 + @Trace 模型（AppStorageV2.connect 或单例 getter 取得）承载共享状态：源端由一个根状态持有者驱动多个屏幕，拆成 Navigation 下多个页面后由子页修改模型；或源端 Flow/StateFlow 持续推送列表与加载态，目标由异步加载、BLE/消息回调整体重新赋值 store 的 @Trace 字段，页面是 @ComponentV2 子组件。

## 例外与边界

- 需要与模型解耦的纯界面态（弹窗开关、未提交的输入草稿）仍放在页面 @Local

## 原因

@Trace 字段变化会刷新直接读它的组件；把字段复制进页面 @Local 后，界面只随手动同步更新，其他页面、异步加载完成或回调对模型的修改都进不了界面。来源中页面先 new 私有模型、再用同步方法把 7 个字段复制进 @Local；后来模型改成共享实例但副本保留，返回刷新放在不会执行的“第二次 aboutToAppear”分支，补上的 onShown 刷新在该页作为 Navigation 首页内容的挂载方式下设备实测也未生效（触发机制未单独验证），最后改成直接绑定模型才修好。另一应用中三个页面在 aboutToAppear 未等待加载就把 store 的列表与 loading 拷进 @Local，之后异步加载和 BLE/消息回调整体替换数组，页面停在 Loading… 且新数据不显示；这些页面是 @ComponentV2 子组件，onPageShow 不会触发，生成者删掉它后只留了手动刷新按钮。

## 做法

1. 页面 build 中要显示的业务状态直接写 this.model.<字段>；页面 @Local 只留纯界面态。
2. 规格或决策说明某模型要被其他功能或页面读写时，页面从一开始就用 AppStorageV2.connect 取同一个共享实例，不在页面里 new 私有实例。
3. 确需在返回时执行一次性动作（如消费反馈），先确认页面是 NavPathStack 中的页面还是 Navigation 首页内容，再选在该挂载方式下会触发的回调，不依赖页面重建。
4. 页面是 @ComponentV2 子组件时，onPageShow 等页面级生命周期不会触发，需要随 store 更新时改用上面的直接绑定，不退回手动刷新按钮；确需本地副本，就同时实现决策要求的刷新路径（服务回调或 @Monitor 同步），让异步加载完成和回调重新赋值后副本随之更新。

## 可选检查

- 对返回后的显示有疑问时，在设备上走一遍“子页修改共享模型 → 返回原页”，dump 原页的高亮、计数与反馈文案，确认与模型一致。
- 对“加载中”一类标志有疑问时，追一遍它的写入方，确认页面不是只在加载开始时读取了一次。
