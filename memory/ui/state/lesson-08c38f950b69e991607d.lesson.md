# 页面直接读共享 @ObservedV2 模型的 @Trace 字段，不复制成 @Local 快照再手动同步

ID：`lesson-08c38f950b69e991607d` · 版本：3

[本主题](index.md)

## 何时使用

功能接线与页面实现阶段，把页面显示状态接到 @ObservedV2 模型或共享 store，且模型会被其他页面、异步加载或服务回调改写时

## 适用情境

目标端用 @ObservedV2 + @Trace 模型（AppStorageV2.connect 或单例 getter 取得）承载共享状态：源端由一个根状态持有者驱动多个屏幕，拆成 Navigation 下多个页面后由子页修改模型；或源端 Flow/StateFlow 持续推送列表与加载态，目标由异步加载、BLE/消息回调整体重新赋值 store 的 @Trace 字段，页面是 @ComponentV2 子组件。

## 例外与边界

- 需要与模型解耦的纯界面态（弹窗开关、未提交的输入草稿）仍放在页面 @Local
- 要解决的是返回时重新拉取数据（模型本身没有被更新）：按页面可见性回调或订阅重新加载，不属本条

## 原因

@Trace 字段变化会刷新直接读它的组件；把字段复制进页面 @Local 后，界面只随手动同步更新，其他页面、异步加载完成或回调对模型的修改都进不了界面。页面是 @ComponentV2 子组件（不是 @Entry 页）时 onPageShow 不会触发，靠页面级回调补同步也不生效。

## 做法

1. 页面 build 中要显示的业务状态直接写 this.model.<字段>，范围是页面实际消费的全部共享字段；页面 @Local 只留纯界面态。
2. 规格或决策说明某模型要被其他功能或页面读写时，页面从一开始就用 AppStorageV2.connect 取同一个共享实例，不在页面里 new 私有实例。
3. 确需本地副本时，同时实现模型到副本的同步路径（服务回调，或 @Monitor 监听模型字段），让异步加载完成和回调重新赋值后副本随之更新；不靠 onPageShow 或手动刷新按钮补同步。

## 可选检查

- 对返回后的显示有疑问时，在设备上走一遍“子页修改共享模型 → 返回原页”，核对原页的高亮、计数与反馈文案与模型一致。
- 对“加载中”一类标志有疑问时，追一遍它的写入方，确认页面不是只在加载开始时读取了一次。
