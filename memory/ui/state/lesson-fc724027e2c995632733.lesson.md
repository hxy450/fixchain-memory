# 拆除共享 ViewModel 单例或让弹窗与宿主各持实例时，跨页面状态显式传递或从持久化重读，不只把 getInstance() 换成 new

ID：`lesson-fc724027e2c995632733` · 版本：1

[本主题](index.md)

## 何时使用

架构重构阶段把跨页面共享的 ViewModel 单例改为页面级实例时；修复阶段为页面补传筛选参数，或让弹窗与宿主页各自持有 ViewModel 实例时

## 适用情境

多个页面经全局单例（如 AppStorageV2）共用一个 ViewModel，其中的筛选或显示状态（当前空间、选中日期、显示偏好）由某个页面的动作写入，其他页面的查询只隐式读这份状态；重构要求改为页面级实例，或弹窗内改动的持久化偏好只经回调通知宿主，宿主刷新时又用自己实例的快照回填。

## 原因

单例是跨页面状态的隐式通道；机械替换成 new 后，写入动作只改自己的私有实例，其他页面停留在初始化值，切换后不刷新或混入其他数据。来源中重构者读到了侧栏写入、各页隐式读取与二十余处 getInstance 调用，仍一次替换为 new；修复期又把侧栏条目的原始 ID 直接传给查询，“所有空间”的哨兵值没有归一化，反而查不到数据。另一处弹窗与宿主各持实例，弹窗里改的显示偏好只写到宿主的本地状态，宿主刷新时被旧快照覆盖，下次打开仍是旧值。

## 做法

1. 拆单例前列出其中跨页面状态字段的写入动作和全部读取页；每个读取页改成显式 @Param + @Monitor、订阅类型化事件，或查询时显式传参，不留隐式依赖。
2. 保留哨兵值归一化：源端在写入动作里把“全部”一类选项归一成空 ID 时，查询层统一使用该值，不把列表条目的原始 ID 直接下传。
3. 弹窗与宿主各持实例时，弹窗改动的持久化偏好同步到宿主的状态来源（调用宿主实例的 setter，或每次打开前从持久化重读），不只改宿主的本地状态。
4. ViewModel 内部写共享列表时也校验请求身份（代次、日期、筛选项）；一次切换只保留一个刷新入口。

## 可选检查

- 用“具体筛选项 → 无数据项 → 全部”与跨视图往返各切一次，确认各页数据一致且只刷新一轮。
