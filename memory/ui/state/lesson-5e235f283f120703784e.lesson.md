# 把 @Monitor 改成生产方显式回调时，保留“被监听字段变化才执行”：回调入口比较上次值，未变即返回

ID：`lesson-5e235f283f120703784e` · 版本：1

[本主题](index.md)

## 何时使用

编译修复或接线阶段，因 @Monitor 未绑定（编译告警 needs to monitor the state variables that exist）或其他原因，改由生产方在各写路径显式调用页面回调时；派发或执行这类替代方案时

## 适用情境

原 @Monitor 只监听少数字段（运行态、结果等），处理函数含 animateTo、资源取色或重算装饰；替代方案在每次状态提交（如每代 tick）、开关、重置等路径尾部都调用回调，派工或协调者把它写成“语义等价”。

## 原因

@Monitor 只在被监听字段的值变化时触发；改成在每个写路径无条件回调后，不改变这些字段的提交也会执行处理函数，每次都重放动画、查询资源，耗时叠加到定时周期上，界面过渡也被反复重启。

## 做法

1. 回调入口记录并比较被监听字段的上次值，未变化直接返回；或只在真正改写这些字段的路径调用。含 animateTo、资源查询的处理函数不挂在每次状态提交上。
2. 执行派工给的替代触发清单前，逐个核对每个新触发点是否会改变原监听的字段；多出来的触发点加变化判断，或在 handback 里提出，不以“清单是协调者有意给的”照做。
