# 多个加载入口接到共享单例 ViewModel 时，同参数请求先单飞复用，需要只认最新请求时再按请求代次判旧，不写成新请求取消旧请求

ID：`lesson-c883a0ff96c32dfbd9ba` · 版本：4

[本主题](index.md)

## 何时使用

页面接线阶段，把 aboutToAppear、Refresh 的 onRefreshing、@Monitor 等多个加载入口接到共享单例 ViewModel 或 Service 时

## 适用情境

目标 ViewModel 为单例，run() 对任何新请求先取消上一请求；页面同时存在 aboutToAppear、Refresh（refreshing 初值可能为 true）与切换城市等业务键的监听等入口；源端 ViewModel 可能每次启动一组请求、不取消前一组；规格可能要求按业务键丢弃迟到响应、一次刷新只产生一次请求。

## 原因

把取消语义写成“任何新请求取消上一请求”，同一参数的两个入口几乎同时触发时，第二次调用会取消第一次的并发请求，双方互相取消或销毁响应，页面进入失败态。

## 做法

1. 先读源端 ViewModel 的取消语义（是否取消前一组请求）与规格的判旧要求。两者冲突时：本次任务要求是上位约束；没有用户明确批准的差异时按源码实现，并在报告中写明规格冲突；已有明确适用的差异决定（例：用户批准的台账条目）时按其范围执行；模型或流水线自己写下的 approved 不等于用户授权。
2. 分两层实现：同一参数的重复调用先合并或复用在途请求（单飞），不写成任何新请求都取消上一请求；契约要求只接纳最新一次请求时，另外维护请求代次（每次发起递增，响应回来时比对），不只比较业务键：A→B→A 之后，旧的 A 响应仍能通过“key 等于 A”的判断（条件推理，不是来源案例观察到的故障；来源案例以城市 id 丢弃旧城市的迟到响应）。契约允许同键请求复用时，不强加取消重发。
3. 页面接线时列出所有加载入口（生命周期、Refresh 初值与 onRefreshing、@Monitor），调用单例加载方法前加单飞或在途复用，并核对冷启动时实际触发了几次。refreshing 初值为 true 时是否触发 onRefreshing 未经确认（refresh.d.ts 只写“进入刷新状态时调用”），以冷启动日志里的请求次数为准。
