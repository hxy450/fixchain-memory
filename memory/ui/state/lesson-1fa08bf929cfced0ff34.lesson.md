# 源端用带兜底的访问器取显示值时，目标调用已移植的等价访问器，不改读原始字段再自拟兜底

ID：`lesson-1fa08bf929cfced0ff34` · 版本：3

[本主题](index.md)

## 何时使用

功能接线阶段，把源端刷新函数里的显示赋值（如 text = Manager.getX()）翻译成目标组件状态，或把登录判定与用户名显示映射成身份文案表达式时

## 适用情境

源端在某一分支调用带空值兜底的访问器（如已登录但昵称为空时返回“用户{id}”或默认昵称），另一分支才显示“未登录”等占位文案；登录判定来自 token/session。目标侧会话或仓库层保留原始字段（昵称可为空），可能已移植同名兜底方法，组件状态是普通字段，工程里有现成的未登录占位字符串资源。也包括源端经工具类把数值码映射为显示文案（天气码、空气质量、风向）的情形。

## 原因

访问器的方法体才是显示语义（空值兜底、游客与登录态分流）；改读原始字段后，接线者往往用手边的占位文案补空值，把另一分支的文案挪进本分支。来源一：接线者读到了源端访问器调用和目标等价方法，仍写成“原字段非空否则显示未登录占位”，已登录用户看到“点击登录”。来源二：接线者先写“昵称非空否则未登录”，读到源端“昵称为空回退用户{id}”后仍未改；巡检修复又把“昵称非空”并入登录条件，token 有效而昵称为空的账号显示“未登录”，用户实测才发现。另一应用中，数据网关读到了源端的码值映射工具与规格的穷举表要求，仍把天气码 toString() 当描述、把空气质量数值直接当等级文案。

## 做法

1. 源端调用的是访问器而非字段时，目标同一分支调用已移植的等价访问器（没有就先移植）；占位文案只放在源端对应的分支。
2. 先读访问器方法体的空值兜底，再按“已登录 + 空值”等组合逐分支核对目标表达式的结果与源端一致；登录判定（token/session）与显示回退链分开实现，新增的字段判空不能改变登录/未登录分支的判定依据。
3. 不要把未登录占位资源复用为已登录用户的空值兜底；为“已登录、显示字段为空、id 存在”写一条显示用例，期望值取源端回退结果。
4. 访问器返回 ResourceStr 而状态是 string 时，按工程已有方式解析资源（宿主 context 判空同时排除 undefined 与 null），不因类型不合回退成占位字符串。
5. 源端经工具类把数值码映射成文案时，目标调用同表的映射函数，不用 toString() 输出原始码；再按 UI 数据模型逐字段核对每个显示字段都有来源。
