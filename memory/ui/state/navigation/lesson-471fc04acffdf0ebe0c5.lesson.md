# 生命周期语义迁移应同时处理框架恢复的 UI 状态

ID：`lesson-471fc04acffdf0ebe0c5` · 版本：1

[本主题](index.md)

## 何时使用

规格提取或实现阶段，把源端离开组合即销毁的页面状态迁移到会保活页面实例的导航容器时

## 适用情境

源端非持久状态随页面离开而消失，目标端 Navigation、Tabs 或 Stack 保留页面实例，并可能在返回时恢复焦点、键盘、滚动或选区；业务显示分支又由这些框架事件驱动。

## 例外与边界

- 目标端确认每次离开都会销毁并重建页面，或已显式关闭相关框架状态恢复

## 原因

只复位数据字段不能阻止框架在返回后重新发出焦点等事件，业务状态会被回调再次改写，从而恢复源端本应丢弃的界面分支。

## 做法

1. 把源端销毁语义展开为数据、焦点、IME、滚动位置和选区清单，逐项决定目标端的复位或禁用恢复方案。
2. 由焦点回调驱动业务状态时，区分用户触摸获得焦点与导航返回的框架恢复，避免直接一比一绑定。
3. 结构收敛不能代替行为验收；将进入子页再返回的往返流程列为生成期或验证期必测项。

## 检查

- 执行目标页面进入、交互、push 子页、系统返回的完整往返，核对焦点、键盘、滚动、选区和所有由它们驱动的显示分支均符合源端生命周期。
