# 生命周期语义迁移应同时处理框架恢复的 UI 状态

ID：`lesson-471fc04acffdf0ebe0c5` · 版本：2

[本主题](index.md)

## 何时使用

规格提取或实现阶段，把源端离开组合即销毁的页面状态迁移到会保活页面实例的导航容器时

## 适用情境

源端非持久状态随页面离开而消失，目标端 Navigation、Tabs 或 Stack 保留页面实例，并可能在返回时恢复焦点、键盘、滚动或选区；业务显示分支又由这些框架事件驱动。

## 例外与边界

- 目标端确认每次离开都会销毁并重建页面，或已显式关闭相关框架状态恢复

## 原因

只复位数据字段不能阻止框架在返回后重新发出焦点等事件，业务状态会被回调再次改写，从而恢复源端本应丢弃的界面分支。

## 做法

1. 将当前源页面实际依赖的销毁语义映射到目标导航生命周期；区分业务数据与焦点等框架状态，不无差别重置所有状态。
2. 对于由 onFocus 等回调驱动的业务分支，区分用户动作和框架恢复，避免任何焦点到来都打开同一分支。采用当前框架提供的状态与事件信息组织转换。
3. 事件示意：返回页面 → 已复位业务状态 → 框架恢复焦点 → onFocus 再次打开分支。修正的是这次非用户触发的转换，不能只在更早时刻清空业务字段。

## 可选检查

仅在适用条件不确定、与当前输入冲突或需要验证关键假设时按需执行；优先复用已有证据和正常测试。
不因读取本条经验而额外启动验证流程；项目原有必需测试照常执行。

- 仅当当前容器是否保活或恢复焦点尚不明确时，复用已有导航往返测试，观察该回调与业务状态的先后顺序；其他无关状态不扩测。
