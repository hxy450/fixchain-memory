# AppStorageV2/PersistenceV2 的 key 只用字母、数字、下划线：不沿用 kebab-case 文件名或点号命名空间，规格键也先校验

ID：`lesson-7508ddc52eaf816887f0` · 版本：2

[本主题](index.md)

## 何时使用

规格提取阶段为跨组件共享状态写 AppStorageV2/PersistenceV2 键名时；状态管理实现阶段，为 AppStorageV2.connect 或 PersistenceV2 共享状态类确定 key 字符串、把规格键名落成键常量，或复用工程已有 key 时

## 适用情境

ArkTS V2 工程以 AppStorageV2.connect(Cls, key, creator) 跨页面共享 @ObservedV2 状态；模块文件名采用 kebab-case（如 window-model.ets），状态管理 skill 只给出签名和一致性示例；编译期不校验 key 内容。也包括源端只有成员字段或回调、没有现成存储键，规格作者为新增共享状态自拟“领域.字段”式点号键，实现者按“与规格逐字一致”照抄进 connect 或键常量。

## 原因

key 只能由字母、数字、下划线组成，含连字符时运行期反复报 Cannot use the key!，编译照常通过，问题只在设备日志里暴露；点号同样不合法（设备日志报 invalid AppStorageV2 key）。来源中首个写者把模块文件名风格用作 key，后续写者读到既有 key 后照样命名或照抄；沉浸式修复者手上的模板本是不传 key 的重载，也改成了与文件同名的连字符 key。输入 skill 没有写字符限制。规格把键名写成契约后，实现者会把它当作必须逐字一致的运行时键照抄。

## 做法

1. 自定义 key 只用 [A-Za-z0-9_]（如 auth_session），不用“.”或“-”做命名空间或分隔；不需要自定义时用不传 key 的重载（默认类名）。
2. 同一共享状态的 key 集中定义为常量；复用已有 key 前先核对其合法性，已有 key 含连字符时把所有 connect 点一起改名，不照抄进新文件。
3. 规格的状态管理节直接写合法的运行时键；要保留分组语义就分列“逻辑名”与“运行时键”。实现时遇到规格键不合法，映射成下划线键并在常量注释或源码笔记中记录映射，不以“与规格逐字一致”为由写入非法键。

## 可选检查

- rg "AppStorageV2\.connect\([^,]+,\s*'[^']*[-.]" 及同类 PersistenceV2 调用应无命中；KEY_* 等键常量逐个对照 ^[A-Za-z0-9_]+$。
