# 裁定横切能力与平台差异时，区分源端默认行为和需额外资源的能力

ID：`lesson-4a81d8bc99d629325e79` · 版本：1

[本主题](index.md)

## 何时使用

规格决策阶段，填写目标平台、横切能力（深色/大字体/方向等）条目和技术必做项时

## 适用情境

源端某项行为由平台默认提供、无需代码或资源（sp文字随系统字号缩放、未声明screenOrientation时随传感器转屏、主题默认系统栏外观），目标平台对应默认值不同；决策参考只按源端是否有额外资源目录或显式代码判断能力有无。

## 原因

只按资源目录或显式代码探测，会把平台默认行为记成“源端无此能力”，于是不给目标端写必要的显式配置；目标默认值与源端不同的地方就会静默偏离。

## 做法

1. 逐项对照源manifest、主题、布局单位与目标脚手架配置（module.json5、app.json5、窗口API），把“源端默认生效、目标端默认不同”的项登记为技术必做项，并写明要写的配置。
2. 常见对照：源文字用sp或textAppearance*，目标在AppScope声明字号跟随系统；源Activity未声明方向且有横屏资源，目标Ability声明随传感器旋转的orientation；源主题未定制系统栏，目标按该主题默认外观设置系统栏颜色与横屏显隐。
3. “不新增X能力”只表示不额外加功能，不能用来保留目标平台与源端不同的默认值。
