# 每层 @BuilderParam 槽都应由 @Builder 方法承载自定义组件树

ID：`lesson-5afc18d10358b3e0e807` · 版本：1

[本主题](index.md)

## 何时使用

ArkUI 实现或收敛阶段，为带 @BuilderParam 内容槽的自定义容器传入一层或多层嵌套组件时

## 适用情境

内容槽以箭头函数传入，闭包体内直接实例化自定义组件；多层共享容器嵌套时，某些层已抽为 @Builder，另一些中间层仍留在普通闭包中。

## 例外与边界

- 当前 ArkUI 工具链与运行时明确支持该闭包写法，并已通过目标页面冷启动验证

## 原因

编译器可能接受普通箭头函数，但运行时在 initialRender 才拒绝其中的自定义组件构建；只修最内层会让中间层继续保留同类风险。

## 做法

1. 让传给 @BuilderParam 的箭头函数只调用本组件的 @Builder 方法；槽内容中出现自定义组件时，先为该层抽出独立 @Builder。
2. 对多层嵌套逐层检查每个 content 槽，不因最内层已抽取而跳过外层。
3. 把闭包体内直接出现自定义组件构造的扫描加入静态收敛门，并至少冷启动一次目标页。

## 检查

- 扫描所有 `<slot>: () => { ... }` 闭包，确认其中没有直接的自定义组件实例化；冷启动目标页且无 initialRender 崩溃。
