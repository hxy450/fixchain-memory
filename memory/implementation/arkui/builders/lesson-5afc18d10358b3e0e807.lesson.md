# 普通闭包构建有风险时，将每层 @BuilderParam 槽内容交给 @Builder

ID：`lesson-5afc18d10358b3e0e807` · 版本：2

[本主题](index.md)

## 何时使用

ArkUI 实现或收敛阶段，为带 @BuilderParam 内容槽的自定义容器传入一层或多层嵌套组件时

## 适用情境

内容槽以箭头函数传入，闭包体内直接实例化自定义组件；多层共享容器嵌套时，某些层已抽为 @Builder，另一些中间层仍留在普通闭包中。

## 例外与边界

- 当前 ArkUI 工具链与运行时明确支持该闭包写法，并已通过目标页面冷启动验证

## 原因

编译器可能接受普通箭头函数，但运行时在 initialRender 才拒绝其中的自定义组件构建；只修最内层会让中间层继续保留同类风险。

## 做法

1. 在存在该风险的工具链中，让传给 @BuilderParam 的普通箭头函数调用本组件的 @Builder 方法，由该方法承载自定义组件树。
2. 最小结构示意：易错 `content: () => { Child(...) }`；改为 `@Builder slotBody() { Child(...) }`，槽传 `content: () => { this.slotBody() }`。Child 和 slotBody 只是示意名称，实际参数按当前组件接口填写。
3. 多层嵌套逐层处理；最内层已经使用 @Builder，不代表外层普通闭包直接构建中间组件也已解决。
