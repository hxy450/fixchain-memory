# 把媒体 URI 交给系统查看器或分享时，type 取该条媒体的精确 MIME 并加 URI 读授权标志，无 URI 按源端回落

ID：`lesson-044358011be198c5bf87` · 版本：1 · 阶段：spec/execute · 主题：[app/media-library](index.md)

概要：查看分享媒体 URI 用精确 MIME 并授读权限

信号：`ACTION_VIEW`, `ACTION_SEND`, `EXTRA_STREAM`, `startAbility`, `Want`, `FLAG_AUTH_READ_URI_PERMISSION`, `ohos.want.action.viewData`, `ohos.want.action.sendData`, `image/*`, `PhotoType.VIDEO`

## 何时使用

系统集成实现阶段，把打开或分享最近媒体的 Intent 翻译为 Want、确定 uri、type、flags 与无媒体分支时；规格提取阶段写 ACTION_VIEW/ACTION_SEND 映射行时

## 适用情境

源端用媒体 URI 发 ACTION_VIEW（常不设 MIME，由 URI 决定查看器）或 ACTION_SEND（EXTRA_STREAM），无媒体时回落打开图库；目标用 startAbility 的 Want(uri/type/flags) 拉起系统查看器或分享面板，媒体记录已能区分照片和视频。

## 原因

Android 的 ACTION_VIEW 不设 MIME 时按 URI 向内容提供方取类型；startActivity 发 ACTION_SEND 时把 EXTRA_STREAM 迁入 ClipData 并附读授权，源码里看不到显式授权标志。目标查看器按 Want.type 匹配：写死 image/* 会把视频交给图片查看器，设备日志中还观察到系统图片查看器拒绝通配 image/*、要求 image/jpeg；不加 FLAG_AUTH_READ_URI_PERMISSION（@ohos.app.ability.wantConstant.d.ts，API 24）时接收方读不到该 URI。

## 做法

1. type 取自当前这条媒体记录：用查询结果的 photoType、文件扩展名或 UTD 推得 image/jpeg、video/mp4 等精确 MIME，连同 isVideo 一起传给网关；不写 image/* 这类通配，也不只传 URI。
2. 查看和分享的 Want 都在 flags 中加 wantConstant.Flags.FLAG_AUTH_READ_URI_PERMISSION；规格的 ACTION_VIEW/ACTION_SEND 映射行写明源端隐式授予的读权限。
3. 无 URI 或拉起失败的分支按源端委托链末端的实际实现迁移（如回落打开图库）；目标没有同名入口时改拉起系统图库或 PhotoViewPicker，不直接 return。

## 可选检查

- 有疑问时分别以最新照片、最新视频、无媒体三种状态点击入口，再从分享面板选一个接收方确认能读到该 URI
