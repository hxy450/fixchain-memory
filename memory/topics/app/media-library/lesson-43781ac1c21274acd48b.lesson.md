# 画廊入口要显示本应用最近拍摄的媒体时，以保存成功的 URI 持久化为准，未获 READ_IMAGEVIDEO 不整库 getAssets

ID：`lesson-43781ac1c21274acd48b` · 版本：1 · 阶段：spec/execute · 主题：[app/media-library](index.md)

概要：最近媒体以自存 URI 为准，未授权不整库查询

信号：`MediaStore`, `MediaStore.Images.Media.EXTERNAL_CONTENT_URI`, `getAssets`, `getThumbnail`, `READ_IMAGEVIDEO`, `checkAccessTokenSync`, `abilityAccessCtrl`

## 何时使用

规格提取与图库入口实现阶段，把源端“最近拍摄的媒体”查询与画廊按钮缩略图恢复映射到 photoAccessHelper 时

## 适用情境

源端经 MediaStore 查询最近媒体做画廊按钮缩略图（Android 分区存储下应用无需权限即可看到自己写入的媒体）；目标为普通应用，未获 READ_IMAGEVIDEO 受限授权，准备改用 photoAccessHelper.getAssets/getThumbnail。

## 例外与边界

- 签名 profile 已获 READ_IMAGEVIDEO 受限授权并完成声明与运行时授权，且功能确需展示其他应用写入的媒体

## 原因

getAssets 标 @permission ohos.permission.READ_IMAGEVIDEO（@ohos.file.photoAccessHelper.d.ts，API 24），该权限在本机 SDK PermissionDefinitions.json 中为 availableLevel=system_basic，普通应用须经受限权限申请才能获得；d.ts 没有“未授权时可见本应用媒体”的分支。照 Android 分区存储的经验直接整库查询，设备上查询失败；失败分支若再清空缩略图，恢复与冷启动后画廊入口就丢失。

## 做法

1. 保存成功后记录该资产 URI 及照片/视频类型并持久化（如偏好存储）；画廊按钮恢复和冷启动直接用它取缩略图，删除成功后清除。
2. 确需整库查询时，先用 abilityAccessCtrl 的 checkAccessTokenSync 核对 READ_IMAGEVIDEO，未授予不调用 getAssets；查询失败或无结果时保留已有缩略图，只在确认当前 URI 已删除时置空。
3. 规格映射 MediaStore 查询行时写明上述权限条件和“以自存 URI 为准”的入口来源，不写成“未授权时只显示本应用媒体”。
