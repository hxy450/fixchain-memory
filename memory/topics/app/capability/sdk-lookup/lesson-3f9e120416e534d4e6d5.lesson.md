# 源端用三方算法库产出要持久化或展示的字符串（RRULE、重复文案、相对时间）时，以库真值的字面输出为契约，不以“自研子集/系统 intl”替代

ID：`lesson-3f9e120416e534d4e6d5` · 版本：2 · 阶段：spec/execute · 主题：[app/capability/sdk-lookup](index.md)

概要：三方算法库输出以库真值字面为契约，不自研子集

信号：`ical4j`, `RRule`, `Recur`, `EventRecurrenceFormatter`, `PrettyTime`, `DateUtils.formatDateTime`, `build.gradle`, `UNTIL`

## 何时使用

规格提取阶段为 build.gradle 中的算法库写映射行与契约时；服务实现阶段替代 lib.toString()、Formatter.getXxx()、PrettyTime.format() 一类库输出，或关闭与其相关的不确定登记时

## 适用情境

源码依赖 ical4j（RRule/Recur 的 toString、getNextDate）、EventRecurrenceFormatter、PrettyTime、DateUtils.formatDateTime 等，库输出被持久化、与其他端互通或直接显示；目标无同名 ohpm 包，映射行写“自研 RFC5545 子集”“系统 intl 相对时间”并只登记毫秒常量；派工要求“与源端产物逐字段兼容”。

## 例外与边界

- 决策记录已批准该库的替代或降级，并写明输出差异

## 原因

映射方向不是契约：库输出的字面形态、文案模板、单位阈值与取整规则由库实现与资源表决定。例：ical4j 3.0.11 的 RRule.toString 产出 FREQ=…;UNTIL=<设备时区本地时间 yyyyMMdd'T'HHmmss>\r\n，UNTIL 不带 Z；规格只登记 UNTIL 的毫秒常量时，实现者无从判断 UTC 与本地浮动时间谁对。PrettyTime 3.2.7 有自己的“刚刚”区间、单位阈值、取整容差与多语言资源，系统 intl 相对时间接口给不出这些规则。“解析侧容忍多形态”“全工程无相等性断言”不能证明产物兼容。

## 做法

1. 规格提取时用本机 Gradle 缓存中的库 jar（或按依赖坐标下载）配 JDK 小程序，对代表输入跑出真实输出，把字面格式（时区形态、行尾、文案模板、单位阈值与取整）写成契约字段；登记常量时同时登记它经库序列化后的字符串。
2. 确无可移植实现或取不到库真值时，按工程的决策分类登记待用户裁决的差异，不在映射行直接写定“自研子集/intl 替代”并标自动化等级。
3. 实现时按库源码移植算法与资源表；系统 i18n/intl 接口只在库本身是系统接口薄封装时才直接替代，否则把自定阈值与库默认逐项对照并登记差异。
4. 登记在案的不确定项只用库真值关闭；不以“解析侧容忍”“无相等性断言”自行宣告 resolved，也不把库文案降级成枚举词。
