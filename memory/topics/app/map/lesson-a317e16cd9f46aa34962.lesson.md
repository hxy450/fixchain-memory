# 源定位 SDK 直接给行政区名而目标 LocationKit 只给坐标时，用逆地理编码取名，不以空名称占位

ID：`lesson-a317e16cd9f46aa34962` · 版本：4 · 阶段：spec/execute · 主题：[app/map](index.md)

概要：定位只给坐标时用逆地理编码取行政区名，不留空名

信号：`geoLocationManager.getAddressesFromLocation`, `geoLocationManager.getCurrentLocation`, `AMapLocation`, `subLocality`, `administrativeArea`, `GeoPoint`

## 何时使用

定位能力实现与规格阶段，把源端定位结果（如高德 AMapLocation 的 district/city）映射为本地城市对象、判断“已定位”状态时

## 适用情境

Android 定位 SDK 的回调直接带 district/city 等行政区名，业务再用经纬度在本地城市库粗筛匹配，粗筛为空时仍用该名称建定位城市；HarmonyOS geoLocationManager.getCurrentLocation 只返回坐标，目标服务接口只列了 locate(): GeoPoint。

## 原因

目标只拿坐标、粗筛失败就写入空名称的定位城市，界面按 ID 或名称判定仍显示“立即定位”，用户看到定位成功却没有位置。来源中实现者读到规格“保留定位返回的名称”和源端取 district、为空取 city 的逻辑，source notes 却写“LocationKit 只给坐标、保留空名称”，没有查平台的逆地理编码。

## 做法

1. 在目标 SDK 中用逆地理编码补名称：geoLocationManager.getAddressesFromLocation，按 subLocality → locality → subAdministrativeArea → administrativeArea 取名；用该名称回查本地城市库补全 ID，坐标粗筛仍作候选。
2. 规格提取时，源端能力由第三方 SDK 隐式附带（定位结果带地址）的，在目标服务接口写明名称来源与降级顺序（district 为空取 city）。
3. “已定位”判定以是否已有定位名称或坐标为准，不只看本地城市 ID 是否大于 0。
