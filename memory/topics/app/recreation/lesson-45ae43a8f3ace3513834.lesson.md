# 源 Activity 为 standard、目标 UIAbility 为 singleton 时，onNewWant 收到的新外部请求带版本号重跑请求解析

ID：`lesson-45ae43a8f3ace3513834` · 版本：1 · 阶段：spec/execute · 主题：[app/recreation](index.md)

概要：singleton 收新请求时带版本重跑请求解析

信号：`android:launchMode`, `launchType`, `onNewWant`, `onCreate`, `getIntent`, `@Monitor`, `ACTION_IMAGE_CAPTURE`, `ACTION_VIDEO_CAPTURE`, `clearTaskOnLaunch`

## 何时使用

规格提取与入口接线阶段，确定外部请求 want 在 onCreate/onNewWant 中的解析、存放与页面消费时

## 适用情境

源 Activity 未设 launchMode（standard），每个外部 intent 新建实例，在 onCreate 读 getIntent extras、结束时 setResult；目标 UIAbility 为 singleton（如由 clearTaskOnLaunch 映射而来），新 want 经 onNewWant 到达已运行实例，want 快照由入口写入、页面或 VM 读取。

## 原因

standard 下每个新请求都有新实例、新的参数读取与结果通道；singleton 只回调 onNewWant，页面与 VM 不会重建。快照只在构造期被拷贝一次时，新 want 只更新了快照，模式、朝向、输出 uri 与结果回传仍沿用旧请求。

## 做法

1. 把“已运行时收到新请求”列为独立场景写进规格与验收。
2. onCreate 与 onNewWant 写同一份请求快照并递增版本号；页面或 VM 用 @Monitor 或回调观察版本号，每次变化都重跑与源端 onCreate 相同的请求解析（模式、朝向、输出位置、限制参数），不只在构造期读取一次。
3. 应用新请求前串行结束旧请求的预览、录像与保存，再应用新参数；旧请求的结果出口按版本号失效，防止旧结果回传给新调用方；切换期间屏蔽交互。
4. 解析 extras 时逐键取自源码与规格：键名、类型、取值域和多个键的先后短路顺序，不凭记忆增删键。
