# 文件导入导出按源端运行时与库默认语义实现：OOM 兜底不改成读前大小阈值，无数量上限就取目标 API 最大值，ZipOutputStream 默认 DEFLATED，picker URI 末段解码后作显示名

ID：`lesson-8534b92df38e546092fe` · 版本：2 · 阶段：spec/execute · 主题：[app/media](index.md)

概要：导入导出按源运行时语义：OOM 兜底与 DEFLATED

信号：`OutOfMemoryError`, `RangeError`, `ZipOutputStream`, `setMethod`, `DEFLATED`, `DocumentViewPicker`, `maxSelectNumber`, `EXTRA_ALLOW_MULTIPLE`, `DISPLAY_NAME`, `decodeURIComponent`, `zlib`

## 何时使用

规格提取与数据层实现阶段，把源端导入导出的异常兜底、压缩流、系统选择器返回值与数量限制映射为目标平台实现时

## 适用情境

Android 导入导出只在 catch(OutOfMemoryError) 时提示文件过大、没有大小阈值；用 ZipOutputStream 打包且未调用 setMethod；以 getFileName 一类 helper 取 DISPLAY_NAME；选择器用 EXTRA_ALLOW_MULTIPLE 不限数量。目标使用 DocumentViewPicker 返回的 URI，系统 zip API 不能控制 entry 名与时间而改手写容器；规格可能把 OOM 兜底写成“读前长度预检”，派工也写了“文件大小上限校验”。

## 例外与边界

- 确需上限或不同压缩方式时登记为有意偏离，并写明数值来源与可见影响

## 原因

读前阈值会拒绝源端能导入的大文件；自定的“安全”数量上限、不压缩的条目与对目录的静默跳过，都改变了导出结果或失败语义；picker 返回的 URI 末段是百分号编码的，直接当显示名会出现 %20 一类字符。来源中规格把 OOM 兜底译成预检，实现者按规格加了 16 MiB 阈值，又自定选择上限 100、因系统 zip API 不可控改成不压缩并跳过非普通文件，页面把未解码的 URI 末段当文件名。

## 做法

1. 源端用 catch(OutOfMemoryError) 兜底时照常读取，捕获目标平台的分配失败（如 RangeError）再提示，不新增读前大小阈值。
2. 源端没有数量限制时取目标 API 允许的最大值（如 DocumentSelectOptions.maxSelectNumber 为 500），不另定更小的“安全值”。
3. 手写 zip 容器时压缩方式仍按源端：ZipOutputStream 未 setMethod 即 DEFLATED，用 zlib 产出原始 deflate 流并加数据描述符；源端会失败的条目（如目录）同样判失败，不静默跳过。
4. 近似源端 helper（如取文件显示名）前先读完它的实现；picker 返回的 file://docs URI 去掉 query/fragment 后对末段 decodeURIComponent，并用含空格或中文的文件名自测。
