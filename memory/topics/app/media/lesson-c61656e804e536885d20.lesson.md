# 源端以 inSampleSize 降采样、按整数读 EXIF 方向时，ImageSource 改设 desiredSize，ORIENTATION 按字符串映射

ID：`lesson-c61656e804e536885d20` · 版本：1 · 阶段：execute · 主题：[app/media](index.md)

概要：降采样改 desiredSize，方向按字符串映射

信号：`inSampleSize`, `BitmapFactory.Options`, `TAG_ORIENTATION`, `DecodingOptions`, `sampleSize`, `desiredSize`, `createPixelMap`, `getImageProperty`, `PropertyKey.ORIENTATION`, `Right-top`

## 何时使用

图片解码实现阶段，把源端降采样解码和按 EXIF 方向旋转迁到 image.ImageSource 时

## 适用情境

源端以 BitmapFactory.Options.inSampleSize 降采样解码缩略图或预览，用 ExifInterface 按整数读 TAG_ORIENTATION 再旋转；目标用 image.createImageSource、createPixelMap(DecodingOptions) 与 getImageProperty(PropertyKey.ORIENTATION)。

## 原因

DecodingOptions.sampleSize 在本机 SDK（API 24）d.ts 只注明“Sampling ratio”，没有说明可用取值；一次设备观察中 sampleSize=8 使解码插件失败。getImageProperty 读 ORIENTATION 返回 "Top-left"…"Left-bottom" 字符串（未定义值为 "Unknown Value <number>"），只有设置时才同时接受数字 1–8（@ohos.multimedia.image.d.ts PropertyKey.ORIENTATION，API 24）；按 Number() 解析得到 NaN，旋转全部丢失。

## 做法

1. 降采样：先 getImageInfo 取原宽高，按源端采样倍数 n 设 desiredSize = { width: 原宽/n, height: 原高/n } 交给 createPixelMap，不把 n 写进 sampleSize；源端 n 不是 2 的幂时 Android 解码器向下取到 2 的幂（BitmapFactory.Options.inSampleSize 文档），按实际生效的倍数算。
2. 方向：把 ORIENTATION 字符串映射为角度——"Top-left"→0、"Right-top"→90、"Bottom-right"→180、"Left-bottom"→270；镜像值（Top-right、Bottom-left、Left-top、Right-bottom）按源端是否处理翻转决定；同时兼容数字串 1/6/3/8，无法识别时按源端读不到方向的默认分支处理。
