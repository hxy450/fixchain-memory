# 源端 Activity 画中画映射到 @ohos.PiPWindow：可用性用 isPiPEnabled，自动进入用 setAutoStartEnabled，画中画状态由 PiPController 的 stateChange 驱动

ID：`lesson-a45be20055d942e12052` · 版本：2 · 阶段：spec/execute · 主题：[app/window](index.md)

概要：画中画映射 PiPWindow 链路，不凭记忆判手机端没有

信号：`PictureInPictureParams`, `onUserLeaveHint`, `onPictureInPictureModeChanged`, `@ohos.PiPWindow`, `isPiPEnabled`, `PiPController`, `PiPConfiguration`, `setAutoStartEnabled`, `stateChange`, `VIDEO_PLAY`

## 何时使用

规格提取与实现阶段，迁移源端画中画（PictureInPictureParams 自动进入、onUserLeaveHint、onPictureInPictureModeChanged、画中画精简 UI 与设置开关）时

## 适用情境

源 Activity 设置 PictureInPictureParams 或在 onUserLeaveHint 进入画中画，按 onPictureInPictureModeChanged 在完整 UI 与精简 UI 间切换；设置页有画中画开关，并检查系统是否允许。目标为 HarmonyOS 手机应用，项目 SDK 含 @ohos.PiPWindow.d.ts。

## 例外与边界

- 项目 compatibleSdkVersion 低于项目 SDK 中 PiPWindow 相关接口的 @since
- 决策已批准应用内替代（如应用内紧凑模式），此时按决策实现并登记差异

## 原因

凭记忆认定“手机端没有画中画”，会把整条链路写成恒 false 的状态和无效的设置行，下游照写。PiPWindow 提供可用性检查、控制器创建、自动启动与状态回调，源端链路的各环节都有对应入口。

## 做法

1. 用 PiPWindow.isPiPEnabled() 判断可用性，设置项的可用状态绑定该结果。可用时，按项目 d.ts 中 PiPConfiguration 的必填字段创建 PiPController（来源用 VIDEO_PLAY 模板加自定义 UI 承载计时界面），由自定义 UI 呈现源端的精简界面。
2. 源端自动进入映射为 controller.setAutoStartEnabled；源端 isInPiP 一类状态改为可观察字段，由 controller 的 stateChange 回调写入，页面据此切换完整与精简 UI。
3. 源端依赖窗口可见性的行为（常亮、回到应用时退出画中画）按“前台或画中画窗口”重新计算，不只看主窗口前后台。
