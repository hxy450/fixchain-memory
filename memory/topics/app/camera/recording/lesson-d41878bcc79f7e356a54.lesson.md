# 同步 MediaRecorder 启停映射到返回 Promise 的 AVRecorder 时，停止共享同一任务、启动逐步查取消，先拆录像输出再释放

ID：`lesson-d41878bcc79f7e356a54` · 版本：1 · 阶段：spec/execute · 主题：[app/camera/recording](index.md)

概要：AVRecorder 启停串行：共享停止任务、启动可取消

信号：`MediaRecorder.prepare`, `MediaRecorder.stop`, `MediaRecorder.release`, `AVRecorder.prepare`, `AVRecorder.start`, `AVRecorder.stop`, `AVRecorder.release`, `BusinessError`, `VideoOutput.release`

## 何时使用

录像编排与录像引擎实现、规格提取阶段，把同步完成的 MediaRecorder 启停与停录后重连相机映射到 AVRecorder 和 CameraKit 时

## 适用情境

源端 MediaRecorder 的 prepare/start/stop/release 同步完成，停止后立即置空录制器并重连相机，重复停止自然被挡住；目标 AVRecorder 的 prepare、start、stop、release 都返回 Promise（API 24 media.d.ts L5265、L5479、L5678、L5797），录像输出还要从会话挂接与拆卸。

## 原因

只在 stop 兑现后才置空，重复调用会再次 stop；prepare→start 链不检查取消，准备期间的停止被忽略，录制随后仍然开始；拆卸 hook 定义成不返回 Promise 并放在 release 之后，录制器释放时输出仍挂在会话上；按 error.message 子串判错、失败时不复位启动标志，状态会卡住。

## 做法

1. 规格接口表按目标 d.ts 写成 Promise，并写明串行契约：重复停止共享同一任务；准备期间停止要取消启动；关闭相机先等停录且不再重连；先拆录像输出再释放录制器。
2. 发起停止时同步记下停止请求并返回共享的停止任务；prepare、挂接、start 的每个 await 之后检查是否已被取消，已取消就走清理、不开始录制。
3. 停止顺序：await AVRecorder.stop() → await 拆卸录像输出（挂接与拆卸 hook 都返回 Promise）→ await release() → 再按需重开或重连；关闭相机引起的停录不自动重连。
4. 错误按 BusinessError.code 数值分档（stop 可能以 5400102、5400103、5400105 拒绝，media.d.ts L5670–L5676），启动标志在 finally 中复位；stop 失败时删除不完整文件并回传空结果，不以原 URI 报成功。

## 可选检查

- 单测覆盖连续两次停止、准备期间停止、录像中关闭相机三种时序：recorder.stop 只调用一次、未开始录制、没有自动重开
