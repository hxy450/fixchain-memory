# 录制器原生时长、文件大小上限改由应用层定时器或轮询承接时，按不含暂停的已录时长计时，到达文件上限按是否自动重启分别停止或重启

ID：`lesson-1957f0e6ad83f19258e8` · 版本：1 · 阶段：spec/execute · 主题：[app/camera/recording](index.md)

概要：应用层录像限额按已录时长计，保留停止分支

信号：`setMaxDuration`, `setMaxFileSize`, `OnInfoListener`, `MEDIA_RECORDER_INFO_MAX_DURATION_REACHED`, `MEDIA_RECORDER_INFO_MAX_FILESIZE_REACHED`, `AVRecorderConfig`, `maxDuration`, `statSize`, `setTimeout`

## 何时使用

录像功能实现与规格提取阶段，用应用层定时器、文件大小轮询或异步启动替代 MediaRecorder 的时长/文件大小上限、onInfo 事件与自动重启计数时

## 适用情境

源端由 MediaRecorder.setMaxDuration/setMaxFileSize 让录制器自行计时与停止并经 onInfo 回调，pause/resume 只累计已录时长，自动重启的剩余次数在同步启动后递减；目标 AVRecorderConfig 只有以秒计的 maxDuration（API 18 起，到达后自动停止并以 stateChange 通知 stopped，media.d.ts L8134–L8142），没有文件大小上限字段，prepare/start 返回 Promise。

## 原因

用一次性墙钟定时器替代时长上限，暂停期间也在消耗预算；只在开启自动重启时处理合成的“到达文件上限”，未开启时录制不会停止；源端在启动调用内同步执行的初始化迁到异步回调后，晚于调用方的递减执行，有限的重复次数被重新补满。

## 做法

1. 时长预算按不含暂停的已录时长：暂停时清除定时器并累计已录时长，恢复时按“上限 − 已录时长”重新安排，pause/resume 加防重入。改用原生 maxDuration 时注意单位是秒，并先核对它是否排除暂停区间再依赖它。
2. 用 statSize 轮询合成“到达文件上限”时实现源端 onInfo 的全部分支：开启自动重启就开始下一段，否则停止录制；关闭相机时取消进行中的重启。
3. 依赖同步时序的计数（启动后递减剩余次数、只有首段才初始化）改在发起端同步初始化，用显式参数区分首段、重复段与文件上限重启段，不依赖回调晚于递减的时序。
4. 规格提取时，多分支事件处理（onInfo 的每个 what）每个分支都写验收或写明跳过理由；平台缺少原生限额时在映射表登记替代方式及其暂停、停止语义。

## 可选检查

- 单测：暂停期间不消耗时长预算；设重启 N 次时录 N+1 段，剩余次数逐段递减到 0
