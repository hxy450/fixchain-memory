# 建 CameraKit 拍照会话时同一次 beginConfig 加齐输入与预览、拍照输出再 commitConfig，拍照档不硬限 JPEG

ID：`lesson-05cd365740c0003662a4` · 版本：1 · 阶段：execute/repair · 主题：[app/camera/session](index.md)

概要：会话一次配齐输出再提交，拍照档不硬限 JPEG

信号：`createCaptureSession`, `ImageReader`, `beginConfig`, `addInput`, `addOutput`, `commitConfig`, `canAddOutput`, `createPhotoOutput`, `photoProfiles`, `CAMERA_FORMAT_JPEG`, `CAMERA_FORMAT_RGBA_8888`, `photoAssetAvailable`

## 何时使用

相机控制器实现与返修阶段，确定 CameraKit 会话的输入输出组合、提交时机、开流前的能力探测方式与拍照 profile 选择时

## 适用情境

源端 Camera2 createCaptureSession 一次传入预览 surface 与 JPEG ImageReader（录像时再加录制 surface）；目标用 Session 的 beginConfig→addInput→addOutput→commitConfig，打开相机后还要先取能力再建正式会话；getSupportedOutputCapability 返回的 photoProfiles 格式随运行环境而异，有的模拟器只报告 RGBA_8888。

## 原因

只含输入就 commitConfig，或在运行中的会话上惰性 addOutput，会导致提交失败、预览黑屏；源端“一次带齐全部输出”的语义丢在了拆开的探测与启动函数之间。按拍照字节通路的格式假设（只取 JPEG 组件）硬过滤 profile、无 JPEG 就抛错，会让只报 RGBA 的环境连相机都打不开。

## 做法

1. 按源端 surfaces 清单，在同一次 beginConfig 中 addInput 并加齐预览与拍照输出（录像会话见录像经验）后再 commitConfig；addOutput 前用 canAddOutput 判定，它只在 addInput 之后、commitConfig 之前有效（API 24 camera.d.ts L4779–L4796）。
2. 开流前需要能力时，用 CameraManager.getSupportedOutputCapability(camera, mode) 的静态能力，或建带输出的探测会话；不提交只含输入的会话，也不在运行中的会话上补 addOutput，需要换输出时按拆卸顺序重建会话。
3. 拍照 profile 选择保持格式无关，或 JPEG 优先、RGBA_8888 兜底；非 JPEG 拍照经 photoAssetAvailable 资产通路（camera.d.ts L7865）或已有编码路径处理。能力枚举只排除确实无法处理的格式并按尺寸去重，不把格式假设写成打开相机或探测会话的硬失败。

## 可选检查

- 改动 profile 过滤或会话组成后，在目标设备或模拟器打印 photoProfiles 的 format 与 size 并看预览能否出帧
