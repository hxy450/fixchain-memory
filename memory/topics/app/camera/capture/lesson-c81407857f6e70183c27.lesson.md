# 从 photoAvailable 的 Photo 取 JPEG 字节交给异步保存时，先复制字节再 release Photo，或在消费完成后 release

ID：`lesson-c81407857f6e70183c27` · 版本：1 · 阶段：spec/execute · 主题：[app/camera/capture](index.md)

概要：Photo 字节先复制或用完再 release，不释放后用

信号：`photoAvailable`, `Photo.release`, `getComponent`, `byteBuffer`, `onImageAvailable`, `Image.close`, `ImageReader`

## 何时使用

拍照回调实现与规格提取阶段，把源端 onImageAvailable 的取帧与 close 时机迁到 CameraKit photoAvailable 回调，并决定字节交给谁消费时

## 适用情境

源端在 onImageAvailable 中先把 JPEG 复制到 byte[] 再 image.close()；目标在 photoAvailable 回调里经 Photo.main.getComponent 取 component.byteBuffer，字节随后进入后台保存队列等异步消费方，Photo.release() 返回 Promise。

## 例外与边界

- 回调内同步消费完全部字节、不再把该 ArrayBuffer 交给任何异步方

## 原因

component.byteBuffer 引用的是 Photo 持有的原生缓冲；先 release 再把同一个 ArrayBuffer 交给排队保存，相当于释放后使用，保存内容可能为空或损坏。源端“先复制再关闭”的顺序只在源码行里，规格若只抽“无回调时 close”，实现方就看不到这一约束。

## 做法

1. 取到 component 后，字节要交给异步消费方时先 byteBuffer.slice(0) 复制，再 await photo.release()；或把 release 放进消费完成后的 finally。不要在 getComponent 之后立即 release 再传同一个 ArrayBuffer（API 24 @ohos.multimedia.camera.d.ts：Photo 只有 main: image.Image 与 release(): Promise<void>，L7502–L7534）。
2. 规格提取时，把原生图像回调的“先复制字节再 close/release”写成验收条目，并为控制器侧 JPEG 取帧指明归属切片。
