# 用 @ohos.xml 重建 SAX 开始事件时采用与回调顺序无关的组装，并自建命名空间作用域

ID：`lesson-447985a4376146f6d9f2` · 版本：2 · 阶段：execute · 主题：[data/parsing](index.md)

概要：@ohos.xml 开始事件按顺序无关组装并建命名空间栈

信号：`@ohos.xml`, `XmlPullParser`, `tokenValueCallbackFunction`, `attributeWithTagCallbackFunction`, `getNamespace`, `START_TAG`, `END_TAG`, `xmlns:p`

## 何时使用

实现阶段，用 XmlPullParser 的 token 与属性分离回调重建 namespace-aware 开始事件（本元素属性与命名空间 URI）时

## 适用情境

源 SAX/XmlPullParser 在开始标签读取本元素属性并按 uri 加前缀分发命名空间；目标用 tokenValueCallbackFunction 与 attributeWithTagCallbackFunction 两路回调，SDK 声明未写两路回调先后，也未保证 getNamespace() 给出元素 URI。

## 原因

在 START_TAG 时快照并清空属性只在属性先到时成立；修复期实测（API 23）为 START_TAG 先于属性，每个元素拿到上一元素的属性。只依赖 getNamespace() 会丢命名空间（依据字段缺失推断，未直接观测其返回值）。

## 做法

1. 能实测时先用最小样例打印两路回调的实际次序与 getName/getPrefix/getNamespace 返回值；无法实测时 START_TAG 先挂起，到下一个 token 或文档结束时连同已累积属性一起分发。
2. 把 xmlns 与 xmlns:p 属性按元素深度建作用域栈，URI 为空时按前缀解析，END_TAG 时弹出。
3. 源码理解笔记中的不确定项写明待验证条件，不写成“两种顺序行为一致”；其他 XML 读取器复用同一回调骨架前，先确认先例已实测或已改为顺序无关。

## 可选检查

- 带前缀的命名空间字段解析结果缺失时，用各命名空间一条样例断言分发到对应处理器
