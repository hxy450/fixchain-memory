# 自写二进制元数据写入器替代 ExifInterface 等库时，tag 号与字符串转值从库源码取，值区跨 IFD 顺排，按输出编码选容器

ID：`lesson-ac58c27e534158e65647` · 版本：1 · 阶段：spec/execute · 主题：[data/parsing](index.md)

概要：自研 EXIF 写入按库源码取语义，值区顺排

信号：`ExifInterface`, `setAttribute`, `setGpsInfo`, `TAG_GPS_TIMESTAMP`, `TAG_XMP`, `TAG_INTEROPERABILITY_INDEX`, `IFD`, `SRATIONAL`, `UserComment`, `APP1`, `eXIf`, `VP8X`

## 何时使用

规格决定自研替代库与数据层实现阶段，编写 TIFF/EXIF 序列化、tag 表、GPS 写入、图像容器拼接与失败处理时

## 适用情境

源端经 androidx ExifInterface 按 tag 名读写 EXIF（setAttribute 字符串值、setGpsInfo(location)、按策略删除 XMP/Interop 等），并对 JPEG/PNG/WebP 输出统一写 EXIF；目标规格决定自研 TIFF/EXIF 段写回。

## 原因

库按 tag 名隐藏了数字 tag 号、子 IFD、字符串到二进制的转换和便捷方法写入的字段，这些都不在调用方源码里；凭记忆补写会写错 tag 号、让源端要删除的 tag 变成空操作、漏写 GPS 字段。TIFF 的多个 IFD 共用值区，每个 IFD 都从同一起点分配会让超长值互相覆盖；有符号类型按无符号读写、ASCII/UNDEFINED 跳过 NUL 会改变值本身。PNG、WebP 有各自的原生 EXIF 容器，套用 JPEG 的 APP1 拼接得到损坏文件。

## 做法

1. 从源端依赖的库版本（build.gradle 中的 androidx.exifinterface 版本）源码取 tag 号、子 IFD 指针、setAttribute 的字符串→二进制规则（如 GPSTimeStamp 'HH:mm:ss' 写成三个有理数 H/1,M/1,S/1）和便捷方法写入的字段：setGpsInfo 写 GPSProcessingMethod、经纬度、海拔，用 Location 自身时间写 GPSDateStamp/GPSTimeStamp，速度由 m/s 换算为 km/h（×3.6）写 GPSSpeed 并置 GPSSpeedRef='K'（androidx.exifinterface 1.4.1 setGpsInfo 字节码）。源端会删除的 tag 给出真实 tag 号或子 IFD，查不到时登记为未确认项，不用占位值让删除变成空操作。
2. 序列化按“各 IFD 目录块（2+12n+4 字节，TIFF 6.0 规范）→ 共用值区”布局，超过 4 字节的值在值区按写入顺序跨 IFD 依次推进偏移；SSHORT/SLONG/SRATIONAL 用 getInt16/getInt32、setInt16/setInt32 有符号读写；ASCII 读到首个 NUL 截断，UNDEFINED 原样保留含 NUL 的字节（如 UserComment 的 'ASCII\0\0\0' 前缀）。
3. 按输出的实际编码选容器：JPEG 写 APP1 段，PNG 写带 CRC 的 eXIf 块，WebP 写 RIFF 的 EXIF 块并置 VP8X 的 EXIF 标志；源库覆盖 PNG/WebP 时目标同样覆盖，规格映射写全库覆盖的容器。
4. 失败与早退按源端：只对源端实际捕获的异常类型（如类缺失）兜底，源方法声明抛出的写入失败上抛，不保存未处理的元数据；源图没有 EXIF 而源端照常写入时，用空文档继续，不新增 return。

## 可选检查

- 对序列化有疑问时跑一次 parse(serialize(doc)) 往返：各 IFD 放超过 4 字节的值，再放负的 SSHORT/SLONG/SRATIONAL 与含 NUL 的 UNDEFINED，逐 tag 比对字节
