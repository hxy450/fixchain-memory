# 源端 SharedPreferences 读取等载入完成：偏好封装用 getPreferencesSync 同步装载并走 Sync 接口，不改成异步载入加写队列

ID：`lesson-93b3eeff61598bc42172` · 版本：3 · 阶段：spec/plan/execute · 主题：[data/preferences](index.md)

概要：偏好入口同步装载，读写走 Sync 接口

信号：`getSharedPreferences`, `PreferenceManager.getDefaultSharedPreferences`, `getPreferencesSync`, `getPreferences`, `getSync`, `getAllSync`, `putSync`, `flushSync`, `awaitLoadedLocked`, `SharedPreferencesImpl`, `EntryAbility.onCreate`

## 何时使用

基础层实现阶段，设计偏好存储封装的初始化时机与读写提交方式时；派工或规格阶段为偏好层撰写验收标准时

## 适用情境

源端经 getSharedPreferences 或 PreferenceManager.getDefaultSharedPreferences 取偏好，在 Application.onCreate 等首个读写之前构建；目标准备用 Promise 版 getPreferences 异步装载，加内存缓存与待写队列，或派工、规格把源端时序转述成“异步初始化容错、context 未就绪时缓存写入”。

## 原因

Android SharedPreferencesImpl 构造时在后台线程读盘，但每个 getXxx 与 edit() 都先 awaitLoadedLocked 阻塞到载入完成（本机 android-36.1 android/app/SharedPreferencesImpl.java），源端读点拿不到“未载入时的缺省值”，写入按调用顺序立即反映在内存。改成异步装载后，就绪前的读返回调用方缺省值，页面可能据此渲染错误状态或把缺省值写回；各写操作分别排队、在 await 间隙后清空队列会丢掉期间到达的新写；就绪前的 clear 只清缓存，载入后旧数据又回来。

## 做法

1. 在 EntryAbility.onCreate（任何页面或服务读偏好之前）用 preferences.getPreferencesSync(context, { name }) 取单一实例；读用 getSync(key, 调用方缺省值)，需要整表时用 getAllSync。
2. 写入用 putSync/deleteSync/clearSync 立即改内存实例，保持源端调用顺序与读到新值的时机；落盘按源端提交方式：apply() 对应异步 flush()，依赖 commit() 同步结果的流程用 flushSync()（API 14 起；compatibleSdkVersion 低于 14 时用 await flush()；本机 SDK API 24 @ohos.data.preferences.d.ts）。
3. 派工或规格描述偏好层时按源端初始化代码写时序（同步构建、读阻塞至载入完成），不把“异步容错/写队列”写成对齐语义；实现者写前读到的源码与该描述不一致时按源码实现并回报分歧。
4. 确有理由异步装载时，在封装接口上写明就绪前读的返回值，并让所有读点在就绪后再读，可见结果与源端一致；做不到就改回同步装载。
