# 源端 SharedPreferences.Editor 累积 put 后一次 commit 的流程（恢复、导入），目标先暂存、全部校验通过后再 put 并 flush：preferences.putSync 立即改共享实例，中途失败不能留下部分写入

ID：`lesson-24bc4929b771a9a33ef4` · 版本：2 · 阶段：execute · 主题：[data/preferences](index.md)

概要：批量 commit 改为先暂存校验再 putSync

信号：`SharedPreferences.Editor`, `editor.putX`, `putSync`, `flushSync`

## 何时使用

数据层实现阶段，迁移 Editor 批量写入后 commit/apply 的恢复或导入流程时

## 适用情境

源端遍历输入逐键 editor.putX，遇到未知键或格式错误时抛出，末尾才 commit；目标准备逐键 putSync 到共享 preferences 实例。

## 原因

Editor 的修改在 commit 前对实例不可见，中途失败时偏好不变；putSync 立即生效，失败后已解析的值会留在内存实例里。

## 做法

1. 把解析出的值先放进暂存表，全部校验通过后再依次 put 并 flushSync；失败分支直接丢弃暂存。验证时注入中途失败，再读实例确认未变。
