# 源端用 FileOutputStream/openOutputStream 整文件覆盖写时，fileIo 加 TRUNC 并按 writeSync 返回值写完

ID：`lesson-89496d5566f87f197bba` · 版本：1 · 阶段：execute · 主题：[data/storage](index.md)

概要：覆盖写加 TRUNC，按 writeSync 返回值写完

信号：`FileOutputStream`, `openOutputStream`, `OutputStream.write`, `fileIo.openSync`, `fileIo.writeSync`, `OpenMode.TRUNC`, `Uint8Array`, `byteOffset`, `byteLength`, `subarray()`

## 何时使用

文件写入实现阶段，把 Java 输出流写文件或写 URI 改成 fileIo 调用时

## 适用情境

源端用 new FileOutputStream(file) 或 ContentResolver.openOutputStream(uri) 加 OutputStream.write(data) 写入完整内容并覆盖旧文件；目标用 fileIo.openSync/writeSync，字节以 Uint8Array 在各层间传递，可能是 subarray 视图。

## 例外与边界

- 源端以追加模式打开（如 FileOutputStream(file, true)），此时用 OpenMode.APPEND 而非 TRUNC

## 原因

new FileOutputStream(file) 截断已有文件，OutputStream.write(byte[]) 写完全部字节；fileIo.openSync 不加 OpenMode.TRUNC 会保留旧内容，新内容较短时留下旧尾部；writeSync 返回本次实际写入的字节数（@ohos.file.fs.d.ts，API 24），需按它确认是否写完。Uint8Array.buffer 是整块底层缓冲，直接传它会把视图 byteOffset 之前与 byteLength 之后的字节一并写入。

## 做法

1. 按源端覆盖语义打开：fileIo.openSync(pathOrUri, OpenMode.WRITE_ONLY | OpenMode.CREATE | OpenMode.TRUNC)。
2. 按 writeSync 返回值推进已写字节数，循环到全部写完；返回 0 时抛错，不吞掉写入失败。
3. 传 ArrayBuffer 前按视图切出：bytes.buffer.slice(bytes.byteOffset, bytes.byteOffset + bytes.byteLength)，不直接传 bytes.buffer。
4. 沿用示例写法前确认示例场景（新建空文件、写一次字符串）与当前写入一致；覆盖已有文件或写二进制时按上面三步。
