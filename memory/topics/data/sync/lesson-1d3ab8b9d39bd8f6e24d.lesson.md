# 源端不等待的落库改为异步写后，在落库完成后再广播触发重查的事件

ID：`lesson-1d3ab8b9d39bd8f6e24d` · 版本：2 · 阶段：execute · 主题：[data/sync](index.md)

概要：异步落库完成后再广播触发重查的事件

信号：`Promise`

## 何时使用

平台适配阶段，同一流程写入数据库后再发事件让订阅方重查数据库时

## 适用情境

源端落库与事件发送近似同步或不等待；目标数据库写入返回 Promise，订阅页收到事件后重查。

## 原因

事件先于落库到达时，订阅方重查读到旧值（如暂停时位置停在节流前的旧值）。

## 做法

1. 保留写入的 Promise，落库完成后再广播，或在落库后补发一次事件。
