# 移植加解密工具时逐分支保留源工具的前置返回与异常回退：空串不进 Cipher，解密失败回退为原文

ID：`lesson-4232e195ff42fc63ba43` · 版本：3 · 阶段：spec/execute · 主题：[data/network-request](index.md)

概要：移植加解密工具保留空串直返与解密失败回退原文

信号：`AESUtil`, `aesEncrypt`, `aesDecrypt`, `isEmpty`, `cryptoFramework`, `AES-CBC`, `String(value ?? '')`, `beforeResponse`

## 何时使用

规格提取与网络层实现阶段，确定响应解密/解码步骤的失败语义，或把 Android 请求参数加密与响应解密工具（AESUtil、aesEncrypt/aesDecrypt 一类）移植为 cryptoFramework 封装时

## 适用情境

Android 加密工具开头以 isEmpty 直接返回空串、不调用 Cipher，解密在 catch 中返回原文（明文响应也能通过）；目标用 cryptoFramework 对每个业务值做 AES-CBC，业务参数可能为空（如缺省城市没有经纬度），部分接口返回明文 JSON。也包括源端在响应转换钩子（如 beforeResponse）里于 release 下无条件调用 aesDecrypt，是否所有接口都返回密文没有抓包证据，规格或台账准备写“解密失败显式报错、不伪造成功”。

## 原因

只移植主路径时，空串送进 Cipher 在目标框架拿到 undefined，随后访问 byteLength 崩溃，请求在组装阶段就失败、从未发出；解密异常直接抛错，则明文响应被判为失败。规格以“显式失败、不伪造成功”一类通用错误策略写解码失败语义时同样丢掉这条回退，实现者照规格写成失败即报错，服务端返回明文的接口全部失败。来源中网络层写者写前已读到 isEmpty 直接返回与 catch 返回原文两个分支，输出仍是无条件加密、解密失败即抛，单测只用假加密器，没有覆盖空值与明文。

## 做法

1. 逐分支列出源加解密工具的前置返回和异常回退（空串、密钥长度、catch 返回原文），在目标封装逐一保留；空值直接返回源端同值（通常为 ''）。
2. 目标做 null/undefined 归一化（如 String(value ?? '')）后，核对该值在源端会走加密工具的哪个分支。
3. 解密失败时按源端回退为原文再解析，只有解析也失败才报错；用真实加密封装补空值与明文响应的用例。
4. 规格写响应解码的失败语义时，沿响应钩子追到被调工具函数的异常分支，把“失败回退原文 / 抛错 / 返回空”照源写进契约；是否全接口密文尚无证据时保留源端容错路径：解密失败按原文进入信封解析、由业务码判定成败，不选更严格的分支再把明文兼容推迟到联调。
