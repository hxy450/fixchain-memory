# 按源端实际色值与字号在资源里反查同值键：主题语义色、排版样式先解析到值，不按 accent、primary、title/body 等名称或别页令牌选键

ID：`lesson-4e9507a2a793c5583aa8` · 版本：6 · 阶段：execute · 主题：[ui/theme/tokens](index.md)

概要：按源端实际色值与字号在资源中反查同值键，不按名选键

信号：`color.json`, `float.json`, `$r('app.color`, `$r('app.float`, `design_tokens_missing`, `shapeSolidColor`, `typography.titleMedium`, `colors.textPrimary`, `Color.GREEN`, `text_size_large`

## 何时使用

界面实现阶段，为按钮、背景、文字与渐变色阶设置颜色资源引用，或为文本绑定字号资源令牌时

## 适用情境

源端颜色以 shapeSolidColor、background、textColor 等硬编码色值或色值资源给出；目标工程已有多组语义名相近但色值不同的颜色资源（如脚手架留下的 color_accent 与迁移出的 brand_accent）。也包括 Compose 源端以主题语义色（如 colors.textPrimary）或排版样式（如 MaterialTheme.typography.titleMedium）取值，而目标 color.json/float.json 只有部分令牌：有名称相近或其他页面前缀的键（text_secondary、feed_font_title），缺同值键，流程要求缺令牌时报告 design_tokens_missing。也包括用 text_size_large、text_size_small 一类名称暗示大小的命名资源承载源端数值（如 16sp 标题、12sp 信息条），或同一组件中语义不同的颜色（进度轨道与选中行底色）准备共用一个已有 token。也包括 Java 以 Color.GREEN、Color.RED 等框架颜色常量着色，规格映射成名称相近、色值不同的应用色（如 light_green #FF66FF66）。

## 原因

资源名只表达意图，模板或脚手架生成的 accent 可能是默认蓝；按名字选键时代码看似引用了主题色，渲染出的颜色却与源端不同，编译和结构检查都发现不了。来源中实现者照抄了按钮高度、圆角与字色，唯独背景按名字选了蓝色 accent，而工程里另有与源端色值相同的键，直到视觉回归才被发现。另一应用中同类选择出现三次：分组标题的 textPrimary（该主题中等于品牌色）被静默写成近黑的 text_secondary；个人页 titleMedium/bodyMedium（16/14）绑定到首页 20fp/16fp 的标题/正文令牌；已正确的渐变字面色值被换成三处值不同的现有令牌。写者都读到了源端取值，也收到了缺令牌须报告的规则。

## 做法

1. 取源端控件的实际色值（展开 shape、selector、style 后的最终值），在 color.json 中找同值键引用并核对该键的值；没有同值键就新增语义资源（被其他页面引用的共享令牌不改值），不借用名字相近或同前缀的键；为消除 hex 字面量改写已正确的字面色值时同样按值找键。
2. 源端用主题语义色或排版样式名时，先在 Theme/Color/Type 定义或设计令牌表中解析到具体值（如该主题的 textPrimary 等于 brand、titleMedium 为 16sp），再按值找键；缺同值键时按调色板或样式名新增令牌，或按流程报告 design_tokens_missing，不用名称相近或其他页面前缀的现有令牌代替。
3. 选用命名资源前读其实际值，注释里写的数值与所引资源一致；同一组件中语义不同的颜色不共用一个 token，从已有组件照搬颜色前先核对源端是否同色。
4. 框架颜色常量按色值匹配（Color.GREEN=#FF00FF00、Color.RED=#FFFF0000），没有同值键就新增，不用名称相近的应用色代替。
