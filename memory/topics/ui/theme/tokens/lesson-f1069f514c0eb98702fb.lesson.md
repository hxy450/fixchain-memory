# 应用内主题切换不只依赖 setColorMode：命令式取色、系统栏与画布要随主题重解析

ID：`lesson-f1069f514c0eb98702fb` · 版本：2 · 阶段：execute · 主题：[ui/theme/tokens](index.md)

概要：应用内切主题时命令式取色随主题重解析

信号：`setColorMode`, `getColorSync`, `getOverrideResourceManager`, `setWindowSystemBarProperties`, `onConfigurationUpdate`, `colorMode`, `Canvas`

## 何时使用

实现阶段，设计应用内深浅色切换，并为系统栏、Canvas、HTML 样式等非 $r 消费点取色时

## 适用情境

源换主题靠 Activity 重建；目标用 ApplicationContext.setColorMode 切换，同时存在 getColorSync 取色、setWindowSystemBarProperties 内容色、Canvas 画笔色与内联 CSS。

## 原因

setColorMode 会让 $r 资源重解析，但修复期真机实测：应用内选深色而系统为浅色时，context.resourceManager.getColorSync 仍按设备配置取值；画布色只在初始化取一次也不会更新；写死的系统栏内容色在深色下不可读。

## 做法

1. 切换前检索 getColorSync/getColor、Canvas 取色、内联色与系统栏设置，逐类写明切换后由谁重解析。
2. 提供按当前主题覆写 colorMode 的资源管理器（resourceManager.getOverrideResourceManager），由主题控制器统一导出；取色点订阅主题态或 onConfigurationUpdate 后重解析并重绘。
3. 系统栏内容色按生效 colorMode 计算（亮色 #000000、暗色 #FFFFFF），并在 onConfigurationUpdate 中重设。
4. 移植构造期取色的自绘 View 时，把取色写成可重入的方法。
