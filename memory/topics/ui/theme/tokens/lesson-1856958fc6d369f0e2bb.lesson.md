# 主题提供的颜色按各主题与深浅两态取值导出成对 base/dark 键：先把引用分成 ?attr 主题属性与 @color 写死两类，values-night 同名 style 未写的主题属性回落框架深色默认；取 Android 框架实际值，不以目标平台 sys token 代替

ID：`lesson-1856958fc6d369f0e2bb` · 版本：4 · 阶段：spec/execute · 主题：[ui/theme/tokens](index.md)

概要：?attr 主题色逐主题取值导出 base/dark 对键

信号：`?attr/colorPrimary`, `colorControlNormal`, `colorOnSecondary`, `values-night`, `Theme.AppCompat.DayNight`, `colorAccent`, `textColorSecondary`, `primary_text_default_material_light`, `fillColor`, `color.json`, `sys.color`

## 何时使用

资源前置、规格提取或界面实现阶段，为引用 ?attr 的图标 fillColor、工具栏主题色、自绘组件前景色或文字色新建或选择颜色 token 时；把 AppCompat DayNight 应用（含日间覆写主题色、values-night 重新定义同名 AppTheme 的情况）映射为 base/dark 颜色资源与页面配色时

## 适用情境

源图标与控件颜色来自主题属性（应用自定义的图标色属性、colorControlNormal=colorOnSurface、colorOnSecondary 等），各主题取值不同；目标 SVG 只保留浅色值，color.json 可能缺对应键。也包括 AppTheme 只继承 Theme.AppCompat.DayNight、没有 values-night、没有 colorPrimary/colorAccent 覆写：窗口、对话框、ActionBar、状态栏、按钮、主次文字、提示、禁用、强调色与分隔线都来自框架默认并随深浅色变化。也包括日间 AppTheme 覆写了 colorPrimary/colorPrimaryDark/colorAccent，values-night 重新定义同名 AppTheme 却没写这些项：夜间回落 AppCompat 深色默认（#212121/#000000/#80CBC4），布局中 ?attr/colorPrimary 处随之变色，@color/colorPrimary 写死处保持不变。规格可能把业务调色板镜像到 dark 当作深色适配，各页转换器各自补键、按某一模式写死 white，或改用目标平台 sys.color 语义色。

## 原因

缺键时借用语义不同的灰色、按名称猜为强调色，或 base/dark 写同一个值，会让颜色在某个主题下错误，并随先例扩散。DayNight 应用的外观几乎全由框架两态默认色决定；把 ?attr 引用与 @color 写死统一成一个常量色，夜间就无法只让主题属性变色。“框架默认色不猜”一类措辞会被召回压成“不导出”，资源前置只写少数键；改用目标平台 sys 语义色则与 Android 框架取值不同。

## 做法

1. 先把颜色引用分成两类：布局与样式里的 ?attr（?attr/colorPrimary、?android:textColorSecondary 等）与 @color 写死。逐主题求 ?attr 的取值，包括 values-night 中的同名 style，夜间块没写的项取父主题（AppCompat 深色）默认；主题属性另建 theme_* 成对键（base/dark 各一），写死色保持常量键，页面按源端引用类型分别绑定。
2. 查矢量 fillColor 或工具栏主题引用的属性，分别取各主题 style 中的值，在 base/dark 各写一个键；检索时不要把目标属性名排除在外。
3. 自绘组件的 foregroundColor=?attr 先查 attrs/styles 的实际值再定默认色，各调用点按自己布局传参。
4. 图标 Image 用 fillColor 绑定该 token，不沿用未着色的先例；资源前置阶段把被引用的主题属性连同解析值导出为颜色键并在映射表注明。
5. 源为 DayNight 时，在规格中列出框架浅、深两态的窗口、对话框、ActionBar、状态栏、按钮、主次文字、提示、禁用、强调色与分隔线取值，成对写入 base/dark；页面背景、文字与菜单颜色只引用这些成对 token，不按某一模式写死，也不把深色适配留待以后。
6. 框架默认值（colorAccent、主次文字色 primary_text_default_material_light #DE000000 与 secondary #8A000000、列表分隔线等）先查依赖的 appcompat/material aar 或本机 SDK 平台资源，或用源端运行截图核对，再写入成对键；查不到才登记未决，不落猜测值，也不用 $r('sys.color.ohos_id_*') 等目标平台语义色代替。
