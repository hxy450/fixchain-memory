# 布局引用的 @drawable（progressDrawable、背景 shape、标签背景、光标 shape）先打开取数值：高度、圆角、轨道色、渐变、描边与光标宽色写进规格与实现

ID：`lesson-771d1ba1a032b769097a` · 版本：4 · 阶段：spec/execute · 主题：[ui/theme/sources](index.md)

概要：布局引用的 @drawable 先打开取数值写进规格与修饰链

信号：`progressDrawable`, `textCursorDrawable`, `layer-list`, `caretStyle`, `borderRadius`, `@drawable`, `backgroundImage`

## 何时使用

规格提取与界面实现阶段，为进度条、搜索框、分组标签等引用 drawable 的控件确定高度、圆角、颜色与描边时

## 适用情境

源布局以 progressDrawable=@drawable/xxx、background=@drawable/bg_xxx 引用 layer-list/shape 资源，尺寸、圆角、轨道色、渐变和描边写在被引用文件里；目标工程可能已有名称相近、含义不同的颜色资源。也包括 EditText 用 textCursorDrawable 引用 shape 定义光标宽度与颜色，且只设在部分字段上。

## 原因

不打开被引用的 drawable，就只能自定高度或沿用工程里已有的颜色，样式与源端不符。来源两例：启动页规格作者列 drawable 目录的命令因 -LiteralPath 不支持通配符报错后未重试，进度条写成 4vp 高并沿用浅灰轨道色，而源端是 12dp、浅蓝轨道、圆角与渐变；城市选择页修复未读搜索框与分组标签的背景文件，分组标题色、搜索框描边与图标、网格外边距到第二轮才对齐。另一应用中，stage 资源转换把 shape 转成 24×24 的 SVG，映射参考又只有“@drawable/bg → backgroundImage”一条通用行：添加城市页写者读到了 SVG 的颜色与 rx，仍以 backgroundImage + Cover 铺到非方形容器；城市卡写者没打开源 shape（10dp 圆角与两种选中色），同样按图片铺设，圆角底色被缩放裁切。另一应用中写者没打开 login_edit_cursor_color，照同族页面把两个输入框都设成蓝色光标；该 shape 实为 2dp #ffdb20，且源端只给验证码框设置。

## 做法

1. 遇到 @drawable 引用就打开被引用文件，把高度、圆角、轨道/前景色、渐变与描边值写进规格和修饰链；不自定高度，不按名称套用工程里含义不同的颜色。
2. 列目录或读取命令报错（如 -LiteralPath 带通配符）时改用 -Path/-Filter 重试，未读到资源前不定稿；写后才读到的数值回写到已生成片段。
3. shape（solid + corners，有 stroke 再加描边）直接写成 backgroundColor + borderRadius（+ border）；不把转换得到的固定尺寸 SVG 以 backgroundImage + Cover 铺到非方形容器。
4. textCursorDrawable 引用的 shape 读出 solid 颜色与 size 宽度，写成 caretStyle({ width, color })；只给源端声明了它的字段设置，未声明的字段不带入。
