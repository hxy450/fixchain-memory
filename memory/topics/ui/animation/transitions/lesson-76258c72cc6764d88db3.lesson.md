# View 体系的 fade/startAnimation 显隐与自写页面转场按源时长与顺序实现，不折叠成即时显隐或默认路由

ID：`lesson-76258c72cc6764d88db3` · 版本：3 · 阶段：spec/execute · 主题：[ui/animation/transitions](index.md)

概要：View 显隐动画与页面转场按源时长顺序实现

信号：`startAnimation`, `ViewPropertyAnimator`, `setCustomAnimations`, `res/anim`, `config_mediumAnimTime`, `animateTo`, `customTransition`, `customNavContentTransition`, `pushPathByName`, `onFinish`, `VISIBLE`, `GONE`

## 何时使用

实现与接线阶段，翻译源码中伴随动画调用的“置 VISIBLE/GONE”或“进入详情、replace fragment”时；规格提取阶段为导航与显隐验收条目登记转场契约时

## 适用情境

源端在显隐处调用 fade(view, show)、startAnimation、ViewPropertyAnimator，或进入详情前调用自写转场助手（列表项缩放、覆盖层淡出）、setCustomAnimations；动画参数在 res/anim、config_*AnimTime 或代码常量中；目标用条件渲染驱动显隐、用 pushPathByName 跳转。

## 例外与边界

- 源端为 Compose 动画 API 时按 Compose 显隐与尺寸动画的对应做法处理
- 决策台账以决策 ID 批准省略该动画

## 原因

条件渲染与路由 push 只表达终态：动画时长、插值和“动画结束后才切可见性”的顺序都会丢失，列表进详情走目标默认滑入。把动画注释成“状态驱动可见性即等价”后，后续核对也不再追查。

## 做法

1. 逐个动画调用列出资源与参数：res/anim 文件、时长（含 @android:integer/config_mediumAnimTime 等引用的取值）、插值器、起止状态与覆盖关系。
2. 显隐：保留节点，用 animateTo 改 opacity 或挂 transition，按源时长与曲线过渡；淡出在动画 onFinish 后再切可见性或移除节点，淡入先置可见再开始动画。
3. 页面转场：源端进入或离开页面时执行缩放、淡出等转场的，用 NavDestination.customTransition（API 15 起，HarmonyOS 文档 ts-basic-components-navdestination，访问于 2026-10-17）或 Navigation 的 customNavContentTransition（低于 API 15 只能用它）按源参数实现进入与退出两侧，不留目标默认横滑。
4. 规格阶段：导航与显隐验收条目写出转场契约（资源、时长、插值器、起止状态、谁覆盖谁）；页面规格只写“动画对齐”时，在功能验收条目中具体化。
