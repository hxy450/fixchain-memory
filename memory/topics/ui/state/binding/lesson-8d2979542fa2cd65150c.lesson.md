# 随状态变化的控件参数不作 @Builder 值参，改为内联读取状态或用 @ComponentV2 子组件的 @Param

ID：`lesson-8d2979542fa2cd65150c` · 版本：9 · 阶段：execute/repair · 主题：[ui/state/binding](index.md)

概要：状态派生值不传 @Builder，改 @Param 子组件

信号：`@Builder`, `@Param`, `@ComponentV2`, `Repeat`, `RepeatItem`, `LazyForEach`, `@Local`, `@ObservedV2`, `onAreaChange`, `UIUtils.makeBinding`

## 何时使用

界面实现阶段（页面转换与公共组件抽取），以及返修或按源端几何重写已有页面时，为源端带状态参数的子控件、多个同构开关行或数据文字选择 ArkUI 复用写法时；把 LazyForEach 改写为 Repeat、拆出条目 @Builder 时

## 适用情境

源端 Compose 子 Composable 以当前状态算出的值作参数（如 enabled = count > 1、颜色随选中态变化），或 Android 页面有多个同构的开关行、各自持有状态；目标 ArkUI 组件需要在状态变化后刷新 enabled、颜色、开关图标等属性，准备把子控件或开关行抽成共享的 @Builder 方法。也包括用多参数 @Builder 渲染会被异步重新赋值的数组或对象（搜索结果、定位城市卡）的情形。也包括把 LazyForEach 改为 Repeat 时，each 回调写成 this.Row(ri.item)，把 RepeatItem.item 按值传给 @Builder。也包括页面转换为子页面嵌入点写只含前向引用的空 @Builder 槽位，并把异步加载的分类数组与选中索引作为位置值参传入。也包括返修时为对齐源端几何重写已能刷新的内联文字（设置摘要、统计数值、按 onAreaChange 尺寸计算的布局），把 this.<状态> 或尺寸作为值参传入新抽出的 @Builder。

## 例外与边界

- 传入 @Builder 的只有文案、尺寸等在该组件生命周期内不随状态变化的值

## 原因

Compose 每次重组都按当前状态重算实参；ArkUI @Builder 按值传入的参数是调用时刻的快照，状态变化后不会刷新 @Builder 内的 UI。来源一：边界步进按钮在状态越过边界后仍保持禁用、点击无效。来源二：蓝牙页两个独立偏好开关共用一个成员 @Builder，各自的 @Local 状态作值参传入、内部据此画开关并接无参回调；后来把复用开关组件放进同一 Builder，isOn 仍取值参，运行时出现点一个开关影响另一个，拆成两个直接绑定各自状态的组件行后才消除。两例中该规则都写在组件构建 skill 的 @Builder 复用一节，但写者要么前置清单里没有该 skill，要么只按固定行数或在截断的批量读取里读到了它的前段。另一应用中两处：添加城市页把搜索结果数组作为 @Builder 值参传入，查询在切到搜索分支后才返回并重新赋值，数据层日志有结果、界面始终为空；城市页把定位卡对象按值传入 @Builder，改为 @ObservedV2 后整体替换仍不刷新，原位更新字段才显示。两处写者都被要求读迁移陷阱表中的对应条目，一个只数了行数，一个读取被截断。另一应用在结构收口中已读到清单“拆出的 @Builder 必须接整个 RepeatItem”，仍按值传 ri.item 并加 virtualScroll；复用节点只更新 RepeatItem.item，按值拿到的旧对象不重绘，非空日期切到另一非空日期时仍显示旧条目。

## 做法

1. 状态派生的 enabled、selected、颜色、开关值、显示文字与尺寸等参数，用内联属性链直接读 this 上的状态，或抽成 @ComponentV2 子组件用 @Param 接收，或用按内容作键的 ForEach 渲染；要保留共享 @Builder（如统一的定位、尺寸与命中修饰链）时，把随状态变化的图标资源、文案改成取值回调 () => T，在 Image()、accessibilityText() 处调用（API 20 起也可传 UIUtils.makeBinding(() => this.x) 得到的 Binding<T>，本机 API 24 SDK @ohos.arkui.StateManagement.d.ts）；@Builder 值参只放不随状态变化的值。
2. 多个开关行共用外观时，每行在 build 中直接写复用组件并绑定自己的状态（如 isOn: this.<该开关状态>），不经共享 @Builder 转发状态值。
3. 写完 grep `@Builder` 签名与调用处，实参含 `this.<状态>` 表达式的即为风险点，改写后再落盘；返修重写已有片段时同样执行，不因原片段能刷新就省略。
4. 异步结果写回 @Local 前，grep 它在 build 中的全部消费点，确认没有经 @Builder 值参快照；“先切分支、后 await 赋值”的流程尤其要查。
5. 按值渲染的 @ObservedV2 实例要原位更新 @Trace 字段，不整体 new 替换，也不靠自赋值触发刷新。
6. Repeat 的 each/template 回调里拆出的 @Builder 或子组件接收完整 RepeatItem，在内部读取 ri.item；出现 this.Xxx(repeatItem.item) 写法先改正再提交，静态审计也加这一条 grep。
7. 即使槽体只是前向引用占位，也按这条规则定签名：空槽的参数表会成为后续填充者沿用的接口契约；后续填充槽体时先确认槽内数据在异步更新后能否刷新，不默认沿用占位签名。

## 可选检查

- 改动涉及按状态显示的文字或尺寸时，验收至少包含一次改变数据或尺寸的操作（切换选项、重置、旋转），确认显示随之更新。
