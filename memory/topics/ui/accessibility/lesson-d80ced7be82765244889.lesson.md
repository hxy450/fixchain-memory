# 图标无障碍文本按源 contentDescription 转写：null 或空串不臆造；源端有文本时用 $r 资源并沿用各语言值，不写死单一语言字面量

ID：`lesson-d80ced7be82765244889` · 版本：2 · 阶段：execute · 主题：[ui/accessibility](index.md)

概要：无障碍文本按源描述用 $r，空不臆造

信号：`contentDescription`, `accessibilityText`, `stringResource`, `IconButton`, `$r('app.string.`

## 何时使用

界面实现阶段，为图标、图标按钮、FAB 等设置 ArkUI accessibilityText、转写源端 contentDescription 时

## 适用情境

源端 Icon/Image/IconButton 的 contentDescription 为 null、空串或 stringResource(R.string.x)；目标工程带多语言字符串资源；同工程里既有用 $r 的页面，也有写死某一语言无障碍文本的页面可参照。

## 原因

contentDescription 为 null 或空串时，源端不为该图标提供朗读文本；按图标含义自拟“返回”“编辑”之类文本是在补写源端没有的语义，写成某一语言的字面量后，多语言资源无法覆盖，任何系统语言下都读这一种语言。

## 做法

1. 源端为 null 或空串时不设 accessibilityText，也不按图标含义自拟。
2. 源端给出字符串资源时写 .accessibilityText($r('app.string.<对应键>'))，键与各语言值随源 values-* 迁移；项目决策要求新增源端没有的无障碍文本时，按已批准的文案来源建资源键并在报告注明差异，不写字面量。

## 可选检查

- 对写死文本存疑时，检索 accessibilityText 的字面量实参（不以 $r 开头）定位候选。
