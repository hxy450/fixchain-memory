# 把预烘焙位图改为每帧矢量绘制前，保留位图隐含的取值时机与缩放语义：烘焙时读取的状态留快照，setBounds 拉伸的全部属性按比例缩放

ID：`lesson-046c8bbb304684669060` · 版本：2 · 阶段：execute · 主题：[ui/graphics/drawing](index.md)

概要：烘焙位图改每帧绘制时状态留快照、按比例缩放

信号：`onSizeChanged`, `Bitmap`, `onDraw`, `setBounds`, `roundRect`, `fillText`, `drawImage`, `Math.trunc`

## 何时使用

渲染实现阶段，用每帧矢量绘制替代源端预渲染的背景位图或 tile 位图缓存，并准备声称“行为等价”时

## 适用情境

源端在 onSizeChanged 等时机把受状态字段控制的元素（如首启说明）和圆角底、数字等烘焙进 Bitmap，onDraw 只贴图，或在出生、合并动画中用 setBounds((int)…) 整体拉伸、按 int 位移绘制；这些状态在位图生成后仍会被其他流程改写；目标改为 Canvas 每帧 roundRect、fillText 等矢量绘制。

## 原因

位图把生成时刻的状态和整体缩放一起固化：生成后再改字段不影响显示，拉伸时圆角、字号、基线修正、描边同比缩放，边界经 (int) 截断。改为每帧读实时字段、只缩放文字、保留浮点坐标后，元素集合、顺序与颜色都对，元素出现与消失的时机、动画中的形状却变了。

## 做法

1. 逐一列出缓存构建函数读到的可变状态、缓存的重建时机，以及位图生成后还有哪些写者改这些状态；在目标对应的尺寸或布局入口给它们留快照，绘制时读快照。快照依赖首次初始化写入（如异步就绪后才开局）时，布局入口加“引擎已就绪”门控，未就绪下一帧重试。
2. 源端用 setBounds 或矩阵拉伸位图时，按 s = 绘制宽 / 烘焙尺寸 统一缩放烘焙内容的全部属性（圆角半径、字号、基线修正、描边），dp 圆角先换成当前画布单位再乘 s；边界与位移按源式的 (int) 向零截断，用 Math.trunc。
3. 决策已批准离屏位图加 drawImage 时优先沿用该路线，它天然保留这些语义；改走每帧绘制时，把取值时机与缩放的处理写进交回的决策缺口。

## 可选检查

- 需要确认时，按源端流程切换状态（如首启 → 新开局 → 重建视图）对照元素出现与消失；出生（比例 0→1）与合并（比例 >1）各取一帧，核对边界为整数、圆角等于基准圆角乘比例。
