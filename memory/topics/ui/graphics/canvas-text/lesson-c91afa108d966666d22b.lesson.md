# 源端绘制辅助从 Paint 读回字号、对齐等状态时，目标在组件内自记当前值，不从 ctx.font、ctx.textAlign 读回

ID：`lesson-c91afa108d966666d22b` · 版本：1 · 阶段：spec/execute · 主题：[ui/graphics/canvas-text](index.md)

概要：Paint 状态读回改为自记，不读 ctx 属性

信号：`Paint.getTextSize`, `getTextSize`, `getTextAlign`, `ctx.font`, `ctx.textAlign`, `CanvasRenderingContext2D`, `setTextAlign`, `measureText`, `actualBoundingBoxAscent`

## 何时使用

渲染实现阶段，把 Android Paint 的有状态读写（setTextSize、setTextAlign 之后在绘制辅助里 getTextSize、getTextAlign 读回）翻译到 ArkUI CanvasRenderingContext2D 时；规格提取阶段写 Paint→Canvas 映射行时

## 适用情境

源端绘制辅助（如带底衬的文字绘制）不接收字号与对齐参数，而是从传入的 Paint 读回 getTextSize()、getTextAlign() 等值再计算底衬尺寸与位置；目标把 Paint 属性映射到 ctx.font、ctx.textAlign 等上下文属性，准备照样从上下文读回或解析字体串。

## 原因

Paint 是可读写的状态对象；CanvasRenderingContext2D 的 font、textAlign 在 canvas.d.ts 中只声明为属性与默认值，没有说明读回语义，在 HarmonyOS 6.1.0.126 模拟器上读回为 undefined，解析字号时抛 TypeError。这类错误只在运行时出现，只编译不启动时发现不了；规格只写“Paint 属性映射 Canvas 等价属性”也不会提示它。

## 做法

1. 在组件内封装 setFont、setTextAlign 等设置函数：写上下文属性的同时记下当前字号（字体串用的物理 px 与布局用的 vp 各一份）、对齐与粗细；绘制逻辑只读这份记录，不从 ctx.font、ctx.textAlign 等属性读回或解析。
2. 源端从 Paint 读回再算的文字高度、包围盒，改用 measureText 返回的 TextMetrics 计算，字段按源度量层级选取（见 lesson-f876887b216b6caf9f39）。
3. 规格写 Paint→Canvas 映射行时注明：上下文属性不能当状态读回，由组件自记。

## 可选检查

- 生成 Canvas 组件后至少在设备或模拟器上启动一次，确认绘制路径没有因读回属性抛 TypeError。
