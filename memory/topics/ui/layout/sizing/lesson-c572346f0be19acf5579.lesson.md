# 把原由 Tabs、Grid 等容器分配槽位的子项搬进自绘 Row/Column 时重新确定主轴尺寸：等分用 layoutWeight(1)，不保留依赖旧容器的 width('100%')

ID：`lesson-c572346f0be19acf5579` · 版本：2 · 阶段：execute · 主题：[ui/layout/sizing](index.md)

概要：槽位子项搬进 Row 改等分权重，不留 100%

信号：`layoutWeight(1)`, `width('100%')`, `BarMode.Fixed`, `LayoutParams`, `Tabs`, `tabBar`

## 何时使用

公共组件或页面实现阶段，把 Tabs 内置 tabBar、Grid 等由容器分配槽位的子项改写为自绘 Row/Column + ForEach（如自绘底部导航），确定每个子项的主轴尺寸时

## 适用情境

源端底栏是水平 LinearLayout，子项由代码以 LayoutParams(0, MATCH_PARENT) 与 weight=1 动态添加，布局 XML 里没有静态子项；目标原先用 Tabs BarMode.Fixed 承载页签、页签 builder 写 width('100%')/height('100%')，新组件把该 builder 原样搬进 Row。

## 原因

在 Tabs、Grid 的槽位里，子项的 '100%' 按容器分给它的槽位解析；搬进 Row 后每个子项都取父容器全宽，N 项合计 N×100%，后面的项被挤出屏幕。只读容器 XML 看不到子项如何分宽，代码里的 LayoutParams 与 weight 才是依据。来源中写者没有打开规格指向的 Activity 代码，照搬旧页签 builder，三栏底部导航的第三项落在屏幕外；后续接线与内联改动都声明不改视觉参数，偏差保留到真机验证。

## 做法

1. 换容器时重新确定子项主轴尺寸：源端等分（0dp + weight=1）写 layoutWeight(1)；需要固定宽或按内容宽时按源端 LayoutParams 写，不保留旧容器里的 '100%'。
2. 组件来源写成“XML + 代码”时，同时读代码中动态添加子项的 LayoutParams 与 weight。

## 可选检查

- 写完做算术核对：Row 内 N 个子项的主轴宽度之和不超过父宽
