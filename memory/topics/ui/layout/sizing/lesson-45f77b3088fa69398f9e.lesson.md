# Compose Row 中无 weight 的 fillMaxWidth 子项先占满剩余宽：不换成 layoutWeight(1)，后续兄弟按实得宽度判断是否绘制

ID：`lesson-45f77b3088fa69398f9e` · 版本：4 · 阶段：spec/execute · 主题：[ui/layout/sizing](index.md)

概要：fillMaxWidth 先占满剩余宽，后续兄弟按实得宽判断

信号：`fillMaxWidth`, `requiredWidth`, `Visibility.Hidden`, `layoutWeight(1)`, `width(0)`, `wrapContent`

## 何时使用

规格提取或页面转换阶段，解释 Compose Row 的可见元素和横向空间分配时

## 适用情境

有限宽度的 Row 中，无 weight 子项使用 fillMaxWidth()，后面还有兄弟（按钮、文字）；规格或派工可能用“近乎不可见、按源码保留”描述该兄弟，实现者准备把该子项换成 layoutWeight(1)。

## 例外与边界

- fillMaxWidth 带比例、主轴约束无上限或子项使用 weight 时，按当前分配规则处理，不套“占满剩余宽度”。
- 后续子项含 requiredWidth/requiredSize、无界 wrapContent 或自定义测量/绘制时，零宽约束仍不足以判断实际是否绘制。

## 原因

Compose Row 按声明顺序测量无 weight 的子项，默认 fillMaxWidth 会消耗测量时剩余的全部宽度，后续兄弟以 0 宽约束测量；ArkUI layoutWeight 先扣除兄弟再分配，改写后兄弟反而显示出来。来源把被挤掉的内容误记成浅色不可见，转换后照常绘制。“分到零宽”与“不绘制”仍是两回事：requiredSize 等可越过传入约束。

## 做法

1. 在当前 Row 的输入中区分 fillMaxWidth 与 weight：前者按测量顺序取剩余宽度，后者参与权重分配；目标布局保留源分配结果，不为了让所有声明节点可见就换成 layoutWeight(1)。
2. 后续子项分到零宽时，结合它自身的尺寸、溢出与裁剪规则判断输出；条件已明确不会绘制，才在规格中标为不可见，目标端写 width(0) + clip 保留零宽结果，只有源端确实保留非零槽位而不绘制内容时才用 Visibility.Hidden，并在注释写明度量推演；条件不明时保留待定，勿直接删除。
3. 规格描述的可见结果与源端度量不同而又要保留时，在规格或报告中写明为有意偏离。

## 可选检查

- 仅当后续子项的溢出或裁剪无法从当前输入确定时，复用该局部已有布局或截图证据。
