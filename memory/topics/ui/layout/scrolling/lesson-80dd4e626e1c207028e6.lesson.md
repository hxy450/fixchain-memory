# ScrollView 未写 overScrollMode 也按 Android 默认 IF_CONTENT_SCROLLS 映射：Scroll 写 edgeEffect(EdgeEffect.Spring, { alwaysEnabled: false })；GridView/ListView 同此，滚动条按源端默认显式设置

ID：`lesson-80dd4e626e1c207028e6` · 版本：3 · 阶段：execute · 主题：[ui/layout/scrolling](index.md)

概要：未写 overScrollMode 时只在可滚时回弹

信号：`overScrollMode`, `IF_CONTENT_SCROLLS`, `EdgeEffect.Spring`, `alwaysEnabled`, `edgeEffect`, `EdgeEffect.None`, `BarState.On`, `BarState.Auto`, `scrollBarWidth`, `scrollBarColor`, `GridView`, `NestedScrollView`

## 何时使用

界面转换阶段，把 ScrollView/NestedScrollView（含对话框内的滚动区）转换为 ArkUI Scroll 并设置边缘效果时；把会滚动的 GridView/ListView 转成 Grid/List 并决定滚动条与越界效果时

## 适用情境

源 ScrollView 没有声明 overScrollMode（Android 默认 IF_CONTENT_SCROLLS：内容可滚时越界回弹）；映射参考只列显式 overScrollMode，且把 ifContentScrolls 与 always 都映射为不带选项的 EdgeEffect.Spring；目标 Scroll 默认没有边缘效果。 也包括 GridView/ListView 没有改写 scrollbars、overScrollMode（AbsListView 同样默认 IF_CONTENT_SCROLLS），目标 Grid/List 没有显式设置 scrollBar 与 edgeEffect。

## 原因

不写 edgeEffect 时 Scroll 没有回弹；写成不带选项的 Spring，内容不满一屏也会回弹。两者都与源端不同；映射参考没有“未声明即 IF_CONTENT_SCROLLS”的规则时，各页会分别落到这两种写法。来源中同一应用的九个滚动页里，六个没设 edgeEffect、三个写了无条件 Spring。 源端视图在窗口变为可见时先显示滚动条约 1200ms 再淡出（View.initialAwakenScrollBars 以 scrollBarDefaultDelayBeforeFade×4 唤醒，默认延迟 300ms；本机 android-36.1 源码 View.java、ViewConfiguration.java），之后滚动时再出现；ArkUI Grid 默认 BarState.Auto，进页不显示（本机 HarmonyOS 6.1.0 SDK component/grid.d.ts，早期版本默认 BarState.Off），宽度与颜色也取目标默认。

## 做法

1. 源未写 overScrollMode 或写 ifContentScrolls：.edgeEffect(EdgeEffect.Spring, { alwaysEnabled: false })；always：alwaysEnabled: true；never：EdgeEffect.None。对话框内的 Scroll 同样处理。 GridView/ListView 转 Grid/List 时同样设置（Grid 默认 EdgeEffect.None）。
2. 内容可滚动时显式设置滚动条：进页用 BarState.On 显示约 1200ms（源端唤醒时长，见原因）后切回 BarState.Auto，滚动时由 Auto 显示；scrollBarWidth 与 scrollBarColor 按源主题的 scrollbarSize 与 scrollbarThumbVertical 资源取值（如 Holo 在 SDK values/themes_holo.xml），不沿用目标默认。是否会滚动按参照机行高×行数判断。
