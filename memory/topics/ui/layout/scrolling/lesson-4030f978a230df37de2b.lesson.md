# LazyRow/LazyColumn 的 contentPadding 译为 contentStartOffset/contentEndOffset，不用 List.padding

ID：`lesson-4030f978a230df37de2b` · 版本：2 · 阶段：spec/execute · 主题：[ui/layout/scrolling](index.md)

概要：Lazy 首尾留白用 contentStartOffset

信号：`contentStartOffset`, `contentEndOffset`, `contentPadding`, `PaddingValues`, `LazyRow`, `LazyColumn`, `Modifier.padding`

## 何时使用

界面实现阶段为滚动列表确定首尾留白时；规格提取阶段描述 Lazy 列表留白时

## 适用情境

源 LazyRow/LazyColumn 用 contentPadding（PaddingValues start/end）给首尾项留白；目标 ArkUI List 可写 .padding，也可写 contentStartOffset/contentEndOffset；映射参考只有通用的 padding → .padding()。

## 原因

contentPadding 只偏移内容、视口不变，项可以滚进留白区；List.padding 缩小视口，项滚到内距处被裁切。两者静止时一样，差异只在滚动时出现，容易被当作“差异小”而降级。

## 做法

1. contentPadding 的首尾值写成 .contentStartOffset/.contentEndOffset；只有源码是 Modifier.padding 时才写 List.padding。
2. 规格里写“内容内距（滚动时不裁切）”，不只写“左右 padding”。

## 可选检查

- 有疑问时检索列表上的 padding，逐处对照源码是 contentPadding 还是 Modifier.padding。
