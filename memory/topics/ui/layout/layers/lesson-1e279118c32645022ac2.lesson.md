# 同一源控件既有只构造不绘制的底层实例、又有经绘制方法刷新的活动实例时，共享组件要能表达构造态：按层分别写可见状态，不把绘制方法里的隐藏分支无条件化

ID：`lesson-1e279118c32645022ac2` · 版本：2 · 阶段：spec/execute · 主题：[ui/layout/layers](index.md)

概要：只构造未绘制的底层按构造态显示，不套隐藏分支

信号：`addView`, `setVisibility`, `INVISIBLE`, `VISIBLE`, `drawItem`

## 何时使用

规格提取与共享组件实现阶段，为棋盘、网格等分层控件定义组件状态参数，以及页面给各层传参时

## 适用情境

源端自定义 View 构造时就设好背景与底色、保持 VISIBLE；页面为背景层逐格 new 实例并 addView，但只对活动层调用 drawItem 一类方法，该方法才在空值时 setVisibility(INVISIBLE)（背景层的 setVisibility 可能被注释掉）；目标把两层交给同一共享组件、按数值决定可见性。

## 原因

把绘制方法的可见性写成组件唯一的分支，就没有参数能表达“构造后未绘制”的可见空格；页面给底层传空值时整层被隐藏，源端的空格底板消失。

## 做法

1. 规格按层写可见状态：只构造的底层写“保持构造态（可见 + 构造时的背景与底色 + 空文本）”，不只写绘制方法的映射；信号是 addView 之后没有调用绘制方法或 setVisibility。
2. 共享组件给出表示构造态/未绘制的参数（如 drawn，默认 true），只在已绘制且为空值时隐藏；页面接线前把要传的值代入组件的可见性与取色分支核对结果，共享文件不能改时改用不走隐藏分支的渲染或上报组件缺口。
