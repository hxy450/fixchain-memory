# 按源端截图复刻控件尺寸时，先判断实测值是内容测量结果还是框架 min/max 约束：落在最小值上就写 constraintSize（并补框架上限），不写 width(实测值)；含多语言文案的控件用最长译文核对

ID：`lesson-42364ad323112c3342ae` · 版本：2 · 阶段：execute/repair · 主题：[ui/layout/intrinsic](index.md)

概要：实测宽落在框架最小值时写 constraintSize

信号：`constraintSize`, `minWidth`, `maxWidth`, `AppCompat`, `strings.xml`, `width(`

## 何时使用

界面实现或返修阶段，按安卓实测几何复刻框架控件（弹出菜单、对话框、按钮）的宽高时

## 适用情境

实测宽度大于“文字宽 + 内边距”，源控件来自框架（如 AppCompat 弹出菜单项 minWidth 196dp、上限 max(屏宽/2, 320dp)）；控件文字是有多种译文的字符串资源，而对比截图只取了英文。

## 原因

把最小宽写成固定 width，较长译文就会折行；英文截图对上不能证明约束正确。

## 做法

1. 实测值与“内容宽 + 内边距”比较：更大说明落在框架约束上，写 constraintSize({ minWidth, maxWidth }) 并按框架规则补上限，单行与省略按源端；注释写的是 minWidth/maxWidth 时，代码里同一元素不应出现 width(N)。
2. 复刻前列出该字符串在全部 values-*/strings.xml 的译文，用最长译文做两端对比截图。
