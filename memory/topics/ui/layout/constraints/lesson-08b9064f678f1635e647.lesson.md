# 源端默认起始对齐和贴顶要显式写出：Android 与 Compose 的纵向容器默认贴起始边、Compose Row 默认贴顶，ArkUI Column/Row 交叉轴默认居中，Scroll 内不满一屏的内容默认居中

ID：`lesson-08b9064f678f1635e647` · 版本：10 · 阶段：execute · 主题：[ui/layout/constraints](index.md)

概要：纵向容器默认起始对齐与贴顶在目标显式写出

信号：`alignItems(HorizontalAlign.Start)`, `alignItems(VerticalAlign.Top)`, `Alignment.Top`, `constraintSize`, `horizontalAlignment`, `verticalAlignment`, `NestedScrollView`

## 何时使用

界面实现阶段，把纵向 LinearLayout、带 constraintStart/Top 的 ConstraintLayout 或 ScrollView/NestedScrollView 转成 ArkUI Column 与 Scroll 时；以及把 Compose Column 中的文本块转成 ArkUI Column 子项时；把未写 verticalAlignment 的 Compose Row 转成 ArkUI Row 时；把 Compose LazyColumn 等从顶部排列的纵向列表落成 Scroll 包裹 Column 时

## 适用情境

源纵向 LinearLayout 没写 gravity（子项默认贴起始边），或 wrap_content 子项以 constraintStart_toStartOf=parent 靠起始边、卡片以 constraintTop_toTopOf=parent 贴顶；目标 Column 宽度撑满，子项为固定或内容宽度；滚动页内容常不满一屏。或显示卡片用 layoutWeight 分高，源端卡内内容 wrap_content 自上而下排列并带上内边距。也包括 Compose Column 未声明 horizontalAlignment（默认 Start），文本只带水平 padding 而无 fillMaxWidth，仅个别项以 fillMaxWidth + TextAlign.Center 居中。也包括 Compose Row 未写 verticalAlignment（默认 Top），子项高度不等。 也包括源端 LazyColumn(fillMaxSize)/RecyclerView 的条目从顶部排列，目标写成 Scroll { Column { ForEach } }.layoutWeight(1)，条目可能不足一屏。

## 原因

ArkUI Column 的交叉轴默认是 Center，把源端“没写 gravity”照搬成“不写 alignItems”，返回键、标题、列表行就会被居中；父 Stack 的 alignContent 只放置 Column 本身，不影响其子项。Scroll 对不满一屏的内容也会纵向居中，而 NestedScrollView 是顶锚。来源中写者在源端本来居中的空态上显式写了 Center，却在源端默认对齐处什么都没写。另一应用计算器显示区源端自上而下排列（上内边距 18dp），生成者写成 justifyContent(FlexAlign.End)，数值落到显示卡片底部。另一应用中，添加城市页的内容 Column 未写 alignItems(Start)，分组标题被居中，而写者写前已读到陷阱表中对齐需显式设置的条目。另一应用的 Compose 页面中，转换者读到标题、价格、正文都只带水平 padding，写进未设 alignItems 的 Column 后整体居中；给内容宽的 Text 加 textAlign(Start) 也无效，因为 textAlign 只作用于 Text 自身框内。Compose Row 的默认纵向对齐同样是 Top，ArkUI Row 默认 Center。 另一应用的购物车把 LazyColumn 写成 Scroll 包裹未定高的 Column，商品少时整块居中；后来按源端重排卡片也没动外层对齐，最终靠 Scroll.align(Alignment.TopStart) 修正，给未定高的 Column 加 justifyContent 不起作用。

## 做法

1. 源端默认起始对齐时（Android 纵向 LinearLayout 未写 gravity、Compose Column 未写 horizontalAlignment），对应 Column 显式写 alignItems(HorizontalAlign.Start)，或给子项 alignSelf，或给文本 width('100%') + textAlign(TextAlign.Start)；只有源端写了 center/center_horizontal，或 fillMaxWidth + TextAlign.Center 的项才居中。内容宽的 Text 只加 textAlign 不会改变它在父容器中的位置。
2. 每写完一个撑满宽的 Column，逐个核对固定尺寸或内容宽子项的水平位置由谁决定。
3. ScrollView/NestedScrollView 或纵向 Lazy 列表转成 Scroll 时，源内容贴顶就给 Scroll 写 .align(Alignment.Top)（或 TopStart），或给子容器加 constraintSize({ minHeight: '100%' }) 一类约束使其顶锚，并确认超出一屏后仍能滚动；源端是可变长度的条目列表时优先映射为 List，条目默认从顶部排列。给未定高的 Column 写 justifyContent 不改变它在 Scroll 中的位置；按源端重排列表卡片时一并核对外层滚动容器的对齐。
4. 容器被 layoutWeight 撑高而源端内容贴顶时，写 justifyContent(FlexAlign.Start) 并沿用源端上内边距，不改成底对齐。
5. Compose Row 未写 verticalAlignment 时，ArkUI Row 显式写 alignItems(VerticalAlign.Top)；写完逐个对照本页 Column()/Row() 的源码构造参数。
