# 源应用声明 supportsRtl=true 时保留逻辑方向：start/end 边距写 LengthMetrics 的 start/end，AutoMirrored 图标加 matchTextDirection(true)

ID：`lesson-786a04847bf10d364d9d` · 版本：4 · 阶段：spec/execute · 主题：[ui/layout/variants](index.md)

概要：声明 RTL 时保留 start/end 并镜像图标

信号：`android:supportsRtl`, `LengthMetrics`, `marginStart`, `paddingStart`, `Icons.AutoMirrored`, `autoMirrored`, `matchTextDirection`, `LocalizedAlignment`, `HorizontalAlign.End`, `Alignment.BottomEnd`, `Direction.Ltr`, `onLayout`

## 何时使用

规格提取与界面实现阶段，为声明 supportsRtl=true 的源应用转换 start/end 边距与自动镜像图标时

## 适用情境

源 Manifest 声明 android:supportsRtl="true"；Compose 用 padding(start/end)、Icons.AutoMirrored.*（或 autoMirrored=true 的矢量），View 用 marginStart/End、paddingStart/End；应用含 RTL 语言资源或可能在 RTL 系统语言下运行；转换者准备写 left/right，把返回箭头等方向性图标转成普通 Image；页面规格可能没有携带 RTL 契约，资源映射可能把自动镜像图标当普通媒体。

## 例外与边界

- 源 Manifest 未声明 supportsRtl：布局恒 LTR，按显式固定 LTR 的做法处理

## 原因

start/end 与 AutoMirrored 都是随布局方向翻转的逻辑语义；写成 left/right 或普通图片后，RTL 语言下间距落在错误一侧、返回箭头指向反方向。规格没把 RTL 列为全局契约时，各页转换者容易就近改成物理方向。

## 做法

1. 规格阶段读到 supportsRtl=true 时，把“布局随语言方向镜像”写成全局契约传给各页，并在资源映射中标出需要镜像的方向性图标。
2. start/end 边距写 .padding/.margin({ end: LengthMetrics.vp(n) })，同一对象各边都用 LengthMetrics；源端本就是物理 left/right 的才写 left/right。同一元素的对齐与边距用同一种方向语义：HorizontalAlign.End（按语言方向末端对齐）与 Stack 的 alignContent/align 中的 Alignment.BottomEnd 会随 RTL 镜像，配 margin end 而不是 right；Stack 以外组件的 .align 传 Alignment 不镜像，需随方向镜像时改传 LocalizedAlignment（API 20 起，只在文档列出的 Button、GridItem 等组件生效）（HarmonyOS 文档 ts-universal-attributes-location，访问于 2026-10-17；本机 SDK API 24 enums.d.ts）。
3. Icons.AutoMirrored.* 或 autoMirrored 矢量转成的 Image 加 .matchTextDirection(true)；图标经共享按钮组件渲染时，由组件提供镜像参数并在调用处传入。
4. 自写 onMeasure/onLayout 的自定义或三方容器（如浮动按钮菜单）内部摆放是否镜像，按其 onLayout 源码确定，不由外层 start/end 属性推断；源端内部不镜像的部分在目标固定 Direction.Ltr，外层仍按逻辑方向镜像。
