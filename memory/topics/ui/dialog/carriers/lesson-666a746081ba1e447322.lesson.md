# 锚定弹出的下拉（PopupWindow showAsDropDown 自定义下拉、框架 ActionBar 的溢出下拉面板）按源样式在锚点下方还原：不换成原生 Select、系统 Menu 或整页筛选视图

ID：`lesson-666a746081ba1e447322` · 版本：3 · 阶段：execute · 主题：[ui/dialog/carriers](index.md)

概要：锚定下拉与溢出菜单原位还原，不换 Select/Menu

信号：`showAsDropDown`, `PopupWindow`, `bindPopup`, `Select`, `Stack`, `Menu`, `showAsAction`, `ListPopupWindow`, `bindMenu`, `MenuItem`, `popup_menu_item_layout`

## 何时使用

界面实现阶段，为筛选栏、排序栏等下拉选项选择 ArkUI 弹出容器、呈现位置与菜单样式时；为工具栏溢出菜单（showAsAction=never 的项）选择承载方式与外观时

## 适用情境

源端点击筛选项后用 PopupWindow 加载自定义布局（固定宽度、固定行高、箭头图、勾选图标），以 showAsDropDown 锚定在触发器或置顶筛选栏下方原位展开；同页可能另有整屏的“更多筛选”面板；目标有现成的 Select 组件或已写好的整页筛选组件可用。 也包括源 Activity 用框架 ActionBar（Theme.Holo 等），showAsAction=never 的菜单项由平台主题绘制的 ListPopupWindow 下拉面板承载，源码里没有面板样式；目标准备用 ArkUI Menu/bindMenu，任务要求逐屏一致。

## 原因

原生 Select 套用系统菜单外观，丢掉源布局的宽度、行高、箭头与勾选样式；把锚定下拉做成整页替换视图，会改变位置与容器，背景列表和置顶筛选栏也不再可见。来源中两位写者都已读到 PopupWindow 的布局与锚点，仍分别改成 Select 与“更多筛选”同款的整页面板。ArkUI Menu 是系统定位的圆角卡片、无分隔线，与框架主题的下拉面板（贴 ActionBar 下沿、固定最小宽度、48dp 行与分隔线、外点只关闭）对不上；规格只写“Menu + MenuItem”通用映射时，实现只改底色与字色也不算对齐。

## 做法

1. 从布局 XML 取宽度、行高、背景、箭头与勾选资源，从代码取锚点与偏移，用 bindPopup（或锚点下方的 Stack 覆盖层）按这些值实现；当前项显示勾选或高亮，外点或再次点击收起。
2. 同一筛选栏有多个入口时按各自 show 方式区分：showAsDropDown 的快捷项做原位下拉（源端先置顶筛选栏并滚动列表的，同时保留置顶栏与背景列表），show(标题栏) 或整屏弹出的“更多筛选”才做独立面板。
3. 框架 ActionBar 的溢出面板写可见契约并取平台值（SDK platforms/android-<api>/data/res 的弹出菜单样式与 popup_menu_item_layout：Holo 最小宽 196dp、行高 48dp、文字字号与左右内边距、行间分隔线、面板底色与边线、锚定位置与右缘偏移，或源端截图实测）；要求一比一时用页内浮层：全屏遮罩只负责关闭并吞掉事件，面板贴锚点下沿，宿主 onBackPressed 先关闭浮层。
