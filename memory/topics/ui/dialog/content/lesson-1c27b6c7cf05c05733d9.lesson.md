# ComponentContent 构造即执行 builder：构造后才赋值的回调以延迟调用传入

ID：`lesson-1c27b6c7cf05c05733d9` · 版本：2 · 阶段：execute/repair · 主题：[ui/dialog/content](index.md)

概要：ComponentContent 后赋的回调以闭包传入

信号：`ComponentContent`, `wrapBuilder`, `openCustomDialog`, `@Param`

## 何时使用

界面实现阶段，用 ComponentContent 加 wrapBuilder 加 openCustomDialog 封装弹窗并接线关闭、确认回调时

## 适用情境

关闭回调需要构造后才得到的 content 句柄，只能在 new ComponentContent(...) 之后赋给 args；内容组件以 @Param 接收回调。

## 原因

builder 在构造时就执行，@Param 拿到的是当时的空默认值；之后再给普通 args 对象赋值不会传入已构建的内容，按钮失效。

## 做法

1. builder 中写 onX: (...): void => args.onX(...)，或把 args 整体传给内容组件、在点击时读取。

## 可选检查

- 复用同族弹窗或按钮无反应时，对每个 new ComponentContent(..., args) 向后查 args.xxx = 赋值，并看 builder 是否以 xxx: args.xxx 直接传入
