# 源端吞触摸的叠放条体与按钮显式设 Block：空 onClick 不阻断下层，祖先 Transparent 时用 BLOCK_HIERARCHY

ID：`lesson-df573635678a799a5f80` · 版本：3 · 阶段：execute/repair · 主题：[ui/interaction/hit-testing](index.md)

概要：吞触摸的叠放层显式 Block，空 onClick 不挡

信号：`HitTestMode.Block`, `HitTestMode.BLOCK_HIERARCHY`, `HitTestMode.Transparent`, `HitTestMode.None`, `hitTestBehavior`, `android:clickable`, `onTouch`, `.onClick(() => {})`

## 何时使用

界面实现阶段，为叠在列表或页面之上的撤销条、浮动按钮组、提示条决定触摸由谁消费、是否透传下层时；给自定义组件实例加 margin、padding、position 等通用属性时

## 适用情境

源端条体 clickable=true（含 style 中声明）或按钮自身消费触摸，下层列表根另有 onTouch/onClick（如触摸即提交待定操作）；目标宿主 Stack 或某个祖先为放行空白区设了 HitTestMode.Transparent。也包括源端只占位、不拦截的叠放层（提示条覆盖工具栏），目标在自定义组件实例上直接加通用属性。

## 例外与边界

- 源端该层本身不消费触摸（非 clickable、无监听），按“不处理点击的覆盖层显式 Transparent”的做法处理

## 原因

ArkUI 的 onClick 只注册手势，不改变命中测试；Transparent 祖先之下，上层节点命中后其下的兄弟仍参与命中，下层的 onTouch 与按钮同时触发（例：点撤销先触发下层的提交，撤销失效）。Block 只作用于本节点所在层级，祖先 Transparent 时挡不住祖先之外的下层。自定义组件实例上的通用属性会生成缺省命中（Default）的包装节点，按包装尺寸拦截下层。

## 做法

1. 逐节点按源端触摸归属写 hitTestBehavior，不依赖缺省值：要吞掉触摸的条体和按钮写 HitTestMode.Block；它位于 Transparent 宿主或祖先之下时写 HitTestMode.BLOCK_HIERARCHY（API 20 起提供，目标 SDK 低于 20 时没有该成员；HarmonyOS 文档 arkts-interaction-basic-principles，访问于 2026-10-17）；只做占位或定位的包装写 None。
2. “条体吞掉触摸、不下穿”不用空 .onClick(() => {}) 表达，命中模式才决定下层是否收到事件。
3. 给自定义组件实例加 margin/padding/position 等通用属性时，同一实例补 .hitTestBehavior(HitTestMode.None 或 Transparent)，或把这些属性挪到已设命中模式的外层容器；工程已有同类包装写法时照用。
4. 随状态出现的层（展开的子按钮行等）按展开、收起分别设命中模式。

## 可选检查

- 对每个叠放层点按目标节点，下层的 onTouch/onClick 不触发；点空白处下层仍可达。
