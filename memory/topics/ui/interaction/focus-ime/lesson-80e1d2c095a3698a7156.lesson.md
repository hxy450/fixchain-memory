# Activity 级 onKeyDown 映射到页面根节点（NavDestination 或 @Entry 根）的 onKeyEvent，并确认页内至少有一个可获焦组件让焦点链经过本页（源端缺省可获焦的 ImageButton/Button 对应件设 focusable(true)）；不把 onKeyEvent 挂在需先抢焦点的子组件上

ID：`lesson-80e1d2c095a3698a7156` · 版本：3 · 阶段：execute · 主题：[ui/interaction/focus-ime](index.md)

概要：Activity onKeyDown 挂页根，页内需可获焦

信号：`onKeyDown`, `dispatchKeyEvent`, `onKeyEvent`, `NavDestination`, `focusable(true)`, `KeyType.Down`, `ImageButton`, `defaultFocus`, `requestFocus`, `consumed: 0`

## 何时使用

页面实现与输入接线阶段，为源端 Activity 级硬件按键回调（onKeyDown、dispatchKeyEvent）选择 ArkUI onKeyEvent 的挂载节点时；接收“焦点获取归本任务”一类移交时

## 适用情境

安卓源在 Activity 上覆写 onKeyDown 或 dispatchKeyEvent 处理方向键、MENU、Ctrl+Z 等，不依赖某个 View 持有焦点；目标页面是 Navigation 下的 NavDestination 或 @Entry 页，交互由内部 Canvas、自绘子组件或 Image + onClick 承载。也包括页内没有 Button/TextInput 或 focusable(true) 组件，源端按键控件是缺省可获焦的 ImageButton/Button。

## 原因

ArkUI 按键沿焦点链派发：页内没有任何可获焦组件时，焦点链不经过本页，按键到达窗口后无人消费（hilog 显示 consumed: 0），挂在根节点也收不到；子组件的 onKeyEvent 也只有在焦点链上才会收到。来源中转换者误以为 NavDestination 不支持 onKeyEvent 而挂到 Canvas，返修中用 defaultFocus、onReady 时 requestFocus 给该子组件抢焦点都没生效，移到 NavDestination 后按键正常，获焦子节点的事件也会冒泡到这里。另一来源的页面把源端 ImageButton 都转成 Image + onClick，根节点上的 onKeyEvent 从未触发，给这些按钮设 focusable(true) 后方向键与 Ctrl+Z 才可用。“只写 focusable(true) 不会让它获焦”只针对把处理挂在子组件上靠抢焦点的做法，让叶子控件可获焦、把焦点带进本页恰恰是必要条件。

## 做法

1. 源端是 Activity 级按键回调时，把 .onKeyEvent 挂在页面根节点（NavDestination 或 @Entry 根组件）上；按源端只在按下时触发的语义加 KeyType.Down 过滤，源端吞掉的键（如 MENU）同样返回 true。同时核对页内有可获焦的叶子控件：源端 ImageButton/Button 缺省可获焦，目标对应的 Image/按钮设 focusable(true)（源端焦点态不可见时把焦点框设为透明样式），焦点进入本页后事件冒泡到根节点。
2. 确需挂在子组件上时同时写出获焦机制，并确认页面显示后的实际焦点节点就是该组件；“某容器不支持 onKeyEvent”一类判断先查 SDK 声明。收到“焦点获取归本任务”的移交时，改挂到根节点并落地可获焦组件才算完成。

## 可选检查

- 对挂载点有疑问时，在设备上注入方向键查看 hilog 中的当前焦点节点与 consumed 结果；consumed: 0 说明焦点链没经过本页。
