# 被 @Entry 页直接组合、未进入 Navigation 栈的子组件要拦截返回键时，由 @Entry.onBackPress 转调子组件登记的处理函数，多个登记方后进先出；@Entry 承载 Navigation 且栈内有 NavDestination 时，挂载点改为栈顶 NavDestination.onBackPressed

ID：`lesson-803ba029eea852122e77` · 版本：5 · 阶段：execute · 主题：[ui/navigation/back-stack](index.md)

概要：子组件拦截返回由 @Entry 转调，多方后进先出

信号：`PredictiveBackHandler`, `BackHandler`, `onBackPress`, `@Event`, `@ComponentV2`, `@Entry`, `aboutToDisappear`, `NavDestination.onBackPressed`, `OnBackPressedDispatcher`

## 何时使用

页面转换与接线阶段，为源端非根 Composable 里的 BackHandler/PredictiveBackHandler，或把 OnBackPressedDispatcher 的多级回调映射到 ArkUI 返回键钩子时

## 适用情境

源端在抽屉宿主等非 Activity 根的 Composable 中按状态条件拦截返回（例如抽屉打开时先关抽屉）；目标端该组件不是 @Entry，由唯一的 @Entry 页直接组合，没有作为页面驻留在 Navigation 路由栈内。也包括源端 OnBackPressedDispatcher 按后登记先问分发（Activity 只登记壳层回调，选择模式等另登记回调），目标壳页的返回处理是封闭分支、嵌入的子页没有登记入口。

## 例外与边界

- 组件本身就是 @Entry 页、且没有承载内有页面的 Navigation 时，直接实现 onBackPress
- 组件位于 NavDestination 内容中（含被页面组合的 BasePage 等共享基座）时，返回先交该 NavDestination.onBackPressed，返回 false 即出栈，@Entry.onBackPress 不会被调用；由该 NavDestination 的 onBackPressed 转调基座的裁决函数，不在 @Entry 上兑现

## 原因

SDK 的 onBackPress 注释写明只对 @Entry 装饰的自定义组件回调，子组件自己实现的 onBackPress 不会触发。来源工程的子组件把同一逻辑另挂到自身 NavDestination.onBackPressed，但该节点被 @Entry 页直接组合、不在 Navigation 栈内，设备实测（API 12 模拟器）也不回调，抽屉打开时按返回直接回到桌面。编译、结构审计与静态判定全部通过，只有设备上按返回键才暴露。

## 做法

1. 先确认子组件的挂载形态：被 @Entry 页直接组合且不在 Navigation 栈内，还是位于 NavDestination 内容中（含页面组合的共享基座）；后者按例外由 NavDestination.onBackPressed 转调。
2. 直接组合时，子组件在 aboutToAppear 经回调参数（@ComponentV2 用 @Event）把 () => boolean 的裁决函数交给 @Entry 页，aboutToDisappear 交回 null；@Entry 页的 onBackPress() 有函数就返回其结果，没有就返回 false 交系统默认处理。
3. 有多个登记方时，宿主提供后进先出回调栈（子页 aboutToAppear 登记、aboutToDisappear 注销），宿主返回处理在执行壳层分支前先分发；同一子页还嵌入其他宿主时，这些宿主也接同一分发。

## 可选检查

- 能上设备时：状态打开（如抽屉展开）按 Back，状态关闭且应用留在前台；关闭态按 Back 仍按源端行为退出。
