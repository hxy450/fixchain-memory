# 源端经 TaskStackBuilder.addNextIntentWithParentStack(...).startActivities() 跳转时，按 Manifest 父链清栈重建 [父…, 目标]：目标 NavPathStack 先 clear 再依次 push 父页与目标，返回落到父页而非来源页

ID：`lesson-2986423250986124d039` · 版本：2 · 阶段：spec/execute · 主题：[ui/navigation/back-stack](index.md)

概要：父栈跳转按 Manifest 父链 clear 后重建

信号：`TaskStackBuilder`, `addNextIntentWithParentStack`, `startActivities`, `parentActivityName`, `PARENT_ACTIVITY`, `NavPathStack`, `pushPathByName`

## 何时使用

规格提取与基座实现阶段，把基类的父栈跳转方法（抽屉导航等）翻译成 NavPathStack 操作与返回验收时

## 适用情境

源基类被多个页面继承，抽屉等跳转经 TaskStackBuilder 发起，Manifest 为目标声明 parentActivityName 或 PARENT_ACTIVITY；目标是单个 Navigation + NavPathStack，跳转可从栈底以外的任意宿主页发起；页面规格里可能有“pushPathByName（主页为根天然在栈底）”一类只在来源页是主页时成立的映射。

## 原因

startActivities 以新任务按父链重建栈，从任一页跳转后都是 [主页, 目标]；写成在当前栈上 push，从非根页跳转后返回会落回来源页，栈也越积越深。只在主页上验证时两者看不出差别。

## 做法

1. 规格按 Manifest 父链写出跳转后的完整栈与返回落点，实现映射写成 clear → 依次 pushPathByName 父页 → pushPathByName 目标（转场按源端设置），不写“带回栈、返回落回来源页”。
2. 把页面规格里的映射行复用到被多个宿主调用的基类方法前，核对该行成立的前提；验收用从非根页发起的样例（设置 → 抽屉 → 帮助 → 返回应到主页，再返回退后台）。
