# Refresh.onRefreshing 会在程序置 refreshing 时触发，发起刷新前先判断是否已在运行

ID：`lesson-fa79c5a6658c68b71a21` · 版本：2 · 阶段：execute · 主题：[ui/list/data-sources](index.md)

概要：onRefreshing 先判刷新已在运行再发起

信号：`Refresh`, `onRefreshing`, `SwipeRefreshLayout`, `setOnRefreshListener`, `setRefreshing`, `$$`

## 何时使用

界面转换时把 SwipeRefreshLayout 映射为 Refresh，以及接线时把运行态事件接到 refreshing 绑定状态时

## 适用情境

源 setOnRefreshListener 只响应用户下拉，另由运行态事件 setRefreshing 同步指示器；目标 Refresh({ refreshing: $$state }) 的状态会被事件或菜单刷新程序置为 true。

## 原因

两条通道合成一个状态后，程序置真也会回调 onRefreshing，重复发起刷新并触发节流提示。

## 做法

1. onRefreshing 内先判断全局刷新是否已在运行，已在运行时只让指示器跟随。
2. 在转换报告或注释写明 onRefreshing 的触发来源与守卫，供同批兄弟页复用；接入运行态事件前回读同组件的 onRefreshing。

## 可选检查

- 页面另有菜单刷新等非下拉入口时，从该入口触发一次，确认只发起一次刷新、没有节流提示
