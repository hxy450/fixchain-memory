# 迁移列表时连同条目点击回调与数据源的本地变换（shuffled、filter、sort）一起实现，不只迁渲染

ID：`lesson-46307bc26d725b4634ca` · 版本：2 · 阶段：execute · 主题：[ui/list/data-sources](index.md)

概要：迁移列表连同条目点击与本地 shuffled 变换一起实现

信号：`addOnItemTouchListener`, `Fisher-Yates`, `RecyclerView`, `Adapter`, `.onClick`, `ForEach`

## 何时使用

页面 UI 转换阶段，迁移 RecyclerView/Adapter 列表的条目点击与数据源初始化时

## 适用情境

源 Fragment 经 adapter 的点击回调或 addOnItemTouchListener 把条目内容回填到输入框等；列表数据来自 ViewModel 对本地静态种子做 shuffled() 等纯本地变换；目标的对应 ViewModel 尚未建立。

## 原因

只迁样式链的条目没有 onClick，注释写着“点击回填”、报告也列为已实现，代码却没有事件；把纯本地变换当作依赖未建 ViewModel 而登记前向占位，后续阶段常把它改挂到无人认领的延迟，功能一直缺失。

## 做法

1. 每迁一个列表，先枚举源端 adapter 点击监听与 RecyclerView 触摸监听中的行为，在 ForEach 条目上逐项接 .onClick；报告列为已实现前 grep 到对应事件代码。
2. 数据源只是对本地集合做 shuffled/filter/sort 时，在组件初始化处对副本复现（如 Fisher-Yates 洗牌），不登记前向占位；只有依赖网络、跨页状态等确实不可得的工件时才延后。
