# maxLines + Ellipsis 截断粒度两端不同：单行用户内容加 wordBreak(BREAK_ALL)，多行末行写明差异，确需字符级一致才测量截断

ID：`lesson-836a5414b52f0e062f1f` · 版本：4 · 阶段：spec/execute · 主题：[ui/text/typography](index.md)

概要：单行省略补 BREAK_ALL，多行末行写差异

信号：`maxLines`, `TextOverflow.Ellipsis`, `android:ellipsize`, `textOverflow`, `WordBreak.BREAK_ALL`, `BREAK_WORD`, `singleLine`, `TextUtils.ellipsize`, `measureTextSize`, `onSizeChange`, `Paragraph`

## 何时使用

规格提取阶段为带 maxLines(N) + TextOverflow.Ellipsis（或 android:ellipsize、singleLine）的单行标题或多行正文写转换决策，以及界面实现阶段落实单行省略位置与折叠态末行时

## 适用情境

源端多行正文以 maxLines + Ellipsis 折叠；目标用 .maxLines() + .textOverflow({ overflow: TextOverflow.Ellipsis })，默认 wordBreak 为 BREAK_WORD；映射参考只记 ellipsize → textOverflow 的 API 对应；项目可能要求完整复刻源端可观察行为。也包括工具栏标题、笔记标题、分类名等单行用户内容：源端 Toolbar 标题或 singleLine TextView 由 TextUtils.ellipsize 按字符省略，目标写成 maxLines(1) + Ellipsis 而未设 wordBreak。也包括源控件是自带截断算法的三方 TextView 子类（布局声明了库命名空间且无 android:ellipsize），省略规则由库决定。

## 例外与边界

- 项目允许平台差异、不要求逐字复刻末行时，直接使用内置行为，不引入运行期测量

## 原因

源端末行按字符填满后接“…”，ArkUI 默认按词换行，末行放不下整词就整词丢弃，再接带前导空格的省略号并留白；单行文本同样先按词断行，长词标题提前在词间省略。只记 API 对应的映射让规格写成“等价”，差异留到视觉核验才暴露。运行期测量能做到字符级截断，但并不排除更简单的 wordBreak/ellipsisMode 配置，也不证明所有工具链都必须这样做。

## 做法

1. 单行用户内容用 maxLines(1) + Ellipsis 时补 .wordBreak(WordBreak.BREAK_ALL)，对齐 Android 字符级省略（BREAK_ALL 与 Ellipsis、maxLines 组合可按字母截断加省略号；HarmonyOS 文档 ts-basic-components-text，访问于 2026-10-17）；源控件是三方 TextView 子类时先按库的截断算法（如取前 N 行、按空格回退、去尾标点再加“…”）实现，内置属性对不上就用同字体同宽的文本排版测量（@ohos.graphics.text Paragraph）自排。
2. 规格不写“等价”：写明两端末行形态的差异，完整复刻口径下登记为平台差异项，或直接给出实现方案；映射参考只给 API 对应时，把渲染语义缺口写进差异验收条目。
3. 实现时先试内置属性能否满足当前要求；确需字符级一致时，在 onSizeChange 得到宽度后，以与 Text 相同的字体、字号、行高和换行设置调用 measureTextSize，二分求“前缀 + …”满足目标行数的最长前缀；只改折叠态，展开态与首帧继续使用原文与内置省略兜底。
