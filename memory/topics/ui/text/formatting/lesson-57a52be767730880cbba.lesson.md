# 移植文本组件时先确认显示的是原始字符串还是加工后的富文本（Compose AnnotatedString、Html.fromHtml、带标记的字符串资源），样式、链接识别与点击要落到目标端；Html.fromHtml 只产出单个符号实体、按大字号逐个生成作页码点等图形时不算富文本，按源字体下的可见几何绘制图形

ID：`lesson-57a52be767730880cbba` · 版本：6 · 阶段：execute · 主题：[ui/text/formatting](index.md)

概要：富文本加工与链接一并迁，单符号实体画图形

信号：`AnnotatedString`, `buildAnnotatedStringWithUrls`, `LinkAnnotation`, `StyledString`, `UrlStyle`, `TextController.setStyledString`, `Html.fromHtml`, `LinkMovementMethod`, `CDATA`, `setMessage`

## 何时使用

界面实现阶段，把源端 Compose Text、TextView 或对话框正文译成 ArkUI Text 时

## 适用情境

源组件先调用工具函数（如按正则识别 URL、附加 LinkAnnotation 的 buildAnnotatedStringWithUrls）生成 AnnotatedString 再交给 Text；目标页面规格和验收条目只写了空值隐藏、折叠展开等布局行为。也包括 View 体系以 Html.fromHtml、setMessage(resId) 或 android:text 引用带 `<b>`/`<i>`/`<a>` 标记或 CDATA 的字符串资源，并用 LinkMovementMethod 让链接可点；目标准备用 Text($r(...)) 直接显示，或在正文外另起链接行。也包括循环中逐个 new TextView、setText(Html.fromHtml("&#8226;")) 并 setTextSize(35) 作翻页圆点：内容只有一个符号，可见尺寸、步进与垂直位置取决于源字体（Roboto）的字形度量。

## 原因

只渲染原始字符串，描述里的链接既不着色也点不开，编译和结构审计都发现不了。来源中转换者读了组件源码，看到了加工调用，却以“验收项没列”为由写成纯 Text，也没有读工具函数的定义。View 体系同理：Text 直接显示带标记的资源时，CDATA 文案露出标签原文，非 CDATA 文案已无标记，链接都点不开；正文外另起链接行会让同一链接出现两次。反过来，把只含一个符号实体的 fromHtml 也当文本移植时，目标字体中同一符号的步进与垂直度量不同（另一来源中 HarmonyOS Sans 的 “•” 步进约为 Roboto 的三倍），圆点间距与位置都偏。

## 做法

1. 先区分“文本内容”与“用字形画图形”：fromHtml 参数只有一个字符实体、无标签无链接、在循环里逐个生成且字号远大于正文时，按源字体下的步进、直径与垂直位置用 Circle 等图形绘制（数值从源字体度量或源端截图实测取），不写成 Text('•')；其余情况按以下各步处理富文本。
2. 看传给 Text 的变量从哪来；经过工具函数加工的，读该函数定义，把识别规则、链接样式和点击行为一起移植。
3. ArkUI 可用 StyledString 配 TextStyle、DecorationStyle 与 UrlStyle 表达链接，通过 TextController.setStyledString 设给 Text({ controller })。
4. 带标记的文案用公共富文本组件把 b/i/u/small/a/br 与实体解析成 Span，链接 Span 设 onClick（如以 ohos.want.action.viewData 打开）实现行内可点；不用 Text($r(...)) 直接显示，也不在正文外另起链接行。
