# 功能对齐与验收结论逐项以代码落点为准：按规格验收项与导航出口检索实际组件和调用，空回调与只含注释的回调不算实现

ID：`lesson-9147be4d87153de9c5b6` · 版本：9 · 阶段：execute/verify · 主题：[process/claimed-without-receipt](index.md)

概要：功能对齐以代码落点为准，空回调不算实现

信号：`onClick`, `JSON.stringify`, `NavPathStack`, `onEventMainThread`, `@Subscribe`, `module.json5`, `TODO:`

## 何时使用

验证阶段核对功能完成度，或实现、返修后向用户报告“已实现/已对齐”时；执行阶段宣告页面转换或流水线阶段完成时；协调者收到子任务“已接入真实接口”“已补齐”的回执时

## 适用情境

验证检查只 grep TODO: 与占位登记表；实现者或返修者按功能点列对齐表并逐项打 ✅；规格写有验收条目、页面导航出口与启动触发条件。 也包括执行者用同一模板循环批量写出只有“内容开发中”或标题的页面、用写死的样例数据顶替接口、把接口响应 JSON.stringify 后整段显示，再以文件齐全、页数相等和编译通过判定完成；子任务回执只写“已补齐”“均保留”，不列对照过的源文件。也包括页面用 void 表达式丢弃 ViewModel 或 presenter 暴露的回调参数，或写者的注释、计划与回执自报“已接线”“→ 某调用”，方法体里却没有对应调用。

## 原因

文本检索只能发现写了标记的占位，发现不了缺失的处理函数、只写注释的回调或没有调用者的函数；对齐表按意图打勾，未实现项就以“已完成”交付，直到用户操作时才暴露。来源中待办勾选、点击跳转、首次启动播种都被报告为已实现或完全一致，代码里却没有对应组件、跳转调用或启动路径调用。另一应用中首页横幅与四张资讯图的点击处理只含 FWD-REF 注释与 return，规格确认消息仍向用户称已对齐点击语义。另一应用中，实现者替换占位后报告“全部 AC 完成、无占位”，实际丢了温度与天气字段、未加载定位城市；另一实现者以占位清零判断完成，漏了规格里“登录成功后重载”的 AC；数据接线者只接了 40 日页的主接口，规格要求的趋势接口没有任何页面调用。另一应用的生成期验证只查静态规则与路由注册，没有核对 P0 功能的深链 AC；返修起初又以 MVP 决策把缺失的深链登记为范围外，读到 AC 后才按缺口补齐。 另一应用首轮流水线以文件存在与编译成功给三十多个页面全部打勾，多数页面是模板空壳或写死数据；后续增量轮的执行代理把接口响应 JSON.stringify 放进 Text，主代理按回执称已接入真实接口；收口审查只看语法风险，未发现回执宣称的编辑态并不存在。

## 做法

1. 报告前按规格验收项逐条在当前代码中找到落点：组件（如 Checkbox）、ViewModel 方法、router/NavPathStack 调用、启动路径上的函数调用者；找不到就标未完成。
2. 验证阶段除检索 TODO 外，扫描空回调与回调体只有注释的 onClick，并把页面规格的导航出口与代码中的跳转调用逐项对账。用 void 丢弃的回调参数与空回调同样按未接线处理；写者自己在注释或计划里写下的调用步骤，也逐项在方法体里找到对应语句，注释不算落点。
3. 实现者替换占位或宣布 AC 完成前，以 UI 壳已声明的展示字段和规格中带事件订阅锚点（onEventMainThread、@Subscribe）的 AC 为清单，逐项找到赋值与订阅的代码位置；占位清零不等于 AC 覆盖，暂缺的来源登记为缺口。
4. P0 功能的 AC 目标符号（如深链处理函数、module.json5 的 uris）检索命中 0、决策账本也没有对应 skip 时，按缺口处理，不以 MVP 或范围决策的名义登记为范围外。
5. 页面完成判定除 TODO 外检索占位特征：“开发中”“XXX 页面”一类只有标题或返回栏的页面、写死的分类与商品样例、把接口响应 JSON.stringify 后直接显示；命中即按未完成处理并登记缺口，不计入完成数。文件存在、页数相等与编译通过都不能区分占位与已转换页面。
6. 子任务回执要列出实际对照过的源文件和已识别但未实现的源端行为；回执没有任何源文件引用，或以“均保留”概括时，协调者按未完成处理，抽查页面里的状态变量、接口路径与按钮可用条件后再向用户报告。
