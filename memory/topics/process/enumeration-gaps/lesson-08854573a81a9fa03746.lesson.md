# 规格提取写验收条目时实读所引源码段落，照抄比较符、范围与名称变换，条目范围不超出本行源锚点，并给出边界样例

ID：`lesson-08854573a81a9fa03746` · 版本：5 · 阶段：spec · 主题：[process/enumeration-gaps](index.md)

概要：验收条目实读源码段落，照抄比较符并给边界样例

信号：`width > 600`, `Linkify`, `grep`, `ViewModel`

## 何时使用

规格提取阶段写阈值、列表范围、过滤条件、复制/变换类或持久化类验收条目并标注源码出处时

## 适用情境

规格作者依赖预生成参考文档或源码片段写验收条目，并以“源码文件:行号”标注出处；读取可能被截断，或只读了参考文档的目录。也包括源端对同类数据维护多组独立集合（如按页面分别写入的两组收藏），规格按页面拆成多个功能分别写条目。

## 原因

验收条目会被实现者、测试和评审当作判据：比较符写反、把“列出全部”写成“只列缺失”、漏掉名称后缀或内容来源，或把别的页面的数据写进本功能条目，下游照条目实现、测试或返修，会把本来正确的实现改错。来源四例：规格作者读参考文档时中段被截断、没读所引源码行，写出与源码相反的列表范围；一条阈值条目与同规格其他条目及所引源码相反，返修照它把正确实现改偏；克隆条目只写“复制字段与步骤”，参考文档里已有的名称后缀与草稿来源没读到正文；源端收藏分为会话设置写入的来源组与另一页写入的目标组，规格作者读到两组独立键与术语表，仍在会话设置条目里写成“两组持久化”，而本行源锚点只有来源组，单测与修复随之把两组耦合。

## 做法

1. 写带出处的条目前打开所引行号段落；参考文档读取 truncated 或只看到目录时，按章节读到正文。
2. 阈值条目照抄源端比较符，并给出边界两侧样例（例如源端 width > 600 时 600 仍为一列）；与同一规格里的同类条目对齐。
3. 复制、导入这类条目写明内容来源（持久化值还是编辑中草稿）、字段变换（名称后缀、id 清零）和完成后的导航，不只写“复制字段”。
4. 为界面组件写条目时覆盖源码对展示内容的加工（如链接识别与着色），并把组件源文件列进该功能的源码锚点；工具类按 grep 到的真实调用点归属功能，不凭名字挂到不调用它的页面。
5. 源端同类数据维护多组独立集合时，逐组确认写入它的页面或 ViewModel，再按功能分别写条目；条目文字（含括注）的范围不超出本行源锚点所列的集合。
