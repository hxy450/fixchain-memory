# 目标把源类拆成接口实现类、引擎、ViewModel 与 UI 门面等多层时，每层的方法集合按源端调用全集核对：子类覆写、源回调调用的界面方法、外部读面

ID：`lesson-61a9fc7190c51c663697` · 版本：1 · 阶段：spec/execute/converge · 主题：[process/enumeration-gaps](index.md)

概要：拆层后各层方法按源端覆写与调用全集核对

信号：`@Override`, `Listener`, `Callback`, `Facade`

## 何时使用

规格提取阶段为接口实现类与门面写服务层清单和 AC 时；实现阶段定义接口实现子类、VM 到 UI 的门面或回调 sink、移植被多处调用的源类时；接线收口阶段按这些接口接线时

## 适用情境

源端一个实现类继承带空默认实现的基类或回调接口，并覆写其中一批回调（错误、信息、就绪、执行期状态），或在回调里直接调用界面方法（显示或隐藏控件、刷新图标）；目标把这条链拆成继承空默认基类的接口实现类、ViewModel、UI 门面与回调 sink，由不同切片编写，接口成员按规格点名的几项设计。也包括被其他源组件调用的公开读面（如供覆盖层读取的位置与状态 getter）。

## 原因

规格只点名部分方法时，其余回调继承空默认、门面缺少对应成员；调用方照常调用，事件全部静默，编译与结构检查都不报错。下游接线者只能按缺项的接口接线，缺口沿层传到页面。

## 做法

1. 源实现类继承带空默认的基类或接口时，列出源子类全部 @Override 方法（含 on* 错误与信息回调），与目标子类的覆写做差集；基类空默认不作为终态，差集非空就补覆写，或写明归属并登记缺口。规格提取阶段按同一份清单写服务层条目与 AC。
2. 定义 VM 到 UI 的门面或回调 sink 时，把源回调里调用的界面方法逐个列为门面成员并在回调里调用；门面缺成员时先补成员，再在页面把它转发到界面层，不按缺项的接口接线后标完成。
3. 移植被其他组件调用的源类时，用“源端外部调用点 → 目标公开方法”清单核对公开读面与对应的存储字段，不只按本 feature 对接点核对。
4. 写完后检索目标中与源回调同名的落点（如 VM 上的同名方法）确有调用者；没有调用者就接线，或登记挂点与负责方。
