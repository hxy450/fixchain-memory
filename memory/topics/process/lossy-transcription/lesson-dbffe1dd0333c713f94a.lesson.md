# 按源函数或验收条目写含多项门控条件、守卫或改变行为的参数的方法时逐项落到代码：缺入口留注入点，不删条件、不换相近能力、不 void 掉参数

ID：`lesson-dbffe1dd0333c713f94a` · 版本：1 · 阶段：spec/execute · 主题：[process/lossy-transcription](index.md)

概要：多条件门控与行为参数逐项落码，不删不换不丢

信号：`&&`, `||`, `canIUse`

## 何时使用

规格提取阶段为能力门、触发守卫与模式开关写验收条目时；实现阶段按源函数或 AC 写能力判断、触发守卫或带布尔模式参数的方法时

## 适用情境

源函数用多项条件的合取决定能力是否可用或动作是否触发（启动来源、内存阈值、传感器存在、预览支持某模式、弹层是否打开、正在录制），或用布尔参数切换行为（连续模式、多帧模式），AC 逐项列出了这些条件；目标端某项条件的判断入口在别的切片或契约里暂缺，写者倾向写“近似”、用相近的设备能力代替，或用 void 丢弃参数。也包括把源端以对象为输入的谓词（按档位尺寸与偏好判定）改成布尔参数，或以空对象占位上报。

## 例外与边界

- 决策台账中带决策编号的差异决策明确删去或替换某项条件

## 原因

条件之间是合取：删去一项或换成相近能力，门控在源端不成立的场景下也会放行；void 吞掉改变行为的参数后调用照常编译，模式退化成默认分支。注释照抄了全部条件而代码少一项时，读注释的审查者也会当作已实现。

## 做法

1. 写代码前把每个源条件列成“源条件 → 目标表达式”对照（判断来源、阈值、传感器、模式支持、界面状态），每行在代码里对应一个分支或参数；规格提取时 AC 同样逐条抄全源函数的条件，不只写最显眼的阈值。
2. 某项条件的判断入口在当前契约里还没有时，在构造参数或接口里留注入点，并按占位协议登记给拥有者；并行切片已实现同一判断时直接复用。不删掉整条门控，不写成恒定值，也不用另一种设备能力（如通用能力探测代替具体传感器）顶替。
3. AC 说明某参数改变行为（多帧、连续模式）时，让参数驱动对应分支；目标平台缺少原生支持就在本层实现等价机制，做不到时登记缺口或待批决策，不用 void 丢弃参数后静默退化。
4. 源端谓词以对象为输入时，目标接口保留该对象参数（如按当次档位判定），不降为布尔或以空对象占位。
5. 写完对照方法注释与 AC，注释或 AC 列出的每个条件都在代码分支里找得到再提交。

## 可选检查

- 对某项条件有疑问时，写一条只让该条件不满足的用例，确认门控为假或动作不触发
