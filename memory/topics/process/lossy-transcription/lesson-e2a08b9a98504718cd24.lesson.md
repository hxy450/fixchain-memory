# 用一个复位函数模拟源端每局重开时，按字段声明位置与生命周期决定复位：只复位重开路径实际赋值或新建对象初始化的字段

ID：`lesson-e2a08b9a98504718cd24` · 版本：2 · 阶段：spec/execute · 主题：[process/lossy-transcription](index.md)

概要：复位函数只复位源端每局路径实际赋值的字段

信号：`initGame`

## 何时使用

规格提取与引擎实现阶段，把源端每局重开（重开函数里 new 循环或状态对象）映射为模块级静态引擎或单例的复位函数，确定新局复位哪些字段、写复位验收时

## 适用情境

源端状态分属不同生命周期：类静态字段只在类加载时初始化一次，宿主 View/Activity 的实例字段随宿主构造初始化，每局新建对象的字段随 new 重置；目标把这些字段合并进同一个模块级静态引擎或单例，用一个 initGame/reset 函数模拟每局重开。

## 例外与边界

- 源端重开本来就重建宿主（重新创建 Activity 或 View）时，宿主实例字段也随之重置，按实际重建范围复位

## 原因

复位函数把三种生命周期压成一种：多复位一个类静态字段或宿主实例字段，跨局残留的计数、在飞对象与标志就被清掉，新局的可观察行为随之改变。规格把这些字段并进同一个“实例态”列表，或用“重置全局态”概括重开函数，实现会照写多出的复位。

## 做法

1. 规格提取时为重开函数逐字段标出声明位置与生命周期（类静态、宿主实例、每局新建对象的实例字段）：每局复位只列重开函数体实际赋值的字段，以及其中 new 出的对象的构造器与字段初始化器；static 字段初始化器与宿主实例字段写成初值说明，不写成每局复位断言。状态管理节按这三组列字段，服务层对重开函数写明复位哪些、保留哪些；验收条目标注的源码区间内要能找到它列出的每条赋值。
2. 实现时复位函数里的每条赋值都要能指到源端每局路径上的一条赋值；多出的复位按源删除，或登记待批决策。规格要求的复位与源码不符时，在 handback 中报规格缺口，不照写。
