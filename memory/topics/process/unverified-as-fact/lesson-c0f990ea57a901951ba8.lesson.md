# 生成期无法核验的规格结论标明置信度与核验方法，不定为硬性决策或带具体 dp 的视觉判据

ID：`lesson-c0f990ea57a901951ba8` · 版本：4 · 阶段：spec · 主题：[process/unverified-as-fact](index.md)

概要：生成期无法核验的结论标置信度，不定 HARD 或具体 dp

信号：`HARD`, `dp`, `SDK`

## 何时使用

规格提取阶段，在没有真机布局 dump、生成期又不能编译或上设备时，写带具体 dp 的视觉验收判据、决策台账条目或 HARD 映射决策时

## 适用情境

基线快照由源码合成、bounds 为空，或 SDK 文档对关键语义只有模糊措辞、参考检索为空；规格准备写入源码字面尺寸、“近乎不可见、按源码保留”类结论，或把依赖未验证语义的映射定为 HARD，把可靠方案降为“真机偏色再回退”。

## 例外与边界

- 已有真机 dump、截图测量或等价单测给出实测值

## 原因

合成快照只有声明树、没有度量，模糊的 SDK 措辞也推不出具体行为；推断一旦写成判据或 HARD 决策，实现者会原样复刻，验收也当已知设计。回退条件要求真机比对时，生成期根本不会触发。

## 做法

1. 带具体 dp 的视觉验收条目标出置信度，注明依据是源码字面，并要求验证阶段用真机 dump 或截图量值取代。
2. “颜色近乎不可见”“保留源端缺陷”类结论先分辨成因是颜色还是布局度量，写成待真机核对项，不进决策台账当已知缺陷。
3. 映射依赖的语义在 SDK 与参考中都没有明确说明时不定 HARD，写明核验方法；已有不依赖该语义的等价方案（包括源码作者留下的实现提示）时，把它设为主方案，依赖未验证语义的方案设为回退。
