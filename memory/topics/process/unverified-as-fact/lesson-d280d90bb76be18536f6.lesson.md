# 规格登记源端字面常量时先分类：应用自定的参数连同单位与出处照抄，随源平台单位、值域或源实现硬编码而定的值改写为目标端取值方式

ID：`lesson-d280d90bb76be18536f6` · 版本：1 · 阶段：spec · 主题：[process/unverified-as-fact](index.md)

概要：规格常量分应用参数与源平台取值，后者写目标取法

信号：`static final`, `= true`, `.0f`

## 何时使用

规格提取阶段写常量清单、实现映射表与带期望值的 AC，抄录源端字面值（传给平台 API 的阈值与角度、硬编码的能力位、以特殊值表示的状态）时

## 适用情境

源端把应用自定的参数以字面值传给平台 API（目标角度与容差、次数、时长），或在实现里按源平台写死取值（能力位恒为真、按镜头写死的角度），或用源平台值域里的特殊值表达状态（如以 0 表示无限远）；规格常量表只收录了部分值，或把源字面值原样写成目标契约。

## 原因

常量清单与 AC 是下游取值的依据：应用参数没登记，接手者只能自拟数值；源平台取值被照抄成契约，目标实现会把源端硬编码或单位相关的特殊值当成规则，例如能力位一律为真，或特殊值在目标值域里指向另一端。

## 做法

1. 逐个判断源端常量的性质：应用自定、跨平台不变的参数（传给平台 API 的阈值、角度、次数）照抄进常量清单，写明单位、换算式与源文件位置；接口签名不带这些参数时，在映射行写明由哪一侧传值。
2. 含义取决于源平台单位、值域或源实现硬编码的值，在契约里标为“源端取值”，并写出目标端的取值方式（会话或能力查询接口、单位换算、目标值域里的对应值）；还没查到目标取值方式时登记为待查的平台差异，不把源字面值写成跨平台判定。
3. 带单位或值域的参数在映射表里写出源端与目标端的单位、值域与换算点，AC 期望值用目标端值域表达。
