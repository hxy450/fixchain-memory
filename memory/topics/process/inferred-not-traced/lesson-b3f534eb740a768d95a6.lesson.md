# 源端行为依赖的辅助方法、谓词、getter 与框架约定，要读到定义再翻译，不按名字或记忆推断

ID：`lesson-b3f534eb740a768d95a6` · 版本：6 · 阶段：spec/execute · 主题：[process/inferred-not-traced](index.md)

概要：辅助谓词与 getter 读到定义再翻译，不按名字推断

信号：`isPlayingState`, `playPause`, `LiveData<String>`, `PAUSED`, `PLAYING`, `${x}`, `padMinutes`

## 何时使用

业务逻辑与界面实现阶段，翻译以辅助谓词分派的切换方法（playPause/toggle）、推导列表行的“正在播放”显示、转写把观察值插进文案模板的显示，或移植兜底链、格式化、名称暗示语义的辅助方法与框架行为时；闭合“等价于源端谓词/聚合器”的占位时；规格提取阶段写这类状态契约时

## 适用情境

源码以 isPlayingState() 一类谓词分派 pause/play，或把 text 前缀的 LiveData<String>（格式化结果）拼进文案；读到的源码片段只含调用或相邻 getter，没有定义；同一 ViewModel 另有同名的原始数值字段。也包括写者只看到调用点、grep 命中行或方法名（链接兜底、文件大小格式化、名称暗示全高的展开方法），或依赖框架约定（偏好摘要的占位符代入），目标侧须自写等价函数；以及列表行、卡片的“正在播放”显示（暂停键、高亮）要等价于源端多条件谓词（媒体匹配、播放服务运行且状态为 PLAYING），页面只保存了正播媒体 id。也包括调用点依赖 Kotlin 默认参数的格式化函数（如时长格式化的补零开关），写者已读到定义，仍准备在页面里按记忆另写一份。

## 原因

凭名字推断谓词的覆盖范围，或把格式化文本映射成原始数值，编译都正常，运行时才出错（暂停后无法续播、定时文案变成裸秒数）。分段 sed、截断的 grep 常刚好漏掉定义行。来源两例中实现者都计划核对，却只读了片段就凭名字写。按方法名或记忆推断还会丢掉定义中的兜底分支、单位与进位规则和额外条件，或误读语义（名称暗示全高的方法实际只展开到内容高度）；只比媒体 id 时，暂停后同一行仍显示暂停键并保持高亮。

## 做法

1. 翻译用到的每个谓词和 getter 都读到定义行；读不到时以规格状态转移表和验收用例为准，不凭名字推断（例如 isPlayingState 是否包含 PAUSED）。
2. 切换方法写完后按规格逐个当前状态核对：暂停态必须走 play，播放态才走 pause；不要把某个方法的前置守卫当作另一个方法的分派条件。
3. 转写 "${x}…" 拼接时先读 x 的定义：text 前缀的 String 通常是格式化结果，不能映射到同名原始数值；规格状态契约要为每个插值写明源 getter、类型与格式。
4. 复用已有格式化函数前，逐分支对照源格式化器（小时分支、封顶值、≤0 的处理）。
5. 移植被调用的辅助方法或框架算法时，打开定义逐分支落实兜底链、空白判断、取整与单位和全部条件；调用点省略的参数按源签名的默认值落实（如 padMinutes = false 即分钟不补零），不按记忆或习惯补齐；目标已有该方法的移植时直接调用，缺该方法时补成共享函数供各处复用，不在页面内另写一份。
6. 闭合“等价于源端谓词/聚合器”的占位时，先列出其全部条件或状态映射再实现，或调用仓内已有的同口径实现；页面折算行显示态时同时保存所需状态（如播放状态），在状态事件与 aboutToAppear 中一起重算，各页复用同一判定，不按同类页先例另写简化表达式。
7. 占位或交接里引用的源方法名必须完整读过对应源码行，下游实现者回源码核对，不按占位里的名称直接实现；规格中消费页引用共享谓词时，内联其完整条件或指向定义它的条款。
8. 删改或否定已实现的源行为前（如断言“源码没有该调用”），用本次读取回执或重新检索核对，不凭记忆。

## 可选检查
