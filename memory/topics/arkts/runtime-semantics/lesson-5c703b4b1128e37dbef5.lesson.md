# 需授权、需初始化或依赖定位坐标的仓库方法，前置条件缺失时按源端分支处理（改走其他查询，或走与声明一致的错误通道），不静默返回空集合

ID：`lesson-5c703b4b1128e37dbef5` · 版本：3 · 阶段：execute · 主题：[arkts/runtime-semantics](index.md)

概要：仓库方法前置失败走声明的错误通道不返回空集合

信号：`UIAbilityContext`, `requestPermissionsFromUser`, `photoAccessHelper`, `Repository`, `throw new Error`

## 何时使用

数据层实现阶段，为依赖上下文与运行时权限的枚举、查询类仓库方法编写前置失败分支（上下文未初始化、未授权、枚举失败）时；为依赖定位的附近列表确定无坐标、未授权时的查询分支与结果状态时

## 适用情境

仓库方法依赖 UIAbilityContext 与运行时权限（如媒体读取）；规格或源端要求失败时由调用方显示错误提示，调用方靠捕获异常区分“出错”与“确实为空”的空态引导；方法还会把结果写入缓存。也包括依赖定位的附近列表：源端有权限且有坐标时按坐标加半径搜索，无权限或坐标未知时仍按当前城市查询；目标坐标可能未知，决策要求失败保持显式错误、不伪造空成功，页面只有加载中、错误信息与列表三个状态，空列表落入预写的“附近无站点”空态。

## 原因

在权限检查之前加 return [] 一类兜底，会把失败伪装成“没有数据”：调用方显示空态引导而不是错误，空结果还可能覆盖缓存。来源中生成者在注释里写明“权限拒绝时抛错”，同类私有方法也把无上下文视为未授权，枚举方法却在上下文为空时返回空列表并继续写缓存；两个生产调用方都会先初始化，暴露它的是未初始化仓库的单测夹具。坐标未知时 return [] 同样把“查询条件缺失”伪装成“查询成功为空”，还丢掉源端在这种情况下的替代查询。

## 做法

1. 把“上下文未初始化”“权限未授予”“枚举失败”统一走同一失败通道（抛错或显式错误结果），与注释和规格一致；空集合只表示确实没有数据，失败时不写入或覆盖缓存。
2. 输出前逐一检查方法的早退分支；同一状态在不同分支被映射成不同结果时先统一。
3. 依赖定位的查询先把源端按“有权限且有坐标 / 无权限 / 坐标未知 / 定位失败”逐分支列出实际行为再映射：源端改走其他查询（如按当前城市）就照做；只有“查询条件有效且服务成功返回空”才表示空态，其余情形以结果联合或状态枚举单独返回，页面的“附近无…”空态只绑定真空数据。
4. 接线时核对源端入口门槛（如无定位权限时转去选城页），不让无坐标状态以空列表进入列表页。
