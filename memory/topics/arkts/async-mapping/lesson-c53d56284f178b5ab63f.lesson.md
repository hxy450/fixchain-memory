# 源端阻塞到完成才继续的关闭、释放、排空、停止方法映射到返回 Promise 的目标时，签名、seam 类型与调用链一路改为 Promise 并 await

ID：`lesson-c53d56284f178b5ab63f` · 版本：1 · 阶段：spec/execute · 主题：[arkts/async-mapping](index.md)

概要：阻塞等待改 Promise 后签名与调用链一路 await

信号：`Thread.join`, `Object.wait`, `CountDownLatch.await`, `Future.get`, `Promise<void>`, `() => void`, `aboutToDisappear`, `onDestroy`, `.catch(`

## 何时使用

规格提取、服务实现与跨切片接线阶段，把源端阻塞到完成才返回的关闭、释放、排空或停止方法映射到返回 Promise 的目标 API，并确定接口签名、seam 回调类型与调用方是否 await 时

## 适用情境

源端方法在后台线程或调用线程内阻塞到操作完成（join、wait、同步 stop/release），完成后才置状态、回调、重开或销毁，验收写着“X 先于 Y”；目标对应 API 返回 Promise，规格接口表却照搬 Java 的 void 签名，生命周期回调（如 aboutToDisappear）不能 await。

## 原因

void 签名让下游只能即发即弃：调用立即返回，后续的状态迁移、销毁或重启在操作完成前执行。只接 .catch 吞错、或用 Promise.resolve().then 包裹调用，看起来是异步串接，实际并不等待真正完成；挂接 hook 做成 async 而拆卸留作 void，同样破坏顺序。

## 做法

1. 规格接口表按目标 d.ts 的返回类型写签名：源方法内部阻塞等待时写 Promise<void>，并在验收写明调用方需 await。
2. 跨切片 seam 即使当前只是桩，回调类型也定为 () => Promise<void>，不定为 () => void；成对的挂接/拆卸 hook 都返回 Promise。
3. 实现与接线时从平台调用到最外层入口逐层 await；状态迁移（如置为已关闭）、完成回调、重开与后续销毁只放在 await 之后，不用 void 丢弃需要排序的 Promise。
4. 不能 await 的生命周期回调只发起一个 async 序列，把依赖完成的销毁放在该序列的 await 之后，页面里不再另行同步销毁。

## 可选检查

- 检索只接 .catch、不 await 的 release()/close()/stop() 调用，以及签名为 void、内部却发起 Promise 的方法
