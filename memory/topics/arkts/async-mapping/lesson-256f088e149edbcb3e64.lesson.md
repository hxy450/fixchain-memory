# 源端 BlockingQueue 加常驻消费线程改写成 Promise 泵时，先入队启动泵再等容量，逐项 try/catch 并在 finally 复位

ID：`lesson-256f088e149edbcb3e64` · 版本：1 · 阶段：execute · 主题：[arkts/async-mapping](index.md)

概要：阻塞队列改 Promise 泵：先启泵，单项失败不卡队

信号：`BlockingQueue`, `ArrayBlockingQueue`, `LinkedBlockingQueue`, `take()`, `put(`, `while (true)`

## 何时使用

服务实现阶段，把源端 BlockingQueue 与常驻消费线程（循环 take()）实现的保存、上传等队列改写为 ArkTS 异步队列，并实现容量占位、排空等待与销毁时

## 适用情境

源端消费线程常驻 take() 阻塞取任务，生产者在队满时阻塞等待空位，并按成本向队列追加占位；目标没有阻塞原语，改为按需启动的异步泵循环加等待者。

## 原因

生产者先 await 全部容量占位、最后才启动泵时，容量不大于单次成本的小队列里占位永远等不到空位；泵循环不隔离单项异常时，一次失败就让计数不减、“泵运行中”标志不复位，排空等待永不返回，后续请求也不再处理。

## 做法

1. 入队后立即启动或保持泵运行，再等待容量；或在入队时同步预占整组成本，多个生产者经串行的入队链排队。
2. 泵循环对每个请求 try/catch，失败也递减计数并通知等待者；泵运行标志在 finally 中复位。
3. 销毁时先停止接收新任务，再投递结束标记；需要“排空先于销毁”时在销毁序列中 await 排空后再释放。

## 可选检查

- 单测覆盖“容量小于单次成本的请求能排空”和“单项保存抛错后排空等待仍返回、后续请求继续处理”
