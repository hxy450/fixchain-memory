# 源端同步的“提交挂起对象后清空字段”改成含 await 的实现时，先摘下对象并清空字段，再 await 提交

ID：`lesson-39506b537e290273ecb1` · 版本：1

[本主题](index.md)

## 何时使用

实现阶段，把源端在单个同步方法里“取出挂起的批次或请求 → 入队或保存 → 字段置空”的逻辑改写为 ArkTS 异步方法时

## 适用情境

源端在主线程同步执行入队或保存后把 pending 字段置 null，期间不会有新对象写入；目标的入队或保存可能 await（队列满时等待槽位、异步写入），等待期间其他回调可能新建对象并写入同一字段。

## 原因

await 让出事件循环；await 之后再把字段置空，清掉的是等待期间新建的对象，已提交的旧对象在等待期间也可能继续被追加。

## 做法

1. 在第一个 await 之前把挂起对象读进局部变量并清空字段（const job = this.pending; this.pending = null），再 await 提交 job，后续判断只用局部变量。
