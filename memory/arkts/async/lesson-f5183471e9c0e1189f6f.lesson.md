# 同键覆盖前先取消旧任务时，完成清理按句柄身份删除：运行表当前项仍是本次句柄才移除

ID：`lesson-f5183471e9c0e1189f6f` · 版本：1

[本主题](index.md)

## 何时使用

后台任务或作业调度实现阶段，为“同一 id 再次启动时先取消旧任务再写入新任务”编写运行表与 finally/完成回调的清理逻辑时

## 适用情境

源端或已批准的差异要求同一 workId 任何时刻最多一个运行实例：再次启动时取消旧句柄并写入新句柄；目标在 finally 或完成回调里清理运行表，旧任务可能晚于新任务开始后才结束。

## 原因

清理只按 id 删除时，晚到结束的旧任务会把新任务的句柄从运行表移除：isRunning 变为 false，随后的停止请求取不到新句柄，无法取消。源端按 id 删除依赖它不显式取消旧任务的覆盖语义，换成“先取消再覆盖”后不再成立。

## 做法

1. finally 或完成回调中比较句柄身份：仅当运行表中该 id 的当前项就是本次运行的句柄时才删除；规格批准“先取消再覆盖”语义时，生命周期的移除步骤也写明按句柄身份移除。

## 可选检查

- 按“同键二次启动、旧任务晚到结束”的顺序核对 isRunning 与停止请求
