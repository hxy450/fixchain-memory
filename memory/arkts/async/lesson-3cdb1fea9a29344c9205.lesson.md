# 源端后台线程或回调里写的字段，调用方发起后又同步写同一字段时，按实际生效顺序推导结果；改成同步调用要把调用方的写挪到调用之前

ID：`lesson-3cdb1fea9a29344c9205` · 版本：1

[本主题](index.md)

## 何时使用

规格提取阶段把源端 Thread、Handler.post、异步回调里写入的状态翻译成目标契约与验收时；实现阶段把源端后台加载改成同步调用时

## 适用情境

源端方法启动后台线程（new Thread、Handler.post、AsyncTask、异步回调），成功后在线程里写某个字段；调用方在发起它之后紧接着在主线程同步写同一字段（如先发起加载、再把该字段清零）。目标把这段后台工作改成事件循环内的同步执行，或规格按代码书写顺序推导可观察结果。

## 原因

后台线程里的写入落在调用方后续同步语句之后，源端最终值来自后台写；按书写顺序推导会得到相反的最终值。目标把后台工作改成同步调用后，调用方的后写反而覆盖了加载结果；以“单线程天然消除竞争”为由照书写顺序实现，返回、重试、撤销这类可重复操作的连续结果就和源端不同。

## 做法

1. 规格提取时，凡源端在 Thread、Handler.post 或异步回调里写的字段，查调用方发起后是否还同步写同一字段；按运行时生效顺序（后台写落在调用方后续语句之后）推导可观察结果，并在契约里列出这些字段与最终值。
2. 把后台工作映射为同步调用时，把调用方在发起之后对同一字段的写挪到同步调用之前，保持源端最终值；源端结果随线程调度而不确定时，在报告里写明并按实测的主要结果取一种。
3. 返回、撤销、重试这类可重复操作的验收连续写第 1、2、3 次的结果，并覆盖不同起点；有后台写参与时以设备实测序列定条目。
