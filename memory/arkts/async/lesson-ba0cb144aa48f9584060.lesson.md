# 源端连续的同步平台调用（先取消再振动、先停止再启动）映射到返回 Promise 的 API 时，在网关内串行发出或改用同步变体，不各自 fire-and-forget

ID：`lesson-ba0cb144aa48f9584060` · 版本：2

[本主题](index.md)

## 何时使用

功能实现阶段封装平台能力网关，把源端依赖先后生效的连续同步系统调用映射为返回 Promise 的目标 API 时；规格提取阶段为这类映射写契约时

## 适用情境

源端在同一方法里依次同步调用两个平台方法且后者依赖前者已生效（如 Vibrator.cancel() 后立刻 vibrate(pattern)）；目标 API（如 vibrator.stopVibration/startVibration）返回 Promise，网关接口按规格声明为 void，调用方仍按源顺序逐个调用。

## 原因

两个 Promise 在平台侧各自执行，先后不保证，取消可能晚于启动而截掉刚开始的效果；只核对调用点顺序与源码一致，看不出生效顺序问题。

## 做法

1. 网关内用 Promise 链队列串行：前一调用 settle（成功或失败）后才发出下一调用，吞错与日志保持原样；或改用 d.ts 中的同步变体（如 stopVibrationSync）。
2. 写后对每个返回 Promise 的平台调用列出前后紧邻的平台调用，问源端是否依赖它们的先后，依赖时确认有 await 或队列；规格把同步 API 换成 Promise 形而接口仍为 void 时，在契约与验收中写出串行要求。
