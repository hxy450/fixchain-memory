# 源端在构造期同步完成 initialize 的客户端，目标设显式就绪门禁：未就绪按源端返回未初始化错误，逐次守卫里不顺手自行初始化

ID：`lesson-9b880b43ef451669814e` · 版本：1

[本主题](index.md)

## 何时使用

服务层实现阶段，把构造函数里 runBlocking { initialize() } 的客户端改成 ArkTS 异步 initialize，并为各业务方法与后台入口编写就绪判断时

## 适用情境

源端客户端构造即完成初始化，业务方法经 safeBlock 一类守卫在未就绪时返回固定错误码（如 1001），不发请求；目标改为异步 initialize，界面、后台作业等多个入口都会调用客户端。

## 原因

在 requireConfigured 一类逐次守卫里顺手从库中解码密钥或加载配置，等于绕过就绪门禁：未初始化时照常发请求并得到另一种错误，规格要求的未就绪错误永远不出现；入口靠这个懒加载才能工作，又掩盖了某些入口从未 await 初始化。

## 做法

1. 设显式 initialized 标志，initialize 完成（含 create/join 一类手动建立就绪状态的成功路径）后置位；未就绪时按源端返回未初始化错误，不在守卫里自行初始化。
2. 逐个检查界面、后台作业等全部入口在首个请求前是否已 await 初始化，缺的在入口补调用。
