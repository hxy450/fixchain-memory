# BlockingQueue 常驻消费线程改成 Promise 泵时，先入队启动泵再等成本占位，逐项 try/catch，泵标志在 finally 复位

ID：`lesson-15256c115e73ac0a1d86` · 版本：1

[本主题](index.md)

## 何时使用

服务实现阶段，把源端常驻消费线程（while(true) queue.take()）与满队等待、成本占位改写成 ArkTS 按需启动的 Promise 消费循环时

## 适用情境

源端处理线程常驻并阻塞在 BlockingQueue.take()，生产者在满队时阻塞等待空位，并按请求成本追加占位条目；目标没有阻塞原语，改成入队后启动一个异步泵，并提供 waitUntilDone 等待计数归零。

## 原因

源端消费者独立于生产者运行；改成按需泵后，若生产者先 await 全部占位才启动泵，队列容量不大于单个请求成本时占位永远等不到空位。泵循环不隔离单项异常时，计数不再递减、泵标志停在运行中，waitUntilDone 永不返回，后续请求也不再处理。

## 做法

1. 入队后立即启动或保持泵，再等待成本占位；或在串行的入队尾部同步预占整组成本，不让泵的启动依赖生产者完成入队。
2. 泵循环对每个请求 try/catch：失败也递减计数、通知等待者并上报错误，泵标志在 finally 中复位。

## 可选检查

- 单测“容量小于单个请求成本时请求能排空”与“单个处理抛错后 waitUntilDone 仍返回、后续请求继续处理”
