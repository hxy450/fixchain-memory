# 需授权或需初始化的仓库方法，前置失败分支走与声明一致的错误通道，不静默返回空集合

ID：`lesson-5c703b4b1128e37dbef5` · 版本：1

[本主题](index.md)

## 何时使用

数据层实现阶段，为依赖上下文与运行时权限的枚举、查询类仓库方法编写前置失败分支（上下文未初始化、未授权、枚举失败）时

## 适用情境

仓库方法依赖 UIAbilityContext 与运行时权限（如媒体读取）；规格或源端要求失败时由调用方显示错误提示，调用方靠捕获异常区分“出错”与“确实为空”的空态引导；方法还会把结果写入缓存。

## 原因

在权限检查之前加 return [] 一类兜底，会把失败伪装成“没有数据”：调用方显示空态引导而不是错误，空结果还可能覆盖缓存。来源中生成者在注释里写明“权限拒绝时抛错”，同类私有方法也把无上下文视为未授权，枚举方法却在上下文为空时返回空列表并继续写缓存；两个生产调用方都会先初始化，暴露它的是未初始化仓库的单测夹具。

## 做法

1. 把“上下文未初始化”“权限未授予”“枚举失败”统一走同一失败通道（抛错或显式错误结果），与注释和规格一致；空集合只表示确实没有数据，失败时不写入或覆盖缓存。
2. 输出前逐一检查方法的早退分支；同一状态在不同分支被映射成不同结果时先统一。
