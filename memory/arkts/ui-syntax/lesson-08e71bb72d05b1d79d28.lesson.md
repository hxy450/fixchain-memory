# build() 与 @Builder 里每个组件、条件与循环渲染各占独立行：if/else 带花括号、块后不加分号，含组件语法的方法声明为 @Builder

ID：`lesson-08e71bb72d05b1d79d28` · 版本：1

[本主题](index.md)

## 何时使用

界面实现阶段，整页编写或重写 ArkTS 页面的 build() 与可复用组件片段，并在交付前自检语法时

## 适用情境

页面含卡片片段、加载/空/错误或有图/无图等条件渲染与 ForEach/Repeat 列表；写者倾向把组件树压成一个方法一行、用分号拼接，或把卡片写成普通 private 方法；生成期常不编译。

## 原因

声明式 UI 只接受组件语法与 if/else、ForEach/Repeat 等渲染控制；if 块后的分号构成空语句，普通方法里的组件、无花括号的 if 分支都会报 Only UI component syntax can be written here、';' expected 一类错误。来源中三个 UI 子代理写前都读到这些约束与多行模板，仍把首页、评价页、购物车页压成单行；两页编译失败，第三页被静态审查拦下重写。

## 做法

1. build() 与 @Builder 中每个组件、if/else 分支、ForEach/Repeat 各占独立行；if/else 一律带花括号，块后不加分号。
2. 方法体里出现 Column、Row、Text 等组件语法就声明为 @Builder，在 build()、ListItem、Repeat.each 中以 this.xxx() 调用；普通 private 方法只放数据逻辑。

## 可选检查

- 不能编译时检索右花括号紧跟分号、无花括号的 if/else 组件分支、未加 @Builder 却含组件尾随闭包的方法。
