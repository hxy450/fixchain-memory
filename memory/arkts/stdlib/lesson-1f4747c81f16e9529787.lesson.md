# Java 集合迭代序、有符号 byte 比较与 switch 返回码按 Java 语义复刻：HashSet/HashMap 决定顺序时用桶序，byte 先换回 -128..127，只把源 case 列出的码判失败

[本主题](index.md)

## 何时使用

规格提取与切片实现阶段，转写依赖 Java 集合迭代序（keySet、toArray、new ArrayList<>(set)）、byte 与 int 字面量比较、按返回码 switch 分支的逻辑时

## 适用情境

源端用 HashSet/HashMap 的迭代序决定输出文件、尝试顺序、写入顺序或问题清单顺序；用 byte 变量与 0x81 一类 int 字面量比较；switch 只把部分返回码（如 2、-1）判为失败；目标准备用 JS Set/Map（插入序）、0–255 的 number 与相邻方法的 result !== 0 判定。

## 例外与边界

- 规格或决策明确不要求复刻集合迭代序，并在验收中写明

## 原因

JS Set/Map 按插入序迭代，Java HashSet/HashMap 按哈希桶序；Java byte 有符号，firstByte < 0x81 对 0x80–0xFF 的结果与无符号比较相反；把“非 0 即失败”套到只列部分失败码的 switch，会把源端判为成功的码当失败。来源中写者已意识到“顺序可能不同”仍放行，按无符号写比较却在注释里称与 Java 一致，并从相邻方法复制了 result !== 0。

## 做法

1. 源端集合迭代序决定输出时，验收写明按 Java 迭代序，实现用桶序工具复刻（键的 hashCode 与 HashMap 容量、扩容规则），不以插入序或 indexOf 保序替代，也不以“HashMap 本来无序”放过。
2. byte 与 int 字面量比较前把 0–255 的值换回 -128..127；用 0x80–0xFF 的样例核对与源码同样恒真或恒假。
3. 实现返回码分支时逐值对照源 switch：只把源码列出的 case 判失败，其余走 default 分支。
