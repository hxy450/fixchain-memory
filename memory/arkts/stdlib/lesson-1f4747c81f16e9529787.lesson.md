# 源端 HashSet/HashMap 的迭代序决定输出文件、尝试或写入顺序时，按 Java 桶序复刻，不用 JS Set/Map 插入序

ID：`lesson-1f4747c81f16e9529787` · 版本：2

[本主题](index.md)

## 何时使用

规格提取与切片实现阶段，转写依赖 Java 集合迭代序（keySet、values、toArray、new ArrayList<>(set)）的逻辑时

## 适用情境

源端用 HashSet/HashMap 的迭代序决定输出文件、尝试顺序、写入顺序或问题清单顺序；目标准备用 JS Set/Map（插入序）或 indexOf 保序替代。

## 例外与边界

- 规格或决策明确不要求复刻集合迭代序，并在验收中写明
- 源端用 LinkedHashSet/LinkedHashMap 或 TreeMap 等有序集合时，按其插入序或键序实现，不套桶序

## 原因

JS Set/Map 按插入序迭代，Java HashSet/HashMap 按哈希桶序（由键的 hashCode、扰动函数、容量与扩容决定）；用插入序替代会改变可观察的输出与尝试顺序。“HashMap 本来无序”只说明源端不该依赖顺序，源端已经依赖时迁移仍要保留。

## 做法

1. 验收写明按 Java 迭代序；实现用桶序工具复刻（键的 hashCode、HashMap 的扰动函数、容量与扩容规则），不以插入序或 indexOf 保序替代，也不以“HashMap 本来无序”放过。
