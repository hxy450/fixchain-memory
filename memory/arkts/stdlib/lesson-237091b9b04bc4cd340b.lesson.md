# Java 文本读行、split/trim、BOM、String.format 与 Calendar 周规则不用同名 JS API 近似：按 Java 语义集中实现一组兼容函数

ID：`lesson-237091b9b04bc4cd340b` · 版本：1

[本主题](index.md)

## 何时使用

页面转换和服务/VM 抽取阶段，把 Java 标准库的读行、切分、去空白、解码、数值格式化与日历计算翻译成 ArkTS 时

## 适用情境

源码用 BufferedReader.readLine、String.split/trim、FileReader/InputStreamReader、String.format("%.2f", float) 或 Calendar.getInstance() 的 WEEK_OF_YEAR 处理文件行、编辑框文本、百分比与日期；目标准备用 JS 的 split/trim/toFixed、TextDecoder 或手写 ISO 周换算；派工可能写“与 readFileLineByLine 等价”“数值域同 Android”。

## 原因

同名 API 语义不同：Java readLine 在最后一个终止符后不产生空行、split 丢弃末尾空串，JS split 保留；Java trim 只去 ≤U+0020，JS trim 还去 NBSP、U+FEFF；TextDecoder 默认丢掉 BOM，Java 读取器把它当普通字符；String.format 按 float、HALF_UP 与默认 Locale 输出小数点（fr、it 等为逗号），toFixed 不是；Calendar 的周首日与首周最少天数随区域变化，不等于 ISO。来源中这些近似分散在多个页面，又被服务抽取原样搬运：以换行结尾的文件多出空行、扇区文本被判为 5 行而报错、差异百分比丢了区域小数点、生产周的起止日偏移。

## 做法

1. 在服务层集中实现一组 Java 兼容函数（readLines、split、trim、decode、formatFixed 等），所有服务、VM 与页面统一调用，不在各处各写近似实现。
2. readLine 按 \n、\r、\r\n 断行且最后一个终止符后不产生空行；split 丢弃末尾空串；trim 只去 ≤U+0020；解码保留 BOM 字符。
3. String.format("%.Nf", float) 按 float 运算、HALF_UP 舍入，并按默认 Locale 输出小数点与数字；Calendar.getInstance() 或 SimpleDateFormat(..., Locale.getDefault()) 按区域的 firstDayOfWeek 与 minimalDaysInFirstWeek（如 i18n Calendar）计算。

## 可选检查

- 最小样例：内容为 "a\nb\n" 的文件按行读取应得 ["a","b"]；以换行结尾的文本 split 后不多出末尾空串
