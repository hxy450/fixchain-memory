# Java 读行、split、trim 与文本解码迁到 ArkTS 时按 Java 语义集中实现兼容函数，不用同名 JS API 近似

ID：`lesson-237091b9b04bc4cd340b` · 版本：3

[本主题](index.md)

## 何时使用

页面转换和服务/VM 抽取阶段，把 Java 的 BufferedReader.readLine、String.split、String.trim 与 FileReader/InputStreamReader 解码翻译成 ArkTS 时

## 适用情境

源码用 readLine 循环读文件行，用 split/trim 处理编辑框或文件文本，用 Reader 解码文件；目标准备用 JS 的 split/trim、按 \n 断行或 TextDecoder；派工可能写“与源端读行函数等价”。多个页面与服务都要用这些调用。

## 原因

同名 API 语义不同：Java readLine 按 \n、\r、\r\n 断行，最后一个终止符后不产生空行；String.split 的参数是正则，limit 缺省或为 0 时丢弃末尾空串，JS split 保留；Java trim 只去 ≤U+0020 的字符，JS trim 还去 NBSP、U+FEFF；Java Reader 把 BOM 当作普通字符保留，TextDecoder 可能把它去掉。近似实现分散在各页面，服务抽取时又被原样搬运，以换行结尾的文本会多出空行或空段，行数判定随之出错。

## 做法

1. 在服务层集中实现一组 Java 兼容函数（readLines、split、trim、decode 等），服务、VM 与页面统一调用，不在各处另写近似实现。
2. readLines 按 \n、\r、\r\n 断行，最后一个终止符后不产生空行；trim 只去 ≤U+0020 的字符；decode 的结果保留 BOM 字符 U+FEFF（核对所用解码器的 BOM 选项）。
3. split 按 Java String.split 语义（android-36.1 String.java 说明）：参数按正则解释，“.”“|”等元字符要转义才是字面量；limit 缺省或为 0 时丢弃末尾空串，limit 为负时保留全部空串，limit 为正时最多切成 limit 段、最后一段保留剩余全部内容。

## 可选检查

- 最小样例：内容为 "a\nb\n" 的文件按行读取得 ["a","b"]；"a\nb\n" 按 Java split("\n") 得 ["a","b"]，split("\n", -1) 得 ["a","b",""]
