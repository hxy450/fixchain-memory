# 源端 SimpleDateFormat/Calendar 未指定时区或区域时，按默认时区与区域语义复刻：时刻取本地字段，周规则随区域

ID：`lesson-91c60cb726d59b315d33` · 版本：2

[本主题](index.md)

## 何时使用

规格提取与实现阶段，把 SimpleDateFormat/DateFormat、GregorianCalendar 或 Calendar.getInstance() 的格式化、字段读取与周计算翻译成 ArkTS 显式算术或 i18n 调用时

## 适用情境

源码 new SimpleDateFormat(pattern[, Locale]) 或 Calendar.getInstance() 后没有调用 setTimeZone，就格式化一个毫秒值（变量语义可能像时长，如“已用时间 + 偏移小时×3600000”）、读 HOUR_OF_DAY，或格式化固定 epoch 时刻、按本地小时位探测偏移；也包括用 Calendar 的 WEEK_OF_YEAR、firstDayOfWeek 计算周起止。目标准备“不经 Date/Intl”按 UTC 手工拆 h/m/s，或手写 ISO 周换算。

## 例外与边界

- 源端显式 setTimeZone 或传入固定时区、固定 Locale：按该显式配置实现

## 原因

未 setTimeZone 的 formatter/Calendar 在构造时绑定默认时区，format 与字段读取输出该时区的本地字段；按 UTC 拆 h/m/s 只在偏移为 0 的时区与源端一致。用当前 getRawOffset 代替对历史时刻的探测，会丢掉该时刻的历史偏移与夏令时。Calendar 的周首日与首周最少天数随区域变化，不等于 ISO 8601；以“确定性”为由改成 ISO，周起止日会偏移。

## 做法

1. 把未 setTimeZone 的 format 输入当作时刻，即使变量语义像时长：在源端构造时机用 i18n.getTimeZone() 取默认时区，local = instant + tz.getOffset(instant)（@ohos.i18n TimeZone.getOffset，含夏令时），再拆 HH/mm/ss。
2. “格式化固定 epoch 的本地小时位”一类偏移探测，用 tz.getOffset(该时刻毫秒值) 复刻，不用当前 getRawOffset。
3. Calendar.getInstance() 或按 Locale.getDefault() 构造的日期计算按区域周规则：从 i18n.getCalendar(当前区域) 取 getFirstDayOfWeek() 与 getMinimalDaysInFirstWeek()，不改用 ISO 周；确需固定语义时写入决策台账待批，不只写在注释或源码笔记里。
4. 时间显示类验收至少给一个非零偏移时区的样例；规格写成“纯时长格式化”“不经 Date/Intl”而源端 formatter 没有 setTimeZone 时，按源端实现并回报规格。

## 可选检查

- UTC+8 时区下把毫秒值 0 交给未 setTimeZone 的 HH:mm:ss 格式化，结果为 08:00:00，不是 00:00:00。
