# 源端单调计时（System.nanoTime）映射到 systemDateTime.getUptime：不写未经 SDK 核实的 performance.now，也不退回会随校时跳变的 Date.now

ID：`lesson-ce456d60534d97524aa4` · 版本：1

[本主题](index.md)

## 何时使用

规格提取阶段为 System.nanoTime 等源端系统计时 API 选目标 API 时；实现或编译修复阶段，时钟映射在当前 SDK 中不存在、需要换时钟源时

## 适用情境

源端帧动画或计时用 System.nanoTime（CLOCK_MONOTONIC）求帧间隔与进度；目标 ArkTS 把时钟封装在单点函数里，规格映射写了 Web API（performance.now），构建报找不到符号或 Kit 无导出。

## 原因

来源工程的 SDK 中没有可导入的 performance，按记忆写的 Web API 把时钟选择推到了编译门；编译门凭印象把 systemDateTime 判为墙钟，换成 Date.now 后单调语义丢失，系统校时会让帧间隔回拨或跳变。systemDateTime.getUptime 自 API 10 提供不受校时影响的开机时长，并以 TimeType 区分是否计入深睡眠。

## 做法

1. 规格映射计时 API 时写清所需语义（单调、是否计入深睡眠、精度），并以项目 SDK 的 d.ts 作为目标 API 存在的依据；System.nanoTime 对应 systemDateTime.getUptime(systemDateTime.TimeType.ACTIVE, true)（@kit.BasicServicesKit，纳秒）再换算毫秒。
2. 编译门遇到时钟 API 不存在时，按原调用注释与规格写明的语义在本地 ets/api 与 kits 的 d.ts 中检索候选（getUptime、TimeType、monotonic），读完声明再排除；只剩语义不同的替代时不在门内落地，作为决策缺口回报。
