# 源端单调计时映射到 getUptime 并按是否计入深睡眠选 TimeType，不用 performance.now 或 Date.now

ID：`lesson-ce456d60534d97524aa4` · 版本：3

[本主题](index.md)

## 何时使用

规格提取阶段为 System.nanoTime、SystemClock.elapsedRealtime 等源端系统计时 API 选目标 API 或写平台差异时；实现或编译修复阶段，时钟映射在当前 SDK 中不存在、需要换时钟源时

## 适用情境

源端帧动画或计时用 System.nanoTime（CLOCK_MONOTONIC）求帧间隔与进度；目标 ArkTS 把时钟封装在单点函数里，规格映射写了 Web API（performance.now），构建报找不到符号或 Kit 无导出。也包括后台计时用 elapsedRealtime（计入深睡眠）记录起点与偏移，规格准备映射为墙钟，并写“平台未开放跨休眠单调时钟”。

## 原因

SDK 的 ets/api 与 kits 声明里没有可导入的 Web performance 对象（本机 API 23 SDK 核实，只有构建工具自带的 TypeScript lib 里有），凭记忆写 performance.now 只会在构建时报找不到符号；Date.now 是墙钟，系统校时会让帧间隔回拨或跳变。systemDateTime.getUptime 自 API 10 提供不受校时影响的开机时长，并以 TimeType 区分是否计入深睡眠（STARTUP 计入、ACTIVE 不计入）。

## 做法

1. 规格映射计时 API 时写清所需语义（单调、是否计入深睡眠、精度），并以项目 SDK 的 d.ts 作为目标 API 存在的依据，记下 @since 并对照 compatibleSdkVersion。System.nanoTime 对应 systemDateTime.getUptime(systemDateTime.TimeType.ACTIVE, true)（@kit.BasicServicesKit，纳秒），再换算毫秒；计入深睡眠的 SystemClock.elapsedRealtime 对应 getUptime(systemDateTime.TimeType.STARTUP)。
2. 编译门遇到时钟 API 不存在时，按原调用注释与规格写明的语义，在本地 ets/api 与 kits 的 d.ts 中检索候选（getUptime、TimeType、monotonic），读完声明再排除；只剩语义不同的替代时不在门内落地，作为决策缺口回报。
