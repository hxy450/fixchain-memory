# 不能编译的生成批次写 SDK 调用前，按本地 .d.ts 核对成员名、所属类型、调用链每一跳与返回可空性

ID：`lesson-6e558834938be19c04e2` · 版本：1

[本主题](index.md)

## 何时使用

页面或组件实现阶段，在禁止编译的转换批次里写组件构造选项、属性方法参数、需实现的 SDK 接口，或 UIContext、状态存储一类调用时

## 适用情境

转换派工禁止编译或构建，映射参考与规格只给组件、接口名而不给成员签名；写者准备凭记忆填写选项字段名、参数类型、接口方法名或链式调用，或只看到一行 grep 命中的声明；本机 SDK 的 ets/component、ets/api 下 .d.ts 可以读取。

## 原因

禁编译只推迟错误，不会消除错误：记忆中的字段名、接口成员名与所属类型常与当前 SDK 不符，写后自检若只核 API 版本号或链尾方法，不存在的字段、错误的接口成员、并不存在的中间一跳和可空返回都会留到编译门；业务页尚未接入可达图时，常规构建还会跳过这些文件。来源同一批并行转换者分别写出菜单项的 startImage、Slider.blockSize(number)、IDataSource.getTotalCount()、UIContext.getResourceManager()、UIContext 上的 openMenu/closeMenu、AlertDialog 参数里的 builder，并直接使用 AppStorageV2.connect 的返回值；其中有人写前已自述没把握，有人 grep 到声明行就按文件名推定了所属类型。

## 做法

1. 对本文件新引入、且未在已编译代码里出现过的每个 SDK 成员，写前在 SDK 的 ets/component/*.d.ts 或 ets/api/*.d.ts 找到声明，确认成员名、选项对象字段与必填项、参数类型和返回类型；有知识核验 skill 时也可以用它。禁止编译不等于禁止读声明。
2. grep 命中声明行后向上找到最近的 class/interface，确认成员属于哪个类型；同一个 d.ts（如 @ohos.arkui.UIContext.d.ts）包含多个类，不按文件名推定归属。链式调用逐跳核对，例如组件内解析字符串资源走 getUIContext().getHostContext()（可能为 undefined，先判空）再取 resourceManager.getStringSync，UIContext 本身没有 getResourceManager()。
3. 声明返回 T | undefined 的接口先判空再读写，AppStorageV2.connect 即使传了 defaultCreator 也一样；实现 ambient 接口时按接口体逐个成员实现，例如 LazyForEach 的 IDataSource 用 totalCount()、getData()、registerDataChangeListener()、unregisterDataChangeListener()，调用点统一用接口成员名。
4. 来源已确认的记忆误写可直接对照：MenuItem 选项的图标字段是 startIcon；Slider.blockSize 接受 SizeOptions（{ width, height }）；AlertDialog 参数没有 builder 字段且 message 必填。写后自检按实际输出逐个复核新写的 SDK 调用，不只核 API 版本号。
