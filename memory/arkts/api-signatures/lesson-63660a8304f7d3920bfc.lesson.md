# 传给 ArkUI 属性方法的值按其实际重载定型，不传 string | Resource 联合值

ID：`lesson-63660a8304f7d3920bfc` · 版本：3

[本主题](index.md)

## 何时使用

规格提取阶段定义页面派生状态的类型，或页面实现阶段把派生状态接到 ArkUI 组件属性方法时；批量横切改动中把其他页面的修饰链模板复用到本文件时

## 适用情境

源端文本属性（如 contentDescription）的值一部分来自字符串资源、一部分来自运行时拼出的字符串，迁移时准备用一个派生状态（getter / @Computed）同时承载 Resource 与 string，再传给属性方法（如 accessibilityText）。也包括数据类字段为方便声明成 ResourceStr（实际各分支都赋 $r() 资源），再把字段传给 accessibilityText 一类只有分开 string/Resource 重载的属性方法；以及跨文件复用修饰链时，参照页面的字段是 Resource，本文件对应字段却声明为 ResourceStr。

## 例外与边界

- 目标方法在当前 SDK 声明中有参数类型覆盖整个联合的重载（例如参数声明为 ResourceStr），此时可直接传入

## 原因

TypeScript 按单个重载逐一匹配实参；属性方法若只分别声明 (value: string) 与 (text: Resource)，string | Resource 的实参哪个都不匹配，ArkTS 编译报 10505001 No overload matches this call。来源中 accessibilityText 就只有这两个分开的重载：规格把联合类型写进状态接口，实现者凭“它接受 ResourceStr”的记忆照搬，在禁止编译的生成批次里留到首道编译门才暴露。另一应用的列表骨架把次级动作的 label 声明为 ResourceStr、各分支都赋 $r()，传给 accessibilityText 时同样报无匹配重载；映射参考只给了 String → String 的示例。第三个应用在统一替换提示的批量改动中，把 Resource 字段页面的 .accessibilityText(this.toastMessage) 模板照搬到 messageText: ResourceStr 的页面，写前已读到该字段类型；构建入口又因无关的前置校验中止，改动没有编译就交付。

## 做法

1. 定型前在本地 SDK 的组件声明（ets/component/*.d.ts）里查该方法的全部重载；只有分开的 string 与 Resource 重载时，让派生状态只返回其中一种类型，并在规格的转换决策里写明取值方式。
2. 资源串与动态串需要共存时，在 getter 内归一成 string：资源分支经 UIContext 取宿主 context，用 resourceManager.getStringSync($r('app.string.<名>').id) 解析，context 不可用时给出明确回落值；示意 get label(): string { return rolled ? String(n) : ctx.resourceManager.getStringSync($r('app.string.x').id) }。
3. 在不编译的生成批次，把凭记忆得出的签名结论（“某方法接受联合类型/ResourceStr”）与其他待核 API 一起列入写码前的 .d.ts 核对，不单独豁免。
4. 字段所有赋值都是 $r() 资源时，直接把字段声明为 Resource；都是运行时字符串时声明为 string；不为省事写成 ResourceStr 再传给分开重载的属性。
5. 把别的文件的修饰链模板复用到本文件前，按本文件实参的声明类型核对重载；字段必须保持 ResourceStr 时，先用 typeof 收窄为 string 或 Resource 再分别调用，不沿用 Resource 字段页面的写法。
