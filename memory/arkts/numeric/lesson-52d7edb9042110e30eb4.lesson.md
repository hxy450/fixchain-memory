# 迁移比值与进度计算时保留源端的零分母分支与范围钳制：ArkTS number 除法不抛错，0/0 得 NaN

ID：`lesson-52d7edb9042110e30eb4` · 版本：1

[本主题](index.md)

## 何时使用

服务或业务逻辑实现阶段，把源端带保护的比值、进度计算改写或内联到目标回调并写入共享状态时

## 适用情境

源端用辅助方法计算 completed/total，其中含 total==0 分支与 coerceIn(0,1) 一类钳制；目标把计算内联进进度回调，直接以 current/total 写入 0..1 语义的共享状态。

## 原因

Kotlin 源端把保护写在辅助方法里，内联时容易只搬除法；ArkTS number 除法 0/0 为 NaN、x/0 为 Infinity，不抛异常，会直接写进进度状态。来源中实现者读到了带零分母分支与钳制的源函数，内联后两者都丢失，验证期单测以 0/0 才发现；修复按测试期望回落 0，而源端对零分母返回 1。

## 做法

1. 内联或改写比值计算时，把源端的零分母分支与钳制一起移到写入共享状态之前：total>0 才相除并钳制到 [0,1]；零分母的返回值按源端语义或已确认的规格决定，并在注释中说明取舍。
2. 写源码笔记时把边界保护（零分母、钳制、空集合）列为行为要点，不只记调用接线。
