# 路由参数类及其基类放进不导入页面的叶子模块，避免路由层与页面循环导入使 extends 读到未初始化的类

ID：`lesson-060a67da4cdf63d03b19` · 版本：1

[本主题](index.md)

## 何时使用

功能切片实现与跨文件接线阶段，决定路由参数类放在哪个模块、路由封装与页面之间的 import 方向，或为满足结构检查新增 import 并 extends 时

## 适用情境

NavRouter 一类路由或服务层需要构造某页面的参数类，规格又规定页面经路由层导航或继承路由层定义的参数基类；参数类当前写在页面 .ets 里，页面之间也互相引用参数类。

## 原因

ArkTS 编译与结构检查都允许循环导入、不检查模块初始化顺序；extends 与顶层静态初始化在模块求值期就要被引用类的运行时值。路由层 import 页面、页面又经他页回 import 路由层时，先被加载的一方求值时读到尚未初始化的类，启动即抛 ReferenceError（X is not initialized）。按当前快照判断“暂时无环”或“已有环无妨”，后续接线会把环闭合。

## 做法

1. 路由层要构造或多页共用的参数类（含参数基类）放进 routing/ 下不 import 任何页面的叶子模块；路由与服务模块不 import 页面模块，页面需要他页参数类时也从叶子模块导入。
2. 判断是否成环时把规格或切片计划里的页面→路由依赖一并算入，不以“编译通过/当前无环”放行。
3. 新增 import { X } from M 并让本文件的类 extends X（或在顶层静态初始化中使用 X）前，查 M 的 import 是否直接或间接引回本文件；是就先把 X 移到叶子模块，或改用不需继承的满足方式。
