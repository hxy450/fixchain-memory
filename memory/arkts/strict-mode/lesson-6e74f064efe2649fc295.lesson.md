# SDK 把观察者或回调类型声明为 class 时不写 implements：用以该类型标注的对象字面量传入

ID：`lesson-6e74f064efe2649fc295` · 版本：1

[本主题](index.md)

## 何时使用

实现或修复阶段，为 errorManager.on('error') 一类需要观察者对象的系统 API 确定观察者的声明形态时

## 适用情境

要传给 SDK 的观察者或回调参数在 d.ts 中声明为 class（如 application/ErrorObserver.d.ts 的 export default class ErrorObserver），写者按 TS 习惯准备用 class 实现它；生成或修复 worker 可能被要求不自行编译。

## 原因

ArkTS 的 implements 只接受 interface（arkts-implements-only-iface），TS 中“class 可当接口被 implements”的写法会编译失败；arkts-no-untyped-obj-literals 要求字面量有显式 class/interface 类型，并不禁止字面量。worker 不编译时，这类错误会留到下一轮编译门。

## 做法

1. 写观察者前先在 d.ts 看该类型是 interface 还是 class；是 class 时写成以该类型标注的对象字面量，例如 const observer: errorManager.ErrorObserver = { onUnhandledException: (errMsg: string): void => {...}, onException: (errObject: Error): void => {...} }，再把 observer 传给 errorManager.on('error', observer)，持有它的字段也标注为 SDK 类型。
2. 是 interface 时可以 implements，也可以用同样的类型化对象字面量。
