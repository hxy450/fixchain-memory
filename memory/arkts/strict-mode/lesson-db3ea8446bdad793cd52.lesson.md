# 新建且尚未被页面或 Ability 导入的 .ets 文件不进入全量编译：落盘后接一处导入或单独做 ArkTS 检查，再报告构建通过

ID：`lesson-db3ea8446bdad793cd52` · 版本：1

[本主题](index.md)

## 何时使用

编码阶段新建令牌、常量、工具或模型文件，或并发 worker 被要求不跑全量构建，准备以构建通过为依据报告完成时

## 适用情境

新写的 .ets 文件还没有被任何页面、组件或 Ability 导入（如先建主题令牌类、之后再接线）；全量构建按入口的导入关系编译，构建日志显示通过。

## 原因

构建只编译从入口页面与 Ability 可达的文件；未接线文件里的严格模式错误（无类型字面量、索引签名等）不会出现在本次构建结果里，要到第一次被导入时才暴露。

## 做法

1. 新文件落盘后，临时在一个已编译页面里导入并使用它，或对该文件单独做一次 ArkTS 检查，再据结果报告通过。
2. 回报时写明哪些新文件尚未接入可达图、是否已单独检查，不以全量构建通过覆盖它们。
