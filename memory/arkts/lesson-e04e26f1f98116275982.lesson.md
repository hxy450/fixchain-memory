# 不能编译的整页生成，写后把引用的常量与 this 成员逐一对照声明；源端局部派生值改为经持有对象访问

ID：`lesson-e04e26f1f98116275982` · 版本：1

[本主题](index.md)

## 何时使用

页面实现阶段，在禁止编译的条件下一次写出大型 ArkTS 页面并做写后自检时

## 适用情境

整页由一次写入生成，常量区与状态区由写者自拟；源码在方法里用局部派生值（如 isX = current instanceof Y）控制菜单显隐，目标把该对象建模为可空状态；设计里决定的尺寸以具名常量在调用点引用。

## 原因

一次生成大文件时，调用点引用的具名常量可能从未写进常量区，源端局部变量名也可能被写成组件成员 this.isX；括号平衡、禁用词、装饰器版本、占位登记这类自检都查不出未声明标识符，错误要到首次编译才出现。来源两处缺陷都在首次写入里，不是后续编辑被截断。

## 做法

1. 写后提取文件中所有 this.<名> 与大写常量引用，与 const、@Local/@Param/private 等声明做差集；差集非空就补定义或改引用。
2. 源端局部派生值迁到模型字段后，每个使用点写成经空值判断的持有对象访问（this.<对象> !== null && this.<对象>.<字段>），或显式声明同名 getter；不把源局部变量名直接当成组件成员。
3. 设计中决定用具名常量表示的尺寸（如按钮命中区），在写调用点的同一次写入里加入常量区。
