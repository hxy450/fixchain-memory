# BuildConfig.DEBUG 映射为 hvigor 生成的 BuildProfile.DEBUG，不因源码目录检索不到就删 DEBUG 分支

ID：`lesson-3af52968ce5762501cd3` · 版本：3

[本主题](index.md)

## 何时使用

实现与收口阶段，把源端含 BuildConfig.DEBUG 的可见性或行为条件转换为 ArkTS 时

## 适用情境

目标为 hvigor 构建的工程，源码目录内尚无 BuildProfile 引用，模块根目录也没有 BuildProfile.ets；规格或已批准决策写着“DEBUG 构建 || X”一类条件。

## 例外与边界

- 代码位于 HAR 模块时，用 HAR 自己的 BuildProfile：import BuildProfile from './BuildProfile'（文件生成在 HAR 模块根目录，经 Build > Make Module 或 hvigorw GenerateBuildProfile 生成，同样含 DEBUG），不必由壳层入口注入（HarmonyOS 文档 ide-hvigor-get-build-profile-para-guide，访问于 2026-10-17）

## 原因

生成文件位于构建产物目录，只在源码目录检索不到就判定“无构建标志”，会删掉 DEBUG 条件分支；签名策略与构建类型无关，不能作为删除理由。

## 做法

1. 使用 import BuildProfile from 'BuildProfile' 的 BuildProfile.DEBUG（debug 构建为 true，默认生成，无需修改 build-profile.json5）。HSP 中改用 import BuildProfile from '${packageName}/BuildProfile'（packageName 取模块 oh-package.json5 的 name），裸名在跨包集成 HSP 时可能编译报错；DEBUG 的文档语义是“应用是否可调试”，需按编译模式区分时读 BUILD_MODE_NAME（HarmonyOS 文档 ide-hvigor-get-build-profile-para-guide，访问于 2026-10-17）。

## 可选检查

- 接手他人留下的“DEBUG 无等价”注释时，核对对应表达式是否真的包含 DEBUG 分支
