# 页面与组件共用的非 UI 函数放进普通模块：不从路由页面模块具名导出供生产代码导入

ID：`lesson-b58f26f0fdb7fb00db9e` · 版本：1

[本主题](index.md)

## 何时使用

界面实现阶段，新组件或弹窗要复用某个页面文件里的校验、工具函数，决定函数放在哪个模块、从哪里导入时

## 适用情境

可复用的非 UI 函数（正则校验、提交前校验链等）定义在 pages/ 下经路由表或 pageMap 注册的页面模块中，该页面可能已为单测导出个别函数；新组件会被主 Ability 首页静态导入，工程同时带有 entry_test 单测或 UI 测试 HAP。

## 例外与边界

- 函数本来就定义在 services/、utils/ 等非页面模块中

## 原因

页面模块的具名导出在主应用里能编译、运行，但在 UI 测试进程中（主 HAP 与测试 HAP 的模块记录同时加载）出现过“does not provide an export name”的启动崩溃；两种构建 flavor 都编译通过，问题直到跑 UI 套件才暴露。来源中写者已读到该页面的导出注释为“供 UT 消费的最小导出 seam”，工程另有 services/ 存放共享逻辑，仍为复用把页面里的私有函数改成导出，并让弹窗组件从页面模块导入。确切的绑定机理是修复者推断，未单独复现；可确定的是迁到普通模块后套件不再崩溃。

## 做法

1. 复用页面里的非 UI 函数时，先把函数原样迁到普通模块（如 services/、utils/），页面和新组件都从该模块导入；不为复用给路由页面模块新增具名导出，组件也不从页面模块导入函数。
2. 页面模块里标注“供单测使用”的导出只当测试接缝；生产代码需要时同样先迁出，单测的导入路径同步改到新模块。

## 可选检查

- 改动页面模块的导出或新增“组件→页面模块”导入后，能上设备时冒烟一个会拉起主 Ability 的 UI 套件；本轮不跑真机时在交付说明里注明“UI 测试进程加载未验证”。
