# 页面迁入或在 HAR 之间移动时带走资源闭包：静态 $r 与按名取资源都要在本模块或已声明依赖中可解析

ID：`lesson-edb937b04e0f1494ca37` · 版本：1

[本主题](index.md)

## 何时使用

架构重构或模块拆分阶段，把页面迁入 HAR 或在 feature 间移动页面、确定字符串/媒体/颜色资源归属时；在 HAR 页面把按名取资源改写为静态 $r 时

## 适用情境

多模块工程（壳 HAP + HAR）里页面或组件移入某个 HAR；页面用 $r('app.string/media/color.x') 或 getStringByNameSync/localized('x') 使用资源，定义可能仍只在壳模块、AppScope 或另一个 feature；整包构建会合并资源，只有按模块分析才报 Unknown resource name。

## 原因

整包构建与真机运行会合并各模块资源，资源留在壳或另一个 feature 时编译、安装都正常，IDE 单独分析该 HAR 才报错，用 assembleHap 和真机一跳验收发现不了。来源中抽取设置页时资源扫描只匹配静态 $r，漏掉按名取的文案；之后把按名取改写为 $r 时，写者已查到某名称只在壳模块、也为另两个名称建了模块自有资源，却仍在同一补丁写了壳里的名称；另一次把详情页迁到其他 feature 时，迁移清单只列代码层，没有列资源。

## 做法

1. 迁移前以页面（及直接组件）为单位列资源闭包：静态 $r 名称与按名取资源的字面量都算；逐个确认定义在目标 HAR 或其 oh-package.json5 声明的依赖里；只在壳、AppScope 或未依赖模块中的，按本模块命名复制或迁入，并补齐各语言限定目录。
2. 在 feature 间移动页面时，把 element 条目与 media 文件列入同一迁移清单，与代码一起搬；声明了禁止新增某依赖时，把被引用资源迁到本模块，不靠整包合并兜底。

## 可选检查

- 不确定时逐模块比对：抽取每个 HAR 的 $r 名称，与该模块及其声明依赖的资源并集比对，缺失即不通过；或按模块单独构建该 HAR。
