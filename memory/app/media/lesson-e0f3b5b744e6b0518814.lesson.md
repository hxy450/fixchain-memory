# 把任意长度内容保存为图片时不靠单次离屏快照：先查快照尺寸限制，内容可能超过一屏就按视口分段渲染再拼接，并校验输出高度

ID：`lesson-e0f3b5b744e6b0518814` · 版本：1

[本主题](index.md)

## 何时使用

界面实现阶段，为“保存完整长内容为图片”或分享长图选择截图、离屏渲染方案时

## 适用情境

源端按内容总高度创建 Bitmap 后整体绘制（如 getBitmapFromView、Canvas.draw），高度随文本无上限增长；目标拟用 componentSnapshot.createFromBuilder 等单次快照，Builder 根组件只定宽、高度随内容撑开。

## 例外与边界

- 内容高度有明确上限且不超过一屏时，可以单次快照

## 原因

离屏渲染不等于不受尺寸约束：SDK 文档的 SnapshotOptions 说明快照不建议超过屏幕尺寸，超过底层限制会失败，且因设备而异。源端整图绘制没有这层限制，单次快照却可能把超长内容截断。来源中截断究竟来自像素上限还是离屏根布局约束未经日志确认，最终分段方案也未经设备验证；两种机制下单次无界快照都不可靠。

## 做法

1. 选定 createFromBuilder/componentSnapshot 前，在项目指定的 SDK 离线文档中查 SnapshotOptions 等尺寸限制说明，把最长内容当作验收边界，不按“离屏”字面推断不受尺寸限制。
2. 内容可能超过约一屏时，按固定视口高度分段渲染（每段平移内容），再用 readPixels/writePixels 拼成一张 PixelMap；先比较单次快照的像素高度与内容实测高度，不一致才走分段。
3. 测量内容自然高度的副本放在主轴不限测量的容器（如 Scroll）中，不放在受父容器可用高度约束的 Stack/Column 里，否则测得的也是被夹紧的高度，校验永远“一致”。

## 可选检查

- 校验与分段两条路径都打日志，用超过一屏的真实长文本保存一次，核对输出图片高度与内容高度一致。
