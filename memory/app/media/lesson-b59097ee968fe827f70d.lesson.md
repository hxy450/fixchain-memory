# 源端写公共目录并做媒体扫描的产物，目标改落沙箱后每条链路都要写出用户可见的导出步骤

ID：`lesson-b59097ee968fe827f70d` · 版本：1

[本主题](index.md)

## 何时使用

规格提取阶段，把源端下载或导出产物的落点及“沙箱 + picker 导出”替代方案映射到各条业务链时；实现者把公共目录换成沙箱路径时

## 适用情境

源端申请 WRITE_EXTERNAL_STORAGE 写公共目录并发 ACTION_MEDIA_SCANNER_SCAN_FILE，使产物在文件管理或媒体库中可见；目标不申请媒体权限，改为下载到应用沙箱；同一功能中可能只有某一条链写了 DocumentViewPicker 导出。

## 原因

沙箱文件对用户不可见，“下载成功”提示仍会出现，用户却找不到文件。替代方案若只写进一条链，移除媒体扫描的理由（“picker 保存后可见”）对其他链并不成立。

## 做法

1. 规格逐条链标注产物的用户可见性：源端写公共目录并做媒体扫描即为用户可见；目标改落沙箱时，在该链的数据流、服务接口和验收里写出导出步骤（如 DocumentViewPicker.save），以及成功、取消、失败时的提示与入库时点。
2. 移除媒体扫描等平台调用前，确认替代理由所引用的步骤确实存在于同一条链；同一决策覆盖多条链时逐链核对。
3. 实现者换成沙箱路径时核对源端的可见性语义；规格缺导出步骤就上报缺口，不在注释里写成“沙箱等价”。
