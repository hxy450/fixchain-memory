# 源端写到公共目录、对用户可见的产物（媒体扫描的导出文件、公共 Documents 下的日志等），目标改落沙箱时每条链路写出导出步骤或可见落点

ID：`lesson-b59097ee968fe827f70d` · 版本：2

[本主题](index.md)

## 何时使用

规格提取阶段，把源端下载或导出产物的落点及“沙箱 + picker 导出”替代方案映射到各条业务链时；实现者把公共目录换成沙箱路径时；规格为日志目录等横切副作用写落点验收时

## 适用情境

源端申请 WRITE_EXTERNAL_STORAGE 写公共目录并发 ACTION_MEDIA_SCANNER_SCAN_FILE，使产物在文件管理或媒体库中可见；目标不申请媒体权限，改为下载到应用沙箱；同一功能中可能只有某一条链写了 DocumentViewPicker 导出。 也包括源端日志库把文件写到公共 Documents 下的子目录（没有媒体扫描，但在文件管理中可见），规格同一文件里映射表写“用户文件目录”、验收条目写“应用沙箱”。

## 原因

沙箱文件对用户不可见，“下载成功”提示仍会出现，用户却找不到文件。替代方案若只写进一条链，移除媒体扫描的理由（“picker 保存后可见”）对其他链并不成立。

## 做法

1. 规格逐条链标注产物的用户可见性：源端写公共目录（含做媒体扫描的导出、公共 Documents 子目录）即为用户可见；目标改落沙箱时，在该链的数据流、服务接口和验收里写出导出步骤（如 DocumentViewPicker.save）或用户可见落点，以及成功、取消、失败时的提示与入库时点。
2. 移除媒体扫描等平台调用前，确认替代理由所引用的步骤确实存在于同一条链；同一决策覆盖多条链时逐链核对。
3. 实现者换成沙箱路径时核对源端的可见性语义；规格缺导出步骤就上报缺口，不在注释里写成“沙箱等价”。
4. 同一规格里映射表与验收条目对落点说法不一致时，回源码判定落点与可见性，把选定落点和可见性降级（如有）写进同一条验收；实现者遇到这种冲突同样回源码决定，不任选一条执行。
