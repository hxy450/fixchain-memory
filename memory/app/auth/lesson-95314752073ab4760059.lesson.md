# 三方授权回调先按 state 判定是否属于当前请求：不匹配就忽略，不把上一请求的迟到回调判为当前会话失败

ID：`lesson-95314752073ab4760059` · 版本：1

[本主题](index.md)

## 何时使用

第三方登录实现阶段，编写 SDK 授权回调的请求归属判断与失败处理时

## 适用情境

登录服务同一时刻只保留一个待处理授权会话，每次请求生成随机 state（或 requestId）随 SDK 请求发出；用户取消、超时或离开后可以重新发起，上一请求的回调可能在新会话等待期间到达；规格写有“state 错配拒绝”“新授权开始时旧回调必须失效”。

## 原因

把 state 当成响应内容的校验项、不一致就抛错并结束会话，旧请求的迟到回调就会把新请求判为失败；“旧回调失效”的含义是该回调不产生任何效果。来源中规格与 SDK 审计已写明旧回调必须失效，实现仍把 state 错配与错误码、空 code 同样处理，契约测试也只断言了 stale state 被拒。

## 做法

1. 回调入口先用 state 或 requestId 判断是否属于当前待处理请求：不匹配就忽略，让当前会话继续等待，不登录、不判失败、不释放 busy；匹配后才按错误码与 code 判定成功、取消或失败并收口会话。

## 可选检查

- 时序用例：发起 A → 取消或超时 → 发起 B → 投递 A 的回调，断言 B 仍在等待；再投递 B 的回调，B 按自身结果完成。
