## 本级经验

- [三方授权回调先按 state 判定是否属于当前请求：不匹配就忽略，不把上一请求的迟到回调判为当前会话失败](lesson-95314752073ab4760059.lesson.md)
  - 时机：第三方登录实现阶段，编写 SDK 授权回调的请求归属判断与失败处理时
  - 情境：登录服务同一时刻只保留一个待处理授权会话，每次请求生成随机 state（或 requestId）随 SDK 请求发出；用户取消、超时或离开后可以重新发起，上一请求的回调可能在新会话等待期间到达；规格写有“state 错配拒绝”“新授权开始时旧回调必须失效”。
