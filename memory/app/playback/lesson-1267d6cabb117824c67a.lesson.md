# AVPlayer 播放应用包内 rawfile 资源时用 getRawFd(Sync) 的 {fd, offset, length} 设 fdSrc，不把描述符拼成 fd://N?offset= 形式的 url；源端 SoundPool 短音效改用 media.SoundPool，三个字段传给 load

ID：`lesson-1267d6cabb117824c67a` · 版本：2

[本主题](index.md)

## 何时使用

规格提取阶段为音视频资源加载写平台 API 契约时；播放服务实现阶段为 AVPlayer 绑定应用包内 rawfile 资源时；为源端短音效选择目标播放 API 时

## 适用情境

源端用 SoundPool.load(context, R.raw.x) 或 MediaPlayer.create(context, R.raw.x) 播放 res/raw 资源，资源迁到 resources/rawfile：MediaPlayer 与较长音频目标用 AVPlayer，SoundPool 预加载的短音效目标用 media.SoundPool；resourceManager.getRawFd/getRawFdSync 返回整个 HAP 的 fd 加该资源在 HAP 内的 offset/length；AVPlayer 有 url 与 fdSrc（AVFileDescriptor）两种设源方式。 SoundPool.load 有 uri 与 (fd, offset, length) 两种重载。

## 原因

url 的 fd:// 形式只接受整文件的 fd://<数字>，拼上 offset/length 查询串会被判参数错误（401），播放器停在 error 态，音效与音乐全部静默。来源中规格作者凭记忆写“getRawFd → url=fd://”，实现者已读到 d.ts 中 fdSrc 适用于连续存放在同一文件中的资源，仍照规格自造了查询串。 源端 SoundPool 在构造时 load 预解码、事件时 play 即时多路发声；改成每次播放新建 AVPlayer，要先走完 prepare 才出声，延迟明显。

## 做法

1. rawfile 资源写成 const d = resourceManager.getRawFdSync(name); player.fdSrc = { fd: d.fd, offset: d.offset, length: d.length }；只有沙箱里的独立文件才用 fileIo 打开后设 url = 'fd://' + fd。 源端是 SoundPool（构造或初始化时 load、事件时 play、maxStreams 多路叠播）时不改用 AVPlayer：media.createSoundPool(maxStreams, audioRendererInfo) 建池，按源端时机用 getRawFdSync 的结果调 load(d.fd, d.offset, d.length)，事件时 play(soundID)，同样不拼 url；接口见本地 SDK ets/api/@ohos.multimedia.media.d.ts 的 createSoundPool 与 ets/api/multimedia/soundPool.d.ts 的 load、play。
2. 规格写法与写前读到的 d.ts 注释冲突时按 d.ts 实现，并回报规格该行有误。 为源端播放类写映射行前，先按源类名在本地 SDK d.ts 中查目标同类 API（如 createSoundPool），列为候选再写取舍；经验提醒与技能模板给出的目标类只作参考。

## 可选检查

- 首次设备运行看 hilog 不出现 401 或“not a fd://+numeric string”；代码中 getRawFd 的结果不流向 .url。
