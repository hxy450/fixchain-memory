# AVPlayer 播放应用包内 rawfile 资源时用 getRawFd(Sync) 的 {fd, offset, length} 设 fdSrc，不把描述符拼成 fd://N?offset= 形式的 url

ID：`lesson-1267d6cabb117824c67a` · 版本：1

[本主题](index.md)

## 何时使用

规格提取阶段为音视频资源加载写平台 API 契约时；播放服务实现阶段为 AVPlayer 绑定应用包内 rawfile 资源时

## 适用情境

源端用 SoundPool.load(context, R.raw.x) 或 MediaPlayer.create(context, R.raw.x) 播放 res/raw 资源，目标改为 AVPlayer 播放 resources/rawfile；resourceManager.getRawFd/getRawFdSync 返回整个 HAP 的 fd 加该资源在 HAP 内的 offset/length；AVPlayer 有 url 与 fdSrc（AVFileDescriptor）两种设源方式。

## 原因

url 的 fd:// 形式只接受整文件的 fd://<数字>，拼上 offset/length 查询串会被判参数错误（401），播放器停在 error 态，音效与音乐全部静默。来源中规格作者凭记忆写“getRawFd → url=fd://”，实现者已读到 d.ts 中 fdSrc 适用于连续存放在同一文件中的资源，仍照规格自造了查询串。

## 做法

1. rawfile 资源写成 const d = resourceManager.getRawFdSync(name); player.fdSrc = { fd: d.fd, offset: d.offset, length: d.length }；只有沙箱里的独立文件才用 fileIo 打开后设 url = 'fd://' + fd。
2. 规格写法与写前读到的 d.ts 注释冲突时按 d.ts 实现，并回报规格该行有误。

## 可选检查

- 首次设备运行看 hilog 不出现 401 或“not a fd://+numeric string”；代码中 getRawFd 的结果不流向 .url。
