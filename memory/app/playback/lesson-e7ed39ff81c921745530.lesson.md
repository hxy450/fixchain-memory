# 源端 SoundPool 预加载短音效迁 media.createSoundPool：初始化时 load、事件时 play，不用每次新建 AVPlayer

ID：`lesson-e7ed39ff81c921745530` · 版本：1

[本主题](index.md)

## 何时使用

规格提取与架构决策阶段为源端短音效选择目标播放器、写跨栈映射行与候选项时；音效服务实现阶段

## 适用情境

源端 import android.media.SoundPool，以 new SoundPool(maxStreams, streamType, srcQuality) 或 SoundPool.Builder 构造，在构造或初始化时 load 资源，碰撞、点击等事件发生时 play，同一音效可能叠播；目标准备用 AVPlayer（单实例或每次新建的实例池）承载，经验提醒或技能模板只给出 AVPlayer 写法。

## 例外与边界

- 源端用 MediaPlayer 播放提示音或较长音频：按 AVPlayer 的迁移经验处理（lesson-5475edc47af05c1c6a5b、lesson-1267d6cabb117824c67a）

## 原因

SoundPool 在 load 时预解码，play 时直接发声，maxStreams 以内可以多路叠播。AVPlayer 每次发声都要走 create → 设源 → prepare → play 的状态机，等 prepare 完成才出声；用每次新建实例模拟叠播会带来明显的出声延迟，对不上源端触发即响的音效。

## 做法

1. 写映射前在本地 SDK 按源类名查同类 API：ets/api/@ohos.multimedia.media.d.ts 的 createSoundPool(maxStreams, audioRendererInfo)，ets/api/multimedia/soundPool.d.ts 的 load(fd, offset, length)、play、setInterruptMode；把查到的同类 API 列为候选并写明取舍，经验摘要或模板里的目标类不代替这次查证。
2. 按源端参数实现：maxStreams 取源构造参数，audioRendererInfo.usage 按源 streamType 或 AudioAttributes 选（未设置的媒体流对应 STREAM_USAGE_MUSIC）；在源端相同的初始化时机用 getRawFdSync(name) 返回的 fd/offset/length 调 load，事件发生时 play；源端同一音效可叠播时保留叠播（setInterruptMode 不打断），源端未申请音频焦点时按 lesson-5475edc47af05c1c6a5b 的混播并发模式处理。

## 可选检查

- 对选型有疑问时，在设备上记录从触发到出声的时间（hilog 中 play 调用到渲染器启动），与源端比较。
