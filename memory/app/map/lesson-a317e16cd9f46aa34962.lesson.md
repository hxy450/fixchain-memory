# 源定位 SDK 直接给行政区名、目标 LocationKit 只给坐标时，用 getAddressesFromLocation 逆地理编码补名称

ID：`lesson-a317e16cd9f46aa34962` · 版本：3

[本主题](index.md)

## 何时使用

定位能力实现与规格阶段，把源端定位结果（如高德 AMapLocation 的 district/city）映射为目标服务接口与业务对象时

## 适用情境

Android 定位 SDK 的回调直接带 district、city 等行政区名，业务据此展示或匹配本地数据；HarmonyOS geoLocationManager.getCurrentLocation 只返回坐标，目标服务接口只列了返回坐标的 locate()。

## 例外与边界

- 源端业务只消费坐标、不读行政区名时，无需补名称

## 原因

目标只拿坐标时，依赖名称的展示和匹配会得到空值；以空名称占位后，界面按名称或匹配结果判定仍显示“未定位”，用户看到定位成功却没有位置。行政区名在源端是定位 SDK 隐式附带的能力，接口映射只列坐标时容易漏掉。

## 做法

1. 用 geoLocationManager.getAddressesFromLocation 逆地理编码补名称，按 subLocality → locality → subAdministrativeArea → administrativeArea 取第一个非空值，对应源端“district 为空取 city”一类降级；名称再按源端的消费方式接入（如匹配本地数据）。
2. 规格提取时，源端能力由第三方 SDK 隐式附带（定位结果带地址）的，在目标服务接口写明名称来源与降级顺序。
3. “已定位”状态以是否已有定位名称或坐标判定，不只看本地数据匹配出的 ID 是否有效；规格要求保留定位名称时不以空名称占位。
