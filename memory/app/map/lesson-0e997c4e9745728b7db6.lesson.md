# 原生地图组件接入 Swiper/Tabs 预构建的页面：可见时初始化或恢复、隐藏时暂停、卸载才释放，并显式写出地图与覆盖层的触摸分工

[本主题](index.md)

## 何时使用

三方地图接入阶段，把参考工程的原生地图组件接入本工程已有页面，确定初始化、暂停、释放的挂载点与触摸分工时

## 适用情境

目标页面作为 Swiper/Tabs 子页被宿主一次性预构建；页面在高德 MapViewComponent 等原生 XComponent 地图之上叠放搜索栏、按钮等 ArkUI 覆盖层；参考桥接把激活/暂停与完整释放分成不同接口。

## 原因

预构建的隐藏子页也会走 onReady；在其中创建原生地图、在 onDisAppear 完整释放，会在页面仍挂载时销毁原生组件，设备日志出现 napi_unwrap fail。原生地图铺满页面又没有声明触摸分工时，上层控件的点击可能被地图接走。来源中移植者读到了参考桥接把激活/暂停与释放分开、MapView 的暂停与销毁接口，也在检索结果里看到页面由主页直接创建，仍在 onReady 初始化、在 onDisAppear 释放；它只读了参考工程的 adapter 目录，没读真正承载地图、给覆盖层设 HitTestMode 的页面。触摸修复与主页 Swiper 的禁用修复同批安装，地图是否独立拦截点击未单独验证。

## 做法

1. 接入前查页面在哪里实例化；位于 Swiper/Tabs 等预构建容器时，原生地图在页面实际可见（onAppear 或选中回调）时初始化或恢复，隐藏时调用暂停接口，完整释放只放在真正卸载时。
2. 服务层同时暴露初始化、暂停/恢复与释放接口，页面按可见性调用，不以释放代替暂停。
3. 在原生地图上叠放 ArkUI 控件时写明触摸分工：地图需要手势就让全尺寸覆盖容器用 HitTestMode.Transparent；只作视觉层就给 MapViewComponent 设 HitTestMode.None。
4. 移植参考工程的地图组件时，同时读参考工程里真正承载地图的页面，按其覆盖层触摸与生命周期调用方式迁移。

## 可选检查

- 真机逐个点击覆盖层控件，并与容器 enabled 等其他可能禁用点击的因素分开验证。
