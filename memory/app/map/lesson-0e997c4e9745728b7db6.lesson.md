# 原生地图组件放在 Swiper/Tabs 预构建的子页时，按选中可见性初始化或恢复、隐藏时暂停，只在 aboutToDisappear 完整释放

ID：`lesson-0e997c4e9745728b7db6` · 版本：3

[本主题](index.md)

## 何时使用

三方地图接入阶段，把原生地图组件接入本工程已有页面，确定初始化、暂停、释放的挂载点时

## 适用情境

目标页面作为 Swiper/Tabs 子页被宿主一次性预构建（在宿主文件里被直接实例化，而不是按路由压栈）；页面承载高德 MapViewComponent 等原生 XComponent 地图；SDK 或参考桥接把激活/暂停与完整释放分成不同接口。

## 例外与边界

- 页面经 Navigation 路由按需压栈、离开即销毁时，按页面自身生命周期初始化与释放

## 原因

预构建的隐藏子页同样会走 aboutToAppear、onReady 与 onAppear（onAppear 是组件挂载回调，见 common.d.ts），在其中创建原生地图会让隐藏页在启动时就初始化（设备日志出现 napi_unwrap fail）；在 onDisAppear 完整释放，会在页面仍挂载时销毁原生组件。

## 做法

1. 接入前查页面在哪里实例化；位于 Swiper/Tabs 等预构建容器时，可见性以宿主的选中索引（Swiper/Tabs 的 onChange）或页面根节点 onVisibleAreaChange 判定，不用 onAppear；页面可见且原生 surface 就绪后初始化或恢复，隐藏时调用暂停接口。
2. 完整释放放在承载页 struct 的 aboutToDisappear，不放 onDisAppear；服务层同时暴露初始化、暂停/恢复与释放接口，页面按可见性调用，不以释放代替暂停。
3. 移植参考工程的地图组件时，同时读参考工程里真正承载地图的页面，按其生命周期调用方式迁移，不只读 adapter 目录。
