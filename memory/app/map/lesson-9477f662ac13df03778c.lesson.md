# 裁剪高德鸿蒙 SDK 桥接时按产品单例分别设置隐私与 Key、分别判定就绪；PoiQueryV2 的 city 不能为空

ID：`lesson-9477f662ac13df03778c` · 版本：1

[本主题](index.md)

## 何时使用

三方 SDK 移植阶段，按参考桥接类与 SDK 声明编写高德地图、定位、搜索的初始化与查询参数时

## 适用情境

HarmonyOS 工程接入高德鸿蒙 SDK（map3d/location/search/navi 分包），以另一工程的完整桥接类为参考，裁剪成本工程的精简桥接，并用 PoiQueryV2 做关键词或周边搜索。

## 原因

高德各产品单例（MapsInitializer、AMapLocationManagerImpl、NaviSetting、ServiceSettings）各自保存隐私状态；只设 Key 或与地图初始化共用一个 try 时，搜索就绪失败会让查询静默返回空结果。PoiQueryV2 的 city 在声明里是必设参数，传空串同样得不到结果。来源中移植者读到了参考注释“每个产品各自保存隐私状态”和 d.ets 中 city 必设的说明，仍把 ServiceSettings 裁到只剩 setApiKey、与地图初始化同处一个 try，并以空城市调用；最终回执仍称“搜索隐私已初始化”。真机空结果还叠加了 Key 平台不匹配这一环境问题。

## 做法

1. 按参考注释逐个核对本工程要用的产品单例，各自调用 updatePrivacyShow、updatePrivacyAgree 与 setApiKey；各单例分别初始化、分别记录成败，搜索就绪不依赖地图初始化是否成功。
2. 构造 PoiQueryV2 前查 d.ets 的必设参数：city 为空时回退为有效城市码（源端默认值或当前定位城市），再 setCityLimit(false) 保留全国搜索；周边搜索另按声明带 location 与 bound。
3. 桥接实例由多个页面共用时，确认初始化是幂等的，不在每个 ViewModel 里重复 initialize。
