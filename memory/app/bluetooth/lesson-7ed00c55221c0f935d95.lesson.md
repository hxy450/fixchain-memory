# 封装声明为 void 的同步系统接口（如 startBLEScan）时读 d.ts 的 @throws，在服务层 try/catch 收敛为失败状态

ID：`lesson-7ed00c55221c0f935d95` · 版本：2

[本主题](index.md)

## 何时使用

服务层与页面实现阶段，封装 BLE 扫描等可能同步抛 BusinessError 的系统接口，并决定页面的失败态时

## 适用情境

目标调用的系统接口在 d.ts 中返回 void 且列有 @throws BusinessError 错误码（如 @ohos.bluetooth.ble 的 startBLEScan/stopBLEScan）；源端对适配器关闭、扫描启动失败有显式状态或异常类型，或决策要求失败降级、不崩溃。

## 原因

签名返回 void 不代表不会失败：这类系统接口把失败写在 d.ts 的 @throws 段，以同步抛出 BusinessError 报告（例：@ohos.bluetooth.ble.d.ts 中 startBLEScan 在蓝牙关闭时抛 2900003 Bluetooth disabled）。只读签名行会漏掉 @throws 段；直译源端调用不会自然带出 try/catch，未捕获的同步异常会让进程被杀。

## 做法

1. 查系统接口时连同 d.ts 的 @throws 错误码段一起读；声明为 void 的同步调用在服务层 try/catch，收敛为返回值或可查询的错误状态，不让 BusinessError 冒泡到点击回调；stop、清理类调用同样加保护。
2. 源端对适配器关闭、扫描启动失败有显式状态或异常类型时，在目标服务中映射为可查询的状态或错误；页面按页面规格的对应分支展示（如适配器关闭时的恢复入口与源端文案）。
3. 页面调用可能失败的服务时检查返回结果，失败时复位“扫描中”等进行中状态并显示错误。
