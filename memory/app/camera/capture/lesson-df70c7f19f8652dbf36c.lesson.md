# 拍照编排与相机拍照图元之间的桥接要回传完成/失败并按模式交付整组多帧：不定义成无参即发即弃的单帧调用

ID：`lesson-df70c7f19f8652dbf36c` · 版本：1

[本主题](index.md)

## 何时使用

拍照编排实现与跨切片接线阶段，设计编排器与相机拍照图元之间的桥接契约（完成/失败回调、单帧/多帧结果通道），实现 HDR、包围曝光、降噪、快速连拍与长按连拍，并接线快门点击、长按与按键拍照入口时

## 适用情境

源端以带完成与错误回调的调用发起拍照（如 takePicture(pictureCallback, errorCallback)）：完成回调里复位拍照阶段与“相机操作中”标志、续拍剩余重复、按偏好暂停预览，错误回调恢复预览；多帧模式按 burst 类型决定帧数并整组交付；长按快门进入连续快拍，松手停止。目标把编排、相机控制器、保存与页面拆到不同文件或切片，经注入的桥接或通道相连；目标相机会话可能没有连续 burst 类型。

## 原因

桥接签名决定下游能实现什么：定义成无参无回调后，编排器没有完成与失败入口，阶段和“操作中”标志无处复位，重复拍照无人续拍，暂停预览与错误恢复丢失；只发一帧时多帧模式只得到一张图，保存侧按单图入队也能编译运行。用 void 吞掉连拍一类行为参数，长按就静默退化成单拍。入口通道指向对焦后的拍照步骤而不是编排总入口时，定时、重复、全景等前置判断被绕过。

## 做法

1. 按源端调用写桥接契约：拍照图元回传完成与失败（回调或 Promise），编排器提供对应的完成/失败入口，在其中统一复位拍照阶段与“相机操作中”标志；完成时续拍剩余重复、按暂停预览偏好处理，失败时按源端恢复预览。
2. 编排器按模式算出的帧数（HDR、包围曝光张数、降噪、快速连拍张数）由图元按同一模式发起并整组交付（源端 onBurstPictureTaken 一类回调的等价），保存请求的图像数与模式一致；不把多帧模式按单帧拍，也不在保存侧按单图入队。
3. 目标会话没有连续 burst 类型时，在编排层自建连拍循环：记录在途帧，上一帧回调后判断是否继续再发下一帧，提供停止与“连拍进行中”查询；长按开始与松手停止两端都接到快门控件，后台、销毁时停止。做不到就登记移交或待批差异，不用 void 吞掉行为参数。
4. 快门点击、长按、硬件键与遥控拍照等入口都接到编排器的同一拍照总入口（源端各入口汇合的那个方法），不直接接对焦后拍照的图元步骤。
