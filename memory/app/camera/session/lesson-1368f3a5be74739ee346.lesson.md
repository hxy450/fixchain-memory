# 释放或重建 CameraKit 会话时逐步 await 拆卸；要复用的 CameraInput 先 removeInput 再 release 旧会话

ID：`lesson-1368f3a5be74739ee346` · 版本：1

[本主题](index.md)

## 何时使用

相机实现与返修阶段，编写会话关闭、拍照与录像会话切换、探测会话转正式会话的拆卸代码时

## 适用情境

拍照/录像切换或探测会话转正式会话需要重建 CameraKit 会话并复用同一个 CameraInput；源端 Camera2 在后台线程按顺序同步停止预览、关闭会话与设备；目标 session.stop/release、各 output 的 release、cameraInput.close 都返回 Promise。

## 原因

Session.release 会关闭仍挂载在该会话上的 CameraInput（设备日志与平台实现确认；d.ts 只写 Release capture session instance），旧会话释放后再把同一 input 加进新会话，预览无法启动；拆卸各步不 await 时，新会话配置、录制器释放或 input.close 会先于旧会话拆卸落地。

## 做法

1. 重建会话需复用同一 CameraInput 时，旧会话按 stop → beginConfig → removeInput(input) → release 处理，再在新会话 addInput；整机关闭才在会话 release 之后 cameraInput.close()。
2. 关闭链逐步 await：先 await 拆卸录像输出再释放录制器 → session.stop → 各 output.release → session.release → input.close；全部完成后才改关闭状态、发完成回调或重开。

## 可选检查

- 无法上设备验证时，宿主 mock 是否模拟了“release 会关闭仍挂载的 input”，并覆盖探测会话转正式会话与拍照/录像切换两条路径
