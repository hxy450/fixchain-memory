# 原生 MethodChannel handler 的方法集合按源原生分支全集与 Dart 调用点双向对照，不以契约列出的方法数为完成标准

ID：`lesson-e6b1032f702fc61940f2` · 版本：1

[本主题](index.md)

## 何时使用

混合工程的通道契约提取与原生桥接实现阶段，确定鸿蒙侧 MethodChannel handler 要实现哪些方法时

## 适用情境

Flutter 与原生共用一个 MethodChannel；契约只按 Dart 侧方法名枚举列方法，源 Android 原生 handler 还处理枚举以外的方法（如 log），Dart 侧用字符串字面量调用，或调用点当前被注释。

## 原因

从 Dart 枚举出发只能发现“Dart 要、原生没实现”的方法，“原生处理、枚举里没有”的方法不会进契约；验证也以契约为准判“无缺失”，缺口一路放行。来源中桥接实现者读过源 handler，第一个分支就是 log，它自己也把 log 列为原生处理的方法之一，最终仍只写了契约里的 18 个 case；Dart 侧的调用又被注释，日志两头都断。

## 做法

1. 契约提取时，除 Dart 枚举外再 grep 源原生侧 when(call.method)/switch 的全部分支，以及 Dart 侧 invokeMethod 的字符串字面量（包括被注释的调用），在契约里标出“原生已处理、Dart 当前未调用”的方法。
2. 实现 handler 时，逐个处理源原生侧有、枚举里没有的方法：实现它，或写明不迁移的理由。
3. 日志类通道方法先看 Dart 侧 release 分支是否真的调用；调用被注释时，把是否恢复记为一条决策，原生侧不直接省略。
