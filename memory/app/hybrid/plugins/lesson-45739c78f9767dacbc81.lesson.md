# Flutter 插件没有现成 OHOS 包时，先按底层能力评估本地兼容插件；判阻断要写明缺失能力，Dart 冻结下的显式失败也要由 OHOS 插件回调

ID：`lesson-45739c78f9767dacbc81` · 版本：1

[本主题](index.md)

## 何时使用

插件适配阶段，为 Registry/pub 上没有 OHOS 实现的 Flutter 插件选择替代层级（同包分支、本地兼容插件、换包或阻断）并写 dependency_overrides 时

## 适用情境

Flutter 复用路线且应用 Dart 冻结；某 federated 插件只声明 Android/iOS 实现，Registry 无对应 OHOS 包；其原生侧做的是 HTTP 上传、签名、文件读写等通用能力；Dart 调用方以 Future、Completer 或事件监听等待平台回调，并处在核心功能链上。

## 例外与边界

- 已逐项查明原生实现依赖的底层能力在 HarmonyOS 没有可用 Kit，且决策记录写明缺失能力与替代方案

## 原因

“Registry 无 OHOS 包”“只联邦 Android/iOS”只排除了现成包，不说明能力无法在 OHOS 实现；据此判阻断就不会产出任何 OHOS 插件。Dart 冻结时，能让等待方结束的只有平台侧回调：插件缺位时监听等待的成功/失败事件永远不会到达，页面停在加载态，只写在方案文档里的“显式失败、不伪造成功”没有实现载体。

## 做法

1. 现成包与同包分支不可用后，先从缓存源码（*_android 实现与 platform_interface）提取 MethodChannel 名、方法、参数与回调事件，列出原生实现用到的底层能力及对应 HarmonyOS Kit（如 HTTP PUT 用 @kit.NetworkKit http、HMAC 签名用 cryptoFramework、读文件用 fs）；能对上就在 ohos/flutter_plugins/<package>/ 建本地兼容插件，保持包名、Dart API 与 Channel，经 dependency_overrides 接入。
2. 只有找不到可用 Kit 才判阻断，evidence 写明缺失的具体能力；尚未提取 Channel 契约时不下阻断结论。
3. 确须阻断而 Dart 冻结时，仍提供 OHOS 插件为每个方法和被等待的事件显式回调失败；处在核心链路上的阻断在报告中标为核心功能阻断，不归为 non-core。
4. 写 dependency_overrides 时逐项对照未决插件清单，每个包都要有 override 或可运行的失败实现。
