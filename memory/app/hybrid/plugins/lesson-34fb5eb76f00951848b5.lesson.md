# 冻结 Dart 下游在 UI isolate 同步解码、缩放原图时，兼容层先用原生图片引擎按业务上限缩放，避免 OHOS 主线程阻塞被结束进程

ID：`lesson-34fb5eb76f00951848b5` · 版本：2

[本主题](index.md)

## 何时使用

插件兼容层实现阶段，决定系统选图结果以什么分辨率交给冻结的 Dart 业务时

## 适用情境

下游业务链用 package:image 等纯 Dart 库在 UI isolate 对所选原图同步 decode、copyResize、encode（如上传前压缩），业务自身有长边上限；用户可能选择千万像素级相机照片；同一 Dart 代码在 Android 上没有报卡死。

## 例外与边界

- 下游已在独立 isolate 处理，或只传递文件路径、不做像素运算时，保持原图交付

## 原因

UI isolate 上的同步像素运算会连续阻塞 UI 线程；OHOS 对主线程长时间阻塞按 appfreeze 处理（hilog 出现 FlutterWatchdog 与 BUSSINESS_THREAD_BLOCK_6S）并结束进程，Android 上同一代码可能只表现为卡顿。冻结的业务链改不成异步，只能在兼容层控制交给它的分辨率。

## 做法

1. 沿选图入口的调用方打开会压缩、上传或编辑原图的代表性链路，确认是否在 UI isolate 同步做像素运算，并读出业务自身的尺寸上限。
2. 存在此类处理时，在兼容层用原生图片引擎（ImageSource，或 flutter_image_compress 的 compressAndGetFile）按业务上限等比缩放到两边都不超界；不在 Dart 侧整图解码。
3. 缩放失败可回退原文件，但这条失败路径未经验证：回退的原图仍会进入同步像素链路，可能再次阻塞；原接口能表达失败时可改为返回失败，并在交付说明写明所选处理。

## 可选检查

- 用千万像素级相机原图走会压缩或上传的入口，过滤 hilog 中的 FlutterWatchdog 与 BUSSINESS_THREAD_BLOCK_3S/6S。
