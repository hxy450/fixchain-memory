# 迁移嵌入 Flutter 页面的原生宿主时打开实际挂载的容器子类，逐项迁移事件监听与反向推送，不只挂 FlutterUIComponent

ID：`lesson-6717b958e274143453a8` · 版本：2

[本主题](index.md)

## 何时使用

原生宿主迁移与规格提取阶段，把承载 Flutter 页面的 Activity/Fragment 转成 ArkTS 页面，确定宿主除挂容器外还要承担哪些原生↔Flutter 通信时

## 适用情境

源端宿主经 flutter_boost 挂载的是自定义 FlutterBoostFragment 子类，在其中 addEventListener(通道名) 分发 Flutter 事件、sendEventToFlutter 反向推数据；事件名常量、桥接 Model 与宿主分散在不同源文件；契约可能把这类桥接标成“待 Feature Spec”。

## 例外与边界

- 源端原生↔Flutter 通信走 MethodChannel 方法调用而非 flutter_boost 事件时，按 MethodChannel handler 方法集合的经验（lesson-e6b1032f702fc61940f2）处理

## 原因

宿主 Activity 里只看得到“挂一个 Fragment”，事件通信写在 Fragment 子类里；不打开它，迁移结果就只剩容器，编译和页面显示都正常，到点击交互才没有反应。事件名常量、桥接 Model 与宿主分散在不同源文件，只读其中一处也会漏掉事件项或把事件锚到别的页面。

## 做法

1. 顺着宿主取 Fragment 的调用找到实际挂载的容器子类，打开源文件，列出 addEventListener 的通道名与事件分支、sendEventToFlutter 的推送点，在目标页逐项实现；目标页未迁的分支写日志占位和 TODO。
2. 已读到事件常量表时，宿主页至少注册对应通道，或显式登记缺口。
3. 契约把某个桥接标为“待 Feature Spec”时，feature spec 要读源端实现，写明通道机制（flutter_boost 事件还是 MethodChannel）、通道名、事件清单、宿主锚点与数据 Model 字段，并落到切片的具体步骤。

## 可选检查

- 有疑问时 grep 源宿主与目标页的 addEventListener/sendEventToFlutter，逐条对应。
