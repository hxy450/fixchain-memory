# 源页面继承带生命周期副作用的业务基类、目标改用组合式 BasePage 时，逐方法列出副作用及守卫条件再逐页落地

ID：`lesson-2fcb6612ee4106b34e17` · 版本：5

[本主题](index.md)

## 何时使用

公共基座实现与页面转换阶段，把 BaseActivity/BaseBusinessActivity 等业务基类的 onCreate、onDestroy、onBackPressed、dispatchTouchEvent 行为迁到 ArkUI 页面时

## 适用情境

Android 页面统一继承业务基类，由基类自动完成页面展示/退出埋点（停留时长、返回键归因）、触摸计数、点外收键盘、进入淡入、前台能力开关等；ArkUI @ComponentV2 struct 不能继承，目标改用需逐页调用的组合式 BasePage 或工具类，页面还可能先于公共基座生成；负责基座或服务的任务可能不能改页面，规格指向的基类等价物（Mixin）也可能并不存在。也包括基类副作用写在 findViewById(R.id.x) != null、instanceof、标志位等守卫之内，并非每个子类都满足。

## 例外与边界

- 基类在 onResume/onPause 开关的是 NFC 前台派发这类按 UIAbility 注册的能力：按能力级注册加可见页登记处理，不逐页开关整个能力

## 原因

目标端没有继承：只迁子类文件里显式出现的调用，基类自动完成的副作用就在每个页面丢失；基座只按规格的映射行实现时，同一方法里映射行没提到的副作用会被静默删掉；组合式基座建好却没给既有页面登记接线，缺口保留到交付。反过来，逐方法列表丢掉守卫条件时，只对部分子类生效的副作用会落到所有页面，多出源端没有的行为。源回调的触发次数也不同：onCreate/onDestroy 每个实例一次，onResume/onPause 每次可见切换都触发，统一落到 aboutToAppear/aboutToDisappear 会把显隐语义改成创建销毁语义。

## 做法

1. 基座阶段按源基类逐方法列出全部副作用连同守卫条件（findViewById 判空、instanceof、标志位），如展示/退出埋点、返回归因与整秒时长、触摸计数、点外收键盘、进入淡入，在目标基座逐项对应；不承接的写明折叠理由并在报告中列为裁剪项，不只按规格的映射行实现。
2. 页面转换时，源页面类继承业务基类的，打开基类并按源回调区分落点：onCreate/onDestroy 类副作用落 aboutToAppear/aboutToDisappear（每个页面实例一次）；onResume/onPause 类（前台能力开关、可见期内的订阅、onResume 里的进入淡入）落 NavDestination 的 onShown/onHidden 或 @Entry 页的 onPageShow/onPageHide（每次可见切换都触发）；onBackPressed 落 onBackPressed，NavDestination 的系统返回也置返回归因。目标等价物未建就登记前向占位。
3. 用组合替代继承时，在源码 grep 继承该基类的页面，与目标页对基座或埋点调用的 grep 结果做差集，给未调用的页面逐页登记接线（负责方指向所属切片），并在 as-built 契约中写成“每页必须调用”的义务，不只列为可用 API。
4. 服务切片不能改页面、基类等价物又不存在时，在服务里交付页面可直接调用的入口（如 pageShown/pageHidden 与默认事件处理），按继承该基类的页面清单逐页登记可追踪的移交；只在笔记里写“归消费切片”不算完成，交账前核对验收声明的目标锚点确实存在。
5. 逐页登记义务前，在每个子类布局（含 layout-land 等变体）中 grep 守卫引用的 id 或核对条件；不成立的页写明“不适用”，不登记义务、不实现该副作用。
