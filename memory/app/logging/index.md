## 本级经验

- [审计或规划日志迁移时按源端日志调用边界列出日志点与验收，不只核对日志库配置](lesson-e23468a0e439f8cf53e9.lesson.md)
  - 时机：迁移审计与计划阶段，对照源端评估已接入的日志框架并制定整改计划时；按计划搬移或改写边界上的日志调用时
  - 情境：源端通过统一日志类直接写日志，或经 log2File、debugFile 等包装在同步各阶段、网络请求、卡片刷新、导入、本地增删改等边界写文件日志；决策要求目标在这些对应边界统一改用日志封装（如 BqLog），而现有目标工程已接入日志库，只有少量起止或 method/status 日志。
- [新增错误日志沿用工程的 hilog 约定，不写 console.*](lesson-11e9d15d947b30d2ce7e.lesson.md)
  - 时机：功能实现阶段，在服务层、ViewModel 或页面的 catch 分支里为新增的错误处理选择日志写法时
  - 情境：源端对失败静默处理或没有日志（如 Kotlin runCatching 吞掉异常），目标 ArkTS 在 catch 中新增错误日志；工程里已有 hilog 写法（TAG、DOMAIN 常量），而生成期规则只约束 build() 内的 console.log 或占位写法。
- [诊断日志上传按源端上传函数的打包清单与协议实现：收窄为 HTTPS 或快照前先列差异交用户确认，动态预签名地址按端点允许协议](lesson-d434bb5c16bc721d9a00.lesson.md)
  - 时机：规格决策、增量审计与诊断归档实现阶段，确定日志上传地址的协议约束与归档内容时；网络层处理服务端下发的动态绝对 URL 时
  - 情境：源端先向服务端取预签名地址再 PUT（返回地址可能是 http，应用声明 usesCleartextTraffic），ZIP 包含日志目录全部留存文件、设备信息与各数据表导出；目标改用替代日志库，并由自研网络层对动态绝对 URL 做协议校验。
  - 例外：用户已确认与源端不同的安全或隐私取舍，此时按确认结果实现，并在报告中写明差异
