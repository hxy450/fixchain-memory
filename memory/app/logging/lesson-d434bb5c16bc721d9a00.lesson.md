# 诊断日志上传按源端上传函数的打包清单与协议实现：收窄为 HTTPS 或快照前先列差异交用户确认，动态预签名地址按端点允许协议

ID：`lesson-d434bb5c16bc721d9a00` · 版本：1

[本主题](index.md)

## 何时使用

规格决策、增量审计与诊断归档实现阶段，确定日志上传地址的协议约束与归档内容时；网络层处理服务端下发的动态绝对 URL 时

## 适用情境

源端先向服务端取预签名地址再 PUT（返回地址可能是 http，应用声明 usesCleartextTraffic），ZIP 包含日志目录全部留存文件、设备信息与各数据表导出；目标改用替代日志库，并由自研网络层对动态绝对 URL 做协议校验。

## 例外与边界

- 用户已确认与源端不同的安全或隐私取舍，此时按确认结果实现，并在报告中写明差异

## 原因

以派生的安全或隐私约束代替源端实际行为时，上传被网络层拦截（只接受 https），归档也只剩当日快照；审计判定“保留现有实现”时没有核对上传函数，修复首轮在已读到源端清单时仍按约束以快照和整库二进制替代。来源中用户两次反馈后，才改为仅上传端点允许 http，并按源端逐项打包。

## 做法

1. 为诊断上传写安全或隐私约束前，先查源端清单的 usesCleartextTraffic/networkSecurityConfig 与上传函数的实际打包清单；要收窄时逐项列出与源端的差异交用户确认。
2. 网络层处理预签名等动态绝对 URL 时，按端点声明允许的协议（如仅日志上传 PUT 允许 http），其余请求保持默认 HTTPS。
3. 实现归档时按源端上传函数逐项对齐：日志目录内全部留存文件（而非内存中的当日快照）、设备信息、各表文本导出；决策约束与源端清单冲突时先确认，不自行以替代物交付。
