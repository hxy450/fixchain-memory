# 审计或规划日志迁移时按源端日志调用边界列出日志点与验收，不只核对日志库配置

ID：`lesson-e23468a0e439f8cf53e9` · 版本：1

[本主题](index.md)

## 何时使用

迁移审计与计划阶段，对照源端评估已接入的日志框架并制定整改计划时；按计划搬移或改写边界上的日志调用时

## 适用情境

源端通过统一日志类直接写日志，或经 log2File、debugFile 等包装在同步各阶段、网络请求、卡片刷新、导入、本地增删改等边界写文件日志；决策要求目标在这些对应边界统一改用日志封装（如 BqLog），而现有目标工程已接入日志库，只有少量起止或 method/status 日志。

## 原因

只核对等级、保留期等配置时，审计会判定“日志库合理、应保留”，计划验收也只剩保留天数；边界上的日志点从未被对照补齐，到排查问题时才发现“日志都没用”。来源中规划者读到决策点名的边界和源端同步每一步的调试日志，审计与计划仍只把日志库当配置项，执行者搬移卡片刷新失败日志时也没有补类型和耗时。

## 做法

1. 审计时除配置外，检索源端日志类的直接调用与包装调用，按业务边界比对目标是否有等价日志。
2. 决策点名的每个边界（网络、同步各阶段、卡片刷新、导入、本地增删改等）在计划中写出日志点与验收项。
3. 搬移或改写这些边界上的日志调用时，对照源端补足定位字段（类型、阶段、失败分类、耗时、数量），同时遵守不记录 token、ID、正文与完整请求/响应的脱敏约束。
