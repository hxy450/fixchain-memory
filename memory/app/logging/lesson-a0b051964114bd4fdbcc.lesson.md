# 源端采集或上报由构建配置决定是否启用（如上报地址为空即不初始化）时，按参照构建的生效状态迁移，不为未启用的采集新增同意门控

ID：`lesson-a0b051964114bd4fdbcc` · 版本：1

[本主题](index.md)

## 何时使用

规格提取与决策阶段，为崩溃上报、统计等需构建期参数才启用的采集功能确定目标范围与合规设计时

## 适用情境

源端在 Application.onCreate 里按 BuildConfig 或 gradle.properties 的值决定是否初始化 SDK（如上报 URL 为空就跳过 ACRA.init），参照构建中该值为空；规格、接口清单或派工以“上架要求隐私同意后才可采集”为由，提议新增本地采集链与同意门控。

## 原因

参照构建里该功能根本不运行，不采集也不上报；按想象的合规要求新增采集链和同意门控，就给源端没有的行为加了流程与开关，下游计划与实现会照台账落地。合规门控只对确实采集或上报的通道有意义。

## 做法

1. 先读初始化条件与参照构建的配置取值，写明该功能在参照构建中是否生效；未生效就按源行为落地为不采集、不门控，源端的开关等设置项照迁。
2. 构建期参数非空、确实采集或上报时，才按目标平台要求设计同意门控，并作为带编号的差异决策登记，写明对用户可见流程的影响。
