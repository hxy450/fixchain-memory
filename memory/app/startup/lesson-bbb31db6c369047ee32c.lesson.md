# 首页启动弹窗按源函数的接口与显示守卫实现，不以目标已有的同类列表接口替代

ID：`lesson-bbb31db6c369047ee32c` · 版本：1

[本主题](index.md)

## 何时使用

宿主页接线阶段，为首页启动弹窗队列中“数据到达后条件弹出”的内容（如每日一言、活动推荐）确定数据源与显示条件时

## 适用情境

源端首页启动后用登录 token 调用专用启动接口，按返回对象字段是否完整决定是否弹出，并限制每日次数；目标端已有同名内容的列表或分页接口可直接调用。

## 原因

同名内容的列表接口返回的不是启动接口的对象，也不带服务端的展示判定；换成列表接口并只保留次数限制，会在未登录或无内容时仍弹窗，或弹出不该展示的内容。来源中实现者写前已读到源函数全文（token 门禁、专用接口、字段完整性检查、每日两次），仍调用列表接口取第一条，只保留了次数限制。

## 做法

1. 先确认源函数实际调用的接口与返回对象再选数据源；目标缺少同源接口时补齐该接口能力，不因已有同名内容的接口而替换。
2. 把源函数的每条显示守卫写成实现检查项：登录/token 门禁、返回对象字段完整性、频次限制；写后逐项对照源函数。修复计划只写“恢复带守卫的触发”时，也要读完源函数全文再实现。
