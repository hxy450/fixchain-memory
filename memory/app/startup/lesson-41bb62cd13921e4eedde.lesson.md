# 用户要求“和源端一样有加载页”而目标初始化极快时，把首启最短可见时长写进验收或交用户决策

ID：`lesson-41bb62cd13921e4eedde` · 版本：2

[本主题](index.md)

## 何时使用

启动页的规格、计划与实现阶段，确定首次冷启动加载页的可见时长时

## 适用情境

源端闪屏继承外部 SDK，可见时长由 SDK 决定；目标初始化只读本地配置、几乎瞬时完成；用户要求首次启动与源端一样看到加载页。

## 例外与边界

- 用户或决策明确要求直接进入主页、不显示启动页

## 原因

只验证首帧状态、以“不伪造延迟”为由不设最短时长，加载页一闪而过，等于没实现用户要的可见加载过程。

## 做法

1. 把“能被看见”写成验收项：源端时长不可得而目标初始化极快时，规定仅首次冷启动的最短可见时长（热启动不等待），时长取源端实测或用户批准的值，或作为决策缺口交用户确认。
2. 实现时在启动页出现时记录起点，初始化完成后取“初始化完成”与“起点加最短时长”中较晚者再跳转，并只对首次冷启动生效。

## 可选检查

- 清数据冷启动测量加载页实际停留时间，低于验收写定的最短可见时长即未满足；验收尚未写定时长时先登记体验决策。
