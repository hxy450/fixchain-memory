# 延后无对等 API 的采集通道时，单独移植源端与采集无关的超时兜底，保证启动门闩等待的事件有发布者

ID：`lesson-99a8d47085e4b1ae44de` · 版本：1

[本主题](index.md)

## 何时使用

功能实现阶段，为依赖平台 SDK 的采集通道（设备标识、归因等）登记延迟占位、划定哪些源端逻辑先行移植时；启动链等待某个就绪事件或缓存键时

## 适用情境

源端启动链在缓存为空时等待就绪事件（如 OaidResultEvent）才继续；该事件既由采集回调发布，也由与采集结果无关的定时兜底（Observable.timer 后无条件 post）发布；目标平台的采集 API 尚未确认，准备写 FWD-REF 或延迟域占位。

## 原因

把整个生产者一并延后，消费端照源等待却等不到事件，只能走完最长兜底（如十几秒的进度动画）才继续；占位注释还会声称“与源端等待语义等价”，编译与结构检查都看不出来。

## 做法

1. 把生产者拆成采集源与门闩放行两部分：只延后确实缺 API 的采集源；源端的定时兜底按原时长移植，到时置单次锁并发布就绪事件，真实采集先到时取消定时器。
2. 登记延迟占位前列出该事件与缓存键的全部等待方，逐一确认占位期间仍有发布者或超时放行；grep 事件的 post/emit 调用点与缓存键写入点，消费者非零而生产者为零时不以占位收尾。
