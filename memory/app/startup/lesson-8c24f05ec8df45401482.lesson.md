# 迁移启动链路时打开闪屏各去向页的初始化入口，列出冷启动请求与登录态组合的处理位置；源端推迟到主页处理的也要迁到位

ID：`lesson-8c24f05ec8df45401482` · 版本：3

[本主题](index.md)

## 何时使用

启动链路迁移与功能切片划分阶段，确定已登录、未登录冷启动要执行哪些请求，以及各登录态组合去向哪里时

## 适用情境

源端闪屏只做路由（如已登录 → 主页、未引导 → 引导页、无 token → 静默游客登录），刷新 token、拉配置等请求写在主页 Activity 的初始化方法里；token 失效等状态靠进入主页后的刷新与拦截器踢登处理；目标端用启动 ViewModel 承载闪屏路由。

## 原因

只迁闪屏的分支，会漏掉路由目标页进入时发出的请求；这些请求常不属于任何功能域，划分切片时容易没人认领。源端靠进入主页后的刷新与拦截器处理的登录态组合，目标若只照搬闪屏分支，就没有任何代码处理。

## 做法

1. 打开闪屏每个去向页的初始化入口（如主页 Activity 的初始化方法），列出冷启动请求清单（刷新 token、拉配置、版本检查、权益等），逐项落到对应 ViewModel 或标为未迁。
2. 按启动判定用到的持久化状态列出组合（用户信息有/无 × token 有/无 × 是否完成引导），写明源端各组合的去向；源端交给后续流程处理的组合，确认目标端的后续流程已经接通，不只照搬闪屏的分支。源端启动固定进主页、登录按需触发时，去向按启动固定主页一条处理，不在启动处按 token 分流。
3. 划分功能与切片时用端点调用方反查（如清单里刷新接口的 callers 指向主页 Activity），确认宿主 Activity 的初始化请求有功能认领。
