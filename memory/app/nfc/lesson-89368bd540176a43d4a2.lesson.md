# 清单声明的 NFC TECH_DISCOVERED 贴卡拉起入口映射为 module.json5 skills（TAG_FOUND + tag-tech），在 onCreate/onNewWant 取 TagInfo；运行时启停开关只作用于这条系统派发

ID：`lesson-89368bd540176a43d4a2` · 版本：1

[本主题](index.md)

## 何时使用

规格提取与入口实现阶段，映射 AndroidManifest 中 NFC TECH_DISCOVERED（activity-alias 或 intent-filter 加 tech-list）入口及偏好里启停它的开关时

## 适用情境

源应用用 activity-alias 声明 android.nfc.action.TECH_DISCOVERED（meta-data 指向 tech-list，如 NfcA）作为贴卡拉起入口，并在偏好里用 PackageManager.setComponentEnabledSetting 启停该 alias；各 Activity 另在 onResume 无条件开启前台派发；目标 module.json5 只有 home skill。

## 原因

贴卡拉起是独立于前台派发的系统入口：目标同样能在 skills 中声明 ohos.nfc.tag.action.TAG_FOUND 与 tag-tech uris，只是第三方不能运行时启停 skill。把它判为无对等，应用失去贴卡拉起；把开关改成前台派发闸门，关闭开关后应用内读卡也失效。来源中规格把整条入口写成“无对等，应用内开关模拟”，开关被实现成前台回调首行的 return。

## 做法

1. 入口 ability 的 skills 增加 actions: ["ohos.nfc.tag.action.TAG_FOUND"] 与 uris: [{ type: "tag-tech/<源 tech-list 中的技术>" }]；EntryAbility 在 onCreate/onNewWant 从 want 取 TagInfo，交给对应页面处理。
2. 源端启停开关只映射到系统派发这条路径：在入口识别贴卡拉起的 want 后按开关决定继续还是退出（来源采用冷启 terminateSelf、热启退回后台），前台派发不受影响；接口名写明作用范围（如 setAutostartEnabled），不复用前台派发的开关。
