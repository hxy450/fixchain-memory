# 应用级图标按 AppScope 自身资源解析：身份落地时把 app.json5 icon 改指迁移后的分层图标并补齐其前景/背景，不把脚手架现值当作“不变”

ID：`lesson-feec63f65102f5396e51` · 版本：1

[本主题](index.md)

## 何时使用

执行阶段应用身份落地（资源迁移之后）确定 AppScope/app.json5 的应用级 icon 引用与 AppScope 图标资源时

## 适用情境

脚手架 AppScope/app.json5 的 icon 仍指向模板占位图（如 $media:app_icon，AppScope media 下只有 1KB 以内的占位 PNG）；源 App 的启动图标（自适应前景/背景，矢量或位图）已由资源迁移落到 entry 模块并被入口 Ability 的 icon（如 $media:layered_image）引用；身份步骤的说明只描述 PNG 来源，或把 icon 写成“保持目标值（不变）”。

## 例外与边界

- AppScope 的 icon 已指向能解析到源 App 图标的资源；此时只需核对引用在 AppScope media 内闭合

## 原因

应用级 icon 只在 AppScope 自己的资源里解析，entry 模块已迁移的分层图标不会被它自动引用。把说明里的“icon 保持 $media:layered_image（不变）”读成“保持脚手架现值”，或因源图是矢量/webp、说明只写 PNG 就放弃替换，应用级图标会停在模板占位图；编译与结构检查不会报错，只在身份校验时以疑似默认图暴露。

## 做法

1. 把 app.json5 的 icon 与身份步骤给出的目标引用比对，而不是与脚手架现值比对；现值仍是模板占位（如 $media:app_icon）时改为目标引用（如 $media:layered_image）。
2. 在 AppScope/resources/base/media 下补齐该引用及其前景/背景：资源迁移已在 entry 侧产出分层图标 JSON 与前景/背景文件时，直接复制 entry 侧正在使用的同一组文件，保持 layered-image 里的 $media 名与文件名一致，读回确认两项引用都能在 AppScope media 内解析；能这样闭合的项不要以“非阻断”附注移交到验证阶段。

## 可选检查

- 不确定应用级图标是否仍为模板图时，看 AppScope media 中被引用图片的大小：1KB 以内的 app_icon/foreground/background 多为脚手架占位。复制的是矢量前景/背景且流程本有构建步骤时，确认 AppScope 资源随之编译通过。
