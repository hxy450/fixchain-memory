# 沿用脚手架 bundleName/vendor 前核对所引部署期决策与签名配置；两者都不成立时按源端 applicationId 落地，或登记决策缺口

ID：`lesson-fb996956b33a1ba65861` · 版本：1

[本主题](index.md)

## 何时使用

资源前置阶段落地应用身份字段、决定 bundleName 与 vendor 是否替换脚手架值时；以及维护流水线里身份规则与验证门的口径时

## 适用情境

AppScope/app.json5 仍是 com.example.* 包名与 example 厂商，源 build.gradle 给出真实 applicationId；执行规则要求这一阶段只写显示名和版本，把包名、厂商留到部署期决策。

## 例外与边界

- 工程已有签名配置，或决策台账里确有已批准的部署期身份决策

## 原因

规则以“部署期决策、签名一致性”为由保留脚手架值，但工程台账里没有该决策、签名配置为空、流水线也没有后续落地步骤，而验证门对 com.example.* 包名直接判失败。来源中资源阶段 worker 读到了 applicationId，仍按规则保留脚手架值，直到验证期才手动改。

## 做法

1. 保留前在决策台账查规则所引的决策，并看 build-profile.json5 的 signingConfigs；二者都不成立时，按源端 applicationId 映射 bundleName 与 vendor，或在迁移报告登记“包名/厂商待定、验证门会判失败”的决策缺口，不静默沿用脚手架值。
2. 维护流水线时，让“部署期再落地”的跳过规则与验证门一致：进入验证前安排落地步骤，或让验证门对已登记延后的字段给出 DEFERRED。
