# 源端写操作经账号就绪守卫包裹时，目标逐回调调用同一守卫，乐观更新放在守卫通过之后

ID：`lesson-d7dcfc800aa6cefa869b` · 版本：2

[本主题](index.md)

## 何时使用

功能切片与收尾接线阶段，为投票、收藏、删除、屏蔽、发送等写操作接入账号校验时；公共组件阶段迁移当前账号读取函数时

## 适用情境

源端以 LiveData/observeAsState 读取当前账号（未装载即匿名哨兵），写操作先过账号就绪校验链（doIfReadyElseDisplayInfo、ActionBarButton(requiresAccount=true)；未登录、未验证、被封禁各有提示）；目标已有或随后会有带 @Trace currentAccount 的全局账号存储与账号校验服务，页面由不同切片分别接线。

## 原因

用本地匿名判断加 Toast 代替校验链，会跳过“未就绪”分支与对应提示，匿名点赞还会先改本地分数；页面挂载时异步读一次账号快照，读到前匿名判定恒为假，冷启动进入的流程按错误账号执行。源端守卫是逐个回调包裹的，接线者只按占位注释点名的几个动作补，其余写操作就绕过校验。

## 做法

1. 公共组件阶段给当前账号提供同步可读的响应式出口（全局 @Trace 存储），装载前取源端兜底值（匿名哨兵）；源端用于引用比较的哨兵（val X = Y.copy()）导出为模块级常量单例。不把“页面挂载时异步拉取、持本地副本”定为契约。
2. 逐个回调对照源端：被 doIfReadyElseDisplayInfo 或 requiresAccount 包裹的回调，目标调用同名的账号守卫服务，不用本地 Toast 判定代替；乐观分数与状态在守卫通过后再更新。
3. 账号存储的写方法（含验证状态）都刷新内存中的当前账号并广播，对应源端 Room/LiveData 任一写入即重发射。
4. 派工或上游已提供响应式账号存储时，在事件处理与 build 中同步读取它；照抄兄弟页旧写法前先与现有存储核对。

## 可选检查

- 逐屏数源端守卫包裹的回调数，与目标页守卫调用数对齐；存储落地后检索一次性异步读库的账号读取，结果应为零
