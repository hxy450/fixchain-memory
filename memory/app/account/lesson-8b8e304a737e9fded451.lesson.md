# 退出登录按源端清理范围执行：停止并等待同步，单事务清空账号业务表，再广播数据变化

ID：`lesson-8b8e304a737e9fded451` · 版本：1

[本主题](index.md)

## 何时使用

账户域实现与重构计划阶段，确定退出登录、账号注销或游客重建要清理哪些本地状态时

## 适用情境

源端退出除清 token 与账号偏好外还清空本地业务库（如退出函数调用整库清理）；仓库里可能已有规格写明退出前停同步并清理账号业务数据；目标把会话清理拆到仓库与宿主桥接，已有实现只删偏好与登录态。

## 原因

只清偏好与 token 时，本地库里的账号日程、待办等仍在，退出后页面重新查库，首页继续显示已退出用户的数据；同步任务不停还可能在清理后写回。来源中编排者读过要求“退出前停止同步并清理账号业务数据”的增量规格，写计划时没把它纳入账户批次的验收；实现者没有重读源端退出实现，把旧的只清偏好的清理函数原样拆进新钩子，还声称已恢复完整游客态。

## 做法

1. 实现退出钩子前读源端退出实现及其调用的库清理，列出所有按账号归属的本地状态（业务表、游标、同步队列、搜索历史、订阅、倒数日等）与目标表逐项对照；旧目标实现只作待验证输入。
2. 按“停止并等待同步 → 单个事务清表（保留图标、颜色、节日等公共静态表）→ 广播数据变化让存活页面刷新”的顺序实现。
3. 编计划或合并批次时核对仓库里状态仍为 planned 的增量规格，把已写明的退出清理要求写进对应批次的验收条件，不只写“符合源端行为”。
