# app/account

账号会话：退出登录、账号注销与游客重建时要清理的本地状态、清理顺序（停同步、清表、广播）与计划验收；写操作的账号就绪守卫逐回调迁移与当前账号的响应式读取

[上一级](../index.md)

## 本级经验

- [源端写操作经账号就绪守卫包裹时，目标逐回调调用同一守卫，乐观更新放在守卫通过之后](lesson-d7dcfc800aa6cefa869b.lesson.md)
  - 时机：功能切片与收尾接线阶段，为投票、收藏、删除、屏蔽、发送等写操作接入账号校验时；公共组件阶段迁移当前账号读取函数时
  - 情境：源端以 LiveData/observeAsState 读取当前账号（未装载即匿名哨兵），写操作先过账号就绪校验链（doIfReadyElseDisplayInfo、ActionBarButton(requiresAccount=true)；未登录、未验证、被封禁各有提示）；目标已有或随后会有带 @Trace currentAccount 的全局账号存储与账号校验服务，页面由不同切片分别接线。
- [退出登录按源端清理范围执行：停止并等待同步，单事务清空账号业务表，再广播数据变化](lesson-8b8e304a737e9fded451.lesson.md)
  - 时机：账户域实现与重构计划阶段，确定退出登录、账号注销或游客重建要清理哪些本地状态时
  - 情境：源端退出除清 token 与账号偏好外还清空本地业务库（如退出函数调用整库清理）；仓库里可能已有规格写明退出前停同步并清理账号业务数据；目标把会话清理拆到仓库与宿主桥接，已有实现只删偏好与登录态。
