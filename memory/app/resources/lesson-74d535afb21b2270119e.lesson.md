# Compose Material 图标（Icons.Rounded、AutoMirrored.Rounded 等变体）从可核来源提取同变体 pathData 并登记来源，不凭记忆写路径标称官方

ID：`lesson-74d535afb21b2270119e` · 版本：3

[本主题](index.md)

## 何时使用

资源迁移或页面转换阶段，为源码引用的 Material 库图标生成目标 SVG 资源时

## 适用情境

源码通过 Compose Icons.Rounded.*、Icons.AutoMirrored.Rounded.*（或 Outlined、Sharp 等变体）引用 material-icons 库矢量，工程 res 下没有对应 drawable；派工要求使用官方 path 数据、缺失写 MISSING 占位；本机可能有 Android Studio 自带的 android.jar 或 Gradle 缓存中的 material-icons 包，生成环境能否读取需当场确认。 也包括 Icons.Outlined、Icons.Filled 等常规变体，而资源 skill 的参考把下载源指向 Material Symbols。

## 原因

同名图标的各变体几何不同：Rounded 的线端与拐角是圆弧，Filled/baseline 是直角折线。记忆中的路径多为 baseline 形状；凭记忆写入并标成官方 rounded 后，映射表与派工都显示已完成，偏差只在逐个比对几何时暴露。

## 做法

1. 按源码引用的变体与名称取矢量，例如 android.jar 中 images/material/icons/materialiconsround/<name>/round_<name>_24.xml 的 pathData，或 Gradle 缓存中的 material-icons 包；把来源路径写进资源映射表。下载 SVG 时取 Material Icons 字形（如 google/material-design-icons 的 materialicons、materialiconsoutlined 目录，viewBox 0 0 24 24），不取 Material Symbols（materialsymbols*，viewBox 0 -960 960 960）；参考文档给出 Symbols 地址时同样按此纠正。
2. Gradle 缓存的 material-icons-core/extended AAR 里，图标是编译进 class 的 PathBuilder 调用，没有 pathData 字符串：从中取路径就是按调用序列重建，映射要覆盖 PathBuilder 的全部路径方法（含 arcTo/arcToRelative → A/a，参数依次为两个半径、旋转角、isMoreThanHalf、isPositiveArc（布尔写 0/1）、终点）；遇到没有映射的调用就报错停止，不跳过；写完逐个检查产物，没有只含 M/m、不绘制的子路径，每个图标解析到的路径调用数等于输出指令数。
3. 可核来源取不到时，按派工写 MISSING_<name> 占位或登记为近似替代，不标“官方”。

## 可选检查

- 抽检一两个图标的变体特征：Rounded 版线端与拐角由弧段（c、a 指令）构成；Filled 版为直角折线，如 check 为 M9 16.17L4.83 12l-1.42 1.41L9 19 21 7l-1.41-1.42z。抽检只能核变体特征，证明不了重建完整：从字节码重建时，与官方 SVG 比对的样本要覆盖实际出现过的每类指令（含弧段），比对出的差异先排除比对器与转换器自身的问题，再记为版本差异。
