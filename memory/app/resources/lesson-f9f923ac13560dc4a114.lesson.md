# 语言限定目录只放源端 values-<locale> 实际有的资源类型：不为补齐键集审计把 base 的颜色、尺寸、布尔、整数文件复制进语言目录

ID：`lesson-f9f923ac13560dc4a114` · 版本：1

[本主题](index.md)

## 何时使用

资源迁移收口阶段，i18n 或资源完整性审计报告语言目录缺键、缺文件，决定如何补齐时；编写按 base 批量补齐限定目录的脚本时

## 适用情境

Android 源的 values-<locale> 通常只有 strings、arrays、plurals；HarmonyOS 目标按语言目录放 element JSON，base 之外还有 horizontal、dark、ldpi 等配置目录覆盖颜色与尺寸；审计脚本以“base 键集合＝每个语言目录键集合”为门槛，findings 列出具体缺失键与所在文件。

## 例外与边界

- 源端该语言目录本身定义了颜色、尺寸等非文字资源（如 values-<locale>/dimens.xml），此时按源端镜像该文件

## 原因

HarmonyOS 资源匹配时语言（区域）限定词优先于横竖屏、屏幕密度等限定词（HarmonyOS 开发文档「资源分类与访问」的限定词匹配优先级：区域高于横竖屏、设备类型、颜色模式、屏幕密度）。把 base 的 color、float、boolean、integer 整份复制进语言目录后，设备语言匹配时这些副本压过 horizontal、ldpi 等目录的覆盖值，base 之后的改动也不再生效；审计门槛只看键是否齐全，副本让审计通过而运行时取值改变。

## 做法

1. 补审计缺项时按 findings 的具体键与文件类型逐项处理：该键在源端对应 values-<locale> 中存在才写入它所属的文件（string.json、strarray.json、plural.json），源端缺键就保持缺失、回落 base；不写“base 有而语言目录没有的文件就整份复制”的通配脚本。
2. 语言目录只放源端 values-<locale> 实际存在的资源类型；颜色、尺寸、布尔、整数留在 base 与 horizontal、dark、ldpi 等配置目录。审计把非文字资源报为缺失时，修正审计范围或按 base 回退语义接受，不靠复制文件消除。
