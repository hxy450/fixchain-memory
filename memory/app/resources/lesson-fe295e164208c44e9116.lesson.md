# 字符串资源以含依赖库的合并资源表为全集：先构建 APK 取合并资源，构建不了按依赖并入库 values-*，不把模块 res/ 当全集

ID：`lesson-fe295e164208c44e9116` · 版本：1

[本主题](index.md)

## 何时使用

资源迁移阶段，确定字符串资源与语言目录的来源范围时

## 适用情境

源工程依赖 appcompat、material、preference 或三方 UI 库（日期选择器、对话框库等），部分界面文案与语言由库资源提供；资源转换 skill 规定先构建 APK 并反编译或 aapt2 取合并资源表；仓库里没有现成 APK，转换脚本只解析模块 src/main/res。

## 原因

合并资源表包含依赖库的字符串和语言目录，库还可能提供源模块没有的语言；只解析模块 res/ 会丢掉库文案与这些语言，缺项再按键集一致被补译填平，就写出源端不存在的译文。

## 做法

1. 按资源转换 skill 的顺序先执行 Gradle 构建（所选 flavor 与 buildType），用 apktool 反编译或 aapt2 dump 取合并资源表，作为字符串与语言目录的全集。
2. 构建确实失败时，从 build.gradle 解析依赖坐标，在本机 Gradle 缓存（~/.gradle/caches）取对应 aar 的 res/values-* 并入；仍取不到的库在资源映射报告逐项列为缺失，不以“构建跳过”收口。
3. 语言目录按合并资源表实际存在的语言镜像，库独有的语言目录也迁；源与库都没有译文的键保持缺失、回落 base。

来源支持：1 张卡 · 迁移数未记录 · 应用数未记录
