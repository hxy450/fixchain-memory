# 埋点门面经 SPI 引擎列表广播时，自有服务端上报引擎按源码移植并注册；三方统计 SDK 的裁剪不覆盖它

ID：`lesson-dc3ac0500599ef7c9636` · 版本：1

[本主题](index.md)

## 何时使用

实现阶段处理埋点上报引擎（门面加引擎 SPI）的移植或其前向占位，决定当场移植还是延后时

## 适用情境

源端埋点门面把事件广播给多个引擎实现，其中一条是自有服务端上报（批量 POST 自有日志端点），另一些是没有鸿蒙版本的三方统计 SDK；目标规格只写“事件收束到自建埋点服务”，feature API 表未列上报端点，决策账本裁剪了三方 SDK。

## 原因

把三方 SDK 的裁剪决策套到全部统计出口，或以“规格没写端点”为由不移植，门面与 SPI 齐备而引擎列表为空，所有埋点静默 no-op，编译与结构检查都会通过。

## 做法

1. 遇到点名源端引擎实现类的占位，先读该类及其接口声明（ApiService、URL 常量），取得端点、请求体、批量阈值、开关门控与失败语义，按源码移植并在门面初始化处注册；feature API 表漏列端点不是留空依据。
2. 只把确实依赖缺失三方 SDK 的引擎登记为裁剪；交付前 grep 引擎接口的实现类与注册调用，两者有一项为零时在本阶段实现或升级为阻塞项。
