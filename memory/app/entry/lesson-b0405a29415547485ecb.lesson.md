# 源端返回栈靠 rememberNavController 或 savedInstanceState 在进程回收后恢复时，规格单列“回收后重建”分支，目标显式开启 UIAbility 恢复与 Navigation recoverable

ID：`lesson-b0405a29415547485ecb` · 版本：1

[本主题](index.md)

## 何时使用

规格提取阶段为宿主 Activity 生命周期与导航容器编写验收项时；入口装配阶段实现 UIAbility 与根 Navigation 时

## 适用情境

源 Activity 在 onCreate(savedInstanceState) 接收存档，或用 Compose rememberNavController + NavHost（以及 Fragment 返回栈）承载页面；源码里没有显式保存代码，进程在后台被系统回收后，返回栈与路由参数由框架恢复。目标为 UIAbility + Navigation/NavDestination + NavPathStack，页面栈恢复默认不开启，入口每次 loadContent 首页并在空栈时 push 起始页；规格只写“冷启进入起始页”。

## 原因

rememberNavController/NavHost 与 savedInstanceState 让源应用在后台回收后回到原页面和参数，这是不靠显式代码的用户可见行为；把带存档的重建入口收窄成冷启，目标回收后只会回到起始页。来源修复中只开 setRestoreEnabled 与 recoverable 时，APP_RECOVERY 拉起后仍未恢复，补 restoreWindowStage 后才生效。开启恢复后路由参数经序列化还原为同形普通对象，按类实例判断参数的接收端会失效。

## 做法

1. 规格提取时，源宿主用 rememberNavController/NavHost 或在 onCreate 接收 savedInstanceState，就在生命周期/导航节单列“进程回收后重建”分支：写明要恢复哪些返回栈页面与路由参数、计时等进行中的会话如何接续，以及目标平台的对应决策；不只写“冷启进入起始页”。
2. 需要页面栈恢复时（来源在 API 24 SDK 上实现）：EntryAbility.onCreate 调用 context.setRestoreEnabled(true)；launchReason 为 AbilityConstant.LaunchReason.APP_RECOVERY 时调用 context.restoreWindowStage(new LocalStorage())，并实现 onWindowStageRestore 加载同一入口页；根 Navigation 设 id 与 recoverable(true)，每个 NavDestination 设 recoverable(true)。
3. 可恢复页面的路由参数只用可序列化的普通字段，接收端按字段结构识别（如 typeof recipeId === 'number'），不用 instanceof 判断参数类实例。

## 可选检查

- 对恢复链路有疑问时，进入详情页后让应用进程在后台被回收再重新进入（来源修复期以 aa force-stop 后重启触发），确认 launchReason 为 APP_RECOVERY，且页面栈与参数都已还原。

来源支持：1 张卡 · 1 次迁移 · 1 个应用
