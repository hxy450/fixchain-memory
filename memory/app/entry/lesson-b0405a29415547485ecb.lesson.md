# 源端返回栈靠框架在进程回收后重建时，规格单列“回收后重建”分支，目标开启 UIAbility 恢复与 Navigation recoverable

ID：`lesson-b0405a29415547485ecb` · 版本：4

[本主题](index.md)

## 何时使用

规格提取阶段为宿主 Activity 生命周期与导航容器编写验收项、为“进程回收后重建”铸平台差异决策时；入口装配阶段实现 UIAbility 与根 Navigation 的恢复路由时

## 适用情境

源 Activity 在 onCreate(savedInstanceState) 接收存档，或用 Compose rememberNavController + NavHost 承载页面，源码里没有显式保存代码，进程在后台被系统回收后返回栈与路由参数由框架恢复。也包括 View 体系的 Activity 任务栈（TaskStackBuilder 建出 [主页, X]、页面参数来自 Intent extra）：进程被系统回收而任务仍在时框架重建整栈，重建页拿原始 Intent。目标为 UIAbility + Navigation/NavDestination + NavPathStack，页面栈恢复默认不开启；规格可能只写“冷启进入起始页”，或把回收重入合并进每次冷启动。

## 例外与边界

- 源 Manifest 给相关 Activity 设了 clearTaskOnLaunch、finishOnTaskLaunch 或 noHistory 时，重回任务不会恢复这些页面，按这些属性迁移

## 原因

rememberNavController/NavHost、savedInstanceState 与任务栈重建让源应用在后台回收后回到原页面和参数，这是不靠显式代码的用户可见行为；把带存档的重建入口收窄成冷启，目标回收后只会回到起始页。反过来，把“回收后重入”扩成每次冷启都恢复、只恢复最后一页或改写参数，冷启动会直接进内页、返回露出空白宿主，参数也与源端不同。目标的恢复链由几处配置共同决定：只开 setRestoreEnabled 与 recoverable、APP_RECOVERY 拉起时不调用 restoreWindowStage，页面栈不会恢复；开启恢复后路由参数经序列化还原为同形普通对象，按类实例判断参数的接收端会失效。

## 做法

1. 规格提取时，源宿主用 rememberNavController/NavHost、在 onCreate 接收 savedInstanceState，或依赖任务栈重建，就在生命周期/导航节单列“进程回收后重建”分支：写明要恢复哪些返回栈页面与路由参数、计时等进行中的会话如何接续，以及目标平台的对应决策；不只写“冷启进入起始页”。
2. 铸恢复决策时把触发条件写成“系统回收进程且任务仍在”：先读源 Manifest 的 clearTaskOnLaunch、finishOnTaskLaunch、noHistory，并注明从桌面隔较长时间重入时系统可能按 alwaysRetainTaskState 的说明重置任务（platforms/android-*/data/res/values/attrs_manifest.xml）；目标在 EntryAbility.onCreate 按 launchParam.lastExitReason（PERFORMANCE_CONTROL、RESOURCE_CONTROL）或 launchReason APP_RECOVERY 判定，其余冷启按启动分流。
3. 恢复时按源端任务栈恢复整栈并保留每页入栈时的参数（写“原始 Intent 值”前对照已读的 putExtra 逐项核对），不只恢复最后一页、不改写参数。
4. 需要页面栈恢复时：EntryAbility.onCreate 调用 context.setRestoreEnabled(true)；launchReason 为 AbilityConstant.LaunchReason.APP_RECOVERY 时调用 context.restoreWindowStage(new LocalStorage())，并实现 onWindowStageRestore；根 Navigation 设 id 与 recoverable(true)，每个 NavDestination 设 recoverable(true)，以项目 d.ts 的 @since 对照 compatibleSdkVersion；自行持久化路由栈时同样持久化整栈。
5. 可恢复页面的路由参数只用可序列化的普通字段，接收端按字段结构识别（如 typeof recipeId === 'number'），不用 instanceof 判断参数类实例。

## 可选检查

- 对恢复链路有疑问时：进入内页后让应用进程在后台被系统回收再重新进入，确认页面栈与参数都已还原；强停、从最近任务划掉、覆盖安装后重启，在目标版本设备上核对 lastExitReason 并确认走冷启分流（已观察：强停为 NORMAL、覆盖安装为 UPGRADE）。
