# 源 Activity 的 SEND 分享接收入口（standard 启动、无 onNewIntent）映射为独立 multiton Ability：skills 用 sendData 加 utd 声明，结束只 terminateSelf 本实例

ID：`lesson-51651155ed8226212e55` · 版本：1

[本主题](index.md)

## 何时使用

规格提取与入口配置阶段，把源端 ACTION_SEND/SEND_MULTIPLE 接收入口映射为目标 Ability 的实例形态、module.json5 skills 声明与结束范围时；接线阶段给入口 Ability 加分享解析或结束逻辑时

## 适用情境

源 AndroidManifest 在某 Activity（常是 LAUNCHER）上另有 SEND + DEFAULT + mimeType（如 text/plain）的 intent-filter，未声明 singleTop/singleTask/singleInstance，源码没有 onNewIntent，只在 onCreate 读 EXTRA_TEXT 等处理，结束时 finish()。目标工程只有入口 EntryAbility（launchType 默认 singleton），外部数据经系统分享面板送达，接收方用 systemShare.getSharedData 读取。

## 例外与边界

- 源 Activity 声明 singleTop/singleTask/singleInstance 或实现 onNewIntent 承接分享：按源端复用实例的语义映射到已有 Ability 的 onNewWant

## 原因

standard 启动的 Activity 每次被分享调起都由框架新建实例，finish() 只结束这个实例并回到来源应用，原来运行的应用不受影响；映射成唯一 EntryAbility 的 onCreate/onNewWant 冷热启动承接后，结束分享流程的 terminateSelf 会关掉整个应用，热启动还要另设全局事件槽。系统分享面板按 UTD 匹配接收目标：把源 mimeType 写成 skills uris 的 type 时，应用不会出现在分享面板里。

## 做法

1. 规格写明实例形态：每次外部分享新建实例、结束只结束该实例。目标用独立 UIAbility（exported、launchType: multiton），加载同一页面，经 loadContent 的 LocalStorage 把分享内容交给页面，结束时在该实例上 terminateSelf；入口 EntryAbility 只保留桌面入口。
2. skills 写 actions ['ohos.want.action.sendData']，uris 每类数据一条 {scheme: 'file', utd: <源 MIME 对应的 UTD，text/plain 为 general.plain-text>, maxFileSupported: N}；写前查本机 SDK toolchains/modulecheck/module.json 中 skills.uris 的字段。接收方用 systemShare.getSharedData(want) 按记录的 utd 取内容，与 skills 声明一致。

## 可选检查

- 从另一个应用打开系统分享面板，确认看到并选中本应用后新开任务；导入或取消后原应用界面仍在前台。
