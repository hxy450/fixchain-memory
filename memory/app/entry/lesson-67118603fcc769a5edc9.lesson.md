# 静态快捷方式 ohos.ability.shortcuts 挂所属 UIAbility 的 metadata，不写 module 级字段

ID：`lesson-67118603fcc769a5edc9` · 版本：2

[本主题](index.md)

## 何时使用

配置实现阶段，在 module.json5 中挂载桌面长按快捷菜单（ohos.ability.shortcuts）时；构建后长按不出菜单或快捷方式条目变少时

## 适用情境

把 Android App Shortcuts 迁为 HarmonyOS 静态快捷方式：在 resources/base/profile 下新建快捷方式配置，并在 module.json5 中用 metadata 引用；module 级已有 metadata 数组（如 client_id），入口 UIAbility 还没有 metadata。 也包括凭记忆在 module.json5 写 module 级 shortcuts 字段，编译报 schema 不允许该属性。

## 原因

快捷方式配置只对在 abilities 里声明了该 metadata 的 UIAbility 生效。就近追加到 module 级 metadata 时长按不出菜单；来源工程的构建插件还把 module 级引用的配置改写成单个 newShortCutObj，4 条只剩 1 条，生成者转去追查插件而没回头核对层级。网络摘要常只写“通过 metadata 挂载”而不讲层级。

## 做法

1. 在 module.abilities 中目标 UIAbility（通常是 EntryAbility）的 metadata 下写 { name: "ohos.ability.shortcuts", resource: "$profile:<配置名>" }；该 ability 没有 metadata 数组就新建，不顺手追加到 module 级已有的 metadata。
2. 资料只说“通过 metadata 挂载”时，以官方或离线 module.json5 文档 shortcuts 一节的示例 JSON 路径为准，写完逐级比对自己的写入位置。
3. 编译报 module.json5 schema 不允许某字段时，先在 SDK 文档查该功能的承载位置（静态快捷方式即上述 ability metadata），不以删除功能块、改记缺口的方式通过编译。

## 可选检查

- 构建后在编译产物的 module.json 中确认该 metadata 位于目标 ability 下，HAP 内快捷方式配置仍是 {shortcuts:[...]} 且条数与源文件一致；出现 newShortCutObj 或条目减少，先回查 metadata 层级再查打包插件。
