# 源 Activity 为 standard、目标入口为 singleton 时，onNewWant 送达的外部请求要被已存在页面观察并重放

ID：`lesson-dc66a65d3ec6e3619046` · 版本：1

[本主题](index.md)

## 何时使用

规格提取与入口接线阶段，确定第三方拉起请求（拍摄、选择等带结果回传的 Want）在已运行实例上的承接方式，以及设计 Want 快照的写入点与消费点时

## 适用情境

源 Activity 未声明 launchMode（standard）且没有 onNewIntent，每次外部请求都新建实例、在 onCreate 一次性读取 Intent extras 并经自己的结果通道回传；目标沿用 singleton 入口 UIAbility，新 Want 经 onNewWant 到达已运行实例，Want 解析写进共享快照，页面或 ViewModel 只在构造时读取一次。

## 例外与边界

- 每次外部请求已由独立的 multiton Ability 实例承接、每个实例只处理自己的 Want 时，不需要本条的重放与失效处理

## 原因

standard 启动下每个外部请求都有新实例、新的 getIntent 与独立结果通道；singleton 只把新 Want 交给 onNewWant。快照只在构造期被拷贝一次时，热启的新请求只更新快照，模式、参数、输出位置与结果回传仍沿用旧请求，旧请求的结果还可能回给新的调用方。

## 做法

1. 规格把“已运行时收到新拉起 Want”列为与冷启动 onCreate 分开的场景，写出新请求覆盖旧请求时的可观察结果。
2. onNewWant 写入的请求快照带递增修订号；已存在的页面或 ViewModel 用 @Monitor 或回调观察它，不只在构造时拷贝一次。
3. 观察到新修订后，先结束旧请求进行中的工作（采集、录制、保存等），再按新 Want 重跑入口判定（模式、参数、输出位置）；切换期间禁止交互，结果出口按修订号丢弃旧请求的回传。
