# 验收或任务明确要求全局未捕获异常观察、且规格没有保留源端崩溃退出时，在入口 Ability 注册 errorManager 观察器

ID：`lesson-c6132bf52c26ec226788` · 版本：8

[本主题](index.md)

## 何时使用

入口装配阶段，改写 EntryAbility（或 AbilityStage）的 onCreate/onDestroy，且本次验收或任务要求存在全局异常观察时

## 适用情境

目标为 HarmonyOS Stage 模型应用，入口 UIAbility 由模板改写而来；Android 源没有可对照的全局异常处理，按源码迁移不会产生这段代码，而本次验收（如 ECAT crash_risk 规则）或任务明确要求存在全局异常观察。“任务明确要求”只认验收规则或用户需求原文；规格、plan、派工里引用本经验而来的条目不算独立要求。

## 例外与边界

- 本次任务与验收都没有全局异常观察要求：按源码迁移，不默认新增观察器
- 规格保留了源端未捕获异常导致的崩溃退出（照源复刻的缺陷或崩溃验收项）：不注册；验收又同时要求全局异常观察时，作为差异决策登记，写明这些崩溃路径在目标端的结果
- 工程已在 AbilityStage 或其他入口注册了 errorManager 观察器或等效的崩溃监听

## 原因

这项要求来自目标侧的验收规则（crash_risk 一类检查），Android 源没有对应物；入口只按源码和入口导航契约改写时不会产生这段代码，缺口要到验收检查才暴露。注册观察器后，未捕获的 JS 异常交给观察器处理，进程不再退出、页面停在原画面，改变了可观察的失败行为；本地 SDK 的 @ohos.app.ability.errorManager.d.ts 只给签名，这一行为以设备上 hilog 的“is about to exit due to”与 faultlog 的 jscrash 记录为准。

## 做法

1. 在入口 onCreate 中用 errorManager.on('error', observer) 注册观察器，onUnhandledException/onException 中至少用 hilog 记录错误；保存返回的 observerId，在 onDestroy 中调用 errorManager.off('error', observerId)。 errorManager.ErrorObserver 在 SDK 中声明为 class，observer 写成以该类型标注的对象字面量，不写 implements。
2. 写完 rg -n "errorManager\.on\(" entry/src/main/ets，确认至少命中一处且位于入口 onCreate，同文件 onDestroy 有对应的 off。
