# 源端“先读当前系统值、再按位移增量写回”的手势（如亮度）分别映射读写两侧；异步读取在页面就绪时预读基线

ID：`lesson-33791daf74fc4298779e` · 版本：4

[本主题](index.md)

## 何时使用

界面实现阶段，把源端按下时读取窗口亮度等系统值、移动时按增量写回的手势迁到鸿蒙时

## 适用情境

源端手势在 ACTION_DOWN 读取窗口当前亮度，未覆写时回退系统亮度设置，移动时按位移增量写回窗口；规格只给出写入接口（setWindowBrightness），读取侧要实现者确定。

## 原因

只映射写入侧并凭记忆认定没有读取接口，首次拖动的基线只能写死常量，亮度从固定值跳变；读取接口可能是属性式（窗口属性集合）或设置模块的键，按对称 getter 名检索查不到。

## 做法

1. 读取侧按能力语义检索 SDK：窗口属性集合（Window.getWindowProperties().brightness）与设置模块的显示亮度键（settings.display.SCREEN_BRIGHTNESS_STATUS，@ohos.settings.d.ts 定义取值 0–255，需归一化）。回退条件照源端代码原样迁移；源端按框架语义判断时，只有窗口值小于 0（未覆写，WindowManager.LayoutParams 的默认值）才回退系统值，0 是有效的最低亮度（BRIGHTNESS_OVERRIDE_OFF），不当作未设置。目标侧按 WindowProperties 文档的取值约定判断（OpenHarmony docs arkts-apis-window-i.md，2026-10-15 访问；本机 @ohos.window.d.ts 未写取值）：未设置、跟随系统时 brightness 读到 -1，回退系统设置值作基线；[0, 1] 内的值（含 0）是有效窗口亮度，直接作基线；其他值视同窗口读取失败，走系统设置读取。设备读值与该约定不符时，先核对实际系统版本再定判据。
2. 读取接口为异步时在页面就绪时预读基线，让手势回调保持同步；常量兜底只用于所有读取都失败，并在注释中标明。
