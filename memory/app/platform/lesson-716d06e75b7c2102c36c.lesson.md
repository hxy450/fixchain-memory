# 源端通知按钮与可空正文迁到 WantAgent 与 NotificationRequest：每个按钮、每次构建用不同 requestCode，并按需加 UPDATE_PRESENT_FLAG；正文不直接给空串

ID：`lesson-716d06e75b7c2102c36c` · 版本：1

[本主题](index.md)

## 何时使用

实现阶段，把源端通知的多个 PendingIntent 动作按钮与可为 null 的 setContentText 映射为 wantAgent.getWantAgent 与 NotificationRequest 时

## 适用情境

源端每次构建通知都给按钮取不同的 requestCode（如逐次取 elapsedRealtime），按钮 Intent 载荷随运行状态变化；部分通知（完成通知、没有文本的步骤）contentText 为 null。目标用 WantAgentInfo（wants、operationType、requestCode、wantAgentFlags）与 NotificationBasicContent（title、text）发布。

## 原因

多个按钮或多次构建共用同一 requestCode、又不设刷新标志时，同一 Want 对应的 WantAgent 可能沿用旧参数，按钮触发的动作与当前状态不符。NotificationBasicContent.text 的声明注释写明内容不可为空，只看签名 text: string 会以为空串可用。这两点来自 SDK 注释与源码对照，来源材料中没有设备上的发布失败日志，也没有按钮串载的复现。

## 做法

1. 每个按钮、每次构建分配不同的 requestCode（递增计数，或沿用源端的取值方式）；需要刷新载荷时，在 wantAgentFlags 加 UPDATE_PRESENT_FLAG。
2. 源端正文可为 null 时按“不可为空”处理：用不可见占位字符（如零宽空格），或改用不依赖空正文的内容形态；完成通知和各类无正文的通知分别核对。
