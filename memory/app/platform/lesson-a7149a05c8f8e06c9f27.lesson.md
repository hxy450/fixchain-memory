# 源端通知构造迁到 NotificationRequest 时，按源端构造代码逐字段映射正文与渠道；可空正文不直接给空串

ID：`lesson-a7149a05c8f8e06c9f27` · 版本：1

[本主题](index.md)

## 何时使用

实现阶段，把源端 NotificationCompat.Builder 的正文、标题、进度与通知渠道映射为 NotificationRequest 与通知槽时

## 适用情境

源端在构造通知的函数里拼接正文（如进度、数量与步骤时长）、创建具名通知渠道（NotificationChannel，含重要度），部分通知（完成通知、没有文本的步骤）的 setContentText 为 null；目标用 NotificationBasicContent（title、text）与通知槽发布，实现者为展示自定义了快照字段。

## 原因

重写通知时容易只套一个字符串模板，漏掉源端正文中的部分字段，自定义的快照字段也没被消费；目标不支持具名渠道时若不声明替代，渠道语义静默丢失。NotificationBasicContent.text 的声明注释写明内容不可为空，只看签名 text: string 会以为空串可用（依据为 SDK 注释，尚无设备上的发布失败日志）。

## 做法

1. 读源端构造正文与渠道的代码，逐字段列出正文、标题、进度与渠道（id、名称、重要度）；目标通知逐项对应，快照里为展示定义的字段要在渲染处消费，用不上就删除并说明。
2. 目标 SDK 不支持具名渠道时，把“源渠道 id、名称、重要度 → 目标槽类型与级别”写成显式映射，并在交付说明中声明这项替代。
3. 源端正文可为 null 时按“不可为空”处理：读 NotificationBasicContent 的 d.ts 注释（不用 grep -v 去掉 JSDoc），用不可见占位字符（如零宽空格）或改用不依赖空正文的内容形态；完成通知与各类无正文的通知分别核对。零宽占位能否通过发布校验、显示是否干净尚未在设备上验证，有设备时发布一次确认，不行就改用其他内容形态。
