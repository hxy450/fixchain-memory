# 激励广告等能力门禁挡在核心功能入口前时，区分“用户未获奖励”与“广告能力不可用”：不可用时显式提示并按台账放行，不伪造奖励

ID：`lesson-0f67121af7969203b76b` · 版本：1

[本主题](index.md)

## 何时使用

规格、巡检出单与接线实现阶段，为“先看激励广告、奖励回调后才导航”的入口确定各广告结果的去向时

## 适用情境

源端功能入口先调起激励视频，仅在 onReward 回调后导航；目标端没有等价广告 SDK 或广告 provider 未装配，showRewarded 一类接口恒返回 unavailable；决策台账同时要求“能力不可用时显式失败、不伪造 SDK 成功”和核心功能流程真实可用，且没有对这些入口批准“不可用即阻断”。

## 例外与边界

- 台账对该入口明确批准“仅获得奖励才可继续”（如只对奖励用户开放的增值功能），此时按该决策阻断，并显示不可用原因

## 原因

“不伪造成功”约束的是结果如实上报，不决定入口是否放行。把 unavailable 与用户关闭、播放失败并列为“未授予”并统一 return，在广告能力不存在的构建上就把依赖门禁的核心功能永久锁死；反过来把 unavailable 静默并入“继续”，又丢掉了不可用状态。来源中巡检单把台账的失败语义写成“仅 rewarded 放行、否则不导航”，修复者照单落码，三个核心工具入口点击后只出提示、停在首页。

## 做法

1. 把门禁结果拆成三类：rewarded 放行；用户关闭或播放失败按源端不放行；广告能力不可用（provider 未装配、平台无等价）先显式提示不可用，再按台账的核心流程范围继续导航，结果仍记为 unavailable，不伪造 rewarded。
2. 判断某入口能否在不可用时阻断，先查台账有没有点名该入口“仅获得奖励可继续”的专门决策；没有专门决策而总则要求核心流程真实可用时，不把不可用分支写成锁死入口。

## 可选检查

- 需要核对时，在未装配广告 provider 的构建上逐个点击门禁入口：应先看到不可用提示再到达目标页；关闭或失败的广告结果仍不导航。
