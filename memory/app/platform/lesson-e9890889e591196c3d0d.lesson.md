# Android 依赖厂商 SDK（地图、登录、支付、账号等）时，先查鸿蒙系统 Kit 与厂商 ohpm 包，再在 Kit、厂商包、H5 与受控降级之间取舍；查证前不写“鸿蒙无等价”

ID：`lesson-e9890889e591196c3d0d` · 版本：2

[本主题](index.md)

## 何时使用

规格提取与迁移规划阶段，为三方 SDK 作依赖决策、判断是否“鸿蒙无等价”、为对应切片绑定 SDK 文档类 skill 时；实现阶段遇到规格要求的 SDK 能力而工程里还没有 SDK 时

## 适用情境

Android 工程直接依赖厂商 SDK（com.amap.api.* 一类），功能规格与接口清单写明这些能力；项目 skill 映射表把该厂商列为 SDK 文档查询类 skill 的典型对象；用户在决策问答中没有提供鸿蒙 SDK 资料，只回复“采用建议”。也包括微信 OpenSDK 登录与支付（ohpm 有 @tencent/wechat_open_sdk）、华为账号（系统 @kit.AccountKit 提供）这类被规格或决策表与其他三方 SDK 并列为占位候选的能力，而 skill 映射表已把它们绑定到登录、支付 skill。

## 例外与边界

- 已查明厂商没有鸿蒙版本，且决策记录写明了替代方案与理由

## 原因

不查厂商鸿蒙包就把整套能力登记为受控降级，后续切片只能写占位或本地替代（如用历史记录过滤代替 POI 搜索），交付后再补接入要重做服务层与页面。来源中规则已要求用户无资料时标 needs_doc_lookup 并查公开文档与 SDK 仓库，规划者只问了用户是否有资料，拿“采用建议”关闭了可用性核查；生成后评估代理几分钟就在厂商官网查到 ohpm 上的鸿蒙包，Key 需按鸿蒙签名另行申请这一前置条件也此时才浮现。另一应用中规格作者未查 ohpm 就写下“鸿蒙无微信 OpenSDK”，计划把整条登录与支付链登记为待入仓占位，依赖、querySchemes 与回调路由都没有写者；华为账号由系统 Kit 提供，却被归为“三方无等价”，还登记了“SDK 入仓”这种永远不会满足的触发条件。修复期 ohpm CDN 曾被 TLS 阻断，改用本地 HAR。

## 做法

1. Android 依赖命中厂商 SDK 时，先查厂商鸿蒙文档与 ohpm 包名、版本（如 @amap/amap_lbs_common、map3d、search、location、navi），结论写进决策记录的事实段；用户未提供资料只意味着需要继续查，不作为关闭依据。
2. 查到厂商鸿蒙包时，决策写明依赖包、版本与前置条件（如 Key 须按鸿蒙签名 App ID 申请，放本地配置、缺失时显式失败），把 Key 列为待用户提供项，不把整套能力登记为 deferred。
3. 切片计划按规格中的厂商 SDK 关键词绑定对应 SDK 文档类 skill，并把依赖声明与初始化列入范围；实现时 SDK 仍缺位就登记三方 SDK 占位或回报计划缺口，不用本地替代静默顶替并当作满足验收。
4. 规格写“无等价”前查 ohpm 与厂商鸿蒙状态，并判断能力是否由系统 Kit 原生提供（如华为账号 → @kit.AccountKit 的 HuaweiIDProvider 授权码流程）；查询结果写进规格，未查证只标“待确认”。
5. 计划阶段 SDK 命中 skill 映射（如微信登录、支付 → 登录、支付 skill）时不登记三方 SDK 占位，把 oh-package 依赖、module.json5 的 querySchemes、EntryAbility onCreate/onNewWant 中的 handleWant 与回调分派列为有写者的任务；执行时载入的 skill 说明 SDK 可得、登记表却写着“待入仓”，在回报中提出冲突。网络受限装不上时记录包名、版本与本地 HAR 等获取方式，仍按真实依赖规划。
6. 运行期依赖 AGC client_id、证书指纹等配置时，先实现真实调用链，再把渠道可见性绑定到配置条件，不以恒返回 null 代替。
