# Android 依赖厂商 SDK（地图、登录、支付、账号）时，先查鸿蒙系统 Kit 与厂商 ohpm 包再定依赖，查证前不写“鸿蒙无等价”

ID：`lesson-e9890889e591196c3d0d` · 版本：4

[本主题](index.md)

## 何时使用

规格提取与迁移规划阶段，为三方 SDK 作依赖决策、判断是否“鸿蒙无等价”、为对应切片绑定 SDK 文档类 skill 时；实现阶段遇到规格要求的 SDK 能力而工程里还没有 SDK，或接入已决策的厂商 SDK（地图承载、Key 缺失时的行为）时

## 适用情境

Android 工程直接依赖厂商 SDK（com.amap.api.* 一类），功能规格与接口清单写明这些能力；项目 skill 映射表把该厂商列为 SDK 文档查询类 skill 的典型对象；用户在决策问答中没有提供鸿蒙 SDK 资料。也包括被规格或决策表与其他三方 SDK 并列为占位候选的能力：微信 OpenSDK 登录与支付（ohpm 有 @tencent/wechat_open_sdk，skill 映射表已把它们绑定到登录、支付 skill）、华为账号（系统 @kit.AccountKit 提供）。也包括源端 MapView 等地图视图，决策要求以平台地图能力或厂商鸿蒙 SDK 真实承载，Key、client_id 等配置尚未提供。

## 例外与边界

- 已查明厂商没有鸿蒙版本，且决策记录写明了替代方案与理由

## 原因

不查厂商鸿蒙包或系统 Kit 就把整套能力登记为受控降级，后续切片只能写占位或本地替代，交付后补接入要重做服务层与页面；系统 Kit 原生提供的能力被归为“三方无等价”，还会登记永远不会满足的“SDK 入仓”触发条件。Key 缺失只是运行期配置问题：把不可用适配器当作唯一实现、用静态图冒充地图，已批准的能力就从未接入。

## 做法

1. Android 依赖命中厂商 SDK 时，先查厂商鸿蒙文档与 ohpm 包名、版本（例：高德 @amap/amap_lbs_common、map3d、search、location、navi），并判断能力是否由系统 Kit 原生提供（例：华为账号 → @kit.AccountKit 的 HuaweiIDProvider 授权码流程，到 SDK 的 hms/ets/kits 检索），结论写进决策记录的事实段；用户未提供资料只意味着需要继续查。
2. ohpm 与厂商鸿蒙文档要实际查过；网络受限查不到时，写明已尝试的来源与失败原因，把该项列为未关闭的验证项（如 needs_doc_lookup）继续查，不写成“无等价”或降级决策。
3. 查到厂商鸿蒙包时，决策写明依赖包、版本与前置条件（如 Key 须按鸿蒙签名 App ID 另行申请，放本地配置），把 Key 列为待用户提供项，不把整套能力登记为 deferred。
4. 切片计划按规格中的厂商 SDK 关键词绑定对应 SDK 文档类 skill，并把依赖声明与初始化列入范围；SDK 命中 skill 映射（如微信登录、支付 → 登录、支付 skill）时不登记三方 SDK 占位，把 oh-package 依赖、module.json5 的 querySchemes、EntryAbility onCreate/onNewWant 中的 handleWant 与回调分派列为有写者的任务；载入的 skill 说明 SDK 可得而登记表写“待入仓”时，在回报中提出冲突。
5. 实现时 SDK 仍缺位就登记三方 SDK 占位或回报计划缺口，不用本地替代（如以历史记录过滤代替 POI 搜索）静默顶替并当作满足验收；网络受限装不上时记录包名、版本与本地 HAR 等获取方式，仍按真实依赖规划。
6. 已批准接入的 SDK 注册真实适配器：Key、client_id、证书指纹等配置缺失只让运行期返回不可用并显示真实状态（如“地图服务未配置”），不把不可用适配器作为默认且唯一的实现，也不以恒返回 null 代替；渠道可见性绑定到配置条件。
7. 源端地图视图落成真实地图组件（平台 Map Kit 或已决策的厂商 SDK）并绑定定位坐标，不以白底加标记图片冒充地图态；规格或计划把这类替代写成具体任务：目标组件与依赖、Key 注入方式、坐标系换算（GCJ-02 与 WGS-84）和未配置态验收。规格与计划汇总行矛盾时把缺口写入决策缺口，回执写明“未接入”，不报告该功能完成。
