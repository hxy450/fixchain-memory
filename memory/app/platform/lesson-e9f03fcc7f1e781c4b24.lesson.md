# 开关控制的常驻通知由应用级服务订阅与发布，不绑在页面 ViewModel 的激活周期上

ID：`lesson-e9f03fcc7f1e781c4b24` · 版本：1

[本主题](index.md)

## 何时使用

系统能力迁移阶段（规格提取与服务、ViewModel 实现），为由开关控制、由后台事件驱动的常驻通知确定订阅归属与生命周期时

## 适用情境

源端在页面初始化时注册一次事件监听且不注销，回调在开关为真时用固定 ID 更新 ongoing 通知；二级页的监听随页面注销且不发通知。目标主壳以条件渲染承载 Tab，或页面在 NavDestination 中出栈，页面 ViewModel 在 aboutToAppear/aboutToDisappear 激活、释放订阅。

## 原因

源端监听从未注销，通知实际随开关存活；目标页面被条件渲染卸载或出栈时订阅随之释放，切换 Tab 或冷启动后通知不再更新。规格里“按页面生命周期订阅、注销”的通用映射与“由单一通知服务更新”的条目并存时，实现者容易把两类消费者绑到同一页面周期；二级页再新增一个发布者，还会用不完整的数据覆盖通知。来源中生成期与修复期两次都把通知更新写进页面级回调，并新增了第二个页面级发布者，最终改为应用级服务后才稳定。

## 做法

1. 规格按消费者拆生命周期：列表、弹窗随页面；常驻通知随“开关 + 系统许可”，冷启动时若偏好开启即恢复，只有关闭开关才撤销，并指定唯一的发布服务。
2. 实现为应用级单例服务（启用、恢复、复核、释放）：在能力装配处按偏好恢复监听，回到前台复核系统许可；页面 ViewModel 只转发开关动作，离页不释放通知需要的订阅。
3. 写离页注销前查目标壳层的真实存活期（Tab 是否条件渲染、页面是否出栈）；源端只注册不注销时，不机械补“离页注销”。
4. 只在源端真正发布通知的回调对应处发布；二级页不新增发布者。

## 可选检查

- 开启提醒后切到其他 Tab、强停后冷启动，再触发连接、断开或电量事件，确认同一 ID 的通知仍在更新；关闭开关后通知撤销。
