# AlarmManager 到点通知改用代理提醒时，按 reminderAgentManager 自身接口落实按钮路由、贪睡与发布失败回退

ID：`lesson-5990184d75275f4df4ff` · 版本：1

[本主题](index.md)

## 何时使用

规格提取与服务实现阶段，把 AlarmManager 定时加自绘通知（按钮各带 PendingIntent）映射到 reminderAgentManager 或 notificationManager，并决定按钮路由、贪睡间隔、失败回退与到点副作用时

## 适用情境

源端用精确闹钟到点后自绘通知，按钮各带 PendingIntent（贪睡按偏好分钟重挂、改期弹选择器），到点在接收器里执行副作用并链式重挂下一次（如按 RRULE），动作可能经无 UI 的透明 Activity 分派；目标拟交系统代理提醒托管：reminderAgentManager.ActionButton 只有 title/titleResource/type，按钮级 wantAgent 只在 notificationManager 的 NotificationActionButton 上，ReminderRequest 提供 snoozeTimes/timeInterval 与提醒级 wantAgent，publishReminder 有条数上限与失败码，到点不回调应用。

## 原因

两个模块的按钮模型不同：把 NotificationActionButton 的 wantAgent 嫁接到代理提醒按钮上，规格写的按钮路由在实现时不可达，按钮只能退成系统关闭/贪睡型，源端各按钮的路由与参数丢失。系统托管也不在到点时刻回调应用，接收器里的副作用、链式重挂，以及超限、发布失败的处理若不在应用侧补，到点可能没有任何通知，或只发出首个发生。

## 做法

1. 规格逐字段对照目标模块自己的 d.ts（ActionButton、ReminderRequest、publishReminder 的 @throws），同一行写出可用手段与限制：按钮类型、提醒级 wantAgent、snoozeTimes/timeInterval、按钮状态订阅接口、有效提醒条数上限（API 24 上观察为单应用 30 条）、发布失败码与到点无回调，再决定应用侧回退。
2. 源端按钮需要各自的路由或参数时，用 notificationManager 本地通知的 NotificationActionButton.wantAgent 承载，或订阅代理提醒的按钮状态回调（API 24 SDK 为 subscribeReminderState）后按源分支处理；贪睡按源偏好设 timeInterval（单位秒，即偏好分钟×60）。
3. publishReminder 失败或超过条数上限时回退为应用侧本地通知或轮转登记，并保留源端在应用侧执行的到点副作用与链式重挂；实现时核出规格与 d.ts 冲突，就把受影响的验收标为阻塞并回报，不以系统型按钮“最大近似”收口。
4. 源端动作经无 UI 的透明 Activity 分派（如贪睡时长选择器）时，入口 Ability 保留它的独立任务、透明窗口与前后台语义：跟踪应用是否在前台，取消或时刻已过时用透明模态窗口提示，退后台时释放，不只在 onCreate/onNewWant 加一行分发。
