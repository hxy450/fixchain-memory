# 前台服务改用扩展能力承载前先确认三方应用能在目标设备启动它；type 与基类成对，backgroundModes 只写在 UIAbility

ID：`lesson-16c24b9a44153d703f04` · 版本：2

[本主题](index.md)

## 何时使用

后台服务迁移的规格、实现与编译/安装修复阶段，为源端 Foreground Service 选择承载类并在 module.json5 登记扩展能力时；因编译错误更换扩展基类时

## 适用情境

源端以 Service/LifecycleService 加 startForeground 承载长任务；目标准备用扩展能力类（如 AppServiceExtensionAbility）承载并在 module.json5 extensionAbilities 注册；规格、决策或文件头注释凭经验写了 ServiceExtensionAbility、type=service 或 backgroundModes，工程可能还不能编译。

## 例外与边界

- 目标改用 UIAbility 加长时任务（backgroundTaskManager.startBackgroundRunning）承载时，只在 abilities[] 的 UIAbility 声明 backgroundModes 与 ohos.permission.KEEP_BACKGROUND_RUNNING，不注册扩展能力

## 原因

扩展基类的可用性和 type 取值随 SDK 版本与导出范围变化，凭记忆写的类在当前 SDK 可能不存在；SDK 导出了也不等于三方应用能用它承载前台服务：startAppServiceExtensionAbility 声明了 801 Capability not supported 与调用方 appIdentifierAllowList 限制（UIAbilityContext.d.ts）。构建 schema 只校验字段是否合法，不校验类与 type 是否对应，错配要到真机安装才报 not allow use privilege extension。

## 做法

1. 选承载方式前，在项目 SDK 读候选扩展基类与对应启动接口的声明：类是否由 kit 导出（如 @kit.AbilityKit.d.ts）及其 @since，是否标 @systemapi，需要的权限，启动接口是否声明 801 Capability not supported 与调用方白名单限制，生命周期能否覆盖源任务；不能确认三方应用在目标设备类型上可启动时，改用 UIAbility 加 backgroundTaskManager.startBackgroundRunning 长时任务，不把扩展能力写成前台服务的默认替代。
2. 规格与决策把类名和 module.json5 的 type 成对写出：按 SDK toolchains/modulecheck/module.json 的 extensionAbilities type 枚举与基类 d.ts 核对后写定（如 AppServiceExtensionAbility 对应 appService，WorkSchedulerExtensionAbility 对应 workScheduler）；长时任务的 backgroundModes 写在 abilities[] 的 UIAbility 上，extensionAbilities 条目不加该字段。
3. 编译修复中更换扩展基类后，同步修改 module.json5 的 type、源文件头注释与交接里的注册说明；构建通过不代表类与 type 匹配，有设备时以安装结果为准。
