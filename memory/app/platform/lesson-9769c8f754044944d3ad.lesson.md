# 源端 Material You 动态取色迁到 HarmonyOS：用 wallpaper.getColors 探测并取种子生成明暗配色、订阅 colorChange，失败回退源端固定配色；该接口已弃用，决策写明风险

ID：`lesson-9769c8f754044944d3ad` · 版本：1

[本主题](index.md)

## 何时使用

规格决策与主题层实现阶段，迁移源端 dynamicLightColorScheme/dynamicDarkColorScheme（Android 12+ 才启用、否则回退固定配色）与“动态配色”设置项时

## 适用情境

源主题在 SDK_INT >= S 且设置开启时使用壁纸取色配色，否则用固定的 light/dark scheme；设置页有动态配色开关。目标公开 SDK 的 @ohos.wallpaper（@kit.BasicServicesKit 导出）提供 getColors(WallpaperType) 与 on('colorChange')；getColors 自 API 9 标记弃用，替代接口不在公开 SDK 中。

## 例外与边界

- 审批在“降级为固定配色”与“弃用接口 + 回退”之间选了前者，此时设置项按决策呈现并登记差异

## 原因

源码本身就是“能力可用才动态、否则固定”的结构，目标只要能探测到取色结果就能保留同一结构；凭记忆写“无取色 API”会删掉动态配色，设置开关也失去实际效果。getColors 已弃用：来源中修复期在一台真机上观察到取色生效，复审仍提示设备相关、置信度低，在其他设备和后续系统版本上是否可用未知。

## 做法

1. 决策中列出 getColors 的弃用状态、失败回退与真机验证项，由审批在“降级”与“弃用接口 + 回退”之间选择。
2. 选用取色时，在启动和 colorChange 回调中用 getColors 取壁纸主色作种子，按源端配色算法生成明暗两套色板（Material You 默认的 TonalSpot 方案可移植 material-color-utilities），放进可观察主题对象；设置开关与取色结果共同决定是否使用，取色失败或返回空时回退源端固定配色。
3. 设置项的可用状态绑定取色能力是否可用，不写成恒可用、无效果的开关。
