# 页面显示设置由应用壳下传时：占位初值取源端默认值常量而非 @Preview 实参，派生判定（如省流是否生效）在壳层算一次共享，多值枚举不按 0/1 判

ID：`lesson-0670bec94637c8ff8c28` · 版本：1

[本主题](index.md)

## 何时使用

页面转换与功能接线阶段，为由应用壳下传的显示设置确定初值、读取方式与激活判定时；数据模型阶段为设置列写类型与注释时

## 适用情境

Android 页面的显示设置是 Composable 必填参数，由主 Activity 从设置存储读取并下传（@Preview 里另有一组示例实参）；省流一类设置是 Auto/Always/Never 三值 ordinal 枚举，激活结果由应用壳统一计算一次；目标页面改为各自读取设置存储。

## 原因

@Preview 的实参只是预览示例，常与真实默认值不同；页面以“接线前取默认”为名写下这组本地副本，后来只接了一个字段，其余停在示例值。三值枚举被当成 0/1，各页自写 !== 0、> 0 判断，Never 档反而开启；源端已放弃的计费网络条件也被重新加入。

## 做法

1. 接线前的占位初值只取源端默认值常量或规格枚举表的默认项，不取 @Preview 或示例调用的实参。
2. 设置类字段直接读设置存储（在 build 或订阅回调中取实时值），不在页面另存一套本地副本；解除设置占位时以所在字段块的全部字段为清单逐项替换。
3. 多值枚举列在数据模型与注释中写成 ordinal 枚举并引用规格枚举表，不写 0/1。
4. 源端在应用壳计算一次再下传的派生结果，目标也在壳层计算一次并经全局状态共享，页面只读结果；源端条件依赖目标读不到的系统开关时，按该开关的默认态退化，不改用会扩大触发范围的条件。
