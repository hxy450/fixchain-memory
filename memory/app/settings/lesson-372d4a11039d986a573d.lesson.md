# 源端选项只经 setter 改会话字段、不写持久偏好时，目标落成会话态并接到读取它的流程，不新建偏好键

ID：`lesson-372d4a11039d986a573d` · 版本：1

[本主题](index.md)

## 何时使用

规格提取阶段整理“读写偏好键”清单，以及实现与接线阶段为弹层或设置选项确定写入目标（持久偏好还是会话状态）时

## 适用情境

源端选项回调里写偏好的 editor.putString 被注释或不存在，只调用应用接口的 setXxx 改会话字段，业务流程经对应 getter 读取；目标的偏好键表、会话状态与应用接口由不同切片产出，规格可能把该项列入持久键或引用并不包含它的权威键表，实现者在目标端找不到对应的会话 setter。

## 原因

把会话态写成持久键，选项变化到不了读取会话字段的流程，重启后还保留源端每次都会重置的值；实现者看到“缺键”就补建偏好，规格的分类错误被原样带进代码。

## 做法

1. 按源端实际执行的写路径分类：有生效的偏好写入才列为持久键；只有 setXxx 改会话字段的，登记为会话态 setter/getter 及其消费者（选项 → setter → 读取它的流程），不列入读写偏好键。
2. 规格与写前读到的源码冲突时以源码执行路径为准并回报；目标缺会话 setter 时补到应用接口，或登记跨切片接口缺口，不新建持久键代替。
