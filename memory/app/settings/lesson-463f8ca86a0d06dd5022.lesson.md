# 源端用 getString(key, null) 区分缺键、空串又是合法值时，偏好封装提供 has 判断，不以空串作缺省哨兵

ID：`lesson-463f8ca86a0d06dd5022` · 版本：1

[本主题](index.md)

## 何时使用

数据层与设置实现阶段，迁移以 null 默认值区分“键不存在”的偏好读取（历史列表、可选路径等）时

## 适用情境

源端 SharedPreferences.getString(key, null) 只把缺键当作不存在，空串是合法值（例如表示根目录或默认位置）；目标偏好封装只提供 get(key, def)，没有存在性判断。

## 原因

以空串作缺省值时缺键与合法空串无法区分；跳过空串会把合法条目当成缺失丢弃，改用别的哨兵值也可能与合法值冲突。

## 做法

1. 偏好封装补存在性判断（@ohos.data.preferences 的 has/hasSync），读取先判键是否存在再取值，保留空串条目。
2. 封装接口不在本任务写权限内时，把缺少存在性判断登记为契约缺口交负责方，不在注释里自行接受数据丢失。
