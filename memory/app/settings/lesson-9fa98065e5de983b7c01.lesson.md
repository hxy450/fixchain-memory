# SharedPreferences 迁移保留同步时序：onCreate 用 getPreferencesSync 装载，读写走 Sync 接口、异步 flush

ID：`lesson-9fa98065e5de983b7c01` · 版本：1

[本主题](index.md)

## 何时使用

基础层偏好迁移阶段，设计偏好存储封装的初始化与读写时序时；派工者为该任务写验收标准时

## 适用情境

源端用 SharedPreferences（或其封装库）在 Application.onCreate 构建，之后任意读都等待载入完成；目标改用 @ohos.data.preferences，派工或封装设想“异步载入 + 内存缓存 + 写队列”，载入完成前的读返回调用方默认值。

## 原因

SharedPreferences 的读在文件载入完成前阻塞，apply 先改内存再异步落盘，所以源端任何读都看到真实值、写后立即可读。异步载入的封装在就绪前把调用方默认值当结果返回；各写操作分别异步排队、就绪前 clear 只清缓存、重放队列时 await 间隙到来的新写被清掉，这些都是源端不存在的时序。把“异步容错/写队列”写进验收当作对齐语义，实现者即使读到同步初始化的源码也会照派工实现。

## 做法

1. 入口 onCreate 中用 preferences.getPreferencesSync 装载（需要全量快照时 getAllSync），早于任何读写；读用 getSync，写用 putSync/deleteSync/clearSync 直接改内存实例，再异步 flush 落盘。
2. 确需异步装载时，在设计里写明就绪前的读写行为并与源端一致（就绪前的读等待装载完成），不以调用方默认值代替真实值，也不维护会丢写的待写队列。
3. 写偏好层验收标准时按源端时序表述：同步装载、先于一切业务访问可用、写后立即可读；不把“异步初始化容错”写成对齐要求。
