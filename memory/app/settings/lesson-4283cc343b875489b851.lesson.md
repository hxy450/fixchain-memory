# 源设置页以 XML 挂载带 android:defaultValue 的偏好时，目标按源端写入时机为缺键补写默认值并落盘，不只在读取时回退

ID：`lesson-4283cc343b875489b851` · 版本：3

[本主题](index.md)

## 何时使用

规格提取与设置页实现阶段，迁移带 android:defaultValue 的 PreferenceScreen XML 时

## 适用情境

源设置页由 PreferenceFragment/PreferenceActivity 以 addPreferencesFromResource 等方法挂载 XML 偏好，各项有 android:defaultValue，或源端在 Application/入口调用 PreferenceManager.setDefaultValues；目标偏好服务只在读取时回退默认值；偏好文件内容会被备份等流程读取。

## 例外与边界

- 偏好设了 android:persistent="false"、没有 key，或改用 PreferenceDataStore 存储时，源端不把默认值写进 SharedPreferences，不补写
- 自定义 Preference 子类重写了 onSetInitialValue 时，按其实现迁移

## 原因

Preference 挂载时，对需要持久化（shouldPersist）且文件中缺该键的项调用 onSetInitialValue 写入默认值（Android SDK sources/android-36.1 的 android.preference.Preference.dispatchSetInitialValue）；setDefaultValues 在启动时就按同一 XML 写入。源端偏好文件因此含这些键，读取时回退不会改变文件，备份内容、恢复校验与“键是否存在”的判断都会与源端不同。

## 做法

1. 规格写明默认值写入的时机：源端调用 setDefaultValues(ctx, R.xml.x, false) 时，在对应启动处按同一 XML 补写；否则写“进入设置页后偏好文件含这些键”，在设置页出现时补写。
2. 实现时按 XML 顺序只对源端真正持久化的偏好补写缺失的键并 flush，已有值不覆盖。
