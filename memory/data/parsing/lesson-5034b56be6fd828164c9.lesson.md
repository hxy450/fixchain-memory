# 源端用 org.json 读 JSON 时照其语义：getString 对 null 得 "null"、缺键才抛，语法比 JSON.parse 宽

ID：`lesson-5034b56be6fd828164c9` · 版本：4

[本主题](index.md)

## 何时使用

实现阶段把源端 org.json 解析函数翻成 ArkTS 解析器、决定各字段必填与空值处理时；规格提取阶段把 org.json 读取导入文件的逻辑映射为 JSON.parse 并写失败验收时

## 适用情境

源端用 Android org.json（new JSONObject(text)、getString/getInt/getJSONArray/getJSONObject）读取打包资源、导入文件、备份或许可数据，数据中可能有 "description": null 一类值，对应 Kotlin 字段可能声明为非空 String；目标准备用 JSON.parse 加 as string 直取、把 null 或缺键的数组读成空数组，或写成“非字符串即抛”的取值函数，规格可能把它标为“纯语言构造”。

## 例外与边界

- 源端用 Gson 填充 Bean 时见本主题 Gson 标量宽松转换的经验；源端没有解析代码、目标自写 fromJson 时见本主题 fromJson 类型收窄的经验

## 原因

Kotlin 非空声明不等于 JSON 值不会是 null；getString 遇到 JSON null 返回字符串 "null"，缺键才抛错，还会把数字转成字符串；getInt 截断小数；getJSONArray、getJSONObject 遇缺键、JSON null 或类型不符都抛错。把字段写成“值必须是字符串”，数据里任一 null 就让整份列表失败；以 as string 直取会把 null 显示成空，把缺键数组读成空数组又改变了成败。JSON.parse 比 org.json 的 JSONTokener 严格（后者接受单引号字符串、无引号字面量与注释等），标成“纯语言构造”时这些差异都不会进入验收。

## 做法

1. 按源端取值 API 定空值与类型规则：getString 缺键才报错，JSON null 得到字符串 "null"，数字转为其字符串；getInt 对小数截断；getJSONArray、getJSONObject 遇缺键、JSON null 或类型不符都抛错。只把源端真正会失败的情况写成抛错，源端会抛错的也不改读成空数组或默认值；只有当前展示契约允许时，才在展示层把 "null" 归一为空串或占位。
2. 写解析器前对打包资源逐字段统计 null、缺键和非字符串的条数，不只统计 UI 里有判空的字段。
3. 源端对该字段不失败（如 JSON null 经 getString 得到 "null"）且展示契约允许时，单条记录的展示字段按契约降级显示，不让整份列表失败；源端会抛错的情形保持失败传播。catch 分支记下具体异常与记录位置。
4. 源端以 org.json 解析导入数据时，逐项写明源解析器的宽松语法、getJSONObject/getString 的类型校验与 null 转换，各写一条失败或取值验收；实现按源端接受范围解析（或登记差异），不标“纯语言构造”。
5. 实现时封装或移植与 org.json 取值等价的工具函数，模型与服务统一调用，不以 as string、typeof 判定或 ?? [] 直接代替 getString/getInt/getJSONArray；用含 JSON null 与数字字段的样例对照源端取值。
