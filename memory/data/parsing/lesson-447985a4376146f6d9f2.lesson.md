# 用 @ohos.xml 重建 SAX 开始事件时按 tagName 与深度归属属性，并自建命名空间作用域

ID：`lesson-447985a4376146f6d9f2` · 版本：3

[本主题](index.md)

## 何时使用

实现阶段，用 XmlPullParser 的 token 与属性分离回调重建 namespace-aware 开始事件（本元素属性与命名空间 URI）时

## 适用情境

源 SAX/XmlPullParser 在开始标签读取本元素属性并按 uri 加前缀分发命名空间；目标用 tokenValueCallbackFunction 与 attributeWithTagCallbackFunction 两路回调。@ohos.xml.d.ts 的 ParseOptions 未写两路回调的先后，AttributeWithTagCb 带 tagName 参数，也未保证 getNamespace() 给出元素 URI。

## 原因

在 START_TAG 时快照并清空属性只在属性先到时成立；API 23 实测为 START_TAG 先于本元素属性，快照会把上一元素的属性交给下一元素。挂起到下一个 token 再分发只对 START_TAG 先到成立，属性若先于其 START_TAG 到达又会混入下一元素，两种组装都依赖实际顺序。只依赖 getNamespace() 时前缀元素的命名空间可能取不到（已观察到前缀字段缺失，未直接观测其返回值）。

## 做法

1. 用 attributeWithTagCallbackFunction（@ohos.xml.d.ts，API 20 起）收属性，按回调带的 tagName 与当前元素深度把属性归到对应元素，不按“最近一个 START_TAG”隐式归属；工程 compatibleSdkVersion 低于 20 时只有不带 tagName 的 attributeValueCallbackFunction，归属只能依赖下一步实测的次序。
2. 先用最小样例（带多个属性的元素、带 xmlns:p 声明的元素）打印两路回调的实际次序与 getName/getPrefix/getNamespace 返回值；已确认 START_TAG 先于本元素属性的版本，可把 START_TAG 挂起到下一个 token 或文档结束再连同属性分发；其他次序按实测改写，不写成“两种顺序行为一致”。
3. 把 xmlns 与 xmlns:p 属性按元素深度建作用域栈，URI 为空时按前缀解析，END_TAG 时弹出。
4. 其他 XML 读取器复用同一回调骨架前，确认它的次序假设已在当前版本实测。

## 可选检查

- 带前缀的命名空间字段解析结果缺失时，用各命名空间一条样例断言分发到对应处理器
