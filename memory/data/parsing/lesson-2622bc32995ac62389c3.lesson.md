# 自写 fromJson 从宽类型输入取值时用 typeof/instanceof 收窄：as 只是编译期断言，?? 只兜底缺失与 null

ID：`lesson-2622bc32995ac62389c3` · 版本：1

[本主题](index.md)

## 何时使用

数据模型实现阶段，为迁移实体编写 fromJson 反序列化方法、确定字段取值与默认值时

## 适用情境

ArkTS 模型的 fromJson 接收 Record<string, Object> 等宽类型输入，字段声明为 number/string/boolean 并带默认值；源端是强类型 data class（Int/Long/Boolean 字段），没有可照搬的序列化代码，由目标自行补写。

## 例外与边界

- 源端经 Gson 等解析器填充并容忍数字与字符串互转时，按源解析器的接受范围转换（见本主题 Gson 标量宽松转换的经验），不一律回落默认值

## 原因

(json[k] as number) ?? 0 在运行期不检查类型，类型不符的值会原样进入声明为 number 的字段，源端由语言保证的字段类型在移植后失去保证。来源中生成者在源端没有序列化代码时自行补了 fromJson，六个字段都写成 as 加 ??，自检只 grep any 与 TODO；验证期新增的类型不符用例才暴露。

## 做法

1. 基元字段先用 typeof 判断、对象字段用 instanceof 判断，通过才赋值，否则回落默认值；?? 只用于处理缺失和 null。
2. 自行补写 fromJson 时，在注释或交接中写明缺字段、null、类型不符三种输入各自的结果。
