# 自写 fromJson 按输入域验证类型：基元用 typeof，类实例才用 instanceof；as 的行为按 ArkTS 工具链核验，?? 只兜底缺失与 null

## 何时使用

数据模型实现阶段，为迁移实体编写 fromJson 反序列化方法、确定字段取值与默认值时

## 适用情境

ArkTS 模型的 fromJson 接收 Record<string, Object> 等宽类型输入，字段声明为 number/string/boolean 并带默认值；源端是强类型 data class（Int/Long/Boolean 字段），没有可照搬的序列化代码，由目标自行补写。

## 例外与边界

- 源端经 Gson 等解析器填充并容忍数字与字符串互转时，按源解析器的接受范围转换（见本主题 Gson 标量宽松转换的经验），不一律回落默认值

## 原因

来源工具链中 (json[k] as number) ?? 0 未提供预期的字段校验，类型不符值进入了模型；这不能泛化为所有 ArkTS 代际的 as 均无运行期检查，当前文档还说明错误转换可编译失败或抛 ClassCastException。源端由语言保证的字段类型在移植后失去保证。来源中生成者在源端没有序列化代码时自行补了 fromJson，六个字段都写成 as 加 ??，自检只 grep any 与 TODO；验证期新增的类型不符用例才暴露。

## 做法

1. 基元字段先用 typeof 判断；对象已是目标类实例时才用 instanceof。普通 JSON 记录按源字段类型和必需项验证后构造模型，不能用类实例身份检查拒绝结构合法的记录。缺失、null 与类型不符分别按源策略处理，?? 不代替类型验证。
2. 自行补写 fromJson 时，在注释或交接中写明缺字段、null、类型不符三种输入各自的结果。
