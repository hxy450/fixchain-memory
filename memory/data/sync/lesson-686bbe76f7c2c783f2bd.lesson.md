# 重写源端同步序列时保留保存之后的副作用步骤：当前选中项的校验与持久化在增量和全量路径都落地

ID：`lesson-686bbe76f7c2c783f2bd` · 版本：1

[本主题](index.md)

## 何时使用

数据同步迁移与重构阶段，改写源端同步序列对应的仓库方法（拉取、对账、删除已删除项）时；审计或规格总结同步顺序时

## 适用情境

源端同步在保存与排序之后调用默认选中处理（当前项为空或已失效时选第一个有效项并持久化，更新全局当前 ID）；目标仓库重写了拉取、级联删除与对账，另有全量刷新路径。

## 原因

这类步骤不产出数据，最容易在总结和重写中被省略；缺少后当前选中项保持空值或指向已删除项，依赖它的请求参数与筛选都跟着出错。来源中审计读到了该函数的完整实现，给根会话的同步顺序总结却漏了这一步；根会话读到调用位置，重写同步时也没有补，全量刷新同样缺失。

## 做法

1. 逐行对照源端同步序列，保存与排序之后的副作用（写全局当前 ID、保存选中项、发事件）都要在目标对应位置落地，增量与全量两条路径都调用；删除或对账移除了当前选中项时同步修复选中。
2. 审计或规格总结同步顺序时，不省略写全局状态的步骤，并注明触发条件。
