# 重写源端同步或扫描等多阶段数据流程时保留不产出数据的副作用步骤：缓存写入、当前选中项校验与持久化逐步落地

ID：`lesson-686bbe76f7c2c783f2bd` · 版本：4

[本主题](index.md)

## 何时使用

数据同步、后台扫描等多阶段数据流程的迁移与重构阶段，改写或内联源端序列对应的仓库、服务方法时；审计或规格总结流程顺序时

## 适用情境

源端同步在保存与排序之后调用默认选中处理（当前项为空或已失效时选第一个有效项并持久化，更新全局当前 ID），目标仓库重写了拉取、级联删除与对账，另有全量刷新路径。也包括源端扫描服务在收尾阶段除保存结果外还调用仓库更新不可读文件缓存（开头另读该缓存做预过滤），目标把整条流程内联进服务方法，并已移植对应的缓存写方法与 DAO。

## 例外与边界

- 拦截器读取的公参键缺写入方（隐私同意后初始化链里的设备标识等生产者）时，见 data/network 的公参生产者经验

## 原因

这类步骤不产出数据，最容易在总结和重写中被省略；缺少后当前选中项保持空值或指向已删除项、缓存永远为空，依赖它们的请求参数、筛选与汇总展示都跟着出错。已定义却无调用者的写方法是常见的残留信号。

## 做法

1. 逐行对照源端同步序列，保存与排序之后的副作用（写全局当前 ID、保存选中项）都要在目标对应位置落地，增量与全量两条路径都调用；删除或对账移除了当前选中项时同步修复选中。
2. 把源端服务流程内联到目标方法前，按阶段列出源函数的全部副作用调用（缓存预过滤读取、缓存写入、偏好标记、结果持久化），逐项落位；源端有调用、目标已有对应写方法或 DAO 时直接补调用。只有目标确实缺写权限或对应能力时，才交给具名负责步骤并上报阻塞，写明缺哪一步、缺哪个提供方。
3. 移植了仓库/DAO 写方法后 grep 其调用点，已定义却无调用者时回查源流程哪一步应调用它。
4. 审计或规格总结流程顺序时，不省略写全局状态或缓存的步骤。
