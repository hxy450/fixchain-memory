# 重写源端同步或扫描等多阶段数据流程时保留不产出数据的副作用步骤：缓存写入、当前选中项校验与持久化逐步落地

ID：`lesson-686bbe76f7c2c783f2bd` · 版本：2

[本主题](index.md)

## 何时使用

数据同步、后台扫描等多阶段数据流程的迁移与重构阶段，改写或内联源端序列对应的仓库、服务方法时；审计或规格总结流程顺序时

## 适用情境

源端同步在保存与排序之后调用默认选中处理（当前项为空或已失效时选第一个有效项并持久化，更新全局当前 ID），目标仓库重写了拉取、级联删除与对账，另有全量刷新路径。也包括源端扫描服务在收尾阶段除保存结果外还调用仓库更新不可读文件缓存（开头另读该缓存做预过滤），目标把整条流程内联进服务方法，并已移植对应的缓存写方法与 DAO。

## 原因

这类步骤不产出数据，最容易在总结和重写中被省略；缺少后当前选中项保持空值或指向已删除项、缓存永远为空，依赖它们的请求参数、筛选与汇总展示都跟着出错。来源中审计读到了同步选中函数的完整实现，给根会话的同步顺序总结却漏了这一步，根会话重写同步时也没有补，全量刷新同样缺失；另一应用的实现者读到了规格“不可读文件记入缓存”与源端收尾段的缓存更新调用，移植时照写了过滤与持久化，也定义了缓存写方法，却从未调用。

## 做法

1. 逐行对照源端同步序列，保存与排序之后的副作用（写全局当前 ID、保存选中项、发事件）都要在目标对应位置落地，增量与全量两条路径都调用；删除或对账移除了当前选中项时同步修复选中。
2. 把源端服务流程内联到目标方法前，按阶段列出源函数的全部副作用调用（缓存预过滤读取、缓存写入、偏好标记、结果持久化），逐项落位或登记为显式缺口；移植了仓库/DAO 写方法后 grep 其调用点，已定义却无调用者时回查源流程哪一步应调用它。
3. 审计或规格总结流程顺序时，不省略写全局状态或缓存的步骤，并注明触发条件。
