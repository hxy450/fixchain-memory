# 替代源端作业聚合器时把结束作业写成显式终态，并保证每个状态都有产出点

ID：`lesson-d18e6e019cad3d26839b` · 版本：1

[本主题](index.md)

## 何时使用

功能实现阶段，把 WorkManager/LiveData 等运行时作业聚合并入目标服务，决定作业结束时状态表与事件载荷怎么写时

## 适用情境

源宿主观察作业列表生成“键→状态”表并粘性广播，结束作业以 COMPLETED 一类终态保留在表里；订阅方按键是否在事件中过滤，查询接口要区分“完成”与“缺失”。

## 原因

把作业结束写成删除键，查询方法检查的终态无人产出，完成那次事件不含该键，订阅方丢弃这次刷新，页面停在旧状态。

## 做法

1. 先读源聚合器实际的状态映射，终态写进表而不是删除键；状态域中的每个值都安排产出点，查询检查某状态而全文件找不到写入点即为偏离。
2. 按订阅方的过滤方式设计事件载荷，使完成时的最后一次事件仍含目标键。
