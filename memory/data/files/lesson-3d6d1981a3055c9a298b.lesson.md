# 用 zlib 替代 GZIPInputStream 识别损坏数据时先校验 gzip 魔数：gzopen 'rb' 对非 gzip 输入不抛错

ID：`lesson-3d6d1981a3055c9a298b` · 版本：1

[本主题](index.md)

## 何时使用

数据层实现阶段，把依赖 GZIPInputStream 抛异常识别损坏或非 gzip 数据的读取路径改写为 HarmonyOS zlib 时

## 适用情境

源端读取 gzip 压缩的正文、缓存或备份文件，损坏或非 gzip 数据由 GZIPInputStream 抛 ZipException/EOFException 落入失败分支（如显示加载失败）；目标用 @ohos.zlib 的 gzopen(path, 'rb') 一类接口读取。

## 原因

@ohos.zlib.d.ts 说明 gzopen 以 'rb' 打开非 gzip 文件时直接读出原始数据；不校验格式时，损坏文件被当作正常内容展示，源端的失败分支永远不触发。

## 做法

1. 读取前校验前两字节为 0x1f 0x8b，不符时走源端的失败分支（失败状态、空结果）；契约注释不声称未验证的抛错行为。
