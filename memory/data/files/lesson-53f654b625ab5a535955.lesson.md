# 源端 ZipOutputStream 未 setMethod 时默认 DEFLATED：手写 zip 容器也用 deflate，不改成存储模式

ID：`lesson-53f654b625ab5a535955` · 版本：1

[本主题](index.md)

## 何时使用

数据层实现阶段，把 ZipOutputStream 打包导出迁到目标，系统 zip 接口不满足要求而改手写容器时

## 适用情境

源端用 java.util.zip.ZipOutputStream 写条目且未调用 setMethod；目标的 zlib 打包接口不能控制条目名或时间，准备手写 local header 与 central directory 的 zip 容器；源端遇到目录等不可读条目时抛错并提示失败。

## 例外与边界

- 源端显式 setMethod(ZipOutputStream.STORED) 时按存储模式写，并按 STORED 要求预先写入 CRC 与大小

## 原因

ZipOutputStream 的默认压缩方式是 DEFLATED（ZipOutputStream.setMethod 的 javadoc），手写容器时顺手写成 STORED，导出文件体积与压缩标志都与源端不同。源端对不能读的条目（如把目录交给 FileInputStream）会抛错走失败提示，静默跳过会把失败变成“成功但缺文件”。

## 做法

1. 条目按 DEFLATED（zip 压缩方法 8）写：用 zlib 产出不带 zlib 头与校验的原始 deflate 流，CRC 与压缩后大小在条目写完后经数据描述符补写（通用标志位 bit3）。
2. 源端会失败的条目（目录、不可读文件）同样判失败并走源端的错误提示，不加 continue 静默跳过。
