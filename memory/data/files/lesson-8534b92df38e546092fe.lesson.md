# 源端只在 catch(OutOfMemoryError) 时提示文件过大：目标照常读取，读取或分配失败时再提示，不加读前大小阈值

ID：`lesson-8534b92df38e546092fe` · 版本：3

[本主题](index.md)

## 何时使用

规格提取与数据层实现阶段，把导入、打开文件时的 OOM 兜底映射为目标读取与错误处理时

## 适用情境

源端导入文件时直接整读，只在 catch (OutOfMemoryError) 分支提示“文件过大”，没有大小阈值；规格或派工可能把它写成“读前长度预检”或“文件大小上限校验”；目标用 @kit.CoreFileKit fileIo 读取。

## 例外与边界

- 当前任务明确批准设置大小上限：登记为有意偏离，写明数值来源

## 原因

读前阈值会拒绝源端能正常导入的大文件，把分配失败时的兜底变成预先拒绝。目标端的失败通道因接口而异：本机 SDK 的 @ohos.file.fs.d.ts 中 readText/readTextSync 声明 BusinessError 13900024 File too large，readSync(fd, buffer) 没有声明这类错误码，按文件大小自行分配缓冲区的语句本身也可能失败；只按一种异常类型捕获会漏掉另一路。

## 做法

1. 照常读取，不新增读前 stat 阈值。
2. 按所用读接口在 @ohos.file.fs.d.ts 的 @throws 确认过大类错误码：readText/readTextSync 为 13900024，捕获该码时给出源端的“文件过大”提示，其余错误走源端的失败分支。
3. 自行按文件大小分配 ArrayBuffer 再 readSync 时，把分配语句放进 try 并单独判定，分配抛错即给“文件过大”提示；本机 d.ts 未声明分配失败的异常类型，不只按 RangeError 过滤。
