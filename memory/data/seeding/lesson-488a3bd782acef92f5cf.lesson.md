# 源端在首次建库回调里播种时，目标把播种放进建表分支的同一事务并写入种子主键；手动补充按不带 id 的新行插入

ID：`lesson-488a3bd782acef92f5cf` · 版本：1

[本主题](index.md)

## 何时使用

数据层实现阶段，确定预置数据何时播种、种子主键如何写入，以及“添加默认项”这类补充入口如何插入与列出时

## 适用情境

源端 Room 在 onCreate 回调里按固定 id 插入预置数据，另有补充对话框列出全部预置项并以 copy(id = 0) 重新插入；目标用 relationalStore 自行建表与播种。

## 原因

用“表为空”代替“首次创建”，用户删空数据后重启会被重新播种；种子不写 id 而由自增生成，依赖固定 id 的深链或引用会指向错误条目；补充路径复用种子构造函数就会插入固定 id。来源中实现者读到了规格“首次建库回调播种、只播一次”和固定 id，仍这样写；修复时给种子补 id，又连带改变了共用同一函数的补充路径。

## 做法

1. 播种放在“表都不存在”的建表分支里，与建表、版本号写入在同一事务。
2. 首建播种写入源端种子 id；手动补充或复制路径构造不带 id 的新 ValuesBucket，并重写子表外键。两条路径分开构造，改共享函数前查它的全部调用方。
3. 补充对话框的列出范围照源端（例如全部预置项），不自行按名称过滤。

## 可选检查

- 删光全部数据后重启，列表应保持为空。
