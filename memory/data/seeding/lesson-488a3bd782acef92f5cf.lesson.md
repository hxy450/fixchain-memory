# 源端在首次建库回调里播种时，目标把播种放进建表分支的同一事务并写入种子主键；手动补充按不带 id 的新行插入

ID：`lesson-488a3bd782acef92f5cf` · 版本：3

[本主题](index.md)

## 何时使用

数据层实现阶段，确定预置数据何时播种、种子主键如何写入，以及“添加默认项”这类补充入口如何插入与列出时

## 适用情境

源端 Room 在 onCreate 回调里按固定 id 插入预置数据，另有补充对话框列出全部预置项并以 copy(id = 0) 重新插入；目标用 relationalStore 自行建表与播种。

## 例外与边界

- 源端在应用首次启动按偏好标记播种（不在建库回调里）时，见本主题首次启动播种的经验

## 原因

用“表为空”判断代替“首次创建”，用户删空数据后重启会被重新播种；种子不写 id 而由自增生成时，条目 id 与源端不同，按 id 排列的列表顺序随之不同；补充路径复用种子构造函数就会插入固定 id，与已有种子主键冲突。

## 做法

1. 播种放进首次创建的建表分支，与建表在同一事务（按 store.version 驱动建表时即旧版本为 0 的分支，版本流程见 data/schema 的 Room 版本迁移经验）；不以“表为空”判定首次创建。
2. 首建播种写入源端种子 id；手动补充或复制路径构造不带 id 的新 ValuesBucket（自增主键的省略规则见 data/schema 的 autoGenerate 主键经验）。两条路径分开构造，改共享函数前查它的全部调用方。
3. 补充对话框的列出范围照源端（例如全部预置项），不自行按名称过滤；规格条目与源码冲突时按源码实现，并在迁移报告登记差异。

## 可选检查

- 删光全部数据后重启，列表应保持为空。
