# 拦截器按本地键读取的公共参数都要有生产者：按源端初始化序列补齐写入步骤，只迁读取侧不算完成

ID：`lesson-7e04234bdf5aef97b651` · 版本：1

[本主题](index.md)

## 何时使用

迁移或重构隐私同意后的初始化链、网络公共参数与拦截器时，确认每个公参字段由谁写入时

## 适用情境

目标拦截器每次请求从偏好键或当前选中项缓存读取设备标识、当前分组等公参；源端这些值由隐私同意后的 SDK 初始化序列（如获取 OAID）或同步后的默认选中处理写入，目标只迁了读取侧。

## 原因

读取侧有默认值时编译与请求都正常，公参却一直为空，问题只在服务端统计或下游功能中暴露。来源中根会话写前读到了源端初始化序列（其中一步是获取 OAID），改写隐私后初始化链时保持原顺序而没有补这个生产者，工程里没有任何代码写那个偏好键。

## 做法

1. 改写初始化链时把源端初始化序列的步骤逐项对到目标 initializer；对拦截器读取的每个本地键在工程内检索写入点，只有读取、没有写入的键按源端来源补实现（含隐私门禁与所需权限声明），或登记为缺口。
