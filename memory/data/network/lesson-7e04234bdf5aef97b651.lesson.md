# 拦截器按本地键读取的公共参数都要有生产者：按源端初始化序列补齐写入步骤，只迁读取侧不算完成

ID：`lesson-7e04234bdf5aef97b651` · 版本：3

[本主题](index.md)

## 何时使用

迁移或重构隐私同意后的初始化链、网络公共参数与拦截器时，确认每个公参字段由谁写入时

## 适用情境

目标拦截器每次请求从偏好键或当前选中项缓存读取设备标识等公参；源端这些值由隐私同意后的 SDK 初始化序列（如获取 OAID）写入，目标只迁了读取侧。

## 例外与边界

- 公参来自同步、扫描等多阶段流程的副作用写入（如同步后的默认选中项）时，见 data/sync 的多阶段流程副作用经验，在源序列对应位置落地

## 原因

读取侧有默认值时编译与请求都正常，公参却一直为空；改写初始化链时保持原顺序，并不保证每个被读取的键都有写入者。

## 做法

1. 改写初始化链时把源端初始化序列的步骤逐项对到目标 initializer；对拦截器读取的每个本地键在工程内检索写入点，只有读取、没有写入的键按源端来源补实现（含隐私门禁与所需权限声明）。
2. 只有目标确实缺对应能力时才登记缺口，写明缺的提供方、键名与负责接线的步骤。
