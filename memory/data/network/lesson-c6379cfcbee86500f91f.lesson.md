# 多路请求聚合写 TTL 缓存时全部失败不写新时间戳，命中同时校验时效与载荷非空

ID：`lesson-c6379cfcbee86500f91f` · 版本：3

[本主题](index.md)

## 何时使用

数据层实现阶段，为首页等多路并发请求实现按键（如城市）的 TTL 缓存写入与命中判定时

## 适用情境

源端或规格按键缓存多路并发结果，有效期为保存时间加源端 TTL 常量；每一路都可能失败；目标 Service 把各路结果聚合成一条缓存记录，命中条件只看保存时间。源端字面实现可能在全部失败时也以空结果和当前时间写缓存，而规格或决策要求成功后才写、网络失败时读有效缓存。

## 原因

全部失败时仍以当前时间写入空记录，命中条件又只看时效，一次失败就变成整个 TTL 内的“有效缓存”，之后冷启动直接返回空结果、不再请求；照搬源端“失败也写空结果”的字面行为会得到同样结果。

## 做法

1. TTL 取源端缓存过期常量与保存函数。写入前判断是否至少一路成功；全部失败时不写新时间戳：有旧的有效缓存就回退使用，没有就把分支错误交给调用方。
2. 缓存命中同时校验时效与载荷非空，失败留下的空记录视为失效并重新请求。
3. 源端字面行为（如全部失败也写空结果）与规格或决策（成功后写入、网络失败读有效缓存）冲突时，按规格与决策实现，并在报告中写明与源码的差异。

## 可选检查

- 对缓存逻辑有疑问时，模拟所有分支失败后再调用一次，第二次必须重新发出请求。
