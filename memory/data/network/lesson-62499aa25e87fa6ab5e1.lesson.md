# 新增或改写请求通道时按源端重载决定是否内置取 key 门；确需门时按请求实际基址握手，不用运行期可改写的默认基址

ID：`lesson-62499aa25e87fa6ab5e1` · 版本：3

[本主题](index.md)

## 何时使用

网络通道实现或修复阶段，为新增或改写的请求通道决定是否内置会话密钥前置门（ensureKey 一类）及其握手基址时

## 适用情境

源端某请求方法只带公共头直接发送、不做前置握手，由调用方先按特定基址握手取会话 key；目标的 key 缓存按基址比对决定命中或重新握手，通道门控若取运行期可被改写的默认基址（例：选择地区或切换服务器后改写），就可能与调用方的握手基址不同。

## 原因

通道内再以另一个基址取 key，两个基址不同时会触发二次握手、覆写会话 key，响应解密失败后静默返回空数据；只在清数据后的初始态验证时两个基址恰好相同，问题被掩盖。

## 做法

1. 按源端重载实际做的事实现通道（请求头、body 形态、是否取 key）；源端无前置门、由调用方先握手时，目标通道不为“与其他通道一致”自行加门。
2. 确需在通道内保证 key 时，门的基址与请求 URL 或调用方的握手基址一致（显式传入或由 URL 推导）；判断两个基址是否恒等时查遍所有赋值点（选省切服、登录后覆盖等），不只看静态初值。

## 可选检查

- 验证涉及会话 key 或服务基址的修复时，至少覆盖一次已切服的持久化状态（选择地区返回后再次进入页面），不只在清数据后的初始态验证。
