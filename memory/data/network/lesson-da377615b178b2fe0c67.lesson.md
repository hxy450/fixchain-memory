# 迁移源端链接 getter 时按完整返回表达式构造 URL：配置里的基础地址加上 getter 追加的渠道等运行期参数，以“key=”空值结尾的 query 是待补值信号

ID：`lesson-da377615b178b2fe0c67` · 版本：1

[本主题](index.md)

## 何时使用

功能切片实现阶段，把源端配置读取与链接 getter（协议、隐私、个人信息清单等）迁移成目标 Service 里的 URL 常量或构造方法时

## 适用情境

Android 从 assets JSON 等配置读取基础地址（query 以 aliasCode= 一类空值结尾），由配置类的 getter 在返回时追加启动渠道等运行期参数；目标在 Service 层统一提供受控 WebView 链接，工程已有渠道常量或构建配置。

## 原因

getter 的返回值才是实际使用的链接；把配置里的 address 抄成常量，会丢掉 getter 追加的参数，页面照常打开，服务端却拿不到渠道等值，差异只在对照运行态 URL 时可见。来源中写者已读到 getter 的 `return url + AdEntrance.getStartChannel()` 与以 aliasCode= 结尾的配置，仍把四个地址原样写成常量；同一类的其他方法用了渠道常量，URL 却没有拼。

## 做法

1. 按 getter 完整的返回表达式（配置基础地址 + 追加参数）构造目标 URL；源端追加的运行期值映射到目标工程统一的来源（渠道常量或构建配置），在 Service 中拼接，页面不硬编码。
2. 写完逐条对照源 getter，核对生成的 URL 是否仍以“=”结尾、追加参数是否齐全。
