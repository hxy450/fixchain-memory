# 用 HttpClient 替代 Retrofit 时先保留根路径与相对路径解析语义，再规范化 baseUrl/path 的分隔符

ID：`lesson-d767b84213eb5ef93034` · 版本：2

[本主题](index.md)

## 何时使用

网络层实现阶段，把 Retrofit 接口迁成自写 HttpClient，确定 baseUrl 常量与各 Service 的 path 如何连成完整 URL 时

## 适用情境

源端用 Retrofit 的 baseUrl 加 @GET/@POST 相对路径（多数不带前导 /，少数带），目标端改用 @kit.NetworkKit http 手工拼 URL；参考模板示范 `${baseUrl}${path}` 直接拼接；baseUrl 常量与各 Service 的 path 分散在不同文件里声明。

## 原因

Retrofit 按 baseUrl 解析相对路径，分隔符由框架处理；手工直接拼接时分隔符只能由其中一侧提供。模板示例是无尾斜杠的 baseUrl 配带前导 / 的 path，照搬拼接方式却按 Retrofit 注解把 path 写成无前导 /，两侧都不带分隔符，host 与路径粘在一起（形如 api.example.colivetranslator/...），请求报无法解析主机，表象像网络不通。来源中同一生成者照模板写拼接，把 60 个 path 的前导 / 全部去掉（连源端原本带 / 的 12 个也去掉），自拟的 baseUrl 也无尾斜杠，自检只查占位符，没有实际拼一次 URL。

## 做法

1. 先保留源 Retrofit 的 URL 解析语义：绝对 URL 直接使用；带前导 / 的根路径从 origin 根解析，无前导 / 的相对路径按 baseUrl 的目录解析。仅 baseUrl 为 origin 或源合同明确统一追加时，才可用去尾斜杠/去前导斜杠再连接的简法；base 含目录时不能一律 strip 前导 /。
2. 沿用参考模板的拼接方式时同时沿用它的 path 形式；按源 Retrofit 注解改写 path（去掉或保留前导 /）后，回头确认拼接函数仍成立。
3. 落盘前用当前的 baseUrl 常量和一个真实接口 path 拼一次完整 URL，除确认 host 与路径分隔符外，同时核 base 带目录时的根路径、相对路径和绝对 URL，结果须与源解析一致。
