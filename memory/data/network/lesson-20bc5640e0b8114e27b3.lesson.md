# rcp Session 以 baseAddress 加相对路径构造 Request 时，拦截器内不无保护地读取 context.request.url

ID：`lesson-20bc5640e0b8114e27b3` · 版本：1

[本主题](index.md)

## 何时使用

网络层实现阶段，在 rcp Interceptor（含 401 刷新与重试链）中读取请求属性，例如为日志取请求地址时

## 适用情境

rcp SessionConfiguration 设置 baseAddress，HTTP 封装以 'users/me' 一类相对路径构造 rcp.Request；拦截器在发送前拿到该 Request，并把源端仅用于调试的 url 日志迁到刷新主链上。

## 原因

rcp.Request.url 声明为 URL 类型，相对路径要到发送时才由 baseAddress 补全；HarmonyOS SDK 6.1.1(24) 下单测诊断实测，读取相对路径 Request 的 url 会抛 'Cannot convert to URL'。日志行抛出的异常会中断 401→refresh→retry 主链，编译期类型检查与正常请求都不暴露；真实 Session 下拦截阶段 url 是否已补全没有运行记录，所以按可能未补全来写。

## 做法

1. 拦截器里需要请求地址时，用 baseAddress 与构造请求时的原始 path 自行拼接，或用 try/catch 读取 context.request.url 并给出占位值；不在刷新、重试主链上直接调用 url.toString()。
2. 迁移源端仅调试用的日志（如 !environment.production 下的 console.info）时，把取值放在不会抛错的旁路，日志失败不得改变刷新或重试的结果。

## 可选检查

- 用相对路径构造的 Request 走一次 401→refresh→retry 分支的单测，确认主链不因读取 url 中断
