# 源端经 BuildConfig/gradle 注入服务地址、签名与解密材料时，目标从私有构建配置接入，不以空配置装配网络客户端

ID：`lesson-30ccd1d65d2c39029256` · 版本：4

[本主题](index.md)

## 何时使用

网络基础设施实现与装配阶段，实现网络运行配置来源并在装配根构造 HTTP 客户端时

## 适用情境

源端通过 BuildConfig/gradle 注入 API 地址、请求签名材料与 release 响应解密密钥；目标决策要求密钥不进源码、构建期从本地私有配置注入，网络层对空配置拒绝发包；另有决策只记录了“未提供测试环境或测试账号”。

## 例外与边界

- 地址与环境本身还没确定时，先按同主题服务地址经验沿键名追到源端取值

## 原因

“密钥不进源码”和“没有测试环境”约束的是存放位置与联调时点，不是允许生产配置缺席；网络层只留可注入参数、装配者又以空字符串构造客户端时，所有自有后端请求在本地就被拦截，缺少解密材料还会让 release 响应无法解析。

## 做法

1. 网络层任务内一并交付配置来源：构建期字段（build-profile.json5 的 buildProfileFields，本地秘密参数经 hvigor parameterFile 引入）或生成模块从环境变量、被忽略的本地配置读取地址与材料，生成文件加入忽略规则；缺键时构建或启动显式失败并登记阻断，不以空字符串构造客户端。
2. 源端在解析前解密响应时，解码器与配置在同一任务交付，算法与失败回退按同主题加解密工具经验逐分支移植；release 下解码器缺失不能默认透传。
3. 区分“无测试环境/测试账号”（影响联调与设备验收）与“生产配置来源存在”（仍须接线）；带作用域限定的决策不外延为允许请求永久失败。
