# OkHttp 缓存映射到 RCP ResponseCache 时，maxSize 按实测单位传入并实写确认，缓存指令名逐项保留

ID：`lesson-17b7079006badd437bb1` · 版本：1

[本主题](index.md)

## 何时使用

网络层与图片策略实现阶段，把 OkHttp Cache(dir, N MiB) 的容量与 CacheControl 指令映射到 RCP ResponseCache 或请求缓存头时

## 适用情境

源端用 OkHttp Cache 提供自动 HTTP 缓存，并用 CacheControl.Builder().maxAge(...).maxStale(...) 控制图片缓存；目标用 @kit.RemoteCommunicationKit 的 rcp.ResponseCache / CacheConfiguration。

## 原因

hms rcp.d.ts 对 CacheConfiguration.maxSize 注释为 Unit: MB，已观察到 API 26 运行时却按字节解释：按文档传 200 时 ResponseCache.set 报 item is too long for cache limits，缓存实际不写入；拦截器若空 catch 吞掉 set 的错误，问题一直不可见。maxStale 与 stale-while-revalidate 是不同指令，替换后过期响应的复用条件改变。

## 做法

1. CacheConfiguration.maxSize 在 API 26 运行时按字节传入（MiB×1024×1024）；其他运行版本以一次真实 2xx 写入后 cache.getState() 的 count>0 为准确定单位。
2. ResponseCache.set 失败至少记录错误信息，不空 catch。
3. CacheControl 指令逐项保留名称：maxAge 对应 max-age，maxStale 对应 max-stale，不用 stale-while-revalidate 代替 max-stale。
