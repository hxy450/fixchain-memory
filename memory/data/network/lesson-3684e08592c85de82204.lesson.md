# RSA-OAEP 包裹密钥加 AES-GCM 的网关移植 cryptoFramework：规格串不加编码后缀，结果判空，Buffer 按长度拷贝

ID：`lesson-3684e08592c85de82204` · 版本：3

[本主题](index.md)

## 何时使用

网络基础设施实现阶段，把 Android 端 RSA-OAEP 包裹会话密钥加 AES-GCM 加密的网关传输改写为 ArkTS cryptoFramework 与 buffer 调用时（含为通过编译改写同步 API 与类型的收敛步骤）

## 适用情境

源端用 X509EncodedKeySpec 解析“BEGIN PUBLIC KEY”PEM，以 RSA/ECB/OAEPWithSHA-256AndMGF1Padding 包裹随机密钥，用 AES/GCM/NoPadding 加密可能为空的请求体并解密响应；目标用 createAsyKeyGenerator/convertPemKeySync、Cipher.updateSync/doFinalSync 与 @kit.ArkTS buffer 实现同一协议。

## 原因

协议理解正确不等于 API 映射正确：生成器规格串附加 PKCS1 后缀时，已观察到真机创建生成器失败，去掉后缀即可（d.ts 未列合法 algName，被拒的精确原因未验证）；GCM 空明文加密与解密 final 可能返回 null；Node 式 .buffer/byteOffset 视图在 ArkTS Buffer 上不可靠。d.ts 把 update/doFinal 的结果声明为非空 DataBlob，但已观察到真机返回 null，按签名删掉判空会在运行期才失败。

## 做法

1. createAsyKeyGenerator 只写算法与按实际公钥得出的位数（如 'RSA2048'），X.509 PEM 直接交给 convertPemKeySync，不附加 PKCS1 等编码后缀。
2. Cipher.update/updateSync 与 doFinal/doFinalSync 的结果一律判空后再取 data，即使 d.ts 签名是非空 DataBlob；为通过编译改写同步 API 时保留原有兜底。
3. 需要独立 Uint8Array 时按 length 分配并拷贝，不用 new Uint8Array(buf.buffer, buf.byteOffset, …)；编译报 Buffer 属性不存在时先查 ArkTS buffer 语义，不做字段名机械替换。

## 可选检查

- 编译通过后在真机用空请求体与实际网关各做一次完整往返，失败时透传所在阶段与原始异常。
