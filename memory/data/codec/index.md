# data/codec

手写二进制编解码与协议字节布局：protobuf 字段 wire type 与读写方法的对称、varint 与负数补码的字节拆分，源码定长字节数组常量的逐下标转写，字面下标改命名常量时按用途选端点

## 本级经验

- [同一定长记录在不同调用处按用途取不同切片区间时，命名常量按用途分开，不沿用相邻用途的端点](lesson-1d0b6dde849cbd70ee8f.lesson.md)
  - 时机：服务层实现或重构阶段，把源端内联的定长记录切片（substring、subarray、slice）抽进服务并用共享命名常量替换字面下标时
  - 情境：源码对同一行或同一块按用途取不同区间（例：同一记录一处取 (a,b) 只做着色，另一处取 (a,c) 提取字段并参与校验）；目标为切分点定义了一组共享常量，页面里可能已有正确的内联切片，规格也可能写了区间。
- [手写 proto3 编解码时按字段 wire type 成对实现读写；int32 负值按 64 位补码逐组拆成 10 字节 varint](lesson-ae1aa4ff5e2217b67e06.lesson.md)
  - 时机：数据层实现阶段，在没有 protobuf 运行时的目标端手写 proto3 编解码基座、为每个消息字段选择读写方法时
  - 情境：目标端（如 ArkTS）需按字段表（字段号、wire type、标量类型）手写 proto3 编码与解码；字段表含 wire type 0 的有符号 int32（非 sint32，值可能为负，如 RSSI、海拔），同时存在 fixed32/sfixed32/float 等 4 字节定长字段；可用的位运算只有 32 位。
- [转写源码定长字节数组常量时逐下标列出全部字节并核总长；规格中的分段简写与源字面量冲突时以源字面量逐下标实现](lesson-0bba9db6a18f2e732334.lesson.md)
  - 时机：规格提取与业务服务实现阶段，把源码中的定长字节数组常量（协议块、扇区尾块、头部魔数）转写成规格常量、伪代码，并据此用 Uint8Array 等按下标填充时
  - 情境：源码用有符号 byte\[\] 字面量定义固定长度的协议块（如 16 字节扇区尾块：KeyA 6 | 访问位 3 | GPB 1 | KeyB 6），规格用 hex 分段串或伪代码重述，同一规格里常量行、验收条目与伪代码可能是几种不同写法；目标按下标逐字节填充。
