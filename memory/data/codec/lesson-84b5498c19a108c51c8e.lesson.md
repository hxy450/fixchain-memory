# 自写 TIFF/EXIF 等多目录二进制序列化器替代库时：值区偏移跨目录连续推进，有符号类型与 NUL 按类型读写，按输出的实际编码选容器

ID：`lesson-84b5498c19a108c51c8e` · 版本：1

[本主题](index.md)

## 何时使用

数据层实现阶段，自写二进制元数据读写器替代源端库（如 androidx ExifInterface），编写多 IFD 序列化、类型读写、tag 表与图像容器写入时

## 适用情境

源端经库按 tag 名读写 EXIF，并对 JPEG、PNG、WebP 输出统一写入；目标无等价 API，自研 TIFF 段写回，需要处理 IFD0/Exif/GPS/Interop 多个目录的超长值区、SSHORT/SLONG/SRATIONAL、含 NUL 的 ASCII/UNDEFINED 值、数字 tag 号与各图像容器。

## 原因

每个目录各从同一偏移分配值区时，超过 4 字节的值互相覆盖；有符号类型按无符号读写或解析时钳成 0 会改掉负值；读 ASCII/UNDEFINED 时跳过所有 NUL 会破坏 UserComment 前缀等定长字节；凭记忆填的 tag 号写到错位置，置成无效值的 tag 让源端的删除变成空操作；把 JPEG 的 APP1 拼接套到 PNG/WebP 上会产出非法文件。这些错误只做语法自检都发现不了。

## 做法

1. 布局按“各目录块 → 共用值区”，值区偏移跨目录连续推进；每个目录块大小按 2 + 12n + 4 字节计算（TIFF 6.0：条目数、每条目 12 字节、下一目录偏移）。
2. 有符号类型用 DataView 的 getInt16/getInt32 与 setInt16/setInt32，SRATIONAL 的分子分母都按有符号解析；ASCII 读到首个 NUL 截断，UNDEFINED 原样保留 NUL 字节。
3. tag 号、字符串值到二进制的转换（如 GPSTimeStamp 的 'HH:mm:ss' 写成三个有理数）和库方法隐含写入的字段，从被替代库对应版本的源码取；源端会删除的 tag 给出真实 tag 号或子目录（例：TransferFunction 0x012D、Exif 子目录的 CFAPattern 0xA302、XMP 700，见 TIFF 6.0/EXIF 2.32），不置无效值。
4. 按输出的实际编码选容器：JPEG 写 APP1 段，PNG 写带 CRC 的 eXIf 块，WebP 写 RIFF 的 EXIF 块并置 VP8X 头中的 EXIF 标志。

## 可选检查

- 规格把编解码项标为单元验收时，用最小夹具跑一次 parse(serialize(doc)) 往返：各目录放超过 4 字节的值、负的 SSHORT/SLONG/SRATIONAL 与含 NUL 的 UserComment，逐 tag 比对字节。
