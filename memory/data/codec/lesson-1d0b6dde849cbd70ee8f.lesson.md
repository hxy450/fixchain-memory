# 用命名常量替换源端字面下标或区间时按每处调用的用途选端点：同一结构里着色与数据提取的边界不同，不沿用相邻用途的常量

ID：`lesson-1d0b6dde849cbd70ee8f` · 版本：1

[本主题](index.md)

## 何时使用

服务层实现或重构阶段，把源端内联的定长记录切片（substring、subarray）抽进服务并用一组共享命名常量替换字面下标时

## 适用情境

源码对同一行或同一块按用途取不同区间（如着色只取 3 字节访问位 substring(12,18)，提取并解码访问条件取访问位加 GPB substring(12,20)）；目标为切分点定义了一组共享常量，页面里原本有正确的内联切片，规格也写明了精确区间。

## 原因

命名常量表达的是某一个用途的边界；拿着色的结束位去做数据提取，会少取或多取字节，而函数注释仍写着规格区间，代码与注释不一致却不报错。来源中实现者的草稿与规格都写 (12,20)，落盘时换成了只对着色正确的常量，并把页面里正确的内联切片替换为服务调用，GPB 字节从此不参与校验。

## 做法

1. 替换字面下标时逐处按调用用途选端点（提取 AC+GPB 用 GPB 结束位，着色用 AC 结束位），常量名写清用途；把页面内联逻辑搬进服务时逐字核对搬移前后的区间与规格。
2. 写后用规格给出的字面区间检查表达式，并核对代码与自身注释一致。

## 可选检查

- 规格标注“区间字符精确”的提取项，补最小断言：每项长度符合规格（如 8 个 hex 字符）
