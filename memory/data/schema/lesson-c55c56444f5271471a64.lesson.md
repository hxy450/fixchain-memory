# 手写 relationalStore 建表 SQL 时给表名与列名统一加引号，关键字列名尤其不能裸写

ID：`lesson-c55c56444f5271471a64` · 版本：1

[本主题](index.md)

## 何时使用

数据层实现阶段，把 Room 实体或列清单手写成 relationalStore 的建表与索引 SQL 字符串时；规格或侦察阶段为实现者整理表结构列清单时

## 适用情境

源端表结构由 Room 注解生成，Room 导出的 createSql 会给表名、列名加反引号；目标端用字符串数组手写 DDL 并在 init 中顺序执行，实体列名可能是 to、order、group、index、default、key 一类 SQL 关键字；SQL 写在字符串里，ArkTS 编译不检查。

## 原因

未加引号的关键字列名会让该条 DDL 语法错误；init 顺序执行时，从这条起的表和索引都建不出来，编译照样通过，只在设备打开数据库时报 SQLite Generic error。来源中生成者读到的列清单写明 reactions 表有列 to，手写 DDL 时把所有标识符都裸写，第 10 条语句失败，其后 5 张表与 9 个索引从未创建。

## 做法

1. DDL 中的表名、列名统一加双引号（或反引号），不按列清单裸写；谓词、查询与索引语句引用这些列时同样加引号。
2. 有 Room 导出 schema（schemas/<Database>/<version>.json）时，以各表 createSql 为底稿，把 ${TABLE_NAME} 换成实际表名，不从列清单重新拼写。
3. 规格或侦察整理列清单时一并保留原始 createSql，或标出属于 SQL 关键字的列名。

## 可选检查

- 写完 DDL 后，在本地 sqlite3 的单个连接中按 init 的实际执行顺序逐条执行全部语句，确认 0 失败；编译成功不代表 SQL 字符串有效。
