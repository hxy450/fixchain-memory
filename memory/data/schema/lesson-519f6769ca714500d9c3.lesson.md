# SQLiteOpenHelper 构造不建库，首个 getReadable/WritableDatabase 才建：目标不在启动 init 里预建库，依赖“库文件是否存在”的流程（备份失败、恢复建库）按源路径保留

ID：`lesson-519f6769ca714500d9c3` · 版本：1

[本主题](index.md)

## 何时使用

规格提取与数据层实现阶段，把继承 SQLiteOpenHelper 的 helper 与其调用方映射为 relationalStore 初始化时

## 适用情境

源 helper 继承 SQLiteOpenHelper，构造只调 super，启动路径只 new helper，DAO 可能没有调用方；目标准备在入口或服务构造里 getRdbStore/init 建库，备份读写依赖库文件是否存在。

## 原因

“构造即建库”是误读：源端正常使用中库文件可能根本不存在（来源中备份因此总是失败），目标启动即建库会改变备份结果与恢复后的文件状态。

## 做法

1. 规格写明建库时机：首个 getReadable/WritableDatabase（或等价写入）时才建，没有调用方就不存在；目标启动路径不预建库，按源端实际调用点打开。
2. 依赖库存在与否的流程（备份写侧“库不存在即失败”、恢复时建库）按源端实现，可提供不触发建表回调的“检查文件存在/仅打开”入口供其使用。
