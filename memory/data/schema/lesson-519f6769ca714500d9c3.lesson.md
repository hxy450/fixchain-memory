# SQLiteOpenHelper 首次取数据库时才建库：有流程依赖库文件是否存在时，目标启动不预建库

ID：`lesson-519f6769ca714500d9c3` · 版本：2

[本主题](index.md)

## 何时使用

规格提取与数据层实现阶段，把继承 SQLiteOpenHelper 的 helper 与其调用方映射为 relationalStore 初始化时

## 适用情境

源 helper 继承 SQLiteOpenHelper，构造只调 super，启动路径只 new helper，DAO 可能没有调用方；备份、恢复或首次判断等流程按数据库文件是否存在分支；目标准备在入口或服务构造里 getRdbStore/init 建库。

## 例外与边界

- 没有任何流程依赖库文件是否存在时，启动时打开数据库不改变行为，按常规初始化即可

## 原因

“构造即建库”是误读：源端正常使用中库文件可能根本不存在，依赖库文件存在与否的流程（备份写侧“库不存在即失败”、恢复时建库）结果随之不同；目标启动即建库会改变这些分支与恢复后的文件状态。getRdbStore 本身会创建数据库文件，不能拿它检查存在性。

## 做法

1. 规格写明建库时机：首个 getReadable/WritableDatabase（或等价写入）时才建，没有调用方就不存在；存在依赖库文件是否存在的流程时，目标启动路径不预建库，按源端实际调用点打开。
2. 这些流程的存在性检查用 fileIo.accessSync 查按库名定位到的数据库文件，不调用 getRdbStore；分支行为（库不存在即失败、恢复时建库）照源端实现。
