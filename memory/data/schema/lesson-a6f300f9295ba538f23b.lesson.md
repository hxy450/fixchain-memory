# Room 数据库落成 relationalStore 时保留库名、schema 版本与显式升级路径；迁移代码里的 xxx_new 是临时表

ID：`lesson-a6f300f9295ba538f23b` · 版本：1

[本主题](index.md)

## 何时使用

数据层实现阶段，把 Room 数据库落成 relationalStore，确定库名、schema 版本、建表语句与升级路径时；以及评审或修复分诊缺表问题时

## 适用情境

源端 Room @Database 声明 version，配 addMigrations/AutoMigration 与 fallbackToDestructiveMigration，迁移代码用 xxx_new 临时表重建后 RENAME；规格要求显式版本化迁移、保留源 schema 历史与字段可空性。

## 原因

无版本的 CREATE TABLE IF NOT EXISTS 没有升级路径，库名不同也会与源端约定脱节；另加源端没有的 DEFAULT 会改变可空语义。把迁移临时表当成缺失的持久表，会让修复去建不存在的模型。来源中实现者读到了规格的版本化迁移要求和源端迁移配置，仍写成无版本建表、库名不同；评审把 MIGRATION_1_2 里的 recipe_new 数成缺表。

## 做法

1. 打开 RdbStore 后按源端 @Database(version=…) 设置 store.version，并为旧版本写出显式升级分支。
2. 建表 SQL 以 Room 导出的最终 schema JSON（schemas/<Database>/<version>.json 的 createSql 与 notNull）为准，不加源端没有的 DEFAULT；库名取 Room.databaseBuilder 的第三个参数。
3. 只在 Migration.migrate 里创建、随后被 RENAME 的 xxx_new 表按临时表处理；缺表对照以最终 schema 的实体为准。
