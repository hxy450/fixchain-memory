# 手写 relationalStore 插入时省略 Room autoGenerate 主键：0（可空为 null）表示未赋值，显式写入会互相替换

ID：`lesson-5c101b4b3f08ab317202` · 版本：2

[本主题](index.md)

## 何时使用

数据层实现阶段，把 Room 实体与 @Insert 方法翻译成 relationalStore 手写 INSERT/INSERT OR REPLACE SQL、决定自增主键列是否写入时

## 适用情境

源 Room 实体用 @PrimaryKey(autoGenerate = true) val id = 0，行由映射函数新建且 id 保持默认 0，再经 @Insert(onConflict = REPLACE) 批量写入；目标用 executeSql 手写插入，行接口保留 id 字段。

## 例外与边界

- 源端确实为该行指定了真实主键（非空整型为非 0 值，可空类型为非 null，如按固定 id 播种），此时照源端写入该值；播种时机与固定种子 id 见 data/seeding 的建库播种经验

## 原因

Room 把非空 Int/Long 主键的 0、可空 Integer/Long 主键的 null 视为未赋值并由数据库分配（room-common PrimaryKey.java 注释）；SQLite 对显式给出的主键值不再自增，同一批多行都带 0 时，后一行按主键替换前一行，子表数据坍缩为一行。

## 做法

1. 对每个 autoGenerate 主键，手写 INSERT/INSERT OR REPLACE 时按 Room 的未赋值判定省略该列：非空 Int/Long 主键仅在 id !== 0 时绑定（负值也是显式主键），可空 Integer/Long 主键以 null 判未赋值；REPLACE 的冲突应落在真实唯一键上。
2. 行接口保留 id 字段时注明“插入时未赋值则由数据库分配”，避免上层按 Room 习惯填 0 后被当作真实主键。

## 可选检查

- 对批量写入有疑问时，同组插入两行再读回，行数应为 2
