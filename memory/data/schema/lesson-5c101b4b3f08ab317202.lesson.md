# 手写 relationalStore 插入语句时省略 Room autoGenerate 主键列：默认 0 表示未赋值，显式写入会让同批行按主键互相替换

ID：`lesson-5c101b4b3f08ab317202` · 版本：1

[本主题](index.md)

## 何时使用

数据层实现阶段，把 Room 实体与 @Insert 方法翻译成 relationalStore 手写 INSERT/INSERT OR REPLACE SQL、决定自增主键列是否写入时

## 适用情境

源 Room 实体用 @PrimaryKey(autoGenerate = true) val id = 0，行由映射函数新建且 id 保持默认 0，再经 @Insert(onConflict = REPLACE) 批量写入；目标用 executeSql 手写插入，行接口保留 id 字段。

## 例外与边界

- 源端确实为该行指定了非 0 的真实主键（如按固定 id 播种），此时照源端写入该值

## 原因

Room 把 0 视为未赋值并由数据库分配；SQLite 对显式给出的主键值不再自增，同一批多行都带 0 时，后一行按主键替换前一行，子表数据坍缩为一行。来源中生成者建表时写了 AUTOINCREMENT，参考示例的插入也不列自增 id，DAO 却把 id 列连同行对象的默认 0 一起绑定，按组读回时组被过滤为空。

## 做法

1. 对每个 autoGenerate 主键，手写 INSERT/INSERT OR REPLACE 的列清单与参数都省略该 id（或仅在 id>0 时绑定）；REPLACE 的冲突应落在真实唯一键上。
2. 行接口保留 id 字段时注明“插入时忽略、由数据库分配”，避免上层按 Room 习惯填 0 后被当作真实主键。

## 可选检查

- 对批量写入有疑问时，同组插入两行再读回，行数应为 2
