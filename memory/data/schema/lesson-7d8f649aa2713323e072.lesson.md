# SQLiteOpenHelper 子类迁到 relationalStore：按 VERSION 分派建表、升级与降级报错，打开失败后下次访问重试

ID：`lesson-7d8f649aa2713323e072` · 版本：3

[本主题](index.md)

## 何时使用

数据层实现阶段，把继承 SQLiteOpenHelper 的 helper 改写成 relationalStore 单例的 init/打开逻辑时；规格写“升级路径不迁移”“onCreate 即唯一入口”时

## 适用情境

源 helper 以 super(context, name, factory, VERSION) 声明版本，onCreate/onUpgrade 由基类按库版本分派，DAO 每次经 getWritableDatabase/getReadableDatabase 取库；目标准备在 init 里 getRdbStore 后直接建表，或写成“version 已达目标就返回、否则执行建表脚本”，并把 init 的 Promise 缓存为单例。

## 原因

SQLiteOpenHelper 的版本分派与“每次取库都重新尝试打开”是基类隐式契约，子类源码和规格文本都看不到：库版本为 0 走 onCreate，低于 VERSION 走 onUpgrade，高于 VERSION 走 onDowngrade（默认抛 SQLiteException），完成后写入版本（Android SQLiteOpenHelper 文档与 AOSP 实现）。只写“未达版本就建表”会对旧库执行建表脚本、跳过升级，对更高版本的库静默放行。把 init 的 Promise 永久缓存后，一次打开失败会让此后每次访问都拿到同一个 rejected Promise，源端下一次 getWritableDatabase 本会重试。规格“不迁移升级内容”只免去 onUpgrade 的脚本内容，不免去分派骨架与失败重试。

## 做法

1. 打开 store 后按源 VERSION 分派（RdbStore.version API 10 起，新建库默认 0，读写会占用数据库连接，避免频繁访问；HarmonyOS 文档 arkts-apis-data-relationalstore-rdbstore 的 version 属性，访问于 2026-10-17）：store.version === 0 执行源 onCreate 内容；0 < version < VERSION 执行源 onUpgrade(old, VERSION)，决策不迁移升级内容时仍保留该分支与版本写入，分支内容按决策处理；version > VERSION 按源 onDowngrade 处理（未覆写即抛错）；成功后置 store.version = VERSION。
2. init 用缓存 Promise 去重时，在失败分支清空缓存再抛出，让下一次访问重新打开；不把一次失败固定为单例的永久状态。
