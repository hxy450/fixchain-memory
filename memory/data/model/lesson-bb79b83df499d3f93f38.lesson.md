# 编辑会话的脏检查与保存差集按源对象语义迁移：isChanged/equals 比全部持久字段，共享集合保持同一引用并就地修改

ID：`lesson-bb79b83df499d3f93f38` · 版本：1

[本主题](index.md)

## 何时使用

数据层或 ViewModel 实现阶段，翻译编辑页的脏检查（isChanged/equals 决定是否写库、是否刷新修改时间）与保存前的差集基线时

## 适用情境

源编辑页持有原始、编辑中、暂存多份实体副本，保存前以 isChanged/equals 判定是否写库，并以 setXxxOld(other.getXxxList()) 一类 setter 让两个对象共享同一集合，保存任务随后对它就地 remove 求差集；判定方法可能定义在主仓之外的基类里。

## 原因

isChanged/equals 的字段集决定哪些修改会落库、修改时间是否刷新；从调用点或验收条文反推“用户可见字段”会漏掉地址、创建与修改时间和标志位，漏掉的修改不再保存。共享引用是源端数据流的一部分：同一列表被一处就地删除，另一处看到的就是删除后的结果；目标在赋值或求差集时各做一次 .slice() 拷贝，就切断了这条数据流，差集基线与源端不同。

## 做法

1. 判定方法读到定义再翻译：按源对象全部持久字段逐一列对照表（含地址、创建与修改时间、各标志位，以及关联集合按 id 还是同一对象比较），不从调用点推断字段集；定义在依赖库里时先取库制品核对，取不到登记决策缺口，不按验收条文反推并标“风险低”。
2. 源端 setter 直接传入另一对象的集合（没有 new ArrayList 拷贝）时，目标赋同一引用，后续删除用原地 splice；只在源端显式拷贝处拷贝。写完逐个核对每个 .slice() 与展开 [...] 是否对应源端的真实拷贝。
