# 模型字段按源端类型与构造路径建模：装箱数值不改成字符串域，null 与空串分开承载，规格缺省值在构造时赋值

[本主题](index.md)

## 何时使用

规格提取阶段为实体写字段表与序列化契约时；模型实现阶段为字段确定类型、可空性与缺省值时，尤其实体继承自外部库基类

## 适用情境

源实体字段为 Double/Long 等装箱类型，另有接受 String 的 setter 或以 String.valueOf 写出 Parcel；某些构造路径显式传 null，另一些调用点传 ""；规格字段表给出构造缺省值（如 id 缺省为当前毫秒）；目标为 ArkTS 显式字段、手写 toJson/fromJson 与 relationalStore 绑定。

## 原因

存储类型由字段声明与 getter 决定，String 入口只是解析入口；按入口把存储改成字符串，会连带改变落库值（"" 写成 TEXT 而非 NULL）、JSON 类型与比较结果。Java 引用字段的 null 与 "" 是两个可观察的值：落库 NULL 与空串、JSON 省略键与输出空串都随之不同，用 '' 兼表两者就无法还原。缺省值从构造挪到仓储层补值，会让未经仓储的对象（备份、比较、新建未保存）拿到不同的值。

## 做法

1. 字段类型取声明与 getter 的类型真值；源端另有 String 入口时存储仍用数值类型，另写访问器复刻解析规则（例：按 Double.parseDouble 解析、失败置 null），落库绑定与写 JSON 都按数值语义（空串或不可解析写 NULL 或省略）。
2. Java 引用类型字段按各构造路径与调用点区分 null 与空串：任一路径显式传 null，目标就声明 T | null 保留原值，落库 NULL 与 JSON 省略键按原值判定，不以 '' 兼表。
3. 规格字段表写明的缺省值在构造时赋值；要改由仓储层补值，先回源码确认无参构造确实不赋值，并在注释引出处。
