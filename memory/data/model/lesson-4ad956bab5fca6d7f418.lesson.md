# 查询层重算源端派生状态时逐分支移植源判定函数；按审查意见修范围只改指明的条件

ID：`lesson-4ad956bab5fca6d7f418` · 版本：4

[本主题](index.md)

## 何时使用

数据层实现、复核或按审查意见修正阶段，在查询层重算源端由判定函数给出的派生状态（完成态、计数），或修改该状态的写入键、删除范围时

## 适用情境

源端由一个含多分支豁免的判定函数给出派生状态（例：完成态按完成模式、是否重复事件与发生日期分支判定），目标准备依据审计或交接摘要在查询层重算，仓内可能已有实现；或审查意见只要求收窄某个范围，修正时可能顺带改写共享状态的写入键。

## 原因

摘要把判定概括成一句话时会漏掉分支豁免，用它重写的查询层计算替换已有结果，部分记录会一直判错；“是否成立”与“计数”常有不同口径，混用会改变结果。修一个范围缺陷时顺带改写写入键，会把共享状态变成个人私有，其他使用者的操作不再生效。

## 做法

1. 重算前定位源端判定函数及其过滤、解析辅助函数，按分支列出条件表：每个分支按什么键匹配（日期、记录 ID、成员 ID）、哪些分支豁免日期条件；“是否成立”与“计数”分别取各自的源口径，不预设统一公式。
2. 仓内已有实现与摘要冲突时以源端函数裁决，不用更严格的重算覆盖；为每个判定分支各备一条回归数据。
3. 改写入键或删除范围前读源端状态创建与删除实现，逐项对齐：写入的是成员 ID 还是共享键，范围条件只对哪类记录生效。
4. 按审查意见修一个范围缺陷时只改意见指明的条件，不顺带改变共享/私有语义；确需改变时以源码为据写明理由。
