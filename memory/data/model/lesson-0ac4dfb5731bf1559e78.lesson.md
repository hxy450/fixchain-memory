# 把源端判定函数改写成名称谓词时，大小写等归一放在谓词内部，不依赖调用方先归一

ID：`lesson-0ac4dfb5731bf1559e78` · 版本：1

[本主题](index.md)

## 何时使用

数据层实现阶段，把源端的系统目录、类型等判定改写成按名称或字符串匹配的谓词函数时

## 适用情境

源端判定函数在内部对名称做 lowercase(Locale.ROOT) 等归一后比对；目标只能拿到显示名等字符串，改写为名称白名单谓词，该谓词被多个调用方使用，之后可能被公开或直接单测。

## 原因

归一放在调用方时，谓词自身的契约依赖一个隐含前置条件，新的调用方或直接调用会得到大小写敏感的结果，与源端不一致。来源中生成者把源端判定函数内部的 lowercase 移到了两个调用方；谓词私有时运行结果正确，公开后被直接传入混合大小写的名称即判错。

## 做法

1. 在谓词内部先做与源端相同的归一（如 const n = name.toLowerCase()）再比较，让谓词对任何调用方都自成契约；调用方已有的归一可以保留。

## 可选检查

- 对归一语义存疑时，用混合大小写样例直接调用谓词，对照源端归一后再判定的结果
