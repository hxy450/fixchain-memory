# process/testing

验证阶段的单元测试：预期值与夹具从源端实现推出，失败用例分诊时对照源端，测试契约与源端语义冲突时上报而不改产品

## 本级经验

- [单元测试的预期与分诊以源端实现为准：设计时按源逐步手算并避开退化输入，失败时用同一输入核源端，不改产品迁就测试](lesson-5bc9af19bedaecaf627c.lesson.md)
  - 时机：验证阶段设计与编写单元测试，为迁移的算法、集合过滤与初始化分支选择输入夹具和预期值时；对单测失败做分诊、写问题文件，以及修复代理处理失败用例时；规格提取阶段为公式写验收样例时
  - 情境：迁移代码按源端逐函数对齐；设计者只拿到抽象期望（如“某模式只预选收藏”“相同输入签名一致”），需要自己选输入、构造夹具，可能加入比源端更严的契约（如“不同图片哈希必然不同”）；验收条目文字可能超出源端范围。修复代理被要求以测试为契约、通常不能改测试，但可用 BLOCKED、manual_review 或处置提示上报。
  - 例外：任务已有用户明确批准的行为变更（规格或台账写明且经用户授权，不是模型或流水线自记的 approved）时，该范围内的预期按批准后的契约写，不用旧源码否决
