# process/testing

验证阶段的单元测试：预期值与夹具从源端实现推出，失败用例分诊时对照源端，测试契约与源端语义冲突时上报而不改产品

## 本级经验

- [单元测试为迁移代码定预期值时按源端实现手算，不编造比源端更严的区分性或过滤期望](lesson-5bc9af19bedaecaf627c.lesson.md)
  - 时机：验证阶段设计与编写单元测试，为迁移的算法、集合过滤与初始化分支选择输入夹具和预期值时
  - 情境：迁移代码按源端逐函数对齐；测试设计模板要求每个验收项覆盖正常、边界、异常输入，设计者只拿到抽象期望（如“某模式只预选收藏”“不同图片哈希不同”），需要自己选输入、构造夹具；验收条目的文字可能超出源端范围。
  - 例外：当前规格或已批准决策明确要求目标行为不同于源端
- [单测失败分诊与修复时先用同一输入核对源端：源端同样如此就按测试契约问题上报，不改产品语义迁就测试](lesson-75cb65ef5601aaa8f159.lesson.md)
  - 时机：验证阶段对单元测试失败做分诊、写问题文件，以及修复代理处理失败用例时
  - 情境：修复代理被要求以测试为契约、通常不能改测试，但可用 BLOCKED、manual_review 或处置提示上报；失败用例的期望可能来自比源端更严或与源端相反的测试设计或规格条目。
  - 例外：当前规格或已批准决策明确要求目标偏离源端行为，此时按规格修复并记录差异
