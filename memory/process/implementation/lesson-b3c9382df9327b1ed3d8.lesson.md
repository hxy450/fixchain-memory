# 源回调接口实现类继承空默认基类时，按源子类的覆写全集落实目标覆写与界面门面，基类空默认不作终态

ID：`lesson-b3c9382df9327b1ed3d8` · 版本：1

[本主题](index.md)

## 何时使用

规格提取阶段从源端回调接口实现类清点服务层回调与验收项时；实现阶段编写目标回调实现类、ViewModel 到界面的门面与页面桥接时

## 适用情境

源端回调接口由 Basic 一类基类提供空默认实现，Activity 级实现类覆写其中一部分（各类 on*Error 提示、就绪回调、拍摄期回调等），引擎与控制器在失败或就绪时只回调接口、不自行提示或刷新界面；目标沿用“继承空基类的实现类 + ViewModel sink + 界面门面”分层，规格可能只点名其中几个回调。

## 原因

目标子类只覆写规格点名的回调时，其余调用落到基类空默认，失败提示与就绪后的刷新全部静默，编译和结构检查都放行；ViewModel 自定义的界面门面缺少源回调会调用的界面方法时，下游只能按缺项接口接线，状态没有出口。

## 做法

1. 列出源实现类的 @Override 全集，与规格服务层清单、目标子类的覆写做差集；差集逐项补规格条目与覆写，或写明归属的 feature；同时确认承接回调的 ViewModel 方法确有调用者。
2. 逐个回调读源实现体，把其中调用的界面方法与提示（显示控件、图标启停状态、错误提示的资源名）列入 ViewModel 到界面的门面并在 sink 中调用；门面缺项时先补成员，再在页面转发，最后才把相应移交项标为完成。
3. 页面桥接的失败路径调用接口的错误回调（源端唯一的提示出口），不在桥里另发提示；确需直接提示时只传已本地化文本，资源名与源一致。
