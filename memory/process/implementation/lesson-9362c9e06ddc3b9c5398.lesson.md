# 错误类型按源路径实际的 catch 与构造映射：sealed class 里有某类型不代表该路径产生它，错误字段逐个对照构造默认值

ID：`lesson-9362c9e06ddc3b9c5398` · 版本：1

[本主题](index.md)

## 何时使用

服务实现阶段，把源端抓取、解析等路径的错误类型与错误数据字段翻译为目标错误模型时

## 适用情境

源端用一层 Either.catching 或 try/catch 把多种格式或步骤的失败统一归为一种错误，sealed class 中另有更细的错误类型却不在该路径产生；错误数据类的 message、description 等字段各有构造来源与默认格式；派工里可能只有“某某失败错误类型”一类笼统措辞。

## 原因

按类型表或派工措辞为每种输入单独分类，会让调用方的分支与提示偏离源端；把 description 的拼接格式同时写进 message，或用自造文案代替源端读取的响应字段，展示与日志也随之改变。

## 做法

1. 以源端该路径实际的 catch 与构造为准决定错误类型：一层 catching 包住全部格式时，各格式失败都返回该类型；派工措辞笼统而具体 AC 与源码一致时按 AC 与源码实现。
2. 移植错误数据类时逐字段对照构造参数与默认值（如 message 取响应原因短语，description 默认为 "code: message"），不把一个字段的格式套到另一个字段。

## 可选检查

- 用每种错误路径各一个最小样例核对类型与字段值，如非法 JSON、带原因短语的 404
