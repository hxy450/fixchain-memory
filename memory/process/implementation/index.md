# process/implementation

把已读到的源端语义落成目标代码时的通用取舍：不补写源端没有的元素、输入规范化或交互步骤，看似缺陷或不够健壮的源端行为照搬（修正须登记决策），含布尔组合的条件表达式逐字翻译；内联被调组件时调用点实参与被调公式的整链转写，非空类型上的空判断（死分支）不译成可达触发

[上一级](../index.md)

## 本级经验

- [不补写源端没有的元素、输入规范化或交互步骤：有没有某元素按源端最终渲染判断，框架与主题默认生成的元素算已有](lesson-352b96f599237cd27403.lesson.md)
  - 时机：规格提取或界面、接线实现阶段，准备按“常见样式”“更稳妥”或项目惯例补写源端未声明的装饰、输入处理或流程步骤时；派工或转换表写了源端没有的元素时
  - 情境：源 XML、回调或主题中不存在某元素或步骤（列表行无尾部箭头、校验与传递使用未 trim 的原文、选项弹层点击只重绘不关闭、批量动作无确认、搜索框无容器底色），写者凭通用样式或兄弟页加入；或派工补充说明、转换表写了源端没有的元素、改了控件类型（如设置行尾部箭头、把复选框改成开关）。也包括源控件的部分可见元素由框架默认生成、源码与 XML 里看不到（如 ListPreference 对话框的 android.R.string.cancel 负按钮），提醒却写成“弹层无按钮”。
  - 例外：决策台账中有带编号的已批准差异决策（如 PD-*）要求新增；派工消息、转换表或兄弟页里的说法不算批准
- [内联或重建被宿主调用的组件时按“调用点实参 → 被调公式”整链转写：调用点上的乘数、换算与派生包装一并保留](lesson-4428ce765fcef294b004.lesson.md)
  - 时机：页面转换或公共组件实现阶段，把源端被宿主调用的共享组件（如 Compose 的 Composable）转写为页面内联方法或目标公共组件，确定各显示值的实参与公式时
  - 情境：源端宿主以表达式作实参调用共享组件（如 Comp(progress = p.value * multiplier)，或 remember { derivedStateOf { a.value * b } } 的结果），被调组件内部只对形参运算；目标准备在页面内联等价实现，或另建公共组件供多页调用；派工可能只把被调组件文件列为样式真源。
- [增量迁移新注册条目时，用同构建器、同分组的已迁移兄弟 key 在目标工程全量检索，列出它所在的全部白名单与映射表](lesson-081caee9c02b394bef92.lesson.md)
  - 时机：增量迁移阶段，为源端新增的注册条目（如按 key 配置的指标）列目标端改动清单、确定要登记的全部位置时
  - 情境：源端条目经公共构建器统一附加说明链接、图标或回调等能力；目标端把这些能力拆成分散在多个文件、按 key 登记的白名单或映射表；计划按功能点逐个找登记点。
- [源端看似缺陷或不够健壮的可观察行为照原样迁移并按可观察次数核对；确需修正时写入决策台账或 decision_gaps 待批](lesson-14411595fd9ac1e17683.lesson.md)
  - 时机：规格提取与切片实现阶段，转写源码中看似缺陷、缺少防护或时序可疑的逻辑（未赋值导致的失败返回、无条件的结果回投、只在成功时退出的循环、在校验前置位的标志、整段一个 try 的循环），或 lint、规格补充件要求补取消、竞态、防御条目时
  - 情境：迁移目标是行为等价，迁移原则（如默认策略文件）要求保留原有行为“包括缺陷、空点击和异常分支”，但续跑或补建的台账、派工里可能没有这条规则；写者认为源码“有缺陷”“不够确定”“不够健壮”，在源码笔记里写“源缺陷不移植/行为增强/防御/确定性取舍”，或规格为回应 lint 写入“页面销毁时丢弃迟到结果”“取消标志为唯一出口”一类源码没有的要求。
  - 例外：决策记录明确批准修正某项原版缺陷；源端崩溃路径按已登记的例外处理
- [目标契约把源端落盘方法内的标志守卫移到调用侧时，逐条并入调用侧条件，并按各退出路径执行时刻的标志值核对](lesson-06e3564e91948a2b05a3.lesson.md)
  - 时机：切片实现阶段，把源端保存/落盘链迁到目标服务与页面、决定写入的抑制条件时
  - 情境：源端落盘方法体首行自带标志守卫（if (flag) return 一类），目标仓储改为纯服务、契约写明该抑制判定在调用侧；退出分支在置抑制标志前调用了会重置其他标志的初始化或 reset 函数，使另一个标志看似可以替代该守卫。
- [翻译 == null / != null 前先核声明类型与来源：编译期保证非空时 == null 恒假（从不触发）、!= null 恒真](lesson-8c18bb22a8ecfe8c7f8a.lesson.md)
  - 时机：规格提取阶段把源端显示条件、弹窗或权限请求的触发条件写成页面契约与偏好默认值时；实现阶段按规格新增依赖该条件的弹窗、权限请求或协调服务时
  - 情境：Compose 页面用 collectAsState(initial = false) 收集 Flow&lt;Boolean&gt;（DataStore getter 映射为 preferences\[KEY\] == true 或带 ?: 默认值），显示条件里却把该状态与 null 比较；规格可能同时写着“该偏好 Boolean、默认 false”与“== null 表示从未写入/首次进入”。
  - 例外：值来自 Java 平台类型（未标注可空性的 Java API 返回值，Kotlin 视为 T!）、反射反序列化（Gson 等可绕过 Kotlin 非空检查写入 null）或其他不受控来源时，非空声明不保证运行时非 null，== null 分支可能可达，回源码看数据的实际来源再判断（依据：kotlinlang.org Java interop 的 null safety and platform types 一节，2026-10-15 访问）；collectAsState(initial) 加受控 getter 映射这类来源仍按非空处理
- [翻译条件表达式与分支时保留源的分组与分支范围：布尔异或在 ArkTS 写成 !==，列真值表，源码没有 else 就不新增分支](lesson-381ebc5899e92cbd23a2.lesson.md)
  - 时机：实现阶段，翻译含异或、与或组合的三元或条件表达式（如气泡箭头位置、方向相关分支），或移植带守卫的 if 分支（空输入守卫、缺参数不动作）时
  - 情境：源表达式形如 a + ((x ^ y) ? 0 : b)，转述时容易丢掉内层括号或取反分支；或源端计算入口只有 if (a != null &amp;&amp; b != null) 分支、没有 else，目标准备在输入无效时新增清空结果或复位界面的分支。
