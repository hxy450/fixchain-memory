# 源端看似缺陷或不够健壮的可观察行为照原样迁移：失败返回、无条件回投、循环退出条件、副作用时序与异常作用域都按源码；确需修正时登记决策

## 何时使用

规格提取与切片实现阶段，转写源码中看似缺陷、缺少防护或时序可疑的逻辑（未赋值导致的失败返回、无条件的结果回投、只在成功时退出的循环、在校验前置位的标志、整段一个 try 的循环），或 lint、评审建议补取消、竞态、防御条目时

## 适用情境

迁移目标是行为等价，迁移原则（如默认策略文件）要求保留原有行为“包括缺陷、空点击和异常分支”，但续跑或补建的台账、派工里可能没有这条规则；写者认为源码“有缺陷”“不够确定”“不够健壮”，在源码笔记里写“源缺陷不移植/行为增强/防御/确定性取舍”，或规格为回应 lint 写入“页面销毁时丢弃迟到结果”“取消标志为唯一出口”一类源码没有的要求。

## 例外与边界

- 决策记录明确批准修正某项原版缺陷；源端崩溃路径按已登记的例外处理

## 原因

用户可见结果（Toast、失败返回、跳转、文件名、写入顺序）随这些“修正”改变，对照源端运行就是偏差；规格里自创的防御会被实现照写成契约。只写在源码笔记里的取舍不会进入任何裁决。来源中同一应用多处如此：保存时 NPE 导致的失败返回被改成成功、无条件追加的扩展名被去重、读卡完成后无条件打开编辑器被规格改成页面销毁即丢弃、范围校验前置位的常亮被收敛到成功路径、重连循环被加了取消出口、整循环一个 try 的复制被改成逐文件 try、按 Locale 的周规则被改成“确定性”的 ISO。

## 做法

1. 规格提取时逐条对照源码表达式与注释，把实际结果按“源码锚点 + 触发条件 + 原结果 + 目标预期”写进验收；源码循环保留原退出条件，回投与副作用写明在页面结束后是否照常发生。
2. 实现时照搬可观察结果：失败返回与提示、无条件回投后的 Toast/跳转/结束页面、标志的 set 与 clear 位置、字段在校验前赋值、异常作用域（整个循环一个 try 即首错停止）与遍历顺序，以及经数组引用原地修改调用方数据的副作用。
3. 认为需要修正、加防御、补取消出口或改用“确定性”语义时，作为待确认决策写入台账交裁决，不在规格补充、源码笔记或注释里自行定案。
4. 中断续跑判定规格已完成前，核对台账是否已有原版缺陷条目；补建台账时按迁移原则枚举缺陷实例，并把“保留原版缺陷”写进后续派工。
