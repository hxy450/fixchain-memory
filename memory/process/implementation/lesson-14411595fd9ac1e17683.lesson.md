# 源端看似缺陷或不够健壮的可观察行为照原样迁移并按可观察次数核对；确需修正时写入决策台账或 decision_gaps 待批

ID：`lesson-14411595fd9ac1e17683` · 版本：5

[本主题](index.md)

## 何时使用

规格提取与切片实现阶段，转写源码中看似缺陷、缺少防护或时序可疑的逻辑（未赋值导致的失败返回、无条件的结果回投、只在成功时退出的循环、在校验前置位的标志、整段一个 try 的循环），或 lint、规格补充件要求补取消、竞态、防御条目时

## 适用情境

迁移目标是行为等价，迁移原则（如默认策略文件）要求保留原有行为“包括缺陷、空点击和异常分支”，但续跑或补建的台账、派工里可能没有这条规则；写者认为源码“有缺陷”“不够确定”“不够健壮”，在源码笔记里写“源缺陷不移植/行为增强/防御/确定性取舍”，或规格为回应 lint 写入“页面销毁时丢弃迟到结果”“取消标志为唯一出口”一类源码没有的要求。

## 例外与边界

- 决策记录明确批准修正某项原版缺陷；源端崩溃路径按已登记的例外处理

## 原因

用户可见结果（Toast、失败返回、跳转、文件名、写入顺序、弹窗个数）随这些“修正”改变，对照源端运行就是偏差；规格里自创的防御会被实现照写成契约；只写在源码笔记里的取舍不会进入任何裁决。只保留代码结构、把同一次操作的多次触发收敛成一次（如多次命中弹窗条件只弹一个），可观察次数同样改变。

## 做法

1. 规格提取时逐条对照源码表达式与注释，把实际结果按“源码锚点 + 触发条件 + 原结果 + 目标预期”写进验收；源码循环保留原退出条件，导入或恢复循环按源码解析与写库的实际先后写中止语义（逐条写入、遇错即停、已写入的保留），回投与副作用写明在页面结束后是否照常发生。
2. 实现时照搬可观察结果并按次数核对：失败返回与提示、无条件回投后的 Toast/跳转/结束页面、标志的 set 与 clear 位置、字段在校验前赋值、异常作用域（整个循环一个 try 即首错停止）与遍历顺序，以及经数组引用原地修改调用方数据的副作用；循环内每次命中都弹窗或落盘时，目标的弹窗个数、确认次数与写入次数与源端相同。
3. 认为需要修正、加防御、补取消出口或改用“确定性”语义时，作为待确认决策写入决策台账或 handback 的 decision_gaps 交裁决，不先改代码；什么算批准按规格与源码冲突的裁决经验（只认带决策 ID 的条目），源码笔记、注释里的登记与无人值守流程的自动批准都不算。
4. 中断续跑判定规格已完成前，核对台账是否已有原版缺陷条目；补建台账时按迁移原则枚举缺陷实例，并把“保留原版缺陷”写进后续派工。
