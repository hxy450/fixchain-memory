# 内联或重建被宿主调用的组件时按“调用点实参 → 被调公式”整链转写：调用点上的乘数、换算与派生包装一并保留

ID：`lesson-4428ce765fcef294b004` · 版本：4

[本主题](index.md)

## 何时使用

页面转换或公共组件实现阶段，把源端被宿主调用的共享组件（如 Compose 的 Composable）转写为页面内联方法或目标公共组件，确定各显示值的实参与公式时

## 适用情境

源端宿主以表达式作实参调用共享组件（如 Comp(progress = p.value * multiplier)，或 remember { derivedStateOf { a.value * b } } 的结果），被调组件内部只对形参运算；目标准备在页面内联等价实现，或另建公共组件供多页调用；派工可能只把被调组件文件列为样式真源。

## 原因

被调组件的形参名与宿主的原始变量同名或近名时，只转写被调公式会把形参直接接到宿主的原始值，丢掉调用点上的乘数、换算或包装。常见输入（倍率为 1）下显示一致，倍率变化才暴露；后续接线者若只核对被调公式，也看不出缺了调用点的那一段。

## 做法

1. 转写被调组件时同时打开它的每个调用点，逐个形参写出“形参 = 调用点实参表达式”，再代入被调公式；内联到页面时以代入后的完整表达式实现，即 显示值 = f(形参 := 调用点实参表达式)，例如 time × (progress × multiplier)。
2. 同一宿主对多个组件或显示值各有调用点时，按调用点分别核对实参与乘数；改为共享组件时，调用点上的换算留在宿主侧或作为显式参数传入，不在组件内部假设已换算。

## 可选检查

- 用一组非 1 的倍率与非 0、非 1 的进度（如倍率 2、进度 0.5）代入，核对各显示值与源端整链公式一致
