# 不补写源端没有的元素、输入规范化或交互步骤：有没有某元素按源端最终渲染判断，框架与主题默认生成的元素（如 ListPreference 对话框的 CANCEL）算源端已有、必须保留；例外只认台账中带编号的已批准差异决策，派工措辞与转换表不算批准

ID：`lesson-352b96f599237cd27403` · 版本：5

[本主题](index.md)

## 何时使用

规格提取或界面、接线实现阶段，准备按“常见样式”“更稳妥”或项目惯例补写源端未声明的装饰、输入处理或流程步骤时；规格、派工与转换表对某行元素或控件类型说法不一致时

## 适用情境

源 XML、回调或主题中不存在某元素或步骤（列表行无尾部箭头、校验与传递使用未 trim 的原文、选项弹层点击只重绘不关闭、批量动作无确认、搜索框无容器底色），写者凭通用样式或兄弟页加入。也包括源端计算入口只有 if (a != null && b != null) 分支、没有 else，目标在输入无效时新增清空结果的分支。也包括派工补充说明或转换表写了源端没有的元素或改了控件类型（如设置行尾部箭头、把复选框改成开关），实现者以“派工指定的例外”“最新指令”为由保留，甚至回写规格去迎合派工。也包括源控件的部分可见元素由框架默认生成、源码与 XML 里看不到（如 ListPreference 对话框的 android.R.string.cancel 负按钮），提醒却写成“弹层无确定/取消钮”。

## 例外与边界

- 决策台账或规格中有带编号的已批准差异决策（如 PD-*）要求新增；派工消息、转换表或兄弟页里出现的说法不算批准

## 原因

新增的元素或步骤会改变可见结果或行为边界：多余箭头误导、trim 改变可接受输入、选中即关闭让同一面板内的后续操作不可达、额外确认改变批量流程。

## 做法

1. 先列出源控件由框架默认生成的可见元素（ListPreference/DialogPreference 对话框的标题、dialogIcon、单选列表与 android.R.string.cancel 负按钮、无确定钮），这些不是补写，按源保留；只有源 XML、代码、主题与框架默认都不产生的元素才不加。
2. 规格只按源 XML 与源码描述组成和流程；以“Material 风格”“保持一致”为由新增的元素须有源依据。
3. 源端校验并传递原文时，目标也校验并传递原文，不额外 trim 或大小写归一。
4. 选项型弹层的选中回调按源端点击处理决定是否关闭：源只重绘并回调时，宿主回调不置 visible=false。
5. 复用兄弟页的确认弹窗、关闭语句或底色前，对照本页源码是否存在。
6. 移植空输入守卫时按源码 if 分支的范围翻译：源码没有 else 就不新增清空或复位界面的分支；服务层的空结果不被页面无条件拿去覆盖界面，页面在调用前判断并直接返回。
7. 派工、转换表与已审规格对源端元素或控件类型说法冲突时，按源 XML 与源码核对后实现源端事实，冲突写进报告交编排者裁决；不以“最新指令”覆盖规格，也不回写规格去迎合派工；编排者写派工补充说明前先读该页已审规格。
