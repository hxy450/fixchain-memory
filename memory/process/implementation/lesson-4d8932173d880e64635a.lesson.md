# 源端在菜单或 ActionMode 回调入口统一门控（验密、登录、权限）再分发动作时，目标在分发入口统一门控，例外动作照抄源列表

ID：`lesson-4d8932173d880e64635a` · 版本：1

[本主题](index.md)

## 何时使用

页面实现与收口接线阶段，把源端 onActionItemClicked、onOptionsItemSelected 一类回调翻成目标动作分发表并为动作接门控时；页面转换阶段为分发表写占位注释时

## 适用情境

源回调先对全部动作执行一次门控（如受保护内容先验密、未登录先拉登录），只把少数动作列为例外，再按菜单 id 分发；目标把分发写成按动作的 switch 或多个处理函数，门控实现由其他切片提供，页面占位注释或规格验收条目可能只点名其中几个动作。

## 原因

入口级门控的适用范围由源回调入口的例外列表决定；改写成逐动作分支后，只在被点名的动作里调用门控，其余动作就绕过保护。占位注释或验收条目是二手概括，按它逐个补门控会把概括漏掉的动作留在门外，编译与结构检查都发现不了。

## 做法

1. 按源回调入口建门控：列出源端门控之前判断的例外动作与之后的全部动作，在目标分发函数入口统一调用门控、例外照源列表放行，不在各分支里分别挂门控。
2. 收口时以源回调为准逐个动作核对目标分发表：每个动作是否经过门控、是否属于例外；页面占位注释或验收条目列出的局部分支只作线索。
3. 页面转换阶段为分发写占位注释时，照抄源回调门控的适用范围（全部动作及例外列表）与源码位置，不把入口级门控缩写成个别动作。
