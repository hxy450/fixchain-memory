# 把源端重开一局的函数迁为复位函数时按字段生命周期取舍：只复位重开路径实际赋值的字段，类静态与宿主实例字段跨局保留

ID：`lesson-bc33ed4f6903382e4fb1` · 版本：1

[本主题](index.md)

## 何时使用

规格提取与引擎实现阶段，把源端重开一局或一轮的函数（initGame、reset 一类，常在其中 new 循环或会话对象）映射为目标的复位函数、确定新局要复位哪些字段时

## 适用情境

源端重开函数体只给一部分字段赋值，并 new 出循环或会话对象（其实例字段由构造与字段初始化器给初值）；另有类 static 字段（只在类加载时初始化）和宿主对象的实例字段（只随宿主构造初始化）。目标把多个源对象合并成模块级静态引擎或单例，规格把这些字段并成一个“实例态”列表，或写“新局复位全部状态”。

## 原因

static 字段初始化器只执行一次，宿主实例字段只随宿主构造初始化，重开函数不碰它们，它们的值会跨局保留（已减到负数的计数、仍在飞的对象），下一局首帧的行为依赖这些残留值。合并成静态引擎后把它们也写进复位，跨局的可观察行为就变了。

## 做法

1. 规格提取时逐字段标出声明位置与生命周期（类静态、宿主实例、重开时新建对象的实例），只把重开函数体实际赋值的字段、以及其中新建对象的构造与字段初始化器列为每局复位，其余字段写明跨局保留；验收条目标注的源码区间内要能找到它列出的每一条赋值。
2. 实现合并后的复位函数时，每条赋值都要能指到源端每局路径中的一条赋值；规格要求的复位与源码不符时按源码实现，并在 handback 中回报规格缺口。
