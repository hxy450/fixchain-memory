# 目标契约把源端落盘方法内的标志守卫移到调用侧时，逐条并入调用侧条件，并按各退出路径执行时刻的标志值核对

ID：`lesson-06e3564e91948a2b05a3` · 版本：3

[本主题](index.md)

## 何时使用

切片实现阶段，把源端保存/落盘链迁到目标服务与页面、决定写入的抑制条件时

## 适用情境

源端落盘方法体首行自带标志守卫（if (flag) return 一类），目标仓储改为纯服务、契约写明该抑制判定在调用侧；退出分支在置抑制标志前调用了会重置其他标志的初始化或 reset 函数，使另一个标志看似可以替代该守卫。

## 原因

调用侧只照抄源端调用点的外层条件，被调方法内的守卫就丢了；按分支开头的赋值推断“另一标志已拦住”，会忽略中途 reset 改回的标志，刚删除的存档在随后的保存中被写回。

## 做法

1. 契约写明某判定在调用侧时，打开源端被调方法，把方法体内每个守卫逐条并入目标调用点条件；写完 grep 调用点，确认外层条件与内部守卫都在。
2. 判断某标志是否冗余前，按实际调用序模拟各退出路径（对话框的否定选项、系统返回、退后台等）在保存时刻的全部标志值，特别核对中途调用的初始化或 reset 函数是否改回了前一个标志。

## 可选检查

- 规格有“操作后存档已删除”一类验收时，按标志序列走查保存函数条件，确认删除后不会被写回。
