# 源端行为经 helper、DAO、适配器或子组件层层委托时，追到最终实现再写规格与代码，不以调用点推断

ID：`lesson-4606ccc434e247d4a240` · 版本：3

[本主题](index.md)

## 何时使用

规格提取与页面、数据层实现阶段，源端调用点只是一行委托（Activity 调 DialogHelper.showXxx、Repository 经 DAO 调 Helper、Fragment 的分页适配器再建 item 适配器、Compose 页面把整块列表交给另一文件的子 Composable）时

## 适用情境

源端真正的布局、点击时序、数据来源、选中样式或空列表分支写在被委托的方法、类或子组件里：调用点只剩 DialogHelper.showXxxDialog(ctx) { 回调 }、repository.queryByDay → dao → DateHelper、CalendarViewPageAdapter(R.layout.item) → CalendarAdapter，或 DeviceList(...) 一类带参数的子 Composable 调用（其 LazyColumn 按分区渲染，列表为空时显示内联空态）；规格按页面类或所有权切分，锚点只列到调用方。也包括 Compose 页面调用项目自定义组件（如图片组件 XxxImage(...)），形状、裁剪与填充方式写在组件定义里，调用点只给尺寸。

## 原因

只看调用点会把调用方 lambda 当成全部行为，把 DAO 名称当成数据来源，把中间适配器当成样式来源，把子组件调用当成单纯的列表。来源为同一应用的三类偏差：隐私弹窗的规格作者与实现者都没打开 DialogHelper，规格只写“显示同意弹窗、接受后继续”，实现者据此认为源端没有拒绝路径，写成单按钮弹窗，后来复刻又漏了同意区的勾选动画与 700ms 延时；农历数据的规格作者读 DAO 正文时被截断、没有打开 DateHelper，把“资产查询”写成数据来源，而源端实际逐日调用农历库计算；月历页的转换者看到分页适配器指向 item 适配器却没有继续读，选中、周末样式只能自拟。另一应用中页面规格作者定位到承载设备列表的子 Composable 却没打开正文，规格只写“LazyColumn → List+ListItem”，空列表时的图标、标题与提示文案既没写出也没标 UNCLEAR，实现者照规格摘要实现后设备列表没有空态。另一应用中三个页面转换者都读到了自定义图片组件的调用却没打开定义，页面规格也只写图片尺寸，圆形裁剪的商品图全部写成矩形。

## 做法

1. 调用点委托给 helper 或工具方法时，打开该方法全文和它 inflate 的布局或 Binding，列出控件、按钮分支和点击时序（状态变化 → 延时 → 回调 → dismiss）后再写。
2. 数据经 Repository、DAO、Helper 逐层委托时，追到最终实现确认来源（算法库、预置库、网络）；读取被截断就补读，规格的数据流与验收条目只写已核实的来源。
3. 列表或网格样式沿适配器链追到实际 item 适配器的 convert/onBind，按分支确认选中、当天、周末、节日等样式。
4. 规格提取时把被委托的实现文件与它用到的布局一并登记进源码锚点和页面契约，不只列调用方。
5. 页面把某块区域交给另一文件的子 Composable 时，打开其正文写出条件分支：空列表、加载中、分区标题与开关；空态注明图标、标题与提示文案的字符串 key 和源行号，并保留在交给实现者的规格与摘要里。未读正文时写 UNCLEAR，不只写一行组件映射。
6. 页面调用项目自定义组件时，打开组件定义取视觉契约（形状、裁剪、填充方式），写进页面规格，并把定义文件列入源码锚点。
