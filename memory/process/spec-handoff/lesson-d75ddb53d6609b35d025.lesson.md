# 多模块 Android 工程的同名布局按页面类所属模块与 Binding 类解析；发现一处误解析就复核全部同名布局

ID：`lesson-d75ddb53d6609b35d025` · 版本：2

[本主题](index.md)

## 何时使用

规格提取阶段为 Activity/Fragment 确定源布局（layout_sources）并生成分页 UI 规格时；页面转换阶段按规格选定源布局时

## 适用情境

Android 工程含多个模块，存在同名的 Activity/Fragment 类与同名布局文件（如 fragment_mine.xml、activity_main.xml）；源布局由脚本或清单按布局文件名匹配，分页规格再把它写成“源码布局”交给页面转换者。也包括同名布局分属不同 product flavor 或源集（main 与 cloud 等）的情形。

## 原因

按文件名匹配会把一个模块的页面类解析到另一个模块的同名布局，合成快照、规格和页面都按错误布局展开；“所属模块”与“源码布局”互相矛盾时，布局来源仍可能被当成权威。来源中规格作者先发现两个页面被解析到另一模块，只手工修正了这两页；后续批次脚本回执已显示页面类在 app 模块、布局在另一模块，规格子代理看到冲突后只改了模块判定并声明布局来源为权威；页面转换者同时读到本模块页面类（其 Binding 类对应只有三处点击的本模块布局），仍按错误布局写出登录区、会员卡等另一模块的内容。另一应用中，转换者用递归搜索取第一个结果读取 include 布局，拿到的是另一 flavor 的同名 item，尺寸与装饰都不同。

## 做法

1. 确定每页源布局时，用页面类的包名/所属模块及其 ViewBinding/DataBinding 类（模块包名下的 XxxBinding 对应该模块的 xxx.xml）核对布局所在模块；类在 A 模块却解析到 B 模块同名布局时，改为 A 模块布局并重新合成快照。
2. 发现任一页同名布局误解析后，列出全部跨模块同名布局逐页复核，不只修已发现的页面。
3. 分页规格里“所属模块”与“源码布局”路径必须一致；冲突时回到源码核对 Binding 类，不以“布局来源为权威”消解。
4. 页面转换写前比对布局 XML 的 data 变量类型/包名与规格中的页面类全名；不一致时按本模块源码实现，并回报规格缺陷。
5. 同名布局按页面类所在的源集选取：Adapter/Fragment 来自 main 或某 flavor 时优先同一源集，不直接用递归搜索（Select-Object -First 1）的结果。
