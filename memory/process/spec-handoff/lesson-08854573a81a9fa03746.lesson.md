# 规格提取写验收与导航条目时实读所引源码段落，照抄比较符、范围与名称变换，导航按监听器函数体写到具体目标

ID：`lesson-08854573a81a9fa03746` · 版本：6

[本主题](index.md)

## 何时使用

规格提取与计划阶段，写阈值、列表范围、过滤条件、复制/变换类或持久化类验收条目并标注源码出处时；写“点击 X 进入 Y”的导航条目与对接点、确定目标页尚不存在时的处理方式时

## 适用情境

规格作者依赖预生成参考文档或源码片段写验收条目，并以“源码文件:行号”标注出处；读取可能被截断，或只读了参考文档的目录。也包括源端对同类数据维护多组独立集合（如按页面分别写入的两组收藏），规格按页面拆成多个功能分别写条目。也包括验收条目写“点击 X 进入 Y；源：某 Fragment”，规格作者只做了声明级检索、没有展开监听器函数体；同页有多个入口（横幅进静态详情、列表子按钮查询后进实时页）。也包括入口点击后打开固定 URL 的 WebView 或带参数的详情页，目标工程尚无对应页面，流程允许用 pending/forward-ref 登记暂缺目标，但本轮之后没有安排实现这些目标页的切片。

## 例外与边界

- 所在流水线有明确的后续切片负责创建目标页并兑现前向引用：导航条目按前向引用登记，并把已读到的源端确定值（目标页、URL 常量、参数）写进登记条目

## 原因

验收条目会被实现者、测试和评审当作判据：比较符写反、把“列出全部”写成“只列缺失”、把源函数的不同分支并成一条、漏掉名称后缀或内容来源，或把别的页面的数据写进本功能条目，下游照条目实现、测试或返修，会写错或把本来正确的实现改错。把源码里已确定的导航目标抽象成“打开对应业务页”，再以 forward-ref 作为可验收结果，没有后续兑现方时交付的入口就是空点击。

## 做法

1. 写带出处的条目前打开所引行号段落；出处是某个函数时，对照它的全部 if/else 分支逐项写条目。参考文档读取 truncated 或只看到目录时，按章节读到正文。
2. 阈值条目照抄源端比较符，并给出边界两侧样例（例如源端 width > 600 时 600 仍为一列）；判例与同一规格里的同类条目和已声明的语义一致（如已声明 HALF_EVEN 就不配四舍五入式的判例）。
3. 复制、克隆这类条目写明内容来源（持久化值还是编辑中草稿）、字段变换（名称后缀、id 清零）和完成后的导航，不只写“复制字段”。
4. 为界面组件写条目时覆盖源码对展示内容的加工（如链接识别与着色），并把组件源文件列进该功能的源码锚点；工具类按 grep 到的真实调用点归属功能，不凭名字挂到不调用它的页面。
5. 源端同类数据维护多组独立集合时，逐组确认写入它的页面或 ViewModel，再按功能分别写条目；条目文字（含括注）的范围不超出本行源锚点所列的集合。
6. 写导航条目前读锚点里对应监听器的函数体（setOnBannerListener、onItemChildClick、点击防抖包装等），逐一列出“控件 → 调用 → 目标页、URL 常量与参数”；同页多个入口分别写条目与对接点，不因存在某个页面就补出源端没有的跳转。
7. 规格阶段核对目标工程是否已有对应页面与路由；没有后续切片兑现时，固定 URL 的 WebView、静态详情一类小页面纳入本轮范围，确实超出已批准范围时向用户逐项列出“哪些入口点击将无反应”作决策确认，不以 forward-ref 收尾。
