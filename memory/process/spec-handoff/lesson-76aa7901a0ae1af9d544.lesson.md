# 页面入口与对接点只从该页布局和页面类的实际绑定推导：共享 ViewModel 里未被调用的方法和仅 import 的 SDK 不构成入口，巡检与修复不据此补出源端没有的控件

ID：`lesson-76aa7901a0ae1af9d544` · 版本：1

[本主题](index.md)

## 何时使用

规格对接点提取、UI 巡检判定与巡检修复阶段，决定某个页面是否需要渲染某类操作入口（登录、账户、支付等）时

## 适用情境

源页面的布局与 initView、点击监听只绑定部分控件；同一页面使用的共享 ViewModel 里还有其他功能方法（如一键登录、微信登录）但页面不调用，相关 SDK 类与事件只出现在 import；目标规格或计划把这些方法列为该页对接点，生成的页面里留有没有 UI 调用点的处理函数；巡检据对接点或验收条目把它判为“入口未渲染”，修复单写“按源端可达入口补 UI”。

## 原因

共享 ViewModel 的方法和 import 只说明代码可达，不说明该页有入口。把它们写成页面对接点后，下游会把没有调用点的处理函数当成缺失 UI，修复者不查源端控件就补出源端没有的按钮和文案，界面反而偏离。来源中规格作者已读到页面布局与页面类全文（没有登录控件），仍把共享 ViewModel 的登录方法写成该页登录入口；巡检据计划对接点把无调用点的处理器判为缺陷，修复者没有打开源布局就新增了登录按钮行。

## 做法

1. 规格提取写页面对接点时，只列该页布局控件与页面类实际绑定的点击和调用；共享 ViewModel 中该页不调用的方法、只出现在 import 的 SDK 与事件类不写成该页入口，可注明“源端该页无此入口”，入口所在的其他页面另行记录。
2. 巡检发现页面里有没有调用点的处理函数时，先回查源页面的点击监听、布局控件与规格的组件表、导航表；源端没有对应控件就按多余接线处理（删除或移出该页），不判为“入口未渲染”，也不把计划里的对接点清单当作 UI 要求。
3. 执行“按源端可达入口补 UI”一类修复前，先定位源端具体控件（布局 id、点击监听、所在页面）；该页找不到就回报条目不适用，不新增源端没有的按钮和文案资源。
