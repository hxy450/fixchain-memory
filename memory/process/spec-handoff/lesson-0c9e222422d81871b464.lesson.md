# 源码或布局引用的资源值（getColor/getDimension(R.x)、@dimen/@color）转成目标值时，按精确资源名在全部 res/values* 检索：近名资源不合并，限定词覆盖（values-land、values-w820dp/sw600dp 等）写成分支并在运行期按配置读取；目标没有对应限定词时跳过的是目录不是行为，被覆盖的键登记为运行时断点需求

ID：`lesson-0c9e222422d81871b464` · 版本：2

[本主题](index.md)

## 何时使用

规格提取阶段，把源码中经资源 ID 读取的颜色、整数、尺寸、布尔值写进验收条目与精确取值表时；资源迁移阶段处理 values-w<N>dp、values-sw<N>dp、values-h<N>dp 等无法映射的限定目录时；实现阶段为引用 @dimen 的边距取值，或在规格字面量与运行期资源读取之间选择时

## 适用情境

源方法通过 getColor(R.color.X)、getResources().getInteger(R.integer.X) 等读取资源，或布局以 @dimen/X 引用；工程里有名称相近、用途不同的资源（如 yellow 与 square_yellow），或该资源在 values-land、values-w820dp 等限定词目录有覆盖值；目标页面支持横竖屏并在旋转后重算几何。也包括布局共用的 dimen（如 activity_horizontal_margin 10dp）在 values-w820dp 覆盖为 64dp，HarmonyOS 资源限定词没有可用宽度维度，资源转换规则要求整目录跳过并标 unmapped。

## 原因

只在报告里标 unmapped、写“由某任务处理”而不核对对方是否承接，被覆盖的值就没有承接方，各页只拿到基础值；按近名资源合并或只取 base 值，限定词条件下的取值同样丢失。

## 做法

1. 按精确资源名在全部 res/values*/ XML 中检索 name="X"（如 grep -rn 'name="X"' res/），把定义文件:行号与值写进验收和常量表；有限定词覆盖时写成“base 2 / land 1，运行期按当前配置读取”，并在验收中补一个限定词条件下的样例。
2. 同一工程有含相同词的多个资源时，色表按资源名逐行列出定义与消费点，不合并成一行；grep 结果被截断时确认目标条目已返回，否则按行号定点再读。
3. 实现时规格给字面量、而已迁移的同名资源键或 Base 契约里需要 context 的读取函数也存在时，先核对注释与资源值；不一致按源端资源实现并回报规格，旋转后重算几何的入口里做运行期读取。
4. 资源迁移跳过无法映射的尺寸限定目录前，逐键列出被覆盖的值（键名、基础值、覆盖值、阈值），在映射表与移交登记中写成“运行时断点”需求并指定承接方（共享窗口模型或具体任务）；写“由某任务处理”前先 grep 对方规格确认已有条目，没有就登记。
5. 界面实现引用 @dimen 时，查源 res 下全部 values-*/dimens.xml 是否覆盖同名键；有宽度覆盖就改用共享窗口模型按当前可用宽取值（窗口尺寸变化时重算），不用单值 $r；水平与垂直边距即使基础值相同也分开取。

来源支持：3 张卡 · 2 次迁移 · 2 个应用
