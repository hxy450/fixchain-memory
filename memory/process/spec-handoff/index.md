# process/spec-handoff

规格、已生成代码等二手输入与源码之间的交接：规格条目的写法（含增量对齐时点击入口的导航契约、页面入口与对接点只取该页实际绑定）、沿 helper/DAO/适配器委托链与继承的共享基类追到最终实现、按 feature 切分归属时的跨 feature 契约、上游产物缺值时如何收口、概括出错、照搬前核对与冲突回报（含对齐既有页面骨架），多模块同名布局的解析，源端并存新旧两套实现时的行为基准，AndroidManifest 中 application 与 activity 属性（含未声明时的缺省）写入规格，合成快照清单的可信度，生成期无法核验结论的置信标注，Application 初始化链注册的接收器与监听写入规格，从窗口与控件封装类提取按触发源或状态分叉的可见行为，平台差异决策只收敛确实做不到的那一步

## 本级经验

- [Activity 的 screenOrientation（含未声明）要写成鸿蒙方向配置，不只写“横竖屏双布局”](lesson-8fff0f8e2f5e200f51f1.lesson.md)
  - 时机：规格提取与工程配置阶段，为每个 Activity 确定窗口方向、在决策账本写“横竖屏”结论，或落 module.json5 的 abilities 配置时
  - 情境：源各 activity 未声明 android:screenOrientation（安卓缺省随传感器与系统自动旋转开关旋转），并提供 layout-land/values-land 等横屏资源；或某 activity 在 manifest 声明锁定方向（如 sensorLandscape），Java 源码只见全屏标志。目标 EntryAbility 来自工程模板，module.json5 的 abilities 没有 orientation，页面已按 mediaquery 或 onConfigurationUpdate 写了横竖两套布局。
  - 例外：源码运行时调用 setRequestedOrientation 覆盖 manifest：以代码设置为准
- [Android 工程的同名布局按页面类所属模块与 Binding 类解析，多源集按 variant 合并优先级取有效布局；发现一处误解析就复核全部](lesson-d75ddb53d6609b35d025.lesson.md)
  - 时机：规格提取阶段为 Activity/Fragment 确定源布局（layout_sources）并生成分页 UI 规格时；页面转换阶段按规格选定源布局时
  - 情境：Android 工程含多个模块，存在同名的 Activity/Fragment 类与同名布局文件（如 fragment_mine.xml、activity_main.xml）；源布局由脚本或清单按布局文件名匹配，分页规格再把它写成“源码布局”交给页面转换者。也包括同名布局分属不同 product flavor 或源集（main 与 cloud 等）的情形。
- [Application 初始化链注册的广播接收器与系统监听要读本体写进规格：锚点、触发条件、承接方法与目标 API](lesson-4fb1c103822a8fd30b2a.lesson.md)
  - 时机：规格提取阶段，把源端 Application 初始化链里注册的 BroadcastReceiver、系统回调与监听写入 feature 规格时；覆盖检查准备把被引用的文件归为平台胶水时；实现阶段逐项迁移初始化链时
  - 情境：Android 源在 Application 初始化链注册接收器（如监听 CONNECTIVITY_ACTION 的网络切换），接收器本体按前后状态判断后调用业务检测或上报，并传入专用触发来源常量；上游契约已点名该接收器，但它不在 feature 锚点内；目标需用 @ohos.net.connection 等监听等价实现。
- [上游清单、规格或指定数据源里取不到所需的具体值时，规格作者与写码者都沿指针回源码取值，不用计数、举例或自拟值收口](lesson-77ca67f164d77ec63cda.lesson.md)
  - 时机：规格提取阶段依赖 API 清单等上游产物写网络层、鉴权、服务地址等小节时；写码者开工、派工要求按源码确认字段、请求体或响应处理，而手头的规格、锚点或上游产物看似已给全，或规格指定的数据源里查不到具体值时
  - 情境：规格模板要求某小节取自上游工具的最终产物（如 api-inventory.json 的 auth_model、common.md），该产物没有落盘、只剩中间文件（如 raw_apis.json），或中间文件只给键名、header_write 标签与计数，没有 host、请求头、错误码等具体值。写码阶段则是规格只给接口签名与源码锚点，没写字段类型、请求体字段、凭证来源或码值；Kotlin 可以在一个 .kt 文件里定义多个类，kapt stub 按类拆分。
- [从源端窗口或控件封装类提取行为时，把按触发源或状态分叉的可见行为逐项写入契约：各动画分支时长、一次性引导、离线禁用与换图](lesson-5948050d3b6dc39239a4.lesson.md)
  - 时机：规格提取或 Android 行为分析阶段，从窗口类、控件封装类（浮层窗口、底栏 FootBar 一类）整理动画、手势与状态相关表现时
  - 情境：源端在同一类中为不同触发源定义独立动画与时长（自动入场、驻留、出场与手势收起各用一组），以偏好标记控制首次全屏引导（显示后写回标记），或由 setOffline、setEnabled 一类方法切换禁用、图标与文字颜色；契约容易只摘主时序和主流程。
- [共享组件挂到哪些页面，以源码里的实际挂载为准（含布局声明的 Fragment 与导航图）；模板示例和上游说法不是依据](lesson-34c8ac69ad849f8c24e1.lesson.md)
  - 时机：功能索引、规格提取与接线规划阶段，确定播放条等 Fragment 型共享组件挂载到哪些目标页面时；页面转换阶段收到要求建槽位的派工时
  - 情境：源端共享组件只被个别宿主挂载：宿主代码把 Fragment replace/add 进自己布局的容器 id，主布局没有对应容器；流水线模板示例、功能索引或派工里写着“主页(某组件)常驻”一类通用说法。
- [合成快照里空的点击或导航清单不能当作“无交互”：按源布局点击绑定与规格导航表实现，目标页未建就登记前向引用](lesson-3ea52b78643f49c13cd1.lesson.md)
  - 时机：页面转换阶段，把源布局的按钮点击落实为 onClick 与页面跳转（或前向引用占位）时；规格提取阶段生成页面快照的点击清单时
  - 情境：页面 UI 快照由布局合成（view_xml_synthesized=true），meta.json 的 clickable_elements、navigation_targets 为空或标注部分置信；Android 用 DataBinding android:onClick=“@{page::onClickXxx}”绑定点击，跳转写在 Fragment 方法里；页面规格的导航关系表列出代码触发的目标页，目标页可能尚未生成。
- [平台差异只收敛确实做不到的那一步：写“无对等”前查证并记录，替代方案只作用于源端同一路径，其余出口、分支与回退照源端保留](lesson-9c973e50aaea054facdc.lesson.md)
  - 时机：规格提取与计划决策阶段，为源端平台专有能力（系统派发入口、商店跳转、系统设置深链、跨应用拉起、设备能力探测、运行时开关、画中画等系统窗口能力、系统取色、后台执行与通知动作），或目标没有现成组件的视觉与交互效果，登记平台差异、skip 或“已批准不可用”时；实现阶段消费这类差异决策时
  - 情境：源端某条链路里只有个别步骤在目标平台确实做不到（如第三方不能运行时启停 skill、查询他包安装与运行状态），规格或台账却把整条入口判为“无对等”、把按钮出口改成说明文案、把不同探测结果合并成一个分支，或把替代开关接到源开关不影响的路径；计划汇总行把只批给少数能力的降级泛化到其他能力；实现者再把差异决策扩展到决策未列明的行为（如整段富文本链接都不实现）。“已查证”的说法可能没有对应的查询记录。也包括目标只是没有现成组件或同名 API、可用滚动回调或 Canvas/Path 等通用能力组合实现的效果，被写成“简化为固定形态”；源码自带版本门槛与“不支持时回退”分支的能力被整体删除；源端检测手段在目标没有同名对应，被判定的状态却可以观察；子代理回执标为“存疑”的推断，或上游 skip-list 里的一句“无 API”，被下游升级为定论或改写成“d.ts 无对应条款”的依据。
  - 例外：差异决策已完成平台查证、并由用户明确批准了更大范围的收敛（无人值守的自动批准不算）：按该决策执行
- [按 feature 切分规格归属时，源 ViewModel 的每一步都要有 feature 以数据流和验收认领；委托出去的步骤写成跨 feature 契约](lesson-431a65808f9b46b95974.lesson.md)
  - 时机：规格提取阶段，按目录或 feature 划分源码归属、把源端 ViewModel 的数据准备与列表组装写进各 feature 的数据流和对接点时
  - 情境：源端 ViewModel 在请求前或列表组装时有中间步骤（按本地 ID 查库补齐请求所需字段、把定位项插入列表首位并去重、恢复与回写选中项）；目标规格把 DAO 划给一个 feature、消费方 feature 只写“使用当前选择对象”，或双方都声明不认领某个容器 ViewModel；规格作者对部分类只读了函数签名。也包括源 Fragment 的设置项动作（清缓存、检查更新）或回前台刷新链被委托给其他 feature，而接收方规格没有对应验收项；以及 API 表列出的端点被注成“归某 feature 消费”，各方都不在服务接口中生产它。
- [沿用已生成页面、兄弟任务的写法或已有解析函数前，回到源码核对该片段的语义](lesson-e9c6e8ef1b29a6fe9c26.lesson.md)
  - 时机：页面转换、公共组件抽取、切片接线或页面重建阶段，参照已生成页面中的同名控件、弹窗、列表、顶栏或导航栈写法时；数据层为新增接口方法复用已有的解析、封装函数时；复用工程已有的共享状态 key 时；按“与 Android 1:1 对齐”修改已有页面（含基线遗留骨架）时；在已有按钮、工具栏或面板上按 Android 契约改写时；把已转换页面的逻辑下沉到服务或 ViewModel 时
  - 情境：后写的 worker 同时读到源码与先前 agent 已生成的目标代码片段（@Builder 控件、输入弹窗、弹窗承载方式、列表键函数、顶栏折叠、图标控件行、全屏遮罩、onReady 取栈写法、共享状态 key、登录结果解析函数等），准备当作项目约定直接沿用；或以仓内同族页面为模板复刻输入行，或用 replace_all、多控件模板批量改写。也包括后一批执行代理把同批尚未验收的兄弟页当作模板；在与源端结构不同的既有页面、已有按钮与面板上做 1:1 对齐，只换图标、文字或颜色；先例里夹带登记为不确定、近似或“需真机校对”的取值，旧注释写着“源码未设，保真”；以及服务或 VM 抽取时把页面里已写的近似原样搬进服务，并在注释里写成“等价 Android”。
  - 例外：用共享组件替换页面已实现片段：按替换前比对共享组件的经验处理；共享件尚未就绪时的页内副本按待收敛项登记
- [源端并存新旧两套实现时，以当前构建启用或目标页对应的实现为行为基准](lesson-2e8ffecce25935dda502.lesson.md)
  - 时机：规格提取与实现阶段，同一能力在源码中有新旧两套实现（构建开关二选一，或新旧页面并存），需要确定行为断言与时序规则时
  - 情境：源码以 buildConfigField、manifestPlaceholders 等开关在两套实现间择一，或旧版与新版页面并存且各有生命周期与竞态规则；两者在若干路径上行为不同，目标只建一套。
- [源端行为经 helper、DAO、适配器、子组件或基类层层委托时，追到最终实现再写规格与代码，不以调用点推断](lesson-4606ccc434e247d4a240.lesson.md)
  - 时机：规格提取与页面、数据层实现阶段，源端调用点只是一行委托（Activity 调 DialogHelper.showXxx、Repository 经 DAO 调 Helper、Fragment 的分页适配器再建 item 适配器、Compose 页面把整块列表或交互交给子 Composable 或共享组件、条目经公共构建器注册、页面类继承共享基类）时
  - 情境：源端真正的布局、点击时序、数据来源、选中样式或空列表分支写在被委托的方法、类或子组件里：调用点只剩 DialogHelper.showXxxDialog(ctx) { 回调 }、repository.query → dao → Helper、分页适配器 → item 适配器，或带参数的子 Composable 调用（其 LazyColumn 按分区渲染、列表为空时显示内联空态）；规格按页面切分，锚点只列到调用方。也包括 Compose 页面调用项目自定义组件或共享弹层，形状、选中切换、数量步进与按钮可用条件写在组件定义里；源端条目经公共构建器注册，构建器为每个条目附加说明链接、图标或回调；页面 Adapter/Fragment 继承共享基类，基类用代码创建 UI（startActionMode 的标题、关闭键、溢出菜单）并登记返回键回调；或规格锚点列出 EmptyViewHandler 一类辅助类，挂载规则写在其中。
  - 例外：委托对象只是谓词、getter、格式化器或带默认参数的工具函数：按读到定义再翻译语义的经验处理
- [生成期结论依赖平台默认值、未检出源码或设备度量时，先查本机 SDK、依赖 res 与子模块源；查不到的推断不写成验收判据或 HARD 决策](lesson-c0f990ea57a901951ba8.lesson.md)
  - 时机：规格提取阶段，在没有真机布局 dump、生成期又不能编译或上设备时，写带具体 dp 的视觉验收判据、决策台账条目或 HARD 映射决策时；结论依赖平台默认值、未检出的子模块或外部库源码时
  - 情境：基线快照由源码合成、bounds 为空，或 SDK 文档对关键语义只有模糊措辞、参考检索为空；规格准备写入源码字面尺寸、“近乎不可见、按源码保留”类结论，或把依赖未验证语义的映射定为 HARD，把可靠方案降为“真机偏色再回退”。也包括结论依赖 ?android:attr、@android:color、Widget 默认样式等平台值，或依赖未检出 git 子模块（.gitmodules 有 URL、目录为空）、外部库里的实现，规格准备凭记忆取值或“按读侧/调用点反推”并标推断置信。
  - 例外：已有真机 dump 或截图测量给出实测值
- [经资源 ID 或 @dimen/@color 取值时按精确名检索全部 res/values*，限定词覆盖写成按配置取值的分支并指定承接方](lesson-0c9e222422d81871b464.lesson.md)
  - 时机：规格提取阶段，把源码中经资源 ID 读取的颜色、整数、尺寸、布尔值写进验收条目与精确取值表时；资源迁移阶段处理 values-w&lt;N&gt;dp、values-sw&lt;N&gt;dp、values-h&lt;N&gt;dp 等无法映射的限定目录时；实现阶段为引用 @dimen 的边距取值，或在规格字面量与运行期资源读取之间选择时
  - 情境：源方法通过 getColor(R.color.X)、getResources().getInteger(R.integer.X) 等读取资源，或布局以 @dimen/X 引用；工程里有名称相近、用途不同的资源，或该资源在 values-land、values-w&lt;N&gt;dp、values-sw&lt;N&gt;dp 等限定词目录有覆盖值（基础值与覆盖值从源 res/values*/ 下的 XML 读取）；目标页面支持横竖屏并在旋转后重算几何。也包括 HarmonyOS 资源限定词没有可用宽度维度，资源转换规则要求整目录跳过并标 unmapped。
  - 例外：源端横屏变体是 layout-land 等整份布局：布局变体的运行期分支按布局经验处理，本条管 values* 中的值覆盖
- [规格或派工与写前读到的源码、主题或映射参考冲突或遗漏时，按源端可观察行为实现并回报规格分歧；只有决策台账中带决策 ID 的取舍才例外，source-notes 登记与转述不算批准](lesson-7a065e8fe384b8c462cc.lesson.md)
  - 时机：页面或数据层实现阶段，规格或派工给出的容器、样式、类型写法、槽位或验收条目与写前读到的源码、主题或映射参考不一致，或验收条目没有列出源码里可见的行为时；重构或模块迁移阶段，规格清单要求改变已与源端一致的现有行为时
  - 情境：实现者同时读到规格或派工与源布局、源码、主题文件、映射参考或 SDK 声明，规格的具体写法（含验收条目里的列表范围、过滤条件、容器类型、要求新建的槽位、所引源布局、列举顺序、启动去向）与源端可观察行为或参考映射不符，或验收条目漏掉了源码对展示内容的加工；规格对该处只有概括性理由或没有提及。也包括规格的 gap 条目写着“源端是 X、规格要求 Y、按规格实现”，而现有目标实现已与源端一致。派工声明“规格为权威”、规格条款（取值、方向、数量等）与源码运行语义矛盾而已有实现恰好符合源码时同样适用。也包括巡检或修复单的修法与决策台账总则（如核心流程必须真实可用）、工程硬性条款或源端行为冲突，修复者写前同时读到了双方。 也包括上游审计或规格写入了源码没有的防护属性（如“有界去重队列”），或摘要漏写源码里的分支（手势专用的动画时长、一次性引导），而实现者写前手里同时有源码。
  - 例外：决策台账中有带决策 ID（如 D-、PD-）的条目明确声明与源端不同的取舍（验收条目带决策锚点或 decision_ref），此时按该决策实现，并在报告里写明与源码的差异；规格或派工里的转述值、锚点仍指向源码而 decision_ref 为空的条目不算决策
