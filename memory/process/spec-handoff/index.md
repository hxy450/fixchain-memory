# process/spec-handoff

规格、已生成代码等二手输入与源码之间的交接：规格条目的写法（含增量对齐时点击入口的导航契约、页面入口与对接点只取该页实际绑定）、沿 helper/DAO/适配器委托链追到最终实现、按 feature 切分归属时的跨 feature 契约、上游产物缺值时如何收口、概括出错、照搬前核对与冲突回报（含对齐既有页面骨架），多模块同名布局的解析，合成快照清单的可信度，生成期无法核验结论的置信标注，Application 初始化链注册的接收器与监听写入规格

[上一级](../index.md)

## 本级经验

- [Application 初始化链注册的广播接收器与系统监听要读本体写进规格：锚点、触发条件、承接方法与目标 API](lesson-4fb1c103822a8fd30b2a.lesson.md)
  - 时机：规格提取阶段，把源端 Application 初始化链里注册的 BroadcastReceiver、系统回调与监听写入 feature 规格时；覆盖检查准备把被引用的文件归为平台胶水时；实现阶段逐项迁移初始化链时
  - 情境：Android 源在 Application 初始化链注册接收器（如监听 CONNECTIVITY_ACTION 的网络切换），接收器本体按前后状态判断后调用业务检测或上报，并传入专用触发来源常量；上游契约已点名该接收器，但它不在 feature 锚点内；目标需用 @ohos.net.connection 等监听等价实现。
- [共享组件挂到哪些页面，以源码里的宿主容器与 replace/add 调用为准；模板示例和上游说法不是依据](lesson-34c8ac69ad849f8c24e1.lesson.md)
  - 时机：功能索引、规格提取与接线规划阶段，确定播放条等 Fragment 型共享组件挂载到哪些目标页面时；页面转换阶段收到要求建槽位的派工时
  - 情境：源端共享组件只被个别 Activity 布局的容器 replace/add 挂载；流水线模板示例、功能索引或派工里写着“主页(某组件)常驻”一类通用说法。
- [合成快照里空的点击或导航清单不能当作“无交互”：按源布局点击绑定与规格导航表实现，目标页未建就登记前向引用](lesson-3ea52b78643f49c13cd1.lesson.md)
  - 时机：页面转换阶段，把源布局的按钮点击落实为 onClick 与页面跳转（或前向引用占位）时；规格提取阶段生成页面快照的点击清单时
  - 情境：页面 UI 快照由布局合成（view_xml_synthesized=true），meta.json 的 clickable_elements、navigation_targets 为空或标注部分置信；Android 用 DataBinding android:onClick=“@{page::onClickXxx}”绑定点击，跳转写在 Fragment 方法里；页面规格的导航关系表列出代码触发的目标页，目标页可能尚未生成。
- [增量对齐时，源码已给出目标的点击入口写成具体导航契约；没有后续兑现方时不以 forward-ref 收尾](lesson-7f6b818559cfac767e4b.lesson.md)
  - 时机：规格提取与计划阶段，为页面对齐需求确定横幅、宫格图片等可点击入口的导航契约，以及目标页尚不存在时的处理方式时
  - 情境：Android 入口点击后打开固定 URL 的 WebView，或带本地资源参数的详情页；目标工程尚无对应页面；需求以“布局与 Android 对齐”为主，流程允许用 pending/forward-ref 登记暂缺目标，但本轮之后没有安排实现这些目标页的切片。
  - 例外：所在流水线有明确的后续切片负责创建目标页并兑现前向引用，此时按前向引用登记规则处理
- [多模块 Android 工程的同名布局按页面类所属模块与 Binding 类解析；发现一处误解析就复核全部同名布局](lesson-d75ddb53d6609b35d025.lesson.md)
  - 时机：规格提取阶段为 Activity/Fragment 确定源布局（layout_sources）并生成分页 UI 规格时；页面转换阶段按规格选定源布局时
  - 情境：Android 工程含多个模块，存在同名的 Activity/Fragment 类与同名布局文件（如 fragment_mine.xml、activity_main.xml）；源布局由脚本或清单按布局文件名匹配，分页规格再把它写成“源码布局”交给页面转换者。也包括同名布局分属不同 product flavor 或源集（main 与 cloud 等）的情形。
- [按 feature 切分规格归属时，源 ViewModel 的每一步都要有 feature 以数据流和验收认领；委托出去的步骤写成跨 feature 契约](lesson-431a65808f9b46b95974.lesson.md)
  - 时机：规格提取阶段，按目录或 feature 划分源码归属、把源端 ViewModel 的数据准备与列表组装写进各 feature 的数据流和对接点时
  - 情境：源端 ViewModel 在请求前或列表组装时有中间步骤（按 areaId 查本地库补齐经纬度、把定位城市插入列表首位并去重、恢复与回写选中项）；目标规格把 DAO 划给城市 feature、天气 feature 只写“消费当前城市选择”，或双方都声明不认领某个容器 ViewModel；规格作者对部分类只读了函数签名。也包括源 Fragment 的设置项动作（清缓存、检查更新）或回前台刷新链被委托给其他 feature，而接收方规格没有对应验收项；以及 API 表列出的端点被注成“归某 feature 消费”，各方都不在服务接口中生产它。
- [沿用已生成页面、兄弟任务的写法或已有解析函数前，回到源码核对该片段的语义](lesson-e9c6e8ef1b29a6fe9c26.lesson.md)
  - 时机：页面转换、公共组件抽取、切片接线或页面重建阶段，参照已生成页面中的同名控件、弹窗、列表、顶栏或导航栈写法时；数据层为新增接口方法复用已有的解析、封装函数时；复用工程已有的共享状态 key 时；按“与 Android 1:1 对齐”修改已有页面（含基线遗留骨架）时
  - 情境：后写的 worker 同时读到源码与先前 agent 已生成的目标代码片段（@Builder 控件、输入弹窗、弹窗承载方式、列表键函数、顶栏折叠、图标控件行、安全控件样式、全屏遮罩、onReady 取栈写法、共享状态 key、登录结果解析函数等），准备当作项目约定直接沿用。或对齐任务在一个与源端结构不同的既有页面上进行，写者已读到源布局 XML。 也包括后一批执行代理把同批尚未验收的兄弟页（如只回显接口 JSON 的页面）当作模板，照同一模式写出更多页面。也包括 1:1 返修重写已有片段时，沿用目标端已有的尺寸、颜色、限制属性（如三框统一的 maxLength、硬编码字色）或注释里的结论（“源码未设，保真”“已裁定”），以及以仓内同族页面为模板复刻输入行时照搬其图标尺寸与光标色。
- [源端行为经 helper、DAO、适配器或子组件层层委托时，追到最终实现再写规格与代码，不以调用点推断](lesson-4606ccc434e247d4a240.lesson.md)
  - 时机：规格提取与页面、数据层实现阶段，源端调用点只是一行委托（Activity 调 DialogHelper.showXxx、Repository 经 DAO 调 Helper、Fragment 的分页适配器再建 item 适配器、Compose 页面把整块列表交给另一文件的子 Composable）时
  - 情境：源端真正的布局、点击时序、数据来源、选中样式或空列表分支写在被委托的方法、类或子组件里：调用点只剩 DialogHelper.showXxxDialog(ctx) { 回调 }、repository.queryByDay → dao → DateHelper、CalendarViewPageAdapter(R.layout.item) → CalendarAdapter，或 DeviceList(...) 一类带参数的子 Composable 调用（其 LazyColumn 按分区渲染，列表为空时显示内联空态）；规格按页面类或所有权切分，锚点只列到调用方。也包括 Compose 页面调用项目自定义组件（如图片组件 XxxImage(...)），形状、裁剪与填充方式写在组件定义里，调用点只给尺寸。 也包括 Compose 页面把规格选择等交互交给共享弹层组件，选中切换、数量步进与按钮可用条件写在组件定义里。
- [生成期无法核验的规格结论标明置信度与核验方法，不定为硬性决策或带具体 dp 的视觉判据](lesson-c0f990ea57a901951ba8.lesson.md)
  - 时机：规格提取阶段，在没有真机布局 dump、生成期又不能编译或上设备时，写带具体 dp 的视觉验收判据、决策台账条目或 HARD 映射决策时
  - 情境：基线快照由源码合成、bounds 为空，或 SDK 文档对关键语义只有模糊措辞、参考检索为空；规格准备写入源码字面尺寸、“近乎不可见、按源码保留”类结论，或把依赖未验证语义的映射定为 HARD，把可靠方案降为“真机偏色再回退”。
  - 例外：已有真机 dump、截图测量或等价单测给出实测值
- [规格或派工写法与写前读到的源码、主题或映射参考冲突或遗漏时，按源端语义实现并标注差异](lesson-7a065e8fe384b8c462cc.lesson.md)
  - 时机：页面或数据层实现阶段，规格或派工给出的容器、样式、类型写法、槽位或验收条目与写前读到的源码、主题或映射参考不一致，或验收条目没有列出源码里可见的行为时；重构或模块迁移阶段，规格清单要求改变已与源端一致的现有行为时
  - 情境：实现者同时读到规格或派工与源布局、源码、主题文件、映射参考或 SDK 声明，规格的具体写法（含验收条目里的列表范围、过滤条件、容器类型、要求新建的槽位、所引源布局、列举顺序、启动去向）与源端可观察行为或参考映射不符，或验收条目漏掉了源码对展示内容的加工；规格对该处只有概括性理由或没有提及。也包括规格的 gap 条目写着“源端是 X、规格要求 Y、按规格实现”，而现有目标实现已与源端一致。派工声明“规格为权威”、规格条款（取值、方向、数量等）与源码运行语义矛盾而已有实现恰好符合源码时同样适用。也包括巡检或修复单的修法与决策台账总则（如核心流程必须真实可用）、工程硬性条款或源端行为冲突，修复者写前同时读到了双方。
  - 例外：规格或决策记录（如 decision ledger）对该差异写明了有意取舍（例如只在成功后写缓存、先授权再定位），此时按该决策实现，并在报告里写明与源码的差异
- [规格提取写验收条目时实读所引源码段落，照抄比较符、范围与名称变换，条目范围不超出本行源锚点，并给出边界样例](lesson-08854573a81a9fa03746.lesson.md)
  - 时机：规格提取阶段写阈值、列表范围、过滤条件、复制/变换类或持久化类验收条目并标注源码出处时
  - 情境：规格作者依赖预生成参考文档或源码片段写验收条目，并以“源码文件:行号”标注出处；读取可能被截断，或只读了参考文档的目录。也包括源端对同类数据维护多组独立集合（如按页面分别写入的两组收藏），规格按页面拆成多个功能分别写条目。
- [规格提取时为每个导航目的地写页面入参契约：参数名、类型、是否可空或默认值与源端读取方式，不只留深链占位](lesson-f4d335605b44a60116b9.lesson.md)
  - 时机：规格提取阶段写导航图与分页页面规格时
  - 情境：源端 nav_graph 为目的地声明 &lt;argument&gt;（必填 id 等）并带 deep link 占位，Fragment 用 requireArguments().getString(ARG_X)、SafeArgs 等读取；规格模板的导航图只列目的地、起始页与深链。
- [规格需要的值在上游清单或数据源里取不到时，回源码补全或标“待核”，不用端点计数、枚举举例或自拟值收口](lesson-77ca67f164d77ec63cda.lesson.md)
  - 时机：规格提取阶段，依赖 API 清单等上游产物写网络层、鉴权、服务地址等小节时；上游产物缺失、结果被截断，或所指数据源里没有所需值时
  - 情境：规格模板要求某小节取自上游工具的最终产物（如 api-inventory.json 的 auth_model、common.md），该产物没有落盘，只剩中间文件（如 raw_apis.json）；中间文件只给出键名、标签或计数，没有 host、请求头、错误码等具体值。 也包括 skill 要求先跑 API 清单提取，子代理派发失败后清单从未运行，后续计划的网络层只有一句概述，下游据此自拟基址与路径。
- [页面入口与对接点只从该页布局和页面类的实际绑定推导：共享 ViewModel 里未被调用的方法和仅 import 的 SDK 不构成入口，巡检与修复不据此补出源端没有的控件](lesson-76aa7901a0ae1af9d544.lesson.md)
  - 时机：规格对接点提取、UI 巡检判定与巡检修复阶段，决定某个页面是否需要渲染某类操作入口（登录、账户、支付等）时
  - 情境：源页面的布局与 initView、点击监听只绑定部分控件；同一页面使用的共享 ViewModel 里还有其他功能方法（如一键登录、微信登录）但页面不调用，相关 SDK 类与事件只出现在 import；目标规格或计划把这些方法列为该页对接点，生成的页面里留有没有 UI 调用点的处理函数；巡检据对接点或验收条目把它判为“入口未渲染”，修复单写“按源端可达入口补 UI”。
