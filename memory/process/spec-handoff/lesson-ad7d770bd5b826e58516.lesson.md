# 页面→feature 归属按页面实际调用的接口与功能判定，不用“所在模块默认归某 feature”的规则闭合；数据前向引用指向的切片要有能提供该数据的服务

ID：`lesson-ad7d770bd5b826e58516` · 版本：1

[本主题](index.md)

## 何时使用

规格提取阶段为全部 page_id 分配所属 feature 时；计划阶段生成切片、页面转换登记数据前向引用（resolve_by）时

## 适用情境

Android 页面位于公共 base 一类模块，同包内却有自己的 Retrofit Service（如分类、列表接口）；归属脚本按模块名把它默认落到某个平台类 feature，而接收 feature 的规格服务层没有对应接口；流水线先做纯 UI 转换，把数据接线按 page→feature→slice 延后。

## 原因

默认桶能让“所有页面都有归属”的检查闭合，却把页面交给不提供其数据的 feature；切片的数据层范围里没有该接口，UI-only 转换登记的前向引用指向一个无人实现的数据提供方，页面一直停在失败桩。

## 做法

1. 分配归属时逐页核对页面源码包内的 Service 调用（接口清单的 callers），确认接收 feature 的服务层已列出这些接口；没有就改归拥有该接口的 feature，或在接收 feature 规格补上数据契约。
2. 归属脚本跑完后抽查每个 feature 新增的页面是否落在其已写明的范围内，越界的作为归属缺口处理，不以页面全部有归属视为通过。
3. 生成切片或登记数据前向引用时，确认 resolve_by 指向的切片在数据层范围里有提供方；没有就报计划缺口，不只写一个 Store 名。
