# 只有查不到权威来源的生成期结论才标置信度与核验方法：平台或库默认值先查本机 SDK 与依赖 res，缺失的源码（未检出子模块、外部库）先按 .gitmodules 或依赖坐标取源；推断不写成字段级验收、硬性决策或带具体 dp 的视觉判据

ID：`lesson-c0f990ea57a901951ba8` · 版本：3

[本主题](index.md)

## 何时使用

规格提取阶段，在没有真机布局 dump、生成期又不能编译或上设备时，写带具体 dp 的视觉验收判据、决策台账条目或 HARD 映射决策时；结论依赖平台默认值、未检出的子模块或外部库源码时；实现阶段源符号定义（实体基类、工具类）不在源码树、只在二进制依赖中时

## 适用情境

基线快照由源码合成、bounds 为空，或 SDK 文档对关键语义只有模糊措辞、参考检索为空；规格准备写入源码字面尺寸、“近乎不可见、按源码保留”类结论，或把依赖未验证语义的映射定为 HARD，把可靠方案降为“真机偏色再回退”。也包括结论依赖 ?android:attr、@android:color、Widget 默认样式等平台值，或依赖未检出 git 子模块（.gitmodules 有 URL、目录为空）、外部库里的实现，规格准备凭记忆取值或“按读侧/调用点反推”并标推断置信。 也包括实体继承二进制依赖中的基类（equals/isChanged/toString/序列化与字段缺省值都在基类里），写者只记“主仓无源码”，或按验收条文、调用点反推字段集并标“风险低”。

## 例外与边界

- 已有真机 dump、截图测量或等价单测给出实测值

## 原因

合成快照只有声明树、没有度量，模糊的 SDK 措辞也推不出具体行为；推断一旦写成判据或 HARD 决策，实现者会原样复刻，验收也当已知设计。回退条件要求真机比对时，生成期根本不会触发。“标待核”还会被用来保留凭记忆的数值，而平台默认值在本机 SDK 可查；推断标签也挡不住下游照做：按读侧反推的备份格式会被写成逐字段相等的验收，实现照此产出与源端不兼容的数据，而子模块源码当场可取。

## 做法

1. 写结论前先找权威来源：平台默认值查本机 Android SDK platforms/android-*/data/res（themes、styles、colors、dimens、layout），依赖库默认值查 aar 的 res；源码缺失时按 .gitmodules URL（如 git submodule update --init）或依赖坐标取源核对；二进制依赖先在本机 Gradle 缓存（~/.gradle/caches/modules-2/files-2.1/<group>/<artifact>/）找 jar 或 sources jar，用 javap -p -c 或反编译核对字段集、缺省值与 equals/toString/序列化。实现阶段同样如此，取不到就登记决策缺口并在实现处留前向引用，不按验收条文反推。查得到就写实值并注明文件；只有设备度量这类生成期确实拿不到的才按以下各步处理。思考中带“我记得/也可能是”的数不以“AOSP 默认值”名义写入资源或报告。
2. 带具体 dp 的视觉验收条目标出置信度，注明依据是源码字面，并要求验证阶段用真机 dump 或截图量值取代。
3. “颜色近乎不可见”“保留源端缺陷”类结论先分辨成因是颜色还是布局度量，写成待真机核对项，不进决策台账当已知缺陷。
4. 映射依赖的语义在 SDK 与参考中都没有明确说明时不定 HARD，写明核验方法；已有不依赖该语义的等价方案（包括源码作者留下的实现提示）时，把它设为主方案，依赖未验证语义的方案设为回退。
5. 取不到的数据格式、协议或字段结构登记为阻塞缺口并写明核验方式（取源比对或真机导出比对），不写成字段级相等的验收，不让下游据推断实现。
