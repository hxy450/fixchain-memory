# 执行已批准计划的批次与全量收口时，把替换清单逐行转成本批检查项；横切项与当前批次同等对待，公共门面先建立再搬页面

ID：`lesson-af15c43279110b3b7692` · 版本：1

[本主题](index.md)

## 何时使用

迁移执行与全量收口阶段，按已批准计划迁移页面、下沉公共工具或执行替换清单时；规划阶段为公共能力安排批次时

## 适用情境

计划或审计已要求用统一门面（如 ToastService）替换散落的直调，并在业务完成时把直调数量归零；当前批次正在移动页面、导出公共工具或做 LazyForEach → Repeat 等静态收口，门面本身还不存在。

## 原因

批次只执行与当前主题相关的清单行时，横切行会一直“留给以后”，页面被原样搬走，直调与页面私有实现跟着扩散。来源中计划写明统一吐司门面与直调归零并获批准，执行会话读到了审计与替换清单，只做了列表改写和工具下沉，门面从未建立；根会话重读该段后还新增了两处页面私有吐司，收口报告也没有统计直调数量。

## 做法

1. 开工前把计划替换清单逐行转成本批检查项；收尾时用 rg 统计各横切项的旧写法（如 promptAction.showToast、DialogHelper.showToast、页面私有提示状态），结果为 0 或逐项登记豁免后再宣称收口通过。
2. 门面尚不存在时，先在最底层公共模块建立薄封装并从包入口导出，再移动或改写页面；移动页面时顺带把页面内实现改为调用门面。
3. 规划阶段把公共能力的建立落到具体批次与产物路径，并给出调用归零的验收命令。
