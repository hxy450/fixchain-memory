# 收尾者处理结构检查报出的缺失服务或未实例化符号时，先读该符号的规格 AC 与源码锚点按契约实现或退回切片，不按调用点补空壳

ID：`lesson-9f4bb32cf5b3cc9dc7d5` · 版本：1

[本主题](index.md)

## 何时使用

组收尾或结构收口阶段，检查器报切片自有服务缺失、某符号未被实例化，收尾者准备就地补齐时

## 适用情境

切片文件的实现范围列出某服务符号（如链接启动器、依赖容器），功能规格用 AC 规定其返回值、守卫、失败提示与异常分类；切片没有创建它，收尾者只从调用点（如 X.open(url)）得知它的名字。

## 原因

按调用点名补出的 void 方法与静默 catch 能通过结构检查，却丢掉规格规定的返回值、守卫、提示与异常分类；注释再声称与源码一致，后续接线者会在空壳上继续扩展，偏差要到验证期才暴露。

## 做法

1. 补齐前读该符号在功能规格里的 AC 与源码锚点，按契约实现返回值、守卫、失败提示与异常分类；读不到或超出收尾范围就退回切片或登记移交项，不写 void、静默 catch 的空壳，也不在注释里声称与源码一致。
