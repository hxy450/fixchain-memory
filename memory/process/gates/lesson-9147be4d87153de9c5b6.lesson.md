# 报告功能已实现或已对齐前，按规格验收项与导航出口在代码里找到实际组件与调用：空回调、只含注释的回调与模板空壳页不算实现

ID：`lesson-9147be4d87153de9c5b6` · 版本：9

[本主题](index.md)

## 何时使用

验证阶段核对功能完成度，或实现、返修后向用户报告“已实现/已对齐”时；执行阶段宣告页面转换或流水线阶段完成时

## 适用情境

验证检查只 grep TODO: 与占位登记表；实现或修复后按功能点列对齐表并逐项打 ✅；规格写有验收条目、页面导航出口、事件订阅锚点与启动触发条件。也包括执行者用同一模板批量写出只有标题或“内容开发中”的页面、用写死的样例数据顶替接口、把接口响应 JSON.stringify 后整段显示，再以文件齐全、页数相等和编译通过判定完成。

## 例外与边界

- 源端同处本身就是空点击、写死数据或把响应整段显示成文本，且当前验收以源端行为为准：按源保留，不判为未完成

## 原因

文本检索只能发现写了标记的占位，发现不了缺失的处理函数、只写注释的回调、没有调用者的函数、定义了却没有消费点的常量或模板空壳页；对齐表按意图打勾、以占位清零或文件与页数判定完成时，未实现项就以“已完成”交付，直到用户操作才暴露。

## 做法

1. 报告前按规格验收项逐条在当前代码中找到落点：组件（如 Checkbox）、ViewModel 方法、router/NavPathStack 调用、启动路径上的函数调用者；找不到就标未完成。
2. 验证阶段除检索 TODO 外，扫描空回调与回调体只有注释的 onClick，并把页面规格的导航出口与代码中的跳转调用逐项对账（从源端副作用处理函数反查导航出口的写法见 lesson-32af50a1dfb0c1c254af）。
3. 替换占位或宣布 AC 完成前，以 UI 壳已声明的展示字段和规格中带事件订阅锚点（onEventMainThread、@Subscribe）的 AC 为清单，逐项找到赋值、接口调用与订阅的代码位置；规格要求的每个接口都要有页面调用，占位清零不等于 AC 覆盖，暂缺的来源登记为缺口。
4. P0 功能的 AC 目标符号（如深链处理函数、module.json5 的 uris）检索命中 0、决策账本也没有对应 skip 时，按缺口处理，不以 MVP 或范围决策的名义登记为范围外。
5. 页面完成判定除 TODO 外检索占位特征：只有标题或返回栏的页面、写死的样例数据（如固定分类、假商品卡片）、把接口响应 JSON.stringify 后直接显示。命中只是线索：先对照源端同处实现，源端同样如此就按源保留，否则按未完成登记缺口，不计入完成数；文件存在、页数相等与编译通过都不能区分占位与已转换页面。
