# 修复安全区等按关键字判定的结构检查 FAIL 时逐页落实避让，不用含检查关键字的注释让检查通过

ID：`lesson-f6b95d7d6d0159cb0436` · 版本：4

[本主题](index.md)

## 何时使用

结构修复阶段处理安全区 Layer 3 等按关键字或 grep 判定的检查失败时

## 适用情境

结构检查按关键字或 grep 判断页面是否处理了安全区等要求；工程已用 setWindowLayoutFullScreen 开启全屏、根 Navigation 设了 expandSafeArea，NavDestination 页需自行在前景避让；修复者面对多页 FAIL，工程有共享窗口模型（顶部/底部避让值），skill 要求全屏 NavDestination 页实际加 padding。

## 例外与边界

- 页面已由上层（父容器、NavDestination 根或共享组件）正确避让时，不再叠加 padding；在修复记录里写明避让落在哪个文件和组件，把这个 FAIL 作为检查器误报上报，而不是用注释或标记迎合检查

## 原因

检查器只看文本特征：含检查关键字的注释能让它通过，页面却没有订阅窗口模型、没有实际避让，检查结论与页面表现脱节。

## 做法

1. 对每个确实缺避让的 FAIL 页（NavDestination 页面）订阅共享窗口模型，在前景顶部/底部加对应避让值；源端另有间距时叠加（如源端搜索栏为状态栏高度加 margin，就写顶部避让值加该 margin，列表底部留底部避让值）。
2. 逐页实现，不添加只为匹配检查规则的注释或标记（如引用工程中并不存在的组件名的注释）。

## 可选检查

- 检查通过后抽查若干页面，确认存在真实的 padding 表达式而不是注释。
