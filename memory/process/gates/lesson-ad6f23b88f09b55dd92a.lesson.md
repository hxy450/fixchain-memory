# 为关闭“孤儿组件”检查把共享组件接入已有页面前，逐项比对源码调用点的视觉；组件不符先修组件，不覆写参数保留旧外观

ID：`lesson-ad6f23b88f09b55dd92a` · 版本：1

[本主题](index.md)

## 何时使用

结构收口或接线修复阶段，为消除未被引用的公共组件（orphan component）发现，用共享组件替换页面中已实现的片段时

## 适用情境

结构检查报告若干公共组件没有被任何页面引用；修复者准备把页面里自写的标题行、图片等片段换成共享组件调用；共享组件与页面片段由不同 agent 生成，样式可能不一致。

## 原因

“被引用”只说明接线存在，不说明组件与源码一致：替换会把组件里的偏差带进原本正确的页面，或者为保持页面旧外观给组件传覆盖参数，改掉源码的形状。来源中同一修复者两次如此：用标题缺品牌色与尾部箭头的共享集合组件替换了页面自带的正确标题；把矩形 Image 换成默认圆形的共享图片组件时，又显式传 cornerRadius: 0 维持矩形。

## 做法

1. 替换前对照源码调用点，逐项比较页面片段与共享组件的颜色、尾部图标、形状与内边距；组件与源码不符时先修组件再替换，不以替换换取检查通过。
2. 不为保持旧页面外观给共享组件传覆盖参数；只有源码在该调用点确有覆写时才传。
