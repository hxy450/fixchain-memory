# 运行会改写源码的自愈脚本后先审阅其改动；异常尺寸或与已有显式尺寸重复的追加要回滚

ID：`lesson-bdb97da6a6eb8d68435f` · 版本：1

[本主题](index.md)

## 何时使用

结构收口阶段运行含图标尺寸自愈等会改写 .ets 的检测管线、决定是否接受其结果时；构建或验证阶段读到同一组件出现两组尺寸修饰时

## 适用情境

迁移管线在收口时自动运行图标尺寸自愈（icon-sizing 一类），会直接给 .ets 中的 Image 追加 .width/.height；页面 Image 已在同一行链式写好尺寸（如 '18vp'、'100%'），资源可能是 jpg 启动图标。

## 原因

自愈脚本读错图片像素时（本例追加值恰为 65535÷3 等异常值的折算，具体解析缺陷未核实），会在已定尺寸后追加上万的宽高；ArkUI 后写生效，组件铺满屏幕，编译与检测计数都不报错。来源中收口者只看 findings 计数和结果文件路径，没打开 icon 结果或 diff 就继续推进；之后构建代理读到这两行也只改了相邻属性。

## 做法

1. 跑完会改写源码的自愈脚本后，先读其改动记录（结果 JSON）或 git diff，再看检测收敛结果；新增尺寸远超屏幕（上万 vp）或与同组件已有显式 width/height 重复时，回滚该处并上报。
2. 图标尺寸自愈只处理缺少尺寸的 Image；同一组件已有显式尺寸的跳过，读不出合法像素尺寸时不写入。
3. 构建或验证中读到同一组件出现两组 width/height 时，按后写生效核对最终尺寸，异常值当场删除或上报。
