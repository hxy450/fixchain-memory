# 源端分支条件或文案插值依赖的辅助谓词、getter，要读到定义再翻译，不按名字推断

ID：`lesson-b3f534eb740a768d95a6` · 版本：1

[本主题](index.md)

## 何时使用

业务逻辑与界面实现阶段，翻译以辅助谓词分派的切换方法（playPause/toggle），或转写把观察值插进文案模板的显示时；规格提取阶段写这类状态契约时

## 适用情境

源码以 isPlayingState() 一类谓词分派 pause/play，或把 text 前缀的 LiveData<String>（格式化结果）拼进文案；读到的源码片段只含调用或相邻 getter，没有定义；同一 ViewModel 另有同名的原始数值字段。

## 原因

凭名字推断谓词的覆盖范围，或把格式化文本映射成原始数值，编译都正常，运行时才出错（暂停后无法续播、定时文案变成裸秒数）。分段 sed、截断的 grep 常刚好漏掉定义行。来源两例中实现者都计划核对，却只读了片段就凭名字写。

## 做法

1. 翻译用到的每个谓词和 getter 都读到定义行；读不到时以规格状态转移表和验收用例为准，不凭名字推断（例如 isPlayingState 是否包含 PAUSED）。
2. 切换方法写完后按规格逐个当前状态核对：暂停态必须走 play，播放态才走 pause；不要把某个方法的前置守卫当作另一个方法的分派条件。
3. 转写 "${x}…" 拼接时先读 x 的定义：text 前缀的 String 通常是格式化结果，不能映射到同名原始数值；规格状态契约要为每个插值写明源 getter、类型与格式。
4. 复用已有格式化函数前，逐分支对照源格式化器（小时分支、封顶值、≤0 的处理）。
