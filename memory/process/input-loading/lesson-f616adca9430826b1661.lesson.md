# 上下文压缩后续跑迁移流水线：把压缩前的规格与源码视为未读，按切片的 spec_ref、页面规格与源码锚点重读后再写计划和代码

[本主题](index.md)

## 何时使用

计划与实现阶段，同一长会话经历上下文压缩后，为切片写 scope/验收/集成点，或写页面、ViewModel、数据层文件前

## 适用情境

迁移流水线在一个会话里先产出逐页 UI 规格、功能规格与切片计划，随后发生上下文压缩；压缩摘要只保留功能名、规格路径或一句概括，切片计划、feature-index 或执行 skill 仍以 spec_ref、页面规格路径和源码类名指向这些输入。

## 例外与边界

- 压缩后已按原文完整重读了该切片对应的规格与源码片段

## 原因

摘要里的路径和功能名不携带规格正文。写者凭功能名与通用印象输出，丢掉的正是规格里的具体值与条件。来源中同一会话压缩前已写出正确规格，压缩后计划与实现都没再打开：固定演示数据被自拟，“首次启动自动播种”在切片验收里退化为“正常重置”，首页的加载/失败/空态、选中行程联动与待办勾选、详情页入参都未实现，执行总结仍称已完成。另一应用中，实现者读完“请求前按 ID 查库补齐经纬度”的源方法后发生压缩，之后只回读了 DAO，写请求链时丢了这一步。

## 做法

1. 压缩后，把压缩前写出的规格、计划与读过的源码当作未加载输入：每个切片动笔前按其 spec_ref、页面规格路径和列出的源码锚点重读原文，读全后再写，不以摘要、feature-index 的一句话或自写的切片摘要代替。
2. 计划阶段写切片 scope、acceptance 与 integration_points 时，从功能规格完整带入业务规则与验收条目；触发时机（如首次启动、设置入口）、固定数据来源、页面入参与交互分别落成条目，不只保留功能名或“正常显示”一类概括。
3. 实现前把规格中的状态、控件与交互列成清单（状态字段与面板、选中/切换回调、列表过滤条件、导航出口与参数、启动调用点），逐项落到代码。
