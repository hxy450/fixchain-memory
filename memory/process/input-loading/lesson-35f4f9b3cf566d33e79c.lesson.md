# 依据另一文件的返回语义改写调用方前，重读该文件当前版本；编辑回执提示文件已变更或有并发会话时，不沿用旧读取

ID：`lesson-35f4f9b3cf566d33e79c` · 版本：1

[本主题](index.md)

## 何时使用

增量修复与实现阶段，依据另一文件（ViewModel、服务）回传数据的语义改写调用方（分页追加、合并、去重）时；顺带修复用户请求范围外的问题时

## 适用情境

调用方与提供方之间的返回语义（当页还是累计、是否已去重）是跨文件约定；同一工程可能有多个会话并发修改，写前读取与实际写入相隔数分钟，或编辑工具回执已提示该文件在上次读取后被改动。

## 原因

跨文件语义以提供方当前代码为准。沿用几分钟前的读取，会与另一会话刚做的语义修改叠加成新错误（两侧各修一次，分页追加变成空追加），编译照常通过，要等用户上拉才发现。

## 做法

1. 写入依赖提供方返回语义的代码前，重读提供方当前版本；编辑工具提示文件自上次读取后已变更时，先重读再决定 append、reset 或 slice。
2. 用户请求范围外发现的问题，先确认当前文件状态以及是否已被其他会话处理；确需修跨文件契约时只在提供方或调用方一侧统一语义，并在两侧注释写明数据是当页还是累计。
3. 写完分页追加逻辑，用两端当前代码推演第二页：提供方回传的长度与调用方的偏移组合后，确实有新增条目。
