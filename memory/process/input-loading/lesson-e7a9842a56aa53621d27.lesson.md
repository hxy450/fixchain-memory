# 推断参考端的默认选中或过滤结果前，读到绑定的默认值回调、过滤函数与回退条件；限制字段追到消费处，不用目标端白名单或注释反推

[本主题](index.md)

## 何时使用

功能对齐阶段，为共用基类的某类页面决定是否覆写默认选中项，或判断某个选项会不会被参考端过滤、默认值会不会回退时

## 适用情境

参考端多个页面共用同一默认值回调与选项构建函数，部分选项带 type 等限制字段；目标端基类提供可被子类覆写的默认值钩子，子类另有用途不同的类型白名单或注释。

## 原因

限制字段可能只驱动“不支持”提示，并不把选项移出列表；凭字段名或目标端已有白名单推断“被过滤→默认回退”，会写出与参考端相反的覆写，编译、运行都正常，只在默认值上与参考端不一致。

## 做法

1. 覆写默认值前，沿参考端链路读三处原文：该页面绑定的默认值回调、选项列表的过滤函数、默认项匹配失败时的回退逻辑，结论以这些函数为据。
2. 读到 type、k 等限制字段时追到它被消费的位置：只用于提示文案时，选项仍可被默认选中；确实在过滤函数里被剔除时才按回退处理。
3. 已得出的参考端结论被新读到的目标端代码动摇时，回参考端补读决定性函数再改；注释写“对齐 Android”时附对应源码位置。
