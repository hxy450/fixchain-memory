# 编排者亲自实现切片（子代理不可用、未按流程派发或与规格子代理并行）时，先加载切片 worker 本应拿到的全部输入，不凭占位登记表或摘要写代码

ID：`lesson-b90d7f55409a3a34253d` · 版本：3

[本主题](index.md)

## 何时使用

执行编排阶段，子代理额度耗尽、限流或失败后，或执行 skill 规定按页派发转换子代理而编排会话决定直接代写时，编排者自己完成 Base/切片实现、页面转换、接线或解决前向引用时；以及编排者一边并行派发规格子代理、一边自己写应用壳、服务与页面时

## 适用情境

编排会话原本只负责派工与收口，手上是占位登记表、feature-plan 的指针和子任务回报这类摘要；切片 worker 派工里列出的切片计划文件、功能规格验收条目、页面规格、决策账本正文和源码锚点，编排会话并没有打开过。也包括编排者并行派发功能与页面规格子代理、同时自己写代码，规格已落盘（列目录可见）或仍在生成，编排者只看了目录或完成通知。

## 原因

占位登记表和计划索引只是指针，状态机、反馈、平台能力选型、外链常量、页面状态与交互等行为细节都在切片计划、功能/页面规格和源码里。来源中同一个编排会话在子代理额度耗尽后接手 Stage 2/3：没打开平台切片计划和规格，就把已批准真实现的后台计时写成桩；没读计时切片计划、源码读取又被截断，就自拟了计时状态机；漏掉登记表和规格里都写了的步骤提示音与振动；外链只看到泛称就猜了网址；克隆回调没读源码就只按登记表一句话实现；深链只接了运行时解析。另一应用的执行 skill 要求按页派发转换子代理并读取页面与功能规格，主会话没有派发、也没打开这些规格就直接连写首页与 ViewModel，漏掉了规格写明的状态面板、选中联动与待办勾选。第三个应用中编排者在规格子代理写出页面与功能规格的同时自己写代码，只列了规格目录、按完成通知里的区块摘要实现：连接页漏了页面规格写明的蓝牙关闭恢复分支和设备列表空态，功能规格里的深链 AC 没有实现，页面标题没有采用规格中的逐字文案。它们读过的只有指针、目录和截断的批量输出。

## 做法

1. 接手前把该切片 worker（或页面转换子代理）派工里的输入逐项列出（切片计划文件、spec_refs 指向的验收条目、页面规格、决策账本相关条目正文、源码锚点行），逐份打开；按 worker 的必读材料对待，不因为自己是编排者就只看摘要或按通用模板写。
2. 解决某个前向引用前，打开它指向的源码行和验收条目取值；登记表、回报里没写全的数据来源、字段变换、导航细节以源码为准补齐。
3. 写完一个切片，对照该切片的验收条目逐条核对实现位置；“标记已删除”“结构闭包 0 FAIL”不作为完成判据。
4. 规格与实现并行时，写某个页面或壳文件前先打开已落盘的对应规格（页面规格的条件分支与标题、功能规格的 P0 AC 与接口）；规格尚未落地就等待，或先写不依赖它的部分；规格晚于代码到达时，在进入验证前按 AC 回补。
