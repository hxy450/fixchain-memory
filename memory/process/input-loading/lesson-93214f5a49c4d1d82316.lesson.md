# 派工要求按源码确认的内容（字段类型、请求体、凭证来源、码值、地址），规格看似完整或指定数据源查不到时都回源码核对；没读到就标未核实

ID：`lesson-93214f5a49c4d1d82316` · 版本：1

[本主题](index.md)

## 何时使用

写码 worker 开工时：派工要求读 Android 源码确认字段、请求体或响应处理，手头的规格、锚点或上游产物却看似已给出签名；或规格指定的数据源里查不到具体值时

## 适用情境

规格给出接口签名与源码锚点，没写字段类型、请求体字段、凭证来源或错误码取值；Kotlin 可以在一个 .kt 文件里定义多个类，kapt stub 按类拆分。

## 原因

规格是源码的摘要，常漏掉正好要用的细节；“锚点已给出完整签名”“规格已明确”这类判断让写码者跳过源码，缺的细节就被空对象、同文件别的类的字段或推断值补上，编译照样通过。来源中同一切片实现者自称无需再读源码，写出空请求体，只从 body 取 token；Base 层实现者在规格指定的数据源里查不到码值，就把规格里的举例当作已核；它还只读了同名类的 kapt stub，用同文件另一个类的字段填占位，回报却写“已从源码核实”。

## 做法

1. 开工前为每个要输出的字段、请求体、凭证和码值列出出处（源文件与行号）；有一项出处为空就读源码，不因规格或锚点看似完整而跳过。
2. 规格指定的数据源里查不到具体值时，回源码读定义和使用处（枚举定义与使用它的拦截器、地址常量与取址函数）再写；仍查不到就留显式待核标记并写进回报，不写推测值。
3. 找类定义时按类名 grep 源 .kt 文件，不只读同名的 kapt stub；没读到定义就在回报里列为未核实，不用其他类的字段填占位，也不声称已核实。
