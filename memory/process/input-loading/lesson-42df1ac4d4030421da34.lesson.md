# 写码前要读全必读 skill、规格、参考文档与源布局/源码：批量读取被截断、命令只回来部分输出或只读前 N 行时，内容并未进入上下文

ID：`lesson-42df1ac4d4030421da34` · 版本：7

[本主题](index.md)

## 何时使用

写码 worker 或规格作者开工时加载 skill、功能规格、预生成参考文档与源码，按源布局 XML 写页面、弹窗前读取源文件时，长会话压缩上下文后继续写码时，以及在回报中填写 loaded_skills 时

## 适用情境

派工列出多份前置 skill（常见十几份 SKILL.md）或多份规格、参考文档，读取者用一次命令批量 cat，或用 sed -n '1,Np' 按固定行数读取；工具对单次输出有长度上限，超出时会省略中段并给出 truncated 提示。也包括一次 exec 批量读取多个源布局、源码或自定义 View，回执中段被省略；串联的查找命令因 yield 超时只返回第一段输出，其余结果只在未轮询的执行事件里；已加载的 skill 要求先读某份参考（如迁移陷阱表），读取者没有读，或只在 grep 回执里碰到片段、之后上下文被压缩。也包括按行号窗口读取源码时，窗口止于目标 Composable 函数中间；或一次 sed 读十几份 Kotlin 源码，回执在某个文件的 import 之后就被截断。

## 原因

被省略或没读到的段落不会进入模型上下文，其中的具体规则或源结构就等于没下发。来源跨两种宿主、四个应用：批量 cat 18–19 份 SKILL.md 时回执中段被省略，或只读某 skill 前 130 行，随后写出的代码正好违反没读到的规则（只能 throw Error、@Builder 值参不随状态刷新、异步加载要 try-catch 兜底、hilog 导入写法）；已加载的 UI skill 要求先读迁移陷阱表，写 Tab 行的 worker 没有读。另一应用里一次 cat 多份功能规格或源码时截断落在要用的段落：计时源码缺了已完成重量与步进函数，参考文档缺了“对话框列出全部默认项、以新 id 复制”，数据库规格缺了库名与版本要求，外观规格段不可见。第四个应用里写页面前批量读取源布局，截断分别落在首页固定用户栏与滚动容器开标签、二级页布局与自定义日历 View、说明页整段布局上；一次关键字查找因 yield 超时只回来第一段输出，弹窗布局的命中没进上下文。写者没有补读，按可见片段、闭合标签或功能描述推断层级、自拟结构与文案，偏差正好落在被截掉的部分。另一应用中，页面转换者一次输出多份源布局，回执中段被截去，三份关键布局全在截去部分，它仍声明“三源已读完”，自拟了整页配色与选中样式；另一转换者读迁移陷阱表两次都被截断，恰好漏掉“@Builder 值参不刷新”的条目。另一应用中，公共组件作者批量读取十余份 Kotlin 源码，回执在目标文件 import 之后被截断，没有重读就用默认文本样式写出集合标题；另一写者自选的读取窗口正好止于 selectable(...) 那行，没读到下方的条件勾选，随后声称“源码对照已完成”并写出 Radio。

## 做法

1. 必读 skill、规格和参考文档逐份读取，或分批控制单次输出量；看到 truncated output、tokens truncated 之类提示时，列出没读全的文件并按章节或行号单独重读，读全后再写码或写验收条目。
2. 组件复用、状态管理、错误处理这类规则常在 skill 后半部分，不要按固定行数截读；需要节省时先用 rg 找到与当前任务相关的小节标题，再读完整小节。
3. skill 正文要求先读的参考文件（如迁移陷阱表、映射表）同样是必读，与本次写码相关的小节要完整读过；上下文被压缩后，写到尺寸、状态、错误处理这类决策前重读对应小节，不依赖摘要。
4. 按源布局写页面或弹窗时，布局 XML 与自定义 View 逐个读取，或用 XML 解析只抽取层级、TextView 文本与 @drawable 引用；查找命令只回来部分输出（yield 超时、串联命令只见第一段）时先轮询结果或单独重跑。仍拿不到时在回执标注缺口，不凭文件列表、可见的闭合标签或功能描述推断结构与文案。按行号窗口（sed -n 'a,bp'）读源码时，确认窗口末尾没有停在目标函数中间，被截断就续读到函数闭合，再声称源码对照完成。
5. loaded_skills 只写读全的 skill；只读了部分的如实注明范围。
