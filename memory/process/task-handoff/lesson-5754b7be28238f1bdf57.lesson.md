# 编排者推进阶段或派发依赖上游的下游任务前，核对约定产物、划给编排者的子步骤、放行门与子任务回执，缺项不推进

ID：`lesson-5754b7be28238f1bdf57` · 版本：10

[本主题](index.md)

## 何时使用

执行编排阶段，子任务返回后决定推进到下一阶段、派发依赖上游产物的下游任务、关闭巡检报告，或按子任务回执向用户报告完成时

## 适用情境

执行规范把某些收尾步骤（如资源阶段之后的应用身份落地）留给编排者亲自调用；后台子任务回报 completed，但约定产物（如清单 JSON）没有落盘、回报文字被截断，或回报提到一个需要在别处调用的入口（如网络初始化函数）却没写调用点；子任务回执只写“已补齐”“均保留”，不列对照过的源文件；资源迁移等阶段设有放行门（HARD-GATE），下游页面转换准备与之并行；巡检报告列出多个 BLOCKER，派发修复失败（如线程上限）或只修了其中一部分。

## 原因

这些收尾项与产物要求只写在规范段落、回报文字或代码注释里，生成期的检查不覆盖它们：编排者按回执直接推进，这项工作就没有执行者，缺项一直保留到验证或运行时才暴露；回执里的“已补齐”“均保留”没人核对，缺失的源端行为就被当作完成报告。放行门未过就派出的下游会把“暂未就绪”写成待定登记或降级，并保留到生成结束。

## 做法

1. 推进阶段前，按该阶段规范列出划给编排者的子步骤，逐项确认已实际调用，并把它们写进该阶段的预期产物与完成报告；没有执行的先执行，或在报告里登记为阻断项。子代理被告知“跳过、由主线程处理”的项，在宣布阶段完成前逐项勾销。
2. 子任务回报完成后，先确认约定产物文件存在、回报文本完整；缺产物或结果被截断时续跑该任务，再进入依赖它的步骤。回报提到需要调用的入口（如初始化函数）时，grep 调用点确认已接入，再把该层记为完成（入口 init 的调用义务见 lesson-8a881c2e07f80f83447c）。
3. 回执要列出实际对照过的源文件和已识别但未实现的源端行为；没有任何源文件引用，或以“均保留”概括时按未完成处理：对照源端抽查页面里的状态变量、数据接口与按钮可用条件，有缺项就回派或补写，再向用户报告；不以语法清理代替行为核对。
4. 规范设有放行门（如资源阶段 HARD-GATE）时，门通过前不派依赖其产物的下游任务；确需并行时，派工写明产物仍在生成、以门的回报为准，依赖产物的部分等门通过后在写入时刻重新列出目标目录再写，不按派发时看到的空目录登记待定或降级。
5. 处理巡检报告时，派发修复失败（如线程上限）就重试或就地修复（派发重试见 lesson-ae78da6f1a3669f6ef59）；关闭报告前逐项核对每个 BLOCKER 都已落地，不只修同批中顺手的项。
