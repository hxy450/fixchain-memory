# 派工转述规则或把某任务的局部做法推广为派工规则时，连同原文的替代写法、适用范围与配套要求一起下发

ID：`lesson-73a7dd4f78cb747f7e7e` · 版本：6

[本主题](index.md)

## 何时使用

编排或返修阶段，把规则清单、决策台账条目或上一批子任务回报的做法转述进后续 worker 派工时

## 适用情境

编排者收到的规则原文带有替代写法（例如“禁止 Record，改用具名字段或 HashMap”），派给多个并发 worker 时压缩成一句禁令。也包括首批子任务回报了按某参考条目采用的局部做法（如把弹窗写成页内覆盖层），编排者把它写成“全部照此处理”的后续派工规则；以及把决策台账里替代某一源模块的技术参数（如替代后台任务的固定 tick 周期）写进另一模块（如前台动画引擎）的派工，派工前没读该 feature 规格的映射行，并按印象概括源码锚点的内容。

## 例外与边界

- 派工同时禁止 worker 构建：收尾构建责任按交付前编译的经验处理

## 原因

只转述禁令不转述替代写法，worker 会各自找一种看似合规的写法，可能同样被禁止；把局部做法写成总则，会同时丢掉原参考的适用范围、负向守卫与配套条件（如浮层要接管返回键）；把其他模块的参数带进派工，下游就按错误的参数实现。

## 做法

1. 转述规则时保留原文的替代写法或示例，不只写禁令。
2. 把某任务的做法推广给后续派工前，回读它所依据的参考条目，把适用范围、负向守卫和配套要求一并写进派工。
3. 派工里的技术参数（刷新周期、补偿方式等）以该 feature 规格的映射行为准；引用决策台账条目前核对它替代的是哪个源模块，不把其他模块的参数带进本派工；概括源码锚点的内容前打开文件核对。

来源支持：3 张卡 · 3 次迁移 · 2 个应用
