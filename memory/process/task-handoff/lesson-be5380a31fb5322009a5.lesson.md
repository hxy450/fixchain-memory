# 移植与其他组件直接互调的源类时，按跨组件调用边逐条落实：他处读取的 getter、本类发出的通知与回调都要有目标出口和调用方

ID：`lesson-be5380a31fb5322009a5` · 版本：1

[本主题](index.md)

## 何时使用

切片实现阶段，移植引擎、控制器、绘制层等与其他组件直接互调的源类（调用方或被调方归其他切片）时；消费方发现上游缺少读面、钩子无人调用时

## 适用情境

源端对象之间直接调用：预览视图 onTouchEvent 转给引擎 touchEvent，绘制类每帧调用引擎 draw 并读取 hasFocusArea()/getFocusPos()，引擎 onPause/onResume 调视图启停 tick，控制器在拍照流程中经回调与应用接口通知界面提亮、画白层。目标按切片单写者分工，引擎、覆盖层、页面与控制器由不同切片生成，规格对接点可能只列按钮回调。

## 原因

切片按文件分工后，跨组件调用边落在两个写者之间：一方只移植本类的内层处理和私有字段，把发往他处的调用映射到空实现或写成“由 UI 层承担”的注释；另一方检索不到入口，就自驱、写死默认值或记成已知近似。两侧都能编译，钩子无人调用、读面缺失、通知不发，行为直到运行时才缺失。

## 做法

1. 动笔前从源码列出本类的跨组件调用边：检索源工程中其他组件对本类公开方法的调用（如绘制类读取的 getFocusPos），以及本类方法体内对其他组件的调用（视图启停、回调接口、应用接口）；逐条写出目标端对应的公开方法、事件或监听。
2. 他处读取的 getter 连同其存储字段与坐标换算一起移植为公开读面；本类发往他处的通知（暂停/恢复、补光触发、完成回调）保留为回调、监听或查询接口，不映射到空实现，也不只在注释里写“由 UI 层承担”。
3. 本侧负责发起的调用（视图入口把触摸交给引擎、覆盖层每帧调用引擎钩子）直接写出；对侧尚未提供时按工程约定登记带负责方的移交项，不假定后续接线会补，也不把无条件默认值记成规格允许的降级。

## 可选检查

- 收尾时检索本次新增的公开钩子与读面：每个至少有一处调用方，或有一条移交登记。
