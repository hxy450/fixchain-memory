# 同一产物只能有一个写者：并行任务可能写同一共享文件时指定唯一作者；worker 超时仍 running 时不凭旧观测接管

ID：`lesson-39e7e31b88e3d6176022` · 版本：3

[本主题](index.md)

## 何时使用

执行编排阶段，安排多个并行任务、其中几个可能创建或改写同一共享文件时；派发的 worker 多次等待超时，或尚未派发某项任务，编排会话考虑自己写入本应由 worker 产出的契约产物时

## 适用情境

流水线 skill 的收口协议规定完成信号是 list_agents 的 completed 而不是产物文件存在，连续超时先核对状态、句柄消失才断点重派，契约产物须出自承担任务的子代理、禁止派发方代写；worker 已重派且仍为 running，编排者早些时候查过目标目录为空。也包括编排者不派发 Base 任务、自写产物后直接以 PASS 写回；以及多个并行转换任务都会创建同一共享组件。

## 原因

目录为空是会过期的观测，running 的 worker 可能已写出产物；两个写者并行写同一目录或文件，会产出同名导出不一致的文件（构造参数顺序也可能不同）或互相整文件覆盖，也绕过了 closer 对单一产物的核对。

## 做法

1. 派发前找出会被多个并行任务创建或改写的共享文件，指定唯一作者，其余任务只消费；确需多方修改时串行交接：确认前一写者已停止后，后来者重读当前版本再合并。
2. 等待超时后先调 list_agents 读 agent_status：仍为 running 就继续 wait 或明确 interrupt，不以“目录里还没有文件”认定 worker 无产出。
3. 任何接管或补写前，在同一时刻复查目标目录与 worker 状态，用写前最新观测决策。
4. skill 规定契约产物出自承担任务的子代理时：未到重派上限就继续收口，到上限仍无产出就记阻断；确需换写者先 interrupt 原 worker 并确认停止；Base 等任务按 skill 交给 worker、由 closer 核对，不自写后标 PASS。
5. 已出现并行产物时按计划选定一套、删除另一套，再检索每个导出只定义一次、构造参数顺序与调用方一致。

来源支持：3 张卡 · 2 次迁移 · 2 个应用
