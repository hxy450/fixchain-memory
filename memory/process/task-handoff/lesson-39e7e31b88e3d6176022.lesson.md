# worker 等待超时但仍为 running 时不凭旧目录观测接管其契约产物：以 list_agents 状态为准，写前同刻复查产物；skill 禁止派发方代写时继续收口或先中断再换写者

ID：`lesson-39e7e31b88e3d6176022` · 版本：1

[本主题](index.md)

## 何时使用

执行编排阶段，派发的实现 worker 多次等待超时，或尚未派发某项任务，编排会话考虑自己写入本应由 worker 产出的契约产物时

## 适用情境

流水线 skill 的收口协议规定完成信号是 list_agents 的 completed 而不是产物文件存在，连续超时先核对状态、句柄消失才断点重派，契约产物须出自承担任务的子代理、禁止派发方代写；worker 已重派且仍为 running，编排者几分钟前查过目标目录为空。也包括编排者不派发 Base 任务、自写产物后直接以 PASS 写回。

## 例外与边界

- skill 对该情形明确规定由编排会话前台补跑，且原 worker 已确认停止

## 原因

目录为空是会过期的观测，running 的 worker 可能已写出产物；编排者按旧观测自写同一目录，两个写者并行产出同名导出不一致的文件（构造参数顺序也可能不同），也绕过了 closer 对单一产物的核对。来源中编排者 8 分钟前查到目录为空、4 分钟前看到 worker 为 running，之后只有两次 wait 超时就自写模型文件，而 worker 已在 2 分钟前写出按职责拆分的五个文件。

## 做法

1. 等待超时后先调 list_agents 读 agent_status：仍为 running 就继续 wait 或明确 interrupt，不以“目录里还没有文件”认定 worker 无产出。
2. 任何接管或补写前，在同一时刻复查目标目录与 worker 状态，用写前最新观测决策。
3. skill 规定契约产物出自承担任务的子代理时：未到重派上限就继续收口，到上限仍无产出就记阻断；确需换写者先 interrupt 原 worker 并确认停止；Base 等任务按 skill 交给 worker、由 closer 核对，不自写后标 PASS。
4. 已出现并行产物时按计划选定一套、删除另一套，再检索每个导出只定义一次、构造参数顺序与调用方一致。

来源支持：2 张卡 · 1 次迁移 · 1 个应用
