# 解决前向占位时按登记的触发文本逐项兑现：只接一半、写成常量或删掉标记都不算闭合

ID：`lesson-eb4de4fd7452308a0483` · 版本：12

[本主题](index.md)

## 何时使用

切片实现或接线阶段，把页面转换留下的前向占位（FWD-REF、TODO）替换成实现并删除标记时；收敛阶段解除“不确定、待真机核验”一类前向标记时

## 适用情境

页面转换阶段按“只输出 UI”约束留下前向占位，登记表或 TODO、文件头注释写有触发文本，例如“持久化并触发主题立即切换”“切换步骤时重触觉”“由服务提供版本号”“通知授权由平台服务实现”“游客登录（登录成功跳主页）”，由后续切片或接手者实现。也包括 forward-ref-uncertain 一类待核验标记，收尾者以“共享件已由另一切片定型”为由删除。也包括导航类钩子只带触发动作的枚举或事件名（如某入口奖励完成），未写目标页，而路由表注册了名称相近的候选页（如 Xxx 与 XxxReal）。也包括关闭共享能力的占位时同一能力还有其他文件消费，或未完成的部分被注释指向另一文件已登记的占位编号。也包括被调方缺少占位所需的能力（停止入口、完成回调、整组结果通道或门面方法不存在），接线者改用名称相近的现有 API 顶替（如以“取消重复拍照”代替“停止连拍”），或把门面接不住的参数 void 掉、在消费侧降级后标为已接线。

## 原因

标记删掉后编译和结构审计都会通过，触发文本里没做的那一半没有任何门会发现。来源一个应用中有四类：只接了偏好持久化、没有运行期消费方；只重置进度、没做反馈；把应由服务提供的版本号写成与配置文件重复的常量；把应真实现的平台能力写成恒定返回值。另一应用里接线者读到“游客登录”的 TODO 和“登录成功跳主页”的注释，只接上登录调用，不等结果、不跳转，就删了 TODO。另一应用中，数据接线者删掉了黄历区块的前向占位标记，却没有给区块的 available 标志赋值，组件按该标志把整块隐藏；另一接线者按只含 P-ID 的钩子接线，没有回读源码，丢了选中项的恢复与回写。导航类钩子没写目标页时，接线者若只看账本和路由表，会在名称相近的已注册页里按字面挑一个，编译与结构审计照样通过，正确目标页成了孤儿。被调方缺少登记的能力时，用相近 API 顶替或丢弃参数同样能通过编译与审计，缺口一旦标为已解除，就不会再有人回到能力所属方补契约。

## 做法

1. 删标记前把触发文本拆成动作清单（持久化、运行期消费方、反馈、值来源、导航），每一项都能在代码里指出实现位置后再删；被调方缺少登记所需的能力（停止入口、完成回调、整组结果通道、门面方法）时，不用名称或语义相近的现有 API 顶替，也不在接线侧丢弃参数或降级后标已解除，保留占位并回到能力所属方登记补契约。
2. 触发文本要求服务或 ViewModel 提供值时，写入常量或复制配置文件里的值不算闭合，改为从运行时来源读取。
3. 只接上了调用、没处理结果分支（成功后的跳转、失败提示）时保留标记，不算接线完成。
4. 删除标记后 grep 同一函数：恒定返回（return false、两支相同的三元表达式）、与配置文件相同的字面量，都是没闭合的信号。
5. 删除标记前，逐项核对组件里每个 available/可选区块开关都有真实的赋值来源；源端在选中项变化时附带的查询（如按选中日查历法）要迁到网关或 ViewModel，不能留默认值让条件渲染把整块隐藏。
6. 填别人留下的钩子前，回读页面规格列出的源码锚点中对应方法，逐项核对加载、恢复、切换回写等行为，不只按钩子名称接线。导航类钩子的目标页按触发控件到 UI 规格的导航关系表或源端监听器的 Intent/startActivity 追溯；路由表有同前缀的候选页时先确认各自对应的源页面，确认不了就登记缺口，不按名称相似度选择。
7. “不确定、待核验”类标记的触发条件是验证：解除时附核验证据（截图、dump 或等价单测），“已由其他切片定型”“实现可行”都不能作为删除理由；生成期拿不到证据就保留标记，并列入验证阶段必测项。
8. 闭合时对照登记原条目逐项核对（参数、清洗、主题、外观与点击是否一并迁移）；未完成的部分在本文件登记新占位，不在注释里借用另一文件的占位编号；关闭共享能力的占位时，把检索命中的所有消费方逐个接上或重新登记。
