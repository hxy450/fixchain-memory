# 计划把 AC 记到 packet 时，标侧文件须在其输出或写权内；跨页面/组件的深色主题接线单独排给有写权的任务，不以“后续阶段接线”代替负责方

ID：`lesson-5d91af2a5eb89405dcd2` · 版本：1

[本主题](index.md)

## 何时使用

计划与执行编排阶段，把规格 AC 映射到 packet 或切片、确定各单写者的输出与写权时，以及在派工或基础契约里把某项能力写成“由后续阶段完成”时

## 适用情境

规格 AC 以某个独立文件为标侧（如主题文件），或要求一项横跨所有页面与公共组件的运行时能力（如深色跟随系统：共享主题状态、应用壳订阅系统深浅设置、各处取色）；计划按“Base 层常量 + 多个单写者切片”分派，每个切片只能写自己的页面文件；派工或基础契约写有“由 Stage 3/页面接线完成”一类说法。

## 原因

覆盖表只记需求 ID、或只给某个步骤挂上专项 skill 提示，并不等于有人能写标侧文件。每个单写者只看自己的范围，“后续阶段”没有具名接收者时，各方都把它当作别人的事：认领该 AC 的切片因写权不足只上报风险，收尾者记 deferred，能力从未实现，编译和静态检查也发现不了。

## 做法

1. 把 AC 记到 packet 时，逐条核对它的标侧文件出现在该 packet 的输出或可写清单里；只挂 suggested_skills、或只在覆盖表里记需求 ID，不算认领。
2. 需求横跨所有页面和公共组件（深色主题选色、全局字号缩放等），而各切片写权都不含主题文件和公共组件时，单独排一个有写权的 packet：新建共享的可观察主题状态、在应用壳订阅系统设置、改组件与页面的取色；或者把这些文件显式授予某个切片。
3. 派工或基础契约写“由后续阶段/页面接线完成”时，同时写明接收的切片、要新建或修改的文件以及写权；写不出接收者就按计划缺口退回规划，不带着空白继续执行。
