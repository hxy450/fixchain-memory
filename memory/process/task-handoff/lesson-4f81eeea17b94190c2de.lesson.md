# 要靠其他文件或任务补实现的功能，登记成带负责方、验证方式和源端确定值的移交项，不只写在注释或动作摘要里

ID：`lesson-4f81eeea17b94190c2de` · 版本：4

[本主题](index.md)

## 何时使用

页面转换、切片实现、基础设施实现或接线阶段，本文件的功能需要别的文件补调用点、或要由后续步骤补值才完整时（包括留下前向引用、TODO 占位、需要在入口调用的初始化函数），以及读到上游留给本文件的移交说明时

## 适用情境

写码者确认某项行为在当前文件里无法闭合（例如非入口组件的平台回调要由入口页转发、宿主回调留给接线切片、脚手架身份值留给后续步骤、新建的 init 要由入口调用、UI 转换阶段先留业务占位），工程提供了移交登记约定（如带 owner/what/verify 的 HANDOFF 标记、前向引用登记表、返回信封中的字段）；或接线者在上游文件头读到要求本文件转发的说明。

## 原因

文件头注释和报告里的开放问题不进入任何检查：编译、结构审计都会放行，后续编排与复核也容易按“已处理”理解；登记只写动作摘要时，写前已读到的源端细节在交接中丢失，接手者只能猜。来源中页面转换者已从 SDK 注释核到平台限制，也起草了指向壳页切片的移交，落盘时删掉，只留文件头说明；资源任务在返回里只写“归属后续步骤”；另一应用里转换者读到了更新卡的确切网址、克隆名的本地化后缀和“以编辑草稿为克隆内容”，登记只写“更新卡外链”“复制并重建列表栈”，接手者没读源码，写了猜测的网址和按持久化数据、原名克隆。第三个应用里，网络层实现者写了必须在入口调用的 init，回报却写“无待接线项”；UI 转换留下的 TODO 只写了调用名，写引导完成标记和失败提示这两项在交接中丢失。另一应用中，UI 转换者读到容器按持久化的选中项恢复当前页、切页时回写选中项，却只留下只含 P-ID 的前向钩子，接线者照钩子名接线，恢复与回写都丢了；另一转换者把选城后回天气 Tab、列表为空进入添加页也只登记为槽名。

## 做法

1. 按工程的移交约定登记：写明负责方（具体切片或阶段）、要补什么、如何验证；验证断言难写时改用切片级断言（如 slice:N），移交本身保留。
2. 登记里写入已读到的源端确定值与出处：网址、常量、比较符、参数来源（持久化值还是编辑草稿）、字段变换、完成后的导航；UI 转换阶段先留业务占位时，TODO 里写清源端完整的成功与失败动作（写标记、跳转、关页、失败提示），只写调用名不够。
3. 按分工保留应由别人处理的值时，在返回里逐项列出保留的键或片段，以及应接手的步骤；新建的初始化函数需要在入口调用而本任务不能改入口时，列出文件、生命周期方法和调用语句，不写“无前向引用”。
4. 接线时读到上游文件要求本文件转发或补调用点，就在本文件实现；派工不允许或实现不了时作为阻塞项上报。接手者从登记里取不到确切值时，打开出处源码取值，取不到就登记缺口，不写推测值。
5. 派工只允许写本文件、而源端依赖的共享工具还没有目标文件时，在本文件实现等价逻辑，或登记前向引用交给后续切片；不要静默省略。
