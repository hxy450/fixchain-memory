# 重新规划或替换计划时，把已批准未执行的规格逐条映射到新计划的批次与验收，或写明合并、推迟、放弃的去向

ID：`lesson-b843621a5b9c279b1b2b` · 版本：1

[本主题](index.md)

## 何时使用

迁移规划阶段，用户要求全量重审、以新计划替换原有局部修复计划时

## 适用情境

增量迁移中已有获用户批准、尚未执行的局部缺陷规格（如某项偏好持久化），随后重新盘点并按模块、批次重写总体计划。

## 原因

“作为后续计划的输入”一类笼统表述没有负责批次与验收项，已批准的规格在新计划里消失；验证阶段相关功能点又因宿主不可达被 BLOCKED，缺陷一直留到修复期。来源中规划者把四项已批准的局部规格写成“不再独立执行、作为页面级输入”，新计划的批次与验收里都没有对应任务。

## 做法

1. 新计划定稿前做追溯核对：列出规格索引中 planned、pending 的条目，逐条确认在新计划中有任务编号与验收项，或有显式的合并、推迟、放弃决策与负责批次。
