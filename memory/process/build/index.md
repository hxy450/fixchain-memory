# process/build

编译修复循环与构建结果判定：只改报错定位处、不以删功能或语义不同的替代换取通过（确需删除承载行为的调用时同步注释并回报退化）、整文件重写时保留未报错写法，读全错误输出，失败构建不以警告或部分通过放行，最终结论只引用晚于最后改动的构建；缺项目根 hvigorw 时改用本机构建入口，确实不能编译时的模式扫描与如实声明；shell 一行命令替换含 $ 片段的引号与读回

## 本级经验

- [交付前要编译：项目根没有 hvigorw 时用 DevEco 自带的 hvigorw；禁编译的 worker 由编排者收齐后全量构建](lesson-25bc0b7518d335a947d6.lesson.md)
  - 时机：实现或修复阶段写完 ArkTS 代码准备交付，而工程根找不到 hvigorw、子任务约定把编译留给主线程，或派工禁止 worker 并发构建时
  - 情境：工程根没有 hvigorw 脚本，本机另有 DevEco Studio 自带的 hvigorw、command-line-tools/bin/hvigorw 或流水线封装的构建命令；子代理常以“缺 hvigorw，交收尾编译”结束。也包括并行子代理只用 node --test 跑按文本或正则读取源码的 .cjs 契约就以“交主线程统一构建”结束；以及编排者禁止 worker 并发构建，worker 写出 TS 习惯写法（implements SDK class、按类名调用顶层函数），收尾构建因会话中断没有执行。
- [用 shell 一行命令改写含 $ 的 ArkTS 片段（如 $r(...)）时防止替换串被 shell 或 Perl 插值，改后读回每一处](lesson-6dae0bf2657b0e339742.lesson.md)
  - 时机：编译修复或批量改写阶段，用 perl -pi、sed -i 等一行命令替换含 $ 的 ArkTS 表达式时
  - 情境：修复脚本用 perl -pi、sed -i 一行命令做批量替换，替换内容含 $r('app.float.xxx') 等以 $ 开头的标记；ArkTS 把字符串传给 Length、ResourceColor 类参数也能编译通过。
- [编译修复只改报错定位的行与符号：整文件重写逐段对照上一版，不以删功能换通过，不按类比改未报错的文件](lesson-29744eb694376e8acaca.lesson.md)
  - 时机：编译修复阶段，为修某条编译错误决定局部修改、整文件重写、删除调用或扩大到同型文件时
  - 情境：修复循环用 here-string 等方式整文件重写页面来处理导入导出、@Entry 等报错，文件里还有未被报错的组件用法（如页签的 @Builder 写法）；或报错只涉及某个导入或符号，修复者考虑把相关功能块（如自绘图表）整体换成占位；或删掉某个调用能通过编译，但会让行为退化（取不到尺寸、状态永不赋值）。也包括修复者按类比把同一改法扩散到没有报错的文件（“潜伏同型”），或以“未检索到某关键字”推断某类写法不受支持。
  - 例外：报错是 API、字段、枚举成员不存在或类型不符：先按原语义选替代（见对应经验），本条约束改动范围
- [编译报 API、字段或枚举成员不存在、类型不符时，按原调用语义在本地 d.ts 选替代，不就近换名、不连内容删掉、不换数据源](lesson-4c82ee3c1e40eab120fc.lesson.md)
  - 时机：编译修复阶段，报错指向 SDK 不存在的 API、参数字段或枚举成员，或指出类型不符（如 Resource 不能赋给 string）时；规格或实现阶段为源端系统 API 选目标 API 时
  - 情境：报错来自调用了 SDK 不存在的参数字段（如在 AlertDialog 参数里写自定义内容 builder），修复者准备删掉该字段连同其中承载的控件；或报错指向不存在的 API（如映射给单调时钟的 Web API），修复者准备换成语义不同的替代（如会随校时跳变的墙钟）；或枚举没有某成员（如 FontWeight.SemiBold），修复者准备按名称换成相邻成员；或 Resource 赋给只收 string 的字段（如 PopupOptions.message），修复者准备换成枚举名、rawName 等字面串。
- [编译检查按完整构建结果判定：读全 ERROR 与 COMPILE RESULT，失败只记 FAIL，“最终通过”只引用最后改动之后的构建](lesson-7426a20525e52e34c2e7.lesson.md)
  - 时机：验证阶段执行编译检查并决定是否标记阶段完成时；编译修复循环查看构建输出时；构建通过后又改动了源码、准备宣称“最终构建通过”时
  - 情境：hvigor 构建输出重定向到文件，WARN 常排在 ERROR 之前；修复循环只截取错误文件前若干行；验收规范规定编译通过才 PASS、否则 FAIL 并继续修复循环。或编排者在构建报成功后又追加源码改动，派出的复核构建尚未返回结果。
