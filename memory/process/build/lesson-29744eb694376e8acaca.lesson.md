# 编译修复只改报错定位的行与符号：整文件重写逐段对照上一版，不以删功能换通过，不按类比改未报错的文件

ID：`lesson-29744eb694376e8acaca` · 版本：9

[本主题](index.md)

## 何时使用

编译修复阶段，为修某条编译错误决定局部修改、整文件重写、删除调用或扩大到同型文件时

## 适用情境

修复循环用 here-string 等方式整文件重写页面来处理导入导出、@Entry 等报错，文件里还有未被报错的组件用法（如页签的 @Builder 写法）；或报错只涉及某个导入或符号，修复者考虑把相关功能块（如自绘图表）整体换成占位；或删掉某个调用能通过编译，但会让行为退化（取不到尺寸、状态永不赋值）。也包括修复者按类比把同一改法扩散到没有报错的文件（“潜伏同型”），或以“未检索到某关键字”推断某类写法不受支持。

## 例外与边界

- 报错是 API、字段、枚举成员不存在或类型不符：先按原语义选替代（见对应经验），本条约束改动范围

## 原因

整文件重写时顺手换掉未报错的写法，会引入新的编译错误或行为变化；以删除功能、占位或类比扩散换取通过，退化不进入任何报错，注释与文件头仍声称行为存在时会被掩盖到运行时。stateStyles、@Styles 一类 UI DSL 在 d.ts 中类型宽松，编译通过不代表运行可用。

## 做法

1. 只改报错指向的行和符号；必须重写时先与上一版逐段对照，未报错的组件用法保持原样，确需改动的先按 API 签名或编译器重载提示确认可用形态。
2. 报错只指向导入或单个符号时，修正导入（如改用全局可用的类型）并保留功能；确需降级时回写规格、把对应验收保持未完成，按占位规则登记丢失的控件与写入及回补位置，不以占位替换后报告通过。
3. 确需删除承载核心行为的调用时，同步改掉仍声称该行为存在的注释与文件头，把行为退化和可替代的平台 API 列为待修项回报，不以“编译通过”收口。
4. 不把修复按类比扩散到没有报错的文件；基于“未检索到关键字”得出的推断，先用一个未报错的同型文件反证；UI DSL 的替代写法在编译门报告里列为需打开页面验证的项，并写明页面入口。
