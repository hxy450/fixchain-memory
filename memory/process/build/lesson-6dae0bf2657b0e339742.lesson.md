# 用 shell 一行命令或脚本改写含 $ 或反斜杠转义的 ArkTS 片段（如 $r(...)、\u0000）时用单引号脚本或字面替换，改后逐字节读回每一处

ID：`lesson-6dae0bf2657b0e339742` · 版本：2

[本主题](index.md)

## 何时使用

编译修复或批量改写阶段，用 perl -pi、sed -i 等一行命令替换含 $ 的 ArkTS 表达式时；用 Python 等脚本把控制字符改写成源码转义序列，或向源码写入含反斜杠的字面量时

## 适用情境

修复脚本在双引号包裹的 shell 命令里写 perl/sed 替换串，替换内容含 $r('app.float.xxx') 等以 $ 开头的标记；ArkTS 把字符串传给 Length、ResourceColor 类参数也能编译通过。也包括写入工具把源码里的 \0 变成了原始 NUL 字节，写者再用 Python heredoc 的 bytes 字面量把它们改回 \u0000 一类转义，替换串里的反斜杠要经过 shell 与 Python 字面量两层解释。

## 原因

双引号里的转义先被 shell 消费，perl 再把 $r 当未定义变量插值为空，写出 ('app.float.xxx') 这样的裸字符串；它是合法的 Length，重编译通过，资源却不会被解析，样式静默失效。反斜杠同理：每经一层字面量解释就被消费一次，层数算多时落盘成字面反斜杠加 u0000，字符串照样编译，二进制头部与前缀却不再含 NUL；print 显示的是解释后的内容，不是 repr，据它推断文件里的反斜杠个数会看错。

## 做法

1. 把 perl/sed 脚本放在单引号内，或改用编辑工具、Python 字面替换；替换后读回每一处被改的行，确认 $r( 仍在。
2. 收尾时对改动文件 grep 未被 $r 包裹的 ('app.float|color|string|media.xxx') 形态；编译通过不能证明资源引用正确。
3. 向源码写转义序列时逐层计算反斜杠（Python 普通或 bytes 字面量里的两个反斜杠落盘为一个），替换后用 repr 或逐字节读取目标文件，确认恰为一个反斜杠加 u0000；也可改用 String.fromCharCode(0) 或显式字节数组，不依赖转义层。
