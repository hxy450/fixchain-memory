# 用 shell 一行命令改写含 $ 的 ArkTS 片段（如 $r(...)）时防止替换串被 shell 或 Perl 插值，改后读回每一处

ID：`lesson-6dae0bf2657b0e339742` · 版本：3

[本主题](index.md)

## 何时使用

编译修复或批量改写阶段，用 perl -pi、sed -i 等一行命令替换含 $ 的 ArkTS 表达式时

## 适用情境

修复脚本用 perl -pi、sed -i 一行命令做批量替换，替换内容含 $r('app.float.xxx') 等以 $ 开头的标记；ArkTS 把字符串传给 Length、ResourceColor 类参数也能编译通过。

## 原因

插值发生在两层：双引号包裹时 shell 先处理 $，把替换串里转义的 \$r 还原成 $r 交给 Perl；Perl 的 s/// 替换部分即使整段脚本放在 shell 单引号里，仍按 Perl 字符串插值，把 $r 当未定义变量替换为空。结果写出 ('app.float.xxx') 这样的裸字符串，它是合法的 Length，重编译通过，资源却不会被解析，样式静默失效。sed 的替换串不做变量插值，单引号包裹即可。

## 做法

1. sed 用单引号包裹脚本；perl 除单引号包裹外，把替换串里的 $ 写成 \$（如 's/X/\$r(1)/'）；或改用编辑工具、Python 字面替换。
2. 替换后读回每一处被改的行，确认 $r( 仍在；收尾对改动文件 grep 未被 $r 包裹的 ('app.float|color|string|media.xxx') 形态，编译通过不能证明资源引用正确。
