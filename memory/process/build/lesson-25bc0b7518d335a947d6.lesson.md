# 交付前要编译：项目根没有 hvigorw 时改用 DevEco 或命令行工具自带的 hvigorw、流水线构建入口；只跑读取源码文本的契约测试不算编译，仍不可用时按已知错误模式扫描并在回执写明未编译

ID：`lesson-25bc0b7518d335a947d6` · 版本：2

[本主题](index.md)

## 何时使用

实现或修复阶段写完 ArkTS 代码、准备交付，而工程根目录找不到 hvigorw，或子任务约定把编译留给主线程统一执行时

## 适用情境

工程根目录没有 hvigorw 脚本，本机另有 DevEco Studio 自带的 hvigorw/hvigorw.js、command-line-tools/bin/hvigorw 或流水线封装的构建命令；子代理常以“缺 hvigorw，交收尾编译”结束。 也包括并行领域子代理只用 node --test 跑按文本或正则读取源码的 .cjs 契约，就以“交主线程统一构建”结束。

## 原因

不编译就交付，会把严格类型、声明顺序、声明式语法等错误留给用户逐个报回。来源中多个写者以项目根没有 hvigorw 收尾，而同一工程的其他会话已经用命令行工具或 DevEco 的 hvigorw 编译过。

## 做法

1. 项目根缺 hvigorw 时，查找并使用本机 DevEco Studio 或 command-line-tools 自带的 hvigorw（或流水线提供的构建命令）执行 assembleHap。
2. 构建仍不可用时，按本轮代码涉及的已知错误模式做针对性扫描（如内联对象字面量、static 初始化器引用的类位置、块后分号），并在回执写明未编译，不以“待收尾编译”结束。
3. 文本契约与正则断言不检查 ArkTS 类型：子代理交回前对自己新增或修改的 .ets 跑一次 CompileArkTS（并发时与其他构建错开），做不到就在回执列出未编译文件，并按本轮写法逐项自查（标识符键的 Record 字面量、与通用属性同名的成员、未 implements 的接口传参）。
