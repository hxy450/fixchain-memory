# 交付前要编译：项目根没有 hvigorw 时用 DevEco 自带的 hvigorw；禁编译的 worker 由编排者收齐后全量构建

ID：`lesson-25bc0b7518d335a947d6` · 版本：4

[本主题](index.md)

## 何时使用

实现或修复阶段写完 ArkTS 代码准备交付，而工程根找不到 hvigorw、子任务约定把编译留给主线程，或派工禁止 worker 并发构建时

## 适用情境

工程根没有 hvigorw 脚本，本机另有 DevEco Studio 自带的 hvigorw、command-line-tools/bin/hvigorw 或流水线封装的构建命令；子代理常以“缺 hvigorw，交收尾编译”结束。也包括并行子代理只用 node --test 跑按文本或正则读取源码的 .cjs 契约就以“交主线程统一构建”结束；以及编排者禁止 worker 并发构建，worker 写出 TS 习惯写法（implements SDK class、按类名调用顶层函数），收尾构建因会话中断没有执行。

## 原因

不编译就交付，会把严格类型、声明顺序、声明式语法等错误留给用户逐个报回；文本契约与正则断言不检查 ArkTS 类型；禁编译的 worker 写出的类型错误只在汇总构建时暴露，汇总构建没跑，错误就随交付进入下一轮。

## 做法

1. 项目根缺 hvigorw 时，使用本机 DevEco Studio 安装目录下的 tools/hvigor/bin/hvigorw（Windows 为 hvigorw.bat）、command-line-tools/bin/hvigorw 或流水线提供的构建命令执行 assembleHap。
2. 子代理交回前对自己新增或修改的 .ets 跑一次构建（CompileArkTS 或 assembleHap），并发时与其他构建错开；只有错开后构建仍失败，才在回执列出未编译文件，并写明已尝试的 hvigorw 路径与报错原文，同时按本轮写法逐项自查（标识符键的 Record 字面量、与通用属性同名的成员、未 implements 的接口传参）。
3. 派工禁止 worker 并发构建时，限制清单写入与 TS 直觉相反的规则（如 implements 只接受 interface），worker 仍做导入名与导出名的静态对照；编排者收齐改动后立即全量构建，逐一核对 worker 新引入的类型声明；收尾构建因会话中断未执行时，下一轮先编译再派工。
