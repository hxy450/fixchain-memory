# 用户只给出部分页面截图时，迁移范围至少包含截图页入口直达的应用内二级页面，不自行取最窄解释

ID：`lesson-91c89aff3f8c5c47bd2a` · 版本：3

[本主题](index.md)

## 何时使用

规格提取阶段，确定本轮迁移范围并处置截图页入口直达的清单外 Activity 时；以及实现、交付阶段遇到被排除在范围外的入口时

## 适用情境

用户附若干页面截图，要求“按图片和源码迁移、修到可交付”并跳过确认；截图页上的按钮、菜单在源码中 startActivity 到说明页、记录页、关于/反馈、设备连接等独立页面；覆盖检查对这些被引用的 Activity 报未计入。

## 例外与边界

- 用户明确限定只迁移截图中的页面本身；此时仍按最后一条汇报未实现入口

## 原因

截图说明的是这些页面长什么样，不是“只做这些页面”。把截图当范围边界并自行登记排除项，会让入口只剩占位 Toast、未注册路由，覆盖检查被 skip-list 关闭，交付报告仍写“占位符 0、可交付”。

## 做法

1. 以截图页为根，从源码点击监听与 Intent 抽出每个入口的直达目标，应用内的二级页面列入本轮页面清单或功能锚点；入口外跳系统或其他应用（应用商店、系统设置、拉起其他应用）时，按源端的调用与失败回退原样保留，不计入要新建的页面。跳过确认不等于授权缩小范围：必问的范围类目无法询问、而用户要求按源码修到可交付时，取入口可达闭包，不取最窄解释。
2. 覆盖检查报被范围内页面引用的 Activity 未计入时，补页面规格或功能锚点，不用自拟的范围决策登记跳过；写完核对导航表和验收条目要打开的目标都在页面清单里，冲突先消解。
3. 范围确被限定时，入口不以“暂不可用”Toast、无响应或其他入口兜底冒充完成；把未实现入口汇总给协调者，并在交付总结中逐项列出。

来源支持：2 张卡 · 2 次迁移 · 2 个应用
