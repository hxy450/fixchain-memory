# 写应用壳契约与实施计划时枚举源导航模块的全部入口能力（含深链解析与 scheme 注册）；只有获批的排除才登记 skip

ID：`lesson-3348c580951ef82a9737` · 版本：3

[本主题](index.md)

## 何时使用

规格与计划阶段，编排者撰写应用壳/导航的共享契约、实施计划或压缩前交接摘要，确定路由表、启动入口与 module 配置要承载哪些源端导航能力时

## 适用情境

源导航模块除路由表和顶层 Tab 外，还含深链路由器（解析器类、深链基址常量、Manifest 的 scheme 或 App Links intent-filter）；目标用 Navigation + NavPathStack 字符串路由重建应用壳；契约先于 feature spec 写出并被后续实现重读，会话中途可能发生上下文压缩。

## 原因

契约和交接摘要会被后续实现（包括上下文压缩之后）重读；源端能力在契约里被概括掉（应用壳记为 simple、锚点只列路由表与 Tab），账本里又没有对应的 skip 决策，实现与验证都不会再想起它。用自拟的范围决策登记 skip，或事后以 MVP、笼统的范围决策为由判为范围外，该能力就不经裁决被裁掉。

## 做法

1. 写契约或实施计划前列出源导航模块的全部文件与入口能力（路由表、顶层 Tab、返回栈、深链解析与基址常量、Manifest 的 scheme 与 App Links），逐项写成契约锚点和目标符号；不做的须是已获批准的范围决策并写进决策账本 skip，不用自拟的范围决策登记 skip，想排除的交决策关口确认；账本没有对应 skip 决策的能力按缺口（待实施）处理，不以 MVP 或笼统的范围决策为由判为范围外。
2. 决策只改变某项能力的形态（如深链参数改为字符串键）时，契约与计划保留承载它的入口：URI 解析函数、入口 Ability 的 onCreate/onNewWant 投递、module.json5 skills 的 uris；可能压缩上下文时，把这些入口写进交接摘要的剩余文件清单。
