# 落盘差异决策时，以成本、复杂度或“首版不做”为理由的降级按范围裁剪处理；无人值守的闸门自动批准不等于用户改判，默认阻断或依据未查证的平台差异保持待批

ID：`lesson-7827e0707780cb7546ee` · 版本：3

[本主题](index.md)

## 何时使用

规格决策阶段登记 skip、降级或按默认政策裁定范围排除（桌面 Widget 等独立扩展入口）、把平台差异写入决策台账并批准时，尤其在无人值守、各阶段闸门预授权自动通过的运行模式下

## 适用情境

项目基线要求完整复刻：可观察行为不得擅自改变，无法等价复刻时差异决策保持待批、进入确认表，“无平台对等”类差异默认阻断、须改判。规格或台账的“平台约束”一栏却写着“可移植但成本高”“复杂度高”“首版无必要”“暂不”，或“无对等”结论没有对应的查询记录；运行授权只说明各阶段闸门自动批准，写者在思考中已注意到策略与降级之间的冲突。也包括默认政策把某个用户可见功能簇（桌面 Widget、穿戴等独立扩展入口）列为默认排除、要求随闸门摘要由用户确认，而目标平台有对等能力、规格已写出该功能的验收。

## 例外与边界

- 用户或产出定位明确把该项列为本轮裁剪（如演示版、首版范围清单），并在决策中写明用户可见影响

## 原因

成本理由说明的是产出取舍，不是平台做不到；放进“无对等”通道就绕开了范围决策，下游会照差异条目删掉可实现的功能，并把降级形态写进验收。闸门自动批准只表示流程可以继续；把它当作用户对默认阻断项的改判，未查证或以成本为由的降级就以“已批准”身份进入台账，后续规格与实现都把它当既定事实，不再复核。

## 做法

1. 登记降级或排除前分清理由：平台确实没有能力（附查询依据）才走平台差异；理由是成本、复杂度、首版取舍或默认政策的，属于范围裁剪，条目里分列“目标能力是否可行”与“排除依据”。完整复刻口径下撤销该降级、写成实现项，不列入“直接砍掉”的范围。
2. 无人值守运行时，默认策略要求用户确认或默认阻断的差异决策保持 proposed，并在闸门摘要中单列披露；也可以直接按完整复刻落实。不要自行把它写成 approved。
3. 批准差异决策（含自动批准）前，逐条核对平台约束在规格过程中有实际查询回执；没有回执的，退回规格作者查证后再裁决。
4. 范围排除尚待确认时保留可逆性：已写好的规格与验收标为 deferred 留在计划映射里，不批量改成作废、不从覆盖表删除；在计划或入口清单（扩展能力声明、卡片配置等）登记待决策占位，改判后可直接按规格实现。
