# 页面直接读共享 @ObservedV2 模型的 @Trace 字段，不复制成 @Local 快照再手动同步

ID：`lesson-08c38f950b69e991607d` · 版本：1

[本主题](index.md)

## 何时使用

功能接线与组收尾阶段，把页面显示状态接到 @ObservedV2 模型，且其他页面也会修改同一模型时

## 适用情境

源端由一个根状态持有者驱动多个屏幕；目标端拆成 Navigation 下的多个页面，共享同一个 @ObservedV2 + @Trace 模型（如 AppStorageV2.connect 取得），子页修改共享模型后返回原页面。

## 例外与边界

- 需要与模型解耦的纯界面态（弹窗开关、未提交的输入草稿）仍放在页面 @Local

## 原因

@Trace 字段变化会刷新直接读它的组件；把字段复制进页面 @Local 后，界面只随手动同步更新，其他页面对模型的修改进不了界面。来源中页面先 new 私有模型、再用同步方法把 7 个字段复制进 @Local；后来模型改成共享实例但副本保留，返回刷新放在不会执行的“第二次 aboutToAppear”分支，补上的 onShown 刷新在该页作为 Navigation 首页内容的挂载方式下设备实测也未生效（触发机制未单独验证），最后改成直接绑定模型才修好。

## 做法

1. 页面 build 中要显示的业务状态直接写 this.model.<字段>；页面 @Local 只留纯界面态。
2. 规格或决策说明某模型要被其他功能或页面读写时，页面从一开始就用 AppStorageV2.connect 取同一个共享实例，不在页面里 new 私有实例。
3. 确需在返回时执行一次性动作（如消费反馈），先确认页面是 NavPathStack 中的页面还是 Navigation 首页内容，再选在该挂载方式下会触发的回调，不依赖页面重建。

## 可选检查

- 对返回后的显示有疑问时，在设备上走一遍“子页修改共享模型 → 返回原页”，dump 原页的高亮、计数与反馈文案，确认与模型一致。
