# process/task-handoff

跨任务移交：留给别的文件、切片或编排者兑现的工作如何登记、分派与接收

[上一级](../index.md)

## 本级经验

- [编排者推进阶段或派发下游前，逐项兑现规范划给自己的步骤和子任务点名给别人的事项](lesson-5754b7be28238f1bdf57.lesson.md)
  - 时机：执行编排阶段，子任务返回后决定推进到下一阶段，或为下游切片写派工时
  - 情境：执行规范把某些收尾步骤（如资源阶段之后的应用身份落地）留给编排者亲自调用；子任务返回的 open_questions、风险项或文件头说明，把某项工作指给另一个阶段、切片或编排者本人。
- [要靠其他文件或任务补调用点才生效的功能，登记成带负责方和验证方式的移交项，不只写在注释里](lesson-4f81eeea17b94190c2de.lesson.md)
  - 时机：页面转换、切片实现或接线阶段，本文件的功能需要别的文件补调用点、或要由后续步骤补值才完整时，以及读到上游留给本文件的移交说明时
  - 情境：写码者确认某项行为在当前文件里无法闭合（例如非入口组件的平台回调要由入口页转发、脚手架身份值留给后续步骤），工程提供了移交登记约定（如带 owner/what/verify 的 HANDOFF 标记、返回信封中的字段）；或接线者在上游文件头读到要求本文件转发的说明。
