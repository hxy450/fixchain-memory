# 要靠其他文件或任务补调用点才生效的功能，登记成带负责方和验证方式的移交项，不只写在注释里

ID：`lesson-4f81eeea17b94190c2de` · 版本：1

[本主题](index.md)

## 何时使用

页面转换、切片实现或接线阶段，本文件的功能需要别的文件补调用点、或要由后续步骤补值才完整时，以及读到上游留给本文件的移交说明时

## 适用情境

写码者确认某项行为在当前文件里无法闭合（例如非入口组件的平台回调要由入口页转发、脚手架身份值留给后续步骤），工程提供了移交登记约定（如带 owner/what/verify 的 HANDOFF 标记、返回信封中的字段）；或接线者在上游文件头读到要求本文件转发的说明。

## 原因

文件头注释和报告里的开放问题不进入任何检查：编译、结构审计都会放行，后续编排与复核也容易按“已处理”理解。来源中页面转换者已从 SDK 注释核到平台限制，也起草了指向壳页切片的移交，落盘时以“移交难以机械验证”为由删掉，只留一段文件头说明；接线切片读到这段说明后仍按原样嵌入，缺陷一直留到设备判定。另一例资源任务在返回里只写“归属后续步骤”，没有逐项列出保留的脚手架键。

## 做法

1. 按工程的移交约定登记：写明负责方（具体切片或阶段）、要补什么、如何验证；验证断言难写时改用切片级断言（如 slice:N），移交本身保留。
2. 按分工保留应由别人处理的值时，在返回里逐项列出保留的键或片段，以及应接手的步骤。
3. 接线时读到上游文件要求本文件转发或补调用点，就在本文件实现；派工不允许或实现不了时作为阻塞项上报，不按“其余不动”默认跳过。
