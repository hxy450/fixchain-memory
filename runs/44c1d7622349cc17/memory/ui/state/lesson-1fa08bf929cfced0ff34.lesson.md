# 源端用带兜底的访问器取显示值时，目标调用已移植的等价访问器，不改读原始字段再自拟兜底

ID：`lesson-1fa08bf929cfced0ff34` · 版本：1

[本主题](index.md)

## 何时使用

功能接线阶段，把源端刷新函数里的显示赋值（如 text = Manager.getX()）翻译成目标组件状态时

## 适用情境

源端在某一分支调用带空值兜底的访问器（如登录态空昵称返回默认昵称），另一分支才显示占位文案；目标侧会话或仓库层已移植同名兜底方法，组件状态是普通字段。

## 原因

访问器的方法体才是显示语义（空值兜底、游客与登录态分流）；改读原始字段后，接线者往往用手边的占位文案补空值，把另一分支的文案挪进本分支。来源中接线者读到了源端访问器调用和目标等价方法，仍写成“原字段非空否则显示未登录占位”，已登录用户看到“点击登录”。

## 做法

1. 源端调用的是访问器而非字段时，目标同一分支调用已移植的等价访问器；占位文案只放在源端对应的分支。
2. 先读访问器方法体的空值兜底，再按“已登录 + 空值”等组合逐分支核对目标表达式的结果与源端一致。
3. 访问器返回 ResourceStr 而状态是 string 时，按工程已有方式解析资源（宿主 context 判空同时排除 undefined 与 null），不因类型不合回退成占位字符串。
