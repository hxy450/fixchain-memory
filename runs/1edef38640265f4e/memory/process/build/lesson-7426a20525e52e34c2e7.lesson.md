# 编译检查按完整构建结果判定：读全 ERROR 列表与 COMPILE RESULT，构建失败只记 FAIL，不以“仅警告”“部分通过”放行

ID：`lesson-7426a20525e52e34c2e7` · 版本：1

[本主题](index.md)

## 何时使用

验证阶段执行编译检查并决定是否标记阶段完成时；编译修复循环查看构建输出时

## 适用情境

hvigor 构建输出重定向到文件，WARN 常排在 ERROR 之前；修复循环只截取错误文件前若干行；验收规范规定编译通过才 PASS、否则 FAIL 并继续修复循环。

## 原因

只看前 N 行会只见警告、漏掉错误；把 BUILD FAILED 记成“部分通过/仅警告”并标记阶段完成，失败构建就进入交付，用户首次运行即遇编译错误。来源中验证阶段读到 FAILURE 与“编译失败”，仍把编译检查写成部分通过并进入下一阶段；页签重载错误和登记页缺 @Entry 两处错误都留到了用户侧。

## 做法

1. 按 ERROR 过滤，或读 COMPILE RESULT 汇总（如 ERROR:6 WARN:7）与 BUILD SUCCESSFUL/FAILED 结论，逐条列出剩余错误。
2. 构建失败时编译检查只记 FAIL 并列出剩余错误，继续修复循环；不以警告为由记为部分通过，也不标记阶段完成。
