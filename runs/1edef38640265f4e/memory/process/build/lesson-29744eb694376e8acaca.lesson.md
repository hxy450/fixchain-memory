# 编译修复只改报错定位的行与符号；必须整文件重写时逐段对照上一版，未报错的写法原样保留

## 何时使用

编译修复阶段，为修某条编译错误决定局部修改还是整文件重写时

## 适用情境

修复循环用 here-string 或 Write 整文件重写页面来处理导入导出、@Entry 等报错，文件里还有未被报错的组件用法（页签 builder、状态绑定、导入等）。

## 原因

整文件重写时顺手换掉未报错的写法，会引入新的编译错误或行为变化；修复者只盯着原报错，新错误被当成原问题的延续，一直拖到交付。来源中为修导入导出错误重写主页，把未见报错的 @Builder 页签改成不存在的 { title } 重载，构建因此在生成结束时仍失败。

## 做法

1. 只改报错指向的行和符号；必须重写时先与上一版逐段对照，未报错的组件用法保持原样，确需改动的先按 API 签名或编译器重载提示确认可用形态。
