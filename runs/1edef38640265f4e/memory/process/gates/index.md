# process/gates

结构检查与自动修复的收口：会改写源码的自愈脚本运行后审阅改动，按关键字判定的检查要真实落实而不是迎合检查器，功能对齐与验收结论以代码中的实际落点为准

## 本级经验

- [修复安全区等按关键字判定的结构检查时逐页落实实现，不用含检查关键字的注释让检查通过](lesson-f6b95d7d6d0159cb0436.lesson.md)
  - 时机：结构修复阶段处理安全区 Layer 3 等按关键字或 grep 判定的检查失败时
  - 情境：结构检查按关键字或 grep 判断页面是否处理了安全区等要求；修复者面对多页 FAIL，工程有共享窗口模型（顶部/底部避让值），skill 要求每个全屏 NavDestination 页实际加 padding。
- [功能对齐与验收结论逐项以代码落点为准：按规格验收项与导航出口检索实际组件和调用，空回调与只含注释的回调不算实现](lesson-9147be4d87153de9c5b6.lesson.md)
  - 时机：验证阶段核对功能完成度，或实现、返修后向用户报告“已实现/已对齐”时
  - 情境：验证检查只 grep TODO: 与占位登记表；实现者或返修者按功能点列对齐表并逐项打 ✅；规格写有验收条目、页面导航出口与启动触发条件。
- [运行会改写源码的自愈脚本后先审阅其改动；异常尺寸或与已有显式尺寸重复的追加要回滚](lesson-bdb97da6a6eb8d68435f.lesson.md)
  - 时机：结构收口阶段运行含图标尺寸自愈等会改写 .ets 的检测管线、决定是否接受其结果时；构建或验证阶段读到同一组件出现两组尺寸修饰时
  - 情境：迁移管线在收口时自动运行图标尺寸自愈（icon-sizing 一类），会直接给 .ets 中的 Image 追加 .width/.height；页面 Image 已在同一行链式写好尺寸（如 '18vp'、'100%'），资源可能是 jpg 启动图标。
