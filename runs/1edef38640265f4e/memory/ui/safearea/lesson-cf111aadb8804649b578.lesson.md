# getWindowAvoidArea 与 windowRect 的数值是 px：写入供 padding 消费的窗口模型前先 px2vp

ID：`lesson-cf111aadb8804649b578` · 版本：1

[本主题](index.md)

## 何时使用

沉浸式安全区实现阶段，在 EntryAbility 或窗口服务里把避让区、窗口尺寸写进共享窗口模型时

## 适用情境

目标用 setWindowLayoutFullScreen(true) 全屏，EntryAbility 通过 getWindowAvoidArea 取状态栏、导航条高度，通过 getWindowProperties().windowRect 取窗口尺寸，写入 AppStorageV2 共享的窗口模型；各页把这些值直接放进 .padding()/.height()，按 vp 解释。

## 原因

避让区 Rect 与 windowRect 的数值单位是 px，ArkUI 数字尺寸默认是 vp；原样写入后，高密度屏上的避让量会放大数倍。来源中修复者首次写入时注释已写“这是物理像素、需换算”，读到工程内页面已用 uiContext.px2vp 的样例后，反而删去换算占位，把注释改成“按 vp 消费”，也没写窗口宽高。

## 做法

1. 在写入窗口模型的边界统一换算：const ui = mainWindow.getUIContext()；top = ui.px2vp(avoid.topRect.height)，bottom 与窗口宽高同理；模型注释标明字段为 vp。
2. 一时取不到 UIContext 时保留 px 字段并上报，不把 px 值写进声明为 vp 的字段。
