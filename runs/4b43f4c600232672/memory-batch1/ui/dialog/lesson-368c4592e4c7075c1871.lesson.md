# 源端 XPopup/DialogFragment 真弹窗迁成可关闭的系统弹窗，不以页面 @Local 可见性叠层充当

ID：`lesson-368c4592e4c7075c1871` · 版本：1

[本主题](index.md)

## 何时使用

迁移实现、弹窗恢复与宿主接线阶段，为 Android 真弹窗（DialogFragment、XPopup Center/Attach 类）确定 ArkUI 承载形态，或为已有弹窗补触发、宿主时

## 适用情境

源端通过 DialogFragment、XPopup CenterPopupView/AttachPopupView 等在当前 Activity 上弹出提示、升级、菜单或锚点气泡，点击遮罩或返回即关闭；目标工程里已有以 @Local visible/visibility 或 if 条件渲染的 Stack + 遮罩叠层，或派工只写“接到现有弹窗”“恢复可关闭的页面内弹层”。

## 例外与边界

- 项目决策明确采用页内浮层，且浮层已实现遮罩点击、返回键与页面离开关闭并只回调一次

## 原因

页面叠层只在宿主页 Stack 里条件渲染，遮罩没有点击处理、宿主不拦返回键时，空白点击与返回都关不掉；把它当作现成弹窗接线，或以“宿主化、恢复关闭回调”为完成标准，会让同一批次里部分弹窗改成真弹窗、其余仍是叠层。来源中执行者写前已读到形态选择表（CenterPopupView 对应真弹窗）与 Android 端的真弹窗实现，同一补丁把评分改为 showCustomDialog，通知提示与升级却只置 visible 标志条件渲染；另一条链是编排者收到用户“xpopup 弹窗都是页面组件、关不掉”的反馈，却把交接写成“恢复页面内弹层的关闭与回调”，下游据此保留了颜色选择叠层。

## 做法

1. 先按源端类定形态：居中类（DialogFragment、CenterPopupView）用 UIContext.getPromptAction().openCustomDialog 或项目已采用的弹窗库（如 @pura/harmony-dialog 的 showCustomDialog）；锚点类（AttachPopupView）用 bindPopup 或按锚点全局坐标定位的自定义弹窗；@ComponentV2 页面不用 CustomDialogController 承载 V2 组件。
2. 目标里已有 @Local 可见性 + Stack/遮罩的实现视为待替换对象：接线时改为真弹窗 API，打开遮罩点击与返回关闭（如 autoCancel/backCancel），在 onDidDisappear 中单次清理状态，页面 aboutToDisappear 时主动关闭残留弹窗。
3. 规划或交接弹窗批次时把“真弹窗、可关闭”写成形态契约，对清单里的每个弹窗记录承载形态；同一批次已有弹窗改用真弹窗 API 时，把其余仍是条件渲染的逐个改掉，不以补可见性赋值收尾。
