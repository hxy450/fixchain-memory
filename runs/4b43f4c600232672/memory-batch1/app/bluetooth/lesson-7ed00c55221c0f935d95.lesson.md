# 封装 startBLEScan 等声明为 void 的同步系统接口时查 @throws，在服务层 try/catch 收敛为失败状态，页面检查结果并复位进行中状态

ID：`lesson-7ed00c55221c0f935d95` · 版本：1

[本主题](index.md)

## 何时使用

服务层与页面实现阶段，封装 BLE 扫描等可能同步抛 BusinessError 的系统接口，并决定页面的失败态时

## 适用情境

目标端用 @ohos.bluetooth.ble 的 startBLEScan/stopBLEScan 等在 d.ts 中声明为 void 的同步接口；源端用 BluetoothState、蓝牙关闭恢复卡、扫描启动异常类等显式建模适配器关闭与扫描失败；决策要求失败降级、不崩溃。

## 原因

签名返回 void 不代表不会失败：蓝牙关闭时 startBLEScan 同步抛 BusinessError（设备实测 2900003），未捕获的同步异常会让进程被杀。来源中生成者查 SDK 时只取了函数签名行，没有取错误码说明；自己写下的“失败降级、不崩溃”决策和源端的失败建模都没有落到扫描入口，页面也在调用前就置为扫描中且不检查结果。

## 做法

1. 查系统接口时连同 d.ts 的 @throws 错误码段一起读；声明为 void 的同步调用在服务层 try/catch，收敛为返回值或可查询的错误状态，不让 BusinessError 冒泡到点击回调；stop、清理类调用同样加保护。
2. 源端有适配器关闭、扫描启动失败等失败建模时，在目标服务中映射为可查询的状态或错误，页面按页面规格的对应分支（如蓝牙关闭恢复卡与源端文案）展示。
3. 页面调用可能失败的服务时检查返回结果，失败时复位“扫描中”等进行中状态并显示错误。
