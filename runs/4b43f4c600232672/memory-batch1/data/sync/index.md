## 本级经验

- [同步调度保留源端每次触发都会执行的语义：合并在途任务要补跑尾随请求，失败队列按源端选取条件重推](lesson-cfe552e1b20080212ce9.lesson.md)
  - 时机：数据同步迁移的规格提取、调度实现与复核阶段，确定多次同步触发的并发语义与失败项重试范围时
  - 情境：源端每次同步触发都启动新任务并在互斥锁后排队执行（如协程 launch + Mutex.withLock，锁内先推送队列再拉取），待推送队列按资源类型而非同步状态选取；目标端用单一同步服务和 Promise 串行队列统一调度全量同步、定向拉取与状态推送；已有规格可能写着“并发触发复用当前任务”。
  - 例外：源端本身在同步进行中直接丢弃新触发，且没有依赖其推送结果的后续读取
- [同步进度与失败事件按整批发布：补跑多轮时终态只在最后一轮后发一次，开始进度保留源端首次同步门控](lesson-34f35851208470602570.lesson.md)
  - 时机：同步调度修改与同步迁移阶段，决定同步协调器在何处发布开始进度、结束/失败终态，以及首页据此显示进度或错误提示时
  - 情境：目标由统一同步服务向首页发布 progress/失败事件，同一批同步可能合并请求或补跑多轮；首页收到结束事件就查询待同步/错误队列并显示错误提示；源端开始进度事件有前置条件（如已登录且空间 cursor 为 0 才算首次同步）。
