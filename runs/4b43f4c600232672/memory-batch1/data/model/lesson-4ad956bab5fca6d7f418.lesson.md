# 查询层派生完成态等状态时逐分支移植源端判定函数，审计摘要只作线索，不用更严的重算覆盖已有结果

ID：`lesson-4ad956bab5fca6d7f418` · 版本：1

[本主题](index.md)

## 何时使用

数据层实现或复核阶段，在列表查询中为记录派生完成态、完成人数等状态时

## 适用情境

源端按完成模式（如任一成员/全部成员）、是否重复事件和发生日期组合判定完成态；目标在查询仓库里重算该状态，手头有审计或交接摘要（如“按模式 + 发生日 + 当前用户派生”）以及仓内已有的判定实现。

## 原因

摘要把判定概括成一句话时会漏掉分支豁免（如非重复事件不限发生日），用它重写的查询层计算替换已有结果，会让部分记录一直显示未完成。来源中复核者写前读回的旧判定保留了“非重复且任一成员完成即完成”的豁免，与源端判定一致；它仍按“发生日过滤 + 只收有效用户 ID”重算并替换了已有完成标志，非重复任一成员事件与用户 ID 为空的完成记录都不再算完成。

## 做法

1. 重算前定位源端判定函数及其过滤、解析辅助函数，逐分支移植：哪些模式或事件类型按发生日匹配、哪些按记录 ID 匹配全部状态；“是否完成”与“完成人数”分开计口径（完成 = 存在任一已完成记录，人数才按非空、去重的用户 ID 统计）。
2. 仓内已有实现与摘要冲突时以源端规则裁决，不用更严格的重算覆盖；为每个判定分支各备一条回归数据（非重复且记录日期不同、用户 ID 为空、重复事件按实例日期）。
