# 依附式弹窗（AttachPopup）的宿主按锚点视图所在页面确定：提示挂在锚点页、按锚点实测坐标定位，弹出条件包含锚点可见

ID：`lesson-29f62d177a17d08b4e4f` · 版本：1

[本主题](index.md)

## 何时使用

迁移审计与实现阶段，判定依附式弹窗的宿主归属、改写触发它的子页逻辑时

## 适用情境

源端弹窗由子 Fragment 触发 show，但 atView 是父 Fragment 标题栏里的按钮，且只在该按钮可见、一次性标记未写入时显示；目标端已有一个画在子页内部、按固定边距定位的同文案浮层。

## 原因

按“哪个类调用了 show”归属，会把父页锚点提示当成子页内联实现：浮层坐标脱离锚点，锚点不可见时也可能出现，提示状态成了子页私有副本，其他逻辑还会依赖它。来源中审计者读到了 atView 锚点与可见条件，仍把子页内固定边距的气泡判为“已内联等价、可删”，随后又在子页用该私有状态守卫其他引导。

## 做法

1. 以 atView 锚点所在页面为宿主，在该页用锚点实测坐标（组件区域或全局位置）定位箭头与气泡，不在触发它的子页按固定边距绘制。
2. 把源端弹出条件逐项映射：锚点可见（如按钮只在特定状态显示）、一次性标记的读取与关闭时写入；锚点在目标端从未变为可见时，先修锚点的驱动链，再判定提示是否等价。
3. 子页需要依赖“提示是否显示”时，经回调或参数读取宿主页状态，不引用子页私有副本。
