# 会从半模态内压入 Navigation 页的弹层用 SheetMode.EMBEDDED 并传宿主 targetId，不照搬选择器模板的 OVERLAY

ID：`lesson-97bf3cf56f55715f7e42` · 版本：1

[本主题](index.md)

## 何时使用

界面实现或弹窗改造阶段，把页面内弹层改成 bindSheet/openBindSheet 系统半模态、确定 SheetMode 与挂载节点时

## 适用情境

弹层内条目会通过 Navigation/NavPathStack 压入新页面（如节日详情、订阅详情），要求跳转时不关闭弹层、新页面盖住弹层、返回后弹层仍在；目标用 UIContext.openBindSheet 或基于它的弹窗库（如 showBindSheet），手头参考的是不从弹层内跳页的选择器类半模态模板。

## 例外与边界

- 弹层内只有选择或确认、不会打开页面，或产品允许跳转前先关闭弹层

## 原因

OVERLAY 半模态显示在窗口顶层，高于所有 Navigation 页面，从弹层内压栈的新页面会显示在弹层下方。EMBEDDED 挂在 Page/NavDestination 节点上，但 openBindSheet 只有传入 targetId 时 EMBEDDED 才生效，未传会回退为 OVERLAY。来源中改造者照抄滚轮选择器模板的 OVERLAY，配置接口也不含 targetId；第一次修复只把 mode 改成 EMBEDDED，用户实测仍被覆盖，读到 openBindSheet 声明后才补上 targetId。

## 做法

1. 改造前列出弹层内会触发的跳转；会压入 Navigation 页且要保留弹层时选 SheetMode.EMBEDDED，不沿用选择器模板的 OVERLAY。
2. 把宿主 Page/NavDestination 内组件的 uniqueId 作为 targetId 纳入弹窗配置接口并由调用方传入（如 this.getUniqueId()）；用封装库时确认它把 targetId 透传给 openBindSheet。
3. 复用已有半模态 Controller 接入新宿主时，核对其 SheetMode 与挂载参数是否匹配本页的跳转动作。

## 可选检查

- 不确定时在真机从弹层内打开页面再返回，确认新页面在弹层之上、返回后弹层仍在。
