# 写应用壳契约与实施计划时枚举源导航模块的全部入口能力（含深链解析与 scheme 注册），不做的登记 skip

ID：`lesson-3348c580951ef82a9737` · 版本：1

[本主题](index.md)

## 何时使用

规格与计划阶段，编排者撰写应用壳/导航的共享契约、实施计划或压缩前交接摘要，确定路由表、启动入口与 module 配置要承载哪些源端导航能力时

## 适用情境

源导航模块除路由表和顶层 Tab 外，还含深链路由器（解析器类、深链基址常量、Manifest 的 scheme 或 App Links intent-filter）；目标用 Navigation + NavPathStack 字符串路由重建应用壳；契约先于 feature spec 写出并被后续实现重读，会话中途可能发生上下文压缩。

## 原因

契约和交接摘要是后续实现最常重读的输入；源端能力在契约里被概括掉、又没有 skip 登记，实现与验证都不会再想起它。来源中编排者读到了深链路由器文件、深链基址常量和 intent-filter，决策账本也只把深链参数改为字符串键，契约却把应用壳记为 simple、锚点只列路由表与 Tab，压缩前的交接只列 Tabs 与权限；随后写出的路由表、入口 Ability 与 module 配置都没有深链。

## 做法

1. 写契约或实施计划前列出源导航模块的全部文件与入口能力（路由表、顶层 Tab、返回栈、深链解析与基址常量、Manifest 的 scheme 与 App Links），逐项写成契约锚点和目标符号；不做的写进决策账本 skip。
2. 决策只改变某项能力的形态（如深链参数改为字符串键）时，契约与计划保留承载它的入口：URI 解析函数、入口 Ability 的 onCreate/onNewWant 投递、module.json5 skills 的 uris；可能压缩上下文时，把这些入口写进交接摘要的剩余文件清单。
