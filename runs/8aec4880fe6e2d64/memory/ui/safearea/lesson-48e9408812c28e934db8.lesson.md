# Tab 宿主按各 Tab 源 Fragment 的沉浸设置分别处理顶部安全区，Activity 只加在底栏的 padding 只加到 tabBar

ID：`lesson-48e9408812c28e934db8` · 版本：1

[本主题](index.md)

## 何时使用

界面实现与规格阶段，实现 MainActivity/Tab 宿主的内容区内边距，以及转换作为 Tab 子组件的 Fragment 的顶部布局时

## 适用情境

Android MainActivity 只给底栏容器加内边距，ViewPager 全宽；部分 Tab 的 Fragment 调用 ImmersionBar.titleBarMarginTop/fitsSystemWindows 让头图延伸到状态栏，其余 Tab 不沉浸；目标宿主可能给整个 Tabs 统一加顶部安全区和左右 padding，页面规格按 page_type（sub_component）自动标记“无需沉浸”。

## 原因

宿主统一加顶部 padding、页面规格又按页面类型推断不沉浸，需要延伸到状态栏的 Tab 头图就被压到状态栏下方；把底栏的左右 padding 加到整个内容区会让每个 Tab 两侧留白；子页再加一次安全区就重复消费。来源为同一应用：天气与 15 日 Tab 的源 Fragment 都用 ImmersionBar，宿主却对所有 Tab 加 windowTopPadding 和左右 5 的 padding，转换者按规格报告“跳过沉浸”且没有登记宿主交接，后续会话逐个 Tab 排除这段 padding；城市页在宿主已加底部安全区后又加了一次；城市 Tab 的规格同样被标为不需沉浸，宿主统一内缩、子组件又跳过沉浸，结果谁都没有让该 Tab 延伸到状态栏。

## 做法

1. 宿主内容区不统一加状态栏 top padding：逐个查 Tab 源 Fragment 是否用 ImmersionBar、titleBarMarginTop、fitsSystemWindows 延伸到状态栏，沉浸的 Tab 由子页承接状态栏高度（标题下移状态栏高度加源 margin，并按源端设置状态栏图标颜色）。
2. Activity 只加在底栏容器上的 padding 只加到 tabBar，内容区保持 ViewPager 的全宽。
3. 源码的沉浸信号与规格的自动判定冲突时以源码为准，在报告中列出，并把“宿主取消该 Tab 顶部 padding”写成交接项。
4. 子页写前查看宿主已处理了哪些安全区，同一边界只消费一次。
