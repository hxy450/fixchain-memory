# 规格写法与写前读到的源码、主题或映射参考冲突时，按源端语义实现并标注冲突

ID：`lesson-7a065e8fe384b8c462cc` · 版本：1

[本主题](index.md)

## 何时使用

页面实现阶段，规格给出的容器、样式或类型写法与写前读到的源码、主题或映射参考不一致时

## 适用情境

实现者同时读到页面规格与源布局、主题文件、映射参考或 SDK 声明，规格的具体写法与源端可观察行为或参考映射不符，而规格对该处只有概括性理由（如“无相对约束需求”“零硬编码色值”）或没有理由。

## 例外与边界

- 规格或决策记录（如 decision ledger）对该差异写明了有意取舍的理由，此时按该决策实现

## 原因

规格是对源端的概括，可能把语义写错；实现者以“按规格”为由保留冲突，偏差就原样进入代码，直到编译门或视觉比对才暴露。来源三例中，实现者写前都读到了与规格相左的输入（映射参考 ConstraintLayout → RelativeContainer、主题紫色与已迁移色令牌、类型映射 String → String），其中按钮一例在推理中已注意到颜色差异，最后都照抄了规格。

## 做法

1. 写码前对冲突点逐一取舍：规格只有概括性理由时，以源端可观察行为为准实现；涉及 API 签名的，以本地 SDK 声明为准。
2. 在转换报告里列出与规格不同的每一处及依据，供规格阶段回改；不要为了与规格一致而删掉已确认的源端语义。
