# 编排者推进阶段或派发下游前，先核对子任务的约定产物和回报里的待接事项，再逐项兑现规范划给自己的步骤与点名给别人的事项

[本主题](index.md)

## 何时使用

执行编排阶段，子任务返回后决定推进到下一阶段，为下游切片、接线任务写派工时，以及处理巡检报告中的阻断项时

## 适用情境

执行规范把某些收尾步骤（如资源阶段之后的应用身份落地）留给编排者亲自调用；子任务返回的 open_questions、风险项或文件头说明，把某项工作指给另一个阶段、切片或编排者本人；也包括后台子任务回报 completed，但约定产物（如清单 JSON）没有落盘、回报文字被截断，或回报提到一个需要在别处调用的入口（如网络初始化函数）却没写调用点；以及巡检报告列出多个 BLOCKER，编排者派发修复失败（如线程上限）或只修其中一部分。

## 原因

这类承接项只存在于规范段落、返回文字或代码注释里，编译、结构审计等门都不检查；编排者直接推进，这项工作就没有执行者。来源两例出自一个应用：编排者读过“资源迁移后由主线程调用应用身份落地”的规范并列进计划，收到资源任务“最终装配归属该步骤”的返回后仍直接进入页面转换，之后页面转换者在 open_questions 点名脚手架 label，也没有处理；页面转换者把返回键转发交给“入口装配或后续接线决定”，编排者没有写进任何后续派工。另一应用里，清单子任务只回了半句就标 completed，约定产物没写出，编排者注意到产物缺失仍推进规格；网络层子任务回报“网络初始化入口”并写“无待接线项”，编排者没核调用点，就在后续派工写“已实现，无需重复”；派发页面接线任务时没附对应页面规格里的导航关系，接线者漏掉了成功后跳主页。第三个应用里，网络巡检把空网络配置判为阻断，派修因线程上限失败后没有重试，编排者就地修了同一报告里的其他两项，阻断项保留到交付后。

## 做法

1. 推进阶段前，按该阶段规范列出划给编排者的子步骤，逐项确认已实际调用；没有执行的先执行，或在报告里登记为阻断项。
2. 收齐子任务返回后，把 open_questions、风险项里点名其他负责方的条目逐条分派：写进对应切片的派工正文（附原文与验收方式），或登记为待办；不随阶段推进丢弃。
3. 派发接线任务时，若上游说明要求该任务在壳页或调用点补转发，在派工里写明要实现的内容，或要求无法实现时上报阻塞；把对应页面规格的导航关系与状态接口一并交给接线者；派工带“其余不动”之类约束时，把这项移交列为例外。
4. 子任务回报完成后，先确认约定产物文件存在、回报文本完整；缺产物或结果被截断时续跑该任务，再进入依赖它的步骤。回报提到需要调用的入口（初始化函数、注册函数）时，grep 调用点确认已接入，再把该层记为完成。
5. 处理巡检报告时，派发修复失败（如线程上限）就重试或就地修复；关闭报告前逐项核对每个 BLOCKER 都已落地，不只修同批中顺手的项。
