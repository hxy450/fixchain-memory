# 视觉修复前把截图尺寸差折算成 vp，与源布局值和目标当前值对照；目标已等于源值时不放大固定尺寸

[本主题](index.md)

## 何时使用

视觉校验与修复阶段，根据双端截图差异撰写尺寸类工单，并决定是否修改页面固定高度、间距时

## 适用情境

源端基线截图与目标截图来自不同设备或屏幕密度，并排对比显示目标主内容“偏小”或“偏上”；目标页的主要区块已按源布局 dp 字面值写入固定高度与 marginTop，并与底部 Tab 共享有限的纵向空间。

## 原因

跨设备截图的像素比例差包含密度与逻辑宽度差，不等于 dp 值写错；只凭观感把已等于源值的固定尺寸放大，累计高度会超出可用空间，底部内容被 Tab 遮挡。来源中视觉协调者没有把差异折算成 dp，也没有与源布局值对照，就按“整体缩小 10%–15%”把地图区、主按钮、统计卡放大并继续加大间距；之前的巡检报告已写明这些尺寸与源端一致。

## 做法

1. 写尺寸工单前，按两端设备各自的密度/逻辑宽度把截图差异折算成 vp，与源布局 dp 值、目标代码当前值三方对照；目标值已等于源值时，改查视口、安全区或容器层级，不写“对齐固定高度”，源码定位不能留空。
2. 拟改值偏离源布局值时，要有源码或资源固有尺寸依据，不用放大常量补偿截图比例。
3. 放大元素前累计所有固定高度与 margin，确认底部内容仍位于 Tab 之上。
