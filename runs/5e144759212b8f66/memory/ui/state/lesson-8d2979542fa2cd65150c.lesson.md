# 随状态变化的控件参数不作 @Builder 值参，改为内联读取状态或用 @ComponentV2 子组件的 @Param

ID：`lesson-8d2979542fa2cd65150c` · 版本：2

[本主题](index.md)

## 何时使用

界面实现阶段（页面转换与公共组件抽取），为源端带状态参数的子控件或多个同构开关行选择 ArkUI 复用写法时

## 适用情境

源端 Compose 子 Composable 以当前状态算出的值作参数（如 enabled = count > 1、颜色随选中态变化），或 Android 页面有多个同构的开关行、各自持有状态；目标 ArkUI 组件需要在状态变化后刷新 enabled、颜色、开关图标等属性，准备把子控件或开关行抽成共享的 @Builder 方法。

## 例外与边界

- 传入 @Builder 的只有文案、尺寸等在该组件生命周期内不随状态变化的值

## 原因

Compose 每次重组都按当前状态重算实参；ArkUI @Builder 按值传入的参数是调用时刻的快照，状态变化后不会刷新 @Builder 内的 UI。来源一：边界步进按钮在状态越过边界后仍保持禁用、点击无效。来源二：蓝牙页两个独立偏好开关共用一个成员 @Builder，各自的 @Local 状态作值参传入、内部据此画开关并接无参回调；后来把复用开关组件放进同一 Builder，isOn 仍取值参，运行时出现点一个开关影响另一个，拆成两个直接绑定各自状态的组件行后才消除。两例中该规则都写在组件构建 skill 的 @Builder 复用一节，但写者要么前置清单里没有该 skill，要么只按固定行数或在截断的批量读取里读到了它的前段。

## 做法

1. 状态派生的 enabled、selected、颜色、开关值等参数，用内联属性链直接读 this 上的状态，或抽成 @ComponentV2 子组件用 @Param 接收；@Builder 值参只放不随状态变化的值。
2. 多个开关行共用外观时，每行在 build 中直接写复用组件并绑定自己的状态（如 isOn: this.<该开关状态>），不经共享 @Builder 转发状态值。
3. 写完 grep `@Builder` 签名与调用处，实参含 `this.<状态>` 表达式的即为风险点，改写后再落盘。

## 可选检查

仅在适用条件不确定、与当前输入冲突或需要验证关键假设时按需执行；优先复用已有证据和正常测试。
不因读取本条经验而额外启动验证流程；项目原有必需测试照常执行。

- 对刷新有疑问且能上设备时，把相关状态切过边界再切回，用 dumpLayout 核对控件的 enabled 与颜色；多个开关共用模板时，只点 A 确认 B 不变，重进页面后两者各自保持。
