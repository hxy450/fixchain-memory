# 同步读取改成异步 initialize 后，失败分支要复位状态并让页面离开加载态

ID：`lesson-338f11844f0010e46bc3` · 版本：1

[本主题](index.md)

## 何时使用

功能实现阶段（ViewModel 与页面接线），把源端同步读取的设置或数据改成异步加载，并给页面加“加载完成前不显示或不可交互”的门时

## 适用情境

源端在首帧前用 SharedPreferences 等同步接口读取（缺键用默认值），界面没有加载态或失败态；目标端改为 async 读取，ViewModel 暴露返回 Promise 的 initialize()，页面在 aboutToAppear 中调用，并用“已加载”标志在 LoadingProgress 与正式内容之间切换。

## 原因

同步改异步后多出一条 reject 路径，规格和源码都不会描述它；只写 then 的加载门在失败时永远停在加载态，若 initialize 在 await 之前就置 initialized=true 且失败不复位，重试也不会重新加载。来源中写码者已读到会抛错的异步偏好包装类，规格状态机只有“已载入设置”一条前置，巡检建议加加载门时也没提失败出口；要求 try-catch 兜底的两份 skill 因批量读取截断没有进入上下文。

## 做法

1. initialize 用 try/catch 包住读取与后续初始化，失败时复位“已初始化/进行中”标志并把错误交回调用方，不要在 await 之前置标志而失败不复位。
2. 页面对 initialize() 同时写 then 与 catch，失败必须离开加载态：显示错误与重试入口，或按源端行为用默认值继续。
3. 写源码理解笔记时把“源端同步、目标端异步”列为差异，至少覆盖加载期交互与加载失败两项；巡检或评审建议加加载门时，同时写明失败出口。
