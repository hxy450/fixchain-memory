冷启动链路：闪屏路由、各去向页的初始化请求、登录态组合在哪里处理、首屏等待异步装配完成的就绪门，首启尚无已选项时的状态，以及加载页的可见时长

## 本级经验

- [源端首启无已选项、需先选择才进主界面时，目标定义“无已选项”状态：不以空编码请求，冷启动验证从清空数据开始](lesson-95aa64d6b0a5c041d326.lesson.md)
  - 时机：规格提取与数据层实现阶段，迁移持久化的已选项持有者（如已选城市）并确定首次进入、尚无已选项时的行为时；真机验证依赖该项的页面时
  - 情境：源端持有者从本地存储恢复、初始可为空，以 hasInit 一类标记首启，首启先选择再进入主界面；数据请求以首个已选项编码为参数；目标入口与初始化流程不可改，或持久化只在进程内。
- [用户要求“和源端一样有加载页”而目标初始化极快时，把首启最短可见时长写进验收或交用户决策](lesson-41bb62cd13921e4eedde.lesson.md)
  - 时机：启动页的规格、计划与实现阶段，确定首次冷启动加载页的可见时长时
  - 情境：源端闪屏继承外部 SDK，可见时长由 SDK 决定；目标初始化只读本地配置、几乎瞬时完成；用户要求首次启动与源端一样看到加载页。
  - 例外：用户或决策明确要求直接进入主页、不显示启动页
- [迁移启动链路时打开闪屏各去向页的初始化入口，列出冷启动请求与登录态组合的处理位置；源端推迟到主页处理的也要迁到位](lesson-8c24f05ec8df45401482.lesson.md)
  - 时机：启动链路迁移与功能切片划分阶段，确定已登录、未登录冷启动要执行哪些请求，以及各登录态组合去向哪里时
  - 情境：源端闪屏只做路由（如已登录 → 主页、未引导 → 引导页、无 token → 静默游客登录），刷新 token、拉配置等请求写在主页 Activity 的初始化方法里；token 失效等状态靠进入主页后的刷新与拦截器踢登处理；目标端用启动 ViewModel 承载闪屏路由。
- [首屏依赖异步装配的服务时，用可等待、失败可复位的就绪门，await 后再计算路由；读到空服务不静默沿用默认路由](lesson-ccbf0a7f5b1809ef5880.lesson.md)
  - 时机：入口装配与启动链路接线阶段，把启动服务改为由 EntryAbility 异步装配到组装根、首屏从组装根取依赖并决定下一页时
  - 情境：EntryAbility.onCreate 以不等待的方式启动异步装配（先 await 数据库等初始化再写服务槽），随即 loadContent 入口页；首屏在 onReady 同步读取服务槽并按启动决策路由；启动 ViewModel 有指向首屏自身的默认路由。
