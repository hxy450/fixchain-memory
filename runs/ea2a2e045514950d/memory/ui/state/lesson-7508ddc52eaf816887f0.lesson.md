# AppStorageV2/PersistenceV2 的 key 只用字母、数字和下划线，不沿用 kebab-case 文件名

ID：`lesson-7508ddc52eaf816887f0` · 版本：1

[本主题](index.md)

## 何时使用

状态管理实现阶段，为 AppStorageV2.connect 或 PersistenceV2 共享状态类确定 key 字符串，或复用工程已有 key 时

## 适用情境

ArkTS V2 工程以 AppStorageV2.connect(Cls, key, creator) 跨页面共享 @ObservedV2 状态；模块文件名采用 kebab-case（如 window-model.ets），状态管理 skill 只给出签名和一致性示例；编译期不校验 key 内容。

## 原因

key 只能由字母、数字、下划线组成，含连字符时运行期反复报 Cannot use the key!，编译照常通过，问题只在设备日志里暴露。来源中首个写者把模块文件名风格用作 key，后续写者读到既有 key 后照样命名或照抄；沉浸式修复者手上的模板本是不传 key 的重载，也改成了与文件同名的连字符 key。输入 skill 没有写字符限制。

## 做法

1. 自定义 key 只用 [A-Za-z0-9_]（如 auth_session）；不需要自定义时用不传 key 的重载（默认类名）。
2. 同一共享状态的 key 集中定义为常量；复用已有 key 前先核对其合法性，已有 key 含连字符时把所有 connect 点一起改名，不照抄进新文件。

## 可选检查

仅在适用条件不确定、与当前输入冲突或需要验证关键假设时按需执行；优先复用已有证据和正常测试。
不因读取本条经验而额外启动验证流程；项目原有必需测试照常执行。

- rg "AppStorageV2\.connect\([^,]+,\s*'[^']*-" 及同类 PersistenceV2 调用应无命中。
