# 构造目标页路由参数以接收端契约为准：接收 Activity 不读取或写死的 extra 不透传

ID：`lesson-4a7c04b864ef635c87b6` · 版本：1

[本主题](index.md)

## 何时使用

功能接线阶段，为跨页跳转构造目标页参数、决定哪些发起页状态要带过去时

## 适用情境

源发起页用 putExtra 传一个开关（如显隐标签），但接收 Activity 不读取该 extra，或创建 Fragment 时写死该参数；目标页参数类已用默认值与注释标明该字段由接收端固定。

## 原因

发起端的 putExtra 只说明“传了”，不说明“被用了”；把发起页状态照搬进参数会覆盖接收端的固定值，出现源端没有的控件。前向占位里的“携带参数”也常按发起端写。来源中接线者两次读到目标参数类“Activity 固定传 false”的注释，仍用发起页的 true 赋值。

## 做法

1. 构造参数前读目标参数类每个字段的注释和默认值；字段注明由接收端固定时，发起端不赋值或写该固定值。
2. 迁移 startActivity + putExtra 时，逐个 extra 到接收 Activity 查 getXxxExtra 是否消费、是否在创建 Fragment 时被写死；只迁移被消费的 extra。
3. 占位登记里的“携带参数”当作发起端线索，接线时与接收端契约核对，冲突以接收端为准。
