# 同一目标页有多个启动入口时，按全部源端入口的 Intent extras 定义一个共享路由载荷，并实现每个来源分支

ID：`lesson-953309e05bc1cd36c0d1` · 版本：1

[本主题](index.md)

## 何时使用

功能切片、页面转换与编译修复阶段，为有多个入口的目标页（如搜索页）定义路由参数、编写各入口的 push 与接收端解析、实现选中结果的去向时

## 适用情境

Android 目标 Activity 被多个入口以不同 Intent extras 启动（如 searchText、locationType、searchFromMap），并按这些 extra 决定结果去向（setResult 回传或跳转下一页）；目标用 NavPathStack 传单一 param，各入口由不同切片、编译修复或巡检修复分别写入。

## 原因

每个写者只按自己的入口塞参数（字符串、对象、数字），接收端只解析其中一种，其余入口的参数被静默忽略；决定结果去向的 extra 丢失后，某个入口的后续跳转整体消失。编译修复自拟载荷字段、实现者用类型断言绕过载荷类型，会让分叉更难发现。来源中切片代理读到了源端按来源分流的结果处理，只实现了一个分支且没有登记占位；编译修复者随后自拟字段，另一切片用 as Object 绕过类型并收窄解析，巡检修复又把一个入口改成迎合当前解析。

## 做法

1. 列出源端所有启动该页的入口及其 extras，在路由契约文件定义一个共享载荷类型承载全部来源字段；各入口 push 与接收端解析都用它，不用 as Object 或裸 string/number 绕过，也不为适配单个入口收窄接收端解析。
2. 源端按某个 extra 分流结果去向时，每个分支都实现；本任务不做的分支登记前向引用并在回执列出。
3. 编译修复需要定义或修正载荷类型时，字段名取自现有调用点、接收端解析或源 Intent 键，不自拟字段。
4. 巡检或修复发现调用方与接收端形状不一致时，以共享契约为准同时修正两端并检查其他入口。
