# 迁移带点击绑定的控件时按源点击处理器的分支逐项迁移副作用，不只做状态取反和换图

ID：`lesson-55e33a0621c3008ab8b3` · 版本：1

[本主题](index.md)

## 何时使用

界面迁移阶段，为布局中带 onClick 绑定、状态选图或滑动面板的控件编写 ArkUI 事件与状态逻辑时

## 适用情境

源布局控件用 android:onClick/数据绑定声明点击，或按 ViewModel 状态选图；实际行为（按键音、振动、偏好持久化、历史面板展开与回填）写在 Fragment 统一点击处理器、ViewModel 或第三方面板组件中；目标页需复刻这些开关与面板。

## 原因

布局只说明控件可点和怎样换图，副作用写在处理器里；只迁外观的开关会切换图标却没有功能，下拉指示图被当成静态装饰。来源中生成者补读到完整点击处理器（切换并持久化开关、按键播放对应音频、振动 50ms、历史面板初始化与回填），输出仍只有取反换图，交付汇报只列“两个模式图标”“下拉指示图”；随后用户多轮反馈无声、无振动、下拉无功能。

## 做法

1. 对每个声明了点击或状态绑定的控件，在统一点击处理器（when 分支）与 ViewModel 找到对应分支，列出副作用（播放哪些音频、振动时长、写哪个偏好键、打开哪个面板）后再写 onClick；未迁移的副作用在报告中逐项列为缺口。
2. 源码读取被截断时，按控件 id 或状态名补读被截断段；补读到的行为逐条落实，不只同步默认值或命名。
3. 滑动面板、历史列表一类组件的展开、收起与数据回填按交互迁移，与规格中的相应验收项对应实现。
4. 迁移按键音与振动时，从源端 assets 定位实际音频复制到 rawfile，用媒体类音频流播放并在加载完成后才允许播放；振动声明 ohos.permission.VIBRATE，实际震感还受系统触感反馈设置影响。
