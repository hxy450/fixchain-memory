# Android 依赖厂商 SDK（如高德地图/定位/搜索/导航）时，规划阶段先查厂商鸿蒙 SDK 包与版本，再在 Kit、厂商包、H5 与受控降级之间取舍

ID：`lesson-e9890889e591196c3d0d` · 版本：1

[本主题](index.md)

## 何时使用

迁移规划阶段为三方 SDK 作依赖决策、为对应切片绑定 SDK 文档类 skill 时；实现阶段遇到规格要求的 SDK 能力而工程里还没有 SDK 时

## 适用情境

Android 工程直接依赖厂商 SDK（com.amap.api.* 一类），功能规格与接口清单写明这些能力；项目 skill 映射表把该厂商列为 SDK 文档查询类 skill 的典型对象；用户在决策问答中没有提供鸿蒙 SDK 资料，只回复“采用建议”。

## 例外与边界

- 已查明厂商没有鸿蒙版本，且决策记录写明了替代方案与理由

## 原因

不查厂商鸿蒙包就把整套能力登记为受控降级，后续切片只能写占位或本地替代（如用历史记录过滤代替 POI 搜索），交付后再补接入要重做服务层与页面。来源中规则已要求用户无资料时标 needs_doc_lookup 并查公开文档与 SDK 仓库，规划者只问了用户是否有资料，拿“采用建议”关闭了可用性核查；生成后评估代理几分钟就在厂商官网查到 ohpm 上的鸿蒙包，Key 需按鸿蒙签名另行申请这一前置条件也此时才浮现。

## 做法

1. Android 依赖命中厂商 SDK 时，先查厂商鸿蒙文档与 ohpm 包名、版本（如 @amap/amap_lbs_common、map3d、search、location、navi），结论写进决策记录的事实段；用户未提供资料只意味着需要继续查，不作为关闭依据。
2. 查到厂商鸿蒙包时，决策写明依赖包、版本与前置条件（如 Key 须按鸿蒙签名 App ID 申请，放本地配置、缺失时显式失败），把 Key 列为待用户提供项，不把整套能力登记为 deferred。
3. 切片计划按规格中的厂商 SDK 关键词绑定对应 SDK 文档类 skill，并把依赖声明与初始化列入范围；实现时 SDK 仍缺位就登记三方 SDK 占位或回报计划缺口，不用本地替代静默顶替并当作满足验收。
