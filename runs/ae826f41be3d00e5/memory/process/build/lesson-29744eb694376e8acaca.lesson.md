# 编译修复只改报错定位的行与符号，不以删掉功能换取通过；必须整文件重写时逐段对照上一版，未报错的写法原样保留

ID：`lesson-29744eb694376e8acaca` · 版本：2

[本主题](index.md)

## 何时使用

编译修复阶段，为修某条编译错误决定局部修改还是整文件重写时

## 适用情境

修复循环用 here-string 或 Write 整文件重写页面来处理导入导出、@Entry 等报错，文件里还有未被报错的组件用法（页签 builder、状态绑定、导入等）。或报错只涉及某个导入或符号，修复者考虑把相关功能块（如自绘趋势图）整体换成占位以通过编译。

## 原因

整文件重写时顺手换掉未报错的写法，会引入新的编译错误或行为变化；修复者只盯着原报错，新错误被当成原问题的延续，一直拖到交付。来源中为修导入导出错误重写主页，把未见报错的 @Builder 页签改成不存在的 { title } 重载，构建因此在生成结束时仍失败。又一应用中构建修复者看到的日志只报 '@kit.ArkUI' 未导出两个 Canvas 相关类型，却把整个 Canvas 趋势图换成文字点列，规格要求的 15 日折线随之消失，直到用户返修才重建。

## 做法

1. 只改报错指向的行和符号；必须重写时先与上一版逐段对照，未报错的组件用法保持原样，确需改动的先按 API 签名或编译器重载提示确认可用形态。
2. 报错只指向导入或单个符号时，修正导入（如改用全局可用的类型）并保留功能；确需降级时回写规格、把对应验收保持未完成，不以占位替换后报告通过。
