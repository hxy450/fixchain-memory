# 把 Android 主题隐式提供的控件外观写成目标控件的显式样式

ID：`lesson-47785524c7f132ea7efe` · 版本：1

[本主题](index.md)

## 何时使用

规格提取阶段写控件转换决策，或页面实现阶段写出按钮等控件的修饰链时

## 适用情境

源布局中的 Button 等控件没有声明 background / backgroundTint / textColor / 圆角，外观来自应用主题（如 Theme.MaterialComponents 的 colorPrimary、colorOnPrimary）；目标工程已迁移同名语义色资源，而 ArkUI 对应组件不设样式时使用平台默认外观。

## 例外与边界

- 源控件已在布局或 style 中显式声明样式，此时按显式声明转换
- 决策记录明确要求目标端采用平台默认外观

## 原因

ArkUI 组件不会继承 Android 主题给控件的默认样式。规格只在全局写“颜色由资源系统负责”而不落到控件行，下游按控件行实现就得到平台默认外观。来源（API 24 工程）中不设样式的 ArkUI Button 呈默认蓝 #0A59F7 胶囊，与源端 Material 紫底白字小圆角按钮不符。

## 做法

1. 规格提取时，对布局里没写样式的控件先查主题的父主题与语义色，把主题带来的背景色、字色、圆角、最小高度写进该控件自己的转换决策行，用已迁移的颜色资源名表达。
2. 实现时对照源主题语义色与目标颜色资源补齐修饰链：MaterialComponents 按钮对应 .backgroundColor($r('app.color.colorPrimary')) 与 .fontColor($r('app.color.colorOnPrimary'))，再按源按钮样式补 borderRadius 与最小高度；规格未写样式时同样补齐，并在转换报告注明依据来自主题。深浅色由 base/dark 资源自动切换。
