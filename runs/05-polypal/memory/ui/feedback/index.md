# ui/feedback

操作结果反馈：异步结果各分支的提示与去向，Snackbar 一类提示的宿主、时长与成功/失败态渲染

[上一级](../index.md)

## 本级经验

- [源端单一 SnackbarHost 的结果反馈用一份反馈状态驱动唯一浮层；每个结果态都要有渲染分支，catch 写入的状态要有消费方](lesson-187c725b1bb9d8d1bf4d.lesson.md)
  - 时机：页面转换与功能接线阶段，把源端 Snackbar 结果反馈和规格里的操作状态落成 ArkUI 提示，并给成功与失败分支接通界面时
  - 情境：源端页面只有一个 SnackbarHost，按顺序显示操作结果；目标规格给出含 error 的操作状态，并要求失败时报错且不留成功状态；目标页用条件渲染的底部浮层实现提示。
- [迁移源端异步结果回调时，按成功、失败分支列出全部副作用（跳转与关页、提示、标记写入），计划与代码逐项对上](lesson-ac7a2e17b8d88c3cee7b.lesson.md)
  - 时机：界面、流程实现与页面接线阶段，把源页面对异步操作结果的观察（LiveData observe 等）改成目标页面的 await 结果、try/catch 或路由枚举，并决定各分支的跳转与反馈时
  - 情境：源 Activity 在结果观察回调里按成功/失败分支同时做几件事（写本地标记、跳页并 finish、showToast）；目标 ViewModel 方法只更新状态，或把失败折叠成返回值，由页面决定导航和提示；页面里可能留有“登录成功跳 X”的注释或 TODO。
