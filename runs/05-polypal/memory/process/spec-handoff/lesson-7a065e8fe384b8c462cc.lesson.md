# 规格写法与写前读到的源码、主题或映射参考冲突或遗漏时，按源端语义实现并标注差异

ID：`lesson-7a065e8fe384b8c462cc` · 版本：2

[本主题](index.md)

## 何时使用

页面或数据层实现阶段，规格给出的容器、样式、类型写法或验收条目与写前读到的源码、主题或映射参考不一致，或验收条目没有列出源码里可见的行为时

## 适用情境

实现者同时读到规格与源布局、源码、主题文件、映射参考或 SDK 声明，规格的具体写法（含验收条目里的列表范围、过滤条件）与源端可观察行为或参考映射不符，或验收条目漏掉了源码对展示内容的加工；规格对该处只有概括性理由或没有提及。

## 例外与边界

- 规格或决策记录（如 decision ledger）对该差异写明了有意取舍的理由，此时按该决策实现

## 原因

规格是对源端的概括，可能把语义写错或写漏；实现者以“按规格”“验收项没列”为由保留差异，偏差就原样进入代码，直到编译门、视觉比对或评审才暴露。来源跨两个应用：三例中实现者写前都读到了与规格相左的输入（映射参考 ConstraintLayout → RelativeContainer、主题紫色与已迁移色令牌、类型映射 String → String），最后照抄了规格；另一应用里规格作者因读取截断把“对话框列出全部默认项”写成“只列数据库里缺失的”，实现者写前已读到源码按全部列出，仍按规格过滤；还有转换者读到描述文本经链接识别函数加工后再显示，推理写明“验收项只要求折叠，可以做成纯文本”，就把链接删了。

## 做法

1. 写码前对冲突点逐一取舍：规格只有概括性理由时，以源端可观察行为为准实现；涉及 API 签名的，以本地 SDK 声明为准。验收条目标注了源码出处时，打开该出处核对。
2. 源码里有、验收条目没写的可见行为，不能据此判定可删：按源码实现；做不了就登记占位，并在报告未决项里写明降级。
3. 在转换或迁移报告里列出与规格不同的每一处及依据，供规格阶段回改；不要为了与规格一致而删掉已确认的源端语义。
