# 派工指定的必读 skill、规格与参考文档要读全再写码：批量读取被截断、只读前 N 行或跳过参考时，规则并未进入上下文

ID：`lesson-42df1ac4d4030421da34` · 版本：3

[本主题](index.md)

## 何时使用

写码 worker 或规格作者开工时加载 skill、功能规格、预生成参考文档与源码，长会话压缩上下文后继续写码时，以及在回报中填写 loaded_skills 时

## 适用情境

派工列出多份前置 skill（常见十几份 SKILL.md）或多份规格、参考文档，读取者用一次命令批量 cat，或用 sed -n '1,Np' 按固定行数读取；工具对单次输出有长度上限，超出时会省略中段并给出 truncated 提示。也包括已加载的 skill 要求先读某份参考（如迁移陷阱表），读取者没有读，或只在 grep 回执里碰到片段、之后上下文被压缩。

## 原因

被省略或没读到的段落不会进入模型上下文，其中的具体规则就等于没下发。来源跨两种宿主、三个应用：批量 cat 18–19 份 SKILL.md 时回执中段被省略，或只读某 skill 前 130 行，随后写出的代码正好违反没读到的规则（只能 throw Error、@Builder 值参不随状态刷新、异步加载要 try-catch 兜底、hilog 导入写法）；已加载的 UI skill 要求先读迁移陷阱表，写 Tab 行的 worker 没有读。另一应用里一次 cat 多份功能规格或源码时截断落在要用的段落：计时源码缺了已完成重量与步进函数，参考文档缺了“对话框列出全部默认项、以新 id 复制”，数据库规格缺了库名与版本要求，外观规格段不可见；陷阱表的对应条目也因截断没被读到。随后的实现或验收条目正好偏在这些段落上。

## 做法

1. 必读 skill、规格和参考文档逐份读取，或分批控制单次输出量；看到 truncated output、tokens truncated 之类提示时，列出没读全的文件并按章节或行号单独重读，读全后再写码或写验收条目。
2. 组件复用、状态管理、错误处理这类规则常在 skill 后半部分，不要按固定行数截读；需要节省时先用 rg 找到与当前任务相关的小节标题，再读完整小节。
3. skill 正文要求先读的参考文件（如迁移陷阱表、映射表）同样是必读，与本次写码相关的小节要完整读过；上下文被压缩后，写到尺寸、状态、错误处理这类决策前重读对应小节，不依赖摘要。
4. loaded_skills 只写读全的 skill；只读了部分的如实注明范围。
