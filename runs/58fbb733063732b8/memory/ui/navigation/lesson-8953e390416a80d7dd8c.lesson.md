# 入口页 Navigation 宿主：NavDestination 首屏只在 navDestination 映射中注册并压入同一栈，不作根内容；.navDestination 直接传 @Builder

ID：`lesson-8953e390416a80d7dd8c` · 版本：1

[本主题](index.md)

## 何时使用

入口页实现或收尾接线阶段，创建 Navigation 宿主、决定首屏放在根内容还是压栈、编写 navDestination 分发时

## 适用情境

目标入口页用 Navigation + @Provider NavPathStack 承载路由；首屏（启动页等）写成返回 NavDestination 的组件，在 onReady 取栈并按启动决策 pushPathByName 下一页；目的地由 @Builder 映射分发。

## 例外与边界

- 首屏是普通组件（不返回 NavDestination）、作为 Navigation 根内容常驻，且不依赖 NavDestinationContext 取栈

## 原因

放在 Navigation 根内容里的 NavDestination 不在 NavPathStack 中，它的 context.pathStack 与宿主栈不一致，push 不产生新页（日志 current stack is not navPathStack）；把 .navDestination 写成箭头函数再调 Builder 会丢失 Builder 元数据（日志 Builder function is empty）。两者叠加时应用停在首屏。来源中收尾者读到首屏是 NavDestination 且在 onReady 取栈，仍把它直接放作根内容，并用箭头函数包装映射。

## 做法

1. 返回 NavDestination 的首屏只在 navDestination 映射中注册；根内容用空容器或普通组件，在其 onAppear 用同一 NavPathStack pushPathByName 推入首屏（只推一次）。
2. .navDestination 直接传 @Builder 方法，如 .navDestination(this.destination)，不再包一层箭头函数。

## 可选检查

仅在适用条件不确定、与当前输入冲突或需要验证关键假设时按需执行；优先复用已有证据和正常测试。
不因读取本条经验而额外启动验证流程；项目原有必需测试照常执行。

- 冷启动日志中不应出现 Builder function is empty 或 current stack is not navPathStack。
