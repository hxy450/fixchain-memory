# 编排者因子代理不可用而亲自实现切片时，先加载切片 worker 本应拿到的全部输入，不凭占位登记表的一行触发文本写代码

ID：`lesson-b90d7f55409a3a34253d` · 版本：1

[本主题](index.md)

## 何时使用

执行编排阶段，子代理额度耗尽、限流或失败后，编排者决定自己完成 Base/切片实现、接线或解决前向引用时

## 适用情境

编排会话原本只负责派工与收口，手上是占位登记表、feature-plan 的指针和子任务回报这类摘要；切片 worker 派工里列出的切片计划文件、功能规格验收条目、决策账本正文和源码锚点，编排会话并没有打开过。

## 原因

占位登记表和计划索引只是指针，状态机、反馈、平台能力选型、外链常量等行为细节都在切片计划、功能规格和源码里。来源中同一个编排会话在子代理额度耗尽后接手 Stage 2/3：没打开平台切片计划和规格，就把已批准真实现的后台计时写成桩；没读计时切片计划、源码读取又被截断，就自拟了计时状态机；漏掉登记表和规格里都写了的步骤提示音与振动；外链只看到泛称就猜了网址；克隆回调没读源码就只按登记表一句话实现；深链只接了运行时解析。它读过的只有指针和截断的批量输出。

## 做法

1. 接手前把该切片 worker 派工里的输入逐项列出（切片计划文件、spec_refs 指向的验收条目、决策账本相关条目正文、源码锚点行），逐份打开；按 worker 的必读材料对待，不因为自己是编排者就只看摘要。
2. 解决某个前向引用前，打开它指向的源码行和验收条目取值；登记表、回报里没写全的数据来源、字段变换、导航细节以源码为准补齐。
3. 写完一个切片，对照该切片的验收条目逐条核对实现位置；“标记已删除”“结构闭包 0 FAIL”不作为完成判据。
