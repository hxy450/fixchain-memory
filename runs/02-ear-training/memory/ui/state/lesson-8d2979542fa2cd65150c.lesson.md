# 随状态变化的控件参数不作 @Builder 值参，改为内联读取状态或用 @ComponentV2 子组件的 @Param

ID：`lesson-8d2979542fa2cd65150c` · 版本：1

[本主题](index.md)

## 何时使用

界面实现阶段（页面转换与公共组件抽取），为源端带状态参数的子控件选择 ArkUI 复用写法时

## 适用情境

源端 Compose 子 Composable 以当前状态算出的值作参数（如 enabled = count > 1、颜色随选中态变化），目标 ArkUI 组件需要在状态变化后刷新 enabled、颜色等属性，准备把子控件抽成 @Builder 方法。

## 例外与边界

- 传入 @Builder 的只有文案、尺寸等在该组件生命周期内不随状态变化的值

## 原因

Compose 每次重组都按当前状态重算实参；ArkUI @Builder 按值传入的参数是调用时刻的快照，状态变化后不会刷新 @Builder 内的 UI。来源中边界步进按钮在状态越过边界后仍保持禁用、点击无效。这条规则写在组件构建 skill 的 @Builder 复用一节，但页面转换器的前置清单里没有该 skill，公共组件 worker 又只按固定行数读了它的前段。

## 做法

1. 状态派生的 enabled、selected、颜色等参数，用内联属性链直接读 this 上的状态，或抽成 @ComponentV2 子组件用 @Param 接收；@Builder 值参只放不随状态变化的值。
2. 写完 grep `@Builder` 签名与调用处，实参含 `this.<状态>` 表达式的即为风险点，改写后再落盘。

## 可选检查

- 对刷新有疑问且能上设备时，把相关状态切过边界再切回，用 dumpLayout 核对控件的 enabled 与颜色。
