# 解决前向占位时按登记的触发文本逐项兑现：只接一半、写成常量或删掉标记都不算闭合

ID：`lesson-eb4de4fd7452308a0483` · 版本：3

[本主题](index.md)

## 何时使用

切片实现或接线阶段，把页面转换留下的前向占位（FWD-REF、TODO）替换成实现并删除标记时

## 适用情境

页面转换阶段按“只输出 UI”约束留下前向占位，登记表或 TODO、文件头注释写有触发文本，例如“持久化并触发主题立即切换”“切换步骤时重触觉”“由服务提供版本号”“通知授权由平台服务实现”“游客登录（登录成功跳主页）”，由后续切片或接手者实现。

## 原因

标记删掉后编译和结构审计都会通过，触发文本里没做的那一半没有任何门会发现。来源一个应用中有四类：只接了偏好持久化、没有运行期消费方；只重置进度、没做反馈；把应由服务提供的版本号写成与配置文件重复的常量；把应真实现的平台能力写成恒定返回值。另一应用里接线者读到“游客登录”的 TODO 和“登录成功跳主页”的注释，只接上登录调用，不等结果、不跳转，就删了 TODO。另一应用中，数据接线者删掉了黄历区块的前向占位标记，却没有给区块的 available 标志赋值，组件按该标志把整块隐藏；另一接线者按只含 P-ID 的钩子接线，没有回读源码，丢了选中项的恢复与回写。

## 做法

1. 删标记前把触发文本拆成动作清单（持久化、运行期消费方、反馈、值来源、导航），每一项都能在代码里指出实现位置后再删。
2. 触发文本要求服务或 ViewModel 提供值时，写入常量或复制配置文件里的值不算闭合，改为从运行时来源读取。
3. 只接上了调用、没处理结果分支（成功后的跳转、失败提示）时保留标记，不算接线完成。
4. 删除标记后 grep 同一函数：恒定返回（return false、两支相同的三元表达式）、与配置文件相同的字面量，都是没闭合的信号。
5. 删除标记前，逐项核对组件里每个 available/可选区块开关都有真实的赋值来源；源端在选中项变化时附带的查询（如按选中日查历法）要迁到网关或 ViewModel，不能留默认值让条件渲染把整块隐藏。
6. 填别人留下的钩子前，回读页面规格列出的源码锚点中对应方法，逐项核对加载、恢复、切换回写等行为，不只按钩子名称接线。
