# 翻译源端 JSON 解析时按源端取值 API 的空值语义定字段规则：org.json 的 getString 对 null 不抛错，只有缺键才抛

ID：`lesson-5034b56be6fd828164c9` · 版本：1

[本主题](index.md)

## 何时使用

实现阶段把源端 JSON 解析函数翻成 ArkTS 手写解析器、决定各字段必填与空值处理时

## 适用情境

源端用 Android org.json 的 getString 等读取打包 JSON 资源；对应 Kotlin 数据类字段声明为非空 String；目标解析器任一字段校验失败就让整页进入加载失败。

## 原因

Kotlin 非空声明不等于 JSON 值不会是 null；getString 遇到 JSON null 返回字符串 "null"，缺键才抛错。把字段写成“值必须是字符串”，数据里任一 null 就让整份列表失败。来源中转换者在推理里写明了 getString 的这一语义并用在两个字段上，却没统计另一个字段的 null，打包数据里恰有一条为 null。

## 做法

1. 按源端取值 API 定空值规则：getString 的字段缺键才报错，null 映射为空串或占位；只把源端真正会失败的情况写成抛错。
2. 写解析器前对打包资源逐字段统计 null、缺键和非字符串的条数，不只统计 UI 里有判空的字段。
3. 单条记录的展示字段为空时降级显示，不让整份列表失败；catch 分支记下具体异常，便于直接定位是哪一条哪个字段。
