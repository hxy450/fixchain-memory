# 编排者推进阶段或派发下游前，逐项兑现规范划给自己的步骤和子任务点名给别人的事项

ID：`lesson-5754b7be28238f1bdf57` · 版本：1

[本主题](index.md)

## 何时使用

执行编排阶段，子任务返回后决定推进到下一阶段，或为下游切片写派工时

## 适用情境

执行规范把某些收尾步骤（如资源阶段之后的应用身份落地）留给编排者亲自调用；子任务返回的 open_questions、风险项或文件头说明，把某项工作指给另一个阶段、切片或编排者本人。

## 原因

这类承接项只存在于规范段落、返回文字或代码注释里，编译、结构审计等门都不检查；编排者直接推进，这项工作就没有执行者。来源两例：编排者读过“资源迁移后由主线程调用应用身份落地”的规范并列进计划，收到资源任务“最终装配归属该步骤”的返回后仍直接进入页面转换，之后页面转换者在 open_questions 点名脚手架 label，也没有处理；另一例页面转换者把返回键转发交给“入口装配或后续接线决定”，编排者没有写进任何后续派工，接线切片的派工只要求原样嵌入，后续复核都按“已处理”放过。

## 做法

1. 推进阶段前，按该阶段规范列出划给编排者的子步骤，逐项确认已实际调用；没有执行的先执行，或在报告里登记为阻断项。
2. 收齐子任务返回后，把 open_questions、风险项里点名其他负责方的条目逐条分派：写进对应切片的派工正文（附原文与验收方式），或登记为待办；不随阶段推进丢弃。
3. 派发接线任务时，若上游说明要求该任务在壳页或调用点补转发，在派工里写明要实现的内容，或要求无法实现时上报阻塞；派工带“其余不动”之类约束时，把这项移交列为例外。
