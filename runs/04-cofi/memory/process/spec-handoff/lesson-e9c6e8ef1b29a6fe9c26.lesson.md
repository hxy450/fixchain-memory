# 沿用已生成页面或兄弟任务的写法前，回到源码核对该片段的语义

ID：`lesson-e9c6e8ef1b29a6fe9c26` · 版本：2

[本主题](index.md)

## 何时使用

页面转换、公共组件抽取、切片接线或页面重建阶段，参照已生成页面中的同名控件、弹窗、列表或顶栏写法时

## 适用情境

后写的 worker 同时读到源码与先前 agent 已生成的目标代码片段（@Builder 控件、输入弹窗、列表键函数、顶栏折叠等），准备当作项目约定直接沿用。

## 原因

已生成片段可能带着偏差，照搬会把它复制到新文件，形成多处同源缺陷。来源跨两个应用：公共组件逐字沿用页面里的 @Builder 值参写法与输入框 onChange 限长，列表页重建沿用只含 id 的 ForEach 键；另一应用里两位设置页转换者都读到了源端连续折叠顶栏的写法，前一位沿用兄弟页的两态近似并称之为项目约定，后一位把前一位的输出当作“约定锚点”再抄一次。写者都读过源码，却以兄弟代码为准。

## 做法

1. 沿用前逐个核对片段在源码里对应的行为：参数是否随状态变化、输入约束是否真的阻止显示、条目更新后键是否变化、折叠是否连续；核对通过再落盘，兄弟代码不能代替对源码的核对。
2. 兄弟页的写法与本页源码不一致时按源码实现，并在报告写明兄弟页与源码的差异，不把兄弟页的近似复制到新页。
