# Web 组件的 onErrorReceive 也报告子资源错误：只在主框架出错时切换整页失败态

ID：`lesson-051f8984f21058916bd9` · 版本：1

[本主题](index.md)

## 何时使用

WebView 页面实现阶段，为 Web 组件的加载错误回调决定是否切换整页失败/重试状态时

## 适用情境

目标页用 Web 组件加载线上第三方 H5，自带加载进度与覆盖 Web 区域的失败重试卡片，在 onErrorReceive 中处理加载错误；参考模板可能把该回调写成无参形式。

## 原因

onErrorReceive 同时报告主文档与图片、脚本等子资源的加载错误；直接绑定整页失败态，页面已渲染时任一子资源失败也会用失败卡覆盖正常内容。来源中写者照技能模板写了无参回调并在其中置失败态，真机上已显示的 H5 表单被“加载失败”覆盖；修复加 event.request.isMainFrame() 判断。

## 做法

1. 在 onErrorReceive((event) => …) 中先判断 event?.request.isMainFrame()：只有主框架错误才切换失败/重试态，子资源错误只记日志。
2. 照参考中的无参回调模板写业务 UI 时，补全事件参数并在本地 SDK 的 web.d.ts 核对事件字段，再决定回调触发的状态变更；源端错误处理不可见时，不自行把任意加载错误升级为整页遮罩。
