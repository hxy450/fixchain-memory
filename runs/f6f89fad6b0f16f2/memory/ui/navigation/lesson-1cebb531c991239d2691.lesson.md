# 嵌在 Swiper/Tabs 里的页面组件只用 @Consumer 注入的根 NavPathStack，不在 onReady 用 context.pathStack 覆盖

ID：`lesson-1cebb531c991239d2691` · 版本：1

[本主题](index.md)

## 何时使用

页面转换与主壳接线阶段，为由主页 Tab/Swiper 承载的 Fragment 页确定导航栈来源、编写 onReady 时；把已有页面接入主页 Swiper/Tabs 时

## 适用情境

Android 主 Activity 用 ViewPager/底部 Tab 承载多个 Fragment；目标由入口页 Navigation 以 @Provider 提供根 NavPathStack，主页 Swiper 嵌入各 Tab 页组件，子页用 @Consumer('navPathStack') 取栈，外层仍保留 NavDestination 与 onReady；工程里经 pushPathByName 压栈的页面普遍在 onReady 写 this.navPathStack = context.pathStack。

## 例外与边界

- 页面本身经 pushPathByName 压入根栈、不在 Swiper/Tabs 子树内时，onReady 的 context.pathStack 就是根栈，该赋值无害

## 原因

嵌入 Swiper 子树的 NavDestination 在 onReady 拿到的是嵌套视觉目的地的栈，不是入口页的根栈；用它覆盖注入栈后，点击处理压到隔离栈上看似无反应，或在真机上报 pushPathByName is not callable 直接崩溃。来源中两位转换者的定义已给出 @Consumer 注入、onReady 只读参数、Tab 子页不套 NavDestination 的模板，却照搬工程内压栈页的写法；页面后来被接入主页 Swiper 才出错。

## 做法

1. Tab/Swiper 承载的子页只用 @Consumer('navPathStack') 注入的根栈；onReady 只读取 pathInfo.param，不写 this.navPathStack = context.pathStack。
2. 参照已有页面前先判断本页是压栈的 NavDestination 还是嵌入 Swiper/Tabs 的子组件；压栈页的栈赋值不照搬到 Tab 子页，套用安全区等模板时只取所需部分。
3. 把页面接入主页 Swiper/Tabs 时，一并删掉被嵌入页面里的 context.pathStack 赋值。

- 接入后对被嵌入的子页检索 pathStack = context.pathStack，应无命中。
