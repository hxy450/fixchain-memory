# 规格要求乐观更新时，先本地翻转状态再发请求，回调只用服务端真值回填

ID：`lesson-18c8e7630a96d66540bc` · 版本：1

[本主题](index.md)

## 何时使用

界面交互实现阶段，编写收藏、点赞类切换的点击处理，确定本地状态翻转与服务端调用的先后时

## 适用情境

验收要求点击后状态翻转、界面即时刷新（乐观更新）；源端把选中态设置写在网络接口的成功回调里；目标用状态变量驱动图标并异步调用接口。

## 原因

把翻转放进 if (ok) 后，接口失败（未登录、参数异常、网络问题）时只剩点击动效、图标不变；注释写着“乐观更新”也不改变控制流。规格与源码结构不一致时若不取舍、不登记，代码会沿用源码的回调门控。

## 做法

1. 本地状态翻转写在异步调用之前，回调只用服务端真值回填；失败是否回滚按规格或决策显式写出。
2. 源码门控在回调里、规格要求乐观更新时，输出前在决策记录或源码笔记写明采用哪一种；写完核对注释声称的语义与实际控制流一致。
