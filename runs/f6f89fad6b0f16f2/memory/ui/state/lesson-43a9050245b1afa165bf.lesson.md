# 迁移按状态切换的显示时同时迁移 setVisibility 分支：该状态下隐藏的控件不渲染，显示的区块要实现

ID：`lesson-43a9050245b1afa165bf` · 版本：2

[本主题](index.md)

## 何时使用

界面实现与巡检修复阶段，迁移登录态等状态下控件的显示内容与显隐时

## 适用情境

源端 Fragment 按登录态等状态对多个控件 setVisibility（如登录后隐藏用户名、显示签到区），部分 setText 被注释；目标 ArkTS 按状态条件渲染；工程可能有显隐或绑定检查器报告源控件丢失。

## 原因

只看 setText 会把被注释的赋值理解成“显示昵称或占位”，漏掉 GONE/VISIBLE 表达的“该状态换成另一块内容”；绑定检查器报控件丢失时，加同名包装函数或收窄清单也能让检查通过，缺的区块却仍不存在。来源中巡检者自己写出“登录后隐藏用户名、显示签到区”的问题单，修复却只把固定文案改成“昵称或未登录”，回执写成“展示昵称”；编排者随后以包装函数让绑定检查转为通过，签到区直到用户提供截图才补上。另一应用中两处：城市页的广告容器在源 XML 中为 visibility=invisible 且带 marginTop=50dp，目标只在广告加载后渲染，默认状态下 50dp 留白消失；个人中心的收益、签到、任务区在源码由远端配置开关决定显隐，返修改成“任一任务列表非空就显示”，目标截图中没有的区块在有数据时出现。

## 做法

1. 对每个状态分支同时列出 setText 与 setVisibility：该状态下 GONE 的控件在目标对应分支不渲染，VISIBLE 的区块及其数据来源要实现，不以回退文案替代。
2. 修复回执按“隐藏了什么、显示了什么”对照问题单自检。
3. 显隐或绑定检查报控件丢失时，补真实的分支与控件，不以同名包装函数或收窄检查清单让检查通过。
4. 源 XML 中 visibility=invisible 的容器在任何状态都保留其尺寸与 margin 占位（可用 Visibility.Hidden），gone 才不占位；不要只在加载成功时才渲染占位容器。
5. 可选区块的显隐沿用源码的判定条件（远端配置开关、渠道、会员），接到等价的运行时配置；不以接口列表是否为空推断显隐。
