# 迁移深链 intent-filter 时同时声明 module.json5 的 skills（actions、entities、uris），并用隐式 Want 验收

ID：`lesson-d77baa7494930d485425` · 版本：1

[本主题](index.md)

## 何时使用

入口与导航接线阶段，把源端 Activity 的 VIEW/BROWSABLE intent-filter 迁成 UIAbility 的 Want 接收与路由解析时；以及规格提取阶段描述深链映射时

## 适用情境

源 AndroidManifest 在启动 Activity 上声明 VIEW+BROWSABLE、http/https 与固定 host 的 intent-filter；目标 module.json5 的入口 Ability skills 仍是脚手架默认的 HOME 一项。

## 原因

只在 onCreate/onNewWant 里解析 want.uri，系统不会把外部链接路由到该 Ability；用 aa start -b/-a 显式拉起会绕过 skills 匹配，把缺声明误判为通过。来源中实现者读到了 Manifest 与深链清单，只写了解析代码；派生规格也只写“启动后解析 URL”；验证用显式启动把这条验收判为通过。

## 做法

1. 把 intent-filter 的 action、category、data 映射到同一 Ability 的 skills：actions 加 ohos.want.action.viewData，entities 加 entity.system.browsable，每个 scheme 一条 uris（scheme、host、pathStartWith 或 pathRegex）；与 want.uri 解析在同一步完成。
2. 应用内解析按源端 uriPattern 锚定 scheme、host、路径段和参数类型，不匹配时清空待处理状态。
3. 验收用隐式 Want：aa start -A ohos.want.action.viewData -U <url>，不带 -b/-a，或从外部应用点击链接。
4. 规格描述深链时同时写平台声明（skills.uris）与运行时解析两部分。
