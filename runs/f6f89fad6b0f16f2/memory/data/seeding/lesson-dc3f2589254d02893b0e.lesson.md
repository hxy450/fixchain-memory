# 源端在应用启动时按标记首次播种、设置中可重置时，目标在启动路径落实际调用并保留门控，重置入口另接

ID：`lesson-dc3f2589254d02893b0e` · 版本：1

[本主题](index.md)

## 何时使用

计划与实现阶段，迁移 Application.onCreate 里的首次启动初始化（如演示数据播种）并确定目标调用点时；执行总结声称“首次运行自动初始化”前

## 适用情境

源端 Application.onCreate 调用 seedDemoDataOnFirstLaunch 一类方法，按偏好标记（如 has_seeded_demo_data）只播一次；同一数据集在设置页可手动重置；目标端用自建数据管理器（单例、KV 或数据库）替代 Room 等持久化。

## 例外与边界

- 源端在数据库首次创建回调里播种：按建库分支与同一事务处理，见同主题的建库播种经验

## 原因

只迁了重置入口时，播种函数在目标里只有设置页一个调用者，首次启动没有数据；切片计划把“首次启动自动播种”写成“演示数据重置”后，实现与总结都不会再发现缺口。来源中执行总结写着首次运行会自动初始化，实际启动路径没有任何调用。

## 做法

1. 在目标启动路径（EntryAbility.onCreate 或数据管理器初始化）落一个实际调用，按源端门控执行：源端用偏好标记就迁同一标记并在播种成功后写入；以“数据为空”近似只在当前契约接受时采用，它会在用户清空数据后重新播种。
2. 设置页的重置单独接线：清空后调用同一播种函数，不受首次启动标记限制。
3. 汇报已实现首次启动初始化前，确认该函数在启动路径上确有调用者；只有设置页调用时不算完成。
