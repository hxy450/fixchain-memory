# 源端由算法库对任意日期实时计算的字段，不改绑为只覆盖少量日期的静态资产；先查目标平台的内置能力，并记录资产覆盖范围

## 何时使用

规格提取、资源转换与数据层实现阶段，确定日历、农历、宜忌等按日期计算的字段来源，以及引用源工程预置数据资产时

## 适用情境

Android 经 Repository → DAO → Helper 调用第三方库（如农历库的 Lunar.fromDate、dayYi/dayJi）为任意日期计算字段；源工程另留有只覆盖少量日期、或已标注弃用的预置 JSON 资产；目标平台没有同名库，规格同时出现“同输入同输出的算法适配”与“资产无匹配保持为空”两种说法。

## 原因

把实时计算改成静态资产查找，资产范围外的日期（包括今天）一律返回空，月历、农历与宜忌卡整块消失；只补部分字段的降级（补了农历、没补宜忌）又会让依赖字段的区块继续隐藏。来源为同一应用：实现者读到算法适配的硬性要求和源端调用农历库的代码，却把全部字段绑定到只覆盖 2021 年前 120 天的资产，范围外返回空；返修补的日期降级只填农历与干支，没有宜忌，报告仍称已接入；平台 Intl 的中国历其实可用。

## 做法

1. 源端字段由算法库对任意日期计算时，先查目标平台内置能力（如 Intl.DateTimeFormat 的 zh-CN-u-ca-chinese）或已批准的库；确无替代时移植算法，或把功能缺口作为阻塞上报，不以静态资产作唯一来源并对范围外返回空。
2. 引用预置资产时记录它的实际覆盖范围（起止日期、行数），与运行期输入域（当前日期、可选年份）比对；覆盖不足就在规格里写明替代算法或降级方案。
3. 为模型补降级时逐一列出下游实际消费的字段（公历、农历、宜、忌），没填到的在报告中写明仍缺。
