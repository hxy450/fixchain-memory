# 多路请求聚合写 TTL 缓存前先确认至少一路成功；缓存命中同时校验时效和载荷

ID：`lesson-c6379cfcbee86500f91f` · 版本：1

[本主题](index.md)

## 何时使用

数据层实现阶段，为首页等多路并发请求（如首页数据与趋势）实现按键（城市）的 TTL 缓存写入与命中判定时

## 适用情境

源端或规格按城市缓存多路并发结果（refreshTime + 4h 一类），每一路都可能失败；目标 Service 把各路结果聚合成一条缓存记录，命中条件只看保存时间。

## 原因

全部失败时仍以当前时间写入空记录，命中条件又只看时效，一次失败就变成数小时的“有效缓存”，之后冷启动直接返回空结果、不再请求。来源中规格写明“成功后写入缓存”、决策账本写明“网络失败优先读有效缓存”，实现却在无缓存且两路都失败时落盘空记录。

## 做法

1. 写缓存前判断至少一路成功；全部失败时不写新时间戳：有旧的有效缓存就回退使用，没有就把分支错误交给调用方。
2. 缓存命中条件同时校验时效与载荷非空；已落盘的空记录视为失效并重新请求。

## 可选检查

仅在适用条件不确定、与当前输入冲突或需要验证关键假设时按需执行；优先复用已有证据和正常测试。
不因读取本条经验而额外启动验证流程；项目原有必需测试照常执行。

- 对缓存逻辑有疑问时，模拟所有分支失败后再调用一次，第二次必须重新发出请求。
