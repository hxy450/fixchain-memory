# 源端构建期注入的服务地址、签名与响应解密材料，按决策从私有构建配置接入并实现同算法解码器；不以空配置装配网络客户端

ID：`lesson-30ccd1d65d2c39029256` · 版本：2

[本主题](index.md)

## 何时使用

网络基础设施实现与装配阶段，实现网络运行配置来源、响应解密，并在装配根构造 HTTP 客户端时

## 适用情境

源端通过 BuildConfig/gradle 注入 API 地址、请求签名材料与 release 响应的 AES 等解密密钥，并在解析前解密响应；目标决策要求密钥不进源码、构建期从本地私有配置注入，网络层对空配置拒绝发包；另有决策只记录了“未提供测试环境或测试账号”。也包括目标用 process.getEnvironmentVar 读取可选运行配置（成功码、渠道、客户端身份）并以 `|| 默认值` 兜底的情形。

## 原因

“密钥不进源码”和“没有测试环境”约束的是存放位置与联调时点，不是允许生产配置缺席；网络层只留可注入参数、装配者又以空字符串构造客户端时，所有自有后端请求在本地就被拦截，解密缺失还会让 release 响应无法解析。来源中网络层实现者读过地址来源、签名规则与 AES/CBC 解密要求，只把地址、签名密钥和解码器做成构造参数（解码器默认空）；装配者把两条决策解释成“装配空配置”并写进基础契约，巡检报出阻断后派修因线程上限失败，同批只修了其他项；真机登录才暴露“网络配置不可用”。修复首版又把服务端明文 JSON 当作密文，说明解码器也要按源端实际分支实现。另一应用中，运行配置经 process.getEnvironmentVar 读取，而它读的是设备进程环境、不是构建环境，安装后的包拿不到密钥，请求在发出前就被拒；返修把缺省改为构建期字段时又删掉了 `|| ''`，仍直接读 `.length`，游客注册响应已经收到，却在读成功码时崩溃，并被包装成网络失败。

## 做法

1. 网络层任务内一并交付配置来源：构建插件或生成模块从环境变量、被忽略的本地配置读取地址与材料，生成文件加入忽略规则，缺键时构建或启动显式失败并登记阻断，不以空字符串构造客户端。
2. 按源端解密工具实现解码器：算法、模式与填充、key/IV 来源、Base64 等编码，以及 debug/release 与明文/密文的分支判定，用合成向量测试；release 下解码器缺失不能默认透传。
3. 区分“无测试环境/测试账号”（影响联调与设备验收）与“生产配置来源存在”（仍须接线）；带作用域限定的决策不外延为允许请求永久失败。
4. process.getEnvironmentVar 读的是设备进程环境，真机通常返回 undefined：构建期材料经 buildProfileFields（本地秘密参数由 hvigor parameterFile 引入）注入；仍保留的环境变量读取收敛到一个返回 string 的安全函数（缺失返回 ''），改写回退链时不删掉空值兜底再读 .length 或做 Number()。
