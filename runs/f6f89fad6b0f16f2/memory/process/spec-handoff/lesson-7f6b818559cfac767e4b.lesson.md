# 增量对齐时，源码已给出目标的点击入口写成具体导航契约；没有后续兑现方时不以 forward-ref 收尾

ID：`lesson-7f6b818559cfac767e4b` · 版本：1

[本主题](index.md)

## 何时使用

规格提取与计划阶段，为页面对齐需求确定横幅、宫格图片等可点击入口的导航契约，以及目标页尚不存在时的处理方式时

## 适用情境

Android 入口点击后打开固定 URL 的 WebView，或带本地资源参数的详情页；目标工程尚无对应页面；需求以“布局与 Android 对齐”为主，流程允许用 pending/forward-ref 登记暂缺目标，但本轮之后没有安排实现这些目标页的切片。

## 例外与边界

- 所在流水线有明确的后续切片负责创建目标页并兑现前向引用，此时按前向引用登记规则处理

## 原因

把源码里已确定的目标抽象成“打开对应业务页”，再以 pending/forward-ref 作为可验收结果，交付的入口就是空点击；没有后续切片兑现时，这些占位要等用户操作才暴露。来源中规格作者写前读全了首页 Fragment：横幅打开固定的火车票 H5、四张图各进详情页，规格却只写“进入对应业务”、验收允许 forward-ref，计划要求找不到目标就登记，worker 照此写出只含 FWD-REF 的空方法；两个目标页都是小页面，修复几分钟完成。

## 做法

1. 逐个列出可点击入口的源码目标：目标页面类、URL 常量与默认值、参数（如资讯索引），写进行为契约，不只写“打开对应业务页”。
2. 规格阶段就核对目标工程是否已有对应页面与路由；目标只是固定 URL 的 WebView 或静态详情一类小页面时纳入本轮范围；确实超出已批准范围时，向用户逐项列出“哪些入口点击将无反应”作为决策确认。
