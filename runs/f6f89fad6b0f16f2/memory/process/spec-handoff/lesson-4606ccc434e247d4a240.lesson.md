# 源端行为经 helper、DAO 或适配器层层委托时，追到最终实现再写规格与代码，不以调用点推断

ID：`lesson-4606ccc434e247d4a240` · 版本：1

[本主题](index.md)

## 何时使用

规格提取与页面、数据层实现阶段，源端调用点只是一行委托（Activity 调 DialogHelper.showXxx、Repository 经 DAO 调 Helper、Fragment 的分页适配器再建 item 适配器）时

## 适用情境

源端真正的布局、点击时序、数据来源或选中样式写在被委托的方法或类里：调用点只剩 DialogHelper.showXxxDialog(ctx) { 回调 }、repository.queryByDay → dao → DateHelper、CalendarViewPageAdapter(R.layout.item) → CalendarAdapter；规格按页面类或所有权切分，锚点只列到调用方。

## 原因

只看调用点会把调用方 lambda 当成全部行为，把 DAO 名称当成数据来源，把中间适配器当成样式来源。来源为同一应用的三类偏差：隐私弹窗的规格作者与实现者都没打开 DialogHelper，规格只写“显示同意弹窗、接受后继续”，实现者据此认为源端没有拒绝路径，写成单按钮弹窗，后来复刻又漏了同意区的勾选动画与 700ms 延时；农历数据的规格作者读 DAO 正文时被截断、没有打开 DateHelper，把“资产查询”写成数据来源，而源端实际逐日调用农历库计算；月历页的转换者看到分页适配器指向 item 适配器却没有继续读，选中、周末样式只能自拟。

## 做法

1. 调用点委托给 helper 或工具方法时，打开该方法全文和它 inflate 的布局或 Binding，列出控件、按钮分支和点击时序（状态变化 → 延时 → 回调 → dismiss）后再写。
2. 数据经 Repository、DAO、Helper 逐层委托时，追到最终实现确认来源（算法库、预置库、网络）；读取被截断就补读，规格的数据流与验收条目只写已核实的来源。
3. 列表或网格样式沿适配器链追到实际 item 适配器的 convert/onBind，按分支确认选中、当天、周末、节日等样式。
4. 规格提取时把被委托的实现文件与它用到的布局一并登记进源码锚点和页面契约，不只列调用方。
