# process/input-loading

写前输入是否真的进入上下文：必读 skill、规格、参考与源码片段的读取方式（含 Windows PowerShell 5.1 读取 UTF-8 中文的编码），长会话上下文压缩后的重读，派工要求的源码核对，辅助谓词与 getter 的定义，以及编排者亲自实现切片时要加载的输入

[上一级](../index.md)

## 本级经验

- [Windows PowerShell 5.1 读取 UTF-8 中文规格与账本要显式 -Encoding UTF8；回执出现乱码就当作没读](lesson-6a3a7f46c8fec282affa.lesson.md)
  - 时机：规格提取、切片实现与接线阶段，在 Windows PowerShell 5.1 下用 Get-Content/Select-String 读取功能规格、决策账本或中文注释源码时
  - 情境：迁移工程的规格、决策账本与计划为 UTF-8（无 BOM）中文 Markdown；读取者在 Windows PowerShell 5.1 中不带编码参数读取，回执里中文段落变成成片乱码，AC 编号、方法名、路径等 ASCII 片段仍然可读。
- [上下文压缩后续跑迁移流水线：把压缩前的规格与源码视为未读，按切片的 spec_ref、页面规格与源码锚点重读后再写计划和代码](lesson-f616adca9430826b1661.lesson.md)
  - 时机：计划与实现阶段，同一长会话经历上下文压缩后，为切片写 scope/验收/集成点，或写页面、ViewModel、数据层文件前
  - 情境：迁移流水线在一个会话里先产出逐页 UI 规格、功能规格与切片计划，随后发生上下文压缩；压缩摘要只保留功能名、规格路径或一句概括，切片计划、feature-index 或执行 skill 仍以 spec_ref、页面规格路径和源码类名指向这些输入。
  - 例外：压缩后已按原文完整重读了该切片对应的规格与源码片段
- [写码前要读全必读 skill、规格、参考文档与源布局/源码：批量读取被截断、命令只回来部分输出或只读前 N 行时，内容并未进入上下文](lesson-42df1ac4d4030421da34.lesson.md)
  - 时机：写码 worker 或规格作者开工时加载 skill、功能规格、预生成参考文档与源码，按源布局 XML 写页面、弹窗前读取源文件时，长会话压缩上下文后继续写码时，以及在回报中填写 loaded_skills 时
  - 情境：派工列出多份前置 skill（常见十几份 SKILL.md）或多份规格、参考文档，读取者用一次命令批量 cat，或用 sed -n '1,Np' 按固定行数读取；工具对单次输出有长度上限，超出时会省略中段并给出 truncated 提示。也包括一次 exec 批量读取多个源布局、源码或自定义 View，回执中段被省略；串联的查找命令因 yield 超时只返回第一段输出，其余结果只在未轮询的执行事件里；已加载的 skill 要求先读某份参考（如迁移陷阱表），读取者没有读，或只在 grep 回执里碰到片段、之后上下文被压缩。
- [派工要求按源码确认的内容（字段类型、请求体、凭证来源、码值、地址），规格看似完整或指定数据源查不到时都回源码核对；没读到就标未核实](lesson-93214f5a49c4d1d82316.lesson.md)
  - 时机：写码 worker 开工时：派工要求读 Android 源码确认字段、请求体或响应处理，手头的规格、锚点或上游产物却看似已给出签名；或规格指定的数据源里查不到具体值时
  - 情境：规格给出接口签名与源码锚点，没写字段类型、请求体字段、凭证来源或错误码取值；Kotlin 可以在一个 .kt 文件里定义多个类，kapt stub 按类拆分。
- [源端分支条件或文案插值依赖的辅助谓词、getter，要读到定义再翻译，不按名字推断](lesson-b3f534eb740a768d95a6.lesson.md)
  - 时机：业务逻辑与界面实现阶段，翻译以辅助谓词分派的切换方法（playPause/toggle），或转写把观察值插进文案模板的显示时；规格提取阶段写这类状态契约时
  - 情境：源码以 isPlayingState() 一类谓词分派 pause/play，或把 text 前缀的 LiveData&lt;String&gt;（格式化结果）拼进文案；读到的源码片段只含调用或相邻 getter，没有定义；同一 ViewModel 另有同名的原始数值字段。
- [编排者亲自实现切片（子代理不可用或未按流程派发）时，先加载切片 worker 本应拿到的全部输入，不凭占位登记表或摘要写代码](lesson-b90d7f55409a3a34253d.lesson.md)
  - 时机：执行编排阶段，子代理额度耗尽、限流或失败后，或执行 skill 规定按页派发转换子代理而编排会话决定直接代写时，编排者自己完成 Base/切片实现、页面转换、接线或解决前向引用时
  - 情境：编排会话原本只负责派工与收口，手上是占位登记表、feature-plan 的指针和子任务回报这类摘要；切片 worker 派工里列出的切片计划文件、功能规格验收条目、页面规格、决策账本正文和源码锚点，编排会话并没有打开过。
