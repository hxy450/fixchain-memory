# 功能对齐与验收结论逐项以代码落点为准：按规格验收项与导航出口检索实际组件和调用，空回调与只含注释的回调不算实现

ID：`lesson-9147be4d87153de9c5b6` · 版本：3

[本主题](index.md)

## 何时使用

验证阶段核对功能完成度，或实现、返修后向用户报告“已实现/已对齐”时

## 适用情境

验证检查只 grep TODO: 与占位登记表；实现者或返修者按功能点列对齐表并逐项打 ✅；规格写有验收条目、页面导航出口与启动触发条件。

## 原因

文本检索只能发现写了标记的占位，发现不了缺失的处理函数、只写注释的回调或没有调用者的函数；对齐表按意图打勾，未实现项就以“已完成”交付，直到用户操作时才暴露。来源中待办勾选、点击跳转、首次启动播种都被报告为已实现或完全一致，代码里却没有对应组件、跳转调用或启动路径调用。另一应用中首页横幅与四张资讯图的点击处理只含 FWD-REF 注释与 return，规格确认消息仍向用户称已对齐点击语义。另一应用中，实现者替换占位后报告“全部 AC 完成、无占位”，实际丢了温度与天气字段、未加载定位城市；另一实现者以占位清零判断完成，漏了规格里“登录成功后重载”的 AC；数据接线者只接了 40 日页的主接口，规格要求的趋势接口没有任何页面调用。

## 做法

1. 报告前按规格验收项逐条在当前代码中找到落点：组件（如 Checkbox）、ViewModel 方法、router/NavPathStack 调用、启动路径上的函数调用者；找不到就标未完成。
2. 验证阶段除检索 TODO 外，扫描空回调与回调体只有注释的 onClick，并把页面规格的导航出口与代码中的跳转调用逐项对账。
3. 实现者替换占位或宣布 AC 完成前，以 UI 壳已声明的展示字段和规格中带事件订阅锚点（onEventMainThread、@Subscribe）的 AC 为清单，逐项找到赋值与订阅的代码位置；占位清零不等于 AC 覆盖，暂缺的来源登记为缺口。
