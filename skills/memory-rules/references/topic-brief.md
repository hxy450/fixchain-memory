# 理主题任务书：给一个产物下的全部触发族定主题树

## 这是什么

这是安卓转鸿蒙（ArkTS）迁移的经验库。库里的「规矩」一条只讲一个触发、一个做法，给「任务刚做完、在审」的 agent 用。规矩按「产物 → 主题 → 触发族」组织：审的 agent 先看这个产物下有哪些主题，挑和自己手里的东西对得上的进去，再看主题下的触发族，最后看族里每条规矩的标题和触发。

触发族已经由别的子代理分好了：每个族有族名、目录名、一行「agent 会看到什么」，有的还有一条通用查法。它们各自给族写过一个建议的主题，但彼此没有商量过，名字和层级各不相同。你的工作是看完这个产物下的全部族，定一棵主题树，把每个族放进去，顺便把说的是同一类写法的族标出来合并。

## 你要做的

给你的是一份清单 `store\families\topic_lists\<产物目录>.json`（产物目录是 `spec`、`plan`、`code`、`resource` 之一）。里面有这个产物下每个族的标识（`family`，形如「提案号#序号」）、族名、族的一行、目录名、规矩条数、有没有通用查法（`general`）、建议的主题，以及建议主题的汇总。增量归并时不做这一步；只有第一次建库时，每个产物做一次。

写一个决定文件 `store\families\topic_decisions\<产物目录>.json`：

1. **定主题树。** 列出这个产物下的全部主题。每个主题有目录名、中文名和一行说明：agent 手里有什么东西时该进来看（读过的文件里有哪类写法，或者交回的产物里有哪类东西）。
2. **把每个族归到一个主题。** 每个族恰好归一次。族的名字、一行、目录名都不改。
3. **标出该合并的族。** 族名和族的一行说的是同一类写法的两个或几个族，标出来合并：写明并进哪个族、哪些族并进去、一句理由。并进去的族的规矩接在它后面，族名和一行用被并进的那个族的。两个族都有通用查法的不合并，列进 `review` 给人看。

## 怎么判断

- **按任务对象分，不按动作分。** 主题是 agent 手里的东西：文本、图片和图形、画布自绘、布局与尺寸、窗口与系统栏、输入与手势、列表与滚动、弹窗与浮层、导航与页面、主题与样式、资源文件、数据与存储、网络、媒体、权限、生命周期……（只是举例，照这个产物下实际有的族来定）。不用「改正」「补齐」「核对」这类动作做主题。
- **1–2 级。** 一级主题直接挂在产物下；一级主题下的族太多时再分二级。二级主题的目录写成「一级/二级」。（检查不限层数；第一次定树时用 1–2 级就够，以后哪里密了再按下面「拆一个超限的主题节点」加一层。）
- **每个节点的直接子项不超过 20 个。** 产物下的一级主题不超过 20 个；每个主题下的子主题和直接挂的族合起来不超过 20 个（合并之后的族算一个）。
- **主题的一行写 agent 看得到的东西。** 例如「源端有 TextView、EditText 等显示和输入文字的控件，或目标端有 Text、TextInput 时」，不写「文本相关的规矩」。
- **参考建议的主题，但不受它约束。** 建议的主题多半能看出族讲的对象；名字和层级以你定的为准。
- **合并要谨慎。** 只有族名和族的一行说的确实是同一类写法才合并（比如两个族都在讲「源端 TextView 的文字阴影属性」）；只是同一个控件、同一个话题下的不同写法，不合并。合并之后同一主题下的族目录名不能重复，重复的要么合并，要么分到不同主题。
- **目录名**用小写英文、数字和短横线；同一层里中文名不重复。不要有空主题。

## 输出

`store\families\topic_decisions\<产物目录>.json`（分支根目录下；UTF-8，不带 BOM，用 Write 工具写）：

```json
{
  "product": "代码",
  "topics": [
    {"dir": "ui", "name": "界面", "line": "源端是 View 和布局 XML、目标端是 ArkUI 组件时"},
    {"dir": "ui/text", "name": "文本", "line": "源端有 TextView、EditText 等文字控件，或目标端有 Text、TextInput 时"}
  ],
  "families": [
    {"family": "fam-0001#1", "topic": "ui/text"},
    {"family": "fam-0042#1", "topic": "ui/text"}
  ],
  "merge": [
    {"into": "fam-0001#1", "from": ["fam-0042#1"], "reason": "两个族说的都是源端 TextView 的文字阴影属性"}
  ],
  "review": [
    {"families": ["fam-0003#1", "fam-0077#2"], "reason": "族名和一行说的是同一类写法，但两个族都有通用查法，没有合并"}
  ]
}
```

- `topics` 里每个主题一项；二级主题的上级也要列出。
- `families` 里清单上的每个族恰好一项，被并掉的族也要列（它的主题以并进的那个族为准）。
- `merge`、`review` 没有就写空列表。

## 自检

写完在分支根目录下跑：

```
py -3 skills\memory-rules\scripts\families.py topics-check --product <产物目录>
```

它检查每个族恰好出现一次；主题目录名字合法，多级主题的上级列了，子主题和族的目录不同名；每个主题有中文名和一行；同一层里中文名不重复；每个节点的直接子项不超过 20 个；没有空主题；合并的族存在、不重复出现、不是两个都带通用查法；合并之后同一主题下族目录不重名。改到「违反 0 处」为止。

## 拆一个超限的主题节点

增量归并之后，某个主题（或产物根）下的直接子项可能超过 20 个。这时给你的不是整个产物的清单，而是一个节点的清单 `store\families\topic_splits\lists\<清单号>.json`（清单号形如 `ts-0001`）：`node` 是这个节点的主题目录（产物根是空串），`node_name`、`node_line` 是它的中文名和一行，`children` 是它的全部直接子项——子主题（`kind: "topic"`，带完整目录 `dir`、中文名、一行、下面有几个子项和几条规矩）和直接挂的族（`kind: "family"`，带 `family` 标识、族名、一行、目录名、规矩条数）。

你的工作是在这个节点下面加一层：按上面「怎么判断」的办法（按任务对象分、一行写 agent 看得到的东西、同一层中文名不重复），新起几个下一级主题，把子项分进去。

- 每个新主题写一级目录名（不带 `/`，脚本会接在这个节点后面）、中文名和一行。新主题的目录名不能和留在这个节点下的子项（族的目录名、子主题的最后一级）同名。
- 每个子项恰好分一次：分进某个新主题，或者留在原节点（`topic` 写 `""`）。子主题整棵挪下去，它下面的东西不变；族的名字、一行、目录名都不改。
- 拆完之后，这个节点的直接子项（新主题加留下的）和每个新主题的直接子项都不超过 20 个；没有空的新主题；分进同一个新主题的子项名字不重复。
- 不合并族，不改别的节点。

输出 `store\families\topic_splits\decisions\<清单号>.json`：

```json
{
  "split": "ts-0001",
  "node": "ui",
  "topics": [
    {"dir": "controls", "name": "基础控件", "line": "源端有 Button、CheckBox、Switch 等控件，或目标端有 Button、Toggle 时"}
  ],
  "assign": [
    {"family": "fam-0012#1", "topic": "controls"},
    {"topic_dir": "ui/text", "topic": "controls"},
    {"family": "fam-0040#2", "topic": ""}
  ]
}
```

自检：在分支根目录下跑 `py -3 skills\memory-rules\scripts\families.py topic-split-check --split <清单号>`，改到「违反 0 处」为止。交回时每份清单一行：新起了几个主题（中文名）、各分进几个子项、留下几个。只读本任务书、给你的清单和 `store\families\topics.json`；只往 `store\families\topic_splits\decisions\` 里写。

## 不许做的

- 只读这些：`skills\memory-rules\references\` 下的本任务书和 `format.md`；检查用的 `skills\memory-rules\scripts\families.py`；给你的清单文件 `store\families\topic_lists\<产物目录>.json`（拆节点时是 `store\families\topic_splits\lists\<清单号>.json`）；`store\families\topics.json`。其他文件和目录一律不打开，包括规矩的原件和正文、卡文件、`store\` 下的卡原件和快照、`store\candidates\`、`store\merge\`、`memory\` 下已有的经验，以及任何具体应用的源码和迁移工程。
- 只往 `store\families\topic_decisions\` 里写，一个产物一个文件（拆节点时只往 `store\families\topic_splits\decisions\` 里写，一份清单一个文件）。临时文件放在本会话的临时目录。
- 不打开凭据文件（文件名或路径带 key、token、credential 的）。
- 不调用任何模型 API，不起子代理。不联网。
- 不改任何已有文件；Python 脚本设 `sys.dont_write_bytecode = True`。

## 交回

不超过 20 行：这个产物下几个族、定了几个一级主题和几个二级主题（列出一级主题的中文名）、合并了几处、列进 review 的几处；拿不准的地方；`families.py topics-check --product <产物目录>` 的最后一行。
