# dark 的 color.json 要覆盖页面引用的全部 app.color 键，缺口写进 decision_gaps

审的是：资源
触发（任一种）：
- 读到：验收条目要求页面配色随深浅资源限定符切换；页面和共享常量里引用 $r('app.color.…')；写错的样子：dark/element/color.json 的键少于 base/element/color.json 里页面用到的 app.color 键（自检输出如 base 15 / dark 8），交付说明 Spec Gap 写「无差异」、decision_gaps 为空
适用范围：拥有视觉深色验收的切片或收口检查交付前
做法：
- 交付前列出页面引用的全部 $r('app.color.<键>')，逐个查 dark/element/color.json 有没有同名条目；再 grep 页面和共享常量里的中性色 hex
- 有缺口就补 dark 值或写进 decision_gaps，不报「无差异」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 限定词目录里找不到该资源时才去 base 目录查找：dark 里缺的键在深色模式下取 base 的浅色值，所以缺键表现为深色下仍是浅色（出处：resource-categories-and-access.md，资源匹配）
- 颜色模式限定词：dark 深色模式、light 浅色模式：dark 目录就是深色模式的限定词目录（出处：resource-categories-and-access.md，限定词目录（表5 限定词取值要求））
- 设置页背景键只有 base 值时，深色开关打开后页面仍全白；dark 补齐后正常：卡里观察到的缺键表现和修复（出处：卡里修好并验证过）
