# Text 要用主题次要文字色而目标工程没有这项颜色资源时，base 和 dark 各补一份

审的是：资源
触发（任一种）：
- 读到：源 TextView 没写 android:textColor，颜色来自 DayNight 一类主题的 ?android:textColorSecondary；写错的样子：resources/base/element/color.json 里没有对应的次要文字色；或者只在 base 里有，resources/dark/element/color.json 缺同名项
适用范围：源控件颜色取自主题默认、目标 Text 要显式写 fontColor 并通过 $r 引用颜色资源时
做法：
- 在 resources/base/element/color.json 加一项次要文字色，value 写浅色值（AppCompat/Material 默认 #8A000000）；在 resources/dark/element/color.json 加同名项，value 写深色值（默认 #B3FFFFFF）
- 这次任务不写资源时，把这项颜色登记为待补资源，不让代码留空颜色
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- {"color": [{"name": "…", "value": "#8a000000"}]}；八位十六进制，前两位是透明度：element/color.json 的写法（出处：resource-categories-and-access.md，资源文件示例）
- 颜色模式限定词 dark（深色）、light（浅色），目录写成 dark/element：深色值放在 resources/dark/element/color.json（出处：resource-categories-and-access.md，限定词目录；创建资源目录和资源文件）
- 先在匹配设备状态的限定词目录里找，找不到才去 base：dark 里缺这一项时深色模式下会用 base 的浅色值（出处：resource-categories-and-access.md，资源匹配）
- secondary_text_default_material_light = #8a000000；secondary_text_default_material_dark = #b3ffffff：AppCompat/Material 默认次要文字色的浅色、深色值（出处：androidx.appcompat:appcompat 包内 res/values/values.xml，secondary_text_default_material_light / secondary_text_default_material_dark（按应用依赖的版本））
针对本应用要查的：
- 应用主题有没有覆盖次要文字色，以及有没有 values-night 变体：源工程 AndroidManifest.xml 的 android:theme 指向的主题，在 res/values/ 和 res/values-night/ 的 styles.xml 或 themes.xml 里找 textColorSecondary、textColorTertiary；没覆盖就用主题族默认的两份值；有覆盖就分别解析浅色、深色下的颜色写进 base 和 dark
- 目标工程里有没有语义相同的颜色项：目标工程 resources/base/element/color.json 和 resources/dark/element/color.json，按名字和值找；已有就复用并补齐缺的那一侧；没有就新建同名两项
