# 布局用 ?attr 引用主题色时，给每个主题属性建 base/dark 成对颜色键，@color 写死的保留单态

审的是：资源
触发（任一种）：
- 读到：布局里有 ?attr/colorPrimary、?attr/colorAccent（Toolbar、ActionBar、抽屉选中项），主题里设了这些属性且日夜取值不同；另有 @color/colorPrimary 写死的引用；写错的样子：base/element/color.json 里只有 colors.xml 直迁的 colorPrimary 等单态常量，dark/element/color.json 里没有主题属性对应的同名键
适用范围：资源前置阶段导出颜色键，源端主题属性色在日夜两态取值不同时
做法：
- 每个被 ?attr 引用的主题属性建一对同名键（如 theme_primary、theme_primary_dark、theme_accent）：base/element/color.json 写日间主题解析出的值，dark/element/color.json 写夜间解析出的值（夜间没写的项取父主题夜间默认）
- @color/ 写死的引用保留 colors.xml 直迁的单态常量；android:windowBackground 也建成对键（如 window_background）
- 框架默认值先查依赖的 appcompat 资源再写入，查不到才登记未决，不以「不猜」为由不导出
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- resources 下建限定词目录 dark，在 base/element/color.json 和 dark/element/color.json 里定义同名颜色、赋不同的值：深色模式下 $r('app.color.<同名键>') 取 dark 里的值（出处：ui-dark-light-color-adaptation.md，应用跟随系统的深浅色模式）
- 颜色模式限定词取值 dark（深色）、light（浅色）：dark 目录名的依据（出处：resource-categories-and-access.md，限定词目录）
- 返修新增主题属性成对键并写入夜间值后，各处改引用这些键，深色模式显示正确：卡里的修法（出处：卡里修好并验证过）
针对本应用要查的：
- 每个主题属性日间和夜间的值：源工程 values/styles.xml 与 values-night/styles.xml 里应用主题的同名 item；夜间没写的，到依赖库 androidx.appcompat:appcompat（按应用依赖的版本）包内 res/values-night-v8/values-night-v8.xml 和 res/values/values.xml 顺着 parent 链找；顺着 @color 引用解析到十六进制值，日间写进 base、夜间写进 dark
