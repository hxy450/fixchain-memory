# @android:color 系统色按固定表转十六进制，动态色无引用就删、有引用给明确 hex 回退

审的是：资源
触发（任一种）：
- 读到：colors.xml 的值引用 @android:color/black、@android:color/white、@android:color/transparent，或 Android 12+ 动态色 @android:color/system_accent1_500、system_neutral1_*、system_error_* 一类；写错的样子：color.json 里原样写着 @android:color/…，或动态色条目既没有 hex 回退、映射文档也没注明近似
适用范围：颜色资源转换里引用了 Android 平台颜色的条目
做法：
- 固定色按表转：@android:color/black → #FF000000、@android:color/white → #FFFFFFFF、@android:color/transparent → #00000000
- system_accent / system_neutral / system_error 等动态色鸿蒙没有对应：确认目标里没有引用就删掉条目；有引用就给明确的 hex 回退（卡里用 M3 基准值、按 tone 近似），并在映射文档注明是近似
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- black = #ff000000、white = #ffffffff、transparent = #00000000：三个固定系统色的定义值（出处：Android SDK 平台资源 data/res/values/colors.xml，black / white / transparent（按应用的 compileSdk 取对应平台））
- 反编译出的 @android:color/* 动态色条目和指向未定义目标的 @color/ 条目全部零代码引用，改成 hex 后资源编译通过：动态色多半没人引用，可以删或给回退（出处：卡里修好并验证过）
针对本应用要查的：
- 动态色条目在目标里有没有引用：目标工程的 .ets 文件和 resources 下各 element JSON，按 $r('app.color.名字') 和 $color:名字 搜；零引用就删掉条目；有引用就给 hex 回退并在映射文档写明近似
