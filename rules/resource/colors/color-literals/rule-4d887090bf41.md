# colors.xml 的 8 位色 #AARRGGBB 原样写进 color.json，不重排成 #RRGGBBAA

审的是：资源
触发（任一种）：
- 读到：源 res/values*/colors.xml 里有 8 位带透明度的 <color>（#AARRGGBB，前两位是透明度，如 #80000000）；写错的样子：目标 element/color.json 里同名键的值首两位和末两位互换（成了 #RRGGBBAA），或转换脚本把 a、r、g、b 拆开后按 {r}{g}{b}{a} 输出
适用范围：把安卓 colors.xml 批量转换成鸿蒙 color.json（含编排者或 worker 自写的转换脚本）时的颜色值格式
做法：
- 8 位值按 #AARRGGBB 原样写进 color.json 的 value，前两位仍是透明度；不套用 CSS 的 #RRGGBBAA
- 转换后逐项往返核对：同名键的安卓值先归一化成 #AARRGGBB（3/4/6 位补全），应与 color.json 的值相等；「首两位和末两位互换后才相等」的项判为字节序错误，改正后再交付
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 安卓颜色串支持 #RRGGBB、#AARRGGBB：源端 8 位值前两位是透明度（出处：android.graphics.Color#parseColor）
- color.json：八位十六进制，前两位表示透明度，后六位表示颜色值：目标端也是 #AARRGGBB，两边同序，照抄即可（出处：resource-categories-and-access.md，资源文件示例）
- ResourceColor 的 string 支持 rgb、rgba、argb；argb 示例 '#ff000000'，rgba 只有 rgba(…) 函数写法：鸿蒙不按 #RRGGBBAA 解析 8 位串（出处：ts-types.md，ResourceColor）
- 比对工具逐项比对安卓 values*/colors 与 color.json，标出 ARGB 互换项后回正，结果与源一致：修好后的核对办法（出处：卡里修好并验证过）
