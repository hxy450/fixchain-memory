# colors.xml 转 color.json 时值只能是十六进制或已定义的 $color:name，不原样写引用

审的是：资源
触发（任一种）：
- 读到：colors.xml 的 <color> 值是 @android:color/…、指向本次没转换资源的 @color/name，或 ?attr/…；写错的样子：color.json 里出现 "value": "@android:color/black"、"@color/…"、"?attr/…"，或 $color:name 指向文件里没有的条目
适用范围：把 Android values 颜色（源 res 或反编译 APK）批量转成 resources/base/element/color.json 时，转换脚本或手写都算
做法：
- 每个值只允许两种出口：#rgb / #argb / #rrggbb / #aarrggbb，或指向本文件已定义条目的 $color:name；@color/name 解析到已转换的条目时写成 $color:name
- 解析不到时不返回原值：落地一个确定的回退值，或者不输出该条目，并记进转换报告
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- {"color": [{"name": "…", "value": "#ffff0000"}]}，value 是 8 位十六进制、前两位透明度：color.json 的结构和颜色值格式（出处：resource-categories-and-access.md，资源文件示例）
- color.json 里留着 @android:color/black 时，编译在 CompileResource 报 Invalid color value '@android:color/black'；改成 hex 后通过：原样写进去的 Android 引用会让资源编译失败（出处：卡里修好并验证过）
未核实：卡里的工程是 API 24，本机按 API 23 的文档和声明核实
