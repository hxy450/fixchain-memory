# 本地 HTML 缺 viewport meta 时，在 rawfile 的 HTML 里补上它

审的是：资源
触发（任一种）：
- 读到：`WebView` 加载 `file:///android_asset/` 下的 HTML，它的 `<head>` 里没有 `<meta name="viewport"`，源端也没调 `setUseWideViewPort(true)`；写错的样子：rawfile 里那份 HTML 的 `<head>` 仍没有 viewport meta；或者 `Web` 上写了 `.metaViewport(false)` 想模拟按 WebView 宽度排版
适用范围：源 WebView 未开 useWideViewPort、加载的本地 HTML 没有 viewport meta，迁成 ArkWeb Web 加载 rawfile 时
做法：
- 在 rawfile 那份 HTML 的 <head> 里加 <meta name="viewport" content="width=device-width, initial-scale=1">，作为 useWideViewPort=false（按 WebView 宽度排版）的等价设置
- Web 上的 metaViewport 保持默认解析（不写，或写 .metaViewport(true)），不要用 .metaViewport(false)
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 页面没有 viewport meta 时，ArkWeb 不按 Web 组件宽度排版；加上 width=device-width, initial-scale=1 后与安卓默认一致：安卓默认按 WebView 宽度排版，ArkWeb 要靠 viewport meta 才能等价（出处：卡里修好并验证过）
- setUseWideViewPort 为 false 时，布局宽度始终是 WebView 控件的宽度（CSS 像素）：源端没调用时的排版宽度（出处：android.webkit.WebSettings#setUseWideViewPort）
- metaViewport(enabled: boolean): WebAttribute，默认 true；false 时不解析 viewport、用默认布局；2in1 设备上不管设什么都不解析：metaViewport(false) 会让补上的 viewport meta 失效（出处：鸿蒙 SDK 的 ets/component/web.d.ts，WebAttribute.metaViewport）
- textAutosizing 生效的前提之一：前端没有 viewport meta，或 viewport meta 里没有 width 和 initial-scale：补上带 width 和 initial-scale 的 viewport meta 后，文本自动缩放不再生效（出处：鸿蒙 SDK 的 ets/component/web.d.ts，WebAttribute.textAutosizing）
针对本应用要查的：
- 源端加载的本地 HTML 有没有 viewport meta：源工程 assets 下被 loadUrl 加载的 HTML 文件，搜 name="viewport"；没有这一行就要在迁到 rawfile 的那份里补上；已有的照搬
未核实：卡里的观察出自 HarmonyOS 6.1.1(24)，本机声明按 API 23 核实
