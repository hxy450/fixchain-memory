# 权限按所调接口的 @permission 声明，不照第三方文档加 MANAGE_BLUETOOTH

审的是：资源
触发（任一种）：
- 读到：第三方（如打印机）SDK 文档要求声明 ohos.permission.MANAGE_BLUETOOTH；或真机安装因系统级权限被拒；写错的样子：module.json5 的 requestPermissions 里有 ohos.permission.MANAGE_BLUETOOTH；或删权限时连带把应用内开关改成跳系统设置
适用范围：鸿蒙工程为蓝牙等能力在 module.json5 里声明权限，或因安装失败删权限时
做法：
- requestPermissions 只列所调接口 @permission 里写的权限：access 的开关、状态接口要 { "name": "ohos.permission.ACCESS_BLUETOOTH", "reason": "$string:…", "usedScene": { "abilities": ["…"], "when": "inuse" } }
- 安装因系统级权限失败时，只删没被实际调用的接口要求的那条；删前删后都不把应用内开关降级成跳转系统设置
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- ohos.permission.ACCESS_BLUETOOTH：权限级别 normal，授权方式 user_grant，起始版本 10：普通应用可申请；user_grant 还要在运行时向用户申请（出处：permissions-for-all-user.md，ohos.permission.ACCESS_BLUETOOTH）
- ohos.permission.MANAGE_BLUETOOTH：权限级别 system_basic，授权方式 system_grant：系统级权限，普通应用声明后真机安装被拒（出处：permissions-for-system-apps.md，ohos.permission.MANAGE_BLUETOOTH）
- 申请 user_grant 权限时 reason 必填、usedScene 必填，when 只能填 inuse 或 always：ACCESS_BLUETOOTH 这一条声明要带的字段（出处：declare-permissions.md，在配置文件中声明权限）
- 声明 MANAGE_BLUETOOTH 后真机安装被拒：卡里观察到的行为（出处：卡里修好并验证过）
