# requestPermissions 以代码实际调用的受权限接口为准汇总，user_grant 权限补 reason

审的是：资源
触发（任一种）：
- 读到：目标 .ets 里调用 sensor.on(SensorId.GYROSCOPE …)、deleteAssets、createAsset 等声明 @permission 的接口；登记表里有要求声明 WRITE_IMAGEVIDEO 的移交项，规格权限节却写「不申请（媒体库路径）」；写错的样子：module.json5 的 requestPermissions 缺 ohos.permission.ACCELEROMETER / GYROSCOPE / WRITE_IMAGEVIDEO，或以规格措辞否决了有 SDK 依据的移交项；user_grant 权限没有 reason 字符串
适用范围：权限归口阶段汇总 module.json5 requestPermissions 和权限 reason 字符串时
做法：
- 在 ets 里搜 sensor.on、deleteAssets、createAsset 等受权限接口的调用，与 requestPermissions 逐项对照补齐
- 规格与移交项冲突时用声明或 skill 文档核实，不以规格措辞否决已有依据的移交项
- user_grant 权限写 { name, reason: "$string:…", usedScene }，reason 字符串在 base 和各语言的 string.json 里都加
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 申请 user_grant / manual_settings 权限时 reason 必填并需多语种适配，格式 $string: ***：WRITE_IMAGEVIDEO 这类用户授权权限要配 reason 字符串（出处：declare-permissions.md，在配置文件中声明权限）
- ACCELEROMETER、GYROSCOPE 是 system_grant；WRITE_IMAGEVIDEO 是受限的 system_basic、user_grant：前两个只需声明，后者还要 reason、运行时请求和受限权限的申请（出处：permissions-for-all.md，ohos.permission.ACCELEROMETER；restricted-permissions.md，ohos.permission.WRITE_IMAGEVIDEO）
- WRITE_IMAGEVIDEO 在签名 ACL 下有效：受限权限要在签名配置里申请 ACL（出处：卡里修好并验证过）
未核实：卡里环境是鸿蒙 6.1.1(24)，本机按 API 23 核对
