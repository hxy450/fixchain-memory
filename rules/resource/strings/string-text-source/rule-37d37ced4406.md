# 为新引用的字符串键补值时，回查源布局或原字面量，不按键名自拟文案

审的是：资源
触发（任一种）：
- 读到：代码里新出现的 `$r('app.string.…')` 引用在 `string.json` 里没有定义，交接只给了键名；写错的样子：`string.json` 里按键名自拟了新文案（如 step 类键写成「第1站」），和源端 `android:text` 或替换前的字面量不一致
- 写错的样子：固定宽高的徽标、角标类 `Text`（写死了 `.width(...)` 和 `.height(...)`）引用的资源值比源端同位置的值长
适用范围：收口阶段在共享 string.json 里为别人新加的引用补值时
做法：
- 按页面 anchor 回查安卓源布局的 android:text 或 strings.xml，以及该引用替换前的代码字面量，值照抄
- 找不到来源时登记缺口，不从键名推断、不自拟文案
- 补值后对照显示容器：固定宽高的徽标/角标 Text 只放源端同长度的内容，新值更长就视为偏差回查
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 徽标按键名写成「第1站」时小尺寸圆形徽标里只显示出第一个字；改回源端的 "1"～"4" 后恢复：自拟文案在固定尺寸容器里直接显示错（出处：卡里修好并验证过）
针对本应用要查的：
- 键对应的源端文案：源工程该页布局 XML 里对应控件的 android:text（引用 @string/… 的再去 res/values/strings.xml），以及目标代码改成 $r 之前的字面量；照抄成 string.json 里该键的 value；多语言目录按源端对应语言的 strings.xml 取
