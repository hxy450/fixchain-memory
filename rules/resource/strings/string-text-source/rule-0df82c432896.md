# 代码引用 android.R.string.* 系统文案时，替代的应用字符串要补到每个已有语言目录

审的是：资源
触发（任一种）：
- 读到：Kotlin / Compose 里 stringResource(android.R.string.ok) 或 getString(android.R.string.cancel) 这类平台字符串引用；写错的样子：新加的键只写进 base/element/string.json（值是英文 OK），工程已有的各语言目录里没有这个键，也没登记 `resource-pending-translation`
适用范围：页面实现时把安卓平台字符串换成应用自己的字符串资源、而目标工程已有多个语言目录时
做法：
- 先列出目标 resources 下已有的语言目录；为每个目录在 <语言>/element/string.json 里补同名键，值取平台资源里对应语言的译文
- 某个语言补不出译文时登记待译占位 `resource-pending-translation`，不能只写 base 英文
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- <public type="string" name="ok" id="0x0104000a" />：android.R.string.ok 是平台公开字符串，随系统语言翻译（出处：Android SDK 平台资源 data/res/values/public-final.xml，string/ok（按应用的 compileSdk 取对应平台））
- <string name="ok">OK</string>：平台默认（英文）值；各语言译文在 data/res/values-<限定词>/strings.xml 的同名项（出处：Android SDK 平台资源 data/res/values/strings.xml，string/ok（按应用的 compileSdk 取对应平台））
- 设备状态匹配的限定词目录里找不到该资源时，才去 base 目录查找：只写 base 时，非英文界面拿到的是 base 里的英文（出处：resource-categories-and-access.md，资源匹配）
- 从平台资源导出系统 ok 译文，为 11 种语言及 zh_TW / zh_HK 加入同名键：修好后的做法（出处：卡里修好并验证过）
针对本应用要查的：
- 每个已有语言目录对应的系统译文：Android SDK 平台资源 data/res/values-<限定词>/strings.xml（按应用的 compileSdk 取对应平台），按代码里 android.R.string 后面的名字找同名 <string>；取引号里的文字写进目标对应语言目录的 string.json；源 values-zh-rCN 对目标 zh_CN、values-zh-rTW 对 zh_TW。例：android-36 下 values-zh-rCN 的 ok 是「确定」
未核实：卡里环境的 compileSdk 未标明，平台资源按 android-36 核实
