# 带 <b>/<a>/CDATA 的 strings.xml 串按 HTML 存进 string.json 并列清单

审的是：资源
触发（任一种）：
- 读到：strings.xml 的 <string> 里内联 <b> / <i> / <u> / <a href> / <br>，或用 <![CDATA[ … ]]> 包 HTML；写错的样子：string.json 里这些键的标记和 href 被丢掉成了纯文本，转换脚本用 ''.join(el.itertext()) 之类只取文本的写法；或 CDATA 键原样留着 HTML 却没人登记
适用范围：资源转换阶段把安卓 strings.xml 转成鸿蒙 string.json 时
做法：
- 先列出含 <b>/<i>/<u>/<a>/<br>/CDATA 的键，值按 HTML 保存（字面的 < 和 & 转义），不用 itertext 或去标签的方式转换
- 交付一份带样式键清单，标出各键的消费方式：setMessage(resId) / android:text 走 Styled，getString + Html.fromHtml 走 Html，并注明是否设了 LinkMovementMethod
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Resources#getText 返回带样式信息的 CharSequence；Resources#getString 去掉样式信息：按 resId 直接取文本的消费方会保留 <b>/<a> 样式，getString 则不保留，消费方式决定目标怎么渲染（出处：android.content.res.Resources#getText、android.content.res.Resources#getString）
- AlertDialog.Builder.setMessage(int) 用 getText(messageId) 取文：setMessage(resId) 属于 Styled 通路（出处：android.app.AlertDialog.Builder#setMessage）
- 带标记键按 HTML 保存进 string.json：修好后链接和粗体信息都保留到目标端（出处：卡里修好并验证过）
针对本应用要查的：
- 每个带样式键在源端怎么被消费：源工程 Java / Kotlin 里引用该 R.string 的调用点和布局 XML 的 android:text；setMessage(resId)、getText、android:text 记为 Styled；getString 再 Html.fromHtml / HtmlCompat.fromHtml 记为 Html；同一控件 setMovementMethod(LinkMovementMethod) 的记为链接可点
