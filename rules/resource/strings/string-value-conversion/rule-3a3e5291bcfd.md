# strings.xml 值中间有未转义双引号时，string.json 里去掉它，只有 \" 转义的保留

审的是：资源
触发（任一种）：
- 读到：源 strings.xml 的 `<string>` 文本中间出现前面没有反斜杠的 `"`（不是整值首尾包裹，形如 文字 "词" 文字）；写错的样子：目标 string.json 对应的 `value` 里残留这对引号（JSON 里写成 `\"`），或转换脚本只在值首尾都是 `"` 时才剥引号
适用范围：安卓 strings.xml（含各语言限定目录下的同名文件）转成鸿蒙 element/string.json 时的每个字符串值
做法：
- 取值时不看位置：值里任何位置前面没有反斜杠的 `"` 都去掉（它只用来保护空白），`\"` 还原成 `"` 保留；整值首尾包裹只是其中一种情形
- 转换前用正则列出源值里含未转义 `"` 的键（各语言一并）作必测样本；转换后逐键核对：这些键的目标值不残留引号，`\"` 转义的键目标值保留引号，抽查同时覆盖整值包裹和值中间出现两种形态
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 安卓端显示的文本里没有值中间那对未转义引号；string.json 的 value 不再经过 aapt2，运行时原样显示：所以引号要在转换时去掉，留到目标端就会多显示出来（出处：卡里修好并验证过）
- {"string": [{"name": "…", "value": "…"}]}：string.json 的结构，value 是普通 JSON 字符串，要显示的引号才按 JSON 写成 \"（出处：resource-categories-and-access.md，资源文件示例）
针对本应用要查的：
- 源工程里哪些键的值中间带未转义双引号：源工程 res/values*/strings.xml 里各 `<string>` 的文本；去掉首尾包裹的一对引号后，仍能搜到前面没有反斜杠的 " 的键，就是必测样本
未核实：aapt2 剥离值中未转义双引号的规则出自卡，本机来源里没有找到原文
