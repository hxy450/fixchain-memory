# string-array 转 strarray.json 时每项写成 value 对象，镜像到限定目录前先自检结构

审的是：资源
触发（任一种）：
- 读到：源端 values/arrays.xml 里的 <string-array>（或 <integer-array>、<plurals>）；写错的样子：element/strarray.json 写成 {"name": n, "value": ["…", "…"]}，数组项是纯字符串；编译报 `The value type of node 'value's child' does not match. Expected type: object`
适用范围：用脚本批量把安卓 values 下的数组资源转成鸿蒙 element JSON，并复制到 zh_CN 等限定目录时
做法：
- 逐类对照目标 JSON 结构输出：strarray、intarray 写成 { "name": n, "value": [ { "value": 项 }, … ] }，plural 写成 { "name": n, "value": [ { "quantity": …, "value": … } ] }；不把从 XML 解析出的列表直接作 value
- 脚本跑完后断言 strarray 每个 value 项都是含 value 键的对象；通过后再复制或镜像到限定目录
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- { "strarray": [ { "name": "test", "value": [ { "value": "I'm one of the array's values." } ] } ] }：strarray.json 的结构，数组项是对象（出处：js-apis-resource-manager.md，getStringArrayValueSync）
- plural 每项是 { "quantity": "one", "value": "%d apple" } 这样的对象：plural.json 的结构（出处：resource-categories-and-access.md，资源文件示例）
- element 目录下 intarray、strarray、plural 等每类一个 JSON 文件，每个文件只放同一类型：转换输出的文件划分（出处：resource-categories-and-access.md，资源组目录）
- 每项包成 {"value": …} 后编译通过：修复后的结构（出处：卡里修好并验证过）
未核实：intarray 的对象项结构出自卡的建议，文档副本里没找到 intarray 的 JSON 示例
