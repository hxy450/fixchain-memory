# 迁字符串资源时取含库依赖的合并资源表，不把应用源 res/ 的 values-* 当全集

审的是：资源
触发（任一种）：
- 读到：Gradle 构建脚本的 dependencies 里有 androidx.appcompat、material、androidx.preference 等自带字符串资源的库；迁移 skill 要求先构建 APK 再反编译取合并资源表；写错的样子：目标 resources 下的语言目录只有应用 res/values-* 那几种，只有库才提供的语言（如 ko、th、vi）和框架、库的译文都没有；报告写「source res/ · build=skipped」且没列缺失的库资源
适用范围：资源迁移阶段确定字符串资源的来源范围、要求 1:1 复刻到 resources/<locale>/element 时
做法：
- 按 skill 顺序先尝试构建 APK 并反编译（apktool 或 aapt2）取合并资源表，按它的键集和语言目录镜像 string.json
- 确实无法构建时，至少解析 Gradle 构建脚本的 dependencies，把各库的 values-* 译文和语言目录并入，并在报告里逐项列出缺失的库资源
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 按合并资源表逐键比对后，镜像出远多于应用 res/ 的语言目录，并补上框架的 ok、cancel：修好的来源范围（出处：卡里修好并验证过）
针对本应用要查的：
- 某个依赖库自带的字符串和语言目录：Gradle 缓存里该库解包后的 aar（transforms 下的 <artifact>-<version>）的 res/values-<语言>/ 目录，按应用依赖的版本取；每个 values-<语言> 目录就是库提供的一种语言，里面的 <string> 按名字并入对应语言的 string.json
- 框架提供的字符串（@android:string/…）：Android SDK 平台资源 data/res/values-<语言>/strings.xml，按应用的 compileSdk 取对应平台；按 name 取各语言的值
