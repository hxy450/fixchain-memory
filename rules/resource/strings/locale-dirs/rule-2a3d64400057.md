# 资源迁移按源端全部 values-* 建对应限定词目录，范围约定无来源时不照缩

审的是：资源
触发（任一种）：
- 读到：源工程 res/values-es、res/values-zh-rTW 等多个语言目录；项目文档写「默认迁 values + values-zh」，资源转换规则写语言数不超过 10 时全部转换；写错的样子：目标 resources/ 下只有 resources/base 和 zh_CN 两个限定词目录，源端其余语言缺失
适用范围：资源迁移阶段把安卓 values-* 语言资源转成鸿蒙限定词目录时
做法：
- 每个 values-<lang>[-r<REGION>] 建一个 resources/<lang>[_<REGION>]/element/string.json（如 values-zh-rTW → zh_TW），内容照该目录的 strings.xml 转
- 项目文档的范围约定与资源转换规则或功能基线冲突时，先核对约定有没有用户或决策来源；没有就按源端全集转，或作为显式冲突上报，不以「项目决策优先」静默覆盖
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 语言、文字、国家或地区之间用下划线连接，如 zh_CN、zh_Hant_CN：限定词目录的写法（出处：resource-categories-and-access.md，限定词目录）
- 区域限定词可取：语言、语言_文字、语言_国家或地区、语言_文字_国家或地区：values-es 这类只有语言的目录可以只写语言（出处：resource-categories-and-access.md，资源匹配）
- 补建 es、fr、it、pt、ru、zh_TW 资源后应用内各语言选项都显示对应文案：改后的效果（出处：卡里修好并验证过）
针对本应用要查的：
- 源端每个语言目录对应的限定词：源工程模块的 res/ 下 values-<语言>[-r<地区>] 子目录名；语言照抄，-r 后的地区码接在下划线后。例：values-pt → pt，values-zh-rTW → zh_TW
