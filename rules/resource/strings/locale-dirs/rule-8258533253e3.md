# 某语言缺的字符串键保留缺失让运行时回退默认语言，不用 TODO 填平再交模型补译

审的是：资源
触发（任一种）：
- 读到：源端某个 values-<语言> 目录的 strings.xml 缺部分 <string> 键（运行时回退默认 values）；写错的样子：缺键用默认语言文本加 `[TODO: translate]` 前缀填平并登记待译，或该语言 string.json 里出现源端没有的模型译文
适用范围：资源迁移阶段处理某 locale 缺键时，以及按 1:1 复刻要求审各语言 string.json
不适用的情形：用户明确要求新增翻译时才补译
做法：
- 该语言的 string.json 里不写这个键（或直接镜像合并资源表的键集），由运行时回退到 base
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 限定词目录里找不到该资源时，才去 base 目录中查找：目标端缺键会自动回退 base，和源端回退默认 values 一致（出处：resource-categories-and-access.md，资源匹配）
- 按合并资源表逐键比对，删除原版不存在的模型译文：修好的写法（出处：卡里修好并验证过）
