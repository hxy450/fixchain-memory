# 源端只有默认 values/ 时只生成 base 字符串，不合成 zh_CN 等译文

审的是：资源
触发（任一种）：
- 读到：源 res 下只有默认 `values/strings.xml`，没有 `values-zh` 等 values-<locale> 语言目录（`values-night`、`values-xlarge` 不是语言目录）；写错的样子：目标出现 `zh_CN/element/string.json`（或 `plural.json`），业务键的值是源端没有的中文译文
- 读到：规格写「资源默认文案为英文，迁移不擅自翻译」，资源转换 skill 却写「至少生成 2 套语言资源；默认英文时生成 base + zh_CN」；写错的样子：按 skill 生成了 `zh_CN` 目录并填中文业务值，只以 base 与 zh_CN 键一致作为通过依据
适用范围：资源迁移阶段决定目标工程生成哪些语言限定字符串目录、各键取什么值时
做法：
- 先盘点源工程实际存在的 values-<locale> 目录，只为这些语言生成目标限定目录；源只有默认 values/ 时只生成 base/element/string.json 等，不合成 zh_CN 等译文
- 流程确需保留第二语言目录（如 app、ability 脚手架键）时，业务键省略以回落 base，或取值与 base 完全相同；非 base 目录里和 base 取值不同的业务字符串，必须能追溯到对应的 Android values-<locale> 源条目
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 系统先从和设备状态匹配的限定词目录找资源；没有匹配的限定词目录、或目录里找不到该资源时，才去 base 目录找：zh_CN 里省略业务键，这些键就回落到 base 的原文（出处：resource-categories-and-access.md，资源匹配）
- zh-Hans 系统语言的设备上 HarmonyOS 优先取 zh_CN，界面出现中文或中英混排，而安卓同设备显示英文；把 zh_CN 裁到只剩 app、ability、widget 键后业务串回落 base 英文：多出来的 zh_CN 会让目标和源端逐屏对不上（出处：卡里修好并验证过）
- 限定词目录里区域的组合是 语言、语言_文字、语言_国家或地区、语言_文字_国家或地区，如 zh_CN：源端 values-<locale> 对应到目标限定目录时的命名（出处：resource-categories-and-access.md，限定词目录与设备状态的匹配规则）
针对本应用要查的：
- 源端实际有哪些语言：源工程各模块 res/ 下的 values-<限定词> 目录名；只算带语言或地区限定词的（如 values-zh、values-de）；values-night、values-xlarge 这类不是语言目录
