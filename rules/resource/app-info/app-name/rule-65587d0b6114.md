# 身份落地改了 EntryAbility_label/app_name 后，所有语言目录的同名键一并同步

审的是：资源
触发（任一种）：
- 读到：身份落地步骤读到源端应用名（manifest `android:label` 引用的字符串），要消除脚手架默认值；写错的样子：只改了 AppScope 和 entry `base/element/string.json` 的 `app_name`、`EntryAbility_label`，`en_US` 等语言目录里的同名键仍是模板值或旧值
适用范围：App 身份落地和资源阶段收口自检时，处理身份类字符串键
做法：
- 改完 base 后，在所有 `resources/*/element/string.json`（含各语言目录）里搜同名键（EntryAbility_label、app_name 等），同步为品牌名或对应译名
- 收口自检按值核对：各语言目录里是否还残留 'label'、'MyApplication' 等模板值；键一致性审计不能代替这项值检查
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 系统优先从与设备状态匹配的限定词目录取资源，找不到才去 base：只改 base 盖不住语言目录里的旧值（出处：resource-categories-and-access.md，资源匹配）
- AppScope 与模块重名资源打包时 AppScope 优先，其次 HAP 模块自身，再次依赖的 HAR：AppScope 和模块里的 app_name 等重名键要一起核对（出处：resource-categories-and-access.md，资源分类）
针对本应用要查的：
- 工程里有哪些语言限定目录带身份类键：目标工程 AppScope/resources 与各模块 src/main/resources 下的 */element/string.json；按键名 EntryAbility_label、EntryAbility_desc、module_desc、app_name 搜，逐个看取值
