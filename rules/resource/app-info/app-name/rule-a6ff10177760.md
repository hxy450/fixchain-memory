# android:label 引用 @string/app_name 时，目标三处应用名取源值，无决策 ID 不改

审的是：资源
触发（任一种）：
- 读到：源 AndroidManifest 的 <application> / <activity> android:label="@string/app_name"，res/values*/strings.xml 里各语言 app_name 有确定的值；写错的样子：AppScope 的 app_name、entry 的 EntryAbility_label 或 app_name 写成规格或派工给的另一个字面值；映射表或回执写「已批决策值」，却引不出决策 ID
适用范围：资源迁移与应用身份落地时确定应用显示名的那几项字符串资源
做法：
- 以源 app_name（有 resValue 时以它为准）作为 AppScope/resources/base/element/string.json 的 app_name、entry 的 EntryAbility_label 和 entry 的 app_name；各语言按源 values-<lang> 写进对应限定词目录
- 派工或规格给出不同字面值时，先定位决策台账查决策 ID：只认带决策 ID、明确声明与源值不同的条目（验收条目带「决:」锚点或 decision_ref，真值为 decision:ID）；锚点仍指向源码、decision_ref 为空的，按源值写，并在回执里标出规格冲突
- 映射表里没有决策 ID 可引用时，不写「已批决策」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- app.json5 的 label：应用名称，取值为字符串资源索引（如 "$string:app_name"），不超过 63 字节，不可缺省：AppScope 的应用名（出处：app-configuration-file.md，配置文件标签）
- module.json5 abilities 的 label：UIAbility 对用户显示的名称，取值为字符串资源索引（如 "$string:EntryAbility_label"），不超过 255 字节：入口 Ability 的显示名（出处：module-configuration-file.md，abilities标签）
- 有入口 UIAbility 时，桌面返回入口 UIAbility 配置的 icon 和 label；它没设 label 时才用 app.json5 的：EntryAbility_label 和 AppScope 的 app_name 都要取源值，否则桌面和系统各处显示不一致（出处：layered-image.md，配置优先级和生成策略）
针对本应用要查的：
- 源应用名的实际值：源工程模块构建脚本里的 resValue("string", "app_name", …)（按 buildType / flavor），再看 res/values*/strings.xml 的 <string name="app_name">；有 resValue 用它；否则逐个语言目录读出 app_name，原样写进目标同语言的 string.json
