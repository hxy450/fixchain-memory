# app_name 和 EntryAbility_label 取安卓实际应用名（resValue 优先），不用模板值

审的是：资源
触发（任一种）：
- 读到：AndroidManifest.xml 的 `android:label="@string/app_name"`，strings.xml 里 app_name 是应用名；写错的样子：只改了一处 app_name；`EntryAbility_label` 的值还是模板 "label"，或 AppScope 的 `app_name` 仍是脚手架值
- 读到：Android 的 Gradle 构建脚本用 resValue 提供 app_name，strings.xml 里没有 app_name；写错的样子：AppScope 的 app_name 仍是模板值，EntryAbility_label 也没同步成安卓应用名
- 读到：编译报 $string:module_desc 或 $string:EntryAbility_label 未定义；写错的样子：编译修复补的 EntryAbility_label 等值是按工程目录名自造的名称
适用范围：落地应用显示名、编译修复补回缺失的身份字符串时
做法：
- 从 app.json5 和 module.json5 入口 UIAbility 的 "label" 解析出 $string 键，把 AppScope、entry 两份 string.json 里这两个键的值都改成安卓应用名（先取 Gradle resValue 给的 app_name，没有再取 strings.xml 的）；或把入口 UIAbility 的 label 改指 "$string:app_name"，EntryAbility_label 删掉或也改成应用名
- 编译修复补身份字符串时，从安卓应用名或身份步骤的产物取值；取不到就登记占位并回报，不按工程目录名自造名称
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 入口 UIAbility 配了 icon 和 label 时系统返回它的；只有入口 UIAbility 没设 icon 或 label 时才用 app.json5 的：桌面显示的名称通常来自 EntryAbility_label，只改 app.json5 引用的 app_name 不够，两处都要是安卓应用名（出处：layered-image.md，配置优先级和生成策略）
- app.json5 的 label：应用名称，取值为字符串资源的索引，长度不超过 63 字节，不可缺省：应用级显示名（app_name）的约束（出处：app-configuration-file.md，配置文件标签 label）
- module.json5 abilities 的 label：UIAbility 对用户显示的名称，取值为字符串资源的索引，不超过 255 字节：入口 UIAbility 的显示名，写成 $string:<资源名>；模板值留着时一旦被引用就显示成 "label"（出处：module-configuration-file.md，abilities标签 label）
- 模板里 EntryAbility 写 "label": "$string:EntryAbility_label"：脚手架的默认引用（出处：module-configuration-file.md，配置文件示例）
- EntryAbility_label 与 AppScope 的 app_name 都改为安卓应用名后，显示名检查通过：返修后的取值（出处：卡里修好并验证过）
针对本应用要查的：
- 安卓应用的实际名称：源工程 app 模块的 Gradle 构建脚本（Groovy 或 Kotlin 写法），在 defaultConfig 和 productFlavors 里找 resValue("string", "app_name", …)；没有再看 res/values/strings.xml 的 app_name；按迁移对应的 flavor 取 resValue 的第三个参数，同时写进 AppScope 的 app_name 和 entry 的 EntryAbility_label
