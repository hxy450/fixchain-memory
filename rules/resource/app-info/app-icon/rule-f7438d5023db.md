# app.json5 的 icon 停在脚手架值而 entry 已有分层图标时，改指分层图标

审的是：资源
触发（任一种）：
- 读到：迁移 skill 或交接给出的 icon 目标值是 $media:layered_image（旁注「(不变)」）；entry 的 module.json5 已是 icon=$media:layered_image，entry media 下有 layered_image.json 和前景、背景文件；写错的样子：AppScope/app.json5 仍是 "icon": "$media:app_icon"，AppScope media 里只有脚手架的 app_icon.png
- 写错的样子：app.json5 的 icon 指向的 AppScope media 文件（app_icon.png 或前景、背景）不到 1KB，是脚手架占位图
适用范围：应用身份落地阶段，确定 AppScope/app.json5 的应用级 icon 时
做法：
- 拿 app.json5 的 icon 和 skill 给出的目标值比，不和脚手架现值比；现值是 $media:app_icon 这类脚手架默认时，改成 "icon": "$media:layered_image"
- 「(不变)」一类说明只在现值已等于目标值时照做；判断现值是不是占位，看 AppScope media 里它指向的文件，不到 1KB 的 app_icon、foreground、background 按脚手架占位处理
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- app.json5 的 icon：标识应用的图标，取值为图标资源文件的索引，支持单层图标和分层图标，不可缺省：应用级图标字段，指向资源索引（出处：app-configuration-file.md，配置文件标签）
- "icon": "$media:layered_image"：app.json5 用分层图标时的写法，引用 AppScope media 下的分层图标资源文件（出处：layered-image.md，配置分层图标和应用名称）
- icon 改为 $media:layered_image，并从 entry media 复制前景、背景和 layered_image.json 到 AppScope media 后，引用可解析：修好的做法（出处：卡里修好并验证过）
未核实：入口 UIAbility 已设 icon 时，app.json5 的 icon 停在占位图对桌面图标的实际影响，卡里没有上机看
