# 源端是自适应图标时，layered_image 前景背景和 startIcon 由源图标生成，不留模板

审的是：资源
触发（任一种）：
- 读到：源工程 mipmap-anydpi-v26/ic_launcher.xml 是 <adaptive-icon>：<foreground> 引用矢量、<background> 引用纯色；写错的样子：AppScope 和 entry 的 media 下 layered_image 引用的 foreground / background PNG 仍是 DevEco 模板（蓝底背景层），startIcon.png 也是模板图；启动图标层只被当普通 drawable 转成 SVG
适用范围：应用身份落地阶段处理应用图标和启动图标时
做法：
- 由源自适应图标的前景矢量和背景色栅格化出 layered_image 的 foreground / background PNG，AppScope 与 entry 两处都替换
- 同时替换 startIcon.png（由源图标生成），并顺着 module.json5 abilities[].icon 的引用核对实际用的是哪套资源
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- { "layered-image": { "background": "$media:background", "foreground": "$media:foreground" } }：分层图标资源文件的写法，前景和背景各引用一张图（出处：layered-image.md，配置分层图标）
- 编译时 AppScope 下的资源会覆盖模块下同名资源：AppScope 与 entry 两处的同名图标都要换，否则 AppScope 的模板图生效（出处：layered-image.md，配置优先级和生成策略）
- 分层图标推荐前景图显示大小 450*450px、资源 1024*1024px 透明图层，背景图 1024*1024px：栅格化前景和背景的尺寸（出处：module-configuration-file.md，shortcuts 标签 icon）
针对本应用要查的：
- 源自适应图标的前景和背景：源工程 res/mipmap-anydpi-v26 下的 ic_launcher.xml，顺着 <foreground>、<background> 的 android:drawable 找到矢量 XML 和颜色值；前景矢量栅格化成透明 PNG，背景色填满一张同尺寸 PNG
未核实：450/1024px 的推荐尺寸出自快捷方式图标的说明，应用图标是否同一规格未核
