# 迁移 adaptive-icon 前景时先裁中央 72/108 可见区再缩放，不直接拷 mipmap 全层

审的是：资源
触发（任一种）：
- 读到：源端 <adaptive-icon> 的 android:foreground 指向 mipmap-*dpi 下 108dp 全层的 PNG；写错的样子：layered_image.json 的 foreground 引用的 PNG 是 mipmap 前景原样拷贝（如 xxxhdpi 的 432×432 没裁剪）
适用范围：把安卓 adaptive-icon 的前景层迁成鸿蒙 layered-image 前景 PNG 时
做法：
- 按源 PNG 边长取中央 72/108（即 2/3）：如 xxxhdpi 的 432px 取中央 288px，再等比缩放到目标尺寸（与背景同为 1024×1024px）
- 交付前对比可见内容占比（如主体宽度占可见区的比例）与安卓一致
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- The inner 72 x 72 dp of the icon appears within the masked viewport；外圈每边 18dp 留给系统做视觉效果：安卓启动器只显示中央 72dp（出处：android.graphics.drawable.AdaptiveIconDrawable（类注释））
- EXTRA_INSET_PERCENTAGE = 1/4；DEFAULT_VIEW_PORT_SCALE = 1 / (1 + 2 × 1/4) = 2/3：可见区是整层边长的 2/3（出处：android.graphics.drawable.AdaptiveIconDrawable，EXTRA_INSET_PERCENTAGE / DEFAULT_VIEW_PORT_SCALE）
- 取 xxxhdpi 中央 288px 后等比放大到 1024px，主体宽度占比与安卓可见区一致：改后的效果（出处：卡里修好并验证过）
针对本应用要查的：
- 源前景 PNG 的像素边长：源工程 res/mipmap-xxxhdpi（或现有最高密度）下 adaptive-icon 的 android:foreground 引用的 PNG；边长 × 2/3 为中央裁切的边长。例：xxxhdpi 下 432px 取 288px
