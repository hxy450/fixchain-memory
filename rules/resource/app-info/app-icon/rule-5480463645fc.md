# app.json5 用分层图标时，AppScope media 里要有分层图标文件和它引用的前景背景

审的是：资源
触发（任一种）：
- 读到：资源迁移已在 entry 的 resources/base/media 产出前景、背景（svg 或位图）和 layered_image.json；迁移 skill 只描述从 PNG 提取，源 mipmap 是 webp；写错的样子：app.json5 的 icon 是（或改成了）$media:layered_image，但 AppScope/resources/base/media 下没有 layered_image.json，或者缺它 "layered-image" 里 foreground、background 引用的文件
适用范围：应用身份落地阶段，AppScope/app.json5 用分层图标时 AppScope 的 media 资源
做法：
- AppScope 和 entry 各自解析 $media 引用：把 entry media 里的 layered_image.json 和它引用的前景、背景文件原样复制到 AppScope/resources/base/media，不因 skill 只讲 PNG、源 mipmap 是 webp 就放弃
- 复制后核对 AppScope media 里 layered_image.json 的 "background"、"foreground" 两个 $media 引用都能在 AppScope media 里找到同名文件
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- { "layered-image": { "background": "$media:background", "foreground": "$media:foreground" } }：分层图标资源文件的格式，两个引用指向同一 media 目录下的前景、背景文件（出处：layered-image.md，配置分层图标和应用名称）
- 用 app.json5 配分层图标时，前景、背景放在 AppScope/resources/base/media 下：app.json5 的引用在 AppScope 自己的 media 里找文件，entry 的不算（出处：layered-image.md，配置分层图标和应用名称）
- 构建时 AppScope 下的资源合入模块同路径目录，重名时 AppScope 的覆盖模块的：AppScope media 里和 entry 同名的占位文件会盖掉 entry 已迁移的图标，所以复制 entry 的同一份文件，不留占位（出处：layered-image.md，配置优先级和生成策略）
- 从 entry media 复制前景、背景 svg 和 layered_image.json 到 AppScope media 后引用可解析：修好的做法（出处：卡里修好并验证过）
