# 无部署期身份步骤而验收要求非 com.example 时，交付前按 applicationId 落 bundleName

审的是：资源
触发（任一种）：
- 读到：安卓 app 模块 Gradle 构建脚本里 defaultConfig 的 `applicationId`（只有两段时尤其要注意）；写错的样子：交付时 AppScope app.json5 的 `bundleName` 仍是 `com.example.*`、`vendor` 仍是 example
适用范围：dev-identity 按约定保留脚手架 bundleName/vendor，而流水线没有单独的部署期身份步骤、验收要求非 com.example.* 时
做法：
- 交付前以 scope=full 从 applicationId 落地 bundleName；applicationId 只有两段时最小扩展成三段（在末尾加一段，如 .app），vendor 取组织段（第二段）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- bundleName 必须以点号分隔且至少包含三段，每段只用英文字母、数字、下划线；长度 7–128 字节：两段的 applicationId 不能原样用作 bundleName（出处：app-configuration-file.md，配置文件标签）
- hvigor 校验 bundleName 至少三段，两段的 applicationId 末尾补一段后通过：修复时的做法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端的应用包名：源工程 app 模块的 Gradle 构建脚本（Groovy 或 Kotlin DSL）里 defaultConfig 的 applicationId；按点号切段：三段以上原样用作 bundleName；两段时末尾补一段；vendor 取第二段
来源：1 张卡，1 个应用
