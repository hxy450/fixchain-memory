# bundleName/vendor 是模板值时按 applicationId 加 flavor 后缀写入

审的是：资源
触发（任一种）：
- 读到：源工程构建脚本里有 applicationId 和 productFlavors 下的 applicationIdSuffix、namespace；skill 规则或派工写「不碰 bundleName / vendor（部署期）」「scope=dev-identity」；写错的样子：app.json5 的 bundleName 仍是 com.example.* 模板值、vendor 仍是 example，交回说明写「原样保留，部署期 scope=full 落地」，而流水线里没有部署期步骤
适用范围：执行阶段落地 App 身份（AppScope 的 app.json5）时
做法：
- 先确认本次流水线有没有部署期 / scope=full 步骤；没有就直接写：bundleName = applicationId + 所选 flavor 的 applicationIdSuffix，vendor 取 namespace 里的厂商段
- 确需推迟时，在 placeholder-registry 登记一个 P-ID，写明由哪个收尾步骤回填
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- bundleName：以点号分隔、至少三段，每段只允许英文字母、数字、下划线，7–128 字节，不可缺省：app.json5 里应用的唯一标识，安卓的 applicationId 加后缀写进来要符合这条规则（出处：app-configuration-file.md，配置文件标签（表1 bundleName））
- vendor：不超过 255 字节的字符串，可缺省，缺省值为空：应用开发厂商的描述（出处：app-configuration-file.md，配置文件标签（表1 vendor））
- bundleName = applicationId 加 foss flavor 的 applicationIdSuffix，vendor 取 namespace 的厂商段：返修后写进 app.json5 的取法（出处：卡里修好并验证过）
针对本应用要查的：
- 所选 flavor 的完整 applicationId：源工程的 gradle.properties 和模块构建脚本：applicationId 的取值、productFlavors 里所选 flavor 的 applicationIdSuffix；所选 flavor 看派工说明和决策台账；applicationId 后面接上 applicationIdSuffix 即 bundleName
