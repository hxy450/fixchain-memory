# AppScope/app.json5 的 bundleName 要等于安卓 applicationId，不留脚手架值

审的是：资源
触发（任一种）：
- 读到：源模块 Gradle 构建脚本 defaultConfig 的 `applicationId`，或没有时的 `namespace`；写错的样子：`AppScope/app.json5` 的 `bundleName` 仍是脚手架的 `com.example.…`，`vendor` 仍是 `example`
- 读到：台账有迁真实身份的技术项，build-profile.json5 的 signingConfigs 为空（unsigned HAP），所引部署期决策编号在台账里查不到；写错的样子：仍是 "bundleName": "com.example.myapplication"，理由写「属部署期、与签名绑定」
适用范围：落地、迁移或收尾应用身份时写、核对 AppScope/app.json5 的 bundleName、vendor
不适用的情形：台账里确有已批准的部署期身份决策、且已有签名配置时，才可以把 bundleName 延后
做法：
- 把 app.json5 的 "bundleName" 写成源端 applicationId 原值（没声明时取 namespace 或 Manifest 的 package），不以部署期、签名为由留 com.example.myapplication
- vendor 写源包名的组织段（反域名第二段），和 bundleName、app_name、版本同一步落地
- 写完读回 app.json5，与源端标识、台账身份技术项逐字段比对，搜 com.example 残留，代码里的旧包名改取 context.abilityInfo.bundleName；要留脚手架值只有台账有对应 approved 决策才披露，否则在迁移报告记决策缺口「包名/厂商待定」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- bundleName：以点号分隔、至少三段，每段只含英文字母、数字、下划线；首段字母开头；7–128 字节；不可缺省；推荐反域名形式，第二级为厂商名：目标应用的唯一标识及命名规则，源包名要满足这些规则才能直接照抄（出处：app-configuration-file.md，配置文件标签 bundleName）
- vendor：应用开发厂商的描述，不超过 255 字节，可缺省，可用于关于页展示开发厂商：同在 app.json5 的厂商字段，写源包名的组织段（出处：app-configuration-file.md，配置文件标签 vendor）
- UIAbilityContext.abilityInfo: AbilityInfo；AbilityInfo.bundleName: string（只读）：运行时取包名，不硬编码（出处：鸿蒙 SDK 的 ets/api/application/UIAbilityContext.d.ts，UIAbilityContext.abilityInfo；ets/api/bundleManager/AbilityInfo.d.ts，AbilityInfo.bundleName）
- 9568332 install sign info inconsistent：设备上已装的应用与新装的签名不一致时安装失败：同 bundleName、不同签名的应用装不上（出处：bm-tool.md，9568332 签名不一致导致安装失败）
- bundleName 改为 applicationId 原值后修好；vendor 当时保持并记为决策缺口：一张卡的修法（出处：卡里修好并验证过）
- 下游验收（verify 的 CHECK-4）对 bundleName 匹配 com.example.*、vendor 为 example 直接判 FAIL；改成源包名和非模板厂商后通过：模板值不能当已完成（出处：卡里修好并验证过）
- bundleName 改为源 applicationId，vendor 保持源组织段，台账和验证报告登记 com.example.* 例外：源 applicationId 本身在 com.example.* 下时的修法（出处：卡里修好并验证过）
- bundleName 改成源包名后签名安装成功；保留脚手架名时模拟器上已有他人应用占用同名，改好前不能安装：保留通用脚手架包名的后果（出处：卡里修好并验证过）
针对本应用要查的：
- 源端包名：源工程应用模块的 Gradle 构建脚本（Groovy 或 Kotlin DSL）defaultConfig 里的 applicationId；没有时看 android 块的 namespace，或 AndroidManifest.xml 根元素 manifest 的 package；原样作 bundleName，先按 bundleName 命名规则核对段数和字符，只有两段等不满足时记决策缺口；反域名第二段作 vendor
- 执行规则引用的部署期身份决策和签名配置在不在：决策台账里按规则所引的 D- 编号找；目标工程 build-profile.json5 的 signingConfigs；编号查不到、签名为 unsigned 或 signingConfigs 为空，就按源包名写
