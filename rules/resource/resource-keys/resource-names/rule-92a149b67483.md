# 反编译 res 里的 $父名__N 内联片段先按父资源分类处理，不按原名输出成 media

审的是：资源
触发（任一种）：
- 读到：apktool 反编译 APK 的 res/drawable 里有 `$<父名>__N.xml` 文件（aapt 从 animated-vector、animation-list、selector 等拆出的内联片段）；写错的样子：base/media 下出现 `$` 开头的文件（如 `$…__0.svg`），其中有带库前缀（avd_、m3_、mtrl_、abc_）的父资源片段没被跳过
适用范围：以 apktool 反编译的 APK 为资源源、批量把 XML drawable 转成 media 并过滤库资源时
做法：
- 文件名匹配 ^\$(.+)__\d+$ 的单独归为内联片段，取出父资源名；它们只供父资源内部引用，不当成独立 drawable
- 库前缀过滤按去掉 `$` 和 `__N` 后的父资源名匹配；父资源是库资源，或是 animated-vector、animation-list 这类不可映射类型的，片段整体跳过；过滤后分别列出跳过和漏网的名字，核对带库前缀的都已跳过
- 确需保留的片段，去掉 `$` 再输出，并检查和已有资源重名
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- aapt 内联片段的文件名形如 `$<父名>__N`，`$` 让锚定在开头的库前缀正则（^(abc_|mtrl_|avd_|m3_…)）匹配不上：前缀过滤要先剥掉 `$` 和 `__N`（出处：卡里修好并验证过）
- 构建报 Resource Pack Error：Invalid resource name '<名>' … should match [a-zA-Z0-9_]：`$` 开头的 media 文件名不合法，构建失败（出处：卡里修好并验证过）
