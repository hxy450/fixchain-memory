# 页面里的 $r 引用键都要在 element/*.json 有定义，按组件实际引用回对

审的是：资源
触发（任一种）：
- 读到：源布局同一容器写了几个方向的内边距或外边距（android:paddingHorizontal、android:paddingTop、android:paddingBottom、layout_margin*），派工要求把 dp 值写成 $r 引用并只向共享 element/*_float.json 追加缺的键；写错的样子：页面 .ets 里有 $r('app.float.…') / $r('app.color.…') / $r('app.string.…') 引用，resources/base/element/*.json 里却没有同名 name；追加的键清单是写组件前按源值预估的，漏了某个方向的值
适用范围：页面转换时边写组件边向共享 element 资源文件追加键的场合
做法：
- 组件写完后，从本页 .ets 实际出现的 $r('app.<type>.<name>') 提取键清单，逐个到 resources/base/element/*.json 查 name（media 键到 media 目录查文件），缺的追加成 {"name": "<键>", "value": "<源值>vp"} 这类条目
- 从源布局抽尺寸时，同一容器 padding / margin 的每个方向都列进键清单，逐项标「已存在」或「需新增」
- 页面自检要做这项逐键比对，缺键就补齐或判自检失败；括号配对、禁用文案扫描、对未跟踪文件跑 git diff 都不能代替
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- $r('app.type.name')：type 是资源类型，name 是定义资源时给的资源名：引用里的 name 要和 element/*.json 某个条目的 name 完全一致（出处：resource-categories-and-access.md，资源访问）
- {"float": [{"name": "…", "value": "28.0fp"}]}：float.json 的条目格式，尺寸写成带单位的字符串（出处：resource-categories-and-access.md，资源文件示例）
- 补上 {键: 34vp} 后组件引用不变，批次资源审计确认所有键可解析：修好后的做法：补定义，不改组件（出处：卡里修好并验证过）
