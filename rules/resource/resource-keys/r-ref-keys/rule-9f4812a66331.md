# HAR 页面引用的资源名不在本模块或已声明依赖里时，复制或迁入本模块

审的是：资源
触发（任一种）：
- 读到：HAR 里的页面用 `$r('app.string.X')` / `$r('app.media.X')` 或 `getStringByNameSync('X')` 引用资源；写错的样子：名字只定义在壳 HAP（products 下）、AppScope 或目标 HAR 的 oh-package.json5 没声明依赖的 feature 的 `resources` 里，目标 HAR 自己没有
适用范围：多模块工程（壳 HAP + feature/组件 HAR）中，页面所在 HAR 的资源归属
做法：
- 逐个确认页面引用的名字定义在目标 HAR 自身或它在 oh-package.json5 声明的依赖里；在壳、AppScope 或未依赖 feature 里的，复制或迁入目标模块（base 和各语言目录都补）
- 已声明禁止新增 A→B 依赖时，把 B 中被页面引用的资源迁到 A；只被 A 用的条目从 B 移除，避免跨 HAR 重名
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 构建 HAP 时从 HAP 及依赖模块收集资源，重名时按 AppScope > HAP 自身 > 依赖的 HAR（按 dependencies 顺序）覆盖：整包会合并资源，所以缺失只在单独分析 HAR 时暴露；跨模块重名会被高优先级的一份覆盖（出处：har-package.md，导出资源）
- $r('app.type.name')：引用本模块或依赖 HAR 资源的写法（出处：resource-categories-and-access.md，访问本模块资源或模块依赖的HAR资源）
- 页面专属字符串和媒体迁入新模块，从原模块移除仅新模块使用的条目，越界文案改成新模块自有名称：修复后的做法（出处：卡里修好并验证过）
针对本应用要查的：
- 目标 HAR 的资源闭包：目标 HAR 的 oh-package.json5 的 dependencies，以及它和这些依赖模块 src/main/resources 下各 element/*.json、media 目录；把这些模块的资源名取并集，页面引用的名字不在并集里的就要补进目标 HAR
