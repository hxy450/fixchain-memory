# 带 autoVerify 的深链迁成 skill 时，同时写 "domainVerify": true

审的是：资源
触发（任一种）：
- 读到：AndroidManifest 里 VIEW/BROWSABLE 的 intent-filter 带 android:autoVerify="true"，data 是 http/https；写错的样子：module.json5 新增的 browsable skill（entity.system.browsable + ohos.want.action.viewData + uris）里没有 "domainVerify": true
- 读到：规格或台账写「https 由域验证 App Linking 承载」，映射行把 intent-filter（autoVerify）映射到 skills.uris；写错的样子：skill 只写了 uris、缺 domainVerify；交回的清单把域验证全归为部署期
适用范围：安卓 App Links 深链迁成 module.json5 里 abilities 的 skills 链接入口时
做法：
- 源 intent-filter 逐项对到一个独立的 skill：action VIEW → "actions": ["ohos.want.action.viewData"]，category BROWSABLE → "entities": ["entity.system.browsable"]，data → "uris"（scheme、host、path），android:autoVerify="true" → "domainVerify": true
- domainVerify 是应用侧声明，写进 module.json5；只有 AGC 域名关联和服务器端校验文件属于部署期
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- domainVerify：布尔值，可缺省，缺省值为 false：不写就是不开域名校验，App Linking 退化成普通 Deep Linking（出处：module-configuration-file.md，skills标签）
- "actions" 含 "ohos.want.action.viewData"，"entities" 含 "entity.system.browsable"，"uris" 含 scheme 为 https、host 为域名的元素，"domainVerify": true：App Linking 在 module.json5 里要声明的四项（出处：app-linking-startup.md，声明应用关联的网站域名）
- 跳转链接不能配在默认的入口 skill 里，要新建独立的 skill 对象；多个跳转场景各建一个：domainVerify 写在承载 https 的那个独立 skill 上（出处：app-linking-startup.md，声明应用关联的网站域名）
- autoVerify 只在 ACTION_VIEW + CATEGORY_BROWSABLE、data scheme 为 http 或 https 时生效，按 data 的 URI 去校验：源端 autoVerify 对应目标端的域名校验开关（出处：Android SDK 平台资源 data/res/values/attrs_manifest.xml，autoVerify（按应用的 compileSdk 取对应平台））
- 在 skill 的 actions 之后加 "domainVerify": true，bm dump 复核该 skill 为 domainVerify: true：改法和复核方式（出处：卡里修好并验证过）
针对本应用要查的：
- 哪些 intent-filter 带 autoVerify、各自的 scheme、host、path：源工程 AndroidManifest.xml 里 activity 下的 intent-filter 及其 data 标签；带 android:autoVerify="true" 的那组，其 https 的 data 写进同一个 skill 的 uris，并在这个 skill 上写 "domainVerify": true
未核实：卡里两端都未通过域名校验，只核对了声明（bm dump），没看到校验通过后的跳转效果
