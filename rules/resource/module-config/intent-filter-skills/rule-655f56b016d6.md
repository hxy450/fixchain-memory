# 源 manifest 没有对应 intent-filter 时，module.json5 不加相机等 skill

审的是：资源
触发（任一种）：
- 读到：源 AndroidManifest.xml 没有相机相关 <intent-filter>，代码只调用系统相机（目标端用 cameraPicker.pick）；写错的样子：module.json5 的 skills 里加了 {"entities": ["entity.system.camera"], "actions": ["ohos.want.action.camera"]}，理由是「cameraPicker.pick 前置」
适用范围：按 worker 笔记或参考文档的配置片段修改 module.json5 skills 时
做法：
- skills 只登记源 manifest 有对应 intent-filter 的受理项；调用系统能力（如 cameraPicker）不需要在 skills 里声明，删掉没有源端对应的 skill
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- skills 标识 UIAbility 或 ExtensionAbility 能够接收的 Want 的特征：skills 是应用自己受理外部 Want 的过滤器，不是调用别的能力的前置（出处：module-configuration-file.md，skills标签）
- pick(context: Context, mediaTypes: Array<PickerMediaType>, pickerProfile: PickerProfile): Promise<PickerResult>：cameraPicker 拉起系统相机的接口（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.cameraPicker.d.ts，cameraPicker.pick）
- 加了相机 skill 后应用成为系统相机候选；返修删掉该 skill：多声明的后果（出处：卡里修好并验证过）
未核实：文档副本和 cameraPicker 声明里没找到要求在 skills 声明相机的说法，只能说明没有这项要求的出处
来源：1 张卡，1 个应用
