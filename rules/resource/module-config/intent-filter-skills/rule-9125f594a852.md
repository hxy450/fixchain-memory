# 深链 skills 照 manifest 注册全部 scheme 和 host，不加源端没有的 scheme

审的是：资源
触发（任一种）：
- 读到：AndroidManifest 的 <intent-filter android:autoVerify="true"> 有 <data android:scheme="https"> 与 <data android:scheme="http">、android:host；写错的样子：module.json5 的 skills uris 注册了源端没有的自定义 scheme，漏掉 http，或没写 domainVerify
适用范围：把安卓深链 intent-filter 迁成 module.json5 abilities 的 skills 时
做法：
- 单独建一个 skill：actions 含 ohos.want.action.viewData，entities 含 entity.system.browsable，uris 按 manifest 每个 scheme 各一项 { "scheme": "https", "host": 域名 }、{ "scheme": "http", "host": 域名 }；源端 autoVerify 为 true 时写 "domainVerify": true
- 规格与源码冲突（源里 grep 不到规格写的 scheme、manifest 有规格未列的 scheme）时，以源码为准注册，或停下回报冲突
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- actions 含 "ohos.want.action.viewData"，entities 含 "entity.system.browsable"，uris 含 scheme 为 https、host 为域名的元素，domainVerify 为 true：声明关联域名的 skill 写法（出处：app-linking-startup.md，声明应用关联的网站域名）
- 跳转链接不能配在标识入口的默认 skill 对象里，要单独建 skill 对象：深链 skill 与入口 skill 分开（出处：app-linking-startup.md，声明应用关联的网站域名）
- uris 每项的 scheme、host、port、path | pathStartWith | pathRegex；path 类只在 scheme 和 host 都配置时生效：uris 的字段（出处：module-configuration-file.md，skills标签（uris标签说明））
- uris 改为 https + http、同一 host、domainVerify，删去自拟 scheme：修复后的配置（出处：卡里修好并验证过）
未核实：卡里的行为出自目标 SDK 6.1.1(24)，文档副本版本 docs f41b9345
