# main_pages.json 只登记路由页，被 import 的 Tab 子组件和 @CustomDialog 不登记

审的是：资源
触发（任一种）：
- 读到：源端单 Activity 用 BottomNavigationView + NavHost 承载底部导航 Fragment；写错的样子：main_pages.json 的 src 列了所有页面文件，包括被主页面 import 进 TabContent 的 @Component export struct 和 @CustomDialog
- 读到：源端是 DialogFragment 或导航图 <dialog>，目标是放在 pages/ 下、没有 @Entry 的 @CustomDialog；写错的样子：main_pages.json 的 src 登记了这个 @CustomDialog 文件
- 读到：编译输出报 10905402（main_pages.json 登记的页面必须恰有一个 @Entry）；写错的样子：只按手写的页面名单补 @Entry，src 里仍有登记项的文件没有 @Entry
适用范围：入口装配时写或改 main_pages.json 的 src，以及编译修复处理 10905402 时
做法：
- 逐文件判定：被 Tabs 或父页面 import 并实例化的是子组件（@Component export，不登记）；router 跳转、恰有一个 @Entry 的才是路由页（不 export，登记进 src）；宿主页弹出的 @CustomDialog 不因放在 pages/ 就登记
- 登记前对每个候选文件搜是否被其他 .ets import，被导入的不登记
- 留在 src 里的文件必须恰有一个 @Entry，登记和装饰器同步改；报 10905402 时以实际的 src 列表逐项查 @Entry 数量，不用手写名单
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- src：当前 Module 中所有页面的路由信息，页面路径以 src/main/ets 为基准，字符串数组，每个元素一个页面：src 只放路由页（出处：module-configuration-file.md，pages标签）
- 在单个 UI 页面中，仅允许存在一个由 @Entry 装饰的自定义组件作为页面的入口：登记进 src 的文件要有且仅有一个 @Entry（出处：ts-universal-entry.md，@Entry）
- 10905402：A page configured in 'main_pages.json' or 'build-profile.json5' must have one and only one '@Entry' decorator.：登记在 main_pages.json 的页面必须恰有一个 @Entry（出处：_ark_ui_compile.md，10905402 @Entry装饰器校验异常）
- @Entry 放在 @CustomDialog 前，main_pages.json 不改，同次编译成功：选择保留登记时的修法；与另一张卡「@CustomDialog 不登记」的说法冲突，见未核实（出处：卡里修好并验证过）
未核实：说法冲突：@CustomDialog 已登记进 src 又报 10905402 时怎么改。case-8138261443f6e670dc52 说 @CustomDialog 不登记、被 import 的组件应从 main_pages.json 移除登记而不是补 @Entry，并把修复期给这个 @CustomDialog 补 @Entry 记为沿用错结构；case-f491afb8eb545306056b 的最终修复是在 @CustomDialog 前补 @Entry、main_pages.json 不改，同次编译成功，卡里说不评判修复方向、不登记也一致；两张卡的行为都出自 HarmonyOS 6.1.1(24)，本机按 docs f41b9345 核对，文档副本未标 API 版本
