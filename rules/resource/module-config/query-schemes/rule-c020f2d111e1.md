# 代码用 canOpenLink 探测某个 scheme 时，在 querySchemes 里登记它

审的是：资源
触发（任一种）：
- 读到：源端用 Intent 拉起外部应用（geo:、mailto:、tel: 等 URI），拉起前查可用性；写错的样子：代码里调了 bundleManager.canOpenLink，entry 模块 module.json5 的 module.querySchemes 没有对应 scheme
适用范围：目标端 entry 模块的 module.json5
做法：
- 在 entry 模块 module.json5 的 module 下加 "querySchemes": ["geo", "mailto", …]，每个要探测的 scheme 一项
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- querySchemes：允许当前应用跳转查询的 URL schemes，只允许 entry 类型模块配置，每项不超过 128 字节；API 21 起最多 200 个，API 20 及之前最多 50 个：字段的限制（出处：module-configuration-file.md，module 标签的 querySchemes）
- canOpenLink 在 scheme 不在 querySchemes 时报 17700056：没登记就探测不了（出处：鸿蒙 SDK 的 ets/api/@ohos.bundle.bundleManager.d.ts，bundleManager.canOpenLink）
