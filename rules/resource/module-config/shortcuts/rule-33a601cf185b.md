# ohos.ability.shortcuts 写进入口 UIAbility 的 metadata，不放 module 级

审的是：资源
触发（任一种）：
- 读到：要把安卓长按应用图标的 App Shortcuts 迁成静态快捷方式，工程 module.json5 的 module 级已有 metadata 数组；写错的样子：module.json5 里 {"name": "ohos.ability.shortcuts", "resource": "$profile:…"} 追加在 module 级 metadata 数组里，入口 UIAbility 的 abilities[].metadata 里没有它
- 写错的样子：构建后 HAP 里的快捷方式配置被改写成 {"newShortCutObj": …} 单个对象，或快捷方式条数比 resources/base/profile 下的源文件少
适用范围：在 module.json5 里挂载桌面长按快捷菜单（静态快捷方式）的配置时
做法：
- 写到承载快捷方式的 UIAbility 下：module.abilities[入口 UIAbility].metadata 里加 { "name": "ohos.ability.shortcuts", "resource": "$profile:<快捷方式配置文件名>" }；该 ability 没有 metadata 时新建数组；module 级 metadata 里不放这一项
- 写完后逐级比对写入位置与文档示例的路径 module → abilities → 那个 UIAbility → metadata
- 构建产物里出现 newShortCutObj 单对象或条目减少时，先回查 metadata 的层级，再考虑打包插件
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 在 module.json5 的 abilities 标签中，针对需要添加快捷方式的 UIAbility 配置 metadata 标签，使 shortcut 配置文件对该 UIAbility 生效：挂载层级是 ability 级（出处：module-configuration-file.md，shortcuts标签）
- metadata 的 name 用 ohos.ability.shortcuts，resource 指向 shortcuts 信息的资源位置（示例 $profile:shortcuts_config）：metadata 项的两个字段（出处：module-configuration-file.md，shortcuts标签）
- 快捷方式配置文件放在 /resources/base/profile/ 下，顶层是 "shortcuts" 数组，每项有 shortcutId、label、icon、wants（API 20 起另有 visible）：被引用的配置文件的格式（出处：module-configuration-file.md，shortcuts标签）
- 挂在 module 级时，构建把配置改写成 {newShortCutObj: 单个快捷方式}，多条只剩一条、长按不出菜单；挂到入口 ability 下后保持 {shortcuts: [全部条目]}，长按出现全部菜单项：层级写错时构建产物里看得到的样子（出处：卡里修好并验证过）
未核实：构建把配置改写成 newShortCutObj 的行为出自 HarmonyOS 5.0.4（API 16）的工具链，本机只按文档核实了挂载层级
