# 快捷方式入口裁定由 shortcuts 配置承担时，ability 的 metadata 引用快捷方式配置

审的是：资源
触发（任一种）：
- 读到：规格或页面规格写明桌面快捷方式入口由鸿蒙侧 module.json5 shortcuts 配置承担；写错的样子：module.json5 的 abilities 里没有 name 为 ohos.ability.shortcuts 的 metadata，resources/base/profile 下也没有对应的快捷方式配置文件
适用范围：源端桌面快捷方式迁成鸿蒙静态快捷方式配置时
做法：
- 在 resources/base/profile/ 下建快捷方式配置 json：{ "shortcuts": [{ "shortcutId": …, "label": …, "icon": …, "wants": [{ "bundleName": …, "moduleName": …, "abilityName": …, "parameters": { 入口参数键: 值 } }] }] }
- 在承接入口的 UIAbility 的 metadata 里加 { "name": "ohos.ability.shortcuts", "resource": "$profile:配置文件名" }
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- metadata.name = ohos.ability.shortcuts：快捷方式信息的标识（出处：module-configuration-file.md，shortcuts标签）
- $profile:shortcuts_config 指向 /resources/base/profile/shortcuts_config.json：metadata.resource 的写法（出处：module-configuration-file.md，metadata标签）
- shortcutId 不超过 63 字节，不能用 $string 资源索引；label、icon、wants 可缺省：shortcuts 数组每项的子标签（出处：module-configuration-file.md，shortcuts标签）
- startShortcut 拉起 wants 里的第一个目标组件，推荐只配一个 wants 元素：wants 的取用规则（出处：module-configuration-file.md，shortcuts标签）
- 新建快捷方式配置文件并在 EntryAbility 的 metadata 中引用：修复时的入口声明（出处：卡里修好并验证过）
针对本应用要查的：
- 快捷方式 want 要带的参数键和值：源工程里创建快捷方式的代码（ShortcutInfo / Intent.putExtra）或页面规格的导航关系；把源端 Intent 的 extra 键原样写进 wants[0].parameters，和 EntryAbility 里识别这类 want 的键一致
