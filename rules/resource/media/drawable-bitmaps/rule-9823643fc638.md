# 源端 @drawable 位图在目标 media 里没有时，从对应密度目录复制原图引用，或登记待补

审的是：资源
触发（任一种）：
- 读到：源端布局或代码引用 @drawable/... / R.drawable....，图在 drawable-xxhdpi 等密度目录里；写错的样子：目标 resources 的 media 目录里没有对应图片，也没有登记待补资源，对应位置在 .ets 里写成了纯 Text
- 读到：规格或布局给出元素到原始 drawable 的对应，按原名查 resources/base/media 没有命中；写错的样子：目标 resources/base/media 里没有这些原图，只有其他模块的同类、近名或带 1 / 2 后缀的图标被拿来用
- 读到：布局 XML 里 ImageView 的 android:src="@drawable/…"、标题 TextView 的 android:background="@drawable/…"；写错的样子：目标 resources/base/media 下没有这些图，页面里也没有 $r('app.media.…') 引用
适用范围：迁移源端用 @drawable 引用位图的图标（工具栏、底栏、菜单行等）、插图和标题条背景，目标 media 里还没有对应原图时
做法：
- 先按原名查鸿蒙 media；缺失就从 Android 对应密度目录（如 res/drawable-xxhdpi）复制原图进目标 media，保持原名（必要时加模块前缀），用 $r('app.media.<原名>') 引用；不拿其他模块同类、近名或带 1 / 2 后缀的图标顶替
- 做不到复制时明确登记为待补资源，不把「没有资源」默认处理成纯文字
- 写完按源布局的 @drawable 清单逐项对照，每一项在 media 下都有文件；复制后用文件大小或哈希比对，确认与 Android 原图一致
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- DENSITY_XXHIGH = 480：Android 的 xxhdpi 是 480 dpi（出处：android.util.DisplayMetrics#DENSITY_XXHIGH）
- xxldpi：适用于 dpi 取值为 (320, 480] 的设备：按密度放置时，drawable-xxhdpi 的图对应目标的 xxldpi 限定词目录（出处：resource-categories-and-access.md，限定词目录（屏幕密度））
- media 目录收图片、音频、视频等非文本文件；图片支持 .jpg、.png、.gif、.svg、.webp、.bmp：能直接放进 media 的图片格式（出处：resource-categories-and-access.md，资源组目录（表3 图片资源类型说明））
- $r('app.media.<名>')：访问本模块 media 资源的写法（出处：resource-categories-and-access.md，资源访问）
- 从 Android drawable-xxhdpi 复制原图到目标 media、按原名改映射后，图标恢复且与源一致：修好的做法；纯文字、近名图标、系统符号都被换掉（出处：卡里修好并验证过）
针对本应用要查的：
- 每个元素对应的原图文件、它在哪个密度目录、有没有矢量版本：规格里的元素→资源表，以及源工程 res 下各 drawable-*dpi 目录和 drawable 目录里与 @drawable/… 同名的文件；按原名取最高的那一档位图（或矢量图转出的位图）复制，文件名保持原名（加前缀时规格和代码一起改）；放 base/media 或按密度放到对应限定词目录的 media
- 每个 @drawable 引用对应的源文件是位图还是 XML drawable：源工程 res/drawable*/ 下与引用同名的文件；扩展名是 .png、.jpg、.webp 等位图的直接拷进 media；是 .xml 的（shape、selector 等）不能原样放进 media，要另行转成目标端写法
未核实：标题条 drawable 若是 shape 一类的 XML，卡里没写怎么迁
