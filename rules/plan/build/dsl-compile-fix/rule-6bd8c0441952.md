# 编译修复改了 stateStyles、@Styles 这类 DSL 写法时，报告列为需打开页面验证并写明入口

审的是：计划与派工
触发（任一种）：
- 读到：编译修复改了 .stateStyles 或 @Styles 的写法，这类 UI DSL 构造在 d.ts 里的类型是 any；写错的样子：编译门报告对这处改动只写构建 PASS，没有列成「需打开页面验证」的项，也没写页面入口
适用范围：编译门、编译修复阶段交回的报告里，涉及 UI DSL 写法改动的条目
做法：
- 报告里为每处这类改动列一项「需打开页面验证」：改了哪个文件、换成了什么写法、页面入口（从哪个页面或菜单进入）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- StateStyles 的状态字段类型是 any：类型检查放行任何写法，只能靠打开页面验证（出处：鸿蒙 SDK 的 ets/component/common.d.ts，StateStyles.pressed）
- 构建 PASS 后从菜单进入页面立即崩溃（TypeError undefined is not callable）：只验证编译漏掉的错（出处：卡里修好并验证过）
针对本应用要查的：
- 改动所在页面的入口：目标工程的路由表或调用 router / Navigation 跳到这个页面的代码；写出从启动页到这个页面要点的菜单或按钮顺序
