# 批量横切改动交回时要有 hvigor 编译结果，未编译要列为阻塞风险

审的是：计划与派工
触发（任一种）：
- 读到：改动横跨多个页面文件（如统一替换 Toast、批量改写观察节点）；写错的样子：交回的回执写「编译尚未执行」，或只列了 rg 静态契约测试作为验证；构建入口因无关的前置校验（如未连接 Android 设备）中止后就停了，移交项里没把「未编译」列为阻塞交付的风险
适用范围：跨多个文件的横切重构写完、交回结果时
做法：
- 实际执行 hvigor 编译并在回执里写结果；构建入口因与本改动无关的前置校验中止时，另行直接运行鸿蒙构建
- 仍无法编译时，把「未编译」写进移交项、列为阻塞交付的风险；不以 rg 静态契约测试代替类型检查
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 只跑 rg 静态契约测试、未编译的横切改动，把类型错误带到了后续会话的构建里才暴露：静态搜索查不出重载不匹配这类类型错误（出处：卡里修好并验证过）
