# 交回报告里的构建结果

agent 会看到什么：收尾报告、验收报告或回执写「最终构建通过」「ArkTS 0 errors」「编译尚未执行」，引用的 BUILD SUCCESSFUL 早于最后一次源码写入、复核构建还没结果，或批量横切改动后构建中止就停了

## 规矩

- rule-3edf60ff0918｜构建通过后又改了源码，收尾报告写「最终构建通过」前要重跑并等到结果｜写错：收尾或验收报告写「最终构建通过」「ArkTS 0 errors」，引用的 BUILD SUCCESSFUL 开始时间早于最后一次源码写入，或者派出的复核构建还没有结果（被中断、未返回）
- rule-e089127d75a4｜批量横切改动交回时要有 hvigor 编译结果，未编译要列为阻塞风险｜读到：改动横跨多个页面文件（如统一替换 Toast、批量改写观察节点）；写错：交回的回执写「编译尚未执行」，或只列了 rg 静态契约测试作为验证；构建入口因无关的前置校验（如未连接 Android 设备）中止后就停了，移交项里没把「未编译」列为阻塞交付的风险
- rule-0fa7ebefd7f4｜构建结果为 FAILED 时，CHECK-1 只能记 FAIL 并列剩余错误，不记「仅警告」｜读到：构建输出 BUILD FAILED 或 COMPILE RESULT:FAIL；错误文件开头几行全是 WARN（如 @Entry + export 不推荐）；写错：CHECK-1 写成「⚠️ 部分通过」「仅 ArkTS 语法警告」，并 mark-stage 进入下一阶段
- rule-6113c949568f｜本地缺 hvigorw 时换可用的构建入口编译，仍不行就做模式扫描并在交付里写明未编译｜读到：工程根目录没有 hvigorw；写错：UI 子代理的回执以「项目根无 hvigorw」「未运行编译验证」收尾照常交付，没把语法未验证列为待办，也没请协调者安排编译或审查
