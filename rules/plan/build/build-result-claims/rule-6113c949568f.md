# 本地缺 hvigorw 时换可用的构建入口编译，仍不行就做模式扫描并在交付里写明未编译

审的是：计划与派工
触发（任一种）：
- 读到：工程根目录没有 hvigorw；写错的样子：UI 子代理的回执以「项目根无 hvigorw」「未运行编译验证」收尾照常交付，没把语法未验证列为待办，也没请协调者安排编译或审查
- 写错的样子：交回报告以「缺 hvigorw、交收尾代理编译」结束，没写做过同类写法扫描，也没明确写「未编译」
- 写错的样子：构建命令失败（如 hvigor 文件锁）后报告仍写「完成」
适用范围：ArkTS 代码实现阶段（含 UI 子代理整页写入 .ets 后）的交回报告和回执
做法：
- 项目根缺 hvigorw 时换可用的构建入口编译：本机 command-line-tools/bin/hvigorw assembleHap、DevEco 自带的 hvigorw.js 或流水线的构建命令
- 构建仍不可用就先做严格类型的模式扫描（`{ id:`、`Array<{`、`constructor(public`、`[key: string]`、调用里的内联 `{`），并在回执里写明「未编译、语法未验证」，由协调者安排编译或审查；不以「待收尾编译」或「完成」结束
针对本应用要查的：
- 本机可用的 hvigorw：DevEco 命令行工具安装目录下的 command-line-tools/bin/hvigorw；在工程根目录用它执行 assembleHap
