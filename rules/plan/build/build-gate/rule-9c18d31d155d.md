# 派工禁止 worker 编译时，要写明导入名与导出名的静态对照，并在收报告前跑编译门

审的是：计划与派工
触发（任一种）：
- 写错的样子：派工写了禁止 worker 自行编译（如「Do NOT run hvigor builds」「由主线程做最终构建」），却没要求 worker 对照导入名与导出名，也没安排主线程在接受报告前跑一次编译门
适用范围：派工限制 worker 编译、又让它改变模块导出形态或跨文件接线时
做法：
- 派工里写明：不编译时 worker 仍要把每个 import 的名字和被导入文件的 export 静态对照一遍
- 派工或验收步骤里写明：主线程接受该 worker 报告前跑一次编译门，不留到下一轮
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- worker 按派工不编译、自检只 grep 了 TODO，导入导出不一致留到后续构建才报 10505001：缺这两项的后果（出处：卡里修好并验证过）
