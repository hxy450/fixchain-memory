# 尺寸问题的工单和拆分交接

agent 会看到什么：派修尺寸问题的工单（跨设备截图偏小、两卡等高）或把布局拆给不同执行者（面板与宿主、横屏变体由共享组件承载）时，派工里的源布局 dp 对照、验收条件和尺寸契约

## 规矩

- rule-9dcb87545af0｜跨设备截图显得偏小时，尺寸类工单先把目标值和源布局 dp 对照，已一致就不写放大｜读到：双端截图来自不同设备，并排对比显示目标页主内容「偏小 / 上移」；目标页的固定高度和 marginTop 已是源布局的 dp 字面值；写错：视觉工单写「主内容约缩小 10%–15%」「对齐固定高度、间距和图片尺寸」，源码缺口写成「…:unknown」，没有源布局值、目标当前值和截图折算值的对照
- rule-1e7b52e69620｜派修等高问题时把「两卡等高」写成验收条件，不只给「改固定高度对齐 Android」｜读到：验收报告写着 Android「两卡等高一行」，修法候选写「右列去掉 weight 改固定 / 与左卡等高」；写错：派工只写「移除 layoutWeight 或改固定高度（对齐 Android 卡片的实际高度）」，没有把两卡等高写成验收条件
- rule-d39a4d2a0b69｜面板和宿主拆给不同执行者时，交接写明面板的尺寸契约｜写错：并行拆给两个执行者的派工或交接接口里，面板一侧没写尺寸契约（自身满高、需宿主分配有界区域，还是由宿主负责高度）
- rule-a447cadea056｜页面登记了横屏布局变体且由共享组件承载时，把变体写进该组件的产出和验收｜读到：页面 meta 登记了 layout_variants_landscape，或计划的资源段写「layout-land/*.xml 由 ArkUI 声明式重建，下游承接」；写错：派工和计划里承载该布局的共享组件，产出只写竖屏骨架（「…结构」「数据驱动消除重复」），横屏变体只出现在资源扫描任务里
