# 拆「深浅主题跟随系统」任务时不标纯常量，派工写明状态可观察、入口由谁读 colorMode

审的是：计划与派工
触发（任一种）：
- 读到：计划或决策写着主题「深浅双主题跟随系统」，源端 Compose 主题按 isSystemInDarkTheme() 选 Light / Dark 套；写错的样子：主题令牌任务的派工限定「纯常量文件、无装饰器需求」或「产出恰 2 个文件」，没写深浅状态必须可观察，也没指定入口由谁读取系统 colorMode
适用范围：执行编排拆分含运行期深浅切换的主题令牌任务、写派工和验收条目时
做法：
- 派工不把含运行期切换的主题文件标成「纯常量、无装饰器需求」，写清两点：深浅状态必须可观察（V2 用 @ObservedV2 类 + @Trace 字段，或 AppStorageV2）；入口 Ability 由谁在 onCreate / onConfigurationUpdate 读取系统 colorMode 并同步
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 未被 @Trace 装饰的属性用在 UI 中无法感知到变化，也无法触发 UI 刷新：普通模块变量或普通字段存深浅状态，切换后 UI 不重绘（出处：arkts-new-observedV2-and-trace.md，概述）
- static connect<T extends object>(type: TypeConstructorWithArgs<T>, keyOrDefaultCreator?: string | StorageDefaultCreator<T>, defaultCreator?: StorageDefaultCreator<T>): T | undefined：AppStorageV2 取应用级共享状态的入口（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.StateManagement.d.ts，AppStorageV2.connect）
