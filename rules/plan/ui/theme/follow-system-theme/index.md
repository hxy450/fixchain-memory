# 深浅主题跟随系统的任务拆分

agent 会看到什么：计划或决策写主题「深浅双主题跟随系统」、源端按 isSystemInDarkTheme() 选套，主题令牌任务的派工限定「纯常量文件」，没写深浅状态可观察、入口由谁读 colorMode

## 规矩

- rule-c90635f8144b｜拆「深浅主题跟随系统」任务时不标纯常量，派工写明状态可观察、入口由谁读 colorMode｜读到：计划或决策写着主题「深浅双主题跟随系统」，源端 Compose 主题按 isSystemInDarkTheme() 选 Light / Dark 套；写错：主题令牌任务的派工限定「纯常量文件、无装饰器需求」或「产出恰 2 个文件」，没写深浅状态必须可观察，也没指定入口由谁读取系统 colorMode
- rule-0c91a039745f｜AC 的标侧文件或「后续阶段接线」没落到任何 packet 的写权里时，单独排一个接线 packet｜读到：规格的验收条目标侧写着某个主题文件（如跟随系统深色、darkTheme 选 DarkColors / LightColors），决策台账里对应的平台差异已批准；写错：没有任何 packet 的输出或可写清单包含该标侧文件；只挂了 suggested_skills，或只在覆盖清单里把 AC 编号记到某个 slice，没补文件范围
- rule-eaff29f7b1f8｜主题切片写盘范围外的静态主题引用逐文件登记交接，不以「下游自行消费」收尾｜读到：规格写主题「共享至全部页面」，已有页面用 $r('app.color.…') / $r('app.float.…') 静态绑定主题色和字号；写错：交付说明或源码笔记写「不在此轮全量换绑」「下游消费 feature 归各 spec」，跨文件交接和 FWD-REF 里没有主题项
- rule-64fba55ba06c｜验收要求页面底/文字/卡片随深浅切换时，计划里要有任务产出这些键的 base+dark 资源｜读到：验收条目写「背景/文本/卡片面色随深浅资源限定符切换」「页面配色令牌由深浅资源限定符自动生效」；写错：计划把设计令牌任务收窄成 accent 色板，深色机制切片只做 ColorMode 切换，页面背景、文字、卡片、分隔线的 base+dark 色资源没有任何任务负责；派工没写键清单和深色取值来源
