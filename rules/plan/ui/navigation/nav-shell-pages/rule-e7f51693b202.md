# 跨切片草稿的守卫注释写注册校验、表达式却查栈成员时，按规格映射改表达式

审的是：计划与派工
触发（任一种）：
- 读到：规格把 isIntentAvailable 映射为「路由表命中页注册态校验（NavDestination 注册表）」，验收条目要求目标不可用或路由未命中时不跳转；写错的样子：派工说明的 cross_slice_edits 草稿注释写「isIntentAvailable 等价：pageMap 未注册页不分发」，表达式却是 getAllPathName().indexOf(pageName) < 0 → return false
适用范围：要交给 closer 原样落实到一个或多个宿主文件的跨切片草稿
做法：
- 草稿注释的意图和表达式实际检查的对象不同时，以规格映射行为准改表达式：查注册名集合或 pageName 非空，不查导航栈里有没有这页
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getAllPathName(): Array<string>：NavPathStack 上返回当前栈里的页名，是栈成员检查，不是注册校验（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.getAllPathName）
- closer 会把草稿原样写进多个宿主，草稿里的偏差随之复制：草稿交出前就要改对（出处：卡里修好并验证过）
