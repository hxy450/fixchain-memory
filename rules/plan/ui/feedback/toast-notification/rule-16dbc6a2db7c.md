# 计划推迟通知等平台能力时，写明它原来交给用户的数据本轮由什么承接

审的是：计划与派工
触发（任一种）：
- 读到：源端经 Notification 或 Toast 把接口返回的数据交给用户；分析回执写着「服务端返回的码通过系统通知显示」；写错的样子：计划把通知整体推迟为后续增量，只写泛化的「接口成功后给出用户可见的反馈」（user-visible feedback），没写那份数据由 Toast 显示还是回填输入框
适用范围：计划里决定推迟通知、通知权限等平台能力，而源端靠这类能力把业务数据交给用户时
做法：
- 在推迟决定旁写明替代承接：「通知推迟；接口返回的<数据>本轮由<回填某输入框 / Toast 显示>承接」，并把这一句落进对应功能的 AC
