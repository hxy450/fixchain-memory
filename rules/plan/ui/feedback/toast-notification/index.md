# 计划里的吐司统一和通知推迟

agent 会看到什么：审计或计划里有「直接 Toast → 统一 ToastService → 调用数归零」的横切行，或把 Notification 整体推迟，计划和批次检查项没有落到产出批次、计数和数据的承接方式

## 规矩

- rule-5e8b230dad9a｜计划要求直调归零时，把公共能力的建立落到具体批次、产物路径和验收命令｜读到：审计列出吐司直调散落，要求建立统一 ToastService；写错：计划只写「对应业务完成时调用数归零」，没有写哪个批次产出 ToastService、放在哪个模块路径并导出，也没有调用归零的验收命令
- rule-6fbbe27395d9｜计划替换清单里有吐司统一和直调归零时，收口前逐行转成本批检查项并计数｜读到：已批准的计划或审计的替换清单里有「直接 Toast → 统一 ToastService → 对应业务完成时调用数归零」这类横切行；写错：批次的检查项或收口报告只列了同批的静态项（如 LazyForEach→Repeat）通过，没有吐司直调的计数，也没有逐项豁免登记
- rule-16dbc6a2db7c｜计划推迟通知等平台能力时，写明它原来交给用户的数据本轮由什么承接｜读到：源端经 Notification 或 Toast 把接口返回的数据交给用户；分析回执写着「服务端返回的码通过系统通知显示」；写错：计划把通知整体推迟为后续增量，只写泛化的「接口成功后给出用户可见的反馈」（user-visible feedback），没写那份数据由 Toast 显示还是回填输入框
