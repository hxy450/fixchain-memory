# 弹窗恢复批次的交接和派工写出承载形态契约，不写成页面内弹层

审的是：计划与派工
触发（任一种）：
- 读到：用户要求「真弹窗、可关闭」；安卓端是 DialogFragment、XPopup CenterPopupView / AttachPopupView；写错的样子：交接或派工写成「恢复 page-hosted popup/sheet 的关闭、返回、遮罩」「恢复为可关闭的页面内弹层」「wire … to the existing dialog」，没指明承载形态；或给锚点类留了「轻量 host overlay」选项
- 读到：同一批次里已有部分弹窗改用真弹窗 API；写错的样子：弹窗清单的核对结果只写补了可见性赋值，没有逐项写每个弹窗的承载形态
适用范围：规划或交接安卓弹窗（DialogFragment、XPopup 等）的迁移或「恢复可关闭」批次时的交接文档、派工说明和核对清单
做法：
- 写形态契约：居中类（DialogFragment、CenterPopupView）用 CustomDialogController 的 .open()，或项目已采用的 @pura/harmony-dialog showCustomDialog；锚点类（AttachPopupView）用 bindPopup 或带锚点偏移的 showCustomDialog
- 完成标准不写「去掉伪路由、改由页面 @Local 持有可见性」
- 清单里其余弹窗逐项核对是否仍是条件渲染，把每个的承载形态写进核对结果
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- constructor(value: CustomDialogControllerOptions)；open()；close()：CustomDialogController 的构造和开关，居中类弹窗的承载（出处：鸿蒙 SDK 的 ets/component/custom_dialog_controller.d.ts，CustomDialogController）
- bindPopup(show: boolean, popup: PopupOptions | CustomPopupOptions): T：锚点类气泡的承载，绑在锚点组件上（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.bindPopup）
针对本应用要查的：
- 项目已采用的弹窗库和封装：目标工程 oh-package.json5 的 dependencies，以及决策台账里关于弹窗形态的条目；有 @pura/harmony-dialog 一类库并已有弹窗走它的 showCustomDialog 时，契约里写同一封装
