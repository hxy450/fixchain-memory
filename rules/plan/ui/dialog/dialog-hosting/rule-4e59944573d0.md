# 派工把弹窗统一改成页内浮层时，写明适用范围和 onBackPressed 关闭要求

审的是：计划与派工
触发（任一种）：
- 读到：上游转换报告以「P-27: inline Stack overlay」上报弹窗做法，没提 Back；写错的样子：派工里写「对话框全部 → 页内 @Builder overlay（P-27）」，没写 P-27 的适用范围和负向守卫，也没要求按 onDismissRequest 接管 Back
适用范围：编排者把某个转换者的局部弹窗做法写进后续派工规则时
做法：
- 派工里写明适用范围：打开期间不跨路由跳转的普通确认框、信息框保留自带 Back 关闭的弹窗机制，只有确需页面级的才用页内做法
- 同时写明配套要求：「页内 overlay 必须在 NavDestination.onBackPressed 中按 onDismissRequest 关闭：有浮层时关最上层并返回 true，否则返回 false」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onBackPressed(callback: () => boolean): NavDestinationAttribute：派工里配套要求落到的接口（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onBackPressed）
- 只转发「对话框全部 → 页内 overlay」后，下游页面的十几个弹窗和下拉都没有 Back 处理，Back 弹出整页：派工缺配套要求时的后果（出处：卡里修好并验证过）
来源：1 张卡，1 个应用
