# 依附式弹窗按 atView 锚点所在页判宿主，不按调用 show() 的类判

审的是：计划与派工
触发（任一种）：
- 读到：源端弹窗类继承 `AttachPopupView`，调用方用 atView(...) 指定锚点，锚点视图取自 parentFragment（父页标题栏上的按钮等），show() 却在子 Fragment 里调用；写错的样子：覆盖清单或审计记录把这个弹窗记在调用 show() 的子页名下，写成「子页已内联等价提示」「可删」；或者目标端锚点在源端弹出条件下从未变为可见，仍记成等价
适用范围：盘点、审计源端依附式弹窗（锚定在某个视图上弹出的提示气泡）在目标端的覆盖情况时
做法：
- 覆盖记录里弹窗的宿主写 atView 锚点视图所在的页面（锚点取自 parentFragment 就记父页），并注明目标端提示要挂在那一页、按锚点实测位置定箭头；不按调用 show() 的类归属
- 记「等价」之前逐项对照源端弹出条件：锚点可见（isShown）、一次性标记的读取和关闭时写入；目标端锚点在源端条件下从未变为可见时，先登记修复锚点的可见性驱动链，不记等价、不记可删
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- View.isShown() 为真要求这个视图和它所有祖先都是 VISIBLE：源端「锚点可见」这一条件的含义：锚点所在父页的布局可见、锚点本身可见（出处：android.view.View#isShown）
- 提示改挂到锚点所在页、按锚点定位后，提示随锚点出现，箭头对齐锚点：按锚点所在页归属后的做法（出处：卡里修好并验证过）
针对本应用要查的：
- 锚点视图属于哪个页面：源工程里调用 atView(...) 的那段代码，看传入的视图从哪里取（parentFragment、activity 的布局，或本页布局）；传入视图所在的 Fragment 或 Activity 就是宿主页；再在目标工程里找到对应页面的锚点组件
