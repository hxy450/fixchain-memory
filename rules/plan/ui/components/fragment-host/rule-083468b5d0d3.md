# 规划 Fragment 型共享组件的嵌入接线时，按源码宿主列目标页，不给别的页加槽位

审的是：计划与派工
触发（任一种）：
- 读到：安卓源码里 Fragment 型共享组件只在某个 Activity 里经 replace / add 放进它布局的容器 id；主 Activity 布局只有 ViewPager 与 Tab 栏；写错的样子：派工或接线归属表要求在宿主以外的页面（多为主页）生成这个组件的空槽位并登记 FWD-REF 占位，或者要求同一个组件填充多个页面的槽位，而其中有的页写不出源端宿主
适用范围：规划 Fragment 型共享组件（如播放控制条）嵌入到哪些目标页、给哪些页派槽位时
做法：
- 接线规划里每个嵌入目标页都写出源端宿主：哪个 Activity、哪个容器 id、哪处 replace/add 调用；目标页只列有宿主的页
- 已确认宿主只有某一页时，只给那一页派槽位和 FWD-REF 占位，不再给主页另加槽位，也不派填充它的任务
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- replace(@IdRes int containerViewId, Fragment fragment)：第一个参数是承载这个 Fragment 的容器 id；按这个 id 去布局 XML 里找到容器，就找到了宿主页面（出处：android.app.FragmentTransaction#replace）
- add(@IdRes int containerViewId, Fragment fragment)：同族接口：add 的第一个参数同样是容器 id；为 0 时不放进任何容器（出处：android.app.FragmentTransaction#add）
针对本应用要查的：
- 共享组件在源端有哪些宿主页：源工程的 Kotlin/Java 代码里搜传入这个 Fragment 的 replace(R.id.… / add(R.id.… 调用，再在布局 XML 里按那个 id 找容器；每处调用所在的 Activity（或父 Fragment）就是一个宿主页；搜不到调用的页面不派槽位
未核实：androidx.fragment.app.FragmentTransaction 的同名方法本机没有源码，参数含义按框架版 android.app.FragmentTransaction 写
