# 列表批量改写和键契约的计划与验收

agent 会看到什么：计划、派工或验收涉及列表的批量改写（LazyForEach 换 Repeat、virtualScroll、短列表豁免）或列表键契约（P-05 键复用陷阱、@Trace 更新方式）

## 规矩

- rule-273b70929099｜批量把 LazyForEach 换成 Repeat 时，计划逐个列表登记 ListItem 高度来源和豁免评估｜读到：重构规则要求列表一律用 Repeat、长列表加 virtualScroll() 空参，短列表可豁免但要在报告里声明；写错：重构计划或报告对所有列表套同一个替换模板，没有逐个列表写 ListItem 高度来源（内容高度、Stretch、layoutWeight、百分比高度），也没有按批加载、条数固定列表的豁免评估
- rule-d28f2261cb47｜批量重构的验收把受影响列表页纳入真机冒烟，数据没加载出来的记为未验证｜读到：重构计划的验收写模块编译、静态审计、该域测试和至少一个主链 smoke；写错：验收只看编译通过和旧符号 grep 计数归零，冒烟清单里没有被改写的列表页；页面停在加载中看不到列表，却记为通过
- rule-6b61d0e023f4｜数据接线切片的派工带上列表键复用陷阱，或在页面键契约旁写明更新方式约束｜读到：转换阶段的陷阱清单里有列表键复用条目（键只含 id 时同 id 新实例不刷新，如 pitfalls 的 P-05），页面的键契约只写了键的组成；写错：负责事件处理或数据接线的切片派工只列状态管理、数据层等技能，没有这条陷阱，页面键契约旁也没注明「换实例要变键 / 只在原实例上改 @Trace 字段」；续收或重试的转换器只 grep 了个别条目
