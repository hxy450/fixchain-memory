# 批量把 LazyForEach 换成 Repeat 时，计划逐个列表登记 ListItem 高度来源和豁免评估

审的是：计划与派工
触发（任一种）：
- 读到：重构规则要求列表一律用 Repeat、长列表加 virtualScroll() 空参，短列表可豁免但要在报告里声明；写错的样子：重构计划或报告对所有列表套同一个替换模板，没有逐个列表写 ListItem 高度来源（内容高度、Stretch、layoutWeight、百分比高度），也没有按批加载、条数固定列表的豁免评估
适用范围：架构重构阶段批量把 LazyForEach/IDataSource 列表改写成 Repeat(...).virtualScroll() 的任务拆分和重构报告
做法：
- 每个要替换的列表登记一行：ListItem 高度来源，项内有没有 alignSelf(ItemAlign.Stretch)、layoutWeight、百分比高度或需测高的装饰；有的标为「不套统一模板、单独处理」
- 条数固定、按批加载的列表先按短列表豁免评估是否真要虚拟化，豁免的在报告里写原因
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 省略 virtualScroll() 时 Repeat 为全量加载，适合短数据列表；数据长度大于 30 的长列表关闭懒加载不建议：评估豁免时可参考的长短界线（出处：arkts-new-rendering-control-repeat.md，懒加载能力说明）
