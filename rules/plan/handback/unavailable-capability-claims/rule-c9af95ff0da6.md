# 修复单描述奖励门结果时分三类给期望，台账没批准阻断就不把「不伪造成功」写成「不导航」

审的是：计划与派工
触发（任一种）：
- 读到：台账写「核心流程全部真实跑通；仅平台或三方能力不可用时返回明确 unavailable，不得伪造成功」，广告输出 closed|rewarded|failed|unavailable；源端入口只在奖励回调后导航；写错的样子：修复单写「return true only for REWARDED; dismissed/failed/unavailable … do not navigate」，把能力不可用和用户未获奖励并列为不放行
适用范围：巡检或修复单描述奖励广告门禁（看完广告才进入功能）的结果分支时
做法：
- 把结果拆成三类各给期望：rewarded 放行；用户关闭、播放失败按源端不放行；广告能力不可用（provider 未装配、平台无等价）显式提示 unavailable，是否继续导航按台账的核心流程范围定
- 先查台账里这个入口有没有像「仅 granted 可继续」那样点名的专门决策；没有专门决策而台账要求核心流程真实跑通时，不可用分支写「提示后继续导航」，不写成锁死入口
针对本应用要查的：
- 该入口是否有「仅 granted 可继续」的专门决策：决策台账里按入口或功能编号搜 granted、阻断、仅…可 这类决策条目；有点名该入口的专门决策才按阻断写；只有通用的「不得伪造成功」时按核心流程跑通写
未核实：派给巡检和修复 agent 的任务正文无法核对是否另有「逐条照单修复」约束
