# 收口报告里的 BLOCKER 和验收条目

agent 会看到什么：巡检报告列出多个 BLOCKER，或功能规格的 AC 源锚点写着 onEventMainThread / @Subscribe，收口报告只写修了几项、「已清除全部自身占位」，没有逐项的落地或核对记录

## 规矩

- rule-d5ca93632e4e｜处理巡检 BLOCKER 时派发失败要重试，关闭前逐项核对每个 BLOCKER 已落地｜读到：巡检报告列出多个 `BLOCKER` 项和修复方向；写错：修复派工因线程上限等原因失败后没有重派；收口时只修了同批次顺手的几项，报告里其余 `BLOCKER` 没有对应的修复或核对记录
- rule-f9c3ab5d6fb3｜规格AC源锚点含onEventMainThread时，覆盖清单逐条写订阅落点，不以占位清零代替｜读到：功能规格的 AC 源锚点写着 onEventMainThread(…Event) 或 @Subscribe（如登录成功后重载数据）；计划的验收模板要求状态、事件、取消、销毁覆盖 AC；写错：占位登记里这一页只有数据加载和点击类占位，没有事件订阅（登录后刷新）那一项；收口报告只写「已清除全部自身 P-S… 占位」，没有逐条 AC 写订阅和释放落在哪里
