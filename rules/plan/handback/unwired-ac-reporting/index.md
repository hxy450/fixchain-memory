# 没接上的 AC 在交回里的记法

agent 会看到什么：规格 AC 要求的字段、数据、失败态、分享渠道或目标符号还没接上时，交回报告、slice notes、占位登记、verify 报告里写的完成说法（全部完成、已实现、N/N、scope 外）

## 规矩

- rule-a84027b4ce73｜上游接口暂缺而字段没接上时，交回里登记缺口，不报告验收条目全部完成｜读到：规格的验收条目要求某些字段经另一功能的接口补齐，实现者搜索时这个接口还不存在；写错：交回的占位登记（如 `generated_placeholders`）为空，报告里写全部验收条目完成，而这些字段实际没有接数据
- rule-128ececf401a｜数据接入推迟时，交回报告里把依赖这份数据的 AC 标为未完成，不报告页面已完成｜读到：规格或计划的风险项写明数据来自资产文件、不能写死少量条目冒充全量；写错：完成报告称页面已实现，只在「限制」里写默认数据仍为兜底列表、应由主线程注入资产文件，依赖这份数据的 AC（级联选择、热门列表等）没有标未完成
- rule-6c8ceb16d6b0｜删除 FWD-REF 或宣布 seam 已解决前，确认对应区块已有数据来源，未接上的列为缺口｜读到：规格写明某组件的区块数据来自尚未接好的 seam（如「daily detail 与日历 seam」），代码里有对应的 `FWD-REF` 占位标记；写错：`FWD-REF` 标记被删除，slice notes 只写「交给后续合并」，没有列出这个区块的数据仍未接入
- rule-71174a6f0f5d｜页面转换把失败界面留给接线阶段时，占位登记写明 error 态要渲染失败提示｜读到：规格状态接口有 error 结果态，验收条目要求失败报错；写错：占位登记里只写状态绑定和计数、状态回填，没有一项写「error 态需渲染失败提示（验收条目编号）」
- rule-1f40ea86c938｜分享类交付报告逐渠道写明已接入、提示缺目标或未接入，不只报 AC 计数｜读到：规格或依赖接缝列出了分享面板的渠道清单；写错：交付回执只写「active_ac_implementation: N/N」这类 AC 计数，Spec Gap 也没提哪个渠道没接
- rule-c17ffed341a2｜P0 规格的 AC 目标符号在代码里搜不到且台账无 skip 时，记为缺口，不记 scope 外｜读到：feature 规格的 P0 验收条目写了深链数据流和目标符号（want.uri → 深链处理函数、module.json5 uris）；写错：verify 报告只查静态规则和路由注册数，没有逐条核对 P0 验收条目的目标符号；或以 MVP 一类理由把深链登记为 scope 外，而决策台账里没有对应 skip 决策
- rule-6c61f65b2e9c｜切片按 3c scope 符号和 AC 标注符号逐项核对，未落地的在信封列出、补派或登记｜读到：切片文件 Step 3c scope 列出多个服务符号，功能 spec 每条 AC 标了目标符号；派工提示只概括了部分类别；写错：信封的已实现 AC 列表漏掉若干 AC，既没列为未实现也没登记 FWD-REF；scope 里有的符号没有生成文件
- rule-c3dd3d7cdc40｜切片只做了某条 AC 的一部分时，不声称已实现，把没做的具体行为登记为 forward-ref｜读到：规格的一条 AC 含多项行为（如「保存值失效→默认档→最高档；无可用档→不支持视频」）；写错：impl-claims 或 source-notes 把这条 AC 记为已实现，代码注释只写「xx 全量归 F00x」，没登记 forward-ref，也没写没做的具体行为
- rule-50dbd46b0d84｜规格里的遥控验收条目没实现时，登记带 owner 的 FWD-REF，不只在笔记写「归另一 feature」｜读到：规格的验收条目要求遥控选择态、按键导航（如曝光面板的行顺序、up/down/ok 三键）；写错：源码笔记或报告只写「归另一 feature」「屏上路径不可达」，移交项里没有带 owner 的 FWD-REF
- rule-c9d46854ed5f｜公开动作方法没有界面调用者时，移交项登记页面挂点，不报接线已就绪｜读到：规格要求某些按钮在某状态下出现并触发动作（如分享、删除最近的图）；写错：交回的移交项或信封自报接线全部就绪，但公开的动作方法只是通道方法，没有界面调用者，也没有登记页面挂点
