# 交付和收口报告里的已补齐、已验证说法

agent 会看到什么：交付说明、收口报告、impl_claims 或自检写「已补齐」「编译通过」「已实现」「符合 P-05」，没有逐项对照实现文件或运行结果，也没把没验证到的项登记出来

## 规矩

- rule-68c82dcd6b36｜收口时对比结论逐条对实现文件核对，缺项回派补写，不拿语法修复当补齐｜读到：页面对比结论列出了列表分组、编辑态、按钮可用条件等差异；写错：收口报告称差异「已补齐」，回派的只是语法修复（如把 Builder 改成多行），实现文件里搜不到编辑态状态变量、按父项的卡片 Builder 或按钮的 enabled 条件
- rule-a1f808615377｜页面交付自检要逐个 ForEach 写明 key 覆盖了哪些可变字段，不只核有选中态的列表｜读到：ui 迁移陷阱清单里有「同 id 新值重建时 key 须含可变字段」这一条（P-05）；写错：交付报告的自检只列出有选中态的列表符合 P-05，没有逐个列出页面里每个 ForEach 的 key 覆盖了哪些可变字段
- rule-5cd11f5dcdf8｜改了页面模块导出或新增组件到页面模块的导入而没跑 UI 套件时，交付说明登记未验证｜读到：本轮改动改了 pages/ 下页面模块的导出，或新增了组件从页面模块的导入；用户说明本轮不跑真机；写错：交付说明只写了 assembleHap 编译通过，没有拉起主 Ability 的 UI 套件冒烟结果，也没有登记「UI 测试进程加载未验证」
- rule-604ce2621b89｜多次被标为风险且只能 判:ui 的 AC，不写进 impl_claims，列入 verify 必测往返｜读到：worker 或 closer 的交回报告里把某条只能 判:ui 的 AC 列为风险或运行期复核项；写错：impl_claims 照抄 plan-coverage 把这条 AC 记为已实现，verify 阶段的必测清单里没有它的往返步骤
- rule-e42780f858fe｜收口时没在设备上走过选图→回填的入口，列为 partial｜读到：派工或计划要求把背景、图库等入口接回现有选择器；写错：收口回执的 partial 项里没有这个相册入口，回报称已接回现有选择器，却没有设备上「选图→预览回填」的验证记录
- rule-ffff55cd8617｜UiModel 里还有空占位字段时，交付说明逐项列出，不写「接线已补齐」｜写错：交付说明或报告写「接线已补齐」「生产态详情接线已补齐」，而 UiModel 赋值里仍有字段给的是空数组、空串之类的占位
- rule-5d2b223d2c08｜无法运行验证时，回执的 API 假设分开写「签名已确认」和「运行能力未确认」｜读到：派工要求在回执里报告 API 假设；写错：回执的 API 假设或风险里只写「签名已在本地 SDK 确认」，没说明所用变体（如声明带 801 的能力受限接口）在目标环境能否运行，也没列成首轮设备测试要核对的风险
- rule-a352c527bfee｜回执写「几何全部取自 SDK 实值」前逐个组件核对，查不到的登记待核并写检索路径｜读到：派工要求平台框架提供外观的组件「几何从本机 Android SDK platform res 取实值，查过仍无才登记 `UNC` 待核」；写错：回执写「几何全部本机 SDK platform res 实值」，但某个组件（如吐司封装）的位置等几何参数没传，也没有登记 `UNC` 待核项；或以「两端都在底部」带过偏移
