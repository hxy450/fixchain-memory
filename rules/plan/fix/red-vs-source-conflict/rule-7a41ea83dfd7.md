# RED 期望与已核的源端语义矛盾时，修复不耦合数据去迁就测试，回执报 BLOCKED

审的是：计划与派工
触发（任一种）：
- 读到：修复者 grep 源端后确认没有同时写两组的方法（两组各归不同页面）；写错的样子：回执写着「某组归属另一功能，但 AC 契约要求双写」，同时把方法改成同时增删两组偏好并判 RESOLVED
适用范围：修复阶段处理 RED 用例，而用例期望与已核实的源端语义冲突时
做法：
- 不用耦合两组偏好来满足测试，保留源端语义
- 在回执里以 BLOCKED 或 disposition 写明 spec / 测试冲突（哪条 AC、哪个用例、源端证据），请求修正 AC 与用例，不判 RESOLVED
