# 修复工单与问题单

交回的是修复工单、问题文件、UT 分诊、修复报告或修复回执：工单建议的修法、RED 用例、§6 预期效果、按截图删减、本轮不修的偏差时

## 触发族

- [测试期望和源端语义冲突时的修复](red-vs-source-conflict/index.md)（1 条）：修复时 RED 用例或 AC 契约的期望和已 grep 核过的源端语义矛盾；修复回执里的 disposition（RESOLVED / BLOCKED）
- [UT 分诊里定成源码缺陷的 RED 用例](ut-triage/index.md)（1 条）：失败用例的输入是纯色、常量这类退化输入，问题文件把它标成 RED、P0 缺陷并建议改算法，却没写源端对同一输入的输出
- [偏离工单建议的修复方案](ticket-deviation/index.md)（1 条）：工单建议的修法（如条件显示）和源码推演的结论不一致，修复改用了别的方案，工单 §6 和 handback 里没写偏离的理由和证据
- [修复轮核出但不修的相邻偏差](known-deviations/index.md)（1 条）：修复时读到的源端和目标代码对不上（如源端带条件、目标无条件调用），交回说明以「不在本轮范围」保留，迁移报告里没有这条已知未修偏差
- [修复报告「预期效果」里的可量化预测](predicted-effect-check/index.md)（1 条）：上一轮修复报告 §6「预期效果」里有可量化预测，这轮判读测出与预测不符、能指到具体公式；产物却记成 residual_low_not_ticketed，理由是页分 ≥0.95 关页
- [按截图删减界面的修复](screenshot-trim-variants/index.md)（1 条）：读到决策台账写着用户可观察行为默认忠实复刻，源码对截图里缺的元素有按渠道或开关隐藏的分支；修复报告写「移除了首屏多余内容」这类按截图删减的结论，没登记渠道或开关变体，也没请用户确认截图属于哪个渠道
