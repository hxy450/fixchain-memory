# 重派资源任务时，派工不能把已完成的 color.json 只标「勿重做」，要写明核对既有 8 位色

审的是：计划与派工
触发（任一种）：
- 读到：前序的资源转换是编排者降级自跑或自写脚本完成的，没走规范指定的资源转换规则；写错的样子：重派或接手的派工把 color.json 列为「已完成部分（勿重做）」，没有要求接手者核对既有 8 位色与源 colors.xml 是否一致
适用范围：资源迁移重派或交接时，派工里对前序已产出的颜色资源的处理
做法：
- 派工里写明：既有 color.json 的 8 位值按 #AARRGGBB 同序规则与源 colors.xml 核对（至少抽查），不一致的改正后再追加新键
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 接手者拿到了同序规则，但只追加新键、没复核既有值，互换的值一直保留到修复：「勿重做」会让前序错误漏过（出处：卡里修好并验证过）
来源：1 张卡，1 个应用
- case-874e7cbffe20f9913597（AntennaPod）：做法第 1 步 ← 建议 4、诊断；取值 1 ← 诊断
