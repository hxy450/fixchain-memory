# 字符串资源在派工和交接里的写法

agent 会看到什么：派工、交接或转换报告涉及把源端字符串资源（strings.xml、@string/app_name、android:text 的字面量、Res.string 的键）带到目标 string.json：键和解析后的值、值语义、缺的条目

## 规矩

- rule-e69763e4e413｜把字面量改成他人单写的资源引用时，交接逐项给「键名=原值」｜读到：页面里有来自安卓布局 `android:text` 的字面量（如徽标里的纯数字序号），资源文件归另一个 agent 单写；写错：交接只写「添加共享字符串 <键名> 至 <键名>」，没给每个键的原值
- rule-1a7d5de78b84｜派页面清单或侦察任务时，导航目的地和页面标题字段同时要资源键和解析后的字面值｜读到：源端导航目的地和页面标题都经资源键引用（枚举 label、路由标题资源、顶部栏 title）；写错：派工自定的清单字段（如 top_level_destinations）只有枚举名、route、icon，没有 label 资源键，也没有解析后的字面值
- rule-32b50387026b｜派发资源或应用身份任务时，应用名写「取源 @string/app_name 的值」，不写字面值｜写错：派工正文写「app_name=某个名字（@string/app_name 按各语言）」这类字面值，且没有引用决策 ID
- rule-2dad435f9514｜转换报告把缺的专属文案列为待补资源或占位，不写「所有引用资源都已存在」｜读到：源布局里有页面专属文案，目标 string.json 检索不到对应条目；写错：转换报告写「所有引用资源都已存在」「未新增共享资源」，没有把缺的专属文案列为需收尾者补充的资源或登记资源占位
- rule-f7ad8c59e6b5｜派发字符串转换时照台账原文带入值语义，不缩成「外层引号剥离」｜读到：决策台账里 strings.xml → string.json 的值语义写着「按 aapt2 编译语义计算值」「未转义双引号剥离」；写错：派发资源转换的说明或转换脚本的注释里删掉了引号剥离这一项，或改写成「成对引号剥离」「去掉外层引号」「strip outer quotes」
- rule-5c2906e0a320｜应用身份裁决按语言列出显示名，并写明 AppScope 与 entry 都覆盖源端语言集合｜读到：源端 android:label 引用的应用名在 values-<语言> 有译名；派工要求语言目录镜像源端实际集合；写错：计划或派工的身份裁决只写「app_name 两处（AppScope + entry Ability label）= <base 名>」，没有按语言列显示名，也没说 AppScope 是否跟随语言集合
- rule-4654e7c5befb｜资源里保留 @string/ 引用数组时，代码级映射表为每个消费方登记解析义务｜读到：转换规则写明 @string/name → $string:name，资源产物的 strarray 条目仍是 '@string/…'；写错：资源映射的「代码级映射」表只给 @drawable 图标数组登记了消费方义务，保留 '@string/…' 的 strarray 数组没有登记
