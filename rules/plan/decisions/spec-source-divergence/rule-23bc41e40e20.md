# 实现时查到 SDK 能力与已批决策前提矛盾，返回信封报 decision_gap 并附 d.ts 证据

审的是：计划与派工
触发（任一种）：
- 读到：台账里 status=approved 的 HARD-DIV 决策前提是「平台没有某能力」（如无 span 级命中检测 API），而 SDK d.ts 里查得到该能力（如 GestureStyle 自 API 12 有 onClick / onLongPress）；写错的样子：返回信封的 decision_gaps 为空，代码照退化方案写（组件级 LongPressGesture + 取首个链接）
适用范围：worker 交回报告时，所依据的已批决策与它查到的 SDK 声明不一致
做法：
- 在返回信封的 decision_gaps 里报这条矛盾：决策编号、决策的前提、查到的 d.ts 文件和符号及原文；不默默沿用退化方案
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onLongPress?: Callback<GestureEvent>（GestureStyleInterface，@since 12）：这类矛盾的一个例子：span 级长按在 SDK 里有声明（出处：鸿蒙 SDK 的 ets/component/styled_string.d.ts，GestureStyleInterface.onLongPress）
