# 重构或迁移模块时，与安卓一致的现有行为不按规格清单当缺陷改，改规格或登记决策

审的是：计划与派工
触发（任一种）：
- 读到：安卓源码入口固定进入某页；迁移前的鸿蒙实现与之一致；只有规格验收清单或 spec gap 条目写着另一种行为（如「进入登录或首页」「按 token 分流」）；写错的样子：重构计划、审计或派工把这个与安卓一致的现有行为列为「关键问题」「已确认缺陷」并派实现去改，没有登记审批决策，也没先改错的清单
适用范围：架构重构或模块迁移阶段，规格清单与现有实现、安卓源码不一致时的计划和派工
做法：
- 默认保持现有行为；要按规格「修正」现有实现前，先对照安卓源码入口；现有实现与安卓一致、只有规格清单不同时，派工写「改规格（或登记决策）」，不派改代码行为
