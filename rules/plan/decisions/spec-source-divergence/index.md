# 派工、台账和源端行为不一致处

agent 会看到什么：派工或规格的要求（如 setInterval 单句柄）和读到的源码不一致，或台账里有与安卓行为不一致的安全隐私约束，交回的 handback、审计结论没有把分歧写进 decision_gaps 或单列待审批

## 规矩

- rule-127898d2b2e2｜源码每轮 new 循环线程而派工要求单句柄时，把分歧写进 handback 的 decision_gaps｜读到：派工或规格要求「setInterval 单句柄」、在 startLoop 里清掉旧句柄，而写前读到的源码每轮 new 循环线程；写错：handback 的 decision_gaps 里没有这条规格分歧，实现直接按单句柄写
- rule-c17eda8abc94｜增量审计判「保留现有实现」时，逐个核对 android_source_anchors 的流程，安全隐私取舍单列待审批｜读到：feature 规格列出的 android_source_anchors 里有上传等完整流程的源文件；决策台账里有与安卓行为不一致的安全或隐私约束；写错：审计或差异报告写「均合理，应保留」「迁模块但不回退配置」，只比对了配置常量（如日志保留期），没有逐个 anchor 核对流程内容和明文策略，也没有把与安卓不一致的安全隐私取舍单列
- rule-48197bf978ef｜重构或迁移模块时，与安卓一致的现有行为不按规格清单当缺陷改，改规格或登记决策｜读到：安卓源码入口固定进入某页；迁移前的鸿蒙实现与之一致；只有规格验收清单或 spec gap 条目写着另一种行为（如「进入登录或首页」「按 token 分流」）；写错：重构计划、审计或派工把这个与安卓一致的现有行为列为「关键问题」「已确认缺陷」并派实现去改，没有登记审批决策，也没先改错的清单
- rule-bdeec876f54a｜上游审计写了源码没有的去重或上限时，按源码实现，并在交接里写明冲突｜读到：上游审计或规格写「前台限定有界去重队列」一类的防护，读到的源码里只有 addAll 整批入队、remove(0) 逐个出队；写错：交接报告把去重、条数上限写成实现特性（「有界串行队列」「去重记录」「每响应最多 N 条」），没写它和源码冲突，也没标成适配策略
- rule-ea449d3c809e｜功能规格与 Base 常量冲突时，返回信封里上报这一冲突｜读到：功能规格的哨兵值和 Base 模型层同名常量的数值不同；写错：返回信封里没有上报这条 Base 冲突，只在本地另定义常量绕过
- rule-23bc41e40e20｜实现时查到 SDK 能力与已批决策前提矛盾，返回信封报 decision_gap 并附 d.ts 证据｜读到：台账里 status=approved 的 HARD-DIV 决策前提是「平台没有某能力」（如无 span 级命中检测 API），而 SDK d.ts 里查得到该能力（如 GestureStyle 自 API 12 有 onClick / onLongPress）；写错：返回信封的 decision_gaps 为空，代码照退化方案写（组件级 LongPressGesture + 取首个链接）
