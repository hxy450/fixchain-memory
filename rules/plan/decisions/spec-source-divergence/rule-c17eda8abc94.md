# 增量审计判「保留现有实现」时，逐个核对 android_source_anchors 的流程，安全隐私取舍单列待审批

审的是：计划与派工
触发（任一种）：
- 读到：feature 规格列出的 android_source_anchors 里有上传等完整流程的源文件；决策台账里有与安卓行为不一致的安全或隐私约束；写错的样子：审计或差异报告写「均合理，应保留」「迁模块但不回退配置」，只比对了配置常量（如日志保留期），没有逐个 anchor 核对流程内容和明文策略，也没有把与安卓不一致的安全隐私取舍单列
适用范围：增量迁移审计决定沿用目标端已有实现时写的审计结论和差异报告
做法：
- 审计报告按 feature 的 android_source_anchors 逐个写核对结果：这个 anchor 里的流程（如上传打包内容、协议）在目标实现里有没有、是否一致
- 与安卓不一致的隐私或安全取舍单独列一节，标为待审批，不并进「保留」的结论
