# 台账要求按源端日志边界改用封装时，计划为每个边界写日志点和验收，不只写库配置

审的是：计划与派工
触发（任一种）：
- 读到：决策台账写「Android 日志对应边界统一改用该封装」，并列出生命周期、网络诊断、同步、推送、卡片刷新、日历导入、日志上传等边界；源端在同步各阶段、网络请求、卡片刷新、导入、本地增删改处调用写文件日志；写错的样子：审计结论或整改计划里日志只出现日志库版本、保留天数（如「BqLog=7天」）、等级、异步、控制台这类配置条目，没有逐个边界的日志点和验收项
适用范围：迁移审计和整改计划阶段，评估目标端已接入的日志框架、规划日志迁移时
做法：
- 审计除了核对等级、异步、保留期、控制台等配置，还要检索源端日志库的直接调用和各层包装调用，按业务边界列出源端写日志的位置，逐个比对目标有没有等价日志
- 计划里为每个边界（网络、同步各阶段、卡片刷新、导入、本地增删改、HTTPDNS、日志上传等）写出日志点和验收项（记哪些字段），不以日志库版本和保留天数作为日志的验收
针对本应用要查的：
- 源端有哪些写日志的调用点：源工程的 Kotlin/Java 文件：先按日志库写文件的方法名全文搜，再找项目自己包装这个方法的工具方法定义，接着搜这些包装方法的调用；把每个调用点归到业务边界（网络、同步的哪一步、卡片刷新、导入、增删改等），连同它记录的字段写成计划里的日志点
