# 以 D-编号作跳过依据前，核对本项目台账里该编号确实覆盖此项，不符就记决策缺口

审的是：计划与派工
触发（任一种）：
- 读到：skill 或派工以决策台账编号（D- 加数字）作为跳过某个字段的依据，如「属部署期决策（对应 D-…）」「部署期再以 scope=full 落地」；写错的样子：跳过清单、派工、worker 信封或迁移报告的遗留披露沿用这个编号作理由，而本项目决策台账里该编号不存在或讲的是别的事，且没有登记决策缺口
- 读到：执行期规则写「某字段属部署期 D-0xx，不碰」，而规定台账是事实源、未命中写「决策缺口」；写错的样子：派工参数或迁移报告写「按 D-0xx 保留/跳过」，项目 decision-ledger 里却没有这个编号；相关技术项没标未完成，也没写「决策缺口」
适用范围：派工、跳过清单、移交登记和迁移报告里以决策台账编号为理由跳过或保留某一项时
做法：
- 援引前在当前工程的决策台账（spec/decision-ledger.md）里 grep 这个 D-编号，确认那一行的结论就是这个字段的决定；skill 文本里的 D-编号不当作本项目编号，签名、部署类决策以台账的实际条目为准
- 编号不存在或含义不同时，不以它作依据、不写「按 D-xxx 保留」：在跳过清单和迁移报告里改记为决策缺口并写明引用不符，把相关技术项标为未完成，派工参数里也不把它当作已批准决策
针对本应用要查的：
- 被援引编号在本项目里的含义：目标工程规格目录下的决策台账（decision-ledger.md），按 D-编号搜条目；读出该行的标题和结论，看是否点名了被跳过的字段、与援引处的说法是否一致
未核实：D-009 的原始决策来源没见到，只核到它不在项目台账里或同号是别的决策
