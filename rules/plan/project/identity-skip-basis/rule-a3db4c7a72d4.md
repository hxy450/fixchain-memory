# 派工前把台账技术必做项逐条映射到任务，skill 默认与之冲突时按台账或写决策缺口

审的是：计划与派工
触发（任一种）：
- 读到：决策台账的技术必做项（T-xxx）要求改某些字段（如 bundleName 改为安卓 applicationId），执行 skill 的默认步骤却跳过这些字段（如 dev-identity 不碰 bundleName / vendor）；写错的样子：派工只派 T 项里的部分字段，写「不碰 bundleName / vendor（部署期字段，保留脚手架值）」，没有引用这条 T 项，也没有安排后续任务或决策缺口；回报把这条 T 项记成 PASS
适用范围：执行编排阶段为资源前置、应用身份等任务撰写派工时
做法：
- 派工前把台账里每条技术必做项逐条映射到具体任务，派工里引用 T 编号并列全它要求的每个字段
- skill 默认与台账冲突时按台账执行；不执行的写入决策缺口阻断；不把 T 项拆成「部分完成」后记 PASS
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 台账是唯一事实源（含技术必做项），台账与其他文档冲突时台账优先，未命中时写决策缺口阻断：执行纪律里的冲突取舍规则（出处：卡里修好并验证过）
针对本应用要查的：
- 这次派工涉及的技术必做项：规格目录下的决策台账，技术必做项（T-xxx）一节；逐条读出要求的字段和目标值，对到派工的任务清单上
