# 派工定分享接收入口时，写独立 multiton Ability 和 utd 声明，不把源 MIME 当 type

审的是：计划与派工
触发（任一种）：
- 读到：参考规格写分享接收是 SEND + DEFAULT + mimeType text/plain，launchMode 未声明即 standard；写错的样子：台账或派工把字段定成「actions=[ohos.want.action.sendData] entities=[entity.system.home] type=text/plain」挂在入口 Ability 上，或写「EntryAbility onCreate/onNewWant 分支有确定写者」
适用范围：编排者给入口配置和接线任务派工、写分享接收入口的决策台账时
做法：
- 派工里写：新建 exported、launchType multiton 的分享承接 Ability；skills 为 actions [ohos.want.action.sendData] 与 uris { scheme: 'file', utd: <源 MIME 对应 UTD>, maxFileSupported: <条数> }；接收端按同一 utd 用 systemShare.getSharedData 取数据
- 验收条目写：从另一个应用打开系统分享面板能看到并选中迁移后的应用，分享后出现独立任务
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- uris 的 utd 适用于分享等场景；maxFileSupported 需与 utd 配合：派工里要写的字段（出处：module-configuration-file.md，uris标签说明）
来源：1 张卡，1 个应用
