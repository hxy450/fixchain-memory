# 权限类占位收口时核对 module.json5 声明和权限能否获得，不凭别条说明标 resolved

审的是：计划与派工
触发（任一种）：
- 读到：占位登记里有权限缺口条目（如媒体库写权限 `ohos.permission.WRITE_IMAGEVIDEO` 声明缺失），交给后续切片收口；写错的样子：该条目被标为 resolved，理由是别处写的「无存储权限门」之类说明；`module.json5` 里没有对应的 `requestPermissions`，也没核对权限是否受限
适用范围：收口阶段处理权限类 deferred-work 和占位条目时
做法：
- 收口前打开 module.json5 核对 requestPermissions 里有没有这项；再查它是否受限开放权限、工程有没有签名授权；拿不到的写明保存路线怎么改，不标 resolved
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- WRITE_IMAGEVIDEO：权限级别 system_basic，授权方式 user_grant，列在受限开放权限里：声明了也不一定拿得到（出处：restricted-permissions.md，ohos.permission.WRITE_IMAGEVIDEO）
针对本应用要查的：
- 这项权限在工程里的状态：目标工程 module.json5 的 requestPermissions；签名所用 profile 的 bundle-info.apl 和 acls；声明、等级、ACL 三项都满足才算可获得
