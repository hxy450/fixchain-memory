# 模块化或插桩批次的验收除 assembleHap 外，加两项搜索和按模块的 ArkTS 检查

审的是：计划与派工
触发（任一种）：
- 读到：派工是把代码迁入或写入 HAR 模块、调整跨模块导入的批次；写错的样子：派工或批次验收里只有 assembleHap 构建通过一项，没有 HAR 目录里 from 'BuildProfile' 为 0、跨模块相对路径为 0 的搜索，也没有按模块的 ArkTS 检查
适用范围：工程拆成宿主 HAP 加 HAR 后，模块化下沉、插桩、结构修复这类批次的验收条目
做法：
- 验收加三项：rg "from 'BuildProfile'" 对所有 HAR 模块目录结果为 0；rg "from '(\.\./)+.*<HAR 所在目录>/" 对宿主和各 HAR 结果为 0；每个模块各跑一次 ArkTS 检查
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 按 HAP 整体 assembleHap 通过时，HAR 里的宿主专属导入仍可能留着：只看 assembleHap 不够的原因（出处：卡里修好并验证过）
针对本应用要查的：
- 哪些目录是 HAR 模块：目标工程根目录的 build-profile.json5 的 modules 列表，以及各模块 module.json5 的 type；type 为 har 的模块目录都列进 BuildProfile 导入的搜索范围
来源：1 张卡，1 个应用
