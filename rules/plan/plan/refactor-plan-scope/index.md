# 重写和重构计划的规格范围与模块拆分

agent 会看到什么：重写或重构的计划（refactor-plan、批次、模块拆分）里，规格索引中已批准但仍是 planned / pending 的规格、功能清单的分组，怎么落成批次任务、验收项和模块

## 规矩

- rule-2fcab0446335｜重写计划时把已批准未执行的规格逐条映射成批次任务和验收项，不用「页面级输入」带过｜读到：spec-index 里有已过 Gate 1、状态仍为 planned / pending 的 BF / F 规格；用户要求整体重审并替换原有局部计划；写错：新计划或审计写「原 BF… 不再独立执行，作为后续计划的页面级输入」，批次任务和验收项里找不到这些规格的编号、要求或关键键名，也没有显式 deferred 决策
- rule-867cb0c5636e｜制定迁移计划时把 planned 增量规格里的退出清理要求写进账户批次验收｜读到：仓库里有状态仍为 planned 的增量规格，写明了退出登录前停止并等待同步、清理账号业务数据、通知刷新这类行为要求；写错：计划的范围只列到已完成的规格编号，漏掉 planned 的增量规格；账户批次的验收只写「登录/退出/游客重建」，完成定义只写「符合 Android 行为」，没有停同步、清账号业务表、广播刷新这几项
- rule-5752ff79d697｜模块拆分计划把功能编号一对一当模块时，补逐页的「页面→归属业务」表｜读到：功能清单按源端历史包分组，同一业务对象的列表、新增页在一个功能组，详情页在另一组，某组的 API 候选同时标两个业务；工程结构规范写「从 entry 的 pages/ 出发，按页面归属拆出 business_xxx」；写错：重构计划把功能编号一对一写成模块（「features/business_… # F 编号」），模块范围照抄功能组标题，没有逐页的归属表，也没标出跨功能组的同一业务对象
