# 模块拆分计划把功能编号一对一当模块时，补逐页的「页面→归属业务」表

审的是：计划与派工
触发（任一种）：
- 读到：功能清单按源端历史包分组，同一业务对象的列表、新增页在一个功能组，详情页在另一组，某组的 API 候选同时标两个业务；工程结构规范写「从 entry 的 pages/ 出发，按页面归属拆出 business_xxx」；写错的样子：重构计划把功能编号一对一写成模块（「features/business_… # F 编号」），模块范围照抄功能组标题，没有逐页的归属表，也没标出跨功能组的同一业务对象
适用范围：架构重构规划阶段，把单模块目标工程拆成多个业务模块、定页面和数据层归属时
做法：
- 计划里逐页列一张「页面→归属业务」表：每页的入口调用方（路由、Tab、跳转来源）和它用到的 Model、ViewModel、Service；源端包名只当线索
- 跨功能组出现的同一业务对象单独标出并写明归属决定：它的列表、新增、详情、编辑页和数据层落同一模块或同一纵向目录，不按功能编号拆开
针对本应用要查的：
- 每个页面的入口调用方：源工程里启动这个页面的地方（Intent 目标、Fragment 列表条目的点击）和目标工程里跳到它的路由调用、Tab 配置；记下是从哪个业务的哪一页进来的；详情、编辑页归到它的列表页所在业务
