# 计划改动清单前，用同构建器同分组的兄弟 key 在目标工程全量 grep，列出所有按 key 的表

审的是：计划与派工
触发（任一种）：
- 读到：目标端把同类能力拆在多个文件里的按 key 白名单或映射表登记，与新条目同构建器、同分组的兄弟 key 已在其中几张表里；写错的样子：计划只按功能点逐个找登记点，改动清单漏了含兄弟 key 的某张白名单或映射表（如说明问号白名单），也没写不加入的源端依据
适用范围：增量迁移的计划阶段，新增按 key 配置的条目时
做法：
- 选一个与新条目同构建器、同分组的已有兄弟 key，在目标工程全量 grep，列出每张包含它的白名单或映射表
- 与计划逐项对照：每张表要么写明把新 key 加在兄弟 key 旁，要么记录不加入的源端依据
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 在兄弟 key 后把新 key 加进说明问号白名单后，名称后的问号说明入口出现：修复的落点（出处：卡里修好并验证过）
针对本应用要查的：
- 目标端登记同类条目的全部按 key 表：目标工程全部 .ets 文件，按兄弟 key 的字面量全量搜；每个命中的数组、Set 或映射表都是一处登记点，逐一确认新 key 在不在
