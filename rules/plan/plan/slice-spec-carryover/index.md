# 切片计划里带入的规格条目

agent 会看到什么：功能或页面规格里写了交互验收、触发时机、事件通道或导航关系，切片计划的 scope、acceptance、integration_points、Step 或接线派工里缺了这一项

## 规矩

- rule-f92c65666160｜写切片验收时，从功能规格的验收标准完整带入，不只留概括项｜读到：功能规格的业务规则和验收里写有具体交互（如「点击复选框切换完成状态」「能够切换完成状态」）；写错：切片计划的 acceptance 只剩「正常显示」「轮播流畅」这类概括项，功能规格里的交互验收没带进来
- rule-2e1430ee93e6｜规格写了首次启动自动触发和设置里手动重置时，切片契约落成启动路径和设置入口两条接线｜读到：功能规格写「播种时机：首次启动时自动播种／设置中可手动重置」，验收含「首次启动自动播种」；写错：切片的 scope 只写「…重置功能」，acceptance 只写「…正常重置」，integration_points 只有设置页重置的 slot，没有启动路径上的首次触发
- rule-a6ef20eb2627｜规格里登记了桥接事件通道时，切片要有实现它的具体 Step｜读到：feature spec 里有原生↔Flutter 事件通道或桥接 Model 的条目；写错：切片只保留服务层和状态管理，事件通道、宿主监听和推送没有进入任何 Step
- rule-85172a9737b3｜派页面接线任务时，把该页 UI spec 的导航关系和状态接口一并交给接线者｜读到：页面的 UI spec（spec/baseline/ui 下的页面规格）写了导航表（如「Skip → 主页」）和状态接口（如「登录成功 ← ViewModel 的完成事件」）；写错：接线派工逐按钮列交互时漏了某个按钮，也没把该页的 UI spec 交给接线者；slice 的 integration_points 里也没有这条跳转
- rule-43b975b875fe｜规格写明的算法要求在转换时被推迟，后续切片的移交项要显式承接并对照完整条件｜读到：规格的验收条目写明「判定算法保留」一类算法要求（如末项可见判定、触发恰一次）；写错：转换报告或代码注释写「精确算法随后续接线」把它推迟，后续切片的派工和移交项里没有承接这条验收条目；或后续切片只补了局部守卫就删掉推迟说明
