# 跨业务依赖模拟用手写骨架时，改用当前代码真实的 import 和路由关系

审的是：计划与派工
触发（任一种）：
- 读到：目标工程当前代码里页面、ViewModel、Service 之间的 import 和路由跳转；写错的样子：重构计划的跨业务依赖模拟只建了手写的依赖骨架文件，没有列出当前代码谁 import 谁、谁跳到谁
适用范围：架构重构规划阶段，模拟拆分后模块之间依赖的那一节
做法：
- 依赖模拟按当前代码逐条列真实的 import 和路由关系（来源页/类 → 目标页/类、所在模块），用它检验拆分后有没有跨业务的反向依赖，不用手写骨架代替
来源：1 张卡，1 个应用
