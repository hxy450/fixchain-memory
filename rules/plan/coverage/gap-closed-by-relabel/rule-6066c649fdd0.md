# 移交里记着「换成语义不同的替代」的 decision-gap 时，不只记遗留，回到生成期补查替代并修正

审的是：计划与派工
触发（任一种）：
- 读到：编译门的派工限定「不得改 spec 语义，已实现的行为代码只做编译级最小改动」；写错的样子：编译门回报的 decision-gap 或迁移报告的遗留披露里写着：单调时钟已换成 Date.now() 墙钟（单调性不同），但没有对应的修正任务，代码保持墙钟
适用范围：编译门修复边界是不改规格语义、而它只找到语义不同的替代时，编译门的回报和主线程对它的处理
做法：
- 编译门只剩语义不同的替代（如 Date.now 墙钟替单调时钟）时，不在门内落地，回报主线程作为 decision-gap
- 主线程收到这类 decision-gap 后，在生成期补查替代 API（单调时钟查到的是 systemDateTime.getUptime(TimeType.ACTIVE, true)）并派修正任务，不只记入遗留披露
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function getUptime(timeType: TimeType, isNanoseconds?: boolean): number：单调时钟的替代，TimeType.ACTIVE 不含深睡眠（出处：鸿蒙 SDK 的 ets/api/@ohos.systemDateTime.d.ts，systemDateTime.getUptime）
