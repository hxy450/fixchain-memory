# 切片收口读到源码后，源 onClick* 与目标按钮、路由参数逐项对照，缺的登记再回写 verified

审的是：计划与派工
触发（任一种）：
- 读到：收口时读到源 Activity 的 onClick* 方法和带来源类型的 start(...) 调用；写错的样子：source notes 写了某个 onClick* 负责 continuation，但 Spec Gap List、handoff 的 cross_slice_edits / deferred_items 都没登记这个动作，页面却被回写为 verified
适用范围：功能切片收口阶段，补读安卓源码后写 source notes、登记跨切片缺口和回写页面状态时
做法：
- 把源 Activity 的每个 onClick* 和带来源类型的 start(...) 调用同目标页的按钮、路由参数逐项对照，不以 source notes 里列出方法名代替核对
- 缺失且归属其他切片的动作登记到 cross_slice_edits / deferred_items 或 Spec Gap List，登记完再决定是否回写 verified
来源：1 张卡，1 个应用
