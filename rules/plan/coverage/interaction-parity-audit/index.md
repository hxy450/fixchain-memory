# 交互对齐和覆盖审计

agent 会看到什么：对齐表、覆盖清单、跳过清单、巡检单、路由 parity 校验里对源端点击、跳转、ViewModel 调用面的判定（✅、一致、已承接、已裁定、入口未渲染）

## 规矩

- rule-b125c34d3b80｜对齐表里标 ✅ 的交互项，要写出代码里对应的那处跳转调用｜读到：页面规格或源 Fragment 里有点击跳转的导航出口（卡片、整项、创建按钮各跳一页）；写错：对齐表、覆盖清单里写「卡片点击跳转 ✅」一类条目，代码里对应组件却没有 onClick、回调为空或只有注释
- rule-6c812f050cb7｜切片收口读到源码后，源 onClick* 与目标按钮、路由参数逐项对照，缺的登记再回写 verified｜读到：收口时读到源 Activity 的 onClick* 方法和带来源类型的 start(...) 调用；写错：source notes 写了某个 onClick* 负责 continuation，但 Spec Gap List、handoff 的 cross_slice_edits / deferred_items 都没登记这个动作，页面却被回写为 verified
- rule-8bf0702c62ce｜路由 parity 校验要比对跳转前的状态写入，源端有、目标缺不能判为一致｜读到：源端跳转处理在 startActivity 之前有共享状态写入（如把播放队列交给播放器）；写错：路由校验把这条路由判为一致或记成 android_source_parity wontfix，比对项只有目标页和参数，没有跳转前的状态写入
- rule-bd06f0c5f1fc｜覆盖审计判定活 ViewModel 已被承接时，逐项对照它的调用面找到具体 AC｜读到：源端 ViewModel 是活码，被 Fragment 调了多个方法（如缓存统计、清理、检查更新）；写错：跳过清单或覆盖审计写「已承接」，依据只是规格范围节的对接点注释或某一条 AC，没有逐项列出调用面各方法对应的 AC
- rule-3e6a06cc7cd7｜对齐审计遇到注释写「已裁定/集成点」的偏差，核运行行为，不一致就列为差异｜读到：目标代码注释写「裁定」「集成点」「决锚」，同时自述源码为死码（如「源码已注释为死码——按集成点接线」）；安卓源码里对应回调体为空或被注释；写错：审计报告或差异清单写「属已裁定偏差，不列差异」，把这项归进已裁定项，后续修复清单里没有它
- rule-49d93bd7b7fe｜巡检见到无调用点的处理函数时，回查源端控件，源端没有就按多余接线处理｜读到：目标页面里有没有任何 UI 或调用点的结果处理函数；源 Fragment 的 setOnClickListener、布局控件和 page spec 的组件表、导航表里都没有对应入口；写错：巡检单把它判成「入口未渲染」类缺陷，依据写 plan 的 integration_points 或某几条 AC，fix 写「按 Android 可达入口补 UI/事件接线」
