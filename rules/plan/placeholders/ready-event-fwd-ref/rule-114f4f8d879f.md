# 登记 FWD-REF 或延迟占位时，列出该事件和缓存键的全部等待方并确认仍有发布者

审的是：计划与派工
触发（任一种）：
- 读到：规格或源码写明某就绪事件是「计数满或定时兜底」后发布，启动流程在缓存为空时等它；写错的样子：占位登记行把定时兜底也列为悬置内容；`FWD-REF` 说明称「与源等待语义等价」，却没列等待方、没写占位期间谁来发布或超时放行
适用范围：为缺 API 的通道登记 FWD-REF 或延迟域占位时
做法：
- 占位里列出该事件和缓存键的全部等待方，逐一写明占位期间仍有的发布者或超时放行；声称「与源等待语义等价」前先核对源端等待的实际上限
- 收尾前搜就绪事件的 post / emit 调用点和缓存键的写入点；有消费者在等而生产者为 0 时，不以占位收尾
