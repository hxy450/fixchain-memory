# 能从源 XML 和位图确定的图片几何量直接落实，不登记或保留为不确定占位

审的是：计划与派工
触发（任一种）：
- 读到：源 XML 里图片是 wrap_content + adjustViewBounds，位图在源资源里可读；写错的样子：registry 把它登记成 forward-ref-uncertain，文字写「adjustViewBounds→layoutWeight+Contain 等价」这类未验证的「等价」，推给后续阶段
- 读到：校准派工要求处理 resolve_by 指向本阶段的图片比例、宽度类占位；写错的样子：校准以「无源图固有比例」「需渲染测量」为由保留占位，代码里的 TODO 标记和缺失的 aspectRatio 原样留下
适用范围：生成阶段登记、校准阶段解除图片比例和宽度类不确定占位时
做法：
- 用资源文件头（sips、PIL 或 webp 头）读出像素尺寸，结合源 XML 算出 aspectRatio、constraintSize 等约束，直接写进 Image，不推给后续阶段或视觉验证
- 确实要登记时，文字写明是未验证的近似，不写成「等价」；校准后读回完整的 Image 修饰链确认占位已落实
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 按 XML 和位图改成 aspectRatio + constraintSize 后删去 TODO 占位：修复时就是这样处理的（出处：卡里修好并验证过）
