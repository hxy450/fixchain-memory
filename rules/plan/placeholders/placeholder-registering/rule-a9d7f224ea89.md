# 已知用户可见差异且有可行实现路线时，当场完成，不用 UNC 占位换编译通过；确需延后按账本归属填 resolve_by

审的是：计划与派工
触发（任一种）：
- 读到：实现者自己已识别出用户可见的行为差异，也想到了可行的实现路线；写错的样子：代码 TODO 挂上 `UNC` 编号的 forward-ref-uncertain 占位，resolve_by 照派工前缀写某个 Slice，而 plans/slices 账本里这一页归别的 Slice；返回报告没列这项降级
适用范围：界面实现阶段，遇到目标端没有现成能力的行为差异、考虑延后时
做法：
- 有可行路线时在当前任务内完成，不登记 forward-ref-uncertain
- 确需延后时，resolve_by 按 plans/slices 账本里本页的实际归属填写，不沿用派工前缀里的 Slice 编号，并在返回报告里显式列出这项降级
针对本应用要查的：
- 这一页实际归哪个 Slice：plans/slices 账本里列出本页的那一行；以账本的归属为准填 resolve_by，和派工前缀不一致时以账本为准
