# 页面只能经外部入口进入时，把入口声明、want 分支、参数键和参数形态作为草稿或 forward-ref 交出

审的是：计划与派工
触发（任一种）：
- 读到：页面规格的导航关系把桌面快捷方式、本地通知点击、推送深链（外部 intent 携带参数）列为本页入口，或写明快捷方式由鸿蒙侧 shortcuts 配置承担；写错的样子：页面注释写「由基座（EntryAbility want 解析）pushPathByName 进入」，但交回的 cross_slice_edits 和 forward-ref / handoff 登记里都没有入口声明和 want 分发这一项
适用范围：切片 worker 交回报告时，module.json5 和 EntryAbility 不在它写域内的外部入口页
做法：
- 把四项作为 cross_slice_edits 草稿或已登记的 forward-ref 交出：module.json5 的 shortcuts / skills 入口声明；EntryAbility onCreate / onNewWant 里的 want 分支；want.parameters 里的参数键；目标页接收的参数形态
- 不只在页面注释里声称「由基座解析进入」；注释里写的接线要么已有承接者的登记，要么改成真实的路由链
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onCreate(want: Want, launchParam: AbilityConstant.LaunchParam): void：冷启时拿到入口 want（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.UIAbility.d.ts，UIAbility.onCreate）
- onNewWant(want: Want, launchParam: AbilityConstant.LaunchParam): void：热启时拿到入口 want（触发 onNewWant 说明这次是热启）（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.UIAbility.d.ts，UIAbility.onNewWant）
- parameters?: Record<string, Object>：入口参数键所在的位置（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.Want.d.ts，Want.parameters）
- metadata 的 name 用 ohos.ability.shortcuts，resource 指向 $profile: 下的快捷方式配置：入口声明在 module.json5 里的写法（出处：module-configuration-file.md，shortcuts标签）
未核实：卡里的行为出自目标 SDK 6.1.1(24) / 6.0.1(21)，声明按本机 API 23 核实
