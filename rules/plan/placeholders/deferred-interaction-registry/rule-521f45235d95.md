# 把数据接线推迟成 FWD-REF 钩子时，钩子说明里写明已读到的加载、恢复、回写行为

审的是：计划与派工
触发（任一种）：
- 读到：源端容器 Fragment 在列表加载完成的观察者里按持久化的选中项算下标再 setCurrentItem，OnPageChangeCallback.onPageSelected 里把当前项写回持久化，容器 ViewModel 组装列表时把某一项 add(0, …) 插到首位；写错的样子：骨架里的 `FWD-REF` 注释或转换报告里的移交项只写 P-ID、resolve_by 和归属切片，钩子被概括成「数据加载」「切页后同步」，没写加载后恢复当前页、切页回写选中项、首项插入和去重这些行为
适用范围：UI 转换把多页容器（ViewPager2 + 每页一个 Fragment → Swiper）的数据接线推迟给其他切片、登记前向钩子时
做法：
- 每个 `FWD-REF` 钩子的说明（或转换报告里对应的移交项）逐条写出已读源码里和它相关的行为契约：加载完成后按哪个持久化选中项定位当前页；切页时回写哪个持久化项；列表首项是什么、按什么键去重；并写出源端在哪个类的哪个方法里做这件事
针对本应用要查的：
- 这个钩子在源端对应的加载、恢复、回写行为：源工程里容器 Fragment 对加载结果的观察者、registerOnPageChangeCallback 的 onPageSelected 回调，以及容器 ViewModel 组装列表的方法体；列出其中读写持久化选中项的调用、对 currentItem 的赋值、对列表的首位插入和去重，逐条抄进钩子说明
