# 工程找不到数据源 getter 时，登记「平台缺口」前先查 SDK d.ts，理由写 d.ts 依据

审的是：计划与派工
触发（任一种）：
- 读到：占位登记写着要注入真实数据源（如 AVRecorder 振幅、拍照会话捕获结果的 ISO / 曝光时间），在工程的控制器或录像引擎里 grep 不到对应 getter；写错的样子：占位登记或代码注释把该项 retag 为「集成期 PD（平台缺口）」，写「HMOS … 无 … 等价 API」「注入不可达」，理由里没有 d.ts 文件和符号
适用范围：接线收口阶段判定数据源缺失是「工程未暴露」还是「平台不支持」，并决定是否登记为平台缺口或延迟项时
做法：
- 登记平台缺口前，到本机 SDK 的 d.ts 里按能力名搜（振幅搜 getAudioCapturerMaxAmplitude，ISO / 曝光搜 getIso、getExposureDuration），把 d.ts 文件和符号写进登记理由；没有 d.ts 依据不写「平台无 API」
- 平台有 API、只是工程未暴露时，登记为补 getter：按单写者职责在控制器或录像引擎里补，或回派给拥有该文件的切片；不用基类默认值加延迟登记顶替
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- AVRecorder.getAudioCapturerMaxAmplitude(): Promise<number>（@since 11）：录音振幅的平台接口（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，AVRecorder.getAudioCapturerMaxAmplitude）
- PhotoSession 继承 ManualIso（getIso(): number）和 ManualExposure（getExposureDuration(): number），API version 24 起：拍照会话读当前 ISO 和曝光时长的平台接口（出处：arkts-apis-camera-PhotoSession.md；arkts-apis-camera-ManualIso.md，getIso；arkts-apis-camera-ManualExposure.md，getExposureDuration）
针对本应用要查的：
- 目标能力在应用所用 SDK 版本里有没有：DevEco SDK 的 ets/api 下对应 Kit 的 d.ts（如 @ohos.multimedia.media.d.ts、@ohos.multimedia.camera.d.ts），按能力名或源端方法名的近义词搜；搜到声明就写文件和符号；看最后一段注释的 @since 是否不高于应用的 compatibleSdkVersion
未核实：本机 SDK 是 API 23，没有 ManualIso / ManualExposure 的声明；getIso、getExposureDuration 按文档副本写（API version 24 起）
