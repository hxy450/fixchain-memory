# 「鸿蒙无对等 API」类延迟占位要写明检索范围；复审时先查 SDK 声明复核前提

审的是：计划与派工
触发（任一种）：
- 读到：占位登记或移交项里有「鸿蒙无对等 API」「待平台 API 核验后接通」一类延迟条目；写错的样子：条目没写检索过哪些 SDK 模块和结果；收尾或复审时只把 resolve_by 改成「集成期」或补一个兜底定时器，前提一直没复核
适用范围：登记和处理以「平台没有对应接口」为由的延迟占位时
做法：
- 登记时在占位里写明检索范围和结果（本地 SDK 的 ets/api、ets/kits 下按能力名或关键词搜了哪些、搜到什么）
- 收尾或复审遇到这类占位，先在 SDK 的 d.ts 里检索复核前提；查到接口就改成实现任务，不只改 resolve_by 或补兜底
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 对本地 SDK 执行一次目录检索即找到 @ohos.identifier.oaid.d.ts：「无对等 API」的前提一查就能推翻（出处：卡里修好并验证过）
