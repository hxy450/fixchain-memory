# 校验正则登记为不确定项前，先用各分支代表输入对照源端，说明里写具体会判错的输入

审的是：计划与派工
触发（任一种）：
- 读到：源端用平台正则常量（如 Patterns.WEB_URL）做校验；写错的样子：占位登记里把自拟正则登记成 `UNC` / forward-ref-uncertain 的「简化等价式」，说明只列猜测的差异、没写具体会判错的输入；或被改判为「近似方案已实现并确认」而没有输入对照记录
适用范围：校验规则类的不确定项在登记、确认或转交时
做法：
- 登记前用覆盖各分支的代表输入和源端预期逐项对照：带 TLD 的域名、IPv4 主机加端口、无 scheme、裸 localhost、IDN/punycode、userinfo、含空格或前导空格
- 仍有差异才登记，说明里写明具体会判错的输入；确认或转交这类不确定项前先跑一遍离线输入对照，不拿视觉核对代替
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 先跑覆盖各分支的对照测试，再替换正则：修复时就是这样做的（出处：卡里修好并验证过）
