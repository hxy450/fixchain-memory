# 占位的关闭和解除

agent 会看到什么：收口或收敛时把 forward-ref / UNC 占位关单、标 resolved、删掉 FWD-REF 标记，或把占位对应的入口记成已接通

## 规矩

- rule-7d7c5ab87d17｜关闭 forward-ref 前逐项对照登记原条目，缺项不整条关单，没做完的在本文件另登记｜读到：占位登记的 forward-ref 行（P-S… 编号）列了多项要求，含横屏变体等结构要求；写错：收口时按「槽位已填组件」关闭这一行，被引用组件缺登记行里的某项（如横屏分支）
- rule-0c26e7fc53d3｜占位登记表里要求运行期切换的条目，消费方接上并核对可达前不删｜写错：重写占位登记表时，触发文本写「持久化并触发…立即切换」的 `P-S*` 条目被删掉或标为已解析，而代码里只做了持久化
- rule-c8d86e330787｜代码里仍有 TODO 或降级注释时，不把 uncertain 占位按降级现状翻成 resolved 关单｜读到：目标代码里对应位置还留着 TODO / 降级注释；写错：登记表里把这条 `UNC` 占位 retag 后「按降级形态关单」或标 resolved，以避开债务闸，代码没改
- rule-a5c5df95edf7｜forward-ref-uncertain 占位解除时附核验证据，不以「共享件已定型」为由删标记｜读到：代码或占位登记里有 FWD-REF … kind=forward-ref-uncertain 标记，指向一处渲染效果没核验过的写法；写错：收敛时删掉了 FWD-REF 标记或把登记行关掉，理由写「共享件已由另一切片定型」，没附截图、dump 或等价单测
- rule-d65e31ae456a｜系统 Kit 提供的能力不登记成「SDK 入仓」占位，forward-ref 只在真实入口建立后关闭｜读到：占位登记里有 forward-ref「华为账号登录入口（鸿蒙等价）建立」，resolve_by 指向本切片；写错：实现留成恒返 null 后把这条 forward-ref 翻成 resolved，另登记一条 thirdparty-sdk 占位「华为账号 SDK(HMOS) 等价入仓」
- rule-69ab5a74ef57｜占位登记同时列「引导」和源端「设置成功」Toast 时，按规格决策只留引导再解除｜读到：规格或已批决策写明能力降级为保存到相册＋引导手动设置，不产出「已设置」状态；写错：占位登记或 FWD-REF 的同一项同时列出「引导…」和源端「Toast 设置成功/失败」回执，没注明 Toast 已被决策取代；或这一项已解除，而对应入口成功路径没有引导、仍有与决策冲突的成功文案
- rule-089d6c07d671｜接线或路由核验不能凭被调方法名或注释判定已接通，要打开方法体确认服务调用和收口｜读到：占位登记把某个页面入口对应到源端的整条业务链（P-S6- 一类编号的条目），被调方法的注释写「由 … busy 态承接」；写错：接线或路由核验记录只按方法名把入口记成已接通的完整链路，没有写服务调用和收口在方法体的哪里
- rule-9297b3f7f7d8｜收口跳转类 marker 前核对发送方 new 的就是目标页 instanceof 的导出类，不只看路由名｜读到：占位登记里同类跳转的先例写着「改用目标页导出的参数类 | resolved」；发送页的参数类和目标页 instanceof 的类名不同；写错：跳转类 marker 被改写成「已接线」「resolved」「目标页已注册 + 参数字段对齐」，而发送页 new 的仍是本地 class，或类名与目标页 onReady 里 instanceof 的不同
- rule-4c8b43a75da2｜解除 FWD-REF 前确认被调方真有登记的语义，不用名字相近的接口顶替后标已解除｜读到：registry 里的占位写着要由被调方的某个能力接管（如「连续快拍停止入口接管，松手即停」），被调文件里找不到这个能力；写错：接线者把占位改成调用名字相近的接口（如重复拍照的取消方法）并在 registry 标为已解除
- rule-88280ffdb32a｜关闭 FWD-REF 注入槽而注入落在别处运行时机时，补带断言的 HANDOFF，不只写已兑现注释｜读到：基座契约列出的 `FWD-REF`（resolve_by=…）注入槽，以及同类启动期接线已有的 HANDOFF 写法（owner 是 EntryAbility.onCreate）；写错：`FWD-REF` 标记被删掉，换成「已兑现：注入点 = ….getInstance()」一类注释，没有留下 owner 指向启动序列、带 verify=grep:… 机械断言的 HANDOFF
- rule-b343aa0bfd7d｜翻译服务未落地时保留 FWD-REF 并写明原因，目标实现写进页面才列 resolved｜读到：marker 注释或页面规格写明了目标实现（运行期翻译服务的 t()），执行规范要求 forward-ref「marker 消失 + 真实实现存在」；写错：回执把该 P-ID 列进 `resolved_fwd_refs`、称「marker 全部消失 + 真实实现落地」，而页面里没有调用目标实现；或者服务还没落地就删了 marker，`uncertain_regions_retained` 里没写
- rule-e0dcadbf8f63｜收口把文案类 P-ID 翻成已解除前，除了 marker 消失，还要查页面接了翻译服务、没留固定语言字面｜读到：worker 回执报某个文案类 P-ID 已解除，页面上的 FWD-REF marker 已消失；写错：收口只核了 marker 消失就把它翻成已解除，closer 的接线清单里没有这一页的翻译接线
- rule-592b5c631f85｜收口跨切片移交项时每个子要求都落地才标已解除，缺一项不翻 resolved｜读到：brief 的一条移交项里写了几件事，例如「订阅补线」和「图片加载经带进度的下载函数接线」；写错：移交项被记为已解除（resolved），实际只落了其中一件：只写了订阅，没有任何生产者发该键的事件
- rule-8213fa6b8a2d｜发现同形参数类不命中后全工程配对修完，点名的统一项未做完不标 resolved｜读到：占位登记点名了上游参数类统一项（owner、范围写明要与 canonical 参数类统一）；写错：收尾时把这一项记进 resolved，移交说明只列了其中一部分；或已确认打不开的跳转只记 to-verify，交给生成期不运行的验证阶段
