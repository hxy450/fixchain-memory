# 占位登记写「平台无此 API」前按能力语义检索 SDK，并写明检索词和文件

审的是：计划与派工
触发（任一种）：
- 读到：派工要求平台映射「按平台事实，不臆测」；规格只给了写入侧接口（如 setWindowBrightness），没说读取侧不存在；写错的样子：占位登记或代码 TODO 里有 UNC 条目，理由写「鸿蒙 window 无亮度读取 API」这类说法，没写检索了哪些词、哪个声明文件
- 读到：前一写者留下的 uncertain 或「平台能力域」类占位；写错的样子：复核或收口时直接保留，或把它 retag 成「平台能力域披露」，没有用一次 SDK 检索复验占位前提
适用范围：实现、复核、收口阶段要登记或保留「平台没有等价能力」类占位时
做法：
- 下结论前在本机 SDK 声明里按能力语义检索三类词：属性名（如 brightness）、属性集合的读取（如 getWindowProperties / WindowProperties）、相关设置模块的键（如 @ohos.settings 的 display 下的键）；不只猜对称的 getter 名
- 三类都检索不到才登记平台能力缺口，占位说明里写明检索词和检索的声明文件；复核时先跑一次检索复验，再决定保留或 retag，死码页、薄任务也一样
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- WindowProperties.brightness: number（由 Window.getWindowProperties() 返回）：窗口亮度的属性式读取，只 grep getWindowBrightness 找不到它（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，WindowProperties.brightness）
- settings.display.SCREEN_BRIGHTNESS_STATUS（0 到 255）：设置模块里的系统亮度键（出处：鸿蒙 SDK 的 ets/api/@ohos.settings.d.ts，display.SCREEN_BRIGHTNESS_STATUS）
