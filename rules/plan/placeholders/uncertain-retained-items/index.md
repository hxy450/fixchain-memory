# 不确定项和近似项的保留与复核

agent 会看到什么：登记里的 UNC 不确定项、retained 近似项、「平台无此 API」类占位，在回执、派工、收口里被保留、预写「保留」、改挂 verify 阶段或标成已解决

## 规矩

- rule-09e323846575｜占位登记写「平台无此 API」前按能力语义检索 SDK，并写明检索词和文件｜读到：派工要求平台映射「按平台事实，不臆测」；规格只给了写入侧接口（如 setWindowBrightness），没说读取侧不存在；写错：占位登记或代码 TODO 里有 UNC 条目，理由写「鸿蒙 window 无亮度读取 API」这类说法，没写检索了哪些词、哪个声明文件
- rule-7b5374ef7015｜派工里对已登记的近似项不预写「保留」，要求执行者对照同工程已有实现复核后再裁决｜读到：决策台账或登记里已有 retained 近似项（P-S 编号的「无对应 / 近似」登记）；写错：slice 工单或二次审视的派工里对这项直接写「……近似——保留」，没要求执行者复核可行性
- rule-5e357c7e5faf｜上游登记为需实测的不确定项没实测时，保持 retained 并写明待测字段和预期值｜读到：上游 TODO 或派工里有 `UNC` 编号的不确定项（如 `P-S1-UNC-…`），写着「注册字体后按实测校正」「若实测不可行则 retained 附因」；写错：回执把该项列进 `uncertain_regions_resolved`、`retained: []`，产物里却没有任何实测记录；代码注释或源码笔记写「数值同值」「≡ 源式」
- rule-27f43ffff572｜可证明的视觉保真缺口交原 owner 修，不 retag 到不运行的 verify 阶段来通过债务闸｜读到：本次只跑 spec → plan → execute，verify 阶段不运行；写错：派工或收口把源有动画、代码是静态图这类遗留项 retag 为 resolve_by=a2h-verify 视觉核验、称「合法外部延迟」让债务闸 PASS，交付摘要写「决策缺口：无」
- rule-a3bed764673a｜占位登记里库行为不确定的 UNC 项，不以「解析侧容忍」「无相等性断言」自行宣告 resolved｜读到：占位登记里有一条 UNC 项，写着库内行为不可见、此处先固定某种形态，交后续切片确认；写错：后续切片的报告在 uncertain_regions_resolved 里列出这条 UNC，理由是「解析侧多形态容忍消化」「全工程无跨栈相等性断言」，没有用库真值核对
- rule-a17e2e75ebc0｜占位登记带明确升级条件且条件已成立时，升级实现并改造先前页面，不登记为 retained｜读到：派工里 `UNC` 占位的处置规则带升级条件（如「AVPlayer 缓冲回调可用则升级真实实现」），执行者已确认该能力可用；写错：决议或登记写成「`UNC` … retained：先前页面为既定架构，本 slice 不推翻」，可实现的 AC 继续保留为占位
- rule-660c8c5dded9｜布局里 gone 的元素与规格明示的可见元素冲突时登记待核，不写平台不显示｜读到：框架布局 XML 里某元素 android:visibility="gone"，而规格或派工明示要有这个可见元素（如「标题线」）；写错：登记项写「平台不显示」「Material 无标题分隔线」后不渲染；或下游没有新证据就把 UNC 待核项改成「确认不补」
