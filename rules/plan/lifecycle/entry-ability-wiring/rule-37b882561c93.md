# 子任务回报导出 API 要宿主调用才生效时，当轮写进拥有宿主文件的切片派工并写明调用点

审的是：计划与派工
触发（任一种）：
- 读到：子任务回报写着「EntryAbility 侧调用接线归属后续段；未接线前取色函数固定返回浅色套」这类：某个导出函数要宿主调用、未接线前默认值错误；写错的样子：拥有 EntryAbility.ets 的切片派工只列了别的事（暂存 want.uri、核对沉浸式），没有要求在 onCreate 与 onConfigurationUpdate 调用主题同步函数；主会话只记「完成」
适用范围：执行编排收到子任务关于「需要宿主接线」的回报、给拥有宿主文件（入口 Ability 等）的切片派工时
做法：
- 当轮把接线写进拥有宿主文件的切片派工，写明调用点：入口 Ability 的 onCreate（冷启动按 this.context.config.colorMode 同步一次）和 onConfigurationUpdate(newConfig)（按 newConfig.colorMode 再同步）各调用一次主题同步函数
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onConfigurationUpdate(newConfig: Configuration): void：系统配置（含深浅色）变化时的回调，UIAbility 继承自 Ability（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.Ability.d.ts，Ability.onConfigurationUpdate）
- config: Configuration：UIAbilityContext 上的当前配置，冷启动时从 config.colorMode 读系统深浅（出处：鸿蒙 SDK 的 ets/api/application/UIAbilityContext.d.ts，UIAbilityContext.config）
