# 源端 Activity 生命周期里的行为

agent 会看到什么：源端 Application / Activity 的 onCreate、onDestroy、onBackPressed 或业务基类钩子里做的事（设主题、发初始化请求、首次启动自动执行、页面级埋点、返回语义），在功能清单、HANDOFF、占位登记、派工或执行总结里怎么交代

## 规矩

- rule-4b90ce4019b4｜划分功能与切片时，宿主 Activity 的初始化请求要归到某个功能或登记未迁｜读到：源端已登录主页的宿主 Activity 在初始化方法里发多个请求（刷新 token、拉配置、检查版本、保存登录信息）；写错：功能清单和切片账本里没有功能认领这个 Activity 的初始化请求：功能只锚到其他模块，切片的接线只到闪屏和引导页
- rule-02fe4bc29b56｜启动恢复的 HANDOFF 要写明「首帧前同步生效」这类时序约束｜读到：源入口 Activity.onCreate 在 super.onCreate 之前设主题，目标的恢复函数交给别的写者接到 EntryAbility.onCreate；写错：`HANDOFF` 只写「在 EntryAbility.onCreate 调用 …」，没写首帧前完成的时序约束；接线方按原样补了一个不等待的 async 调用就把移交项记为已兑现
- rule-9bc0e98b3095｜执行总结声称启动时自动执行某行为前，grep 确认该函数在启动路径上有调用者｜读到：规格或源端写明某行为在首次启动时自动执行；写错：执行总结写「首次运行会自动初始化…」，而 grep 该函数只有设置页一个调用者，启动路径上没有调用
- rule-4b441fa40e8e｜公共基座用组合式基座替代业务基类时，逐页登记接线占位，契约写成每页必须调用｜读到：源端各页面统一继承业务基类、由基类自动做生命周期副作用；规格映射写「页面级埋点改为基座的钩子」，ArkUI struct 不能继承，目标改成需每页调用的组合式基座；写错：占位登记里只有基座自身的条目，没有逐页的基座 / 生命周期埋点接线行；as-built 契约只把基座列为可用 API，接线指针里没有逐页接线
- rule-d32ff47c2d3a｜派工引用注入经验写返回语义时，写经验的前提和源码依据，不写成源码事实｜读到：注入的经验写「源端无返回处理就按 Activity 默认退到后台」这类通用结论；写错：派工或台账写「返回键=退后台（不出栈）」「源 Activity 默认 = 退后台」，没有引源码依据（是否覆写 onBackPressed、onDestroy 做了什么），也没有平台版本依据
- rule-97bb091484d5｜wiring map 指派宿主页 onBackPressed 的负责切片｜读到：规格里有页内弹层或根页的返回语义，返回链分散在 VM 和宿主页面；写错：wiring map 没有列宿主页 onBackPressed，没有指派负责切片
- rule-9677f9ed0bd9｜源偏好在 Application.onCreate 同步构建时，派工验收要求同步 API 预热，不写异步写队列｜读到：源 Application.onCreate 里先同步初始化 SharedPreferences（或 EasyPrefs 等封装），再做其他初始化，此后各处直接读；写错：派工验收标准写「异步初始化容错」「context 未就绪时缓存写队列」，并称这是对齐源端初始化语义
- rule-d4c8b3be25a4｜派工提示不写未核实的「源端缺陷照搬」结论，写成待核问题并给源码锚点｜读到：源码里判定在 setContent 的组合副作用里、写入在 onCreate 尾部，按行序看像是首启就会命中；写错：派工提示或规格写「注意首启也命中——照源码」这类源端行为结论，没标待核、没给源码锚点，也没对照参考文档的用例
