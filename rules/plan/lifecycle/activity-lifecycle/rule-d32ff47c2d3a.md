# 派工引用注入经验写返回语义时，写经验的前提和源码依据，不写成源码事实

审的是：计划与派工
触发（任一种）：
- 读到：注入的经验写「源端无返回处理就按 Activity 默认退到后台」这类通用结论；写错的样子：派工或台账写「返回键=退后台（不出栈）」「源 Activity 默认 = 退后台」，没有引源码依据（是否覆写 onBackPressed、onDestroy 做了什么），也没有平台版本依据
适用范围：编排派工阶段把注入的经验转成派工要求，涉及源端 Activity 默认行为时
做法：
- 派工里写经验的前提，并附源码依据：源 Activity 是否覆写 onBackPressed；onDestroy 做了什么（释放哪些资源）；不写「源 Activity 默认 = …」这类断言
