# 切片计划不把共享服务的 stop 挂到页面 onDisappear，最终释放写在拥有它的 Ability

审的是：计划与派工
触发（任一种）：
- 读到：规格写「页面销毁：取消播放任务并 stop()」，源端清理挂在承载多屏的外层 Composable 的 DisposableEffect 上；写错的样子：切片计划的对接点写「某页面.onDisappear → 共享播放服务.stop()」，并把这个回调登记成跨切片编辑或占位
适用范围：计划阶段为共享服务（播放、连接等）写停止和释放的对接点时
做法：
- 写对接点前先确认页面挂载方式（Navigation 首页内容还是 NavPathStack 页面）和推入子页时实际触发的回调
- 对接点写成：共享服务的最终释放放在拥有它的层级（如 EntryAbility.onDestroy），页面离开只解除自身监听
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onDestroy(): void | Promise<void>：UIAbility 销毁回调，共享服务的最终释放点（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.UIAbility.d.ts，UIAbility.onDestroy）
