# 源端回调和计算入口的全部产出

agent 会看到什么：源端一个结果回调（LiveData observe）或计算入口同时给出几项：成功、失败分支各自的跳转、finish、Toast、本地标记，或一组下游字段；计划、TODO 占位或修复报告里只写了其中几项

## 规矩

- rule-4af4868cc45a｜实现计划按分支列全源端副作用，失败分支不只写导航或留页｜读到：源页面结果回调（LiveData observe）的失败分支同时有 showToast 和跳转或留页；写错：计划的迁移方案里失败分支只剩导航（「失败 → push(登录页)」「失败留当前页」），源端小节写过的 toast 在方案步骤里丢了
- rule-8413082e0d9e｜UI 转换先留业务占位时，TODO 写清源端成功和失败的全部动作，不只写调用名｜读到：源 Activity 点击后调 ViewModel，结果观察者里成功时写本地标记、跳页并 finish()，失败时 Toast；写错：页面留的 `TODO` 只写「某某登录（调用名）」，头注释只写「成功跳某页」，没有写本地标记、关闭当前页和失败提示
- rule-de8a2547bb39｜修复补范围外降级时，报告逐一核对下游消费字段，没填到的写明仍缺｜读到：下游区块消费的字段是一组（如公历、农历、宜、忌），源端由同一个计算入口一起给出；写错：修复报告写「区域已接入」「已接入详情路由」，而降级路径只填了其中几个字段，没列出仍缺的字段
- rule-7085ebc93483｜交接摘要把多分支源方法写成只剩一个分支时，对照源方法原文复核并补全｜读到：源方法原文有几个分支（url 图片、单色、渐变、为空恢复默认）；写错：交接摘要或覆盖说明把源方法记成只剩一支（如「uses url globally」），没提其余分支
