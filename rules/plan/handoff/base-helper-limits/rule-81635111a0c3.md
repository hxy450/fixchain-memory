# Base 回执说共享 helper 返回值可能不准时，下游复用前要求核实或替换，并在基础契约注明限制

审的是：计划与派工
触发（任一种）：
- 读到：Base 阶段交回的回执风险里写共享 helper 的返回值「依赖单连接 / 串行执行语义，可能不准」；写错的样子：调度只记 Base 完成就派发收尾和下游 feature，派工里没有要求核实或替换这个 helper，基础契约里也没写它的限制
适用范围：调度或收尾阶段收到基础层回执、下游 feature 会复用其中共享 helper 时
做法：
- 下游 feature 复用前，派工要求核实或替换这个 helper（如取行数的 helper 改用 store.update / store.delete 的返回值）
- 在基础契约里注明该 helper 的限制（哪个返回值不可靠、该用什么代替）
