# 子任务回执里要带给下一方的事项（交接项、Host-side 项、decision_gaps）

agent 会看到什么：子任务回执、worker 信封或组件头注里写着「写权不属本批（交接项）」、Host-side 项（要宿主补的调用）、decision_gaps 和跨文件注入项；之后的移交登记、下游派工、接线切片派工或给 closer 的摘要里没有这些项，也没点名负责方

## 规矩

- rule-cda9f4b38012｜子任务回报「写权不属本批（交接项）」时，写进下游派工的穷举清单或登记点名负责方的待办｜读到：子任务的回报里写着某项「写权不属本批（交接项）」（如 module.json5 的 orientation）；写错：之后派给下游功能规格或计划的派工说明里，穷举清单没有这一项，也没有登记点名负责方的待办
- rule-fabdbd1650d7｜组件写给宿主的义务要登记进移交登记，编排者把 Host-side 项写进接线切片派工｜读到：子任务回执或组件头注里有 Host-side 项（要宿主补的调用，如打开弹层后 requestFocus）；写错：移交登记表里没有这条；接线切片的派工正文只写「接通打开 / 回调 / 预填 / 取消」，没有这条宿主项
- rule-2c6894836801｜向 closer 转述 worker 信封时，原样保留 decision_gaps 和跨文件注入项及其值域｜读到：worker 信封里有 `decision_gaps` 和跨文件注入项（如入口的 want 解析注入点及其键域、优先级）；写错：派给 closer 的摘要只列已登记的 `P-…` 编号，丢了 decision_gaps、注入项和值域，只给计划路径让它「顺链接读 spec」
