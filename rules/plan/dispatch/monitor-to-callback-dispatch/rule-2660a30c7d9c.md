# 用回调替换 @Monitor 的派工清单，逐个核对触发点是否改写被监听字段

审的是：计划与派工
触发（任一种）：
- 读到：原 @Monitor 只监听运行态和结果两个字段；源端效果按目标值变化触发；写错的样子：派工或补丁方案把不改被监听字段的路径（如每代 tick 的提交尾部）列为回调触发点，没要求变化判断，主会话还判为「语义等价」
适用范围：派发或执行「删 @Monitor、改由生产方显式回调」这类替代方案时
做法：
- 逐个核对新触发点是否会改变原监听的字段；多出来的触发点（如每代提交）在派工里要求加变化判断，或执行方在 handback 里明确提出，不因「清单是协调者有意给的」照做
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- @Monitor 装饰成员方法，监听的属性发生变化时才触发回调：替代方案的触发点要和它等价（出处：arkts-new-monitor.md，装饰器说明）
