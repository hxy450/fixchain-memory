# 存相册未声明 WRITE_IMAGEVIDEO 时改用 showAssetsCreationDialog 授权写入

审的是：代码
触发（任一种）：
- 读到：源端用 MediaStore 入库；规格写鸿蒙侧走免权限的媒体库/picker 通道；写错的样子：代码用 MediaAssetChangeRequest.createAssetRequest + addResource + applyChanges 入库，而 module.json5 的 requestPermissions 里没有 ohos.permission.WRITE_IMAGEVIDEO，也没有运行时申请
适用范围：把图片或视频保存到系统相册、而应用没有声明并申请 ohos.permission.WRITE_IMAGEVIDEO 时
做法：
- 保存前把参考列出的权限与 module.json5 的 requestPermissions、运行时申请逐项对照；applyChanges 需要 WRITE_IMAGEVIDEO，没声明时不走 createAssetRequest + applyChanges
- 改为 const uris = await phAccessHelper.showAssetsCreationDialog([沙箱文件 uri], [{ fileNameExtension: 扩展名, photoType: photoAccessHelper.PhotoType.IMAGE }])；对 uris[0] 用 fileIo.openSync(uri, fileIo.OpenMode.WRITE_ONLY) 取 fd，把沙箱文件内容写进去后关闭
- 用户拒绝时给权限被拒的提示
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- applyChanges(mediaChangeRequest: MediaChangeRequest): Promise<void>，@permission ohos.permission.WRITE_IMAGEVIDEO：createAssetRequest 这条路最后一步需要写相册权限（出处：鸿蒙 SDK 的 ets/api/@ohos.file.photoAccessHelper.d.ts，PhotoAccessHelper.applyChanges）
- showAssetsCreationDialog(srcFileUris: Array<string>, photoCreationConfigs: Array<PhotoCreationConfig>): Promise<Array<string>>：弹窗授权保存，返回已授权给应用的媒体库文件 uri 列表；@since 12，声明里没有 @permission（出处：鸿蒙 SDK 的 ets/api/@ohos.file.photoAccessHelper.d.ts，PhotoAccessHelper.showAssetsCreationDialog）
- PhotoCreationConfig：fileNameExtension: string、photoType: PhotoType 必填，title?、subtype? 可选：每个待保存文件一项（出处：鸿蒙 SDK 的 ets/api/@ohos.file.photoAccessHelper.d.ts，PhotoCreationConfig）
- fileIo.open(desFileUris[0], fileIo.OpenMode.WRITE_ONLY)：官方示例对返回的媒体库 uri 以只写方式打开再复制内容（出处：photoAccessHelper-savebutton.md，使用弹窗授权保存媒体库资源）
- module.json5 的 abilities 里要配 label 和 icon：弹窗要显示应用名称，靠这两项（出处：photoAccessHelper-savebutton.md，使用弹窗授权保存媒体库资源）
- showAssetsCreationDialog 取得媒体库 URI 后 openSync 取 fd 写入，拒绝时提示权限被拒：修好的写法（出处：卡里修好并验证过）
未核实：没核实三方应用能否经 ACL 获得 WRITE_IMAGEVIDEO；用户拒绝时 showAssetsCreationDialog 是返回空列表还是抛错，声明没写
