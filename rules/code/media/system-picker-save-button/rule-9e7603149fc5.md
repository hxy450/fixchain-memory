# SaveButton 保存链里，下载和缓存放在点击之前，SUCCESS 回调内只写相册

审的是：代码
触发（任一种）：
- 读到：现有实现先下载或缓存、准备完成后才渲染 SaveButton；服务或头注写明临时授权在点击 SUCCESS 后只在有限窗口内有效；写错的样子：SaveButton 的 .onClick 里判断 SaveButtonOnClickResult.SUCCESS 之后才开始下载或缓存（await 下载），再调 photoAccessHelper 写相册
适用范围：用 SaveButton 安全控件临时授权写系统相册，保存前还要下载或缓存网络文件（如视频）时，包括把多步保存流程改成主按钮直达
做法：
- 耗时准备放在点击之前：进页时（如 onReady / aboutToAppear）预热下载缓存，或准备完成后才呈现 SaveButton
- .onClick((event, result) => { if (result === SaveButtonOnClickResult.SUCCESS) { … } }) 里只做相册写入和落盘，不在里面下载
- 改造已有保存链时对照原实现的执行顺序；已知会超出授权窗口的写法不因「同款页面也这样」而保留
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onClick(event: SaveButtonCallback): SaveButtonAttribute；SaveButtonCallback = (event: ClickEvent, result: SaveButtonOnClickResult, error?: BusinessError<void>) => void：SaveButton 的点击回调，result 说明授权是否成功（出处：鸿蒙 SDK 的 ets/component/save_button.d.ts，SaveButtonAttribute.onClick、SaveButtonCallback）
- SaveButtonOnClickResult.SUCCESS = 0，TEMPORARY_AUTHORIZATION_FAILED = 1：授权成功和临时授权失败（出处：鸿蒙 SDK 的 ets/component/save_button.d.ts，SaveButtonOnClickResult）
- 从 onClick 回调到调用媒体库特权接口的间隔需控制在授权时间内：API version 19 及之前 10 秒，API version 20 及之后 1 分钟；点一次只获取一次授权：下载放进回调会吃掉授权时间（出处：savebutton.md，约束与限制）
- 冷缓存下载放在 SUCCESS 回调里时写相册静默失败；改为进页预热缓存后保存成功：修好后的时序（出处：卡里修好并验证过）
未核实：卡里的鸿蒙 SDK 是 6.1.1(24)，声明照本机 API 23 核实
