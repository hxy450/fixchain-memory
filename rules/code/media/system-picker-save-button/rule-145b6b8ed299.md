# EXTRA_ALLOW_MULTIPLE 不限数量时，maxSelectNumber 取上限 500

审的是：代码
触发（任一种）：
- 读到：Intent.EXTRA_ALLOW_MULTIPLE 设为 true，源端没有数量限制；写错的样子：maxSelectNumber 写成比 500 小的「安全值」（如 100），或没写（DocumentSelectOptions 默认 1）
适用范围：源端多选文件不限数量、目标用 DocumentViewPicker 选文档时
做法：
- const opts = new picker.DocumentSelectOptions(); opts.maxSelectNumber = 500; 再调 new picker.DocumentViewPicker(context).select(opts)
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- DocumentSelectOptions.maxSelectNumber?: number，取值 1 到 500，默认 1：文档选择器一次能选的最大数量（出处：鸿蒙 SDK 的 ets/api/@ohos.file.picker.d.ts，DocumentSelectOptions.maxSelectNumber）
- select(option?: DocumentSelectOptions): Promise<Array<string>>：DocumentViewPicker 的选择接口，返回所选文档的 URI 数组（出处：鸿蒙 SDK 的 ets/api/@ohos.file.picker.d.ts，DocumentViewPicker.select）
- AudioSelectOptions.maxSelectNumber?: number，默认 1，取值 1 到 500：同族接口：音频选择器的最大数量（出处：鸿蒙 SDK 的 ets/api/@ohos.file.picker.d.ts，AudioSelectOptions.maxSelectNumber）
- PhotoSelectOptions.maxSelectNumber?: number，默认 50，最大 500（@deprecated since 18，改用 photoAccessHelper 的 PhotoSelectOptions.maxSelectNumber）：同族接口：图片视频选择器的最大数量（出处：鸿蒙 SDK 的 ets/api/@ohos.file.picker.d.ts，PhotoSelectOptions.maxSelectNumber）
- EXTRA_ALLOW_MULTIPLE 是布尔 extra，默认 false；为 true 时允许用户选多项：源端多选开关本身不带数量限制（出处：android.content.Intent#EXTRA_ALLOW_MULTIPLE）
