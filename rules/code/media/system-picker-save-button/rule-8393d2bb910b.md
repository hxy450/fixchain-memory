# 源端下载到公共目录并媒体扫描，迁成沙箱下载后要补 DocumentViewPicker.save 导出

审的是：代码
触发（任一种）：
- 读到：源码查 WRITE_EXTERNAL_STORAGE、写外部存储目录，下载成功后 sendBroadcast(ACTION_MEDIA_SCANNER_SCAN_FILE)；写错的样子：request.agent 下载到 filesDir 后直接提示成功并入库，没有 DocumentViewPicker.save；注释写沙箱目录与 /sdcard 目录「等价」或媒体扫描「已裁剪」
适用范围：源端下载产物对用户可见、目标端用 request.agent 下载到应用沙箱的实现
做法：
- 下载完成分支里调 new picker.DocumentViewPicker(context).save({ newFileNames: [默认文件名] })，把沙箱里的文件写进返回的 uri
- 导出成功后才提示下载成功并入库；用户取消时静默、记为取消；写入失败记为失败并提示重试
- 规格链路里没有导出步骤时，在回报里上报规格缺口，不在注释里写「沙箱等价」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- constructor(context: Context)：DocumentViewPicker 的构造，传 UIAbilityContext（出处：鸿蒙 SDK 的 ets/api/@ohos.file.picker.d.ts，DocumentViewPicker.constructor）
- save(option?: DocumentSaveOptions): Promise<Array<string>>：拉起文档保存页，返回保存文件的 URI 数组（出处：鸿蒙 SDK 的 ets/api/@ohos.file.picker.d.ts，DocumentViewPicker.save）
- newFileNames?: Array<string>：要保存的文件名；不给时由用户输入（出处：鸿蒙 SDK 的 ets/api/@ohos.file.picker.d.ts，DocumentSaveOptions.newFileNames）
- Picker 预置空文件并返回 URI 数组，拿到 URI 后用 fileIo.openSync 打开得到 fd 再写入：把沙箱文件内容写到用户选的位置（出处：save-user-file.md，保存文档类文件）
- save(option?: AudioSaveOptions): Promise<Array<string>>：同族接口：AudioViewPicker 的保存，返回 URI 数组（出处：鸿蒙 SDK 的 ets/api/@ohos.file.picker.d.ts，AudioViewPicker.save）
- request.agent 的 Config.saveas 只支持应用存储的 base 目录及其子目录：下载产物只落沙箱，必须另做导出（出处：鸿蒙 SDK 的 ets/api/@ohos.request.d.ts，request.agent.Config.saveas）
未核实：卡里没写把沙箱文件写进 uri 用的具体接口，fileIo.openSync 的写法出自文档；卡里的修复出自 API 24（6.1.1），本机声明是 API 23
