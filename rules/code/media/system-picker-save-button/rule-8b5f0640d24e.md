# 选媒体库写入接口前查 @permission，受限权限没有签名授权就不作默认保存路线

审的是：代码
触发（任一种）：
- 读到：参考资料或规格把 `ohos.permission.WRITE_IMAGEVIDEO` 写成普通 user_grant（`module.json5` 声明 + 运行时请求即可）；写错的样子：默认保存路线调用 `createAsset` / `createAssetRequest` + `applyChanges` / `createAssetWithShortTermPermission`，工程没有对应受限权限的签名授权
适用范围：为媒体库写入选择 photoAccessHelper 接口时
做法：
- 在 SDK d.ts 里查接口注释的 @permission，再查这个权限是否受限开放权限（要 ACL 申请并重新签名）；工程没有授权时，createAsset、createAssetRequest、createAssetWithShortTermPermission 都不作默认保存路线
- 读 SDK 时出现的模式枚举（如 FileGenerationMode）逐项评估，不按记忆里的示例跳过
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- createAsset：@permission ohos.permission.WRITE_IMAGEVIDEO；applyChanges：@permission ohos.permission.WRITE_IMAGEVIDEO，无权限抛 201：应用自建资产和提交变更都声明了写权限（出处：鸿蒙 SDK 的 ets/api/@ohos.file.photoAccessHelper.d.ts，PhotoAccessHelper.createAsset、PhotoAccessHelper.applyChanges）
- createAssetWithShortTermPermission：@permission ohos.permission.SHORT_TERM_WRITE_IMAGEVIDEO：同族接口：短时写权限的创建接口（出处：鸿蒙 SDK 的 ets/api/@ohos.file.photoAccessHelper.d.ts，PhotoAccessHelper.createAssetWithShortTermPermission）
- WRITE_IMAGEVIDEO：权限级别 system_basic，授权方式 user_grant，列在受限开放权限里：普通应用要通过 ACL 跨级申请（出处：restricted-permissions.md，ohos.permission.WRITE_IMAGEVIDEO）
- 受限开放权限要通过 ACL 跨级申请：把 HarmonyAppProvision 的 bundle-info > apl 改成 system_basic 并重新签名：只在 module.json5 声明、运行时请求拿不到（出处：restricted-permissions.md，申请方式）
- 没有签名配置的构建上，createAsset 系列写相册返回 201：上机看到的现象（出处：卡里修好并验证过）
针对本应用要查的：
- 工程有没有这项受限权限的授权：目标工程的签名配置（build-profile.json5 的 signingConfigs）和所用 profile 的 bundle-info.apl、acls；module.json5 的 requestPermissions；apl 不是 system_basic 或 acls 里没有这项权限的，按没有授权处理
