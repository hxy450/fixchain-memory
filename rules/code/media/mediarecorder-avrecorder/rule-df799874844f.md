# 相机录像默认用 AUTO_CREATE_CAMERA_SCENE，不用 createAsset 建 fd

审的是：代码
触发（任一种）：
- 读到：源端 `MediaRecorder` 录像写到输出文件（可能带 `setMaxFileSize`）；决策台账只写「AVRecorder 录制 + photoAccessHelper 媒体库落盘」；写错的样子：`AVRecorderConfig` 没设 `fileGenerationMode`，`url` 用 `helper.createAsset(PhotoType.VIDEO, 'mp4')` + `fileIo.openSync` 得到的 `fd://`，并按 fd 大小轮询 maxFileSize
适用范围：目标是没有受限权限签名授权的普通应用，用 AVRecorder 录相机视频并存入相册时
做法：
- AVRecorderConfig 写 fileGenerationMode: media.FileGenerationMode.AUTO_CREATE_CAMERA_SCENE；prepare 前 avRecorder.on('photoAssetAvailable', (asset) => …)
- stop 后等资产到达，new photoAccessHelper.MediaAssetChangeRequest(asset).saveCameraPhoto() 并 applyChanges，成功后再上报 URI 或释放录制器；超时、释放或出错时 discardCameraPhoto()
- 只有调用方显式给出输出 URI 时才用 APP_CREATE + fd；系统建资产模式下无法轮询文件大小，maxFileSize 和续录明确提示不支持
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- fileGenerationMode?: FileGenerationMode：AVRecorderConfig 的文件创建模式，和 on('photoAssetAvailable') 一起用（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，AVRecorderConfig.fileGenerationMode）
- APP_CREATE = 0（应用在沙箱里建文件）；AUTO_CREATE_CAMERA_SCENE = 1（系统建文件，只在相机录像场景生效，忽略应用设的 URL）：FileGenerationMode 的两个取值（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，FileGenerationMode）
- on(type: 'photoAssetAvailable', callback: Callback<photoAccessHelper.PhotoAsset>): void：AVRecorder 在 stop 完成后回调系统创建的资产；多次订阅以最后一次为准（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，AVRecorder.on('photoAssetAvailable')）
- createAsset(...) 的 @permission 是 ohos.permission.WRITE_IMAGEVIDEO：应用自建视频资产要受限写权限（出处：鸿蒙 SDK 的 ets/api/@ohos.file.photoAccessHelper.d.ts，PhotoAccessHelper.createAsset）
- 默认 AUTO_CREATE_CAMERA_SCENE + stop 后 saveCameraPhoto，录像能存入相册；createAsset 路线报 201：验证过的录像保存路线（出处：卡里修好并验证过）
未核实：卡里的效果在目标 API 24 上验证，本机核对用的是 API 23 的声明
