# 轮询文件大小合成到达上限事件时，未开启自动重启的分支要停止录制

审的是：代码
触发（任一种）：
- 读到：源端 MediaRecorder.setMaxFileSize(...)，onInfo 里未开启自动重启、收到 MEDIA_RECORDER_INFO_MAX_FILESIZE_REACHED 时停止录制；写错的样子：轮询文件大小合成 MAX_FILESIZE_REACHED 后，处理函数只在开启自动重启时处理，未开启时继续录制
适用范围：目标录制器没有原生文件大小上限，用轮询文件大小替代 setMaxFileSize 时
做法：
- 到达上限的处理写全两支：开启自动重启时重启下一段，否则走停止录制流程；关闭时取消进行中的重启
- 对照源端 onInfo 的整条 if/else 链逐支核对目标处理函数，不在中间分支截断
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- setMaxFileSize(long max_filesize_bytes)：单位字节；到达后收到 MEDIA_RECORDER_INFO_MAX_FILESIZE_REACHED，录制被停止：源端到达上限是录制器自己停的，替代后要由应用自己停（出处：android.media.MediaRecorder#setMaxFileSize）
- AVRecorderConfig 里只有 maxDuration，没有文件大小上限字段：文件上限只能由应用层承接（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，AVRecorderConfig）
- readonly size: number：File size, in bytes：轮询用的文件大小单位是字节，和源端上限同单位（出处：鸿蒙 SDK 的 ets/api/@ohos.file.fs.d.ts，Stat.size）
- 到达上限时开启重启则重启下一段、否则停止录制，并在关闭时取消进行中的重启后，未开启重启时到达上限即停止：修好的写法（出处：卡里修好并验证过）
未核实：卡里的行为出自鸿蒙 SDK API 24，本机核对用 API 23
