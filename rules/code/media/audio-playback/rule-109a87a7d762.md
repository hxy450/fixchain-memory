# 源端 SoundPool 短音效，目标用 createSoundPool 预加载后 play，不每次建 AVPlayer

审的是：代码
触发（任一种）：
- 读到：源端 new SoundPool(maxStreams, AudioManager.STREAM_MUSIC, srcQuality) 或 SoundPool.Builder，初始化时 load(context, resId, priority)，事件时 play(soundID, ...)；写错的样子：每次播放都 media.createAVPlayer() → 设 fdSrc → prepare → prepared 后 play，播完 release
适用范围：源端用 android.media.SoundPool 播放短音效、迁成 ArkTS 音效服务时
做法：
- 初始化时建一次 pool = await media.createSoundPool(maxStreams, { usage: audio.StreamUsage.STREAM_USAGE_MUSIC, rendererFlags: 0 })，maxStreams 取源端构造的第 1 个参数
- 初始化时逐个音效 const rf = context.resourceManager.getRawFdSync('<rawfile 名>')；soundID = await pool.load(rf.fd, rf.offset, rf.length)，三个字段原样传，不拼成 fd:// 的 url
- 事件触发时 pool.play(soundID)，用默认参数
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function createSoundPool(maxStreams: number, audioRenderInfo: audio.AudioRendererInfo): Promise<SoundPool>：创建音频池，maxStreams 取 1 到 32（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，media.createSoundPool）
- usage: StreamUsage；rendererFlags: number（保留字段，建议设 0）：AudioRendererInfo 的两个必填字段（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.audio.d.ts，AudioRendererInfo）
- load(fd: number, offset: number, length: number): Promise<number>：按 fd 加载，返回 soundID（出处：鸿蒙 SDK 的 ets/api/multimedia/soundPool.d.ts，SoundPool.load）
- load(uri: string) 不能加载 rawfile 目录里的资源：rawfile 音效只能走 fd、offset、length 的重载（出处：鸿蒙 SDK 的 ets/api/multimedia/soundPool.d.ts，SoundPool.load）
- getRawFdSync(path: string): RawFileDescriptor（含 fd、offset、length）：取 rawfile 的描述符，三个字段原样交给 load（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getRawFdSync）
- play(soundID: number, params?: PlayParameters): Promise<number>：播放已加载的音效，返回 streamID；params 不传用默认值（出处：鸿蒙 SDK 的 ets/api/multimedia/soundPool.d.ts，SoundPool.play）
- 资源加载完成通过 on('loadComplete') 通知，收到回调后再 play：初始化时 load、事件时 play 的先后要满足这一点（出处：using-soundpool-for-playback.md，开发步骤及注意事项）
- 改成 createSoundPool、初始化时 load、play 用默认参数后，触发到出声从约 290ms 降到约 40ms：改法的依据（出处：卡里修好并验证过）
针对本应用要查的：
- 要预加载的音效和它们在目标端的 rawfile 名：源工程里 SoundPool.load(context, R.raw.…, priority) 的调用；目标工程 resources/rawfile 下迁过来的音频文件；每个 load 调用对应一次 getRawFdSync + pool.load，记下返回的 soundID 给对应事件的 play 用
