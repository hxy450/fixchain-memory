# 源端重载开头的 MediaPlayer.release() 只丢旧实例，目标封装类拆出只释放实例的方法，重载路径不调全清

审的是：代码
触发（任一种）：
- 读到：源端重新装载的方法开头只有 MediaPlayer.release(); 字段 = null，随后照常 MediaPlayer.create(...)；宿主 Context 引用只在整体 release() 的全清末段置 null；写错的样子：目标封装类只有一个 release()，里面同时作废令牌、释放播放器并把 context 置 null，重载路径也调这个 release()；或者 load() 自己已先释放旧实例，调用方又调一次全清的 release()
适用范围：把安卓播放器的释放调用映射到目标端自写的播放通道封装类（持有播放器实例、宿主 context、代数令牌）时
做法：
- 封装类拆成两个方法：只释放实例的 releasePlayer(): void { this.token++; this.player?.release(); this.player = null }，和全清的 release(): void { this.releasePlayer(); this.context = null }（反注册事件也只放在全清里）
- 逐个源调用点判断：调用之后这个对象还要继续 create/load 的（重载开头），调只释放实例的方法；只有宿主销毁路径调全清的 release()
- load() 内已经包含释放旧实例这一步时，调用方不再另调释放方法重复这一步
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 重载路径调了置空 context 的全清 release() 后，load 见 context 为空直接走失败回调，播放通道第一次装载就失败；改为重载调只释放实例的方法后恢复：两个释放方法分开的依据（出处：卡里修好并验证过）
- public void release()：Releases resources associated with this MediaPlayer object：源端 release() 只释放这个 MediaPlayer 实例的资源，不涉及宿主 Context（出处：android.media.MediaPlayer#release）
- release(): Promise<void>（除 released 外任何状态都能调）：目标端释放单个 AVPlayer 实例，放在只释放实例的方法里（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，AVPlayer.release）
- function createAVPlayer(): Promise<AVPlayer>：释放旧实例后重载时用它新建 AVPlayer（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，media.createAVPlayer）
