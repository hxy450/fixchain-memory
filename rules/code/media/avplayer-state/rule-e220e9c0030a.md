# AVPlayer 播控方法返回 Promise，要接 .catch，不靠同步 try/catch

审的是：代码
触发（任一种）：
- 写错的样子：对 `avPlayer.prepare()`、`play()`、`pause()`、`stop()`、`reset()` 只包同步 `try { … } catch`，既没 `await` 也没 `.catch`，拒绝落到 unhandledRejection
适用范围：目标代码调用 AVPlayer 的异步播控方法时
做法：
- 这些调用写成 `avPlayer.prepare().catch((e: BusinessError) => {...})` 或在 async 函数里 `await` 并用 try/catch 接；错误已由 on('error') 上报的，`.catch` 里不再重复上报（可为空处理）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- prepare(): Promise<void>；play(): Promise<void>；pause(): Promise<void>：AVPlayer 的播控方法都返回 Promise（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，AVPlayer.prepare / AVPlayer.play / AVPlayer.pause）
- stop(): Promise<void>；reset(): Promise<void>：状态不允许时以 5400102（Operation not allowed）拒绝（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，AVPlayer.stop / AVPlayer.reset）
- stop(): Promise<void>（AVRecorder）：同族接口：AVRecorder 的停止同样返回 Promise（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，AVRecorder.stop）
- 未接住的拒绝落到 unhandledRejection，被写成伪崩溃报告；加 no-op catch 后消失：修好的写法（出处：卡里修好并验证过）
