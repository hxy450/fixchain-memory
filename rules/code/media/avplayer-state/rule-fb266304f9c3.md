# 源端依赖缓冲态或缓冲位时用 AVPlayer+XComponent，接 bufferingUpdate

审的是：代码
触发（任一种）：
- 读到：派工或决策台账写「视频播放用 AVPlayer」，源端 STATE_BUFFERING → LOADING、bufferedPosition.coerceAtLeast(currentPosition)；写错的样子：写成 Video({ src, controller })：onPrepared 后直接 SUCCESS，没有 BUFFERING 态，bufferedMs = currentMs
适用范围：实现视频页或 feed 内嵌播放、源端依赖缓冲态、缓冲位时
做法：
- 播放器用 media.createAVPlayer()，画面用 XComponent({ type: XComponentType.SURFACE, controller })，onLoad 后把 controller.getXComponentSurfaceId() 赋给 player.surfaceId
- player.on('bufferingUpdate', (type, value) => …)：BUFFERING_START 映射 LOADING、BUFFERING_END 映射 SUCCESS；CACHED_DURATION 的 value 加 player.currentTime 得缓冲位
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function createAVPlayer(): Promise<AVPlayer>：创建 AVPlayer（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，media.createAVPlayer）
- on(type: 'bufferingUpdate', callback: OnBufferingUpdateHandler): void；OnBufferingUpdateHandler = (infoType: BufferingInfoType, value: number) => void：缓冲事件，只在网络播放场景支持（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，AVPlayer.on('bufferingUpdate')）
- BufferingInfoType：BUFFERING_START = 1、BUFFERING_END = 2、BUFFERING_PERCENT = 3、CACHED_DURATION = 4（毫秒）：缓冲事件的类型（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，BufferingInfoType）
- readonly currentTime: number（毫秒，-1 为无效值）：当前播放位置，和 CACHED_DURATION 相加得缓冲位（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，AVPlayer.currentTime）
- surfaceId?: string：AVPlayer 渲染画面的窗口 id，取自 XComponent（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，AVPlayer.surfaceId）
- XComponentType.SURFACE；getXComponentSurfaceId(): string：XComponent 的 Surface 类型和取 surfaceId 的方法（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，XComponentType.SURFACE；ets/component/xcomponent.d.ts，XComponentController.getXComponentSurfaceId）
