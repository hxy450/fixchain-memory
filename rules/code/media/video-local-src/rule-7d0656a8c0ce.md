# 跨页把缓存或预载接口的输出接到播放器前，先核对它返回的是路径还是可播放 URI

审的是：代码
触发（任一种）：
- 读到：目标工程的缓存 / 预载工具同时有返回裸绝对路径的方法和返回 file:// 播放地址的方法，同工程已有 Video 的 src 经后者取源；写错的样子：路由参数里传的是返回裸路径那个方法的输出，参数类型或注释没写格式，消费页原样交给 Video({ src: … })；同一任务里只给部分 Video 改用了播放地址
适用范围：跨页接线把缓存、预载接口的输出经路由参数送到播放组件时
做法：
- 接线前读该接口的返回说明：是文件系统路径还是可播放 URI；给播放器的优先传可播放 URI
- 传文件路径时在参数契约（参数类型的字段注释）写明「本地绝对路径，消费方转 file://」，并确认消费页做了转换
- 同一任务已为某个 Video 改用播放地址时，逐个检查工程里其他 Video src 的来源是否经过同样的转换
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Video 的 string 型 src 支持网络地址和 file:// 沙箱 URI：裸路径不在支持的格式里，接线时要分清两种返回（出处：ts-media-components-video.md，VideoOptions对象说明）
针对本应用要查的：
- 缓存 / 预载接口各方法的返回格式：目标工程里缓存或预载工具类的方法注释和 return 语句；返回值以 file:// 开头的是播放地址，以 / 开头的是文件路径
