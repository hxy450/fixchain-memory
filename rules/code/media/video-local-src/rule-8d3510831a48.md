# Video 的 src 来自本地文件路径参数时，在消费处补成 file:// URI，网络地址原样传

审的是：代码
触发（任一种）：
- 读到：源端把本地缓存文件路径经 Intent 传给播放器（VideoView.setVideoPath 或第三方播放器 setUrl(path)）；映射参考的本地视频示例是 Video({ src: '/sdcard/video.mp4' }) 这类裸路径；写错的样子：Video({ src: … }) 拿到的是以 / 开头的沙箱绝对路径，没有 file:// 前缀，也没经过 fileUri 转换
适用范围：页面转换时 Video 的 src 来自路由参数或缓存工具给出的本地文件路径
做法：
- 在赋给 src 的地方统一规范：以 / 开头的沙箱路径写成 'file://' + path（或 fileUri.getUriFromPath(path)），http/https 网络地址原样传入
- 不把映射参考里 '/sdcard/video.mp4' 这类裸路径示例当成可播放的格式
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- src?: string | Resource：Video 的数据源（出处：鸿蒙 SDK 的 ets/component/video.d.ts，VideoOptions.src）
- string 格式支持网络视频地址和 file:// 前缀的应用沙箱 URI：file://<bundleName>/<sandboxPath>；Resource 格式只支持 $rawfile：src 能接受的写法，没有裸路径（出处：ts-media-components-video.md，VideoOptions对象说明）
- getUriFromPath(path: string): string：把应用沙箱里的文件路径转成文件 URI（出处：鸿蒙 SDK 的 ets/api/@ohos.file.fileuri.d.ts，fileUri.getUriFromPath）
- 对以 / 开头的本地路径补 file:// 前缀后赋给 src，视频区正常播放：修好后上机看到的结果（出处：卡里修好并验证过）
未核实：fileUri.getUriFromPath 写法卡里没上机验证；卡里上机看到的行为出自 HarmonyOS API 24，本机声明按 API 23 核实
