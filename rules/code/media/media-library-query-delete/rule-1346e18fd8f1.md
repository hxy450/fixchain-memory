# 整库 getAssets 前先核 READ_IMAGEVIDEO，查询失败不清空缩略图，画廊入口用自存 URI

审的是：代码
触发（任一种）：
- 读到：源端用 MediaStore 查询最近媒体给画廊按钮取缩略图；写错的样子：photoAccessHelper.getAssets 整库查询前没有权限检查；查询失败就 resolve(null) 并把画廊缩略图置空；没有记录应用自己保存的 URI
适用范围：实现阶段写最近媒体查询和画廊缩略图恢复、应用没有 READ_IMAGEVIDEO 授权时
做法：
- 查询前用 abilityAccessCtrl.createAtManager().checkAccessTokenSync(<应用 accessTokenId>, 'ohos.permission.READ_IMAGEVIDEO') 核对，不是 PERMISSION_GRANTED 就不查
- 保存成功后记录并持久化该 URI（如写进偏好），恢复时直接解码它；删除当前 URI 时同步忘掉
- 查询失败或无结果时保留已有缩略图，只在确认当前 URI 被删除时置空
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- checkAccessTokenSync(tokenID: number, permissionName: Permissions): GrantStatus：同步核对权限授予状态（出处：鸿蒙 SDK 的 ets/api/@ohos.abilityAccessCtrl.d.ts，AtManager.checkAccessTokenSync）
- GrantStatus.PERMISSION_GRANTED = 0；createAtManager(): AtManager：已授权的取值和管理器的取法（出处：鸿蒙 SDK 的 ets/api/@ohos.abilityAccessCtrl.d.ts，abilityAccessCtrl.GrantStatus、abilityAccessCtrl.createAtManager）
- getAssets 标 @permission ohos.permission.READ_IMAGEVIDEO，缺权限报 201 Permission denied：不核权限直接查会失败（出处：鸿蒙 SDK 的 ets/api/@ohos.file.photoAccessHelper.d.ts，PhotoAccessHelper.getAssets）
- 加读权限守卫、保存成功的 URI 持久化到偏好、恢复时解码自有 URI、删除时忘掉后，冷启动和恢复时画廊入口不再丢失：返修的落法（出处：卡里修好并验证过）
未核实：卡里环境是 API 24，声明按本机 API 23 核对
