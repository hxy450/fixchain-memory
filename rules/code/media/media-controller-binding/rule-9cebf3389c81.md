# 源端 getter 在服务未运行时懒加载媒体，目标的同步 seekTo、getPosition 也要有回退来源

审的是：代码
触发（任一种）：
- 读到：源端 UI 控制器的取媒体方法在成员为空时懒加载（从偏好里存的当前媒体 ID 读库），seekTo / getPosition / getDuration 都经它取媒体；写错的样子：目标控制器只有异步的取媒体方法带回查，同步的 seekTo、getPosition 只读服务实例上的 playable，服务没起时为 null，规格里「服务未运行」的分支成了死代码
适用范围：实现播放等 UI 控制门面，源端在后台服务未运行时仍要能 seek、读位置和时长
做法：
- 控制器缓存一份媒体：服务上没有 playable 时，同步方法回退到这份缓存；页面读出偏好里的当前媒体后，调控制器的登记方法把它交给控制器；seekTo 也走这条带回退的取法
- 规格写了「服务未运行」分支时，写完确认这个分支的数据前提在冷启动、服务未起时能成立
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 同步取媒体回退到偏好媒体、seekTo 改用它、页面读出偏好媒体后登记给控制器；冷启动快退生效，播放可起播：卡里的修法和复测结果（出处：卡里修好并验证过）
针对本应用要查的：
- 源端控制器在服务未运行时从哪里取当前媒体：源工程 UI 控制器的取媒体 getter 及 seek、位置、时长方法；看 getter 为空时读的偏好键和数据库查询，目标侧在同步路径上提供同一来源
