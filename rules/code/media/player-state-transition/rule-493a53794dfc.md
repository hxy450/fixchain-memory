# 播放暂停切换方法按转移表逐态分派：只有 PLAYING 走 pause()，PAUSED 走 play()

审的是：代码
触发（任一种）：
- 读到：源端 playPause 以辅助谓词分派：`谓词() ? pause() : play()`；规格转移表写 PAUSED 经 play() 或 playPause() 转 PLAYING，只有 PLAYING 经 pause() / playPause() 转 PAUSED；写错的样子：目标写成 `if (state === PLAYING || state === PAUSED) this.pause() else this.play()`，把 pause() 允许的起始态套成切换的分派条件，PAUSED 永远走 pause()
适用范围：把源端播放 / 暂停这类切换方法翻译成目标引擎的状态分支时
做法：
- 把每个当前状态逐一对到规格转移表再写分支：`if (state === PLAYING) { this.pause() } else { this.play() }`，其余状态（PAUSED、STOPPED、NONE 等）都走 play()
- 不把某个方法的前置守卫（pause() 允许的起始态）直接复用为另一个方法的分派条件，两者分别对照规格
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 改为仅 PLAYING → pause()、其余 → play() 后，暂停再点能续播，进度继续走：修好的写法（出处：卡里修好并验证过）
- play(): Promise<void>，只能在 prepared、paused 或 completed 状态调用：目标用 AVPlayer 时，暂停态续播调 play()（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，AVPlayer.play）
- pause(): Promise<void>，只能在 playing 状态调用：pause() 的前置守卫只有 playing，不能拿来当切换的分派条件（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，AVPlayer.pause）
未核实：卡的目标 SDK 是 HarmonyOS 6.1.1(24)，本机声明是 API 23
