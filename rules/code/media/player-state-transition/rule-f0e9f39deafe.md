# 把一套实现的切换步骤接到另一套的入口时，由入口统一切换当前项，不先改写入口守卫读的状态

审的是：代码
触发（任一种）：
- 读到：规格一条写启用实现的跳下一集（`seekToNextMediaItem` → 队列下一项）直接切换当前媒体，另一条写播放入口「同一媒体且 `PLAYING` 即忽略」的守卫；写错的样子：目标代码先把当前媒体字段赋成下一项，再调用带「同一媒体且 `PLAYING` 即忽略」守卫的播放入口，守卫拿下一项和自己比较：在播中跳下一集被吞，旧音频位置记到下一集
适用范围：目标端播放引擎把两套源端实现的步骤拼接在一起时
做法：
- 去掉调用前的当前媒体预赋值，由播放入口在守卫判断之后统一切换当前媒体；切换前先把旧位置记到旧的那一集
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 改为由播放入口切换当前媒体：返修后保留的写法（出处：卡里修好并验证过）
来源：1 张卡，1 个应用
