# AVRecorder 停录发起即登记并返回共享 Promise，prepare/start 链每步 await 后查取消

审的是：代码
触发（任一种）：
- 读到：源端 MediaRecorder.stop() 同步完成后立即把录制器置为 null，以 null 守卫挡住重复停止；写错的样子：停录方法每次都独立调 recorder.stop()，只在 stop() 兑现后才置空；prepare(...).then(...start()) 的回调链不检查是否已被要求停止，准备期间的停止因尚未开始直接返回
适用范围：把安卓 MediaRecorder 的同步停录迁成 AVRecorder 异步调用时
做法：
- 发起停止时同步记下「已要求停止」并保存这次的停止 Promise；再次调用直接返回同一个 Promise，recorder.stop() 只调一次
- prepare、挂接录像输出、start 每次 await 之后都检查「已要求停止」，是就中止启动并走清理；启动进行中的停止先 await 启动任务，再决定 stop 还是直接清理
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- stop(): Promise<void>，只能在 start() 或 pause() 之后调：AVRecorder 准备期间调 stop 不合法，只能取消启动（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，AVRecorder.stop）
- start(): Promise<void>，纯音频录制要在 prepare() 之后、视频录制要在 getInputSurface() 之后调：启动链是 prepare → getInputSurface → 挂接输出 → start 的多段 await（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，AVRecorder.start）
- 共享停止任务并等待启动任务，各步检查已要求停止后，连续两次停止只调一次 recorder.stop，准备期间停止不再开始录制：改后的效果，保留到最终（出处：卡里修好并验证过）
未核实：卡里观察到的行为出自 HarmonyOS 6.1.1（API 24），本机声明按 API 23 核实
