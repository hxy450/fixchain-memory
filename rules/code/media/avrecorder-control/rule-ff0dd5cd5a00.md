# 依赖同步时序的重复计数迁到异步启动时，在发起端同步初始化，用参数区分首段和重复段

审的是：代码
触发（任一种）：
- 读到：源端重复次数在 takePicture() 同步返回后才递减（注释说明避免被重置），启动回调里「剩余为 0 才初始化」在同步调用中执行；写错的样子：初始化放进 prepare().then(() => start().then(...)) 之后的回调，递减却在启动函数同步返回后立即执行
适用范围：把依赖同步调用顺序的计数迁到 AVRecorder 这类 Promise 启动流程时
做法：
- 在发起启动的函数里同步初始化剩余次数，用显式参数（如 repeating: boolean）区分首次段和重复段，只在首次段初始化；删去异步回调里的初始化，不依赖回调晚于递减的时序
- 按规格判据写单测：重复 2 次 → 三段录制，剩余次数依次 2→1→0
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- prepare(config: AVRecorderConfig): Promise<void>；start(): Promise<void>：目标端准备和启动都是异步的，then 里的代码晚于启动函数返回后的同步代码执行（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，AVRecorder.prepare / AVRecorder.start）
- 启动函数加 repeating 参数、只在首次启动（非重复、非文件上限重启）时同步初始化，并删去启动回调里的初始化后，有限重复次数不再被补满：修好的写法（出处：卡里修好并验证过）
未核实：卡里的行为出自鸿蒙 SDK API 24，本机核对用 API 23
