# 拍照能力枚举只排除处理不了的格式并按尺寸去重，不只认 JPEG，DNG 不算 RAW

审的是：代码
触发（任一种）：
- 读到：camera.CameraFormat 枚举里有 RGBA_8888、YUV、JPEG 等多种格式，photoProfiles 里各格式的 size；写错的样子：能力枚举（拍照尺寸列表、拍照录像能否同时进行）只认 CAMERA_FORMAT_JPEG，没有 JPEG 就 throw（如 'no JPEG picture sizes'）；或因有 DNG 格式 profile 就把 RAW 支持置为 true
适用范围：鸿蒙相机实现向上层报告拍照能力（可选尺寸、RAW、拍照录像并行）时
做法：
- 拍照尺寸从 photoProfiles 里所有能处理的格式（JPEG 与 RGBA_8888）取 size，按 width×height 去重；拍照录像并行等能力判断同样不只认 JPEG
- RAW 支持不因出现 DNG 格式的 profile 置为 true，DNG 不等于 RAW 支持
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- readonly size: Size：Profile 的尺寸，去重按它的 width、height（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.camera.d.ts，Profile.size）
- FINAL 改用 JPEG|RGBA_8888 判断支持的拍照 profile，能力枚举按尺寸去重，失败文案改为 'no supported photo profile'：修好后的写法（出处：卡里修好并验证过）
未核实：本机 API 23 的 CameraFormat 里没有 CAMERA_FORMAT_DNG，卡里读到的 DNG = 4 出自 HarmonyOS SDK 6.1.1(24)
