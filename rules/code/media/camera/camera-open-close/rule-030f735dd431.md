# 相机关闭中收到打开请求记为待重开，销毁和 aboutToDisappear 走同一条有序关闭路径

审的是：代码
触发（任一种）：
- 读到：源端关闭进行中 onResume 只置 reopen、关闭完成后再打开；Activity.onDestroy 最多等关闭任务 3000ms；写错的样子：关闭进行中收到的打开相机调用只记日志就返回；aboutToDisappear 里直接调同步的 onDestroy() 强释放，或在已触发销毁序列后又调一次
适用范围：迁移带关闭中状态和销毁等待的相机生命周期时
做法：
- 关闭进行中到来的打开相机调用或 onResume 记一个待重开标志，在关闭的 Promise 完成后检查并执行重开，不丢弃
- onDestroy 与页面 aboutToDisappear 走同一条有序关闭路径：aboutToDisappear 只触发这条异步路径（await 关闭，或按源端上限如 3000ms 用 Promise.race 收尾），不另写同步强释放，也不重复调
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- aboutToDisappear?(): void：页面销毁回调是同步 void，不能在里面 await；只能触发异步关闭路径（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CustomComponent.aboutToDisappear）
- 关闭进行中收到打开相机调用时记待重开、关闭完成后重开；onDestroy 改走同一条异步关闭；页面不再直接调 onDestroy：改后的做法，保留到最终（出处：卡里修好并验证过）
未核实：卡里观察到的行为出自 HarmonyOS 6.1.1（API 24），本机声明按 API 23 核实
