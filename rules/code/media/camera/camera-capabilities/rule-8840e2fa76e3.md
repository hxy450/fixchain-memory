# 源控制器里前屏补光分支回调 UI 时，目标控制器保留「是否需补光」查询和触发出口

审的是：代码
触发（任一种）：
- 写错的样子：目标相机控制器把前屏补光的开、自动两种模式映射成 camera.FlashMode.FLASH_MODE_CLOSE，注释写「由 UI 层承担」，却没有判定是否需要补光的查询、没有触发出口，也没有登记占位和消费方
适用范围：源端相机控制器在预拍（precapture）流程里对前屏补光不开硬件闪光、改为回调 UI，且自动模式按当前 ISO 阈值判定时
做法：
- 控制器保留「是否需要前屏补光」查询：前置摄像头、模式为开，或模式为自动且当前 ISO 达到源端阈值时为真；并提供触发出口（回调或事件）交给 UI 层显示
- 判定或触发跨切片延后时，在占位登记里写明占位和具体消费方（哪个切片的哪个调用方），不只把硬件闪光设为关闭
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- camera.FlashMode.FLASH_MODE_CLOSE = 0：只表示关闭硬件闪光（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.camera.d.ts，FlashMode.FLASH_MODE_CLOSE）
针对本应用要查的：
- 源端自动前屏补光的判定条件和 ISO 阈值：源工程相机控制器里自动前屏补光的判定方法，按 ISO 比较和前摄判断找；读出阈值和前提条件（前摄、相机未释放或暂停），照搬进目标的查询。例：某实现是当前 ISO≥750
未核实：卡里记的鸿蒙 SDK 是 6.1.1(24)，声明按本机 API 23 核实
