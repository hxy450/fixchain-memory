# 源端带约束或过滤参数的尺寸选择，移植时保留参数和降档、过滤分支

审的是：代码
触发（任一种）：
- 读到：源端把约束对象传进偏好读取，选尺寸时约束不满足就降到满足约束的最大尺寸；尺寸列表方法带 boolean 过滤参数（按连拍、扩展模式、约束过滤），调用方传 `(true)`；写错的样子：目标端把约束参数传成 `null` 或改名不用（注释「constraints 未消费」），只实现保存值和最大面积两支；带过滤参数的方法改成无参、直接返回全量列表，弹出菜单的分辨率列表用了它
适用范围：实现阶段移植相机预览的尺寸选择和尺寸列表时
做法：
- 把约束对象传进偏好读取函数，并实现「约束不满足时降到满足约束的最大尺寸（无则最小）」这一支
- 尺寸列表方法保留过滤参数，源端传 (true) 的消费方改调过滤版
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 预览引擎在会话内按约束降档，新增带过滤参数的尺寸列表方法，弹出菜单改用过滤版：修好的做法（出处：卡里修好并验证过）
