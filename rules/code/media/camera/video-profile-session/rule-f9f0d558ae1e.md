# 承接的状态容器里当前索引只有 setter 没调用方时，按源端时机补建表和选档

审的是：代码
触发（任一种）：
- 读到：源端在打开或切换相机后的初始化里建视频质量表、选当前档并写回 SharedPreferences；写错的样子：目标状态容器的当前索引一直是 `-1`，只有 setter 没有调用方；消费方遇到 `-1` 返回 dummy 配置；建表只在表为空时懒加载
适用范围：承接别的切片交来的「全量归本切片」状态容器时，逐个字段核对谁写入
做法：
- 按源端时机（每次相机 setup、每次启动录制）重建质量表并选档：保存值有效用保存值，否则默认档，否则最高档；选完写回偏好
- 是否支持录像看当前档是否存在，不只看尺寸列表非空；找不到可用档时提示编码器不支持
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 预览 setup 和启动录制时都重建质量表、选档并写回偏好；支持录像改看当前档：修好的时机（出处：卡里修好并验证过）
针对本应用要查的：
- 源端选当前档的顺序和默认档：源工程相机预览类里建视频质量表的初始化方法，按视频质量列表和写回偏好的代码搜；读出保存值失效时选哪一档、再退到哪一档，以及写回偏好的那一句
