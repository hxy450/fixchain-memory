# 一次性拍照请求在相机就绪后消费并沿用源端延时，不在 aboutToAppear / onShown 里直接拍

审的是：代码
触发（任一种）：
- 读到：契约或 AC 写“相机打开完成回调内调用、先开后拍”，计划写的挂载点却是 aboutToAppear / onPageShow；写错的样子：页面在 aboutToAppear、onShown 或 onPageShow 里消费请求，拿到后立即调用快门按钮的处理函数
适用范围：接线收口阶段，计划给出的挂载点和已实现的契约冲突、源端在相机打开后才消费一次性请求时
做法：
- 以源端时序和 AC 正文为准：把消费放进引擎打开相机、预览启动之后的回调，沿用源端设置流程按对焦模式的延时再拍；不用页面显示代替相机就绪，也不改走受定时、连拍偏好影响的快门按钮入口
- 页面 onHidden、aboutToDisappear 时作废还没消费的请求，删掉页面显示时直接拍照的代码
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onPageShow?(): void：页面每次显示时调用，只对 @Entry 组件生效：页面显示不等于相机就绪（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CustomComponent.onPageShow）
- open(): Promise<void>：CameraInput 打开相机（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.camera.d.ts，CameraInput.open）
- on(type: 'frameStart', callback: AsyncCallback<void>): void：PreviewOutput 预览开始出帧的回调（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.camera.d.ts，PreviewOutput.on('frameStart')）
- 页面显示后立即拍照被拒；改为引擎打开相机、预览启动后按对焦模式延时拍照，页面隐藏时作废请求后，冷启动和暖启动各保存一张：返修后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端拍照前的延时：源工程相机打开回调之后调用的设置方法（读取入口标志后传参的那个方法）；读它按对焦模式分支设置的延时毫秒数，目标照抄
未核实：卡里的实测出自 HarmonyOS 6.1.1（API 24），本机核实用的是 API 23
