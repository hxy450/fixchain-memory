# 录像选项在目标确实不支持时，创建资产前明确报错，不静默换成别的选项

审的是：代码
触发（任一种）：
- 读到：源端 setOutputFormat(MediaRecorder.OutputFormat.THREE_GPP) 或 OutputFormat.WEBM；写错的样子：3gp/webm 只改了文件扩展名，fileFormat 仍是 ContainerFormatType.CFT_MPEG_4，没有提示
- 读到：源端音源 MediaRecorder.AudioSource.UNPROCESSED；写错的样子：被映射成 AUDIO_SOURCE_TYPE_VOICE_RECOGNITION 或 AUDIO_SOURCE_TYPE_MIC，没有提示
- 读到：源端 setCaptureRate(fps) 与播放帧率不同（延时摄影）；写错的样子：只按 videoFrameRate 录，采集帧率被静默丢掉
适用范围：源端录像选项在目标 AVRecorder 上确无对应能力时
做法：
- 能查询的先查询（编码用 getAvailableEncoder）；确认不支持的，在创建录制资产前抛出专门的「不支持的录像配置」错误，并用本地化文案明确提示用户
- 不改扩展名冒充容器，不换成另一个音源或帧率
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- ContainerFormatType：CFT_MPEG_4 = 'mp4' 是唯一的视频容器，其余 m4a、mp3、wav、amr、aac 都是音频容器：3GP、WebM 没有对应项（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，media.ContainerFormatType）
- AudioSourceType 只有 DEFAULT = 0、MIC = 1、VOICE_RECOGNITION = 2、VOICE_COMMUNICATION = 7、VOICE_MESSAGE = 10、CAMCORDER = 13：没有 UNPROCESSED 的对应项（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，media.AudioSourceType）
- AVRecorderProfile 只有 videoFrameRate（范围 1–60），没有单独的采集帧率字段：采集与播放帧率不同的延时摄影没有对应能力（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，media.AVRecorderProfile.videoFrameRate）
- setCaptureRate：设置与播放帧率不同的采集帧率，并把录制设为 time lapse：源端这个调用的含义（出处：android.media.MediaRecorder#setCaptureRate）
- 3GP/WebM 容器、UNPROCESSED 音源、采集与播放帧率不同，修复后在创建资产前抛错并新增本地化文案：修好的处理（出处：卡里修好并验证过）
未核实：卡的环境是 API 24，声明按本机 API 23 核实
