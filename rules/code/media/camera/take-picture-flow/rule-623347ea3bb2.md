# photoAssetAvailable 没有拍摄 ID，超时或失败时退役 PhotoOutput 并重建会话

审的是：代码
触发（任一种）：
- 读到：`photoAssetAvailable` 回调只交付 `PhotoAsset`，不带 capture 或请求 ID；写错的样子：回调把资产交给当时唯一的结果接收者；拍照超时只清空接收者，同一 `PhotoOutput` 继续订阅，上一张迟到的资产被下一次拍摄收到
适用范围：用 photoAssetAvailable 这类不带请求 ID 的回调实现拍照，并给拍照加了超时时
做法：
- 按一次拍摄独占一个输出设计：超时或失败时退役这个 PhotoOutput（不再接受它之后到达的资产），重建拍照预览会话
- 后续拍照（单拍、连拍）都等会话恢复完成后再发起
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- on(type: 'photoAssetAvailable', callback: AsyncCallback<photoAccessHelper.PhotoAsset>): void：回调只带资产，无法按拍摄区分（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.camera.d.ts，PhotoOutput.on('photoAssetAvailable')）
- 超时或失败即退役 PhotoOutput、重建拍照预览会话并等恢复完成后，不再串帧：验证过的做法（出处：卡里修好并验证过）
未核实：卡里的效果在目标 API 24 上验证，本机核对用的是 API 23 的声明
