# 新增取消补光等待的路径时，复用已有的请求代数作废机制，使迟到的对焦回调不再拍照

审的是：代码
触发（任一种）：
- 写错的样子：新加的取消函数只复位阶段标志等状态，没有让编排器已有的请求代数加一，而已登记的对焦续拍回调按这个代数判断是否继续调 takePicture()
适用范围：编排器已有按请求代数作废旧请求的机制（发起时记下代数、回调里比对、停止时加一），修复或新增取消路径时
做法：
- 取消路径和停止连拍一样让请求代数加一，使已登记的对焦续拍回调在比对时失效
- 加一条「取消后迟到回调不拍照」的测试
