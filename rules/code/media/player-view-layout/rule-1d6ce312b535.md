# PlayerView match_parent 转 XComponent 时按视频宽高比内接算尺寸

审的是：代码
触发（任一种）：
- 读到：布局里 PlayerView 的 layout_width / layout_height 为 match_parent，没写 app:resize_mode；写错的样子：XComponent(SURFACE) 直接 .width('100%').height('100%')，横屏或宽高比不同时画面被拉伸
适用范围：Media3 PlayerView 迁成 XComponent + AVPlayer 的视频画面时
做法：
- 从播放器取视频宽高（AVPlayer 的 on('videoSizeChange', (width, height) => {…}) 或 prepared 后的 width / height），在根区域内按宽高比内接计算 XComponent 的宽高并居中
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- AVPlayer.videoScaleType 默认 VIDEO_SCALE_TYPE_FIT = 0：拉伸铺满渲染区，宽高比不同时不保持比例：XComponent 铺满而不算比例时画面会被拉伸的原因（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，media.VideoScaleType、media.AVPlayer.videoScaleType）
- on(type: 'videoSizeChange', callback: OnVideoSizeChangeHandler): void；OnVideoSizeChangeHandler = (width: number, height: number) => void，默认只在 prepared 态报一次：取视频宽高的事件（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，media.AVPlayer.on('videoSizeChange')）
- AVPlayer.width / height：单位 px，prepared 后有效：也可直接读的视频宽高（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，media.AVPlayer.width）
- PlayerView 的 resize_mode 取值：fit = 0、fixed_width = 1、fixed_height = 2、fill = 3、zoom = 4：源端写了 resize_mode 时按对应方式换算（出处：androidx.media3:media3-ui 包内 res/values/values.xml，resize_mode（按应用依赖的版本））
- PlayerView match_parent 默认等比适配；按宽高比内接计算 surface 宽高后不再拉伸：修复后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端 PlayerView 的缩放方式：源工程布局 XML 里 PlayerView 的 app:resize_mode，或代码里的 setResizeMode；没写按等比内接（fit）；写了 fill / zoom 等按对应方式算 XComponent 尺寸
