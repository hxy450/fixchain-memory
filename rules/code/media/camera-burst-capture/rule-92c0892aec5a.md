# 多帧拍照模式下拍照图元按模式发起多帧并整组交付，不只调一次 capture

审的是：代码
触发（任一种）：
- 读到：源端按 burst 类型（HDR、包围曝光、降噪、快速连拍）决定一次快门的帧数，结果经整组回调一次交付；写错的样子：编排器已按模式算出帧数，拍照图元却只调一次 PhotoOutput.capture()；保存请求 images = [data] 单图入队，算出的连拍标志用 void 表达式丢弃
适用范围：源端有一次快门产生多张的拍照模式，迁成 ArkUI 相机拍照链路时
做法：
- 拍照图元按当前模式发起与源端同样帧数的序列拍摄，全部到齐后经整组结果回调一次交付
- 保存侧按整组接收和保存，不丢弃连拍、快速连拍这类标志
- 加最小检查：一次快门得到的保存请求 images.length 等于该模式的帧数（如 HDR 为 3，包围曝光 5 张时为 5）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- capture(): Promise<void>：一次调用只拍一帧，多帧要按序列多次发起（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.camera.d.ts，PhotoOutput.capture）
针对本应用要查的：
- 各模式一次快门的帧数：源工程拍照预览类里按 burst 类型计算张数的逻辑，以及相机控制器设置 burst 类型的方法；逐个模式读出帧数（固定值或按 ISO / 曝光、偏好张数算），目标端按同一规则发起
