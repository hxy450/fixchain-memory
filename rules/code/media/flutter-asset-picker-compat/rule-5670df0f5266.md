# 冻结业务在 UI isolate 同步处理所选原图时，选图兼容层先按业务上限原生预缩放再交出

审的是：代码
触发（任一种）：
- 读到：冻结的 Dart 业务对 AssetPicker.pickAssets 选出的图用 package:image 的 decodeImage / copyResize / encodePng 在 UI isolate 同步处理，并有长边上限；写错的样子：兼容层把系统选择器返回的缓存原图按原分辨率直接包装成 AssetEntity 交给业务，并称业务压缩调用不需要改
适用范围：Flutter 应用迁到 OHOS、业务 Dart 冻结，选图插件改由兼容层承接时
做法：
- 交出前沿 AssetPicker.pickAssets 的调用方打开上传、AI 处理等代表性消费链，确认是否在 UI isolate 对原图做同步像素运算，以及业务自己的尺寸上限
- 有这类同步处理时，在兼容层用原生图片引擎（ImageSource 解码时设 desiredSize，或 flutter_image_compress 的 compressAndGetFile）按业务上限等比缩到两边都不超界，失败回退原缓存文件；不在 Dart 侧整图解码
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 兼容层经 compressAndGetFile 预缩放到业务上限内、失败回退原文件后，同一张千万像素级原图不再触发 FlutterWatchdog：修好后的做法，业务压缩走不需缩放的分支（出处：卡里修好并验证过）
- function createImageSource(uri: string): ImageSource：按文件路径或 uri 创建原生解码源（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.image.d.ts，image.createImageSource；arkts-apis-image-f.md，image.createImageSource）
- createPixelMap(options?: DecodingOptions): Promise<PixelMap>；DecodingOptions.desiredSize?: Size，(0, 0) 表示按原图尺寸解码：原生解码时直接缩到指定尺寸（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.image.d.ts，ImageSource.createPixelMap、DecodingOptions.desiredSize）
针对本应用要查的：
- 业务的尺寸上限和是否在 UI isolate 同步处理：源 Dart 工程里 grep AssetEntity / AssetPicker.pickAssets 的调用方，顺到压缩、上传函数；读出缩放阈值（如长边上限）；看 decodeImage / copyResize / encode* 是否直接在调用方执行，而不是放进 compute 或 Isolate.run
