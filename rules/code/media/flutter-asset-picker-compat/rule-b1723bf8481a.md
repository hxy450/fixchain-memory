# 选图插件要 READ_IMAGEVIDEO 而应用是普通签名时，在本地兼容包里改走系统选择器

审的是：代码
触发（任一种）：
- 读到：原生插件的 OHOS 实现走 `photoAccessHelper` 读媒体库，默认申请 `ohos.permission.READ_IMAGEVIDEO` / `ohos.permission.WRITE_IMAGEVIDEO`；写错的样子：选图入口仍走插件的媒体库实现（上层选图包保持托管版本、直接调原生插件），`Platform.isOhos` 下没有改走系统选择器的分支
适用范围：APL 为 normal 的应用，Flutter 选图链在 OHOS 上的实现，应用业务 Dart 冻结不能改时
做法：
- 把上层选图包本地化（pubspec 的 dependency_overrides 指向本地包），在选图入口加 `Platform.isOhos` 分支改调系统选择器（卡里验证的是 file_picker 的 FilePicker；建议里也列了 PhotoViewPicker），选中的文件复制到应用缓存
- 把缓存文件包装回原 Dart API 的返回类型（如 AssetEntity），读文件和缩略图为缓存本地路径加直读分支，原 Dart API 签名不变
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- select(option?: PhotoSelectOptions): Promise<PhotoSelectResult>：photoAccessHelper.PhotoViewPicker 拉起系统图库，返回所选文件的 uri（出处：鸿蒙 SDK 的 ets/api/@ohos.file.photoAccessHelper.d.ts，photoAccessHelper.PhotoViewPicker.select）
- PhotoViewPicker 接口本身无需申请权限，适用于界面 UIAbility：系统选择器不依赖 READ_IMAGEVIDEO（出处：photoAccessHelper-photoviewpicker.md，使用Picker选择媒体库资源）
- OHOS 分支改走 FilePicker、复制到应用缓存后包装为 AssetEntity，真机选图回传通过；module.json5 不加媒体库权限：验证过的替换方式（出处：卡里修好并验证过）
