# Web 的 onErrorReceive 切整页失败态时，只在 isMainFrame() 为真时切

审的是：代码
触发（任一种）：
- 读到：安卓端经 WebView（外部库承载、错误处理不可见）打开线上 H5；参考模板里是无参的 `.onErrorReceive(() => {})`；写错的样子：Web 组件 .onErrorReceive(() => { … }) 没有事件参数或不判断 isMainFrame，里面直接置加载失败，显示覆盖整个 Web 区域的失败 / 重新加载卡片
适用范围：ArkWeb 的 Web 组件页面自带整页失败或重试状态，并用 onErrorReceive 触发时
做法：
- 回调补全事件参数：.onErrorReceive((event: OnErrorReceiveEvent) => { if (!event || !event.request.isMainFrame()) { 只记日志; return; } 置加载失败并显示重新加载 })
- 安卓端错误处理不可见时，不把任意加载错误升级为整页遮罩；子资源（图片、脚本等）出错不覆盖已加载的页面
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onErrorReceive(callback: Callback<OnErrorReceiveEvent>): WebAttribute：网页加载资源出错时触发（带事件参数的这一版 @since 12）（出处：鸿蒙 SDK 的 ets/component/web.d.ts，WebAttribute.onErrorReceive）
- 主资源与子资源出错都会回调 onErrorReceive，用 isMainFrame 判断是否主资源报错：回调范围不只主文档（出处：arkts-basic-components-web-events.md，onErrorReceive）
- OnErrorReceiveEvent { request: WebResourceRequest; error: WebResourceError }：事件字段：请求信息和错误信息（出处：鸿蒙 SDK 的 ets/component/web.d.ts，OnErrorReceiveEvent）
- isMainFrame(): boolean：WebResourceRequest 判断请求是否为主框架（出处：鸿蒙 SDK 的 ets/component/web.d.ts，WebResourceRequest.isMainFrame）
- 页面已渲染后子资源失败仍触发 onErrorReceive，失败卡片盖住已加载的页面；加 isMainFrame 判断后不再出现，主文档失败仍可重新加载：修复前后的行为（出处：卡里修好并验证过）
- onHttpErrorReceive(callback: Callback<OnHttpErrorReceiveEvent>): WebAttribute；事件同样带 request: WebResourceRequest：同族接口：资源 HTTP 错误（响应码 >= 400）回调，用它切失败态时同样要按 isMainFrame 区分（出处：鸿蒙 SDK 的 ets/component/web.d.ts，WebAttribute.onHttpErrorReceive、OnHttpErrorReceiveEvent）
未核实：安卓端承载 WebView 的外部库是否区分主框架，卡里没读到
