# shouldOverrideUrlLoading 迁到 onLoadIntercept 时，先判主框架且手势触发

审的是：代码
触发（任一种）：
- 读到：`WebViewClient.shouldOverrideUrlLoading` 只处理用户点开的链接（时码或外链），正文用 `loadDataWithBaseURL` 程序装载；写错的样子：Web 的 .onLoadIntercept(...) 只判 isMainFrame()，再按 getRequestUrl() 逐字等于 baseUrl 或 'about:blank' 放行，其余主框架加载一律外开并 return true，正文停在 about:blank
适用范围：源端 WebView 程序装载正文、只拦用户导航，迁成 ArkWeb Web + onLoadIntercept 时
做法：
- 写成 .onLoadIntercept((event) => { const req = event.data; if (!(req.isMainFrame() && req.isRequestGesture())) { return false; } …按 req.getRequestUrl() 分发时码或外链，处理了就 return true })
- 不猜 loadData 产生的请求 URL 再逐字放行；确需按 URL 判断，先打印真实的 getRequestUrl() 核对
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onLoadIntercept(callback: Callback<OnLoadInterceptEvent, boolean>): WebAttribute：导航触发前回调（含 iframe），返回 true 取消导航、false 允许，undefined/null 按 false（出处：鸿蒙 SDK 的 ets/component/web.d.ts，WebAttribute.onLoadIntercept；arkts-basic-components-web-events.md，onLoadIntercept）
- isRequestGesture(): boolean；isMainFrame(): boolean：WebResourceRequest 上判断请求是否由手势触发、是否主框架（出处：鸿蒙 SDK 的 ets/component/web.d.ts，WebResourceRequest.isRequestGesture、WebResourceRequest.isMainFrame）
- shouldOverrideUrlLoading 不为应用自己用 loadUrl() 发起的导航回调，只报网页、用户和重定向发起的导航：源端拦截的只是用户导航，不含程序装载（出处：android.webkit.WebViewClient#shouldOverrideUrlLoading）
- onLoadIntercept 也为 loadData 自身的主框架导航回调，其请求 URL 不是 baseUrl 原串；改成 isMainFrame()&&isRequestGesture() 后正文正常显示：逐字比 URL 放行会把正文当外链拦掉（出处：卡里修好并验证过）
- onOverrideUrlLoading(callback: OnOverrideUrlLoadingCallback): WebAttribute，回调参数是 WebResourceRequest：同族接口：URL 将要加载到当前 Web 时回调，返回 true 阻止（出处：鸿蒙 SDK 的 ets/component/web.d.ts，WebAttribute.onOverrideUrlLoading）
