# loadDataWithBaseURL 迁移时用五参 loadData 带上 baseUrl，并先清洗

审的是：代码
触发（任一种）：
- 读到：`loadDataWithBaseURL(baseUrl, data, "text/html", "utf-8", historyUrl)`，data 先经清洗器产出；写错的样子：目标写成三参 loadData(data, 'text/html', 'utf-8')，正文直接装原始文本；baseUrl、historyUrl 和清洗都推到占位说明里「如需再切五参重载」
适用范围：源端用 loadDataWithBaseURL 装载清洗后的 HTML、迁成 WebviewController.loadData 时
做法：
- 写成 controller.loadData(data, mimeType, encoding, baseUrl, historyUrl)：源端第 1 参 baseUrl → 第 4 参，第 5 参 historyUrl → 第 5 参，mimeType、encoding 照搬
- 源端 data 先经清洗再装载的，目标同样先调清洗服务再 loadData，不装原始文本
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- loadData(data: string, mimeType: string, encoding: string, baseUrl?: string, historyUrl?: string): void：baseUrl 赋给 window.origin（http/https/data 协议）；baseUrl 为空时 historyUrl 无效（出处：鸿蒙 SDK 的 ets/api/@ohos.web.webview.d.ts，WebviewController.loadData）
- loadDataWithBaseURL(String baseUrl, String data, String mimeType, String encoding, String historyUrl)：源端参数顺序：baseUrl 在第一位（出处：android.webkit.WebView#loadDataWithBaseURL）
- 接上清洗和 baseUrl/historyUrl 后的五参装载保留到最终版本：修好后的装载参数（出处：卡里修好并验证过）
