# 没设 WebViewClient 的 WebView，用 onOverrideUrlLoading 把外链交浏览器

审的是：代码
触发（任一种）：
- 读到：`WebView` 没有 `setWebViewClient`，页面里有外部 http(s) 链接和页内锚点；写错的样子：`Web` 上没有拦截、链接在 Web 里打开；或拦截后交出的 `Want` 没有 `entities: ['entity.system.browsable']`、`startAbility` 失败只记日志不回退；或页内锚点、本地资源也被拦截
适用范围：源 WebView 没有 WebViewClient（安卓默认把跨文档链接交给外部应用），迁成 ArkWeb Web 时的链接导航
做法：
- .onOverrideUrlLoading((req: WebResourceRequest) => { … })：用 req.getRequestUrl() 判断，页内锚点和本地资源（rawfile、file 等）返回 false 放行，其余非本地 URL 返回 true 并交外部打开
- 外部打开写 context.startAbility({ action: 'ohos.want.action.viewData', entities: ['entity.system.browsable'], uri: url })；Promise 失败（catch）时 controller.loadUrl(url) 由 Web 自己加载
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 没有 WebViewClient 时，WebView 默认请系统选合适的处理者打开 URL：源端的默认导航语义：交外部应用（出处：android.webkit.WebViewClient#shouldOverrideUrlLoading）
- onOverrideUrlLoading(callback: OnOverrideUrlLoadingCallback): WebAttribute（@since 12）：URL 将要在当前 Web 里加载时的拦截回调；POST 请求不触发（出处：鸿蒙 SDK 的 ets/component/web.d.ts，WebAttribute.onOverrideUrlLoading）
- type OnOverrideUrlLoadingCallback = (webResourceRequest: WebResourceRequest) => boolean：返回 true 中止当前 Web 加载该 URL，返回 false 照常加载（出处：鸿蒙 SDK 的 ets/component/web.d.ts，OnOverrideUrlLoadingCallback）
- getRequestUrl(): string：WebResourceRequest 上取请求的 URL（出处：鸿蒙 SDK 的 ets/component/web.d.ts，WebResourceRequest.getRequestUrl）
- startAbility(want: Want, options?: StartOptions): Promise<void>：拉起外部浏览器；失败走 catch 回退（出处：鸿蒙 SDK 的 ets/api/application/UIAbilityContext.d.ts，UIAbilityContext.startAbility）
- loadUrl(url: string | Resource, headers?: Array<WebHeader>): void：拉起失败时让 Web 自己加载（出处：鸿蒙 SDK 的 ets/api/@ohos.web.webview.d.ts，WebviewController.loadUrl）
- entities?: Array<string>：隐式 Want 的类别补充（如浏览器），用来筛选能力；拉浏览器填 ['entity.system.browsable']（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.Want.d.ts，Want.entities）
未核实：缺少 browsable 实体的 Want 在设备上的实际表现（直接打开、弹选择器还是失败）卡里没有运行记录；卡里的观察出自 HarmonyOS 6.1.1(24)，本机声明按 API 23 核实
