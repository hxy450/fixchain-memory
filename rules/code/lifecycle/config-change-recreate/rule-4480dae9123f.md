# 目标的横竖翻转或配置变化分支，要重放源端新实例 onCreate 恢复分支和 onResume 的效果

审的是：代码
触发（任一种）：
- 读到：源 Activity 没有 android:configChanges，onCreate 的 savedInstanceState 分支调刷新显示的方法，onResume 复位导航或计数字段；写错的样子：目标页的横竖翻转分支或 onConfigurationUpdate 转发回调只关通关类弹窗、重算视口，没有调对应的刷新显示方法、没有复位那些字段
适用范围：源 Activity 靠重建刷新显示或复位状态、目标页面在配置变化时不重建时，页面的配置变化路径
做法：
- 在翻转或配置变化分支里，关完非托管弹窗后依次执行与源 onCreate 恢复分支、onResume 对应的语句：重读持久数据后刷新显示，把导航或计数字段复位成源 onResume 里赋的值
- 源 onCreate 按启动 Intent 弹窗或导入的，配置变化时同样再执行一次
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onConfigurationUpdate(newConfig: Configuration): void：系统配置变化时 Ability 收到的回调，可在这里转发给页面（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.Ability.d.ts，Ability.onConfigurationUpdate）
- 翻转分支在关闭通关框后补调刷新计分显示的方法并复位返回计数，返修后转屏表现与源端一致：返修后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 要重放的语句和复位值：源工程这个 Activity 的 onCreate（savedInstanceState 非空分支）和 onResume；把有可见效果的调用和赋值逐条对到目标页面的方法和状态变量上，在配置变化分支里照顺序调用
