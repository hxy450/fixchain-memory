# 重放源端重建效果时，先执行 onCreate 体内的写语句，再触发组合副作用对应的判定

审的是：代码
触发（任一种）：
- 读到：源 Activity onCreate 先 setContent（组合内 LifecycleEventEffect(ON_CREATE) 读状态做判定），之后才写同一状态（如计数自增）；写错的样子：配置变化重放里先同步 emit 事件让订阅方重新判定、后执行自增，注释写「源序 setContent 判定先于自增」
适用范围：目标端显式排列首启或配置变化重放里、对应源端 onCreate 与组合副作用的读写次序时
做法：
- 重放按实际执行时机排：先执行对应 onCreate 体内的写语句（如计数自增），再同步发出触发判定的事件（对应组合内 ON_CREATE 副作用）
- 订阅方的注释写「读到自增后的计数」，不写行序依据
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 重放改为先自增、后 emit 判定事件后，连续转屏只在计数到达 9 的倍数时弹出，与源端一致：修好后的次序（出处：卡里修好并验证过）
未核实：冷启路径上目标端 loadContent 回调与页面 aboutToAppear 的实际先后卡里没核实
