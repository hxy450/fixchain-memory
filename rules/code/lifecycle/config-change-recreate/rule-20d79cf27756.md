# 转屏不重建的目标页，依赖宽度的一次性计算挂到 onAreaChange 宽度变化上

审的是：代码
触发（任一种）：
- 读到：源端 Compose 在 BoxWithConstraints 里读 maxWidth，用带键的 LaunchedEffect(key) 算格数或列数；AndroidManifest 的 Activity 没有 android:configChanges；写错的样子：onAreaChange 只在首次测量时发计算事件（如“上次值 < 0”守卫），之后只由键对应的 @Monitor 触发，转屏只重绘
适用范围：目标 UIAbility 与 NavDestination 转屏不重建、源端每次重建都会按新宽度重算的一次性计算
做法：
- .onAreaChange((oldValue: Area, newValue: Area) => { … })：首次测量照常算；之后旧宽 > 0 且新旧宽不同时再算一次；宽度不变不产生副作用，交给 VM 的同值短路
- 规格写着“宽度变化不重算”而源 Activity 未声明 configChanges 时，先核对源 Manifest 和重建路径，再决定是否照写
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onAreaChange(event: (oldValue: Area, newValue: Area) => void): T：组件尺寸或位置变化完成后回调，转屏后宽度变化从这里拿到（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onAreaChange）
- Area.width: Length：新旧宽度比较用的字段（出处：鸿蒙 SDK 的 ets/component/units.d.ts，Area.width）
- 非首次且宽度确有变化时也发计算事件后，转横屏按新宽度重算铺满画布，转回竖屏恢复原格数：按此改后保留（出处：卡里修好并验证过）
- 目标 UIAbility 与 NavDestination 转屏时不重建，宽度变化只表现为 onAreaChange 回调：源端靠重建触发的计算，目标端要自己在尺寸变化里重放（出处：卡里修好并验证过）
