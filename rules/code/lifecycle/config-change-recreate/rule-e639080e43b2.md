# 未声明 configChanges 的 Activity，目标 Ability 要在配置变化时通知页面重建

审的是：代码
触发（任一种）：
- 读到：`AndroidManifest.xml` 里 Activity 没有 `android:configChanges`，Activity 有 `onSaveInstanceState` / `savedInstanceState` 恢复分支；写错的样子：`EntryAbility` 只在 `onForeground` / `onBackground` 发 save / load 事件，没有 `onConfigurationUpdate`，也没订阅 `display.on('change')`；注释写「冷启即 load 即进程恢复」
适用范围：源 Activity 会随配置变化重建，目标 UIAbility 不重建、要自己通知页面时
做法：
- onConfigurationUpdate(newConfig) 里用 language、colorMode、fontSizeScale、fontWeightScale、screenDensity、mcc、mnc 拼成签名，与上次比较，变了才向页面发重建事件
- display.on('change', (id) => …) 里按 displayId 取 Display 的 densityPixels 与上次比较，变了先重测按 vp 存的安全区，再发重建事件
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onConfigurationUpdate(newConfig: Configuration): void：系统配置更新时回调，UIAbility 不重启（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.Ability.d.ts，Ability.onConfigurationUpdate）
- language、colorMode、screenDensity、fontSizeScale、fontWeightScale、mcc、mnc：Configuration 里拼签名用的字段，都是可选的（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.Configuration.d.ts，Configuration）
- function on(type: 'add' | 'remove' | 'change', callback: Callback<number>): void：显示设备变化回调，callback 收到 displayId（出处：鸿蒙 SDK 的 ets/api/@ohos.display.d.ts，display.on）
- function getDisplayByIdSync(displayId: number): Display；Display.densityPixels: number：按 displayId 取 Display，读它的显示密度（出处：鸿蒙 SDK 的 ets/api/@ohos.display.d.ts，display.getDisplayByIdSync、Display.densityPixels）
- 配置签名比较 + display 'change' 比较 densityPixels 后发重建事件，切语言、深浅色、字号、显示大小后页面都按新配置刷新：验证过的接线（出处：卡里修好并验证过）
未核实：显示大小变化在鸿蒙只发 display 'change'、不触发 onConfigurationUpdate，是卡里返修插桩看到的，本机声明没写明
