# onConfigurationUpdate 重放先比配置指纹，没变就返回，变了先落新指纹再重放

审的是：代码
触发（任一种）：
- 读到：源 Activity 没声明 android:configChanges，配置真实变化才整窗重建并重跑 attachBaseContext / onCreate；规格的重放签名带变化域（如 onConfigurationReplay(change: ConfigurationChange)）；写错的样子：onConfigurationUpdate(newConfig) 每次回调都无条件执行重放清单，没有基线、没有字段比较
- 读到：重放项或启动链里会调用 ApplicationContext.setLanguage / i18n.System.setAppPreferredLanguage 重套持久化的应用语言；写错的样子：重放内部调用 setLanguage / setAppPreferredLanguage，又没有变化判据或重入守卫，冷启动栈溢出
适用范围：把源端配置变化整窗重建的副作用，落成 UIAbility.onConfigurationUpdate 的显式重放时
做法：
- 启动 attach 的第一句（在 setLanguage / setAppPreferredLanguage 之前）记录 context.config 指纹：语言按 Intl.Locale 归一到语言子标签，加 colorMode、direction、screenDensity、fontSizeScale、fontWeightScale
- 重放入口算新指纹：和基线相同就直接 return；不同就先把基线更新成新指纹，再执行重放各项（语言重套可以保留）
- 在系统回调里调用会改同一配置的接口（设置语言、深浅色等）前，先确认它会不会同步触发同一回调，再加变化判据或重入守卫
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onConfigurationUpdate(newConfig: Configuration): void：配置更新回调（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.Ability.d.ts，Ability.onConfigurationUpdate）
- language?: string；colorMode?: ConfigurationConstant.ColorMode；direction?: ConfigurationConstant.Direction；screenDensity?: ConfigurationConstant.ScreenDensity；fontSizeScale?: number；fontWeightScale?: number：指纹要取的 Configuration 字段（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.Configuration.d.ts，Configuration）
- setLanguage(language: string): void（只能在主线程调用）：设置应用语言，会改应用配置（出处：鸿蒙 SDK 的 ets/api/application/ApplicationContext.d.ts，ApplicationContext.setLanguage）
- static setAppPreferredLanguage(language: string): void：设置应用偏好语言，启动时按它加载资源（出处：鸿蒙 SDK 的 ets/api/@ohos.i18n.d.ts，i18n.System.setAppPreferredLanguage）
- 设置应用语言后，不再支持订阅系统语言变化：调过 setLanguage 后，回调里不会再因系统语言变化收到 language（出处：subscribe-system-environment-variable-changes.md，设置应用语言）
- setLanguage / setAppPreferredLanguage 即使值没变也会同步回调 onConfigurationUpdate；回调里的 language 写法可能和 context.config 不同（如 en 与 en-Latn-US）：必须比较、比较前要归一语言、基线要先于重放更新（出处：卡里修好并验证过）
- 加指纹后回灌的回调全部短路，两次冷启动的重放计数正常：修好后的结果（出处：卡里修好并验证过）
未核实：「设置语言会同步回调 onConfigurationUpdate」出自卡里的设备观察，声明和文档副本里没有对应原文
