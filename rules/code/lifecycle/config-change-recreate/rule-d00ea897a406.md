# 目标页配置变化时，仍开着的托管弹层改用重建后的内容和回调，不原样保留

审的是：代码
触发（任一种）：
- 读到：源 DialogFragment 的 listener、路径、标题经 setter 注入，所在 Activity 没有 android:configChanges；规格写了重建后按钮只关闭、列表回默认；写错的样子：onConfigurationUpdate 转发到页面的回调、mediaquery 或 onAreaChange 的横竖翻转分支里只关内联弹窗，注释写「托管弹层按契约保留」，openCustomDialog 打开的弹层继续持有原回调和参数；或页面根本没订阅配置变化
适用范围：目标页面在配置变化时不重建、托管对话框用 openCustomDialog 等自定义弹窗承载时，页面的配置变化路径
做法：
- 配置变化路径上，对仍开着、源端是 setter 注入监听的弹层，把按钮回调换成重建后的效果（依赖监听器的按钮只关闭）
- 内容依赖 setter 参数的弹层（列表、标题）：closeCustomDialog 关掉后用默认参数再 openCustomDialog，对应源端无参新实例的内容
- 每个承载这类弹层的页面都要真正接上配置变化通知（Ability 的 onConfigurationUpdate 转发或页面内的横竖翻转监听），不留给后续接线
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- openCustomDialog<T extends Object>(dialogContent: ComponentContent<T>, options?: promptAction.BaseDialogOptions): Promise<void>：PromptAction（UIContext.getPromptAction()）上打开 ComponentContent 自定义弹窗（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.openCustomDialog）
- closeCustomDialog<T extends Object>(dialogContent: ComponentContent<T>): Promise<void>：同族接口：关闭对应 ComponentContent 的弹窗，重开前先关（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.closeCustomDialog）
- updateCustomDialog<T extends Object>(dialogContent: ComponentContent<T>, options: promptAction.BaseDialogOptions): Promise<void>；只能更新 alignment、offset、autoCancel、maskColor：同族接口：不能用它换弹窗内容和回调（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.updateCustomDialog）
- onConfigurationUpdate(newConfig: Configuration): void：系统配置变化时 Ability 收到的回调，UIAbility 不重启（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.Ability.d.ts，Ability.onConfigurationUpdate；subscribe-system-environment-variable-changes.md，在UIAbility组件中订阅回调）
- 配置变化时按默认参数重开列表类弹层；标题框、导入框这类弹层把回调换成只关闭：返修后的写法（出处：卡里修好并验证过）
