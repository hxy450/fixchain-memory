# 源端 onCreate 里 findViewById 后立即调 setter 时，目标在子组件登记时回调宿主完成接线

审的是：代码
触发（任一种）：
- 读到：Activity.onCreate 里 findViewById 取到自定义 View 后立即调它的 setter（设状态、设触摸监听）；写错的样子：子组件 aboutToAppear 只把自身写进宿主传入的句柄、不回调宿主，宿主在 NavDestination.onReady 里读句柄后接线
适用范围：目标页以 NavDestination 为根、宿主拿不到子 struct 实例、改由子组件登记句柄时
做法：
- 句柄加登记回调（如 onAttach）：子组件 aboutToAppear 写入句柄后立即调用它，宿主在回调里完成全部 setter 接线
- 宿主自己的初始化（如 onReady 里的 init）发现句柄已登记时调用同一个接线函数，无论先后都只经这一条路径接通
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onReady(callback: Callback<NavDestinationContext>): NavDestinationAttribute，在 NavDestination 的子组件创建之前回调：onReady 时子组件的 aboutToAppear 还没执行，句柄为空（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onReady）
- aboutToAppear 在创建自定义组件的新实例后、build() 执行前调用：子组件的登记发生在它被创建时，晚于宿主的 onReady（出处：ts-custom-component-lifecycle.md，aboutToAppear）
- 句柄增 onAttach，子组件 aboutToAppear 登记后调用；宿主在 aboutToAppear 挂上 onAttach，初始化里句柄非空时也调用同一接线函数：修好后的做法（出处：卡里修好并验证过）
