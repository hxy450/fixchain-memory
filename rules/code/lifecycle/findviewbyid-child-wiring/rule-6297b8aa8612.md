# 依赖宿主生命周期回调和子组件创建的先后时，照 d.ts 注释写，没核实就按与先后无关设计

审的是：代码
触发（任一种）：
- 读到：源端在 onCreate 里用 findViewById 同步拿到子 View 引用；写错的样子：注释写「句柄登记于子组件 aboutToAppear，onReady 时必已就绪」「页面 onReady 后注入」这类没核实的先后断言
适用范围：宿主在 NavDestination.onReady、onShown、aboutToAppear 里使用子组件才登记的东西时
做法：
- 写前在本机 SDK 对应 .d.ts 里读该回调的完整注释段（不只看签名行），把核实到的先后写进注释；NavDestination.onReady 在其子组件创建之前回调
- 没核实时按与先后无关设计（登记回调），不在注释里写「必已就绪」之类的断言
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onReady：当 NavDestination 即将构建子组件之前触发：onReady 早于子组件 aboutToAppear（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onReady；ts-basic-components-navdestination.md，onReady）
- onShown(callback: Callback<VisibilityChangeReason>): NavDestinationAttribute：同族接口：NavDestination 页面显示时回调（API 21 起带显示原因）（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onShown）
