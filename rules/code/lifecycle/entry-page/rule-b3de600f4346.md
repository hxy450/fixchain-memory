# 页面从异步装配的服务槽位取依赖时，提供可等待、失败可复位的幂等就绪门，首屏 await 后再路由

审的是：代码
触发（任一种）：
- 读到：EntryAbility.onCreate 以 void 方式调用异步装配（不等待），随后 onWindowStageCreate 里 loadContent 加载入口页；写错的样子：首屏在 onReady 里同步读可空槽位，读到 null 只记一条日志就 return，沿用默认路由；或只有 Ability 私有的 Promise，首屏没法等
适用范围：启动所需服务由 EntryAbility 异步装配到组装根槽位、首屏从槽位取依赖时
做法：
- 组装根提供一个幂等的就绪门：返回同一个 Promise，失败时复位以便重试；EntryAbility 和首屏都调它
- 首屏在 onReady 里先 await 就绪门再计算路由；读到 null 时不静默 return 沿用默认路由，按失败处理
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onCreate(want: Want, launchParam: AbilityConstant.LaunchParam): void，同步返回，不支持异步回调：onCreate 里起的异步装配不会被等待，页面可能先于装配完成（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.UIAbility.d.ts，UIAbility.onCreate）
- onWindowStageCreate(windowStage: window.WindowStage): void：入口页在这里 loadContent，与 onCreate 里的异步装配并行（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.UIAbility.d.ts，UIAbility.onWindowStageCreate）
