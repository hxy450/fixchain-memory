# 报 10905402 或 @Entry 与 export 同在时，先判定页面角色再改登记或装饰器

审的是：代码
触发（任一种）：
- 读到：编译错误 10905402：main_pages 登记的页面须有且仅有一个 @Entry；写错的样子：给被 Tabs 或父页面 import 的子组件补 @Entry 并保留 export struct
- 读到：编译警告：export struct 带 @Entry；写错的样子：在「去 export → 导入失败 → 恢复 export」之间来回，最后 @Entry 与 export struct 同在；或用只有标题和 // TODO 的 @Builder 顶替原页面
适用范围：页面入口装配和修编译时处理 @Entry、export 与 main_pages.json 登记的冲突
做法：
- 报 10905402 时先查该文件是否被 import 作子组件：是就从 main_pages.json 的 "src" 移除登记，不补 @Entry；确是路由页才补 @Entry，同时去掉 export、确认没有导入方
- 同一内容既要做 Tab 又要做独立路由页时，抽出 @Component export struct 供 Tab 用，另写一个不 export 的 @Entry 外壳引用它；不用 TODO 占位的 builder 代替原页面
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 在单个 UI 页面中，仅允许存在一个由 @Entry 装饰的自定义组件作为页面的入口：@Entry 只给路由页（出处：ts-universal-entry.md，@Entry）
- @Entry 页面带 export 时编译报警告；去掉 export 后仍被 import 的地方编译失败：@Entry + export 是页面 / 组件角色冲突的信号（出处：卡里修好并验证过）
未核实：卡里的修复出自 API 24（6.1.1），本机文档副本未标 API 版本
来源：1 张卡，1 个应用
