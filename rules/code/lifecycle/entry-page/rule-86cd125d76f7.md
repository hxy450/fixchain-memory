# 模板工程的入口页要覆盖为主界面时，交回前读回核对已不是 Hello World 模板

审的是：代码
触发（任一种）：
- 读到：目标工程 EntryAbility 的 onWindowStageCreate 里 windowStage.loadContent('pages/Index')，Index.ets 是 DevEco 模板（struct Index、@State message: string = 'Hello World'）；写错的样子：交回时入口页仍含 'Hello World' 和 RelativeContainer 或 Row/Column 模板结构，没有计划的根组件（如 Tabs 和 TabContent）
适用范围：鸿蒙工程由 DevEco 模板创建、迁移要把入口页覆盖成主界面时
做法：
- 覆盖入口页（loadContent 指向的 pages/Index）后立即读回：不再含 'Hello World' 与模板结构，且含计划的根组件（如 Tabs 及各 TabContent）
- 读回与预期不符时按「写入未执行」处理，当场重写并再次读回，再继续其他修复
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- loadContent(path: string, callback: AsyncCallback<void>): void：WindowStage 加载启动页，path 就是入口页（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，WindowStage.loadContent）
- 模板 Index.ets 是 struct Index、@State message: string = 'Hello World'，build 里只有一个 Text：模板的识别特征；根容器随 DevEco 版本不同（文档示例是 Row/Column，卡里是 RelativeContainer）（出处：start-with-ets-stage.md，构建第一个页面）
- 模板入口页可以编译通过，文件存在性检查也会显示通过：编译和存在性检查区分不了模板与已迁移页面（出处：卡里修好并验证过）
针对本应用要查的：
- 入口页是哪个文件：目标工程 entryability 下的 Ability 文件里 onWindowStageCreate 的 loadContent 参数，以及 resources/base/profile/main_pages.json；loadContent 的 path 对应 ets 下的页面文件，读回核对的就是它
