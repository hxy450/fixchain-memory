# 存档、计时这类非幂等方法只挂源端同一时机有的调用位，aboutToDisappear 里源端没有的删掉

审的是：代码
触发（任一种）：
- 读到：源端 save() 按 now − startingTime 累计时长或写统计，只在 onPause / onBackPressed / onSaveInstanceState / Up 调用，onDestroy 里没有；写错的样子：目标页面的 aboutToDisappear() { this.save…() } 和 .onHidden、onBackPressed 共用同一个存档方法，形成双挂或三挂
适用范围：目标页是 Navigation 下的 NavDestination、可能在隐藏后很久才被销毁（桌面图标重进清栈、popToIndex、replace）时的存档、计时、计数调用
做法：
- grep 页面里的 aboutToDisappear，逐个对照源 Activity 的 onDestroy：源端 onDestroy 不做的存档、计时、统计副作用删掉；这里只留幂等的停止或移交入口，用来收掉还在运行、没经 onHidden 处理的任务
- 给非幂等方法加调用位前，先在源码里找同一时机的调用，源端没有就不加；判断「多调一次无害」时，至少走一遍「页面已隐藏、很久以后才被销毁」的路径，不只看返回出栈时几个回调连续触发
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 删掉 aboutToDisappear 及其中的存档调用，存档只挂 onHidden、onBackPressed：修好后上机核对，后台时长不再计入（出处：卡里修好并验证过）
- aboutToDisappear?(): void：自定义组件即将销毁时回调，声明里写明不要在其中改状态变量（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CustomComponent.aboutToDisappear）
- onHidden(callback: Callback<VisibilityChangeReason>): NavDestinationAttribute：页面隐藏时回调，原因含应用退后台（APP_STATE）（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onHidden）
