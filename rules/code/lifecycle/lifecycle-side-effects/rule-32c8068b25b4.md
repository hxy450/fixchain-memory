# Activity 的 onPostCreate、onResume、onStop 各自落点，不塞进 onPageShow

审的是：代码
触发（任一种）：
- 读到：Activity 里 onPostCreate（启动后只跑一次，如引导页或更新日志分流）、onResume（每次回前台，如校验密码或 init）、onStop（注销 EventBus 等订阅）；写错的样子：onPostCreate 和 onResume 的逻辑一起写进 onPageShow()，每次显示都重跑；onStop 没有落点
适用范围：把入口 Activity 的生命周期回调映射到目标端页面时
做法：
- onPostCreate 的逻辑只在首次显示时跑一次（加只跑一次的标记），之后再更新页面状态；onResume 的逻辑每次回前台跑；onStop 的逻辑放在页面被全屏覆盖或应用进后台时
- 用页面类别、前后台和外部 Activity 覆盖合成出 onActivityResume / onActivityStop 两个时机，各接源端对应的逻辑
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onPostCreate 在 onStart 和 onRestoreInstanceState 之后、启动完成时调用：源端只在创建后跑一次（出处：android.app.Activity#onPostCreate）
- 首显先跑 onPostCreate 再更新状态，按页面类别、前后台、外部 Activity 合成 onActivityResume / onActivityStop 后与源端一致：修好后的写法（出处：卡里修好并验证过）
