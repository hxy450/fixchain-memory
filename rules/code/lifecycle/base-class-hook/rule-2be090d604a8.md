# 接到基类横切钩子义务时先在源布局 grep 守卫 id，不成立就不实现并登记差异

审的是：代码
触发（任一种）：
- 读到：派工写「某页承接基类淡入钩子」，源基类里是 findViewById(R.id.x) 判空后才执行；写错的样子：页面里加了 .opacity(...) + .onAppear / onShown 的淡入或其他基类横切副作用，而源子类布局里没有基类守卫的 id
适用范围：实现者接到「基类横切钩子」类义务、要在某个页面落地时
做法：
- 动手前在源子类布局（含 layout-land 等变体）grep 守卫 id；不成立就按源端不实现，在 source-notes 登记差异
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 按源 findViewById 语义删除全部淡入：修好的写法，返修后保留（出处：卡里修好并验证过）
针对本应用要查的：
- 源子类布局里有没有守卫 id：源工程 res/layout* 下该页 setContentView 引用的布局文件及其限定符变体；grep android:id="@+id/x"；都没有就不实现该副作用
