# 源端 SavedStateHandle 守卫而 AC 要求保存态优先时，实现草稿持久化，不登记为无等价残余

审的是：代码
触发（任一种）：
- 读到：源 ViewModel 每个表单字段由 if (!state.contains("…")) 守卫，只在 SavedStateHandle 没有该键时才取数据库值；写错的样子：目标端 aboutToAppear 加载时无条件把数据库值赋给表单字段
- 读到：规格 AC 写「SavedState 已有值则不被数据库值覆盖」，FWD-REF 契约写 only when not restored from saved state；写错的样子：source-notes 记「ArkTS 无等价物，残余」，替换 FWD-REF 时去掉了这个条件
适用范围：源端依赖 SavedStateHandle 一类平台状态恢复、而规格 AC 已要求它的可观察行为时
做法：
- 按实体 id 持久化表单草稿：加载时草稿里有的字段优先于数据库值，没有的才用数据库值回填；aboutToDisappear 里写入草稿；保存成功后清理草稿
- 替换 FWD-REF 时保留契约里写明的条件（only when not restored from saved state），不改成无条件赋值
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- aboutToDisappear?(): void：组件即将销毁时调用，在这里落草稿；声明提示不要在其中改状态变量（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CustomComponent.aboutToDisappear）
- 按 id 持久化草稿、加载时草稿优先、aboutToDisappear 落草稿、保存成功后清理后，AC 判为实现：改法的依据（出处：卡里修好并验证过）
针对本应用要查的：
- 哪些字段受保存态守卫、哪些无条件取数据库：源工程 ViewModel 的 init 里 SavedStateHandle 的 contains / get 调用；有 contains 守卫的字段进草稿并优先；无条件取数据库的字段（源端不守卫的）照旧从数据库取
