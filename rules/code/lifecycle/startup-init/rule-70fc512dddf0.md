# 源端加载页由 SDK 初始化驱动而目标初始化瞬时完成时，首次冷启动补足最短展示时长

审的是：代码
触发（任一种）：
- 读到：SplashActivity 继承外部 SDK 的启动 Activity，进度回调更新 ProgressBar，SDK 初始化结束才 startActivity 进 MainActivity；规格要求首次冷启动有可见加载页；写错的样子：目标端初始化 load 返回后立刻把进度置满并跳转，没有 setTimeout 之类的最短展示时长
适用范围：目标端启动页的初始化只读本地配置、几乎瞬时完成，而用户或规格要求首次启动有可见加载页时
做法：
- 首次冷启动、配置未就绪走真实初始化时，记下开始时间；初始化完成后不足最短展示时长就 setTimeout(剩余毫秒) 再置就绪、跳转；热启动和配置已就绪时不等待
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 修复者给首次 idle 且配置未就绪的真实初始化补足约 800ms 最短展示：800ms 是按用户截图选定的，不是源端常量；以规格或用户确认的值为准（出处：卡里修好并验证过）
