# 源端在 onCreate 链上直接调起一键登录 SDK 时，目标不借用先查自有协议勾选的按钮逻辑

审的是：代码
触发（任一种）：
- 读到：源端登录 Activity 在 onCreate → 初始化 → SDK 初始化回调末尾无条件调用一键登录，直接进入官方 SDK 的授权页流程；写错的样子：目标页在 onReady 或 aboutToAppear 里调用登录按钮的处理方法，该方法在协议未勾选（默认 false）时先弹应用自有的协议确认框
适用范围：复刻运营商一键登录（官方 SDK 授权页流程），页面同时有应用自有协议勾选与确认框时
做法：
- 按源端接收方的实际触发点映射：源端在哪个生命周期、哪个回调里调起 SDK，目标就在对应时机直接进入官方 SDK 流程
- 入页自动动作不调用会先检查应用自有协议勾选状态的按钮处理方法；按钮逻辑只挂在按钮的 onClick 上
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 借用按钮处理方法实现入页动作时，协议勾选默认 false，入页即弹应用自有协议框，而源端入页直接进 SDK 流程：两种映射在首屏上的差别（出处：卡里修好并验证过）
针对本应用要查的：
- 源端一键登录在什么时机调起 SDK：源工程登录 Activity 的 Java 或 Kotlin 文件，从 onCreate 顺着调用链找一键登录 SDK 的初始化回调和调起授权页的调用；记下调用所在的生命周期和回调、前面有没有协议勾选判断，目标端按同一时机、同样的前置条件写
