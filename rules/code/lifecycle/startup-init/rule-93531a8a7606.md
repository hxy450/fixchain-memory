# 快照依赖引擎首次写入而初始化是异步的，布局加「引擎已启动」门控并下一帧重试

审的是：代码
触发（任一种）：
- 读到：源端 View 构造器里先调开局初始化，onSizeChanged 才生成背景，所以背景取到的是首次开局后的状态；写错的样子：目标的开局初始化在偏好就绪后的异步冷启链里（Promise / await 之后），布局或取快照的函数没有判断引擎是否已启动，可能在首次开局之前取到初始值
适用范围：目标端快照取值依赖的状态由异步初始化首次写入时
做法：
- 布局函数开头判断引擎已启动（如核心数据已初始化非空），未启动就不取快照、安排下一帧重试；重试逻辑抽成单独函数
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 布局函数加「引擎已启动（数据非空）」门控，未启动就下一帧重试：修复后的写法（出处：卡里修好并验证过）
