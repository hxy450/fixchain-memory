# 基础模块暴露未调用就抛错的 static configure/init 时，在模块源码就地写 HANDOFF 标记

审的是：代码
触发（任一种）：
- 读到：流水线规则要求：要靠另一处调用点（如 EntryAbility.onCreate）才算完成的代码必须写 `// HANDOFF: owner=… what=… verify=grep:…`，散文交代会被放行；写错的样子：基础模块里 static configure(...) 未调用时取配置就 throw（如「configuration is missing」），源码没有 `// HANDOFF:` 标记，只在注释、handoff 文档或「Suggested P-ID」里写「由启动 owner 调用」
适用范围：基础设施（Base 层）实现阶段，模块对外暴露启动期必须调用的入口、自己又不能改启动入口文件时
做法：
- 在该模块源码就地写 `// HANDOFF: owner=EntryAbility.onCreate what=调用 <模块>.configure 注入运行期值 verify=grep:<模块>.configure(`，不只写在 handoff 文档、注释或建议 P-ID 里
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 写了 `// HANDOFF: … verify=grep:…` 的跨文件义务被终态结构闭环扫到并派修复补上；只写散文和建议 P-ID 的不在修复清单里，启动入口始终没调用：源码标记是后续机械对账的唯一来源（出处：卡里修好并验证过）
来源：1 张卡，1 个应用
