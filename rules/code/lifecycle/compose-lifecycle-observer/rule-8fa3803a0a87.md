# 把 ON_RESUME 观察者迁进 ViewModel 刷新方法时，回调里的每个赋值都迁，含授权后隐藏插页

审的是：代码
触发（任一种）：
- 读到：Compose 界面的 Lifecycle.Event.ON_RESUME 观察者重查权限，权限新获得时把 remember 的插页显隐状态置 false（注释如 Permission was granted, dismiss permission screen）；写错的样子：ViewModel 的刷新方法只更新授权标志，由 NavDestination 的 onShown 或 onPageShow 调用，没有授权后把插页状态置 false；拒绝分支置 true 却已迁
适用范围：把 Compose 界面的局部状态和生命周期回调集中迁到 ViewModel，由页面显示回调调用刷新方法时
做法：
- 逐条列出源回调里的全部赋值（重查权限后更新授权标志、授权成功时隐藏插页等），逐项对应到目标刷新方法里，例如授权标志为 true 时同时把插页状态置 false，不只迁第一个状态更新
- 成对的 UI 状态核对打开和关闭两条路径都在，并写「授权后刷新 → 插页隐藏」的单测
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onShown(callback: Callback<VisibilityChangeReason>): NavDestinationAttribute：NavDestination 页面显示时的回调，承接 ON_RESUME 的重查（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onShown）
- onPageShow?(): void：每次页面显示（含回到前台）时调用，只对 @Entry 装饰的自定义组件生效：Router 页面承接 ON_RESUME 的回调（出处：鸿蒙 SDK 的 ets/component/common.d.ts，BaseCustomComponent.onPageShow）
- 刷新方法里加「授权标志为 true 时插页状态 = false」后，重新授权回来插页隐藏：修好的写法（出处：卡里修好并验证过）
未核实：卡里的行为出自鸿蒙 SDK API 22，本机核对用 API 23
