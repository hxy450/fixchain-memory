# 页面离开要销毁引擎时先调移交入口 onStop 再 dispose，onShown 时调 onResume

审的是：代码
触发（任一种）：
- 读到：引擎类公开 onStop()/onResume() 生命周期入口；源端 DisposableEffect(LocalLifecycleOwner.current) 里的 LifecycleEventObserver 在 ON_STOP 移交后台、ON_RESUME 取回；写错的样子：NavDestination 页的 aboutToDisappear 只调 engine.dispose()，没有 .onShown / .onHidden，engine.onStop() 在工程里没有调用方
适用范围：目标页面是 NavDestination、引擎是普通类、要由页面显式调用移交入口时；VisibilityChangeReason 出自声明 @since 21
做法：
- NavDestination 上接 .onHidden((reason: VisibilityChangeReason) => …)：APP_STATE 时调 engine.onStop()；TRANSITION 等离开路径要销毁引擎的，先 engine.onStop() 再 dispose
- .onShown(...) 时调 engine.onResume()；aboutToDisappear 里若销毁引擎，同样先调 onStop 再 dispose
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onHidden(callback: Callback<VisibilityChangeReason>): NavDestinationAttribute：隐藏后回调；在非栈顶页 push 进栈、栈顶页 pop 出栈或应用切到后台时执行（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onHidden；arkts-navigation-navdestination.md，页面生命周期）
- onShown(callback: Callback<VisibilityChangeReason>): NavDestinationAttribute：显示后回调，带显示原因（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onShown）
- VisibilityChangeReason.TRANSITION = 0、CONTENT_COVER = 1、APP_STATE = 2：隐藏、显示的原因：页面导航、bindContentCover、应用前后台（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，VisibilityChangeReason）
- aboutToDisappear?(): void：自定义组件析构前执行，不要在里面改状态变量（出处：鸿蒙 SDK 的 ets/component/common.d.ts，BaseCustomComponent.aboutToDisappear）
- onHidden(APP_STATE) 调 engine.onStop()；导航离开、宿主仍可见时先 engine.onStop() 再 dispose：修好后返回出栈、跳到其他页都会移交后台，计时不丢（出处：卡里修好并验证过）
未核实：卡里环境是 API 24（6.1.1），本机按 API 23 的声明核对
