# 找不到源码或契约说只传 ID 时，保留页面已声明的来源参数并按来源出动作，不整体删减

审的是：代码
触发（任一种）：
- 读到：源端打开结果页的静态 start(context, …, 来源常量, …) 带来源类型，结果页的 onClick 方法按来源分支进入编辑页；写错的样子：目标端 router.pushUrl / pushPathByName 的参数只剩媒体 ID；页面路由参数接口里声明的来源字段没人传也没人读；底栏没有按来源出现的「下一步」
- 写错的样子：交回里写找不到 Android 源码，随后按「只传 ID」契约把跳转调用的 `params` 从多个字段收窄为只剩 ID
适用范围：迁移结果页一类按启动来源分支的页面及其调用方时
做法：
- 调用方 push 时在参数里带上来源类型字段，取值对应源端传的来源常量
- 结果页读出来源字段，只在源端对应的来源（及源端的其他条件，如非视频）下显示「下一步」并进入编辑页
- 找不到源码时先查迁移配置里登记的 android 源根；仍找不到就保留已声明的来源字段并登记待核，不按「只传 ID」整体删减
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- params?: Object：router 跳转时传给目标页的数据，来源字段放这里（用 router 的工程）（出处：鸿蒙 SDK 的 ets/api/@ohos.router.d.ts，RouterOptions.params）
- pushPathByName(name: string, param: unknown, animated?: boolean): void：Navigation 路由时的参数位置（用 Navigation 的工程）（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pushPathByName）
- 调用方补来源字段（拍照时取源端相机来源的常量值），结果页新增来源读取和仅该来源且非视频时的「下一步」按钮：改法的依据；只过了编译和静态路由审计（出处：卡里修好并验证过）
针对本应用要查的：
- 源端各来源常量的取值和结果页按来源出现的动作：源工程结果页 Activity 的伴生对象或常量定义、onClick* 方法；调用它的 start(...) 处；常量值原样写成目标端来源字段的取值，onClick* 的分支条件照搬到目标页按钮的显示条件
未核实：卡里的修法只过了编译和静态路由审计，没上机运行
