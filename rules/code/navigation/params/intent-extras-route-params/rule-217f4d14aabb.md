# 同一路由参数被分别当完整 JSON、ID、图片地址时，拆成三个字段或入口解析，不用 startsWith 屏蔽

审的是：代码
触发（任一种）：
- 读到：调用方把完整的业务 JSON 写进路由参数；页面内又把同一个参数当 ID 拼进请求路径，或直接传给 Image(...) 当图片地址；写错的样子：页面用 startsWith('{') / startsWith('[') 一类判断把 JSON 排除在预览之外，预览恒为占位；参数仍原样当 ID 去请求
适用范围：按截图补齐或改写页面时，启动参数在调用方和页面内部语义不一致的情形
做法：
- 按源端契约拆成三个字段：ID、业务 JSON、预览地址；或在页面入口 JSON.parse 这份 JSON，取出其中的 id 和预览字段，再分别用于请求和 Image
- 本任务无权改参数契约时，把冲突登记为结构化缺口，不用字符串前缀判断把它屏蔽成占位图
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 参数拆成 ID、业务 JSON、预览来源三个字段，先用 JSON 恢复预览、再按解析出的 ID 拉详情后，详情请求和预览都正常：修复后的落法（出处：卡里修好并验证过）
针对本应用要查的：
- 参数在各调用方里实际装的是什么：目标工程里所有跳到这个页面的地方（搜页面名或路由名，看写进参数的值），以及源端页面恢复会话的那段代码；列出每个调用方传的值的类型（ID、JSON、URL），和源端从哪里取 ID 和预览，对齐成一份参数契约
未核实：卡里环境的 target_sdk 是 26.0.0，本条没有落在具体声明上
