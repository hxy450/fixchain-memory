# 映射启动器打开页面时，核对构造器写入的默认 extras 与读取端默认值再选清栈或压栈

审的是：代码
触发（任一种）：
- 读到：源端用启动器类打开页面：构造器里就 putExtra 写入清栈标志（如 clear_back_stack=false），调用处只链式加了要打开的对象再 start()；写错的样子：目标把这类调用接成清栈切页（并持久化最后页）；或按目标侧清栈字段的默认值、注释选了分支，与源端构造器 `putExtra` 写入的值相反
适用范围：接线阶段把源端启动器（构造器预置 extras 的 Intent 封装）映射到目标壳路由时
做法：
- 查源启动器构造器写入的 extras 和接收端 getBooleanExtra 的默认值，按实际值选分支：清栈标志为 false 就接壳内压栈加载子页的入口
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getBooleanExtra(String name, boolean defaultValue)：返回之前 putExtra() 放入的值，没有才返回 defaultValue：构造器已写入的值优先于读取端默认值（出处：android.content.Intent#getBooleanExtra）
- 打开对象的调用改为壳的压栈加载入口：返修后的映射（出处：卡里修好并验证过）
针对本应用要查的：
- 启动器构造器写入的默认 extras：源工程里这个启动器类的构造器（putExtra 调用）和接收 Activity 里对应的 getBooleanExtra；读出构造器写入的值；没写入时才看读取端的默认值
