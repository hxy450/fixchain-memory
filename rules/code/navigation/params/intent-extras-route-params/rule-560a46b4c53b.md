# 调用方 putExtra 而接收方 Activity 从不读取的参数，目标页 onReady 里不新增入页动作

审的是：代码
触发（任一种）：
- 读到：调用方用 Intent.putExtra("…", true) 启动某个 Activity，但接收方 Activity 里没有用 getIntent().getBooleanExtra / getStringExtra / getExtras() 读这个键；写错的样子：目标页的参数类里新增了同名字段，并在 NavDestination 的 onReady 里读 pathInfo.param 的这个键，为 true 时调用登录、弹窗等入页动作
适用范围：把安卓 Activity 之间的 Intent 传参迁成 ArkUI Navigation 路由参数、给目标页补入参消费时
做法：
- 先在源端接收方（Activity/Fragment）里找这个键的 getXxxExtra 读取，确认它读不读、读到后做什么；目标页只复刻接收方实际有的行为
- 接收方从不读取的参数，目标端调用方可以照传（透传）或删掉，目标页不新增参数字段，onReady 里不为它写任何入页动作
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onReady(callback: import('../api/@ohos.base').Callback<NavDestinationContext>): NavDestinationAttribute：NavDestination 在创建子组件前回调，路由参数从回调参数的 pathInfo 读（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onReady）
- NavPathInfo.param?: unknown：push 时带进来的页面参数，NavDestinationContext.pathInfo 的类型是 NavPathInfo（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathInfo.param）
- public boolean getBooleanExtra(String name, boolean defaultValue)：接收方读 putExtra 放进来的布尔值的写法；源端接收方里搜不到这个键的 getXxxExtra，就是没有读取（出处：android.content.Intent#getBooleanExtra）
- 接收方不读该 extra 时，删掉目标页的参数接口和 onReady 里的消费后，带参入口与无参入口首屏一致、不再弹源端没有的协议框：修复后的观察（出处：卡里修好并验证过）
针对本应用要查的：
- 这个 extra 在源端接收方有没有被读取、读到后做什么：源工程里调用方 startActivity 的目标 Activity/Fragment 的 Java 或 Kotlin 文件，按 extra 的键名全文搜，并搜 getIntent()、intent.extras、arguments；只有调用方的 putExtra 而接收方搜不到读取的，就是死参数；有读取的，按读取处的分支写目标页的行为
