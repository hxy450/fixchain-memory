# 构建修复补建缺失的模型时按规格数据流和上游 DTO 建模，不按一个调用方的字段补最少实现

审的是：代码
触发（任一种）：
- 读到：规格数据流写着启动参数按已安装实例、用户组件、缓存 JSON 的顺序解析；上游 DTO 里已有预览地址和原始 JSON 两个字段；写错的样子：补建的启动参数模型只有调用方用到的几个 ID 字段，没有承接缓存 JSON 的位置；从详情转模板时丢掉预览地址和原始 JSON；open() 不解析就拿参数原样请求 /{id}
适用范围：构建修复阶段为悬空引用补建业务模型或 ViewModel 时
做法：
- 以规格数据流和上游 DTO 建模：启动参数模型保留业务 JSON 和预览地址，并提供按规格顺序解析出 ID 的方法；模板保留上游 DTO 的预览地址和原始 JSON 字段
- ViewModel 先按解析出的 ID 发请求，不把原始参数直接拼进路径
- 建模前先用 rg 查清全部调用方实际传入的值，不能只按一个调用方用到的字段补
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 启动参数模型加业务 JSON、预览地址和解析 ID 的方法，模板保留预览地址和原始 JSON，ViewModel 按解析出的 ID 请求后，详情页正常：修复后的落法（出处：卡里修好并验证过）
针对本应用要查的：
- 模型要承接哪些字段：规格里这个页面的数据流一节，上游 DTO 的类型定义，以及目标工程里所有调用方写进参数的值；把三处出现的字段取并集，按规格的解析顺序写出解析方法
