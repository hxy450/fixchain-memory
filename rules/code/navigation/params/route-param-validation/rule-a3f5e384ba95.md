# 路由参数缺 id 的默认值必须落在有效性判定的无效区间里

审的是：代码
触发（任一种）：
- 写错的样子：路由参数类里 id 的默认值是 0，有效性判定却只写 `id < 0`，不带 id 的参数对象以默认值通过校验
适用范围：目标页用带默认值的路由参数类接收 id，并按验收项对缺失或无效 id 进入错误态时
做法：
- 默认值和判定用同一个哨兵：默认值是 0 时判定写 `id <= 0`；非整数也判为无效（`Number.isInteger(id)` 为 false 时进错误态）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 0、负数、非整数的 id 都判为错误态：按此改后通过验收（出处：卡里修好并验证过）
