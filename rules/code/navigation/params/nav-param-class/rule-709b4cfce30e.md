# 路由层要构造或多页共用的路由参数类，放进不导入页面的叶子模块，路由层不导入页面

审的是：代码
触发（任一种）：
- 读到：规格或切片对接点写明页面依赖路由封装：页面的 NavPathStack 接收路由层定义的参数类型，页面经路由封装的 push(route, param) 导航和返回；写错的样子：路由封装或服务层文件里出现 `import { …Param } from '../pages/…'`，参数类定义在页面 .ets 里并 export
- 写错的样子：页面文件从另一个页面文件导入它的参数类（`import { …Param } from './…Page'`），两个页面互相 import
适用范围：ArkTS Navigation 迁移里，路由封装或服务层要构造某页面的参数类，或多个页面共用路由参数类（含参数基类）时
做法：
- 路由层要构造的、或多个页面共用的参数类（含参数基类）放进 routing/ 下一个不 import 任何页面的叶子模块；路由封装、服务层和各页面都从它导入，路由/服务模块不 import 页面模块
- 规格写明页面 → 路由封装的依赖时，即使当前快照还没成环也按这个方向落位；判断成环要把计划里的页面 → 路由依赖算进去，「编译通过」「目前无环」「已有环无妨」都不能作放行理由
- 发现两个页面已经互导参数类时，先把参数类抽到叶子模块再接线
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 新建只含参数类和它用到的常量的 routing 叶子模块，路由封装和页面改从它导入：修好的写法：重建通过，启动不再报未初始化（出处：卡里修好并验证过）
- 模块按深度遍历执行：加载链路 A->B->A 时 B 先执行；B 若在全局或类静态里用到 A 的变量就报「… is not initialized」：环里谁先求值取决于入口先加载谁，只要有一处在求值期用到对方导出就会崩（出处：arkts-module-faq.md，Object is not initialized）
- 将公共依赖提取到独立模块：官方给的消除循环依赖的常见方法之一，即叶子模块（出处：arkts-module-faq.md，Object is not initialized 的解决措施）
