# pushPathByName 的参数用发送页自建的同形类时，改为 import 目标页导出的参数类

审的是：代码
触发（任一种）：
- 读到：目标页 NavDestination 的 onReady 里 context.pathInfo.param as Object 之后 instanceof 自己的参数类取参；写错的样子：发送页 pushPathByName / replacePathByName('页面名', new P(...)) 里的 P 是本文件 class P 定义的同形类，不是从目标页所在文件（或共享模型）import 进来的
适用范围：ArkTS Navigation 跨页跳转，接收页在 onReady 里用 instanceof 判定路由参数类时
做法：
- 发送页删掉本地同形类，从目标页文件（或共享模型）import 它导出的参数类，再写 pushPathByName('页面名', new 导入的类(...))；new 的类和目标页 instanceof 的类必须是同一个导出符号，字段名一致
- 对每个 pushPathByName / replacePathByName('X', param) 追 param 的构造类来源：不是从页面 X 所在文件或共享模型 import 的，就算断链
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 发送方 new 的是同形本地类时，目标页 onReady 的 instanceof 恒为 false，落入加载失败分支；改为 import 目标页导出的类后取参成功：类身份不同就判不中，同形不够（出处：卡里修好并验证过）
- pushPathByName(name: string, param: unknown, animated?: boolean): void：NavPathStack 按路由名入栈，param 原样带到目标页（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pushPathByName）
- NavDestinationContext.pathInfo: NavPathInfo；NavPathInfo.param?: unknown：目标页在 onReady 回调里从 context.pathInfo.param 取到入栈时的参数，类型是 unknown，要自己判定（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationContext.pathInfo；ets/component/navigation.d.ts，NavPathInfo.param）
- replacePathByName(name: string, param: Object, animated?: boolean): void：同族接口：NavPathStack 按名替换栈顶，参数同样要用目标页导出的类（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.replacePathByName）
- pushDestinationByName(name: string, param: Object, animated?: boolean): Promise<void>：同族接口：NavPathStack 按名入栈并返回 Promise（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pushDestinationByName）
未核实：卡里记的是鸿蒙 SDK API 24，本机核实用的是 API 23
