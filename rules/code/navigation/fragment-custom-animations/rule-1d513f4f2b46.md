# Fragment 换页带自定义动画时，目标 NavDestination 写 customTransition

审的是：代码
触发（任一种）：
- 读到：源码进入详情或覆盖页面时用 FragmentTransaction.setCustomAnimations(…) 配 res/anim 资源，或先用动画辅助方法缩放列表项再 replace fragment；写错的样子：目标只写 navPathStack.pushPathByName(...)，对应 NavDestination 上没有 .customTransition(...)，走 Navigation 默认滑入；缩放层也没有
适用范围：安卓 Fragment 换页带自定义动画、迁成 ArkUI Navigation/NavDestination 时；customTransition 自 API 15 起有（出自声明）
做法：
- 列出源端 setCustomAnimations 的 enter / exit / popEnter / popExit 四个资源各自的 alpha、scale 起止值、时长和插值器；源端先缩放列表项的，把这段缩放层按源实现一并迁过去
- 在进出的 NavDestination 上写 .customTransition((operation: NavigationOperation, isEnter: boolean) => [{ duration: <源时长>, curve: <对应曲线>, event: () => { <opacity/scale 改到终值> } }])：PUSH 时 isEnter 对 enter、否则对 exit；POP 时对 popEnter / popExit
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- customTransition(delegate: NavDestinationTransitionDelegate): NavDestinationAttribute：NavDestination 的自定义转场；和 systemTransition 都设时后设的生效（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.customTransition）
- type NavDestinationTransitionDelegate = (operation: NavigationOperation, isEnter: boolean) => Array<NavDestinationTransition> | undefined：按操作和进出方向返回一组转场（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationTransitionDelegate）
- NavDestinationTransition { event: Callback<void>; duration?: number（默认 1000 ms）; curve?: Curve（默认 Curve.EaseInOut）; delay?: number（默认 0）; onTransitionEnd?: Callback<void> }：每段转场的参数；源时长要显式写（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationTransition）
- NavigationOperation.PUSH = 1、POP = 2：区分进入和返回，分别对应源端 enter/exit 和 popEnter/popExit（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavigationOperation）
- setCustomAnimations(enter, exit, popEnter, popExit)：popEnter/popExit 只在弹回栈时播放；两参数版本弹栈时不播放：源端四个资源和目标 PUSH/POP × isEnter 的对应（出处：android.app.FragmentTransaction#setCustomAnimations）
针对本应用要查的：
- 源端换页动画的起止值、时长和插值器：源工程 res/anim 或 res/animator 下 setCustomAnimations 引用的 XML；缩放辅助方法里的 Animator 时长常量；<alpha>/<scale> 的 from/to 值作起止状态，android:duration 解析成毫秒，interpolator 对到 curve
未核实：卡里环境是 API 24，本机按 API 23 声明核实
