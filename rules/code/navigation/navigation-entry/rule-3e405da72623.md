# 启动页作为首个 NavDestination 压入空 Navigation 时，该页 onBackPressed 退后台

审的是：代码
触发（任一种）：
- 读到：源端启动页是 NavHost 的 startDestination，没有 BackHandler；写错的样子：空的 Navigation(this.navPathStack) {}，aboutToAppear 里 pushPathByName 启动页，它的 NavDestination 没有 .onBackPressed
- 读到：源端任务根 Activity 没覆写 onBackPressed（或抽屉关时 super.onBackPressed()）；写错的样子：可能成为栈底的 NavDestination 没有 .onBackPressed，或共享裁决函数在抽屉关闭分支直接 return false
- 写错的样子：退后台兜底写在承载 Navigation 的 @Entry 页 onBackPress() 里
适用范围：@Entry 页承载 Navigation，首页由首次 pushPathByName 成为栈底 NavDestination 时
做法：
- 每个可能成为栈底的 NavDestination（或它转调的共享裁决函数）写 .onBackPressed(() => { if (this.navPathStack.size() > 1) return false; context.moveAbilityToBackground(); return true; })
- 兜底不放 @Entry 的 onBackPress（栈内有页时它收不到返回）；或按标准入口模板把首页内容直接放进 Navigation 内容区，只有子页面是 NavDestination
- 列出会让栈只剩启动页的路径（冷启动首次 push、深链重建、清栈回列表），确认都落到这同一个处理
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onBackPressed(callback: () => boolean): NavDestinationAttribute：返回 true 表示自己处理；返回 false 表示回退到上一个页面（栈底时露出 Navigation 首页）（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onBackPressed；ts-basic-components-navdestination.md，onBackPressed）
- size(): number：路由栈深度，取值 [0, +∞)（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.size）
- moveAbilityToBackground(): Promise<void>：把当前 Ability 移到后台；只能在前台时调用（16000065）（出处：鸿蒙 SDK 的 ets/api/application/UIAbilityContext.d.ts，UIAbilityContext.moveAbilityToBackground）
- onBackPress?(): void | boolean：只对 @Entry 组件回调；Navigation 栈内有页时不会被调用（出处：鸿蒙 SDK 的 ets/component/common.d.ts，BaseCustomComponent.onBackPress）
- 从 Android 12（S）起，任务根且在清单里声明 ACTION_MAIN + CATEGORY_LAUNCHER 的 Activity 按返回时连同任务移到后台，不结束；其他 Activity 直接结束：源端栈底返回的默认行为及其条件（出处：android.app.Activity#onBackPressed）
- size() > 1 时不拦截，否则 moveAbilityToBackground() 并返回 true，接在启动页 NavDestination 上：按此改后复审确认不再露出空白首页，栈结构保持不变（出处：卡里修好并验证过）
- 栈深 ≤ 1 时 moveAbilityToBackground 并消费的公共函数，由共享裁决函数的抽屉关闭分支和栈底页 onBackPressed 调用：按此改后冷启各路径按返回都退到后台，最终保留（出处：卡里修好并验证过）
针对本应用要查的：
- 页面里拿到 UIAbilityContext 的写法：目标工程里已有的获取 UIAbilityContext 的封装（如入口 UIAbility 保存的 context）；沿用同一个获取方式调 moveAbilityToBackground
未核实：卡里上机的行为出自 HarmonyOS 6.1.1（API 24），本机声明按 API 23 核实
