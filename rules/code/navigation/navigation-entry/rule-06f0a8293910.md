# 启动页根是 NavDestination 时，入口空栈时 pushPathByName 压入，不放进 navBar 槽

审的是：代码
触发（任一种）：
- 读到：规格写「单 Navigation + 各 Activity 映射为 NavDestination」，启动 Activity 靠 onResume、onActivityResult 驱动；写错的样子：启动页写在 Navigation(...) { } 内容槽里、从未进栈，onShown / onResult / onBackPressed 落空
- 读到：启动页 build 根是 NavDestination()，已登记进 pageMap，或在 onReady(context) 里取 context.pathStack；写错的样子：入口写成 Navigation(this.navPathStack){ 启动页() }，启动页不在该栈里，也没有空栈时的 pushPathByName
适用范围：入口用 Navigation + navDestination(pageMap) 装配、启动页是 NavDestination 时
做法：
- 启动页只注册进 navDestination 映射，用同一个栈推入：入口 aboutToAppear() 里空栈（navPathStack.size() === 0）时 navPathStack.pushPathByName('启动页名', null)，或在 Navigation 的 .onAppear(() => …) 里推入；名字与 pageMap 一致
- Navigation(pathStack) 内容槽留空加 .hideNavBar(true)，或只放空容器（如 Stack()），由 pageMap 渲染启动页
- 装配后核对：写了 onShown / onResult / onBackPressed 的页面都经栈推入
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 放在 Navigation 首页内容槽里的 NavDestination 页面不在 NavPathStack 里，它的 onShown / onResult 不触发，子页返回的结果丢失；改成 aboutToAppear 里 pushPathByName 推栈、Navigation 留空并 hideNavBar 后恢复：内容槽和推栈两种写法的生命周期差别（出处：卡里修好并验证过）
- 空栈时 pushPathByName(启动页, null)、Navigation 内容改为空后启动页可见：修复后保留的写法（修前 navBar 槽被隐藏、栈为空，首屏白屏）（出处：卡里修好并验证过）
- 首屏写成根内容时设备日志出现 current stack is not navPathStack；改为空 Stack + onAppear 推入后正常：写错时的现象和另一种修好的写法（出处：卡里修好并验证过）
- pushPathByName(name: string, param: unknown, animated?: boolean): void：NavPathStack 按 pageMap 里的路由名把 NavDestination 压栈；param 可传 null，animated 默认 true（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pushPathByName）
- size(): number，取值 [0, +∞)：栈深度，0 表示空栈（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.size）
- hideNavBar(value: boolean): NavigationAttribute：隐藏 NavBar（标题栏、Navigation 的子内容和工具栏），直接显示栈顶页，栈空时显示空白；默认 false（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavigationAttribute.hideNavBar）
- onResult(callback: Optional<Callback<ESObject>>): NavDestinationAttribute：别的 NavDestination pop 或侧滑返回到本页时触发（@since 15）（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onResult；arkts-navigation-navdestination.md，页面生命周期）
- onReady(callback: Callback<NavDestinationContext>): NavDestinationAttribute：NavDestination 就绪回调，context.pathStack 是它所在的栈（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onReady）
