# 源端起点会在会话内变时，目标起点做成可重算，变了就 clear 后以新起点重压

审的是：代码
触发（任一种）：
- 读到：源端 NavHost(startDestination = 读偏好或状态的函数) 写在会重组的壳层内容 lambda 里，没有 remember；写错的样子：目标只在 NavPathStack 为空时 pushPathByName 首屏一次、另加布尔守卫，顶级导航器构造时固定首压时的起点名，navigateToTopLevel 只以这个固定起点为 popToName 基准
适用范围：单个 Navigation + NavPathStack 承载导航壳，源端起点读的状态在会话内会变时
做法：
- 起点写成可重算的值，在源端重组的等价时机重算；值变了就 navPathStack.clear(false)，再 pushPathByName(新起点, …)，并以新起点重建顶级切换的基准
- 起点没变（非首跑会话）时什么都不做，不清栈
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- clear(animated?: boolean): void：NavPathStack 清空整个栈，animated 默认 true，传 false 不做转场（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.clear）
- pushPathByName(name: string, param: unknown, animated?: boolean): void：按名字把新起点压栈（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pushPathByName）
- popToName(name: string, animated?: boolean): number：回退到指定名字的页，栈里没有时返回 -1（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.popToName）
- declare const Monitor: MonitorDecorator：@Monitor 方法装饰器，用来在状态变化时回调（出处：鸿蒙 SDK 的 ets/component/common.d.ts，Monitor；arkts-new-monitor.md，概述）
- 重算起点，变化时 clear(false) 后以新起点压栈：修好后的写法和行为（出处：卡里修好并验证过）
针对本应用要查的：
- 源端哪些时机会让壳层重组、从而重算起点：源工程里包着 NavHost 的壳层 Composable（抽屉、Rail、常驻抽屉的内容 lambda）及它读的状态；把这些状态变化（抽屉开合、配置变化、订阅的状态）对应成目标里的 @Monitor 回调或导航入口，在那里重算起点
未核实：navigation-compose 里起点变化即换图清栈的实现没有在源码里核对
