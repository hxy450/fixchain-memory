# Activity 开头无条件跳走并 finish() 的按跳板转，鸿蒙页进入即替换到实际目标

审的是：代码
触发（任一种）：
- 读到：Activity 的 onCreate 或 initView 开头不经用户操作就 startActivity(Intent(...)) 到别的页并紧接 finish()（可按条件分几支，每支都跳走），它的布局 XML 里仍有按钮等可渲染控件；写错的样子：对应的鸿蒙页照布局渲染成可停留的页面，跳转放进按钮的 onClick 里才调用 replacePathByName / pushPathByName
适用范围：页面转换阶段把入口或路由用的 Activity 迁成 Navigation 下的鸿蒙页（NavDestination）时
做法：
- 不按布局渲染可见页：鸿蒙页一进入就按源码同样的条件（每个分支对应一个目标页）调用 NavPathStack.replacePathByName('<实际目标页名>', param)，用目标页替换自己，不等用户点击
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- replacePathByName(name: string, param: Object, animated?: boolean): void：NavPathStack 的方法：用指定名字的页替换栈顶当前页，当前页被销毁；animated 默认 true（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.replacePathByName）
- 在 onCreate 里调用 finish() 时，onCreate 之后直接 onDestroy，onStart、onResume 都不执行：源端这个 Activity 的布局从不显示，用户直接看到跳转的目标页（出处：android.app.Activity#onCreate 的说明）
未核实：卡里的修复只改了调用方的路由、保留了中间页，进入即 replacePathByName 的写法卡里没有上机验证
