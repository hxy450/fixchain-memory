# 共享组件里的锚定面板要配点外关闭层时，组件用 OverlayManager 把遮罩加面板整层挂到窗口级

审的是：代码
触发（任一种）：
- 读到：源端溢出菜单是 ActionBar 的 PopupWindow（浮在窗口最上层，点外部只关闭菜单）；页内原写法是全幅透明捕获层后接面板，注释写「面板 z 序居上」；写错的样子：共享标题栏把面板画在自身节点里（根 Stack 子节点或 .overlay()），组件契约写「外点捕获层由宿主兑现」，宿主在标题栏之后的兄弟 Stack 里放全幅捕获层，面板项点不中
适用范围：把页内锚定浮层（溢出菜单面板与点外关闭的全幅遮罩）搬进共享标题栏等组件时
做法：
- 遮罩和面板放在同一个承载层，面板后声明、层级在上；面板在组件里画而遮罩要盖住页面时，整层由组件经 this.getUIContext().getOverlayManager() 挂到窗口级
- 整层写成全局 @Builder：全窗口透明层在 TouchType.Down 时关闭，加右上对齐的面板；args 里的回调先赋值再 new ComponentContent(uiContext, wrapBuilder(builder), args)；可见态变化时（@Monitor）addComponentContent / removeComponentContent，aboutToDisappear 里移除
- 不把遮罩留给宿主做后声明的兄弟节点；确需宿主参与的（如返回键先关面板），在组件契约里写明层级要求
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getOverlayManager(): OverlayManager：UIContext 上取窗口级浮层管理器（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.getOverlayManager）
- addComponentContent(content: ComponentContent, index?: number): void：新节点默认在页面居中；index 不传或小于 0 时加在最高层，所以整层要做成全窗口大小、面板自己对齐右上（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，OverlayManager.addComponentContent）
- removeComponentContent(content: ComponentContent): void：面板关闭和组件 aboutToDisappear 时移除节点（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，OverlayManager.removeComponentContent）
- constructor(uiContext: UIContext, builder: WrappedBuilder<[T]>, args: T)：ComponentContent 的构造，args 带回调和面板数据（出处：鸿蒙 SDK 的 ets/api/arkui/ComponentContent.d.ts，ComponentContent.constructor）
- 右子树（后声明的兄弟）显示在上方；HitTestMode.Default 的组件命中后阻塞兄弟组件：宿主后声明的全幅捕获层会在重叠区先命中，面板收不到点击（出处：arkts-interaction-basic-principles.md，事件响应链、干预命中）
- 改由 OverlayManager 承载全窗口透明层加右上面板后，面板项可点，菜单打开时点外部只关闭菜单：改法的依据（出处：卡里修好并验证过）
