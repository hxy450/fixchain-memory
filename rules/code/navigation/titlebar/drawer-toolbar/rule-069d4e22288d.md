# 源端基类 toggle 接管导航图标的页面，目标装进抽屉基座的汉堡栏，不自绘返回标题栏

审的是：代码
触发（任一种）：
- 读到：所继承基类的 onPostCreate 里 new ActionBarDrawerToggle(this, drawerLayout, toolbar, …) 并 toggle.syncState()，而规格或派工写的是「标题栏 + 返回箭头」；写错的样子：页面自绘标题栏，放返回箭头图标、点击 pop() 返回，没有接共享的抽屉基座组件；文件头注释写与抽屉基座的汉堡栏不可共存、按 setDisplayHomeAsUpEnabled(true) 保留自定义标题栏
适用范围：页面实现阶段，源 Activity 继承抽屉基类、目标端有共享的抽屉基座组件时
做法：
- 按源端生效形态把页面装进共享的抽屉基座（汉堡图标、点击开关抽屉、选中当前导航项），不画返回箭头；读到的源码与规格或派工冲突时照源码写，并登记这处差异
- 页面需要工具栏菜单或 AppBar 内 Tab 而基座没有位置时，给基座加可选槽位：用 @BuilderParam 成员并以空的 @Builder 本地初始化，页面按需传入工具栏动作和 AppBar 底部内容；不绕开基座丢掉抽屉
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- @BuilderParam 装饰指向 @Builder 方法的变量，初始化自定义组件时可用参数或尾随闭包传入；只能由 @Builder 方法初始化：给共享基座开可选槽位的写法（出处：arkts-builderparam.md，@BuilderParam装饰器：引用@Builder函数）
- 给抽屉基座加工具栏动作槽和 AppBar 底部槽后，页面改为装进基座的抽屉页，再按源端复刻溢出按钮和 Tab 行：修好后的写法（出处：卡里修好并验证过）
