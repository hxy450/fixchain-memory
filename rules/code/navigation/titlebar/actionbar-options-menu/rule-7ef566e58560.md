# 规格只给 Menu + MenuItem 而源端是平台主题弹出菜单时，逐项对照外观，对不上改页内浮层

审的是：代码
触发（任一种）：
- 读到：规格的溢出菜单只写 Menu + MenuItem；源 Activity 主题 parent=android:Theme.Holo，菜单项 android:showAsAction="never"；写错的样子：⋮ 按钮 .bindMenu(builder) 里 Menu + 若干 MenuItem，只改了 contentFontColor 和 backgroundColor（还借用对话框底色），没有面板边线和分隔线；返回键不先关菜单
适用范围：界面实现阶段，按规格落地平台主题绘制的溢出菜单时
做法：
- 先把源主题弹出样式与目标组件默认外观逐项对照（形状、分隔线、宽度、位置、模态）；只改底色和字色不算对齐，差异消不掉就回报规格或改用页内浮层
- 页内浮层：全屏遮罩 .hitTestBehavior(HitTestMode.Block)，onClick 只关闭；面板按契约自绘并配专用颜色资源，不借对话框底色
- 宿主的返回处理里先关这个浮层：@Entry 页 onBackPress() 浮层打开时关闭并 return true；在 NavDestination 里用 .onBackPressed(() => …)
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onBackPress?(): void | boolean：@Entry 页的返回回调，返回 true 表示自己处理（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CustomComponent.onBackPress）
- onBackPressed(callback: () => boolean): NavDestinationAttribute：NavDestination 的返回回调（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onBackPressed）
- hitTestBehavior(value: HitTestMode): T；HitTestMode.Block：遮罩吞掉触摸，不传到下层（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.hitTestBehavior；ets/component/enums.d.ts，HitTestMode.Block）
