# 定高标题栏加顶部 padding 时按 height 含 padding 算，inset 放外层或同步增高

审的是：代码
触发（任一种）：
- 读到：源标题栏或 ActionBar 是固定高度（如 48dp）的一行；写错的样子：同一行写 .height(48) 又加 .padding({ top: topInset })，以为高度不含 padding，可见高度被压成 48 − inset
适用范围：给固定高度的标题栏、ActionBar 一类行组件加顶部内距时
做法：
- 按 ArkUI 盒模型算：height 含 padding，可见内容高 = height − paddingTop；需要 inset 时放在外层容器的 padding 上，或把 height 同步加上 inset
- 源窗口非全屏时不需要 inset，标题栏直接 .height(<源高度>)
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 设置了固定的 width 和 height 时，组件内容的大小是 width、height 减去 padding 和 border：padding 吃在固定高度里面，不往外撑（出处：arkts-layout-development-overview.md，布局元素的组成）
- 标题栏定高 48、不再把 topInset 放进 48vp 行内后，可见高度恢复：inset 和行高分开放（出处：卡里修好并验证过）
