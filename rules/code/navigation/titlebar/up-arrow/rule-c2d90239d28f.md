# home 分支调 super.onBackPressed() 或 finish() 时，Up 单独实现，不并进返回键分支

审的是：代码
触发（任一种）：
- 读到：onMenuItemSelected / onOptionsItemSelected 的 android.R.id.home 分支调 super.onBackPressed()、finish() 或直接跳转，而子类覆写的 onBackPressed 里另有分支（如先回退内部步骤）；写错的样子：目标 Up 和系统返回共用一个处理函数（Up 也先走 onBackPressed 里的回退分支），注释写「home 与 onBackPressed 同分支」；或者用 NavDestination 系统标题栏的返回钮承接 Up
适用范围：源 Activity 用 setDisplayHomeAsUpEnabled(true) 并处理 android.R.id.home，迁成 NavDestination 页时
不适用的情形：home 分支调的是 this.onBackPressed()，两路本来是同一逻辑，目标让两者调同一个处理函数
做法：
- 逐字读两路的实际调用：home 分支调什么，onBackPressed 覆写做什么；调 super.onBackPressed()、finish() 或跳转的，两路分开
- Up 写在自绘或共享标题栏的返回点击里，照源调用执行（super.onBackPressed() 对应 this.navPathStack.pop()，不经内部回退）；系统返回写在 NavDestination 的 .onBackPressed(() => …) 里，保留覆写里的分支
- 两路要分开时不用 NavDestination 系统标题栏的返回钮：它固定触发 onBackPressed，分不开
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onBackPressed(callback: () => boolean): NavDestinationAttribute：点击返回键（含标题栏返回钮）时触发；返回 true 表示自己处理，false 表示回退到上一个页面（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onBackPressed；ts-basic-components-navdestination.md，onBackPressed10+）
- pop(animated?: boolean): NavPathInfo | undefined（animated 默认 true）：NavPathStack 弹出栈顶页，Up 直接用它（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pop）
- Up 改为直接 navPathStack.pop()、系统返回保留覆写里的回退分支后，两端验证 Up 回到上一页：分开实现后的行为（出处：卡里修好并验证过）
