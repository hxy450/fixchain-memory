# 读源码的回执被截断时，按函数名或行窗口重读被截部分再写组件，不用默认文本样式补空

审的是：代码
触发（任一种）：
- 读到：批量读多个 Kotlin 源文件的回执带 `Warning: truncated output`，要复刻的 @Composable 函数体落在被截掉的部分；写错的样子：目标组件的标题写成单个 Text 加默认的次要文字色、width('100%')，源端标题 Row 里的品牌色、maxLines、weight(1f) 和尾部 IconButton 都没有
适用范围：按规格指定的源文件复刻公共组件或页面片段、而读源码的工具输出被截断时
做法：
- 按规格指定的源文件逐个定位目标 composable；回执有 truncated 标记时，按函数名搜索或按行号窗口重读被截部分
- 核对标题 Row、颜色、尾部图标和间距（heightIn、padding）都读到了再写组件；读不到的不拿默认文本样式补空
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 标题写成 Row：Text 用品牌色、.maxLines(1)、.layoutWeight(1)，尾部 Image 用品牌色着色，带源端的高度和左右 padding：修好后的标题行，对应源端 Row + Text(weight(1f), maxLines = 1) + IconButton(tint)（出处：卡里修好并验证过）
- layoutWeight(value: number | string): T：按权重分父容器（Row、Column、Flex）主轴上的剩余空间，默认 0；对应 Compose 的 Modifier.weight(1f)（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.layoutWeight）
