# 契约写安卓点击启动独立 Activity 并带参数时，目标用 router.pushUrl 带等价参数跳转

审的是：代码
触发（任一种）：
- 读到：源端点击里 startActivity(intent) 并 putExtra 当前项和类型等参数，或规格写「入口 → 某 Activity，传 …」；写错的样子：目标端 onClick 里打开页内的简化面板，没有 router.pushUrl 到对应的共享页面，或跳转时没带源端那些参数
适用范围：安卓点击后启动独立页面（Activity）并携带参数，迁成 ArkUI 页面时
做法：
- onClick 里写 router.pushUrl({ url: '<对应共享页面的 pages/… 路径>', params: { <源端每个 putExtra 的键>: <对应值> } })，源端带的每个参数在 params 里都有一项，不用页内面板代替
- 入口跳转和目标页逻辑分开核对：目标页的选章分流修好，不等于源页入口已改成跳转
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- router.pushUrl({ url, params }) 跳到共享目录页并带当前章和类型，替换页内面板后行为与安卓一致：卡里的修法（出处：卡里修好并验证过）
- function pushUrl(options: RouterOptions): Promise<void>（@deprecated since 18，@useinstead ohos.arkui.UIContext.Router#pushUrl）：按页面 url 和参数跳转，新页压栈（出处：鸿蒙 SDK 的 ets/api/@ohos.router.d.ts，router.pushUrl）
- RouterOptions { url: string; params?: Object }：url 是目标页在页面列表里的路径（如 pages/detail/detail），params 是传给目标页的数据（出处：鸿蒙 SDK 的 ets/api/@ohos.router.d.ts，RouterOptions）
- function getParams(): Object：目标页读跳转带来的参数（出处：鸿蒙 SDK 的 ets/api/@ohos.router.d.ts，router.getParams）
针对本应用要查的：
- 源端启动的 Activity 对应目标端哪个页面、源端带了哪些参数：源工程里点击回调中构造 Intent 的那段（putExtra 的键）和规格里的跳转条目；目标工程的页面列表配置；每个 putExtra 的键对应 params 里的一项，目标页路径取页面列表里登记的 pages/… 路径
