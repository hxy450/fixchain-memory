# 源端工厂把相近类型映射到不同 Fragment 时，目标端各保留各的去向

审的是：代码
触发（任一种）：
- 读到：源端工厂（按类型字符串 when / switch 返回不同 Fragment）把几个相近类型分给不同 Fragment：一个点击进编辑页，另几个进选择页；写错的样子：目标端把这几个类型合并进同一个选择处理（同一个回调、同一个 pushPathByName 目标），原本进编辑页的类型也去了选择页
适用范围：把按类型分派 Fragment 的安卓工厂迁成 ArkTS 容器里的类型分派时
做法：
- 按源工厂逐类型保留去向：每个类型接到对应源 Fragment 的目标端页面或回调，不合并到同一个选图处理
- 接线后逐个类型对照源 Fragment 的点击目标（startActivity 的目标、回调去向）核对一次
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 编辑类型和选择类型合并到同一个选图处理后，编辑类型进不了编辑页；分开分派后恢复：验证过的接法（出处：卡里修好并验证过）
针对本应用要查的：
- 每个类型对应的源 Fragment 及其点击目标：源工程里按类型返回 Fragment 的工厂类（Kotlin 的 when 或 Java 的 switch），再到各 Fragment 的点击处理；逐类型记下返回的 Fragment 类，再看它点击后 startActivity 的目标或回调，目标端按这张表接线
