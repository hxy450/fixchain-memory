# 写 fail-loud 占位前逐项核对源端实现和目标端等价组件，两者都有就接线，不笼统报「契约未确认」

审的是：代码
触发（任一种）：
- 读到：源端这些动作（分享、附件、前序、添加后续、更多菜单）在共享的 DialogFragment 或公共分享弹层里已有实现；写错的样子：动作分发的兜底分支（`default` / else）统一弹「该操作所需契约尚未确认，暂不可用」之类的提示，把多个可见动作都落进去
适用范围：功能实现阶段决定尚未接通的动作如何处理时
做法：
- 逐个动作核对：源端是否已有实现、目标端是否已有等价组件；两者都有就接线复用
- 只有平台 SDK 凭据这类真实外部缺口才给明确的阻断提示，提示和交接里写明具体缺什么，不写笼统的「契约未确认」
