# 源端回退失败时走带 popUpTo 清栈的导航，目标 fallback 也先清栈，不用通用 push

审的是：代码
触发（任一种）：
- 读到：if (!navController.popBackStack()) XDestination.navigate(navController)，而该 navigate 带 popUpTo(navController.graph.id) { inclusive = true }；写错的样子：目标回退函数在 pop 失败后调用通用的 push(fallbackRoute, …)，没先清栈；同文件里已有先 clear 再 push 的方法却没用，单页栈回退后栈深为 2
适用范围：源端返回键在栈空时回退到图根页、且该导航带 popUpTo 图根 inclusive，迁成 ArkTS 路由时
做法：
- fallback 是图根页时，调用与源 destination 等价的清栈导航（先清空栈再压入该页，如已有的清栈 push 方法）；其它 fallback 走单例置顶的 push
- 自检：单页栈回退后栈深为 1、栈顶为图根页
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- fallback 为图根页时走清栈 push、其它走单例置顶 push 后，单页栈回退落到约定回退页：修法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端 fallback 实际调用的导航带什么选项：源工程 Compose Navigation 的 destination 定义里该 navigate 函数的 NavOptions（popUpTo、inclusive、launchSingleTop）；popUpTo 图根 inclusive → 目标先清栈再 push；launchSingleTop → 目标单例置顶
