# pushPathByName 前先看目标页 onReady instanceof 的类并 import，不自造同形类

触发（任一种）：
- 读到：目标页 NavDestination 的 onReady 用 param instanceof <某参数类> 收窄，或工程里已有统一的路由参数类模块；写错的样子：生产页在本文件里新建字段相同或相近的局部参数类，并 new 它传给 pushPathByName
- 写错的样子：为避免 import 成环，把已用的统一参数类换成本页局部的同形类，靠目标页 onReady 的形态桥接兜底
适用范围：页面转换或切片接线时，往 NavPathStack.pushPathByName 传类实例参数
做法：
- 写 pushPathByName 前打开目标页的 onReady（或统一的路由参数类模块），确认它 instanceof 的类，直接 import 该类并按它的字段赋值；不新建同形局部类，也不依赖目标页的形态桥接
- 担心 import 成环时，把参数类移到不 import 任何页面的独立模块再引用，不在生产页复制同形类
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- pushPathByName(name: string, param: unknown, animated?: boolean): void；另有 pushPathByName(name: string, param: Object, onPop: Callback<PopInfo>, animated?: boolean): void：参数类型是 unknown / Object，编译器不检查生产端和目标页用的是不是同一个类（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pushPathByName）
- ArkTS 不支持 structural typing（规则 arkts-no-structural-typing），编译器不比较两个类的 public API 是否相同：字段相同的两个类仍是两个类型，instanceof 只认目标页那个类（出处：typescript-to-arkts-migration-guide.md，不支持structural typing）
- 生产端统一改用目标页 onReady instanceof 的类后跳转恢复：修好的写法（出处：卡里修好并验证过）
- pushDestinationByName(name: string, param: Object, animated?: boolean): Promise<void>：同族接口：NavPathStack 的另一种按名入栈，参数同样要用目标页认的类（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pushDestinationByName）
- replacePathByName(name: string, param: Object, animated?: boolean): void：同族接口：NavPathStack 按名替换栈顶（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.replacePathByName）
