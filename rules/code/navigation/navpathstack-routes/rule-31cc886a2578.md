# 来源页 pushPathByName 带 onPop 时，子页成功出栈写 pop(result)，不写裸 pop()

审的是：代码
触发（任一种）：
- 读到：来源页用 pushPathByName(name, param, onPop) 打开子页，onPop 里按 instanceof 判 popInfo.result 的类型；写错的样子：子页成功分支写完共享回传通道后裸 this.navPathStack.pop()，或 pop(...) 出去的实例类型和 onPop 里 instanceof 判的类型不一致
- 读到：安卓子页经 savedStateHandle 写回结果后 navigateUp()，来源页回来后读取；写错的样子：目标子页只调 NavPathStack.pop()，不带 result
适用范围：鸿蒙 Navigation 里子页把结果交回来源页、来源页用 pushPathByName 的 onPop 接收时
做法：
- 子页每个成功出栈点写 this.navPathStack.pop(result)（回退多层用 popToName(name, result) / popToIndex(index, result)），result 用来源页 onPop 里 instanceof 判的那个类的实例
- 同时还写共享回传通道时也保留 result，不省成裸 pop()
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- pop(result: Object, animated?: boolean): NavPathInfo | undefined：NavPathStack 出栈并调用 onPop 回调交回结果（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pop）
- pushPathByName(name: string, param: Object, onPop: Callback<PopInfo>, animated?: boolean): void：来源页带 onPop 回调入栈（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pushPathByName）
- onPop 仅在 pop、popToName、popToIndex 设置了 result 参数后触发：裸 pop() 不触发 onPop（出处：ts-basic-components-navigation.md，pushPathByName11+）
- 裸 pop() 下 onPop 回调不执行，回传永远收不到；改成 pop(结果实例) 后来源页 onPop 收到并消费：上机看到的行为（出处：卡里修好并验证过）
- PopInfo.result: Object：onPop 回调里拿到的就是子页 pop(result) 传的对象（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，PopInfo.result）
- popToName(name: string, result: Object, animated?: boolean): number：同族接口：NavPathStack 回退到指定名字的页面并交回结果（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.popToName）
- popToIndex(index: number, result: Object, animated?: boolean): void：同族接口：NavPathStack 回退到指定下标的页面并交回结果（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.popToIndex）
- pushDestinationByName(name: string, param: Object, onPop: Callback<PopInfo>, animated?: boolean): Promise<void>：同族接口：NavPathStack 另一个带 onPop 的入栈方法，同样要子页 pop(result) 才触发（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pushDestinationByName）
