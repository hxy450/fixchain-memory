# 返回原页要做一次性动作时按挂载方式选回调，不依赖第二次 aboutToAppear

审的是：代码
触发（任一种）：
- 读到：子页修改共享模型后 pop 回原页；原页是 Navigation(this.navPathStack) { … } 的首页内容或 NavPathStack 里的 NavDestination；写错的样子：返回时的同步放在「第二次 aboutToAppear」分支里，或给 Navigation 首页内容挂 .onShown 刷新；pop 回来时这些都没执行，界面仍是旧值
适用范围：子页修改共享模型、pop 回仍保留着的原页时
做法：
- 先确认原页是 NavPathStack 里的 NavDestination 还是 Navigation 首页内容，再选在这种挂载方式下确实会触发的回调；不依赖第二次 aboutToAppear，pop 回来时组件不重建
- 能按模型状态渲染的（如「正在使用」提示按模型里的反馈字段渲染）直接绑定模型，不靠返回回调同步
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- aboutToAppear 在创建自定义组件的新实例后、build() 执行前调用：组件没有重建就不会再调用（出处：ts-custom-component-lifecycle.md，aboutToAppear）
- onShown(callback: Callback<VisibilityChangeReason>): NavDestinationAttribute：NavDestination 页显示时的回调，是 NavDestination 的属性，Navigation 首页内容上没有（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onShown）
- 原页作为 Navigation 首页内容时，返回后放在第二次 aboutToAppear 和 onShown 里的刷新都没生效；改为直接读模型后返回刷新正确：设备上观察到的行为（出处：卡里修好并验证过）
针对本应用要查的：
- 原页的挂载方式：目标工程里挂 Navigation 的页面，看原页是写在 Navigation(...) { } 里，还是作为 NavDestination 由 navDestination 构建器按名字创建；首页内容不走 NavDestination 生命周期；NavDestination 页可用它自己的显示回调
未核实：onShown 在 Navigation 首页内容上不生效的触发机制卡里没有单独验证
