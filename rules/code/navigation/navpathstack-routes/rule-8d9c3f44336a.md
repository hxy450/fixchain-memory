# 调用方传来动态目的地名时，改回固定名，navDestination 只按固定名精确匹配

审的是：代码
触发（任一种）：
- 读到：调用方 pushPathByName 的首参是模板字符串（如 `detail/${id}`）；写错的样子：navDestination 的 builder（pageMap）里用 name.startsWith('…/') 前缀分发；路由常量类里留着按 id 拼串的构造函数
适用范围：导航壳实现时为 Navigation 的 navDestination 写按名字分发的 builder
做法：
- 回头把调用方改成固定名加 param，pageMap 按固定名精确匹配（name === 常量 或 switch），不用 startsWith 前缀分发去迁就
- 路由常量类只留固定名常量，删掉按参数拼路由串的构造函数
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- navDestination(builder: (name: string, param: unknown) => void): NavigationAttribute：builder 拿到的 name 就是 pushPathByName 的首参，param 另传（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavigationAttribute.navDestination）
- 三处跳转改成固定名加 param、pageMap 按字面名匹配后，静态路由对账的可达页补齐：固定名精确匹配是核对过的写法（出处：卡里修好并验证过）
