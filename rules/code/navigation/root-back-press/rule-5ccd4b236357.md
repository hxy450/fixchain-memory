# 根页按 finish 返回时，先做 onDestroy 释放和复位，再 moveAbilityToBackground

审的是：代码
触发（任一种）：
- 读到：源根 Activity 没有覆写 onBackPressed，onDestroy 里有 release() / close()；写错的样子：NavDestination 的 onBackPressed 在栈深≤1 时只调 moveAbilityToBackground() 并 return true，onDestroy 的释放只挂在 aboutToDisappear 上
- 写错的样子：栈底返回调的是 terminateSelf()
适用范围：目标用 Navigation + NavDestination 承载、根页在栈深≤1 时接管返回，源根 Activity 返回是 finish 语义
不适用的情形：参照设备实测返回后是移到后台（再启动为 HOT、原实例恢复）时，省略复位
做法：
- onBackPressed 里栈深≤1 时：先执行源 onDestroy 的释放（如释放背景音乐），把页面实例态复位到初值，记一个待重建标记；再调 UIAbilityContext 的 moveAbilityToBackground()，return true
- NavDestination 的 onShown 里看到待重建标记，就重走源 onCreate 的初始化（新建音乐从头播放、刷新列表、恢复初始焦点）
- 不用 terminateSelf()：它会结束鸿蒙进程，静态单例里的局面（续局）丢失
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- moveAbilityToBackground(): Promise<void>：把当前 UIAbility 移到后台，进程保留（出处：鸿蒙 SDK 的 ets/api/application/UIAbilityContext.d.ts，UIAbilityContext.moveAbilityToBackground）
- terminateSelf(): Promise<void>：销毁当前 UIAbility；卡里实测会结束进程、续局丢失（出处：鸿蒙 SDK 的 ets/api/application/UIAbilityContext.d.ts，UIAbilityContext.terminateSelf）
- onBackPressed(callback: () => boolean): NavDestinationAttribute：NavDestination 接管返回，返回 true 表示已消费（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onBackPressed）
- onShown(callback: Callback<VisibilityChangeReason>): NavDestinationAttribute：NavDestination 显示时回调，放重建初始化（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onShown）
- 栈底返回先复位（释放菜单音乐、名字与等级复位、清焦点、记待重建）再 moveAbilityToBackground，下次 onShown 重建；terminateSelf 结束进程、续局丢失；aboutToDisappear 在退后台时不执行：卡里返修的修法和观察（出处：卡里修好并验证过）
针对本应用要查的：
- 源 onDestroy 释放了什么、哪些字段是实例态、onCreate 做了哪些初始化：源工程里根 Activity 的 onDestroy、onCreate 和成员字段；onDestroy 的每项释放进复位方法，onCreate 的初始化进重建方法，静态单例不动
未核实：onShown 的签名照本机 API 23 声明（@since 21 改成 Callback<VisibilityChangeReason>），卡里的目标 SDK 也是 API 23
