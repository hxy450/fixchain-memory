# 奖励门的能力不可用分支显式提示后继续导航，不伪造 REWARDED，也不和关闭、失败一起 return

审的是：代码
触发（任一种）：
- 读到：源端入口先调激励广告、只在 onReward 回调后导航；修复单要求能力不可用时阻断，而通用条款写「显式失败/禁止伪成功只约束失败路径语义，禁止把未配置实现成功能整片不可用」；写错的样子：入口 handler 里 UNAVAILABLE 和 DISMISSED、FAILED 一起进 if (!canContinue) { 提示; return }，广告 provider 未装配时入口点了只出提示、停在原页
- 写错的样子：把 UNAVAILABLE 静默并入放行结果（如统一归成 CONTINUE），不给任何提示
适用范围：目标端广告能力缺失或未装配、入口仍要求先看奖励广告的功能导航
做法：
- 结果为 UNAVAILABLE 时先显式提示广告不可用，再按目标继续导航；DISMISSED、FAILED 仍提示并 return；任何分支都不返回伪造的 REWARDED
- 修复单要求阻断而与通用条款、台账核心流程冲突时，照上一步实现，并在回执里标出与修复单的分歧
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- rewardOutcome 为 UNAVAILABLE 时提示不可用后继续按 target 导航，其余非授予结果仍提示并 return，不伪造 rewarded：修复后的分支，复验三单判 fixed（出处：卡里修好并验证过）
