# 功能规格写结果交给 Store、页面 spec 写成功后进结果页时，写完 Store 再 push 结果页

审的是：代码
触发（任一种）：
- 读到：源端保存成功后 startActivity 启动结果页并带来源类型；页面 spec 写「成功后进入结果页」，功能规格只写「结果交给 Store」「不新建重复路由栈」；写错的样子：导出成功回调里只把结果写进共享 Store，没有 HMRouterMgr.push 到已注册的结果页
适用范围：目标工程用 HMRouter 和共享结果 Store、源端操作成功后直接打开结果页时
做法：
- 两者合并实现：成功分支先把结果写进 Store，再用既有 HMRouter push 已注册的结果页，参数按约定只带稳定的媒体 ID 或路径，并带上源端的来源类型
- 「不新建重复路由栈」只是不另起一套路由，不等于不跳转
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 写 Store 之后 HMRouterMgr.push(结果页, { 媒体 ID, 路径, 来源类型, 是否视频 })：修好后的成功分支（出处：卡里修好并验证过）
针对本应用要查的：
- 结果页在 HMRouter 里注册的页面名和参数约定：目标工程里结果页的 @HMRouter 注解和页面常量定义，以及结果页功能规格里路由参数的约定；用注册的页面名 push，参数键照结果页读取参数的代码写
