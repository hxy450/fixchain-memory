# 替换 TODO / FWD-REF 占位接线时，按源端回调链落实成功和失败分支的每个动作

审的是：代码
触发（任一种）：
- 读到：源 Activity 的 initObserve 观察 ViewModel 的完成事件（`LiveData<Boolean>`），成功时写 SharedPreferences 标记、startActivity 跳主页并 finish()，失败时 Toast；目标头注释或 `TODO` 写着「成功后跳 X」；写错的样子：按钮 onClick 只写 this.vm.xxx()，没有 await 结果也没有 @Monitor，成功后不跳转、失败不提示；TODO 被删掉
- 读到：源 Activity / ViewModel 里成功回调跳主页并 finish()，失败或重复时 Toast，个别分支按源码特例处理；写错的样子：替换 FWD-REF 后成功只回填数据停留本页，失败或重复没有任何提示，特例分支被统一处理；同页已有的返回和参数处理也没复核
适用范围：接线阶段把占位按钮的点击或页面上的 FWD-REF 换成实际调用（含只更新状态、不跳转的 ViewModel 异步调用）时
做法：
- 替换占位前，在源端找到这次调用的结果观察者和回调链，把成功、失败（含重复）分支的动作逐条列出（写本地标记、跳主页或 pop、失败 Toast），特例分支照抄
- 让调用消费结果：ViewModel 方法返回 Promise<boolean>，页面写 const ok = await this.vm.xxx(); 成功分支逐条落实（如写标记后 pathStack.clear() 再 pushPathByName 主页），失败分支 toast；或用 @Monitor 监听状态做同样的分支
- 只接了调用、结果分支没处理完时保留 TODO，不算接线完成；同时复核同页已有的返回处理和参数接收是否符合源码
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- clear(animated?: boolean): void：清空导航栈，animated 默认 true（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.clear）
- pushPathByName(name: string, param: unknown, animated?: boolean): void：按名称把 NavDestination 压栈（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pushPathByName）
- VM 方法改为返回 Promise<boolean>；页面新增处理函数，成功后写引导完成标记、清栈并 push 主页，失败 toast：修好后的接法（出处：卡里修好并验证过）
- 定位成功后 pop、重复添加 Toast、特例分支按源码取子级：修好的回调去向（出处：卡里修好并验证过）
针对本应用要查的：
- 这次调用在源端的成功和失败动作：源工程里对应 Activity/Fragment 的 LiveData 观察代码（initObserve、observe 回调）和 ViewModel，按 ViewModel 的完成事件名或 finish(、startActivity(、Toast 搜；逐条记下写哪些本地标记、startActivity 去哪一页、是否 finish()、失败或重复时提示什么，作为接线后的核对清单
