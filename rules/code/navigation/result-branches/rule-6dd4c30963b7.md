# 源端回调把接口返回值交给通知时，页面不能只 await 不接返回值，要回填或提示

审的是：代码
触发（任一种）：
- 读到：源端接口成功回调把返回数据交给发 Notification 或 Toast 的调用（数据是给用户的验证码，不是可丢弃的发送回执）；写错的样子：页面里 `await` 一个返回 `Promise<string>` 的接口后直接开始倒计时或关弹窗，返回值没赋给任何变量，既没写进 @State 输入框状态，也没有 showToast
适用范围：鸿蒙页面调用返回非 void 的接口，而源端把这个返回值经通知、Toast 交给用户时
做法：
- 接住返回值：const code = await <接口>(...)；code 非空时写入输入框绑定的 @State 变量（this.<输入框状态> = code），再开始倒计时
- 规格写明用 Toast 承接时，写成 this.getUIContext().getPromptAction().showToast({ message: code })
- 准备丢弃某个非 void 返回值前，回查源端回调里这个值交给了谁
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 返回值非空时写入验证码输入框绑定的状态变量：回填承接，修好后用户不看日志也能拿到验证码（出处：卡里修好并验证过）
- getPromptAction(): PromptAction：从 UIContext 取 Toast 等提示能力的入口（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.getPromptAction）
- showToast(options: promptAction.ShowToastOptions): void：显示 Toast；options.message 是要显示的文字（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.showToast）
- message: string | Resource；duration?: number，默认 1500（ms），小于 1500 按 1500，最大 10000：ShowToastOptions 的显示文字和停留时长（出处：鸿蒙 SDK 的 ets/api/@ohos.promptAction.d.ts，promptAction.ShowToastOptions）
- function showToast(options: ShowToastOptions): void（@deprecated since 18，@useinstead ohos.arkui.UIContext.PromptAction#showToast）：同族接口：模块级 promptAction.showToast，已废弃，改用 UIContext 的 PromptAction（出处：鸿蒙 SDK 的 ets/api/@ohos.promptAction.d.ts，promptAction.showToast）
- openToast(options: promptAction.ShowToastOptions): Promise<number>：同族接口：PromptAction.openToast，返回 toast id 供 closeToast 用（@since 18）（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.openToast）
未核实：Toast 承接卡里没有上机验证，验证过的是回填输入框
