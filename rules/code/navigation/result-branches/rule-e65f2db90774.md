# 源端结果回调的失败分支有 showToast 时，目标失败处同样提示，不只导航或留页

审的是：代码
触发（任一种）：
- 读到：源 Activity 在 LiveData observe 回调的失败分支里 showToast(R.string.…)，再跳转、finish 或留在当前页（常带一句「失败留在当前页，用户可重试」的注释）；写错的样子：目标的 catch 或失败返回处只有 pushPath / push 跳转，或只有转写过来的留页注释，没有 showToast；ViewModel 的 catch 只 return false，失败被折叠成某个跳转目标
适用范围：迁移源页面异步结果回调（LiveData observe 等）的成功、失败分支，目标由 try/catch 或 ViewModel 返回值承接、页面决定导航时
做法：
- 按分支列出源端全部副作用（导航、toast 或弹窗、标记写入、finish），目标对应分支逐项写全
- 失败处调 this.getUIContext().getPromptAction().showToast({ message: $r('app.string.名称') })，文案取源字符串资源的值；ViewModel 吞掉异常时把失败结果返回页面层，由页面提示
- 转写了源注释的地方，核对注释后面的源语句都已落地；源页与目标页的 showToast 调用数量和所在分支逐一对上
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getPromptAction(): PromptAction：从 UIContext 取 PromptAction 对象（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.getPromptAction）
- showToast(options: promptAction.ShowToastOptions): void：显示 toast（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.showToast）
- ShowToastOptions.message: string | Resource；duration?: number 默认 1500（ms），小于 1500 按 1500，最大 10000：文案可直接传 $r 资源；时长单位毫秒（出处：鸿蒙 SDK 的 ets/api/@ohos.promptAction.d.ts，promptAction.ShowToastOptions）
- openToast(options: promptAction.ShowToastOptions): Promise<number>（@since 18）：同族接口：PromptAction 上返回 toast id 的版本，可配 closeToast（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.openToast）
- function showToast(options: ShowToastOptions): void（@deprecated since 18，useinstead UIContext.PromptAction#showToast）：同族接口：模块级 promptAction.showToast，已废弃（出处：鸿蒙 SDK 的 ets/api/@ohos.promptAction.d.ts，promptAction.showToast）
针对本应用要查的：
- toast 文案：源工程 res/values*/strings.xml 里 showToast 引用的那个 string，目标工程 resources/*/element/string.json 里同名或对应的资源；目标没有对应资源就按源值补上，再用 $r 引用
