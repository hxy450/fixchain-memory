# 源端用 OnBackPressedDispatcher 时，壳实现可登记的后进先出返回回调栈，宿主先分发

审的是：代码
触发（任一种）：
- 读到：源端 Activity 通过 onBackPressedDispatcher.addCallback 登记壳层回调，子组件（列表多选、菜单）另行登记 OnBackPressedCallback；写错的样子：壳的 NavDestination .onBackPressed(...) 写成封闭的固定分支（栈判断 → 默认页 → 开抽屉 → 退出），没有子页登记返回回调的入口；嵌入同一子页的其他 NavDestination 宿主也不分发
适用范围：壳实现阶段迁移安卓返回键分发、子页嵌在壳或其他 NavDestination 宿主里时
做法：
- 壳提供登记、注销、分发三个方法，按后登记先问的顺序分发，任一回调返回 true 就停
- 子页在 aboutToAppear 里登记回调、aboutToDisappear 里注销
- 宿主 NavDestination.onBackPressed(() => boolean) 在栈判断之后、执行壳层分支之前先分发；同一子页还嵌在预览等其他 NavDestination 时，这些宿主也接同一分发
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onBackPressed(callback: () => boolean): NavDestinationAttribute：NavDestination 的返回键回调（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onBackPressed）
- 返回 true 表示重写返回键逻辑，返回 false 表示回退到上一个页面：分发里有回调消费时宿主要返回 true（出处：ts-basic-components-navdestination.md，onBackPressed）
- aboutToAppear?(): void、aboutToDisappear?(): void：自定义组件的出现和即将消失回调，用来登记和注销（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CustomComponent.aboutToAppear / aboutToDisappear）
