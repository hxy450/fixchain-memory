# 源端有 OnBackPressedCallback 时，VM 提供单一返回决策方法，不用注释代替实现

审的是：代码
触发（任一种）：
- 读到：源端注册了几个 OnBackPressedCallback（handleOnBackPressed，按状态 setEnabled，如锁屏、暂停预览、popup）；规格验收条目写「锁定后按返回仅提示不离开」「按返回恢复预览」；写错的样子：VM 里没有返回决策方法，只写注释「由 Navigation back 拦截承载」；也没有 FWD-REF 或交接到宿主页的 onBackPressed
适用范围：把源端 OnBackPressedCallback 的返回链迁到目标端 VM 时
做法：
- VM 提供一个返回决策方法，按源端各回调的优先级逐个判断（如锁屏提示 → 恢复暂停预览 → 关 popup），返回 boolean 表示是否已消费
- 宿主页归别的切片时，登记 FWD-REF / 交接项，写明要接到宿主页的 .onBackPressed
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onBackPressed(callback: () => boolean): NavDestinationAttribute：宿主页调 VM 返回决策方法的入口，返回值直接作回调的返回值（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onBackPressed）
针对本应用要查的：
- 源端返回链的优先级：源工程 Activity 里 onBackPressedDispatcher.addCallback 的注册顺序和各回调 setEnabled 的时机；后注册、当前启用的回调先处理；按这个顺序写进 VM 的返回决策方法
未核实：源端返回链按注册顺序和启用状态分派出自 androidx.activity 库代码，本机没有源码，没能逐字核实
