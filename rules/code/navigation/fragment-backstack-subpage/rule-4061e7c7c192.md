# 调用点按源端 API 区分清栈切页与壳内压栈，不把压栈子页写成清栈切页

审的是：代码
触发（任一种）：
- 读到：源端调用点有的走清栈加载（替换内容区并保存最后页），有的走压栈加载（addToBackStack、不持久化），如区段「更多」、搜索、单集详情；写错的样子：压栈的调用点在目标写成清栈切页（并保存最后页 tag），或写成 pushPathByName 推出壳外
适用范围：接线阶段把源端各调用点映射到目标壳路由入口时
做法：
- 逐个调用点看源端调的是哪个加载方法：清栈的接壳路由的清栈入口（持久化最后页），压栈的接压栈加载子页入口（不持久化）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 「更多」和搜索调用点改为压栈加载子页入口后，返回回到原区段：返修后的调用点映射（出处：卡里修好并验证过）
