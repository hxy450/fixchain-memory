# 卡片式宿主里新增子页时，按源容器复刻卡片几何并用透明 DIALOG 路由

审的是：代码
触发（任一种）：
- 读到：子 Fragment 经 `replace(R.id.<容器>, fragment).addToBackStack(...)` 进入卡片式宿主里（`CardView` 包住的）同一个容器；写错的样子：新子页写成默认模式的 `NavDestination` 全屏 `Column`，只设安全区 padding 和不透明 `backgroundColor`，没有卡片几何，子页盖住整个屏幕
适用范围：宿主是透明卡片式页面、子页在宿主卡片容器内替换内容时（含修复阶段新增的子页路由）
做法：
- 子页 NavDestination 同样写 `.mode(NavDestinationMode.DIALOG).backgroundColor(Color.Transparent)`，内容包进与宿主同几何的卡片（外边距、圆角、背景色照宿主卡片）
- 遮罩和下层页面沿用宿主，不另建不透明全屏页；卡片外的点击关闭宿主
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 子页包进同几何卡片、改为 DIALOG 透明路由、卡片外点击关闭宿主后，子页留在预览卡片内：修好后的写法（出处：卡里修好并验证过）
- mode(value: NavDestinationMode): NavDestinationAttribute；DIALOG 模式页面默认透明：子页也要用透明路由（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.mode、NavDestinationMode.DIALOG）
针对本应用要查的：
- 宿主卡片的几何：源工程宿主 Activity 布局 XML 里包住 fragment 容器的 CardView：layout_margin*、cardCornerRadius、cardBackgroundColor；dp 数值照搬成 vp，颜色换成目标工程的颜色 token，子页卡片和宿主卡片用同一套
