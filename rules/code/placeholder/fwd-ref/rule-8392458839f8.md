# 源码调用工程内的取值辅助方法时，目标按它的源定义逐分支移植兜底链

审的是：代码
触发（任一种）：
- 读到：源码在显示文案或可见性判断里调用工程自己模型类或工具类的取值辅助方法，方法体是多级兜底，每级用 isNotBlank( 之类做空白判断；写错的样子：目标里对应的函数兜底顺序或字段和源定义不同、少了一级，或只判 `!== null` 而源端判的是空白；目标模型缺这个方法时在调用处内联了一个按方法名猜的简化表达式
- 读到：代码注释或派工里的 `FWD-REF` 写着要实现某个源方法；写错的样子：实现照 `FWD-REF` 里的方法名或自己的猜测写，源码里找不到这个方法，或实现缺了源方法里的前置条件和兜底分支
适用范围：移植安卓源码调用的工程内辅助方法（模型类、工具类里的取值和判断方法），目标端要自行实现等价函数时
做法：
- 打开被调用方法的源定义，逐分支照写：兜底的先后顺序、每一级取哪个字段、每一级是判空还是判空白，最后的缺省返回值也照写
- 目标模型缺这个方法时补成一个共享函数，显示文案、可见性判断、点击动作等各调用处都调它，不在各页面各写一份
- 实现 `FWD-REF` 引用的源方法前，先在源码里确认这个方法存在并读完定义；名字对不上源码的，以源码里真实的方法为准
针对本应用要查的：
- 被调用辅助方法的完整定义：源工程里该方法所在类的 Java/Kotlin 源文件，按「方法名(」找定义处而不是调用处；grep 只命中一行时读完整个方法体；列出每个 return 分支的条件和取值，按顺序写成目标函数的 if 链，空白判断和判空分开写
