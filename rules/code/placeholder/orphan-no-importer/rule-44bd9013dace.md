# 孤儿检测报无调用方的弹窗或页面已在规格和清单里登记时，保留文件、上报缺的触发点，不删

审的是：代码
触发（任一种）：
- 读到：孤儿检测对 dialogs/ 或 pages/ 下的组件报 `NO_IMPORTER`，而页面规格写了它的 ArkTS output、ui-manifest 记为 verified 或 feature-index 列为范围内页面；写错的样子：收口补丁 `Delete File` 删了这个 .ets（回执只写 Removed …），或给它补了源码里不存在的调用方（伪接线）
适用范围：生成末段结构收口时处理孤儿检测报出的无调用方页面、弹窗，决定接线、保留上报还是删除时
做法：
- 删 dialogs/pages 下的文件前先查 ui-manifest、页面规格的 ArkTS output 和 feature-index；已登记为范围内页面的产物不当废弃文件删
- 源端找不到真实调用方、台账又禁止实现会员、支付、权益逻辑时，保留规格允许的纯 UI 加宿主回调（onCancel / onConfirm / onDismiss）的实现，不跳转购买、无调用方时不主动弹出
- 缺的宿主触发点作为未决项或范围决策提案回传主线程，不伪造接线
