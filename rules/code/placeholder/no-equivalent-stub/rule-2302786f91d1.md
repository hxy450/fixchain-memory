# 源端消费的标志在目标端“无入口”时去源码找置位者，不写“契约位保留”收口

审的是：代码
触发（任一种）：
- 写错的样子：目标代码注释写 `恒false`、`契约位保留`、“本管线无入口”，源端在多处 if 里消费的那个标志在目标端从不置位，或写成 UI 观察不到的普通字段
适用范围：功能切片实现时，源端页面消费一个由基类或别处置位的标志、目标端暂时找不到置位入口
做法：
- 到源码里找这个标志的置位者（基类的菜单项、全选切换等）：找到就补上置位入口的实现；找不到就登记规格缺口，不静默收口
- 标志由 UI 置位并影响界面时，放在 @ObservedV2 类里用 @Trace 装饰，进入和退出多选时复位
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- declare const Trace: PropertyDecorator：@ObservedV2 类里属性的观测装饰器（出处：鸿蒙 SDK 的 ets/component/common.d.ts，Trace）
- 未被 @Trace 装饰的属性用在 UI 中无法感知变化，也不能触发刷新；@ObservedV2 与 @Trace 要配合使用：标志写成普通字段时，置位后界面不更新（出处：arkts-new-observedV2-and-trace.md，概述）
- 补上操作栏的全选入口置位该标志、字段改为 @Trace 后，确认条件、跨页循环和懒加载选中恢复源端行为：按此改后保留（出处：卡里修好并验证过）
针对本应用要查的：
- 标志的置位者：源工程里定义该标志的类（多半是页面继承的基类）里所有给它赋值的地方，以及触发这些赋值的菜单项或按钮；列出每个置位入口和条件，在目标端逐个实现
