# 规格 AC、状态接口和对接点要的行为

agent 会看到什么：读到规格的 AC、状态接口（'idle' | 'success' | 'error'）、端点和门控或对接点写明的行为，交回的代码少了它要的渲染分支、端点，或和已读源码冲突时把偏差写成契约、没回报

## 规矩

- rule-4988d4fbe1e8｜规格状态有 error 且验收要求失败报错时，build 里每个结果态都要有渲染分支｜读到：规格状态接口写 `'idle' | 'success' | 'error'`，验收标准要求失败时报错且不留成功状态；写错：状态枚举里定义了 Error，build() 里没有消费它的分支；catch 里写了 Error 状态，但没有任何地方显示失败提示
- rule-4ccdb86cb88b｜规格 AC 给出端点和门控且 service 归本切片时，先在 service 里建好端点｜读到：规格 AC 写明调用的 POST 端点和门控（成功后置单次标志、写全局配置、进程内只发一次）；写错：本切片拥有的 service 里只建了别的端点，没有 AC 里的这个 POST 端点和门控标志，调用随 P-S… 占位留给后续切片
- rule-6777b1a4875d｜对接点和已读源码的入口跳转冲突时，按源码接线并在回执里报冲突｜读到：规格的对接点把列表项点击接到详情页，已读的源码里该按钮的 `onItemChildClick` 却先调查询接口、再 `startActivity` 进另一个结果页（只有 `setOnBannerListener` 进详情页）；写错：替换 `FWD-REF` 占位时照规格在列表项按钮回调里用 `NavPathStack` 跳详情页；源码那条「查询 → 结果页」链路只接到别的页面，或没接
- rule-20172e2aae5f｜把页面逻辑下沉到服务层时逐条对照规格 AC 和源码，不把已有偏差写成服务契约注释｜读到：规格的 AC 写着「两侧齐备才渲染（缺任一为空操作）」这类说法，源码守卫没有 else；写错：新建的 Service 方法对 null 输入返回空结果，注释写「页面据此复位 UI 态」「等价 Android 无动作 + 清空渲染」这类和 AC 相悖的契约
- rule-21cbba034fb1｜AC 与已读源码语义冲突时按源码实现，并在迁移报告登记规格差异｜读到：规格 AC 要求只列缺失项，而已读源码用 items(<全部预置项>) 列出全部；写错：实现按 AC 用名称集合 filter 剔除已存在项，没有与源码对照，也没登记差异
- rule-3d1264a47ca8｜按排除决策落门槛时，只套在源端配置类里有该字段的类型上｜读到：决策台账里有排除某项能力的决定；源端只有部分类型的 Kotlin 配置类声明了对应的 Boolean 字段，其他类型的配置类没有；写错：代码把门槛写到一组类型上（[...].includes(item.type) && params.X 判为 unsupported / excluded），连源端配置类没有该字段的类型也被排除
- rule-7af727375f54｜规格写了多步交互的面板，要实现每一步的状态和切换，只改字数上限和文案不算对齐｜读到：规格或行为文档写面板是多步交互：先在底部对话框（Dialog）里编辑文字，再到内容图上拖动定位，最后确认或取消；写错：面板只改了 TextArea 的 maxLength、placeholder 或标题，仍是输入后直接发送的单步流程，没有定位层和确认、取消
- rule-96776e778559｜按规格新增弹窗或权限请求前核对源端分支可达，三态条件和源码非空类型冲突时照源端行为｜读到：规格要求「无权限且设置未初始化」时弹窗，服务契约的参数是 boolean | null；源端该变量由 collectAsState(initial = false) 收集、非空；写错：页面新增 @Local 状态 boolean | null，aboutToAppear 里读三态偏好后以 === null 为条件弹出对话框或请求权限，或新建只服务这一分支的协调服务
- rule-5723442df012｜在已有页面上对齐契约时，契约里的字号、字数上限逐项改到现有表达式上｜读到：目标端已有一版页面，规格或契约逐项写了控件字号（「16dp」）、输入上限（「N字以内」）和点击跳转到哪个 Activity；写错：同一控件上 .fontSize(…)、.maxLength(…) 仍是旧值，与契约不一致；只改了颜色，报告里写「既有回调保留」而没有逐项说明
- rule-d2605babec86｜规格 AC 逐条写明的分支，目标逐支照写，不降级、不改分支条件｜读到：源方法按偏好取值分多支（如 SharedPreferences.getString 读出的四个取值各自 setBackgroundColor 或只给标记上色），规格 AC 已逐条写了每个取值或每个分支的效果；写错：目标的 if/switch 只区分其中一两个取值，注释写「…降级为…」并登记占位；或 if 条件换成别的变量、丢了某支里的赋值
- rule-cad2a582b7bc｜规格 AC 写明的引擎调用要逐条落进 VM 方法体，不能只写偏好再重置｜读到：规格的 AC 写明界面动作要经引擎完成会话切换（「完成某引擎调用后恢复」「重置 → 引擎方法 → 图标刷新」）；写错：VM 的动作方法体只写偏好、再重置并翻转 UI 镜像状态，没有调用 AC 里写的引擎方法；方法上的注释写着「→ 引擎方法」，方法体里却找不到
- rule-2c4006455019｜自研等价清单组件逐条落实规格 AC：读偏好键传档位、拖拽排序、hint 为真实子项，不加源端没有的行为｜读到：源端 ChecklistManager 配置链 showCheckMarks / keepChecked / moveCheckedOnBottom / newEntryHint，勾选移动档位由偏好设置决定；规格 AC 写了偏好档位映射、拖拽排序、hint 为真实子项；写错：自研组件只有 Checkbox + TextInput 行和底部独立的 hint 草稿 TextInput，没有勾选移动档位和拖拽排序；页面不读该偏好键；或多了源端没有的行为（如转换后弹撤销条）
- rule-78aed39c706d｜规格的偏好键和源码会话 setter 冲突时，按源码登记 setter 缺口，不新建持久键代替｜读到：规格把某设置项列为偏好键，而源码里该项的 editor.putString 被注释、实际调用会话 setter；目标的偏好键表和应用接口里都没有对应项；写错：代码新建一个局部偏好键常量，切换时用偏好存储的 put(...) 持久化，注释「键语义权威见某规格」；会话状态没有被改，也没登记接口缺口
- rule-2a5ef11ddaf6｜验收条目列出几项触发守卫时，每项都写成代码分支，不只抄进注释｜写错：规格验收条目列了一组守卫（如弹窗打开、相机在后台、正在拍照或计时、正在录像时都不触发拍照），触发函数的注释照抄了全部守卫，`if` 分支只写了其中几项；同次新增的弹窗探测方法没被调用
- rule-69efd55b9023｜注释只凭源码行号论证先后时，读被引用的源组件核对触发时机，冲突写进 decision_gaps｜读到：上游契约注释要求「自增须挂在判定之后」，依据只有源码行号，被引用的判定其实在 Composable 的 LifecycleEventEffect 里；写错：新写的注释用源码行号论证先后（「源序 :N 判定先于 :M 自增」这类），沿用了上游次序却没写进 decision_gaps
- rule-f01345a124a1｜规格写的装饰与已读源码调用点矛盾时，按源码实现并回报规格勘误｜读到：源码调用点 Preference(title, icon, onClick) 没有 divider 和尾部图标，规格却写「Preference 自带分隔线」并决定加 chevron_right；写错：目标写成 List + .divider({ startMargin: … }) + chevron_right 图标，注释写「按 spec 决策」
