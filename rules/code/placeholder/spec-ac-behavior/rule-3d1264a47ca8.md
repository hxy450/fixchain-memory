# 按排除决策落门槛时，只套在源端配置类里有该字段的类型上

审的是：代码
触发（任一种）：
- 读到：决策台账里有排除某项能力的决定；源端只有部分类型的 Kotlin 配置类声明了对应的 Boolean 字段，其他类型的配置类没有；写错的样子：代码把门槛写到一组类型上（[...].includes(item.type) && params.X 判为 unsupported / excluded），连源端配置类没有该字段的类型也被排除
适用范围：按决策台账的排除项给一组编辑项或功能类型写不支持门槛时
做法：
- 逐类型看源端配置类：门槛只落在声明了该字段的类型上（只把这些类型列进 includes），没有该字段的类型保留原来的路由
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 门槛改成只作用于声明了该字段的选择类类型后，编辑类型保留编辑路由：验证过的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 哪些类型的配置带被排除能力的字段：源工程里各类型的配置类（Kotlin data class 或 Java bean），按类型逐个打开；看类里是否声明该字段；声明了的才列进门槛的类型列表
未核实：门槛误伤在真实配置数据里是否被触发过，卡里没核
