# 规格的偏好键和源码会话 setter 冲突时，按源码登记 setter 缺口，不新建持久键代替

审的是：代码
触发（任一种）：
- 读到：规格把某设置项列为偏好键，而源码里该项的 editor.putString 被注释、实际调用会话 setter；目标的偏好键表和应用接口里都没有对应项；写错的样子：代码新建一个局部偏好键常量，切换时用偏好存储的 put(...) 持久化，注释「键语义权威见某规格」；会话状态没有被改，也没登记接口缺口
适用范围：实现阶段发现规格的状态归类和已读源码冲突、目标端缺会话 setter 时
做法：
- 以源码执行路径为准：切换时调用目标端应用接口的会话 setter 写会话状态，并上报规格和源码的冲突
- 目标端还没有这个 setter 时，登记跨切片接口缺口（写明缺哪个接口上的哪个 setter），不新建持久键代替
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 删掉局部偏好键常量，改成把切换值交给应用接口的会话 setter，写进会话状态并在主页面接线：修好后的写法（出处：卡里修好并验证过）
