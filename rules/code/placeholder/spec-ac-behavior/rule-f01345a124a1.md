# 规格写的装饰与已读源码调用点矛盾时，按源码实现并回报规格勘误

审的是：代码
触发（任一种）：
- 读到：源码调用点 Preference(title, icon, onClick) 没有 divider 和尾部图标，规格却写「Preference 自带分隔线」并决定加 chevron_right；写错的样子：目标写成 List + .divider({ startMargin: … }) + chevron_right 图标，注释写「按 spec 决策」
适用范围：页面实现阶段，手里同时有规格和源码、两者对装饰或结构说法不一时
做法：
- 以源码调用点为准实现（如 Column + 行组件，无 divider、无 chevron），并在交回时回报规格勘误
来源：1 张卡，1 个应用
