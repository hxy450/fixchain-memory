# 在已有页面上对齐契约时，契约里的字号、字数上限逐项改到现有表达式上

审的是：代码
触发（任一种）：
- 读到：目标端已有一版页面，规格或契约逐项写了控件字号（「16dp」）、输入上限（「N字以内」）和点击跳转到哪个 Activity；写错的样子：同一控件上 .fontSize(…)、.maxLength(…) 仍是旧值，与契约不一致；只改了颜色，报告里写「既有回调保留」而没有逐项说明
适用范围：增量迁移时在已有目标页面上按安卓契约修改控件，契约给出了可核对的数值和跳转
做法：
- 把契约里每个可核对的数值和跳转对到现有表达式上逐项改：字号写成 .fontSize(<契约里的数值>)，输入上限写成 TextArea/TextInput 的 .maxLength(<契约里的字数>)；确要保留旧值的，在报告里逐项写理由
- 改完同一个 builder 后，用契约里的关键值（字号数值、跳转目标页、maxLength 数值、状态入参、替换图标资源）在代码里搜一遍，确认不只改了颜色
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- fontSize(value: number | string | Resource): TextAttribute：Text 的字号；传 number 时单位是 fp，默认 16fp（出处：鸿蒙 SDK 的 ets/component/text.d.ts，TextAttribute.fontSize）
- maxLength(value: number): TextAreaAttribute：TextArea 的最大字数；不写时没有上限，到上限后不能再输入（出处：鸿蒙 SDK 的 ets/component/text_area.d.ts，TextAreaAttribute.maxLength）
- maxLength(value: number): TextInputAttribute：同族接口：TextInput 的最大字数（出处：鸿蒙 SDK 的 ets/component/text_input.d.ts，TextInputAttribute.maxLength）
- maxLength(value: number): SearchAttribute：同族接口：Search 的最大字数（出处：鸿蒙 SDK 的 ets/component/search.d.ts，SearchAttribute.maxLength）
