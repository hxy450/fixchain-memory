# 带求交过滤的初始化分支写单测时，期望里的成员必须在 mock 的可用列表里

审的是：代码
触发（任一种）：
- 读到：源端或已读实现先合并再与可用列表求交，如 Kotlin 的 (基集 + 收藏).distinct().filter { it in 可用列表 }，或实现里的 合并结果.filter(...)；写错的样子：单测复制相邻用例的列表夹具，mock 的可用列表里没有期望值里的成员（如可用列表 mock 成 [a, b]、收藏 {c}，却写 expect(选中结果).deepEquals(['c'])）
适用范围：单元测试编写阶段，为带集合求交或过滤语义的初始化分支构造夹具和期望值时
做法：
- 对每个用例用刚读到的实现逐行推演期望值：先算合并结果，再与 mock 的可用列表求交，期望值就是求交后的结果
- 要预选的成员（如某模式下只选收藏）必须先放进 mock 的可用列表；设计标「已实现→GREEN」的用例写完后按最终夹具复算一次
