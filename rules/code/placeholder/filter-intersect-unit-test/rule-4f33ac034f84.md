# 单测 RED 与实现冲突且源端与实现一致时，按测试缺陷上报，不放宽产品过滤

审的是：代码
触发（任一种）：
- 读到：RED 断言期望的成员不在 mock 的可用列表里；源端对应函数是 .filter { it in 可用列表 } 这类求交，实现与之一致；写错的样子：产品代码把 合并结果.filter(...) 改成只对基集求交、收藏无条件并入，只为让这个测试变绿
适用范围：单测修复阶段、修复者不得改测试代码时，裁决 RED 属于测试缺陷还是产品缺陷
做法：
- 先读源端对应函数；源端与实现一致时，产品代码保持与源端相同的求交过滤
- 把这个用例按夹具冲突上报（`DISPOSITION_HINTS` 或 `manual_review`），写明期望成员不在 mock 列表里
针对本应用要查的：
- 源端这一分支的过滤语义：源工程 ViewModel 里初始化选择的那个函数（Kotlin 或 Java）；看合并后是否整体再与可用列表求交；是的话，不在列表里的收藏不预选
