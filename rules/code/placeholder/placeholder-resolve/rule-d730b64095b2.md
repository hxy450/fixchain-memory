# 为 FWD-REF 占位补调用时，按占位注释指向的目标符号接线，不自写简化副本

审的是：代码
触发（任一种）：
- 读到：代码里的 `FWD-REF` 占位注释写明了落地时要调用的目标符号，该符号在目标工程里已经存在；写错的样子：接线时没调这个符号，自写了副本函数（只复制文件、无扩展名补 '.bin'、沿用原件的 mime 建对象，name 为空、size 为 0）
适用范围：收尾接线阶段为 FWD-REF 占位补真实调用时
做法：
- 直接 await 调用占位注释指向的目标符号，参数按注释和源 helper 的调用传
- 目标符号确实不存在才自写；自写时对照源 helper 返回的对象逐字段核对 name、size、mime、扩展名来源
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 返修改为 await 调用占位注释指向的那个创建附件副本的函数，副本的 name、size、mime 与源端一致：返修后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源 helper 返回对象的各字段怎么来：源工程里被调 helper 的 Java 文件（如创建附件副本的那个方法）；逐字段看 name、size、mime、扩展名从哪里取，自写时一一照做
