# 占位触发写「持久化并触发立即切换」时，解析要同时接持久化和运行期消费方再删标记

审的是：代码
触发（任一种）：
- 读到：占位登记里某条 `P-S*` 占位的触发文本写着「持久化某开关并触发主题 / 进度样式立即切换」；写错的样子：代码里这个 `P-S*` 标记只被换成偏好仓库的写入调用（setter），没有主题应用点，也没有读这个偏好的渲染分支
适用范围：解析外观类设置开关的占位、把标记替换成实际接线时
做法：
- 按触发文本逐项完成：持久化调用之外，把运行期消费也接上（全局主题状态的写入与应用、计时器等页面的渲染分支），之后再删标记
- 给每个开关列出消费方并 grep 主题状态类和偏好的读取点：除默认值外没人读写，就算没解析完
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 修复后：主题状态改为 @ObservedV2 / @Trace 并在切换时 setColorMode，EntryAbility 启动与 onConfigurationUpdate 时应用主题，详情页按开关选进度渲染：两个开关各自的运行期消费方（出处：卡里修好并验证过）
针对本应用要查的：
- 每个开关在源端由谁实时读取：源工程里读这个偏好的 Kotlin / Compose 代码（主题 composable、进度组件）；每个读取点在目标端都要有对应的消费方，逐一列出再接线
