# 占位登记条目的兑现

agent 会看到什么：读到占位登记里 FWD-REF、P-S*、forward-ref 条目的触发文本和 resolve_by；产物里这个占位被换成了只做一半的实现：自拟的状态机、只写持久化、留 no-op、恒 return null

## 规矩

- rule-a99e8001f842｜代码替换 FWD-REF 桩时，逐条对上登记指向的切片计划和验收项｜读到：占位登记里的 `FWD-REF` 条目带 resolve_by，指向某个切片计划的某一步；功能计划里写着该切片的细则在哪个切片计划文件；写错：代码里 `FWD-REF` 桩已换成实现，但状态机是自拟的：初始态、完成态、对话框出现条件、派生量的重算与切片计划引用的 AC 不符或相反
- rule-0935cfbb1833｜占位触发写「持久化并触发立即切换」时，解析要同时接持久化和运行期消费方再删标记｜读到：占位登记里某条 `P-S*` 占位的触发文本写着「持久化某开关并触发主题 / 进度样式立即切换」；写错：代码里这个 `P-S*` 标记只被换成偏好仓库的写入调用（setter），没有主题应用点，也没有读这个偏好的渲染分支
- rule-60d02faf551f｜埋点门面的引擎列表为空时，按源端实现类移植自有服务端上报引擎并注册，不留 no-op｜读到：源端埋点门面持有引擎接口列表（SPI）广播事件，其中一个实现类是自有服务端上报（Retrofit 的 @POST 接口批量传日志）；占位登记或 FWD-REF 行点名了这个实现类，resolve_by 指向本 Slice；写错：目标门面只做转发，没有任何类实现引擎接口、也没有注册调用，文件头注释写「引擎列表为空期间各出口为安全 `no-op`」
- rule-d6379538f7d1｜华为账号登录通道用 AccountKit 实现真实授权调用链，可见性门绑定配置条件，不恒返 null｜读到：规格写着「Account Kit vs 占位，待裁决」，UI 规格写「可映射华为 Account Kit」，占位登记的 forward-ref 要求本切片建立鸿蒙等价入口；写错：华为账号登录方法恒 `return null`，注释写「账号体系形态未定」「SDK 未入仓」
- rule-184b13850ca2｜接线把 FWD-REF 换成实现时，标记和规格里的每个守卫条件都写进代码｜读到：FWD-REF 标记或规格写了守卫条件（某状态成功且账号非匿名已就绪才执行、只对失败态作废、加载中不动、按某字段小写排序）；写错：实现只判一个条件、`else` 分支（含加载中）一律执行；注释照抄了条件或写「已规约」「已在被调函数处理」，代码却没做；调用参数和标记不一致
- rule-d730b64095b2｜为 FWD-REF 占位补调用时，按占位注释指向的目标符号接线，不自写简化副本｜读到：代码里的 `FWD-REF` 占位注释写明了落地时要调用的目标符号，该符号在目标工程里已经存在；写错：接线时没调这个符号，自写了副本函数（只复制文件、无扩展名补 '.bin'、沿用原件的 mime 建对象，name 为空、size 为 0）
- rule-a243b2d49e00｜接线数据源的显示函数写成恒等函数时，按登记的源函数名找实现，找不到留 FWD-REF｜读到：占位登记的 FWD-REF 行写明数据源要注入的源函数名，派工信封列出提供实现的上游切片产物；写错：接线代码把显示文本函数写成恒等的 `(key: string): string => key`，没有缺口标记，登记行却标为 resolved
- rule-fe187d9360ef｜解除 FWD-REF 占位时不沿用本地取反，启停按真实监听状态，图标只由状态回调更新｜读到：FWD-REF 占位只对图标激活态做本地取反，占位注释或登记写明激活态应由启动/停止回调写入；写错：解除占位时保留取反（称「乐观更新」，`active = !active`），按取反后的图标态选启停；VM 门面没有启动/停止回调成员，页面没把状态转发给图标控制器，登记却标成 resolved
- rule-aa0594abad06｜解除 FWD-REF 时逐项兑现注释里的动画和共享元素，做不了的登记缺口｜读到：代码里待解除的 `FWD-REF` 注释写着要兑现的内容（如「含缩放动画与共享元素」）；写错：解除后只剩路由 pushPathByName(...)，注释里点名的动画、共享元素没有对应实现，也没有登记缺口，只留了注释或被删掉
