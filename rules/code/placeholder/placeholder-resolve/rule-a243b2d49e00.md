# 接线数据源的显示函数写成恒等函数时，按登记的源函数名找实现，找不到留 FWD-REF

审的是：代码
触发（任一种）：
- 读到：占位登记的 FWD-REF 行写明数据源要注入的源函数名，派工信封列出提供实现的上游切片产物；写错的样子：接线代码把显示文本函数写成恒等的 `(key: string): string => key`，没有缺口标记，登记行却标为 resolved
适用范围：跨切片接线、解除数据源 forward-ref 时
做法：
- 按登记行列出的源函数名，在所有上游产物里逐个找实现（不只查预想的那一个类），接上真实实现
- 找不到就保留 FWD-REF 或登记缺口，不写恒等函数，也不把登记行标 resolved
- 给显示文本适配器加一条断言：对内部键的输出不等于输入键
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 改为调用上游切片已有的真实描述实现后，弹层显示描述文本而不是内部键：修法（出处：卡里修好并验证过）
针对本应用要查的：
- 登记行里源函数在目标工程中的实现在哪：派工信封列出的所有上游切片产物（.ets 文件），按源函数名和它的目标改名逐个搜；找到带同样语义（含所需参数，如当前设备或上下文）的方法就接它；全都没有才登记缺口
