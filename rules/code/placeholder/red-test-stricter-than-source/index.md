# 比源端更严的 RED 测试契约

agent 会看到什么：读到问题文件把某个用例标 RED、要求的区分度或行为超出源端算法（如 dHash 逐行 right > left 取 64 位、没有亮度分量）；产物里产品代码加了源端没有的分量，或按别的用例期望反推实现，只为让用例转 GREEN

## 规矩

- rule-6ce018f1144b｜测试契约比源端更严时，不改产品算法迁就测试，写 BLOCKED / DISPOSITION_HINTS 说明源端行为｜读到：源端 dHash 逐行 `right > left` 取 64 位、没有亮度分量；问题文件标 RED P0 要求提升区分度；写错：产品哈希里把某个梯度位换成平均亮度位（`avg < 128` 置 1）等源端没有的分量，或按其他用例的期望反推取位方向，只为让区分用例转 GREEN
