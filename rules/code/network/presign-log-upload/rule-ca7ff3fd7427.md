# 诊断归档照安卓上传函数逐项对齐日志目录、设备信息和各表 TXT，不用快照或整库代替

审的是：代码
触发（任一种）：
- 读到：安卓上传函数先写设备信息 TXT，把 ObjectBox 的各个 Box 逐表导出成 TXT，flush 后把日志目录递归压进 ZIP；写错的样子：目标归档只放 BqLog 的 `take_snapshot()` 当日快照或一个诊断 JSON，或者用整库数据库文件代替分表 TXT，没有收集日志目录里的全部留存文件
适用范围：实现或修复诊断日志归档（打包后上传）时
做法：
- 按安卓上传函数列出归档清单逐项实现：递归收集日志目录下全部留存日志文件（不是内存里的当日快照）、设备信息文件、按安卓的分组逐表导出 TXT
- 整库备份可以另外保留，但不能代替分表 TXT；快照也不能代替日志目录里的持久日志文件
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 递归收集日志目录全部留存文件，按安卓分组生成各表 TXT，并保留整库备份：第二轮修复后的归档内容，覆盖了安卓上传的全部内容（出处：卡里修好并验证过）
针对本应用要查的：
- 安卓归档里的文件清单：源工程里日志上传函数调用的设备信息收集、逐表导出和压缩日志目录的那几个函数；数出写入 ZIP 的文件个数和分组（每张表一个 TXT、日志目录是否递归、保留几天），目标归档逐项对上
