# 源端链接 getter 在配置地址后拼渠道等参数时，目标按完整表达式构造 URL，不只抄配置地址

审的是：代码
触发（任一种）：
- 读到：配置读取类的 getter 返回 `return url + 渠道getter()` 这类拼接表达式；assets JSON 等配置里的地址 query 最后一个参数是空值、以 `=` 结尾；写错的样子：目标 Service 里把配置 address 原样写成 `const` / `static readonly` URL 常量，链接仍以 `=` 结尾，取链接的方法直接返回常量，没拼任何运行期参数
适用范围：把源端配置读取和协议、隐私、清单等链接 getter 迁成目标 Service 里的 URL 常量或构造方法时
做法：
- 按 getter 完整的返回表达式构造目标 URL：配置基础地址 + getter 追加的渠道等参数，不把配置里的 address 当成最终值
- 源端追加的运行期值映射到目标工程统一的渠道来源（渠道常量或构建配置），在 Service 里拼接，页面不硬编码；写完逐条对照源 getter，确认生成的 URL 不再以 `=` 结尾
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Service 里新增渠道常量，各协议链接改为「配置地址 + 渠道」后，WebView 打开的链接与安卓运行态一致：以空值结尾的 query 就是要在运行期补值（出处：卡里修好并验证过）
针对本应用要查的：
- 源端在 getter 里追加的运行期参数及其取值来源：源工程读取配置的类里返回链接的 getter，看 return 表达式在配置地址后追加了什么调用；找到追加值的来源（渠道、版本等），在目标工程里对应到统一的渠道常量或构建配置后拼接
