# 源 Repository 从响应头取 token 和 refreshToken 时，目标照源取值，不传空串

审的是：代码
触发（任一种）：
- 读到：源 Repository 成功回调里用 headers()["Authorization"] 等响应头写 accessToken 和 refreshToken，body 的 data 只存用户信息；写错的样子：目标的解析函数只从 resp.data 取 token，不读 response.header；保存凭证时 refreshToken 一参传空串 `''`；新补的登录方法直接复用已有解析函数
适用范围：实现登录、注册、找回密码等写凭证的 Repository 方法时
做法：
- 动笔前读源 Repository 每个登录方法的成功回调，分别记下 token 与 refreshToken 来自哪个头或 body 的哪个字段
- 目标从封装层返回的响应头里按同一头名取 token 和 refreshToken，结果对象带上 refreshToken，保存凭证时传它，不传 ''
- 补写新的登录方法时按该方法自己的源码取值，不直接复用已有的解析函数
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- token 改读 Authorization 头并保留 body 兜底，另解析 refreshToken，结果对象带 refreshToken，保存凭证时传它：修复后的取值方式（出处：卡里修好并验证过）
- HttpResponse.header: Object：目标端响应头从这里取（出处：鸿蒙 SDK 的 ets/api/@ohos.net.http.d.ts，http.HttpResponse.header）
针对本应用要查的：
- 每个登录方法的 token 与 refreshToken 来源：源工程登录相关 Repository 的 Kotlin 或 Java 文件，在各方法的成功回调里搜 headers() 和写进凭证管理类的赋值；读出头名和写入的字段，目标按同样的头名取值
未核实：响应头键名在目标端是否保留原大小写未核
