# 源端读 OkHttp response.message 时，目标用 rcp Response.reasonPhrase

审的是：代码
触发（任一种）：
- 读到：源端非 2xx 分支用 OkHttp 的 response.message（HTTP 原因短语）构造错误；写错的样子：目标非 2xx 分支传 'HTTP ' + response.statusCode 一类自造文案，没用 Response.reasonPhrase，也没在差异清单登记
适用范围：目标端用 @hms.collaboration.rcp 发请求、源端读取 HTTP 原因短语时
做法：
- 写一个取文案的函数：response.reasonPhrase 有值就用它，缺失时才回退 `HTTP ${response.statusCode}`；所有非 2xx 分支都用它
- 源码读平台响应属性时先打开目标 SDK 的类型声明确认有无对应字段；确实没有才自造文案，并在差异清单登记
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- readonly reasonPhrase?: string：rcp.Response 状态行里的原因短语，可选；@since 5.0.0(12)（出处：鸿蒙 SDK 的 hms/ets/api/@hms.collaboration.rcp.d.ts，rcp.Response.reasonPhrase）
- readonly statusCode: number：rcp.Response 的 HTTP 状态码，回退文案用（出处：鸿蒙 SDK 的 hms/ets/api/@hms.collaboration.rcp.d.ts，rcp.Response.statusCode）
- readonly reasonPhrase?: string（ResponseSendable）：同族接口：ResponseSendable 的原因短语，@since 6.0.0(20)（出处：鸿蒙 SDK 的 hms/ets/api/@hms.collaboration.rcp.d.ts，rcp.ResponseSendable.reasonPhrase）
- 优先 response.reasonPhrase、缺失时回退 HTTP <code>，替换全部非 2xx 分支：修好的写法（出处：卡里修好并验证过）
未核实：卡里环境标的鸿蒙 SDK 是 23 和 26.0.0，声明按本机 API 23 核实
