# requestInStream 的 Promise<number> 是 HTTP 响应码，按 2xx 判成功，不删校验

审的是：代码
触发（任一种）：
- 读到：原稿按 resp.responseCode 在 200–299 才返回字节，编译报 responseCode 不存在于 number；写错的样子：改成 await httpRequest.requestInStream(...) 后无条件返回拼合的字节，删掉了 2xx 判定
适用范围：用 @ohos.net.http 的 requestInStream 流式下载，或编译修复遇到它的返回类型不符时
做法：
- const code = await req.requestInStream(url, options)；code 在 200–299 才返回 dataReceive 拼合的字节，否则返回 null
- 编译修复遇到返回类型不符时先查声明确认返回值语义再改写判定，保留原有业务校验，不以删校验换编译通过
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- requestInStream(url: string, options?: HttpRequestOptions): Promise<number>：流式请求；结果在 dataReceive / dataEnd 事件里（出处：鸿蒙 SDK 的 ets/api/@ohos.net.http.d.ts，HttpRequest.requestInStream）
- 返回发起请求的结果，具体含义见 ResponseCode：resolve 的 number 是 HTTP 响应码，不是请求 id（出处：js-apis-http.md，requestInStream）
- ResponseCode.OK = 200：响应码枚举（出处：鸿蒙 SDK 的 ets/api/@ohos.net.http.d.ts，ResponseCode）
- resolve 值作为 HTTP 码，非 2xx 返回 null：修好的写法（出处：卡里修好并验证过）
