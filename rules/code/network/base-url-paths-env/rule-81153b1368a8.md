# 规格写新旧接口双轨并存时，先确认是否不同 host，是就让客户端持两个 baseUrl 按规则选

审的是：代码
触发（任一种）：
- 读到：规格写「双轨制并存（旧接口 + 新接口）」；源端取址分两个方法（旧接口、新接口各一个，按 BuildType 或环境工具选址）；写错的样子：HTTP 客户端只有一个静态 baseUrl 和 init(baseUrl)，注释写「同一套 client 承载，Service 各自声明 path 前缀」
适用范围：源端新旧两套后端接口并存、目标封装 HTTP 客户端时
做法：
- 先查两套接口的取址方法是不是返回不同 host；是就让客户端同时持 baseUrl 和 newBaseUrl，按源端规则（如请求 path 是否以新接口的前缀开头）选择
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 客户端持 baseUrl / newBaseUrl 两个地址，按 path 前缀选址：修好后新旧接口各打到自己的 host（出处：卡里修好并验证过）
针对本应用要查的：
- 新旧两套接口各自的 host 和选址规则：源工程里两个取址方法（常在依赖注入或网络模块里，各给一个 Retrofit 或客户端实例）和它们引用的地址常量；读出两个方法各返回哪个常量、在哪些接口上使用，归纳出按 path 前缀或接口分组的选址规则
