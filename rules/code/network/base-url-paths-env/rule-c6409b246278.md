# HTTP 封装的基址和接口路径逐字取自源端 BuildConfig 和 Retrofit 注解，不自拟

审的是：代码
触发（任一种）：
- 读到：源端网络模块里有 BuildConfig.BASE_URL（或构造 Retrofit 时的 baseUrl(...)），Service 接口方法上有 @POST("…") / @GET("…") 注解；写错的样子：目标封装的 BASE_URL 是源码里搜不到的域名（用应用名拼的占位域名），页面里 post('/…') 的路径和源端注解里的路径不一致
适用范围：把 Retrofit 网络层迁成目标端的 HTTP 请求封装和页面调用时
做法：
- BASE_URL 逐字取源端 BuildConfig.BASE_URL，连同它的上下文路径；每个接口路径逐字取对应 Service 方法 @POST / @GET 注解里的值
- 写完对账：搜目标 BASE_URL 与源端值一致，每个页面调用路径与源 Service 注解一一对上
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 修复后基址按源端 BuildConfig 的值（含上下文路径）写，登录注册路径按源 Service 注解改正，请求正常：卡里的修法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端基址：源工程网络模块的 Gradle 构建脚本里 buildConfigField 定义的 BASE_URL，或网络装配类里 Retrofit.Builder().baseUrl(...) 的实参；按构建变体取实际值，原样写进目标常量，保留末尾的上下文路径和斜杠
- 每个接口的路径：源工程网络模块里 Retrofit Service 接口，按方法名找 @POST / @GET 注解；注解括号里的字符串原样作路径，拼在基址后面
