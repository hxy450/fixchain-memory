# 决策要求构建期注入网络配置时，网络层在同一任务交付配置来源和响应解码器

审的是：代码
触发（任一种）：
- 读到：源端 gradle 里定义 API_HOST、签名材料和 AES_KEY，代码读 BuildConfig.API_HOST；决策台账要求签名/加密材料经构建 profile 或 gitignored 本地私有配置注入、由网络层集中读取；写错的样子：网络层只把 baseUrl、signSecret、解码器做成配置类的构造参数（解码器默认 null），没有任何配置读取，也没有解码器实现，回执写「通过 … 注入」把接线推给装配者
适用范围：网络基础设施实现阶段，决策要求配置在构建期从私有来源注入、由网络层集中读取时
做法：
- 同一任务内交付配置来源：构建期从环境变量或被 .gitignore 忽略的本地私有配置（如 local.properties）生成配置模块，缺键时构建失败
- 同时交付和源端等价的响应解码器，配置类默认就接上它，不留 null 给装配者
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 构建期从环境变量或 gitignored local.properties 生成私有配置模块，装配根以其中的地址、签名密钥和 AES 解码器构造配置后，真机登录恢复：修好后的配置来源（出处：卡里修好并验证过）
针对本应用要查的：
- 源端有哪些构建期注入的网络配置：源工程模块级 Gradle 构建脚本里的 buildConfigField 和 buildTypes 的 debug/release 分支，以及代码里对 BuildConfig 字段的引用；逐个列出字段名和它在 debug/release 下的取值来源，在目标端的配置模块里各给一个同名常量
