# 运行配置只从环境变量读、缺省写死时，改用 BuildProfile 构建期字段作缺省

审的是：代码
触发（任一种）：
- 读到：源端成功码、渠道、客户端 id、项目 id 来自 assets 下的配置 json、flavor 常量或 buildConfigField；写错的样子：目标代码里这些配置只从 `getEnvironmentVar` 读，读不到时落到源码里写死的缺省（空串密钥、与源端不同的渠道或 id），没有读 `BuildProfile` 字段
适用范围：设备进程环境不会带这些配置变量时，ArkTS 应用的运行配置读取
做法：
- 在模块 build-profile.json5 的 buildProfileFields 里按源端实际值定义各配置项，代码 import BuildProfile from 'BuildProfile' 后读 BuildProfile.<字段>，作为环境变量读不到时的缺省
- 密钥等秘密值不写进源码：buildProfileFields 里用 @param 引用，经 hvigor-config 的 parameterFile 指向本地不入库（gitignore）的参数文件
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- buildProfileFields 放 BASE_URL、SUCCESS_CODE、CHANNEL、CLIENT、PROJECT_ID 和 @param 引用的密钥；hvigor-config 的 parameterFile 引入本地 json5 参数文件：构建期注入后真机启动不依赖进程环境变量（出处：卡里修好并验证过）
针对本应用要查的：
- 源端各运行配置项的实际值（成功码、渠道、客户端 id、项目 id、服务地址）：源工程 assets 下的配置 json、定义缺省渠道和身份的常量类、app 模块 Gradle 构建脚本里 flavor 的 buildConfigField；按应用实际打包用的 flavor 取值；assets 配置文件和常量类给的值不同时，以运行时实际读取的那一处为准，填进 buildProfileFields
