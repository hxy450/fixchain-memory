# 源端有统一响应壳和鉴权拦截器时，目标封装带 Authorization 头并按成功码解包

审的是：代码
触发（任一种）：
- 读到：源端有统一响应包装类（code、message、data 字段）按成功码判定，OkHttp Interceptor 给请求加 Authorization 头；写错的样子：目标封装直接 JSON.parse(result) as T 返回，没有按成功码解包，header 里没有 Authorization，也没判 responseCode 是否 2xx
适用范围：目标端用 @ohos.net.http 写 HTTP 请求封装、源端有响应壳和鉴权拦截器时
做法：
- request(url, { method, header: { 'Authorization': 照源拦截器取的 token 写法 }, extraData }) 发请求
- 响应先判 responseCode 在 200–299，再解析 result 按源包装类解包：code 不等于源成功码时抛错并带 message，否则返回 data；空响应要处理
- 请求结束调用 httpRequest.destroy()
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- request(url: string, options?: HttpRequestOptions): Promise<HttpResponse>：发请求，鉴权头放在 options.header（出处：鸿蒙 SDK 的 ets/api/@ohos.net.http.d.ts，HttpRequest.request）
- header?: Object，默认 'content-type': 'application/json'：请求头；不写时带默认 content-type（出处：鸿蒙 SDK 的 ets/api/@ohos.net.http.d.ts，HttpRequestOptions.header）
- responseCode: ResponseCode | number；result: string | Object | ArrayBuffer：HTTP 状态码和响应体，先判状态码再解包（出处：鸿蒙 SDK 的 ets/api/@ohos.net.http.d.ts，HttpResponse.responseCode、HttpResponse.result）
- destroy(): void：销毁这次请求（出处：鸿蒙 SDK 的 ets/api/@ohos.net.http.d.ts，HttpRequest.destroy）
- 补上 Authorization、成功码不符时抛错、HTTP 非 2xx 判断和业务消息空值保护后保留：卡里的修法（出处：卡里修好并验证过）
针对本应用要查的：
- 源成功码和响应壳字段名：源工程网络模块里的响应包装类，以及调用方判定成功的那段代码；读出成功码的值和 code、message、data 的字段名，原样用在目标解包里
- 鉴权头的写法：源工程网络模块里的 OkHttp Interceptor 实现；读出头名、取 token 的来源和拼法（是否带前缀），目标照写
