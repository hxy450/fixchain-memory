# ResponseCache.set 的失败不要空 catch 吞掉，至少把错误信息记进日志

审的是：代码
触发（任一种）：
- 写错的样子：拦截器或缓存封装里 await cache.set(...) 外面是空的 catch {}，缓存写入失败没有任何日志
适用范围：目标端用 rcp.ResponseCache 手动写缓存（拦截器、强制缓存等）时
做法：
- catch (e) 里至少记录错误码和信息，例如 hilog.error(domain, tag, 'cache set failed: %{public}s', JSON.stringify(e))，能看出 item is too long for cache limits 这类容量错误
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- set(key: ResponseCacheKey, response: CachedResponse, expirationPolicy?: ExpirationPolicy): Promise<void>：加入或替换缓存记录；参数校验失败抛 1007900401，文件系统 IO 错误抛 1007900985（出处：鸿蒙 SDK 的 hms/ets/api/@hms.collaboration.rcp.d.ts，rcp.ResponseCache.set）
- 空 catch 吞掉 set 的错误，容量配置错误直到加日志后才看到 item is too long for cache limits：日志能区分容量配置问题和记录构造问题（出处：卡里修好并验证过）
未核实：卡里的运行时是 API 26，本机用 API 23 的声明核实
