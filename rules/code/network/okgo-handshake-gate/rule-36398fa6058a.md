# 源端请求重载没有取密钥前置门时，目标通道照源端只带头发送，不为与其他通道一致自加握手门

审的是：代码
触发（任一种）：
- 读到：源端某个请求重载只构造请求头后 OkGo.post(url).headers(headers).execute()，没有 body，也没有取会话密钥的前置步骤，由调用方先按特定基址握手；写错的样子：目标端新补的通道开头照搬既有 post 通道多写了一次会话密钥握手调用，源端 OkGo 重载并没有这一步
适用范围：网络通道实现或修复阶段，为新增或改写的请求通道决定是否内置会话密钥前置门时
做法：
- 逐项对照源端重载实际做了什么：请求头、body 形态、是否取密钥；源端无前置门、由调用方先握手的，目标通道也不设门，并在注释里写明「本通道不设门，由调用方先按正确基址握手」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 删掉通道内以默认基址取密钥的门后，在已切服的状态下列表全量加载：改法的依据：多出的门会用另一基址重新握手、覆写调用方刚取的密钥，响应解密失败后页面静默空白（出处：卡里修好并验证过）
针对本应用要查的：
- 源端这个重载实际做的事：源工程网络工具类里该重载的方法体，以及它调用的取请求头方法；列出请求头、有无 body、有无取密钥或基址检查三项，目标通道逐项对上
