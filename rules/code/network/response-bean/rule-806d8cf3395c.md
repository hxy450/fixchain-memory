# 响应字段的键链和类型照源端 Bean 的声明写，不按字段名猜

审的是：代码
触发（任一种）：
- 读到：源端 Retrofit 接口和 Repository 回调返回 BaseResponse<T> 或解包后的容器 Bean，字段在 Kotlin data class 或 Java Bean 里声明（如 val time: String、内层 data）；写错的样子：目标对 res.data 按键手写取值，或另写 BaseResponse 等类型，键链少一层、字段类型自选，和源端 Bean 不一致
适用范围：目标网络层、服务层或模型层手写响应的取值键链和字段类型时
做法：
- 先定目标 res.data 对应源端哪一层类型（通常是解包后的容器 Bean），从那一层起照 Bean 的字段链逐层写键，Bean 有内层 data 就多取一层
- 字段类型照 Bean 或规格里共享模型类型表的声明写；已有共享定义就 import 复用，不另写一份
- 写完列出每个端点「目标键链 ↔ Bean 字段链」的对照
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 容器 Bean 自身还有 data 字段时，实测响应是 body.data.data.xxx，要先取 getObject(res.data, 'data') 再取目标字段：带条件的例子：res.data 对应解包后的容器 Bean、容器里还有一层 data（出处：卡里修好并验证过）
针对本应用要查的：
- 端点返回的 Bean、它的字段链和每个字段的声明类型：规格里的共享模型类型表；源工程里 Retrofit 接口和 Repository 方法的返回类型，按类名搜 Kotlin data class 或 Java Bean 的定义；从 res.data 对应的那层开始逐层写出到目标字段的键名，记下每个字段的声明类型（String、Int 等）；字段带 @SerializedName 的，键名记注解里的名字
未核实：字段带 @SerializedName 时 JSON 键名以注解为准，族里规矩没有查实
