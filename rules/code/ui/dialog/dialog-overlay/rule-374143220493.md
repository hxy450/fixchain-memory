# 框架 AlertDialog 落地成页内弹卡时，宽写 '95%' 加左右 16 内边距，不写 width(300)

审的是：代码
触发（任一种）：
- 读到：源端是框架生成的 AlertDialog（含 ListPreference 选项对话框），没有自定义宽度；写错的样子：页面根 Stack 的遮罩里，弹卡写死 width(300) 一类固定值，或照「约 280–320vp」估值
适用范围：用页内遮罩加居中卡片落地框架 AlertDialog，遮罩所在的页面根 Stack 是定尺寸父级时
做法：
- 卡片外层写 .width('95%').padding({ left: 16, right: 16 })，可见卡片宽 = 95% 屏宽 − 32；不写固定 vp 宽
- 遮罩铺满整窗，卡片在系统栏之间居中
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- dialog_min_width_minor = 95%（dialog_min_width_major = 65%）：竖屏时对话框窗口宽 95% 屏宽（横屏取 65%）（出处：Android SDK 平台资源 data/res/values/dimens.xml，dialog_min_width_minor、dialog_min_width_major（按应用的 compileSdk 取对应平台））
- dialog_background_material：<inset android:inset="16dp">：背景四周内缩 16dp，所以可见卡宽再减 32dp（出处：Android SDK 平台资源 data/res/drawable/dialog_background_material.xml（按应用的 compileSdk 取对应平台））
- width(value: Length): T：Length 可以写百分比字符串，如 '95%'（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.width）
- 百分比尺寸参考最近设置了固定大小的祖先节点：页面根 Stack 定了尺寸时，'95%' 就是相对它（出处：ts-universal-attributes-size.md，尺寸设置）
- 实测卡宽 95% × 屏宽 − 32dp；改成 '95%' 加左右各 16 内边距后与源端一致：修好后的宽度写法（出处：卡里修好并验证过）
