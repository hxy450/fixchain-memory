# 一个页面要挂多个 bindSheet 时，每个挂在独立的零尺寸锚点上，不在同一组件上连写

审的是：代码
触发（任一种）：
- 读到：源端同一页面由菜单或按钮分别弹出多个 BottomSheetDialogFragment / 对话框；写错的样子：同一组件上连写多个 .bindSheet(...)（两个 .bindSheet 之间没有新组件），只有最后一个能打开；或照抄先例页面的整段 bindSheet 属性链
适用范围：页面转换与接线阶段，一个页面承载多个半模态弹层时
做法：
- 每个 sheet 挂在独立的零尺寸锚点上：Column().width(0).height(0).bindSheet(该 sheet 的显示状态, 该 sheet 的 @Builder, options)，一个锚点一个 bindSheet
- 写完扫描一次「两个 .bindSheet 之间没有新组件」的链式调用；复用已接线页面作先例前，先核对先例里的这段结构是否合乎框架约束，不整段照抄
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- bindSheet(isShow: boolean, builder: CustomBuilder, options?: SheetOptions): T：给组件绑定半模态面板，一个组件上的同名属性链式多次调用时只留一个生效（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.bindSheet）
- 每个 sheet 移到独立零尺寸锚点后，原先打不开的面板能打开：零尺寸锚点不参与视觉（出处：卡里修好并验证过）
- bindContentCover(isShow: boolean, builder: CustomBuilder, options?: ContentCoverOptions): T：同族接口：全模态，同样按 isShow + builder 绑定在组件上（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.bindContentCover）
未核实：「链上只有最后一个生效」出自卡里修复者对 ArkUI 属性覆盖的判断和工程内注释，本机声明和文档里没找到原文；修复后的复测同时含其他改动
