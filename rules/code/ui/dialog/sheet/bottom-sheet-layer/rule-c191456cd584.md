# openBindSheet 用 EMBEDDED 时传宿主页内组件的 targetId，否则回退 OVERLAY

审的是：代码
触发（任一种）：
- 写错的样子：SheetOptions 写了 mode: SheetMode.EMBEDDED，但 uiContext.openBindSheet(content, options) 没传第三个参数 targetId，弹窗配置接口只有 uiContext
适用范围：用 UIContext.openBindSheet（或封装它的弹窗 Controller）打开 EMBEDDED 半模态时
做法：
- 弹窗配置接口加 targetId，调用方传宿主 Page / NavDestination 内组件的 this.getUniqueId()，调用写成 uiContext.openBindSheet(content, options, targetId)
- 复用已有弹窗 Controller 接新页面时，核对它的 SheetMode、挂载参数与本页跳转动作是否匹配；回归断言同时检查 mode 和 targetId 是否传入，不只匹配 mode 字面值
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- openBindSheet<T extends Object>(bindSheetContent: ComponentContent<T>, sheetOptions?: SheetOptions, targetId?: number): Promise<void>：UIContext 打开半模态，第三个参数是要绑定的组件 id（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.openBindSheet）
- 未传 targetId 时 SheetOptions.mode 不能设为 EMBEDDED，默认 OVERLAY：只改 mode 不传 targetId 等于没改（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.openBindSheet）
- 错误码 120004 targetId 不存在、120005 节点不在组件树上、120006 节点不是 Page 或 NavDestination 的子节点：targetId 要取宿主页内已上树的组件（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.openBindSheet）
- getUniqueId(): number；节点创建前或销毁后调用返回 -1：取宿主组件 id 的写法，要在组件上树后调用（出处：鸿蒙 SDK 的 ets/component/common.d.ts，BaseCustomComponent.getUniqueId）
- 配置和 SheetOptions 增加 targetId，调用页传入 this.getUniqueId() 后新页面能覆盖弹窗：修复后的挂载（出处：卡里修好并验证过）
