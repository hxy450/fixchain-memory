# 弹窗用 DialogAlignment.Center 居中承载源对话框时，按上下避让差的一半加 offset

审的是：代码
触发（任一种）：
- 读到：源端用 AlertDialog / Dialog 窗口弹出对话框（对话框窗口在状态栏与导航栏之间居中）；写错的样子：openCustomDialog 写 alignment: DialogAlignment.Center，没有 offset，也没读主窗口的 TYPE_SYSTEM / TYPE_NAVIGATION_INDICATOR 避让
适用范围：目标窗口保持非全屏、用 openCustomDialog 等系统弹窗居中承载源对话框时
做法：
- 主窗口创建时和 on('avoidAreaChange') 回调里，用 getWindowAvoidArea(AvoidAreaType.TYPE_SYSTEM).topRect.height 取顶部避让，底部取 TYPE_SYSTEM 与 TYPE_NAVIGATION_INDICATOR 两者 bottomRect.height 的较大值（都是 px），存进共享工具
- 所有打开处与 alignment: DialogAlignment.Center 一起写 offset: { dx: 0, dy: px2vp((top − bottom) / 2) }；页面本身不必因此加避让 padding，但对话框偏移仍要读避让值
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getWindowAvoidArea(type: AvoidAreaType): AvoidArea：取主窗口某类避让区，AvoidArea 有 topRect、bottomRect 等（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.getWindowAvoidArea）
- AvoidAreaType.TYPE_SYSTEM = 0；AvoidAreaType.TYPE_NAVIGATION_INDICATOR = 4：系统栏避让区和底部导航条避让区（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，AvoidAreaType）
- Rect 的 left、top、width、height 单位是 px：避让高度要先换成 vp 再交给 offset（出处：arkts-apis-window-i.md，Rect）
- on(type: 'avoidAreaChange', callback: Callback<AvoidAreaOptions>): void：避让区变化（旋转、导航方式切换）时更新存下的上下避让（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.on('avoidAreaChange')）
- alignment?: DialogAlignment；offset?: Offset（dx、dy 为 Length，数值按 vp）：openCustomDialog 选项里的对齐和偏移（出处：鸿蒙 SDK 的 ets/api/@ohos.promptAction.d.ts，BaseDialogOptions.alignment / offset；ets/component/units.d.ts，Offset）
- px2vp(value: number): number（UIContext 的方法；全局 px2vp 自 API 18 废弃）：把 px 的避让差换成 vp（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.px2vp；ets/component/common.d.ts，px2vp）
- DialogAlignment.Center 以整窗（含状态栏与底部手势条）为基准；加 dy = px2vp((top − bottom) / 2) 后卡片中心落在系统栏之间：改前改后的效果（出处：卡里修好并验证过）
- CustomDialogControllerOptions：alignment?: DialogAlignment；offset?: Offset：同族接口：CustomDialogController 也用 alignment 加 offset 定位；它的居中参照卡里没验证（出处：鸿蒙 SDK 的 ets/component/custom_dialog_controller.d.ts，CustomDialogControllerOptions.alignment / offset）
