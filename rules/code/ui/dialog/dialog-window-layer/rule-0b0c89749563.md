# 自绘对话框容器不写 width('100%') 或凭印象的百分比，按库或主题公式算 dialogWidth

审的是：代码
触发（任一种）：
- 读到：源端用 material-dialogs 的 MaterialDialog.Builder（含 customView）弹窗；写错的样子：自绘对话框根 Column 写 .width('100%') 交给 openCustomDialog，只设了 alignment，没有窗口宽度约束，运行时整屏宽
- 读到：AndroidManifest 里 Activity 的 android:theme 是 Theme.*.Dialog（如 Theme.MaterialComponents.Light.Dialog），窗口是 wrap_content 浮动窗口；写错的样子：目标的对话框卡片写成 .width('100%') 加外层 padding，或凭印象的 '80%'、'95%'
- 写错的样子：注释写「按同族对话框同款视觉」「匹配既定约定」，照搬了同族组件或页面的 .width('100%')，放弃了已识别的「浮动窗口不是全屏」
适用范围：用 openCustomDialog 或 NavDestination 卡片自绘对话框，源端对话框宽度由库 dimens 或 Dialog 主题决定时
做法：
- 按公式算宽度写到根容器 .width(w)：material-dialogs 为 min(356, 屏宽 − 56)；Theme.*.Dialog 的 wrap_content Activity 为 min(320, 屏宽)；AlertDialog 风格为屏宽 × 95%（竖）/ 65%（横）再减背景 inset；可抽成共享的宽度函数给同族对话框复用
- 窗口尺寸变化时按方向重算；没有公式就先回规格或库资源查，再写数值
- 复用同族页面的写法前，先核对它的窗口几何是否已对照过源端
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 库对话框改为 min(356, 屏宽 − 56) 并导出共享宽度函数，Dialog 主题页改为 min(320, 屏宽) 后与源一致：修好的写法（出处：卡里修好并验证过）
- openCustomDialog<T extends Object>(dialogContent: ComponentContent<T>, options?: promptAction.BaseDialogOptions): Promise<void>：用 ComponentContent 打开自定义弹窗；宽度写在内容的根容器上（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.openCustomDialog）
- on(type: 'windowSizeChange', callback: Callback<Size>): void：窗口尺寸变化的回调，在这里按方向重算对话框宽度（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.on('windowSizeChange')）
- config_prefDialogWidth = 320dp：wrap_content 浮动窗口先按这个宽度试排（出处：Android SDK 平台资源 data/res/values/config.xml，config_prefDialogWidth（按应用的 compileSdk 取对应平台）；android.view.ViewRootImpl#measureHierarchy）
- dialog_min_width_minor = 95%，dialog_min_width_major = 65%：AlertDialog 风格的窗口最小宽度比例（出处：Android SDK 平台资源 data/res/values/dimens.xml，dialog_min_width_minor / dialog_min_width_major（按应用的 compileSdk 取对应平台））
针对本应用要查的：
- 这个对话框对应的库 dimens 或主题宽度值：规格的跨栈基线；没有时查 Gradle 缓存里应用依赖版本的库 AAR 的 res/values/values.xml，或源工程应用主题的 windowMinWidthMinor / windowMinWidthMajor；读出 dp 或百分比代入公式
未核实：卡的目标 SDK 是 HarmonyOS 6.1.1(24)，本机声明是 API 23；material-dialogs 的 356 / 28 两个值本机 Gradle 缓存里没有这个库，取自卡
