# 源端在循环里对每个命中元素各弹一个模态窗时，目标用计数信号叠放弹窗，确认只关最上面一个

审的是：代码
触发（任一种）：
- 读到：判定方法只在循环外检查一次防重标志，双层 `for` 循环不 `break`，每个命中元素都先落盘统计再 `new AlertDialog.Builder(…).setCancelable(false).create().show()`；写错的样子：引擎的 pending 信号是 `boolean`，consume 方法返回 `boolean`；页面用一个 `@Local` 布尔只渲染一个弹窗，确认、取消都直接置 `false`；注释写「幂等收敛为单窗」「罕见路径」
适用范围：迁移在循环里按命中次数弹窗、且副作用（落盘、统计）也按次数执行的源端判定
做法：
- 引擎里每个命中元素都执行一次源端副作用（落盘统计）并 pending += 1；consume 方法返回 number（取走的个数）
- 页面用 @Local 计数（number）按个数叠放弹窗，只有最上面一个画遮罩；确认键只关最上面一个（计数减一），其他按钮照源端行为处理
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 引擎每个命中 pending += 1、consume 返回 number；页面按计数叠放，只有顶层画遮罩，确认减一、取消清零：返修后保留的写法，实测源端弹两窗时目标也弹两窗（出处：卡里修好并验证过）
针对本应用要查的：
- 源端每个弹窗各个按钮的行为和副作用次数：源工程判定方法里的循环体和 AlertDialog.Builder 的 setPositiveButton / setNegativeButton 回调；数出一次触发里弹窗个数、每个按钮关几个窗、落盘几次，照这个次数写目标
