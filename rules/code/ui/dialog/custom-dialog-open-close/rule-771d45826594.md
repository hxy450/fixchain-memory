# 页内遮罩复刻可点外取消的源对话框时，遮罩 onClick 关闭最上层，与返回键共用取消处理

审的是：代码
触发（任一种）：
- 读到：源端 AlertDialog.Builder 没调用 setCanceledOnTouchOutside(false) 或 setCancelable(false)；写错的样子：遮罩层 .hitTestBehavior(HitTestMode.Block) 加空 onClick 吞掉点击，注释写「源 AlertDialog 模态语义——外触不 dismiss」；宿主页没有点外部关闭
适用范围：界面实现阶段用页内遮罩加自绘面板复刻源端平台对话框时
做法：
- 宿主页的变暗层 .onClick(() => 关闭最上层对话框)；onBackPress() 在同一个对话框栈上关闭最上层并 return true；两处调用同一个取消函数，对话框组件只画面板、不带吞点击的遮罩
- 源端显式 setCancelable(false) 或 setCanceledOnTouchOutside(false) 时，遮罩才只吞点击、不关闭
- 自己对平台默认的判断与规格冲突时，写进 handback 的 decision_gaps 回报，不按窄规格实现，也不在注释里把规格限制写成源端语义
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onBackPress?(): void | boolean：返回 true 表示页面自己处理返回，不走默认返回（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CustomComponent.onBackPress）
- hitTestBehavior(value: HitTestMode): T：遮罩若设 Block 会把点击挡在自己身上（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.hitTestBehavior）
- HitTestMode.Block：阻塞子组件的触摸测试，自身命中时阻塞兄弟组件及父组件：吞点击的遮罩只在源端不可点外取消时才用（出处：arkts-interaction-basic-principles.md，干预命中）
- 删掉组件自带的 Block 遮罩，宿主变暗层 onClick 和 onBackPress 都关最上层后，点外部与返回键都是 2→1→0：改法的依据（出处：卡里修好并验证过）
针对本应用要查的：
- 源对话框的点外部取消是否开启：源工程里构造对话框处的 setCancelable / setCanceledOnTouchOutside 调用；没有调用时按对话框主题的 windowCloseOnTouchOutside（见对应规格规矩的查法）；true 或未关闭就让遮罩 onClick 关闭最上层；显式 false 才吞点击
