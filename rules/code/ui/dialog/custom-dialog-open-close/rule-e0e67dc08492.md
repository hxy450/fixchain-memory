# openCustomDialog 承载点外取消时，起于框内可消费控件的 TOUCH_OUTSIDE 不关闭

审的是：代码
触发（任一种）：
- 读到：规格写「点外取消」，或源端 Dialog / AlertDialog 没调 setCanceledOnTouchOutside(false)，对话框里有按钮、列表、输入框或可滚动正文；写错的样子：openCustomDialog 只靠 autoCancel: true（或默认值）、不设 onWillDismiss；或 onWillDismiss 里对 DismissReason.TOUCH_OUTSIDE 无条件 action.dismiss()
适用范围：目标用 openCustomDialog 承载源端没关点外取消、且框内有会消费触摸的控件的对话框时
做法：
- 给框内会消费触摸的区域（正文、列表、输入框、按钮条）挂 .onTouch：event.type === TouchType.Down 时登记「按下起于可消费区」；Up 或 Cancel 后等本次事件处理完再清除（如延到下一轮任务）
- openCustomDialog 设 onWillDismiss: (action) => { if (action.reason === DismissReason.TOUCH_OUTSIDE && 已登记) { return; } action.dismiss(); }；PRESS_BACK 照常关闭
- 登记和判断做成共享守卫，所有 openCustomDialog 的打开处都在 onWillDismiss 里先问它
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- autoCancel?: boolean，@default true —— Allows users to click the mask layer to exit.：不设就是点遮罩即关，声明没写按下点在哪（出处：鸿蒙 SDK 的 ets/api/@ohos.promptAction.d.ts，BaseDialogOptions.autoCancel）
- onWillDismiss?: Callback<DismissDialogAction>；注册后点遮罩、侧滑、返回键不会立刻关闭，由回调按 reason 决定：拦截关闭的入口（出处：鸿蒙 SDK 的 ets/api/@ohos.promptAction.d.ts，BaseDialogOptions.onWillDismiss；js-apis-promptAction.md，BaseDialogOptions）
- DismissDialogAction { dismiss: Callback<void>; reason: DismissReason }：回调参数：调 dismiss() 才关闭（出处：鸿蒙 SDK 的 ets/api/@ohos.promptAction.d.ts，DismissDialogAction）
- DismissReason.PRESS_BACK = 0（返回键、侧滑、Esc）；TOUCH_OUTSIDE = 1（点遮罩）；CLOSE_BUTTON = 2；SLIDE_DOWN = 3：关闭原因（出处：鸿蒙 SDK 的 ets/component/common.d.ts，DismissReason）
- onTouch(event: (event: TouchEvent) => void): T；TouchType 有 Down、Up、Move、Cancel：登记按下起点用的触摸回调（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onTouch；ets/component/enums.d.ts，TouchType）
- ArkUI 按抬起点判定：从框内按钮按下拖到遮罩松手会关闭，安卓不关；加守卫后两端同一组拖动手势逐项一致：改前改后的现象（出处：卡里修好并验证过）
- onWillDismiss?: Callback<DismissDialogAction>（CustomDialogControllerOptions）：同族接口：CustomDialogController 承载时同样在这里拦 TOUCH_OUTSIDE（出处：鸿蒙 SDK 的 ets/component/custom_dialog_controller.d.ts，CustomDialogControllerOptions.onWillDismiss）
- onWillDismiss?: Callback<DismissDialogAction>（AlertDialogParam）：同族接口：AlertDialog 承载时同样在这里拦（出处：鸿蒙 SDK 的 ets/component/alert_dialog.d.ts，AlertDialogParam.onWillDismiss）
未核实：点遮罩判定按抬起点这一行为声明里没写，是卡里两端实测得到的
