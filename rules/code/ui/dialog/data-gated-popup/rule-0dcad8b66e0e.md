# 复刻「数据到达后条件弹窗」时，目标用源函数调用的同一接口取数，不换成同名内容的列表接口

审的是：代码
触发（任一种）：
- 读到：源端弹窗函数先判 `token` 为空就返回，再带 token `POST` 一个专用接口（如启动接口），按返回对象决定是否打开弹窗；写错的样子：目标的弹窗任务改调目标端已有的同名内容列表或分页接口，取第一页 `items[0]` 就打开弹窗
适用范围：宿主页接线阶段，复刻源端启动后按接口返回条件弹出的弹窗时
做法：
- 照源函数实际调用的接口和返回对象选数据源：目标端没有同源接口时，在数据层补一个请求同一接口的方法（带同样的 token），不拿列表或分页接口代替
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 新增请求源端同一启动接口的数据层方法，登录后用统一 token 调用，替换原先的列表接口取第一条：修复后的数据源（出处：卡里修好并验证过）
针对本应用要查的：
- 源端弹窗实际用的接口路径、请求方式、参数和返回对象：源工程里打开该弹窗的 Activity/Fragment（.kt/.java）中的取数函数，以及它调用的网络接口定义；记下接口路径、是否带 token、返回对象类型，目标数据层照此请求同一接口
