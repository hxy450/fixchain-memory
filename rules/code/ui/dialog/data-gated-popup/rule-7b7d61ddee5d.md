# 源端弹窗带显示守卫时，把登录门禁、字段完整性、频次逐条写进目标实现

审的是：代码
触发（任一种）：
- 读到：源端弹窗函数里有多道守卫：`token` 为空 `return`、返回对象为空或必填字段有空值不展示、按当日次数限制展示；写错的样子：目标只在打开弹窗前判了每日次数，没有 `token` 门禁，也没有返回对象字段完整性判定
- 写错的样子：修复计划只写「恢复带守卫的触发」时，目标只落地了弹窗组件和每日计数，没有 `token` 门禁和字段判定，实现说明里也没写接口和各条守卫
适用范围：复刻源端带条件的启动弹窗、提示弹窗时
做法：
- 读完源函数全文，把每条守卫写成代码：未登录或 token 为空直接返回；数据层只在返回对象各必填字段都非空时给出可展示结果；按本地自然日计数，达上限不弹
- 实现说明里列出接口和每条守卫，写后对照源函数逐项核对，或写成测试断言
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 登录后请求；数据层仅在返回对象的作者、图片、id、日期、正文都完整时给出可展示结果；页面按本地自然日最多展示两次：修复后落实的三类守卫（字段和次数是那次的取值，照源函数换）（出处：卡里修好并验证过）
针对本应用要查的：
- 源端弹窗的每条显示守卫：源工程里该弹窗取数函数的全文，以及返回对象上的判空方法、记录展示时间和次数的本地存储键；逐条列出：门禁条件、哪些字段必须非空、频次上限和计数周期，目标逐条实现
