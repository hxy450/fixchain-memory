# 未声明 supportsRtl 时，自绘对话框的面板和按钮条都加 .direction(Direction.Ltr)

审的是：代码
触发（任一种）：
- 读到：manifest 的 `<application>` 没有 `android:supportsRtl`；源端确认框是 Material `AlertDialog`，按钮在右侧按 [负键][正键] 排；写错的样子：复刻对话框的面板 `Column` 和按钮条 `Row` 都没写 `.direction(`，依赖默认 `Direction.Auto`，阿拉伯语系统下按钮镜像到左侧
适用范围：源端未声明 supportsRtl，目标端用 Row/Column 自绘对话框或按钮条（含返修中替换系统弹窗）时
做法：
- 按钮条 Row 加 .direction(Direction.Ltr)，面板 Column 也加；有顺序语义的子容器各自加，不靠父容器传下去
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- direction(value: Direction): T：设置容器主轴方向的布局方向，默认 Direction.Auto（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.direction）
- enum Direction { Ltr, Rtl, Auto }：Ltr 从左到右，Rtl 从右到左，Auto 用默认布局方向（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，Direction）
- 只给面板 Column 加 Direction.Ltr 时按钮仍镜像，子组件默认 Auto 跟随系统语言、不继承父容器；给按钮条 Row 也加上后按钮回到右侧：返修时观察到的行为（出处：卡里修好并验证过）
未核实：Column 上那一处 .direction(Direction.Ltr) 是否起作用卡里没单独验证（文档说该属性在 Column 上不生效）
