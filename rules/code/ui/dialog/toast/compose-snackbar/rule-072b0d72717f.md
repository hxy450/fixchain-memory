# 源端 ActionPerformed 后才执行动作时，目标等 Snackbar 结果，不用 Toast 加确认弹窗代替

审的是：代码
触发（任一种）：
- 读到：showSnackbar(message, actionLabel, true, SnackbarDuration.Long) == SnackbarResult.ActionPerformed 时才执行动作；写错的样子：目标写成 showToast 或提示组件 show(...) 再加 showAlertDialog 确认弹窗承接动作，注释写「Snackbar 动作按钮 → Toast + 确认弹窗」
适用范围：消费共享提示组件的页面或服务，源端靠 Snackbar 动作钮触发后续动作时
做法：
- 调用带动作钮的 Snackbar（传动作文案、关闭钮、时长），等返回 ActionPerformed 再执行动作，Dismissed 时不执行
- 共享组件不支持动作钮或结果时，把能力缺口登记给组件所有者或记成决策缺口，不就地改成 Toast + 确认弹窗
