# showSnackbar 带 actionLabel 时常驻、无 action 为 4 秒，目标用队列串行展示

审的是：代码
触发（任一种）：
- 读到：源端 showSnackbar(消息) 不带 actionLabel，或 showSnackbar(消息, actionLabel = …) 带动作，都没写 duration；写错的样子：目标端提示一律按同一时长定时消失，或带动作的提示也被 setTimeout 自动关掉，没有和源端调用对应
- 读到：源端 SnackbarHostState.showSnackbar(message, actionLabel = …)，没写 duration；写错的样子：目标对所有提示用固定 setTimeout(…, 4000) 的单槽定时器，带操作按钮的也 4 秒消失，新消息直接覆盖旧消息
适用范围：Compose Material3 的 SnackbarHostState.showSnackbar 没写 duration，迁成目标端自写的提示浮层时
做法：
- 按调用参数推时长：不带 actionLabel 的按 Short（4000ms）自动消失；带 actionLabel 的按 Indefinite 常驻，到点动作、关闭或离页才消失
- 目标端提示宿主用 FIFO 队列，一条结束再显示下一条，不用单槽覆盖
- 和评审口径不同时（例如要求带动作的提示也定时消失），照评审改并在迁移报告里登记这处差异
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 无 action 用 Short 4000ms，有 action 用 Indefinite，提示宿主排队：修复后的提示时长和队列（出处：卡里修好并验证过）
针对本应用要查的：
- 源端每次 showSnackbar 有没有 actionLabel、有没有显式 duration：源工程的 Compose 页面里调 showSnackbar 的地方；写了 duration 的照它；没写的按有无 actionLabel 取默认
未核实：Material3 showSnackbar 的默认时长（不带动作 Short 约 4 秒、带动作常驻）本机只有编译产物，没核到源码
