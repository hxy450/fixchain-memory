# showSnackbar 带动作、关闭钮或读结果时，目标自绘 Snackbar，不用 showToast

审的是：代码
触发（任一种）：
- 读到：SnackbarHostState.showSnackbar(message, actionLabel, withDismissAction, duration) 的 actionLabel 非空、withDismissAction = true，或调用方比较返回值 == SnackbarResult.ActionPerformed；写错的样子：目标提示出口只有 getPromptAction().showToast(...)，没有动作钮、关闭 X 和结果回传，注释写「Toast 无动作位」
适用范围：源端用 Compose SnackbarHost / showSnackbar 做提示，迁成 ArkUI 的共享提示组件或页面时
不适用的情形：showSnackbar 没有 actionLabel、withDismissAction 为 false、调用方也不读 SnackbarResult 的纯提示，可以映射成 showToast
做法：
- 先列出全部 showSnackbar 调用的 actionLabel、withDismissAction、duration 和是否读 SnackbarResult；任一处有动作、关闭钮或读结果，就自绘 Snackbar（叠加层或页内），不用 showToast
- 自绘组件：actionLabel → 动作钮，withDismissAction = true → 关闭 X，同时只显示一条（Promise 排队），返回 ActionPerformed / Dismissed；SnackbarDuration.Short → 4000ms、Long → 10000ms、Indefinite 不自动消失
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- showToast(options: promptAction.ShowToastOptions): void：PromptAction.showToast 没有返回值；ShowToastOptions 的字段是 message、duration、bottom、showMode、alignment、offset、backgroundColor、textColor、backgroundBlurStyle、shadow、enableHoverMode、hoverModeArea，没有动作钮、关闭钮或结果回调（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.showToast；ets/api/@ohos.promptAction.d.ts，promptAction.ShowToastOptions）
- 即时反馈控件本身不应该包含任何可交互的元素，如按钮或链接：Toast 按设计不承载动作（出处：arkts-create-toast.md，使用建议）
- SnackbarDuration.Short = 4000ms、Long = 10000ms、Indefinite 不自动消失；自绘组件带动作/关闭钮、Promise 排队、SnackbarResult：返修后自绘 Snackbar 的时长和能力（出处：卡里修好并验证过）
- openToast(options: promptAction.ShowToastOptions): Promise<number>：同族接口：PromptAction.openToast，返回给 closeToast 用的 toast id，同样没有动作参数（@since 18）（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.openToast）
未核实：卡里的环境是 HarmonyOS 6.1.1(24)，声明按本机 API 23 核实；Snackbar 的 4000/10000ms 出自 Compose material3 库代码，本机没有源码，按卡写
