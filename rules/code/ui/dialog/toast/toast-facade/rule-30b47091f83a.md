# 计划要求统一吐司门面时，移动或下沉页面前先建门面并把页面里的直调改成调门面

审的是：代码
触发（任一种）：
- 读到：计划或审计要求用统一 `ToastService`（全局吐司管理）替换 `promptAction.showToast`、`DialogHelper.showToast` 和页面自绘吐司，业务侧直调归零；写错的样子：移动或改写后的页面里仍有 `promptAction.showToast(`、`DialogHelper.showToast(`，或页面私有 `@Local` 显隐状态加 `Text` 覆盖层和 `setTimeout` 的自绘吐司；公共模块的 `Index.ets` 导出了别的工具，却没有吐司门面
适用范围：迁移执行与收口阶段，按已批准计划移动页面、向公共模块下沉工具或改写页面时
做法：
- 门面还不存在时，先在最底层的公共模块建一个薄封装并从它的 `Index.ets` 导出
- 移动页面、下沉工具时顺带把页面内的吐司直调和自绘覆盖层改成调用这个门面（如 `toastManager.show(...)`），删掉私有显隐状态和覆盖层，不原样搬走
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 在公共模块新增全局吐司管理类并从 Index.ets 导出，页面直调和自绘覆盖层全部改走它：修好后的做法，收口了全部提示点（出处：卡里修好并验证过）
- function showToast(options: ShowToastOptions): void（@deprecated since 18）：页面里要替换掉的模块级直调（出处：鸿蒙 SDK 的 ets/api/@ohos.promptAction.d.ts，promptAction.showToast）
针对本应用要查的：
- 门面放在哪个公共模块、从哪里导出：已批准计划里写「状态/Toast 薄适配」承接模块的那一节，以及目标工程各公共模块的 Index.ets；取依赖层级最低、业务模块都依赖的那个模块，在它的 Index.ets 里导出门面
