# 源端系统写入后 Toast「设置成功」而目标已降级为存相册时，各入口成功路径改弹引导

审的是：代码
触发（任一种）：
- 读到：源端调用系统写入接口（如 WallpaperManager 设壁纸）后用 Toast 回执「设置成功/失败」；规格或已批决策把目标端改成 SaveButton 保存到相册、再引导用户手动设置；写错的样子：目标入口的成功分支仍弹源端的「设置…成功」Toast，没有展示决策规定的引导
- 读到：规格或派工写明同一个保存服务接到多个入口，服务成功时 emit(...) 全局成功事件，由各入口订阅后展示引导；写错的样子：某个调用这个保存服务的入口既没有订阅成功事件、也没有在保存回调里展示引导，成功分支只有 Toast；或服务报告已展示引导而调用方实际没展示
适用范围：源端「设置壁纸」一类系统写入在目标端没有对应接口、已批决策降级为保存到相册＋引导手动设置时，每个调用入口的成功反馈
做法：
- 每个入口的成功分支（保存真正完成之后）展示决策规定的引导：告诉用户已保存到相册、请到相册或系统设置里手动设置；删掉源端「设置…成功」Toast，失败分支仍 Toast 失败
- 保存服务被多个入口复用时逐个入口核对：要么订阅服务发出的成功事件，要么在回调里展示引导；服务报告已展示引导时，调用方确实展示了
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 入口订阅保存服务的成功事件，收到后显示常驻的引导浮层（已保存到相册、请到相册设置）；失败分支仍 Toast 失败：修好的成功反馈写法（出处：卡里修好并验证过）
- function setWallpaper(source: string | image.PixelMap, wallpaperType: WallpaperType): Promise<void>，标 @deprecated since 9：公开声明里设壁纸的接口已废弃，目标端「设置壁纸成功」不属实，只能保存后引导（出处：鸿蒙 SDK 的 ets/api/@ohos.wallpaper.d.ts，wallpaper.setWallpaper）
- type SaveButtonCallback = (event: ClickEvent, result: SaveButtonOnClickResult, error?: BusinessError<void>) => void：SaveButton 的 onClick 回调，成功与否看 result（出处：鸿蒙 SDK 的 ets/component/save_button.d.ts，SaveButtonCallback）
- SaveButtonOnClickResult.SUCCESS = 0、TEMPORARY_AUTHORIZATION_FAILED = 1、CANCELED_BY_USER = 2（@since 21）：只有 SUCCESS 能进成功分支；后两个是失败或用户取消，不弹引导（出处：鸿蒙 SDK 的 ets/component/save_button.d.ts，SaveButtonOnClickResult）
- result == SaveButtonOnClickResult.SUCCESS 后再用 MediaAssetChangeRequest.createImageAssetRequest + applyChanges 写入相册：授权成功之后写入相册完成，才是「已保存」，引导放在这之后（出处：photoAccessHelper-savebutton.md，使用安全控件保存媒体库资源）
- WallpaperManager#setBitmap：Change the current system wallpaper to a bitmap：源端成功回执代表系统壁纸已改，目标端保存到相册后没有这个状态（出处：android.app.WallpaperManager#setBitmap）
未核实：卡的环境是 API 24，声明按本机 API 23 核实
