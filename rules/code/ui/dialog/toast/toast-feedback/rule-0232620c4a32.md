# 源端权限被拒时弹“去设置”引导，目标失败分支按失败类型分派，不一律 toast

审的是：代码
触发（任一种）：
- 读到：源端权限回调拒绝后用 AlertDialog.Builder 弹“无法使用…／取消／去设置”，去设置跳 Settings.ACTION_APPLICATION_DETAILS_SETTINGS；只有启动器本身失败才 Toast；目标 ViewModel 的启动方法只返回 boolean，失败类型另存在一个字段里（含权限拒绝）；写错的样子：宿主页的 if (!started) 分支一律 promptAction.showToast(...) 后返回，没读失败类型，没有去设置引导弹窗
适用范围：把源端控制器的“权限→启动→失败反馈”流程接到目标宿主页，而源端对权限拒绝和启动失败给不同反馈时
做法：
- 失败分支先读 ViewModel 存的失败类型：是权限拒绝就弹引导框（标题、说明、取消、去设置照源端），确认后 context.startAbility({ action: 'ohos.settings.application.details', uri: <当前 bundleName> })，bundleName 用 bundleManager.getBundleInfoForSelf 取
- 其他失败类型保留原来的 toast；动手前把源方法的每个失败分支和对应 UI 逐条列出，和目标实现逐项对照
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- ACTION_APPLICATION_DETAILS_SETTINGS = 'ohos.settings.application.details'：打开指定应用详情页的 action（声明在旧模块，deprecated since 9）（出处：鸿蒙 SDK 的 ets/api/@ohos.ability.wantConstant.d.ts，wantConstant.Action.ACTION_APPLICATION_DETAILS_SETTINGS）
- startAbility(want: Want, options?: StartOptions): Promise<void>：UIAbilityContext 拉起目标页面（出处：鸿蒙 SDK 的 ets/api/application/UIAbilityContext.d.ts，UIAbilityContext.startAbility）
- function getBundleInfoForSelf(bundleFlags: number): Promise<BundleInfo>：取自身的 BundleInfo，从中读 bundleName 填进 uri（出处：鸿蒙 SDK 的 ets/api/@ohos.bundle.bundleManager.d.ts，bundleManager.getBundleInfoForSelf）
- Settings.ACTION_APPLICATION_DETAILS_SETTINGS：显示某个应用的详情页，Intent 的 data 用 package: 加包名：源端“去设置”的语义（出处：android.provider.Settings#ACTION_APPLICATION_DETAILS_SETTINGS）
- !started 时先判断失败类型为权限拒绝，弹“取消／去设置”引导框，确认后跳应用详情设置页；其余失败仍 toast：返修后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源方法的全部失败分支和各自的 UI：源工程里该控制器的 Java/Kotlin 文件：权限结果回调、启动方法的返回值判断、异常处理；每个分支记下弹的是 AlertDialog、Toast 还是别的对话框，以及按钮文案和跳转目标
未核实：卡里没写上机跳到设置页的结果
