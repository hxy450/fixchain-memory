# 安卓校验失败用 toast 提示时，目标也用 showToast，页内错误行放固定位置

审的是：代码
触发（任一种）：
- 读到：安卓确认或保存时的必填校验失败分支用 toast 提示（`Toast` 或封装的 `toast("…")`）后返回；写错的样子：校验失败分支只给状态变量赋值（如 `errorMessage = '…'`）再 `return`，反馈只是追加在 `layoutWeight(1)` 内容区末尾的条件 `Text`，没有 `showToast`
适用范围：安卓用 toast 等全局瞬时提示报校验失败，迁成鸿蒙弹层或表单页的确认按钮时
做法：
- 校验失败分支调用 `this.getUIContext().getPromptAction().showToast({ message: <安卓 toast 的文案> })`，每个失败分支各弹各的文案
- 若另加页内错误文字，放在操作栏下方或键盘上方的固定行，不追加到可变高度内容区的末尾
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- showToast(options: promptAction.ShowToastOptions): void：UIContext 的 PromptAction 弹 toast；用 getUIContext().getPromptAction() 取实例（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.showToast、UIContext.getPromptAction）
- ShowToastOptions.message: string | Resource；duration?: number，默认 1500 ms，小于 1500 按 1500，最大 10000：toast 的文案和显示时长（出处：鸿蒙 SDK 的 ets/api/@ohos.promptAction.d.ts，ShowToastOptions）
- function showToast(options: ShowToastOptions): void，@deprecated since 18，@useinstead UIContext.PromptAction#showToast：同族接口：@ohos.promptAction 的全局 showToast，API 18 起改用 UIContext 的 PromptAction（出处：鸿蒙 SDK 的 ets/api/@ohos.promptAction.d.ts，promptAction.showToast）
未核实：加 showToast 后用户仍报告无反应，材料里没看到当时是否装了新包、Toast 是否实际弹出；错误行被键盘遮住是按截图的布局余量和代码结构推定的，没有直接截图
