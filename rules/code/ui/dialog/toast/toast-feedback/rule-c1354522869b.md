# 源端服务层弹 Toast 时，目标用 getLastWindow 加 showToast 复刻，不换成日志

审的是：代码
触发（任一种）：
- 读到：Java 帮助类或服务里 `Toast.makeText(context, ..., ...).show()`（含 Handler(mainLooper).post 里弹出），如设定提醒后提示时间、未授权时再提示一次；写错的样子：ArkTS 把 Toast 换成 hilog.info，注释写「服务层无后台 Toast 通道，降级日志」
适用范围：源端在非页面代码里弹出用户可见的 Toast，迁到 ArkTS 服务层时
做法：
- 用 window.getLastWindow(context) 取到窗口后调用 promptAction.showToast({ message: <源端拼出的文案> })，源端弹几次就弹几次；做不到时登记 PD 决策
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function getLastWindow(ctx: BaseContext): Promise<Window>：取当前应用最上层的窗口，没有子窗口时返回主窗口（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，window.getLastWindow）
- function showToast(options: ShowToastOptions): void（@deprecated since 18，@useinstead ohos.arkui.UIContext.PromptAction#showToast）：弹出 Toast；声明标了 18 起弃用（出处：鸿蒙 SDK 的 ets/api/@ohos.promptAction.d.ts，promptAction.showToast）
- ShowToastOptions.message: string | Resource；duration 默认 1500，小于 1500 按 1500，最大 10000（ms）：Toast 的文案和时长（出处：鸿蒙 SDK 的 ets/api/@ohos.promptAction.d.ts，ShowToastOptions）
