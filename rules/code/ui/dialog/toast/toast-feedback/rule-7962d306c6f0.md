# 整页错误态只由列表加载失败且无数据驱动，不用聚合了次级动作的单一 errorMessage

审的是：代码
触发（任一种）：
- 读到：规格把列表状态（Loading | Content | Empty | Error）和定位、权限等次级状态分成两套；验收条目写「权限拒绝后允许手动选择」「不支持时保留并提示」；写错的样子：页面写成 errorMessage 非空即整页错误态（if (this.errorMessage) 渲染错误内容），而 ViewModel 把定位、权限、选择、列表等所有失败都写进同一个 errorMessage
适用范围：列表页同时承载列表加载和定位、权限、选择等次级动作，把 ViewModel 状态绑定到页面时
做法：
- 整页错误/重试分支的条件写成「列表加载失败且没有可用数据」：列表状态为 Error 且目录数组都为空（如 errorMessage 非空 && items.length === 0 && hotItems.length === 0）；首次加载失败、无任何目录时仍显示整页错误
- 次级动作失败（权限拒绝、不支持、编码解析失败）用 Toast、提示条或对话框呈现，保留已加载目录可继续手动选择，并和验收条目逐条对照
- 交付前逐个代入 ViewModel 的每个错误值，看页面内容落到哪个分支，确认只有首次列表失败、没有缓存时才是整页错误
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 整页错误分支收窄为「errorMessage 非空且各目录数组都为空」后，次级错误不再遮住已加载目录；首次失败仍显示整页错误：修好后的分支条件（出处：卡里修好并验证过）
- showToast(options: promptAction.ShowToastOptions): void：次级错误用 Toast 提示时的接口（UIContext 的 PromptAction）（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.showToast）
