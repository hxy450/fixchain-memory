# Toast 的 LENGTH_SHORT/LONG 迁成 showToast 时长写 2000/3500

审的是：代码
触发（任一种）：
- 读到：Toast.makeText(context, text, Toast.LENGTH_SHORT) 或 Toast.LENGTH_LONG，或经辅助方法传 Toast.LENGTH_LONG；写错的样子：showToast({ message }) 没写 duration（落到默认 1500），或 duration 写成 1500 / 3000 这类估算值，注释写「短≈1.5s / 长≈3s」
适用范围：安卓 Toast.makeText 迁成 promptAction 或 UIContext 的 showToast 时
做法：
- 定义两个命名常量：短 2000、长 3500（毫秒）；Toast.LENGTH_SHORT → showToast({ message, duration: 短 })，Toast.LENGTH_LONG → showToast({ message, duration: 长 })，不沿用默认值或估算值
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Toast.LENGTH_SHORT = 2000ms、Toast.LENGTH_LONG = 3500ms：两档 Toast 的显示时长（出处：卡里修好并验证过）
- LENGTH_SHORT = 0、LENGTH_LONG = 1：源端常量本身是档位标志，不是毫秒数，不能照搬成 duration（出处：android.widget.Toast#LENGTH_SHORT、android.widget.Toast#LENGTH_LONG）
- duration?: number，默认 1500；建议 1500–10000ms，小于 1500 自动改成 1500，最大 10000：不写 duration 就是 1.5s，比 LENGTH_SHORT 短（出处：鸿蒙 SDK 的 ets/api/@ohos.promptAction.d.ts，promptAction.ShowToastOptions.duration）
- showToast(options: promptAction.ShowToastOptions): void：UIContext.getPromptAction() 上的 showToast，duration 通过 ShowToastOptions 传（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.showToast）
- function showToast(options: ShowToastOptions): void（@deprecated since 18，改用 UIContext 的 PromptAction#showToast）：同族接口：@ohos.promptAction 的 showToast，参数相同（出处：鸿蒙 SDK 的 ets/api/@ohos.promptAction.d.ts，promptAction.showToast）
- openToast(options: promptAction.ShowToastOptions): Promise<number>：同族接口：PromptAction.openToast，duration 同样在 ShowToastOptions 里（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.openToast）
未核实：卡里的环境是 HarmonyOS 6.1.1(24)，声明按本机 API 23 核实；2000/3500ms 定义在安卓系统服务里，本机 SDK 源码里没有原文
