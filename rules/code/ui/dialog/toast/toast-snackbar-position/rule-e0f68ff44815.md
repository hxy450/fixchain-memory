# Toast 未设 setGravity 时，showToast 显式传 bottom，取 toast_y_offset

审的是：代码
触发（任一种）：
- 读到：`Toast.makeText(...).show()`，没调 `setGravity` / `setMargin`；写错的样子：`showToast({ message, duration })` 或公共 Toast 封装的 show() 只传文案和时长，没有 `bottom`，位置落在默认 80vp
适用范围：源端文字 Toast 用平台默认位置，迁到 showToast 或公共 Toast 封装时，包括页面、ViewModel 里直接调 showToast 的地方
不适用的情形：源端调了 setGravity / setMargin 的，位置按源端的值，不取平台默认
做法：
- 位置和时长一样显式传：showToast({ message, duration, bottom })，bottom 写平台默认纵向偏移 toast_y_offset 的 dp 数值（单位 vp），不依赖 showToast 的默认 bottom
- 公共封装里把 bottom 定成常量；项目里直接调 showToast 的地方也传同一常量，或改走封装
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- toast_y_offset：android-33 到 android-37 为 48dp，android-30 为 24dp：安卓文字 Toast 的默认纵向偏移（出处：Android SDK 平台资源 data/res/values/dimens.xml，toast_y_offset（按对照机的系统版本取对应平台））
- config_toastDefaultGravity = 0x00000051：Toast 默认重力，底部居中（出处：Android SDK 平台资源 data/res/values/config.xml，config_toastDefaultGravity）
- mTN.mY = context.getResources().getDimensionPixelSize(com.android.internal.R.dimen.toast_y_offset)：Toast 在构造时从运行设备的框架资源读偏移和重力，所以取值跟对照机的系统版本走（出处：android.widget.Toast#Toast(Context, Looper)）
- showToast(options: promptAction.ShowToastOptions): void：UIContext 下 PromptAction 的显示吐司（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.showToast）
- ShowToastOptions.bottom：Toast 底部边框距离导航条的高度，默认值 80vp；底部没有导航条时是距离窗口底部的高度：不传 bottom 时离导航条 80vp，比安卓默认高（出处：js-apis-promptAction.md，ShowToastOptions）
- 实测安卓吐司底边在导航栏上方 50.5dp；目标传 bottom: 50 后吐司底边距屏底 80vp（50 加指示条区 30），与安卓相对导航区的位置一致：修复后的取值和效果（出处：卡里修好并验证过）
- openToast(options: promptAction.ShowToastOptions): Promise<number>：同族接口：PromptAction.openToast，同样收 ShowToastOptions，也要传 bottom（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.openToast）
针对本应用要查的：
- 对照安卓机系统版本下的 toast_y_offset：Android SDK 平台资源 values/dimens.xml 的 toast_y_offset，取与对照机系统版本相同的平台目录；dp 数值直接作为 bottom 的 vp 值；例：android-33 及以上是 48dp
未核实：平台资源的 48dp 与卡里实测的 50.5dp 差约 2.5dp，来源没有核实
