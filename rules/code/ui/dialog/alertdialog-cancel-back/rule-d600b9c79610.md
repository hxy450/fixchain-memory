# 可取消的 AlertDialog 用 openCustomDialog 承载，返回键和点外走 onCancel

审的是：代码
触发（任一种）：
- 读到：AlertDialog.Builder 链没有 setCancelable(false)（默认可取消），或带 setOnCancelListener；写错的样子：目标写成页内 Stack 条件渲染浮层，只接蒙层 .onClick 取消；弹窗打开时按返回直接退出页面或叠弹别的框
- 读到：AlertDialog.Builder…setTitle(...).setView(ListView) 的列表选择对话框；写错的样子：目标用 .bindSheet 半模态加 List 承载
适用范围：实现安卓 AlertDialog（含列表选择对话框）的承载和取消语义时；levelMode 自 API 15 起可用（出自声明）
做法：
- 先列出源对话框的取消路径：返回键、点外、OnCancelListener 里做什么
- 用 this.getUIContext().getPromptAction().openCustomDialog(content, { levelMode: LevelMode.EMBEDDED（需要页面级时）, onWillDismiss: (action) => { 执行源端 onCancel 逻辑; action.dismiss() } })，或用 showDialog，由系统处理返回键
- 列表选择对话框同样做成居中模态对话框，列表放在对话框内容里，不改成 bindSheet
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- openCustomDialog<T extends Object>(dialogContent: ComponentContent<T>, options?: promptAction.BaseDialogOptions): Promise<void>：打开自定义弹窗（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.openCustomDialog）
- LevelMode.OVERLAY = 0（显示在所有页面之上，默认）、LevelMode.EMBEDDED = 1（显示在当前页面内）：BaseDialogOptions.levelMode 的取值，页面级弹窗用 EMBEDDED（出处：鸿蒙 SDK 的 ets/api/@ohos.promptAction.d.ts，LevelMode；BaseDialogOptions.levelMode）
- onWillDismiss?: Callback<DismissDialogAction>：交互式关闭（返回键、点蒙层）前的回调，在这里调源端取消逻辑再 dismiss（出处：鸿蒙 SDK 的 ets/api/@ohos.promptAction.d.ts，BaseDialogOptions.onWillDismiss）
- DismissDialogAction { dismiss: Callback<void>; reason: DismissReason }；DismissReason.PRESS_BACK = 0（返回键、侧滑、Esc）、TOUCH_OUTSIDE = 1（点蒙层）：按 reason 区分返回键和点外（出处：鸿蒙 SDK 的 ets/component/action_sheet.d.ts，DismissDialogAction；ets/component/common.d.ts，DismissReason）
- AlertDialog.Builder#setCancelable：默认 true：源端没写 setCancelable(false) 就是可取消（出处：android.app.AlertDialog.Builder#setCancelable）
- openCustomDialog + LevelMode.EMBEDDED，返回键和点外经 onWillDismiss 走 onCancel 后，按返回只关弹窗、页面仍在：卡里修好的做法（出处：卡里修好并验证过）
