# 自绘层复刻 AlertDialog 时，返回键和点遮罩都走同一个 OnCancelListener 去向

审的是：代码
触发（任一种）：
- 读到：源端 AlertDialog.Builder 或 Dialog 上 setOnCancelListener(...)，cancel 时写偏好、finish 或进入下一步；写错的样子：目标只在遮罩 onClick 里调 cancel 处理，NavDestination 上没有 .onBackPressed(...)（@Entry 页没有 onBackPress()），返回键不推进 cancel 去向
- 读到：源 Activity 的 onBackPressed 只在有未保存改动时弹 AlertDialog；保存框等其他 AlertDialog 打开时返回键先取消它们；写错的样子：页面用页内浮层弹窗，NavDestination 没有 .onBackPressed，或 onBackPressed 只判有无改动、不先关可见弹窗；组件注释称 cancelable 覆盖系统返回，实现只接蒙层 onClick
适用范围：用页内自绘层（Stack 条件渲染的浮层或共享弹窗组件，而不是系统弹窗）复刻安卓 AlertDialog 及其 cancel 行为时
做法：
- 先列出每个对话框的 OnCancelListener 去向，各写成一个 cancel 处理函数
- NavDestination 上写 .onBackPressed(() => { 有自绘对话框显示时关闭最上层并调它的 cancel 处理，return true；再处理源端原有的返回逻辑（如未保存提示），或 return false 放行 })，点遮罩也调同一个处理
- 共享弹窗组件把这份返回键契约写进组件说明，cancelable 注释与实现一致；使用方页面照契约接 onBackPressed
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Dialog#onBackPressed 在 mCancelable 时调 cancel()；cancel() 会回调已注册的 OnCancelListener 再 dismiss()：源端返回键会触发 OnCancelListener（出处：android.app.Dialog#onBackPressed、android.app.Dialog#cancel）
- onBackPressed(callback: () => boolean): NavDestinationAttribute；返回 true 表示重写返回键逻辑，false 回退到上一页：NavDestination 拦截返回键；关掉弹窗后 return true，页面不退出（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onBackPressed；ts-basic-components-navdestination.md，onBackPressed）
- onBackPress?(): void | boolean：同族接口：@Entry 页的返回键回调，返回 true 时由页面自己处理（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CustomComponent.onBackPress）
