# 源端带结果回调的选择器改成 Navigation 打开时，同一改动里接通结果回传

审的是：代码
触发（任一种）：
- 读到：源端用 DialogFragment.show(..., 当前值) { result -> … } 这类带结果回调的选择器，回调里把结果写回控件（setText、刷新预览）；写错的样子：调用页只写 pushPathByName('目标页', new 参数类(当前值))，参数类没有结果回调、也没用 onPop，写回编辑状态的方法没接到任何返回路径
适用范围：把源端带结果回调的选择弹层迁成 ArkUI Navigation 跳转的 NavDestination 时
做法：
- 目标页参数类加一个结果回调字段（如 onSelect?: (value: string) => void），调用页传入 (v) => this.写回方法(v)，目标页在选中处调用它；也可用 pushPathByName(name, param, onPop) 配合目标页 pop(result) 回传
- 调用方拿到结果后写入当前编辑状态并刷新预览；对照源端回调里的每个写回动作（setText、刷新预览等）都要有实现
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 参数类增加 onSelect，编辑页传入 (text) => this.写回方法(text)，目标页的选中处理里调用：修复后的回传写法（出处：卡里修好并验证过）
- pushPathByName(name: string, param: Object, onPop: Callback<PopInfo>, animated?: boolean): void：NavPathStack 带 onPop 的入栈，下一页返回时回调（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pushPathByName）
- pop(result: Object, animated?: boolean): NavPathInfo | undefined：出栈并调用 onPop 传回处理结果（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pop）
- PopInfo { info: NavPathInfo; result: Object }：onPop 收到的结果在 result 里（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，PopInfo）
- pushDestinationByName(name: string, param: Object, onPop: Callback<PopInfo>, animated?: boolean): Promise<void>：同族接口：NavPathStack.pushDestinationByName 的 onPop 重载（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pushDestinationByName）
- constructor(name: string, param: unknown, onPop?: Callback<PopInfo>, isEntry?: boolean)：同族接口：NavPathInfo 构造带 onPop，配合 pushPath 使用（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathInfo.constructor）
未核实：onPop / pop(result) 回传的写法卡里没有上机验证，验证过的是参数回调；卡里的 target_sdk 是 26.0.0，本机声明是 API 23（与卡里的 compatible_sdk 相同）
