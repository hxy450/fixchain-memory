# 源端每次 new 的对话框，目标端每次调用新建 ComponentContent，只关闭自身

审的是：代码
触发（任一种）：
- 读到：方法里每次 `new MaterialDialog.Builder(…)…build().show()`，对话框由局部变量持有；写错的样子：服务里用单例字段持有 `ComponentContent`，每次新调用前先 dismiss 旧句柄，前一个弹窗被静默关闭、回调永不触发
适用范围：把每次调用都新建的源端对话框迁成 openCustomDialog 自定义弹窗时
做法：
- 每次调用新建 new ComponentContent(uiContext, wrapBuilder(builder), args)，用 getPromptAction().openCustomDialog(content, options) 打开
- 关闭时只 closeCustomDialog(本次的 content)；不设服务级的弹窗字段，不在新调用前关旧弹窗
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- constructor(uiContext: UIContext, builder: WrappedBuilder<[T]>, args: T)：ComponentContent 的构造，每次调用新建一个（出处：鸿蒙 SDK 的 ets/api/arkui/ComponentContent.d.ts，ComponentContent.constructor）
- openCustomDialog<T extends Object>(dialogContent: ComponentContent<T>, options?: promptAction.BaseDialogOptions): Promise<void>：打开以这个 content 为内容的弹窗（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.openCustomDialog）
- closeCustomDialog<T extends Object>(dialogContent: ComponentContent<T>): Promise<void>：同族接口：按 content 关闭对应的那个弹窗（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.closeCustomDialog）
- updateCustomDialog<T extends Object>(dialogContent: ComponentContent<T>, options: promptAction.BaseDialogOptions): Promise<void>：同族接口：按 content 更新对应弹窗的选项（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.updateCustomDialog）
- 每次调用独立 ComponentContent，dismiss 只关自身：返修后保留的写法（出处：卡里修好并验证过）
未核实：卡里目标 SDK 是 6.1.1(24)，签名按本机 API 23 核实
