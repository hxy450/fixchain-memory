# 安卓真弹窗不复用 @Local 可见性加 Stack 遮罩的页面叠层，按原类改用真弹窗 API

审的是：代码
触发（任一种）：
- 读到：安卓端 DialogFragment.show(supportFragmentManager, …)，或 XPopup 的 CenterPopupView / AttachPopupView；写错的样子：目标端把 @Local 的可见性状态置 true 来弹出，在页面树里用 if (this.…) 或 .visibility(…) 条件渲染 Stack + 遮罩组件（常带 .zIndex(…)）
适用范围：为安卓真弹窗在目标端补触发或宿主接线时
做法：
- 先按安卓原类定形态：DialogFragment、CenterPopupView → CustomDialogController 的 .open()（或项目已用的 showCustomDialog）；AttachPopupView → bindPopup 或带锚点偏移的 showCustomDialog
- 现有实现若是 @Local 可见性 + Stack/遮罩的页面叠层，把它当待替换对象，不当 existing dialog 直接复用
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- constructor(value: CustomDialogControllerOptions)；open()；close()：居中类弹窗的承载（出处：鸿蒙 SDK 的 ets/component/custom_dialog_controller.d.ts，CustomDialogController）
- bindPopup(show: boolean, popup: PopupOptions | CustomPopupOptions): T：锚点类气泡的承载（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.bindPopup）
- 页面叠层改成 showCustomDialog 真弹窗，宿主改为 show/dismiss，页面不再持有可见性；锚点类按锚点重算三角位置：修复后遮罩和返回都能关闭的写法（出处：卡里修好并验证过）
