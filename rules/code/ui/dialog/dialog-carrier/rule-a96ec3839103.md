# 安卓底部弹窗迁移时用系统半模态 Sheet 承载，不写成 visible 驱动的页面内全屏 Stack

审的是：代码
触发（任一种）：
- 读到：源弹窗继承 XPopup 的 BottomPopupView 一类底部弹窗基类，或是底部 DialogFragment；映射计划或决策台账写「BottomPopup → showBindSheet / 系统半模态」；写错的样子：目标弹窗是 @Param popupVisible / dialogVisible 驱动的全屏 Stack：自绘半透明遮罩、PanGesture 阈值下拉关闭、宿主传返回信号，在宿主页里内嵌或靠 zIndex 叠加；或仍是 NavDestination 路由页
适用范围：安卓底部弹窗迁成 ArkUI、目标工程已定下（或已有样板）用半模态 Sheet 承载时
做法：
- 弹窗内容写成 @Builder，用 harmony-dialog 的 DialogHelper.showBindSheet（或 bindSheet(isShow, builder, options)）打开；遮罩、返回、下拉关闭交给系统 Sheet，不自绘
- 宿主页只持有弹窗的控制器（打开、关闭、结果回调），删掉 popupVisible 加 Visibility 切换的内嵌组件；对照工程里已验证的 Sheet 样板核对
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- bindSheet(isShow: boolean, builder: CustomBuilder, options?: SheetOptions): T：给组件绑定半模态页，由 isShow 控制显示（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.bindSheet）
- SheetOptions.dragBar?: boolean，@default true；SheetOptions.maskColor?: ResourceColor：拖拽条和遮罩色由 Sheet 自带，不用自绘（出处：鸿蒙 SDK 的 ets/component/common.d.ts，SheetOptions.dragBar、SheetOptions.maskColor）
- 改用 harmony-dialog 的 showBindSheet 承载、宿主改持控制器后，弹窗成为真正的底部弹窗：卡里的修法（出处：卡里修好并验证过）
针对本应用要查的：
- 工程里已验证的 Sheet 样板和弹层映射：目标工程的映射计划、决策台账里底部弹窗那一项，以及已用 showBindSheet 实现的弹窗文件；照样板的调用方式和宿主接线写，映射写的目标 API 原样采用
