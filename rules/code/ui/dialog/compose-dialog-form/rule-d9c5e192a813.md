# 源对话框是 Dialog 独立窗口时，目标走系统弹窗通道；用页内遮罩就隐藏背景无障碍

审的是：代码
触发（任一种）：
- 读到：源端 Dialog(onDismissRequest, properties) / AlertDialog；规格把它映射为 @CustomDialog，或共享对话框组件头注要求经 openCustomDialog 打开；写错的样子：目标改成页内 Stack 遮罩加对话框，显示期间背景没有 .accessibilityLevel('no-hide-descendants')，读屏仍能遍历背景；或把规格改写成「页内 Stack overlay」
适用范围：把源端独立窗口的模态对话框迁成 ArkUI 时
做法：
- 按规格和共享组件约定用 UIContext 的 showAlertDialog 或 getPromptAction().openCustomDialog(content) 打开；别页的页内遮罩先例不能替代规格映射
- 确需页内 Stack 遮罩时：显示期间背景内容写 .accessibilityLevel(show ? 'no-hide-descendants' : 'auto')，处理返回键关闭，在报告里说明偏离，不改写规格
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- openCustomDialog<T extends Object>(dialogContent: ComponentContent<T>, options?: promptAction.BaseDialogOptions): Promise<void>：系统弹窗通道打开自定义对话框（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.openCustomDialog）
- showAlertDialog(options: AlertDialogParamWithConfirm | AlertDialogParamWithButtons | AlertDialogParamWithOptions): void：系统警告对话框（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.showAlertDialog）
- accessibilityLevel 取 "no-hide-descendants" 时组件和子组件都不被无障碍服务识别：页内遮罩显示期间用来隐藏背景（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.accessibilityLevel）
- 对话框显示期间背景加 accessibilityLevel('no-hide-descendants')：修复后读屏只遍历对话框（出处：卡里修好并验证过）
