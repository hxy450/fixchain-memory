# 源端弹窗改成页内 Stack 浮层时，NavDestination 上加 onBackPressed 逐层关闭

审的是：代码
触发（任一种）：
- 读到：源端 Compose Dialog / AlertDialog / ExposedDropdownMenu / ModalBottomSheet 带 onDismissRequest，关闭只关弹窗、留在当前页；写错的样子：目标改成 Stack 里 if 渲染的遮罩浮层，所在 NavDestination 没有 .onBackPressed（或照搬了别页没处理返回键的覆盖层）
- 读到：源页有 Dialog / ModalBottomSheet，另有 `BackHandler(…)` 处理行内编辑器和未保存门禁；写错的样子：`onBackPressed` 只翻译了 BackHandler 的分支，没检查对话框、底部弹窗是否打开
适用范围：源端弹窗、底部弹窗或下拉改成 Navigation 栈里 NavDestination 的页内覆盖层时
做法：
- 列出本页可叠加的层（对话框、底部弹窗、下拉、行内编辑器），各对应一个 @State；.onBackPressed 里从上到下判断，最上层可见的只关它并 return true，都关了才走门禁或出栈，没有门禁时 return false；拦截条件与渲染条件一致
- 源端 onDismissRequest 同时对应返回和点外部（DialogProperties 默认）：遮罩 .onClick 和 onBackPressed 分支调同一个关闭方法
- 自检：有遮罩浮层就要有这样的 onBackPressed；每个覆盖层状态各走一遍分支，不会调门禁、保存、丢弃或 pop()；复用别页覆盖层先看它处理了返回键没有
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onBackPressed(callback: () => boolean): NavDestinationAttribute：NavDestination 的返回键回调（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onBackPressed）
- 返回 true 表示重写返回键逻辑，返回 false 表示回退到上一个页面：关了浮层就返回 true，否则页面也跟着退（出处：ts-basic-components-navdestination.md，onBackPressed）
- 当与 Navigation 绑定的导航控制器中存在内容时，此回调生效：页面要在 Navigation 栈里，回调才会被调用（出处：ts-basic-components-navdestination.md，onBackPressed）
- onBackPress?(): void | boolean：同族接口：@Entry 自定义组件（router 页面）的返回键回调，true 表示页面自己处理返回（出处：鸿蒙 SDK 的 ets/component/common.d.ts，BaseCustomComponent.onBackPress）
- 修复前浮层打开时按 Back 弹出整页或退出应用；宿主页加上逐层关闭的 onBackPressed 后只关浮层：有浮层时关最上层并返回 true，否则返回 false（出处：卡里修好并验证过）
- 先关 sheet、再清 activeDialog，之后才是行内编辑器和未保存门禁：带门禁的页面修复后的分支顺序（出处：卡里修好并验证过）
