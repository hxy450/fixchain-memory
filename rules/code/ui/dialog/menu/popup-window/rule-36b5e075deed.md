# 同一筛选栏里 showAsDropDown 的快捷项做原位下拉，只有整屏弹出的“更多筛选”做独立面板

审的是：代码
触发（任一种）：
- 读到：同一筛选栏有几种入口：快捷项点击时先把置顶筛选栏设为可见、setSelectionFromTop 把列表滚到筛选位置，再 showAsDropDown 在置顶栏下展开；“更多筛选”走另一个弹窗的 show(...) 整屏弹出；写错的样子：快捷项和“更多筛选”调用同一个打开面板的方法，build() 里条件成立时用筛选面板整块替换列表（标题也改成筛选），置顶栏和背景列表不见了
适用范围：安卓同一筛选栏里混有 showAsDropDown 锚定下拉和整屏弹窗两种入口，迁成 ArkUI 时
做法：
- 按源端每个入口的 show 方式分开实现：showAsDropDown 锚定的快捷项用 Stack 叠加，列表之上固定置顶筛选栏，点击时在栏下原位展开对应的下拉面板，背景列表保留
- 只有源端用整屏弹窗 show(...) 打开的“更多筛选”才做独立的全屏面板
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- showAsDropDown(View anchor, int xoff, int yoff)：弹窗锚在 anchor 的左下角：源端快捷项的下拉是锚定在置顶栏下的原位弹出，不是换页（出处：android.widget.PopupWindow#showAsDropDown）
- Stack 里列表上方固定筛选栏，快捷项原位展开下拉面板，仅“更多筛选”走全屏面板；改后与安卓真机一致：返修后的结构（出处：卡里修好并验证过）
针对本应用要查的：
- 每个筛选入口用的是哪种弹出方式：源工程 Java/Kotlin 里筛选入口的点击监听；调 showAsDropDown 的是锚定下拉；调整屏弹窗 show(...) 或 showAtLocation 铺满的是独立面板；点击时有没有先显示置顶栏、滚动列表也一并记下
