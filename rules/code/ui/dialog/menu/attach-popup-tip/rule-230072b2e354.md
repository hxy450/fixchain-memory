# 源端弹窗要求锚点 isShown 且一次性标记未写时，目标照搬两个条件并持久化标记

审的是：代码
触发（任一种）：
- 读到：弹出前判断锚点 `isShown` 和一次性「已显示」标记，弹窗的 onDismiss 里写入这个标记；写错的样子：目标只用页面里的 `@State` 布尔量控制提示显隐，关闭时不写持久化存储；或者显示条件里缺了锚点可见这一项
适用范围：安卓一次性提示弹窗（只在锚点可见、标记未写时弹出，关闭时写标记）迁成 ArkUI 时
做法：
- 显示条件写成源端各项的合取：锚点组件在目标端可见（与源端 isShown 的条件一致）且持久化的一次性标记为未显示
- 关闭回调里把标记写回持久化存储（preferences 的 putSync(key, true) 后 flush()），进入页面时先 getSync(key, false) 读出再决定是否显示，不只放在 @State 里
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- View.isShown() 为真要求这个视图和它所有祖先都是 VISIBLE：源端锚点可见条件的含义，目标端要对应到锚点组件及其外层都显示（出处：android.view.View#isShown）
- function getPreferencesSync(context: Context, options: Options): Preferences：取得 preferences 实例（出处：鸿蒙 SDK 的 ets/api/@ohos.data.preferences.d.ts，preferences.getPreferencesSync）
- getSync(key: string, defValue: ValueType): ValueType：读标记，没有时返回 defValue（出处：鸿蒙 SDK 的 ets/api/@ohos.data.preferences.d.ts，Preferences.getSync）
- putSync(key: string, value: ValueType): void；flush(): Promise<void>：putSync 只写进内存中的实例，要调 flush 才存到文件（出处：鸿蒙 SDK 的 ets/api/@ohos.data.preferences.d.ts，Preferences.putSync、Preferences.flush）
- 日视图里的临时状态未持久化，是提示没有按「首次」出现的原因之一：只用页面状态会出的错（出处：卡里修好并验证过）
针对本应用要查的：
- 源端一次性标记存在哪、key 是什么：源工程里弹窗 onDismiss 回调写标记的那段代码，以及读同一个 key 的工具类；读出存储方式和 key 名；目标工程已有持久化封装的就用它写同名 key，没有的用 preferences
- 目标端锚点的可见性由哪个状态驱动：目标工程里锚点组件的 .visibility(...) 或外层 if 条件；顺着状态变量找到赋值处，确认在源端锚点可见的情形下它会变为可见；从不变为可见的先修驱动链
