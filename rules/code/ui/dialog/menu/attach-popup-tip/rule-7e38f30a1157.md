# 子页逻辑依赖父页提示是否显示时，经参数或回调读父页状态，不用子页私有副本

审的是：代码
触发（任一种）：
- 读到：提示由父页的锚点控件承载（atView 取自 parentFragment），子 Fragment 里另有逻辑在提示显示时跳过（如显示时不计数）；写错的样子：子页组件里自建一个表示提示是否显示的私有 `@State` 布尔量，别的逻辑以它作 if (…) return 守卫
适用范围：子页（子组件）里新增依赖某个提示显示状态的逻辑，而提示的宿主在父页时
做法：
- 先确认提示状态归哪一页；归父页时，状态只在父页定义为 @State，子组件用 @Prop（单向）或 @Link（双向）接收，子页逻辑读这个成员
- 子页要通知父页时，父页给子组件传一个函数类型的成员作回调，子页调用它；不在子页另存一份提示状态
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- @Prop：子组件变量和父组件建立单向同步：子页只读父页的提示状态时用（出处：arkts-prop.md，@Prop装饰器：父子单向同步；鸿蒙 SDK 的 ets/component/common.d.ts，Prop）
- @Link：父组件状态变量与子组件 @Link 双向同步，一方改变另一方同步更新：子页也要改父页的提示状态时用（出处：arkts-link.md，装饰器使用规则说明；鸿蒙 SDK 的 ets/component/common.d.ts，Link）
- 删掉子页的私有提示状态和守卫、在宿主页新建锚定锚点的提示后，问题消失：卡里的修法（出处：卡里修好并验证过）
