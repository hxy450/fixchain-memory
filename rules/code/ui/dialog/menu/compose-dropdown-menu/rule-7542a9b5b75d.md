# cascade 子菜单在同一容器内原地切层，不并排多列、不平铺；bindMenu 承载时截断触摸冒泡

审的是：代码
触发（任一种）：
- 读到：me.saket.cascade 的 CascadeDropdownMenu，或带 children 的菜单项在同一菜单内切到子层；写错的样子：子菜单写成 Row 里并排的多列面板，或把 children 平铺成同级 MenuItem / Select 选项
- 读到：me.saket.cascade 的 CascadeDropdownMenu 迁到 .bindMenu(CustomBuilder) 的自定义内容里；写错的样子：子菜单入口和返回 Header 上没有 onTouch 截断冒泡，轻点子菜单入口时整个菜单被关掉
适用范围：把 cascade 级联菜单（含居中级联）迁成 ArkUI 时
做法：
- 按源库语义在同一容器里原地替换当前层：点带 children 的项进入子层，子层顶部放返回 Header 回到上一层；返回键先退子层
- 用 bindMenu 自定义内容承载级联时，在子菜单入口和 Header 上写 .onTouch((e: TouchEvent) => { e.stopPropagation() })，不让点击冒泡关掉菜单
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- bindMenu 自定义内容轻点即关；在子菜单入口上 onTouch 里 stopPropagation 后可原地切层：改成 bindMenu 后新出现的平台行为和它的解法（出处：卡里修好并验证过）
- onTouch(event: (event: TouchEvent) => void): T：触摸事件回调（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onTouch）
- TouchEvent.stopPropagation: () => void：阻止事件向上或向下冒泡（出处：鸿蒙 SDK 的 ets/component/common.d.ts，TouchEvent.stopPropagation）
未核实：卡里的环境是 API 24（6.1.1），本机用 API 23 的声明核实
