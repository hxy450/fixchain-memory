# openMenu 是 PromptAction 成员，经 getPromptAction() 调用

审的是：代码
触发（任一种）：
- 读到：源端长按弹出菜单（PopupMenu、showContextMenu）；grep @ohos.arkui.UIContext.d.ts 只看到 openMenu / closeMenu 的声明行；写错的样子：写成 this.getUIContext().openMenu(...) / uiContext.closeMenu(...)，编译报 UIContext 上不存在
适用范围：按 grep 到的声明行写 UIContext 相关调用时
做法：
- grep 命中声明行后向上找最近的 class / interface，确认所属类型；这个文件里有 PromptAction 等多个类，不按文件名推定为 UIContext 方法
- PromptAction 的成员经 this.getUIContext().getPromptAction() 取对象再调用；卡里修好用的是同类的 openCustomDialog / closeCustomDialog，且 BaseDialogOptions 不写 title
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- openMenu<T extends Object>(content: ComponentContent<T>, target: TargetInfo, options?: MenuOptions): Promise<void>：声明在 export class PromptAction 内，不是 UIContext 的成员（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.openMenu）
- getPromptAction(): PromptAction：UIContext 上取 PromptAction 的方法（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.getPromptAction）
- openCustomDialog<T extends Object>(dialogContent: ComponentContent<T>, options?: promptAction.BaseDialogOptions): Promise<void>：同在 PromptAction 里，卡里修复所用（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.openCustomDialog）
- closeMenu<T extends Object>(content: ComponentContent<T>): Promise<void>：同在 PromptAction 里，关菜单（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.closeMenu）
