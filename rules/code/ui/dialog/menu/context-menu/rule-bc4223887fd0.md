# 源上下文菜单由菜单 XML 膨胀再按判据 setVisible 时，目标按 XML 顺序并调已移植的判据

审的是：代码
触发（任一种）：
- 读到：onCreateContextMenu 里 MenuInflater.inflate 一份菜单 XML，再调一个按条目状态逐项 MenuItem.setVisible 的判据函数；写错的样子：目标共享菜单组件用自写的 `switch` 定可见项（注释自称简化），条目顺序和源菜单 XML 里 `<item>` 的先后不同
适用范围：源端上下文菜单的项和可见性来自菜单 XML 加判据函数，目标写共享菜单组件时
做法：
- 菜单组件直接调用已移植的那个可见性判据函数决定每项显示与否，不另写简化判据
- 输出顺序照菜单 XML 里 `<item>` 的先后；读菜单 XML 要整读或保留 android:visible 等属性，不只摘 id 和 title
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- MenuBuilder.findInsertIndex：从尾部找第一个 getOrdering() <= ordering 的项插在它后面：没写 android:orderInCategory 时各项 ordering 相同，菜单顺序就是 XML 里的先后（出处：com.android.internal.view.menu.MenuBuilder#findInsertIndex）
- MenuItem setVisible(boolean visible)：源端判据函数逐项开关可见性用的接口（出处：android.view.MenuItem#setVisible）
- 共享菜单改调已移植的可见性函数、按 XML 顺序输出：修复后保留的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 菜单项的先后和默认可见性：源工程 res/menu/ 下被 onCreateContextMenu inflate 的那份菜单 XML；整读文件，按 <item> 出现的先后记顺序，同时记下每项的 android:visible、android:orderInCategory（写了 orderInCategory 的按它的值排）
