# 按源码重写隐私弹窗时，源配置里每个协议链接回调在目标都要有可点击入口

审的是：代码
触发（任一种）：
- 读到：源码隐私弹窗配置里有 goServiceLink / goPrivacyLink 这类回调，调用 WebView 页的启动方法打开协议 URL；写错的样子：目标弹窗里协议名称只是没有 .onClick 的 Text，或者替换正文文案时把协议名称连同入口一起删掉；整页没有 pushPathByName 到 WebView 页的跳转
适用范围：实现或收口阶段，目标端自绘隐私遮罩/弹窗，按源码重写正文或操作区时
做法：
- 重写前列出源配置的全部可交互回调，和目标代码里的 onClick 逐项对上；替换文案时不删还没有实现的入口
- 每个协议入口写成可点击的 Text(...).onClick(...)：从资源取对应的协议 URL，再 pathStack.pushPathByName('<WebView 页名>', 带 URL 的参数)；两个入口可以放在「已阅读并同意《…》及《…》」一行里
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- pushPathByName(name: string, param: unknown, animated?: boolean): void：NavPathStack 按名字推入 NavDestination，param 传给目标页，animated 默认 true（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pushPathByName）
- 两个可点击 Text 共用一个打开协议的方法：取协议 URL 资源后 pushPathByName 到 WebView 页：返修后的写法，观察截止时保留（出处：卡里修好并验证过）
- pushDestinationByName(name: string, param: Object, animated?: boolean): Promise<void>：同族接口：按名字推入并返回 Promise，可捕获 100005、100006 等错误（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pushDestinationByName）
- pushPath(info: NavPathInfo, animated?: boolean): void：同族接口：用 NavPathInfo 推入（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pushPath）
针对本应用要查的：
- WebView 页在目标工程里注册的名字和它接收的参数：目标工程的路由表（route_map.json 或 Navigation 的 navDestination 构建函数、pageMap）和 WebView 页的参数类型；用注册名作 pushPathByName 的 name，按参数类型传协议 URL
