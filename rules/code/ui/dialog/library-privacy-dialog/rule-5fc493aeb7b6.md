# 只有外部模板的配置参数时，不把配置条目展开成可见分区，先取 AAR 布局或截图

审的是：代码
触发（任一种）：
- 读到：源端只调用外部库模板方法并传入 Config 对象（标题、条目数组、图标、勾选图、链接色、链接回调），工程里没有模板的 layout；写错的样子：目标页把 Config 里的条目数组展开成标题下的独立摘要分区，沿用两个等宽 Button，按钮文案是源码里没有的自拟文字
适用范围：迁移由第三方库或 SDK 模板渲染的弹窗、页面时
做法：
- 先在源工程的构建脚本里定位该库坐标，解包对应 AAR 的 res/layout 与 res/values 字符串，或请求安卓实机截图
- 按取到的分区、文案和操作区结构实现；不把配置字段直接展开成可见分区，也不自拟按钮文案
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 配置条目不作首屏独立分区；面板有问候、说明、类别行和文内协议链接，操作区是灰色拒绝文字加黑底主操作（勾选图标 + 文案）：以安卓截图为基准重构后的结构，视觉判定不再报结构差异（出处：卡里修好并验证过）
针对本应用要查的：
- 外部模板的实际分区、控件顺序和操作区结构：Gradle 缓存 caches 下解包的 aar：transforms-<N>/<hash>/transformed/<artifact>-<version>/res/layout/，按模板方法名或模板编号找对应的布局 XML；按布局 XML 的层级读出分区和控件顺序；同一库缓存了几个版本时按源工程依赖的版本取
来源：1 张卡，1 个应用
