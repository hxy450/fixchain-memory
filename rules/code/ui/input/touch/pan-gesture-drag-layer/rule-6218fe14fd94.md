# 带列表的弹窗改成 bindSheet 时，顶部下拉门禁映射到 nestedScroll 和 onWillDismiss

审的是：代码
触发（任一种）：
- 读到：旧弹窗的 PanGesture 在 onActionStart 记下列表是否在顶部（currentOffset().yOffset <= 0），在顶部才跟手下拉、过阈值才关、否则 animateTo 回弹；或参考模板没有滚动列表、onWillDismiss 无条件 action.dismiss()；写错的样子：新 SheetOptions 照搬无条件 onWillDismiss: (action) => action.dismiss()，删掉 PanGesture 和顶部判断，内部 List 没写 .nestedScroll，也没注册 onWillSpringBackWhenDismiss
适用范围：把含可滚动 List 的自绘底部弹窗替换成系统半模态（bindSheet / showBindSheet）时
做法：
- 先列出旧实现的手势门禁（只在列表顶部才允许下拉关闭、关闭阈值、未达阈值回弹）；内部 List 写 .nestedScroll({ scrollForward: NestedScrollMode.SELF_FIRST, scrollBackward: NestedScrollMode.SELF_FIRST })
- 手势开始时记下列表是否在顶部；onWillDismiss 里 reason 为 DismissReason.SLIDE_DOWN 时按这次手势起点决定：在顶部才 action.dismiss()（或直接关闭半模态），否则不关
- 注册 onWillSpringBackWhenDismiss，只在拦截时调用 action.springBack()；参考模板没有滚动列表时，它的无条件 dismiss 不能直接套用
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- SheetOptions.onWillDismiss?: Callback<DismissSheetAction>；注册后交互关闭不再立即生效，由回调决定是否调用 dismiss：按手势起点放行或拦截的入口（出处：鸿蒙 SDK 的 ets/component/common.d.ts，SheetOptions.onWillDismiss）
- DismissSheetAction { dismiss: Callback<void>; reason: DismissReason }，DismissReason.SLIDE_DOWN = 3：回调里区分下拉关闭的依据（出处：鸿蒙 SDK 的 ets/component/common.d.ts，DismissSheetAction、DismissReason.SLIDE_DOWN）
- SheetOptions.onWillSpringBackWhenDismiss?: Callback<SpringBackAction>；没注册而注册了 onWillDismiss 时，下拉后半模态先回弹，再按回调决定留下或关闭：不注册就会出现关闭前先上弹（出处：鸿蒙 SDK 的 ets/component/common.d.ts，SheetOptions.onWillSpringBackWhenDismiss、SpringBackAction.springBack）
- nestedScroll(value: NestedScrollOptions): ListAttribute；NestedScrollOptions { scrollForward, scrollBackward: NestedScrollMode }；SELF_FIRST 为自身优先滚动：列表先滚到顶，再把下拉交给半模态（出处：鸿蒙 SDK 的 ets/component/list.d.ts，ListAttribute.nestedScroll；ets/component/enums.d.ts，NestedScrollMode.SELF_FIRST）
- nestedScroll(value: NestedScrollOptions): ScrollAttribute：同族接口：面板里是 Scroll 时同样配置（出处：鸿蒙 SDK 的 ets/component/scroll.d.ts，ScrollAttribute.nestedScroll）
- nestedScroll(value: NestedScrollOptions): GridAttribute：同族接口：面板里是 Grid 时同样配置（出处：鸿蒙 SDK 的 ets/component/grid.d.ts，GridAttribute.nestedScroll）
- currentOffset(): OffsetResult：手势开始时用 yOffset <= 0 判断列表是否在顶部（出处：鸿蒙 SDK 的 ets/component/scroll.d.ts，Scroller.currentOffset）
- List 配 nestedScroll SELF_FIRST、按手势起点放行、只在拦截时 springBack、允许时直接关闭后，顶部下拉关闭和中部快速回滑都正常：三项组合是返修后核对过的写法（出处：卡里修好并验证过）
未核实：卡里用的是第三方库的 showBindSheet，库对 SheetOptions 的透传方式没核实；本机按 API 23 的 SheetOptions 声明核实
