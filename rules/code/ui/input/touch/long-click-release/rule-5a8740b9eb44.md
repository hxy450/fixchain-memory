# 源端快门有点击和长按两条入口时，目标快门同时挂 onClick 和 LongPressGesture 及松手回调

审的是：代码
触发（任一种）：
- 读到：源端快门 View 同时有 setOnClickListener 和 setOnLongClickListener，触摸监听里 MotionEvent.ACTION_UP 时停止连拍；写错的样子：目标快门组件只挂了 .onClick(...)，没有 LongPressGesture，也没有松手停止的回调
适用范围：组装快门等控件、切片计划写着「含 ACxx 触发侧」时
做法：
- 对照切片计划的「含 ACxx 触发侧」和被调文件头的入口说明，逐个补齐点击、长按、松手回调：.onClick 走单拍，.gesture(LongPressGesture().onAction(开始连拍).onActionEnd(停止连拍))
- 长按要按模式、分辨率、RAW、偏好门控时，用 onGestureJudgeBegin 在不满足时返回 GestureJudgeResult.REJECT
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- LongPressGesture(value?: { fingers?: number; repeat?: boolean; duration?: number })：长按手势，duration 是最短按住时长（毫秒）（出处：鸿蒙 SDK 的 ets/component/gesture.d.ts，LongPressGestureInterface）
- onActionEnd(event: (event: GestureEvent) => void): LongPressGestureInterface：长按识别成功后手指抬起时回调，对应源端 ACTION_UP 停止（出处：鸿蒙 SDK 的 ets/component/gesture.d.ts，LongPressGestureInterface.onActionEnd）
- onGestureJudgeBegin(callback: (gestureInfo: GestureInfo, event: BaseGestureEvent) => GestureJudgeResult): T；GestureJudgeResult.CONTINUE = 0、REJECT = 1：手势识别前的门控（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onGestureJudgeBegin；ets/component/gesture.d.ts，GestureJudgeResult）
- setOnLongClickListener：注册按住视图时的回调：源端长按入口（出处：android.view.View#setOnLongClickListener）
- 快门加 onGestureJudgeBegin 和 LongPressGesture、VM 门控开始连拍后，长按连拍、松手停止正常：修复后的观察（出处：卡里修好并验证过）
未核实：卡里环境是 API 24，本机按 API 23 的声明核实
