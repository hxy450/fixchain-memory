# 多按钮 onTouch 判首末指不用 touches.length，改用本控件的手指 id 集合

审的是：代码
触发（任一种）：
- 读到：安卓源里多个兄弟 View 各自 setOnTouchListener，按 getAction() 的 ACTION_DOWN / ACTION_UP 驱动按住-释放（setPressed、开始或停止动作）；写错的样子：目标里每个按钮的 .onTouch 用 event.touches.length === 1（或 > 1 就 return）作 TouchType.Down / TouchType.Up 的门，注释写着只跟首指、丢掉非首指 Down 和非末指 Up
适用范围：源端多个控件各自监听触摸且默认分指（targetSdkVersion ≥ 11、没设 splitMotionEvents=false），目标每个按住-释放按钮各挂 ArkUI .onTouch 时
不适用的情形：只有单个视图独占全部手指（如整屏只有一个视图接收滑动）时，按 touches.length 过滤才成立
做法：
- 每个按钮持有一个手指 id 集合；TouchType.Down 时取 event.changedTouches[0].id，集合为空才进入按下，再把 id 加进集合
- TouchType.Up 时从集合删掉 changedTouches[0].id，删后集合为空才抬起；TouchType.Cancel 清空集合并抬起
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onTouch(event: (event: TouchEvent) => void): T：组件的触摸回调（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onTouch）
- touches: TouchObject[]：全部屏幕触点（多指）的信息，包含落在别的按钮上的手指（出处：鸿蒙 SDK 的 ets/component/common.d.ts，TouchEvent.touches；ts-universal-events-touch.md，TouchEvent对象说明）
- changedTouches: TouchObject[]：发生变化而产生这次事件的手指，取 [0].id 作本次手指（出处：鸿蒙 SDK 的 ets/component/common.d.ts，TouchEvent.changedTouches）
- id: number：TouchObject 上的手指唯一标识（出处：鸿蒙 SDK 的 ets/component/common.d.ts，TouchObject.id）
- TouchType.Down、TouchType.Up、TouchType.Move、TouchType.Cancel：按下、抬起、移动、取消四种触摸类型（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，TouchType）
- 两指跨按钮注入时，旧写法下第二个按钮按下时 touches.length=2 被丢、第一个按钮的抬起也被丢而卡按；改成控件内手指集合后两者各自按下抬起：改法的效果（出处：卡里修好并验证过）
