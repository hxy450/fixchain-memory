# ArkUI 逐指触摸先折成 MotionEvent 序列，再按源端顺序先喂缩放检测器、后喂手势检测器

审的是：代码
触发（任一种）：
- 读到：源端 onTouchEvent 里先 scaleGestureDetector.onTouchEvent(event)、再 gestureDetector.onTouchEvent(event)，之后才走自己的 ACTION_MOVE 分支；写错的样子：目标 onTouch 里把 TouchEvent 直接分给各自的检测逻辑，没有折成 DOWN / POINTER_DOWN / MOVE / POINTER_UP / UP 序列，或喂检测器的顺序和源端不同
适用范围：在 ArkUI onTouch 上复刻源端「先缩放检测器、再手势检测器、再自己的分支」这一触摸处理链时
做法：
- 按指针折叠：首指 TouchType.Down 记为 DOWN，其余手指的 Down 记为 POINTER_DOWN；TouchType.Move 记为 MOVE，带 event.touches 里全部指针；非末指 Up 记为 POINTER_UP，末指 Up 记为 UP
- 每个折出来的事件照源端顺序先喂移植的缩放检测器、再喂手势检测器，最后走源端自己的 ACTION_MOVE 分支
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onTouch(event: (event: TouchEvent) => void): T：目标拿触摸事件的入口（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onTouch）
- TouchEvent.touches: TouchObject[]（全部手指）；TouchEvent.changedTouches: TouchObject[]（这次变化的手指）：折叠时 MOVE 用 touches 带全部指针，按 changedTouches 判断是哪根手指按下或抬起（出处：鸿蒙 SDK 的 ets/component/common.d.ts，TouchEvent.touches / TouchEvent.changedTouches）
- TouchType { Down, Up, Move, Cancel }：目标触摸类型，Cancel 对应 ACTION_CANCEL（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，TouchType）
- Applications should pass a complete and consistent event stream to this method：检测器要求从 ACTION_DOWN 到 ACTION_UP/ACTION_CANCEL 的完整一致事件流（出处：android.view.ScaleGestureDetector#onTouchEvent）
