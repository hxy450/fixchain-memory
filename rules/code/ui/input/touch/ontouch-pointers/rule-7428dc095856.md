# 预览 View 的 onTouchEvent 分派手势时，目标要接 .onTouch 和 PinchGesture

审的是：代码
触发（任一种）：
- 读到：源端预览 View（SurfaceView 子类等）的 onTouchEvent 直接 return 给另一个类的触摸方法，再由 GestureDetector / ScaleGestureDetector 分派到单击对焦、onDoubleTap、ScaleGestureDetector 的 onScale；写错的样子：目标只写了单击、缩放等内层处理函数，没有入口分派；预览宿主 XComponent 上只有 .onLoad / .onDestroy，没有 .onTouch 和 PinchGesture，这些处理函数在 UI 文件里没有调用方
适用范围：把安卓预览表面的触摸手势（点按、双击、捏合）迁到 ArkUI XComponent 预览宿主时
做法：
- 从源端 View.onTouchEvent 起逐层对照目标调用链：XComponent 上接 .onTouch((e: TouchEvent) => …) 和 .parallelGesture(PinchGesture().onActionUpdate(…))，都交给一个分派器（复刻 GestureDetector / ScaleGestureDetector 的判定阈值），再由分派器调单击、双击、缩放等处理函数
- 触点坐标按 surface 在组件里的矩形换算后再交给处理函数（TouchObject.x / y 是 vp，源端 MotionEvent.getX / getY 是 px）
- 收尾前对每个处理函数在 UI 文件里搜调用方；没有调用方的不算完成，不按对接点个数计完成
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onTouch(event: (event: TouchEvent) => void): T：通用触摸事件；XComponentAttribute 继承 CommonMethod，XComponent 上可直接接（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onTouch；ets/component/xcomponent.d.ts，XComponentAttribute）
- TouchObject 的 x、y 是相对事件响应组件左上角的坐标，单位 vp：目标触点坐标的单位（出处：ts-universal-events-touch.md，TouchObject）
- MotionEvent.getX(int) / getY(int) 的单位是 px（可带小数）：源端处理函数按 px 写，接目标触点时要换算（出处：android.view.MotionEvent#getX）
- PinchGesture(value?: { fingers?: number; distance?: number })；fingers 默认 2，distance 默认 5，单位 vp：捏合手势的构造，回调里用 GestureEvent.scale 取缩放比（出处：鸿蒙 SDK 的 ets/component/gesture.d.ts，PinchGestureInterface；ts-basic-gestures-pinchgesture.md，接口）
- parallelGesture(gesture: GestureType, mask?: GestureMask): T：绑定可与组件内部手势同时触发的手势，和 onTouch 并存（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.parallelGesture）
- gesture(gesture: GestureType, mask?: GestureMask): T：同族接口：CommonMethod 的普通手势绑定（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.gesture）
- priorityGesture(gesture: GestureType, mask?: GestureMask): T：同族接口：CommonMethod 的优先识别手势绑定（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.priorityGesture）
- DOUBLE_TAP_TIMEOUT = 300（ms，第一次抬起到第二次按下）；DOUBLE_TAP_SLOP = 100（dp，两次按下的距离）：分派器复刻 GestureDetector 双击判定时用的框架默认阈值（出处：android.view.ViewConfiguration，DOUBLE_TAP_TIMEOUT、DOUBLE_TAP_SLOP）
未核实：卡里环境是 HarmonyOS API 24，本机按 API 23 核实；GestureEvent.scale 是相对手势开始的累计比例还是相对上一事件，声明没写明；ScaleGestureDetector.getScaleFactor 是相对上一事件的比例，接缩放处理函数前要核对
