# 桥接源端同名方法而目标缺失时，读源方法正文实现，不用 toggle 或恒 false 近似

审的是：代码
触发（任一种）：
- 读到：目标端 `interface` 的注释写明其中方法对应源端同名方法（如菜单命令、上下键处理，返回 true 表示已消费），而目标控制器里没有这些方法；写错的样子：接线时把这类方法接到现成的 toggle 方法上，或让返回「是否已消费」的方法恒 `return false`，注释还自述会改变行为
适用范围：接线阶段要把目标端接口接到源端同名方法、目标实现里缺这些方法时
做法：
- 先读源方法正文，按它的分支实现等价方法（如面板未开时打开、已开时进入菜单命令；处理了按键才返回 true）；做不到的回报缺口，不用近似静默合入
针对本应用要查的：
- 源方法的实际行为：源工程里这个同名方法的正文；读出它的分支和返回值含义，逐支写进目标方法
未核实：近似接线的后果（面板打开时按菜单键反而关掉面板、上下键回落到别的功能）是卡里的分析，没写上机验证过
