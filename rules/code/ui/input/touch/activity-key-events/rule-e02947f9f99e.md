# Activity 级 onKeyDown 迁成 onKeyEvent 时，页内要有可获焦组件让焦点链经过本页

审的是：代码
触发（任一种）：
- 读到：Activity 上覆写 onKeyDown(int keyCode, KeyEvent event)，处理 KEYCODE_DPAD_* 方向键或 Ctrl 组合键（如 KEYCODE_Z 加 isCtrlPressed()）；写错的样子：目标页把 onKeyEvent 挂在 NavDestination 或 @Entry 根节点，但 build 里没有 Button、TextInput 或显式 .focusable(true) 的组件；按键到达窗口后 DispatchKeyEventCallback consumed: 0，页面回调不触发
适用范围：把安卓 Activity 级按键处理迁到 ArkUI 页面（NavDestination 或 @Entry 页）时
做法：
- onKeyEvent 挂在 NavDestination（或 @Entry 根节点）上处理按键，同时让页内至少有一个可获焦组件（源端按键控件的对应件设 .focusable(true)），按键从获焦的叶子沿焦点链冒泡到根节点
- 写完在 build 里检查本页有没有 Button、TextInput 或显式 focusable(true) 的控件，没有就补上
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onKeyEvent(event: (event: KeyEvent) => void): T；onKeyEvent(event: Callback<KeyEvent, boolean>): T（@since 15）：组件的按键回调（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onKeyEvent）
- 绑定 onKeyEvent 的组件获焦后，按键动作触发该回调：回调只在焦点链经过该组件时触发（出处：ts-universal-events-key.md，onKeyEvent）
- 按键事件先找完整的节点获焦链，从叶子节点到根节点逐一发送，子组件不处理就冒泡给父组件：页内没有获焦的叶子时，挂在根节点的回调也收不到（出处：arkts-interaction-development-guide-keyboard.md，按键事件数据流）
- Button、TextInput 这类有默认交互逻辑的组件默认可获焦；Text、Image 等默认不可获焦：按钮转成 Image 后页内可能就没有可获焦组件了（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.focusable）
- Activity.onKeyDown 在 Activity 内的 View 都没处理按键时调用：安卓有 Activity 兜底，ArkUI 没有，按键只沿焦点链派发（出处：android.app.Activity#onKeyDown）
- onKeyEvent 留在 NavDestination，给按钮对应的 Image 加 focusable(true) 后，方向键和 Ctrl+Z 在设备上验证通过：验证过的写法（出处：卡里修好并验证过）
