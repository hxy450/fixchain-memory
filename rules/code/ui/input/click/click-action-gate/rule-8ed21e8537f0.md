# 源端调用接口前有省份或用户类型门控时，目标展平调用链也保留同样的条件分支

审的是：代码
触发（任一种）：
- 读到：源端在发起某个接口调用前用 `if (...)` 判断条件（地区是否在某个省份列表里、个人新学员这类用户标志），满足才调用，否则走重置提示或直接跳转；写错的样子：目标端把这条链展平成共享函数后无条件 `await` 该接口，接口返回 null 时静默 return；宿主对象上也没有源端判断所需的用户标志
适用范围：把源端分散在适配器、点击处理里的前置调用链迁成目标端的共享调用链时，链上每一个带条件的接口调用
做法：
- 照源端补回门控：同样的条件（地区列表常量、用户标志）满足才调用该接口，否则按源端走后续分支（重置提示、直接进入下一页）；地区列表照源端搬成常量，用户标志加到调用链的宿主对象上并由各调用方写入
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 按源码加回门控后，条件不满足的账号不再调用该接口，直接进入后续分支，与源端一致：修复后的形态（出处：卡里修好并验证过）
针对本应用要查的：
- 源端调用该接口的门控条件：源工程里调用这个接口的那个 Java 方法（适配器、点击处理），看调用前的 if 判断；逐项列出条件（地区列表常量、用户标志）和每个 else 分支去哪，照搬到目标调用链
