# 点击动作前的确认弹窗和条件门控

agent 会看到什么：读到源端点击或批量动作执行前的 if 门控（地区、用户类型、基类标志）和有没有 AlertDialog 确认；产物里无条件 await 接口后静默 return，或照先例页拷入了确认弹窗和门控

## 规矩

- rule-8ed21e8537f0｜源端调用接口前有省份或用户类型门控时，目标展平调用链也保留同样的条件分支｜读到：源端在发起某个接口调用前用 `if (...)` 判断条件（地区是否在某个省份列表里、个人新学员这类用户标志），满足才调用，否则走重置提示或直接跳转；写错：目标端把这条链展平成共享函数后无条件 `await` 该接口，接口返回 null 时静默 return；宿主对象上也没有源端判断所需的用户标志
- rule-4fe3714614f1｜复用先例页接线时以本页源码为准，不照搬先例里的确认弹窗和门控｜读到：本页源码的批量动作监听里没有弹 AlertDialog 确认、直接执行，懒加载页的选中由基类标志门控；写错：照先例页拷入按数量阈值的 showAlertDialog 确认；懒加载追加选中只用多选态判断，与注释和源码门控相反；剩余页循环被省掉
- rule-c7681ac87e7d｜源码在确认对话框 onPositive 后才执行的破坏性操作，目标也先弹确认再执行｜读到：源码分支里 MaterialDialog.Builder(...).onPositive(...) 或 setPositiveButton 的回调里才执行删除、清空等操作；写错：目标的动作分支直接把数据清空（如赋值 `= []`），没有先弹确认弹窗
