# 源 clickable 带 Role.Button 和 enabled 时，目标写按钮角色和 .enabled

审的是：代码
触发（任一种）：
- 读到：源端可点击行 Modifier.clickable / combinedClickable(onClick, onLongClick, enabled = …, role = Role.Button)；写错的样子：目标只写 .onClick(...) 加 LongPressGesture，没有 .accessibilityRole(AccessibilityRoleType.BUTTON)，也没有 .enabled(...)
适用范围：把 Compose 可点击行、卡片的点击语义转写成 ArkUI 时
做法：
- role = Role.Button 写 .accessibilityRole(AccessibilityRoleType.BUTTON)；源端 enabled 的条件原样写进 .enabled(条件)
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- accessibilityRole(role: AccessibilityRoleType): T（@since 18）：设置组件的无障碍角色（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.accessibilityRole）
- AccessibilityRoleType.BUTTON = 5：按钮角色的枚举值（出处：鸿蒙 SDK 的 ets/component/common.d.ts，AccessibilityRoleType.BUTTON）
- enabled(value: boolean): T；false 时不响应点击：对应源端 clickable 的 enabled（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.enabled）
- 步骤行改为恒 BUTTON 角色 + enabled(可交互)：修复后的写法（出处：卡里修好并验证过）
