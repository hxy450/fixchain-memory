# 源端写操作包在账号就绪守卫里时，目标调用已移植的同名守卫，不用本地 Toast 判定代替

审的是：代码
触发（任一种）：
- 读到：Compose 里写操作（投票、收藏、删除、屏蔽、发送）的 onClick lambda 包在源端的账号就绪守卫函数里，或按钮组件收 account 参数、点击前默认先校验；写错的样子：目标自写判定，未就绪时只 showToast 后 return；或接线回调时直接调 ViewModel 写方法不加守卫；投票先改本地分数再上抛
适用范围：功能切片和收尾阶段接线写操作回调、目标端已有移植过来的账号校验服务时
做法：
- 源端每个被守卫包裹的回调，目标都调用已移植的同名守卫函数，把写操作放进它的回调里，不另写本地 Toast 判定
- 乐观更新（本地分数等）放到守卫通过之后再改并上抛
- 逐屏数源端守卫包裹的个数，和目标页守卫调用的个数对齐
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 页面改走已移植的守卫、按钮先过守卫再更新分数并回调：修复后保留的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端哪些回调带守卫：源工程对应 Screen 的 Compose 文件，以及按钮组件的定义；搜守卫函数名和按钮组件的 account 参数，逐个列出被包裹的回调名，和目标页逐一对照
