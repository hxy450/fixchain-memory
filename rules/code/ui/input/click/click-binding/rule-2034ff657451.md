# 父子组件都要响应点击时，在父组件上用 parallelGesture，不按 DOM 冒泡推理

审的是：代码
触发（任一种）：
- 读到：安卓整行可点的 Preference 行里还带自己响应点击的子控件，行和子控件都要响应；写错的样子：子组件挂了 .onClick，父容器（ListItem、Row）也挂 .onClick，注释或自检按「点子组件会冒泡到行」推理；父子都要响应却没有 .parallelGesture(...)
适用范围：ArkUI 里父子组件嵌套、都绑了点击的地方
做法：
- 按 ArkUI 手势规则推理：子组件已有 .onClick 时，父容器的 .onClick 不会触发；只要一方响应时只在一层挂点击
- 父子都要响应时，在父组件上写 .parallelGesture(TapGesture({ count: 1 }).onAction((event: GestureEvent) => { … }))，子组件保留自己的点击
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- parallelGesture(gesture: GestureType, mask?: GestureMask): T：绑定可与子组件手势同时触发的手势（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.parallelGesture）
- 父组件设置 parallelGesture 时，父子组件相同的手势事件都可以触发；手势事件为非冒泡事件：parallelGesture 写在父组件上（出处：ts-gesture-settings.md，parallelGesture）
- 当父子组件均绑定同一类手势时，子组件优先于父组件触发：默认只有子组件响应（出处：arkts-gesture-events-multi-level-gesture.md，手势与事件）
- priorityGesture(gesture: GestureType, mask?: GestureMask): T：同族接口：父组件优先识别，子组件不再触发（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.priorityGesture）
- gesture(gesture: GestureType, mask?: GestureMask): T：同族接口：普通绑定，父子同类手势时子组件优先（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.gesture）
未核实：卡里没有上机验证 parallelGesture 的写法；卡里上机所用 SDK 是 API 24（6.1.1），声明按本机 API 23 核实
