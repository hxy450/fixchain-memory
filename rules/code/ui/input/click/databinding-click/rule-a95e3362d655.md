# 源布局有 android:onClick 绑定时，目标按钮接跳转或登记 FWD-REF，不按合成快照判无交互

审的是：代码
触发（任一种）：
- 读到：源布局 XML 里按钮或可点击容器带 DataBinding 点击 android:onClick="@{page::onClick…}"，规格「导航关系」表列了代码触发的目标页；写错的样子：目标写出可见的 Button(...) 却没有 .onClick，页面也没拿 NavPathStack，没写 `FWD-REF`
- 读到：合成快照 meta.json 标 view_xml_synthesized=true，clickable_elements 为空、navigation_targets 为空或部分置信；写错的样子：回执或注释声明「无交互」「没有引入 forward-ref」，而源布局和规格导航表里有点击或跳转条目；按钮没有 .onClick
适用范围：页面转换阶段把源布局的按钮点击绑定落实为 ArkUI 事件和页面跳转（或登记前向引用占位）时
做法：
- 写页面前在源布局里搜 android:onClick 和 @{…::…} 等 DataBinding 点击绑定，读被绑定的 Fragment 方法确认跳转目标，并把规格「导航关系」表逐条对到页面的 handler
- 目标页已存在：在 NavDestination 的 .onReady(ctx => { this.pathStack = ctx.pathStack }) 拿到栈，onClick 里 pushPathByName('已注册路由名', 参数)；目标页未建：在 onClick 处写已登记的 `FWD-REF` marker（含 resolve_by）
- 落盘自检：每个可见 Button 或可点击容器都有 onClick 或已登记的占位；声明「无交互」前先确认源布局和导航表里确实没有点击或跳转
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- pushPathByName(name: string, param: unknown, animated?: boolean): void（animated 默认 true）：按路由名把目标页压栈（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pushPathByName）
- onReady(callback: Callback<NavDestinationContext>): NavDestinationAttribute：NavDestination 就绪时拿到上下文（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onReady）
- NavDestinationContext.pathStack: NavPathStack：当前页所在的页面栈（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationContext.pathStack）
- pushDestinationByName(name: string, param: Object, animated?: boolean): Promise<void>：同族接口：NavPathStack 按路由名压栈并返回 Promise，可捕获路由名不存在等错误（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.pushDestinationByName）
- 按钮加 onClick，在 onClick 里 pushPathByName 到已注册路由名，NavDestination.onReady 里取 context.pathStack：路由对账补上缺边后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 点击的跳转目标和路由名：源工程里布局绑定的 Fragment/Activity 的 Kotlin/Java 源文件，按 @{…::方法名} 里的方法名找定义；目标工程的路由表（route_map 等）按目标页名找；方法里启动的页面就是跳转目标；路由表里有它就用注册名，没有就登记 `FWD-REF`
未核实：卡里的页面在 API 24（6.1.1）上，本机核对用 API 23 的声明
