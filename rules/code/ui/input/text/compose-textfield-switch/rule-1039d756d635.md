# 源端字段是只读框加弹窗选择回填时，目标也做选择流程，不退化成并列的自由输入框

审的是：代码
触发（任一种）：
- 读到：源端表单字段是 onValueChange = {} 的只读 OutlinedTextField，上面盖一层透明可点击层打开选择弹窗，选中结果拆成几段后经一个回调一次性回填（如省、市、区）；写错的样子：目标写成几个并列的 TextInput({ text: $$…, placeholder: … }) 自由输入框，没有选择器，也没有多级联动
适用范围：迁移表单页时，源端用选择器（只读字段加弹窗回填）录入的字段
做法：
- 字段只做展示，点击打开分级选择弹窗（如省 → 市 → 区），选定后在同一个回调里把各级结果一起写进模型的对应字段
- 选项数据沿用源端的数据来源，不另造
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 改成省 → 市 → 区分级选择的弹窗，选定后一并写入三个字段，用户报告的问题消失：自由输入框丢了源端的选择语义和联动（出处：卡里修好并验证过）
针对本应用要查的：
- 源端选择弹窗的选项数据从哪来：源工程里选择弹窗组件的参数和它调用的数据提供类（如地区数据的获取方法）；目标的选择弹窗用同一份数据（同一接口或同一份内置数据），层级和顺序照源端
