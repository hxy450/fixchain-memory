# Compose 受控输入丢弃非法输入时，TextInput 用 onWillChange 返回 false 拦截

审的是：代码
触发（任一种）：
- 读到：源端 OutlinedTextField(value, onValueChange = { if (!合法) return@OutlinedTextField … })，非法输入不调用 onValueChange；写错的样子：目标写 TextInput({ text: value }).onChange(...)，拒绝时回调旧值、指望父值不变就回退，被拒字符留在框里
适用范围：迁移 Compose 受控输入框的拒绝分支时
做法：
- 在 .onWillChange((v: EditableTextChangeValue) => 合法(v.content)) 里对非法输入返回 false 拦截，框内文本按宿主值回显
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onWillChange(callback: Callback<EditableTextChangeValue, boolean>): TextInputAttribute（@since 15）：文本将要变化时回调，返回值决定是否放行（出处：鸿蒙 SDK 的 ets/component/text_input.d.ts，TextInputAttribute.onWillChange）
- 返回 true 表示正常修改，返回 false 表示拦截此次触发：非法输入返回 false 就不会进框（出处：ts-basic-components-textinput.md，onWillChange15+）
- onWillChange(callback: Callback<EditableTextChangeValue, boolean>): TextAreaAttribute：同族接口：TextArea 的同一拦截回调（出处：鸿蒙 SDK 的 ets/component/text_area.d.ts，TextAreaAttribute.onWillChange）
- onWillChange(callback: Callback<EditableTextChangeValue, boolean>): SearchAttribute：同族接口：Search 的同一拦截回调（出处：鸿蒙 SDK 的 ets/component/search.d.ts，SearchAttribute.onWillChange）
- 父值不变时 TextInput 不会回显旧值；改为 onWillChange 返回 false 并按宿主值回显后，被拒字符不再留在框里：只靠 onChange 回调旧值回退不了（出处：卡里修好并验证过）
