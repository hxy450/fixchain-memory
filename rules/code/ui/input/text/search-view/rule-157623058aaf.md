# 菜单状态挂在输入框焦点上时绑定 TextInput 的 onFocus/onBlur，不用手工布尔开关

审的是：代码
触发（任一种）：
- 读到：源端 SearchView.setOnQueryTextFocusChangeListener 按焦点切换菜单显隐；规格写「搜索焦点下某些菜单可见、其他隐藏」；写错的样子：标题栏用一个点击时手工翻转的布尔量决定展开态和菜单矩阵，TextInput 没有 .onFocus / .onBlur，展开时不 requestFocus
适用范围：把源端随输入框焦点变化的菜单、工具栏状态迁成 ArkUI TextInput 时，含按条件构建的输入框
做法：
- 焦点态绑到 TextInput(...).onFocus(() => { 焦点态 = true }).onBlur(() => { 焦点态 = false })，菜单矩阵只读这个焦点态
- 展开时用 requestFocus 取焦；输入框按条件构建的，先记一个待取焦标记，在它的 .onAppear 里再 requestFocus（还没上树就取焦会抛 150003）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onFocus(event: () => void): T；onBlur(event: () => void): T：CommonMethod 的获焦、失焦回调（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onFocus、CommonMethod.onBlur）
- onAppear(event: () => void): T：CommonMethod：组件挂载显示时回调，在这里取焦（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onAppear）
- requestFocus(key: string): void，组件不在树上或不存在时抛 150003：FocusController 按组件的 inspector key 取焦，经 UIContext.getFocusController() 取得（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，FocusController.requestFocus）
- 待取焦标记 + onAppear 后再 requestFocus：修好后按条件构建的输入框不再抛 150003（出处：卡里修好并验证过）
未核实：卡里环境是 API 24（6.1.1），本机按 API 23 的声明核对
