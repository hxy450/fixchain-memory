# 源码在回调里才设置的界面状态，目标用回调后置位的状态门控，不改成静态派生

审的是：代码
触发（任一种）：
- 读到：源码在回调或它调用的方法里（如 SearchView.OnQueryTextListener#onQueryTextSubmit 触发的查询方法）才显示某个尾部按钮、进度或空态，onCreateView 进入页面时不调用这个方法；写错的样子：build() 里用只由参数或数据派生的静态条件（如 `list.length > 0 || …`）渲染这部分，注释写成「由 build 派生」，首屏就出现；没有一个只在回调执行后才置位的 @Local 状态
适用范围：安卓页面在回调里按时机设置的界面状态（尾部按钮、进度、空态等），迁成 ArkUI 声明式条件渲染时
做法：
- 加一个布尔 @Local 状态（初值 false），只在对应回调真正执行完查询后置为 true，空查询提前返回的分支不置位
- 条件渲染写成 if (<该状态> && <原有条件>) { … }，把源端的调用时机一起移植，不只看参数
