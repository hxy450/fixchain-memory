# 复刻 SearchView 时展开、焦点、提交、收起、菜单重建分成独立状态，不用一个布尔加取消图标

审的是：代码
触发（任一种）：
- 读到：源端 SearchView 作菜单 actionView，有 expandActionView / collapseActionView、OnActionExpandListener、setOnQueryTextFocusChangeListener；写错的样子：页面里一个布尔同时表示「展开」和「焦点」，展开态只渲染 TextInput 加取消图标，取消时清空了事；没有 collapse 出口、菜单重建时收起、空串不提交、提交后收键盘
适用范围：目标用自绘标题栏复刻源端菜单里可展开的 SearchView 时
做法：
- 写一个搜索控制器，分开持有 expanded 和 focused 两个状态：expand() / collapse() 对应 expandActionView / collapseActionView，collapse 时执行源端 onMenuItemActionCollapse 里的逻辑；另留不触发监听的收起出口供菜单重建时用
- TextInput 的 .onChange 对应 onQueryTextChange（同文本不重复触发），.onSubmit 对应 onQueryTextSubmit：空串不提交，按源端返回值决定是否走 ACTION_SEARCH 那条投递路径，提交后收键盘；.onFocus / .onBlur 对应焦点监听
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onSubmit(callback: OnSubmitCallback): TextInputAttribute；OnSubmitCallback = (enterKey: EnterKeyType, event: SubmitEvent) => void：TextInput 按下回车提交时回调（出处：鸿蒙 SDK 的 ets/component/text_input.d.ts，TextInputAttribute.onSubmit）
- onChange(callback: EditableTextOnChangeCallback): TextInputAttribute：TextInput 文本变化回调，对应即时查询（出处：鸿蒙 SDK 的 ets/component/text_input.d.ts，TextInputAttribute.onChange）
- 返修写成搜索控制器：expandActionView / collapseActionView / collapseWithoutListener、setText 去重、空串不提交与 launchQuerySearch、onFocusChange：拆成独立状态与事件后与源端一致（出处：卡里修好并验证过）
- onSubmit(callback: SearchSubmitCallback): SearchAttribute：同族接口：Search 组件的提交回调（出处：鸿蒙 SDK 的 ets/component/search.d.ts，SearchAttribute.onSubmit）
- onSubmit(callback: TextAreaSubmitCallback): TextAreaAttribute：同族接口：TextArea 的提交回调（出处：鸿蒙 SDK 的 ets/component/text_area.d.ts，TextAreaAttribute.onSubmit）
针对本应用要查的：
- 源端各回调里做了什么：源工程里初始化 SearchView 的那个方法全文（含 OnActionExpandListener 的 expand / collapse、OnQueryTextListener、焦点监听）；每个回调里的调用逐条搬进控制器对应的方法；读源码回执被截断时补读到方法结束
未核实：卡里环境是 API 24，声明按本机 API 23 核对
