# 源端 setText 预填的输入框，目标首次 onFocus 调 caretPosition(0)

审的是：代码
触发（任一种）：
- 读到：源端 onCreateDialog 里对 EditText 调 setText(...) 预填；写错的样子：目标 TextInput({ text }) / TextArea({ text }) 预填后没有 controller，也没有 caretPosition 处理，光标停在末尾
适用范围：迁移预填的输入框、源端光标在开头时
做法：
- 写成 TextInput({ text: this.value, controller: this.ctrl }).onFocus(() => { if (首次获焦) this.ctrl.caretPosition(0) })；TextArea 用 TextAreaController 同样处理
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- caretPosition(value: number): void（TextInputController）；小于 0 按 0，超过文本长度放到末尾：把光标放到开头（出处：鸿蒙 SDK 的 ets/component/text_input.d.ts，TextInputController.caretPosition）
- caretPosition(value: number): void（TextAreaController）：同族接口：TextArea 的控制器（出处：鸿蒙 SDK 的 ets/component/text_area.d.ts，TextAreaController.caretPosition）
- 源端 EditText 的 ArrowKeyMovementMethod.initialize 调 Selection.setSelection(text, 0)：源端 setText 后光标在开头（出处：android.text.method.ArrowKeyMovementMethod#initialize）
- 两个预填框挂 controller，首次 onFocus 调 caretPosition(0)：修复后直接键入不再接在末尾，长文本从首行显示（出处：卡里修好并验证过）
