# 常驻 NavBar 的页面里，TextInput.onFocus 先判别是否用户触发再写业务状态

审的是：代码
触发（任一种）：
- 读到：源端 BasicTextField 的 Modifier.onFocusChanged 写业务 focused，状态用 remember 持有；写错的样子：目标 TextInput 写 .onFocus(() => 回调(true)) 无条件上抛、写进业务 focused，没有 enableKeyboardOnFocus(false) 和 onTouch 的来源判别
适用范围：页面处于 Navigation 的 NavBar 或常驻 Stack / Tabs 中、会被 pushPath 覆盖再系统返回时
做法：
- TextInput 加 .enableKeyboardOnFocus(false) 和 .onTouch((e: TouchEvent) => { if (e.type === TouchType.Down) 记下 inputTouched = true })
- .onFocus 里没有 touch-down 先行的视为框架恢复焦点：controller.stopEditing() 加 this.getUIContext().getFocusController().clearFocus()，不写业务 focused；有 touch-down 的照常写 focused=true；复位方法里一并清掉标记
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- enableKeyboardOnFocus(value: boolean): TextInputAttribute，默认 true：以点击以外的方式获焦时是否拉起输入法；设 false 后框架恢复焦点不弹键盘，点击仍弹（出处：鸿蒙 SDK 的 ets/component/text_input.d.ts，TextInputAttribute.enableKeyboardOnFocus）
- onTouch(event: (event: TouchEvent) => void): T；TouchType.Down 是手指按下：用 touch-down 判别用户触发的获焦（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onTouch；ets/component/enums.d.ts，TouchType.Down）
- stopEditing(): void：TextInputController 退出编辑态（出处：鸿蒙 SDK 的 ets/component/text_input.d.ts，TextInputController.stopEditing）
- clearFocus(): void（焦点清到根容器）：FocusController 清掉当前层级页面里的焦点（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，FocusController.clearFocus）
- enableKeyboardOnFocus(value: boolean): TextAreaAttribute：同族接口：TextArea（出处：鸿蒙 SDK 的 ets/component/text_area.d.ts，TextAreaAttribute.enableKeyboardOnFocus）
- enableKeyboardOnFocus(value: boolean): SearchAttribute：同族接口：Search（出处：鸿蒙 SDK 的 ets/component/search.d.ts，SearchAttribute.enableKeyboardOnFocus）
- 改用 touch-down 判别后，返回时未聚焦、显示原分支，点击输入框仍进入编辑分支：修复后的观察（出处：卡里修好并验证过）
未核实：复位里的 clearFocus 改在返回时执行能否压掉框架焦点恢复，卡里没有做实验
