# 定长格子密码框输满即校验时，目标在 onChange 里按位数自动比对，不加确定按钮

审的是：代码
触发（任一种）：
- 读到：源端定长格子密码框（MNPasswordEditText 一类）的 OnTextChangeListener 在 isComplete 时比对存储密码，else 分支 Toast 失败文案；写错的样子：目标用普通 TextInput({ type: InputType.Password }) 加“确定” Button 提交比对，或注释写“源端不匹配无提示”而没有失败反馈
适用范围：复刻源端定长格子密码框和它的校验时机、失败反馈时
做法：
- 保留源端格数和尺寸，输入用 .maxLength(位数)，在 .onChange((value: string) => { if (value.length === 位数) { 比对 } }) 里输满即校验；源端没有确定按钮就不加
- 失败反馈照源端 else 分支：如 this.getUIContext().getPromptAction().showToast({ message: 源端文案资源 })；没读到的分支不写成“源端无提示”
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onChange(callback: EditableTextOnChangeCallback): TextInputAttribute：输入内容变化回调，第一个参数是当前文本（出处：鸿蒙 SDK 的 ets/component/text_input.d.ts，TextInputAttribute.onChange）
- type EditableTextOnChangeCallback = (value: string, previewText?: PreviewText, options?: TextChangeOptions) => void：onChange 回调的形参（出处：鸿蒙 SDK 的 ets/component/text_common.d.ts，EditableTextOnChangeCallback）
- maxLength(value: number): TextInputAttribute：限定输入位数（出处：鸿蒙 SDK 的 ets/component/text_input.d.ts，TextInputAttribute.maxLength）
- showToast(options: promptAction.ShowToastOptions): void：失败时的提示（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.showToast）
- onChange(callback: EditableTextOnChangeCallback): TextAreaAttribute：同族接口：TextArea 的同一回调（出处：鸿蒙 SDK 的 ets/component/text_area.d.ts，TextAreaAttribute.onChange）
- 格子密码框在 onChange 输满位数时即校验，失败 toast 源端文案：卡里修好的做法（出处：卡里修好并验证过）
针对本应用要查的：
- 格数、格子尺寸和失败文案：源工程弹窗布局 XML 里密码框的属性（位数、宽高），以及弹窗函数里密码监听的完整分支；读到函数结尾（grep 截断就继续读），else 分支里的 Toast 文案就是失败反馈
