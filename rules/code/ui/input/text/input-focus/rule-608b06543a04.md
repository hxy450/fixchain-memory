# 条件挂载的页内浮层不靠 defaultFocus，输入框设 key、onAppear 里 requestFocus

审的是：代码
触发（任一种）：
- 读到：源端每段输入是一个独立 Dialog（如 CustomDialog），弹出时里面的 EditText 获焦弹键盘；写错的样子：目标用页内 Stack 里 if 条件挂载的浮层，TextInput 只写 .defaultFocus(true) 指望自动弹键盘，没有 key 和 requestFocus
适用范围：页内用 if 条件挂载（不是 Page、NavDestination、Dialog 这类层级页面）的输入浮层
做法：
- 给 TextInput 设 .key('唯一字符串')，在浮层或输入框的 .onAppear(() => ...) 里按这个 key 调 requestFocus
- 格区的点击也显式 requestFocus 同一个 key，键盘收起后再点能重新拉起
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- defaultFocus 只在初次创建的层级页面第一次进入时生效；层级页面指 Page、NaviDestination、NavBar、PopUp、Dialog 等：页内条件挂载的子树不是层级页面，后挂载或第二次挂载时不会自动获焦（出处：ts-universal-attributes-focus.md，defaultFocus）
- function requestFocus(value: string): boolean（focusControl，参数是组件的 id 或 key）：按 key 请求焦点（出处：鸿蒙 SDK 的 ets/component/common.d.ts，focusControl.requestFocus）
- requestFocus(key: string): void（FocusController，经 UIContext.getFocusController() 取得）：同族接口：UIContext 上的按 key 请求焦点，失败抛 150001/150002/150003（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，FocusController.requestFocus）
- key(value: string): T：给组件设标识，requestFocus 按它找组件（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.key）
- onAppear(event: () => void): T：组件挂载时回调，在这里请求焦点（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onAppear）
- key + onAppear 里 requestFocus 代替 defaultFocus 后能弹键盘：修复后保留的写法（出处：卡里修好并验证过）
