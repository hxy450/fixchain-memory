# 单行 EditText 没写 imeOptions 时，TextInput 写 EnterKeyType.Next 链

审的是：代码
触发（任一种）：
- 读到：源端一组单行 EditText（singleLine 或 inputType=textPassword 等），没写 android:imeOptions；写错的样子：目标各 TextInput 都没写 .enterKeyType(...)，软键盘回车全是默认 Done
适用范围：一页里有多个连续单行输入框、源端靠框架默认的 IME 动作时
做法：
- 除最后一框外写 .enterKeyType(EnterKeyType.Next)，组成按 Next 跳到下一框的链；最后一框保持 EnterKeyType.Done
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 未设 IME 动作时：后面还有可聚焦的编辑框就补 IME_ACTION_NEXT，否则补 IME_ACTION_DONE：源端单行框默认是 Next 链，最后一个是 Done（出处：android.widget.TextView#onCreateInputConnection）
- enterKeyType(value: EnterKeyType): TextInputAttribute，默认 EnterKeyType.Done：目标默认全是 Done，要显式写 Next（出处：鸿蒙 SDK 的 ets/component/text_input.d.ts，TextInputAttribute.enterKeyType）
- EnterKeyType.Next = 5，EnterKeyType.Done = 6：两个要用的枚举值（出处：鸿蒙 SDK 的 ets/component/text_input.d.ts，EnterKeyType）
- enterKeyType(value: EnterKeyType): TextAreaAttribute：同族接口：TextArea 的回车键类型（出处：鸿蒙 SDK 的 ets/component/text_area.d.ts，TextAreaAttribute.enterKeyType）
- enterKeyType(value: EnterKeyType): SearchAttribute：同族接口：Search 的回车键类型（出处：鸿蒙 SDK 的 ets/component/search.d.ts，SearchAttribute.enterKeyType）
未核实：ArkUI 按 Next 是否自动把焦点移到下一框、还是要在 onSubmit 里 requestFocus，卡里没写
