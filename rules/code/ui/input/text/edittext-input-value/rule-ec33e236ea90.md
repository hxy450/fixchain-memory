# 源页面多组表单字段同名时，执行请求按写模式各设独立字段，不复用别的表单槽位

审的是：代码
触发（任一种）：
- 读到：同一 Activity 里有几组语义相近的输入控件（都叫扇区/块/数值一类），各执行方法分别从本组的 EditText#getText 取值；写错的样子：目标的请求 interface 只有一组扇区/块/数值字段，页面从一个 @State 表单取值填进去，另一个表单的值没进请求或被别的表单值顶替
适用范围：把 Activity 的多个输入表单收集成交给服务层执行的请求对象时
做法：
- 先按源端执行方法逐个列出它实际读取的控件，为每个写模式在请求里设独立字段（每个模式有自己的扇区、块、数值字段），不因字段同名而复用其他表单的槽位
- 请求写完后逐模式反查：从服务执行方法用到的请求字段追回页面表单变量，确认每条路径只来自它自己的表单；出现跨表单取值即修正
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 请求里为值块模式另加扇区、块字段，为另一模式另加数值字段，执行方法按各自字段取钥、写入和编码：修好的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 每个执行方法实际读的是哪几个输入控件：源工程的 Activity 源码里各执行方法（onActivityResult 之后调用的那些）；逐个记下方法体里 getText() 读的 EditText 字段，按模式分组，对应到目标页面的表单状态
