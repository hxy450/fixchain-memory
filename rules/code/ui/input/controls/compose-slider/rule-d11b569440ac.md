# Slider 步长按源码写 (max - min) / (steps + 1)，规格口径冲突时不改成规格值

审的是：代码
触发（任一种）：
- 读到：源端 Slider(valueRange = a..b, steps = N)；规格或验收条目写「N+1 个停靠点」；写错的样子：目标 Slider({ step: max / steps }) 或直接用规格给的值，注释写「与 spec 口径差 1 个停靠点，留 verify」
适用范围：实现 Compose Slider 的离散刻度，规格口径与源码运行语义冲突时
做法：
- 写 Slider({ value, min, max, step: (max - min) / (steps + 1) })，已符合源码的实现不改成规格值
- 把冲突的规格条款列为待更正并上报，不只写在注释里
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- SliderOptions.step?: number，@default 1，取值范围 [0.01, max - min]：目标端是步长（出处：鸿蒙 SDK 的 ets/component/slider.d.ts，SliderOptions.step）
- 步长改回 max / (steps + 1)（min 为 0）：修复后刻度数与源端一致（出处：卡里修好并验证过）
