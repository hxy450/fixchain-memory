# CircularProgressIndicator() 不定进度要自绘复刻，不换成 LoadingProgress

审的是：代码
触发（任一种）：
- 读到：Compose 里 `CircularProgressIndicator()` 没传 progress，可能带 `Modifier.size(…)`、`strokeWidth`、`color`；不写 color 时是默认 primary；写错的样子：目标换成 `LoadingProgress()`（系统加载动效）或定值 `Progress({ type: ProgressType.Ring })`，尺寸、描边、颜色和源端不同（如写死白色）
适用范围：源端 Compose Material3 的圆形不定进度迁到 ArkUI 时
做法：
- 做一个共享的 M3 圆形不定进度组件（Canvas 自绘旋转弧，逐帧驱动），参数对上源端：尺寸 ← Modifier.size，描边宽 ← strokeWidth，颜色 ← color，没写 color 时取主题 primary
- 页面和共享件里每处 CircularProgressIndicator 都用这个组件，不留 LoadingProgress
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- LoadingProgress：用于显示加载动效的组件：系统自带的加载动效，和 M3 的旋转弧不同（出处：ts-basic-components-loadingprogress.md，LoadingProgress）
- ProgressOptions.value: number（必填）：Progress 的 Ring 类型也只显示定值（出处：鸿蒙 SDK 的 ets/component/progress.d.ts，ProgressOptions.value）
- 自绘的 M3 圆形不定进度替换 LoadingProgress 后，描边宽度和 primary 颜色与源端一致：验证过的复刻方式（出处：卡里修好并验证过）
针对本应用要查的：
- 源端圆形进度的尺寸、描边宽、颜色：源码调用处的 modifier.size、strokeWidth、color；没写的，查源工程依赖的 androidx.compose.material3 版本里 ProgressIndicatorDefaults 的默认描边宽和颜色角色；dp 换成 vp；颜色角色按应用主题解析到色值；尺寸跟着字号等表达式算的，照同样的表达式在目标端算
未核实：卡里的效果在目标 API 24 上验证，本机核对用的是 API 23 的声明
