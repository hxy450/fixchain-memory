# 同意区先 setChecked 动画再 postDelayed 回调时，目标先切选中态，再延时调同意逻辑

审的是：代码
触发（任一种）：
- 读到：弹窗同意区点击里先 checkBox.setChecked(true, true) 播放勾选动画，再 checkBox.postDelayed({ 回调; dialog.dismiss() }, N)；布局里的勾选控件有 checked / unchecked 两套颜色；写错的样子：同意按钮或同意区 .onClick(() => …) 里直接调同意逻辑并跳转，勾选控件只画了静态的未选中外观，没有延时
适用范围：迁移弹窗里带勾选反馈和延时回调的点击处理时
不适用的情形：源码里直接回调的分支（如二次确认弹窗里的同意）保持不延时
做法：
- 勾选控件按 checked / unchecked 两套颜色建一个布尔状态；同意区点击先 animateTo({ duration: … }, () => { this.<选中态> = true })
- 再 this.<定时器> = setTimeout(() => { <同意逻辑> }, <源码毫秒数>)；延时期间屏蔽重复点击，aboutToDisappear 里 clearTimeout(this.<定时器>)
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- setTimeout(handler: Function | string, delay?: number, ...arguments: any[]): number；clearTimeout(timeoutID?: number): void：可取消的延时，返回的编号留着在销毁时清理（出处：鸿蒙 SDK 的 ets/api/@internal/full/global.d.ts，setTimeout、clearTimeout）
- animateTo(value: AnimateParam, event: () => void): void；全局 animateTo 自 API 18 标为废弃，@useinstead UIContext#animateTo：切换选中态的动画（出处：鸿蒙 SDK 的 ets/component/common.d.ts，animateTo；ets/api/@ohos.arkui.UIContext.d.ts，UIContext.animateTo）
- aboutToDisappear?(): void：组件将要销毁时回调，在这里清定时器（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CustomComponent.aboutToDisappear）
- animateTo 300ms 切到选中外观，setTimeout 700ms 后再同意；延时期间屏蔽重复点击，aboutToDisappear 清理定时器：修好的写法（毫秒数取源码）（出处：卡里修好并验证过）
- View#postDelayed 的 delayMillis 单位是毫秒：源端数值直接作为 setTimeout 的 delay（出处：android.view.View#postDelayed）
针对本应用要查的：
- 勾选控件两态的颜色：源工程弹窗布局 XML 里勾选控件的颜色属性（如 checked / tick / unchecked / stroke 几项）；分别写进选中态和未选中态的样式
未核实：勾选控件来自第三方库，它的勾选动画时长在三类来源里查不到，卡里用了 300ms
