# 移植「建表+setMax+setProgress」的滑杆工具时，上限和初始进度一起写入状态并实际调用

审的是：代码
触发（任一种）：
- 读到：源端滑杆工具先建刻度表，再 SeekBar.setMax(values.size() - 1)、setProgress(最近一档)，调用点在相机就绪回调里；写错的样子：移植成只返回进度的函数，新增的上限状态初值 0 没有赋值者，Slider 的 max 恒为 0 或 Math.max(1, 0)
适用范围：把源端曝光面板（ISO、快门、白平衡）这类刻度滑杆迁成 ArkUI Slider 时
做法：
- 移植成一个同时产出刻度表、上限（表长 - 1）和初始进度的初始化函数，在面板打开或相机就绪路径实际调用，三者写入状态，Slider({ value: 进度, min: 0, max: 上限, step: 1 })
- 新增的状态字段在本切片找到赋值者；跨切片交出时登记 FWD-REF 并核对对方实现。最小检查：支持 ISO 范围时打开面板后上限 == 刻度表长度 - 1
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- SliderOptions.max?: number，@default 100；min 大于等于 max 时 min 取 0、max 取 100：上限没赋值时滑杆范围不对（出处：鸿蒙 SDK 的 ets/component/slider.d.ts，SliderOptions.max）
- ProgressBar#setMax(int max)：Set the upper range of the progress bar：源端 setMax 定上限（出处：android.widget.ProgressBar#setMax）
- 面板初始化时为 ISO、快门、白平衡建表并设上限和当前进度：修好的写法（出处：卡里修好并验证过）
