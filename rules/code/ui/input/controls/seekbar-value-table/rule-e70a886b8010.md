# 声称与源端步进入口等价前先读源实现，曝光补偿按滑杆值表索引步进，不直接改偏好值

审的是：代码
触发（任一种）：
- 读到：源端曝光补偿 SeekBar 的值表在 0 处重复多格，步进按 setProgress(索引 ± 1) 移动并跨过重复的零；写错的样子：注释写「等价源端 changeExposure 一类方法」，代码却直接对曝光补偿偏好值 ±1
适用范围：移植曝光补偿等按值表步进的入口（按键、手势、滑杆）时

- 先读源端步进实现和值表；按值表索引移动（跨过重复零、钳在 [0, 上限]），再把索引对应的值写回偏好，不直接对偏好值 ±1
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 曝光补偿表在 0 处重复 3 格并以中央零为零点，步进按表索引移动：修好的写法（出处：卡里修好并验证过）

- 源端曝光补偿滑杆的值表和步进方式：源工程相机主 Activity 里相机就绪后建曝光滑杆值表的代码，以及按键改曝光的方法；读出值表（含几个零）和步进时是改索引还是改值
