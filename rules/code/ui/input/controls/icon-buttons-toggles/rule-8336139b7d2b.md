# @Builder 接收随状态变化的图标或文案时，改传 () => Resource 回调或在内部读状态，不按值传

审的是：代码
触发（任一种）：
- 读到：安卓源码在模式切换、暂停等状态变化后调用 setImageResource 或刷新图标的方法，重设按钮的图标或描述；写错的样子：@Builder 形参写成 resource: Resource、label: Resource，调用处传入读 this 上状态的三元表达式（cond ? $r('app.media.a') : $r('app.media.b')）求值后的结果，状态变了按钮仍停在首次渲染的图标和文案
适用范围：ArkUI 页面把图标或无障碍文案依赖页面状态的按钮提取成共享 @Builder 时
做法：
- 动态实参改传回调：形参写 resource: () => Resource、label: () => Resource，builder 里写 Image(resource())、.accessibilityText(label())；调用处传 () => (cond ? $r(…) : $r(…))；或在 builder 内直接读 this 上的状态
- 提取前逐个检查实参：三元表达式或调用里读到 this 上状态的是动态实参，不和常量实参共用值参数签名，拆成静态、动态两个 builder；值参数只留给常量资源
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 调用 @Builder 默认按值传递；参数是状态变量时，状态变量的改变不会引起 @Builder 内的 UI 刷新：按值传入的 Resource、文案停在调用时的值（出处：arkts-builder.md，按值传递参数）
- 按引用传递只在传入一个参数且直接传入对象字面量时生效，有多个参数时不支持 @Builder 内 UI 组件刷新：多参数的共享 builder 不能靠按引用传递刷新（出处：arkts-builder.md，参数传递规则）
- 形参改成 () => Resource 并在 Image()/accessibilityText() 内调用后，状态切换时图标和文案随之刷新；常量资源的调用保持值参数不变：动态与静态拆成两个 builder 的做法（出处：卡里修好并验证过）
- accessibilityText(text: Resource): T：无障碍文案的 Resource 重载（@since 12）（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.accessibilityText）
- accessibilityText(value: string): T：同族接口：无障碍文案的 string 重载（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.accessibilityText）
未核实：卡里工程的 SDK 是 6.1.1(24)，本机按 API 23 核对
