# 接复用开关组件时，把 @Event 给出的目标值原样传给该开关的 setter，不改成无参回调再反转

审的是：代码
触发（任一种）：
- 读到：复用开关组件的契约是 @Param 接当前状态、@Event 回调带一个下一状态参数（组件内点击时传当前状态取反）；写错的样子：页面把组件的 @Event 回调写成无参的 (): void => action()，丢掉组件给出的值，再由页面变量或 ViewModel 的 toggle 反转接口拿旧值取反
适用范围：ArkUI 页面接入带 @Param 状态、@Event 输出回调的复用开关组件时
做法：
- 回调写成 (next: boolean) => 调用这个开关自己的显式 setter(next)，把组件给出的目标值原样传下去，并按它写偏好
- ViewModel 一侧给每个开关提供按值设置的 setter，页面不再调用反转接口
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- @Event 装饰回调方法是一种规范，表明子组件需要传入更新数据源的回调：组件把要设的值交给父组件，父组件据此改数据源（出处：arkts-new-event.md，@Event装饰器：规范组件输出）
- @Event 修改父组件的值立刻生效，但从父组件同步回子组件 @Param 是异步的：回调之后子组件的 @Param 不会立刻变，目标值以回调参数为准（出处：arkts-new-event.md，更改父组件中变量）
- 页面回调改传显式目标值、ViewModel 改用显式 setter 后，开关按组件给出的值写偏好：修好的做法（出处：卡里修好并验证过）
