# 屏幕层把交互交给共享 Composable 组件时，按组件源码写弹层的点击、步进和可用条件

审的是：代码
触发（任一种）：
- 读到：Compose 屏幕里调用另一个模块（如 core/ui）提供的 @Composable 弹层组件，只传数据和回调，点击切换、数量加减、按钮可用条件都在组件内部；写错的样子：ArkUI 弹层的 onClick、数量加减和确认按钮的 .enabled(...) 是凭页面调用参数推断的，与组件源码不一致，或者没写可用条件
适用范围：安卓屏幕层把交互委托给共享 Compose 组件，迁成 ArkUI 弹层时
做法：
- 按调用处的函数名在源工程找到组件定义，读出选项点击的切换规则、数量步进的上下限、确认按钮 enabled 的条件
- 照写到 ArkUI 弹层：选项 onClick 按切换规则，数量 Button 按同样的边界增减，确认按钮写 Button(...).enabled(<组件里的同一条件>)
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- enabled(value: boolean): T：false 时组件不响应点击，用来还原源组件的按钮可用条件（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.enabled）
针对本应用要查的：
- 共享弹层组件的交互规则：源工程里被调用的 @Composable 函数定义：按调用名在各模块（如 core/ui）的 .kt 文件里搜 fun 加函数名；读选项点击 lambda、数量加减的判断和按钮 enabled 参数的表达式，逐项记下再写到目标弹层
未核实：卡里没有上机核对弹层按钮可用条件和数量步进的还原结果
