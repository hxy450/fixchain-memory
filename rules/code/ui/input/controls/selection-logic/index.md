# 选项的选中、取消选中和按选中决定的按钮可用

agent 会看到什么：读到 ViewModel 的选择方法（同值再点置 null）、默认选中的回退、Compose Button(enabled = …) 按选中数决定可用、共享 @Composable 弹层内部的点击和步进；产物里对应的 onClick、.enabled(...) 和子类覆写的默认值方法

## 规矩

- rule-b1e8cc9bb31a｜源端选择方法同值再点即置 null 时，ArkUI 的 onClick 写成切换，不写单向赋值｜读到：ViewModel 的选择方法里，当前已选值等于传入值时置为 null（再次点击取消选择），否则选中；写错：选项的 onClick 里只做一次赋值把被点项设为已选，没有「相同则置 undefined」的分支，再点一次取消不了
- rule-6950e86074d9｜安卓按钮 enabled 依赖选中数时，目标按钮写 .enabled(选中数 > 0)｜读到：Compose `Button(enabled = …)` 的条件是选中数大于 0（空选时禁用结算或删除）；写错：目标对应的 `Button` 没有 `.enabled(`，空选时仍可点
- rule-9bb9489ee114｜屏幕层把交互交给共享 Composable 组件时，按组件源码写弹层的点击、步进和可用条件｜读到：Compose 屏幕里调用另一个模块（如 core/ui）提供的 @Composable 弹层组件，只传数据和回调，点击切换、数量加减、按钮可用条件都在组件内部；写错：ArkUI 弹层的 onClick、数量加减和确认按钮的 .enabled(...) 是凭页面调用参数推断的，与组件源码不一致，或者没写可用条件
- rule-5b85527618d0｜子类覆写参考端默认选中值前，按参考端的回调、过滤和回退函数核实，不凭目标端白名单反推｜读到：参考端多个页面共用同一个默认值回调；选项列表由完整列表构建，默认项只在与列表无匹配时才回退 options.get(0)；写错：目标子类新增覆写基类的默认值方法、返回回退值，注释写 `// 对齐 Android 回退首项`，没附参考端源码位置；推断依据是目标端那份只用于「不支持」提示的类型白名单
