# 源端选择方法同值再点即置 null 时，ArkUI 的 onClick 写成切换，不写单向赋值

审的是：代码
触发（任一种）：
- 读到：ViewModel 的选择方法里，当前已选值等于传入值时置为 null（再次点击取消选择），否则选中；写错的样子：选项的 onClick 里只做一次赋值把被点项设为已选，没有「相同则置 undefined」的分支，再点一次取消不了
适用范围：安卓 ViewModel 里带「再点取消」语义的单选（规格、标签、筛选项等），迁成 ArkUI 页面的点击处理时
做法：
- onClick 写成 this.selected = (this.selected === item) ? undefined : item，判等用源端比较的同一字段；依赖已选值的按钮、价格等随之回到未选状态
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 同一项再次点击取消选择：onClick 改成切换后与源端一致（出处：卡里修好并验证过）
