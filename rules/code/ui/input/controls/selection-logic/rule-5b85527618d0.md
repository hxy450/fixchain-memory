# 子类覆写参考端默认选中值前，按参考端的回调、过滤和回退函数核实，不凭目标端白名单反推

审的是：代码
触发（任一种）：
- 读到：参考端多个页面共用同一个默认值回调；选项列表由完整列表构建，默认项只在与列表无匹配时才回退 options.get(0)；写错的样子：目标子类新增覆写基类的默认值方法、返回回退值，注释写 `// 对齐 Android 回退首项`，没附参考端源码位置；推断依据是目标端那份只用于「不支持」提示的类型白名单
- 读到：参考端选项定义里带 `type` 之类的限制字段，只在生成「当前标的不支持」提示的函数里被读；写错的样子：把限制字段当成选项过滤，断言该类页面的列表里没有这些选项、默认回退 options.get(0)
适用范围：目标基类提供默认值钩子、子类可覆写，为共用参考端默认值的各类页面决定是否覆写时
做法：
- 覆写前沿参考端实际链路核对三件事：该页面绑定哪个默认值回调、选项列表在哪个函数里过滤、默认项何时回退；以这些函数原文为据
- 读到限制字段时追到它被消费的位置：只用于不支持提示的（选项仍可选中，面板显示提示）不影响默认选中值；只有真正过滤掉选项、默认匹配失败时才回退
- 核实后不需要覆写就继承基类默认值；注释写「对齐 Android」时附上对应参考端源码的类和方法
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 补核到限制字段只被不支持提示函数使用、过滤函数只滤另一类标的后，删除子类覆写、继承基类的登录默认值：修法（出处：卡里修好并验证过）
针对本应用要查的：
- 参考端该类页面的默认值、选项列表和回退规则：参考端工程里该页面绑定的默认值回调、构建选项列表的函数、选项过滤函数、按默认 key 选中并回退的更新函数，以及限制字段被读取的所有位置；按调用链确认默认 key 是否在该页面的选项列表里：在就选中它，不在才回退首项
