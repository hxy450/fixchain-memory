# 迁 SeekBar 时按 AbsSeekBar 规则实现触摸取值，不把 Slider.onChange 当等价

审的是：代码
触发（任一种）：
- 读到：<SeekBar> 配 setOnSeekBarChangeListener / onProgressChanged，触摸取值交给框架 AbsSeekBar；写错的样子：目标只把 Slider.onChange 当作 onProgressChanged 的等价物，没有处理按下跳位、拇指偏移和取值公式
适用范围：安卓 SeekBar 迁成 ArkUI 可拖动控件（含自定义组件）时
做法：
- 按下即跳到按下位置；按在当前拇指 thumbOffset 范围内时保持拇指偏移；progress = Math.round((x − paddingLeft) / 可用宽 × max)，x 越界夹到 0 / max；在滚动容器里越过 touchSlop 才开始拖动，没越过就松手按点按跳位处理
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- ACTION_DOWN 时 mTouchThumbOffset = 当前进度比例 − (x − paddingLeft) / 可用宽，|偏移 × 可用宽| > thumbOffset 时置 0：按在拇指范围内保持偏移，否则跳到按下位置（出处：android.widget.AbsSeekBar#onTouchEvent）
- scale = (x − paddingLeft) / availableWidth + mTouchThumbOffset，x < paddingLeft 取 0、x > width − paddingRight 取 1；progress = Math.round(scale × (max − min) + min)：取值公式和越界夹取（出处：android.widget.AbsSeekBar#trackTouchEvent）
- 在滚动容器里 ACTION_DOWN 只记下 x，移动超过 getScaledTouchSlop() 才 startDrag；没越过就松手按点按跳位：滚动容器内的拖动起点（出处：android.widget.AbsSeekBar#onTouchEvent）
- 同比例位置点按后两端取值一致，拖到末端得 max：按上面规则写的自定义组件实测结果（出处：卡里修好并验证过）
