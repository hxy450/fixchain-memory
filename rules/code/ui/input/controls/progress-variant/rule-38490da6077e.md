# 源 Compose 按偏好在两种进度组件间二选一时，两个分支都实现或登记占位，不静态选一个

审的是：代码
触发（任一种）：
- 读到：源 Compose 代码按一个布尔偏好在 CircularWavyProgressIndicator 与 CircularProgressIndicator 之间二选一；写错的样子：目标只写一种 Progress({ type: ProgressType.Ring })，没有偏好驱动的另一个分支，也没在这个位置登记 `P-S*` / forward-ref 占位
适用范围：页面转换时，源端渲染按偏好分支、而偏好由别的切片接线时
做法：
- 两个分支都实现：普通分支写 Progress({ value, total, type: ProgressType.Ring })，波浪分支用 Canvas 自绘；按偏好状态选择，初值取源端偏好的默认值
- 本切片接不到偏好时，在这个位置登记指向设置切片的 forward-ref 占位；不以「偏好未知」为由静态选一个分支
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- <Type extends keyof ProgressStyleMap>(options: ProgressOptions<Type>): ProgressAttribute<Type>：Progress 组件的构造（出处：鸿蒙 SDK 的 ets/component/progress.d.ts，ProgressInterface）
- ProgressType.Ring = 1（Linear = 0、Eclipse = 2、ScaleRing = 3、Capsule = 4）：普通环形进度的类型，没有波浪样式（出处：鸿蒙 SDK 的 ets/component/progress.d.ts，ProgressType）
- 新增 Canvas 自绘的波浪进度组件，并按偏好选渲染：波浪分支的实现方式（出处：卡里修好并验证过）
针对本应用要查的：
- 这个偏好的默认值：源工程里定义偏好键和默认值的 Kotlin 代码（DataStore 的读取函数或默认值常量）；目标端偏好状态的初值照搬这个默认值，静态预览时也选它对应的分支
未核实：卡里的行为出自 API 21（HarmonyOS 6.0.1），本机声明是 API 23
