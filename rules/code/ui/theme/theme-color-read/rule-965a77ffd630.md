# 缓存颜色或在 Canvas 里取色的组件改读主题令牌，并用 @Monitor 监听令牌变化后重绘

审的是：代码
触发（任一种）：
- 读到：源端 Canvas 或绘制回调里取 MaterialTheme.colorScheme.primary / error / onSurface，颜色随应用内主题设置变化；写错的样子：Canvas 组件声明 Resource 类型的颜色参数（默认 $r(...)），绘制时 getColorSync 取默认资源值；或把颜色缓存在成员里，没有订阅主题变化
适用范围：源端主题随应用内设置切换时，目标端缓存了颜色或用 Canvas 自绘取色的组件
做法：
- 删掉 Resource 颜色参数和 getColorSync，绘制时读主题对象的令牌；在 @ComponentV2 组件里写 @Monitor('主题对象.tokens') 回调，令牌变化时刷新缓存色并重绘画布
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 画布组件删去 Resource 颜色参数改读主题令牌，并用 @Monitor 监听主题令牌重绘后，换调色板时画布跟着变色：Canvas 取色要订阅主题变化（出处：卡里修好并验证过）
- declare const Monitor: MonitorDecorator；MonitorDecorator = (value: string, ...args: string[]) => MethodDecorator：@Monitor 接受被监听属性的路径字符串（出处：鸿蒙 SDK 的 ets/component/common.d.ts，Monitor / MonitorDecorator）
- @Monitor 用在 @ComponentV2 组件里；监听类属性要求类被 @ObservedV2 装饰、属性被 @Trace 装饰：主题对象的令牌字段要是 @Trace 才能被监听到（出处：arkts-new-monitor.md，概述）
