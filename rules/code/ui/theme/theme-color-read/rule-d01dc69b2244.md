# 源端用 textPrimary 这类主题语义色时，先解析实际值再选资源，缺令牌就报告或补同值令牌

审的是：代码
触发（任一种）：
- 读到：Compose 源码里 Text / Icon 的 color = …Theme.colors.textPrimary、iconPrimary 这类主题语义色；写错的样子：目标写成 fontColor($r('app.color.text_secondary')) 这类名字相近的已有资源；目标 color.json 里没有对应令牌，也没报 `design_tokens_missing`
适用范围：把 Compose 自定义主题的语义色映射成 ArkUI 颜色资源、而目标颜色资源只覆盖部分语义令牌时
做法：
- 先在源端主题文件（定义 colors 的 Theme.kt、调色板）或设计令牌里解析这个语义色的实际值，再选目标资源
- 目标资源有同值令牌就用它；缺这个令牌时按协议报告 `design_tokens_missing`，或在 color.json 补一个同值令牌，不拿名称相近的 text_secondary 代替
针对本应用要查的：
- 这个语义色在当前主题下的实际值：源工程的 Compose 主题文件：定义颜色数据类的 Kotlin 文件里该字段的默认值，以及浅色、深色调色板里对它的赋值；顺着赋值跟到具体的 Color(0x…) 或别的语义字段（例：某主题里 textPrimary 默认取 brand），再在目标 color.json 里找同值资源
