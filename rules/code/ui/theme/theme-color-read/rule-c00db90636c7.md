# 源端应用内切深浅档和多套调色板时，页面主题色读主题对象的令牌，不用 $r 资源色

审的是：代码
触发（任一种）：
- 读到：Compose MaterialTheme(colorScheme = if (darkTheme) palette.dark else palette.light) 包住全部页面，darkTheme 和 palette 来自应用内设置（Light/Dark/System、多套调色板）；写错的样子：页面和组件里调色板角色色写成 $r('app.color.<角色>') 或 getColorSync 取资源色；按压层、禁用色用按默认调色板预混的资源色
适用范围：源端深浅档由应用内设置覆盖系统、或在多套调色板间切换，目标端有可观察主题对象（色板令牌）时
不适用的情形：与调色板无关的颜色（遮罩、启动窗色）保留 $r 资源
做法：
- 页面主题色在渲染期读主题对象当前色板：$r('app.color.<角色>') 换成 主题对象.tokens.<角色>，开关、FAB、文字、底色都一样
- 预混派生色（按压层、禁用色、混色）改由令牌计算，例如按压层 = onSurface 令牌加 10% 透明度，不用预混好的资源色
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 页面写 $r 资源色时，应用内切 Dark 只有调色板圆点变，选另一套调色板后页面仍是默认调色板色；换成主题令牌后随设置变色：$r 色键跟不上应用内切换（出处：卡里修好并验证过）
- 颜色模式限定词只有 dark（深色模式）、light（浅色模式），表示设备的颜色模式：$r 资源按设备颜色模式匹配 base / dark 目录里的一套值，没有调色板维度（出处：resource-categories-and-access.md，限定词目录）
- 限定词目录里含颜色模式限定词时，取值必须与当前的设备状态完全一致才参与匹配：资源匹配看设备状态，不看应用内设置（出处：resource-categories-and-access.md，限定词目录与设备状态的匹配规则）
针对本应用要查的：
- 源端每个页面颜色对应哪个色板角色：源工程 Compose 主题文件里 MaterialTheme 的 colorScheme 选择，和页面里 MaterialTheme.colorScheme.<角色> 的取用处；按角色名对应到主题对象令牌的同名字段
