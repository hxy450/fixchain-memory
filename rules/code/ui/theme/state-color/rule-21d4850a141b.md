# 源组件套在 elevation > 0 的 Surface 里时，每种状态色都按源叠加公式算底色

审的是：代码
触发（任一种）：
- 读到：Compose 源组件外面是 Surface(elevation = 2.dp) 这类 elevation > 0 的 Surface，Surface 的实现按 elevation 给底色叠白；写错的样子：目标 .backgroundColor 直接用选中、未选中的资源原色，只核对了白底一种状态（白上叠白不变）就简化成原色
适用范围：源端 Surface 按 elevation 给底色做叠加、迁成 ArkUI 组件底色时
做法：
- 对每种状态色（选中、未选中、深色）按源公式算出叠加后的颜色写进目标底色，或在目标导出一个同公式的叠加函数，各状态都经它取色
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 白色叠加 alpha = (4.5 · ln(e + 1) + 2) / 100（e 为 elevation 的 dp 值），2dp 约 6.94%：源 Surface 的叠加公式；非白底色叠加后会变浅（出处：卡里修好并验证过）
针对本应用要查的：
- 源 Surface 的底色叠加实现：源工程里 Surface 组件的 Kotlin 源文件，按 elevation 参数找计算底色的那段；照公式对每种状态色算出叠加后的 RGB，写成目标颜色
