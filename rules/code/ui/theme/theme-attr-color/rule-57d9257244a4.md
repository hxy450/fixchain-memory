# 窗口底色来自主题 windowBackground 时，页面根 NavDestination 等显式设底色

审的是：代码
触发（任一种）：
- 读到：源端页面布局根上没写 android:background，窗口底色来自生效主题的 windowBackground（Material 系为 ?attr/colorBackground）；写错的样子：页面根 Navigation 或 NavDestination 的属性链里没有 .backgroundColor(...)
适用范围：源端页面靠主题窗口底色、迁成 Navigation / NavDestination 页面时
做法：
- 页面根 Navigation 或 NavDestination 写 .backgroundColor(<windowBackground 解析出的颜色资源>)；Material.Light 系没覆写时是 background_material_light（#FFFAFAFA）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- backgroundColor(value: ResourceColor): T：组件底色，所有组件共有（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.backgroundColor）
- <item name="windowBackground">?attr/colorBackground</item>；Theme.Material.Light 的 colorBackground 是 @color/background_material_light：窗口底色的解析链（出处：Android SDK 平台资源 data/res/values/themes_material.xml，Theme.Material.Light 的 windowBackground、colorBackground（按应用的 compileSdk 取对应平台））
- background_material_light = @color/material_grey_50 = #fffafafa：Material.Light 系没覆写时的窗口底色（出处：Android SDK 平台资源 data/res/values/colors_material.xml，background_material_light、material_grey_50（按应用的 compileSdk 取对应平台））
- Navigation 与 NavDestination 加上 background_material_light 底色后和源端一致：修好后的接法（出处：卡里修好并验证过）
针对本应用要查的：
- 生效主题的 windowBackground 或 colorBackground 覆写：源工程 values-vNN/styles.xml 里生效主题的 item；没覆写时平台 themes_material.xml 里父主题的同名 item；顺着 ?attr/colorBackground → @color/… 解析到 #AARRGGBB，迁成目标颜色资源再引用
