# 源图标没写 tint、颜色来自主题属性时，fillColor 用与主题同值的深浅色键，不借次要文字灰

审的是：代码
触发（任一种）：
- 读到：矢量图标的 android:fillColor="?attr/…"（主题属性），使用它的 ImageView / 菜单项上没有 android:tint 或 app:tint；写错的样子：目标 Image(...).fillColor($r('app.color.…')) 用的是次要文字色一类语义不同的灰，或只按 SVG 里的浅色值写死
- 读到：Toolbar 上的导航、菜单图标没写 tint，颜色来自 Toolbar 主题的 colorControlNormal（如 ?attr/colorOnSurface）；写错的样子：工具栏图标的 .fillColor(...) 或 .fontColor(...) 用了次要文字色一类的灰，深色模式下也不是主题给的值
适用范围：源图标没有显式 tint、颜色由矢量里的主题属性或 Toolbar 主题决定，目标用 SVG 加 fillColor 着色时
做法：
- 顺着 ?attr/ 引用在源工程主题里解出浅色、深色两套值（查法见要查的），映射到同值的颜色键
- 目标写 Image($r('app.media.<图标>')).fillColor($r('app.color.<同值的键>'))，这个键在 base 和 dark 各有值；没有就补键，不借用 text secondary 这类语义不同的灰
- 同一主题属性全工程只映射到一个键；兄弟页或公共组件的先例和源 XML、主题对不上时，改先例，不为保持一致照搬
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- fillColor(color: ResourceColor | ColorContent | ColorMetrics): ImageAttribute：Image 叠加的填充色，只对 SVG 图生效；默认不填充，传无效值时用主题默认色（浅色黑、深色白）（出处：鸿蒙 SDK 的 ets/component/image.d.ts，ImageAttribute.fillColor）
- android:tint="?attr/colorControlNormal"：平台自带的工具栏返回箭头按 colorControlNormal 着色，工具栏图标的颜色由主题里这一项决定（出处：Android SDK 平台资源 data/res/drawable/ic_ab_back_material.xml，android:tint（按应用的 compileSdk 取对应平台））
- <attr name="colorControlNormal" format="color" />：控件常态下的颜色属性，定义在平台 attrs.xml，取值在主题里给（出处：Android SDK 平台资源 data/res/values/attrs.xml，colorControlNormal（按应用的 compileSdk 取对应平台））
- 深色值放在 resources/dark/element/color.json：颜色模式限定词 dark 的 element 目录，深色模式下按同名键取值（出处：resource-categories-and-access.md，创建资源目录和资源文件）
针对本应用要查的：
- 图标颜色所用主题属性在浅色、深色主题下的值：源工程 res/values/attrs.xml 里该 attr 的声明；res/values/styles.xml、themes.xml 里控件 style、Toolbar 的 android:theme / app:theme、Activity 主题和应用主题的 <item name="…">；res/values-night/ 下的同名主题；按控件 style → 祖先 android:theme → Activity 主题 → 应用主题找到提供值的那一项，再顺着 ?attr/、@color/ 引用解到颜色字面量，浅色、深色各记一个。例：Toolbar 主题里 colorControlNormal=?attr/colorOnSurface 时，取应用主题里 colorOnSurface 的浅、深两值
- Toolbar 主题来自依赖库时 colorControlNormal 的值：com.google.android.material:material 包内 res/values/values.xml，Toolbar 用的主题 style（如 ThemeOverlay.Material3.Toolbar.Surface）；按应用依赖的版本找到该 style 的 colorControlNormal item，再顺着引用解到颜色
