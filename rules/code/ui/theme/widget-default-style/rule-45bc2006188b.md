# 源端禁用不变透明时，用 HitTestMode.None 拦截点击，不写 .enabled(false)

审的是：代码
触发（任一种）：
- 读到：规格或映射表写 .enabled(false)（如「setEnabled(false) → .enabled(false)」）；源端禁用只靠 setBackgroundResource 换背景，android:textColor 固定；写错的样子：按钮修饰链上写 .enabled(状态变量) 加 backgroundColor(启用 ? 主色 : 灰)，禁用时背景和文字整体变半透明
适用范围：页面实现阶段，落实运行时禁用控件的外观和点击拦截时
做法：
- 源端禁用无透明或换色态时去掉 .enabled()：写 .hitTestBehavior(启用 ? HitTestMode.Default : HitTestMode.None) 拦截点击，背景按启停态显式切换，禁用时投影置空（AppCompat / Material 按钮禁用时投影为 0）
- 源端靠 state_enabled 选择器变灰的，按选择器里的色值显式写禁用态颜色，不依赖 ArkUI 默认禁用透明度
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 去掉 .enabled()，禁用时投影置空、hitTestBehavior(HitTestMode.None)，背景照旧按启停态切换后，禁用态取色等于源背景色且点击不跳转：修好的写法（出处：卡里修好并验证过）
- hitTestBehavior(value: HitTestMode): T：设置触摸测试模式（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.hitTestBehavior）
- HitTestMode.None = 3：自身不响应触摸测试；HitTestMode.Default = 0：默认触摸测试效果：禁用时用 None，启用时用 Default（出处：ts-appendix-enums.md，HitTestMode）
- enabled(value: boolean): T，false 时不响应点击：声明只说不响应点击，没写外观；卡里实测会整体降透明（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.enabled）
