# 冷启动恢复持久化主题放在 EntryAbility.onCreate 的同步路径，loadContent 前完成

审的是：代码
触发（任一种）：
- 读到：入口 Activity.onCreate 里 super.onCreate(...) 之前按 SharedPreferences 调 setTheme(...) 设 DayNight 主题；写错的样子：恢复函数写成 async …: Promise<void>，内部 await preferences.getPreferences(...) 后才 setColorMode，EntryAbility.onCreate 里不等待地调用它
适用范围：Stage 模型入口在冷启动时应用持久化的外观设置（深浅色）时
做法：
- 在 EntryAbility.onCreate 里同步读取：preferences.getPreferencesSync(this.context, { name: <偏好文件名> }).getSync(<主题键>, <默认值>)，随即 this.context.getApplicationContext().setColorMode(...)；都在 onWindowStageCreate 的 loadContent 之前完成
- 恢复函数若返回 Promise 而调用方不等待，按「首帧之后才生效」处理，改成同步版本
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getPreferencesSync(context: Context, options: Options): Preferences：同步取得偏好实例，可用在首帧前（出处：鸿蒙 SDK 的 ets/api/@ohos.data.preferences.d.ts，preferences.getPreferencesSync）
- getSync(key: string, defValue: ValueType): ValueType：同步读一个键（出处：鸿蒙 SDK 的 ets/api/@ohos.data.preferences.d.ts，Preferences.getSync）
- setColorMode(colorMode: ConfigurationConstant.ColorMode): void，只能在主线程调用：设置应用的深浅色（出处：鸿蒙 SDK 的 ets/api/application/ApplicationContext.d.ts，ApplicationContext.setColorMode）
- COLOR_MODE_NOT_SET = -1、COLOR_MODE_DARK = 0、COLOR_MODE_LIGHT = 1：ColorMode 的取值，源端 DayNight 的跟随系统、深色、浅色分别对应（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.ConfigurationConstant.d.ts，ConfigurationConstant.ColorMode）
- 偏好仓库加同步初始化（getPreferencesSync），恢复函数改同步并在首帧前 applyTheme，EntryAbility.onCreate 同步调用后首帧即为所选主题：修好后的写法（出处：卡里修好并验证过）
未核实：卡里的环境是 HarmonyOS SDK 6.1.1(24)，签名按本机 API 23 的声明核实
