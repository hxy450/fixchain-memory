# 颜色端点是 32 位 ARGB 或 #AARRGGBB 时，插值按 A/R/G/B 位移拆分，不用 slice(1,3)

审的是：代码
触发（任一种）：
- 读到：颜色端点取自 resourceManager.getColorSync(...)（32 位 ARGB 数），或 color.json 里的 8 位值 '#AARRGGBB'；规格要求按 fraction 插值或混色（折叠顶栏、状态过渡、按压态）；写错的样子：插值或混合函数用 slice(1, 3) / slice(3, 5) / slice(5, 7) 当 R / G / B 拆，再 padStart(6) 拼回 6 位串，把 alpha 字节当成红色
适用范围：界面代码里对颜色值做插值、混合或其他按通道的运算时
做法：
- 数值端点按 (c >>> 24) & 0xFF、(c >>> 16) & 0xFF、(c >>> 8) & 0xFF、c & 0xFF 拆成 A、R、G、B；8 位串先 parseInt(s.slice(1), 16) 转成数再拆；四个通道各自插值后输出同一种 8 位表示（'#' + 十六进制 padStart(8, '0')，或 32 位数）
- 最小检查：fraction = 0 和 1 时结果应分别原样等于两个端点（8 位端点原样返回）；位数变了或首两位变成别的值就是通道错位
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getColorSync(resId: number): number，返回颜色值（十进制）：端点是一个整数，按位取通道（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getColorSync；js-apis-resource-manager.md，getColorSync）
- color.json 的颜色值是 8 位十六进制，前两位透明度、后六位颜色：8 位串里 slice(1, 3) 是 alpha，不是红色（出处：resource-categories-and-access.md，资源文件示例）
- 改成按 ARGB 四通道混色后，8 位端点不再被拆成错位的 6 位色（原先 alpha 的 FF 被当成红色，偏粉）：按 #RRGGBB 偏移拆 8 位串会把颜色整体错位（出处：卡里修好并验证过）
- getColorSync(resource: Resource): number：同族接口：按 Resource 对象取颜色，同样返回整数（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getColorSync(resource)）
- getColorByNameSync(resName: string): number：同族接口：按资源名取颜色，同样返回整数（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getColorByNameSync）
