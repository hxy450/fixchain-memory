# 负责主题运行时的切片交付界面 build 可直接读的全局响应式主题状态

审的是：代码
触发（任一种）：
- 读到：源端用 MaterialTheme（CompositionLocalProvider）包裹全树、按色板 × 明暗 × 字号计算 colors 与 typography；规格写主题「共享至全部页面」「变更即重算」；写错的样子：主题控制器只把解析出的主题包发到没有界面订阅的状态流，界面 build 里没有可读的全局主题状态（没有 @ObservedV2 / @Trace 一类可观测状态）
适用范围：实现全局主题运行时（色板、明暗、字号）的那一个切片
做法：
- 交付界面 build 中可直接读取的全局响应式主题状态（色板 × 明暗 × 字号）：如 @ObservedV2 单例，颜色、字体令牌用 @Trace，主题控制器重算时写入它
- 交付前全工程搜 $r('app.color.…')、$r('app.float.…') 的静态主题引用并统计个数，本切片写盘范围内的换成主题状态
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- declare const ObservedV2: ClassDecorator；declare const Trace: PropertyDecorator：全局主题状态类用的装饰器（@since 12）（出处：鸿蒙 SDK 的 ets/component/common.d.ts，ObservedV2、Trace）
- @ObservedV2 类里 @Trace 的属性变化时，会触发绑定它的 UI 组件刷新：界面读单例属性即订阅，不需要另接事件流（出处：arkts-new-observedV2-and-trace.md，观察变化）
未核实：卡里观察到的行为出自鸿蒙 SDK 6.1.1(24)，本机声明按 API 23 核实
