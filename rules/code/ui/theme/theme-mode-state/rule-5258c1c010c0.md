# 源端动态取色迁移时用 wallpaper.getColors 取主色做种子，失败回退固定配色

审的是：代码
触发（任一种）：
- 读到：Compose 主题里 SDK_INT >= S 且开关打开时用 dynamicLightColorScheme(context) / dynamicDarkColorScheme(context)，否则用固定 scheme；设置行 enabled = Build.VERSION.SDK_INT >= Build.VERSION_CODES.S；写错的样子：目标主题只按 isDark 二值返回固定 Palette，没有 wallpaper.getColors 调用；动态主题开关恒可用、只写偏好、无视觉效果
- 读到：源端 @Composable 主题函数按动态主题开关用 Material You 动态配色，低版本回落固定配色；写错的样子：动态主题被做成 setColorMode(COLOR_MODE_NOT_SET) 与固定模式之间的切换，注释写「没有系统壁纸取色 API」，决策台账里没有这条降级
适用范围：源端主题按开关（Android 12+ 门槛）用 Material You 动态取色、不可用时回落固定配色，迁到鸿蒙主题实现时
做法：
- 以 wallpaper.getColors(wallpaper.WallpaperType.WALLPAPER_SYSTEM) 的主色为种子生成明暗配色，写进全局主题状态的调色板供页面消费；订阅 wallpaper.on('colorChange', …) 和动态主题开关，变化时重新生成；取色失败时用源端原固定配色（固定资源色）；EntryAbility.onDestroy 里停掉监听
- 设置页的动态主题行 enabled 绑定取色能力是否可用
- 壁纸主色只能派生完整色阶的子集；确要降级时写进决策台账，不在实现里自行降成颜色模式切换
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function getColors(wallpaperType: WallpaperType): Promise<Array<RgbaColor>>，@since 7，@deprecated since 9：取指定类型壁纸的主要颜色（出处：鸿蒙 SDK 的 ets/api/@ohos.wallpaper.d.ts，wallpaper.getColors）
- function on(type: 'colorChange', callback: (colors: Array<RgbaColor>, wallpaperType: WallpaperType) => void): void：订阅壁纸颜色变化，变化时重新生成配色；声明标 @deprecated since 9（出处：鸿蒙 SDK 的 ets/api/@ohos.wallpaper.d.ts，wallpaper.on('colorChange')）
- function off(type: 'colorChange', callback?: (colors: Array<RgbaColor>, wallpaperType: WallpaperType) => void): void：同族接口：取消订阅壁纸颜色变化（出处：鸿蒙 SDK 的 ets/api/@ohos.wallpaper.d.ts，wallpaper.off）
- WallpaperType.WALLPAPER_SYSTEM（主屏）、WALLPAPER_LOCKSCREEN（锁屏）：取色用主屏壁纸（出处：鸿蒙 SDK 的 ets/api/@ohos.wallpaper.d.ts，wallpaper.WallpaperType）
- 以壁纸主色为种子按 TonalSpot 生成明暗配色、订阅开关和 colorChange，设置行 enabled 绑定取色能力后，真机上看到动态取色生效：修好的写法（出处：卡里修好并验证过）
- 新建壁纸调色板服务从壁纸主色派生调色板，经主题状态的 palette 供外观页消费，固定模式回落资源色，onDestroy 时停止：修复后的动态主题（出处：卡里修好并验证过）
针对本应用要查的：
- 源端动态配色和回落配色各取哪些颜色角色：源工程的主题 Kotlin 文件（主题 composable 里动态配色与固定配色两个分支）；固定分支的颜色写成目标端资源色作回落；动态分支列出要从壁纸主色派生的角色
未核实：getColors 自 API 9 弃用、替代接口不在公开 SDK；复审仍提示设备相关、置信度低，其他设备和后续版本上是否可用未知；其中一张卡（case-470d704a6ec794b4c3c9）的行为出自 API 21（HarmonyOS 6.0.1），本机声明是 API 23
