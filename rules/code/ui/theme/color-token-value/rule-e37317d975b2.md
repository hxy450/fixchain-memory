# 源色值来自带深色覆盖的主题变量时，写 $r('app.color.*')，不写浅色 hex 字面量

审的是：代码
触发（任一种）：
- 读到：源样式用 var(--ion-background-color)、var(--ion-text-color)、var(--ion-card-background) 或 Ionic 组件默认色，主题文件里这些变量有 body.dark 覆盖值；写错的样子：页面写 .backgroundColor('#FFFFFF')、.fontColor('#000000')、Divider().color('#E0E0E0')，或 COLOR_BG 这类 string 常量存浅色 hex；也没有为这些中性色登记 FWD-REF
适用范围：页面转换阶段给页面底色、文字、卡片、分隔线等中性色取值，源端这些色值随深色模式切换时
做法：
- 引用有 base 和 dark 两档的资源：.backgroundColor($r('app.color.<键>'))，共享常量也存 Resource 而不是 hex 字符串；或用随深浅切换的系统资源，如 $r('sys.color.ohos_id_color_text_primary')
- 颜色资源还不存在时，为每个中性色登记 forward-ref / handoff，写明键名和所需的深色值；不能只给 accent 登记
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- $r('sys.color.ohos_id_color_text_primary')：系统预置的文本主要配色，同一资源 ID 在深浅色下取不同值（出处：ui-dark-light-color-adaptation.md，应用跟随系统的深浅色模式（通过系统资源实现））
- 页面 hex 改成 $r('app.color.*')、共享常量改成 Resource，base 和 dark 都补上对应键后深色生效：修好后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 每个中性色的浅值和深值：源工程主题 CSS 的浅色块和 body.dark / .ios body.dark / .md body.dark 块里同名 --ion-* 变量；浅值写进 base/element/color.json，深值写进 dark/element/color.json，键名两边一致
