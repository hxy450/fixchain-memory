# Compose 行组件转 ArkUI 时，Row 间距照源码，继承的内容色逐个显式写

审的是：代码
触发（任一种）：
- 读到：Compose `Row` 没写 `horizontalArrangement = Arrangement.spacedBy(...)`，间距只靠子项 padding；写错的样子：ArkUI 写成 `Row({ space: … })`，多出源端没有的间距
- 读到：Compose `Text` / `Icon` 没写 color，靠外层 `LocalContentColor` 继承；写错的样子：ArkUI `Text` 没写 `.fontColor(...)`、SVG 图标没写 `.fillColor(...)`，深色主题下仍是默认深色
适用范围：把 Compose 的行组件（列表项、抽屉项、底栏项）转成 ArkUI Row 时
做法：
- 源 Row 没写 spacedBy 就写 Row()，不加 space；写了 Arrangement.spacedBy(n) 才写 Row({ space: n })
- 源端靠 LocalContentColor 继承的颜色，在 ArkUI 每个 Text 上写 .fontColor(<该内容色>)，SVG 图标写 .fillColor(<该内容色>)
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- RowOptions.space?: string | number：Row 子项间距，不写就没有间距（出处：鸿蒙 SDK 的 ets/component/row.d.ts，RowOptions.space）
- Text.fontColor 默认值 '#e6182431'：不写 fontColor 时是固定深色，不随深色主题变（出处：ts-basic-components-text.md，fontColor）
- fillColor(value: ResourceColor): ImageAttribute，只对 SVG 图片生效：图标着色要用 SVG 源图（出处：鸿蒙 SDK 的 ets/component/image.d.ts，ImageAttribute.fillColor）
- ColumnOptions.space?: string | number：同族接口：Column 子项间距，同样照源 Arrangement.spacedBy 写（出处：鸿蒙 SDK 的 ets/component/column.d.ts，ColumnOptions.space）
针对本应用要查的：
- 外层提供的内容色：源码里包住这一行的容器（Surface、NavigationDrawerItem、CompositionLocalProvider 等）的 contentColor，或 MaterialTheme 的 onSurface 一类角色；读出它对应的颜色角色，写进 fontColor / fillColor
