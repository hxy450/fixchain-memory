# 源端有偏好标记控制的首次引导图时，浮层实现引导和标记读写，或在交接中列为差异

审的是：代码
触发（任一种）：
- 读到：源码里引导 ImageView 只在偏好标记为真时 VISIBLE、点击隐藏，显示后随即写回标记；布局为 match_parent 加 android:scaleType="fitXY"；写错的样子：浮层组件里没有引导用的 Image 和首次状态的 @Param，偏好类没有引导标记的读写，交接报告也没列这项差异
适用范围：实现者手里同时有摘要规格和源码，迁移带首次引导的浮层时
做法：
- 对照源码补上：首次状态为真时显示全屏引导图，点击隐藏并写回「已显示」；偏好类加对应的读写方法，资源补引导图
- 这一轮做不了的，在交接里明确列为差异，不只按摘要规格实现
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- FIT_XY：Scale the image using Matrix.ScaleToFit#FILL：源端引导图不保持比例铺满（出处：android.widget.ImageView.ScaleType#FIT_XY）
- ImageFit.Fill：Zoom in or out without maintaining the aspect ratio so that the image fills the display boundary；objectFit(value: ImageFit): ImageAttribute：目标端不保持比例铺满的写法（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，ImageFit.Fill；ets/component/image.d.ts，ImageAttribute.objectFit）
- 浮层加显示引导和引导关闭回调、偏好类加「待显示」读取和「已显示」写入、资源补引导图及无障碍描述后，首次引导和源端一致：修好的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 引导标记的键名和默认值：源工程里读写该标记的偏好方法（getter / setter 的方法体）；读出键名和默认值，目标偏好类用同样的默认值；卡里没核到方法体时以「显示后立即写回」判定它是一次性标记
未核实：源端标记读写方法的方法体和键名卡里没核到，一次性的判断出自「显示后立即写回」
