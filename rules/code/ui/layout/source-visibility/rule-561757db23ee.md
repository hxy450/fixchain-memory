# 源容器 GONE 而内部组件常驻并自报可见性时，目标常建该组件，不用 if 或 Visibility.None 包住

审的是：代码
触发（任一种）：
- 读到：布局里容器 android:visibility="gone"，但 onCreate 无条件用 FragmentTransaction.replace 把 Fragment 挂进去，由这个 Fragment 自己回调宿主切换容器 VISIBLE / GONE；写错的样子：目标把这个组件放进 if(…) 条件分支或 .visibility(Visibility.None) 下，而把可见状态置 true 的正是它自己（aboutToAppear 里经 @Event 上抛）
- 读到：宿主页给本组件预留的槽位外面包着 if(…) 构建条件；写错的样子：条件依赖本组件经 @Event 上抛的状态，组件仍被直接填进这个 if 槽位，宿主条件没改
适用范围：源端容器初始隐藏、内部组件常驻并负责上报可见性，迁成 ArkUI 时
做法：
- 让该组件常建：隐藏时用 .height(0).clip(true) 收起，或用 .opacity(0) 加 .hitTestBehavior(HitTestMode.None)，不用 if 或 Visibility.None 包住
- 写前确认把可见状态置 true 的调用方不在被条件隐藏的子树里；往别人预留的槽位嵌组件前读宿主的构建条件，条件依赖本组件上抛的状态时，先把宿主改成常建或登记接线问题再填
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- if 条件构建和 Visibility.None 下，自定义组件都不实例化；强制 Visible 后 aboutToAppear 随即执行；改成常建（高度 0 + clip）后可见性正常：条件隐藏会让自报可见性的组件永远不构建，形成死锁（出处：卡里修好并验证过）
- if 条件变为 false 时，分支里的组件从父组件中删除：条件分支外的组件不存在，生命周期回调不会执行（出处：arkts-rendering-control-ifelse.md，更新机制示例）
- Visibility.Hidden：隐藏但占位参与布局；Visibility.None：隐藏且不参与布局、不占位：两种隐藏的区别（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，Visibility）
- clip(value: boolean): T：裁掉超出自身尺寸的子内容，配 height(0) 收起（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.clip）
- hitTestBehavior(value: HitTestMode): T：配 opacity(0) 时屏蔽点击（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.hitTestBehavior）
