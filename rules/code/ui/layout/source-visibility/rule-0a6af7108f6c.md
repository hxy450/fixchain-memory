# 截图里缺、源码布局仍有的入口，先查可见性分支，是渠道或开关变体就保留

审的是：代码
触发（任一种）：
- 读到：源 Fragment / Activity 里对这些 tab、入口或区块按渠道（`getChannel()`）、会员或开关分支调用 `setVisibility(View.GONE)`；布局 XML 里它们仍有定义，代码里有点击逻辑；写错的样子：截图对照修复时，目标端把截图里没出现的 tab、入口、详情按钮或整块区域从 `build()` 里删掉，或把对应子组件的调用移除
适用范围：截图对照修复阶段（含修崩溃类问题时）决定删除还是保留截图中未出现、但源码布局和点击逻辑仍存在的界面元素时
做法：
- 删之前在源 Fragment / Activity 里搜这些控件的 setVisibility、getChannel、会员或开关分支，确认是运行变体还是已下线；读源码的输出被截断时分批重读再下结论
- 确认是渠道或开关变体时，按忠实复刻保留完整入口，或实现同等条件的开关（用 if 按同一条件渲染）；修崩溃类问题时不顺带按截图删减页面结构
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 截图只来自一种渠道变体；恢复源码定义的 tab、入口和区块后，页面与另一渠道的截图一致：按源码而非单张截图取舍（出处：卡里修好并验证过）
针对本应用要查的：
- 截图里缺的元素是不是运行变体：源工程里加载该布局的 Fragment / Activity，按控件 id 搜 setVisibility、getChannel、开关或会员判断；能找到按条件隐藏的分支就是变体，保留或照条件实现；找不到再看是否已下线
