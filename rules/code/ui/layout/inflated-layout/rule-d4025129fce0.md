# 源端弹窗加载专用布局 XML 时，读完该布局逐项复刻控件，不按行为代码或通用弹窗拼

审的是：代码
触发（任一种）：
- 读到：源端弹窗由 ViewBinding 类的 inflate(...)、工具方法里的 LayoutInflater.inflate 或 setContentView(R.layout.…) 加载专用布局（标题、ImageView 图标、正文、Button、关闭图标）；计划或审计只给了功能描述，或接线时要解开指向弹窗的 FWD-REF；写错的样子：目标弹窗与源布局 XML 不一致：按行为代码、toast 文案或相邻弹窗外壳拼出，自拟「标题 Text + 文本 + 整宽关闭 Button」的通用结构，或直接调工程现成的通用确认弹窗；缺图标、右上关闭 X、说明文字
适用范围：为源端加载自定义布局的 Dialog / DialogFragment 编写或补建 ArkUI 弹窗（应用内弹层或二级页）时，含接线阶段解 FWD-REF 顺带新建
做法：
- 从调用处定位布局：ViewBinding 类名去掉末尾 Binding、驼峰转小写下划线就是布局名（例：DialogCreateBinding 对应 res/layout/dialog_create.xml），setContentView / inflate 取 R.layout 后的名字；整份读完（或运行 dialog probe 取 dialog_specs）
- 先列出控件清单再写：标题、图标、正文或说明、输入框、按钮数量文案颜色尺寸、关闭入口、遮罩点击、卡体边距都照 XML（dp 写成 vp）；通用确认弹窗缺任何一项都不算等价
- 公共组件目录写不了时，在页面内用 @State 布尔控制的 if 分支渲染 @Builder 浮层，遮罩加 .onClick 关闭
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 读该布局 XML 后逐属性重写弹窗，标题、关闭 X、输入框底色圆角、计数字号颜色、单个确定键和卡体边距与源一致：修复方式（出处：卡里修好并验证过）
- 按源布局重写弹窗、补上图标和右上关闭图、双语标题 / 前缀 / 说明文案后与源一致：修好的做法（出处：卡里修好并验证过）
- 页面内 @Builder 浮层加条件渲染复刻专用布局（标题、图标、正文、单个按钮、关闭图标，点遮罩可关闭）：卡里修好的实现形态，不需要改公共组件目录（出处：卡里修好并验证过）
- if 的条件用状态变量时，值变化会实时渲染；常规变量变化不会：浮层显隐要用 @State 这类状态变量控制（出处：arkts-rendering-control-ifelse.md，使用规则）
- @Builder 内部不能定义状态变量，要通过参数或访问所属组件的状态变量交互：显隐状态和文案放在页面组件上，浮层 @Builder 读它们（出处：arkts-builder.md，@Builder 与 @Component 的差异）
- Dialog#setCancelable 只决定返回键能否关闭：源端点遮罩关闭来自布局里视图的点击 dismiss，要单独复刻成遮罩的 .onClick（出处：android.app.Dialog#setCancelable）
针对本应用要查的：
- 弹窗实际加载的布局文件和其中每个控件：源工程里创建这个弹窗的函数（Dialog 构造、DialogFragment 的 onCreateView、Activity / Fragment 里 show…Dialog 一类调用到的工具方法）里 inflate / setContentView 的参数对应的 res/layout 下的 XML，以及弹窗类里给各控件设的点击监听；按 ViewBinding 命名约定或 R.layout 名找到 XML 整份读完，不截断到一半；逐个控件记下类型、文案引用（@string）、图片引用（@drawable）、尺寸、颜色和点击后做什么（dismiss、复制、跳转），在目标逐项写出
