# 源端经工具方法弹窗时，照该方法加载的布局和各按钮分支实现目标弹窗

审的是：代码
触发（任一种）：
- 读到：源端页面调用工具类的静态方法弹对话框（show…Dialog(this, …) 这类），调用方 lambda 只传了接受回调；被调方法里 inflate 独立布局或 ViewBinding，列表项用 Adapter 渲染；写错的样子：目标弹窗只有标题、Scroll 长文和一个同意 Button，缺列表项和图标、「不同意」按钮、拒绝后的二次确认和退出
- 写错的样子：弹窗按钮文案用 $r('app.string.…') 借了别的页面的字符串；源弹窗列表项的 drawable 在目标里没有对应的 $r('app.media.…') 引用
适用范围：源端经工具类方法弹出的对话框（隐私同意这类带列表和多按钮的），迁成 ArkUI 弹窗时
做法：
- 先打开被调的工具方法和它 inflate 的布局 XML / ViewBinding，列出标题、列表项和图标、按钮文案，以及每个按钮回调的分支（如 不同意→二次确认弹窗→退出进程）
- 目标弹窗逐项实现：按钮数量和文案与源弹窗一致、每个分支都有处理，列表项图标写成 Image($r('app.media.<资源名>'))，引用已迁过来的同名图标
- 标题、正文、按钮文案用源弹窗自己的字符串资源，不借用其他页面的字符串
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- $r('app.type.name')：访问本模块 media、string 等资源的写法，type 是资源类型，name 是资源名（出处：resource-categories-and-access.md，资源访问）
- 按源布局复刻图标卡片列表、底部「不同意 / 已阅读并同意」两个按钮，并补上「不同意→二次确认→退出」：卡里的修法（出处：卡里修好并验证过）
针对本应用要查的：
- 源弹窗的结构和分支：源工程里被调的弹窗工具方法，以及它 inflate 的布局 XML 和列表项布局；布局里读出标题、列表项、按钮控件和它们引用的 @string、@drawable；方法里读出每个按钮的点击回调分别走到哪（关闭、弹确认、退出）
