# 源端文本连同两侧间距随进度收到 0 时，目标的 padding/margin 也按选中条件取 0

审的是：代码
触发（任一种）：
- 读到：Compose 自定义 Layout 里文本 Box 带 Modifier.padding(horizontal = …)，摆放时用文本 Placeable.width × 动画进度求图标 x，未选中时文本连同间距宽度为 0、图标居中；写错的样子：对应 Text 上写着无条件的 .padding({ left: 常量 }) 或 .margin(...)，只靠 constraintSize({ maxWidth: 选中 ? N : 0 })、opacity、scale 折叠文本
适用范围：把源端按动画进度收放图标与文本位置的自定义布局（如底部导航项）翻译成 ArkUI Row 加属性时
做法：
- 源端随进度缩放的每个量逐项对应到目标属性：间距写成 .padding({ left: this.selected ? 间距 : 0 })（margin、Row 的 space 同理），与 maxWidth/opacity/scale 放进同一个 spring 动画一起收放
- 不依赖拿不准的框架行为（如 constraintSize 的 maxWidth: 0 是否把 padding 一起压掉），间距直接按选中条件赋值；不以“偏移很小、不可感知”保留已算出的偏差
- 按未选中态手算一次：图标中心偏移 = −(图标之后仍占位的宽度)/2，结果应为 0
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- constraintSize({ maxWidth: 0 }) 时 Text 上无条件的左 padding 仍占位，未选中图标比槽位中心偏左半个间距；改成按选中条件给 0 后居中：卡里实测的行为（出处：卡里修好并验证过）
- padding(value: Padding | Length | LocalizedPadding): T，默认 0，单位 vp：组件内边距（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.padding；ts-universal-attributes-size.md，padding）
- margin(value: Margin | Length | LocalizedMargin): T：组件外边距，间距写在 margin 上时同样按选中条件取 0（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.margin）
- constraintSize(value: ConstraintSizeOptions): T，默认 {minWidth: 0, maxWidth: Infinity, minHeight: 0, maxHeight: Infinity}：组件布局时的尺寸范围限制（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.constraintSize）
- space?: string | number：Row 子组件之间的间距，用它放图文间距时也按选中条件取 0（出处：鸿蒙 SDK 的 ets/component/row.d.ts，RowOptions.space）
未核实：constraintSize 的 maxWidth 是否钳住 padding，声明和文档都没写，只有卡里的实测偏移
