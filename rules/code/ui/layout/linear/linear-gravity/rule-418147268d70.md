# 嵌套 Compose Column 都没写对齐时，外层和内层 ArkUI Column 都写 Start

审的是：代码
触发（任一种）：
- 读到：外层满宽卡片 `Column(Modifier.clickable)` 里套一个只带 `Modifier.padding(...)`、没有 `fillMaxWidth` 的文本 `Column`，两层都没写 `horizontalAlignment`；写错的样子：只有内层文本 `Column` 写了 `.alignItems(HorizontalAlign.Start)`，外层根 `Column` 没有 `alignItems`，宽度随内容的文本块被居中；转换报告却写「满宽 Column 显式 alignItems(Start)」
适用范围：把嵌套的 Compose Column 迁成两层 ArkUI Column、内层宽度随内容时
做法：
- 两层 Column 都写 `.alignItems(HorizontalAlign.Start)`；或者给内层写 `.width('100%')` 再加 `.alignItems(HorizontalAlign.Start)`。内层的 alignItems 只排它自己的子项，不决定内层块在父 Column 里的位置
- 写完按源码逐个 `Column(` 列出对应的 ArkUI Column，源端默认 Start 的每一层都要能指出 alignItems(Start) 写在哪一行，根容器那一行最容易漏；转换报告声明之前也逐个核对
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- alignItems(value: HorizontalAlign): ColumnAttribute：Column 子组件的水平对齐，只作用于这一层的直接子项（出处：鸿蒙 SDK 的 ets/component/column.d.ts，ColumnAttribute.alignItems）
- 默认值：HorizontalAlign.Center：根 Column 不写 alignItems 时，内容宽的子块按自身宽度居中（出处：ts-container-column.md，alignItems）
- 根 Column 补 .alignItems(HorizontalAlign.Start) 后，几张卡的标题、正文起点都等于卡片左边加源端 padding：修好后的表现（出处：卡里修好并验证过）
未核实：内层改写 width('100%') 加 Start 的写法卡里没有上机验证，出自建议
来源：1 张卡，1 个应用
