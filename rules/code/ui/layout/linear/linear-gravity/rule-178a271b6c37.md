# 源端子项贴起始边时，目标 Column 显式写 alignItems 为 Start

审的是：代码
触发（任一种）：
- 读到：纵向 `LinearLayout` 没写 android:gravity，子项也没有 android:layout_gravity；写错的样子：撑满宽的 Column 没写 .alignItems(...)，wrap_content 子项居中
- 读到：ConstraintLayout 的 wrap_content 子元素写 app:layout_constraintStart_toStartOf="parent"；写错的样子：Column 没写 .alignItems(...)，子元素居中
- 读到：Compose `Column(...)` 没写 `horizontalAlignment`；写错的样子：ArkUI `Column()` 没写 `.alignItems(...)`，内容宽的 `Text` 只加了 `textAlign(TextAlign.Start)`，仍整块居中
适用范围：源端子项默认或按约束贴起始边，迁成 ArkUI Column、子项是固定尺寸或内容宽
做法：
- Column 写 .alignItems(HorizontalAlign.Start)；源端写了 center / center_horizontal 才用 Center，个别要居中的子项用 .alignSelf(ItemAlign.Center)
- 或给 Text 写 .width('100%').textAlign(TextAlign.Start)；内容宽 Text 的 textAlign、父 Stack 的 .alignContent(Alignment.TopStart) 都不改子项位置
- 逐个对照本页每个 Column( 的源端对齐；源端写 fillMaxWidth() 加 TextAlign.Center 的才居中
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- alignItems(value: HorizontalAlign): ColumnAttribute，默认值 HorizontalAlign.Center：Column 的交叉轴（水平）对齐，不写时居中（出处：鸿蒙 SDK 的 ets/component/column.d.ts，ColumnAttribute.alignItems；ts-container-column.md，alignItems）
- HorizontalAlign.Start：按语言方向贴起始边（随 RTL 翻转），对应安卓的 start 和 Compose 的 Alignment.Start（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，HorizontalAlign.Start）
- LinearLayout 的 mGravity 默认是 Gravity.START | Gravity.TOP：源端没写 gravity 时子项贴起始边（出处：android.widget.LinearLayout#mGravity）
- 纵向布局时子项没写 layout_gravity 就用容器 gravity 的水平部分，落到 default 分支 childLeft = paddingLeft + lp.leftMargin：默认贴左（起始边）的代码出处（出处：android.widget.LinearLayout#layoutVertical）
- textAlign(value: TextAlign): TextAttribute，默认 TextAlign.Start；文字占满 Text 组件自身的宽度：textAlign 只在 Text 自己的框内排文字，Text 是内容宽时不起作用（出处：鸿蒙 SDK 的 ets/component/text.d.ts，TextAttribute.textAlign）
- Compose Column 不写 horizontalAlignment 时子项靠起始边（Start）：源端的默认，迁过去要显式写出（出处：卡里修好并验证过）
- 补上 .alignItems(HorizontalAlign.Start) 后图标回到左上、标题回到卡片起始边，文字不再在卡片内居中：修好后的效果（出处：卡里修好并验证过）
- 文本加 `.width('100%').textAlign(TextAlign.Start)` 后贴起始边，与源端一致：修好后的另一种写法（出处：卡里修好并验证过）
