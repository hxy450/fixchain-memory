# Row 用 IntrinsicSize.Min 定高时，算出固有高度写显式 height，子项保留 top 偏移

审的是：代码
触发（任一种）：
- 读到：Compose Row(Modifier.height(IntrinsicSize.Min)) 内子项 Modifier.fillMaxHeight().padding(top = …)；写错的样子：目标 Row 没有显式 height，子项改成垂直居中并删掉源码的 top 偏移（以 P-20 百分比撑满为由）
适用范围：Compose Row 用 IntrinsicSize.Min 让子项 fillMaxHeight 对齐最高兄弟时
做法：
- 先算出固有高度（取最高子项，例：IconButton 为 48），给 Row 写 .height(48) 这样的显式高度
- 子项写 .height('100%')，保留 .align(Alignment.Top) 和 .padding({ top: … })；P-20 只提醒不定高父级下百分比会撑满，父级定高后就能用
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- align(value: Alignment): T：组件内容在自身区域里的对齐，写 Alignment.Top 让文字靠上（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.align）
- 头部 Row height(48)、标题 height('100%') + align(Top) + padding top 8：修复时用的写法，标题位置和源端一致（出处：卡里修好并验证过）
针对本应用要查的：
- Row 的固有高度：源 Compose 代码里这个 Row 的各子项；取各子项固有高度的最大值；例：含 IconButton 时是 48
