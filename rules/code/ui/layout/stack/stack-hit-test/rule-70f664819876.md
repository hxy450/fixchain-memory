# 安卓叠放层吞触摸时，目标逐节点写 hitTestBehavior，不靠空 onClick 和缺省值

审的是：代码
触发（任一种）：
- 读到：叠在列表上的条体样式或布局写 android:clickable="true"，条体自己消费触摸、不下穿；写错的样子：目标条体只写空 .onClick(() => {})（注释称吞掉触摸），没有 hitTestBehavior；承载它的叠放 Stack 是 HitTestMode.Transparent，点条体时下层列表的 onTouch 也触发
- 读到：FrameLayout 根内的层序：列表在下，撤销条、浮动按钮组依次叠在上面，按钮消费触摸后下层收不到；写错的样子：浮动按钮组根 Stack 为 HitTestMode.Transparent，主钮、子钮只挂 onTouch / onClick 用缺省命中，承载 padding 的包装节点也是缺省命中
适用范围：Stack 叠放的撤销条、浮动按钮、提示条等覆盖在可交互内容上的层
做法：
- 逐个节点写明 .hitTestBehavior(...)：要吞触摸、里面还有可点子节点的条体用 HitTestMode.BLOCK_HIERARCHY（宿主 Transparent 时必须用它）；按钮用 HitTestMode.Block
- 只做占位或承载 padding 的包装节点用 HitTestMode.None；空 onClick 不改变命中测试，不能当阻断用
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- hitTestBehavior(value: HitTestMode): T；缺省 Default：自身和子节点响应，挡住兄弟节点，不影响祖先节点的命中：命中测试的设置和缺省行为（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.hitTestBehavior）
- HitTestMode：Default、Block（自身响应，挡住子节点和被它遮住的节点）、Transparent（自身和子节点响应，也放行被遮住的节点）、None（自身不响应，子节点响应）、BLOCK_HIERARCHY（@since 20，挡住所有低优先级的兄弟和父节点）：各模式的含义（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，HitTestMode）
- 条体改 BLOCK_HIERARCHY、按钮改 Block、包装节点改 None 后，点叠放层不再触发下层，点空白下层仍可达：修复后的写法（出处：卡里修好并验证过）
未核实：卡里的行为在 API 24（6.1.1）上观察，声明按本机 API 23 核实
