# 按钮上叠了不可点的进度环时，上层设 Transparent 命中或把 onClick 挂到 Stack 上

审的是：代码
触发（任一种）：
- 读到：源布局里可点的按钮之后声明了没有 id、没有 android:clickable 的自绘进度环或 ProgressBar，叠在按钮上；写错的样子：目标 Stack 里 onClick 只挂在最底层 Image 上，同尺寸（width('100%').height('100%')）的进度环、LoadingProgress 没写 hitTestBehavior
适用范围：把安卓叠放的按钮和展示层迁成 ArkUI Stack 并保留 z 序时，包括控件排里的按钮环和加载层
做法：
- Stack 里每个在按钮上面的纯展示节点写 .hitTestBehavior(HitTestMode.Transparent)；或者把 onClick 挂在整个 Stack 容器上，不只挂在最底层 Image
- 自检覆盖所有 Stack 叠层：搜同一 Stack 里 width('100%').height('100%') 的兄弟节点，逐个确认写了 hitTestBehavior 或 onClick 落在容器上
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- hitTestBehavior(value: HitTestMode): T：组件的命中测试方式；不写时为 Default：自己和子节点响应，被它盖住的兄弟节点收不到（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.hitTestBehavior）
- HitTestMode.Transparent：自己和子节点响应，同时让被它盖住的节点也能命中；纯展示层用它（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，HitTestMode.Transparent）
- HitTestMode.None：自己不响应，子节点照常响应（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，HitTestMode.None）
- View 只有 CLICKABLE / LONG_CLICKABLE / CONTEXT_CLICKABLE 时才在 onTouchEvent 里消费触摸：源端没写 clickable 的进度环、ProgressBar 不吞点击，触摸交给下层按钮（出处：android.view.View#onTouchEvent）
- 把 onClick 从底层 Image 移到外层 Stack 容器后播放键可点：卡里的修法（出处：卡里修好并验证过）
