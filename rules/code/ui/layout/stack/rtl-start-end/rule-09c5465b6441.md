# 同一元素用了会镜像的逻辑对齐时，边距也用 start/end，不和 margin({ right }) 混用

审的是：代码
触发（任一种）：
- 读到：源布局 XML 里同一个控件同时有 android:layout_gravity="bottom|end" 和 android:layout_marginEnd；写错的样子：目标外层用 Stack({ alignContent: Alignment.BottomEnd }) 或 HorizontalAlign.End，而同一元素的边距写成 .margin({ right: … })
适用范围：源应用清单 android:supportsRtl="true"，一个元素的位置由对齐和边距共同决定时
做法：
- 对齐和边距用同一套键：逻辑对齐 Alignment.BottomEnd / HorizontalAlign.End 配 .margin({ bottom: LengthMetrics.vp(b), end: LengthMetrics.vp(<layout_marginEnd>) })
- 确有理由要固定物理方向时，对齐和边距都写物理的，并在注释里写明理由
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Alignment.BottomEnd / HorizontalAlign.End 随 RTL 镜像，margin({ right }) 不镜像：两者混用时 RTL 下元素到了左侧，边距却还留在右侧（出处：卡里修好并验证过）
- 组件 direction 为 Direction.Rtl，或为 Direction.Auto 且系统语言从右向左时，镜像生效；Stack、Row、Column 已默认适配镜像：逻辑对齐会镜像的条件（出处：arkts-internationalization.md，使用镜像能力）
- LocalizedMargin = LocalizedPadding（start/end/top/bottom 都是 LengthMetrics）：逻辑边距的写法（出处：鸿蒙 SDK 的 ets/component/units.d.ts，LocalizedMargin）
未核实：卡里环境是 API 24，本机按 API 23 的声明和文档核实
