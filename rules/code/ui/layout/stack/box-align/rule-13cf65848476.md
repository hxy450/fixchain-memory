# Stack 子项不靠 .align() 定位，改用 alignContent 或 .position

审的是：代码
触发（任一种）：
- 写错的样子：Stack 子项上写 .align(Alignment.Start / End / Top / Bottom) 想贴到容器边上，结果落在中央或左缘
- 读到：Compose `Box` 里子项 `Modifier.align(Alignment.CenterEnd)` 等，贴右缘、底部或角落；写错的样子：对应的 Stack 子组件上写 .align(Alignment.End)
- 读到：Compose `Scaffold(snackbarHost = { SnackbarHost(...) })` 的底部槽位；写错的样子：Snackbar 外层在根 Stack 里写 .align(Alignment.Bottom)
- 读到：Compose `drawCircle` 按 Offset 把角标圆点画到图标右上；写错的样子：圆点在 Stack(Center) 里写 .align(Alignment.TopEnd)
适用范围：ArkUI Stack 里给尺寸小于容器的子项定位时
做法：
- 所有子项同向贴边时写 Stack({ alignContent: Alignment.Start })
- 单个子项贴边贴角写 .position(Edges)：贴右 { right: 0, top: 0 }，贴底 { left: 0, bottom: 0 }，角标 { right: 2, top: 2 }；首尾分置用与 Stack 同尺寸的 Row / Column 加 Blank()
- 自检 Stack 里每个小于容器的子项，位置要来自 alignContent、position 或 offset
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- align(value: Alignment): T，说明是设置组件内容在绘制区域内的对齐方式，默认 Alignment.Center：子项的 .align 只对齐它自己的内容，不改它在 Stack 里的位置（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.align）
- StackOptions.alignContent?: Alignment，@default Alignment.Center；alignContent(value: Alignment): StackAttribute：Stack 里子项的对齐由容器决定（出处：鸿蒙 SDK 的 ets/component/stack.d.ts，StackOptions.alignContent、StackAttribute.alignContent）
- position(value: Position | Edges | LocalizedEdges): T：相对父组件的绝对定位；Edges 形式（top/left/bottom/right）自 @since 12；父容器宽高为 0 时不可用（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.position；ets/component/units.d.ts，Edges）
- offset(value: Position | Edges | LocalizedEdges): T：同族接口：相对原位置的绘制偏移，不影响父容器布局（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.offset）
- alignContent(value: Alignment): FolderStackAttribute：同族接口：FolderStack 的子项对齐（出处：鸿蒙 SDK 的 ets/component/folder_stack.d.ts，FolderStackAttribute.alignContent）
- 改成 .position 后滚动条从 Stack 左缘移到右缘，Snackbar 回到底部：修复后的观察（出处：卡里修好并验证过）
未核实：角标圆点修复后没有视觉验证
