# ArkTS 里出现 Alignment.CenterStart 等 Compose 名时，换成实有枚举并按语义重选接口

审的是：代码
触发（任一种）：
- 读到：Compose 源码或问题单里用 Compose 的对齐名描述位置，如 `Alignment.CenterStart`；写错的样子：.ets 里写了 `Alignment.CenterStart`（ArkUI 的 Alignment 没有这个成员，编译不过）
- 读到：Compose 源码 `Modifier.align(Alignment.CenterEnd)` 等 BoxScope 对齐写法；写错的样子：ArkTS 里出现 `Alignment.CenterEnd`（编译报不是 ArkUI 枚举），或编译修复把它换成最近的名字 .align(Alignment.End) 了事
适用范围：ArkUI 代码里给 align、alignContent 等传 Alignment 枚举值，或转换、编译修复时遇到照搬过来的 Compose 枚举名
做法：
- 只用 ArkUI Alignment 实有的九个名字；纵向居中、靠起始边写 `Alignment.Start`，不照搬 Compose 的 `Alignment.CenterStart`
- 把 Compose 名当成逐词照搬的信号，回到源端语义重选接口：Compose 的子项定位对应 Stack 子组件的 .position 或 Stack 的 alignContent，不只换成近名的 .align(...)
- 编译修复只做名字替换时，确认替换后的属性能实现源端位置；做不到的在回执里作为行为风险报告，交给实现或收口阶段
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Alignment：TopStart、Top、TopEnd、Start、Center、End、BottomStart、Bottom、BottomEnd：ArkUI 对齐枚举的全部成员，没有 CenterStart、CenterEnd、TopCenter 这类 Compose 名字；End 是「纵向居中、横向贴尾」，换成它后仍是内容对齐，不是子项定位（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，Alignment）
- Alignment.Start：起始端、纵向居中（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，Alignment.Start）
- 写 `Alignment.CenterStart` 编译不过，构建修复时被改成 `Alignment.Start`：照搬 Compose 名字会直接导致构建失败（出处：卡里修好并验证过）
- align(value: Alignment): T：同族接口：所有组件的内容对齐，参数是 Alignment（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.align）
- alignContent(value: Alignment): StackAttribute：同族接口：Stack 子组件的对齐，参数是 Alignment（出处：鸿蒙 SDK 的 ets/component/stack.d.ts，StackAttribute.alignContent）
未核实：Compose Alignment.CenterStart 的定义本机没有源码可核
