# RelativeLayout 里没有相对规则的子 View 会叠放，目标用 Stack 叠放，不改成 Column

审的是：代码
触发（任一种）：
- 读到：RelativeLayout 下几个子 View 都没有 android:layout_below、android:layout_above、android:layout_toRightOf 等相对规则，落在同一块区域（常见于固定高度的 item 里叠放两条曲线）；写错的样子：目标把这些子组件放进 Column 顺序排列、各占一段 height，列被拉长，底部内容被裁切
适用范围：把安卓 RelativeLayout（尤其是固定尺寸的 item 布局）迁成 ArkUI 布局时
做法：
- 没有相对规则的子 View 放进同一个 Stack 叠放，用 .position({ x: <layout_marginLeft>, y: <layout_marginTop> }) 定位到源端的同一坐标；Stack 默认居中，不用 position 时写 Stack({ alignContent: Alignment.TopStart }) 贴左上
- 自检：目标里各子区块高度之和应等于源 item 的固定高度，叠放的几个子 View 只算一次高度
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- RelativeLayout 里横向、纵向都没有规则的子 View，LTR 下放在左上（RTL 下右上），按自己的 margin 偏移：没有相对规则的几个子 View 因此叠在同一坐标（出处：android.widget.RelativeLayout#positionChildHorizontal）
- (options?: StackOptions): StackAttribute；StackOptions.alignContent 默认 Alignment.Center：Stack 的构造；子组件默认居中，和 RelativeLayout 的左上不同（出处：鸿蒙 SDK 的 ets/component/stack.d.ts，StackInterface、StackOptions.alignContent）
- position(value: Position | Edges | LocalizedEdges): T：相对父组件的绝对定位，用来把叠放的子组件放到同一坐标（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.position）
- 两条曲线改为同一 Stack 内 position({ y: <源端 marginTop> }) 叠放后，列高回到源 item 的固定高度，底部不再被裁切：修好后的写法（出处：卡里修好并验证过）
- offset(value: Position | Edges | LocalizedEdges): T：同族接口：相对自身原位置偏移，仍占原来的布局位置（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.offset）
针对本应用要查的：
- 叠放子 View 的坐标和所在区域的尺寸：源工程 item 布局 XML 里这个 RelativeLayout 及其子 View 的 android:layout_marginTop、layout_marginLeft、layout_width、layout_height；dp 值按 vp 写进目标的 width、height 和 position 的 x、y
