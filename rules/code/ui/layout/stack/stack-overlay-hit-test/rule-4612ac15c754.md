# 源端只在播放时 addView 全屏覆盖层、播完移除时，目标用 if 条件挂载，不常驻

审的是：代码
触发（任一种）：
- 读到：源端动效在触发时才 decorView / rootView.addView(overlay, MATCH_PARENT)，结束回调和取消时 removeView 移除，overlay 设 isClickable = false；写错的样子：目标把全屏覆盖组件无条件挂在页面、弹层或 Sheet 上（.width('100%').height('100%').zIndex(...)），空闲时只 clearRect，只靠内部 Canvas 的 .hitTestBehavior(HitTestMode.None) 让出点击
适用范围：把安卓一次性的窗口级全屏覆盖动效迁成 ArkUI 自定义组件加 Canvas，挂到页面、弹层或 Sheet 上时
做法：
- 调用处写成 if (this.playing) { 覆盖组件({...}).width('100%').height('100%').zIndex(...) }：playing 只在播放期间为 true，播放结束回调和取消时置回 false，组件随之移除
- 覆盖组件在 aboutToAppear() 里启动首帧，不做成常驻组件再靠状态监听触发播放
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- hitTestBehavior(value: HitTestMode): T，默认 HitTestMode.Default：不设时节点和子节点都响应，并挡住被它盖住的兄弟节点（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.hitTestBehavior）
- HitTestMode.None：自身不响应、子节点照常响应；HitTestMode.Default：自身和子节点响应，屏蔽被盖住的其他节点：None 只作用于设了它的那个节点；外层没设的全屏节点仍按 Default 挡住下层（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，HitTestMode）
- aboutToAppear?(): void：自定义组件新实例创建后、build() 执行前调用，条件挂载时在这里启动播放（出处：鸿蒙 SDK 的 ets/component/common.d.ts，BaseCustomComponent.aboutToAppear）
- 空闲态常驻的全屏覆盖组件即使内部 Canvas 设了 HitTestMode.None，下层页面仍点不动、滑不动；改为只在播放期间条件挂载后恢复：常驻加 None 不等于源端的「播放时才挂、播完移除」（出处：卡里修好并验证过）
