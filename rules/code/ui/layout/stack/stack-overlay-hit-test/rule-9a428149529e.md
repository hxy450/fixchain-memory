# 页面全屏遮罩用无 padding 根 Stack 的条件子节点，不在带 padding 的容器上 .overlay()

审的是：代码
触发（任一种）：
- 读到：同仓已有页面在 NavDestination 下无 padding 的根 Stack 里用 if (…) 条件子节点铺全屏遮罩（保存中 loading、成功引导）；当前页根容器是带安全区 padding 的 Column；写错的样子：在带 padding 的根 Column 上写 .overlay(this.xxxOverlay())，builder 里 if (…) 条件渲染遮罩；遮罩底部 padding 带不变暗，遮罩上的 SaveButton 点击日志是 Touch test result is empty
适用范围：给页面加覆盖整屏的 loading 或引导遮罩（遮罩上可能还有可点控件），页面根容器带安全区 padding 时
做法：
- 页面根改成（或外包一层）无 padding 的 Stack：内容层带安全区 padding，遮罩写成内容之后的 if (state) { Column(){…}.width('100%').height('100%') } 条件子节点
- 复用同仓已有遮罩时，连同它的挂载层级（根 Stack 条件子节点）一起复用，不只复制遮罩内容
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- overlay(value: string | CustomBuilder | ComponentContent, options?: OverlayOptions): T：给当前组件加浮层（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.overlay）
- 浮层的定位基于当前组件计算；浮层不通过组件树进行渲染：overlay 跟着所挂组件走，不是页面级的一层（出处：ts-universal-attributes-overlay.md，overlay）
- overlay 挂在带 padding 的 Column 上时底部 padding 带不变暗、SaveButton 命中为空；改为无 padding 根 Stack 条件子节点后遮罩盖满、点击被接受：修好后的挂载方式（出处：卡里修好并验证过）
