# 原生地图上叠 ArkUI 控件时写明触摸分工，纯视觉层设 HitTestMode.None

审的是：代码
触发（任一种）：
- 读到：参考实现里 MapViewComponent（或其他原生 XComponent 地图）100% 宽高放在最底层，上面叠搜索栏、按钮等 ArkUI 覆盖层；参考的承载页用 HitTestMode.Transparent / HitTestMode.None 划分地图和控件的触摸；写错的样子：地图组件和覆盖层容器都没写 .hitTestBehavior(…)，覆盖层控件点不动
适用范围：原生地图组件（XComponent 承载）之上叠放 ArkUI 控件的页面
做法：
- 地图只作视觉层时：MapViewComponent(...).hitTestBehavior(HitTestMode.None)
- 地图需要手势时：盖在地图上的全宽覆盖容器写 .hitTestBehavior(HitTestMode.Transparent)，覆盖层自己的控件照常响应
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- hitTestBehavior(value: HitTestMode): T，默认 HitTestMode.Default（自身和子节点响应，兄弟节点被挡）：所有组件共有的触摸测试属性（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.hitTestBehavior）
- HitTestMode.None：自身不响应触摸测试，子节点响应：给地图组件用，地图只作视觉层（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，HitTestMode.None）
- HitTestMode.Transparent：自身和子节点响应，同时允许被它盖住的节点也参与触摸测试：给覆盖层容器用，触摸能穿到下面的地图（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，HitTestMode.Transparent）
- MapViewComponent 加 .hitTestBehavior(HitTestMode.None) 后覆盖层可点，作为最终保留的方案：纯视觉层方案（出处：卡里修好并验证过）
未核实：地图 Surface 本身是否独立拦截点击，卡里和 Swiper enabled 的修复同批安装，没单独验证
