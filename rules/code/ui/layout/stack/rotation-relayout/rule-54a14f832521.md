# 布局控制器已产出逐控件摆位时，按钮层按摆位解算渲染，不用固定百分比 position

审的是：代码
触发（任一种）：
- 读到：源 Activity 运行时按界面方向和系统朝向重排 RelativeLayout 子控件；目标布局状态里有控制器产出的逐控件摆位（边、沿边偏移、margin），注释写「按钮层消费」；写错的样子：页面按钮层用固定百分比 .position({ x: 'NN%', y: 'NN%' }) 摆主控件列和面板，只取摆位状态里的按钮尺寸，不按逐控件摆位渲染
适用范围：源端运行时重排控件、目标端由状态产出摆位并由页面按钮层渲染时
做法：
- 按钮层逐个消费摆位：先在实测视口（onAreaChange 拿到的 vp 宽高）上把边、沿边偏移、margin 解算成坐标并按朝向变换，再用 .position({ x, y }) 渲染每个控件
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- position(value: Position | Edges | LocalizedEdges): T：按解算出的坐标定位控件（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.position）
- onAreaChange(event: (oldValue: Area, newValue: Area) => void): T：拿实测视口宽高，作为解算的输入（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onAreaChange）
- 新增解算函数在实测 vp 视口上解算摆位并按朝向变换，页面用参数化的定位 Builder 渲染各控件和面板：修复后的写法（出处：卡里修好并验证过）
未核实：卡里的环境是 HarmonyOS 6.1.1(24)，声明按本机 API 23 核实
