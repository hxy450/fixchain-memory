# 叠层子层 layout_width=match_parent 时，Stack 子节点写 .width('100%')

审的是：代码
触发（任一种）：
- 读到：条目布局用 FrameLayout 叠放封面和底部信息条，信息条 android:layout_width="match_parent"、android:layout_gravity="bottom"；写错的样子：Stack 里对应的 Row 只写了 .height / .padding / .justifyContent(FlexAlign.Center)，没有 .width('100%')，条带按内容宽度收窄
适用范围：把 RecyclerView 条目里的叠层布局转成 ArkUI Stack 加 Row / Column 时
做法：
- 逐个子层对照源 XML 的 layout_width / layout_height：match_parent 写 .width('100%') / .height('100%')，不因已写 justifyContent(Center) 或父容器定了尺寸就省略
- Stack 内贴边条带核对几何是否等于源层的覆盖区域（宽、高、贴哪条边）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- width(value: Length): T；不设时宽度取能完整容纳内容的宽度：不写 width 的 Row 按内容收窄，不会像 match_parent 那样撑满父容器（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.width）
- match_parent = -1：和父容器一样大（减去内边距）；wrap_content = -2：只包住内容：源端两个取值的含义（出处：Android SDK 平台资源 data/res/values/attrs.xml，ViewGroup_Layout 的 layout_width（按应用的 compileSdk 取对应平台））
- 补上 .width('100%') 后遮条铺满卡宽：修复后的观察（出处：卡里修好并验证过）
未核实：卡里环境是 API 24，本机按 API 23 的声明核实
