# Compose 链里 padding 在 background/shape 之前时，内距放外层，背景和圆角放内层组件

审的是：代码
触发（任一种）：
- 读到：Compose Modifier 链里 .padding(...)、statusBarsPadding()、navigationBarsPadding() 写在 .background(...)、.clip(...) 之前；写错的样子：同一组件上同时写 .padding(...) 和 .backgroundColor(...) / .borderRadius(...)
- 读到：Surface 类包装组件 Surface(color = …, shape = …, modifier = modifier.padding(...)) 收到的 modifier 带 padding；写错的样子：外层容器上写 .height(...).padding(...).borderRadius(...).backgroundColor(...)
适用范围：把 Compose 的 Modifier 链翻成 ArkUI 属性，链中有 background、clip 或形状时
做法：
- 标出 background / clip / 形状在链中的位置：它之前的 padding、statusBarsPadding、navigationBarsPadding 写到外层容器的 .padding(...)，或改用 .margin(...)、位移；.backgroundColor()、.borderRadius()、.clip(true) 写到内层组件
- 包装组件收到的 modifier 算在它的背景之前；只有在 background 之后的 padding 才和背景同组件
- 核对「圆角基准高度 = 背景所在组件高度」：圆角按内距以内尺寸算的，背景要在同尺寸的内层组件上
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- padding(value: Padding | Length | LocalizedPadding): T：组件内边距，默认 0（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.padding）
- 宽高 80 的 Row 带 padding 和 margin(20)、backgroundColor(Color.White)：内边距是白色区域，外边距是父容器的蓝色区域：ArkUI 组件自己的背景涂满内边距区域，外边距不涂；内距要留白就得放到背景组件之外（出处：ts-universal-attributes-size.md，示例1（设置组件的宽高和边距））
- margin(value: Margin | Length | LocalizedMargin): T；在计算位置时外边距视为组件大小的一部分，从而影响组件位置：可替代外层 padding 的写法之一（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.margin；ts-universal-attributes-size.md，margin）
- The radius is restricted by the component size. The maximum value is half of the component width or height.：borderRadius 按它所在组件的尺寸生效，圆角基准要和背景所在组件一致（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.borderRadius）
- 把 borderRadius、backgroundColor、clip 移到内层 Stack，外层只留 padding 后，内距恢复、药丸只画在内距以内：修好的写法（出处：卡里修好并验证过）
