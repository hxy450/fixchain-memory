# 库组件内部给的单侧 inset，目标按侧写 padding({ start })，不扩成两侧对称

审的是：代码
触发（任一种）：
- 读到：源是 Compose Material3 TopAppBar（或 IconButton、Scaffold 等库组件），title 槽里的 Row / Text / IconButton 只有 weight、align，没有 Modifier.padding；写错的样子：目标端 title Row 上写 .padding({ left: 16, right: 16 }) 这类两侧对称留白，常量注释却写的是起始侧的 TopAppBarTitleInset
适用范围：源端留白由库组件内部布局决定、源码里没有显式 padding 修饰符，目标端要补这份留白时
做法：
- 按库的布局规则分侧写：哪一侧有 inset、由什么槽位撑开；M3 TopAppBar 没有导航图标时标题只在起始侧有 16dp inset，写成 .padding({ start: LengthMetrics.vp(16) })（import { LengthMetrics } from '@kit.ArkUI'），末端不加
- 常量注释写明这个值来自哪条库规则、作用于哪一侧
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- padding(value: Padding | Length | LocalizedPadding): T：padding 可传 LocalizedPadding，按 start/end 分侧（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.padding）
- LocalizedPadding { top?: LengthMetrics; end?: LengthMetrics; bottom?: LengthMetrics; start?: LengthMetrics }：分侧 padding 的各边取 LengthMetrics，不能直接写 number（出处：鸿蒙 SDK 的 ets/component/units.d.ts，LocalizedPadding）
- static vp(value: number): LengthMetrics：以 vp 为单位构造 LengthMetrics（出处：鸿蒙 SDK 的 ets/api/arkui/Graphics.d.ts，LengthMetrics.vp）
- .padding({ start: LengthMetrics.vp(<标题起始 inset>) })，末端不加；IconButton（48dp）贴末端，图标距屏缘 12vp，与安卓一致：M3 TopAppBar 无导航图标时 title Row 的留白写法（出处：卡里修好并验证过）
- safeAreaPadding(paddingValue: Padding | LengthMetrics | LocalizedPadding): T：同族接口：安全区 padding，同样接受 LocalizedPadding（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.safeAreaPadding）
针对本应用要查的：
- 库组件内部各槽位两侧的 inset 和宽度：androidx.compose.material3:material3 的 TopAppBar 布局实现（按应用依赖的 compose BOM 版本）；本机 Gradle 缓存里多半只有编译产物；读出标题槽起始/末端的 inset、导航和动作槽的宽度，各侧分别写；查不到源码时按卡里核过的值写并在注释里写明出处
未核实：M3 TopAppBar 的 TopAppBarTitleInset 等内部留白没在本机核实（缓存里没有 material3 源码），按卡写
