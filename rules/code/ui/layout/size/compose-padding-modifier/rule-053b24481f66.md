# statusBarsPadding 在 background 之前时，不在带背景的同一组件上加顶部 padding

审的是：代码
触发（任一种）：
- 读到：Compose 链 heightIn(min = …).statusBarsPadding() 之后才有 .background(...)，状态栏内距在背景之前、不涂色；写错的样子：同一个带 .backgroundColor(...) 的组件上写 .padding({ top: 状态栏高度 }) 和 .constraintSize({ minHeight: … })，状态栏区被涂成背景色
适用范围：沉浸式布局里用状态栏避让高度替代 Compose 的 statusBarsPadding，且源链里 background 在 statusBarsPadding 之后时
做法：
- 先看源链里 background 是否在 statusBarsPadding 之后；在之后的，不在带背景的组件上加 top padding，改为外层容器让出状态栏高度，或把状态栏高度并入该组件的 .translate({ y: … })
- statusBarsPadding 之前的 heightIn(min = H) 包含状态栏，换算成内容区尺寸：.constraintSize({ minHeight: H − 状态栏高度 })
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- constraintSize(value: ConstraintSizeOptions): T：设最小高度用的约束尺寸（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.constraintSize）
- 组件带 padding 和 backgroundColor 时，内边距区域按该组件背景涂色：顶部内距和背景写在同一组件，状态栏区就被涂色（出处：ts-universal-attributes-size.md，示例1（设置组件的宽高和边距））
- 去掉带背景组件上的顶部 padding，minHeight 改为 H − 状态栏高度，状态栏高度并入 translate 后，状态栏区不再被涂色：修好的写法（出处：卡里修好并验证过）
来源：1 张卡，1 个应用
