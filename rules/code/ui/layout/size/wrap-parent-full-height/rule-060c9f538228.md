# Scroll 或无高度 Column 里的子树不写 height('100%') 和 layoutWeight

审的是：代码
触发（任一种）：
- 读到：源端 NestedScrollView 里，或 android:layout_height="wrap_content" 的 FrameLayout 槽位里，子 View 写 match_parent（实际按内容取高）；写错的样子：目标 Scroll() { Column() {...} } 或未设 height 的 Column 里，子树（含嵌进去的子组件 build() 根节点和各状态分支）写 .height('100%') 或依赖父高的 .layoutWeight(1)
适用范围：目标位于 Scroll 内、或父链上没有定高 Column 的子树，含宿主页面往无高度槽位嵌入子组件的接线
做法：
- 这类子树按内容取高：去掉 .height('100%') 和依赖父高的 .layoutWeight(...)
- 宿主往无高度槽位嵌入组件前，读被嵌组件 build() 根节点及各状态分支的高度修饰；有百分比高度时，先把组件改成按内容取高，或在槽位按源端内容尺寸写显式 .height(<源端 dp 值>)
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 百分比尺寸参考最近设置了固定大小的祖先节点的尺寸：Scroll 内无高度的 Column 不是参照，100% 落到更上层定了高的祖先（出处：ts-universal-attributes-size.md，尺寸设置（开头的说明））
- ScrollView 以 MeasureSpec.UNSPECIFIED 量子 View 的高度：源端滚动容器里的 match_parent 子 View 实际按内容取高（出处：android.widget.ScrollView#measureChildWithMargins）
- layoutWeight(value: number | string): T，按权重分配父容器（Row、Column、Flex）主轴上的空间，默认 0：父 Column 没有高度时，按权重分的是父链上定了高的空间，不是内容高度（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.layoutWeight）
- 修复时在宿主给槽位外层容器和槽位 Column 写显式高度（按源端标题与内容的 dp 尺寸），首屏后续区块恢复可见：在槽位上定高的做法（出处：卡里修好并验证过）
针对本应用要查的：
- 槽位要写的显式高度：源工程宿主页面的布局 XML 里对应槽位及其兄弟节点的 android:layout_height，以及被嵌 Fragment 布局里各节点写死的 dp 尺寸；源端写死的 dp 照搬成 vp；槽位是 wrap_content 时优先让组件按内容取高，不另编固定值
未核实：卡里的修复用固定高度而非让组件按内容取高，固定值的推导没有展开
