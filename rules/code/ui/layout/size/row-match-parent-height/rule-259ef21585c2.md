# 按钮行里有 match_parent 竖分隔 View 时，先给 Row 定高，再让分隔线 Stretch

审的是：代码
触发（任一种）：
- 读到：wrap_content 高的弹窗卡片里，按钮行有 layout_height="match_parent" 的竖分隔 View，按钮是 wrap_content + padding；写错的样子：按钮 Row 没写 .height(...)，只给竖 Divider 写 .alignSelf(ItemAlign.Stretch)，卡片被撑成父容器全高
适用范围：把带竖分隔线的按钮行迁成 ArkUI Row、所在卡片高度由内容决定时
做法：
- 先给按钮 Row 写 .height(<按钮行高 vp>)，取源按钮实测高度，或由按钮 padding 与字号算出
- 再让竖分隔线 .alignSelf(ItemAlign.Stretch) 或 .height('100%')，保留源端上下 margin；不让未定高 Row 里的 Stretch 子项决定卡片高度
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- alignSelf(value: ItemAlign): T：子组件在父容器交叉轴上的对齐方式（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.alignSelf）
- ItemAlign.Stretch = 4：除换行 Flex 外，无论元素尺寸是否设置，均拉伸到容器尺寸：容器没有确定高度时，Stretch 子项会把它撑到上层给的最大高度（出处：ts-appendix-enums.md，ItemAlign）
- 按钮 Row 加 .height(<源按钮行高>) 后卡片高度回到由内容决定：定高后 Stretch 只拉伸到行高（出处：卡里修好并验证过）
针对本应用要查的：
- 按钮行高度：源工程弹窗布局 XML 里按钮的 android:padding 与 android:textSize（或真机实测的按钮行 bounds）；有实测值用实测 dp；没有就按上下 padding 加单行文字行框高度算
