# wrap_content 行里的 match_parent 子项用 alignSelf 拉伸，不写 '100%'

审的是：代码
触发（任一种）：
- 读到：横向 LinearLayout 的 android:layout_height="wrap_content"，子项 android:layout_height="match_parent"；纵向 LinearLayout 时是 android:layout_width 这一轴；写错的样子：对应的 Row/Column 在这一轴没定尺寸，子项却写了 .height('100%') 或 .width('100%')，内容被撑到父级最大约束
- 读到：列表项 XML 的行容器 layout_height="wrap_content"，其中子控件 android:layout_height="match_parent"；写错的样子：目标行组件里这个子项写 .height('100%')，放进 List 后按视口高解析，每行撑成整屏
适用范围：安卓 LinearLayout 某一轴是 wrap_content、子项在同一轴是 match_parent，迁成 ArkUI Row/Column（含放进 List 的行组件）且容器在这一轴不定尺寸时
做法：
- 去掉该子项这一轴的 .height('100%') / .width('100%')，改写 .alignSelf(ItemAlign.Stretch)（或明确尺寸），让它拉伸到由兄弟项决定的行高（Row）或列宽（Column）
- 算容器这一轴的尺寸时不把这个子项算进去，只由非 match_parent 的兄弟项决定
- 行组件写完后搜所有 '100%'，确认放进 List 后不会按视口解析
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- alignSelf(value: ItemAlign): T：子组件在父容器交叉轴上的对齐方式，默认 ItemAlign.Auto（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.alignSelf）
- ItemAlign.Stretch：在交叉轴上拉伸；子项这一轴没设尺寸时拉到容器尺寸，所以不能再写 height/width（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，ItemAlign.Stretch）
- alignSelf 只在 Flex、Column、Row、DynamicLayout 里生效（GridRow 也支持）：外层容器必须是这几种之一（出处：ts-universal-attributes-flex-layout.md，弹性布局（说明））
- 父高不是 EXACTLY 且子项 lp.height == MATCH_PARENT 时先记下 matchHeight；父高定下后 forceUniformHeight 以父的测量高、MeasureSpec.EXACTLY 重量这些子项：源端 match_parent 子项只拉伸到兄弟项决定的高度（出处：android.widget.LinearLayout#measureHorizontal、android.widget.LinearLayout#forceUniformHeight）
- Row 高度自适应时子项的 '100%' 取父级最大约束，不是行内最高兄弟项的高度；改成 alignSelf(ItemAlign.Stretch) 后随行高：'100%' 和 match_parent 在 wrap_content 父容器里语义不同（出处：卡里修好并验证过）
- 列表行里改为 alignSelf(ItemAlign.Stretch) 后行高恢复正常：放进 List 的行组件里的修法（出处：卡里修好并验证过）
- alignItems(value: ItemAlign): GridRowAttribute：同族接口：GridRow 每行的交叉轴对齐（出处：鸿蒙 SDK 的 ets/component/grid_row.d.ts，GridRowAttribute.alignItems）
- FlexOptions.alignItems?: ItemAlign（默认 ItemAlign.Start）：同族接口：Flex 容器统一设置子项交叉轴对齐（出处：鸿蒙 SDK 的 ets/component/flex.d.ts，FlexOptions.alignItems）
