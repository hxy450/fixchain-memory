# measureTextSize 按列宽测折行时 constraintWidth 直接传 vp 宽，不先 vp2px

审的是：代码
触发（任一种）：
- 读到：源端 TextView 为 android:layout_height="wrap_content"，文字在列宽内折行后自身变高并把后续视图下推；写错的样子：目标端 getMeasureUtils().measureTextSize({ …, constraintWidth: ui.vp2px(width) })，width 本是 vp 列宽
适用范围：目标端用 MeasureUtils.measureTextSize 按宽度推算折行行数和高度，再据此定位后续视图时
做法：
- constraintWidth 直接传布局里的 vp 宽：measureTextSize({ textContent, fontSize, constraintWidth: width })；拿不准时传带单位的字符串 `${width}vp`
- 返回的 width/height 是 px：行数用两次返回值的比值（按列宽测的高 / 单行高），或 px2vp 后再和 vp 常量比较
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- measureTextSize(options: MeasureOptions): SizeOptions：返回的文本宽和高都是 px（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，MeasureUtils.measureTextSize）
- constraintWidth?: number | string | Resource；默认单位 vp，不支持百分比字符串：number 按 vp 解析，与 .width(number) 相同；声明没写单位，单位出自文档（出处：鸿蒙 SDK 的 ets/api/@ohos.measure.d.ts，MeasureOptions.constraintWidth；js-apis-measure.md，MeasureOptions）
- constraintWidth: width（vp）后，必折行的标签测得两行，后续视图落在其下：去掉 vp2px 后折行分支生效（出处：卡里修好并验证过）
- measureText(options: MeasureOptions): number：同族接口：只测单行宽（px），constraintWidth、maxLines 对它不起作用，不能用来判断折行（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，MeasureUtils.measureText；arkts-apis-uicontext-measureutils.md，measureText）
