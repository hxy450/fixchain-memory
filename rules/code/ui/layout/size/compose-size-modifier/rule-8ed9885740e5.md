# 只绘制不改测量的修饰符落成包装组件时，遮罩层按实测内容尺寸定数值，不写 '100%'

审的是：代码
触发（任一种）：
- 读到：Compose 里 Modifier.fadingEdges、Modifier.border 这类只绘制、不参与测量的修饰符，挂在由内容定高的 LazyRow 等节点上；写错的样子：目标用不设尺寸的 Stack 包 @BuilderParam 内容，叠在上面的遮罩条写 .height('100%') 或 .width('100%')，包装层被撑到页面高
适用范围：把只绘制、不改测量的 Compose 修饰符落成包裹内容的 ArkUI 组件，内容上要叠一层遮罩或描边时
做法：
- 包装组件尺寸等于内容尺寸：内容包进 Column，用 .onAreaChange((o, n) => { … }) 或 .onSizeChange(...) 实测宽高存进状态，遮罩层用这两个数值写 width / height，不写 '100%'
- 遮罩层里用 Row / Column 加 Blank()（或 position）把首尾两条分开；整层和每个子节点 .hitTestBehavior(HitTestMode.None)；遮罩层承载保持 Stack，不改用 .overlay()
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onAreaChange(event: (oldValue: Area, newValue: Area) => void): T：组件尺寸或位置变化完成后回调，读 newValue.width / height（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onAreaChange）
- onSizeChange(event: SizeChangeCallback): T；SizeChangeCallback = (oldValue: SizeOptions, newValue: SizeOptions) => void：布局更新导致尺寸变化时回调（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onSizeChange、SizeChangeCallback）
- Blank(min?: number | string)，min 默认 0：在 Row / Column 主轴上填满剩余空间，把首尾两条推到两端（出处：鸿蒙 SDK 的 ets/component/blank.d.ts，BlankInterface）
- HitTestMode.None：自身不响应触摸测试，子节点响应：所以整层和每个子节点都要设，遮罩才不挡内容的滑动（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，HitTestMode.None）
- 尺寸用百分比设置时，参考最近设置了固定大小的祖先节点的尺寸：不设尺寸的 Stack 里的 '100%' 会按更外层的约束解析（出处：ts-universal-attributes-size.md，尺寸设置（说明））
- 用 .overlay() 承载遮罩层时，其中的 '100%' 不按宿主解析（约 136vp 对 60vp 行），还吞掉横向滑动；退回 Stack 加实测尺寸后正常：承载方式的取舍（出处：卡里修好并验证过）
