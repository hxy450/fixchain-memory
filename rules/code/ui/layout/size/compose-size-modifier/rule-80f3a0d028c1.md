# 源码注释说明用于撑齐宽度的零高 Text 不能跳过，目标给列设 constraintSize 的 minWidth

审的是：代码
触发（任一种）：
- 读到：Compose 里带注释（如 invisible Text … aligns width）的不可见对齐子项：Text("00000", Modifier.height(0.dp))；写错的样子：目标里省略了这个对齐子项，或照搬成 .height(0) 的 Text，列上也没有 minWidth，列宽随内容变化
适用范围：Compose 用零高或不可见子项撑齐列宽，迁成 ArkUI 时
做法：
- 不跳过这条约束：在该列容器上写 .constraintSize({ minWidth: W })，W 是对齐文本在源端同一文字样式下测得的宽度；不靠 height(0) 的 Text 撑宽
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- constraintSize(value: ConstraintSizeOptions): T，默认 {minWidth: 0, maxWidth: Infinity, minHeight: 0, maxHeight: Infinity}：给列设最小宽度（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.constraintSize）
- ArkUI 里高为 0 的 Text 不参与宽度测量，照搬后列宽仍随内容变化；按测得的文本宽设最小宽后列宽对齐：为什么不能照搬零高 Text（出处：卡里修好并验证过）
- constraintSize(value: ConstraintSizeOptions): T：同族接口：安全控件（SecurityComponentMethod）的约束尺寸（出处：鸿蒙 SDK 的 ets/component/security_component.d.ts，SecurityComponentMethod.constraintSize）
针对本应用要查的：
- 对齐文本在目标字号下的宽度：源工程 Compose 文件里该不可见 Text 的文本和 style（如 MaterialTheme.typography 的某一档），以及目标工程里与之对应的字号；按目标字号测出这段文本的宽度（vp），作为列的 minWidth
未核实：卡里观察到的行为出自鸿蒙 SDK API 24（6.1.1），本机核实用 API 23；零高 Text 不参与测宽在声明和文档里没找到说法
