# 排在固定高度兄弟之后、占剩余高度的内容区写 layoutWeight(1)，不写 100% 高

审的是：代码
触发（任一种）：
- 读到：Compose Column 里内容区排在搜索栏、分隔线这类固定高度节点之后，用 Modifier.fillMaxSize() 或 LazyColumn 占满剩余高度；写错的样子：内容区（或它的各个状态分支容器）写成 .height('100%')；或规划过的 layoutWeight(1) 包裹层没写出来，状态分支直接挂在根 Column 下
适用范围：目标 Column 中内容区之前有固定高度的兄弟节点、源端内容区只拿剩余高度时
做法：
- 给内容区容器写 .layoutWeight(1)，不写 .height('100%')
- 有多个状态分支时，所有分支都放进这一层 layoutWeight(1) 容器里；写完回看 build()，确认这层容器真的写出来了
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- layoutWeight(value: number | string): T：在 Row / Column / Flex 主轴上按权重分配剩余空间，默认 0（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.layoutWeight）
- 不设 layoutWeight 的元素先占位，设了大于 0 的从主轴剩余空间按权重分，分配时忽略元素本身的尺寸设置：layoutWeight(1) 就是「占剩余高度」（出处：ts-universal-attributes-size.md，layoutWeight）
- 尺寸用百分比时，参考最近设置了固定大小的祖先节点的尺寸：height('100%') 取的是父 Column 的整高，不扣掉前面的兄弟（出处：ts-universal-attributes-size.md，开头的说明）
- 四个状态容器由 height('100%') 改成 layoutWeight(1) 后，57vp 溢出消失：溢出量等于搜索栏加分隔线的高度（出处：卡里修好并验证过）
