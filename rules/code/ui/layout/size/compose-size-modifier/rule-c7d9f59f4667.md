# 源端靠 matchContentSize 贴合内容的描边或指示器，画在内容节点自身，不用 100% 覆盖层

审的是：代码
触发（任一种）：
- 读到：Compose 选中指示器或背景层用 Modifier.fillMaxSize()、tabIndicatorOffset(matchContentSize = true) 加 .border(...) 贴合选中项内容；写错的样子：目标在没有定尺寸的 Stack/Row 里另放一层 .width('100%').height('100%') 的覆盖层画描边或背景
适用范围：源端描边、背景或选中指示器贴合内容尺寸，目标父容器由内容定尺寸时
做法：
- 把描边或背景直接写在由内容定尺寸的节点自身：.border({ width, color: 选中 ? 描边色 : Color.Transparent, radius }) 或 .backgroundColor(...)，未选中用 Color.Transparent，两态尺寸一致
- 源端指示器的左右内缩拆成两段水平 padding：外层单元格一段、文本块一段，描边画在文本块上
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 组件尺寸用百分比时，参考最近设置了固定大小的祖先节点的尺寸：wrap-content 父级里的 100% 层会解析到更上层有确定尺寸的祖先，把整行撑大（出处：ts-universal-attributes-size.md，开头说明）
- border(value: BorderOptions): T：组件自身的边框（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.border）
- backgroundColor(value: ResourceColor): T：组件自身的背景色（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.backgroundColor）
- Color.Transparent：未选中态的描边色，保持边框占位一致（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，Color.Transparent）
- 文本块自身常驻 .border()、未选中用 Color.Transparent，左右内缩拆成单元格和文本两段 padding 后，选中格与 Tab 行尺寸恢复正常：卡里设备复验的做法（出处：卡里修好并验证过）
