# heightIn(max) 紧接 verticalScroll 时，高度上限挂在 Scroll 上

审的是：代码
触发（任一种）：
- 读到：Compose 同一 Modifier 链里 `heightIn(max = …)` 紧接 `verticalScroll(rememberScrollState())`，圆角、背景也在这个节点上；写错的样子：目标拆成外层卡片 `Column` + `Scroll` + 内容 `Column` 后，`.constraintSize({ maxHeight: … })` 挂在外层 `Column` 上，`Scroll` 只写了 `width('100%')`；转换报告的理由是「Column 会 wrap，Scroll 不会」
适用范围：把 Compose 带高度上限的滚动卡片拆成 ArkUI 外层容器包 Scroll 的多节点结构时
做法：
- 上限紧接滚动修饰表示它是滚动视口的上限：写 `Scroll() { Column() { … } }.constraintSize({ maxHeight: <源端上限的 dp 数> })`
- 圆角、背景、裁剪、共享元素留在外层卡片 Column，外层不写高度上限，随 Scroll 尺寸 wrap
- 「滚动容器显式给交叉轴尺寸」这类陷阱只管交叉轴，不能据此把纵向 Scroll 的视口上限挪到包装节点；拿不准 Scroll 自适应高度时，在转换报告里列为设备核验项：内容超过上限时拖动，能否到达最后一节
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- constraintSize(value: ConstraintSizeOptions): T：约束组件布局时的尺寸范围，默认 {minWidth: 0, maxWidth: Infinity, minHeight: 0, maxHeight: Infinity}（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.constraintSize）
- Scroll 滚动的前提是主轴方向大小小于内容大小：上限要落在 Scroll 本身，它的主轴大小才被直接限住（出处：ts-container-scroll.md，Scroll）
- 修复把上限从外层 Column 移到 Scroll 上，最终保留这一放置：修好后的写法（出处：卡里修好并验证过）
未核实：上限挂在外层 Column、而触摸拦截已修好的组合没有上机跑过，这一放置单独是否导致不可滚动未核实
