# 视觉修复改尺寸前先读源布局取值，已一致就不改，偏离要有源码或资源依据

审的是：代码
触发（任一种）：
- 读到：视觉差异单只有文字结论（如「行高更大」「下方内容被下推」），源布局里对应尺寸是 android:layout_height 等属性引用的 @dimen/ 值；写错的样子：目标尺寸被改成和源端 @dimen/ 取值不同的数值，尝试记录里没有引用源端取值
- 读到：源布局给出固定 android:layout_height="…dp" 和 android:layout_marginTop="…dp"，目标代码当前值与之相同；写错的样子：修复把已等于源布局值的 .height(...) / .margin({ top: ... }) 改成更大的常量，依据只写「按较小视觉比例配置」这类跨设备截图比例
适用范围：视觉修复阶段按差异单或截图修改页面固定高度、间距、图片尺寸时
做法：
- 定数值前读源布局属性和它引用的 dimen（dp 数值写成 vp），逐项列出源布局值和拟改值；拟改值偏离源布局时要给出源码或资源固有尺寸依据（图片固有像素按密度折 dp：dp = px × 160 / 密度），否则保留源布局值
- 源端和目标数值已经一致时，回头复核差异单的成因，不压缩或放大这个数值去迎合截图
- 放大前累计同一纵向空间里所有固定高度和 margin，确认整块内容仍在底部 Tab 之上；不满足时先找视口、安全区、容器的原因
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- DENSITY_MEDIUM = 160（DENSITY_DEFAULT）、DENSITY_XHIGH = 320、DENSITY_XXHIGH = 480：资源目录密度对应的 dpi，用来把图片固有像素折成 dp（xhdpi 下 px ÷ 2）（出处：android.util.DisplayMetrics#DENSITY_MEDIUM、#DENSITY_XHIGH、#DENSITY_XXHIGH）
- 恢复源布局的固定高度和顶距、图片按固有像素折 dp 后，统计卡回到底部 Tab 之上：源布局值本身就是正确值（出处：卡里修好并验证过）
针对本应用要查的：
- 源端这个尺寸的取值：源工程布局 XML 里该控件或容器的 android:layout_height 等属性，顺着 @dimen/ 到 res/values*/dimens.xml 按名找；读出 dp 数值作为目标值
- 图片资源的固有尺寸：源工程 res 下 drawable-<密度> 目录里的图片文件（看它放在哪个密度目录）；读出图片像素宽高，按目录密度折成 dp（例：xhdpi 目录下 154px 宽即 77dp）
