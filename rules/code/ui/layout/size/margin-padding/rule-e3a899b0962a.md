# 注释写 minWidth/maxWidth 的元素代码却是 .width(N) 时，改成 constraintSize

审的是：代码
触发（任一种）：
- 读到：规格或映射里写着该元素的 minWidth / maxWidth（源端是 android:minWidth、android:maxWidth 这类下限上限）；写错的样子：代码注释写着 minWidth / maxWidth，同一个元素上却是 .width(N)，没有 .constraintSize(...)
适用范围：目标端 ArkUI 代码里，注释或规格把某个尺寸说成最小值或最大值约束的元素
做法：
- 把这个元素的 .width(N) 换成 .constraintSize({ minWidth: N })；注释或规格里还有上限的，同一个对象里补 maxWidth
- 在产物里搜 width( ，逐处对照附近的注释和规格，凡是写着 minWidth / maxWidth 的都按上一步改
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- constraintSize(value: ConstraintSizeOptions): T：组件布局时的尺寸范围，minWidth、maxWidth、minHeight、maxHeight 都可选；默认 {minWidth: 0, maxWidth: Infinity, minHeight: 0, maxHeight: Infinity}（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.constraintSize；ets/component/units.d.ts，ConstraintSizeOptions）
- constraintSize(value: ConstraintSizeOptions): T：同族接口：安全控件（SecurityComponentMethod）的尺寸约束（出处：鸿蒙 SDK 的 ets/component/security_component.d.ts，SecurityComponentMethod.constraintSize）
- itemConstraintSize(value: ConstraintSizeOptions): WaterFlowAttribute：同族接口：WaterFlow 子项的尺寸约束（出处：鸿蒙 SDK 的 ets/component/water_flow.d.ts，WaterFlowAttribute.itemConstraintSize）
