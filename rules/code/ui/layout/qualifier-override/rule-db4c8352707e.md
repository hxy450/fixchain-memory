# 源布局有 layout-land / layout-sw600dp 同名变体时，按窗口条件写两套分支

审的是：代码
触发（任一种）：
- 读到：被替代的源布局在 res/layout-land/（或 layout-sw600dp/）下有同名 XML；占位登记或移交行写明「横屏变体 layout-land/… 权重 …」；写错的样子：共享组件只按 res/layout/ 的竖屏结构写 layoutWeight，没有按窗口方向的分支，头注只溯源 res/layout；也没有登记横屏移交项
- 读到：<include layout="@layout/名"> 或 setContentView(R.layout.名) 引用的布局在 layout-sw600dp/、layout-land/ 下有同名 XML（如 base 纵向、变体横向）；写错的样子：页面只按 base 写成一套 Column（或 Row），没有按窗口尺寸切换的分支
适用范围：实现替代带 layout-land / layout-sw 变体的源布局的 ArkUI 页面或组件时
做法：
- 开写前对每个被替代的源布局查 res/layout-*/ 下的同名 XML，并查占位登记和派工里同名组件的 forward-ref 行；有变体就读变体 XML
- 按窗口条件分支，各用一个 @Builder 照 layout/ 和变体的结构排布：land 写成窗口宽 > 高；sw600dp 写成窗口宽、高里较小的 ≥ 600vp（window.getLastWindow(ctx) 取窗口，getWindowProperties().windowRect 的 px 宽高经 this.getUIContext().px2vp() 换算后比）
- 本任务确实不做横屏时登记移交项，写负责方、变体路径和权重值，不按竖屏骨架静默交付
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- base目录、限定词目录、rawfile目录、resfile目录称为资源目录，element、media、profile称为资源组目录：目标端资源组没有 layout，布局变体没法靠资源限定词承接，只能在组件代码里分支（出处：resource-categories-and-access.md，资源分类）
- smallestScreenWidthDp：screenWidthDp 和 screenHeightDp 在横竖两个方向上的最小值：sw600dp 要和宽高里较小的那个比（出处：android.content.res.Configuration#smallestScreenWidthDp）
- function getLastWindow(ctx: BaseContext): Promise<Window>；getWindowProperties(): WindowProperties；WindowProperties.windowRect: Rect：取当前窗口的位置和大小（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，window.getLastWindow、Window.getWindowProperties、WindowProperties.windowRect）
- Rect 的 width、height 单位为 px：要先换算成 vp 再和 600 比（出处：arkts-apis-window-i.md，Rect）
- px2vp(value: number): number：px 换算成 vp（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.px2vp）
- 新增横屏 Builder 按 layout-land 的权重算法排布，按窗口是否横屏选布局：横屏变体修复后的写法（出处：卡里修好并验证过）
- 加 600 阈值和判断是否 sw600dp 的函数，大屏走横向按钮行分支：sw600dp 变体修复后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 变体的结构差异和权重：源工程 res/layout-land/、res/layout-sw600dp/ 下与被替代布局同名的 XML；逐层对比 layout/ 与变体的 LinearLayout 方向、android:layout_weight 和子块排布，差异写成横屏分支
