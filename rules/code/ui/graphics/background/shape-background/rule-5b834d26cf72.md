# 源背景是带底边或描边的 layer-list 时，目标显式补 border 或 padding

审的是：代码
触发（任一种）：
- 读到：源控件 `android:background` 引用的 drawable 是 `<layer-list>`：下层 item 是一种颜色，上层 item 用 `android:bottom` 等 inset 让下层露出一条边，或有 `<stroke>`；写错的样子：目标只写了 `.backgroundColor(...)` 或 `.backgroundImage(...)`，露出的底边、描边缺失
适用范围：源背景 drawable 用 layer-list 叠出边线或描边时
做法：
- 读出各层颜色和 inset，补成 .border({ width: { bottom: <上层 bottom inset> }, color: { bottom: <下层颜色> } })；描边按 stroke 的宽和色写 border，inset 造成的内容位移用 padding 补
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- LayerDrawableItem 的 android:bottom：Bottom inset to apply to the layer：上层 item 的 bottom inset 就是下层露出的底边厚度（出处：Android SDK 平台资源 data/res/values/attrs.xml，LayerDrawableItem 的 bottom（按应用的 compileSdk 取对应平台））
- border(value: BorderOptions): T；BorderOptions.width?: EdgeWidths | Length | LocalizedEdgeWidths：边框可按四边分别给宽度和颜色（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.border；ets/component/units.d.ts，BorderOptions.width）
- 补上底部 2dp 的灰色 border 后卡片底边与源端一致：验证过的做法（出处：卡里修好并验证过）
针对本应用要查的：
- 背景 drawable 各层的颜色和 inset：源工程 res/drawable*/ 下这个背景 XML 的各个 <item>：android:top / bottom / left / right，里面 <shape> 的 <solid>、<stroke>；上层 item 的 inset 是下层露出的边宽，下层 solid 色是边色；dp 换成 vp
