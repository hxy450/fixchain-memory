# holder 动态 addView 的视图要打开它的布局，取 CardView 的 cardCornerRadius

审的是：代码
触发（任一种）：
- 读到：holder 把另一个组件的根视图 addView 进内容容器，那个视图的布局根是 CardView（或其子类），写了 app:cardCornerRadius="@dimen/…"；写错的样子：目标端卡片的 .borderRadius($r(...)) 没有出自这个 CardView 布局，取的是别的布局或兄弟页的值，和源端 cardCornerRadius 不一致
适用范围：列表项外观来自 holder 运行时加入的动态视图、迁成 ArkUI 卡片时
做法：
- 沿 holder 找到被 addView 的视图类，打开它 inflate 的布局，读根 CardView 的 app:cardCornerRadius，把 @dimen 解析到 dp 值
- 写成 .borderRadius($r('app.float.同名 dimen'))，float 资源值等于该 dp 值；转换报告里注明来源布局文件
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- CardView 的 cardCornerRadius 是 dimension 属性；不写时 Base.CardView 用 cardview_default_radius = 2dp：源端圆角真值在 CardView 布局或其样式里（出处：androidx.cardview:cardview 包内 res/values/values.xml，CardView 的 cardCornerRadius、cardview_default_radius（按应用依赖的版本））
- borderRadius(value: Length | BorderRadiuses | LocalizedBorderRadiuses): T：目标端卡片圆角（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.borderRadius）
- 沿 holder 追到组件根视图布局的 CardView cardCornerRadius，改用这个 dimen 后普通项圆角正确：验证过的做法（出处：卡里修好并验证过）
- borderRadius(value: Length | BorderRadiuses | LocalizedBorderRadiuses, type?: RenderStrategy): T：同族接口：可指定绘制策略的重载（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.borderRadius）
针对本应用要查的：
- 动态视图的圆角真值：源工程里 holder 类 addView 的视图类 → 它 inflate 的 res/layout XML 根 CardView 的 app:cardCornerRadius → res/values 下 dimens.xml 里的同名 dimen；解析到 dp 值，写进目标端同名 float 资源；CardView 没写 cardCornerRadius 时查它的 style 或库默认
未核实：CardView 会把子视图裁成圆角；目标端只写 borderRadius 是否还要配 .clip(true) 才裁子组件，卡里没验证
