# EditText 去掉背景、起始无内边距时，TextInput 的 padding 显式写 left: 0

审的是：代码
触发（任一种）：
- 读到：EditText 写了 android:background="@null"，起始边没有 paddingStart，文字贴边；写错的样子：TextInput 的 .padding({...}) 只写了 top、bottom、right，没写 left，起始边仍有默认内边距
适用范围：把去掉背景的 EditText（如嵌在卡片里的搜索框）迁成 ArkUI TextInput 时
做法：
- TextInput 写 .padding({ left: 0, top: …, right: …, bottom: … })，四边按源端实际内边距写全，不留默认值
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- TextInput 默认 padding { top: 8vp, right: 16vp, bottom: 8vp, left: 16vp }：不写 left 时起始边有 16vp 内边距（出处：ts-basic-components-textinput.md，属性说明）
- padding(value: Padding | Length | LocalizedPadding)，默认 0、单位 vp：通用内边距接口，对象写法只覆盖写到的边（出处：ts-universal-attributes-size.md，padding）
- View 的内边距来自背景 drawable 的 getPadding；background=@null 时没有这部分内边距：源端去掉背景后起始边是 0（出处：android.view.View#setBackgroundDrawable）
