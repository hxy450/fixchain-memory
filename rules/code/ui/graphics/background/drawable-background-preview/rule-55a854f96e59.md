# 源端背景是组件自身 Drawable、目标只有成品静态预览图时，用 blendMode 合成或登记缺口

审的是：代码
触发（任一种）：
- 读到：源端背景作为组件自身的 Drawable 随组件重绘；写错的样子：目标预览是一张成品静态图 Image(…).objectFit(ImageFit.Contain) 叠在背景层上面，没有合成；回执只写一句「静态预览图无法对背景重着色」，没有登记缺口
适用范围：目标端只能用成品静态预览图展示组件、又要呈现用户所选背景时
做法：
- 明确选一种合成方式：白底的静态预览图在已选背景时加 .blendMode(BlendMode.DARKEN)，与下层背景合成
- 做不到合成时，把「该分支无法呈现所选背景」登记为结构化缺口并报告，不交付一个选了也看不出效果的选项
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 已选背景时静态图用 blendMode(BlendMode.DARKEN) 与下层背景合成：修好后所选背景可见（出处：卡里修好并验证过）
- blendMode(value: BlendMode, type?: BlendApplyType): T，value 默认 BlendMode.NONE（效果同 SRC_OVER），type 默认 BlendApplyType.FAST；声明 @since 12：组件与下方已有内容的混合方式；OFFSCREEN 时先把组件及子组件画到离屏画布再混合（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.blendMode）
- BlendMode.DARKEN = 17：rc = s + d - max(s * da, d * sa)：取较暗的一方，白底处露出下层背景色（出处：鸿蒙 SDK 的 ets/component/common.d.ts，BlendMode.DARKEN）
未核实：非白底的静态预览图用 DARKEN 合成的效果卡里没有核对；卡里工程的 target_sdk 记为 26.0.0，本机按 API 23 核对声明
