# stateStyles 用 pressed 改了属性时，同一处用 normal 写回静止值

审的是：代码
触发（任一种）：
- 读到：源端按钮、ImageButton、列表行的按压反馈由主题 ripple 或 selector 提供，松手即恢复；写错的样子：可点击元素上 .stateStyles({ pressed: { .backgroundColor(...) } }) 只写了 pressed，没有 normal
- 写错的样子：stateStyles({ pressed: this.某个 @Styles 方法 }) 只引用了按压态方法，没配 normal 的静止态方法
- 读到：收口按压色类的占位（UNC 编号）；写错的样子：只确认或修改了按压色，同一 stateStyles 里仍只有 pressed
适用范围：为列表行、对话框文字按钮、ImageButton/图标按钮、标题栏动作钮等任何可点击元素用 stateStyles 写按压态时（内联样式块和 @Styles 方法引用都算）
做法：
- 先看 pressed 改了哪些属性，在同一 stateStyles 里用 normal 写回这些属性的静止值：无底色写 normal: { .backgroundColor(Color.Transparent) }，有底色写原色
- 用 @Styles 方法引用时同样配一个静止态方法：{ normal: 静止态方法, pressed: 按压态方法 }，静止态方法里写 .backgroundColor(Color.Transparent) 或原色
- 照搬兄弟组件的按压写法或收口按压色占位时，同时核对同一 stateStyles 是否已有 normal，缺的补上
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- stateStyles(value: StateStyles): T：通用属性方法，按组件内部状态设样式（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.stateStyles）
- normal?: any；pressed?: any：StateStyles 的正常态、按压态都是可选字段，不写 normal 不会报错（出处：鸿蒙 SDK 的 ets/component/common.d.ts，StateStyles）
- stateStyles({ normal: this.normalStyle, pressed: this.pressedStyle })：文档里 @Styles 与 stateStyles 联用的示例是成对写的（出处：arkts-statestyles.md，@Styles和stateStyles联合使用）
- 只写 pressed 时离开按下态被改的 backgroundColor 不还原；补 normal: Color.Transparent 后装机取样无残留：成对写的必要性（出处：卡里修好并验证过）
未核实：官方文档没有写「只写 pressed 松手不还原」，依据是卡里返修前后的装机对照
