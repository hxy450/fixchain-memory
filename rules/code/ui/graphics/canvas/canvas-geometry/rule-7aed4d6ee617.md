# 源端自适应尺寸公式用固定参照基数时，目标保留成独立常量，不用当前实际格高代替

审的是：代码
触发（任一种）：
- 读到：源端自绘 View 的尺寸推导里有一个固定参照基数常量（如月历自动行高的参照周数 = 6），先用内容总高 / 参照基数得到参照格高，再减去固定区、除以最少可见行数求行高；写错的样子：目标 Canvas 组件里行高直接由当前实际格高（可用高度 / 当月实际行数）推算，参照基数常量不见了，行数多少的两种情形被算成同一行数
适用范围：把源端自绘 View 里按固定参照基数反推尺寸的自适应公式移植到 ArkUI Canvas 绘制代码时
做法：
- 把参照基数写成独立常量（如 `const REFERENCE_ROW_COUNT = 6`），参照格高 = 内容总高 / REFERENCE_ROW_COUNT，再按源端公式减固定区、除以最少可见行数得到行高
- 当前布局变量（按实际行数平分出的格高）只用来决定一格里能放下几行，不代入行高公式
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 行高按固定 6 周参照格高（内容总高 / 6）推算后，5 周月份因格子更高而多显示提醒行，6 周月份至少放下最少行数：参照基数与当前格高分开后的效果（出处：卡里修好并验证过）
针对本应用要查的：
- 源端公式里哪个量是固定参照基数、哪个是当前布局变量：源工程里自绘 View 的尺寸推导函数（onSizeChanged、onDraw 调用的行高计算），以及它引用的常量定义；写死的常量或配置项（参照周数、参照行数）是参照基数；由当前数据算出的量（当月实际周数、实际格高）是布局变量
