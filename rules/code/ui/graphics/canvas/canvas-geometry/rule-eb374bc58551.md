# px 画布上下文里用到 dp 声明的圆角等长度，先 vp2px 再交给 roundRect

审的是：代码
触发（任一种）：
- 读到：源端 drawable 的 <corners android:radius="…dp"> 等 dp 尺寸被自绘几何使用，迁成按 vp 1:1 的数值常量；写错的样子：上下文按 LengthMetricsUnit.PX 构造，ctx.roundRect(x, y, w, h, radii) 的 radii 仍直接用 dp/vp 数值常量，没有 vp2px
适用范围：画布上下文按 px 构造、绘制里用到来自 dp 资源或 vp 常量的长度（圆角、线宽、间距）时
做法：
- 交给 px 上下文的 dp 常量逐个换算：ctx.roundRect(x, y, w, h, this.getUIContext().vp2px(radius))（或已存的 uiContext.vp2px(radius)）；遮罩、填充形状里的同一类常量一并换，不只改字体一处
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- vp2px(value: number): number：UIContext 的 vp 转 px（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.vp2px）
- getUIContext(): UIContext：自定义组件里取 UIContext 的写法（出处：鸿蒙 SDK 的 ets/component/common.d.ts，BaseCustomComponent.getUIContext）
- 全局 vp2px(value: number) 自 API 18 起废弃，改用 UIContext#vp2px：不要写全局函数（出处：鸿蒙 SDK 的 ets/component/common.d.ts，vp2px）
- roundRect(x: number, y: number, w: number, h: number, radii?: number | Array<number>): void：CanvasPath 的圆角矩形（@since 20），radii 按上下文单位解释（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，CanvasPath.roundRect）
- DrawableCorners 的 radius 是 format="dimension"：源端圆角是带单位的尺寸，dp 值迁成 vp 数值后，在 px 上下文里要换算（出处：Android SDK 平台资源 data/res/values/attrs.xml，DrawableCorners 的 radius（按应用的 compileSdk 取对应平台））
- fillShape、遮罩和方块的 roundRect 圆角改为 uiContext.vp2px(radius) 后与 drawable corners 的 dp→px 一致：dp 常量在 px 上下文里换算后圆角正确（出处：卡里修好并验证过）
