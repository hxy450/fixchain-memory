# 带 clip(true) 的容器按行数×行高定高时，行高和画布绘制行高引用同一常量

审的是：代码
触发（任一种）：
- 读到：源端自定义 View 在 onDraw 里按固定行高（@dimen/ 资源或常量）画一行行单元，外层布局的高度和折叠距离也由同一行高推出；写错的样子：目标容器 .height(行数 × 行高 + …).clip(true) 和折叠范围用的行高数值，与 Canvas 组件里画行用的常量不同；或者只改了容器的行高，画布的行高常量没动
适用范围：自绘 Canvas 组件按固定行高绘制、外层容器按行数计算高度并裁切（含按行高算折叠距离）的场合
做法：
- 改容器高度前先找到画布实际绘制行高的来源（Canvas 组件里的行高常量），容器高度、折叠范围都引用这同一个常量
- 确需改行高时只改这个常量，绘制、容器高度、折叠范围一起变；不单独压缩外层容器
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- clip(value: boolean): T，默认 false：为 true 时裁掉子组件超出本组件边界的部分，超出部分也不响应手势（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.clip）
- 容器行高和折叠范围改回与画布行高常量同值后，最后一行不再被裁、日程面板不再盖住日历：修好后的做法（出处：卡里修好并验证过）
