# 源 View 按 int px 布局和 Paint 度量时，画布上下文用 LengthMetricsUnit.PX 构造

审的是：代码
触发（任一种）：
- 读到：安卓自定义 View 在 onSizeChanged(int w, int h) 的 px 尺寸上推导布局，Paint.setTextSize / measureText 按 px 算字号和派生内边距；写错的样子：目标写的是默认构造 new CanvasRenderingContext2D(settings)，却把 ctx.width / height 当 px 用、字体串拼 `${n}px`，测宽结果偏小、字号被钳小
适用范围：把安卓自绘 View 的布局方程逐式移植到 ArkUI Canvas、源端布局和 Paint 度量都在 px 域时
做法：
- 写成 new CanvasRenderingContext2D(settings, LengthMetricsUnit.PX)，并 import { LengthMetricsUnit } from '@kit.ArkUI'；字号、measureText 结果、ctx.width / height 和几何就都和源端 View/Paint 同为 px，再逐式移植布局方程
- 字体串的字号后缀和上下文单位一致：PX 上下文写 ctx.font = `bold ${size}px <字体>`，不再写 vp 后缀
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- constructor(settings?: RenderingContextSettings, unit?: LengthMetricsUnit)：CanvasRenderingContext2D 带单位模式的构造（@since 12）；只写 settings 的构造按默认单位（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，CanvasRenderingContext2D.constructor）
- LengthMetricsUnit.DEFAULT = 0（vp）、LengthMetricsUnit.PX = 1：单位模式的两个取值，默认是 vp（出处：鸿蒙 SDK 的 ets/api/arkui/Graphics.d.ts，LengthMetricsUnit）
- unit 默认值 DEFAULT，配置后无法更改：单位模式只能在构造时定，之后改不了（出处：ts-canvasrenderingcontext2d.md，constructor12+）
- import { LengthMetricsUnit } from '@kit.ArkUI'：LengthMetricsUnit 的导入写法（出处：鸿蒙 SDK 的 ets/kits/@kit.ArkUI.d.ts，LengthMetricsUnit）
- ctx.font = 'font-style font-weight font-size font-family'，font-size 单位支持 px、vp，使用时要加单位：字体串的字号必须带单位后缀（出处：ts-canvasrenderingcontext2d.md，font）
- 默认构造下 px 字号被当物理像素、measureText 结果按 vp 偏小；改成 LengthMetricsUnit.PX 构造后字号、测宽、几何、触点与安卓 View/Paint 同为 px：改用 PX 构造后布局方程可以原样移植（出处：卡里修好并验证过）
- constructor(width: number, height: number, settings?: RenderingContextSettings, unit?: LengthMetricsUnit)：同族接口：OffscreenCanvasRenderingContext2D 的构造，同样用 unit 定单位（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，OffscreenCanvasRenderingContext2D.constructor）
- constructor(unit?: LengthMetricsUnit)：同族接口：DrawingRenderingContext 的构造（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，DrawingRenderingContext.constructor）
