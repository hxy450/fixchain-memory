# drawText 用默认 Paint 时，每次 fillText 前按首个强方向字符设 ctx.direction

审的是：代码
触发（任一种）：
- 读到：`canvas.drawText(...)` 配默认 `new Paint()`，只改了 `setTextAlign`，没设 bidi 或方向；写错的样子：`ctx.fillText(` 前没有设 `ctx.direction`，RTL 系统语言下句末标点被挪到行首
适用范围：安卓 Canvas 文字迁到 ArkUI Canvas，应用可能在 RTL 系统语言（含没有对应资源、回落英文的语言）下运行时
做法：
- 写一个绘制函数：取串里首个强方向字符，落在希伯来、阿拉伯字符区块设 ctx.direction = 'rtl'，其他字母设 'ltr'，没有字母设 'ltr'，然后再 ctx.fillText；所有 fillText 都改调它
- 判断字符区块的正则用 \u 转义写码位，不在源码里直接写 RTL 字符
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- direction: CanvasDirection：画布上下文的文字方向，@default inherit（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，CanvasRenderer.direction）
- CanvasDirection = "inherit" | "ltr" | "rtl"：inherit 继承画布组件的设置，ltr 从左到右，rtl 从右到左（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，CanvasDirection）
- mBidiFlags = BIDI_DEFAULT_LTR：源端默认 Paint 按启发式判段落方向、判不出时 LTR，目标的首个强字符判断就是在复刻它（出处：android.graphics.Paint 的 mBidiFlags、BIDI_DEFAULT_LTR）
- 按首个强方向字符设 ctx.direction 后再 fillText，阿拉伯语系统下句点回到句末：返修后的写法（出处：卡里修好并验证过）
