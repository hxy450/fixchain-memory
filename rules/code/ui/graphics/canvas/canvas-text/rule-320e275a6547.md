# 移植 getTextBounds 的顶部对齐时保留 top 为负的语义，写 ascent + padding - 1

审的是：代码
触发（任一种）：
- 读到：源端 paint.getTextBounds(text, 0, len, bounds) 后顶部对齐写 top_y_diff = -bounds.top + padding - 1（bounds.top 是基线以上的负值，文字下移）；写错的样子：目标端写成 -boundsHeight + padding - 1 这类符号相反的式子，文字往上跑
适用范围：把安卓按 Paint.getTextBounds 结果做文字对齐（文字底衬、OSD 标签）的算法迁到 ArkUI Canvas 时
做法：
- const m = ctx.measureText(text); topYDiff = m.actualBoundingBoxAscent + padding - 1：actualBoundingBoxAscent 是基线到文字顶的距离，对应源端的 -bounds.top；底部用 actualBoundingBoxDescent 对应 bounds.bottom
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getTextBounds 返回包住所有字符的最小矩形，隐含原点在 (0,0)（基线起点）：bounds.top 在基线之上，是负值（出处：android.graphics.Paint#getTextBounds）
- readonly actualBoundingBoxAscent: number：textBaseline 所指水平线到文字矩形上沿的距离（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，TextMetrics.actualBoundingBoxAscent）
- 文本框改用 TextMetrics 的上升、下降值后对齐和源端一致：验证过的写法（出处：卡里修好并验证过）
