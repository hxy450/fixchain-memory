# 注册字体参与 measureText 布局时，首次布局前做就绪检查，几何经布局完成回调同步

审的是：代码
触发（任一种）：
- 读到：源端 Typeface.createFromAsset 同步装载，measureText 测宽参与布局；写错的样子：目标端调 registerFont 后马上 measureText 做首次布局；页面在尺寸变化回调之后立刻同步读布局结果算几何
适用范围：ArkUI Canvas 用注册字体测宽、测宽结果参与布局时
做法：
- 首次布局前做就绪探针：同字号下 `${size}px ${familyName}` 与 `${size}px sans-serif` 的 measureText(样本).width 不同即视为就绪；未就绪按帧重试，超过 1000ms 记日志后用系统字体继续
- 依赖布局结果的页面几何经布局完成回调（onLayout 一类）同步并重绘，不在尺寸变化后立即同步读取
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- measureText(text: string): TextMetrics：按当前 ctx.font 测宽，就绪探针用它比较两种 font 串的 width（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，CanvasRenderer.measureText）
- 通过 registerFont 注册是异步接口，调用后立即绘制可能导致自定义字体不生效：就绪检查的理由（出处：ts-canvasrenderingcontext2d.md，font）
- 就绪探针 + 按帧重试 + 1000ms 超时降级 + onLayout 回调同步几何后，冷启首次布局都得到注册字体度量：改法的依据（出处：卡里修好并验证过）
