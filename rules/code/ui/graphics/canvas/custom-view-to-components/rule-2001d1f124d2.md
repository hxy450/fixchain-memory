# 自绘指示条改写成组合布局时，底部内边距照源值，不把指示条高度扣掉

审的是：代码
触发（任一种）：
- 读到：自定义 View 的 onDraw 在 height − paddingBottom 之上画选中指示条和文字基线，布局 XML 给了 android:paddingBottom；写错的样子：鸿蒙端在 Text 下另加一个指示条高度的 Blank，又把 bottom padding 写成源值减去指示条高度
适用范围：把在 onDraw 里画指示条的自定义 View 改写成 Column + Text + 指示条的组合布局时
做法：
- 指示条放在 Text 下方（高度 = 源端 onDraw 里的指示条高度），容器的 .padding({ bottom: <源端 paddingBottom> }) 照源值写，指示条在内边距之上
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- bottom padding 改回源端 paddingBottom 的值：修好后指示条底距与源端一致（出处：卡里修好并验证过）
未核实：修复后只用契约测试锁定尺寸、没再做真机对比；这处 padding 是不是「显示过大」的全部原因卡里没确认
