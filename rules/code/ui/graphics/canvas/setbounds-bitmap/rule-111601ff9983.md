# 台账已批准离屏位图缓存时，沿用 OffscreenCanvas 预渲染加 drawImage 拉伸

审的是：代码
触发（任一种）：
- 读到：决策台账或规格写着位图「以 `OffscreenCanvas` 预渲染缓存」（对应源端 `createBitmap` 预烘焙 + `setBounds` 拉伸）；写错的样子：代码改走逐帧 `roundRect` + `fillText` 矢量绘制，注释却声明「行为等价」
适用范围：源端用预烘焙位图做动画缩放、而上游已批准离屏位图路线时
做法：
- 沿用离屏位图：用 OffscreenCanvas(烘焙尺寸, 烘焙尺寸).getContext('2d') 画一次底和文字，transferToImageBitmap() 取 ImageBitmap；每帧 ctx.drawImage(bitmap, 左, 上, 右 − 左, 下 − 上) 按源端 setBounds 的边界拉伸
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- drawImage(image: ImageBitmap | PixelMap, dx: number, dy: number, dw: number, dh: number): void：按 dw、dh 缩放绘制，位图里的圆角和文字随之等比缩放（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，CanvasRenderer.drawImage）
- constructor(width: number, height: number)：OffscreenCanvas 的构造（另有带 unit: LengthMetricsUnit 的重载）（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，OffscreenCanvas.constructor）
- getContext(contextType: "2d", options?: RenderingContextSettings): OffscreenCanvasRenderingContext2D；transferToImageBitmap(): ImageBitmap：取离屏 2D 上下文画好后转成 ImageBitmap（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，OffscreenCanvas.getContext、OffscreenCanvas.transferToImageBitmap）
未核实：离屏位图路线卡里没有上机验证，返修走的是矢量重绘加缩放和截断
