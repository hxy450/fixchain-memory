# 源端预缩放后原尺寸绘制时，目标按密度解码再 scaleSync，drawImage 不传 dw/dh

审的是：代码
触发（任一种）：
- 读到：BitmapFactory.decodeResource 解码单一密度目录的位图，Bitmap.createScaledBitmap(raw, w, h, filter) 预缩放，drawBitmap(bmp, x, y, null) 原尺寸绘制；写错的样子：原图解码一次后每帧 ctx.drawImage(img, x, y, w, h) 绘制期缩放，没有密度解码，也没指定最近邻
适用范围：渲染实现阶段把源端预缩放位图移植到 ArkUI Canvas 时
做法：
- 用 image.DecodingOptions.desiredSize 做密度解码：宽高 = (int)(资源像素 × 设备 dpi / 目录 dpi + 0.5)，设备 dpi 取 display.getDefaultDisplaySync().densityPixels × 160，目录 dpi 按源 res/drawable-<桶> 取
- 再 pixelMap.scaleSync(目标宽 / 当前宽, 目标高 / 当前高, level) 缩到目标尺寸：filter=false 用 image.AntiAliasingLevel.NONE，true 用 LOW
- 绘制写 ctx.drawImage(pixelMap, x, y)，不传 dw/dh
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- desiredSize?: Size，(0, 0) 表示按原图尺寸解码：DecodingOptions 里定解码输出尺寸（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.image.d.ts，DecodingOptions.desiredSize）
- scaleSync(x: number, y: number, level: AntiAliasingLevel): void，x、y 是宽高的缩放倍数：PixelMap 原地缩放（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.image.d.ts，PixelMap.scaleSync）
- AntiAliasingLevel.NONE = 0（最近邻）、LOW = 1（双线性）：对应 createScaledBitmap 的 filter=false / true（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.image.d.ts，AntiAliasingLevel）
- createScaledBitmap 的 filter 为 true 用双线性，为 false 用最近邻：源端 filter 的语义（出处：android.graphics.Bitmap#createScaledBitmap）
- DENSITY_LOW = 120、DENSITY_MEDIUM = 160、DENSITY_HIGH = 240、DENSITY_XHIGH = 320、DENSITY_XXHIGH = 480：ldpi / mdpi / hdpi / xhdpi / xxhdpi 目录对应的 dpi（出处：android.util.DisplayMetrics#DENSITY_LOW 等常量）
- densityPixels: number，物理像素与逻辑像素的缩放系数，低分辨率屏为 1.0：乘 160 得设备 dpi（出处：鸿蒙 SDK 的 ets/api/@ohos.display.d.ts，Display.densityPixels）
- 先按 (像素 × dpi + 60) / 120 解码，再 scaleSync(…, AntiAliasingLevel.NONE) 缩到目标尺寸、1:1 绘制，锯齿和源端一致：修好后的写法（ldpi 资源）（出处：卡里修好并验证过）
- createScaledPixelMapSync(x: number, y: number, level?: AntiAliasingLevel): PixelMap：同族接口：按倍数缩放并返回新的 PixelMap（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.image.d.ts，PixelMap.createScaledPixelMapSync）
针对本应用要查的：
- 资源所在密度目录和原图像素：源工程 res/drawable-<密度桶>/ 下按资源名找，读 PNG 的实际宽高；桶名按 DisplayMetrics 常量换成 dpi，代进解码尺寸公式
未核实：解码尺寸的 +0.5 取整出自建议，Android 端的取整在原生代码里，本机没核到
