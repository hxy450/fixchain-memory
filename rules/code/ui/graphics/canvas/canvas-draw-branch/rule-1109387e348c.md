# 源端 helper 不分 key 定描边宽时，目标共享分支统一 px2vp 换算，不按 key 特判

审的是：代码
触发（任一种）：
- 读到：源端通用绘制 helper 对所有图形统一设 paint.style = Paint.Style.STROKE 或 Paint.Style.FILL_AND_STROKE、paint.strokeWidth = 传入值 ?: 默认 px 值，没有指标 key 参与；写错的样子：目标多个指标共用的 Canvas 绘制分支写成 ctx.lineWidth = key === '某指标' ? 新值 : 旧值，只给被反馈的那个指标改线宽
- 写错的样子：共享绘制分支里 ctx.lineWidth 的旧值注释写着它服务于某个指标，而按分派条件那个指标已经不走这个分支，其他落入该分支的指标仍用这个旧值
适用范围：源端由不区分指标的通用 helper 绘制、目标端多个指标经分派落到同一个 Canvas 绘制分支时
做法：
- 先确认源端这个参数是否按 key 区分；不区分时在目标共享分支对所有落入的项统一写 ctx.lineWidth = px2vp(源端 strokeWidth 的 px 值)，不写 key === … ? … : …
- 按分派条件列出当前落入该分支的指标，核对旧值注释所称的服务对象是否仍走此分支；旧值已失去来源的，整个分支回到源端规则
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 共享空心柱分支去掉按 key 的三元，改为对所有落入的项统一用源端默认描边宽经 px2vp 换算后的值，作为修复保留：按源端通用规则统一实现，不做单指标特判（出处：卡里修好并验证过）
- public void setStrokeWidth(float width)：Set the width for stroking. Pass 0 to stroke in hairline mode.：源端描边宽是画布像素，Style 为 STROKE 或 FILL_AND_STROKE 时生效（出处：android.graphics.Paint#setStrokeWidth）
- Paint.Style.STROKE (1)、Paint.Style.FILL_AND_STROKE (2)：前者只描边（空心），后者填充加描边，两者都用 strokeWidth（出处：android.graphics.Paint.Style）
- lineWidth: number（不能为 0 或负数，@default 1(px)）：目标画布的线宽属性（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，CanvasRenderer.lineWidth）
- constructor(settings?: RenderingContextSettings, unit?: LengthMetricsUnit)；LengthMetricsUnit.DEFAULT 按 vp：不传 unit 构造的上下文按 vp 解释长度，这时源端 px 值要经 px2vp 换算（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，CanvasRenderingContext2D.constructor；ets/api/arkui/Graphics.d.ts，LengthMetricsUnit）
- declare function px2vp(value: number): number（@deprecated since 18，@useinstead UIContext#px2vp）：px 换 vp 的全局函数（出处：鸿蒙 SDK 的 ets/component/common.d.ts，px2vp）
针对本应用要查的：
- 源端这一类图形的默认描边宽：源工程里通用绘制 helper 的 Kotlin/Java 代码，找 Paint 的 strokeWidth 赋值（含 ?: 后的默认值）和 style 赋值；取默认 px 数值，填进 px2vp(…)；看 style 是 STROKE 还是 FILL_AND_STROKE 决定空心还是实心加描边
未核实：卡里记的是鸿蒙 SDK API 16，本机核实用的是 API 23（全局 px2vp 在 16 上还没废弃）
