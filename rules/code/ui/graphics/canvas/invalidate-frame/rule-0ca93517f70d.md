# 移植 View.invalidate 自续帧时，写成待决标志合并、postFrameCallback 只绘一次的唯一入口

审的是：代码
触发（任一种）：
- 读到：自定义 View 的 onDraw 尾部在动画进行时调 invalidate() 再 tick() 自续帧，业务层也用 invalidate() 请求重绘；写错的样子：目标渲染器另有同步直调 render() 的公开入口（方法体只有 this.render()），引擎桥、尺寸变化、onDraw 尾部各走各的路径；或者没有待决标志，同一帧的多次请求各排一次
适用范围：把安卓自定义 View 的 invalidate/onDraw 重绘迁成 ArkUI Canvas 全量重绘时，渲染器的重绘入口和帧调度
做法：
- 渲染器只留一个 invalidate()：已有待决帧或已 stop 就直接返回；否则置待决标志，调 uiContext.postFrameCallback(cb)；cb.onFrame 里先清待决标志再 render()
- render() 设为 private，按 onDraw 原顺序在尾部写 invalidate(); tick()；引擎桥、尺寸变化和业务调用都改调 invalidate()，不再同步调 render()
- UIContext 由页面用 getUIContext() 在构造渲染器时注入；页面销毁时调 stop() 置 stopped，之后到达的帧回调不再绘制
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- postFrameCallback(frameCallback: FrameCallback): void：UIContext 的方法，把回调排到下一帧执行一次（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.postFrameCallback）
- abstract class FrameCallback { onFrame(frameTimeInNano: number): void; onIdle(timeLeftInNano: number): void }：下一帧渲染时调 onFrame，参数是帧时间（纳秒）（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，FrameCallback.onFrame）
- postDelayedFrameCallback(frameCallback: FrameCallback, delayTime: number): void：同族接口：延迟 delayTime 毫秒后的下一帧执行（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.postDelayedFrameCallback）
- invalidate()：视图可见时 onDraw 会在之后某一帧被调用：源端每次 invalidate 只请求之后的一次 onDraw，可合并（出处：android.view.View#invalidate）
- 待决标志合并同帧请求、postFrameCallback 下一 vsync 绘制一次、stop() 丢弃待决帧：返修后的帧循环写法，动画结束后不再重绘（出处：卡里修好并验证过）
