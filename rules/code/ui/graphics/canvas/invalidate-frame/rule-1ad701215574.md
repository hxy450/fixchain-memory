# 引擎承接源端逐帧分发时，逐帧钩子要有调用方或 FWD-REF 登记，驱动源先核实

审的是：代码
触发（任一种）：
- 读到：源自绘 View 用 Handler.postDelayed 循环 invalidate，onDraw 里依次做暂停判断、过期复位、逐帧分发；spec 把这条 AC 指向覆盖层的逐帧入口；写错的样子：引擎里写了逐帧钩子，注释称由 XComponent 帧率或 frameStart 驱动，但 grep 钩子名只有定义、没有调用方，registry 里也没有 FWD-REF / HANDOFF
适用范围：相机预览这类没有逐帧回调的目标端，承接源端定时 tick 驱动的逐帧逻辑时
做法：
- 为钩子写出实际调用方，或在 placeholder registry 登记 FWD-REF / HANDOFF，指向覆盖层切片
- 注释里写的驱动源先核实目标平台确有这个逐帧回调：PreviewOutput.on('frameStart') 只在底层第一次开始曝光时回调，不是周期回调
- 交付前 grep 钩子名，结果至少有一处调用方或一条 registry 登记
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- on(type: 'frameStart', callback: AsyncCallback<void>): void：PreviewOutput 的预览帧开始事件（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.camera.d.ts，PreviewOutput.on('frameStart')）
- frameStart 在 previewOutput 创建成功后可监听，底层第一次开始曝光时触发：只回调一次，驱动不了逐帧逻辑（出处：arkts-apis-camera-PreviewOutput.md，on('frameStart')）
- on(type: 'frameStart', callback: AsyncCallback<void>): void：同族接口：VideoOutput 的录像开始事件（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.camera.d.ts，VideoOutput.on('frameStart')）
- 由覆盖层每个 tick 在未暂停且预览可见时调用引擎的逐帧钩子，并注明 frameStart 不是周期回调：修好后的接线（出处：卡里修好并验证过）
未核实：卡里修好时的目标 SDK 是 6.1.1(24)，本机核实声明用的是 API 23
