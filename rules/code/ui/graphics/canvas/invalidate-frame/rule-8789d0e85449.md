# 覆盖层用 setInterval 代替源端 tick 时，每个 tick 先判暂停、再调引擎逐帧钩子、最后绘制

审的是：代码
触发（任一种）：
- 读到：源 onDraw 里先判暂停，再做对焦框过期复位等逐帧处理，最后分发绘制回调；写错的样子：覆盖层 setInterval 回调里的绘制函数没有暂停守卫，也不调用引擎的逐帧钩子，只自己绘制
适用范围：Canvas 自绘覆盖层用定时器替代源端自绘 View 的定时 tick 时
做法：
- 每个 tick 按源端顺序执行：暂停守卫（未暂停且预览可见）→ 调引擎的逐帧钩子（对焦框过期、帧分析刷新）→ 绘制
- 发现钩子没有调用方时，由自身 tick 调用它或登记 FWD-REF，不默认「后续接线会补」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- setInterval(handler: Function | string, delay: number, ...arguments: any[]): number：重复定时器，返回定时器 ID；非精准计时（出处：js-apis-timer.md，setInterval）
针对本应用要查的：
- tick 周期：源自绘 View 里 postDelayed 的延迟参数（或它调用的取帧率方法）；毫秒数照搬给 setInterval 的 delay
