# drawBitmap+Matrix 迁到 ArkUI Canvas 时，PixelMap 用五参数 drawImage

审的是：代码
触发（任一种）：
- 读到：源端 canvas.drawBitmap(bitmap, matrix, paint)，Matrix.setRectToRect 把位图像素矩形映射到画布；写错的样子：目标端变换矩阵的源矩形取 PixelMap 的 getImageInfoSync().size（像素），绘制却用三参数 ctx.drawImage(pm, 0, 0)
适用范围：在 ArkUI CanvasRenderingContext2D 上配合变换矩阵绘制 PixelMap（缩略图、叠加图、斑马纹等）时
做法：
- const info = pm.getImageInfoSync(); ctx.drawImage(pm, 0, 0, info.size.width, info.size.height)：dw/dh 和矩阵源矩形用同一对数值，不依赖三参数形式的默认尺寸
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- drawImage(image: ImageBitmap | PixelMap, dx: number, dy: number, dw: number, dh: number): void：dw/dh 是图在目标画布上的绘制宽高，图会按它缩放（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，CanvasRenderer.drawImage）
- drawImage(image: ImageBitmap | PixelMap, dx: number, dy: number): void；dx、dy 默认单位 vp：三参数形式不给绘制尺寸（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，CanvasRenderer.drawImage；ts-canvasrenderingcontext2d.md，drawImage）
- getImageInfoSync(): ImageInfo；ImageInfo.size: Size：PixelMap 的宽高，用作矩阵源矩形和 dw/dh（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.image.d.ts，PixelMap.getImageInfoSync、ImageInfo.size）
- 三参数 drawImage 按 PixelMap 原始像素尺寸绘制，在 vp 画布上和像素矩阵混用会错位；全部改成 drawImage(bm, 0, 0, info.size.width, info.size.height) 后正确：验证过的写法（出处：卡里修好并验证过）
- drawImage(image: ImageBitmap | PixelMap, sx: number, sy: number, sw: number, sh: number, dx: number, dy: number, dw: number, dh: number): void：同族接口：九参数形式，先裁源矩形再画到目标矩形（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，CanvasRenderer.drawImage）
未核实：三参数 drawImage 按原始像素尺寸绘制只出自卡里观察，声明和文档没写默认绘制尺寸；卡里环境是 HarmonyOS 6.1.1（API 24），本机声明是 API 23
