# 源端一次烘焙背景位图、目标改每帧矢量重绘时，render() 开头先 clearRect 整幅画布

审的是：代码
触发（任一种）：
- 读到：自定义 View 构造里 `setBackgroundColor(…)`，`onDraw` 开头 `drawBitmap(background)` 画一张只烘焙一次的 `ARGB_8888` 透明背景位图（标题、说明等抗锯齿文字只栅格化一次），再叠动态层；写错的样子：目标 `render()` 开头直接画背景层，标题、说明每帧 `fillText` 叠到上一帧上，没有 `clearRect`，也没有整幅填背景色
适用范围：把源端预烘焙位图改成 ArkUI Canvas 上 CanvasRenderingContext2D 每帧矢量重绘时
做法：
- render() 开头写 ctx.clearRect(0, 0, ctx.width, ctx.height)（或整幅填背景色），再按源端顺序绘制背景层和动态层
- 源端 View 的 setBackgroundColor 由 Canvas 组件的 .backgroundColor(…) 承担，清屏后露出的就是这层底色
- 判断能否省略清屏时按「每帧是否从空白开始」判定；透明区域重复 fillText、描边的抗锯齿内容都会逐帧累积，不能只看不透明色块是否覆盖
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- clearRect(x: number, y: number, w: number, h: number): void：清除矩形区域的绘制内容（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，CanvasRenderer.clearRect）
- readonly width: number / readonly height: number：绑定到画布的宽高，清屏矩形用它（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，CanvasRenderingContext2D.width）
- View.draw 先 drawBackground(canvas) 再 onDraw(canvas)：源端每次绘制先铺背景色，位图里的文字不会叠画（出处：android.view.View#draw）
- CanvasRenderingContext2D 的位图跨帧保留；render() 开头加 clearRect 后，多次滑动标题区边缘像素数不再变化：不清屏时抗锯齿文字逐帧累积 alpha 变粗（出处：卡里修好并验证过）
