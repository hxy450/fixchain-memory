# 源端在 onSizeChanged 预渲染背景位图时，目标每帧重绘也要给条件元素的状态留快照

审的是：代码
触发（任一种）：
- 读到：自定义 View 在 onSizeChanged 里生成背景 Bitmap，生成函数里 if (某状态字段) 才画某元素；onDraw 每帧只 canvas.drawBitmap(背景位图, …)；该字段之后还会被新开局一类流程改写；写错的样子：目标 Canvas 每帧画背景层时直接读实时状态字段（if (状态字段) 每帧判断），没有在布局或尺寸变化入口留快照
适用范围：把安卓自绘 View 的预渲染背景位图或缓存，改成 ArkUI Canvas 每帧矢量绘制时
做法：
- 先逐一列出缓存生成函数里读到的可变状态，以及缓存的重建时机（只在 onSizeChanged）
- 在目标端对应的布局或尺寸变化入口（与源端重建时机相同的那个函数）把这些状态存成快照字段，背景层绘制只读快照，不读实时字段
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- protected void onSizeChanged(int w, int h, int oldw, int oldh)：This is called during layout when the size of this view has changed：源端位图只在尺寸变化时重建，里面的条件元素按那一刻的状态取定（出处：android.view.View#onSizeChanged）
- 布局函数里取宿主的状态存成背景快照，背景层改读快照；首启、新游戏后、重启三态与安卓一致：修复后的写法和复测结果（出处：卡里修好并验证过）
- onReady(event: VoidCallback): CanvasAttribute：Canvas 上下文就绪回调，常和尺寸变化一起作为布局入口（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，CanvasAttribute.onReady）
