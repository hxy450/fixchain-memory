# 源端每轮 new 循环线程时，目标每个实例对应一个循环对象，startLoop 不先清掉旧句柄

审的是：代码
触发（任一种）：
- 读到：源码初始化方法里 new 一个 Thread 子类赋给同一字段，停止只经这个字段；写错的样子：目标用一个 static 句柄字段承载全局唯一循环，起新循环前先 clearInterval(旧句柄) 再 setInterval 新句柄；页面用两个布尔旗承载结算弹窗
适用范围：把源端每局新建、旧实例不停的 Thread 游戏循环迁成 ArkTS 帧循环时
做法：
- 写一个循环类对应源端 Thread 子类：状态放实例字段，start 只能调一次，退出循环后再投递结算回调；初始化先 new 实例，surfaceCreated/surfaceDestroyed 的对应物只作用于最新引用
- 结算对话框用按出现顺序叠放的列表承载，不用两个布尔旗
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 改为实例类（实例字段、start 只调一次、退出后投递结算）、共享 60fps vsync 轮转、对话框按出现顺序成列表后，与安卓实测一致：修好的结构（出处：卡里修好并验证过）
- It is never legal to start a thread more than once：目标循环对象同样只允许启动一次（出处：java.lang.Thread#start）
