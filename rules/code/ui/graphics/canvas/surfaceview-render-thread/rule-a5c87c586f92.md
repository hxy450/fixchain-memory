# 画布下放背景层前核对源自绘类，默认 Z 序 SurfaceView 不放背景 Image

审的是：代码
触发（任一种）：
- 读到：源自绘视图类 extends SurfaceView（或 GLSurfaceView），构造器只 getHolder().addCallback(this)，没有 setZOrderOnTop / setFormat，每帧 drawColor(Color.TRANSPARENT, PorterDuff.Mode.CLEAR)；写错的样子：目标 Stack 底层放了 Image(…).objectFit(ImageFit.Fill) 背景层，上面是透明 Canvas，每帧 clearRect 后露出背景图
适用范围：把安卓 SurfaceView 自绘视图迁成 ArkUI Canvas、并在它下面叠背景层时
做法：
- 打开源自绘视图类，核对父类（SurfaceView 还是普通 View）、setZOrderOnTop / setFormat 调用和清屏方式；是默认 Z 序的 SurfaceView 时去掉画布下的背景 Image
- 画布所在的根 Stack 写 .backgroundColor(Color.Black)（surface 清成透明时的可见色），每帧 clearRect 不变；规格或派工给的背景层和源码冲突时按源端可见结果实现，并回报规格分歧
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- SurfaceView 的 surface 按 Z 序位于持有它的窗口之后，SurfaceView 在窗口上打洞：父容器 android:background 在 surface 区域不可见（出处：android.view.SurfaceView 类注释）
- Color.Black：写进根 Stack 的 backgroundColor（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，Color.Black）
- clearRect(x: number, y: number, w: number, h: number): void：每帧清屏保持不变（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，CanvasRenderer.clearRect）
- 去掉背景 Image、根 Stack 为 backgroundColor(Color.Black) 后，和安卓同一画面对照为黑底：修好的写法（出处：卡里修好并验证过）
针对本应用要查的：
- surface 区域的可见底色：源工程里该 SurfaceView 子类的绘制循环开头；CLEAR 成透明或不画底色时为黑；画了实色就取那个颜色写进 backgroundColor
