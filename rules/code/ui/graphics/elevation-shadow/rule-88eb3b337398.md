# dp 高程阴影不用预置 ShadowStyle，经共享映射写 ShadowOptions，全工程只留一条通路

审的是：代码
触发（任一种）：
- 读到：Modifier.shadow(elevation = 3.dp, shape = …)，或规格、派工里写「shadow 3dp」这类高程阴影；写错的样子：.shadow(ShadowStyle.OUTER_DEFAULT_XS) 等预置样式替代高程阴影
- 读到：规格 mapping 的阴影节已定义共享的 elevation → ShadowOptions 映射函数；写错的样子：页面里另写字面的 .shadow({ radius: …, offsetY: …, color: … })，不经共享映射函数
适用范围：工程定义了共享高程阴影映射、源端用 dp 高程表达阴影时，页面和组件里的每一处 .shadow
做法：
- 源端 dp 高程一律经共享映射函数得到按 dp 校准的 ShadowOptions，再写进 .shadow(...)；不用 ShadowStyle 预置值替代
- 写完在全工程搜 \.shadow\( ，核对除共享映射函数外没有别的阴影写法
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- ShadowStyle：OUTER_DEFAULT_XS = 0、OUTER_DEFAULT_SM = 1、OUTER_DEFAULT_MD = 2、OUTER_DEFAULT_LG = 3、OUTER_FLOATING_SM = 4、OUTER_FLOATING_MD = 5：系统预置的几档固定阴影，不随源端高程数值变化（出处：鸿蒙 SDK 的 ets/component/common.d.ts，ShadowStyle）
- shadow(value: ShadowOptions | ShadowStyle): T：同一个接口既收预置样式也收 ShadowOptions，编译不会拦预置值（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.shadow）
