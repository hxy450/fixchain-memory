# dp 高程落到 .shadow 时，radius 和 offset 先 vp2px 换算再填

审的是：代码
触发（任一种）：
- 读到：Compose `Modifier.shadow(elevation = 3.dp, shape = …)`，或 Surface 类容器的 `elevation: Dp` 参数（内部 .shadow(elevation = elevation, …)）；写错的样子：`.shadow({ radius: …, offsetY: … })` 里直接写源端 dp 数值、this.elevation / 2 或字面数字，没有经过 vp2px
- 读到：android:elevation；写错的样子：.shadow({ radius: 6, offsetY: 3, … }) 这类把 dp 数直接填进 ShadowOptions，没有 vp2px
适用范围：源端 dp 高程阴影（Compose Modifier.shadow、Surface elevation、android:elevation）迁成 ArkUI 组件 .shadow(ShadowOptions) 时
做法：
- radius、offsetX、offsetY 按 px 写，源端 dp 高程 e 先经 UIContext 换算：.shadow({ radius: uiContext.vp2px(k * e), offsetY: uiContext.vp2px(m * e), color: … })，uiContext 取 this.getUIContext()，共享映射函数把 UIContext 作为参数传进去；k、m 和颜色见取值
- 长度属性的 dp→vp 1:1 规则不用到 ShadowOptions 的数值字段上
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- ShadowOptions.radius: number | Resource，单位 px；offsetX、offsetY 单位 px，默认 0：阴影的模糊半径和偏移都按 px 解释，与 width、padding 缺省 vp 不同；dp 来源的数要先换成 px（出处：鸿蒙 SDK 的 ets/component/common.d.ts，ShadowOptions）
- shadow(value: ShadowOptions | ShadowStyle): T：组件阴影接口（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.shadow）
- vp2px(value: number): number：UIContext 上把 vp 换成 px（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.vp2px）
- radius = vp2px(e)、offsetY = vp2px(e / 2)、25% 黑（'#40000000'）：一张卡里修好的换算；dp 直写时 3.5px/vp 设备上 elevation 2 的模糊只剩约 0.6vp，投影几乎不可见（出处：卡里修好并验证过）
- radius = vp2px(1.2 * e)、offsetY = vp2px(0.8 * e)、color '#33000000'：另一张卡按三档安卓实测反推的常量；多数组件对齐，一处侧晕、顶晕仍约为安卓的一半（出处：卡里修好并验证过）
- shadow?: ShadowOptions | ShadowStyle：同族接口：SheetOptions.shadow（半模态的阴影），数值同样按 px（出处：鸿蒙 SDK 的 ets/component/common.d.ts，SheetOptions.shadow）
- shadow?: ShadowOptions | ShadowStyle：同族接口：CustomDialogControllerOptions.shadow（自定义弹窗的阴影），ShadowOptions 同样按 px（出处：鸿蒙 SDK 的 ets/component/custom_dialog_controller.d.ts，CustomDialogControllerOptions.shadow）
- textShadow(value: ShadowOptions | Array<ShadowOptions>): TextAttribute：同族接口：Text 的文字阴影，ShadowOptions 同样按 px（出处：鸿蒙 SDK 的 ets/component/text.d.ts，TextAttribute.textShadow）
未核实：换算系数和颜色两张卡不同：case-6aedeaac4c252c3c5626 是 radius vp2px(e)、offsetY vp2px(e / 2)、25% 黑；case-75329cae60986f74dc43 是 radius vp2px(1.2e)、offsetY vp2px(0.8e)、#33000000（按三档安卓实测反推）。两张卡都先 vp2px 换算，分歧只在常量；实测反推的常量只在部分组件上收敛，ArkUI 单模糊阴影与安卓 spot+ambient 模型的差异没判定
来源：2 张卡，1 个应用
- case-6aedeaac4c252c3c5626（Jetsnack）：做法第 1 步 ← 建议 1、诊断；做法第 2 步 ← 建议 1；取值 4 ← 诊断
- case-75329cae60986f74dc43（Jetsnack）：做法第 1 步 ← 建议 1、诊断；取值 5 ← 诊断
