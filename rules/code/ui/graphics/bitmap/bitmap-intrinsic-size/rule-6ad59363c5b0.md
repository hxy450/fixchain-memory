# wrap_content 图片按资源像素和密度目录定宽高或 Contain，不用固定正方形再叠 padding

审的是：代码
触发（任一种）：
- 读到：ImageView 的 layout_width / layout_height 是 wrap_content，带 android:padding，src 指向某个密度目录下的位图；写错的样子：Image 写成固定正方形 .width(n).height(n) 再叠 .padding(...)，可视图形被压小或裁切
适用范围：把 wrap_content 的图片控件迁成 ArkUI Image 时
做法：
- 查资源的像素尺寸和所在密度目录，换成 vp：vp = px × 160 ÷ 目录密度（xxldpi / xxhdpi 按 480 即 px ÷ 3）；按这个固有尺寸写 .width().height()，或按固有比例写一边加 .objectFit(ImageFit.Contain)
- 源端的 padding 加在这个尺寸外面，不压进固定框里
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- objectFit(value: ImageFit): ImageAttribute，默认 ImageFit.Cover：图片在容器里的缩放方式；默认 Cover 会裁切（出处：鸿蒙 SDK 的 ets/component/image.d.ts，ImageAttribute.objectFit）
- ImageFit.Contain：保持宽高比缩放，图片完整显示在边界内：按固有比例完整显示（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，ImageFit.Contain）
- xxldpi 适用于 dpi 取值 (320, 480] 的设备：目标资源目录的密度档（出处：resource-categories-and-access.md，限定词目录）
- DENSITY_XXHIGH = 480，DENSITY_DEFAULT = DENSITY_MEDIUM = 160：源端 xxhdpi 位图按 480 / 160 = 3 换成 dp（出处：android.util.DisplayMetrics#DENSITY_XXHIGH）
- 180×81px 的 xxldpi 资源按 60×30vp 加 Contain 写后，可视图形与源端一致：按资源像素定尺寸的落法（出处：卡里修好并验证过）
- objectFit(value: ImageFit): ImageSpanAttribute：同族接口：ImageSpan 的缩放方式（出处：鸿蒙 SDK 的 ets/component/image_span.d.ts，ImageSpanAttribute.objectFit）
- objectFit(value: ImageFit): VideoAttribute：同族接口：Video 的缩放方式（出处：鸿蒙 SDK 的 ets/component/video.d.ts，VideoAttribute.objectFit）
针对本应用要查的：
- 资源的像素尺寸和密度目录：源工程 res/drawable-*dpi 或目标工程 resources 下各密度目录里的同名位图；读出图片宽高像素和目录的密度档，按上面的公式换成 vp
