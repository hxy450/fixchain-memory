# 位图图标显示尺寸按资源像素 ÷ 源密度换算，不凭经验填 32、44

审的是：代码
触发（任一种）：
- 读到：安卓位图放在 drawable-xxhdpi 等密度目录（如 72×72px 的 png），由 ImageView 显示；写错的样子：Image 写 .width(32).height(32)、44 这类不是由像素换算来的尺寸
适用范围：把安卓密度目录里的位图图标放到目标端无密度限定的 base/media 并给 Image 定显示尺寸时
做法：
- 读每个资源的实际像素（png 文件头 IHDR 的宽、高），按所在密度目录分别换算宽和高：vp = px × 160 ÷ 目录 dpi；xxhdpi 是 px ÷ 3（72×72px → 24×24vp，74×72px → 25×24vp）
- 更换图标资源后重新读像素、重新核对尺寸
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- DENSITY_MEDIUM = 160，一个 dp 在约 160dpi 屏上是一个像素：换算基准（出处：android.util.DisplayMetrics#DENSITY_MEDIUM、android.util.DisplayMetrics#density）
- DENSITY_HIGH = 240、DENSITY_XHIGH = 320、DENSITY_XXHIGH = 480、DENSITY_XXXHIGH = 640：hdpi、xhdpi、xxhdpi、xxxhdpi 目录对应的 dpi，除数分别是 1.5、2、3、4（出处：android.util.DisplayMetrics#DENSITY_XXHIGH 等常量）
- xxhdpi 的 72×72px 位图显示为 24×24vp：按此改后图标大小与源端一致（出处：卡里修好并验证过）
针对本应用要查的：
- 每个图标的像素宽高和所在密度目录：源工程 res 下 drawable-<密度> 目录里同名 png（读文件头 IHDR 的宽、高）；目标工程 resources/base/media 里换成的同名图也要核；宽、高各自 × 160 ÷ 目录 dpi，得到 vp
未核实：安卓 ImageView 在承载区里默认缩放下的实际绘制尺寸没在设备上核实，卡里以修复后 24–25vp 且用户未再反馈为参照
