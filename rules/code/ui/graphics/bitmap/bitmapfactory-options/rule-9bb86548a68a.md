# inSampleSize 不直译成 DecodingOptions.sampleSize，改算 desiredSize

审的是：代码
触发（任一种）：
- 读到：源端 BitmapFactory.Options 先 inJustDecodeBounds 取尺寸，再按 2 的幂设 inSampleSize 降采样解码；写错的样子：目标 ImageSource.createPixelMap 的 DecodingOptions 里写 sampleSize: <源端的 inSampleSize>
适用范围：把源端降采样解码迁成 ImageSource.createPixelMap 时
做法：
- 先 imageSource.getImageInfoSync() 取原图宽高，写 createPixelMap({ desiredSize: { width: Math.floor(原宽 / sampleSize), height: Math.floor(原高 / sampleSize) } })，不写 sampleSize
- 用 fd 打开源文件创建 ImageSource，在 finally 里释放 ImageSource 和 fd
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- desiredSize?: Size；(0, 0) 表示按原图尺寸解码：解码输出的宽高（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.image.d.ts，DecodingOptions.desiredSize）
- sampleSize?: number（Sampling ratio of the image pixel map，@since 12）：声明只写了采样比，没写取值限制（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.image.d.ts，DecodingOptions.sampleSize）
- 设备上 sampleSize = 8 使解码插件失败；改成 desiredSize = 原尺寸 / sampleSize 后正常：直译的后果和落法（出处：卡里修好并验证过）
- inSampleSize > 1 时按 2 的幂向下取整，输出宽高为原图的 1/inSampleSize；≤ 1 等同 1：源端值的含义，用来算 desiredSize（出处：android.graphics.BitmapFactory.Options#inSampleSize）
- createPixelMap(options?: DecodingOptions): Promise<PixelMap>；getImageInfoSync(index?: number): ImageInfo：解码和取原图信息（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.image.d.ts，ImageSource.createPixelMap、ImageSource.getImageInfoSync）
未核实：sampleSize 只支持 1 是设备上观察到的，声明和本地文档里都没写；卡里环境是 API 24
