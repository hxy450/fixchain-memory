# ImageView 带 adjustViewBounds 时，Image 用 aspectRatio 跟随位图比例

审的是：代码
触发（任一种）：
- 读到：ImageView 写了 wrap_content 和 android:adjustViewBounds="true"，可带 app:layout_constrainedWidth="true"、horizontal_bias，宽度受同行兄弟和边距约束；写错的样子：Image 只写了 .layoutWeight(1).objectFit(ImageFit.Contain)，或写了固定的 .width().height()，没有 .aspectRatio(...)
适用范围：把 wrap_content + adjustViewBounds 的安卓 ImageView 迁成 Row 等容器里的 ArkUI Image 时的宽高约束
做法：
- 读源位图的像素宽高和所在密度桶，换算本征 vp 宽高（像素 × 160 / 桶的 dpi）
- 写成 Image(...).layoutWeight(1).constraintSize({ maxWidth: <本征宽vp> }).aspectRatio(<像素宽> / <像素高>).objectFit(ImageFit.Contain)：aspectRatio 让高度跟随分得的宽度，maxWidth 对应 wrap_content 上限，layoutWeight 或父容器剩余空间对应 constrainedWidth
- 写完确认高度由 aspectRatio 决定；只有 layoutWeight + Contain 或固定 height 时，高度不随比例变化
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- aspectRatio(value: number): T；aspectRatio = width / height，只设宽时 height = width / aspectRatio：高度按位图比例跟随宽度（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.aspectRatio；ts-universal-attributes-layout-constraints.md，aspectRatio）
- constraintSize(value: ConstraintSizeOptions): T，默认 {minWidth: 0, maxWidth: Infinity, minHeight: 0, maxHeight: Infinity}：maxWidth 写本征宽，对应 wrap_content 不超过位图本身（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.constraintSize）
- layoutWeight(value: number | string): T，默认 0：在 Row / Column / Flex 主轴上按权重分剩余空间（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.layoutWeight）
- ImageFit.Contain：保持宽高比缩放，使图片完全显示在显示边界内：只决定内容在框内怎么缩放，不决定组件高度（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，ImageFit.Contain）
- adjustViewBounds：为 true 时 ImageView 调整边界以保持 drawable 的宽高比：源端高度跟随位图比例（出处：Android SDK 平台资源 data/res/values/attrs.xml，ImageView 的 adjustViewBounds（按应用的 compileSdk 取对应平台））
- layoutWeight(1) + constraintSize({ maxWidth: 本征宽 }) + aspectRatio(像素宽 / 像素高) + Contain，去掉固定高度：修复后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源位图的像素宽高和密度桶：源工程 res/ 下各 drawable-*dpi/、mipmap-*dpi/ 目录里与 src 引用同名的 png/webp 文件；用 sips、PIL 或读 webp/png 文件头取像素宽高；目录名的 mdpi/hdpi/xhdpi/xxhdpi/xxxhdpi 定 dpi，按 像素 × 160 / dpi 得本征 vp
