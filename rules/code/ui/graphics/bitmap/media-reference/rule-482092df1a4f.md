# 判 $r('app.media.…') 缺失前查遍各限定词目录，缺了登记，不用字形、纯色或近似图标顶替

审的是：代码
触发（任一种）：
- 读到：源布局用 @drawable/… 引图（ImageView 的 android:src、TextView 的 android:drawableStart、容器的 android:background），图只在 drawable-xhdpi 这类密度目录里；写错的样子：目标在该处写成 Text('›') 这类文字字形、只垫一个 .backgroundColor(...) 纯色，或换成名字不同的通用图标；理由是 base/media 里没有这张图
- 读到：源码 setImageResource(R.drawable.…) 或 XML android:background="@drawable/…" 引原图，目标代码已有对应的 Image($r('app.media.…'))；写错的样子：以「仓库中不存在的 media」为由把 Image($r('app.media.…')) 换成 SymbolGlyph＋文字按钮或白底描边行，并改了尺寸、间距
适用范围：安卓 drawable 迁到 resources 下的 media（base 或 xldpi 等限定词目录）后，代码引用这些图片时
做法：
- 判断 $r('app.media.<源 drawable 名>') 是否可用时，检索 resources 下全部限定词目录的 media（base、xldpi、xxldpi 等）或按资源映射表核对；任一目录有同名文件就照源名写 Image($r('app.media.<源 drawable 名>'))
- 各目录都确实没有时，登记资源缺口；不用文字字形、纯色底、SymbolGlyph 或外观近似的图标替代源 drawable，也不改尺寸和间距
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 系统先在与设备状态相匹配的限定词目录里找资源，限定词目录里没有才去 base 目录找：资源放在 xldpi/media 而 base/media 没有时，$r 引用照样能取到，不算缺失（出处：resource-categories-and-access.md，资源匹配）
- 限定词目录（如 xxldpi）同 base 一样有 media 子目录，里面的资源同样分配资源 ID，按类型和名称访问：$r('app.media.x') 的文件可能只在限定词目录里（出处：resource-categories-and-access.md，资源目录）
- DENSITY_XHIGH = 320；xldpi 适用于 dpi 取值 (240, 320] 的设备：源 drawable-xhdpi 的图迁过来常落在 xldpi/media，不在 base/media（出处：android.util.DisplayMetrics#DENSITY_XHIGH；resource-categories-and-access.md，限定词目录（表5 屏幕密度））
- 屏幕密度限定词：sdpi、mdpi、ldpi、xldpi、xxldpi、xxxldpi：检索时这些目录都要搜（出处：resource-categories-and-access.md，限定词目录）
- 构建日志对只在限定词目录、base 下没有的 media 报 “does not have a base resource”：这句说明资源在别的限定词目录里，改用原图即可，不是资源缺失（出处：卡里修好并验证过）
- 修好后改回 Image 32vp、右距 13 和 83×28 的背景图，直接复用限定词目录里的 png：原图一直在 xxldpi/media（出处：卡里修好并验证过）
- (src: PixelMap | ResourceStr | DrawableDescriptor | ImageContent): ImageAttribute：Image 组件的构造，源 drawable 写成 Image($r('app.media.<名>'))（出处：鸿蒙 SDK 的 ets/component/image.d.ts，ImageInterface）
针对本应用要查的：
- 源 drawable 在目标工程里落在哪个目录：目标工程模块 resources 下各目录（base、xldpi、xxldpi 等）的 media 子目录，或流水线的资源映射表里 drawable-<密度> 到目标目录的对应；按源 drawable 名（去掉扩展名）找同名文件，找到任一处即可在代码里用 $r('app.media.<名>')
