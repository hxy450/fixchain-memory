# ContentScale.FillWidth 不用 ImageFit.Fill，按图片比例算高并 clip

审的是：代码
触发（任一种）：
- 读到：Compose Image / AsyncImage 写 contentScale = ContentScale.FillWidth，或组件的 contentScale 由调用方传入、调用处传 ContentScale.FillWidth；写错的样子：目标 Image 写 .objectFit(ImageFit.Fill) 或 ImageFit.Cover 代替；或 ArkTS 组件只暴露 ImageFit 参数，调用处传 ImageFit.Fill
适用范围：Compose 图片的 ContentScale.FillWidth 迁成 ArkUI Image 时
做法：
- 宽度铺满容器；在 Image 的 .onComplete((e) => …) 里用 e.width / e.height 求图片宽高比，高度设为容器宽 ÷ 宽高比；外层容器 .clip(true)
- 源组件的 contentScale 由调用方传入时，ArkTS 组件也提供对应参数（例如布尔的 fillWidth），调用处照源端传
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- ImageFit：Contain、Cover、Auto、Fill、ScaleDown、None、TOP_START = 7 … BOTTOM_END = 15、MATRIX = 16，没有按宽铺满的成员：FillWidth 在 ImageFit 里没有对应值（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，ImageFit）
- ImageFit.Fill：不保持宽高比缩放到填满显示边界：用 Fill 会把图拉变形（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，ImageFit.Fill）
- onComplete(callback: (event?: { width: number, height: number, componentWidth: number, componentHeight: number, loadingStatus: number, contentWidth: number, contentHeight: number, contentOffsetX: number, contentOffsetY: number }) => void): ImageAttribute：加载或解码成功时回调，width / height 是图源尺寸，单位 px（出处：鸿蒙 SDK 的 ets/component/image.d.ts，ImageAttribute.onComplete）
- objectFit(value: ImageFit): ImageSpanAttribute：同族接口：ImageSpan 的 objectFit，同样没有 FillWidth（出处：鸿蒙 SDK 的 ets/component/image_span.d.ts，ImageSpanAttribute.objectFit）
- objectFit(value: ImageFit): VideoAttribute：同族接口：Video 的 objectFit（出处：鸿蒙 SDK 的 ets/component/video.d.ts，VideoAttribute.objectFit）
未核实：卡里的上机行为出自 HarmonyOS 6.1.1(24)，本机按 API 23 的声明核实
