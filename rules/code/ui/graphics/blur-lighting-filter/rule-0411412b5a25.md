# 源端模糊加 LightingColorFilter(mul, 0) 压暗时，用 blur 加黑色覆盖层按乘数换算

审的是：代码
触发（任一种）：
- 读到：源码给头部背景图加模糊变换，并 setColorFilter(new LightingColorFilter(mul, add)) 压暗；写错的样子：目标背景 Image 没有 .blur(...)，只用 ImageFit.Cover 加半透明遮罩近似，或没按 mul 的系数压暗
- 读到：Glide 加载背景图时做模糊变换，并 setColorFilter(new LightingColorFilter(mul, 0)) 乘法压暗；写错的样子：目标以「ArkUI 无对等图片模糊链」为由只用 Cover 图加固定 50% 黑色 tint 近似，并登记 UNC 占位
适用范围：源端背景图同时有模糊变换和 LightingColorFilter 乘法压暗，迁成 ArkUI Image 背景时
做法：
- 背景 Image 加 .blur(模糊半径)，半径照源端模糊变换的参数取
- 按 mul 逐通道相乘压暗：R' = R × mul.R / 0xFF（如 0xff828282 即 × 0x82/0xFF）；add 为 0 时用叠在图上的纯黑覆盖层 .backgroundColor(Color.Black).opacity(1 - mul 的通道值 / 255) 直接实现，不登记近似占位
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- R' = R * colorMultiply.R + colorAdd.R（G、B 同理），结果截到 [0..255]，alpha 不变；mul、add 的 alpha 被忽略：源端压暗的算法：mul 各通道按 /255 当乘数；add 为 0 时等价于盖一层不透明度 1 - mul/255 的纯黑（出处：android.graphics.LightingColorFilter）
- blur(value: number, options?: BlurOptions): T：给组件内容加模糊，入参是模糊半径，0 为不模糊（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.blur）
- opacity(value: number | Resource): T：黑色覆盖层的不透明度（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.opacity）
- backdropBlur(value: number, options?: BlurOptions): T：同族接口：模糊组件背后的内容，不是模糊组件自身（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.backdropBlur）
- 模糊加乘法系数 0x82 后与源端一致：按源参数复刻是上机核对过的写法（出处：卡里修好并验证过）
- tint 底 + blur 的封面图 + opacity = 1 - mul/255 的黑层：卡里返修后的叠法（出处：卡里修好并验证过）
针对本应用要查的：
- 模糊半径和压暗的 mul、add：源工程加载背景图的 Java/Kotlin 代码：Glide 等图片库 transform 里模糊变换的构造参数，以及 setColorFilter 里 LightingColorFilter 的两个参数；mul 取 RGB 三个字节各除以 0xFF 作乘数（三通道相同时取其一代入 1 - mul/255 作黑层不透明度），add 取 RGB 作偏移；模糊半径照构造参数取
未核实：源端模糊半径与 ArkUI blur 半径是否同一尺度没核实；一张卡返修用的是 blur 20
