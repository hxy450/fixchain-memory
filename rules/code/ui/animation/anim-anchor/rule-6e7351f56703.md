# 源端触发时才读锚点窗口位置，目标取本次手势坐标，onAreaChange 缓存只兜底

审的是：代码
触发（任一种）：
- 读到：源端在动效触发时对锚点 View 调 getLocationInWindow，再加 getWidth() / 2、getHeight() / 2 求起点；写错的样子：目标在 onAreaChange 里缓存 newValue.globalPosition 加半宽半高，点击（TapGesture / onClick）时直接拿缓存值当起点
适用范围：列表项或面板里点击触发、起点跟着被点元素的一次性动效，尤其列表项有 translate 平移或 LazyForEach 复用时
做法：
- 在 TapGesture(...).onAction((event: GestureEvent) => …) 里取 event.fingerList[0].globalX / globalY 作起点；拿不到触点（fingerList 为空）时才用 onAreaChange 记下的控件中心兜底
- 起点换成覆盖层宿主里的坐标：FingerInfo.globalX/Y 相对应用窗口左上角，onAreaChange 的 globalPosition 相对页面左上角，和宿主的位置换到同一坐标系后再相减
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- fingerList: FingerInfo[]：GestureEvent 上的全部手指信息，用于 TapGesture 和 LongPressGesture（出处：鸿蒙 SDK 的 ets/component/gesture.d.ts，GestureEvent.fingerList）
- FingerInfo.globalX / globalY：相对应用窗口左上角，单位 vp：本次触点的窗口坐标（出处：鸿蒙 SDK 的 ets/component/gesture.d.ts，FingerInfo.globalX；ts-gesture-common.md，FingerInfo 对象说明）
- onAreaChange(event: (oldValue: Area, newValue: Area) => void): T：只在布局变化导致大小、位置变化时回调；translate、offset、scale、transform 这类绘制变化不触发，所以缓存不含平移（出处：ts-universal-component-area-change-event.md，onAreaChange）
- Area.globalPosition：目标元素相对页面左上角的位置：和 FingerInfo.globalX/Y 的原点（应用窗口左上角）不同（出处：ts-universal-component-area-change-event.md，onAreaChange 参数说明；鸿蒙 SDK 的 ets/component/units.d.ts，Area.globalPosition）
- getLocationInWindow(int[] outLocation)：调用当下 View 在所在窗口坐标系里的位置：源端起点是触发瞬间读的，不是事先缓存的（出处：android.view.View#getLocationInWindow）
- 本次点击的全局坐标优先、控件中心兜底后，起点落在点击处：改用 onAreaChange 缓存时，平移后和 LazyForEach 复用后起点错位、跑到顶部（出处：卡里修好并验证过）
- fingerList: FingerInfo[]（BaseGestureEvent）：同族接口：手势基础事件上的全部手指信息（出处：鸿蒙 SDK 的 ets/component/gesture.d.ts，BaseGestureEvent.fingerList）
