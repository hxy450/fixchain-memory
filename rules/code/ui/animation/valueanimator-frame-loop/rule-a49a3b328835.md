# 用 postFrameCallback 自写帧循环并以待决标志去重时，回调入口第一行先清标志

审的是：代码
触发（任一种）：
- 读到：源端用 ValueAnimator（0→1、固定时长）加 onAnimationUpdate 逐帧写进度并 invalidate()，或规格写「回调先清标志再绘制」的重绘契约；写错的样子：调度函数里 if (pending) return; pending = true; 再 postFrameCallback(...)，而 FrameCallback 子类的 onFrame 或它转发到的宿主方法里没有 pending = false，续帧被拦下
- 读到：同工程里已有一段 FrameCallback 子类转发给宿主方法的帧循环，被当作模板照抄；写错的样子：照抄出来的 onFrame 转发方法同样没有 pending = false，注释写「同某某形态」
适用范围：用一次性帧回调（UIContext.postFrameCallback 等）自写逐帧动画、用待决标志合并续帧请求时
做法：
- onFrame 转发到的回调方法第一行写 this.<待决标志> = false，再做销毁判断、按帧时间算进度、决定是否再调度下一帧
- 把回调体从箭头闭包抽成方法或 FrameCallback 子类转发时，逐行核对清标志、销毁判断和终止条件都还在
- 照兄弟实现写之前，先找同工程按重绘契约实现的同模式入口，逐项对照标志在哪里置位、在哪里清除
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- postFrameCallback(frameCallback: FrameCallback): void：只在下一帧跑一次，续帧要再调一次（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.postFrameCallback）
- export abstract class FrameCallback { onFrame(frameTimeInNano: number): void; onIdle(timeLeftInNano: number): void }：要写子类覆盖 onFrame，不能直接传箭头函数（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，FrameCallback）
- postDelayedFrameCallback(frameCallback: FrameCallback, delayTime: number): void：同族接口：延迟 delayTime 毫秒后的下一帧跑一次，同样要自己清标志（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.postDelayedFrameCallback）
- 回调入口补一行「标志 = false」后，走一步的动画和半屏滚动都能走完：返修的做法（出处：卡里修好并验证过）
