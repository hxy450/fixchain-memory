# Compose 两层共享转场，每端只在外层挂一个 geometryTransition，不嵌套

审的是：代码
触发（任一种）：
- 读到：SharedTransitionLayout 内用 Modifier.sharedBounds(…"<id>-bounds"…) 包住带 Modifier.sharedElement(…id…) 的内容，两层 key 不同，两端（列表卡与详情浮层）各有这两层；写错的样子：同一配对子树里外层容器挂了 .geometryTransition(`${id}-bounds`)，内层组件根节点又挂 .geometryTransition(id)，嵌套两对
适用范围：把 Compose 两层共享转场落成 ArkUI 同页条件浮层加 geometryTransition 时
做法：
- 每端只挂一个 geometryTransition，挂在外层容器上（用外层那一层的键），内层内容不再挂，随容器一起过渡
- 规格写的是「geometryTransition(id) 双端绑定」时，按每端一对理解，不把源端每个共享层逐层各译成一对
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- geometryTransition(id: string, options?: GeometryTransitionOptions): T：组件内隐式共享元素转场，options 只有 follow（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.geometryTransition）
- GeometryTransitionOptions.follow?: boolean，默认 false：仍在树上的组件是否跟随目标（出处：鸿蒙 SDK 的 ets/component/common.d.ts，GeometryTransitionOptions.follow）
- 同一个 id 只能有两个组件绑定，且是 in/out 不同角色；必须配合 animateTo 才有动画：每个键在两端各一个组件（出处：ts-transition-animation-geometrytransition.md，geometryTransition）
- 嵌套两对时浮层卡和收起后的列表卡在控件树里都没有子节点；删掉内层那对、只留外层后打开关闭均正常：嵌套配对的后果和修法（出处：卡里修好并验证过）
