# rememberAnimatedVectorPainter 迁成两组 pathData 间插值，不用静态图或符号切换

审的是：代码
触发（任一种）：
- 读到：源 Compose 用 AnimatedImageVector.animatedVectorResource(R.drawable.…) 加 rememberAnimatedVectorPainter(icon, atEnd)；写错的样子：目标端写成 SymbolGlyph 在 sys.symbol.play_fill / pause_fill 间按状态切换，或 Image($r('app.media.…')) 只显示静态首帧
适用范围：界面实现阶段把源端 animated-vector 两态形变图标写成 ArkUI 组件时
做法：
- atEnd=false 画动画首帧（valueFrom 的路径）、true 画末帧（valueTo 的路径）；状态变化时按源 duration 和插值器在两组 pathData 的数值间逐帧插值，反向时从当前帧回放
- 规格写「图标态切换」而源码是形变时以源码为准实现，并回报规格缺口
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- constructor(d: string)：Path2D 接受符合 SVG path 规范的字符串，插值后的 pathData 可直接构造路径绘制（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，Path2D.constructor）
- cubicBezierCurve(x1: number, y1: number, x2: number, y2: number): ICurve；ICurve.interpolate(fraction: number): number：把时间进度映射成插值进度；fast_out_slow_in 写 cubicBezierCurve(0.4, 0, 0.2, 1)（出处：鸿蒙 SDK 的 ets/api/@ohos.curves.d.ts，curves.cubicBezierCurve、ICurve.interpolate）
- initCurve(curve?: Curve): ICurve；Curve.FastOutSlowIn 是 cubic-bezier (0.4, 0.0, 0.2, 1.0)：同族接口：用预置曲线建 ICurve（出处：鸿蒙 SDK 的 ets/api/@ohos.curves.d.ts，curves.initCurve、Curve.FastOutSlowIn）
- @android:interpolator/fast_out_slow_in：controlX1=0.4、controlY1=0、controlX2=0.2、controlY2=1：源端插值器的确切控制点（出处：Android SDK 平台资源 data/res/interpolator/fast_out_slow_in.xml（按应用的 compileSdk 取对应平台））
- 新建形变图标组件：取起止 pathData，按 500ms、fast_out_slow_in 逐数值插值，atEnd=false 画首帧、true 画末帧：改法的依据（500ms 是出事应用的取值，按源资源取）（出处：卡里修好并验证过）
针对本应用要查的：
- 起止 pathData、duration、interpolator：源工程 res/drawable 下的 <animated-vector> 及其 objectAnimator（res/animator 或内联 aapt:attr）；propertyName="pathData" 的 valueFrom / valueTo 是两组路径，两者命令序列和数值个数一致，逐个数值线性混合后再按插值曲线取进度
