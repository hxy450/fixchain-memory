# AnimatedVisibility 转成折叠容器时只放 lambda 内的节点，lambda 外的兄弟留在容器外常驻

审的是：代码
触发（任一种）：
- 读到：Compose 同一 Row 里既有常驻节点，又有 AnimatedVisibility(visible) { … } 或条件块只包住其中一部分兄弟（连同它前面的 Spacer）；写错的样子：目标的折叠容器（.width(cond ? N : 0) 加 .clip(true)，或 if 分支）里放进了源端在 AnimatedVisibility lambda 外的常驻节点，容器外没有它
- 写错的样子：带 .clip(true) 的折叠容器展开尺寸写成常量（注释如「间距 + 按钮」），常量与容器里实际子节点的尺寸加间距合计对不上
- 写错的样子：注释或转换报告写「仅某节点受开关控制」，而带 .clip(true) 的受控容器里不止它一个
适用范围：把 Compose 的 AnimatedVisibility 或条件显隐块转成 ArkUI 常驻折叠容器（显式宽高 0↔内容、clip(true)）或 if 分支时
做法：
- 按源码分出 lambda 内和 lambda 外的节点：只把 lambda 内的节点（连同其中的 Spacer）放进折叠容器；lambda 外的兄弟写在容器外常驻，源端间距在哪一侧就跟着哪一侧走（如常驻按钮自带 .margin({ left: 10 })）
- 展开尺寸常量按容器里实际的子节点逐项加总核对；对不上就是节点归属写错了，clip(true) 会静默裁掉多放进去的节点
- 按开关的每个状态各数一遍可见控件，与源端对照；注释或报告写「仅某节点受控」时，核对受控容器里确实只有它
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- clip(value: boolean): T，默认 false；为 true 时裁掉超出本组件边界的子组件区域：折叠容器宽为 0 或小于内容时，多放进去的节点被裁掉、不报错（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.clip）
- 常驻节点移出容器并加 .margin({ left: 10 })，容器只放受控节点，宽度不变，用 .justifyContent(FlexAlign.End) 代替条件 margin：修好的写法（出处：卡里修好并验证过）
- justifyContent(value: FlexAlign): RowAttribute：Row 主轴对齐，折叠容器里的节点靠右对齐时用（出处：鸿蒙 SDK 的 ets/component/row.d.ts，RowAttribute.justifyContent）
- RowOptions.space?: string | number：Row({ space }) 的子节点间距；放进容器的节点数变了，展开宽也要跟着变（出处：鸿蒙 SDK 的 ets/component/row.d.ts，RowOptions.space）
