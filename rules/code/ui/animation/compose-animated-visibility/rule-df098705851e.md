# 可见性动画没写 animationSpec 时用 springMotion(2π/√400, 1.0)

审的是：代码
触发（任一种）：
- 读到：AnimatedVisibility 的 expandVertically()、shrinkVertically()、fadeIn()、fadeOut() 都没传 animationSpec（沿用 Compose 默认 spring）；写错的样子：目标转场或 animateTo 写 .animation({ duration: 200 }) 之类的定时长 tween
适用范围：源端可见性动画沿用 Compose 默认 spring、目标要写曲线时
做法：
- 曲线写 curves.springMotion(2 * Math.PI / Math.sqrt(400), 1.0)，用在转场的 .animation({ curve }) 和 animateTo({ curve }) 里
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- expand / shrink 与 fadeIn / fadeOut 的默认是 spring(StiffnessMediumLow 400, dampingRatio 1)，换算成 springMotion(2π/√400, 1.0)：源端默认曲线到目标参数的对应（出处：卡里修好并验证过）
- function springMotion(response?: number, dampingFraction?: number, overlapDuration?: number): ICurve：弹簧曲线；时长由参数决定，不看 animation 的 duration（出处：鸿蒙 SDK 的 ets/api/@ohos.curves.d.ts，curves.springMotion）
- response 是一次完整振荡的时长，单位秒，默认 0.55；dampingFraction 默认 0.825，1 为临界阻尼：springMotion 两个参数的含义、单位和默认值（出处：鸿蒙 SDK 的 ets/api/@ohos.curves.d.ts，curves.springMotion）
- function responsiveSpringMotion(response?: number, dampingFraction?: number, overlapDuration?: number): ICurve：同族接口：跟手弹簧曲线，参数同 springMotion，overlapDuration 默认 0.25（出处：鸿蒙 SDK 的 ets/api/@ohos.curves.d.ts，curves.responsiveSpringMotion）
针对本应用要查的：
- 源端是否传了 animationSpec：源工程里 AnimatedVisibility 调用处的 Kotlin 文件，看 enter / exit 的 expandVertically(…)、fadeIn(…) 有没有 animationSpec 参数；都没传 animationSpec 时才按默认 spring 换算成 springMotion(2π/√400, 1.0)
未核实：Compose 默认 spring 的数值出自卡（返修从库里取得），本机没有 Compose 源码可核
