# 列表项带 animateItem() 时，增删用 animateTo 包裹并给 ListItem 加转场

审的是：代码
触发（任一种）：
- 读到：Compose 列表项上有 Modifier.animateItem()（如 ListItem(modifier = Modifier.animateItem())），或者某一项随持久化状态回推而消失；写错的样子：数据数组直接赋值、没有 animateTo，ListItem 上没有 .transition(...)；由持久化回推的移除写成同步把显示标志置 false
适用范围：Compose 惰性列表的列表项带 animateItem，迁成 ArkUI List / ListItem 时
做法：
- 数据增删放进 this.getUIContext().animateTo({ … }, () => { 改数据 }) 的闭包里，ListItem 加 .transition(...) 转场
- 由持久化回推触发的移除（如更新提示卡）按「先写入持久化，再在 animateTo 闭包里移除」实现，不直接同步置 false
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- animateTo(value: AnimateParam, event: () => void): void：UIContext 上的显式动画，闭包里的状态改动会被做成动画（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.animateTo）
- 全局 animateTo 自 API 18 起废弃，改用 UIContext#animateTo：写成 this.getUIContext().animateTo(...)，不用全局函数（出处：鸿蒙 SDK 的 ets/component/common.d.ts，animateTo（@deprecated since 18））
- transition(value: TransitionOptions | TransitionEffect): T：组件插入、移除时的转场（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.transition）
未核实：卡里观察到的行为出自鸿蒙 SDK 6.1.1(24)，本机声明按 API 23 核实
