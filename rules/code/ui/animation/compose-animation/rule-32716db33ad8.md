# 源 Compose 动画逐帧刷新时，目标用 displaySync 逐帧驱动，不用 500ms setInterval

审的是：代码
触发（任一种）：
- 读到：源端进度由 Compose `Animatable.animateTo(…, tween(…, LinearEasing))` 逐帧驱动；规格映射行写高频 tick，派工却写 500ms ticker；写错的样子：目标用 `setInterval(…, 500)` 驱动进度环和计时文本
适用范围：把 Compose 帧驱动的前台动画改写成 ArkTS 自驱计时时；派工和规格、源码行为冲突的情形
做法：
- 按规格和源码行为实现：const sync = displaySync.create(); sync.on('frame', (info) => { 按 info.timestamp 推进 }); sync.start()；派工与规格冲突又拿不准时回报冲突，不以派工覆盖规格
- 帧时钟随宿主可见性暂停/恢复：UIAbility 的 onBackground 里 sync.stop()，onForeground 里 sync.start()
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function create(): DisplaySync：创建帧回调对象（出处：鸿蒙 SDK 的 ets/api/@ohos.graphics.displaySync.d.ts，displaySync.create）
- on(type: 'frame', callback: Callback<IntervalInfo>): void；start(): void；stop(): void：注册逐帧回调，start 加入管线开始派帧，stop 移出管线停止派帧（出处：鸿蒙 SDK 的 ets/api/@ohos.graphics.displaySync.d.ts，DisplaySync.on、DisplaySync.start、DisplaySync.stop）
- IntervalInfo.timestamp：当前帧到达的时间，单位纳秒：按它算帧时间，换算毫秒要除以 1e6（出处：js-apis-graphics-displaySync.md，IntervalInfo）
- 不调用 setExpectedFrameRateRange 时最小/最大/期望帧率默认 60：要跟随高刷屏时显式设帧率范围（出处：鸿蒙 SDK 的 ets/api/@ohos.graphics.displaySync.d.ts，DisplaySync.setExpectedFrameRateRange）
- displaySync 逐 vsync 的帧时钟，可 pause/resume，随宿主可见性暂停/恢复：修复后的做法（出处：卡里修好并验证过）
- onBackground(): void；onForeground(): void：UIAbility 退后台、回前台的回调，在这里停、启帧时钟（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.UIAbility.d.ts，UIAbility.onBackground、UIAbility.onForeground）
