# 源端 expandVertically 或规格写高度过渡时，不用 TransitionEffect.OPACITY 代替

审的是：代码
触发（任一种）：
- 读到：源 AnimatedVisibility(enter = expandVertically(), exit = shrinkVertically())；或规格写「if/else 条件渲染 + animateTo 高度过渡，等价 expandVertically」；写错的样子：目标条件渲染的块只有 .transition(TransitionEffect.OPACITY.animation(...)) 或 OPACITY.combine(scale({ y: 0 }))，没有高度过渡，切换状态时没有 animateTo，也没登记不确定项
适用范围：源端竖向展开收起的显隐动画迁成 ArkUI 条件渲染时
做法：
- 切换可见性的状态改动包进 this.getUIContext().animateTo({ curve: … }, () => { … })，展开、收起都带高度变化、下方内容随之推移；不以透明度转场代替
- 高度变化按卡里验证过的一种写：if/else 条件渲染的外层容器高度由状态驱动，在 animateTo 里于 0 与内容高度之间变化；或可见性块外套独立的 .clip(true) 容器，块本身加 TransitionEffect.translate({ y: '-100%' }) 配 OPACITY 转场
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- TransitionEffect.OPACITY：出现时透明度 0→1、消失时 1→0，等同 TransitionEffect.opacity(0)：只有透明度，不含高度变化（出处：鸿蒙 SDK 的 ets/component/common.d.ts，TransitionEffect.OPACITY）
- animateTo(value: AnimateParam, event: () => void): void：UIContext 上的显式动画，闭包里的状态变化带来的高度、布局变化会过渡（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.animateTo）
- static translate(options: TranslateOptions): TransitionEffect<"translate">：平移转场（出处：鸿蒙 SDK 的 ets/component/common.d.ts，TransitionEffect.translate）
- clip(value: boolean): T：外层容器裁切，平移进出的块不露出容器外（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.clip）
- 编辑页补上高度显隐和添加卡淡入后与源端一致：外层高度由状态驱动的修法（出处：卡里修好并验证过）
- 共享的可见性组件：clip(true) 容器 + translate(-100% ↔ 0) + OPACITY，曲线 springMotion(2π/√400, 1.0)，切换状态包进 animateTo：clip 容器加平移转场的修法（出处：卡里修好并验证过）
未核实：卡里观察到的行为出自鸿蒙 SDK API 24（6.1.1），本机核实用 API 23
