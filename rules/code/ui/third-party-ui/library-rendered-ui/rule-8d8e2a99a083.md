# 源端 UI 由三方库 AAR 渲染时，目标按解包反编译得到的库真值实现，不凭猜测近似

审的是：代码
触发（任一种）：
- 读到：Activity extends 三方库类（如 AppIntro2），或布局里只有库的自定义 View 节点（如 com.larswerkman.holocolorpicker.ColorPicker 加 SVBar、OpacityBar），调用代码里有 addSVBar / addOpacityBar 之类库方法；写错的样子：代码注释写「库源不可见 → 自绘近似」「源码不在本仓库 → 按 spec 自研等价」，圆点直径、间距、透明度、色环厚度等常量凭猜测或反推自 README
适用范围：实现阶段落地由三方开源库提供整块 UI 的页面或控件时
做法：
- 按依赖坐标取库 AAR，解包 res/layout、res/values、res/drawable 并反编译 classes.jar，按库里的尺寸、颜色、布局权重、动画时长和插值、手势逻辑实现
- 取不到制品时回报缺库制品的阻塞，不写近似实现
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 按 AAR 反编译重建后（引导页底栏权重、图标、圆点 layer-list、200ms quintic 翻页；取色器三个模型；选择器的日期、时间、重复三部分）与源端一致：修复后的做法（出处：卡里修好并验证过）
针对本应用要查的：
- 库内几何和交互常量：库 AAR 解包后的 res/values（dimens、colors、styles）、res/layout、res/drawable，以及反编译的视图类；按控件逐项读出尺寸、颜色、动画参数和手势判定，写进目标代码并在注释里写明取自哪个库文件
