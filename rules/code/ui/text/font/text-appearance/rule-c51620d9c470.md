# 源 TextView 贴顶且没关 includeFontPadding 时，目标 Text 按字号补顶部 padding

审的是：代码
触发（任一种）：
- 读到：TextView 贴顶（android:layout_alignParentTop 加 android:layout_marginTop，或在定高盒内贴顶），没写 android:includeFontPadding（默认 true）；写错的样子：对应的 Text 只照搬 margin 贴顶，没补顶部 padding，也没在转换报告里登记「字形纵向差待设备核对」
适用范围：源 TextView 顶部对齐、includeFontPadding 取默认 true，迁成 ArkUI Text 时
做法：
- 按字号给 Text 补顶部 padding：.padding({ top: 字号 × 0.17 })（卡里实测约 0.17em：36sp 标题约 6dp，14sp 标签约 3dp）
- 禁止构建、不能上机实测的批次，在转换报告里登记「字形纵向差待设备核对」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- includeFontPadding 的 format 是 boolean，平常为 true：源端没写就是 true（出处：Android SDK 平台资源 data/res/values/attrs.xml，TextView 的 includeFontPadding（按应用的 compileSdk 取对应平台））
- mIncludePad = true；读属性时 getBoolean(attr, true)，为 false 才 setIncludeFontPadding(false)：TextView 默认带字体内边距（出处：android.widget.TextView#mIncludePad；android.widget.TextView 构造里读 TextView_includeFontPadding）
- 顶部补偿约 0.17em（36sp 标题低约 6.1dp，14sp 标签低约 3dp）：源端字形比 ArkUI Text 低的量（出处：卡里修好并验证过）
未核实：0.17em 是一次设备实测，换字体或字号后是否相同未核实
