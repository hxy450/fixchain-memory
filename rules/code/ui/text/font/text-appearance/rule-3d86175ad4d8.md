# 源布局指定字体文件时，注册 rawfile 字体并在 Text 上写 fontFamily

审的是：代码
触发（任一种）：
- 读到：源布局 TextView 上有 `pixlui:typeface`（指向 ttf 文件）或 `android:fontFamily`；写错的样子：对应 Text 没有 `.fontFamily(...)`，字体名只写在注释里；粗体字体用 `.fontWeight(FontWeight.Bold)` 伪粗体代替
适用范围：源端用自定义字体文件（pixlui 或 fontFamily）的文本迁到 ArkUI Text、Span 时
做法：
- 确认 ttf 已在 resources/rawfile/fonts 下；在页面 aboutToAppear 里注册：this.getUIContext().getFont().registerFont({ familyName: '<字体名>', familySrc: $rawfile('fonts/<文件名>.ttf') })
- 在每个对应 Text 上写 .fontFamily('<字体名>')；粗体字体文件单独注册成一个族来用，不用 fontWeight(Bold) 代替字体族
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- registerFont(options: font.FontOptions): void：UIContext 的 Font 对象注册自定义字体（经 getFont(): Font 取得）（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，Font.registerFont、UIContext.getFont）
- familyName: string | Resource；familySrc: string | Resource：FontOptions 的两项：注册的字体名、字体文件路径（出处：鸿蒙 SDK 的 ets/api/@ohos.font.d.ts，FontOptions）
- font.registerFont 标了 @deprecated since 18，改用 UIContext.Font#registerFont：不要再用 @ohos.font 的全局 registerFont（出处：鸿蒙 SDK 的 ets/api/@ohos.font.d.ts，font.registerFont）
- fontFamily(value: string | Resource): TextAttribute：Text 的字体族，传注册时的 familyName（出处：鸿蒙 SDK 的 ets/component/text.d.ts，TextAttribute.fontFamily）
- fontFamily(value: string | Resource): SpanAttribute：同族接口：Span 的字体族（出处：鸿蒙 SDK 的 ets/component/span.d.ts，SpanAttribute.fontFamily）
- fontFamily(value: ResourceStr): TextInputAttribute：同族接口：TextInput 的字体族（出处：鸿蒙 SDK 的 ets/component/text_input.d.ts，TextInputAttribute.fontFamily）
- 注册 rawfile/fonts 下的字体并在 Text 上写 fontFamily 后，字形与源端一致：验证过的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 每个文本用哪个字体文件：源布局 XML 里各 TextView 的 pixlui:typeface / android:fontFamily，以及它们引用的 style；源工程的 assets 或 res/font 下的字体文件；按控件逐个记下字体文件名，确认目标 rawfile/fonts 下有同名文件
未核实：卡里的效果在目标 API 24 上验证，本机核对用的是 API 23 的声明
