# 源端字号只由 dp 和文字倍率得出时，目标 fontSize、lineHeight 不乘几何画布比例

审的是：代码
触发（任一种）：
- 读到：源端文本的 textSize 由 dp 值乘文字倍率得到、行距 spacingAdd 由 dp 值得到；padding、背景、位置另按根尺寸与设计宽度之比换算；写错的样子：目标写了一个按「渲染宽度 / 设计宽度」缩放的通用换算函数，并对 .fontSize(...)、minFontSize、maxFontSize、lineHeight 一并调用
适用范围：迁移几何按设计画布比例整体缩放、文字却按 dp 设置的动态布局文本（预览、渲染组件）时
做法：
- 字号、行距照源端公式落为 vp：.fontSize(`${dp 值 × 文字倍率}vp`)，minFontSize、maxFontSize、lineHeight 同样用源端 dp 值加 vp 后缀，不乘画布比例
- 只有宽高、位置、padding、背景尺寸这类几何量乘「渲染宽度 / 设计宽度」
- 加一条回归：画布比例不为 1 时，字号仍等于源端 dp 值，几何仍按比例缩放
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- fontSize(value: number | string | Resource): TextAttribute：Text 的字号；传 number 时按 fp 解释，所以源端 dp 值写成带 vp 后缀的字符串（出处：鸿蒙 SDK 的 ets/component/text.d.ts，TextAttribute.fontSize）
- minFontSize(value: number | string | Resource): TextAttribute、maxFontSize(value: number | string | Resource): TextAttribute：自适应字号的上下限，单位 fp，字符串可带单位（如 "10fp"）（出处：鸿蒙 SDK 的 ets/component/text.d.ts，TextAttribute.minFontSize、TextAttribute.maxFontSize）
- lineHeight(value: number | string | Resource): TextAttribute：Text 的行高；传 number 时单位 fp（出处：鸿蒙 SDK 的 ets/component/text.d.ts，TextAttribute.lineHeight）
- 字号、行距改为直接用源端的 vp 值，padding、背景等几何仍按画布比例：修复后的写法，画布比例 0.334 时文字不再比安卓小（出处：卡里修好并验证过）
- fontSize(value: number | string | Resource): SpanAttribute：同族接口：Span 的字号（出处：鸿蒙 SDK 的 ets/component/span.d.ts，SpanAttribute.fontSize）
- fontSize(value: Length): TextInputAttribute：同族接口：TextInput 的字号，number 时单位 fp（出处：鸿蒙 SDK 的 ets/component/text_input.d.ts，TextInputAttribute.fontSize）
- fontSize(value: Length): TextAreaAttribute：同族接口：TextArea 的字号（出处：鸿蒙 SDK 的 ets/component/text_area.d.ts，TextAreaAttribute.fontSize）
未核实：卡里的行为出自目标 SDK 26.0.0，声明按本机 API 23 核实
