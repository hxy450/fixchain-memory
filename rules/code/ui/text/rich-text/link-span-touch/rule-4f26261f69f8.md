# 源端按触点命中链接 span 派发点击和长按时，目标用 LayoutManager 按触点找链接，不取首个链接

审的是：代码
触发（任一种）：
- 读到：源端用 BetterLinkMovementMethod 按触点查找 ClickableSpan，在按下的那个 span 上派发点击或长按；写错的样子：Text 上挂组件级 LongPressGesture，回调里取的是第一个链接的 URL
适用范围：含多个链接的富文本迁成 ArkUI Text（StyledString / Span）时的链接点按与长按
做法：
- Text 绑定 TextController；手势回调里取触点相对组件的坐标，调 controller.getLayoutManager().getGlyphPositionAtCoordinate(x, y) 得到字符位置 position
- 找起止区间包含 position 的链接 run，命中链接才派发这个链接的点按或长按
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getLayoutManager(): LayoutManager：TextController 取布局管理器（出处：鸿蒙 SDK 的 ets/component/text.d.ts，TextController.getLayoutManager）
- getGlyphPositionAtCoordinate(x: number, y: number): PositionWithAffinity：按相对组件的坐标取最近字形的位置，返回值的 position 是字符位置（出处：鸿蒙 SDK 的 ets/component/text_common.d.ts，LayoutManager.getGlyphPositionAtCoordinate）
- getGlyphPositionAtCoordinate 的 x、y 单位是 px：手势给的触点坐标是 vp，传入前要换成 px（出处：ts-text-common.md，getGlyphPositionAtCoordinate）
- FingerInfo.localX / localY 相对当前组件，单位 vp：手势回调里的触点坐标（出处：ts-gesture-common.md，FingerInfo对象说明）
- TextController LayoutManager 按触点命中后再派发点按 / 长按：修复后的链接手势（出处：卡里修好并验证过）
- getLayoutManager(): LayoutManager（TextBaseController）：同族接口：文本选择控制器 TextBaseController 的布局管理器（出处：鸿蒙 SDK 的 ets/component/text_common.d.ts，TextBaseController.getLayoutManager）
未核实：卡里没写触点坐标是否做了 vp 到 px 的换算；卡里的行为出自目标 SDK 6.1.1(24)，声明按本机 API 23 核实
