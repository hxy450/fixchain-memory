# 可编辑的分段着色编辑框用 RichEditor 常驻编辑，不拆成只读 Text 和单色 TextArea 两态

审的是：代码
触发（任一种）：
- 读到：源端 EditText 常驻可编辑，文本以 Spannable 分段着色，宽度 WRAP_CONTENT；写错的样子：目标写成「着色只读 Text ↔ 点击切换单色 TextArea」两态，编辑态没有颜色；注释却写等价于常驻可编辑的 EditText
适用范围：源控件同时要求可编辑和分段着色、迁成 ArkUI 时
做法：
- 用 RichEditor({ controller: new RichEditorController() }) 常驻编辑，按段 addTextSpan(段文本, { style: { fontColor: 段颜色 } }) 写入着色；宽度按最长行测量，对应源端 wrap_content
- 新输入的字取插入点后一字符的颜色
- 确需降级时，在规格和占位登记里列出丢失的行为（常驻着色、插入色、wrap_content 宽度、整体重建与焦点恢复），代码注释不写「等价」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- addTextSpan(content: ResourceStr, options?: RichEditorTextSpanOptions): number：按段加文本，返回 span 序号（出处：鸿蒙 SDK 的 ets/component/rich_editor.d.ts，RichEditorController.addTextSpan）
- RichEditorTextSpanOptions.offset?: number；RichEditorTextSpanOptions.style?: RichEditorTextStyle；RichEditorTextStyle.fontColor?: ResourceColor：插入位置和这段的颜色（出处：鸿蒙 SDK 的 ets/component/rich_editor.d.ts，RichEditorTextSpanOptions、RichEditorTextStyle）
- 改成 RichEditor 常驻可编辑着色 Span、新字取插入点后一字符颜色、按最长行测宽并居中后行为与源端一致：卡里的修法（出处：卡里修好并验证过）
未核实：卡里环境是 API 24，按本机 API 23 的声明核实
