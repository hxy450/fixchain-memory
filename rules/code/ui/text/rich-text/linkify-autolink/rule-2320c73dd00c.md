# 规格写明 WEB_URLS 语义时，移植 AUTOLINK_WEB_URL 和 @ 前不链接过滤，不缩成协议前缀

审的是：代码
触发（任一种）：
- 读到：源端 LinkifyPlugin.create(Linkify.WEB_URLS)；规格 AC 写「裸 URL（WEB_URLS 语义，不含 email）」；写错的样子：自动链接（autoLink）的正则只认 `https?://` 或 `www.` 前缀，注释写「语义近似、不识别无协议域名」
适用范围：目标端自研自动链接、源端用 Linkify 的 WEB_URLS 掩码时
做法：
- 照 Patterns.AUTOLINK_WEB_URL 的源码移植正则：WEB_URL_WITH_PROTOCOL | WEB_URL_WITHOUT_PROTOCOL，含无协议、按已知 TLD 匹配的域名
- 照 Linkify.sUrlMatchFilter 丢掉紧跟在 @ 后面的命中；和用户/社区简写等规则重叠时按源端监听注册顺序处理，不靠缩窄匹配范围避冲突
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- WEB_URLS 掩码下 gatherLinks(links, text, Patterns.AUTOLINK_WEB_URL, { "http://", "https://", "rtsp://", "ftp://" }, sUrlMatchFilter, null)：源端 WEB_URLS 用的正则、补协议前缀和过滤器（出处：android.text.util.Linkify#addLinks）
- AUTOLINK_WEB_URL = (WEB_URL_WITH_PROTOCOL | WEB_URL_WITHOUT_PROTOCOL)，标了 @hide：不带协议的分支要求 TLD 是已知 TLD（出处：android.util.Patterns#AUTOLINK_WEB_URL）
- sUrlMatchFilter：命中起点前一个字符是 @ 时不链接：避免把邮箱的域名部分链接成网址（出处：android.text.util.Linkify#sUrlMatchFilter）
- 返修改用 Patterns.AUTOLINK_WEB_URL 的移植正则：修复后的自动链接（出处：卡里修好并验证过）
针对本应用要查的：
- 应用 compileSdk 对应版本的 AUTOLINK_WEB_URL 完整正则：Android SDK 框架源码 android.util.Patterns（按应用的 compileSdk 取对应版本），从 AUTOLINK_WEB_URL 往上顺着 STRICT_DOMAIN_NAME、STRICT_TLD、IANA_TOP_LEVEL_DOMAINS 等常量；把各常量按源码的拼接顺序拼成一条正则，再改写成目标端 RegExp
未核实：卡里 compileSdk 37，框架源码按本机 android-36.1 核实；目标端 RegExp 对源正则里反向断言的支持未核
