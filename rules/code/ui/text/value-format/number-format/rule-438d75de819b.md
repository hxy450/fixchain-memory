# 源端 String.format 按 %.Nf 格式化 float 时，目标按 float、HALF_UP、区域小数点写

审的是：代码
触发（任一种）：
- 读到：`String.format("%.2f", percentage)`，参数是 float（如 (float)a / b * 100f）；写错的样子：目标用 number 直接算再 .toFixed(2) 输出，注释里写着 String.format("%.2f")
适用范围：Java 用 String.format 按 %.Nf 格式化 float，迁成 ArkTS 时
做法：
- 运算按 float 逐步取整：每一步结果包一层 Math.fround(...)，如 Math.fround(Math.fround(a / b) * 100)
- 舍入按 HALF_UP（.5 远离 0），在 float 的十进制表示（Float.toString 的结果）上舍到 N 位，不用 toFixed
- 小数点和数字字形换成默认区域的写法（fr、it、pt、ru 等下小数点是逗号）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- %f 对 float 按 Float.toString 的十进制串、用 HALF_UP 舍到精度位：源端舍入规则（出处：java.util.Formatter（'f' 转换））
- 数字字形按当前区域的 zero digit 替换，小数点换成区域的 decimal separator：源端输出随区域变化（出处：java.util.Formatter（本地化算法））
- String.format 用的区域是 Locale.getDefault(Locale.Category.FORMAT)：源端取默认区域（出处：java.lang.String#format）
- fround(x: number): number：取最接近的单精度值，用来模拟 float 运算（出处：鸿蒙 SDK 的 ets/build-tools/ets-loader 内 typescript/lib/lib.es2015.core.d.ts，Math.fround）
- static getSystemLocaleInstance(): Intl.Locale（@since 20；旧的 getSystemLocale(): string 自 20 起废弃）：目标端取系统区域（出处：鸿蒙 SDK 的 ets/api/@ohos.i18n.d.ts，System.getSystemLocaleInstance）
- double 运算加 toFixed(2) 丢了 float 精度、HALF_UP 舍入和按区域的小数点：直接用 toFixed 的后果（出处：卡里修好并验证过）
