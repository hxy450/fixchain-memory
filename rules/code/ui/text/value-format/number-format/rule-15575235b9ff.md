# intl 货币格式与迁移基线显示串不一致时（如 US$ 对 $），按基线可观察字符串定格式

审的是：代码
触发（任一种）：
- 读到：迁移基线（截图、UT 期望值）里价格显示为 `$4.99` 这种只带 $ 的形式；写错的样子：intl.NumberFormat(…, { style: 'currency', currency: 'USD', currencyDisplay: 'symbol' }) 在目标系统地区输出 US$ 前缀，与基线不一致
适用范围：价格格式化迁到 ArkTS 后，目标系统地区对同一币种给出与基线不同的符号变体时
做法：
- 无法构建运行时，至少用样例值（如 499 分）把格式化结果和基线的实际显示串逐字对照
- 不一致时按基线串写格式；卡里最终改为 `$${(cents / 100).toFixed(2)}` 并删掉 intl 导入，复核通过
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- NumberOptions.currencyDisplay?: string，取值 "symbol"、"narrowSymbol"、"code"、"name"，默认 "symbol"：货币显示方式；默认 symbol 在部分地区把 USD 显示为 US$（出处：鸿蒙 SDK 的 ets/api/@ohos.intl.d.ts，NumberOptions.currencyDisplay）
- currency: 'USD' + currencyDisplay: 'symbol' 在当时的系统地区显示 US$；改为 `$${(cents / 100).toFixed(2)}` 后与基线一致：卡里两轮验证看到的结果（出处：卡里修好并验证过）
针对本应用要查的：
- 基线的价格显示串：迁移基线截图、源端 UT 的期望字符串，或规格验收条目里的样例；取一个样例金额的完整显示串（符号、位置、小数位），目标输出逐字对照
未核实：US$ 出现在哪些系统地区没核实
