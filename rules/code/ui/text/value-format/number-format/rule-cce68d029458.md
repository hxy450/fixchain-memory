# 源端格式化没传 Locale 时，intl.NumberFormat 显式传应用偏好语言，不用无参构造

审的是：代码
触发（任一种）：
- 读到：源端 new DecimalFormat(",##0.00")、NumberFormat 或 String.format 没有显式传 Locale；写错的样子：目标写 new intl.NumberFormat().format(…)（注释「无参构造 = 系统Locale」）、toLocaleString()，或用 getSystemLanguage / getSystemLocale 取区域
适用范围：目标端复刻源端默认 Locale 下的数字分组符和小数点时
做法：
- 写成 new intl.NumberFormat(i18n.System.getAppPreferredLanguage(), options).format(n)（import { i18n, intl } from '@kit.LocalizationKit'）
- 规格写「系统Locale」而源码和派工写默认 Locale 时，按源语义实现，并在报告里标出这条差异
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- constructor(locale: string | Array<string>, options?: NumberOptions)：intl.NumberFormat 按指定区域构造（出处：鸿蒙 SDK 的 ets/api/@ohos.intl.d.ts，NumberFormat.constructor）
- constructor()：使用当前系统区域创建：无参构造取系统区域，不跟应用语言（出处：js-apis-intl.md，NumberFormat 的 constructor8+）
- static getAppPreferredLanguage(): string：i18n.System 上取应用偏好语言（出处：鸿蒙 SDK 的 ets/api/@ohos.i18n.d.ts，System.getAppPreferredLanguage）
- static getSystemLanguage(): string；static getSystemLocale(): string（since 20 弃用，改用 getSystemLocaleInstance）：系统语言和系统区域，不随应用语言（出处：鸿蒙 SDK 的 ets/api/@ohos.i18n.d.ts，System.getSystemLanguage、System.getSystemLocale）
- new intl.NumberFormat(i18n.System.getAppPreferredLanguage())：修复后的构造，应用语言德语时显示逗号小数点（出处：卡里修好并验证过）
