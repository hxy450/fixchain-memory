# 品类精度和基类不同时，子类 ViewModel 覆写全部高亮文本 getter，用同精度格式化

审的是：代码
触发（任一种）：
- 写错的样子：子类 ViewModel 没覆写高亮文本 getter，页面的高亮分支直接用基类 getter（内部是 `toFixed(2)` 的通用格式化），而同一字段的静态值已用 `toFixed(3)` 的格式化
适用范围：多个品类详情页共用基类 ViewModel，某一品类的源端联动和静态展示用了和基类不同的小数位时
做法：
- 复用基类高亮 getter 前打开它的格式化函数核对小数位；与当前品类不同就在该品类子类里覆写全部相关高亮文本 getter（现价、涨跌额、最高、最低），改用同精度的格式化，竖屏和横屏行情头共用这一来源
- 改同一显示字段的任一分支（静态值、无数据兜底、高亮值）时，搜这个字段在子类和基类里的全部格式化调用，比对小数位一致
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 在品类子类里把四个高亮文本 getter 覆写为 3 位格式化后，竖屏收起行情头与横屏行情头的联动值都与源端同精度：验证过的做法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端每个跟随字段的小数位：源端这个品类的行情视图里高亮回调和非高亮刷新两处的格式化调用，看传入的小数位参数；逐字段记下小数位，对照目标子类和基类 getter 用的格式化函数
来源：1 张卡，1 个应用
