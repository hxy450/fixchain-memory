# 给展示型 UiModel 赋值时，code 或 ID 字段先迁源端的转换函数或目录查表，不用 join 或原值透传

审的是：代码
触发（任一种）：
- 读到：源端同一页面在显示前对数据字段先调转换函数（提醒 code → 文案、重复规则 → 文案）或目录查表（getIcon(id)、getColor(id) → 图片、颜色）；写错的样子：宿主或适配层给 UiModel 的文本、图标字段直接赋数据层原值：code 数组 .join('、')、规则类型字段原样当文案、图标和颜色字段直接传 ID
适用范围：界面接线和数据适配阶段，把仓库层领域数据映射成弹窗、详情页 UiModel 的展示字段时
做法：
- 逐字段确认数据层的取值是 code、ID 还是可直接展示的值；凡是 code / ID，先在源端同一页面找到对应的转换调用
- 把转换迁成共用的格式化器或目录查表（code → 文案，ID → 图片 URL / 颜色），UiModel 用它的结果赋值，不用 join 或原值透传占位
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 新建共用格式化器（提醒 code → 文案、重复规则 → 具体文案、重复结束 → 文案），宿主改用它；图标、颜色 ID 按本地目录解析成图片 URL 和 RGB：修好的做法（出处：卡里修好并验证过）
针对本应用要查的：
- 每个 code / ID 字段在源端怎么转成展示值：源工程里显示这条数据的页面（Activity、Fragment、Dialog 的 .kt / .java）：按字段名搜到它绑到控件的那一行，看外面包了哪个函数或查表；读出转换函数的映射（code 对应哪个字符串资源、ID 对应目录里哪一项），原样迁成目标端的格式化器或查表
