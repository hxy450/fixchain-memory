# TextView 中间或开头省略时，不退成尾部 Ellipsis，实现测量式中间截断

审的是：代码
触发（任一种）：
- 读到：TextView 带 android:ellipsize="middle"（或 "start"）且 android:lines="1" / android:maxLines="1"，显示文件名这类尾部有意义的文本，可能还有关键字 Span 高亮；写错的样子：Text 写成 .textOverflow({ overflow: TextOverflow.Ellipsis }) 尾部省略，旁边留 TODO 待确认；或写了不存在的 TextOverflow.MIDDLE
适用范围：界面实现阶段，源端要求中间或开头省略的单行文本迁成 ArkUI Text 时
做法：
- 不直接退到尾部 Ellipsis，在本阶段实现测量式中间截断：onAreaChange 取可用宽度，this.getUIContext().getMeasureUtils().measureText({ textContent, fontSize… }) 测宽，二分保留头尾（如保留扩展名），保护代理对，按（宽度, 文本）缓存
- 有关键字 Span 高亮时先截断，再在截断后的文本上做高亮
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- TextOverflow 的成员是 None、Clip、Ellipsis、MARQUEE，没有 MIDDLE：textOverflow 本身只能尾部省略（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，TextOverflow）
- onAreaChange(event: (oldValue: Area, newValue: Area) => void): T；Area.width 单位 vp：取 Text 的可用宽度（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onAreaChange；ts-types.md，Area）
- getMeasureUtils(): MeasureUtils；measureText(options: MeasureOptions): number，返回单行文本宽度，单位 px：和 vp 的可用宽度比较前要换成同一单位（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.getMeasureUtils、MeasureUtils.measureText）
- 新建中间截断组件：onAreaChange 取宽、measureText 测量、二分保留首尾、保护代理对、加缓存，先截断再高亮：修好后的写法（出处：卡里修好并验证过）
- measureTextSize(options: MeasureOptions): SizeOptions：同族接口：MeasureUtils 同时测宽高（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，MeasureUtils.measureTextSize）
