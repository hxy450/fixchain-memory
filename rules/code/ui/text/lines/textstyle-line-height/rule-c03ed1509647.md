# Compose TextStyle 带 lineHeight 的单行文本，Text 不写 .lineHeight()

审的是：代码
触发（任一种）：
- 读到：Compose `TextStyle(fontSize = …, lineHeight = …)` 没有设 `lineHeightStyle`，用在单行文本（标题、价格、按钮文字等）上；写错的样子：对应的 ArkUI `Text` 上写了 `.lineHeight(…)`，值取样式行高（常量、`$r('app.float.…')` 或主题表字段）
适用范围：Compose 源端 TextStyle 带 lineHeight、未显式设 lineHeightStyle，单行文本迁成 ArkUI Text 时
做法：
- 单行 Text 删掉 .lineHeight(…)，只写 .fontSize(<源 sp 数值>)，高度回到字体自然高度
- 可能为空串的单行文本加 .constraintSize({ minHeight: <该字号的字体自然高度> })，自然高度的查法见下
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Android 端单行文本高度是字体自然高度，不是样式 lineHeight；ArkUI 的 lineHeight 按每行完整行高排版，不裁首行上方和末行下方的余量：两端行高语义不同，直译会让单行文本偏高（出处：卡里修好并验证过）
- lineHeight(value: number | string | Resource): TextAttribute；number 的单位是 fp，小于等于 0 时不限行高：ArkUI Text 的行高属性（出处：鸿蒙 SDK 的 ets/component/text.d.ts，TextAttribute.lineHeight）
- constraintSize(value: ConstraintSizeOptions): T：给空串文本设最小高度（minHeight）（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.constraintSize）
针对本应用要查的：
- 某字体某字号的单行自然高度：源工程 res/font 或目标工程 resources/rawfile 里的字体文件，读 hhea 表的 ascender、descender 和 head 表的 unitsPerEm；自然高度 = 字号 × (ascender + |descender|) / unitsPerEm；系数随字体而变
未核实：带 .lineHeight 时空串文本的实际高度卡里没单独测；minHeight 是按 Compose 对等处理加的
