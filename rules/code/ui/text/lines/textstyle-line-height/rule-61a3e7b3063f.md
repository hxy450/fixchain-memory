# 按文本高度给容器定高时，单行文本取字体自然高度，不用样式 lineHeight

审的是：代码
触发（任一种）：
- 读到：Compose 里行按内容包裹（LazyRow / Column 无固定高度），其中 Text(style = …titleMedium) 带 lineHeight；写错的样子：ArkUI 横向 List 的交叉轴高度写成字面常量（const …_HEIGHT: number = <数>），注释按「某令牌 lineHeight N」算文本盒高
- 读到：源端 `LazyRow` / `Row` 没有显式高度、按子项 wrap，子项里有用带 `lineHeight` 的 `TextStyle` 的单行 Text；写错的样子：横向 `List` 的 `.height(…)` 按样式 lineHeight 常量与图片、padding 相加算出，比子项实际高
适用范围：目标端必须给容器显式定高（如 ArkUI 横向 List 的交叉轴尺寸）、高度要由子项里的单行文本高度推算时
做法：
- 定高写成表达式：<上下内边距> + <图片尺寸> + <文本自然高> + …；单行文本自然高取 fontSize × (ascender + |descender|) / unitsPerEm（字体 hhea 比），或引用排版令牌上的自然高派生函数，不用样式 lineHeight，不写含 lineHeight 的字面常量
- 注释写明文本高度取自哪里（字体自然高、哪个令牌），主题改写法时能被 grep 到并随之重推
- 定不准时在子项上 .onSizeChange((oldValue, newValue) => { … }) 读实高，回写到容器的高度状态
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 行高常量改为 8 + 图片尺寸 + 8 + <令牌>.naturalHeight() + 8 + 8 的派生式后，双端对上：修好后的写法（各项内边距随源布局而定）（出处：卡里修好并验证过）
- 按 lineHeight 计的定高比源端按子项 wrap 的高度大；改用该字号的自然高度后一致：定高用错文本高度的后果（出处：卡里修好并验证过）
- onSizeChange(event: SizeChangeCallback): T：组件尺寸变化时回调，取子项实高（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onSizeChange）
针对本应用要查的：
- 文本的单行自然高（字体高度系数）：源工程 res/font 或目标工程 resources/rawfile 里该令牌所用字体文件的 hhea 表 ascender、descender 和 head 表 unitsPerEm；或 Android dump 里同一 Text 的盒高；fontSize × (ascender + |descender|) / unitsPerEm；dump 盒高按 px ÷ density 换成 dp 对照
未核实：自然行高比是否要计入 hhea 的 lineGap 卡里没写
