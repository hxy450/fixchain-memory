# 源 targetSdk < 28 时，含日文等回退字体的正文和标题用固定 lineHeight 锁行距

审的是：代码
触发（任一种）：
- 读到：源工程 targetSdkVersion 小于 28，TextView 没写 android:fallbackLineSpacing，正文或标题里有日文等由回退字体绘制的文字；写错的样子：对应的 Text 没有固定 .lineHeight(...)，含 CJK 的行比拉丁文字的行高
适用范围：源 targetSdk < 28、文字含 CJK 等需回退字体的语言时的正文和标题
做法：
- 正文和标题写固定的 .lineHeight(<源默认字体的行距 px> / <设备密度>)，回退字体的行和拉丁文字的行用同一个行距
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- STATICLAYOUT_FALLBACK_LINESPACING 是 @EnabledSince(targetSdkVersion = Build.VERSION_CODES.P)：targetSdk 28 起 StaticLayout 才按回退字体的 ascent/descent 撑高行；28 以下回退字体的行仍按默认字体的行盒（出处：android.widget.TextView#STATICLAYOUT_FALLBACK_LINESPACING）
- fallbackLineSpacing 为 true 时，用到的回退字体会增大所在行的 ascent 和 descent：这个属性的含义（出处：Android SDK 平台资源 data/res/values/attrs.xml，TextView 的 fallbackLineSpacing（按应用的 compileSdk 取对应平台））
- lineHeight(value: number | string | Resource): TextAttribute；number 的单位是 fp：固定行距，回退字体的行不再变高（出处：鸿蒙 SDK 的 ets/component/text.d.ts，TextAttribute.lineHeight）
- 固定 lineHeight 后日文行与英文行用同一行距，和安卓一致：不固定时鸿蒙输出里含日文的行随回退字体变高（出处：卡里修好并验证过）
针对本应用要查的：
- 源工程的 targetSdkVersion：源工程模块的 Gradle 构建脚本里 defaultConfig 的 targetSdkVersion / targetSdk，或 AndroidManifest 的 uses-sdk；小于 28 时按这条做；28 及以上不在这条范围内
