# wrap_content 的 TextView 文本可能为空时，目标 Text 用空格或零宽字符兜底保留一行高

审的是：代码
触发（任一种）：
- 读到：`TextView` 是 `wrap_content`、可见或 INVISIBLE，文本可能为空（无标题、空正文、名称丢失），相邻元素依赖它的一行高度定位；写错的样子：目标 `Text(this.title)` 不处理空串，或已改成 `Visibility.Hidden` 但内容仍是 `''`，空 Text 高度为 0，相邻元素上移
适用范围：空串可能到达的 Text（列表卡片标题、正文预览、网格文字条等）
做法：
- Text 内容为空时用 ' '（单空格）或 '\u200B'（零宽空格）兜底，如 `Text(this.title !== '' ? this.title : ' ')`；或给定 `.lineHeight(...)`
- 核对依赖它定位的相邻元素（日期行、正文起始行、底部文字条）在空文本时的位置
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 安卓空文本的 wrap_content TextView 仍按一行字体高度占高；ArkUI 空字符串 Text 高度为 0，Visibility.Hidden 的空 Text 也是 0：只改显隐不够，还要保住行高（出处：卡里修好并验证过）
- 空串以单空格或 '\u200B' 代替后行高恢复，和安卓一致：修好的写法（出处：卡里修好并验证过）
- lineHeight(value: number | string | Resource): TextAttribute：Text 的行高；number 单位是 fp，小于等于 0 时不限制（出处：鸿蒙 SDK 的 ets/component/text.d.ts，TextAttribute.lineHeight）
未核实：卡里的行为出自 HarmonyOS 6.1.1(24)，核对声明用的是本机 API 23；用 lineHeight 保住空 Text 行高这一写法卡里没有上机验证
