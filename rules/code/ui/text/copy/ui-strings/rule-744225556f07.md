# 页面读回的字符串首尾带引号或反斜杠时，回资源层改 string.json，不在页面里剥

审的是：代码
触发（任一种）：
- 读到：getStringSync 或 $r 读回的字符串值首尾带字面双引号，或残留反斜杠，源 strings.xml 里对应的 <string> 是用双引号包着或带转义的；写错的样子：页面代码在 getStringSync(...) 的结果上再剥一层引号或去反斜杠（自写的取值辅助函数、.replace(...)、首尾截取）
适用范围：界面实现阶段读回字符串资源显示或拼接时
做法：
- 对照源 strings.xml 确认是 aapt 的外层引号或转义后，回到各 locale 的 element/string.json 改值（去掉外层引号、还原转义），页面直接使用 getStringSync / $r 的结果，不加剥除逻辑
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getStringSync(resId: number): string：按资源 ID 同步取字符串，返回的是资源里存的原值（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getStringSync）
- getStringSync(resource: Resource): string，@deprecated since 20，@useinstead ohos.resourceManager.getStringSync：同族接口：按 Resource 对象取字符串（已废弃）（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getStringSync）
- getStringByNameSync(resName: string): string：同族接口：按资源名取字符串（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getStringByNameSync）
未核实：卡里鸿蒙 SDK 是 6.1.1(24)，getStringSync 按本机 API 23 的声明核实
