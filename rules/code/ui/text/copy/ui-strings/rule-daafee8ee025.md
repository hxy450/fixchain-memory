# 源布局的页面专属文案在目标 string.json 里缺失时，用专属新 key，不拿通用资源顶替

审的是：代码
触发（任一种）：
- 读到：源布局 XML 里 TextView 的 android:text 是硬编码的页面专属文案（如空态提示），目标 string.json 里没有对应条目；写错的样子：目标写成 Text($r('app.string.…')) 引用一个语义相近的通用资源（如通用的「暂无数据」），文案与源不同
适用范围：页面转换阶段把源布局里硬编码的页面专属文案迁成 $r 字符串资源引用时
做法：
- 用页面专属的新 key 引用：Text($r('app.string.<页面专属 key>'))，值逐字取源文案
- 不用语义相近的通用资源顶替；写完把源文案与所引 $r 资源的实际值逐字比对
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 改为引用新加的专属 key，string.json 由收尾者补上该条目：修复后显示源端原文（出处：卡里修好并验证过）
针对本应用要查的：
- 源文案的确切字面：源工程布局 XML 里该 TextView 的 android:text（或它引用的 @string 资源）；逐字取出，作为新 key 的值；目标 string.json 里按值检索确认没有同文的条目
