# 源端登录分支调用带空值兜底的 getter 时，目标调用已移植的同名 getter，不读原始字段

审的是：代码
触发（任一种）：
- 读到：源端刷新界面时 if (已登录) setText(管理器的 getter()) else setText(未登录占位)，getter 方法体里空值返回默认文案；写错的样子：目标登录分支读原始字段写成 `字段.length > 0 ? 字段 : 未登录占位文案`，没调用已移植的同名 getter
适用范围：功能接线阶段，把源端按登录态分支给文本赋值的逻辑翻译成目标组件状态赋值时
做法：
- 登录分支直接调用目标侧已移植的等价 getter 取值；未登录占位文案只放在 else 分支
- 先读源 getter 的方法体确认空值兜底，再逐分支核对目标表达式在「已登录 + 空值」时的结果和源端一致
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 登录态空值时走 getter 的默认文案，已登录不再显示未登录占位：修复后保留的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源 getter 的空值兜底：源工程里被调用的用户信息管理类的 getter 方法体；读空值时的返回分支（已登录、游客各返回什么），和目标侧已移植的同名方法逐项对照
