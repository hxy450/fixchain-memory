# 弹窗专用文案在目标字符串表里缺时，按源端原文新建资源或留 HANDOFF，不借用别处文案

审的是：代码
触发（任一种）：
- 读到：源端弹窗配置里的标题、说明、按钮文案在目标 string.json 里搜不到；写错的样子：目标用其他页面的 $r('app.string.…')（如个人中心的同类条目）顶替标题正文，按钮用通用取消/确定冒充「同意并继续 / 不同意」；没有新增资源，HANDOFF 和 uncertain_regions 里都没提
适用范围：页面实现时目标字符串表缺本页专用文案的情形
做法：
- 按源端原文命名新字符串资源，写进 resources/base/element/string.json，代码里用 $r('app.string.新资源名') 引用
- 本角色不能改共享资源时，留 HANDOFF 交给负责共享资源的 closer，或在 uncertain_regions 里显式报告缺的文案
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- $r('app.type.name')，type 为资源类型、name 为资源名：string 类资源的引用写法：$r('app.string.资源名')（出处：resource-categories-and-access.md，访问本模块资源或模块依赖的HAR资源）
