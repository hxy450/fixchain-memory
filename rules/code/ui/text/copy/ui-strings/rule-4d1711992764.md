# 偏好对话框没声明按钮文案时引用框架译文资源，不借应用同名的 ok、cancel、confirm

审的是：代码
触发（任一种）：
- 读到：<ListPreference> / <EditTextPreference> 只有 entries、entryValues、key、title、dialogTitle，没有 android:positiveButtonText / android:negativeButtonText；写错的样子：对应弹层的按钮写 $r('app.string.cancel')、$r('app.string.confirm') 这类应用字符串
适用范围：源端 Preference、AlertDialog 的默认按钮文案（应用没显式声明）迁到目标对话框时
做法：
- 按钮引用从框架译文落成的资源（如 $r('app.string.android_ok')、$r('app.string.android_cancel')），不因应用恰好有同名键就引用应用串
- 最小检查：对照源 XML 有没有 positiveButtonText / negativeButtonText，有就用它引用的字符串
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Preference.DialogPreference 样式：android:positiveButtonText = @android:string/ok，android:negativeButtonText = @android:string/cancel：androidx.preference 的默认按钮文案来自框架（出处：androidx.preference:preference 包内 res/values/values.xml，Preference.DialogPreference（按应用依赖的版本））
- Preference.DialogPreference 样式：positiveButtonText = @string/ok，negativeButtonText = @string/cancel：平台 android.preference 的默认按钮文案（出处：Android SDK 平台资源 data/res/values/styles.xml，Preference.DialogPreference（按应用的 compileSdk 取对应平台））
- 返修把按钮改成 android_cancel / android_ok：修好的写法（出处：卡里修好并验证过）
