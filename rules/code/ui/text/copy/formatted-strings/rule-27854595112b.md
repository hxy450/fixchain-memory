# 字符串资源占位是 %s/%1$s 时，$r 的格式化参数传 string，数值先 toString()

审的是：代码
触发（任一种）：
- 读到：stringResource(R.string.x, 数值) 传 Long/Int，对应字符串资源值里的占位是 %1$s；写错的样子：$r('app.string.x', 数值变量) 直接把 number 传给 %s/%1$s 占位，界面上占位处为空
适用范围：带格式化参数的字符串资源迁成 $r 或 resourceManager 取串时，占位符是 %s 或 %数字$s 的参数
做法：
- 先看资源值里每个占位的类型：%s/%1$s 对应的实参写成 string，数值写成 value.toString()，例如 $r('app.string.资源名', count.toString())；不假定 $r 会隐式转换
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- declare function $r(value: string, ...params: any[]): Resource：格式化参数是 any[]，编译期不检查与占位符的类型是否匹配（出处：鸿蒙 SDK 的 ets/component/common.d.ts，$r）
- %1$s 和 %2$d 两个占位时写成 $r('app.string.label', 'aaa', 444)：文档示例里 %s 传字符串、%d 传数字（出处：resource-categories-and-access.md，资源访问）
- 支持的占位：%d、%f、%s、%%、%数字$d、%数字$f、%数字$s：资源串格式化支持的占位符类型（出处：js-apis-resource-manager.md，getStringSync<sup>10+</sup>）
- 给 %1$s 传 number 时界面只显示占位以外的文字；改传 toString() 后正常：错误写法的表现和修法（出处：卡里修好并验证过）
- getStringSync(resId: number, ...args: Array<string | number>): string：同族接口：resourceManager.ResourceManager 按资源 ID 取格式化串，占位规则相同（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getStringSync）
- getStringByNameSync(resName: string, ...args: Array<string | number>): string：同族接口：resourceManager.ResourceManager 按资源名取格式化串（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getStringByNameSync）
针对本应用要查的：
- 资源串里每个占位符的类型：目标工程 resources/base/element/string.json（或源工程 res/values/strings.xml）里该资源名的 value；读出 %s/%数字$s 还是 %d/%数字$d，%s 类的实参写成 string
