# 源端在代码里格式化出带固定措辞的文案时，目标建参数化字符串资源，用 $r 传参

审的是：代码
触发（任一种）：
- 读到：源端 Kotlin/Java 用 `SimpleDateFormat("yyyy年M月")`、`String.format(...)` 或字符串拼接生成带中文单位或固定措辞的显示文本，不在 strings.xml 里；写错的样子：目标把这段文案写成模板字符串或 `+` 拼接直接传给 `Text(...)`，没有对应的 `$r('app.string.…')`
- 写错的样子：`Text()`、`accessibilityText()` 的文本实参是反引号模板或 `+` 拼接，且夹带非数字的字面量（年、月、单位、固定前缀等）
适用范围：目标工程约定可见文案走 $r('app.string.*')，源端在代码里动态格式化可见文案时
不适用的情形：实参只是纯数字（如日期格子的 day.toString()）时可以保留
做法：
- 在模块 string.json 里登记格式串（如 `%s年%s月`），文本写成 `Text($r('app.string.<key>', 参数1.toString(), 参数2.toString()))`，源端格式里的每个变量按出现顺序对应一个参数
- 不因源端文案没进 strings.xml 就当作非资源文案；accessibilityText 里的同类文本也改成 `$r(...)`
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- declare function $r(value: string, ...params: any[]): Resource：取资源，后面的参数依次替换字符串里的占位符（出处：鸿蒙 SDK 的 ets/component/common.d.ts，$r）
- value 里有 %1$s、%2$d 两个占位符时写 $r('app.string.label', 'aaa', 444)：多占位符的访问写法，参数按顺序替换（出处：resource-categories-and-access.md，访问本模块资源或模块依赖的HAR资源）
- (content?: string | Resource, value?: TextOptions): TextAttribute：Text 的内容可以直接传 Resource（出处：鸿蒙 SDK 的 ets/component/text.d.ts，TextInterface）
- accessibilityText(text: Resource): T（@since 12）：同族接口：无障碍文本也能传 Resource（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.accessibilityText）
- string.json 加 `%s年%s月`，标题改为 Text($r('app.string.<key>', 年.toString(), 月.toString()))，显示与安卓一致：修好后的写法，修的是文案来源（出处：卡里修好并验证过）
针对本应用要查的：
- 源端格式串和变量顺序：源工程 Kotlin/Java 里给该控件设文本的代码，找 SimpleDateFormat 的 pattern、String.format 的格式串或拼接表达式；固定措辞原样写进 string.json 的 value，每个变量换成一个 %s（数字要补零的先在代码里格式化成字符串再传）
