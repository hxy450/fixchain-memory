# 代码内取文案用 getStringSync($r(…).id) 按 id 取，不传 Resource 对象

审的是：代码
触发（任一种）：
- 读到：安卓自绘 View 里用 getResources().getString(R.string.*) 取文案，再交给 canvas.drawText 或 paint.measureText；写错的样子：代码内取字符串写成 resourceManager.getStringSync($r('app.string.*'))，传的是 Resource 对象而不是它的 .id
适用范围：目标端要在 ArkTS 代码里拿到纯字符串（画布绘制、测宽、拼串）、应用带多个 locale 资源目录时
做法：
- 写成 resourceManager.getStringSync($r('app.string.<名>').id)，按数字 id 取值，和组件上声明式 $r 文本走同一条解析路径；源端 R.string.<名> 对应 $r('app.string.<名>')
- 后续把这种取值扩到更多调用点时照同一写法，已有的 getStringSync($r(...)) 先例对照源端语义一并改成 .id，不以「前一切片用过」为据
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getStringSync(resId: number): string：按资源 id 取字符串（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getStringSync）
- getStringSync(resId: number, ...args: Array<string | number>): string：按 id 取带格式参数的字符串（对应 getString(id, formatArgs)）（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getStringSync）
- getStringSync(resource: Resource): string 标着 @deprecated since 20：Resource 对象重载（带 args 的那个也一样）从 API 20 起废弃（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getStringSync）
- Resource.id: number（resource id in hap）：$r(...) 返回的 Resource 上的数字 id，传给按 id 的重载（出处：鸿蒙 SDK 的 ets/api/global/resource.d.ts，Resource.id）
- 应用偏好语言 fa（locale fa_Arab_）下，按 id 取值返回 fa 文案，Resource 重载回落到 base 的英文；改成 .id 后画布与安卓一致：两个重载在应用偏好语言下行为不同（出处：卡里修好并验证过）
- getStringValue(resId: number): Promise<string>：同族接口：异步按 id 取字符串（它的 Resource 重载同样从 API 20 起废弃）（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getStringValue）
- getStringArrayValueSync(resId: number): Array<string>：同族接口：按 id 取字符串数组（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getStringArrayValueSync）
- getIntPluralStringValueSync(resId: number, num: number, ...args: Array<string | number>): string：同族接口：按 id 取复数字符串（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getIntPluralStringValueSync）
未核实：Resource 重载在应用偏好语言下回落的行为只来自模拟器插桩，没有找到官方文档说明；声明只写了它从 API 20 起废弃；同族接口的 Resource 重载是否同样回落，卡里没有验证
