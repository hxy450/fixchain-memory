# ResourceStr 传给 accessibilityText 时先用 typeof 收窄再调用

审的是：代码
触发（任一种）：
- 读到：目标页面里的 `@Local` 状态字段或方法参数声明为 `ResourceStr`，参照的修饰链模板来自字段类型是 `Resource` 的其他页面；写错的样子：把 ResourceStr 字段直接传进 `.accessibilityText(...)`，编译报 10505001（没有匹配的重载）
适用范围：把 ResourceStr 类型的值传给只有 string 和 Resource 两个分立重载的属性方法时（accessibilityText、accessibilityDescription）
做法：
- 先用 typeof 分支收窄再调用：if (typeof v === 'string') { 组件.accessibilityText(v) } else { 组件.accessibilityText(v as Resource) }，或把字段改存确定的 string / Resource 类型
- 复用别的文件里的修饰链前，逐个核对实参的声明类型和目标方法的重载，不沿用 Resource 字段页面的写法
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- accessibilityText(value: string): T；accessibilityText(text: Resource): T（@since 12）：两个分立重载，没有接受 string | Resource 联合类型的版本（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.accessibilityText）
- declare type ResourceStr = string | Resource：ResourceStr 是联合类型，不能直接匹配上面任一重载（出处：鸿蒙 SDK 的 ets/component/units.d.ts，ResourceStr）
- accessibilityDescription(value: string): T；accessibilityDescription(description: Resource): T：同族接口：CommonMethod.accessibilityDescription，同样是 string 和 Resource 分立重载（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.accessibilityDescription）
- 10505001：TSC 原生报错，常见原因含赋值类型与接收类型不一致：看到这个错误码时，先核对实参类型和方法重载（出处：errorcode-tsc.md，10505001 TSC原生报错）
- typeof 收窄为 string 或 Resource 后分别调用 accessibilityText，编译通过：验证过的写法（出处：卡里修好并验证过）
