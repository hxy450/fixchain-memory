# 编译修复遇 Resource 不能赋给 string 时，用 getStringSync 解析本地化文本，不用枚举名

审的是：代码
触发（任一种）：
- 读到：构建日志报 `Type 'Resource' is not assignable to type 'string'`（如 PopupOptions.message），源端是 stringResource(nameResId) 的本地化提示；写错的样子：修复把 message 改成枚举的 rawName / name，本地化名称退化为英文枚举名
适用范围：编译修复阶段处理字符串类型参数收到 Resource 的报错时
做法：
- 用 resourceManager 把原 Resource 解析成本地化字符串：message: this.getUIContext().getHostContext()!.resourceManager.getStringSync(res.id)；或改用接受 builder 的 CustomPopupOptions
- 声称「源码就是如此」之前先回读对应源码
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- PopupOptions.message: string：气泡的文本参数只收 string（出处：鸿蒙 SDK 的 ets/component/common.d.ts，PopupOptions.message）
- getStringSync(resId: number, ...args: Array<string | number>): string；getStringSync(resource: Resource): string 自 20 起废弃：按资源 id 取本地化字符串（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getStringSync）
- Resource.id: number：取 $r(…) 的资源 id（出处：鸿蒙 SDK 的 ets/api/global/resource.d.ts，Resource.id）
- CustomPopupOptions.builder: CustomBuilder：同族接口：自定义气泡内容，可直接放 Text($r(…))（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CustomPopupOptions.builder）
- 提示改回本地化名称后与源端一致：卡里的修法（出处：卡里修好并验证过）
