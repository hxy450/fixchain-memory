# 已移植的 getter 返回 ResourceStr 而状态是 string 时，解析资源，不回退成占位字符串

审的是：代码
触发（任一种）：
- 读到：目标侧已移植的 getter 返回 ResourceStr，空值时给的是 $r('app.string.…') 资源；写错的样子：组件状态（@Local 字段）声明成 `string`，因类型不合改读原始字段或回退成占位字符串，没解析资源
适用范围：把返回 ResourceStr 的访问器结果赋给 string 类型组件状态时
做法：
- 按代码库已有方式解析：const ctx = this.getUIContext().getHostContext()；ctx 不为 undefined 也不为 null 时用 ctx.resourceManager.getStringSync(资源.id) 取字符串，取不到时回落到同一默认文案而不是未登录占位
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- declare type ResourceStr = string | Resource：要先判断是不是 Resource 再解析（出处：鸿蒙 SDK 的 ets/component/units.d.ts，ResourceStr）
- getHostContext(): Context | undefined：从 UIContext 取 Ability 的 Context（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.getHostContext）
- getStringSync(resId: number): string：按资源 id 同步取字符串，传 Resource 的 id（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getStringSync）
- getStringSync(resource: Resource): string 自 API 20 废弃：同族接口：按 Resource 对象取，不要再用（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getStringSync）
- id: number（Resource）：资源在 hap 里的 id（出处：鸿蒙 SDK 的 ets/api/global/resource.d.ts，Resource.id）
未核实：声明里 getHostContext 只返回 Context | undefined，卡里编译修复把判空扩到 null 的原因没核实；卡里观察到的行为出自 API 24 目标 SDK，本机按 API 23 核实
