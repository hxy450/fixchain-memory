# 联合类型的值传给组件属性方法前查重载，没有接受整个联合的就归成单一类型再传

审的是：代码
触发（任一种）：
- 读到：源端控件写了 android:contentDescription（映射参考只给 String → String）；写错的样子：字段声明为 ResourceStr、赋 $r(...) 后传给 .accessibilityText(...)，联合类型匹配不上任何一个重载
- 读到：规格状态接口写 string | Resource，转换决策写 .accessibilityText()（初始取字符串资源、之后为普通字符串）；写错的样子：getter 返回 string | Resource 后直接传给 .accessibilityText(...)，编译报 10505001（没有匹配的重载）
适用范围：页面实现阶段把联合类型或可选类型的值传给组件属性方法（如 string、Resource 分开重载的 accessibilityText）时
做法：
- 在本地 SDK 的组件声明里查该方法签名（搜 accessibilityText( 这类方法名），确认有接受整个联合类型的重载
- 没有就把字段声明为 string 或 Resource 中的一种（都用 $r() 时声明为 Resource），不用 ResourceStr 联合类型
- 初始取字符串资源、之后为普通字符串时，在 getter 内归一成 string：资源串用 this.getUIContext().getHostContext() 的 resourceManager.getStringSync($r('app.string.…').id) 取，context 为空时回落到源端的默认文本；调用点不变，与规格的差异写进转换报告
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- accessibilityText(value: string): T；accessibilityText(text: Resource): T（@since 12）：string 和 Resource 两个重载分开声明，联合类型两者都不匹配（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.accessibilityText）
- accessibilityDescription(value: string): T；accessibilityDescription(description: Resource): T：同族接口：无障碍描述同样分开声明（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.accessibilityDescription）
- getStringSync(resId: number): string：按资源 id 同步取字符串，传 $r(...).id（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getStringSync）
- getStringSync(resource: Resource): string 自 API 20 起 @deprecated：不要改传 Resource 对象，用 resId 那个重载（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getStringSync）
- getHostContext(): Context | undefined：UIContext 取宿主 Context，可能为 undefined，要判空（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.getHostContext）
- getter 返回 string，资源串经 getStringSync 解析，context 为空时回落默认文本：修好后增量编译通过（出处：卡里修好并验证过）
