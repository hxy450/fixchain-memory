# 翻译键 t() 的文案和 FWD-REF 过渡

agent 会看到什么：源页面文案来自运行期翻译键 t('…')（i18next、useTranslation），目标页面里有固定语言的 Text('…') 字面量、指向翻译服务的 FWD-REF 标记，或头注释里拿 D- 编号给字面量过渡做依据

## 规矩

- rule-f2f904649e95｜要随语言刷新的页面里 Text 写死中文字面量、没有 i18n 引用时，改成经键取文案｜读到：源页面文案来自运行期 i18n 键 `t('…')`，spec 写语言切换后刷新全部文案；写错：页面各处 `Text('…')` 散写中文字面量，文件里没有 i18n 服务或 `tr(` 的引用，registry 里也没有对应的 `FWD-REF`
- rule-b2942e71f62e｜解除文案类 FWD-REF 时翻译服务已落盘，就把字面字段改成渲染期 t(key)，不拿字面当接线｜读到：页面注释里有 `FWD-REF:` marker 指向运行期翻译服务的 t()（resolve_by 是本切片的接线步骤），页面规格写明文案是「某语言包字面 + 逐键注释占位」；写错：删掉了 FWD-REF 行，但文案的 @Local 字段仍直接赋固定语言的字面字符串，页面没有 import 翻译服务、也没有调用 t(key)
- rule-e9a393a74431｜注释里不拿 D- 编号给过渡做法当依据，核对 ledger 原文后按延期占位登记｜读到：decision-ledger 里被引用的 `D-` 条目原文只规定别的事（如 i18n 声明式状态刷新），没批准页面文案用字面量；写错：页面头注释（以及页面 spec）写「`D-…` 文案取单一语言字面量（i18n 服务接管前）」，把过渡做法包装成 ledger 决策
