# 解除文案类 FWD-REF 时翻译服务已落盘，就把字面字段改成渲染期 t(key)，不拿字面当接线

审的是：代码
触发（任一种）：
- 读到：页面注释里有 `FWD-REF:` marker 指向运行期翻译服务的 t()（resolve_by 是本切片的接线步骤），页面规格写明文案是「某语言包字面 + 逐键注释占位」；写错的样子：删掉了 FWD-REF 行，但文案的 @Local 字段仍直接赋固定语言的字面字符串，页面没有 import 翻译服务、也没有调用 t(key)
适用范围：功能切片接线阶段解除页面上登记的文案类前向引用时
做法：
- 写入前重新查一次翻译服务文件是否已落盘（目标工程里带 t() 和语言状态的那个服务）
- 服务存在就 import 它，删掉字面字段，每处文案改成渲染期 t(key) 并接上它的语言状态（如 @Trace 的 lang）；弹窗、分享、toast 的文案在调用时取 t(key)
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 删掉固定语言字面字段、改成渲染期 t(key) 读 @Trace 语言状态后，简体系统下不再显示繁体：字面和某个语言包一致不等于接上了翻译（出处：卡里修好并验证过）
针对本应用要查的：
- 翻译服务的入口、语言状态和每个文案的键：目标工程里翻译服务所在的 .ets 文件（按 t( 方法和带 @Trace 的语言字段找），以及页面上逐键注释里写的键；文案写成 服务.t('键')，键照逐键注释；语言状态按服务导出的那个可观察对象接
