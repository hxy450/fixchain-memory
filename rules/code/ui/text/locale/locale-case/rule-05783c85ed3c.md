# 资源 locale 转 BCP 47 时按 '_' 拆分、丢空子标签再用 '-' 连接，失败回落

审的是：代码
触发（任一种）：
- 写错的样子：把 resourceManager.getConfigurationSync().locale 直接传给 toLocaleUpperCase，或写成 locale.replace(/_/g, '-')，没处理空子标签，也没有 RangeError 回落
适用范围：把鸿蒙资源配置里的 locale 字符串交给 toLocaleUpperCase / toLocaleLowerCase 等按 locale 的 JS 接口时
做法：
- tag = locale.split('_').filter(s => s.length > 0).join('-')；tag 为空时用 str.toUpperCase()；toLocaleUpperCase(tag) 包在 try/catch 里，抛 RangeError 时回落 str.toUpperCase()
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 资源配置的 locale 见过 en_Latn_US，应用偏好语言只有语言码时是 fa_Arab_（尾部空子标签）；直接传或只替换下划线会生成非法标签 fa-Arab-，toLocaleUpperCase 抛 RangeError 崩溃：格式不固定，不能从单个样本推断（出处：卡里修好并验证过）
- getConfigurationSync(): Configuration；Configuration.locale: string：取当前资源配置里的 locale 字符串（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getConfigurationSync、Configuration.locale）
