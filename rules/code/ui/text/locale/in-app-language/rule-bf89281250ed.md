# 规格要求保存后立即切换语言时，setAppPreferredLanguage 外还要 setLanguage 并刷新文案

审的是：代码
触发（任一种）：
- 读到：规格验收条目写「保存后应用界面语言立即切换」；源端应用内按 supported_locales 切换语言；写错的样子：只调 i18n.System.setAppPreferredLanguage(...)，注释称无需手动刷新；已显示的 getStringSync 文案不重取
适用范围：实现应用内语言切换、且要求当前进程立即生效时（ApplicationContext.setLanguage 声明 @since 21）
做法：
- 持久化仍用 i18n.System.setAppPreferredLanguage(lang)（下次启动按它加载）；同时调 applicationContext.setLanguage(lang) 让当前进程立即生效（只能在主线程调）
- 已显示的文案用一个语言代次之类的状态变量触发重取：切换后代次加一，依赖它的 getStringSync 文案重新求值
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- static setAppPreferredLanguage(language: string): void —— Resources are loaded in the preferred language when the application is launched.：i18n.System 设应用偏好语言，启动时才按它加载资源；设成 default 时冷启动后生效（出处：鸿蒙 SDK 的 ets/api/@ohos.i18n.d.ts，System.setAppPreferredLanguage）
- setLanguage(language: string): void（只能主线程调，@since 21）：ApplicationContext 设当前应用语言（出处：鸿蒙 SDK 的 ets/api/application/ApplicationContext.d.ts，ApplicationContext.setLanguage）
- getStringSync(resId: number): string：ResourceManager 同步取字符串；已取出的值不会自己变，要重取（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getStringSync）
- 增加 setLanguage 即时生效并以代次刷新 getStringSync 文案后，保存即切换：改后的效果（修复后真机验证）（出处：卡里修好并验证过）
未核实：卡里观察到的行为出自 HarmonyOS 6.1.1（API 24），本机声明按 API 23 核实；修前没有在设备上实测「保存后不即时切换」，依据是声明注释
