# 窗口级属性在 onWindowStageCreate 取到主窗口后执行，不靠 getLastWindow

审的是：代码
触发（任一种）：
- 读到：源端在组合期由 LocalView 取 Activity window，再设 FLAG_SECURE 和 isAppearanceLightStatusBars，此时窗口已存在；写错的样子：主题服务用 window.getLastWindow(context) 取窗口设状态栏极性或隐私窗，HANDOFF 写 owner=EntryAbility.onCreate，onWindowStageCreate 里没有注入主窗口
适用范围：目标端在 EntryAbility 启动链里设置窗口级属性（系统栏属性、隐私窗）时
做法：
- 在 onWindowStageCreate(windowStage) 里用 windowStage.getMainWindowSync() 取主窗口注入主题服务，再执行或补执行 setWindowSystemBarProperties / setWindowPrivacyMode
- 交到 onCreate 的服务不依赖 getLastWindow 取窗口；在 onConfigurationUpdate 里按新主题重新下发，并加重入保护
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onWindowStageCreate(windowStage: window.WindowStage): void：UIAbility 的 WindowStage 创建后回调，这时才有主窗口（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.UIAbility.d.ts，UIAbility.onWindowStageCreate）
- getMainWindowSync(): Window：WindowStage 上同步取主窗口；窗口未创建或已销毁时抛 1300002（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，WindowStage.getMainWindowSync）
- getLastWindow(ctx: BaseContext): Promise<Window>：取应用当前最上层窗口；顶层或主窗口为空时以 1300002 失败（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，window.getLastWindow）
- setWindowPrivacyMode(isPrivacyMode: boolean): Promise<void>，需 ohos.permission.PRIVACY_WINDOW：隐私窗，对应源端 FLAG_SECURE（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.setWindowPrivacyMode）
- onConfigurationUpdate(newConfig: Configuration): void：系统配置（如深浅色）变化时回调，在这里重新下发极性（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.Ability.d.ts，Ability.onConfigurationUpdate）
- onWindowStageCreate 注入 getMainWindowSync() 后重放窗口属性，onConfigurationUpdate 重新应用并加重入保护：修复后的时序（出处：卡里修好并验证过）
未核实：卡里的行为出自目标 SDK 6.1.1(24)，声明按本机 API 23 核实
