# 源端公式用 DisplayMetrics 宽高时，目标按避让区算出的内容区取值，不用整屏尺寸

审的是：代码
触发（任一种）：
- 读到：源端布局公式里用 DisplayMetrics 的宽高（如高度的几分之一作留白），Activity 是 FLAG_FULLSCREEN 全屏、targetSdk 较低；写错的样子：目标用 display.getDefaultDisplaySync() 的整屏宽高代替 DisplayMetrics；页面内容没放进按内容区定宽高与偏移的容器
- 读到：源自绘 View 用 getDisplayMetrics().widthPixels / heightPixels 算格径、底栏、行数，Activity 是 FLAG_FULLSCREEN，targetSdkVersion 低；写错的样子：量尺寸的方法取 windowRect.height 减 TYPE_SYSTEM 与 TYPE_NAVIGATION_INDICATOR 底部较大值作高，没减挖孔所在的边，也没按宽高比上限截长边
适用范围：源端按 DisplayMetrics 宽高推算几何的全屏页面迁成 ArkUI，目标要换算等价基准时
做法：
- 基准宽高取 getWindowProperties().windowRect，减去 getWindowAvoidArea(AvoidAreaType.TYPE_CUTOUT) 所在的边，再减 TYPE_SYSTEM 与 TYPE_NAVIGATION_INDICATOR 两种避让的 bottomRect 高度中较大的
- 源 targetSdk 低于 26 且没声明宽高比上限时，长边再截到 1.86 × 短边，得到内容区
- 页面内容放进按内容区定宽高与偏移的 Stack，源端 DisplayMetrics 参与的公式改用内容区宽高；主窗口底色设黑，留出的挖孔边和截掉的部分显示黑
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getWindowProperties(): WindowProperties；WindowProperties.windowRect: Rect：窗口的位置和大小，单位 px（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.getWindowProperties、WindowProperties.windowRect）
- getWindowAvoidArea(type: AvoidAreaType): AvoidArea：取某类避让区（窗口不能显示内容的区域）（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.getWindowAvoidArea）
- AvoidAreaType.TYPE_SYSTEM = 0、TYPE_CUTOUT = 1（Notch）、TYPE_NAVIGATION_INDICATOR = 4：系统栏、挖孔、导航条三类避让区（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，AvoidAreaType）
- setWindowBackgroundColor(color: string | ColorMetrics): void：设主窗口底色（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.setWindowBackgroundColor）
- 从 Activity 取的 DisplayMetrics 是当前应用窗口的尺寸；API 34 及以下还减去系统装饰区和挖孔：源端公式里的宽高对应内容区（出处：android.view.Display#getMetrics）
- DEFAULT_PRE_O_MAX_ASPECT_RATIO = 1.86f：targetSdk < O 的旧应用默认最大宽高比（出处：com.android.internal.pm.pkg.parsing.ParsingPackageUtils#setMaxAspectRatio）
- getWindowAvoidAreaIgnoringVisibility(type: AvoidAreaType): AvoidArea（@since 22）：同族接口：不论该类区域当前是否可见都返回避让区（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.getWindowAvoidAreaIgnoringVisibility）
- 内容区 = 屏幕减挖孔边与导航避让区、再按 1.86 截长边；页面按它定宽高与偏移、窗口底色黑后与源端一致，派生行数与参照机一致：修法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端公式用的是哪个宽高：源工程 Activity 或自定义 View 的 Java/Kotlin 代码里 DisplayMetrics 的 widthPixels/heightPixels 及其参与的计算；逐个公式换成内容区宽高（目标单位按工程约定换算）
- 源应用是否受挖孔和宽高比限制：源工程 AndroidManifest.xml 的 targetSdkVersion、activity 的 android:maxAspectRatio / android:resizeableActivity，主题链里的 android:windowLayoutInDisplayCutoutMode；targetSdk 低于 28 且没设挖孔模式：减挖孔边；targetSdk 低于 26 且没声明上限：按 1.86 截长边
未核实：resizeableActivity 为 true 时不截窗的条件按卡写，本机源码只核了 targetSdk < O 默认 1.86
