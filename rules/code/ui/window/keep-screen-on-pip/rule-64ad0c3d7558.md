# Activity 窗口常亮迁到页面时，在 onShown/onHidden 成对调常亮开关

审的是：代码
触发（任一种）：
- 读到：源端 Activity.onCreate 里 getWindow().addFlags(FLAG_KEEP_SCREEN_ON)，没有 clearFlags；写错的样子：页面在 aboutToAppear 里 window.getLastWindow 后 setWindowKeepScreenOn(true)，onHidden、aboutToDisappear 里都没有 setWindowKeepScreenOn(false)
适用范围：目标端页面是 NavDestination、共用 UIAbility 主窗口，通过 window.getLastWindow 调窗口级 API 实现源端单个 Activity 窗口上的效果时
做法：
- 调之前核对源端调用的是哪个 Activity 的 getWindow()；只作用于这个 Activity 窗口的，按该页可见期成对设置，即使规格只写了「onCreate 时机」也一样
- 在该页 NavDestination 上写 .onShown(() => { win.setWindowKeepScreenOn(true) }) 和 .onHidden(() => { win.setWindowKeepScreenOn(false) })，win 由 window.getLastWindow(context) 取得；源端加标志的条件（如读偏好）只决定 onShown 里要不要打开
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- setWindowKeepScreenOn(isKeepScreenOn: boolean): Promise<void>：Window 的常亮开关，true 开、false 关（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.setWindowKeepScreenOn）
- function getLastWindow(ctx: BaseContext): Promise<Window>：取当前应用最上层窗口，没有子窗口时就是主窗口（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，window.getLastWindow）
- onShown(callback: Callback<VisibilityChangeReason>): NavDestinationAttribute；onHidden(callback: Callback<VisibilityChangeReason>): NavDestinationAttribute：NavDestination 页面显示、隐藏时的回调（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onShown / onHidden）
- Window.setKeepScreenOn(isKeepScreenOn: boolean)：@deprecated since 9，@useinstead Window#setWindowKeepScreenOn：窗口上的旧名接口已废弃，不用（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.setKeepScreenOn）
- aboutToAppear 只开不关时回到上一页后仍持有 windowLock；改成 onShown 传 true、onHidden 传 false 后释放：成对开关才和源端窗口作用范围一致（出处：卡里修好并验证过）
未核实：卡里的修复写的是 setKeepScreenOn(on)，看不出是页面里的封装还是窗口上已废弃的同名接口
