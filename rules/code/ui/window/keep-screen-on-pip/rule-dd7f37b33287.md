# 常亮和紧凑模式这类前台专属状态，每条退出路径都显式复位

审的是：代码
触发（任一种）：
- 读到：源端用 WakeLock 或窗口常亮保持亮屏、用系统 PiP，退出 PiP 时回调把标志置 false；规格写明「stop clears flag」；写错的样子：setKeepScreenOn(true) 和紧凑模式标志置 true 之后，回前台、后台交接、后台完成、通知 Stop、页面销毁中有的路径只停服务或重启 ticker，没有对应的 false
适用范围：目标端用窗口常亮代替 WakeLock、用应用内紧凑模式代替系统 PiP 的页面和服务
做法：
- 列出常亮和紧凑模式的进入点与全部退出点（回前台、后台交接前后、后台完成、通知 Stop、页面销毁），每个退出点显式调 setWindowKeepScreenOn(false) 并把紧凑模式标志置 false，服务侧释放后台任务时同样清常亮
- 对照规格里的 stop clears flag 和 Stop 清常亮的验收条目核对；搜每处置 true 的调用，确认每条退出路径都有对应的 false
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- setWindowKeepScreenOn(isKeepScreenOn: boolean): Promise<void>：窗口常亮的开关，退出时传 false（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.setWindowKeepScreenOn）
- setKeepScreenOn(isKeepScreenOn: boolean): Promise<void> 自 API 9 废弃，改用 setWindowKeepScreenOn：产物里见到的 setKeepScreenOn 若是窗口接口本身，要换成新接口（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.setKeepScreenOn）
未核实：卡里环境是鸿蒙 target 6.0.1(21)，本机按 API 23 核对
