# Tab 宿主按各 Fragment 的状态栏处理逐 Tab 定穿透或避让，不给整列内容加顶部 padding

审的是：代码
触发（任一种）：
- 读到：源主题 `android:windowTranslucentStatus` 为 true 或用 `ImmersionBar` 沉浸；有的 Fragment 设 `statusBarView(...)` 或放占位 View，有的只调 `statusBarDarkFont`、头图铺到状态栏下；写错的样子：宿主给承载所有 Tab 的整列容器写 `.padding({ top: <状态栏高度> })`，回执记成「前景 inset」
- 读到：宿主 Activity 的基类里调了 ImmersionBar.with(this).transparentStatusBar() 一类的透明状态栏设置；写错的样子：宿主统一加顶部状态栏 padding、外层设白底，Tab 背景和标题落在状态栏下方；状态栏文字颜色没按 Tab 调
适用范围：一个宿主页承载多个 Tab、源端状态栏透明或沉浸时，顶部安全区由哪层处理
做法：
- 留位前先查宿主 Activity / Fragment 基类的状态栏设置（如 transparentStatusBar），再逐个看各 Fragment 有无 statusBarView、占位 View、头图是否铺到状态栏下，给每个 Tab 定穿透或避让
- 穿透的 Tab 从顶端开始、背景铺满；顶部 inset 只加在要避让的前景元素上或由宿主按 Tab 注入，不加在承载所有 Tab 的容器上；状态栏设透明，用 setWindowSystemBarProperties 的 statusBarColor、statusBarContentColor 按 Tab 同步
- 回执里逐 Tab 写明穿透或避让、inset 加在哪个元素上，不把整块 padding 记成前景 inset
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- windowTranslucentStatus：format="boolean"，对应 WindowManager.LayoutParams#FLAG_TRANSLUCENT_STATUS：源端窗口请求半透明状态栏，内容画到状态栏下，是否让位交给各页面（出处：Android SDK 平台资源 data/res/values/attrs.xml，windowTranslucentStatus（按应用的 compileSdk 取对应平台））
- expandSafeArea(types?: Array<SafeAreaType>, edges?: Array<SafeAreaEdge>): T：让背景延伸进安全区；默认 types 为 SYSTEM、CUTOUT、KEYBOARD，edges 为四边（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.expandSafeArea）
- getWindowAvoidArea(type: AvoidAreaType): AvoidArea；AvoidAreaType.TYPE_SYSTEM = 0；topRect 以 px 计：取状态栏避让高度，作为前景 inset 前要 px2vp（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.getWindowAvoidArea、AvoidAreaType.TYPE_SYSTEM）
- setWindowSystemBarProperties(systemBarProperties: SystemBarProperties): Promise<void>：设置状态栏颜色和文字颜色（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.setWindowSystemBarProperties）
- statusBarColor?: string；statusBarContentColor?: string：SystemBarProperties 里的状态栏背景色和文字颜色（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，SystemBarProperties.statusBarColor、SystemBarProperties.statusBarContentColor）
- 删掉宿主整列 padding 后，宿主各层容器从 y=0 开始：修复时的做法；剩余位移另有来源（出处：卡里修好并验证过）
- ignoreLayoutSafeArea(types?: Array<LayoutSafeAreaType>, edges?: Array<LayoutSafeAreaEdge>): T：同族接口：组件布局忽略安全区（CommonMethod，另有 Navigation、NavDestination 各一个）（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.ignoreLayoutSafeArea）
针对本应用要查的：
- 每个 Tab 在源端是否为状态栏让位：源工程各 Fragment 的 Kotlin/Java 文件里 ImmersionBar.with(this) 链式调用（看有没有 statusBarView、fitsSystemWindows），以及对应布局 XML 顶部有没有状态栏高度的占位 View；有占位或 statusBarView 的定为前景避让；只设状态栏字色、头图从顶端开始的定为背景穿透
- 源端状态栏是否透明、哪些页面内容延伸到状态栏：源工程里宿主 Activity 和它的基类（Java/Kotlin）里对 ImmersionBar、Window.setStatusBarColor、SYSTEM_UI_FLAG_LAYOUT_FULLSCREEN 的调用；各 Fragment 布局顶部的背景和 marginTop；基类设了透明状态栏的，背景铺到状态栏下面的 Tab 写成延伸；读出各 Tab 状态栏文字是深色还是浅色
未核实：卡里最终修复（状态栏设透明、文字设白色）注明未上机验证
