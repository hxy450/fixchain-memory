# 源端 Tab 用 titleBarMarginTop 让头图延伸到状态栏下时，宿主去掉顶部避让，标题加避让高度

审的是：代码
触发（任一种）：
- 读到：宿主 Fragment 里 `ImmersionBar.with(this).titleBarMarginTop(view)`，头图从屏幕顶部画起，顶部栏下移状态栏高度；写错的样子：标题写成固定的 margin({ top: … })，不含状态栏偏移；宿主仍对该 Tab 加顶部避让 padding；报告写 `immersive_safearea_skipped`
- 读到：源 Tab Fragment 调 `titleBarMarginTop(<标题 View>)` 自己延伸到状态栏；写错的样子：规格把页面判为 sub_component，目标组件没有 topPadding 参数；宿主给包住整个 `Tabs` 的容器统一加 `padding({ top: windowTopPadding })`
- 读到：源 Activity 布局根没有 padding，`paddingStart` / `paddingEnd` 只写在底部 Tab 栏容器上；写错的样子：宿主把底栏的左右 `padding` 加在包住整个 `Tabs` 的容器上，所有 Tab 内容区多出留白
适用范围：一个宿主页承载多个 Tab 子组件，源端有的 Tab 自己做沉浸、处理状态栏时
做法：
- 宿主对该 Tab 不加顶部避让 padding，头图从顶部画起；组件预留 topPadding 参数由宿主传入状态栏避让高度，标题 margin top 写成 topPadding + 源端原有间距
- 切到该 Tab 时把状态栏图标颜色设成与源端一致（深色头图上用白色图标）
- 宿主容器的 padding 照源 Activity 布局：只属于底栏的内边距加在底栏上，不加在包住 Tabs 的容器上
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getWindowAvoidArea(type: AvoidAreaType): AvoidArea，type 取 AvoidAreaType.TYPE_SYSTEM = 0：取系统栏避让区，顶部高度在 topRect.height（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.getWindowAvoidArea、AvoidAreaType.TYPE_SYSTEM）
- setWindowSystemBarProperties(systemBarProperties: SystemBarProperties): Promise<void>：设置系统栏属性（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.setWindowSystemBarProperties）
- SystemBarProperties.statusBarContentColor?: string：状态栏图标和文字的颜色（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，SystemBarProperties.statusBarContentColor）
- 把 windowTopPadding 传给组件标题的 margin，宿主排除该 Tab 的顶部内边距：修复后的做法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端标题栏原有的上边距和状态栏图标深浅：源工程该 Tab 的布局 XML 里被 titleBarMarginTop 传入的那个控件的 layout_marginTop，以及 ImmersionBar 链上的 statusBarDarkFont 调用；上边距照 dp 数值写成 vp 加在避让高度上；没有 statusBarDarkFont(true) 时按头图深色用白色图标
- 哪些 Tab 自己处理状态栏：源工程各 Tab Fragment 里 ImmersionBar.with(this) 的链式调用；调了 titleBarMarginTop / titleBar 的，组件自己按传入的 topPadding 让标题下移，宿主不给这个 Tab 加顶部内边距
未核实：避让区 topRect.height 的单位声明里没写（文档示例当作 px 用）；statusBarDarkFont 与图标颜色的对应是按库的命名推断，卡里只写了改成白色图标；规格把页面判为 sub_component 还是 full_screen_page 的判定过程卡里没追溯
