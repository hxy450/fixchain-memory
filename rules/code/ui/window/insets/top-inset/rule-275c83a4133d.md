# 源布局没处理 insets 时 Toolbar 置于 y=0，不为过闸补 windowTopPadding

审的是：代码
触发（任一种）：
- 读到：源布局根 android:fitsSystemWindows="false" 或没有 WindowInsets 处理，Toolbar 叠放在 WebView 等内容上，targetSdkVersion ≥ 35；写错的样子：目标页给叠放的 Toolbar 或根 Column 加 .padding({ top: windowTopPadding })，注释「Layer 3：前景避让状态栏」，出现状态栏高度的色条、工具栏下移
适用范围：源应用 targetSdk ≥ 35、目标窗口已 setWindowLayoutFullScreen(true) 沉浸，实现全屏页的顶部布局时
做法：
- Toolbar / ActionBar 和内容从 y=0 起，不加 windowTopPadding；页头标 needs_immersive_safearea=false 豁免沉浸式结构闸，不为过闸补避让
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- setWindowLayoutFullScreen(isLayoutFullScreen: boolean): Promise<void>：设置主窗口布局是否沉浸；沉浸后内容从状态栏下的 y=0 起（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.setWindowLayoutFullScreen）
- targetSdk ≥ VANILLA_ICE_CREAM（35）时 setDecorFitsSystemWindows 的行为等同 false 且不能改：源端没处理 insets 的视图本就从 y=0 起（出处：android.view.Window#setDecorFitsSystemWindows）
- 返修把 Toolbar 置 y=0、Web 全屏，去掉页面顶部的状态栏色条后与参照机一致：不避让才对得上源端（出处：卡里修好并验证过）
针对本应用要查的：
- 源页面是否处理了 insets：源工程这个页面的布局 XML（根和 Toolbar 的 android:fitsSystemWindows）和对应 Activity 里的 setOnApplyWindowInsetsListener / WindowInsets 调用；都没有、且 targetSdk ≥ 35 时不避让；确有处理的才映射成 windowTopPadding
未核实：卡里的行为出自 API 24（HarmonyOS 6.1.1），本机声明是 API 23
