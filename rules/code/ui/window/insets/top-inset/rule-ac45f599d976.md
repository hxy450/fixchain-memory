# NavigationView fitsSystemWindows 时，抽屉头部从窗口顶画并叠 #44000000 条

审的是：代码
触发（任一种）：
- 读到：NavigationView 自身 android:fitsSystemWindows="true"，并带 app:headerLayout；写错的样子：抽屉面板或头部被 .padding({ top: 状态栏高度 }) 推到状态栏下；或头部从窗口顶画了，但状态栏那一段没有叠半透明黑的前景
适用范围：源端 NavigationView 写了 android:fitsSystemWindows="true" 且有 app:headerLayout，迁成目标的抽屉面板时
做法：
- 抽屉面板从窗口顶开始画，头部高度保持源值、不加顶部避让；头部改成 Stack({ alignContent: Alignment.Top })，里面先放头部内容，再叠一条 Column().width('100%').height(状态栏高度).backgroundColor('#44000000')
- 抽屉收进共享基座时，这条前景放在基座的抽屉头部里，宿主页不再管
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- insetForeground = #4000（即 #44000000）：NavigationView 状态栏那段前景的默认颜色（出处：com.google.android.material:material 包内 res/values/values.xml，Widget.Design.ScrimInsetsFrameLayout 的 insetForeground（按应用依赖的版本））
- Widget.Design.NavigationView 的 parent 是 Widget.Design.ScrimInsetsFrameLayout；Widget.MaterialComponents.NavigationView、Widget.Material3.NavigationView 都从它派生：各主题族下 NavigationView 的 insetForeground 默认都来自这一项（出处：com.google.android.material:material 包内 res/values/values.xml，Widget.Design.NavigationView、Widget.Material3.NavigationView（按应用依赖的版本））
- Stack(options?: StackOptions)，StackOptions.alignContent?: Alignment，默认 Alignment.Center：叠前景条的容器；要贴顶须写 Alignment.Top（出处：鸿蒙 SDK 的 ets/component/stack.d.ts，StackInterface、StackOptions.alignContent；ts-container-stack.md，StackOptions）
针对本应用要查的：
- NavigationView 有没有改写 insetForeground：源工程布局 XML 里这个 NavigationView 的 app:insetForeground，以及主题里 navigationViewStyle 指向的样式；有改写就用改写后的颜色；没有就用 #44000000
