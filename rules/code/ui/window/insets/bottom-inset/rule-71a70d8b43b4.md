# 全屏布局页的贴底按钮行，不因安卓 XML 没有底部间距就省掉 bottomPadding

审的是：代码
触发（任一种）：
- 读到：安卓布局 XML 里贴底的按钮行和标题只有固定的 android:padding / layout_marginBottom，没有导航栏间距；写错的样子：目标页在 setWindowLayoutFullScreen(true) 下，贴底按钮行的 .padding({ bottom: N }) 和贴底元素的底距没加底部避让值，或者声明了底部避让变量却没在任何地方用
适用范围：目标窗口全屏布局、安卓源窗口不延伸到导航栏下时，迁移贴底的按钮行、CTA 和贴底浮层
做法：
- 贴底的按钮行、CTA 和浮层写成 .padding({ bottom: N + bottomPadding })（底距同理叠加），N 是源端的固定间距，bottomPadding 是导航指示条避让值（vp）
- 贴底的部分在子组件里时，子组件声明 @Param bottomSafe: number = 0，由宿主页把共享窗口模型的 bottomPadding 传进去
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- setWindowLayoutFullScreen(isLayoutFullScreen: boolean): Promise<void>：设置窗口布局是否沉浸式；为 true 时窗口布局延伸到导航区域下（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.setWindowLayoutFullScreen）
- 沉浸式布局下窗口可布局区域与导航区域等系统界面元素重叠，需要在组件布局时做额外的布局避让：全屏布局时贴底元素要自己叠加避让值（出处：immersive-window-feature.md，布局避让）
- @Param 表示组件从外部传入的状态（@ComponentV2 中使用，API 12 起）：子组件用它接收宿主注入的底部避让值（出处：arkts-new-param.md，概述）
- 底部按钮行和标题底距叠加宿主注入的 bottomPadding 后，按钮离屏底由 10vp 抬到 37.4vp：全屏布局页底部前景要消费底部避让（出处：卡里修好并验证过）
- windowOptOutEdgeToEdgeEnforcement 为 false（默认）时，targetSdk 达到 VANILLA_ICE_CREAM（35）的应用窗口强制 edge-to-edge；targetSdk 达到 BAKLAVA（36）时这个属性被忽略、一律强制：判断安卓源窗口是否延伸到导航栏下要看 targetSdk 和这个主题属性（出处：Android SDK 平台资源 data/res/values/attrs.xml，windowOptOutEdgeToEdgeEnforcement（按应用的 compileSdk 取对应平台））
针对本应用要查的：
- 安卓源窗口是否延伸到导航栏下：源工程模块构建脚本里的 targetSdk、Activity 主题里的 android:windowOptOutEdgeToEdgeEnforcement，以及代码里有没有 enableEdgeToEdge / setDecorFitsSystemWindows(false)；targetSdk 低于 35 且没有主动 edge-to-edge 的，源窗口停在导航栏上方，源 XML 不写底部间距是正常的；目标全屏布局仍要叠加 bottomPadding
未核实：卡里的环境是 API 24（6.1.1），本机用 API 23 的声明和文档核实
