# 全屏沉浸页里贴屏底的 bindSheet 内容，由宿主经 @Param 注入导航条避让值加到底部 padding

审的是：代码
触发（任一种）：
- 读到：源端 BottomSheetDialogFragment 的布局根只写 android:paddingBottom；写错的样子：目标 sheet 组件根容器只写 .padding({ bottom: 源值 })，没有避让参数；页面测得的底部安全区只用在页面自己的控件上
适用范围：页面开了全屏沉浸、底部弹层用 bindSheet 贴屏底显示时
做法：
- sheet 组件加一个接收底部避让值（vp）的 @Param，根容器写 .padding({ bottom: 源 paddingBottom + 这个避让值 })；宿主在 bindSheet 的 builder 里把页面的导航条避让值传进去
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getWindowAvoidArea(type: AvoidAreaType): AvoidArea；AvoidAreaType.TYPE_NAVIGATION_INDICATOR = 4：取导航条区域，用 bottomRect.height（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.getWindowAvoidArea、AvoidAreaType.TYPE_NAVIGATION_INDICATOR）
- Rect.height 单位是 px：加到 padding 前要换成 vp（padding 写 number 时默认单位是 vp）（出处：arkts-apis-window-i.md，Rect；ts-types.md，Length）
- sheet 组件加接收避让值的 @Param、根容器底部 padding 改成源值加这个避让值、页面注入导航条避让值后，内容不再落进导航指示条区域：卡里的修法（出处：卡里修好并验证过）
针对本应用要查的：
- 页面已有的导航条避让值：目标工程里页面做沉浸式避让的那段代码（取 getWindowAvoidArea 或从 AppStorage 读避让值的地方）；用页面已在用的同一个值（vp）注入 sheet，不在 sheet 里另取
未核实：卡里环境是 API 24，按本机 API 23 的声明核实
