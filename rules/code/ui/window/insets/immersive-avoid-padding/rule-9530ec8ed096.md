# 收口安全区 FWD-REF 或开启全屏前，逐页查自绘标题栏有没有消费 windowTopPadding

审的是：代码
触发（任一种）：
- 读到：安全区 FWD-REF 的注释只写底部份额；base-contracts 写 WindowModel 共享 windowTopPadding / windowBottomPadding；写错的样子：收口时只改成 .padding({ bottom: 12 + windowBottomPadding }) 并删掉 marker，自绘标题栏仍没有 windowTopPadding
- 写错的样子：EntryAbility 调 setWindowLayoutFullScreen(true)，而某个 hideTitleBar 的 NavDestination 只消费 windowBottomPadding，头部没有 windowTopPadding
适用范围：接线阶段收口安全区前向引用，以及收尾阶段由入口统一开启全屏布局时
做法：
- 按沉浸式第 3 层清单逐页核对：自绘标题栏外层 .padding({ top: windowTopPadding })，底部内容 .padding({ bottom: <原值> + windowBottomPadding })；不只按 marker 注释补一处
- 开启 setWindowLayoutFullScreen(true) 前，逐个全屏 NavDestination 查自绘头部是否消费 windowTopPadding，不只看页面是否引用 windowModel；base-contracts 列的 WindowModel 字段每个都要有消费位置或写明不用的理由
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- setWindowLayoutFullScreen(isLayoutFullScreen: boolean): Promise<void>：设 true 后窗口布局忽略状态栏、导航栏，页面要自己避让（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.setWindowLayoutFullScreen）
- 设置为true表示由组件模块控制忽略状态栏、导航栏的沉浸式全屏布局：开全屏之后，没消费顶部避让的头部落到状态栏下（出处：application-window-stage.md，体验窗口沉浸式能力）
- getWindowAvoidArea(type: AvoidAreaType): AvoidArea：同族接口：取避让区，topRect 的高度就是顶部要让出的值（px）（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.getWindowAvoidArea）
- 给 toolbar 外包 Column 并补 .padding({ top: windowTopPadding })，运行期标题在场：修复后的写法（出处：卡里修好并验证过）
未核实：卡里的环境是 HarmonyOS 26.0.0，声明按本机 API 23 核实
