# onWindowStageCreate 里依赖 UIContext 的步骤，放进 loadContent 成功回调里做

审的是：代码
触发（任一种）：
- 读到：派工或沉浸式说明要求在 EntryAbility.onWindowStageCreate 里做全屏、系统栏设置，用 getWindowAvoidArea 测避让区换成 vp 写入窗口模型；写错的样子：onWindowStageCreate 中位于 windowStage.loadContent(...) 之前、或在它的回调之外同步执行的代码（含被它同步调用的辅助函数）调用了 mainWindow.getUIContext()，再用它 px2vp 换算避让区或 setKeyboardAvoidMode
适用范围：目标 EntryAbility 的 onWindowStageCreate 里安排窗口设置、避让区换算等步骤与 windowStage.loadContent 的先后时
做法：
- 凡依赖 UIContext 的步骤（window.getUIContext()、用 uiContext.px2vp 换算避让区写入窗口模型、uiContext.setKeyboardAvoidMode 等）都写进 windowStage.loadContent(path, (err) => { if (err.code) { return; } … }) 的成功分支里
- loadContent 之前只留不依赖 UIContent 的窗口调用（如 setWindowLayoutFullScreen、setWindowSystemBarProperties）；交回前逐个核对 loadContent 之前和回调之外同步执行的代码里没有 getUIContext
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getUIContext(): UIContext，@throws 1300002 - This window state is abnormal：Window 取 UIContext 的方法，声明里列了 1300002（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.getUIContext）
- loadContent(path: string, callback: AsyncCallback<void>): void：WindowStage 加载页面，异步回调返回结果；UIContent 在这之后才建立（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，WindowStage.loadContent）
- 必须在UI实例创建完成后，才可以通过窗口对象的getUIContext方法获取UIContext。建议在loadContent的成功回调中调用：官方文档对取 UIContext 时机的说明；示例注释写明在 loadContent 前调用 getUIContext 时 UI 实例未创建、存在异常（出处：arkts-global-interface.md，通过窗口对象获取UIContext对象）
- 在 loadContent 之前同步调用 mainWindow.getUIContext() 冷启动抛 1300002（Uicontent is nullptr）；移进 loadContent 成功回调后不再抛：运行期行为（出处：卡里修好并验证过）
- px2vp(value: number): number：UIContext 上的 px 转 vp，避让区数值换算用它（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.px2vp）
- setKeyboardAvoidMode(value: KeyboardAvoidMode): void：UIContext 上设键盘避让模式，同样要在取到 UIContext 之后调用（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.setKeyboardAvoidMode）
未核实：声明里 1300002 的说明是窗口未创建或已销毁，没写 UIContent 为空的情形；Uicontent is nullptr 这一说法出自卡里的运行日志
