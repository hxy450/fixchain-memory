# 沉浸式底部避让取 TYPE_SYSTEM 与导航条底部高度的较大值，并监听 avoidAreaChange

审的是：代码
触发（任一种）：
- 读到：源端按 isUsingGestures 区分手势 / 三键导航，规格写「两种导航模式下页面内容均不被导航栏遮挡」；写错的样子：windowBottomPadding = 只取 TYPE_NAVIGATION_INDICATOR 的 bottomRect.height，三键导航时底部避让为 0
适用范围：入口实现沉浸式安全区、计算页面底部避让时
做法：
- 底部 inset = max(getWindowAvoidArea(TYPE_SYSTEM).bottomRect.height, getWindowAvoidArea(TYPE_NAVIGATION_INDICATOR).bottomRect.height)，px 转 vp 后用
- 注册 win.on('avoidAreaChange', …) 重新计算，响应导航方式切换；规格要求两种导航都不遮挡时，不以 skill 模板的单一 indicator 测量代替
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- AvoidAreaType.TYPE_SYSTEM = 0、TYPE_NAVIGATION_INDICATOR = 4：三键导航栏算在 TYPE_SYSTEM 底部，手势条是 TYPE_NAVIGATION_INDICATOR（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，AvoidAreaType）
- getWindowAvoidArea(type: AvoidAreaType): AvoidArea：取避让区（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.getWindowAvoidArea）
- on(type: 'avoidAreaChange', callback: Callback<AvoidAreaOptions>): void：避让区变化回调（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.on('avoidAreaChange')）
- 底部避让取 max(TYPE_SYSTEM 底部, 手势条) 后，三键和手势导航下内容都不被遮挡：卡里修复后的取法（出处：卡里修好并验证过）
