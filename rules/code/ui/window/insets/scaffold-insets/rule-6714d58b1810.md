# 宿主壳的 tab 内容区要显式写顶部 padding 消费状态栏，只靠 layoutWeight 不算消费

审的是：代码
触发（任一种）：
- 读到：Scaffold(bottomBar = …) { padding -> … Modifier.padding(padding).consumeWindowInsets(padding) }，Scaffold 不传 topBar；写错的样子：窗口全屏、根 Navigation 已 expandSafeArea，宿主的 tab 内容区却只有 .width('100%').layoutWeight(1)，没有 .padding({ top: … })；报告仍写「宿主已统一避让」
适用范围：目标端全屏窗口加根容器 expandSafeArea、前景靠手动 padding 避让，宿主壳承载 tab 子组件时
做法：
- tab 内容区写 .padding({ top: <顶部避让值> })，用的是全局发布的那个状态栏高度（vp），底部分量照底栏处理
- Scaffold padding 的每一边逐一对到宿主代码里确有的 padding 或底栏占位，对不上就补，不只凭构思或报告
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- expandSafeArea(types?: Array<SafeAreaType>, edges?: Array<SafeAreaEdge>): T；默认 types 为 SYSTEM、CUTOUT、KEYBOARD，edges 为四边：根容器扩展到安全区后，内容从 y=0 起，前景要自己补 padding（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.expandSafeArea）
- tab 内容区加 .padding({ top: 顶部避让值 }) 后，悬浮顶栏和列表首项与安卓对齐：修好后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 顶部避让值（状态栏高度）从哪里取：目标工程里发布窗口避让值的模型或 AppStorage 键（搜 getWindowAvoidArea、on('avoidAreaChange')）；用它发布的顶部值（已换成 vp 的那一个），宿主和子页都引用同一个
