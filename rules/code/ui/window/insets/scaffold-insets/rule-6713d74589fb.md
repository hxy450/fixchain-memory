# 子页收到接了线却没用的 statusBarHeight 时，父容器没加顶部避让就在根容器 padding.top 加上它

审的是：代码
触发（任一种）：
- 读到：源端子页根布局 modifier.fillMaxSize().padding(24.dp)，modifier 由 Scaffold content 带着 innerPadding 传入；写错的样子：目标子页声明了 @Param statusBarHeight 却没用，根容器只有 .padding(24)；注释写「No statusBarsPadding on Android」
适用范围：目标父容器把状态栏高度以参数下发、要求子页自理顶部避让时
做法：
- 先看目标父容器有没有替内容区加顶部避让；没有就消费参数：根容器写 .padding({ top: this.statusBarHeight + <源端顶部 padding>, right: <源端>, bottom: <源端>, left: <源端> })
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- padding(value: Padding | Length | LocalizedPadding): T，默认 0：传 Padding 对象可逐边给值（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.padding）
- Padding = { top?: Length; right?: Length; bottom?: Length; left?: Length }：逐边的写法（出处：鸿蒙 SDK 的 ets/component/units.d.ts，Padding）
- .padding({ top: this.statusBarHeight + 24, right: 24, bottom: 24, left: 24 }) 后内容块中心与源端一致：返修的写法（24 是源端的 padding 值）（出处：卡里修好并验证过）
未核实：statusBarHeight 的单位按父页传入的口径，卡里没写明是 vp 还是 px
