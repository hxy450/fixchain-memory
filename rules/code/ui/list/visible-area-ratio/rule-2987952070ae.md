# 滚动中算可见比例时用 onVisibleAreaChange，不用 onAreaChange

审的是：代码
触发（任一种）：
- 读到：Compose Modifier.onGloballyPositioned { it.boundsInWindow() … } 在滚动中算可见高度（如 visibleHeight > height * 0.5f）；写错的样子：可见性挂在 .onAreaChange((old, new) => …) 上，用 globalPosition.y 加屏幕高算相交高度
适用范围：列表滚动中按可见比例切换自动播放、曝光等逻辑的实现
做法：
- 改用 .onVisibleAreaChange([0, 0.5, 1], (isExpanding, currentRatio) => …) 取可见比例；选离顶最近的卡前，实时查各卡窗口位置（如 componentUtils.getRectangleById(id)）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onVisibleAreaChange(ratios: Array<number>, event: VisibleAreaChangeCallback): T；VisibleAreaChangeCallback = (isExpanding: boolean, currentRatio: number) => void：按阈值回调组件可见面积占比（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onVisibleAreaChange）
- onAreaChange 仅响应由布局变化导致的组件大小、位置变化：列表滚动不是布局变化，滚动中不会触发（出处：ts-universal-component-area-change-event.md，onAreaChange）
- getRectangleById(id: string): componentUtils.ComponentInfo：UIContext 的 ComponentUtils 实时取组件的坐标和大小（模块级 componentUtils.getRectangleById 自 API 18 起废弃，改用这个）（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，ComponentUtils.getRectangleById）
- onVisibleAreaChange(ratios: Array<number>, event: VisibleAreaChangeCallback, measureFromViewport: boolean): T：同族接口：带 measureFromViewport 的重载（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onVisibleAreaChange）
- onVisibleAreaApproximateChange(options: VisibleAreaEventOptions, event: VisibleAreaChangeCallback | undefined): T：同族接口：可设回调间隔的可见面积变化（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onVisibleAreaApproximateChange）
未核实：onAreaChange 滚动时不触发依据返修报告的判定，卡里没有真机对照记录
