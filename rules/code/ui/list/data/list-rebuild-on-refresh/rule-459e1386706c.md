# 本地查询期间用 if 把内容整块换成 LoadingProgress 时，去掉这层加载遮罩

审的是：代码
触发（任一种）：
- 写错的样子：页面写成 if (加载中) { LoadingProgress() } else { 内容 }，每次本地查询（翻页、切换模式）都切到 LoadingProgress 分支，内容子树被移除再重建
适用范围：ArkUI 页面在读本地数据、很快返回的查询期间切换加载状态时
做法：
- 本地查询不切到 LoadingProgress 分支：查询期间保留现有内容子树，结果回来后只更新绑定的数据
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- if 的分支变化时，先移除此前构建的所有子组件，再执行新分支的构造函数：切到加载分支再切回来，原内容（含其中组件的状态）整块销毁重建（出处：arkts-rendering-control-ifelse.md，更新机制）
- (): LoadingProgressAttribute：LoadingProgress 的构造签名，只是一个加载动效组件（出处：鸿蒙 SDK 的 ets/component/loading_progress.d.ts，LoadingProgressInterface）
- 去掉本地查询的加载遮罩后，翻页不再反复销毁重建：修好后的行为（出处：卡里修好并验证过）
未核实：卡里没写这类查询读的是哪种本地存储
来源：1 张卡，1 个应用
