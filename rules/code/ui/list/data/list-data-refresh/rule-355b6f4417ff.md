# 源端以同 id 新值重建列表再 setList 时，ForEach 的 key 要含所有可变展示字段

审的是：代码
触发（任一种）：
- 读到：操作成功后重新请求列表并 adapter.setList(...)，新列表条目 id 不变而 count、title 等展示字段变了；写错的样子：ForEach 的 keyGenerator 只用 index 和 item.id（加个别状态位）拼键，不含 count、title 等可变展示字段
适用范围：把 RecyclerView 列表转成 ForEach / LazyForEach 渲染、数组元素是普通对象（没有用 @ObservedV2 / @Trace）时
做法：
- 写 keyGenerator 前先列出条目里所有展示字段，再查源端的刷新方式；同 id 新值重建列表的，key 必须拼上这些可变字段（如 id 加 count、title）
- 或者把条目类改成 @ObservedV2、可变字段加 @Trace，原地更新；不要把「整表重载」当作会重渲染的依据
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- ForEach(arr: Array<any>, itemGenerator: (item: any, index: number) => void, keyGenerator?: (item: any, index: number) => string)：第三个参数生成键值（出处：鸿蒙 SDK 的 ets/component/for_each.d.ts，ForEachInterface）
- 非首次渲染时键值已存在就不创建新组件，直接复用；对象项变了而键值未变，会数据变化不渲染：同 id 重建对象但 key 不变时界面不刷新（出处：arkts-rendering-control-foreach.md，非首次渲染 / 使用建议）
- LazyForEach(dataSource: IDataSource, itemGenerator: (item: any, index: number) => void, keyGenerator?: (item: any, index: number) => string)：同族接口：LazyForEach 的键值生成（出处：鸿蒙 SDK 的 ets/component/lazy_for_each.d.ts，LazyForEachInterface）
- key(keyGenerator: (item: T, index: number) => string): RepeatAttribute<T>：同族接口：Repeat 的键值生成（出处：鸿蒙 SDK 的 ets/component/repeat.d.ts，RepeatAttribute.key）
- key 扩成含 count、title 后，添加后首数 1→2 正常刷新：修复后的观察（出处：卡里修好并验证过）
针对本应用要查的：
- 源端列表的刷新方式：源工程里持有该 Adapter 的 Activity / Fragment / Dialog 的 Kotlin 或 Java 文件，找操作成功回调后的重新请求和 setList / submitList / notifyDataSetChanged；重新请求后整表替换、条目 id 不变的，就是同 id 新值重建
