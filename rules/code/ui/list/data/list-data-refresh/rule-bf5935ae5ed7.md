# 分页追加依赖 ViewModel 返回的是当页还是累计时，写前重读提供方并按当前语义追加

审的是：代码
触发（任一种）：
- 读到：编辑工具回执提示 `The file changed since your last read`，或提供方回调里 `result.list` 的赋值和注释（「当页数据，非全量累积列表」）与之前读到的不同；写错的样子：页面上拉加载写成 `dataSource.append(result.list.slice(已有条数))`，注释称 `result.list` 是累计列表，而提供方当前回传的是当页数据
适用范围：增量修复阶段，改写依赖另一文件（ViewModel、仓库层）返回语义的分页追加代码时，尤其有并发会话在改同一工程
做法：
- 写入前重新读取提供方当前版本；编辑工具提示文件自上次读取后已变更时，先重读再决定 append、reset 还是 slice。请求范围外的顺带修复，先确认是否已被别的会话处理
- 只在提供方或消费方一侧统一语义，并在两侧注释写明 list 是当页还是累计；提供方回传当页时页面写 `dataSource.append(result.list)`
- 写完用当前两端代码推演第二页：回调 list 的长度和页面已有条数组合后是否确有新增（当页 15 条再 slice(15) 就是空）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 提供方回传当页数据时，页面改回 dataSource.append(result.list) 后上拉加载正常追加：修好后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 提供方回调里的 list 是当页还是累计：目标工程里 ViewModel 或仓库层的加载方法：给回调结果 list 赋值的那一行，以及结果类型上的注释；赋的是本次请求的数据就是当页，赋的是内部累积的数组就是累计；页面据此选 append 原样或 slice
