# 源端「查看全部」页走独立分页接口并带刷新和加载更多时，目标照接，不用详情接口附带的数组

审的是：代码
触发（任一种）：
- 读到：源端列表页的 Service 接口带 `page` / `size` 参数分页取数，Screen 里有下拉刷新和 `onLoadMore` 加载更多；写错的样子：目标「查看全部」页仍取详情接口附带的少量数组，没有 `Refresh`、加载更多、重试和空态
适用范围：按「对比安卓」实现「查看全部」类列表子页面，目标端现有代码只有详情预览数据时
做法：
- 目标数据层补一个同源的分页取数方法（page、size 与源端一致），页面用 Refresh 包列表做下拉刷新，滚到底加载下一页，按条目 ID 去重
- 补首次加载、失败重试和空态三种状态
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- (value: RefreshOptions): RefreshAttribute：Refresh 下拉刷新容器（出处：鸿蒙 SDK 的 ets/component/refresh.d.ts，RefreshInterface）
- refreshing: boolean（支持 $$ 双向绑定）：RefreshOptions 里表示是否正在刷新（出处：鸿蒙 SDK 的 ets/component/refresh.d.ts，RefreshOptions.refreshing）
- onRefreshing(callback: () => void): RefreshAttribute：进入刷新状态时回调，在这里重拉第一页（出处：鸿蒙 SDK 的 ets/component/refresh.d.ts，RefreshAttribute.onRefreshing）
- 接分页接口、补首次加载/重试/空态、Refresh 与加载更多、按 ID 去重后与安卓一致：重建后的页面要素（出处：卡里修好并验证过）
针对本应用要查的：
- 源端列表页的分页接口和每页条数：源工程里该页 Screen/ViewModel 调用的 Service 接口定义（.kt），找带 page、size 参数的方法；记下接口路径和 size 取值，目标分页方法照用
