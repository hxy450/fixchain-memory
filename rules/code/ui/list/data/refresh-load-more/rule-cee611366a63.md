# PullToRefreshBox 迁 Refresh 时隐藏系统指示器、自绘指示器并抵消内容位移

审的是：代码
触发（任一种）：
- 读到：源端 `PullToRefreshBox` 用默认 M3 指示器，或规格写明了指示器外观和内容不随下拉移动；写错的样子：目标 `Refresh({ refreshing })` 没传 builder，用系统默认指示器，内容随下拉下移
适用范围：把 Compose PullToRefreshBox 迁成 ArkUI Refresh 时
做法：
- Refresh({ refreshing: $$this.<刷新状态>, builder: <空内容的 @Builder> }) 隐藏系统指示器，加 .pullDownRatio(0.5)
- .onOffsetChange((offset: number) => { this.<下拉偏移> = offset }) 记下偏移（vp），Refresh 的每个子组件加 .translate({ y: -this.<下拉偏移> }) 反向抵消位移
- 按偏移自绘 M3 指示器（箭头弧随下拉张开、带张力），叠在静止内容上方
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- builder?: CustomBuilder：自定义刷新区域显示内容；传空内容即不显示系统指示器（出处：鸿蒙 SDK 的 ets/component/refresh.d.ts，RefreshOptions.builder）
- 设置了 builder 时，下拉位移通过更新子组件相对 Refresh 的位置实现；没设 builder 时靠子组件的 translate 实现，子组件自己的 translate 不生效：要用 translate 抵消位移，必须先传 builder（出处：ts-container-refresh.md，RefreshOptions对象说明）
- pullDownRatio(ratio: Optional<number>): RefreshAttribute：下拉跟手系数，0 不跟随、1 等比例跟随，取 0–1；不设时用动态系数（出处：鸿蒙 SDK 的 ets/component/refresh.d.ts，RefreshAttribute.pullDownRatio；ts-container-refresh.md，pullDownRatio）
- onOffsetChange(callback: Callback<number>): RefreshAttribute：下拉偏移变化回调，单位 vp（出处：鸿蒙 SDK 的 ets/component/refresh.d.ts，RefreshAttribute.onOffsetChange）
- translate(value: TranslateOptions): T：子组件的平移，用 y 取负的下拉偏移抵消位移（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.translate）
- 空 builder + pullDownRatio(0.5) + 子组件 translate 反向抵消 + 自绘箭头弧指示器后，内容静止、指示器浮在上方：验证过的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 自绘指示器的尺寸、颜色和触发阈值：规格的转换决策；规格没写的，查源工程依赖的 androidx.compose.material3 版本里 PullToRefreshDefaults；尺寸、阈值 dp 换成 vp；颜色角色按应用主题解析到色值
未核实：卡里的效果在目标 API 24 上验证，本机核对用的是 API 23 的声明
