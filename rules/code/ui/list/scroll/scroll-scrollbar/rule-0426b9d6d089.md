# 复刻进页唤醒滚动条时，Scroll 到时切 BarState.Off，触摸按下再切 Auto

审的是：代码
触发（任一种）：
- 读到：源 `HorizontalScrollView` / `ScrollView` 没写 android:fadeScrollbars、android:scrollbars 等滚动条属性，窗口可见时由 initialAwakenScrollBars 先显示滚动条再淡出；写错的样子：目标 `Scroll` 进页设 `BarState.On`，setTimeout 到时切回 `BarState.Auto`（或先切 `BarState.Off`、不久再切 `BarState.Auto`）
适用范围：安卓滚动视图转成 ArkUI Scroll、用 scrollBar(BarState) 的状态切换复刻进页唤醒滚动条时
做法：
- 进页把 .scrollBar(...) 绑定的状态设为 BarState.On；唤醒时长到后切 BarState.Off 立即收起，不切 BarState.Auto
- 给 Scroll 加 .onTouch((e: TouchEvent) => { if (e.type === TouchType.Down && 状态 === BarState.Off) 状态 = BarState.Auto })，之后滚动时按 Auto 显示
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 从 BarState.On 切到 Auto、或切 Off 后不久再切 Auto，滚动条会重新显示约 1.3–2s，进页约 3s 才消失；只切 Off 立即消失：Auto 会按自己的淡出节奏重新显示一次，所以唤醒结束要切 Off（出处：卡里修好并验证过）
- BarState.Off 不显示；BarState.Auto 按需显示（触摸时显示，2 秒后消失）；BarState.On 常驻：三种滚动条状态（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，BarState）
- scrollBar(barState: BarState): ScrollAttribute，默认 BarState.Auto：Scroll 的滚动条状态（出处：鸿蒙 SDK 的 ets/component/scroll.d.ts，ScrollAttribute.scrollBar）
- onTouch(event: (event: TouchEvent) => void): T；TouchType.Down 是手指按下：按下时把 Off 切回 Auto 用的事件（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onTouch；ets/component/enums.d.ts，TouchType.Down）
- awakenScrollBars(mScrollCache.scrollBarDefaultDelayBeforeFade * 4, true)；scrollBarDefaultDelayBeforeFade 没设时取 ViewConfiguration 的 SCROLL_BAR_DEFAULT_DELAY = 300：源端进页唤醒的显示时长是 scrollbarDefaultDelayBeforeFade 的 4 倍（出处：android.view.View#initialAwakenScrollBars、android.view.View#initializeScrollbarsInternal、android.view.ViewConfiguration）
- scrollBar(value: BarState): ListAttribute：同族接口：List 的滚动条状态（卡里只实测了 Scroll）（出处：鸿蒙 SDK 的 ets/component/list.d.ts，ListAttribute.scrollBar）
- scrollBar(value: BarState): GridAttribute：同族接口：Grid 的滚动条状态（卡里只实测了 Scroll）（出处：鸿蒙 SDK 的 ets/component/grid.d.ts，GridAttribute.scrollBar）
针对本应用要查的：
- 进页唤醒的显示时长：源布局里这个滚动视图的 android:scrollbarDefaultDelayBeforeFade；没写时顺着 Activity 主题的 parent 链到 Android SDK 平台资源 data/res/values/themes_*.xml 找同名项（按应用的 compileSdk 取平台）；读出的毫秒数乘 4 就是切 Off 的时刻；主题也没设时按 300×4=1200ms。例：Theme.Material.Light 设为 400，约 1600ms
未核实：唤醒时长：卡里按 300ms×4=1200ms 写，主题设了 scrollbarDefaultDelayBeforeFade 时（如 Material 为 400）源端约 1600ms，机上取样区分不了两者；List、Grid 用同一 BarState 切换时是否同样重新显示，卡里只实测了 Scroll（HarmonyOS 6.1.0）
