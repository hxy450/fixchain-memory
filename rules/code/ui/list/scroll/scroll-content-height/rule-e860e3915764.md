# 源内容区顶部流式、目标是 Scroll 包 Column 时，子 Column 加 minHeight 和顶部对齐

审的是：代码
触发（任一种）：
- 读到：源端内容区是 IonContent（ion-content），内容从顶部往下流式排布；写错的样子：目标 Scroll() { Column() { … } } 的子 Column 只有 width、padding、alignItems(HorizontalAlign.Center)，没有 constraintSize({ minHeight: '100%' }) 和 justifyContent(FlexAlign.Start)，内容短于一屏时整体被垂直居中
适用范围：源内容区顶部流式排布、目标用 Scroll 包一个 Column 承载，内容可能短于视口时
做法：
- 给 Scroll 的子 Column 写 .constraintSize({ minHeight: '100%' }).justifyContent(FlexAlign.Start)（或等价的顶部对齐）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- constraintSize(value: ConstraintSizeOptions): T：组件的尺寸约束，minHeight 写在 ConstraintSizeOptions 里（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.constraintSize）
- minHeight?: Length：ConstraintSizeOptions 的最小高度（出处：鸿蒙 SDK 的 ets/component/units.d.ts，ConstraintSizeOptions.minHeight）
- justifyContent(value: FlexAlign): ColumnAttribute：Column 主轴（竖直）方向的对齐（出处：鸿蒙 SDK 的 ets/component/column.d.ts，ColumnAttribute.justifyContent）
- FlexAlign.Start：子元素在主轴起始端对齐，依次排下去（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，FlexAlign.Start）
- 内容 Column 加 constraintSize({minHeight:'100%'}) + justifyContent(Start) 后，短内容从顶部开始排：卡里的修法（出处：卡里修好并验证过）
未核实：Scroll 子组件短于视口时被居中的原因，声明和文档副本里都没找到说明；修法出自卡里实测
