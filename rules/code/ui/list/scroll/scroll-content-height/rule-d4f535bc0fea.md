# 固定高度键盘配 layoutWeight 中间区时，加条件行前确认有空间，否则改滚动或固定位置

审的是：代码
触发（任一种）：
- 写错的样子：固定高度的键盘和 `layoutWeight(1)` 的中间区放在同一个 `Column` 里，中间区末尾追加条件行（`if (...) { Text(...) }`），中间区没有 `Scroll`
适用范围：整页弹层或表单页由「固定高度键盘 + layoutWeight 中间内容区」组成、中间区条目数随数据变化时
做法：
- 按条目最多时（如分类最多占几行）估算中间区内容高度，新增条件行前确认中间区还有余量
- 余量不够时把中间区内容包进 `Scroll() { Column() { … } }`，或把条件行移到中间区外的固定位置
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- layoutWeight(value: number | string): T，默认 0：按权重在父容器（Row、Column、Flex）主轴上分配剩余空间；中间区高度是容器减去键盘等固定部分后剩下的（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.layoutWeight）
- (scroller?: Scroller): ScrollAttribute：Scroll 容器的构造，内容超出时可滚动（出处：鸿蒙 SDK 的 ets/component/scroll.d.ts，ScrollInterface）
- 条目占两行后中间区下沿已贴着键盘，没有余量，追加的行落到键盘区域之下：条目数多时中间区放不下新行（出处：卡里修好并验证过）
针对本应用要查的：
- 中间区在条目最多时的内容高度：源端或目标端的数据定义里条目最多的那一类（如分类列表），以及目标页里每行的高度、间距和键盘的固定高度；条目行数乘行高加其他行，与屏高减去键盘、标题等固定高度比较；不够就改成可滚动
未核实：错误行被键盘遮住是按截图的布局余量和代码结构推定的，没有直接截图
