# 横向列表的 contentPadding 写成 contentStart/EndOffset，不写 padding

审的是：代码
触发（任一种）：
- 读到：Compose 的 LazyRow(contentPadding = PaddingValues(start = …, end = …))；写错的样子：对应的横向 List（listDirection(Axis.Horizontal)）写成 .padding({ left/start: …, right/end: … })，项滚到内距处被裁切
适用范围：Compose 滚动列表用 contentPadding 给首尾项留白、迁成 ArkUI List 时
做法：
- 写成 List(...).contentStartOffset(<start>).contentEndOffset(<end>)，PaddingValues 的 start 对 contentStartOffset、end 对 contentEndOffset，dp 数值照搬为 vp
- 逐处对照源码是 contentPadding 还是 Modifier.padding：只有后者才写 List 的 .padding；看出裁切差异后不以「差异小」「更简单」降级
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- contentStartOffset(offset: number | Resource): ListAttribute；contentEndOffset(offset: number | Resource): ListAttribute：内容首尾到列表显示区边界的偏移，默认 0，单位 vp（这个重载 @since 22；更早的 contentStartOffset(value: number) 从 API 11/12 起有）（出处：鸿蒙 SDK 的 ets/component/list.d.ts，ListAttribute.contentStartOffset、ListAttribute.contentEndOffset）
- List.padding 缩小视口，项在内距边界被裁切；contentPadding 的项能滚到屏边；改成 contentStartOffset / contentEndOffset 后与源端一致：两种写法的差别（出处：卡里修好并验证过）
- contentStartOffset(offset: number | Resource): T；contentEndOffset(offset: number | Resource): T：同族接口：ScrollableCommonMethod 上的同名属性（@since 22），Grid、WaterFlow 等滚动容器共用（出处：鸿蒙 SDK 的 ets/component/common.d.ts，ScrollableCommonMethod.contentStartOffset）
