# 源端工厂按配置项 type 逐个创建 Fragment 时，目标逐行显式分派到专页，按配置顺序放在同一列表

审的是：代码
触发（任一种）：
- 读到：源端编辑 Fragment 遍历配置列表，经工厂按每项的 type 用 when 分支各自 create 对应 Fragment，按顺序加入同一个容器；外观类（背景、文字色、边框）也在同一个 when 里；写错的样子：目标用一个通用控件（Toggle / Slider / TextInput / Radio）按类型分支统一渲染多数类型，已有专页的类型没接专页；外观类编辑器放在列表外、提前显示，或和列表里的同类项重复
适用范围：把源端按配置逐项派发 Fragment 的编辑区迁成 ArkTS 列表，且目标工程已有逐类型专页时
做法：
- 把工厂的 type→Fragment 表逐行落成显式分派：有 ArkTS 专页的类型直接接专页；外观类也经同一列表的插槽，按配置项序号在列表里渲染，不在列表外提前放
- 接手已有的通用控件骨架时先对照工厂表，骨架已偏离逐类型分派就替换，不把「补齐全部类型」做成给通用控件加分支
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 按工厂表把各类型接到现有专页、外观项经列表插槽按配置序号渲染后，顺序和分派与源端一致：逐行显式分派是修好并保留下来的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 每个 type 对应哪个源 Fragment、目标有没有对应专页：源工程里创建编辑 Fragment 的工厂类（Kotlin / Java 里按 type 的 when 或 switch），以及目标工程 pages 目录下按源 Fragment 命名的专页；逐个 case 列出 type → 源 Fragment → 目标专页，没有专页的记下来
