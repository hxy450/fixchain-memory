# 为配置驱动的编辑项列表写用例时，按源端配置断言每项都在且顺序一致，子集只按源端实际移除的项

审的是：代码
触发（任一种）：
- 读到：源码按配置列表逐项由 factory 创建 Fragment，另有子模块场景按固定的几个 type 从列表里移除；写错的样子：测试没有「配置含多个 type、未选中子模块时这些项都在列表里、顺序与配置一致」的 expect(...) 断言，或子模块用例断言的移除项比源端多
适用范围：为按配置生成的编辑项列表写契约或单元测试时
做法：
- 补根文档用例：配置为两项以上、未选中子模块时，断言每项都在列表中且顺序与配置一致；子模块用例只按源端代码实际移除的那些 type 断言
针对本应用要查的：
- 子模块场景下源端从列表里移除的 type：源工程里子模块编辑项的 bean 或构造列表的那段代码；读出被移除的 type 名单，子模块用例只断言这些项不在
