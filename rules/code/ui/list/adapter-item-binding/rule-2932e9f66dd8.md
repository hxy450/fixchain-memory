# 同一选项在列表和主预览取自不同资源时分别映射，按尺寸选资源只落到主预览

审的是：代码
触发（任一种）：
- 读到：列表项 Holder 的 onBindView 里 setBackgroundResource(res)，res 是固定的 R.drawable；主预览的 Drawable 另按组件尺寸经 getUrl 拼路径加载 .webp；写错的样子：列表缩略图的 Image($rawfile(...)) 改成调和主预览相同的按尺寸取资源的函数
适用范围：目标端同时有选项列表和主预览、同一个选项 ID 在源端两处取自不同资源族时
做法：
- 列表缩略图按源端列表 Holder 的绑定迁：setBackgroundResource 的 res 指向的那张固定 drawable；主预览按它的 Drawable 加载路径（getUrl 里按尺寸拼的路径）迁
- 「按组件尺寸选资源」只写在实际绘制在组件上的那一层（主预览叠加层），不扩展到列表缩略图
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- setBackgroundResource(@DrawableRes int resid)：Set the background to a given resource：列表项的缩略图就是 res 指向的那张 drawable（出处：android.view.View#setBackgroundResource）
- 列表改回取固定 PNG（与安卓原图哈希一致），主预览仍用按尺寸的 WebP：两层各用各的资源族（出处：卡里修好并验证过）
针对本应用要查的：
- 同一选项 ID 在列表和主预览各用哪套资源：源工程里列表 Holder 的 onBindView（看 setBackgroundResource 的参数）和主预览 Drawable 的加载方法（看拼路径的 getUrl 一类方法）；列表取 res 对应的 drawable 文件；主预览取路径模板里随尺寸变的那一段，分别对应到目标端两处
