# ItemDecoration 的项偏移落到容器 padding 或 Grid gap，不转成外 margin

审的是：代码
触发（任一种）：
- 读到：RecyclerView 挂了 ItemDecoration，getItemOffsets 给每项的 outRect 设偏移；RecyclerView 自身没有 layout_margin；写错的样子：目标 Grid 或 List 的链上写了 .margin(N) 作外边距，并配 .width('100%')
适用范围：把 RecyclerView 加 ItemDecoration 的项间距迁成 ArkUI Grid 或 List 时
做法：
- 源端的项偏移落到容器的 .padding(...) 或 Grid 的 .columnsGap(...) / .rowsGap(...)，不写成 Grid、List 外面的 .margin(...)
- 容器宽仍是 .width('100%') 时，链上不再另加水平 .margin；确需外边距时改成 .width('calc(100% - Nvp)')，N 是两侧 margin 之和
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getItemOffsets 设的偏移在 RecyclerView 边界之内，不扩大列表宽度：源端的项偏移是内部间距，不是列表的外边距（出处：卡里修好并验证过）
- columnsGap(value: Length): GridAttribute，默认 0，单位 vp：Grid 的列间距（出处：鸿蒙 SDK 的 ets/component/grid.d.ts，GridAttribute.columnsGap）
- rowsGap(value: Length): GridAttribute，默认 0，单位 vp：Grid 的行间距（出处：鸿蒙 SDK 的 ets/component/grid.d.ts，GridAttribute.rowsGap）
- padding(value: Padding | Length | LocalizedPadding): T，默认 0：容器的内边距（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.padding）
针对本应用要查的：
- 每项偏移的四个方向各是多少：源工程里这个 ItemDecoration 子类的 getItemOffsets；读出 outRect 的 left/top/right/bottom 各设了什么值，再分到容器 padding（外沿）和 gap（项与项之间）
未核实：修复时这一处同样改成了 calc(100% - Nvp)；padding / gap 的写法卡里没有上机验证；四向同一偏移时相邻两项实际间距是两倍偏移，padding 与 gap 各取多少卡里没写
