# 网格里不同跨度的卡片要同行等高时，按实际列宽推导宽卡 aspectRatio，不套组件原生宽高比

审的是：代码
触发（任一种）：
- 读到：源列表用 12 列网格按卡片规格分配 spanCount（窄卡占 4、宽卡占 8），常量里有组件自身内容尺寸（如宽卡 334.75 × 158）；参考截图里同一行的窄卡和宽卡外框等高；写错的样子：宽卡外框写成 .aspectRatio(原生宽 / 原生高)，套在百分比列宽且两侧有固定内边距的单元上，宽卡比同行窄卡矮
适用范围：首页等网格列表里不同跨度的卡片同一行排列、参考截图显示同行等高时
做法：
- 用 onAreaChange 取网格实际宽度，扣除列表留边得到列宽；窄卡外框高 = 窄卡单元宽 − 两侧内边距（方形时），宽卡写 .aspectRatio((宽卡单元宽 − 两侧内边距) ÷ 窄卡外框高)，例：宽卡跨两列、网格留边 6、两侧内边距共 6 时为 (2·列宽 − 6) / (列宽 − 6)
- 组件原生尺寸只用于卡片内部内容缩放，不直接当网格单元的 aspectRatio
- 输出前至少用两种视口宽度（如 360vp、392vp）代入列宽、内边距和 aspectRatio，算出窄卡和宽卡的外框高度，二者应相等
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- aspectRatio(value: number): T，aspectRatio = width / height：宽高比按组件自身宽度算高度，宽度已扣内边距时比例也要按扣后的宽度算（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.aspectRatio；ts-universal-attributes-layout-constraints.md，aspectRatio）
- onAreaChange(event: (oldValue: Area, newValue: Area) => void): T，Area.width 单位 vp：取网格实际宽度，屏宽变化时重算比例（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.onAreaChange；ts-types.md，Area）
- 由 onAreaChange 取网格宽度、扣留边和内边距后用 (2·列宽 − 6) / (列宽 − 6) 作宽卡比例，多屏宽下与窄卡等高：修好的写法；先改成固定 2 不够（出处：卡里修好并验证过）
针对本应用要查的：
- 网格留边、卡片内边距和各规格的列跨度：源工程列表布局 XML 的 padding / item 间距，以及设置 GridLayoutManager span 的代码；目标页面里网格和卡片的 padding；代入「宽卡单元宽 − 两侧内边距」和「窄卡外框高」算出比例
