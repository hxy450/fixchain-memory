# ItemTouchHelper 左右滑删除用 PanGesture 跟手加阈值和回弹，不用 SwipeGesture

审的是：代码
触发（任一种）：
- 读到：源 `ItemTouchHelper`（`SimpleCallback` 左右滑，`onSwiped` 里删除）；写错的样子：`ListItem` 上挂 `SwipeGesture({ direction: SwipeDirection.Horizontal }).onAction(...)`，识别即删除：没有跟手位移、半宽或甩动阈值、回弹
适用范围：把 RecyclerView 上 ItemTouchHelper 的滑动删除迁到 ArkUI List 行时
做法：
- 先读源 Callback 子类的方法体，看 getSwipeThreshold、getSwipeEscapeVelocity 有没有覆写；映射参考里「ItemTouchHelper → SwipeGesture」只当组件候选
- 行上挂 PanGesture：onActionUpdate 里 translate({ x: event.offsetX }) 跟手；onActionEnd 里 |offsetX| ≥ 滑出阈值×行宽 或 |event.velocityX| ≥ 甩动速度时滑出并删除，否则动画回弹到 0
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- PanGesture 跟手 + 0.5 行宽滑出阈值 + 120dp/s 甩动 + 回弹：返修后的写法，对应 ItemTouchHelper 没覆写时的行为（出处：卡里修好并验证过）
- item_touch_helper_swipe_escape_velocity = 120dp；item_touch_helper_swipe_escape_max_velocity = 800dp：ItemTouchHelper 默认的甩动速度门槛和上限（按秒计）（出处：androidx.recyclerview:recyclerview 包内 res/values/values.xml，item_touch_helper_swipe_escape_velocity（按应用依赖的版本））
- GestureEvent.velocityX：x 轴速度，从左往右为正，单位 vp/s：和 120dp/s 门槛直接比较（dp 与 vp 同为密度无关单位）（出处：ts-gesture-common.md，GestureEvent对象说明）
- SwipeGesture 的 onAction 在识别成功时触发一次；speed 默认 100VP/s：识别器没有跟手和回弹，不能承接 ItemTouchHelper 的行为（出处：ts-basic-gestures-swipegesture.md，onAction）
针对本应用要查的：
- 源端有没有改滑出阈值和甩动速度：源工程里 ItemTouchHelper.Callback / SimpleCallback 子类的 getSwipeThreshold、getSwipeEscapeVelocity、getSwipeVelocityThreshold；覆写了按返回值写；没覆写按默认（0.5 行宽、120dp/s）
未核实：卡里环境是 API 24，本机按 API 23 的声明和文档核实
