# Tab 或 Swiper 承载的子页只用 @Consumer 注入的根栈，onReady 不改写栈

审的是：代码
触发（任一种）：
- 读到：源端 Fragment 由 ViewPager 或底部 Tab 承载；规格标「页面类型 fragment（Tab 判定）」，父页的 Swiper / Tabs 预留了这个 Tab 槽位；写错的样子：子页声明 @Consumer('navPathStack') navPathStack 的同时，在 .onReady((context) => { this.navPathStack = context.pathStack }) 里覆盖它
适用范围：把 Tab、ViewPager 承载的 Fragment 转成嵌入父页 Swiper / Tabs 的 ArkUI 子组件时
做法：
- 导航栈只用 @Consumer('navPathStack') 注入的根栈；onReady 里只读 context.pathInfo.param，删掉 this.navPathStack = context.pathStack
- 照搬已有页面前先分清它是 pushPathByName 压栈的 NavDestination 还是嵌入 Swiper / Tabs 的子组件；压栈页的 onReady 栈赋值、安全区模板里的 ctx.pathStack 赋值都不搬到 Tab 子页
- 页面接入父页 Swiper / Tabs 后，在被嵌入的子页里搜 pathStack = context.pathStack，应无命中
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- NavDestinationContext.pathStack: NavPathStack：当前 NavDestination 所在的页面栈；子页外壳是嵌套的 NavDestination 时拿到的是嵌套的栈，不是根栈（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationContext.pathStack）
- NavDestinationContext.pathInfo: NavPathInfo：取页面参数用这一项（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationContext.pathInfo）
- onReady(callback: Callback<NavDestinationContext>): NavDestinationAttribute：NavDestination 构建子组件前的回调（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onReady）
- 删除两页 onReady 中的覆盖、保留 @Consumer 注入栈后，点击跳转恢复、pushPathByName is not callable 不再出现：覆盖后的栈不是根栈（出处：卡里修好并验证过）
