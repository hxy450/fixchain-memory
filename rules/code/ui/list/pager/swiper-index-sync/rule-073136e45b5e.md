# 源端延后 setCurrentItem 定初始页时，Swiper 用 .index 绑状态，不调 changeIndex

审的是：代码
触发（任一种）：
- 读到：源端装好数据后用 `view.post { … setCurrentItem(index, false) }`（或 `doOnLayout`）延后定位 `ViewPager2` 的初始页；写错的样子：目标在 `onReady` 或 `aboutToAppear` 里给列表赋值后立即调用 `swiperController.changeIndex(index, false)`，而 `Swiper` 在列表非空的 if/else 分支里才创建；声明的初始页状态没有绑到 `.index(...)`
适用范围：把安卓分页容器的初始页定位迁成 ArkUI Swiper，初始页来自路由参数时
做法：
- 在读路由参数的地方把初始页写进响应式状态（`this.startIndex = 参数`，和列表赋值放在一起），Swiper 写 `.index(this.startIndex)` 承接
- 删掉同一回调里立即调用的 `changeIndex`：目标容器依赖同一回调里刚赋值的数据才创建时，它的 controller 此时还没生效
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- index(value: number): SwiperAttribute；默认 0，小于 0 或不小于子组件数时按 0：Swiper 当前显示项的声明式绑定（出处：鸿蒙 SDK 的 ets/component/swiper.d.ts，SwiperAttribute.index）
- changeIndex(index: number, useAnimation?: boolean)（@since 12）；changeIndex(index: number, animationMode?: SwiperAnimationMode | boolean)（@since 15）：SwiperController 的命令式跳转（出处：鸿蒙 SDK 的 ets/component/swiper.d.ts，SwiperController.changeIndex）
- Swiper 挂载前调用的 changeIndex 被静默丢弃；改成 .index(startIndex) 并在 onReady 写入 startIndex 后，从任一项进入都定位到点击项：修好前后的表现（出处：卡里修好并验证过）
- changeIndex(value: number): void：同族接口：TabsController 的命令式切换，同样要求 Tabs 已挂载（出处：鸿蒙 SDK 的 ets/component/tabs.d.ts，TabsController.changeIndex）
- changeIndex(index: number, useAnimation?: boolean): void：同族接口：IndicatorComponentController 的命令式跳转（出处：鸿蒙 SDK 的 ets/component/indicatorcomponent.d.ts，IndicatorComponentController.changeIndex）
未核实：changeIndex 在 Swiper 挂载前被丢弃这一点文档里没有说明，依据卡里的真机实证
