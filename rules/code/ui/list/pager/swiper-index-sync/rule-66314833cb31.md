# 源端「装载后默认选中首项」迁成一次性初始化，@Param 数组更新只按 selectedIndex 同步

审的是：代码
触发（任一种）：
- 读到：源码只在 initData 一次性取完分类数据后 selectItem(0) 并回调父 ViewPager，翻页时父级只调 setSelect(position) 同步选中；写错的样子：子组件监听 @Param 数组的 @Monitor 回调里先把初始化标志置 false，再走「初始选中」，固定选中第 0 项并 @Event 回调父级
适用范围：把安卓 Tab 列表的默认选中与父分页联动迁成 ArkUI V2 子组件（@Param 数组、selectedIndex，@Event 回调父 Swiper）时
做法：
- 默认选中写成一次性初始化：只在首个非空数组到达且没有有效选中时回调一次；初始项优先取在范围内的 selectedIndex
- @Param 数组后续更新只按 selectedIndex 同步高亮，不重置初始化标志，不硬编码回调第 0 项
- 按父组件每次渲染都重建数组的情形自检：设 selectedIndex = 1 后替换数组引用，确认不会回调第 0 项
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- @Monitor 判断属性是否变化用严格相等（===），不相等就触发回调：父组件每次渲染用 .map(...) 新建数组时，即使内容相同也会触发 @Monitor（出处：arkts-new-monitor.md，概述）
- @Param 与父组件传入的数据源同步，数据源变化时把修改同步给子组件：父组件改 selectedIndex 或重建数组都会进到子组件（出处：arkts-new-param.md，变量传递）
- 删掉数组更新时的重新初始化、selectedIndex 在范围内时保持初始化标志为 true 只同步当前索引后，横滑不再被拉回首页：一次性初始化的做法（出处：卡里修好并验证过）
未核实：卡里工程的 compatible SDK 是 6.1.0(23)、target 26.0.0，本机按 API 23 核对
