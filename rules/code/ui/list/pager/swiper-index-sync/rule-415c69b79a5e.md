# 源端首播靠 onPageSelected 时，目标对初始项显式延迟播放并与 onChange 去重

审的是：代码
触发（任一种）：
- 读到：源端 `setCurrentItem(index, false)` 后由 `onPageSelected` 里 `postDelayed(…)` 启动当前页播放；写错的样子：目标只在 `Swiper` 的 `onChange` 里启动播放，初始项靠命令式定位去间接触发 `onChange`，或初始项另起一个不和 `onChange` 去重的播放
适用范围：把安卓分页容器的选页即播放迁成 ArkUI Swiper，初始页不是第 0 项时
做法：
- 对初始项显式调度和源端相同延迟的播放：`this.playDelayId = setTimeout(() => this.startPlay(startIndex), 源端延迟)`
- `onChange` 里的延迟播放共用同一个句柄：调度前先 `clearTimeout(this.playDelayId)`，避免同一项播两次
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onChange(event: Callback<number>): SwiperAttribute：当前显示项索引变化时回调；动画引起的变化在动画结束时触发（出处：鸿蒙 SDK 的 ets/component/swiper.d.ts，SwiperAttribute.onChange）
- 首播改为统一的延迟 startPlay(videoIndex)，与 onChange 共用延迟句柄去重：修好后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端选页后启动播放的延迟：源工程分页容器的 onPageSelected 回调里的 postDelayed / Handler 调用；读出延迟毫秒数，初始项和 onChange 都用这个值
