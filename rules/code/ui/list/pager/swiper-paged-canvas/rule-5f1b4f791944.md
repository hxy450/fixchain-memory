# 相邻页数据按源端先合并再一次提交，拖动中只写缓存，Swiper 落定后再替换

审的是：代码
触发（任一种）：
- 读到：源端并发查询当前、上、下月，await 后合并成 map，再一次调用 setEventData 一类的提交方法；写错的样子：ArkTS 在 onGestureSwipe 里触发预加载，结果在拖动中直接写进 Canvas 绑定的状态，落定后 onChange 又刷新一次
适用范围：自绘翻页视图加载和提交相邻页数据时
做法：
- 并发查询当前页和前后页，合并后一次提交；拖动中（onGestureSwipe）只写缓存，Swiper 动画结束（onAnimationEnd）后一次替换可见数据
- 查询期间保留旧数据，不先清空
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onAnimationEnd(event: OnSwiperAnimationEndCallback): SwiperAttribute，切换动画结束时触发：落定的时机（出处：鸿蒙 SDK 的 ets/component/swiper.d.ts，SwiperAttribute.onAnimationEnd）
- OnSwiperAnimationEndCallback = (index: number, extraInfo: SwiperAnimationEvent) => void：回调参数（出处：鸿蒙 SDK 的 ets/component/swiper.d.ts，OnSwiperAnimationEndCallback）
- 拖动中写入可见数据会让移动中的 Canvas 重绘而闪烁；改成落定后一次提交后不再闪：修复后的观察（出处：卡里修好并验证过）
