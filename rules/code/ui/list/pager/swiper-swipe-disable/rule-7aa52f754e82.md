# 承载可交互子页的容器设 enabled 或 hitTestBehavior 时，按作用于整个子树来选取值

审的是：代码
触发（任一种）：
- 读到：源端 ViewPager2 等容器承载多个可交互的 Fragment，容器本身只限制某个行为（如滑动）；写错的样子：Swiper、Tabs、Stack 等容器上写了 .enabled(false) 或会挡住子节点的 .hitTestBehavior(...)，放进去的子页控件点不动
适用范围：目标端容器组件里放着要响应点击的子页或控件时
做法：
- 子页要可交互时，容器上不写 .enabled(false)；只想关掉容器自身某个行为时用它的专门属性（Swiper 禁滑用 .disableSwipe(true)）
- 容器上要写 hitTestBehavior 时，不选会挡住子节点的 HitTestMode.Block 或 HitTestMode.BLOCK_DESCENDANTS
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Swiper 上 .enabled(false) 让全部子页都不可点击：enabled 作用于容器的整个子树（出处：卡里修好并验证过）
- hitTestBehavior(value: HitTestMode): T：组件在命中测试中的行为，默认 HitTestMode.Default（自身和子节点都响应）（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.hitTestBehavior）
- HitTestMode.Block：自身响应，挡住子节点和被遮住的其他节点：容器设成 Block 时子页点不到（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，HitTestMode.Block）
- HitTestMode.BLOCK_DESCENDANTS（@since 20）：自身和全部后代都不响应：容器设成它时整棵子树点不到（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，HitTestMode.BLOCK_DESCENDANTS）
- 设置组件是否可交互。当未设置enabled时，组件默认可交互。：不写 enabled 就是可交互（出处：ts-universal-attributes-enable.md，enabled）
未核实：卡里的行为出自 API 24（6.1.1），本机用 API 23 的声明核实
