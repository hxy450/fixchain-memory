# 多列 WaterFlow 的每个 FlowItem 都写 .width('100%')，再用 padding 表达间距

审的是：代码
触发（任一种）：
- 读到：源端多列瀑布流：LazyVerticalStaggeredGrid(StaggeredGridCells.Adaptive(...) / Fixed(...))，或 RecyclerView 配 StaggeredGridLayoutManager；项上带 Modifier.padding(horizontal = ...)，头尾项用 StaggeredGridItemSpan.FullLine；写错的样子：WaterFlow 的 columnsTemplate 在某个断点下是两列及以上，FlowItem() {...} 的修饰链里没有 .width('100%')（只有 .padding(...) / .margin(...)），里面卡片根节点写的是 .width('100%')
适用范围：把多列瀑布流迁成 WaterFlow + FlowItem、columnsTemplate 在至少一个窗口宽度下为两列及以上时的每个 FlowItem，含头部整块和尾部占位
做法：
- 每个 FlowItem 写成 FlowItem() { <卡片> }.width('100%').padding({ left: <源端水平 padding>, right: <源端水平 padding> })：先显式撑满列宽，再在 FlowItem 上加 padding 表达源端项间距；头部整块、尾部占位的 FlowItem 同样补 .width('100%')
- 不要假定列宽会自动成为子组件 .width('100%') 的参照；FlowItem 没写宽度时，子组件的百分比宽度会按瀑布流整宽测量
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- FlowItem 未写宽度、子卡片根节点 .width('100%') 时，卡片按瀑布流整宽测量（两列时是列宽的约 2 倍），内容在列边界被裁、第二列超出窗口；FlowItem 补 .width('100%') 后卡片收回列内：修复前后在多列窗口下量到的布局宽度（出处：卡里修好并验证过）
- declare class FlowItemAttribute extends CommonMethod<FlowItemAttribute> {}：FlowItem 没有自己的属性，宽度、padding 都用 CommonMethod 的通用属性（出处：鸿蒙 SDK 的 ets/component/flow_item.d.ts，FlowItemAttribute）
- width(widthValue: Length | LayoutPolicy): T：通用宽度；不写时组件取装下内容所需的宽度，比父容器宽时画出父容器范围（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.width）
- 百分比尺寸参考最近设置了固定大小的祖先节点的尺寸：FlowItem 没写宽度时，卡片的 width('100%') 落到更上层定了宽的祖先（如 WaterFlow 整宽），不是列宽（出处：ts-universal-attributes-size.md，尺寸设置（开头的说明））
- columnsTemplate(value: string | ItemFillPolicy): WaterFlowAttribute，默认 '1fr'（单列）：WaterFlow 的列数；写成 '1fr 1fr' 或按断点的 ItemFillPolicy 时才出现多列（出处：鸿蒙 SDK 的 ets/component/water_flow.d.ts，WaterFlowAttribute.columnsTemplate）
- FlowItem() { Column() {...} }.width('100%').height(...)，WaterFlow 上 .columnsTemplate('1fr 1fr')：官方示例里多列瀑布流的 FlowItem 也显式写 .width('100%')（出处：ts-container-waterflow.md，示例1（使用基本瀑布流））
未核实：文档只有「百分比参考最近定了尺寸的祖先」的通用说明，没有专讲 FlowItem；机制判断出自修复前后实测的布局宽度；卡里的观察出自 HarmonyOS 6.1.1(24)，本机核对声明用的是 API 23
