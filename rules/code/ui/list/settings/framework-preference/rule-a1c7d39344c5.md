# onPreferenceChange 返回 true 后再验密的开关，目标端先落值再验密，取消不回滚

审的是：代码
触发（任一种）：
- 读到：`setOnPreferenceChangeListener` 里调验密弹窗，`onPreferenceChange` 返回 `true`，验密成功再 `setChecked(newValue)`；写错的样子：目标开关先回滚视觉态（如 `revertSwitch`），注释写「确认通过后才 setChecked」「SUCCEED 才落值」，验密失败或取消时开关回弹
适用范围：迁移设置页里带验证回调的开关联动（Switch / Toggle）
做法：
- Toggle 的 onChange 里先把新值写进状态并持久化，再打开验密弹窗
- 验密成功时再设一次同值；失败、取消不回滚
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onPreferenceChange 在状态更新和持久化之前调用；返回 true 表示用新值更新 Preference 的状态：返回 true 即新值立即生效并落盘，之后的验密只是补偿（出处：android.preference.Preference.OnPreferenceChangeListener#onPreferenceChange）
- return true 先生效落盘，SUCCEED 再 setChecked(同值)，失败、取消不回滚：返修后保留的写法（出处：卡里修好并验证过）
