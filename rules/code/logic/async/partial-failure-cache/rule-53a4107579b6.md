# 源端多个请求各自 launch、各自更新时，目标页按区块分别判成功失败，不用 a 或 b 为空判整页错误

审的是：代码
触发（任一种）：
- 读到：源 ViewModel 里几个请求各自 `launch`，各自只在 `Result.Success` 时写自己的 `LiveData`，Activity 各自 observe；规格写「任一请求失败保留其他已成功区块，不清空整页」；写错的样子：目标页面用 `=== null ||` 把两支结果连起来，任一为空就整页 `ERROR`
适用范围：数据接线阶段，源详情页由多个独立请求分别填充不同区块时
做法：
- 逐个列出源页的每个请求和它的 observer；目标每个区块有自己的结果和状态，分别赋值，某支失败只让该区块显示错误或空态，其他已成功的区块照常显示
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 两支分别赋值、独立降级后，单支失败不再清空整页：修复后的判定方式（出处：卡里修好并验证过）
针对本应用要查的：
- 源详情页由哪几个请求分别填充哪些区块：源工程里该详情页的 ViewModel（.kt）中各个 launch 块，以及 Activity/Fragment 里对各 LiveData 的 observe；每个 launch 对应一个区块，记下它成功时写哪个 LiveData、失败时怎么处理，目标逐个区块照写
