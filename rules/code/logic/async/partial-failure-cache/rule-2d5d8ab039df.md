# 源页面先用缓存填充再请求详情时，组件的详情失败分支保留内容加轻提示，不切整页 ERROR

审的是：代码
触发（任一种）：
- 读到：源 Fragment 先读缓存填充列表和趋势，再请求单日详情；ViewModel 只在 Result.Success 时替换数据、失败不动已有内容；决策台账写「网络失败优先读有效缓存、禁止白屏」；写错的样子：组件把网关的 FAILED 和异常一律映射成整页 ERROR 态，build 里只渲染错误文字加重试，日期条和各模块只来自网关成功结果
适用范围：页面内容以缓存为底、详情接口只做补充的界面组件，设计加载失败分支时
做法：
- 失败分支不只设 CONTENT / ERROR 两态：详情失败时保留已有或缓存内容，只做轻提示；整页 ERROR 只留给缺城市这类不可恢复的前置条件
- 没有缓存时也渲染各模块骨架（日期条、逐小时、趋势卡），缺值以 -- 占位，不切整页错误或白屏
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 详情失败时用缓存数据构造内容、只做轻提示；无缓存时保留各模块骨架并以 -- 占位：修好的失败分支（出处：卡里修好并验证过）
针对本应用要查的：
- 源页面哪些区块来自缓存、哪些来自详情接口：源工程里这个页面的 Fragment 或 Activity 加载数据的方法，以及对应 ViewModel 的请求方法；看先读缓存填了哪些区块、详情请求失败分支是否清空数据；只被详情覆盖的区块失败时保留
