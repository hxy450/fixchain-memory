# 同键覆盖前先取消旧任务时，清理运行表按句柄身份比对，不按键无条件删除

审的是：代码
触发（任一种）：
- 读到：规格写同一 Job ID 连续触发时显式 cancel 旧 handle 再写入、不变式「同一 workId 最多一个 running 实例」；源端 JobService 用 jobs.remove(jobId)；写错的样子：任务结束的 finally 里无条件 running.delete(workId)（运行表是 Map<number, TaskHandle>），被取消的旧任务晚到时把新 handle 删掉
适用范围：实现「同键覆盖前先取消旧任务」的任务表（后台任务、协程任务表）时
做法：
- 清理写成 if (running.get(workId) === handle) { running.delete(workId) }：只有运行表当前项仍是本次句柄才删除；结束函数带上句柄参数
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 结束函数改为带 workId 和 handle，仅当运行表当前 handle 就是本次 handle 才删除：修好的写法；旧任务晚到不再影响新任务的运行状态和停止（出处：卡里修好并验证过）
未核实：规格生命周期里「运行表移除 workId」一步没写身份校验，源端也按 id 删除；卡里按覆盖语义和唯一性不变式归因
