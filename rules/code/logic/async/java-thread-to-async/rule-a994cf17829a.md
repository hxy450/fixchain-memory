# 源端异步写被同步化后，调用方先取出旧值并写清零，再调用同步方法

审的是：代码
触发（任一种）：
- 读到：源端调用方先调一个在 new Thread 里成功后才写某字段的方法，紧接着在主线程把同一字段置 0；写错的样子：目标的处理（如 onBackPress 里）照源端书写顺序先调已同步化的方法、再把字段置 0，同步方法里的写被随后的清零覆盖
适用范围：目标端把源端后台线程工作改成同步执行、调用方又会写同一字段时
做法：
- 改成 const target = this.field; this.field = 0; this.method(target)：调用方的写挪到同步调用之前，同步方法成功时写入的值作为最终值保留
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 先取出 target 并清零，再调用同步方法，由成功分支写回旧值：修复后返回行为逐次和源端一致（出处：卡里修好并验证过）
