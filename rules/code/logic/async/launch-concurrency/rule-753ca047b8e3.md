# 共享单例 ViewModel 按规格的业务键只丢旧键迟到响应，不让新调用一律取消上一请求

审的是：代码
触发（任一种）：
- 读到：规格状态段写「以某个业务键（如城市 id）作 generation key，旧键的迟到响应不得覆盖新页面」；安卓源码每次用 viewModelScope.launch / async 发一组请求，后到的调用不取消在途的前一组；写错的样子：单例里的加载方法对任何新调用都先 cancel() 上一请求，generation 计数全局递增，不分键
适用范围：迁成多个页面或入口共享的单例 ViewModel / Service，且规格写了按键丢弃迟到响应时
做法：
- 请求发出时记下它的业务键和该键的代次；响应回来时只在当前键已切走（旧键迟到）时丢弃，不对每次新调用都 cancel() 上一请求
- 同键的重复调用合并：已有同键在途请求时直接返回那一个在途的 Promise，不新发也不取消它
