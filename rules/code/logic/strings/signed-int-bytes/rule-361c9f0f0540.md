# 手写 int32 负值 varint 时拆成 lo/hi 两个 32 位半字逐 7 位写，不写死 0xFF

审的是：代码
触发（任一种）：
- 读到：proto 字段类型是 `int32`（不是 `sint32`），wire type 0（varint），值可能为负；写错的样子：手写的编码函数在低 4 组 7 位之后直接写死 `0xff` ×5 再加 `0x01`，第 5 组没取低 32 位的 bit28..31
适用范围：目标端没有 protobuf 运行时、在 ArkTS 里用 32 位位运算手写 int32 varint 编码时
做法：
- 负值按 64 位符号扩展：lo = v >>> 0，hi = 0xFFFFFFFF；第 1–4 组取 (lo >>> 7k) & 0x7f（k = 0..3），第 5 组取 ((lo >>> 28) | ((hi & 0x0f) << 4)) & 0x7f，第 6–10 组从 hi >>> 3 起逐 7 位取，除最后一组外都或上 0x80
- 不凭「高位全 1」拼常量字节，单独核对跨 32 位边界的第 5 组（bit28..34）由哪些位组成
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- int32 以无符号 varint 写出，负值长 10 字节：负 int32 先符号扩展成 64 位再编码（出处：android.util.proto.ProtoOutputStream#writeInt32）
- 负值走 writeRawVarint64(val)，每次取 val & 0x7F 或上 0x80，再 val >>>= 7：标准的逐 7 位拆分，按 64 位做（出处：android.util.proto.ProtoOutputStream#writeUnsignedVarintFromSignedInt；android.util.proto.EncodedBuffer#writeRawVarint64）
- 第 5 组 = (lo >>> 28) | ((hi & 0x0f) << 4)：修好后的跨边界分组，INT32_MIN 等用例通过（出处：卡里修好并验证过）
