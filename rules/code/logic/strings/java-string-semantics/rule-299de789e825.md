# BufferedReader.readLine 迁过来按 /\r\n|\r|\n/ 分行，不写 split('\n')

审的是：代码
触发（任一种）：
- 读到：源端用 BufferedReader 包装后 readLine() 逐行读脚本或文本；写错的样子：目标端写成 text.split('\n')，只认 LF；CR 行尾的文件整份成一行
适用范围：把安卓 BufferedReader.readLine 的逐行解析迁成目标端字符串分行时
做法：
- 写成 text.split(/\r\n|\r|\n/)：CRLF 放在最前，单独的 CR、单独的 LF 也各算一个行尾
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- readLine 以 '\n'、'\r' 或紧跟 '\n' 的 '\r' 任一为行终止，读到 EOF 也结束一行：源端分行语义，目标端的正则要三种都认（出处：java.io.BufferedReader#readLine）
- split(/\r\n|\r|\n/) 后 CR 行尾的升级脚本能正确分行：改法的依据（出处：卡里修好并验证过）
针对本应用要查的：
- 被解析文件的实际行尾：源工程 assets 或 res/raw 下被逐行解析的脚本、文本文件；用 file 或 od -c 看行尾是 \r\n、\r 还是 \n；混有 CR 行尾的，split('\n') 必然分不开
