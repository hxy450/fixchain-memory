# 源端 BufferedReader.readLine 逐行读时，目标按 \n、\r、\r\n 断行且末尾不多出空行

审的是：代码
触发（任一种）：
- 读到：`BufferedReader.readLine()` 循环逐行读文件（常接着 line.trim()）；写错的样子：目标读全文后 split(/\r\n|\r|\n/) 或 split('\n') 直接当行列表，文件以换行结尾时最后多出一个空串行；或只按 '\n' 断行，裸 \r 不断行
适用范围：Java 的 BufferedReader.readLine 逐行读文本，迁成 ArkTS 读全文再断行时
做法：
- 断行写成：\r\n、\r、\n 都是行终止符，行内容不含终止符；最后一个终止符之后为空时不产生行（按 /\r\n|\r|\n/ 切分后，若最后一项是空串就去掉这一项）
- 用最小样例自检：内容为 "a\nb\n" 的文件应读出 ["a","b"]，不是 ["a","b",""]
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- readLine 的行终止符是 '\n'、'\r'、'\r\n' 或到达文件尾；返回的行不含终止符，流已到尾且没读到字符时返回 null：源端断行语义：最后一个终止符后没有字符时不再返回一行（出处：java.io.BufferedReader#readLine）
- 读全文后 split(/\r\n|\r|\n/) 在文件以换行结尾时多出一个空串行，编辑器末尾因此多一空行：直接用 JS split 的后果（出处：卡里修好并验证过）
