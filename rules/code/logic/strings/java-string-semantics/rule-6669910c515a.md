# 源端 String.trim 时，目标只去首尾码点 ≤U+0020 的字符，不用 JS trim()

审的是：代码
触发（任一种）：
- 读到：`line.trim()`（java.lang.String#trim）；写错的样子：目标直接用 JS 的 .trim()，注释写着「trim 语义与 Java 一致」
适用范围：Java String.trim 迁成 ArkTS 时，文本可能含 NBSP、U+FEFF 等非 ASCII 空白的场合
做法：
- 写成只去首尾码点 ≤ U+0020 的函数：s.replace(/^[\u0000-\u0020]+|[\u0000-\u0020]+$/g, '')；NBSP、U+FEFF 等保留
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Java trim 去掉的「空白」是码点 ≤ 'U+0020' 的字符：源端去空白的范围（出处：java.lang.String#trim）
- trim(): string 去掉首尾的 white space 和 line terminator：JS trim 的范围比 Java 宽，会多去 NBSP、U+FEFF 等（出处：鸿蒙 SDK 的 ets/build-tools/ets-loader 内 typescript/lib/lib.es5.d.ts，String.trim）
- JS trim 多去掉 NBSP、U+FEFF 等字符：直接用 JS trim 的差异（出处：卡里修好并验证过）
