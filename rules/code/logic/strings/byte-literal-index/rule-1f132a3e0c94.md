# 规格的字节公式和源码字面量不一致时，按源码逐下标实现，不靠循环填充凑长度

审的是：代码
触发（任一种）：
- 读到：源码 `byte[]` 字面量（如 {-1, …, 7, -128, 105, …}，MifareClassic 扇区尾块）和规格公式的字节数或顺序对不上；写错的样子：目标 Uint8Array 按规格公式填了前几个下标，再用 for 循环把 0xFF 延伸到末尾凑足长度；注释仍是少字节的写法
适用范围：实现源码里定长协议常量（如 MIFARE Classic 扇区尾块）的目标字节数组时
做法：
- 以源码字面量为准逐下标写：每个下标照源字节换成无符号（b & 0xFF），不用延伸填充的循环凑长度
- 在源码理解笔记里登记这处规格冲突
- 最小自检：断言长度为 16、与源字面量逐字节相等，并用项目现有的访问位校验确认三字节访问位合法
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- writeSingleBlock(blockIndex: number, data: number[]): Promise<void>，一块 16 字节：目标写 MIFARE Classic 块的接口，data 须是完整的 16 字节（出处：鸿蒙 SDK 的 ets/api/tag/nfctech.d.ts，MifareClassicTag.writeSingleBlock）
- MifareClassic.BLOCK_SIZE = 16：源端块长（出处：android.nfc.tech.MifareClassic#BLOCK_SIZE）
- Byte.toUnsignedInt(x) = ((int) x) & 0xff：源字节换成目标无符号值的规则（出处：java.lang.Byte#toUnsignedInt）
- 尾块改成 [0..5]=FF、[6..8]=FF 07 80、[9]=GPB、[10..15]=FF 后访问位校验通过：逐下标照源字面量是上机核对过的写法（出处：卡里修好并验证过）
未核实：卡里环境是 HarmonyOS API 24，本机按 API 23 核实
