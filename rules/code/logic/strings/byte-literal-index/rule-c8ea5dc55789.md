# 用命名常量替换源端切片下标时按每处用途选端点，提取区间不套用着色边界

审的是：代码
触发（任一种）：
- 读到：源码对同一行字符串按用途取不同区间：着色只取 substring(12, 18)，提取并交给解码的是 substring(12, 20)；规格写提取区间且标「区间字符精确」；写错的样子：目标把字面下标换成一组共享常量后，提取处写成与着色相同的终点（等效 substring(12, 18)），同一函数的文档注释却仍写 substring(12, 20)；或把页面里原本正确的内联切片搬进服务层时改错了区间
适用范围：把源端内联的字符串 / 字节切片抽进服务层、用命名常量代替字面下标时
做法：
- 逐处按用途选端点：数据提取用源端提取那处的终点（如 MIFARE Classic 尾块的访问条件 + GPB 到 20），不沿用着色那处的终点（访问条件到 18）
- 搬移后逐字核对切片区间和规格契约的字面区间，并核对代码与它自己的注释一致
- 规格标「区间字符精确」的提取项补最小断言：每项长度等于规格给的字符数（如 8 个 hex），带前缀的项为前缀加同样长度
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 提取终点改成 20（访问条件 3 字节 + GPB 1 字节，共 8 hex）后，GPB 含非法字符时两端都判为访问条件无效：修好后与源端运行时一致（出处：卡里修好并验证过）
针对本应用要查的：
- 每处切片的用途和区间：源工程里对同一字符串做 substring 的各处调用（提取、着色、校验）和规格里的提取契约；按调用列出用途与起止下标，每个常量只用在同用途的调用上
