# 源码里的字节数组字面量和切片下标

agent 会看到什么：读过的源码里有 byte[] 字面量、substring(起, 止) 这类按下标取的区间，规格另写了公式或区间；交回的代码里 Uint8Array 的逐下标内容和切片端点

## 规矩

- rule-1f132a3e0c94｜规格的字节公式和源码字面量不一致时，按源码逐下标实现，不靠循环填充凑长度｜读到：源码 `byte[]` 字面量（如 {-1, …, 7, -128, 105, …}，MifareClassic 扇区尾块）和规格公式的字节数或顺序对不上；写错：目标 Uint8Array 按规格公式填了前几个下标，再用 for 循环把 0xFF 延伸到末尾凑足长度；注释仍是少字节的写法
- rule-c8ea5dc55789｜用命名常量替换源端切片下标时按每处用途选端点，提取区间不套用着色边界｜读到：源码对同一行字符串按用途取不同区间：着色只取 substring(12, 18)，提取并交给解码的是 substring(12, 20)；规格写提取区间且标「区间字符精确」；写错：目标把字面下标换成一组共享常量后，提取处写成与着色相同的终点（等效 substring(12, 18)），同一函数的文档注释却仍写 substring(12, 20)；或把页面里原本正确的内联切片搬进服务层时改错了区间
