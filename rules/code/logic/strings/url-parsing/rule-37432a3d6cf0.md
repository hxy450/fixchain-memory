# 从 URL 取最后路径段或扩展名时，先去掉 #fragment 和 ?query 再取

审的是：代码
触发（任一种）：
- 读到：源码对链接调用同文件的私有或扩展 helper 取路径段，helper 定义里是 `substringBefore('#')`、`substringBefore('?')`、`substringAfterLast('/')`；读到的片段可能只有调用、没有定义；写错的样子：目标端直接在整串 URL 上 `lastIndexOf('/')` 取段再取扩展名，没先去掉 `?query` 和 `#fragment`（带参数的链接得到 `mp3?x=1` 这样的扩展名）
适用范围：把源码里从 URL 或链接截取路径段、扩展名的逻辑翻译成 ArkTS 时
做法：
- 按源 helper 的顺序写：const noFrag = link.split('#')[0]; const noQuery = noFrag.split('?')[0]; const seg = noQuery.substring(noQuery.lastIndexOf('/') + 1)，再从 seg 取扩展名
- 源码调用私有或扩展 helper 而读到的片段里没有它的定义时，先补读定义再翻译，不按函数名推断语义
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 先按 # 再按 ? 截断，再取最后路径段与扩展名：修好后的截取顺序（出处：卡里修好并验证过）
针对本应用要查的：
- helper 的确切截取步骤：源工程里调用处所在的同一个 Kotlin 文件，按 helper 的函数名找 private fun 或扩展函数定义；逐个照搬它用的 substringBefore / substringAfterLast 及顺序
