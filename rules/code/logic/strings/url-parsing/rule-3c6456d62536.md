# 源码用 URL(base, 绝对路径) 取 scheme 和 authority 时，目标按字符串截取保留显式端口

审的是：代码
触发（任一种）：
- 读到：源码 URL(remoteUrl, "/api/…/") 取 base 地址（如 Retrofit 的 baseUrl(URL(…, "/path/"))），默认地址带显式端口（:443）；写错的样子：目标写成 parsed.protocol + '//' + parsed.host + '/path/'，catch 才回退默认；默认地址丢了 :443，非法串得到 ///path/
适用范围：把用 java.net.URL 的 (context, spec) 构造截取 scheme 与 authority 的逻辑改写成 ArkTS 时
做法：
- 不用 url.URL 的 host 拼接；按字符串截取 scheme://authority（到第一个 / 为止），保留显式端口，再接上源端的绝对路径
- scheme 不是 http/https 或没有 authority 时，显式回退默认地址
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 解析时 port 等于当前 protocol 的默认端口（https: 443、http: 80）就解析为空字符串：host 不带默认端口，按 host 拼接会丢掉显式写的 :443（出处：js-apis-url.md，URL 的属性说明）
- hostname 是不带端口的主机名，host 是主机部分：两者都不能用来还原源端写明的端口（出处：js-apis-url.md，URL 的属性）
- 按 scheme/authority 确定性截取、保留显式端口，非 http/https 或无 authority 回退默认：修好后判例全过的写法（出处：卡里修好并验证过）
未核实：对 https 合法输入 protocol / host 是否也为空卡里没有确认
