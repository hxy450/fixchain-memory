# toIntOrNull/toLongOrNull 用 /^[+-]?\d+$/ 整串校验加范围检查，不用前缀解析

审的是：代码
触发（任一种）：
- 读到：Kotlin 源里把外部字符串转数用 toIntOrNull() / toLongOrNull()，失败时 ?: 回落默认值、null 或某个枚举；写错的样子：目标写成 parseInt(value, 10) / Number.parseInt 只判 NaN，带尾随字符的串按前缀被接受；或者在回落分支外加了源码没有的 `<= 0` 之类合法性规则
- 读到：Kotlin 对字符串调用 toIntOrNull()（如可空链上的 ?.toIntOrNull()）；写错的样子：注释写「toIntOrNull 等价」，实现是 /^-?\d+$/ 匹配后 parseInt：不接受 + 号，也不检查 Int 范围
适用范围：把 Kotlin 的 toIntOrNull / toLongOrNull 整数解析（设置项、HTTP 头、外部 JSON 字段等）改写成 ArkTS 时
做法：
- 先用 /^[+-]?\d+$/ 校验整串，通过后再转数（Number(value) 或 parseInt），并检查落在源类型范围内（Int 为 -2147483648..2147483647）；不匹配或越界就走源码的回落值（toIntOrNull 本身返回 null）
- 只保留源码已有的回落分支（如 ?: 60），不加源码没有的合法性规则（如把 0 当非法）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- /^[+-]?\d+$/ 整串校验后再转数值：卡里修好的整数解析；改前 parseInt 让 '15abc' 命中 15，自加的 <= 0 让合法的 0 被回退（出处：卡里修好并验证过）
- toIntOrNull 接受可选的 + / - 号，超出 Int 范围返回 null：直译要保留这两点（出处：卡里修好并验证过）
- MIN_VALUE = 0x80000000，MAX_VALUE = 0x7fffffff：32 位 int 的范围，toIntOrNull 超出就返回 null（出处：java.lang.Integer 的 MIN_VALUE、MAX_VALUE）
- Number.MAX_SAFE_INTEGER = 9007199254740991（2^53 − 1）：Long 范围的值超过它时 Number 转出来不精确，要另行处理（出处：鸿蒙 SDK 的 ets/build-tools/ets-loader/node_modules/typescript/lib/lib.es2015.core.d.ts，NumberConstructor.MAX_SAFE_INTEGER）
