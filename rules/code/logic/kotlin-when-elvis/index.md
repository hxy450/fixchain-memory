# Kotlin 的 when 分支和 ?: 回退链

agent 会看到什么：读到 Kotlin 源码里 when / in setOf(...) 按一组常量分支、a ?: b ?: 常量 的回退链（含 StateFlow 初值里先解析持久值再回退）；产物里 TS 的 if / switch、?? 链和 !== 组合少了链上某一步、漏了页面上看不到的取值，或回退只写在设置方法里

## 规矩

- rule-e3077f0eae68｜源端当前值是 override ?: 默认值 ?: 常量的回退链时，目标照搬回退链，不写死默认值｜读到：源端状态的当前值写成 `override ?: itemDefault ?: false`，切换写成 `override?.not() ?: itemDefault?.not() ?: true`；写错：目标的切换函数签名里写死 `false` 作默认值，或改成由调用方传入当前展示态、直接覆盖已存的 override，没有先取已存 override 再取条目默认值
- rule-b86225da0b85｜源端在初始化或 getter 里对持久值解析回退时，目标的读取路径和对外快照也要做｜读到：Kotlin 的 StateFlow 或状态字段初始化时，对 preferences 读出的持久值先解析、解析不到再用 `?:` 回退默认值；写错：目标服务的读取方法或对外快照直接把 preferences.get(...) 读出的原始值赋进状态，回退只写在设置方法或辅助服务里，读取路径没调用它
- rule-4b32a06e0bc0｜派生判定按源 ViewModel 谓词的完整取值集实现，不按页面可见单选项推导｜读到：源 ViewModel 的布尔派生谓词对一组常量（含页面上不可见的取值）逐个返回 false、其余返回 true；写错：目标端只声明页面可见单选项对应的常量，把「默认」写成 `x !== A && x !== B && x !== C`，漏掉不可见的取值
- rule-dcd1b0faf340｜Kotlin 的 when 加 ?: 回退链改写成 ArkTS 时，每个分支保留链上每一步｜读到：源码 `when` 按条件分支，其中通用分支是 `a() ?: b()` 这样的回退链（先查一张映射表，查不到再走 Locale 解析）；写错：ArkTS 里链上前一项只放在某个条件的 `if (...)` 分支里调用，另一分支直接走最后的回退，少了 `?:` 链里的那一步
