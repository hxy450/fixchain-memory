# 源端当前值是 override ?: 默认值 ?: 常量的回退链时，目标照搬回退链，不写死默认值

审的是：代码
触发（任一种）：
- 读到：源端状态的当前值写成 `override ?: itemDefault ?: false`，切换写成 `override?.not() ?: itemDefault?.not() ?: true`；写错的样子：目标的切换函数签名里写死 `false` 作默认值，或改成由调用方传入当前展示态、直接覆盖已存的 override，没有先取已存 override 再取条目默认值
适用范围：把源端 ViewModel 里带 override 和条目默认值的开关状态（如全文显示）迁到目标仓库或状态类时
做法：
- 当前值写成 `storedOverride ?? itemDefault ?? false`，顺序和源端 `?:` 链一致；切换时存入 !当前值
- 签名里缺条目默认值时补一个参数传条目默认值，不写死 false，也不让调用方传入的展示态覆盖已存 override
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 切换函数的第二个参数是条目默认值，当前值取 override ?? default：修好后的签名和取值（出处：卡里修好并验证过）
针对本应用要查的：
- 回退链的每一层和最后的常量：源工程里 ViewModel 对这个状态的取值表达式和切换函数（Kotlin 的 `?:` 链）；按出现顺序抄下每一层的来源和最后的常量，目标的 `??` 链照同样顺序写
