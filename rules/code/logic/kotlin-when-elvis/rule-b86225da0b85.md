# 源端在初始化或 getter 里对持久值解析回退时，目标的读取路径和对外快照也要做

审的是：代码
触发（任一种）：
- 读到：Kotlin 的 StateFlow 或状态字段初始化时，对 preferences 读出的持久值先解析、解析不到再用 `?:` 回退默认值；写错的样子：目标服务的读取方法或对外快照直接把 preferences.get(...) 读出的原始值赋进状态，回退只写在设置方法或辅助服务里，读取路径没调用它
适用范围：把源端带解析回退的派生状态落到目标的读取型服务（读取方法、快照、getter）时
做法：
- 读取路径上调用同一个解析回退函数：state.x = resolve(await prefs.get(key, 默认值))，resolve 在解析不到（如文件不存在）时返回源端 `?:` 右边的默认值；不要只在设置方法或辅助服务里做
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- get(key: string, defValue: ValueType): Promise<ValueType>：defValue 只在键不存在或值为 null、类型不符时返回；值存在但解析不到时不会回退，要自己做（出处：鸿蒙 SDK 的 ets/api/@ohos.data.preferences.d.ts，Preferences.get）
- 读取方法改为先取原始 pref 值，再经辅助服务的解析回退函数得到结果：修好的写法，重启后找不到文件时回退到默认值（出处：卡里修好并验证过）
未核实：卡里环境标的鸿蒙 SDK 是 23 和 26.0.0，Preferences.get 按本机 API 23 核实
来源：1 张卡，1 个应用
