# System.nanoTime 计时用 getUptime(TimeType.ACTIVE)，不换成墙钟

审的是：代码
触发（任一种）：
- 读到：源端用 System.nanoTime() 求帧间隔、推进动画进度或重置计时基线（单调纳秒时钟）；写错的样子：目标的时钟函数里写 performance.now()（ArkTS SDK 里没有，编译报找不到符号或 Kit 无导出），或者改成 Date.now() / systemDateTime.getTime()，注释写「ms 墙钟」
适用范围：源端单调计时（System.nanoTime）迁到 ArkTS 时的时钟取值，含编译修复时替换找不到的时钟 API
做法：
- import { systemDateTime } from '@kit.BasicServicesKit'；时钟写成 systemDateTime.getUptime(systemDateTime.TimeType.ACTIVE, true) / 1000000 得到毫秒（要纳秒就不除）；源端两次 nanoTime 之差对应两次 getUptime 之差
- 时钟函数的注释写明它承担的语义：对应 System.nanoTime，单调、不受校时影响、不含深睡眠；不用 Date.now() 这类会随系统校时回拨或跳变的墙钟顶替
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function getUptime(timeType: TimeType, isNanoseconds?: boolean): number：系统启动以来的时长；isNanoseconds 为 true 时单位是纳秒，否则毫秒；@since 10（出处：鸿蒙 SDK 的 ets/api/@ohos.systemDateTime.d.ts，systemDateTime.getUptime）
- TimeType.STARTUP = 0（含深睡眠）、TimeType.ACTIVE = 1（不含深睡眠）：getUptime 的计时口径；System.nanoTime 不计深睡眠，对应 ACTIVE（出处：鸿蒙 SDK 的 ets/api/@ohos.systemDateTime.d.ts，systemDateTime.TimeType）
- System.nanoTime() 只用于量经过的时间，与墙钟无关，不计深睡眠：源端时钟的语义（出处：java.lang.System#nanoTime）
- function getTime(isNanoseconds?: boolean): number：从 Unix 纪元起算的时间戳，是墙钟，不能顶替 nanoTime（出处：鸿蒙 SDK 的 ets/api/@ohos.systemDateTime.d.ts，systemDateTime.getTime）
- @kit.BasicServicesKit 导出 systemDateTime；@kit.PerformanceAnalysisKit 只导出 hiAppEvent、hilog、hiTraceMeter 等，没有 performance：import 从哪个 Kit 来；performance.now 在 ArkTS SDK 里没有对应（出处：鸿蒙 SDK 的 ets/kits/@kit.BasicServicesKit.d.ts 与 ets/kits/@kit.PerformanceAnalysisKit.d.ts 的 export）
- nowMs 改为 systemDateTime.getUptime(systemDateTime.TimeType.ACTIVE, true) / NANOS_PER_MILLI 后通过返修检查：替换 Date.now 墙钟的写法（出处：卡里修好并验证过）
