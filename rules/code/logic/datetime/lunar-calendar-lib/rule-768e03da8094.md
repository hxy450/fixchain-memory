# 源端字段由算法库对任意日期实时计算时，不改绑弃用的静态资产，移植算法或上报阻塞

审的是：代码
触发（任一种）：
- 读到：源端用算法库按日期实时算字段（如 lunar-java 的 `Lunar.fromDate(date)` 取 `dayYi` / `dayJi`），模型里另有标了 `@Deprecated` 的字段，assets 下有只覆盖少量日期的静态 json 表；写错的样子：目标仓储把这些字段只绑定到 rawfile 里的静态 json，`loadDate` 查不到日期就返回 `null`；或降级用 `Intl` 只补了部分字段，其余字段仍为空
适用范围：数据层迁移时源端字段由算法库对任意输入实时计算，目标平台没有等价库
做法：
- 把源端算法移植到目标端，在按日期构造数据的入口里动态计算所有被消费的字段；做不到就把功能缺失作为阻塞上报，不改绑弃用的静态资产
- 写完用当前日期调用一次，确认每个下游消费的字段都非空
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 按日期构造数据的方法里先用 Intl 中国历补公历、农历、干支、节日，再动态计算宜忌；资产未命中时走这条路：返修后保留的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源工程静态资产实际覆盖的日期范围：源工程 assets 下对应的 json 表（看表头和最后一条记录），以及模型里该字段是否标了 @Deprecated；读出首末日期，和当前日期比较；不覆盖当前日期的就不能当数据源
