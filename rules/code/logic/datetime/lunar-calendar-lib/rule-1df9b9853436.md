# 规格要求农历库同输入同输出适配时，用 Intl 的 chinese 历法生成，不以静态资产为唯一来源

审的是：代码
触发（任一种）：
- 读到：规格 HARD 映射写「com.nlf.calendar.Lunar → 传统历法适配器，同输入同输出」或「任意合法日期可转换」；源码调 Lunar.fromDate / lunarToLunarDate；写错的样子：数据层只按 rawfile 里的预置 JSON 查行，查不到就返回 null 或空网格 []；完成报告的 generated_placeholders 是 []
适用范围：源端用第三方农历库按任意日期算农历，目标端没有同名库时
做法：
- 先用目标平台内置能力：农历文本用 new Intl.DateTimeFormat('zh-CN-u-ca-chinese').format(date) 按任意日期生成；资产未命中时用它确定性生成公历月网格和农历文本，不返回空
- 内置能力和已批准的库都给不出的字段，登记占位或决策缺口，不以只覆盖少量日期的静态资产作为唯一来源
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- new Intl.DateTimeFormat('zh-CN-u-ca-chinese') 能按任意日期给出农历文本，如 2026-08-13 得「丙午年七月1」：资产范围外日期改用它生成后月历恢复（出处：卡里修好并验证过）
- new(locales?: string | string[], options?: DateTimeFormatOptions): DateTimeFormat：全局 Intl.DateTimeFormat 的构造（出处：鸿蒙 SDK 的 ets/build-tools/ets-loader/node_modules/typescript/lib/lib.es5.d.ts，Intl.DateTimeFormat）
- @ohos.intl 的 DateTimeFormat 构造自 20 起废弃，改用 Intl.DateTimeFormat.constructor：用全局 Intl，不用 @ohos.intl 的旧类（出处：鸿蒙 SDK 的 ets/api/@ohos.intl.d.ts，intl.DateTimeFormat.constructor）
- locale 扩展参数 ca 表示历法，农历写 chinese（u-ca-chinese）：locale 串 'zh-CN-u-ca-chinese' 的含义（出处：i18n-locale-culture.md，表2 扩展参数）
未核实：干支、节日、宜忌等字段目标平台有无内置来源，卡里没有核实
