# 源码用库输出作持久化串或文案时，先取库真值再写序列化，不固定成 UTC Z、不降级文案

审的是：代码
触发（任一种）：
- 读到：源端 new RRule(recur).toString().replace("RRULE:", "")、EventRecurrenceFormatter.getRepeatString(...)、Recur.getNextDate(...)；派工要求与源端产物逐字段兼容；写错的样子：目标 RRULE 串写成固定 UTC 的 UNTIL=…Z、没有 CRLF；下一次时间自写 DAILY / WEEKLY 步进；重复文案「降级为 FREQ 词 + 原样透传」
适用范围：服务实现阶段替代算法型第三方库、产物要和源端逐字段兼容时
做法：
- 先用该版本的库 jar 跑代表输入取真值，再写序列化和文案；RRULE 按库的 Recur 逐行移植，buildRule 产出设备时区浮动时间加 CRLF
- 重复文案按库的格式化器移植成独立模块，不降级成 FREQ 词
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 目标的 RRULE 工具类改为 ical4j Recur 逐行移植，buildRule 产出设备时区浮动时间 + CRLF；另建重复文案模块：用 ical4j jar 对拍后修好（出处：卡里修好并验证过）
针对本应用要查的：
- 库在代表输入下的真实输出：本机 Gradle 缓存 modules-2/files-2.1/<group>/<artifact>/<version>/ 下源工程依赖版本的 jar；用 JDK 小程序按源码实参调用，逐字比对目标实现的输出
