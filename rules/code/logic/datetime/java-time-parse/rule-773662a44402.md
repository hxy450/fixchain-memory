# ZonedDateTime.parse 先校验带偏移的 ISO 串再 Date.parse，不裸用

审的是：代码
触发（任一种）：
- 读到：Kotlin 源里 ZonedDateTime.parse(text)，catch 后保留旧值或取 now；规格写「日期字符串非法 → 保留旧值」；写错的样子：目标直接 Date.parse(raw)（注释还写着源为 ZonedDateTime.parse），只判 NaN，纯日期 '2024-01-02' 这类源函数会拒绝的串也被接受、覆盖旧值
适用范围：把 Kotlin/Java 的 ZonedDateTime.parse 改写成 ArkTS 时间解析时
做法：
- 先用正则校验整串符合 ISO_ZONED_DATE_TIME：yyyy-MM-ddTHH:mm，可选 :ss 和小数秒，必须接 Z 或 ±HH:MM 偏移，可再跟 [区域 ID]；通过后再 Date.parse 转 epoch 毫秒，不通过走源码的回落（保留旧值或 now）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- ZonedDateTime.parse(text) 用 DateTimeFormatter.ISO_ZONED_DATE_TIME 解析，不能解析就抛 DateTimeParseException：源函数的接受范围就是这个格式（出处：java.time.ZonedDateTime#parse(CharSequence)）
- ISO_ZONED_DATE_TIME = ISO_OFFSET_DATE_TIME + 可选的 '[' 区域 ID ']'；ISO_OFFSET_DATE_TIME = ISO_LOCAL_DATE_TIME + 偏移 ID；ISO_LOCAL_DATE_TIME = 日期 + 'T' + HH:mm[:ss[.小数]]：偏移必需、区域 ID 可选、必须有 T 和时分（出处：java.time.format.DateTimeFormatter 的 ISO_ZONED_DATE_TIME、ISO_OFFSET_DATE_TIME、ISO_LOCAL_DATE_TIME、ISO_LOCAL_TIME）
- 先用 ISO_ZONED_DATE_TIME 正则校验再 Date.parse，纯日期等非法串走保留旧值：卡里修好的写法；改前 Date.parse 接受纯日期、覆盖了旧值（出处：卡里修好并验证过）
未核实：带 [区域 ID] 的串交给 Date.parse 能否解析，卡里没验证；卡里 compileSdk 是 37，本机核对用的是 android-36.1 源码
