# 声明与源端同名的常量时打开定义文件核对数值，规格默认值与源定义冲突以源为准

审的是：代码
触发（任一种）：
- 读到：源实体字段默认值引用 const val 常量（如 var id: Long = 某常量），规格表给了这个字段的默认数值；写错的样子：`export const` 与源端同名的常量，数值照抄规格表（如 -1），和源端 const val 定义不一致；定义所在文件列出来了却没读
适用范围：模型实现阶段声明与源端同名的共享常量（未设置哨兵、全部项 id 等）时
做法：
- 声明前打开源端定义文件，按 const val 的值写目标常量
- 规格表默认值与源定义冲突时以源定义为准，并回报规格
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 把共享常量改成源定义的值后，引用它的偏好缺省和列表行 id 一并对上：修好后的结果（出处：卡里修好并验证过）
针对本应用要查的：
- 常量的源端定义值：源工程里该常量名的 const val 定义（数据库类、companion object、常量文件）；读字面量，按目标类型写成 export const
未核实：卡里环境写了 API 23 和 26.0.0 两种，本机按 API 23
