# 与源端或 Base 层同名的常量和哨兵值

agent 会看到什么：读到源端 const val 常量（实体字段默认值、companion object 里的哨兵）、Base 模型层 export const 的同名常量，而规格表给了另一个默认数值；产物里 export const 的数值照抄哪一边、偏好缺省和列表行 id 用的是哪一层的常量

## 规矩

- rule-fc635f4a00b3｜声明与源端同名的常量时打开定义文件核对数值，规格默认值与源定义冲突以源为准｜读到：源实体字段默认值引用 const val 常量（如 var id: Long = 某常量），规格表给了这个字段的默认数值；写错：`export const` 与源端同名的常量，数值照抄规格表（如 -1），和源端 const val 定义不一致；定义所在文件列出来了却没读
- rule-9fdd27c1d387｜功能规格的哨兵值与 Base 常量不一致时，对外的偏好缺省和列表行 id 在本层投影成规格值｜读到：功能规格写明某哨兵的值（如「初值 … = 0」），而读到的 Base 模型层里 `export const` 的同名常量是另一个数；写错：只在本层另定义一个 `const` 哨兵，读偏好时仍经 Base 的 getter 取缺省、列表行对外 id 仍沿用 Base 常量，注释说「只靠类型字段分类」「不影响分支」
