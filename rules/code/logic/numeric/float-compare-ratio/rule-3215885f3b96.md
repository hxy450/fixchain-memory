# 源端进度比值带零分母分支和 coerceIn(0f, 1f) 时，目标写入前保留 total > 0 判断和钳制

审的是：代码
触发（任一种）：
- 读到：源端辅助方法算进度：if (total == 0) … else (completed.toFloat() / total.toFloat()).coerceIn(0f, 1f)；写错的样子：目标在进度回调里直接用 current / total 写进共享状态，写入前没有 total > 0 判断，也没有 Math.min / Math.max 钳制
适用范围：把源端带守卫的进度、比率计算改写到 ArkTS 的回调或状态写入处时
做法：
- 写成 const pct = total > 0 ? Math.min(1, Math.max(0, current / total)) : <源端 total == 0 分支的值>，再写进共享状态；计算内联进回调时守卫一起搬过去
- 零分母时的取值照源端那个分支，在注释里写明取舍

- total > 0 ? current / total : 0：修复时在调用侧加的零分母判断，写入后不再出现 NaN（出处：卡里修好并验证过）
- ArkTS 的 number 除法不抛异常：0/0 为 NaN，x/0 为 Infinity：不加判断时 NaN 或 Infinity 会直接写进进度状态（出处：卡里修好并验证过）
