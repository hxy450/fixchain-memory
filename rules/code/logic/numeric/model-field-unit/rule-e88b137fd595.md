# 逐字段照搬源端 Builder 构造时，两端模型数值字段单位不同就在构造处显式换算

审的是：代码
触发（任一种）：
- 读到：源端用 Builder().setDuration(x) 一类的链式构造逐字段直传数值；目标端来源模型和目标模型对同名数值字段注明了不同单位（如一个注 ms、一个注「秒」）；写错的样子：目标端 new <目标模型>(…, src.duration, …) 把来源字段原样传进单位不同的参数，没有 / 1000 或 * 1000 换算
适用范围：功能实现时把源端模型的 Builder 或构造调用逐字段翻成目标端模型构造参数，且字段是时长、尺寸、时间戳一类带单位的数值
做法：
- 对每个数值字段同时核对来源模型和目标模型已声明的单位；两端不同就在构造处显式换算，如毫秒到秒写 Math.floor(src.duration / 1000)，不以「源码直传」作为等价依据
- 复核构造参数时把顺序和单位一起列表：来源字段单位 → 目标字段单位；再 grep 目标字段的现有消费方（如按「{duration}秒」显示、× 1000 交给播放会话）确认目标单位域
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 构造处改为 Math.floor(src.duration / 1000) 后，列表时长显示正确：修好的写法（毫秒域字段进秒域字段）（出处：卡里修好并验证过）
- floor(x: number): number，返回不大于参数的最大整数：毫秒换秒时取整（出处：鸿蒙 SDK 的 ets/build-tools/ets-loader/node_modules/typescript/lib/lib.es5.d.ts，Math.floor）
- AVMetadata.duration：媒体时长，单位毫秒（ms）：目标字段若最终交给播放会话，消费方要的是毫秒（出处：arkts-apis-avsession-i.md，AVMetadata）
- MediaStore.MediaColumns.DURATION 标注 @DurationMillisLong：源端从媒体库读到的时长是毫秒（出处：android.provider.MediaStore.MediaColumns#DURATION）
针对本应用要查的：
- 来源字段和目标字段各自的单位：目标工程里两个模型类的字段声明和注释，以及目标字段的消费方（显示拼接、交给播放或计时接口的地方）；读字段注释里的单位；注释缺失时看消费方是按秒拼文案还是 × 1000 转毫秒，据此定目标单位
未核实：源端列表对同一队列是否同样显示原始毫秒值卡里没有核对
