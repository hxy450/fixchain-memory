# 同一业务链有弹窗确认和无弹窗直调两个入口时，每个入口都要起链调服务并在终态收口

审的是：代码
触发（任一种）：
- 读到：源端工具方法在回调里先显示 loading 的 Dialog，随即直接下载并设置，fail / cancel / success 各分支都关闭这个 Dialog，中间没有选择弹窗；写错的样子：目标的直调入口方法只置 busy = true、visible = true，服务调用和收口（busy = false）只写在弹窗「确定」的 onConfirm 里；注释却写着「直接调用」「busy 态起链」
适用范围：目标把源端一条直调链拆成弹窗组件加静态入口、同一链有多个入口时
做法：
- 逐个入口写全三步：显示 loading（busy = true）→ 调用服务 → 在成功、失败、取消每个终态各收口一次（busy = false）；直调入口不经弹窗，自己调服务
- 按源端的调用顺序逐个入口走一遍目标代码：每个 busy = true 都要能找到经服务终态到达的 busy = false 调用点
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 直调入口在 busy 态内直接调用服务并在终态收口后，页面点击后 loading 能正常结束：只置忙态不起链时 loading 永不收口（出处：卡里修好并验证过）
