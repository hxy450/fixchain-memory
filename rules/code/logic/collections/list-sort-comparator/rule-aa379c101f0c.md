# 新列表数据路径要排序时，照源端该列表自己的 Comparator 写，不复用同文件别的列表的比较函数

审的是：代码
触发（任一种）：
- 读到：源端这个列表有自己的 Comparator 实现（如待办列表：未完成在前、同状态按创建时间降序），在 Collections.sort 或 List.sort 里使用；写错的样子：目标新增的查询直接照搬同文件里另一个列表的 .sort(比较函数)，排序键和方向与源端该列表的排序器不同
适用范围：目标端多个列表共用同一仓库或查询服务、为其中一个列表新增或修改数据路径时
做法：
- 在源端找到该列表自己的排序器，把排序键和方向逐项写成这个列表专用的比较函数（如先按完成状态未完成在前，再按创建时间降序），在新数据路径的 .sort() 里用它
- 这个专用比较函数不读别的列表的排序配置
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 待办改用独立比较函数（未完成在前、创建时间降序），不再套日程比较器和日程排序配置后，顺序与源端一致：返修后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 该列表的排序键和方向：源工程里这个列表的 Fragment 或 Adapter 设置数据前调用的 Comparator 实现类（compare 方法）；按 compare 里比较的先后顺序读出每个键和升降序，照顺序写进目标比较函数
