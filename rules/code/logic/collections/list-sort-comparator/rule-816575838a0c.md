# 偏好类设置落地后，读它的列表查询要真有调用点，比较函数不能写死排序

审的是：代码
触发（任一种）：
- 读到：源端列表排序时读取用户的排序偏好（经某个 Helper 的 getter 或 SharedPreferences.getString 取出）；写错的样子：目标的排序配置键或加载函数在仓库、查询服务里没有调用点；列表的 .sort() 比较函数写死排序顺序
适用范围：用户可配置的列表排序等偏好，在目标端的读取一侧
做法：
- 在仓库和查询服务里搜这个配置键或它的加载函数，没有调用点就视为未接通
- 接通：每个按该偏好排序的查询路径先读配置，再按配置选择排序键和顺序
