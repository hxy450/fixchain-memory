# 源端 addAll 整批入队、不去重不设上限时，目标照样整批入队，不加去重和截断

审的是：代码
触发（任一种）：
- 读到：源端单例窗口的队列用 List.addAll(list) 整批入队、get(0) 后 remove(0) 逐个播放，没有按 id 去重，也没有 size() 上限；响应里的列表用 JSON.parseArray 整批解析后交给它；写错的样子：目标队列多了按 id 去重的 Set、超过常量条数就丢弃的截断，或解析时用 Math.min(数组.length, 常数) 只取前若干条
适用范围：迁移源端单例持有、逐个播放的全局广播、飘屏、消息横幅队列时，入队、出队和解析这几步
做法：
- 入队整批、按原顺序追加；出队逐个取队头播放，动画结束有剩余就接着播；响应列表整批转换，不截断
- 源端没有的去重、条数上限不作为默认防护加进代码
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- boolean addAll(Collection<? extends E> c)：按迭代顺序把整个集合追加到表尾：源端入队不过滤、不截断（出处：java.util.List#addAll）
- E remove(int index)：移除并返回该位置的元素，后面的元素左移：remove(0) 就是取队头逐个出队（出处：java.util.List#remove(int)）
- 源端连续播放全部广播；去掉去重、队列上限和解析上限后，重复项不再被吞、大批次不再被截断：加了去重和上限，用户看到的广播比源端少（出处：卡里修好并验证过）
