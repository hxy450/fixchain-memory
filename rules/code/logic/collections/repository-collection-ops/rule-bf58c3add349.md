# 源端队列选取不过滤状态时，目标端待推送选取同时取 pending 与 fail

审的是：代码
触发（任一种）：
- 读到：源端待推送队列的查询只有 equal(…) 按资源类型一个条件、不按同步状态过滤，失败项置 fail 后留在队列里；写错的样子：目标端待推送阶段只查状态为 `'pending'` 的记录，fail 项不再被选中
适用范围：迁移带失败标记的同步推送队列时
做法：
- 待推送选取同时取 pending 与 fail（返修在待推送阶段把 fail 并入），让失败项在下一次同步自动重推
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 待推送阶段同时取 pending 与 fail 后，失败项在下一次触发时被重推：修好后的行为（出处：卡里修好并验证过）
