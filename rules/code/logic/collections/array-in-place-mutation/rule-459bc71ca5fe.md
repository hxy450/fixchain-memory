# 源码经数组引用原地改调用方数据时，目标不要传 .slice() 副本切断这个副作用

审的是：代码
触发（任一种）：
- 读到：源码把调用方传入的 String[] 等数组按引用原地改写（如 arr[i] = 替换后的值，写回调用方持有的数组）；写错的样子：目标调用时传 arr.slice() 副本，或服务另存一份副本，改写不再回到调用方的数组
适用范围：源端依赖数组引用的原地改写副作用、迁成 ArkTS 时
做法：
- 传原数组引用并在原数组上改写（arr[i] = …），保留源端的副作用
- 不保留时，在规格里登记这条偏离，写明调用方的数据不再被原地改写
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- slice(start?: number, end?: number): T[]，返回数组一段的副本：对副本的改写不会回到原数组（出处：鸿蒙 SDK 的 ets/build-tools/ets-loader/node_modules/typescript/lib/lib.es5.d.ts，Array.slice）
- 原地写回调用方持有的数组：修好的写法（出处：卡里修好并验证过）
