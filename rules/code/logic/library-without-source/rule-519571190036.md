# 规格要求从三方库工件提取时，本地缓存为空就去取 aar 反编译，取不到登记占位

审的是：代码
触发（任一种）：
- 读到：规格或映射表写「HARD 行为等价」「实现期必须从库工件（jitpack aar 反编译或上游 tag）提取」「禁止凭印象」，源端只看得到库的配置调用链；写错的样子：自研的等价组件或序列化器按配置面近似实现（如 parse 只用 startsWith 剥行首符号），注释写「库无源码」「按 spec 取值」或自称行为权威，没有反编译对照，也没登记占位
适用范围：源端以 Gradle 远程坐标引入二进制三方库、目标端要自研行为等价实现时
做法：
- 本地 Gradle 缓存为空不是终点：按规格去 jitpack（https://jitpack.io/com/github/<owner>/<lib>/<ver>/）或上游仓库对应 tag 取 aar，unzip 出 classes.jar，用 javap -c -p 逐方法对照后照库算法写
- 取不到就登记占位，列出未核项（文本拆分判定、hint 条目位置、勾选移动档位、拖拽、序列化换行等），并在交付报告里标明，不按配置面自写近似
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- String#split(String) 等同 limit 为 0 的 split，结果末尾的空串不保留：库里用 Java split 拆文本时，目标端要照这个语义去掉尾随空串（出处：java.lang.String#split）
- 取到 aar、unzip classes.jar 并 javap -c -p 对照后，按库算法重写的序列化和组件与源端一致：返修用的做法（出处：卡里修好并验证过）
针对本应用要查的：
- 库的坐标、版本和工件：源工程构建脚本的 dependencies 里该库的 group:artifact:version；Gradle 用户缓存 caches/modules-2/files-2.1/<group>/<artifact>/<version>/ 下的 aar；没有时取 jitpack 或上游仓库同版本 tag；unzip aar 得 classes.jar，javap -c -p 读出判定、替换、拆分、排序的确切写法；例：checklistview 4.1.0 的勾选判定是 indexOf("[x] ") == 0，再 replace 全部出现，按 Java split 语义去尾随空串
