# 源方法定义在依赖库里取不到源码时，实现处标 FWD-REF 并登记缺口，不按验收条文反推

审的是：代码
触发（任一种）：
- 读到：源类 extends 依赖库里的父类，被调用的方法在源码树里找不到 .java 定义；写错的样子：目标自写了近似实现，源码理解笔记写「差异风险低」或「按 AC 行为反推」，实现处没有 `FWD-REF` 标记、决策台账里也没有这条缺口
适用范围：被翻译的源方法定义在二进制依赖（commons 一类的库）里、主仓没有它的源码时
做法：
- 先到 Gradle 缓存里找这个依赖的 jar 或 -sources.jar，反编译或读源码，核实方法体后照它实现
- 取不到时在实现处标 `FWD-REF`，并把它登记成决策缺口；不按规格的验收条文反推字段集，也不标「风险低」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 依赖库父类的 equals / 脏检查方法反编译后可得完整的比较字段集，返修照它实现：依赖库的字节码能查到真实定义，不必反推（出处：卡里修好并验证过）
针对本应用要查的：
- 这个依赖的坐标和版本：源工程模块 Gradle 构建脚本里的 dependencies 块，以及 Gradle 缓存 modules-2/files-2.1/<group>/<artifact>/<version>/；按坐标找到 jar 或 -sources.jar，在里面按类名找父类
