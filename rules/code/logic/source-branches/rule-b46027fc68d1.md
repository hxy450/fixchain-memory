# 源端只在特定方法里重建列表时，目标在同一时机更新状态，不改成渲染时派生

审的是：代码
触发（任一种）：
- 读到：Java 源码只在某个重建方法里、且条件真正变化时才重建列表（否则跳过），解析失败分支 Toast 后提前 return、不调用重建；写错的样子：ArkTS 用 @Monitor 或在 build() 里按状态即时派生列表项，称「响应式等价」；解析失败后显示新条目而不是源端留下的旧条目
适用范围：源端命令式重建列表数据、迁成 ArkUI 状态驱动界面时
做法：
- 列表项存成状态数组，只在与源端重建方法对应的函数里、按源端同样的条件赋新值；失败分支照源端提前 return，不更新列表
