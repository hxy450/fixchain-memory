# 已选城市列表为空时走显式分支，不以空编码调天气接口

审的是：代码
触发（任一种）：
- 读到：源端用 mapNotNull { it.firstOrNull()?.code } 取首个城市编码，没有城市就不发请求；写错的样子：页面以 `?.code ?? ''` 把空编码传给天气服务；城市仓储初始 `[]`、只从进程内静态存储加载，没有首启分支
适用范围：数据层和页面迁移依赖首个已选城市编码的请求时
做法：
- 列表为空时走显式分支：不调天气接口，按规格进入选城引导，或把规格定的默认城市写入保存（已有选择不覆盖）
- 持久化只在进程内时，每次冷启动都按首启处理，并在交付说明里写明这一影响
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 存储为空时写入默认城市并保存，已有选择不覆盖；真机首启直接显示天气：修好后的行为（默认城市是用户定的产品选择）（出处：卡里修好并验证过）
