# 仓储契约写明抑制判定在调用侧时，源端被调方法里的每个标志守卫都写进调用点条件

审的是：代码
触发（任一种）：
- 读到：源端写盘方法体首行自带 if(...) 标志守卫，外层 save 只判另一个标志；退出分支依次是置标志 A → 初始化方法（会把 A 改回）→ 删档 → 置守卫标志为 false → onBackPressed()；目标仓储的写入方法不判标志，注释或契约写着抑制判定在调用侧；写错的样子：目标调用仓储写入前的 if(...) 条件只有另一个标志和非空判断，没有源端写盘方法首行守卫的那个标志
适用范围：源端落盘方法自带标志守卫、目标端仓储改成不判标志的纯服务，把守卫交给调用侧时
做法：
- 把源端被调方法体内的每个守卫逐条对应到目标调用点的条件里：外层判断的标志和写盘方法首行守卫的标志都写进同一个 if(...)，写完后搜调用点确认两个条件都在
- 某个标志看似是另一标志之外的冗余保险时，按实际调用序列出各退出路径（弹窗否定分支、系统返回、页面隐藏）在写盘时刻的标志值，特别看中途调用的初始化或重置方法有没有把前一个标志改回去
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 调用侧条件改成「外层标志 && 守卫标志 && 状态非空」，并注释源端写盘方法内部先判守卫标志后，否定分支退出时删掉的存档不再被写回：修好的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端写盘链上有哪些守卫、各退出路径在写盘时刻的标志值：源工程里 save 一类方法和它调用的写盘方法的方法体首行，以及各退出分支（对话框否定按钮、onBackPressed、页面隐藏回调）里的调用序列；逐条记下守卫条件；顺着退出分支的调用序列走进中途调用的初始化/重置方法，看它对每个标志的赋值，列出写盘时刻的标志值表
