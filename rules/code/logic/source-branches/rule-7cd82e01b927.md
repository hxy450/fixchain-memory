# 源端成功分支先 close() 再 Toast 和 finish() 时，目标成功分支也要先关闭

审的是：代码
触发（任一种）：
- 读到：源端写循环结束的成功分支依次调用读写器的 close()、cancel()、Toast.makeText(...).show()、finish()；写错的样子：目标只在失败或 catch 分支 close()，成功分支直接提示并关闭页面（router.back() / pop）
适用范围：迁移源端带显式 close() 的读写、连接收尾逻辑时，各分支的收尾
做法：
- 逐分支核对源码的 close / cancel / Toast / finish 顺序，目标每个分支按同样顺序写；成功分支先 close() 再提示和关闭页面
- 规格的验收条目只写用户可见结果（「提示并关闭页面」）时，仍按源码在成功分支补 close()
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 写循环的成功分支先 close() 再提示、关闭页面：修好的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端每个分支的收尾顺序：源工程 Activity 里这个写方法的成功、失败分支；按出现顺序记下 close()、cancel()、Toast、finish() 的调用，逐分支对到目标代码
未核实：不关闭的具体后果（连接占用）卡里没有上机复现，按源码语义写
