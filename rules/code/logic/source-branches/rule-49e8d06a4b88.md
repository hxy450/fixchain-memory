# 源端计算入口的空输入守卫没有 else 时，目标不新增清空界面的分支，页面在调用前直接 return

审的是：代码
触发（任一种）：
- 读到：源端计算入口只有 if (mA != null && mB != null) { … } 分支、没有 else；输入校验失败时只 Toast 并把该侧置 null；写错的样子：目标在 null 分支里把结果清空（`= []`、`= ''`），或页面无条件用服务层对 null 输入返回的空结果覆盖界面
适用范围：移植带空输入守卫的计算入口，规格写着「缺任一为空操作」之类时
做法：
- 照源码 if 分支的范围翻译：源码没有 else 就不新增清空界面的分支，界面保留上一次结果
- 页面在调用计算前判断：if (a === null || b === null) { return }；服务层对 null 输入的空结果不拿去覆盖界面，注释写明由页面在调用前跳过
