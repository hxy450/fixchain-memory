# 源码行为像缺陷时，目标照搬可观察结果，不在注释里自定「缺陷不移植」

审的是：代码
触发（任一种）：
- 读到：Java 源码有可观察的缺陷：数组元素没赋值就用、NullPointerException 被 catch 后返回 false；字段在输入校验前赋值；后缀无条件追加；非法输入转成 null 后照样交给下层调用得到失败码；写错的样子：代码注释或源码笔记写「源缺陷不移植」「行为增强，非回归」「防御」，改成 indexOf 保序去重、endsWith 防重、首元素补空串后写入成功、遇 null 静默 return，或把校验前的赋值挪到校验之后
适用范围：迁移目标是行为等价、台账里没有登记「修正原版缺陷」决策时
不适用的情形：源端的崩溃路径按已登记的例外处理
做法：
- 照搬可观察结果：失败返回值、Toast、null 参数交给下层调用后得到的结果码、校验前已赋值的字段、无条件追加的后缀，都按源码顺序写
- 确需修正或加防御时，先在决策台账登记并上报，代码和源码笔记里不自行定案
