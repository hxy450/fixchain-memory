# 实现回调接口具体类时对照源实现类的 @Override 清单覆写，基类空默认不能当终态

审的是：代码
触发（任一种）：
- 读到：源端回调接口的实现类 @Override 了若干回调（如相机就绪、拍摄进行中），目标端实现类继承一个回调全是空默认的 Basic 基类；写错的样子：目标实现类没覆写源端覆写过的回调，引擎调来的回调落到基类的空实现；VM 上承接这个回调的同名方法在工程里没有调用者
适用范围：目标端把源端的回调接口拆成接口、带空默认的基类和具体实现类时
做法：
- 逐项对照源实现类的 @Override 清单决定覆写；源端覆写过的回调，在目标实现类里覆写并转给 VM 的承接方法（经 sink 或回调槽）
- 搜索确认 VM 上的同名承接方法确有调用者
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 实现类新增就绪回调的覆写并转到 VM，VM 在其中做就绪处理、刷新图标：修好后引擎就绪回调不再落空（出处：卡里修好并验证过）
