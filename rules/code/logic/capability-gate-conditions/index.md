# 能力门函数（supports…）的多重条件

agent 会看到什么：读到源端 supports… 一类能力门函数用 && 连着几重条件（是否由拍照 Intent 启动、大堆内存阈值、陀螺仪是否存在、预览能力）；产物里的能力判断少了条件、用 canIUse('SystemCapability.…') 设备能力位代替，或契约里缺判断入口时写成恒 false 删掉这条

## 规矩

- rule-491bc8a1b9af｜移植多条件能力门时逐条对照源条件写目标表达式，不用相近的设备能力位代替｜读到：源端 supports… 一类能力门函数里有多重条件：是否由拍照 Intent 启动、大堆内存阈值、陀螺仪是否存在、预览是否支持连拍或曝光时间，用 && 连在一起；写错：目标的能力判断少了源端的某些条件（只剩内存阈值），或用 canIUse('SystemCapability.Sensors.Sensor') 这类设备能力位代替陀螺仪是否存在；注释写着陀螺仪，实现却不是
- rule-c238a95bf35d｜契约缺某个判断入口时，在能力类构造里留注入点或登记 FWD-REF，不写恒 false 删门控｜读到：源端能力门先判是否由拍照 Intent 启动，目标端的应用接口契约里搜不到对应的判断入口；写错：能力类注释写 `无入口，恒 false 近似`，各能力门里这条判断整条删掉；能力类和上层控制器的构造参数里没有它的来源，也没有登记 FWD-REF
