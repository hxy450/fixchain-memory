# 组装请求参数前核对经纬度来源，只有 ID 或经纬度为空时先查库补齐

审的是：代码
触发（任一种）：
- 读到：源端 ViewModel 请求前用 DAO 的按 ID 查询（@Query）回填 `lon` / `lat`；写错的样子：目标直接用传入城市对象的 `lon` / `lat` 构造请求，首页和详情跳转都取它；对象只有 ID 时请求带空经纬度
适用范围：实现接口请求参数组装、请求对象可能只有 ID 时
做法：
- 发请求前判断：只有 ID 或经纬度为空时，先 await 查本地库按 ID 取回经纬度再组装请求
- 把补齐后的对象作为首页请求和各详情跳转的唯一来源，ID 一致时复用这份结果
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 请求前调用按 ID 查询补齐经纬度，详情页复用补齐后的对象后，首页和详情请求都带完整经纬度：卡里修复后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端补齐参数的方法：源工程 ViewModel 里发请求前调用的查库方法和对应 DAO 的 @Query；看它回填了请求对象的哪些字段，目标在同一时机补齐同样的字段
