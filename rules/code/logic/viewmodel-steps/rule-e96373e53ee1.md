# 源 ViewModel 推进后主动预取后续几张图时，目标 ViewModel 实现预解码并给缓存设上限

审的是：代码
触发（任一种）：
- 读到：源 ViewModel 在加载完成和每次推进后调预取方法：排除已处理、已跳过、有挂起变更的项和视频，取后续 3 项，用 Coil 的 imageLoader.enqueue 预取到内存缓存；写错的样子：目标 ViewModel 里没有任何预加载字段、方法或调用；页面只用 Image 组件按需显示当前项
适用范围：ViewModel 迁移阶段，源端有显示前主动预取或预解码后续若干项图片的行为时
做法：
- 在 ViewModel 里加预取方法：按源端同样的规则选后续最多 N 个（跳过已处理、已跳过、挂起项和视频，N 取源端的数）
- 对每一项 image.createImageSource(uri).createPixelMap() 解码，放进有上限的缓存（卡里上限 6 个）
- 在加载完成和每次推进的末尾调用这个方法，与源端调用时机一致
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- createImageSource(uri: string): ImageSource；失败时返回 undefined：按 URI 创建图片源（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.image.d.ts，image.createImageSource）
- createPixelMap(options?: DecodingOptions): Promise<PixelMap>：ImageSource 按解码参数异步解码出 PixelMap（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.image.d.ts，ImageSource.createPixelMap）
- createImageSource(fd: number): ImageSource；createImageSource(buf: ArrayBuffer): ImageSource：同族接口：按文件描述符或缓冲区创建图片源（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.image.d.ts，image.createImageSource）
- createPixelMapSync(options?: DecodingOptions): PixelMap；解码失败返回 undefined：同族接口：同步解码（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.image.d.ts，ImageSource.createPixelMapSync）
- 最多选 3 个非视频后续项，createImageSource(uri).createPixelMap() 解码放进最多 6 个的缓存，在推进末尾调用：返修后的写法，编译通过（出处：卡里修好并验证过）
针对本应用要查的：
- 源端预取的数量、排除规则和调用时机：源 ViewModel 里的预取方法（filter 条件、take(N)）和调用它的地方（加载、推进处理）；照搬过滤条件和 N，在目标对应的加载和推进方法末尾调用
