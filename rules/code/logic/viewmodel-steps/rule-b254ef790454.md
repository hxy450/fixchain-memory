# 源端操作写入仓库后才提示成功时，目标先写入共享状态再 showToast，不用成功提示占位

审的是：代码
触发（任一种）：
- 读到：ViewModel 的提交方法先校验参数，再经 Repository 写入（同键累加、新项追加），最后关闭弹层并提示成功；写错的样子：确认分支里只有 showToast(...) 的成功提示，Service 里没有对应的写入方法，也没有写到别的页面能读到的状态
适用范围：安卓端「加入购物车」这类经 Repository 落库的写操作，迁成 ArkUI 页面和 Service 时
做法：
- 在 Service 里补写入方法，按源端规则写进别的页面能读到的共享状态（修复用 AppStorageV2.connect 取出的 @ObservedV2 类实例，同键累加、新项追加）
- 确认分支先调用写入方法，写入后再关闭弹层并 showToast；本轮不实现写入时不写成功提示，并在完成汇报里写明未写入
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- static connect<T extends object>(type: TypeConstructorWithArgs<T>, keyOrDefaultCreator?: string | StorageDefaultCreator<T>, defaultCreator?: StorageDefaultCreator<T>): T | undefined：AppStorageV2 取出或创建应用级共享对象；只存在内存里，与应用同生命周期（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.StateManagement.d.ts，AppStorageV2.connect）
- declare const ObservedV2: ClassDecorator：共享状态类加 @ObservedV2，被观察的属性加 @Trace（出处：鸿蒙 SDK 的 ets/component/common.d.ts，ObservedV2）
- declare const Trace: PropertyDecorator：@ObservedV2 类里需要触发界面刷新的属性（出处：鸿蒙 SDK 的 ets/component/common.d.ts，Trace）
- 写入改为按商品聚合的 AppStorageV2 + @ObservedV2 共享状态，确认分支调用写入方法：购物车页能读到加购结果（出处：卡里修好并验证过）
针对本应用要查的：
- 写操作的合并规则（同键累加还是覆盖、新项怎么追加）：源工程 ViewModel 的提交方法和它调用的 Repository 方法（.kt 文件里按方法名找）；逐个分支读出：查已有记录的键、同键时怎么改数量、新键时怎么写入，照写到目标 Service 的写入方法
未核实：卡里记的环境没写鸿蒙 SDK 版本，本机按 API 23 的声明核实
