# 按 BusinessError.code 分派错误码分支时，先 Number(code) 归一再比较，不直接 ===

审的是：代码
触发（任一种）：
- 读到：d.ts 里接口写着 @throws { BusinessError } 加数值错误码（如 geoLocationManager 的 3301100 定位开关关闭），@ohos.base 的 BusinessError.code 声明为 number；写错的样子：catch 里写 (error as BusinessError).code === 某个 number 常量，没有归一；新增分支照抄已有的这种 === 判别
适用范围：ArkTS 代码 catch Kit 接口同步抛出或 Promise 拒绝的 BusinessError，并按错误码分派不同行为时
做法：
- 写成 Number((error as BusinessError).code) === 常量（或同时接受数值和字符串两种形式），再进对应分支
- 沿用或新增已有代码里的错误码判别时，同样改成归一后的比较，不照抄 === 写法
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- code: number：BusinessError.code 的声明类型；运行时实际可能是字符串，声明不是运行时保证（出处：鸿蒙 SDK 的 ets/api/@ohos.base.d.ts，BusinessError.code）
- function on(type: 'locationChange', request: LocationRequest | ContinuousLocationRequest, callback: Callback<Location>): void，@throws { BusinessError } 3301100 - The location switch is off.：定位开关关闭时同步抛出 3301100（出处：鸿蒙 SDK 的 ets/api/@ohos.geoLocationManager.d.ts，geoLocationManager.on）
- 开关关闭时 on 同步抛出的 code 打印为 {"code":"3301100"}（字符串）；改成 Number(code) === 3301100 后分支命中：运行时观察和修好后的写法（出处：卡里修好并验证过）
未核实：卡里的鸿蒙 SDK 是 6.1.1(24)，声明照本机 API 23 核实；code 是字符串只在定位 Kit 的 on('locationChange') 上观察到
