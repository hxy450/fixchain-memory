# catch 里新增错误日志时沿用工程的 hilog 写法写 hilog.error，不写 console.error

审的是：代码
触发（任一种）：
- 读到：源端 Kotlin runCatching { audioTrack.stop() } 之类静默吞错、没有 Log 调用；工程里已有 import { hilog } from '@kit.PerformanceAnalysisKit' 和 TAG、DOMAIN 常量；写错的样子：服务层或 ViewModel 的 catch 里新写了 console.error(`… ${error}`) 或 console.log(...)
适用范围：功能实现阶段，在服务层或 ViewModel 的 catch 分支为新增的错误处理写日志时
不适用的情形：已登记的占位（流水线规定的占位写法）不在此列
做法：
- 先搜工程现有的日志写法，沿用它的 import { hilog } from '@kit.PerformanceAnalysisKit'、DOMAIN 和 TAG（TAG 取当前类名），写 hilog.error(DOMAIN, TAG, '<说明>: %{public}s', String(error))
- 写完一个切片后在改动的 .ets 里搜 console.，除已登记的占位外每个命中都改成 hilog；源端静默吞错时新增的日志也照此写
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function error(domain: number, tag: string, format: string, ...args: any[]): void：错误级日志（出处：鸿蒙 SDK 的 ets/api/@ohos.hilog.d.ts，hilog.error）
- export { …, hilog, … }（import hilog from '@ohos.hilog'）：hilog 从 @kit.PerformanceAnalysisKit 导入（出处：鸿蒙 SDK 的 ets/kits/@kit.PerformanceAnalysisKit.d.ts）
- 隐私标识符缺省为 private，打印结果不可见；%{public}s 明文显示 string 参数：错误信息要写 %{public}s 才看得到（出处：hilog-guidelines-arkts.md，参数解析）
- domain 是 0x0–0xFFFF 的十六进制整数，超出范围不打印；tag 不超过 32 字节，超出截断：DOMAIN、TAG 的限制（出处：鸿蒙 SDK 的 ets/api/@ohos.hilog.d.ts，hilog.error）
- function warn(domain: number, tag: string, format: string, ...args: any[]): void：同族接口：警告级日志，参数相同（出处：鸿蒙 SDK 的 ets/api/@ohos.hilog.d.ts，hilog.warn）
针对本应用要查的：
- 工程已有的 DOMAIN 和 TAG 写法：目标工程 .ets 文件里 hilog 的导入和调用处（脚手架的 EntryAbility 常有）；照抄它的 import 和 DOMAIN 常量；TAG 换成当前类名
