# 辅助接口请求和主体加载写在同一个 try 里时，拆成独立 try/catch，失败不覆盖已有列表

审的是：代码
触发（任一种）：
- 写错的样子：辅助请求的 `await` 赋值放在主体加载同一个 `try` 的末尾：没成功就用 [] 覆盖已有列表，抛异常就落进主 `catch` 把整次加载置成错误
适用范围：一个页面的加载里既有主体数据又有可失败的辅助接口请求，规格验收条目要求两者成败互不影响（如「失败时不覆盖当前成功列表」）时
做法：
- 把辅助请求放进独立的 try/catch；只在请求未过期（仍是当前选中项发起的）且结果非空时替换列表，失败时保留原列表，也不改主体的加载状态
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 辅助请求独立 try/catch、只在未过期且非空时替换后，请求失败不再破坏主体：修复后的写法（出处：卡里修好并验证过）
