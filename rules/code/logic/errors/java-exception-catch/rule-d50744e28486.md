# SDK 异常 message 是错误码原文时，目标异常类保留原值，状态码放独立字段

审的是：代码
触发（任一种）：
- 读到：SDK 异常的 message 是服务端错误码原文；下游（如登录错误文案映射）按 exception.message 字符串匹配；写错的样子：目标异常类把 message 拼成 `HTTP ${code}: ${errorText}` 这类字符串，下游的 message 匹配永远不命中
适用范围：手写网络客户端替代三方 SDK 时，代码里的自定义异常类和下游按 message 匹配的地方
做法：
- 异常类构造时 super(<错误码原文>)，状态码等附加信息放在独立字段，不拼进 message
- 写完后 grep 下游按 message 匹配的消费点，逐一核对能命中
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 修好后 message 恢复为错误码原文：登录错误文案匹配恢复命中（出处：卡里修好并验证过）
