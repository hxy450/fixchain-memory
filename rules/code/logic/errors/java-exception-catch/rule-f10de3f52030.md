# 迁移 EXIF 写入的失败和早退语义时只兜源端实际 catch 的异常，没有早退就不加 return

审的是：代码
触发（任一种）：
- 读到：源 updateExif 声明 throws IOException，只 catch NoClassDefFoundError；setExifFromData 没有早退，源图没有 EXIF 也照常 setExif → modifyExif → removeExifTags；写错的样子：目标 updateExif 用 catch (error) 吞掉全部异常并原样返回，注释称与源兜底同义；setExifFromData 在源图无 EXIF 时 return
适用范围：把源端带异常兜底和条件分支的元数据写入流程迁到 ArkTS 时
做法：
- 只对源端实际 catch 的异常类型做等价兜底；源方法 throws IOException 的写入失败要上抛（如 throw new Error('failed to update image metadata')），不保存未处理的元数据
- 源端没有早退的路径照常执行：源图无 EXIF 时用一个空文档（如 ?? new ExifDocument()）继续，不新增 return
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 改为空文档继续、写入失败上抛后，源图无 EXIF 时也写入元数据，失败不再静默保存：修复后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端实际捕获的异常和早退点：源工程写元数据的方法体：throws 声明、catch 子句的异常类型、方法开头的 return；只把 catch 到的类型映射成兜底，其余照 throws 上抛；没有 return 的分支在目标端也不加
