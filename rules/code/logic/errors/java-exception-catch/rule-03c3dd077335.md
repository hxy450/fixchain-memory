# 移植 try/catch 时保持源端异常作用域和遍历顺序，整个循环一个 try 就首错即停

审的是：代码
触发（任一种）：
- 读到：源端 for 循环整个包在一个 try { … } catch (IOException e) 里，遍历 AssetManager.list(...) 返回的文件名；写错的样子：目标改成循环体内逐项 try/catch、失败后继续，或不按文件名而按自己排的固定顺序遍历 getRawFileListSync 等取到的列表，注释称单项失败只记日志
适用范围：移植源端带 try/catch 的循环（如逐个复制资源文件）时
做法：
- 异常作用域照源端：源端整个循环一个 try，目标也整个循环一个 try/catch，首个失败即停止；不按「更健壮」改成逐项 try
- 遍历顺序照源 API：AssetManager.list 按文件名排序，目标取到文件名列表（如 resourceManager.getRawFileListSync(path)）后同样按文件名排序再遍历
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 修复恢复整循环一个 try 和 AssetManager.list 的文件名顺序：修好后的写法（出处：卡里修好并验证过）
- getRawFileListSync(path: string): Array<string>：取 rawfile 目录下的文件列表；声明里没写返回顺序（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getRawFileListSync）
- getRawFileList(path: string): Promise<Array<string>>：同族接口：Promise 版本（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getRawFileList）
未核实：AssetManager.list 按文件名排序出自卡；Java 源码里由 native 实现，没查到排序的原文；getRawFileListSync 的返回顺序声明没写
