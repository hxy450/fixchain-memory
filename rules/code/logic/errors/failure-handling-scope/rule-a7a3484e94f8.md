# 逐个对照源函数的 try/catch 作用域，保持相同的中断和继续语义

审的是：代码
触发（任一种）：
- 读到：源端辅助函数内部自带 `try { … } catch (e: Exception)`（失败只记日志）；写错的样子：目标辅助函数没有内部 `catch`，异常冒泡到调用方，调用方后续的持久化（如 hash 落库）被跳过
- 读到：源端循环里 decrypt(...) 一类调用没有逐条 `catch`，抛错落到外层 catch 中断整批；写错的样子：目标给每条记录包 `try` / `catch`，解密失败也推进游标并 `continue`
- 读到：源端 chunked(N).forEach { 发送一批 } 忽略单批失败结果；写错的样子：目标首批失败就 `return` 失败值，后续批次不再发送
适用范围：实现阶段迁移带循环、批次或辅助函数的源函数时
做法：
- 按源码的 catch 位置写：辅助函数内部的 catch 照搬；源端没有逐条 catch 的调用，目标也不逐条 catch；源端忽略单批结果的，目标每批独立 try 后继续，结束返回成功
- 规格和已读源码不一致时以源码为准，并在报告里写明差异，不只在注释里引用规格条目
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 辅助函数外包 try / catch 不再阻断后续持久化；解密异常中断整批；每批独立 try / continue：修复后按源码恢复的语义（出处：卡里修好并验证过）
