# 带结果回调的拦截和分支

agent 会看到什么：源端回调按 result.on(true) 继续、result.on(false) 中止（如登录拦截后续做原操作）；产物里拦截处只 return 中止，或注释写「对齐源端回调」却少了分支

## 规矩

- rule-4b97cc932668｜源端登录拦截成功后会继续原操作时，目标暂存待执行动作，页面重新可见时续做｜读到：源端需登录的操作带结果回调：未登录拉起登录页并 observe 登录结果，仍未登录才 result.on(false)，登录成功则 result.on(true) 继续原操作（如应用所点的选项）；写错：目标端拦截处只调登录守卫跳转登录页然后 `return` / return false 中止，没有暂存所点的动作，从登录页回来后原操作丢失
- rule-d591c4c13624｜注释写「对齐源端回调」前核对已覆盖全部分支，省略的要写明｜读到：源端回调有多个分支（如 result.on(true) 继续、result.on(false) 中止）；写错：代码注释写「对齐源端…回调」，实现里只有其中一部分分支（如只有拦截和 `return` 中止），注释和完成报告都没说明省略了哪一步
