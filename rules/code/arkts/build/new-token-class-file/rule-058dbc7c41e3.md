# 新建但没被页面或 Ability 导入的 .ets 不进全量编译，报告构建通过前先接一处导入或单独检查

审的是：代码
触发（任一种）：
- 读到：派工要求输出新的 .ets（如主题令牌类），或要求 worker 不跑全量构建；写错的样子：新建的 .ets 没有被任何 @Entry 页面或 UIAbility 链路 import，报告却写全量构建通过
适用范围：编码阶段新建、但当时还没被页面或 Ability 导入的 .ets 文件
做法：
- 落盘后临时接一处导入或单独跑 ArkTS 检查，按这次结果报告通过；没检查到的文件在报告里写明未编译
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 没有文件导入的 .ets，全量构建通过时并没有编译它；一被导入，潜伏的类型错误立刻报出：全量构建通过不代表新文件过了检查（出处：卡里修好并验证过）
