# 搬页面时按入口调用方和业务定去向，不按它 import 了哪个模块的 ViewModel

审的是：代码
触发（任一种）：
- 读到：被搬的页面 import 了某个业务模块的 ViewModel 或 Service，但它的入口是另一模块里列表页的条目跳转；写错的样子：页面按「import 了哪个模块的 ViewModel」被移进那个模块，同一业务对象的列表、新增页和详情、编辑页及 Model、Service、ViewModel 分在两个模块
适用范围：执行模块搬迁、按计划把页面和数据层移进各业务模块时
做法：
- 定页面去向看入口调用方（路由、Tab、跳转来源）和业务语义：详情、编辑页跟它的列表页走，不看它当前 import 了哪个模块的 ViewModel
- 发现同一业务对象被拆在两个模块时不就地沿用，回到规划补归属决定；修好的样子是这个业务对象的页面和 Model、Service、ViewModel 放进同一模块下的同一纵向目录，原模块的 Service 删去它的方法
