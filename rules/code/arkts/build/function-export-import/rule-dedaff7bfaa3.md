# 组件要复用路由页面模块里的函数时，先迁到普通模块再导入，不从页面模块导入

审的是：代码
触发（任一种）：
- 读到：要复用的校验或工具函数定义在 pages/ 下经系统路由表或 pageMap 注册的页面模块里（文件里有供路由装配的 @Builder），工程另有 services/ 这类放共享逻辑的非页面目录；写错的样子：新组件里写了 `import { … } from '../../pages/…'`，从页面模块导入非 UI 函数；或者页面模块为此把原本私有的 `function` 改成 `export function`
- 读到：页面模块里的具名导出注释写着只「供 UT 消费」、是「最小导出 seam」；写错的样子：组件或别的页面这类生产代码用 `import { … } from '…/pages/…'` 引入了这个只供测试的导出
适用范围：ArkTS 工程里新组件（会被主 Ability 首页静态导入）要复用页面模块里的非 UI 函数，工程同时带 ohosTest 单测和 UI 测试套件时
做法：
- 把函数和它用到的常量原样迁到普通模块（如 services/ 下新建一个 .ets 文件）并 export；页面模块删掉本地定义，改从这个模块 import
- 新组件和单测都改从这个普通模块导入；页面模块不为复用新增具名导出，标着供 UT 的导出只当测试接缝
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 函数迁到 services/ 下的普通模块，页面、组件、单测都从它导入后，两种 flavor 重建重装，UI 套件运行不再崩溃：返修后的放置方式（出处：卡里修好并验证过）
未核实：崩溃机理（entry 与 entry_test 两个 hap 的模块记录同时存在时绑定错位）是修复者推断的，没有单独复现；同样的 does not provide an export name 报错，文档里另有一种成因：开启导出名混淆后跨模块导入（source-obfuscation-questions.md），与卡里的情形不同
来源：1 张卡，1 个应用
