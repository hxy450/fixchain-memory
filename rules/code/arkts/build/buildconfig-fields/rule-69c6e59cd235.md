# 源端条件里的 BuildConfig.DEBUG 腿写成 BuildProfile.DEBUG，不以无等价为由删掉

审的是：代码
触发（任一种）：
- 读到：源端显隐条件含 BuildConfig.DEBUG（如 BuildConfig.DEBUG || 某开关）；写错的样子：目标端表达式只剩另一腿，没有 BuildProfile.DEBUG；注释写「DEBUG 腿无 HMOS 运行期等价」「无构建标志基建」「按 release 语义」
- 读到：页面规格、AC 或已批准决策写「DEBUG 构建 || X 时可见」「DEBUG 构建恒可见」；写错的样子：实现因 entry 根目录没有 BuildProfile.ets、src 里 grep 不到 DEBUG，就判定没有构建标志而删掉 DEBUG 腿
- 读到：移交项 uncertain_regions_retained 写 DEBUG 腿「无运行期等价」，派工写「按保留注记处置」；写错的样子：收口后表达式仍没有 BuildProfile.DEBUG，注释改以签名策略（unsigned 统一构建）为理由
适用范围：源端、规格或决策的条件含 BuildConfig.DEBUG，目标是 hvigor 构建的 HarmonyOS 工程时
做法：
- 文件头 import BuildProfile from 'BuildProfile'，条件写成 BuildProfile.DEBUG || <其余各腿>，各腿顺序照源端；删掉「无等价」一类不实注释
- 签名策略（是否签名）与 debug/release 构建类型无关，不能作删 DEBUG 腿的理由；收口时先复核保留注记的前提，再对照 AC 原文
- 审时搜注释里提到 DEBUG 或 BuildConfig.DEBUG 的位置，核对同一处表达式真的含 BuildProfile.DEBUG
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- import BuildProfile from 'BuildProfile'；BuildProfile.DEBUG：hvigor 构建期生成，debug 构建为 true，默认就有，不用改 build-profile.json5；生成文件在 entry/build/<product>/generated/profile/<target>/BuildProfile.ets，源码目录里看不到（出处：卡里修好并验证过）
- 改成 BuildProfile.DEBUG || <原另一腿> 后，debug HAP 与 Android debug 基线一致显示入口：改法的依据（出处：卡里修好并验证过）
