# 跨模块用类时只从模块包名入口导入，不改成跨进别的模块 src/main/ets 的相对路径

审的是：代码
触发（任一种）：
- 读到：代码里已有 import { … } from '<模块包名>'；静态检测报 orphan 并建议 `import ... from '<relative-path>'`；写错的样子：跨模块的类被改成 from '../../../…/<另一模块>/src/main/ets/…' 这样的相对路径导入
适用范围：HAP 或 HAR 使用另一个 HAR 模块里的类、组件时的导入写法
做法：
- 写成 import { 类名 } from '<模块包名>'，类由那个模块的 Index.ets 导出；没导出的先在 Index.ets 里补 export
- 检测因不解析模块名而报 orphan 时，记成误报或修检测配置，合法的模块入口导入不动
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Index.ets 是 HAR 导出声明的入口，由 oh-package.json5 的 main 字段指定：别的模块能导入的类都在这里导出（出处：har-package.md，开发）
- import { Log, func } from 'library';：引用 HAR 导出的类和方法用模块名导入（出处：har-package.md，引用HAR的类和方法）
