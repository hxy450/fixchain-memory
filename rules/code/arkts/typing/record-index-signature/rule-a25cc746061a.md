# 查询参数让请求工具收 Map<string,string> 或参数类，不加索引签名适配 Record 形参

审的是：代码
触发（任一种）：
- 写错的样子：为适配 `Record<string, string>` 形参给参数类加 `[key: string]: string`，或把 `Record` 字面量写成标识符键 `{ page: '1' }`、改成带 `Record<string, string>` 注解的变量仍是标识符键
适用范围：目标工程启用 ArkTS 严格检查、请求工具的查询参数形参是 Record 时
做法：
- 请求工具改收 `Map<string, string>`（内部用 forEach 拼接）或明确的参数类；调用方 `const q = new Map<string, string>(); q.set('page', '1');` 后传入
- 不给类加 `[key: string]` 索引签名去适配 Record 形参；保留 Record 字面量时键写字符串字面量 `{ 'page': '1' }`，并以本工程编译结果为准
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- arkts-no-indexed-signatures，级别错误，错误码 10605017：ArkTS 不允许 index signature（出处：typescript-to-arkts-migration-guide.md，不支持index signature）
- 用 Record 类型给对象字面量标注类型时，key 要用字符串：{ 'value': 123, 'name': 'abc' }：标识符键的 Record 字面量不行，引号键可以（出处：arkts-more-cases.md，使用Record类型为object literal标注类型，要求使用字符串作为object literal的key）
- 同次编译里引号键的 headers Record 字面量通过、标识符键的 { page: '1' } 被拒；改成 Map 形参、调用方 new Map 后 set 通过：卡里的编译结果（出处：卡里修好并验证过）
