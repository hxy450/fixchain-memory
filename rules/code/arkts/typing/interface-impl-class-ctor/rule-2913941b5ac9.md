# 把已有类实例交给接口参数时，写 implements 该接口的适配类再传，不靠结构兼容

审的是：代码
触发（任一种）：
- 读到：目标参数类型是新声明的接口（`interface` 只声明方法签名），手头的对象是没有 `implements` 它的独立 class；工程里已有 class … implements … 的适配写法；写错的样子：直接把这个类实例传给接口参数（编译报 `arkts-no-structural-typing`），或改用箭头函数属性的对象字面量实现该接口
适用范围：ArkTS 启动装配或接线时，把已有类的实例交给以接口为类型的参数
做法：
- 写 class <适配类> implements <接口>，在方法里转调已有实例，传 new <适配类>(<已有实例>)；参照工程里已有的 implements 适配类
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- ArkTS不支持structural typing，编译器无法比较两种类型的public API并决定它们是否相同。使用其他机制，例如继承、接口或类型别名。：规则 arkts-no-structural-typing，级别错误，错误码 10605030（出处：typescript-to-arkts-migration-guide.md，不支持structural typing）
- 直接传实例报 arkts-no-structural-typing；先改的对象字面量也不行，最后改成 implements 该接口的类后通过：修好后的写法（出处：卡里修好并验证过）
未核实：卡里的编译报错出自 API 26（target_sdk 26.0.0）工具链，文档副本没有标 API 版本
