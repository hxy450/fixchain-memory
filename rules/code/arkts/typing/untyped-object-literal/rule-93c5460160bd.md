# 编译修复把路由载荷的 Record 或对象字面量类型改成具名接口时，字段名取自调用方和目标页解析

审的是：代码
触发（任一种）：
- 读到：构建日志报 arkts-no-obj-literals-as-types 或 arkts-no-any-unknown，路由表里目标页的载荷类型是 Record<string, string> 或对象字面量类型；写错的样子：新写的 interface 字段名在各调用方 pushPathByName 的参数和目标页 pathInfo.param 的解析里都找不到，源 Activity 的 Intent extra 键里也没有
适用范围：为消除 ArkTS 类型检查错误，把路由载荷的宽类型或对象字面量类型改成具名 interface / class 时
做法：
- 改之前先搜目标页名的所有 pushPathByName 调用传了哪些字段、目标页从 pathInfo.param 读哪些字段，再看源 Activity 的 Intent extra 键；新接口的字段名照这些写，不自拟
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- arkts-no-obj-literals-as-types（错误码 10605040）：ArkTS 不支持用对象字面量声明类型，用类或接口声明：报这个错时只需把类型改成 interface / class，字段沿用原来的（出处：typescript-to-arkts-migration-guide.md，对象字面量不能用于类型声明）
- arkts-no-any-unknown（错误码 10605008）：不支持 any 和 unknown，显式指定具体类型：解析 pathInfo.param 时要落到具体的载荷接口上（出处：typescript-to-arkts-migration-guide.md，使用具体的类型而非any或unknown）
