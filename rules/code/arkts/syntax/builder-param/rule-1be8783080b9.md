# @BuilderParam 槽的箭头函数体只转调 @Builder，槽里要放自定义组件先抽成 @Builder

审的是：代码
触发（任一种）：
- 读到：共享容器组件声明 `@BuilderParam content: () => void = this.默认Builder`，已有调用范例写成 `content: () => { this.某个Builder() }`；写错的样子：传给 `@BuilderParam` 的普通箭头函数体里直接实例化了自定义组件（如 `content: () => { 另一个容器组件({ ... }) }`），多层嵌套时只给最内层抽了 `@Builder`
适用范围：给自定义组件的 @BuilderParam 槽传内容，尤其共享容器组件层层嵌套两层以上时
做法：
- 箭头函数体只写 `this.<本组件的 @Builder 方法>()`；槽内容里只要出现自定义组件实例化，先抽成本组件的 `@Builder 方法名() { 组件({...}) }`，再传 `content: () => { this.方法名() }`
- 多层嵌套逐层核对：每一层的 content 都由自己的 @Builder 承载，不能只给最内层抽 @Builder
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- @BuilderParam 装饰的变量只能通过 @Builder 函数初始化：槽内容要由 @Builder 承载（出处：arkts-builderparam.md，限制条件）
- (): void => { this.componentBuilder() }：文档里传给 @BuilderParam 的箭头函数写法，函数体只调用 @Builder（出处：arkts-builderparam.md，初始化@BuilderParam装饰的方法）
- 箭头函数体里直接实例化自定义组件时编译通过，运行到 this.content() 抛 TypeError: class constructor cannot called without 'new'；抽成 @Builder 后冷启不再崩溃：这个错只在运行期首次渲染时暴露（出处：卡里修好并验证过）
未核实：官方文档没有明文写「@BuilderParam 箭头函数体内不得直接实例化自定义组件」，规则出自卡里的运行期崩溃和修复后验证
