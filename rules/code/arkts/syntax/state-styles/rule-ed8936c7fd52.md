# 编译修复只改构建日志报错的那一处，没报错文件里的同型写法原样保留

审的是：代码
触发（任一种）：
- 读到：构建日志的报错（如 10905203 '.stateStyles' doesn't conform standard）只指向某个文件的某一行，别的文件里有同型写法但没报错；写错的样子：改动里连日志没报错的文件中同型的 .stateStyles 写法也改了（报告里称「潜伏同型」），原来的 @Styles 方法留着不再使用
适用范围：编译门或编译修复阶段按构建日志改代码时

- 只改日志报错的那一处引用；没报错文件里的同型写法不动，等下一轮构建的真实结果出来再判断
- 凭「搜不到某个关键字」推出的限制（如「@ComponentV2 不登记 @Styles」），先拿一个没报错的同型文件反证，再决定改动范围
