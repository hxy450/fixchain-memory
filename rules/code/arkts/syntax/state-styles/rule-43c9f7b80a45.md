# 同文件有多个 struct 时，stateStyles 用内联样式块或全局 @Styles，不引用成员的

审的是：代码
触发（任一种）：
- 读到：构建日志对 .stateStyles 报 10905203 '.stateStyles' doesn't conform standard，报错的文件里除页面外还有别的 struct（如页内弹窗组件）
- 写错的样子：同一 .ets 文件里有两个以上 `struct`，其中 .stateStyles 的状态值写成 this.… 引用成员 @Styles 方法
适用范围：同一 .ets 文件里有两个以上 struct 时的 .stateStyles 写法（卡里观察到的是两个 @ComponentV2 struct；单 struct 的页面引用成员 @Styles 可以编译运行）
做法：
- 这类文件里状态值写以点号开头的内联样式块 pressed: { .backgroundColor($r(…)) }，或改用全局 @Styles function 的名字，不写 this.<成员 @Styles 名>
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 两个 @ComponentV2 struct 的文件拒绝 pressed: this.<成员 @Styles>（报 10905203），单 struct 的 V2 页面接受；改成内联样式块后编译通过、页面能打开：卡里观察到的条件和修法（出处：卡里修好并验证过）
- pressed: { .backgroundColor('#ff707070') }：内联样式块写法（出处：arkts-statestyles.md，基础场景）
- 全局 @Styles 要在方法名前加 function，组件内的不加：全局 @Styles 的定义写法（出处：arkts-style.md，装饰器使用说明）
未核实：ets-loader 为何在多 struct 文件里拒绝成员 @Styles 引用没有查清，只观察到单、双 struct 的差异；只在 @ComponentV2 的文件上观察过，@Component 的多 struct 文件是否同样拒绝没有核实
