# build() / @Builder 组件树压成一行、if 块后带分号或不带花括号时，拆成多行并补花括号

审的是：代码
触发（任一种）：
- 写错的样子：build() 或 @Builder 里组件树写在一行用分号拼接，if 块后接分号：`if (...) { this.…() }; if (...) {...}`，或 `} else {...}; Text(...)`
- 写错的样子：条件分支不带花括号：`if (cond) Image(...); else Text(...)`，或 `if (flag) ListItem() {...} else if ...`
适用范围：ArkTS 声明式页面（@Entry 加 @Component 或 @ComponentV2）的 build() 和 @Builder 方法体
做法：
- 每个组件、每个 if / else 分支、每个 ForEach / Repeat 各占独立行；if / else 一律带花括号，块后不加分号
- 交付前在写出的 .ets 里搜右花括号紧跟分号的位置和无花括号的 if / else 组件分支，逐一改成合法写法
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 10905209：Only UI component syntax can be written here.：build() 里出现 UI 语法以外的内容（如块后的分号构成的空语句）时的编译错误（出处：_ark_ui_compile.md，10905209 build()方法UI语法校验异常）
- 条件渲染支持 if、else 和 else if；每个分支内部必须遵循构建函数的规则，并创建一个或多个组件：build() 里允许的条件控制流和分支要求（出处：arkts-rendering-control-ifelse.md，使用规则）
- 改为多行、条件块补花括号、去掉块后分号后编译通过：修好的写法；编译报错的列号正指向块后的分号（出处：卡里修好并验证过）
