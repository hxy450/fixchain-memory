# 源端只在断连事件里写的占位串，目标不拿来当状态初值，初值用空串

审的是：代码
触发（任一种）：
- 读到：源端只在 BluetoothGatt 断连事件的分支里写入占位串（如 "-- °C" / "-- m"），收到读数时写读数；规格写「断连置 …」；写错的样子：目标状态类的 @Trace 字段初值直接用这个断连占位常量，未连接外设时就显示断连占位
适用范围：服务层为事件驱动的状态（外设读数 OSD 这类）确定初值，源端占位只由某个事件写入时
做法：
- 初值按源端还没收到任何事件时的语义设：源端该行初始为 null、不绘制，目标初值就是空串；占位只在断连事件到达时写入
- 单测核对：未连接时 OSD 为空，断连事件后显示占位
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 初值改成空串，只有读数或真实断连事件到达后才显示：修好后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端这一行在没收到事件时显示什么：源工程里绘制这一行的 View 或自绘代码，按该字段的初值和 null 判断找；初值为 null 且 null 时不绘制，目标就用空串；有显式初值的照抄
