# 源端从 assets 文本解析层级数据时，目标先按源解析规则转成目标数据，不写少量硬编码条目

审的是：代码
触发（任一种）：
- 读到：源 ViewModel 从 assets 下的文本文件解析出省→市→区这类层级数据，热门列表只是从中取几个名字；写错的样子：目标的数据仓库里只有十几个硬编码条目的数组字面量（`[{...}, ...]`），层级数据和热门数据返回同一扁平列表；或注释写着默认数据为兜底列表、待注入资产文件
适用范围：源端页面的数据来自 assets 资产文件（区域、城市等层级数据）、迁成 ArkUI 页面时
做法：
- 写页面之前，先把源 assets 文本按源 ViewModel 里的解析规则转换成目标数据：保持源端的层级（例：省→市→区，直辖市在省级带 code）；热门列表、全量列表、各层级子列表都从这份数据取
- 不拿少量硬编码条目当作全量数据
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 由源 assets 文本生成目标端的区域数据，再在其上实现级联选择：修好的做法：数据先转换，页面后写（出处：卡里修好并验证过）
针对本应用要查的：
- 资产文件的格式和源端的解析规则：源工程 assets 目录下的文本文件，以及读取它的 ViewModel / Repository 里的解析函数；读出分隔符、层级字段、code 的取法和热门列表的取法，转换时照搬
