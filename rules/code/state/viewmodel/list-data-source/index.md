# 列表、选项和页面模型数据的来源

agent 会看到什么：读到源 ViewModel / Repository 从 assets 文本解析层级数据、按 <Bean, ViewModel> 数据源给 RecyclerView 发布选项列表、几个 RecyclerView 各绑一份列表、公开多个取数方法，UI 模型里有多组列表字段；产物里写死的数组字面量、几个分组的 ForEach 渲染同一个数组、网关只给部分字段赋值、只接了主接口

## 规矩

- rule-8095cd44f2c6｜色板、边框、样式这类选项列表照源 ViewModel 数据源迁移，截图只用来核对视觉｜读到：Fragment 继承的列表基类带 <Bean, ViewModel> 泛型参数，或布局 XML 的 <data> 里 <variable> 绑定 ViewModel、选项区是 <include> 进来的列表布局；写错：目标页面用 ForEach(...) 渲染一组写死、按截图估色的选项数组：项数、顺序、色值和源数据源不一致，渐变方案换成纯色块，位图素材换成色块
- rule-031fe3aded01｜源端从 assets 文本解析层级数据时，目标先按源解析规则转成目标数据，不写少量硬编码条目｜读到：源 ViewModel 从 assets 下的文本文件解析出省→市→区这类层级数据，热门列表只是从中取几个名字；写错：目标的数据仓库里只有十几个硬编码条目的数组字面量（`[{...}, ...]`），层级数据和热门数据返回同一扁平列表；或注释写着默认数据为兜底列表、待注入资产文件
- rule-3c2bd3f8fa78｜多个 RecyclerView 绑定不同列表时，ArkUI 各分组绑定各自的数组，并实现逐级推进与回退｜读到：布局里有几个 RecyclerView（热门、全量、当前层级），各自的 adapter 绑定 ViewModel 发布的不同列表；点击回调推进到下一层，返回回调退回上一层；写错：ArkUI 里几个分组的 ForEach 渲染同一个数组；点击任一项即提交，没有逐级推进和返回退层
- rule-1ec0badda8fd｜数据网关写完后，按 UI 数据模型逐字段核对每个字段都有来源｜读到：源 `Fragment` 由宿主同步首页缓存的多日数据，UI 数据模型里有当日详情之外的列表字段（日期带、趋势、农历、小时等）；写错：网关只给模型的一部分字段赋值（如只填当日详情），列表类字段保持空数组 `[]`，组件只剩空的列表区段
- rule-9df00a8e3db0｜规格要求一页同时取得几个接口的数据时，Service→ViewModel→Page 逐个接上，不只接主接口｜读到：源 ViewModel 公开多个取数方法（如主数据和趋势各一个接口），规格验收写「同时取得 A 与 B」，接口草案也列了两个加载方法；写错：目标 Service、ViewModel 只提供主接口的加载方法，Page 只调它；另一个接口在目标里没有任何页面调用，对应字段从不赋值
