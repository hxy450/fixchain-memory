# 规格要求一页同时取得几个接口的数据时，Service→ViewModel→Page 逐个接上，不只接主接口

审的是：代码
触发（任一种）：
- 读到：源 ViewModel 公开多个取数方法（如主数据和趋势各一个接口），规格验收写「同时取得 A 与 B」，接口草案也列了两个加载方法；写错的样子：目标 Service、ViewModel 只提供主接口的加载方法，Page 只调它；另一个接口在目标里没有任何页面调用，对应字段从不赋值
适用范围：数据接线阶段，源页面依赖多个接口、目标由 Service/ViewModel 聚合成结果对象时
做法：
- 实现前把每条验收项映射到 Service→ViewModel→Page 的具体调用；需要几个接口的页面，新增组合结果类型和加载方法，并发请求这几个接口，页面分别消费
- 输出前检查每个源接口都有页面调用；没有的补齐，或登记缺口
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 新增组合结果类型和加载方法，并发请求两个接口，页面两支都消费：修复后的接线方式（出处：卡里修好并验证过）
针对本应用要查的：
- 源页面用到的全部接口：源工程里该页 ViewModel（.kt）的公开取数方法和它们调用的 api 方法；规格的验收项和接口表；每个接口在目标 Service、ViewModel、Page 三层各找到一处调用，缺哪层补哪层
来源：1 张卡，1 个应用
