# 转写 "${x}…" 拼接时先读 x 的定义，text 前缀的字符串字段不映射到原始数值

审的是：代码
触发（任一种）：
- 读到：源端 observe 一个返回 LiveData<String> 的 text 前缀字段，拼成 "${x}…" 文案；写错的样子：目标页面直接把状态里的原始数值拼进模板字符串（`${this.store.<数值字段>}…`），没有经过格式化，显示成裸秒数
适用范围：实现阶段转写源端文案拼接，插值字段在源端是格式化结果
做法：
- 先读 x 本身的定义，读取范围覆盖它的 getter 所在行，不停在相邻 getter；text 前缀的 LiveData<String> 按格式化结果处理
- 模板里插入经格式化的值；复用已有的时间格式化函数前，逐分支对照源格式化器（小时分支、封顶值、≤0 的处理），不默认 mm:ss 函数就等价
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 新增与源格式化器逐分支一致的格式化函数（MM:SS，≥1 小时为 HH:MM:SS，有封顶，≤0 为 00:00），文案改用它：卡里的修法，真机显示为分秒格式（出处：卡里修好并验证过）
针对本应用要查的：
- 源格式化器的各分支：源工程里 text 字段 getter 调用的格式化函数；逐个读出小时分支、封顶值、≤0 的输出，目标格式化函数照写
