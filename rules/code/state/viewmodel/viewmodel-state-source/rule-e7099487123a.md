# 从安卓 ViewModel 迁移时带上驱动界面的常量和状态，Tab 顺序按源数组，不用内部 id 当标题

审的是：代码
触发（任一种）：
- 读到：源 ViewModel 里有驱动界面的常量和状态：Tab 文案数组 arrayOf(...) 及下标到类型的映射、选中项下标、距离等格式化函数；列表项字段来自 item 布局；写错的样子：目标 Tab 顺序照规格 AC 或枚举类型的列举顺序写；列表卡片用内部 id 当主标题、少了 item 布局里的字段；目标 ViewModel 没有选中下标和格式化好的文本，页面显示不出选中态
适用范围：把安卓 ViewModel 驱动的列表、标签页迁到 ArkTS ViewModel 和页面时
做法：
- Tab 顺序和类型映射照源数组常量及下标映射写（每个下标对应哪种类型），不按规格或枚举的列举顺序
- 列表项字段按源数据类和 item 布局逐个带上；选中态按源的选中下标做成目标 ViewModel 的状态；距离等文本按源格式化函数移植
- 内部 id 不作用户可见的标题，可见标题照源 item 布局的文案
针对本应用要查的：
- Tab 顺序、列表项字段和选中下标：源工程对应 ViewModel 的 Kotlin/Java 源文件（数组常量、选中下标、格式化函数），以及列表 item 的布局 XML；数组下标顺序就是 Tab 顺序；item 布局里每个 TextView 对应一个列表项字段
