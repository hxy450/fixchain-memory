# 组件用 available 一类开关条件渲染可选区块时，开关要有真实赋值来源，迁入源端选中项变化时的查询

审的是：代码
触发（任一种）：
- 读到：源端 ViewModel 在选中项变化时触发附带查询（如 `setSelectDay(index)` → 按今天的 id 加 `index - 1` 查当日数据）写进 `LiveData`，Fragment 里 `observe` 后绑定几个 `TextView`；写错的样子：目标组件用 `if` 加区块数据的 `.available` 条件渲染该区块，而 gateway / ViewModel 只映射了别的字段，这个数据对象一直是默认值 `available=false`，区块永不显示
- 读到：源端区块的数据来自本页 ViewModel 按选中项计算的状态；写错的样子：目标 gateway 改从另一个模型上已有的字段取值（如首页数据对象的同名字段，默认 `null`），而目标端从没给这个字段赋过值，或只在某一个 `selectedIndex` 下才填
适用范围：迁移带可选区块的页面，区块数据由源端选中项变化时的本地查询或计算产生
做法：
- 逐项核对组件里每个 available / 可选区块开关和它的数据字段，在目标代码里找到真实赋值处；找不到的不能留默认值让 if 把整块隐藏
- 把源 ViewModel 在选中项变化时的附带查询迁到 gateway / ViewModel：选中项变化时按同样的偏移（今天加 index - 1）取当日数据并赋给区块
- 借用目标端已有字段前，先确认它确实被赋过值，且和源页面实际用的来源语义一致；不一致就按源页面的来源实现
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 组件内新增按选中索引加载当日数据的方法（今天加 index - 1），删掉从首页对象取值的分支：返修后保留的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 区块数据在源端从哪来、怎么按选中项算：源工程里该页面的 ViewModel：选中项回调（如 setSelectDay）及它调用的查询方法；Fragment 里对应 LiveData 的 observe；读出查询的入参（基准日、偏移）和赋值的 LiveData，照着写进目标 gateway / ViewModel
