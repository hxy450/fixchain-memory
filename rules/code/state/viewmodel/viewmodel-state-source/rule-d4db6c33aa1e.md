# 源端初始化时同步写入的输入状态，在目标初始化方法的第一个 await 之前赋值

审的是：代码
触发（任一种）：
- 读到：源 Activity / Fragment 初始化时同步写 viewModel.keyWord.value = … 和 EditText.setText(…)，搜索动作读取输入框当前文本；写错的样子：ViewModel 的初始化方法先 await 存储或 SDK 的绑定调用，之后才给 TextInput 双向绑定的字段（关键词、清除按钮可见性）赋初值；页面在 aboutToAppear / onReady 里以 void 调用它、不等待
适用范围：目标页面的输入框双向绑定 ViewModel 字段、初始化方法里含 await 且由生命周期回调不等待地调用时
做法：
- 源端初始化时同步写入的输入类状态（关键词、输入框文本、清除按钮可见性）挪到初始化方法第一个 await 之前赋值；异步绑定存储或 SDK 只负责加载数据，不在续体里回写用户可编辑字段
- 逐一检查初始化续体里对双向绑定字段的赋值；确需在续体里赋值时，先确认字段仍是进入方法时的值再写，不覆盖用户已输入的内容
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 把关键词和清除按钮可见性移到所有 await 之前赋值后，初始化期间用户输入不再被覆盖，点击搜索能拿到关键词：修复用的顺序（出处：卡里修好并验证过）
未核实：卡里没有单独复现竞态的真机日志，修复与另一处修复同批装机
来源：1 张卡，1 个应用
