# 源端账号表经 Room LiveData 读出时，目标存储的每个写方法都刷新内存状态并广播

审的是：代码
触发（任一种）：
- 读到：源端当前账号来自 Room @Dao 返回的 LiveData，ViewModel 的写方法（含验证状态）只写库、靠 LiveData 重新发射；写错的样子：目标存储的某个写方法只写库、不刷新内存 @Trace 当前值，注释称「写库但不广播」或「非身份变更」
适用范围：账号存储阶段，把 Room + LiveData 的账号仓库迁成目标端带 @Trace 缓存的全局存储时
做法：
- 存储里每个写账号表的方法（update、验证状态等）写库后都刷新内存当前值并广播，不按「非身份变更」自行豁免
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 验证状态写方法补上刷新广播后，就绪判断成立，不再每次重跑验证：修复后保留的写法（出处：卡里修好并验证过）
