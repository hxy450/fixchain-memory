# 上游已有 @Trace 全局存储时，页面同步读它，不用 @Local 快照加 aboutToAppear 异步赋值

审的是：代码
触发（任一种）：
- 读到：派工写明某个全局存储已就绪，或读到的目标存储里有 @Trace 当前值字段；源页面在提交前用 observeAsState 读到的当前值做守卫判断；写错的样子：页面写 @Local 布尔或对象快照（初值 false 或兜底哨兵），在 aboutToAppear 里异步查库 .then 赋值，再用快照做守卫；照抄兄弟页的旧写法
适用范围：功能切片阶段，页面的写操作守卫依赖全局当前状态（如当前账号）且目标已有响应式存储时
做法：
- 在事件处理和 build 里直接同步读全局存储的 @Trace 当前值做判断，去掉页面里的快照字段和 aboutToAppear 的异步赋值
- 照抄兄弟页先例前先和现有存储核对；存储落地后搜一遍页面里的异步一次性读取和初值 false 的快照字段，应为零
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 被 @Trace 装饰的属性变化时，只通知关联的组件刷新：直接读存储字段就能在切换后自动刷新，不需要页面快照（出处：arkts-new-observedV2-and-trace.md，概述）
- 各页改为直接读全局存储的当前值后，读库前误判和切换不刷新都消失：修复后保留的写法（出处：卡里修好并验证过）
