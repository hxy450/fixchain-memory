# 加请求代次时，VM 内部异步写 @Trace 列表也要校验代次、日期和筛选值

审的是：代码
触发（任一种）：
- 读到：VM 的异步加载方法在 await 查询返回后直接给 @Trace 列表赋值；写错的样子：只在页面提交结果前比对请求代次，VM 内部写 @Trace 列表时没有校验代次、请求的日期和筛选值，旧请求的结果可能覆盖新数据
适用范围：ViewModel 里异步查询后写共享列表、且同一筛选值会被快速切换的情形
做法：
- VM 为这类加载单独维护一个自增代次；发请求时记下代次、日期和筛选值，await 返回后三者都与当前一致才写 @Trace 列表，否则丢弃
来源：1 张卡，1 个应用
- case-8f714106a538afa3c22a（记得日历）：做法第 1 步 ← 建议 4、诊断
