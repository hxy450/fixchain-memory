# 源端用 observeAsState / LiveData 读守卫依赖的状态时，目标出口给同步可读的 @Trace 存储

审的是：代码
触发（任一种）：
- 读到：源端公共读取函数是 observeAsState() + derivedStateOf { current ?: 兜底哨兵 } 这类响应式读取（或 LiveData / StateFlow），写操作前的守卫依赖它；写错的样子：目标公共函数写成 async 一次性查库，注释要求调用方在 aboutToAppear 里拉取后持本地副本
适用范围：公共组件阶段迁移账号这类守卫依赖状态的读取函数时
做法：
- 出口给成同步可读的响应式全局存储：@ObservedV2 类里用 @Trace 字段保存当前值，页面在事件处理和 build 里直接读；装载前的初值用源端 ?: 后面的兜底值
- 存储还没建好时登记前向引用（FWD-REF），存储落地后切换过去；不把「挂载时异步拉取、持本地副本」定成契约
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- declare const ObservedV2: ClassDecorator；declare const Trace: PropertyDecorator：两者配合使用：@ObservedV2 类里 @Trace 属性变化时通知关联组件刷新（出处：鸿蒙 SDK 的 ets/component/common.d.ts，ObservedV2、Trace）
- @ObservedV2 与 @Trace 须配合使用，单独用没有作用；类要 new 出实例才可被观测；@Trace 静态属性也可被观测：全局存储写成 @ObservedV2 类的单例（或静态 @Trace 属性）（出处：arkts-new-observedV2-and-trace.md，概述 / 观察变化）
- 修复后改为响应式出口，页面直接读存储的 @Trace 当前值：修复后保留的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 装载前的兜底值：源工程这个读取函数里 derivedStateOf 或 map 的 ?: 右边；读出兜底的哨兵对象（如匿名账号），目标存储 @Trace 字段的初值用同一个哨兵
