# 页面显示的业务状态直接读 @ObservedV2 模型的 @Trace 字段，不复制成 @Local 副本

审的是：代码
触发（任一种）：
- 读到：决策台账或规格写某个模型统一管理状态、并向其他功能提供数据；状态管理约定是 @ObservedV2 类的 @Trace 属性变化触发刷新；写错的样子：页面把模型的多个字段复制进 @Local，在每个处理函数调用模型后用一个同步方法手动拷贝一遍，build 读的是这些副本
- 读到：store 类是 @ObservedV2、字段带 @Trace，异步加载 await 后、BLE 或消息回调里整体重新赋值数组和 loading；决策写「@ObservedV2/@Trace 页内响应」，源端是 Flow / StateFlow 持续推送；写错的样子：页面声明 @Local 列表、loading 镜像，aboutToAppear 里未 await 地调加载后立即把 store 字段拷进来，此后没有 @Monitor、回调或轮询，build 里不读 store
适用范围：@ComponentV2 页面把显示状态接到 @ObservedV2 + @Trace 模型（单例服务、AppStorageV2 或共享 store）、模型会在别处被修改时
做法：
- build 和处理函数直接读模型的 @Trace 字段（this.model.<字段>）；组件 @Local 只持有模型实例本身（取单例 store 的函数()，或由父组件 @Param 传入），以及弹窗开关、输入草稿等纯界面态
- 删掉 aboutToAppear 里的一次性拷贝和发送后的重拷；确需本地副本时同时写刷新路径：@Monitor 监听 store 字段同步副本，或服务回调，轮询只兜底
- 把模型改成跨页共享时，逐个检查持有它的页面是否还在渲染本地副本，有就改成直接绑定模型字段
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- @ObservedV2 类中被 @Trace 装饰的属性值变化时，会触发该属性绑定的 UI 组件刷新：在 build 里读 store.<@Trace 字段> 才会建立绑定（出处：arkts-new-observedV2-and-trace.md，观察变化）
- @Local 装饰简单类型只观测对变量本身的赋值；装饰类对象时只观测整体赋值，成员属性的观察依赖 @ObservedV2 / @Trace：拷进 @Local 的数组、布尔值与 store 断开；@Local 持有 store 引用时，@Trace 字段的变化仍能刷新（出处：arkts-new-local.md，观察变化）
- connect 取到的对象，修改的数据被 @Trace 装饰时，修改会同步更新 UI：直接读共享实例的 @Trace 字段就能刷新，不需要副本（出处：arkts-new-appstoragev2.md，使用场景）
- @Monitor 可在 @ComponentV2 中监听 @Local / @Param 等状态变量，也可在 @ObservedV2 类中监听 @Trace 属性：保留本地副本时用来同步（出处：arkts-new-monitor.md，概述）
- 题号、计数、子组件参数、按钮 enabled 等全部改为直接读 this.model.* 后，返回页面时高亮和计数刷新正确：修好后的写法（出处：卡里修好并验证过）
- 改成 @Local 持有 store、build 和派生方法读 @Trace 字段并删掉拷贝后，永久「加载中」消失，新数据和回调消息都能显示：持有引用即可随异步加载和回调刷新（出处：卡里修好并验证过）
