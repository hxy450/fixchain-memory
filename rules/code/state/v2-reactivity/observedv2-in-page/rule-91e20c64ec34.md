# 源端每次变更都生成新列表时，ArkTS 入队出队都整体重新赋值数组，不用 push

审的是：代码
触发（任一种）：
- 读到：Kotlin 的 MutableStateFlow<List<…>> 用 update { it + item } 入队、filterNot 出队，每次生成新列表；写错的样子：ArkTS 生产方入队用 .push(...) 原位修改 @Trace 数组，出队却重新赋值，两种变更信号不一致
- 写错的样子：消费方用 @Monitor 监听整个数组属性来模拟 collect，而生产方对这个数组用 .push(...) 入队
适用范围：把源端 StateFlow 承载的消息、事件队列迁成 ArkUI V2 的 @Trace 数组时，生产方的写法
做法：
- 生产方入队写成 this.list = [...this.list, item]，出队写成 this.list = this.list.filter(...)，入队和出队用同一种变更信号
- 消费方用 @Monitor 监听整个数组属性时，先核对生产方是整体赋值；是 push 的，改生产方为整体赋值，不假定 push 会触发
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- @Monitor 监听数组整体时，只能观测到数组整体的赋值；无法监听 Array 的 API 调用引起的变化：push 不触发监听整个数组的 @Monitor（出处：arkts-new-monitor.md，通用监听能力）
- declare const Monitor: MonitorDecorator：@Monitor 装饰器（出处：鸿蒙 SDK 的 ets/component/common.d.ts，Monitor）
- 入队改成 this.list = [...this.list, new Message(...)] 后，消费方 @Monitor 触发，提示正常弹出：修复后复测通过（出处：卡里修好并验证过）
