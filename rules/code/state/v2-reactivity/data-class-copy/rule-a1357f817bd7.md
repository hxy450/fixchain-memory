# ForEach 只以 id 作 key 且行用 @Param 收整个元素时，行内字段用 @Trace 原位改

审的是：代码
触发（任一种）：
- 读到：Kotlin data class 列表项用 it.copy(...) 替换同 id 的那一项，Compose 列表按稳定 id 作 key；写错的样子：ArkTS 的更新方法用 .map(...) 生成 new 对象替换同 id 的元素，ForEach 的 keyGenerator 只返回 id，行组件以 @Param 接收整个元素；或改写时删掉了原有的 @ObservedV2 类和 @Trace 字段
适用范围：ArkUI V2 状态管理下，用 ForEach 渲染、行组件以 @Param 接收整个元素的可变列表
做法：
- 元素类加 @ObservedV2，会变的显示字段写成 @Trace 字段（不写 readonly），更新时原位改，如 line.count = n，不用 map 生成新对象
- 坚持替换对象时，把变化的字段并进 keyGenerator 的返回值（id 加该字段），让同 id 的行重建
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- (arr: Array<any>, itemGenerator: (item: any, index: number) => void, keyGenerator?: (item: any, index: number) => string): ForEachAttribute：ForEach 的第三个参数决定键值（出处：鸿蒙 SDK 的 ets/component/for_each.d.ts，ForEachInterface）
- 非首次渲染时键值已存在则不创建新组件，直接渲染该键值对应的组件：同 key 换了新对象，行组件不重建，行内仍显示旧对象的字段（出处：arkts-rendering-control-foreach.md，非首次渲染）
- declare const ObservedV2: ClassDecorator；declare const Trace: PropertyDecorator：元素类和它会变的字段用这两个装饰器，原位修改才能被观察到（出处：鸿蒙 SDK 的 ets/component/common.d.ts，ObservedV2、Trace）
- declare const Param: PropertyDecorator：行组件接收元素的装饰器（出处：鸿蒙 SDK 的 ets/component/common.d.ts，Param）
- 元素类加 @ObservedV2、数量字段改 @Trace 并原位写入后，行内数量随增减变化：修复后复测通过（出处：卡里修好并验证过）
- (dataSource: IDataSource, itemGenerator: (item: any, index: number) => void, keyGenerator?: (item: any, index: number) => string): LazyForEachAttribute：同族接口：LazyForEach 同样用 keyGenerator 定键值（出处：鸿蒙 SDK 的 ets/component/lazy_for_each.d.ts，LazyForEachInterface）
未核实：「同 key 换对象后行不刷新」卡里依据修复者诊断和改后复测，文档的键值复用说法与之相符
