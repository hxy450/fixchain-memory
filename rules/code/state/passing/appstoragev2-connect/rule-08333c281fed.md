# AppStorageV2/PersistenceV2 的 key 只用字母、数字、下划线，连字符和点号换成下划线

审的是：代码
触发（任一种）：
- 读到：工程模块文件名用 kebab-case，状态管理参考只给了 `AppStorageV2.connect(Cls, key, …)` 签名；写错的样子：`AppStorageV2.connect(Cls, '…-…', …)` 或 PersistenceV2 的 key 含连字符（照文件名连字符化写的）
- 读到：工程里已有 `AppStorageV2.connect(…, '<含连字符的 key>', …)`，新文件要订阅同一实例；写错的样子：新文件的 `AppStorageV2.connect` 照抄已有的连字符 key
- 读到：规格或派工里的 AppStorageV2 键带「.」或「-」（「领域.字段」式命名空间）；写错的样子：AppStorageV2.connect / PersistenceV2.globalConnect 或 KEY_* 常量里照抄了带点号的键（注释写「与 spec 逐字一致」）
适用范围：给 AppStorageV2 / PersistenceV2 命名 key、落规格里的存储键或复用已有 key 时
做法：
- key 只用字母、数字和下划线；规格键带「.」「-」时换成「_」，在键常量注释里记「规格逻辑键 → 运行时键」；不需要自定义 key 时用不传 key 的重载 AppStorageV2.connect(Cls, () => new Cls())，默认用类名
- key 集中定义成常量，按 ^[A-Za-z0-9_]+$ 自检；写完后把 connect / globalConnect 调用和 KEY_* 常量里的字符串键逐个对照，不匹配就改
- 沿用已有 key 共享同一实例前先核它是否合法；含连字符时把所有 connect 点一并改名，不照抄进新文件
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- static connect<T extends object>(type: TypeConstructorWithArgs<T>, keyOrDefaultCreator?: string | StorageDefaultCreator<T>, defaultCreator?: StorageDefaultCreator<T>): T | undefined：AppStorageV2.connect，第二个参数是 key 或默认构造器，不传 key 时第二个参数当默认构造器；PersistenceV2 继承它（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.StateManagement.d.ts，AppStorageV2.connect）
- key 可由字母、数字、下划线组成，长度不超过 255，使用非法字符或空字符的行为未定义：AppStorageV2 / PersistenceV2 的 key 字符集和长度限制（出处：arkts-new-appstoragev2.md，使用说明；js-apis-StateManagement.md，globalConnect18+）
- 未指定 key 时使用 type 的 name 作为 key：不传 key 的重载默认用类名（出处：js-apis-StateManagement.md，AppStorageV2 的 connect）
- 关联 @Observed 对象时 type 的 name 属性未定义，需要指定 key 或自定义 name：不传 key 的重载用在 @Observed（V1）类上取不到类名（出处：arkts-new-appstoragev2.md，使用说明）
- 编译通过，装机后 AceStateMgmt 输出 “Cannot use the key! The value of key can only consist of letters, digits and underscores”：连字符 key 只在运行时报错；改成下划线后恢复（出处：卡里修好并验证过）
- 点号键时回归测试报 must use a valid ArkUI storage key、hilog 报 invalid AppStorageV2 key；改成下划线键并注释「点号逻辑键映射为下划线键」后通过：规格点号键映射成下划线键的做法（出处：卡里修好并验证过）
- static globalConnect<T extends object>(type: ConnectOptions<T>): T | undefined；key 写在 ConnectOptions.key?: string：同族接口：PersistenceV2 的应用级连接，key 同样只能由字母、数字、下划线组成（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.StateManagement.d.ts，PersistenceV2.globalConnect、ConnectOptions.key；js-apis-StateManagement.md，globalConnect）
未核实：运行时报错出自鸿蒙 SDK API 24（HarmonyOS 6.1.1），本机核实用的是 API 23；本机声明里没写 key 的字符集，限制出自文档，文档只说非法字符的行为未定义
