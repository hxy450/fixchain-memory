# VM 改成页面实例后，隐式读 VM 筛选字段的查询要在查询前同步或改成显式传参

审的是：代码
触发（任一种）：
- 读到：页面调用 VM 的查询方法只传起止时间、不传筛选参数，筛选条件取自 VM 自己的 @Trace 字段；写错的样子：VM 改成页面 new 的实例后，查询前没有把页面当前的筛选值（父页传入的 @Param）写进 VM 字段，也没有改成显式传参；页面虽有对应 @Param，查询仍用 VM 初始化时的值
适用范围：共享 ViewModel 改成页面级实例后，所有隐式依赖 VM 内部状态的查询调用
做法：
- 逐个找出不带筛选参数、靠 VM 字段过滤的查询调用
- 每次查询前由页面把当前筛选值（父页传入的 @Param）赋给 VM 的筛选字段再查询，或者把查询方法改成显式接收筛选参数
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- @Param：由父到子单向同步，组件内不能本地修改：页面收到的筛选值在 @Param 上，VM 字段不会自动跟着变，要在查询前手动同步（出处：arkts-new-param.md，装饰器说明）
