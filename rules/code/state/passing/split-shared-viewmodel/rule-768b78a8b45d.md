# 新加 @Monitor 触发重查后，同一次切换不再另外递增刷新计数

审的是：代码
触发（任一种）：
- 写错的样子：新加的 @Monitor 监听筛选参数并重新查询，同一次切换的关闭回调里又递增刷新计数（revision 一类的 ++），一次切换刷新两轮
适用范围：给视图补上 @Monitor 监听筛选参数、而原来靠刷新计数触发重查的情形
做法：
- 一次切换只保留一个刷新入口：保留 @Monitor 这条，切换路径上不再二次递增刷新计数
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- @Monitor 是状态变量修改的异步监听；单个 @Monitor 同时监听多个属性时，一次事件里共同变化只回调一次：要合并的刷新可以放进同一个 @Monitor 的多个路径，不必另设计数（出处：arkts-new-monitor.md，概述）
