# 新建筛选值下传通道时沿用源头对「全部」哨兵的归一化，不下传条目原始 ID

审的是：代码
触发（任一种）：
- 读到：VM 的 @Trace 筛选字段在选择动作和偏好读取里都把「全部」类条目归一化成空字符串 ID；写错的样子：新加的 @Param 下传或对 VM 字段的直接赋值，把选择条目或页头保存的原始 ID 原样传下去；「全部」条目的非空 ID 成了过滤条件，选「全部」反而无数据
适用范围：给页面补传筛选参数、或改写选择回调时，筛选源头带有「全部」哨兵归一化的情形
做法：
- 在新下传通道的源头（选择回调、恢复上次选择处）套用与源头相同的归一化：「全部」条目传空 ID，与偏好读取对「全部」类型返回空 ID 一致
- 同一个筛选值要下传给的每个视图都传归一化后的值，不只传给其中一个
针对本应用要查的：
- 「全部」哨兵在源头怎么归一化：目标工程里原共享 VM 的选择动作处理和偏好读取方法；读出「全部」条目被换成什么值（例：换成空字符串），新通道照同一规则写
