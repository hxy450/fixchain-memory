# 子控件的启用态、颜色由当前状态算出时，不作 @Builder 值参，改内联属性链或 @Param 子组件

审的是：代码
触发（任一种）：
- 读到：Compose 自定义子 Composable 以状态算出的布尔值作参数（如按钮的 label、enabled、onClick），内部 `Surface` 颜色和 `Modifier.clickable(enabled = enabled)` 由它决定，调用处传 `enabled = count > 1` 这类表达式；写错的样子：目标写成 `@Builder` 函数带 `enabled: boolean` 值参，调用处传 `this.count > 1` 一类状态表达式，内部 `.enabled(enabled)`、fontColor、backgroundColor 读这个值参
- 读到：从已转换页面搬来的 `@Builder` 片段，参数里有随状态变化的布尔或数值；写错的样子：公共组件里原样沿用这个 `@Builder` 签名和调用表达式
适用范围：把源端带状态参数的子控件迁成 ArkUI V2 组件里的复用写法时
做法：
- 删掉这类 @Builder，在调用处写内联属性链：.enabled(this.count > 1)、.fontColor(…)、.backgroundColor(…) 直接读 this 上的状态，onClick 直接调回调
- 要复用时抽成 @ComponentV2 子组件，状态相关的值用 @Param 接收；@Builder 值参只放文案、尺寸等不随状态变化的值
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 调用 @Builder 函数默认按值传递；传入的参数是状态变量时，状态变量的改变不会引起 @Builder 函数内的 UI 刷新：值参只是调用时刻的快照（出处：arkts-builder.md，按值传递参数）
- @Param 的数据源是状态变量时，数据源的修改会同步给 @Param（父到子单向同步）：@ComponentV2 子组件用 @Param 接收会随状态刷新（出处：arkts-new-param.md，概述）
- 删除 @Builder、四处改为内联 Text 链直接读状态后，状态切过边界再切回，−、+ 均为 enabled=true：内联写法已上机验证（出处：卡里修好并验证过）
