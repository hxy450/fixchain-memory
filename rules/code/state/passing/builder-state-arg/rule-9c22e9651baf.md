# 随语言变化的文案不作 @Builder 值参，改传键在体内调 t(key)，或用 @Param 子组件

审的是：代码
触发（任一种）：
- 读到：目标工程的文案在渲染期经 `t(key)` 或委托 `t()` 的 getter 取值，语言状态是 `@Trace` 字段、声明式驱动刷新；写错的样子：带参 `@Builder` 的签名里有 `label: string` 一类文案值参，调用处传 getter 或 `t(…)` 的求值结果，再转交给子组件
适用范围：ArkTS V2 页面把随语言切换的文案接入带参 @Builder，且页面在语言切换时仍挂在导航栈里
做法：
- @Builder 参数改传文案键（labelKey: string），在 @Builder 体内调用 t(labelKey)（或 i18n 服务实例的 t）求值后交给子组件
- 或抽成 @ComponentV2 子组件用 @Param 接收文案；只有静态字面量走 @Builder 值参
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 调用 @Builder 函数默认按值传递；传入的参数是状态变量时，状态变量的改变不会引起 @Builder 函数内的 UI 刷新：文案值参只是调用时刻的快照，切换语言不变（出处：arkts-builder.md，按值传递参数）
- build 内直写 Text(t(key)) 会随语言刷新，经 @Builder 值参传入的文案不刷新；改为传键在 @Builder 内求值后修复：机制已在设备上实测（出处：卡里修好并验证过）
未核实：卡里环境是 SDK 26.0.0，文档按副本、声明按本机 API 23 核实；其中一处修复只经静态审查，未在设备上复现旧文案
