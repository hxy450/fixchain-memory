# @ComponentV2 里把会变的状态当 @Builder 值参传入时，改为片段内直读或子组件 @Param

审的是：代码
触发（任一种）：
- 写错的样子：@ComponentV2 组件里调用带参 @Builder 时，实参是 @Local 状态或 @Trace 属性（延迟填充的数组、数值、文案、当前条目、enabled 布尔），片段里的菜单、数值、文案不随状态变化
- 写错的样子：为了类型收窄，把片段里直接读 this 状态的写法改成带参 @Builder，调用处用 `as` 强转后传值（如把可能为 null 的当前条目 `as` 成具体类型）
适用范围：ArkUI 状态管理 V2（@ComponentV2、@Local、@Param、@ObservedV2/@Trace）里抽带参数的 @Builder 片段时
做法：
- 逐个实参判断是否随 @Local/@Trace 变化；会变的改成在片段内直读 this.状态，或抽成 @ComponentV2 子组件用 @Param 接收，或传整个 @Trace 对象、在片段内读它的属性；只有静态字面量走值参
- 需要类型收窄时，在片段内用局部 const 收窄或改用子组件 @Param，不用值参 builder 换取编译通过
- 写完用 grep -n 'this\.[a-zA-Z]*(.*this\.' 列出把状态当实参的 builder 调用，逐条复核
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- @Builder 默认按值传递；参数是状态变量时，状态变化不会引起 @Builder 内的 UI 刷新：值参拿到的是调用时的快照（出处：arkts-builder.md，按值传递参数）
- @ComponentV2 中按值传参时，修改 @Trace 装饰的对象属性可以触发 UI 刷新：传整个 @Trace 对象、在片段内读属性是可刷新的写法（出处：arkts-builder.md，@Builder函数联合V2装饰器）
- @ComponentV2 中传简单数据类型不能触发 UI 刷新：把 @Trace 数值、文案、布尔拆出来当值参就不刷新（出处：arkts-builder.md，使用@ComponentV2装饰器触发动态刷新）
- 两个及以上参数时，即使用对象字面量传递，值的改变也不会触发 UI 刷新：多参 builder 没有按引用刷新这条路（出处：arkts-builder.md，@Builder存在两个或两个以上参数）
- 延迟填充的数组按值传入 builder，片段停在构建期的空数组快照，菜单项全不显示；换成片段内直读状态后正常：值参 builder 的实际表现和修法（出处：卡里修好并验证过）
未核实：卡里的行为出自 API 24（6.1.1），本机只核对了文档副本，没有 API 24 的声明
