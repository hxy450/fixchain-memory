# 泛型事件总线 emit 不直接传 {}，先声明载荷接口再传类型化变量

审的是：代码
触发（任一种）：
- 读到：工程里的事件总线声明成 emit<T extends Object>(name, payload: T)，已有事件都配有导出的载荷接口，调用处先 const payload: <接口> = {…} 再 emit；写错的样子：新增或调用处写成 emit('<事件名>', {}) 或 emit('<事件名>', { … }) 内联对象字面量；新事件名只加进事件名联合类型，没有对应的载荷接口
适用范围：ArkTS 工程里新增事件或新增 emit 调用，载荷为空或只作信号时也一样
做法：
- 和事件名同一补丁声明并导出载荷接口；只作信号也给一个可选标记字段（如 closed?: boolean），确认每个事件名都有对应的载荷类型
- 调用处写 const payload: <载荷接口> = { … }; bus.emit('<事件名>', payload)，不写 emit(name, {})
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 规则 arkts-no-untyped-obj-literals，级别：错误，错误码 10605038：对象字面量要显式标注类型；初始化 any、Object、object 类型的对象时不支持字面量（出处：typescript-to-arkts-migration-guide.md，需要显式标注对象字面量的类型）
- 声明载荷接口、改传类型化变量后编译通过：修好的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 事件总线的 emit 签名和已有的载荷约定：目标工程里定义事件名联合类型和 emit 的那个 .ets 文件，以及全工程的 emit 调用；看 payload 参数的类型约束和已有事件的载荷接口命名，新事件照同一约定补
