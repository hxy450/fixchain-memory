# 源页面靠 EventBus @Subscribe 重拉数据时，目标 ViewModel 构造时订阅对应事件并在回调里重拉

审的是：代码
触发（任一种）：
- 读到：源 Fragment 或 Activity 里有 @Subscribe 方法（登录成功、记录刷新这类事件）和 registerForActivityResult 回调，里面调 ViewModel 重拉统计或列表；写错的样子：目标 ViewModel 只在页面激活时（aboutToAppear 链上）调一次刷新方法，没有订阅会话状态或刷新事件；验收里「源:事件回调 → 标:刷新方法」只落成了丢弃迟到响应的 token
适用范围：迁移源页面的数据刷新入口到目标 ViewModel 时
做法：
- 把源页面所有重拉数据的入口列成清单（生命周期回调、@Subscribe 方法、ActivityResult 回调），逐条在目标 ViewModel 构造时写出对应订阅（会话状态订阅、记录刷新事件订阅，用工程已有的事件设施），回调里重拉
- 确认每个订阅的事件有发布方；并发 token 只作附加约束，不代替触发映射
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- ViewModel 构造时订阅会话状态和记录刷新事件，回调重拉统计与打卡天数后，登录、保存或删除记录返回首页即更新：返修后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源页面全部重拉数据的入口：源工程这个 Fragment 或 Activity 的 Kotlin/Java 文件：@Subscribe 注解的方法、registerForActivityResult 的回调、onResume 等生命周期回调；每个入口里调用的重拉方法和它监听的事件类各记一行，对到目标的订阅和刷新方法
