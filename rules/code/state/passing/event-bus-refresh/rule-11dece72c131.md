# 就绪事件带与平台无关的定时兜底时，采集通道悬置也要照原时长移植兜底

审的是：代码
触发（任一种）：
- 读到：源端缓存为空时等某个就绪事件才继续；事件的生产者里有 Observable.timer(…, SECONDS) 到时调上送方法，上送方法末尾无条件 EventBus.post(…Event())；写错的样子：目标缓存未命中分支只有 `FWD-REF` 注释、没有代码，把定时兜底和事件发布连同采集源一起悬置；注释称「与 Android 等待语义等价」
适用范围：目标平台缺对等的采集 API、需要给采集通道登记延迟占位，而源端就绪事件另有定时兜底时
做法：
- 把生产者拆成「采集源」和「门闩放行」两部分：只延迟确实缺 API 的采集源，与平台无关的定时兜底按源端原时长照常移植
- 在缓存未命中分支起定时器（setTimeout，时长写源端的值换成毫秒），到时走上送方法：置单次锁、清定时器、打告警日志，再向工程的事件总线发布同一个就绪事件
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 缓存未命中时恢复 10000 ms 定时器，上送方法置单次锁、清定时器、hilog.warn，再发布就绪事件；后续接入真实采集也保留它：返修后的兜底（出处：卡里修好并验证过）
针对本应用要查的：
- 源端兜底的时长和放行条件：源工程 Application 或启动类里起 Observable.timer 的那段，及它调用的上送方法；timer 的数值和 TimeUnit 换成毫秒；看上送方法末尾的 post 是否无条件
