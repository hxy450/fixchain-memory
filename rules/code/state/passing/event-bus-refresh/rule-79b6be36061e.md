# 接线成功导航前先查全局成功事件的订阅，同一次成功只保留一个改动 NavPathStack 的出口

审的是：代码
触发（任一种）：
- 读到：服务层在返回成功前 emit 全局成功事件（`EVT_*_SUCCESS`），规格里同时有「成功回调导航」和「收到事件后 pop」两条；写错的样子：页面 aboutToAppear 订阅成功事件并在回调里 navPathStack.pop()，成功回调里又 clear() + pushPathByName(…) 或 pop()，同一次成功两次改栈
适用范围：实现阶段给登录等成功结果接导航，且同一路径上有全局事件订阅会操作导航栈时
做法：
- 删掉事件订阅里的导航，各分支成功都调用同一个导航函数：`if (stack.popToName(主页名) < 0) { stack.replacePathByName(主页名, param) }`
- 与规格冲突的地方回写到规格
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 只把回调改成 pop() 而留着事件订阅的 pop，会连续出栈两次，症状不变；删除订阅导航、统一走 popToName / replacePathByName 后正确：修好的过程：要去掉的是多出的出口，不是改其中一个（出处：卡里修好并验证过）
- popToName(name: string, animated?: boolean): number：不在栈中返回 -1，据此走替换兜底（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.popToName）
- replacePathByName(name: string, param: Object, animated?: boolean): void：主页不在栈中时的兜底；param 必填（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.replacePathByName）
