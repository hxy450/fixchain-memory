# greenrobot EventBus 要同步按引用投递时自建进程内总线，不直接换成 emitter

审的是：代码
触发（任一种）：
- 读到：源码 `EventBus.getDefault().post(event)` 投递类实例事件，订阅方用 `onEvent` / `onEventMainThread`，订阅回调里还会再 post；写错的样子：目标总线以 `emitter.emit` / `emitter.on` 作传输层承载类实例事件，头注称回调「在发布线程执行」；没有嵌套 post 队列和订阅表快照
适用范围：迁移 greenrobot EventBus 2.x 的事件总线，事件载荷是类实例、或调用方依赖 post 返回前回调已执行时
做法：
- 先逐条核对投递契约：同步还是异步、按引用还是序列化拷贝、priority 与注册序、嵌套 post 是否排队
- 需要同步按引用语义时自建进程内总线：订阅表按 priority 降序、同级按注册序；post 时对订阅表取快照逐个同步调用，载荷按引用传；正在投递时再 post 的进队列（isPosting），本轮结束后依次投递
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Emitter 事件异步执行：发布后插入内部事件队列，队列串行执行时才调用订阅回调：emit 返回时回调还没执行，不是同步调用（出处：itc-with-emitter.md，场景介绍、运作机制）
- EventData.data 支持 Array、ArrayBuffer、Boolean、DataView、Date、Error、Map、Number、Object、Primitive、RegExp、Set、String、TypedArray，最大 16M：载荷按这些类型传递，不按引用传类实例（卡里观察到实例方法与 instanceof 失效）（出处：js-apis-emitter.md，EventData）
- function emit<T>(eventId: string, data?: GenericEventData<T>): void：emitter 的泛型发布接口，同样走事件队列（出处：鸿蒙 SDK 的 ets/api/@ohos.events.emitter.d.ts，emitter.emit）
- 重写为进程内同步按引用总线，priority 降序 / 注册序，带 isPosting 队列：返修后保留的写法（出处：卡里修好并验证过）
未核实：EventBus 2.x 的同步投递、priority、嵌套 post 排队语义按卡写，本机没有库源码；卡里目标 SDK 是 6.1.1(24)，emitter 声明按本机 API 23 核实
