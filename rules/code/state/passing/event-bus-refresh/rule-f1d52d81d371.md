# Navigation 根页或 Tab 内容要「返回后刷新」时，不靠 aboutToAppear，改用订阅或可见性回调

审的是：代码
触发（任一种）：
- 读到：规格写「返回主页刷新」「删除后返回主页同步」，首页用 pushPathByName 进入登录、编辑、记录等子页再 pop 返回；写错的样子：首页只在 aboutToAppear 里调激活和刷新，pop 回来后没有任何刷新入口；或订阅回调被页面 inactive 标志丢弃
适用范围：目标页是 Navigation 下常驻的根内容或 Tab 内容、被子页覆盖后再返回的场景
做法：
- 返回刷新用会话或事件订阅触发（见上一条），或在 NavDestination 上用 .onShown(...) 这类可见性回调触发，不把 aboutToAppear 当返回刷新入口
- 订阅回调不因页面 inactive 标志丢弃事件，在 aboutToDisappear 里注销
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- aboutToAppear?(): void：在自定义组件新实例创建后、build() 执行前调用：只在创建实例时调用一次，页面被覆盖后 pop 回来不会再调（出处：鸿蒙 SDK 的 ets/component/common.d.ts，BaseCustomComponent.aboutToAppear）
- onShown(callback: Callback<VisibilityChangeReason>): NavDestinationAttribute（@since 21）：NavDestination 页面显示时回调（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onShown）
- 首页被登录页覆盖后返回原导航目的地时，aboutToAppear 不再触发：真机上定位到的原因（出处：卡里修好并验证过）
未核实：卡里返修用的是订阅，onShown 写法没有上机验证；首页是 Navigation 根内容而不是 NavDestination 时没有 onShown
