# 多个页面订阅同一个全局保存成功事件时，订阅回调先判断是否本入口发起再弹引导

审的是：代码
触发（任一种）：
- 读到：规格或派工写明保存服务成功时 emit(...) 一个全局成功事件，已有别的页面或组件订阅它弹引导；写错的样子：入口的订阅（on(...)）回调收到成功事件就弹引导，没有判断这次保存是不是本入口发起的
适用范围：同一个全局成功事件被多个页面或组件订阅、各自在回调里展示引导时，每个订阅方
做法：
- 入口发起保存时置一个只属于本入口的「保存进行中」标志，订阅回调里先判断它，为假时直接返回不弹引导；处理完复位
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 订阅回调加「本组件发起的保存」门槛，只承接本组件发起的保存，再显示引导浮层：修好的写法（出处：卡里修好并验证过）
未核实：卡里没写事件机制是 emitter、eventHub 还是自建事件总线
