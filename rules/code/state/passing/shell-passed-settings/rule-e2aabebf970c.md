# 源端在壳层算一次再下传的派生结果，目标端也在壳层算一次放进全局状态

审的是：代码
触发（任一种）：
- 读到：源 Activity 的 setContent 顶层算出派生结果（如 设置.toEnum<枚举>().isActive(connectivityManager)），再作参数下传各路由；写错的样子：各页自己写 settings.x !== 0、> 0、=== 1 重算；或入口页私有函数算出结果却不提供给页面
适用范围：源端把设置的派生判定集中在应用壳计算的情形
做法：
- 入口页在每次设置变化时算一次，写进全局共享状态（如一个带 active 字段的状态对象），页面只读这个结果
- 规格列出的共享判定函数要实际写出来，各页不用 !== 0 / > 0 自行重算
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 入口页每次设置发射时写入共享状态的 active，各页在 build 内读它：修复后各页对省流模式的判定一致（出处：卡里修好并验证过）
来源：1 张卡，1 个应用
