# 源 Screen 由 ViewModel 和网络状态驱动时，目标页按源结构逐页转换，不用同一模板空壳

审的是：代码
触发（任一种）：
- 读到：源 Screen 用 hiltViewModel()、collectAsState() 取状态，带 HorizontalPager、ScrollableTabRow、LazyColumn 等结构；写错的样子：多个业务页由同一模板循环生成：build() 正文只有一个 Text("…内容开发中...")，或只有返回栏和「… 页面」标题文字
适用范围：迁移执行阶段逐页生成业务页面代码时
做法：
- 每个业务页先读该页源 Screen 及其 ViewModel / 数据源，再按源结构写目标页（Tab、分页、列表、状态分支），不用同一模板循环批量生成
针对本应用要查的：
- 页面的结构和数据来源：源工程里该页的 Compose Screen 文件和它引用的 ViewModel、Repository；列出 Screen 里的布局结构（Pager、TabRow、列表）和 ViewModel 暴露的状态流，逐项在目标页实现
来源：1 张卡，1 个应用
