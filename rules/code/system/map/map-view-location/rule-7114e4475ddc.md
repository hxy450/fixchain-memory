# 用原生地图 SDK 替换占位地图时，把定位结果接到相机和蓝点，就绪前暂存中心

审的是：代码
触发（任一种）：
- 读到：源端 AMapLocationClient 定位后 aMap.moveCamera(CameraUpdateFactory.newLatLngZoom(...)) 并开启 MyLocation（MyLocationStyle、setMyLocationEnabled）；写错的样子：新增的地图桥接只有初始化和生命周期（getMapAsync 存 map、resume / pause / release），注释写只保留生命周期；页面定位按钮仍只调缓存型 provider 的 center()，没有 moveCamera / setMyLocationEnabled
适用范围：用高德等原生地图 SDK 替换占位地图、接入页面已有的定位入口时
做法：
- 先列出页面现有的地图状态出口（provider.center、定位按钮回调），逐一接到地图对象：定位成功后 map.moveCamera(CameraUpdateFactory.newLatLngZoom(latLng, zoom))，并设 MyLocationStyle、setMyLocationEnabled(true)；定位失败不更新中心
- getMapAsync 还没回调时把要居中的坐标暂存，就绪回调里再应用
- 裁剪参考桥接时按用户可见入口（如定位按钮）逐项确认仍有效果；页面仍依赖的居中、坐标适配保留，做不完就登记为未完成
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 桥接加 center()、MyLocationStyle、setMyLocationEnabled、moveCamera(newLatLngZoom(…))和就绪前暂存中心；页面定位成功后经地图服务同时驱动缓存与原生地图：修复后的接法（出处：卡里修好并验证过）
针对本应用要查的：
- 鸿蒙版高德地图 SDK 里相机、蓝点和就绪回调的确切签名：目标工程依赖的高德鸿蒙地图包（oh-package.json5 里的依赖，oh_modules 下该包的 .d.ts），按 moveCamera、newLatLngZoom、setMyLocationEnabled、MyLocationStyle、getMapAsync 搜；照包里的声明写调用；没有对应接口时先记为缺口再决定替代
未核实：卡里的行为出自 API 24（HarmonyOS 6.1.1），本机声明是 API 23
