# 调用带 @permission 的接口而本切片不管 module.json5 时，登记 deferred-work

审的是：代码
触发（任一种）：
- 写错的样子：代码调用 sensor.on(sensor.SensorId.ACCELEROMETER / GYROSCOPE, …) 或 MediaAssetChangeRequest.deleteAssets，module.json5 requestPermissions 里没有对应权限，本切片的交回里也没登记 deferred-work / 移交项
适用范围：系统能力实现阶段，引入新的系统 API 时
做法：
- 引入新系统 API 时读取它完整的 JSDoc，不过滤 @permission 和 @throws 201
- 需要声明权限而 module.json5 不归本切片时，登记 deferred-work 交权限归口者，写明权限名、调用处和是否 user_grant
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- @permission ohos.permission.ACCELEROMETER / ohos.permission.GYROSCOPE（sensor.on），@permission ohos.permission.WRITE_IMAGEVIDEO（deleteAssets）：这些接口的声明里写着所需权限，缺权限抛 BusinessError 201（出处：鸿蒙 SDK 的 ets/api/@ohos.sensor.d.ts，sensor.on；ets/api/@ohos.file.photoAccessHelper.d.ts，MediaAssetChangeRequest.deleteAssets）
针对本应用要查的：
- 新引入接口要的权限：鸿蒙 SDK 的 ets/api/ 下该模块的 .d.ts，按方法签名往上读它前面最后一段注释；读 @permission 那一行和 @throws { BusinessError } 201；没有 @permission 的不用登记
未核实：卡里环境是鸿蒙 6.1.1(24)，本机按 API 23 核对
