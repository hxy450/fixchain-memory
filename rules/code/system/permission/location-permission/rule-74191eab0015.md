# 定位权限把 APPROXIMATELY_LOCATION 与 LOCATION 当一组判定，任一授予就继续

审的是：代码
触发（任一种）：
- 读到：源端同时声明 ACCESS_COARSE_LOCATION 与 ACCESS_FINE_LOCATION，两者都处理；写错的样子：requestPermissionsFromUser(context, [APPROXIMATELY_LOCATION, LOCATION]) 之后用 for 循环遍历 authResults，任一项 !== 0 就 return false（照搬通用「全部授予」模板），只授予模糊位置时定位被判为拒绝
适用范围：同时申请 ohos.permission.APPROXIMATELY_LOCATION 与 ohos.permission.LOCATION、按授权结果决定是否定位时
做法：
- 判定写成 result.authResults.some((s: number) => s === 0)：至少模糊位置那一项为 0 就继续定位
- 精确位置（LOCATION）那一项不为 0 时按模糊位置降级继续，不抛权限拒绝
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- requestPermissionsFromUser(context: Context, permissionList: Array<Permissions>): Promise<PermissionRequestResult>：AtManager 向用户申请权限（出处：鸿蒙 SDK 的 ets/api/@ohos.abilityAccessCtrl.d.ts，AtManager.requestPermissionsFromUser）
- authResults: Array<number>：0 已授予，-1 未授予，2 请求无效：按位置对应 permissionList 的每一项（出处：鸿蒙 SDK 的 ets/api/security/PermissionRequestResult.d.ts，PermissionRequestResult.authResults）
- 只申请 APPROXIMATELY_LOCATION 得到模糊位置（5 公里）；同时申请两项得到精准位置：两项是一组，授予模糊位置也能定位（出处：location-permission-guidelines.md，开发步骤）
- LOCATION 需要与 APPROXIMATELY_LOCATION 一起才可申请：精确权限依附于模糊权限（出处：permissions-for-all-user.md，ohos.permission.LOCATION）
- 改为 authResults.some(=== 0) 后，只授予模糊位置时定位按钮能工作：修复后的判定（出处：卡里修好并验证过）
- requestPermissionsFromUser(context: Context, permissionList: Array<Permissions>, requestCallback: AsyncCallback<PermissionRequestResult>): void：同族接口：回调形式的重载，结果同样在 authResults（出处：鸿蒙 SDK 的 ets/api/@ohos.abilityAccessCtrl.d.ts，AtManager.requestPermissionsFromUser）
