# 源端请求 FINE+COARSE 定位时，授权列表同时含模糊和精确两项定位权限

审的是：代码
触发（任一种）：
- 读到：源端同时请求 Manifest.permission.ACCESS_FINE_LOCATION 和 ACCESS_COARSE_LOCATION（如 PermissionX.permissions(...)、requestPermissions(...)）；写错的样子：授权检查和申请只 checkAccessTokenSync / requestPermissionsFromUser 'ohos.permission.LOCATION' 一项
适用范围：把安卓定位权限组迁成 abilityAccessCtrl 的授权检查和申请、并调用 geoLocationManager 定位时
做法：
- 逐项映射：ACCESS_FINE_LOCATION → ohos.permission.LOCATION，ACCESS_COARSE_LOCATION → ohos.permission.APPROXIMATELY_LOCATION；需要精确定位时 requestPermissionsFromUser(context, ['ohos.permission.APPROXIMATELY_LOCATION', 'ohos.permission.LOCATION'])
- 已授权判定用 checkAccessTokenSync(tokenId, 'ohos.permission.APPROXIMATELY_LOCATION')
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getCurrentLocation(request?: CurrentLocationRequest | SingleLocationRequest): Promise<Location> 的 @permission ohos.permission.APPROXIMATELY_LOCATION：定位接口要求的是模糊定位权限（出处：鸿蒙 SDK 的 ets/api/@ohos.geoLocationManager.d.ts，geoLocationManager.getCurrentLocation）
- 申请 APPROXIMATELY_LOCATION 得模糊位置（5 公里）；同时申请 APPROXIMATELY_LOCATION 和 LOCATION 得精准位置（米级）：前台定位只有这两种允许的申请方式（出处：location-permission-guidelines.md，开发步骤）
- API9 及之后无法单独申请 ohos.permission.LOCATION：只申请 LOCATION 不成立（出处：js-apis-geolocation.md，申请权限）
- requestPermissionsFromUser(context: Context, permissionList: Array<Permissions>): Promise<PermissionRequestResult>；checkAccessTokenSync(tokenID: number, permissionName: Permissions): GrantStatus：申请和检查授权的接口（出处：鸿蒙 SDK 的 ets/api/@ohos.abilityAccessCtrl.d.ts，AtManager.requestPermissionsFromUser、AtManager.checkAccessTokenSync）
