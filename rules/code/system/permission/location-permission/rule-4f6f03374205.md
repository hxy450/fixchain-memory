# 规格写先授权再定位时，链路写成授权 → isLocationEnabled → 定位

审的是：代码
触发（任一种）：
- 读到：源端先 isLocationEnabled() 检查 GPS 开关再请求权限；规格数据流写「确保授权 → 系统位置能力可用性检查 → 定位」，验收要求授权前不启动定位；写错的样子：目标沿用源端顺序，先 geoLocationManager.isLocationEnabled() 再 requestPermissionsFromUser
适用范围：目标定位链路的调用顺序与规格数据流不一致时
做法：
- 按规格数据流写：先 checkAccessTokenSync，未授权就 await requestPermissionsFromUser(...) → geoLocationManager.isLocationEnabled() → geoLocationManager.getCurrentLocation(...)
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function isLocationEnabled(): boolean：检查位置开关（出处：鸿蒙 SDK 的 ets/api/@ohos.geoLocationManager.d.ts，geoLocationManager.isLocationEnabled）
- getCurrentLocation 的错误码：201 权限校验失败、3301100 位置开关关闭、3301200 获取位置失败：三种失败分别对应未授权、开关关闭、定位失败（出处：鸿蒙 SDK 的 ets/api/@ohos.geoLocationManager.d.ts，geoLocationManager.getCurrentLocation）
