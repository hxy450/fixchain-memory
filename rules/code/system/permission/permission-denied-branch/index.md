# 权限拒绝、服务关闭或无坐标时的失败分支

agent 会看到什么：读过的源码里权限拒绝、定位服务关闭、无坐标时仍有反馈、错误提示或按城市的另一条查询；交回的仓库方法开头 return [] 短路，或 UI 只写了成功分支、errorMessage 没展示

## 规矩

- rule-201444af6a7c｜定位入口不只写成功分支，拒绝、关闭和失败时展示错误并保留手动兜底｜读到：源端 PermissionX 拒绝、永久拒绝和服务关闭时都有反馈（弹说明框、跳应用设置或位置设置）；规格验收要求这些情况不能静默，台账写定位失败开放手动选择；写错：UI 里 await 定位结果后只有 if (result) { … } 成功分支，ViewModel 已置的 errorMessage 没有展示
- rule-3d78ff817e13｜源端无权限或无坐标仍按城市查询时，目标数据层照分支保留城市查询，不用 return [] 短路｜读到：源端附近检索按当前城市建查询（如 PoiSearchV2.Query 带城市编码），只在有定位权限且有坐标时才附加 SearchBound 半径；写错：目标 Repository 的附近查询开头写坐标未知就 `return []`，只剩按坐标搜索，按城市查询的分支没了
- rule-60f09ec13ab6｜需授权的仓库方法里，无上下文、未授权、枚举失败都走声明的抛错通道，不静默 return []｜读到：源端 ViewModel 在 catch 里置加载失败错误（失败经异常从仓库传到 VM）；规格要求扫描失败或权限拒绝时显示错误提示，空列表另显示空态引导；写错：仓库方法注释写「权限拒绝时 throw」，却在权限检查前写 if (this.context === null) { return []; }，随后还用空结果 replaceAll 覆盖缓存
