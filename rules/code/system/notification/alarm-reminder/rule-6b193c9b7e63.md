# 源端以 Parcel 快照写回时，目标按快照覆盖写回，不改成 DB 现值优先或跳过

审的是：代码
触发（任一种）：
- 读到：Java `BroadcastReceiver.onReceive` 用 Parcel 反序列化还原快照对象，直接 set 字段后 update 写库，没有读回或存在性检查；写错的样子：ArkTS 写回前先按 id 读 DB 现值，读回为 null（已删）或已置位就 `return`；注释写「以 DB 现值优先（快照仅兜底）」「有据偏离」，台账里没有对应决策
适用范围：到点副作用、通知动作等以快照 upsert 写回的路径
做法：
- 按快照覆盖写回：用提醒或通知携带的快照对象直接 update/upsert，不先读 DB 现值，也不因记录已删或已置位而跳过（复活已删记录、覆盖之后的修改都照搬）
- 认为会损数据要偏离的，登记 PD 决策并在规格里写差异 AC，不在源码笔记里自记偏离后直接改
