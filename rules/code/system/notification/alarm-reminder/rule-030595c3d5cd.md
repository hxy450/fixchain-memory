# 提醒按钮用 subscribeReminderState 回调分派、贪睡写 timeInterval，不以系统型按钮近似

审的是：代码
触发（任一种）：
- 读到：源端提醒通知的按钮各带 PendingIntent：贪睡 = 现在加偏好分钟，推迟 = 弹时间选择器；写错的样子：ReminderRequest.actionButton 只写 ACTION_BUTTON_TYPE_SNOOZE / ACTION_BUTTON_TYPE_CLOSE 当「最大近似」，不设 timeInterval，不订阅按钮状态，按钮动作只能经点通知本体到达
适用范围：实现阶段用 reminderAgentManager 代理源端带动作按钮的闹钟提醒时（subscribeReminderState 声明标 @since 23）
做法：
- 按钮点击走 reminderAgentManager.subscribeReminderState((states) => …)：按 ReminderState.reminderId 和 buttonType 分派源端各按钮的动作；需要按钮级跳转的改用 notificationManager 本地通知的 NotificationActionButton.wantAgent
- 贪睡写 ReminderRequest.timeInterval = 偏好分钟 × 60（单位 s），不用系统默认间隔
- 核出规格的平台契约和声明冲突时，把受影响的 AC 判据标为阻塞，不只记 GAP
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- subscribeReminderState(callback: Callback<Array<ReminderState>>): Promise<void>，需 ohos.permission.PUBLISH_AGENT_REMINDER：订阅提醒按钮点击状态（出处：鸿蒙 SDK 的 ets/api/@ohos.reminderAgentManager.d.ts，reminderAgentManager.subscribeReminderState）
- ReminderState { reminderId: number; buttonType: ActionButtonType; isMessageResent: boolean }：同一次点击会发两次：用户点按钮时 isMessageResent 为 false，应用注册回调时再发一次为 true，分派时要去重（出处：鸿蒙 SDK 的 ets/api/@ohos.reminderAgentManager.d.ts，reminderAgentManager.ReminderState）
- timeInterval 单位 s，最少 30s：偏好分钟乘 60 写进去（出处：js-apis-reminderAgentManager.md，ReminderRequest）
- NotificationActionButton { title: string; wantAgent: WantAgent }：本地通知上的按钮级跳转（出处：鸿蒙 SDK 的 ets/api/notification/notificationActionButton.d.ts，NotificationActionButton）
- 加 subscribeReminderState 按钮回调和 timeInterval 贪睡后，按钮行为与安卓对齐：返修的落法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端每个按钮的动作和贪睡分钟数：源工程通知 helper 里 addAction 的 PendingIntent 和它指向的 Activity / Receiver，贪睡分钟数在偏好设置的 key 里；逐个按钮对上 buttonType 或本地通知按钮，贪睡分钟读出后乘 60
未核实：卡里环境是 API 24，声明按本机 API 23 核对
