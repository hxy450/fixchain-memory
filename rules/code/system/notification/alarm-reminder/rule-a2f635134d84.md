# publishReminder 失败或超出条数上限时回退本地通知，并保留应用侧链式重挂

审的是：代码
触发（任一种）：
- 读到：源端 AlarmManager 精确闹钟到点自绘通知，重复提醒（RRULE）到点后由应用链式挂下一次；写错的样子：publishReminder 失败只记日志、返回 0，没有条数上限处理，也没有 notificationManager 本地通知回退；重复提醒只发布首个发生
适用范围：实现阶段用 reminderAgentManager 代理源端精确闹钟、提醒可能多于平台上限或发布可能失败时
做法：
- catch publishReminder 的错误（1700001 通知未开启、1700002 个数超限等）后改用 notificationManager.publish(request) 发本地通知，到点补弹
- 有效提醒按时间轮转，只挂最近的、不超过上限，到点再补挂；重复提醒在应用侧链式重挂下一次，不只发布首个发生
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- publishReminder(reminderReq: ReminderRequest): Promise<number>；1700001 Notification is not enabled，1700002 The number of reminders exceeds the limit：要 catch 的失败（出处：鸿蒙 SDK 的 ets/api/@ohos.reminderAgentManager.d.ts，reminderAgentManager.publishReminder）
- 普通应用最多 30 个有效提醒：轮转的上限（出处：agent-powered-reminder.md，约束与限制）
- publish(request: NotificationRequest): Promise<void>：本地通知回退用的发布接口（出处：鸿蒙 SDK 的 ets/api/@ohos.notificationManager.d.ts，notificationManager.publish）
- 真机上 publishReminder 一直返回 1700002 时到点没有任何通知；加 30 条轮转、到点补弹和本地通知回退后恢复：不回退的后果和返修的落法（出处：卡里修好并验证过）
未核实：真机恒返回 1700002 的原因卡里写为未开通相应能力，本地文档副本里查不到对应说明
