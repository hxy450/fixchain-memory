# 源端建具名高重要度通知渠道时，写出渠道到 SlotType 的显式映射并声明这项替代

审的是：代码
触发（任一种）：
- 读到：new NotificationChannel(id, name, NotificationManager.IMPORTANCE_HIGH) 后 createNotificationChannel；写错的样子：addSlot 和 NotificationRequest 直接用通用 SlotType.SERVICE_INFORMATION，代码里没有源渠道 id、名称、重要度到目标槽的映射，交付汇报也没声明这项替代
适用范围：安卓具名通知渠道迁成鸿蒙通知槽时（鸿蒙 addSlot 只收 SlotType，不能自定义渠道名）
做法：
- 写一个显式映射常量：源渠道 id、名称（取资源）、重要度 → 目标 SlotType 与级别（IMPORTANCE_HIGH → SlotType.SERVICE_INFORMATION，对应 LEVEL_HIGH），注明目标不支持具名槽；addSlot 和请求的 notificationSlotType 都取这个常量
- 发布前用 getSlot 取槽，enabled 为 false 时显式降级；交付汇报里声明这项渠道替代
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function addSlot(type: SlotType): Promise<void>：只按类型加槽，没有名称参数（出处：鸿蒙 SDK 的 ets/api/@ohos.notificationManager.d.ts，notificationManager.addSlot）
- SlotType.SERVICE_INFORMATION = 2，对应 SlotLevel.LEVEL_HIGH（= 4）：与安卓 IMPORTANCE_HIGH 对应的服务类槽（出处：鸿蒙 SDK 的 ets/api/@ohos.notificationManager.d.ts，SlotType.SERVICE_INFORMATION、SlotLevel.LEVEL_HIGH）
- IMPORTANCE_HIGH = 4（到处显示、发声并浮动提示）：源渠道的重要度（出处：android.app.NotificationManager#IMPORTANCE_HIGH）
- notificationSlotType?: notificationManager.SlotType（默认 OTHER_TYPES）：请求上不写槽类型时落到 OTHER_TYPES，要和 addSlot 用同一个常量（出处：鸿蒙 SDK 的 ets/api/notification/notificationRequest.d.ts，NotificationRequest.notificationSlotType）
- function getSlot(slotType: SlotType): Promise<NotificationSlot>；readonly enabled?: boolean：取槽后看 enabled 判断槽是否被禁用（出处：鸿蒙 SDK 的 ets/api/@ohos.notificationManager.d.ts，notificationManager.getSlot；ets/api/notification/notificationSlot.d.ts，NotificationSlot.enabled）
针对本应用要查的：
- 源渠道的 id、名称和重要度：源工程 Java/Kotlin 里 new NotificationChannel(...) 的调用和渠道名引用的 strings.xml 资源；读出三个参数，名称对应到目标的字符串资源，重要度按上面的槽类型和级别映射
未核实：卡里环境是鸿蒙 target 6.0.1(21)，本机按 API 23 核对
