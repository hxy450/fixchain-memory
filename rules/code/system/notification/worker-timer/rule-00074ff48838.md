# 源端 Worker 逐拍刷新后台计时通知时，目标在短时任务窗口内照刷，到期转代理提醒

审的是：代码
触发（任一种）：
- 读到：WorkManager Worker 里 tickerFlow 每 500ms 刷新进度通知、步终切下一步、最后发完成通知；写错的样子：ArkTS 退后台只记锚点，notificationManager.publish 一条静态常驻通知，不启动 `countdown`，后台不推进
适用范围：源端后台逐拍刷新的计时通知迁到 ArkTS 时
做法：
- 退后台时用 backgroundTaskManager.requestSuspendDelay 申请短时任务，保活窗口内照源端节奏在进程内逐拍刷新通知、切换步骤
- 保活到期（回调触发）时把后续步骤交给 reminderAgentManager.publishReminder 代理提醒接续
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function requestSuspendDelay(reason: string, callback: Callback<void>): DelaySuspendInfo：申请延迟挂起，callback 在保活时间到期时触发（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceschedule.backgroundTaskManager.d.ts，backgroundTaskManager.requestSuspendDelay）
- function publishReminder(reminderReq: ReminderRequest): Promise<number>（需 ohos.permission.PUBLISH_AGENT_REMINDER）：发布代理提醒，返回提醒 id（出处：鸿蒙 SDK 的 ets/api/@ohos.reminderAgentManager.d.ts，reminderAgentManager.publishReminder）
未核实：短时任务保活窗口的时长随系统而定，声明里没写
