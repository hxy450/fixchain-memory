# 源端通知正文可为空时，NotificationBasicContent.text 不给空串，用不可见占位

审的是：代码
触发（任一种）：
- 读到：源端 `setContentText(...)` 的值可为 null，完成通知只有标题没有正文；写错的样子：ArkTS 写 `text: text !== null ? text : ''` 或完成通知 `text: ''`
适用范围：把可空正文的通知迁成 NOTIFICATION_CONTENT_BASIC_TEXT 等基础内容时
做法：
- text 不给空串：正文为空时用不可见占位（零宽空格 '\u200B'）或改用其他内容形态
- 完成通知和无进度文本的步骤分别核对一遍
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- text: string（Notification content. It cannot be empty or exceed 3072 bytes）：基础通知正文不能为空，超过 3072 字节截断（出处：鸿蒙 SDK 的 ets/api/notification/notificationContent.d.ts，NotificationBasicContent.text）
- title: string（cannot be empty or exceed 1024 bytes）：同族：标题同样不能为空（出处：鸿蒙 SDK 的 ets/api/notification/notificationContent.d.ts，NotificationBasicContent.title）
未核实：空正文被拒没有设备发布失败日志，按声明推定
