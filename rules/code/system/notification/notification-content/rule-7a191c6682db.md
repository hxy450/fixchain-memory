# 源端通知正文拼了多个字段时，目标通知 text 逐字段照输出，快照字段都要消费

审的是：代码
触发（任一种）：
- 读到：源端通知构建处 setContentText(…) 传入拼接的正文（如数值文本后接 " (m:ss)" 时长）；写错的样子：目标 publish 的 normal.text 只输出其中部分字段，某个字段只在另一字段缺失时才作为退路显示；服务快照 interface 里为正文定义的字段没被渲染函数读取
适用范围：把安卓通知（含前台服务、计时类常驻通知）的正文迁成鸿蒙 notificationManager 通知时
做法：
- 按源端拼正文的方法逐字段核对，目标 NotificationBasicContent.text 同时输出全部字段，格式照源端（如时长按 m:ss 拼在后面）
- 服务接口里自己定义的快照字段要在渲染处实际读取；自检发现未用的，要么接到输出，要么删掉并在汇报里说明原因
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- text: string（不能为空，超过 3072 字节截断）：NotificationBasicContent 的正文，源端正文的全部字段拼进这里（出处：鸿蒙 SDK 的 ets/api/notification/notificationContent.d.ts，NotificationBasicContent.text）
针对本应用要查的：
- 源端通知正文由哪些字段拼成：源工程 Java/Kotlin 里构建通知的方法（NotificationCompat.Builder 的 setContentText 调用及其传入字符串的拼接函数）；逐个列出拼进正文的字段和格式（含倍率换算后的时长），目标 text 照同样顺序拼
未核实：卡里环境是鸿蒙 target 6.0.1(21)，本机按 API 23 核对
