# 通知封装按源端 builder 默认值填齐 smallIcon 和默认大图标，再由调用方覆盖

审的是：代码
触发（任一种）：
- 读到：源端通知 helper 的 builder 默认调 setSmallIcon(...) 和 setLargeIcon(...)（默认大图标来自应用 drawable）；写错的样子：NotificationRequest 没写 smallIcon，largeIcon 只在调用方传入时才写，没有默认大图标
适用范围：实现阶段写 notificationManager 的通知封装时
做法：
- 封装里默认给 request.smallIcon 和 request.largeIcon 赋值（源端默认图标迁入后解码成 image.PixelMap），调用方有附件缩略图时再覆盖 largeIcon
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- smallIcon?: image.PixelMap；largeIcon?: image.PixelMap：通知的小图标和大图标，像素字节总数不超过 192 KB，建议 128 px × 128 px（出处：鸿蒙 SDK 的 ets/api/notification/notificationRequest.d.ts，NotificationRequest.smallIcon、NotificationRequest.largeIcon）
- 返修给通知封装补上默认大图标和 smallIcon：按源端 builder 默认值补齐（出处：卡里修好并验证过）
针对本应用要查的：
- 源端默认的小图标和大图标：源工程通知 helper 里 NotificationCompat.Builder 的 setSmallIcon、setLargeIcon 调用，及规格 render 节写的默认图标；读出 drawable 名，到目标 resources 下 media 里找迁入后的同名资源
