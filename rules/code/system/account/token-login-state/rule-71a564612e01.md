# 身份文案按 token 判登录、按源端 getter 回退链显示，未登录占位只进未登录分支

审的是：代码
触发（任一种）：
- 读到：源端按 token 判定登录（hasToken 一类），已登录时显示名字 getter 的结果，getter 在昵称为空时有回退分支（如回退成「用户」加 id），只有未登录的 else 分支才写「未登录」；写错的样子：目标表达式写成 昵称.length > 0 ? 昵称 : $r('app.string.…')（未登录占位资源），或 isLoggedIn && 昵称.length > 0 ? … : $r(…)，让昵称判空决定是否显示「未登录」
适用范围：把源端登录判定和用户名显示接成目标页面的身份文案表达式，或改写、内联已有的显示表达式时
做法：
- 展开源端显示 getter 的完整分支，把登录判定（token / session 的 isLoggedIn）和显示回退链（昵称 → 用户{id} → …）分开写；未登录占位资源只出现在 !isLoggedIn 分支，不拿它给已登录用户的空值兜底
- 改写或内联显示表达式时，对照源端 if/else 逐分支核对条件：新加的字段判空不能改变登录 / 未登录分支的判定依据
- 为「token 有效、昵称为空、id 存在」写一条显示用例，期望值取源端回退的结果
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 登录判定统一为 session/token，显示按 昵称 → 用户{id} → … 回退，未登录占位只在 !isLoggedIn 时返回；空昵称、有 id 的用例断言显示「用户」加 id：修好后的判定和显示写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端显示名的完整回退链：源工程里管理登录状态的类中，返回显示名的 getter 和页面里设置用户名的 if/else；按分支顺序列出每一级的取值条件和回退值，原样写成目标端的显示函数；登录判定照源端看 token 还是看 session
