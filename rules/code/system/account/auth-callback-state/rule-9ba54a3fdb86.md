# 单会话授权回调先比 state 判归属，不匹配直接忽略，匹配后才判成功、取消或失败

审的是：代码
触发（任一种）：
- 读到：规格或审计写「旧回调必须失效」「state 错配拒绝」「迟到回调不换账号」，每次请求生成随机 state 写进 SendAuthReq 等 SDK 请求；写错的样子：回调处理只查有没有当前会话和命令类型，没有先比 `state`，就把 `state` 不一致和错误码、空 `code` 放进同一个校验一起抛错，catch 后结束当前会话
适用范围：同一时刻只保留一个待处理授权会话、取消或超时后可重新发起的第三方登录回调处理
做法：
- 回调入口先比较 response.state !== session.state（或 requestId），不一致直接 return，当前会话继续等待；一致后才按错误码和 code 判成功、取消或失败
- 「旧回调失效」「state 错配拒绝」落实为该回调不产生任何效果：不登录、不判失败、不释放 busy，不写成结束当前会话
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 回调入口先比 state、不一致时 return，再进入原有的错误码和 code 校验：修好后的写法，后续加换码逻辑时也保留这条早退（出处：卡里修好并验证过）
针对本应用要查的：
- SDK 回调里带回的请求标识字段：目标工程依赖的第三方登录 SDK 的请求、响应类型声明（如 SendAuthReq 的 state 字段及对应响应类型）；确认响应原样带回请求时设的 state，用它和当前会话保存的值比较
