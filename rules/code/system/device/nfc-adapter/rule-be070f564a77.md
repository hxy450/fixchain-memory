# 用 canIUse 等换掉能力探测时，只在源端设标志的那个分支设标志，其余缺失只返回 false

审的是：代码
触发（任一种）：
- 读到：源端只在 NfcAdapter.getDefaultAdapter(...) 为 null 时设降级标志，其他不支持路径 return false；写错的样子：目标在 canIUse('SystemCapability.Communication.NFC.Tag') 不成立或适配器缺失任一情况下都调用同一个降级标志的 setter 置 true，注释引用「统一收敛」的验收条目
适用范围：实现阶段，把源端设备能力探测改写成目标端 syscap 或适配器检查时
做法：
- 判据换成目标端写法后仍按源端分支：只有对应「无适配器」的条件设降级标志；能力缺失（如 canIUse('SystemCapability.Communication.NFC.Tag') 为 false）只 return false，交给后续启动流程弹不支持提示
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- canIUse(syscap: string): boolean：按系统能力判断（出处：鸿蒙 SDK 的 ets/api/@internal/full/global.d.ts，canIUse）
- 仅无 NFC 适配器时设降级标志，NFC.Tag 能力缺失只返回 false，由启动链弹不支持对话框：修好后的分支（出处：卡里修好并验证过）
