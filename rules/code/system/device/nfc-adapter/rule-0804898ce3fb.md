# 源端分不支持和 NFC 关闭两支时，目标服务层拆开判断，关闭态打开系统 NFC 设置页

审的是：代码
触发（任一种）：
- 读到：源码 NfcAdapter 为 null 时提示不支持，isEnabled() 为 false 时 startActivity(Settings.ACTION_NFC_SETTINGS)；写错的样子：目标只有一个 isAvailable() 布尔门：canIUse 失败、nfcController.isNfcOpen() 为 false 和异常都返回 false，ViewModel 一律置 UNSUPPORTED 并提示不支持，没有打开设置页的入口和关闭态文案
适用范围：源端 NFC 入口有能力检查分支、目标用 HarmonyOS nfcController 时；openNfcSettingsPage 按文档 24+、仅 Stage 模型
做法：
- 服务层拆成可区分的结果：是否支持用 canIUse('SystemCapability.Communication.NFC.Core')，是否开启用 nfcController.isNfcOpen()，调用异常单独返回出错
- ViewModel 给不支持、已关闭、出错各设独立状态（如 DISABLED）；关闭态调 settings.openNfcSettingsPage(context) 打开系统 NFC 设置页，并给单独的提示文案（如「请在系统设置中开启 NFC，返回后再次点击」），不复用「不支持」文案
- 规格缺这个分支时不并入相邻分支：照上两步实现，或作为阻塞缺口写进回执交协调者裁决
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- canIUse("SystemCapability.Communication.NFC.Core")：判设备支不支持 NFC（isNfcAvailable 自 API 9 废弃，用它代替）（出处：鸿蒙 SDK 的 ets/api/@ohos.nfc.controller.d.ts，nfcController.isNfcAvailable 的 @useinstead）
- function isNfcOpen(): boolean：NFC 开关是否打开，true 为已开启（出处：鸿蒙 SDK 的 ets/api/@ohos.nfc.controller.d.ts，nfcController.isNfcOpen）
- openNfcSettingsPage(context: Context): void（24+，仅 Stage 模型，Phone、Tablet 上生效；错误码 16900010、16900020）：打开系统 NFC 设置页，context 用 UIAbilityContext 或 ExtensionContext（出处：js-apis-settings.md，settings.openNfcSettingsPage）
- function enableNfc(): void 只能由系统应用调用：普通应用不能直接打开 NFC，关闭态只能拉起设置页（出处：鸿蒙 SDK 的 ets/api/@ohos.nfc.controller.d.ts，nfcController.enableNfc）
- 服务层拆出 isSupported() 与 openSettings()（settings.openNfcSettingsPage），ViewModel 新增 DISABLED，未开启时打开系统 NFC 设置并提示返回后再次点击：修好后的做法，与源端行为一致（出处：卡里修好并验证过）
未核实：openNfcSettingsPage 本机 API 23 的声明里没有，只在文档里核到（标 24+）；卡里修复用的是 API 24
