# 接入平台蓝牙设备名时在单一入口归一：空名、等于地址或 12 位十六进制都当作无名称

审的是：代码
触发（任一种）：
- 读到：源端用 `BluetoothDevice.getName()` 取设备名，取不到时为 null，列表按空名回退；写错的样子：目标端把 `connection.getRemoteDeviceName(deviceId)`、扫描结果的 `deviceName` 在各页直接拿来显示，没有在一个入口把空名、等于地址或形如 12 位十六进制的名称归一为无名称
适用范围：目标端从鸿蒙蓝牙接口取远端设备名（扫描、已配对、已连接三类来源）并在界面显示时
做法：
- 在设备模型构造或蓝牙服务里写一个名称归一入口：trim 后为空、去掉冒号和横线后忽略大小写与设备地址相同、或去分隔符后匹配 /^[0-9A-Fa-f]{12}$/ 的，一律存为空名
- 扫描、已配对、已连接三类来源都经过这个入口，各页对空名用同一个回退文案
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function getRemoteDeviceName(deviceId: string, alias?: boolean): string：取远端设备名或别名，不传 alias 时默认取别名；deviceId 形如 11:22:33:AA:BB:FF（出处：鸿蒙 SDK 的 ets/api/@ohos.bluetooth.connection.d.ts，connection.getRemoteDeviceName）
- function getRemoteDeviceName(deviceId: string): string：不带 alias 的重载（出处：鸿蒙 SDK 的 ets/api/@ohos.bluetooth.connection.d.ts，connection.getRemoteDeviceName）
- DiscoveryResult.deviceName: string：同族接口：经典蓝牙发现结果里的设备名（出处：鸿蒙 SDK 的 ets/api/@ohos.bluetooth.connection.d.ts，connection.DiscoveryResult.deviceName）
- ScanResult.deviceName: string：同族接口：BLE 扫描结果里的设备本地名（出处：鸿蒙 SDK 的 ets/api/@ohos.bluetooth.ble.d.ts，ble.ScanResult.deviceName）
- BluetoothDevice.getName() 出问题时返回 null：源端空名是 null，目标端返回的是 string，空名的形态不同（出处：android.bluetooth.BluetoothDevice#getName）
- 在设备模型构造里把空名、与地址相同、形如 12 位十六进制的名称归一为空，另一页同步用同一回退：返修后重复 MAC 由 8 个降为 0（出处：卡里修好并验证过）
未核实：getRemoteDeviceName 对没有名称的设备是否返回 MAC：声明只写返回设备名，只见修复者判断；模型归一与另一页同步在卡里列为未决归因，修法本身已上机
