# 页面调用可能失败的服务时检查结果并复位进行中状态，规格里的失败分支逐个实现

审的是：代码
触发（任一种）：
- 读到：页面规格里有失败分支，如蓝牙关闭时显示恢复卡（打开蓝牙设置），状态取自 `@ohos.bluetooth.access`；写错的样子：页面先置 `scanning = true` 再调用服务的 `startScan()`，不检查返回值、失败不复位；没有规格里的蓝牙关闭恢复卡，只在超时后提示没找到设备
适用范围：连接页一类页面调用可能失败的系统服务、页面规格列有失败分支时
做法：
- 写页面前读对应页面规格，核对每个条件分支（如蓝牙关闭的恢复卡和它的文案），逐个实现
- 调用写成 `if (!svc.startScan()) { this.scanning = false; <显示 getScanError() 对应的失败态> }`，失败时复位进行中状态
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 页面检查返回值、复位 scanning 并显示错误，文案用源端的蓝牙关闭字符串：修好后的页面写法（出处：卡里修好并验证过）
针对本应用要查的：
- 失败分支的文案：源工程 res/values/strings.xml 里蓝牙关闭、打开设置一类字符串；照抄到目标 string.json，页面失败态引用它
