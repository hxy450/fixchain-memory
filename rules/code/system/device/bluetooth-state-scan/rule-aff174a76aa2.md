# 源端显式建模扫描失败和适配器关闭时，目标服务映射成可查询的错误给页面用

审的是：代码
触发（任一种）：
- 读到：源端用 `BluetoothState` 一类适配器状态和 `BleScanStartException` 一类扫描启动异常建模失败，决策台账有「不崩溃、显式失败」的兜底决策；写错的样子：目标服务的 `startScan()` 返回 `void`，不查适配器状态、不保存失败原因，页面拿不到任何失败信息
适用范围：迁移源端带失败建模的系统能力封装（如 BLE 扫描）时
做法：
- 把已批准的失败兜底决策逐个落到每个系统调用入口：入口返回 `boolean`，失败原因存进 `lastScanError`，另给 `getScanError()` 供页面查询
- 源端的每种失败（适配器关闭、启动失败）在目标服务里都对应一个可查询的状态或错误，页面据此显示失败态
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- startScan 改为返回 boolean，以 try/catch 收敛到 lastScanError，新增 getScanError()；stop 等调用加保护：修好后的服务写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端有哪些失败建模：源工程里蓝牙仓库和传输层的类：适配器状态类、扫描异常类、异常分类和重试逻辑；每种失败列出触发条件和给页面的表现，在目标服务里各对应一个错误码或状态
