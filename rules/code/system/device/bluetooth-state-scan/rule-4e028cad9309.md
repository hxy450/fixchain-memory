# 初始水合先同步读 access.getState() 通知 UI，再 await 偏好和通知授权

审的是：代码
触发（任一种）：
- 读到：源端 initView 先同步读蓝牙开关设置开关图，再读偏好；写错的样子：ViewModel 的 load() 在权限、偏好、通知授权等几次 await 之后才给开关赋值（= getState() 或 isEnabled()）
适用范围：页面或 ViewModel 初始化时既要显示系统真值、又要读偏好等异步数据时
做法：
- load() 开头先同步 this.enabled = access.getState() 回读的结果并通知 UI，再 await 偏好、通知授权等异步读取；不把系统状态和无关 await 绑成一次性赋值
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function getState(): BluetoothState：同步返回，不需要等（出处：鸿蒙 SDK 的 ets/api/@ohos.bluetooth.access.d.ts，access.getState）
- 系统状态同步前移到其他异步读取之前：修好的写法（出处：卡里修好并验证过）
