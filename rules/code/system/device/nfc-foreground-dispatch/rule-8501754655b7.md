# 源端前台派发无条件开启时，不在前台贴卡回调里按自启动开关加闸门

审的是：代码
触发（任一种）：
- 读到：基类 onResume 无条件 enableForegroundDispatch，偏好开关只用于 setComponentEnabledSetting 启停 alias；写错的样子：前台 tag 回调（tag.on('readerMode', …) / registerForegroundDispatch 的 callback）开头按偏好开关 return，开关关闭时前台贴卡不响应
适用范围：迁移「贴卡自启动」类开关、目标端同时有前台派发和 TAG_FOUND 系统派发的实现
做法：
- 去掉前台回调里的开关判断；开关只在入口 Ability 处理 TAG_FOUND 拉起时判断：关闭时冷启动调 this.context.terminateSelf()，热启动退回后台
- 接口位或骨架要求在前台派发期消费开关、而源端基类无条件开启前台派发时，把冲突回报给规格，不在前台回调里加闸门
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function registerForegroundDispatch(elementName: ElementName, discTech: number[], callback: AsyncCallback<TagInfo>): void：前台派发注册，回调里不按自启动开关过滤（出处：鸿蒙 SDK 的 ets/api/@ohos.nfc.tag.d.ts，tag.registerForegroundDispatch）
- function on(type: 'readerMode', elementName: ElementName, discTech: number[], callback: AsyncCallback<TagInfo>): void：同族接口：readerMode 前台读卡注册，同样不按开关过滤（出处：鸿蒙 SDK 的 ets/api/@ohos.nfc.tag.d.ts，tag.on）
- terminateSelf(): Promise<void>：开关关闭时冷启动由系统派发拉起，入口 Ability 自行结束（出处：鸿蒙 SDK 的 ets/api/application/UIAbilityContext.d.ts，UIAbilityContext.terminateSelf）
未核实：卡里的修复出自 API 24（6.1.1），本机声明是 API 23
