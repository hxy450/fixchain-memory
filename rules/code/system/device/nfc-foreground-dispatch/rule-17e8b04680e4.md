# 源页面继承开关前台派发的基类时，目标在 NavDestination 的 onShown/onHidden 里登记和注销

审的是：代码
触发（任一种）：
- 读到：页面类 extends 一个在 onResume 开、onPause 关 NFC 前台派发的基类 Activity；或服务的订阅接口注释写明页面 onShow 期注册、onHide 期注销；写错的样子：页面把标签订阅写在 aboutToAppear、注销写在 aboutToDisappear，被别的页面覆盖后仍收卡
适用范围：继承源端前台派发基类的每个页面，迁成 NavDestination 页面时
做法：
- 在 NavDestination 上写 .onShown(() => 登记本页为可见页 / 订阅) 和 .onHidden(() => 注销)，调用服务给的可见页登记入口；不放在 aboutToAppear / aboutToDisappear
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onShown(callback: Callback<VisibilityChangeReason>): NavDestinationAttribute：NavDestination 页面显示时回调（对应源端 onResume）（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onShown）
- onHidden(callback: Callback<VisibilityChangeReason>): NavDestinationAttribute：NavDestination 页面隐藏时回调（对应源端 onPause），被新页面覆盖时也会触发（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onHidden）
- 订阅放在 aboutToAppear / aboutToDisappear 时，被覆盖的页面仍收卡；改到 onShown / onHidden 后只有可见页收卡：修复后保留的写法（出处：卡里修好并验证过）
未核实：卡里观察到的行为出自 API 24 目标 SDK，本机按 API 23 核实
