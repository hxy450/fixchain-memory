# 源随 onResume/onPause 开关 NFC 前台派发时，目标改在 UIAbility 前后台开关

审的是：代码
触发（任一种）：
- 读到：源端基类 Activity 的 onResume 里 NfcAdapter.enableForegroundDispatch、onPause 里 disableForegroundDispatch，onNewIntent 统一处理新标签，多数页面继承它；写错的样子：目标在某个页面的 onHidden / aboutToDisappear 里调 tag.unregisterForegroundDispatch，注销整个应用的派发；或注册函数里顺带设置当前待处理页；收到标签广播给所有监听者
适用范围：把 Activity 级的 NFC 前台派发迁到 HarmonyOS tag 模块、页面用 Navigation / NavDestination 组织时
做法：
- 在 EntryAbility 的 onForeground() 里调 tag.registerForegroundDispatch(elementName, 技术列表, 回调)，onBackground() 里调 tag.unregisterForegroundDispatch(elementName)；任何单个页面隐藏时都不注销
- 服务里维护可见页登记表，给页面可直接调用的显示/隐藏登记入口；回调收到 TagInfo 只投递给当前可见的顶页，并带源基类 onNewIntent 的默认处理（仿真 onPause → onNewIntent → onResume）
- 设置待处理组件名单独成一步，不合并进通用的注册函数
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function registerForegroundDispatch(elementName: ElementName, discTech: number[], callback: AsyncCallback<TagInfo>): void：按 ElementName（bundleName + abilityName）注册前台派发，粒度是 UIAbility（出处：鸿蒙 SDK 的 ets/api/@ohos.nfc.tag.d.ts，tag.registerForegroundDispatch）
- function unregisterForegroundDispatch(elementName: ElementName): void：按同一个 ElementName 注销（出处：鸿蒙 SDK 的 ets/api/@ohos.nfc.tag.d.ts，tag.unregisterForegroundDispatch）
- function on(type: 'readerMode', elementName: ElementName, discTech: number[], callback: AsyncCallback<TagInfo>): void：同族接口：读卡器模式的前台注册，同样按 ElementName（出处：鸿蒙 SDK 的 ets/api/@ohos.nfc.tag.d.ts，tag.on('readerMode')）
- onForeground(): void；onBackground(): void：UIAbility 进入前台、转到后台的回调，注册和注销写在这里（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.UIAbility.d.ts，UIAbility.onForeground / UIAbility.onBackground）
- enableForegroundDispatch 只能在 Activity 处于前台（resumed）时调用，Activity 要在 onPause 完成前 disableForegroundDispatch：源端的开关粒度是每个 Activity 的前后台（出处：android.nfc.NfcAdapter#enableForegroundDispatch）
- 注册移到 EntryAbility 前后台、服务按可见页投递后，各页只在可见时收卡：修复后保留的写法（出处：卡里修好并验证过）
未核实：卡里观察到的行为出自 API 24 目标 SDK，本机按 API 23 核实
