# 源端采集 OAID 且规格要求承接时，目标用 identifier.getOAID 真实采集，不写「无对等 API」

审的是：代码
触发（任一种）：
- 读到：源端用 MSA 的 MiitHelper 或厂商通道采集 OAID，写缓存、上送接口并发布就绪事件；规格验收要求承接，裁剪项里没有 OAID；写错的样子：目标取 OAID 的方法在缓存未命中分支只有注释「HMOS 侧无对等 API」「待平台标识域 API 核验后接通」，没有调 identifier.getOAID()，不上送、不发事件
适用范围：规格要求采集或上送 OAID 等平台标识、且没把它列为无等价裁剪项时的服务层实现
做法：
- 写成 import { identifier } from '@kit.AdsKit'; const oaid: string = await identifier.getOAID();，再按规格写缓存、上送并发布事件
- 拿不准时先在本地 SDK 的 ets/api 和 ets/kits 里检索候选模块（如 @ohos.identifier.oaid.d.ts、@kit.AdsKit），检索确实无果才登记延迟占位
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function getOAID(): Promise<string>：取 OAID（Promise 形式），@since 10，需要 ohos.permission.APP_TRACKING_CONSENT（出处：鸿蒙 SDK 的 ets/api/@ohos.identifier.oaid.d.ts，identifier.getOAID）
- function getOAID(callback: AsyncCallback<string>): void：同族接口：回调形式的重载（出处：鸿蒙 SDK 的 ets/api/@ohos.identifier.oaid.d.ts，identifier.getOAID）
- export { AdComponent, AutoAdComponent, RespCallback, advertising, identifier }：@kit.AdsKit 导出 identifier，可以从 kit 导入（出处：鸿蒙 SDK 的 ets/kits/@kit.AdsKit.d.ts，identifier）
- 新建采集生产者，在服务里接入 getOAID 和上送：修好后的写法（出处：卡里修好并验证过）
未核实：卡里上机的是 HarmonyOS 6.0.1 / 6.1.1（API 21 / 24），本机核对用的是 API 23 的声明
