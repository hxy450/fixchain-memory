# 源端同步先 cancel 再 vibrate 时，网关用 Promise 队列串行发出停止和振动

审的是：代码
触发（任一种）：
- 读到：源端同一方法里先同步调用 `Vibrator.cancel()` 再调用 `vibrate(long[] pattern, int repeat)`（或别的 stop 后 start、先释放再创建），后一调用依赖前一调用已生效；写错的样子：目标网关的 void 方法里 `vibrator.stopVibration()` 和 `vibrator.startVibration(...)` 各自发出、只挂 `.catch`，后一调用不等前一调用完成；只核了调用点顺序和源码一致
适用范围：把源端连续的同步平台调用映射到返回 Promise 的鸿蒙 API，而网关或服务层方法按规格保持 void 时
做法：
- 网关内部持有一条 Promise 链：`private chain: Promise<void> = Promise.resolve()`；每个平台调用写成 `this.chain = this.chain.then(() => vibrator.stopVibration()).catch((e: BusinessError) => { 记日志 })`，前一调用 settle（成功或失败）后才发下一个，吞错和日志照旧
- 取消这一步也可以改用同步变体 `vibrator.stopVibrationSync()`，之后再发 `startVibration`
- 对每个返回 Promise 的平台调用，列出调用点紧邻的前后平台调用；源端依赖它们的先后时，目标端必须有 await 或进同一队列
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function startVibration(effect: VibrateEffect, attribute: VibrateAttribute): Promise<void>：发起振动，异步返回（出处：鸿蒙 SDK 的 ets/api/@ohos.vibrator.d.ts，vibrator.startVibration）
- function stopVibration(): Promise<void>：停止任何类型的振动，异步返回（出处：鸿蒙 SDK 的 ets/api/@ohos.vibrator.d.ts，vibrator.stopVibration）
- function stopVibrationSync(): void：停止振动的同步变体（声明里 @since 12）（出处：鸿蒙 SDK 的 ets/api/@ohos.vibrator.d.ts，vibrator.stopVibrationSync）
- function stopVibration(stopMode: VibratorStopMode): Promise<void>：同族接口：按停止模式停止，同样异步返回（出处：鸿蒙 SDK 的 ets/api/@ohos.vibrator.d.ts，vibrator.stopVibration(stopMode)）
- 队列串行后日志顺序为：取消完成 → 网关记录 stop 结果 → 发波形：串行化之后取消先于新波形生效（出处：卡里修好并验证过）
未核实：鸿蒙模拟器没有振动器，未实测到落底振动被截断；串行修改靠日志顺序确认；改用 stopVibrationSync 的写法卡里没有上机验证
