# A2DP/HFP 分协议连接回调按设备聚合，所有协议都断开才算断开

审的是：代码
触发（任一种）：
- 读到：源端连接/断开走 BluetoothDevice 的 ACL 设备级广播（ACTION_ACL_CONNECTED / ACTION_ACL_DISCONNECTED）；写错的样子：a2dp 或 hfp 任一 profile 的 on('connectionStateChange') 收到 STATE_DISCONNECTED 就上报设备断开；待断开设备收到首个协议的断开即判定断开成功
适用范围：用 A2DP、HFP 等分协议 profile 的连接回调代替源端设备级连接事件时
做法：
- 按 deviceId 聚合：A2DP、HFP 任一仍是 STATE_CONNECTED，或各 profile getConnectedDevices() 的并集里仍有该设备，都不判定断开或断开成功
- 连接、配对成功也要等系统回调或回读确认后才显示
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function createA2dpSrcProfile(): A2dpSourceProfile；function createHfpAgProfile(): HandsFreeAudioGatewayProfile：取 A2DP、HFP 的 profile 对象，二者都继承 BaseProfile（出处：鸿蒙 SDK 的 ets/api/@ohos.bluetooth.a2dp.d.ts，a2dp.createA2dpSrcProfile；ets/api/@ohos.bluetooth.hfp.d.ts，hfp.createHfpAgProfile）
- on(type: 'connectionStateChange', callback: Callback<StateChangeParam>): void；StateChangeParam.state: ProfileConnectionState：单个协议的连接状态变化，只代表这一个协议（出处：鸿蒙 SDK 的 ets/api/@ohos.bluetooth.baseProfile.d.ts，BaseProfile.on('connectionStateChange')、StateChangeParam）
- getConnectedDevices(): Array<string>：这个协议当前已连接设备的地址列表；需要 ohos.permission.ACCESS_BLUETOOTH（出处：鸿蒙 SDK 的 ets/api/@ohos.bluetooth.baseProfile.d.ts，BaseProfile.getConnectedDevices）
- getConnectionState(deviceId: string): ProfileConnectionState：回读某设备在这个协议上的连接状态（出处：鸿蒙 SDK 的 ets/api/@ohos.bluetooth.baseProfile.d.ts，BaseProfile.getConnectionState）
- ProfileConnectionState：STATE_DISCONNECTED = 0、STATE_CONNECTING = 1、STATE_CONNECTED = 2、STATE_DISCONNECTING = 3：协议连接状态枚举（出处：鸿蒙 SDK 的 ets/api/@ohos.bluetooth.constant.d.ts，constant.ProfileConnectionState）
- 新增「所有协议都断开才算断开」的判断，连接页只在回调或回读确认后显示成功：修好的写法（出处：卡里修好并验证过）
