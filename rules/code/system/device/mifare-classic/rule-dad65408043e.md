# 源 API 以 false 表示被拒、目标只会 reject 时，先写单次适配器区分被拒与丢卡，重试都经它

审的是：代码
触发（任一种）：
- 读到：源码 ret = authenticateSectorWithKeyA/B(...) 取 boolean，ret 为 false 时按偏好重试，只有 IOException、TagLostException 这类异常才立即返回 false；写错的样子：目标的认证方法 try { await ….authenticateSector(...) } catch { return false }：任何 reject 都直接返回，「被拒后重试」的分支永远走不到
适用范围：安卓 MifareClassic 认证这类以返回值表示被拒、以异常表示丢卡的 API，迁到只以 Promise reject 报错的 MifareClassicTag 时
做法：
- 写一个单次原语适配器：await authenticateSector(sectorIndex, key, isKeyA) resolve 返回 true；reject 且判为被拒返回 false；判为丢卡时 throw
- 所有带重试或返回码的上层方法（认证、读扇区、写块等）每轮都调这个适配器：得 false 按偏好进下一轮，捕到 throw 才立即失败；上层不再 catch 全部 reject 后直接返回
- 按规格判定用例走读：持续被拒在目标上表现为每轮 reject，确认代码确实进入第 2、3 轮，次数与用例一致
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- authenticateSector(sectorIndex: number, key: number[], isKeyA: boolean): Promise<void>：目标的扇区认证没有 boolean 结果，被拒只能以 reject 出现（出处：鸿蒙 SDK 的 ets/api/tag/nfctech.d.ts，MifareClassicTag.authenticateSector）
- @throws BusinessError 201、401、3100201（The tag running state is abnormal in the service）、3100204（The tag I/O operation failed）：声明列出的 reject 码，没有写哪个是密钥被拒（出处：鸿蒙 SDK 的 ets/api/tag/nfctech.d.ts，MifareClassicTag.authenticateSector）
- @return true on success, false on authentication failure；@throws TagLostException if the tag leaves the field：源端被拒走返回值、丢卡走异常（出处：android.nfc.tech.MifareClassic#authenticateSectorWithKeyA）
