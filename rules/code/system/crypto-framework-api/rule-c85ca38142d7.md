# MessageDigest 输入可能为空时，Md 遇空串不调 update，直接返回空串摘要常量

审的是：代码
触发（任一种）：
- 读到：源码对可能为空的字符串调用 `MessageDigest.digest(value.toByteArray())` 求摘要，或规格允许空字段参与哈希；写错的样子：ArkTS 里无条件 `md.update({ data: bytes })` 后 `md.digest()`，没有处理 bytes 长度为 0 的情况
适用范围：把 java.security.MessageDigest 求摘要改写成 cryptoFramework.createMd 的 Md，且输入可能是空串或空字节数组时
做法：
- 先判空：输入字节长度为 0 时直接返回 SHA-256("") 的常量 e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855，不调用 update
- 非空时才 `await md.update({ data: bytes })`，再 `await md.digest()` 取 `.data` 转十六进制
- 单元测试里补一条空串输入的用例，期望值就是上面的常量
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- update(input: DataBlob): Promise<void>；updateSync(input: DataBlob): void：Md 传入消息更新摘要状态的异步、同步写法（出处：鸿蒙 SDK 的 ets/api/@ohos.security.cryptoFramework.d.ts，Md.update / Md.updateSync）
- digest(): Promise<DataBlob>；digestSync(): DataBlob：Md 输出摘要结果（出处：鸿蒙 SDK 的 ets/api/@ohos.security.cryptoFramework.d.ts，Md.digest / Md.digestSync）
- interface DataBlob { data: Uint8Array }：update 的入参，字节放在 data 里（出处：鸿蒙 SDK 的 ets/api/@ohos.security.cryptoFramework.d.ts，DataBlob.data）
- e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855：SHA-256("") 的十六进制，空串时直接返回它（出处：卡里修好并验证过）
- Md.update 传入空的 DataBlob 时运行时报 `build context fail.`：空输入照常 update 会失败，不会得到空串摘要（出处：卡里修好并验证过）
- update(input: DataBlob): Promise<void>（Mac）：同族接口：Mac 的 update，入参同为 DataBlob；空输入是否同样报错卡里没验证（出处：鸿蒙 SDK 的 ets/api/@ohos.security.cryptoFramework.d.ts，Mac.update）
- update(data: DataBlob): Promise<DataBlob>（Cipher）：同族接口：Cipher 的分段加解密 update；空输入是否同样报错卡里没验证（出处：鸿蒙 SDK 的 ets/api/@ohos.security.cryptoFramework.d.ts，Cipher.update）
未核实：Md.update 拒绝空 DataBlob 在声明和文档里都没写明，出自卡里的运行时观察；Mac、Cipher 的 update 遇到空输入是否同样报错
