# 小部件转 ArkTS 卡片时文字按源 sp 写 fp、图标随空间分配，不按 designWidth 放大

审的是：代码
触发（任一种）：
- 读到：源小部件布局按钮 match_parent / wrap_content，android:drawableTop 放图标，android:textSize 用 sp；appwidget-provider 的 minWidth / minHeight 很小；写错的样子：ArkTS 卡片里图标写成固定的大 width / height（vp），Text 的 fontSize 放大成源值的倍数，理由是 designWidth 720 要放大；桌面上文字被截断
适用范围：把安卓桌面小部件布局转成 ArkTS 服务卡片、确定图标和文字尺寸时
做法：
- Text 的 fontSize 写源 sp 的同数值 fp，宽度满宽居中；图标 Image 写 .width('100%').layoutWeight(1) 随卡片剩余高度分配，不写固定大尺寸
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- designWidth 属于 form_config.json 的 window 标签，只支持在 JS 卡片中使用：ArkTS 卡片的 vp、fp 不受 designWidth 影响，不需要按它放大（出处：arkts-ui-widget-configuration.md，window标签）
- lpx 是实际屏幕宽度与 designWidth 的比值；fp 默认等于 vp，随系统字体缩放：designWidth 只影响 lpx，源 sp 直接对应 fp（出处：faqs-arkui-component.md，组件支持的参数类型及参数单位类型区别是什么，使用场景是什么(API 10)）
- layoutWeight(value: number | string): T：图标按权重占满剩余空间（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.layoutWeight）
- 固定 120vp 图标加放大字号时卡片文字被截断；改成图片 width 100% + layoutWeight(1)、文字按源 sp 写 fp 满宽居中后完整显示：返修后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源小部件的字号和图标布局：源工程 res/layout 下小部件布局 XML，以及 res/xml 下 appwidget-provider 的 minWidth / minHeight；读 android:textSize 的 sp 数值写成 fp；drawableTop 图标改成卡片里按权重分配的 Image
