# 源端状态跨进程读不到时，选语义相同的持久投影，不借名称相近的派生值

审的是：代码
触发（任一种）：
- 读到：规格的卡片数据流是 combine(运行标志, items)，并写明 FormExtensionAbility 与主 UIAbility 不共享内存、状态源只能是 RDB + preferences；写错的样子：FormExtensionAbility 侧用另一个派生值（如「最近一次同步时间在 N 秒内」）代替「worker 正在运行」，注释写「源：X」而 X 与所用的值定义不同
适用范围：源端某个内存状态在目标端因进程隔离（如服务卡片进程）读不到、要改从持久数据推出时
做法：
- 从可读的持久投影里选与源信号定义相同的那个（如表里「正在同步」的持久列，任一行为 true 即同步中），不用名称相近、定义不同的派生值（如时间窗口）
- 注释里的「源：X」只写真正等价的符号；两个源端信号不同时在注释里分开写明
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- UIAbility 组件默认运行在主进程中，FormExtensionAbility 组件运行在独立进程中，两者进程隔离：卡片侧读不到主进程的内存状态，只能读持久数据（出处：stage-model-development-overview.md，构成要素）
- 改为「任一行的正在同步列为 true」判同步中，注释里区分另一个按时间窗口派生的信号：修好的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 与源信号定义相同的持久投影是哪一列或哪个键：源工程里写这个运行标志的地方（worker 开始、结束时同步写入的数据库列或 preferences 键），以及目标工程 DAO 里对应的写入方法；选随运行开始置真、结束置假的那一项；只按时间推测的派生值不算
