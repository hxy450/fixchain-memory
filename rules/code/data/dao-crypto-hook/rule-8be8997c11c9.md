# 钩子默认是恒等实现时，依赖 DAO 加解密的备份导出导入任务开始前先确保钩子已注入

审的是：代码
触发（任一种）：
- 读到：源端导出时对 DAO 读出的明文记录再 encrypt(...)、导入时先 decrypt(...) 再交给 DAO 写回；目标 DAO 的钩子默认值是恒等/空实现；写错的样子：目标端导出/导入任务直接调 DAO 的读写方法，开始前没有确保钩子已注入（没有先行调用注入入口，也没有在未注入时 `throw`）
适用范围：基座给数据层钩子配了恒等/空默认实现、而备份导出导入等调用方依赖 DAO 读出时已解密、写回时会加密时
做法：
- 这类任务开头先确保钩子已注入（未注入就先调用注入入口），再读写 DAO
- 确保不了时让任务显式失败（抛错），不在恒等默认下继续读写
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 备份服务在导出/导入任务开始前先确保钩子注入：修好的写法，和启动期注入并存（出处：卡里修好并验证过）
