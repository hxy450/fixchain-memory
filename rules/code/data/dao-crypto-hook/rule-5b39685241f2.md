# 数据层钩子替代源端无条件加解密时，注入放进 EntryAbility.onCreate，不挂单例 getInstance

审的是：代码
触发（任一种）：
- 读到：安卓 DAO 的读写方法里无条件直接调用加解密（写入时 encrypt(...)、读出时 decrypt(...)），源端没有「未注入」状态；目标 DAO 由基座留了钩子 setter，默认值是恒等/空实现；写错的样子：钩子的 setter 注入写在某个业务单例 getInstance() 的首次构造分支里，EntryAbility.onCreate 里没有这次注入
- 写错的样子：收尾装配时 EntryAbility.onCreate 装配了各项 init 移交，注入点却仍只挂在某业务单例的 getInstance() 上，依据只是 DAO 里「已兑现、注入点 = ….getInstance()」的注释
适用范围：源端数据层每次读写都无条件做加解密等横切处理、目标端改由基座 DAO 的 setter 注入钩子且未注入时为恒等/空默认实现时
做法：
- 注入放进应用启动序列：EntryAbility.onCreate 里数据库 init 之后、任何读写和页面分发之前，直接调用 DAO 的钩子 setter，或显式取用一次负责注入的单例（调用它的 getInstance()）
- 不把注入挂在只有部分路径才会取用的业务单例首次构造上（如只有开了启动锁才走的验密流程）；对每个 setter 注入点核对它的调用方在冷启路径上是否必经
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onCreate(want: Want, launchParam: AbilityConstant.LaunchParam): void：UIAbility 冷启动时进入的初始化回调，同步返回，不支持异步回调；EntryAbility 继承 UIAbility（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.UIAbility.d.ts，UIAbility.onCreate）
- EntryAbility.onCreate 在数据库 init 之后、页面分发之前加一次注入入口的取用：修好的位置；冷启后列表读出为明文，保存不再二次加密（出处：卡里修好并验证过）
针对本应用要查的：
- 冷启路径上最早的一次数据库读写在哪：目标工程里 UIAbility 子类的 onCreate / onWindowStageCreate，以及首页组件 aboutToAppear 里调用 DAO 读方法的位置；注入调用必须排在其中最早的一处之前；只在某个条件分支里才会执行的位置不算
未核实：卡里环境是 HarmonyOS 6.1.1(24)，onCreate 的签名和说明按本机 API 23 核实
