# 种子带固定主键时首建写入该 id，补充路径按 copy(id = 0) 插新行，两条路径分开构造

审的是：代码
触发（任一种）：
- 读到：源端种子数据的 Room 实体构造里显式传 id = <常量>（固定主键）；手动补充或复制路径用 copy(id = 0) 插入；写错的样子：首建播种的 ValuesBucket 不写 id、由自增主键重新编号；或补充路径复用首建的构造函数也写入固定 id
适用范围：目标端用 relationalStore 插入源端带固定主键的预置数据，以及补充、复制预置项时
做法：
- 首建播种的 ValuesBucket 写入源端的固定 id（'id': seed.id）
- 补充或复制路径照源端 copy(id = 0) 插新行：ValuesBucket 不带 id，交给自增主键
- 两条路径各自构造 ValuesBucket；改共享的构造函数前先查它的全部调用方
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- insert(table: string, values: ValuesBucket): Promise<number>：插入一行，成功返回行 ID，失败返回 -1（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，RdbStore.insert）
- 首建用带 id 的一套 bucket，补充用不带 id 的新副本：两条路径分开后，列表顺序与源端一致、补充不撞主键（出处：卡里修好并验证过）
针对本应用要查的：
- 源端种子的固定主键值：源工程里预置数据的定义（Room 实体构造里显式传的 id 常量）；逐个读出 id，首建播种时原样写进 ValuesBucket
