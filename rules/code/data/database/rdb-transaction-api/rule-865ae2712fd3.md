# 普通 RDB 库的多语句事务用 beginTransaction 系列，不用 beginTrans

审的是：代码
触发（任一种）：
- 读到：relationalStore.getRdbStore 的 StoreConfig 里没有 vector: true；参考给的是 beginTransaction() 或 createTransaction()；写错的样子：代码用 beginTrans() 取事务 ID，再 execute(sql, txId, args)、commit(txId)、rollback(txId)
- 读到：Room 的 @Transaction 方法、RoomDatabase.runInTransaction / withTransaction；写错的样子：公共事务辅助写成 await store.beginTrans() 再 commit(txId) / rollback(txId)，运行时抛 801
适用范围：@kit.ArkData relationalStore 普通（非向量）库上要多条语句一起成败的写入，含 Room 事务迁成的公共事务辅助
做法：
- 写成 store.beginTransaction() → 逐条 await store.execute(sql, args) → store.commit()，异常时 store.rollBack() 再原样抛出；API 14 起也可用 await store.createTransaction() 返回的 tx 的 execute / commit() / rollback()
- 带 txId 的 beginTrans / execute(sql, txId, args) / commit(txId) / rollback(txId) 只留给 StoreConfig 设了 vector: true 的向量库
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- beginTransaction(): void；commit(): void；rollBack(): void：RdbStore 上不带事务 ID 的一套事务接口，不嵌套、不跨进程或线程；公共封装被嵌套调用时要自己判断是否已在事务里（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，RdbStore.beginTransaction / RdbStore.commit / RdbStore.rollBack；arkts-apis-data-relationalStore-RdbStore.md，beginTransaction）
- createTransaction(options?: TransactionOptions): Promise<Transaction>（@since 14）：创建并开始一个 Transaction 对象，用它的 execute、commit()、rollback()；不同事务对象互相隔离（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，RdbStore.createTransaction）
- beginTrans(): Promise<number>，声明抛 801 - Capability not supported；文档写明该接口仅支持向量数据库（StoreConfig 配置 vector 为 true）：普通库上调用会失败（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，RdbStore.beginTrans；arkts-apis-data-relationalStore-RdbStore.md，beginTrans<sup>12+</sup>）
- execute(sql: string, txId: number, args?: Array<ValueType>): Promise<ValueType>；commit(txId: number): Promise<void>；rollback(txId: number): Promise<void>：同族接口：带 txId 的三个，文档都写明仅支持向量数据库（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，RdbStore.execute / RdbStore.commit / RdbStore.rollback；arkts-apis-data-relationalStore-RdbStore.md，execute<sup>12+</sup>、commit<sup>12+</sup>、rollback<sup>12+</sup>）
- vector?: boolean（@since 18）：StoreConfig 里指定是否向量库，没写就是普通库（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，StoreConfig.vector）
- 普通库上 beginTrans() 真机返回 801，写入全部失败：出错时观察到的行为（出处：卡里修好并验证过）
- 经 beginTrans 的事务封装在单元测试里一调用就抛 801；改成同步 beginTransaction / commit / rollBack 后通过：验证过的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 这个库是不是向量库：目标工程里调 relationalStore.getRdbStore 的那个文件，传入的 StoreConfig 对象；有 vector: true 的是向量库，才可以用带 txId 的接口；没写或为 false 是普通库
