# 源端事务迁到 RdbStore 后体内要 await 的，改用 createTransaction 返回的事务对象

审的是：代码
触发（任一种）：
- 读到：源端 db.beginTransaction() … setTransactionSuccessful() / endTransaction() 包着多步写入；写错的样子：目标端在共享的 store 上 store.beginTransaction() 后，同一函数里 await store.insert / store.update / store.delete 再 store.commit()
适用范围：@ohos.data.relationalStore 上事务体内有 await 的多步写入；createTransaction 自 API 14 起可用（出自声明 @since 14）
做法：
- 写成 const tx = await store.createTransaction({ transactionType: relationalStore.TransactionType.IMMEDIATE })；体内各步改成 await tx.insert / tx.update / tx.delete / tx.execute，成功后 await tx.commit()，catch 里 await tx.rollback()
- 审时搜 beginTransaction，同一函数里在它之后出现 await 的都按上一步改
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- createTransaction(options?: TransactionOptions): Promise<Transaction>：RdbStore 上创建事务对象并开始事务（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，RdbStore.createTransaction）
- TransactionOptions { transactionType?: TransactionType }；TransactionType.DEFERRED = 0、IMMEDIATE = 1、EXCLUSIVE = 2：事务类型要包在 options 对象里传，不是直接传枚举（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，TransactionOptions、TransactionType）
- commit(): Promise<void>；rollback(): Promise<void>；insert(table: string, values: ValuesBucket, conflict?: ConflictResolution): Promise<number>：Transaction 对象上的提交、回滚和写入方法，另有 update、delete、execute（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，Transaction）
- 不同事务对象之间是隔离的；一个 store 最多同时存在四个事务对象，超过返回 14800015；事务对象里的写入不会被 on('dataChange') 监听到：createTransaction 和 beginTransaction 的区别及限制（出处：arkts-apis-data-relationalStore-RdbStore.md，createTransaction）
- beginTransaction(): void，不允许嵌套事务，不支持在多进程或多线程中使用：共享 store 上的同步事务，体内 await 时别的异步库操作会混进来（出处：arkts-apis-data-relationalStore-RdbStore.md，beginTransaction）
- 共享 store 上 beginTransaction 后多次 await，并发调用形成 SAVEPOINT 嵌套错位；改成 createTransaction(IMMEDIATE) 的独立事务对象后修好：改法的依据（出处：卡里修好并验证过）
未核实：卡里的行为出自 HarmonyOS 6.1.1(24)，本机核实用的是 API 23 的声明；IMMEDIATE 和 DEFERRED 在并发下的差别卡里没比较
