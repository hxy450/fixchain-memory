# 带 COALESCE 或子查询的 UPDATE 要返回行数时，先按同一 WHERE 计数再更新

审的是：代码
触发（任一种）：
- 读到：源端 Room @Query 的 UPDATE 带 COALESCE(...) 等表达式或 WHERE id IN (子查询)，写不成 ValuesBucket，方法返回 Int；写错的样子：整条 SQL 交给 executeSql，再用 SELECT changes() 或依赖它的 helper 取行数
适用范围：数据层实现阶段，SQL 不能直接写成 ValuesBucket + RdbPredicates、又要返回受影响行数的 UPDATE
做法：
- 先用同一 WHERE 查出目标 id 或 count(*)（store.querySql('SELECT count(*) … WHERE …', args) 或查 id 列表），再用 RdbPredicates（如 .in(列, ids)）调 store.update 并返回数量
- 要保留原值的（COALESCE 这类），先读出原值，再按读到的值组 ValuesBucket 写回
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- querySql(sql: string, bindArgs?: Array<ValueType>): Promise<ResultSet>：RdbStore 执行查询，用来按同一 WHERE 计数或取 id（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，RdbStore.querySql）
- in(field: string, value: Array<ValueType>): RdbPredicates：RdbPredicates 的 IN 条件，把查到的 id 列表交给 update（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，RdbPredicates.in）
- constructor(name: string)：RdbPredicates 的构造，name 是表名（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，RdbPredicates.constructor）
- 先按同一 WHERE 做 count(*) 再 UPDATE 并返回匹配行数；需要 COALESCE 语义的先读原值再 update：修好后行数正确、原值保留语义不变（出处：卡里修好并验证过）
