# 源端 Cursor.getString 读 REAL 列时，迁到 ResultSet 按 %g 复刻文本

审的是：代码
触发（任一种）：
- 读到：源码用 `cursor.getString(i)` 读回 REAL（浮点）列，再交给 String 入口解析；写错的样子：目标端 relationalStore 里同样用 `rs.getString(idx)` 读 REAL 列，得到全精度文本，和 Android 的文本不同
适用范围：把 SQLite Cursor 读取转成 relationalStore ResultSet 读取、且源端对数值列取文本时
做法：
- 读回前用 `rs.getColumnTypeSync(idx)` 判列类型：为 `relationalStore.ColumnType.REAL` 时取 `rs.getDouble(idx)`，按 C printf 的 `%g`（6 位有效数字）格式化成文本，再交给源端同样的解析
- INTEGER 列取文本时同样按源平台的规则（十进制 `%lld`）复刻，不把 getString 一对一搬过去
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- FIELD_TYPE_FLOAT 列的 getString 结果按 printf 的 %g 格式化；FIELD_TYPE_INTEGER 按 %lld：Android 端 REAL 列取文本只有 6 位有效数字（出处：android.database.CursorWindow#getString）
- getColumnTypeSync(columnIdentifier: number | string): ColumnType：取当前行某列的类型，@since 18（出自声明）（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，ResultSet.getColumnTypeSync）
- ColumnType.REAL = 2（另有 NULL = 0、INTEGER = 1、TEXT = 3）：列类型枚举（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，relationalStore.ColumnType）
- getDouble(columnIndex: number): number：按数值取 REAL 列，再自行格式化（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，ResultSet.getDouble）
- ResultSet.getString 读 REAL 列得到全精度文本，和 Android 的 %g 文本不同：不能一对一替换 cursor.getString（出处：卡里修好并验证过）
- getColumnType(columnIdentifier: number | string): Promise<ColumnType>（LiteResultSet）：同族接口：LiteResultSet 的取列类型（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，LiteResultSet.getColumnType）
未核实：卡里的行为出自 HarmonyOS 6.1.1(24)，核对声明用的是本机 API 23；%g 的指数形式切换规则卡里没写，按 C 标准实现时要另核
