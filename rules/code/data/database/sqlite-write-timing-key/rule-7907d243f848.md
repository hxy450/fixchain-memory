# 源端不等落库就发事件、目标改成异步 RDB 写时，等写完再发或补发一次事件

审的是：代码
触发（任一种）：
- 写错的样子：目标的写库函数用 `relationalStore` 的异步 `update` / `insert`，返回的 Promise 没被 await 或没被返回，就接着发状态事件，订阅页重查读到旧值
适用范围：源端 fire-and-forget 的落库映射成目标端返回 Promise 的异步写，且同一流程随后发事件让订阅方重查时
做法：
- 让写库函数返回 Promise（return store.update(...)），发事件前 await 它；或在写完后的 then 里补发一次同样的事件
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- update(values: ValuesBucket, predicates: RdbPredicates): Promise<number>：RdbStore 的异步更新，Promise 完成时才写完（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，RdbStore.update）
- insert(table: string, values: ValuesBucket): Promise<number>：同族接口：RdbStore 的异步插入（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，RdbStore.insert）
- 写库函数改为返回 Promise、落库后补发一次状态事件后，订阅页显示的进度与落库值一致：验证过的写法（出处：卡里修好并验证过）
未核实：卡里的现象出现在目标 API 22/23 上，本机核对用的是 API 23 的声明
