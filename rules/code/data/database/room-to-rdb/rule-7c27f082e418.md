# 把 Room 实体手写成 relationalStore 建表 SQL 时，表名和列名一律加双引号

审的是：代码
触发（任一种）：
- 读到：源端 Room @Entity 里 @ColumnInfo(name = …) 的列名是 to、order、group、index、default、key 这类 SQL 关键字，或 Room 导出 schema 的 createSql 里标识符带反引号；写错的样子：交给 executeSql 的 CREATE TABLE 字符串里标识符裸写，如 `to TEXT,`；注释还称列名与 Room @Entity 一致
适用范围：把安卓 Room 的表结构迁成 ArkTS relationalStore、需要手写建表、建索引 SQL 时
做法：
- 建表 SQL 里所有表名、列名统一加双引号（或反引号），如 CREATE TABLE IF NOT EXISTS "t" ("to" TEXT, …)；索引、查询、谓词里引用这些列时同样转义
- 有 Room 导出的 schema（schemas/<Database 类>/<version>.json）时，以每张表的 createSql 为底稿，把 ${TABLE_NAME} 换成实际表名，不按列清单重拼
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- executeSql(sql: string, bindArgs?: Array<ValueType>): Promise<void>：RdbStore 执行建表等 SQL；SQL 在字符串里，ArkTS 编译不会检查它（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，RdbStore.executeSql）
- 14800021 - SQLite: Generic error：executeSql 抛出的错误码之一；关键字列名裸写时建库报的就是它（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，RdbStore.executeSql 的 @throws）
- 裸写 to 时 sqlite3 报 near "to": syntax error；建库逐条 await，这一条抛错后后续表和索引都没建；改成 "to" TEXT 后正常：改前改后的现象（出处：卡里修好并验证过）
针对本应用要查的：
- 源端每张表的原始建表语句：源工程 Room 导出目录 schemas/<Database 类全名>/<version>.json，取 entities 下每项的 createSql；版本取 @Database(version = …) 的值；把 createSql 里的 ${TABLE_NAME} 换成 tableName，反引号可原样保留或换成双引号
未核实：RdbPredicates 等谓词的字段参数里引用关键字列名时要不要自己加引号，卡里只建议同样处理，没验证；卡里观察到的报错出自 HarmonyOS 6.1.1（API 24），本机声明按 API 23 核实
