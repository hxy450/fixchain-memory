# 写演示/种子数据时照 spec_ref 和源端种子类逐字段搬运，不按功能名自拟样例

审的是：代码
触发（任一种）：
- 读到：计划或 feature-index 写明演示数据依赖源端的种子类、模板类，并给出 spec_ref 指向的功能 spec；写错的样子：写演示行的代码里行程标题、日期偏移、主题 key、note、清单项和完成状态都是自拟的，和 spec、源端种子类对不上：主题 key 原值被换成 `#RRGGBB` 颜色串，清单项条数不同、全部未完成
适用范围：实现演示数据、种子数据、预置数据的具体内容时，尤其是上下文压缩或跨回合续跑之后
做法：
- 写前打开 spec_ref 指向的功能 spec 和源工程的种子类、模板类、主题类
- 逐字段搬运：标题、目的地、日期偏移、主题 key 原值、note、清单项标题/分类/优先级、完成集合与完成时间偏移
- 写完拿源端关键值对照一次：每条记录的标题、项数、完成数、主题 key
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 回读源端种子类、模板类、主题类后重写：每条演示记录按源端模板生成清单项、按源端偏移分布完成时间，重置时先清空再调用同一个种子函数：卡里最终保留的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 演示数据的每个字段原值：spec_ref 指向的功能 spec 里的演示数据节，以及源工程里构造演示数据的种子类、清单模板类、主题常量类；按源码里的字面量和常量引用逐个读出（主题 key 顺着常量读到原值，如某个 DEFAULT 常量对应的字符串）
