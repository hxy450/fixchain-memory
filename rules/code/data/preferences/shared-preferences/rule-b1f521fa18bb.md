# 迁移设置页的保存逻辑时，源端保存的每个副作用都要在目标落地，只写远端设置不算完成

审的是：代码
触发（任一种）：
- 读到：源设置页的保存处理除远端保存外，还调用本地配置更新方法，并发同步或刷新事件（如 EventBus.post、sendBroadcast）；写错的样子：目标的保存函数里只有写远端设置 JSON 的调用，没有本地配置写入，也没有 emitter.emit 之类通知读取它的列表刷新的调用
适用范围：迁移带有用户偏好（如排序方式）的设置页保存和加载逻辑时
做法：
- 逐项列出源端保存处理的副作用（远端同步、本地配置缓存、刷新事件），每一项在目标端写出对应调用并指明谁消费它
- 保存和加载时同步写读一份列表可读的本地配置，列表的查询按它排序
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 保存和加载时同步本地排序配置，仓库、查询服务和列表展示统一读它排序后，设置生效：返修后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端保存处理的全部副作用：源工程设置页 Activity 或 Fragment 里保存按钮的点击处理方法（onClick 或 onOptionsItemSelected 里调到的那个方法）；逐句列出它调用的远端保存、本地 Helper 更新、EventBus 或广播，每一句在目标端找到或写出对应调用
