# 迁移 Application.onCreate 里的首次启动初始化时，在目标启动路径落实际调用并保留门控

审的是：代码
触发（任一种）：
- 读到：源端 Application.onCreate 调用一个首次启动初始化方法，方法里按 SharedPreferences 标记（或空库判断）门控，只在未执行过时写入数据；写错的样子：目标的数据管理器构造只加载已有数据，初始化函数只由设置页的重置入口调用；EntryAbility.onCreate 和数据管理器初始化里都没调用它
适用范围：源端在 Application.onCreate 里做首次启动初始化（写入演示数据、默认配置等）时
做法：
- 在目标启动路径（EntryAbility.onCreate 或数据管理器初始化）落一个实际调用点，保留源端门控：偏好标记未置或库为空时才执行；例：加载已有数据后为空就调用初始化
- 设置里的手动重置改为先清空再复用同一个初始化函数
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Application#onCreate 在任何 Activity、Service、Receiver 创建前调用：源端初始化的时机是应用启动，不是某个页面（出处：android.app.Application#onCreate）
- onCreate(want: Want, launchParam: AbilityConstant.LaunchParam): void：目标启动路径上的调用点之一（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.UIAbility.d.ts，UIAbility.onCreate）
- getPreferencesSync(context: Context, options: Options): Preferences；getSync(key: string, defValue: ValueType): ValueType；putSync(key: string, value: ValueType): void：用偏好标记门控时的读写（出处：鸿蒙 SDK 的 ets/api/@ohos.data.preferences.d.ts，preferences.getPreferencesSync、Preferences.getSync、Preferences.putSync）
- flush(): Promise<void>；flushSync(): void：putSync 后要 flush 才落盘，否则下次启动标记丢失（出处：鸿蒙 SDK 的 ets/api/@ohos.data.preferences.d.ts，Preferences.flush）
- 加载已有数据后为空即调用初始化，重置改为清空后复用同一函数：修复后的启动接线（出处：卡里修好并验证过）
针对本应用要查的：
- 源端首次启动初始化的门控条件：源工程 Application 子类的 onCreate 调用的初始化方法，以及它读的 SharedPreferences 键或数据库空表判断；按同样的条件在目标端门控：偏好键用 Preferences.getSync 读、执行后 putSync 并 flush；空库判断用加载后的数据是否为空
