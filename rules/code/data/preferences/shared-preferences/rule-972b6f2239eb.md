# 偏好值的序列化格式以源函数和同工程其他读写方为准，读写两端用同一格式

审的是：代码
触发（任一种）：
- 读到：源端读写某个偏好（如分辨率）的函数用 SharedPreferences 存成特定分隔的字符串，同工程别的页面也读写同一个键；写错的样子：目标端 getter 按另一种分隔拆分、setter 写 `${width}x${height}`，和源格式或同工程其他读写方不一致；契约要求的参数被去掉
适用范围：实现阶段移植偏好的读写函数，尤其是同一个键由多个切片分别读写时
做法：
- 实现读写前先读源端对应的 get/set 函数，照它的分隔符和字段顺序写入，保留契约里的参数
- 读取时兼容同工程已写出的其他格式，写入只用源格式；拿设置页或弹出菜单写入的值调用读取函数，应解析回同一个值
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 读取同时兼容两种分隔、写入用源格式后，设置页选的分辨率能解析回来：修好的做法（出处：卡里修好并验证过）
针对本应用要查的：
- 这个偏好值的序列化格式：源工程里写这个偏好键的 putString 调用和读它之后的 split / 解析处；目标工程里其他读写同一个键的文件；照抄分隔符和字段顺序；源函数里有特殊模式的分支（如某模式下不回写偏好）的，一并照写
