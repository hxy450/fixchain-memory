# 模型带 bigint 字段时，每条 JSON 持久化往返都配成对的 replacer / reviver

审的是：代码
触发（任一种）：
- 读到：源端被存进偏好或数据库的 bean 有 Long 字段；写错的样子：存取用户等对象时用裸 JSON.stringify(obj) 存、JSON.parse(json) 取，DAO 或 preferences 里存的 JSON 也没处理 bigint
适用范围：数据模型里有 bigint 字段、又要以 JSON 存进偏好、数据库或文件时
做法：
- 每条持久化路径写配对的 stringify（replacer 把 bigint 转字符串）和 parse（reviver 把这些字段转回 BigInt）
- 存完读回来比较 id 是否和存之前一致
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 给用户存取加配对的 stringify / parse 函数：修复时网络层改好后，存下的 id 仍被舍入，补上这对函数才一致（出处：卡里修好并验证过）
