# 源端视图切换写进持久化键时，目标切换先写偏好，启动时等偏好加载完再恢复

审的是：代码
触发（任一种）：
- 读到：安卓切换视图时把视图位置写进 MMKV 的键，只接受几个固定取值，启动时读回恢复；写错的样子：目标 ViewModel 的视图切换方法只改内存里的模式状态，没写偏好；页面在 `await` 偏好加载完成之前就读取默认值，重启总回到默认视图
适用范围：迁移带持久化的视图切换（首页视图、标签位置等）时
做法：
- 切换时先把视图位置写进偏好（与源端同一个键、同一套取值），再更新内存模式
- 启动时 await 偏好加载完成后再恢复视图；读到的值按源端允许的取值归一化，非法值回退默认并写回
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 服务层加视图位置读写与取值归一化；切换先持久化再更新模式，加载偏好时恢复；页面 await 偏好加载后恢复视图状态：修复后重启能回到上次的视图（出处：卡里修好并验证过）
- put(key: string, value: ValueType): Promise<void>：Preferences 写键值；要调 flush 才落到文件（出处：鸿蒙 SDK 的 ets/api/@ohos.data.preferences.d.ts，Preferences.put）
- flush(): Promise<void>：把 Preferences 异步保存到文件（出处：鸿蒙 SDK 的 ets/api/@ohos.data.preferences.d.ts，Preferences.flush）
- get(key: string, defValue: ValueType): Promise<ValueType>：异步读键值，结果出来前页面拿到的只是默认值（出处：鸿蒙 SDK 的 ets/api/@ohos.data.preferences.d.ts，Preferences.get）
针对本应用要查的：
- 源端持久化的键名和允许的取值：源工程里切换视图的那个方法（写 MMKV 的调用）和启动时读这个键的地方；读出键名、合法取值集合和非法值的回退值，目标照同一套写和读
