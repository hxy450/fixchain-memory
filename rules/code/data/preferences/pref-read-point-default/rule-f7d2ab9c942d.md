# 接线组装保存请求时打开源方法逐字段对照：偏好类型、格式映射、有效性门控

审的是：代码
触发（任一种）：
- 读到：源端在一个方法里用 sharedPreferences.getString(...) 读多项偏好（含 no / photo 这类字符串值域、图片格式、按模式区分的存底偏好），并按传感器数据是否有效的标志决定写不写方位、俯仰角；写错的样子：目标把字符串偏好读成 getBoolean(..., true)，请求的格式字段不赋值走默认，模式相关的存底偏好不映射；方位、俯仰写死 0 并注释「公开面未导出」，不查有效性标志；注释引用的源码区间不是这段逻辑
适用范围：接线阶段在拍照回调里从偏好和传感器状态组装保存请求时
做法：
- 打开源端组装请求的方法逐字段对照：每个偏好按源端的读取类型和值域比较（字符串值域就比字符串），格式偏好映射到请求的格式字段，模式相关的存底偏好映射到对应字段
- 传感器值只在对应有效性标志为真时写入（三项都有效才写姿态）；注释「未导出」或写死 0 前，先在目标工程 grep 对应的 getter
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 镜像偏好按字符串值比较，格式映射到 PNG / WEBP / 标准，NR 和全景各自映射存底，方位和俯仰取自已有接口，姿态需三者都有效，自动水平需稳定标志：修好后的组装方式（出处：卡里修好并验证过）
针对本应用要查的：
- 每个偏好的读取类型和值域：源工程组装保存请求的方法里的 getString / getBoolean 调用，以及偏好定义处（设置页的 ListPreference entryValues 或键常量旁的注释）；读出类型和取值集合，目标端按同样的类型比较
未核实：镜像的字符串值域只写在目标偏好键旁的注释里，接线者是否看到卡里没核实
