# 同一偏好键在不同读点缺省值不同时，各读点保留自己的显式缺省值，不收敛成单一默认

审的是：代码
触发（任一种）：
- 读到：源码同一偏好键在不同读点用不同缺省值（如一处 getBoolean(key, false)、另一处 getBoolean(key, true)），或键表写「读点不一致 / 该读点特判」；写错的样子：键常量注释只留一个默认值，封装只提供以该默认值读取的单一访问器（如只有 getSync(<键>, false)）
适用范围：迁移偏好键常量、访问器和各页面读点时
做法：
- 每个特判读点保留调用方显式缺省值，如 prefs.getSync(<键>, true)，或提供按读点命名的访问器
- 键常量注释里列出这个键的所有读点及各自缺省值
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getSync(key: string, defValue: ValueType): ValueType：缺省值由每次调用传入，键不存在时返回调用方给的 defValue（出处：鸿蒙 SDK 的 ets/api/@ohos.data.preferences.d.ts，Preferences.getSync）
针对本应用要查的：
- 这个键在源端的全部读点和各自缺省值：源工程里 grep 该键常量或键名字符串，看每处 getBoolean / getString / getInt 的第二个参数；逐处记下读点所在的方法和缺省值，缺省值不同的读点分别保留
