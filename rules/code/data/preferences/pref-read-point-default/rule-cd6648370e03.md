# 源端在点击时实时读首选项的判定，目标端也在回调里现读，不在 aboutToAppear 缓存

审的是：代码
触发（任一种）：
- 读到：点击监听里实时调用首选项的 `getString(key, null)`，按是否为 null 判定先走哪条分支；写错的样子：`aboutToAppear` 里读一次存进 `@Local` 字段，点击回调直接用这个字段判定
适用范围：源端在事件回调里实时读取持久化状态做判定，迁到 ArkUI 页面时
做法：
- 在点击回调里现读：preferences 实例 getSync(key, defValue)（或工程里封装的同一读取方法），按读到的值判定分支，不复用页面出现时的缓存
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getSync(key: string, defValue: ValueType): ValueType：同步读取首选项，可在回调里直接调用（出处：鸿蒙 SDK 的 ets/api/@ohos.data.preferences.d.ts，preferences.Preferences.getSync）
- get(key: string, defValue: ValueType): Promise<ValueType>：同族接口：异步读取（出处：鸿蒙 SDK 的 ets/api/@ohos.data.preferences.d.ts，preferences.Preferences.get）
- 每次点击实时读首选项再判定：返修后保留的写法（出处：卡里修好并验证过）
