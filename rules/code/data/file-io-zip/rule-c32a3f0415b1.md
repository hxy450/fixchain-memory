# 源端 createOrExistsDir / mkdirs 建目录，目标保留「已存在即成功」，不裸调 mkdirSync

审的是：代码
触发（任一种）：
- 读到：源码用 FileUtils.createOrExistsDir(dir)、File.mkdirs() 或 getExternalFilesDir("…") 保证目录存在，并在同一固定目录里重复下载、复制；写错的样子：目标裸调 fileIo.mkdirSync(dir, true)，和后续 moveFileSync / copyFileSync 放在同一个 try 里，第二次执行抛 13900015 被当成下载或设置失败
适用范围：把 Android 的建目录步骤翻译成 @kit.CoreFileKit 的 fileIo 调用、且目录会被重复使用时
做法：
- 建目录写成 if (!fileIo.accessSync(dir)) { fileIo.mkdirSync(dir, true) }，或把 mkdirSync 单独包 try，只在 err.code === 13900015 时继续
- 写完按第二次执行走查：目录和同名文件都已存在时每一步是否仍成功
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- mkdirSync(path: string, recursion: boolean): void；@throws 13900015 - File exists：recursion 传 true 也不是幂等调用，目录已存在照样抛错（出处：鸿蒙 SDK 的 ets/api/@ohos.file.fs.d.ts，mkdirSync）
- mkdirSync 对已存在目录即便传 true 也抛 13900015：真机上观察到的行为（出处：卡里修好并验证过）
- accessSync(path: string, mode?: AccessModeType): boolean，不传 mode 时检查是否存在：建目录前先判存在（出处：鸿蒙 SDK 的 ets/api/@ohos.file.fs.d.ts，accessSync）
- File.mkdirs() 目录已存在时返回 false，不抛异常：源端「已存在」不算失败（出处：java.io.File#mkdirs）
- mkdir(path: string, recursion: boolean): Promise<void>：同族接口：异步建目录，同样列了 13900015（出处：鸿蒙 SDK 的 ets/api/@ohos.file.fs.d.ts，mkdir）
未核实：卡里的行为在 target SDK 6.1.1(24) 下观察，本机核实用的声明是 API 23
