# 源端只在 OutOfMemoryError 时报文件过大：目标照常读、catch RangeError 再提示

审的是：代码
触发（任一种）：
- 读到：catch (OutOfMemoryError e) 里提示文件过大，读之前没有大小判断；写错的样子：读前用 fs.stat(...) / fs.statSync(...) 比较 size，超出自定上限（如 16 MiB）就拒读，替换了 try/catch
适用范围：源端靠内存耗尽异常兜底「文件过大」的读文件实现
做法：
- 照常读取文件；在 catch 里判断 e instanceof RangeError 时给源端同一条文件过大提示，其他错误走原来的失败处理；去掉读前大小上限
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 不设读前大小上限，只在 RangeError 时报文件过大：和源端「先读、内存耗尽才报错」一致的实现（出处：卡里修好并验证过）
