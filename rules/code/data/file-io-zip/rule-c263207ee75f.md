# FileOutputStream 覆盖写迁成 fileIo 时，加 TRUNC 并按 writeSync 返回值写完

审的是：代码
触发（任一种）：
- 读到：源端 new FileOutputStream(file) 或 openOutputStream(uri) 加 OutputStream.write(data) 整文件写入；写错的样子：fileIo.openSync(path, OpenMode.WRITE_ONLY | OpenMode.CREATE) 没有 TRUNC，只调一次 writeSync 且不检查返回的字节数
适用范围：把源端整文件覆盖写入迁成 @ohos.file.fs 时
做法：
- 打开模式写 fileIo.OpenMode.WRITE_ONLY | fileIo.OpenMode.CREATE | fileIo.OpenMode.TRUNC
- 按 writeSync 的返回值循环写剩余部分直到写完，某次返回 0 时报错
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- const TRUNC = 0o1000（File truncate len 0）：打开时把文件截成 0 长度（出处：鸿蒙 SDK 的 ets/api/@ohos.file.fs.d.ts，OpenMode.TRUNC）
- writeSync(fd: number, buffer: ArrayBuffer | string, options?: WriteOptions): number，返回实际写入的字节数：写入可能不足量，要看返回值（出处：鸿蒙 SDK 的 ets/api/@ohos.file.fs.d.ts，fileIo.writeSync）
- FileOutputStream(File file) 等于 this(file, false)：源端不追加，从文件开头覆盖写（出处：java.io.FileOutputStream#FileOutputStream）
- 新增循环写、TRUNC 和精确切片后保留到最终：返修后的写法（出处：卡里修好并验证过）
- write(fd: number, buffer: ArrayBuffer | string, options?: WriteOptions): Promise<number>：同族接口：异步写，同样返回写入字节数（出处：鸿蒙 SDK 的 ets/api/@ohos.file.fs.d.ts，fileIo.write）
- writeSync(buffer: ArrayBuffer | string, options?: WriteOptions): number：同族接口：Stream 和 RandomAccessFile 上的同步写（出处：鸿蒙 SDK 的 ets/api/@ohos.file.fs.d.ts，Stream.writeSync）
