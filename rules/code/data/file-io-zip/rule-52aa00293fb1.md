# ZipOutputStream 没调 setMethod 时，手写 ZIP 按 DEFLATED 加数据描述符

审的是：代码
触发（任一种）：
- 读到：new ZipOutputStream(...) 后 putNextEntry 写条目，没有调用 setMethod 或 ZipEntry.setMethod；写错的样子：因 zlib.zipFile / compressFile 控制不了条目名和时间而手写 ZIP 容器，条目写成 STORED（method 0，不压缩）
适用范围：源端用 ZipOutputStream 默认方式导出 ZIP、目标手写 ZIP 容器时
做法：
- 每个条目用 zlib 压成原始 deflate 流：const z = zlib.createZipSync(); await z.deflateInit2(strm, level, zlib.CompressMethod.DEFLATED, -15, memLevel, strategy)（负的 windowBits 表示不带 zlib 头）
- 本地头 method 写 8，通用标志写 0x0808（数据描述符 + UTF-8 文件名），条目数据后写数据描述符（CRC-32、压缩后大小、原大小）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- private int method = DEFLATED;：ZipOutputStream 的默认压缩方式（出处：java.util.zip.ZipOutputStream#method）
- DEFLATED 条目没有预先给出大小和 CRC 时 e.flag = 8（数据描述符），文件名 UTF-8 时 e.flag |= USE_UTF8：源端条目的通用标志，合起来是 0x0808（出处：java.util.zip.ZipOutputStream#putNextEntry）
- deflateInit2(strm: ZStream, level: CompressLevel, method: CompressMethod, windowBits: number, memLevel: MemLevel, strategy: CompressStrategy): Promise<ReturnStatus>：Zip 对象的压缩初始化；windowBits 和 inflateInit2 同义，取 -8..-15 是原始 deflate（出处：鸿蒙 SDK 的 ets/api/@ohos.zlib.d.ts，Zip.deflateInit2；Zip.inflateInit2）
- CompressMethod.DEFLATED = 8：唯一支持的压缩方式，也是本地头里 method 字段的值（出处：鸿蒙 SDK 的 ets/api/@ohos.zlib.d.ts，CompressMethod.DEFLATED）
- crc32(crc: number, buf: ArrayBuffer): Promise<number>：Checksum 对象算数据描述符里的 CRC-32（zlib.createChecksumSync() 取得）（出处：鸿蒙 SDK 的 ets/api/@ohos.zlib.d.ts，Checksum.crc32）
- 原始 deflate 流 + 数据描述符（标志 0x0808）：修好后导出的 ZIP 和源端一样是压缩条目（出处：卡里修好并验证过）
未核实：windowBits 取 -15 由声明推出（deflateInit2 的 windowBits 与 inflateInit2 同义，-8..-15 为原始 deflate），卡里只写了「原始 deflate 流」
