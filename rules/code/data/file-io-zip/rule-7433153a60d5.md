# picker 返回的 URI 先 fileIo.openSync 取 fd，再交给 copyFileSync

审的是：代码
触发（任一种）：
- 写错的样子：fileIo.copyFileSync(源路径, uri)：DocumentViewPicker 或媒体库返回的 URI 被直接当成目标路径传给 copyFileSync
适用范围：把沙箱文件写到 DocumentViewPicker 或媒体库返回的 URI 时
做法：
- const file = fileIo.openSync(uri, fileIo.OpenMode.WRITE_ONLY)；fileIo.copyFileSync(源沙箱路径, file.fd)；fileIo.closeSync(file)
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- copyFileSync(src: string | number, dest: string | number, mode?: number): void：dest 是目标路径或已创建文件的 FD；URI 不是路径（出处：鸿蒙 SDK 的 ets/api/@ohos.file.fs.d.ts，copyFileSync）
- openSync(path: string, mode?: number): File：path 可以是沙箱路径或文件 URI；mode 默认 OpenMode.READ_ONLY，写入要传 WRITE_ONLY 或 READ_WRITE（出处：鸿蒙 SDK 的 ets/api/@ohos.file.fs.d.ts，openSync）
- copyFile(src: string | number, dest: string | number, mode?: number): Promise<void>：同族接口：异步版本，dest 同样接受 FD（出处：鸿蒙 SDK 的 ets/api/@ohos.file.fs.d.ts，copyFile）
- 对 picker 返回的 uri openSync 取 fd 后复制：修好的写法（出处：卡里修好并验证过）
未核实：卡里只写了 openSync(uri) 取 fd，没写打开模式
