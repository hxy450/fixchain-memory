# 规格写了后台或并发拷贝时，拷贝用 fileIo 的异步 API，不用 *Sync 再包 async

审的是：代码
触发（任一种）：
- 读到：源端在 AsyncTask.executeOnExecutor(THREAD_POOL_EXECUTOR) 的 doInBackground 里拷贝文件；规格或 addendum 写「taskpool.execute 并发 + 主线程收束」「逐个并发创建任务（多 uri 并行拷贝）」；写错的样子：拷贝链写成 fileIo.copyFileSync、fileIo.openSync + readSync 同步 IO，外面只包一层 async 函数
适用范围：目标端服务层的文件拷贝、导入链，规格要求后台或并发执行时
做法：
- 拷贝改成异步 API：await fileIo.open(...) 拿到源和目标的 fd，再 await fileIo.copyFile(srcFd, dstFd)；async 函数里调同步 API 不等于后台执行
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- copyFile(src: string | number, dest: string | number, mode?: number): Promise<void>：异步拷贝，src、dest 可以是路径或 fd（出处：鸿蒙 SDK 的 ets/api/@ohos.file.fs.d.ts，fileIo.copyFile）
- open(path: string, mode?: number): Promise<File>：异步打开文件，拿到 File.fd（出处：鸿蒙 SDK 的 ets/api/@ohos.file.fs.d.ts，fileIo.open）
- copyFileSync(src: string | number, dest: string | number, mode?: number): void：同步版本，在调用线程上阻塞，不要用在主线程的导入链里（出处：鸿蒙 SDK 的 ets/api/@ohos.file.fs.d.ts，fileIo.copyFileSync）
- 新增 fileIo.open + copyFile(fd, fd) 的异步拷贝链后，多文件导入不再阻塞主线程：修好后的写法（出处：卡里修好并验证过）
