# 按审查意见修一个范围缺陷时只改意见点名的条件，不顺带改共享状态的 userId 写入键

审的是：代码
触发（任一种）：
- 读到：审查意见只要求给某个撤销或删除条件加限定（如重复事件撤销时加日期条件）；现有实现的写入键是 `共享模式 ? '' : 当前用户 id`，与源端「只有按成员模式才写 userId」一致；写错的样子：diff 把共享模式的 userId 也改成当前用户 id，撤销和子项删除加上 userId = 当前用户，或把只对重复事件生效的日期条件改成无条件
适用范围：数据层按审查意见修完成态、子任务状态的撤销或删除范围，而状态分共享（不绑定成员）和按成员两种时
做法：
- 只改意见指明的那个条件（例如只给重复事件的撤销加日期限定），写入键和其他删除条件保持原样
- 改动若会碰到写入键或删除范围，先对照源端状态的创建和删除实现逐项对齐：哪种模式写 userId、共享模式按什么键清旧状态、日期条件是否只对重复事件生效；确需改变共享和私有语义时，在交接里写明源码依据
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 写入键恢复成「共享模式 ? '' : 当前用户 id」、同步载荷的 userId 用同一个本地值、删除条件只在重复事件时才加日期后，子任务单条点击状态恢复正常：把共享状态改成当前用户私有后，其他成员看不到完成态，单条点击状态也不变（出处：卡里修好并验证过）
针对本应用要查的：
- 源端哪种完成模式写成员 id、删除旧状态用哪些键：源工程里创建和清除完成态、子任务状态的方法（创建状态、清除共享模式旧状态、解析状态这一类）；逐个模式记下写不写 userId、清旧状态的条件、日期条件加在哪类事件上，目标实现照这几项对齐
