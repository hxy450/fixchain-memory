# 共享和按成员两种完成状态的 userId 写入

agent 会看到什么：读到源端完成状态分共享（任一成员完成即完成、不写 userId）和按成员两种、重复事件另按日期区分；产物里的写入键 userId、撤销和子项删除的 where 条件，以及对应的测试用例

## 规矩

- rule-1f2d17047dc4｜按审查意见修一个范围缺陷时只改意见点名的条件，不顺带改共享状态的 userId 写入键｜读到：审查意见只要求给某个撤销或删除条件加限定（如重复事件撤销时加日期条件）；现有实现的写入键是 `共享模式 ? '' : 当前用户 id`，与源端「只有按成员模式才写 userId」一致；写错：diff 把共享模式的 userId 也改成当前用户 id，撤销和子项删除加上 userId = 当前用户，或把只对重复事件生效的日期条件改成无条件
- rule-dba9c19da11e｜状态分共享和按成员、重复和非重复时，各补一条用例核对 userId、他人可见和删除行｜读到：源端状态按完成模式区分共享（任一成员完成即完成、不写 userId）和按成员两种，重复事件另按日期区分；写错：测试里没有共享模式的用例，或没有断言写入后的 userId 为 `''`、另一成员查询时的显示、撤销后删除了哪些行
