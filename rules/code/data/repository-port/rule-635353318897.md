# 把源端服务流程内联移植到目标方法时，逐阶段落齐源函数的全部副作用调用

审的是：代码
触发（任一种）：
- 读到：源端 Service 的扫描方法分阶段执行：开头读缓存做预过滤，收尾在保存结果、置偏好标记之前还调用 Repository 的缓存更新方法；写错的样子：目标方法只移植了结果持久化和偏好标记，Repository 的缓存更新调用和开头的缓存预过滤都没有；文件头的「对齐源端各阶段」流程说明也漏列这两步
- 读到：规格 AC 写「…记入某缓存并汇总展示」，feature-base 的数据表写该缓存「扫描时记录」；写错的样子：目标只实现了缓存的读取和展示页，数据层流程里没有调用 Repository 写入这个缓存
适用范围：把源端后台服务（Service、Worker）的多阶段流程内联到目标的一个方法里时
做法：
- 动笔前逐阶段列出源函数的全部副作用调用（缓存读取预过滤、缓存更新、偏好标记、结果持久化），在目标方法里按源端顺序逐项落位；落不了的登记为显式缺口
- AC 写「记入某缓存」时，确认写入发生在流程的哪一步（如扫描收尾、结果持久化之前），不只实现读取和展示
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 在结果持久化之前补上缓存更新调用后，验证用例的缓存行数与预期一致：修复位置在收尾阶段、持久化之前（出处：卡里修好并验证过）
针对本应用要查的：
- 源函数各阶段的副作用调用及顺序：源工程里被内联的那个 Service 方法，按阶段注释或分段逐行找对 Repository、DAO、SharedPreferences 的调用；列成「阶段 → 调用 → 参数来源」清单，逐项对到目标方法里的调用
未核实：修复没补开头的缓存预过滤，这一步缺失的影响卡里没核
