# 源端实体按月份和分类关联时，目标模型和仓储方法也带月份键并按选中月份读写

审的是：代码
触发（任一种）：
- 读到：源端实体的构造参数里有月份时间戳和分类键，ViewModel 经 Dao 按（月份时间戳, 分类键）两个参数查询，已有当月记录时按该记录更新；写错的样子：目标模型只加一个数值字段（注释写「每月」却没有月份字段），仓储和服务的方法写成 `set…(id, value)` 不带月份参数，页面读写不按当前选中月份过滤
适用范围：迁移带「本月」等时间段语义的数据的保存、读取和展示逻辑时
做法：
- 把源端实体的构造参数和 Dao 查询条件逐项映射成目标模型字段和仓储方法参数：模型加月份键字段（如 monthTimestamp: number），写入方法写成 set(id, value, monthTimestamp)，读取方法按（id, monthTimestamp）取
- 页面打开弹窗、保存、展示三处都按当前选中的月份取同一组关联键（月份 + 分类），不只核对弹窗外观和校验文案
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 模型加月份时间戳字段、写入方法加月份参数后，按当月记录读写并计算展示值：卡里的修法（出处：卡里修好并验证过）
针对本应用要查的：
- 源端数据按哪些键关联：源工程里新建这个实体的那段代码（构造参数）和 Dao 的查询方法（参数和 WHERE 条件）；构造参数和查询条件里出现的每个键（时间戳、分类值等）都要在目标模型里有对应字段、在仓储方法里有对应参数
