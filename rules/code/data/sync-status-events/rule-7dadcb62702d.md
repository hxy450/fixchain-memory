# 安卓开始进度事件带首次同步门控时，目标只在首次同步才发进度 0

审的是：代码
触发（任一种）：
- 读到：安卓端发同步开始进度（进度 `0`）的事件前有门控：已登录且同步 cursor 为 0 时才发；写错的样子：同步入口每次一开头就无条件发进度 `0` 的事件，首页收到就显示同步进度提示，刷新状态时还按通用的「同步中」快照补显示
适用范围：迁移同步链路里的开始进度通知，源端对它有前置条件时
做法：
- 照源端条件写判断：只在首次同步（同步 cursor 缺失或为 0）时发进度 `0` 的开始事件
- 首页只按开始事件显示进度提示，删掉刷新状态时按通用「同步中」快照补显示的逻辑
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 改成首次同步（cursor 缺失或为 0）时才发进度 0，并删掉首页的快照补显示后，非首次同步不再出现进度提示：改后的效果（出处：卡里修好并验证过）
针对本应用要查的：
- 源端开始进度事件的前置条件：源工程里发同步开始进度事件的方法（搜发布进度 0 的那一处调用），看它外面的 if 条件；把条件照写成目标端的判断。例：已登录且同步 cursor 为 0 时才发
