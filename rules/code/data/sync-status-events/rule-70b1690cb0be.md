# 重写源端同步序列时，保存之后的当前项校验和持久化在增量、全量两条路径上都要补

审的是：代码
触发（任一种）：
- 写错的样子：目标仓库重写的增量同步和全量刷新只做保存、级联删除和对账，之后没有校验并写回当前选中项；Interceptor 读到的当前项字段为空或指向已删除的项
适用范围：源端同步序列在保存之后调用默认项处理（当前项为空或失效时选第一个有效项并保存），迁成目标仓库的同步方法时
做法：
- 保留源端保存之后的副作用步骤：在增量同步和全量刷新之后都调用一次「当前项缺失或失效时按源端规则选默认项并持久化」
- 删除或对账时当前选中项被删掉的，同一步里修复当前选中项
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 增量同步和全量刷新之后都调用修复当前选中项的方法：修复后请求头的当前项字段有值（出处：卡里修好并验证过）
针对本应用要查的：
- 源端同步序列里保存之后的步骤和默认项规则：源工程同步方法的完整函数体，以及它在保存、排序之后调用的默认项处理函数的函数体（.kt 文件）；读出什么情况下判为失效、选哪一项作默认（例：跳过「全部」这类虚拟项）、写到哪个全局状态，照写到目标
