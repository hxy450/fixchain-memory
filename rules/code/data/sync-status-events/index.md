# 同步和后台操作的进度、状态事件

agent 会看到什么：读到源端同步序列发进度事件（开始 0、结束 100、失败）的门控和时机、保存之后的收尾步骤；产物里进度事件发的时机或次数不对、catch 写进了别的操作的状态字段、保存后少了当前项的校验和写回

## 规矩

- rule-7dadcb62702d｜安卓开始进度事件带首次同步门控时，目标只在首次同步才发进度 0｜读到：安卓端发同步开始进度（进度 `0`）的事件前有门控：已登录且同步 cursor 为 0 时才发；写错：同步入口每次一开头就无条件发进度 `0` 的事件，首页收到就显示同步进度提示，刷新状态时还按通用的「同步中」快照补显示
- rule-be589d73ab14｜同步改成合并请求或补跑多轮时，批次终态事件移到整批最后一轮后只发一次｜写错：单轮同步函数在结束时发进度 `100`、异常时发失败事件，外层新增的循环（合并请求、补跑尾随请求、重试）逐轮调用它，一批同步里每轮都发一次终态
- rule-70b1690cb0be｜重写源端同步序列时，保存之后的当前项校验和持久化在增量、全量两条路径上都要补｜写错：目标仓库重写的增量同步和全量刷新只做保存、级联删除和对账，之后没有校验并写回当前选中项；Interceptor 读到的当前项字段为空或指向已删除的项
- rule-9544d04b6f00｜某操作的 catch 写了别的操作的状态时，改成写本操作自己的失败态｜写错：`catch` 块里把一个操作的失败写进另一个操作的状态字段（备份失败也写成恢复状态的 Error）
