# 同步改成合并请求或补跑多轮时，批次终态事件移到整批最后一轮后只发一次

审的是：代码
触发（任一种）：
- 写错的样子：单轮同步函数在结束时发进度 `100`、异常时发失败事件，外层新增的循环（合并请求、补跑尾随请求、重试）逐轮调用它，一批同步里每轮都发一次终态
适用范围：修改同步调度（合并请求、尾随补跑、重试），且订阅方按终态事件刷新界面时
做法：
- 先列出单轮函数里已经发布的事件；把进度 `100`、失败这类批次终态从单轮里移出，放到整批最后一轮结束处只发一次，失败只在批次停止后发
- 对照订阅方收到终态后做什么（如立即查待同步、出错队列并显示错误提示），确认中间轮次不会被它当成最终结果
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 终态移到整批最后一轮后只发一次，首页不再在尾随轮执行前闪现错误提示：改后的效果（出处：卡里修好并验证过）
针对本应用要查的：
- 单轮函数里发了哪些事件、订阅方怎么处理：目标工程同步服务里被循环调用的那个单轮函数（看它的结束处、异常分支和 finally），以及首页等订阅方的事件回调；逐个列出事件和订阅方收到后的动作；凡是订阅方当成「整批结束」处理的，都只能在批次末尾发
