# 源端恢复在循环里逐条解析插入时，目标逐条插入、遇错即停、已插入保留

审的是：代码
触发（任一种）：
- 读到：源码恢复流程在 for 循环里逐条 getJSONObject → 解析 → insert → getJSONArray(子项) → insertAll；写错的样子：目标先全量解析校验再写库；子项为 null 或缺键时读成空数组 `[]` 继续
适用范围：备份恢复、批量导入从源端迁到 ArkTS 数据层时
做法：
- 照源循环逐条解析并插入；某条解析抛错（如子项数组缺键或为 null）就停止，已插入的条目保留，不回滚
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 改为逐条插入、遇错即停且保留已插入条目后与源端一致：修复后的写法（出处：卡里修好并验证过）
- getJSONArray 缺键或非数组抛 JSONException：源端子项缺失时这条抛错、循环中止（出处：org.json.JSONObject#getJSONArray）
