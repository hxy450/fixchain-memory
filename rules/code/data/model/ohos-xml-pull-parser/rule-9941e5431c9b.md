# @ohos.xml 开始标签与属性分两路回调时，START_TAG 先挂起，到下一 token 连同属性分发

审的是：代码
触发（任一种）：
- 读到：源端 SAX 的 ContentHandler.startElement(uri, localName, qName, Attributes) 或 XmlPullParser 在 START_TAG 时读本元素属性；规格要求开始事件带齐 attrs；写错的样子：tokenValueCallbackFunction 收到 START_TAG 就把 attributeWithTagCallbackFunction 已累积的属性快照、清空并分发，注释写「属性先/后于 token 两种顺序行为一致」
- 读到：派工写某个已有 XML 解析器的实现模式可参考，先例头注释写属性回调先于或后于 START_TAG 两种顺序行为一致；写错的样子：新写的 XML 读取器照搬先例在 START_TAG 时快照并清空属性的循环
适用范围：目标用 @ohos.xml 的 token 回调加 attributeWithTagCallbackFunction（声明 @since 20）重建开始事件时
做法：
- tokenValueCallbackFunction 收到 EventType.START_TAG 时只记下挂起的开始标签（名字、前缀、深度），不分发；attributeWithTagCallbackFunction 把属性累积到挂起项上
- 下一个 token（任何 eventType）或 END_DOCUMENT 到来时先 flush：把挂起的开始标签连同已累积属性一起分发，再清空
- 照先例写其他 XML 读取器前，先确认先例已实测或已改成顺序无关；先例里标为不确定或「防御式设计」的平台假设当作待核项
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- tokenValueCallbackFunction?: (eventType: EventType, value: ParseInfo) => boolean：ParseOptions 的 token 回调，开始标签在这里以 START_TAG 到达（出处：鸿蒙 SDK 的 ets/api/@ohos.xml.d.ts，ParseOptions.tokenValueCallbackFunction）
- attributeWithTagCallbackFunction?: AttributeWithTagCb；type AttributeWithTagCb = (tagName: string, key: string, value: string) => boolean：属性另走这一路回调，声明没写它与 START_TAG token 的先后（出处：鸿蒙 SDK 的 ets/api/@ohos.xml.d.ts，ParseOptions.attributeWithTagCallbackFunction / AttributeWithTagCb）
- EventType：START_DOCUMENT = 0，END_DOCUMENT = 1，START_TAG = 2，END_TAG = 3：flush 的时机看这几个事件（出处：js-apis-xml.md，EventType）
- parseXml(option: ParseOptions): void（@since 14；旧的 parse 自 API 14 废弃）：启动解析（出处：鸿蒙 SDK 的 ets/api/@ohos.xml.d.ts，XmlPullParser.parseXml）
- API 23 实测顺序：START_TAG token → 本元素各属性回调 → 下一个 token；开始标签挂起到下一 token 再分发后属性归属正确：在 START_TAG 时快照会把上一元素的属性交给下一元素（出处：卡里修好并验证过）
- attributeValueCallbackFunction?: (name: string, value: string) => boolean：同族接口：不带标签名的属性回调，同样与 token 分开上报（出处：鸿蒙 SDK 的 ets/api/@ohos.xml.d.ts，ParseOptions.attributeValueCallbackFunction）
