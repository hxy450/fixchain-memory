# 派工要求读源码确认 Model 字段时，到所属 .kt 源里找类定义，没读到就报未核实

审的是：代码
触发（任一种）：
- 读到：所属的 .kt 源文件里同时定义了多个 `data class`，而只读了 kapt 生成的同名 stub；写错的样子：目标 Model 的 `class` 字段照搬了同文件另一个类的字段，注释写「占位，字段由 Feature Spec 补充」，汇报却说字段已从源码核实
适用范围：按派工从安卓源码 bean 类提取桥接或数据 Model 字段时
做法：
- 按类名在所属 .kt 源文件里找 `class <类名>(…)` 的定义，逐个照写字段名和类型；一个 Kotlin 文件可定义多个类，kapt stub 按类拆分，只读同名 stub 会漏掉同文件的其他类
- 没读到定义就在汇报里列为未核实，不用别的类的字段填占位，也不声称已核实
针对本应用要查的：
- Model 类的真实字段：源工程里按类名全文搜 `class <类名>`，常和同模块的其他 Model、类型常量写在同一个 .kt 里；读出构造参数的名字和类型，以及同文件里配套的常量对象，原样写到目标 Model
