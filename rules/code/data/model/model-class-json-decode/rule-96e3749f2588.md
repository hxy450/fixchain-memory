# fromJson 取值写成 (x as T) ?? 默认时，改成先 typeof / instanceof 判断再赋值

审的是：代码
触发（任一种）：
- 读到：源模型是 Kotlin data class，字段为 Int / Long / Boolean / String 等强类型，运行期类型由语言保证；写错的样子：目标模型的 fromJson(json: Record<string, Object>) 里字段写成 `(json['k'] as number) ?? 0`、`(json['k'] as boolean) ?? false` 这类，只靠 as 加 ?? 取值
适用范围：强类型源模型移植成 ArkTS 模型后，凡是宽类型输入（Record<string, Object>、Object）进入模型字段的入口
做法：
- 基元字段先判断再赋值：`this.k = typeof json['k'] === 'number' ? json['k'] as number : 0`，string / boolean 同样用 typeof 判断 'string' / 'boolean'，不通过就回落默认值
- 对象字段用 `json['k'] instanceof 目标类` 判断通过再赋值，否则回落默认值
- `?? 默认` 只留给缺失和 null，不拿它代替类型判断；把「字段运行期类型恒定」当作要保留的约束
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- `(json['k'] as number) ?? 0` 遇到 json['k'] = 'abc' 时字段拿到字符串 'abc'，不是 0：as 只是编译期断言，?? 只兜底 null / undefined，类型不符的值原样进入声明为 number 的字段（出处：卡里修好并验证过）
- 六个字段都改成直接用 typeof 判断、否则回落默认值后，类型不符用例通过：修好的写法；不需要先存成 Object | undefined 的中间变量（出处：卡里修好并验证过）
- typeof 只能用在表达式里，不能用作类型（规则 arkts-no-type-query）：`typeof x === 'number'` 这种判断在 ArkTS 里合法（出处：typescript-to-arkts-migration-guide.md，仅允许在表达式中使用typeof运算符）
