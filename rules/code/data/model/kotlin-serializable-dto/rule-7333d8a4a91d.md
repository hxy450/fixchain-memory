# 直译 decodeFromString 和可空调用时，JSON.parse 结果逐字段校验类型和 null

审的是：代码
触发（任一种）：
- 读到：kotlinx.serialization 的 runCatching { Json.decodeFromString<T>(text) }.getOrNull() ?: 默认值，@Serializable 类里有非空字段或全为 String / String? 字段；写错的样子：写成 JSON.parse(body) as T 后直接读字段，或读取 helper 只写 value as string；外层 try/catch 只兜住 JSON.parse 的错误，缺字段或类型不符时原样通过、不回落默认值
- 读到：Kotlin 对 JSON 来源字段写 x?.f()（如 post.url?.toHttps()），字段为 null 时不调用；写错的样子：译成 x !== undefined ? f(x) : null，JSON 里显式为 null 的字段会进 f 崩溃
适用范围：把 kotlinx.serialization 的类型化解码和 Kotlin 对 JSON 数据的可空调用直译成 ArkTS 手写 JSON 解析时
做法：
- 手写 fromJson：JSON.parse 后对每个字段做 typeof 检查（非空字段还要存在，可空字段另允许 null），不通过就 throw，交给外层 catch 走源端 runCatching 的失败分支、回落默认值
- 可空字段按 undefined 和 null 都可能出现处理：x !== undefined && x !== null 时才调用
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 字段做 typeof 检查，不符就抛错，交给外层 catch 回落空缓存：卡里修好的写法；改前 as string 不做运行时检查，数字字段原样通过（出处：卡里修好并验证过）
- 补 null 守卫、补必填字段校验函数：修好后 JSON null 不再崩溃，缺字段按失败处理（出处：卡里修好并验证过）
针对本应用要查的：
- 源数据类每个字段的类型、可空性和是否必填：源工程里被 decodeFromString 解码的 @Serializable data class 声明；逐字段读出 Kotlin 类型（String、String?、Int…）；没有 ? 且没有默认值的属性是必填；目标 fromJson 按它写 typeof 判断和 null 允许
