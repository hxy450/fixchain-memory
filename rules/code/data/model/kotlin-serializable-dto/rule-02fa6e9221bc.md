# 基础层用字符串枚举承载线上枚举名，序号只在 DB 读写边界换算

审的是：代码
触发（任一种）：
- 读到：SDK 数据类字段注释是字符串字面量联合，Room 列存 .ordinal；写错的样子：目标写成数字枚举 enum X { A = 0, B = 1 } 并用于 DTO 字段和请求 query，DTO 枚举字段类型是 number；各 Repository / VM 里有「UI 字符串枚举 ↔ ordinal」的转换桥
适用范围：目标端手写 DTO、枚举和请求组装，源端枚举既作请求参数又以序号存 DB 时
做法：
- 枚举写成字符串枚举，值 = SDK 枚举名 = 线上值，每个成员写成「成员名 = '成员名'」；DTO 的枚举字段用这个类型，请求直接发枚举名
- 另按 SDK 声明序提供序号表和 toInt / fromInt，只在 DB 读写边界用；删掉各层的 ordinal 转换桥
- 规格与现有代码（UI 层已是字符串枚举）、实测响应（golden 里枚举字段是字符串）或自己判断冲突时，记为决策缺口并用一次带枚举参数的真实请求核实，不静默照规格
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 字符串枚举（值 = SDK 枚举名）承载线上值、序号只在 DB 边界换算：修复用的结构（出处：卡里修好并验证过）
- ordinal()：枚举常量在声明中的位置，第一个常量为 0：DB 序号表按 SDK 枚举的声明顺序排（出处：java.lang.Enum#ordinal）
针对本应用要查的：
- 每个枚举的线上名和声明序：源工程依赖的 API SDK 源码里的枚举类定义；成员名（或 @SerialName 的值）作字符串枚举的值；声明顺序作 DB 序号表
