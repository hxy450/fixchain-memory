# 非 SDK REST 的协议响应按协议自身命名，规格只写 Object 时不凭推测补子字段

审的是：代码
触发（任一种）：
- 读到：规格里协议响应（如 nodeinfo）顶层是 camelCase（openRegistrations），子类型只写 usage: Object；写错的样子：DTO 按「字段名 snake_case 保持」自行拟出 active_half_year / local_posts 这类子字段
适用范围：数据模型阶段，声明不属于主 SDK REST 接口的协议响应 DTO 时
做法：
- 按协议自身的命名（如 camelCase）声明字段，不套用主接口的 snake_case 规则
- 规格只写 Object 时先查 SDK 里对应的子类型定义再声明字段；查不到就报回规格，不凭推测补名
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 修复把 NodeInfo 改为 camelCase 并补上 software.version：协议响应按自身命名（出处：卡里修好并验证过）
针对本应用要查的：
- 协议响应子类型的字段：SDK 的 sources jar 中协议响应对应的 data class（如 NodeInfoSoftware、NodeInfoUsage 一类）；逐个读构造参数的名字（有 @SerialName 时取它）、类型和可空性
