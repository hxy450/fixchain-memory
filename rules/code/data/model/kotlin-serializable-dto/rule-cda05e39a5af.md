# 规格只文字概括嵌套结构时，写 DTO 前 grep 源端消费点核对访问路径

审的是：代码
触发（任一种）：
- 读到：规格对响应的嵌套结构只有文字概括；源端消费点是平铺访问（如 view.post.copy(...)、view.community、view.counts）；写错的样子：DTO 照概括写成包装字段（如 post_view / comment_view 嵌套），和源端访问路径不一致
适用范围：数据模型阶段，把规格的响应结构写成目标端 DTO 接口时
做法：
- 先 grep 源端消费点（字段访问、copy(...) 调用）核对每个字段的访问路径，按源端路径声明 DTO 字段
- 和规格冲突时以源码或 SDK 为准声明，并把冲突报回规格
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 修复后举报类视图改为平铺字段，原包装字段标为 LEGACY，页面改读平铺字段：按源端访问路径声明后列表不再为空或抛错（出处：卡里修好并验证过）
