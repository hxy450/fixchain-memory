# 源端以 String 承接 JSON 数值 id 时，全局解析在 JSON.parse 之前保留数字原文

审的是：代码
触发（任一种）：
- 读到：Android 模型用 Gson 把服务端的 JSON 数值读进 String 字段（id、*_id 一类标识），线上响应或探针里这些字段是数值 token；写错的样子：全局响应解析入口直接 JSON.parse(text)，之后再用 `${value}` / String(value) 把数值转成字符串
适用范围：ArkTS 网络层的统一响应解析入口，服务端数值标识可能超过 2^53 − 1 时
做法：
- 逐项对照 Android 模型声明类型和线上 token 类型；凡 Android 以 String 承接、线上是 JSON 数值的标识字段，在 JSON.parse 之前保留数字原文：先把值位置上 ≥16 位的十进制整数字面量改成 JSON 字符串再解析，或改用保留原文的解析器
- 不依赖 parse 之后再 String(value)：那时大整数已经按双精度截断
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 数值超出 -(2^53 – 1) 到 (2^53 – 1) 时，普通 number 不能逐位表示：19 位的雪花 id 远超这个范围，JSON.parse 后末几位会变（出处：鸿蒙 SDK 的 ets/api/@ohos.util.json.d.ts，BigIntMode.PARSE_AS_BIGINT）
- parse 前把值位置上 ≥16 位的整数字面量转成字符串，id 回查和收藏同步恢复：修好后的写法（出处：卡里修好并验证过）
未核实：Gson 把数值 token 原样读进 String 字段出自库代码，本机没有源码，按卡写
