# Gson Bean 改写成显式 decoder 时，string/number 读取保留 Gson 的标量宽松转换

审的是：代码
触发（任一种）：
- 读到：Android Bean 由 Gson 反序列化（@SerializedName、TypeAdapter），字段声明为 String / Int（如 var id = ""、var x = 0）；写错的样子：decoder 的 string 读取写成 `typeof v !== 'string'` 就 throw DecodeError，number 读取写成 `typeof v !== 'number'` 就抛错
适用范围：把 Retrofit + Gson 的 Bean 和响应壳翻成 ArkTS 手写 JSON decoder 时，尤其真实响应样例还没采集时
做法：
- string 读取接受有限数字和布尔并转成字符串，number 读取接受数字字符串并转成数字；只有转换不了才报错，不按 typeof 一不符就抛
- 写最小回归：JSON 数字进 string 字段得到对应字符串，数字字符串进 number 字段得到对应数字
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Gson 会把 JSON 数字填进 String 字段、把数字字符串填进 Int / int 字段：源端解析器的标量容忍范围（出处：卡里修好并验证过）
- string / nullableString 接受有限数字与布尔并转字符串，number / nullableNumber 接受数字字符串后，HTTP 200 不再被判为解析失败：修好后的 decoder 写法（出处：卡里修好并验证过）
未核实：Gson 的标量转换规则出自库代码，本机没有源码，按卡写
