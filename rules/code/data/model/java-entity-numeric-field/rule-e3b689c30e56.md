# 源端 Double 字段在模型和落库绑定上保持数值语义，空串或不可解析绑 NULL

审的是：代码
触发（任一种）：
- 读到：Java 实体的 getter 返回 `Double`，另有 `setX(String)` 重载；写错的样子：ArkTS 模型把字段写成 `string | null`，只有数值读取的访问器，没有 String 入口「解析失败 → null」的语义
- 读到：数据层用 `values.put(KEY, note.getX())` 以 Double 绑定 REAL 列；写错的样子：`ValuesBucket` 里直接绑模型的字符串字段，空串以 TEXT `''` 落库而不是 NULL
适用范围：Java 实体里的 Double/装箱数值字段迁成 ArkTS 模型和 relationalStore 读写时
做法：
- 模型给 String 入口写访问器：按 Double 解析，失败 → null；数值出口返回 `number | null`；若保留文本存储，文本统一成 Java Double.toString 的形态
- 落库绑定走数值访问器：`bucket[col] = 数值或 null`，空串、不可解析的文本绑 null，不绑字符串
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- type ValueType = null | number | string | boolean | Uint8Array | Asset | Assets | Float32Array | bigint：ValuesBucket 每个键可绑的值；数值列绑 number，空值绑 null（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，relationalStore.ValueType）
- type ValuesBucket = Record<string, ValueType>：insert/update 用的键值对（出处：鸿蒙 SDK 的 ets/api/@ohos.data.relationalStore.d.ts，relationalStore.ValuesBucket）
- 空串以 TEXT '' 落库时，`col != 0` 一类的查询会把它当成有值：绑字符串的后果；改绑数值、空串绑 NULL 后修好（出处：卡里修好并验证过）
针对本应用要查的：
- String 入口的解析规则和文本形态：源工程里该字段的 setter（含基类，基类在二进制依赖里时用 javap 读）；看 String 重载里调用的解析方法和异常分支（如 parseDouble 捕获 NumberFormatException 后置 null）
未核实：卡里的行为出自 HarmonyOS 6.1.1(24)，核对声明用的是本机 API 23
