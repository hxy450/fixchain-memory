# 移植的模型类和它的构造器

agent 会看到什么：读到被移植类的源构造器和相邻类的构造器、或计划写明 models/ 按职责拆文件；交回的目标类构造器初值和源类自身不一样，或同一类型在两个文件里都有 export class

## 规矩

- rule-a129dc590ee3｜移植类的构造器初值只照这个类自己的源构造器写，不套相邻类的初值｜读到：被移植类的源构造器给结果或状态字段赋初值（含 `null`），同一任务里还读了相邻类的构造器，那里的初值不同；写错：目标类构造器里的字段初值和源类自身的构造器不一样，例如源端是 `null`，目标却写成某个错误码和一段错误文案
- rule-bbc3fd8c2dd9｜同一目录出现两套模型文件、同名导出重复时，按计划留一套删另一套并核对构造参数顺序｜读到：计划或派工写明 `models/` 下的模型按职责拆成几个文件，由一个 worker 负责产出；写错：`models/` 下同一个类型在两个文件里都有 `export class` 定义（一个汇总文件和几个按职责拆分的文件并存），两版构造参数顺序不同
- rule-81423c17d9b5｜规格表写了构造缺省值（如当前毫秒）时，模型构造器照写，不改成 null 留给落库补｜读到：规格字段表的缺省列写了构造缺省值（如 id 缺省「当前毫秒」），Java 无参构造只有 `super()`；写错：ArkTS 模型写成 `id: number | null = null`，注释把缺省解释成落库侧补值
