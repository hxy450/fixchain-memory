# 源端一次 Either.catching 包住全部格式解析时，JSON 解码失败也返回同一个错误类型

审的是：代码
触发（任一种）：
- 读到：源端解析入口用一次 Either.catching(onCatch = 某解析错误) 包住 XML、JSON 等全部格式；sealed class 里另有一个 JSON 专用的错误类型，但这条路径不产生它；写错的样子：目标解析的 catch 里按格式分支，为 JSON 格式单独返回 JSON 专用的错误 kind；文件头注释写「XML/JSON 解码失败 → 两种错误」
适用范围：把源端抓取/解析路径的错误类型翻译成目标错误模型时
做法：
- 以源端这条路径实际的 catch / 构造为准：一次 Either.catching 包住全部格式时，所有格式的解码失败（含非法 JSON、字段类型不符）都返回 onCatch 给的那个错误类型
- sealed class 里存在某类型只说明它存在，不说明这条路径会产生它；派工里笼统的「XML/JSON 解码失败错误类型」与具体验收条目不一致时，按验收条目和源码实现
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 删除 JSON 专用分支，所有格式统一返回同一个解析错误；非法 JSON 样例返回该解析错误：修好的写法，单测全部通过（出处：卡里修好并验证过）
针对本应用要查的：
- 源端这条路径实际产生哪个错误类型：源工程里解析入口函数的 Either.catching / try-catch 及其 onCatch 参数；以 onCatch 构造的类型为准，不以 sealed class 的成员清单为准
