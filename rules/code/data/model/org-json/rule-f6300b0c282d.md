# org.json 的 getJSONObject/getString 改写时补宽松解析、对象校验和 null 取值

审的是：代码
触发（任一种）：
- 读到：new JSONObject(text).getJSONObject("…") / getString(...)（org.json）；写错的样子：JSON.parse(text) 后 parsed['…'] as Record<string, string> 强转，字段不是对象也不判失败；getString 的 JSON null 取成 null 而不是 "null"
适用范围：源端用 org.json 解析导入文件或接口数据、目标在 ArkTS 里解析时
做法：
- 解析用移植自 org.json JSONTokener 的宽松解析器（接受注释、单引号或不带引号的字符串、= / => / ; 分隔等），不直接用 JSON.parse
- getJSONObject 对应处判断取到的值是非数组、非 null 的对象，否则按解析失败处理；getString 对应处遇 JSON null 取字符串 "null"
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- JSONTokener 宽松：忽略 // 与 # 行注释、/* */ 注释，接受不带引号或单引号字符串、0x 十六进制、0 开头八进制、; 分隔数组元素、多余分隔符（当作 null）、= 或 => 分隔键值、; 分隔键值对：移植的解析器要接受的写法（出处：org.json.JSONTokener（类注释））
- getJSONObject(name)：值不是 JSONObject 时 throw JSON.typeMismatch(name, object, "JSONObject")：取到的字段不是对象就失败（出处：org.json.JSONObject#getJSONObject）
- getString(name)：经 JSON.toString 取值，非字符串用 String.valueOf 转换；JSON null 是 JSONObject.NULL，toString 返回 "null"：数字、布尔也转成字符串，null 得到 "null"（出处：org.json.JSONObject#getString；org.json.JSON#toString；org.json.JSONObject#NULL）
- 移植 JSONTokener 宽松语法 + 对象校验 + getString(null) → "null"：修好后导入行为和源端一致（出处：卡里修好并验证过）
