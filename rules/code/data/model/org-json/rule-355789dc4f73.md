# 源端用 org.json 的 getString 取字段时，目标解析器遇 JSON null 不抛错，只在缺键时失败

审的是：代码
触发（任一种）：
- 读到：源码用 getString("key") 读字段，实际数据（rawfile、备份 JSON）里该字段有 "key": null 或数字；写错的样子：目标用 `as string` 直取字段，保留真 null（显示成空行）；或写成非字符串即抛错的守卫
- 读到：源端解析函数用 JSONObject.getString("key") 取字段，对应 Kotlin 数据类的字段声明为非空 String；写错的样子：目标手写解析器对这个字段做必填校验：`typeof v !== 'string'`（包括 JSON null）就 throw，一条记录失败整份解析失败
适用范围：把源端 org.json 反序列化迁成 ArkTS 手写解析器，读资源 JSON 或备份 JSON、为字段定必填和空值规则时
做法：
- 按源端取值 API 定空值规则，读取走 org.json 等价写法：getString 遇 JSON null 不抛错、数字转字符串，只有缺键才失败；getInt 截断；getJSONArray 缺键或非数组抛错。Kotlin / DTO 字段非空不等于 JSON 值不会是 null
- JSON null 的落值两张卡说法不同：读成字符串 "null"（与源端显示一致），或读成 string | null 再 `?? ''` 兜底；见未核实
- 写解析器前对实际数据逐字段统计 null、数字、缺键、非字符串的条数，有 null 的字段不写成必填，并核对「条数等于数组长度」这类验收在真实数据上成立
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getString(name)：先 get(name)，再 JSON.toString(object)，结果为 null 才抛 typeMismatch；值存在就按需强转：getString 只在缺键或值转不成字符串时抛错（出处：org.json.JSONObject#getString；org.json.JSON#toString）
- get(name) 在没有这个键时 throw new JSONException("No value for " + name)：缺键是源端真正会失败的情形（出处：org.json.JSONObject#get）
- JSON null 解析为 JSONObject.NULL，它的 toString() 返回 "null"：源端 getString 读 JSON null 得到字符串 "null"，不抛错（出处：org.json.JSONTokener#readLiteral；org.json.JSONObject#NULL）
- getInt 对 Number 取 intValue()：小数被截断（出处：org.json.JSON#toInteger）
- getJSONArray 缺键或非数组抛 JSONException：不读成空数组（出处：org.json.JSONObject#getJSONArray）
- JSON null 描述用 getString 等价写法转成 "null" 后，显示与源端一致（源端显示 "null"）：一张卡修复后的写法（出处：卡里修好并验证过）
- 字段改成可空读取再 ?? '' 后，含 null 的条目能解析，列表正常渲染：另一张卡修复后的写法（出处：卡里修好并验证过）
针对本应用要查的：
- 实际数据里每个字段有没有 null、数字、缺键或非字符串：目标工程 rawfile 里迁过来的 JSON，或源工程 assets / res/raw 里的同一份（含备份 JSON）；对每条记录逐个键统计 null、缺键、类型不是 string 的条数（可按键名搜 ": null 和不带引号的数字值）；条数不为 0 的字段不写成必填，按 getString 的语义强转
未核实：JSON null 的落值有分歧：case-7e6984a7fa6d5845737b 读成字符串 "null"，修好后与源端显示一致；case-ffdccd8c954d99b4c6d6 读成 string | null 再 ?? '' 兜底，修好后列表正常渲染。源端 org.json 对 JSON null 得到的是字符串 "null"，两种兜底显示不完全相同
