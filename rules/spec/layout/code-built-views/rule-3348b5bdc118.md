# 源端用单个字形（•、●）大字号画指示器时，规格写源字体下的几何，不写字符加字号的硬映射

审的是：规格
触发（任一种）：
- 读到：源码在循环里 new TextView、setText(Html.fromHtml("&#8226;")) 或单个符号（•、●、·、★）、setTextSize(远大于正文的字号)，逐个 addView 到 gravity=center 的 LinearLayout；内容只有一个符号，无标签、无链接；写错的样子：规格的跨栈映射或组件契约写成「Html.fromHtml("&#8226;") 圆点 → Text('•')」「• U+2022, textSize 字号」这类字符加字号的硬映射，没写单点步进、直径、垂直位置
适用范围：规格提取阶段，给源端用文字字形充当图形的指示器（页码点、星标等）写跨栈映射和共享组件契约时
做法：
- 不把「字符 + 字号」列为跨栈硬映射；组件契约写源字体下的可见几何：单点步进、直径、相对容器的垂直位置，并写明来源（源端截图实测或 Roboto 字形度量）
- 契约里注明目标默认字体（HarmonyOS Sans）下同一字形的度量不同，实现要按几何画图形或先实测
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 目标默认字体下同一个 '•' 按同字号显示时步进明显变大、位置偏上；按源字体几何画 Circle 后与源端一致：字符加字号的映射不能保住外观（出处：卡里修好并验证过）
- setTextSize(float size)：按 scaled pixel（sp）解释，随密度和用户字体缩放调整：源端字号是 sp，换算几何时按 sp 计（出处：android.widget.TextView#setTextSize）
针对本应用要查的：
- 源字体下这个字形在给定字号的单点步进、直径和点心的垂直位置：源端截图实测；或源字体（默认 Roboto）字体文件里这个字形的 advance width 和轮廓边界；字形度量按 em 比例乘字号（sp）得到 dp；垂直位置按 TextView 高度和基线算点心距顶的距离。例：卡里 Roboto、字号 35 时实测步进约 11.8dp、直径约 6.6dp、点心在 TextView 内偏下
