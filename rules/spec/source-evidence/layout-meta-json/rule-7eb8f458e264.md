# 多模块有同名布局时，按页面类所在模块和它用的绑定类定源码布局，不按布局名解析

审的是：规格
触发（任一种）：
- 读到：多模块安卓工程里几个模块各有同名的 Fragment/Activity 类和同名布局 XML；页面类 import 的 ViewBinding 绑定类在本模块包名下的 .databinding 包里；写错的样子：meta.json 的 layout_sources 或规格的「源码布局」指向另一个模块的同名布局；只手工改了已发现的几页，其余同名布局没复核
- 写错的样子：分页规格同时写着「所属模块: A」和「源码布局: B 模块/src/main/res/layout/…」，或注释里写「layout_sources 为权威」来消解两者的冲突
适用范围：规格提取阶段为多模块安卓工程的 Activity/Fragment 确定 layout_sources、写分页规格的「源码布局」时
做法：
- 生成 meta.json 后逐页核对：页面类的包名和所属模块、它用的绑定类在哪个模块；布局取那个模块 src/main/res/layout 下的文件。解析到别的模块时修正 layout_sources 并重新合成 view.xml
- 发现一处同名布局解析错，就列出所有跨模块同名布局逐页复核，不只修已发现的页面
- 规格里「所属模块」和「源码布局」必须是同一个模块；冲突时回源码核对绑定类再改布局路径，不用「layout_sources 为权威」消解
针对本应用要查的：
- 页面类所属模块和它对应的布局：源工程里页面类的 .kt/.java 源文件：package 声明、import 的 *.databinding.*Binding 类；再看各模块 src/main/res/layout 下的同名布局；绑定类所在包属于哪个模块，就取哪个模块的布局；布局 <data> 里 <variable> 的 type 全名也应和页面类一致
