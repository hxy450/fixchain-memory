# 源码笔记遇到声明没写先后的平台回调时，写成待验证项，不写「两种顺序行为一致」

审的是：规格
触发（任一种）：
- 读到：@ohos.xml 声明没写 attributeWithTagCallbackFunction 与 START_TAG token 的先后，也没保证 getNamespace() 给出元素 URI；写错的样子：源码理解笔记把不确定项写成「START_TAG 时快照并清空——两种顺序下行为一致」，或写成「每个元素自报 uri，可直接取 getNamespace()」
适用范围：源码理解或规格阶段记录目标平台回调语义里声明没写明的点时
做法：
- 不确定项写明：声明未写先后（或未保证返回值），待实测；只有属性先到时「START_TAG 时快照后清空」才成立；实测前实现用与顺序无关的组装（开始标签挂起到下一 token 再分发）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- API 23 实测：START_TAG token 先到，本元素属性回调随后，再到下一个 token：按「属性先到」写的笔记结论不成立（出处：卡里修好并验证过）
