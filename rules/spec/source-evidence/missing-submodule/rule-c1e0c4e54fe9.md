# 关键实现在未检出子模块里时规格先取源，取不到登记阻塞缺口，不把反推格式写成逐字段 AC

审的是：规格
触发（任一种）：
- 读到：源端读写流交给子模块里的工具函数，.gitmodules 有 URL、子模块目录为空，app 侧只见调用点；写错的样子：规格写「按读侧反推」「推断（读侧源码实证）」，却把反推出的数据格式写成逐字段相等的 AC（如「库内 N 行→content N 行、各字段值全等」）
适用范围：规格提取时，结论依赖未检出子模块、外部库或远端仓库源码的那些契约
做法：
- 先取源：在副本里 git submodule update --init，或按 .gitmodules 的 URL 取对应文件，按源码写格式
- 取不到时把格式登记为未知缺口、写明阻塞和核验方式；不按调用点反推字段结构，也不把推断写成逐字段相等的 AC
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 反推出的扁平行格式与子模块实际写出的「表数组（表名、建表语句、行值）」不同，取回子模块后按源码改正：反推格式的后果（出处：卡里修好并验证过）
针对本应用要查的：
- 子模块的源码位置：源工程根目录 .gitmodules 的 url 和 path，或 Gradle 依赖声明里的坐标；按 URL 和路径取到写侧工具函数原文，再写格式契约
