# 第三方 TextView/Dialog 库登记进跨栈基线时，写明截断策略、行距倍数和默认装饰

审的是：规格
触发（任一种）：
- 读到：Gradle 构建脚本的 implementation 里有第三方 UI 库的二进制依赖（如 pixlui、material-dialogs），布局用库里的 TextView / EditText / Dialog 子类；写错的样子：跨栈映射基线里这个库只登记成「自定义字体 TextView → ArkUI Text .fontFamily()，L2 Auto」或「→ CustomDialog」，没有截断策略、行距倍数、默认装饰三项
适用范围：规格提取阶段把源工程的第三方 UI 库登记为跨栈映射基线时
做法：
- 登记前取得库的源码核实渲染行为；对 TextView / EditText / Dialog 子类在基线行里至少写出截断策略（是否自带省略算法、按字符还是按词回退）、行距倍数、默认装饰三项，并写明出处
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 一个第三方 TextView 子类自带 N 行省略算法（取前 N 行→按空格回退到「文本+…」→去尾标点→加「…」，禁用系统省略），被登记成纯字体替换后截断语义在规格里缺失：只凭类名登记的后果（出处：卡里修好并验证过）
针对本应用要查的：
- 库控件的截断、行距、装饰缺省：依赖库的源码包或库仓库里对应的 TextView 子类和 Dialog Builder（按应用依赖的版本）；读出它是否覆盖省略逻辑、Builder 里行距倍数等缺省字段，原样写进基线行
来源：1 张卡，1 个应用
