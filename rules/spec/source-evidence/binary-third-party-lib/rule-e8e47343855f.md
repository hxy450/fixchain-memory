# 调用点的布尔实参不从值推断含义，核库签名；恢复后重启就把「应用重启」写进 AC

审的是：规格
触发（任一种）：
- 读到：源端调用点只露出含义不明的布尔实参，如 import(ctx, uri, true)；写错的样子：规格按实参猜含义（如解释成整库替换 replace），导入链写成「替换 → 重开连接 → 内存状态重载 → Toast」，AC 拿调用行作真值
适用范围：规格提取阶段，转写源端三方库调用的参数语义和调用后行为时
做法：
- 核库签名里这个参数的名字和 true 分支的行为；是重启进程的，AC 写「恢复后应用重启」，不写「内存重载 + Toast」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- room-db-export-import 的 import 第三个参数 true 是 restartApp：startActivity 后 System.exit：反编译 AAR 确认的库行为（出处：卡里修好并验证过）
针对本应用要查的：
- 布尔参数的名字和 true 分支行为：该库同版本的 AAR 反编译结果或源码里这个方法的签名；读参数名和 true 分支调用了什么（重启、替换、合并），照实写进 AC
来源：1 张卡，1 个应用
