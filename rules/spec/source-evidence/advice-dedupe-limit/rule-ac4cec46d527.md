# 审计或规格给实现建议时，源端行为和鸿蒙适配建议分开写，去重上限附源码出处

审的是：规格
触发（任一种）：
- 写错的样子：审计或规格的「最小链」一类实现建议里写了「有界去重队列」等去重、上限属性，没附源码出处，也没标明是源端已核行为还是鸿蒙适配建议
适用范围：审计、规格阶段描述队列一类行为契约并给出实现建议的那一节
做法：
- 每个属性（入队、去重、上限、出队、点击、清理）标明来源：源端已核行为附源文件和方法或行号；没有源码出处的单列为「鸿蒙适配建议」，不写进契约
