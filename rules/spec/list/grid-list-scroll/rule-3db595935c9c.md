# 验收写「网格不滚动、一屏全可见」时，先按源端格高算总高再定

审的是：规格
触发（任一种）：
- 读到：源 GridView / ListView 没有固定行高，条目高由内容量出（getView 未设固定高的 LayoutParams）；写错的样子：规格或验收条目写「网格不滚动」「典型屏全可见」，没有按源端格高和行距算出的总高做依据
适用范围：规格和验收条目里写网格或列表一屏能放几行、是否滚动的那一项
做法：
- 先按格高 = 图片按密度放大后的固有高 + 条目上下 padding、行距 = dp 间距按密度截断的 px，算出 行数 × 格高 +（行数 − 1）× 行距，与典型屏可用高比较，再写是否滚动；不按方格结果反推
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 按源端格高算，安卓参照机上一屏只放三行半、需要滚动；方格结果是一屏全放下：两种算法得出的结论相反（出处：卡里修好并验证过）
针对本应用要查的：
- 典型屏的可用高和 dpi：规格或验收里指定的参照设备；没有指定时取安卓参照机的屏幕参数；可用高减去标题栏等固定区域，与算出的网格总高比较
来源：1 张卡，1 个应用
