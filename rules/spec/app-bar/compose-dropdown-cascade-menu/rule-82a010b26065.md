# 规格把下拉和级联菜单的弹出形态写成验收契约：锚点、无遮罩、点外与返回关闭、子层原地切换

审的是：规格
触发（任一种）：
- 读到：Compose 源里菜单是 M3 DropdownMenu、me.saket.cascade 的 CascadeDropdownMenu 或基于 Popup 的居中菜单，放在触发 IconButton 所在的 Box 里；带 children 的项在同一菜单内切到子层；写错的样子：规格把级联菜单映射成「两级 Menu / 半模态面板」，写了「弹出形态差异由 visual 断言容忍」这类放行条款，没写锚点、有无遮罩、关闭方式和子层切换方式
适用范围：规格提取阶段为下拉菜单、级联子菜单和居中操作菜单写映射和验收条目时
做法：
- 验收条目逐项写：锚点（菜单顶对齐触发按钮底，起点或末端对齐）、无变暗遮罩、点外与返回关闭、children 子层在同一菜单内原地切换并带返回 Header
- 居中级联另写：全屏透明点外关闭层、内容垂直居中、宽度按源端的屏宽比例；不写「弹出形态差异由 visual 断言容忍」
针对本应用要查的：
- 每个菜单的源端组件类型、锚点和宽度：源工程里调用菜单的 Composable（看菜单和哪个 IconButton 同在一个 Box 里）和菜单组件的定义（DropdownMenu / CascadeDropdownMenu / Popup 的对齐参数、宽度常量）；记下组件类型、对齐方式、宽度常量和有没有背景色，原样写进验收条目
