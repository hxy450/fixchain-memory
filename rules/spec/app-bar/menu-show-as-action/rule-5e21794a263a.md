# 源 ActionBar 菜单有 ifRoom 项时，规格按框架分配规则写上栏结果，不简写成进图标位

审的是：规格
触发（任一种）：
- 读到：源 Activity 用平台主题的窗口 ActionBar（非 AppCompat，android:showAsAction 生效），菜单 XML 有 showAsAction="ifRoom" 项；写错的样子：规格、feature-base 或派工写「always/ifRoom 带图标的项进图标位、never 进溢出」，没有名额、溢出钮预留、半屏宽度预算和横竖屏重算
适用范围：规格提取阶段转写框架窗口 ActionBar 的菜单上栏与溢出分配时
做法：
- 上栏写成条件规则：always 必上栏；ifRoom 按名额与宽度分配——名额按屏幕 dp 取，有 never 项或 always+ifRoom 总数超名额时先为溢出钮扣一个名额，always 先扣；宽度预算为屏宽一半减溢出钮宽，按顺序逐项扣按钮宽，透支则退回溢出；横竖屏或窗口宽变化后重算
- 按典型竖屏、横屏宽度列出每页实际上栏的项，未上栏的 ifRoom 项和 never 项一起按 orderInCategory 进溢出面板
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- smallestScreenWidthDp > 600 或（宽 > 960 且高 > 720）或（宽 > 720 且高 > 960）→ 5；宽 ≥ 500 或（宽 > 640 且高 > 480）或（宽 > 480 且高 > 640）→ 4；宽 ≥ 360 → 3；否则 2（单位 dp）：上栏名额（含溢出钮）（出处：com.android.internal.view.ActionBarPolicy#getMaxActionButtons）
- getEmbeddedMenuWidthLimit() = widthPixels / 2，再减去溢出钮测量宽：上栏宽度预算（出处：com.android.internal.view.ActionBarPolicy#getEmbeddedMenuWidthLimit；android.widget.ActionMenuPresenter#initForMenu）
- hasOverflow 或 requiredItems + requestedItems > maxActions 时 maxActions--；随后 maxActions -= requiredItems：先为溢出钮扣名额，always 项先扣（出处：android.widget.ActionMenuPresenter#flagActionItems）
- 移植名额与分配算法后，竖屏实机上栏项与安卓一致：修好后的结果（出处：卡里修好并验证过）
针对本应用要查的：
- 每页菜单项的 showAsAction 和顺序：源工程 res/menu/ 下每页的菜单 XML，每个 <item> 的 android:showAsAction、android:icon、android:orderInCategory；按上面的规则在典型竖屏（如宽 360–411dp）和横屏宽度下逐项算出上栏集合
