# 源布局多处 fitsSystemWindows 时，规格的安全区段逐个子视图写由谁消费

审的是：规格
触发（任一种）：
- 读到：源布局 DrawerLayout、内容列（CoordinatorLayout 等）、NavigationView 各自写了 android:fitsSystemWindows="true"，NavigationView 带 app:headerLayout；写错的样子：规格的沉浸、安全区段只写根节点的 fitsSystemWindows（如「DrawerLayout(fitsSystemWindows) → SideBarContainer」），没写内容列下移、抽屉头部画到状态栏下并叠 insetForeground
适用范围：页面规格里写沉浸和安全区的那一段，源布局有 DrawerLayout + NavigationView 时
做法：
- 安全区段按子视图逐个写 fitsSystemWindows 由谁消费：DrawerLayout——画状态栏底色；内容列——下移到状态栏之下（目标在内容列顶部放状态栏高的占位）；NavigationView——头部从窗口顶画，状态栏那段叠 insetForeground #44000000
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- insetForeground = #4000（即 #44000000）：NavigationView 状态栏那段前景的默认颜色，规格里照写（出处：com.google.android.material:material 包内 res/values/values.xml，Widget.Design.ScrimInsetsFrameLayout 的 insetForeground（按应用依赖的版本））
针对本应用要查的：
- NavigationView 有没有改写 insetForeground：源工程布局 XML 里这个 NavigationView 的 app:insetForeground，以及主题里 navigationViewStyle 指向的样式；有改写就在规格里写改写后的颜色；没有就写 #44000000
未核实：卡里没记 material 库版本，本机按 material 1.12.0 核实
