# API 清单的鉴权摘要还没落盘时，规格的网络层认证小节保留待补标记，不以 raw_apis 收口

审的是：规格
触发（任一种）：
- 读到：feature-base 模板要求认证和拦截器取自 api-inventory.json 的 auth_type / auth_detail 和 common.md，但磁盘上只有 raw_apis.json；写错的样子：规格网络层写「数据源 raw_apis.json（已就绪）」，删掉了「待 api-inventory.json（含 auth_type）」这类待补标记，认证只写「统一 token 注入」一句
适用范围：规格提取阶段写网络基础层（feature-base）的认证、拦截器小节时
做法：
- api-inventory.json 的 auth_model 或 common.md 不在磁盘上时，认证小节保留待补标记，不改写成「raw_apis.json 已就绪」
- 要在当下收口的，改为直接读 raw_apis 里标了 header_write 或 token_injection 的拦截器源码，把每个请求头的名称、取值来源和格式逐项写进 feature-base
