# 把源端活行为委托给其他 feature 时，先核到目标规格里的 AC，端点写明唯一生产方

审的是：规格
触发（任一种）：
- 读到：源 Fragment / Activity 里有已确认的活行为（设置项点击、onResume 刷新链），或接口文档列出某个 POST 端点及其调用位置；写错的样子：范围节把这些行为归给其他 feature「AC 登记但不展开」或写成跨 feature 对接点，目标 feature 规格里却没有对应 AC；API 表列出端点并注「归某 feature 消费」，任何服务接口里都没有它
适用范围：规格拆分时，把源端行为或网络端点交给别的 feature 的那些条目
做法：
- 委托前打开目标 feature 的规格，核到对应的 AC 或服务接口再写委托；对接表逐项列出被委托的每个行为，不只列其中几项
- 端点只出现在 API 表、不在任何服务接口里时，写明唯一生产方（「<端点> 由 <某 Service> 提供」），不写「归某 feature 消费」就结束
