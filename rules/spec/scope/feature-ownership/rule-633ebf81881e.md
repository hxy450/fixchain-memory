# 源端由多个方法组成的会话，规格按生命周期逐步写 AC，参考规格的取消规则要落到某个 feature

审的是：规格
触发（任一种）：
- 读到：源端一个会话分散在多个方法里：拍照入口的开始/完成分支、启动（开传感器录制、显示取消按钮）、保存路径里的逐帧累积分支、完成提交、停止/取消；参考规格列了「中途取消 → 丢弃或按偏好保存」「张数超限 → 强制结束并合成」；写错的样子：规格只为其中一步（如引导点计算、张数上限）写 AC，启动、逐帧入批、完成提交、取消丢批没有任何 feature 的 AC 承接；各 feature 互相把编排推给对方
适用范围：规格提取阶段，把源端跨方法的会话（启动、逐帧累积、完成、取消）拆成验收项时
做法：
- 按生命周期逐条写 AC：开始/完成入口；启动（开录制、显示取消按钮）；逐帧（未对齐拒帧、首帧建批并记视角、每帧入批附旋转矩阵）；完成（写方向后提交批次）；停止/取消（停录制、清目标、丢批）
- 参考规格列出的取消、超限规则逐条写进某个 feature 的 AC，并写明属主
针对本应用要查的：
- 会话由哪些方法组成：源工程里会话入口方法（开始、逐帧、完成、取消）和保存路径里按模式分支的那段代码；顺着开始到取消读完整段，每个方法对应一条 AC
