# 源端行为、页面和接口归到哪个 feature

agent 会看到什么：读到源页面有已确认的活行为、接口文档列着 POST 端点及调用位置，或页面同包里有自己的 Retrofit Service、api-inventory 的 callers 指向它；规格把行为、端点写成「归某 feature」或按模块、名称关键词分桶写 page_id ownership，目标 feature 的 AC 和服务层里却没有它们

## 规矩

- rule-51301545f558｜把源端活行为委托给其他 feature 时，先核到目标规格里的 AC，端点写明唯一生产方｜读到：源 Fragment / Activity 里有已确认的活行为（设置项点击、onResume 刷新链），或接口文档列出某个 POST 端点及其调用位置；写错：范围节把这些行为归给其他 feature「AC 登记但不展开」或写成跨 feature 对接点，目标 feature 规格里却没有对应 AC；API 表列出端点并注「归某 feature 消费」，任何服务接口里都没有它
- rule-b67d2003cb23｜页面包内有自己的网络 Service 时，按接口归属 feature，不按模块默认桶｜读到：安卓页面在公共 base 模块，但同包里有自己的 Retrofit Service 接口（@GET 分类、列表），api-inventory 里该接口的 callers 指向这个页面；写错：页面被写进某个 feature 规格的 Phase B page_id ownership，但这个 feature 的范围和服务层里没有该接口，也没补数据契约；归属是按模块或名称关键词分桶得出的
- rule-315594ad7f55｜规格把工具类归到功能时按真实调用点（grep 调用者），不凭名字挂到不调用它的页面｜读到：源码里有一个文本或格式化工具类（…Utils.kt），只在少数几个组件里被调用；写错：规格把这个工具类挂到一个并不调用它的功能上，真正调用它的功能的锚点里却没有它
- rule-7a90cc432033｜规格把设置位的行为推给另一个 feature 时，先核对方规格有行为 AC，没有就本规格认领｜读到：源码里某个设置位决定显示行为（例如切换全局 ImageLoader），它的读写和界面行为分在两个 feature 的源码里；写错：规格写「这个设置位 → 另一个 feature」把行为整体推走，而对方规格只有开关持久化的 AC，没有这个设置位在各界面上的行为 AC，两边都没认领
- rule-633ebf81881e｜源端由多个方法组成的会话，规格按生命周期逐步写 AC，参考规格的取消规则要落到某个 feature｜读到：源端一个会话分散在多个方法里：拍照入口的开始/完成分支、启动（开传感器录制、显示取消按钮）、保存路径里的逐帧累积分支、完成提交、停止/取消；参考规格列了「中途取消 → 丢弃或按偏好保存」「张数超限 → 强制结束并合成」；写错：规格只为其中一步（如引导点计算、张数上限）写 AC，启动、逐帧入批、完成提交、取消丢批没有任何 feature 的 AC 承接；各 feature 互相把编排推给对方
- rule-bf787cf9f40a｜规格给拍照完成回调和多帧采集执行指定归属 AC，不只写「归某功能」而该功能只覆盖触发侧｜读到：源端拍照完成回调里复位状态、续拍、暂停预览，失败回调恢复预览；burst 类型决定帧数并整组回调；写错：一份规格写「拍照 / 连拍归 F00x」「下发消费归 F00x」，被指向的那份规格只写触发侧，没有 AC 覆盖完成回调和多帧采集执行
