# 页面包内有自己的网络 Service 时，按接口归属 feature，不按模块默认桶

审的是：规格
触发（任一种）：
- 读到：安卓页面在公共 base 模块，但同包里有自己的 Retrofit Service 接口（@GET 分类、列表），api-inventory 里该接口的 callers 指向这个页面；写错的样子：页面被写进某个 feature 规格的 Phase B page_id ownership，但这个 feature 的范围和服务层里没有该接口，也没补数据契约；归属是按模块或名称关键词分桶得出的
适用范围：规格提取阶段给页面分配所属 feature（page→feature 归属）时
做法：
- 逐页核对页面源码包内的 Service 调用（api-inventory 的 callers）是否已在接收 feature 的服务层出现
- 缺失时把页面改归拥有该接口的 feature，或在接收 feature 的规格里补上这个接口的数据契约
- 归属脚本跑完后抽查每个 feature 新增的页面是否落在它已写明的范围内；不在的按归属缺口处理，不以“全部 page_id 已闭合”视为通过
针对本应用要查的：
- 页面实际调用的网络接口：源工程里页面所在包的 Retrofit Service 接口（@GET/@POST 注解的方法），以及流水线 api-inventory 里各接口的 callers；把页面会调用的接口路径逐个列出，和接收 feature 规格服务层里的接口对照
