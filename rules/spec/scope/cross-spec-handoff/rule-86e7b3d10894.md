# AC 与实现冲突又怀疑归属别的功能时，UT 设计先查源端写入点，查不清记为 spec 待确认，不写 RED

审的是：规格
触发（任一种）：
- 读到：AC 文字要求的范围比实现和源锚点大，设计者自己注了「需补方法或确认归属其他 feature」；写错的样子：UT 设计按 AC 字面写出要求当前方法实现的 RED 用例，没有核实源端写入点和其他功能的规格
适用范围：按规格 AC 设计单元测试用例、发现 AC 与代码冲突时
做法：
- 先查源端的写入点和其他功能的 spec，确认这部分是否属于当前功能
- 仍无法确认就把这条记为「spec 待确认」，不直接写成要求当前方法实现的 RED 用例
来源：1 张卡，1 个应用
