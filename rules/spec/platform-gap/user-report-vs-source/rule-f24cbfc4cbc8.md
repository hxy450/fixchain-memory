# 联调时用户描述与源 XML 不一致，先核源控件运行语义，再定复刻缺陷还是用户例外

审的是：规格
触发（任一种）：
- 读到：用户报告的行为（如首次进入应为未选中）和源 XML 的声明值不一致；写错的样子：例外登记里把它记成用户例外（U-…），没写源控件的实际运行语义；和源端行为一致的修正也被当成新要求
适用范围：联调修复阶段登记用户例外和新要求时
做法：
- 先读源控件的实现核对运行语义：和源端运行时一致的，记为复刻缺陷修正，不记用户例外
- 只有和源常量不同的要求（如延时从源端的值改成别的值）才作为新要求登记
