# 规格写「目标能力受限需降级」前先核对候选组件，未核实的不写成已批降级

审的是：规格
触发（任一种）：
- 读到：源端输入框带 `visualTransformation`（如按 URL 构造带样式的 AnnotatedString）等富文本效果；写错的样子：规格转换决策表写「ArkTS 输入框内富文本高亮能力受限，编辑态降级、保底纯文本」，没有核对 RichEditor 等候选组件；后续 uncertain 复审直接沿用
适用范围：规格提取阶段写转换决策表里的降级项时，以及之后复审 uncertain 项时
做法：
- 写降级前先核对候选组件（如 RichEditor 加 span 样式可在编辑态高亮 URL），写明核过的组件和结论；未核实的写成待核实项，不写成已批降级；复审 uncertain 项时重新验证
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- RichEditor 加 span 样式实现了编辑态 URL 高亮：所谓「能力受限」不成立（出处：卡里修好并验证过）
