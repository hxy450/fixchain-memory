# 规格判定「编辑态无可点击 span」前先查 RichEditor 声明，替代通道标为行为差异

审的是：规格
触发（任一种）：
- 读到：安卓源用三方 EditText 在编辑态给正文内的链接加可点击 span（如 gatherLinksForText + setOnTextLinkClickListener）；写错的样子：规格断言「ArkUI TextInput/TextArea 不支持编辑态内嵌可点击 span」「RichText 只读」，据此登记决策改走替代通道（如长按 → 解析全文 → 动作列表），映射行仍标 HARD 行为等价
适用范围：规格提取阶段，给源端二进制依赖的三方控件判定目标端有无等价能力时
做法：
- 先在本项目鸿蒙 SDK 的 rich_editor.d.ts 核实：RichEditor 的 addTextSpan(content, { gesture: { onClick } }) 能在编辑态给文字段挂点击；确认无等价后才登记决策
- 登记了替代通道的，映射行标为行为差异，不标 HARD 等价
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- addTextSpan(content: ResourceStr, options?: RichEditorTextSpanOptions): number：RichEditorController 加一段文字，options 里可带手势（出处：鸿蒙 SDK 的 ets/component/rich_editor.d.ts，RichEditorController.addTextSpan）
- RichEditorTextSpanOptions.gesture?: RichEditorGesture；RichEditorGesture.onClick?: Callback<ClickEvent>、onLongPress?: Callback<GestureEvent>：编辑器里单个文字段的点击和长按回调（出处：鸿蒙 SDK 的 ets/component/rich_editor.d.ts，RichEditorTextSpanOptions.gesture、RichEditorGesture.onClick）
- 用 RichEditor 承载编辑态链接 span 后，链接可在编辑态单击：返修用的做法（出处：卡里修好并验证过）
- RichEditorImageSpanOptions.gesture?: RichEditorGesture：同族接口：图片段同样可挂点击、长按（出处：鸿蒙 SDK 的 ets/component/rich_editor.d.ts，RichEditorImageSpanOptions.gesture）
未核实：卡里的行为出自 HarmonyOS 6.1.1(24)，本机按 API 23 声明核实
