# 决策台账里 PD 条目的依据、批准状态和缺陷表

agent 会看到什么：读到默认策略、spec 默认原则对 PD 的要求（依据要有条目原文、某类 PD 默认阻断、原版缺陷要保留）；交回的决策台账里 PD 依据只写 skill 名或「@kit.ArkUI d.ts」、凭 gate 自动批准写成 approved，或只有 `PD` 条目没有 `C12` 原版缺陷表

## 规矩

- rule-8c69aa91804f｜铸「平台无对等」的 PD 时，依据只引本会话读过的 skill 段落或声明、文档条目｜读到：参考里有「使用 Scroll 的 onScroll 回调手动计算 AppBar 高度和透明度」或「需组合模拟 AppBar 折叠效果」这类说明；写错：决策台账的 PD 写「HMOS 无滚动联动折叠标题栏对等」，依据只写一个 skill 名或「@kit.ArkUI d.ts」，没有具体条目原文，且本会话没读过这些文件
- rule-bb6f9c61276f｜无人值守的 gate 自动批准不等于 PD 已改判，默认阻断的 PD 保持 proposed，不写成 approved｜读到：default-policy 的确认表里某类 PD 默认「阻断，本行必须改判」，只有无法等价复刻时才记 PD 并保持 proposed；运行处于所有 gate 自动批准的模式；写错：决策台账把这类 PD 写成 approved，依据只是「gate 自动批准」，没有用户改判记录
- rule-d0335e55116c｜决策台账只收 PD 平台差异、缺 C12 原版缺陷表时，补列缺陷实例并标保留｜读到：spec 默认原则要求保留原有行为「包括缺陷、空点击、未完成功能和异常分支」，已确认缺陷写进 AC；写错：台账只有 `PD` 平台差异条目，`D0` 只写「全量行为等价迁移」，没有 `C12` 原版缺陷确认表
- rule-16dded76e0ed｜完整复刻且 Gate 无人值守时，按默认政策排除功能簇的台账条目标成待确认｜读到：默认迁移原则写「排除桌面 Widget、穿戴 / 电视等独立扩展入口」并要求「默认裁定不是静默生效」，用户 prompt 给出 headless 预授权「所有阶段审阅/继续 gate 自动批准并继续」，产出定位 D0 为完整复刻；写错：决策台账写「排除桌面 Widget…不迁移｜approved｜default-policy + headless 预授权」，Gate 摘要没有呈现确认表就自动批准，阶段报告里也没有这条决策缺口
- rule-ba3ad6ee007f｜按范围政策排除有对等能力的功能时，台账分别写能力可行和政策排除｜读到：源端有 `AppWidgetProvider`、`RemoteViews`、小组件配置 Activity，功能规格已把它映射到 Form Kit（FormExtensionAbility + ArkTS 卡片）；写错：台账的排除条目依据只有政策条文和源端调用链（如「仅被 APPWIDGET_UPDATE 链路触达」），没写目标平台对等能力的结论
- rule-2d90b3e7c365｜写决策台账时，worker 标出的行为不确定项登记为带用户可见后果的决策项，不用「不改变 X」锁死｜读到：worker 回执摘要里写了行为差异（如「某类设备源端显示 A、目标显示 B」）；写错：decision-ledger 只把它登记为 API 用法查证，还写「不改变 X 规格行为」把有争议的行为锁死
- rule-bb18dbce9560｜台账自动批准时，标「替代形态待批」「待查证」的条目保留 pending，不落成具体替代方案｜读到：规格里某个 PD 条目写着「替代形态待批（候选：…，grill 拍板）」或「待查证」；写错：决策台账在无人值守自动批准下，把它直接写成某个具体替代方案并标 approved，没有要求实现前做平台验证
