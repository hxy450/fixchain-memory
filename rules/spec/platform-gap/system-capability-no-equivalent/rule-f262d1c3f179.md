# 源码笔记写「SDK 无某枚举成员」前按成员名搜或读完整枚举体，和规格 AC 冲突时复查

审的是：规格
触发（任一种）：
- 读到：规格 AC 要求映射到某个 SDK 成员（如音源 CAMCORDER、编码 HEVC）；写错的样子：source-notes 写「AudioSourceType 无 CAMCORDER/UNPROCESSED」「无 HEVC 录制枚举」这类缺失结论，和 AC 冲突却没有按成员名复查的记录
适用范围：写源码理解笔记、平台差异时对 SDK 枚举或接口成员下「不存在」结论
做法：
- 下「不存在」结论前，按成员名在 d.ts 里搜（如 grep -n 'CAMCORDER\|HEVC'），或读完整枚举体到闭合括号；固定字符窗口、head、sed +N 截断的结果只证明看到了哪些成员
- 和规格映射要求冲突时先按成员名定向复查，确认确实缺失后再记为平台差异
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- AUDIO_SOURCE_TYPE_CAMCORDER = 13（@since 12）：AudioSourceType 里有 CAMCORDER（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，media.AudioSourceType.AUDIO_SOURCE_TYPE_CAMCORDER）
- VIDEO_HEVC = 'video/hevc'：CodecMimeType 里有 HEVC（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，media.CodecMimeType.VIDEO_HEVC）
- CAMCORDER 在 AudioSourceType 起点后约 1625 字符、VIDEO_HEVC 在 CodecMimeType 起点后约 3413 字符，1600 / 2600 字符的窗口都截不到：截断扫描为什么会漏（出处：卡里修好并验证过）
