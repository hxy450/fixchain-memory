# 写「目标平台无对等 / 不迁移」前先在 SDK 声明里按能力名检索，结果写进决策证据

审的是：规格
触发（任一种）：
- 读到：源端用 PictureInPictureParams、setAutoEnterEnabled、onUserLeaveHint、onPictureInPictureModeChanged 这类系统窗口能力；写错的样子：页面规格、feature-base 或决策台账写「HarmonyOS 无等价 API / 不迁移（恒 false）」，没有检索证据，也没标 [待验证]
适用范围：规格提取时判定源端系统能力在目标平台有没有对等 API 的条目
做法：
- 先在鸿蒙 SDK 的 ets/api 声明目录按能力名检索（画中画查 @ohos.PiPWindow.d.ts、isPiPEnabled、setAutoStartEnabled），把检索词和结果（模块名、@since、syscap）写进决策证据
- 查不到时标 [待验证] 交决策，不写成定论
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- namespace PiPWindow，@since 12，syscap SystemCapability.Window.SessionManager：鸿蒙有公开的画中画模块（出处：鸿蒙 SDK 的 ets/api/@ohos.PiPWindow.d.ts，PiPWindow）
- function isPiPEnabled(): boolean：当前系统是否支持画中画，可作为设置项可用性判定（出处：鸿蒙 SDK 的 ets/api/@ohos.PiPWindow.d.ts，PiPWindow.isPiPEnabled）
- 修复时在本机 SDK 找到 @ohos.PiPWindow.d.ts 并接入画中画：「无对等」的判定是未经检索的推断（出处：卡里修好并验证过）
