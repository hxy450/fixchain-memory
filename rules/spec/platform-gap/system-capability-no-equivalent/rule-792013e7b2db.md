# 决策台账写「平台无对等」前先检索 SDK 声明，把命中接口和弃用、权限标注写进平台约束

审的是：规格
触发（任一种）：
- 读到：源端功能依赖系统级能力（如 dynamicLightColorScheme / dynamicDarkColorScheme 壁纸取色），模板要求 HARD-DIV 的依据是 SDK d.ts 注释并禁止凭记忆；写错的样子：决策台账的 HARD-DIV / 降级条目写「平台约束：HarmonyOS 无 X API 对等（无 d.ts 能力条款）」，没有检索词、没有命中的 d.ts，自批 approved
适用范围：规格提取和决策登记阶段，判定源端系统能力在 HarmonyOS 有无对等接口时
做法：
- 在工程 local.properties 的 hwsdk.dir 下检索 openharmony/ets/api、hms/ets/api 和 kits 导出，用能力关键词找最接近的接口；把命中的 d.ts 及其 @deprecated、@systemapi、@permission 标注写进「平台约束」；检索为空时写明检索词和路径
- 最接近的只剩已弃用的公开接口（替代接口仅系统可用）时，写出弃用风险、失败回退和真机验证项，让审批在「降级」和「弃用接口 + 回退」之间选，不写成「平台无对等」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getColors(wallpaperType: WallpaperType): Promise<Array<RgbaColor>>（另有 AsyncCallback 重载），@since 7，@deprecated since 9：例：壁纸取色在公开 SDK 里有入口，只是已弃用（出处：鸿蒙 SDK 的 ets/api/@ohos.wallpaper.d.ts，wallpaper.getColors）
- on(type: 'colorChange', callback: (colors: Array<RgbaColor>, wallpaperType: WallpaperType) => void): void，@deprecated since 9：例：壁纸主色变化的监听（出处：鸿蒙 SDK 的 ets/api/@ohos.wallpaper.d.ts，wallpaper.on('colorChange')）
- @kit.BasicServicesKit 导出 wallpaper（import wallpaper from '@ohos.wallpaper'）：kits 导出里也能检索到这个模块（出处：鸿蒙 SDK 的 ets/kits/@kit.BasicServicesKit.d.ts，wallpaper）
针对本应用要查的：
- 这项能力最接近的鸿蒙接口：鸿蒙 SDK 的 openharmony/ets/api、hms/ets/api 下的 .d.ts 和 ets/kits 的导出，按能力关键词全文搜（例：取色搜 wallpaper、getColors、colorChange、theme）；读出接口签名和 @since、@deprecated、@systemapi、@permission，原样写进平台约束
未核实：getColors 自 API 9 弃用，在其他设备和后续版本上是否可用未知
