# 源端数值格式化没传 Locale 时，规格写「默认 Locale = 应用语言」，不改写成系统 Locale

审的是：规格
触发（任一种）：
- 读到：源端 new DecimalFormat(",##0.00")、NumberFormat 或 String.format 没有显式传 Locale，分组符和小数点取 Locale.getDefault()；写错的样子：规格的映射行或验收写「分组符/小数点取系统 Locale」「千位分组随系统 Locale」，把默认 Locale 写成了系统区域
适用范围：规格提取阶段为数字、金额、时长等格式化定区域来源时
做法：
- 映射写「Locale.getDefault() = 应用语言（未设置应用语言时为系统语言）→ 目标取 i18n.System.getAppPreferredLanguage()」
- 验收补一条判例：系统语言英语、应用语言德语时，小数点显示为逗号
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- DecimalFormat(String pattern) 用默认 FORMAT locale 的符号：源端没传 Locale 时分组符、小数点来自默认 locale（出处：java.text.DecimalFormat#DecimalFormat(String)）
- 安卓设置了应用语言（per-app locale）时，Locale.getDefault() 是应用语言而不是系统区域：源端「默认 Locale」的真实含义（出处：卡里修好并验证过）
- static getAppPreferredLanguage(): string：i18n.System 上取应用偏好语言（出处：鸿蒙 SDK 的 ets/api/@ohos.i18n.d.ts，System.getAppPreferredLanguage）
