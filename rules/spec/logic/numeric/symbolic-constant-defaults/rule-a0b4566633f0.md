# 源端默认值写的是符号常量时，规格先查到 const val 定义再填数，查不到写符号名标待核

审的是：规格
触发（任一种）：
- 读到：Room 实体 @PrimaryKey(autoGenerate = true) var id: Long = 某个大写常量，或 SharedPreferences.getLong(key, 某个大写常量)：默认值是引用别的文件里 const val 的符号，不是字面量；写错的样子：规格表的默认值、偏好缺省值一栏写成 -1 这类具体数，没有注明取自哪个常量定义，和源定义的值不一致
适用范围：规格提取阶段把源码里用符号常量表达的实体字段默认值、偏好缺省值落成具体数值时
做法：
- 先 grep `const val <常量名>` 找到定义，取实际值写进规格表，并写上常量名；没解析到定义时写常量名并标「待核」，不按「未设置 = -1」的习惯填数
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- long getLong(String key, long defValue)：defValue 是该键不存在时返回的值：偏好缺省值就是调用处第二个参数，它是符号时要去定义处取值（出处：android.content.SharedPreferences#getLong）
- Room autoGenerate 主键以 0 表示未分配：主键哨兵常见是 0，不是 -1；仍以源定义为准（出处：卡里修好并验证过）
针对本应用要查的：
- 符号常量的实际值：源工程 Kotlin/Java 源码：全文搜 `const val <常量名>` 或 `static final … <常量名>`，常在数据库类、companion object 或常量文件里；读等号右边的字面量；它若又引用别的常量就继续往下找到字面量为止
未核实：Room autoGenerate 以 0 表示未分配按卡写，本机只有 room-common 的编译产物
