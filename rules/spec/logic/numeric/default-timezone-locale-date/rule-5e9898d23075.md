# 源端格式化固定 epoch 时刻探测偏移时，规格用 getOffset(该时刻)，不用 getRawOffset

审的是：规格
触发（任一种）：
- 读到：源码在 SimpleDateFormat 构造后格式化一个固定的 epoch 时刻（如 60000 ms，即 1970-01-01T00:01Z），按结果的小时位前缀（如 23、01）判定偏移；写错的样子：规格把这个探测写成当前的 getRawOffset()，或断言 rawOffset 与 1970 年那一刻的本地小时位等价、历史或夏令时差异可以忽略
适用范围：源端用格式化固定历史时刻来探测时区偏移、规格要把它翻译成显式算术时
做法：
- 契约写成 offset = tz.getOffset(探测时刻的毫秒值)（如 tz.getOffset(60000)），tz 为构造时取得的 i18n.getTimeZone()；用这个偏移算出该时刻的本地小时位，再照源端的前缀判定
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getOffset(date?: number): number：按指定毫秒时刻求偏移（毫秒），含夏令时（出处：鸿蒙 SDK 的 ets/api/@ohos.i18n.d.ts，TimeZone.getOffset）
- getRawOffset(): number：时区的原始偏移（毫秒），不随时刻变，不含夏令时和历史变更（出处：鸿蒙 SDK 的 ets/api/@ohos.i18n.d.ts，TimeZone.getRawOffset）
- java.util.TimeZone#getOffset(long date) 在实现支持时返回历史上正确的偏移：源端格式化 1970 年时刻用的是那一刻的历史偏移（出处：java.util.TimeZone#getOffset）
- Europe/London 1970 年偏移为 +1，和现在的 rawOffset 不同，用当前 rawOffset 会判错：1970 年偏移与现在不同的时区的例子（出处：卡里修好并验证过）
未核实：Europe/London 下两端一致未上机，按卡里推算
