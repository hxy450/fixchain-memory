# 平台限制文件名时规格保留源格式、只替换非法字符，改格式要有选择器实测证据

审的是：规格
触发（任一种）：
- 读到：源码建议文件名用 DateFormat.getDateTimeInstance(SHORT, SHORT, Locale.getDefault()) 格式化；页面规格写「文件名规则保留」；写错的样子：规格或决策台账把建议文件名改成固定格式（如 yyyy-MM-dd_HH-mm）并新开决策项，理由是选择器拒绝某些字符，但没有实测证据
适用范围：规格或决策台账处理导出、备份的建议文件名时
做法：
- 先保留源格式，只把非法字符替换掉（参照 Android 的 FAT 文件名合法化：控制字符和 " * / : < > ? \ | DEL 换成 _）
- 确需改格式时，先实测目标保存选择器（DocumentViewPicker.save 的 newFileNames）的行为，把证据写进决策
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- buildValidFatFilename 把非法字符换成 "_"；非法字符为 0x00–0x1F、'"'、'*'、'/'、':'、'<'、'>'、'?'、'\\'、'|'、0x7F：合法化的字符集（出处：android.os.FileUtils#buildValidFatFilename、android.os.FileUtils#isValidFatFilenameChar）
- DocumentSaveOptions.newFileNames?: Array<string>：要保存的文档名，不传时由用户输入：目标端建议文件名的传入处（出处：鸿蒙 SDK 的 ets/api/@ohos.file.picker.d.ts，picker.DocumentSaveOptions.newFileNames）
针对本应用要查的：
- 源格式在当前语言下会带出哪些非法字符：源工程生成建议文件名的代码（DateFormat 的样式和 Locale）；用目标语言环境格式化一次看结果；例：中文短日期常带 '/'、短时间带 ':'，这些换成 _
未核实：DocumentViewPicker.save 传入含 '/' 的 newFileNames 时的表现，卡里没有实测
