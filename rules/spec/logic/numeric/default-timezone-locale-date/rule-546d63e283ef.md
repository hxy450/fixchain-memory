# SimpleDateFormat 未 setTimeZone 格式化毫秒值时，规格按时刻加默认时区偏移写契约

审的是：规格
触发（任一种）：
- 读到：源码 new SimpleDateFormat(pattern, Locale)、GregorianCalendar 或 Calendar.getInstance() 没有调用 setTimeZone，format(...) 作用在一个毫秒值上（变量名或用途看起来像时长也一样）；写错的样子：规格的实现映射或算法说明写成「纯时长格式化（手工 h/m/s + 补零）」「不经 Date/Intl」，对毫秒值直接拆时分秒，没写时区偏移
适用范围：把源端没有设时区的 Java 日期格式化或日历调用，翻译成目标端显式算术契约的那一节规格
做法：
- 契约写成 local = instant + tz.getOffset(instant)：tz 在源端 formatter 构造的时机用 i18n.getTimeZone() 取得并保存，instant 是交给 format 的毫秒值；再从 local 拆 HH/mm/ss 补零
- 规格里写明：「不用 Date/Intl」只是不用模板近似，不等于按 UTC 拆分；输入语义上是时长也按时刻在默认时区的本地字段处理
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- calendar = Calendar.getInstance(loc)（构造时创建，注释：the calendar should use the current default TimeZone）：SimpleDateFormat(pattern, locale) 构造时就绑定了当时的默认时区，没 setTimeZone 时 format 按它取本地字段（出处：java.text.SimpleDateFormat#initializeCalendar）
- GregorianCalendar() 等于 this(TimeZone.getDefaultRef(), Locale.getDefault(Locale.Category.FORMAT))：无参的 GregorianCalendar 也用默认时区（出处：java.util.GregorianCalendar#GregorianCalendar）
- function getTimeZone(zoneID?: string): TimeZone：不传 zoneID 时取系统时区（出处：鸿蒙 SDK 的 ets/api/@ohos.i18n.d.ts，i18n.getTimeZone）
- getOffset(date?: number): number：date 是毫秒时刻；返回该时刻相对 UTC 的偏移，单位毫秒，夏令时期间含夏令时偏移（出处：鸿蒙 SDK 的 ets/api/@ohos.i18n.d.ts，TimeZone.getOffset）
- 保存构造时的 i18n.getTimeZone()，显示前先加 timeZone.getOffset(时刻) 再拆时分秒，两端在 UTC+8 下对照一致：返修后的写法（出处：卡里修好并验证过）
未核实：卡里上机只对照了 UTC+8，其他时区的一致性按推算
