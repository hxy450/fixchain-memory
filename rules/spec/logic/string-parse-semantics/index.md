# 源端的字符串切分、正则和解码调用

agent 会看到什么：读到源方法体直接调 String.split / trim、正则、Base64.decode、Uri.parse，或用 split、下标、拼接解析深链和 URL（如 `"?" + x.split("?")[1]`）；规格只写口语描述，或服务层公式、验收条目和示例互相矛盾，把没有分隔符时的结果写成空串

## 规矩

- rule-80d9ee4b9a4c｜规格遇到平台库调用时，把迭代序、切分、正则引擎、舍入、解码容错写成契约｜读到：源方法体直接调 HashMap、String.split / trim、正则、(float) 运算、Base64.decode、Uri.parse、ContentResolver.getType；写错：规格只写口语描述（「拒绝 /data 前缀与 ../」「非空白字符数」「后继非纯数字词」「其余→file/*」），没写迭代序、分隔截断、正则引擎、浮点舍入、解码容错、未知值默认
- rule-a381e7a2637e｜解析类规格写完后，用几个具体输入手算源端输出，核对服务层、验收条目和示例一致｜读到：源端用 split、下标、字符串拼接或子串查找解析深链或 URL；写错：同一规格里服务层公式、验收条目文字和示例互相矛盾：有的条目照源写 `"?" + x.split("?")[1]`，服务层写守卫空串；示例写的结果和按源算出的不一样
- rule-d2873d36ec41｜源端用 '?' 加 split 结果拼查询串时，规格照写无分隔符时的字面 '?undefined'｜读到：源端 JS/TS 深链解析里写 `search: "?" + x.split("?")[1]` 这类拼接，没有判断分隔符是否存在；写错：规格的服务层契约写成 `x.indexOf('?') >= 0 ? '?' + x.split('?')[1] : ''`，或写「无 '?' → query ''」，同时又声称和源端逐字符等价
