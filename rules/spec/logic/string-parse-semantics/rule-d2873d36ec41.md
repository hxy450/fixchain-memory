# 源端用 '?' 加 split 结果拼查询串时，规格照写无分隔符时的字面 '?undefined'

审的是：规格
触发（任一种）：
- 读到：源端 JS/TS 深链解析里写 `search: "?" + x.split("?")[1]` 这类拼接，没有判断分隔符是否存在；写错的样子：规格的服务层契约写成 `x.indexOf('?') >= 0 ? '?' + x.split('?')[1] : ''`，或写「无 '?' → query ''」，同时又声称和源端逐字符等价
适用范围：规格提取阶段，把源端 JS/TS 的字符串解析（split、下标取值、字符串拼接）转写成目标解析函数的契约和验收条目时
做法：
- 逐表达式保留源端求值语义：契约和验收条目写明「x 不含 '?' 时 search 是字面串 '?undefined'」，不改写成存在性守卫或空串
- 确需修正源端行为时，另立一条决策条目并 supersede 原取向，不在服务层契约里悄悄规范化
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- "?" + x.split("?")[1] 在 x 不含 '?' 时得到字面串 "?undefined"：源端真值；按源真值写的单测断言它，守卫成空串的实现会测红（出处：卡里修好并验证过）
