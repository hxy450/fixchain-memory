# 源应用接口实现类覆写多个 on* 回调时，规格按 @Override 全集写清单项和 AC

审的是：规格
触发（任一种）：
- 读到：源端应用接口实现类继承一个各回调都是空默认实现的基类，在一段连续区域 @Override 多个 on 开头的错误/信息回调，各自 showToast 本地化提示；派工要求可枚举分支各单独成 AC；写错的样子：规格的服务层清单和 AC 只列了其中几个回调，其余 @Override 的错误回调既无清单项也无 AC，也没写明归属哪个 feature
适用范围：规格提取时，从继承空默认基类的源实现类清点需覆写的 on* 错误/信息回调
做法：
- 按 @Override 逐方法清点，服务层清单和 AC 覆盖全部 on* 错误/信息回调，每项写「回调 → 提示用的资源键或拼接规则」
- 最小检查：源文件 @Override 方法名与规格服务层方法名做差集，非空就补 AC 或写明归属哪个 feature
针对本应用要查的：
- 源实现类覆写了哪些 on* 回调、各自提示什么：源工程里实现应用接口的那个 Java/Kotlin 类，搜 @Override 和其后的 on 开头方法名；逐个读方法体里 showToast 用的 R.string 资源名或拼接逻辑，写进清单项和 AC
