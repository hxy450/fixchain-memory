# 源端只在 catch(OutOfMemoryError) 时报文件过大，规格写照常读取、捕获分配失败再提示

审的是：规格
触发（任一种）：
- 读到：源码只在 catch (OutOfMemoryError) 里提示文件过大，读之前没有任何大小阈值；写错的样子：映射表写成「读前长度预检（超阈值拒读并提示文件过大）+ try/catch 兜底」，并以「纯语言构造」为依据新增大小上限
适用范围：源端靠内存耗尽异常兜底「文件过大」的读文件路径，规格里的映射行和 AC
做法：
- 映射写「照常读取；捕获目标平台的分配失败（如 RangeError）再给源端同一条文件过大提示」，不写读前大小阈值
- 确需上限时，在规格里登记为有意偏离，写明数值和它的来源
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 不设读前大小上限，只在 RangeError 时报文件过大：和源端「先读、内存耗尽才报错」一致的映射（出处：卡里修好并验证过）
