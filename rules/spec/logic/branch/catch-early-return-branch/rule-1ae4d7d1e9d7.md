# 源码条件含 &&/|| 混排、未赋值元素或提前 return 时，AC 按源码实际结果写

审的是：规格
触发（任一种）：
- 读到：Java 源码里有未加括号的 `a && (…) || (…) || (…)` 混排、数组元素没赋值就使用（NullPointerException 被 catch 后返回 false）、格式错误时 Toast 后提前 return 的分支；写错的样子：AC 按注释或通用真值表概括（如「三组态真值归某功能」「HashSet 语义去重」「响应式等价」），没有源码锚点、触发条件和原结果
适用范围：规格提取时，把 Java 源码的条件表达式、异常分支和失败分支写进验收条目（AC）
做法：
- 每条 AC 写成「源码锚点（类#方法和那段表达式）＋触发条件＋原结果＋目标预期」，结果按 Java 实际求值写（&& 先于 || 结合），不按注释、通用真值表或「响应式等价」概括
- 源码有缺陷但结果可观察的（未赋值元素引发 NPE 后返回 false、失败分支提前 return 后列表不重建），AC 写原结果并标明保留
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- `c1 == 0 && (A) || (B) || (C)` 按 `(c1 == 0 && A) || B || C` 求值，c1 只约束第一组：未加括号的混排表达式，前置条件只管第一个析取项（出处：卡里修好并验证过）
