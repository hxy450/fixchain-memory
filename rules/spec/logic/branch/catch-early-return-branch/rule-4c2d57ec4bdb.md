# 规格总结源端循环的错误处理时，把抛异常和返回 null 分开写传播范围

审的是：规格
触发（任一种）：
- 读到：源端循环里有一步可能抛异常（如解密）且没有逐条 catch，异常落到外层 catch；另一步返回 null 时推进游标并 continue；写错的样子：验收条目把「解密失败 / 解析为 null」合并成同一个 continue 分支，写「推进时间戳、不中断整批」
适用范围：规格提取阶段总结源端循环或批次的错误处理时
做法：
- 按「抛异常」和「返回 null / 失败值」分开写：抛异常时写明被哪一层 catch 接住、是否中断整批、是否推进游标；只有 null 分支才写推进游标并 continue
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 解密异常中断整批，只有解析为 null 才推进时间戳并 continue：修复后按源码恢复的语义（出处：卡里修好并验证过）
针对本应用要查的：
- 循环里每一步失败后的去向：源工程对应函数的循环体和外层 try / catch；逐个调用看有没有逐条 try，没有的就找接住它的外层 catch；看返回 null 的分支是否推进游标再 continue
