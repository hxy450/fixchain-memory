# 源码注释说无匹配交给常规路由时，规格只按实际判断写跳转门槛，不加注册路由过滤

审的是：规格
触发（任一种）：
- 读到：源端深链处理只有 `if (x)` 真值判断就 `history.push(...)`，旁边注释写 'If no match, do nothing - let regular routing logic take over'；写错的样子：规格的验收条目写「为空或未注册路径 → 不 push，resolve 返回 null」，在解析函数里新增注册路由过滤
适用范围：规格提取阶段，把源端深链或 URL 解析后的跳转条件写成解析函数的返回条件时
做法：
- 跳转门槛以实际判断表达式为准：只有 x 为空时解析函数返回 null，任何非空 x 都产出路由结果
- 源码注释说明的兜底写进契约的分发一节：未注册路径由路由层处理（写明有没有 catch-all），不写成解析函数返回 null
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 仅 x 为空返回 null；未注册路径时解析结果非 null，由壳的分发分支不匹配而不跳转：修好后解析函数和壳的分工（出处：卡里修好并验证过）
