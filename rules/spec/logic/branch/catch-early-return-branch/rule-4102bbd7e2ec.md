# 转写源码错误处理分支时，AC 按运行时会抛的异常和实际结局写，不写成兜底继续

审的是：规格
触发（任一种）：
- 读到：Java 源码只 `catch (IOException e)`，try 里却有 Gson 解析（抛 JsonSyntaxException）；`findFile(...)` 的返回值直接 `.exists()`；`R.string.x + ": " + e.getMessage()` 把资源 int 与字符串相加；写错的样子：AC 写「读取/解析失败兜底：返回空对象（不崩溃），任务继续处理其余文件」「目录缺失整体返回 false，进程不崩溃」「不复制崩溃行为」「源码现状兜底」，或把资源 id 拼接写成文案拼接，且没有引 PD-/D- 决策 ID
适用范围：规格提取时转写源码的异常处理、null 解引用和错误提示分支
做法：
- 按运行时语义而非 catch 子句字面写：先列出该路径会抛出的未检查异常（不在 catch 类型里的解析异常、返回 null 后解引用的 NPE）和实际结局（任务在此终止、已导入的保留、进行中的通知残留、提示里显示资源 id 数字），再写 AC
- 要写成「不崩溃/继续」的，AC 里必须引对应的 PD-/D- 决策 ID 作锚，不写「源码现状兜底」「不复制崩溃行为」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Gson 的 JsonSyntaxException 不在 catch (IOException) 范围内；findFile 返回 null 后解引用抛 NPE；两者都使导入任务在该处终止：AC 里该写的实际结局（出处：卡里修好并验证过）
