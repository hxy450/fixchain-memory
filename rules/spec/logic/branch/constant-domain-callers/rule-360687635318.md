# 功能规格写对接点参数时，从该 UI 的实际调用处取值，不套别的流程

审的是：规格
触发（任一种）：
- 读到：源码里同一函数有两类调用：UI 处用默认参数，另一流程（如失效恢复）显式传了非默认值；写错的样子：规格「对接点」一节写的参数取自另一流程（如把恢复流程的 true 套到 UI 的退出操作上），和该 UI 的实际调用不符
适用范围：功能规格写 UI 组件和 ViewModel/Store 的对接点时
做法：
- 对接点里每个参数从该 UI 的实际调用处取值；调用处没传的写函数默认值，并注明取自哪个调用
针对本应用要查的：
- 这个 UI 操作实际怎么调用：源工程里该 UI 组件的点击回调（传给组件的 lambda）调用目标函数的那一行，以及目标函数声明里的默认参数；读出调用处实际传的参数，没传的取声明里的默认值
