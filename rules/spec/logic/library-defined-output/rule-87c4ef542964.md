# 产出持久化或展示字符串的算法库，映射行写库输出的字面契约或登记 PD-*

审的是：规格
触发（任一种）：
- 读到：源工程依赖里有 RRULE 解析与序列化、重复文案、相对时间、日期格式这类算法库（如 org.mnode.ical4j:ical4j、org.ocpsoft.prettytime:prettytime），源码用 RRule.toString()、PrettyTime.format() 产出要存库或显示的串；写错的样子：跨栈映射行只写「自研 / tiny RRULE 解析（RFC5545 子集）」「@ohos.i18n intl 相对时间或自研」并标 Auto / Semi-Auto，没写库输出的字面格式，标了 Manual 也没转成 PD-*
适用范围：规格提取阶段给目标端没有同名库的算法型第三方依赖写映射行和功能 spec 算法节时
做法：
- 用本机 Gradle 缓存里该版本的 jar（或 JDK 小程序）跑代表输入，取真实输出，把字面格式写成契约字段：UNTIL 的时区形态和是否带 CRLF、文案模板、单位阈值和取整规则
- 取不到真值、或决定不移植时，按三方依赖无等价物的策略登记 PD-* 交用户改判，不在映射行里直接写定替代方向
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- ical4j 的 RRule.toString() 产出「FREQ=<F>;UNTIL=<设备时区 yyyyMMddTHHmmss>\r\n」，UNTIL 是设备时区浮动时间、末尾带 CRLF：持久化串的字面形态，用 jar 对拍确认（出处：卡里修好并验证过）
针对本应用要查的：
- 算法库的版本和代表输入下的真实输出：源工程模块构建脚本里的依赖坐标和版本；本机 Gradle 缓存 modules-2/files-2.1/<group>/<artifact>/<version>/ 下的 jar；按依赖版本取 jar，用 JDK 小程序以源码里的实参调用（如 new RRule(recur).toString()、PrettyTime.format(date)），把输出逐字写进契约
