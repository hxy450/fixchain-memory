# 映射表把同步调用换成 Promise 形且服务层是 void 时，规格写明连续调用的串行要求和可单测判据

审的是：规格
触发（任一种）：
- 读到：源端同一方法里依次同步调用两个平台方法且后者依赖前者生效（如 `Vibrator.cancel()` 后紧接 `vibrate(...)`）；写错的样子：规格的映射表把对应目标 API 标为「Promise 形」、服务层把方法声明为 void，契约里却没写「前一调用完成后才发后一调用」，对应验收条目也没有可单测的判据
适用范围：规格提取阶段，源端连续同步平台调用映射成返回 Promise 的目标 API 时，规格的契约和验收条目
做法：
- 在契约里写出串行要求，例如「cancel 完成后才发 pattern」，写明是生效顺序而不只是调用点顺序
- 给对应验收条目加可单测的判据：注入一个延迟完成的假 stop，断言 pattern 在 stop 完成之后才发出
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function stopVibration(): Promise<void>：目标端停止振动是异步的，规格里不能把它当成同步的 cancel（出处：鸿蒙 SDK 的 ets/api/@ohos.vibrator.d.ts，vibrator.stopVibration）
- function startVibration(effect: VibrateEffect, attribute: VibrateAttribute): Promise<void>：目标端发起振动也是异步的（出处：鸿蒙 SDK 的 ets/api/@ohos.vibrator.d.ts，vibrator.startVibration）
未核实：鸿蒙模拟器没有振动器，未实测到截断
