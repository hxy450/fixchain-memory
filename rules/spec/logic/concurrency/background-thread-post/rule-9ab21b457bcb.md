# 按次数核对结算弹窗前先数同时存活的循环实例，规格里弹窗写成按出现顺序叠放的列表

审的是：规格
触发（任一种）：
- 读到：循环线程判负后每帧 post 结算弹窗、出循环后再 post 另一个弹窗，弹窗按钮直接重开新循环而不关已有弹窗；写错的样子：规格只给页面设两个布尔旗（won / lost 各一个 visible），AC 写「两个弹窗状态复位」，没有多实例下弹窗叠加的结构和验收
适用范围：规格里核对由循环线程投递的对话框个数与叠放顺序时
做法：
- 次数＝每个实例的投递次数×存活实例数：先列出各操作序列（如重开后仍留在下面的对话框再点重开）下有几个实例在跑、各自投递什么
- 规格把结算对话框写成按出现顺序叠放的列表，并补一条验收：新关卡后再点底下对话框的重开，两循环并存、弹窗持续叠加
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 安卓实测：普通判负弹 1~2 个判负对话框再叠胜利对话框；多循环并存时判负对话框无限叠加：单循环下弹窗个数与多循环下不同（出处：卡里修好并验证过）
