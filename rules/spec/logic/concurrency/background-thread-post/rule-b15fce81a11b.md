# 源码后台线程完成后无条件回投 UI 时，规格写结果照常处理，不写丢弃迟到结果

审的是：规格
触发（任一种）：
- 读到：源码新线程做完后无条件 mHandler.post(...) 回 UI，被回投的方法里没有 isFinishing() / isDestroyed() 判断，直接 Toast、startActivity、finish；写错的样子：规格的竞态或顺序条目、验收条目写「读取期间返回（页面销毁）→ 迟到的完成回调必须丢弃，不写 UI、不路由下一页」这类源码里没有的守卫
适用范围：规格提取阶段写顺序、取消、竞态不变式和对应验收条目时，源端是后台线程加 Handler 回投
做法：
- 按源码实际行为写：规格里写明「页面结束后，后台任务完成时的 Toast、打开下一页与 finish 照常发生」，不用「页面销毁应丢弃迟到结果」的通用防御代替
- 认为确需偏离源码时，登记为有意偏离（写进决策台账）供裁决，不直接写成不变式或验收条目
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Handler.post(Runnable) 把 Runnable 加进消息队列，在 Handler 所在线程上运行：回投本身不检查 Activity 是否已结束，守卫只能来自回调里的显式判断（出处：android.os.Handler#post）
- 迟到结果照常 Toast 并打开下一页后，行为与源一致：修复后的做法：页面结束只做标记，不丢结果（出处：卡里修好并验证过）
