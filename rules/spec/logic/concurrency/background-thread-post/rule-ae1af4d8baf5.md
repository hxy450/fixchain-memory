# 源端字段在后台线程里写、调用方随后又同步写时，规格按实际生效顺序推导可观察结果

审的是：规格
触发（任一种）：
- 读到：源端方法在 new Thread、Handler.post 或异步回调里成功后写某个字段，调用方发起它之后紧接着在主线程同步写同一字段；写错的样子：规格按代码书写顺序写可观察结果（如「先跳回该项并清零，否则退出」），验收也按这个顺序写，没考虑后台写落在调用方后续语句之后
适用范围：规格提取阶段，翻译源端后台线程或 post 回调里写入的状态和相关验收时
做法：
- 凡在 Thread、Handler.post 或异步回调里写的字段，先查调用方发起后是否还同步写同一字段；有的话最终值是后台写的那个，按这个生效顺序推导可观察结果再写验收
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Handler.post：把 Runnable 加进消息队列，在 handler 所在线程上执行：post 的回调在调用方当前这段代码跑完之后才执行，回调里的写晚于调用方后续的同步写（出处：android.os.Handler#post）
- 后台线程里的写总晚于主线程随后的置 0，返回键在两项之间来回切换：源端的实际可观察行为（出处：卡里修好并验证过）
针对本应用要查的：
- 异步体里写了哪些字段、调用方随后有没有再写：源工程里这个方法的函数体（new Thread / Handler.post / 回调里的赋值），以及所有调用处发起调用后的语句；同一字段两处都写的，记下后台那次在后，最终值取后台写的值
