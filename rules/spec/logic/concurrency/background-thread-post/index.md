# 后台线程回投 UI 和单线程执行器

agent 会看到什么：读到源码新开 Thread 或循环线程做完后 Handler.post / runOnUiThread 回 UI（不判 isFinishing、每帧都 post 弹窗），或单线程执行器在执行线程内直接内联运行；规格的竞态条目、弹窗状态和验收条目写成丢弃迟到结果、两个布尔旗、只验提交顺序

## 规矩

- rule-b15fce81a11b｜源码后台线程完成后无条件回投 UI 时，规格写结果照常处理，不写丢弃迟到结果｜读到：源码新线程做完后无条件 mHandler.post(...) 回 UI，被回投的方法里没有 isFinishing() / isDestroyed() 判断，直接 Toast、startActivity、finish；写错：规格的竞态或顺序条目、验收条目写「读取期间返回（页面销毁）→ 迟到的完成回调必须丢弃，不写 UI、不路由下一页」这类源码里没有的守卫
- rule-9ab21b457bcb｜按次数核对结算弹窗前先数同时存活的循环实例，规格里弹窗写成按出现顺序叠放的列表｜读到：循环线程判负后每帧 post 结算弹窗、出循环后再 post 另一个弹窗，弹窗按钮直接重开新循环而不关已有弹窗；写错：规格只给页面设两个布尔旗（won / lost 各一个 visible），AC 写「两个弹窗状态复位」，没有多实例下弹窗叠加的结构和验收
- rule-b83e3cd8bb8d｜串行写执行契约的验收条目除提交顺序外，还要有任务内嵌套写能完成的一条｜读到：源端写执行器有「调用方已在执行线程则同步内联、不再排队」的重入分支；写错：规格的验收条目只写「并发提交 N 个写任务后结果等于某串行顺序」，没有覆盖重入分支：队列任务内调用另一个写方法、外层 Promise 能完成
- rule-ae1af4d8baf5｜源端字段在后台线程里写、调用方随后又同步写时，规格按实际生效顺序推导可观察结果｜读到：源端方法在 new Thread、Handler.post 或异步回调里成功后写某个字段，调用方发起它之后紧接着在主线程同步写同一字段；写错：规格按代码书写顺序写可观察结果（如「先跳回该项并清零，否则退出」），验收也按这个顺序写，没考虑后台写落在调用方后续语句之后
- rule-f62fd41c6531｜源端后台工作映射成目标同步调用时，契约列出异步体与调用方都写的字段，写明调用方的写挪到前面｜读到：源端方法在后台线程成功后写字段，调用方发起后又同步写同一字段；写错：实现映射把这个方法定为事件循环内同步顺序执行，称单线程「天然消除」源端竞争，没列出两处都写的字段，也没写调用方的写要挪到同步调用之前
- rule-ed05c7e868b9｜返回、撤销、重试这类可重复操作的验收，连续写第 1、2、3 次的结果和不同起点｜读到：源端返回、撤销、重试的处理里有后台线程写入参与；写错：验收只断言第一次操作的结果（如「返回回到上一项，再返回退出」），没有逐次写第 1、2、3 次，也没区分重试后、切换后这类起点
