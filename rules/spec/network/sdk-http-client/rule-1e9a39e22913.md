# SDK 装了 HttpTimeout 等插件时，规格写 SDK 的超时重试，不用应用 OkHttp 配置

审的是：规格
触发（任一种）：
- 读到：应用的 Http 包装层只给 OkHttp 配了超时，再通过 SDK 的默认客户端配置把引擎交给 SDK；SDK 自己创建 HttpClient 时装了 HttpTimeout、HttpRequestRetry，设了 expectSuccess；写错的样子：规格的客户端契约只写应用包装层的超时（如「预配 OkHttp：30s 超时」），没有 SDK 自身的请求 / socket / 连接三类超时、重试次数和触发条件、expectSuccess
适用范围：要手写客户端替代三方 HTTP SDK 时，规格里写客户端策略的那一节
做法：
- 把 SDK 创建 HttpClient 的配置文件列为必读，逐项写进契约：HttpTimeout 的请求、socket、连接三类超时各多少；HttpRequestRetry 重试几次、对哪些响应和异常重试；expectSuccess 是否开启
- 应用包装层的配置（OkHttp 超时、日志、UserAgent）只记为引擎配置，不代替 SDK 自身的策略
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 修好后按 SDK 重写截止时间模型和分类超时，并对 5xx 重试：契约里写全了 SDK 的超时和重试，实现才能照做（出处：卡里修好并验证过）
针对本应用要查的：
- SDK 自身的超时、重试和 expectSuccess：三方 SDK 源码里创建 HttpClient 的那个文件，看 install(HttpTimeout)、install(HttpRequestRetry) 块和 expectSuccess；没有源码时用 javap 看字节码里的常量；读出三类超时的毫秒数、重试次数和重试条件。例：卡里那个 SDK 是请求 20s、socket 20s、连接 10s，5xx 与非超时异常重试 5 次
未核实：例子里的超时和重试数值来自修复期 javap，生成材料里没有原文可复核
