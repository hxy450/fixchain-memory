# SDK 按服务端版本分路由时，端点下限取最早出现的版本，minor 分支写成 x.y.x

审的是：规格
触发（任一种）：
- 读到：SDK 的版本路由代码：宽松 semver 解析服务端版本，按 minor 分到各版本路由表，不支持的 minor 抛不支持异常，另有 MIN_SUPPORTED_VERSION 一类常量；写错的样子：规格把整个 minor 的分支写成单个补丁号、写「未知版本落最新分支」、省略解析规则，或无门控的端点下限一律写成最新大版本
适用范围：要手写客户端替代三方 HTTP SDK、SDK 支持多个服务端版本时，规格里的版本路由和端点版本下限
做法：
- 端点版本下限取它在 SDK 各版本路由表中最早出现的版本，再和决策账本的版本范围核对
- 版本路由写清：解析规则（如宽松 semver、major/minor 校验）；覆盖整个 minor 的分支写成 0.18.x 这种；不支持的 minor 照 SDK 处理（如抛不支持异常），不写「未知版本落最新分支」
- 旧版本适配器的鉴权方式（如鉴权放在表单里）、字段白名单和响应转换也写进契约
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 修好后版本路由改为宽松 semver 并做 major/minor 校验，端点下限降到旧 minor 的起始版本：旧版本服务端的端点恢复可用（出处：卡里修好并验证过）
针对本应用要查的：
- 各端点在哪些服务端版本可用、版本怎么解析和分支：三方 SDK 源码里的版本路由入口（按版本选路由表的函数和最低支持版本常量）以及各版本的路由接口文件；读出解析函数和分支条件；把每个端点在各版本路由表里出现与否列出来，取最早出现的版本作下限
