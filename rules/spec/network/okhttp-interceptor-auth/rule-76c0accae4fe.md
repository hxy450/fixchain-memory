# 规格写鉴权失效判定时，按源端响应拦截器的分支写「码→动作」表，不拿错误码枚举举例

审的是：规格
触发（任一种）：
- 读到：源端 OkHttp 响应拦截器按响应体错误码分支踢登，错误码枚举里同时有多个登录过期、token 为空、过期、无效、异地登录类成员；写错的样子：规格里写「401/某码 刷新」或「对应错误码枚举（某码 登录过期…）」当作失效条件，没有「码→动作」表、没写出自哪个拦截器
适用范围：规格提取阶段写网络层的鉴权失效判定时
做法：
- 读源端响应拦截器实际 switch / when 的错误码和每个分支的后续动作，规格里写成「码→动作」表（哪些码发 token 失效踢登、哪些码按异地登录踢登），标明出自哪个拦截器
针对本应用要查的：
- 触发踢登或刷新的错误码集合，以及每个码的动作：源工程里实现 okhttp3.Interceptor 的响应拦截器类（处理错误、处理 token 的那几个）的 intercept 方法，看它对响应体错误码的 switch / when 分支；每个分支读出码值（引用枚举的，到枚举定义读数值）和后续动作（发登出事件、跳登录、异地登录提示、刷新），逐行填进「码→动作」表
未核实：卡里看到一例：错误码枚举里名为登录过期的成员属网关层、不在拦截器的踢登分支里；这是调查中读源码的观察，不是修好后验证的做法
