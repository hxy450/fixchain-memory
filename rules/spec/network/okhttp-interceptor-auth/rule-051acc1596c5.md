# 源端拦截器统一注入请求头时，规格逐项写出每个头的名称、取值来源和格式

审的是：规格
触发（任一种）：
- 读到：OkHttp 拦截器（Interceptor.intercept 里 Request.Builder.addHeader）给每个请求加鉴权、语言、平台、地区等头，接口声明上看不到；raw_apis 里该拦截器标了 header_write / token_injection；写错的样子：规格网络层只写「统一 token 注入」「统一平台头」，没有逐项列出公共请求头，也没写 Authorization 是直接放 token 还是带 Bearer 前缀
适用范围：规格提取阶段写网络基础层的公共请求头和鉴权格式时
做法：
- 直接读标了 header_write 或 token_injection 的拦截器源码，把每个 addHeader 的头名、取值来源（token、语言、平台常量、地区、调试开关）和格式逐项写进 feature-base，如「Authorization：直接放 token，不带 Bearer 前缀」
针对本应用要查的：
- 源端每个公共请求头的名称、取值和条件：源工程里实现 okhttp3.Interceptor 的类，按 addHeader / header 调用找；raw_apis 的 interceptors 条目给出它的路径；逐条抄下头名、值的来源和拼接格式，以及只在 DEBUG 等条件下才加的头
