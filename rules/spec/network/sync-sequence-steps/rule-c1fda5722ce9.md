# 同步链路的行为审计报告逐条写每个界面通知事件的发布位置和前置条件

审的是：规格
触发（任一种）：
- 读到：安卓同步代码里发进度 0、进度 100、失败等界面通知事件，有的带前置条件（如已登录且同步 cursor 为 0）；写错的样子：安卓行为审计的同步事实报告只列推拉顺序和触发入口，没逐条写进度 0、进度 100、失败各在哪发、前置条件是什么
适用范围：审计或源码理解阶段汇总安卓同步链路、供实现者照着改同步服务时
做法：
- 事实报告里给每个界面通知事件一行：事件（进度 0 / 进度 100 / 失败）→ 发布位置（哪个方法，开头、结束还是 finally）→ 前置条件（如「已登录且同步 cursor 为 0」）
针对本应用要查的：
- 每个通知事件的发布处和条件：源工程同步相关类里发布进度、失败事件的调用处；记下所在方法、在方法里的位置和外层 if 条件
