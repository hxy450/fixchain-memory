# API 规格里每个枚举字段分写线上形态和本地持久化形态，线上按 SDK 序列化取枚举名

审的是：规格
触发（任一种）：
- 读到：源端经第三方 SDK 的 kotlinx.serialization 数据类调 REST 接口，字段注释列出字符串字面量联合（如 "All" | "Local" | …）；同一枚举另以 .ordinal 存进 Room 列；写错的样子：请求通用约定写「枚举一律以 ordinal/int 上送」，接口页把 query 参数或请求字段标成「枚举 ordinal」/ Int
- 读到：源码里另有按 when 表排列的枚举映射；写错的样子：DB 序号列的顺序取自应用里的 when 表，没写 SDK 枚举的声明序
适用范围：API 规格提取时，为 SDK 封装的 REST 接口写枚举参数和字段的序列化形态
做法：
- 对每个枚举字段分开写「线上形态」和「本地持久化形态」：线上形态以 SDK 数据类与序列化器为准（kotlinx.serialization 默认按枚举名，@SerialName 覆盖），不从 Room 列的 .ordinal 或 toEnum() 推断
- SDK 字段注释已列出字符串字面量联合时，按字面量写进请求契约，并在请求通用约定里给一个带枚举参数的请求示例（query 里写枚举名）
- 确需 ordinal 的 DB 列，另列 SDK 枚举的声明序，不用应用内 when 表的顺序代替
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- ordinal()：枚举常量在声明中的位置，第一个常量为 0：DB 列里的序号按 SDK 枚举的声明顺序算（出处：java.lang.Enum#ordinal）
- name()：枚举常量的名字，即声明时用的标识符：按枚举名序列化时线上值就是它（出处：java.lang.Enum#name）
针对本应用要查的：
- 每个枚举在线上的字面量和声明顺序：源工程依赖的 API SDK 源码里的数据类（看字段注释的字符串联合）和枚举类定义（看 @SerialName 与声明顺序）；线上形态写枚举名或 @SerialName 的值；DB 序号按声明顺序从 0 数
