# 同步调度的规格写清源端每次触发怎么执行；目标单飞合并时写明运行中请求要尾随补跑

审的是：规格
触发（任一种）：
- 读到：源端每次同步触发都 scope.launch 新任务，在 Mutex.withLock 内先推送队列再拉取，不复用在途任务；写错的样子：规格写「并发触发复用当前任务」「全量同步、定向刷新共用一个 active task」，没写运行中到达的请求会触发尾随补跑
适用范围：规格提取阶段，迁移数据同步调度、确定多次触发的并发语义时
做法：
- 逐项写出源端每次触发如何执行：是否每次新建任务、是否在锁后排队、是否合并或丢弃
- 目标采用单飞合并时，契约写明运行中到达的请求触发尾随补跑，保证触发前入队的本地变更在该轮拉取之前被推送
- 已有规格与源码不一致时以源码为准，并回写规格
