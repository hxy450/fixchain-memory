# 功能调用跨模块端点时，规格的 API 表列上它，并写出不透明请求体的字段和取值来源

审的是：规格
触发（任一种）：
- 读到：源端功能代码经 ViewModel、Repository 调到别的模块的 Service 方法，该方法参数是 `@Body ... RequestBody`，请求体在调用方组装；写错的样子：规格的 API 表只列了本模块 Service 的端点，漏了本功能调用的跨模块端点；或者列了端点，但对 @Body RequestBody 这类不透明参数没写字段名和取值来源
适用范围：规格提取阶段写功能规格的 API 表时，本功能调用的所有端点（含其他模块提供的）
做法：
- API 表里把本功能调用的跨模块端点也列上，写明它在哪个模块的哪个 Service 方法
- 对不透明请求体参数，追到源端构造处，在该端点下逐项写「字段名 ← 取值来源（哪个工具方法或偏好项）」
针对本应用要查的：
- 本功能调用的跨模块端点及其请求体字段：源工程里功能模块的 ViewModel 调用的 Repository 方法（可能在公共模块），以及其中构造 RequestBody 的那一句；记下端点路径、所在模块的 Service 方法、每个字段名和取值来源，写进 API 表
未核实：没有核查规格作者的派工是否要求追到公共模块的 Repository
