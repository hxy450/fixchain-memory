# Compose TextStyle.lineHeight 映射到 ArkUI 时，规格写明单行语义差并标 HARD

审的是：规格
触发（任一种）：
- 读到：Compose Typography 的 TextStyle(…, fontSize = N.sp, lineHeight = M.sp, …)；d.ts 里只核到 Text 有 lineHeight(value: number | string | Resource)；写错的样子：映射表把 lineHeight.sp 直接写进统一 AttributeModifier 的 .lineHeight，契约写「sp → fp 1:1（依据 lineHeight(number)）」、难度「低」，没写单行文本盒高两端不同
适用范围：规格里为 Compose 排版令牌（TextStyle → 统一 AttributeModifier）写 Source→ArkTS 映射契约时
做法：
- 契约写明两端语义：Compose 单行文本盒高 = 字体自然高（ascent − descent），lineHeight 只作用于行与行之间；ArkUI .lineHeight 把包括单行在内的每一行都撑到该高度；这一行标为行为等价难点（HARD）
- 给出目标写法：.lineSpacing(LengthMetrics.vp(<行间距>), { onlyBetweenLines: true })，或只在多行段落上用 .lineHeight；验收条目写「单行 Text 的盒高与 Android dump 的盒高一致」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- lineHeight(value: number | string | Resource): TextAttribute；number 单位 fp，不大于 0 时不限制行高：ArkUI 的文本行高，同名同单位不等于行为等价（出处：鸿蒙 SDK 的 ets/component/text.d.ts，TextAttribute.lineHeight）
- lineSpacing(value: LengthMetrics, options?: LineSpacingOptions): TextAttribute（@since 20）：行间距，带 options 的重载（出处：鸿蒙 SDK 的 ets/component/text.d.ts，TextAttribute.lineSpacing）
- onlyBetweenLines 为 true 时行间距只在行与行之间，首行上方和尾行下方没有；默认 false，首行上方和尾行下方也有行间距：要写 { onlyBetweenLines: true } 才不撑高单行（出处：ts-text-common.md，LineSpacingOptions20+对象说明）
- bodyLarge 单行 ArkUI 28vp 对 Android ≈19dp；改成 lineSpacing onlyBetweenLines 加字体自然高后对上：两端单行盒高的实测差和修好后的结果（出处：卡里修好并验证过）
未核实：Compose 单行按字体自然高计高的机制（LineHeightStyle 的 Trim）卡里只核了实测，没核 Compose 源码
