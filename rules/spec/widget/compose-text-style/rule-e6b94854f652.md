# Compose Text 没显式写颜色或行高样式时，规格沿调用链查出实际取值，写成显式值

审的是：规格
触发（任一种）：
- 读到：Compose Text(...) 没传 color（颜色取 LocalContentColor），或 TextStyle 带 lineHeight 没设 lineHeightStyle；写错的样子：规格写「默认 onSurface」「未显式指定色 token」这类结论，或排版令牌只列字号、行高数值，没写解析到的取值，也没标待核
适用范围：规格提取阶段写 Compose 文本里没显式写出的外观属性时
做法：
- 颜色：沿调用链找最近的 Surface、Scaffold（含应用包装的这两类）或 CompositionLocalProvider(LocalContentColor provides …)，读出它提供的 contentColor，解析到主题颜色名写进规格
- 行高样式：没设 lineHeightStyle 的令牌写明「未设置（默认裁剪）；单行文本高度 = 字体自然高度，多行行距 = lineHeight − fontSize」
- 没核到取值来源时把这一项标成待核，不写成平台默认值
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- bodyLarge 单行 ArkUI 按 .lineHeight 直译是 28vp，Android ≈19dp；改成 lineSpacing onlyBetweenLines 加字体自然高后对上：例：没写单行语义时两端单行盒高的实测差（出处：卡里修好并验证过）
针对本应用要查的：
- 无色文本实际拿到的 contentColor：源工程 Kotlin 文件里这个页面外层的 Surface / Scaffold 调用，以及应用包装的 Scaffold、Surface 函数的参数默认值 contentColor = …；页面传了 contentColor 就取传入值，没传取包装函数参数的默认值，再解析到主题颜色名（例：包装 Scaffold 的 contentColor 默认取主题的次要文字色）
- 各排版令牌有没有设 lineHeightStyle：源工程里定义 Typography(...) 的 Kotlin 文件，逐个 TextStyle 看参数；读出 fontSize、lineHeight，以及 lineHeightStyle 有没有写、写的是什么
未核实：Compose 单行按字体自然高计高的机制（LineHeightStyle 的 Trim）卡里只核了实测，没核 Compose 源码；Text 其他没传的参数（如 style 取 LocalTextStyle）是否同样由宿主提供，族里规矩没有查实
