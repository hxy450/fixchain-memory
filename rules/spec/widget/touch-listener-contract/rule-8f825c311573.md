# 多个兄弟控件各自监听触摸时，触控契约写明分指、按控件内手指集合判首末指

审的是：规格
触发（任一种）：
- 读到：安卓源里多个兄弟 View（按钮等）各自 setOnTouchListener，监听里用未掩码的 getAction() 只认 ACTION_DOWN / ACTION_UP 驱动按住-释放；targetSdkVersion ≥ 11，且没写 android:splitMotionEvents="false"；写错的样子：规格的触控契约写成「touches.length>1 时非首指的 Down/Up 不进状态机」这类按全屏手指数过滤的说法，或者没写安卓按控件分指、每个控件只收落在自己身上的手指
适用范围：安卓多个兄弟控件各自监听触摸、迁成 ArkUI 每个控件各挂 .onTouch 时，规格里写触控契约的那一节
不适用的情形：只有单个视图独占全部手指（如整屏只有一个视图接收滑动）时，屏幕上的手指数才等于源端这个视图收到的指针数，按 touches.length 过滤才成立
做法：
- 触控契约里写明：源端多个控件各自监听且默认分指，每个控件只收自己的指针流；目标按控件内的手指 id 集合（取 changedTouches[0].id）判首指/末指，不以全屏 event.touches.length 过滤
- 契约里写出集合规则：集合为空时的 Down 算按下，Up 移除后集合为空才算抬起，Cancel 清空集合并抬起
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- touches: TouchObject[]：全部屏幕触点（多指）的信息，不是落在本控件上的手指（出处：鸿蒙 SDK 的 ets/component/common.d.ts，TouchEvent.touches；ts-universal-events-touch.md，TouchEvent对象说明）
- changedTouches: TouchObject[]：发生变化而产生这次事件的手指（出处：鸿蒙 SDK 的 ets/component/common.d.ts，TouchEvent.changedTouches）
- id: number：TouchObject 上的手指唯一标识，用它记本控件的手指集合（出处：鸿蒙 SDK 的 ets/component/common.d.ts，TouchObject.id）
- splitMotionEvents：HONEYCOMB 及以后默认 true，每根手指的事件派给它最初按下的那个子 View：源端分指的依据；ViewGroup 构造时默认置 FLAG_SPLIT_MOTION_EVENTS（出处：Android SDK 平台资源 data/res/values/attrs.xml，splitMotionEvents（按应用的 compileSdk 取对应平台）；android.view.ViewGroup#setMotionEventSplittingEnabled）
- 按全屏 touches.length 过滤时，按住一个按钮再按另一个，第二个的按下和第一个的抬起都被丢、按键卡在按下态；改成控件内手指集合后各自按下抬起：两种契约的实际差别（出处：卡里修好并验证过）
针对本应用要查的：
- 源端是否关掉了分指：源工程的 AndroidManifest 里 targetSdkVersion；布局 XML 里父布局的 android:splitMotionEvents；Java 里对父布局调用的 setMotionEventSplittingEnabled；targetSdkVersion ≥ 11 且没有设成 false 就是分指，契约按控件内手指集合写；设了 false 时整组只有首指所在的控件收事件
