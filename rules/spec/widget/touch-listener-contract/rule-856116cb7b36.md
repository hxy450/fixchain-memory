# MotionEvent 动作分支映射到 TouchType 时，规格写明附加手指怎么处理、怎么过滤

审的是：规格
触发（任一种）：
- 读到：源端 onTouch 里 switch (event.getAction())（未掩码）只列 ACTION_DOWN / ACTION_MOVE / ACTION_UP，坐标用无索引的 getX() / getY()；写错的样子：实现映射把 ACTION_DOWN/MOVE/UP 逐一写成 TouchType.Down/Move/Up 或写「行为等价」一句带过；没写用的是 getAction 还是 getActionMasked、ACTION_POINTER_DOWN/UP 是否参与，没写 ArkUI 逐指派发 Down/Up 和过滤规则
适用范围：安卓 MotionEvent 动作分支迁成 ArkUI .onTouch 时，规格的触控映射和差异清单
做法：
- 映射行写明源端分支用的是 getAction()（未掩码：附加手指的 ACTION_POINTER_DOWN/UP 带指针索引位，不进任何 case，被忽略）还是 getActionMasked()（附加手指参与）；无索引的 getX()/getY() 取指针索引 0
- 目标契约写明 ArkUI .onTouch 对每根手指都派发 TouchType.Down/Up，并规定过滤：Down/Up 时 event.touches.length > 1 就跳过（非首指按下、非末指抬起），Move 取 event.touches[0]，首指 Down、末指 Up 和 Cancel 取 event.changedTouches[0]
- 差异清单里单列一条：源端实际进入分支的事件子集（只有首指的 DOWN/MOVE/UP），桥接处照上一步过滤
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getAction() 返回的是 ACTION_DOWN 这类值，或 ACTION_POINTER_DOWN 与移位后的指针索引的组合：未掩码时附加手指按下/抬起的值不等于 ACTION_POINTER_DOWN/UP，也不等于 ACTION_DOWN/UP，switch 里哪个 case 都不进（出处：android.view.MotionEvent#getAction）
- getActionMasked() = getAction() & ACTION_MASK：去掉指针索引位后才能匹配 ACTION_POINTER_DOWN / ACTION_POINTER_UP（出处：android.view.MotionEvent#getActionMasked）
- ACTION_POINTER_DOWN = 5：A non-primary pointer has gone down：非首指按下的动作常量，索引编码在未掩码动作的 ACTION_POINTER_INDEX_MASK 位里（出处：android.view.MotionEvent#ACTION_POINTER_DOWN）
- getX()：The X coordinate of the first pointer index：无索引的 getX()/getY() 取指针索引 0（出处：android.view.MotionEvent#getX）
- touches: TouchObject[]（All finger information）；changedTouches: TouchObject[]（Finger information changed）：touches 是全部在屏触点，changedTouches 是本次变化的触点；文档要求使用时先校验是否为空（出处：鸿蒙 SDK 的 ets/component/common.d.ts，TouchEvent.touches、TouchEvent.changedTouches；ts-universal-events-touch.md，TouchEvent对象说明）
- 组件收到手指 Id 为 0 的 Down 后，也会收到手指 Id 为 0 的 Move 和 Up：onTouch 按手指闭环派发，每根手指各有自己的 Down/Up（出处：arkts-gesture-events-multi-level-gesture.md，触摸事件）
- 不过滤时第二指 Down 会把起点重置，Move 在两指间跳动，首指抬起被当成 ACTION_UP；按上面的规则过滤后两指同向滑动只触发一次：契约里不写过滤规则时实现端会出的错（出处：卡里修好并验证过）
未核实：Up 事件的 touches 是否还含正在抬起的那根手指，声明和文档都没写明
