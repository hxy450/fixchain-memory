# 源端有键盘/遥控导航状态机时，规格为弹层行项和面板各写验收条目并写明归属

审的是：规格
触发（任一种）：
- 读到：源端 onKeyDown 里有遥控模式标志驱动的导航：进入遥控模式、逐行逐项上下移动、OK 选择、行和元素高亮（初始化遥控、处理上下键、菜单命令、高亮一类方法和行/项下标字段）；写错的样子：规格只有一句概括的「DPAD 上下→遥控导航」，弹层行导航没有单独的验收条目；或两个 feature 都把这套状态机当成对方的职责
适用范围：规格提取阶段处理源端键盘、遥控共用的菜单导航状态机时
做法：
- 弹层行/项和曝光等面板各写一条验收条目：进入条件、行序和跳过不可见行的规则、OK 选择、行和元素的高亮色、退出条件
- 在两个 feature 的对接点写明这套状态机归哪个 feature 实现，另一方只调用
针对本应用要查的：
- 导航的行序、跳过规则和高亮色：源工程里遥控模式的初始化、上下键处理和高亮函数，以及行/项下标字段；按源码读出每个面板的行顺序、哪些行不可见时跳过、高亮用的颜色，写进验收条目
