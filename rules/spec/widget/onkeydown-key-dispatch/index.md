# 源端 onKeyDown 的按键分发和遥控导航

agent 会看到什么：读到源端 Activity 或 View 的 onKeyDown 分发音量、相机、媒体键和 SPACE、DPAD、NUMPAD 等键盘键，或用遥控模式标志驱动逐行逐项移动、OK 选择和高亮；规格写「按键交互仅保留屏上控件路径」「DPAD 上下→遥控导航」一句概括，弹层行导航没有验收条目

## 规矩

- rule-c6ea5a759ab6｜源端 onKeyDown 分发多类按键时，规格按键类分别写接收通道，只对核实不可达的键收缩｜读到：源端 Activity 或 View 的 onKeyDown 同时分发音量、相机、媒体键和键盘 SPACE、DPAD、NUMPAD、FUNCTION 等键；写错：规格映射行以「不投递音量键」为由把决策扩成「按键交互仅保留屏上控件路径」，没有引用读到的参考或 d.ts；同一文件的验收条目仍要求按键分发全部键位
- rule-fa601b58d7c7｜源端有键盘/遥控导航状态机时，规格为弹层行项和面板各写验收条目并写明归属｜读到：源端 onKeyDown 里有遥控模式标志驱动的导航：进入遥控模式、逐行逐项上下移动、OK 选择、行和元素高亮（初始化遥控、处理上下键、菜单命令、高亮一类方法和行/项下标字段）；写错：规格只有一句概括的「DPAD 上下→遥控导航」，弹层行导航没有单独的验收条目；或两个 feature 都把这套状态机当成对方的职责
