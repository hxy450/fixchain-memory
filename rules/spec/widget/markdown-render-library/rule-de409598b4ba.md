# 迁移整套第三方 Markdown 渲染库时，规格契约覆盖 CommonMark 核心语法并给可断言样例 AC

审的是：规格
触发（任一种）：
- 读到：源端用 Markwon（以 commonmark 解析为底座）加若干插件渲染 Markdown，Markwon.builder(context).usePlugin(...) 插件链；写错的样子：规格的实现映射写「行为目标=各插件可观察效果逐一等价」，AC 只覆盖插件和表格/删除线/HTML，没有嵌套列表、惰性续行、松紧列表、引用内块、行内元素按原文顺序的契约；复杂度按插件代码量判为 simple
适用范围：源端整套用第三方 Markdown 渲染库、目标端自研解析器或换库时的功能规格
做法：
- 契约同时覆盖库的 CommonMark 核心语法（嵌套列表、惰性续行、松紧列表、引用内的块、行内元素按原文顺序）和自研插件
- 为每类核心语法给可断言的样例 AC：输入一段 Markdown，写出期望的块结构或行内 run 序列
- 复杂度不按插件代码行数判为 simple
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 返修移植 commonmark.js 0.29 的块/行内算法得到有序 run，替换逐行正则的轻渲染：核心语法要按 CommonMark 算法实现（出处：卡里修好并验证过）
针对本应用要查的：
- 源端库所依赖的 CommonMark 解析器及版本：源工程 Gradle 依赖声明里 Markwon 的坐标和版本，再看该库 pom 里依赖的 commonmark 解析器版本；按该解析器对应的 CommonMark 规范版本选核心语法的样例
