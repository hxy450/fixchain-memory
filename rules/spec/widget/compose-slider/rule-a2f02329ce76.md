# 提取 Compose Slider 时记录 steps 的求值结果，换算成目标步长，不把名为 step 的常量当步进

审的是：规格
触发（任一种）：
- 读到：源端 Slider(valueRange = a..b, steps = (b / step).roundToInt() + 1) 这类由表达式算出的 steps，旁边有名为 step 的常量；写错的样子：快照或规格写「Slider 0..3 步进 0.1」「steps 0.1」，映射写 Slider(min, max, step = 源常量)，没有写 steps 的求值结果和换算后的步长
适用范围：UI 快照和规格提取 Compose Slider 的刻度时
做法：
- 规格写 steps 的求值结果并换算：可停位置数 = steps + 2，目标步长 = (max - min) / (steps + 1)，映射写 Slider({ min, max, step: (max - min) / (steps + 1) })
- 值标签写「按 Float.toString 输出」，不写 toFixed(1) 一类固定位数
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- SliderOptions.step?: number，@default 1，取值范围 [0.01, max - min]：目标端是步长，不是刻度数（出处：鸿蒙 SDK 的 ets/component/slider.d.ts，SliderOptions.step）
- SliderOptions.min 默认 0，max 默认 100：范围要显式写出（出处：鸿蒙 SDK 的 ets/component/slider.d.ts，SliderOptions.min / SliderOptions.max）
- 步长改为 (max - min) / (steps + 1)，标签改为 Float.toString 的输出：修复后刻度和标签与源端一致（出处：卡里修好并验证过）
针对本应用要查的：
- Slider 的 steps 整数值和 valueRange：源工程 Compose 文件里 Slider(steps = …) 的表达式及它引用的常量和 range；把表达式算成整数（含 roundToInt、+1 等），再按 (max - min) / (steps + 1) 得目标步长
