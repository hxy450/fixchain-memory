# 源组件来自 material3 且只传部分颜色时，规格写明库默认外观和未传颜色的取值

审的是：规格
触发（任一种）：
- 读到：源端 material3 Slider 只用 SliderDefaults.colors 传了 thumb / activeTrack / inactiveTrack 几种颜色，其余外观取库默认；写错的样子：规格外观只记传入的几种颜色，映射直接写 ArkUI 内置样式（如 style: SliderStyle.OutSet），没写 thumb 形状、轨道高度、thumb 两侧留隙、刻度点和末端指示
适用范围：规格提取阶段处理 material3 组件的库默认外观时
做法：
- 规格写明该库版本的默认外观：thumb 形状、轨道高度、thumb 两侧留隙、刻度点和末端指示；未传入的颜色写明取 MaterialTheme.colorScheme 的哪个值
- 没有运行截图时把这些外观标为「待核」，不直接映射成 ArkUI 内置样式
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- SliderBlockType.DEFAULT = 0：Round slider：ArkUI 内置滑块是圆形，和 M3 的竖条 thumb 不同（出处：鸿蒙 SDK 的 ets/component/slider.d.ts，SliderBlockType.DEFAULT）
- 源端实测为竖条 thumb，有 thumb 两侧留隙、刻度点和末端 stop indicator：M3 滑杆的默认外观（出处：卡里修好并验证过）
针对本应用要查的：
- material3 库版本：源工程的依赖声明：Gradle 版本目录或模块构建脚本里的 compose-bom 和 material3 坐标；读出 BOM 或 material3 的版本，按该版本的默认外观记录 thumb、轨道、留隙和刻度
- 未显式传入的颜色：源工程主题文件里 MaterialTheme(colorScheme = …) 用的 lightColorScheme / darkColorScheme 定义；对每个没传入的颜色记下它对应的 colorScheme 角色和该角色的值；查不到对应角色时标待核
未核实：M3 滑杆的默认几何随 material3 版本变化，卡里只在一个版本上实测
