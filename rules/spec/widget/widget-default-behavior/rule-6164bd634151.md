# 源端 setError 在规格里写「尾部错误图标 + 仅焦点框气泡 + 输入即清」，不写实时校验或行内红字

审的是：规格
触发（任一种）：
- 读到：源端校验时调 EditText.setError(...)；写错的样子：规格转换决策写「setError 字段校验 → TextInput .errorMessage / 错误状态变量，实时校验」，或写成输入框下常显红字
- 读到：源码对 EditText 调用 setError(...)；写错的样子：规格的转换决策表把「setError 字段校验」写成「行内错误红字（条件渲染 Text）」，或先写 TextInput.errorMessage、又以「属性存在性不确定」改成别的形态
适用范围：规格提取阶段给源端 setError 字段校验写转换决策（翻成目标契约的那一行）时
做法：
- 转换决策写 setError 的呈现：输入框尾部（右端）错误图标；错误文案只在该框获焦时以不占布局的气泡浮层显示（对应 Editor.ErrorPopup）；文本一改就清除图标和气泡
- 拿不准目标属性在不在时写出 SDK 声明核实的结论：TextInput 没有 errorMessage，错误提示属性是 showError（显示在输入框下方）；不拿形态不同的替代品（行内文本、实时校验）写进规格
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- setError 把右侧 compound drawable 设成错误图标，错误文案在 TextView 获焦时以弹出气泡显示，任何改动文本的按键都会清掉图标和文案：源端的完整呈现语义（出处：android.widget.TextView#setError）
- showError(value?: ResourceStr | undefined): TextInputAttribute：TextInput 的错误提示属性，错误文本显示在输入框下方，和源端气泡不是一回事；声明里没有 errorMessage（出处：鸿蒙 SDK 的 ets/component/text_input.d.ts，TextInputAttribute.showError）
