# 多行省略的转换决策不写「等价」，写明末行截断粒度差异并登记 PD 或方案

审的是：规格
触发（任一种）：
- 读到：源码多行正文写 `maxLines = N, overflow = TextOverflow.Ellipsis`（或 `android:maxLines` 加 `android:ellipsize`）；映射参考只记 `ellipsize → textOverflow` 的 API 对应；写错的样子：规格「转换决策」表把 `.maxLines(N).textOverflow({ overflow: TextOverflow.Ellipsis })` 的理由写成「等价」，没写末行截断粒度的差异，也没有 PD 登记或差异 AC
适用范围：决策台账定为完整复刻安卓可观察行为（D0）时，规格里多行正文省略的转换决策和验收条目
做法：
- 转换决策里写明差异：ArkUI 默认 wordBreak 为 BREAK_WORD，末行放不下整词就整词丢弃，再补带前导空格的「 ...」并在右侧留白；安卓按字符填满末行后接单个「…」
- D0 为完整复刻时，登记为平台差异项（PD），或直接写出实现方案（折叠态按字符预截断）
- 映射参考只给 API 对应时，把渲染语义的缺口写成规格里的差异 AC，不留给视觉核验补票
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- wordBreak(value: WordBreak): TextAttribute，默认 WordBreak.BREAK_WORD：Text 不写 wordBreak 时按词换行，末行省略也按词（出处：鸿蒙 SDK 的 ets/component/text.d.ts，TextAttribute.wordBreak）
- ArkUI maxLines + Ellipsis 的末行：整词丢弃，接「 ...」（前导空格），右侧留白：和安卓末行形态不同，不能判为等价（出处：卡里修好并验证过）
- 末尾省略时逐字符累加宽度，加上省略号宽度放不下就停，其余字符换成省略号；省略号是单个 U+2026：安卓 StaticLayout 的末行按字符截断（出处：android.text.StaticLayout#calculateEllipsis；android.text.TextUtils#ELLIPSIS_NORMAL）
- textOverflow(options: TextOverflowOptions): TextAttribute：ArkUI Text 的溢出显示方式，Ellipsis 要配 maxLines 才生效（出处：鸿蒙 SDK 的 ets/component/text.d.ts，TextAttribute.textOverflow）
未核实：ArkUI ellipsisMode(END) 或 wordBreak(BREAK_ALL) 能否做到字符级末行，卡里没有试验记录
