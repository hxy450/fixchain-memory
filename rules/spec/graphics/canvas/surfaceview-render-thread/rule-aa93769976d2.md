# 源端每轮 new 循环线程、停止只经最新实例时，规格按实例映射，不收敛成全局单一帧循环句柄

审的是：规格
触发（任一种）：
- 读到：初始化或重开方法里 new 一个 Thread 子类赋给同一字段，surfaceCreated / surfaceDestroyed 只经这个字段 start 或置 isRunning = false 再 join，对话框按钮直接 init + start、不先停旧实例；写错的样子：规格把循环写成「单一帧循环句柄」（setInterval / displaySync），startLoop/stopLoop 对应 surfaceCreated/surfaceDestroyed，并写「每局新实例不释放…不可观察差异，行为等价」
适用范围：规格提取阶段把源端 Thread（或自建 Runnable）游戏循环映射为目标帧调度结构时
做法：
- 先数源端循环实例的创建与停止路径：每个实例映射为一个目标循环对象（实例字段加各自的帧订阅），surfaceCreated/surfaceDestroyed 的对应物只作用于最新引用
- 规格写明哪些字段是实例字段、哪些是静态共享；旧实例还在跑循环时，不写「每局新实例不释放是不可观察差异」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- It is never legal to start a thread more than once：源端每次重开只能 new 新实例，旧实例要靠字段上的停止路径才会结束；没被停的旧实例继续跑（出处：java.lang.Thread#start）
- 安卓实测：进入下一关后再点底下判负对话框的重开，两个循环并存，判负对话框持续叠加：同时存活的循环数本身是可观察行为（出处：卡里修好并验证过）
针对本应用要查的：
- 源端同时存活的循环实例数：源工程里 Thread / Runnable 子类的构造调用点、保存实例的字段的全部赋值、SurfaceHolder.Callback 的 surfaceCreated/surfaceDestroyed 方法体、各对话框按钮 onClick；列出每条操作序列下哪些实例被 start、哪些被停，未被停的实例都算存活
