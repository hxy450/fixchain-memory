# 规格写帧循环「与源端等价节流」时，先写源端节拍来源和目标驱动 API，races 和 C7 候选列出 vsync 驱动

审的是：规格
触发（任一种）：
- 读到：源端帧循环是无 Thread.sleep 的 SurfaceHolder.lockCanvas / unlockCanvasAndPost 忙循环，或分析器缺陷表写「帧率不限、弹速随设备帧率漂移（帧计数时间基准）」；写错的样子：规格的跨栈映射、实现映射、races 节或决策候选写「单一帧循环句柄（setInterval ~16ms）」「16ms≈60fps」「setInterval 16ms 等价节流」，没写源端节拍来自 vsync 还是固定周期，也没把 displaySync / postFrameCallback 列为候选
适用范围：规格提取与架构决策阶段，写源端游戏线程或动画帧循环到目标帧驱动方式的映射行、races 节和 C7 候选时
做法：
- 映射行先写源端节拍来源（vsync：无 sleep 的 lockCanvas 循环 / Choreographer / invalidate 自续帧；或固定周期）和目标驱动 API，例：「目标用 displaySync.create() + setExpectedFrameRateRange({expected, min, max} 取源端帧率) + on('frame') 驱动 update+render，stop 时 stop() 并 off('frame')」，附 d.ts 出处
- races 节和 C7 候选把 vsync 驱动（displaySync / postFrameCallback）列为候选并写取舍；不只凭「16ms≈60fps」推定定时器等价
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- setInterval(16) 在 60Hz 模拟器上实际约 39 帧/秒，安卓同场景约 60 帧/秒：「16ms 等价节流」不成立（出处：卡里修好并验证过）
- function create(): DisplaySync；setExpectedFrameRateRange(rateRange: ExpectedFrameRateRange): void；on(type: 'frame', callback: Callback<IntervalInfo>): void：规格里写的目标驱动 API 及其 d.ts 出处（出处：鸿蒙 SDK 的 ets/api/@ohos.graphics.displaySync.d.ts，displaySync.create / DisplaySync.setExpectedFrameRateRange / DisplaySync.on）
- postFrameCallback(frameCallback: FrameCallback): void：另一个可列入候选的 vsync 驱动（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.postFrameCallback）
