# 源端字体同步装载并参与测宽布局时，规格写明「首次测宽前字体必须可用」

审的是：规格
触发（任一种）：
- 读到：源端构造器里 Typeface.createFromAsset 同步装载后 paint.setTypeface，随后 measureText 的结果参与布局（如按测宽定字号）；写错的样子：实现映射把 Typeface 一行只写成「rawfile 注册字体 → ctx.font 引用」，风险标低、按「字形差异 → visual 兜底」处理，没写首次测宽前字体须可用
适用范围：规格为源端自定义字体写 ArkUI Canvas 的映射行和字体可用时序契约时
做法：
- 映射行和契约里写明「首次测宽/布局前字体必须已可用」：目标端注册是异步的，要规定就绪检查、超时降级和布局完成后的回调；风险不归为字形差异或视觉兜底
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 通过 this.uiContext.getFont().registerFont 注册是异步接口，调用后立即绘制可能导致自定义字体不生效：源端同步装载、目标端异步注册，时序要写进契约（出处：ts-canvasrenderingcontext2d.md，font）
- public static Typeface createFromAsset(AssetManager mgr, String path)：源端同步返回 Typeface，构造器里装载后马上就能测宽（出处：android.graphics.Typeface#createFromAsset）
- 去掉引号后 6 次冷启首次布局都得到注册字体度量，其中一次仍需等约 37ms 才就绪：注册后不能假定同步可用（出处：卡里修好并验证过）
