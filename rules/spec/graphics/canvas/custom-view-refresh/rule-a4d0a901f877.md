# 源 View 在构造、onSizeChanged、绘制时取文案或一次性状态的，规格标「随配置重建刷新」

审的是：规格
触发（任一种）：
- 读到：源 View 在构造函数、onSizeChanged、onDraw 里经 getResources().getString 取文案，或在构造时读 firstRun 一类一次性状态决定是否显示帮助；写错的样子：规格没把这些文案和状态标成「随配置重建刷新」，目标映射里没写刷新入口，或者只写「尺寸变化时重算」
适用范围：规格提取阶段，源 Activity 会随配置变化重建、View 里缓存了资源文案或一次性状态时
做法：
- 把这些文案和一次性状态逐项标注「随配置重建刷新」
- 目标映射写触发入口：UIAbility.onConfigurationUpdate(newConfig) 比较 language、colorMode、fontSizeScale、fontWeightScale、mcc、mnc；显示大小变化用 display.on('change', cb) 比较 densityPixels
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onConfigurationUpdate(newConfig: Configuration): void：系统配置更新时回调（UIAbility 继承自 Ability）（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.Ability.d.ts，Ability.onConfigurationUpdate）
- language?: string；colorMode?: ConfigurationConstant.ColorMode；fontSizeScale?: number；fontWeightScale?: number；mcc?: string；mnc?: string：Configuration 里要比较的字段（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.Configuration.d.ts，Configuration）
- function on(type: 'add' | 'remove' | 'change', callback: Callback<number>): void：显示设备变化回调，callback 收到变化的 displayId（出处：鸿蒙 SDK 的 ets/api/@ohos.display.d.ts，display.on）
- densityPixels: number：Display 的显示密度（物理像素与逻辑像素的缩放系数）（出处：鸿蒙 SDK 的 ets/api/@ohos.display.d.ts，Display.densityPixels）
- 显示大小变化另走 display 'change' 比较 densityPixels：显示大小这一项单靠 onConfigurationUpdate 接不住（出处：卡里修好并验证过）
- onConfigurationUpdate(newConfig: Configuration): void：同族接口：AbilityStage.onConfigurationUpdate，模块级的配置更新回调（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.AbilityStage.d.ts，AbilityStage.onConfigurationUpdate）
针对本应用要查的：
- 哪些文案和一次性状态依附在随重建的 View 上：源 View 的构造函数、onSizeChanged、onDraw 里 getResources().getString / getText 的调用，以及构造时读的偏好或首次运行标志；逐项列出它们在哪一步读取，写进规格的「随配置重建刷新」清单
未核实：显示大小变化在鸿蒙只发 display 'change'、不触发 onConfigurationUpdate，是卡里返修插桩看到的，本机声明没写明
