# 源端用 Paint 取文字度量时，规格先分清墨迹级还是字体级，再对 TextMetrics 同层级字段

审的是：规格
触发（任一种）：
- 读到：源端自绘 View 用 Paint.getTextBounds / rect.height()、Paint.ascent() / descent() 或 getFontMetrics 算行高、基线或自适应字号；写错的样子：规格的映射行把 actualBoundingBox* 和 fontBoundingBox* 混列为候选、注「近似」「待实测」，或没写取整，契约栏留「—」
适用范围：规格提取阶段写 Paint 文字度量到 TextMetrics 的映射行时
做法：
- 按源 API 判断度量层级：getTextBounds / Rect.height() 是所测字符的墨迹紧包围盒；Paint.ascent / descent / getFontMetrics 是主字体的字体级上下伸
- 映射行只列同层级的目标字段：墨迹级对 ctx.measureText(所测子串) 的 actualBoundingBoxAscent / actualBoundingBoxDescent；字体级不列 actualBoundingBox*
- 照源端式子写出取整：(int) 写成 Math.trunc，getTextBounds 的外扩写成两项各自 Math.ceil
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getTextBounds 返回包住所有字符的最小矩形，原点隐含在 (0,0)（基线起点）：源端的墨迹级度量（出处：android.graphics.Paint#getTextBounds）
- Paint.ascent() 按当前字体和字号返回基线以上的距离（负值），按主字体、不含回退字体：源端的字体级度量（出处：android.graphics.Paint#ascent）
- actualBoundingBoxAscent / actualBoundingBoxDescent：textBaseline 指示的水平线到渲染文字矩形边界顶部 / 底部的距离：目标端的墨迹级度量（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，TextMetrics.actualBoundingBoxAscent、TextMetrics.actualBoundingBoxDescent）
- fontBoundingBoxAscent / fontBoundingBoxDescent：到所有字体渲染文字最高矩形边界顶部 / 底部的距离：目标端的字体级行框（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，TextMetrics.fontBoundingBoxAscent、TextMetrics.fontBoundingBoxDescent）
- getTextBounds 高度对 actualBoundingBox 两项各自 Math.ceil（对应 Skia 的 roundOut）；用字体行框时约大 1.4 倍：例：墨迹级用错成字体级时的偏差量级（出处：卡里修好并验证过）
针对本应用要查的：
- 源端式子用的是哪个度量、测的是哪段文字、怎么取整：源工程自绘 View 的 onDraw / onMeasure 里调 Paint 度量的地方；读出调用的方法（getTextBounds 的 start、end，ascent / descent 的组合）和外面的 (int)、Math.round 等取整，照写进映射行
未核实：字体级的 ascent() / descent() 对 fontBoundingBoxAscent / fontBoundingBoxDescent 是否数值一致，族里规矩没有实测（卡里要求字段须实测确认）
