# 规格写文字基线映射时，写明 Paint.ascent/descent 是字体级带符号度量、结果按 (int) 截断

审的是：规格
触发（任一种）：
- 读到：源端用 `Paint.ascent()` / `Paint.descent()` 算基线偏移，式子带 `(int)`；写错的样子：规格的实现映射只写「actualBoundingBoxAscent/Descent 或 fontMetrics 近似」，契约栏为「—」，没写度量的来源级别和截断
适用范围：规格提取阶段写 Canvas 文字基线、垂直居中映射的那一行
做法：
- 映射里写明：源端 ascent()（负值）/ descent()（正值）是主字体的字体级（hhea）上下伸，偏移 = (int)((descent + ascent) / 2)，向零截断
- 目标候选不列字形墨迹级的 actualBoundingBox*；契约栏写出截断（Math.trunc）和字段须实测确认，不留「—」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- public float ascent()：基线上方的距离，负值，按主字体（不含回退字体）（出处：android.graphics.Paint#ascent）
- readonly actualBoundingBoxAscent: number：到实际渲染文字边界顶部的距离，随字形墨迹变，不是 ascent() 的等价量（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，TextMetrics.actualBoundingBoxAscent）
