# 图片经 Coil 全局 ImageLoader 加载时，规格的图片管线写明默认占位、错误图、过渡和动图行为

审的是：规格
触发（任一种）：
- 读到：源码里 ImageLoaderFactory.newImageLoader 或 Coil.setImageLoader 建的默认 ImageLoader.Builder 设了 placeholder(...)、error(...)、crossfade(...)，components 里只 add 了部分解码器（没有 GifDecoder / ImageDecoderDecoder），另有带 GIF 解码器的 ImageLoader 由设置位切换；写错的样子：规格的图片管线 AC 只写了 crossfade，没写默认占位图和错误图；或者写成「GIF 按帧动画播放，与 Android 一致」，没写默认 loader 只出首帧、也没写切换 loader 的设置位
适用范围：安卓图片经 Coil 全局 ImageLoader（ImageLoaderFactory / Coil.setImageLoader）加载，规格整理图片加载管线时
做法：
- 图片管线 AC 写明默认 loader 的 placeholder、error、crossfade 各是什么，以及已装的解码器决定动图是播放还是只显示首帧
- 写明哪个设置位把全局 loader 切换成带 GIF 解码器的 loader、默认取值下的行为；只有用带 GIF 解码器的 loader（如图片查看器）的界面才写「动图播放」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 默认 loader 没装 GIF 解码器、设置位为默认值时，列表、卡片、头像、缩略图里的动图只显示首帧；目标端按首帧 PixelMap 显示，解码期间显示默认占位：规格里「动图行为」那一项应写成的样子（出处：卡里修好并验证过）
针对本应用要查的：
- 默认 loader 的占位图、错误图、过渡和已装解码器，以及切换 loader 的设置位：源工程里实现 ImageLoaderFactory 的 Application 类的 newImageLoader，以及所有调用 Coil.setImageLoader / ImageLoader.Builder 的地方；读 Builder 上的 placeholder、error、crossfade 和 components { add(...) } 里的解码器；找出另建 loader 的条件（设置位及其默认值）
未核实：卡里的上机行为出自 HarmonyOS 6.1.1(24)，本机按 API 23 的声明核实
