# 规格给 ShadowOptions 写阴影配方时，写明字段单位 px 并在公式里写 vp2px 换算

审的是：规格
触发（任一种）：
- 读到：源端阴影是 dp 量纲：Compose Modifier.shadow(elevation: Dp)、Surface 的 elevation: Dp，或 android:elevation；写错的样子：规格里阴影配方写成 { radius: 2e, offsetY: e } 这类把 dp 数直接填进 ShadowOptions 字段的式子，没写单位和 vp2px 换算
适用范围：规格或映射文档里给 ArkUI 数值型渲染属性（阴影 radius / offset、模糊等）写数值配方的那一节
做法：
- 配方里写明 ShadowOptions 的 radius、offsetX、offsetY 单位是 px，dp/vp 来源的数进 px 字段前在公式里显式换算：radius: uiContext.vp2px(k * e)、offsetY: uiContext.vp2px(m * e)，映射函数的签名带上 UIContext 参数
- 规格里附上检查法：配方里每个 dp/vp 来源的数进入 px 字段前是否有显式换算
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- ShadowOptions.radius：Blur radius of the shadow and the unit is px：阴影模糊半径的单位是 px（出处：鸿蒙 SDK 的 ets/component/common.d.ts，ShadowOptions.radius）
- ShadowOptions.offsetX / offsetY：Unit is px，默认 0：阴影偏移的单位是 px（出处：鸿蒙 SDK 的 ets/component/common.d.ts，ShadowOptions.offsetX、ShadowOptions.offsetY）
- vp2px(value: number): number：UIContext 上把 vp 换成 px（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.vp2px）
- <attr name="elevation" format="dimension" />：源端高程是尺寸量纲（dp），不是像素数（出处：Android SDK 平台资源 data/res/values/attrs.xml，elevation（按应用的 compileSdk 取对应平台））
