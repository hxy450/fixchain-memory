# 源端 AnimatedImageVector 两态形变，规格写成 parity 要求并给插值路线，不写图标态切换

审的是：规格
触发（任一种）：
- 读到：源 Compose 用 AnimatedImageVector.animatedVectorResource(R.drawable.…) 加 rememberAnimatedVectorPainter(icon, atEnd)，atEnd 随状态变化；写错的样子：转换决策表写「矢量动画无直接等价，图标态切换即可满足」「SymbolGlyph 切换或 ImageAnimator 序列帧」，没有决策 ID；结构段、映射表和 AC 对这个动画说法不一致
适用范围：规格提取阶段为源端 animated-vector 两态形变图标确定 ArkUI 实现方案时
做法：
- 读对应的 animated-vector 资源，取 pathData 的 valueFrom / valueTo、duration 和 interpolator，把「两态之间的形变过渡」写成 parity 要求，并写实现路线：Canvas / Path 按数值插值，或等价的属性动画
- 确需降级时走 decision-ledger 决策 ID 和差异 AC，并让结构段、映射表、AC 三处一致；不以「无直接等价」作转换决策
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- valueType 的 pathType = 2：values are paths defined as strings，用于 AnimatedVectorDrawable 的 path morphing：objectAnimator 的 propertyName="pathData"、valueType="pathType" 就是两态形变，起止路径在 valueFrom / valueTo（出处：Android SDK 平台资源 data/res/values/attrs.xml，valueType（按应用的 compileSdk 取对应平台））
- @android:interpolator/fast_out_slow_in 是 pathInterpolator，controlX1=0.4、controlY1=0、controlX2=0.2、controlY2=1：源端常用插值器的确切曲线（出处：Android SDK 平台资源 data/res/interpolator/fast_out_slow_in.xml（按应用的 compileSdk 取对应平台））
- Curve.FastOutSlowIn：cubic-bezier (0.4, 0.0, 0.2, 1.0)：目标端同一条曲线（出处：鸿蒙 SDK 的 ets/api/@ohos.curves.d.ts，Curve.FastOutSlowIn）
- 从 animated-vector 取起止 pathData，按源 duration 和 fast_out_slow_in 逐数值插值，atEnd=false 画首帧、true 画末帧后形变恢复：插值路线可行的依据（出处：卡里修好并验证过）
针对本应用要查的：
- 形变的起止路径、时长和插值器：源工程 res/drawable 下 animatedVectorResource 引用的 <animated-vector>：它的 <target> 指向的 res/animator 里的 objectAnimator，或内联在 <aapt:attr name="android:animation"> 里的 objectAnimator；读 android:propertyName="pathData" 那个 objectAnimator 的 valueFrom、valueTo、duration、interpolator；@android:interpolator/… 到平台资源 res/interpolator 下解析成曲线参数
