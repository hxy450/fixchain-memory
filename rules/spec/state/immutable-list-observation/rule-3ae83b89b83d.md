# 规格写可变列表或订阅队列时，把 ArkUI 端的变更写法和观察方式成对写明

审的是：规格
触发（任一种）：
- 读到：源端用 data class copy 替换列表项、StateFlow.update { list + item } 生成新列表，宿主订阅队列；写错的样子：规格把「map + copy 只替换目标行」「尾拼接」当作照搬的写法，写了 key=id 和「@Trace 数组驱动刷新」，却没写行内字段变化靠什么被观察、订阅队列的消费方靠什么触发
适用范围：规格里把源端可变列表、事件队列映射到 ArkUI V2 状态的那一节
做法：
- 列表写明：ForEach 的 key 只含 id 时，行内会变的字段是 @ObservedV2 类上的 @Trace 字段、原位修改；要替换对象，key 就要含变化的字段
- 订阅队列写明：生产方入队、出队都整体重新赋值数组，消费方用 @Monitor 监听这个数组属性
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 非首次渲染时键值已存在则不创建新组件，直接渲染该键值对应的组件：key 只含 id 时，换对象不会让行重建（出处：arkts-rendering-control-foreach.md，非首次渲染）
- @Monitor 监听数组整体时，只能观测到数组整体的赋值：订阅队列的生产方要整体赋值（出处：arkts-new-monitor.md，通用监听能力）
