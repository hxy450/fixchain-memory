# ViewModel 里请求前补齐和列表组装的步骤

agent 会看到什么：读到 ViewModel 在发请求前 launch 按 ID 查本地库（Dao @Query）回填参数，或在 init 里组装列表（add(0, …) 插首项、去重），容器按持久化选中项 setCurrentItem；规格的数据流、跨 feature 契约、对接点和 AC 没写这一步，或声明「不认领」「仅消费选择对象」

## 规矩

- rule-02f94531d86d｜源端请求前按 ID 查本地库补齐参数的，规格的数据流和验收条目写出这一步｜读到：源端 ViewModel 在发请求前先 launch 一个按 ID 查本地库的方法（DAO 查询），把 lon / lat 等回填进请求对象，缓存命中与否都走这一步；写错：规格数据流写成「取当前选择对象 → 发请求」，验收条目只覆盖缓存和 TTL，没有「请求前按 ID 查库补齐经纬度」；详情入口直接用未补齐的选择对象导航
- rule-0c8212a5d775｜按 feature 划分所有权时，委托出去的步骤写成跨 feature 契约，写明提供方接口和「输入可能只有 ID」｜读到：源端请求前按 ID 查本地库补齐参数，规格把对应 DAO 划给另一个 feature；写错：本 feature 规格只写「消费当前选择对象」「仅通过对方服务契约消费」，没有写提供方的查询接口、调用时机和输入只有 ID 的情形；对方规格也只发布选择对象
- rule-b6965e6fd852｜源端容器 ViewModel 组装列表、容器恢复选中页时，规格要认领组装规则并写进验收条目｜读到：源码清单里的容器 ViewModel 在 init 里组装列表（取已存列表，再把定位项 add(0, …) 插到首位并去重），容器 Fragment 加载后按持久化选中项 setCurrentItem、onPageSelected 里回写；写错：各功能规格的锚点都不含这个容器 ViewModel，或声明「不认领」它和容器 Fragment，对接点只写「容器消费某列表、某选中项」；验收条目里没有首项插入、去重、重启后恢复当前页、切页回写这几项
