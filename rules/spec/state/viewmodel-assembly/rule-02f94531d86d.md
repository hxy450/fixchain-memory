# 源端请求前按 ID 查本地库补齐参数的，规格的数据流和验收条目写出这一步

审的是：规格
触发（任一种）：
- 读到：源端 ViewModel 在发请求前先 launch 一个按 ID 查本地库的方法（DAO 查询），把 lon / lat 等回填进请求对象，缓存命中与否都走这一步；写错的样子：规格数据流写成「取当前选择对象 → 发请求」，验收条目只覆盖缓存和 TTL，没有「请求前按 ID 查库补齐经纬度」；详情入口直接用未补齐的选择对象导航
适用范围：规格阶段把源端接口调用前的数据准备步骤写进目标数据流和验收条目时
做法：
- 逐步列出源端请求前的准备链（入口方法 → 查库方法 → DAO 查询 → 各接口），把「按 ID 查本地库补齐 lon / lat 后再请求」写进数据流和验收条目
- 写明首页请求和各详情入口都使用补齐后的对象
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 默认城市只有 ID、没有经纬度时，源端靠查库补齐照常可用；目标在请求前补上查库后请求参数完整：只有 ID 的输入是常态，补齐步骤不能省（出处：卡里修好并验证过）
针对本应用要查的：
- 源端请求前的准备链：源工程 ViewModel 里发请求的方法，往前找它调用的协程、查库方法和 DAO 查询；按调用顺序列出每一步改了请求对象的哪些字段，写进规格数据流
