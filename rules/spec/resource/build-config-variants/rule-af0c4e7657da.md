# 源端功能在参照构建里不触发时，规格按不触发落地，不新增同意门控和本地采集链

审的是：规格
触发（任一种）：
- 读到：源端初始化被构建期配置短路：`if (!TextUtils.isEmpty(BuildConfig.…))` 包住 ACRA.init，参照构建里该值为空，上报静默禁用；写错的样子：规格或台账为「平台合规」新增隐私同意门控、本地崩溃日志采集链，把源端的启用开关默认值改成关，并标 HARD-DIV
适用范围：规格提取阶段处理崩溃上报一类由构建期配置决定是否启用的源端功能时
做法：
- 按源行为写：参照构建不初始化、不采集、不上报，目标端同样不采集、不加门控；源端的启用开关照迁，默认值不改
- 合规门控只在目标端确实采集或上报时才设计
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- TextUtils.isEmpty(str)：str 为 null 或长度为 0 时返回 true：构建期值为空串时整段初始化被跳过（出处：android.text.TextUtils#isEmpty）
- 参照构建从不初始化 ACRA、不采集不上报，无需门控，启用开关照迁：修好的做法（出处：卡里修好并验证过）
针对本应用要查的：
- 参照构建里这个构建期配置的值：源工程的 gradle.properties，以及模块构建脚本里 buildConfigField 定义这个字段的地方；读出参照构建用的值；为空时源端这段初始化不执行
