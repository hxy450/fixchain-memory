# 构建开关在新旧两套实现间二选一时，规格先查开关取值，以启用的一套为行为基准，不取并集

审的是：规格
触发（任一种）：
- 读到：源码按 BuildConfig 布尔开关在两套实现间择一启动（如 starter 里 if (BuildConfig.USE_…) 选服务），停用的一套在开关为真时于 onCreate 抛 IllegalStateException；写错的样子：规格基线写「两路径的行为断言取并集」，冲突路径的验收条目照停用实现写（如换集时收尾上一集、跳过即标记已播、只在某一状态回退）
- 读到：ref 里已记录构建事实（「某实现默认启用」、开关取值）；写错的样子：feature 规格仍写「二选一」「取并集」，或验收条目引用停用实现的行为，交叉验证没有报告
适用范围：规格提取和交叉验证阶段，源码同一能力由构建开关在两套实现间择一启用、目标端只建一套
做法：
- 先在源工程 Gradle 构建脚本（公共脚本和模块构建脚本）的 buildConfigField 与 manifestPlaceholders 查出当前构建取值，以启用的实现作为行为基准；停用实现只作对照
- 两套行为冲突的路径逐条标明来源实现，至少核对：手动换集是否收尾上一集、显式跳过是否标记已播/出队、暂停后续播是否回退、片尾跳过如何收尾；要偏离启用实现时铸 PD 决策
- 交叉验证时把 ref 里的构建事实与 feature 里「二选一 / 取并集」的表述对照，规格引用了停用实现的验收条目即报告
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 停用的一套在开关为真时 onCreate 直接抛 IllegalStateException，说明两套互斥而非叠加：看到这种写法就要先查开关值（出处：卡里修好并验证过）
- 用户决定对齐启用的实现后，删除停用实现的换集收尾和跳过逻辑，按启用实现的换集、跳过、续播回退、片尾跳过重写：按启用实现为基准是最终保留的做法（出处：卡里修好并验证过）
针对本应用要查的：
- 构建开关的当前取值：源工程根目录或模块的 Gradle 构建脚本（含被 apply 的公共脚本）里的 buildConfigField 和 manifestPlaceholders，按开关名搜；读出 true / false；为真的那一套是行为基准，另一套在规格里只作对照
