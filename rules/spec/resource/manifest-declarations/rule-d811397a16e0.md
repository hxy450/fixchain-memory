# 台账给日志上传定 HTTPS 或只传快照时，逐项写明与安卓明文策略和打包清单的差异

审的是：规格
触发（任一种）：
- 读到：安卓 AndroidManifest 的 <application> 写了 android:usesCleartextTraffic="true"（或 android:networkSecurityConfig）；上传函数先向服务端取预签名地址再 PUT，ZIP 里有日志目录全部留存文件、设备信息和 ObjectBox 各表导出；写错的样子：决策台账或规格把上传定成「经 presign → HTTPS PUT」「只传快照、不上传完整数据库」这类收窄约束，却没写安卓清单的明文策略和上传函数的实际打包清单，也没把差异逐项标成待用户确认
适用范围：规格阶段为诊断或日志上传写协议约束和归档内容约束的那几项（决策台账、规格页、源码理解笔记）
做法：
- 规格里先照安卓写下两项事实：清单里 usesCleartextTraffic / networkSecurityConfig 的取值，上传函数实际打包的每个文件或目录（日志目录、设备信息、各表导出）
- 要收窄为 HTTPS 或只传快照时，逐项写出与安卓的差异（协议、少传的文件），每项标为待用户确认，不以派生的安全隐私约束直接定稿
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- android:usesCleartextTraffic（format="boolean"）：为 true 表示应用可以走 HTTP 等明文通道；安卓端声明了它，上传地址就可能是 http（出处：Android SDK 平台资源 data/res/values/attrs_manifest.xml，usesCleartextTraffic（按应用的 compileSdk 取对应平台））
- network_config.json 的 cleartextTrafficPermitted：明文 HTTP 是否允许，默认为 true：鸿蒙端系统层默认不拦明文 HTTP，「必须 HTTPS」不是平台强加的约束（出处：http-request.md，明文HTTP访问权限配置说明）
针对本应用要查的：
- 安卓端的明文策略：源工程 AndroidManifest.xml 的 <application> 标签，以及 android:networkSecurityConfig 指向的 res/xml 文件；读出 usesCleartextTraffic 的取值和 network-security-config 里按域名放行明文的条目，原样写进规格
- 安卓上传函数的实际打包清单：源工程里取预签名地址并 PUT 上传日志的那个函数及它调用的收集、压缩函数；按调用顺序列出写入 ZIP 的每个文件或目录（是否递归、是否只取当天），逐项写进规格
