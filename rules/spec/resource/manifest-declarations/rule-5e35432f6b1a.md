# 规格逐项列出 manifest 的 application/activity 属性和缺省语义，映射到目标配置

审的是：规格
触发（任一种）：
- 读到：AndroidManifest 的 <application android:allowBackup="false">，<activity> 没写 android:screenOrientation、android:windowSoftInputMode（依赖平台缺省）；写错的样子：规格或功能基线的配置段只写权限（或「requestPermissions 为空」），没有备份、屏幕方向、软键盘避让的映射；界面图里方向记为 unspecified、软键盘记为 unknown 却没给目标值，也没有对应的实现任务
适用范围：规格阶段把 AndroidManifest 的应用级和页面级属性落到 module.json5、备份配置和窗口配置时
做法：
- 逐项列出 application / activity 属性及缺省语义并映射：allowBackup → backup_config.json 的 allowToBackupRestore；screenOrientation → module.json5 abilities 的 orientation；windowSoftInputMode → UIContext.setKeyboardAvoidMode(KeyboardAvoidMode.…)；每项指派实现任务
- 源端没写、记为 unspecified / unknown 的项，也按平台缺省写出目标值，不留空
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- android:allowBackup 默认 true：源端没写时是允许备份（出处：Android SDK 平台资源 data/res/values/attrs_manifest.xml，allowBackup（按应用的 compileSdk 取对应平台））
- allowToBackupRestore 默认 false：目标端不写就不允许备份，源端 false 或 true 都要显式写（出处：app-file-backup-extension.md，allowToBackupRestore）
- android:screenOrientation 的 unspecified = -1；module.json5 abilities 的 orientation 可缺省，缺省值 unspecified（由系统判断方向）：源端没写方向时，目标写 unspecified 或不写（出处：Android SDK 平台资源 data/res/values/attrs_manifest.xml，screenOrientation（按应用的 compileSdk 取对应平台）；module-configuration-file.md，abilities标签）
- setKeyboardAvoidMode(value: KeyboardAvoidMode): void，默认 KeyboardAvoidMode.OFFSET；OFFSET = 0 布局上移，RESIZE = 1 布局缩小：软键盘避让的目标写法（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，UIContext.setKeyboardAvoidMode、KeyboardAvoidMode）
针对本应用要查的：
- 源端软键盘模式：源 AndroidManifest 里各 <activity> 的 android:windowSoftInputMode，没写时再看该 activity 主题里的 android:windowSoftInputMode；adjustResize 一类对到 KeyboardAvoidMode.RESIZE（据声明 RESIZE 是布局缩小），adjustPan 一类对到 OFFSET（布局上移）；都没写时按平台缺省在规格里写明选哪一种
未核实：windowSoftInputMode 和 KeyboardAvoidMode 的对应是按两边声明的说明推的，卡里没有验证
