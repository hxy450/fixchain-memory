# Activity 窗口加 FLAG_KEEP_SCREEN_ON 且无清除时，规格写成页面可见期内成对开关

审的是：规格
触发（任一种）：
- 读到：源端 Activity 的 onCreate 里 getWindow().addFlags(FLAG_KEEP_SCREEN_ON)（建议里也点名 FLAG_SECURE 等窗口标志），没有 clearFlags 之类的清除代码；写错的样子：规格的映射行或验收只写「onCreate 时机 setWindowKeepScreenOn(true)」，没写作用范围是该页可见期间，也没写离开该页时设回 false
- 写错的样子：跨栈基线或映射表里的窗口级映射行只写「FLAG_KEEP_SCREEN_ON | window.setWindowKeepScreenOn | —」，备注没写目标窗口全应用共享、须随页面可见性成对开关
适用范围：目标端各页面以 NavDestination 共用 UIAbility 主窗口，把源端某个 Activity 自身窗口的标志映射成窗口级 API 时，规格的映射行、基线行和验收
做法：
- 先写明作用范围：这个效果只在该 Activity 可见（存活）期间生效，离开或 finish 后随窗口自动解除；鸿蒙主窗口全应用共享，setWindowKeepScreenOn(true) 会一直生效到显式设为 false
- 映射行和验收写成成对开关：该页 NavDestination 的 onShown 里 setWindowKeepScreenOn(true)，onHidden 里 setWindowKeepScreenOn(false)；不写「onCreate 时机 setWindowKeepScreenOn(true)」
- 基线表里这类窗口级映射行的备注写上「目标窗口为全应用共享，须随页面可见性成对开关」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- FLAG_KEEP_SCREEN_ON：as long as this window is visible to the user, keep the device's screen turned on and bright：源端标志只在加它的那个窗口对用户可见时生效（出处：android.view.WindowManager.LayoutParams#FLAG_KEEP_SCREEN_ON）
- setWindowKeepScreenOn(isKeepScreenOn: boolean): Promise<void>：Window 的常亮开关，true 开、false 关（出处：鸿蒙 SDK 的 ets/api/@ohos.window.d.ts，Window.setWindowKeepScreenOn）
- onShown(callback: Callback<VisibilityChangeReason>): NavDestinationAttribute；onHidden(callback: Callback<VisibilityChangeReason>): NavDestinationAttribute：NavDestination 页面显示、隐藏时的回调，成对开关挂在这两处（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onShown / onHidden）
- 只开不关时回到上一页后鸿蒙仍持有 windowLock，源端的亮屏锁已释放；改成 onShown 传 true、onHidden 传 false 后离开页面即释放：只写打开的一侧会让常亮作用到整个应用（出处：卡里修好并验证过）
