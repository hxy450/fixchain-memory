# Scaffold 无 topBar 时 innerPadding 含状态栏，规格不能写成只消费底栏

审的是：规格
触发（任一种）：
- 读到：Scaffold 没传 topBar、没改 contentWindowInsets，content 用 Modifier.padding(innerPadding)（常接 .consumeWindowInsets）挂子页；写错的样子：壳页规格写「只消费底栏高度，顶部状态栏由各 Tab 页自行处理」；子页规格消费真实 statusBarHeight 或写「不做顶部占位」
- 读到：宿主已 consumeWindowInsets，子页有 windowInsetsTopHeight(WindowInsets.statusBars…) 或 statusBarsPadding() 的 Spacer；写错的样子：子页规格写「按源码语义消费顶部安全区（statusBars + 56dp）」，和宿主页「宿主统一处理」矛盾
适用范围：规格提取时写 Compose 壳页及嵌套子页的顶部安全区由谁避让时
做法：
- 先核 Scaffold 有无 topBar、是否改 contentWindowInsets，沿 modifier 链逐边写 innerPadding 来源：无 topBar 时 top = 状态栏 inset，有 bottomBar 时 bottom = 底栏高
- 写明 consumeWindowInsets 后子页内 statusBars 为 0、嵌套页整体在状态栏下：statusBars + N 的 spacer 只留 N，statusBarsPadding spacer 不占位；子页没 statusBarsPadding 推不出「不做顶部占位」
- 子页规格写明 statusBarHeight 的来源（innerPadding top）或为 0 的依据，与宿主页对齐；验收写内容块在 [状态栏底, 底栏顶] 内
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 无 topBar 时 innerPadding 含状态栏顶 inset；consumeWindowInsets 之后子页内 statusBars 为 0：源端嵌套页（含其中的浮层）整体落在状态栏之下（出处：卡里修好并验证过）
- Material3 Scaffold 没有 topBar、contentWindowInsets 用默认时，innerPadding.top 就是状态栏高度，bottom 是底栏高度：子页顶部避让来自传入的 modifier，不在子页自己的代码里（出处：卡里修好并验证过）
- 宿主消费后，statusBars + 56.dp 的 spacer 实际只剩 56dp，Spacer(statusBarsPadding) 高度为 0：源端子页的实际留白（出处：卡里修好并验证过）
针对本应用要查的：
- Scaffold 有没有 topBar、contentWindowInsets 是否被改，宿主有没有消费 insets，子页的 innerPadding 每条边来自哪里：源工程里调用 Scaffold 的 Kotlin 文件和项目自定义的 Scaffold 包装（看 topBar、bottomBar、contentWindowInsets 参数），以及 content lambda 里 padding 一路传到嵌套导航或 tab 子页的 modifier 链；没传 topBar 且没改 contentWindowInsets 的，top 记为状态栏 inset；有 bottomBar 的，bottom 记为底栏高；改了 contentWindowInsets 的按它写的 WindowInsets 读；链上有 .padding(padding).consumeWindowInsets(padding) 的，子页的 statusBars 项按 0 记
未核实：Scaffold 默认 contentWindowInsets 含状态栏（具体取值）、consumeWindowInsets 的语义出自 Compose 库代码，本机没有源码，按卡写
