# 铺满的 SurfaceView 未置顶时，规格写区域可见底色，不把容器背景当画布底层 Image

审的是：规格
触发（任一种）：
- 读到：容器有 android:background 位图，布局或 onCreate 的 addView 给它加了铺满的 SurfaceView / GLSurfaceView 子类（FrameLayout 默认铺满），源码搜不到 setZOrderOnTop(true)，每帧先 drawColor(Color.TRANSPARENT, PorterDuff.Mode.CLEAR)；写错的样子：规格写「background=@drawable/… → Stack + 底层 Image(ImageFit.Fill)」「Stack{ 背景Image, 画布 }」，把 drawColor(TRANSPARENT, CLEAR) 对成 clearRect，没写这一区域的可见底色
适用范围：规格里为承载自绘 SurfaceView 的页面确定背景层和画布叠放关系时，SurfaceView 未调用 setZOrderOnTop(true)
做法：
- 按源端最终可见结果判断：默认 Z 序的 SurfaceView 在窗口之下，窗口在它铺满的区域打洞，父容器背景在该区域不可见；规格写明该区域的可见底色（surface 清成透明时为黑），不建背景 Image
- 规格同时注明：ArkUI Canvas 做 clearRect 后会露出下层组件，可见底色要由画布所在容器的 backgroundColor 给出
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- SurfaceView 的 surface 按 Z 序位于持有它的窗口之后，SurfaceView 在窗口上打洞让 surface 显示出来：默认 Z 序下父容器背景在 surface 区域被擦掉（出处：android.view.SurfaceView 类注释）
- setZOrderOnTop(boolean onTop)：通常 surface 在窗口之后，设了才放到窗口之上：要判断的那个调用；源码没调就是默认 Z 序（出处：android.view.SurfaceView#setZOrderOnTop）
- clearRect(x: number, y: number, w: number, h: number): void：清掉矩形区域的绘制内容，清后透出下层组件（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，CanvasRenderer.clearRect）
- 默认 Z 序、每帧 CLEAR 的 SurfaceView 区域在安卓上是黑底；ArkUI 画布 clearRect 后透明，下层背景图会露出来：两端在这一区域的可见结果不同（出处：卡里修好并验证过）
针对本应用要查的：
- surface 区域的可见底色：源工程里该 SurfaceView 子类的 onDraw / 绘制循环开头；开头是 drawColor(Color.TRANSPARENT, PorterDuff.Mode.CLEAR) 或不画底色时为黑；画了实色就取那个颜色
