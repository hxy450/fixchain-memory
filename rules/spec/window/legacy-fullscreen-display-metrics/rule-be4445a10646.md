# 源 targetSdk 低的全屏窗口，规格写明挖孔边留黑和按 1.86 截长边后的内容区

审的是：规格
触发（任一种）：
- 读到：源自绘 View 用 getDisplayMetrics() 的 widthPixels / heightPixels（或 Display.getSize）作几何基准，Activity 只设 FEATURE_NO_TITLE + FLAG_FULLSCREEN，targetSdkVersion 低；写错的样子：规格或台账把几何基准写成「全屏窗口 px 尺寸 − 底部系统避让区高度」，只把导航栏当成两端的差别
- 读到：targetSdkVersion 低于 28 且主题链没有 android:windowLayoutInDisplayCutoutMode，或低于 26 且没声明 android:maxAspectRatio / android.max_aspect；Activity 是 FLAG_FULLSCREEN 全屏；写错的样子：规格没写挖孔边留黑、没写按最大宽高比截长边，源端 DisplayMetrics 参与的公式按整屏取值
适用范围：源应用 targetSdk 较低、Activity 为 FLAG_FULLSCREEN 全屏时，规格（含决策台账）里写窗口区和尺寸基准的那一节
做法：
- 规格逐边写出源 Activity 的应用窗口区：targetSdk<28 且主题链未设挖孔模式时挖孔边留黑；导航栏在窗口外；targetSdk<26 且未声明 maxAspectRatio、android.max_aspect，resizeableActivity 也不为 true 时按 1.86 截长边
- 目标基准写成等价内容区：windowRect 减挖孔边、减底部系统避让，再按宽高比上限截长边；源端 DisplayMetrics 宽高参与的公式按它取值，不写「全屏窗口减底部避让」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- windowLayoutInDisplayCutoutMode 的 default（枚举值 0，对应 LAYOUT_IN_DISPLAY_CUTOUT_MODE_DEFAULT）：只有挖孔完全落在系统栏内时窗口才延伸进挖孔区，否则窗口不与挖孔区重叠：主题链里查的属性；FLAG_FULLSCREEN 隐藏状态栏后，未声明挖孔模式的窗口在挖孔所在边留黑（出处：Android SDK 平台资源 data/res/values/attrs.xml，windowLayoutInDisplayCutoutMode（按应用的 compileSdk 取对应平台））
- LAYOUT_IN_DISPLAY_CUTOUT_MODE_DEFAULT = 0：全屏或横屏时窗口布局不与挖孔区重叠：主题没设挖孔模式时取默认值，全屏窗口避开挖孔边（出处：android.view.WindowManager.LayoutParams#LAYOUT_IN_DISPLAY_CUTOUT_MODE_DEFAULT）
- DEFAULT_PRE_O_MAX_ASPECT_RATIO = 1.86f；targetSdkVersion < O 时作默认最大宽高比（16.7:9），应用声明了 maxAspectRatio 或 meta-data android.max_aspect 时用声明值：旧应用在长屏上截长边的比例和豁免条件（出处：android.content.pm.PackageParser#setMaxAspectRatio；com.android.internal.pm.pkg.parsing.ParsingPackageUtils#setMaxAspectRatio）
- 从 Activity 取的 DisplayMetrics 是当前应用窗口的尺寸；API 34 及以下还减去系统装饰区和挖孔：源端公式里的宽高是内容区，不是整屏（出处：android.view.Display#getMetrics）
- 参照机实测：状态栏隐藏、导航栏保留、挖孔边留黑、按 1.86 截长边：旧 targetSdk 全屏窗口的实际窗口区（出处：卡里修好并验证过）
- 取屏幕减挖孔边与导航避让的内容区，再按 1.86 截长边后，派生的起始空行与参照机一致：修好的做法（出处：卡里修好并验证过）
针对本应用要查的：
- 源应用的 targetSdk、挖孔模式和最大宽高比声明：源工程 AndroidManifest 的 uses-sdk targetSdkVersion（或 Gradle 的 targetSdk）、application/activity 的 android:maxAspectRatio、android:resizeableActivity、meta-data android.max_aspect，以及 Activity 主题链里的 android:windowLayoutInDisplayCutoutMode；targetSdk<28 且无挖孔模式 → 挖孔边留黑；targetSdk<26 且三项声明都没有 → 按 1.86 截长边
未核实：resizeableActivity 不为 true 这一条件按卡写，本机 PackageParser / ParsingPackageUtils 的 setMaxAspectRatio 片段只核了 targetSdk < O 默认 1.86 和声明值优先
