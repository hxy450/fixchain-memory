# 源码里 putString 被注释、改调会话 setter 的设置项，规格登记为会话态，不列进偏好键

审的是：规格
触发（任一种）：
- 读到：源端设置弹窗里写 SharedPreferences 的 editor.putString(...) 被注释掉，旁边改调应用接口上的 setter（只改会话字段），读取处同样是 getString 被注释、改调 getter；写错的样子：规格把这个设置项列进「读写偏好键」清单，验收条目写成「切换写 <偏好键>」，或注「语义见某权威表」而那张表里没有这一项
适用范围：规格提取阶段把源端设置项分成持久偏好键和会话状态时
做法：
- 按源码实际执行的写路径归类：被注释的 editor.putString 和会话 setter 并存时，登记成会话态，写明 setter、getter 和它的消费者（如 setter → getter → 拍照会话），不列入「读写偏好键」
针对本应用要查的：
- 设置项实际走的写路径：源工程里改这个设置的 UI 代码，看 SharedPreferences.Editor 的 put* 调用是否被注释、是否改调应用接口的 setter；再搜这个 setter 对应的 getter 的调用点；只有 put* 在执行路径上的才算持久键；否则记成会话态及其消费者
