# 源端同步读设置、目标端改异步时，源码笔记写异常分支、差异记进 Spec Gap List

审的是：规格
触发（任一种）：
- 读到：安卓源端在首帧前用 SharedPreferences.getString / getInt 带默认值同步读设置，界面没有加载态和失败态；目标端的偏好读取是 async；写错的样子：source-notes 的 presenter 摘要没有“异常分支”一项；Spec Gap List 没记“源端同步读取、目标端异步且可能失败”这一差异
适用范围：源码理解阶段写 source-notes 和 Spec Gap List，源端同步读取在目标端要改成异步时
做法：
- presenter 摘要补“异常分支”，列出目标端改成异步后新增的加载失败路径
- Spec Gap List 记一条平台差异“源端同步读取、目标端异步加载”，至少写明两项：加载期间的交互（完成前阻止交互或不呈现内容）和加载失败的出口（错误与重试，或用默认设置继续）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- String getString(String key, @Nullable String defValue)：源端同步读取，缺键返回默认值（出处：android.content.SharedPreferences#getString）
- function getPreferences(context: Context, name: string): Promise<Preferences>：目标端取偏好实例返回 Promise，可 reject（出处：鸿蒙 SDK 的 ets/api/@ohos.data.preferences.d.ts，preferences.getPreferences）
