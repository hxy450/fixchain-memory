# 源工程 assets/ 下的预置数据

agent 会看到什么：源工程 assets/ 下有按日期等键查表的预置 JSON 或 DB，规格引用它却没写覆盖范围、没和运行期输入比对，或数据流写成「资产 + DAO」而源码实际层层委托到第三方库计算

## 规矩

- rule-42c5b363025a｜规格引用预置数据资产时写明覆盖范围并和运行期输入比对，不足时写替代算法｜读到：源工程 assets/ 下有按日期等键查表的预置 JSON 或 DB；运行期输入是当前日期或用户可选的年份；写错：规格引用了这份资产，却没写它覆盖的起止范围和条数，没和运行期输入域比对；覆盖不足时没写替代算法或降级方案
- rule-d8b998e804d5｜源端数据经 DAO/Helper 层层委托时，规格的数据流只写核实的最终来源，不写走不到的资产无匹配分支｜读到：源码 Repository 委托 Dao，Dao 再委托 Helper，最终实现调第三方库按任意日期计算（如 com.nlf.calendar.Lunar.fromDate）；工程 assets/ 下另有一份预置 JSON；写错：规格数据流写成「资产 + DAO → Repository」，并有「资产查询无匹配时保持为空」的验收条目；同一稿又有「第三方库 → 适配器，同输入同输出」「任意合法日期可转换」的 HARD 映射，两种来源并存
