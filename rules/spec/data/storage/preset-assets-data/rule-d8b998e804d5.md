# 源端数据经 DAO/Helper 层层委托时，规格的数据流只写核实的最终来源，不写走不到的资产无匹配分支

审的是：规格
触发（任一种）：
- 读到：源码 Repository 委托 Dao，Dao 再委托 Helper，最终实现调第三方库按任意日期计算（如 com.nlf.calendar.Lunar.fromDate）；工程 assets/ 下另有一份预置 JSON；写错的样子：规格数据流写成「资产 + DAO → Repository」，并有「资产查询无匹配时保持为空」的验收条目；同一稿又有「第三方库 → 适配器，同输入同输出」「任意合法日期可转换」的 HARD 映射，两种来源并存
适用范围：规格提取阶段描述源端数据流和数据来源，源端经多层委托到第三方库、预置 DB 或网络时
做法：
- 沿 Repository → Dao → Helper 打开最终实现，确认数据来源是第三方库计算、预置 DB 还是网络；数据流里只写已核实的来源
- 源端走不到的分支（如「资产无匹配 → 保持为空」）不写成验收条目
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 源端 Helper 实际逐日用 Lunar.fromDate 生成日期数据，资产 DB 查询已注释；规格写成资产来源后下游只做静态查表：资产文件存在不等于它是运行期数据来源（出处：卡里修好并验证过）
针对本应用要查的：
- 源端日期或业务数据的真实来源：源工程里 Repository 委托的 Dao 类、Dao 委托的 Helper 类的方法体；看最终方法是调第三方库计算、查预置 DB/资产还是请求网络；被注释掉的查询不算来源
