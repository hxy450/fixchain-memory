# 规格把源端公共目录改成沙箱时，同一 AC 写明用户可见性降级并与映射表一致

审的是：规格
触发（任一种）：
- 读到：源端把文件写到 Environment.getExternalStoragePublicDirectory(...) 或封装它的工具方法下的目录（如 Documents 下的日志目录），用户在文件管理里看得到；写错的样子：规格的 AC 写“映射到应用沙箱目录”，同一文件的映射表却写“用户文件目录”，两处矛盾，也没写用户可见性降低了
适用范围：规格为目录、权限这类横切副作用写验收条目时
做法：
- 源端用户可见的公共目录在目标映射到沙箱时，在同一条 AC 里写明“用户不再能在文件管理中看到这些文件”这一降级；映射表与 AC 写成同一个目标目录
- 发现同一文件内 AC 与映射表冲突时，回源码看目录是否用户可见再定，两处改成一致，不挑其中一条
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getExternalStoragePublicDirectory 返回共享存储的顶层目录，是用户自己放置和管理文件的地方：源端目录对用户可见（出处：android.os.Environment#getExternalStoragePublicDirectory）
- 应用沙箱目录：应用默认只能看到自己的应用文件；访问用户文件要走用户文件的方式：映射到沙箱就不再是用户可见目录（出处：app-sandbox-directory.md，应用沙箱目录）
- 应用对用户文件的创建、访问、删除，需要提前获取用户授权，或由用户操作完成：保留用户可见时目标要走用户文件的授权方式（出处：user-file-overview.md，用户文件概述）
