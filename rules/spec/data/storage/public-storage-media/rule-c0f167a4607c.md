# 源端扫 MediaStore.Audio 时，规格写 AudioViewPicker 导入沙箱而非媒体库查询

审的是：规格
触发（任一种）：
- 读到：安卓源码先申请 READ_EXTERNAL_STORAGE / READ_MEDIA_AUDIO，再查询 MediaStore.Audio 列出本地音频；写错的样子：规格或验收条目写成「MediaStore 音频扫描 → MediaLibraryKit 查询音频资产」「READ_EXTERNAL_STORAGE → 音频库读取权限 + requestPermissionsFromUser，拒绝→引导空态」，或把 READ_MEDIA_AUDIO 映射成 READ_AUDIO「按需 user_grant」
适用范围：把安卓 MediaStore.Audio 本地音频扫描迁到鸿蒙、且约束不申请图片/视频媒体权限时，规格里写能力映射、权限和验收条目的地方
做法：
- 规格把本地音频写成：AudioViewPicker 选择导入（new picker.AudioViewPicker(context).select(options)，可多选）→ 把选中的文件复制进应用沙箱 → 页面进入时扫描沙箱里已导入的文件；不写「MediaLibraryKit / photoAccessHelper 查询音频资产」
- READ_EXTERNAL_STORAGE / READ_MEDIA_AUDIO 不映射成音频读取权限门：验收条目不写「未授权→引导空态 + 按钮申请权限」，写「按钮直接拉起音频选择器」
- 目标 API 覆盖哪些资源类型、读取要什么权限核实不了时，登记为待决策项，不写成确定映射
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- PhotoType 只有 IMAGE = 1、VIDEO = 2：photoAccessHelper 的媒体库只管图片和视频，没有音频类型（出处：鸿蒙 SDK 的 ets/api/@ohos.file.photoAccessHelper.d.ts，photoAccessHelper.PhotoType）
- PhotoAccessHelper.getAssets 的 @permission 是 ohos.permission.READ_IMAGEVIDEO：读媒体库要的是图片/视频读取权限，在禁申图片/视频权限的约束下不能用（出处：鸿蒙 SDK 的 ets/api/@ohos.file.photoAccessHelper.d.ts，PhotoAccessHelper.getAssets）
- select(option?: AudioSelectOptions): Promise<Array<string>>：AudioViewPicker 拉起音频选择页，返回选中音频的 URI（出处：鸿蒙 SDK 的 ets/api/@ohos.file.picker.d.ts，AudioViewPicker.select）
- AudioSelectOptions.maxSelectNumber?: number，默认 1，取值 1 到 500：多选导入时设这个值（出处：鸿蒙 SDK 的 ets/api/@ohos.file.picker.d.ts，AudioSelectOptions.maxSelectNumber）
- Picker 接口本身无需申请权限；select() 返回的 URI 是临时只读权限，退出应用后台后失效：不用写权限门；要长期使用的文件得复制进沙箱（出处：select-user-file.md，选择音频类文件）
- ohos.permission.READ_AUDIO：权限级别 system_basic，用户授权；普通应用要通过 ACL 跨级申请：把 READ_MEDIA_AUDIO 对成 READ_AUDIO 权限门，普通应用拿不到（出处：restricted-permissions.md，ohos.permission.READ_AUDIO）
- AudioViewPicker 多选导入 → 复制进沙箱 → AVMetadataExtractor 取时长，进页扫描沙箱；页面删掉权限查询/申请链，按钮直接拉 picker：修好后的做法（出处：卡里修好并验证过）
未核实：卡里的行为在 target SDK 6.1.1(24) 下观察，本机核实用的声明是 API 23
