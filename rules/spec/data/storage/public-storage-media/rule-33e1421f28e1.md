# MediaStore 查询映射到 getAssets 时写明需 READ_IMAGEVIDEO，画廊以自存 URI 为准

审的是：规格
触发（任一种）：
- 读到：源端用 MediaStore 查询最近媒体（scoped storage 下应用天然可见自己保存的媒体），再 loadThumbnail 取缩略图；写错的样子：规格把「MediaStore 查询 / loadThumbnail」映射成 photoAccessHelper.getAssets + getThumbnail，没写读权限，也没写画廊入口以应用自己保存成功的 URI 为准
适用范围：规格阶段把源端最近媒体查询映射到 photoAccessHelper 时，尤其是相机类应用的画廊入口
做法：
- 映射行写明：整库 getAssets 需要 ohos.permission.READ_IMAGEVIDEO（受限权限，普通应用通常拿不到），HarmonyOS 不像 Android scoped storage 那样默认可见应用自己保存的媒体
- 画廊入口写成以应用自己保存成功的 URI 为准：保存后记录并持久化，恢复时解码它
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getAssets(options: FetchOptions): Promise<FetchResult<PhotoAsset>>，@permission ohos.permission.READ_IMAGEVIDEO：整库查询要这个权限，缺权限报 201（出处：鸿蒙 SDK 的 ets/api/@ohos.file.photoAccessHelper.d.ts，PhotoAccessHelper.getAssets）
- READ_IMAGEVIDEO：权限级别 system_basic，授权方式 user_grant，列在受限权限里：普通应用要走受限权限申请（出处：restricted-permissions.md，ohos.permission.READ_IMAGEVIDEO）
- 推荐方案（无需申请权限）是用 Picker 读、用保存控件 / 授权弹窗保存；受限使用方案才申请 READ_IMAGEVIDEO：不申请受限权限时的替代（出处：app-permission-group-list.md，读写媒体库中的图片或视频的替代方案）
- 工程不声明 READ_IMAGEVIDEO 时设备上 getAssets 失败；改为以自存 URI 恢复后画廊入口正常：不写明权限的后果和落法（出处：卡里修好并验证过）
未核实：卡里环境是 API 24，声明按本机 API 23 核对；文档写明 API 26.0.0 起该权限只能读本地公共目录
