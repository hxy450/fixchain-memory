# 规格映射 MediaStore 时写明 WRITE_IMAGEVIDEO 受限和相机资产路线

审的是：规格
触发（任一种）：
- 读到：源端用 `MediaStore` insert（`IS_PENDING` 两段写）或 `MediaRecorder` 输出文件保存照片、视频；写错的样子：映射行只写「photoAccessHelper PhotoAsset 创建/提交（IS_PENDING 两段写）」，没写 WRITE_IMAGEVIDEO 是受限开放权限、能否获得，也没写相机拍摄走系统资产路线
适用范围：规格提取和知识准备阶段，写 MediaStore→photoAccessHelper 的映射行和保存路线时
做法：
- 映射行写明：WRITE_IMAGEVIDEO 为受限开放权限，要 ACL 申请和签名授权，不能只靠 module.json5 声明加运行时请求获得
- 写明保存路线：相机拍的照片和视频走相机系统资产（photoAssetAvailable + saveCameraPhoto），应用自己生成的图片走用户授权的保存控件或弹窗
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- WRITE_IMAGEVIDEO：权限级别 system_basic，授权方式 user_grant，列在受限开放权限里：规格里要写的权限性质（出处：restricted-permissions.md，ohos.permission.WRITE_IMAGEVIDEO）
- showAssetsCreationDialog(srcFileUris: Array<string>, photoCreationConfigs: Array<PhotoCreationConfig>): Promise<Array<string>>：建议里「用户授权的弹窗」对应的接口：弹窗让用户确认保存（出处：鸿蒙 SDK 的 ets/api/@ohos.file.photoAccessHelper.d.ts，PhotoAccessHelper.showAssetsCreationDialog）
- 相机照片、视频走 photoAssetAvailable + saveCameraPhoto 后，没有签名授权也能存入相册：规格里该指定的相机保存路线（出处：卡里修好并验证过）
未核实：应用自生成图片走保存控件或弹窗这条路线卡里没有上机验证
