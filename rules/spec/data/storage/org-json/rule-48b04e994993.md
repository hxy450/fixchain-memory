# 规格写导入、恢复流程时按源循环里解析和写库的先后写中止语义

审的是：规格
触发（任一种）：
- 读到：源码恢复流程在 for 循环里逐条 getJSONObject → 解析 → insert → getJSONArray(子项) → insertAll；写错的样子：规格写「解析先于任何 DB 写入，不产生部分导入」或称「源端解析在循环外先行」
适用范围：规格提取阶段描述备份恢复、批量导入流程时
做法：
- 按源码循环中解析和写库的实际先后写中止语义：逐条插入、遇错即停、已插入的保留；不把「先全量校验再写库」写成源行为
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getJSONArray 遇缺键或 JSON null 抛 JSONException：循环里某条子项缺失时，这条及之后的都不再插入，前面已插入的保留（出处：org.json.JSONObject#getJSONArray）
针对本应用要查的：
- 源端恢复的中止点：源工程恢复流程（协程或线程）里的循环体；看每条的解析和 insert 是否在同一次迭代里、异常在哪一层被捕获，按此写「遇错即停、已插入保留」或其他语义
