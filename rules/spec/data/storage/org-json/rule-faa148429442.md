# 源端用 org.json 解析时，规格逐项写宽松语法、取值类型校验和 null 转换并各写 AC

审的是：规格
触发（任一种）：
- 读到：源码 new JSONObject(...) 后 getJSONObject("…") / getString(...)（org.json）；写错的样子：映射写「org.json.JSONObject → JSON.parse + 显式 class」并标「纯语言构造」；AC 只列非法 JSON、缺字段、空对象，没有宽松语法、getJSONObject 的类型校验和 getString 对 null 的取值
适用范围：源端用 org.json（JSONObject / JSONTokener）解析输入、目标改用 JSON.parse 时规格里的映射行和 AC
做法：
- 映射行不标纯语言构造，写明 JSON.parse 比 org.json 严格，逐项列出源库的宽松语法（注释、单引号或不带引号的字符串、= / => / ; 分隔等）、getJSONObject 取到的不是对象就抛异常、getString 遇 JSON null 得到字符串 "null"
- 宽松语法、类型校验失败、null 取值各写一条失败或取值 AC
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- JSONTokener 宽松：忽略 // 与 # 行注释、/* */ 注释，接受不带引号或单引号字符串、0x 十六进制、0 开头八进制、; 分隔数组元素、多余分隔符（当作 null）、= 或 => 分隔键值、; 分隔键值对：源库能解析而 JSON.parse 会拒绝的写法（出处：org.json.JSONTokener（类注释））
- getJSONObject(name)：值不是 JSONObject 时 throw JSON.typeMismatch(name, object, "JSONObject")：取到的字段不是对象就解析失败（出处：org.json.JSONObject#getJSONObject）
- getString(name)：经 JSON.toString 取值，非字符串用 String.valueOf 转换；JSON null 是 JSONObject.NULL，toString 返回 "null"：getString 遇 null 得到字符串 "null"，遇数字、布尔得到它们的字符串形式（出处：org.json.JSONObject#getString；org.json.JSON#toString；org.json.JSONObject#NULL）
