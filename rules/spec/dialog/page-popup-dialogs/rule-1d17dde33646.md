# 界面只由外部库方法加 Config 渲染时，规格写明布局来自依赖库、列全配置字段和结构基准

审的是：规格
触发（任一种）：
- 读到：源端只调用外部库或 SDK 的模板方法，传入 Config / Builder 对象（标题、条目数组、图标、勾选/未勾选图、链接色、链接回调）；工程 layout 和合成的 view.xml 里都没有这个界面的结构；写错的样子：页面规格只写界面大意（如「隐私概要弹框、协议链接与同意/拒绝操作」）和「SDK … Dialog → CustomDialogController」一类映射；没写布局由依赖库提供，没列配置字段，也没列实现前要取得的结构基准
适用范围：规格提取时，遇到由第三方库或 SDK 渲染、工程源码里没有布局的界面
做法：
- 页面规格里写明「布局由依赖库提供、工程源码无结构」，并写出依赖库的坐标
- 列出全部配置字段及其语义：条目、图标、勾选/未勾选图（协议确认状态）、链接色和链接回调（可点的协议文本）
- 把依赖 AAR 的 res/layout 与 res/values 里的字符串，或安卓实机截图，列为实现前必须取得的结构基准
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 以安卓截图为基准重构后，配置条目不在首屏面板上作独立分区；面板有问候、说明、类别行，操作区是弱化的拒绝文字加带勾选图标的主操作，协议是文内可点链接：配置字段和可见结构不是一一对应的（出处：卡里修好并验证过）
针对本应用要查的：
- 依赖库的坐标和版本：源工程模块的 Gradle 构建脚本里 dependencies 块，按模板方法所在包名找对应的那一行；读出 group:artifact:version，写进规格
来源：1 张卡，1 个应用
