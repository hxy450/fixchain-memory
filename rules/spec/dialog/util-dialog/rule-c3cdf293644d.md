# 规格登记经工具方法弹出的主弹窗及其确认弹窗，写明布局、图标和按钮分支

审的是：规格
触发（任一种）：
- 读到：源端页面经工具类的静态方法弹对话框，主弹窗里的按钮还会再弹确认弹窗；写错的样子：规格的弹窗清单或页面契约只登记了确认弹窗，或只列了弹窗的状态变量，没写主弹窗用的布局、图标资源和每个按钮的分支
- 读到：调用方 lambda 只传了接受回调；写错的样子：源码理解笔记写「只有接受回调，没有 decline / 拒绝路径」，没有打开被调的弹窗方法核对
适用范围：整理页面弹窗清单、写源码理解笔记时，对经工具方法弹出的对话框
做法：
- 在父页面契约里给主弹窗和它的确认弹窗各登记一项：源布局、列表项和图标资源、按钮文案、每个按钮的回调分支（如 不同意→确认弹窗→退出进程）
- 笔记里「有没有拒绝路径」的结论，依据被调方法内部的按钮回调写，不凭调用方 lambda 写
针对本应用要查的：
- 主弹窗和确认弹窗各用哪个布局、哪些图标：源工程里被调的弹窗工具方法和它 inflate 的布局 XML、列表项布局；把布局名、@drawable 引用、按钮的 @string 和点击回调的去向抄进契约条目
