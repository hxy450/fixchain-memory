# 源端 MaterialDialog / AlertDialog / Dialog 主题窗口，规格映射为独立弹窗并记按钮

审的是：规格
触发（任一种）：
- 读到：源码里有 MaterialDialog.Builder、MaterialAlertDialogBuilder、AlertDialog.Builder 构造的确认、单选（setSingleChoiceItems）或 customView 对话框，或 manifest 里 Activity 用 Theme.*.Dialog 主题；写错的样子：规格决策表写「→ bindSheet」「→ 页内弹层（无独立页面）」「Select 弹层」，没读对话框构造就改了形制，也没记 positive / negative / neutral 按钮文案和 cancelable
适用范围：规格提取时，为源端对话框和 Dialog 主题 Activity 选目标弹窗形制的决策表
做法：
- 默认映射为独立弹窗：CustomDialog（openCustomDialog / CustomDialogController）或 Dialog 形态页，不写 bindSheet 或页内 overlay
- 要改形制，先读到对话框的构造代码，并在决策表写明理由
- 每个对话框记下按钮集合（positive / negative / neutral 的文案，没设的写「无」）和 cancelable
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- AlertDialog 的按钮文案为空时该按钮 setVisibility(View.GONE)：源端没设文案的按钮不出现，按钮集合要照构造代码记（出处：com.android.internal.app.AlertController#setupButtons）
- openCustomDialog<T extends Object>(dialogContent: ComponentContent<T>, options?: promptAction.BaseDialogOptions): Promise<void>：独立弹窗的一种写法（UIContext 的 PromptAction）（出处：鸿蒙 SDK 的 ets/api/@ohos.arkui.UIContext.d.ts，PromptAction.openCustomDialog）
- constructor(value: CustomDialogControllerOptions)：独立弹窗的另一种写法：CustomDialogController（出处：鸿蒙 SDK 的 ets/component/custom_dialog_controller.d.ts，CustomDialogController.constructor）
针对本应用要查的：
- 每个对话框的构造和按钮：源工程里弹出对话框的 Java / Kotlin 方法，按 MaterialDialog.Builder、MaterialAlertDialogBuilder、AlertDialog.Builder 找；读 positiveText / negativeText / neutralText 或 setPositiveButton / setNegativeButton / setNeutralButton、setCancelable / cancelable 的调用，逐项记
