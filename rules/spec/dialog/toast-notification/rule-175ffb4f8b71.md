# 源端只经通知或 Toast 把接口返回的数据交给用户时，规格的 AC 写明它怎么呈现给用户

审的是：规格
触发（任一种）：
- 读到：源端接口的成功回调（如 onData）把返回的数据（如验证码）交给发 Notification 或 Toast 的调用，界面本身不显示这个值；写错的样子：规格只列了接口签名（如返回 Promise<string>）和「请求某数据」的 AC，没写返回的数据以什么方式交给用户
适用范围：迁移源端经通知、Toast 等平台副通道把接口返回数据交给用户的流程时，规格里这个功能的 AC
做法：
- 逐个看源端对接口返回值的消费（成功回调的参数交给了谁）；数据只经通知、Toast 交给用户的，在 AC 里写一条：「接口成功后，返回的<数据>以<承接方式>交给用户」，承接方式写确切（回填到某输入框、Toast 显示）
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 接口返回值非空时写入验证码输入框，用户不看日志也能继续登录、注册：一种已验证可行的承接方式（回填），可写进 AC（出处：卡里修好并验证过）
