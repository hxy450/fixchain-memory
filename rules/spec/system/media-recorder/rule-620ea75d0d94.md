# 抽取 onInfo 这类多分支事件处理时，每个 what 分支都写验收或写明跳过理由

审的是：规格
触发（任一种）：
- 读到：源端 MediaRecorder.OnInfoListener 的 onInfo(mr, what, extra) 按 what 分 MAX_DURATION_REACHED、MAX_FILESIZE_REACHED、APPROACHING、NEXT_OUTPUT_FILE_STARTED，并再按是否自动重启分支；写错的样子：规格只为部分分支写了 AC，缺「未开启自动重启时到达文件上限即停止」，或写成「到达上限走某条重启 AC」
适用范围：规格提取阶段抽取源端多分支事件处理函数时
做法：
- 按源端 if/else 链逐支列出，每个 what 分支（含未开启自动重启、到达文件上限即停止）各写一条 AC，或写明跳过理由
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- void onInfo(MediaRecorder mr, int what, int extra)：源端事件分发的入口，what 是事件码（出处：android.media.MediaRecorder.OnInfoListener#onInfo）
- MEDIA_RECORDER_INFO_MAX_DURATION_REACHED = 800、MAX_FILESIZE_REACHED = 801、MAX_FILESIZE_APPROACHING = 802、NEXT_OUTPUT_FILE_STARTED = 803：onInfo 里要逐个覆盖的 what 码（出处：android.media.MediaRecorder#MEDIA_RECORDER_INFO_MAX_FILESIZE_REACHED）
