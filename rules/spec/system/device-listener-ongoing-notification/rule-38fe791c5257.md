# 同一源监听有多个消费者时，规格按生命周期拆开写契约，常驻通知随开关与许可、指定唯一发布服务

审的是：规格
触发（任一种）：
- 读到：Fragment 里注册一次设备监听且不注销，连接、断开、电量回调在开关为真时以固定通知 ID、setOngoing(true) 更新通知；二级页的监听随页面注销且不发通知；写错的样子：规格只写「监听按页面生命周期订阅/注销」，把常驻通知也归进页面生命周期；没有单列「随通知开关 + 系统许可、冷启动恢复、关开关才撤销」的应用级契约，也没指定唯一发布服务
适用范围：规格提取阶段为由开关控制、由设备事件驱动的常驻通知写订阅归属与生命周期时
做法：
- 按消费者拆开写：页面列表、弹窗随页面订阅；常驻通知随「通知开关 + 系统许可」，是应用级的——冷启动时偏好开启就恢复，只有关闭开关才撤销
- 规格里指定唯一的通知发布服务，写明哪些回调经它发布，页面 ViewModel 不直接发布
针对本应用要查的：
- 源端监听的注册与注销位置、哪些回调发通知：源工程里注册、注销这个设备监听的 Fragment、Activity，以及通知帮助类的调用点；逐个消费者记下注册点、有无注销、回调里是否调通知，按此分成页面级和应用级两类契约
