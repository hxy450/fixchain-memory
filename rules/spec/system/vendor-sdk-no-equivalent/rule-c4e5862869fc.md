# 源端依赖高德 com.amap.api.* 时，C8 决策先查厂商鸿蒙 SDK，写明 ohpm 包、版本和 Key 前置

审的是：规格
触发（任一种）：
- 读到：Android 工程依赖 com.amap.api.*（高德地图、定位、搜索、导航 SDK），api-inventory 或 feature spec 写着高德能力，skill 映射表把高德列为 hmos-sdk-docs 的厂商 SDK；写错的样子：决策台账的 C8 决策写「优先 HarmonyOS Kit；无等价能力时使用 Web/H5 或受控降级」，依据是「未提供 SDK 资料」或用户只答「采用建议」，没有厂商鸿蒙 SDK 这一档，「鸿蒙等价 SDK 可用性」的风险项被标 answered 关闭
适用范围：规划阶段为源端厂商 SDK（地图、定位、POI、导航）做三方依赖决策、写进决策台账时
做法：
- 先按 hmos-sdk-docs 或 grill-with-docs 查厂商鸿蒙 SDK（高德开放平台的 HarmonyOS NEXT 文档、ohpm 上 @amap/amap_lbs_common / map3d / search / location / navi），把包名与版本写进决策台账的事实段；用户只答「采用建议」时该项标 needs_doc_lookup 继续查，不用这句回复关闭验证项
- 决策写成有序候选：HarmonyOS Kit → 厂商鸿蒙 SDK → Web/H5 → 受控降级，不跳过厂商 SDK 这一档
- 查到厂商包时，决策写明依赖包、版本和前置条件：高德 Harmony Key 须按鸿蒙签名的 App ID 另行申请，按密钥策略放本地配置、缺失时显式失败；Key 列为待用户提供项
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- @amap/amap_lbs_common、@amap/amap_lbs_map3d、@amap/amap_lbs_search、@amap/amap_lbs_location、@amap/amap_lbs_navi：高德的鸿蒙 ohpm 包；返修时声明这些依赖、配置 Key 并初始化后接入了地图、POI 和路线（出处：卡里修好并验证过）
- 高德 Harmony Key 要绑定鸿蒙签名另行申请，安卓的 Key 不能直接用：接入的前置条件，列为待用户提供项（出处：卡里修好并验证过）
针对本应用要查的：
- 高德鸿蒙 ohpm 包的版本：ohpm 仓库上 @amap/amap_lbs_* 各包的版本信息，或高德开放平台 HarmonyOS NEXT 开发文档；取与目标工程 SDK 兼容的版本，写进决策台账和 oh-package.json5 的 dependencies；例：卡里返修声明的是 11.2.0
