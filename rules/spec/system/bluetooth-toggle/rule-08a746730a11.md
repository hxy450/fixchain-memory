# 蓝牙开关的鸿蒙契约写明 API 20 版本分支、用户拒绝的错误码和回读方式

审的是：规格
触发（任一种）：
- 读到：源端点击开关调 BluetoothAdapter.enable() / disable()，再由广播回调更新开关和列表；写错的样子：规格里蓝牙开关的契约只写一种调用，没写 API 20+ 与低版本的分支，没写用户拒绝或未响应时怎么处理，也没写操作后用什么回读真实状态
适用范围：规格里写鸿蒙端应用内开关蓝牙的契约时
做法：
- 契约写：API 20+ 用 access.enableBluetoothAsync() / access.disableBluetoothAsync()（ACCESS_BLUETOOTH，应用内弹系统确认），处理错误码 2900013（用户未响应）、2900014（用户拒绝）；低版本用 access.enableBluetooth() / disableBluetooth() 或设置页兜底
- 写明操作后以 access.on('stateChange', …) 或 access.getState() 回读真实状态再更新开关
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function enableBluetoothAsync(): Promise<void>（@since 20）：API 20+ 的应用内开蓝牙，带系统确认（出处：鸿蒙 SDK 的 ets/api/@ohos.bluetooth.access.d.ts，access.enableBluetoothAsync）
- 2900013 - The user does not respond.；2900014 - User refuse the action.：异步开关接口的用户未响应、用户拒绝错误码（出处：鸿蒙 SDK 的 ets/api/@ohos.bluetooth.access.d.ts，access.enableBluetoothAsync 的 @throws）
- function getState(): BluetoothState：读当前蓝牙状态（@since 13 的说明不再列权限）（出处：鸿蒙 SDK 的 ets/api/@ohos.bluetooth.access.d.ts，access.getState）
- function on(type: 'stateChange', callback: Callback<BluetoothState>): void：订阅蓝牙状态变化（出处：鸿蒙 SDK 的 ets/api/@ohos.bluetooth.access.d.ts，access.on('stateChange')）
- STATE_OFF = 0、STATE_TURNING_ON = 1、STATE_ON = 2、STATE_TURNING_OFF = 3、STATE_BLE_TURNING_ON = 4、STATE_BLE_ON = 5、STATE_BLE_TURNING_OFF = 6：BluetoothState 的全部取值，回读映射要覆盖（出处：鸿蒙 SDK 的 ets/api/@ohos.bluetooth.access.d.ts，access.BluetoothState）
- 构建提示该接口为 API 20+，保留运行时版本分支与设置页兜底：修好后的契约要点（出处：卡里修好并验证过）
针对本应用要查的：
- 要不要写低版本分支：目标工程的 build-profile.json5 里 compatibleSdkVersion；兼容版本低于 20 时契约写同步接口或设置页兜底；不低于 20 时可只写异步接口
未核实：修复的写入不在卡的材料内，最终实现以分析推荐和构建说明为据，没见上机确认系统确认弹窗的行为
