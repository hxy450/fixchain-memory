# 源端直接开关蓝牙的 BluetoothAdapter.enable / disable

agent 会看到什么：源码里点击开关直接调 BluetoothAdapter.enable() / disable()，规格或验收条目里写的是蓝牙开关在鸿蒙上的契约（走系统设置、只写一种调用、没写回读）

## 规矩

- rule-7cc10c01b3c7｜源端应用内直接开关蓝牙时，规格先查 access 声明，不把现有跳设置的实现当平台限制｜读到：源码或可达图里点击开关直接调用 BluetoothAdapter.enable() / disable()；决策台账只允许「平台不允许应用直接完成的开关」改走系统授权弹窗或设置跳转；现有鸿蒙代码的开关是打开系统蓝牙设置；写错：规格写「蓝牙开关走系统设置并在返回时回读」、验收条目写「进入系统设置并回读」，或把这条外部边归为 `PLATFORM_EQUIVALENT`，却没有引用目标 SDK 的声明说明平台不允许
- rule-08a746730a11｜蓝牙开关的鸿蒙契约写明 API 20 版本分支、用户拒绝的错误码和回读方式｜读到：源端点击开关调 BluetoothAdapter.enable() / disable()，再由广播回调更新开关和列表；写错：规格里蓝牙开关的契约只写一种调用，没写 API 20+ 与低版本的分支，没写用户拒绝或未响应时怎么处理，也没写操作后用什么回读真实状态
