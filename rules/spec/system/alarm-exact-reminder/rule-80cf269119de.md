# 规格写代理提醒替代路径时逐字段对照 reminderAgentManager 声明，不嫁接通知按钮的 wantAgent

审的是：规格
触发（任一种）：
- 读到：源端 AlarmManager 精确闹钟到点自绘通知，按钮各带 PendingIntent（贪睡 = 现在加偏好分钟、推迟 = 弹选择器）；写错的样子：规格把提醒按钮写成 actionButton{title, wantAgent = 拉起 UIAbility 的 Want}，或以「系统托管」裁决降级到点副作用和开机恢复，没写发布失败码、有效提醒条数上限、到点无回调
适用范围：规格阶段把 AlarmManager 加 PendingIntent 按钮加通知渠道映射到 reminderAgentManager / notificationManager、写替代路径决策时
做法：
- 逐字段对照目标模块自己的声明：reminderAgentManager.ActionButton 只有 title、titleResource、type（ActionButtonType 只有 CLOSE、SNOOZE），按钮级 wantAgent 只在 notificationManager 的 NotificationActionButton 上；不跨模块嫁接字段
- 同一行写明平台的等价手段（贪睡用 ReminderRequest.timeInterval / snoozeTimes，按钮点击用 subscribeReminderState，必要时 notificationManager 本地通知）和限制（publishReminder 失败码、有效提醒条数上限、到点无回调），再决定要不要应用侧回退
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- ActionButton { title: string; titleResource?: string; type: ActionButtonType }：提醒按钮只有这三个字段，没有 wantAgent（出处：鸿蒙 SDK 的 ets/api/@ohos.reminderAgentManager.d.ts，reminderAgentManager.ActionButton）
- ActionButtonType：ACTION_BUTTON_TYPE_CLOSE = 0、ACTION_BUTTON_TYPE_SNOOZE = 1：提醒按钮只能是关闭或贪睡（出处：鸿蒙 SDK 的 ets/api/@ohos.reminderAgentManager.d.ts，reminderAgentManager.ActionButtonType）
- ReminderRequest.wantAgent?: WantAgent：点通知本体时跳转的目标，不是按钮级的（出处：鸿蒙 SDK 的 ets/api/@ohos.reminderAgentManager.d.ts，reminderAgentManager.ReminderRequest.wantAgent）
- NotificationActionButton { title: string; wantAgent: WantAgent }：按钮级跳转只在 notificationManager 的本地通知上（出处：鸿蒙 SDK 的 ets/api/notification/notificationActionButton.d.ts，NotificationActionButton）
- publishReminder(reminderReq: ReminderRequest): Promise<number>；1700001 通知未开启，1700002 提醒个数超限：发布失败码（出处：鸿蒙 SDK 的 ets/api/@ohos.reminderAgentManager.d.ts，reminderAgentManager.publishReminder）
- 普通应用最多 30 个有效提醒；三方应用 actionButton 最多两个按钮：条数和按钮数上限（出处：agent-powered-reminder.md，约束与限制；js-apis-reminderAgentManager.md，ReminderRequest）
- timeInterval 单位 s，最少 30s；snoozeTimes 默认 0 次（都不适用于倒计时提醒）：贪睡的等价字段（出处：js-apis-reminderAgentManager.md，ReminderRequest）
未核实：卡里环境是 API 24，声明按本机 API 23 核对
