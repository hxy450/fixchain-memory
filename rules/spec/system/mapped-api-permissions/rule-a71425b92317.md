# 写权限契约前按每个已映射的系统 API 查 @permission，不因安卓免权限就写空

审的是：规格
触发（任一种）：
- 读到：源端用 ClipboardManager 读剪贴板、NfcAdapter 读标签等无需运行时权限的系统服务；写错的样子：规格或功能基线写「requestPermissions 为空」「…免权限」，没逐个查已映射接口的 @permission（如 pasteboard 的 getData 需要 ohos.permission.READ_PASTEBOARD）
适用范围：规格阶段写目标端权限契约（module.json5 要声明哪些权限）时
做法：
- 对映射表里每个目标系统接口，在 SDK d.ts 注释里查 @permission，把权限连同用到它的功能写进权限契约：如 SystemPasteboard.getData / getDataSync 需要 ohos.permission.READ_PASTEBOARD，tag.registerForegroundDispatch 等 NFC 接口需要 ohos.permission.NFC_TAG
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getData(): Promise<PasteData> 和 getDataSync(): PasteData 标注 @permission ohos.permission.READ_PASTEBOARD：读剪贴板要声明这个权限（出处：鸿蒙 SDK 的 ets/api/@ohos.pasteboard.d.ts，SystemPasteboard.getData、SystemPasteboard.getDataSync）
- ohos.permission.READ_PASTEBOARD 列在受限开放权限里，权限级别 system_basic，授权方式 user_grant：不只是在配置里写一行，还要按受限权限和用户授权处理（出处：restricted-permissions.md，ohos.permission.READ_PASTEBOARD）
- registerForegroundDispatch 等 tag 接口标注 @permission ohos.permission.NFC_TAG：NFC 标签接口要声明这个权限（出处：鸿蒙 SDK 的 ets/api/@ohos.nfc.tag.d.ts，tag.registerForegroundDispatch）
针对本应用要查的：
- 其他已映射接口要不要权限：鸿蒙 SDK ets/api 下对应模块的 .d.ts，按方法名找它最后一段注释；有 @permission 行就把权限名写进契约；没有就记为免权限并注明查过的符号
未核实：卡里的环境是 HarmonyOS SDK 6.1.1(24)，@permission 按本机 API 23 的声明核实
