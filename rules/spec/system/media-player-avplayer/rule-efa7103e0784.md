# 源端播放器用到缓冲态、缓冲位或共享实例时，规格把 AVPlayer+XComponent 写成唯一路线

审的是：规格
触发（任一种）：
- 读到：ExoPlayer / media3 的 Player.Listener 区分 STATE_BUFFERING / STATE_READY，轮询 bufferedPosition，Lifecycle ON_PAUSE / ON_RESUME 暂停恢复，feed 多卡共享一个 ExoPlayer；写错的样子：转换决策写「ExoPlayer + PlayerView → Video 组件（或 AVPlayer + XComponent）」，理由写「Video 组件自带播放/缓冲状态回调」，三态由 onPrepared / onError / onLoading 驱动
适用范围：规格提取阶段为视频查看器、feed 内嵌视频确定播放器路线时
做法：
- 写决策前列出源端实际用到的播放器能力（BUFFERING / READY 状态、bufferedPosition、多卡共享实例、前后台暂停恢复），逐项核对候选组件的公开 API
- 需要缓冲事件、缓冲位或共享实例时，决策只写 AVPlayer + XComponent 一条路线，不写「Video 组件（或 AVPlayer）」，也不写未经核实的「Video 组件自带缓冲回调」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- VideoAttribute 的事件只有 onStart、onPause、onFinish、onFullscreenChange、onPrepared、onSeeking、onSeeked、onUpdate、onError、onStop：Video 组件没有缓冲事件，也拿不到缓冲位置（出处：鸿蒙 SDK 的 ets/component/video.d.ts，VideoAttribute）
- on(type: 'bufferingUpdate', callback: OnBufferingUpdateHandler): void：AVPlayer 有缓冲事件（网络播放场景）（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，AVPlayer.on('bufferingUpdate')）
