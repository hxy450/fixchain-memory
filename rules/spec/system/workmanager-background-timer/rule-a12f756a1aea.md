# 后台计时降级只降执行载体，回前台的跨步推进、需输入停顿和完成判定写进替代路径和 AC

审的是：规格
触发（任一种）：
- 读到：源端 WorkManager `Worker` 在后台跨步推进计时：一步到时递归启动下一步、需用户输入的步发通知后停住、末步发完成通知，用 `SystemClock.elapsedRealtime()` 计偏移；写错的样子：规格的降级替代路径和 AC 只锚定 {当前步, 剩余时长, 锚点时间}，回前台「从剩余时长续跑」，没规定后台时长越过当前步时如何跨步、停在需输入步、判完成
适用范围：规格提取阶段，为源端持久化后台计时任务写平台差异替代方案、降级决策和差异 AC 时
做法：
- 把源后台任务拆成「执行载体」和「可观察语义」：只降级平台确实不支持的载体（后台持续 tick）；回前台的跨步推进、需输入步停顿、完成判定写成按锚点 + 步骤表纯计算复现，写进替代路径和 AC
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 按 Worker 语义从锚点生成计时段、需输入等待段和完成段：修复后的回前台重算方式（出处：卡里修好并验证过）
