# CameraKit 没有 AE 状态事件时，规格写明前屏补光等待的回退时序和触发方

审的是：规格
触发（任一种）：
- 写错的样子：规格或源码理解笔记只写「AE 状态不可观测 → 走 fake-precapture 近似」，没写补光等待的回退时长、与 AE 驱动时序的差异，也没说由谁触发
适用范围：规格里写前屏补光拍照时序的那一项，目标相机接口没有曝光状态事件时
做法：
- 规格写明：开补光后按源端旧相机路径的固定回退时长等待再拍，标注这与 Camera2 由 AE 收敛驱动的时序不同，并指明由拍照编排一侧触发
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 首次调用时开补光，按旧相机路径的回退时长等待后再拍：修好后编排器的时序（出处：卡里修好并验证过）
针对本应用要查的：
- 源端补光等待的回退时长：源工程旧相机 API（Camera1）路径的拍照函数里，开前屏补光后延时再拍的那段；读出延时毫秒数写进规格。例：某实现是 1000ms
来源：1 张卡，1 个应用
