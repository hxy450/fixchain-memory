# 源端 SoundPool 预加载短音效时，规格映射和决策候选写 media.createSoundPool

审的是：规格
触发（任一种）：
- 读到：源端 import android.media.SoundPool，new SoundPool(...) 或 SoundPool.Builder，初始化时 load、事件发生时 play，两者分开调用；写错的样子：跨栈映射写成 SoundPool → AVPlayer 实例池（每次播放新实例）+ fdSrc，服务层写「每次调用新建 AVPlayer 实例，prepared 后 start，播完 release」；或选型决策的候选里没有 media.SoundPool
适用范围：规格里为源端 SoundPool 短音效选目标播放器、写跨栈映射行和选型决策时
做法：
- 映射行写 new SoundPool(maxStreams, streamType, srcQuality) → media.createSoundPool(maxStreams, { usage: audio.StreamUsage.STREAM_USAGE_MUSIC, rendererFlags: 0 })（STREAM_MUSIC 对应 STREAM_USAGE_MUSIC，srcQuality 不映射）；源端 load 对应初始化时 soundPool.load(fd, offset, length)，play 对应事件时 soundPool.play(soundID)
- 选型决策的候选里列上 media.SoundPool 并写明取舍；写「含 d.ts 查证」的，附上 createSoundPool 的查询结果
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function createSoundPool(maxStreams: number, audioRenderInfo: audio.AudioRendererInfo): Promise<SoundPool>：目标端的音频池；maxStreams 取 1 到 32 的整数（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，media.createSoundPool）
- usage 为 STREAM_USAGE_UNKNOWN、STREAM_USAGE_MUSIC、STREAM_USAGE_MOVIE、STREAM_USAGE_AUDIOBOOK 时，SoundPool 播短音用混音模式，不打断其他音频：对应源端 STREAM_MUSIC 的不抢焦点混播（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，media.createSoundPool）
- SoundPool 支持解码后 1MB 以下的音频，超过的只播前 1MB（44.1kHz 16bit 立体声约 5.6 秒）：选 SoundPool 的适用边界：短音效（出处：using-soundpool-for-playback.md，使用SoundPool播放短音频(ArkTS)）
- public SoundPool(int maxStreams, int streamType, int srcQuality)；srcQuality 目前不起作用：源端构造三个参数的含义（出处：android.media.SoundPool#SoundPool）
- 每次新建 AVPlayer 走 create → fdSrc → prepare → play，触发到出声约 290ms；改成 createSoundPool 预加载后约 40ms：选型的依据（出处：卡里修好并验证过）
针对本应用要查的：
- 源端的 maxStreams 和 streamType：源工程 Java/Kotlin 里 new SoundPool(...) 的前两个参数，或 SoundPool.Builder 的 setMaxStreams、setAudioAttributes；maxStreams 原样写进 createSoundPool 第 1 个参数；streamType 按用途换成 audio.StreamUsage 的对应项（例：STREAM_MUSIC 写 STREAM_USAGE_MUSIC）
