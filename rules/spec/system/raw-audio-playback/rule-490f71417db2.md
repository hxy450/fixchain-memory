# 规格写 rawfile 音视频设源契约时写 getRawFd 到 fdSrc，不写 url=fd://

审的是：规格
触发（任一种）：
- 读到：安卓源端用 SoundPool.load(context, R.raw.x) 或 MediaPlayer.create(context, R.raw.x) 播 res/raw 资源，目标改为 AVPlayer 播 resources/rawfile；写错的样子：规格实现映射的契约列写「资源经 getRawFd → url=fd://」，或同一格里只给其中一个 API（如 setVolume）标 d.ts 依据，设源方式没有依据
适用范围：规格阶段为应用包内 rawfile 的音频、视频资源写平台 API 映射契约时
做法：
- 契约列写成：resourceManager.getRawFdSync(name)（或 getRawFd）→ RawFileDescriptor { fd（HAP 整包）, offset, length } → AVPlayer.fdSrc = { fd, offset, length }；依据引 media d.ts 的 fdSrc 注释和 rawFileDescriptor.d.ts 的 offset 注释
- 同一格里每个跨端传递的值（路径、句柄、URI、描述符）各给自己的 d.ts 依据，不只给其中一个 API 标出处
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- getRawFdSync(path: string): RawFileDescriptor；getRawFd(path: string): Promise<RawFileDescriptor>：取 rawfile 的描述符（出处：鸿蒙 SDK 的 ets/api/@ohos.resourceManager.d.ts，ResourceManager.getRawFdSync / getRawFd）
- RawFileDescriptor { fd: number; offset: number; length: number }，offset 是 rawfile 在 HAP 内的起点，length 是它在 HAP 内的长度：fd 是整个 HAP 的句柄，不是独立文件（出处：鸿蒙 SDK 的 ets/api/global/rawFileDescriptor.d.ts，RawFileDescriptor）
- fdSrc?: AVFileDescriptor —— This attribute is required when media assets of an application are continuously stored in a file.：资源段在同一个文件里连续存放时用 fdSrc 设源（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.media.d.ts，AVPlayer.fdSrc）
- 独立的媒体文件才用 fd://xx：url 的 fd:// 形式只对应独立文件的句柄（出处：arkts-apis-media-AVPlayer.md，属性 fdSrc）
