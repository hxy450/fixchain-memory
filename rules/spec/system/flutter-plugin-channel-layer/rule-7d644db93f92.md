# 核心链路上、Dart 以 Future 等平台回调的插件不能只判阻断，要有 OHOS 插件

审的是：规格
触发（任一种）：
- 读到：参考规格把插件放在核心功能链路上（如先上传取 URL 再调后续接口）；Dart 调用方用 `Future`、`Completer` 或监听等待平台回调；写错的样子：插件记为 F5 blocked、没有任何 OHOS 插件，报告里归为 blocked non-core integration
- 写错的样子：solution、插件解析记录或报告里只写「no fake success」「显式失败边界」，没有对应的 OHOS 插件或 override 去回调失败
适用范围：Flutter 复用路线且 Dart 冻结时，判定插件阻断之前
做法：
- 核对插件在参考规格里的调用链和 Dart 调用方的等待方式；在核心链路上且 Dart 等平台回调的，走 F3
- 确实无法实现时也提供 OHOS 插件，为每个方法显式回调失败；Dart 冻结时能回调失败事件的只有 OHOS 插件本身，文档里写失败策略不构成失败路径
- 报告里标为核心功能阻断，不写 non-core
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- OHOS 上没有该插件时，页面置 loading 后 await 上传 Future 永不回调，后续接口不被调用：只判阻断、不给插件的实际后果是悬挂，不是显式失败（出处：卡里修好并验证过）
针对本应用要查的：
- Dart 调用方怎样等平台结果：Flutter 工程里调用该插件 API 的 Dart 代码；看是 await Future、Completer 还是注册监听等事件；凡是等平台回调的，没有 OHOS 插件都会悬挂
