# 源码能力检查分不支持、开关关闭、可用时，规格的接口、状态和验收逐个列出

审的是：规格
触发（任一种）：
- 读到：源码入口先判 NfcAdapter.getDefaultAdapter() 为 null 提示不支持，再判 isEnabled() 为 false 时 startActivity(Settings.ACTION_NFC_SETTINGS)，否则进入功能页；写错的样子：规格的服务接口只有一个 isAvailable()，状态枚举没有关闭态（disabled），验收条款只写「不支持时提示且不导航」，没有「NFC 关闭→打开系统 NFC 设置页」
- 读到：源码被引用的函数里有多个 if/else 分支；写错的样子：验收条款标注「源:某函数()」，但该函数有的分支没有对应的条款
适用范围：规格提取阶段，把源码入口的平台能力前置检查写成服务接口、状态枚举和验收条款时
做法：
- 源码有几个分支就列几个：服务接口分开「是否支持」「是否开启」「打开系统设置」；状态枚举含不支持、已关闭、可用；验收条款每个分支一条，关闭态写「打开系统 NFC 设置页，返回后需用户再次点击」
- 真机只观察到其中一个分支（如不支持）时，其余分支照源码契约保留，不按真机覆盖面裁剪
- 标注「源:某函数()」的验收条款写完后，对照该函数全部 if/else 分支逐项核对，每个分支都有对应条款
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- NfcAdapter.getDefaultAdapter(context) 在设备没有 NFC 时返回 null：源端「不支持」分支的判据（出处：android.nfc.NfcAdapter#getDefaultAdapter）
- Settings.ACTION_NFC_SETTINGS = "android.settings.NFC_SETTINGS"：源端「NFC 关闭」分支打开的系统 NFC 设置页（出处：android.provider.Settings#ACTION_NFC_SETTINGS）
- canIUse("SystemCapability.Communication.NFC.Core")；function isNfcOpen(): boolean：目标端判「是否支持」和「是否开启」的两个接口（出处：鸿蒙 SDK 的 ets/api/@ohos.nfc.controller.d.ts，nfcController.isNfcAvailable（@useinstead）、nfcController.isNfcOpen）
- openNfcSettingsPage(context: Context): void（24+）：目标端打开系统 NFC 设置页（出处：js-apis-settings.md，settings.openNfcSettingsPage）
未核实：openNfcSettingsPage 本机 API 23 的声明里没有，只在文档里核到（标 24+）
