# ACTION_SEND 分享接收的规格写 utd 声明和 getSharedData 取数，依据写出处

审的是：规格
触发（任一种）：
- 读到：AndroidManifest 里 intent-filter 带 action.SEND + category.DEFAULT 和 mimeType（text/plain、image/*），代码从 EXTRA_TEXT / EXTRA_STREAM 取分享内容；写错的样子：规格映射行写「sendData + type 注册；EntryAbility 读 want.parameters」，取数契约按 want.parameters 和 want 的 uri 写，依据栏只写「grill 确认」；验收写「skills 含两类 type 声明」
适用范围：规格里为 Android 分享接收（ACTION_SEND）写 HarmonyOS 平台映射和取数契约时
做法：
- 契约写成：module.json5 里 ohos.want.action.sendData 的 skill，uris 用 utd（如 general.text、general.plain-text、general.hyperlink、general.image 及其子类型）加 maxFileSupported 声明可接收类型；取数用 systemShare.getSharedData(want) 后 getRecords()，按每条的 utd 区分 content 和 uri
- 依据栏写 SDK d.ts 出处；跨栈基线和参考里都查不到时记成待查证缺口写进 summary 上报，不写「grill 确认」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- function getSharedData(want: Want): Promise<SharedData>：从分享拉起的 want 里解析分享数据（出处：鸿蒙 SDK 的 hms/ets/api/@hms.collaboration.systemShare.d.ts，systemShare.getSharedData）
- getRecords(): Array<SharedRecord>；SharedRecord 有 utd: string、content?: string、uri?: string：逐条取分享记录，按 utd 区分文本内容和文件 uri（出处：鸿蒙 SDK 的 hms/ets/api/@hms.collaboration.systemShare.d.ts，SharedData.getRecords、SharedRecord）
- skills.uris 的 utd：与 Want 匹配的标准化数据类型，适用于分享；maxFileSupported：一次能接收的该类文件最大数量，需与 utd 配合，缺省 0：接收端声明可接收类型的两个字段（出处：module-configuration-file.md，skills 标签的 uris）
- TEXT = 'general.text'、PLAIN_TEXT = 'general.plain-text'、HYPERLINK = 'general.hyperlink'、IMAGE = 'general.image'、JPEG = 'general.jpeg'、PNG = 'general.png'、GIF = 'general.gif'：常用的 utd 取值（出处：鸿蒙 SDK 的 ets/api/@ohos.data.uniformTypeDescriptor.d.ts，UniformDataType）
未核实：卡里记的鸿蒙 SDK 是 6.1.1(24)，声明按本机 API 23 核实
