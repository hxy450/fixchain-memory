# 规格把 Manifest 每条 intent-filter 逐条映射成 skills，不合并、不移交

审的是：规格
触发（任一种）：
- 读到：AndroidManifest.xml 的入口 Activity 下有多条独立 intent-filter（如 SEARCH、VIEW 自定义 scheme、SEND、SEND_MULTIPLE、PROCESS_TEXT）；写错的样子：规格把 SEND 与 SEND_MULTIPLE 合成一条 sendData skill（uris 只有 type */*，没有 utd、maxFileSupported），SEARCH 写成「交给应用内搜索组件」或「不路由（域外）」而不登记 skill
适用范围：规格提取阶段，把源 manifest 的 intent-filter 翻译成 module.json5 skills 时
做法：
- 每条 intent-filter 逐条写出 skills 映射（actions / entities / uris 含 type 或 utd）；平台有对应 action 的（SEARCH → ohos.want.action.search，SEND_MULTIPLE → ohos.want.action.sendMultipleData）各成一条，不并入他条、不移交应用内组件
- 分享目标按 Share Kit 要求写 utd 与 maxFileSupported
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- ohos.want.action.search；ohos.want.action.sendData；ohos.want.action.sendMultipleData；ohos.want.action.viewData：搜索、发送单个数据、发送多个数据、查看数据四个 action 的字符串（出处：js-apis-ability-wantConstant.md，Action）
- uris 的 utd：与 Want 相匹配的标准化数据类型，适用于分享；maxFileSupported：一次能接收的最大文件数，需与 utd 配合，缺省 0：分享目标的 uris 要写这两项（出处：module-configuration-file.md，skills标签的 uris）
未核实：PROCESS_TEXT 在目标端对应哪个 skill，卡里没写明
来源：1 张卡，1 个应用
