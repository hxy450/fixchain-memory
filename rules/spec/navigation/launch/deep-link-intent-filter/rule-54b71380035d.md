# 规格写深链映射时，同时写 module.json5 skills.uris 和 want/newWant 解析

审的是：规格
触发（任一种）：
- 读到：安卓清单里启动 Activity 有深链 intent-filter（VIEW + BROWSABLE，scheme / host / path，如 http/https、固定 host）；清单或 inventory 里有外部深链条目；写错的样子：规格里深链只写了运行时一半（「启动后解析 URL」「UIAbility want/newWant listener + NavPathStack 路径解析」「skills 匹配 + onNewWant 等价」），没点名 module.json5 里 Ability 的 skills（actions、entities、uris 的 scheme/host/path）具体条目
适用范围：规格提取阶段描述外部深链怎么迁的那一节，以及以清单深链为来源的验收条目
做法：
- 深链映射写成两部分：平台声明——module.json5 对应 Ability 的 skills 加一项 actions [ohos.want.action.viewData]、entities [entity.system.browsable]、uris 按源端每个 intent-filter 的 scheme 写 {scheme, host, pathStartWith}；运行时解析——onCreate/onNewWant 读 want.uri 解析成页面路由
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Deep Linking 基于隐式 Want 的 uri 匹配来查询、拉起目标应用：先有 skills.uris 匹配，want.uri 才会到 onCreate / onNewWant（出处：deep-linking-startup.md，实现原理）
- 默认的入口 skill 里不能配跳转链接，要另建独立的 skill 对象：规格里写「新增一项 skill」，不写成改 home 那一项（出处：deep-linking-startup.md，配置module.json5文件）
- onCreate(want: Want, launchParam: AbilityConstant.LaunchParam): void；onNewWant(want: Want, launchParam: AbilityConstant.LaunchParam): void：运行时解析的两个入口：冷启动走 onCreate，已在前台或后台的实例再次拉起走 onNewWant（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.UIAbility.d.ts，UIAbility.onCreate、UIAbility.onNewWant）
- uri?: string：Want 里携带的链接，解析代码从 want.uri 读（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.Want.d.ts，Want.uri）
