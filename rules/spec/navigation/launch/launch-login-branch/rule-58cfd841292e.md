# 启动路由规格按持久化状态组合逐项写去向，源端交给后续流程的组合要核对已迁移

审的是：规格
触发（任一种）：
- 读到：源端闪屏或启动 Activity 用 when / if 链按持久化的用户信息、token、引导完成标记分支跳转；「已登录」判定只看用户信息、不看 token；写错的样子：规格只照搬源端的 when 分支，没有列出「用户信息有/无 × token 有/无 × 引导是否完成」各组合的去向；源端进主页后才处理的组合（启动刷新 token、网络拦截器按 token 失效错误码踢回登录页）没写，也没写目标端这两段是否已迁移
适用范围：启动路由迁移阶段，规格里写冷启动去向的那一节
做法：
- 规格里列一张组合表：源端启动判定用到的每个持久化状态（用户信息、token、引导标记）的有/无组合，各写源端去向
- 源端不在启动处理、交给后续流程的组合，写明后续在哪处理（进主页后刷新 token、拦截器按 token 失效错误码发踢登），并加一条验收项：目标端这两段已迁移接通
针对本应用要查的：
- 源端对某个状态组合的后续处理：源工程主页 Activity 的初始化（刷新 token 的调用）和网络层拦截器（按错误码发踢登事件、观察者执行登出并跳登录页）；读出触发踢登的错误码和刷新时机，写进组合表对应行
未核实：源端「有用户信息无 token」时服务端是否确实返回 token 失效错误码并触发踢登，卡里只依据枚举名和拦截器代码
