# 源端持有者带首启标记或先选后进主界面时，规格写明「无已选项」的首启行为和验收路径

审的是：规格
触发（任一种）：
- 读到：源端状态持有者从 SharedPreferences 恢复已选列表、为空时首启标记为 false（如 isNotEmpty() 判定），选择页在首启时选完才 startActivity 进主界面；写错的样子：规格只写「已选列表变化后按首个条目的编码触发请求」，视觉验收路径直接假定「冷启→页面→已有选择」，没定义无已选项的首启状态
适用范围：规格里迁移持久化的已选城市（或类似已选项）列表，及依赖它的首次进入页面行为时
做法：
- 规格写明「无已选项」时的首启行为和目标端承载方式；入口与初始化不可改时，列出引导选城、空态提示、默认城市等选项请用户决策
- 把「未存已选项时冷启动进入该页面」列为一条验收路径
针对本应用要查的：
- 源端首启时怎么处理空列表：源工程里持有已选列表的类（从 SharedPreferences 恢复的那段）和选择页的点击回调；看列表为空时置的标记，以及选择页在首启分支里跳到哪里，写成规格里的首启行为
未核实：源端首启标记为 false 时如何路由到选择页卡里没看到，是由选择页首选后启动主界面推断的
