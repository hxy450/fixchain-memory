# 启动判定里的登录态和首启分支

agent 会看到什么：读到闪屏或启动 Activity 用 when / if 按持久化的用户信息、token、引导完成、已选列表是否为空分支跳转；规格只照搬 when 分支，没列各状态组合的去向、无已选项的首启行为，或加了源端没有的 token 拦截分支却没登记

## 规矩

- rule-58cfd841292e｜启动路由规格按持久化状态组合逐项写去向，源端交给后续流程的组合要核对已迁移｜读到：源端闪屏或启动 Activity 用 when / if 链按持久化的用户信息、token、引导完成标记分支跳转；「已登录」判定只看用户信息、不看 token；写错：规格只照搬源端的 when 分支，没有列出「用户信息有/无 × token 有/无 × 引导是否完成」各组合的去向；源端进主页后才处理的组合（启动刷新 token、网络拦截器按 token 失效错误码踢回登录页）没写，也没写目标端这两段是否已迁移
- rule-137bde8e31bb｜启动决策加了源端没有的 token 拦截分支时，台账标为相对源端的新增行为｜读到：用户或产品方要求冷启动时拦截「有用户信息但 token 为空」；源端启动判定里没有这个分支；写错：决策台账或迁移记录里没有这条相对源端的新增行为；或者把「取不到用户信息」的组合也一并改成去登录页
- rule-0485326d3123｜源端持有者带首启标记或先选后进主界面时，规格写明「无已选项」的首启行为和验收路径｜读到：源端状态持有者从 SharedPreferences 恢复已选列表、为空时首启标记为 false（如 isNotEmpty() 判定），选择页在首启时选完才 startActivity 进主界面；写错：规格只写「已选列表变化后按首个条目的编码触发请求」，视觉验收路径直接假定「冷启→页面→已有选择」，没定义无已选项的首启状态
