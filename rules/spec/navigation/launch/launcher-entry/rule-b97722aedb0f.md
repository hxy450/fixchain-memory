# 用户要求「和源端一样有加载页」时，规格把首次冷启动的最短可见时长写成验收项

审的是：规格
触发（任一种）：
- 读到：用户要求首次启动和安卓一样有页面加载；源端 SplashActivity 继承外部 SDK 的启动 Activity，SDK 初始化走完才启动 MainActivity；目标端初始化只读本地配置；写错的样子：验收标准只要求首帧进度状态，或写「不通过人为延迟伪造用户可见行为」，没写首次冷启动的最短可见时长，也没登记为决策缺口
适用范围：源端加载页时长由外部 SDK 决定、目标端本地初始化极快，而用户要求可见加载页时，规格的验收条目
做法：
- 验收条目写「首次冷启动加载页至少可见 N ms；仅首次，热启动不等待」
- 源端时长取不到时把 N 作为决策缺口交用户确认，不以「不伪造」为由只验首帧状态
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 修复者给首次真实初始化补足约 800ms 最短展示：按用户截图选定的值，不是源端常量（出处：卡里修好并验证过）
未核实：源端首次启动的实际可见时长由外部 SDK 决定，卡里没有其源码
