# 入口分流的规格按冷启、回收重入、运行中桌面再拉起、最近任务切回逐种写验收

审的是：规格
触发（任一种）：
- 读到：LAUNCHER Activity 是无界面跳板，manifest 未声明 launchMode（缺省 standard）；应用内用 TaskStackBuilder.startActivities 或 NEW_TASK|CLEAR_TASK 改写任务根；写错的样子：规格和验收条目只写「EntryAbility 首帧加载前（loadContent 之前）选入口路由」这一种冷启分流，没有进程存活时从桌面图标再次拉起的分支，也没写单例 UIAbility 再次拉起走 onNewWant、页面栈原样保留
适用范围：规格提取阶段，源端入口是 LAUNCHER 路由跳板、目标是单例 UIAbility 加单个 Navigation 的入口分流
做法：
- 入口分流按「冷启 / 进程回收后重入 / 进程存活时从桌面图标再次拉起 / 从最近任务切回」逐种写验收条目
- 结合 LAUNCHER Activity 的 launchMode（未声明即 standard）和 TaskStackBuilder.startActivities、NEW_TASK|CLEAR_TASK 是否改写任务根，判断源端重进时是否重跑跳板；要重跑的，写明目标承载点：EntryAbility.onNewWant 里按同一条件再分流
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- launchMode 缺省是 standard（enum value="0"），通常每次启动都新建实例：manifest 没写 launchMode 时，从桌面再次进入已有任务会在栈顶新建跳板 Activity 再分流（出处：Android SDK 平台资源 data/res/values/attrs_manifest.xml，launchMode（按应用的 compileSdk 取对应平台））
- TaskStackBuilder.getIntents 给第一个 Intent 加 FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_CLEAR_TASK | FLAG_ACTIVITY_TASK_ON_HOME：startActivities 会清掉原任务重建，任务根变成第一个 Intent 的 Activity（跳板不再是根）（出处：android.app.TaskStackBuilder#getIntents）
- singleton 是 UIAbility 的默认启动模式；实例已存在时再次启动只进 onNewWant()，不进 onCreate() 和 onWindowStageCreate()：目标端再次拉起时页面栈原样保留，冷启分流不会重跑（出处：uiability-launch-type.md，singleton启动模式）
- onNewWant(want: Want, launchParam: AbilityConstant.LaunchParam): void：规格里写的再分流承载点（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.UIAbility.d.ts，UIAbility.onNewWant）
针对本应用要查的：
- 源端 LAUNCHER Activity 的 launchMode 和改写任务根的调用：源工程的 AndroidManifest.xml 里 MAIN/LAUNCHER 那个 activity 的 android:launchMode；Java/Kotlin 源码里的 TaskStackBuilder、addFlags；没写 launchMode 即 standard；有 TaskStackBuilder.startActivities 或 NEW_TASK|CLEAR_TASK 的，任务根被改写，重进时会重跑跳板
