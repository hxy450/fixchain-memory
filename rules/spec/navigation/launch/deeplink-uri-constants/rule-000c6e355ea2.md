# 源端深链 URI 由常量拼接时，规格先展开常量写出完整 URI，展不开就标待查，不自拟 scheme

审的是：规格
触发（任一种）：
- 读到：navDeepLink { uriPattern = "$常量/路径/{id}" } 或复制链接的字符串由一个域名常量拼出；写错的样子：页面数据、规格或 AC 里出现源码中不存在的自定义 scheme（如 xxx://路径/{id}），没有写出常量展开后的 https 地址
适用范围：页面数据准备和规格提取阶段记录深链、分享链接等 URI 时
做法：
- 先找到常量定义、展开成真实值，写出完整 URI（scheme、host、path、参数占位）；展不开时保留原表达式并标注「待查」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 修复后 uris 只留 https 与 http（源端的域名），删去自拟的 scheme：源端没有的入口不注册（出处：卡里修好并验证过）
针对本应用要查的：
- 深链常量的真实值：源工程里 uriPattern 引用的那个常量的定义处（Kotlin const val 或 strings 资源）；把常量值代回模式串，得到完整的 scheme://host/path
