# 页面有多个点击入口时，规格按各监听器函数体逐个写「控件→调用→目标页」

审的是：规格
触发（任一种）：
- 读到：源 Fragment / Activity 里有多个点击入口（`setOnBannerListener`、`onItemChildClick`、clickDelay 等监听器），规格作者只看过声明级的搜索结果，没展开函数体；写错的样子：规格 AC 写「点击X进入Y；源:某Fragment」，Y 却不是该监听器函数体里实际跳转的页面；或几个入口并成一条，补出源码里没有的「列表项→详情」AC 和对接点
适用范围：规格提取阶段，为列表项按钮、Banner 等多个点击入口写跳转 AC 和页面对接点时
做法：
- 每条「点击X进入Y」的 AC，先读锚点里对应监听器的函数体，逐一列出「控件→调用→目标页」；声明级搜索只用来定位函数，不作跳转目标的依据
- 同一页面的每个入口分别写 AC 和对接点，如「Banner → 详情页（带它的 Intent 参数）」「列表子按钮 → 查询接口 → 首条结果进结果页，空结果提示」；不因为存在详情页就补出列表项进详情
针对本应用要查的：
- 页面每个入口实际跳到哪里：源工程这个 Fragment / Activity 的 Kotlin 或 Java 文件，搜 setOnBannerListener、onItemChildClick、setOnClickListener、startActivity；顺着每个监听器的函数体读到 startActivity 的目标 Activity 和中间的查询调用，记成「控件→调用→目标页」
