# 两层共享转场写成目标契约时，规格写明每端一对、用哪个键、挂哪个节点、内层不再挂

审的是：规格
触发（任一种）：
- 读到：源端 Modifier.sharedBounds("<id>-bounds") 包住 Modifier.sharedElement(id)，两层 key 不同；写错的样子：规格把 id 值域写成「`${id}` 与 `${id}-bounds` 两对」，或只写「geometryTransition(id) 双端绑定」而没写用哪个键、挂在哪个节点、内层不再挂第二个；页面结构一节原样列出源端两层 key
适用范围：规格提取阶段写共享转场的转换决策和页面结构时
做法：
- 转换决策写成：每端只挂一对 geometryTransition，键用外层 `${id}-bounds`，挂在外层容器节点上，内层内容不再挂第二个
- 页面结构或 id 值域里不把源端两层 key 写成「两对」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 同一个 id 只能有两个组件绑定，且是 in/out 不同角色：契约里每个键对应两端各一个节点（出处：ts-transition-animation-geometrytransition.md，geometryTransition）
