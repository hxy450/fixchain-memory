# 恢复契约按源端任务栈恢复整栈，每页参数保留入栈时的原值

审的是：规格
触发（任一种）：
- 读到：源端 `TaskStackBuilder.addNextIntentWithParentStack` 建出「父页 + 当前页」的栈；跳转 Intent 用 `putExtra` 的布尔值区分新开和续接；写错的样子：恢复契约写「恢复至最后路由」只恢复一页，或把恢复页的参数写死成续接值，没有对照已读的 putExtra 行
适用范围：规格里写进程回收后的目标端恢复契约时
做法：
- 契约写：恢复整栈（从栈底父页到栈顶），每页参数是入栈时的原值；写「原始 Intent 值」前对照已读的 putExtra 行逐项核对，不推定成续接
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- addNextIntentWithParentStack 把目标 Activity 在 manifest 里声明的父链加入栈，再加入该 Intent：源端回收重建的是整栈（出处：android.app.TaskStackBuilder#addNextIntentWithParentStack）
- 重建的页面按原始 Intent 行事；新开时 Intent 带的是新开值，新进程中静态字段回到缺省值：恢复时参数不能一律写成续接（出处：卡里修好并验证过）
针对本应用要查的：
- 每个页面入栈时带的参数：源工程启动该 Activity 的代码里的 putExtra 行，以及目标 Activity 读 extras 的 getXxxExtra 缺省值；契约里每页参数照这些原值写
