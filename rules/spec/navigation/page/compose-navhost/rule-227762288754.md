# 源宿主用 NavHost 或接收 savedInstanceState 时，规格单列进程回收后重建分支

审的是：规格
触发（任一种）：
- 读到：源宿主 Activity 的 onCreate(savedInstanceState) / super.onCreate(savedInstanceState)，或 Compose 的 rememberNavController() + NavHost(startDestination = …)；源码里没有显式的保存代码；写错的样子：规格的宿主生命周期节只写「onCreate 初始化 → 冷启进入起始页」和前后台回切，没有「进程回收后重建 → 恢复页面栈与路由参数」的分支，也没有对应的平台差异决策
适用范围：规格提取阶段，为宿主 Activity 生命周期和导航容器写验收项时
做法：
- 在生命周期或导航节单列「进程回收后重建」分支：写明要恢复哪些返回栈页面、各页的路由参数，以及计时等会话怎么接续
- 写明目标平台的对应决策（启用 UIAbility 备份恢复、Navigation 与 NavDestination 可恢复），不只写「冷启进入起始页」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 启用 UIAbility 备份恢复后，应用在后台被系统关闭，下次启动时恢复先前的页面栈和 onSaveState 里保存的数据：目标平台有对应机制，但要显式开启（出处：ability-recover-guideline.md，场景介绍）
- 应用正常启动（startAbility 或点图标）时不触发恢复流程：冷启分支和回收重建分支是两条，规格要分开写（出处：ability-recover-guideline.md，场景介绍）
