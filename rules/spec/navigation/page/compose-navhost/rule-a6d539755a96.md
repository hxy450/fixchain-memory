# 迁移 handleDeepLink 时，规格写明外部拉起清栈并合成 [起始页, 目标] 返回栈

审的是：规格
触发（任一种）：
- 读到：源端 LaunchedEffect(intent) { navController.handleDeepLink(intent) }，NavHost 有 startDestination；写错的样子：规格数据流写「→ NavPathStack.pushPathByName」，AC 写「不中断当前导航栈（目标已在栈顶则仅更新参数）」，没写返回栈语义
适用范围：规格写深链消费和返回栈时
做法：
- 规格写明：外部拉起时清栈，按导航图起始目的地合成 [起始页, 目标]，不是在当前栈上 push
- 加一条验收：从非起始页（如设置页）收到深链进入目标后，按返回回到起始页
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Navigation 的 handleDeepLink 对外部 VIEW 意图（经 NEW_TASK 拉起）会清栈并以起始目的地 + 目标合成返回栈：源端返回栈语义（出处：卡里修好并验证过）
针对本应用要查的：
- 源端导航图的起始目的地：源工程 NavHost 的 startDestination 参数；它就是合成返回栈的第一页
未核实：合成返回栈属框架隐含语义，卡里没核到修复后返回键行为的单独运行验证
