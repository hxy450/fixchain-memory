# 壳层 lambda 里 NavHost 起点会在会话内重算时，规格写出重算时机和换图清栈

审的是：规格
触发（任一种）：
- 读到：Compose 源端在 ModalNavigationDrawer 等会重组的壳层内容 lambda 里写 NavHost(startDestination = 读偏好或状态的函数)，没有 remember；写错的样子：规格只写「栈空时 pushPathByName 首屏」「只推一次」「初始路由压栈」，没写起点在哪些重组时重算、起点变化后清栈重进、popUpTo 基准随之改变
适用范围：源端 NavHost 的起点是重组作用域里每次求值的表达式、且读的状态在会话内会变时，规格里写首屏、返回栈和顶级切换的那一节及验收条目
做法：
- 验收里写三件事：哪些重组会触发起点重算（打开抽屉、配置变化、订阅的状态变化）；起点变化后清空返回栈、以新起点和新实例重进；popUpTo(graph.findStartDestination()) 的基准随之改为新起点
- 推演返回栈时按标记变化前、变化后分别写返回路径，不假设图的起点在整个会话里不变
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 标记变化后壳层下一次重组（打开抽屉就会触发）时起点变成新值，NavHost 换图并清空整个返回栈，以新起点重新进入：源端在安卓设备上实测到的行为，规格要照此写（出处：卡里修好并验证过）
针对本应用要查的：
- 起点表达式读的是什么状态、会不会在会话内变：源工程里 NavHost(startDestination = …) 调用处所在的 Kotlin 文件，顺着起点函数找它读的偏好或状态；读的是会被首跑流程、登录等改写的偏好或状态，且调用处没有 remember，就按会重算写进规格
未核实：navigation-compose 里起点变化即换图清栈的实现没有在源码里核对，依据的是安卓设备上的实测行为
