# 验收条目写着带参进入会自动弹框而源端接收方不读该参数时，改成带参无参首屏一致

审的是：规格
触发（任一种）：
- 读到：源端调用方 putExtra 传了某个参数，接收方 Activity 不读取它；写错的样子：验收条目或 UI 测试用例写着「带某参数进入 → 自动出现协议框 / 自动执行某动作」，把源端没有的入页行为写成了期望
适用范围：为路由接线写验收条目或 UI 用例、页面有多个入口且有的入口带参时
做法：
- 验收条目写成：同一页面分别从带参入口和无参入口进入，首屏一致，不出现源端没有的自动弹窗或自动动作
针对本应用要查的：
- 条目里依赖的入参在源端接收方有没有被读取：源工程接收方 Activity/Fragment 的 Java 或 Kotlin 文件，按 extra 的键名搜 getXxxExtra；搜不到读取的，条目里不能把它写成驱动入页行为的条件
