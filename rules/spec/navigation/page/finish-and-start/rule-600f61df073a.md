# 源页面对同一次成功有多条导航响应时，规格只定义一个导航出口，不拆成独立的出栈和入栈验收

审的是：规格
触发（任一种）：
- 读到：源 Activity 对同一次成功有两条响应：EventBus 订阅（onEventMainThread）里 finish()，LiveData observe 回调里 startActivity(主页) 配 FLAG_ACTIVITY_NEW_TASK；成功管理器在回调页面前先 post 全局成功事件；写错的样子：规格把两条响应写成两条独立的导航验收：一条要求成功后 navPathStack.clear() + pushPathByName(主页)，另一条要求收到成功事件后本页 pop；两者怎么合并、谁先执行都没定义
适用范围：规格提取时，把源页面对同一业务结果的多条导航响应翻译成目标导航契约的那一节
做法：
- 先列出源页面对同一业务结果的全部响应（EventBus 订阅、LiveData 回调、结果回传），逐条标明是否由同一次成功触发
- 给目标页定义唯一的导航出口，写成一条验收；不要把 finish() 和 startActivity 各写成独立的出栈 / 入栈验收
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Activity#finish()：Call this when your activity is done and should be closed.：源端 finish() 只结束当前 Activity，不抵消已启动的主页；目标端两条都操作同一个 NavPathStack，效果会叠加（出处：android.app.Activity#finish）
- 两个出口叠加时登录后栈从 2 变 0，主页被移除、露出栈底启动页：卡里观察到的后果（出处：卡里修好并验证过）
针对本应用要查的：
- 同一业务结果在源端的全部响应和触发顺序：源工程这个 Activity 里的 EventBus 订阅方法和 LiveData observe 回调，以及它调用的成功管理器（看是否 post 全局事件）；按调用链排出先后，判断是不是同一次成功触发
未核实：MainActivity 的 launchMode 卡里没核，FLAG_ACTIVITY_NEW_TASK 是否等于清栈未判定
