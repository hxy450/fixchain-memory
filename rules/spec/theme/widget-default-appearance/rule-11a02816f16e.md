# wrap_content 单行 TextView 参与纵向排布时，规格写出默认行框高度并列为验收项

审的是：规格
触发（任一种）：
- 读到：wrap_content 的单行 TextView（textAppearanceLarge / Small 或 sp 字号，没写 includeFontPadding）是标题、列表项或页脚，决定下方分隔线、行高或按钮位置；写错的样子：规格只写字号（Large / Small、30sp / 18sp），没有写这行文字的视图高度，也没有对应验收项
适用范围：规格阶段为 wrap_content 单行 TextView 写转换决策、UI 快照又没有实测 bounds 时
做法：
- 除字号外写出安卓默认行框高度：includeFontPadding 为 true 时按 Roboto 的 top / bottom 度量，约为字号的 1.33–1.39 倍，换算成 dp 写进决策行
- 这些文字决定后面分隔线、列表行高或底部按钮位置时，把高度写成验收项
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- includeFontPadding：Leave enough room for ascenders and descenders instead of using the font ascent and descent strictly. (Normally true)：默认按字体 top / bottom 留出上下空间，行框比字号高（出处：Android SDK 平台资源 data/res/values/attrs.xml，TextView 的 includeFontPadding（按应用的 compileSdk 取对应平台））
- setIncludeFontPadding 的默认是 true：没写这个属性就带额外上下边距（出处：android.widget.TextView#setIncludeFontPadding）
- Roboto + includeFontPadding=true：单行视图高度约为字号的 1.33–1.39 倍（如 22sp→29.71dp、14sp→19.43dp）：实测换算比例，目标端默认 Text 比这矮（出处：卡里修好并验证过）
针对本应用要查的：
- 源端单行文字的字号：源工程布局 XML 里该 TextView 的 android:textSize 或 textAppearance；textAppearance 的字号在对应平台 data/res/values/styles.xml 的 TextAppearance.Large / Small 等样式里；读出 sp 数后乘约 1.33–1.39 得行框 dp；字体不是 Roboto 时按该字体的 top / bottom 度量算
未核实：1.33–1.39 倍是 Roboto 在卡里那台设备上的实测，别的字体或系统字体缩放下没核
