# 应用主题在 values-vNN 下另有同名定义时，规格的主题行按 API 级写覆盖后的生效链

审的是：规格
触发（任一种）：
- 读到：manifest 的 android:theme 指向的应用主题在 values/ 和 values-v21 等 values-vNN 下各有一份同名 `<style>`；values/styles.xml 的注释写着 replaced by … from res/values-vXX/styles.xml on newer devices；写错的样子：规格（ui-manifest）的主题行写成 values/ 里的父主题，如「主题 extends android:Theme.Light」，没提 values-vNN 的覆盖；页面元数据 style_sources 列了 values-v21 却没反映到主题行
适用范围：规格提取阶段确定应用生效主题、写全局约定的主题行时
做法：
- 把 manifest 引用的应用主题在 values/ 和全部 values-vNN 下的同名 style 都读出来，按参照设备 API 级（不低于 minSdk，通常 21+）取覆盖后的父主题链写进主题行，如「API 21+：应用主题 → 父主题 → android:Theme.Material.Light.DarkActionBar（values-v21）」
- values/ 的父主题只写成低版本回落；页面元数据 style_sources 列出的样式文件全部读完再定主题行
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- <style name="Theme.Material.Light" parent="Theme.Light">：Material.Light 是在 Theme.Light 之上重新定义状态栏、窗口底色和 ActionBar 的另一套主题，停在 Theme.Light 会漏掉这些项（出处：Android SDK 平台资源 data/res/values/themes_material.xml，Theme.Material.Light（按应用的 compileSdk 取对应平台））
针对本应用要查的：
- 参照设备 API 级下应用主题的生效父主题链：源工程 res/values/ 和各 res/values-vNN/ 下的 styles.xml、themes.xml，按 manifest android:theme 的名字找同名 `<style>`；取不高于参照 API 级的最高 vNN 那份的 parent，再顺着 parent 往上到平台主题；各份覆写的 item 也一并记下
