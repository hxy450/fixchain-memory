# 基类副作用带 findViewById 判空等守卫时，规格连条件一起写并逐个子类按布局判定

审的是：规格
触发（任一种）：
- 读到：安卓业务基类的 onPostCreate / onResume 里先 findViewById(R.id.x)，if (view != null) 才执行淡入等副作用；或用 instanceof、标志位守卫；写错的样子：规格的基类副作用表把它写成无条件表项（「某子类继承 → 进页 250ms 淡入」），没写守卫条件，也没给每个子类「生效 / 不生效」的布局证据
适用范围：规格提取阶段逐方法列安卓业务基类的生命周期副作用、并映射到各子类页面时
做法：
- 副作用连同守卫一起写：findViewById(R.id.x) 后判空的写成「仅当子类布局含 x 时生效」，instanceof、标志位同理
- 逐个子类打开它 setContentView 的布局（含 layout-land 等变体）grep 该 id，规格里写出每页「生效 / 不生效」的结论和布局证据；不生效的页写「不适用」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Activity#findViewById 找不到 id 时返回 null：子类布局没有该 id 时守卫不成立，副作用不执行（出处：android.app.Activity#findViewById）
针对本应用要查的：
- 每个子类布局里有没有守卫用的 id：源工程 res/layout* 下该子类 setContentView 引用的布局文件，含 layout-land 等限定符变体；grep android:id="@+id/x"；所有变体都没有就判不生效
