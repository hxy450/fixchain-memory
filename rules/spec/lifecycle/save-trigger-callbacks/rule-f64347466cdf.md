# 源端存档触发点按时机逐个对到目标回调，onDestroy 不存档就不写 aboutToDisappear

审的是：规格
触发（任一种）：
- 读到：源 Activity 只在 onPause、onBackPressed、onSaveInstanceState 和标题栏 Up 里调 save()，没有覆写 onDestroy，或 onDestroy 里不存档；写错的样子：规格的转换决策把存档触发写成「onHide / onBackPressed / aboutToDisappear 等价钩子」，onSaveInstanceState 被对到组件销毁回调；也没写源端哪些回调不存档
适用范围：规格提取阶段，把源 Activity 的存档、计时触发点映射到目标页面（NavDestination）生命周期回调时
不适用的情形：源端在 onDestroy 或 finish 路径里确实存档时，才把 aboutToDisappear 写成存档钩子
做法：
- 逐个按触发时机对齐：onPause → 页面隐藏或退后台（NavDestination.onHidden）；onBackPressed → 返回拦截（NavDestination.onBackPressed）；onSaveInstanceState → 配置重建或系统回收前（如 onConfigurationUpdate）；Up → 标题栏返回
- 同时写出源端不存档的回调（如 onDestroy），注明目标端对应的 aboutToDisappear 不存档
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onHidden(callback: Callback<VisibilityChangeReason>): NavDestinationAttribute：NavDestination 页面被隐藏时回调；这个带原因参数的签名声明 @since 21（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onHidden）
- VisibilityChangeReason.TRANSITION = 0、CONTENT_COVER = 1、APP_STATE = 2：隐藏的原因：页面导航、bindContentCover、应用前后台切换；退后台也会触发 onHidden（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，VisibilityChangeReason）
- onBackPressed(callback: () => boolean): NavDestinationAttribute：NavDestination 的返回拦截（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onBackPressed）
- onConfigurationUpdate(newConfig: Configuration): void：系统配置更新时回调，对应源端配置重建前的存档（出处：鸿蒙 SDK 的 ets/api/@ohos.app.ability.Ability.d.ts，Ability.onConfigurationUpdate）
- aboutToDisappear?(): void：自定义组件即将销毁时回调；页面可能在 onHidden 之后很久才走到这里（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CustomComponent.aboutToDisappear）
- 删掉 aboutToDisappear 里的存档后，开新局 → 回桌面 → 等待 → 桌面图标重进 → 看统计，两端时长一致：修好并上机核对的结果（出处：卡里修好并验证过）
针对本应用要查的：
- 源端在哪些回调里存档、计时：源 Activity 的 Java / Kotlin 源码，按 save( 或存档方法名 grep，并看有没有覆写 onDestroy；列出每个调用所在的回调，再按上面的对应关系逐个写进规格；没有调用的回调写「不存档」
