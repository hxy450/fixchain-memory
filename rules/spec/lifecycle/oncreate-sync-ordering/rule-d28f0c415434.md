# 给共享组件加跨页句柄机制时，契约写明宿主最早可用点，差异表列出延后登记

审的是：规格
触发（任一种）：
- 读到：源端在 onCreate 里 findViewById 同步取得 View 并立即调用它；写错的样子：共享组件的句柄契约没写宿主何时可用、也没有登记回调；源码理解笔记的差异表把「findViewById → 句柄登记」的外显影响写成「无」
适用范围：给共享组件加跨页句柄机制的切片写源码理解笔记和组件契约时
做法：
- 把「宿主何时可用」写进句柄契约：提供登记回调，或写明最早可消费点
- 差异清单里把「源端同步取得 View、目标端延后登记」列为可观察差异
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onReady 在 NavDestination 的子组件创建之前回调：宿主的 onReady 不是子组件句柄的可消费点（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onReady）
