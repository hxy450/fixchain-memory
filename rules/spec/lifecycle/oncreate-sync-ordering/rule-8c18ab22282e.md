# onCreate 里 setContent 的组合副作用晚于 onCreate 后续语句，规格按运行顺序写读写先后

审的是：规格
触发（任一种）：
- 读到：Activity.onCreate 里 setContent { … } 挂 Compose 内容，组合内 LifecycleEventEffect(Lifecycle.Event.ON_CREATE)、LaunchedEffect 或 DisposableEffect 读某个状态，setContent 之后 onCreate 还有写同一状态的语句（如启动计数自增）；写错的样子：规格按源码行号写成「先判后自增」「首启读到 0」，首启边界样例和「时序照搬」验收也按行序推出
适用范围：规格提取阶段确定源端 onCreate 语句与 setContent 内 Compose 组合副作用的读写先后时
做法：
- 规格里写明：组合内的 LifecycleEventEffect(ON_CREATE)、LaunchedEffect、DisposableEffect 在 onCreate 返回、内容首次组合时才执行（ON_CREATE 由观察者注册时补发），晚于 onCreate 里 setContent 之后的全部语句，读到的是这些语句写过之后的值
- 读写先后、首启边界样例（第几次启动命中）和「时序照搬」验收都按这一运行顺序写，不按源码行号推断
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 组合内 LifecycleEventEffect(ON_CREATE) 的判定读到 onCreate 尾部自增后的计数：按 n % 9 == 0 判定时冷启第 9、18 次弹出，首启不弹：两端实测一致的运行顺序（出处：卡里修好并验证过）
