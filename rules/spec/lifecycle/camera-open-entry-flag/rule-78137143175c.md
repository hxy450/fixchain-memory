# 源端在相机打开回调里读一次性入口标志时，规格锚点和对接点落在目标相机就绪回调

审的是：规格
触发（任一种）：
- 读到：源端在相机打开或预览建立的回调里读取一次性入口标志（桌面小部件、快捷入口置位的拍照标志）并读后即清，再进入按对焦模式延时拍照的设置流程；写错的样子：AC 正文写“相机打开完成后读取、先开后拍”，`标:` 锚点和对接点却写成 aboutToAppear / onPageShow；计划的 cross_slice_edits 照此挂到页面生命周期
适用范围：规格提取与跨切片计划阶段，确定外部入口一次性请求在目标中的消费时点和挂载点时
做法：
- AC 的 `标:` 锚点和对接点落在目标引擎的相机打开 / 预览启动之后的回调，不写成 aboutToAppear、onPageShow 这类页面生命周期
- 写完逐条核对 AC 正文的时序（“相机打开完成后”）与锚点、对接点是否一致
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- onPageShow?(): void：页面每次显示时调用（页面跳转、应用切到前台），只对 @Entry 组件生效：页面显示和相机就绪无关，不能当相机打开回调的等价时机（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CustomComponent.onPageShow）
- open(): Promise<void>：CameraInput 打开相机，resolve 之后相机才打开（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.camera.d.ts，CameraInput.open）
- on(type: 'frameStart', callback: AsyncCallback<void>): void：PreviewOutput 预览第一帧开始时回调，对应“预览建立”（出处：鸿蒙 SDK 的 ets/api/@ohos.multimedia.camera.d.ts，PreviewOutput.on('frameStart')）
- 页面显示时消费请求，相机还没打开，拍照被拒；改到引擎打开相机、预览启动后再消费，冷启动和暖启动点入口各拍到一张：消费时点（出处：卡里修好并验证过）
未核实：卡里的实测出自 HarmonyOS 6.1.1（API 24），本机核实用的是 API 23
