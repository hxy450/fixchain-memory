# Activity 未声明 configChanges 时，规格写出重建后消失的对话框和目标端的关闭要求

审的是：规格
触发（任一种）：
- 读到：Manifest 的 <activity> 没有 android:configChanges，也没有 screenOrientation 锁定；源码用 AlertDialog.Builder(...).show() / Dialog.show() 直接弹出对话框，不经 DialogFragment、showDialog 或 DialogPreference；写错的样子：页面规格只写「Manifest 事实: 无 configChanges、无 screenOrientation」溯源注记；状态接口的关闭条件和验收里没有「配置变化/旋转时关闭对话框」
适用范围：规格提取时，每个未声明 configChanges 的 Activity，不论页面有没有动态文案
做法：
- 逐个 Activity 列出重建后哪些可见状态消失、哪些恢复：直接 Builder.show() / Dialog.show() 的对话框消失；DialogFragment、showDialog、DialogPreference 托管的会恢复
- 把消失项写进状态接口的关闭条件和验收，如「对话框打开时旋转，对话框关闭、列表保留」
- 把这行 Manifest 缺省翻成目标端的生命周期要求和负责实现的位置：页面不重建，由根容器 onAreaChange 判断横竖翻转，或在 onConfigurationUpdate 里显式关闭这些浮层
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- configChanges：If not specified, the activity will be restarted if any of these configuration changes happen in the system：没声明的配置变化都会重建 Activity（出处：Android SDK 平台资源 data/res/values/attrs_manifest.xml，configChanges（按应用的 compileSdk 取对应平台））
- showDialog：Show a dialog managed by this activity … the dialog will be automatically saved and restored：托管的对话框重建后恢复；直接 show 的不恢复（出处：android.app.Activity#showDialog）
- 目标端页面在旋转等配置变化时不重建，浮层会一直留着：源端靠重建自然消失的对话框，目标端要显式关闭（出处：卡里修好并验证过）
