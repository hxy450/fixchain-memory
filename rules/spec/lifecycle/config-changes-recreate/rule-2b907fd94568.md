# 未声明 configChanges 时，重建契约列出新实例重跑 onCreate/onResume 的效果

审的是：规格
触发（任一种）：
- 读到：Activity 没有 android:configChanges；onCreate 的 savedInstanceState 分支、onStart 或 onResume 里有重读持久数据并刷新显示、复位导航或计数字段、按启动 Intent 再次弹窗或导入的语句；写错的样子：规格的重建或配置变化契约只写 onSaveInstanceState 存取和对话框关闭或保留，没有列这些语句的效果；onResume 只映射成回前台路径，重建验收里没有它们
适用范围：源 Activity 未声明 configChanges、目标页面在配置变化时不重建时，规格里的重建契约和重建验收
做法：
- 逐条列出新实例会重跑的 onCreate（含 savedInstanceState 恢复分支）、onStart、onResume 语句的可见效果：重读持久化数据并刷新显示、复位导航或计数字段、按启动 Intent 再次弹窗或导入，写进重建验收条目
- 契约里写明目标在横竖翻转或配置变化路径上重放这些效果，接在「关闭非托管对话框 → 存档 → 读档 → 重读资源、重算布局」之后，不只写 View 的一次性状态和资源文案
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 未声明 configChanges 时，配置变化让当前 Activity 走 onPause、onStop、onDestroy，再用 savedInstanceState 新建实例；声明了的类型改为回调 onConfigurationChanged、不重启：新实例会把 onCreate、onStart、onResume 全部重跑一遍（出处：android.app.Activity 类注释「Configuration Changes」一节）
- UIAbility 在配置变化时回调 onConfigurationUpdate，不重启：目标端不会自动重跑页面初始化，源端重建带来的效果要在配置变化路径上显式重放（出处：subscribe-system-environment-variable-changes.md，在UIAbility组件中订阅回调）
针对本应用要查的：
- 新实例重跑时有可见效果的语句：源工程这个 Activity 的 Java 或 Kotlin 文件：onCreate（含 savedInstanceState 非空的分支）、onStart、onResume；逐条看每句改了什么显示或字段（刷新计分类显示、把计数复位、按 getIntent() 的内容再弹窗），各写成一条重建后的效果
未核实：按启动 Intent 再次导入的一项，卡里没有核对生成期结构下分享实例转屏的实际表现
