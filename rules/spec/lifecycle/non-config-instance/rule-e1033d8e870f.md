# 规格写「已有实例优先、忽略启动参数」的验收条目时，按入口×前置状态逐格列出

审的是：规格
触发（任一种）：
- 读到：源端只在 getLastCustomNonConfigurationInstance() 为 null 时才按启动参数分支，页面有新建、继续等多个入口，状态对象同时是只在退出时销毁的静态单例；写错的样子：验收条目写成「有实例时传入任意启动参数仍恢复原对象、不新建」，没有按入口和前置状态逐一列出，也没有「已有旧对象时走新建入口得到新状态」这一条
适用范围：规格里写「某实例优先、忽略启动参数」一类的验收条目时
做法：
- 写这类验收条目前列一张表：每个入口（新建、继续…）× 前置状态（无旧对象、有未结束的旧对象、有已结束的旧对象），再加配置变化重建，逐格代入源条件，写清哪些组合真的会忽略启动参数
- 验收条目同时给两条判据：「已有旧对象时走新建入口 → 得到全新状态，启动参数（如起始等级）生效」和「配置变化重建后保留当前对象」
针对本应用要查的：
- 页面有哪些入口、各入口带的启动参数取值：源工程里启动这个 Activity 的 Java 代码中 Intent 的 putExtra 键值，以及目标 Activity 的 onCreate 里读这些键的分支；每个不同的取值算一个入口，作为表的一行
- 状态对象在哪些时刻被销毁：源工程里这个单例的销毁方法的调用处（菜单退出、finish 等）；没有销毁调用的时刻都算「已有旧对象」的前置状态
