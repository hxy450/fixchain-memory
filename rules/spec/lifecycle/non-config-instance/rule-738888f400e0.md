# 源端 getLast…NonConfigurationInstance 为空才读启动参数时，规格分写配置重建和正常进入

审的是：规格
触发（任一种）：
- 读到：Activity.onCreate 先取 getLastCustomNonConfigurationInstance() 或 getLastNonConfigurationInstance()，只有为 null 时才按 Intent 的启动参数分支；同一 Activity 有 onRetainCustomNonConfigurationInstance / onRetainNonConfigurationInstance；写错的样子：规格写成「已有实例时启动参数全部忽略、直接复用当前对象」，或映射行写「getLastCustomNonConfigurationInstance → 单例天然续存」，没有区分配置变化重建和正常启动
适用范围：源 Activity 没有在清单里用 android:configChanges 接管配置变化（配置变化会重建 Activity），迁移时写这段建局或取回逻辑的规格
做法：
- 规格里把这段写成两种进入方式：配置变化重建时取回当前对象、忽略启动参数；正常启动时该值恒为 null，必须按启动参数走分支
- 规格里写明目标端的判据是「本次是否由配置变化重建」（如 onConfigurationUpdate 触发的重建路径带的标志），不写成单例 hasInstance() 或全局状态是否存在
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- Activity#getLastNonConfigurationInstance 返回 onRetainNonConfigurationInstance() 先前返回的对象，只在新实例最初的 onCreate、onStart 里可取：取回的对象只用来优化配置变化的处理，正常启动时为 null（出处：android.app.Activity#getLastNonConfigurationInstance）
- Activity#onRetainNonConfigurationInstance 只在因配置变化销毁、且马上要为新配置建新实例时由系统调用：源端「取回非空」只发生在配置变化重建（出处：android.app.Activity#onRetainNonConfigurationInstance）
- android:configChanges 没写时，列表里的配置变化发生会重启 Activity；写了的变化不重启，改调 Activity.onConfigurationChanged：哪些配置变化会走到取回分支，由清单里这个属性决定（出处：Android SDK 平台资源 data/res/values/attrs_manifest.xml，configChanges（按应用的 compileSdk 取对应平台））
- UIAbility.onConfigurationUpdate() 在环境变量变化时被调用，通过 Configuration 取最新信息，而无需重启 UIAbility：目标端配置变化默认不重建，正常进入和配置变化要靠自己的标志区分（出处：subscribe-system-environment-variable-changes.md，在UIAbility组件中订阅回调）
针对本应用要查的：
- 源 Activity 接管了哪些配置变化：源工程 AndroidManifest.xml 里这个 Activity 的 <activity> 元素的 android:configChanges 属性；没写这个属性：所有配置变化都重建、都会走取回分支；写了的取值（如 orientation|screenSize）对应的变化不重建、不会取回
