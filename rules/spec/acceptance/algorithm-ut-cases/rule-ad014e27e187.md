# UT 设计给迁移算法写「不同输入→不同输出」用例时，按源实现手算预期，dHash 不拿纯色图作区分样本

审的是：规格
触发（任一种）：
- 读到：源端 dHash 实现缩放到 9x8、灰度化后逐行比较相邻像素（right > left）取 64 位，没有亮度分量；规格只要求符号级对齐源实现、相同图片输出一致签名；写错的样子：UT 设计里有「全黑 vs 全白 → 两个 hex 不同（hamming>0）→ GREEN」这类区分用例，预期没有按源算法演算，比规格和源端更严
适用范围：UT 设计阶段为迁移来的纯算法（感知哈希等）写区分性用例和预期值时
做法：
- 每个「不同输入→不同输出」用例的预期先按源实现对所选输入逐位手算，写源端实际输出，不写想当然的区分结论
- dHash 这类只看相邻梯度的哈希，区分样本换成有梯度差异的图像；纯色、常量图只能写「两者哈希相同、均为 0000000000000000」
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- 纯黑、纯白 9x8 输入的 dHash 都是 0000000000000000：相邻像素差全为 0，源端和目标端都输出全 0，两者汉明距离为 0（出处：卡里修好并验证过）
针对本应用要查的：
- 源端哈希算法对所选样本的实际输出：源工程里实现该哈希的函数（缩放尺寸、灰度公式、取位比较）；按函数逐步对样本手算出 hex，作为用例预期；算出两样本相同就换样本
