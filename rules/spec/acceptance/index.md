# 验收条目与验收判定

规格里有验收条目（AC）和它挂的源码真值、UT 设计，或交回的验收报告、回归诊断给出 PASS、「两端一致」这类判定时

## 触发族

- [对话框列出预置项时的列表范围和过滤条件](preset-list-scope/index.md)（1 条）：读到源端对话框用 items(…) 列出全部预置项、参考规格写了空库时的反例；AC 里的列表范围、过滤条件和源码不一致，或漏了反例
- [RDB 共享写入口的验收判定方式](rdb-write-acceptance/index.md)（1 条）：读到计划要求用 @kit.ArkData RDB、插入删除在事务完成后返回、异常回滚；共享写入口的验收条目只写「判:unit」或签名比对，没有一次真实的 RdbStore 写入，也没注明设备能力未验证
- [只有静态证据的选图功能验收](photo-picker-acceptance/index.md)（1 条）：读到规格里选图功能的验收条目要求「允许权限并选中图片后收到真实可读图片」「受限时不进伪成功」；验收报告凭构建、注册器和首屏证据判 PASS，选图链没有走过
- [回归诊断里「两端 1:1、服务端问题」的结论](server-side-verdict/index.md)（1 条）：读到回归时点击无响应、接口返回 404 或静默返回，源端调用点前有地区、用户类型或新学员门控；迁移报告写「两端行为 1:1 一致」「服务端问题结案，保真勿修」，依据只有响应处理分支的比对
- [AC 标的源码真值区间和赋值组](ac-truth-range/index.md)（1 条）：AC 上标的「真:」源码区间和「组:{…}」里点名的各条赋值
- [新 UI 入口的视觉要素](ui-entry-visuals/index.md)（1 条）：源布局里菜单行的 ImageView 加 TextView、分组标题的 drawableLeft 图标和 @color/ 颜色资源；差异清单或规格验收项里对这些入口的写法
- [迁移算法的 UT 区分用例](algorithm-ut-cases/index.md)（1 条）：源端 dHash 一类感知哈希算法的实现细节；UT 设计里「不同输入→不同输出」的区分用例和它的预期
- [上游说有而源布局里没有的组件](upstream-layout-conflict/index.md)（1 条）：派工职责或功能索引说某页有某组件（如常驻的底部栏），读到的源布局 XML 里却没有承载它的容器或 include；验收条目和它挂的真值锚
- [源码里的断点和阈值比较（width > N.dp）](threshold-comparison-ac/index.md)（2 条）：读到源码里的断点或阈值比较，如 width > N.dp；验收条目的边界和源端比较符相反（源端 >，条目写「恰好 N 得宽布局」或要求 >=），或和同一规格里另一条同类条目说法不一
- [AC 要照抄的源端条件和已批准的怪癖](ac-source-conditions/index.md)（2 条）：读到源码锚点所在的函数有多重条件（启动方式、内存阈值、能力支持），或怪癖台账里有决策台账批准照源复刻的条目；规格的 AC、阈值表只写了单个条件，或照一般约定写了与怪癖相反的契约
- [参考文档、派工意图与 AC 对源端行为说法相反](conflicting-behavior-claims/index.md)（2 条）：读到 ref 文档、参考规格或派工清单写的源端行为和 feature AC 或源码实际运行结果相反（如「旋转后按新宽度重算」对「宽度变化不重算」、写了但因竞态不生效的分支）；交回的 AC 写死了其中一方，交叉验证以「带源锚的 AC 优先」收尾，或冲突只留在回执摘要的「残留不确定项」里
