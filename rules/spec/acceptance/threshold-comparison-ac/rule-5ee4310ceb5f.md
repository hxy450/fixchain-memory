# 源端分支条件带比较符和边界时，规格转述保留比较符，判定列补边界另一侧的用例

审的是：规格
触发（任一种）：
- 读到：源端按带比较符的条件选分支，如 `toLocalDate() >= today` 时用时间格式、否则用中等日期格式；写错的样子：规格或验收条目把它转述成「当日 / 往日」这类二分短句，判定列只写「当日/往日分支正确」，没有落在边界另一侧（未来日期）的用例
适用范围：规格提取时把源端的比较条件（>=、<=、>、<）转述成验收条目和判定列
做法：
- 转述时保留比较符和边界：`>= today` 写成「当天及以后显示时间，早于今天显示中等日期」这一类，不写成「当日/往日」
- 判定列给出边界两侧和边界上的用例，至少含一个未来日期的用例
已核实的写法和取值（核实时用的是鸿蒙 SDK API 23）：
- LocalDate#compareTo 依次比较年、月、日，大于为正：`toLocalDate() >= today` 对今天和未来日期都成立（出处：java.time.LocalDate#compareTo）
