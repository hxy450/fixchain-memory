# 参考文档、派工意图与 AC 对源端行为说法相反

agent 会看到什么：读到 ref 文档、参考规格或派工清单写的源端行为和 feature AC 或源码实际运行结果相反（如「旋转后按新宽度重算」对「宽度变化不重算」、写了但因竞态不生效的分支）；交回的 AC 写死了其中一方，交叉验证以「带源锚的 AC 优先」收尾，或冲突只留在回执摘要的「残留不确定项」里

## 规矩

- rule-9030312b7fd2｜交叉验证遇 ref 与 AC 对源端行为说法相反时，回源码和 Manifest 推执行路径｜读到：ref 文档写“旋转后按新宽度重算”，feature AC 写“宽度变化不重算”，两者说的是同一源端行为；写错：交叉验证记录以“带源锚的 AC 优先”结束冲突，把 ref 的相反说法当异常值舍掉，没有推重建后的执行路径，也没登记待裁决
- rule-5cc7af1b948b｜规格作者发现文档化意图与实际运行行为冲突时，不在 AC 写死争议分支，写成待决项｜读到：参考规格或派工清单写的「文档化意图」与源码实际运行结果不一致（如一个分支写了但因竞态不生效）；写错：AC 判据写死了有争议的分支，冲突只在回执摘要里作为「残留不确定项」出现，没写进 spec 和回执 JSON
