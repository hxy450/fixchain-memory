# 交叉验证遇 ref 与 AC 对源端行为说法相反时，回源码和 Manifest 推执行路径

审的是：规格
触发（任一种）：
- 读到：ref 文档写“旋转后按新宽度重算”，feature AC 写“宽度变化不重算”，两者说的是同一源端行为；写错的样子：交叉验证记录以“带源锚的 AC 优先”结束冲突，把 ref 的相反说法当异常值舍掉，没有推重建后的执行路径，也没登记待裁决
适用范围：规格交叉验证阶段处理 ref 文档与功能规格 AC 的冲突时
做法：
- 回到源码与 AndroidManifest 推出该行为的执行路径（例如 Activity 是否声明 configChanges、重建后首次组合是否重跑副作用），按推出的结果改 AC 或 ref
- 推不出就登记为待裁决项，两种说法都保留，不以“AC 带源锚就优先”结束
来源：1 张卡，1 个应用
