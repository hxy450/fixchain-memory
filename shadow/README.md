# 定向核对版的影子（这一版库的配套用法）

影子 = 原 agent 交付之后，另起一个 agent 拿着挑出来的经验，核对并修改原 agent 交出来的东西。这里是这一版库配套的做法、提示词和量过的数。

## 文件

| 文件 | 内容 |
|---|---|
| `template.md` | 定向核对的影子提示词模板，应用相关的地方是 `@@…@@` 占位符 |
| `select-prompt.md` | 分叉原 agent 一步挑选用的提示词，`{N}` 和 `{CANDIDATES}` 是候选的条数和候选清单 |
| `exclude.json` | 留在库里、但不交给影子的通用审查式经验（9 条，id、标题、理由） |

## 流程

1. **粗筛（不调模型）**：作者的 c3lexn（a2h-memory 的 `recall/recall_coarse_lex.py`），只用转录切块那几路（代码词 K、K.A、K.W 和上下文切块的 BM25@c、BO@c；没有盘点，盘点那三路不跑）；去掉三个常驻主题（`process/spec-handoff`、`process/implementation`、`arkts/api-signatures`）的经验，取前 60 条候选。
2. **分叉挑选**：在原 agent 交付的那一刻分叉它的会话，把 `select-prompt.md`（填上候选）作为下一条消息发给它，一步挑出情景对得上、做法不一致的十来条；它只回一个 JSON `{"differs": [...], "unsure": [...]}`，清单是 differs 接着 unsure。
3. 粗筛和挑选的结果里去掉 `exclude.json` 里的经验。
4. **定向核对**：另起一个 agent，提示词是 `template.md` 填好占位符，拿着这些经验（正文后面接知识）做定向核对：只核对经验点到的地方，接口名、签名、导入、枚举成员不逐个去查（写错编译会报），默认值、单位、实际行为才去查。

兜底：分叉挑选用时不到 30 秒或挑出不到 5 条时重跑一次。

## 占位符怎么填

`template.md`：

- `@@COUNT@@`：这一批经验的条数。
- `@@ANDROID@@`、`@@ANDROID_SDK@@`、`@@HM_SDK@@`：安卓源码、Android SDK、鸿蒙 SDK 在本机的位置。
- `@@DISPATCH@@`：原 agent 收到的派工原文（工程路径换成影子的工作区）。
- `@@FILES@@`：原 agent 交回时写好的文件，每行「- <路径>（N 行）」。
- `@@LESSONS@@`：经验块，每条 `<经验 k>`、换行、`python knowledge/render.py lesson-<id>` 的输出、换行、`</经验 k>`；块之间空一行，k 从 1 起，顺序就是挑选清单的顺序。没有知识文件的经验只有正文。

`select-prompt.md`：

- `{N}`：候选条数。
- `{CANDIDATES}`：候选清单，按粗筛名次排，每条一块、块之间空一行。一块是：`<id>｜<标题>`；`何时使用：<何时使用一段，空白压成一个空格>`；`适用情境：<适用情境一段，同上>`；`做法：` 换行接做法的编号列表原样。不带例外、原因、来源。

## 量出来的数

一个留出应用的三个单元，各两轮，Opus 盲评 32 处偏差（判据来自返修归因：真的看到问题、修掉、再往前追到原 agent）：

- 这套做法修掉 12 处（两轮 14、10），挑选每单元约 1.5 分钟。
- 不粗筛的基线修掉 10.3 处、挑选每单元 12–15 分钟。
- 直接审查（不给库）修掉 3.5 处。
- 同样的定向做法拿掉知识修掉 7.5 处且更贵。
- 合计花费和直接审查相差一成左右。

这些数是在本分支之前的配置上量的：同一套流程和模板，库是 main 加当时已有的知识（上面「第三版」那批）。本分支的库本身还没有拿来跑过。

## 没验证的

- 效果只在上面这一个应用上量过。
- 在第二个留出应用的三个单元上只验证了挑选这一步的速度（每单元 77–119 秒，和上面一致）；效果没有比成——那份迁移代码上有返修或上机证据、又能只读代码判的问题总共只有 8 个，三个单元最多覆盖 4–6 个，不够分出差别。拿「对照源码审查出来的偏差」当判据不行：那类偏差天然偏向直接审查。
- 第七版规则补的 22 条知识有独立复核、没有效果数据。
- 新格式（2026-11-21 起）补的 263 条知识（1108 个条目）没有效果数据，复核情况见 `knowledge/README.md` 的「并入记录」。
- 其余经验还没有知识。
- `exclude.json` 的 9 条只按经验自己的文字判定，没有逐条的效果数据。
