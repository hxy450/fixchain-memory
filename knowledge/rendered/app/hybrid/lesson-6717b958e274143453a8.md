# 迁移嵌入 Flutter 页面的原生宿主时打开实际挂载的容器子类，逐项迁移事件监听与反向推送，不只挂 FlutterUIComponent

## 何时使用

原生宿主迁移与规格提取阶段，把承载 Flutter 页面的 Activity/Fragment（经 flutter_boost 挂载自定义容器子类）转成 ArkTS 页面，确定宿主除挂容器外还要承担哪些原生↔Flutter 通信时

## 适用情境

源端宿主经 flutter_boost 挂载的是自定义 FlutterBoostFragment 子类，在其中 addEventListener(通道名) 分发 Flutter 事件、sendEventToFlutter 反向推数据；事件名常量、桥接 Model 与宿主分散在不同源文件；契约可能把这类桥接标成“待 Feature Spec”。

## 例外与边界

- 源端宿主直接挂库里的容器、没有子类，或子类里没有 addEventListener、sendEventToFlutter 等通信代码时，目标页只挂容器就是对的，不为对齐本条补通道

## 原因

宿主 Activity 里只看得到“挂一个 Fragment”，事件通信写在 Fragment 子类里；不打开它，迁移结果就只剩容器，编译和页面显示都正常，到点击交互才没有反应。来源中首页宿主被整页写过几次，写者读过事件常量表，也看到宿主调用了向 Flutter 推送的方法，写出来仍只有容器；规格作者也没读宿主源码，把事件锚到了别的页面，切片又把事件项丢了。

## 做法

1. 顺着宿主取 Fragment 的调用找到实际挂载的容器子类，打开源文件，列出 addEventListener 的通道名与事件分支、sendEventToFlutter 的推送点，在目标页逐项实现；目标页未迁的分支写日志占位和 TODO。
2. 写完后 grep 源宿主与目标页的 addEventListener/sendEventToFlutter，逐条对应；已读到事件常量表时，宿主页至少注册对应通道，或显式登记缺口。
3. 契约把某个桥接标为“待 Feature Spec”时，feature spec 要读源端实现，写明通道机制（flutter_boost 事件还是 MethodChannel）、通道名、事件清单、宿主锚点与数据 Model 字段，并落到切片的具体步骤。
