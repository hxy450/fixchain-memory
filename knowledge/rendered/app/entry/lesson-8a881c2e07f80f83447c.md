# 源端靠依赖注入或全局静态工具就绪的基础设施改成需显式 init 的封装后，在入口 onCreate 最早处调用，并确认启动期读写都晚于初始化

## 何时使用

网络、键值存储等基础设施实现与入口接线阶段：新建必须先 init 才能用的封装，或改写 EntryAbility.onCreate、宣告基础层完成时

## 适用情境

源端网络 baseUrl 由 DI 模块在注入时带上、键值工具（SpUtils/MMKV 一类）全局静态可用，Application.onCreate 里看不到对应的初始化；目标端改为静态 HttpClient（baseUrl 默认空串）加 NetworkConfig.init()、偏好封装需先传入上下文；入口 Ability 由编排会话维护，Flutter 插件 onAttachedToEngine 等回调里也能拿到上下文。也包括网络层以静态运行期配置承接构建期注入值（configure 写入、未配置即 throw），基础模块不得改入口，启动接线者不知道这条调用义务。在入口补上 init 时，业务服务里原有的 init/configure 调用（如用户切换环境时按新环境重配）照留：它负责运行中改配置，不是重复调用，也不能替代入口那一次。也包括源端数据层每次读写都无条件调用的能力（加解密等），目标由基座在 DAO 留 setter 注入接缝并配恒等或空实现默认值，实现由后续切片注入。模块里还有别的 UIAbility 或 ExtensionAbility（服务卡片、后台服务等）可能不经入口 UIAbility 就被拉起并读写时，只写在入口 UIAbility.onCreate 的 init 在这些路径上不执行，要放到 AbilityStage.onCreate（模块内任何应用组件实例加载前执行）或在每个入口都调用。

## 原因

迁移把“注入即就绪”改成“调用 init 才就绪”，调用义务是新产生的，源端没有可对照的调用点。实现者写了 init 却不接入口，或把唯一的 init 放进较晚的回调、只在某个业务单例首次取用时才执行，启动期的请求和读写就会拿到空 baseUrl、空偏好或未注入的钩子；这类封装在未初始化时常静默返回默认值，表象是网络错误或数据丢失，恒等加解密默认值还会让密文与明文混写。实现者回报“无待接线项”或把占位改成“已兑现”注释后，后续接线者照此认定已完成，不再追问冷启路径。

## 做法

1. 新建需显式 init 的封装时，在同一任务里把调用写进 UIAbility.onCreate（或 AbilityStage.onCreate），早于任何请求和读写；onCreate 同步返回、系统不等待其中的异步回调，init 返回 Promise 时，启动期的读写方（含 onWindowStageCreate 里加载的首页）要先等这个 Promise 完成，不能只靠在 onCreate 里 await；派工不许改入口文件时，在回报里单列待接线项，写明文件、生命周期方法和调用语句。
2. 列出启动期所有读写方（入口里的网络初始化、闪屏的状态恢复、通道回调等），逐个确认晚于初始化；写冷启动即发请求的流程前先确认这一点，以后在 onCreate 新增读写方时再核一次。
3. 未初始化就被调用时抛出或打出明确的错误日志（例如 baseUrl 为空时报“网络层未初始化”），不静默返回默认值，也不把相对路径交给 http.request；注入接缝的恒等或空实现默认值会造成静默写坏时（如加解密钩子未注入即读写），调用方在未注入时显式失败，或在批量读写任务开始前先确保注入。
4. 宣告基础层完成或改写 onCreate 前，grep 各 init 与 setXxxHook 的调用点，确认命中入口 onCreate；只命中业务服务（如环境切换）或业务单例的首次取用（getInstance）时，按未接线处理，在入口启动序列补显式注入。
5. 启动入口接线时列出基础层所有带缺失即抛错守卫的静态 configure/init（检索 static configure(、static init(、configuration is missing 等），逐一确认已在 onCreate 或启动编排中调用，再宣布启动链闭合。

- 〔原因 / 做法第 3 步〕HttpRequest.request、requestInStream 的 url 参数是发起请求的完整地址；地址缺协议时报 2300001（Unsupported protocol），格式不对或缺地址时报 2300003（Invalid URL format or missing URL）
- 〔做法第 1 步〕UIAbility.onCreate 在完全关闭状态的 UIAbility 实例被创建（冷启动）时调用；声明写明它同步返回结果，不支持异步回调
- 〔做法第 1 步〕AbilityStage 在开始加载对应 Module 的第一个应用组件（UIAbility 或 ExtensionAbility）实例之前创建，创建完成后执行它的 onCreate，所以 AbilityStage.onCreate 早于该 Module 里任何 UIAbility 的 onCreate；它持有 AbilityStageContext
- 〔适用情境 / 做法第 1 步〕preferencesDir 随上下文类型不同：ApplicationContext 取到 <路径前缀>/<加密等级>/base/preferences，AbilityStageContext、UIAbilityContext、ExtensionContext 取到 <路径前缀>/<加密等级>/base/haps/<module-name>/preferences；偏好封装用哪种上下文初始化决定首选项文件落在哪个目录
- 〔原因〕设备上网络层 baseUrl 为默认空串时，请求被发成没有 https:// 和 host 的相对路径而失败，经应用统一包装后只表现为网络错误，看不出是没初始化
