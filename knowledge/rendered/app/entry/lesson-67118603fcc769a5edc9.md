# ohos.ability.shortcuts 挂在承载快捷方式的 UIAbility 的 metadata 下，不追加到 module 级 metadata

## 何时使用

配置实现阶段，在 module.json5 中挂载桌面长按快捷菜单（ohos.ability.shortcuts）时；构建后长按不出菜单或快捷方式条目变少时；编译门报 module.json5 schema 不允许某字段时；只管源端清单静态声明的快捷方式，不含运行时动态添加的

## 适用情境

把 Android App Shortcuts 迁为 HarmonyOS 静态快捷方式：在 resources/base/profile 下新建快捷方式配置，并在 module.json5 中用 metadata 引用；module 级已有 metadata 数组（如 client_id），入口 UIAbility 还没有 metadata。把 shortcuts 引用从 module 级挪到 ability 下时，module 级 metadata 里原有的其他项（如 client_id）原样保留，只移走 ohos.ability.shortcuts 这一项。这里管的是源端在清单里静态声明的快捷方式（启动器 Activity 下 meta-data 引用的 shortcuts XML）；源端用 ShortcutManager.setDynamicShortcuts、requestPinShortcut 在运行时添加的动态或固定快捷方式不属于这份静态配置，不在这条范围内。 也包括规格或笔记凭记忆给出 module 级 shortcuts 数组，构建 schema 报 propertyName shortcuts 不允许，编译门准备删掉整块并记缺口。

## 原因

快捷方式配置只对在 abilities 里声明了该 metadata 的 UIAbility 生效。就近追加到 module 级 metadata 时长按不出菜单；来源工程的构建插件还把 module 级引用的配置改写成单个 newShortCutObj，4 条只剩 1 条，生成者转去追查插件而没回头核对层级。网络摘要常只写“通过 metadata 挂载”而不讲层级。

## 做法

1. 在 module.abilities 中目标 UIAbility（通常是 EntryAbility）的 metadata 下写 { name: "ohos.ability.shortcuts", resource: "$profile:<配置名>" }；该 ability 没有 metadata 数组就新建，不顺手追加到 module 级已有的 metadata。module 级没有 shortcuts 字段，不另写 shortcuts 数组。
2. 资料只说“通过 metadata 挂载”时，以官方或离线 module.json5 文档 shortcuts 一节的示例 JSON 路径为准，写完逐级比对自己的写入位置。
3. 写入规格或笔记给出的 module.json5 配置前，按本机 SDK toolchains/modulecheck 下的 module.json schema 核对字段是否存在；编译门报 schema 不允许的字段（如 module 级 shortcuts）时，在 SDK 文档中查该功能的现行承载位置并迁过去（快捷方式即第 1 步的 ability metadata + $profile 配置），不删除功能块后记缺口。

## 可选检查

- 构建后在编译产物的 module.json 中确认该 metadata 位于目标 ability 下，HAP 内快捷方式配置仍是 {shortcuts:[...]} 且条数与源文件一致；出现 newShortCutObj 或条目减少，先回查 metadata 层级再查打包插件。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因 / 做法第 1 步〕快捷方式配置要在 module.json5 的 abilities 里、需要快捷方式的那个 UIAbility 下配置 metadata 才对该 UIAbility 生效：写成 "metadata": [{ "name": "ohos.ability.shortcuts", "resource": "$profile:<配置名>" }]
- 〔做法第 1 步〕metadata 的 name 必须是 ohos.ability.shortcuts，这是系统识别快捷方式信息的标识；resource 指向 shortcuts 信息的资源位置
- 〔适用情境 / 做法第 1 步〕被引用的快捷方式配置文件放在 /resources/base/profile/ 下，顶层 shortcuts 是数组，每项含 shortcutId、label、icon、wants 子标签
- 〔做法第 1 步〕shortcutId 取值为不超过 63 字节的字符串，不支持用资源索引（$string）配置，不可缺省
- 〔原因〕在 HarmonyOS 5.0.4（API 16）的构建工具链上：ohos.ability.shortcuts 的 metadata 挂在 module 级时，构建产物里的快捷方式配置被改写成只含单个快捷方式的 newShortCutObj，多条只剩一条，长按桌面图标不出菜单；挂在入口 UIAbility 的 metadata 下时产物保持 shortcuts 数组的全部条目，长按出现全部菜单项
