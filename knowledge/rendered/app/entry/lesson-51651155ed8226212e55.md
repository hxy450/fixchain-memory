# 源 Activity 的 SEND 分享接收入口（standard 启动、无 onNewIntent）映射为独立 multiton Ability：skills 用 sendData 加 utd 声明，结束只 terminateSelf 本实例

## 何时使用

规格提取与入口配置阶段，把源端 ACTION_SEND/SEND_MULTIPLE 接收入口映射为目标 Ability 的实例形态、module.json5 skills 声明与结束范围时；接线阶段给入口 Ability 加分享解析或结束逻辑时

## 适用情境

源 AndroidManifest 在某 Activity（常是 LAUNCHER）上另有 SEND + DEFAULT + mimeType（如 text/plain）的 intent-filter，未声明 singleTop/singleTask/singleInstance，源码没有 onNewIntent，只在 onCreate 读 EXTRA_TEXT 等处理，结束时 finish()。目标工程只有入口 EntryAbility（launchType 默认 singleton），外部数据经系统分享面板送达，接收方用 systemShare.getSharedData 读取。

## 例外与边界

- 源 Activity 声明 singleTop/singleTask/singleInstance 或实现 onNewIntent 承接分享：按源端复用实例的语义映射到已有 Ability 的 onNewWant
- 把分享承接从 EntryAbility 移到独立 Ability 时，只删 EntryAbility 里为分享加的解析、热启动分支和中转事件槽；它的桌面入口 skill（ohos.want.action.home 加 entity.system.home）和 onNewWant 里其他来源的处理保留；新 Ability 的分享 skill 不挂 entity.system.home

## 原因

standard 启动的 Activity 每次被分享调起都由框架新建实例，finish() 只结束这个实例并回到来源应用，原来运行的应用不受影响；映射成唯一 EntryAbility 的 onCreate/onNewWant 冷热启动承接后，结束分享流程的 terminateSelf 会关掉整个应用，热启动还要另设全局事件槽。系统分享面板按 UTD 匹配接收目标：把源 mimeType 写成 skills uris 的 type 时，应用不会出现在分享面板里。

## 做法

1. 规格写明实例形态：每次外部分享新建实例、结束只结束该实例。目标用独立 UIAbility（exported、launchType: multiton），加载同一页面，经 loadContent 的 LocalStorage 把分享内容交给页面，结束时在该实例上 terminateSelf；入口 EntryAbility 只保留桌面入口。
2. skills 写 actions ['ohos.want.action.sendData']，uris 每类数据一条 {scheme: 'file', utd: <源 MIME 对应的 UTD，text/plain 为 general.plain-text>, maxFileSupported: N}；写前查本机 SDK toolchains/modulecheck/module.json 中 skills.uris 的字段。接收方用 systemShare.getSharedData(want) 按记录的 utd 取内容，与 skills 声明一致。

## 可选检查

- 从另一个应用打开系统分享面板，确认看到并选中本应用后新开任务；导入或取消后原应用界面仍在前台。

来源支持：2 张卡 · 2 次迁移 · 2 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36 的平台资源。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因〕Activity 没有声明 launchMode 时为 standard：每次启动通常新建一个实例；singleTop（同一 Activity 实例在前台时）和 singleTask（已有以它开头的任务时）复用已有实例并回调 onNewIntent
- 〔适用情境 / 做法第 1 步〕module.json5 的 abilities.launchType 不写时为 singleton（仅第一次启动创建新实例）；multiton 每次启动创建一个新实例；standard 是 multiton 的曾用名
- 〔原因 / 做法第 1 步〕UIAbilityContext.terminateSelf 销毁 UIAbility 自身；module.json5 的 removeMissionAfterTerminate 不写时为 false，此时销毁后任务列表里保留这个任务（最近任务里留快照）；2in1 设备和平板的自由多窗模式下默认移除
- 〔原因 / 做法第 1 步〕HarmonyOS 6.1.0（API 23）上，从另一应用的系统分享面板选中本应用后，承接分享的 launchType 为 multiton 的独立 UIAbility 作为新任务打开；这个实例 terminateSelf 后分享任务结束，应用原先打开的界面仍在
- 〔原因 / 做法第 2 步〕HarmonyOS 6.1.0（API 23）上，sendData skill 的 uris 只写 {type: 'text/plain'} 时系统分享面板里不出现该应用；uris 写 {scheme: 'file', utd: 'general.plain-text', maxFileSupported: 1} 时出现
- 〔做法第 2 步〕skills.uris 里：scheme 只在 uris 仅配置 type 时可以缺省，否则不可缺省；utd 是与 Want 匹配的标准化数据类型、适用于分享等场景，缺省为空；maxFileSupported 是对指定类型一次能接收的最大数量，要与 utd 配合，缺省为 0
- 〔做法第 2 步〕分享接收 skills 的 action 值是字符串 'ohos.want.action.sendData'（wantConstant.Action.ACTION_SEND_DATA，发送单个数据记录）
- 〔做法第 2 步〕UTD 预置列表里 MIME text/plain 对应 general.plain-text（父类型 general.text），image/jpeg、image/png、image/gif 对应 general.jpeg、general.png、general.gif（父类型 general.image）；general.text、general.image、general.hyperlink 没有对应的 MIME；text/plain 还挂在 general.log、general.diff、general.asc-text 等按扩展名区分的类型上
- 〔做法第 2 步〕systemShare.getSharedData(want) 从拉起分享承接 Ability 的 want 解析分享数据，解析失败以 1003703001 拒绝；SharedRecord.content 放文本、HTML 文本、URL 这类不需授权的内容，文件走 SharedRecord.uri
