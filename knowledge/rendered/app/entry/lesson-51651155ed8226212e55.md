# 源 Activity 的 SEND 分享接收入口（standard 启动、无 onNewIntent）映射为独立 multiton Ability：skills 用 sendData 加 utd 声明，结束只 terminateSelf 本实例

## 何时使用

规格提取与入口配置阶段，把源端 ACTION_SEND/SEND_MULTIPLE 接收入口映射为目标 Ability 的实例形态、module.json5 skills 声明与结束范围时；接线阶段给入口 Ability 加分享解析或结束逻辑时

## 适用情境

源 AndroidManifest 在某 Activity（常是 LAUNCHER）上另有 SEND + DEFAULT + mimeType（如 text/plain）的 intent-filter，未声明 singleTop/singleTask/singleInstance，源码没有 onNewIntent，只在 onCreate 读 EXTRA_TEXT 等处理，结束时 finish()。目标工程只有入口 EntryAbility（launchType 默认 singleton），外部数据经系统分享面板送达，接收方用 systemShare.getSharedData 读取。

## 例外与边界

- 源 Activity 声明 singleTop/singleTask/singleInstance 或实现 onNewIntent 承接分享：按源端复用实例的语义映射到已有 Ability 的 onNewWant

## 原因

standard 启动的 Activity 每次被分享调起都由框架新建实例，finish() 只结束这个实例并回到来源应用，原来运行的应用不受影响；映射成唯一 EntryAbility 的 onCreate/onNewWant 冷热启动承接后，结束分享流程的 terminateSelf 会关掉整个应用，热启动还要另设全局事件槽。系统分享面板按 UTD 匹配接收目标：把源 mimeType 写成 skills uris 的 type 时，应用不会出现在分享面板里。

## 做法

1. 规格写明实例形态：每次外部分享新建实例、结束只结束该实例。目标用独立 UIAbility（exported、launchType: multiton），加载同一页面，经 loadContent 的 LocalStorage 把分享内容交给页面，结束时在该实例上 terminateSelf；入口 EntryAbility 只保留桌面入口。
2. skills 写 actions ['ohos.want.action.sendData']，uris 每类数据一条 {scheme: 'file', utd: <源 MIME 对应的 UTD，text/plain 为 general.plain-text>, maxFileSupported: N}；写前查本机 SDK toolchains/modulecheck/module.json 中 skills.uris 的字段。接收方用 systemShare.getSharedData(want) 按记录的 utd 取内容，与 skills 声明一致。

## 可选检查

- 从另一个应用打开系统分享面板，确认看到并选中本应用后新开任务；导入或取消后原应用界面仍在前台。

来源支持：2 张卡 · 2 次迁移 · 2 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；Share Kit 声明在 SDK 的 hms/ets 下；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 平台资源 android-36。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 原因〕安卓清单里 activity 没有声明 launchMode 时为 standard：每次启动通常新建一个实例；singleTop 时，同一 Activity 的实例已在前台与用户交互就复用它并回调 onNewIntent；singleTask、singleInstance 已有对应实例时把它所在的任务带到前台并回调 onNewIntent；API 31 起另有 singleInstancePerTask（只能作任务根，一个任务里只有一个实例）。运行时 Intent 的 FLAG_ACTIVITY_SINGLE_TOP、FLAG_ACTIVITY_NEW_TASK、FLAG_ACTIVITY_MULTIPLE_TASK 可以改变这些启动行为
- 〔原因〕安卓上 standard 启动、没有 onNewIntent 的 SEND 接收 Activity：每次从别的应用分享都新建一个实例并出现独立任务，它 finish 后回到原来的界面，原先运行中的列表界面不受影响
- 〔原因 / 做法第 2 步〕鸿蒙系统分享面板按 skills uris 的 utd 选接收目标：sendData skill 的 uris 只写 MIME type（如 type: 'text/plain'）、不写 utd 时，本应用不出现在分享面板里
- 〔适用情境 / 做法第 1 步〕module.json5 abilities 的 launchType：multiton 每次启动创建一个新实例（最近任务列表里可见多个），singleton 仅第一次启动创建新实例，specified 运行时由开发者决定，standard 是 multiton 的曾用名；缺省为 singleton。singleton 的 UIAbility 实例已存在时再次被拉起，只进 onNewWant，不进 onCreate 和 onWindowStageCreate
- 〔做法第 1 步〕module.json5 abilities 的 exported 缺省为 false：只能由同应用或有 ohos.permission.START_INVISIBLE_ABILITY 权限（仅系统应用可申请）的应用拉起；为 true 才能被其他应用拉起
- 〔做法第 1 步〕WindowStage.loadContent(path: string, storage?: LocalStorage): Promise<void>（另有 loadContent(path, storage, callback) 重载，首段 @since 9）加载页面并把 LocalStorage 交给页面，多次调用会先销毁已有页面内容；页面里用 this.getUIContext().getSharedLocalStorage(): LocalStorage | undefined（@since 12）取这一 stage 共享的 LocalStorage 实例，不存在时返回 undefined
- 〔做法第 1 步〕UIAbilityContext.terminateSelf(): Promise<void>（另有 callback 重载，首段 @since 9）销毁调用它的这个 UIAbility 实例，只能在主线程调用；销毁后任务中心里的任务默认不清理，abilities 的 removeMissionAfterTerminate 设为 true 才移除（缺省 false；2in1 和平板的自由多窗模式下这个配置不生效、默认移除）
- 〔做法第 2 步〕skills.actions 里的 'ohos.want.action.sendData' 是发送单个数据记录的 action 字符串（发送多个为 'ohos.want.action.sendMultipleData'）；它们出自 @ohos.ability.wantConstant 的 Action 枚举（ACTION_SEND_DATA、ACTION_SEND_MULTIPLE_DATA），这个模块 API 9 起废弃，新模块 @ohos.app.ability.wantConstant 的声明里没有 Action 枚举，module.json5 里直接写字符串
- 〔做法第 2 步〕skills.uris 的每一项可写 scheme、host、port、path | pathStartWith | pathRegex、type、utd、maxFileSupported、linkFeature；utd 是与 Want 相匹配的标准化数据类型，适用于分享等场景；maxFileSupported 是对指定类型的文件一次能接收或打开的最大数量，需与 utd 配合，缺省 0；scheme 只在这一项仅配置 type 时可缺省。编译期校验（toolchains/modulecheck/module.json）对 uris 每一项的要求：要么带 scheme（其余字段取上面那些），要么只有 type 一个字段
- 〔做法第 2 步〕uniformTypeDescriptor（从 @kit.ArkData 导入）的 UniformDataType 枚举：PLAIN_TEXT = 'general.plain-text'、TEXT = 'general.text'、HTML = 'general.html'、HYPERLINK = 'general.hyperlink'、IMAGE = 'general.image'、JPEG = 'general.jpeg'、PNG = 'general.png'、GIF = 'general.gif'、FILE = 'general.file'、OBJECT = 'general.object'。UTD 预置列表里 general.plain-text 对应 MIME text/plain（text/plain 还对应 general.asc-text、general.log 等），general.png 对应 image/png，general.jpeg 对应 image/jpeg；general.text、general.image、general.object 是基类型，没有对应的 MIME
- 〔做法第 2 步〕uniformTypeDescriptor.getUniformDataTypeByMIMEType(mimeType: string, belongsTo?: string): string（首段 @since 11）按 MIME 查对应的 UTD，查不到时返回动态类型（flexible type）；getUniformDataTypesByMIMEType(mimeType: string, belongsTo?: string): Array<string>（首段 @since 13）返回全部对应的 UTD
- 〔做法第 2 步〕systemShare（从 @kit.ShareKit 导入，HarmonyOS 能力，声明在 SDK 的 hms 下）：getSharedData(want: Want): Promise<SharedData>（@since 4.1.0(11)）从拉起分享接收 Ability 的 want 里解析分享数据，解析失败抛 1003703001；SharedData.getRecords(): Array<SharedRecord>；SharedRecord 有 utd: string、content?: string（不需授权的内容，如文本、HTML 文本、URL）、uri?: string、title?: string、description?: string
