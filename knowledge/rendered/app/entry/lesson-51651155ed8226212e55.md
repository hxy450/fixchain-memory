# 源 Activity 的 SEND 分享接收入口（standard 启动、无 onNewIntent）映射为独立 multiton Ability：skills 用 sendData 加 utd 声明，结束只 terminateSelf 本实例

## 何时使用

规格提取与入口配置阶段，把源端 ACTION_SEND/SEND_MULTIPLE 接收入口映射为目标 Ability 的实例形态、module.json5 skills 声明与结束范围时；接线阶段给入口 Ability 加分享解析或结束逻辑时

## 适用情境

源 AndroidManifest 在某 Activity（常是 LAUNCHER）上另有 SEND + DEFAULT + mimeType（如 text/plain）的 intent-filter，未声明 singleTop/singleTask/singleInstance，源码没有 onNewIntent，只在 onCreate 读 EXTRA_TEXT 等处理，结束时 finish()。目标工程只有入口 EntryAbility（launchType 默认 singleton），外部数据经系统分享面板送达，接收方用 systemShare.getSharedData 读取。

## 例外与边界

- 源 Activity 声明 singleTop/singleTask/singleInstance 或实现 onNewIntent 承接分享：按源端复用实例的语义映射到已有 Ability 的 onNewWant

## 原因

standard 启动的 Activity 每次被分享调起都由框架新建实例，finish() 只结束这个实例并回到来源应用，原来运行的应用不受影响；映射成唯一 EntryAbility 的 onCreate/onNewWant 冷热启动承接后，结束分享流程的 terminateSelf 会关掉整个应用，热启动还要另设全局事件槽。系统分享面板按 UTD 匹配接收目标：把源 mimeType 写成 skills uris 的 type 时，应用不会出现在分享面板里。

## 做法

1. 规格写明实例形态：每次外部分享新建实例、结束只结束该实例。目标用独立 UIAbility（exported、launchType: multiton），加载同一页面，经 loadContent 的 LocalStorage 把分享内容交给页面，结束时在该实例上 terminateSelf；入口 EntryAbility 只保留桌面入口。
2. skills 写 actions ['ohos.want.action.sendData']，uris 每类数据一条 {scheme: 'file', utd: <源 MIME 对应的 UTD，text/plain 为 general.plain-text>, maxFileSupported: N}；写前查本机 SDK toolchains/modulecheck/module.json 中 skills.uris 的字段。接收方用 systemShare.getSharedData(want) 按记录的 utd 取内容，与 skills 声明一致。

## 可选检查

- 从另一个应用打开系统分享面板，确认看到并选中本应用后新开任务；导入或取消后原应用界面仍在前台。

来源支持：2 张卡 · 2 次迁移 · 2 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；安卓 Android SDK 源码 android-36.1。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境〕module.json5 里 UIAbility 不写 launchType 时取 singleton：实例已存在时再次启动会复用它，只进 onNewWant，不进 onCreate 和 onWindowStageCreate；multiton（standard 是它的曾用名）每次启动都在应用进程中新建一个实例，最近任务列表里能看到多个。〔成立范围：对 Stage 模型 UIAbility 的 launchType；specified 由开发者在运行时决定是否新建；最常见的不成立情形：singleton 实例还在启动过程中时再次 startAbility，会收到错误码 16000082。〕
- 〔做法第 1 步〕UIAbilityContext.terminateSelf() 销毁调用它的这个 UIAbility 实例；调用后任务中心里的任务默认不清理，要在该 Ability 的 module.json5 配置 removeMissionAfterTerminate 为 true 才在销毁后移除任务（缺省 false）。〔成立范围：对 UIAbility 实例；2in1 设备和平板的自由多窗模式下 removeMissionAfterTerminate 不生效、默认移除任务；最常见的不成立情形：在应用唯一的入口 EntryAbility 上调用，会把整个应用界面关掉。〕
- 〔做法第 1 步〕UIAbility.onBackPressed 未覆写时，targetSdkVersion ≥ 12 默认返回 true：侧滑或按返回键退到 UIAbility 层时实例被移到后台、不销毁；targetSdkVersion < 12 默认返回 false，实例被销毁。安卓上不是任务根的 Activity 按返回默认 finish。〔成立范围：对每个 UIAbility，包括为分享新开的 multiton 实例；最常见的不成立情形：覆写 onBackPressed 返回 false，或在其中调用 terminateSelf 时会销毁。〕
- 〔做法第 2 步〕skills.uris 的 utd 是与 Want 匹配的标准化数据类型，用于分享等场景，缺省为空；maxFileSupported 是对指定类型一次能接收或打开的最大数量，需要与 utd 配合使用，缺省为 0；uris 里只配置 type 时 scheme 才可缺省，其他情况 scheme 不可缺省。〔成立范围：对 module.json5 中 abilities 的 skills.uris（这些字符串字段不支持 $string 资源引用）；最常见的不成立情形：只写 utd 不写 maxFileSupported 时取缺省值 0。〕
- 〔做法第 2 步〕MIME 类型 text/plain 对应的预置 UTD 是 general.plain-text（归属 general.text，后缀 .txt、.text）；uniformTypeDescriptor.getUniformDataTypeByMIMEType 可按 MIME 查 UTD，查不到预置类型时返回按入参生成的动态类型 ID 而不报错。〔成立范围：对 UTD 预置列表里的类型，其他 MIME 要逐个查列表；最常见的不成立情形：非预置 MIME 查到的是动态生成的类型 ID，不在预置列表里。〕
- 〔做法第 2 步〕systemShare.getSharedData(want) 解析出的每条 SharedRecord 带 utd；文本、HTML 文本、URL 等不需要授权的内容在 content 字段，文件等以 URI 给出的内容在 uri 字段，另有 title、description 等可选字段；解析失败抛 1003703001。〔成立范围：对 Share Kit（@hms.collaboration.systemShare，4.1.0(11) 起）的接收端，依据是 SDK 声明的注释（本机文档副本没有 Share Kit 文档）；最常见的不成立情形：content、uri 都是可选字段，同一条记录可能只有其中之一。〕
