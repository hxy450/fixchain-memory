# adaptive-icon 转 layered-image 时前景与背景生成同尺寸图层，前景先裁出启动器可见区再缩放，不直接拷贝 108dp 全层

## 何时使用

资源迁移阶段，把 Android adaptive-icon 转成鸿蒙 layered-image 并生成前景、背景图层 PNG 时；核验应用图标或维护资源转换规则时

## 适用情境

Android 应用图标是 adaptive-icon（规范：图层 108dp，启动器只显示中央 72dp）：背景为 @color 纯色或 108dp 图层，前景为 mipmap 下 108dp 全层 PNG或 drawable 下的矢量（如 ic_launcher_foreground.xml），工程里通常还有旧版合成的 ic_launcher.png；鸿蒙侧用 layered_image.json 的 foreground/background 两个 $media 图层；转换规则写“mipmap 直接拷贝”“纯色背景任意尺寸（如 1×1 或 108×108）”。

## 例外与边界

- 72/108 的裁切只对 adaptive-icon 的前景、背景层成立：源端应用图标不是 adaptive-icon（没有 <adaptive-icon> 资源，只有旧版 ic_launcher.png 一类整张位图）时，那张图本身就是完整的可见图形，不按 72/108 再裁，按目标图层尺寸等比放入即可。

## 原因

鸿蒙分层图标要求前景、背景同像素尺寸（规范为 1024×1024px），来源对照中按整层显示；直接拷贝安卓前景全层会把可见区外的 18dp 外圈一并显示，图形比安卓小，任意尺寸的纯色背景又与前景尺寸不一。只比颜色与字节一致的核验发现不了这两点。

## 做法

1. 前景取 adaptive-icon <foreground> 引用的资源（位图取最高密度；drawable 矢量先按 108dp 视窗栅格化），不用旧版合成的 ic_launcher.png 充当前景；按 adaptive icon 规范裁出中央 72/108（例：432px 取中央 288px），再等比缩放到目标图层尺寸；@color 背景生成与前景同尺寸的纯色 PNG。
2. 核验图标时除颜色外检查两层尺寸相等，并对比可见内容占比与安卓一致；维护转换规则时把“任意尺寸纯色底”“mipmap 直接拷贝”改成“同尺寸图层加裁到可见区”。

- 〔适用情境 / 原因 / 做法第 1 步〕安卓 adaptive icon 的前景层和背景层都按 108 x 108 dp 设计，只有中央 72 x 72 dp 出现在启动器的遮罩视窗里，四边各 18 dp 留给系统界面做视觉效果
- 〔做法第 1 步〕AdaptiveIconDrawable 的 EXTRA_INSET_PERCENTAGE 为 1/4，DEFAULT_VIEW_PORT_SCALE = 1 / (1 + 2 × 1/4) = 2/3，即可见视窗边长是整层边长的 2/3（432px 的层对应中央 288px）
- 〔原因 / 做法第 1 步〕鸿蒙文档里 1024×1024px 的分层图标规格写在 module.json5 shortcuts 的 icon 说明里：推荐前景图显示大小 450×450px、资源大小 1024×1024px 的透明图层，背景图 1024×1024px；「配置应用图标和名称」一文没有给应用图标的像素规格
- 〔做法第 2 步〕编译构建时 AppScope 下的资源文件会合入模块下相同路径的资源目录，重名时 AppScope 的文件覆盖模块里的；分层图标资源同名而图片不同时，最终生效的是 AppScope（app.json5）里的图标
