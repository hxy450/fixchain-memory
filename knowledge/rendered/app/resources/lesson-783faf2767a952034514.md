# 8 位颜色保持 #AARRGGBB 字节序，转换后与源逐项往返核对

## 何时使用

资源迁移阶段，编写或运行 colors.xml 到 color.json 的转换逻辑（包括编排者降级自跑脚本）时

## 适用情境

源含带透明度的 8 位颜色；转换由自写脚本完成而不是直接按资源转换 skill 的规则执行，深色值可能从浅色转换结果派生，接手者可能被告知已完成部分“勿重做”。

## 原因

HarmonyOS 颜色与 Android 同为 #AARRGGBB，套用 CSS #RRGGBBAA 的直觉会互换字节；从已出错的浅色结果派生会把错误复制到深色目录。

## 做法

1. 自写或降级执行转换前，先加载规范指定的资源转换 skill 及其颜色规则，8 位值原样保留；深色值从同名或同义源值转换，不复制浅色转换结果。

## 可选检查

- 转换由自写脚本完成或中途换人接手时，把同名键的源值归一化为 #AARRGGBB 后与结果逐项比对，“首两位与末两位互换后才相等”即为字节序错误

来源支持：1 张卡 · 1 次迁移 · 1 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；安卓 Android SDK 源码 android-36.1。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因〕鸿蒙 color.json 的颜色值只收 #rgb、#argb、#rrggbb、#aarrggbb 四种十六进制，或 $color:（应用自身）、$ohos:color:（系统）引用；ArkUI 的字符串颜色也按 ARGB 解析：8 位时前两位是透明度（如 '#E5FFFFFF' 为透明度 E5、RGB 为 FFFFFF），与安卓 #AARRGGBB 同序；4 位是 #argb，不是 CSS 的 #rgba。要写透明度在后的 CSS 式写法只有 ArkUI 字符串的 rgba() 函数形式（如 'rgba(255, 100, 255, 0.5)'），color.json 不收。〔成立范围：对象：resources 下 element/color.json 的颜色值，以及 ArkUI 组件属性里字符串形式的 ResourceColor。条件：color.json 一侧依据是文档说明（restool 错误码 11211108 的格式要求）；字符串一侧依据 ResourceColor 类型说明与启动页背景色的 ARGB 示例，4 位按 ARGB 取值依据 arkui_ace_engine 仓 master 的 Color::FromString（3、4 位逐位重复成 6、8 位后按 ARGB 取值）。不成立：number 形式的颜色按透明度字节是否为 0 区分格式，见条目 2。〕
- 〔例外与边界〕ArkUI 的 number 型颜色不看写了几位：透明度字节（最高 8 位）为 0 时一律当 RGB、补成不透明，非 0 时按 ARGB；所以 0x00FFFFFF 是不透明白色，0（安卓 Color.TRANSPARENT 的值）是不透明黑色，而安卓 Color int 里这两个都是全透明。〔成立范围：对象：ArkUI 组件属性接收的 number 型 ResourceColor（声明式前端 JSViewAbstract::ParseJsColor 这条路径）。条件：依据是文档说明（ResourceColor 的 number 说明，示例 0x00ffffff 按 RGB 解析）与 arkui_ace_engine 仓 master 的 ColorAlphaAdapt（origin >> 24 为 0 时或上 0xFF000000）；attributeModifier 等其他绑定路径未核。不成立：透明度字节非零的值（如 0x80FFFFFF、0xffff0000）按 ARGB 解析，与安卓一致；color.json 不收数字。〕
- 〔做法第 1 步〕限定词目录（如 dark/element/color.json）里找不到某个名字时，运行时回到 base 目录取同名资源，不报错；dark 下漏转或漏写的颜色会静默显示 base（浅色）的值。〔成立范围：对象：按颜色模式等限定词匹配的 element 资源。条件：依据是文档说明；dark 目录只在当前颜色模式为深色时参与匹配（跟随系统，或应用经 ApplicationContext.setColorMode 设为深色）。不成立：rawfile、resfile 不按设备状态匹配，没有这种回退。〕
