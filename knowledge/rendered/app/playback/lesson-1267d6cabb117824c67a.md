# AVPlayer 播放应用包内 rawfile 资源时用 getRawFd(Sync) 的 {fd, offset, length} 设 fdSrc，不把描述符拼成 fd://N?offset= 形式的 url；源端 SoundPool 短音效改用 media.SoundPool，三个字段传给 load

## 何时使用

规格提取阶段为音视频资源加载写平台 API 契约时；播放服务实现阶段为 AVPlayer 绑定应用包内 rawfile 资源时；为源端短音效（解码后 1MB 以内）选择目标播放 API 时

## 适用情境

源端用 SoundPool.load(context, R.raw.x) 或 MediaPlayer.create(context, R.raw.x) 播放 res/raw 资源，资源迁到 resources/rawfile：MediaPlayer 与较长音频目标用 AVPlayer，SoundPool 预加载的短音效目标用 media.SoundPool；resourceManager.getRawFd/getRawFdSync 返回整个 HAP 的 fd 加该资源在 HAP 内的 offset/length；AVPlayer 有 url 与 fdSrc（AVFileDescriptor）两种设源方式。 SoundPool.load 有 uri 与 (fd, offset, length) 两种重载。改用 media.SoundPool 的前提是源端那条音效解码后在 1MB 以内（44.1kHz、16bit 立体声约 5.6 秒）；源端拿 SoundPool 放更长的音频（如循环背景音）时，超出部分会被截掉，这一条走 AVPlayer，不按第 1 步改成 SoundPool。

## 原因

url 的 fd:// 形式只接受整文件的 fd://<数字>，拼上 offset/length 查询串会被判参数错误（401），播放器停在 error 态，音效与音乐全部静默。来源中规格作者凭记忆写“getRawFd → url=fd://”，实现者已读到 d.ts 中 fdSrc 适用于连续存放在同一文件中的资源，仍照规格自造了查询串。 源端 SoundPool 在构造时 load 预解码、事件时 play 即时多路发声；改成每次播放新建 AVPlayer，要先走完 prepare 才出声，延迟明显。

## 做法

1. rawfile 资源写成 const d = resourceManager.getRawFdSync(name); player.fdSrc = { fd: d.fd, offset: d.offset, length: d.length }；只有沙箱里的独立文件才用 fileIo 打开后设 url = 'fd://' + fd。 源端是 SoundPool（构造或初始化时 load、事件时 play、maxStreams 多路叠播）时不改用 AVPlayer：media.createSoundPool(maxStreams, audioRendererInfo) 建池，按源端时机用 getRawFdSync 的结果调 load(d.fd, d.offset, d.length)，事件时 play(soundID)，同样不拼 url；接口见本地 SDK ets/api/@ohos.multimedia.media.d.ts 的 createSoundPool 与 ets/api/multimedia/soundPool.d.ts 的 load、play。
2. 规格写法与写前读到的 d.ts 注释冲突时按 d.ts 实现，并回报规格该行有误。 为源端播放类写映射行前，先按源类名在本地 SDK d.ts 中查目标同类 API（如 createSoundPool），列为候选再写取舍；经验提醒与技能模板给出的目标类只作参考。

## 可选检查

- 首次设备运行看 hilog 不出现 401 或“not a fd://+numeric string”；代码中 getRawFd 的结果不流向 .url。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 做法第 1 步〕resourceManager.getRawFd / getRawFdSync 返回的 RawFileDescriptor 里，offset 是该 rawfile 在 HAP 包中的起始位置，length 是它的大小，单位都是字节；fd 指向的不是这个 rawfile 单独的文件
- 〔适用情境 / 原因 / 做法第 1 步〕AVPlayer 的 url、fdSrc 都只能在 idle 状态设置；fdSrc 用于多个媒体资源连续存放在同一文件里、按偏移和长度播放的情形，文档说明独立的媒体文件才用 url 的 fd://xx 形式
- 〔做法第 1 步〕AVFileDescriptor.offset 不写时为 0，length 不写时取文件中从 offset 起的剩余字节；两者要按预置资源的实际信息填，非法值会造成音视频资源解析错误
- 〔原因〕卡里设备上把 url 写成 fd://<数字> 再拼 ?offset=&length= 查询串时，播放器建好即报 401，系统日志为「not a fd://+numeric string」
- 〔原因〕卡里设备上每次新建 AVPlayer 播短音效，从 createAVPlayer 到 playing 约 290ms；用 createSoundPool 预先 load、事件时 play，出声约 40ms
- 〔做法第 1 步〕media.createSoundPool 的 maxStreams 取 1 到 32 的整数；API 18 之前 SoundPool 底层是单例，一个应用进程只能创建一个 SoundPool 实例
- 〔做法第 1 步〕createSoundPool 的 audioRenderInfo.usage 为 STREAM_USAGE_UNKNOWN、STREAM_USAGE_MUSIC、STREAM_USAGE_MOVIE 或 STREAM_USAGE_AUDIOBOOK 时，SoundPool 播短音用混音模式，不打断其他音频
- 〔做法第 1 步〕SoundPool.load(uri) 的 uri 是由文件描述符生成的 fd:// 字符串，不能加载 rawfile 目录里的资源；rawfile 要用 load(fd, offset, length)
- 〔做法第 1 步〕SoundPool 加载完成通过 on('loadComplete') 回调通知，文档要求 play 放在收到这个回调之后；多次调用 play 播放同一个 soundID，只会播放一次
- 〔适用情境 / 做法第 1 步〕SoundPool 只支持解码后 1MB 以下的音频，超过的只截取前 1MB 播放（44.1kHz、16bit 立体声约 5.6 秒）
- 〔适用情境〕安卓 SoundPool(int maxStreams, int streamType, int srcQuality) 的 srcQuality（采样率转换质量）目前不起作用
