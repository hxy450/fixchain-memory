# 清单声明的 NFC TECH_DISCOVERED 贴卡拉起入口映射为 module.json5 skills（TAG_FOUND + tag-tech），在 onCreate/onNewWant 取 TagInfo；运行时启停开关只作用于这条系统派发

## 何时使用

规格提取与入口实现阶段，映射 AndroidManifest 中 NFC TECH_DISCOVERED（activity-alias 或 intent-filter 加 tech-list）入口及偏好里启停它的开关时

## 适用情境

源应用用 activity-alias 声明 android.nfc.action.TECH_DISCOVERED（meta-data 指向 tech-list，如 NfcA）作为贴卡拉起入口，并在偏好里用 PackageManager.setComponentEnabledSetting 启停该 alias；各 Activity 另在 onResume 无条件开启前台派发；目标 module.json5 只有 home skill。

## 例外与边界

- 第 2 步的前提是源端开关只启停清单入口、前台派发在 onResume 无条件开启；源端基类或页面在开启前台派发前也读了同一偏好时，按源端实际受控的路径映射，两条路径都受开关控制。

## 原因

贴卡拉起是独立于前台派发的系统入口：目标同样能在 skills 中声明 ohos.nfc.tag.action.TAG_FOUND 与 tag-tech uris，只是第三方不能运行时启停 skill。把它判为无对等，应用失去贴卡拉起；把开关改成前台派发闸门，关闭开关后应用内读卡也失效。来源中规格把整条入口写成“无对等，应用内开关模拟”，开关被实现成前台回调首行的 return。

## 做法

1. 入口 ability 的 skills 增加 actions: ["ohos.nfc.tag.action.TAG_FOUND"] 与 uris: [{ type: "tag-tech/<源 tech-list 中的技术>" }]（技术名取源端类名去掉 android.nfc.tech. 前缀，须落在 NfcA、NfcB、NfcF、NfcV、IsoDep、Ndef、MifareClassic、MifareUL、NdefFormatable 中并区分大小写，MifareUltralight 写作 MifareUL；requestPermissions 同时声明 ohos.permission.NFC_TAG）；EntryAbility 在 onCreate/onNewWant 从 want 取 TagInfo，交给对应页面处理。
2. 源端启停开关只映射到系统派发这条路径：在入口识别贴卡拉起的 want 后按开关决定继续还是退出（来源采用冷启 terminateSelf、热启退回后台），前台派发不受影响；接口名写明作用范围（如 setAutostartEnabled），不复用前台派发的开关。

来源支持：1 张卡 · 1 次迁移 · 1 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1 步〕后台读取标签（系统贴卡拉起应用）要在 module.json5 的 skills 里静态声明：actions 必须包含 ohos.nfc.tag.action.TAG_FOUND；uris 的 type 前缀必须是 tag-tech/，后接 NfcA、NfcB、NfcF、NfcV、IsoDep、Ndef、MifareClassic、MifareUL、NdefFormatable 之一，多个 type 分行填写，填错会造成解析失败
- 〔做法第 1 步〕后台读写时 tag-tech/ 后面的技术类型描述字符必须完整匹配并区分大小写
- 〔做法第 1 步〕后台读取标签时 module.json5 requestPermissions 里的权限名必须是 ohos.permission.NFC_TAG
- 〔做法第 1 步〕UIAbility.onCreate 只在 UIAbility 冷启动时触发；已经启动的 UIAbility 实例再次被拉起时触发的是 onNewWant
- 〔适用情境 / 做法第 1 步〕安卓 ACTION_TECH_DISCOVERED 过滤的技术写在 manifest meta-data 指向的 XML 里，含一个或多个 tech-list，tech 写技术类全名（如 android.nfc.tech.NfcA）；安卓的 MifareUltralight 在鸿蒙 tag-tech 里写作 MifareUL
- 〔原因 / 做法第 2 步〕安卓 PackageManager.setComponentEnabledSetting 设置包内组件（activity、receiver、service、provider）的启用状态，会覆盖组件在 manifest 里声明的启用状态
