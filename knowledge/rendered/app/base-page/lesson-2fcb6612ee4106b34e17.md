# Android 业务基类的横切行为逐方法映射到组合式 BasePage：副作用受守卫（findViewById 判空、instanceof、标志位）时，先按每个子类布局（含横竖屏变体）核对守卫是否成立，成立的页才逐页落地生命周期调用

## 何时使用

公共基座实现与页面转换阶段，把 BaseActivity/BaseBusinessActivity 等业务基类的 onCreate、onDestroy、onBackPressed、dispatchTouchEvent 行为迁到 ArkUI 页面时

## 适用情境

Android 页面统一继承业务基类，由基类自动完成页面展示/退出埋点（停留时长、返回键归因）、触摸计数、点外收键盘、进入淡入等；ArkUI @ComponentV2 struct 不能继承，目标改用需逐页调用的组合式 BasePage 或工具类，页面还可能先于公共基座生成。也包括基类在 onResume/onPause 开关前台能力（如 NFC 前台派发）、onNewIntent 统一处理并在不支持时跳转；服务切片不能改页面，规格指向的基类等价物（Mixin）并不存在。也包括基类副作用写在 findViewById(R.id.x) != null 等守卫之内，并非每个子类布局都含该 id。子类自己重写 onBackPressed、dispatchTouchEvent、onNewIntent 等方法而不调 super 时，基类写在这些方法里的副作用对该页同样不成立，按守卫不成立处理；onCreate、onPostCreate、onResume、onPause、onDestroy 由框架强制调 super（不调会抛 SuperNotCalledException），基类在这几个方法里的副作用对每个子类都执行。

## 原因

目标端没有继承：只迁子类文件里显式出现的调用，基类自动完成的副作用就在每个页面丢失；基座照规格“鸿蒙映射”一行实现时，同一方法里映射行没提到的副作用（如点外收键盘）会被静默删掉；组合式基座建好却没给既有页面登记接线，切片只兑现登记过的占位，缺口保留到交付。反过来，逐方法列表丢掉守卫条件时，只对部分子类生效的副作用会被当成所有子类的义务：来源中只对含 main_content 的页面生效的淡入落到了游戏页，多出源端没有的整页淡入。

## 做法

1. 基座阶段按源基类逐方法列出全部副作用连同其守卫条件（如 onCreate 记 createTime 并发展示事件、onDestroy 按返回归因发退出事件与整秒时长、dispatchTouchEvent 的触摸计数与点外收键盘、onPostCreate 只在 findViewById(main_content) 不为空时淡入），在目标基座逐项对应；不承接的写明折叠理由并在报告中列为裁剪项。
2. 页面转换时，源页面类继承业务基类的，打开基类把生命周期副作用落到 aboutToAppear/aboutToDisappear 与返回回调（@Entry 页面用 onBackPress，NavDestination 页面用 .onBackPressed 属性；两种返回都置返回归因）；目标等价物未建就登记前向占位。
3. 用组合替代继承时，在源码 grep 继承该基类的页面，与目标页对基座或埋点调用的 grep 结果做差集，给未调用的页面逐页登记接线（负责方指向所属切片），并在 as-built 契约中写成“每页必须调用”的义务，不只列为可用 API。
4. 服务切片不能改页面、基类等价物又不存在时，在服务里交付页面可直接调用的入口（如 pageShown/pageHidden 与默认事件处理），按继承该基类的页面清单逐页登记可追踪的移交；只在笔记里写“归消费切片”不算完成，交账前核对验收声明的目标锚点确实存在。
5. 逐页登记义务前，在每个子类布局（含 layout-land 等变体）中 grep 守卫引用的 id 或核对条件；不成立的页写明“不适用”，不登记义务、不实现该副作用。

来源支持：4 张卡 · 3 次迁移 · 3 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因 / 做法第 2、3 步〕ArkUI 自定义组件基于 struct 实现，不能有继承关系；源端基类里自动完成的生命周期副作用不会带到目标页面，只有页面自己调用的才生效
- 〔做法第 2 步〕自定义组件的 aboutToAppear 在组件实例创建之后、build() 执行之前调用；aboutToDisappear 在组件即将销毁时调用
- 〔做法第 2 步〕自定义组件的 onBackPress 只对 @Entry 装饰的页面组件生效；返回 true 表示页面自己处理返回，返回 false（不写返回值时同此）走默认返回逻辑
- 〔做法第 2 步〕NavDestination 的 onBackPressed 回调在与之绑定的 Navigation 导航栈里有内容、用户按返回键时触发；回调返回 true 表示重写返回逻辑，返回 false 回退到上一页
- 〔适用情境〕tag.registerForegroundDispatch 按 ElementName（必须含 bundleName 和 abilityName）注册，开关粒度是 UIAbility 而不是页面；应用必须在前台才能调用，须与 tag.unregisterForegroundDispatch（同一个 ElementName）成对使用，在退出前台或销毁前取消注册；读卡器模式 tag.on('readerMode') 同样按 ElementName 注册
- 〔适用情境〕UIAbility.onForeground 在应用从后台转到前台时触发，onBackground 在应用从前台转到后台时触发，粒度是整个 UIAbility
- 〔适用情境〕安卓 NfcAdapter.enableForegroundDispatch 只能在主线程、Activity 处于前台（resumed）时调用，Activity 必须在 onPause 返回前调用 disableForegroundDispatch，开关粒度是单个 Activity 的前后台
