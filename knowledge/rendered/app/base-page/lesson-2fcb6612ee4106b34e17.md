# Android 业务基类的横切行为逐方法映射到组合式 BasePage：副作用受守卫（findViewById 判空、instanceof、标志位）时，先按每个子类布局（含横竖屏变体）核对守卫是否成立，成立的页才逐页落地生命周期调用

## 何时使用

公共基座实现与页面转换阶段，把 BaseActivity/BaseBusinessActivity 等业务基类的 onCreate、onDestroy、onBackPressed、dispatchTouchEvent 行为迁到 ArkUI 页面时

## 适用情境

Android 页面统一继承业务基类，由基类自动完成页面展示/退出埋点（停留时长、返回键归因）、触摸计数、点外收键盘、进入淡入等；ArkUI @ComponentV2 struct 不能继承，目标改用需逐页调用的组合式 BasePage 或工具类，页面还可能先于公共基座生成。也包括基类在 onResume/onPause 开关前台能力（如 NFC 前台派发）、onNewIntent 统一处理并在不支持时跳转；服务切片不能改页面，规格指向的基类等价物（Mixin）并不存在。也包括基类副作用写在 findViewById(R.id.x) != null 等守卫之内，并非每个子类布局都含该 id。

## 原因

目标端没有继承：只迁子类文件里显式出现的调用，基类自动完成的副作用就在每个页面丢失；基座照规格“鸿蒙映射”一行实现时，同一方法里映射行没提到的副作用（如点外收键盘）会被静默删掉；组合式基座建好却没给既有页面登记接线，切片只兑现登记过的占位，缺口保留到交付。反过来，逐方法列表丢掉守卫条件时，只对部分子类生效的副作用会被当成所有子类的义务：来源中只对含 main_content 的页面生效的淡入落到了游戏页，多出源端没有的整页淡入。

## 做法

1. 基座阶段按源基类逐方法列出全部副作用连同其守卫条件（如 onCreate 记 createTime 并发展示事件、onDestroy 按返回归因发退出事件与整秒时长、dispatchTouchEvent 的触摸计数与点外收键盘、onPostCreate 只在 findViewById(main_content) 不为空时淡入），在目标基座逐项对应；不承接的写明折叠理由并在报告中列为裁剪项。
2. 页面转换时，源页面类继承业务基类的，打开基类把生命周期副作用落到 aboutToAppear/aboutToDisappear/onBackPressed（NavDestination 的系统返回也置返回归因）；目标等价物未建就登记前向占位。
3. 用组合替代继承时，在源码 grep 继承该基类的页面，与目标页对基座或埋点调用的 grep 结果做差集，给未调用的页面逐页登记接线（负责方指向所属切片），并在 as-built 契约中写成“每页必须调用”的义务，不只列为可用 API。
4. 服务切片不能改页面、基类等价物又不存在时，在服务里交付页面可直接调用的入口（如 pageShown/pageHidden 与默认事件处理），按继承该基类的页面清单逐页登记可追踪的移交；只在笔记里写“归消费切片”不算完成，交账前核对验收声明的目标锚点确实存在。
5. 逐页登记义务前，在每个子类布局（含 layout-land 等变体）中 grep 守卫引用的 id 或核对条件；不成立的页写明“不适用”，不登记义务、不实现该副作用。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；安卓 Android SDK 源码 android-36.1；Android SDK 平台资源 android-34、android-36。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 2 步〕ArkUI 的 onPageShow、onPageHide、onBackPress 只在 router 路由页面（@Entry 装饰的自定义组件）上触发；aboutToAppear 在任何自定义组件新实例创建后、build() 执行前调用，aboutToDisappear 在该组件析构销毁时调用；onBackPress 返回 true 表示页面自己处理返回、不做路由返回，返回 false 或不返回值走默认路由返回。〔成立范围：对象：自定义组件的生命周期回调。条件：页面以 router 方式加载、组件带 @Entry。不成立：写在非 @Entry 的组件里（包括作为 NavDestination 内容的自定义组件、页面里的子组件）时，onPageShow/onPageHide/onBackPress 不会对它触发，NavDestination 页面要改用它自己的 onShown/onHidden/onBackPressed；@Reusable 组件被回收进复用缓存时调 aboutToRecycle、从缓存取回时调 aboutToReuse，不按新建、析构走 aboutToAppear/aboutToDisappear（依据是文档说明）。〕
- 〔适用情境（onResume/onPause 开关前台能力）与做法第 2 步〕NavDestination 页面的显隐回调是 onShown/onHidden（被 push 盖住、pop 出栈、应用切后台时触发 onHidden；拉起全模态 bindContentCover 时默认也触发 onHidden、关闭时触发 onShown），系统返回触发 NavDestination 的 onBackPressed：返回 true 表示改写返回逻辑，返回 false 回退到上一页；mode 为 NavDestinationMode.DIALOG 的页面进出路由栈不触发下层页面的 onShown/onHidden，只触发 onActive/onInactive。〔成立范围：对象：Navigation 管理的 NavDestination 页面。条件：onBackPressed 在 Navigation 绑定的导航控制器里有内容时才生效；全模态联动由 Navigation 的 enableVisibilityLifecycleWithContentCover 控制（API 21 起提供，默认 true，设 false 后全模态不再触发 onShown/onHidden），NavBar 里嵌套的内层 Navigation 的 NavDestination 不与全模态联动；onActive/onInactive 从 API 17 起提供，自定义弹窗、半模态、全模态和 Overlay 的开关也会触发它们。不成立：只把 Android 的 onResume/onPause 映射到 onShown/onHidden 时，页面被 DIALOG 类型页面、自定义弹窗、半模态或 Overlay 盖住的情况收不到回调。〕
- 〔适用情境（dispatchTouchEvent 的触摸计数与点外收键盘）〕Android 的 Activity.dispatchTouchEvent 在事件分发到视图树之前收到本 Activity 窗口的全部触摸事件；ArkUI 挂在页面根组件上的 onTouch 是靠冒泡、在命中的子组件之后才收到事件。〔成立范围：对象：基类覆写的 dispatchTouchEvent 与 ArkUI 通用事件 onTouch。条件：ArkUI 触摸事件默认冒泡，祖先组件默认参与触摸测试。不成立：子组件在回调里调用 TouchEvent.stopPropagation()，或命中的组件 hitTestBehavior 为 HitTestMode.Block、BLOCK_HIERARCHY（阻塞祖先参与触摸测试）时，根组件的 onTouch 收不到这次触摸。〕
- 〔做法第 5 步〕Android 旋转屏幕会同时改变 orientation 和 screenSize 两项配置，默认销毁并重建 Activity、重新 setContentView，此时按新方向选用 layout-land 等变体，onCreate/onPostCreate 里的守卫按新布局重新判断；manifest 的 android:configChanges 同时声明 orientation 与 screenSize 时不重建，只回调 onConfigurationChanged，已有视图树保持旋转前加载的布局变体。〔成立范围：对象：Activity 的布局变体选择，以及基类生命周期里依赖布局的守卫。条件：targetSdk 低于 13（HONEYCOMB_MR2）时 screenSize 变化本身不导致重建；screenSize、smallestScreenSize、screenLayout 这类尺寸配置项只在跨过应用资源限定词的分档时才计入是否重建（依据是 SizeConfigurationBuckets 的注释）。不成立：这次变化里还含没声明的其他配置项时仍会重建、不回调 onConfigurationChanged；声明了 configChanges、但在 onConfigurationChanged 里自己重新 setContentView 的页面，会换成新方向的变体。〕
- 〔原因（返回键归因）〕manifest 的 activity 或 application 把 android:enableOnBackInvokedCallback 设为 true（application 上没写时，targetSdk 不低于 36 的应用默认就是 true）时，系统返回不再调用 Activity.onBackPressed()，改为调用焦点窗口的 OnBackInvokedCallback.onBackInvoked()（Activity 默认注册的回调把返回直接交给系统任务管理处理），基类覆写的 onBackPressed 里的返回归因不会执行。〔成立范围：对象：android.app.Activity 子类覆写的 onBackPressed。条件：Android 13（API 33）起支持该属性；activity 上显式写的值优先于 application；application 未写时的默认值由系统解析 manifest 时按 targetSdk 定（android-36.1 源码：targetSdk 高于 35 即默认 true）。不成立：值为 false（或 targetSdk 不高于 35 且没写）、或系统低于 Android 13 时，返回键仍走 KEYCODE_BACK 并调用 onBackPressed。〕
