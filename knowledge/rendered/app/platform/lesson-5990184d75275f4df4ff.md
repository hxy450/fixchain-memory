# AlarmManager 到点通知改用代理提醒时，按 reminderAgentManager 自身接口落实按钮路由、贪睡与发布失败回退

## 何时使用

规格提取与服务实现阶段，把 AlarmManager 定时加自绘通知（按钮各带 PendingIntent）映射到 reminderAgentManager 或 notificationManager，并决定按钮路由、贪睡间隔、失败回退与到点副作用时；源端按钮只关闭或按固定间隔贪睡时用代理提醒自带按钮即可，不在此列

## 适用情境

源端用精确闹钟到点后自绘通知，按钮各带 PendingIntent（贪睡按偏好分钟重挂、改期弹选择器），到点在接收器里执行副作用并链式重挂下一次（如按 RRULE），动作可能经无 UI 的透明 Activity 分派；目标拟交系统代理提醒托管：reminderAgentManager.ActionButton 只有 title/titleResource/type，按钮级 wantAgent 只在 notificationManager 的 NotificationActionButton 上，ReminderRequest 提供 snoozeTimes/timeInterval 与提醒级 wantAgent，publishReminder 有条数上限与失败码，到点不回调应用。

## 例外与边界

- 源端按钮只做关闭，或只按固定、偏好间隔贪睡而不带别的参数时，代理提醒自带的关闭型、贪睡型按钮（贪睡间隔由 timeInterval 给）已经对上，不必改走本地通知的按钮 wantAgent；点通知本体打开应用的跳转由提醒级 wantAgent 承载即可。只有源端按钮要各自路由或带参数（如弹选择器改期、带记录参数）时，才按本条换承载方式。

## 原因

两个模块的按钮模型不同：把 NotificationActionButton 的 wantAgent 嫁接到代理提醒按钮上，规格写的按钮路由在实现时不可达，按钮只能退成系统关闭/贪睡型，源端各按钮的路由与参数丢失。系统托管也不在到点时刻回调应用，接收器里的副作用、链式重挂，以及超限、发布失败的处理若不在应用侧补，到点可能没有任何通知，或只发出首个发生。

## 做法

1. 规格逐字段对照目标模块自己的 d.ts（ActionButton、ReminderRequest、publishReminder 的 @throws），同一行写出可用手段与限制：按钮类型、提醒级 wantAgent、snoozeTimes/timeInterval、按钮状态订阅接口、有效提醒条数上限（API 24 上观察为单应用 30 条）、发布失败码与到点无回调，再决定应用侧回退。
2. 源端按钮需要各自的路由或参数时，用 notificationManager 本地通知的 NotificationActionButton.wantAgent 承载，或订阅代理提醒的按钮状态回调（API 24 SDK 为 subscribeReminderState）后按源分支处理；贪睡按源偏好设 timeInterval（单位秒，即偏好分钟×60）。
3. publishReminder 失败或超过条数上限时回退为应用侧本地通知或轮转登记，并保留源端在应用侧执行的到点副作用与链式重挂；实现时核出规格与 d.ts 冲突，就把受影响的验收标为阻塞并回报，不以系统型按钮“最大近似”收口。
4. 源端动作经无 UI 的透明 Activity 分派（如贪睡时长选择器）时，入口 Ability 保留它的独立任务、透明窗口与前后台语义：跟踪应用是否在前台，取消或时刻已过时用透明模态窗口提示，退后台时释放，不只在 onCreate/onNewWant 加一行分发。

来源支持：1 张卡 · 迁移数未记录 · 应用数未记录

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 做法第 1 步〕ReminderRequest.wantAgent 是点击提醒通知本体后要跳转的目标 ability，属于整条提醒，不对应某个按钮
- 〔适用情境 / 做法第 1 步〕ReminderRequest.actionButton 对三方应用最多支持两个按钮（系统应用从 API 10 起最多三个）
- 〔做法第 1、3 步〕reminderAgentManager.publishReminder 在通知未开启时以 1700001、提醒个数超限时以 1700002 拒绝（Promise reject）
- 〔做法第 1、3 步〕代理提醒的条数上限：文档写 API 版本 25 及以下单个普通应用最多支持 30 个提醒（API 25 超出本机 SDK 的 API 23）
- 〔做法第 1、2 步〕ReminderRequest.timeInterval 是延时提醒（贪睡）间隔，单位秒，最少 30 秒；snoozeTimes 不写时为 0 次；这两项都不适用于倒计时提醒
- 〔做法第 2 步〕reminderAgentManager.subscribeReminderState 需要 ohos.permission.PUBLISH_AGENT_REMINDER 权限，缺权限时以 201 拒绝
- 〔做法第 2 步〕代理提醒按钮状态的投递：用户点通知按钮时应用进程在，就回调一次（isMessageResent 为 false）；应用未运行则收不到；应用之后注册新的回调函数时，会把该应用下用户点过的按钮状态全部再回调一遍（点击时进程在的那些标 isMessageResent 为 true），缓存最多保存 30 天，注册新回调或超过 30 天未注册时删除
- 〔做法第 3 步〕卡里真机上 publishReminder 一直以 1700002 拒绝时，到点没有任何提醒通知出现
- 〔做法第 4 步〕UIAbility.onForeground 在应用从后台转到前台时触发，onBackground 在应用从前台转到后台时触发
