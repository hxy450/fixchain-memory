# 源端用 getString(key, null) 区分缺键、空串又是合法值时，偏好封装提供 has 判断，不以空串作缺省哨兵

## 何时使用

数据层与设置实现阶段，迁移以 null 默认值区分“键不存在”的偏好读取（历史列表、可选路径等）时

## 适用情境

源端 SharedPreferences.getString(key, null) 只把缺键当作不存在，空串是合法值（例如表示根目录或默认位置）；目标偏好封装只提供 get(key, def)，没有存在性判断。

## 例外与边界

- 源端写入一侧用 putString(key, null) 清除条目时，那等同删除这个键；目标对应 delete/deleteSync，不改写成存空串——空串在这里是合法值，存进去会被当成有效条目读回。

## 原因

以空串作缺省值时缺键与合法空串无法区分；跳过空串会把合法条目当成缺失丢弃，改用别的哨兵值也可能与合法值冲突。

## 做法

1. 偏好封装补存在性判断（@ohos.data.preferences 的 has/hasSync），读取先判键是否存在再取值，保留空串条目。
2. 封装接口不在本任务写权限内时，把缺少存在性判断登记为契约缺口交负责方，不在注释里自行接受数据丢失。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境〕安卓 SharedPreferences.getString(key, defValue) 在键存在时返回存的值（包括空串），键不存在时返回调用方给的 defValue；传 null 作 defValue 时，只有缺键才得到 null
- 〔原因 / 做法第 1 步〕Preferences.getSync(key, defValue) 在找不到键、或读到的值为 null 或不是 ValueType 格式时都返回 defValue，单靠返回值区分不了缺键和存了与 defValue 相同的值
