# 设置页由 addPreferencesFromResource/PreferenceFragment 挂载时，缺持久值的偏好会写入 android:defaultValue：目标在设置页出现时按 XML 顺序为缺键补写默认值并落盘，不只在读取时回退默认

## 何时使用

规格提取与设置页实现阶段，迁移带 android:defaultValue 的 PreferenceScreen XML 时

## 适用情境

源设置页由 PreferenceFragment/PreferenceActivity 以 XML 挂载偏好，各项有 defaultValue；目标偏好服务只在读取时回退默认值；偏好文件内容会被备份等流程读取。

## 例外与边界

- 不补写的键：XML 里标 android:persistent="false"、没有 key，或应用给偏好另设了 PreferenceDataStore 的项，源端挂载时不写偏好文件，目标也不写。时机要前移的：源端在主界面启动时调 PreferenceManager.setDefaultValues 的，默认值在应用首次启动就写进偏好文件，目标对应在启动流程里补写，而不是等进入设置页。

## 原因

源端进入设置页后偏好文件就含这些键，读取时回退不会改变文件；备份内容、恢复校验与“键是否存在”的判断因此与源端不同。

## 做法

1. 规格写明“进入设置页后偏好文件含这些键”；实现时设置页出现时按 XML 顺序对缺失的键写入默认值并 flush，已有值不覆盖。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 原因〕安卓 Preference 挂载时（dispatchSetInitialValue），应用没有为它另设 PreferenceDataStore、偏好文件里还没有这个 key 且 XML 给了 android:defaultValue 时，调用 onSetInitialValue(false, 默认值) 用默认值初始化
- 〔原因〕安卓 TwoStatePreference.setChecked 第一次调用时不论值是否变化都会 persistBoolean，应用没有另设持久化方式（如 setPersistent(false)、PreferenceDataStore）时，开关类偏好的默认值因此在设置页挂载时写进偏好文件
- 〔做法第 1 步〕鸿蒙 Preferences.putSync 只写进缓存的 Preferences 实例，调用 flush 后才持久化到文件
