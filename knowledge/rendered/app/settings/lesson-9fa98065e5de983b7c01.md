# SharedPreferences 迁移保留同步时序：onCreate 用 getPreferencesSync 装载，读写走 Sync 接口、异步 flush

## 何时使用

基础层偏好迁移阶段，设计偏好存储封装的初始化与读写时序时；派工者为该任务写验收标准时

## 适用情境

源端用 SharedPreferences（或其封装库）在 Application.onCreate 构建，之后任意读都等待载入完成；目标改用 @ohos.data.preferences，派工或封装设想“异步载入 + 内存缓存 + 写队列”，载入完成前的读返回调用方默认值。

## 原因

SharedPreferences 的读在文件载入完成前阻塞，apply 先改内存再异步落盘，所以源端任何读都看到真实值、写后立即可读。异步载入的封装在就绪前把调用方默认值当结果返回；各写操作分别异步排队、就绪前 clear 只清缓存、重放队列时 await 间隙到来的新写被清掉，这些都是源端不存在的时序。把“异步容错/写队列”写进验收当作对齐语义，实现者即使读到同步初始化的源码也会照派工实现。

## 做法

1. 入口 onCreate 中用 preferences.getPreferencesSync 装载（需要全量快照时 getAllSync），早于任何读写；读用 getSync，写用 putSync/deleteSync/clearSync 直接改内存实例，再异步 flush 落盘。
2. 确需异步装载时，在设计里写明就绪前的读写行为并与源端一致（就绪前的读等待装载完成），不以调用方默认值代替真实值，也不维护会丢写的待写队列。
3. 写偏好层验收标准时按源端时序表述：同步装载、先于一切业务访问可用、写后立即可读；不把“异步初始化容错”写成对齐要求。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；安卓 Android SDK 源码 android-36.1。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1 步〕XML 存储模式下，putSync/deleteSync/clearSync（以及异步的 put/delete/clear）只改缓存中的 Preferences 实例，不调用 flush 或 flushSync 就不会写进持久化文件；应用没有在 Options.storageType 另设时取 XML 模式。〔成立范围：对象：@ohos.data.preferences 的 Preferences 写接口。条件：storageType 缺省或为 StorageType.XML（GSKV 从 API 18 起可选，创建后不能中途切换模式）。不成立的情形：以 StorageType.GSKV 创建的实例写入即实时落盘、无需 flush。〕
- 〔做法第 1 步〕Preferences 的持久化文件放在所传 context 的 preferencesDir 下：ApplicationContext 取 <路径前缀>/<加密等级>/base/preferences，AbilityStageContext、UIAbilityContext、ExtensionContext 取 <路径前缀>/<加密等级>/base/haps/<module-name>/preferences，同名实例用不同级别（或不同加密等级）的 Context 获取会落到不同文件、互相读不到；安卓 getSharedPreferences(name) 不论从 Application 还是 Activity 调用，都解析到应用数据目录下的 shared_prefs/<name>.xml。〔成立范围：对象：Stage 模型下 preferences.getPreferences / getPreferencesSync 的 context 参数。条件：Options 未指定 dataGroupId（指定时在该应用组对应的沙箱路径下创建，不按 Context 区分）；同一应用里装载用一种 Context（如 AbilityStage 或 UIAbility 的 this.context）、别处读写用另一种（如 getApplicationContext()）。不成立的情形：全工程统一用同一级别、同一加密等级的 Context 获取时，同名指向同一文件。〕
- 〔适用情境〕首次 getPreferences/getPreferencesSync 读取持久化文件后实例被缓存，之后对同一文件的获取直接返回这个缓存实例、不再读文件，所以任一持有者 putSync 后另一持有者立刻 getSync 就能读到新值；调用 removePreferencesFromCache 之后再获取才会重新读文件、生成新实例；deletePreferences 会把持久化文件一并删除，之后再获取得到的是新的空实例。〔成立范围：对象：同一进程内指向同一持久化文件（同级别 Context、同名）的 Preferences 获取。条件：期间没有调用 removePreferencesFromCache(Sync)/deletePreferences。不成立的情形：多个进程同时持有同一文件——文档写明首选项不支持多进程场景。〕
- 〔原因〕安卓 Editor.apply() 先提交到内存，在写盘之前就回调 OnSharedPreferenceChangeListener（回调在主线程执行）；鸿蒙 XML 模式下 on('change')/on('dataChange') 要等执行 flush 之后才回调，putSync 本身不触发。〔成立范围：对象：从 OnSharedPreferenceChangeListener 迁到 Preferences.on('change' / 'dataChange') 的监听。条件：XML 存储模式（缺省）。不成立的情形：GSKV 模式下订阅的键变更后无需 flush 即回调。〕
- 〔做法第 1 步〕getSync(key, defValue) 在值为 null 或值的类型与 defValue 不同时直接返回 defValue、不报错；安卓 getInt、getLong、getString 等遇到同名但类型不符的值会抛 ClassCastException。〔成立范围：对象：Preferences.get / getSync。条件：读取时给的 defValue 类型与已存值类型不同（如存的是字符串、读时给数字默认值）。不成立的情形：类型一致时返回存储值。〕
