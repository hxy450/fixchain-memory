# SharedPreferences 迁移保留同步时序：onCreate 用 getPreferencesSync 装载，读写走 Sync 接口、异步 flush

## 何时使用

基础层偏好迁移阶段，设计偏好存储封装的初始化与读写时序时；派工者为该任务写验收标准时

## 适用情境

源端用 SharedPreferences（或其封装库）在 Application.onCreate 构建，之后任意读都等待载入完成；目标改用 @ohos.data.preferences，派工或封装设想“异步载入 + 内存缓存 + 写队列”，载入完成前的读返回调用方默认值。

## 原因

SharedPreferences 的读在文件载入完成前阻塞，apply 先改内存再异步落盘，所以源端任何读都看到真实值、写后立即可读。异步载入的封装在就绪前把调用方默认值当结果返回；各写操作分别异步排队、就绪前 clear 只清缓存、重放队列时 await 间隙到来的新写被清掉，这些都是源端不存在的时序。把“异步容错/写队列”写进验收当作对齐语义，实现者即使读到同步初始化的源码也会照派工实现。

## 做法

1. 入口 onCreate 中用 preferences.getPreferencesSync 装载（需要全量快照时 getAllSync），早于任何读写；读用 getSync，写用 putSync/deleteSync/clearSync 直接改内存实例，再异步 flush 落盘。
2. 确需异步装载时，在设计里写明就绪前的读写行为并与源端一致（就绪前的读等待装载完成），不以调用方默认值代替真实值，也不维护会丢写的待写队列。
3. 写偏好层验收标准时按源端时序表述：同步装载、先于一切业务访问可用、写后立即可读；不把“异步初始化容错”写成对齐要求。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 源码 android-36.1。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因〕安卓 SharedPreferencesImpl 构造时调 startLoadFromDisk，在后台线程从文件载入；getString、getInt、getAll、contains 等读方法和 edit() 都先 awaitLoadedLocked()，文件没载入完就阻塞等待，所以不会读到载入前的调用方默认值；载入后 getString 在键不存在时才返回 defValue；载入时文件不存在、不可读或解析失败，载入结果是空表，读方法都返回 defValue；只有其他意外异常会让之后的读方法抛 IllegalStateException
- 〔原因 / 做法第 1 步〕安卓 Editor.apply() 先 commitToMemory() 改内存里的映射、再把落盘排进队列异步写，监听器在落盘前就收到通知，所以 apply 返回后立即可读到新值；commit() 同样先改内存、在当前线程等写盘完成；同一个 Editor 里调了 clear() 的，commitToMemory 先清空再套用这个 Editor 里的 put/remove，与调用先后无关
- 〔做法第 1 步〕preferences.getPreferencesSync(context: Context, options: Options): Preferences（首段 @since 10，import { preferences } from '@kit.ArkData'）：同步取 Preferences 实例，载入文件全部数据并驻留内存；同一文件首次取到后实例被缓存，再次调用直接取缓存、不再读文件；可用 removePreferencesFromCache 移出内存
- 〔做法第 1 步〕Preferences.getSync(key: string, defValue: ValueType): ValueType（首段 @since 10）从缓存的实例取值，值为 null 或类型与 defValue 不同时返回 defValue；getAllSync(): Object（首段 @since 10）同步取全部键值；hasSync(key: string): boolean（首段 @since 10）查键是否存在
- 〔做法第 1 步〕Preferences.putSync(key: string, value: ValueType): void、deleteSync(key: string): void、clearSync(): void（首段 @since 10）只改缓存的实例（键已存在时 putSync 覆盖），要持久化再调 flush；value 含非 UTF-8 字符串时要用 Uint8Array 存，否则持久化文件格式出错、文件损坏
- 〔做法第 1 步〕Preferences.flush(): Promise<void> 与 flush(callback: AsyncCallback<void>): void（首段 @since 9）把缓存实例里的数据异步写到持久化文件；同步版 flushSync(): void 自 @since 14；数据没改或改后与缓存一致时不刷文件；flush 只在 XML 存储模式下需要，GSKV 存储模式下操作实时落盘、无需调用
- 〔适用情境〕@ohos.data.preferences 文档写明首选项不保证进程并发安全，有文件损坏和数据丢失的风险，不支持在多进程场景下使用
