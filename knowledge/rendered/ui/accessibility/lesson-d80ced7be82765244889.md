# 图标无障碍文本按源 contentDescription 转写：null 或空串不臆造；源端有文本时用 $r 资源并沿用各语言值，不写死单一语言字面量

## 何时使用

界面实现阶段，为图标、图标按钮、FAB 等设置 ArkUI accessibilityText、转写源端 contentDescription 时

## 适用情境

源端 Icon/Image/IconButton 的 contentDescription 为 null、空串或 stringResource(R.string.x)；目标工程带多语言字符串资源；同工程里既有用 $r 的页面，也有写死某一语言无障碍文本的页面可参照。

## 原因

contentDescription 为 null 或空串时，源端不为该图标提供朗读文本；按图标含义自拟“返回”“编辑”之类文本是在补写源端没有的语义，写成某一语言的字面量后，多语言资源无法覆盖，任何系统语言下都读这一种语言。

## 做法

1. 源端为 null 或空串时不设 accessibilityText，也不按图标含义自拟。
2. 源端给出字符串资源时写 .accessibilityText($r('app.string.<对应键>'))，键与各语言值随源 values-* 迁移；项目决策要求新增源端没有的无障碍文本时，按已批准的文案来源建资源键并在报告注明差异，不写字面量。

## 可选检查

- 对写死文本存疑时，检索 accessibilityText 的字面量实参（不以 $r 开头）定位候选。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；安卓 androidx.compose.material3:material3-android 1.4.0、1.5.0-alpha08；androidx.compose.material:material-android 1.6.2、1.12.0；androidx.compose.foundation:foundation-android 1.10.3、1.12.0。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境〕Compose 的 Icon（material、material3）和 Image（foundation）在 contentDescription 为 null 时不加任何 semantics，对无障碍服务是装饰性的；不为 null（包括空串 ""）时会加上带该 contentDescription 和 Role.Image 的 semantics。〔成立范围：对象：androidx.compose 的 Icon / Image 组合函数。版本：material 1.6.2、1.12.0，material3 1.4.0、1.5.0-alpha08，foundation 1.10.3、1.12.0 的字节码一致。空串节点由朗读服务怎样播报不在这些库里，未核。最常见的不成立情形：源端是 View 体系的 ImageView / ImageButton，不走这套逻辑。〕
- 〔做法第 1 步〕ArkUI 的 accessibilityText 默认为空串；组件既没有文本属性也没设 accessibilityText 时，屏幕朗读选中它时不播报内容；组件同时有文本属性和 accessibilityText 时，选中后只播报 accessibilityText。〔成立范围：对象：ArkUI 通用属性 accessibilityText。依据是文档说明。最常见的不成立情形：组件在 accessibilityGroup(true) 的父容器里，不再单独被识别（见下两条）。〕
- 〔做法第 2 步〕父容器设 accessibilityGroup(true) 且自身没有文本属性和 accessibilityText 时，合并朗读只拼接子组件的通用文本属性、不拼接子组件的 accessibilityText，只有 accessibilityText 的子组件（如图标）被忽略；要优先拼接子组件的 accessibilityText，须给 accessibilityGroup 传 accessibilityPreferred 为 true 的选项。〔成立范围：对象：设了 accessibilityGroup 的容器及其子组件（带选项的重载从 API 14 起）。例外：子组件 accessibilityLevel 设为 "yes" 时不受分组约束、可单独聚焦。依据是文档说明。最常见的不成立情形：父容器自己设了 accessibilityText，直接播报它、不拼接子组件。〕
- 〔做法第 1 步〕accessibilityLevel 默认 "auto"，此时组件能否被无障碍服务识别由服务和 ArkUI 综合判断；"no" 表示组件不可被识别，"no-hide-descendants" 表示组件及其子组件都不可被识别。〔成立范围：对象：ArkUI 通用属性 accessibilityLevel。条件："auto" 下父组件 accessibilityGroup 为 true 或父组件为 "no-hide-descendants" 时，组件不可被识别。依据是文档说明，"auto" 的具体判断在服务内部、文档没列。最常见的不成立情形：组件设了 accessibilityLevel("yes")。〕
