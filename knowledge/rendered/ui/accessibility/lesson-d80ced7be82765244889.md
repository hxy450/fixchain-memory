# 图标无障碍文本按源 contentDescription 转写：null 或空串不臆造；源端有文本时用 $r 资源并沿用各语言值，不写死单一语言字面量

## 何时使用

界面实现阶段，为图标、图标按钮、FAB 等设置 ArkUI accessibilityText、转写源端 contentDescription 时

## 适用情境

源端 Icon/Image/IconButton 的 contentDescription 为 null、空串或 stringResource(R.string.x)；目标工程带多语言字符串资源；同工程里既有用 $r 的页面，也有写死某一语言无障碍文本的页面可参照。

## 原因

contentDescription 为 null 或空串时，源端不为该图标提供朗读文本；按图标含义自拟“返回”“编辑”之类文本是在补写源端没有的语义，写成某一语言的字面量后，多语言资源无法覆盖，任何系统语言下都读这一种语言。

## 做法

1. 源端为 null 或空串时不设 accessibilityText，也不按图标含义自拟。
2. 源端给出字符串资源时写 .accessibilityText($r('app.string.<对应键>'))，键与各语言值随源 values-* 迁移；项目决策要求新增源端没有的无障碍文本时，按已批准的文案来源建资源键并在报告注明差异，不写字面量。

## 可选检查

- 对写死文本存疑时，检索 accessibilityText 的字面量实参（不以 $r 开头）定位候选。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 androidx.compose.material3 Icon（androidx-main 源码）；androidx.compose.material3:material3-android 1.4.0（字节码）。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因〕Compose material3 的 Icon：contentDescription 不为 null 时给图标加语义 contentDescription 和 role = Role.Image；为 null 时只用不带语义的 Modifier，读屏拿不到这个图标的任何文本（material3 1.4.0 与 androidx-main 相同；ImageVector、ImageBitmap 两个重载都转到 painter 版）
- 〔原因 / 做法第 1 步〕ArkUI accessibilityText：组件不含文本属性又没设无障碍文本时，屏幕朗读选中它不播报；设了无障碍文本则播报该文本；组件同时有文本属性和无障碍文本时只播报无障碍文本；无障碍分组为 true 且两者都没有时，拼接子节点文本（深度优先）。该接口不支持在 attributeModifier 中调用
- 〔做法第 2 步〕CommonMethod.accessibilityText 有两个重载：accessibilityText(value: string): T（首段 @since 10，默认值 ""）和 accessibilityText(text: Resource): T（@since 12），后者可直接传 $r('app.string.<键>')
- 〔做法第 2 步〕$r 引用的 string 资源按设备当前状态匹配限定词目录：目录名里的语言、文字、国家或地区要与设备一致才参与匹配，没有匹配的限定词目录或其中找不到该资源时才取 base 目录；写成字符串字面量则不经过这一匹配，任何系统语言下都是同一文本
