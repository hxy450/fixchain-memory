# linearGradient 遮罩条模拟边缘淡出：angle 按 CSS 语义或用 direction，终点取同色 alpha 0，不用透明黑

## 何时使用

界面实现与共享组件实现阶段，用 ArkUI linearGradient 写滚动边缘渐隐遮罩条（模拟 fadingEdges、FadeClip），确定渐变方向、终点色以及遮罩层尺寸与命中时

## 适用情境

源端用 fadingEdges 一类修饰让横滑行或纵向滚动区的内容在边缘淡出、不着色；目标改用叠在内容上、从容器底色渐变到透明的 linearGradient 遮罩条，按左右或上下边分别放置，底色常是运行期解析出的 '#AARRGGBB' 主题色；生成期不能上机看效果。

## 例外与边界

- 渐隐的是 List、Grid、Scroll、WaterFlow 这类滚动容器本身、且目标已用其 fadingEdge 属性（API 14 起，默认渐隐长度 32vp）实现时，平台按透明度淡出内容、不依赖底色，不要换成本条的遮罩条；fadingEdge 生效时会覆盖该组件自己的 overlay 与 blendMode，该组件上也不宜再设 background
- 遮罩条要求边缘下方是单一的容器底色：底下是图片或渐变背景时，从底色到透明的遮罩条会盖出一道色带，不能当作淡出

## 原因

ArkUI linearGradient 的 angle 与 CSS 同义：0 指向上方（colors[0] 在底边）、90 左→右、180 上→下（缺省）、270 右→左；按数学坐标或 Android GradientDrawable 的习惯把 0 当成向右，横向与纵向会整体互换。'transparent' 与 Color.Transparent 是透明黑，渐变不按预乘插值，从底色到透明黑的中段会出现半透明灰带。方向与灰带的结论依据两端截图对照；本机 SDK 的 .d.ts 对 angle 只写缺省值 180，不足以单独判断方向。

## 做法

1. 轴向渐变优先用 direction: GradientDirection.Right/Left/Bottom/Top；写 angle 时按 0 向上、90 左→右、180 上→下、270 右→左，不凭记忆换算。
2. 终点色取起点同 RGB、alpha 0（'#AARRGGBB' → '#00RRGGBB'），不写 'transparent' 或 Color.Transparent；起点色是 Resource 或主题令牌时先解析成具体色值再派生透明版，主题切换时一起重算。
3. 遮罩层的尺寸、定位与命中按内容落实：包装组件尺寸等于内容尺寸，遮罩层按实测内容宽高定数值尺寸（不写 '100%'），层内用 Row/Column 加 Blank 或 position 把首尾两条分开（不靠子项 .align），每个实际有尺寸的绘制节点都设 HitTestMode.None；见 lesson-a58ebfe7a4c55b041b14 第 5 步与 lesson-4a4f8d845a204ffa244b 第 1 步。

## 可选检查

- 不能上机时，逐条列出每个遮罩条所在的边、angle/direction、colors[0] 落在哪条边、终点是否同色透明；同一文件里横向与纵向遮罩分别核对。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因 / 做法第 1 步〕linearGradient 的 angle 是度数，0 度时渐变方向从下往上，顺时针为正，没写时为 180；字符串格式非法时按 180 处理
- 〔做法第 1 步〕angle 不是 undefined 时 direction 不生效；direction 没写时为 GradientDirection.Bottom，设为 GradientDirection.None 时按默认方向
- 〔做法第 1 步〕GradientDirection.Left 是从右向左，Right 是从左向右，Top 是从下向上，Bottom 是从上向下
- 〔原因 / 做法第 2 步〕Color.Transparent 的值是 rgba(0,0,0,0)，即透明黑
- 〔原因 / 做法第 2 步〕设备截图上，linearGradient 从非黑底色渐变到透明黑时中段出现半透明灰带；终点取与起点同 RGB、alpha 为 0 的颜色时没有灰带（渐变不按预乘色插值，声明和文档没写）
- 〔做法第 3 步〕HitTestMode.None 表示自身不响应触摸测试，不阻塞子节点、兄弟节点和祖先节点的触摸测试；它只作用于设置它的节点
- 〔做法第 3 步〕遮罩层只在外层容器设 HitTestMode.None、内部有尺寸的渐变节点没设时，被盖住的边缘控件点不到
- 〔做法第 3 步〕用 .overlay() 承载遮罩层时，其中写的 '100%' 不按宿主尺寸解析（约 136vp 对 60vp 的行），而且会吞掉横向滑动
- 〔做法第 3 步〕组件尺寸用百分比设置时，按最近设置了固定大小的祖先节点的尺寸计算
- 〔做法第 3 步〕Blank 只在父组件为 Row、Column、Flex 时生效，主轴方向没设大小时自动填充容器空余部分；设了大小或容器自适应子节点大小时不拉伸
