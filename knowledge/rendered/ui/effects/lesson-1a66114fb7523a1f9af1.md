# 位图着色（ColorFilter.tint、setColorFilter）用 Image.colorFilter：fillColor 只对 SVG 图源生效

## 何时使用

界面实现阶段为源端着色的图片写 ArkUI Image 修饰链、选择着色 API 时；规格提取阶段为 ColorFilter.tint 一类着色写转换决策时

## 适用情境

源端 Compose Image 的 colorFilter = ColorFilter.tint(color)（默认 SrcIn），或 ImageView 的 tint、setColorFilter（XML android:tint 未写 tintMode 与 setColorFilter(int) 默认 SRC_ATOP，app:tint、setImageTintList 默认 SRC_IN），作用在 png/jpg/webp 位图上（常见白色加透明通道、靠着色才可见的示意图）；目标资源仍是同一位图；规格转换行可能把 fillColor 与 colorFilter 列成并列选项。

## 例外与边界

- 资源已转成 SVG 时，fillColor 可以承担着色（它替换 SVG 中所有可绘制元素的填充色；工程开了 supportSvg2(true) 时，fill 为 'none' 的元素不受 fillColor 影响）

## 原因

ArkUI Image.fillColor 只作用于 SVG 图源，对位图不改像素颜色，白色透明位图在浅色背景上几乎看不见（HarmonyOS 6.1.0(23) 工程实测）；位图着色要经 colorFilter。

## 做法

1. 位图用 Image.colorFilter：SrcIn 着色写 drawing.ColorFilter.createBlendModeColorFilter(色值, drawing.BlendMode.SRC_IN)，源端是 SRC_ATOP 时换成 drawing.BlendMode.SRC_ATOP（着色色不透明时两者结果相同）（@kit.ArkGraphics2D，色值为 common2D.Color，可由 '#AARRGGBB' 主题色拆出），不改写成 4x5 矩阵（矩阵着色要把着色色换算进第 5 列偏移量：Image 的 4x5 ColorFilter 按 0–255 的像素值计算、第 5 列乘 255 后相加，偏移量要写 0–1 的比例而不是 0–255 的色值；drawing.ColorFilter.createMatrixColorFilter 的文档没写偏移量刻度）；颜色在渲染期按当前主题取值，不着色的分支不挂滤镜。
2. 修饰符对当前资源类型是否生效拿不准时，先查 SDK component/image.d.ts 中该属性的注释再写；规格写着色决策时注明源资源格式，只给对该格式生效的 API，并在同一行写出前提（如“PNG 位图 → colorFilter SRC_IN；fillColor 仅 SVG”），下游汇总规格时不丢掉这一前提。

## 可选检查

- 对着色是否生效有疑问时，在浅色与深色背景下各截图一次，核对白色透明位图是否显出着色。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码；androidx.compose.ui:ui-graphics-android 1.10.3、1.12.0；androidx.appcompat:appcompat 1.1.0、1.7.1；androidx.core:core 1.16.0。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境〕Compose 的 ColorFilter.tint(color) 不传 blendMode 时混合模式为 BlendMode.SrcIn（ui-graphics 1.10.3、1.12.0 相同）
- 〔适用情境〕ImageView 在布局 XML 里写了 android:tint、没写 android:tintMode 时，混合模式取 SRC_ATOP（之后代码再调 setImageTintList 也沿用这个 SRC_ATOP）；布局没写 android:tint 和 android:tintMode、代码调 setImageTintList 时 ImageView 不另设混合模式，按 Drawable 自身的 tint 混合模式（Drawable 没另设时为 SRC_IN）；setColorFilter(int color) 等于 setColorFilter(color, PorterDuff.Mode.SRC_ATOP)
- 〔适用情境〕AppCompatImageView 的 app:tint 经 ImageViewCompat.setImageTintList 设进去（API 21 起直接调平台 ImageView.setImageTintList），没写 app:tintMode 时不另设混合模式，按 Drawable 的 SRC_IN；同一布局还写了平台的 android:tint 时，ImageView 构造里已把混合模式设成 SRC_ATOP，之后沿用（appcompat 1.1.0、1.7.1 的 AppCompatImageHelper 写法相同）
- 〔原因 / 例外与边界〕Image.fillColor 只对 SVG 图源生效，对 png 等位图不改颜色；文档写明 png 改色用 colorFilter；签名 fillColor(color: ResourceColor | ColorContent | ColorMetrics) 自 API 20，只收 ResourceColor 的写法自 API 11
- 〔原因〕HarmonyOS 6.1.0(23) 工程里，白色加透明通道的 PNG 位图挂 Image.fillColor(主题色) 时，设备上在浅色背景中只显示为极淡的白块，没有着色
- 〔例外与边界〕Image.fillColor 作用在 SVG 上时替换 SVG 中所有可绘制元素的填充颜色；API 21 起 supportSvg2 设为 true 时 fillColor 依 SVG 的 fill 属性，fill 为 'none' 时不生效（supportSvg2 不写时为 false）
- 〔例外与边界 / 做法第 1 步〕Image.colorFilter 对 SVG 图源：API 11 及之前不支持；API 12 起只有 SVG 设了 stroke 属性才生效；API 21 起 supportSvg2 为 true 时作用于整个 SVG 图源
- 〔做法第 1 步〕Image.colorFilter(value: ColorFilter | DrawingColorFilter)：参数可以是 4x5 矩阵的 ColorFilter，或 @ohos.graphics.drawing 的 ColorFilter（API 12 起）；设了 colorFilter 时 renderMode 不生效
- 〔做法第 1 步〕Image.colorFilter 直接收 ResourceColor（按 SRC_ATOP 混合）的重载从 API 26.0.0 起才有（超出本机 SDK 的 API 23，本机声明里没有）
- 〔做法第 1 步〕drawing.ColorFilter.createBlendModeColorFilter(color: common2D.Color, mode: BlendMode) 自 API 11 提供；API 18 起另有 color 为 common2D.Color | number 的重载，number 是 16 进制 ARGB 无符号整数（0–0xFFFFFFFF）；drawing、common2D 都从 @kit.ArkGraphics2D 导入
- 〔做法第 1 步〕common2D.Color 有 alpha、red、green、blue 四个字段，各是 0–255 的整数
- 〔做法第 1 步〕drawing.BlendMode.SRC_IN = 5，r = s * da；SRC_ATOP = 9，r = s * da + d * (1 - sa)（s 为滤镜色，d 为图像像素）；滤镜色 alpha 为 255 时两式结果相同
- 〔做法第 1 步〕Image 的 4x5 ColorFilter 按行优先排列，像素 [R, G, B, A] 取值 0–255，计算为 R' = r1·R + r2·G + r3·B + r4·A + 255·r5（G、B、A 同理），即第 5 列偏移量按 0–1 的比例乘 255；drawing.ColorFilter.createMatrixColorFilter 的文档只写参数是长度为 20 的 4×5 矩阵，没写偏移量刻度
