# 源端经 TaskStackBuilder.addNextIntentWithParentStack(...).startActivities() 跳转时，按 Manifest 父链清栈重建 [父…, 目标]：目标 NavPathStack 先 clear 再依次 push 父页与目标，返回落到父页而非来源页

## 何时使用

规格提取与基座实现阶段，把基类的父栈跳转方法（抽屉导航等）翻译成 NavPathStack 操作与返回验收时

## 适用情境

源基类被多个页面继承，抽屉等跳转经 TaskStackBuilder 发起，Manifest 为目标声明 parentActivityName 或 PARENT_ACTIVITY；目标是单个 Navigation + NavPathStack，跳转可从栈底以外的任意宿主页发起；页面规格里可能有“pushPathByName（主页为根天然在栈底）”一类只在来源页是主页时成立的映射。

## 例外与边界

- 父链的根（主页）在目标端是 Navigation 自己的首页内容（Navigation 的子组件），而不是栈里的 NavDestination 时，clear 清掉栈里所有页面后显示的就是它，不再 push 主页，只依次 push 根以下的父页和目标；否则栈里会多出第二个主页。

## 原因

startActivities 以新任务按父链重建栈，从任一页跳转后都是 [主页, 目标]；写成在当前栈上 push，从非根页跳转后返回会落回来源页，栈也越积越深。只在主页上验证时两者看不出差别。

## 做法

1. 规格按 Manifest 父链写出跳转后的完整栈与返回落点，实现映射写成 clear → 依次 pushPathByName 父页 → pushPathByName 目标（转场按源端设置），不写“带回栈、返回落回来源页”。
2. 把页面规格里的映射行复用到被多个宿主调用的基类方法前，核对该行成立的前提；验收用从非根页发起的样例（设置 → 抽屉 → 帮助 → 返回应到主页，再返回退后台）。

来源支持：1 张卡 · 1 次迁移 · 1 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因〕TaskStackBuilder.addNextIntentWithParentStack 先把目标 Activity 在 Manifest 里声明的父链加进合成栈，再加目标本身，跳转后的栈只由目标的父链决定
- 〔原因 / 做法第 2 步〕TaskStackBuilder 给栈底的 Intent 加上 FLAG_ACTIVITY_NEW_TASK、FLAG_ACTIVITY_CLEAR_TASK、FLAG_ACTIVITY_TASK_ON_HOME：旧任务里的 Activity 全部结束、按父链重建，在新任务栈底再按返回键回到桌面
- 〔做法第 1 步〕NavPathStack.clear 和 pushPathByName 的 animated 不传时都是 true，即播放转场动画
