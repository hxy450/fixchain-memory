# 源端对同一次成功有多条导航响应时，目标只保留一个导航出口，并按净效果定义返回栈

## 何时使用

规格提取与接线阶段，把源页面对同一业务结果的多条响应（事件订阅里 finish、成功回调里 startActivity）翻译成目标 NavPathStack 操作时

## 适用情境

源 Activity 对同一次成功既在全局事件订阅里关闭本页，又在回调里启动主页（可能带 FLAG_ACTIVITY_NEW_TASK）；全局管理器在回调前发布成功事件；目标由单一 NavPathStack 管理页面，Navigation 根内容可能是启动页。

## 例外与边界

- 只合并导航动作：全局成功事件的发布，以及其他订阅者对它的非导航处理（刷新登录态、更新数据等）照旧保留；去掉的只是本页订阅里对导航栈的出栈或入栈。
- 两条响应不是由同一次成功触发的（例如订阅的是另一个业务结果，或只在别的入口生效），各自保留，不合并。

## 原因

Android 中 finish() 只结束当前 Activity，与启动主页互不抵消；目标端两条响应操作同一个栈，效果会叠加：连续两次出栈把主页也弹掉，露出栈底的启动页。只修其中一条（如把 clear+push 改成 pop）时另一条仍在，症状不变。来源中规格把两条响应拆成两条独立验收，实现者照写。

## 做法

1. 先列出源页面对同一结果的全部响应（事件订阅、回调、结果回传），标明是否由同一次成功触发，再为目标定义唯一导航出口。
2. 写出合并后的“操作前栈 → 操作后栈”，例如 [主页, 登录页] → [主页]，并写主页不在栈中时的替换兜底；根内容是启动页时，不用 clear() 表达“回主页”。
3. 接线成功导航前，查本页与服务层是否还有全局成功事件的订阅会操作导航栈；有就只保留一个出口，并把与规格的冲突回写规格。

来源支持：1 张卡 · 1 次迁移 · 1 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因〕android.app.Activity#finish() 只结束调用它的这个 Activity；已经由 startActivity 启动的其他 Activity 不受影响，两条调用互不抵消
- 〔原因〕设备上同一次登录成功先后触发两次导航出栈时，路由栈从 2 层变成 0 层：主页一并被移除、没有新建节点，露出栈底的启动页
- 〔做法第 2 步〕NavPathStack.popToName(name) 回退到从栈底开始第一个名为 name 的页面并返回它的索引；栈中没有名为 name 的页面时返回 -1
- 〔做法第 2 步〕NavPathStack.replacePathByName(name, param) 先把当前栈顶页面退出，再把 name 指定的页面入栈
- 〔做法第 2 步〕NavPathStack.clear() 清除路由栈中所有页面，不保留任何一页
