# 被 @Entry 页直接组合、未进入 Navigation 栈的子组件要拦截返回键时，由 @Entry.onBackPress 转调子组件登记的处理函数，多个登记方后进先出；@Entry 承载 Navigation 且栈内有 NavDestination 时，挂载点改为栈顶 NavDestination.onBackPressed

## 何时使用

页面转换与接线阶段，为源端非根 Composable 里的 BackHandler/PredictiveBackHandler，或把 OnBackPressedDispatcher 的多级回调映射到 ArkUI 返回键钩子时

## 适用情境

源端在抽屉宿主等非 Activity 根的 Composable 中按状态条件拦截返回（例如抽屉打开时先关抽屉）；目标端该组件不是 @Entry，由唯一的 @Entry 页直接组合，没有作为页面驻留在 Navigation 路由栈内。也包括源端 OnBackPressedDispatcher 按后登记先问分发（Activity 只登记壳层回调，选择模式等另登记回调），目标壳页的返回处理是封闭分支、嵌入的子页没有登记入口。

## 例外与边界

- 组件本身就是 @Entry 页、且没有承载内有页面的 Navigation 时，直接实现 onBackPress
- 组件位于 NavDestination 内容中（含被页面组合的 BasePage 等共享基座）时，返回先交该 NavDestination.onBackPressed，返回 false 即出栈，@Entry.onBackPress 不会被调用；由该 NavDestination 的 onBackPressed 转调基座的裁决函数，不在 @Entry 上兑现

## 原因

SDK 的 onBackPress 注释写明只对 @Entry 装饰的自定义组件回调，子组件自己实现的 onBackPress 不会触发。来源工程的子组件把同一逻辑另挂到自身 NavDestination.onBackPressed，但该节点被 @Entry 页直接组合、不在 Navigation 栈内，设备实测（API 12 模拟器）也不回调，抽屉打开时按返回直接回到桌面。编译、结构审计与静态判定全部通过，只有设备上按返回键才暴露。

## 做法

1. 先确认子组件的挂载形态：被 @Entry 页直接组合且不在 Navigation 栈内，还是位于 NavDestination 内容中（含页面组合的共享基座）；后者按例外由 NavDestination.onBackPressed 转调。
2. 直接组合时，子组件在 aboutToAppear 经回调参数（@ComponentV2 用 @Event）把 () => boolean 的裁决函数交给 @Entry 页，aboutToDisappear 交回 null（@Entry 页用不加状态装饰器的普通成员保存该函数，交回 null 时不改状态变量）；@Entry 页的 onBackPress() 有函数就返回其结果，没有就返回 false 交系统默认处理。
3. 有多个登记方时，宿主提供后进先出回调栈（子页 aboutToAppear 登记、aboutToDisappear 注销），宿主返回处理在执行壳层分支前先分发；同一子页还嵌入其他宿主时，这些宿主也接同一分发。

## 可选检查

- 能上设备时：状态打开（如抽屉展开）按 Back，状态关闭且应用留在前台；关闭态按 Back 仍按源端行为退出。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 androidx.activity:activity 1.8.1（字节码）；androidx.activity:activity 1.8.1、1.13.0 源码包；androidx.activity:activity-compose 1.8.1、1.13.0 源码包；androidx.activity:activity、activity-compose 的官方参考文档（当前版本）。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因 / 例外与边界 / 做法第 2 步〕onBackPress 只对 @Entry 装饰的页面组件回调：返回 true 表示页面自己处理返回，返回 false 或不返回值时走默认返回逻辑；非 @Entry 的子组件里写的 onBackPress 不会被调用
- 〔原因 / 例外与边界 / 做法第 1 步〕NavDestination.onBackPressed(callback: () => boolean)（API 10 起）只在与 Navigation 绑定的导航控制器里有内容时生效，按返回键时回调；返回 true 表示重写返回逻辑，返回 false 表示回退到上一个页面
- 〔原因 / 例外与边界〕目标 SDK 为 API 12 的设备上：被 @Entry 页直接组合、不在 Navigation 路由栈内的子组件，自身写的 onBackPress 和挂在它根部 NavDestination 上的 onBackPressed 按返回键时都没有被调用，抽屉打开时按返回应用直接回到桌面
- 〔标题 / 例外与边界〕目标 SDK 为 API 23 的设备上：@Entry 页的 build 是 Navigation、栈内压着 NavDestination 时，按返回键先交栈顶 NavDestination 的 onBackPressed；它没有消费时 Navigation 出栈，栈深为 1 时露出空的宿主内容，@Entry 页的 onBackPress 收不到这次返回
- 〔做法第 2 步〕@Event 自 API 12 起提供，只能用在 @ComponentV2 组件里（用在 @Component 里编译时报错）；装饰的是回调方法，参数和返回值由开发者定（如 () => boolean），传入箭头函数；外部没有初始化且本地没有默认值时自动生成空函数
- 〔做法第 2、3 步〕aboutToAppear 在自定义组件新实例创建后、build() 执行前调用；aboutToDisappear 在组件析构销毁时调用，文档写明不允许在 aboutToDisappear 里改变状态变量（@Link 变量的修改可能导致应用行为不稳定）
- 〔适用情境 / 做法第 3 步〕androidx.activity 的 OnBackPressedDispatcher.onBackPressed 按登记的倒序找第一个 isEnabled 为 true 的 OnBackPressedCallback，只调它的 handleOnBackPressed，后登记的先拿到返回键（预测性返回手势进行中时交给开始手势的那个回调）；没有任何启用的回调时才执行构造时传入的 fallbackOnBackPressed；addCallback(lifecycleOwner, callback) 登记的回调只在 owner 至少 STARTED 时在列表里：1.8.1 在每次 ON_START 时重新加到最后、ON_STOP 时移除、ON_DESTROY 时注销（1.13.0 的源码注释写同样的倒序规则，内部改由 NavigationEventDispatcher 分发）
- 〔何时使用 / 做法第 1 步〕Compose 的 BackHandler(enabled, onBack) 向 LocalOnBackPressedDispatcherOwner（没另外提供时取宿主 Activity）的返回分发登记回调，只在 LifecycleOwner 至少 STARTED 时参与，enabled 为 false 的不参与、返回继续交给更早登记的启用者：activity-compose 1.8.1 在 DisposableEffect 里 addCallback(lifecycleOwner, …)，文档写嵌套时最内层启用的那个先拿到返回；1.13.0（优先用 LocalNavigationEventDispatcherOwner）文档写多个启用的 BackHandler 里最后组合的那个被调用，放在 if 里有条件地调用会改变组合顺序
