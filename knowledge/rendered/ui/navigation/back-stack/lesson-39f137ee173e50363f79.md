# 底部 tab 的 popUpTo(start){saveState}、外部入口的 CLEAR_TOP，以及进程存活时从桌面图标再次拉起触发的路由跳板再分流，要拆出返回栈后果写成验收，并在 onBackPress、onNewWant 显式实现

## 何时使用

规格提取阶段描述底部 tab 切换和外部深链入口，或把 LAUNCHER 路由跳板 Activity（启动页按条件分流）映射为入口分流时；入口装配与实现阶段核对导航壳差异、接线 EntryAbility 与入口页时

## 适用情境

源端 tab 切换用 navigate { popUpTo(startDestination){ saveState }; launchSingleTop; restoreState }，桌面卡片、通知等外部入口用带 FLAG_ACTIVITY_CLEAR_TOP/NEW_TASK 的 Intent 拉起主 Activity；目标端用单 Navigation 加下标或条件渲染切 tab，NavPathStack 承载详情页。也包括 LAUNCHER 路由跳板 Activity（未声明 launchMode 即 standard）按条件跳主页并带 CLEAR_TOP，任务根已被 TaskStackBuilder 等改写成主页：进程存活时从桌面图标再次进入，源端在任务顶新建跳板并重跑分流（首启进引导，否则清掉主页之上的页面回主页），从最近任务切回才保持原页；目标单例 UIAbility 再次拉起只回原页面栈。

## 原因

popUpTo(start) 同时决定 tab 状态保存和“非起始 tab 上按返回先回起始 tab”；CLEAR_TOP 决定热启动时清掉压在上面的页面。规格只写“状态保留”“落到某 tab”时，目标端下标切 tab 又没有 tab 返回栈，返回键直接退出、深链落在旧详情页下面。入口分流只接在冷启路径时，CLEAR_TOP 会被“冷启时根页天然唯一”消解，进程存活时从桌面图标重进停在原页。

## 做法

1. 规格把每个导航调用拆成“返回栈后果”和“状态保存”两类验收项；每个 Intent flag 写出可观察后果与对应的进入场景（CLEAR_TOP 只在目标页已在栈中才生效，对应热启动或桌面图标重进），或明确登记豁免；源码注释里描述的返回行为原样转成验收项。
2. 下标或条件渲染切 tab 时，在 @Entry 页 onBackPress 里显式处理：详情栈非空交给 Navigation 弹栈；在非起始 tab 上切回起始 tab 并返回 true；已在起始 tab 才交系统默认处理。
3. onNewWant 落 tab 前，按源端 flag 决定是否先清空 NavPathStack。
4. 入口分流按“冷启 / 进程回收后重入 / 进程存活时从桌面图标再次拉起 / 从最近任务切回”逐种写验收，结合跳板的 launchMode 与是否改写任务根判断源端重进时是否重跑跳板；需要重跑时在 EntryAbility.onNewWant 经事件通知入口页按同一条件再分流（首启压引导，否则回主页并清掉其上的页面）。

## 可选检查

- 有设备时，各非起始 tab 按一次系统返回应回到起始 tab；打开详情后从外部入口深链进来，返回不应再出现该详情页；游戏等内页中按 Home 再点桌面图标，两端都回主页，从最近任务切回则保持原页。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36 的平台资源；android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因 / 做法第 1 步〕FLAG_ACTIVITY_CLEAR_TOP：被启动的 Activity 已在当前任务中运行时，关掉它上面的所有 Activity；它自己的 launchMode 为 standard（manifest 没写时的取值）且同一 Intent 没带 FLAG_ACTIVITY_SINGLE_TOP 时会被结束并重建，其他启动模式或带了 SINGLE_TOP 时 Intent 交给它的 onNewIntent；和 FLAG_ACTIVITY_NEW_TASK 一起启动任务根 Activity 时，把已有任务带到前台并清回根状态
- 〔适用情境 / 做法第 4 步〕manifest 没写 launchMode 时为 standard，启动时通常新建一个实例
- 〔适用情境 / 做法第 4 步〕TaskStackBuilder.getIntents 给第一个 Intent 加上 FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_CLEAR_TASK | FLAG_ACTIVITY_TASK_ON_HOME，startActivities 后原任务被清掉，任务根变成第一个 Intent 的 Activity
- 〔做法第 2 步〕应用没有覆写 onBackPressed、也没注册返回回调时，Activity 的返回行为：Android 12（S）以前结束当前 Activity；S 起，任务根且在 manifest 里声明了 ACTION_MAIN + CATEGORY_LAUNCHER intent-filter 的 Activity 连同任务移到后台、不结束，其他 Activity 照样结束
- 〔原因 / 做法第 2 步〕安卓 Navigation 切 tab 带 popUpTo(startDestination) 时，非起始 tab 上按系统返回先回到起始 tab，在起始 tab 上按返回才退出
- 〔适用情境 / 做法第 4 步〕UIAbility 默认是 singleton 启动模式：实例已存在时再次启动只进 onNewWant，不进 onCreate 和 onWindowStageCreate，页面栈原样保留
- 〔做法第 3、4 步〕onNewWant 被触发说明这次是热启动，但热启动不一定触发 onNewWant；可用 UIAbilityContext.setOnNewWantSkipScenarios 在特定场景下抑制它
- 〔做法第 2 步〕onBackPress 只对 @Entry 装饰的路由页面生效：返回 true 表示页面自己处理返回、不做页面路由；返回 false 或不返回值时走默认的路由返回逻辑
- 〔做法第 3、4 步〕NavPathStack.clear 清除栈中所有页面，animated 不写时为 true（带转场动画）
