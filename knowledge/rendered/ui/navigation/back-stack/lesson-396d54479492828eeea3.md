# 源端对话框、底部弹层或下拉菜单改成页内覆盖层后，在宿主 onBackPressed 里自顶向下逐层关闭，全部关闭后才进未保存门禁或出栈

## 何时使用

页面转换阶段，把源端 Dialog/AlertDialog/ModalBottomSheet/ExposedDropdownMenu（以及可能存在的 BackHandler）改写成 NavDestination 页内覆盖层、确定系统返回如何处理时

## 适用情境

源页的对话框、底部弹层或下拉菜单以 onDismissRequest 关闭；源页可能另有 BackHandler 处理行内编辑器或未保存门禁，也可能完全没有 BackHandler。目标把这些弹层做成 NavDestination 内 Stack 条件渲染的覆盖层或由 activeDialog 一类状态驱动的组件，而不是自带返回关闭的弹窗机制，系统返回统一交给宿主。也包括源端 ContextMenu 窗口、ActionMode 多选态被改写成页面 @Local 浮层或选择态，页面是嵌入宿主的组件。也包括 View 体系 AlertDialog（默认可取消、带 setOnCancelListener）被写成自带蒙层的共享页内浮层组件，只接蒙层点击，页面的返回拦截不感知弹窗。

## 例外与边界

- 弹层改用自带返回关闭的弹窗机制（openCustomDialog、bindSheet、NavDestinationMode.DIALOG，以及 onWillDismiss 不设的 bindPopup 气泡等）时，由弹窗自身处理返回
- 源端的层不可按返回关闭（View 体系 setCancelable(false)、Compose 的 dismissOnBackPress = false）时，它可见期间按返回不关闭它、不走它的取消回调，这次返回也不传给下层页面：目标在它可见时 return true，但不调用关闭回调

## 原因

Compose 的对话框与下拉菜单是独立窗口，系统返回先触发它的 onDismissRequest（DialogProperties、PopupProperties 的 dismissOnBackPress 没有另设时为 true；源端设成 false 的层按返回不关闭，目标同样不关），BackHandler 只在没有弹层时才收到。搬进页面树后，只翻译显式的 BackHandler 或宿主根本不写返回处理，覆盖层打开时按返回会走到保存或丢弃门禁，甚至整页出栈、退出应用。来源中一个转换者读过源端 BackHandler 和各对话框的 onDismissRequest，onBackPressed 只处理了编辑器和门禁两支；另一应用的源页没有 BackHandler，转换者读到了 onDismissRequest 与给出自带返回关闭方案的映射参考，仍把关闭确认、关于、赞助弹窗和下拉选项写成 Stack 覆盖层，宿主没有返回处理。

## 做法

1. 列出本页所有可叠加的层（页内对话框、下拉或选项浮层、自绘底部弹窗、行内编辑器），onBackPressed 按从上到下判断：最上层可见就只调用它的关闭回调并 return true；没有可见层时 return false 交给默认返回；页面是被入口 Navigation 压栈的根页时，return false 会让它出栈、只剩空的 Navigation 外壳，这时按源端根页的返回语义处理并 return true。判断“可见”用的条件与该层实际渲染的条件一致（含渲染时附加的数据条件，如只在有内容时才渲染），不只看打开标志，否则标志为真而层未渲染时会吞掉一次返回。
2. 所有层都关闭后才进入未保存门禁或出栈。
3. 输出前对每个条件渲染的覆盖层（activeDialog 的每个取值、showXxx/pickerVisible 一类标志）和打开的编辑器各模拟一次返回，确认不会触发保存、丢弃或 pop；页内有这类覆盖层而宿主没有 onBackPressed 时先补上再交付。
4. 编排者把某个任务的页内覆盖层写法推广到后续派工时，同时写上“宿主 onBackPressed 按 onDismissRequest 关闭可见覆盖层”的配套要求。
5. 把 ContextMenu、ActionMode 等窗口型临时 UI 改写为页内状态时同步实现其返回语义：浮层打开时先关闭，多选态先退出，并消费本次返回；页面没有自己的返回钩子时，经宿主的回调分发登记。
6. 返回键与点遮罩路由到同一取消处理，按源端各对话框 OnCancelListener 的去向执行（如写首用标记、持久化勾选），不只关闭；共享浮层组件随组件交付返回键契约，消费它的页面逐个验证“弹窗打开时按返回只关弹窗、页面仍在、不叠弹”。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 androidx.compose.ui:ui-android 1.10.4、androidx.compose.material3:material3-android 1.4.0（字节码）；android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因〕androidx.compose.ui 1.10.4 的 Dialog 由独立的 Dialog 窗口（DialogWrapper）承载；应用没有另设 DialogProperties 时 dismissOnBackPress、dismissOnClickOutside 都是 true，按返回时由这个窗口自己的返回回调调用 onDismissRequest
- 〔原因〕material3 1.4.0 的 DropdownMenu 不传 properties 时用 PopupProperties(focusable = true)，dismissOnBackPress 没有另设时为 true；ui 1.10.4 的 Popup 窗口收到返回键或 ESC 且 dismissOnBackPress 为 true 时调用 onDismissRequest
- 〔原因〕material3 1.4.0 的 ModalBottomSheet 在应用没有另设 ModalBottomSheetProperties 时，shouldDismissOnBackPress、shouldDismissOnClickOutside 都是 true
- 〔适用情境 / 做法第 6 步〕android.app.Dialog 在应用没有另调 setCancelable(false) 时可取消；按返回键时 onBackPressed 在可取消时调用 cancel()，cancel() 先发出已注册 OnCancelListener 的回调再 dismiss()；不可取消时返回键不关闭对话框
- 〔适用情境 / 做法第 6 步〕android.app.AlertDialog.Builder 没有调 setCancelable(false) 时，create() 出的对话框可取消并设了 setCanceledOnTouchOutside(true)：点对话框外部同样走 cancel()，触发 OnCancelListener
- 〔做法第 1 步〕NavDestination.onBackPressed 的回调只在与 Navigation 绑定的导航控制器（路由栈）里有内容时生效；返回 true 表示重写返回键逻辑（本次返回被消费），返回 false 表示回退到上一个页面
- 〔原因 / 做法第 3 步〕NavDestination 没有 onBackPressed、页内 Stack 条件渲染的浮层打开着时按系统返回：浮层不关，整页从路由栈弹出；在引导页上则直接退出应用（HarmonyOS 6.0.2，API 22）
- 〔做法第 1 步〕被入口 Navigation 压栈的根页 NavDestination 不拦截返回时，按返回会把它出栈，屏幕上只剩空的（黑色）Navigation 外壳
- 〔做法第 5 步〕onBackPress 只在 router 路由页面（@Entry 装饰的自定义组件）生效；返回 true 表示页面自己处理返回、不做路由，返回 false 或不返回值按默认路由返回
- 〔例外与边界〕CustomDialogController 打开的弹窗按返回键或 ESC 会退出，返回、ESC、点遮罩退出时调用 cancel 回调；注册 onWillDismiss 后，点遮罩、侧滑、三键 back、ESC 都不会立刻关闭，由回调按 reason 决定
- 〔例外与边界〕UIContext 的 openCustomDialog 弹窗（BaseDialogOptions）在点遮罩、侧滑、三键 back、ESC 时关闭；注册 onWillDismiss 后不立刻关闭，回调参数的 reason 给出关闭操作类型
- 〔例外与边界〕bindSheet 半模态没有注册 shouldDismiss、onWillDismiss 时，侧拉关闭（侧滑、三键 back、ESC）以及下拉、点遮罩、点关闭按钮都直接关闭半模态；注册后不立刻关闭，由回调决定
- 〔例外与边界〕弹窗选项 levelMode 不写时为 LevelMode.OVERLAY（显示在所有页面之上）；EMBEDDED 是页面级弹窗，只在 showInSubWindow 为 false 时生效
- 〔例外与边界〕mode 为 NavDestinationMode.DIALOG 的 NavDestination 默认透明，进出路由栈不影响下层 NavDestination 的可见性：不触发下层的 onShown、onHidden，只触发 onActive、onInactive
