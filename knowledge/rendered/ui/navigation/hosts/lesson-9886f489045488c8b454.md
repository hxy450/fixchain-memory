# 源 Activity 或其基类 onCreate 调 overridePendingTransition(0,0) 时，“进入无转场”是目的地页的属性：进入该页的每条路由（按钮跳转、引导完成、启动分流、抽屉）都关闭转场；未调用时按主题默认窗口动画写目标转场，不留目标默认横滑

## 何时使用

规格提取阶段写页面规格与路由契约时；实现阶段写 pushPathByName/replacePathByName 时；规格提取阶段把 startActivity/finish 映射为路由契约、决定页面切换动画时

## 适用情境

源 Activity 或所继承的基类在 onCreate 调 overridePendingTransition(0,0)；目标用 Navigation 的 push/replace 进入该页，进入路径不止一条，规格可能只把转场禁用挂在抽屉基座等某一条路径上。只有调用写在目的地自己或基类的 onCreate 里才算目的地属性；调用方在某次 startActivity 或 finish 之后紧接着调的 overridePendingTransition 只管那一次切换，按那一条路由写 animated=false，不推广到进入该页的其他路由。 也包括源端多个 Activity 用 startActivity 线性跳转、按返回 finish，源码没有 overridePendingTransition，styles 也没覆盖 windowAnimationStyle；目标 router.pushUrl 的 @Entry 页或 Navigation 页未写转场，系统默认横向滑入滑出。

## 原因

把目的地属性当成某个基座的横切行为，其余路径按默认动画进入（来源中按钮进游戏页、教程完成进主菜单都出现滑入）。 没调用 overridePendingTransition 时，Activity 切换仍有动画，由主题 windowAnimationStyle 决定；主题没覆盖时沿 parent 链落到平台 Animation.Activity 的 activity_open_enter、open_exit、close_enter、close_exit（例：Theme.Holo 指向 Animation.Holo.Activity，本机 SDK android-30 values/themes_holo.xml），具体动画随系统版本变化。目标页不写转场时用系统默认横滑，与源端不同；把“没调用”记成“无转场”，各页就都留着目标默认值。

## 做法

1. 对每个目的地 Activity 查它及所继承基类的 onCreate（grep overridePendingTransition 与 extends），把“进入无转场”写进该页页面规格，并在所有进入该页的路由契约里写 animated=false（或让目的地统一关闭系统转场）。 同时查主题 windowAnimationStyle：没有 overridePendingTransition 时，按参照机 API 从 SDK platforms/android-<api>/data/res 沿主题 parent 链（含 values-v11/v14）读窗口动画的四段参数，写成每个目标页 Push/Pop × Enter/Exit 的转场（router 页用 pageTransition 的 PageTransitionEnter/Exit 按 RouteType 分支，见 ets/component/page_transition.d.ts）；导航图的转场字段写“平台默认（主题名）”，不写 none；查不到目标值时作为规格缺口回报，不保留目标默认横滑。
2. 实现时与工程已有路由保持一致：规格只给两参伪代码时，不据此省略第三参数。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-30、android-36 的平台资源；android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1、2 步〕NavPathStack.pushPathByName、replacePathByName 的第三参数 animated 不写时为 true（有转场动画），传 false 时没有转场动画
- 〔适用情境 / 做法第 1 步〕Activity.overridePendingTransition(enterAnim, exitAnim) 的两个参数传 0 表示进入、退出都不用动画
- 〔原因 / 做法第 1 步〕平台主题的窗口切换动画样式：Theme 的 windowAnimationStyle 是 Animation.Activity；Theme.Holo 是 Animation.Holo.Activity，Theme.Material 是 Animation.Material.Activity，这两个样式的 parent 都是 Animation.Activity（android-36 平台资源）
- 〔原因 / 做法第 1 步〕Animation.Activity 的四段切换动画：activityOpenEnterAnimation、activityOpenExitAnimation、activityCloseEnterAnimation、activityCloseExitAnimation 分别指向 anim/activity_open_enter、activity_open_exit、activity_close_enter、activity_close_exit
- 〔原因 / 做法第 1 步〕activity_open_enter 随平台版本变化：android-30 是 alpha 0→1（50ms）加 scale 0.85→1（400ms）；android-36 是 alpha 0→1（83ms，延迟 50ms）加 translate 96dp→0（450ms）
- 〔做法第 1 步〕PageTransitionEnter、PageTransitionExit 的选项不写时：type 为 RouteType.None，duration 为 1000（毫秒），curve 为 Curve.Linear，delay 为 0
- 〔做法第 1 步〕router 页转场按 RouteType 生效：Push（A 跳到 B）时 A 的 type 为 None 或 Push 的 PageTransitionExit、B 的 type 为 None 或 Push 的 PageTransitionEnter 生效；Pop（B 回到 A）时 B 的 None 或 Pop 的 Exit、A 的 None 或 Pop 的 Enter 生效，分别对应安卓的 open_exit、open_enter、close_exit、close_enter
- 〔做法第 1 步〕页面转场的 translate、scale、opacity 给的是入场时的起点值和退场时的终点值；opacity 取值范围 [0, 1]；slide 和 translate 同时设置时 slide 生效
