# 半透明卡片式 Activity 迁移为透明 DIALOG 路由，遮罩只作页内一层

## 何时使用

界面实现与规格提取阶段，迁移 windowIsTranslucent 主题的卡片式 Activity 及其内嵌子页时

## 适用情境

源主题 windowIsTranslucent=true、windowBackground 透明、backgroundDimEnabled=true，以卡片内的容器承载 Fragment；目标为 Navigation/NavDestination。

## 例外与边界

- 改成 DIALOG 路由后，下层页面原来在卡片关闭时要做的处理不能丢：源端半透明 Activity 盖在上面时下层只失去焦点、仍处于可见状态，回到前台只走 onResume；目标 DIALOG 页进出不触发下层的 onShown、onHidden，只触发 onActive、onInactive（API 17 起），这类刷新挂在 onActive，不挂 onShown。

## 原因

默认 STANDARD 模式的 NavDestination 有不透明背景，只铺遮罩也透不出下层页面；子页另建全屏页会离开卡片几何。

## 做法

1. 目标 NavDestination 用 mode(NavDestinationMode.DIALOG) 加 backgroundColor(Color.Transparent)，遮罩取源主题的 backgroundDimAmount（应用主题直接继承平台 Theme.Material 一族时为 0.6；继承 Material3 主题时为 0.32），换成黑色遮罩的透明度。
2. 规格写成“下层页面保持可见、仅压暗”，并写明路由需透明。
3. 卡片宿主内新增子页时，按源 replace(容器) 复刻卡片几何与透明路由，不另建不透明全屏页。

## 可选检查

- 写完核对遮罩下仍能看到下层页面和底栏

来源支持：1 张卡 · 1 次迁移 · 1 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-37.0 的平台资源；com.google.android.material:material 1.4.0、1.14.0。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因 / 做法第 1 步〕NavDestination 没有另设 mode 时为 NavDestinationMode.STANDARD；DIALOG 模式的页面默认透明，进出路由栈不影响下层 NavDestination 的可见性（不触发它的 onShown、onHidden），只触发 onActive、onInactive
- 〔做法第 1、3 步〕NavDestination 的 mode 不支持动态修改，页面类型要在创建时定下
- 〔做法第 1 步〕应用主题直接继承平台 Theme.Material（及其父主题 Theme）且没有另设 backgroundDimAmount 时，窗口压暗程度为 0.6
- 〔做法第 1 步〕应用主题继承 Material3 一族、没有另设 backgroundDimAmount 时，压暗程度取 m3_comp_scrim_container_opacity = 0.32（material 1.14.0 有此资源；1.4.0 里没有这一项）
