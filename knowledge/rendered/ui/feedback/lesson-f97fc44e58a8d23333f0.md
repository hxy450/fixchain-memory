# 源端以 toast 提示的校验失败，目标用全局提示；页内错误文字放在固定可见行，不追加到可变高度区末尾

## 何时使用

界面实现阶段，为弹层表单的确定按钮实现必填校验失败反馈、且源端校验失败用 toast 提示时

## 适用情境

Android 弹窗确认时依次校验必填项并以 toast 提示；目标用“遮罩 + layoutWeight 中间区 + 固定高度键盘”的弹层承载，校验失败只写一个页内错误文字状态。

## 例外与边界

- 改成全局提示时保留源端的校验顺序和逐项文案，校验失败后弹层保持打开、已填内容不清空；源端本来就用页内错误文字（如输入框自带的错误提示）而不是 toast 的，保持页内形式，只按做法第 2 步确认它处在可见位置

## 原因

中间区被分类网格等内容占满时，追加在末尾的错误行会落到键盘之下不可见，用户看到的是点击确定没有任何反应。来源中规格已要求错误文案可见，实现只写条件错误行、没有 toast，也未编译截图；用户两次报告“点击确认没反应”后才补上 showToast。

## 做法

1. 源端用 toast 一类全局瞬时提示时，目标同样用全局提示（promptAction 或 UIContext 的 showToast）；另加页内文字时放在操作栏下方或键盘上方的固定行。
2. 固定高度键盘与 layoutWeight 中间区组合时，按最多内容估算中间区高度；新增条件行前确认仍有空间，否则改为可滚动区或固定位置。

## 可选检查

- 规格写有“错误文案可见”的界面判定时，至少触发一次最常见的失败路径并截图确认提示出现。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1 步〕Toast 的显示时长 ShowToastOptions.duration 单位毫秒，应用没有另设 duration 时为 1500ms；取值范围 [1500, 10000]，小于 1500 按 1500、大于 10000 按 10000
- 〔原因 / 做法第 2 步〕layoutWeight 只在 Row、Column、Flex 中生效，应用没有另设时为 0；父容器尺寸确定时，没设或值为 0 的子组件先占位，设了大于 0 的子组件按权重分剩余空间，分配时忽略自身 width/height、保留 minWidth/minHeight
