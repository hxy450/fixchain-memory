# 按数据来源分区块管理页面状态：单个来源或次级动作失败只影响自己的区块，缓存、已加载内容与静态默认内容保留，整页错误只留给不可恢复的前置条件

## 何时使用

界面转换与数据接线阶段，为由多个数据来源（多个接口、首页缓存、本地登录态、XML 静态默认内容、可选附属请求）组成、源端各来源失败时不清空其他区块已有数据的页面设计加载、失败与降级状态时；把 ViewModel 的错误状态绑定到页面、决定整页错误或重试态由哪个状态驱动时

## 适用情境

源页面的多个请求各自 launch/observe、只在成功时更新自己的数据；或先用缓存填充再请求详情；或首屏含 XML 静态默认文案与本地状态；目标准备用一个结果对象或快照、CONTENT/ERROR 两态驱动整页。也包括列表页同时承载列表加载与定位、权限、选择等次级动作，ViewModel 把所有失败写进同一个错误信息字段、加载失败时清空已成功的列表，页面按“错误信息非空即整页错误”渲染；或刷新时用全屏遮罩盖住其他分区。

## 例外与边界

- 缺少城市、参数等所有区块都依赖的前置条件，此时整页错误态是合理的
- 页面用 Refresh 承载下拉刷新时，refreshing 为 true 期间 Refresh 已在自己的刷新区域显示刷新内容，这本身就是第 6 步要的局部指示，不需要再另加加载遮罩，也不要为此去掉 Refresh 改写刷新方式

## 原因

把多个来源聚合成一个成功/失败判定，任一请求失败就整页报错，或把已渲染区块替换成错误，源端“失败不动已有数据”和工程的缓存优先决策都会丢失。来源为同一应用四处：空气质量页用“实时或 48 小时任一为空”判整页错误；15 日页单日详情失败就整页 HTTP 错误，没有先用首页缓存填充；个人中心把账户、静态提醒和奖励任务都挂在奖励接口上，奖励失败连同账户一起变成错误；黄历页的历史请求失败把整个月历标为失败。单一错误字段聚合次级动作的失败后，权限拒绝、不支持城市等都会把已加载的目录替换成网络错误整页态；刷新失败清空列表或盖上全屏遮罩，最近成功的数据也就看不到了。

## 做法

1. 列出页面每个区块的数据来源与源端的更新条件（只在 Success 时更新、失败保留旧值）；目标按区块分别保存结果与错误，不用 a === null || b === null 决定整页错误。
2. 源端先用缓存或首页数据填充再请求详情时，网关先取缓存构造基础数据，详情失败时返回带缓存内容的结果并轻提示；无缓存时保留页面骨架，缺值以 -- 占位。
3. XML 里已有的静态文案与图标作为首帧默认值同步渲染；共享快照的加载钩子只合并本来源负责的字段，不新建快照整体替换。
4. 可选的附属数据（历史、节假日）单独 try/catch，失败或空结果都不覆盖主数据和已有列表。
5. 整页错误或重试态只绑定列表加载失败且没有可用数据（如列表状态为 Error 且目录为空）；次级动作（权限拒绝、不支持、编码解析失败）用 Toast、提示条或对话框呈现，保留已加载内容可继续操作。
6. ViewModel 的 catch 不清空已成功的列表，或页面只在成功结果到达时替换数据；刷新失败时已有内容优先，错误以提示条与重试入口显示；刷新加载用局部指示，不用遮住其他分区的全屏遮罩。

## 可选检查

- 逐个模拟 ViewModel 的每个错误值，确认只有首次加载失败且无数据时才显示整页错误
