# 公共 Toast 封装把时长做成每次调用的参数，逐调用点映射源端 LENGTH_SHORT/LONG，位置按源端默认显式传 bottom；源端对文案的字符串加工在取得字符串后保留

## 何时使用

服务层与页面实现阶段，把源端 Toast.makeText 调用翻译成目标 Toast 封装或 showToast，确定每处时长、显示位置与文案拼接时

## 适用情境

Android 源码在同一文件或同一公共方法中混用 Toast.LENGTH_SHORT 与 LENGTH_LONG，部分文案先取资源串再做 toLowerCase 等加工；目标用毫秒 duration 的 promptAction.showToast 或自建公共 Toast 桥，资源经 getStringSync 等取成 string 后再拼接。源端调用的是应用自己封装的 showToast 一类方法时，调用点没写时长按该方法内的默认值映射（如基类方法默认 LENGTH_LONG），不按 Toast 自身的默认 LENGTH_SHORT；把目标封装改成收时长参数时，封装原有的开关判断（如提示总开关偏好）与文案处理照旧保留。 也包括源端文字 Toast 未调用 setGravity/setMargin、位置取平台默认，目标封装或直接调用的 showToast 不传 bottom。这条只管源端 Toast.makeText；源端是 Snackbar（尤其带 actionLabel、withDismissAction 或依赖 SnackbarResult）时不按 Toast 档位映射，也不该降成 showToast。

## 原因

按多数调用把时长硬编码进封装，少数 SHORT 调用就全部变长；以“Resource 不能 toLowerCase”为由删掉加工，忽略了已经解析出的 string 可以照常加工。来源中引擎实现者与页面转换者都读到了逐处的 LENGTH_*，前者把封装写成只收 message、固定 3500ms，后者只定义了 LONG 常量；删除 toLowerCase 的理由在同一段代码里并不成立。 位置同样不同：Android 文字 Toast 默认底部居中、纵向偏移取平台 toast_y_offset（平台资源 values/dimens.xml，取应用运行所在系统版本的值：android-30 为 24dp，android-33 至 android-37 为 48dp；重力 config_toastDefaultGravity 为 0x51，即底部居中），showToast 不传 bottom 时用系统默认 80vp，吐司偏高。

## 做法

1. 公共 Toast 封装把时长作为每次调用的参数（SHORT 2000ms、LONG 3500ms），逐个调用点按源码 LENGTH_* 映射；写页面或服务前在源文件 grep 两种时长，输出只定义了一种时回到每个调用点补齐。
2. 位置与时长一样显式映射：源端未调 setGravity/setMargin 时，按平台默认重力与 toast_y_offset 换算成 showToast 的 bottom（相对导航区，有参照截图时以实测为准），写成封装常量；直接调用 showToast 的地方传同一常量或改走封装；源端调了 setGravity/setMargin 的按源值；但 targetSdkVersion ≥ 30 的应用运行在 Android 11 及以上时，这两个方法对文字 Toast 不生效，此时仍按平台默认位置映射。
3. 以平台限制为由删除源码的字符串加工前，先查实际采用的 API 返回类型；getStringSync 等取得 string 后保留源码加工。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-30、android-33 至 android-37.0 的平台资源；android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 做法第 1 步〕Toast.LENGTH_SHORT、LENGTH_LONG 是时长档位常量（值为 0、1），不是毫秒；应用没有另调 setDuration 时为 LENGTH_SHORT；源码注释说两档的实际时长可以由用户设置决定
- 〔做法第 1 步〕ShowToastOptions.duration 单位毫秒，不传时为 1500；取值范围 [1500, 10000]，小于 1500 按 1500，大于 10000 按 10000，所以把 0、1 这类档位值当 duration 传入得到的是 1500
- 〔原因 / 做法第 2 步〕安卓文字 Toast 在应用没有另设重力和偏移（setGravity）时，重力取框架资源 config_toastDefaultGravity（0x51，底部居中），纵向偏移取 toast_y_offset：android-30 为 24dp，android-33 至 android-37.0 为 48dp（android-31、32 的值没有核）；Toast 构造时从运行设备的框架资源读这两个值
- 〔做法第 2 步〕targetSdkVersion 不低于 30 的应用运行在 Android 11 及以上时，文字 Toast 由 SystemUI 绘制，setGravity 不生效、setMargin 的值不被使用（只打错误日志）；用 setView 自定义视图的 Toast 不在此列
- 〔做法第 2 步〕ShowToastOptions.bottom 是 Toast 底边到导航条的距离，不传时为 80vp；底部没有导航条时按到窗口底部算；软键盘拉起且 bottom 过小会被遮挡时自动避让到距软键盘 80vp；设置了 alignment 后 bottom 不生效
- 〔做法第 2 步〕对照测量（安卓 Pixel_5；HarmonyOS 6.1.0，API 23）：安卓文字 Toast 底边在导航栏上方约 50.5dp（平台资源值为 48dp）；鸿蒙 showToast 不传 bottom 时吐司底边距屏幕底边 110vp，传 bottom: 50 时为 80vp，即 bottom 从底部约 30vp 高的指示条区上沿算起
