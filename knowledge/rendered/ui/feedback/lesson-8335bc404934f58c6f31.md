# 公共 Toast 封装把时长做成每次调用的参数，逐调用点映射源端 LENGTH_SHORT/LONG，位置按源端默认显式传 bottom；源端对文案的字符串加工在取得字符串后保留

## 何时使用

服务层与页面实现阶段，把源端 Toast.makeText 调用翻译成目标 Toast 封装或 showToast，确定每处时长、显示位置与文案拼接时

## 适用情境

Android 源码在同一文件或同一公共方法中混用 Toast.LENGTH_SHORT 与 LENGTH_LONG，部分文案先取资源串再做 toLowerCase 等加工；目标用毫秒 duration 的 promptAction.showToast 或自建公共 Toast 桥，资源经 getStringSync 等取成 string 后再拼接。 也包括源端文字 Toast 未调用 setGravity/setMargin、位置取平台默认，目标封装或直接调用的 showToast 不传 bottom。

## 原因

按多数调用把时长硬编码进封装，少数 SHORT 调用就全部变长；以“Resource 不能 toLowerCase”为由删掉加工，忽略了已经解析出的 string 可以照常加工。来源中引擎实现者与页面转换者都读到了逐处的 LENGTH_*，前者把封装写成只收 message、固定 3500ms，后者只定义了 LONG 常量；删除 toLowerCase 的理由在同一段代码里并不成立。 位置同样不同：Android 文字 Toast 默认底部居中、纵向偏移取平台 toast_y_offset（框架资源 dimens.xml：Android 12 即 API 31 起竖屏 48dp、横屏 values-land 24dp，API 27–30 横竖屏都是 24dp，API 26 及以前为 64dip；重力 config_toastDefaultGravity 为 0x51 即底部居中；取的是应用运行时那一版系统的值），showToast 不传 bottom 时用系统默认 80vp，吐司偏高。

## 做法

1. 公共 Toast 封装把时长作为每次调用的参数（SHORT 2000ms、LONG 3500ms），逐个调用点按源码 LENGTH_* 映射；写页面或服务前在源文件 grep 两种时长，输出只定义了一种时回到每个调用点补齐。
2. 位置与时长一样显式映射：源端未调 setGravity/setMargin 时，按平台默认重力与 toast_y_offset 换算成 showToast 的 bottom（相对导航区，有参照截图时以实测为准），写成封装常量；直接调用 showToast 的地方传同一常量或改走封装；源端调了 setGravity/setMargin 的按源值；但 targetSdkVersion ≥ 30 的应用运行在 Android 11 及以上时，这两个方法对文字 Toast 不生效，此时仍按平台默认位置映射。
3. 以平台限制为由删除源码的字符串加工前，先查实际采用的 API 返回类型；getStringSync 等取得 string 后保留源码加工。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 平台资源 android-30、android-33、android-34、android-36、android-37.0（另取 AOSP frameworks/base android-11.0.0_r1、android-12.0.0_r1、android-12.1.0_r1 的 dimens.xml 定起始版本）；源码 android-36.1；AOSP frameworks/base android-14.0.0_r1（NotificationManagerService、PhoneWindowManager、SystemUIToast）；kotlin-stdlib 2.1.0（源码包）。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1 步〕android.widget.Toast.LENGTH_SHORT = 0、LENGTH_LONG = 1 是时长档位，不是毫秒数；系统 NotificationManagerService 显示 Toast 时把 LENGTH_LONG 换成 LONG_DELAY = 3500ms，其余换成 SHORT_DELAY = 2000ms，再经 AccessibilityManager.getRecommendedTimeoutMillis 与用户的无障碍提示时长设置比较、取较长的（用户没有另设时不变）。Android 12（API 31）起，系统绘制的文字 Toast（targetSdkVersion ≥ 30 的纯文字 Toast）再加 333ms 进场动画时间，前一条也是文字 Toast 时另加 250ms，即 SHORT 约 2333ms、LONG 约 3833ms；Android 11 没有这两项加时。LONG_DELAY 在 Android 11 直接取 PhoneWindowManager.TOAST_WINDOW_TIMEOUT（3500），Android 12 起取 TOAST_WINDOW_TIMEOUT 4100 减 TOAST_WINDOW_ANIM_BUFFER 600，值都是 3500ms
- 〔做法第 1 步〕promptAction.ShowToastOptions.duration?: number（单位 ms）：应用没有另传时为 1500；取值范围 [1500, 10000]，小于 1500 按 1500、大于 10000 按 10000
- 〔做法第 1、2 步〕this.getUIContext().getPromptAction() 得到的 PromptAction 上有 showToast(options: promptAction.ShowToastOptions): void（首段 @since 10）和 openToast(options: promptAction.ShowToastOptions): Promise<number>（@since 18，返回供 closeToast 用的 toastId），两者收同一个 ShowToastOptions；@ohos.promptAction 的全局函数 promptAction.showToast(options: ShowToastOptions): void 自 API 18 起废弃，替代为 UIContext 的 PromptAction#showToast；ShowToastOptions.message 的类型是 string | Resource
- 〔原因 / 做法第 2 步〕ShowToastOptions.bottom?: string | number 是 Toast 底部边框距离导航条的高度，应用没有另传时为 80vp；底部没有导航条时是距窗口底部的高度；软键盘拉起且 bottom 过小会被遮挡时，自动避让到距软键盘 80vp；设置了 alignment（@since 12）后 bottom 不生效；offset（@since 12）只收 px 数值
- 〔原因 / 做法第 2 步〕设备上 showToast 的 bottom 从底部导航指示条区的上沿量起：不传 bottom 时吐司底边距屏幕底边约 110vp（默认 80vp 加指示条区约 30vp），传 bottom: 50 时约 80vp
- 〔原因 / 做法第 2 步〕平台资源 toast_y_offset：Android 12（API 31）起 values/ 为 48dp、values-land 为 24dp，常见手机竖屏取 48dp，手机横屏取 24dp，平板竖屏 48dp、横屏 24dp；Android 8.1–11（API 27–30）只有 values/ 的 24dp，横竖屏相同；Android 8.0（API 26）及以前为 64dip，横竖屏相同（Android 5.0 起核过，更早未核）；手表（values-watch）为 0dip（android-30 起核过）。config_toastDefaultGravity 为 0x51（Gravity.BOTTOM | Gravity.CENTER_HORIZONTAL，底部居中），手表为 0x11（居中），Android 5.0、8.0、8.1 和 android-30、36、37.0 都是这个值
- 〔原因 / 做法第 2 步〕Toast 构造时用传入 Context 的资源读 toast_y_offset 和 config_toastDefaultGravity；targetSdkVersion ≥ 30 的应用运行在 Android 11 及以上时，纯文字 Toast（没有 setView）由 enqueueTextToast 交给 SystemUI 绘制，只带文字和时长，位置由 SystemUI 用框架资源读的 toast_y_offset、config_toastDefaultGravity 决定，取值随运行设备的系统版本（Android 12 起设备装了 SystemUI 的吐司插件时，插件给的重力和偏移优先）；这时 setGravity、setMargin 对文字 Toast 不生效，只打一条错误日志。带 setView 的自定义 Toast 和 targetSdkVersion < 30 的应用仍按 Toast 里的 gravity 和偏移显示
- 〔做法第 3 步〕ResourceManager.getStringSync 的四个重载都同步返回 string：getStringSync(resId: number)、getStringSync(resource: Resource)（首段 @since 9），带格式化参数的 getStringSync(resId: number, ...args: Array<string | number>)、getStringSync(resource: Resource, ...args: Array<string | number>)（首段 @since 10）
- 〔做法第 3 步〕Java 的 String.toLowerCase() 等同 toLowerCase(Locale.getDefault())，按默认语言区域的规则转换（土耳其语区域下 "TITLE" 得到带无点 ı 的 "tıtle"），toLowerCase(Locale.ROOT) 与区域无关；Kotlin 的 String.lowercase()（Kotlin 1.5 起）是 toLowerCase(Locale.ROOT)，已废弃的 Kotlin String.toLowerCase() 是 Java 的 toLowerCase()（跟默认区域），Kotlin 1.5 起编译警告、2.1 起编译报错。ArkTS 的 string 有 toLowerCase(): string 和 toLocaleLowerCase(locales?: string | string[]): string
