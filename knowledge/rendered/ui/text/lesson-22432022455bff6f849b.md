# resourceManager 代码内取值（字符串、数组、复数、颜色）一律传 $r(...).id 数字重载，不用 Resource 对象重载

## 何时使用

界面与服务实现阶段，把安卓命令式取资源（getString、getStringArray、getQuantityString、getColor，如自绘 View 里 drawText、measureText 的文案）改写为 ArkTS 代码内取值并选择 resourceManager 接口时；新写取值辅助函数，或把已有取值写法扩展到更多调用点、其他取值方法时

## 适用情境

源端在自绘 View 或代码里按当前资源配置取文案、字符串数组、复数串或颜色；目标需要在 ArkTS 中拿到纯值（Canvas 绘制、测宽、拼接、菜单与选择器文案），同一屏还有走声明式 $r 的组件文本；应用带多个 locale 资源目录，可能以应用偏好语言运行（i18n.System.setAppPreferredLanguage）；SDK 对 getStringSync、getStringArrayValue(Sync)、getIntPluralStringValueSync、getColorSync 等同时提供 (resId: number) 与 (resource: Resource) 两种重载。

## 原因

两个重载都存在不代表行为一致：在应用偏好语言下，getStringSync($r(...)) 曾观察到回落 base 英文，而 getStringSync($r(...).id) 返回偏好语言译文；以 Resource 对象取字符串数组同样让菜单混入默认语言文案。只在系统语言下核对，或只检索到 $r/getStringSync 引用就判 i18n 落地，发现不了这一差异；把数字 id 约定只套到 getStringSync，数组、复数等其余取值方法和新写的辅助函数仍会走 Resource 重载。

## 做法

1. 代码内取值统一传数字 id：getStringSync($r('app.string.x').id)、getStringArrayValueSync($r('app.strarray.x').id)、getIntPluralStringValueSync($r('app.plural.x').id, n, ...args)（n 只用来选单复数类别，串里的 %d 要在 args 里再传一次 n）、getColorSync($r('app.color.x').id)；辅助函数形参收 Resource 时在内部取 .id。新写辅助函数或把已有写法扩展到更多调用点、其他取值方法前，按这一规则核对，不只改 getStringSync。
2. 遇到没有验证资料的重载差异时，临时用 i18n.System.setAppPreferredLanguage 切到一个有资源的 locale，打印两种取值对比后再定。

## 可选检查

- “文案随语言切换”的验收在系统语言与应用偏好语言两种配置下，分别对比代码内取值的文本与组件文本是否为同一语言。
- 批量改写或交付前检索 resourceManager 取值调用中直接传 $r(...) 或 Resource 形参的写法，确认都已改为 .id 重载。

- 〔做法第 1 步〕getIntPluralStringValueSync(resId, num, ...args) 的 num 只用于按当前语言的复数规则选出对应 quantity 的串，串里的 %d 等占位符由 args 填充，要显示数量须在 args 里再传一次（文档示例 num 为 1、args 为 1, "basket", 0.3）；已废弃的 getPluralStringValueSync(resId, num) 则把 num 代入串中（示例 "%d apple" 输出 "1 apple"）。〔成立范围：对象：resourceManager 的 getIntPluralStringValueSync / getIntPluralStringValue（API 18 起）。条件：plural 资源的值含 %d、%s 等占位符。不成立的情形：串里没有占位符时只传 resId 与 num 即可。安卓对应：getQuantityString(id, quantity) 也只选串不格式化，带 formatArgs 的重载才代入。〕
- 〔做法第 1 步〕resourceManager 代码内取值的格式化参数（getStringSync(resId, ...args)、getIntPluralStringValueSync 等的 args）在文档里列出的占位符只有 %d、%f、%s、%%、%数字$d、%数字$f、%数字$s，不含精度、宽度、填充写法（%.2f、%02d）和 %x、%c 等其他转换符；文档写 9001007 的可能原因是参数类型不在支持范围、参数与占位符个数不等或类型不匹配。安卓 getString(id, args)、getQuantityString(id, n, args) 交给 String.format 按当前配置的语言格式化，支持 %.2f、%02d、%x 等完整 Formatter 语法。〔成立范围：对象：resourceManager 带 ...args 的取串接口。条件：从安卓 strings.xml 迁来的串含精度、宽度、填充或其他转换符（如 %.1f、%02d、%x、%c）。依据是文档说明：超出列表的写法是抛 9001007 还是原样输出，文档没写，迁移时不能依赖它们。不成立的情形：串里只用 %s、%d、%1$s 等支持的写法时不受此限。〕
- 〔适用情境〕getColorSync 返回 ARGB 排布的 number（文档示例 "#FFFFFF" 得到 4294967295，即 0xFFFFFFFF）；number 颜色传给 ResourceColor 时按数值大小判定格式，不大于 0xFFFFFF 的值（如 alpha 为 00 的全透明色）按 rgb 解析成不透明色，Canvas 的 fillStyle 用 number 时不支持全透明色；安卓 getColor 返回的 int 交给 Paint.setColor 时 alpha 照常生效。〔成立范围：对象：getColorSync / getColor 的返回值直接用作组件 ResourceColor 属性（fontColor、backgroundColor 等）或 Canvas fillStyle 的 number。条件：颜色资源的 alpha 为 00。不成立的情形：alpha 不为 00 的颜色数值大于 0xFFFFFF，按 argb 解析，与安卓一致。〕
- 〔做法第 2 步〕i18n.System.setAppPreferredLanguage(语言) 设置后应用优先加载该语言的资源、界面切换为目标语言，只影响本应用；设为 'default' 恢复跟随系统语言，要在应用重新启动（冷启动）后才生效。〔成立范围：对象：i18n.System.setAppPreferredLanguage（API 11 起）。条件：用它临时切语言核对后，再改回跟随系统。不成立的情形：设置具体语言（不是 'default'）时文档未要求重启；应用只能设置一种偏好语言。〕
