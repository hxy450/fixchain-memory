# resourceManager 代码内取值（字符串、数组、复数、颜色）一律传 $r(...).id 数字重载，不用 Resource 对象重载

## 何时使用

界面与服务实现阶段，把安卓命令式取资源（getString、getStringArray、getQuantityString、getColor，如自绘 View 里 drawText、measureText 的文案）改写为 ArkTS 代码内取值并选择 resourceManager 接口时；新写取值辅助函数，或把已有取值写法扩展到更多调用点、其他取值方法时

## 适用情境

源端在自绘 View 或代码里按当前资源配置取文案、字符串数组、复数串或颜色；目标需要在 ArkTS 中拿到纯值（Canvas 绘制、测宽、拼接、菜单与选择器文案），同一屏还有走声明式 $r 的组件文本（组件属性里直接写的 $r(...) 本身随应用偏好语言切换，不在这条的改写范围，保持原样，不改成代码内取值）；应用带多个 locale 资源目录，可能以应用偏好语言运行（i18n.System.setAppPreferredLanguage）；SDK 对 getStringSync、getStringArrayValue(Sync)、getIntPluralStringValueSync、getColorSync 等同时提供 (resId: number) 与 (resource: Resource) 两种重载。取值代码和资源同在 HAP 或 HSP 模块里时直接适用；代码在中间码 HAR 或字节码 HAR 里取 HAR 自身资源时，compatibleSdkVersion 低于 23、或取值发生在本模块 AbilityStage 的 onCreate 回调之前，按资源 ID 取会因 ID 无效抛异常，这时改用按资源名取的接口（如 getStringByNameSync），不套 .id；跨 HAP、HSP 取资源要先用 createModuleContext 拿到对应模块的 resourceManager，再按 ID 或资源名取。

## 原因

两个重载都存在不代表行为一致：在应用偏好语言下，getStringSync($r(...)) 曾观察到回落 base 英文，而 getStringSync($r(...).id) 返回偏好语言译文；以 Resource 对象取字符串数组同样让菜单混入默认语言文案。只在系统语言下核对，或只检索到 $r/getStringSync 引用就判 i18n 落地，发现不了这一差异；把数字 id 约定只套到 getStringSync，数组、复数等其余取值方法和新写的辅助函数仍会走 Resource 重载。

## 做法

1. 代码内取值统一传数字 id：getStringSync($r('app.string.x').id)、getStringArrayValueSync($r('app.strarray.x').id)、getIntPluralStringValueSync($r('app.plural.x').id, n, ...args)（n 只用来选单复数类别，串里的 %d 要在 args 里再传一次 n）、getColorSync($r('app.color.x').id)；辅助函数形参收 Resource 时在内部取 .id。新写辅助函数或把已有写法扩展到更多调用点、其他取值方法前，按这一规则核对，不只改 getStringSync。
2. 遇到没有验证资料的重载差异时，临时用 i18n.System.setAppPreferredLanguage 切到一个有资源的 locale，打印两种取值对比后再定。

## 可选检查

- “文案随语言切换”的验收在系统语言与应用偏好语言两种配置下，分别对比代码内取值的文本与组件文本是否为同一语言。
- 批量改写或交付前检索 resourceManager 取值调用中直接传 $r(...) 或 Resource 形参的写法，确认都已改为 .id 重载。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因 / 做法第 1 步〕目标 API 23 的应用把应用偏好语言设为 fa（locale fa_Arab_）时，同一个 resourceManager 上 getStringSync($r('app.string.x')) 返回 base 目录的英文，getStringSync($r('app.string.x').id) 返回 fa 译文
- 〔原因 / 做法第 1 步〕以 i18n.System.setAppPreferredLanguage 做应用内语言切换的应用（API 24 设备，超出本机 SDK 的 API 23）里，getStringArrayValue 等取值方法传 Resource 对象时，中文界面的抽屉和选择器文案混入英文
- 〔适用情境 / 做法第 1 步〕getStringSync、getStringArrayValue、getStringArrayValueSync、getIntPluralStringValueSync、getColorSync 的 Resource 参数重载都标 @deprecated since 20，文档建议用 resId 重载；文档另说明入参为 Resource 的接口比 resName、resId 接口耗时更长；两种重载在语言解析上的差别文档未写
- 〔做法第 1 步〕getIntPluralStringValueSync(resId, num, ...args) 的 num 只按当前语言的 CLDR 基数词规则选单复数串，串里的 %d、%s、%1$d 等占位符只由 args 依次替换（%1$d 取 args[0]）；中文环境不区分单复数；安卓 getQuantityString 的 quantity 同样只用于选串，格式参数另由 formatArgs 传
- 〔适用情境 / 做法第 2 步〕i18n.System.setAppPreferredLanguage 设置后，应用优先加载应用偏好语言对应的资源；传 'default' 时应用语言跟随系统语言，冷启动生效
- 〔做法第 1 步〕API 22 及之前，中间码 HAR、字节码 HAR 通过资源 ID 相关接口访问资源时因 ID 无效抛异常；API 23 起可以正常访问
