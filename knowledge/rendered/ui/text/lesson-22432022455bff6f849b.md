# resourceManager 代码内取值（字符串、数组、复数、颜色）一律传 $r(...).id 数字重载，不用 Resource 对象重载

## 何时使用

界面与服务实现阶段，把安卓命令式取资源（getString、getStringArray、getQuantityString、getColor，如自绘 View 里 drawText、measureText 的文案）改写为 ArkTS 代码内取值并选择 resourceManager 接口时；新写取值辅助函数，或把已有取值写法扩展到更多调用点、其他取值方法时

## 适用情境

源端在自绘 View 或代码里按当前资源配置取文案、字符串数组、复数串或颜色；目标需要在 ArkTS 中拿到纯值（Canvas 绘制、测宽、拼接、菜单与选择器文案），同一屏还有走声明式 $r 的组件文本；应用带多个 locale 资源目录，可能以应用偏好语言运行（i18n.System.setAppPreferredLanguage）；SDK 对 getStringSync、getStringArrayValue(Sync)、getIntPluralStringValueSync、getColorSync 等同时提供 (resId: number) 与 (resource: Resource) 两种重载。

## 原因

两个重载都存在不代表行为一致：在应用偏好语言下，getStringSync($r(...)) 曾观察到回落 base 英文，而 getStringSync($r(...).id) 返回偏好语言译文；以 Resource 对象取字符串数组同样让菜单混入默认语言文案。只在系统语言下核对，或只检索到 $r/getStringSync 引用就判 i18n 落地，发现不了这一差异；把数字 id 约定只套到 getStringSync，数组、复数等其余取值方法和新写的辅助函数仍会走 Resource 重载。

## 做法

1. 代码内取值统一传数字 id：getStringSync($r('app.string.x').id)、getStringArrayValueSync($r('app.strarray.x').id)、getIntPluralStringValueSync($r('app.plural.x').id, n, ...args)（n 只用来选单复数类别，串里的 %d 要在 args 里再传一次 n）、getColorSync($r('app.color.x').id)；辅助函数形参收 Resource 时在内部取 .id（资源属于别的 HAP/HSP 时，按 id 取值要用那个 module 的 resourceManager：先用 application.createModuleContext 取该 module 的 context；代码在中间码 HAR 或字节码 HAR 里时，按 id 取值 API 22 及以前会因 id 无效抛异常，API 23 起正常）。新写辅助函数或把已有写法扩展到更多调用点、其他取值方法前，按这一规则核对，不只改 getStringSync。
2. 遇到没有验证资料的重载差异时，临时用 i18n.System.setAppPreferredLanguage 切到一个有资源的 locale，打印两种取值对比后再定。

## 可选检查

- “文案随语言切换”的验收在系统语言与应用偏好语言两种配置下，分别对比代码内取值的文本与组件文本是否为同一语言。
- 批量改写或交付前检索 resourceManager 取值调用中直接传 $r(...) 或 Resource 形参的写法，确认都已改为 .id 重载。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 做法第 1 步〕ResourceManager 按 id 取字符串的两个重载：getStringSync(resId: number): string（首段 @since 9）和 getStringSync(resId: number, ...args: Array<string | number>): string（首段 @since 10，args 依次替换 %s、%d、%f、%数字$s 等占位符）；resourceManager 从 @kit.LocalizationKit 导入（import { resourceManager } from '@kit.LocalizationKit'）；资源 id 无效抛 9001001、找不到匹配资源抛 9001002、循环引用抛 9001006，带 args 的格式化失败抛 9001007
- 〔适用情境 / 原因〕Resource 对象重载在声明里都标了 @deprecated since 20、@useinstead 同名接口：getStringSync(resource: Resource)（首段 @since 9）与 getStringSync(resource: Resource, ...args)（首段 @since 10）、getStringArrayValueSync(resource: Resource)（首段 @since 10）、getStringArrayValue(resource: Resource) 的 callback 与 Promise 两种（首段 @since 9）、getIntPluralStringValueSync(resource: Resource, num, ...args)（@since 18）、getColorSync(resource: Resource)（首段 @since 10）；文档对应小节写「从 API version 20 开始废弃，建议使用」参数为 resId 的同名接口
- 〔做法第 1 步〕$r('app.string.x') 返回的 Resource 上有 id: number（声明注释 resource id in hap），另有 bundleName、moduleName；文档写明 resId 可通过 $r(资源地址).id 的方式获取，如 $r('app.string.test').id
- 〔做法第 1 步〕按 id 取字符串数组：getStringArrayValueSync(resId: number): Array<string>（首段 @since 10）；异步的 getStringArrayValue(resId: number): Promise<Array<string>> 与 getStringArrayValue(resId: number, callback: AsyncCallback<Array<string>>): void（首段 @since 9）
- 〔做法第 1 步〕getIntPluralStringValueSync(resId: number, num: number, ...args: Array<string | number>): string（@since 18）：num 是数量值（整数），只用来按当前语言的单复数规则选 quantity 类别；串里的占位符由 args 依次替换（支持 %d、%f、%s、%%、%数字$d 等，%1$d 取 args[0]），num 不会自动代入——文档示例 getIntPluralStringValueSync($r('app.plural.format_test').id, 1, 1, "basket", 0.3) 在 args 里把 1 又传了一次；中文环境下不区分单复数；只支持基数词，不支持序数词
- 〔做法第 1 步〕旧的复数接口 getPluralStringValueSync(resId: number, num: number): string 与其 Resource 重载（首段 @since 10）自 API 18 起废弃，@useinstead getIntPluralStringValueSync；旧接口没有 args 参数
- 〔做法第 1 步〕按 id 取颜色：getColorSync(resId: number): number（首段 @since 10），返回表示颜色的整数值
- 〔做法第 1 步〕取 resourceManager：Context 上有 resourceManager: resmgr.ResourceManager；组件里用 UIContext.getHostContext(): Context | undefined（@since 12）取 Context；全局 getContext(component?: Object): Context 自 API 18 起废弃，@useinstead UIContext.getHostContext
- 〔做法第 1 步〕文档在 ResourceManager 开头说明：入参为 Resource 的接口比入参为 resName、resId 的接口耗时更长，单 HAP 取自身资源和跨 HAP/HSP 取资源都更推荐 resName 或 resId 接口；跨 HAP/HSP 包取资源要先用 application.createModuleContext(context: Context, moduleName: string): Promise<Context>（@kit.AbilityKit，@since 12）创建对应 module 的 context，再调用 resName 或 resId 接口
- 〔做法第 1 步〕API version 22 及之前，中间码 HAR、字节码 HAR 通过资源 ID 相关接口访问资源时因 ID 无效会抛异常；从 API version 23 起可以正常访问
- 〔原因〕设了应用偏好语言 fa（resourceManager 的 locale 为 fa_Arab_）时，同一个 resourceManager 上 getStringSync($r('app.string.x')) 返回 base 目录的英文，getStringSync($r('app.string.x').id) 返回 fa 目录的译文（模拟器，target SDK 6.1.0(23)）；文档和声明都没有写两种重载在语言解析上有差异
- 〔原因〕用 setAppPreferredLanguage 设了中文偏好语言的应用里，经 getStringArrayValue($r('app.strarray.x')) 取的抽屉菜单文案和经 getStringSync(resource) 取的选择器按钮文案显示为默认语言（英文），同屏走 .id 重载的文案是中文（HarmonyOS 6.1.1，API 24，实机）
- 〔适用情境 / 做法第 2 步〕i18n.System.setAppPreferredLanguage(language: string): void（static，import { i18n } from '@kit.LocalizationKit'，首段 @since 11）：language 为合法语言 ID（如 'zh-Hans'、'fa'）或 'default'；文档写设置后应用优先加载偏好语言对应的资源，设为 'default' 后应用语言跟随系统语言、应用冷启动生效；声明注释写资源在应用启动时按偏好语言加载；参数校验失败抛 890001；当前偏好语言用 i18n.System.getAppPreferredLanguage(): string（首段 @since 9）读
