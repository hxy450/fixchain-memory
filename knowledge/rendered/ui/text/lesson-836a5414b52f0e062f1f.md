# maxLines + Ellipsis 两端截断粒度不同：单行补 wordBreak(BREAK_ALL)，多行写明差异、确需字符级一致才测量截断

## 何时使用

规格提取阶段为带 maxLines(N) + TextOverflow.Ellipsis（或 android:ellipsize、singleLine）的单行或多行文本写转换决策，以及界面实现阶段落实标题行与折叠态末行时（文本含英文等按空格分词的文字时；纯中文等 CJK 不必）

## 适用情境

源端多行正文以 maxLines + Ellipsis 折叠；目标用 .maxLines() + .textOverflow({ overflow: TextOverflow.Ellipsis })，默认 wordBreak 为 BREAK_WORD；映射参考只记 ellipsize → textOverflow 的 API 对应；项目可能要求完整复刻源端可观察行为。 也包括单行用户内容（标题、分类名、工具栏标题）：Android 的 TextUtils.ellipsize 按字符截断，ArkUI 默认先按词断行再省略；以及源控件是三方 TextView 子类（布局声明了库命名空间、未写 android:ellipsize），截断由库自身实现（例如取前 N 行、按空格回退、去尾标点再加省略号）。

## 例外与边界

- 项目允许平台差异、不要求逐字复刻末行时，直接使用内置行为，不引入运行期测量
- 粒度差异只出在英文等以空格分词的文字上：中文等 CJK 文本在默认设置下本就按字截断，BREAK_ALL 对 CJK 与 NORMAL 相同，纯 CJK 文案不必为此补 wordBreak 或测量

## 原因

源端末行按字符填满后接“…”，ArkUI 默认按词换行，末行放不下整词就整词丢弃，再接带前导空格的省略号并留白；只记 API 对应的映射让规格写成“等价”，差异留到视觉核验才暴露。单行文本只有一行，改为 wordBreak(BREAK_ALL) 就得到字符级截断；多行时该属性会让前几行也在词中断开，与源端按词换行、只在末行按字符截断不同，测量截断是已观察可行的做法，ellipsisMode 按文档只决定省略位置（默认行尾，START、CENTER 仅单行生效），不是多行末行按字符截断的现成配置。源控件是三方 TextView 子类时截断由库实现决定，按属性名直译成 maxLines + Ellipsis 会丢掉库的回退与去尾规则。

## 做法

1. 规格不写“等价”：写明两端末行形态的差异，完整复刻口径下登记为平台差异项，或直接给出实现方案；映射参考只给 API 对应时，把渲染语义缺口写进差异验收条目。
2. 单行（maxLines(1) 或 singleLine）用户内容要与源端字符级截断一致时，在 maxLines(1) + textOverflow(Ellipsis) 上补 .wordBreak(WordBreak.BREAK_ALL)；多行不用它代替末行截断。
3. 实现时先试内置属性能否满足当前要求；确需字符级一致时，在 onSizeChange 得到宽度后，以与 Text 相同的字体、字号、行高和换行设置调用 measureTextSize，二分求“前缀 + …”满足目标行数的最长前缀；只改折叠态，展开态与首帧继续使用原文与内置省略兜底。
4. 源控件是三方 TextView 子类且未写 android:ellipsize 时，先取库实现核对截断策略（取前几行、回退规则、去尾标点、省略号字符），再按该规则用与 Text 相同字体与宽度的测量或 @ohos.graphics.text Paragraph 自排版实现，不直译为 maxLines + Ellipsis。

## 可选检查

- 仅当内置属性能否满足要求不明时，在正在实现的这一段文本上核对末行截断位置与省略号前是否有空格。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 原因〕ArkUI Text 没有设置 wordBreak 时默认 WordBreak.BREAK_WORD；默认情况下文本截断按字进行，英文以单词为最小单位截断
- 〔做法第 2 步〕WordBreak.BREAK_ALL 让非 CJK 文本可在任意两个字符间断行（CJK 文本同 NORMAL）；与 Ellipsis、maxLines 一起用时溢出处可在字母间断开再接省略号
- 〔做法第 2、3 步〕textOverflow 设 None、Clip、Ellipsis 时要配合 maxLines 使用，单独设置不生效；默认按 BREAK_WORD 的方式截断，要以字母为单位截断需设 wordBreak 为 BREAK_ALL
- 〔原因〕ellipsisMode 只设置省略位置，没有设置时默认在行尾省略（END），要与 Ellipsis、maxLines 一起用；START、CENTER 只在单行文本超长时生效
- 〔原因〕ArkUI maxLines + Ellipsis（默认 wordBreak）的末行放不下整词时整词丢弃，接带前导空格的「 ...」，右侧留白
- 〔做法第 2 步〕单行标题 maxLines(1) + Ellipsis 不设 wordBreak 时省略在词边界（如「Alpha beta …」）；设 wordBreak(BREAK_ALL) 时在字符处省略（如「Alpha beta gamma delt…」，与安卓参照机相同）
- 〔原因〕安卓 StaticLayout 计算行尾省略时按字符宽度逐个累加，放不下的字符连同省略号一起替换；省略号是单个 U+2026（…）
- 〔适用情境〕安卓 Toolbar 的标题、副标题 TextView 由框架设为 setSingleLine() 且 setEllipsize(TextUtils.TruncateAt.END)
- 〔做法第 3 步〕MeasureUtils.measureTextSize 返回的文本宽、高单位都是 px
- 〔做法第 3 步〕MeasureOptions.constraintWidth 默认单位是 vp，不支持百分比字符串；fontSize 默认 16
- 〔做法第 4 步〕@ohos.graphics.text 的 Paragraph.layoutSync(width) 中 width 是单行最大宽度，单位 px
- 〔做法第 4 步〕Paragraph.getActualTextRange(lineNumber, includeSpaces) 的行号从 0 起，返回该行实际可见的文本范围（不含溢出省略号）；行号无效时 start、end 都为 0
