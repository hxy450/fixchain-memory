# Compose 可折叠正文（onTextLayout 的 didOverflowHeight 决定展开钮、maxLines 折叠）迁 ArkUI：用文本测量比较限行与不限行高度判定溢出，overflow 按源默认 Clip，其余加工与交互逐项落实

## 何时使用

界面实现阶段，把 Compose 可折叠文本卡转换为 ArkUI 组件，确定是否显示展开按钮、折叠态 overflow 与文本加工时；占位复核阶段决定字符数近似是否保留时

## 适用情境

源 Text 用 onTextLayout { didOverflowHeight / hasVisualOverflow } 决定是否显示展开钮，maxLines 在折叠与展开间切换且未设 overflow（Compose 默认 Clip），正文可能经 buildAnnotatedStringWithUrls 等加工，外层 toggleable/clickable 带按压反馈；ArkUI Text 没有同名排版回调，写者可能用字符数阈值近似。

## 例外与边界

- 目标 Text 没写 textOverflow 时默认就是 Clip，与源端一致，不必为此补写；源端显式设了 overflow（如 Ellipsis）时按源端的值，不在第 3 步的范围内。
- 按压反馈跟随源端的可切换状态：外层 toggleable 只在文本溢出、可展开时有按压态，不溢出时不加。

## 原因

字符数阈值与字体、行宽、换行无关，同样长度的文字在不同屏宽、字号与语言下溢出与否不同，展开钮会多出或缺失。只把最难的溢出判定登记为近似时，同一组件的链接、overflow 默认值与按压反馈常被静默丢弃；习惯性加 Ellipsis 也改变了源端的 Clip 外观。

## 做法

1. 先把源组件拆成逐项契约：溢出判定依据、文本加工与链接、overflow、交互反馈、容器色；每项给出实现或登记，不只登记最难的一项。
2. 溢出判定用 UIContext.getMeasureUtils().measureTextSize：以与 Text 相同的字号、字重、行高、字距，在实际约束宽度（如 onAreaChange 取得的宽度）下分别测不限行与 maxLines = N 的高度，前者更高即溢出；字符数阈值只作显式登记的临时近似。
3. 源 Text 未设 overflow 时按 Compose 默认 Clip 落实，不加 TextOverflow.Ellipsis。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 androidx.compose.material3:material3-android 1.5.0-alpha08（字节码）。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 3 步〕Compose material3 Text 不传 overflow 时取 TextOverflow.Clip（material3-android 1.5.0-alpha08 字节码中如此；其他版本未核）
- 〔做法第 3 步〕ArkUI TextOverflowOptions.overflow 默认 TextOverflow.Clip；None 与 Clip 效果相同；None、Clip、Ellipsis 要配合 maxLines 才生效
- 〔做法第 2 步〕ArkUI Text 默认自动折行；指定 maxLines 后最多显示到该行数，多余文本由 textOverflow 指定截断方式
- 〔做法第 2 步〕MeasureUtils.measureTextSize 返回的文本宽、高单位都是 px
- 〔做法第 2 步〕MeasureOptions.constraintWidth 默认单位是 vp，不支持百分比字符串；fontSize 默认 16
- 〔做法第 2 步〕官方示例判断截断的方法：同一文本分别测不限行与设 maxLines 的高度，不限行的更高即存在截断
- 〔做法第 1 步〕Span 支持通用事件 onClick、onHover；Span 没有尺寸信息，点击事件返回的 ClickEvent 的 target 属性无效
