# Tab 标签、页面标题与设置行等可见文案沿资源引用链取源端 strings 资源的逐字值，不用枚举名、路由名或自拟英文

## 何时使用

界面实现阶段，为 Tab 标签、页面/路由标题、设置入口行等可见文案取值并写入页面与路由表时；以及派发侦察或规格任务、确定导航与标题字段的形态时

## 适用情境

源端可见文案经资源键间接引用（导航目的地的 label、配置路由的标题资源、顶栏 title），常与目的地枚举名或功能名不同（如 Map 目的地显示“Mesh Map”、Messages 目的地的页面标题为“Conversations”）；目标以硬编码字符串或自建资源表承载；上游 brief 或页面规格已给出、或可从 strings.xml 解析出逐字值。

## 原因

枚举名、路由名和自拟短语与源端显示文案经常不同，按它们填写会在每个入口留下近似改写，要求逐字一致的验收会成批失败。来源中生成者两分钟前读到的 brief 已逐字给出 User、Security、System AI 与完整的开关摘要，写页面时仍用了自建资源表里的 User Config、App Functions，并删去摘要的括号内容；另一批 Tab 与页面标题取自只含枚举名的侦察清单，已落盘的页面规格里有正确字面值却没有打开。

## 做法

1. 写可见文案前沿源端引用链（导航目的地 label → 资源键 → strings.xml）解析出逐字值；已读的 brief 或页面规格给出字面值时直接照抄，括号与标点一并保留。
2. 把 P0 可见文案集中到一个常量或资源文件，逐条注明源资源键，页面与路由表只引用它。
3. 派发侦察或规格任务时，导航目的地和页面标题字段同时要求资源键与解析后的字面值，不只给枚举名。

## 可选检查

- 对文案有疑问时，用源 strings.xml 与集中文案文件逐项比对。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；安卓 aapt2 2.20（build-tools 36.1.0）；Android SDK 源码 android-36.1；material 1.4.0、1.14.0；Compose Multiplatform compose-gradle-plugin 1.7.3、1.10.0 与 components-resources 1.10.0（源码）。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1 步〕Android 的 res/values*/strings.xml 经 aapt2 编译后，显示值不等于 XML 原文：\' \" \@ \n \uXXXX 等转义换成对应字符，&amp; 一类实体被解码；没转义的双引号被去掉，引号里的空白原样保留；引号外的首尾空白被去掉，中间连续空白（含换行和缩进）压成一个空格；<b> 等标签变成样式区间，文字里不含标签；值为 @string/其他键 时是引用，要再沿引用取值。〔成立范围：对 Android 工程 res/values*/strings.xml、经 aapt2 编译、用 getString 或 stringResource 等 Android 资源接口取值的文案成立；用 build-tools 36.1.0 的 aapt2 2.20 编译样例核过。不成立：Compose Multiplatform 的 composeResources 字符串另有处理规则（见下一条）。〕
- 〔做法第 1 步〕Compose Multiplatform 的 composeResources/values*/strings.xml（Res.string.x）在构建时只处理 \n、\t、\uXXXX 和 \\ 四种转义，XML 实体照常解码；不去双引号、不压缩空白（首尾空白、换行和缩进原样进入文案），\' 与 \" 的反斜杠留在文案里。〔成立范围：对 org.jetbrains.compose 的 compose-gradle-plugin 1.7.3 与 1.10.0（两版 handleSpecialCharacters 实现相同）和 components-resources 1.10.0 运行时（只做 Base64 解码，不再处理）成立。不成立：同一工程里 Android 端 res/values 下的 strings.xml 仍按 aapt2 的规则。〕
- 〔做法第 1 步〕View 体系的 com.google.android.material.tabs.TabLayout 在 Theme.MaterialComponents 系主题下，标签文字外观取 ?attr/textAppearanceButton，即 TextAppearance.MaterialComponents.Button，其 android:textAllCaps 为 true，屏幕上显示的是资源值的全大写；在 Theme.Material3 系主题下取 TextAppearance.Material3.TitleSmall，textAllCaps 为 false，按原样显示。〔成立范围：对应用没有另设 tabStyle、tabTextAppearance 或 textAllCaps 的 TabLayout 成立；material 1.4.0 与 1.14.0 资源核过，Material3 部分只在 1.14.0 核过。Theme.AppCompat 系主题没有 tabStyle，TabLayout 用默认样式 Widget.Design.TabLayout，其 TextAppearance.Design.Tab 的 textAllCaps 同样为 true。不成立：应用把 tabTextAppearance 换成 textAllCaps 为 false 的样式时按原样显示。〕
