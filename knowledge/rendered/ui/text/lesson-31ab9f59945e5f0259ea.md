# Tab 标签、页面标题与设置行等可见文案沿资源引用链取源端 strings 资源的逐字值，不用枚举名、路由名或自拟英文

## 何时使用

界面实现阶段，为 Tab 标签、页面/路由标题、设置入口行等可见文案取值并写入页面与路由表时；以及派发侦察或规格任务、确定导航与标题字段的形态时

## 适用情境

源端可见文案经资源键间接引用（导航目的地的 label、配置路由的标题资源、顶栏 title），常与目的地枚举名或功能名不同（如 Map 目的地显示“Mesh Map”、Messages 目的地的页面标题为“Conversations”）；目标以硬编码字符串或自建资源表承载；上游 brief 或页面规格已给出、或可从 strings.xml 解析出逐字值。

## 原因

枚举名、路由名和自拟短语与源端显示文案经常不同，按它们填写会在每个入口留下近似改写，要求逐字一致的验收会成批失败。来源中生成者两分钟前读到的 brief 已逐字给出 User、Security、System AI 与完整的开关摘要，写页面时仍用了自建资源表里的 User Config、App Functions，并删去摘要的括号内容；另一批 Tab 与页面标题取自只含枚举名的侦察清单，已落盘的页面规格里有正确字面值却没有打开。

## 做法

1. 写可见文案前沿源端引用链（导航目的地 label → 资源键 → strings.xml）解析出逐字值；已读的 brief 或页面规格给出字面值时直接照抄，括号与标点一并保留；从 Android res/values 下的 strings.xml 取值时取编译后显示的值：字符串里没有 <b>、<i> 等标签时先去掉首尾空白，去掉转义用的反斜杠（\' 得 '，\n 得换行），去掉成对的包裹双引号，引号外的连续空白算一个空格。
2. 把 P0 可见文案集中到一个常量或资源文件，逐条注明源资源键，页面与路由表只引用它。
3. 派发侦察或规格任务时，导航目的地和页面标题字段同时要求资源键与解析后的字面值，不只给枚举名。

## 可选检查

- 对文案有疑问时，用源 strings.xml 与集中文案文件逐项比对。

来源支持：1 张卡 · 1 次迁移 · 1 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 aapt2 源码（AOSP frameworks/base main）。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1 步〕Android res/values 的字符串由 aapt2 编译，界面显示的是编译后的值（字符串没标成保留空白时）：没有 <b>、<i> 这类 span 标签时，先去掉原文首尾的空白（在处理引号和转义之前，所以引号里或用 \u0020 写的首尾空格保留）；引号外连续空白折成一个空格；未转义的 " 不输出、只切换「引号内」状态，引号内空白原样保留；\n、\t 转成换行、制表；\'、\"、\\、\@、\?、\# 输出字面字符；\uXXXX 按码点输出；其他 \x 去掉反斜杠留下字符；引号外未转义的 ' 编译报错
- 〔做法第 2 步〕$r(value: string, ...params: any[]): Resource（@since 7）按 'app.type.name' 取资源；string.json 的值里有 %1$s、%2$d 这类占位符时，写 $r('app.string.label', 'aaa', 444)，后面的参数依次替换占位符
- 〔做法第 2 步〕Text 的构造 (content?: string | Resource, value?: TextOptions) 可以直接接 $r 返回的 Resource
