# 源应用声明 supportsRtl=true 时保留逻辑方向：start/end 边距写 LengthMetrics 的 start/end，AutoMirrored 图标加 matchTextDirection(true)

## 何时使用

规格提取与界面实现阶段，为声明 supportsRtl=true 的源应用转换 start/end 边距与自动镜像图标时

## 适用情境

源 Manifest 声明 android:supportsRtl="true"；Compose 用 padding(start/end)、Icons.AutoMirrored.*（或 autoMirrored=true 的矢量），View 用 marginStart/End、paddingStart/End；应用含 RTL 语言资源或可能在 RTL 系统语言下运行；转换者准备写 left/right，把返回箭头等方向性图标转成普通 Image；页面规格可能没有携带 RTL 契约，资源映射可能把自动镜像图标当普通媒体。 也包括 View 布局用 paddingStart/End、layout_marginEnd、layout_gravity="bottom|end"，目标外层 Stack 用 Alignment.BottomEnd 定位而边距写成 right；或第三方容器（库 View）内部另有自己的排布规则。

## 例外与边界

- 源 Manifest 未声明 supportsRtl：布局恒 LTR，按显式固定 LTR 的做法处理

## 原因

start/end 与 AutoMirrored 都是随布局方向翻转的逻辑语义；写成 left/right 或普通图片后，RTL 语言下间距落在错误一侧、返回箭头指向反方向。规格没把 RTL 列为全局契约时，各页转换者容易就近改成物理方向。

## 做法

1. 规格阶段读到 supportsRtl=true 时，把“布局随语言方向镜像”写成全局契约传给各页，并在资源映射中标出需要镜像的方向性图标。
2. start/end 边距写 .padding/.margin({ end: LengthMetrics.vp(n) })，同一对象各边都用 LengthMetrics；源端本就是物理 left/right 的才写 left/right。写完 grep 目标文件里的 left:/right:，逐处回对源 XML 是否为 Start/End。同一元素的对齐与边距用同一套方向语义：Stack 的 alignContent 与 align() 取 Alignment.BottomEnd、Column 的 alignItems 取 HorizontalAlign.End 等容器对齐随布局方向镜像（align() 传 Alignment 只在 Stack 上镜像；其他组件要镜像须传 LocalizedAlignment，它只在 Shape、Button 等少数组件上有效，在 Stack 上无效），margin({ right }) 不镜像，混用会在 RTL 下让对齐与留白落在两侧。
3. Icons.AutoMirrored.* 或 autoMirrored 矢量转成的 Image 加 .matchTextDirection(true)；图标经共享按钮组件渲染时，由组件提供镜像参数并在调用处传入。
4. 三方库容器（如 FAB 菜单）内部子项是否随 RTL 镜像，按库的 onMeasure/onLayout 源码确定，不由外层 Start/End 属性推断；库内按物理方向排布的部分，在目标对应容器上显式固定方向。

- 〔例外与边界〕安卓 Manifest 的 android:supportsRtl 默认 false；View 解析布局方向时只有应用声明了 RTL 支持才按 RTL 解析，否则一律 LTR，start/end 落在左/右。〔成立范围：对象：<application android:supportsRtl> 与该应用内所有 View 的布局方向。条件：平台 attrs_manifest 文档（android-36）与 android-36.1 源码。不成立的情形：声明 supportsRtl="true" 后，布局随语言方向镜像。〕
- 〔做法第 3 步〕Image 的 matchTextDirection 默认 false：不设时图片在 RTL 语言环境下不镜像，设为 true 才随系统语言方向镜像翻转；图片参数为 AnimatedDrawableDescriptor 时设置不生效。〔成立范围：对象：Image 组件。条件：API 9+，方向取系统语言方向。不成立的情形：图片源是 AnimatedDrawableDescriptor 时即使设 true 也不镜像。〕
- 〔做法第 2 步〕padding、margin 传 LocalizedPadding、LocalizedMargin（start/end 为 LengthMetrics）时，从右至左语言下 start 落在右侧、end 落在左侧；传 left/right 不随语言方向翻转。position、markAnchor、offset 同样要用 start/end 入参才镜像，x/y 不镜像。〔成立范围：对象：通用属性 padding、margin、position、markAnchor、offset、borderWidth、borderColor、borderRadius 的 Localized 入参（API 12+）。条件：组件布局方向为 RTL（系统语言或 direction 决定）。不成立的情形：LTR 语言且未把 direction 设为 Rtl 时，start 就是左侧。〕
- 〔做法第 2 步〕Stack、Row、Column、Flex、List、RelativeContainer 等容器默认适配镜像：Stack 的 alignContent 取 TopStart、BottomEnd 等起始端/尾端值，Column 的 alignItems 取 HorizontalAlign.Start/End 时，按语言方向确定起始端，RTL 下随之翻转。〔成立范围：对象：这些容器的子组件对齐参数。条件：组件 direction 为 Auto（默认，按系统语言）或显式设为 Rtl。不成立的情形：Canvas 只有限支持文本绘制的镜像，XComponent 不支持镜像；通用属性 align() 传 Alignment 时除 Stack 外不镜像（Stack 上 align 与 alignContent 一样随方向镜像）。〕
- 〔做法第 2 步〕通用属性 align() 传 Alignment 时，只在 Stack 上随 direction 或系统语言镜像（与 alignContent 效果一致），在其他组件上不镜像；要在其他组件上镜像须传 LocalizedAlignment（API 20+），它只在 Shape、Button、GridItem、FlowItem、Toggle、Checkbox、MenuItem、Progress 等少数组件上有效果，ListItem 上与 Alignment 效果相同；Stack 不在 LocalizedAlignment 的生效列表里，在 Stack 上传 LocalizedAlignment 无效果，按组件默认效果（居中）显示。〔成立范围：对象：通用属性 align（LocalizedAlignment 为 API 20+）。条件：direction 不为 Auto 时按 direction，否则按系统语言方向；依据是文档说明。不成立的情形：Stack 上 align 传 Alignment 本身就随方向镜像（在 Stack 上改传 LocalizedAlignment 无效果，再手工按方向翻转会在 RTL 下翻两次）；生效列表以外的组件（含 Stack）设 LocalizedAlignment 无效果，按组件默认对齐显示。〕
- 〔做法第 4 步〕组件的 direction 默认 Direction.Auto，按系统语言方向布局；direction 在 Column 组件上不生效。〔成立范围：对象：通用属性 direction。条件：取 undefined 或 null 时按默认值处理。不成立的情形：在 Column 上设 direction 固定方向无效，需设在 Row、Stack 等其他组件上。〕
