# 把原由 Tabs、Grid 等容器分配槽位的子项搬进自绘 Row/Column 时重新确定主轴尺寸：等分用 layoutWeight(1)，不保留依赖旧容器的 width('100%')

## 何时使用

公共组件或页面实现阶段，把 Tabs 内置 tabBar、Grid 等由容器分配槽位的子项改写为自绘 Row/Column + ForEach（如自绘底部导航），确定每个子项的主轴尺寸时

## 适用情境

源端底栏是水平 LinearLayout，子项由代码以 LayoutParams(0, MATCH_PARENT) 与 weight=1 动态添加，布局 XML 里没有静态子项；目标原先用 Tabs BarMode.Fixed 承载页签、页签 builder 写 width('100%')/height('100%')，新组件把该 builder 原样搬进 Row。

## 例外与边界

- layoutWeight(1) 只对应源端主轴写 0 加 weight 的等分：源端子项主轴是 wrap_content 等自然尺寸再加 weight（最终宽 = 自然宽 + 分到的余量），或父容器写了 android:weightSum 时，layoutWeight 不在自然尺寸上叠加、也没有总权重参数，不能直接写 layoutWeight，要按源端算出的宽度写。
- 只改主轴上的 '100%'；交叉轴（Row 里子项的 height）的 '100%' 对应源端 LayoutParams 的 MATCH_PARENT，保留不动。

## 原因

在 Tabs、Grid 的槽位里，子项的 '100%' 按容器分给它的槽位解析；搬进 Row 后每个子项都取父容器全宽，N 项合计 N×100%，后面的项被挤出屏幕。只读容器 XML 看不到子项如何分宽，代码里的 LayoutParams 与 weight 才是依据。来源中写者没有打开规格指向的 Activity 代码，照搬旧页签 builder，三栏底部导航的第三项落在屏幕外；后续接线与内联改动都声明不改视觉参数，偏差保留到真机验证。

## 做法

1. 换容器时重新确定子项主轴尺寸：源端等分（0dp + weight=1）写 layoutWeight(1)；需要固定宽或按内容宽时按源端 LayoutParams 写，不保留旧容器里的 '100%'。
2. 组件来源写成“XML + 代码”时，同时读代码中动态添加子项的 LayoutParams 与 weight。

## 可选检查

- 写完做算术核对：Row 内 N 个子项的主轴宽度之和不超过父宽

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因 / 做法第 1 步〕LinearLayout 里 weight 大于 0 的子项：主轴尺寸写 0 时（父容器主轴为 EXACTLY）最终尺寸只取分到的余量 share；主轴有自然尺寸（如 wrap_content）时最终尺寸是自然尺寸加 share
- 〔做法第 1 步〕LinearLayout 按子项先后逐个分余量：share = weight × 剩余余量 / 剩余权重和，每分一项就从余量和权重和里减掉；剩余权重和的起始值在写了 android:weightSum（大于 0）时取它，否则取各子项权重之和；余量可以为负
- 〔做法第 1 步〕layoutWeight 默认 0，只在 Row、Column、Flex 中生效；生效值大于 0 的子组件从主轴剩余空间按权重分配尺寸，忽略自身 width/height 但保留 minWidth/minHeight；它没有安卓 weightSum 那样的总权重参数，也不在自然尺寸上叠加
- 〔原因〕组件尺寸用百分比设置时，按最近一个设置了固定大小的祖先节点的尺寸计算；Row 里子项的 width('100%') 取的是这个祖先的整宽，不是平分后的一格
