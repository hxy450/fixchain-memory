# 随选中进度收放的图标与文本位置：源端为 0 的间距按同一选中条件归零

## 何时使用

界面实现阶段，把源端自定义 Layout 中随动画进度收放的图标、文本位置公式翻成 ArkUI 属性时

## 适用情境

源端导航项等按 animationProgress 计算文本宽度（含其两侧间距），未选中时为 0、图标在槽内居中；目标用 Row 居中加 constraintSize、opacity、scale 折叠文本来模拟。

## 例外与边界

- 只把源端公式里乘了动画进度（未选中时为 0）的那几段间距按选中条件归零；源端不随进度变化的间距（槽位自身的内边距、图标的外边距等）在两种状态下都保留，不跟着一起取 0。

## 原因

目标端只把文本宽度折叠为 0、保留固定 padding 时，未选中项仍多占一段间距，图标偏离槽中心，偏移等于残留宽度的一半。无法确认的框架行为（如 constraintSize 是否钳住 padding）被当作“很小、不可感知”接受时，已算出的偏差会留到验收。

## 做法

1. 把随进度缩放的每个量逐项对应到目标属性；源端未选中时为 0 的部分（包括间距），目标 padding、margin、space 也按同一选中条件取 0，并与宽度、透明度同一动画收放。
2. 遇到不能确认的框架行为时改用不依赖它的写法；确需保留近似时在报告里给出偏移值与复验位置。

## 可选检查

- 按未选中态手算一次：图标中心偏移 = −(图标之后仍占位的宽度)/2，结果应为 0。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因〕Text 设 constraintSize({ maxWidth: 0 }) 并带一个不随选中变化的左 padding（4vp）时，设备上这段 padding 仍然占位：同一 Row 居中的图标比槽位中心偏左约 2vp，即残留宽度的一半
- 〔做法第 1 步〕应用没有另设 padding 时内边距默认 0，数值单位是 vp；参数为 Length 时四个方向同时生效
- 〔做法第 1 步〕constraintSize 优先级高于 width、height，单位 vp；没有设置时取 {minWidth: 0, maxWidth: Infinity, minHeight: 0, maxHeight: Infinity}；文档和声明都没有写它是否连同 padding 一起压缩
- 〔做法第 1 步〕Row 的 space 不写时子组件间距为 0，单位 vp，不支持百分比；space 为负数，或 justifyContent 为 FlexAlign.SpaceBetween、SpaceAround、SpaceEvenly 时 space 不生效；非法值按默认值处理
