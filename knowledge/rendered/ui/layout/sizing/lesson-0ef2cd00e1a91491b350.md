# 源端在整数 px 上取整的布局公式：规格写明运算域，实现在 px 域取整、写入布局属性前再换回 vp

## 何时使用

规格提取阶段，把自定义 Layout、MeasureScope 里的测量与整数几何公式翻成目标契约时；界面实现阶段，用 onAreaChange、measureText 等返回值驱动这类公式时；移植自绘 View 的绘制坐标、setBounds 边界、位移与文字基线修正中的 (int) 强转时

## 适用情境

源算法在约束或测量结果（Compose constraints、placeable 宽高等整数 px）上做整数除法、.toInt() 截断或取整；目标布局属性和尺寸回调（onAreaChange）使用 vp 等逻辑单位，回调值通常不是整数；UIContext.getMeasureUtils().measureText 返回 px，画布 CanvasRenderingContext2D.measureText 的结果与画布坐标同单位（默认 vp）。 也包括 Canvas 绘制代码中的 (int) 强转（setBounds 边界、int 位移、文字基线修正），其中的量可能为负。

## 例外与边界

- 公式本来作用于 Dp 常量（固定间距、固定尺寸），不涉及 constraints 或 placeable 时，按原单位保留；View 体系里经 getDimensionPixelSize / getDimensionPixelOffset 或 XML 布局读入的 dp 尺寸已是整数 px（前者四舍五入、后者截断），对它们做的整数运算仍在 px 域，不属于此例外

## 原因

单位缩放与取整不可交换：保留 floor 等函数名却把输入换成 vp，每次截断的小数按 vp 丢弃，槽宽总和铺不满容器、位置偏移；把 MeasureUtils.measureText 返回的 px 先转 vp 再进公式也改变了运算域。规格把 vp 回调值写成“整数”或把“源端余下 W mod n 空白”按 vp 复述时，错误的等价性声明看起来成立，并传给所有照做的实现者。

## 做法

1. 规格提取：写出公式输入输出的单位、整数或浮点类型、取整位置和换算边界，以源测量代码为准；例如源公式为 Wpx/(n+1) 时，契约写成 u_px = floor(Wpx/(n+1))、供布局使用时 u_vp = px2vp(u_px)，不要写成 floor(Wvp/(n+1))。用例至少放一个非整数 vp 宽与对应 px 宽的对照行。
2. 实现：参数名带单位（如 widthPx）；onAreaChange 的 vp 宽（Area.width 声明为 Length，按 number 取用）和默认 vp 画布上 measureText 的结果先 vp2px，MeasureUtils.measureText 的 px 直接使用，公式在 px 域取整，结果写入 width、translate、position 前再 px2vp。规格把回调值写成“vp、整数”时，先用一个真实回调值核对。
3. Java/Kotlin 的 (int)/toInt() 向零截断，用 Math.trunc；量可能为负（反向位移、扩张时的负边界）时不能换成 Math.floor。视觉验收看不出亚像素差也原样保留，偏移被乘倍使用时误差随之放大。

## 可选检查

- 单位或取整顺序有疑问时，代入一个实测宽度比较两种顺序；能 dump 时核对行总宽是否等于容器 px 宽。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，openharmony ets 6.1.0.105；文档副本含到 API 26 的内容，超出 SDK 的已注明）；安卓 平台资源 android-34；框架源码 android-36.1；androidx Compose 1.10.3（foundation、ui、ui-unit、ui-graphics，按字节码核）。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境〕Compose Constraints 的 minWidth/maxWidth 等是 Int（px），Placeable.width/height 是 Int（px）；Density.roundToPx 返回 Int、toPx 返回 Float
- 〔适用情境〕Java 整数除法按向零取整（截断），Math.floorDiv 才向负无穷取整，负数时两者不同
- 〔适用情境〕Drawable.setBounds(int left, int top, int right, int bottom)：源端边界本身是 int，取整发生在传参处
- 〔做法第 2 步〕onAreaChange(event: (oldValue: Area, newValue: Area) => void)；Area.width/height 声明为 Length（string | number | Resource）、单位 vp，回调值一般不是整数
- 〔做法第 2 步〕UIContext.vp2px(value: number): number、px2vp(value: number): number（@since 12）；全局 vp2px/px2vp 自 API 18 废弃，声明指向 UIContext 上的同名方法
- 〔做法第 2 步〕MeasureUtils.measureText(options: MeasureOptions): number 返回 px；measureTextSize 的宽高也是 px；经 UIContext.getMeasureUtils() 取得
- 〔做法第 2 步〕默认 vp 单位的画布上，CanvasRenderingContext2D.measureText 的 width/height 与 fillText、strokeRect 坐标同为 vp：文档写画布接口参数如无说明单位均为 vp，示例直接用测得的宽高画边框
- 〔做法第 2 步〕Length 的字符串可显式带单位，'10px' 按 px；number 或不带单位的字符串按 vp
- 〔做法第 2 步〕画布坐标：CanvasRenderingContext2D(settings?, unit?: LengthMetricsUnit)，默认 DEFAULT（vp），传 LengthMetricsUnit.PX 后 fillRect、translate、drawImage 等按 px；构造后不能改
- 〔做法第 3 步〕Math.trunc(x) 去掉小数部分（向零）；Math.floor(x) 取不大于 x 的最大整数，负数时比 trunc 小 1
- 〔做法第 3 步〕Java 的 (int) 强转把浮点向零截断：在负的非整数值上 Math.trunc 与它相同，Math.floor 比它小 1
