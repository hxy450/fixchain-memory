# “父尺寸减边距”或“扣除兄弟后的剩余空间”不写成 '100%'：match_parent/0dp 加同轴 margin 改用容器 padding 或 calc，Column 中占剩余高度的内容区用 layoutWeight(1)，等权重兄弟的间距改用 space

## 何时使用

界面实现阶段，把 match_parent 或两侧约束 0dp 且带同轴 margin 的视图、或带 margin 的等权重兄弟翻译成 ArkUI 尺寸与间距时；按要求调整左右边距时；为 Compose Column 中排在搜索栏、分隔线等固定高度节点之后、占满剩余高度的内容区确定高度时；宿主页在固定标题栏下嵌入根节点为 height('100%') 的面板或弹层组件时

## 适用情境

源元素 match_parent（或约束到父两侧的 0dp）同时设 layout_marginHorizontal/Start/End 或 marginTop/Bottom；或水平 LinearLayout 中等权重（0dp + weight）的子项以 marginStart 作间距（改用 space 的前提是各相邻兄弟之间间距相同：space 对每对相邻子项一律生效，justifyContent 为 SpaceBetween、SpaceAround、SpaceEvenly 时不生效；间距不等或只在部分兄弟之间时，在对应位置放固定宽的占位节点）；目标用 width/height('100%') 或 layoutWeight。宽高写固定值或随内容的节点上的 margin 不涉及父尺寸扣减，照源端保留，不在这条的改动范围内。也包括 Compose Column 里内容区排在固定高度兄弟之后，靠 fillMaxSize、weight 或 Lazy 列表默认行为占满剩余高度，可能有空结果、加载、结果等多个状态分支。 也包括宿主页 Column 顶部有固定高度标题栏，下方直接放根节点 height('100%')、自带标题行与底部按钮栏的筛选面板；对应 Android 以 MATCH_PARENT 的 PopupWindow showAsDropDown(标题栏) 弹出、且源端在弹出前按锚点下沿限定了弹窗高度，只占锚点以下的高度。也包括 wrap_content 加 minWidth 实际占满可用宽，或 RecyclerView 项偏移（ItemDecoration）被写成容器外边距的变体。也包括 Compose 元素水平占满父级（fillMaxWidth，或被 fillMaxWidth 的子项撑满），修饰链里 padding(horizontal) 写在 background、clip 或 Button 等包装之前：这时 padding 起外边距作用，可见宽为父宽减两侧之和；padding 只写在 background 之后时背景仍铺满父宽，不属于这条。

## 原因

Android 中这类元素的尺寸是父尺寸减去同轴边距，权重也在扣除 margin 后分配；ArkUI 的百分比尺寸按父尺寸计算、margin 再向外扩，layoutWeight 的份额也包含子项自身 margin。结果是横向右溢（没有右边距、行尾截断、贴屏）、纵向在 Stack 中超高并被默认居中顶穿、等权重卡片不等宽。映射参考只做逐属性对应、没有这条规则时，多个页面会重复同一偏差；用户要求加大边距时改子项 margin，溢出会更明显。又一应用的首页统计卡同样由 match_parent + 左右 18dp 写成 width('100%') 加左右 margin，修复改为 calc(100% - 36vp)。再一应用的计算器页，显示卡片与键盘同样写成 width('100%') 加左右 15 的 margin、按键 height('100%') 加上下 margin，真机上贴边且行间无留白，修复改为按比例宽居中与 calc(100% - 14vp)。Compose 测量 Column 中的 fillMaxSize 子项时，可用高度已扣除先测的兄弟；ArkUI height('100%') 取父容器全高，会多出兄弟的高度而溢出到底栏之下。 子组件根节点的 '100%' 取父容器全高，再叠上固定标题栏就超出窗口，底部按钮被挤出屏幕。另一应用的标签筛选面板如此：宿主写者已读到源端锚在标题栏下的弹出方式，后来也读到面板根节点是 height('100%')，仍保持标题栏加面板的 Column。

## 做法

1. 同轴有 margin 时，把边距放到父容器或新增包装容器的 padding 上，子项只保留 '100%'；父级还有需要贴边的兄弟时，用包装容器、layoutWeight 或 calc(100% - 边距之和)。
2. Stack 叠层中 match_parent 加纵向 margin 的层，用外包容器的 padding 承接内缩，内层 '100%' 相对其内容区。
3. 等权重兄弟以 margin 作间距时，删掉 margin，改用父 Row/Column 的 space（或固定宽的 Blank），让 layoutWeight 只分配扣除间距后的空间。
4. 写完 grep 同一修饰链里 width/height('100%') 与同轴 margin 的组合；意识到这条规则后把同页的按钮、卡片、列表行一起改；按要求加大边距时改容器 padding 的数值。
5. Column 中占剩余高度的内容区写成一个 .layoutWeight(1) 容器，各状态分支都放在这一层里，分支自身不写 height('100%')；规划过这层包裹容器时，写完回看 build() 确认它确实写出。规格里写“占某元素之后的剩余高度”，不写“全屏”。
6. 嵌入自带标题行与底栏、根节点为 height('100%') 的面板时，先读组件根尺寸声明，不在同一 Column 里再给它叠固定高度兄弟：给面板槽位 layoutWeight(1) 或外包有界容器，或放到外层 Stack 作覆盖层并去掉重复标题。源端 MATCH_PARENT + showAsDropDown(锚点) 先看源端弹出前是否按锚点下沿另算了高度：另算了的对应锚点以下的剩余高度，不译成相对整页的 '100%'；直接 setHeight(MATCH_PARENT) 后 showAsDropDown 的，弹窗取窗口可见区全高并被上移到可见区内、盖住锚点，对应外层 Stack 的全屏覆盖层。并行拆分面板与宿主时，交接写明尺寸契约（面板满高、由宿主分配有界区域）。
7. RecyclerView 项偏移等内部间距落到容器 padding 或网格 gap，不转成容器外边距。

## 可选检查

- 用布局 dump 或截图核对左右间距对称、右缘不越出父容器、等权重项宽度相等。
- 带底部操作栏的弹层打开最长内容态，核对底栏下边界不越出可视区、按钮可点。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因 / 做法第 1、4 步〕ArkUI 百分比尺寸参考最近设置了固定大小的祖先节点的尺寸；width、height 设百分比时以父容器的宽、高作为基础值，'100%' 不扣除组件自身的 margin
- 〔原因 / 做法第 1 步〕margin 默认 0、单位 vp，传 Length 时四个方向同时生效，设百分比时上下左右都以父容器的 width 为基础值；在 Row、Column、Flex 交叉轴上，子组件占用的空间是自身尺寸加 margin，所以 width('100%') 再加水平 margin 会超出父容器
- 〔做法第 1、2 步〕padding 默认 0、单位 vp，传 Length 时四个方向同时生效，设百分比时上下左右内边距都以父容器的 width 为基础值
- 〔做法第 1、2 步〕内容区 Stack 没有设 alignContent，两层子组件分别写 height('100%') 加 margin({ top: 170 }) 与 height('100%') 加 margin({ top: 8, bottom: 125 }) 时，真机上内容层标题被顶到状态栏下、渐变卡整体上移；外包 Column 承接纵向 padding、内层 height('100%') 时，真机上内层落在外包容器扣除 padding 后的区域内
- 〔做法第 1 步〕width、height、size、padding、margin、constraintSize 从 API 10 起支持 calc，运算符与数值之间要用空格隔开（如 'calc(100% - 36vp)'）；width、height 收到 undefined 时设置不生效，收到其它异常值时恢复到不配置时的默认行为
- 〔原因 / 做法第 1、4 步〕Column 中显示卡片写 width('100%') 加左右 margin 15、按键写 height('100%') 加上下 margin 7 时，真机截图上卡片和键盘贴边、按键行间没有留白；只把 margin 加大到 45 时仍然贴边
- 〔原因〕Column 没有另设 alignItems 时，子组件在水平方向居中（HorizontalAlign.Center）；Row 没有另设 alignItems 时子组件在垂直方向居中（VerticalAlign.Center）
- 〔原因 / 做法第 1 步〕安卓 ViewGroup.measureChildWithMargins 以父容器 MeasureSpec 减去父 padding 和子视图两侧 margin 后的尺寸算子视图的 MeasureSpec，所以 match_parent 加同轴 margin 的子视图尺寸是父尺寸减父 padding 再减 margin；FrameLayout 量子视图时同样走 measureChildWithMargins
- 〔原因 / 做法第 3 步〕安卓水平 LinearLayout 在宽度确定时，先把 0dp 加 weight 子项的 leftMargin、rightMargin 计入总长，再把剩余空间按 weight 分给这些子项，所以源端的权重份额不含 margin
- 〔原因 / 做法第 3、5 步〕layoutWeight 默认 0，小于 0 按 0 处理，只在 Row、Column、Flex 中生效：父容器尺寸确定时，不设或为 0 的子组件先占位，大于 0 的子组件从主轴剩余空间按权重分配尺寸，分配时忽略自身 width、height 但保留 minWidth、minHeight；容器里有子组件 layoutWeight 大于 0 时，所有子组件不再按 flexShrink、flexGrow 布局
- 〔原因 / 做法第 3 步〕Row 中两张卡都 layoutWeight(1)、右卡另设 margin({ left: 15 }) 时，真机布局 dump 左卡宽 640px、右卡宽 588px；两卡都不设 margin、Row 设 space 15 时两卡都是 614px
- 〔做法第 3 步〕Row、Column 的 space 默认 0、单位 vp，不支持百分比，非法值按默认值处理；space 为负数或 justifyContent 设为 FlexAlign.SpaceBetween、SpaceAround、SpaceEvenly 时 space 不生效
- 〔原因 / 做法第 2 步〕Stack 没有另设 alignContent（构造参数或属性）时子组件按 Alignment.Center 对齐，非法值按默认值处理，所以比 Stack 高的子组件上下两头都越出
- 〔原因 / 做法第 2 步〕安卓 FrameLayout 子视图在应用没有另设 layout_gravity 时按 DEFAULT_CHILD_GRAVITY（Gravity.TOP | Gravity.START）摆放，和 ArkUI Stack 默认居中不同
- 〔原因〕组件没有设 clip 时不裁剪子组件超出自身范围的部分，越出父容器的子组件照样画出来
- 〔原因 / 做法第 5 步〕根 Column 里先放 56vp 搜索栏和 1vp 分隔线、四个状态容器再写 height('100%') 时，设备上布局 dump 显示内容区溢出 57vp，底部被宿主底栏遮住
- 〔适用情境 / 做法第 6 步〕安卓 PopupWindow.showAsDropDown(anchor) 把弹窗挂在锚点左下角；屏幕上放不下时先尝试滚动父滚动视图，滚不动时把弹窗的左下角钉在锚点左上角
- 〔适用情境 / 做法第 6 步〕安卓 PopupWindow 高度设为 MATCH_PARENT（setHeight）后 showAsDropDown 时，findDropDownPosition 把高度取成窗口可见区全高，锚点下方放不下就把弹窗上移到可见区顶部，弹窗会盖住锚点；应用在弹出前自己算好高度时不走这个分支（按 android-36.1 源码，更早版本本机没有源码）
- 〔做法第 6 步〕宿主根 Column 里先放 44vp 标题栏、下面直接放根节点 height('100%') 且自带标题行和 42vp 底栏的面板时，设备截图上底栏只露出上半截、压在手势条处
- 〔做法第 7 步〕Grid 的 columnsGap、rowsGap 只设列与列、行与行之间的间距，默认 0，小于 0 按 0 显示，不在网格外沿留白
