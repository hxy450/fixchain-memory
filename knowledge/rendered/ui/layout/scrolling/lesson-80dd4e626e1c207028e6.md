# ScrollView 未写 overScrollMode、Compose verticalScroll/Lazy 列表未置空 overscroll 时，都按 Android 默认 IF_CONTENT_SCROLLS 映射：Scroll 写 edgeEffect(EdgeEffect.Spring 或 Fade, { alwaysEnabled: false })，按源设备版本选（API 31 起 Spring、30 及以下 Fade）；GridView/ListView 同此，滚动条按源端默认显式设置

## 何时使用

界面转换阶段，把 ScrollView/NestedScrollView（含对话框内的滚动区）转换为 ArkUI Scroll 并设置边缘效果时；把会滚动的 GridView/ListView 转成 Grid/List 并决定滚动条与越界效果时；把 Compose Modifier.verticalScroll/horizontalScroll 或 LazyColumn/LazyRow 转成 Scroll/List（含 bindSheet 半模态里的内容区）并设置边缘效果时

## 适用情境

源 ScrollView 没有声明 overScrollMode（Android 默认 IF_CONTENT_SCROLLS：内容可滚时有越界效果（API 31 起为拉伸，API 30 及以下为辉光））；映射参考只列显式 overScrollMode，且把 ifContentScrolls 与 always 都映射为不带选项的 EdgeEffect.Spring；目标 Scroll 默认没有边缘效果。 也包括 GridView/ListView 没有改写 scrollbars、overScrollMode（AbsListView 同样默认 IF_CONTENT_SCROLLS），目标 Grid/List 没有显式设置 scrollBar 与 edgeEffect。 也包括 Compose Modifier.verticalScroll/horizontalScroll、LazyColumn/LazyRow 的默认重载带平台越界效果（Android 12+ 拉伸；foundation-android 1.12.1 的默认重载经 LocalOverscrollFactory 取平台效果，字节码已核），源工程没有经 LocalOverscrollFactory/LocalOverscrollConfiguration 或 overscrollEffect 参数置空，页面规格只写 verticalScroll、不提边缘效果。

## 原因

不写 edgeEffect 时 Scroll 没有回弹；写成不带选项的 Spring，内容不满一屏也会回弹。两者都与源端不同；映射参考没有“未声明即 IF_CONTENT_SCROLLS”的规则时，各页会分别落到这两种写法。来源中同一应用的九个滚动页里，六个没设 edgeEffect、三个写了无条件 Spring。 源端视图在窗口变为可见时先显示滚动条约 1200ms 再淡出（View.initialAwakenScrollBars 以 scrollBarDefaultDelayBeforeFade×4 唤醒，默认延迟 300ms；本机 android-36.1 源码 View.java、ViewConfiguration.java），之后滚动时再出现；ArkUI Grid 默认 BarState.Auto，进页不显示（本机 HarmonyOS 6.1.0 SDK component/grid.d.ts，早期版本默认 BarState.Off），宽度与颜色也取目标默认。ArkUI Scroll 把 scrollBar 从 BarState.On 切到 Auto（或切 Off 后不久再切 Auto）时会重新显示滚动条，按 Auto 的淡出节奏再停约 1.3–2s（HarmonyOS 6.1.0 Scroll 截屏取样：On→Auto 约 3s 才消失，只切 Off 立即消失），到时直接切 Auto 会让进页滚动条停留过久。唤醒延迟取自主题的 scrollbarDefaultDelayBeforeFade：Material 系主题在 themes_material.xml 改写为 400，唤醒约 1600ms，参照取样未能区分 1200 与 1600ms，按源主题值取并在报告注明。

## 做法

1. 先按源端参照设备的系统版本定效果类型：源端越界效果随运行设备系统版本，不随 targetSdk——API 31 起为拉伸（目标取 EdgeEffect.Spring），API 30 及以下为辉光（目标取 EdgeEffect.Fade），两种都配 { alwaysEnabled: false } 对应 IF_CONTENT_SCROLLS；参照设备版本不明时取 Spring，并在报告里写明按 API 31+ 处理；本步下文写 Spring 处都按这一分支取（Compose 的默认越界效果同样随设备版本）。源未写 overScrollMode 或写 ifContentScrolls：.edgeEffect(EdgeEffect.Spring, { alwaysEnabled: false })；always：alwaysEnabled: true；never：EdgeEffect.None。对话框内的 Scroll 同样处理。 GridView/ListView 转 Grid/List 时同样设置（Grid 默认 EdgeEffect.None）。 Compose 的 verticalScroll/horizontalScroll、LazyColumn/LazyRow：先在源工程检索 LocalOverscrollFactory、LocalOverscrollConfiguration 与 overscrollEffect 参数，没有置空就同样写 Spring + alwaysEnabled: false；规格没写边缘效果不是保留 None 的理由。第 2 步的滚动条规则针对 View 体系的默认滚动条，Compose 源端按源码是否显式绘制滚动条决定。
2. 源端视图默认带滚动条且内容可滚动时显式设置滚动条（ScrollView、HorizontalScrollView、ListView、GridView 的默认样式带滚动条；NestedScrollView 没写 android:scrollbars 时没有滚动条，目标写 BarState.Off；写了 android:fadeScrollbars=false 时滚动条常显，目标写 BarState.On）：进页用 BarState.On 显示源端唤醒时长（约 1200ms，见原因）后切到 BarState.Off 立即收起，不直接切 Auto；在 onTouch 的 TouchType.Down 且当前为 Off 时再切 BarState.Auto，滚动时由 Auto 显示（Grid/List 用同一切换）。scrollBarWidth 与 scrollBarColor 按源主题对应滚动方向的 scrollbarThumbHorizontal/Vertical 滑块取值：宽取滑块可见部分的宽（滑块图有固有宽度时源端按图宽画，没有才用 scrollbarSize），色取滑块颜色。Holo 在 SDK values/themes_holo.xml，滑块是 10dp 槽宽的 9-patch、可见约 2–4dp，暗色取宽 4、色 '#7B808080'；Material 系在 themes_material.xml，滑块无固有宽度，宽取 scrollbarSize 4dp，色按 tint 算合成色：tint 为 colorControlNormal，浅色主题下源设备 API≤32 为黑×0.54（合成约 #47000000）、API≥33 为黑×0.60（合成约 #4F000000）（Material3 主题的 colorControlNormal 是不透明的 #49454F，合成约 #8449454F，不随 API 变），源主题不是示例中的主题时同样去对应 themes_*.xml 查，查不到在报告里登记缺口，不静默沿用目标默认。是否会滚动按参照机行高×行数判断。

- 〔标题 / 适用情境 / 做法第 1 步〕View 构造时 setOverScrollMode(OVER_SCROLL_IF_CONTENT_SCROLLS)，布局没写 android:overScrollMode 时就是这个值：ScrollView、HorizontalScrollView 只在内容超出视图（range>0）时允许越界，AbsListView（ListView、GridView）在内容放不下时允许越界；OVER_SCROLL_ALWAYS 只要视图能滚动就允许，OVER_SCROLL_NEVER 不允许
- 〔适用情境〕android-36.1 源码里 EdgeEffect 构造时按变更开关 USE_STRETCH_EDGE_EFFECT_BY_DEFAULT（@EnabledSince targetSdkVersion = BASE，对所有 targetSdk 开启）取拉伸型，应用没有另设时越界为拉伸；AOSP android12-release 的 EdgeEffect 已是同样的写法，android11-release 的 EdgeEffect 没有拉伸代码，只画辉光；与拉伸配套的 EdgeEffect(Context, AttributeSet)、getDistance、onPullDistance 自 API 31 起提供。即设备 API 31 起为拉伸，API 30 及以下为辉光。API 31 起另有两个分支：系统动画被关（ValueAnimator.areAnimatorsEnabled() 为 false，如动画时长缩放设为 0）时不显示任何越界效果；拉伸只在硬件加速绘制（RecordingCanvas）时生效，软件绘制时不显示越界效果
- 〔适用情境 / 做法第 1 步〕androidx.compose.foundation 1.12.0 中，Modifier.verticalScroll/horizontalScroll 不带 overscrollEffect 参数的重载走 scrollableArea 的 useLocalOverscrollFactory 分支，从 LocalOverscrollFactory 取越界效果；LazyColumn 等的 overscrollEffect 参数没传时取 rememberOverscrollEffect()，同样来自 LocalOverscrollFactory；LocalOverscrollFactory 没有另设时用 defaultOverscrollFactory：LocalOverscrollConfiguration 为 null 时返回 null（无越界效果），否则建平台效果，设备 API 31 起为平台 EdgeEffect（拉伸），以下为辉光；LocalOverscrollConfiguration 的默认值是 OverscrollConfiguration()，不为 null，应用没经它或 LocalOverscrollFactory 置空时就有平台越界效果（foundation-android 1.10.3、1.11.4 的 defaultOverscrollFactory 同样按 LocalOverscrollConfiguration 是否为 null 分支）
- 〔标题 / 适用情境 / 做法第 1 步〕ArkUI 不写 edgeEffect 时：Scroll 为 EdgeEffect.None，options 默认 { alwaysEnabled: true }（只写 Spring 时内容不满一屏也回弹）；List 为 EdgeEffect.Spring、{ alwaysEnabled: false }；Grid、WaterFlow 为 EdgeEffect.None、{ alwaysEnabled: false }
- 〔做法第 1 步〕EdgeEffectOptions.alwaysEnabled 决定组件内容小于组件自身时是否开启滑动效果（API 11 起）；EdgeEffect 取值 Spring 为弹性回弹，Fade 为圆弧阴影，None 为无效果
- 〔何时使用 / 做法第 1 步〕HarmonyOS 6.1.0 设备上，bindSheet(height: SheetSize.FIT_CONTENT) 半模态里的内容区 Scroll{Column}，内容超过弹层上限时，edgeEffect 为默认 None 的 Scroll 拖不动；同样的控件树写 .edgeEffect(EdgeEffect.Spring, { alwaysEnabled: false }) 时可以滚到最后一项（竖屏、横屏各见一例）
- 〔原因 / 做法第 2 步〕View 在窗口变为可见（onWindowVisibilityChanged 收到 VISIBLE）或聚合可见性变为可见时调 initialAwakenScrollBars，以 scrollBarDefaultDelayBeforeFade×4 唤醒滚动条，到时按 scrollBarFadeDuration 淡出；视图和主题都没设 scrollbarDefaultDelayBeforeFade 时取 ViewConfiguration 的 300ms（唤醒约 1200ms），淡出时长没设时为 250ms；内容不超出（range ≤ extent）时不画滑块
- 〔原因 / 做法第 2 步〕视图没写 android:scrollbarDefaultDelayBeforeFade 时取主题值：平台 Theme.Material、Theme.Material.Light 为 400（唤醒约 1600ms），Theme.Holo 系和 Theme 为 300（约 1200ms），三者 scrollbarFadeDuration 都是 250
- 〔原因 / 做法第 2 步〕androidx.appcompat 1.7.1 的 Theme.AppCompat、Theme.AppCompat.Light 在 API 21 起的设备上父主题为 android:Theme.Material.NoActionBar、android:Theme.Material.Light.NoActionBar（API 20 及以下为 Theme.Holo、Theme.Holo.Light），appcompat 1.1.0–1.8.0 相同；appcompat 1.1.0–1.8.0 与 material 1.4.0–1.14.0 包内都没有改写 scrollbar 开头的主题项，滚动条唤醒延迟、宽度和滑块图取父平台主题的值；滑块图的着色取 colorControlNormal，Material3 主题下它和平台不同（见 colorControlNormal 一条）
- 〔原因 / 做法第 2 步〕HarmonyOS 6.1.0 的 Scroll：scrollBar 从 BarState.On 切到 BarState.Auto，或切到 Off 后约 50ms 再切 Auto，滚动条都会重新显示，进页约 3s 才消失；只切到 Off 时滚动条立即消失。日志确认 On 在进页时设置、1.2s 时切换准时
- 〔原因 / 做法第 2 步〕BarState.Off 不显示，Auto 按需显示（触摸时显示，2s 后消失），On 常驻显示；Scroll、List、Grid 的 scrollBar 不写时为 BarState.Auto，WaterFlow 为 BarState.Off；容器无法滚动时滚动条不显示；Grid 的默认值在 API 9 及以下为 Off、API 10 起为 Auto
- 〔做法第 2 步〕onTouch(event: (event: TouchEvent) => void) 在触摸事件触发时回调，TouchType.Down 表示手指按下
- 〔做法第 2 步〕Scroll、Grid 等的 scrollBarWidth 不写时为 4，单位 vp；scrollBarColor 不写时为 '#182431'（40% 不透明度），API 22 起另有接受 Resource 的重载；Grid 的滚动条宽度超过主轴可视尺寸时按 4vp
- 〔做法第 2 步〕平台默认样式里 Widget.ScrollView 设 scrollbars=vertical，Widget.HorizontalScrollView 设 horizontal，Widget.AbsListView（ListView、GridView 样式的父样式）设 vertical，Material、Holo 的同名样式继承它们；View 只在 android:scrollbars 解析为非 none 时初始化滚动条，布局和样式都没写时没有滚动条
- 〔做法第 2 步〕androidx.core 的 NestedScrollView 两参构造：1.6.0 起（核过 1.6.0、1.9.0、1.17.0、1.19.0）以 nestedScrollViewStyle 为默认样式属性，1.5.0 传 0（没有默认样式属性）；appcompat 1.1.0–1.8.0、material 1.4.0–1.14.0 的主题都没设 nestedScrollViewStyle，所以布局没写 android:scrollbars 时 NestedScrollView 没有滚动条
- 〔做法第 2 步〕android:fadeScrollbars 为 false 时滚动条状态置为常显，没写时为 true（唤醒后淡出）
- 〔做法第 2 步〕源端竖向滚动条的绘制宽度取 ScrollBarDrawable.getSize：有轨道图取轨道图固有宽，没有取滑块图固有宽，都不大于 0 时用 scrollbarSize；视图和主题都没设 scrollbarSize 时取 ViewConfiguration 的 4dp 换算值
- 〔做法第 2 步〕平台 Theme.Material、Theme.Material.Light 下，应用没有另设滚动条属性时：scrollbarSize 为 @dimen/config_scrollbarSize（4dp），竖向滑块为 config_scrollbarThumbVertical（指向 scrollbar_handle_material），横向滑块为 scrollbar_handle_material，两个方向的轨道都是 @null；scrollbar_handle_material 是不带尺寸的矩形 shape，solid #84ffffff，tint 为 ?attr/colorControlNormal
- 〔做法第 2 步〕Theme.Material、Theme.Material.Light 的 colorControlNormal 为 ?attr/textColorSecondary，即 color/text_color_secondary：colorForeground（浅色为黑、暗色为白）乘 secondaryContentAlpha；浅色的 secondary_content_alpha_material_light 在 android-30、AOSP android12-release 和 android12L-release 为 0.54，android-33（AOSP android13-release）起为 0.60，暗色为 0.7；ColorStateList 按 (int)(255×alpha+0.5) 取整，0.54 得 0x8A，0.60 得 0x99，0.7 得 0xB3。库主题的覆写：AppCompat、MaterialComponents 的浅色和暗色主题在 API 21 起把 android:colorControlNormal 指向 ?android:attr/textColorSecondary，取平台的这个值（与上同）；Material3 主题（material 1.8.0–1.14.0）把 android:textColorSecondary 改成 m3_default_color_secondary_text，colorControlNormal 浅色为不透明的 #FF49454F、暗色 #FFCAC4D0，不随 API 级别变（动态取色另算）
- 〔做法第 2 步〕drawable 的 android:tint 没写 tintMode 时按 SRC_IN 混合：结果取 tint 的 RGB，alpha 为 tint alpha×原 alpha；#84ffffff 经黑×0.54（0x8A）着色约为 #47000000，经黑×0.60（0x99）约为 #4F000000，平台暗色主题经白×0.7（0xB3）约为 #5DFFFFFF；Material3 主题的 colorControlNormal 不透明，着色后浅色约为 #8449454F、暗色约为 #84CAC4D0
- 〔做法第 2 步〕Theme.Material.Light 系主题下、没改滚动条属性的 HorizontalScrollView，卡里量得滚动条颜色约 #47000000，与按平台资源（#84ffffff 经 colorControlNormal 黑×0.54 着色）算出的合成色相同
- 〔做法第 2 步〕平台 Theme.Holo 下，应用没有另设滚动条属性时：scrollbarSize 为 10dip，滑块为 scrollbar_handle_holo_dark（Theme.Holo.Light 为 scrollbar_handle_holo_light），轨道 @null；两张滑块图都是 9-patch，内容宽 10dp（mdpi 10px、xhdpi 20px、xxhdpi 30px）。常见手机（xxhdpi）命中的那份：scrollbar_handle_holo_dark 中间 8px（约 2.7dp）为 #80808080，两侧各 1px #33CCCCCC、再外 1px 近乎透明，可见部分约 3.3dp；scrollbar_handle_holo_light 中间 8px 为 #99808080，两侧各 1px #7A777777。xhdpi 那份 holo_dark 中间 4px（2dp）#80808080、两侧 #59969696、#1ACCCCCC，holo_light 中间 4px #99808080、两侧 #897C7C7C、#3E777777；mdpi 那份 holo_dark 中间 2px #80808080、两侧 #3C969696；另有 hdpi 一份
- 〔原因 / 做法第 2 步〕Holo 暗色主题、没改 listSelector、scrollbars、overScrollMode 的 GridView，在安卓参照机（Android 12 以上）录屏上：进页滚动条先亮约 1.2s 再淡出，越界为拉伸；卡里从录屏取得的滚动条颜色为 #7B808080（与 9-patch 中心像素 #80808080 相近）
