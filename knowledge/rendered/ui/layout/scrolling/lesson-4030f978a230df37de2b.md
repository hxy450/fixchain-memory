# LazyRow/LazyColumn 的 contentPadding 译为 contentStartOffset/contentEndOffset，不用 List.padding

## 何时使用

界面实现阶段为滚动列表确定首尾留白时；规格提取阶段描述 Lazy 列表留白时

## 适用情境

源 LazyRow/LazyColumn 用 contentPadding 在滚动方向上给首尾项留白（LazyRow 是 PaddingValues 的 start/end，LazyColumn 是 top/bottom）；contentStartOffset/contentEndOffset 各只有一个沿滚动方向的数，交叉轴方向的留白（LazyRow 的 top/bottom、LazyColumn 的 start/end）不在这条的范围内；目标 ArkUI List 可写 .padding，也可写 contentStartOffset/contentEndOffset；映射参考只有通用的 padding → .padding()。

## 原因

contentPadding 只偏移内容、视口不变，项可以滚进留白区；List.padding 缩小视口，项滚到内距处被裁切。两者静止时一样，差异只在滚动时出现，容易被当作“差异小”而降级。

## 做法

1. contentPadding 的首尾值写成 .contentStartOffset/.contentEndOffset；只有源码是 Modifier.padding 时才写 List.padding。
2. 规格里写“内容内距（滚动时不裁切）”，不只写“左右 padding”。

## 可选检查

- 有疑问时检索列表上的 padding，逐处对照源码是 contentPadding 还是 Modifier.padding。

- 〔做法第 1 步〕List 的 contentStartOffset / contentEndOffset 是列表滚动到起始（末尾）位置时内容与显示区域边界保留的距离：不写时为 0，单位 vp，设负数按 0 处理；两者之和超过 List 内容区长度时都被置 0
- 〔原因〕List 组件通用属性 clip 的默认值为 true，超出 List 区域的内容被裁剪
- 〔原因〕设备上 List 写 padding 时列表显示区随之缩小，滚动中的列表项在内距边界处被裁切；静止时和 contentPadding 的效果看不出差别
