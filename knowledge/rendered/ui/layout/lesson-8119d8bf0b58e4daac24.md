# 视觉修复以源布局与源码分支为准：截图尺寸差先折算成 vp 对照，容器尺寸与自绘组件的绘制尺寸同源修改，截图里缺少的入口先查渠道与开关分支，截图里的元素先对应到所属组件，文档截图与 @Preview 示例不当应用真值

## 何时使用

视觉校验与修复阶段，根据截图差异撰写工单，决定修改固定尺寸、列数、背景，删减截图中没有出现的入口与区块，或按基线截图选定空态等文案与图标时；按差异单调整包裹自绘组件（Canvas 日历等）的容器高度与折叠范围时；按参考截图补齐无数据空态、决定截图中某段文案归属哪个组件时

## 适用情境

依据截图或视觉差异单修改页面尺寸、可见入口、文案或图标；基线可能跨设备密度、渠道或运行状态，也可能来自docs/assets或@Preview。页面含Canvas自绘组件时，外层高度、clip和折叠范围还可能依赖绘制端的行高等尺寸。 也包括按参考截图为无数据状态补边框、图例与“暂无数据”类文案：页面由图表 Canvas 与相邻侧栏列表等并列组件组成，截图里的文案在源图表代码中没有绘制逻辑。

## 原因

截图差异同时受密度、视口与运行条件影响，不直接证明源布局尺寸有误；仅凭观感缩放常量会累积高度偏差。渠道、开关和运行状态决定某时刻的可见入口、列数与背景，文档或@Preview又可能使用示例内容；把单张截图当成全部行为会误删或写死已正确的实现。自绘组件的外层高度、裁剪与折叠范围若独立于实际绘制尺寸修改，还会产生截断和遮挡。另一应用中实现者已从页面布局读到图表右侧是成交明细列表，也查到源图表库对该文案只赋值不绘制，仍为“与截图一致”在正在修改的分时副图里补画“暂无数据”，用户随后指出它属于相邻列表。

## 做法

1. 写尺寸工单前，按两端设备各自的密度/逻辑宽度把截图差异折算成 vp，与源布局 dp 值、目标代码当前值三方对照；目标值已等于源值时，改查视口、安全区或容器层级，不写“对齐固定高度”，源码定位不能留空。
2. 拟改值偏离源布局值时，要有源码或资源固有尺寸依据，不用放大常量补偿截图比例。
3. 放大元素前累计所有固定高度与 margin，确认底部内容仍位于 Tab 之上。
4. 截图中缺少而源码布局存在、且有点击逻辑的 tab、入口或区块，先在 Fragment/Activity 中搜索其 setVisibility、getChannel、会员或开关分支，确认是运行变体还是已下线；属于变体时按忠实复刻保留完整入口或实现同等条件开关，并请用户确认截图所属渠道，不按单张截图删减。
5. 截图只代表某一时刻与状态：列数与区块数以 Adapter 实际绑定的数据项为准，背景以源码的状态选择逻辑为准，尺寸以源布局为准；读取出现截断就按单个文件重读后再下删改结论。
6. docs/assets 截图与 @Preview 中的示例文案、图标不是应用真值：选定字符串 key 或图标前，搜索它在应用代码中的真实引用；与页面实际调用链读到的不一致时以调用链为准。
7. 差异涉及自绘组件时，先定位实际绘制尺寸的来源（如 Canvas 的行高常量）；外层容器高度、clip 范围与折叠距离引用同一常量同步修改，不单独压缩外层容器。源端与目标值已一致时，回头复核差异单的成因。
8. 按截图补空态或提示时，先依据页面布局区域把截图中每个元素对应到具体组件，不默认归入正在修改的组件；源绘制代码中找不到它的绘制逻辑（只赋值、未被消费）时，转查相邻组件的空态实现；仍无法确认就只实现用户文字明确列出的元素，并向用户确认文案位置，不在 Canvas 里自行补画。

## 可选检查

- 改动带 clip 的自绘容器后，用行数不同的数据（如 5 行、6 行月份）及折叠中间态截图，核对末行完整、相邻面板不遮挡。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码；android-37.0 的平台资源。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 7 步〕clip 没有设置时不裁剪子组件超出本组件范围的部分；设为 true 后，子组件超出本组件范围的区域也不响应绑定的手势
- 〔做法第 2 步〕安卓属性取值按先后：控件 AttributeSet 里直接写的值 → AttributeSet 里 style 指定的样式 → defStyleAttr、defStyleRes → 主题，排在前面的优先
- 〔做法第 1 步〕Text 的 fontSize 传 number 时单位是 fp，不设时为 16fp（Wearable 设备上 15fp）
- 〔做法第 1、2 步〕鸿蒙 float 资源写在 float.json 里，每项的数值和单位只在 value 里（如 "28.0fp"），资源名不代表数值
- 〔做法第 1、2 步〕安卓 DENSITY_MEDIUM（即 DENSITY_DEFAULT）是 160、DENSITY_XHIGH 是 320、DENSITY_XXHIGH 是 480；dp = px × 160 / dpi，同一 dp 在不同密度设备上截图像素不同
- 〔做法第 2 步〕ImageFit.Fill 不保持宽高比缩放，使图片填满显示边界
- 〔做法第 2 步〕安卓 ImageView 的 scaleType 取值 fitXY = 1，X、Y 各自缩放填满
- 〔做法第 8 步〕if、else if 的条件可以用状态变量或常规变量：状态变量的值改变时实时重新渲染，常规变量的值改变不会
