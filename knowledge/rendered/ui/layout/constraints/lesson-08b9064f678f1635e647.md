# 源端默认起始对齐和贴顶要显式写出：Android 与 Compose 的纵向容器默认贴起始边、Compose Row 默认贴顶，ArkUI Column/Row 交叉轴默认居中，Scroll 内不满一屏的内容默认居中

## 何时使用

界面实现阶段，把纵向 LinearLayout、带 constraintStart/Top 的 ConstraintLayout 或 ScrollView/NestedScrollView 转成 ArkUI Column 与 Scroll 时；以及把 Compose Column 中的文本块转成 ArkUI Column 子项时；把未写 verticalAlignment 的 Compose Row 转成 ArkUI Row 时；把 Compose LazyColumn 等从顶部排列的纵向列表落成 Scroll 包裹 Column 时

## 适用情境

源纵向 LinearLayout 没写 gravity（子项默认贴起始边），或 wrap_content 子项以 constraintStart_toStartOf=parent 靠起始边、卡片以 constraintTop_toTopOf=parent 贴顶；目标 Column 宽度撑满，子项为固定或内容宽度；滚动页内容常不满一屏。或显示卡片用 layoutWeight 分高，源端卡内内容 wrap_content 自上而下排列并带上内边距。也包括 Compose Column 未声明 horizontalAlignment（默认 Start），文本只带水平 padding 而无 fillMaxWidth，仅个别项以 fillMaxWidth + TextAlign.Center 居中。也包括 Compose Row 未写 verticalAlignment（默认 Top），子项高度不等。 也包括源端 LazyColumn(fillMaxSize)/RecyclerView 的条目从顶部排列，目标写成 Scroll { Column { ForEach } }.layoutWeight(1)，条目可能不足一屏。也包括 Stack 中应贴顶的块未设 alignContent（默认 Center），或修复缩短头部、内容后 Scroll 子项矮于视口。也包括列表页空态：空态容器是 wrap_content 的滚动容器、在父 RelativeLayout 中未声明居中，内层 LinearLayout 写 gravity=center；工程已有全高居中的空态 Builder 可以照搬。

## 原因

ArkUI Column 的交叉轴默认是 Center，把源端“没写 gravity”照搬成“不写 alignItems”，返回键、标题、列表行就会被居中；父 Stack 的 alignContent 只放置 Column 本身，不影响其子项。Scroll 对不满一屏的内容也会纵向居中，而 NestedScrollView 是顶锚。来源中写者在源端本来居中的空态上显式写了 Center，却在源端默认对齐处什么都没写。另一应用计算器显示区源端自上而下排列（上内边距 18dp），生成者写成 justifyContent(FlexAlign.End)，数值落到显示卡片底部。另一应用中，添加城市页的内容 Column 未写 alignItems(Start)，分组标题被居中，而写者写前已读到陷阱表中对齐需显式设置的条目。另一应用的 Compose 页面中，转换者读到标题、价格、正文都只带水平 padding，写进未设 alignItems 的 Column 后整体居中；给内容宽的 Text 加 textAlign(Start) 也无效，因为 textAlign 只作用于 Text 自身框内。Compose Row 的默认纵向对齐同样是 Top，ArkUI Row 默认 Center。 另一应用的购物车把 LazyColumn 写成 Scroll 包裹未定高的 Column，商品少时整块居中；后来按源端重排卡片也没动外层对齐，最终靠 Scroll.align(Alignment.TopStart) 修正，给未定高的 Column 加 justifyContent 不起作用。

## 做法

1. 源端默认起始对齐时（Android 纵向 LinearLayout 未写 gravity、Compose Column 未写 horizontalAlignment），对应 Column 显式写 alignItems(HorizontalAlign.Start)，或给子项 alignSelf，或给文本 width('100%') + textAlign(TextAlign.Start)（文本另带左右 margin 时宽度写 calc(100% - 左右 margin 之和)，百分比宽度不扣自身 margin）；只有源端写了 center/center_horizontal、ConstraintLayout 子项 start 与 end 都约束到 parent（bias 默认 0.5），或 fillMaxWidth + TextAlign.Center 的项才居中。内容宽的 Text 只加 textAlign 不会改变它在父容器中的位置。
2. 写完用一条命令把本页的 Column( 和 Row( 连同紧跟的 alignItems、justifyContent 列出来（例如 grep -n -E 'Column\(|Row\(|alignItems|justifyContent' 文件），只看没有显式写对齐的撑满宽 Column：它里面固定尺寸或内容宽子项的水平位置由谁决定。
3. ScrollView/NestedScrollView 或纵向 Lazy 列表转成 Scroll 时，源内容贴顶就给 Scroll 写 .align(Alignment.Top)（或 TopStart），或给子容器加 constraintSize({ minHeight: '100%' }) 一类约束使其顶锚，并确认超出一屏后仍能滚动；源端是可变长度的条目列表时优先映射为 List，条目默认从顶部排列。给未定高的 Column 写 justifyContent 不改变它在 Scroll 中的位置；按源端重排列表卡片时一并核对外层滚动容器的对齐。
4. 容器被 layoutWeight 撑高而源端内容贴顶时，写 justifyContent(FlexAlign.Start) 并沿用源端上内边距，不改成底对齐。
5. Compose Row 未写 verticalAlignment 时，ArkUI Row 显式写 alignItems(VerticalAlign.Top)；上一条命令列出的、没有显式写对齐的 Row，对照源码的构造参数补上。
6. Stack 中应贴顶的块设 alignContent(Alignment.Top) 或 position；内容恰好高于视口时 Scroll 的默认居中被掩盖，修复中缩短了头部或内容高度后，复查 Scroll 子项是否仍贴顶。
7. 空态按本页源布局定纵向位置：wrap_content 且未在父容器中居中的空态容器靠上放并保留源边距，内层 gravity=center 只排列包裹高度内的子项，不等于在整个内容区居中；参照已有空态 Builder 时只复用样式骨架。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码；android-36 的平台资源；androidx.constraintlayout:constraintlayout 2.2.1；androidx.compose.foundation:foundation-layout-android 1.10.3、1.12.0；androidx.compose.foundation:foundation-android 1.10.3；androidx.core:core 1.16.0。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 做法第 1 步〕安卓 LinearLayout 没写 android:gravity 时 mGravity 为 Gravity.START | Gravity.TOP；纵向排布时子项没写 layout_gravity 就取容器 gravity 的水平部分，落到 childLeft = paddingLeft + leftMargin 的分支，贴起始边（RTL 时起始边在右），子项从 paddingTop 处依次往下排
- 〔适用情境 / 做法第 7 步〕android:gravity 的属性说明是控制对象在自身边界内摆放内容；容器写 gravity="center" 只在它自己的范围内（wrap_content 时即包裹高度内）居中子项，不决定它在父布局里的位置
- 〔做法第 1 步〕ConstraintLayout 子项 start、end 都约束到 parent 时按 layout_constraintHorizontal_bias 摆位，应用没写 bias 时 LayoutParams 的 horizontalBias（以及 verticalBias）为 0.5，即居中（constraintlayout 2.2.1、2.2.2 相同）
- 〔适用情境 / 做法第 1、5 步〕Compose 的 Column 没传参数时 verticalArrangement 为 Arrangement.Top、horizontalAlignment 为 Alignment.Start；Row 没传时 horizontalArrangement 为 Arrangement.Start、verticalAlignment 为 Alignment.Top（foundation-layout 1.10.3、1.12.0 相同）
- 〔适用情境 / 做法第 3 步〕Compose 的 LazyColumn 没传 verticalArrangement 时，reverseLayout 为 false 用 Arrangement.Top，为 true 用 Arrangement.Bottom（foundation-android 1.10.3、1.12.0 相同）
- 〔原因 / 做法第 3 步〕安卓 ScrollView 和 androidx 的 NestedScrollView 都继承 FrameLayout；FrameLayout 子项没写 layout_gravity 时按 DEFAULT_CHILD_GRAVITY = Gravity.TOP | Gravity.START 摆，内容矮于视口时贴顶
- 〔适用情境 / 做法第 7 步〕安卓 RelativeLayout 子项没写纵向定位规则（layout_below、alignParentBottom、centerVertical、centerInParent 等都没写）时，top = 父布局 paddingTop + 子项 marginTop，贴父布局顶部；这是父 RelativeLayout 没写 android:gravity（默认 START|TOP）时的结果，父写了 gravity 的纵向部分（center_vertical、bottom 等）时，没被 ignoreGravity 排除的子项整体按它在父布局内偏移
- 〔标题 / 原因 / 做法第 1 步〕Column.alignItems(value: HorizontalAlign) 不写时为 HorizontalAlign.Center，只排这一层的直接子项；HorizontalAlign.Start 按语言方向的起始端对齐
- 〔原因 / 做法第 1 步〕设备上 Column 没写 alignItems 时，内容宽的子项（图标、标题、正文）在 Column 内水平居中，同类卡片文本长短不一时各卡文字起点随文本宽度变化
- 〔做法第 1 步〕alignSelf(value: ItemAlign) 设子组件在父容器交叉轴上的对齐，覆盖父 Column、Row、Flex 的 alignItems；不写时为 ItemAlign.Auto，继承父容器的设置
- 〔原因 / 做法第 1 步〕Text.textAlign 不写时为 TextAlign.Start（Wearable 设备上为 Center）；文本段落宽度占满 Text 组件自身的宽度，textAlign 只在这个框内排文字，Text 是内容宽时改 textAlign 不改变它在父容器里的位置
- 〔做法第 1 步〕width 设百分比时以父容器宽度为基础，不扣除组件自身的 margin；在 Column 交叉轴上子组件占用的宽度是自身宽度加左右 margin，所以 width('100%') 再带左右 margin 会超出父容器；width 自 API 10 起支持 calc，运算符与数值之间要有空格
- 〔做法第 3、4 步〕Column.justifyContent(value: FlexAlign) 不写时为 FlexAlign.Start（首端对齐，后续依次排）；它排的是子项在 Column 自身高度内的纵向位置，不决定 Column 在父容器里的位置
- 〔做法第 4 步〕父容器尺寸确定时，设了 layoutWeight 的子组件从主轴剩余空间按权重分得尺寸，分配时忽略它自己的 width/height，保留 minWidth/minHeight 约束
- 〔标题 / 原因 / 做法第 5 步〕Row.alignItems(value: VerticalAlign) 不写时为 VerticalAlign.Center，Row.justifyContent 不写时为 FlexAlign.Start；VerticalAlign.Top 为顶部对齐
- 〔标题 / 原因 / 做法第 3 步〕通用属性 align(value: Alignment) 设当前组件绘制区域内子组件的对齐，只在 Scroll、Stack、Text、Button 等列明的组件上生效，不写时为 Alignment.Center；所以 Scroll 的子组件矮于视口时被居中；写在 Column 这类不在列表里的组件上不起作用，也不移动写它的组件本身
- 〔原因 / 做法第 3 步〕Scroll 只支持单个子组件；主轴方向内容尺寸大于 Scroll 自身时才能滚动
- 〔做法第 3 步〕constraintSize(value: ConstraintSizeOptions) 限定组件布局时的尺寸范围，不写时为 {minWidth: 0, maxWidth: Infinity, minHeight: 0, maxHeight: Infinity}，优先级高于 width、height；ConstraintSizeOptions.minHeight 是 Length，可写百分比；只设 minHeight 时 height = MAX(minHeight, height)，内容更高时照常变高
- 〔原因 / 做法第 3 步〕设备上 Scroll 不设 align、子 Column 只设宽度且内容矮于视口时，整块内容在 Scroll 里垂直居中；子 Column 设了 constraintSize({ minHeight: '100%' }) 时，它至少与 Scroll 视口等高，首块从视口顶部排起
- 〔做法第 3 步〕List.stackFromEnd 不写时为 false，List 从顶部开始布局；设为 true 时内容小于 List 高度则底部对齐（API 19 起）
- 〔原因 / 适用情境 / 做法第 6 步〕Stack 的 alignContent 不写时为 Alignment.Center，是所有子组件在容器内的对齐方式，只放置子组件本身；属性写法 alignContent(value: Alignment) 与构造参数同时设时以属性为准，与 align 同时设时后设的覆盖先设的
- 〔做法第 6 步〕layoutGravity(alignment: LocalizedAlignment)（API 20 起）单独设 Stack 里某个子组件的对齐，只在父组件为 Stack 时生效，和 align 同时用时 layoutGravity 优先
- 〔做法第 6 步〕position(value: Position | Edges | LocalizedEdges)：Edges（API 12 起）按组件各边到父组件内容区对应边的距离定位；父组件为 Row、Column、Flex 时，设了 position 的子组件不占位
