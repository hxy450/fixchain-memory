# 导航图标与菜单分区按实际生效者实现：DrawerToggle 画汉堡、parentActivityName 默认 Up，showAsAction 按名额宽度分流

## 何时使用

界面实现阶段，转换工具栏菜单 XML、自绘 ActionBar 或标题栏，决定导航图标（返回箭头或汉堡）、图标位与溢出菜单时；自绘框架主题提供的 ActionBar（应用图标、Up 尖角、溢出按钮、横竖屏高度与标题字号）时；同一菜单复用到自绘多选 CAB（ActionMode）时

## 适用情境

源菜单项带图标与 showAsAction=ifRoom/always，或带 checkable=true。也包括 Activity 基于 AppCompat、菜单 XML 写的是 android:showAsAction（常带 tools:ignore="AppCompatResource"）。也包括判断导航图标的输入：Manifest 是否为 Activity 声明 parentActivityName 或 PARENT_ACTIVITY meta-data、代码是否调用 setDisplayHomeAsUpEnabled、基类 onPostCreate 是否以同一 Toolbar 构造 ActionBarDrawerToggle 并 syncState；目标套用自带返回箭头的标题栏模板、兄弟页标题栏，或保留自定义 Up 标题栏。也包括框架 ActionBar（Theme.Holo 等）带 manifest android:icon、setDisplayHomeAsUpEnabled 与 showAsAction="ifRoom|withText"，目标多个页面各自用 hideTitleBar 自绘标题栏。 也包括同一菜单 XML 在多选 CAB（ActionMode）里复用，部分项未声明 showAsAction；目标自绘工具栏与 CAB 栏，规格只登记了菜单 id 清单与显隐规则。

## 原因

全部放进溢出菜单或只设选中态，会丢掉工具栏图标位与勾选指示；反过来把 ifRoom 项一律上栏，又会在窄屏多出源端放进溢出的图标、挤掉标题——ifRoom 项是否上栏由 ActionMenuPresenter 按按钮名额与宽度预算决定。AppCompat 只读 app: 命名空间的 showAsAction，android:showAsAction 被忽略、所有项进右上 ⋮ 溢出菜单；把这些项做成标题栏图标，会多出源端没有的入口。导航图标同样由实际生效者决定：“只在源端启用 Up 时绘制”只是必要条件——AppCompat 窗口 ActionBar 在 Manifest 有 parentActivityName 时默认启用 Up，不调 setDisplayHomeAsUpEnabled 也显示箭头；基类的 ActionBarDrawerToggle.syncState 又会把同一 Toolbar 的 Up 换成汉堡。把前者读成“没调 setDisplayHomeAsUpEnabled 就不画”，或把后者保留成自定义返回标题栏，都会与源端不同。框架 ActionBar 的 withText 安卓 7.0 起由屏宽（≥480dp）或横屏决定（6.0 及以前由 values-w480dp 的 config_allowActionMenuItemTextWithIcon 控制），高度与标题字号另有 values-land 取值。同一菜单复用到 ActionMode 时，未声明 showAsAction 的项缺省值与选项菜单不同；DrawerToggle 管理的导航图标是按抽屉进度插值的同一绘制，不是两张图标切换。

## 做法

1. 绘制导航图标前按顺序判定：①Activity 或其基类（常见 BaseActivity.onPostCreate）以同一 Toolbar 构造 ActionBarDrawerToggle 并 syncState() 时，导航图标是汉堡、点击开关抽屉，setDisplayHomeAsUpEnabled 不再决定图标，目标装配抽屉基座的汉堡栏；②否则看主题是否带窗口 ActionBar（NoActionBar + 自建 Toolbar 按 setSupportActionBar 之后的调用判断）；③窗口 ActionBar 页在 Manifest 声明 parentActivityName 或 PARENT_ACTIVITY meta-data 时 AppCompat 默认显示 Up，点 Up 走 onOptionsItemSelected 的 android.R.id.home 分支或回父页；④代码显式 setDisplayHomeAsUpEnabled(true/false) 时以它为准；都没有才不画，返回交给系统返回键与手势。复用模板或兄弟页标题栏前先按当前源核对。
2. 按生效的 showAsAction（AppCompat 读 app:showAsAction，框架 ActionBar 读 android:showAsAction）照 ActionMenuPresenter.flagActionItems 分配：always 项必上栏；ifRoom 项按名额与宽度分配——名额取 ActionBarPolicy.getMaxActionButtons（按当前配置 dp：smallestWidth>600，或宽>960 且高>720，或宽>720 且高>960 为 5；宽≥500，或宽>640 且高>480，或宽>480 且高>640 为 4；宽≥360 为 3；否则 2），有 never 项或 always 与 ifRoom 合计超出名额时先给溢出钮扣一个名额，always 先扣；宽度预算为屏宽像素一半减溢出钮宽，按菜单顺序（orderInCategory 小的在前，相同的按 XML 先后）逐项扣按钮宽，扣完后「剩余预算 + 第一个上栏按钮宽」不大于 0 的才退回溢出（可透支不到一个首按钮宽）；未上栏的 ifRoom 项与 never/collapseActionView 项按 orderInCategory 进溢出面板；横竖屏或窗口宽变化后重算。判断信号：同一菜单 always 与 ifRoom 合计 3 个以上，或含无图标的 ifRoom 文字项。checkable 项显式开启 selectIcon 等勾选指示。框架 ActionBar 的 withText 项（安卓 7.0 起；6.0 及以前看 values-w480dp 的 config_allowActionMenuItemTextWithIcon）在 screenWidthDp ≥480、或宽 ≥640 且高 ≥480、或横屏时在图标旁显示 TextAppearance.Holo.Widget.ActionBar.Menu 文字（12sp 粗体全大写；出处：框架 ActionMenuItemView.shouldAllowTextWithIcon 与 styles_holo.xml），竖屏且宽 <480dp 时只显示图标。
3. Activity 基于 AppCompat 而菜单写 android:showAsAction 时，该属性被忽略，全部项进右上 ⋮ 溢出菜单，不转成标题栏图标或 NavDestination 图标菜单。
4. 自绘框架 ActionBar 时多页共用一个标题栏组件，各页只传图标、标题、是否 Up 与动作项（showAsAction、orderInCategory），上栏集合由组件按上一步计算：显示该 Activity 或 application 的 manifest android:icon，Up 尖角与溢出按钮用平台原图（如 ic_ab_back_holo_dark_am、ic_menu_moreoverflow_normal_holo_dark），高度、背景与标题字号取平台样式及 values-land 覆盖值，随窗口尺寸切换。
5. 同一菜单复用于 ActionMode（CAB）时分别填充：未声明 showAsAction 的项在选项菜单缺省 never，在 AppCompat StandaloneActionMode 缺省 ifRoom（MenuBuilder.setDefaultShowAsAction），按各自缺省值再走第 2 步的名额与宽度计算，不复制同一张固定清单。自绘 CAB 覆盖工具栏；窗口为 edge-to-edge 时 AppCompat（1.1.0 至 1.7.x）在 CAB 显示期间给状态栏区绘制 status guard 并盖住工具栏投影，按源 targetSdk、窗口模式与 appcompat 版本核对后实现；源端依赖 appcompat 1.8.0 时不画 status guard。
6. 源端由 ActionBarDrawerToggle 管理导航图标时，图标是 DrawerArrowDrawable：汉堡与返回箭头是同一绘制按 position 插值，position 由 onDrawerSlide 写入抽屉滑动进度（源端调 setDrawerSlideAnimationEnabled(false) 或覆写 onDrawerSlide 时按源端）；setDrawerIndicatorEnabled(false) 改显主题的 homeAsUpIndicator（或 setHomeAsUpIndicator 设的图），点击不再开关抽屉，改走源端 setToolbarNavigationClickListener 设的监听（以 Toolbar 构造时）或 onOptionsItemSelected 的 android.R.id.home 分支（未传 Toolbar 时），syncState() 按抽屉开合重设图标。目标用一个按进度绘制的图标和指示器启用态逐条承接源端这些调用，不用两张图标切透明度，也不以验收描述已覆盖代替缺失的调用。

- 〔做法第 1 步〕框架 Activity：Activity#onCreate 在 ActivityInfo.parentActivityName（清单 android:parentActivityName）不为空时，给窗口 ActionBar（WindowDecorActionBar）调 setDefaultDisplayHomeAsUpEnabled(true)；ActionBar 尚未创建时记下，到 initWindowDecorActionBar 创建时再设。setDefaultDisplayHomeAsUpEnabled 只在 DISPLAY_HOME_AS_UP 还没被设过时生效：ActionBar style 的 displayOptions 已含 homeAsUp，或代码调过 setDisplayHomeAsUpEnabled(true 或 false)、含 DISPLAY_HOME_AS_UP 位的 setDisplayOptions(options)、mask 含该位的 setDisplayOptions(options, mask)，都以那一处为准（不含该位的 setDisplayOptions 不算）
- 〔做法第 1 步〕AppCompat（appcompat 1.1.0、1.8.0 相同）：AppCompatDelegateImpl.onCreate 用 NavUtils.getParentActivityName 取上级——先读 ActivityInfo.parentActivityName，再读 meta-data android.support.PARENT_ACTIVITY；取到时只给窗口 ActionBar（WindowDecorActionBar，initWindowDecorActionBar 里设）默认开启 Up（代码没有另调 setDisplayHomeAsUpEnabled 时）。setSupportActionBar(toolbar) 得到的 ToolbarActionBar 的 setDefaultDisplayHomeAsUpEnabled 是空实现，声明了上级也不会自动显示 Up
- 〔做法第 1 步〕主题带不带 AppCompat 窗口 ActionBar 看库属性 windowActionBar（不带 android: 前缀）：Theme.AppCompat、Theme.AppCompat.Light、Theme.AppCompat.Light.DarkActionBar、Theme.MaterialComponents.Light、Theme.Material3.Light、Theme.Material3.DayNight 经 Base.V7.Theme.AppCompat(.Light) 为 true；Theme.AppCompat.NoActionBar、Theme.MaterialComponents.DayNight.NoActionBar、Theme.Material3.Light.NoActionBar 为 false。这些主题的 android:windowActionBar 都是 false（框架 ActionBar 关掉，由 AppCompat 自己出 ActionBar）。appcompat 1.1.0 与 1.8.0、material 1.4.0 与 1.14.0 取值相同（Material3 主题只在 material 1.14.0 里有）
- 〔做法第 1 步〕点 Up 时产生 id 为 android.R.id.home 的菜单项：框架 Activity#onMenuItemSelected 先调 onOptionsItemSelected、再分给 Fragment，都没处理且 ActionBar 的 displayOptions 含 DISPLAY_HOME_AS_UP 时调 onNavigateUp，按上级 Activity 的 Intent 返回上级并 finish 当前页；AppCompatActivity#onMenuItemSelected 在同样条件下调 onSupportNavigateUp
- 〔做法第 1、6 步〕ActionBarDrawerToggle（appcompat 1.8.0）：syncState() 按 DrawerLayout 起始边抽屉是否打开把进度设成 1 或 0，指示器启用时把导航图标设成它的 DrawerArrowDrawable（并配开 / 关抽屉的无障碍描述）；onOptionsItemSelected 只在菜单项是 android.R.id.home 且指示器启用时开关抽屉并返回 true，否则返回 false；用带 Toolbar 的构造函数时它接管 Toolbar 的导航点击：指示器启用时开关抽屉，未启用时调 setToolbarNavigationClickListener 设的监听（没设就不做事）
- 〔做法第 6 步〕ActionBarDrawerToggle 的图标是一个 DrawerArrowDrawable：onDrawerSlide 在抽屉滑动动画开启（应用没调 setDrawerSlideAnimationEnabled(false) 时即开启）时把 slideOffset 限到 [0,1] 作为进度，setDrawerSlideAnimationEnabled(false) 后滑动中进度恒为 0；onDrawerOpened 设 1、onDrawerClosed 设 0；进度为 1 时开竖直镜像、为 0 时关，再 setProgress(进度)，汉堡到箭头是同一绘制按进度插值。setDrawerIndicatorEnabled(false) 把导航图标换成主题的 homeAsUpIndicator（或 setHomeAsUpIndicator 设的图）
- 〔做法第 6 步〕DrawerArrowDrawable 的默认尺寸（主题 drawerArrowStyle = Widget.AppCompat.DrawerArrowToggle，应用没有另设 drawerArrowStyle 时）：barLength 18dp、thickness 2dp、gapBetweenBars 3dp、arrowHeadLength 8dp、arrowShaftLength 16dp、drawableSize 24dp、spinBars true，appcompat 1.1.0 与 1.8.0 相同；颜色取所在主题上下文的 colorControlNormal：Theme.AppCompat.Light、Theme.MaterialComponents.Light 为 ?android:textColorSecondary（平台 android-30 为 #8a000000，android-33 起 #99000000），Theme.AppCompat（深色）为 #b3ffffff，ActionBar 用 ThemeOverlay.AppCompat.Dark.ActionBar（Theme.AppCompat.Light.DarkActionBar 的 actionBarTheme）时为 #ffffffff，Theme.Material3.Light 为 #ff49454f（material 1.14.0）
- 〔做法第 6 步〕SideBarContainer 的事件只有 onChange(callback: (value: boolean) => void)：侧边栏在显示和隐藏之间切换时回调（showSideBar 值变化、showSideBar 自适应变化、拖分割线触发 autoHide），参数是切换后的显示状态；SideBarContainerAttribute 没有拖动或滑出进度的回调
- 〔原因 / 做法第 2 步〕showAsAction 是位标志：never=0、ifRoom=1、always=2、withText=4、collapseActionView=8（框架 android:showAsAction 与 AppCompat 的 showAsAction 声明相同）。菜单项含 always 位即必须上栏（requiresActionButton），否则含 ifRoom 位即请求上栏（requestsActionButton），所以 ifRoom|withText、ifRoom|collapseActionView 都按 ifRoom 分配；两位都没有的（never、单独的 withText 或 collapseActionView）进溢出
- 〔做法第 2 步〕上栏名额 getMaxActionButtons（框架与 AppCompat 的 ActionBarPolicy 相同，appcompat 1.1.0、1.8.0 一致）按当前 Configuration 的 dp：smallestScreenWidthDp > 600，或宽 > 960 且高 > 720，或宽 > 720 且高 > 960 → 5；宽 ≥ 500，或宽 > 640 且高 > 480，或宽 > 480 且高 > 640 → 4；宽 ≥ 360 → 3；否则 2（宽、高为 screenWidthDp、screenHeightDp，随横竖屏变）
- 〔做法第 2 步〕上栏宽度预算：ActionMenuPresenter#initForMenu 取 getEmbeddedMenuWidthLimit() = DisplayMetrics.widthPixels / 2（像素），要留溢出钮时再减去溢出钮的测量宽。框架总是留溢出钮；AppCompat 的 showsOverflowMenuButton 在 appcompat 1.8.0 恒为 true，1.1.0 在 API 19 起为 true。只有分离式 ActionBar（split action bar）和它的 CAB 才把预算改成整屏宽、严格不透支、名额不限
- 〔做法第 2 步〕ActionMenuPresenter#flagActionItems（框架；appcompat 1.8.0 字节码同样的分支）：先数可见项里 always 项、ifRoom 项，有两者都不是的项或两者合计超过名额时名额先减 1 给溢出钮，再减去 always 项数；然后按菜单顺序逐项：always 项一律上栏并从预算扣按钮宽；ifRoom 项在（剩余名额 > 0 或同 groupId 已有项上栏）且剩余预算 > 0 时测量并扣宽，非严格模式下扣完后「剩余预算 + 第一个上栏按钮宽」> 0 就仍上栏，否则退回溢出；同组有一项因宽度退回时，整组已上栏的项一起退回；每上栏一个 ifRoom 项名额减 1
- 〔做法第 2 步〕菜单顺序：MenuBuilder 按 ordering（类别的序号左移后与 orderInCategory 合成）把项插入列表，orderInCategory 小的在前，相同的按添加（XML 填充）先后；flagActionItems 和溢出面板都按这个顺序
- 〔做法第 2 步〕框架 ActionMenuItemView（安卓 7.0 起；android-30 至 android-36.1 源码相同；6.0 及以前改由 values-w480dp/config.xml 的 config_allowActionMenuItemTextWithIcon 决定）：withText 的文字在 screenWidthDp ≥ 480、或宽 ≥ 640 且高 ≥ 480、或横屏时显示（shouldAllowTextWithIcon，配置变化时重算）；没有图标的项总是显示文字。这几版平台资源里没有 config_allowActionMenuItemTextWithIcon 这项 bool，values-w480dp/bools.xml 里只有 split_action_bar_is_narrow
- 〔做法第 2 步〕框架主题的动作项文字：基础 Theme 的 actionMenuTextAppearance 为 TextAppearance.Holo.Widget.ActionBar.Menu（Theme.Holo 沿用），它的 parent 为 TextAppearance.Holo.Small，textSize 12sp、textStyle bold、textAllCaps = @bool/config_actionMenuItemAllCaps（true）、textColor = ?attr/actionMenuTextColor；android-30 与 android-36.1 相同
- 〔做法第 2 步〕ArkUI MenuItem 的勾选：selected(value: boolean) 设菜单项是否选中，默认 false（API 10 起支持 $$ 双向绑定，API 18 起支持 !!）；selectIcon(value: boolean | ResourceStr | SymbolGlyphModifier) 设选中时的图标，true 显示默认对勾，false 不显示，传 ResourceStr（API 10 起）或 SymbolGlyphModifier（API 12 起）显示指定图标，默认 false——只设 selected 不设 selectIcon 时选中不显示勾。两者都从 API 9 起有
- 〔做法第 3 步〕AppCompat 的 SupportMenuInflater 只读库自己声明的 showAsAction（app: 命名空间，declare-styleable MenuItem 里不带 android: 前缀的那一项），没写时读出 -1、不调 setShowAsAction，沿用菜单的缺省值（选项菜单为 never）；菜单 XML 里的 android:showAsAction 不被它读取（appcompat 1.1.0、1.8.0）
- 〔做法第 3 步〕NavDestination.menus(value: Array<NavigationMenuItem> | CustomBuilder)（API 12 起；带 NavigationMenuOptions 的重载 API 19 起）与 Navigation.menus：用 Array<NavigationMenuItem> 写法时竖屏最多显示 3 个图标、横屏最多 5 个，多余的放进自动生成的「更多」图标；不设时不显示菜单
- 〔做法第 4 步〕框架 Holo 主题的 ActionBar：Theme.Holo 的 actionBarStyle 为 Widget.Holo.ActionBar（background @drawable/ab_transparent_dark_holo，是图不是纯色；titleTextStyle TextAppearance.Holo.Widget.ActionBar.Title，textSize @dimen/action_bar_title_text_size），actionBarSize 为 @dimen/action_bar_default_height；Theme.Holo.Light 换成 Widget.Holo.Light.ActionBar.Solid（背景 ab_solid_light_holo），Theme.Holo.Light.DarkActionBar 换成 Widget.Holo.Light.ActionBar.Solid.Inverse（背景 ab_solid_dark_holo）
- 〔做法第 4 步〕框架 ActionBar 尺寸（android-30 与 android-36.1 相同）：action_bar_default_height 在 values 为 48dip、values-land 为 40dip、values-sw600dp 为 56dip；action_bar_title_text_size 在 values 为 18dp、values-land 为 16dp、values-sw600dp 为 18dp
- 〔做法第 4 步〕框架 Holo 主题的 Up 与溢出图（应用主题、ActionBar style 没有另设 homeAsUpIndicator、actionOverflowButtonStyle 时）：Theme.Holo 的 homeAsUpIndicator 为 @drawable/ic_ab_back_holo_dark（drawable/ 下的 bitmap XML，指向 ic_ab_back_holo_dark_am，autoMirrored）；actionOverflowButtonStyle 为 Widget.Holo.ActionButton.Overflow，src 为 @drawable/ic_menu_moreoverflow_holo_dark（selector，默认项 ic_menu_moreoverflow_normal_holo_dark）；两张 png 在 drawable-mdpi、-hdpi、-xhdpi、-xxhdpi 各有一份。Theme.Holo.Light 换成 ic_ab_back_holo_light 与 Widget.Holo.Light.ActionButton.Overflow（ic_menu_moreoverflow_holo_light），Theme.Holo.Light.DarkActionBar 用回 dark 两项
- 〔做法第 4 步〕框架 ActionBar 显示的图标：Widget.ActionBar 的 displayOptions 为 useLogo|showHome|showTitle，Holo 的 ActionBar style 都沿用，所以显示 logo（设了 android:logo 时）或图标加标题；Widget.Material.ActionBar 只有 showTitle，不显示图标。图标取 Activity 的 android:icon，没设时取 application 的（ComponentInfo#getIconResource，logo 同理），Activity 创建窗口 ActionBar 时设为窗口默认图标
- 〔做法第 5 步〕菜单缺省的 showAsAction：MenuBuilder 默认 SHOW_AS_ACTION_NEVER；ActionMode 的菜单由 setDefaultShowAsAction(SHOW_AS_ACTION_IF_ROOM) 改成 ifRoom——框架的 StandaloneActionMode、WindowDecorActionBar.ActionModeImpl，AppCompat（1.1.0、1.8.0）的 StandaloneActionMode、WindowDecorActionBar$ActionModeImpl 都如此。MenuInflater / SupportMenuInflater 在 XML 没写 showAsAction 时读出 -1、不调 setShowAsAction，项的取值由填进哪种菜单决定
- 〔做法第 5 步〕AppCompat 的 status guard（AppCompatDelegateImpl.updateStatusGuard，CAB 的 ActionBarContextView 显示且窗口有顶部系统窗口 inset 时在状态栏区加一块色块）随版本变：appcompat 1.1.0 用 abc_input_method_navigation_guard（@android:color/black）；1.2.0 至 1.7.1 窗口 SYSTEM_UI_FLAG_LIGHT_STATUS_BAR 置位时用 abc_decor_view_status_guard_light（#ffffffff），否则 abc_decor_view_status_guard（#ff000000）；1.8.0 的类里已没有 status guard 相关代码。框架 DecorView 按同样的浅色状态栏位选 decor_view_status_guard_light / decor_view_status_guard
- 〔做法第 5 步〕edge-to-edge 强制：windowOptOutEdgeToEdgeEnforcement 默认 false（主题没设这一项时）；为 false 时 targetSdk ≥ 35（VANILLA_ICE_CREAM）的应用窗口强制 edge-to-edge（框架不按 inset 适配内容视图、状态栏和导航栏色设为透明）；targetSdk ≥ 36（BAKLAVA）时这个属性被忽略、一律强制
- 〔做法第 2 步〕窗口尺寸变化：Window.on(type: 'windowSizeChange', callback: Callback<Size>)（API 7 起），Size 的 width、height 单位 px；窗口拖动或拖拽缩放后不论大小变没变都会回调。display.on(type: 'add' | 'remove' | 'change', callback: Callback<number>) 的回调参数只是变化的屏幕 id，宽高要另取
- 〔做法第 1 步〕AppCompat Toolbar 的导航按钮与标题：Widget.AppCompat.Toolbar.Button.Navigation 的 android:minWidth 为 56dp（API 21 起取自框架 Widget.Material.Toolbar.Button.Navigation，也是 56dp）；有导航按钮时标题起始缩进 contentInsetStartWithNavigation = abc_action_bar_content_inset_with_nav，values/ 72dp、values-sw600dp-v13 80dp（Widget.Material3.Toolbar 改为 0dp）；ActionBar 高 abc_action_bar_default_height_material 为 56dp（values-land 48dp、values-sw600dp-v13 64dp）。主题的 homeAsUpIndicator 在 values 里是 @drawable/abc_ic_ab_back_material，values-v21 起改为 ?android:attr/homeAsUpIndicator，取框架 Theme.Material 的 @drawable/ic_ab_back_material（appcompat 1.1.0、1.8.0 相同）
