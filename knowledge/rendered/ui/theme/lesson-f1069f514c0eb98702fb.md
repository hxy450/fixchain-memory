# 应用内主题切换不只依赖 setColorMode：命令式取色、系统栏与画布要随主题重解析

## 何时使用

实现阶段，设计应用内深浅色切换，并为系统栏、Canvas、HTML 样式等非 $r 消费点取色时

## 适用情境

源换主题靠 Activity 重建，系统栏背后是随主题变化的页面背景、源端浅色主题下系统栏图标为深色（主题设了 windowLightStatusBar=true）时，第 3 步的 #000000/#FFFFFF 才成立；源端状态栏下是深色底、浅色主题也用白色图标的，按源端各主题实际的图标深浅取值；目标用 ApplicationContext.setColorMode 切换，同时存在 getColorSync 取色、setWindowSystemBarProperties 内容色、Canvas 画笔色与内联 CSS。应用用 setColorMode 设置深浅色时收不到这次切换的 onConfigurationUpdate 回调，第 2、3 步的重解析、重绘与系统栏重设要挂在主题切换处（主题态变化）触发，onConfigurationUpdate 只覆盖跟随系统时的系统切换。

## 原因

setColorMode 会让 $r 资源重解析，但修复期真机实测：应用内选深色而系统为浅色时，context.resourceManager.getColorSync 仍按设备配置取值；画布色只在初始化取一次也不会更新；写死的系统栏内容色在深色下不可读。

## 做法

1. 切换前检索 getColorSync/getColor、Canvas 取色、内联色与系统栏设置，逐类写明切换后由谁重解析。
2. 提供按当前主题覆写 colorMode 的资源管理器（resourceManager.getOverrideResourceManager），由主题控制器统一导出；取色点订阅主题态或 onConfigurationUpdate 后重解析并重绘。
3. 系统栏内容色按生效 colorMode 计算（亮色 #000000、暗色 #FFFFFF），并在 onConfigurationUpdate 中重设。
4. 移植构造期取色的自绘 View 时，把取色写成可重入的方法。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 源码 android-36.1。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 原因〕安卓 Context.obtainStyledAttributes 从该 Context 当前主题取样式属性；Activity.recreate 用新实例重建 Activity，流程与配置变化时的重建基本相同，构造期从主题取的颜色随新实例重新取
- 〔做法第 2 步〕ApplicationContext.setColorMode 只能在主线程调用；参数可取深色、浅色或跟随系统（不设置）
- 〔做法第 2 步〕限定词目录匹配只取与当前状态最匹配的资源；要取指定配置（如指定颜色模式）的资源，用 getOverrideResourceManager(configuration) 得到按该配置取值的资源管理器
- 〔原因〕应用内选深色而系统为浅色时，设备上 context.resourceManager.getColorSync 仍返回浅色值
