# 引用 style 或抽成共享 @Builder 的控件：先展开共享默认值，再逐实例叠加元素自身的覆写（字号、圆角、间距）；圆角不按半高推，也不照抄相邻控件

## 何时使用

界面实现阶段（含返修期重写弹窗或按钮），为通过 style 继承形状、尺寸与渐变的控件确定修饰链时；把重复 XML 元素抽成 @Builder 时；为 TextView 的 maxLines/lines、TextAppearance 字号字重行高，或 LinearProgressIndicator 等 Material 控件的轨道色确定取值时

## 适用情境

源 XML 控件以 style="@style/X" 继承圆角、高度、渐变等属性，元素本身只覆写部分项；同一或相邻布局里有圆角更大的卡片，或同 style 但显式覆写成胶囊的按钮。或按键等控件以 style 给默认 textSize、单个控件再覆写不同字号；多个同构元素（分组标题）各自带不同的 layout_marginTop。也包括 maxLines/lines、TextAppearance 与 trackColor 来自 style 引用或 Material 控件默认样式，布局 XML 本身没写。也包括 TextView 只声明 textAppearance（如 ?android:attr/textAppearanceMedium）而没写 textColor，映射参考只说“展开为样式”，写者只取了字号。

## 原因

style 里的形状值不在元素上，不展开就只能猜：按高度一半推成胶囊、照抄外层卡片或相邻按钮的圆角；把某处的显式覆写当成 style 默认值也会扩散错误。来源中三处按钮的写者输入不同（有人读过 styles.xml 仍未应用，有人没读，返修时自问默认值却没有查），结果都写成胶囊。另一应用计算器按键 style 默认 36sp，各键覆写为 28/32sp，生成者统一写 36；新建账本页把两个分组标题抽成无 margin 参数的 @Builder，丢掉“账本类型”的 30dp 顶距。

## 做法

1. 遇到 style 引用先展开其全部 item（圆角、高度、渐变起止色），再逐项叠加元素上的显式属性；元素没覆写的形状值取 style 值。
2. 在注释里写明每个形状值来自 style 还是哪一行覆写；写不出来源就先读 styles.xml，不用估算值占位。
3. 同一 style 多处复用时逐个控件核对有无显式覆写，覆写处保持覆写值，不把某处覆写当成 style 默认值。
4. 字号等文本属性同样逐控件取有效值：元素覆写优先于 style 默认；把重复元素抽成 @Builder 时，逐实例不同的属性（margin、字号）作为参数传入，写完逐条对照 XML 数值。
5. maxLines/lines、TextAppearance、trackColor 同样先在 res/values 的 styles/themes 查出再写，不按“XML 未写即默认”推断；android:lines=N 对应 minLines(N) 加 maxLines(N)。
6. 展开 textAppearance 时字号与 textColor 一起展开（AppCompat 的 TextAppearance.Medium 为 18sp 加 ?android:textColorSecondary）；没写 textColor 的正文（style=、控件默认样式和主题里也都没给 android:textColor 时）按所引 textAppearance 的颜色属性取色令牌：AppCompat、Material 系主题下 Medium 取次级、Large 取主、Small 取三级文字色，旧版 Theme、Theme.Holo 下 Medium 取主文字色、Small 取次级；不一律默认用主文字色。

## 可选检查

- grep 注释含该 style 名的 borderRadius，与 styles.xml 及各处 XML 覆写逐一比对。

- 〔原因 / 做法第 1、3、4 步〕安卓定一个属性的最终值按这个先后取：元素在 XML 里自己写的值 → 元素 style= 指定的样式 → 控件的默认样式（defStyleAttr / defStyleRes，如主题的 textViewStyle、buttonStyle）→ 主题里的基础值；元素写了的覆盖 style 里的
- 〔做法第 6 步〕TextView 构造时先按同样的先后（元素 → style= → 默认样式 → 主题）取出 textAppearance，读入它的字号、颜色等；再读 TextView 自身的 textSize、textColor 等覆盖上去，这一步同样按元素 → style= → 默认样式 → 主题里直接给的值取。所以直接写在元素或 style 上的 textColor 优先于 textAppearance 里的颜色；应用主题里直接写了 android:textColor（或 textSize）时，它也盖过 textAppearance 里的同名项
- 〔做法第 6 步〕平台 TextView 的默认样式把 textAppearance 设为 ?attr/textAppearanceSmall：主题的 textViewStyle 在 Theme 下是 Widget.TextView，在 Theme.Material.Light 下是 Widget.Material.Light.TextView（经 Widget.Material.TextView 继承 Widget.TextView，都不另设 textAppearance）；AppCompat 系主题（含 Theme.MaterialComponents、Theme.Material3）把 android:textViewStyle 设为 Widget.AppCompat.TextView，它在 values、values-v21、values-v23 里的各份都以平台 Widget.TextView 或 Widget.Material.TextView 为父、不另设 textAppearance（appcompat 1.1.0、1.8.0），结果相同；元素和 style= 都没写 textAppearance 时，文字外观取主题的 textAppearanceSmall（android-30、android-36 相同）
- 〔做法第 6 步〕主题里 textAppearanceSmall / Medium / Large 指向的样式：旧 Theme 为 TextAppearance.Small / Medium / Large；Theme.Holo 为 TextAppearance.Holo.*（Theme.Holo.Light 为 TextAppearance.Holo.Light.*）；Theme.Material 与 Theme.Material.Light 为 TextAppearance.Material.*。AppCompat 主题在 API 14–20 由 Platform.AppCompat(.Light) 指向 TextAppearance.AppCompat.*，API 21 起不另设，取父主题 android:Theme.Material(.Light) 的 TextAppearance.Material.*（appcompat 1.1.0、1.8.0 相同）；Theme.MaterialComponents.Light、Theme.Material3.Light（material 1.14.0）同样取 TextAppearance.Material.*
- 〔做法第 6 步〕各 TextAppearance 的字号和颜色属性（平台 android-30 与 android-36 相同）：TextAppearance.Material.Small 为 14sp、?attr/textColorTertiary，Medium 为 18sp、?attr/textColorSecondary，Large 为 22sp、?attr/textColorPrimary（手机取 values/ 的这几个字号；手表 values-watch 下为 12 / 14 / 16sp）；Base.TextAppearance.AppCompat.Small / Medium / Large 在 values/ 里同为 14 / 18 / 22sp 和 ?android:attr/textColorTertiary / Secondary / Primary，values-v21 里重定义为以 android:TextAppearance.Material.Small / Medium / Large 为父、不另设，API 21 起取的就是上面平台那几项（appcompat 1.1.0、1.8.0）；旧 TextAppearance.Small 为 14sp、?textColorSecondary，TextAppearance.Medium 18sp、TextAppearance.Large 22sp 不写颜色，继承 TextAppearance 的 ?textColorPrimary；TextAppearance.Holo.Medium、Holo.Small 分别以 TextAppearance.Medium、Small 为父，颜色属性同旧版
- 〔做法第 6 步〕应用主题没另设这些颜色属性时：Theme.Material.Light（API 21 起的 Theme.AppCompat.Light、Theme.MaterialComponents.Light 和 DayNight 日间都取它）下 textColorPrimary 为 #DE000000，textColorTertiary 为 #8A000000，textColorSecondary 在平台资源 android-30 为 #8A000000（alpha 0.54）、android-33 起为 #99000000（alpha 0.60），设备上取它自己那一版框架的值；Theme.Material（暗，AppCompat 暗色和 DayNight 夜间同）下 textColorSecondary、textColorTertiary 都是 #B3FFFFFF；AppCompat 在 API 14–20 用自带的 abc_ 颜色，亮色 secondary、tertiary 为 #8A000000，暗色 secondary 为 #B3FFFFFF。Theme.DeviceDefault.Light 系（应用没设主题、targetSdkVersion ≥ 24 时的默认主题 Theme.DeviceDefault.Light.DarkActionBar 也在内）只在 Android 11 及以前取这里的值，Android 12 起改取系统色
- 〔做法第 6 步〕Material3 主题自己给文字色（应用没另设时）：Theme.Material3.Light 的 textColorSecondary 和 textColorTertiary 都是 #FF49454F，textColorPrimary 在 material 1.8.0 为 #FF1C1B1F、1.12.0 和 1.14.0 为 #FF1D1B20；Theme.Material3.DayNight 夜间 textColorSecondary 为 #FFCAC4D0；应用启用动态取色（DynamicColors，叠加 ThemeOverlay.Material3.DynamicColors.Light）时，API 31 起 textColorSecondary 改取系统色（API 31–33 为 system_neutral2_700，API 34 起为 system_on_surface_variant_light），随壁纸变。旧 Theme（暗）的 textColorSecondary 为 #BEBEBE、textColorTertiary 为 #808080；Theme.Holo.Light 的 textColorPrimary 为 #FF000000、textColorSecondary 为 #323232；Theme.DeviceDefault.Light（及 .DarkActionBar、DayNight 日间）在 Android 11 及以前沿用 Theme.Material.Light 的值，Android 12 起改取系统色：textColorPrimary / Secondary / Tertiary 的资源默认值 android-31 到 34 为 #191C1E / #40484D / #70777C，android-35 起为 #1A1B20 / #44464F / #757780；这些系统色注明可在运行时被覆盖，设备按壁纸取色时实际值不同
- 〔做法第 5 步〕TextView 的 mMaximum 初值是 Integer.MAX_VALUE：控件、style 和默认样式都没写 maxLines、lines，也不是单行时，行数不设上限，不是 1 行；setLines(n)（android:lines）把最少和最多行数都设成 n（模式都为 LINES），是固定行数而不只是上限。写了 android:singleLine="true"，或（没写 android:digits 时）设了不带 textMultiLine 的 inputType（如 text、number、phone、textPassword）时，构造时按单行处理：setLines(1) 并横向滚动
- 〔做法第 5 步〕ArkUI Text 的 maxLines(value: number): TextAttribute 未设时文本自动折行、不限行数，设为 0 时不显示文本；minLines(minLines: Optional<number>): TextAttribute 自 API 22 起，文本高度不足最小行数时按最小行数的高度显示，与 maxLines 同设时不超过 maxLines 对应的高度，undefined 表示不限
- 〔做法第 5 步〕ArkUI Text 的 textOverflow(options: TextOverflowOptions): TextAttribute 中 overflow 默认 TextOverflow.Clip；None、Clip、Ellipsis 要配合 maxLines 才生效，None 与 Clip 效果相同；设为 MARQUEE 时单行滚动，maxLines 不生效
- 〔做法第 4、6 步〕ArkUI Text 的 fontSize(value: number | string | Resource)：number 按 fp，字符串可带单位（如 '10fp'），不支持百分比，未设时 16fp（可穿戴设备 15fp）；fontColor(value: ResourceColor) 未设时为 '#e6182431'（深灰、不透明度 90%，可穿戴设备 '#c5ffffff'）
- 〔做法第 4 步〕margin(value: Margin | Length | LocalizedMargin): T 默认 0、单位 vp，给 Length 时四边同时生效；Margin 即 Padding 类型 { top?, right?, bottom?, left?: Length }，按边给值；Length 为 number 或不带单位的字符串时按 vp；百分比 margin 四边都以父容器宽为基准；padding(value: Padding | Length | LocalizedPadding): T 同样按边给值
- 〔做法第 4 步〕安卓 layout_marginVertical 相当于 layout_marginTop、layout_marginBottom 取同一值，与它们同时写时 layout_marginVertical 优先；layout_marginHorizontal 对左右两边同理；layout_margin 优先于以上全部（写了它 Start、End 也不读）。没写 layout_margin 而写了 layout_marginStart 或 layout_marginEnd 时：应用声明了 android:supportsRtl="true"，左右边距改按 Start、End 重取（LTR 下左 = Start、右 = End，没写的一侧为 0），layout_marginHorizontal、Left、Right 给的横向值被换掉；没声明 supportsRtl 时 Start、End 只在对应的 Left、Right 没写（也没写 layout_marginHorizontal）时补上
- 〔原因 / 做法第 1、2 步〕borderRadius(value: Length | BorderRadiuses | LocalizedBorderRadiuses): T 默认 0，默认单位 vp，百分比以组件宽度为基准；四个圆角值不同、其中某个超过宽高较小者的一半时按值的比例绘制异形圆角；API 22 起另有重载 borderRadius(value, type?: RenderStrategy)；用 border 统一设边框且没给 radius 时，borderRadius 要写在 border 之后才生效
- 〔适用情境 / 做法第 5 步〕Material3 LinearProgressIndicator 的轨道色（应用主题和控件都没另设 trackColor 时）：Widget.Material3.LinearProgressIndicator 在 material 1.8.0 到 1.10.0 为 ?attr/colorSurfaceVariant（更早的版本未核），1.11.0 为 ?attr/colorSurfaceContainerHighest，1.12.0 起（核到 1.14.0）为 ?attr/colorSecondaryContainer（经 @macro/m3_comp_progress_indicator_track_color）；1.12.0 起另有 Widget.Material3.LinearProgressIndicator.Legacy，为 ?attr/colorSurfaceContainerHighest；父样式 Widget.MaterialComponents.LinearProgressIndicator 在资源里不设 trackColor
