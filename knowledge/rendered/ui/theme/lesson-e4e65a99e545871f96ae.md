# 视觉属性逐项取自源布局、item 布局与适配器分支，缺项就补读，不以近似值、通用卡片或自拟分隔线代替；菜单行与操作栏的图标、按状态切换的图与颜色同列清单

## 何时使用

界面转换与视觉返修阶段，确定标题栏背景、文字颜色与字号、周末与选中样式、item 尺寸、胶囊圆角、行高与分隔线时；把弹出菜单行、列表分组标题与批量操作底栏转成组件时

## 适用情境

页面规格只给合成的结构（无颜色与尺寸），视觉数值分散在 Fragment 布局、include 布局、item 布局与适配器 convert 分支里；转换者可能只读到部分文件，或读到了却按经验取整。 也包括增量迁移的差异清单与规格只按功能行为描述新入口，菜单行或操作按钮由 ImageView 加 TextView 组成、标题用 drawableLeft 图标与专用颜色资源，部分图标随选中状态切换。

## 原因

视觉属性一旦凭经验补齐，就会整体偏离源端：白底标题栏代替红底、统一灰色星期行代替红色周末、方块标签代替圆角胶囊、多出源端没有的横线与竖线、行高与内边距取近似值。来源为同一应用：月历页转换者在批量读取被截断后自拟配色与选中样式；15 日页生成者读到了 item 与 Fragment 布局的 dp 值，仍写成近似尺寸并额外加了分隔线；月历生成者读全了日期格 item 布局，仍把 46 高写成 48、用圆形与文字色块代替今日与班休图片角标。 规格只承载行为时，写者容易只写出文字与点击。另一应用中写者已看过 Android 截图、读到菜单布局与按选中状态换图的源码，仍把更多菜单、推荐标题与批量底栏写成纯文字。

## 做法

1. 写样式前从源布局、item 布局与适配器分支逐项摘出清单：背景色、主要文字颜色与字号、周末与节日颜色、选中与当天样式、item 宽高、圆角、行高与上下间距、分隔线的有无；某项在已读内容里找不到就回到对应文件补读。
2. 写完按清单逐个 dp 值对照，不用近似值，不自行增加源端没有的分隔线或卡片圆角。
3. 清单同时覆盖图标元素：ImageView、drawableLeft/Start、按选中数量或模式切换的 drawable（如未选中用灰图、选中用高亮图）及对应文字颜色，按状态成组映射。差异清单或规格只描述行为时，实现者仍回到源布局补出可见元素；规格提取描述新 UI 入口时，把关键视觉要素（图标、标题颜色、“图标 + 文字”结构）写进验收项。

来源支持：4 张卡 · 2 次迁移 · 2 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-28（提交 4d3e2aa3）；安卓 框架源码 android-36.1。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1 步〕安卓控件一项属性的最终值按四层取，前面的覆盖后面的：布局 XML 里控件自身写的属性 → 控件 style 属性指定的样式 → 构造时的 defStyleAttr / defStyleRes 默认样式（defStyleRes 只在 defStyleAttr 为 0 或当前主题里没有这个属性时才用）→ 当前主题里的基值。布局里没写的属性，值来自后三层之一。「当前主题」是控件所在 Context 的主题：布局里控件自己或祖先写了 android:theme 时，是叠加了它的主题，子控件沿用。构造之后代码里再调用 setXxx（如适配器里按状态设颜色、图片）会覆盖这四层得出的值。
- 〔做法第 3 步〕TextView 同时写了 drawableLeft/Right 和 drawableStart/End 时显示哪一个，取决于 RTL 兼容模式：应用 targetSdk ≥ 17 且清单 application 写了 android:supportsRtl="true" 时，只要写了 drawableStart 或 drawableEnd 中的任一个，从左到右布局下左侧显示 drawableStart、右侧显示 drawableEnd（没写的那一侧为空，即使写了 drawableLeft 或 drawableRight 也不显示），从右到左布局下两侧对调；targetSdk < 17 或没有声明 supportsRtl 为 true（这个清单属性不写时为 false）时，drawableStart 只在没写 drawableLeft 时补到左侧，drawableEnd 只在没写 drawableRight 时补到右侧。以上是布局 XML 里的写法；代码里调用 setCompoundDrawables 或 setCompoundDrawablesWithIntrinsicBounds（左、上、右、下）会丢掉已有的 drawableStart/End、按左右显示，调用 setCompoundDrawablesRelative 或 setCompoundDrawablesRelativeWithIntrinsicBounds（起、上、止、下）会丢掉已有的 drawableLeft/Right、按起止显示。
- 〔做法第 1、2 步〕ArkUI 尺寸参数的数值不带单位时（写 number 或不带单位的字符串）默认单位是 vp，vp 换成 px 要乘设备 display 的 densityPixels（物理像素与逻辑像素的缩放系数，取值范围 0.5–4.0）；Text 的 fontSize 和 lineHeight 例外：写 number 或不带单位的字符串（如 "10"）时单位是 fp（fontSize 应用没有另设时为 16fp，穿戴设备 15fp）。fp 和 vp 一样按屏幕密度换算，另外随系统字体大小设置变化。
