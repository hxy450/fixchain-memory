# 主题提供的颜色按各主题与深浅两态取值导出成对 base/dark 键：先把引用分成 ?attr 主题属性与 @color 写死两类，values-night 同名 style 未写的主题属性回落框架深色默认；取 Android 框架实际值，不以目标平台 sys token 代替

## 何时使用

资源前置、规格提取或界面实现阶段，为引用 ?attr 的图标 fillColor、工具栏主题色、自绘组件前景色或文字色新建或选择颜色 token 时；把 AppCompat DayNight 应用（含日间覆写主题色、values-night 重新定义同名 AppTheme 的情况）映射为 base/dark 颜色资源与页面配色时

## 适用情境

源图标与控件颜色来自主题属性（应用自定义的图标色属性、colorControlNormal=colorOnSurface、colorOnSecondary 等），各主题取值不同；目标 SVG 只保留浅色值，color.json 可能缺对应键。也包括 AppTheme 只继承 Theme.AppCompat.DayNight、没有 values-night、没有 colorPrimary/colorAccent 覆写：窗口、对话框、ActionBar、状态栏、按钮、主次文字、提示、禁用、强调色与分隔线都来自框架默认并随深浅色变化。也包括日间 AppTheme 覆写了 colorPrimary/colorPrimaryDark/colorAccent，values-night 重新定义同名 AppTheme 却没写这些项：夜间回落 AppCompat 深色默认（#212121/#000000/#80CBC4），布局中 ?attr/colorPrimary 处随之变色，@color/colorPrimary 写死处保持不变。这组回落值只在夜间那份 AppTheme 声明的父主题属于 AppCompat 一系时成立；父主题属于 MaterialComponents 一系时默认值不同（如 colorPrimary 浅色 #6200EE、深色 #BA86FC），其他主题族同理，先按应用在 values 与 values-night 里实际声明的父主题和所依赖的库版本解析，不套用 AppCompat 的这组值。规格可能把业务调色板镜像到 dark 当作深色适配，各页转换器各自补键、按某一模式写死 white，或改用目标平台 sys.color 语义色。这里的「@color 写死」指只在 values 里定义、values-night（或 color-night）里没有同名颜色的资源；源端在夜间限定目录里给了同名颜色的，它本身随深浅色变化，按两态各自的取值写成 base/dark 成对键，不并成常量。

## 原因

缺键时借用语义不同的灰色、按名称猜为强调色，或 base/dark 写同一个值，会让颜色在某个主题下错误，并随先例扩散。DayNight 应用的外观几乎全由框架两态默认色决定；把 ?attr 引用与 @color 写死统一成一个常量色，夜间就无法只让主题属性变色。“框架默认色不猜”一类措辞会被召回压成“不导出”，资源前置只写少数键；改用目标平台 sys 语义色则与 Android 框架取值不同。

## 做法

1. 先把颜色引用分成两类：布局与样式里的 ?attr（?attr/colorPrimary、?android:textColorSecondary 等）与 @color 写死。逐主题求 ?attr 的取值，包括 values-night 中的同名 style，夜间块没写的项取父主题（AppCompat 深色）默认；主题属性另建 theme_* 成对键（base/dark 各一），写死色保持常量键，页面按源端引用类型分别绑定。
2. 查矢量 fillColor 或工具栏主题引用的属性，分别取各主题 style 中的值，在 base/dark 各写一个键；检索时不要把目标属性名排除在外。
3. 自绘组件的 foregroundColor=?attr 先查 attrs/styles 的实际值再定默认色，各调用点按自己布局传参。
4. 图标 Image 用 fillColor 绑定该 token，不沿用未着色的先例；资源前置阶段把被引用的主题属性连同解析值导出为颜色键并在映射表注明。
5. 源为 DayNight 时，在规格中列出框架浅、深两态的窗口、对话框、ActionBar、状态栏、按钮、主次文字、提示、禁用、强调色与分隔线取值，成对写入 base/dark；页面背景、文字与菜单颜色只引用这些成对 token，不按某一模式写死，也不把深色适配留待以后。
6. 框架默认值（colorAccent、主次文字色 primary_text_default_material_light #DE000000 与 secondary #8A000000、列表分隔线等）先查依赖的 appcompat/material aar 或本机 SDK 平台资源，或用源端运行截图核对，再写入成对键；查不到才登记未决，不落猜测值，也不用 $r('sys.color.ohos_id_*') 等目标平台语义色代替。

- 〔适用情境 / 做法第 1、5 步〕androidx.appcompat 的 Theme.AppCompat.DayNight 在 values 下继承 Theme.AppCompat.Light、在 values-night-v8 下继承 Theme.AppCompat：浅色模式取 Light 那一支的主题值，深色模式取 Theme.AppCompat 那一支（缓存里 1.1.0 与 1.8.0 相同）
- 〔适用情境 / 做法第 1、5 步〕应用主题继承 Theme.AppCompat.DayNight 且没有另设 colorPrimary、colorPrimaryDark、colorAccent 时（appcompat 1.7.1，API 21 起）：浅色分别为 #fff5f5f5、#ff757575、#ff008577，深色分别为 #ff212121、#ff000000、#ff80cbc4
- 〔做法第 6 步〕平台 Material 文字色资源：primary_text_default_material_light 为 #de000000、secondary_text_default_material_light 为 #8a000000；深色对应 primary_text_default_material_dark 为 #ffffffff、secondary_text_default_material_dark 为 #b3ffffff
- 〔做法第 5、6 步〕平台 Theme.Material.Light 的 windowBackground 取 ?attr/colorBackground，colorBackground 为 @color/background_material_light，即 material_grey_50 = #fffafafa（应用主题没有另设 windowBackground、colorBackground 时）
- 〔做法第 2 步〕平台自带的工具栏返回箭头 ic_ab_back_material 是白色路径加 android:tint="?attr/colorControlNormal"，显示颜色由主题的 colorControlNormal 决定
- 〔做法第 1、4、5 步〕resources 下建颜色模式限定词目录 dark（目录名格式为「限定词/资源组」，即 dark/element），在 base/element/color.json 与 dark/element/color.json 定义同名颜色并赋不同值时，深色模式下 $r('app.color.<同名键>') 取 dark 里的值
- 〔原因 / 做法第 1 步〕系统优先从与设备状态匹配的限定词目录找资源，只有没有匹配的限定词目录、或限定词目录里找不到该资源时才去 base 目录：dark 里缺某个键时，深色模式下取 base 的浅色值
- 〔做法第 4 步〕Image 的 fillColor 只对 SVG 图生效；没设置时不叠加填充色，传无效值时用主题默认色（浅色模式黑、深色模式白）
- 〔做法第 1 步〕color.json 的标准十六进制颜色值是八位，前两位表示透明度、后六位表示颜色（#AARRGGBB）
