# 按源端实际色值与字号在资源里反查同值键：主题语义色、排版样式先解析到值，不按 accent、primary、title/body 等名称或别页令牌选键

## 何时使用

界面实现阶段，为按钮、背景、文字与渐变色阶设置颜色资源引用，或为文本绑定字号资源令牌时

## 适用情境

源端颜色以 shapeSolidColor、background、textColor 等硬编码色值或色值资源给出；目标工程已有多组语义名相近但色值不同的颜色资源（如脚手架留下的 color_accent 与迁移出的 brand_accent）。也包括 Compose 源端以主题语义色（如 colors.textPrimary）或排版样式（如 MaterialTheme.typography.titleMedium）取值，而目标 color.json/float.json 只有部分令牌：有名称相近或其他页面前缀的键（text_secondary、feed_font_title），缺同值键，流程要求缺令牌时报告 design_tokens_missing。也包括用 text_size_large、text_size_small 一类名称暗示大小的命名资源承载源端数值（如 16sp 标题、12sp 信息条），或同一组件中语义不同的颜色（进度轨道与选中行底色）准备共用一个已有 token。也包括 Java 以 Color.GREEN、Color.RED 等框架颜色常量着色，规格映射成名称相近、色值不同的应用色（如 light_green #FF66FF66）。

## 原因

资源名只表达意图，模板或脚手架生成的 accent 可能是默认蓝；按名字选键时代码看似引用了主题色，渲染出的颜色却与源端不同，编译和结构检查都发现不了。来源中实现者照抄了按钮高度、圆角与字色，唯独背景按名字选了蓝色 accent，而工程里另有与源端色值相同的键，直到视觉回归才被发现。另一应用中同类选择出现三次：分组标题的 textPrimary（该主题中等于品牌色）被静默写成近黑的 text_secondary；个人页 titleMedium/bodyMedium（16/14）绑定到首页 20fp/16fp 的标题/正文令牌；已正确的渐变字面色值被换成三处值不同的现有令牌。写者都读到了源端取值，也收到了缺令牌须报告的规则。

## 做法

1. 取源端控件的实际色值（展开 shape、selector、style 后的最终值），在 color.json 中找同值键引用并核对该键的值（同名键在 dark 等限定词目录或 AppScope 里另有定义时，按实际生效的那份比：与设备状态匹配的限定词目录优先于 base，AppScope 与模块重名的资源编译后只留 AppScope 的）；没有同值键就新增语义资源（被其他页面引用的共享令牌不改值），不借用名字相近或同前缀的键；为消除 hex 字面量改写已正确的字面色值时同样按值找键。
2. 源端用主题语义色或排版样式名时，先在 Theme/Color/Type 定义或设计令牌表中解析到具体值（如该主题的 textPrimary 等于 brand、titleMedium 为 16sp；Typography(...)、lightColorScheme(...)、darkColorScheme(...) 里没有覆写的样式和颜色角色取 Material3 库的默认值，如 titleMedium 16sp、bodyMedium 14sp、labelSmall 11sp），再按值找键；缺同值键时按调色板或样式名新增令牌，或按流程报告 design_tokens_missing，不用名称相近或其他页面前缀的现有令牌代替。
3. 选用命名资源前读其实际值，注释里写的数值与所引资源一致；同一组件中语义不同的颜色不共用一个 token，从已有组件照搬颜色前先核对源端是否同色。
4. 框架颜色常量按色值匹配（Color.GREEN=#FF00FF00、Color.RED=#FFFF0000），没有同值键就新增，不用名称相近的应用色代替，也不用同名而值不同的 ArkUI Color 枚举代替。

- 〔原因〕$r('app.color.<键>') 引用的键只要存在就能编译通过；引用到值与源端不同的键时编译不报错，颜色偏差到模拟器视觉回归时才显现
- 〔做法第 1 步〕color.json 里颜色的标准写法是八位十六进制：前两位透明度、后六位颜色，与安卓 #AARRGGBB 同序
- 〔做法第 1 步〕安卓颜色资源写成 #RGB、#ARGB、#RRGGBB、#AARRGGBB 都能编译：#RGB、#RRGGBB 的透明度补 FF，#RGB、#ARGB 每一位重复一次展开（#F80 即 #FFFF8800）；代码里 Color.parseColor 只认 #RRGGBB（透明度补 FF）、#AARRGGBB 和 red、green、gray 等颜色名
- 〔做法第 1 步〕控件属性的最终值按先后取：布局里控件自身写的属性 → 控件 style 指定的样式 → defStyleAttr 指向的主题属性所给的样式（defStyleAttr 为 0 或主题里找不到它时才用 defStyleRes）→ 主题；排在前面的覆盖后面的
- 〔做法第 1、2 步〕安卓平台常用颜色资源的取值（android-30 至 37.0 的平台资源相同、没有限定目录变体）：@android:color/white #FFFFFFFF、black #FF000000、transparent #00000000、darker_gray #FFAAAAAA、background_light #FFFFFFFF、background_dark #FF000000、holo_blue_light #FF33B5E5、holo_blue_dark #FF0099CC、holo_blue_bright #FF00DDFF、holo_green_light #FF99CC00、holo_green_dark #FF669900、holo_red_light #FFFF4444、holo_red_dark #FFCC0000、holo_orange_light #FFFFBB33、holo_orange_dark #FFFF8800、holo_purple #FFAA66CC。应用主题没有另设时平台主题的颜色属性：Theme.Material.Light 的 colorAccent #FF008577、colorPrimary #FFF5F5F5、colorPrimaryDark #FF757575、textColorPrimary #DE000000、textColorSecondary 在 android-30 为 #8A000000、android-33 起（核到 37.0；31、32 未核）为 #99000000；Theme.Material（深色）的 colorAccent #FF80CBC4、colorPrimary #FF212121、colorPrimaryDark #FF000000、textColorPrimary #FFFFFFFF、textColorSecondary #B3FFFFFF；Theme.DeviceDefault.Light 在 android-30 与 Theme.Material.Light 相同，android-33 起改取 system_accent1_600、system_neutral1_50 等系统调色板色，平台资源里的值各版不同（如 colorAccent android-33、34 为 #FF00668B，35、36 为 #FF475D92，37.0 分日夜为 #FF4B5D8B、#FF505E81）
- 〔做法第 1、2 步〕应用主题没有另设时库主题的颜色属性：Theme.AppCompat.Light、Theme.AppCompat（appcompat 1.1.0 至 1.8.0）在 API 21 起的 colorAccent、colorPrimary、colorPrimaryDark 与平台 Theme.Material.Light、Theme.Material 相同（#FF008577、#FFF5F5F5、#FF757575；#FF80CBC4、#FF212121、#FF000000），API 21 以下取 Holo 的值；Theme.MaterialComponents.Light（material 1.4.0 至 1.14.0）的 colorPrimary #FF6200EE、colorPrimaryDark #FF3700B3、colorSecondary #FF03DAC6，colorAccent 指向 colorSecondary
- 〔做法第 1 步〕引用资源时先在与设备状态匹配的限定词目录（如颜色模式 dark）里找，找不到才用 base 目录；AppScope 与模块下同一资源目录里重名的资源，编译打包后只保留 AppScope 的
- 〔做法第 2、3 步〕float.json 每项是 name 与 value，数值和单位只写在 value 里（如 "28.0fp"）
- 〔做法第 2、3 步〕Text.fontSize 传 number 时单位是 fp，传 string 可带单位（如 "10fp"）、不支持百分比；应用没有设 fontSize 时默认 16fp（Wearable 设备上 15fp）
- 〔做法第 2 步〕Compose Material3 的 Typography 没有覆写的样式取库的默认字号：displayLarge 57sp、displayMedium 45sp、displaySmall 36sp、headlineLarge 32sp、headlineMedium 28sp、headlineSmall 24sp、titleLarge 22sp、titleMedium 16sp、titleSmall 14sp、bodyLarge 16sp、bodyMedium 14sp、bodySmall 12sp、labelLarge 14sp、labelMedium 12sp、labelSmall 11sp（material3 1.0.0、1.4.0 与 androidx-main 相同）
- 〔做法第 2 步〕Compose Material3 的 lightColorScheme(...) 不传的颜色角色取 ColorLightTokens 的默认值（如 primary 为 PaletteTokens.Primary40，即 #FF6750A4），darkColorScheme(...) 取 ColorDarkTokens（如 primary 为 Primary80，即 #FFD0BCFF）；MaterialTheme 不传 colorScheme 时用 lightColorScheme()，系统处于深色模式也不会自动换成深色方案；dynamicLightColorScheme、dynamicDarkColorScheme（Android 12 起）从系统调色资源取色，随壁纸变化（material3 1.0.0、1.4.0 相同）
- 〔做法第 4 步〕android.graphics.Color 常量的 ARGB 值：BLACK 0xFF000000、DKGRAY 0xFF444444、GRAY 0xFF888888、LTGRAY 0xFFCCCCCC、WHITE 0xFFFFFFFF、RED 0xFFFF0000、GREEN 0xFF00FF00、BLUE 0xFF0000FF、YELLOW 0xFFFFFF00、CYAN 0xFF00FFFF、MAGENTA 0xFFFF00FF、TRANSPARENT 0
- 〔做法第 4 步〕ArkUI 的 Color 枚举值：Black 0x000000、Blue 0x0000ff、Brown 0xa52a2a、Gray 与 Grey 0x808080、Green 0x008000、Orange 0xffa500、Pink 0xffc0cb、Red 0xff0000、White 0xffffff、Yellow 0xffff00、Transparent 为全透明；其中 Green、Gray 与安卓同名常量的值不同，枚举里没有 Cyan、Magenta
- 〔适用情境 / 做法第 3 步〕应用主题和控件 style 没有另设 trackColor 时：Theme.Material3 系主题把 linearProgressIndicatorStyle 指向 Widget.Material3.LinearProgressIndicator（material 1.14.0 的 Material3Expressive 主题指向的样式也继承它），indicatorColor 为 colorPrimary；trackColor 随 material 版本不同：1.5.0–1.10.0 为 ?attr/colorSurfaceVariant，1.11.0 为 ?attr/colorSurfaceContainerHighest，1.12.0 起（核到 1.14.0）为 ?attr/colorSecondaryContainer——Theme.Material3.Light 下是 #FFE8DEF8、Theme.Material3.Dark 下是 #FF4A4458（DayNight 按日夜取），对应的 colorPrimary 为 #FF6750A4、#FFD0BCFF；套了 DynamicColors（API 31 起）时这些颜色换成随壁纸的系统色；1.12.0 起另有 Widget.Material3.LinearProgressIndicator.Legacy，其 trackColor 为 ?attr/colorSurfaceContainerHighest。Theme.MaterialComponents 系主题用 Widget.MaterialComponents.LinearProgressIndicator，不设 trackColor，代码按 indicatorColor（缺省 colorPrimary）叠上主题 android:disabledAlpha（取不到时 0.2）的透明度作轨道色
