# 按源端实际色值与字号在资源里反查同值键：主题语义色、排版样式先解析到值，不按 accent、primary、title/body 等名称或别页令牌选键

## 何时使用

界面实现阶段，为按钮、背景、文字与渐变色阶设置颜色资源引用，或为文本绑定字号资源令牌时

## 适用情境

源端颜色以 shapeSolidColor、background、textColor 等硬编码色值或色值资源给出；目标工程已有多组语义名相近但色值不同的颜色资源（如脚手架留下的 color_accent 与迁移出的 brand_accent）。也包括 Compose 源端以主题语义色（如 colors.textPrimary）或排版样式（如 MaterialTheme.typography.titleMedium）取值，而目标 color.json/float.json 只有部分令牌：有名称相近或其他页面前缀的键（text_secondary、feed_font_title），缺同值键，流程要求缺令牌时报告 design_tokens_missing。也包括用 text_size_large、text_size_small 一类名称暗示大小的命名资源承载源端数值（如 16sp 标题、12sp 信息条），或同一组件中语义不同的颜色（进度轨道与选中行底色）准备共用一个已有 token。也包括 Java 以 Color.GREEN、Color.RED 等框架颜色常量着色，规格映射成名称相近、色值不同的应用色（如 light_green #FF66FF66）。

## 例外与边界

- 源端颜色随深浅色变化（values-night 资源、主题按深浅色切换调色板）时，浅色、深色两套值都要对上：目标键在基础目录与 dark 限定目录里的值分别等于源端两套值才算同值键；目标已有随深浅色变化、两套值都对的引用，不换成只在浅色下同值的键或字面色值。源端颜色固定、不随深浅色变时，不选在 dark 目录里另有取值的键。

## 原因

资源名只表达意图，模板或脚手架生成的 accent 可能是默认蓝；按名字选键时代码看似引用了主题色，渲染出的颜色却与源端不同，编译和结构检查都发现不了。来源中实现者照抄了按钮高度、圆角与字色，唯独背景按名字选了蓝色 accent，而工程里另有与源端色值相同的键，直到视觉回归才被发现。另一应用中同类选择出现三次：分组标题的 textPrimary（该主题中等于品牌色）被静默写成近黑的 text_secondary；个人页 titleMedium/bodyMedium（16/14）绑定到首页 20fp/16fp 的标题/正文令牌；已正确的渐变字面色值被换成三处值不同的现有令牌。写者都读到了源端取值，也收到了缺令牌须报告的规则。

## 做法

1. 取源端控件的实际色值（展开 shape、selector、style 后的最终值），在 color.json 中找同值键引用并核对该键的值；没有同值键就新增语义资源（被其他页面引用的共享令牌不改值），不借用名字相近或同前缀的键；为消除 hex 字面量改写已正确的字面色值时同样按值找键。
2. 源端用主题语义色或排版样式名时，先在 Theme/Color/Type 定义或设计令牌表中解析到具体值（如该主题的 textPrimary 等于 brand、titleMedium 为 16sp），再按值找键；缺同值键时按调色板或样式名新增令牌，或按流程报告 design_tokens_missing，不用名称相近或其他页面前缀的现有令牌代替。
3. 选用命名资源前读其实际值，注释里写的数值与所引资源一致；同一组件中语义不同的颜色不共用一个 token，从已有组件照搬颜色前先核对源端是否同色。
4. 框架颜色常量按色值匹配（Color.GREEN=#FF00FF00、Color.RED=#FFFF0000），没有同值键就新增，不用名称相近的应用色代替，也不用同名而值不同的 ArkUI Color 枚举代替。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 Android SDK 平台资源 android-34；Android SDK 源码 android-36.1；compose material3-android 1.4.0、ui-graphics-android 1.12.0。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1 步〕Color.parseColor 只接受 #RRGGBB 与 #AARRGGBB（及颜色名）：7 位时补 alpha 0xFF，与 #FFRRGGBB 同值；平台 colors.xml 里还有 3 位写法（如 darker_gray=#aaa）
- 〔做法第 1 步〕color.json 的标准值是八位十六进制，前两位透明度、后六位颜色，与安卓 #AARRGGBB 同序；引用写 $r('app.color.<name>')
- 〔做法第 1、3 步〕float.json 每项 { "name": …, "value": "28.0fp" }，数值和单位都在 value 里，键名不代表数值；引用写 $r('app.float.<name>')
- 〔做法第 1、4 步〕@android:color：white #FFFFFFFF、black #FF000000、transparent #00000000、darker_gray #AAA；holo_blue_light/dark #FF33B5E5/#FF0099CC、holo_green_light/dark #FF99CC00/#FF669900、holo_red_light/dark #FFFF4444/#FFCC0000、holo_orange_light/dark #FFFFBB33/#FFFF8800、holo_purple #FFAA66CC
- 〔做法第 2 步〕Material3 默认 Typography（应用未覆写时）：字号 display 57/45/36、headline 32/28/24、title Large/Medium/Small 22/16/14、body 16/14/12、label 14/12/11（sp）；字重 display、headline、titleLarge、body 为 Regular（400），titleMedium、titleSmall、label 为 Medium（500）
- 〔做法第 2 步〕单位对应：fp 与 vp 一样随屏幕密度换算，并随系统字体大小变化（对应 sp）；vp 对应 dp；Text.fontSize 传 number 时按 fp
- 〔做法第 4 步〕android.graphics.Color 常量：BLACK #FF000000、DKGRAY #FF444444、GRAY #FF888888、LTGRAY #FFCCCCCC、WHITE #FFFFFFFF、RED #FFFF0000、GREEN #FF00FF00、BLUE #FF0000FF、YELLOW #FFFFFF00、CYAN #FF00FFFF、MAGENTA #FFFF00FF、TRANSPARENT 0
- 〔做法第 4 步〕Compose 的 Color.Black/DarkGray/Gray/LightGray/White/Red/Green/Blue/Yellow/Cyan/Magenta 与 android.graphics.Color 同名常量同值（如 Green=0xFF00FF00、Gray=0xFF888888）
- 〔做法第 4 步〕ArkUI 的 Color 枚举与安卓同名常量值不同：Green=0x008000、Gray/Grey=0x808080，另有 Brown、Orange、Pink；Red、Blue、Yellow、White、Black 的 RGB 与安卓相同
