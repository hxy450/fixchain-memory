# 追加主题颜色资源时同一次写深色限定目录的同名键，已存在的资源文件只追加不覆盖

## 何时使用

页面转换或资源阶段，为主题色追加颜色资源键时

## 适用情境

源主题有 Light/Dark 两套调色板；目标颜色资源分 base 与 dark 限定目录，多个任务会分别追加，部分文件由模板预置。

## 原因

只追加 base 键时深色下回落到浅色值；用整体写入覆盖已存在的资源文件，会删掉他人或模板写入的键（如启动窗背景色）。把深色值推给“后续任务”而无人承接时，这些键一直没有深色值。

## 做法

1. 为主题色追加 base 键时，同一次按源深色调色板写 dark 同名键。
2. 写前列出目标目录，文件已存在就先读再只追加，不用整体写入覆盖。

来源支持：1 张卡 · 1 次迁移 · 1 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因〕取资源时先在与当前设备状态匹配的限定词目录里找，目录里没有这个键才回到 base 目录；dark 目录缺某个颜色键时，深色模式下这个键取 base 的浅色值，按键逐个回落，不报错。〔成立范围：对 resources 下 element、media 等资源成立（rawfile、resfile 不参与匹配）；目录名里的 MCC/MNC、语言、文字、横竖屏、设备类型、颜色模式限定词都要与设备状态完全一致，该目录才参与匹配（如 zh_CN-dark 不参与英文设备的匹配），屏幕密度则取最接近的目录。不成立：应用调用 setColorMode 把颜色模式固定为浅色后，深浅色不再随系统变（依据是文档说明）。〕
- 〔做法第 1 步〕应用没有调用 setColorMode 时，系统按工程 dark 目录里有没有深色资源决定系统组件的深浅：有任何深色资源，系统组件在深色模式下自动切成深色；一个都没有，系统组件在深色模式下仍保持浅色。第一次往 dark 目录写颜色键时，全应用系统组件的深色表现会一起改变，没有 dark 同名键的 base 颜色仍是浅色值。〔成立范围：依据是文档说明。不成立：应用调用过 setColorMode 时以接口设定为准；文档示例里调用 setColorMode(COLOR_MODE_NOT_SET) 后，只用系统组件和系统颜色、没有 dark 资源的应用也跟随系统切换深浅色。〕
- 〔做法第 2 步〕编译时 AppScope/resources 会合入各模块的资源；同一资源目录、同一资源组里重名的资源按 AppScope、模块自身、依赖的 HAR 的优先级只保留一个，AppScope 最高。往模块 base/element/color.json 追加一个与 AppScope 重名的颜色键不会生效。〔成立范围：对 Stage 模型多模块工程成立；依据是文档说明。不成立：重名键分别在不同的限定词目录（如 AppScope 的 base 与模块的 dark）时不算重名冲突，按资源匹配规则取值。〕
