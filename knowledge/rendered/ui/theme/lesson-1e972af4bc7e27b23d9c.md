# 追加主题颜色资源时同一次写深色限定目录的同名键，已存在的资源文件只追加不覆盖

## 何时使用

页面转换或资源阶段，为主题色追加颜色资源键时

## 适用情境

源主题有 Light/Dark 两套调色板，并按系统深浅色选用（如 Compose 用 isSystemInDarkTheme() 选调色板）；目标颜色资源分 base 与 dark 限定目录，多个任务会分别追加，部分文件由模板预置。dark 目录里的值按应用当前的颜色模式选取：应用没调 setColorMode 时跟随系统，调了则以设定为准；源端只有一套调色板或固定一种外观的，不在这条范围内，不为它补 dark 值。

## 原因

只追加 base 键时深色下回落到浅色值；用整体写入覆盖已存在的资源文件，会删掉他人或模板写入的键（如启动窗背景色）。把深色值推给“后续任务”而无人承接时，这些键一直没有深色值。

## 做法

1. 为主题色追加 base 键时，同一次按源深色调色板写 dark 同名键。
2. 写前列出目标目录，文件已存在就先读再只追加，不用整体写入覆盖。

来源支持：1 张卡 · 1 次迁移 · 1 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因 / 做法第 1 步〕系统优先从与设备状态匹配的限定词目录找资源，限定词目录里找不到该资源时才去 base 目录：只写 base 键、dark 里没有同名键时，深色模式下显示 base 的浅色值
- 〔做法第 1 步〕颜色模式限定词 dark 表示深色模式、light 表示浅色模式；限定词目录名格式固定为「限定词/资源组」，深色颜色值放在 resources/dark/element/color.json
