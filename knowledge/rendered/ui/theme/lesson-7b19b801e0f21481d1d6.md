# 深浅主题与应用内色板状态放在可观察对象里并由入口同步，组件在渲染期从主题对象读取主题色：应用内切换色板时 build() 里的 $r 资源色不算

## 何时使用

主题层实现深浅色切换，以及组件、页面读取主题色（含对主题色做插值等数值运算）时（源端有多套色板、应用内切换或对主题色做数值运算时）

## 适用情境

源端 Theme(darkTheme = isSystemInDarkTheme()) 经 CompositionLocal 下发两套颜色，组件在组合期读取；目标用模块级主题函数与 $r 颜色资源实现，由入口读取系统 colorMode。也包括源端对 MaterialTheme.colorScheme 的颜色做数值插值（如按折叠比例 lerp 顶栏容器色），而 $r 资源不能直接参与运算。 也包括源端 MaterialTheme.colorScheme/typography 随多套色板、明暗与字号缩放在运行时取值，而页面转换时目标还没有全局响应式主题状态，或主题运行时归另一切片负责。源端只跟随系统深浅、只有一套色板、也不对主题色做数值运算时，目标颜色全部经 base/dark 同名的 $r 资源取值就会随系统切换自动换值，不必为此改成主题对象；已是这种写法的代码不在本条改动范围内。

## 原因

Compose 靠组合期读取随系统切换重组。目标端用普通模块变量保存深浅状态、组件在字段初始化器或 @Param 默认值里取一次色时，界面不会随切换刷新；同步函数没有调用点时深色永远不生效，编译照常通过。需要数值插值时，写者还容易因 $r 不能运算，把浅色色值复制成页面常量，深色下直接错色。

## 做法

1. 深浅状态放进 @ObservedV2 类的 @Trace 字段（或 AppStorageV2），入口 onCreate 与 onConfigurationUpdate 各调用一次同步。
2. 组件在 build() 或 get 访问器里读取主题色，不写进字段初始化器；颜色类 @Param 默认值设为 undefined，在 getter 里回落到主题色。 源端深浅档或调色板由应用内设置决定时，“渲染期读取”指从主题对象的当前色板读取，静态色同样如此；在 build() 里写 $r 资源只按系统（或 setColorMode）深浅解析一套值，不算满足本条。
3. 需要对主题色做数值插值时，端点从可观察主题对象当前色板的数值色读取（如 surface、surfaceContainer 对应项），在渲染期计算。主题层还没提供数值色板时，登记有负责方的前向引用，不把某一模式的色值复制成页面常量。
4. 页面与公共组件转换时把 MaterialTheme 的颜色与字体读值都按运行时主题处理：主题状态未建好时经单一主题访问入口引用或登记主题绑定的前向引用，不把某一色板的浅色值写成静态 $r 颜色或字号资源，也不直接 import 某一套色板常量对象（如只引用浅色板）取色；负责主题运行时的切片交付前提供界面可直接读取的全局主题状态（色板×明暗×字号），检索全工程静态主题资源引用，超出写盘范围的逐文件登记交接。

## 可选检查

- 有疑问时检索主题同步函数，确认 onCreate 与 onConfigurationUpdate 各有一处调用。

来源支持：5 张卡 · 5 次迁移 · 5 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因 / 做法第 1 步〕@ObservedV2 与 @Trace 要配合使用，单独用任一个没有作用；未被 @Trace 装饰的属性用在 UI 中无法感知变化、也不触发刷新；类要用 new 实例化后才具备被观测能力；@Trace 属性变化时刷新绑定它的组件
- 〔做法第 1 步〕Ability.onConfigurationUpdate 在系统配置（Configuration，含 colorMode）更新时回调，UIAbility 继承它
- 〔做法第 1 步〕AppStorageV2 是应用 UI 启动时创建的单例，数据在应用运行过程中保留，可经 connect 绑定同一个 key 跨 UIAbility 共享；AppStorage 与 AppStorageV2 的数据互不共享
- 〔做法第 2 步〕颜色模式限定词只表示颜色模式（dark、light），含颜色模式限定词的目录取值必须与当前状态完全一致才参与匹配；$r 颜色资源只在 base 与 dark 两套值之间选，没有应用内调色板这一维
- 〔原因 / 做法第 2 步〕组件在构造期（字段初始化器、@Param 默认值）取一次主题色时，即使主题状态本身可观察，深浅切换后这个组件也不重绘
