# 布局引用的 @drawable（progressDrawable、背景 shape、标签背景、光标 shape）先打开取数值：高度、圆角、轨道色、渐变、描边与光标宽色写进规格与实现

## 何时使用

规格提取与界面实现阶段，为进度条、搜索框、分组标签等引用 drawable 的控件确定高度、圆角、颜色与描边时

## 适用情境

源布局以 progressDrawable=@drawable/xxx、background=@drawable/bg_xxx 引用 layer-list/shape 资源，尺寸、圆角、轨道色、渐变和描边写在被引用文件里；目标工程可能已有名称相近、含义不同的颜色资源。也包括 EditText 用 textCursorDrawable 引用 shape 定义光标宽度与颜色，且只设在部分字段上。

## 例外与边界

- 被引用的是位图或九宫格（png、9.png、<bitmap>、<nine-patch>）时用图片承接（Image 或 backgroundImage），不改成纯色加圆角；第 3 步只管 shape
- 被引用的是 <selector>，或随选中、按压态切换的几份 shape 时，逐个状态打开取值并按状态落实（stateStyles 或随选中态切换的属性），不只取默认态那一份

## 原因

不打开被引用的 drawable，就只能自定高度或沿用工程里已有的颜色，样式与源端不符。来源两例：启动页规格作者列 drawable 目录的命令因 -LiteralPath 不支持通配符报错后未重试，进度条写成 4vp 高并沿用浅灰轨道色，而源端是 12dp、浅蓝轨道、圆角与渐变；城市选择页修复未读搜索框与分组标签的背景文件，分组标题色、搜索框描边与图标、网格外边距到第二轮才对齐。另一应用中，stage 资源转换把 shape 转成 24×24 的 SVG，映射参考又只有“@drawable/bg → backgroundImage”一条通用行：添加城市页写者读到了 SVG 的颜色与 rx，仍以 backgroundImage + Cover 铺到非方形容器；城市卡写者没打开源 shape（10dp 圆角与两种选中色），同样按图片铺设，圆角底色被缩放裁切。另一应用中写者没打开 login_edit_cursor_color，照同族页面把两个输入框都设成蓝色光标；该 shape 实为 2dp #ffdb20，且源端只给验证码框设置。

## 做法

1. 遇到 @drawable 引用就打开被引用文件，把高度、圆角、轨道/前景色、渐变与描边值写进规格和修饰链；不自定高度，不按名称套用工程里含义不同的颜色。进度条的高度先看 ProgressBar 的 layout_height：写的是 wrap_content 时，实际高度是 drawable 高度夹在样式 minHeight～maxHeight 之间的值（drawable 按控件高度拉伸）；目标 Progress 把这个高度同时写进 .height 和 .style({ strokeWidth })。
2. 列目录或读取命令报错（如 -LiteralPath 带通配符）时改用 -Path/-Filter 重试，未读到资源前不定稿；写后才读到的数值回写到已生成片段。
3. shape（solid + corners，有 stroke 再加描边）直接写成 backgroundColor + borderRadius（+ border；有 stroke 时把圆角写进 border 的 radius，或把 borderRadius 写在 border 之后）；不把转换得到的固定尺寸 SVG 以 backgroundImage + Cover 铺到非方形容器。
4. textCursorDrawable 引用的 shape 读出 solid 颜色与 size 宽度，写成 caretStyle({ width, color })；只给源端声明了它的字段设置，未声明的字段不带入；这些字段在安卓上显示主题默认光标（颜色取 colorControlActivated，AppCompat 主题下即 colorAccent），鸿蒙不写时为 '#007DFF'，主题色与它不同时给这些字段写 caretColor(主题色)。

- 〔做法第 1 步〕ProgressBar 的 progressDrawable 是 layer-list 时按层 id 取层：@android:id/progress（和 @android:id/secondaryProgress）这一层随进度设 level，@android:id/background 这一层不随进度变化、整条画出作轨道；layer-list 里找不到对应 id 的层时，level 设给整个 drawable
- 〔做法第 1 步〕进度层套在 <clip> 里、<clip> 没另写 android:clipOrientation 和 android:gravity 时，按横向、靠左裁，按进度比例只露出整条 shape 的左段：进度层里的 gradient 按整个控件宽度铺开、只显示左段，进度前端是裁出来的直边，shape 的圆角只在左端可见
- 〔做法第 1 步〕ProgressBar 的 layout_height 为 wrap_content 时，测量高度是 progressDrawable 的固有高度夹在 minHeight～maxHeight 之间的值（再加 padding），progressDrawable 按控件尺寸铺满拉伸；平台样式 Widget.ProgressBar.Horizontal 的 minHeight、maxHeight 都是 20dip，Widget.Material.ProgressBar.Horizontal 都是 16dip；布局或样式里写的 maxHeight 在 progressDrawable 之后读取，会覆盖按 drawable 抬高的上限
- 〔做法第 1 步〕Progress 重写了通用属性 backgroundColor：写在 Progress 上设的是进度条底色（轨道色），整个组件的背景色要写在包住 Progress 的外层容器上
- 〔做法第 1 步〕Progress 的 color 不写时 Linear 样式前景色为 '#ff007dff'；传 LinearGradient 给 Linear、Capsule 样式从 API 23 起生效，API 22 及以前传渐变会以默认主题色显示
- 〔做法第 1 步〕Linear 样式 Progress 的条宽 strokeWidth 不写时为 4.0vp（不支持百分比，非法值按默认）；圆角半径 strokeRadius 不写时为 strokeWidth / 2，取值范围 [0, strokeWidth / 2]，超出范围按默认值处理
- 〔做法第 1 步〕shape 的 <gradient> 没写 android:angle 时按 0 处理，即从左到右（startColor 在左、endColor 在右）；angle 取 45 的倍数定方向：90 为从下到上，180 为从右到左，270 为从上到下
- 〔做法第 1、3 步〕shape 的 <corners> 里 android:radius 作用于四个角，topLeftRadius、topRightRadius、bottomLeftRadius、bottomRightRadius 没写时各自取 radius 的值；四角相同时，radius 大于控件短边一半的按短边一半画
- 〔做法第 1、3、4 步〕ArkUI 的 Length 写 number 时单位是 vp，写不带单位的字符串（如 '10'）也按 vp
- 〔做法第 1、3 步〕ResourceColor 写字符串时 '#ff000000' 这类 8 位值按 argb 解析（与安卓 #AARRGGBB 同序）；写 number 时按数值大小判断格式，0x00ffffff 这类高位为 0 的值会按 rgb 解析，透明度丢失
- 〔做法第 3 步〕View 的 background drawable 按控件的整块尺寸设置边界、随控件拉伸；shape 里的 <size> 只抬高控件的最小宽高（getSuggestedMinimumHeight 取背景的最小高度），不固定控件尺寸
- 〔做法第 3 步〕backgroundImage 没设 backgroundImageSize 时按 ImageSize.Auto 显示，保持原图比例和尺寸、不随组件拉伸；ImageSize.Cover 保持宽高比缩放到两边都大于或等于显示边界，宽高比不同的容器上会裁掉一部分
- 〔做法第 3 步〕固定尺寸（24×24 viewBox）的圆角矩形 SVG 用 backgroundImage 加 ImageSize.Cover 铺到非方形容器时，设备上圆角随缩放被裁切，圆角底色缺失
- 〔做法第 3 步〕border() 不写 width 时边框宽度为 0（不显示），不写 radius 时圆角为 0，不写 color 时为 Color.Black；border 缺省 radius 或 color 时，写在它前面的 borderRadius、borderColor 不生效，要写在 border 之后
- 〔做法第 3 步〕shape 的 <stroke> 只有 dashWidth 大于 0 时才画虚线（线段长 dashWidth、间隔 dashGap），否则为实线；ArkUI 边框样式不写时为 BorderStyle.Solid，BorderOptions 的 dashGap、dashWidth 只在边框样式为虚线时生效
- 〔做法第 3 步〕layer-list 的 item 上 android:left/top/right/bottom 是这一层相对整块的内缩量，上层内缩后下层露出的那条边宽度等于内缩量；item 没写 width/height 时该方向 gravity 默认 fill_horizontal/fill_vertical（铺满），写了尺寸时默认 left/top，width、height 默认取该层的固有尺寸
- 〔做法第 4 步〕textCursorDrawable 引用的 drawable 画光标时，宽度取它的固有宽度（shape 的 <size android:width>），高度按文字行高拉伸，<size> 的 height 不起作用
- 〔做法第 4 步〕EditText 没写 textCursorDrawable 时：Theme.Material、Theme.Material.Light 下用平台 text_cursor_material（2dp 宽矩形，外加 2dp inset），着色取 ?attr/colorControlActivated，Theme.Material 下它等于 colorAccent；AppCompat 1.7.1 的主题在 API 21+ 继承 Theme.Material.NoActionBar、EditText 样式不覆盖 textCursorDrawable，并把 android:colorControlActivated 指到 AppCompat 的 colorControlActivated（默认 ?attr/colorAccent），即光标色为应用的 colorAccent；Theme.MaterialComponents.Light 系把 colorAccent 指到 colorSecondary（material 1.12.0）
- 〔做法第 4 步〕TextInput 不写 caretColor 时光标色为 '#007DFF'（Wearable 设备为 '#5EA1FF'）；CaretStyle 的 width 不写时为 '2vp'、color 不写时为 '#ff007dff'；caretColor 和 caretStyle 的 color 同时写时后写的生效；API 12 起两者也决定文本手柄颜色
