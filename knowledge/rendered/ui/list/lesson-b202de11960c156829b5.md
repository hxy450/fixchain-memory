# 列表项新增独立副行显示某字段时，主行的空值回退不再回退到同一字段

## 何时使用

界面实现阶段，迁移设备、联系人等列表项的主标题、副标题与空值回退文案，且目标比源端多出一行固定显示主行回退字段时

## 适用情境

源端列表项只有一个名称控件，名称为空时回退显示地址或 ID；目标布局另加了一行地址/ID 副标题；名称来自平台接口，无名条目较多。

## 原因

源端的“回退到地址”只在单行里成立；加了副行后仍回退到同一字段，无名条目两行显示相同的值。来源中蓝牙设备列表的写者读过源端单行适配器与布局，却在新增 MAC 副行的同时保留主行回退到 MAC，真机上 8 个设备两行都是 MAC。修复者认为平台对无名设备会把 MAC 当名称返回，这一点未在 SDK 声明中核实。

## 做法

1. 新增副行后，把主行空值回退改为“未知设备”等占位文案，副行固定展示该字段。
2. 写完按“有名称 / 名称为空 / 名称等于副行字段”三种样本逐行自检，不出现两行相同。
3. 平台接口可能把地址当名称返回时，在模型或服务的单一入口把空白、与地址相同（忽略分隔符和大小写）的名称归一为无名称，扫描、已配对、已连接等来源共用。

来源支持：1 张卡 · 1 次迁移 · 1 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 3 步〕connection.getRemoteDeviceName(deviceId, alias?) 不传 alias 时默认取设备别名（API 16 起的重载）；声明没有写对没有名称的设备返回什么
- 〔原因 / 做法第 3 步〕安卓 BluetoothDevice.getName() 在蓝牙服务不可用、蓝牙未开启或取名出错时返回 null，取到的名称会把制表符和换行替换成空格
