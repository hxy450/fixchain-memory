# 列表长按上下文菜单按源 onCreateContextMenu 契约逐项移植

## 何时使用

功能切片接线阶段，为列表页与首页区段实现条目长按交互和上下文菜单、且源端经 registerForContextMenu 与 onCreateContextMenu 弹出菜单时

## 适用情境

源经 registerForContextMenu 与 onCreateContextMenu 弹出菜单：选择模式中直接返回、设置标题、共享准备函数决定可见项、multi_select 默认隐藏仅子类开放；目标在多个页面、共享组件和区段组件中移植。

## 例外与边界

- 源端上下文菜单只有含可见项时才弹出：可见性函数算完一项都不可见（或选择态提前返回）时，目标端不弹菜单，不显示只有标题的空弹层。

## 原因

照兄弟页把长按直接接到进入多选、自拟可见项与顺序、漏标题与选择态守卫、在区段内放页内浮层，都会让菜单与源不一致。

## 做法

1. 长按弹菜单，multi_select 才进多选；选择态长按提前返回；设标题；可见性调用已移植的共享准备函数，按菜单 XML 膨胀顺序输出（读 XML 时保留 android:visible）。
2. 区段、卡片组件用 openCustomDialog 等全局弹层承载菜单；宿主不开放多选时不渲染 multi_select。
3. 规格条款与 UI 阶段写法冲突时按条款与源码改，不以“已接受的简化”保留。

来源支持：1 张卡 · 1 次迁移 · 1 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 做法第 1 步〕Fragment、Activity 的 registerForContextMenu(view) 把 view 的 OnCreateContextMenuListener 设成自己，长按该 view 时回调 onCreateContextMenu 构建上下文菜单
- 〔做法第 1 步〕上下文菜单只有在含可见菜单项时才弹出：onCreateContextMenu 提前返回、一项都没加时，不显示菜单
- 〔做法第 1 步〕MenuInflater 膨胀菜单 XML 时，item 没写 android:visible 就取所在 group 的可见性，group 也没写时默认可见；写了 android:visible="false" 的项膨胀后是隐藏的，要代码 setVisible(true) 才出现
- 〔做法第 1 步〕菜单项没写 android:orderInCategory 时 order 默认 0，插入时排在最后一个 ordering 不大于它的项之后，所以菜单顺序就是 XML 里 item 的先后
- 〔做法第 1 步〕上下文菜单里某一项被选中时回调 onContextItemSelected；Fragment 子类没有重写它时返回 false
- 〔做法第 2 步〕bindSheet 给组件绑定的是半模态页面，显隐由 isShow 控制，不是锚在条目旁的浮动菜单
