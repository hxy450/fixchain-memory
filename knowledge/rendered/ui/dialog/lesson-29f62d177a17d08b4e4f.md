# 依附式弹窗（AttachPopup）的宿主按锚点视图所在页面确定：提示挂在锚点页、按锚点实测坐标定位，弹出条件包含锚点可见

## 何时使用

迁移审计与实现阶段，判定依附式弹窗的宿主归属、改写触发它的子页逻辑时

## 适用情境

源端弹窗由子 Fragment 触发 show，但 atView 是父 Fragment 标题栏里的按钮，且只在该按钮可见、一次性标记未写入时显示；目标端已有一个画在子页内部、按固定边距定位的同文案浮层。

## 原因

按“哪个类调用了 show”归属，会把父页锚点提示当成子页内联实现：浮层坐标脱离锚点，锚点不可见时也可能出现，提示状态成了子页私有副本，其他逻辑还会依赖它。来源中审计者读到了 atView 锚点与可见条件，仍把子页内固定边距的气泡判为“已内联等价、可删”，随后又在子页用该私有状态守卫其他引导。

## 做法

1. 以 atView 锚点所在页面为宿主，在该页用锚点实测坐标（组件区域或全局位置）定位箭头与气泡，不在触发它的子页按固定边距绘制。
2. 把源端弹出条件逐项映射：锚点可见（如按钮只在特定状态显示）、一次性标记的读取与关闭时写入；锚点在目标端从未变为可见时，先修锚点的驱动链，再判定提示是否等价。
3. 子页需要依赖“提示是否显示”时，经回调或参数读取宿主页状态，不引用子页私有副本。

来源支持：1 张卡 · 1 次迁移 · 1 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1 步〕onAreaChange 在组件因布局变化导致大小、位置变化后回调；translate、offset、markAnchor、scale、transform 引起的位置变化不触发它
- 〔做法第 1 步〕onAreaChange 回调里的 Area.width、height 单位 vp；Area.position 是左上角在父组件坐标系中的位置，Area.globalPosition 是左上角在当前窗口坐标系中的位置
- 〔做法第 2 步〕View.isShown() 只有在该视图和它所有祖先都是 VISIBLE、且已挂到视图根上时才返回 true
- 〔做法第 2 步〕Preferences.putSync 只改内存中的 Preferences 对象，要调 flush 才把它写入文件
- 〔做法第 3 步〕@Prop 与父组件单向同步：父组件状态变量的变化同步给子组件；子组件对 @Prop 变量的本地修改不回传父组件，数据源再变化时会覆盖本地修改
- 〔做法第 3 步〕@Link 与父组件状态变量双向同步，任一方改变另一方随之更新
