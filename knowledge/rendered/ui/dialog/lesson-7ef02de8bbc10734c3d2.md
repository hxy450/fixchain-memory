# 源端在当前页 show 的底部弹窗保持叠在宿主页上：“路由统一用某框架”只约束页面跳转，不把弹窗改成路由页

## 何时使用

规格提取阶段把在当前 Activity 上 show、不入返回栈的 Android Dialog/BottomSheet 的呈现方式映射到 ArkUI 承载方式时；界面实现阶段落实弹窗内的二级日历或选择弹层时

## 适用情境

Android 入口经 bottomDialog/Dialog 在当前 Activity 上 show 全宽底部面板（遮罩下仍见宿主页、点背景关闭、不入返回栈），面板内再弹同类底部选择器；目标工程有“路由统一使用 HMRouter/Navigation”的约束，且已有同名路由页可复用。

## 例外与边界

- 目标用 Navigation 承载、把这个路由页设为 NavDestinationMode.DIALOG 时，页面默认透明，入栈出栈不影响下层页面的生命周期，下层宿主页保持可见，满足第 2 步的“宿主页可见”，不必为此改回同页叠层；遮罩与点背景关闭仍按第 2 步逐项确认

## 原因

路由页会带来独立页面栈、伪造的遮罩和不同的关闭方式；路由约束管的是页面间跳转，不决定弹窗形态。来源中规格作者正确记录了“全宽底部弹窗”，却援引路由决策写成“用路由页承载等价弹层”，执行者据此把记账面板做成路由页并以半透明色块伪装遮罩；规格明确要求的日历弹层又被插进 layoutWeight 内容列，被键盘面板挤压；用户多轮反馈后才改为宿主页内顶层叠层与半屏日历。

## 做法

1. 规格把源端呈现方式写成验收契约：叠在宿主页之上、遮罩下可见宿主页、点背景或取消关闭、不新增返回栈；映射为宿主页内 Stack 顶层叠层或 bindSheet/自定义弹窗，关闭回调由宿主持有。
2. 选用非同页承载时，先确认该机制能保留宿主页可见与点背景关闭，并在验收中写明对应检查。
3. 弹窗内的二级日历或选择器放在根 Stack 顶层（遮罩加底部半屏容器），覆盖面板和键盘；不在受 layoutWeight 约束的内容列里插入可见性切换块。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1、2 步〕bindSheet 的 SheetOptions 没写 onWillDismiss 时，下拉、返回键、点击蒙层或关闭图标都会立即关闭半模态
- 〔做法第 1、2 步〕bindSheet 的 SheetOptions 没写 height 时为 SheetSize.LARGE；底部弹窗竖屏时最大高度到距状态栏 8vp 处
- 〔原因 / 做法第 3 步〕zIndex 只决定同一容器内兄弟组件之间的层级，值大的在上
- 〔原因 / 做法第 3 步〕设了 layoutWeight 的子组件按权重分配父容器（Row、Column、Flex）主轴上的空间；layoutWeight 默认值为 0
