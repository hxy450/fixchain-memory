# ComponentContent 构造即执行 builder：构造后才赋值的回调以延迟调用传入

## 何时使用

界面实现阶段，用 ComponentContent 加 wrapBuilder 加 openCustomDialog 封装弹窗并接线关闭、确认回调时

## 适用情境

关闭回调需要构造后才得到的 content 句柄，只能在 new ComponentContent(...) 之后赋给 args；内容组件以 @Param 接收回调。 回调在 new ComponentContent(...) 之前就已赋好、之后不再改的，构造时取到的就是真值，直接以 xxx: args.xxx 传入没有问题，不在改写范围内。

## 原因

builder 在构造时就执行，@Param 拿到的是当时的空默认值；之后再给普通 args 对象赋值不会传入已构建的内容，按钮失效。

## 做法

1. builder 中写 onX: (...): void => args.onX(...)，或把 args 整体传给内容组件、在点击时读取。

## 可选检查

- 复用同族弹窗或按钮无反应时，对每个 new ComponentContent(..., args) 向后查 args.xxx = 赋值，并看 builder 是否以 xxx: args.xxx 直接传入

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 未用。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因〕new ComponentContent(uiContext, wrapBuilder(builder), args) 构造时 builder 就执行，内容组件的 @Param 取的是构造当时 args 字段的值；构造完成之后给同一个普通 args 对象的字段赋值，已构建内容里的 @Param 不变，按钮调用的仍是构造时的默认回调
- 〔原因〕ComponentContent 的内容不随参数自动刷新，要通过 update(args) 手动更新 builder 参数（参数类型与构造时一致）；需要响应式自动更新的是 ReactiveComponentContent
