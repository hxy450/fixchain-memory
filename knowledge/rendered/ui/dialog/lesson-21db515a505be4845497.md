# 按源弹层类型逐个选呈现形态：居中 CustomDialog/AlertDialog（含框架生成的 ListPreference 选项框：无确定钮、留 CANCEL）用居中卡片，底部面板才用 bindSheet，锚定菜单按锚点弹出；形态不同的面板不共用一个弹窗；定长密码框输满即校验

## 何时使用

页面接线与界面实现阶段，为源端 DialogHelper 一类函数弹出的确认或输入弹窗选择承载形态与校验触发方式时；对齐同页多个工具面板（如阅读页的设置、更多、发弹幕）的容器、锚点与交互步骤时

## 适用情境

源端经 CustomDialog/AlertDialog 加自定义布局弹出居中卡片，卡内可能有定长格子密码框（输满即比对、失败提示），根视图点击关闭；目标公共弹窗封装只有确认/提示类，带输入的弹窗需要在页面内自建。也包括源端同页多个工具面板容器各不相同（底部 PopupWindow 面板、锚定在标题栏右上角带箭头的弹出菜单、先编辑再在内容上拖动定位的多步弹层），目标现有实现用一个固定高度、带拖动条与关闭按钮的 bindSheet 承载全部面板。也包括源端 MaterialAlertDialogBuilder（含 setView 输入、下拉）对话框，工程惯例或规格并列给出 bindSheet/CustomDialog。也包括 AlertDialog.Builder…setView(ListView) 的列表选择框被规格写成 bindSheet 半模态加 List；按钮的上下文菜单被写成锚定 bindPopup 或 bindMenu，丢了长按入口与标题图标。也包括 android.preference.ListPreference 的选项对话框：由框架生成的居中 AlertDialog，代码中看不到 Builder，规格却写成 Select 或 bindSheet。 改换承载形态时保留源对话框的取消路径：源端没有 setCancelable(false) 时返回键能取消、点外是否关闭照源端；居中卡片用页内条件浮层承载时返回键不由系统代管，要在页面返回回调里先关最上层弹窗，打开弹窗时按返回只关弹窗、页面仍在。

## 原因

以“带输入的模态最简单”为由改成底部 sheet，会同时改变呈现形态、关闭方式和校验时机（多出确定按钮、失败没有提示）。 共用一个弹窗组件再改底色与文字，位置、拖动条、关闭按钮、选中样式与后续步骤仍与源端不同。另一应用的阅读页已读到逐面板差异与 Android 实拍，仍只把共用 bindSheet 改成深色并称已对齐；后一轮改发弹幕面板时也只改了字数上限，拖动定位步骤一直缺失。

## 做法

1. 居中卡片类（CustomDialog、AlertDialog）用页内条件浮层（遮罩 + 居中卡片）或 CustomDialog/ComponentContent 实现；只有源端是 BottomSheetDialog 一类时才用 bindSheet，不因弹窗里有输入框就改成半模态。
2. 复刻定长格子密码框时保留格数与尺寸，输入长度达到位数即自动比对；源端没有确定按钮就不加，失败提示取源端文案。
3. 同页多个源面板逐个列出容器类型（底部面板、锚定弹出菜单、全屏覆盖层）、锚点、宽高，以及有无标题、拖动条和关闭按钮；只有这些一致时才共用一个弹窗组件，否则拆成各自布局与打开方式（锚定菜单用 bindPopup 或按锚点定位的覆盖层）。
4. 源面板是多步交互（如编辑文字 → 在内容上拖动定位 → 确认或取消）时，每一步的状态与切换都要实现；只改字数上限、占位文案或标题不算对齐。
5. MaterialAlertDialogBuilder（含 setView）对应居中模态，BottomSheetDialog 对应 bindSheet；规格并列给出两种形态时按源码择一，不以“本工程既定用 bindSheet”替换。
6. AlertDialog（含 setView(ListView) 列表选择）映射为居中模态对话框；上下文菜单区分点击 openContextMenu（无坐标的居中模态列表，带 header 标题与图标）与已 registerForContextMenu 视图的长按（触点锚定的浮动菜单），两条入口都实现。
7. ListPreference 选项对话框映射为居中模态：无确定钮、有 CANCEL 负按钮，取消路径为 CANCEL、点外与返回，选中即写入并关闭；外观按平台默认 AlertDialog 复刻（遮罩、卡宽、圆角、标题、单选圆环），不套用目标平台卡片样式。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36 的平台资源；android-36.1 的源码；com.google.android.material:material 1.4.0、1.14.0。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1 步〕源端没有调 AlertDialog.Builder.setCancelable 另设时，可取消默认为 true，返回键能取消；点外部取消还要求窗口的 closeOnTouchOutside 为真（Material 对话框主题取 config_closeDialogWhenTouchOutside，values 下为 true）
- 〔做法第 1 步〕promptAction.BaseDialogOptions.levelMode 默认 LevelMode.OVERLAY（弹窗显示在所有页面之上）；LevelMode.EMBEDDED 让弹窗显示在当前页面内
- 〔做法第 1 步〕BaseDialogOptions.onWillDismiss 在用户交互关闭弹窗（返回键、点蒙层等）时回调，回调参数 DismissDialogAction 带 reason 和 dismiss()：DismissReason.PRESS_BACK = 0 是返回键，TOUCH_OUTSIDE = 1 是点蒙层
- 〔做法第 3 步〕SheetOptions.showClose 默认 true（显示系统关闭按钮）；dragBar 默认 true，但只有 detents 设了多档且生效时才显示拖拽条
- 〔做法第 3 步〕SheetOptions.preferType 受窗口宽度限制：宽度 < 600vp 时只支持 bottom；600vp 起才支持 bottom、center、popup：手机竖屏上 bindSheet 只能从底部弹出
- 〔做法第 3、6 步〕ContextMenuOptions.placement：作为 bindMenu 入参时默认 Placement.BottomLeft；作为 bindContextMenu（8+ 那个重载）入参时默认菜单跟随点击位置弹出；作为 bindContextMenu（12+ 带 isShown 的重载）入参时默认 Placement.BottomLeft
- 〔做法第 5 步〕Material3 的 MaterialAlertDialog（material 1.14.0）：底色取 ?attr/colorSurfaceContainerHigh，圆角取 ?attr/shapeAppearanceCornerExtraLarge（28dp），卡片左右各缩进 mtrl_alert_dialog_background_inset_start / _end = 24dp，遮罩不透明度 m3_comp_scrim_container_opacity = 0.32
- 〔做法第 6 步〕Activity.openContextMenu(view) 以程序方式为已 registerForContextMenu 的视图打开上下文菜单（内部调 view.showContextMenu()，没有触点坐标）；registerForContextMenu(view) 给视图设 OnCreateContextMenuListener，该视图另有长按弹出上下文菜单的入口
- 〔做法第 7 步〕android.preference.ListPreference 的选项对话框用 setSingleChoiceItems 列出选项并 setPositiveButton(null, null)，没有确定钮；点选某项即按正键处理（写入值）并关闭对话框
- 〔做法第 7 步〕应用没有给 DialogPreference 另设按钮文案时，平台 Preference.DialogPreference 样式的 negativeButtonText 为 @string/cancel、positiveButtonText 为 @string/ok；AlertController 对文案为空的按钮 setVisibility(View.GONE)
