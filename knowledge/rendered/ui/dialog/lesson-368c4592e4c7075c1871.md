# 源端 XPopup/DialogFragment 真弹窗（居中、锚点、底部）迁成可关闭的系统弹窗或半模态，不以页面可见性叠层充当

## 何时使用

迁移实现、弹窗恢复与宿主接线阶段，为 Android 真弹窗（DialogFragment、XPopup Center/Attach/Bottom 类）确定 ArkUI 承载形态，或为已有弹窗补触发、宿主、去掉路由时

## 适用情境

源端通过 DialogFragment、XPopup CenterPopupView/AttachPopupView 等在当前 Activity 上弹出提示、升级、菜单或锚点气泡，点击遮罩或返回即关闭；目标工程里已有以 @Local visible/visibility 或 if 条件渲染的 Stack + 遮罩叠层，或派工只写“接到现有弹窗”“恢复可关闭的页面内弹层”。也包括源弹窗继承 BottomPopupView 一类底部弹窗基类，计划或决策已写明映射到 showBindSheet/系统半模态，而现有实现是 NavDestination 路由页或由 @Param 可见性驱动、内嵌在宿主页的全屏 Stack（自绘遮罩、PanGesture 下拉关闭、返回信号参数）。 也包括 BottomSheetDialogFragment 被写成标准模式的 NavDestination 路由页，在页内自绘蒙层与底板，调用方随之 pushPathByName。也包括源端 BottomSheetDialogFragment 的宿主页在目标中嵌在壳内容区（标题栏、底部导航由外层提供），写者为回避同节点第二个 bindSheet 改用页内浮层。也包括 AlertDialog.Builder 构造、默认可取消的对话框，为满足“每个组件 @ComponentV2 导出”被写成自带蒙层的共享页内浮层，注释称覆盖返回键而实现只接蒙层点击。

## 例外与边界

- 项目决策明确采用页内浮层，且浮层已实现遮罩点击、返回键与页面离开关闭并只回调一次

## 原因

页面叠层只在宿主页 Stack 里条件渲染，遮罩没有点击处理、宿主不拦返回键时，空白点击与返回都关不掉；把它当作现成弹窗接线，或以“宿主化、恢复关闭回调”为完成标准，会让同一批次里部分弹窗改成真弹窗、其余仍是叠层。来源中执行者写前已读到形态选择表（CenterPopupView 对应真弹窗）与 Android 端的真弹窗实现，同一补丁把评分改为 showCustomDialog，通知提示与升级却只置 visible 标志条件渲染；另一条链是编排者收到用户“xpopup 弹窗都是页面组件、关不掉”的反馈，却把交接写成“恢复页面内弹层的关闭与回调”，下游据此保留了颜色选择叠层。同一交接下的底部弹窗是另一来源：计划已批准“BottomPopup → showBindSheet”并有已验证样板，根会话自己把日期弹层从路由页改成可见性参数驱动、内嵌宿主页的全屏 Stack（自绘遮罩、下拉阈值关闭），弹窗能关闭了，仍是页面组件。

## 做法

1. 先按源端类定形态：居中类（DialogFragment、CenterPopupView）用 UIContext.getPromptAction().openCustomDialog 或项目已采用的弹窗库（如 @pura/harmony-dialog 的 showCustomDialog）；锚点类（AttachPopupView）用 bindPopup 或按锚点全局坐标定位的自定义弹窗；底部类（BottomPopupView、底部 DialogFragment）用 bindSheet、UIContext.openBindSheet 或项目弹窗库已有的 showBindSheet 一类封装承载系统半模态；@ComponentV2 页面不用 CustomDialogController 承载 V2 组件。
2. 目标里已有 @Local 可见性 + Stack/遮罩的实现视为待替换对象：接线时改为真弹窗 API，打开遮罩点击与返回关闭（系统弹窗接口里点遮罩由 autoCancel 控制、返回键默认关闭，要拦截时用 onWillDismiss；backCancel 不是鸿蒙 SDK 的选项，只在项目弹窗库提供时使用），在 onDidDisappear 中单次清理状态（退场动画没走完时它不触发，例如关闭弹窗与页面切换同时发生），页面 aboutToDisappear 时主动关闭残留弹窗（默认层级的弹窗不随页面路由切换关闭）。
3. 规划或交接弹窗批次时把“真弹窗、可关闭”写成形态契约，对清单里的每个弹窗记录承载形态；同一批次已有弹窗改用真弹窗 API 时，把其余仍是条件渲染的逐个改掉，不以补可见性赋值收尾。
4. “去掉路由、能关闭”不等于完成映射：可见性参数 + 全屏 Stack + 自绘遮罩 + 手势阈值关闭属于待替换的形态；交接与执行日志原样引用映射目标 API，不改述成泛化的“页面内弹层”。
5. 源类为 BottomSheetDialogFragment/DialogFragment、规格 page_type 为 modal_overlay 或 dialog 时，不用标准 NavDestination 加自绘蒙层模拟；要用路由承载就显式 .mode(NavDestinationMode.DIALOG)，否则用 openCustomDialog/bindSheet。调用方接入已转换的弹层前，对照源端 show(childFragmentManager, …) 确认目标提供的是弹层入口；目标只暴露路由页时先修正呈现方式。
6. 宿主页嵌在壳内容区时，页内浮层只能覆盖标题栏与底栏之间；源端底部面板用零尺寸锚点上的窗口级 bindSheet 或共享面板组件承载，定样式前把面板子项布局一并读完。
7. AlertDialog 一类居中对话框优先用 openCustomDialog（页面级用 LevelMode.EMBEDDED，返回键与点外经 onWillDismiss 走取消回调）或 showDialog，由系统处理返回；保留页内浮层时同时交付返回键契约。

## 可选检查

- 对形态存疑时逐个弹层核对：弹层文件是否调用系统弹窗/半模态 API，宿主页是否只持有控制器，而不是可见性状态加内嵌组件。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1、7 步〕PromptAction（UIContext.getPromptAction() 取得）的 openCustomDialog 有两个重载：openCustomDialog<T extends Object>(dialogContent: ComponentContent<T>, options?: promptAction.BaseDialogOptions): Promise<void>（@since 12，错误码 103301 内容不对、103302 内容已打开），配 closeCustomDialog<T extends Object>(dialogContent: ComponentContent<T>): Promise<void>；openCustomDialog(options: promptAction.CustomDialogOptions): Promise<number>（@since 12，返回 dialogId），配 closeCustomDialog(dialogId: number): void；另有 openCustomDialogWithController(dialogContent, controller: promptAction.DialogController, options?)（@since 18）
- 〔做法第 1 步〕ComponentContent 的构造器（@since 12，从 @kit.ArkUI 导入）：constructor(uiContext: UIContext, builder: WrappedBuilder<[]>)、constructor(uiContext: UIContext, builder: WrappedBuilder<[T]>, args: T)，以及多带一个 BuildOptions 的重载；builder 用 wrapBuilder 包一个全局 @Builder
- 〔做法第 1 步〕状态管理 V1 与 V2 能力对比表里，V1 的 @CustomDialog 在 V2 对应 openCustomDialog 接口，文档写「V2 建议使用 openCustomDialog 实现自定义弹窗功能」
- 〔做法第 1、6 步〕CommonMethod.bindSheet(isShow: boolean, builder: CustomBuilder, options?: SheetOptions): T（@since 10）；SheetOptions.dragBar 默认 true，maskColor 可设遮罩色，mode?: SheetMode 默认 SheetMode.OVERLAY（@since 12）；SheetMode.OVERLAY 在当前 UIContext 内顶层显示、在所有页面之上、和弹窗类组件同一层级；SheetMode.EMBEDDED 在当前页面内顶层显示，只挂在 Page 或 NavDestination 上，新起的页面可以盖住它，返回后它仍在
- 〔做法第 1、6 步〕UIContext.openBindSheet<T extends Object>(bindSheetContent: ComponentContent<T>, sheetOptions?: SheetOptions, targetId?: number): Promise<void>（@since 12）以 ComponentContent 为内容弹出半模态，不需要把 bindSheet 写在某个组件上；配 updateBindSheet、closeBindSheet(bindSheetContent)，bindSheetContent 要自己保存；没传有效 targetId 时不支持 SheetOptions.mode 设为 EMBEDDED（按 OVERLAY）和 preferType 设为 POPUP（按 CENTER）
- 〔做法第 1 步〕CommonMethod.bindPopup(show: boolean, popup: PopupOptions | CustomPopupOptions): T（@since 7）把气泡绑在锚点组件上，show 默认 false
- 〔做法第 2 步〕BaseDialogOptions（openCustomDialog 的选项）：autoCancel（@since 12）点遮罩是否关闭，默认 true；isModal 默认 true（模态、有蒙层）；maskColor（@since 12）默认 0x33000000；onWillDismiss（@since 12）注册后点遮罩、侧滑、三键 back、键盘 ESC 都不立即关闭，在回调里按 reason 决定，reason 暂不返回 CLOSE_BUTTON；onDidDisappear（@since 12）在弹窗消失后回调，退场动画没走完（如同时触发关闭和页面切换）时不触发
- 〔做法第 2、7 步〕LevelMode（@since 15，BaseDialogOptions.levelMode 默认 OVERLAY，只在 showInSubWindow 为 false 时生效）：OVERLAY = 0，弹窗挂在应用窗口根节点，应用内路由导航切换时不隐藏；EMBEDDED = 1，弹窗是页面内路由/导航下的节点，随页面切换一起隐藏，只支持挂在 Page 或 NavDestination 上，新起的页面可以盖住它、返回后弹窗仍在，拉起时目标页面节点须已挂上树，否则挂不进该页面
- 〔做法第 2 步〕ArkUI 弹出框默认不是页面级的：页面路由跳转时没调用 close 关闭，弹出框不会自动关闭；要随页面被覆盖用 NavDestination 的弹窗类型或页面级弹出框
- 〔做法第 7 步〕DismissDialogAction 有 dismiss（调用后关闭）和 reason 两个字段；DismissReason（@since 12）：PRESS_BACK = 0（返回键、侧滑、ESC）、TOUCH_OUTSIDE = 1（点遮罩）、CLOSE_BUTTON = 2、SLIDE_DOWN = 3
- 〔做法第 2 步〕CustomDialogControllerOptions：autoCancel 默认 true；cancel 在返回键、ESC、点遮罩退出时回调；onWillDismiss（@since 12）；onDidDisappear（@since 19）；文档说明按下返回键和 ESC 会让弹窗退出；鸿蒙 SDK 的 CustomDialogControllerOptions 和 BaseDialogOptions 里都没有 backCancel
- 〔做法第 7 步〕PromptAction.showDialog(options: promptAction.ShowDialogOptions): Promise<promptAction.ShowDialogSuccessResponse>（@since 10，另有 AsyncCallback 重载）弹出系统样式的对话框
- 〔做法第 5 步〕NavDestinationAttribute.mode(value: NavDestinationMode)（@since 11）：STANDARD = 0 为默认的标准页；DIALOG = 1 默认透明，进出路由栈不影响下层 NavDestination 的可见性（不触发 onShown、onHidden），只触发 onActive、onInactive；API 13 之前 DIALOG 默认没有系统转场动画，API 13 起支持
- 〔例外与边界 / 做法第 7 步〕NavDestinationAttribute.onBackPressed(callback: () => boolean)（@since 10）：与 Navigation 绑定的导航控制器里有内容时生效，按返回键时触发；返回 true 表示重写返回键逻辑，返回 false 表示回退到上一个页面
