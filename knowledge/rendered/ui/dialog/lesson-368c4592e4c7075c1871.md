# 源端 XPopup/DialogFragment 真弹窗（居中、锚点、底部）迁成可关闭的系统弹窗或半模态，不以页面可见性叠层充当

## 何时使用

迁移实现、弹窗恢复与宿主接线阶段，为 Android 真弹窗（DialogFragment、XPopup Center/Attach/Bottom 类）确定 ArkUI 承载形态，或为已有弹窗补触发、宿主、去掉路由时

## 适用情境

源端通过 DialogFragment、XPopup CenterPopupView/AttachPopupView 等在当前 Activity 上弹出提示、升级、菜单或锚点气泡，点击遮罩或返回即关闭（这条只管源端以独立窗口弹出的这几类；源端本身就是 Activity 布局里按 visibility 显隐的 View，如页内遮罩、加载层、展开面板，目标用条件渲染叠层承载是对的，保持原样）；目标工程里已有以 @Local visible/visibility 或 if 条件渲染的 Stack + 遮罩叠层，或派工只写“接到现有弹窗”“恢复可关闭的页面内弹层”。也包括源弹窗继承 BottomPopupView 一类底部弹窗基类，计划或决策已写明映射到 showBindSheet/系统半模态，而现有实现是 NavDestination 路由页或由 @Param 可见性驱动、内嵌在宿主页的全屏 Stack（自绘遮罩、PanGesture 下拉关闭、返回信号参数）。 也包括 BottomSheetDialogFragment 被写成标准模式的 NavDestination 路由页，在页内自绘蒙层与底板，调用方随之 pushPathByName。也包括源端 BottomSheetDialogFragment 的宿主页在目标中嵌在壳内容区（标题栏、底部导航由外层提供），写者为回避同节点第二个 bindSheet 改用页内浮层。也包括 AlertDialog.Builder 构造、默认可取消的对话框，为满足“每个组件 @ComponentV2 导出”被写成自带蒙层的共享页内浮层，注释称覆盖返回键而实现只接蒙层点击。

## 例外与边界

- 项目决策明确采用页内浮层，且浮层已实现遮罩点击、返回键与页面离开关闭并只回调一次
- 源端关掉了某种关闭方式的（setCancelable(false)、setCanceledOnTouchOutside(false)，或弹窗库里关掉点外、返回关闭的开关），目标照样关掉对应方式（autoCancel: false，或在 onWillDismiss 里按 reason 只放行源端允许的那种），不统一打开遮罩与返回关闭
- 换成系统弹窗或半模态时只换承载：弹层内容、按钮的个数与文案、各按钮的回调、点选后关不关（如源端点排序项只原地刷新、不 dismiss）都照源端，不借换形态增减按钮或改关闭时机

## 原因

页面叠层只在宿主页 Stack 里条件渲染，遮罩没有点击处理、宿主不拦返回键时，空白点击与返回都关不掉；把它当作现成弹窗接线，或以“宿主化、恢复关闭回调”为完成标准，会让同一批次里部分弹窗改成真弹窗、其余仍是叠层。来源中执行者写前已读到形态选择表（CenterPopupView 对应真弹窗）与 Android 端的真弹窗实现，同一补丁把评分改为 showCustomDialog，通知提示与升级却只置 visible 标志条件渲染；另一条链是编排者收到用户“xpopup 弹窗都是页面组件、关不掉”的反馈，却把交接写成“恢复页面内弹层的关闭与回调”，下游据此保留了颜色选择叠层。同一交接下的底部弹窗是另一来源：计划已批准“BottomPopup → showBindSheet”并有已验证样板，根会话自己把日期弹层从路由页改成可见性参数驱动、内嵌宿主页的全屏 Stack（自绘遮罩、下拉阈值关闭），弹窗能关闭了，仍是页面组件。

## 做法

1. 先按源端类定形态：居中类（DialogFragment、CenterPopupView）用 UIContext.getPromptAction().openCustomDialog 或项目已采用的弹窗库（如 @pura/harmony-dialog 的 showCustomDialog）；锚点类（AttachPopupView）用 bindPopup 或按锚点全局坐标定位的自定义弹窗；底部类（BottomPopupView、底部 DialogFragment）用 bindSheet/showBindSheet 等系统半模态；@ComponentV2 页面不用 CustomDialogController 承载 V2 组件。
2. 目标里已有 @Local 可见性 + Stack/遮罩的实现视为待替换对象：接线时改为真弹窗 API，打开遮罩点击与返回关闭（系统弹窗的 autoCancel 默认 true、返回键默认关闭，注册了 onWillDismiss 就要在回调里调 dismiss；backCancel 一类开关只出自所用的弹窗库），在 onDidDisappear 中单次清理状态，页面 aboutToDisappear 时主动关闭残留弹窗，并在这里补做那次单次清理（弹窗关闭与页面切换同时发生、退场动画没做完时 onDidDisappear 不触发；LevelMode.OVERLAY 的弹窗不会随路由切换隐藏）。
3. 规划或交接弹窗批次时把“真弹窗、可关闭”写成形态契约，对清单里的每个弹窗记录承载形态；同一批次已有弹窗改用真弹窗 API 时，把其余仍是条件渲染的逐个改掉，不以补可见性赋值收尾。
4. “去掉路由、能关闭”不等于完成映射：可见性参数 + 全屏 Stack + 自绘遮罩 + 手势阈值关闭属于待替换的形态；交接与执行日志原样引用映射目标 API，不改述成泛化的“页面内弹层”。
5. 源类为 BottomSheetDialogFragment/DialogFragment、规格 page_type 为 modal_overlay 或 dialog 时，不用标准 NavDestination 加自绘蒙层模拟；要用路由承载就显式 .mode(NavDestinationMode.DIALOG)，否则用 openCustomDialog/bindSheet。调用方接入已转换的弹层前，对照源端 show(childFragmentManager, …) 确认目标提供的是弹层入口；目标只暴露路由页时先修正呈现方式。
6. 宿主页嵌在壳内容区时，页内浮层只能覆盖标题栏与底栏之间；源端底部面板用零尺寸锚点上的窗口级 bindSheet 或共享面板组件承载，定样式前把面板子项布局一并读完。
7. AlertDialog 一类居中对话框优先用 openCustomDialog（页面级用 LevelMode.EMBEDDED，返回键与点外经 onWillDismiss 走取消回调）或 showDialog，由系统处理返回；保留页内浮层时同时交付返回键契约。

## 可选检查

- 对形态存疑时逐个弹层核对：弹层文件是否调用系统弹窗/半模态 API，宿主页是否只持有控制器，而不是可见性状态加内嵌组件。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码；android-36 的平台资源。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 做法第 7 步〕应用没有另设可取消性（没调 setCancelable）时，安卓 android.app.AlertDialog.Builder 建出的对话框可取消（默认 true），create() 在可取消时同时 setCanceledOnTouchOutside(true)，所以返回键和点对话框外都会取消对话框
- 〔适用情境 / 做法第 1 步〕应用没有另调 setCancelable、setCanceledOnTouchOutside，主题也没有另设 windowCloseOnTouchOutside 时：安卓 Dialog 与 android.app.DialogFragment 的 mCancelable 默认 true，Dialog 在可取消时按返回键即 cancel；Theme.Dialog、Theme.Material.BaseDialog、Theme.Material.Light.BaseDialog 的 windowCloseOnTouchOutside 取 config_closeDialogWhenTouchOutside（默认 true），用这些主题的对话框点窗口外即关闭
- 〔做法第 1、2、7 步〕openCustomDialog 等的 BaseDialogOptions 没有另设时：autoCancel 为 true（点遮罩关闭），isModal 为 true（有蒙层，蒙层区域事件不透传），maskColor 为 0x33000000，showInSubWindow 为 false（弹窗显示在应用内）
- 〔做法第 2、7 步〕BaseDialogOptions.onWillDismiss 注册后，点遮罩、侧滑、三键 back、键盘 ESC 都不会立刻关闭弹窗，由回调里的 DismissDialogAction.dismiss() 关闭，reason 区分返回键（PRESS_BACK）和点遮罩（TOUCH_OUTSIDE）；回调里不能再做 onWillDismiss 拦截，reason 暂不返回 CLOSE_BUTTON
- 〔做法第 2 步〕弹窗生命周期回调的正常时序是 onWillAppear、onDidAppear、onWillDisappear、onDidDisappear；退场动画没完成时（例如同时触发弹窗关闭和页面切换）onDidDisappear 不触发，入场动效没完成就关闭时 onDidAppear 不触发，快速开关时 onWillDisappear 可能先于 onDidAppear
- 〔做法第 2、7 步〕BaseDialogOptions.levelMode 默认 LevelMode.OVERLAY：弹窗层级为应用窗口根节点，应用内路由导航切换时弹窗不隐藏；levelMode 只在 showInSubWindow 为 false 时生效（API 15 起）
- 〔做法第 7 步〕LevelMode.EMBEDDED 的弹窗挂在 Page 或 NavDestination 节点下，随路由导航切换随页面隐藏，新页面可以盖在弹窗上，返回后弹窗仍在、内容不丢失；目标页面节点还没挂载上树时拉起，弹窗无法挂到该页面内
- 〔做法第 1 步〕CustomDialogController 只有作为 @CustomDialog 和 @Component struct 的成员变量、且在 @Component struct 内部定义时赋值才有效；状态管理 V2 建议用 openCustomDialog 实现自定义弹窗
- 〔做法第 2 步〕CustomDialogControllerOptions 没有另设时 autoCancel 为 true（点遮罩退出），按返回键和 ESC 键弹窗退出，cancel 回调在返回、ESC 和点遮罩退出时调用，未设置时不执行任何操作
- 〔做法第 1、6 步〕bindSheet 严格绑定宿主节点：宿主节点还没挂载上树就把 isShow 置为 true，半模态不生效；SheetMode.EMBEDDED 时除宿主节点外还要页面节点已挂载
- 〔做法第 2 步〕bindSheet 的 isShow 不是双向绑定（$$ 或 API 18 起的 !!）时，拖拽关闭半模态不会改变 isShow 的值；半模态离场动效执行期间再次拉起不响应
- 〔做法第 2 步〕SheetOptions 注册 shouldDismiss 或 onWillDismiss 后，下拉、侧拉、点遮罩、点关闭按钮都不会立即关闭半模态，由回调里的 dismiss() 关闭；不注册时这些交互正常关闭半模态
- 〔做法第 6 步〕SheetOptions.mode 默认 SheetMode.OVERLAY：半模态在当前 UIContext 内顶层显示，在所有页面之上，和弹窗类组件同层；SheetMode.EMBEDDED 在当前页面内顶层显示，新起的页面可以盖住它；显示期间 mode 不支持动态切换
- 〔做法第 1、6 步〕SheetOptions 没有另设时：height 为 LARGE；preferType 按窗口宽度取，宽度小于 600vp 为底部样式，600vp 到 840vp 为居中样式，840vp 及以上为跟手样式；enableOutsideInteractive 未设时底部和居中样式不允许下层交互并显示蒙层，跟手样式允许交互
- 〔做法第 1、6 步〕SheetOptions.dragBar 默认值写作 true，但 detents 没有设多个挡位时默认不显示控制条；showClose 默认 true，显示关闭图标
- 〔做法第 6 步〕宽高都为 0 的 Column 作宿主节点挂 bindSheet 时，设备上半模态面板能正常打开
- 〔做法第 5 步〕NavDestination 没有另设 mode 时为 NavDestinationMode.STANDARD，mode 不支持动态修改；DIALOG 模式默认透明，进出路由栈不影响下层 NavDestination 的可见性（不触发 onShown、onHidden），只触发 onActive、onInactive，API 13 之前默认没有系统转场动画
- 〔做法第 5 步〕NavDestination.onBackPressed 在导航控制器栈里有内容时生效，按返回键时触发：回调返回 true 表示重写返回键逻辑，返回 false 表示回退到上一个页面
- 〔做法第 1 步〕bindPopup 的 show 在页面构建过程中置为 true 会导致气泡位置和形状错误；PopupOptions 的 autoCancel 默认 true，页面有操作时气泡自动关闭，onWillDismiss 默认 true，气泡响应点击、侧滑和三键 back 关闭
