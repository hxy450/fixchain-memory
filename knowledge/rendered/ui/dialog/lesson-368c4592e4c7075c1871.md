# 源端 XPopup/DialogFragment 真弹窗（居中、锚点、底部）迁成可关闭的系统弹窗或半模态，不以页面可见性叠层充当

## 何时使用

迁移实现、弹窗恢复与宿主接线阶段，为 Android 真弹窗（DialogFragment、XPopup Center/Attach/Bottom 类）确定 ArkUI 承载形态，或为已有弹窗补触发、宿主、去掉路由时

## 适用情境

源端通过 DialogFragment、XPopup CenterPopupView/AttachPopupView 等在当前 Activity 上弹出提示、升级、菜单或锚点气泡，点击遮罩或返回即关闭；目标工程里已有以 @Local visible/visibility 或 if 条件渲染的 Stack + 遮罩叠层，或派工只写“接到现有弹窗”“恢复可关闭的页面内弹层”。也包括源弹窗继承 BottomPopupView 一类底部弹窗基类，计划或决策已写明映射到 showBindSheet/系统半模态，而现有实现是 NavDestination 路由页或由 @Param 可见性驱动、内嵌在宿主页的全屏 Stack（自绘遮罩、PanGesture 下拉关闭、返回信号参数）。 也包括 BottomSheetDialogFragment 被写成标准模式的 NavDestination 路由页，在页内自绘蒙层与底板，调用方随之 pushPathByName。也包括源端 BottomSheetDialogFragment 的宿主页在目标中嵌在壳内容区（标题栏、底部导航由外层提供），写者为回避同节点第二个 bindSheet 改用页内浮层。也包括 AlertDialog.Builder 构造、默认可取消的对话框，为满足“每个组件 @ComponentV2 导出”被写成自带蒙层的共享页内浮层，注释称覆盖返回键而实现只接蒙层点击。

## 例外与边界

- 项目决策明确采用页内浮层，且浮层已实现遮罩点击、返回键与页面离开关闭并只回调一次

## 原因

页面叠层只在宿主页 Stack 里条件渲染，遮罩没有点击处理、宿主不拦返回键时，空白点击与返回都关不掉；把它当作现成弹窗接线，或以“宿主化、恢复关闭回调”为完成标准，会让同一批次里部分弹窗改成真弹窗、其余仍是叠层。来源中执行者写前已读到形态选择表（CenterPopupView 对应真弹窗）与 Android 端的真弹窗实现，同一补丁把评分改为 showCustomDialog，通知提示与升级却只置 visible 标志条件渲染；另一条链是编排者收到用户“xpopup 弹窗都是页面组件、关不掉”的反馈，却把交接写成“恢复页面内弹层的关闭与回调”，下游据此保留了颜色选择叠层。同一交接下的底部弹窗是另一来源：计划已批准“BottomPopup → showBindSheet”并有已验证样板，根会话自己把日期弹层从路由页改成可见性参数驱动、内嵌宿主页的全屏 Stack（自绘遮罩、下拉阈值关闭），弹窗能关闭了，仍是页面组件。

## 做法

1. 先按源端类定形态：居中类（DialogFragment、CenterPopupView）用 UIContext.getPromptAction().openCustomDialog 或项目已采用的弹窗库（如 @pura/harmony-dialog 的 showCustomDialog）；锚点类（AttachPopupView）用 bindPopup 或按锚点全局坐标定位的自定义弹窗；底部类（BottomPopupView、底部 DialogFragment）用 bindSheet/showBindSheet 等系统半模态；@ComponentV2 页面不用 CustomDialogController 承载 V2 组件。
2. 目标里已有 @Local 可见性 + Stack/遮罩的实现视为待替换对象：接线时改为真弹窗 API，打开遮罩点击与返回关闭（如 autoCancel/backCancel），在 onDidDisappear 中单次清理状态，页面 aboutToDisappear 时主动关闭残留弹窗。
3. 规划或交接弹窗批次时把“真弹窗、可关闭”写成形态契约，对清单里的每个弹窗记录承载形态；同一批次已有弹窗改用真弹窗 API 时，把其余仍是条件渲染的逐个改掉，不以补可见性赋值收尾。
4. “去掉路由、能关闭”不等于完成映射：可见性参数 + 全屏 Stack + 自绘遮罩 + 手势阈值关闭属于待替换的形态；交接与执行日志原样引用映射目标 API，不改述成泛化的“页面内弹层”。
5. 源类为 BottomSheetDialogFragment/DialogFragment、规格 page_type 为 modal_overlay 或 dialog 时，不用标准 NavDestination 加自绘蒙层模拟；要用路由承载就显式 .mode(NavDestinationMode.DIALOG)，否则用 openCustomDialog/bindSheet。调用方接入已转换的弹层前，对照源端 show(childFragmentManager, …) 确认目标提供的是弹层入口；目标只暴露路由页时先修正呈现方式。
6. 宿主页嵌在壳内容区时，页内浮层只能覆盖标题栏与底栏之间；源端底部面板用零尺寸锚点上的窗口级 bindSheet 或共享面板组件承载，定样式前把面板子项布局一并读完。
7. AlertDialog 一类居中对话框优先用 openCustomDialog（页面级用 LevelMode.EMBEDDED，返回键与点外经 onWillDismiss 走取消回调）或 showDialog，由系统处理返回；保留页内浮层时同时交付返回键契约。

## 可选检查

- 对形态存疑时逐个弹层核对：弹层文件是否调用系统弹窗/半模态 API，宿主页是否只持有控制器，而不是可见性状态加内嵌组件。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；安卓 androidx.fragment:fragment 1.1.0、1.8.9。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 2 步〕openCustomDialog 等 ArkUI 弹窗在应用没有另设时：点蒙层关闭（autoCancel 默认 true），三键 back、侧滑、键盘 ESC 也直接关闭；注册 onWillDismiss 后这几种交互都不再立即关闭，须在回调里按 reason 决定是否调用 dismiss。〔成立范围：对象：UIContext.getPromptAction().openCustomDialog 等使用 BaseDialogOptions 的弹窗（autoCancel、onWillDismiss 为 API 12+）。条件：isModal 默认 true，有蒙层。不成立的情形：isModal 设为 false 时没有蒙层，不存在点蒙层关闭。〕
- 〔做法第 2 步〕弹窗显示层级默认 LevelMode.OVERLAY：挂在应用窗口根节点，应用内路由或 Navigation 切换页面时弹窗不隐藏；设为 LevelMode.EMBEDDED 时默认挂在当前显示的 Page 下（层级高于该 Page 内所有 Navigation 页面），要挂进某个 NavDestination 须再传 levelUniqueId（该页面内某节点的 uniqueId）；所挂的页面被切走时弹窗随之隐藏、返回该页后仍在，并且必须在页面节点上树后再拉起，否则挂不进页面。〔成立范围：对象：openCustomDialog、AlertDialog 等弹窗选项里的 levelMode（API 15+，Stage 模型）与 levelUniqueId。条件：showInSubWindow 为 false（默认）时才生效。不成立的情形：showInSubWindow 为 true 时弹窗显示在子窗口，levelMode 不起作用；只设 EMBEDDED、不传 levelUniqueId 时弹窗挂在 Page 上，同一 Page 内 Navigation 切换 NavDestination 不会让它隐藏。〕
- 〔做法第 1 步（底部类）〕bindSheet 半模态在应用没有另设时：下拉、侧拉（侧滑、三键 back、键盘 ESC）、点蒙层、点关闭按钮都会直接关闭；showClose 默认 true，显示关闭图标；底部与居中形态默认有蒙层、下层不可交互。注册 shouldDismiss 或 onWillDismiss 后这些交互不再立即关闭，要在回调里调用 dismiss。〔成立范围：对象：通用属性 bindSheet 的 SheetOptions（showClose、shouldDismiss、enableOutsideInteractive 为 API 11+，onWillDismiss 为 API 12+）。条件：未设 enableOutsideInteractive 和 preferType，且显示为底部或居中样式（preferType 缺省时窗口宽度 < 600vp 为底部、600–840vp 为居中）。不成立的情形：跟手弹窗（窗口宽度 ≥ 840vp 时的默认样式）默认允许下层交互、不显示蒙层，下滑面板也不关闭；全屏样式（SheetType.CONTENT_COVER，API 20+）不支持关闭按钮和蒙层，不能上下滑动、只能侧滑关闭。〕
- 〔做法第 5 步〕NavDestinationMode.DIALOG 的页面默认背景透明，进出路由栈不改变下层 NavDestination 的可见性，下层不触发 onShown、onHidden，只触发 onActive、onInactive；API version 13 之前默认没有系统转场动画，13 起才有。〔成立范围：对象：mode 设为 NavDestinationMode.DIALOG 的 NavDestination（API 11+）。条件：页面由 Navigation 路由栈管理。不成立的情形：mode 未设（默认 STANDARD 标准模式）的页面不适用。〕
- 〔做法第 1 步（源端 DialogFragment）〕androidx DialogFragment 的 mCancelable 默认 true；它在 onCreateDialog 建好对话框之后，再用自己的 mCancelable 调用 Dialog.setCancelable，并给对话框设上自己的 OnCancelListener、OnDismissListener，所以在 onCreateDialog 里直接对 Dialog 调 setCancelable 或设这两个监听会被覆盖；源端要让返回键不关闭，须调用 DialogFragment.setCancelable(false)。〔成立范围：对象：androidx.fragment.app.DialogFragment 及其子类弹出的对话框。条件：fragment 1.1.0（在 onActivityCreated 里覆盖）与 1.8.9（在 prepareDialog 里覆盖）一致。不成立的情形：直接 new Dialog/AlertDialog 后 show()、不经 DialogFragment 时，对话框自己的 setCancelable 与监听有效。〕
