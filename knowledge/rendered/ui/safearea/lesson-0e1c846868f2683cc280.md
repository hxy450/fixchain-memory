# 仅当源窗口内容延伸到系统栏下，或窗口背景是按窗口尺寸拉伸或定位的位图（Material / AppCompat 系）时，才做全屏沉浸与底部避让：导航指示条取 bottomRect，贴底按钮、按键区、Tab 栏与 bindSheet 内容都让出避让值（原高度已含底部留白时先抵扣），并加在占据屏幕底边的那一层；FLAG_FULLSCREEN 只隐藏状态栏，导航栏与旧应用的挖孔边、宽高比截边在窗口外

## 何时使用

沉浸式安全区实现阶段，测量导航指示条避让区，并为底部按钮行、按键区、Tab 栏或贴底弹层确定底部间距及承载它的容器层时；为已有固定高度（含内容下方留白）的底部 Tab 栏或底部定位元素补导航条避让时；决定目标窗口是否全屏（沉浸式）、系统栏底色与是否做内容避让时；源端以 DisplayMetrics 等屏幕宽高定游戏几何、为目标确定几何基准时

## 适用情境

目标页面在 setWindowLayoutFullScreen(true) 下用 getWindowAvoidArea 测避让值，写入页面或全局窗口模型；Android 源布局的底部按钮行、底部 sheet 没有导航栏间距（源窗口不延伸到导航栏下，BottomSheetDialog 由系统处理 inset）。或页面规格标注全屏页、需要沉浸式安全区，入口对 BOTTOM 边 expandSafeArea，根容器与底部内容层背景色不同。 也包括底部 Tab 栏原固定高度已在图标文字下方留有空白，避让值取自 TYPE_NAVIGATION_INDICATOR 的单一 px 快照、不区分三键与手势模式，用户只报告某一种导航模式被遮挡。也包括 Material3 BottomSheet 页面（库默认带 paddingBottomSystemWindowInsets）迁为 bindSheet，规格把“弹层跳过沉浸式处理”理解为自动避让。也包括规格要求手势与三键两种导航模式下内容都不被导航栏遮挡，而入口按沉浸式模板只以 TYPE_NAVIGATION_INDICATOR 测底部。 也包括源主题非全屏（Theme.Holo/Theme.Black 等，targetSdk 低，主题与代码都没有全屏或透明系统栏标志；requestWindowFeature(FEATURE_NO_TITLE) 只去标题栏），规格模板或页面元数据却按页面类型默认标注全屏页、需要沉浸式安全区。 也包括源 Activity 只用 FEATURE_NO_TITLE 加 FLAG_FULLSCREEN（或 windowFullscreen），未设导航栏延伸或隐藏标志，targetSdk 低（<28 且主题没设挖孔模式、<26 未声明最大宽高比且 activity 不可调整大小）；目标按沉浸式模板 setWindowSystemBarEnable([]) 隐藏全部系统栏、各页根容器四向 expandSafeArea，或把源端 getDisplayMetrics() 的宽高换算成“全屏窗口高减底部避让”。

## 例外与边界

- 源窗口内容不延伸到系统栏下（主题与代码都没有 windowFullscreen、windowTranslucentStatus/Navigation、透明 statusBarColor、FLAG_FULLSCREEN、SYSTEM_UI_FLAG_LAYOUT_*、setDecorFitsSystemWindows(false)/enableEdgeToEdge，targetSdk<35、运行系统低于 Android 15，或 targetSdk 为 35 且主题设 windowOptOutEdgeToEdgeEnforcement=true）：窗口背景是纯色，或生效主题的 windowDrawsSystemBarBackgrounds 不为 true（平台 Theme、Holo 系）时，目标保持非全屏，按做法第 1 步处理，其余各步不适用；windowDrawsSystemBarBackgrounds=true（Material / AppCompat 系）且窗口背景是按窗口尺寸拉伸或定位的位图时，源端位图铺满整屏、两条栏是盖在其上的不透明色块，目标改开全屏布局，按做法第 1 步的「窗口背景层」处理，其余各步按全屏页执行

## 原因

TYPE_NAVIGATION_INDICATOR 的避让区在窗口底部，值在 bottomRect；复制 TYPE_SYSTEM 那一行只改常量会读成 topRect（恒为 0），这种写法一旦被收敛进全局窗口模型，所有页面的底部避让都变成 0。三键导航栏的避让区按文档计入 TYPE_SYSTEM 的底部；文档又写明三键导航显示时 TYPE_NAVIGATION_INDICATOR 的底部区域也始终存在（一款真机两种模式都报 84px），两类的高度关系文档没有规定，所以底部取两者较大值，不只测其中一类。另一方面，源 XML 没有底部间距是因为源窗口不延伸到导航栏，目标全屏窗口会延伸，照 XML 写就贴屏底；bindSheet 内容贴屏底布局，也不会自动避让。来源中页面写者以“视频铺满、源端也没有底部避让”为由不消费底部值，sheet 写者照抄了 XML 的 paddingBottom。又一应用中两类偏差：计算器页规格已写明全屏与四层安全区方案，生成者只写 padding({ bottom: 8 })，底部按键落入指示条区域；补修账本页时把底部避让 padding 加在蓝色根容器上，而屏幕底边原本由浅灰内容层占据，避让区显示成一块蓝色——padding 区域显示的是承载它的容器的背景。另一应用中原 Tab 栏 barHeight(50 + 10) 已在内容下方留有约 10–16vp 空白，生成者把全额避让再加到 60vp 之上，并假设手势模式的避让值很小而未核实；真机上两种模式都报 84px（28vp），手势模式下留白翻倍，同批还给用户未提出的引导圆点追加了避让。最终由用户改为以避让值替代原 10vp 留白（手势模式仍余约 15vp）。反过来，源窗口本就非全屏时套用全屏模板，标题栏或内容会压进状态栏，各页再用避让去补偿，几何与底色都偏离源端；FEATURE_NO_TITLE 只去标题栏，不等于全屏。另一应用的页面类型模板把所有 Activity 默认标为需要沉浸式，经验摘要又被转述成“7 页全部全屏 + 底部避让”，Theme.Holo 源的各页随之被迁成全屏窗口并逐页补避让。 FLAG_FULLSCREEN 与 windowFullscreen 只隐藏状态栏：导航栏仍可见，应用窗口止于其上。主题与代码未设挖孔模式时（windowLayoutInDisplayCutoutMode 默认 DEFAULT），全屏窗口不覆盖挖孔所在的边、该边留黑；targetSdk<26、未声明 maxAspectRatio 且 activity 不可调整大小（resizeableActivity 未设 true；未声明时只有 targetSdk<24 才算不可调整）时，系统按最大宽高比 1.86 截长边（Android 源码 WindowManager.LayoutParams 的 LAYOUT_IN_DISPLAY_CUTOUT_MODE_DEFAULT 注释、ParsingPackageUtils.setMaxAspectRatio、ParsedActivityImpl.setMaxAspectRatio）。源端 getResources().getDisplayMetrics() 或 Display.getSize 取的宽高就是这块应用窗口区。目标用 setWindowSystemBarEnable([]) 会连三键导航栏一起隐藏；用“全屏窗口减底部避让”作几何基准，会多算挖孔边与截边部分，经整数截断的格数、行数随之改变。

## 做法

1. 先判定源窗口的内容是否延伸到系统栏下（窗口背景另判，见本步「窗口背景层」）：主题链按运行设备 API 级取覆盖后的生效链——应用主题的同名 style 在 values-vNN 下另有定义时以该覆盖为准，values/ 只是低版本回落（windowTranslucentStatus、statusBarColor 常只写在 values-v19/v21）；再查生效主题链的 windowFullscreen、windowTranslucentStatus/Navigation、statusBarColor 是否透明，代码中的 FLAG_FULLSCREEN、SYSTEM_UI_FLAG_LAYOUT_*、setDecorFitsSystemWindows(false)/enableEdgeToEdge，以及 targetSdk≥35 的强制 edge-to-edge（只在 Android 15 起的系统上发生；targetSdk 为 35 且生效主题设 windowOptOutEdgeToEdgeEnforcement=true 时不强制；targetSdk≥36 时这个属性被忽略）。全都没有时内容不延伸；窗口背景是纯色（主题的 windowBackground 或代码设的纯色），或生效主题的 windowDrawsSystemBarBackgrounds 不为 true 时，目标保持非全屏：在 loadContent 回调里 setWindowLayoutFullScreen(false)，按源设置系统栏底色与图标色（setWindowSystemBarProperties；底色取生效主题的 statusBarColor，Material / AppCompat 系即生效主题链上的 colorPrimaryDark：从应用主题沿 parent 逐级查到第一个写它的 style（库主题同时看 values/ 与 values-vNN 下的同名定义），平台与 AppCompat 的 Light.DarkActionBar 都把它覆写为黑，不按主题名里的 Light/Dark 推断，Holo 及更早的主题为黑；状态栏写 statusBarColor 与 statusBarContentColor，导航栏只在源端为黑时写 navigationBarColor '#FF000000'，其余导航栏色不写），用 setWindowSystemBarEnable(['status','navigation']) 保证横屏也显示系统栏，不建避让窗口模型、各页不加避让 padding。窗口背景层：生效主题 windowDrawsSystemBarBackgrounds=true（Theme.Material*、Theme.AppCompat* 及其子主题在 API 21+ 设备且 targetSdk≥21 时的默认；平台 Theme、Theme.Holo 为 false）的非浮动窗口按整屏布局：窗口背景（windowBackground 或 getWindow().setBackgroundDrawable 设的图）铺满整屏，两栏颜色不透明时状态栏、导航栏是框架画在其上的不透明色块，只有 content 被让开。此时若窗口背景是按窗口尺寸拉伸或定位的位图（BitmapDrawable 默认 FILL，按整窗拉伸），目标开全屏布局：背景节点铺满整窗、按源端方式缩放（FILL 对应 ImageFit.Fill），statusBarColor / statusBarContentColor 按源设不透明色，同样调 setWindowSystemBarEnable(['status','navigation'])，前景逐边补避让（按 lesson-a8452bfea5d42d3dcae3 第 3 步；底部导航区按其第 1 步叠源端导航栏同色、不参与命中的占位），以下各步按全屏页执行；窗口背景是纯色时维持上面的非全屏做法。只有确需全屏时才执行以下各步。 逐边判定：windowFullscreen 与 FLAG_FULLSCREEN 只隐藏状态栏，导航栏仍可见、应用窗口止于其上；目标只隐藏状态栏（window.setSpecificSystemBarEnabled('status', false)，保留导航栏与手势条），不用 setWindowSystemBarEnable([])，页面背景与内容不向导航区延伸。主题与代码未设 windowLayoutInDisplayCutoutMode 且窗口没被强制 edge-to-edge（targetSdk<35，或运行系统低于 Android 15，或 targetSdk 为 35 且主题 opt-out）时，全屏窗口不覆盖挖孔所在的边、该边留黑（挖孔不深于 16dp 时厂商可让窗口延伸进去；被强制 edge-to-edge 时铺满屏幕的窗口按 always 进入挖孔区）；targetSdk<26、未声明 maxAspectRatio 或 meta-data android.max_aspect、且 activity 不可调整大小（resizeableActivity 未设为 true；未声明时只有 targetSdk<24 才算不可调整）时，系统按最大宽高比 1.86 截长边。源端（targetSdk≤34）用 getDisplayMetrics() 或 Display.getSize/getMetrics 的宽高作几何基准时，目标基准取等价内容区：windowRect 减挖孔边与底部避让（TYPE_SYSTEM 与 TYPE_NAVIGATION_INDICATOR 的较大值），再按宽高比上限截长边，不用“全屏窗口减底部避让”；内容区以外（挖孔边、截掉的长边）照源端铺黑（setWindowBackgroundColor('#FF000000') 或黑底容器）。targetSdk≥35 时 Display.getSize/getMetrics 从 Activity 取的是整个窗口尺寸，不减系统装饰区和挖孔。取值位置：模块 build.gradle 的 targetSdkVersion（常经 gradle.properties 等间接定义，合并构建后才写进 Manifest，源 AndroidManifest 里多半没有）与 AndroidManifest 的 activity 属性、主题链的挖孔模式，参照机 adb shell dumpsys window windows 中该窗口的 mAppBounds，目标端 getWindowAvoidArea 的 TYPE_CUTOUT。
2. 按避让区方位取矩形：顶部取 TYPE_SYSTEM 的 topRect.height；底部取 TYPE_SYSTEM 与 TYPE_NAVIGATION_INDICATOR 两者 bottomRect.height 的较大值（文档：三键导航栏计入 TYPE_SYSTEM 底部；TYPE_NAVIGATION_INDICATOR 是底部导航区，手势与三键导航下都存在），并订阅 avoidAreaChange 在导航方式切换时重算；复制测量代码时同时核对矩形字段。
3. 把页面测量收敛成共享窗口模型前，对照沉浸式参考或工程内已正确的实现逐字段核语义，不直接照搬现有页面片段。
4. 全屏页（按第 1 步判定确需全屏）的底部 CTA、按键区、贴底浮层与 bindSheet 内容都叠加底部避让值（子组件由宿主经 @Param 注入）；源窗口全屏时不因源 XML 没有底部间距就判定无需避让，源窗口内容不延伸、且窗口背景是纯色（或主题 windowDrawsSystemBarBackgrounds 不为 true）时，源 XML 没有底部间距正是保持非全屏的信号；窗口背景是按窗口尺寸拉伸或定位的位图（Material / AppCompat 系）时改走第 1 步「窗口背景层」开全屏，底部照本步叠加避让值。页面规格标注全屏或沉浸式安全区时，生成页面即消费已发布的底部避让值，不用固定小 padding 代替。
5. 放置底部避让 padding 前先确认屏幕底边由哪一层背景占据，把 padding 加在那一层（如浅色内容层），根容器只承担顶部状态栏区；Tab 栏保持内容高度，让其背景延伸覆盖避让区。
6. 原 Tab 栏或底部栏的固定高度已包含内容下方留白时，让避让值替代或抵扣这段留白，不在总高度上整额叠加；三键与手势等导航模式以实测的各模式避让值为准，用户声明正常的模式把“布局不变”列为验收。同一避让值在不同模式下视觉占用不同时，以 TYPE_SYSTEM 底部高度是否大于 0 区分三键与手势导航，或请用户取舍，并在交付说明中标明未验证的模式。
7. 已有固定底部偏移的元素（如 position bottom: 50 的指示器）先比较该偏移与实测避让高度，已足以避开时不追加，也不把用户未提出的组件并入同一改动。

## 可选检查

- 在带导航指示条的设备上确认 bottomPadding 非 0、底部按钮与屏底之间留出指示条高度。
- 调整底部 Tab 高度后，分别在三键与手势导航模式下截图，核对文字到屏底或指示条的间距符合预期。
- 源端非全屏时对照两端截图：状态栏与导航栏区域为源端底色，内容起点在状态栏下沿、终点在导航栏上沿。

- 〔做法第 1 步〕参照机（API 36）上 targetSdk 35 的应用，根布局 fitsSystemWindows=false 且没处理 WindowInsets 时，Toolbar 从 y=0 起叠在透明状态栏下；主题没设 windowLightStatusBar 时状态栏图标为浅色
- 〔做法第 1 步〕应用主题链没有另设 statusBarColor 时的状态栏底色：Theme（Theme.Light、Theme.Black、Theme.Holo 都继承它）写 statusBarColor=@color/black、windowDrawsSystemBarBackgrounds=false，状态栏为黑；Theme.Material、Theme.Material.Light 写 statusBarColor=?attr/colorPrimaryDark、windowDrawsSystemBarBackgrounds=true（targetSdk < 21 时 PhoneWindow 不采用这个旗标）。没有另设 colorPrimaryDark 时，Theme.Material 与 Theme.Material.Light.DarkActionBar 的 colorPrimaryDark 是 primary_dark_material_dark（黑），Theme.Material.Light 是 primary_dark_material_light（material_grey_600，#FF757575）。Theme.Material.Light 的 parent 是 Theme.Light，状态栏色在 Material 这一层重新定义；没强制 edge-to-edge 时 PhoneWindow 在主题没给 statusBarColor 的情况下也取黑。库主题的覆写（API 21 起，它们不改 statusBarColor，只改 colorPrimaryDark）：Theme.AppCompat.Light 为 #FF757575，Theme.AppCompat 与 *.Light.DarkActionBar 为黑（appcompat 1.1.0–1.8.0）；Theme.MaterialComponents.Light 为 #FF3700B3，Theme.MaterialComponents（暗色）与 Theme.MaterialComponents.Light.DarkActionBar 为黑；Theme.Material3.Light 的 colorPrimaryDark 指向 colorPrimary，为 #FF6750A4，Theme.Material3.Dark 为 #FFD0BCFF（material 1.4.0–1.14.0，Material3 自 1.8.0 起核过）
- 〔做法第 1 步〕Theme.Material 系里只有 Theme.Material.Light.LightStatusBar 把 windowLightStatusBar 设为 true，生效主题没设 windowLightStatusBar 时状态栏图标为浅色；appcompat 1.1.0–1.8.0、material 1.4.0–1.14.0 的 AppCompat、MaterialComponents、Material3 主题都没设 android:windowLightStatusBar；windowLightStatusBar 要在窗口绘制系统栏背景（windowDrawsSystemBarBackgrounds）且状态栏没设半透明时才生效
- 〔做法第 1 步〕应用主题和代码都没另设 navigationBarColor、窗口没被强制 edge-to-edge 时导航栏为黑：android-33 及以前的平台资源里 Theme、Theme.Material 直接写 navigationBarColor=@color/black（核过 android-30、android-33）；android-34 起写 @color/navigation_bar_default（#00808080），PhoneWindow.generateLayout 在主题没指定、没强制 edge-to-edge、设备 config_navBarDefaultTransparent 为 false（平台默认 false）时换成 navigation_bar_compatible（@android:color/black）；appcompat 1.1.0–1.8.0、material 1.4.0–1.14.0 的 Activity 主题都没改 navigationBarColor
- 〔做法第 1 步〕targetSdk 17、各 Activity 用 Theme.Holo 系主题、主题和代码都没有全屏或透明系统栏标志（有的页面只调 requestWindowFeature(FEATURE_NO_TITLE)）时，源端各页内容位于黑色状态栏和黑色导航栏之间，系统栏图标为白色
- 〔例外与边界 / 原因 / 做法第 1 步〕windowLayoutInDisplayCutoutMode（对应 LayoutParams.layoutInDisplayCutoutMode）没设时为 default（LAYOUT_IN_DISPLAY_CUTOUT_MODE_DEFAULT=0）：窗口只在挖孔完全落在系统栏内时才延伸进挖孔区（LayoutParams 注释另写：挖孔不深于 16dp 时也可以，取决于厂商），设了 FLAG_FULLSCREEN 或 SYSTEM_UI_FLAG_FULLSCREEN、或横屏时窗口不与挖孔区重叠；厂商还可以给用户一个开关，让挖孔在系统栏另一侧且与窗口重叠不超过 16dp 时窗口总能延伸进去；强制 edge-to-edge 时（targetSdk ≥ 35 等条件见上）铺满屏幕的窗口按 always 处理。PhoneWindow.generateLayout 读主题里的这个属性时不看 targetSdk
- 〔适用情境 / 原因 / 做法第 1 步〕targetSdk < 26（O）的应用，在没声明 maxAspectRatio 时最大宽高比取 1.86（DEFAULT_PRE_O_MAX_ASPECT_RATIO）；应用或 Activity 声明了 maxAspectRatio 或 meta-data android.max_aspect 时用声明值；可调整大小的 Activity（resizeableActivity 写 true，或没写且 targetSdk ≥ 24）不受最大宽高比限制
- 〔原因 / 做法第 1 步〕从 Activity 取的 Display.getMetrics、Display.getSize 是当前应用窗口的尺寸：注释写明 API 34 及以下为窗口减去系统装饰区和挖孔，API 35 及以上为窗口尺寸；对应兼容变更 INSETS_DECOUPLED_CONFIGURATION_ENFORCED（@EnabledSince targetSdkVersion = VANILLA_ICE_CREAM），即应用 targetSdk ≥ 35 且系统 Android 15 起才按窗口尺寸；Resources.getDisplayMetrics 的注释说它报的值可能和应用关心的窗口不同
- 〔做法第 1 步〕setWindowLayoutFullScreen(true) 让应用主窗口进入沉浸式布局，布局不避让状态栏与三键导航栏、组件可能与之重叠（状态栏、三键导航栏仍显示）；false 时布局避让它们。非自由窗口状态下，应用子窗以外的窗口创建时就是非沉浸式布局；进入或退出沉浸式布局不改变窗口尺寸和位置。OpenHarmony 5.1.1 起在 PC/2in1 设备和电脑模式下调用不生效
- 〔做法第 1 步〕setWindowSystemBarProperties(systemBarProperties) 设置主窗口状态栏（及三键导航栏）的属性，另有回调形式；子窗口调用不生效，主窗口在自由悬浮、分屏等非全屏/最大化模式下配置不生效，进入全屏/最大化后生效
- 〔做法第 1 步〕SystemBarProperties：statusBarColor 是状态栏背景色，入参写十六进制 RGB 或 ARGB（如 '#FF00FF00'），不设时为系统配置的颜色；statusBarContentColor 是状态栏文字颜色，文档写的默认值为 '#E5FFFFFF'，设了它 isStatusBarLightIcon 就无效；navigationBarColor 是三键导航栏的背景色（写法同上，不设时为系统配置的颜色），navigationBarContentColor 是三键导航栏文字颜色
- 〔做法第 1 步〕非沉浸式主窗口只调 setWindowSystemBarEnable、不调 setWindowSystemBarProperties 时，设备上状态栏显示为白底黑字（和文档写的 statusBarContentColor 默认 '#E5FFFFFF' 不同）；同一处试设 navigationBarColor 时看不到效果（卡里没有记录当时的导航模式）
- 〔做法第 1 步〕setWindowSystemBarEnable(names) 控制主窗口全屏/最大化模式下显示哪些系统栏：'status' 是状态栏，'navigation' 是三键导航栏；全部显示传 ['status', 'navigation']，传 [] 则都不显示；调用返回不代表显隐已完成。这类控制系统栏显示的接口只有非自由窗口状态下的主窗口支持，主窗口在非全屏/最大化模式下配置不生效、进入全屏/最大化后生效
- 〔做法第 1 步〕设备上应用窗口转到横屏时状态栏默认隐藏；入口显式调用 setWindowSystemBarEnable(['status','navigation']) 时横屏也显示状态栏
- 〔做法第 1 步〕setSpecificSystemBarEnabled(name, enable, enableAnimation?) 单独显示或隐藏主窗口的一种系统栏，enable 为 false 时隐藏，子窗口调用不生效；SpecificSystemBar 取 'status'（状态栏）、'navigation'（三键导航栏）、'navigationIndicator'（底部导航，OpenHarmony 文档注明各设备不支持）。文档隐藏状态栏的示例是先 setWindowLayoutFullScreen(true)，再 setSpecificSystemBarEnabled('status', false)
- 〔做法第 1 步〕Window.getWindowProperties().windowRect 是窗口尺寸（Rect，单位 px，左、上边界相对窗口所在屏幕的左上角）；setWindowBackgroundColor 设置窗口内容区域的背景色（十六进制 RGB/ARGB），未调用时浅色模式为 '#FFF0F0F0'、深色模式为 '#FF1A1A1A'，Stage 模型下要在 loadContent 生效后调用
- 〔适用情境 / 做法第 1 步〕expandSafeArea(types?, edges?) 只把组件的绘制区域扩展到安全区外、不改变布局，也不限制或裁剪子组件；不传参时 types 为 [SYSTEM, CUTOUT, KEYBOARD]、edges 为 [TOP, BOTTOM, START, END]，CUTOUT 要在 metadata 配置后才生效；只有组件边界与安全区域重合时才延伸，没设 position、offset 的弹窗和半模态边界不与避让区重叠，设置不生效
- 〔原因 / 做法第 2、6 步〕AvoidAreaType：TYPE_SYSTEM=0 是系统默认区域，包含状态栏和三键导航栏区域；TYPE_CUTOUT=1 是挖孔区域；TYPE_NAVIGATION_INDICATOR=4 是底部导航区域，三键导航显示时这一底部导航避让区域也始终存在
- 〔原因 / 做法第 2 步〕getWindowAvoidArea(type) 返回 AvoidArea（visible、leftRect、topRect、rightRect、bottomRect）：窗口按两条对角线分成四块，系统界面元素的矩形中心落在哪一块，避让区就放进对应方向的 Rect，底部导航区域在 bottomRect（0, H−h2, W, h2）；返回值全为 0 表示避让区为空，visible 没有实际含义
- 〔原因 / 做法第 2 步〕全屏布局下对 TYPE_NAVIGATION_INDICATOR 的避让区读 topRect.height 时，设备上得到 0，底部避让值为 0、底部按钮贴屏底
- 〔原因 / 做法第 2、6 步〕一款真机上三键与手势两种导航模式下 TYPE_NAVIGATION_INDICATOR 的 bottomRect.height 都是 84px（28vp）；手势小白条只占距屏底约 9–13vp，三键图标约在距屏底 13–29vp，两种模式的导航区都在距屏底 50vp 以内
- 〔原因 / 做法第 2 步〕另一台设备上三键导航时只读 TYPE_NAVIGATION_INDICATOR 的 bottomRect，底部避让为 0（卡里没有记录设备型号和系统版本），和上一条真机、文档“三键导航显示时底部导航避让区域始终存在”的说法不同
- 〔原因 / 做法第 2、4 步〕Rect 的 left、top、width、height 单位为 px，应为整数（API 23 起另有以 vp 为单位的 RectInVP）；padding 等 Length 写 number 时默认单位是 vp；UIContext.px2vp(value) 把 px 值换成 vp
- 〔做法第 2 步〕on('avoidAreaChange', callback) 监听当前应用窗口系统避让区的变化，回调参数 AvoidAreaOptions 带 type（避让区类型）和 area（变化后的避让区）；文档列的常见触发场景是窗口在全屏、悬浮、分屏模式之间切换，窗口旋转，折叠状态变化，多设备流转。文档示例在回调里按 type 分别取 TYPE_SYSTEM 的 topRect 和 TYPE_NAVIGATION_INDICATOR 的 bottomRect
- 〔做法第 2 步〕getWindowAvoidAreaIgnoringVisibility(type)（API 22 起）在避让区当前不可见时也返回它，不支持 TYPE_KEYBOARD；getWindowAvoidArea 一般用在 onWindowStageCreate 里取启动时的初始避让区
- 〔适用情境 / 做法第 4 步〕com.google.android.material 1.8.0、1.12.0、1.14.0 的 Widget.Material3.BottomSheet 写 paddingBottomSystemWindowInsets=true（paddingTopSystemWindowInsets 也是 true，左右 margin 跟随系统窗口 insets）；应用没另设这一样式项时，Material3 底部弹层内容底部自动加系统栏内边距，源布局 XML 里看不到这段间距
- 〔原因 / 做法第 4 步〕全屏沉浸页里 bindSheet 底部弹层的内容贴屏底布局：内容根容器只写源 XML 的 paddingBottom（10vp）时，内容落进导航指示条区域
- 〔做法第 4 步〕bindSheet 文档只对全屏样式（SheetType.CONTENT_COVER，API 20 起）写明 builder 内容默认布局在安全区内，底部弹窗（BOTTOM）样式没有写导航条避让
- 〔做法第 4 步〕@Param 表示组件从外部传入的状态，在 @ComponentV2 装饰的自定义组件中使用（API 12 起），父子组件之间的数据由它同步
- 〔做法第 4 步〕窗口 setWindowLayoutFullScreen(true)、页面根对 BOTTOM 边 expandSafeArea 时，底部按键行或按钮行所在容器只写固定的底部间距（8vp、10vp）而不加底部避让值，按键落进导航指示条区域
- 〔做法第 4、5 步〕沉浸式布局下窗口可布局区域与状态栏、导航区域重叠，系统界面元素层级始终高于应用内容，状态栏和导航区域默认透明、透出应用界面的背景色，避让区可能为 0；文档示例给顶部容器的 padding top 加 TYPE_SYSTEM 的 topRect 高度、给底部容器的 padding bottom 加 TYPE_NAVIGATION_INDICATOR 的 bottomRect 高度（都经 px2vp 换算并多加 10vp），两个容器各自设 backgroundColor
- 〔做法第 5 步〕组件区域由 width、height 决定，padding 在组件区域之内（组件内容的大小是 width、height 减 padding 和 border）；backgroundColor 设置的是组件背景色
- 〔做法第 5 步〕根容器与延伸到屏幕底边的内容层背景色不同时，底部避让 padding 加在根容器上，避让区显示根容器的背景色（屏幕底部出现一块根容器颜色的色块）
- 〔做法第 5、6 步〕Tabs 从 API 11 起 expandSafeArea 的缺省值为 ([SafeAreaType.SYSTEM], [SafeAreaEdge.BOTTOM])；barHeight(value) 设置 TabBar 高度，小于 0 或大于 Tabs 高度时按默认值显示，横向 Tabs 可设 'auto' 让 TabBar 随子组件高度
- 〔做法第 7 步〕position(value) 用 Edges 类型时，top、left、right、bottom 是组件各边到父组件内容区相应边的距离；在 Row、Column、Flex 里设了 position 的子组件不占位
