# 仅当源窗口内容延伸到系统栏下，或窗口背景是按窗口尺寸拉伸或定位的位图（Material / AppCompat 系）时，才做全屏沉浸与底部避让：导航指示条取 bottomRect，贴底按钮、按键区、Tab 栏与 bindSheet 内容都让出避让值（原高度已含底部留白时先抵扣），并加在占据屏幕底边的那一层；FLAG_FULLSCREEN 只隐藏状态栏，导航栏与旧应用的挖孔边、宽高比截边在窗口外

## 何时使用

沉浸式安全区实现阶段，测量导航指示条避让区，并为底部按钮行、按键区、Tab 栏或贴底弹层确定底部间距及承载它的容器层时；为已有固定高度（含内容下方留白）的底部 Tab 栏或底部定位元素补导航条避让时；决定目标窗口是否全屏（沉浸式）、系统栏底色与是否做内容避让时；源端以 DisplayMetrics 等屏幕宽高定游戏几何、为目标确定几何基准时

## 适用情境

目标页面在 setWindowLayoutFullScreen(true) 下用 getWindowAvoidArea 测避让值，写入页面或全局窗口模型；Android 源布局的底部按钮行、底部 sheet 没有导航栏间距（源窗口不延伸到导航栏下，BottomSheetDialog 由系统处理 inset）。或页面规格标注全屏页、需要沉浸式安全区，入口对 BOTTOM 边 expandSafeArea，根容器与底部内容层背景色不同。 也包括底部 Tab 栏原固定高度已在图标文字下方留有空白，避让值取自 TYPE_NAVIGATION_INDICATOR 的单一 px 快照、不区分三键与手势模式，用户只报告某一种导航模式被遮挡。也包括 Material3 BottomSheet 页面（库默认带 paddingBottomSystemWindowInsets）迁为 bindSheet，规格把“弹层跳过沉浸式处理”理解为自动避让。也包括规格要求手势与三键两种导航模式下内容都不被导航栏遮挡，而入口按沉浸式模板只以 TYPE_NAVIGATION_INDICATOR 测底部。 也包括源主题非全屏（Theme.Holo/Theme.Black 等，targetSdk 低，主题与代码都没有全屏或透明系统栏标志；requestWindowFeature(FEATURE_NO_TITLE) 只去标题栏），规格模板或页面元数据却按页面类型默认标注全屏页、需要沉浸式安全区。 也包括源 Activity 只用 FEATURE_NO_TITLE 加 FLAG_FULLSCREEN（或 windowFullscreen），未设导航栏延伸或隐藏标志，targetSdk 低（<28 无法声明挖孔模式、<26 未声明最大宽高比且 activity 不可调整大小）；目标按沉浸式模板 setWindowSystemBarEnable([]) 隐藏全部系统栏、各页根容器四向 expandSafeArea，或把源端 getDisplayMetrics() 的宽高换算成“全屏窗口高减底部避让”。

## 例外与边界

- 源窗口内容不延伸到系统栏下（主题与代码都没有 windowFullscreen、windowTranslucentStatus/Navigation、透明 statusBarColor、FLAG_FULLSCREEN、SYSTEM_UI_FLAG_LAYOUT_*、setDecorFitsSystemWindows(false)/enableEdgeToEdge，targetSdk<35）：窗口背景是纯色，或生效主题的 windowDrawsSystemBarBackgrounds 不为 true（平台 Theme、Holo 系）时，目标保持非全屏，按做法第 1 步处理，其余各步不适用；windowDrawsSystemBarBackgrounds=true（Material / AppCompat 系）且窗口背景是按窗口尺寸拉伸或定位的位图时，源端位图铺满整屏、两条栏是盖在其上的不透明色块，目标改开全屏布局，按做法第 1 步的「窗口背景层」处理，其余各步按全屏页执行

## 原因

TYPE_NAVIGATION_INDICATOR 的避让区在窗口底部，值在 bottomRect；复制 TYPE_SYSTEM 那一行只改常量会读成 topRect（恒为 0），这种写法一旦被收敛进全局窗口模型，所有页面的底部避让都变成 0。三键导航栏的避让区按文档计入 TYPE_SYSTEM 的底部；文档又写明三键导航显示时 TYPE_NAVIGATION_INDICATOR 的底部区域也始终存在（一款真机两种模式都报 84px），两类的高度关系文档没有规定，所以底部取两者较大值，不只测其中一类。另一方面，源 XML 没有底部间距是因为源窗口不延伸到导航栏，目标全屏窗口会延伸，照 XML 写就贴屏底；bindSheet 内容贴屏底布局，也不会自动避让。来源中页面写者以“视频铺满、源端也没有底部避让”为由不消费底部值，sheet 写者照抄了 XML 的 paddingBottom。又一应用中两类偏差：计算器页规格已写明全屏与四层安全区方案，生成者只写 padding({ bottom: 8 })，底部按键落入指示条区域；补修账本页时把底部避让 padding 加在蓝色根容器上，而屏幕底边原本由浅灰内容层占据，避让区显示成一块蓝色——padding 区域显示的是承载它的容器的背景。另一应用中原 Tab 栏 barHeight(50 + 10) 已在内容下方留有约 10–16vp 空白，生成者把全额避让再加到 60vp 之上，并假设手势模式的避让值很小而未核实；真机上两种模式都报 84px（28vp），手势模式下留白翻倍，同批还给用户未提出的引导圆点追加了避让。最终由用户改为以避让值替代原 10vp 留白（手势模式仍余约 15vp）。反过来，源窗口本就非全屏时套用全屏模板，标题栏或内容会压进状态栏，各页再用避让去补偿，几何与底色都偏离源端；FEATURE_NO_TITLE 只去标题栏，不等于全屏。另一应用的页面类型模板把所有 Activity 默认标为需要沉浸式，经验摘要又被转述成“7 页全部全屏 + 底部避让”，Theme.Holo 源的各页随之被迁成全屏窗口并逐页补避让。 FLAG_FULLSCREEN 与 windowFullscreen 只隐藏状态栏：导航栏仍可见，应用窗口止于其上。主题与代码未设挖孔模式时（windowLayoutInDisplayCutoutMode 默认 DEFAULT），全屏窗口不覆盖挖孔所在的边、该边留黑；targetSdk<26、未声明 maxAspectRatio 且 activity 不可调整大小（resizeableActivity 未设 true；未声明时只有 targetSdk<24 才算不可调整）时，系统按最大宽高比 1.86 截长边（Android 源码 WindowManager.LayoutParams 的 LAYOUT_IN_DISPLAY_CUTOUT_MODE_DEFAULT 注释、ParsingPackageUtils.setMaxAspectRatio、ParsedActivityImpl.setMaxAspectRatio）。源端 getResources().getDisplayMetrics() 或 Display.getSize 取的宽高就是这块应用窗口区。目标用 setWindowSystemBarEnable([]) 会连导航条一起隐藏；用“全屏窗口减底部避让”作几何基准，会多算挖孔边与截边部分，经整数截断的格数、行数随之改变。

## 做法

1. 先判定源窗口的内容是否延伸到系统栏下（窗口背景另判，见本步「窗口背景层」）：主题链按运行设备 API 级取覆盖后的生效链——应用主题的同名 style 在 values-vNN 下另有定义时以该覆盖为准，values/ 只是低版本回落（windowTranslucentStatus、statusBarColor 常只写在 values-v19/v21）；再查生效主题链的 windowFullscreen、windowTranslucentStatus/Navigation、statusBarColor 是否透明，代码中的 FLAG_FULLSCREEN、SYSTEM_UI_FLAG_LAYOUT_*、setDecorFitsSystemWindows(false)/enableEdgeToEdge，以及 targetSdk≥35 的强制 edge-to-edge。全都没有时内容不延伸；窗口背景是纯色（主题的 windowBackground 或代码设的纯色），或生效主题的 windowDrawsSystemBarBackgrounds 不为 true 时，目标保持非全屏：在 loadContent 回调里 setWindowLayoutFullScreen(false)，按源设置系统栏底色与图标色（setWindowSystemBarProperties；底色取生效主题的 statusBarColor，Material / AppCompat 系即生效主题链上的 colorPrimaryDark：从应用主题沿 parent 逐级查到第一个写它的 style（库主题同时看 values/ 与 values-vNN 下的同名定义），平台与 AppCompat 的 Light.DarkActionBar 都把它覆写为黑，不按主题名里的 Light/Dark 推断，Holo 及更早的主题为黑；状态栏写 statusBarColor 与 statusBarContentColor，导航栏只在源端为黑时写 navigationBarColor '#FF000000'，其余导航栏色不写），用 setWindowSystemBarEnable(['status','navigation']) 保证横屏也显示系统栏，不建避让窗口模型、各页不加避让 padding。窗口背景层：生效主题 windowDrawsSystemBarBackgrounds=true（Theme.Material*、Theme.AppCompat* 及其子主题在 API 21+ 设备且 targetSdk≥21 时的默认；平台 Theme、Theme.Holo 为 false）的非浮动窗口按整屏布局：窗口背景（windowBackground 或 getWindow().setBackgroundDrawable 设的图）铺满整屏，两栏颜色不透明时状态栏、导航栏是框架画在其上的不透明色块，只有 content 被让开。此时若窗口背景是按窗口尺寸拉伸或定位的位图（BitmapDrawable 默认 FILL，按整窗拉伸），目标开全屏布局：背景节点铺满整窗、按源端方式缩放（FILL 对应 ImageFit.Fill），statusBarColor / statusBarContentColor 按源设不透明色，同样调 setWindowSystemBarEnable(['status','navigation'])，前景逐边补避让（按 lesson-a8452bfea5d42d3dcae3 第 3 步；底部导航区按其第 1 步叠源端导航栏同色、不参与命中的占位），以下各步按全屏页执行；窗口背景是纯色时维持上面的非全屏做法。只有确需全屏时才执行以下各步。 逐边判定：windowFullscreen 与 FLAG_FULLSCREEN 只隐藏状态栏，导航栏仍可见、应用窗口止于其上；目标只隐藏状态栏（window.setSpecificSystemBarEnabled('status', false)，保留导航栏与手势条），不用 setWindowSystemBarEnable([])，页面背景与内容不向导航区延伸。主题与代码未设 windowLayoutInDisplayCutoutMode 时，全屏窗口不覆盖挖孔所在的边、该边留黑；targetSdk<26、未声明 maxAspectRatio 或 meta-data android.max_aspect、且 activity 不可调整大小（resizeableActivity 未设为 true；未声明时只有 targetSdk<24 才算不可调整）时，系统按最大宽高比 1.86 截长边。源端用 getDisplayMetrics() 或 Display.getSize/getMetrics 的宽高作几何基准时，目标基准取等价内容区：windowRect 减挖孔边与底部避让（TYPE_SYSTEM 与 TYPE_NAVIGATION_INDICATOR 的较大值），再按宽高比上限截长边，不用“全屏窗口减底部避让”。取值位置：模块 build.gradle 的 targetSdkVersion（常经 gradle.properties 等间接定义，合并构建后才写进 Manifest，源 AndroidManifest 里多半没有）与 AndroidManifest 的 activity 属性、主题链的挖孔模式，参照机 adb shell dumpsys window windows 中该窗口的 mAppBounds，目标端 getWindowAvoidArea 的 TYPE_CUTOUT。
2. 按避让区方位取矩形：顶部取 TYPE_SYSTEM 的 topRect.height；底部取 TYPE_SYSTEM 与 TYPE_NAVIGATION_INDICATOR 两者 bottomRect.height 的较大值（文档：三键导航栏计入 TYPE_SYSTEM 底部；TYPE_NAVIGATION_INDICATOR 是底部导航区，手势与三键导航下都存在），并订阅 avoidAreaChange 在导航方式切换时重算；复制测量代码时同时核对矩形字段。
3. 把页面测量收敛成共享窗口模型前，对照沉浸式参考或工程内已正确的实现逐字段核语义，不直接照搬现有页面片段。
4. 全屏页（按第 1 步判定确需全屏）的底部 CTA、按键区、贴底浮层与 bindSheet 内容都叠加底部避让值（子组件由宿主经 @Param 注入）；源窗口全屏时不因源 XML 没有底部间距就判定无需避让，源窗口内容不延伸、且窗口背景是纯色（或主题 windowDrawsSystemBarBackgrounds 不为 true）时，源 XML 没有底部间距正是保持非全屏的信号；窗口背景是按窗口尺寸拉伸或定位的位图（Material / AppCompat 系）时改走第 1 步「窗口背景层」开全屏，底部照本步叠加避让值。页面规格标注全屏或沉浸式安全区时，生成页面即消费已发布的底部避让值，不用固定小 padding 代替。
5. 放置底部避让 padding 前先确认屏幕底边由哪一层背景占据，把 padding 加在那一层（如浅色内容层），根容器只承担顶部状态栏区；Tab 栏保持内容高度，让其背景延伸覆盖避让区。
6. 原 Tab 栏或底部栏的固定高度已包含内容下方留白时，让避让值替代或抵扣这段留白，不在总高度上整额叠加；三键与手势等导航模式以实测的各模式避让值为准，用户声明正常的模式把“布局不变”列为验收。同一避让值在不同模式下视觉占用不同时，以 TYPE_SYSTEM 底部高度是否大于 0 区分三键与手势导航，或请用户取舍，并在交付说明中标明未验证的模式。
7. 已有固定底部偏移的元素（如 position bottom: 50 的指示器）先比较该偏移与实测避让高度，已足以避开时不追加，也不把用户未提出的组件并入同一改动。

## 可选检查

- 在带导航指示条的设备上确认 bottomPadding 非 0、底部按钮与屏底之间留出指示条高度。
- 调整底部 Tab 高度后，分别在三键与手势导航模式下截图，核对文字到屏底或指示条的间距符合预期。
- 源端非全屏时对照两端截图：状态栏与导航栏区域为源端底色，内容起点在状态栏下沿、终点在导航栏上沿。

- 〔做法第 1 步〕导航栏底色默认值：应用主题与代码都没另设 navigationBarColor（值等于 navigation_bar_default #00808080）、未强制 edge-to-edge、设备 config_navBarDefaultTransparent 为 false 时，框架改用 navigation_bar_compatible，即不透明黑
- 〔做法第 1 步〕setWindowLayoutFullScreen(isLayoutFullScreen: boolean): Promise<void>：主窗口创建时默认非沉浸式，界面内容默认避开状态栏和导航区域；true 时布局不避让、组件可能与其重叠；进出沉浸式不改变窗口尺寸和位置
- 〔做法第 1 步〕setWindowSystemBarProperties(systemBarProperties: SystemBarProperties): Promise<void>，颜色 '#RRGGBB' 或 '#AARRGGBB'；statusBarContentColor 默认 '#E5FFFFFF'，设了它 isStatusBarLightIcon 无效；设备上 statusBarColor、statusBarContentColor 生效，navigationBarColor 一次试设没有生效（卡里上机）

- 〔做法第 1 步〕没设挖孔模式时 layoutInDisplayCutoutMode 默认 LAYOUT_IN_DISPLAY_CUTOUT_MODE_DEFAULT（主题枚举 default = 0）：设了 FLAG_FULLSCREEN 或横屏时窗口不与挖孔区重叠（OEM 可对不深于 16dp 的挖孔放开）
- 〔做法第 1 步〕最大宽高比：targetSdk < 26 默认 1.86；application 的 maxAspectRatio 或 meta-data android.max_aspect 有值时用声明值；activity 可调整大小（resizeableActivity=true，或未声明且 targetSdk ≥ 24）时不设上限
- 〔做法第 1 步〕从 Activity 的 WindowManager 取 Display#getMetrics/getSize 得到当前应用窗口尺寸：API ≤ 34 的设备上再减去系统装饰区与挖孔，API ≥ 35 返回窗口尺寸
- 〔做法第 1 步〕安卓上 targetSdk 低于 24、未声明 resizeableActivity、只设 FLAG_FULLSCREEN、主题未设挖孔模式与宽高比的窗口：状态栏隐藏、导航栏保留、挖孔所在边留黑、长边按 1.86 截断（参照机上机）
- 〔做法第 1 步〕安卓 Theme.Holo、targetSdk 低且无全屏或透明系统栏标志的窗口，内容在不透明黑色状态栏与导航栏之间；鸿蒙主窗口横屏时默认隐藏状态栏（非沉浸式布局下也是），调 setWindowSystemBarEnable(['status','navigation']) 后横屏也显示
- 〔做法第 1 步〕AppCompat 主题的状态栏颜色从哪来（应用主题没有另设 android:statusBarColor 时）：库主题不写 android:statusBarColor，API 21+ 设备上沿用平台父主题 Theme.Material(.Light).NoActionBar 的 ?android:attr/colorPrimaryDark，Base.V21.Theme.AppCompat(.Light) 再把 android:colorPrimaryDark 指向库属性 colorPrimaryDark。每个属性取主题链上离应用主题最近、写了它的那个 style：从应用主题沿 parent 全名逐级向上（没写 parent 时去掉名字最后一段），库里同名 style 在 values-vNN 下另有定义时按设备 API 级取覆盖版本（如 Base.Theme.AppCompat.Light 在 API 28+ 经 Base.V28→V26→V23→V22→V21 各层），不按主题名里的 Light/Dark 推断；MaterialComponents、Material3 主题本条不列值，按同一查法沿链查
- 〔做法第 1 步〕AppCompat 各标准主题的库属性 colorPrimaryDark（应用主题没有另设时，即状态栏默认色）：Theme.AppCompat 为 primary_dark_material_dark（@android:color/black）；Theme.AppCompat.Light 为 primary_dark_material_light（material_grey_600，#ff757575）；Theme.AppCompat.Light.DarkActionBar 由只在 values/ 定义的 Base.Theme.AppCompat.Light.DarkActionBar 覆写为 primary_dark_material_dark（黑）；Theme.AppCompat.DayNight 白天同 .Light（#ff757575）、夜间（values-night-v8）同 Theme.AppCompat（黑）；Theme.AppCompat.DayNight.DarkActionBar 白天同 .Light.DarkActionBar、夜间同 Theme.AppCompat，两种都是黑；.NoActionBar 变体同各自父主题。appcompat 1.1.0、1.3.1、1.6.1、1.8.0 取值相同；库也不写 android:windowLightStatusBar（状态栏图标默认浅色）
- 〔做法第 1 步 / 例外与边界〕非浮动窗口分内容和窗口背景两层（按 android-36.1 源码；R 之前版本的窗口布局代码未核）：PhoneWindow 给非浮动窗口设 FLAG_LAYOUT_IN_SCREEN|FLAG_LAYOUT_INSET_DECOR 与 setFitInsetsTypes(0)，生效主题 windowDrawsSystemBarBackgrounds=true 且 targetSdk≥21 时再加 FLAG_DRAWS_SYSTEM_BAR_BACKGROUNDS；此时 DecorView 只把导航栏 inset 记成 content root 的边距、decor 布局根（如 screen_simple）以 fitsSystemWindows=true 让出状态栏，窗口背景不内缩（mBackgroundInsets = Insets.NONE），两条栏是 DecorView 按 statusBarColor、navigationBarColor 画在背景之上的色块。windowDrawsSystemBarBackgrounds 默认值：平台 Theme 为 false（Holo 不覆写），Theme.Material、Theme.Material.Light 为 true，AppCompat 不覆写（API 21+ 沿用 Material 的 true）
- 〔做法第 1 步〕窗口背景怎么画：主题 windowBackground 与 Window#setBackgroundDrawable 设的图都经 DecorView#setWindowBackground 成为 DecorView（整个窗口）的背景；BitmapDrawable 的 gravity 默认 Gravity.FILL，位图按整窗宽高拉伸、不保持宽高比，所以窗口背景位图的几何取决于窗口尺寸
- 〔做法第 1 步〕ImageAttribute.objectFit(value: ImageFit): ImageAttribute；ImageFit.Fill：不保持宽高比缩放，使图片充满显示边界（对应安卓 BitmapDrawable 的 FILL 拉伸）
- 〔做法第 2、6 步〕AvoidAreaType：TYPE_SYSTEM = 0（文档：含状态栏和三键导航栏区域）、TYPE_CUTOUT = 1、TYPE_SYSTEM_GESTURE = 2（文档：当前所有设备均无）、TYPE_KEYBOARD = 3、TYPE_NAVIGATION_INDICATOR = 4（底部导航区域；文档：三键导航显示时始终存在）；平台没有规定两类高度的关系
- 〔做法第 2 步〕getWindowAvoidArea(type: AvoidAreaType): AvoidArea，AvoidArea = { visible, leftRect, topRect, rightRect, bottomRect }：系统元素中心落在窗口对角线分出的哪个三角区就放进哪个 Rect，状态栏在 topRect、底部导航区在 bottomRect；visible 无实际意义
- 〔做法第 2 步〕Rect = { left, top, width, height }，单位 px、整数（getWindowProperties().windowRect 同为 px）；UIContext.px2vp(value: number): number 把 px 换成 vp
- 〔做法第 2 步〕on(type: 'avoidAreaChange', callback: Callback<AvoidAreaOptions>): void，AvoidAreaOptions = { type: AvoidAreaType; area: AvoidArea }，off 同名注销；文档列的触发场景：全屏/悬浮/分屏切换、窗口旋转、折叠屏开合、跨设备流转
- 〔做法第 4 步〕bindSheet(isShow: boolean, builder: CustomBuilder, options?: SheetOptions): T；文档：未设 position、offset 且边界不与避让区重叠的组件（如弹窗、半模态）设 expandSafeArea 不生效
- 〔适用情境 / 做法第 4 步〕库的默认样式 Widget.Material3.BottomSheet 设 paddingBottomSystemWindowInsets=true（paddingTopSystemWindowInsets 也为 true）：应用没有另设 bottomSheetStyle 或覆写这两项时，源端 M3 底部弹层由库按系统栏 inset 补内边距
- 〔做法第 4 步〕窗口开了全屏布局时，bindSheet 底部弹层里贴底的内容不会自动避让导航指示条，会落进导航区
- 〔做法第 5 步〕padding 区域显示的是设了这个 padding 的组件自己的背景色（组件背景铺满含 padding 的整个组件区域）
- 〔做法第 5 步〕Tabs 自 API 11 默认 expandSafeArea([SafeAreaType.SYSTEM], [SafeAreaEdge.BOTTOM])；横向未设样式时 barHeight 默认 56vp；API 14 起 barHeight 为固定值时配合 safeAreaPadding（bottom 不设或为 0）TabBar 可扩展进底部安全区
- 〔做法第 6 步〕一款真机上 TYPE_NAVIGATION_INDICATOR 的 bottomRect 在三键与手势两种模式下都是 84px（28vp），手势小白条视觉上只占距底约 9–13vp：这个值不随导航模式变，也不等于小白条的视觉高度
