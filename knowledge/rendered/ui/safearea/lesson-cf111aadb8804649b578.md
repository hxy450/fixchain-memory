# getWindowAvoidArea 与 windowRect 的数值是 px：在 windowStage.loadContent 成功回调里取 UIContext、先 px2vp 再写入供 padding 消费的窗口模型（loadContent 之前调 getUIContext 抛 1300002）

## 何时使用

沉浸式安全区实现阶段，在 EntryAbility 或窗口服务里把避让区、窗口尺寸写进共享窗口模型时；安排 EntryAbility.onWindowStageCreate 中依赖 UIContext 的步骤相对 loadContent 的时机时

## 适用情境

目标用 setWindowLayoutFullScreen(true) 全屏，EntryAbility 通过 getWindowAvoidArea 取状态栏、导航条高度，通过 getWindowProperties().windowRect 取窗口尺寸，写入 AppStorageV2 共享的窗口模型；各页把这些值直接放进 .padding()/.height()，按 vp 解释。 也包括换算或其他依赖 UIContext 的步骤（如 setKeyboardAvoidMode）写在 onWindowStageCreate 中、位于 loadContent 调用之前或在其回调之外同步执行。

## 原因

避让区 Rect 与 windowRect 的数值单位是 px，ArkUI 数字尺寸默认是 vp；原样写入后，高密度屏上的避让量会放大数倍。来源中修复者首次写入时注释已写“这是物理像素、需换算”，读到工程内页面已用 uiContext.px2vp 的样例后，反而删去换算占位，把注释改成“按 vp 消费”，也没写窗口宽高。另一应用基线 EntryAbility 把导航避让区 84px 原样发布，页面按 vp 消费后底部留白过大，修复在发布端统一 px2vp。UIContent 只在 loadContent 成功后建立，之前调用 mainWindow.getUIContext() 会抛 1300002（Uicontent is nullptr），冷启动即闪退；d.ts 签名不写这一时序，只凭成员存在推定此刻可调用就会写错，而不运行应用的编译门发现不了。

## 做法

1. 在 windowStage.loadContent 的成功回调里（err.code 为 0 之后）取 const ui = mainWindow.getUIContext()；top = ui.px2vp(avoid.topRect.height)，bottom 与窗口宽高同理；模型注释标明字段为 vp。onWindowStageCreate 中 loadContent 之前只做不依赖 UIContent 的窗口调用。
2. 一时取不到 UIContext 时保留 px 字段并上报，不把 px 值写进声明为 vp 的字段。

## 可选检查

- 改动 EntryAbility 生命周期后静态核对：onWindowStageCreate 中位于 loadContent 之前或其回调之外同步执行的代码不调用 getUIContext、不依赖 UIContent。

- 〔适用情境 / 做法第 1 步〕Window.getWindowAvoidArea(type: AvoidAreaType): AvoidArea（首段 @since 9，窗口状态异常抛 1300002）；AvoidAreaType：TYPE_SYSTEM = 0（状态栏等系统区域）、TYPE_CUTOUT = 1（挖孔）、TYPE_SYSTEM_GESTURE = 2、TYPE_KEYBOARD = 3、TYPE_NAVIGATION_INDICATOR = 4（底部导航条，@since 11）；AvoidArea 有 leftRect、topRect、rightRect、bottomRect 四个 Rect，visible 字段文档写「无实际意义，暂不支持使用」；window 从 @kit.ArkUI 导入
- 〔原因 / 做法第 1 步〕window 的 Rect（left、top、width、height）单位是 px、应为整数；AvoidArea 的四个矩形和 WindowProperties.windowRect 都是 Rect，所以都是 px；ArkUI 的 Length 写 number 或不带单位的字符串时默认单位是 vp，'10px' 这样显式写单位才按 px
- 〔适用情境 / 做法第 1 步〕Window.getWindowProperties(): WindowProperties（首段 @since 9，窗口状态异常抛 1300002）；windowRect 是窗口尺寸，left、top 相对窗口所在屏幕左上角，文档写可在页面 onPageShow 或应用 onForeground 阶段获取；drawableRect（@since 11）要在 loadContent 或 setUIContent 加载页面后获取
- 〔做法第 1 步〕避让区变化用 Window.on(type: 'avoidAreaChange', callback: Callback<AvoidAreaOptions>): void 监听（首段 @since 9），回调参数的 type 是 AvoidAreaType、area 是同样以 px 为单位的 AvoidArea；文档列的触发场景有全屏、悬浮、分屏模式切换，窗口旋转，折叠屏折叠态与展开态切换，跨设备流转；避让区可能为 0
- 〔适用情境〕同族接口 Window.getWindowAvoidAreaIgnoringVisibility(type: AvoidAreaType): AvoidArea（@since 22）：不管该类区域当前是否可见都返回避让区，返回值同样是 px 的 AvoidArea；不支持的设备抛 801
- 〔适用情境〕API 23 起页面侧另有以 vp 表示的避让区：@Env(SystemProperties.WINDOW_AVOID_AREA) 装饰的变量类型为 window.UIEnvWindowAvoidAreaInfoVP（statusBar、cutout、keyboard、navigationIndicator 四项，各项的 Rect 单位为 vp），@Env(SystemProperties.WINDOW_AVOID_AREA_PX) 给 px 版本；避让区变化时变量自动更新
- 〔做法第 1 步〕WindowStage.getMainWindowSync(): Window（首段 @since 9，窗口状态异常抛 1300002、WindowStage 异常抛 1300005）取主窗口；另有 Promise 和 callback 版的 getMainWindow
- 〔原因 / 做法第 1 步〕WindowStage.loadContent 是异步接口：loadContent(path: string, callback: AsyncCallback<void>): void、loadContent(path: string, storage: LocalStorage, callback: AsyncCallback<void>): void、loadContent(path: string, storage?: LocalStorage): Promise<void>（首段 @since 9）；回调里 err.code 非 0 表示失败；多次调用会先销毁已有的页面内容（UIContent）
- 〔原因 / 做法第 1 步〕Window.getUIContext(): UIContext（首段 @since 10）的声明和文档只列错误码 1300002，原因写「窗口未创建或已销毁」，签名不写调用时机；指南写明必须在 UI 实例创建完成后才能通过窗口对象的 getUIContext 取 UIContext，建议在 loadContent 的成功回调中调用，并注明 loadContent 是异步接口、在它之后同步执行的代码不能保证 UI 实例已创建
- 〔原因〕EntryAbility.onWindowStageCreate 里在 loadContent 之前同步调用 mainWindow.getUIContext()，冷启动即抛 1300002，故障日志写 [window][getUIContext] Uicontent is nullptr，应用闪退（target SDK 6.1.0(23)）；只跑编译不运行时不报
- 〔做法第 1 步〕UIContext.px2vp(value: number): number（首段 @since 12）把 px 换成 vp，vp2px 反之；全局函数 px2vp 自 API 18 起废弃，@useinstead UIContext.px2vp；UIContext 从 @kit.ArkUI 导入
- 〔做法第 2 步〕px2vp/vp2px 的换算依赖 UI 实例：主窗口 loadContent 或 setUIContent 之前（无 UI 实例）全局 px2vp/vp2px 按默认屏幕的像素密度换算，多屏时可能和预期不一致；文档给的替换写法是用 display.getDefaultDisplaySync() 取默认屏幕的逻辑像素密度 densityPixels（物理像素与逻辑像素的缩放系数）来算
- 〔原因〕全屏窗口下设备底部导航条避让区 bottomRect.height 为 84px；把它不经换算当作 vp 写进 padding 时，底部留白明显大于导航条高度
- 〔适用情境〕UIContext.setKeyboardAvoidMode(value: KeyboardAvoidMode): void（@since 11）：声明注释写默认模式 KeyboardAvoidMode.OFFSET；KeyboardAvoidMode 取值 OFFSET = 0、RESIZE = 1、OFFSET_WITH_CARET = 2、RESIZE_WITH_CARET = 3、NONE = 4，从 @kit.ArkUI 导入；它是 UIContext 上的方法，同样要先取到 UIContext
