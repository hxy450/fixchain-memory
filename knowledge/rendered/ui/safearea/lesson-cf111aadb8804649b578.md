# getWindowAvoidArea 与 windowRect 的数值是 px：在 windowStage.loadContent 成功回调里取 UIContext、先 px2vp 再写入供 padding 消费的窗口模型（loadContent 之前调 getUIContext 抛 1300002）

## 何时使用

沉浸式安全区实现阶段，在 EntryAbility 或窗口服务里把避让区、窗口尺寸写进共享窗口模型时；安排 EntryAbility.onWindowStageCreate 中依赖 UIContext 的步骤相对 loadContent 的时机时

## 适用情境

目标用 setWindowLayoutFullScreen(true) 全屏，EntryAbility 通过 getWindowAvoidArea 取状态栏、导航条高度，通过 getWindowProperties().windowRect 取窗口尺寸，写入 AppStorageV2 共享的窗口模型；各页把这些值直接放进 .padding()/.height()，按 vp 解释。on('avoidAreaChange') 与 on('windowSizeChange') 回调给出的避让区、窗口尺寸同样是 px，回调里更新同一模型时同样先换算；改从以 vp 计的避让区环境变量（UIEnvWindowAvoidAreaInfoVP，API 23 起）取值的已经是 vp，不再换算。 也包括换算或其他依赖 UIContext 的步骤（如 setKeyboardAvoidMode）写在 onWindowStageCreate 中、位于 loadContent 调用之前或在其回调之外同步执行。换算只做一次：页面自己调 getWindowAvoidArea 并已用 px2vp 换算的保持原样；页面改读发布端已换成 vp 的模型字段时，去掉页面上原有的那次 px2vp，不在同一个值上换算两次。

## 原因

避让区 Rect 与 windowRect 的数值单位是 px，ArkUI 数字尺寸默认是 vp；原样写入后，高密度屏上的避让量会放大数倍。来源中修复者首次写入时注释已写“这是物理像素、需换算”，读到工程内页面已用 uiContext.px2vp 的样例后，反而删去换算占位，把注释改成“按 vp 消费”，也没写窗口宽高。另一应用基线 EntryAbility 把导航避让区 84px 原样发布，页面按 vp 消费后底部留白过大，修复在发布端统一 px2vp。UIContent 只在 loadContent 成功后建立，之前调用 mainWindow.getUIContext() 会抛 1300002（Uicontent is nullptr），冷启动即闪退；d.ts 签名不写这一时序，只凭成员存在推定此刻可调用就会写错，而不运行应用的编译门发现不了。

## 做法

1. 在 windowStage.loadContent 的成功回调里（err.code 为 0 之后）取 const ui = mainWindow.getUIContext()；top = ui.px2vp(avoid.topRect.height)，bottom 与窗口宽高同理；模型注释标明字段为 vp。onWindowStageCreate 中 loadContent 之前只做不依赖 UIContent 的窗口调用。
2. 一时取不到 UIContext 时保留 px 字段并上报，不把 px 值写进声明为 vp 的字段。

## 可选检查

- 改动 EntryAbility 生命周期后静态核对：onWindowStageCreate 中位于 loadContent 之前或其回调之外同步执行的代码不调用 getUIContext、不依赖 UIContent。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因 / 做法第 1 步〕window 的 Rect（left、top、width、height）以 px 为单位、取整数；getWindowAvoidArea 与 getWindowAvoidAreaIgnoringVisibility 返回的 AvoidArea 四个矩形、WindowProperties.windowRect 都是这种 Rect
- 〔原因〕ArkUI 数值不带单位时默认单位是 vp，vp 与 px 的比例取决于屏幕像素密度
- 〔做法第 1 步〕AvoidAreaType.TYPE_SYSTEM 是系统默认区域（含状态栏和三键导航栏），TYPE_NAVIGATION_INDICATOR 是底部导航区域（三键导航显示时始终存在），TYPE_CUTOUT 是挖孔区域；getWindowAvoidArea 用于在 onWindowStageCreate 中获取应用启动时的初始避让区
- 〔做法第 1 步〕WindowProperties.windowRect 文档写明可在页面生命周期 onPageShow 或应用生命周期 onForeground 阶段获取
- 〔原因 / 做法第 1 步〕必须在 UI 实例创建完成后才能通过窗口对象的 getUIContext 取得 UIContext，文档建议在 loadContent 的成功回调中调用；loadContent 是异步接口，写在它之后的同步代码不能保证 UI 实例已创建
- 〔原因〕EntryAbility.onWindowStageCreate 中在 loadContent 之前同步调用 mainWindow.getUIContext() 时，冷启动抛 1300002、日志为 Uicontent is nullptr，应用闪退；声明和文档对 1300002 的说明是窗口未创建或已销毁
- 〔做法第 2 步〕loadContent 或 setUIContent 之前没有 UI 实例，此时 px2vp、vp2px 按默认屏幕的像素密度换算（多屏时可能与预期屏幕不一致），fp2px 等返回 undefined；文档给的替代是用 display.getDefaultDisplaySync() 取默认屏幕的逻辑像素密度计算
- 〔原因〕设备底部导航避让区为 84px 时，按原值写入 padding 被当作 84vp，页面底部留白明显过大
