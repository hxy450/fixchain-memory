# 系统栏图标深浅按源端浅色状态栏标志推导：未设标志时安卓图标为白色，不照搬模板默认，也不按主题名或底色对比度自选

## 何时使用

沉浸式窗口配置阶段，调用 setWindowSystemBarProperties 设置 statusBarContentColor/navigationBarContentColor 或修改系统栏底色时；规格提取阶段整理主题与状态栏外观时

## 适用情境

Android 源端以主题、values-vNN 覆盖或代码决定状态栏图标深浅：windowLightStatusBar、SYSTEM_UI_FLAG_LIGHT_STATUS_BAR、setSystemBarsAppearance(APPEARANCE_LIGHT_STATUS_BARS)、ImmersionBar darkMode(true)、WindowInsetsControllerCompat.isAppearanceLightStatusBars = true 等表示深色图标；androidx.activity 的 enableEdgeToEdge() 用默认参数时按当前界面配置的深浅色设图标（浅色模式深色图标、深色模式白色图标，应用自己强制了深浅色时按应用的设定）；全都没有时为白色图标，即使主题是 Theme.AppCompat.Light 一类、状态栏底色偏浅；目标全屏窗口用 setWindowSystemBarProperties 设置系统栏，沉浸式 skill 示意写“透明背景 + 浅色文字”，规格可能只要求底色 parity。

## 原因

内容色决定时间、电量等系统图标的深浅。照模板写白色，源端为深色图标的浅色页面顶部会看不见图标；按“Light 主题”或“浅底配深色”的对比度自选，又会把源端的白色图标改成深色。主题名里的 Light 只决定窗口与控件配色，不会让状态栏图标变深。来源中一处修复者只读派工和沉浸式 skill 就写成白色；另一应用的两位实现者都读到了未设浅色标志的 Light 主题，仍按底色对比度选了深色。

## 做法

1. 设置内容色前查源主题（顺着 parent 链查到底，平台的 Theme.Material.Light.LightStatusBar 一类父主题自带标志）、各 values-vNN 与 values-night 覆盖和代码中的浅色状态栏标志：有则用深色图标（如 #FF000000），全都没有则用 '#ffffff'；values-night 里取值不同、或源端用默认参数调用 enableEdgeToEdge() 时，按深浅色模式分别设置；页面间不同时按页切换。
2. “与底色对比足够”只作为源端没有可迁移设定时的兜底，并在注释写明依据；修改系统栏底色时按源主题同步复核内容色，不沿用按旧底色写的注释。
3. 规格在主题与样式链中写明状态栏图标明暗（相关标志是否存在及结论），状态栏外观验收同时列出底色与图标色。
