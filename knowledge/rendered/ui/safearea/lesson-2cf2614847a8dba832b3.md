# 向子页或页内浮层下发状态栏高度参数时写明消费方式，挂在同一 Stack 的每一层都拿到它

## 何时使用

派工与界面实现阶段，向子页、页内浮层下发状态栏高度参数，或把浮层挂进从窗口顶起的宿主 Stack 时（前提：源端该层确实落在状态栏之下）

## 适用情境

宿主页采用“子页自理”分工，以组件参数下发状态栏高度；子页或浮层（遮罩 + 居中卡片、铺满父容器）与列表、顶栏同挂一个 Stack；派工或槽位契约可能只列出回调参数，或写“接收但本页不使用”。

## 例外与边界

- 目标父容器已替该层加了顶部避让，且能指出对应代码位置
- 这条的前提是源端该层确实落在状态栏之下：例如作为 Material3 Scaffold 的内容经 padding(innerPadding) 挂载、Scaffold 没有 topBar 且没覆写 contentWindowInsets，innerPadding 顶部就是状态栏高。源端 Scaffold 覆写了 contentWindowInsets 不含状态栏、或该层本来就铺到状态栏下时，目标也不给该层加顶部避让，以源端该层实际的顶边位置为准

## 原因

参数接上却在派工里写“本页不使用”，实现者会照办，状态栏高度就无人消费；槽位契约和派工漏掉某一层时，只有这一层压到状态栏下、其他层正常，容易被当作局部偏差放过。

## 做法

1. 派工不写“接收但不使用”；认为某层无需消费时，给出源端父容器已消费该 inset 的源码位置。实现者收到未消费的参数时，先核目标父容器是否替它避让，没有就消费。
2. 浮层挂在从窗口顶起的 Stack 时，槽位契约和派工都带上状态栏高度，组件以参数透传，根节点加顶部 padding，与兄弟层同一基准。

## 可选检查

- 有疑问时检索每个状态栏高度参数的消费点；对照源端截图核浮层遮罩起点是否等于状态栏高。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 2 步〕@Param 由父到子单向同步：允许本地初始化，同时有本地初始值和外部传入值时以外部传入值初始化；父组件的数据源（@Local 或 @Param）变化时同步给子组件；子组件不能本地修改 @Param
- 〔例外与边界 / 做法第 2 步〕expandSafeArea() 不传参时 types 为 SYSTEM、CUTOUT、KEYBOARD，edges 为上下左右四边
- 〔做法第 2 步〕窗口接口 getWindowAvoidArea、avoidAreaChange 返回的避让区矩形（Rect）以 px 为单位、取整数；ArkUI 的 padding、height 传数字时按 vp 解释，两者相加前要先用 px2vp 换算
