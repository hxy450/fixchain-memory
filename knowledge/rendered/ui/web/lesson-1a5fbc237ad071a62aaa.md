# 宿主原生标题栏与 H5 自带导航栏按 H5 当前状态双向决定显隐；单页 H5 的状态从页面内容判断

## 何时使用

WebView 页面实现与修复阶段，加载的第三方 H5 有的状态自带导航栏、有的没有，决定宿主原生返回/标题栏在 H5 各页面状态下是否显示时

## 适用情境

目标页用 Web 加载第三方单页 H5，宿主自带返回与标题栏；H5 首页没有自己的导航栏，而结果、查单、选择城市等子状态自带返回栏，状态切换时 URL 可能不变。

## 例外与边界

- runJavaScript 执行失败时结果是 null：探测拿不到结果时沿用上一次的显隐，不把 null 当成首页态或子状态去切换；“每次判定都给出显示或隐藏”只针对拿到了页面特征的那次判定。

## 原因

宿主栏该不该显示取决于 H5 当前状态；整体删除会让首页丢失返回与标题，只在命中子页时隐藏又不恢复会形成单向状态，按 URL 判断则漏掉 URL 不变的单页切换。来源中修复者针对结果页“两个状态栏”整体删掉宿主栏，随后改为按 URL 子串只置隐藏，再改为脚本探测却忽略首页态，经四轮用户反馈才稳定为逐状态双向映射。

## 做法

1. 修改前列出 H5 各状态中哪些自带导航栏、哪些只靠宿主栏；只在自带导航栏的状态隐藏宿主栏。
2. 把显隐写成当前状态的完整映射，每次判定都给出显示或隐藏，回到首页态时恢复宿主栏。
3. 状态判断用 runJavaScript 读取页面特征（标题格式、特征文字），在页面事件与短周期探测中都更新以覆盖加载瞬间；不只依赖 URL 或 onOverrideUrlLoading。

## 可选检查

- 需要确认时，在真机逐个状态核对：首页有返回和标题、每个子状态只有一层导航栏、从子状态返回后宿主栏恢复。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 3 步〕WebviewController.runJavaScript 异步执行脚本，Promise 结果是脚本执行结果，执行失败时为 null；回调版本在执行失败或脚本没有返回值时返回 null
- 〔做法第 3 步〕onPageEnd 只对主框架触发，不对子框架触发
- 〔做法第 3 步〕onOverrideUrlLoading 在 URL 将要加载到当前 Web 时触发；POST 请求、loadUrl 主动触发的跳转、iframe 加载 HTTP(s) 或 about:blank 都不触发
