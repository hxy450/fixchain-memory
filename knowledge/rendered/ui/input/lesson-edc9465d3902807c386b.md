# 菜单 SearchView 迁成自绘搜索栏时把展开、焦点、提交、收起与菜单重建分成独立状态和事件，焦点态取自 TextInput 焦点回调

## 何时使用

规格提取与界面实现阶段，把菜单 actionView 的 SearchView（collapseActionView）翻成自绘标题栏搜索框、决定工具栏菜单随搜索状态切换时

## 适用情境

源端菜单项以 SearchView 为 actionView 且 showAsAction 含 collapseActionView，代码注册 OnActionExpandListener、OnQueryTextFocusChangeListener 与 OnQueryTextListener（onQueryTextSubmit 返回 false 才由 SearchView 投递 ACTION_SEARCH），收起时 invalidateOptionsMenu 重建菜单，提交后只收键盘不清焦点；目标为自绘标题栏加按条件构建的 TextInput。展开、收起回调只在菜单项带 collapseActionView 时存在：源端菜单项没有这个标志时 OnActionExpandListener 不回调，不给目标补展开态和收起时的清空、重载、菜单重建副作用，按源端实际注册的监听列状态。

## 原因

SearchView 的展开态与输入焦点是两套状态：展开后可以失焦（收键盘、打开对话框），收起有独立回调与菜单重建，提交是否投递 ACTION_SEARCH 取决于 onQueryTextSubmit 的返回值。把控件折成几个查询函数，或用一个布尔同时表示展开与焦点、用取消图标代替 collapseActionView、在点击时手工翻转焦点标志，展开取焦、按焦点切换菜单、收起复位与重载就会丢失或互相串扰。

## 做法

1. 规格按控件 API 列状态机，每个回调写成验收项：展开与收起回调各自的副作用（收起清空查询、复位标签、重载列表、重建菜单）、焦点变化对应的菜单显隐、onQueryTextSubmit 返回值与 ACTION_SEARCH 投递、trim 后为空（含纯空白）不提交、提交后收键盘；不以“应用内直调、内化等价”替代。
2. 实现前读源端创建该控件的方法全文，目标分设展开态与焦点态：展开态只由展开、收起入口改写，焦点态只在 TextInput 的 onFocus/onBlur 中写，菜单矩阵按源端监听读取对应的那一个。
3. 展开时用 FocusController.requestFocus(key) 取焦；输入框按条件构建时先置待取焦标记，在它的 onAppear 之后再请求（控件未上树时请求会失败，已观察错误码 150003）。
4. 源端提交后只收键盘、保留焦点时，把“收键盘引起的失焦”标记出来，不触发焦点变化分支，工具栏保持聚焦态菜单；收键盘接口按是否保留焦点选择：TextInput 回车提交默认失焦并收起键盘，要保持编辑态在 onSubmit 回调里调 keepEditableState()；inputMethodController.stopInputSession 会让编辑框失焦；showSoftKeyboard、hideSoftKeyboard 只有系统应用能调。
5. 源方法里对宿主栏控件和框架对象的每个调用（展开、收起、菜单重建、前置提交）逐条落到目标或登记缺口，不以验收描述已覆盖代替。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码；androidx.appcompat:appcompat 1.7.0（字节码）。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 做法第 1 步〕MenuItem.OnActionExpandListener 只对带 SHOW_AS_ACTION_COLLAPSE_ACTION_VIEW 的菜单项回调；onMenuItemActionExpand、onMenuItemActionCollapse 返回 false 时这次展开或收起被抑制；expandActionView() 在菜单项没有可折叠的 actionView 时直接返回 false，不回调监听
- 〔适用情境 / 原因 / 做法第 1 步〕SearchView 提交时先看文本 trim 后是否为空，为空则什么都不做，也不调 onQueryTextSubmit；监听为空或 onQueryTextSubmit 返回 false 时，配置了 searchable 的投递搜索 Intent（ACTION_SEARCH），并收起输入法、关掉建议列表；返回 true 时这些都不做，输入法也不收；框架 SearchView 与 AppCompat 1.7.0 的 SearchView 逻辑相同
- 〔原因 / 做法第 1、2 步〕SearchView 作为 actionView 展开（onActionViewExpanded）时清空文本并退出图标化，输入框 requestFocus 并弹出输入法；收起（onActionViewCollapsed）时用 setQuery("", false) 清空文本（不触发提交）、clearFocus，并恢复图标化
- 〔做法第 3 步〕FocusController.requestFocus(key) 按组件 id 转移焦点、当前帧生效；目标组件不可获焦抛 150001，有不可获焦的祖先抛 150002，组件不在树上或不存在抛 150003
- 〔做法第 3 步〕通用事件 onAppear 在组件挂载后触发
- 〔做法第 3 步〕按条件构建的 TextInput 在构建条件刚被改写、组件尚未挂载时调用 FocusController.requestFocus，设备上抛 150003
- 〔做法第 4 步〕TextInput 在按下输入法回车键时触发 onSubmit；非 TV 设备上回车后输入框默认失焦并收起键盘，在 onSubmit 回调里调用 SubmitEvent.keepEditableState() 可保持编辑态
- 〔做法第 4 步〕inputMethodController 的 showSoftKeyboard、hideSoftKeyboard 需要 ohos.permission.CONNECT_IME_ABILITY，仅系统应用可用；stopInputSession 结束输入会话并隐藏软键盘；hideTextInput 隐藏软键盘、使编辑框退出编辑状态，不解除与输入法的绑定
- 〔做法第 4 步〕对 ArkUI TextInput 调用 inputMethodController.stopInputSession 收键盘时，编辑框随之失焦
- 〔原因 / 做法第 2 步〕openCustomDialog 等弹窗的 focusable 不设时为 true（API 19 起），覆盖在当前窗口之上的弹窗弹出时获取焦点
