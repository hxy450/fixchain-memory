# 菜单 SearchView 迁成自绘搜索栏时把展开、焦点、提交、收起与菜单重建分成独立状态和事件，焦点态取自 TextInput 焦点回调

## 何时使用

规格提取与界面实现阶段，把菜单 actionView 的 SearchView（collapseActionView）翻成自绘标题栏搜索框、决定工具栏菜单随搜索状态切换时

## 适用情境

源端菜单项以 SearchView 为 actionView 且 showAsAction 含 collapseActionView，代码注册 OnActionExpandListener、OnQueryTextFocusChangeListener 与 OnQueryTextListener（onQueryTextSubmit 返回 false 才由 SearchView 投递 ACTION_SEARCH），收起时 invalidateOptionsMenu 重建菜单，提交后只收键盘不清焦点；目标为自绘标题栏加按条件构建的 TextInput。

## 原因

SearchView 的展开态与输入焦点是两套状态：展开后可以失焦（收键盘、打开对话框），收起有独立回调与菜单重建，提交是否投递 ACTION_SEARCH 取决于 onQueryTextSubmit 的返回值。把控件折成几个查询函数，或用一个布尔同时表示展开与焦点、用取消图标代替 collapseActionView、在点击时手工翻转焦点标志，展开取焦、按焦点切换菜单、收起复位与重载就会丢失或互相串扰。

## 做法

1. 规格按控件 API 列状态机，每个回调写成验收项：展开与收起回调各自的副作用（收起清空查询、复位标签、重载列表、重建菜单）、焦点变化对应的菜单显隐、onQueryTextSubmit 返回值与 ACTION_SEARCH 投递、trim 后为空（含纯空白）不提交、提交后收键盘；不以“应用内直调、内化等价”替代。
2. 实现前读源端创建该控件的方法全文，目标分设展开态与焦点态：展开态只由展开、收起入口改写，焦点态只在 TextInput 的 onFocus/onBlur 中写，菜单矩阵按源端监听读取对应的那一个。
3. 展开时用 FocusController.requestFocus(key) 取焦；输入框按条件构建时先置待取焦标记，在它的 onAppear 之后再请求（控件未上树时请求会失败，已观察错误码 150003）。
4. 源端提交后只收键盘、保留焦点时，把“收键盘引起的失焦”标记出来，不触发焦点变化分支，工具栏保持聚焦态菜单；收键盘接口按是否保留焦点选择。
5. 源方法里对宿主栏控件和框架对象的每个调用（展开、收起、菜单重建、前置提交）逐条落到目标或登记缺口，不以验收描述已覆盖代替。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；安卓 Android SDK 源码 android-36.1；appcompat 1.1.0、1.8.0。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境〕SearchView 的提交（onSubmitQuery）只在查询串 TextUtils.getTrimmedLength > 0 时进行，纯空白也不提交；onQueryTextSubmit 返回 true 时 SearchView 不再做任何事（不投递 ACTION_SEARCH、不收键盘）；返回 false 或没设监听时，配置了 searchable 才投递搜索 Intent，然后收起软键盘、关闭建议下拉，焦点不清除。〔成立范围：对象：android.widget.SearchView 与 androidx.appcompat.widget.SearchView 的提交路径（appcompat 1.1.0 与 1.8.0 字节码一致）。条件：用户按输入法的提交键。不成立的情形：应用在 onQueryTextSubmit 里自行 clearFocus 或收键盘时以应用代码为准。〕
- 〔做法第 1 步〕菜单项收起时 SearchView.onActionViewCollapsed 执行 setQuery("", false)（清空查询且不提交）、clearFocus()，并恢复展开前的 imeOptions；展开时 onActionViewExpanded 清空文本并 setIconified(false)，后者让输入框请求焦点并弹出软键盘。〔成立范围：对象：showAsAction 含 collapseActionView、actionView 为 SearchView（框架或 appcompat 1.1.0 至 1.8.0）的菜单项。条件：经菜单项展开、收起（含返回键收起）。不成立的情形：SearchView 直接放在布局里、不作为可折叠 actionView 时不走这两个回调。〕
- 〔做法第 5 步〕返回键会先收起已展开的 actionView：框架 Activity#onBackPressed 先调 ActionBar.collapseActionView()，收起成功就结束这次返回；appcompat 在返回键抬起时先关闭已打开的选项菜单面板（1.1.0 在 AppCompatDelegateImpl#onKeyUp 里、1.8.0 在 AppCompatDelegateImpl#onBackPressed 里），再结束 ActionMode，再调 support ActionBar 的 collapseActionView()，收起成功即消费这次返回。〔成立范围：对象：带可折叠 SearchView 菜单项的 Activity（框架 ActionBar，或 appcompat 1.1.0 至 1.8.0 setSupportActionBar 的 Toolbar）。条件：搜索栏处于展开态时按返回。不成立的情形：应用覆写 onBackPressed 或 onKeyUp 且不调父类时。〕
- 〔做法第 4 步〕鸿蒙 TextInput 在非 TV 设备上按输入法回车键提交时，默认失焦并收起键盘；在 onSubmit 回调里调用 event.keepEditableState() 才保持编辑态。〔成立范围：对象：TextInput 的 onSubmit。条件：非 TV 设备、onSubmit 里没有调用 keepEditableState()。不成立的情形：TV 设备，或回调里调用了 keepEditableState()。〕
- 〔做法第 3 步〕FocusController.requestFocus(key) 按组件 id 把焦点转到组件树上的对应节点、当前帧生效，失败时抛错：150001 组件不可获焦，150002 有不可获焦的祖先，150003 组件不在树上或不存在。〔成立范围：对象：UIContext.getFocusController().requestFocus（API 12 起），key 为组件的 .id()。条件：目标 TextInput 由条件分支构建、与改状态在同一帧请求（还没上树）时。不成立的情形：组件已挂上组件树且可获焦。〕
- 〔做法第 4 步〕InputMethodController.hideSoftKeyboard 需要 ohos.permission.CONNECT_IME_ABILITY、仅系统应用可用；hideTextInput 会退出文本编辑状态并隐藏软键盘，不解除与输入法的绑定（再调 showTextInput 可重新进入编辑态）。〔成立范围：对象：@ohos.inputMethod 的 InputMethodController。条件：为“提交后只收键盘”选收键盘接口时。不成立的情形：持有该权限的系统应用可以调用 hideSoftKeyboard。〕
