# 菜单 SearchView 迁成自绘搜索栏时把展开、焦点、提交、收起与菜单重建分成独立状态和事件，焦点态取自 TextInput 焦点回调

## 何时使用

规格提取与界面实现阶段，把菜单 actionView 的 SearchView（collapseActionView）翻成自绘标题栏搜索框、决定工具栏菜单随搜索状态切换时

## 适用情境

源端菜单项以 SearchView 为 actionView 且 showAsAction 含 collapseActionView，代码注册 OnActionExpandListener、OnQueryTextFocusChangeListener 与 OnQueryTextListener（查询 trim 后非空才回调 onQueryTextSubmit；返回 false 时 SearchView 收起键盘、不清焦点，设过 setSearchableInfo 的才再投递 ACTION_SEARCH；返回 true 时这两件都不做），收起时 invalidateOptionsMenu 重建菜单，提交后只收键盘不清焦点；目标为自绘标题栏加按条件构建的 TextInput。

## 原因

SearchView 的展开态与输入焦点是两套状态：展开后可以失焦（收键盘、打开对话框），收起有独立回调与菜单重建，提交是否投递 ACTION_SEARCH 取决于 onQueryTextSubmit 的返回值。把控件折成几个查询函数，或用一个布尔同时表示展开与焦点、用取消图标代替 collapseActionView、在点击时手工翻转焦点标志，展开取焦、按焦点切换菜单、收起复位与重载就会丢失或互相串扰。

## 做法

1. 规格按控件 API 列状态机，每个回调写成验收项：展开与收起回调各自的副作用（收起清空查询、复位标签、重载列表、重建菜单）、焦点变化对应的菜单显隐、onQueryTextSubmit 返回值与 ACTION_SEARCH 投递、trim 后为空（含纯空白）不提交、提交后收键盘；不以“应用内直调、内化等价”替代。
2. 实现前读源端创建该控件的方法全文，目标分设展开态与焦点态：展开态只由展开、收起入口改写，焦点态只在 TextInput 的 onFocus/onBlur 中写，菜单矩阵按源端监听读取对应的那一个。
3. 展开时用 FocusController.requestFocus(key) 取焦；输入框按条件构建时先置待取焦标记，在它的 onAppear 之后再请求（控件未上树时请求会失败，已观察错误码 150003）。
4. 源端提交后只收键盘、保留焦点时，把“收键盘引起的失焦”标记出来，不触发焦点变化分支，工具栏保持聚焦态菜单；收键盘接口按是否保留焦点选择：目标 TextInput 回车提交默认失焦并收起键盘（非 TV 设备），要保留焦点就在 onSubmit 回调里调 event.keepEditableState()；保留焦点时不用 stopInputSession()（会让输入框失焦），也不用三方应用无权调用的 hideSoftKeyboard()。
5. 源方法里对宿主栏控件和框架对象的每个调用（展开、收起、菜单重建、前置提交）逐条落到目标或登记缺口，不以验收描述已覆盖代替。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 源码 android-36.1；androidx.appcompat:appcompat 1.1.0、1.7.1（字节码）。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 原因〕框架菜单项 MenuItemImpl.expandActionView() 只在 showAsAction 含 SHOW_AS_ACTION_COLLAPSE_ACTION_VIEW 且有 actionView（或 ActionProvider 能建出）时才展开；设了 OnActionExpandListener 时 onMenuItemActionExpand 返回 true 才展开、返回 false 不展开。collapseActionView() 在没有该标志时直接返回 false，有该标志但还没有 actionView 时直接返回 true（视为已收起），设了监听时 onMenuItemActionCollapse 返回 true 才收起。
- 〔适用情境 / 做法第 1 步〕SearchView 提交（框架 android.widget.SearchView 与 androidx.appcompat.widget.SearchView 1.1.0、1.7.1 同一逻辑）：查询 trim 后长度为 0 时什么都不做，也不回调 onQueryTextSubmit；设了监听且 onQueryTextSubmit 返回 true 时 SearchView 不再做任何事（不投递、不收键盘）；没有监听或返回 false 时，设过 setSearchableInfo（mSearchable 非空）才 launchQuerySearch 投递 ACTION_SEARCH，然后一律 setImeVisibility(false) 收起键盘（不清焦点）并关掉建议下拉。
- 〔原因 / 做法第 1、3 步〕SearchView 作为 collapseActionView 的 actionView：展开时 onActionViewExpanded 把文本清空并 setIconified(false)，经 onSearchClicked 让输入框 requestFocus() 并弹出键盘；收起时 onActionViewCollapsed 调 setQuery("", false) 清空查询（不提交）并 clearFocus()（框架 SearchView 与 AppCompat 1.7.1 相同）。
- 〔做法第 2 步〕ArkUI CommonMethod.onFocus(event: () => void): T、onBlur(event: () => void): T（自 API 8）：组件获得焦点、失去焦点时回调。
- 〔做法第 3 步〕FocusController.requestFocus(key: string): void（自 API 12）：FocusController 经 UIContext.getFocusController()（自 API 12）取得；按组件标识（组件 .id(key) 设的 id）把焦点移到组件树上对应的节点，当前帧生效；错误码 150001 组件不可获焦、150002 有不可获焦的祖先、150003 组件不在树上或不存在。
- 〔做法第 3 步〕ArkUI CommonMethod.onAppear(event: () => void): T（自 API 7）：组件挂载显示时回调。
- 〔做法第 3 步〕按条件构建的 TextInput 在条件刚置为真、组件还没构建上树时调 requestFocus(key)，设备上抛 150003。
- 〔做法第 4 步〕TextInputAttribute.onSubmit(callback: OnSubmitCallback)（onSubmit 自 API 7，这个签名自 API 18；type OnSubmitCallback = (enterKey: EnterKeyType, event: SubmitEvent) => void）：按输入法回车键时回调；非 TV 设备默认提交后输入框失焦并收起键盘，在回调里调 event.keepEditableState()（SubmitEvent 自 API 11）可保持编辑态。
- 〔做法第 4 步〕@ohos.inputMethod 的 InputMethodController（inputMethod.getController()，自 API 9）：hideTextInput(): Promise<void>（自 API 10）隐藏软键盘、编辑框退出编辑状态，但不解除与输入法的绑定，文档定位为自绘控件用、与 showTextInput 配对；stopInputSession(): Promise<boolean>（自 API 9）结束当前输入会话并隐藏软键盘，要在编辑框与输入法绑定后才能调；hideSoftKeyboard(): Promise<void>（自 API 9）只给系统应用，需权限 ohos.permission.CONNECT_IME_ABILITY，权限校验失败报 201。
- 〔做法第 4 步〕系统 TextInput 获焦时调 inputMethodController.stopInputSession()，设备上编辑框随之失焦。
- 〔原因〕promptAction.BaseDialogOptions.focusable 与 CustomDialogControllerOptions.focusable（自 API 19）默认 true：自定义弹窗显示时获取焦点；输入框获焦时打开这样的弹窗，设备上输入框被弹窗抢走焦点。
