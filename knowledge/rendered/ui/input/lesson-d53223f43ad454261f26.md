# 源码用 selectable 行加条件尾部勾选表示选中时按同一结构实现，不按“单选”语义换成 Radio

## 何时使用

界面实现阶段，把 Compose 排序、筛选等选择列表行转换为 ArkUI 行组件并确定选中标记时

## 适用情境

源端每行是 Row(Modifier.selectable(selected) { ... })，行首图标加文字，选中时才出现尾部 Icon(ic_check, tint = brand)，未选中行不显示任何标记；目标有 ArkUI Radio 等现成单选控件可用。

## 例外与边界

- 源码本身使用 RadioButton/Radio 控件

## 原因

selectable 只提供可选语义，视觉由源码的条件分支决定；换成 Radio 会让每行都出现圆圈并改变选中样式，与源端“只有选中行有勾”的界面不同。来源中写者按行号窗口读取源文件，窗口恰好止于 selectable(...) 那行，没读到下方的条件勾选分支，就按单选语义写出 Radio({ group })。

## 做法

1. 读完该行 Composable 的完整函数体再定控件：源码是 if (selected) Icon(ic_check) 时，ArkUI 用同一条件渲染 Image(ic_check) 并按源 tint 着色（用 fillColor 着色时 ic_check 要是 SVG 资源，位图格式设了 fillColor 也不变色），未选中行放同尺寸占位保持对齐；写前确认 ic_check 资源已迁移。

来源支持：1 张卡 · 1 次迁移 · 1 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1 步〕Image 的 fillColor 只对 SVG 图生效，位图格式的图设了也不变色；不设时不叠加填充色，传非法值时用主题默认色
