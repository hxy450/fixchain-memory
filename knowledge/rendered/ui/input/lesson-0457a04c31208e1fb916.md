# EditText 的 inputType 键盘与候选提示和内容约束分开映射：textCapCharacters → autoCapitalizationMode、textNoSuggestions → enablePreviewText(false)、带符号数字用含 +/- 的键盘；只有源端有 digits/InputFilter 才过滤，程序写入按 maxLength 截断

## 何时使用

界面实现阶段（含公共输入组件设计、页面规格的控件映射与页面转换），把 Android EditText 的 inputType、digits、InputFilter、maxLength 与粘贴回填翻译成 ArkUI TextInput/TextArea 属性时；为多个单行输入框确定键盘动作键与焦点链时

## 适用情境

源布局用 textCapCharacters、textNoSuggestions、number、numberSigned 等 inputType 标志声明键盘与输入法行为，多数未配 android:digits 或 InputFilter，内容合法性在点击计算或保存时才校验；个别控件挂了 InputFilter.AllCaps；页面另有粘贴或扫描回填写入带 maxLength 的输入框。目标 ArkUI（SDK 6.x 可用 autoCapitalizationMode、enablePreviewText、InputType.Number/PhoneNumber）；映射参考只给 number → InputType.Number 与“capitalize 无直接对应，使用文本转换”。 也包括多个单行 EditText 未写 imeOptions，源端键盘动作键靠框架缺省形成“下一项”焦点链。

## 原因

textCapCharacters、textNoSuggestions 这类 text 类 inputType 标志只决定键盘与输入法提示，不限制内容（number 类 inputType 会装 DigitsKeyListener、phone 类会装 DialerKeyListener，按字符规则过滤键入与粘贴）：翻成 inputFilter 加 toUpperCase，输入期就丢字符、改大小写（依赖原文的比较也变成大小写不敏感），校验时机从点击前移到输入；反过来以“无直接对应”跳过，又丢掉大写键盘与关闭候选。InputType.Number 不能输入负号；Android setText 经过 LengthFilter，直接赋值则不截断。来源中公共组件作者把单处 AllCaps 推广成全部 textCapCharacters 输入的默认组件，规格与多个页面照抄；另一些页面写成“无对应，下沉校验”。

## 做法

1. 键盘与候选提示：textCapCharacters → autoCapitalizationMode(AutoCapitalizationMode.ALL_CHARACTERS)（小写仍可输入，不 toUpperCase、不过滤）；textNoSuggestions → enablePreviewText(false)。
2. 内容约束只来自源端 android:digits 或 InputFilter：有才加 inputFilter；InputFilter.AllCaps 在输入时拦截转大写（如 RichEditor 的 aboutToIMEInput，粘贴同样处理），不推迟到保存或校验；源端保存、点击时的校验不前移成输入期过滤，也不把单处行为推广成公共输入组件的默认值。
3. 数值框按源 inputType 选键盘：number → InputType.Number 加 [0-9]；numberSigned（含 number|numberSigned）→ 带 +/- 的键盘（如 InputType.PhoneNumber）并只允许首位单个符号（inputFilter 用 [0-9+-] 收窄字符；逐字输入时它只按单个字符匹配，表达不了「只在首位、只有一个」，这条在 onWillInsert 或 onChange 里按插入位置和已有文本判断），不用 InputType.Number 承载可负值字段。
4. 粘贴、扫描回填等程序写入先按该框 maxLength 截断再赋值；比较原文的逻辑保持输入原样大小写。写前逐个 EditText 列出 inputType、digits、maxLength、InputFilter 与目标属性的对应，映射参考没有对应行时查 TextInput/TextArea API。
5. 单行 EditText 未写 imeOptions 时，键盘动作键由框架按焦点链给出：向下焦点搜索还能找到另一个输入框时为 Next、回车把焦点移过去，否则为 Done（Android 源码 TextView.onCreateInputConnection）；目标逐框显式 enterKeyType(EnterKeyType.Next 或 Done)，并在 onSubmit 中把焦点移到源端焦点链的下一字段。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 平台资源 android-36；源码 android-36.1。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 做法第 1、3 步〕安卓 inputType 标志的取值：textCapCharacters = 0x00001001（TYPE_TEXT_FLAG_CAP_CHARACTERS，请求所有字符大写），textNoSuggestions = 0x00080001（TYPE_TEXT_FLAG_NO_SUGGESTIONS，输入法不显示基于词典的建议），number = 0x00000002（TYPE_CLASS_NUMBER），numberSigned = 0x00001002（TYPE_CLASS_NUMBER | TYPE_NUMBER_FLAG_SIGNED），numberDecimal = 0x00002002（TYPE_CLASS_NUMBER | TYPE_NUMBER_FLAG_DECIMAL）
- 〔原因 / 做法第 1、3 步〕TextView.setInputType 按类别装键监听器：text 类装 TextKeyListener（textCapCharacters 对应 Capitalize.CHARACTERS），它不是 InputFilter，不过滤内容（大写只在硬键盘键入、且系统开着自动大写时把小写转大写，软键盘提交的文字不经过它）；number 类装 DigitsKeyListener（signed、decimal 按标志），phone 类装 DialerKeyListener，datetime 类装 Date / Time / DateTimeKeyListener，它们都继承 NumberKeyListener、实现了 InputFilter，TextView 会把它追加到可编辑文本的过滤器里，此后键入和粘贴进来的字符都按它过滤。XML 里写了 android:digits 时，构造时装的是按 digits 的 DigitsKeyListener，inputType 只用作告诉输入法的类型
- 〔做法第 3 步〕signed 的 DigitsKeyListener 只接受 0–9 和 + 或 -：符号只能是整段文本的第一个字符、最多一个，已有符号时不能在它前面插入任何字符，不合规的符号被去掉
- 〔原因 / 做法第 4 步〕android:maxLength 让 TextView 装上 InputFilter.LengthFilter(maxLength)；setText(text) 先让文本依次经过 mFilters 里的每个过滤器，所以程序用 setText 写入的内容（如粘贴、扫描回填）也被截到 maxLength。代码里再调 setFilters(数组) 是整组替换，XML 的 maxLength 对应的 LengthFilter 随之没了（新数组里没自己带上时）；Android 12 起，单行可编辑框没写 maxLength 时另装一个 5000 字的 LengthFilter
- 〔做法第 1 步〕autoCapitalizationMode(mode: AutoCapitalizationMode): TextInputAttribute 自 API 20 起（TextArea、Search 有同名同版本的接口）；AutoCapitalizationMode（ets/component/text_common.d.ts，API 20 起）成员 NONE = 0、WORDS = 1、SENTENCES = 2、ALL_CHARACTERS = 3。文档写明它只提供接口能力，大小写转换由输入法应用实现；未设置时不产生大小写转换
- 〔做法第 1 步〕enablePreviewText(enable: boolean) 自 API 12 起，TextInput、TextArea、Search、RichEditor 都有，未设时为 true；它开关的是输入预上屏，即输入法未确认候选词时输入框里显示的标记文本（如拼音），预上屏内容不触发 onWillInsert、onDidInsert、onWillDelete、onDidDelete。声明和文档里没有关闭输入法候选词条的属性
- 〔做法第 3 步〕TextInput 的 type(value: InputType) 未设时为 InputType.Normal，不同类型拉起对应键盘并限制输入：Number(2) 纯数字，不支持负数、小数；PhoneNumber(3) 支持数字、空格、+、-、*、#、(、)；NUMBER_DECIMAL(12，API 11 起) 数字和一个小数点，不支持负数。TextArea 用 type(value: TextAreaType)（API 11 起），其中 NUMBER = 2、PHONE_NUMBER = 3
- 〔原因 / 做法第 2、3 步〕inputFilter(value: ResourceStr, error?: Callback<string>): TextInputAttribute（API 8 起）：匹配正则的输入才显示，不匹配的被过滤，error 回调返回被过滤的内容；单字符输入只做单字符匹配，多字符输入（如粘贴）按字符串匹配；未设时不过滤；自 API 11 起，设了 inputFilter 且输入内容不为空时，type 附带的文本过滤失效。TextArea、Search 有同名接口
- 〔做法第 3 步〕onWillInsert(callback: Callback<InsertValue, boolean>): TextInputAttribute 自 API 12 起，在将要输入时触发；InsertValue（ets/component/text_common.d.ts）有 insertOffset: number、insertValue: string；返回 false 拦截这次输入，返回 true 允许输入并随后触发 onDidInsert；声明注明它不对预上屏、候选词操作触发，只对系统输入法可用
- 〔原因 / 做法第 4 步〕TextInput 的 maxLength(value: number) 未设时不限输入字符数，取值范围 [0, 2^31-1]，小数取整数部分，异常值取默认；声明和文档讲的是「最大输入字符数」，没有写程序赋给 text 的内容会不会被截断。TextArea 有同名接口，Search 的 maxLength 自 API 20 起
- 〔做法第 2 步〕RichEditor 的 aboutToIMEInput(callback: Callback<RichEditorInsertValue, boolean>): RichEditorAttribute 在输入法输入内容前触发，RichEditorInsertValue 有 insertOffset: number、insertValue: string；返回 true 组件执行插入，返回 false 不插入；用 RichEditorStyledStringOptions 构建的 RichEditor 不支持这个回调
- 〔做法第 2 步〕RichEditor 的 onPaste(callback: PasteEventCallback): RichEditorAttribute（API 11 起）在粘贴完成前触发，PasteEventCallback = (event?: PasteEvent) => void；调用 PasteEvent.preventDefault?: Callback<void>（API 12 起）可覆盖系统默认粘贴，由应用自行插入
- 〔做法第 5 步〕安卓 TextView.onCreateInputConnection：应用没给 imeOptions 设动作时，向下焦点搜索找到的下一个视图是可编辑文本框就补 IME_ACTION_NEXT，否则补 IME_ACTION_DONE；非单行（且不是 email 类 variation）的框另加 IME_FLAG_NO_ENTER_ACTION。按 Next 时焦点移到焦点搜索找到的下一个视图（设过 imeOptions 时经 onEditorAction 按 FOCUS_FORWARD，否则经回车键处理按 FOCUS_DOWN）
- 〔做法第 5 步〕TextInput 的 enterKeyType(value: EnterKeyType) 未设时为 EnterKeyType.Done（TextArea 默认 EnterKeyType.NEW_LINE，Search 默认 EnterKeyType.Search）；EnterKeyType 成员 Go = 2、Search = 3、Send = 4、Next = 5、Done = 6、PREVIOUS = 7、NEW_LINE = 8（后两个 API 11 起），文档对 Next 只写「显示为下一步样式」
- 〔做法第 5 步〕TextInput 的 onSubmit(callback: OnSubmitCallback): TextInputAttribute 在按下输入法回车键时触发，OnSubmitCallback = (enterKey: EnterKeyType, event: SubmitEvent) => void（API 18 起的写法）；非 TV 设备按回车键时输入框默认失焦并收起键盘，在回调里调 event.keepEditableState()（SubmitEvent，API 11 起）可保持编辑态
- 〔做法第 5 步〕把焦点给指定组件：组件用 id 属性设标识后，UIContext.getFocusController() 取到 FocusController，requestFocus(key: string): void（API 12 起）在当前帧把焦点转给该组件，组件不可获焦、有不可获焦的祖先、不在组件树上时分别抛错误码 150001、150002、150003；旧接口 focusControl.requestFocus(value: string): boolean（API 9 起）仍在
