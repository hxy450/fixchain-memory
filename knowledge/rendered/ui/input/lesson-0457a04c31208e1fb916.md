# EditText 的 inputType 键盘与候选提示和内容约束分开映射：textCapCharacters → autoCapitalizationMode、textNoSuggestions → enablePreviewText(false)、带符号数字用含 +/- 的键盘；只有源端有 digits/InputFilter 才过滤，程序写入按 maxLength 截断

## 何时使用

界面实现阶段（含公共输入组件设计、页面规格的控件映射与页面转换），把 Android EditText 的 inputType、digits、InputFilter、maxLength 与粘贴回填翻译成 ArkUI TextInput/TextArea 属性时；为多个单行输入框确定键盘动作键与焦点链时

## 适用情境

源布局用 textCapCharacters、textNoSuggestions、number、numberSigned 等 inputType 标志声明键盘与输入法行为，多数未配 android:digits 或 InputFilter，内容合法性在点击计算或保存时才校验；个别控件挂了 InputFilter.AllCaps；页面另有粘贴或扫描回填写入带 maxLength 的输入框。去掉目标端多出的输入期过滤或大写转换时，源端在点击、计算或保存时做的合法性校验与提示留在原处（目标只有过滤、没有这道校验的，按源端补回）；源端确实挂了 InputFilter 或 android:digits 的那几个控件保留对应约束，不随公共组件的默认过滤一起去掉。目标 ArkUI（SDK 6.x 可用 autoCapitalizationMode、enablePreviewText、InputType.Number/PhoneNumber）；映射参考只给 number → InputType.Number 与“capitalize 无直接对应，使用文本转换”。 也包括多个单行 EditText 未写 imeOptions，源端键盘动作键靠框架缺省形成“下一项”焦点链。

## 原因

inputType 只决定键盘与输入法提示，不限制内容：翻成 inputFilter 加 toUpperCase，输入期就丢字符、改大小写（依赖原文的比较也变成大小写不敏感），校验时机从点击前移到输入；反过来以“无直接对应”跳过，又丢掉大写键盘与关闭候选。InputType.Number 不能输入负号；Android setText 经过 LengthFilter，直接赋值则不截断。来源中公共组件作者把单处 AllCaps 推广成全部 textCapCharacters 输入的默认组件，规格与多个页面照抄；另一些页面写成“无对应，下沉校验”。

## 做法

1. 键盘与候选提示：textCapCharacters → autoCapitalizationMode(AutoCapitalizationMode.ALL_CHARACTERS)（小写仍可输入，不 toUpperCase、不过滤）；textNoSuggestions → enablePreviewText(false)。
2. 内容约束只来自源端 android:digits 或 InputFilter：有才加 inputFilter；InputFilter.AllCaps 在输入时拦截转大写（如 RichEditor 的 aboutToIMEInput，粘贴同样处理），不推迟到保存或校验；源端保存、点击时的校验不前移成输入期过滤，也不把单处行为推广成公共输入组件的默认值。
3. 数值框按源 inputType 选键盘：number → InputType.Number 加 [0-9]；numberSigned（含 number|numberSigned）→ 带 +/- 的键盘（如 InputType.PhoneNumber）并只允许首位单个符号（inputFilter 对逐字输入按单个字符匹配，表达不了符号的位置，首位单个符号的规则在 onChange 里按 DigitsKeyListener 的规则剔除），不用 InputType.Number 承载可负值字段。
4. 粘贴、扫描回填等程序写入先按该框 maxLength 截断再赋值；比较原文的逻辑保持输入原样大小写。写前逐个 EditText 列出 inputType、digits、maxLength、InputFilter 与目标属性的对应，映射参考没有对应行时查 TextInput/TextArea API。
5. 单行 EditText 未写 imeOptions 时，键盘动作键由框架按焦点链给出：向下焦点搜索还能找到另一个输入框时为 Next、回车把焦点移过去，否则为 Done（android-36.1 源码 TextView.onCreateInputConnection）；目标逐框显式 enterKeyType(EnterKeyType.Next 或 Done)，并在 onSubmit 中把焦点移到源端焦点链的下一字段。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36 的平台资源；android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因 / 做法第 1 步〕inputType 的 textCapCharacters（TYPE_TEXT_FLAG_CAP_CHARACTERS）是请求输入法把所有字符大写的标志，只对有大小写的语言起作用；它随 EditorInfo.inputType 交给输入法，不在 mFilters 里，不改写也不过滤 setText 写入的文本
- 〔做法第 1 步〕textNoSuggestions（TYPE_TEXT_FLAG_NO_SUGGESTIONS）表示输入法不需要显示候选建议界面，多数输入法也据此不做自动纠错
- 〔做法第 1 步〕TextInput 的 autoCapitalizationMode 只提供接口能力，大小写效果由输入法应用决定，不改写组件里的文本；不写时不产生大小写转换效果；ALL_CHARACTERS 为按全字符自动大小写（API 20 起）
- 〔做法第 1 步〕TextInput 的 enablePreviewText 不写时开启输入预上屏；预上屏指输入法未确认候选词时在输入框里显示的标记文本（如拼音字母），文档没有说它控制输入法候选词栏
- 〔做法第 2 步〕TextInput 的 inputFilter 不写时不过滤；写了时匹配正则的输入才显示、不匹配的被丢弃；逐字输入时按单个字符匹配，粘贴等多字符输入按整串匹配；从 API 11 起，设了 inputFilter 且输入内容不为空时，type 附带的文本过滤失效
- 〔做法第 2 步〕InputFilter.AllCaps 把输入里的小写字母按 locale 转成大写，不拒绝字符；TextView.setText 会让文本依次经过 mFilters（AllCaps、maxLength 的 LengthFilter 等），所以粘贴后 setText 写入的文本同样被转大写和截断；DigitsKeyListener 这类 KeyListener 只附加在 Editable 的过滤器上，setText 的初始文本不经过它
- 〔做法第 2 步〕RichEditor 的 aboutToIMEInput 在输入法输入内容前触发，回调返回 true 组件照常插入、返回 false 不插入；用 RichEditorStyledStringOptions 构建的 RichEditor 不支持该回调；粘贴走 onPaste，在粘贴完成前触发，可覆盖系统默认粘贴
- 〔做法第 2 步〕TextInput 的 onWillInsert 只能放行（返回 true）或拦截（返回 false）一次插入，不能改写要插入的文本；输入预上屏和候选词操作时不触发，只支持系统输入法输入的场景
- 〔做法第 3 步〕TextInput 的 type 不写时为 InputType.Normal；type 拉起对应键盘并限制输入：Number 只收数字、不支持负数和小数；PhoneNumber 收数字、空格、+、-、*、#、(、)；NUMBER_DECIMAL 收数字和一个小数点、不支持负数
- 〔做法第 3 步〕numberSigned（number|numberSigned）的 EditText 用带符号的 DigitsKeyListener：接受 0–9 和 + -，符号只能是第一个字符且只能有一个，已有符号时不能在它前面插入任何字符
- 〔做法第 4 步〕android:maxLength 让 TextView 装上 InputFilter.LengthFilter(maxLength)；LengthFilter 只保留放得下的前段字符，超出部分丢弃
- 〔做法第 4 步〕TextInput 的 maxLength 是最大输入字符数，不写时可以无限输入，写小数取整数部分；文档没有说程序给 text 赋值时是否按它截断
- 〔做法第 5 步〕单行 EditText 没写 imeOptions 时，向下焦点搜索找得到另一个可编辑文本框就把动作键设为 IME_ACTION_NEXT，否则为 IME_ACTION_DONE；按 Next 时焦点移到 focusSearch(FOCUS_FORWARD) 找到的视图，按 Done 时只收起软键盘
- 〔做法第 5 步〕TextInput 的 enterKeyType 不写时为 EnterKeyType.Done，Next 只决定回车键显示为下一步样式，文档没有说它会移动焦点；非 TV 设备按回车触发 onSubmit 时输入框默认失焦并收起键盘，在回调里调 SubmitEvent.keepEditableState() 保持编辑态
