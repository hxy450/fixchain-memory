# 受控值含文本与选区（TextFieldValue）时，选区经 TextAreaController.setTextSelection 落到输入框

## 何时使用

公共组件实现阶段，把 Compose 受控输入组件（格式工具栏、插入链接、插图回填）转成 ArkUI 共享组件时

## 适用情境

源组件以 TextFieldValue 同时回写文本与选区（工具栏加粗、插入链接后光标落到末尾）；目标 ArkUI TextArea/TextInput 的选区只能经 controller 设置，组件内另有 @Local 记录选区。

## 原因

只回写文本、把算出的选区存进组件内部状态时，输入框的光标与选区不变，下一次格式操作作用在错误位置；controller 声明了却没调用，编译与检查都通过。

## 做法

1. 回写文本后用 TextAreaController.setTextSelection(start, end)（目标是 TextInput 时用 TextInputController 的同名方法）把计算出的选区落到输入框（光标即 start 等于 end；这个接口在输入框获焦时才生效，调用时输入框要仍在焦点上），交付前确认 controller 确有调用，不只更新组件内状态。
2. 源组件的子对话框（AlertDialog）用系统弹窗实现；源组件内聚的副作用链（选图、匿名判定、上传、回填、上传中状态）在共享组件里保持内聚，服务未就绪时占位的负责切片指向真正拥有该服务的 feature，不下推给每个宿主页。

来源支持：1 张卡 · 1 次迁移 · 1 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1 步〕TextAreaController.setTextSelection(start, end) 的位置从 0 算，小于 0 按 0、大于文本长度按文本长度处理；options 不传时菜单策略为 MenuPolicy.DEFAULT
