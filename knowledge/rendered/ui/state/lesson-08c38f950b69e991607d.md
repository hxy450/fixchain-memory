# 页面直接读共享 @ObservedV2 模型的 @Trace 字段，不复制成 @Local 快照再手动同步

## 何时使用

功能接线与页面实现阶段，把页面显示状态接到 @ObservedV2 模型或共享 store，且模型会被其他页面、异步加载或服务回调改写时

## 适用情境

目标端用 @ObservedV2 + @Trace 模型（AppStorageV2.connect 或单例 getter 取得）承载共享状态：源端由一个根状态持有者驱动多个屏幕，拆成 Navigation 下多个页面后由子页修改模型；或源端 Flow/StateFlow 持续推送列表与加载态，目标由异步加载、BLE/消息回调整体重新赋值 store 的 @Trace 字段，页面是 @ComponentV2 子组件。

## 例外与边界

- 需要与模型解耦的纯界面态（弹窗开关、未提交的输入草稿）仍放在页面 @Local
- 用 @Local 或 @Param 持有模型实例本身（引用，如 @Local store = 取共享实例的 getter）不算快照，保留；要改的是把 @Trace 字段的值或由它过滤、派生出的列表拷进 @Local——派生结果改在 build 或它调用的方法里现算

## 原因

@Trace 字段变化会刷新直接读它的组件；把字段复制进页面 @Local 后，界面只随手动同步更新，其他页面、异步加载完成或回调对模型的修改都进不了界面。来源中页面先 new 私有模型、再用同步方法把 7 个字段复制进 @Local；后来模型改成共享实例但副本保留，返回刷新放在不会执行的“第二次 aboutToAppear”分支，补上的 onShown 刷新在该页作为 Navigation 首页内容的挂载方式下设备实测也未生效（触发机制未单独验证），最后改成直接绑定模型才修好。另一应用中三个页面在 aboutToAppear 未等待加载就把 store 的列表与 loading 拷进 @Local，之后异步加载和 BLE/消息回调整体替换数组，页面停在 Loading… 且新数据不显示；这些页面是 @ComponentV2 子组件，onPageShow 不会触发，生成者删掉它后只留了手动刷新按钮。

## 做法

1. 页面 build 中要显示的业务状态直接写 this.model.<字段>；页面 @Local 只留纯界面态。
2. 规格或决策说明某模型要被其他功能或页面读写时，页面从一开始就用 AppStorageV2.connect 取同一个共享实例，不在页面里 new 私有实例。
3. 确需在返回时执行一次性动作（如消费反馈），先确认页面是 NavPathStack 中的页面还是 Navigation 首页内容，再选在该挂载方式下会触发的回调，不依赖页面重建。
4. 页面是 @ComponentV2 子组件时，onPageShow 等页面级生命周期不会触发，需要随 store 更新时改用上面的直接绑定，不退回手动刷新按钮；确需本地副本，就同时实现决策要求的刷新路径（服务回调或 @Monitor 同步），让异步加载完成和回调重新赋值后副本随之更新。

## 可选检查

- 对返回后的显示有疑问时，在设备上走一遍“子页修改共享模型 → 返回原页”，dump 原页的高亮、计数与反馈文案，确认与模型一致。
- 对“加载中”一类标志有疑问时，追一遍它的写入方，确认页面不是只在加载开始时读取了一次。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因 / 做法第 1 步〕被 @Trace 装饰的属性变化时只通知关联的组件刷新；未被 @Trace 装饰的属性用在 UI 中无法感知变化，也不会触发刷新
- 〔做法第 1、2 步〕@ObservedV2 与 @Trace 须配合使用，单独用任一个都没有作用；类要通过 new 实例化后才可被观测；类中 @Trace 装饰的静态属性也可被观测
- 〔做法第 1 步〕@ObservedV2 类中 @Trace 属性的值变化时，会触发绑定了该属性的 UI 组件刷新
- 〔原因 / 例外与边界〕@Local 装饰类对象时只观测对变量本身的整体赋值，类成员属性的变化要靠 @ObservedV2/@Trace 才能观测；装饰嵌套类或对象数组时观测不到深层属性变化——把模型字段的值拷进 @Local 后，模型字段之后的变化不会反映到这个 @Local
- 〔做法第 2 步〕AppStorageV2.connect：给定 key 已存在时返回已存的值，否则用默认构造器构造并返回（API 12 起）
- 〔做法第 2 步〕修改 connect 取到的对象时，@Trace 属性的修改会同步刷新 UI；非 @Trace 属性的修改已同步回 AppStorageV2 但 UI 不刷新；remove 只把数据从 AppStorageV2 删除，不影响组件中已创建的数据
- 〔做法第 2 步〕同一个 key 被 connect 成不同类型的数据会导致应用异常，应用需保证各处 connect 的类型一致
- 〔做法第 4 步〕@Monitor 可在 @ComponentV2 中监听 @Local、@Param 等状态变量，也可在 @ObservedV2 类中监听 @Trace 属性；未被 @Trace 装饰的属性无法被 @Monitor 监听到变化
- 〔做法第 4 步〕onPageShow 只对 @Entry 装饰的自定义组件生效；写在 @ComponentV2 子组件里不会被调用
- 〔原因 / 做法第 3 步〕aboutToAppear 在创建自定义组件的新实例后、执行其 build() 之前调用；组件实例没有重建就不会再次调用
- 〔做法第 3 步〕onShown 是 NavDestination 的属性方法（NavDestination 页显示时回调）；直接写在 Navigation(...){} 里的首页内容不是 NavDestination，没有这个回调
- 〔原因 / 做法第 3 步〕页面作为 Navigation 首页内容挂载时，从子页返回后，写在“第二次 aboutToAppear”分支里和 onShown 里的刷新在设备上都没有执行（API 24 目标 SDK；onShown 不执行的触发机制没有单独验证）
