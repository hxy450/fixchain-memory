# 列表条目以新对象替换或整表重建时，ForEach/Repeat 键要包含会变且需要显示的字段；要稳定键就改为可观察实例原位更新

## 何时使用

功能实现与页面接线阶段，为可编辑或会重新拉取的列表选定条目更新方式与 ForEach 键时；为消除重建抖动而稳定 ForEach/Repeat 的键时

## 适用情境

列表条目编辑（如改名）后以保留 id 的新对象替换，或操作成功后重新请求列表并整表 setList（id 不变、计数等字段变化）；ArkUI 用 ForEach 渲染，并把条目字段作为子组件的 @Param 传入；源端是 Compose 不设 key 的 forEach 加不可变 copy，或 RecyclerView 整表刷新。也包括分页或 Swiper 的页模型是普通 interface，键原先拼入请求状态与数据导致每次加载都销毁重建（抖动），修复者准备把键缩成只含页标识。也包括 RecyclerView 的 remove+add+notifyItemChanged 被迁成 arr[pos] = 新实例、splice 或整表赋值，行内显示取自条目可变字段（下载态、播放态），注释以“@Trace 字段级刷新”代替键检查。也包括源端 removeAllViews 后逐项 inflate 的结果区改成嵌套 ForEach，键只用显示内容拼接（内容可能完全相同，如多个全零数据块），条目是普通 class，每次计算整体重建。

## 例外与边界

- 更新方式是对 @ObservedV2 条目的 @Trace 字段原地赋值，子组件绑定的仍是同一对象，此时可保留只含 id 的键；已有代码是这种写法时，不为套用本条把原位写入改成不可变替换，也不删掉原位 @Trace 写法而不在键里补可变字段
- 行组件里有自己的 @Local 状态（展开、输入中的文字、动画进度）或重建会抖动时，不把高频变化的字段并入键：键一变整行按新组件重建，这些行内状态回到初值；这类列表改用做法第 4 步的原位更新

## 原因

ForEach 键值不变时复用已有子组件、不再执行条目构建，子组件拿不到替换后的新对象，界面停在旧值；Compose 不设 key 的 forEach 与 RecyclerView 整表刷新每次都拿到新值，所以源端没有这个问题。来源两例：改名后反馈与持久化都已更新，卡片仍显示旧名，只含 id 的键由早期页面写入、重建时被沿用，写码者读到的状态参考只讲“替换实例会触发刷新”；另一应用里弹层列表的键只含下标、id 与类型标志，写者认为“整表重载”即会重渲染，添加成功后计数停在旧值，而它读到的陷阱清单已写明同 id 新值重建时键须含可变字段。另一应用为消除翻页抖动把键缩成只含查询键，页模型仍是普通对象、异步结果以新对象替换，已创建的页节点再也收不到数据，各视图都显示为空；改成 @ObservedV2/@Trace 并原位更新才显示，后来又被改回不可变替换而再次无数据。@Trace 只追踪同一实例上的属性写入，不能代替键变化。只由显示内容拼出的键在内容重复时互相冲突，ForEach 只渲染其中一个；整体重建时内容相同的旧行又会被复用。同键复用时，条目生成函数里的事件闭包（onClick 等）捕获的行对象同样停在旧实例：整表重建为新对象后，闭包里按对象身份 indexOf 当前数组得 -1。键只含下标与分类属性、不含条目身份时，显示子集随宽度或方向变化会复用错位的子节点。

## 做法

1. 先定更新方式：替换对象或整表重建就把会变且显示的字段并入键，如 `${item.id}:${item.name}:${item.count}`；改为给 @Trace 字段原地赋值则可保留 id 键。
2. 写键前列出条目内所有展示字段，并查源端的刷新方式（替换对象、重新请求后 setList），不把“整表重载”当作会重渲染的依据。
3. 对每个修改动作核一遍：动作 → 数组元素是否换成新对象 → ForEach 键是否变化 → 子组件 @Param 与条目事件闭包（onClick 等）捕获的是哪个对象，确认新值能到达条目界面；闭包里要定位当前行时，按行内唯一字段在当前数组里 findIndex，不用对象身份 indexOf，也不用生成时的 index；键至少包含条目身份（id、资源 id 或命令标识），不只用下标加分类属性；页面交付自检对每个 ForEach 都做这一核对。
4. 为消除抖动稳定键时，同步把条目或页模型改为 @ObservedV2 类、需要显示的字段标 @Trace 并原位赋值，@Builder 与子组件 @Param 链传可观察实例或完整 RepeatItem；在测试断言或注释中写明该实例禁止整体替换。
5. 键要随新实例变化时也可追加实例分量（如按 WeakMap 记录的实例序号）：新实例得到新键而重建该行，同实例 @Trace 原地变更时键不变；接线时把数组元素替换写成新实例的同时核对该列表的键。
6. 条目内容可能重复时，键包含本次结果中的位置标识（如分组号加序号），再按需加内容字段；结果每次整体重建且条目是普通 class 时，给每次计算分配代次前缀写入键，确保旧行不被复用。

## 可选检查

- 行内状态（如下载完成后的按钮）在设备上不刷新时，检索写入新对象而键不含实例分量的列表

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因 / 做法第 1 步〕ForEach 非首次渲染时检查新生成的键值在上次渲染中是否存在：不存在就创建新组件，存在就不创建新组件、直接渲染该键值对应的已有组件（不重新执行条目生成函数）；键值变化时框架视为该数组元素已被替换，按新键值新建组件
- 〔原因 / 做法第 1、3 步〕替换数组项后新项生成的键值没变时，ForEach 不把数据更新同步给子组件，子组件仍绑定旧数组项，之后对新数组项的修改也不刷新这个子组件；文档因此不建议对象数组用内容相同的新项替换旧项
- 〔做法第 1、3 步〕条目生成函数 itemGenerator 声明了 index 参数而 keyGenerator 没有声明 index 时，框架在 keyGenerator 的返回值后拼接 index 作为最终键值
- 〔做法第 3、6 步〕ForEach 不传 keyGenerator 时默认键值为 index + '__' + JSON.stringify(item)；JSON.stringify 序列化失败的数据（如含 bigint）会让应用 jscrash 退出
- 〔做法第 3 步〕ForEach 键值含 index 时，向数组中间插入一项会让该项及其后所有项重新创建组件；键值只用 index 时插入后旧键都还在，组件被按位置复用，界面显示错位（渲染结果非预期）
- 〔做法第 6 步〕ForEach 出现重复键值时框架发出运行时警告，UI 更新时框架可能无法正常工作；基本类型数组用数据项本身作键值时必须保证数据项不重复
- 〔例外与边界 / 做法第 4 步〕Repeat 根据键值是否变化判断数据项是否更新：.key() 缺省时生成新的随机键值，遇到重复键会在已有键值基础上递归生成新键；全量加载模式下更新前后键值相同时，即使数据改变页面也不刷新，新数组里找到相同键值的直接沿用对应子组件节点、只更新 index
- 〔例外与边界 / 做法第 1、4 步〕@ObservedV2 类中被 @Trace 装饰的属性值变化时，触发绑定该属性的 UI 组件刷新；未被 @Trace 装饰的属性用在 UI 中无法感知变化，也无法触发刷新
- 〔做法第 4 步〕@Param 由父到子单向同步，不允许在组件内部直接修改；类对象等复杂类型的 @Param 接受数据源的引用，组件内改对象属性会同步到数据源
- 〔原因 / 做法第 1 步〕ForEach 键只含 id、改名后以保留 id 的新对象替换数组项时，设备上反馈已显示新名，卡片仍显示旧名
- 〔原因 / 做法第 4 步〕Swiper 页模型是普通对象、键只含页标识、异步结果以新对象替换时，真机上各视图都显示为空；用 Repeat 但把 RepeatItem.item 解包后传给子组件时，两轮真机仍为空；页模型为 @ObservedV2 类、字段 @Trace 并原位赋值时数据显示，页对象换成不可变替换时又无数据
- 〔原因 / 做法第 3 步〕整表重建为新对象后，同键复用的行里 onClick 闭包捕获的仍是旧行对象，按对象身份 indexOf 当前数组得 -1，再取该下标元素的字段时设备上 TypeError 闪退
- 〔适用情境 / 做法第 5 步〕行键只含 id 和选中位、下载完成时整体换入同 id 新实例时，设备复查中行按钮仍停在下载前的状态
- 〔例外与边界 / 做法第 4 步〕条目类为 @ObservedV2、数量字段 @Trace 并在同一实例上原位写入时，设备上行内数量随增减变化
- 〔做法第 3 步〕安卓 ListActivity.onListItemClick 的 position 是被点视图在列表里的位置，按 position 从列表当前数据取行（getItemAtPosition），不依赖对象身份
