# 随状态变化的控件参数不作 @Builder 值参，改为内联读取状态或用 @ComponentV2 子组件的 @Param

## 何时使用

界面实现阶段（页面转换与公共组件抽取），以及返修或按源端几何重写已有页面时，为源端带状态参数的子控件、多个同构开关行或数据文字选择 ArkUI 复用写法时；把 LazyForEach 改写为 Repeat、拆出条目 @Builder 时

## 适用情境

源端 Compose 子 Composable 以当前状态算出的值作参数（如 enabled = count > 1、颜色随选中态变化），或 Android 页面有多个同构的开关行、各自持有状态；目标 ArkUI 组件需要在状态变化后刷新 enabled、颜色、开关图标等属性，准备把子控件或开关行抽成共享的 @Builder 方法。也包括用多参数 @Builder 渲染会被异步重新赋值的数组或对象（搜索结果、定位城市卡）的情形。也包括把 LazyForEach 改为 Repeat 时，each 回调写成 this.Row(ri.item)，把 RepeatItem.item 按值传给 @Builder。也包括页面转换为子页面嵌入点写只含前向引用的空 @Builder 槽位，并把异步加载的分类数组与选中索引作为位置值参传入。也包括返修时为对齐源端几何重写已能刷新的内联文字（设置摘要、统计数值、按 onAreaChange 尺寸计算的布局），把 this.<状态> 或尺寸作为值参传入新抽出的 @Builder。

## 例外与边界

- 传入 @Builder 的只有文案、尺寸等在该组件生命周期内不随状态变化的值

## 原因

Compose 每次重组都按当前状态重算实参；ArkUI @Builder 按值传入的参数是调用时刻的快照，状态变化后不会刷新 @Builder 内的 UI。来源一：边界步进按钮在状态越过边界后仍保持禁用、点击无效。来源二：蓝牙页两个独立偏好开关共用一个成员 @Builder，各自的 @Local 状态作值参传入、内部据此画开关并接无参回调；后来把复用开关组件放进同一 Builder，isOn 仍取值参，运行时出现点一个开关影响另一个，拆成两个直接绑定各自状态的组件行后才消除。两例中该规则都写在组件构建 skill 的 @Builder 复用一节，但写者要么前置清单里没有该 skill，要么只按固定行数或在截断的批量读取里读到了它的前段。另一应用中两处：添加城市页把搜索结果数组作为 @Builder 值参传入，查询在切到搜索分支后才返回并重新赋值，数据层日志有结果、界面始终为空；城市页把定位卡对象按值传入 @Builder，改为 @ObservedV2 后整体替换仍不刷新，原位更新字段才显示。两处写者都被要求读迁移陷阱表中的对应条目，一个只数了行数，一个读取被截断。另一应用在结构收口中已读到清单“拆出的 @Builder 必须接整个 RepeatItem”，仍按值传 ri.item 并加 virtualScroll；复用节点只更新 RepeatItem.item，按值拿到的旧对象不重绘，非空日期切到另一非空日期时仍显示旧条目。

## 做法

1. 状态派生的 enabled、selected、颜色、开关值、图标资源、显示文字与无障碍文案、尺寸等参数，用内联属性链直接读 this 上的状态，或抽成 @ComponentV2 子组件用 @Param 接收，或用按内容作键的 ForEach 渲染；要保留一个共享 @Builder 统一多个按钮的修饰链时，把这类参数改为取值函数（如 icon: () => Resource），在 builder 内的 Image(icon())、accessibilityText(label()) 里调用。@Builder 值参只放不随状态变化的值。可空状态需要类型收窄时同样不改成值参：在 builder 内判空后直接读同一 this 路径，或在父级判空后交给子组件 @Param。
2. 多个开关行共用外观时，每行在 build 中直接写复用组件并绑定自己的状态（如 isOn: this.<该开关状态>），不经共享 @Builder 转发状态值。
3. 写完 grep `@Builder` 签名与调用处，实参含 `this.<状态>` 表达式的即为风险点，改写后再落盘；返修重写已有片段时同样执行，不因原片段能刷新就省略。
4. 异步结果写回 @Local 前，grep 它在 build 中的全部消费点，确认没有经 @Builder 值参快照；“先切分支、后 await 赋值”的流程尤其要查。
5. 按值渲染的 @ObservedV2 实例要原位更新 @Trace 字段，不整体 new 替换，也不靠自赋值触发刷新。
6. Repeat 的 each/template 回调里拆出的 @Builder 或子组件接收完整 RepeatItem，在内部读取 ri.item；出现 this.Xxx(repeatItem.item) 写法先改正再提交，静态审计也加这一条 grep。
7. 即使槽体只是前向引用占位，也按这条规则定签名：空槽的参数表会成为后续填充者沿用的接口契约；后续填充槽体时先确认槽内数据在异步更新后能否刷新，不默认沿用占位签名。

## 可选检查

- 改动涉及按状态显示的文字或尺寸时，验收至少包含一次改变数据或尺寸的操作（切换选项、重置、旋转），确认显示随之更新。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因〕@Builder 默认按值传参，传入的状态变量变化不会刷新 @Builder 内的 UI；只有只传一个参数、且这个参数直接写成对象字面量时才按引用传递并随状态刷新，传两个及以上参数（即使用对象字面量）或按值与按引用混传都不刷新。〔成立范围：依据是文档说明，V1、V2 组件都适用。例外：成员 @Builder 内直接读 this 上的状态照常刷新；@ComponentV2 中按值传入 @ObservedV2 实例时改它的 @Trace 属性会刷新（见下一条）；API 20 起用 UIUtils.makeBinding 包装读回调传入也会刷新。〕
- 〔做法第 5 步〕在 @ComponentV2 组件里按值把 @ObservedV2 类实例传给 @Builder 时，修改实例的 @Trace 属性会刷新 @Builder 内的 UI；按值传简单类型不刷新；把 @Local 对象整体换成新对象，只有按引用（单个对象字面量参数）传递时才刷新 @Builder。〔成立范围：依据是文档说明；只对 @Trace 装饰的属性成立，没加 @Trace 的属性变化不刷新。〕
- 〔做法第 6 步〕Repeat 与 @Builder 混用时，只传 RepeatItem.item 或 RepeatItem.index，数据变化不会刷新 @Builder 内的 UI；把整个 RepeatItem 作为参数传入（或 API 20 起用 UIUtils.makeBinding 包装读取回调）才会刷新。〔成立范围：依据是文档说明；文档在使用限制里对自定义组件也作同样要求（与自定义组件或 @Builder 混用时必须整体传 RepeatItem）。按 @Builder 文档的 V2 规则，item 是 @ObservedV2 实例时，原位改它的 @Trace 属性即使只传 ri.item 也会刷新；数组项被换成另一个对象、或节点被复用到别的数据项时不刷新。Repeat 节点复用时不触发子组件的 aboutToRecycle、aboutToReuse。〕
- 〔做法第 6 步〕Repeat 不开 virtualScroll（全量加载）时，页面刷新取决于键值变化：更新前后键值相同，即使数据变了页面也不刷新；开 virtualScroll（懒加载）时键值变化或数据变化都会触发刷新。〔成立范围：依据是文档说明；全量加载模式下 template 不可用，可配合 V1 使用；懒加载模式要配合状态管理 V2 和 List、Grid 等滚动容器。〕
- 〔做法第 1 步〕ForEach 不传 keyGenerator 时默认键值为 index + '__' + JSON.stringify(item)，数组项内容一变键值就变、该项组件重新创建；自定义 keyGenerator 只返回 id 这类不变字段时，内容变化而键值不变，ForEach 直接复用原组件、不重新创建。〔成立范围：依据是文档说明。键值只在 ForEach 重新渲染时重算：V1 下只改对象数组项的某个属性，框架监听不到、ForEach 不重新渲染，默认键也不会跟着变（要配合 @Observed 和 @ObjectLink 让子组件自己刷新）。默认键含 index，在中间插入会让其后各项全部重建；itemGenerator 声明了 index 而 keyGenerator 没声明时，框架会在返回值后再拼上 index；不同项键值相同时行为未定义。〕
