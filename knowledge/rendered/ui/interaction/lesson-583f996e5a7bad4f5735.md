# 源端用键盘或遥控逐行逐项导航弹层与面板时，行/项选择与展开态放进可观察模型由按键处理层驱动，不存在组件 @Local

## 何时使用

规格提取与菜单、弹层、参数面板实现阶段，迁移源端遥控或键盘导航模式（方向键在行间移动、确认键选中、行与项高亮）并确定选择态归属时

## 适用情境

源端以遥控模式一类状态在按键回调里调用 processRemoteUp/Down、commandMenu* 与 init*ForRemote 等方法，逐行、逐项高亮弹层与曝光面板并跳过不可见行；BLE 遥控与键盘共用这套导航。目标弹层把当前行索引、展开态写在组件 @Local 或不可观察的普通类里，按键分发与面板分属不同文件或 feature。

## 例外与边界

- 模型放对了还要有按键入口：按键事件只投给获焦组件，目标页面要有可获焦的组件（默认不可获焦的容器设 focusable，并设 defaultFocus）挂 onKeyEvent 或 onKeyPreIme 交给按键处理层；处理层只把自己处理了的键标为已消费（返回 true），没处理的键返回 false，留给冒泡、输入法和框架默认的方向键走焦，不要一律吞掉。

## 原因

选择与展开态只存在组件内部时，按键处理层读不到也改不了，遥控导航只能退化成开关弹层或回落到其他动作；行导航状态机分散在按键分发与面板两处，按 feature 拆分后双方都以为由对方实现。

## 做法

1. 规格阶段把遥控/键盘导航单列验收：进入条件、行序与跳过不可见行、上下移动、确认选中、高亮样式与退出，并在对接点写明状态机归哪一方。
2. 实现时把模式标志、当前行、当前项与展开态放进可观察模型（@ObservedV2/@Trace），由按键处理层的上/下/确认方法修改；面板组件只读模型渲染高亮并滚动到可见，不在组件 @Local 另存一份选择态。
3. 按源端按键分发表逐键映射：导航模式下方向键走行导航，不并入打开或关闭弹层的分支；遥控模式下确认键先走菜单命令。做不完的部分登记带负责方的移交项。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 3 步〕鸿蒙 KeyCode 的键码数值和安卓 KeyEvent 不同：方向键上、下在鸿蒙是 2012、2013，空格是 2050；安卓 KEYCODE_DPAD_UP、KEYCODE_DPAD_DOWN、KEYCODE_SPACE 分别是 19、20、62，照搬安卓数值比较 keyCode 能编译但匹配不到按键
- 〔做法第 2 步〕@ObservedV2 和 @Trace 要配合使用，单独用其中一个没有作用；只有被 @Trace 装饰的属性变化才会通知关联组件刷新，未加 @Trace 的属性用在 UI 中感知不到变化；类要通过 new 实例化后才具备被观测的能力
- 〔原因 / 做法第 2 步〕@Local 装饰的变量无法从外部初始化，必须在组件内部初始化，它是组件内部的状态
