# 弹窗防穿透的 Block 只放在无子控件的遮罩层，内容面板与根容器保持 Default；改真弹窗 API 后删掉自绘防穿透

## 何时使用

弹窗或浮层实现与改造阶段，为遮罩、内容面板、根容器设置 hitTestBehavior，或把页面内浮层迁到 showCustomDialog/showBindSheet、openCustomDialog 等真弹窗时

## 适用情境

弹窗或底部面板采用“根 Stack + 遮罩 + 内容面板”结构，在根或内容面板上写 hitTestBehavior(HitTestMode.Block)（含 visible ? Block : None）防止点击穿透；面板内有按钮、checkbox、列表项等要响应点击的子控件。也包括源端用全屏空 clickable 拦截层防穿透、遮罩点击关闭、居中卡片阻止冒泡，目标在包住遮罩、卡片、滑杆与滚动区的弹层根 Stack 上写 Block。

## 原因

HitTestMode.Block 让节点自身参与命中测试，不再对子节点做命中测试，并阻断下方兄弟节点和所有祖先节点自身的事件收集，写在内容面板或根容器上时，面板内按钮、checkbox 与整行点击都无法命中，hilog 显示 Touch test result is empty。框架弹窗已自带模态遮罩与外部点击处理，迁到真弹窗后仍保留的内容容器 Block 会变成弹窗内容根。来源中两次把页内浮层改成 harmony-dialog 时都只删了外层遮罩的 Block，保留了包住按钮或列表的内容 Column 的 Block，导致“立即升级”、checkbox 与整行点击全部无响应；生成期别的浮层已发现同类问题并定过“交互容器 Default、只留遮罩 Block”的规则，这两个弹窗没有被扫到。

## 做法

1. 防穿透只写在没有可点击子控件的遮罩层（Block，或 Default 加 onClick 关闭）；承载按钮、checkbox、列表的内容面板与根容器用 Default；需要把事件让给下层时用 Transparent 或 None。
2. 把页内浮层改为真弹窗 API 时，删掉全部自绘遮罩与 visible ? Block : None 一类写法，并对照同仓已有真弹窗内容检查目标控件的整条祖先链。
3. 在一个弹窗发现 Block 吞掉子项点击后，按 HitTestMode.Block 检索同类弹窗与浮层，逐个确认它是否包住可点击的子控件。
4. 源端已有全屏拦截层时由该层承担防穿透，弹层根容器保持 Default；对 hitTestBehavior 各值对子节点的作用拿不准时，先查交互映射参考的触摸测试表或 SDK 声明，不凭记忆定稿。

## 可选检查

- 交付前在真机点击面板内至少一个子控件，或用 uitest dumpLayout 查看目标控件祖先链的 hitTestBehavior。

- 〔原因〕hitTestBehavior(HitTestMode.Block) 的节点自身被命中（触点在它的热区内）时：不再对任何子节点做触摸测试，子节点的 onClick、手势全部收不到；它自身照常收集；同时阻断同一父节点中位于它下方的兄弟节点，并让所有祖先节点不再收集自身的事件与手势。〔成立范围：对任何组件的 hitTestBehavior 成立；组件不设 hitTestBehavior 时为 HitTestMode.Default（文档）。依据：HitTestMode 文档与交互基础原理文档（「如果自身触摸测试命中，会阻塞兄弟组件及父组件的触摸测试」），实现见 OpenHarmony arkui_ace_engine 标签 OpenHarmony-v6.0-Release 的 FrameNode::TouchTest；声明注释只写了阻断子节点和被它遮住的节点，没写祖先。触点只落在它未裁剪的子节点超出它的部分时，v6.0 实现也会阻断，但文档写的是自身命中才阻断，按文档不依赖这种情形。不成立：触点不在 Block 节点范围内时它不起作用；节点 enabled(false) 时连同子树不参与命中测试。〕
- 〔做法第 1 步〕未设 hitTestBehavior（即 Default）的节点只要触点落在自身热区内或它的某个子节点被命中就算命中，并阻断同一父节点中位于它下方（zIndex 更小，或同值时声明更早）的兄弟节点，与它有没有绑定 onClick 或手势无关；Transparent 命中后不阻断下方兄弟；None 自身不收集事件，子节点照常参与，且它的子节点被命中时也不阻断它的下方兄弟。〔成立范围：对同一父节点下互相重叠的兄弟节点成立（Stack 叠放最常见），兄弟按 zIndex 升序、同值按声明顺序排列，排在后面的在上层、先做测试。依据：HitTestMode 文档、hitTestBehavior 文档的 Stack 说明，实现见 OpenHarmony arkui_ace_engine 标签 OpenHarmony-v6.0-Release 的 FrameNode::TouchTest。不成立：父节点对子节点开启独占时（实现中的 IsExclusiveEventForChild，框架内部个别组件使用）None 子树命中也会阻断兄弟；节点 enabled(false) 时连同子树不参与、也不阻断。〕
- 〔适用情境〕安卓里 View 只有 clickable、longClickable、contextClickable（或设了 tooltip）时默认 onTouchEvent 才消费触摸，禁用但 clickable 的 View 照样消费；setOnClickListener 会把 View 设为 clickable；不可点击的上层 View 不消费 DOWN，ViewGroup 会继续把它派给下层（绘制顺序更早）的兄弟。所以安卓源端要用全屏空 clickable 层防穿透，而鸿蒙 Default 节点命中即阻断下方兄弟，不看是否可点击。〔成立范围：对 android.view.View 默认的 onTouchEvent 与 ViewGroup#dispatchTouchEvent 成立（android-36.1 源码）。不成立：View 覆写了 onTouchEvent 或 dispatchTouchEvent、设了返回 true 的 OnTouchListener，或父级在 onInterceptTouchEvent 里拦截时另算。〕
- 〔做法第 2 步〕CustomDialogController 与 promptAction.openCustomDialog 未另设时 isModal 为 true（有蒙层，蒙层区域事件不透传）、autoCancel 为 true（点蒙层关闭）、maskColor 为 0x33000000；bindSheet 的 enableOutsideInteractive 不设时，底部弹窗与居中弹窗不允许下层交互并显示蒙层，跟手弹窗允许交互、不显示蒙层。〔成立范围：依据：@ohos.promptAction.d.ts 的 BaseDialogOptions 中 isModal、autoCancel 的 @default；maskColor 默认值依据是自定义弹窗文档与 promptAction 文档说明；bindSheet 依据是半模态文档说明。bindSheet 不设 preferType 时样式随窗口宽度定：宽度 < 600vp 只有底部与全屏样式（默认底部），600–840vp 默认居中，≥ 840vp 默认跟手，所以宽窗口上不设 enableOutsideInteractive 也可能没有蒙层；侧边（SIDE）样式文档没写这一默认，全屏（CONTENT_COVER）样式不支持蒙层与 enableOutsideInteractive。不成立：isModal 设为 false 时无蒙层、可与周围交互；openCustomDialog 设 levelMode 为 EMBEDDED 时蒙层只按页面内父节点布局约束显示；bindSheet 设 enableOutsideInteractive 为 true 时无蒙层且 maskColor 无效。〕
