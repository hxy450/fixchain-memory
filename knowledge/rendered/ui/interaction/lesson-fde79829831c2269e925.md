# 源端可点击容器自带的按压反馈（Compose clickable、Card(onClick)，View 体系主题 listSelector 的列表行）在 ArkUI onClick 上不会自动出现：用通用属性 stateStyles 补状态层并成对写 normal 写回静止值（stateEffect 只属于 Button），不可点击时不显示；View 体系列表选择器按压色作底色画在内容下，不用 opacity 代替；选择器是 <ripple> 时不按原色整块平铺

## 何时使用

界面实现阶段，为任何可点击元素（列表行、对话框文字按钮、ImageButton/图标按钮、标题栏动作钮）用 stateStyles 写按压态时；把带 Modifier.clickable/toggleable/selectable，或 Card、Surface(onClick) 的 Compose 容器转成挂 onClick 的 ArkUI 容器时；把 ListView、PreferenceActivity 中由主题 listSelector 提供按压态的可点击行转成 ArkUI 列表行时；把 GridView 条目转成 Grid/GridItem 时

## 适用情境

源端容器经 clickable/toggleable（可带 role = Button、Switch）或 Card/Surface(onClick) 响应点击，没有把 indication 设为 null，按压时由主题提供涟漪或状态层；目标用 Column/Row/Stack 加 .onClick 实现，ArkUI 通用容器默认没有按压反馈（Button 自带的按压效果除外）。 也包括 View 体系的 ListView、PreferenceActivity 行没有把 background 或 listSelector 设为 null，按压态由主题选择器（如 Holo 暗色 list_selector_holo_dark）提供；写者在 d.ts 里找不到通用容器的 stateEffect，就放弃了按压态。 也包括 GridView 条目：GridView 未改写 listSelector 与 drawSelectorOnTop，Activity 主题分散在 res/values 与 values-v11/v14 等多个 styles.xml，低 minSdk 的旧工程在新设备上走 values-v11+ 的 Holo 父主题。 也包括 Material 主题（values-v21 的 android:Theme.Material*）下，列表选择器、标题栏按钮背景（?attr/actionBarItemBackground）与无边框按钮背景解析到 <ripple> drawable，规格或兄弟页只给出一个“按压色”。

## 例外与边界

- 源端显式 indication = null 或自定义 indication 时，按源端写法处理
- 目标用自带按压效果的 Button 承载点击时，不再叠加

## 原因

Compose 的点击修饰符默认带按压指示，调用处看不到任何反馈代码；只翻译 onClick 时点击可用但按压没有反馈，编译与结构检查都发现不了。stateEffect 只是 Button 的属性，通用容器的按压态要用 stateStyles 或 onTouch 状态驱动；以“查不到 stateEffect”为由省略，按压反馈整体缺失。 stateStyles 里只写 pressed、没有用 normal 写回被改属性时，松手后该属性停在按下值（实测按下底色一直残留），按钮与列表行都一样。 AbsListView（ListView、GridView）的 drawSelectorOnTop 默认 false（本机 android-36.1 源码 AbsListView.java），选择器的按压色画在条目内容下面，图标与文字像素不变；用 opacity 整体变暗会连内容一起变淡。只看 res/values 会认错主题代际：同名主题在 values-v11/v14 常改为继承 Theme.Holo，低 minSdk 不等于老式 list_selector_background。 Material 主题的选择器与按钮背景是 RippleDrawable：colorControlHighlight（highlight_alpha × 前景色）只是涟漪着色输入，屏上是有界径向层或无界圆，把原值整块平铺会偏深、形状也不同。

## 做法

1. 在承载点击的同一容器上加通用属性 stateStyles，pressed 与 normal 成对声明：pressed 改了哪些属性（如 backgroundColor），normal 就把这些属性写回静止值（无底色写 Color.Transparent，有底色写原色）；内联样式块与 @Styles 方法引用（如 { normal: this.released, pressed: this.pressedStyle }）都要成对。任何容器可用；stateEffect 只属于 Button，查不到它不是省略按压态的理由。按压时叠加状态层：Compose 源按 Material3 取约 10% 的内容色，View 体系按源主题选择器的实际按压外观（如 Holo 暗色 #40CCCCCC）；叠层随容器圆角裁剪，纯色背景也可预混成按压色。 View 体系列表与网格的状态层是底色：选择器画在条目内容下面（drawSelectorOnTop 默认 false），pressed 态写 backgroundColor、normal 透明，不用 opacity、整体变暗或盖在内容上的叠层代替。取色前按设备 API 沿 res/values-vNN/styles.xml 找 Activity 主题的 parent 链确认主题代际，再从 SDK platforms/android-<api>/data/res 下该主题 listSelector（按钮看其 background）指向的 drawable 先看根元素：<selector> 的纯色按压项取色；<ripple> 按下一步处理，不取 colorControlHighlight 原值整块平铺。取不到时在报告里写明缺口，不以 opacity 兜底。
2. drawable 根元素是 <ripple> 时（Material 主题 API 21+ 的 listChoiceBackgroundIndicator、selectableItemBackground、actionBarItemBackground、btn_borderless_material 等）按涟漪形状落实：含 mask 或内容层的有界涟漪在视图边界内画以视图中心为圆心、视图半对角线为半径的径向层；无 mask、无内容层的无界涟漪按 android:radius 画圆（圆心按源控件热区），圆外无色，不铺满按钮矩形。highlight_alpha 原值随 SDK 版本不同（本机 android-30/34/35 为 0.10/0.5/0.20），屏上稳态不透明度由对照设备 Android 版本的 RippleDrawable 绘制决定：按该版本实测按住稳态，或在报告里登记待实测；不按“与兄弟页同值”挑某一版本，也不在同一组件里混用不同版本的值。
3. 按源端 enabled 条件决定是否出现：clickable/toggleable 的 enabled 为假时（如内容不足、无可展开项）既不响应点击也不显示按压态。

- 〔做法第 1 步〕stateStyles 只支持通用属性；组件私有属性（如 fontColor、TextInput 的 backgroundColor）写进 stateStyles 不生效，文档给的替代是 attributeModifier；pressed 与 clicked 同时写在一个组件上时只有后注册的生效。〔成立范围：对象：通用属性 stateStyles 的 normal、pressed、disabled、focused、clicked、selected 各态。条件：API 8+；stateStyles 本身不能在 attributeModifier 里调用。不成立的情形：backgroundColor、opacity 这类通用属性在 Column、Row、Stack 上可以正常按状态切换。〕
- 〔做法第 1 步〕stateStyles 直接写在没有自定义组件父节点的 @Builder 内容里的组件上不生效（多态样式靠自定义组件节点触发刷新），典型是全局 @Builder 经 wrapBuilder 包成 ComponentContent 交给 openCustomDialog；要把带 stateStyles 的组件封装进自定义组件，再把自定义组件放进 @Builder。〔成立范围：对象：作为 ComponentContent / BuilderNode 等根节点使用、没有自定义组件父节点的 @Builder（如 wrapBuilder 后交给 openCustomDialog）里直接声明的组件。条件：依据是文档说明（原句没有区分 @Builder 的调用位置，所给理由和示例针对的是没有自定义父节点的情形），本机没法上机核。不成立的情形：stateStyles 写在自定义组件 build() 里的组件上正常生效；在自定义组件 build() 里调用的 @Builder 有该组件作父节点，文档没有说它失效。〕
- 〔例外与边界〕Button 的 stateEffect 默认 true，按下时自带按压效果；同时设了 stateStyles 时，会在状态样式设置后的背景色上再叠加按压色，所以用 stateStyles 自绘按压态时要先把 stateEffect 设为 false。〔成立范围：对象：Button 组件（ButtonOptions.stateEffect 或 stateEffect 属性）。条件：应用未改 stateEffect。不成立的情形：stateEffect 设为 false 后只显示 stateStyles 的按压样式。〕
- 〔原因〕AbsListView（ListView、GridView）的 drawSelectorOnTop 默认 false：dispatchDraw 先画选择器再画子视图，按压色在条目内容下面，条目自身有不透明背景时会把选择器挡住。〔成立范围：对象：ListView、GridView 及 PreferenceActivity 的列表行。条件：Android SDK 源码 android-36.1；布局未写 android:drawSelectorOnTop。不成立的情形：drawSelectorOnTop 设为 true 时选择器画在内容之上。〕
- 〔做法第 1 步〕Holo 列表选择器的按压图是纯色 9-patch：暗色 list_pressed_holo_dark 为 #40CCCCCC，亮色 list_pressed_holo_light 为 #33999999；按压项是 TransitionDrawable，列表视图本身可长按时在长按超时内渐变到 list_longpressed_holo_dark（#80F0F0F0）或 list_longpressed_holo_light（#4D4F4F4F）。〔成立范围：对象：主题 listSelector 为 list_selector_holo_dark 或 list_selector_holo_light 的 ListView、GridView 行。条件：android-30、android-36 资源一致；AbsListView 自身 isLongClickable() 为 true 时才渐变（setOnItemLongClickListener、registerForContextMenu 会把它置 true），否则停在按压色。不成立的情形：应用改写了 listSelector 或条目 background。〕
- 〔做法第 2 步〕Material 主题下 selectableItemBackground（item_background_material）是带 mask 的有界 ripple，actionBarItemBackground（action_bar_item_background_material）是无 mask、radius 20dp 的无界 ripple，颜色都取 colorControlHighlight；亮主题 ripple_material_light 为黑色乘 highlight_alpha_material_light（android-30、33 为 0.10，34 为 0.5，35、36 为 0.20）。〔成立范围：对象：Theme.Material.* 系（API 21+）框架主题属性解析到这些 drawable 的视图背景。条件：应用未覆写 colorControlHighlight。不成立的情形：AppCompat 主题（及继承它的 MaterialComponents、Material3 主题）在 API 21+ 把 android:colorControlHighlight 指向 appcompat 的 ripple_material_light #1F000000（暗色 ripple_material_dark #33FFFFFF），不随平台版本变；框架暗主题用 ripple_material_dark，为白色乘 highlight_alpha_material_dark（各版本取值同亮主题）。〕
