# 源端可点击容器自带的按压反馈（Compose clickable、Card(onClick)，View 体系主题 listSelector 的列表行）在 ArkUI onClick 上不会自动出现：用通用属性 stateStyles 补状态层并成对写 normal 写回静止值（stateEffect 只属于 Button），不可点击时不显示；View 体系列表选择器按压色作底色画在内容下，不用 opacity 代替；选择器是 <ripple> 时不按原色整块平铺

## 何时使用

界面实现阶段，为任何可点击元素（列表行、对话框文字按钮、ImageButton/图标按钮、标题栏动作钮）用 stateStyles 写按压态时；把带 Modifier.clickable/toggleable/selectable，或 Card、Surface(onClick) 的 Compose 容器转成挂 onClick 的 ArkUI 容器时；把 ListView、PreferenceActivity 中由主题 listSelector 提供按压态的可点击行转成 ArkUI 列表行时；把 GridView 条目转成 Grid/GridItem 时

## 适用情境

源端容器经 clickable/toggleable（可带 role = Button、Switch）或 Card/Surface(onClick) 响应点击，没有把 indication 设为 null，按压时由主题提供涟漪或状态层；目标用 Column/Row/Stack 加 .onClick 实现，ArkUI 通用容器默认没有按压反馈（Button 自带的按压效果除外）。 也包括 View 体系的 ListView、PreferenceActivity 行没有把 background 或 listSelector 设为 null，按压态由主题选择器（如 Holo 暗色 list_selector_holo_dark）提供；写者在 d.ts 里找不到通用容器的 stateEffect，就放弃了按压态。 也包括 GridView 条目：GridView 未改写 listSelector 与 drawSelectorOnTop，Activity 主题分散在 res/values 与 values-v11/v14 等多个 styles.xml，低 minSdk 的旧工程在新设备上走 values-v11+ 的 Holo 父主题。 也包括 Material 主题（values-v21 的 android:Theme.Material*）下，列表选择器、标题栏按钮背景（?attr/actionBarItemBackground）与无边框按钮背景解析到 <ripple> drawable，规格或兄弟页只给出一个“按压色”。

## 例外与边界

- 源端显式 indication = null 或自定义 indication 时，按源端写法处理
- 目标用自带按压效果的 Button 承载点击时，不再叠加

## 原因

Compose 的点击修饰符默认带按压指示，调用处看不到任何反馈代码；只翻译 onClick 时点击可用但按压没有反馈，编译与结构检查都发现不了。stateEffect 只是 Button 的属性，通用容器的按压态要用 stateStyles 或 onTouch 状态驱动；以“查不到 stateEffect”为由省略，按压反馈整体缺失。 stateStyles 里只写 pressed、没有用 normal 写回被改属性时，松手后该属性停在按下值（实测按下底色一直残留），按钮与列表行都一样。 AbsListView（ListView、GridView）的 drawSelectorOnTop 默认 false（本机 android-36.1 源码 AbsListView.java），选择器的按压色画在条目内容下面，图标与文字像素不变；用 opacity 整体变暗会连内容一起变淡。只看 res/values 会认错主题代际：同名主题在 values-v11/v14 常改为继承 Theme.Holo，低 minSdk 不等于老式 list_selector_background。 Material 主题的选择器与按钮背景是 RippleDrawable：colorControlHighlight（highlight_alpha × 前景色）只是涟漪着色输入，屏上是有界径向层或无界圆，把原值整块平铺会偏深、形状也不同。

## 做法

1. 在承载点击的同一容器上加通用属性 stateStyles，pressed 与 normal 成对声明：pressed 改了哪些属性（如 backgroundColor），normal 就把这些属性写回静止值（无底色写 Color.Transparent，有底色写原色）；内联样式块与 @Styles 方法引用（如 { normal: this.released, pressed: this.pressedStyle }）都要成对。任何容器可用；stateEffect 只属于 Button，查不到它不是省略按压态的理由。按压时叠加状态层：Compose 源按 Material3 取约 10% 的内容色，View 体系按源主题选择器的实际按压外观（如 Holo 暗色 #40CCCCCC）；叠层随容器圆角裁剪，纯色背景也可预混成按压色。 View 体系列表与网格的状态层是底色：选择器画在条目内容下面（drawSelectorOnTop 默认 false），pressed 态写 backgroundColor、normal 透明，不用 opacity、整体变暗或盖在内容上的叠层代替。取色前按设备 API 沿 res/values-vNN/styles.xml 找 Activity 主题的 parent 链确认主题代际，再从 SDK platforms/android-<api>/data/res 下该主题 listSelector（按钮看其 background）指向的 drawable 先看根元素：<selector> 的纯色按压项取色；<ripple> 按下一步处理，不取 colorControlHighlight 原值整块平铺。取不到时在报告里写明缺口，不以 opacity 兜底。
2. drawable 根元素是 <ripple> 时（Material 主题 API 21+ 的 listChoiceBackgroundIndicator、selectableItemBackground、actionBarItemBackground、btn_borderless_material 等）按涟漪形状落实：含 mask 或内容层的有界涟漪在视图边界内画以视图中心为圆心、视图半对角线为半径的径向层；无 mask、无内容层的无界涟漪按 android:radius 画圆（圆心按源控件热区），圆外无色，不铺满按钮矩形。highlight_alpha 原值随 SDK 版本不同（本机 android-30/34/35 为 0.10/0.5/0.20），屏上稳态不透明度由对照设备 Android 版本的 RippleDrawable 绘制决定：按该版本实测按住稳态，或在报告里登记待实测；不按“与兄弟页同值”挑某一版本，也不在同一组件里混用不同版本的值。
3. 按源端 enabled 条件决定是否出现：clickable/toggleable 的 enabled 为假时（如内容不足、无可展开项）既不响应点击也不显示按压态。

- 〔适用情境 / 做法第 1 步〕material3 的 MaterialTheme 把 LocalIndication 设为 material3 的 ripple()，Modifier.clickable、Card(onClick) 等不传 indication 时用它；ripple 没指定颜色时取 LocalContentColor，不透明度取 RippleDefaults.RippleAlpha：pressed 0.1（StateTokens.PressedStateLayerOpacity），dragged 0.16、focused 0.1、hovered 0.08。material3 1.4.0 与 1.5.0-alpha08 相同
- 〔原因 / 做法第 1 步〕stateEffect 的声明只有两处：ButtonAttribute.stateEffect(value: boolean)（首段 @since 7，按压态切换效果开关）和安全控件 SaveButtonAttribute.stateEffect(enabled: boolean)（@since 20，需要 ohos.permission.CUSTOMIZE_SAVE_BUTTON）；CommonMethod 上没有，Column、Row、Stack 等通用容器不能写 stateEffect
- 〔做法第 1 步〕stateStyles(value: StateStyles): T 是通用属性（CommonMethod，首段 @since 8）；StateStyles 的字段都可选：normal（无状态时）、pressed、disabled、focused、clicked 为 any（API 8 起），selected 为 object（API 10 起，只对 Checkbox、CheckboxGroup、Radio、Toggle、ListItem、GridItem、MenuItem 的选中属性生效），hovered 自 26.0.0 起（超出本机 SDK 的 API 23）
- 〔做法第 1 步〕多态样式只支持通用属性，组件的私有属性（如 fontColor、TextInput 的 backgroundColor）写进 stateStyles 不生效；stateStyles 不能在 attributeModifier 里调用；组件同时处于几种状态、各状态设了同一属性时，后设置的生效；clicked 与 pressed 同时用在一个组件上时，只有后注册的那个生效；focused 态只在焦点激活态开启时生效
- 〔做法第 1 步〕多态样式直接写在 @Builder 里的组件上不生效（Builder 没有独立的自定义父节点，无法触发刷新）；把带 stateStyles 的组件封装成自定义组件，再放进 @Builder 才生效
- 〔原因 / 做法第 1 步〕stateStyles 里只设 pressed（改 backgroundColor）、没有 normal 时，设备上手指离开按下态后该底色不恢复，一直保留按下时的颜色；按钮、标题栏图标和列表行都是这样
- 〔做法第 3 步〕enabled(value: boolean): T（通用属性，首段 @since 7）：false 时组件不可交互、不响应交互操作；禁用控制只在按下时生效，交互过程中改 enabled 无效；StateStyles 另有 disabled 态
- 〔原因 / 做法第 1 步〕AbsListView（ListView、GridView）的 drawSelectorOnTop 默认 false：mDrawSelectorOnTop 初值 false，读 XML 属性时缺省也是 false；attrs.xml 说明为 false 时选择器画在条目后面（true 时画在条目上面）。Theme.Holo 的 Widget.Holo.GridView 链上没有另设
- 〔适用情境 / 做法第 1 步〕Theme.Holo（暗色）：gridViewStyle = Widget.Holo.GridView，其 listSelector = ?attr/selectableItemBackground，Theme.Holo 里解析为 @drawable/item_background_holo_dark；listViewStyle = Widget.Holo.ListView，其 listSelector = ?attr/listChoiceBackgroundIndicator，解析为 @drawable/list_selector_holo_dark。ListView 与 GridView 走的是两个不同的主题属性（android-30 与 android-36.1 相同）
- 〔做法第 1 步〕list_selector_holo_dark 与 item_background_holo_dark 的根元素都是 <selector>：按下项（state_pressed，聚焦与否都是）指向 list_selector_background_transition_holo_dark（<transition>，由九宫格 list_pressed_holo_dark 过渡到 list_longpressed_holo_dark）；禁用且聚焦时为 list_selector_disabled_holo_dark；list_selector_holo_dark 在窗口未获焦时为透明，item_background_holo_dark 的默认项为透明
- 〔做法第 1 步〕Theme.Holo 暗色主题下，GridView 条目（布局没改 listSelector、drawSelectorOnTop）按下时，整格（含内边距空白）出现一层 #40CCCCCC 底色画在图标下面，图标像素不变
- 〔适用情境 / 做法第 1、2 步〕Theme.Material / Theme.Material.Light（android-30 与 android-36.1 相同）：Widget.Material.ListView 的 listSelector = ?attr/listChoiceBackgroundIndicator → @drawable/list_choice_background_material；selectableItemBackground = @drawable/item_background_material；actionBarItemBackground = @drawable/action_bar_item_background_material；Widget.Material.Button.Borderless（含对话框按钮条按钮）的 background = @drawable/btn_borderless_material
- 〔做法第 2 步〕这几个 drawable 的根元素都是 <ripple>：list_choice_background_material 的颜色为 @color/list_highlight_material（默认项 ?attr/colorControlHighlight，另有 state_activated 项），带 id=mask 的白色 item；item_background_material 为 ?attr/colorControlHighlight 加 id=mask 的白色 item；btn_borderless_material 为 ?attr/colorControlHighlight 加 id=mask 的 btn_default_mtrl_shape；action_bar_item_background_material 为 <ripple android:color="?attr/colorControlHighlight" android:radius="20dp" />，没有 mask 也没有子层（android-30 与 android-36.1 相同）
- 〔做法第 2 步〕RippleDrawable：设了 mask 层时，涟漪先按 mask 裁剪，再画在其余子层合成之上（mask 层本身不画）；没有 mask 时按子层的合成形状裁剪；既没有子层也没有 mask、又作 View 背景时，涟漪画在层级里最近一个有背景的祖先上，绘制区可以超出自身 drawable 边界（无界涟漪）
- 〔做法第 2 步〕应用主题与代码没有另设 colorControlHighlight 时，平台默认值是 ripple_material_light / ripple_material_dark：前景色（浅色主题黑、深色主题白）乘 highlight_alpha_material_light / _dark；这个 alpha 随平台版本变：android-30、android-33 为 0.10，android-34 为 0.5，android-35、android-36、android-36.1、android-37.0 为 0.20，即 Theme.Material.Light 下 #1a000000、#80000000、#33000000；应用主题是 AppCompat 系（含 MaterialComponents、Material3）时，values-v21 起 android:colorControlHighlight 接到库的 ?attr/colorControlHighlight，Light 为 #1f000000、深色 Theme.AppCompat 为 #33ffffff，不随平台版本变（appcompat 1.1.0、1.8.0，material 1.8.0、1.14.0 相同）
- 〔做法第 2 步〕Android 12 对照设备上按住不放的稳态：有界涟漪（列表行等带 mask 的）在视图边界内是以视图中心为圆心、半径 R 为视图半对角线的径向层，r ≤ 0.6R 处约 8.6%、R 处约 6%，不等于任何一版 highlight_alpha 原值；标题栏按钮（action_bar_item_background_material）是半径 20dp 的无界白色圆，圆心在按钮内容区中心，圆外无色
- 〔做法第 2 步〕radialGradient(value: RadialGradientOptions): T（首段 @since 7），另有 radialGradient(options: Optional<RadialGradientOptions>): T（@since 18，传 undefined 恢复为无径向渐变）。RadialGradientOptions：center: [Length, Length] 是相对组件左上角的坐标，number 单位 vp；radius: Length，number 单位 vp，小于 0 按 0，undefined 时按组件尺寸自动计算；colors: Array<[ResourceColor, number]>，位置取 [0, 1.0]、超出按端点处理、应递增；repeating 默认 false。颜色渐变属于组件内容，画在背景上方；同一组件只能有一种渐变，后调用的覆盖前面的
- 〔做法第 2 步〕onTouch(event: (event: TouchEvent) => void): T 是通用事件（首段 @since 7）；TouchType 有 Down、Up、Move、Cancel
