# 源端 onTouch 自己按未掩码 getAction 只跟随首指时，先看手指由谁接收再过滤 ArkUI 逐指派发：Up 事件的 touches 仍含正在抬起的手指（末指抬起为 touches.length === 1）；单个视图独占全部手指才按 touches 计数，兄弟控件各自监听时按 pointer id 集合；源端交给 GestureDetector/ScaleGestureDetector 时按本机 SDK 源码逐段移植该检测器

## 何时使用

输入控制的规格提取与实现阶段，把 Android onTouch 的 MotionEvent 动作分支和坐标读取映射为 ArkUI onTouch 的 TouchType 分支与触点来源时

## 适用情境

源端 OnTouchListener 用未掩码的 event.getAction() 只匹配 ACTION_DOWN/MOVE/UP，以无索引的 getX()/getY()（指针索引 0）读坐标，附加手指的 POINTER_DOWN/UP 不进入任何分支；目标 ArkUI .onTouch 对每根手指都派发 TouchType.Down/Up，TouchEvent 同时提供 touches（含本次抬起手指在内的全部触点）与 changedTouches（本次变化的触点）。也包括源端多个兄弟控件（方向键、旋转键等）各自 setOnTouchListener，未设 splitMotionEvents=false（ViewGroup 构造时默认开启分指），每个控件只收落在自己身上的指针流（窗口级的 windowEnableSplitTouch 只管一次多指操作能否分到不同窗口，不决定同一窗口里兄弟控件之间的分指）；目标每个按钮各挂 .onTouch，而 TouchEvent.touches 列出屏幕上全部手指。也包括源端 onTouch 只 return gestureDetector.onTouchEvent(event)，方向写在 SimpleOnGestureListener.onFling/onScroll 中。

## 例外与边界

- 源端用 getActionMasked() 处理 POINTER_DOWN/UP，或按 pointerId 跟踪多指时，按源端的多指语义逐指映射
- 源端 onTouch 只把事件交给 GestureDetector（new GestureDetector、extends SimpleOnGestureListener、return gestureDetector.onTouchEvent(event)）时不套用本条的计数过滤，按做法第 3 步移植检测器

## 原因

ArkUI 回调的派发粒度比源端细，桥接处不过滤，源端忽略的事件就会进入状态机：逐一映射 Down/Up 并统一取 changedTouches[0] 时，第二指按下被当成新的 ACTION_DOWN 而重置起点，Move 跟着本次变化的手指在两指间跳动，首指抬起被当成 ACTION_UP。反过来，Up 事件的 touches 仍包含正在抬起的手指，把“末指抬起”写成 touches.length === 0 时判定永不执行，滑动完全失效（来源中规格、转换与切片三处提醒都把末指抬起读成 touches 为空）。touches 是全屏触点：多按钮时按 touches.length 过滤，会把另一按钮上的手指当作本控件的附加手指。源端经 GestureDetector 触发 onFling 时还有触摸容差、长按、双击与最小抛掷速度等前置条件，简化成“位移超阈值且速度大于 0”会让源端不触发的手势也触发。交给 GestureDetector/ScaleGestureDetector 的其他行为同样在框架里而不在应用源码：长按到期后吞掉后续滚动与单击、滚动按全部手指平均焦点、双击锚点、缩放开始条件与 quick scale；按参数清单自建的“等效检测器”会漏掉这些分支，表现为捏合不缩放、长按后仍走步、滚动只跟首指。

## 做法

1. 先确认源端由哪个视图接收手指、是否交给 GestureDetector。单个视图独占全部手指（如整屏棋盘）且源端自己判 action 时：Down 事件 touches.length > 1 直接忽略；Up 事件只在 touches.length === 1（仅剩正在抬起的这一根）时进入状态机，大于 1 忽略；Move 取 event.touches[0]，首指 Down、末指 Up 与 Cancel 取 changedTouches[0]（取 [0] 前先判空）。多个兄弟控件各自监听时：在每个控件内按 changedTouches[0].id 维护落在本控件的指针集合，集合为空时的 Down 算按下，移除后集合为空的 Up 算抬起，Cancel 清空并抬起。
2. 规格映射动作分支时写明源端用的是 getAction() 还是 getActionMasked()、附加手指是否参与、窗口是否分指、是否经 GestureDetector，并写出目标端的过滤规则，不用“TouchType.Down/Move/Up 行为等价”一句带过；按键 Down/Up 双派发等同类细粒度回调，也先写明源端实际进入分支的事件子集再过滤。
3. 源端只依赖 onFling 时实现等价检测器（先核源端能否收到 DOWN 之后的事件：listener 的 onDown 没覆写成返回 true、视图本身又不可点时，onTouch 对 DOWN 返回 false，源端的 onScroll、onFling 永不触发，目标也不触发）：按 ViewConfiguration 的触摸容差（8dp）、长按超时（400ms）、双击窗口、多指时取消点击，用 VelocityTracker 同类的速度估计与最小/最大抛掷速度判定 fling，满足后再调用源 onFling 的方向判定。源端回调依赖 onScroll、onDoubleTap、onSingleTapUp 的多指与时序语义，或同时把事件交给 ScaleGestureDetector 时，按本机 SDK sources/android-<api> 中 GestureDetector（及 ScaleGestureDetector）的 onTouchEvent 逐段移植（未装 sources 包先装对应版本），Handler 消息改用定时器，ViewConfiguration 尺寸按本机密度换算；把 ArkUI 逐指触摸折成 MotionEvent 序列（首指 DOWN、其余 POINTER_DOWN，MOVE 带全部指针，非末指 POINTER_UP、末指 UP），照源顺序先喂缩放检测器、再喂手势检测器、再走源端自己的 ACTION_MOVE 分支。参数清单方案会漏：长按到期后不再回调 onScroll/onSingleTapUp（onLongPress 为空实现也如此）；onScroll 距离按全部未抬起手指的平均焦点；双击要求第二次按下时第一次按下的 TAP 消息未到期，onDoubleTap 收到第一次按下事件；ScaleGestureDetector 在每个 MOVE 判定开始，跨度变化须超过 spanSlop 且不小于 minSpan，targetSdk>18 时 quick scale 默认开启。

## 可选检查

- 两指同时同向滑动只触发一次该方向的移动，单指四向仍各触发一次。
- 按住一个按钮再点另一个按钮，两者各自恰好产生一次按下、一次抬起，不卡按。
- 源端用 GestureDetector 时：单指快速滑动抬起触发一次，停顿后抬起、长按后拖动不触发。
- 源端用 GestureDetector/ScaleGestureDetector 时：按住超过长按超时后拖动不滚动、松手不算单击；双指捏合能缩放并在最小跨度处停止；双击后按住拖动以第一次按下点为焦点缩放。

- 〔适用情境 / 例外与边界〕安卓 MotionEvent.getAction() 在附加手指按下、抬起时返回 ACTION_POINTER_DOWN(5)、ACTION_POINTER_UP(6) 与指针索引（ACTION_POINTER_INDEX_MASK = 0xff00 那几位）的组合；getActionMasked() = getAction() & ACTION_MASK(0xff) 才能稳定匹配 ACTION_POINTER_DOWN/UP；未掩码的值永远不等于 ACTION_DOWN(0)、ACTION_UP(1)、ACTION_MOVE(2)
- 〔适用情境〕安卓 MotionEvent.getX()、getY() 不带索引时取指针索引 0（first pointer index）的坐标
- 〔适用情境 / 做法第 2 步〕安卓 ViewGroup 的分指（FLAG_SPLIT_MOTION_EVENTS）开启时，每根手指的事件派给它最初按下的那个子 View（鼠标来源的事件不分指）；android-36.1 源码在 ViewGroup 构造时就置上这个标志，属性说明写 HONEYCOMB 及以后默认开启；应用布局没写 android:splitMotionEvents="false"、代码也没调 setMotionEventSplittingEnabled(false) 时一直开着
- 〔适用情境 / 做法第 2 步〕安卓 PhoneWindow 按主题的 android:windowEnableSplitTouch 给窗口加 FLAG_SPLIT_TOUCH，主题没写这个属性时 targetSdk ≥ 11（HONEYCOMB）即为 true；这个标志决定一次多指操作的各根手指能否分到不同窗口，同一窗口里兄弟 View 之间的分指由 ViewGroup 的 splitMotionEvents 决定
- 〔例外与边界 / 做法第 3 步〕安卓 View 在 enabled 时先调 OnTouchListener.onTouch，返回 false（或视图 disabled、没挂监听）时再调 onTouchEvent；视图没开 CLICKABLE、LONG_CLICKABLE、CONTEXT_CLICKABLE（也没有 tooltip，TouchDelegate 也没消费）时 onTouchEvent 返回 false，disabled 但可点的视图仍消费事件；View 在应用没另设 clickable 时不可点，setOnClickListener、setOnLongClickListener 会把它设成可点，平台 Widget.Button、Widget.ImageButton 样式里 clickable 为 true；ACTION_DOWN 没被某个子 View 消费时，父 ViewGroup 不把它记为触摸目标，这一轮后续的 MOVE、UP 不派给它
- 〔例外与边界 / 做法第 3 步〕GestureDetector.SimpleOnGestureListener 没覆写的 onDown、onScroll、onFling、onSingleTapUp、onDoubleTap 都返回 false；GestureDetector.onTouchEvent 对 ACTION_DOWN 的返回值取 onDown（以及双击回调）的结果
- 〔原因 / 做法第 3 步〕GestureDetector 在 ACTION_UP 时：正在双击只回调 onDoubleTapEvent；已进入长按则不回调 onSingleTapUp、onFling；焦点没移出触摸容差则回调 onSingleTapUp；否则用 VelocityTracker 算抬起时仍按着的那根手指（指针索引 0）的速度（以最大抛掷速度为上限），x 或 y 方向绝对值大于最小抛掷速度才回调 onFling(按下事件, 抬起事件, vx, vy)；多指时 ACTION_POINTER_UP 若抬起的手指与其余手指的速度方向相反（点积为负）会清空速度记录
- 〔原因 / 做法第 3 步〕GestureDetector 在应用没调 setIsLongpressEnabled(false) 时，ACTION_DOWN 安排一条在 按下时刻 + 长按超时 到期的 LONG_PRESS 消息；焦点在到期前移出触摸容差时 ACTION_MOVE 回调 onScroll 并撤掉这条消息，不再进入长按；到期后 dispatchLongPress 置 mInLongPress 并回调 onLongPress（空实现也一样），此后 ACTION_MOVE 开头直接跳出、不回调 onScroll，ACTION_UP 不回调 onSingleTapUp 和 onFling；ACTION_POINTER_DOWN 会取消待发的单击和长按
- 〔原因 / 做法第 3 步〕GestureDetector 每个事件把全部指针的坐标取平均作焦点（ACTION_POINTER_UP 时跳过正在抬起的那根），onScroll 的距离是 上次焦点 − 当前焦点；焦点没移出触摸容差之前不回调 onScroll
- 〔原因 / 做法第 3 步〕GestureDetector 设了双击监听时，ACTION_DOWN 若发现第一次按下发出的 TAP 消息仍未到期，且第一次按下后手指没移出双击触摸容差、第二次按下距第一次抬起在 DOUBLE_TAP_MIN_TIME 与 DOUBLE_TAP_TIMEOUT 之间、与第一次按下的距离小于双击容差，就回调 onDoubleTap(第一次的按下事件) 和 onDoubleTapEvent(本次按下)；否则发出一条 DOUBLE_TAP_TIMEOUT 后到期的 TAP 消息
- 〔做法第 3 步〕安卓 ViewConfiguration 的取值（设备没改平台资源、用户没改系统长按延迟时）：触摸容差 8dp（手表 values-watch 为 4dp），TAP_TIMEOUT 100ms，DOUBLE_TAP_TIMEOUT 300ms，DOUBLE_TAP_MIN_TIME 40ms（android-36 起改由平台资源 config_tapTimeoutMillis 等给出，取值不变），双击容差 DOUBLE_TAP_SLOP 100dp（屏幕尺寸类别为 xlarge 时乘 1.5，即 150dp），最小、最大抛掷速度 50dp/s、8000dp/s（手表 values-watch 最小为 500dp/s，最大在 android-30 至 35 为 8000dp/s、android-36 起为 2750dp/s，核到 37.0）；长按超时取系统设置 LONG_PRESS_TIMEOUT，没改时为 DEFAULT_LONG_PRESS_TIMEOUT 400ms
- 〔原因 / 做法第 3 步〕安卓设备上用 GestureDetector 的视图，按住约 0.7 秒（超过长按超时）后拖动，onScroll 驱动的平移没有发生，松手也没有触发单击动作
- 〔原因 / 做法第 3 步〕ScaleGestureDetector 公开构造时 spanSlop = getScaledTouchSlop() × 2，minSpan = getScaledMinimumScalingSpan()（平台资源 config_minScalingSpan，设备没改时手机为 27mm，最短边 ≥600dp 命中 values-sw600dp 时为 32mm）；targetSdk 大于 18（JELLY_BEAN_MR2）时构造里打开 quick scale，大于 22（LOLLIPOP_MR1）时打开手写笔按键缩放
- 〔原因 / 做法第 3 步〕ScaleGestureDetector.onTouchEvent 对 UP、CANCEL 以外的每个事件都算焦点和跨度：没在缩放时，跨度 ≥ minSpan 且（刚才在缩放或与初始跨度之差 > spanSlop）才调 onScaleBegin，它返回 false 时不进入缩放；正在缩放时跨度 < minSpan 或指针数变化（DOWN、POINTER_DOWN、POINTER_UP）就调 onScaleEnd，指针变化时跨度仍够会立即重新 onScaleBegin；onScale 只在缩放中的 MOVE 时回调，返回 false 时不更新上一次跨度（缩放比按累积算）；quick scale 等锚定模式下焦点固定在双击开始处、跨度只取 spanY、开始门槛用 spanSlop，且不因跨度变小或指针数变化而结束
- 〔做法第 3 步〕ScaleGestureDetector 要求从 ACTION_DOWN 到 ACTION_UP 或 ACTION_CANCEL 的完整一致事件流；收到 ACTION_DOWN、ACTION_UP、ACTION_CANCEL 时结束正在进行的缩放
- 〔何时使用 / 做法第 1 步〕ArkUI 的 onTouch(event: (event: TouchEvent) => void) 是通用事件；TouchType 有 Down、Up、Move、Cancel 四种，手指按住屏幕时点 Home 键回桌面会触发 Cancel
- 〔适用情境 / 原因 / 做法第 1 步〕TouchEvent.touches 是全部触点（声明注释 All finger information；参考文档写全部屏幕触点；交互指南写包含窗口所有按压手指，落在别的组件上的手指也在内），changedTouches 是本次变化而产生事件的触点；两者使用时都要先判空；TouchObject.id 是手指的唯一标识
- 〔标题 / 原因 / 做法第 1 步〕ArkUI 的 Up 事件里 touches 仍含正在抬起的那根手指：交互指南的多指示例以 type 为 TouchType.Up 且 touches.length === 1 判定所有手指都已抬起
- 〔标题 / 原因 / 做法第 1 步〕HarmonyOS 6.1.0(23) 设备上，末指抬起时 onTouch 收到的 Up 事件 touches.length 为 1
- 〔做法第 1 步〕非事件注入场景下 changedTouches 是按屏幕刷新率重采样的点，touches 是按器件刷新率上报的点，两者数据可能不同；按下、抬起事件立即上报（抬起前先补报未处理的 move），帧内的 move 重采样合并后上报
- 〔适用情境 / 做法第 1 步〕ArkUI 的 onTouch 按手指闭环且一致：组件收到某个手指 id 的 Down，后续也会收到这根手指的 Move 和 Up；没收到某根手指的 Down，就收不到这根手指后续的触摸事件
- 〔原因 / 做法第 1 步〕HarmonyOS 6.1.0(23) 设备上两指同时在同一组件上按下时，该组件的 onTouch 对第二根手指也收到一次 TouchType.Down，其 changedTouches[0] 是第二根手指
- 〔适用情境 / 做法第 1 步〕HarmonyOS 6.1.0(23) 设备上两个兄弟按钮各挂 onTouch：一指按住 A 时另一指按 B，B 收到的 Down 事件 touches.length 为 2；B 仍按着时 A 抬起，A 收到的 Up 事件 touches.length 也不为 1
- 〔做法第 2 步〕ArkUI 的 onKeyEvent 对每个按键回调 2 次，分别对应 KeyType.Down 和 KeyType.Up，按 KeyEvent.type 区分；onKeyEvent(event: (event: KeyEvent) => void) 自 API 11 声明，API 15 起另有回调返回 boolean 的重载
- 〔做法第 2 步〕安卓 KeyEvent.dispatch 把 ACTION_DOWN 交给 onKeyDown、ACTION_UP 交给 onKeyUp；按住不放时系统按重复间隔继续发 ACTION_DOWN（getRepeatCount() > 0），onKeyDown 会被重复调用；ACTION_MULTIPLE 先给 onKeyMultiple，没处理时拆成一次 onKeyDown（处理了再补一次 onKeyUp）；只覆写 onKeyDown 的源端只在按下（含按住时的重复）时进入
