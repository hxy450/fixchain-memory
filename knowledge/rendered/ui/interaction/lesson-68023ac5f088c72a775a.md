# 源端 onTouch 自己按未掩码 getAction 只跟随首指时，先看手指由谁接收再过滤 ArkUI 逐指派发：Up 事件的 touches 仍含正在抬起的手指（末指抬起为 touches.length === 1）；单个视图独占全部手指才按 touches 计数，兄弟控件各自监听时按 pointer id 集合；源端交给 GestureDetector/ScaleGestureDetector 时按本机 SDK 源码逐段移植该检测器

## 何时使用

输入控制的规格提取与实现阶段，把 Android onTouch 的 MotionEvent 动作分支和坐标读取映射为 ArkUI onTouch 的 TouchType 分支与触点来源时

## 适用情境

源端 OnTouchListener 用未掩码的 event.getAction() 只匹配 ACTION_DOWN/MOVE/UP，以无索引的 getX()/getY()（指针索引 0）读坐标，附加手指的 POINTER_DOWN/UP 不进入任何分支；目标 ArkUI .onTouch 对每根手指都派发 TouchType.Down/Up，TouchEvent 同时提供 touches（含本次抬起手指在内的全部触点）与 changedTouches（本次变化的触点）。也包括源端多个兄弟控件（方向键、旋转键等）各自 setOnTouchListener，未设 splitMotionEvents=false（ViewGroup 构造时默认开启分指），窗口默认分指，每个控件只收落在自己身上的指针流；目标每个按钮各挂 .onTouch，而 TouchEvent.touches 列出屏幕上全部手指。也包括源端 onTouch 只 return gestureDetector.onTouchEvent(event)，方向写在 SimpleOnGestureListener.onFling/onScroll 中。

## 例外与边界

- 源端用 getActionMasked() 处理 POINTER_DOWN/UP，或按 pointerId 跟踪多指时，按源端的多指语义逐指映射
- 源端 onTouch 只把事件交给 GestureDetector（new GestureDetector、extends SimpleOnGestureListener、return gestureDetector.onTouchEvent(event)）时不套用本条的计数过滤，按做法第 3 步移植检测器

## 原因

ArkUI 回调的派发粒度比源端细，桥接处不过滤，源端忽略的事件就会进入状态机：逐一映射 Down/Up 并统一取 changedTouches[0] 时，第二指按下被当成新的 ACTION_DOWN 而重置起点，Move 跟着本次变化的手指在两指间跳动，首指抬起被当成 ACTION_UP。反过来，Up 事件的 touches 仍包含正在抬起的手指，把“末指抬起”写成 touches.length === 0 时判定永不执行，滑动完全失效（来源中规格、转换与切片三处提醒都把末指抬起读成 touches 为空）。touches 是全屏触点：多按钮时按 touches.length 过滤，会把另一按钮上的手指当作本控件的附加手指。源端经 GestureDetector 触发 onFling 时还有触摸容差、长按、双击与最小抛掷速度等前置条件，简化成“位移超阈值且速度大于 0”会让源端不触发的手势也触发。交给 GestureDetector/ScaleGestureDetector 的其他行为同样在框架里而不在应用源码：长按到期后吞掉后续滚动与单击、滚动按全部手指平均焦点、双击锚点、缩放开始条件与 quick scale；按参数清单自建的“等效检测器”会漏掉这些分支，表现为捏合不缩放、长按后仍走步、滚动只跟首指。

## 做法

1. 先确认源端由哪个视图接收手指、是否交给 GestureDetector。单个视图独占全部手指（如整屏棋盘）且源端自己判 action 时：Down 事件 touches.length > 1 直接忽略；Up 事件只在 touches.length === 1（仅剩正在抬起的这一根）时进入状态机，大于 1 忽略；Move 取 event.touches[0]，首指 Down、末指 Up 与 Cancel 取 changedTouches[0]（取 [0] 前先判空）。多个兄弟控件各自监听时：在每个控件内按 changedTouches[0].id 维护落在本控件的指针集合，集合为空时的 Down 算按下，移除后集合为空的 Up 算抬起，Cancel 清空并抬起。
2. 规格映射动作分支时写明源端用的是 getAction() 还是 getActionMasked()、附加手指是否参与、窗口是否分指、是否经 GestureDetector，并写出目标端的过滤规则，不用“TouchType.Down/Move/Up 行为等价”一句带过；按键 Down/Up 双派发等同类细粒度回调，也先写明源端实际进入分支的事件子集再过滤。
3. 源端只依赖 onFling 时实现等价检测器（先核源端能否收到 DOWN 之后的事件：listener 的 onDown 没覆写成返回 true、视图本身又不可点时，onTouch 对 DOWN 返回 false，源端的 onScroll、onFling 永不触发，目标也不触发）：按 ViewConfiguration 的触摸容差（8dp）、长按超时（400ms）、双击窗口、多指时取消点击，用 VelocityTracker 同类的速度估计与最小/最大抛掷速度判定 fling，满足后再调用源 onFling 的方向判定。源端回调依赖 onScroll、onDoubleTap、onSingleTapUp 的多指与时序语义，或同时把事件交给 ScaleGestureDetector 时，按本机 SDK sources/android-<api> 中 GestureDetector（及 ScaleGestureDetector）的 onTouchEvent 逐段移植（未装 sources 包先装对应版本），Handler 消息改用定时器，ViewConfiguration 尺寸按本机密度换算；把 ArkUI 逐指触摸折成 MotionEvent 序列（首指 DOWN、其余 POINTER_DOWN，MOVE 带全部指针，非末指 POINTER_UP、末指 UP），照源顺序先喂缩放检测器、再喂手势检测器、再走源端自己的 ACTION_MOVE 分支。参数清单方案会漏：长按到期后不再回调 onScroll/onSingleTapUp（onLongPress 为空实现也如此）；onScroll 距离按全部未抬起手指的平均焦点；双击要求第二次按下时第一次按下的 TAP 消息未到期，onDoubleTap 收到第一次按下事件；ScaleGestureDetector 在每个 MOVE 判定开始，跨度变化须超过 spanSlop 且不小于 minSpan，targetSdk>18 时 quick scale 默认开启。

## 可选检查

- 两指同时同向滑动只触发一次该方向的移动，单指四向仍各触发一次。
- 按住一个按钮再点另一个按钮，两者各自恰好产生一次按下、一次抬起，不卡按。
- 源端用 GestureDetector 时：单指快速滑动抬起触发一次，停顿后抬起、长按后拖动不触发。
- 源端用 GestureDetector/ScaleGestureDetector 时：按住超过长按超时后拖动不滚动、松手不算单击；双指捏合能缩放并在最小跨度处停止；双击后按住拖动以第一次按下点为焦点缩放。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 Android SDK 源码 android-36.1；Android SDK 平台资源 android-34（config.xml）。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境〕MotionEvent：DOWN=0、UP=1、MOVE=2、CANCEL=3、POINTER_DOWN=5、POINTER_UP=6；未掩码 getAction() 对附加手指返回 5/6 |（指针索引<<8），不进 DOWN/MOVE/UP 任一分支；getActionMasked()=getAction() & 0xff
- 〔适用情境〕无参 getX()/getY() 取指针索引 0（nativeGetAxisValue(…, AXIS_X, 0, HISTORY_CURRENT)）
- 〔适用情境〕ViewGroup.initViewGroup 默认置 FLAG_SPLIT_MOTION_EVENTS（android-36.1 源码不看 targetSdk），每根手指的事件派给它按下时命中的子 View；布局 android:splitMotionEvents="false" 或 setMotionEventSplittingEnabled(false) 才关闭
- 〔做法第 1 步〕TouchEvent：type: TouchType；touches: TouchObject[] 为全部屏幕触点（多指），含落在别的组件上的手指；changedTouches: TouchObject[] 为发生变化而产生本次事件的手指；两者都可能为空
- 〔做法第 1 步〕TouchObject.id：手指唯一标识；x、y 是以事件响应组件为基准的组件坐标，单位 vp（windowX、displayX 等同为 vp）
- 〔做法第 1 步〕TouchType：Down=0、Up=1、Move=2、Cancel=3；HOVER_ENTER/MOVE/EXIT/CANCEL（9–12，API 20+）只在无障碍模式下出现
- 〔做法第 1 步〕onTouch 按手指闭环派发：组件收到手指 id 0 的 Down，后续也会收到 id 0 的 Move 和 Up；没收到某手指的 Down，就不会收到该手指的后续事件
- 〔做法第 1 步〕ArkUI onTouch 的 Up 事件里 touches 仍含正在抬起的手指：最后一根手指抬起时 type 为 Up、touches.length 为 1，不会出现 0
- 〔做法第 2 步〕onKeyEvent 对每个按键回调两次，分别是 KeyType.Down 与 KeyType.Up；安卓 onKeyDown 只在按下时进入
- 〔做法第 3 步〕ViewConfiguration 平台默认值（厂商可在 config 资源里改，长按超时随系统设置 Settings.Secure.LONG_PRESS_TIMEOUT）：触摸容差 8dp、长按 400ms、TAP 100ms、双击窗口 300ms（最短 40ms）、双击距离 100dp、最小/最大抛掷速度 50/8000 dp/s（config.xml 对应项同值）；config_minScalingSpan 27mm
- 〔做法第 3 步〕GestureDetector（长按检测默认开启，未调用 setIsLongpressEnabled(false) 时）：ACTION_MOVE 在 mInLongPress 时直接 break（不再 onScroll）；ACTION_UP 在 mInLongPress 时只清标志、不调 onSingleTapUp；UP 时 computeCurrentVelocity(1000, 最大速度)，抬起指针 |vx| 或 |vy| 超过最小抛掷速度才调 onFling
- 〔做法第 3 步〕onScroll 按焦点：focusX=sumX/div，指针抬起时 div=count−1（排除抬起指针）。双击：DOWN 时仍有未到期的 TAP 消息且 isConsideredDoubleTap（40ms≤第二次按下−第一次抬起≤300ms、距离²<doubleTapSlop²）才 onDoubleTap(mCurrentDownEvent)，传入的是第一次按下事件
- 〔做法第 3 步〕ScaleGestureDetector(Context, …) 默认：spanSlop=触摸容差×2，minSpan=config_minScalingSpan；每个事件都判定 span≥minSpan（锚定模式用 spanSlop）且 |span−initialSpan|>spanSlop（或已在进行）才 onScaleBegin；targetSdk>18 时构造里开启 quick scale（之后可被 setQuickScaleEnabled 改）
- 〔做法第 3 步〕密度换算：ArkUI 触点坐标是 vp；UIContext.vp2px/px2vp 在 vp 与 px 间换算，全局 vp2px/px2vp 自 API 18 起废弃
