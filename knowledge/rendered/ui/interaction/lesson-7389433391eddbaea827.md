# Image 承载点击/长按按钮或自绘拖拽柄时设 draggable(false)：ArkUI Image 默认可被系统拖出，按住会进入拖拽并接管输入

## 何时使用

界面实现阶段，用 Image 承载按钮、可点图标或拖拽柄时：在 Image 或其外层 Stack/Button 上挂 onClick、长按手势，或在其上挂 onTouch、PanGesture 等自绘拖拽或按压逻辑时

## 适用情境

源端在 ACTION_DOWN 或 onTouch 中立即开始自定义拖拽（如清单条目拖拽排序），或图标只是点击、长按按钮（ImageButton/可点 ImageView，如快门、缩略图入口、屏上开关图标），没有任何拖放行为；目标用 Image 组件实现（可外包挂点击的 Stack/Button），未设置 draggable。

## 例外与边界

- 源端本就允许把图片拖出到其他位置或应用时保留系统拖拽

## 原因

ArkUI 的 Image 默认可拖出（Image 自身的 draggable 自 API 10 起默认为 true，API 9 及之前为 false，与通用属性的默认值不同）：按住后系统图片拖拽接管输入，自绘的 onTouch、PanGesture 收到 Cancel，按下时已隐藏的条目或拖拽阴影停在中间态；只挂点击或长按的图标按钮也会进入拖拽识别与拖拽预览，点击响应卡顿，外层 Stack/Button 上的点击不会关闭子 Image 的默认拖拽。Android ImageView/ImageButton 没有这种默认拖拽。

## 做法

1. 作按钮、可点图标或拖拽柄使用的 Image 写 .draggable(false)：点击或长按挂在外层 Stack/Button 上时也写在内层每个 Image 上，再挂自绘的 onTouch 或手势时同样先关闭；源端只在按下时起拖、没有长按分支的，目标也不保留长按触发的系统拖拽。

- 〔原因 / 做法第 1 步〕Image 组件自身的 draggable 默认值随 API 版本不同：API 9 及之前默认 false，API 10 及之后默认 true（以文档为准；SDK 声明里写 false 的注释段标 @since 9，写 true 的注释段标 @since 11、@since 18）
- 〔原因 / 做法第 1 步〕Image 的 draggable 为 true 时组件可拖拽，绑定在它上面的长按手势不生效；设为 false 后拖拽类事件不再触发；要在 Image 上用自定义手势须把 draggable 设为 false
- 〔原因〕通用属性 draggable 在组件没有另设时为 false（组件默认不允许拖拽）；Search、TextInput、TextArea、RichEditor、Text、Image、Hyperlink 是默认支持拖出的组件，由各自的 draggable 控制默认拖拽，所以 Image 与通用属性的默认值不同
- 〔原因〕手势触发拖拽时，ArkUI 先校验组件能否拖出（默认支持拖出的组件看 draggable 是否为 true）；按下约 50ms 进入拖拽手势检测，长按达到 500ms 即可发起拖拽，800ms 起拖拽预览图开始浮起
- 〔原因〕Image 承载快门、图库缩略图等点击按钮且没有设 draggable 时，设备上点按这些控件出现卡顿，线程栈停在按钮图片的拖拽预览
- 〔原因 / 做法第 1 步〕Image 作拖拽柄、挂 onTouch 与 PanGesture 而没有设 draggable 时，长按后系统图片拖拽接管输入，自绘拖拽收到 Cancel，按下时已隐藏的条目停在隐藏态
- 〔原因〕Android 的 ImageView、ImageButton 源码里没有调用 startDragAndDrop；View 的拖放要有人调用 View#startDragAndDrop（或已废弃的 startDrag）才开始，框架控件里自己发起拖放的只有 TextView 的编辑器（拖动选中的文字时）
