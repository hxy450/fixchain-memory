# 图标按源端原始资源落实：缺失时从 Android 密度目录、SDK 平台或依赖库 AAR 复制原图，不用字形、近名图标、系统符号或二次着色替代

## 何时使用

页面转换与截图对齐修复阶段，把源布局中的 @drawable 引用（头像、图标、装饰图、带透明边缘的头图、行尾箭头）落成 $r('app.media.X') 并确认资源是否已迁移时；为工具栏、菜单行、操作栏与悬浮入口选定图标资源，或在已有页面上把占位符号换成源端图标时；规格提取阶段为源端图标与界面字符写转换决策时

## 适用情境

资源迁移把 drawable-xhdpi 等位图直接复制到 resources/xldpi/media 一类限定词目录，不在 base/media；构建日志对这些图只报“does not have a base resource”警告；工程里还有外观相近的通用图标（如生活指数图标）。 也包括规格或布局已给出原始 drawable 名，目标 media 却只有其他模块的同类近名图标（如带 1/2 后缀的阅读器图标），现有代码用 SymbolGlyph 或 Unicode 字形占位，或工程 skill 要求图标优先用已验证的系统 symbol；以及源端用粗体文字字符（“-”“+”）充当按钮图形。也包括源端 Text 直接显示 emoji 字符（如 ⭐、☕️），规格或写者按“不把 emoji 塞进 Text 当图标”一类 symbol 规则改成 SymbolGlyph。 也包括图标由平台主题或框架控件提供（ActionBar 的 Up 与溢出按钮、CheckBox 勾选图），应用 res 里没有同名资源，写者以“平台 chrome、应用无源图”为由用 Polyline、Circle 或字形自绘。 也包括 AppCompat Activity 调 setDisplayHomeAsUpEnabled(true)，返回箭头由 appcompat 库主题提供，已迁移的 media 目录里找不到，目标准备改用系统符号。

## 原因

只在 base/media 查找会把已迁移的资源判为缺失，写者随之用 Text('人')、Text('›') 之类字形、品牌色底或外观相近的通用图标代替，头像、箭头、提醒图标和透明波浪头图的收口都与源端不符；截图修复时按视觉相似挑图也会延续偏差。来源中页面转换者读到源布局列出的全部 drawable 名，只核对 base/media 就把四个资源判为不存在，改成字形占位并在透明头图下垫了品牌色；返修又从通用资源里挑近似图标。 缺图时用近名资源、系统符号或 fillColor 着色去模仿原图，同样会改变图形、线宽与颜色；skill 的“只用已验证 symbol 名称”约束的是名称合法，不保证外形与源端一致。另一应用中写者已读到规格列出的原图名并查到目标缺图，仍改用另一模块的近名图标加黄色着色，交付时称其为原图；同一应用的步进器把文字“-”换成带圆圈的 minus_circle，另一页的菜单与批量底栏在缺图时直接写成纯文字。

## 做法

1. 判断资源可用性时检索 resources 下全部限定词目录（base、xldpi、dark 等）或按资源映射表核对；构建日志里的“does not have a base resource”说明文件在限定词目录：只在屏幕密度目录（如 xldpi）里的，任何密度的设备都取得到，不是缺失；只在 dark、横竖屏、设备类型或语言目录里的，设备状态不一致时（如浅色模式下的 dark 目录）回落 base 取不到，仍按缺失处理。
2. 图标与装饰图按源布局的 src、drawableStart、background 中的 drawable 名取用，写完按源布局的 drawable 清单逐项对照组件中的引用；确认缺失时登记资源缺口，不以文字字形、纯色底或外观近似的图标替代。
3. 头图带透明边缘时，其下的底色取页面背景，不填品牌色。
4. 源图在目标 media 缺失时，从 Android 仓库对应密度目录（如 drawable-xxhdpi）复制原图并引用（重名时加模块前缀），或登记资源缺口；应用 res 里没有、由主题或框架控件提供的图标，从本机 SDK platforms/android-<api>/data/res 复制原图：Holo 主题的在 drawable-<密度> 下，是位图（返回箭头的位图名带 _am 后缀，drawable/ 下的同名 XML 只是包装）；Material 主题的返回箭头和溢出按钮（ic_ab_back_material、ic_menu_moreoverflow_material）在 drawable/ 下，是靠 android:tint="?attr/colorControlNormal" 着色的白色矢量，转 SVG 后按图标所在处生效的 colorControlNormal 设 fillColor（窗口动作栏里取 actionBarTheme 覆盖层的值）；其他控件图（如 CheckBox 勾选框）按各自矢量的 tint 取色。不拿其他模块同类、近名或带 1/2 后缀的图标顶替，不用 Polyline、Circle 或字形自绘平台图标，也不因缺图把“图标 + 文字”结构降成纯文字。 AppCompat/Material 库主题提供的图标（如 homeAsUp 的 abc_ic_ab_back_material）不在 SDK 平台目录，从对应版本库 AAR 的 res/drawable 取矢量转 SVG；矢量声明 autoMirrored=true 的加 matchTextDirection(true)（安卓应用 manifest 没声明 android:supportsRtl="true" 时 RTL 语言下也不镜像，这种情况不加）；路径填充为白色、靠 android:tint="?attr/colorControlNormal" 着色的（abc_ic_ab_back_material 即是），转 SVG 后按图标所在处生效的 colorControlNormal 设 fillColor（窗口动作栏里是 actionBarTheme 覆盖层设的 colorControlNormal：AppCompat 主题和 MaterialComponents、Material3 的亮色主题（含 DarkActionBar）的覆盖层把它设为 textColorPrimary，MaterialComponents、Material3 的暗色主题用 ThemeOverlay.MaterialComponents.ActionBar.Surface，设为 colorOnSurface 乘 0.6 透明度），这不属于第 5 步说的二次着色。系统符号只在库资源确实取不到时使用，并登记为替代。
5. 原图自带颜色时不再 fillColor 二次着色；替代图颜色不对时先确认是否选错资源。现有代码里对应 Android 位图的 SymbolGlyph 或 Unicode 占位要换成原图，只改颜色或字号不算对齐；交付记录写明每个资源来自 Android 原图复制还是工程既有资源，不把近名资源称作原图。
6. 源端用文字字符充当按钮图形或直接显示字符（粗体“-”“+”、Text 中的 emoji）时按原字符用 Text 实现（短横也可用 Divider/Rect 画同形），symbol 库没有同形名称时不选外形不同的近似 symbol（如 minus_circle）；“只用 symbol、不把 emoji 当图标”一类规则约束的是源端矢量图标资源的映射，与源端字面字符冲突时在规格中记录，不替换。

- 〔适用情境 / 做法第 1 步〕鸿蒙 resources 下的限定词目录与 base 一样可有 media 子目录，其中文件同样编译并分配资源 ID、按类型和名称访问（$r('app.media.<名>')）；屏幕密度限定词与 dpi 范围：sdpi (0,120]、mdpi (120,160]、ldpi (160,240]、xldpi (240,320]、xxldpi (320,480]、xxxldpi (480,640]
- 〔做法第 1 步〕鸿蒙资源匹配：先在与设备状态匹配的限定词目录里找，只有没有匹配的限定词目录、或其中找不到该资源时才去 base；移动国家码和网络码、语言、文字、横竖屏、设备类型、颜色模式这些限定词必须与设备状态完全一致，目录才参与匹配；屏幕密度不要求一致，有多个密度目录时优先向上取最接近的，否则向下取最接近的（所以只放在密度目录里的资源在任何密度上都取得到，只放在 dark 目录里的在浅色模式下不参与匹配）
- 〔适用情境 / 做法第 1 步〕构建时对只在限定词目录（如 xldpi/media）而 base/media 没有的资源报 “does not have a base resource” 警告，构建照常通过；这些只在 xldpi、xxldpi 的 media 里的 png 用 $r('app.media.<名>') 引用，在设备上正常显示
- 〔做法第 1、4 步〕安卓密度常量 DENSITY_XHIGH = 320、DENSITY_XXHIGH = 480、DENSITY_XXXHIGH = 640，对应鸿蒙的 xldpi (240,320]、xxldpi (320,480]、xxxldpi (480,640]：drawable-xhdpi 的图落在 xldpi，drawable-xxhdpi 的图落在 xxldpi
- 〔做法第 2、4 步〕鸿蒙 media 目录支持的图片格式：.jpg、.png、.gif、.svg、.webp、.bmp
- 〔做法第 4 步〕Holo 主题（android-30 与 android-37.0 相同）：Theme.Holo 的 homeAsUpIndicator 为 @drawable/ic_ab_back_holo_dark，Theme.Holo.Light 为 ic_ab_back_holo_light；drawable/ 下这两个 XML 是 <bitmap android:src="@drawable/ic_ab_back_holo_*_am" android:autoMirrored="true"/> 包装，位图 ic_ab_back_holo_dark_am.png、ic_ab_back_holo_light_am.png 在 drawable-mdpi、hdpi、xhdpi、xxhdpi 四档（没有 xxxhdpi）。溢出按钮 Widget.Holo.ActionButton.Overflow 的 src 为 ic_menu_moreoverflow_holo_dark（Light 版为 _light），drawable/ 下是只含一项的 selector，指向同四档密度目录里的位图 ic_menu_moreoverflow_normal_holo_dark.png / _light.png；Theme.Holo.Light 的 actionOverflowButtonStyle 为 Widget.Holo.Light.ActionButton.Overflow，Theme.Holo.Light.DarkActionBar 把 homeAsUpIndicator 设回 ic_ab_back_holo_dark、actionOverflowButtonStyle 设回 Widget.Holo.ActionButton.Overflow（即 dark 版图标）
- 〔做法第 4 步〕Material 主题（android-30 与 android-37.0 相同）：Theme.Material 的 homeAsUpIndicator 为 @drawable/ic_ab_back_material，Widget.Material.ActionButton.Overflow 的 src 为 @drawable/ic_menu_moreoverflow_material；两者都是 drawable/ 下的矢量：24dp×24dp、viewport 24×24、路径 fillColor 为 @color/white、android:tint="?attr/colorControlNormal"；返回箭头另有 android:autoMirrored="true"，pathData 为 M20,11L7.8,11l5.6,-5.6L12,4l-8,8l8,8l1.4,-1.4L7.8,13L20,13L20,11z，溢出按钮没有 autoMirrored
- 〔做法第 4 步〕窗口动作栏的根布局（screen_action_bar.xml 等）带 android:theme="?attr/actionBarTheme"。应用主题和 Activity 主题都没另设 actionBarTheme、colorControlNormal、textColorPrimary 时：Theme.Material 与 Theme.Material.Light 的 actionBarTheme 为 ThemeOverlay.Material.ActionBar，Theme.Material.Light.DarkActionBar 为 ThemeOverlay.Material.Dark.ActionBar，两个覆盖层都把 colorControlNormal 设为 ?attr/textColorPrimary；解析结果：Theme.Material 下 #ffffffff，Theme.Material.Light 下 #de000000（黑 × 0.87），Light.DarkActionBar 下为白色、透明度取 primaryContentAlpha（覆盖层不设，按 Theme.Material.Light 为 0.87）
- 〔做法第 4 步〕动作栏以外，主题没另设 colorControlNormal 时 Material 主题取 ?attr/textColorSecondary：Theme.Material 为 #b3ffffff（白 × 0.7，android-30 至 37.0 相同）；Theme.Material.Light 在 android-30 为 #8a000000（黑 × 0.54），android-33 起为 #99000000（黑 × 0.60）。AppCompat 主题（appcompat 1.1.0、1.8.0）和 material 的 MaterialComponents 主题（1.4.0、1.14.0）都不另设，colorControlNormal 取 ?android:attr/textColorSecondary，API 21 起就是平台主题的上述值；Material3 主题（material 1.14.0）另设了 android:textColorSecondary，取值不在本条
- 〔做法第 4 步〕Material 主题下 CheckBox 的 button 为 ?attr/listChoiceIndicatorMultiple → btn_check_material_anim（animated-selector，勾选态 btn_checkbox_checked_mtrl、未勾选 btn_checkbox_unchecked_mtrl）；这些矢量路径填黑色、android:tint="@color/control_checkable_material"，该颜色列表禁用时（不论勾选与否）取 ?attr/colorControlNormal 再乘 ?attr/disabledAlpha（Theme.Material 0.30、Theme.Material.Light 0.26），启用且勾选时取 ?attr/colorControlActivated（Theme.Material 与 Theme.Material.Light 里为 ?attr/colorAccent），启用未勾选时取 ?attr/colorControlNormal（android-30 与 37.0 这几个文件相同）
- 〔做法第 4 步〕appcompat 1.1.0 至 1.8.0 的 res/drawable/abc_ic_ab_back_material.xml 相同：24dp 矢量、android:autoMirrored="true"、android:tint="?attr/colorControlNormal"、路径 fillColor 为 @android:color/white，pathData 与平台 ic_ab_back_material 相同。Base.V7.Theme.AppCompat 的 homeAsUpIndicator 为 @drawable/abc_ic_ab_back_material，但 values-v21 的 Base.V21.Theme.AppCompat 把它改成 ?android:attr/homeAsUpIndicator：API 21 起、应用没另设 homeAsUpIndicator 时取到的是平台主题的 ic_ab_back_material（外形与库里那份一致）
- 〔做法第 4 步〕appcompat 1.1.0 至 1.8.0、应用主题没另设 actionBarTheme 和 colorControlNormal 时：Theme.AppCompat.Light 的 actionBarTheme 为 ThemeOverlay.AppCompat.ActionBar，Theme.AppCompat.Light.DarkActionBar 为 ThemeOverlay.AppCompat.Dark.ActionBar，两者都把 colorControlNormal 设为 ?android:attr/textColorPrimary；解析结果：Light.DarkActionBar 的动作栏里为 #ffffffff，Theme.AppCompat.Light 的动作栏里为 #de000000，Theme.AppCompat（暗色）的 textColorPrimary 为 #ffffffff；Theme.AppCompat.DayNight（.DarkActionBar）日间按 Theme.AppCompat.Light（.DarkActionBar）、夜间按 Theme.AppCompat 取。material 1.4.0、1.14.0 的 Theme.MaterialComponents.Light 沿用上面 AppCompat 的覆盖层（动作栏里 #de000000），Light.DarkActionBar 用继承 ThemeOverlay.AppCompat.Dark.ActionBar 的 ThemeOverlay.MaterialComponents.Dark.ActionBar（#ffffffff），暗色 Theme.MaterialComponents 改用 ThemeOverlay.MaterialComponents.ActionBar.Surface，colorControlNormal 为 colorOnSurface（#FFFFFF）× 0.6 = #99ffffff；Material3 主题另设了 android:textColorPrimary 和 colorOnSurface，取值不在本条
- 〔做法第 4 步〕安卓 VectorDrawable、BitmapDrawable 只在 isAutoMirrored() 为 true 且 drawable 的布局方向为 RTL 时镜像；View 的布局方向只在应用支持 RTL（ApplicationInfo.hasRtlSupport()，即 manifest 写了 android:supportsRtl="true"）时才按父布局和语言解析为 RTL，否则保持 LTR，此时 autoMirrored 的图标在 RTL 语言下也不镜像
- 〔做法第 4 步〕ImageAttribute.matchTextDirection(value: boolean): ImageAttribute（首段 @since 7）：默认 false；为 true 时图片跟随系统语言方向，在 RTL 语言环境下镜像翻转显示；组件参数为 AnimatedDrawableDescriptor 时不生效
- 〔做法第 4、5 步〕ImageAttribute.fillColor 有三个重载：fillColor(value: ResourceColor)（首段 @since 7）、fillColor(color: ResourceColor | ColorContent)（@since 15）、fillColor(color: ResourceColor | ColorContent | ColorMetrics)（@since 20）；只对 SVG 图源生效，默认不填充，设置后替换 SVG 中所有可绘制元素的填充颜色（API 21 起 supportSvg2 为 true 时改为依赖 SVG 的 fill 属性，fill 为 'none' 的不生效）；png 等位图要改色用 colorFilter
- 〔做法第 6 步〕DividerAttribute.strokeWidth(value: number | string)（首段 @since 7）：分割线宽度，默认 1px、默认单位 vp，不支持百分比；水平分割线时它控制线的高度（优先级低于通用属性 height），垂直分割线时控制宽度（低于 width）
- 〔做法第 3 步〕布局根和外层容器都没写 android:background 时，页面底色来自 Activity 主题的 windowBackground；应用主题没另设时 Theme.Material 为 ?attr/colorBackground = #ff303030，Theme.Material.Light（含 Light.DarkActionBar）为 #fffafafa（android-30 至 37.0 相同）。库主题：Theme.AppCompat、Theme.AppCompat.Light 与之相同（appcompat 1.1.0、1.8.0，API 21 起取平台主题的值；DayNight 日间同 Light、夜间同暗色）；MaterialComponents（material 1.4.0、1.14.0）API 21 起暗色为 #ff121212、Light 为 #ffffffff；Material3 随 material 版本变：1.8.0 Light #fffffbfe、Dark #ff1c1b1f，1.12.0 与 1.14.0 Light #fffef7ff、Dark #ff141218（中间版本未核）
