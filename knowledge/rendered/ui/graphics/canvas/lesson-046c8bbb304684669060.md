# 把预烘焙位图改为每帧矢量绘制前，保留位图隐含的取值时机与缩放语义：烘焙时读取的状态留快照，setBounds 拉伸的全部属性按比例缩放

## 何时使用

渲染实现阶段，用每帧矢量绘制替代源端预渲染的背景位图或 tile 位图缓存，并准备声称“行为等价”时

## 适用情境

源端在 onSizeChanged 等时机把受状态字段控制的元素（如首启说明）和圆角底、数字等烘焙进 Bitmap，onDraw 只贴图，或在出生、合并动画中用 setBounds((int)…) 整体拉伸、按 int 位移绘制；这些状态在位图生成后仍会被其他流程改写；目标改为 Canvas 每帧 roundRect、fillText 等矢量绘制。

## 原因

位图把生成时刻的状态和整体缩放一起固化：生成后再改字段不影响显示，拉伸时圆角、字号、基线修正、描边同比缩放，边界经 (int) 截断。改为每帧读实时字段、只缩放文字、保留浮点坐标后，元素集合、顺序与颜色都对，元素出现与消失的时机、动画中的形状却变了。

## 做法

1. 逐一列出缓存构建函数读到的可变状态、缓存的重建时机，以及位图生成后还有哪些写者改这些状态；在目标对应的尺寸或布局入口给它们留快照，绘制时读快照。快照依赖首次初始化写入（如异步就绪后才开局）时，布局入口加“引擎已就绪”门控，未就绪下一帧重试。
2. 源端用 setBounds 或矩阵拉伸位图时，按 s = 绘制宽 / 烘焙尺寸 统一缩放烘焙内容的全部属性（圆角半径、字号、基线修正、描边），dp 圆角先换成当前画布单位再乘 s；边界与位移按源式的 (int) 向零截断，用 Math.trunc。
3. 决策已批准离屏位图加 drawImage 时优先沿用该路线，它天然保留这些语义；改走每帧绘制时，把取值时机与缩放的处理写进交回的决策缺口。

## 可选检查

- 需要确认时，按源端流程切换状态（如首启 → 新开局 → 重建视图）对照元素出现与消失；出生（比例 0→1）与合并（比例 >1）各取一帧，核对边界为整数、圆角等于基准圆角乘比例。

来源支持：2 张卡 · 1 次迁移 · 1 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 做法第 1 步〕安卓 View.onSizeChanged 在布局过程中视图尺寸变化时才调用（刚加入视图层级时旧尺寸按 0 传入）；只在这里重建的位图，内容固定为那一刻读到的状态
- 〔做法第 1 步〕ArkUI Canvas 的 onReady 在 Canvas 组件构造完成后触发，从这时起可以在画布上绘制
- 〔原因 / 做法第 2 步〕安卓 Drawable.setBounds 的四个参数都是 int，drawable 在 draw() 时画进这个矩形；拉伸位图时位图里烘焙的圆角、文字和描边随边界整体缩放
- 〔做法第 2 步〕Math.trunc 去掉小数部分（向零取整），Math.floor 取不大于参数的最大整数，两者在负数时结果不同（如 -1.5 分别得 -1 和 -2）
- 〔做法第 2 步〕源端出生、合并动画里 setBounds 和 int 位移的表达式在合并扩张、反向位移时会出现负数，Java 的 (int) 强转在这些位置向零截断
- 〔做法第 2 步〕CanvasPath.roundRect（API 20 起）的 radii 按画布上下文的长度单位解释，不写时为 0（直角）；radii 数组为空、多于 4 个元素或含负值时属于非法参数
- 〔做法第 3 步〕CanvasRenderer.drawImage 的五参数形式按 dw、dh 把整张图缩放到目标矩形，图里的圆角和文字随之等比缩放；三参数形式不给绘制尺寸
