# Canvas 字体串按注册字族名原样引用、不加源端没有的 bold；字体参与测宽布局时，首次布局前确认字体已就绪

## 何时使用

规格提取与渲染实现阶段，为源端自定义字体制定 ArkUI Canvas 的 ctx.font 串格式，并安排字体注册与首次 measureText 布局的先后时

## 适用情境

源端以 Typeface.createFromAsset 同步装载单一字面（如 Bold）的字体文件并 setTypeface 给 Paint，文本测宽参与布局计算；目标用 font.registerFont 注册字族，在 Canvas 中以 ctx.font 串引用并 measureText。Canvas 的字体串从 API 20 起才能引用注册过的自定义字体（只能在主线程用），工程最低 API 低于 20 时这条的做法不成立。

## 原因

源端字体同步可用、字面本身已是粗体；目标的字体串格式或注册时序不对时，Canvas 静默回落系统字体，测宽驱动的字号与布局随之改变，编译与粗看截图都不报错。来源工程实测：给字族名加引号的串在首次布局时都回落系统字体，去掉引号后仍有一次冷启需等待数十毫秒字体才可用；叠加源端未请求的 bold 还可能触发合成加粗。

## 做法

1. 字体串写成 `${size}px FamilyName`：字族名用注册名、不加引号；单一字面的字体文件按 normal 引用，不叠加源端没有的 bold/italic。
2. 首次测宽布局前做就绪检查：同字号下注册字族与 sans-serif 的 measureText 宽度不同即视为就绪；未就绪按帧重试，超时（如 1s）记日志后用系统字体继续。依赖布局结果的页面几何经布局完成回调同步，不在尺寸回调后立即同步读取。
3. 规格写明“首次测宽/布局前字体必须可用”，不把字体映射只归为字形风险交给视觉兜底。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 原因〕安卓 Typeface.createFromAsset 同步构建并返回 Typeface，返回后马上可用于 Paint 测宽；asset 里找不到该字体文件时抛 RuntimeException
- 〔原因 / 做法第 2 步〕Canvas 的 font 从 API 20 起支持注册过的自定义字体（只能在主线程用）；用 uiContext.getFont().registerFont 注册是异步的，调用后立即绘制可能不生效；也可以用字体引擎 text.FontCollection.getGlobalInstance() 的 loadFontSync 同步注册，用其他 FontCollection 实例注册可能不生效
- 〔做法第 1 步〕画布 font 串语法是 'font-style font-weight font-size font-family'，各项可选，font-size 支持 px、vp 且必须带单位；没设 font 时为 'normal normal 14px sans-serif'；文档示例里自定义字族名直接写在串尾、不加引号（如 "bold 30vp HarmonyOS_Sans_Thin_Italic"）
- 〔做法第 1 步〕Canvas font 串里给注册字族名加引号时，无论写不写 bold，新进程首次布局 measureText 得到的都是系统字体的度量
- 〔做法第 2 步〕字族名不加引号、按 normal 字重引用时，6 次冷启动的首次布局都得到注册字体的度量，其中一次在注册后约 37ms 字体才可用
