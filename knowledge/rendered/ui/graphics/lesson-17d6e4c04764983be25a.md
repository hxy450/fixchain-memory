# 修共享绘制分支里某一指标的显示差异时，按源端通用规则统一实现，不写单 key 特判；先列出落入该分支的全部指标

## 何时使用

界面绘制修复阶段，按用户对某一指标的视觉反馈，调整多个指标共用的 Canvas 绘制分支（线宽、描边、填充样式）、且源端该参数不按指标区分时

## 适用情境

源端同类图形由通用 helper 按统一规则绘制（如 drawBars 中 STROKE/FILL_AND_STROKE 与 strokeWidth ?: 3f 像素），不区分指标 key；目标多个指标经分派落到同一绘制分支，用户只报告其中一个与源端粗细不一致。

## 例外与边界

- 源端对个别指标显式传了不同的线宽或样式（如构造绘制配置时单独给出 strokeWidth、isStroke）的，那份按指标的差异照源端保留，只把走默认值的指标统一到默认规则
- 源端线宽为 0（hairline，最细线）时，目标 lineWidth 不能写 0（0、负数按默认值处理），写成 1 个物理像素对应的值（vp 上下文用 px2vp(1)）

## 原因

单 key 特判只修好被报告的指标，同一分支的其他指标仍保留来源已失效的旧值；源端参数本来不按 key 区分时，特判本身就偏离了源端，后续还会被当成“有意设计”继续沿用。

## 做法

1. 修单个指标的显示差异前，先确认源端该参数是否按指标区分；是通用 helper 的默认值时，在目标共享分支按同一规则统一实现，并用 px2vp 把源端像素值换成 vp（Canvas 上下文按默认的 vp 单位构造时；以 LengthMetricsUnit.PX 构造的上下文直接用像素值），不写 key === '某指标' ? 新值 : 旧值。
2. 改共享分支前按分派条件列出落入该分支的指标，核对旧值注释所称的服务对象是否仍走此分支；旧值失去来源时整体回归源端规则，并请用户复测受影响的其他指标。
3. 定位用的临时诊断可以按 key 加条件，样式修复本身不与诊断条件绑定；交付前检索并清除诊断日志与残留特判。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 做法第 1 步〕安卓 Paint.setStrokeWidth 的宽度按画布像素计，在 Style 为 STROKE 或 FILL_AND_STROKE 时用于描边；传 0 为 hairline（最细线）模式
- 〔适用情境〕安卓 Paint.Style 在应用没有另设时为 FILL；STROKE 只描边，FILL_AND_STROKE 填充加描边
- 〔做法第 1 步〕Canvas 上下文的 lineWidth 文档写默认值 1（px）、默认单位 vp；不支持 0 和负数，0、负数和 NaN 按默认值处理
- 〔做法第 1 步〕CanvasRenderingContext2D 构造时不传 unit 按 LengthMetricsUnit.DEFAULT，即长度按 vp 解释；传 PX 时按 px 解释，配置后不能更改
