# Compose 的显隐、内容切换、尺寸与条目位移动画（AnimatedVisibility expand/shrink、AnimatedContent + SizeTransform、animateContentSize、animateItem）逐项落为 ArkUI 动画，不以透明度渐变或直切代替

## 何时使用

规格提取与界面实现阶段，把 Compose 显隐、内容切换、容器尺寸与列表条目的动画翻译成 ArkUI 时；规格已写“animateTo 高度过渡 / expandVertically 等价”而准备换成其他转场时

## 适用情境

源端用 AnimatedVisibility(enter = expandVertically, exit = shrinkVertically)、AnimatedContent(transitionSpec … using SizeTransform)、Modifier.animateContentSize，或 LazyColumn/LazyRow 条目上的 Modifier.animateItem()；目标用 if/else 条件渲染、TransitionEffect 与 animateTo 实现；流程允许把视觉差异登记为近似或留给后续核验。 源端 AnimatedVisibility 没写 enter/exit 时默认就是淡入加展开、收起加淡出（Column 内为 expandVertically / shrinkVertically，Row 内为 expandHorizontally / shrinkHorizontally，其余为 expandIn / shrinkOut），同样属于本条。

## 例外与边界

- 决策记录以编号批准省略该动画，并写明差异验收
- 源端显式只写 fadeIn / fadeOut（没有 expand、shrink、slide，也没有 animateContentSize、SizeTransform）时，源端本就只做透明度变化、容器尺寸随之直接变化，目标端挂透明度转场就是对的，不额外加高度或位移动画

## 原因

这些动画里，节点自身的出现方式只是一部分，容器高度的变化、相邻内容的推移和条目位移来自尺寸与布局动画；只给节点挂 TransitionEffect.OPACITY 或直切时，节点会出现，但容器高度跳变、下方内容瞬移。写者把它们当作可省的“视觉细节”且不登记，下游就无从发现。

## 做法

1. AnimatedVisibility 的 expand/shrink：承载容器的高度要在 0 与内容高度之间过渡，可在 animateTo 中改变容器的显式高度（目标值取实测内容高度）并配 clip(true)；被插入或移除的节点按源 enter/exit 另挂透明度、位移等 transition，不只挂 TransitionEffect.OPACITY。源码没写 animationSpec 时按 Compose 默认值换算曲线（expand/shrink 与 fadeIn/fadeOut 默认 spring(StiffnessMediumLow 400, dampingRatio 1)，ArkUI 写 curves.springMotion(2π/√400, 1.0)），不自定 200ms 一类 tween；fadeIn/fadeOut 包住的小元素（如徽标）同样挂淡入淡出转场，不用 if 瞬显。
2. animateContentSize 与 SizeTransform：把引起内容尺寸变化的状态更新放进 animateTo，让容器尺寸从旧值过渡到新值；AnimatedContent 的新旧内容用随目标状态变化的 key（if/else 分支或键化 ForEach）承载，分别挂入场、出场转场（如上下滑入滑出），方向条件取自源 transitionSpec；SizeTransform(clip = false) 时过渡期间不裁切内容。
3. animateItem：List 的 ForEach 用稳定键，数据增删放进 animateTo，ListItem 挂插入/删除转场，其余条目的位移随之过渡；删除由持久化写入后经数据流回推触发时，先完成写入，再在 animateTo 中改变驱动显示的状态，不在动画闭包外同步置 false。
4. 本步确实做不了时，按动画逐项登记缺口（哪种动画、源参数）交给有写权的后续步骤，不以“视觉细节”省略，也不只写透明度近似。

来源支持：3 张卡 · 2 次迁移 · 2 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 未用。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因 / 做法第 1 步〕TransitionEffect.OPACITY 只做透明度转场：出现时 0→1、消失时 1→0，等同 TransitionEffect.opacity(0)，不带尺寸或位置变化
- 〔做法第 1、2、3 步〕UIContext.animateTo 对闭包里的状态改动引起的属性变化自动生成过渡动画
- 〔做法第 1、2 步〕属性动画 animation 只对写在它前面的属性方法生效；写在它后面的属性变化直接跳变到目标值；组件构造器参数（如 Column 的 space）不支持动画
- 〔做法第 1 步〕clip 默认 false；设为 true 时裁掉子组件超出本组件边界的部分
- 〔做法第 1 步〕curves.springMotion 的时长由弹簧参数和先前速度决定，不看 animation、animateTo、pageTransition 的 duration
- 〔做法第 1 步〕curves.springMotion 的 response 是一次完整振荡的时长，单位秒，默认 0.55（传 ≤0 时按 0.55）；dampingFraction 默认 0.825（传 <0 时按 0.825），1 为临界阻尼
