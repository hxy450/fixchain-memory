# 写 SDK 调用前按本地 .d.ts 核对成员名、所属类型、调用链每一跳与返回可空性：不能编译时如此，可编译时也不凭记忆写、靠编译门兜底

## 何时使用

页面或组件实现阶段，在禁止编译的转换批次里写组件构造选项、属性方法参数、需实现的 SDK 接口，或 UIContext、状态存储一类调用时；或在可编译的修复轮里准备凭记忆写组件属性名、指望编译门报错兜底时；或因记不清 SDK 是否提供某能力，准备放弃规格或映射指定的组件 API、改用换了结构或交互的替代写法时

## 适用情境

转换派工禁止编译或构建，映射参考与规格只给组件、接口名而不给成员签名；写者准备凭记忆填写选项字段名、参数类型、接口方法名或链式调用，或只看到一行 grep 命中的声明；本机 SDK 的 ets/component、ets/api 下 .d.ts 可以读取。也包括修复或接线 worker 访问平台对象字段（如 BundleInfo 的包名字段）、填写 SDK 回调类型或命令常量时，凭 Android 命名或记忆书写。 也包括派工要求颜色、尺寸一律经 $r 资源绑定，或写者参照同批并发生成、尚未编译的兄弟页与 rg 检索到的零散用法改写参数（如给 blur、Swiper.itemSpace 传 $r，给 onClick 加 ClickEvent.stopPropagation，把 Text 换成 SymbolGlyph 后沿用单值 fontColor）。

## 原因

禁编译只推迟错误，不会消除错误：记忆中的字段名、接口成员名与所属类型常与当前 SDK 不符，写后自检若只核 API 版本号或链尾方法，不存在的字段、错误的接口成员、并不存在的中间一跳和可空返回都会留到编译门；业务页尚未接入可达图时，常规构建还会跳过这些文件。来源同一批并行转换者分别写出菜单项的 startImage、Slider.blockSize(number)、IDataSource.getTotalCount()、UIContext.getResourceManager()、UIContext 上的 openMenu/closeMenu、AlertDialog 参数里的 builder，并直接使用 AppStorageV2.connect 的返回值；其中有人写前已自述没把握，有人 grep 到声明行就按文件名推定了所属类型。另一应用的修复轮凭记忆给 TextInput 写 caretWidth，自述“若不支持编译门会报错”，编译门随即报属性不存在，返工后才查声明改用 caretStyle。

## 做法

1. 对本文件新引入、且未在已编译代码里出现过的 SDK 成员，写前用脚本批量查声明，不逐个手工翻 .d.ts 文件：先列出要查的名字（组件属性方法、选项对象字段、接口成员、import 的名字、枚举成员），自己写一个脚本在本机 SDK 的 ets/component/*.d.ts、ets/api/*.d.ts 里找每个名字的声明（import 的名字对照 ets/kits 下对应 kit 的导出表；@hms 模块和 HarmonyOS 专有的 kit 在同级 hms/ets 的 api、kits 下），打印它所属的类型或接口和那一行签名，并报出对不上的（名字不存在，或所写的类型连同它继承的父类型、接口里都没有）；报出来的逐处回到声明确认再写，打印出的签名逐个看成员名、选项对象字段与必填项、参数类型和返回类型，返回带 undefined 或 null 的按第 3 步先判空。链式调用中间一跳的返回类型、泛型参数这类要类型推断才看得出的，按第 2 步逐跳查声明，可编译时再用编译结果补充确认，不代替写前查声明。有知识核验 skill 时也可以用它。禁止编译不等于禁止读声明。 因没把握而从方案里去掉的 SDK 能力同样要查声明：查到声明就回到规格指定的写法；确实查不到才降级，并在报告里逐项写出与源端的交互差异（拖动起点、点击命中、测量口径），不写“行为等价”。
2. grep 命中声明行后向上找到最近的 class/interface，确认成员属于哪个类型；同一个 d.ts（如 @ohos.arkui.UIContext.d.ts）包含多个类，不按文件名推定归属。链式调用逐跳核对，例如组件内解析字符串资源走 getUIContext().getHostContext()（可能为 undefined，先判空）再取 resourceManager.getStringSync($r('app.string.<名>').id)（传 Resource 对象的重载自 API 20 废弃；组件在中间码 HAR 或字节码 HAR 里取 HAR 自身的字符串时，按资源 ID 取要 compatibleSdkVersion 配成 23 及以上、并在本模块 AbilityStage 的 onCreate 之后才正常，否则因 ID 无效抛异常（按名字取的 getStringByNameSync('<名>') 不经资源 ID）），UIContext 本身没有 getResourceManager()。
3. 声明返回 T | undefined 的接口先判空再读写，AppStorageV2.connect 即使传了 defaultCreator 也一样；实现 ambient 接口时按接口体逐个成员实现，例如 LazyForEach 的 IDataSource 用 totalCount()、getData()、registerDataChangeListener()、unregisterDataChangeListener()，调用点统一用接口成员名。
4. 来源已确认的记忆误写可直接对照：MenuItem 选项的图标字段是 startIcon；Slider.blockSize 接受 SizeOptions（{ width, height }）；AlertDialog 参数没有 builder 字段且 message 必填。写后自检从实际写出的文件里重新提取新写的 SDK 成员名，再跑一遍第 1 步的脚本，报出的逐处回到声明复核；签名返回带 undefined 或 null 的逐处看调用点有没有先判空，链式调用逐跳看，不只核 API 版本号。
5. 访问平台对象字段前在 d.ts 核对字段名，只核函数签名不足以证明字段存在（BundleInfo 的包名字段是 name，不是 bundleName 或 packageName）；SDK 常量（回调类型、命令码）从已安装 SDK 的声明读取（如 Command.kCommandPay），或按 skill 用 instanceof 区分响应类型，不凭记忆写数值。
6. 可编译时同样先查声明再写，不把编译门当作 API 查询手段；例如 TextInput 没有 caretWidth，光标宽度与颜色用 caretStyle({ width, color })。
7. 资源绑定惯例只用于声明接受 Resource、Length、ResourceColor 的参数；blur 只收 number、Swiper.itemSpace 收 number|string，保留数值常量。参照同批尚未编译的兄弟页或 rg 到的零散用法时同样回到声明核对，并看清所在回调的事件类型（TouchEvent 与 ClickEvent 不同，ClickEvent 没有 stopPropagation），不用它覆盖自己与已编译页面一致的写法；换组件（如 Text → SymbolGlyph）时逐个核对沿用的修饰器签名，SymbolGlyph.fontColor 接收 ResourceColor 数组。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-28（提交 4d3e2aa3）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1 步〕鸿蒙 SDK 的 openharmony/ets 下，component/ 是 ArkUI 组件和通用属性、通用事件的声明（通用属性在 common.d.ts 的 CommonMethod 里，各组件的属性在各自文件的 <组件>Attribute 类里），api/ 是 @ohos.* 模块的声明，kits/ 是各 @kit.* 的导出表（列出每个 kit 从哪些 @ohos 模块导出哪些名字）；HarmonyOS 专有能力（如 @hms.*）在同级的 hms/ets 下。一个成员从哪一版开始有，看它声明前第一段注释的 @since。
- 〔原因 / 做法第 2 步〕@ohos.arkui.UIContext.d.ts 里声明了 UIContext、PromptAction、Router、Font、MediaQuery、UIInspector、OverlayManager、DragController、FocusController、MeasureUtils、ComponentUtils 等多个类。openMenu<T extends Object>(content: ComponentContent<T>, target: TargetInfo, options?: MenuOptions): Promise<void> 和 closeMenu<T extends Object>(content: ComponentContent<T>): Promise<void>（都自 API 18 起）、openCustomDialog（自 API 12 起）是 PromptAction 的成员，不是 UIContext 的；从 UIContext 取 PromptAction 用 getPromptAction(): PromptAction（自 API 10 起）。UIContext 上没有 getResourceManager。
- 〔做法第 2 步〕UIContext.getHostContext(): Context | undefined（自 API 12 起）；Context 上的 resourceManager: resmgr.ResourceManager；ResourceManager.getStringSync(resId: number): string（自 API 9 起）和 getStringSync(resId: number, ...args: Array<string | number>): string（自 API 10 起，格式化占位符）；传 Resource 对象的两个重载自 API 20 废弃，资源 ID 取 Resource 的 id: number 字段（如 $r('app.string.x').id）。
- 〔做法第 3 步〕AppStorageV2.connect<T extends object>(type: TypeConstructorWithArgs<T>, keyOrDefaultCreator?: string | StorageDefaultCreator<T>, defaultCreator?: StorageDefaultCreator<T>): T | undefined（自 API 12 起）：返回类型带 undefined，不论传没传 defaultCreator；key 已存在时返回已存的值，不存在时用默认构造器构造后返回；不指定 key 时用 type 的 name 作 key，第二个参数就当默认构造器。数据不在又没传默认构造器时，文档两处说法不同：参数表和返回值说明写返回 undefined，同一小节的说明第 2 条写「必须指定默认构造器，不指定将导致应用异常」，两种情况都要按着写（返回值先判空，数据可能还没存时传默认构造器）。同一个 key 连接不同类型的数据会导致应用异常。
- 〔做法第 3 步〕LazyForEach 的数据源接口 IDataSource（自 API 7 起）有四个成员：totalCount(): number、getData(index: number): any、registerDataChangeListener(listener: DataChangeListener): void、unregisterDataChangeListener(listener: DataChangeListener): void；没有 getTotalCount。
- 〔做法第 4 步〕MenuItem 的选项 MenuItemOptions 里，起始图标是 startIcon?: ResourceStr（自 API 9 起），文字是 content?: ResourceStr，用 HMSymbol 图标时是 symbolStartIcon?: SymbolGlyphModifier（自 API 12 起）；没有 startImage 字段。
- 〔做法第 4 步〕SliderAttribute.blockSize(value: SizeOptions): SliderAttribute（自 API 10 起），参数是 { width?: Length, height?: Length } 对象，不收单个 number。
- 〔做法第 4 步〕AlertDialog.show 的参数都继承 AlertDialogParam：message: ResourceStr 必填，title、subtitle 可选，没有 builder 一类放自定义内容的字段；自定义弹窗内容要用 CustomDialogController（CustomDialogControllerOptions.builder 传 @CustomDialog 组件）或 PromptAction.openCustomDialog。
- 〔做法第 5 步〕BundleInfo 的包名字段是 readonly name: string（自 API 9 起），BundleInfo 里没有 bundleName 或 packageName 字段；取本应用自己的 BundleInfo 用 bundleManager.getBundleInfoForSelfSync(bundleFlags: number): BundleInfo（自 API 10 起，import { bundleManager } from '@kit.AbilityKit'），bundleFlags 传 bundleManager.BundleFlag.GET_BUNDLE_INFO_DEFAULT 时也带 name。
- 〔做法第 6 步〕TextInput 没有 caretWidth 属性；光标宽度和颜色用 caretStyle(value: CaretStyle)（TextInput、Search 自 API 10 起，TextArea 自 API 12 起），CaretStyle { width?: Length; color?: ResourceColor }：width 不支持百分比，应用没有另设时为 '2vp'；color 应用没有另设时，文档只给了一个值 '#ff007dff'（蓝色），没写是哪种颜色模式下的、深色模式下是否不同；本机 SDK 声明里 CaretStyle.color 没写默认值，TextInputAttribute.caretColor 的注释只写 '#007DFF'，也没有深色下的值，深色下的值没查到——目标侧不设 color 时由系统默认决定，要设时用跟着深浅色切换的颜色资源（$r 引用的 color 资源）承载，不把 '#ff007dff' 写死。同时设 caretColor 和 caretStyle 的 color 时后设置的生效；自 API 12 起 caretStyle 的颜色同时用于光标和文本选择手柄，两者颜色一致。
- 〔做法第 7 步〕参数类型里能收 $r(...) 的是带 Resource 的类型：Length = string | number | Resource，ResourceColor = Color | number | string | Resource，ResourceStr = string | Resource（都自 API 7 起）；参数声明成 number 或 number | string 的不收 Resource。
- 〔做法第 7 步〕blur 的三个重载都只收数值：blur(value: number, options?: BlurOptions)（自 API 7 起）、blur(blurRadius: Optional<number>, options?: BlurOptions)（自 API 18 起）、blur(blurRadius: Optional<number>, options?: BlurOptions, sysOptions?: SystemAdaptiveOptions)（自 API 19 起），传 Resource 编译报错。Swiper 的 itemSpace(value: number | string)：number 按 vp；string 要显式写单位（如 '10px'），不写单位按 vp；不支持百分比；应用没有另设时为 0，设成小于 0 或超出 Swiper 宽度时按 0 处理。
- 〔做法第 7 步〕onClick(event: (event: ClickEvent) => void) 的 ClickEvent（继承 BaseEvent）有 preventDefault，没有 stopPropagation；stopPropagation 在 TouchEvent（onTouch 回调）以及 KeyEvent、MouseEvent、HoverEvent 上。TouchEvent.stopPropagation 只终止触摸事件往父组件冒泡：父组件的 onTouch 不再收到这次事件，但父组件上绑定的手势（如 TapGesture）仍照常接收和处理这次触摸；同一次触摸的 Down、Move、Up 不一致地拦截时，父组件可能只收到部分类型的事件。
- 〔做法第 7 步〕SymbolGlyphAttribute.fontColor(value: Array<ResourceColor>): SymbolGlyphAttribute（自 API 11 起）只收数组，Text.fontColor 那样的单个颜色值要包成 [颜色]。
