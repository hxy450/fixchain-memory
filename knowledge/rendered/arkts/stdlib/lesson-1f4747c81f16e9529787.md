# Java 集合迭代序、有符号 byte 比较与 switch 返回码按 Java 语义复刻：HashSet/HashMap 决定顺序时用桶序，byte 先换回 -128..127，只把源 case 列出的码判失败

## 何时使用

规格提取与切片实现阶段，转写依赖 Java 集合迭代序（keySet、toArray、new ArrayList<>(set)）、byte 与 int 字面量比较、按返回码 switch 分支的逻辑时

## 适用情境

源端用 HashSet/HashMap 的迭代序决定输出文件、尝试顺序、写入顺序或问题清单顺序；用 byte 变量与 0x81 一类 int 字面量比较；switch 只把部分返回码（如 2、-1）判为失败；目标准备用 JS Set/Map（插入序）、0–255 的 number 与相邻方法的 result !== 0 判定。

## 例外与边界

- 规格或决策明确不要求复刻集合迭代序，并在验收中写明
- 按实际构造的类型判断，不看变量声明成 Set/Map：源端构造的是 LinkedHashSet/LinkedHashMap（默认插入序）时，JS Set/Map 的插入序本来就一致，不改成桶序；TreeSet/TreeMap 按键排序；源端迭代后随即整体排序再输出的，按那次排序复刻即可，不需要桶序工具。

## 原因

JS Set/Map 按插入序迭代，Java HashSet/HashMap 按哈希桶序；Java byte 有符号，firstByte < 0x81 对 0x80–0xFF 的结果与无符号比较相反；把“非 0 即失败”套到只列部分失败码的 switch，会把源端判为成功的码当失败。来源中写者已意识到“顺序可能不同”仍放行，按无符号写比较却在注释里称与 Java 一致，并从相邻方法复制了 result !== 0。

## 做法

1. 源端集合迭代序决定输出时，验收写明按 Java 迭代序，实现用桶序工具复刻（键的 hashCode、HashMap 初始容量与扩容规则；new HashSet(集合)、new HashMap(容量) 这类构造的初始容量按参数算，与无参构造的 16 不同），不以插入序或 indexOf 保序替代，也不以“HashMap 本来无序”放过。
2. byte 与 int 字面量比较前把 0–255 的值换回 -128..127；用 0x80–0xFF 的样例核对与源码同样恒真或恒假。
3. 实现返回码分支时逐值对照源 switch：只把源码列出的 case 判失败，其余走 default 分支。

- 〔原因 / 做法第 1 步〕HashMap 对键先做扰动：null 键的 hash 为 0，其余为 h ^ (h >>> 16)（h 是键的 hashCode）
- 〔做法第 1 步〕HashMap 的桶下标是 (n - 1) & hash，n 是当前表长（2 的幂）
- 〔做法第 1 步〕应用构造 HashMap 时没有传容量和负载因子（无参构造）时，初始容量 16、负载因子 0.75；插入后 ++size > threshold 时扩容为两倍，扩容拆桶时同一桶内元素保持原相对顺序
- 〔做法第 1 步〕new HashSet() 背后是 new HashMap()（容量 16）；android-36.1 源码中 new HashSet(集合) 用 HashMap.newHashMap(max(集合大小, 12))，初始容量取 ceil(个数 / 0.75) 向上到 2 的幂；new HashMap(容量) 的表长取不小于参数的 2 的幂
- 〔原因 / 做法第 1 步〕HashSet.iterator 返回背后 HashMap 的 keySet().iterator()，遍历顺序就是 HashMap 的键遍历顺序
- 〔做法第 1 步〕HashMap 的迭代器按表下标从小到大找下一个非空桶，同一桶内沿 next 链依次返回
- 〔做法第 1 步〕String.hashCode = s[0]*31^(n-1) + … + s[n-1]，按 32 位 int 运算、溢出回绕
- 〔做法第 1 步〕Integer.hashCode 返回整数值本身
- 〔原因〕HashMap 不保证迭代顺序，也不保证顺序随时间不变（扩容会改变顺序）；JS Map/Set 则按插入序迭代
- 〔原因 / 做法第 2 步〕Java byte 取值 -128..127，与 int 字面量比较时按有符号提升为 int：b < 0x81 对任何 byte 都成立，b > 0xFE 恒不成立
- 〔做法第 1 步〕同一桶链长达到 TREEIFY_THRESHOLD（8）时，若表长小于 MIN_TREEIFY_CAPACITY（64）则扩容而不转树
