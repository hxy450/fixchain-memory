# Java 文本读行、split/trim、BOM、String.format、SimpleDateFormat/Calendar 的时区与周规则不用同名 JS API 近似：按 Java 语义集中实现兼容函数，未 setTimeZone 的格式化按构造时默认时区取本地字段

## 何时使用

页面转换和服务/VM 抽取阶段，把 Java 标准库的读行、切分、去空白、解码、数值格式化与日历计算翻译成 ArkTS 时；把 SimpleDateFormat 格式化毫秒值（含语义像时长的值）或格式化固定 epoch 的偏移探测翻译成显式算术时

## 适用情境

源码用 BufferedReader.readLine、String.split/trim、FileReader/InputStreamReader、String.format("%.2f", float) 或 Calendar.getInstance() 的 WEEK_OF_YEAR 处理文件行、编辑框文本、百分比与日期；目标准备用 JS 的 split/trim/toFixed、TextDecoder 或手写 ISO 周换算；派工可能写“与 readFileLineByLine 等价”“数值域同 Android”。 也包括 new SimpleDateFormat(pattern, Locale) 或 Calendar 未调用 setTimeZone 就格式化一个毫秒值（变量语义像时长，如 gameTime + hourOffset×3600000），或格式化 1970-01-01T00:01Z 按本地小时位探测偏移；目标准备“不经 Date/Intl”按 UTC 手工拆 h/m/s。第 2、3 步对应的是源端的默认写法：split 传了负数 limit 时保留末尾空串、传正数 limit 时最多切成 limit 段；String.format 显式传了 Locale（如 Locale.US）时按传入的区域输出小数点和数字。按源端实际传的参数实现，不统一成丢弃末尾空串或按默认区域输出。

## 原因

同名 API 语义不同：Java readLine 在最后一个终止符后不产生空行、split 丢弃末尾空串，JS split 保留；Java trim 只去 ≤U+0020，JS trim 还去 NBSP、U+FEFF；util.TextDecoder 默认（ignoreBOM 为 false）结果保留 BOM、设 ignoreBOM: true 才去掉，Java 读取器把它当普通字符；String.format 按 float、HALF_UP 与默认 Locale 输出小数点（fr、it 等为逗号），toFixed 不是；Calendar 的周首日与首周最少天数随区域变化，不等于 ISO。来源中这些近似分散在多个页面，又被服务抽取原样搬运：以换行结尾的文件多出空行、扇区文本被判为 5 行而报错、差异百分比丢了区域小数点、生产周的起止日偏移。未 setTimeZone 的 formatter 绑定构造时的默认时区，format 输出本地字段；按 UTC 拆 h/m/s 只在偏移为 0 的时区与源端一致，用当前 getRawOffset 代替对 1970 时刻的探测会丢掉历史偏移与夏令时。另一应用中召回摘要把本条压成“不用 Date/Intl 模板近似”，规格与实现都把对局时间写成了 UTC 纯时长。

## 做法

1. 在服务层集中实现一组 Java 兼容函数（readLines、split、trim、decode、formatFixed 等），所有服务、VM 与页面统一调用，不在各处各写近似实现。
2. readLine 按 \n、\r、\r\n 断行且最后一个终止符后不产生空行；split 丢弃末尾空串；trim 只去 ≤U+0020；解码保留 BOM 字符。
3. String.format("%.Nf", float) 按 float 运算、HALF_UP 舍入，并按默认 Locale 输出小数点与数字；Calendar.getInstance() 或 SimpleDateFormat(..., Locale.getDefault()) 按区域的 firstDayOfWeek 与 minimalDaysInFirstWeek（如 i18n Calendar）计算。
4. SimpleDateFormat/DateFormat/Calendar 未调用 setTimeZone 时，把 format 的输入当作时刻：在源端构造时机取 i18n.getTimeZone()，local = instant + tz.getOffset(instant) 后再拆 HH/mm/ss，输入值语义像时长也一样；“格式化固定 epoch 的本地小时位”一类探测用 tz.getOffset(该时刻) 复刻，不用当前 getRawOffset；时间显示类验收至少给一个非零偏移时区的样例。

## 可选检查

- 最小样例：内容为 "a\nb\n" 的文件按行读取应得 ["a","b"]；以换行结尾的文本 split 后不多出末尾空串
- UTC+8 时区下 gameTime=0 的格式化结果为 08:00:00，不是 00:00:00。

- 〔原因 / 做法第 2 步〕BufferedReader.readLine 以 '\n'、'\r'、'\r\n' 或文件尾结束一行，返回的行不含终止符；读到文件尾且没有读到字符时返回 null，所以最后一个终止符之后不再多出一行空串
- 〔原因 / 做法第 2 步〕String.split(regex) 等于 split(regex, 0)，结果里不含末尾的空串
- 〔原因 / 做法第 2 步〕Java String.trim 只去掉两端码点 ≤ U+0020 的字符；JS String.trim 去掉两端的空白符和行终止符，范围比 Java 宽
- 〔原因 / 做法第 2 步〕FileReader、InputStreamReader 读文件时把 BOM 当普通字符保留在结果里
- 〔原因 / 做法第 2 步〕util.TextDecoder 的 ignoreBOM 默认 false；文档写 true 表示忽略 BOM、false 表示解码结果包含 BOM；卡里观察到 TextDecoder 解码后 BOM 丢失，但卡里没记所用的构造和选项（行为以文档为准，设备上的实际结果待核）
- 〔原因 / 做法第 3 步〕String.format 没传 Locale 时用 Locale.getDefault(Locale.Category.FORMAT) 返回的区域
- 〔做法第 3 步〕Formatter 的 %f 不写精度时为 6 位；参数是 float 时取 Float.toString(float) 的十进制串，精度少于小数位数时按 HALF_UP 舍入
- 〔原因 / 做法第 3 步〕Formatter 按区域本地化数字：数字字形按区域的 zero digit 替换，小数点换成区域的 decimal separator（fr、it 等为逗号）
- 〔做法第 3 步〕intl.NumberFormat 的无参构造使用当前系统区域创建
- 〔原因 / 做法第 3 步〕java.util.Calendar 的周由 firstDayOfWeek 和 minimalDaysInFirstWeek（1–7）定义，两者取自区域数据；WEEK_OF_YEAR 的第一周是从 getFirstDayOfWeek() 开始、至少含 getMinimalDaysInFirstWeek() 天的最早 7 天
- 〔做法第 3 步〕i18n Calendar.getFirstDayOfWeek() 返回 1 代表周日、7 代表周六；而 i18n.System.getFirstDayOfWeek()（API 18 起）返回 WeekDay 枚举，周日为 7
- 〔原因 / 做法第 4 步〕SimpleDateFormat 构造时用 Calendar.getInstance(locale) 建内部日历，取构造当时的默认时区；没调用 setTimeZone 时 format 按这个时区输出本地字段；无参 GregorianCalendar() 同样用 TimeZone.getDefaultRef()
- 〔原因 / 做法第 4 步〕java.util.TimeZone.getOffset(long date) 返回该时刻加到 UTC 上得到本地时间的毫秒数，含夏令时；底层实现支持时返回历史上正确的偏移
- 〔做法第 4 步〕i18n.getTimeZone() 不传 zoneID 时取系统时区
- 〔做法第 4 步〕i18n TimeZone.getOffset(date) 的 date 是毫秒时刻（默认当前时间），返回毫秒偏移，处于夏令时时为原始偏移加夏令时偏移；getRawOffset() 返回时区的原始偏移（毫秒）
