# Java 文本读行、split/trim、BOM、String.format、SimpleDateFormat/Calendar 的时区与周规则不用同名 JS API 近似：按 Java 语义集中实现兼容函数，未 setTimeZone 的格式化按构造时默认时区取本地字段

## 何时使用

页面转换和服务/VM 抽取阶段，把 Java 标准库的读行、切分、去空白、解码、数值格式化与日历计算翻译成 ArkTS 时；把 SimpleDateFormat 格式化毫秒值（含语义像时长的值）或格式化固定 epoch 的偏移探测翻译成显式算术时

## 适用情境

源码用 BufferedReader.readLine、String.split/trim、FileReader/InputStreamReader、String.format("%.2f", float) 或 Calendar.getInstance() 的 WEEK_OF_YEAR 处理文件行、编辑框文本、百分比与日期；目标准备用 JS 的 split/trim/toFixed、TextDecoder 或手写 ISO 周换算；派工可能写“与 readFileLineByLine 等价”“数值域同 Android”。 也包括 new SimpleDateFormat(pattern, Locale) 或 Calendar 未调用 setTimeZone 就格式化一个毫秒值（变量语义像时长，如 gameTime + hourOffset×3600000），或格式化 1970-01-01T00:01Z 按本地小时位探测偏移；目标准备“不经 Date/Intl”按 UTC 手工拆 h/m/s。

## 原因

同名 API 语义不同：Java readLine 在最后一个终止符后不产生空行、split 丢弃末尾空串，JS split 保留；Java trim 只去 ≤U+0020，JS trim 还去 NBSP、U+FEFF；util.TextDecoder 默认（ignoreBOM 为 false）结果保留 BOM、设 ignoreBOM: true 才去掉，Java 读取器把它当普通字符；String.format 按 float、HALF_UP 与默认 Locale 输出小数点（fr、it 等为逗号），toFixed 不是；Calendar 的周首日与首周最少天数随区域变化，不等于 ISO。来源中这些近似分散在多个页面，又被服务抽取原样搬运：以换行结尾的文件多出空行、扇区文本被判为 5 行而报错、差异百分比丢了区域小数点、生产周的起止日偏移。未 setTimeZone 的 formatter 绑定构造时的默认时区，format 输出本地字段；按 UTC 拆 h/m/s 只在偏移为 0 的时区与源端一致，用当前 getRawOffset 代替对 1970 时刻的探测会丢掉历史偏移与夏令时。另一应用中召回摘要把本条压成“不用 Date/Intl 模板近似”，规格与实现都把对局时间写成了 UTC 纯时长。

## 做法

1. 在服务层集中实现一组 Java 兼容函数（readLines、split、trim、decode、formatFixed 等），所有服务、VM 与页面统一调用，不在各处各写近似实现。
2. readLine 按 \n、\r、\r\n 断行且最后一个终止符后不产生空行；split 丢弃末尾空串；trim 只去 ≤U+0020；解码保留 BOM 字符。
3. String.format("%.Nf", float) 按 float 运算、HALF_UP 舍入，并按默认 Locale 输出小数点与数字；Calendar.getInstance() 或 SimpleDateFormat(..., Locale.getDefault()) 按区域的 firstDayOfWeek 与 minimalDaysInFirstWeek（如 i18n Calendar）计算。
4. SimpleDateFormat/DateFormat/Calendar 未调用 setTimeZone 时，把 format 的输入当作时刻：在源端构造时机取 i18n.getTimeZone()，local = instant + tz.getOffset(instant) 后再拆 HH/mm/ss，输入值语义像时长也一样；“格式化固定 epoch 的本地小时位”一类探测用 tz.getOffset(该时刻) 复刻，不用当前 getRawOffset；时间显示类验收至少给一个非零偏移时区的样例。

## 可选检查

- 最小样例：内容为 "a\nb\n" 的文件按行读取应得 ["a","b"]；以换行结尾的文本 split 后不多出末尾空串
- UTC+8 时区下 gameTime=0 的格式化结果为 08:00:00，不是 00:00:00。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；安卓 Android SDK 源码 android-36.1。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 2 步〕Java 的 String.split(regex) 参数是正则（"."、"|"、\s+ 都按正则解释）；limit 为 0（单参数版本）时去掉结果末尾的全部空串，开头的零宽匹配不产生前导空串、开头的正宽度匹配会产生一个前导空串。JS 的 split 传字符串时按字面字符串切分。〔成立范围：对象：java.lang.String#split(String) 与 split(String, 0)。条件：分隔符含正则元字符，或文本以分隔符结尾（如以换行结尾的文件内容）。不成立的情形：split(regex, 负数) 时不去掉末尾空串。〕
- 〔原因〕鸿蒙 util.TextDecoder 的 ignoreBOM 缺省为 false，文档写明此时解码结果包含 BOM；设为 true 才去掉 BOM（文档示例 0xEF 0xBB 0xBF 0x61 0x62 0x63 在 ignoreBOM: true 下 decodeToString 得到 "abc"），而官方文档里的 TextDecoder 示例多数写了 ignoreBOM: true。〔成立范围：对象：util.TextDecoder.create(encoding, options) 及其 decodeToString。条件：要像 Java FileReader/InputStreamReader 那样保留 U+FEFF。不成立的情形：照抄文档示例写了 ignoreBOM: true 时 BOM 被去掉。〕
- 〔做法第 3 步〕java.util.Formatter 的 %.Nf 在 double 的十进制数字串（与 Double.toString 同一算法 FloatingDecimal）上按 HALF_UP 舍入到 N 位；float 参数先拓宽成 double 再走同一路径（Formatter 的 print(float) 直接转成 double），所以舍入依据的是 (double)f 的数字串而不是 Float.toString(f)：例如 1.005f 按 %.2f 得 "1.00"（Float.toString 为 "1.005"，(double)f 的数字串为 1.0049999952316284），0.45f 按 %.1f 得 "0.4"。String.format(format, args) 用 Locale.getDefault(Locale.Category.FORMAT)，小数点和数字字符都取该区域的十进制符号（decimalSeparator、zeroDigit）。〔成立范围：对象：String.format / Formatter 的 'f' 转换。条件：源端没有显式传 Locale。不成立的情形：String.format(Locale.US, …) 一类显式区域时按该区域输出。〕
- 〔做法第 4 步〕new SimpleDateFormat(pattern, locale) 在构造时调用 Calendar.getInstance(locale)，取的是构造当时的 TimeZone.getDefault()（android-36.1 的实现里 locale 带 -u-tz- 扩展时改用该时区）；之后不调用 setTimeZone，format 都按这个时区输出本地字段。〔成立范围：对象：SimpleDateFormat(String, Locale)、Calendar.getInstance(Locale)、Calendar.getInstance()。条件：源端没有调用 setTimeZone。不成立的情形：源端 setTimeZone(TimeZone.getTimeZone("UTC")) 后按 UTC 输出。〕
- 〔做法第 3 步〕Android 的 Calendar.getInstance(locale) 固定返回 GregorianCalendar（不按 locale 选佛历、和历），firstDayOfWeek 与 minimalDaysInFirstWeek 随 locale 变化；鸿蒙 i18n.getCalendar(locale, type) 的 type 缺省取“区域默认的历法”，getFirstDayOfWeek 返回 1 代表周日、7 代表周六。〔成立范围：对象：用 i18n.getCalendar 复刻 Calendar.getInstance(locale) 的周规则和年份字段。条件：没有传 type。不成立的情形：显式传 type 为 'gregory' 时两端都按公历。另：i18n.System.getFirstDayOfWeek()（API 18+）返回 WeekDay 枚举，周一为 1、周日为 7，与 Calendar.getFirstDayOfWeek 的 1=周日、7=周六编码不同，两者不能混用。〕
- 〔做法第 4 步〕鸿蒙 i18n.getTimeZone(zoneID?) 不传 zoneID 时取系统时区；TimeZone.getOffset(date?) 返回该时刻的偏移，单位毫秒，处于夏令时时为原始偏移加夏令时偏移，date 单位毫秒、缺省为当前系统时间；getRawOffset() 只返回原始偏移（毫秒，不含夏令时）。〔成立范围：对象：@ohos.i18n 的 TimeZone。条件：复刻未 setTimeZone 的 formatter，或复刻“格式化固定 epoch 探测偏移”。不成立的情形：getOffset 不传 date 时按当前时间计算，不等于目标时刻的偏移；应用调用过 TimeZone.setAppDefaultTimeZoneById（26.0.0 起）时，getTimeZone() 不传 zoneID 仍按文档取系统时区，而未指定时区的日期时间格式化改用应用默认时区，要与之一致须用 TimeZone.getAppDefaultTimeZone()。〕
