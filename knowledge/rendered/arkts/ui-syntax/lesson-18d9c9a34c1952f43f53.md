# justifyContent/alignItems 只属于 Column/Row/Flex：替换容器头时连同尾部修饰链核对，Stack 的内容对齐用 alignContent

## 何时使用

界面实现阶段，替换容器类型（如把 Column 改成 Scroll 包裹内容）或为 Scroll、Stack 等容器设置内容对齐时

## 适用情境

页面把占位 Column 改成 Scroll 包裹内容而补丁只替换了容器头，或把 Compose Box(contentAlignment)、FrameLayout 居中布局迁成 Stack，并在容器修饰链上写 justifyContent、alignItems。

## 原因

Scroll、Stack 的属性类型上没有 justifyContent/alignItems，编译报 Property 'justifyContent' does not exist on type 'ScrollAttribute'/'StackAttribute'。来源中一处补丁只替换了 Column() { 及子项，尾部的修饰链留下来落到 Scroll 上；另一处派发失败后改为本地实现，未加载布局参考就在 Stack 上写了 justifyContent。

## 做法

1. 替换容器头时把原容器尾部整条修饰链纳入同一补丁逐项核对：Column/Row 专属的 justifyContent、alignItems 移到内部 Column 或删除，只保留 layoutWeight 等通用属性。
2. Stack 的内容对齐写 Stack({ alignContent: Alignment.X })（不写即居中）；迁移 Box(contentAlignment) 时按此映射；源端 Box 没写 contentAlignment（Compose 默认 TopStart）或 FrameLayout 的子视图都没写 layout_gravity（默认顶部、起始侧）时写 Alignment.TopStart，不留空；只有部分子视图写了 layout_gravity 时，Stack 仍写 Alignment.TopStart，写了的子视图用 layoutGravity（API 20 起）单独设置。

来源支持：1 张卡 · 1 次迁移 · 1 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；安卓 Android SDK 源码 android-36.1（android.widget.FrameLayout）；androidx.compose.foundation:foundation-layout-android 1.10.3、1.12.0。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 2 步〕Compose 的 Box 不传 contentAlignment 时默认 Alignment.TopStart（子项放在顶部起始角）；ArkUI Stack 的 alignContent 在应用没有另设时默认 Alignment.Center，两边默认值不同。〔成立范围：对象：androidx.compose.foundation.layout.Box 的 contentAlignment 参数，对应 Stack 的构造参数或属性 alignContent。条件：已核 foundation-layout-android 1.10.3 与 1.12.0（字节码里 Box 的默认参数分支取 Alignment.TopStart）；Stack 的 alignContent 传非法值也按 Center 处理。不成立的情形：源端 Box 显式写了 contentAlignment 时按其值映射，与默认值无关；Stack 上写了通用属性 align 时与 alignContent 效果一致，两者以后设置的为准。〕
- 〔做法第 1 步〕Scroll 上的通用属性 align（子组件在其绘制区域内的对齐方式）在应用没有另设时为 Alignment.Center：Scroll 的子组件小于 Scroll 本身时（如内容不足一屏）居中摆放，而不是从顶部排起。〔成立范围：对象：Scroll 容器及其唯一子组件，常见于把原 Column 改成 Scroll 包住内容之后。条件：Scroll 上没有设置 .align。不成立的情形：在 Scroll 上显式设置 .align（如 Alignment.Top）时按设置值。依据是文档说明（通用属性 align 的生效组件列表含 Scroll，默认值 Alignment.Center）。〕
- 〔适用情境〕FrameLayout 的子视图没写 android:layout_gravity 时按 Gravity.TOP | Gravity.START 摆放（顶部、起始侧）；每个子视图的位置由它自己的 layout_gravity 决定。〔成立范围：对象：android.widget.FrameLayout 的直接子视图，FrameLayout.LayoutParams.gravity 为 UNSPECIFIED_GRAVITY 时。条件：已核 android-36.1 源码。不成立的情形：子视图写了 layout_gravity（如 center）时按其值；对应到 Stack，不写 alignContent 的默认是居中而不是顶部起始。〕
- 〔做法第 1 步〕应用没有另设时：Column 的 alignItems 为 HorizontalAlign.Center、justifyContent 为 FlexAlign.Start；Row 的 alignItems 为 VerticalAlign.Center、justifyContent 为 FlexAlign.Start；Flex 的 alignItems 为 ItemAlign.Start、justifyContent 为 FlexAlign.Start。〔成立范围：对象：Column、Row 的 alignItems/justifyContent 属性方法，以及 Flex 构造参数 FlexOptions 里的同名项（Flex 传异常值按默认值处理）。条件：删掉或挪走原链上的这两个属性后即按这些默认值排版。不成立的情形：Flex 交叉轴默认是起始对齐，与 Column/Row 的居中不同。〕
- 〔适用情境〕layoutGravity 单独设置某个子组件在 Stack 内的对齐，只在父组件是 Stack 时生效；Stack 同时设了 alignContent 或 align 时，该子组件按 layoutGravity 摆放，其余子组件仍按 Stack 的设置；传入异常值按 LocalizedAlignment.CENTER 处理。〔成立范围：对象：Stack 的直接子组件，常见于各子视图 layout_gravity 不同的 FrameLayout 迁成 Stack 时。条件：API 20 起提供。不成立的情形：用在 Column、Row 等其他容器的子组件上不生效。依据是文档说明。〕
