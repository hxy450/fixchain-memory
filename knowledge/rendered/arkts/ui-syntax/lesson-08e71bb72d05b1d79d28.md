# build() 与 @Builder 里每个组件、条件与循环渲染各占独立行：if/else 带花括号、块后不加分号，含组件语法的方法声明为 @Builder

## 何时使用

界面实现阶段，整页编写或重写 ArkTS 页面的 build() 与可复用组件片段，并在交付前自检语法时

## 适用情境

页面含卡片片段、加载/空/错误或有图/无图等条件渲染与 ForEach/Repeat 列表；写者倾向把组件树压成一个方法一行、用分号拼接，或把卡片写成普通 private 方法；生成期常不编译。

## 原因

声明式 UI 只接受组件语法与 if/else、ForEach/Repeat 等渲染控制；if 块后的分号构成空语句，普通方法里的组件、无花括号的 if 分支都会报 Only UI component syntax can be written here、';' expected 一类错误。来源中三个 UI 子代理写前都读到这些约束与多行模板，仍把首页、评价页、购物车页压成单行；两页编译失败，第三页被静态审查拦下重写。

## 做法

1. build() 与 @Builder 中每个组件、if/else 分支、ForEach/Repeat 各占独立行；if/else 一律带花括号，块后不加分号。
2. 方法体里出现 Column、Row、Text 等组件语法就声明为 @Builder，在 build()、ListItem、Repeat.each 中以 this.xxx() 调用；普通 private 方法只放数据逻辑。

## 可选检查

- 不能编译时检索右花括号紧跟分号、无花括号的 if/else 组件分支、未加 @Builder 却含组件尾随闭包的方法。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 2 步〕调用 @Builder 默认按值传参：把状态变量作为参数传入时，状态变量之后的变化不会刷新 @Builder 内的组件；只有恰好传一个参数且直接写成对象字面量（按引用传递），或用 UIUtils.makeBinding 包装（按回调传递）时才刷新；两个及以上参数时即使写成对象字面量也不刷新。〔成立范围：对象：组件内私有 @Builder 方法与全局 @Builder 函数的参数，在 @Component 和 @ComponentV2 中调用都按这套规则。条件：数据经参数传入；makeBinding 自 API 20 起可用；@Builder 里再调用 @Builder 时，每一层都按引用传递，最内层才会刷新；同时含按值和按引用的参数也不刷新。不成立的情形：组件内 @Builder 直接读 this.<状态变量>（不经参数）时照常刷新；@ComponentV2 中按值传 @ObservedV2 对象并改其 @Trace 属性，或按值传 @Local 的 Map、Set、数组并经 set、add、下标修改时也能刷新（按值传 number 等简单类型仍不刷新）。〕
- 〔做法第 2 步〕在 @Builder 函数内给参数本身重新赋值（简单类型参数，或把对象参数换成新对象）不报错、也不刷新；修改参数对象的属性会抛运行时错误（文档示例为闪退），从 API 23 起返回错误码 140109。〔成立范围：对象：组件内与全局 @Builder 的参数，常见于把原先会改动入参的普通方法改成 @Builder 时。条件：文档限制条件第 5 条笼统写修改参数属性会抛运行时错误，第 1 条和闪退示例写的是按引用传递（只传一个对象字面量参数）的情形。不成立的情形：参数是 makeBinding 传入写回调得到的 MutableBinding 时，可以在内部改 .value 并同步回调用方；声明为 MutableBinding 却没传写回调时，写 .value 会运行时报错。依据是文档说明。〕
