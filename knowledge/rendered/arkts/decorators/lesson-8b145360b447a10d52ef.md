# V2 组件成员装饰器裸写（@Local/@Param/@Once/@Event），@BuilderParam 的默认值只引用 @Builder 函数或方法

## 何时使用

界面实现阶段，在 @ComponentV2 自定义组件里声明 @Event 回调、@BuilderParam 插槽和状态字段时

## 适用情境

组件要向宿主暴露交互回调、提供带空默认的可选内容插槽；派工或 skill 只列出装饰器名单，写者准备凭记忆给装饰器补括号，或用箭头函数作插槽默认值；生成期不编译。

## 原因

@Event() 会被当成调用一个返回 void 的装饰器，编译报 Expected 2 arguments, but got 0 与 Type 'void' has no call signatures；@BuilderParam 只能由 @Builder 函数初始化，箭头函数默认值报 '@BuilderParam' property can only initialized by '@Builder' function。来源输入一律把 @Event 写成裸装饰器、只把 @Provider()/@Consumer() 标为需要括号，两个转换者仍凭记忆写出 @Event()；另一转换者的设计已写明默认值要引用空 @Builder，落盘却写成箭头函数，自检还判为合法。

## 做法

1. @Local、@Param、@Once、@Event、@Trace 裸写；只有 @Provider()、@Consumer()、@Monitor('path') 这类带参装饰器写括号。落盘前 grep '@Event()'、'@Local()'、'@Param()'，命中即改。
2. 可选插槽的默认值写成全局 @Builder function emptySlot() {} 或组件内的 @Builder 方法，再以 @BuilderParam slot: () => void = emptySlot 引用；新增的全局 @Builder 放在组件 @ComponentV2 装饰器之前，不插在装饰器与 struct 之间。
3. 这条只约束声明处的默认值；在调用方向子组件 @BuilderParam 传页面自己的 builder 时，箭头闭包包装仍是正确写法。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 3 步〕把组件自己的 @Builder 方法以 this.xxx 直接赋给子组件的 @BuilderParam 时，builder 里的 this 指向子组件：读到的是子组件的同名成员，父组件状态变化也不会刷新这段内容；用 () => { this.xxx() } 箭头函数包装后传入，this 仍指向父组件。〔成立范围：对象：@Component 与 @ComponentV2 自定义组件里引用了 this 的局部 @Builder 方法，经构造参数传给子组件 @BuilderParam 的情形。this 指向子组件的结论文档对 V1、V2 组件都给了示例；「父组件改状态不刷新」的常见问题示例是 V1 组件。不成立的情形：传全局 @Builder 函数（不依赖 this）时，直接传与箭头包装效果相同。〕
- 〔适用情境〕子组件调用 @Event 回调、父组件在回调里给数据源变量重新赋值后，父组件的值立即改变，但同步回子组件 @Param 是异步的：紧接在调用之后读 this.<该 @Param> 仍是旧值，新值在下一次渲染之前才同步回来。〔成立范围：对象：@ComponentV2 组件里经 @Event 回调请父组件改数据源、再由 @Param 回流的写法（如回调后立刻据 @Param 计算或打日志）。条件：父组件在回调里给传给该 @Param 的状态变量重新赋值（文档示例是 number）。不成立的情形：@Param 是类对象时子组件拿到的是数据源的引用，父组件只改该对象的属性（不整体替换）时，子组件经同一引用立刻读到新值；父组件回调不改数据源时 @Param 一直不变；@Param 加了 @Once 时数据源的变化被拦截，之后也不会同步回来。〕
- 〔适用情境〕@Event 变量既没有本地默认值、父组件也没有传入时，系统自动生成一个空函数作为回调，调用它不报错也不做任何事；本地写了默认函数而父组件未传时，调用的是本地默认函数。〔成立范围：对象：@ComponentV2 里 @Event 修饰的回调类型成员。条件：父组件构造子组件时没有传这个参数。不成立的情形：@Event 修饰非回调类型的变量时装饰不生效。依据是文档说明。〕
- 〔做法第 1 步〕@Param 搭配 @Once 时只在组件初始化时从父组件同步一次，之后父组件改数据源不再同步到子组件；该变量同时可以在子组件本地修改并触发刷新。〔成立范围：对象：@ComponentV2 组件里同时加了 @Param 和 @Once 的成员（@Once 只在 @ComponentV2 中与 @Param 搭配使用）。@Once 只拦截数据源本身的变化，不影响 @Param 的观测能力。不成立的情形：只写 @Param 不加 @Once 时，父组件每次改数据源都会同步下来；@Param 是类对象时子组件持有与父组件同一个对象的引用，父组件只改该对象的 @Trace 属性（不整体替换）时子组件仍会看到变化。依据是文档说明。〕
- 〔做法第 1 步〕@Local 只观测被装饰的变量本身：装饰类对象时只有对象整体重新赋值会刷新，给成员属性赋值不刷新；数组的整体与元素项变化、Array/Set/Map/Date 经 API 调用的变化能被观测；类成员属性只有在类加 @ObservedV2 且属性加 @Trace（或对象经 makeObserved 包装）时才被观测。〔成立范围：对象：@ComponentV2 组件里 @Local 修饰的类对象、嵌套对象或对象数组的深层属性。条件：类没有 @ObservedV2/@Trace，也没经 makeObserved。不成立的情形：API 19 起 @Local 持有经 UIUtils.enableV2Compatibility 包装的 V1 @Observed 类实例（或 UIUtils.makeV1Observed 的结果）时，属性赋值也能刷新，具体规则（如 @Track 的影响）见状态管理 V1/V2 混用指导；API 19 之前 @Local 不能与 @Observed 类实例混用。〕
