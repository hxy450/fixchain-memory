# 写应用壳契约与实施计划时枚举源导航模块的全部入口能力（含深链解析与 scheme 注册），不做的登记 skip

## 何时使用

规格与计划阶段，编排者撰写应用壳/导航的共享契约、实施计划或压缩前交接摘要，确定路由表、启动入口与 module 配置要承载哪些源端导航能力时

## 适用情境

源导航模块除路由表和顶层 Tab 外，还含深链路由器（解析器类、深链基址常量、Manifest 的 scheme 或 App Links intent-filter）；目标用 Navigation + NavPathStack 字符串路由重建应用壳；契约先于 feature spec 写出并被后续实现重读，会话中途可能发生上下文压缩。

## 例外与边界

- 按第 2 步给入口 Ability 补 skills 的 uris 时，另建独立的 skill 对象承载深链，原有的入口 skill（entity.system.home、ohos.want.action.home）原样保留，不把 uris 写进它，也不因加深链改动它；源端有多个跳转场景时各建一个 skill。

## 原因

契约和交接摘要是后续实现最常重读的输入；源端能力在契约里被概括掉、又没有 skip 登记，实现与验证都不会再想起它。来源中编排者读到了深链路由器文件、深链基址常量和 intent-filter，决策账本也只把深链参数改为字符串键，契约却把应用壳记为 simple、锚点只列路由表与 Tab，压缩前的交接只列 Tabs 与权限；随后写出的路由表、入口 Ability 与 module 配置都没有深链。

## 做法

1. 写契约或实施计划前列出源导航模块的全部文件与入口能力（路由表、顶层 Tab、返回栈、深链解析与基址常量、Manifest 的 scheme 与 App Links），逐项写成契约锚点和目标符号；不做的写进决策账本 skip。
2. 决策只改变某项能力的形态（如深链参数改为字符串键）时，契约与计划保留承载它的入口：URI 解析函数、入口 Ability 的 onCreate/onNewWant 投递、module.json5 skills 的 uris；可能压缩上下文时，把这些入口写进交接摘要的剩余文件清单。

来源支持：2 张卡 · 2 次迁移 · 2 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-37.0 的平台资源。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 做法第 2 步〕Deep Linking 基于隐式 Want 的 uri 匹配查询、拉起目标应用；目标应用在 module.json5 的 skills 标签配置 uris，在 UIAbility 的 onCreate() 或 onNewWant() 中获取、解析传入的链接
- 〔做法第 2 步〕skills 下默认的入口 skill（entity.system.home、ohos.want.action.home）里不能配置跳转链接，要另建独立的 skill 对象；有多个跳转场景时各建一个 skill 对象
- 〔做法第 2 步〕深链 skill 的 actions 不能为空，为空会造成目标方匹配失败
- 〔做法第 2 步〕uris 里 scheme 除只配 type 外必填，host 只在配了 scheme 时生效，port 和 path | pathStartWith | pathRegex（三选一：全匹配、前缀、正则）只在 scheme 与 host 都配置时生效；API 18 起 scheme、host 参与隐式 Want 匹配时不区分大小写；uris 里这些字符串标签不支持用 $string 资源索引配置
- 〔适用情境 / 做法第 1 步〕安卓 intent-filter 的 <data> 里 path 要求路径全匹配，pathPrefix 为前缀匹配，pathPattern 为简单通配模式（另有 pathAdvancedPattern、pathSuffix）
- 〔做法第 2 步〕网址类链接（App Linking）的接收方 skills 要求：actions 含 ohos.want.action.viewData，entities 含 entity.system.browsable，uris 含 scheme 为 https 且 host 为域名的元素
- 〔做法第 2 步〕以 ohos 为前缀的 scheme 为系统预留，第三方应用组件的 scheme 以 ohos 开头时可能无法通过该 uri 拉起目标组件
- 〔做法第 2 步〕UIAbility 冷启动创建实例时走 onCreate；实例已经创建、又一次启动它时触发 onNewWant，不走 onCreate
- 〔做法第 2 步〕module.json5 里为入口 Ability 另配 actions 为 ohos.want.action.viewData、uris 为源端自定义 scheme 与 host 的独立 skill 时，外部的自定义 scheme 深链能拉起该 Ability
