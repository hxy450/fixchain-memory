# 用共享组件替换页面已实现片段前（关闭孤儿组件检查或按计划收口），完整读取被替换片段并逐项比对源码视觉与层叠、事件关系；组件不符先修组件，不覆写参数保留旧外观

## 何时使用

结构收口或接线阶段，为消除未被引用的公共组件（orphan component）发现，或按计划、切片要求用共享组件替换页面中已实现的片段时

## 适用情境

结构检查报告若干公共组件没有被任何页面引用，或计划要求页面改用某个共享组件（如统一弹窗组件）；修复者或收口者准备把页面里自写的标题行、图片、弹窗操作区等片段换成共享组件调用；共享组件与页面片段由不同 agent 生成，样式和变体完整度可能不一致，替换者可能只读了页面的部分行段。

## 原因

“被引用”只说明接线存在，不说明组件与源码一致：替换会把组件里的偏差带进原本正确的页面，或者为保持页面旧外观给组件传覆盖参数，改掉源码的形状。来源中同一修复者两次如此：用标题缺品牌色与尾部箭头的共享集合组件替换了页面自带的正确标题；把矩形 Image 换成默认圆形的共享图片组件时，又显式传 cornerRadius: 0 维持矩形。替换前只读页面的部分行段时，看不到局部实现比共享组件更完整之处，替换会直接删掉正确实现，让共享组件里有缺陷的变体成为运行时实际显示的版本。

## 做法

1. 替换前对照源码调用点，逐项比较页面片段与共享组件的颜色、尾部图标、形状与内边距，以及被替换片段中的层叠与事件关系（浮层与遮罩或点外关闭层的声明顺序、注释里的 z 序约束、点外与返回两条关闭路径），替换后这些关系仍要成立；组件与源码不符时先修组件再替换，不以替换换取检查通过。
2. 不为保持旧页面外观给共享组件传覆盖参数；只有源码在该调用点确有覆写时才传。
3. 替换前完整读取将被删除的调用及其引用的 builder，并与共享组件的对应变体比较；局部实现更完整时，先把差异补进共享组件或报告缺口，再切换调用。
4. 按“组件不符先修组件”改动组件内节点的几何或挂载方式（.overlay()、position、移出原容器）后，重核它与宿主保留的全尺寸层在重叠区的命中顺序，对面板项与面板外区域各点一次确认。
