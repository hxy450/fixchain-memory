# 按源端截图复刻控件尺寸时，先判断实测值是内容测量结果还是框架 min/max 约束：落在最小值上就写 constraintSize（并补框架上限），不写 width(实测值)；含多语言文案的控件用最长译文核对

## 何时使用

界面实现或返修阶段，按安卓实测几何复刻框架控件（弹出菜单、对话框、按钮）的宽高时

## 适用情境

实测宽度大于“文字宽 + 内边距”，源控件来自框架（如 AppCompat 弹出菜单项 minWidth 196dp、上限 max(屏宽/2, config_prefDialogWidth：手机常见配置 320dp，values-large 440dp，values-sw600dp 580dp)）；控件文字是有多种译文的字符串资源，而对比截图只取了英文。 前提是源端宽度由框架按内容测量、再受 minWidth / 上限约束；源端布局或样式本身把宽度写成固定 dp 值时，实测值就是设定值，目标端照写 width 不在这条的改写范围内。

## 原因

把最小宽写成固定 width，较长译文就会折行；英文截图对上不能证明约束正确。

## 做法

1. 实测值与“内容宽 + 内边距”比较：更大说明落在框架约束上，写 constraintSize({ minWidth, maxWidth }) 并按框架规则补上限，单行与省略按源端；注释写的是 minWidth/maxWidth 时，代码里同一元素不应出现 width(N)。
2. 复刻前列出该字符串在全部 values-*/strings.xml 的译文，用最长译文做两端对比截图。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36 的平台资源；android-36.1 的源码；androidx.appcompat:appcompat 1.1.0、1.8.0。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1 步〕应用没有另设 constraintSize 时，组件的尺寸约束默认是 {minWidth: 0, maxWidth: Infinity, minHeight: 0, maxHeight: Infinity}，即没有下限也没有上限
- 〔适用情境 / 做法第 1 步〕框架弹出菜单项布局 popup_menu_item_layout 与 AppCompat 的 abc_popup_menu_item_layout（1.8.0）根节点 ListMenuItemView 都写 android:minWidth="196dip"，宽度 wrap_content：196dp 是每项的下限，短文案的菜单项也按 196dp 宽显示
- 〔适用情境 / 做法第 1 步〕框架 StandardMenuPopup 的宽度上限 mPopupMaxWidth = max(Resources.getDisplayMetrics().widthPixels / 2, config_prefDialogWidth)，菜单内容宽按各项测量的最大值取（measureIndividualMenuWidth），不超过这个上限
- 〔适用情境 / 做法第 1 步〕config_prefDialogWidth 随屏幕配置变化：values 下 320dp，values-large 440dp，values-sw600dp 580dp；AppCompat 包内 abc_config_prefDialogWidth 在 1.1.0、1.8.0 取值相同（320 / 440 / 580dp）
- 〔做法第 1 步〕框架菜单项的标题 TextView 设 android:singleLine="true"、android:ellipsize="marquee"：标题只显示一行，超长文案不折行
- 〔做法第 1 步〕ArkUI Text 默认自动折行；设了 maxLines 后不超过指定行数，多出的文字按 textOverflow 处理，TextOverflow.Ellipsis 用省略号替换
