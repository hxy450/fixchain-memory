# 源码或布局引用的资源值（getColor/getDimension(R.x)、@dimen/@color）转成目标值时，按精确资源名在全部 res/values* 检索：近名资源不合并，限定词覆盖（values-land、values-w820dp/sw600dp 等）写成分支并在运行期按配置读取；目标没有对应限定词时跳过的是目录不是行为，被覆盖的键登记为运行时断点需求

## 何时使用

规格提取阶段，把源码中经资源 ID 读取的颜色、整数、尺寸、布尔值写进验收条目与精确取值表时；资源迁移阶段处理 values-w<N>dp、values-sw<N>dp、values-h<N>dp 等无法映射的限定目录时；实现阶段为引用 @dimen 的边距取值，或在规格字面量与运行期资源读取之间选择时

## 适用情境

源方法通过 getColor(R.color.X)、getResources().getInteger(R.integer.X) 等读取资源，或布局以 @dimen/X 引用；工程里有名称相近、用途不同的资源（如 yellow 与 square_yellow），或该资源在 values-land、values-w820dp 等限定词目录有覆盖值；目标页面支持横竖屏并在旋转后重算几何。也包括布局共用的 dimen（如 activity_horizontal_margin 10dp）在 values-w820dp 覆盖为 64dp，HarmonyOS 资源限定词没有可用宽度维度，资源转换规则要求整目录跳过并标 unmapped。

## 原因

只在报告里标 unmapped、写“由某任务处理”而不核对对方是否承接，被覆盖的值就没有承接方，各页只拿到基础值；按近名资源合并或只取 base 值，限定词条件下的取值同样丢失。

## 做法

1. 按精确资源名在全部 res/values*/ XML 中检索 name="X"（如 grep -rn 'name="X"' res/），把定义文件:行号与值写进验收和常量表；有限定词覆盖时写成“base 2 / land 1，运行期按当前配置读取”，并在验收中补一个限定词条件下的样例。
2. 同一工程有含相同词的多个资源时，色表按资源名逐行列出定义与消费点，不合并成一行；grep 结果被截断时确认目标条目已返回，否则按行号定点再读。
3. 实现时规格给字面量、而已迁移的同名资源键或 Base 契约里需要 context 的读取函数也存在时，先核对注释与资源值；不一致按源端资源实现并回报规格，旋转后重算几何的入口里做运行期读取。
4. 资源迁移跳过无法映射的尺寸限定目录前，逐键列出被覆盖的值（键名、基础值、覆盖值、阈值），在映射表与移交登记中写成“运行时断点”需求并指定承接方（共享窗口模型或具体任务）；写“由某任务处理”前先 grep 对方规格确认已有条目，没有就登记。
5. 界面实现引用 @dimen 时，查源 res 下全部 values-*/dimens.xml 是否覆盖同名键；有宽度覆盖就改用共享窗口模型按当前可用宽取值（窗口尺寸变化时重算），不用单值 $r；水平与垂直边距即使基础值相同也分开取。

来源支持：3 张卡 · 2 次迁移 · 2 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-28（提交 4d3e2aa3）；安卓 框架源码 android-36.1；资源匹配取 AOSP frameworks/base main 的 libs/androidfw/ResourceTypes.cpp（2026-11-27 取）。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 做法第 1、5 步〕安卓运行时对每个资源分别在定义了它的 res/values* 目录里选一份：values-w<N>dp 只在 Configuration.screenWidthDp ≥ N 时参与匹配，values-h<N>dp 只在 screenHeightDp ≥ N 时参与匹配，values-sw<N>dp 只在 smallestScreenWidthDp ≥ N 时参与匹配，values-land 只在横屏时、values-port 只在竖屏时参与匹配；几份都能匹配时按限定词的固定先后逐个比，先在靠前的一类上分出胜负的那份胜出（与这里有关的先后：sw 先于 w、h，w、h 先于横竖屏，横竖屏先于夜间模式、密度和 vNN），同为 sw<N>dp 的取 N 最大的，带 w、h 的取与当前宽高差之和最小的；匹配上的目录里没有定义这个资源时不算，都不匹配时用 values/ 里的。同一个 @dimen/X 或 getDimension(R.dimen.X)，旋转、分屏或换设备后可能取到不同目录里的值。
- 〔适用情境 / 做法第 4、5 步〕Configuration.screenWidthDp 是应用可用显示区的宽度（dp）：应用 targetSdk 为 35（VANILLA_ICE_CREAM）及以上时等于 WindowMetrics 的宽（含窗口避让区，取整到 dp），targetSdk 低于 35 时不含窗口避让区；分屏等多窗口下是应用窗口的可用宽，不是整块屏幕的宽；旋转后随之变。screenHeightDp 同样按这两种口径。smallestScreenWidthDp 是竖屏、横屏两个方向下 screenWidthDp 与 screenHeightDp 中的最小值，由这两个值算出、口径跟着它们，旋转时不变。
- 〔适用情境 / 做法第 4 步〕鸿蒙资源的限定词只有移动国家码和移动网络码、语言、文字、国家或地区、横竖屏（vertical、horizontal）、设备类型（phone、tablet、car、tv、wearable、2in1）、颜色模式（dark、light）和屏幕密度（sdpi 到 xxxldpi）八类，没有可用宽度、最小宽度、可用高度这类限定词；安卓的 values-land 对应 horizontal 目录，values-w<N>dp、values-sw<N>dp、values-h<N>dp 在资源目录里没有对应。
- 〔做法第 1、3 步〕鸿蒙取资源时先按当前设备状态找匹配的限定词目录，那里没有这个资源或没有匹配的目录时才取 base 目录；限定词目录里的移动国家码和移动网络码、语言、文字、横竖屏、设备类型、颜色模式要和设备状态完全一致才参与匹配，屏幕密度先向上、再向下取最接近的一档；几个目录都匹配时按 移动国家码和移动网络码 > 区域 > 横竖屏 > 设备类型 > 颜色模式 > 屏幕密度 的优先级取。
- 〔做法第 3、5 步〕运行期按资源 ID 读数值用 ResourceManager.getNumber(resId: number): number（import { resourceManager } from '@kit.LocalizationKit'；实例取 Context 的 resourceManager；resId 可取 $r('app.float.X').id；自 API 9 起有，传 Resource 的重载自 API 20 废弃），读到的是按当前设备状态匹配到的那份资源：integer 资源返回定义的原值；float 资源不带单位时返回原值，带 vp 或 fp 单位时返回换算后的 px（原值 × densityPixels），不是 vp。
- 〔做法第 5 步〕监听窗口尺寸用 Window.on(type: 'windowSizeChange', callback: Callback<Size>): void（自 API 7 起有，只能在主线程调用；窗口拖动或拖拽缩放后，不论大小变没变都会回调）；Size 的 width、height 单位是 px（整数）。启动时的当前尺寸可由 Window.getWindowProperties().windowRect 取，Rect 同样是 px。和 dp 阈值比较前要换成 vp：UIContext.px2vp(value: number): number（自 API 12 起有；全局函数 px2vp 自 API 18 废弃，改用 UIContext 的）。全屏的应用窗口包括状态栏和导航区域所在的部分，进入或退出沉浸式布局不改变窗口尺寸、只改变界面内容避不避开这些区域；窗口里被系统界面占掉的区域由 Window.getWindowAvoidArea(type: AvoidAreaType): AvoidArea（自 API 9 起）取，AvoidArea 的 leftRect、topRect、rightRect、bottomRect 是四个方向上的矩形（px），相关类型有 TYPE_SYSTEM（状态栏和三键导航栏）、TYPE_CUTOUT（挖孔）、TYPE_NAVIGATION_INDICATOR（底部导航区域，自 API 11 起）。
