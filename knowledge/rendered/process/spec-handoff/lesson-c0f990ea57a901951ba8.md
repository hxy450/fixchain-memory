# 只有查不到权威来源的生成期结论才标置信度与核验方法：平台或库默认值先查本机 SDK 与依赖 res，缺失的源码（未检出子模块、外部库）先按 .gitmodules 或依赖坐标取源；推断不写成字段级验收、硬性决策或带具体 dp 的视觉判据

## 何时使用

规格提取阶段，在没有真机布局 dump、生成期又不能编译或上设备时，写带具体 dp 的视觉验收判据、决策台账条目或 HARD 映射决策时；结论依赖平台默认值、未检出的子模块或外部库源码时

## 适用情境

基线快照由源码合成、bounds 为空，或 SDK 文档对关键语义只有模糊措辞、参考检索为空；规格准备写入源码字面尺寸、“近乎不可见、按源码保留”类结论，或把依赖未验证语义的映射定为 HARD，把可靠方案降为“真机偏色再回退”。也包括结论依赖 ?android:attr、@android:color、Widget 默认样式等平台值，或依赖未检出 git 子模块（.gitmodules 有 URL、目录为空）、外部库里的实现，规格准备凭记忆取值或“按读侧/调用点反推”并标推断置信。

## 例外与边界

- 已有真机 dump、截图测量或等价单测给出实测值

## 原因

合成快照只有声明树、没有度量，模糊的 SDK 措辞也推不出具体行为；推断一旦写成判据或 HARD 决策，实现者会原样复刻，验收也当已知设计。回退条件要求真机比对时，生成期根本不会触发。“标待核”还会被用来保留凭记忆的数值，而平台默认值在本机 SDK 可查；推断标签也挡不住下游照做：来源中按读侧反推的备份格式被写成逐字段相等的验收，实现照此产出与源端不兼容的数据，而子模块源码当场可取。

## 做法

1. 写结论前先找权威来源：平台默认值查本机 Android SDK platforms/android-*/data/res（themes、styles、colors、dimens、layout），依赖库默认值查 aar 的 res；源码缺失时按 .gitmodules URL（如 git submodule update --init）或依赖坐标取源核对。查得到就写实值并注明文件；只有设备度量这类生成期确实拿不到的才按以下各步处理。思考中带“我记得/也可能是”的数不以“AOSP 默认值”名义写入资源或报告。
2. 带具体 dp 的视觉验收条目标出置信度，注明依据是源码字面，并要求验证阶段用真机 dump 或截图量值取代。
3. “颜色近乎不可见”“保留源端缺陷”类结论先分辨成因是颜色还是布局度量，写成待真机核对项，不进决策台账当已知缺陷。
4. 映射依赖的语义在 SDK 与参考中都没有明确说明时不定 HARD，写明核验方法；已有不依赖该语义的等价方案（包括源码作者留下的实现提示）时，把它设为主方案，依赖未验证语义的方案设为回退。
5. 取不到的数据格式、协议或字段结构登记为阻塞缺口并写明核验方式（取源比对或真机导出比对），不写成字段级相等的验收，不让下游据推断实现。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；本条没有用到鸿蒙接口；OpenHarmony 文档 master 2026-11-28（提交 4d3e2aa3）；安卓 平台资源 android-36；依赖库 com.google.android.material:material 1.4.0、1.12.0、1.14.0，androidx.appcompat:appcompat 1.1.0、1.8.0（看包内资源的目录结构和 Platform.AppCompat 的 parent 链）。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1 步〕Android SDK 的 platforms/android-<N>/data/res 是 API N 框架自带的全部资源：主题在 values/themes*.xml（Material 系在 themes_material.xml），控件的框架样式（Widget.*）在 values/styles*.xml（styles_material.xml），平台色值在 values/colors*.xml（colors_material.xml），尺寸在 values/dimens*.xml，属性声明在 values/attrs.xml，控件自带布局在 layout*/ 下，颜色状态列表在 color*/ 下（主题属性常先指到这里，例：Theme.Material 的 textColorPrimary 是 @color/text_color_primary，一个按 enabled 状态取 ?attr/colorForeground 加透明度的选择器，要再解析下去才是色值）；同名资源还会在 values-night、values-land、values-sw600dp 等限定目录里重定义，实际取哪一份随设备配置（深浅色、横竖屏、屏幕宽度）而定，不同 N 的平台取值也可能不同。Theme.DeviceDefault 系（values/themes_device_defaults.xml）按文件里的说明是设备原生外观的别名、留给设备厂商定制，SDK 里是 AOSP 的取值，同一应用在不同设备上可能是不同的样式。
- 〔做法第 1 步〕依赖库的 aar 包里，默认限定的 values 资源（库的主题、样式、属性默认值、色值、尺寸）全部合并在 res/values/values.xml 一个文件里，每个限定目录也各合并成一个文件（如 res/values-v21/values-v21.xml、res/values-night-v8/values-night-v8.xml）；颜色状态列表不合并，仍是 res/color*/ 下各自的 xml；Gradle 下载过的 aar 在 Gradle 用户目录的 caches/modules-2/files-2.1/<group>/<artifact>/<version>/ 下（material 1.4.0–1.14.0、appcompat 1.1.0–1.8.0 都是这种结构）。应用继承库主题（AppCompat、MaterialComponents、Material3）时，没有另设的属性取值由应用所依赖那个版本的 aar 里这些文件中的主题 parent 链给出，库版本不同取值可能不同；这条链会接到 android: 开头的平台主题（例：appcompat 的 Platform.AppCompat 在 values/ 里 parent 是 android:Theme.Holo，values-v21、values-v25 里改经 Platform.V21.AppCompat、Platform.V25.AppCompat 接到 android:Theme.Material.NoActionBar），平台那一段的取值不在 aar 里，按设备的系统版本取平台资源。
