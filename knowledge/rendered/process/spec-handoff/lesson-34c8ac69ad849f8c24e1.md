# 共享组件挂到哪些页面，以源码里的宿主容器与 replace/add 调用为准；模板示例和上游说法不是依据

## 何时使用

功能索引、规格提取与接线规划阶段，确定播放条等 Fragment 型共享组件挂载到哪些目标页面时；页面转换阶段收到要求建槽位的派工时

## 适用情境

源端共享组件只被个别 Activity 布局的容器 replace/add 挂载；流水线模板示例、功能索引或派工里写着“主页(某组件)常驻”一类通用说法。

## 例外与边界

- 宿主布局里用 <fragment android:name=…>（或 class=…）标签、或带 android:name 的 FragmentContainerView 静态声明的 Fragment，没有代码里的 replace/add 调用也挂在该页：布局加载时由框架实例化并放进容器，同样算源码里的挂载依据，按源保留到对应目标页。

## 原因

模板示例来自别的应用，写进功能索引后会沿规格、接线计划和派工一路传成“事实”；后续的规格作者与页面转换者即使读到主布局没有对应容器，也倾向保住上游说法（把验收锚点改挂到无关源行、按“常见位置”放槽），目标页多出源端没有的组件。

## 做法

1. 每条“组件 → 页面”关系都先在源码中找到宿主布局的容器 id 与 replace/add 调用再写；找不到就不写。
2. 上游索引或派工声称某页有某组件、源布局却没有对应容器时，登记为待决冲突交裁决；不要把验收锚点改挂到无关源行来保住这条要求。
3. 页面转换时派工要求的槽位在源布局中不存在，在回报里列为冲突并请求确认，不自行放到“常见位置”。
