# 交付前要编译：项目根没有 hvigorw 时改用 DevEco 或命令行工具自带的 hvigorw、流水线构建入口；只跑读取源码文本的契约测试不算编译，仍不可用时按已知错误模式扫描并在回执写明未编译

## 何时使用

实现或修复阶段写完 ArkTS 代码、准备交付，而工程根目录找不到 hvigorw，或子任务约定把编译留给主线程统一执行时

## 适用情境

工程根目录没有 hvigorw 脚本，本机另有 DevEco Studio 自带的 hvigorw/hvigorw.js、command-line-tools/bin/hvigorw 或流水线封装的构建命令；子代理常以“缺 hvigorw，交收尾编译”结束。 也包括并行领域子代理只用 node --test 跑按文本或正则读取源码的 .cjs 契约，就以“交主线程统一构建”结束。

## 原因

不编译就交付，会把严格类型、声明顺序、声明式语法等错误留给用户逐个报回。来源中多个写者以项目根没有 hvigorw 收尾，而同一工程的其他会话已经用命令行工具或 DevEco 的 hvigorw 编译过。

## 做法

1. 项目根缺 hvigorw 时，查找并使用本机 DevEco Studio 或 command-line-tools 自带的 hvigorw（或流水线提供的构建命令）执行 assembleHap。
2. 构建仍不可用时，按本轮代码涉及的已知错误模式做针对性扫描（如内联对象字面量、static 初始化器引用的类位置、块后分号），并在回执写明未编译，不以“待收尾编译”结束。
3. 文本契约与正则断言不检查 ArkTS 类型：子代理交回前对自己新增或修改的 .ets 跑一次 CompileArkTS（并发时与其他构建错开），做不到就在回执列出未编译文件，并按本轮写法逐项自查（标识符键的 Record 字面量、与通用属性同名的成员、未 implements 的接口传参）。

来源支持：4 张卡 · 2 次迁移 · 2 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；DevEco Studio 自带 hvigor 6.23.6；OpenHarmony 文档 master 2026-11-28（提交 4d3e2aa3）；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1 步〕DevEco Studio 安装目录的 tools/hvigor/bin 下有 hvigorw（bash 脚本）、hvigorw.bat 和 hvigorw.js，同一安装目录的 tools/node 下自带 node.exe；两个启动脚本最后都是用 node 执行 hvigorw.js 并原样传参。bash 版 hvigorw：设了 NODE_HOME 时用 NODE_HOME/bin/node 或 NODE_HOME/node.exe，两处都没有可执行的 node 就报错退出，不再去找 PATH；没设 NODE_HOME 时用 PATH 里的 node，找不到就报错退出。NODE_HOME 设成 DevEco 的 tools/node 时，bash 版用其中的 node.exe，不依赖 PATH。Windows 的 hvigorw.bat：设了 NODE_HOME 时只检查 NODE_HOME 下有没有 node.exe，没有就报错退出，有也只是放行，真正启动时仍按命令名 node.exe 去 PATH 里找；没设 NODE_HOME 时先用 PATH 里的 node.exe 试跑 --version，失败就报错退出。所以 PATH 里没有 node.exe 时，不论设没设 NODE_HOME，hvigorw.bat 都起不来。
- 〔做法第 1 步〕assembleHap 是 hvigor-ohos-plugin 给 entry、feature 模块注册的打包 HAP 任务；hvigor 命令行的 -p（--prop）传额外属性，-p product=<名> 选工程 build-profile.json5 里 app.products 的哪一项，不传时取名为 default 的 product。
- 〔做法第 3 步〕ArkTS 编译在 hvigor 里是 CompileArkTS 任务，任务全名带模块和 target，如 :entry:default@CompileArkTS；测试代码对应 OhosTestCompileArkTS；HAR 模块对应 HarCompileArkTS（用开源 SDK 或 SDK 的 ets-loader 带 rollup 插件时，本机 SDK 6.1.0.105 属于后者），否则是 HarBuildArkTS。这一步失败时构建输出里有「hvigor ERROR: Failed :entry:default@CompileArkTS...」一行。
- 〔做法第 2 步〕同一文件里在类声明之前就 new 这个类或读它的静态属性，报「Class 'A' used before its declaration.」；这些用法写在函数体里时，只要函数在类声明执行之后才被调用就不报，函数在类声明之前就被调用时运行时报「A is not initialized」。
- 〔做法第 2 步〕类的 static 字段初始化式在类定义时就求值：服务类写 private static readonly x: S = AppStorageV2.connect(S, KEY, () => new S())!、而 S 声明在同一文件的服务类后面时，编译报「Class 'S' used before its declaration」，位置是 connect 的第一个参数；S 只出现在类型注解和方法体里的 new S() 时，类定义时不求值，不报。
- 〔做法第 2 步〕ArkTS 的对象字面量要显式标注类型，否则编译报错（规则 arkts-no-untyped-obj-literals，错误级，错误码 10605038）；文档同时写明某些场景下编译器可以根据上下文推断出字面量的类型，那时不用另标。不论标没标，下面这些都不能用对象字面量初始化：any、Object、object 类型的对象，带方法的类或接口，有带参构造函数的类，带 readonly 字段的类。
- 〔做法第 3 步〕自定义组件的基类 BaseCustomComponent 继承 CommonAttribute，width、height、animation 这类通用属性方法都是组件类自身的成员（CustomComponent 和 CustomComponentV2 都继承 BaseCustomComponent）；组件里再声明同名的成员（@Param、@Local、private 字段或 getter）时，编译报这个成员不能赋给 CustomComponent 的同名属性。
- 〔做法第 3 步〕ArkTS 不支持 structural typing（规则 arkts-no-structural-typing，错误级，错误码 10605030）：两个类型之间没有继承关系、也没有实现同一个接口时，公开成员再一致也不能互相赋值或传参；子类实例可以赋给父类类型的变量，反过来不行；两个类 implements 同一个接口时，声明成这个接口类型的变量之间可以互相赋值，两个类的实例也都能传给这个接口类型的参数；类实例要传给接口类型的参数，这个类要 implements 该接口（或继承实现了它的类）。
