# 派工的必读清单、阅读顺序与对接清单要覆盖任务依赖的语义来源（含已识别的框架约束与移交的验收条款），附加提速要求时也保留

## 何时使用

执行编排阶段，给页面转换、公共组件或收敛替换任务写派工，附加“效率纪律”、规定逐项“读源→立即写”的顺序，或列出要换成共享原语的对接点时；派发“对比源端还原某功能或页面”的实现、修复任务时；维护共享踩坑参考、在切片之间移交职责，或安排多个并行任务可能写同一共享组件时

## 适用情境

派工为提速限制阅读范围，或按组件清单规定阅读顺序；被写的组件依赖同目录的 Modifier 扩展、交互映射参考中的 API 语义表等外部定义；收敛任务要把页面私有写法替换成映射文档里的共享原语（阴影、排版、颜色映射函数等），并允许整文件重写。 也包括并行派发对比与实现子代理，派工没写源工程路径与对应 Screen/ViewModel/Service，实现者未读源界面就写页面。也包括某些框架约束只出现在某页注释、某个 skill 或移出方笔记里（一个组件只挂一个半模态、列表键须随实例变化、百分比宽度叠加外边距溢出、深色模式专项 skill、聚合器状态映射条款），接收方的写前输入里没有；以及多个并行转换任务都会创建同一共享组件。

## 原因

被限制阅读的实现者会跳过 API 语义参考、凭记忆定稿；被依赖的源排在消费组件之后读，写组件时拿不到默认参数（如描边宽度），读到后也未必回头修正。对接清单只点名部分共享原语时，未点名的私有写法会在整文件重写中原样保留，即使执行者读到了映射文档的对应小节。已识别的约束不在接收方写前输入中时，接收方会按逐属性映射或惯例合理地写错，同一偏差在多页重现；职责移交只记在移出方笔记里，承接方拿不到验收条款；并行任务各自整文件写同一共享组件会互相覆盖。

## 做法

1. 附加效率要求时，仍把与本任务交互、布局相关的语义参考（如命中测试控制表）列为必读。
2. 把被依赖的 Modifier 扩展等源文件排在消费它的组件之前，或要求随组件一起读取；允许后读时，要求读到后回查已写组件。
3. 派发收敛替换任务时，逐条列出映射文档里的全部共享原语及其对接点，要求执行者对读到的映射小节逐项对账、替换完成后再整文件重写。
4. 派发对比源端还原类任务时，派工写明源工程路径和该功能的 Screen/ViewModel/Service 文件，要求实现者写前自行读取；需要并行时先完成页面级行为对比（列表层级、模式状态、按钮可用条件），或把对比结论列为实现者的必读输入。
5. 已识别的框架约束写进页面转换共享的踩坑参考或派工模板，不只留在某页注释里；负责事件处理、数据接线的切片同样拿到相关的列表刷新、弹层、安全区条目，续跑或重试的 agent 重新加载完整参考，不只 grep 个别条目。返修与重写任务同样适用：派工只写“某 skill 可用”不算交付，把该 skill 中与本任务相关的硬规则内联进派工，或要求执行者读到对应小节并在回报中确认。
6. 转换器所用参考只有逐属性映射时，把布局组合规则（如 match_parent 加水平外边距不得直译）一并交付；涉及主题切换、系统栏、Canvas/Web 取色的切片把深色模式专项 skill 列入派工。
7. 源端某角色的职责移交给另一切片时，把对应验收条款写进承接切片的规格引用或派工，不只记在移出方笔记。
8. 多个并行任务会创建同一共享组件时指定唯一作者，或要求后来者先读已有文件再增量修改，不整文件覆盖。

## 可选检查

- 收敛后有疑问时，检索原生属性（如 .shadow(）确认只剩共享函数调用。
