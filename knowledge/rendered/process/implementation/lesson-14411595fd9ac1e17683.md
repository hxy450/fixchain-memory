# 源端看似缺陷或不够健壮的可观察行为照原样迁移并按次数核对：失败返回、异常作用域与副作用时序按源码，修正须作待批决策

## 何时使用

规格提取与切片实现阶段（迁移目标为行为等价、迁移原则要求保留原有缺陷与异常分支时），转写源码中看似缺陷、缺少防护或时序可疑的逻辑（未赋值导致的失败返回、无条件的结果回投、只在成功时退出的循环、在校验前置位的标志、整段一个 try 的循环、只捕获部分异常类型的 catch、以快照覆盖写回），或 lint、评审建议补取消、竞态、防御条目时

## 适用情境

迁移目标是行为等价，迁移原则（如默认策略文件）要求保留原有行为“包括缺陷、空点击和异常分支”，但续跑或补建的台账、派工里可能没有这条规则；写者认为源码“有缺陷”“不够确定”“不够健壮”，在源码笔记里写“源缺陷不移植/行为增强/防御/确定性取舍”，或规格为回应 lint 写入“页面销毁时丢弃迟到结果”“取消标志为唯一出口”一类源码没有的要求。 也包括源端每轮初始化或重开都 new 一个循环线程或定时器对象，停止只经保存最新实例的字段，重开不关闭已有对话框，规格准备以“每局新实例不释放＝不可观察的资源累积”收敛成单实例。也包括目标端的 try/catch、可空类型、系统托管提醒或缺少后台提示通道，诱使规格或实现写成“返回空对象继续”“return false 后继续发完成通知”“DB 现值优先、已删跳过”“只记日志”。 也包括 JS/TS 源端字符串与 URL 解析的求值结果：'?' + arr[1] 在缺分隔符时拼出字面 '?undefined'，只用真值判断决定是否跳转，注释说明的“未匹配交给常规路由”由 router 层兜底；规格准备把它们写成空串守卫或解析层的注册路由过滤。

## 例外与边界

- 决策记录明确批准修正某项原版缺陷；源端崩溃路径按已登记的例外处理

## 原因

用户可见结果（Toast、失败返回、跳转、文件名、写入顺序、弹窗个数、任务是否中止）随这些“修正”改变，对照源端运行就是偏差；规格里自创的防御会被实现照写成契约。只写在源码笔记里的取舍不会进入任何裁决。catch 子句只说明它捕获的类型：未被捕获的运行时异常（如 JSON 语法异常、对 null 返回值解引用）照样中止整个任务，已完成的部分保留、后续步骤与完成提示不发生，目标用宽 catch 或可空返回“兜底继续”就改变了结局。可观察次数由同时存活的循环、线程或定时器实例数决定：旧实例停止后，“每轮 new 不释放”才只是资源累积；旧实例仍在跑时，每个实例都向 UI 投递弹窗、音效与副作用，只沿单个循环的退出路径数弹窗会少算。 JS 拼接 undefined 得到的字面串、只判真值的跳转同样是可观察行为；规格把它们“规范化”后，接口、验收与示例互相矛盾，实现照规格落地。

## 做法

1. 规格提取时逐条对照源码表达式与注释，把实际结果按“源码锚点 + 触发条件 + 原结果 + 目标预期”写进验收；源码循环保留原退出条件，回投与副作用写明在页面结束后是否照常发生。 按次数写验收前先列出各操作序列下同时存活的循环、线程或定时器实例（如重开后仍留在下面的对话框再点重开、取消后再进入），次数＝每个实例的投递次数×存活实例数；去 Thread/Runnable 子类的构造调用点、保存实例的字段及其停止方法体、各对话框按钮回调里数，旧实例仍在跑时不以“不可观察差异”收敛成单实例。
2. 实现时照搬可观察结果并按次数核对：失败返回与提示、无条件回投后的 Toast/跳转/结束页面、标志的 set 与 clear 位置、字段在校验前赋值、异常作用域（整个循环一个 try 即首错停止）与遍历顺序，以及经数组引用原地修改调用方数据的副作用；循环内每次命中都弹窗或落盘时，目标的弹窗个数、确认次数与统计写入次数与源端相同，只保留代码结构而把信号收敛成布尔不算照搬。
3. 异常与写回按运行时语义迁移：列出该路径会抛出的未检查异常与实际结局再写验收和代码；源码只 catch 某些类型时，其余异常在目标中同样中止该任务，不并入宽 catch 后继续，对可能为 null 的返回值直接解引用的路径在目标中抛出终止；源端以快照覆盖写回的照快照写回；源端经平台通道给用户的提示（如服务层 Toast）在目标找等价通道实现，不降为只记日志。
4. 认为需要修正、加防御、补取消出口或改用“确定性”语义时，作为待确认决策写入决策台账或 handback 的 decision_gaps 交裁决，不先改代码；源码笔记、注释里的登记与无人值守流程的自动批准都不算批准。
5. 中断续跑判定规格已完成前，核对台账是否已有原版缺陷条目；补建台账时按迁移原则枚举缺陷实例，并把“保留原版缺陷”写进后续派工。
6. 转写 JS 字符串与 URL 解析时逐表达式保留求值结果（undefined 拼成字面串、split 取段越界得 undefined）；源码注释描述的兜底只说明由哪一层负责，不当作解析函数的返回条件；写完用缺分隔符、未注册路径、词中误切等 2–3 个输入按源码手算，核对接口签名、各验收文字与示例一致。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码（java.lang.Thread、android.os.Handler、org.json）。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔原因 / 做法第 3 步〕安卓端 Gson 解析抛出的 JsonSyntaxException 不在 catch (IOException) 的捕获范围内，对返回 null 的 findFile 结果解引用会抛 NullPointerException；这两种情况下导入任务都在该处终止
- 〔原因 / 做法第 1 步〕java.lang.Thread 的同一个实例只能 start 一次，再次 start 抛 IllegalThreadStateException；每次重开都要 new 新的线程对象，新线程启动不会让旧线程结束
- 〔原因 / 做法第 1 步〕源端重开时 new 新的循环线程、旧循环没有被停止的情形下，两个循环同时运行，判负对话框持续叠加；只有一个循环时，普通判负弹出 1～2 个判负对话框，随后叠加胜利对话框
- 〔做法第 1、2 步〕android.os.Handler#post 只把 Runnable 放进消息队列，到时在 Handler 所在线程执行，投递和执行时都不检查 Activity 是否已结束
- 〔原因 / 做法第 3 步〕org.json 的 JSONObject.getJSONArray 在键不存在或值不是 JSONArray（含 JSON null）时抛 JSONException，不会返回空数组
- 〔做法第 2 步〕Array 的 slice 返回原数组一段的浅拷贝新数组，对返回数组增删元素不影响原数组
- 〔做法第 2 步〕ResourceManager.getRawFileListSync 的声明只说明返回 rawfile 目录下的文件列表，没有规定列表的排列顺序
- 〔适用情境 / 做法第 6 步〕JS/TS 中 "?" + x.split("?")[1] 在 x 不含 '?' 时求值为字面串 "?undefined"
