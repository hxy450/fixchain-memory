# 把 RSA-OAEP + AES-GCM 网关加密移植到 cryptoFramework：生成器规格串只写算法与位数、加解密结果判空、Buffer 不套 Node 视图

## 何时使用

网络基础设施实现阶段，把 Android 端 RSA-OAEP 包裹会话密钥加 AES-GCM 加密的网关传输改写为 ArkTS cryptoFramework 与 buffer 调用时（含为通过编译改写同步 API 与类型的收敛步骤）

## 适用情境

源端用 X509EncodedKeySpec 解析“BEGIN PUBLIC KEY”PEM，以 RSA/ECB/OAEPWithSHA-256AndMGF1Padding 包裹随机密钥，用 AES/GCM/NoPadding 加密可能为空的请求体并解密响应；目标用 createAsyKeyGenerator/convertPemKeySync、Cipher.updateSync/doFinalSync 与 @kit.ArkTS buffer 实现同一协议。

## 例外与边界

- 不加 PKCS1 后缀只针对 createAsyKeyGenerator 的规格串；createCipher 的 RSA 加解密规格串仍要写全填充、摘要和掩码摘要（OAEP 与 MGF1 都是 SHA-256 时写 RSA2048|PKCS1_OAEP|SHA256|MGF1_SHA256），不能跟着一并删掉。

## 原因

协议理解正确不等于 API 映射正确：生成器规格串附加 PKCS1 后缀会拒绝 X.509 公钥；GCM 空明文加密与解密 final 可能返回 null；Node 式 .buffer/byteOffset 视图在 ArkTS Buffer 上不可靠。来源中这三处都在编译通过后于真机失败（生成器创建失败、读取 null 的 data、newByteLength 越界），其中判空兜底是为通过编译改用同步 API 时按 d.ts 非空签名删掉的。

## 做法

1. createAsyKeyGenerator 只写算法与按实际公钥得出的位数（如 'RSA2048'），X.509 PEM 直接交给 convertPemKeySync，不附加 PKCS1 等编码后缀。
2. Cipher.update/updateSync 与 doFinal/doFinalSync 的结果一律判空后再取 data，即使 d.ts 签名是非空 DataBlob；为通过编译改写同步 API 时保留原有兜底。
3. 需要独立 Uint8Array 时按 length 分配并拷贝，不用 new Uint8Array(buf.buffer, buf.byteOffset, …)；编译报 Buffer 属性不存在时先查 ArkTS buffer 语义，不做字段名机械替换。

## 可选检查

- 编译通过后在真机用空请求体与实际网关各做一次完整往返，失败时透传所在阶段与原始异常。

来源支持：1 张卡 · 1 次迁移 · 1 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码（com.android.org.conscrypt）。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔做法第 1 步〕RSA 非对称密钥生成器的字符串参数只由「RSA密钥类型|素数个数」组成（如 RSA2048|PRIMES_2，PRIMES_2 可省略），没有编码或填充项；生成器用于密钥转换时，得到的密钥规格跟转换时的密钥数据一致
- 〔原因 / 做法第 1 步〕真机上 createAsyKeyGenerator 写成 'RSA1024|PKCS1' 或 'RSA2048|PKCS1' 时报 create c generator fail；写 'RSA2048' 时同一 X.509 公钥的 PEM 转换和加密正常
- 〔做法第 1 步〕convertPemKey 接受的公钥是满足 X.509 规范或 PKCS#1 规范的 PEM 编码字符串，BEGIN PUBLIC KEY 的 X.509 PEM 可以直接转换
- 〔适用情境〕安卓 Conscrypt 的 RSA/ECB/OAEPWithSHA-256AndMGF1Padding 由 OpenSSLCipherRSA$OAEP$SHA256 实现，应用没有传 OAEPParameterSpec 时 OAEP 摘要和 MGF1 摘要都取 SHA-256
- 〔适用情境〕cryptoFramework 的 RSA OAEP 加解密规格串由密钥类型、PKCS1_OAEP、摘要、掩码摘要用 | 拼接，摘要和 MGF1 都是 SHA-256 的写 RSA2048|PKCS1_OAEP|SHA256|MGF1_SHA256
- 〔适用情境〕cryptoFramework 的 AES-GCM 加密把各次 update 和 doFinal 的输出拼起来是「密文 + authTag」（authTag 为末尾 16 字节）；解密时 authTag 要填进 GcmParamsSpec，data 只传密文
- 〔原因 / 做法第 2 步〕Cipher.doFinal 的结果可能为 null；解密时 GCM、CCM、CFB、OFB、CTR 模式 doFinal 传 null 返回 null；doFinalSync 的说明同 doFinal
- 〔做法第 2 步〕Cipher.update/updateSync 没凑满一个新分组时这次输出为 null，未处理的数据留到下一次 update 或 doFinal
- 〔原因 / 做法第 2 步〕真机上 AES-GCM 加密空请求体、以及 GCM 解密收尾时，updateSync/doFinalSync 的返回值为 null，直接取 .data 报错，尽管声明的返回类型是非空 DataBlob
- 〔适用情境 / 做法第 2 步〕Cipher.update/updateSync 的 data 不能为 null；doFinal（API 10 起）和 doFinalSync 在对称加解密中 data 可以为 null，但都不能传 {data: 空 Uint8Array}
- 〔做法第 3 步〕Buffer.byteOffset 是所在内存池的偏移：经 allocUninitializedFromPool 创建、或 buffer.from() 传字符串且长度加内存池偏移小于 4KB 时，返回相对内存池的偏移；直接分配内存时为 0
- 〔原因 / 做法第 3 步〕真机上用 new Uint8Array(buf.buffer, buf.byteOffset, …) 取 Buffer 视图时，加密和解密两处抛 RangeError: The newByteLength is out of range
- 〔做法第 3 步〕Buffer.copy(target, targetStart?, sourceStart?, sourceEnd?) 把数据拷到 Buffer 或 Uint8Array 里，targetStart 默认 0，sourceEnd 默认本 Buffer 的 length，返回拷贝的字节数
