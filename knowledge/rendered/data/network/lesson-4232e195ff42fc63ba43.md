# 移植加解密工具时逐分支保留源工具的前置返回与异常回退：空串不进 Cipher，解密失败回退为原文

## 何时使用

规格提取与网络层实现阶段，确定响应解密/解码步骤的失败语义，或把 Android 请求参数加密与响应解密工具（AESUtil、aesEncrypt/aesDecrypt 一类）移植为 cryptoFramework 封装时（源工具带空串直接返回、catch 返回原文一类分支）

## 适用情境

Android 加密工具开头以 isEmpty 直接返回空串、不调用 Cipher，解密在 catch 中返回原文（明文响应也能通过）；目标用 cryptoFramework 对每个业务值做 AES-CBC，业务参数可能为空（如缺省城市没有经纬度），部分接口返回明文 JSON。也包括源端在响应转换钩子（如 beforeResponse）里于 release 下无条件调用 aesDecrypt，是否所有接口都返回密文没有抓包证据，规格或台账准备写“解密失败显式报错、不伪造成功”。

## 例外与边界

- 回退和前置返回都以源工具实际有的分支为准：源工具解密失败照常抛错、或空串也照样加密的，目标照源端写，不凭这条补上源端没有的回退。

## 原因

只移植主路径时，空串送进 Cipher 在目标框架拿到 undefined，随后访问 byteLength 崩溃，请求在组装阶段就失败、从未发出；解密异常直接抛错，则明文响应被判为失败。规格以“显式失败、不伪造成功”一类通用错误策略写解码失败语义时同样丢掉这条回退，实现者照规格写成失败即报错，服务端返回明文的接口全部失败。来源中网络层写者写前已读到 isEmpty 直接返回与 catch 返回原文两个分支，输出仍是无条件加密、解密失败即抛，单测只用假加密器，没有覆盖空值与明文。

## 做法

1. 逐分支列出源加解密工具的前置返回和异常回退（空串、密钥长度、catch 返回原文），在目标封装逐一保留；空值直接返回源端同值（通常为 ''）。
2. 目标做 null/undefined 归一化（如 String(value ?? '')）后，核对该值在源端会走加密工具的哪个分支。
3. 解密失败时按源端回退为原文再解析，只有解析也失败才报错；用真实加密封装补空值与明文响应的用例。
4. 规格写响应解码的失败语义时，沿响应钩子追到被调工具函数的异常分支，把“失败回退原文 / 抛错 / 返回空”照源写进契约；是否全接口密文尚无证据时保留源端容错路径：解密失败按原文进入信封解析、由业务码判定成败，不选更严格的分支再把明文兼容推迟到联调。

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境 / 做法第 1 步〕安卓 TextUtils.isEmpty(str) 在 str 为 null 或长度为 0 时都返回 true
- 〔适用情境 / 做法第 3 步〕安卓 javax.crypto.Cipher.doFinal 在解密模式、要求去填充而解出的数据不符合填充时抛 BadPaddingException；算法无法处理给定输入时抛 IllegalBlockSizeException
- 〔原因〕cryptoFramework 的 doFinal/doFinalSync 不能传 {data: 空 Uint8Array}（对称加解密可传 null）
- 〔原因〕cryptoFramework 的 doFinal 结果可能为 null，用 .data 取数据前不判空会直接报错
- 〔原因〕空串经 UTF-8 编码后无条件送进 cryptoFramework AES-CBC 加密时，在请求组装阶段抛 byteLength of undefined，请求没有发出
- 〔原因 / 做法第 3、4 步〕用 cryptoFramework 的 AES 对服务端返回的明文 JSON（HTTP 200 加业务码）解密时报 WRONG_FINAL_BLOCK_LENGTH
