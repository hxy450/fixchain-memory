# 用 @ohos.xml 重建 SAX 开始事件时采用与回调顺序无关的组装，并自建命名空间作用域

## 何时使用

实现阶段，用 XmlPullParser 的 token 与属性分离回调重建 namespace-aware 开始事件（本元素属性与命名空间 URI）时

## 适用情境

源 SAX/XmlPullParser 在开始标签读取本元素属性并按 uri 加前缀分发命名空间；目标用 tokenValueCallbackFunction 与 attributeWithTagCallbackFunction 两路回调，SDK 声明未写两路回调先后，也未保证 getNamespace() 给出元素 URI。

## 原因

在 START_TAG 时快照并清空属性只在属性先到时成立；修复期实测（API 23）为 START_TAG 先于属性，每个元素拿到上一元素的属性。只依赖 getNamespace() 会丢命名空间（依据字段缺失推断，未直接观测其返回值）。

## 做法

1. 能实测时先用最小样例打印两路回调的实际次序与 getName/getPrefix/getNamespace 返回值；无法实测时 START_TAG 先挂起，到下一个 token 或文档结束时连同已累积属性一起分发。
2. 把 xmlns 与 xmlns:p 属性按元素深度建作用域栈，URI 为空时按前缀解析，END_TAG 时弹出。
3. 源码理解笔记中的不确定项写明待验证条件，不写成“两种顺序行为一致”；其他 XML 读取器复用同一回调骨架前，先确认先例已实测或已改为顺序无关。

## 可选检查

- 带前缀的命名空间字段解析结果缺失时，用各命名空间一条样例断言分发到对应处理器

来源支持：1 张卡 · 1 次迁移 · 1 个应用

已核实的平台事实（核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；OpenHarmony 文档 master 2026-11-21（提交 e42bd18a）；安卓 android-36.1 的源码。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看）：
- 〔适用情境〕安卓 SAX ContentHandler.startElement 的 uri 参数是元素的命名空间 URI，元素没有命名空间或没有开命名空间处理时为空串
- 〔原因 / 做法第 1 步〕API 23 设备上 @ohos.xml 的 parseXml 回调次序是：START_TAG 的 tokenValueCallbackFunction 先到，随后是本元素各属性的 attributeWithTagCallbackFunction，再到下一个 token；在 START_TAG 时快照属性会把上一元素的属性交给下一元素
- 〔做法第 2 步〕ParseOptions.ignoreNameSpace 没写时默认 false（解析命名空间），设成 true 时不解析命名空间
- 〔原因 / 做法第 2 步〕文档 getNamespace 示例（ignoreNameSpace 为 false）里，带前缀的 h:title 在 START_TAG、END_TAG 上 getNamespace() 返回绑定的 URI，没有命名空间的元素返回空串；示例没有覆盖默认命名空间（xmlns="…"）的元素
