# 交付前要编译：项目根没有 hvigorw 时改用 DevEco 或命令行工具自带的 hvigorw、流水线构建入口；只跑读取源码文本的契约测试不算编译，仍不可用时按已知错误模式扫描并在回执写明未编译

## 何时使用

实现或修复阶段写完 ArkTS 代码、准备交付，而工程根目录找不到 hvigorw，或子任务约定把编译留给主线程统一执行时

## 适用情境

工程根目录没有 hvigorw 脚本，本机另有 DevEco Studio 自带的 hvigorw/hvigorw.js、command-line-tools/bin/hvigorw 或流水线封装的构建命令；子代理常以“缺 hvigorw，交收尾编译”结束。 也包括并行领域子代理只用 node --test 跑按文本或正则读取源码的 .cjs 契约，就以“交主线程统一构建”结束。

## 原因

不编译就交付，会把严格类型、声明顺序、声明式语法等错误留给用户逐个报回。来源中多个写者以项目根没有 hvigorw 收尾，而同一工程的其他会话已经用命令行工具或 DevEco 的 hvigorw 编译过。

## 做法

1. 项目根缺 hvigorw 时，使用本机 DevEco Studio 自带的 hvigorw（安装目录 tools/hvigor/bin 下；找不到 node 时把 NODE_HOME 设为同一安装目录的 tools/node，或加 --node-home）、command-line-tools 自带的 hvigorw 或流水线提供的构建命令，执行 assembleHap（多 product 工程加 -p product=<名>）。
2. 构建仍不可用时，按本轮代码涉及的已知错误模式做针对性扫描（如内联对象字面量、static 初始化器引用的类位置、块后分号），并在回执写明未编译，不以“待收尾编译”结束。
3. 文本契约与正则断言不检查 ArkTS 类型：子代理交回前对自己新增或修改的 .ets 跑一次 CompileArkTS（并发时与其他构建错开），做不到就在回执列出未编译文件，并按本轮写法逐项自查（标识符键的 Record 字面量、与通用属性同名的成员、未 implements 的接口传参（类实例要传给接口参数时写 implements 该接口的类））。

## 已核实的平台事实

核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；DevEco Studio 自带 hvigor 6.23.6；安卓 不涉及。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看。

- 〔做法第 1 步〕DevEco Studio 安装目录的 tools/hvigor/bin 下有 hvigorw、hvigorw.bat、hvigorw.js，tools/node 下有 node；hvigorw.bat 先找 NODE_HOME，再找 PATH 里的 node，都没有就报错退出；hvigorw.js 引用环境变量 DEVECO_SDK_HOME（出处：DevEco Studio 安装目录 tools/hvigor/bin/hvigorw.bat、hvigorw.js；tools/node）
- 〔做法第 1、3 步〕assembleHap 与 CompileArkTS 是 hvigor-ohos-plugin 定义的任务名（出处：DevEco Studio 安装目录 tools/hvigor/hvigor-ohos-plugin（src/plugin/hap-plugin.js、src/const/common-const.js））
- 〔做法第 1 步〕hvigorw 命令行选项：-p/--prop <value> 定义额外属性（ohos 插件从中读 product，写 -p product=<名>），-m/--mode <string> 设执行模式，--node-home <string> 指定 Node.js 位置，--stop-daemon 停止本工程守护进程（出处：DevEco Studio 安装目录 tools/hvigor/hvigor/src/cli/main/cli.js（option 定义）；tools/hvigor/hvigor-ohos-plugin（getExtraConfig().get("product")））
- 〔做法第 2 步〕arkts-no-untyped-obj-literals（10605038）：对象字面量必须能对应到已声明的类或接口；不能用字面量初始化 any/Object/object、带方法的类或接口、带含参构造函数的类、带 readonly 字段的类（出处：文档 typescript-to-arkts-migration-guide.md，需要显式标注对象字面量的类型）
- 〔做法第 2 步〕模块级或 static 字段初始化里 new A()、A.a 写在 class A 声明之前报 Class 'A' used before its declaration；函数体里的引用只要调用发生在声明之后就正常，否则报 xxx is not initialized。AppStorageV2.connect(type, …) / PersistenceV2.globalConnect({ type }) 的 type 传的是类本身，会被即时求值（出处：文档 faqs-arkts-module.md，class声明前实例化、class声明前访问其静态属性；鸿蒙 SDK 的 ets/api/@ohos.arkui.StateManagement.d.ts，AppStorageV2.connect、PersistenceV2.globalConnect）
- 〔做法第 2 步〕build() 里只能写 UI 语法，违反时报 10905209 Only UI component syntax can be written here：if 块后加分号（空语句）报这一条，列号指向分号；无花括号的 if/else 组件分支报 ';' expected（出处：文档 _ark_ui_compile.md，10905209；卡里编译实测（case-daad0f4a891d962cfb25））
- 〔做法第 3 步〕arkts-identifiers-as-prop-names（10605001）：属性名须为合法标识符，例外是字符串字面量和枚举字符串值，文档的 Record 字面量示例写成 ['value']: 3。赋给 Record<string, Object> 的对象字面量：标识符键 { k: v } 编译报错；字符串字面量键，或先建空 Record 再 r['k'] = v，可以通过（出处：文档 typescript-to-arkts-migration-guide.md，对象的属性名必须是合法的标识符；卡里编译实测（case-5f5a856b7e04d91c8df6））
- 〔做法第 3 步〕组件成员与通用属性方法同名编译失败：@ComponentV2 组件里名为 width、height、animation 等通用属性方法名的 @Param 成员，报不能赋给 CustomComponent 的同名属性；另有 10905228：struct 名不能与内置属性方法同名（出处：卡里编译实测（case-5f5a856b7e04d91c8df6）；文档 _ark_ui_compile.md，10905228）
- 〔做法第 3 步〕arkts-no-structural-typing（10605030）：不支持结构化类型，类实例传给接口类型参数时，该类必须 implements 该接口（出处：文档 typescript-to-arkts-migration-guide.md，不支持structural typing）
- 〔做法第 2 步〕另两条限制：arkts-no-ctor-prop-decls（10605025）不支持 constructor(public x) 这类构造参数声明字段；arkts-no-indexed-signatures（10605017）不支持 [key: string] 索引签名（出处：文档 typescript-to-arkts-migration-guide.md，不支持在constructor中声明字段、不支持index signature）
