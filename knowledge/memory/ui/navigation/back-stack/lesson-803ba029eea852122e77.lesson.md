# 被 @Entry 页直接组合、未进入 Navigation 栈的子组件要拦截返回键时，由 @Entry.onBackPress 转调子组件登记的处理函数，多个登记方后进先出；@Entry 承载 Navigation 且栈内有 NavDestination 时，挂载点改为栈顶 NavDestination.onBackPressed

## 何时使用

页面转换与接线阶段，为源端非根 Composable 里的 BackHandler/PredictiveBackHandler，或把 OnBackPressedDispatcher 的多级回调映射到 ArkUI 返回键钩子时

## 适用情境

源端在抽屉宿主等非 Activity 根的 Composable 中按状态条件拦截返回（例如抽屉打开时先关抽屉）；目标端该组件不是 @Entry，由唯一的 @Entry 页直接组合，没有作为页面驻留在 Navigation 路由栈内。也包括源端 OnBackPressedDispatcher 按后登记先问分发（Activity 只登记壳层回调，选择模式等另登记回调），目标壳页的返回处理是封闭分支、嵌入的子页没有登记入口。

## 例外与边界

- 组件本身就是 @Entry 页、且没有承载内有页面的 Navigation 时，直接实现 onBackPress
- 组件位于 NavDestination 内容中（含被页面组合的 BasePage 等共享基座）时，返回先交该 NavDestination.onBackPressed，返回 false 即出栈，@Entry.onBackPress 不会被调用；由该 NavDestination 的 onBackPressed 转调基座的裁决函数，不在 @Entry 上兑现

## 原因

SDK 的 onBackPress 注释写明只对 @Entry 装饰的自定义组件回调，子组件自己实现的 onBackPress 不会触发。来源工程的子组件把同一逻辑另挂到自身 NavDestination.onBackPressed，但该节点被 @Entry 页直接组合、不在 Navigation 栈内，设备实测（API 12 模拟器）也不回调，抽屉打开时按返回直接回到桌面。编译、结构审计与静态判定全部通过，只有设备上按返回键才暴露。

## 做法

1. 先确认子组件的挂载形态：被 @Entry 页直接组合且不在 Navigation 栈内，还是位于 NavDestination 内容中（含页面组合的共享基座）；后者按例外由 NavDestination.onBackPressed 转调。
2. 直接组合时，子组件在 aboutToAppear 经回调参数（@ComponentV2 用 @Event）把 () => boolean 的裁决函数交给 @Entry 页，aboutToDisappear 交回 null；@Entry 页的 onBackPress() 有函数就返回其结果，没有就返回 false 交系统默认处理。
3. 有多个登记方时，宿主提供后进先出回调栈（子页 aboutToAppear 登记、aboutToDisappear 注销），宿主返回处理在执行壳层分支前先分发；同一子页还嵌入其他宿主时，这些宿主也接同一分发。

## 可选检查

- 能上设备时：状态打开（如抽屉展开）按 Back，状态关闭且应用留在前台；关闭态按 Back 仍按源端行为退出。

## 已核实的平台事实

核实时用的是 API 23（HarmonyOS 6.1.0，SDK ets 6.1.0.105）；文档用 2026-05 的 OpenHarmony 中文文档副本；安卓 androidx.activity:activity 1.8.1、androidx.activity:activity-compose 1.13.0（字节码）。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看；每条下面的「写法」是在 SDK 声明里核过的导入语句、归属、签名和枚举成员，写代码时直接照抄。

- 〔做法第 1 步〕NavDestination.onBackPressed(callback: () => boolean)：文档写明与 Navigation 绑定的导航控制器中有内容时才生效；返回 true 表示重写返回逻辑，false 表示回退到上一页（出处：鸿蒙 SDK 的 ets/component/nav_destination.d.ts，NavDestinationAttribute.onBackPressed；文档 ts-basic-components-navdestination.md，onBackPressed）
  写法：NavDestination() 的属性方法，全局组件，全局可用，不用导入
        NavDestination() { }.onBackPressed((): boolean => { return this.handler ? this.handler() : false; })  // API 10
- 〔做法第 1 步〕被 @Entry 页直接组合、不在 Navigation 栈内的 NavDestination，按返回键时其 onBackPressed 不回调；栈内只有一个 NavDestination 且它返回 false 时直接出栈，@Entry 的 onBackPress 收不到这次返回（出处：卡里修好并验证过）
- 〔做法第 2 步〕onBackPress?(): void | boolean 只对 @Entry 装饰的自定义组件（router 页面）生效；返回 true 表示页面自己处理、不路由，返回 false 或不返回走默认返回（出处：鸿蒙 SDK 的 ets/component/common.d.ts，BaseCustomComponent.onBackPress；文档 ts-custom-component-lifecycle.md，onBackPress）
  写法：自定义组件生命周期，全局可用，不用导入
        @Entry @Component struct Index { onBackPress(): boolean | void { return false; } }
- 〔做法第 2 步〕aboutToAppear?(): void 在自定义组件新实例创建后、build() 执行前调用；aboutToDisappear?(): void 在组件销毁前调用（出处：鸿蒙 SDK 的 ets/component/common.d.ts，BaseCustomComponent.aboutToAppear、BaseCustomComponent.aboutToDisappear；文档 ts-custom-component-lifecycle.md，aboutToAppear、aboutToDisappear）
  写法：自定义组件生命周期，全局可用，不用导入
        struct Child { aboutToAppear(): void { } aboutToDisappear(): void { } }
- 〔做法第 2 步〕@Event（API 12）只能用在 @ComponentV2 里，装饰回调方法作为组件输出，允许传入箭头函数；未初始化时自动生成空函数，外部未传但本地有默认值时用本地函数（出处：鸿蒙 SDK 的 ets/component/common.d.ts，Event；文档 arkts-new-event.md，装饰器说明、限制条件）
  写法：全局装饰器，全局可用，不用导入（@ComponentV2、@Event 自 API 12）
        @ComponentV2 struct <子组件> { @Event <登记返回>: (h: (() => boolean) | null) => void = () => {}; }
        父组件：<子组件>({ <登记返回>: (h: (() => boolean) | null) => { this.backHandler = h; } })
- 〔适用情境〕Compose BackHandler(enabled: Boolean = true, onBack)：enabled 默认 true（出处：androidx.activity:activity-compose 1.13.0，BackHandlerKt.BackHandler 的默认参数（字节码））
- 〔做法第 3 步〕OnBackPressedDispatcher.onBackPressed 从最后加入的回调往前找第一个 isEnabled 的，只调它的 handleOnBackPressed；一个都没有时执行 fallbackOnBackPressed（Activity 默认返回）（出处：androidx.activity:activity 1.8.1，OnBackPressedDispatcher.onBackPressed（字节码））
- 〔适用情境〕View 体系的 DrawerLayout 默认自己处理返回（应用没有另设时）：drawerlayout 1.0.0–1.2.0 在 onKeyDown 遇到返回键且有可见抽屉时 startTracking 并消费，onKeyUp 时若抽屉锁模式为 LOCK_MODE_UNLOCKED 就 closeDrawers()，有可见抽屉即返回 true；1.2.0 起在 API 33+ 抽屉可见、未锁且已附着窗口时另注册 OnBackInvokedCallback（优先级 1000000，即 PRIORITY_OVERLAY），1.2.0 之前只有按键路径。源端没写任何返回代码时，“抽屉打开先关抽屉”也可能来自这里（出处：androidx.drawerlayout:drawerlayout 1.0.0、1.2.0 字节码 widget.DrawerLayout#onKeyDown、#onKeyUp、#updateBackInvokedCallbackState、DrawerLayout$Api33Impl）
- 〔适用情境 / 例外与边界〕返回键的默认分发随 targetSdk 与清单变化：Android 16 及以上设备上，清单未写 enableOnBackInvokedCallback 时 targetSdk > 35（≥36）按 true 处理；为 true 时 ViewRootImpl 把返回键交给 OnBackInvokedCallback 栈（doOnBackKeyEvent），不再把 KEYCODE_BACK 分发给 View 的 onKeyDown/onKeyUp，只靠按键处理返回的控件（如 drawerlayout 1.2.0 之前）收不到。Activity.onBackPressed 默认：先收起动作视图、弹出平台 Fragment 返回栈；API 31 前结束 Activity，API 31 起若是任务根且声明了 MAIN/LAUNCHER 则把任务移到后台、不结束（出处：com.android.internal.pm.pkg.parsing.ParsingPackageUtils（enableOnBackInvokedCallback 的缺省值）；android.window.WindowOnBackInvokedDispatcher#isOnBackInvokedCallbackEnabled；android.view.ViewRootImpl#doOnBackKeyEvent；android.app.Activity#onBackPressed）
- 〔做法第 2、3 步〕OnBackPressedDispatcher.addCallback(owner, callback) 按生命周期挂接（activity 1.0.0 与 1.13.0 相同）：owner 到 ON_START 才加入分发，ON_STOP 时移出，ON_DESTROY 时移除并解除观察；不带 owner 的 addCallback(callback) 一直有效直到 remove()。分发只看 isEnabled，后加入的先问（出处：androidx.activity:activity 1.0.0 字节码 OnBackPressedDispatcher$LifecycleOnBackPressedCancellable#onStateChanged；androidx.activity:activity 1.13.0 字节码 OnBackPressedDispatcher$addCallback$observer$1）
- 〔适用情境〕Compose 抽屉的默认返回处理：material3-android 1.4.0 的 ModalDrawerSheet(drawerState, …) 与 DismissibleDrawerSheet(drawerState, …) 重载内部调用 DrawerPredictiveBackHandler，以 drawerState.isOpen 为 enabled 注册 PredictiveBackHandler（抽屉打开时返回先关抽屉）；不传 drawerState 的旧重载和 ModalNavigationDrawer 本身不处理返回。Compose Material（M2）的 ModalDrawer 不处理返回（material-android 1.6.2、1.12.0）（出处：androidx.compose.material3:material3-android 1.4.0 字节码 NavigationDrawerKt.ModalDrawerSheet、NavigationDrawerKt.DrawerPredictiveBackHandler、internal.BackHandler_androidKt.PredictiveBackHandler；androidx.compose.material:material-android 1.6.2、1.12.0 字节码 DrawerKt）
- 〔做法第 1 步〕判断 Navigation 栈里有没有 NavDestination 用 NavPathStack.size()；栈顶出栈用 pop()，清栈 clear()，取全部页名 getAllPathName()。栈为空时返回事件交给 @Entry 页的 onBackPress（出处：鸿蒙 SDK 的 ets/component/navigation.d.ts，NavPathStack.size、NavPathStack.pop、NavPathStack.clear、NavPathStack.getAllPathName；文档 ts-basic-components-navigation.md，NavPathStack）
  写法：全局类，全局可用，不用导入：NavPathStack（API 10），Navigation(pathInfos: NavPathStack)
        size(): number；pop(animated?: boolean): NavPathInfo | undefined；pop(result: Object, animated?: boolean): NavPathInfo | undefined
        clear(animated?: boolean): void；getAllPathName(): Array<string>
        例：if (this.pathStack.size() > 0) { this.pathStack.pop(); }
