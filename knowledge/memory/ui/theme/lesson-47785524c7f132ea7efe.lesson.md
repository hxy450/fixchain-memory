## 何时使用

规格提取阶段写控件转换决策，或页面实现阶段写出按钮、文本、工具栏等控件的修饰链时；为带 android:theme 覆盖（ThemeOverlay）的 AppBarLayout/Toolbar 定色时；为只显式写了部分属性的 Button、未写颜色的 TextView、SwitchPreference 开关、NavigationView 菜单项确定默认外观时；为未写 tint/color 的 Compose Icon、Text 着色，翻译未传 textStyle 的 BasicTextField，或迁移 GlanceTheme 等依赖库主题色时；把 CheckBox、RadioButton、MaterialButton、TabLayout、EditText/Spinner、工具栏 SearchView 等 Material 控件映射为 ArkUI 组件时；为框架主题提供的窗口背景、文字色、列表分隔线、文字行框（单行与多行），以及平台 drawable 状态背景（ImageWell 按钮、EditText、SeekBar 的位图或 9-patch，Material CheckBox/RadioButton 的向量）确定目标取值时

## 适用情境

源布局中的控件没有声明（或只声明了部分）background / backgroundTint / textColor / 圆角 / 字重 / 投影，外观来自应用主题、控件默认样式或祖先布局上的 android:theme 覆盖；ArkUI 对应组件不设样式时使用平台默认外观。也包括 AppBarLayout/Toolbar 以 android:theme 指定 ThemeOverlay（如 AppBarOverlay 的父样式为 ThemeOverlay.AppCompat.Light），而 Activity 主题是 DarkActionBar。也包括 Button/AppCompatButton 只写了 background、textColor、textSize，没有 style、textAllCaps、stateListAnimator、elevation，或自定义 View 继承 AppCompatButton 只换背景。也包括 TextView 未声明 textColor/textAppearance/style（缺省 textAppearanceSmall：次文字色、14sp、includeFontPadding）与 EditText 未声明 textColor（缺省主文字色）。也包括 PreferenceFragment 的 SwitchPreference 开关、未写 item 样式的 NavigationView 菜单项。也包括 Compose 的 Icon/Text 未写 tint/color、颜色来自宿主 Surface 的 LocalContentColor；foundation 的 BasicTextField 不传 textStyle；颜色来自 GlanceTheme 一类依赖库主题、源码与规格里都没有具体色值。也包括映射参考只给一对一或逐属性映射，而 ArkUI 组件自带的默认外观与源端 Material 默认不同：Checkbox 默认圆形、Radio 默认勾选样式、Toggle 胶囊开关、TextInput/Search/Select 默认填充底、Tabs 默认标签样式。也包括应用主题父链止于 android:Theme.Holo/Material/DeviceDefault 的老工程，外观由框架主题或 style="@android:style/*" 引用提供，本机装有 Android SDK 平台资源。

## 例外与边界

- 源控件在应用自有的 layout 或 style 中写出了具体值时，按显式声明转换这些属性；显式声明只覆盖被声明的几项，其余属性仍按控件默认样式补齐；style="@android:style/*" 或 ?android:attr 引用不算显式声明
- 决策记录明确要求目标端采用平台默认外观

## 原因

ArkUI 组件不会继承 Android 主题给控件的默认样式。规格只在全局写“颜色由资源系统负责”而不落到控件行，下游按控件行实现就得到平台默认外观，还会被后续页面当先例照搬。实际提供方因控件而异：祖先布局上的 android:theme 覆盖对整棵子树优先于 Activity 主题（DarkActionBar 只决定窗口装饰 ActionBar）；控件只写了部分属性时，其余仍来自控件默认样式（按钮的全大写、Medium 字重、投影与最小尺寸）；TextView 与 EditText 的缺省文字色不同。凭“Activity 是 DarkActionBar”“按钮已显式声明”“未写颜色即主文字色”推断，或凭记忆、另一设计体系的基线色、相邻页面先例填写，颜色、字号与投影都会偏；召回提醒还可能把草稿里的未核推断当作经验结论传下去。框架主题的提供方是 SDK 平台资源：windowBackground 可能是渐变 drawable，ListView 分隔线来自 listDivider，按钮与输入框背景是按状态切换的 9-patch，Material 勾选框与单选框是按状态切换的向量，本机 SDK 一直可查。ArkUI 内置组件的同名能力不等于源端绘制规则：List.divider 只画项间，Android ListView 在末行底边高于列表底边时还会在末行后画一条；Checkbox 的圆角与勾形不可配，对不上框架 btn_checkbox 向量（方框、圆角与镂空勾的几何见本机 SDK drawable/btn_checkbox_checked_mtrl.xml）。TextView 默认 includeFontPadding 的行框由源字体度量决定，ArkUI Text 不设 lineHeight 时按目标字体自然行高排版，决定纵向排布的行、列表行与对话框会整体偏矮或偏高。

## 做法

1. 先定位提供方并解析到值，顺序：控件自身 style/textAppearance → 祖先布局上的 android:theme/app:theme 覆盖（ThemeOverlay.AppCompat.Light 下标题取 textColorPrimary、导航图标取 colorControlNormal）→ Activity 主题 → 应用主题；框架主题（android:Theme.*、@android:style/*、?android:attr）到本机 SDK（ANDROID_HOME 或 %LOCALAPPDATA%/Android/Sdk）的 platforms/android-<api>/data/res 沿 themes/styles → color selector 或 drawable → 具体值解析，依赖库到其 aar 的 res 解析。查过仍缺才标待核并写明已查路径；规格、注释与提醒里出现的具体值注明来自哪一层，源值已解析时不按可读性或记忆改写，未核实的值不写成“平台默认”。外观也包括文字行框：未声明行高的 TextView（默认 includeFontPadding）决定纵向排布时，按源字体行框给目标 Text 写 lineHeight（见第 10 步）。
2. 控件只显式声明部分属性时，先列出该控件默认样式的属性清单，再与源端显式属性做差集，差出的项照默认补齐。AppCompat/Material Button：textAllCaps 全大写与 sans-serif-medium、stateListAnimator 静止 2dp 投影/按下抬升 +4dp/禁用 0、minHeight 48dp 与 minWidth 88dp、内边距（平台/AppCompat 按钮的左右 8dp、上下 4dp 来自默认背景 btn_default_mtrl_shape，源端换成不带 <padding> 的背景时内边距为 0；MaterialButton 的 16dp/4dp 写在样式里，换背景后仍在）；自定义 shape 背景没有 pressed 态时按下不变色（ArkUI Button 设 stateEffect:false，按压用 stateStyles 只换投影，shadow 的 radius、offset 按 px 写（dp 值乘屏幕密度））；继承 AppCompatButton 的自定义 View 只换背景时投影仍在。
3. 规格提取时，对布局里没写样式的控件先查主题的父主题与语义色，把主题与控件默认样式带来的背景色、字色、字重、圆角、最小高度、投影写进该控件自己的转换决策行，用已迁移的颜色资源名表达。
4. 框架主题的隐式外观不只是控件色，规格逐项写出：windowBackground 解析到最终 drawable（Holo 暗色经 screen_background_selector_dark 到 background_holo_dark，#000000→#272D33 自上而下渐变，铺在页面根部，与同名 @color 不是一个资源）；文字色按 textAppearance 取（Holo 与老主题 Large/Medium 为主色，Small 与未声明颜色的 TextView 为次色 textColorSecondary；Material 下 Large 为主色、Medium 为 textColorSecondary、Small 与未声明颜色的 TextView 为 textColorTertiary；提示为 hint 色，Holo 暗色依次 #F3F3F3、#BEBEBE、#808080），源端显式色（如 @android:color/white）单列；ListView/ListActivity 未声明 divider 时写出主题 listDivider：项与项之间各一条，末行底边高于列表底边时末行之后也画一条（ListView.dispatchDraw 的 bottom < listBottom，列表填满并滚到底时不画）；ArkUI List.divider 只画项间，末行那条要由 ListItem 内的 Divider 按同一条件承担，不能只写 List.divider；决定纵向排布的 wrap_content 单行 TextView 按源字体与 includeFontPadding 的行框定高。
5. 外观由平台 drawable 状态选择器决定的框架控件复制平台原图并按状态切换：位图或 9-patch（Widget.ImageWell、EditText 的 editTextBackground、SeekBar 的拇指与双粗细轨道、Holo CheckBox/RadioButton）取 9-patch 内容内边距作为 padding；向量（Material 主题 CheckBox 的 btn_checkbox_checked/unchecked_mtrl、RadioButton 的 btn_radio_on/off_mtrl，画布取向量的 android:width/height）转 SVG 后按各状态烘焙 tint 解析色（tint 指向 colorControlNormal、textColorSecondary 的，透明度按源设备系统版本取：API≤30 为 0.54，API≥31 按 0.60），Image 尺寸取向量画布，点击挂在承载行上并补无障碍角色与选中态；只给 ArkUI 内置组件改颜色不算显式化。
6. 实现时对照源主题语义色与目标颜色资源补齐修饰链：MaterialComponents 按钮对应 .backgroundColor($r('app.color.colorPrimary')) 与 .fontColor($r('app.color.colorOnPrimary'))，再按源按钮样式补 borderRadius 与最小高度；规格未写样式时同样补齐，并在转换报告注明依据来自主题。深浅色由 base/dark 资源自动切换。
7. Compose Icon/Text 未写 tint/color 时，沿调用链找最近的 Surface、Scaffold 或 CompositionLocalProvider，取它的 contentColor 对应的资源写进规格与实现；没核到宿主时标为待核，不写“默认 onSurface”或系统字色，也不照搬别处显式使用的 iconPrimary、brand 或其他页面的先例。源端显式写了 color 与禁用 alpha（如 uiBackground.copy(alpha = if (!enabled) 0.38f else 1f)）时，分别落实为 fontColor 与按状态的 opacity，不用品牌色加 enabled() 代替。
8. foundation BasicTextField 未传 textStyle 时按 TextStyle.Default 落实（14sp、黑色、系统字体）；bodyLarge 等 M3 排版只用于 M3 TextField/Text。
9. 依赖库主题色（如 GlanceTheme.widgetBackground）从库包的 res/values 与 values-night 取回退值（如 Gradle 缓存中的 aar）；取不到时登记待核，不用其他设计体系的基线色代替。
10. TextView/EditText 未声明 textSize/textColor 时按控件区分：TextView（含 AppCompatTextView）没有 textColor、textAppearance、style 时取 textAppearanceSmall——14sp；字色在 Material、AppCompat 下为 ?android:textColorTertiary（浅色 #8A000000、深色 #B3FFFFFF，白底约 #757575），在 Holo 与老主题下为 ?android:textColorSecondary；EditText 取 editTextColor 即主文字色（浅色 #DE000000）。给 ArkUI Text 显式写 fontColor，不留给 ArkUI 默认近黑，也不沿用旧实现、相邻组件或同组控件的硬编码值。TextView 默认 includeFontPadding=true，ArkUI Text 默认不加首末行留白（API 23 起的 Text.includeFontPadding 默认 false，本步不用它代替）：顶部对齐、决定纵向排布的文字按源字体度量用 Text.lineHeight 固定行盒——单行取字体 top..bottom；多行行距取 ascent..descent，只在首行上方、末行下方用 padding 补 (ascent−top)、(bottom−descent)，不逐行套单行行框；源 targetSdk < 28（fallbackLineSpacing=false）时，日文等由回退字体绘制的行仍按源默认字体的行盒排版，目标同样用固定 lineHeight 锁定，否则含 CJK 的行变高。源端字体是平台默认 sans-serif（Roboto）时，按所附 Roboto 每 em 度量乘字号换算（取整可能差 1px）；用了其他字体又拿不到度量时登记待设备核对，写明要 dump 的控件。
11. 映射 Material 控件时先列出它在源主题或库中的默认外观，逐项与 ArkUI 默认值对照并显式设置：TextInput/Select/Search 透明底与提示色、Tabs 用 SubTabBarStyle 指定 labelStyle 与指示条；CheckBox/RadioButton → Checkbox/Radio 只是功能映射：至少设 Checkbox .shape(CheckBoxShape.ROUNDED_SQUARE)、Radio 的 indicatorType，但圆角、勾形与尺寸设不成框架样子，外观要一致时按第 5 步用平台两态图；SwitchPreference/Switch → Toggle 同样只是功能映射（框架 Material Switch 为细轨道加外凸带投影拇指，偏好行中开关本身不接收点击、由整行切换，开关设 hitTestBehavior(HitTestMode.None)），外观要一致时自绘或显式定制；未写 item 样式的 NavigationView 菜单项写出选中项通栏底色、加粗与 colorPrimary 着色，未选图标次文字色着色，组间通栏分隔与列表上下留白。源样式继承 MDC/M3 库按钮时，从合并资源解析 textAppearance 的 letterSpacing 与文字颜色 selector，不凭记忆取强调色。

## 已核实的平台事实

核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；安卓 Android SDK 平台资源 android-34（另比对 android-30/33/35/36 的同名颜色与透明度）；Android SDK 源码 android-36.1；appcompat 1.7.1、material 1.12.0；compose material3-android 1.4.0、foundation-android / ui-text-android 1.12.0。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看；每条下面的「写法」是在 SDK 声明里核过的导入语句、归属、签名和枚举成员，写代码时直接照抄。
