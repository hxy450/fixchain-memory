# Image 承载点击/长按按钮或自绘拖拽柄时设 draggable(false)：ArkUI Image 默认可被系统拖出，按住会进入拖拽并接管输入

> 带知识的试验版（未并入 store）：正文按 `knowledge/lessons/lesson-7389433391eddbaea827.json` 改了 1 句，后面接了 11 条已核实的平台事实。原文、来源和证据卡见 [memory/ui/interaction/lesson-7389433391eddbaea827.lesson.md](../../../../memory/ui/interaction/lesson-7389433391eddbaea827.lesson.md)。

## 何时使用

界面实现阶段，用 Image 承载按钮、可点图标或拖拽柄时：在 Image 或其外层 Stack/Button 上挂 onClick、长按手势，或在其上挂 onTouch、PanGesture 等自绘拖拽或按压逻辑时

## 适用情境

源端在 ACTION_DOWN 或 onTouch 中立即开始自定义拖拽（如清单条目拖拽排序），或图标只是点击、长按按钮（ImageButton/可点 ImageView，如快门、缩略图入口、屏上开关图标），没有任何拖放行为；目标用 Image 组件实现（可外包挂点击的 Stack/Button），未设置 draggable。

## 例外与边界

- 源端本就允许把图片拖出到其他位置或应用时保留系统拖拽

## 原因

ArkUI 的 Image 默认可拖出（Image 自身的 draggable 自 API 11 起默认为 true，API 9 为 false，与通用属性的默认值不同）：按住后系统图片拖拽接管输入，自绘的 onTouch、PanGesture 收到 Cancel，按下时已隐藏的条目或拖拽阴影停在中间态；只挂点击或长按的图标按钮也会进入拖拽识别与拖拽预览，点击响应卡顿，外层 Stack/Button 上的点击不会关闭子 Image 的默认拖拽。Android ImageView/ImageButton 没有这种默认拖拽。

## 做法

1. 作按钮、可点图标或拖拽柄使用的 Image 写 .draggable(false)：点击或长按挂在外层 Stack/Button 上时也写在内层每个 Image 上，再挂自绘的 onTouch 或手势时同样先关闭；源端只在按下时起拖、没有长按分支的，目标也不保留长按触发的系统拖拽。

## 已核实的平台事实

核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；安卓 框架源码 android-36.1。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看；每条下面的「写法」是在 SDK 声明里核过的导入语句、归属、签名和枚举成员，写代码时直接照抄。

- 〔原因〕ImageAttribute.draggable(value: boolean)：Image 自己的默认拖拽开关，自 API 11 起默认 true（API 9 默认 false）（出处：鸿蒙 SDK 的 ets/component/image.d.ts，ImageAttribute.draggable）
  写法：Image(src: PixelMap | ResourceStr | DrawableDescriptor)：全局组件；.draggable(value: boolean)，如 Image($r('app.media.<名>')).draggable(false)
- 〔原因〕Image 的 draggable 为 true 时绑定的长按手势不生效；设为 false 后拖拽类事件不再触发（出处：文档 ts-basic-components-image.md，draggable）
  写法：签名同上：ImageAttribute.draggable(value: boolean)
- 〔原因〕通用属性 CommonMethod.draggable(value: boolean): T 默认 false（「默认情况下，组件不允许拖拽」），与 Image 自身默认不同（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.draggable；文档 ts-universal-attributes-drag-drop.md，draggable）
  写法：通用属性，全局可用，不用导入：.draggable(value: boolean)
- 〔原因〕默认支持拖出的组件：Search、TextInput、TextArea、RichEditor、Text、Image、Hyperlink，用 draggable 控制默认拖拽（Text 还要配 copyOption）（出处：文档 ts-universal-events-drag-drop.md，默认支持拖出能力的组件）
  写法：Text 的默认拖出还要 .copyOption(value: CopyOptions)；CopyOptions { None, InApp, LocalDevice, CROSS_DEVICE } 全局枚举，不用导入
- 〔原因〕长按触发拖拽：对默认可拖出且 draggable 为 true 的组件，长按达到 500ms 即触发拖拽，800ms 时开始预览图浮起动效（出处：文档 arkts-common-events-drag-event.md，手势拖拽、500ms、800ms）
  写法：全局可用，不用导入；签名见 draggable 条
- 〔做法第 1 步〕Image 未设 draggable(false) 时，按住会进入系统拖拽识别和拖拽预览（设备上表现为点击卡顿）；把 onClick、长按挂在外层 Stack/Button 上不会关掉子 Image 的默认拖拽（出处：卡里上机实测（case-1071843a480186d94d42））
  写法：通用事件 .onClick(event: (event: ClickEvent) => void)；长按 .gesture(LongPressGesture(value?: { fingers?: number; repeat?: boolean; duration?: number }).onAction(event: (event: GestureEvent) => void))
- 〔做法第 1 步〕Image 上挂 onTouch 与 PanGesture 自绘拖拽而 draggable 未关时，长按后系统图片拖拽接管输入，自绘拖拽收到 Cancel（出处：卡里上机实测（case-d38fbc2e9b64b7c3338b））
  写法：PanGesture(value?: { fingers?: number; direction?: PanDirection; distance?: number } | PanGestureOptions)：.onActionStart / .onActionUpdate / .onActionEnd(event: (event: GestureEvent) => void)、.onActionCancel(event: () => void)
        绑定：.gesture(gesture: GestureType, mask?: GestureMask) 或 .priorityGesture(gesture: GestureType, mask?: GestureMask)；触摸 .onTouch(event: (event: TouchEvent) => void)
        PanDirection { None, Horizontal, Left, Right, Vertical, Up, Down, All }；PanGesture、LongPressGesture 与枚举都全局可用，不用导入
- 〔原因〕安卓框架里自己发起拖放的只有 TextView 的选中文字（Editor 内部调 startDragAndDrop）；ImageView、ImageButton 等其他视图只在应用代码调用 View#startDragAndDrop（API 24 起，之前是 startDrag）时才进入系统拖放，按住不会自动拖出（出处：android.view.View#startDragAndDrop、#startDrag；android.widget.Editor#startDragAndDrop）
- 〔做法第 1 步〕安卓长按判定时长取 ViewConfiguration.getLongPressTimeout()：读系统设置 Settings.Secure.LONG_PRESS_TIMEOUT，未设置时用 DEFAULT_LONG_PRESS_TIMEOUT（android-36.1 源码为 400 ms；更早版本的取值本机无源码）（出处：android.view.ViewConfiguration#getLongPressTimeout、#DEFAULT_LONG_PRESS_TIMEOUT；android.view.View#checkForLongClick）
- 〔做法第 1 步〕LongPressGesture 的参数与缺省值：fingers 最少手指数，缺省 1、取值 1–10；repeat 是否连续触发，缺省 false（为 true 时按 duration 间隔重复回调）；duration 最短长按时长，缺省 500 ms；API 22 起另有 LongPressGesture(options?: LongPressGestureHandlerOptions)，可设 allowableMovement（识别期允许的最大移动距离）（出处：鸿蒙 SDK 的 ets/component/gesture.d.ts，LongPressGestureInterface、LongPressGestureHandlerOptions.allowableMovement；文档 ts-basic-gestures-longpressgesture.md，LongPressGesture）
  写法：全局组件与全局接口，全局可用，不用导入
        LongPressGesture(value?: { fingers?: number; repeat?: boolean; duration?: number })  // 缺省 1、false、500
        LongPressGesture(options?: LongPressGestureHandlerOptions)  // API 22，含 allowableMovement?: number
        .gesture(LongPressGesture({ duration: 400 }).onAction((event: GestureEvent) => { … }).onActionEnd((event: GestureEvent) => { … }))
- 〔原因〕onTouch 收到的 TouchType：Down、Up、Move、Cancel（API 7 起）；API 20 起另有 HOVER_ENTER = 9、HOVER_MOVE = 10、HOVER_EXIT = 11、HOVER_CANCEL = 12。系统拖拽接管输入时，自绘逻辑收到的是 Cancel，要按源端 ACTION_CANCEL 的分支处理（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，TouchType.Cancel、TouchType.HOVER_CANCEL）
  写法：全局枚举，全局可用，不用导入
        TouchType：Down、Up、Move、Cancel；HOVER_ENTER = 9、HOVER_MOVE = 10、HOVER_EXIT = 11、HOVER_CANCEL = 12（API 20）
        Image(src).draggable(false).onTouch((event: TouchEvent) => { if (event.type === TouchType.Cancel) { … } })
