# android:background 的整屏背景位图按拉伸铺满映射，不默认用 ImageFit.Cover 裁切；被铺满且未置顶的 SurfaceView 盖住时不建背景层

## 何时使用

界面实现阶段，把源根布局的 android:background 背景图转换为 ArkUI 背景 Image 或背景图属性时；规格提取阶段为承载自绘游戏视图的页面确定背景层与画布叠放关系时

## 适用情境

源根容器以 android:background=@drawable/xxx 铺设整屏背景位图，背景上画有需要完整显示的图文；目标用 Stack 底层 Image 或背景图属性重建。 也包括根容器内 addView 或布局了铺满的 SurfaceView/GLSurfaceView 子类（未调用 setZOrderOnTop(true)，绘制时 drawColor(Color.TRANSPARENT, PorterDuff.Mode.CLEAR) 清屏或不画底色），目标准备用 Stack 叠放背景 Image 与透明 Canvas。

## 例外与边界

- 源端是 ImageView 且显式 scaleType=centerCrop 一类裁切语义，按该 scaleType 映射
- 源容器内铺满的 SurfaceView/GLSurfaceView/VideoView 未 setZOrderOnTop(true)：该区域的父容器背景在源端不可见，不建背景层，按做法第 1 步取可见底色

## 原因

View 背景位图按视图边界拉伸铺满、不裁切；Cover 等比铺满会裁掉上下或左右，背景上的关键图文被截掉。来源中生成者读到根布局背景与资源尺寸，仍写 objectFit(ImageFit.Cover)，顶部图文被裁，修复改为 ImageFit.Fill。 背景要在源端最终渲染中可见才需要迁移：SurfaceView 的 surface 默认在其所在窗口之下合成，SurfaceView 在窗口上打洞让 surface 显示（android.view.SurfaceView 类注释），铺满的 SurfaceView 区域内父容器的 android:background 被擦掉，可见的是 surface 自身内容，清成透明时为黑。ArkUI Canvas 的 clearRect 清成透明后会露出下层组件，把源容器背景放到画布下层，本该黑底的画面就显示出背景图。

## 做法

1. 源 android:background 的位图背景用 ImageFit.Fill（或等效铺满方式）映射；确需等比裁切时，先用资源宽高比与目标屏幕比例核对关键图文不会被裁。 映射前先确认该背景在源端最终可见：容器内有铺满的 SurfaceView/GLSurfaceView 子类时，打开该视图类核对父类、构造器与 SurfaceHolder 设置（grep setZOrderOnTop|setZOrderMediaOverlay|setFormat|getHolder）和清屏方式；未 setZOrderOnTop(true) 时该区域不建背景 Image 层，目标底色取 surface 的实际可见色（未经 getHolder().setFormat 改成带透明度的格式、每帧清成透明时即为黑），每帧 clearRect 照旧。规格或派工给出的背景层与这些源码事实冲突时，按源端可见结果实现，并回报规格分歧。

## 已核实的平台事实

核实时用的是 API 23（HarmonyOS 6.1.0，SDK ets 6.1.0.105）；文档用 2026-05 的 OpenHarmony 中文文档副本；安卓 源码 android-36.1。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看；每条下面的「写法」是在 SDK 声明里核过的导入语句、归属、签名和枚举成员，写代码时直接照抄。

- 〔原因 / 做法第 1 步〕View 背景 drawable 的 bounds 设为 (0, 0, 宽, 高)；BitmapDrawable 默认 gravity 为 Gravity.FILL：背景是普通位图（不是带 gravity/tileMode 的 <bitmap>、.9.png 或 layer-list）时，按视图边界拉伸铺满，不保持宽高比（出处：android.view.View#setBackgroundBounds；android.graphics.drawable.BitmapDrawable 的 BitmapState.mGravity）
- 〔例外与边界〕ImageView 的布局与 style 都没设 scaleType 时默认 ScaleType.FIT_CENTER（等比完整显示）；只有显式设了 centerCrop 等才是裁切语义（出处：android.widget.ImageView#initImageView）
- 〔做法第 1 步〕Image.objectFit(value: ImageFit)：不设置时默认 ImageFit.Cover（保持宽高比，两边都 ≥ 显示边界，超出部分被裁）（出处：鸿蒙 SDK 的 ets/component/image.d.ts，ImageAttribute.objectFit；文档 ts-basic-components-image.md，objectFit）
  写法：全局组件，全局可用，不用导入
        Image(src: PixelMap | ResourceStr | DrawableDescriptor)  // API 12 起 src 还可为 ImageContent
        Image($r('app.media.bg')).width('100%').height('100%').objectFit(ImageFit.Fill)
- 〔做法第 1 步〕ImageFit.Fill：不保持宽高比缩放，充满显示边界；ImageFit.Contain：保持宽高比完整显示在边界内（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，ImageFit；文档 ts-appendix-enums.md，ImageFit）
  写法：全局枚举，全局可用，不用导入
        ImageFit：Contain | Cover | Auto | Fill | ScaleDown | None | TOP_START | TOP | TOP_END | START | CENTER | END | BOTTOM_START | BOTTOM | BOTTOM_END（这九个 API 12）| MATRIX（API 15）
- 〔做法第 1 步〕背景图属性：backgroundImage(src, repeat?/options?) 配 backgroundImageSize(value: SizeOptions | ImageSize)；不设时 ImageSize.Auto（保持原图比例）；拉伸铺满用 ImageSize.FILL（API 12，全大写）（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.backgroundImage、CommonMethod.backgroundImageSize；ets/component/enums.d.ts，ImageSize；文档 ts-universal-attributes-background.md，backgroundImageSize）
  写法：通用属性与枚举，全局可用，不用导入
        .backgroundImage(src: ResourceStr | PixelMap, repeat?: ImageRepeat)；.backgroundImage(src: ResourceStr | PixelMap, options?: BackgroundImageOptions)（API 18）
        .backgroundImageSize(value: SizeOptions | ImageSize)
        ImageSize：Auto | Cover | Contain | FILL（API 12）；ImageRepeat：NoRepeat | X | Y | XY
- 〔原因 / 做法第 1 步〕SurfaceView 类注释：surface 的 Z 序在持有它的窗口之后，SurfaceView 在窗口上打洞让 surface 显示（出处：android.view.SurfaceView（类注释））
- 〔做法第 1 步〕setZOrderOnTop(true) 把 surface 放到窗口之上（要在窗口 attach 前调用，已废弃，替代为 setCompositionOrder）；setZOrderMediaOverlay 仍在窗口之后，只压在其他 SurfaceView 之上（出处：android.view.SurfaceView#setZOrderOnTop、#setZOrderMediaOverlay）
- 〔做法第 1 步〕SurfaceView 默认请求的像素格式为 PixelFormat.RGB_565（不透明），只有经 getHolder().setFormat 改成带 alpha 的格式才有透明 surface（出处：android.view.SurfaceView#mRequestedFormat、SurfaceView 内 SurfaceHolder 的 setFormat）
- 〔原因 / 做法第 1 步〕clearRect(x: number, y: number, w: number, h: number): void 删除指定区域内的绘制内容，坐标默认单位 vp（出处：鸿蒙 SDK 的 ets/component/canvas.d.ts，CanvasRenderer.clearRect；文档 ts-canvasrenderingcontext2d.md，clearRect）
  写法：全局组件与类，全局可用，不用导入
        private settings: RenderingContextSettings = new RenderingContextSettings(true);
        private ctx: CanvasRenderingContext2D = new CanvasRenderingContext2D(this.settings);
        Canvas(this.ctx)；this.ctx.clearRect(0, 0, w, h)  // CanvasRenderingContext2D 继承 CanvasRenderer
- 〔原因 / 做法第 1 步〕Stack 子组件按顺序入栈，后一个覆盖前一个：画布 clearRect 后透明的区域露出排在它前面的背景组件（出处：文档 ts-container-stack.md，后一个子组件覆盖前一个子组件）
  写法：全局组件，全局可用，不用导入
        Stack(options?: StackOptions)  // StackOptions = { alignContent?: Alignment }
        Stack() { /* 先写的在下层 */ Canvas(this.ctx) }.backgroundColor(Color.Black)
- 〔做法第 1 步〕铺满的 SurfaceView 未调 setZOrderOnTop、未用 getHolder().setFormat 设为带透明度的格式、每帧 drawColor(Color.TRANSPARENT, PorterDuff.Mode.CLEAR) 时，安卓上该区域显示为黑，父容器背景不可见（出处：卡里修好并验证过）
- 〔例外与边界〕GLSurfaceView 在应用没有另设时创建 PixelFormat.RGB_888 的 surface、默认选 RGB_888 带深度缓冲的 EGLConfig（不透明）；要透明 surface 得 getHolder().setFormat(PixelFormat.TRANSLUCENT) 并选带 alpha 的 EGLConfig（setEGLConfigChooser）。VideoView 直接继承 SurfaceView，Z 序与打洞规则同 SurfaceView（出处：android.opengl.GLSurfaceView（类注释）、android.opengl.GLSurfaceView#setEGLConfigChooser；android.widget.VideoView）
- 〔做法第 1 步〕背景图属性的其余成员：backgroundImage 的 API 18 重载收 BackgroundImageOptions { syncLoad?: boolean（默认 false，异步加载）, repeat?: ImageRepeat（默认不重复） }；backgroundImageSize 也可传 SizeOptions { width?, height? }（取值 [0, +∞)）；backgroundImagePosition(value: Position | Alignment) 不设时背景图在组件左上角，x、y 写百分比时相对组件自身宽高；背景图为透明底色且同时设了 backgroundColor 时两者叠加、背景色在最底（出处：鸿蒙 SDK 的 ets/component/common.d.ts，BackgroundImageOptions、CommonMethod.backgroundImagePosition、CommonMethod.backgroundImageSize；文档 ts-universal-attributes-background.md，backgroundImage、backgroundImageSize、backgroundImagePosition）
  写法：通用属性，全局可用，不用导入
        .backgroundImage(src: ResourceStr | PixelMap, options?: BackgroundImageOptions)  // API 18；BackgroundImageOptions { syncLoad?: boolean; repeat?: ImageRepeat }
        .backgroundImageSize(value: SizeOptions | ImageSize)  // SizeOptions { width?: Length; height?: Length }
        .backgroundImagePosition(value: Position | Alignment)  // Position { x?: Length; y?: Length }
        Column().backgroundImage($r('app.media.bg'), { syncLoad: true }).backgroundImageSize(ImageSize.FILL)
