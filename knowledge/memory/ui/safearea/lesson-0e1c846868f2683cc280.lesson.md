# 仅当源窗口本身延伸到系统栏下才做全屏沉浸与底部避让：导航指示条取 bottomRect，贴底按钮、按键区、Tab 栏与 bindSheet 内容都让出避让值（原高度已含底部留白时先抵扣），并加在占据屏幕底边的那一层；FLAG_FULLSCREEN 只隐藏状态栏，导航栏与旧应用的挖孔边、宽高比截边在窗口外

## 何时使用

沉浸式安全区实现阶段，测量导航指示条避让区，并为底部按钮行、按键区、Tab 栏或贴底弹层确定底部间距及承载它的容器层时；为已有固定高度（含内容下方留白）的底部 Tab 栏或底部定位元素补导航条避让时；决定目标窗口是否全屏（沉浸式）、系统栏底色与是否做内容避让时；源端以 DisplayMetrics 等屏幕宽高定游戏几何、为目标确定几何基准时

## 适用情境

目标页面在 setWindowLayoutFullScreen(true) 下用 getWindowAvoidArea 测避让值，写入页面或全局窗口模型；Android 源布局的底部按钮行、底部 sheet 没有导航栏间距（源窗口不延伸到导航栏下，BottomSheetDialog 由系统处理 inset）。或页面规格标注全屏页、需要沉浸式安全区，入口对 BOTTOM 边 expandSafeArea，根容器与底部内容层背景色不同。 也包括底部 Tab 栏原固定高度已在图标文字下方留有空白，避让值取自 TYPE_NAVIGATION_INDICATOR 的单一 px 快照、不区分三键与手势模式，用户只报告某一种导航模式被遮挡。也包括 Material3 BottomSheet 页面（库默认带 paddingBottomSystemWindowInsets）迁为 bindSheet，规格把“弹层跳过沉浸式处理”理解为自动避让。也包括规格要求手势与三键两种导航模式下内容都不被导航栏遮挡，而入口按沉浸式模板只以 TYPE_NAVIGATION_INDICATOR 测底部。 也包括源主题非全屏（Theme.Holo/Theme.Black 等，targetSdk 低，主题与代码都没有全屏或透明系统栏标志；requestWindowFeature(FEATURE_NO_TITLE) 只去标题栏），规格模板或页面元数据却按页面类型默认标注全屏页、需要沉浸式安全区。 也包括源 Activity 只用 FEATURE_NO_TITLE 加 FLAG_FULLSCREEN（或 windowFullscreen），未设导航栏延伸或隐藏标志，targetSdk 低（<28 无法声明挖孔模式、<26 未声明最大宽高比且 activity 不可调整大小）；目标按沉浸式模板 setWindowSystemBarEnable([]) 隐藏全部系统栏、各页根容器四向 expandSafeArea，或把源端 getDisplayMetrics() 的宽高换算成“全屏窗口高减底部避让”。

## 例外与边界

- 源窗口不延伸到系统栏下（主题与代码都没有 windowFullscreen、windowTranslucentStatus/Navigation、透明 statusBarColor、FLAG_FULLSCREEN、SYSTEM_UI_FLAG_LAYOUT_*、setDecorFitsSystemWindows(false)/enableEdgeToEdge，targetSdk<35）：目标保持非全屏，按做法第 1 步处理，其余各步不适用

## 原因

TYPE_NAVIGATION_INDICATOR 的避让区在窗口底部，值在 bottomRect；复制 TYPE_SYSTEM 那一行只改常量会读成 topRect（恒为 0），这种写法一旦被收敛进全局窗口模型，所有页面的底部避让都变成 0。三键导航栏的避让区按文档计入 TYPE_SYSTEM 的底部；文档又写明三键导航显示时 TYPE_NAVIGATION_INDICATOR 的底部区域也始终存在（一款真机两种模式都报 84px），两类的高度关系文档没有规定，所以底部取两者较大值，不只测其中一类。另一方面，源 XML 没有底部间距是因为源窗口不延伸到导航栏，目标全屏窗口会延伸，照 XML 写就贴屏底；bindSheet 内容贴屏底布局，也不会自动避让。来源中页面写者以“视频铺满、源端也没有底部避让”为由不消费底部值，sheet 写者照抄了 XML 的 paddingBottom。又一应用中两类偏差：计算器页规格已写明全屏与四层安全区方案，生成者只写 padding({ bottom: 8 })，底部按键落入指示条区域；补修账本页时把底部避让 padding 加在蓝色根容器上，而屏幕底边原本由浅灰内容层占据，避让区显示成一块蓝色——padding 区域显示的是承载它的容器的背景。另一应用中原 Tab 栏 barHeight(50 + 10) 已在内容下方留有约 10–16vp 空白，生成者把全额避让再加到 60vp 之上，并假设手势模式的避让值很小而未核实；真机上两种模式都报 84px（28vp），手势模式下留白翻倍，同批还给用户未提出的引导圆点追加了避让。最终由用户改为以避让值替代原 10vp 留白（手势模式仍余约 15vp）。反过来，源窗口本就非全屏时套用全屏模板，标题栏或内容会压进状态栏，各页再用避让去补偿，几何与底色都偏离源端；FEATURE_NO_TITLE 只去标题栏，不等于全屏。另一应用的页面类型模板把所有 Activity 默认标为需要沉浸式，经验摘要又被转述成“7 页全部全屏 + 底部避让”，Theme.Holo 源的各页随之被迁成全屏窗口并逐页补避让。 FLAG_FULLSCREEN 与 windowFullscreen 只隐藏状态栏：导航栏仍可见，应用窗口止于其上。主题与代码未设挖孔模式时（windowLayoutInDisplayCutoutMode 默认 DEFAULT），全屏窗口不覆盖挖孔所在的边、该边留黑；targetSdk<26、未声明 maxAspectRatio 且 activity 不可调整大小（resizeableActivity 未设 true；未声明时只有 targetSdk<24 才算不可调整）时，系统按最大宽高比 1.86 截长边（Android 源码 WindowManager.LayoutParams 的 LAYOUT_IN_DISPLAY_CUTOUT_MODE_DEFAULT 注释、ParsingPackageUtils.setMaxAspectRatio、ParsedActivityImpl.setMaxAspectRatio）。源端 getResources().getDisplayMetrics() 或 Display.getSize 取的宽高就是这块应用窗口区。目标用 setWindowSystemBarEnable([]) 会连导航条一起隐藏；用“全屏窗口减底部避让”作几何基准，会多算挖孔边与截边部分，经整数截断的格数、行数随之改变。

## 做法

1. 先判定源窗口是否延伸到系统栏下：主题链按运行设备 API 级取覆盖后的生效链——应用主题的同名 style 在 values-vNN 下另有定义时以该覆盖为准，values/ 只是低版本回落（windowTranslucentStatus、statusBarColor 常只写在 values-v19/v21）；再查生效主题链的 windowFullscreen、windowTranslucentStatus/Navigation、statusBarColor 是否透明，代码中的 FLAG_FULLSCREEN、SYSTEM_UI_FLAG_LAYOUT_*、setDecorFitsSystemWindows(false)/enableEdgeToEdge，以及 targetSdk≥35 的强制 edge-to-edge。全都没有时目标保持非全屏：在 loadContent 回调里 setWindowLayoutFullScreen(false)，按源设置系统栏底色与图标色（setWindowSystemBarProperties；底色取生效主题的 statusBarColor，Material 系默认即 colorPrimaryDark，Holo 及更早的主题为黑；状态栏写 statusBarColor 与 statusBarContentColor，导航栏只在源端为黑时写 navigationBarColor '#FF000000'，其余导航栏色不写），用 setWindowSystemBarEnable(['status','navigation']) 保证横屏也显示系统栏，不建避让窗口模型、各页不加避让 padding；只有确需全屏时才执行以下各步。 逐边判定：windowFullscreen 与 FLAG_FULLSCREEN 只隐藏状态栏，导航栏仍可见、应用窗口止于其上；目标只隐藏状态栏（window.setSpecificSystemBarEnabled('status', false)，保留导航栏与手势条），不用 setWindowSystemBarEnable([])，页面背景与内容不向导航区延伸。主题与代码未设 windowLayoutInDisplayCutoutMode 时，全屏窗口不覆盖挖孔所在的边、该边留黑；targetSdk<26、未声明 maxAspectRatio 或 meta-data android.max_aspect、且 activity 不可调整大小（resizeableActivity 未设为 true；未声明时只有 targetSdk<24 才算不可调整）时，系统按最大宽高比 1.86 截长边。源端用 getDisplayMetrics() 或 Display.getSize/getMetrics 的宽高作几何基准时，目标基准取等价内容区：windowRect 减挖孔边与底部避让（TYPE_SYSTEM 与 TYPE_NAVIGATION_INDICATOR 的较大值），再按宽高比上限截长边，不用“全屏窗口减底部避让”。取值位置：模块 build.gradle 的 targetSdkVersion（常经 gradle.properties 等间接定义，合并构建后才写进 Manifest，源 AndroidManifest 里多半没有）与 AndroidManifest 的 activity 属性、主题链的挖孔模式，参照机 adb shell dumpsys window windows 中该窗口的 mAppBounds，目标端 getWindowAvoidArea 的 TYPE_CUTOUT。
2. 按避让区方位取矩形：顶部取 TYPE_SYSTEM 的 topRect.height；底部取 TYPE_SYSTEM 与 TYPE_NAVIGATION_INDICATOR 两者 bottomRect.height 的较大值（文档：三键导航栏计入 TYPE_SYSTEM 底部；TYPE_NAVIGATION_INDICATOR 是底部导航区，手势与三键导航下都存在），并订阅 avoidAreaChange 在导航方式切换时重算；复制测量代码时同时核对矩形字段。
3. 把页面测量收敛成共享窗口模型前，对照沉浸式参考或工程内已正确的实现逐字段核语义，不直接照搬现有页面片段。
4. 全屏页（按第 1 步判定确需全屏）的底部 CTA、按键区、贴底浮层与 bindSheet 内容都叠加底部避让值（子组件由宿主经 @Param 注入）；源窗口全屏时不因源 XML 没有底部间距就判定无需避让，源窗口非全屏时源 XML 没有底部间距正是保持非全屏的信号。页面规格标注全屏或沉浸式安全区时，生成页面即消费已发布的底部避让值，不用固定小 padding 代替。
5. 放置底部避让 padding 前先确认屏幕底边由哪一层背景占据，把 padding 加在那一层（如浅色内容层），根容器只承担顶部状态栏区；Tab 栏保持内容高度，让其背景延伸覆盖避让区。
6. 原 Tab 栏或底部栏的固定高度已包含内容下方留白时，让避让值替代或抵扣这段留白，不在总高度上整额叠加；三键与手势等导航模式以实测的各模式避让值为准，用户声明正常的模式把“布局不变”列为验收。同一避让值在不同模式下视觉占用不同时，以 TYPE_SYSTEM 底部高度是否大于 0 区分三键与手势导航，或请用户取舍，并在交付说明中标明未验证的模式。
7. 已有固定底部偏移的元素（如 position bottom: 50 的指示器）先比较该偏移与实测避让高度，已足以避开时不追加，也不把用户未提出的组件并入同一改动。

## 可选检查

- 在带导航指示条的设备上确认 bottomPadding 非 0、底部按钮与屏底之间留出指示条高度。
- 调整底部 Tab 高度后，分别在三键与手势导航模式下截图，核对文字到屏底或指示条的间距符合预期。
- 源端非全屏时对照两端截图：状态栏与导航栏区域为源端底色，内容起点在状态栏下沿、终点在导航栏上沿。

## 已核实的平台事实

核实时用的是 API 23（HarmonyOS 6.1.0，SDK ets 6.1.0.105）；文档用 2026-05 的 OpenHarmony 中文文档副本；安卓 平台资源 android-34（windowOptOutEdgeToEdgeEnforcement 用 android-36）；源码 android-36.1；material 1.14.0。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看；每条下面的「写法」是在 SDK 声明里核过的导入语句、归属、签名和枚举成员，写代码时直接照抄。

- 〔做法第 1 步〕windowFullscreen 对应 FLAG_FULLSCREEN（窗口在顶层时隐藏状态栏）；windowTranslucentStatus 对应 FLAG_TRANSLUCENT_STATUS，并自动加 SYSTEM_UI_FLAG_LAYOUT_STABLE|LAYOUT_FULLSCREEN；windowNoTitle 与 Window.FEATURE_NO_TITLE 只关标题栏（出处：Android SDK 平台资源 data/res/values/attrs.xml，Window 的 windowFullscreen、windowTranslucentStatus、windowNoTitle；android.view.WindowManager.LayoutParams#FLAG_FULLSCREEN、#FLAG_TRANSLUCENT_STATUS；android.view.Window#FEATURE_NO_TITLE）
- 〔做法第 1 步〕targetSdk ≥ 35（VANILLA_ICE_CREAM）默认强制 edge-to-edge：框架不再按 insets 适配内容，statusBarColor、navigationBarColor 置为透明；主题 windowOptOutEdgeToEdgeEnforcement=true 可退出（默认 false），targetSdk ≥ 36 时该属性被忽略（出处：com.android.internal.policy.PhoneWindow#ENFORCE_EDGE_TO_EDGE；Android SDK 平台资源 data/res/values/attrs.xml（android-36），windowOptOutEdgeToEdgeEnforcement）
- 〔做法第 1 步〕资源与构建：values-vNN 目录只在 NN ≤ 设备 API 级时参与匹配，多份都匹配时取 NN 最高的；构建时清单合并器把构建脚本里的 targetSdk 写进合并后清单的 <uses-sdk>（出处：com.android.tools:sdk-common 32.4.1，VersionQualifier#isMatchFor、#isBetterMatchThan（字节码）；com.android.tools.build:manifest-merger 32.4.1，ManifestSystemProperty.UsesSdk.TARGET_SDK_VERSION（字节码））
