# 源端默认起始对齐和贴顶要显式写出：Android 与 Compose 的纵向容器默认贴起始边、Compose Row 默认贴顶，ArkUI Column/Row 交叉轴默认居中，Scroll 内不满一屏的内容默认居中

## 何时使用

界面实现阶段，把纵向 LinearLayout、带 constraintStart/Top 的 ConstraintLayout 或 ScrollView/NestedScrollView 转成 ArkUI Column 与 Scroll 时；以及把 Compose Column 中的文本块转成 ArkUI Column 子项时；把未写 verticalAlignment 的 Compose Row 转成 ArkUI Row 时；把 Compose LazyColumn 等从顶部排列的纵向列表落成 Scroll 包裹 Column 时

## 适用情境

源纵向 LinearLayout 没写 gravity（子项默认贴起始边），或 wrap_content 子项以 constraintStart_toStartOf=parent 靠起始边、卡片以 constraintTop_toTopOf=parent 贴顶；目标 Column 宽度撑满，子项为固定或内容宽度；滚动页内容常不满一屏。或显示卡片用 layoutWeight 分高，源端卡内内容 wrap_content 自上而下排列并带上内边距。也包括 Compose Column 未声明 horizontalAlignment（默认 Start），文本只带水平 padding 而无 fillMaxWidth，仅个别项以 fillMaxWidth + TextAlign.Center 居中。也包括 Compose Row 未写 verticalAlignment（默认 Top），子项高度不等。 也包括源端 LazyColumn(fillMaxSize)/RecyclerView 的条目从顶部排列，目标写成 Scroll { Column { ForEach } }.layoutWeight(1)，条目可能不足一屏。也包括 Stack 中应贴顶的块未设 alignContent（默认 Center），或修复缩短头部、内容后 Scroll 子项矮于视口。也包括列表页空态：空态容器是 wrap_content 的滚动容器、在父 RelativeLayout 中未声明居中，内层 LinearLayout 写 gravity=center；工程已有全高居中的空态 Builder 可以照搬。

## 原因

ArkUI Column 的交叉轴默认是 Center，把源端“没写 gravity”照搬成“不写 alignItems”，返回键、标题、列表行就会被居中；父 Stack 的 alignContent 只放置 Column 本身，不影响其子项。Scroll 对不满一屏的内容也会纵向居中，而 NestedScrollView 是顶锚。来源中写者在源端本来居中的空态上显式写了 Center，却在源端默认对齐处什么都没写。另一应用计算器显示区源端自上而下排列（上内边距 18dp），生成者写成 justifyContent(FlexAlign.End)，数值落到显示卡片底部。另一应用中，添加城市页的内容 Column 未写 alignItems(Start)，分组标题被居中，而写者写前已读到陷阱表中对齐需显式设置的条目。另一应用的 Compose 页面中，转换者读到标题、价格、正文都只带水平 padding，写进未设 alignItems 的 Column 后整体居中；给内容宽的 Text 加 textAlign(Start) 也无效，因为 textAlign 只作用于 Text 自身框内。Compose Row 的默认纵向对齐同样是 Top，ArkUI Row 默认 Center。 另一应用的购物车把 LazyColumn 写成 Scroll 包裹未定高的 Column，商品少时整块居中；后来按源端重排卡片也没动外层对齐，最终靠 Scroll.align(Alignment.TopStart) 修正，给未定高的 Column 加 justifyContent 不起作用。

## 做法

1. 源端默认起始对齐时（Android 纵向 LinearLayout 未写 gravity、Compose Column 未写 horizontalAlignment），对应 Column 显式写 alignItems(HorizontalAlign.Start)，或给子项 alignSelf，或给文本 width('100%') + textAlign(TextAlign.Start)；只有源端写了 center/center_horizontal、ConstraintLayout 子项 start 与 end 都约束到 parent（bias 默认 0.5），或 fillMaxWidth + TextAlign.Center 的项才居中。内容宽的 Text 只加 textAlign 不会改变它在父容器中的位置。
2. 每写完一个撑满宽的 Column，逐个核对固定尺寸或内容宽子项的水平位置由谁决定。
3. ScrollView/NestedScrollView 或纵向 Lazy 列表转成 Scroll 时，源内容贴顶就给 Scroll 写 .align(Alignment.Top)（或 TopStart），或给子容器加 constraintSize({ minHeight: '100%' }) 一类约束使其顶锚，并确认超出一屏后仍能滚动；源端是可变长度的条目列表时优先映射为 List，条目默认从顶部排列。给未定高的 Column 写 justifyContent 不改变它在 Scroll 中的位置；按源端重排列表卡片时一并核对外层滚动容器的对齐。
4. 容器被 layoutWeight 撑高而源端内容贴顶时，写 justifyContent(FlexAlign.Start) 并沿用源端上内边距，不改成底对齐。
5. Compose Row 未写 verticalAlignment 时，ArkUI Row 显式写 alignItems(VerticalAlign.Top)；写完逐个对照本页 Column()/Row() 的源码构造参数。
6. Stack 中应贴顶的块设 alignContent(Alignment.Top) 或 position；内容恰好高于视口时 Scroll 的默认居中被掩盖，修复中缩短了头部或内容高度后，复查 Scroll 子项是否仍贴顶。
7. 空态按本页源布局定纵向位置：wrap_content 且未在父容器中居中的空态容器靠上放并保留源边距，内层 gravity=center 只排列包裹高度内的子项，不等于在整个内容区居中；参照已有空态 Builder 时只复用样式骨架。

## 可选检查

- 用 1–3 条少量数据查看首屏：首块紧贴上方元素，标题靠起始边。

## 已核实的平台事实

核实时用的是 API 23（HarmonyOS 6.1.0，SDK ets 6.1.0.105）；文档用 2026-05 的 OpenHarmony 中文文档副本；安卓 平台资源 android-34；源码 android-36.1；Compose foundation 与 foundation-layout 1.12.0、androidx.core 1.19.0（字节码）。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看。

- 〔做法第 1 步〕LinearLayout 与 RelativeLayout 的 mGravity 默认 Gravity.START | Gravity.TOP：布局、style 和代码都没设 gravity 时子项贴起始边、贴顶（出处：android.widget.LinearLayout#mGravity；android.widget.RelativeLayout#mGravity）
- 〔做法第 1 步〕ConstraintLayout.LayoutParams 的 horizontalBias、verticalBias 默认 0.5：没写 layout_constraintHorizontal_bias / Vertical_bias 时，子项 start 与 end（或 top 与 bottom）都约束到 parent 就在两约束间居中，只约束 start 时贴起始边（出处：androidx.constraintlayout:constraintlayout 2.2.2，ConstraintLayout.LayoutParams 构造函数（字节码））
- 〔做法第 1 步〕Compose Column 默认 verticalArrangement = Arrangement.Top、horizontalAlignment = Alignment.Start（出处：androidx.compose.foundation:foundation-layout 1.12.0，ColumnKt.Column 的默认参数（字节码））
- 〔做法第 1 步〕Column.alignItems(value: HorizontalAlign) 默认 HorizontalAlign.Center；HorizontalAlign 成员 Start、Center、End（出处：鸿蒙 SDK 的 ets/component/column.d.ts，ColumnAttribute.alignItems；ets/component/enums.d.ts，HorizontalAlign；文档 ts-container-column.md，alignItems）
- 〔做法第 1 步〕alignSelf(value: ItemAlign): T 覆盖父 Column、Row、Flex、GridRow 的 alignItems，默认 ItemAlign.Auto；ItemAlign 成员 Auto、Start、Center、End、Baseline、Stretch（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.alignSelf；文档 ts-universal-attributes-flex-layout.md，alignSelf）
- 〔做法第 1 步〕Text.textAlign(value: TextAlign) 默认 TextAlign.Start（Wearable 上默认 Center）；文本段落宽度占满 Text 组件宽度，只在 Text 自身框内水平对齐（出处：鸿蒙 SDK 的 ets/component/text.d.ts，TextAttribute.textAlign；文档 ts-basic-components-text.md，textAlign）
- 〔做法第 3 步〕ScrollView 继承 FrameLayout、onLayout 交给 FrameLayout；子项没写 layout_gravity 时按 DEFAULT_CHILD_GRAVITY = TOP | START 摆放，不满一屏时贴顶；androidx NestedScrollView 同样继承 FrameLayout（出处：android.widget.ScrollView#onLayout；android.widget.FrameLayout#DEFAULT_CHILD_GRAVITY；androidx.core:core 1.19.0 的 androidx.core.widget.NestedScrollView（字节码））
- 〔做法第 3 步〕LazyColumn 默认 verticalArrangement 为 Arrangement.Top（reverseLayout=true 时 Bottom），horizontalAlignment 为 Alignment.Start（出处：androidx.compose.foundation:foundation 1.12.0，LazyDslKt.LazyColumn 的默认参数（字节码））
- 〔做法第 3 步〕align(value: Alignment): T 设置子组件在当前组件绘制区内的对齐，在 Scroll、Stack 等组件上生效，默认 Alignment.Center：Scroll 子组件矮于视口时居中（出处：鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.align；文档 ts-universal-attributes-location.md，align）
- 〔做法第 3 步〕Scroll 只支持单个子组件；constraintSize(value: ConstraintSizeOptions) 默认 { minWidth: 0, maxWidth: Infinity, minHeight: 0, maxHeight: Infinity }，优先级高于 width/height，minHeight 可写 '100%'（出处：文档 ts-container-scroll.md，子组件；鸿蒙 SDK 的 ets/component/common.d.ts，CommonMethod.constraintSize；文档 ts-universal-attributes-size.md，constraintSize）
- 〔做法第 3 步〕List.stackFromEnd(enabled: boolean)（API 19）默认 false：List 从顶部开始布局（出处：鸿蒙 SDK 的 ets/component/list.d.ts，ListAttribute.stackFromEnd；文档 ts-container-list.md，stackFromEnd）
- 〔做法第 3 步〕Scroll 的子 Column 未定高且矮于视口时整块居中；给这个子 Column 写 justifyContent 不改变它在 Scroll 中的位置（出处：卡里修好并验证过）
- 〔做法第 4 步〕Column.justifyContent(value: FlexAlign) 默认 FlexAlign.Start：只在 Column 自身高度内排列子项（出处：鸿蒙 SDK 的 ets/component/column.d.ts，ColumnAttribute.justifyContent；文档 ts-container-column.md，justifyContent）
- 〔做法第 5 步〕Compose Row 默认 horizontalArrangement = Arrangement.Start、verticalAlignment = Alignment.Top（出处：androidx.compose.foundation:foundation-layout 1.12.0，RowKt.Row 的默认参数（字节码））
- 〔做法第 5 步〕Row.alignItems(value: VerticalAlign) 默认 VerticalAlign.Center（成员 Top、Center、Bottom）；Row.justifyContent 默认 FlexAlign.Start（出处：鸿蒙 SDK 的 ets/component/row.d.ts，RowAttribute.alignItems、RowAttribute.justifyContent；文档 ts-container-row.md）
- 〔做法第 6 步〕Stack 的 alignContent 默认 Alignment.Center（构造参数 StackOptions.alignContent 与属性 alignContent(value: Alignment) 等效）；在 Stack 上 align 与 alignContent 效果一致（出处：鸿蒙 SDK 的 ets/component/stack.d.ts，StackOptions.alignContent、StackAttribute.alignContent；文档 ts-container-stack.md；ts-universal-attributes-location.md，align）
- 〔做法第 6 步〕源端对照：Compose Box 默认 contentAlignment = Alignment.TopStart，FrameLayout 子项默认 TOP | START：没写 contentAlignment / layout_gravity 时都贴左上（出处：androidx.compose.foundation:foundation-layout 1.12.0，BoxKt.Box 的默认参数（字节码）；android.widget.FrameLayout#DEFAULT_CHILD_GRAVITY）
- 〔做法第 7 步〕android:gravity 只决定控件在自身边界内如何摆放内容，不决定控件在父布局中的位置（出处：Android SDK 平台资源 data/res/values/attrs.xml，gravity）
