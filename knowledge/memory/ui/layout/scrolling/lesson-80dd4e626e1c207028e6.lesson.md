# ScrollView 未写 overScrollMode、Compose verticalScroll/Lazy 列表未置空 overscroll 时，都按 Android 默认 IF_CONTENT_SCROLLS 映射：Scroll 写 edgeEffect(EdgeEffect.Spring, { alwaysEnabled: false })；GridView/ListView 同此，滚动条按源端默认显式设置

## 何时使用

界面转换阶段，把 ScrollView/NestedScrollView（含对话框内的滚动区）转换为 ArkUI Scroll 并设置边缘效果时；把会滚动的 GridView/ListView 转成 Grid/List 并决定滚动条与越界效果时；把 Compose Modifier.verticalScroll/horizontalScroll 或 LazyColumn/LazyRow 转成 Scroll/List（含 bindSheet 半模态里的内容区）并设置边缘效果时

## 适用情境

源 ScrollView 没有声明 overScrollMode（Android 默认 IF_CONTENT_SCROLLS：内容可滚时越界回弹）；映射参考只列显式 overScrollMode，且把 ifContentScrolls 与 always 都映射为不带选项的 EdgeEffect.Spring；目标 Scroll 默认没有边缘效果。 也包括 GridView/ListView 没有改写 scrollbars、overScrollMode（AbsListView 同样默认 IF_CONTENT_SCROLLS），目标 Grid/List 没有显式设置 scrollBar 与 edgeEffect。 也包括 Compose Modifier.verticalScroll/horizontalScroll、LazyColumn/LazyRow 的默认重载带平台越界效果（Android 12+ 拉伸；foundation-android 1.12.1 的默认重载经 LocalOverscrollFactory 取平台效果，字节码已核），源工程没有经 LocalOverscrollFactory/LocalOverscrollConfiguration 或 overscrollEffect 参数置空，页面规格只写 verticalScroll、不提边缘效果。

## 原因

不写 edgeEffect 时 Scroll 没有回弹；写成不带选项的 Spring，内容不满一屏也会回弹。两者都与源端不同；映射参考没有“未声明即 IF_CONTENT_SCROLLS”的规则时，各页会分别落到这两种写法。来源中同一应用的九个滚动页里，六个没设 edgeEffect、三个写了无条件 Spring。 源端视图在窗口变为可见时先显示滚动条约 1200ms 再淡出（View.initialAwakenScrollBars 以 scrollBarDefaultDelayBeforeFade×4 唤醒，默认延迟 300ms；本机 android-36.1 源码 View.java、ViewConfiguration.java），之后滚动时再出现；ArkUI Grid 默认 BarState.Auto，进页不显示（本机 HarmonyOS 6.1.0 SDK component/grid.d.ts，早期版本默认 BarState.Off），宽度与颜色也取目标默认。ArkUI Scroll 把 scrollBar 从 BarState.On 切到 Auto（或切 Off 后不久再切 Auto）时会重新显示滚动条，按 Auto 的淡出节奏再停约 1.3–2s（HarmonyOS 6.1.0 Scroll 截屏取样：On→Auto 约 3s 才消失，只切 Off 立即消失），到时直接切 Auto 会让进页滚动条停留过久。唤醒延迟取自主题的 scrollbarDefaultDelayBeforeFade：Material 系主题在 themes_material.xml 改写为 400，唤醒约 1600ms，参照取样未能区分 1200 与 1600ms，按源主题值取并在报告注明。

## 做法

1. 源未写 overScrollMode 或写 ifContentScrolls：.edgeEffect(EdgeEffect.Spring, { alwaysEnabled: false })；always：alwaysEnabled: true；never：EdgeEffect.None。对话框内的 Scroll 同样处理。 GridView/ListView 转 Grid/List 时同样设置（Grid 默认 EdgeEffect.None）。 Compose 的 verticalScroll/horizontalScroll、LazyColumn/LazyRow：先在源工程检索 LocalOverscrollFactory、LocalOverscrollConfiguration 与 overscrollEffect 参数，没有置空就同样写 Spring + alwaysEnabled: false；规格没写边缘效果不是保留 None 的理由。第 2 步的滚动条规则针对 View 体系的默认滚动条，Compose 源端按源码是否显式绘制滚动条决定。
2. 内容可滚动时显式设置滚动条：进页用 BarState.On 显示源端唤醒时长（约 1200ms，见原因）后切到 BarState.Off 立即收起，不直接切 Auto；在 onTouch 的 TouchType.Down 且当前为 Off 时再切 BarState.Auto，滚动时由 Auto 显示（Grid/List 用同一切换）。scrollBarWidth 与 scrollBarColor 按源主题对应滚动方向的 scrollbarThumbHorizontal/Vertical 滑块取值：宽取滑块可见部分的宽（滑块图有固有宽度时源端按图宽画，没有才用 scrollbarSize），色取滑块颜色。Holo 在 SDK values/themes_holo.xml，滑块是 10dp 槽宽的 9-patch、可见约 2–4dp，暗色取宽 4、色 '#7B808080'；Material 系在 themes_material.xml，滑块无固有宽度，宽取 scrollbarSize 4dp，色按 tint 算合成色：tint 为 colorControlNormal，浅色主题下源设备 API≤30 为黑×0.54（合成约 #47000000）、API≥31 按黑×0.60（约 #50000000），源主题不是示例中的主题时同样去对应 themes_*.xml 查，查不到在报告里登记缺口，不静默沿用目标默认。是否会滚动按参照机行高×行数判断。

## 已核实的平台事实

核实时用的是 HarmonyOS 6.1.0（API 23，SDK 6.1.0.105）；安卓 Android SDK 平台资源 android-34（另比对 android-30/33 的 secondary_content_alpha）；Android SDK 源码 android-36.1；compose foundation-android 1.12.0。和具体应用无关，直接用，不用再查；其中的默认值只在应用自己的主题、样式、清单和代码没有另设时成立，应用有没有另设要到应用里看。

- 〔适用情境〕View(Context) 构造里 setOverScrollMode(OVER_SCROLL_IF_CONTENT_SCROLLS)，XML 未写 overScrollMode 时也取 IF_CONTENT_SCROLLS；ScrollView、AbsListView（ListView/GridView）都继承这一默认（出处：android.view.View#View(Context)、View 构造里 overScrollMode 属性的默认值）
- 〔做法第 1 步〕Scroll.edgeEffect(edgeEffect: EdgeEffect, options?: EdgeEffectOptions)：默认 EdgeEffect.None；options 默认 { alwaysEnabled: true }，所以只写 EdgeEffect.Spring 时内容不满一屏也回弹（出处：鸿蒙 SDK 的 ets/component/scroll.d.ts，ScrollAttribute.edgeEffect；文档 ts-container-scroll.md，edgeEffect）
- 〔做法第 1 步〕List 的 edgeEffect 默认 EdgeEffect.Spring、options 默认 { alwaysEnabled: false }（已等于 IF_CONTENT_SCROLLS）；Grid 默认 EdgeEffect.None、options 默认 { alwaysEnabled: false }（出处：文档 ts-container-list.md、ts-container-grid.md，edgeEffect）
- 〔做法第 1 步〕EdgeEffect：Spring=0、Fade=1、None=2；EdgeEffectOptions.alwaysEnabled: boolean 表示内容小于组件时是否仍启用越界效果（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，EdgeEffect；ets/component/common.d.ts，EdgeEffectOptions）
- 〔做法第 1 步〕foundation-android 1.12.0：verticalScroll/horizontalScroll 默认重载经 ScrollableAreaNode 从 LocalOverscrollFactory 取越界效果；LazyColumn/LazyRow 的 overscrollEffect 默认 rememberOverscrollEffect()（同读 LocalOverscrollFactory）；另有带 OverscrollEffect 参数的重载，旧的 LocalOverscrollConfiguration 仍在（出处：androidx.compose.foundation:foundation-android 1.12.0 字节码 ScrollKt、ScrollableAreaNode、OverscrollKt、OverscrollConfiguration_androidKt、lazy.LazyDslKt）
- 〔做法第 2 步〕View.initialAwakenScrollBars()=awakenScrollBars(scrollBarDefaultDelayBeforeFade×4, true)，窗口变可见（onWindowVisibilityChanged、onVisibilityAggregated）时调用；ViewConfiguration 默认延迟 300ms、淡出 250ms（出处：android.view.View#initialAwakenScrollBars、#onWindowVisibilityChanged、#onVisibilityAggregated；android.view.ViewConfiguration）
- 〔做法第 2 步〕主题默认的 scrollbarDefaultDelayBeforeFade（视图和应用主题没有另设时）：Theme 与 Theme.Holo(.Light) 为 300（唤醒约 1200ms），Theme.Material(.Light) 为 400（约 1600ms）；scrollbarFadeDuration 均为 250（出处：Android SDK 平台资源 data/res/values/themes.xml、themes_holo.xml、themes_material.xml，scrollbarDefaultDelayBeforeFade、scrollbarFadeDuration）
- 〔做法第 2 步〕竖向滚动条宽度 = ScrollBarDrawable.getSize(true)，即 track 或 thumb drawable 的固有宽度；≤0 时才用 scrollbarSize（出处：android.view.View#getVerticalScrollbarWidth；android.widget.ScrollBarDrawable#getSize）
- 〔做法第 2 步〕Holo 主题默认（应用没有另设 scrollbarSize、滑块图时）：scrollbarSize 10dip，scrollbarThumbVertical/Horizontal=scrollbar_handle_holo_dark（Light 为 _light），9-patch 内容区 10dp 宽（mdpi 10px、xxhdpi 30px），可见部分只在中间约 2–4dp，核心像素 #80808080、两侧半透明渐隐（出处：Android SDK 平台资源 data/res/values/themes_holo.xml，scrollbarSize、scrollbarThumbVertical；drawable-mdpi/-xhdpi/-xxhdpi/scrollbar_handle_holo_dark.9.png（像素读取））
- 〔做法第 2 步〕Material 主题默认（应用没有另设 scrollbarSize、滑块图时）：scrollbarSize=@dimen/config_scrollbarSize（4dp）；竖、横向滑块都是 scrollbar_handle_material：无尺寸的 shape，solid #84FFFFFF，tint ?attr/colorControlNormal（宽度因此回落到 4dp）（出处：Android SDK 平台资源 data/res/values/themes_material.xml，scrollbarSize、scrollbarThumb*；values/config.xml，config_scrollbarSize；values/config_material.xml，config_scrollbarThumbVertical；drawable/scrollbar_handle_material.xml）
- 〔做法第 2 步〕Material 主题默认 colorControlNormal=?attr/textColorSecondary（应用主题没有另设时）=colorForeground×secondaryContentAlpha；浅色 secondary_content_alpha_material_light 在 android-30 为 0.54、android-33 起为 0.60，滑块合成色随源设备系统版本不同（出处：Android SDK 平台资源 data/res/values/themes_material.xml，colorControlNormal、secondaryContentAlpha；color/text_color_secondary.xml；android-30 与 android-33/34 的 values/colors_material.xml）
- 〔做法第 2 步〕BarState：Off=0、Auto=1（触摸时显示、之后消失）、On=2；List、Grid、Scroll 的 scrollBar 默认 BarState.Auto（API 9 及以下为 Off），WaterFlow 默认 Off；scrollBarWidth 默认 4vp，scrollBarColor 默认 '#182431' 40% 不透明（Scroll 文档写作 '#66182431'）（出处：鸿蒙 SDK 的 ets/component/enums.d.ts，BarState；文档 ts-container-scrollable-common.md，scrollBar、scrollBarWidth、scrollBarColor；ts-container-scroll.md、ts-container-grid.md、ts-container-list.md，scrollBar）
- 〔做法第 2 步〕Scroll 的 scrollBar 从 BarState.On 切到 Auto，或切 Off 后不久再切 Auto，滚动条会重新显示约 1.3–2s（On→Auto 约 3s 才消失）；只切 Off 立即消失（出处：卡里上机实测（case-4f6e04418ec9319dbb6d，HarmonyOS 6.1.0 截屏取样））
- 〔做法第 2 步〕应用没有另设滚动条滑块时，源端设备上的可见滚动条：Holo 暗色主题宽约 4dp、色约 #7B808080；Material 浅色主题宽 4dp，色为滑块（#84FFFFFF）经 colorControlNormal 着色，tint 为黑×0.54 时约 #47000000，黑×0.60（API≥33）时约 #50000000（出处：卡里上机录屏取样（Holo：case-ecf6bf1e97fdf99c99a3；Material 浅色：case-4f6e04418ec9319dbb6d）；Android SDK 平台资源 data/res/drawable/scrollbar_handle_material.xml，android-33 起 values/colors_material.xml 的 secondary_content_alpha_material_light）
