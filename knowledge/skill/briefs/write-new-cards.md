# 任务书模板：归并之后，给一组新增或加了句子的经验配「已核实的平台事实」

> 协调的人填花括号：`{组号}`、`{经验号列表}`（每行一个完整经验号，后面注明「新增」或「加了句子」）、`{skill 目录}`（本 skill 的目录）、`{memory}`（归并 apply 之后开发版导出的阅读包里的 `memory/`）、`{归并前的阅读包}`、`{store}`（这次归并的 store，来源卡在 `{store}/cases/`）、`{文档同步目录}`、`{鸿蒙 SDK}`（含 `openharmony/ets`、`hms/ets` 的那一级）、`{安卓 SDK}`、`{安卓源码版本}`（如 `android-36`）、`{Gradle 缓存}`、`{产出目录}`、`{应用名参数}`（留作评测的应用名，写成 `--app-name 名字` 若干个；只写在发给写的人的这份里，不进仓库）。
>
> 给协调的人：
> - 这批经验要是出自留作评测的应用，写的人只给正文和这几条经验引的卡，别的都不给。
> - 加了句子的经验已有新格式知识文件的，按 `SKILL.md`「一次归并里三种经验怎么做」第 2 条做增量；下面第 3 点默认整条做，要做增量就改那一点。
> - 条目数的上限不在写的时候定：写的人全写，条目多的另给先后。

你是安卓 → 鸿蒙（ArkTS）迁移经验库的维护者。一次归并刚把一批返修卡并进经验库：有的经验是新增的，有的是在已有经验上加了句子。这次给第 {组号} 组的几条经验各配一份「已核实的平台事实」知识文件：查、核、写，不跑模型。你自己做，不要再派子代理。

## 照什么做

照这份 skill 做：`{skill 目录}/SKILL.md`，先读完它，再读 `references/` 下的 `rules.md`、`sources.md`、`knowledge-format.md`、`examples.md`、`tools.md`。具体到这次：

1. **正文**读 `{memory}` 里的经验文件（只读）。改句的原句从这份文件里逐字取，恰好出现一次。不用跑 export。
2. **候选从来源卡直接收：**
   `py -3.12 -B -X utf8 {skill 目录}/scripts/candidates.py --from-case-files links --memory {memory} --base-memory {归并前的阅读包} lesson-<id>`
   打印的编号就是「用到的候选」的下标；头部的「卡里记的环境」供 `sdk` 和版本条件参考；「改动的部分」「新引的卡」照看。然后照 `rules.md` C6 逐张读这条经验的来源卡（`{store}/cases/<卡号>/`；只读被引的结论——诊断是卡的 `summary`，建议 N 是 `recommendations` 第 N 条——和卡的 `unknown`），把脚本收不到的平台事实另列成「卡补」行，写进工作稿。
   - 卡里有引历史会话里模型思考的句子（「思考中」「推理写」「以为」这类）：不摘抄、不转述，只取设备、编译器、声明、文档、返修结果说明的平台表现。
   - 卡里点到的转录文件和行号、应用源码和迁移工程的路径，一律不去找、不打开；卡的 `graphs`（调查图）不当出处。
3. **加了句子的经验也整条做**（这几条还没有新格式的知识文件）。
4. **文档同步目录**是共用的：`{文档同步目录}`，协调的人已经拉好。你只跑 `py -3.12 -B -X utf8 {skill 目录}/scripts/sync_ohdocs.py {文档同步目录} --show` 读提交号和日期填进 `sdk`，不拉、不改。
5. **读全用工具**（`rules.md` V6a）：引文档的用 `scripts/ohdocs_section.py` 取整节读；安卓的 style、主题属性、平台色值和尺寸用 `scripts/android_res.py --sdk {安卓 SDK} --gradle {Gradle 缓存}` 查全部 `values*` 限定目录和整条 parent 链（依赖库加 `--lib`，默认比最旧和最新两版），取值照它的小结四段分别写；鸿蒙声明用 `scripts/dts_lookup.py`，同名的每处都看。
6. **安卓平台和依赖库两类**是抽查里出入最多的，写这两类时逐条过这四件事（V6a 第 6–11 条和 T4a）：
   - **取值写哪一份**：以小结里「★常见手机竖屏」命中的那一份为主来写，同时写出横屏、平板和其他限定目录下的取值；只写 `values/` 里那一份不行。
   - **版本起点**：写「从某个版本起才有 / 才改」的，要逐版确认到「上一版没有、这一版有」；本机 Gradle 缓存里没有的中间版本，从 Google Maven、Maven Central 取。找不准就写「至少在 X 版已有，更早未核」。安卓系统版本要比到每一版最后一个发布标签。
   - **代码行为**：读到调用它的上下游和同一函数的其他分支。
   - **默认值**：它最常见的覆写（标准父主题的变体、覆盖层）写在同一条里。同一个资源值在你负责的几条经验里出现多次的，写法要一致。
7. **条目多的经验另外排个先后。** 条目数不设上限，核得到、用得上的都写。某条经验的条目超过 24 条时，写完以后再给它的全部条目排一个先后，存成 `{产出目录}/rank/lesson-<id>.json`，内容 `{"lesson": "lesson-<id>", "order": [条目在 entries 里的下标（从 0 起），全部都要在、不重不漏]}`。排法：照这条经验做事的人没有它某一步就写不出来、或会把适用前提判错的排最前；能让结果更准但缺了也能做对的其次；背景性的、能由别的条目推出来的最后。知识文件本身不因此删条目、不加键。
8. **边做边记两样数，交回时报：** 每条经验大约用了多少次工具调用（几条交错做的按你的估计分摊）；候选里用上的下标、丢掉的行数，读卡后另列的「卡补」几条、其中几条进了条目。都记在工作稿里。

上面以外的地方一律不看。

## 可以写的

- `{产出目录}/lesson-<id>.json`：只写你负责的那几条，新格式（目录不在就建）。
- `{产出目录}/rank/lesson-<id>.json`：条目超过 24 条的经验的先后（上面第 7 点）。
- `{产出目录}/work-g{组号}/`：草稿、工作稿和辅助脚本。

## 不许看的（硬性）

- 评测用的工程和评测结果：被迁移的应用、它的迁移工程、评测和试验的记录与报告。
- 别人已经写好的同一批知识：别的组的工作稿和产出、以前给这些经验做过的知识文件（包括经验库仓库 `knowledge/` 下的一切）。skill 的例子引用的是别的经验，可以看。
- 卡里点到的会话转录、证据目录。
- 凭据：文件名带 key、token、credential 的文件，名叫 `cfg` 的目录，任何存放 API 密钥的文件，都不打开。

## 不许做的

- 不调任何模型 API，不起子代理，不碰模拟器和真机（hdc、adb）；不读会话转录；不改经验库、SDK、文档同步目录、skill。
- 某个动作被权限机制拒绝了，不换办法绕，记下来交回时说。
- 改 json 用写在文件里的脚本读入、改、写回（`ensure_ascii=False`，缩进 1）；带反斜杠的内容用写文件的方式建，不用 heredoc。

## 自查（必须跑，改到错误为 0）

```
py -3.12 -B -X utf8 {skill 目录}/scripts/check.py <你的几个 lesson-<id>.json> --memory {memory} --require-new --docs {文档同步目录} {应用名参数} --sources --oh-ets {鸿蒙 SDK}/openharmony/ets --hms-ets {鸿蒙 SDK}/hms/ets --android-platforms {安卓 SDK}/platforms --android-src {安卓 SDK}/sources/{安卓源码版本}
```

「错误」改到 0；「要人看的」逐条看；卡里验证的条目逐条读一遍，确认写的是「什么条件下平台怎么表现」，没有某次返修怎么改的话，也没有被迁移应用自己的类名、变量名、取值。不改检查脚本。
