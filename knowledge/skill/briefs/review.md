## 背景

- 这是安卓 → 鸿蒙（ArkTS）迁移经验库的知识文件：每条经验一个 JSON，`entries` 里每条是一个平台事实（step、fact、source、kind、origin），`changes` 是对经验正文句子的改动（where、before、after、basis、type）。
- 写的人照的规则在 `{skill 目录}`（先读 `references/rules.md`——重点 V5a、V6、V6a、T1、T4、T4a——和 `references/sources.md`、`references/knowledge-format.md`、`references/tools.md`）。
- 安卓平台和依赖库两类常见的毛病：
  1. 资源取值只写了 `values/` 里那一份，漏了限定目录里的变体（`values-h720dp`、`sw600dp`、`land`、`v21` 等）。例：对话框按钮条最小高度只写 48dip，漏了 `values-h720dp` 的 54dip；竖屏手机的可用高度 `screenHeightDp`（targetSdk 35 以下不含状态栏和导航栏）到了 720dp 就命中 54dip，没到的仍是 48dip，两种情形都要写。
  2. 「从某个版本起才有 / 才改」的起点没找准，只看了本机有的两个版本。例：写成「1.12.0 起才有」，实际 1.10.0 起就有。
  3. 核代码行为时只读了被引用的函数，没读调用它的上下游（预处理、字段是否已设）或同一函数里的其他分支。
  4. 默认值写了，它最常见的覆写（父主题变体、覆盖层）没写在同一条里；或者同一个资源值在两条经验里写法对不上。

## 要你做的

1. 对这些文件里 **kind 是「安卓平台」或「依赖库」的每一条条目**，以及**每一处改句**（不论它的依据是什么），回到原始出处重核一遍，专门找上面四种毛病：
   - 资源取值：用 `scripts/android_res.py --sdk {安卓 SDK} --gradle {Gradle 缓存}`（平台资源；依赖库加 `--lib`）查**全部**限定目录和整条 parent 链，工具输出里每一个变体都要看；按工具小结里「★常见手机竖屏」那一行（默认宽 360–412dp、可用高 660–915dp；写「因配置而异」时照它分的情形）实际命中哪一份来判断条目写的值对不对，并把别的配置下的取值补进同一条。条目里只写到资源名（dimen、color 的名字）没写取值的，把取值解析出来写上。
   - 版本起点：本机 Gradle 缓存里没有的中间版本，从官方仓库（Google Maven `dl.google.com/android/maven2`、Maven Central `repo1.maven.org`）取对应版本的 aar 或源码包逐版确认，找到「上一版没有、这一版有」；找不准就改成「至少在 X 版已有，更早未核」。安卓系统版本的起点要比到每一版**最后一个**发布标签（有的改动会回移到旧版的后期补丁，只比各版的 r1 会把起点写晚）；写了「从 X 起是某值」的要看到本机最新的平台，后面又变了的分段写、写明上界。
   - 代码行为：安卓框架看 `{安卓 SDK}/sources/{安卓源码版本}`（本机没有的版本可联网取 AOSP 源码站原文），读到调用它的上下游和同一函数的其他分支。代码行为类的每条都要自己重读，不能记成沿用。
   - 默认值：把最常见的覆写补进同一条。
2. **不准的就地改**：改条目的 `fact`（必要时改 `source`），保持条目的其他键不变；改句有问题就改 `after`、`basis`、`type`（`before` 不许动，它必须仍在正文里恰好出现一次；正文在 `{memory}` 下按文件名找）。条目本身是错的、救不回来的，删掉并在日志里说明。不要新增和这次复核无关的条目（`rules.md` V5a、T4a、V6a 要求补的除外），不要动 kind 是「鸿蒙接口」「卡里验证」的条目（发现它们和你改过的条目说法对不上时，只在日志里记一笔）。**正文里某一句和你改后的条目矛盾、或者照它做会做错的，为它新增一处改句**（只改那一句：`before` 取正文里逐字的一段、恰好出现一次，不和已有改句的 `before` 重叠；`after` 只做这一处改正；`where`、`basis`、`type` 照 `knowledge-format.md`）；只是条目比正文更细、正文那句本身不错的不加。
3. **跨文件一致**：同一个资源名、同一个库属性在你负责的文件里出现多次的，改完后说法要一致。
4. 改完跑检查，错误要是 0：
   `py -3.12 -B -X utf8 {skill 目录}/scripts/check.py <你负责的文件> --memory {memory} --require-new --docs {文档同步目录}`
5. **日志**：`{目录}/_qa/review/log-{号}.json`：逐条记（文件、是条目还是改句、下标、判定：原样 / 改了 / 删了 / 新增、属于上面哪一种毛病、改之前和改之后的原文、依据）。改 json 用写在文件里的脚本读入、改、写回（`ensure_ascii=False`，缩进 1），脚本放 `{目录}/_qa/review/work-{号}/`。

- 可以读：skill 目录、正文目录 `{memory}`、来源卡 `{cases}`、文档同步目录 `{文档同步目录}`（只读不拉）、鸿蒙 SDK `{鸿蒙 SDK}`、安卓 SDK `{安卓 SDK}`、Gradle 缓存 `{Gradle 缓存}`；联网只取一手来源（AOSP 源码站、Google Maven、Maven Central、官方库仓库、安卓官方参考文档、OpenHarmony 文档仓库），请求里不带本机信息。
