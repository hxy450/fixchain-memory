# 经验后面挂「已核实的平台事实」（试验，第三版）

这个分支在 main（369bbbf3）之上只加了 `knowledge/` 一个目录，`memory/` 和 `store/` 没有动，也没有并入 store。第五版在分支 `memory/knowledge-v5-20261118`。

## 是什么

main 上 27 条经验的带知识版本。迁移模型照经验写代码时，要反复去查和应用无关的平台事实：鸿蒙接口的参数和默认值是什么、安卓框架和依赖库的默认值和默认行为是什么。这里把这些事实提前查好、核过，挂在经验后面，模型拿到后直接用。

每条经验做了两件事：

1. **正文对齐**：正文里和核到的事实对不上、或缺条件的句子改掉，交出去的经验只有一个说法。
2. **挂事实**：后面接一节「已核实的平台事实」，每条带出处。

## 目录

| 路径 | 内容 |
|---|---|
| `lessons/lesson-<id>.json` | 每条经验的知识源文件 |
| `memory/<主题>/lesson-<id>.lesson.md` | 渲染好的带知识经验，相对路径和 `memory/` 里的原文件一致；来源和证据卡不复制，指回原文件 |
| `render.py` | 从 `memory/` 的原文件和 `lessons/` 重新渲染：`python knowledge/render.py` |

json 的字段：

- `sdk`：核实时用的版本。
- `changes`：对正文的改动，每项有 `where`（哪一部分）、`before`（原句）、`after`（新句）、`basis`（依据）、`type`（改错 / 加条件 / 写成明确做法 / 改措辞）。
- `entries`：平台事实，每项有 `step`（服务于正文哪一部分）、`fact`、`source`（出处，不含本机路径）、`kind`（鸿蒙接口 / 安卓平台 / 依赖库 / 卡里验证）、`origin`（沿用并复核 / 新查）。
- `device_todo`：要上机才能确定的事项，只留给维护的人，不交给模型。

## 规模

- 27 条经验，其中 25 条有事实（2 条纯流程类经验没有可挂的）。
- 事实 306 条：鸿蒙接口 170、安卓平台 82、依赖库 22、卡里验证过的做法 32。其中 232 条从前一版沿用并复核，74 条是这一版新查的。
- 正文改动 39 处，涉及 16 条经验：改错 12、加条件 12、写成明确做法 11、改措辞 4。
- 要上机才能定的 10 条。
- 渲染后 27 个文件共约 15.3 万字；事实约 4.4 万字，出处约 3.2 万字。

## 和别的版本的关系

- 第五版（分支 `memory/knowledge-v5-20261118`）= 这一版，加上鸿蒙接口的「写法」（导入语句、归属、签名、枚举成员），再加 98 条事实（同族接口、依赖组件的默认行为、主题变体），共 418 条。
- 实际交给模型时还用过一个轻量的交法：条目和这一版相同，但不带出处，正文多改了 13 句。

## 怎么配的

配的人只看经验正文、证据卡和 SDK，不看任何被评测的应用。规则：

- 只挂这条经验自己的做法用得上的平台事实；默认值写明「应用没有另设时」。
- 核到的事实和正文对不上时改正文：静态事实以 SDK 和源码为准，运行时表现以卡里实测为准，随版本变的写条件，卡里验证过的做法不删。
- 核不到的不写；要上机才能定的不交给模型，记在 `device_todo`。

核实用的版本：鸿蒙 API 23（SDK ets 6.1.0.105）和 2026-05 的 OpenHarmony 中文文档；安卓源码 android-36.1 和 android-34 的平台资源；依赖库版本写在各条出处里。

## 核对到什么程度

- 出处：安卓平台资源、安卓源码、鸿蒙文档、鸿蒙声明四类，脚本能核的 439 处里 418 处对得上。对不上的 21 处是出处里点到的章节名或成员名在文件里没找到（多数是「页首说明」这类描述性的写法），没有逐条重查。
- 另有 27 处出处的写法脚本认不出，没有核；依赖库的出处（34 处）和卡里验证的出处（35 处）脚本不核。
- 第五版把出处的写法改规范后，四类 710 处全部对得上。
- 没有上机。

## 用下来的情况

在留出应用的三个代码单元上、用 GLM 5.3、按「做完后拿经验逐条核对修改」的方式跑过，判定一共 32 处已知偏差里修掉几处。单趟波动很大：

| 交法 | 修掉 | 带出的新错 |
|---|---|---|
| 不带知识，新起的 agent（2 趟） | 10、8 | 1、1 |
| 第三版，新起的 agent（2 趟） | 14、9 | 0、2 |
| 第三版的轻量交法，新起的 agent（1 趟） | 11 | 2 |
| 第三版，接着原 agent 的会话改（1 趟） | 9 | 2 |

- 带知识后，查安卓默认值这一类调用基本没有了；查鸿蒙声明的调用还在。
- 有几处要靠一个平台取值才改得对的偏差，带知识后稳定修得更多；带出的新错没有减少。
- 花费和不带知识时大致相同。
