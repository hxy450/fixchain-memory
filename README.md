# 多应用迁移经验库

[从 memory/index.md 开始阅读](memory/index.md)

## 两层产物

- `memory/`：开发维护用的阅读包，按三个检索轴组织：`stage`（阶段字段）、`topic`（领域/主题[/子主题]，按技术机制划分）、`signals`（输入里可 grep 的符号）。根 `index.md` 给出三步召回协议、领域与阶段入口；`catalog.jsonl` 每行一条经验，`signals.json` 是符号到经验 id 的倒排表，`by-stage/` 按阶段分组，`topics/` 每级只列直接子项，`topics/<主题>/<id>.lesson.md` 是正文（与主题索引同目录，末尾自动附同源经验和来源段，可点击到 `store/` 中对应版本的卡片）。
- `store/`：正式情景卡、经验数据及格式需要的版本快照。经验通过 case、claim、revision 关联具体来源卡。

正式卡使用自包含的 `migloop-case/4`，保存模型总结、建议、归因图及必要身份与环境信息。迁移模型通常只阅读经验，证据卡用于按需复核；图的 UI 结合原始迁移转录重新生成，不把检查回执和展示缓存存成知识。

当前知识版本以 `store/HEAD.json` 为准；`memory/manifest.json` 记录对应 revision、文件校验和与来源绑定。[MEMORY.md](MEMORY.md) 保留为兼容入口。

## 更新与历史

每次迁移的调查任务收尾后统一归并，通过机械检查，再更新根目录的 `store/` 与带来源的 `memory/`，由调度器 commit 并 push 一次。推送失败保留本地提交，续跑只补推送，不重跑分析或强推远端。

只有部署给迁移 agent 时，才从同一 store 另行导出不带完整来源列表的精简阅读包；不拿部署包替换本仓库的 `memory/`。相对卡片链接按最终目录位置生成，仓库移动或克隆后仍可用。

两种阅读版均保留一行“来源支持：N 张卡 · M 次迁移 · K 个应用”。计数从当前绑定卡片自动计算：同卡的多个 claim 只算一张；迁移按记录的 server_session_id（本地记录可用 migration.id）去重；应用按 project 标识去重，不把同应用的多次迁移当成多个应用。缺失项标为未记录，不从子代理、材料池或分析会话推断。计数仅是历史样本覆盖，可辅助理解佐证强度，不是正确概率或成功复用次数；适用条件仍优先。开发版在计数之后继续保留全部来源链接。

旧版阅读包由 Git 历史保留，不按迁移复制多份。此前的 `runs/` 已退出当前 Git 树，本地的材料、稿件、报告与断点仍保留；原有提交没有改写。此次目录调整不改变卡片内容、经验语义或知识 revision。

当前发布分支：`memory/multi-app-20260929`。工作目录、转录、SQLite、模型日志、提案及本机调度信息不进入正式发布树。

机械检查保证格式、引用及所画历史关系符合契约，不等于归因语义认证或泛化效果证明。评测应冻结一个 Git commit / memory revision，在未入库应用上对照。

## 2026-10-07：按检索轴重建阅读包结构

### 改了什么

- **经验 schema 加三个检索字段**：`stage`（spec / plan / execute / verify 为主，repair / converge 可选，可多值，与 a2h 的阶段 skill 对应）、`summary`（不超过 30 字的条件＋动作）、`signals`（当前输入里能 grep 到的 API、组件、装饰器、文件名）。367 条全部回填：execute 333、spec 88、plan 29、verify 34、repair 78、converge 22；1,580 个不同符号（第一版 1,747 个，剔除 179 个 import、title 这类在任何工程都会命中的泛词，apply 现在直接拒收这类符号）。stage 代替 `when` 里 227 种阶段写法成为可过滤字段。
- **主题树按机制重划**：5 个领域 78 个主题，64 个叶子，每个叶子 4 到 9 条（旧树 1 到 17 条）。ui 改为三层（9 组 34 叶），其余领域两层；旧的 17 条 dialog、16 条 state、16 条 spec-handoff 等大主题按子机制拆开，account、analytics 等单条主题并入机制主题；process 下按阶段命名的 build、testing、visual-review 改为按失真机制命名。主题描述统一为一句定义，不再随经验追加枚举。
- **结构契约进入脚本**：经验只能放在叶子主题、一个叶子最多 12 条、主题描述不超过 60 字，apply 和 export 都会拒绝违反的提案；少于 4 条或多于 9 条只给整理提示。
- **正文与主题索引同目录**：`topics/<主题>/<id>.lesson.md`，维护者按主题文件夹即可看到索引和全部正文，移动主题即移动文件；每条正文自动列出由相同来源卡提炼的「同源经验」（最多 5 条）。
- **claim ID 稳定化**：建议绑定从 `recommendation:N` 改为建议文本哈希 `rec-<10 位>`，增删或重排其他建议不再影响既有绑定。427 张卡、1,517 条建议绑定由 `memory.py migrate` 在快照里重绑，卡片文件未改。
- **阅读成本**：从根索引到一条 dialog 经验所需读取的索引由 27 KB 降到 6.5 KB；按 stage × 领域 × 符号过滤 catalog 时候选通常只剩几条，读取量不随经验总数增长。

### 没有做的

- 主题分类代理给出的 35 条跨领域调整建议（例如 module.json5 权限声明从 data 移到 app）没有采纳，经验仍在原领域。
- 快照仍是全量存储，63 个快照占 store 体积大头；差量化留待发布器单独处理。
- 没有做召回评测；冻结任务集与 Recall@K 测量是下一步。

本次提案由分类与字段回填子任务生成后一次 apply；分类和字段的最终内容都在快照 `store/snapshots/6c97badf….json` 中，README 历史章节里指向旧目录路径的链接已随目录重建失效，保留为历史记录。
